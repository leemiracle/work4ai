## Purpose and Scope

 This document details the model evaluation system within the ESFT (Expert Selective Fine-Tuning) framework. Model evaluation is a critical component that measures model performance across specific tasks or datasets, providing metrics that support informed decisions during the expert selection process. The evaluation results directly feed into the expert scoring system (see [Expert Scoring](https://deepwiki.com/deepseek-ai/ESFT/2.1-expert-scoring)) and drive the expert configuration generation (see [Expert Configuration Generation](https://deepwiki.com/deepseek-ai/ESFT/2.2-expert-configuration-generation)).

 The model evaluation system is designed to efficiently evaluate large language models across multiple GPUs and distributed processes, ensuring that evaluation can be conducted on resource-intensive models in a reasonable timeframe.

### Model Distribution Across GPUs

 The model evaluation system uses an intelligent device mapping strategy to distribute model layers across available GPUs:

 
```

```

 The `infer_auto_device_map` function automatically creates a device map that assigns model components to specific GPU devices based on the provided pipeline parallelism splits:

 
 - The embedding layer is always assigned to the first GPU
 - Transformer layers are distributed according to specified pipeline splits
 - The normalization layer and language model head are assigned to the last GPU
 
 This allows efficient use of GPU memory and enables evaluation of models that would be too large to fit on a single GPU.

### Dataset Distribution

 The evaluation dataset is evenly distributed across worker processes. Each process evaluates a subset of the data:

 
```
cur_dataset = dataset[rank::args.world_size]
```

 This line efficiently implements a strided slice of the dataset, assigning every `world_size`-th example to a process starting from its rank. For example, with 4 processes, process 0 evaluates examples 0, 4, 8..., process 1 evaluates examples 1, 5, 9..., and so on.

## Supported Evaluators

 The system supports multiple task-specific evaluators, each designed to evaluate model performance for a specific type of task:

 
| Evaluator | Task Type | Description |
|---|---|---|
| IntentEvaluator | Intent Classification | Evaluates the model's ability to identify user intents from text |
| SummaryEvaluator | Text Summarization | Assesses the quality of model-generated summaries |
| LawEvaluator | Legal Reasoning | Tests the model's capability for legal reasoning and analysis |
| TranslationEvaluator | Language Translation | Evaluates translation quality across languages |

 Each evaluator can be selected via the `--eval_dataset` parameter when running the evaluation script. The evaluators implement a common interface with an `evaluate` method that returns both detailed results and aggregated metrics.

### Key Configuration Parameters

 
 - **Model Parameters**:

 
 - `--base_model_path`: Path to the pre-trained model
 - `--adapter_dir`: Directory containing adapter weights to be applied to the model
 - **Evaluation Parameters**:

 
 - `--eval_dataset`: Specifies which dataset/task to evaluate (e.g., "translation")
 - `--max_new_tokens`: Maximum number of tokens to generate for each prompt
 - `--eval_batch_size`: Batch size for evaluation
 - `--openai_api_key`: API key for OpenAI (used for certain evaluators that require API access)
 - **Distribution Parameters**:

 
 - `--world_size`: Number of processes to distribute evaluation across
 - `--gpus_per_rank`: Number of GPUs to allocate per process
 - **Output Parameters**:

 
 - `--output_path`: Path where evaluation results will be saved
