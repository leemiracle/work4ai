## Purpose and Scope

 This document explains the Expert Parallelism (EP) training system in DeepSeek ESFT, which enables efficient distributed training of large language models with Mixture of Experts (MoE) architectures. Expert Parallelism distributes experts across multiple GPUs to accelerate training and reduce memory requirements per device. For information about standard training without expert parallelism, see [Standard Training Pipeline](https://deepwiki.com/deepseek-ai/ESFT/3.1-standard-training-pipeline). For training configuration details, see [Training Configuration](https://deepwiki.com/deepseek-ai/ESFT/3.3-training-configuration).

 
## Overview of Expert Parallelism

 Expert Parallelism is a specialized approach for training MoE models that distributes experts across multiple GPUs. This technique allows for efficient scaling of model training by parallelizing the expert computation, which is particularly valuable for the DeepseekV2 model's MoE layers.

## Parallel Groups Initialization

 Expert Parallelism uses two types of parallel groups to organize distributed training:

 
 - **Expert Parallel (EP) Groups**: Distribute experts across GPUs
 - **Expert Data Parallel (EDP) Groups**: Allow data parallelism within each expert group
 
 
```

```

 The system initializes these parallel groups using the `init_parallel_groups` function, which sets up the necessary communication channels between GPUs. The EP size is configurable and determines how many GPUs will participate in each expert parallel group.

### Expert Parameter Management

 Expert parameters require special handling in distributed training:

 
 - Parameters with `.expert` in their name are excluded from DDP's automatic synchronization
 - A dummy parameter is added to prevent DDP from having no trainable parameters
 - Each MoE layer is configured with the expert parallel group for communication

## Custom Gradient Synchronization

 Expert Parallelism requires custom gradient synchronization logic to ensure proper training across distributed experts:

 
```

```

 The custom backward method overrides the accelerator's backward function to:

 
 - Call the original backward function
 - Perform gradient synchronization for expert parameters across the EDP group
 - Use `ReduceOp.AVG` to average the gradients
 
 This ensures that expert parameters are properly updated based on gradients from all GPUs in the corresponding EDP group.

## Expert Parallelism vs. Standard Training

 This table highlights the key differences between Expert Parallelism training and standard training:

 
| Feature | Expert Parallelism Training | Standard Training |
|---|---|---|
| Main Implementation | train_ep.py | train.py |
| Script | scripts/train_ep.sh | scripts/train.sh |
| Parallelism Strategy | Distributes experts across GPUs | Standard data parallelism |
| Gradient Synchronization | Custom handling for expert parameters | Standard DDP synchronization |
| Memory Efficiency | Higher (experts distributed) | Lower (all experts on each GPU) |
| Communication Pattern | All-to-all for expert routing | Standard all-reduce |
| Checkpoint Saving | Distributed across ranks | Standard single-process saving |
