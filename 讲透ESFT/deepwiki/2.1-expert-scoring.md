## Purpose and Scope

 Expert Scoring is a critical component of the ESFT (Expert Selection for Fine-Tuning) system that analyzes and quantifies the importance of individual experts in a Mixture-of-Experts (MoE) model for specific tasks or datasets. This document details how expert scores are calculated based on model evaluation, which forms the foundation for selective expert training in ESFT. For information about how these scores are used to generate expert configurations, see [Expert Configuration Generation](https://deepwiki.com/deepseek-ai/ESFT/2.2-expert-configuration-generation).

 
## Overview

 In an MoE architecture, determining which experts specialize in which types of tasks is essential for efficient fine-tuning. The Expert Scoring system measures the contribution of each expert when processing specific datasets, enabling the subsequent selection of only the most relevant experts for task-specific fine-tuning.

## Expert Scoring Process

 The expert scoring process involves running inference on a sample of task-specific data and tracking which experts are activated during processing. The system then analyzes these activation patterns to determine the importance of each expert for the specific task.

## Execution Flow

 The expert scoring execution flow consists of these main steps:

 
 - **Initialization**:

 
 - Loading the base model
 - Enabling expert weight logging
 - Preparing the dataset
 - **Parallel Processing**:

 
 - Spawning multiple worker processes
 - Distributing the model across available GPUs
 - Dividing the dataset among workers
 - **Data Collection**:

 
 - Processing samples until the token limit is reached
 - Collecting expert activation data during inference
 - Storing logs in the output directory
 - **Output**:

 
 - Expert activation logs organized by process rank
 - These logs will be later processed to calculate final expert scores

## Expert Activation Data

 During inference, when `log_expert_weights = True`, the model tracks which experts are activated for each token and with what weights. This produces data that can be conceptualized as:

 
| Token | Expert 1 Weight | Expert 2 Weight | ... | Expert N Weight |
|---|---|---|---|---|
| Token 1 | 0.75 | 0.25 | ... | 0.0 |
| Token 2 | 0.1 | 0.0 | ... | 0.9 |

## Technical Implementation

 The system uses several key components:

 
 - **Device Mapping**: The `infer_auto_device_map` function distributes model layers across available GPUs for efficient processing
 - **Multi-Processing**: The `torch.multiprocessing` module (`mp.spawn`) is used to create parallel worker processes
 - **Accelerate Library**: The `dispatch_model` function from the Accelerate library is used to distribute the model across devices
 - **Configuration**: Expert logging is enabled by setting `model.config.log_expert_weights = True`

## Output and Next Steps

 The expert scoring process produces activation logs stored in the specified output directory, organized by process rank. These logs are processed in the next step by the `generate_expert_config.py` script, which uses them to determine the importance of each expert for the specific task and generates a configuration for selective expert training.

 The organization of output data is:

 
```
results/expert_scores/translation/
├── rank_0/
│   └── expert_logs.json
├── rank_1/
│   └── expert_logs.json
├── ...
└── rank_N-1/
    └── expert_logs.json
```

 After expert scoring is complete, the next step in the ESFT pipeline is to generate expert configurations, which is handled by the Expert Configuration Generation component (see [Expert Configuration Generation](https://deepwiki.com/deepseek-ai/ESFT/2.2-expert-configuration-generation)).
