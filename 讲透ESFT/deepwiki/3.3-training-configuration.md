## Configuration Overview

 The ESFT system uses YAML configuration files to specify training parameters. These files control various aspects of the training process, including:

 
 - Model settings (sequence length)
 - Data settings (batch size, number of devices)
 - Training hyperparameters (optimizer, learning rate, steps)
 - Evaluation and checkpointing frequency
 - Expert parallelism settings

## Key Configuration Parameters and Their Effects

 
| Parameter | Description | Default Value | Impact on Training |
|---|---|---|---|
| seed | Random seed for reproducibility | 5934875 | Ensures consistent results across training runs |
| seq_length | Maximum sequence length | 4096 | Affects memory usage and model's context window |
| per_device_batch_size | Batch size per device | 1 | Controls memory usage per GPU |
| n_device | Number of devices | 8 | Used for distributed training calculations |
| optim | Optimizer type | adamw_torch_fused | Affects training dynamics and convergence |
| steps | Number of training steps | 500 | Total training duration |
| learning_rate | Learning rate | 0.00001 | Controls how quickly weights are updated |
| weight_decay | Weight decay for optimizer | 0.1 | Regularization to prevent overfitting |
| warmup_steps | Warmup steps for learning rate scheduler | 0 | Affects learning rate schedule |
| gradient_accumulation_steps | Steps to accumulate before update | 16 | Enables larger effective batch sizes |
| max_grad_norm | Max gradient norm for clipping | 1.0 | Prevents gradient explosion |
| ep_size | Expert parallelism size | 2 | Number of GPUs per expert group |

 Sources: [configs/base.yaml1-31](https://github.com/deepseek-ai/ESFT/blob/579a7711/configs/base.yaml#L1-L31)

 
## Expert Parallelism Specific Configuration

 The `ep_size` parameter is specific to expert parallelism training. It determines how many GPUs are allocated to each expert group during distributed training.

## Effective Batch Size Calculation

 The effective batch size in the ESFT system is calculated as:

 
```
Effective Batch Size = per_device_batch_size × n_device × gradient_accumulation_steps
```

 With the default configuration:

 
 - `per_device_batch_size` = 1
 - `n_device` = 8
 - `gradient_accumulation_steps` = 16
 
 The effective batch size is 1 × 8 × 16 = 128.
