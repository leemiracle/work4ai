## Purpose and Scope

 This document describes the expert configuration generation process in the DeepSeek ESFT system. Expert configuration generation is the critical step where the system selects which specific experts in a Mixture-of-Experts (MoE) model should be fine-tuned for a particular task. The output of this process is a configuration file that specifies exactly which experts to train and which to keep frozen during fine-tuning.

 For information about how expert scores are calculated prior to configuration generation, see [Expert Scoring](https://deepwiki.com/deepseek-ai/ESFT/2.1-expert-scoring). For details on how the generated configurations are used during training, see [ESFT Adaptation](https://deepwiki.com/deepseek-ai/ESFT/4.2-esft-adaptation).

 
## Process Overview

 Expert configuration generation involves processing the scores assigned to each expert during the expert scoring phase and creating a configuration file that selects the most relevant experts for a specific task or set of tasks.

## Configuration Generation Algorithm

 The configuration generation process follows these key steps:

 
 - **Loading Expert Scores**: The system loads expert scores that were previously calculated during the expert scoring phase.
 - **Score Summarization**: The scores are summarized across all tokens and layers.
 - **Expert Selection**: For each layer, experts are ranked by their scores and selected based on a cumulative probability threshold.
 - **Configuration Generation**: The selected experts are compiled into a JSON configuration.
 
 
### Score Summarization

 The system processes two types of scores for each expert:

 
 - **Gate scores**: Weighted scores from the MoE gate/router mechanism
 - **Token scores**: Simple counts of tokens routed to each expert

### Expert Selection Algorithm

 The expert selection process uses either token scores or gate scores (specified by the `score_function` parameter) to identify the most important experts for each layer:

 
 - For each layer, experts are sorted by their scores in descending order.
 - Experts are selected in order until their cumulative score exceeds the `top_p` threshold.
 - The selected experts for each layer are recorded in the configuration.

## Configuration Format

 The generated expert configuration is a JSON file with the following structure:

 
```
{
  "experts": {
    "1": [list of expert IDs for layer 1],
    "2": [list of expert IDs for layer 2],
    ...
    "N": [list of expert IDs for layer N]
  },
  "shared_experts": boolean,
  "non_expert_modules": boolean
}
```

 Where:

 
 - `experts`: A dictionary mapping layer numbers to lists of expert IDs to be trained
 - `shared_experts`: A boolean indicating whether to train shared experts
 - `non_expert_modules`: A boolean indicating whether to train non-expert modules

## Usage

 The expert configuration generation is typically run as part of a pipeline, but can also be executed directly using the `generate_expert_config.py` script with appropriate parameters.

 
### Command-line Usage

 
```
python scripts/expert/generate_expert_config.py \
    --eval_dataset=<dataset_name> \
    --expert_scores_dir=<path_to_scores> \
    --output_path=<output_json_path> \
    --score_function=<token|gate> \
    --top_p=<threshold> \
    [--train_shared_experts] \
    [--train_non_expert_modules]
```

 
### Key Parameters

 
| Parameter | Description | Default |
|---|---|---|
| eval_dataset | Name of the dataset used for evaluation | (Required) |
| expert_scores_dir | Directory containing expert scores | (Required) |
| output_path | Path where the config file will be saved | (Required) |
| score_function | Which scoring method to use: "token" or "gate" | (Required) |
| top_p | Probability threshold for expert selection (0.0-1.0) | (Required) |
| train_shared_experts | Whether to train shared experts | False |
| train_non_expert_modules | Whether to train non-expert modules | False |

 Here's an example of how expert configuration generation is used in a typical workflow:

    --top_p=0.2

 - **Use Configuration for Training**: Pass the generated configuration to `train.py` or `train_ep.py`.

### Score Processing

 The script processes scores from multiple evaluation ranks (distributed evaluation results) to create a comprehensive view of expert performance:

 
 - For each layer, the system aggregates scores across all evaluation files
 - Both token counts and gate weights are tracked and normalized
 - The final scores are normalized across experts within each layer

## Hyperparameter Considerations

 The two main hyperparameters that control expert selection are:

 
 - **Score Function (`score_function`)**: Determines whether to use token counts (`token`) or gate weights (`gate`) for ranking experts
 - **Selection Threshold (`top_p`)**: Controls how many experts to select for each layer
 
 Higher `top_p` values select more experts, potentially improving performance but requiring more compute resources during training. Lower values are more computationally efficient but may limit model capabilities.

 The example in the codebase uses `top_p=0.2`, meaning experts are selected until their cumulative probability reaches 20%.
