# 讲透神经符号（Neuro-Symbolic）

> 神经符号（Neuro-Symbolic）是"**LLM 生成 + 符号验证**"的闭环——LLM 负责直觉生成（像人猜思路），符号系统（Lean4 / TLA+ / Z3）负责严格验证（像人写证明）。AlphaProof 用这个闭环拿 IMO 银牌，Delta-Prover 用它零微调达 95.9%，KVerus 用它验证真实 OS 内核。本系列讲清楚这个 2025-2026 最热的范式：**它的奇迹、它的陷阱（生成≠判别）、它为什么会重塑"AI 能否可信"的讨论**。

## 反模式 10 条

1. **把神经符号当银弹** → 它只验证你写了 spec 的性质，没写的全裸奔。正解：先列"必须可信"的性质清单，其余接受 best-effort。
2. **信任 LLM 生成的 spec 不做对抗** → VERISPECGEN 87% 通过率里的 25% 是语义偏移。正解：必跑 [02 对抗层]。
3. **prover/disprover 二元思维** → 现实 spec 大量"盲区"既不可证也不可驳。正解：加 adversarial 第三层。
4. **spec 一次写死不迭代** → spec 和代码一样需要 v1→v2。正解：用反例 trace 倒逼 spec 演化。
5. **混淆"类型检查通过"与"spec 正确"** → 类型检查只管语法。正解：语义正确性靠对抗层 + 人类 review。
6. **原子分解忽略隐含耦合** → "列表非空" + "首元素为 0"实际依赖。正解：分解后跑耦合检测。
7. **用随机 fuzz 代替语义导向生成** → 随机很难命中低概率边界。正解：LLM 按 spec 语义生成边界 trace。
8. **spec 越严越好** → 过严的 spec 会拒绝合法程序。正解：spec 严格度匹配真实约束，留意图。
9. **忽略 spec 的未言明假设** → 需求方心里有但嘴里没说的约束。正解：对抗层专门挖这些。
10. **把神经符号等同于"LLM + 编译器"** → 编译器只查语法，符号系统查语义。正解：用 Lean4/Z3/TLA+ 等带语义的逻辑系统。

## 选型决策树

```
你的需求是什么？
├─ 数学定理证明 → AlphaProof 路线（LLM 生成 + Lean4 验证）
├─ 程序正确性验证 → VERISPECGEN + 对抗层（NL→spec→adversarial）
├─ 系统不变量（如 OS 内核） → KVerus 路线（spec + 运行时检查）
├─ 需求合规检查 → NL→逻辑公式 + 反例生成
└─ 不确定 → 先用 [00] §五 判断系统域根本难点
```
