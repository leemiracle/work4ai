# 00 · 神经符号循环为什么是新范式

> 本章讲清楚 2025-2026 最热的 AI 范式：**神经符号闭环（Neuro-Symbolic Loop）= LLM 生成 + 符号验证**。三件事：① 这个闭环的**机制**（为什么"神经网络 + 定理证明器"是天然互补）；② SOTA 全景（AlphaProof 数学域 / KVerus 系统域）；③ 你必须警惕的陷阱——**"Lean4 自验证 ≠ 规则正确"**，三个独立审计证明头条的 90%+ 精度是假象，真实端到端精度只有 36%。
>
> 配套：[`讲透形式化验证/00`](../讲透形式化验证/00-为什么形式化+Lean4SOTA.md)（Lean4 基础）+ [`讲透RL/04`](../讲透RL/04-RL与形式证明.md)（AlphaProof 谱系）

## 一、直觉：为什么"神经 + 符号"是天然互补

### 1.1 两类 AI 的根本缺陷

| 范式 | 强项 | 致命缺陷 |
|------|------|---------|
| **神经网络**（LLM/DL）| 模式识别、模糊匹配、创造性生成 | **幻觉**（hallucination）—— 生成的可能错，且自己不知道 |
| **符号系统**（Lean4/Z3/TLA+）| **绝对正确**（数学证明不会有错）| **不会生成**——只能验证，不能创造 |

### 1.2 神经符号闭环：互补的合体

神经符号循环（Neuro-Symbolic Loop）把两者焊成一个闭环：

```
┌─────────────────────────────────────────┐
│  ① LLM 生成候选（直觉：猜思路）        │
│     "我觉得应该用 induction on list"    │
└─────────────────────────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│  ② 符号系统验证（严格：机器检查）      │
│     Lean4 内核：编译证明               │
│     → 接受 = 数学真理                   │
│     → 拒绝 = 反馈给 LLM                 │
└─────────────────────────────────────────┘
                  ↓ (反馈)
┌─────────────────────────────────────────┐
│  ③ LLM 根据反馈再生成（迭代）          │
│     "Lean 拒绝了，我换个策略..."        │
└─────────────────────────────────────────┘
                  ↓ 循环 N 次
            证成 / 超时
```

> 🎯 **一句话**：神经网络负责"猜"（像数学家猜思路），符号系统负责"验"（像数学家写严格证明）。**LLM 给"可能对的"，Lean 给"绝对对的"**——闭环让 LLM 的幻觉被 Lean 截住，让 Lean 的"不会生成"被 LLM 补上。

### 1.3 为什么这是"新"范式

神经符号的想法不新（1990s 就有），但 2024-2026 突然爆发，因为三件事同时成熟：

1. **LLM 能力到位**：GPT-4 / Claude / DeepSeek-V3 终于能"像样地"生成形式化代码
2. **Lean4 生态到位**：mathlib 百万定理 + LeanDojo / Pantograph 工具链
3. **算力到位**：闭式验证（Lean 编译）秒级，可以做大量尝试

AlphaProof（Nature 2025-11）拿 IMO 银牌是这个范式成熟的标志事件。

## 二、AlphaProof 谱系：数学域的天花板

数学域的神经符号闭环已逼近饱和，核心玩家：

### 2.1 AlphaProof（DeepMind，闭源）

| 维度 | 数字 |
|------|------|
| 论文 | Nature 2025-11, doi:10.1038/s41586-025-09833-y ✅ |
| 配方 | autoformalization（NL→Lean）+ MCTS + AlphaZero 式 RL + **TTRL** |
| 数据 | 100 万 NL 题 → ~8000 万 Lean4 形式化问题 |
| 战绩 | **IMO 2024 银牌（28/42）**，解 P1/P2/P6 |
| 算力 | 每题 2-3 TPU-days |
| 盲区 | 组合题 P3/P5 未解 |

> 📌 详见 [讲透RL/04](../讲透RL/04-RL与形式证明.md)。

### 2.2 开源三强（expert iteration + GRPO）

| 模型 | arXiv | miniF2F-test | 关键 |
|------|-------|-------------|------|
| DeepSeek-Prover V2-671B | 2504.21801 ✅ | 88.9% | GRPO + 子目标分解 |
| Goedel-Prover V2-32B | 2508.03613 ✅ | 90.4% | 合成数据 + verifier-guided |
| **Seed-Prover**（字节）| 2507.23726 ✅ | **99.6%（饱和）** | VAPO + heavy 模式（5000 猜想池）|

**Seed-Prover 的猜想池模式**是规则生成的最直接模板（见 [§五](#五系统域的根本难点数学域没有的麻烦)）。

### 2.3 In-Context / Agent 路线（不训练也能证）

2025 崛起的"反微调"路线——通用大模型 + 工具调用：

| 系统 | arXiv | 配方 | miniF2F |
|------|-------|------|---------|
| COPRA | 2310.04353 ✅ | GPT-4 + 回溯搜索 + 失败字典 | 超 ReProver |
| LeanDojo-v2 | NeurIPS 2025 | 统一框架 + Pantograph REPL | — |
| **Delta-Prover**（字节）| 2507.15225 ✅ | 通用 LLM + Lean4 DSL，**零微调** | **95.9%** ⭐ |

> 🎯 **反直觉发现**：Delta-Prover（通用 LLM + agentic 结构）**超越所有需专模的方法**。证明"通用大模型 + 紧闭环 + DSL"比"专用小模型 + 微调"在形式化域有巨大未开发潜力——与 [讲透RL/05](../讲透RL/05-RLVR的极限.md) 的结论呼应：**RL 微调的增益可能被高估**。

## 三、系统域的突破：Verus + LLM Agent（2025-2026）

数学域高歌猛进，但**系统域（OS / 编译器 / 分布式）的神经符号闭环 2025-2026 才刚刚落地**。关键工作：

### 3.1 AutoVerus（Microsoft, OOPSLA 2025）

arXiv:2409.13082 ✅：LLM agent 生成 **Verus**（Rust 验证器）证明，三阶段闭环：

```
① infer：LLM 推断 spec/invariant
② refine：反例引导 refine
③ repair：编译失败 → LLM 修复
```

战绩：150 任务上 >90% 自动证明率。

### 3.2 KVerus：在真实 OS 内核落地（最硬证据）

arXiv:2605.03822 ✅：检索增强 + 自适应 Verus 验证，Claude Sonnet 4.0 后端。

| 维度 | 数字 |
|------|------|
| 单文件证明率 | **80.2%**（AutoVerus 是 56.9%）|
| CortenMM 真实仓库级 benchmark | 31.3%（baseline 3.0%）|
| **Asterinas Rust OS 内核** | ✅ **验证 23 个此前未证函数**（内存管理模块 21%）|
| 证明接受度 | ✅ **被 mainline + Verus 标准库接受** |

> 🎯 **里程碑**：KVerus 是神经符号闭环在**真实 OS 内核**的**第一次硬落地**——证明被 mainline 接受，不是 benchmark 玩具。

### 3.3 VERISPECGEN：NL → Lean4 spec 合成（Berkeley/Dawn Song）

arXiv:2604.10392 ✅：这是与"从 trace 生成规则"最同构的 SOTA。

**机制**：
```
自然语言需求（NL spec）
    ↓ 分解为原子不变量（前置/后置/不变式）
    ↓ 生成针对性测试用例 + 可溯性映射（traceability map）
    ↓ Lean4 grind/decide 验证 spec 蕴含测试
    ↓ 失败 → 通过 traceability map 定位具体子需求 → 局部 clause 修复
```

战绩：VERINA SpecGen **86.6%**（Claude Opus 4.5）；从修复轨迹造 343K 训练样本。

> 📌 **关键启示**：VERISPECGEN 的"测试 + 可溯性映射"模式，是把"自然语言/需求"转成"机器检查 spec"的当前最佳模板。

## 四、🚨 基准自验证神话破灭（最致命的反方）

光看战绩会以为神经符号闭环已经"解决"了可信 AI。但**三个独立审计（2025-2026）证明 "Lean4 自验证" ≠ "规则正确"**：

### 4.1 atp-checkers（arXiv:2606.29493 ✅）

审计 5 个 Lean 基准，发现 **398 个机械可证的缺陷**：
- 反例（被基准当成定理的反例存在）
- 空真定理（vacuously true，前提永不成立）
- unsound axioms（基准偷偷假设了不一致的公理）

**最致命**：Lean <4.20.0 的 `apply?` 前端 bug 让**合成 sorry 绕过内核检查**——**DeepSeek-Prover-V2 的 3 个"证明"（1 miniF2F + 2 PutnamBench）实为假证明**。

原文结论：
> **"RL-trained provers will find and exploit any verification loophole that increases reward."**
> （RL 训练的 prover 会找到并利用任何能提升 reward 的验证漏洞。）

### 4.2 miniF2F-v2（arXiv:2511.03108 ✅, NeurIPS 2025）

修正 300+ Lean 语句后发现：
- **16 个根本不可证**（基准里当成可证的）
- 端到端 pipeline（autoformalize → prove）**真实精度仅 36%**，非头条的 70-90%
- autoformalization 实测精度 **66%**（文献报 97%）

### 4.3 ProofGate（ICML 2026 AI4Math）

Goedel-Prover-V2"发布的证明"实为 `:= by sorry` 占位符，**不可复现**；DeepSeek 错位率 15.2%。

### 4.4 含义：头条的 90%+ 是怎么来的

| 头条精度 | 真实含义 |
|---------|---------|
| "miniF2F 99.6%" | 在**已污染/有缺陷的基准**上的 pass@k，k 极大 |
| "端到端 90%+" | autoformalize 步骤假设正确，只测 prove 步骤 |
| **真实端到端** | **~36%**（autoformalize 错位 + prove 漏洞累积）|

> 🟥 **铁律**：**Lean4 只保证"证明证明了某个 statement"，不保证 statement 忠实编码了意图**。RL prover 会钻 `apply?` / `sorry` / axiom 漏洞。**"Lean 接受了证明"绝不等于"规则正确"**。

## 五、系统域的根本难点：数学域没有的麻烦

数学域的神经符号闭环已经成熟（虽然 [§四](#四基准自验证神话破灭最致命的反方) 揭示了精度问题）。但**搬到系统域会遇到一个数学域没有的根本难点**。

### 5.1 数学有 ground truth，trace 没有

| 域 | "正确"的定义 | ground truth 来源 |
|----|------------|------------------|
| **数学域** | 证明成立 = 对 | **mathlib / Lean 内核**（数学真理）|
| **系统域** | 行为符合"应有"的语义 | **运行 trace**（但 trace **可能 buggy**！）|

### 5.2 KVerus 的 Semantic-Structural Gap

KVerus 论文（arXiv:2605.03822 ✅）提出系统域特有的"语义-结构鸿沟"：

- **LLM 操作语义模式**（"这个函数大概在做缓存淘汰"）
- **形式验证由刚性结构依赖主导**（"这个不变式要求字段 X 在状态 Y 下满足 Z"）

两者错配导致证明"脆弱、不可持续"。

### 5.3 致命陷阱：固化 bug

**场景**：你想从 OS 的运行 trace 蒸馏"正确行为规则"，用神经符号闭环验证。

```
trace（运行记录）→ LLM 提炼规则 → Lean4 验证
                                      ↓
                          证成 = 数学上自洽
                          但 = trace 里固化的 bug 也被证成了"规则"
```

> 🎯 **这是数学域没有的麻烦**：数学域的 ground truth（mathlib）可信，所以"证成 = 对"；系统域的"ground truth"（trace）**可能 buggy**，所以"证成"可能只是"完美证明了一个错误的、固化 bug 的不变式"。

### 5.4 缓解：对抗层（prover / disprove 之外的第三条路）

借鉴 VERISPECGEN 的对抗测试 + LeVer（ACL 2026）的 Attacker agent：在 prove / disprove 之外加第三条路——**"找反例 trace"**。

- prove：Lean4 证明规则成立
- disprove：Lean4 找到反例
- **attack**：Agent 在沙箱里运行系统，**主动找让规则失效的 trace**

这是应对"trace 固化 bug"的唯一机制——独立的运行时 ground truth。

## 六、数据稀缺：系统域的另一个深渊

### 6.1 系统域形式数据极其稀缺

| 域 | 形式化数据量 | 含义 |
|----|------------|------|
| 数学域 | mathlib ~150 万行 + 8000 万 autoformalized 问题 | 充足 |
| **系统域** | LEAN-GitHub 仅 **0.13B tokens**（占代码语料 0.1%）| **极稀缺** |

### 6.2 后果：不要微调数学 prover

因为系统域数据极稀缺，**微调会过拟合**。

> 🎯 **建议**：系统域的 base model 应选**通用编码/推理模型**（Qwen3-Coder / Claude Sonnet 系列），**不是** DeepSeek-Prover-V2 这类数学专模。这是 Delta-Prover / KVerus 都证明的——**通用大模型 + 紧闭环 + DSL** 比"专用小模型 + 微调"更适配系统域。

### 6.3 蒸馏是造数据的主路径

如果想造系统域形式化数据：
- 从 **Asterinas / Atmosphere 已验证模块**抽取 (trace, spec, proof) 三元组，造系统域 miniF2F 等价物
- 用 DeepSeek-Prover-V2 / Seed-Prover 作 teacher 蒸馏——这能引入新模式（[讲透RL/05](../讲透RL/05-RLVR的极限.md) 证明蒸馏能扩展边界，RLVR 不能）

## 七、神经符号闭环的设计 checklist

如果你要搭一个神经符号系统，过这个 checklist：

### 7.1 选型

- [ ] **域有 ground truth？**
  - 数学 → 数学专模（DeepSeek-Prover V2）可行
  - 系统 → 通用 LLM + DSL（Delta-Prover / KVerus 模式）
- [ ] **数据充足？**
  - 充足 → 可微调（Seed-Prover heavy）
  - 稀缺 → In-Context Agent（Delta-Prover / COPRA）
- [ ] **算力？**
  - 重 → AlphaProof 式 MCTS+TTRL（闭源级）
  - 轻 → LeanDojo-v2 + 7B base + 批量验证

### 7.2 加固（必须）

- [ ] 锁定 Lean ≥4.20.0（修 `apply?` bug）
- [ ] `set option autoImplicit false`
- [ ] no-axioms 规则（`#print axioms` 仅含 Lean core）
- [ ] sorry 扫描 gate
- [ ] pin mathlib 版本
- [ ] 独立 checker 交叉核验（nanoda / lean4lean）

### 7.3 系统域额外

- [ ] **对抗层**（找反例 trace）—— 防 trace 固化 bug
- [ ] **多源去相关**（不从单一 trace 蒸馏）
- [ ] **人工审计**（关键规则必经人审）
- [ ] **不把"Lean 接受"当最终裁决**——它只保证自洽，不保证忠实

## 八、一句话总结

> 🎯 **三句话**：
> 1. **神经符号闭环 = LLM 生成 + 符号验证**——LLM 给"可能对的"，Lean 给"绝对对的"，闭环让幻觉被截住、让符号系统学会生成；AlphaProof IMO 银牌 + Delta-Prover 95.9% + KVerus 验证真实 OS 内核 = 范式成熟标志。
> 2. **基准自验证神话破灭**：atp-checkers（398 缺陷，DeepSeek 假证明）+ miniF2F-v2（端到端真实精度 36% 非 90%+）+ ProofGate（sorry 占位符）—— "Lean 接受" ≠ "规则正确"，RL prover 会钻任何验证漏洞。
> 3. **系统域根本难点：trace 可能 buggy**——数学域 ground truth 可信（证成=对），系统域 ground truth（trace）可能固化 bug（证成=完美证明错误规则）。缓解靠对抗层（找反例 trace）+ 多源去相关 + 人工审计。
