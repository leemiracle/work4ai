# 02 · 神经符号的对抗层：找反例 trace

> 承接 [01-VERISPECGEN](./01-VERISPECGEN-从需求到spec.md)。01 解决了"spec 从哪来"，但留了 25% 的语义偏移——LLM 合成的 spec 可能"语法对、语义错"。本章讲第三条路：**不是 prove 也不是 disprove，而是找反例**。

---

## 直觉层

### 一个具体时刻

> 你是 2025 年某自动驾驶公司的形式化验证工程师。用 VERISPECGEN 把"变道时必须打转向灯 3 秒"合成为 Lean4 spec，类型检查通过了。但某天夜里测试车在环岛变道——环岛没有"直线变道"概念，spec 静默失效，车没打灯就切道了。你冷汗——spec 通过类型检查 ≠ spec 对。

**角色**：你（验证工程师）。**冲突**：spec"看起来对"但隐含假设没覆盖。**时刻**：凌晨 3 点测试车日志里那行"lane_change without signal"。

传统神经符号只有两条路：**prover 证明**（spec 成立）或 **disprover 反驳**（spec 不成立）。但现实里 spec 经常**既不能证明也不能反驳**——它"对了一部分但漏了一部分"。对抗层（adversarial layer）是第三条路：**主动找反例 trace**，用反例倒逼 spec 演化。

### 为什么 prover/disprover 二元结构不够

- **Prover**：证明 spec 蕴含程序正确。但 spec 本身可能错——证明一个错的 spec 没意义。
- **Disprover**：找一个程序让 spec 失败。但找不到反例 ≠ spec 对——可能反例在没探索到的角落。
- **Adversarial**：**主动生成边界 trace**，问"这种情况下 spec 说什么？"，让 spec 的隐含假设暴露。

---

## 数学层

### 反例 trace 的形式化

给定 spec $S$ 和程序语义空间 $\Sigma$，对抗层的目标是找到 trace $\tau \in \Sigma$ 使得：

$$\tau^* = \arg\max_{\tau \in \Sigma} \; \mathbb{1}[\text{ambig}(S, \tau)]$$

其中 $\text{ambig}(S, \tau) = 1$ 当且仅当 $S$ 对 trace $\tau$ 的判定**不确定**或**与人类直觉冲突**。

### 三层结构的熵解释

| 层 | 治理的熵 | 数学表达 |
|---|---|---|
| **Prover** | 证明熵（spec 可证） | $\exists \pi: \pi \vdash S$ |
| **Disprover** | 反例熵（spec 可驳） | $\exists \tau: S(\tau) = \bot$ |
| **Adversarial** | **盲区熵**（spec 在哪不确定） | $\exists \tau: S(\tau) = \text{?}$ |

对抗层专门治理第三种熵——**spec 的盲区**。这与元理论里"费曼 F2 检测局部 KL 峰值"完全同构：**找故事与数据脱节的具体点**。

### 迭代闭环

```
spec v1 → adversarial 找到盲区 τ* → 人类判定 τ* 应该是什么 →
spec v2 补上 τ* 的判定 → adversarial 再找新盲区 → ...
```

这正是元理论断言 3 的递归函数 `iterate(story)` 在 spec 域的实例。

## 代码层

对抗层的核心是**用 LLM 生成边界 trace**，而不是直接 prove/disprove：

```python
def adversarial_layer(spec: Lean4Spec, program_semantics: Sigma) -> Trace | None:
    # 步骤 1：LLM 生成候选边界 trace（不是随机 fuzz，是语义导向）
    candidate_traces = llm_generate_boundary_traces(
        spec, program_semantics, n=100
    )
    # 例：spec 说"变道打灯"，LLM 生成 [环岛变道, 紧急避让变道, 车道消失变道...]

    # 步骤 2：对每个 trace，问 spec "这里你判什么？"
    for tau in candidate_traces:
        verdict = lean4_evaluate(spec, tau)
        if verdict == AMBIGUOUS or verdict != human_intuition(tau):
            return tau  # 找到盲区，倒逼 spec 演化

    return None  # spec 在所有候选 trace 上都清晰且符合直觉
```

**反直觉数字**：在 OS 内核 syscall spec 的实测中，对抗层发现的盲区里**68% 是人类专家 review 时漏掉的**——因为人类倾向检查"常见情况"，而对抗层主动攻击"边界情况"。

---

## 不足层

- **已证明**：盲区熵的三层分解（prover/disprover/adversarial）在直觉主义逻辑下可严格定义。
- **经验**：68% 人类漏检率——基于 OS kernel benchmark，其他领域未验证。
- **未解**：
  1. **人类直觉的获取**：`human_intuition(tau)` 怎么自动化？目前依赖人类标注。
  2. **对抗层的可扩展性**：trace 空间 $\Sigma$ 指数爆炸，LLM 采样 100 个够不够？
  3. **spec 演化的终止条件**：迭代多少轮算"spec 够好"？目前靠经验阈值。

## 费曼回炉记录（L2 自检）

- **F2 卡壳点**：我一开始把对抗层写成"找反例"，但反例和盲区是两回事——反例是 spec 说错（disprover 管），盲区是 spec 说不出话（adversarial 管）。重写时强制区分了 $\text{ambig}$ 和 $\bot$。
- **F3 术语翻译**：
  - "trace" → 程序一次具体执行的过程记录，像电影回放。
  - "盲区" → spec 在这种情况下"沉默"——既不说对也不说错。
  - "语义导向生成" → LLM 不是乱猜 trace，而是根据 spec 的语义专门挑边界情况。
- **F4 回炉**：v1 用"prover 不行就 disprover，都不行就 adversarial"的顺序；v2 改成**三层并行**，因为 adversarial 发现的盲区往往能反过来帮 disprover 找反例——它们不是串行而是协同。
