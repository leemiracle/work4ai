# 04 · 中国哲学史转代码:思想史怎么接上键盘

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(古籍 NLP 与概念谱系工具)。

---

## 开篇:先立字据

把中国哲学史「转代码」,第一反应往往是两派:
一派觉得荒谬(义理岂能计算),一派觉得多余( Humanities 要什么代码)。
本家族的立场先立三条:

1. **能转的**:03 章四个自产数据结构的外壳——编年记录、注疏层级、
   谱系连线、概念用例——全部可入库可计算;文本的形式特征
   (词频/共现/异文对读)是概念史的第一层证据。
2. **不能转的**:义理判读(「理」的意义跃迁)、诠释创造(「接着讲」)、
   谱系的立场裁决(哪条道统线是对的)——工具到证据层为止,
   判读永远交还给人。
3. **转的时候的红线**:凡概念表必须申报编者立场(谁选的词、
   按哪家的训释);凡谱系图必须多版本并存(谁画的线算谁的,
   不做合并权威版);凡词频必须配语义判读层(02 章红区三)。

一句话:**代码是思想史的显微镜,不是思想史的法官**。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 哲学对象 | 代码化身 | 备注 |
|---------|---------|------|
| 大事编年(七次转场) | 时代×学派×人物×概念的记录表+密度统计 | 本家族实验脚本即最小版;密度断言对单条错位稳健(03 章红区二) |
| 概念用例(训诂的原料) | 词频/共现/分布对比 | 戴震《字义疏证》的手工操作可计算化(02 章美之时刻 4) |
| 注疏层级(堆栈) | 文本-层级-态度的三轴标注库 | (所据经文位置,所释层级,护/驳/补)三字段即 schema(03 章 §二) |
| 谱系连线(道统/师承) | 人物-师承-归属的图(多版本) | 立场性数据,多版本并存是入库前提(03 章红区四) |
| 卦象系统 | 6 bit 状态空间+变爻变换 | 纯离散对象,天然可算(03 章 §一) |
| 异文对读(版本学) | 文本 diff+对校本合并 | 出土本与传世本的对读(郭店《老子》vs 王弼本)是 diff 的哲学版 |

**转不动的边界(红色区)**:

1. **义理判读不可外包**。「理」从玉之纹理到天理的语义跃迁,
   词频曲线只给证据,判读需要训诂+义理双素养——LLM 的「伪接着讲」
   (流畅的六经注我)恰恰是这里最大的风险:格式的合法性不等于
   诠释的合格性。工程对策:判读字段永不由模型填,或必须标注人审。
2. **谱系不可合并权威版**。朱熹道统、禅门法统、《宋元学案》连线
   互不相同且各有道理——合并即判教。工程对策:边带 provenance
   (谁画的线),查询按版本分账。
3. **断代与系年不可单点断言**。先秦系年全带误差棒,
   「老子早于孔子」不可作为硬约束入库。工程对策:日期区间+
   系年依据字段;一切断言只在统计密度层成立。
4. **「中国有无哲学」不可回归**。这是定义权之争(00 章 §四),
   用任何指标(论证密度/范畴数量)「验证」它都是范畴错误——
   指标只能描述筛子,不能裁决筛子。

## 二、代码走廊清单(两条走廊,每条=对象→数据结构→算法→真实系统)

### 走廊 1:思想史数据库——把编年与谱系做成可查的库

```
史料(正史艺文志/学案/年谱/出土简牍)
   │  抽取(年代区间,学派,人物,概念,系年依据)
   ▼
记录表(84+ 条起)──时代切片──▶ 密度统计 ──▶ 七次转场的量化侧写
   │                                        │
   └──人物-师承-归属图(多版本谱系)◀──道统对照(谁的版本)
```

- **对象→结构**:本家族 `experiments/00_pre_qin_timeline.py` 是这条走廊的
  最小成品:84 条「年代×学派×人物×概念/事件」,断代×学派双维切片,
  断言三连(轴心期密度为古代之冠/理学概念是宋明断代指纹/近代西学事件连锁在场)。
- **算法层**:按断代桶聚合(密度=条数/百年)、按学派分组计数、
  关键词指纹匹配(概念词条命中即断代证据)——纯标准库
  (`dict`+`Counter`)即可起步,毫无依赖。
- **可检验的哲学命题**(走廊的灵魂):
  ①「轴心突破」命题(雅斯贝尔斯/余英时):诸子密度是否显著高于
  其前后诸断代——密度断言 A 的直接对象;
  ②「理学是范畴革命」命题:太极/天理/心即理/良知这组双字概念
  是否只在宋明窗口出现——断言 B 的指纹逻辑;
  ③「西学东渐是连锁事件」:1840-1949 窗口西学标记词是否密集在场
  ——断言 C。
  三个老论断在数据层变成可复查的对象——**密度不证明思想,
  但把「感觉」升级为「证据」**。
- **真实系统**:中国哲学书电子化计划(ctext.org,先秦两汉文献的
  开放文库+工具)、CBETA 电子佛典(佛学中国化段的核心语料)、
  各类基本古籍库;学术侧的 CBDB(中国历代人物传记资料库)
  正是「人物-关系-时间」的专业化实现。
- **性能工程要点**:断代桶的边界即解释(1840/1919 是 GB/T+思想史
  双重约定的切口)——桶变了曲线就变,敏感性分析(桶宽扫描)
  必须随结果交付;系年争议字段不可省略(省略=假装确定)。

### 走廊 2:概念史词频与概念谱系工具——把训诂做成管道

```
历代文本(分语料库:先秦/两汉/唐/宋/清……)
   │  分词与概念表(编者立场申报!)
   ▼
概念标注语料 ──▶ 词频年代分布 ──▶ 语义漂移的证据层
   │                                    │
   ├──共现网络(心-性-理-气的亲和结构)  │人审判读层
   └──注疏层级标注(经/注/疏分行)      ▼
                              范畴史(如「理」的谱系图)
```

- **对象→结构**:概念表=每个核心范畴的词族(理≈{理,天理,条理,
  义理,分理};诚≈{诚,诚信,诚者})——**词族划分本身就是一次
  立场申报**(按朱熹的「理」还是戴震的「理」归并,结果不同);
  语料按断代+文体分层(子书/注疏/语录的词频不可混桶)。
- **算法层**:分层词频(概念的断代指纹)、共现 PMI(心-性-理-气的
  结构是理学的还是先秦的)、逐注疏层的分布对比(朱熹《集注》
  相对二程语录的概念增量)——`collections.Counter`+字典共现
  即可起步;进阶接 embedding 做语义漂移检测(注意:embedding 的
  训练语料自带时代偏差,需申报)。
- **可检验的哲学命题**:①戴震命题:「宋儒之理是后世意义漂移」——
  「理」字在先秦语料的用例分布(多为「分理/条理/治理」义)与
  宋明语录(「天理」复合词占比陡增)是否分层;
  ②佛学中国化命题:格义期(晋)译经的玄学词(无/自然)密度
  是否显著高于唐以后新译——概念替换的量化侧写;
  ③「接着讲」的密度证据:现代新儒家文献中先秦概念与康德术语的
  共现结构。
- **真实系统**:ctext.org 的文本工具(检索/词典)、数字人文界的
  古籍词频与共现分析流程( Voyant/R/Python 生态)、
  「汉典重光」等古籍数字化项目(OCR 与整理,方向锚,01 章主线 E)。
- **性能工程要点**:文言分词没有空格可偷懒——概念表优先于分词器
  (最长匹配+词族归并即可绕过大半分词难题,这是古籍 NLP 的
  第一条捷径);异体字/繁简归一(理=理?「无/無」)是必须前置的
  脏活;样本量小的桶(隋唐语录残)不给词频结论。

## 三、工程师落点:古籍 NLP 与概念谱系工具

这是本家族 2021-2026 最热的工程接口(01 章主线 E),
也是工程师**带着手艺入场**的地方:

| 任务(思想史侧的需求) | 工程形态(你能做的) | 难点即研究 |
|----------------------|---------------------|-----------|
| 自动标点/断句 | 序列标注模型在文言文上的适配 | 义理层的标点错误最难发现(「民可使由之不可使知之」的歧义断句是哲学问题) |
| 繁简/异体归一 | 字表工程+上下文消歧 | 「发/髮」「余/餘」类一对多;出土文献的隶定字无标准码位 |
| 概念检索与词族归并 | 概念表+最长匹配+共现扩展 | 词族划分=立场申报(走廊 2 的红线) |
| 注疏层级解析 | 版式+引文识别→经注疏分行入库 | 「注不驳经」的层间引用格式因刊本而异 |
| 谱系可视化 | 人物-师承-归属的多版本图(道统图生成器) | 边带 provenance;不做合并权威版(红区 2) |
| 出土文献对读 | 简序重排+异文 diff(郭店本 vs 传世本) | 简序即系年即思想史(《老子》甲乙丙组的分合是哲学问题) |

**三步法(一个最小可行研究)**:
直觉图像——把《论语集注》的一个条目想象成一条带多层评论的
 commit 记录:经文是原始提交,程子曰是引用的旧 patch,
 朱子自己的圈发是最新的 rebase;
严格陈述——取一概念(如「学」),在先秦子书、汉注、宋《集注》
三个语料层各统计其共现邻居(「学」邻「礼」还是邻「理」),
共现结构的迁移即概念语义漂移的证据层;
最小例子——手工完成三层的各一百条用例摘录(一上午的工作量),
你就有了一篇可答辩的概念史札记的实证部分——
**这个规模不需要写代码,需要的是纪律**;代码把规模放大一百倍,
不改变证据/判读的两层结构。

**工程师的独特杠杆**:
- 你**读得懂**语料库的构建管道——语料偏差(传世文献的幸存者偏差,
  00 章 §五)在管道里最容易被声明;
- 你能把「概念表立场」「谱系多版本」做成系统的 first-class citizen,
  而不是事后补丁——人文数据的 provenance 设计是真工程问题;
- LLM 时代你在结构性位置:自动标点、白话翻译、引文定位的准确率
  每提高一档,思想史的语料就变厚一档;同时「伪接着讲」的风险
  也由你的评估层把关(红区 1)。

## 四、可机械化的检验仪式(把本家族用成瑞士军刀)

遇到任何「思想史断言」,做三问:
1. **证据问**:这个断言的证据层是什么(文本可查/密度可算/纯义理推断)?
   可算的部分,指标是什么、桶在哪切?
2. **立场问**:证据的编者是谁(概念表谁定的/谱系谁画的/断代谁系的)?
   换一个立场申报,结论变不变?
3. **反事实问**:如果出土一批新文献,这个断言的哪部分会动?
   完全不动的部分,是不是本来就不在证据层(那它在哪个层说话)?

三问过完,断言的「可机械化含量」就裸露了——
剩下的才是纯义理问题(它们不是残余,是主菜)。
(对照数学宇宙数学史家族的「敏感性分析是正确姿势」:
那边换选样重跑,这边换立场申报重跑——同一种史学纪律。)

## 📌 收束 + 🧭 新眼睛(认知升维)

**兑现之眼**:看到任何思想史断言,先问它的证据层可不可算;
看到任何古籍数字工具,先问它的概念表立场申报了没;
看到任何自动标点的古文,先数一数那些「机器不会错、错了就要命」
的义理层断句。

本家族的转代码不是让思想史变快,而是让思想史**可复查**——
引文可以被误引,跑出来的密度很难被抵赖;
而判读永远留在人这边,这不是谦逊,是这门学问的结构。
