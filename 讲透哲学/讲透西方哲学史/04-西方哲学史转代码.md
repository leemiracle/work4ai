# 04 · 西方哲学史转代码:谱系怎么接上键盘

> **本章回答五问之五(Q5):这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(知识本体工程)。

---

## 开篇:两个先要拆掉的雷

把哲学史"转代码",第一反应分成两派:
一派觉得荒谬(两千年的思辨,关代码什么事);
一派觉得轻佻(把黑格尔写进 Python,是对双方的侮辱)。

本家族的立场先立字据:

1. **能转的**:术语的**概念史**(词频/共现/义项漂移——01 章主线 D 的
   「归摄」钻头可计算化)、编年与谱系的**结构**(03 章三大构造物全部可数字化)、
   正典的**统计画像**(谁被教、被谁引)。
2. **不能转的**:**语境判断**(这段话在跟谁吵架)、**义项判定**
   (同一个词这次是不是换脑了)、**哲学价值**(谁更深刻)、
   **"影响"的因果裁断——史学与哲学的最终判断权不可外包。
3. **转的时候的红线**:凡是术语统计,必须申报**词表与切分歧义的处理方式**
   (同一术语的多译名/多义项是数据质量的天花板);凡是谱系图,
   必须区分"机器提的候选边"与"人裁的认定边"。

一句话:代码是哲学史的**望远镜**,不是哲学史家——
它让谱系可检索、让断言可复查,但不替你读原文。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 哲学史对象 | 代码化身 | 备注 |
|-----------|---------|------|
| 术语概念史 | 词频/共现/语义漂移管道 | 「归摄」从康德到马克思的迁徙可被词分布追踪(走廊 1) |
| 大事编年 | 事件四元组+时期切片 | 本家族 `experiments/00_philosophy_timeline.py` 即最小版 |
| 概念谱系 | 有向图+三色边(候选) | 机器提候选边,人裁边类型(03 章 §二) |
| 论证标准形 | 前提-结论结构化数据 | 重构本身是人活,存成数据后可检索/可统计(形式家族计数) |
| 正典画像 | 作者×时代×引用矩阵 | "谁被写进教材"的量化(01 章主线 A 的工具侧) |
| 接受网络 | 传播图+变形记录 | 文本旅程的版本树(03 章 §四) |

**转不动的边界(红色区)**:

1. **义项判定不可全自动**:同一个 substantia,这次是"承载体"还是"个体实体"?
   词形相同、义项不同——任何不处理多义项的词频统计都是在测量噪声。
   工程对策:义项表人工维护,统计按义项聚合而不是按词形。
2. **"影响"不可由共现判**:文本相似+时间在后≠受影响(共同源头、
   时代套话都会伪造信号)。工程对策:候选边只入"待审池",
   认定边必须有人工证据对(03 章"证据成对"规则)。
3. **语境不可省略**:重构论证时删掉的那一半文本(修辞、论战对象、体裁惯例)
   恰恰是史学家的主料。工程对策:标准形数据必须**回链原文位置**
   (贝克尔页码/DK 残篇号),让"删掉的一半"一键可回。
4. **进步不可拟合**:没有"更对"的度量函数;任何给哲学史算"进步指数"的
   脚本都是把史学立场伪装成数学(00 章 §5 圣杯问题的工程表述)。

## 二、代码走廊清单(两条走廊,每条=对象→数据结构→算法→真实系统)

### 走廊 1:哲学术语概念史——把一个词的两千年变成一条管道

```
多语语料(希腊/拉丁/德/英/中译本)
   │ 词表工程(术语→{原文形,译名集,义项集})
   ▼
义项标注语料 ──窗口共现──▶ 义项共现网络
   │                            │
   按时代切片                    漂移检测(义项亲和度的时间差分)
   ▼                            ▼
词频曲线(显要度)      迁移报告(哪个义项何时接班)
```

- **对象→结构**:术语表是走廊的地基——
  例:subsumption/归摄 ≈ {subsumere, subsumption, 归摄, 包摄,……}
  × 义项 {逻辑归摄(判断), 康德判断力难题, 黑格尔具体普遍, 马克思实质归摄}。
  数据结构=按年代切片的文档流+义项字典。
- **算法层**:`collections.Counter` 词频;滑动窗口共现矩阵;
  按时代排序的义项占比转移(哪个义项何时成为默认义)——纯标准库可起步。
- **可检验的哲学史命题**(走廊的灵魂):
  ①"实体"在 1277 之后是否出现"个体化"义项的占比上升(唯名论的压力)?
  ②「归摄」在康德与黑格尔文本中的共现伙伴是否从"判断"换成"概念"?
  ——经典断代争论(02 章 §三)在词汇分布层面**可判分、可复查**。
- **真实系统**:数字人文的 TLG(希腊语文献库)/Corpus Thomisticum/
  牛津国家语料库工具链;概念史研究的 HistSemantics 方向;
  Voyant/Python 文本分析环境。
- **性能工程要点**:多语对齐与译名归一是本走廊的脏活——
  词表质量上限决定一切(垃圾进垃圾出);窗口敏感性分析必做;
  语料的**时代分层**比语料规模更关键(全库混算会把 19 世纪的
  "substance"用法算到亚里士多德头上)。

### 走廊 2:数字人文编年与谱系——把 03 章的构造物跑起来

```
事件表(年代×人物×事件×概念) ──密度切片──▶ 时期画像(双峰检验)
        │
概念标签 ──时期重合度──▶ 术语更替率(换弹药检验)
        │
谱系边(候选:文本相似/师承/引用) ──人工认定──▶ 三色边谱系图
```

- **对象→结构**:本家族实验脚本即最小版:70+ 条四元组,按 GB/T 六支
  对应的时期切片,断言两个密度峰(古典希腊/十七十八世纪)与
  相邻时期概念标签低重合(术语随时期更替)。
- **算法层**:时期密度=事件数/(跨年/100);标签重合=Jaccard(相邻时期
  概念标签集合);谱系边的候选生成(共时代+共术语+师承关系的三重过滤)。
- **可检验的哲学史命题**:①"哲学史事件在时间上均匀吗?"(不——双峰,
  教学叙事的"重点章节"有数据形状);②"每个时代用同一套概念武器吗?"
  (不——更替率高,为 02 章"时代隔离律"提供量化注脚)。
- **更大规模的同型研究**:人物师承网络(苏格拉底→柏拉图→亚里士多德→
  ……的学术族谱与数学家谱系计划同构,见
  [../../讲透数学/讲透数学史/README.md](../../讲透数学/讲透数学史/README.md)
  的谱系树);教材正典的百年变迁(用不同年代教材目录做差分——
  01 章主线 A"范围重划"的实证版)。
- **性能工程要点**:编年数据的**口径声明**必须前置(什么算"大事"?
  口径即立场);断言要留余量(密度对比用倍数不用显著性——
  小样本事件流的统计检验容易自我欺骗)。

## 三、工程师落点:知识本体工程(本家族的前线阵地)

这是哲学史训练在 2026 年最直接兑现的工程职业——
**知识本体工程师**(ontologist):给领域知识建"存在论清单"
(类、属性、关系、公理),干的活正是亚里士多德《范畴篇》的工业版。

| 哲学史装备(工程师已有) | 本体工程现场(可直接上岗) |
|------------------------|--------------------------|
| 亚里士多德十范畴(实体/性质/关系/…) | 顶层本体设计(BFO/DOLCE 的范畴表) |
| 属+种差的定义法 | 类定义标准写法(owl:Class 的必要充分条件) |
| 共相之争(唯名论 vs 实在论) | 类与实例的建模决策("疾病"类真实存在还是编码便利?) |
| 奥卡姆剃刀 | 本体工程第一军规:entia non sunt multiplicanda——不要为同一批数据造两个类 |
| 波菲利树(属种层次) | 分类体系/知识图谱的层级设计(继承与多继承) |
| 奎内-实体同一性问题(××是××吗) | URI 命名与同一性对齐(同一个概念两个库怎么合并) |
| 中世纪 quaestio(正反论证) | 本体验证的 competency questions(能力问题清单) |

- **行业现场**:生物医药本体(OBO Foundry)、企业知识图谱、
  LLM 时代的结构化知识源(RAG 的知识层)——都在招"会画范畴表的人"。
- **三步法(一个最小可行练习)**:
  直觉图像——给自己熟悉的系统(比如一家公司的工单)画一张"波菲利树":
  什么是它的实体、什么只是性质;
  严格陈述——用属+种差写五个类定义,标出每个定义的必要条件与充分条件,
  找出"既可归 A 又可归 B"的边界案例(共相之争会在你自己的表里重演);
  最小例子——用 30 行 Python 字典表达这张树(类→属性→父类),
  写一个查询"找出某实例的全部祖先类"——多继承一出现,
  你就亲手撞上中世纪学者撞过的那堵墙。
- **为什么哲学史训练在这里值钱**:本体工程的深坑从来不是语法
  (OWL 三个月能学完),而是**范畴判断**——什么该是类、什么该是属性、
  何时拆分、何时合并。这些判断的判例库,就是两千年的西方哲学史。

**红线重申**(承 §一):本体是**约定**不是发现——
你的类层次是设计决策(带利益与代价),不是世界结构的不动点;
宣称"本体=实在本身"的工程师,正在重演中世纪实在论最重的翻车现场。

## 四、可机械化的检验仪式(把本家族用成瑞士军刀)

遇到任何"知识组织"任务(文档分类/标签体系/知识库 schema),做三问:
1. **范畴问**:这套类是发现的还是规定的?谁是类,谁只是属性?
   拆分标准统一吗(同一个划分轴吗)?
2. **历史问**:这套分类是何时、为解决什么问题发明的?
   那个问题还在吗(分类的遗产税)?
3. **边界问**:最能打的边界案例是什么(既像 A 又像 B 的那个实例)?
   分类体系的质量藏在边界案例里,不在 happy path 里。

三问过完,任何知识系统的范畴骨架就裸露了——
剩下的才是纯技术问题。(对照马克思主义哲学家族的三问仪式:
那边裸露社会骨架,这边裸露范畴骨架;两问叠用,知识系统的两层一起现形。)

**户口眼**:见任何分类体系(标签系统/知识图谱/目录),
先问它的范畴表是谁、何时、以什么划分为轴立的法——
本体有户口,而且户口很年轻;两千年的范畴争论是你的判例库。
本家族的转代码不是让哲学史变快,而是让哲学史**可复查**——
谱系可以画错,跑出来的密度与更替率很难被抵赖。
