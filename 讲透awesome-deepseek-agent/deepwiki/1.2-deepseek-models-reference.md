It serves as the foundational reference for all tool-specific integration guides in this repository, ensuring consistent configuration of model identifiers, context windows, and reasoning capabilities.

 
## Model Identifiers and Capabilities

 DeepSeek currently maintains two primary model identifiers. As of April 2026, all legacy identifiers (e.g., `deepseek-chat`, `deepseek-reasoner`) are deprecated and must not be used in configurations [CONTRIBUTING.md27-35](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/CONTRIBUTING.md?plain=1#L27-L35)

 
| Model ID | Primary Use Case | Key Capabilities |
|---|---|---|
| deepseek-v4-pro | Complex reasoning, architecture design, and advanced coding. | Supports multi-level reasoning effort (high, max), deep thinking mode, and 1M context. |
| deepseek-v4-flash | Rapid iteration, simple debugging, and cost-sensitive tasks. | Low latency, 1M context, optimized for speed. |

 
### 1M Context Window

 Both V4 models support a context window of up to **1,000,000 tokens** [CONTRIBUTING.md36-38](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/CONTRIBUTING.md?plain=1#L36-L38)

 
 - **OpenAI-compatible:** Tools should be configured with `context_window: 1000000` or `max_tokens: 384000` where supported [CONTRIBUTING.md41](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/CONTRIBUTING.md?plain=1#L41-L41)
 - **Anthropic-compatible:** Use the `[1m]` suffix convention (e.g., `deepseek-v4-pro[1m]`) to signal high-context support to the agent [CONTRIBUTING.md40](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/CONTRIBUTING.md?plain=1#L40-L40)
 
 
### Reasoning Effort Levels

 `deepseek-v4-pro` supports adjustable reasoning intensity. For coding agents, it is mandatory to configure the **max** effort level to ensure the highest quality of logic synthesis [CONTRIBUTING.md46-49](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/CONTRIBUTING.md?plain=1#L46-L49)

## API Architecture and Endpoints

 DeepSeek provides two protocol families to ensure compatibility with various agent frameworks. The choice of endpoint often dictates how thinking/reasoning content is handled.

 
### Protocol Comparison

 
| Protocol | Implementation Detail | Configuration Key |
|---|---|---|
| OpenAI-Compatible | Standard v1/chat/completions endpoint. | reasoning_effort in request body CONTRIBUTING.md52 |
| Anthropic-Compatible | Used for tools like Claude Code. | thinking: { type: "enabled" } CONTRIBUTING.md51 |

## Pricing Snapshot

 Pricing is calculated based on token usage across three categories: Input, Output, and Cache Hits. The following table represents the snapshot verified for the current V4 release.

 
| Model | Input (per M tokens) | Output (per M tokens) | Cache Hit (per M tokens) |
|---|---|---|---|
| deepseek-v4-pro | $0.435 | $0.87 | $0.003625 |
| deepseek-v4-flash | $0.14 | $0.28 | $0.0028 |

### Critical Implementation Checklist

 
 - **Model Names:** Verify that `deepseek-chat` or `deepseek-coder` is not used in any `config.json` or `settings.yaml` [CONTRIBUTING.md27-32](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/CONTRIBUTING.md?plain=1#L27-L32)
 - **Context Suffix:** For Anthropic-compatible agents, ensure the `[1m]` suffix is present in the model string [CONTRIBUTING.md40](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/CONTRIBUTING.md?plain=1#L40-L40)
 - **Reasoning Passback:** Do not document workarounds that disable thinking mode. If a tool fails to parse reasoning blocks, the guide must link to the upstream bug report or fix rather than degrading model performance [CONTRIBUTING.md54-70](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/CONTRIBUTING.md?plain=1#L54-L70)
