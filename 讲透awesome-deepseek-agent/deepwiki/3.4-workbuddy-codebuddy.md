# WorkBuddy / CodeBuddy

  Relevant source files

  WorkBuddy (also known as CodeBuddy) is an AI agent and coding assistant that enables deep integration with custom Large Language Models (LLMs) via local configuration files. It utilizes an OpenAI-compatible Chat Completions API to interface with DeepSeek V4 models.

 
### Local Configuration Mechanism

 WorkBuddy identifies available models by scanning for a `models.json` file within a specific directory structure. This allows for both global (user-level) and project-specific model overrides.

 
#### Configuration Pathing

 The application looks for configuration in two primary locations:

 
 - **User-level:** `C:\Users\<your-username>\.codebuddy\models.json` [docs/workbuddy.md18-19](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/docs/workbuddy.md?plain=1#L18-L19)
 - **Project-level:** `<your-project>\.codebuddy\models.json` [docs/workbuddy.md23-25](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/docs/workbuddy.md?plain=1#L23-L25)
 
 
#### The `models.json` Schema

 The configuration file defines the model identity, provider details, and capability flags.

 
| Key | Description |
|---|---|
| id | The exact model identifier used in API requests (e.g., deepseek-v4-pro). docs/workbuddy.md39 |
| vendor | Metadata label for the model provider. docs/workbuddy.md41 |
| url | The full OpenAI-compatible endpoint URL. docs/workbuddy.md42 |
| apiKey | The authentication token, supporting ${ENV} expansion. docs/workbuddy.md43 |
| maxInputTokens | The context window limit (recommended: 128000). docs/workbuddy.md44 |
| supportsToolCall | Boolean flag enabling agentic function calling. docs/workbuddy.md46 |
| relatedModels | Mapping for specialized modes like lite or reasoning. docs/workbuddy.md48-51 |

### Implementation Requirements

 
#### Encoding Requirement

 The `models.json` file **must** be saved using **UTF-8 without BOM** encoding. Files containing a UTF-8 Byte Order Mark (BOM) header may cause the application to fail while parsing the local model configuration [docs/workbuddy.md72](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/docs/workbuddy.md?plain=1#L72-L72)

 
#### Environment Variable Expansion

 WorkBuddy supports the `${VARIABLE_NAME}` syntax within the `apiKey` field. For this to function:

 
 - The variable must be set in the OS (e.g., `setx DEEPSEEK_API_KEY "..."`) [docs/workbuddy.md29-31](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/docs/workbuddy.md?plain=1#L29-L31)
 - WorkBuddy must be launched from an environment where the variable is inherited. If the UI displays the literal string `${DEEPSEEK_API_KEY}`, the application was likely started without access to the environment variable [docs/workbuddy.md106](https://github.com/deepseek-ai/awesome-deepseek-agent/blob/4481ad5b/docs/workbuddy.md?plain=1#L106-L106)

### Troubleshooting

 
| Error | Root Cause | Resolution |
|---|---|---|
| 401 (Authentication Fails) | Invalid apiKey or URL in key field. | Ensure apiKey contains only the key, not the URL docs/workbuddy.md102 |
| 404 (Model Not Found) | Incorrect id string. | Verify id is exactly deepseek-v4-pro or deepseek-v4-flash docs/workbuddy.md103 |
| Parsing Failure | Invalid JSON or UTF-8 BOM. | Validate JSON syntax and strip BOM header docs/workbuddy.md104 |
| Missing Model | Directory or Restart issue. | Confirm file is in .codebuddy/models.json and fully restart the app docs/workbuddy.md105 |
