## 3. 谱系定位：四家对比

| 维度 | LangChain/LangGraph | Mastra | opencode | **dsh** |
|---|---|---|---|---|
| 扩展单元 | 图节点 / runnable | 框架类型（workflow/agent/tool） | session hook + provider 插件 | **一切皆 Cordis 插件（含 loop 本身）** |
| 状态 | checkpointer 旁路存储 | 框架管理 | SQLite 会话库 | **append-only 事件日志 = 唯一事实源**，模型历史是其投影 |
| 检查点/恢复 | interruption 特性 | 无对应物 | 无（归档，续于 charmbracelet/crush） | **公理级**：每步是事件、每次请求可从日志 byte 级重建（invariant 机器校验） |
| 卸载语义 | 手工清理 | 手工清理 | 手工清理表 | **effect 生成器逆序回卷**（fiber.ts:675-686） |
| 取向 | 组装智能（笔记本 DSL） | 组装应用 | 组装终端体验 | **组装 harness 本身** |

一句话：**dsh 是第一个把 chatbot 框架十年沉淀的插件内核（cordis/Koishi 系）与 event-sourcing 的写/读分离（log vs surface）完整结合的开源 agent harness**。它给"想替换 loop 某一段"的人设计，而不是"想往 loop 外挂东西"的人。

代价也明确：概念密度高（epoch/scope/fiber/surface/inbox/initiator…），扩展一个行为要理解的契约远多于 LangChain 的一跳回调——**把复杂度从用户代码搬到框架契约**的典型交易；developer preview 无兼容承诺、暂不接受外部 PR（`CONTRIBUTING.md:9`）。
