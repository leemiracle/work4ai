# 01 · 符号级代码图谱与枢纽分析（codegraph.db 取证）

> 数据源：本地 `.codegraph/codegraph.db`（CodeGraph MCP v1.5.0 对全仓 3839 文件建立的真实索引，230MB SQLite）——比 [08-graph-analysis](../08-graph-analysis/01-模块依赖图与工程全景.md) 的**包级**依赖图再往下钻一层：**符号级**（函数/接口/调用边）。
> 上游 HEAD `47f943859b`（2026-08-13）。
> 本笔记所有数字可用文末 SQL 一键复现。

## 1. 全图规模

| 维度 | 数值 | 解读 |
|---|---|---|
| 索引文件 | 3839（TS 2285 + TSX 259 + YAML 1236 + py 19 + C/C++ 2） | TypeScript 单语言占比 88%，与"全景篇"语言画像一致；YAML 1236 个是 cordis 插件配置即代码的证据 |
| 符号节点 | 35,531（function 8168 / constant 5339 / method 3655 / interface 2629 / class 668） | 接口:类 ≈ 4:1——契约先行 |
| 边 | 226,165（**calls 133,442** / contains 37,697 / references 24,943 / imports 24,174 / instantiates 5,520 / extends 295 / implements 95） | 调用边占 59%，是真实执行流而非声明图 |
| 异步函数 | 1880 / 11,823（16%） | 异步集中在 IO 边界（流/持久化/沙箱），核心状态机是同步的——事件溯源让"等"变成了日志追加 |

## 2. 枢纽节点（in-degree Top，被 import/reference 次数）

| 符号 | 位置 | 入度 | 角色 |
|---|---|---:|---|
| `Context`（interface） | `vendor/cordis/src/context.ts`（经 `@deepseek-ai/cordis` re-export） | **2410** | 全仓服务定位器——每个插件 `ctx.xxx` 的类型根 |
| `SessionId` | `packages/core/session/src/types.ts` | 1119 | Branded ID 贯穿全系统（AGENTS.md"跨边界 id 必须 Branded"在图上的投影） |
| `expect` | `packages/jobs/jobs-local` | 962 | 测试断言基建 |
| `SessionEvent` | `packages/core/session/src/types.ts` | 814 | 唯一事实源的事件联合类型 |
| `Agent`（interface） | `packages/core/agent/src/runtime-types.ts` | 756 | Agent 是**接口**不是类——loop 只是它的一个实现 |
| `StreamChunk` / `ContentBlock` | `packages/llm/llm/src/types.ts` | 264 / 253 | 流协议词汇表 |
| `InvariantInstaller` | `packages/runtime-diagnostics/invariants` | 246 | "每包自证不变量"机制的类型入口 |
| `ConversationNodeDefinition` | `packages/client/runtime` | 128 | Web UI 的节点注册契约 |

**结论：入度 Top 几乎全是 `types.ts` 里的类型契约，不是实现**。hub 是词汇表（SessionEvent/StreamChunk/Agent），实现包彼此几乎不互指——"扩展插件只依赖 Service Definition"这条 AGENTS.md 规则在符号图上成立。这解释了为什么换 provider 不 fork：没有实现到实现的边。

## 3. 跨包引用流（imports+references 聚合，>200 边）

| 方向 | 边数 | 解读 |
|---|---:|---|
| client/* → host/* | 920 | 浏览器半边经 host 的 RPC 契约（RpcRequest/RpcResponse 也是 Top hub）说话 |
| client/* → core/* | 553 | UI 直接消费核心类型（Session/Agent）渲染 |
| session/* → core/* | 436 | 持久化插件实现核心声明的缝 |
| subagent/* → core/* | 415 | 11 个 subagent 后端全部只面向 `Agent` 接口 |
| core/* → llm/* | 338 | loop 只欠一个 `stream()` |
| client/* → context/* | 316 | UI 渲染 session-reference 等上下文产物 |

与 08 笔记的四层单向结构（util → 脊柱 → 能力缝 → 组装）完全吻合，且补充了包级图看不到的事实：**core↔host 之间没有直接重边，全部流量经类型契约中转**。

## 4. 复现命令（PowerShell + sqlite3）

```powershell
PS> sqlite3 C:\workspace\deepseek-harness\.codegraph\codegraph.db `
  "SELECT n.name, COUNT(*) inbound FROM edges e JOIN nodes n ON n.id=e.target
   WHERE e.kind IN ('imports','references') GROUP BY n.id ORDER BY inbound DESC LIMIT 15;"
PS> sqlite3 .codegraph\codegraph.db "SELECT kind, COUNT(*) FROM edges GROUP BY kind;"   # 边分布
PS> sqlite3 .codegraph\codegraph.db "SELECT SUM(is_async=1), SUM(is_async=0) FROM nodes WHERE kind IN ('function','method');"  # 异步比
```

> 方法论注记：codegraph（MCP daemon + SQLite）与仓库自带 `gen-module-graph`（package.json 依赖）是互补双源——前者回答"哪些**符号**是枢纽"，后者回答"哪些**包**分层"。两图结论一致时，架构判断才可信。
