# 01 · 信任平面与反欺骗

> 对应 `packages/sandbox/`、`packages/interaction/`、`packages/guard/`、`packages/client/connection/`、`vendor/README.md`、`pnpm-workspace.yaml`
> 行号钉版 `47f943859b`
> 与 [`欺骗动力学-AI纪实验包.md`](../../../../欺骗动力学-AI纪实验包.md) 实验 5 互为详略两版

## 1. 沙箱：wrap-argv 契约

一句话契约（`packages/sandbox/sandbox/README.md:7`）：`ctx.sandbox.confine(argv, policy)` 返回**用来替换调用方原始 argv 的受限 argv**——进程及其一切派生都在限制内运行；**没有可用后端时抛 `SandboxUnavailableError`（`src/index.ts:131`），绝不原样放行**。

- `SandboxMode`：`read-only → workspace-write → danger-full-access` 单调阶梯。
- 返回的 `ConfinedArgv` 附带 `enforcement: full|partial`（诚实报告强制完整度）、`denialSignatures`（后端拒绝方言——工具层据此把 stderr 分类为"被拒"而非"崩溃"）、`runnerFailureRules`。
- 后端链（`sandbox-local/src/index.ts:1-4`）：Linux bwrap→Landlock（`native/landlock-run`，自限制后 exec 的 C11/musl 启动器，fail-closed）；macOS Seatbelt；Windows ACL 受限令牌（per-workspace 写 SID；**诚实报告 partial**：WRITE_RESTRICTED 须保留 Everyone SID、NTFS 硬链接别名同一文件对象）。
- 调用方纪律（`sandbox/src/index.ts:167-170`）：传精确 argv（如 `['bash','-c',command]`），**永不传 shell 字符串**。

## 2. 升级审批：先审后执

被拒后模型可请求升级（`WIDER_MODES` 阶梯）。`approveEscalation`（`sandbox/src/escalation.ts:157`）：**审批在任何执行之前完成**，每个 ask/outcome 审计入会话日志。有序 fail-closed 序列有测试钉死：

```bash
$ rg -n "no approval service is composed" packages/sandbox/sandbox/tests/escalation.spec.ts
95:    await expect(approveEscalation(req(), ingredients({ approver: undefined }))).rejects.toThrow(/no approval service is composed/)
```

## 3. 审批与权限预设

- `ApprovalService`（`interaction/user-approval/src/index.ts:192`，`ctx.approval`）：策略 `ask|never`；每次切换是 durable `approval/policy` 会话事件；当前策略作为系统上下文**暴露给模型**（它知道自己会被问）。
- `PermissionPresetService`（`interaction/permission-presets/src/index.ts:159`）：命名打包 `sandbox/mode × approval/policy`；默认 `workspace-write`（workspace-write + ask）与 `danger-full-access`（+ never）；会话创建时钉住选择。
- 工具管线的 `ask`（见 tools 笔记 §2）：无审批服务 = deny（`tools/src/index.ts:1696`）——**两层 fail-closed**（沙箱层 + 工具层）。

## 4. 循环卫生 guard（行为级反 reward hacking）

- `repeat-tool-reminder`（`guard/repeat-tool-reminder/src/index.ts:29`）：同一 agent 连续**完全相同**（规范化后）的工具调用达阈值 `[3,5,8]` → 递进提醒注入 additionalContexts；**被 deny 的调用也计数**（`:278` 起"hammering a denied tool still draws the reminder"）；链按 agent 隔离。
- `timeout-policy`（`guard/timeout-policy/src/index.ts:61`）：`using d = deadline(exec.signal, timeoutMs, TOOL_TIMEOUT)`——到期信号**替换**调用方信号派发，自家 deadline 先赢则结果强制 `TOOL_TIMEOUT`。

## 5. Web 信任栅栏（反 DNS-rebinding / 注入的网络面）

`packages/client/connection/src/api-request-trust.ts:96` `isTrustedApiRequest`：

- 每个 `/api` 请求（**无论是否带浏览器标记**）的 Host 必须是回环或 `trustedHosts` 精确匹配（WHATWG 归一化后比较——rebinder 伪造不了 Host 头）。
- `Origin` 不等 Host 权威 → 403；显式 `sec-fetch-site: cross-site` → 403；HTTP 失败在任何 RPC 分发前纯 403，upgrade 失败在事件流启动前拒绝握手。
- `trustedHosts` 条目不是"纯权威"（如 `harness.internal/path`）→ **插件加载即报错**（防笔误悄悄授权）。
- **特权方法集**（配置面、凭据面、agent-preset 创作面、`host.pickDirectory/openPath`）钉死回环——即使声明了 trustedHosts 也不放开：读一个 preset = 侦察（它列出了会话跑哪些插件）。
- `dsh web --host 0.0.0.0` **故意不支持**，直到有认证层。文档明说：栅栏是可达性策略，不是认证。

## 6. MCP 命名空间

外部 MCP 服务器工具强制改名 `mcp__<server>__<rawName>`（`mcp/mcp-client/src/tools.ts:97`）——不可信指令来源**永远带前缀**，无法冒充内置工具名；同一前缀内的冲突在加载期报错。

## 7. 供应链（反 data poisoning 的工程化）

- **框架 vendored**：Cordis 9 包源码内嵌 + 逐包锁定上游 commit（`vendor/README.md:13-23`，cordis = `56b3d4f7…`）；`verify-vendored-links` hygiene 门禁断言 lockfile 中无 registry 副本——npm 投毒对框架层无效。18 处本地修改全部留痕（`vendor/README.md:29-50`）。
- **install 脚本默认拒绝**：`pnpm-workspace.yaml:40` `allowBuilds` 显式白名单（esbuild、lefthook、node-pty、koffi……），未列出的一律硬失败——供应链投毒最常用的 lifecycle-script 载体被默认封死。甚至显式 `false` 否决 no-op 脚本（`@google/genai` 等）。
- **补丁显式化**：`patchedDependencies`（`:71-72`）声明式（node-pty），无静默篡改。

## 8. 汇总：欺骗形态 → 架构反制

| 欺骗形态 | 反制 | 证据 |
|---|---|---|
| 两面派（对模型/对用户两套账） | model-visible⟺logged 单一日志 + 运行时断言 | `session/src/index.ts:425,726` |
| 越权执行 | 审批缺位=deny + 升级先审后执 | `tools/src/index.ts:1696`、`escalation.ts:157` |
| 先斩后奏 | wrap-argv 沙箱 + 后端不可用即抛 | `sandbox/src/index.ts:131,175` |
| 原地打转刷上下文 | repeat-tool-reminder（拒答也计数）+ TOOL_TIMEOUT | `guard/*/src/index.ts` |
| 网络 rebinding | Host 栅栏 + 特权方法钉回环 | `api-request-trust.ts:96` |
| 工具名冒充 | MCP 强制命名空间 | `mcp-client/src/tools.ts:97` |
| 供应链偷换 | SHA 锁定 + allowBuilds 默认拒 + 显式 patch | `vendor/README.md:13-23`、`pnpm-workspace.yaml:40-72` |

## 9. 设计要点提炼

1. **结构优先于检测**——上述大多是"让欺骗在结构上无利可图"，不是"事后抓到欺骗"。
2. **诚实即反欺骗文化**——partial enforcement 如实报告、栅栏"不是认证"如实声明、Windows 缺口写进文档。
3. **每个 fail-closed 都有测试钉死**——不是注释里的愿望，是 spec 里的断言。
