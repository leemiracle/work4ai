## Purpose and Scope

 The WebGPU backend enables TVM to compile and execute deep learning models and compute kernels in web browsers using the WebGPU API. This backend generates WGSL (WebGPU Shading Language) shaders from TVM's Tensor IR and manages execution through a JavaScript/WebAssembly runtime. The system consists of a C++ code generator that produces WGSL code, a TypeScript runtime that interfaces with browser WebGPU APIs, and a bridge layer compiled to WebAssembly.

 For general code generation concepts, see [Code Generation](https://deepwiki.com/apache/tvm/6-code-generation). For LLVM-based CPU/GPU backends, see [LLVM Backend](https://deepwiki.com/apache/tvm/6.2-llvm-backend). For WebAssembly runtime details, see [WebAssembly Runtime](https://deepwiki.com/apache/tvm/7.2-webassembly-runtime).

## Code Generation

 The code generation logic transforms TIR functions into WGSL shader code. It maps TIR constructs to WGSL-specific syntax, handling buffer bindings, workgroup configurations, and specialized math operations. The `CodeGenWebGPU` class inherits from `CodeGenC` but overrides key methods to emit WGSL syntax instead of C/C++.

 
### WGSL Generation Details

 
| TVM Construct | WGSL Output | Implementation Detail |
|---|---|---|
| Buffer arguments | @group(0) @binding(N) var<storage, read_write> | Binding indices mapped to buffer IDs. read mode is used for read-only buffers src/backend/webgpu/codegen/codegen_webgpu.cc28-42 |

### Memory and Allocation Constraints

 The WebGPU backend enforces strict memory constraints during code generation:

 
 - **Stack Allocation**: Local buffer allocations (e.g., `T.alloc_buffer(..., scope="local")`) must have a finite, positive compile-time upper bound [tests/python/codegen/test_target_codegen_webgpu.py87-91](https://github.com/apache/tvm/blob/b16cdecb/tests/python/codegen/test_target_codegen_webgpu.py#L87-L91)
 - **Workgroup Memory**: Shared memory allocations are limited by the `max_shared_memory_per_block` target attribute, typically defaulting to 32KB [src/backend/webgpu/codegen/target_kind.cc59](https://github.com/apache/tvm/blob/b16cdecb/src/backend/webgpu/codegen/target_kind.cc#L59-L59) Total workgroup allocation exceeding this limit results in a compilation error [tests/python/codegen/test_target_codegen_webgpu.py206-210](https://github.com/apache/tvm/blob/b16cdecb/tests/python/codegen/test_target_codegen_webgpu.py#L206-L210)

### Buffer Management

 The context maintains three types of GPU buffers:

 
 - **Storage Buffers** (`bufferTable`): Main data buffers allocated via `deviceAllocDataSpace()`, tracked by pointer ID with a free list for recycling [web/src/webgpu.ts850-895](https://github.com/apache/tvm/blob/b16cdecb/web/src/webgpu.ts#L850-L895)
 - **Uniform Buffers** (`uniformBufferPool`): Per-dispatch pool for passing POD arguments and grid dimensions, reused across flushes to avoid allocation overhead [web/src/webgpu.ts608-625](https://github.com/apache/tvm/blob/b16cdecb/web/src/webgpu.ts#L608-L625)
 - **Staging Buffers** (`readStagingBufferPool`): Pool of `MAP_READ` buffers for GPU→CPU transfers, limited to `maxReadStagingBuffers` [web/src/webgpu.ts405-407](https://github.com/apache/tvm/blob/b16cdecb/web/src/webgpu.ts#L405-L407)
 
 
### Command Batching Optimization

 The runtime batches multiple compute dispatches into a single command encoder to reduce JavaScript-to-native boundary crossings:

 
 - **Batching**: Compute passes accumulate in `pendingEncoder` without immediate submission [web/src/webgpu.ts414-422](https://github.com/apache/tvm/blob/b16cdecb/web/src/webgpu.ts#L414-L422)
 - **Flushing**: `flushCommands()` finishes and submits the encoder, triggered before readback, synchronization, or buffer deallocation [web/src/webgpu.ts454-463](https://github.com/apache/tvm/blob/b16cdecb/web/src/webgpu.ts#L454-L463)
 - **Uniform Buffers**: Each dispatch gets its own uniform buffer from the pool because `queue.writeBuffer()` executes immediately while compute passes are deferred [web/src/webgpu.ts608-625](https://github.com/apache/tvm/blob/b16cdecb/web/src/webgpu.ts#L608-L625)

## Integration and Deployment

 
### WebAssembly Compilation

 The WebAssembly runtime is compiled using Emscripten. The `web/Makefile` defines the compilation process for `tvmjs_runtime.wasm`:

 
 - **Includes**: Includes TVM root, 3rdparty/tvm-ffi, and dlpack [web/Makefile20-23](https://github.com/apache/tvm/blob/b16cdecb/web/Makefile#L20-L23)
 - **LDFLAGS**: Uses `-s WASM_BIGINT=1`, `-s ALLOW_MEMORY_GROWTH=1`, and `-s ASYNCIFY=1` for browser compatibility [web/Makefile33-35](https://github.com/apache/tvm/blob/b16cdecb/web/Makefile#L33-L35)
 - **Bridge Files**: Links `wasm_runtime.bc`, `tvmjs_support.bc`, and `webgpu_runtime.bc` [web/Makefile43-45](https://github.com/apache/tvm/blob/b16cdecb/web/Makefile#L43-L45)
 
 
### Artifact Caching

 To optimize model loading in the browser, the backend supports several caching mechanisms for model weights (tensors):

 
 - **IndexedDB**: Persistent browser storage [web/src/artifact_cache.ts33](https://github.com/apache/tvm/blob/b16cdecb/web/src/artifact_cache.ts#L33-L33)
 - **OPFS (Origin Private File System)**: High-performance file system access [web/src/artifact_cache.ts34](https://github.com/apache/tvm/blob/b16cdecb/web/src/artifact_cache.ts#L34-L34)
 - **Cross-Origin Storage**: Shared caching across different origins using SHA-256 descriptors [web/src/artifact_cache.ts147-200](https://github.com/apache/tvm/blob/b16cdecb/web/src/artifact_cache.ts#L147-L200)

### Performance Limits and Fallbacks

 Device initialization carefully checks and requests appropriate limits. If the requested 1GB limit for `maxBufferSize` or `maxStorageBufferBindingSize` is rejected, the runtime falls back to smaller default values (256MB and 128MB respectively) [web/src/webgpu.ts69-110](https://github.com/apache/tvm/blob/b16cdecb/web/src/webgpu.ts#L69-L110)

 
| Limit | Default Request | Fallback | Purpose |

| maxStorageBufferBindingSize | 1 GB | 128 MB | Per-binding size web/src/webgpu.ts91-110 |
| maxComputeWorkgroupStorageSize | 32 KB | - | Shared memory web/src/webgpu.ts112-119 |
| maxStorageBuffersPerShaderStage | 10 | - | Argument count web/src/webgpu.ts121-128 |
| maxComputeInvocationsPerWorkgroup | 1024 | 512, 256 | Threads per block web/src/webgpu.ts130-140 |
