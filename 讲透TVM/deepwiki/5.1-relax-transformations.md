  **Purpose**: This document describes the suite of optimization and transformation passes that operate on Relax IR to optimize neural network graphs. These passes transform high-level Relax operations into optimized low-level implementations, perform operator fusion, manage memory allocation, and integrate with auto-scheduling systems.

 For information about Relax IR structure and operators, see [Relax IR](https://deepwiki.com/apache/tvm/2.2-relax-ir). For TIR scheduling primitives used after legalization, see [TIR Transformations](https://deepwiki.com/apache/tvm/5.2-tir-transformations). For runtime execution of transformed modules, see [Virtual Machine](https://deepwiki.com/apache/tvm/7.1-virtual-machine).

 
## Overview

 Relax transformations are implemented as IR passes that operate on `IRModule` objects containing Relax functions. The transformation pipeline converts high-level neural network graphs into optimized executable code through stages including legalization, fusion, memory planning, and auto-scheduling integration.

## Operator Legalization

 
### LegalizeOps Pass

 The `LegalizeOps` pass converts high-level Relax operators (e.g., `R.nn.conv2d`) into `call_tir` operations that invoke TIR `PrimFunc` implementations [include/tvm/relax/transform.h230-244](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/relax/transform.h#L230-L244) This is the critical bridge between high-level neural network operations and low-level tensor computations.

 The legalization function for each operator is registered as an attribute on the operator using the `FLegalize` key [include/tvm/relax/transform.h236](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/relax/transform.h#L236-L236)

## Operator Fusion

 
### FuseOps Pass

 The `FuseOps` pass groups bindings in dataflow blocks and generates a new grouped Relax function for each group [src/relax/transform/fuse_ops.cc22-25](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/fuse_ops.cc#L22-L25) It uses post-dominator analysis to handle diamond-shaped branches [src/relax/transform/fuse_ops.cc61-78](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/fuse_ops.cc#L61-L78)

 **Key Implementation Details**:

 
 - **Graph Construction**: Uses `GraphCreator` to build an `IndexedForwardGraph` [src/relax/transform/fuse_ops.cc109-113](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/fuse_ops.cc#L109-L113)
 - **Post-Dominator Analysis**: Uses a single-pass LCA-based algorithm for DAGs [src/relax/transform/fuse_ops.cc84-90](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/fuse_ops.cc#L84-L90)
 - **Union-Find**: Manages groups during the fusion traversal [src/relax/transform/fuse_ops.cc99-100](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/fuse_ops.cc#L99-L100)
 - **Depth Limit**: Configurable via `relax.FuseOps.max_depth` [src/relax/transform/fuse_ops.cc107](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/fuse_ops.cc#L107-L107)
