## Purpose and Scope

 This page documents the Relax-level operator API, which provides high-level operations for constructing neural network computations in the Relax IR. Relax operators are the building blocks used by ML framework frontends (ONNX, PyTorch, etc.) to represent model computations before they are lowered to executable TIR code.

 For information about low-level operator implementations and schedules, see [TOPI - TVM Operator Inventory](https://deepwiki.com/apache/tvm/3.2-topi-tvm-operator-inventory). For details on how Relax operators are legalized to TIR, see [Relax Transformations](https://deepwiki.com/apache/tvm/5.1-relax-transformations).

 
## Overview

 Relax operators are high-level, framework-agnostic operations that represent common deep learning computations. They exist at a higher abstraction level than TensorIR (TIR) and provide:

 
 - **Type inference** through StructInfo and `FInferType` annotations [src/relax/op/tensor/manipulate.cc138](https://github.com/apache/tvm/blob/b16cdecb/src/relax/op/tensor/manipulate.cc#L138-L138)
 - **Automatic legalization** to low-level TIR implementations via the `LegalizeOps` pass [python/tvm/relax/transform/legalize_ops/manipulate.py19-31](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/transform/legalize_ops/manipulate.py#L19-L31)
 - **Fusion opportunities** through operator pattern classification [src/relax/op/op_common.h169-171](https://github.com/apache/tvm/blob/b16cdecb/src/relax/op/op_common.h#L169-L171)
 - **Framework interoperability** by serving as a common target for multiple ML frontends.

## Operator Definition and Registration

 
### Operator Attributes and Registration

 Relax operators are registered in C++ with specific attributes controlling their behavior. The `RELAX_REGISTER_UNARY_OP` macro [src/relax/op/op_common.h165-171](https://github.com/apache/tvm/blob/b16cdecb/src/relax/op/op_common.h#L165-L171) provides a standard template for registering unary element-wise ops:

 
 - `FRelaxInferLayout`: Function for layout propagation.
 - `TMixedPrecisionPolicy`: Controls how the op behaves under Auto-Mixed Precision (AMP).
 - `FPurity`: Boolean flag marking the operator as side-effect free.

### Operator Pattern Classification

 Operators are classified by `OpPatternKind` to determine fusion eligibility. This is often inferred or explicitly set during registration to assist the `FuseOps` pass. For example, broadcasting ops like `broadcast_to` are treated with `kFollow` mixed precision policy [src/relax/op/tensor/manipulate.cc139](https://github.com/apache/tvm/blob/b16cdecb/src/relax/op/tensor/manipulate.cc#L139-L139)

## Type and Shape Inference

 Relax uses `FInferType` (in C++) and `StructInfo` to perform compile-time shape and type propagation.

 
### Example: `broadcast_to` Inference

 The `InferTypeBroadcastTo` function [src/relax/op/tensor/manipulate.cc76-132](https://github.com/apache/tvm/blob/b16cdecb/src/relax/op/tensor/manipulate.cc#L76-L132) performs several checks:

 
 - **Argument Count**: Ensures exactly 2 arguments are provided [src/relax/op/tensor/manipulate.cc77](https://github.com/apache/tvm/blob/b16cdecb/src/relax/op/tensor/manipulate.cc#L77-L77)
 - **Type Validation**: Validates that the first argument is a `Tensor` and the second is a `Shape` [src/relax/op/tensor/manipulate.cc82-91](https://github.com/apache/tvm/blob/b16cdecb/src/relax/op/tensor/manipulate.cc#L82-L91)
 - **Rank Check**: Ensures the target shape rank is at least equal to the input tensor rank [src/relax/op/tensor/manipulate.cc93-99](https://github.com/apache/tvm/blob/b16cdecb/src/relax/op/tensor/manipulate.cc#L93-L99)
 - **Symbolic Analysis**: Uses `arith::Analyzer` to prove that existing dimensions are broadcast-compatible with the target shape [src/relax/op/tensor/manipulate.cc110-130](https://github.com/apache/tvm/blob/b16cdecb/src/relax/op/tensor/manipulate.cc#L110-L130)

### Legalization Mechanism

 The `LegalizeOps` pass uses registered Python functions to convert high-level Relax ops into `call_te` or `call_tir` nodes. For example, `relax.reshape` is legalized by calling `topi.reshape` [python/tvm/relax/transform/legalize_ops/manipulate.py49](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/transform/legalize_ops/manipulate.py#L49-L49)

## Constant Folding

 The `FoldConstant` pass [src/relax/transform/fold_constant.cc36](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/fold_constant.cc#L36-L36) optimizes the graph by pre-computing operations on constant tensors at compile-time.

 
### Folding Logic

 
 - **Target Selection**: The pass identifies `call_tir` nodes where all inputs are `relax.Constant` [src/relax/transform/fold_constant.cc77-86](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/fold_constant.cc#L77-L86)
 - **Safety Heuristics**: To avoid binary size explosion, the pass skips folding pure creation ops (like `zeros` or `ones`) if the output exceeds `kMaxFoldElements` (default 1024) [src/relax/transform/fold_constant.cc159-193](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/fold_constant.cc#L159-L193)
 - **Execution**: It uses `tirx.build` to compile the `PrimFunc` for the host CPU and executes it using the TVM runtime [src/relax/transform/fold_constant.cc106-132](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/fold_constant.cc#L106-L132)
 
 **Sources:** [src/relax/transform/fold_constant.cc36-194](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/fold_constant.cc#L36-L194) [tests/python/relax/test_transform_fold_constant.py60-117](https://github.com/apache/tvm/blob/b16cdecb/tests/python/relax/test_transform_fold_constant.py#L60-L117)

 
## Operator Overloading in TVMScript

 Relax supports Python-style operator overloading for Tensors via `_register_op_make` [python/tvm/relax/op/__init__.py172](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/op/__init__.py#L172-L172) This allows users to write `x + y` in TVMScript, which is automatically translated to `relax.op.add(x, y)` [python/tvm/relax/op/__init__.py212](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/op/__init__.py#L212-L212)

 Supported overloads include:

 
 - Arithmetic: `__add__`, `__sub__`, `__mul__`, `__div__` [python/tvm/relax/op/__init__.py212-227](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/op/__init__.py#L212-L227)
 - Comparison: `__lt__`, `__le__`, `__gt__`, `__ge__` [python/tvm/relax/op/__init__.py202-211](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/op/__init__.py#L202-L211)
 - Access: `__getitem__` (mapped to `TupleGetItem`) [python/tvm/relax/op/__init__.py188-200](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/op/__init__.py#L188-L200)
