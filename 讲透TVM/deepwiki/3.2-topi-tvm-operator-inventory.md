## Purpose and Scope

 TOPI (TVM Operator Inventory) is TVM's comprehensive operator library that provides reusable compute declarations and optimized schedules for common operations in machine learning and tensor computation. TOPI sits between high-level operator APIs and low-level code generation, offering both generic implementations and hardware-specific optimizations.

 This document covers:

 
 - TOPI's package organization and operator categories.
 - The dual C++/Python schedule registration system.
 - Hardware-specific optimization strategies.
 - Integration with Tensor Expression (TE) and the compilation pipeline.

## Architecture Overview

 TOPI is organized as a layered library where compute declarations are separated from schedule optimizations. The library follows a "compute-once, schedule-many" philosophy, allowing the same compute logic to be optimized differently for various hardware targets.

## Schedule Registration System

 TOPI implements a dual-registration system where C++ schedules and compute declarations are registered through FFI, and Python implementations can extend or override them.

 
### Registration Pattern

 The registration order is critical. C++ schedules must be registered first via `topi.cpp` so that Python modules can build upon or override them. [python/tvm/topi/__init__.py29-31](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/topi/__init__.py#L29-L31)

 In C++, operators are registered using `TVM_FFI_STATIC_INIT_BLOCK` and `refl::GlobalDef().def_packed()`. For example, `topi.nn.relu` and `topi.nn.dense` are registered to bridge the C++ implementation to the Python API. [src/topi/nn.cc48-96](https://github.com/apache/tvm/blob/b16cdecb/src/topi/nn.cc#L48-L96)

 **Sources:** [python/tvm/topi/__init__.py29-31](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/topi/__init__.py#L29-L31) [src/topi/nn.cc48-96](https://github.com/apache/tvm/blob/b16cdecb/src/topi/nn.cc#L48-L96)

 
## Tensor Expression (TE) Integration

 TOPI operators are primarily defined using TVM's Tensor Expression (TE) language. This allows developers to describe "what" to compute symbolically, while the "how" (scheduling) is handled separately.

 
### Compute Definition Logic

## Neural Network Operations (topi.nn)

 The `topi.nn` module contains high-performance implementations of standard deep learning layers.

 
### Convolution (Conv2D)

 The `conv2d` operator supports multiple layouts (NCHW, NHWC, HWCN). It uses a `Workload` named tuple to describe the operation parameters (stride, padding, dilation, filters) for optimization and autotuning. [python/tvm/topi/nn/conv2d.py37-151](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/topi/nn/conv2d.py#L37-L151)

 
### Pooling

 Pooling operations (Max/Avg) are implemented with support for gradient computation (`pool_grad_impl`). The C++ implementation in `pooling.h` uses `MakeArgmaxReducer` for MaxPool gradients and handles padding logic via `arith::Analyzer`. [include/tvm/topi/nn/pooling.h49-162](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/nn/pooling.h#L49-L162)

## Reduction Operations

 Reduction operations like `sum`, `min`, and `max` are built using `CommReduce`. This utility handles:

 
 - **Axis Normalization**: `GetRealAxis` converts Python-style negative indices into absolute dimensions. [include/tvm/topi/reduction.h65-86](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/reduction.h#L65-L86)
 - **Target Shape Calculation**: `MakeReduceTargetShape` determines the output shape based on `keepdims`. [include/tvm/topi/reduction.h99-125](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/reduction.h#L99-L125)
 - **TE Compute Generation**: `DoCommReduce` generates the `te.compute` call with the appropriate `reduce_axis`. [include/tvm/topi/reduction.h140-169](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/reduction.h#L140-L169)
 
 **Sources:** [include/tvm/topi/reduction.h65-169](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/reduction.h#L65-L169)
