  The WebAssembly Runtime enables TVM to execute compiled deep learning models in web browsers and Node.js environments through WebAssembly (WASM). It provides a JavaScript/TypeScript API for loading models, managing memory, executing computations, and optionally leveraging WebGPU for GPU acceleration. This runtime allows ML models to run client-side without requiring server infrastructure.

 For information about the Virtual Machine bytecode executor that runs on top of this runtime, see [Virtual Machine](https://deepwiki.com/apache/tvm/7.1-virtual-machine). For WebGPU code generation, see [WebGPU Backend](https://deepwiki.com/apache/tvm/6.5-webgpu-backend).

 
## Architecture Overview

 The WebAssembly Runtime consists of three primary layers: a JavaScript/TypeScript frontend ([web/src/runtime.ts](https://github.com/apache/tvm/blob/b16cdecb/web/src/runtime.ts)), a WebAssembly binary compiled from C++ ([web/emcc/wasm_runtime.cc](https://github.com/apache/tvm/blob/b16cdecb/web/emcc/wasm_runtime.cc)), and optional WebGPU compute support ([web/src/webgpu.ts](https://github.com/apache/tvm/blob/b16cdecb/web/src/webgpu.ts)). The system bridges JavaScript and compiled TVM code through the Foreign Function Interface (FFI).

### WebGPU Integration

 The `WebGPUContext` class manages GPU resources including buffers, command encoding, and compute shader execution. It provides the device-level operations needed for GPU-accelerated inference.

 **Command Batching**: The runtime accumulates compute dispatches in a single `GPUCommandEncoder` (`pendingEncoder`) and submits them together when `flushCommands()` is called [web/src/webgpu.ts454-463](https://github.com/apache/tvm/blob/b16cdecb/web/src/webgpu.ts#L454-L463) This reduces JavaScript-to-native boundary crossings. The system automatically flushes before any operation that requires synchronization.

 **Uniform Buffer Pool**: Each dispatch in a batch needs its own uniform buffer because `queue.writeBuffer()` executes immediately while compute passes are deferred. The `uniformBufferPool` maintains per-dispatch uniform buffers that are reused across flushes [web/src/webgpu.ts610-625](https://github.com/apache/tvm/blob/b16cdecb/web/src/webgpu.ts#L610-L625)

 **Key Methods:**

## Function Invocation System

 The runtime enables bidirectional function calls between JavaScript and WebAssembly through the `PackedFunc` interface, with support for both synchronous and asynchronous execution.

 **Async Support**: The `AsyncifyHandler` enables WASM code to suspend execution when calling async JavaScript functions, using Emscripten's Asyncify feature to unwind and rewind the WASM stack around Promise boundaries [web/src/asyncify.ts](https://github.com/apache/tvm/blob/b16cdecb/web/src/asyncify.ts)

 **Marshalling**: The `CachedCallStack` handles the conversion of JavaScript values to `TVMValue` and `TypeIndex` in WASM memory. For example, `loadCString` is used to retrieve error messages from `TVMFFIWasmGetLastError` [web/src/runtime.ts101-103](https://github.com/apache/tvm/blob/b16cdecb/web/src/runtime.ts#L101-L103)

## Tensor Operations

 The `Tensor` class provides n-dimensional array operations with automatic device management.

 **Memory Layout**: Tensors are backed by `DLTensor` C structures. The runtime uses `TVMTensorAllocWithScope` for allocation [web/src/runtime.ts204](https://github.com/apache/tvm/blob/b16cdecb/web/src/runtime.ts#L204-L204) and `TVMTensorCopyFromTo` for transfers [web/src/runtime.ts205](https://github.com/apache/tvm/blob/b16cdecb/web/src/runtime.ts#L205-L205)

 **Decoding**: The runtime supports decoding specialized storage formats like `f32-to-bf16` via `ArrayDecodeStorage` [web/emcc/wasm_runtime.cc155-181](https://github.com/apache/tvm/blob/b16cdecb/web/emcc/wasm_runtime.cc#L155-L181) This allows models to be stored in 16-bit formats to save bandwidth and then expanded during runtime population. Rounding to nearest even is performed during the dump phase in Python to reduce error [python/tvm/contrib/tvmjs.py44-59](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/contrib/tvmjs.py#L44-L59)

## Artifact Caching

 The `artifact_cache.ts` module provides strategies for persisting model weights and compiled modules in the browser.

 
| Cache Type | Class | Description |
|---|---|---|
| cache | ArtifactCache | Uses the standard Browser Cache API |
| indexeddb | ArtifactIndexedDBCache | Uses IndexedDB for large object storage |
| opfs | ArtifactOPFSCache | Uses Origin Private File System for high-performance I/O |
| cross-origin | ArtifactCrossOriginStorageCache | Uses content-addressable storage for sharing artifacts across domains |

 **Shard Loading**: The `TensorShardEntry` defines how multiple tensors are packed into a single binary shard file to optimize fetch requests [web/src/artifact_cache.ts33-38](https://github.com/apache/tvm/blob/b16cdecb/web/src/artifact_cache.ts#L33-L38) Shards are validated using MD5 checksums generated during the dump phase [python/tvm/contrib/tvmjs.py67-72](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/contrib/tvmjs.py#L67-L72)
