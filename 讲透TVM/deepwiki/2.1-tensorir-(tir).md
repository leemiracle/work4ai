  TensorIR (TIR) is TVM's low-level, loop-based intermediate representation for expressing tensor computations at the loop and statement level. TIR operates below the high-level Relax IR in the compilation pipeline and provides fine-grained control over loop schedules, memory access patterns, and hardware-specific optimizations. TIR programs consist of `PrimFunc` objects that encapsulate imperative loop nests, buffer allocations, and computational blocks.

 For high-level operator definitions and schedules, see [TOPI - TVM Operator Inventory](https://deepwiki.com/apache/tvm/3.2-topi-tvm-operator-inventory). For loop-level transformation passes, see [TIR Transformations](https://deepwiki.com/apache/tvm/5.2-tir-transformations). For writing TIR using Python syntax, see [TVMScript](https://deepwiki.com/apache/tvm/2.3-tvmscript).

 
## Core IR Structure

 TIR is built around a hierarchical IR structure with two primary categories: expressions (`PrimExpr`) and statements (`Stmt`). The top-level container is `PrimFunc`, which represents a primitive function with typed parameters, buffer bindings, and a statement body.

### PrimFunc Structure

 A `PrimFunc` is the primary container for TIR code, analogous to a function in traditional programming languages. Each `PrimFunc` contains parameters, a body, and attributes that define how variables relate to memory buffers.

 
| Component | Type | Description |
|---|---|---|
| params | Array<Var> | Function parameters (scalars and BufferVar handles) |
| body | Stmt | The statement body containing the computation |
| ret_type | Type | Return type annotation |
| attrs | DictAttrs | Function attributes (e.g., global_symbol, tirx.noalias, layout_free_buffers) |

### Buffer Management

 In the modern TIRx implementation, memory is accessed via `BufferVar` and defined by regions.

 
| Field | Type | Description |
|---|---|---|
| BufferVar | Object | Represents a pointer variable to the underlying data with associated type and shape. |
| BufferLoad | Expr | Loads a value from a buffer at specific indices. |
| BufferStore | Stmt | Stores a value into a buffer at specific indices. |
| SBlock | Stmt | Defines a computation block that can declare local buffers via sblock_alloc_buffer. |

## Block Structure (SBlock)

 The `SBlock` (Scheduled Block) is a fundamental abstraction in TIR representing a unit of computation with explicit data access patterns. It is central to the "S-TIR" (Schedulable TIR) layer.

 
### SBlock Components

 A block encapsulates the computation body along with metadata for scheduling.

 
| Component | Description |
|---|---|
| iter_vars | Block iteration variables, often mapped from loops via T.axis.remap. |
| annotations | Key-value pairs for optimization hints (e.g., layout_free_buffers, tirx.noalias). |
| init | Optional initialization block for reductions. |
| body | The actual computation statement (e.g., BufferStore). |

## IRBuilder API

 The `IRBuilder` provides a high-level API for programmatically constructing TIR, utilized heavily by the TVMScript parser.

 
### IRBuilder Components

 
| Class | Purpose |
|---|---|
| IRBuilder | The main entry point for building IR modules and functions. |
| PrimFuncFrame | Manages the scope of a PrimFunc, including parameters and attributes. |
| ExecScope | Handles variable definitions and scope identifiers within the builder. |
| meta_var | Allows injecting metadata or existing IR objects into the builder scope. |
