## Purpose and Scope

 The TIRx subsystem (`tvm.tirx`) is the hardware-native Domain-Specific Language (DSL) and compiler framework specialized for expressing and optimizing machine learning (ML) kernels targeting GPUs and AI accelerators. It provides fine-grained control over low-level hardware constructs, including thread binding, buffer management, and hardware-specific primitives such as tile operations, asynchronous copies, and PTX dialect integration.

 TIRx serves as the foundation for high-performance kernel generation, bridging the gap between high-level tensor operations and target-specific ISA instructions.

 
---

 
## 1. Overview of TIRx

 TIRx extends TVM's TensorIR (TIR) with richer primitives and constructs enabling intricate kernel optimizations. It is designed to handle the complexity of modern accelerators like NVIDIA Hopper (sm_90) and Blackwell (sm_100).

 
### Key Components:

 
 - **Hardware-Native Primitives:** Operators that map directly to hardware instructions (e.g., `T.cuda.ldg`, `T.ptx.mma`).
 - **S-TIR (Schedulable TIR):** An IR layer that enables programmatic scheduling and composition of kernel blocks with explicit concurrency [python/tvm/s_tir/pipeline.py18-141](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/s_tir/pipeline.py#L18-L141)
 - **PTX Dialect:** A table-driven system for generating inline PTX assembly for NVIDIA GPUs [python/tvm/backend/cuda/ptx/table.py17-57](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/backend/cuda/ptx/table.py#L17-L57)
 - **Tile Layouts:** A layout system for managing data movement and computation in tiles [python/tvm/tirx/layout.py86-94](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/tirx/layout.py#L86-L94)

## 2. The PTX Dialect and Hardware Primitives

 TIRx provides a comprehensive interface to NVIDIA PTX (Parallel Thread Execution) through a table-driven dialect. This allows developers to write low-level GPU code directly in TVMScript while maintaining type safety and integration with TVM's analyzer.

 
### Table-Driven Instruction Registry

 The PTX dialect is defined in a central registry that maps PTX mnemonics to TVM `Op` nodes. This includes support for modifiers (sem, scope, space, type) and predication [python/tvm/backend/cuda/ptx/table.py29-57](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/backend/cuda/ptx/table.py#L29-L57)

 
 - **Memory Ops:** `ld.global`, `st.shared`, `cp.async` [tests/python/tirx/codegen/test_ptx_ld_st_ops.py1-50](https://github.com/apache/tvm/blob/b16cdecb/tests/python/tirx/codegen/test_ptx_ld_st_ops.py#L1-L50)
 - **Compute Ops:** `mma`, `red`, `atom`, `abs`, `add` [python/tvm/script/tirx.pyi25-80](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/script/tirx.pyi#L25-L80)

## 3. S-TIR: The Schedulable Layer

 S-TIR adds explicit support for scheduling constructs, most notably for software pipelining and multi-version buffer management.

 
### Software Pipelining (`InjectSoftwarePipeline`)

 This transformation parallelizes producers and consumers by overlapping memory loads with computation. It uses `PipelineOpaqueAccessRewriter` to remap buffer indices for multi-stage pipelines [src/s_tir/transform/inject_software_pipeline.cc18-215](https://github.com/apache/tvm/blob/b16cdecb/src/s_tir/transform/inject_software_pipeline.cc#L18-L215)

 
### Thread and Storage Scopes

 TIRx supports an expanded set of storage ranks beyond standard TIR, including accelerator-specific buffers:

 
 - `kTrnSbuf` / `kTrnPsum`: AWS Trainium specific buffers [src/runtime/thread_storage_scope.h76-80](https://github.com/apache/tvm/blob/b16cdecb/src/runtime/thread_storage_scope.h#L76-L80)

## 5. Backend Implementation: CodeGenCUDA

 The `CodeGenCUDA` class handles the translation of TIRx IR into CUDA C++ and inline PTX.

 
### Key Implementation Details:

 
 - **FP8/FP6/FP4 Support:** Specialized logic for NVIDIA's narrow-precision types (e.g., `__nv_fp8_e4m3x2`) [src/backend/cuda/codegen/codegen_cuda.cc81-170](https://github.com/apache/tvm/blob/b16cdecb/src/backend/cuda/codegen/codegen_cuda.cc#L81-L170)
 - **Intrinsic Lowering:** Maps TIRx intrinsics to `__forceinline__ __device__` helper functions in the generated source [tests/python/tirx/codegen/test_codegen_cuda.py52-72](https://github.com/apache/tvm/blob/b16cdecb/tests/python/tirx/codegen/test_codegen_cuda.py#L52-L72)
 - **Global Barriers:** Implements `tvm_global_barrier_state` for multi-block synchronization [src/backend/cuda/codegen/codegen_cuda.cc174-179](https://github.com/apache/tvm/blob/b16cdecb/src/backend/cuda/codegen/codegen_cuda.cc#L174-L179)
 
 
### CUDA Runtime Module

 The `CUDAModuleNode` manages the lifecycle of compiled kernels. It supports multi-GPU execution by lazily loading modules into the primary context of each device [src/backend/cuda/runtime/cuda_module.cc68-94](https://github.com/apache/tvm/blob/b16cdecb/src/backend/cuda/runtime/cuda_module.cc#L68-L94) It also preserves the caller's current device during destructor cleanup to avoid side effects in multi-tenant environments [src/backend/cuda/runtime/cuda_module.cc76-93](https://github.com/apache/tvm/blob/b16cdecb/src/backend/cuda/runtime/cuda_module.cc#L76-L93)
