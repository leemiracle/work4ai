  Relax IR is TVM's high-level intermediate representation designed specifically for neural network computation. It serves as the primary abstraction layer for representing dataflow graphs and control flow in machine learning models, sitting above TensorIR (TIR) in TVM's compilation stack. Relax IR handles the representation and optimization of neural network operators, tensor manipulations, and model structure before lowering to hardware-specific implementations.

 For information about TensorIR (low-level tensor computations), see [TensorIR (TIR)](https://deepwiki.com/apache/tvm/2.1-tensorir-(tir)). For details about TVM's operator inventory and hardware-specific implementations, see [TOPI - TVM Operator Inventory](https://deepwiki.com/apache/tvm/3.2-topi-tvm-operator-inventory).

 
## Architecture Overview

 Relax IR forms the high-level layer of TVM's compilation pipeline, providing abstractions for neural network operations and dataflow computation. The IR is built on a type system that tracks tensor shapes and types, enabling compile-time shape inference and optimization. Unlike previous high-level IRs, Relax treats functions as first-class citizens and supports dynamic shapes natively through TIR symbolic variables.

## Core IR Components

 Relax IR is defined by several key data structures that represent the program's structure and dataflow.

 
### IRModule and Function

 The `IRModule` is the global container for all functions in a Relax program [python/tvm/relax/block_builder.py29](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/block_builder.py#L29-L29) It maps `GlobalVar` identifiers to `BaseFunc` implementations, which can be either Relax `Function` nodes or TIR `PrimFunc` nodes [src/relax/ir/block_builder.cc79-107](https://github.com/apache/tvm/blob/b16cdecb/src/relax/ir/block_builder.cc#L79-L107)

 A Relax `Function` consists of:

 
 - **Parameters**: A list of `Var` objects representing input tensors [python/tvm/relax/block_builder.py33](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/block_builder.py#L33-L33)
 - **Body**: Typically a `SeqExpr` containing a series of `BindingBlock`s and a final return expression [src/relax/analysis/well_formed.cc51-52](https://github.com/apache/tvm/blob/b16cdecb/src/relax/analysis/well_formed.cc#L51-L52)
 - **Attributes**: A dictionary of attributes such as `Primitive` or `global_symbol` [tests/python/relax/test_tvmscript_parser.py50-57](https://github.com/apache/tvm/blob/b16cdecb/tests/python/relax/test_tvmscript_parser.py#L50-L57)
 - **Purity**: Relax supports tracking side effects via the `is_pure` flag [python/tvm/relax/block_builder.py42](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/block_builder.py#L42-L42)
 
 
### Variable Scoping and Bindings

 Relax distinguishes between different types of variables to enable precise dataflow analysis:

 
 - `Var`: A standard variable visible within its scope [python/tvm/relax/expr.py33](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/expr.py#L33-L33)
 - `DataflowVar`: A specialized variable used within `DataflowBlock`s that is not visible outside the block, facilitating aggressive optimizations like fusion [src/relax/analysis/well_formed.cc38-39](https://github.com/apache/tvm/blob/b16cdecb/src/relax/analysis/well_formed.cc#L38-L39)
 - `GlobalVar`: A reference to a function within the `IRModule` [python/tvm/relax/expr.py33](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/expr.py#L33-L33)
 
 Variables are bound to expressions using `Binding` nodes, which are organized into `BindingBlock`s [python/tvm/relax/block_builder.py33](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/block_builder.py#L33-L33)

## Well-Formedness and Analysis

 To ensure that Relax IR is valid for optimization and code generation, TVM provides a `WellFormedChecker` [src/relax/analysis/well_formed.cc91](https://github.com/apache/tvm/blob/b16cdecb/src/relax/analysis/well_formed.cc#L91-L91) This analysis pass verifies several properties:

 
 - **SSA Form**: Each variable must be defined exactly once [src/relax/analysis/well_formed.cc37](https://github.com/apache/tvm/blob/b16cdecb/src/relax/analysis/well_formed.cc#L37-L37)
 - **Scoping**: Variables must be defined before use, and `DataflowVar`s must not be defined inside a standard `BindingBlock` [src/relax/analysis/well_formed.cc36-38](https://github.com/apache/tvm/blob/b16cdecb/src/relax/analysis/well_formed.cc#L36-L38)
 - **ANF (Administrative Normal Form)**: Expressions cannot contain nested complex expressions; nested inputs must be "leaf" expressions like constants or variables [src/relax/analysis/well_formed.cc43-57](https://github.com/apache/tvm/blob/b16cdecb/src/relax/analysis/well_formed.cc#L43-L57)
 - **Type Completeness**: Every expression (except `Op`) must have its type (`ty`) field populated [src/relax/analysis/well_formed.cc58](https://github.com/apache/tvm/blob/b16cdecb/src/relax/analysis/well_formed.cc#L58-L58)

## Transformations and Passes

 Relax IR supports a modern pass infrastructure for graph-level and lowering transformations.

 
### Dead Code Elimination (DCE)

 The `DeadCodeElimination` pass removes unused bindings and functions from the `IRModule` [src/relax/transform/dead_code_elimination.cc](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/dead_code_elimination.cc) It is capable of removing unused Relax functions and TIR functions that are no longer referenced [tests/python/relax/test_transform_dead_code_elimination.py162-190](https://github.com/apache/tvm/blob/b16cdecb/tests/python/relax/test_transform_dead_code_elimination.py#L162-L190)

 
### Normalization

 The `Normalize` pass ensures that the IR adheres to structural invariants (like ANF) and that type information is correctly propagated throughout the graph [src/relax/transform/normalize.cc](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/normalize.cc)

 
### Lambda Lifting

 The `LambdaLift` pass converts local `relax.Function` definitions (closures) into global functions within the `IRModule`, which is a prerequisite for backends that do not support nested functions [src/relax/transform/lambda_lift.cc](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/lambda_lift.cc)
