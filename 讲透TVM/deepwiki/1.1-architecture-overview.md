## Purpose and Scope

 This document provides a high-level map of TVM's architecture, illustrating how the major subsystems—frontends, intermediate representations (IRs), transformations, code generation, and runtime—interconnect to form a complete machine learning compilation stack. The focus is on the structural organization and data flow through the system.

 TVM follows a layered design where a model is progressively lowered from a high-level computational graph to hardware-specific machine code. The primary data structure throughout this flow is the `IRModule`, which serves as a container for various function types, primarily `relax::Function` and `tirx::PrimFunc`.

## Core IR Representations

 The `IRModule` is the fundamental unit of transformation. It encapsulates functions, global information, and metadata attributes.

 
| Component | Class / Node | File Path | Purpose |
|---|---|---|---|
| Module Container | IRModule / IRModuleNode | src/ir/module.cc44-61 | Holds functions, global_infos, and attrs. |
| High-level Func | relax::Function | src/relax/ir/expr.cc43 | Represents graph-level dataflow and control flow. |
| Low-level Func | tirx::PrimFunc | include/tvm/ir/module.h51-56 | Loop-nest choices, vector/tensor instructions. |
| Attributes | DictAttrs | include/tvm/ir/attrs.h70-82 | Map-backed metadata for modules and functions. |
| Expression Base | Expr / ExprNode | include/tvm/ir/expr.h48-58 | Base class for all IR expressions. |

## Expression and Type System

 TVM uses a unified expression system where `PrimExpr` handles scalar/primitive logic and `relax::Expr` handles high-level tensor operations.

 
 - **PrimExpr**: Represents scalar expressions (e.g., `IntImm`, `FloatImm`) used in indexing and loop bounds [include/tvm/ir/expr.h117-248](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/ir/expr.h#L117-L248)
 - **Relax Expr**: Extends the IR to support dataflow via `VarBinding` and `DataflowBlock` [include/tvm/relax/expr.h192-230](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/relax/expr.h#L192-L230)
 - **Types**: Managed through `tvm::ir::Type`, including `PrimType`, `TensorType`, and `TupleType` [include/tvm/ir/type.h36-100](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/ir/type.h#L36-L100)

## Target and Device Abstraction

 The `Target` system describes compiler options, while `VirtualDevice` represents runtime constraints.

 
 - **Target**: Describes the microarchitecture (e.g., `llvm -mcpu=sky-lake`).
 - **VirtualDevice**: A quadruple of `device_type`, `virtual_device_id`, `target`, and `memory_scope`. It is used during device planning to solve constraints.

## Code Generation and Runtime

 After transformations, the `IRModule` is translated into an executable format.

 
 - **Codegen**: Translates `tirx::PrimFunc` into target-specific code via backends like LLVM or CUDA [src/ir/module.cc33](https://github.com/apache/tvm/blob/b16cdecb/src/ir/module.cc#L33-L33)
 - **runtime.Module**: Encapsulates the generated code and provides a `PackedFunc` interface for execution [python/tvm/runtime/__init__.py33](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/runtime/__init__.py#L33-L33)
 - **Virtual Machine (VM)**: Executes `relax::Function` by interpreting bytecode and calling into optimized kernels [python/tvm/relax/op/vm/vm.py23](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/op/vm/vm.py#L23-L23)
