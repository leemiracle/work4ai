  The TVM build system is a CMake-based configuration and compilation infrastructure that manages cross-platform builds for TVM's compiler and runtime libraries. It provides a flexible option system for enabling different backends (CUDA, ROCM, OpenCL, Vulkan, etc.), compiler features (LLVM, MLIR), and third-party libraries (cuDNN, CUTLASS, TensorRT).

 
## Overview

 The build system consists of three main components:

 
 - **Main Build Configuration** - [CMakeLists.txt1-144](https://github.com/apache/tvm/blob/b16cdecb/CMakeLists.txt#L1-L144) orchestrates the entire build.
 - **Option Management** - [cmake/config.cmake1-224](https://github.com/apache/tvm/blob/b16cdecb/cmake/config.cmake#L1-L224) provides user-configurable build options.
 - **Utility Macros** - [cmake/utils/Utils.cmake1-50](https://github.com/apache/tvm/blob/b16cdecb/cmake/utils/Utils.cmake#L1-L50) provides standard functions like `tvm_option` for feature toggling.

## Configuration System

 
### Option Declaration and Management

 TVM uses a custom CMake macro `tvm_option()` to declare configurable build options. This is the primary mechanism for feature toggling.

 
| Option Category | Examples | Purpose |
|---|---|---|
| Backends | USE_CUDA, USE_VULKAN, USE_ROCM | Enables hardware-specific runtimes CMakeLists.txt43-60 |
| Compiler | USE_LLVM, USE_MLIR | Enables code generation backends CMakeLists.txt71-72 |
| Contrib | USE_DNNL, USE_CUDNN, USE_CUTLASS | Integrates external libraries CMakeLists.txt94-98 |
| Runtime | USE_RPC, USE_RTTI, USE_THREADS | Configures core runtime features CMakeLists.txt69-76 |

 Sources: [CMakeLists.txt43-116](https://github.com/apache/tvm/blob/b16cdecb/CMakeLists.txt#L43-L116) [cmake/config.cmake49-224](https://github.com/apache/tvm/blob/b16cdecb/cmake/config.cmake#L49-L224)

 
### User Configuration Workflow

 Users typically follow this workflow to customize their build:

 
 - Create a `build` directory.
 - Copy `cmake/config.cmake` to the `build` folder [cmake/config.cmake23-27](https://github.com/apache/tvm/blob/b16cdecb/cmake/config.cmake#L23-L27)
 - Modify `set(OPTION VALUE)` in the local `config.cmake` [cmake/config.cmake29-32](https://github.com/apache/tvm/blob/b16cdecb/cmake/config.cmake#L29-L32)
 - Run `cmake ..` which includes the local configuration [CMakeLists.txt31-37](https://github.com/apache/tvm/blob/b16cdecb/CMakeLists.txt#L31-L37)
 
 In CI environments, this is automated via scripts like `task_config_build_gpu.sh`, which append specific `set` commands to `config.cmake` [tests/scripts/task_config_build_gpu.sh26-43](https://github.com/apache/tvm/blob/b16cdecb/tests/scripts/task_config_build_gpu.sh#L26-L43)

 Sources: [cmake/config.cmake18-37](https://github.com/apache/tvm/blob/b16cdecb/cmake/config.cmake#L18-L37) [CMakeLists.txt31-37](https://github.com/apache/tvm/blob/b16cdecb/CMakeLists.txt#L31-L37) [tests/scripts/task_config_build_gpu.sh26-43](https://github.com/apache/tvm/blob/b16cdecb/tests/scripts/task_config_build_gpu.sh#L26-L43)

 
## Platform-Specific Builds

 The build system handles complex platform-specific logic via dedicated modules in `cmake/modules/`.

 
### CUDA and GPU Backends

 The CUDA build is managed by [cmake/modules/CUDA.cmake](https://github.com/apache/tvm/blob/b16cdecb/cmake/modules/CUDA.cmake) It handles:

 
 - Finding the CUDA toolkit and cuDNN via `find_cuda` [cmake/modules/CUDA.cmake19-21](https://github.com/apache/tvm/blob/b16cdecb/cmake/modules/CUDA.cmake#L19-L21)
 - Setting `CMAKE_CUDA_ARCHITECTURES` (defaults to `native` if CMake >= 3.24) [cmake/modules/CUDA.cmake53-59](https://github.com/apache/tvm/blob/b16cdecb/cmake/modules/CUDA.cmake#L53-L59)
 - Building the `tvm_runtime_cuda` shared library which links `libcuda` and `libcudart` [cmake/modules/CUDA.cmake85-87](https://github.com/apache/tvm/blob/b16cdecb/cmake/modules/CUDA.cmake#L85-L87)
 - Configuring contrib libraries like `cuBLAS`, `cuDNN`, and `Thrust` [cmake/modules/CUDA.cmake128-152](https://github.com/apache/tvm/blob/b16cdecb/cmake/modules/CUDA.cmake#L128-L152)
 
 Sources: [cmake/modules/CUDA.cmake1-152](https://github.com/apache/tvm/blob/b16cdecb/cmake/modules/CUDA.cmake#L1-L152)

 
### Hexagon DSP Support

 Hexagon support is managed by [cmake/modules/Hexagon.cmake](https://github.com/apache/tvm/blob/b16cdecb/cmake/modules/Hexagon.cmake) It includes logic for:

 
 - Finding the Hexagon toolchain within the Hexagon SDK [cmake/modules/Hexagon.cmake23-44](https://github.com/apache/tvm/blob/b16cdecb/cmake/modules/Hexagon.cmake#L23-L44)
 - Differentiating between builds `BUILD_FOR_HEXAGON` (the DSP), `BUILD_FOR_ANDROID` (the host), or `BUILD_FOR_HOST` (simulator) [cmake/modules/Hexagon.cmake76-78](https://github.com/apache/tvm/blob/b16cdecb/cmake/modules/Hexagon.cmake#L76-L78)
 - Enabling Qualcomm Hexagon Libraries (QHL) and HVX-specific optimizations [cmake/modules/Hexagon.cmake162-179](https://github.com/apache/tvm/blob/b16cdecb/cmake/modules/Hexagon.cmake#L162-L179)
 
 Sources: [cmake/modules/Hexagon.cmake1-197](https://github.com/apache/tvm/blob/b16cdecb/cmake/modules/Hexagon.cmake#L1-L197)

 
### LLVM Integration

 LLVM is a critical dependency for CPU code generation. The build system:

 
 - Supports auto-searching or specific `llvm-config` paths [cmake/utils/FindLLVM.cmake36-40](https://github.com/apache/tvm/blob/b16cdecb/cmake/utils/FindLLVM.cmake#L36-L40)
 - Maps LLVM components to library names using `llvm_map_components_to_libnames` [cmake/utils/FindLLVM.cmake55-56](https://github.com/apache/tvm/blob/b16cdecb/cmake/utils/FindLLVM.cmake#L55-L56)
 - Detects available targets like `AArch64` [cmake/utils/FindLLVM.cmake74-77](https://github.com/apache/tvm/blob/b16cdecb/cmake/utils/FindLLVM.cmake#L74-L77)
 
 Sources: [cmake/utils/FindLLVM.cmake36-173](https://github.com/apache/tvm/blob/b16cdecb/cmake/utils/FindLLVM.cmake#L36-L173)

 
## Versioning and Python Integration

 
### Version Baking

 The TVM version is resolved during the CMake configure step.

 
 - If built via `scikit-build-core`, the version is passed in as `SKBUILD_PROJECT_VERSION_FULL` [CMakeLists.txt9-11](https://github.com/apache/tvm/blob/b16cdecb/CMakeLists.txt#L9-L11)
 - The version is baked into the C++ compilation via the `TVM_VERSION` macro [CMakeLists.txt12-15](https://github.com/apache/tvm/blob/b16cdecb/CMakeLists.txt#L12-L15)
 
 Sources: [CMakeLists.txt4-15](https://github.com/apache/tvm/blob/b16cdecb/CMakeLists.txt#L4-L15)

 
### Dependency Installation

 TVM provides scripts to prepare build environments, particularly for Python and ONNX dependencies.

 
 - `ubuntu_install_python_package.sh` installs core Python dependencies like `numpy`, `scipy`, and `pytest` using `uv` [docker/install/ubuntu_install_python_package.sh24-43](https://github.com/apache/tvm/blob/b16cdecb/docker/install/ubuntu_install_python_package.sh#L24-L43)
 - `ubuntu_install_onnx.sh` installs `onnx`, `onnxruntime`, and `torch` [docker/install/ubuntu_install_onnx.sh30-44](https://github.com/apache/tvm/blob/b16cdecb/docker/install/ubuntu_install_onnx.sh#L30-L44)
