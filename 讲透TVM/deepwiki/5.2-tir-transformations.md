## Purpose and Scope

 TIR transformations are compiler passes that optimize and lower TensorIR (TIR) programs toward executable code. These passes operate on `tvm.ir.IRModule` objects containing `tvm.tirx.PrimFunc` functions, applying optimizations, lowering high-level constructs to target-specific code, and ensuring correctness through legalization.

 TIR transformations are distinct from TIR scheduling (which provides an interactive API for manual optimization). Transformations are automatic passes applied during compilation pipelines, while scheduling is typically used for manual tuning or as part of auto-tuning systems like MetaSchedule.

 For information about TensorIR itself, see [TensorIR (TIR)](https://deepwiki.com/apache/tvm/2.1-tensorir-(tir)). For Relax-level transformations, see [Relax Transformations](https://deepwiki.com/apache/tvm/5.1-relax-transformations).

## Transformation Categories

 
### Simplification and Optimization

 
#### Dead Code Elimination (DCE)

 `DeadCodeElimination` removes unreachable functions and unused local variables. In Relax/TIR modules, it identifies entry functions (marked with `kExternal` linkage or user-specified) and performs a reachability analysis to prune the module.

 Sources: [src/relax/transform/run_codegen.cc103](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/run_codegen.cc#L103-L103) [src/relax/transform/run_codegen.cc49-75](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/run_codegen.cc#L49-L75)

 
#### Arithmetic Simplification

 TIR transformations rely heavily on the arithmetic analysis subsystem to simplify indices and predicates. The `IRMutatorWithAnalyzer` provides a base for passes to simplify expressions within statements like `For` loops and `IfThenElse`.

 
 - **IterMapSimplify**: Uses detected patterns to rewrite complex index expressions into simplified forms, often used during buffer access lowering.
 - **Constraint Facts**: The analyzer collects facts from conditions (e.g., `extent > 0`) to simplify the body of loops or branches.
 
 Sources: [src/arith/ir_mutator_with_analyzer.cc156-167](https://github.com/apache/tvm/blob/b16cdecb/src/arith/ir_mutator_with_analyzer.cc#L156-L167) [src/arith/ir_mutator_with_analyzer.cc169-187](https://github.com/apache/tvm/blob/b16cdecb/src/arith/ir_mutator_with_analyzer.cc#L169-L187) [src/arith/ir_mutator_with_analyzer.cc189-204](https://github.com/apache/tvm/blob/b16cdecb/src/arith/ir_mutator_with_analyzer.cc#L189-L204)

 
### Lowering and Decomposition

 
#### CUDA Graph Rewriting

 `RewriteCUDAGraph` transforms a module to capture and execute static regions using CUDA Graphs.

 
 - **Planning**: `CUDAGraphRewritePlanner` identifies static regions that only depend on internal constant-shape allocations and contain no control flow.
 - **Lifting**: Identified regions are lifted into separate functions for allocation (`cuda_graph_alloc`) and capturing (`main_cuda_graph_capture`).
 - **Runtime Integration**: The original function is rewritten to use `vm.builtin.cuda_graph.get_cached_alloc` and capture/launch mechanisms.
 
 Sources: [src/relax/transform/rewrite_cuda_graph.cc24-51](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/rewrite_cuda_graph.cc#L24-L51) [src/relax/transform/rewrite_cuda_graph.cc76-95](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/rewrite_cuda_graph.cc#L76-L95) [src/relax/transform/rewrite_cuda_graph.cc127-140](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/rewrite_cuda_graph.cc#L127-L140)

 
#### VM Shape Lowering

 `VMShapeLower` handles the boundary between symbolic shape definitions and runtime execution. It collects symbolic `PrimExpr` slots and generates code to compute their values at runtime, ensuring that symbolic variables are defined before they are used in tensor allocations or kernel launches.

 Sources: [src/relax/backend/vm/vm_shape_lower.cc20-35](https://github.com/apache/tvm/blob/b16cdecb/src/relax/backend/vm/vm_shape_lower.cc#L20-L35) [src/relax/backend/vm/vm_shape_lower.cc43-62](https://github.com/apache/tvm/blob/b16cdecb/src/relax/backend/vm/vm_shape_lower.cc#L43-L62) [src/relax/backend/vm/vm_shape_lower.cc92-109](https://github.com/apache/tvm/blob/b16cdecb/src/relax/backend/vm/vm_shape_lower.cc#L92-L109)

 
### Loop and Storage Transformations

 Automated passes exist for optimizing the low-level TIR structure:

 
 - **Vectorization**: Lowering loops with vector annotations to target-specific SIMD instructions.
 - **FlattenBuffer**: Linearizing multi-dimensional buffer accesses into 1D pointer arithmetic.
 - **StorageRewrite**: Reusing memory buffers for non-overlapping tensor lifetimes to reduce peak memory usage.
 - **Narrow Indexing**: `ForceNarrowIndexToInt32` forces index calculations to use 32-bit integers for performance on certain hardware targets.
