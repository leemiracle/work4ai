  Disco is TVM's distributed runtime framework designed for multi-GPU and multi-node execution. It follows a **Single-Program-Multiple-Data (SPMD)** model where a controller manages a cluster of workers by broadcasting commands. Each worker maintains its own register file, and instructions are executed synchronously across the cluster [include/tvm/runtime/disco/session.h24-35](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/runtime/disco/session.h#L24-L35).

 
## Architecture Overview

 Disco consists of three primary layers: the **Control Plane** for command orchestration, the **Data Plane** for high-performance collective communication, and the **Session** interface for user interaction [include/tvm/runtime/disco/session.h53-72](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/runtime/disco/session.h#L53-L72).

## Session Management

 The `Session` is the primary interface for interacting with the distributed runtime. It manages the lifecycle of workers and provides methods to allocate memory and call functions across the cluster.

 
### Session Types

 Disco supports several session implementations depending on the hardware topology:

 
 - **ThreadedSession**: Uses a thread pool for single-node multi-GPU scenarios.
 - **ProcessSession**: Uses multiple processes for better isolation.
 - **SocketSession**: Connects to remote nodes via TCP sockets for multi-node clusters [include/tvm/runtime/disco/session.h64-67](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/runtime/disco/session.h#L64-L67), [python/tvm/runtime/disco/session.py34](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/runtime/disco/session.py#L34-L34), [python/tvm/runtime/disco/process_pool.py27-49](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/runtime/disco/process_pool.py#L27-L49).
 
 
### DRef: Distributed References

 A `DRef` (Distributed Reference) represents an object that exists on all workers. The controller assigns a unique "register ID" to each object, and workers use this ID to access the local instance of the data [python/tvm/runtime/disco/session.py37-41](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/runtime/disco/session.py#L37-L41).

## Collective Communication (CCL)

 Disco provides a unified interface for data plane operations, supporting NCCL (NVIDIA), RCCL (AMD), and NVSHMEM.

 
### Core Collective Operations

 Built-in primitives are defined in `include/tvm/runtime/disco/builtin.h` and implemented via backend-specific libraries.

 
 - **AllReduce**: Combines tensors from all workers using a `ReduceKind` (Sum, Prod, Min, Max, Avg) [include/tvm/runtime/disco/builtin.h34-82](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/runtime/disco/builtin.h#L34-L82).
 - **AllGather**: Concatenates tensors from all workers into a single tensor on each worker [include/tvm/runtime/disco/builtin.h89](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/runtime/disco/builtin.h#L89-L89).
 - **Broadcast**: Sends data from Worker-0 to all other workers [include/tvm/runtime/disco/builtin.h96](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/runtime/disco/builtin.h#L96-L96).
 - **Scatter/Gather**: Chunks and distributes data from Worker-0, or collects chunks back to Worker-0 [include/tvm/runtime/disco/builtin.h98-112](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/runtime/disco/builtin.h#L98-L112).
 - **Group Transfer**: `SendToNextGroup` and `RecvFromPrevGroup` allow data movement between worker groups [include/tvm/runtime/disco/builtin.h119-129](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/runtime/disco/builtin.h#L119-L129).
 
 
### NVSHMEM Support

 For low-latency communication, Disco integrates with NVSHMEM. This requires initializing a Unique ID (`runtime.disco.nvshmem.init_nvshmem_uid`) and calling `init_nvshmem` across the session [tests/python/disco/test_nvshmem.py182-186](https://github.com/apache/tvm/blob/b16cdecb/tests/python/disco/test_nvshmem.py#L182-L186).

## Integration with Paged KV Cache and FlashInfer

 Disco is extensively used in LLM deployments to manage distributed KV caches and execute attention kernels via FlashInfer.

 
### FlashInfer Runtime

 Disco sessions can load FlashInfer modules to perform paged attention across multiple GPUs. The `gen_flashinfer_prefill_module` and `gen_flashinfer_decode_module` functions generate JIT-compiled kernels that are then loaded into Disco workers [python/tvm/relax/backend/cuda/flashinfer.py58-186](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/backend/cuda/flashinfer.py#L58-L186).

## Sharded Model Loading

 Disco includes a `ShardLoader` to handle loading large model weights into a distributed environment.

 
 - **ShardLoader**: A global function (`runtime.disco.ShardLoader`) that takes a path to a tensor cache and a sharding specification [tests/python/disco/test_loader.py114-116](https://github.com/apache/tvm/blob/b16cdecb/tests/python/disco/test_loader.py#L114-L116).
 - **Sharding Functions**: Custom functions (e.g., `shard_dim_0`, `shard_qkv_0`) can be registered to define how tensors are split across workers during the load process [tests/python/disco/test_loader.py63-101](https://github.com/apache/tvm/blob/b16cdecb/tests/python/disco/test_loader.py#L63-L101).
 - **Pre-sharded Weights**: Disco also supports loading weights that have already been partitioned on disk, matching the MLC-LLM format [tests/python/disco/test_loader.py119-205](https://github.com/apache/tvm/blob/b16cdecb/tests/python/disco/test_loader.py#L119-L205).
