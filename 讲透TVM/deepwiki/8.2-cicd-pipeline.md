## Purpose and Scope

 This document describes TVM's continuous integration and continuous deployment (CI/CD) infrastructure. The CI/CD pipeline validates code changes, builds TVM across multiple platforms, runs test suites, and ensures code quality. The system primarily uses a Jenkins-based infrastructure with Docker-isolated build environments, supplemented by GitHub Actions for specific platforms like macOS and Windows.

 For information about the CMake build system that the CI/CD pipeline orchestrates, see [Build System](https://deepwiki.com/apache/tvm/8.1-build-system). For information about TVM's community contribution process, see [Community and Governance](https://deepwiki.com/apache/tvm/8.4-community-and-governance).

## Docker Infrastructure

 TVM relies heavily on Docker to provide reproducible, isolated build and test environments. Each major platform (CPU, GPU, ARM, WASM) has a dedicated Docker image.

 
### Docker Image Definitions

### Execution Wrappers

 
#### `bash.sh`

 The `docker/bash.sh` script is the primary entry point for running commands inside TVM CI containers. It handles:

 
 - **Mounting**: Automatically mounts the TVM repository root to `/workspace` (in Jenkins) or the current path [docker/bash.sh64-68](https://github.com/apache/tvm/blob/b16cdecb/docker/bash.sh#L64-L68)
 - **User Mapping**: Ensures files created in the container are owned by the host user via `docker/with_the_same_user`.
 - **GPU Passthrough**: Configures `--gpus all` for CUDA-enabled images unless `--no-gpu` is specified [docker/bash.sh164-174](https://github.com/apache/tvm/blob/b16cdecb/docker/bash.sh#L164-L174)
 
 
#### `build.sh`

 The `docker/build.sh` script automates the creation of these Docker images. It supports custom tags, specific Dockerfiles, and caching mechanisms using `--cache-from` [docker/build.sh108-115](https://github.com/apache/tvm/blob/b16cdecb/docker/build.sh#L108-L115)

## Jenkins Pipeline Management

 TVM uses a template-based approach to generate Jenkinsfiles to avoid manual repetition across hardware pipelines.

 
### Generation Logic

 The generator script [ci/jenkins/generate.py102-151](https://github.com/apache/tvm/blob/b16cdecb/ci/jenkins/generate.py#L102-L151) implements a "smart" update mechanism:

 
 - **Change Classification**: The `change_type()` function detects if a change is purely a Docker image tag update (`Change.IMAGES_ONLY`) or a logic change (`Change.FULL`) [ci/jenkins/generate.py58-99](https://github.com/apache/tvm/blob/b16cdecb/ci/jenkins/generate.py#L58-L99)
 - **Timestamp Preservation**: If only Docker tags change, the generator preserves the existing "// Generated at" timestamp to minimize repository noise [ci/jenkins/generate.py143-146](https://github.com/apache/tvm/blob/b16cdecb/ci/jenkins/generate.py#L143-L146)
 - **CI Validation**: In CI, `generate.py --check` ensures that the committed `generated/` files match the source templates [ci/jenkins/generate.py163-188](https://github.com/apache/tvm/blob/b16cdecb/ci/jenkins/generate.py#L163-L188)
 
 
### Generated Pipelines

 Pipelines are generated for specific architectures:

 
 - `arm_jenkinsfile.groovy`: Handles AArch64 builds and tests [ci/jenkins/generated/arm_jenkinsfile.groovy1-153](https://github.com/apache/tvm/blob/b16cdecb/ci/jenkins/generated/arm_jenkinsfile.groovy#L1-L153)
 - `gpu_jenkinsfile.groovy`: Orchestrates CUDA and GPU-accelerated testing.
 - `cpu_jenkinsfile.groovy`: Standard x86 verification.
 
 **Sources:** [ci/jenkins/generate.py58-151](https://github.com/apache/tvm/blob/b16cdecb/ci/jenkins/generate.py#L58-L151) [ci/jenkins/generated/arm_jenkinsfile.groovy1-110](https://github.com/apache/tvm/blob/b16cdecb/ci/jenkins/generated/arm_jenkinsfile.groovy#L1-L110)

## Testing Infrastructure

 TVM uses `pytest` as its primary testing framework, supplemented by custom utilities in `tvm.testing`.

 
### Environment Probing and Markers

 The `tvm.testing` module provides utilities to gate tests based on hardware availability:

 
 - **Markers**: `@pytest.mark.gpu` is used to route tests to Jenkins nodes with GPU hardware [python/tvm/testing/utils.py29-38](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/testing/utils.py#L29-L38)
 - **Skips**: Tests use `tvm.testing.env` probes (e.g., `has_cuda()`, `has_vulkan()`) to skip tests when required libraries are missing [python/tvm/testing/utils.py43-55](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/testing/utils.py#L43-L55)
 - **CI Detection**: The `IS_IN_CI` flag (based on `CI` env var) allows tests to adjust behavior [python/tvm/testing/utils.py94](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/testing/utils.py#L94-L94)
 
 
### CI Scripts and Utilities

 TVM includes specific scripts to manage CI behavior:

 
 - `git_skip_ci.py`: Logic to skip CI based on commit messages (e.g., `[skip ci]`) or PR titles [tests/python/ci/test_ci.py38-103](https://github.com/apache/tvm/blob/b16cdecb/tests/python/ci/test_ci.py#L38-L103)
 - `git_skip_ci_globs.py`: Logic to skip CI if only specific files (like `README.md`) are modified [tests/python/ci/test_ci.py130-143](https://github.com/apache/tvm/blob/b16cdecb/tests/python/ci/test_ci.py#L130-L143)
 
 
### Code Quality and Linting

 Before functional testing, the CI runs several linting tasks:

 
 - **File Type Check**: `tests/lint/check_file_type.py` ensures no binary files or unauthorized extensions are committed [tests/lint/check_file_type.py24-95](https://github.com/apache/tvm/blob/b16cdecb/tests/lint/check_file_type.py#L24-L95)
 - **CI Script Validation**: `tests/python/ci/test_ci.py` validates the CI's own logic, including Docker tag updates and skip-ci logic [tests/python/ci/test_ci.py18-200](https://github.com/apache/tvm/blob/b16cdecb/tests/python/ci/test_ci.py#L18-L200)

## Platform-Specific Workflows

 While Jenkins handles the bulk of the CI (Linux, GPU, ARM), GitHub Actions is used for platforms where Jenkins nodes are not available.

 
### macOS and Windows CI

 The `.github/workflows/main.yml` workflow manages:

 
 - **macOS Build**: Builds TVM with LLVM and Metal support, running minimal platform tests [.github/workflows/main.yml41-91](https://github.com/apache/tvm/blob/b16cdecb/ .github/workflows/main.yml#L41-L91)
 - **Windows Build**: Builds TVM using `scikit-build-core` and LLVM on Windows runners [.github/workflows/main.yml92-120](https://github.com/apache/tvm/blob/b16cdecb/ .github/workflows/main.yml#L92-L120)
