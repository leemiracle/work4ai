## Purpose and Scope

 The CUTLASS Integration provides a backend for offloading matrix multiplication (GEMM), convolution (Conv2D), attention, and normalization operations to NVIDIA's CUTLASS library for optimized execution on NVIDIA GPUs. This integration enables TVM to leverage CUTLASS's highly optimized tensor core kernels for deep learning workloads.

 For general information about code generation backends, see [Code Generation](https://deepwiki.com/apache/tvm/6-code-generation). For the native CUDA backend, see [CUDA Backend](https://deepwiki.com/apache/tvm/6.3-cuda-backend). For target configuration, see [Target System](https://deepwiki.com/apache/tvm/6.1-target-system).

 
## Architecture Overview

 The CUTLASS integration operates as a specialized code generation backend within TVM's compilation pipeline. It identifies suitable operation patterns in Relax IR, partitions them into composite functions, profiles CUTLASS kernel candidates, and generates C++ host code that dispatches to the selected CUTLASS kernels.

## Supported Operations

 The CUTLASS integration supports the following operation categories, each with specific fusion patterns and epilogue options:

 
| Operation | Epilogue Options | Residual Support | Pattern Function |
|---|---|---|---|
| GEMM/MatMul | bias, relu, gelu, silu | add, multiply | make_matmul_pattern |
| Conv2D | bias, relu, gelu, silu, sigmoid, hardswish | add, multiply | make_conv2d_pattern |
| Attention | bias, causal mask, variable length | No | make_attention_pattern |
| Layer Norm | - | No | make_layer_norm_pattern |
| RMS Norm | - | No | make_rms_norm_pattern |

### Key Pattern Functions

 The pattern matching system uses the following core functions from `tvm.relax.backend.patterns`:

 
 - **`make_matmul_pattern(with_bias, activation, transposed_rhs)`**: Creates patterns for matrix multiplication with optional bias addition, activation, and transposed right-hand side [python/tvm/relax/backend/patterns.py176-217](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/backend/patterns.py#L176-L217)
 - **`make_conv2d_pattern(with_bias, activation)`**: Creates patterns for 2D convolution with optional bias and activation [python/tvm/relax/backend/patterns.py140-174](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/backend/patterns.py#L140-L174)
 - **`make_attention_pattern(with_bias, var_len)`**: Creates patterns for fused multi-head attention with optional bias and variable sequence lengths [python/tvm/relax/backend/patterns.py219-269](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/backend/patterns.py#L219-L269)

 For GEMM operations, the `is_shape_valid_for_cutlass_matmul` function validates whether input shapes are compatible with CUTLASS's stride-based batch matmul implementation. It checks for constant reduction axes and ensures batch dimensions do not require complex broadcasting that CUTLASS cannot handle [python/tvm/contrib/cutlass/build.py407-440](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/contrib/cutlass/build.py#L407-L440)

### Epilogue Fusion

 The CUTLASS integration supports various epilogue operations fused into the kernel. The `EPILOGUE_MAP` dictionary in `python/tvm/contrib/cutlass/gen_tensor_op.py` maps Relax operation names to CUTLASS epilogue functors [python/tvm/contrib/cutlass/gen_tensor_op.py26](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/contrib/cutlass/gen_tensor_op.py#L26-L26):

 
| Operation Type | Epilogue Functor | No Beta Scaling |
|---|---|---|
| cutlass.matmul | LinearCombination | False |
| cutlass.matmul_bias | LinearCombination | True |
| cutlass.matmul_bias_relu | LinearCombinationRelu | True |
| cutlass.conv2d_bias_silu | LinearCombinationSilu | False |

## Compilation and Runtime Integration

 
### Module Compilation

 The `compile_cutlass_module` function compiles generated C++ code using NVCC. Compilation options are retrieved via `_get_cutlass_compile_options`, which sets include paths for CUTLASS headers and architecture-specific gencode flags [python/tvm/contrib/cutlass/build.py59-93](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/contrib/cutlass/build.py#L59-L93)

 
### Runtime Execution

 At runtime, the compiled CUTLASS modules are loaded and executed through TVM's Virtual Machine. The kernels are invoked through the `call_dps` (destination-passing style) convention.

## Performance Considerations

 
### Kernel Caching

 Both `CutlassGemmProfiler` and `CutlassConv2DProfiler` implement persistent caching of profiling results in pickle files (`cutlass_gemm_cache.pickle`) to avoid redundant profiling across compilation sessions [python/tvm/contrib/cutlass/gen_gemm.py201-205](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/contrib/cutlass/gen_gemm.py#L201-L205) [python/tvm/contrib/cutlass/gen_conv2d.py192-196](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/contrib/cutlass/gen_conv2d.py#L192-L196)

 
### Profiling Strategies

 
 - **Find First Valid**: If `find_first_valid=True` is passed to the `RunCodegen` pass, the system returns the first kernel that successfully compiles and runs [python/tvm/contrib/cutlass/build.py122-123](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/contrib/cutlass/build.py#L122-L123)
