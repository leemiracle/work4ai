  The **Bring Your Own Codegen (BYOC)** framework in TVM allows the compilation and execution of specific subgraphs on external hardware accelerators or highly optimized vendor libraries. This mechanism enables TVM to act as a top-level orchestrator, partitioning a computational graph so that parts are handled by TVM's native code generation (LLVM/CUDA/TIR) while other parts are offloaded to backends like **NVIDIA TensorRT**, **cuBLAS**, **cuDNN**, **Intel DNNL**, or custom NPUs.

 
## BYOC Workflow and Architecture

 The BYOC pipeline in Relax consists of four primary stages: pattern registration, graph partitioning, external code generation, and runtime execution [docs/how_to/tutorials/bring_your_own_codegen.py56-64](https://github.com/apache/tvm/blob/b16cdecb/docs/how_to/tutorials/bring_your_own_codegen.py#L56-L64)

 
### 1. Pattern Registration

 Backends register their capabilities using the Relax Dataflow Pattern Language (DPL). These patterns describe sequences of Relax operations (e.g., `conv2d + relu`) that the backend can handle as a single unit [python/tvm/relax/backend/contrib/example_npu/patterns.py21-35](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/backend/contrib/example_npu/patterns.py#L21-L35)

 
### 2. Graph Partitioning and Merging

 
 - **`FuseOpsByPattern`**: Groups matched ops into composite functions based on registered patterns [python/tvm/relax/transform/pipeline.py88](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/transform/pipeline.py#L88-L88)
 - **`MergeCompositeFunctions`**: Consolidates adjacent composite functions bound for the same backend into a single external call to minimize overhead [docs/how_to/tutorials/bring_your_own_codegen.py128-140](https://github.com/apache/tvm/blob/b16cdecb/docs/how_to/tutorials/bring_your_own_codegen.py#L128-L140)
 
 
### 3. External Codegen

 The `RunCodegen` pass identifies functions with the `attr::kCodegen` attribute and invokes the corresponding backend serializer [src/relax/backend/contrib/tensorrt/codegen.cc94-95](https://github.com/apache/tvm/blob/b16cdecb/src/relax/backend/contrib/tensorrt/codegen.cc#L94-L95) This pass replaces the Relax function body with a `runtime::Module` containing backend-specific artifacts [docs/how_to/tutorials/bring_your_own_codegen.py156-160](https://github.com/apache/tvm/blob/b16cdecb/docs/how_to/tutorials/bring_your_own_codegen.py#L156-L160)

 
### 4. Runtime Execution

 At runtime, the TVM Virtual Machine (VM) or Executable encounters the external function and dispatches execution to the backend's runtime module (e.g., `TensorRTRuntimeModule` or `ExampleNPUJSONRuntime`) [src/runtime/extra/contrib/tensorrt/tensorrt_runtime.cc35-50](https://github.com/apache/tvm/blob/b16cdecb/src/runtime/extra/contrib/tensorrt/tensorrt_runtime.cc#L35-L50)

## Integration with Vendor Libraries

 
### TensorRT Integration

 The TensorRT backend uses a JSON-based serialization approach. The `TensorRTJSONSerializer` converts Relax operators and their attributes into a JSON format that the TVM TensorRT runtime interprets to build an `nvinfer1::ICudaEngine` [src/relax/backend/contrib/tensorrt/codegen.cc100-113](https://github.com/apache/tvm/blob/b16cdecb/src/relax/backend/contrib/tensorrt/codegen.cc#L100-L113)

 
 - **Attribute Mapping**: Relax attributes like `padding` and `strides` are extracted via `OpAttrExtractor` and mapped to JSON node attributes [src/relax/backend/contrib/tensorrt/codegen.cc111-118](https://github.com/apache/tvm/blob/b16cdecb/src/relax/backend/contrib/tensorrt/codegen.cc#L111-L118)
 - **Operator Converters**: Specific classes like `ActivationOpConverter` and `Conv2DOpConverter` map Relax ops to `nvinfer1::ILayer` types [src/runtime/extra/contrib/tensorrt/tensorrt_ops.cc161-170](https://github.com/apache/tvm/blob/b16cdecb/src/runtime/extra/contrib/tensorrt/tensorrt_ops.cc#L161-L170)
 - **Configuration**: Supports `max_workspace_size`, `use_fp16`, and `use_implicit_batch` via `TensorRTCompilerConfig` [src/relax/backend/contrib/tensorrt/codegen.cc56-84](https://github.com/apache/tvm/blob/b16cdecb/src/relax/backend/contrib/tensorrt/codegen.cc#L56-L84)
 
 
### cuBLAS and cuDNN

 These backends target specific high-performance primitives on NVIDIA GPUs:

 
 - **cuBLAS**: The `partition_for_cublas` utility identifies `matmul` patterns, including those with epilogues like `relu` or `gelu` [tests/python/relax/test_codegen_cublas.py29-111](https://github.com/apache/tvm/blob/b16cdecb/tests/python/relax/test_codegen_cublas.py#L29-L111)
 - **cuDNN**: The `partition_for_cudnn` utility targets `conv2d` and `fused_attention` operations [tests/python/relax/test_codegen_cudnn.py30-169](https://github.com/apache/tvm/blob/b16cdecb/tests/python/relax/test_codegen_cudnn.py#L30-L169)
 
 
### Backend Dispatch for Sort and Scan

 TVM uses a `SortScanDispatcher` to offload `relax.sort`, `relax.topk`, and `relax.cumsum` to platform-specific libraries like **NVIDIA Thrust** when available [python/tvm/relax/backend/dispatch_sort_scan.py34-42](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/backend/dispatch_sort_scan.py#L34-L42) If Thrust is enabled in the `Target` (e.g., `+libs=thrust`), the dispatcher replaces generic ops with `topi.gpu.sort_thrust` [python/tvm/relax/backend/dispatch_sort_scan.py95-110](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/backend/dispatch_sort_scan.py#L95-L110)

## Example NPU Integration

 The "ExampleNPU" serves as a template for hardware vendors to integrate custom accelerators.

 
 - **Pattern Definitions**: Defined in `python/tvm/relax/backend/contrib/example_npu/patterns.py` using DPL to match `conv2d + relu` [docs/how_to/tutorials/bring_your_own_codegen.py146-148](https://github.com/apache/tvm/blob/b16cdecb/docs/how_to/tutorials/bring_your_own_codegen.py#L146-L148)
 - **Codegen**: The C++ codegen in `src/relax/backend/contrib/example_npu/codegen.cc` serializes the partitioned subgraph into a custom format.
 - **Runtime**: The `ExampleNPUJSONRuntime` in `src/runtime/extra/contrib/example_npu/example_npu_runtime.cc` implements the `Run` method to execute the serialized tasks [docs/how_to/tutorials/bring_your_own_codegen.py91-93](https://github.com/apache/tvm/blob/b16cdecb/docs/how_to/tutorials/bring_your_own_codegen.py#L91-L93)

## Internal vs. External Partitioning

 TVM distinguishes between partitioning for internal TIR generation and external BYOC backends.

 
 - **`FuseOps`**: An internal pass that groups Relax operations based on fusion rules (e.g., Injective, Reduction) to be lowered into a single `tirx::PrimFunc` [src/relax/transform/fuse_ops.cc21-28](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/fuse_ops.cc#L21-L28)
 - **`FuseOpsByPattern`**: An external-facing pass that uses specific structural patterns to identify subgraphs for BYOC backends [docs/how_to/tutorials/bring_your_own_codegen.py128-132](https://github.com/apache/tvm/blob/b16cdecb/docs/how_to/tutorials/bring_your_own_codegen.py#L128-L132)
 - **Workspace Allocation**: For backends requiring temporary memory (like Thrust or certain cuDNN kernels), the `AllocateWorkspace` pass inserts `relax.builtin.alloc_tensor` calls to manage GPU memory buffers [python/tvm/relax/backend/dispatch_sort_scan.py97-110](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/backend/dispatch_sort_scan.py#L97-L110)
