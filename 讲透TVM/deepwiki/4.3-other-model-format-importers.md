## Purpose and Scope

 This document covers TVM's model import frontends for deep learning frameworks beyond ONNX and PyTorch. These importers translate models from TensorFlow Lite, Keras, MXNet, PaddlePaddle, NNEF, StableHLO, and other formats into TVM's intermediate representations. Most of these frontends target the Relay IR, while newer formats like StableHLO target the Relax IR.

 For ONNX model import, see [ONNX Frontend](https://deepwiki.com/apache/tvm/4.1-onnx-frontend). For PyTorch model import, see [PyTorch Frontend](https://deepwiki.com/apache/tvm/4.2-pytorch-frontend). For information about the Relay and Relax IRs that these frontends target, see [Relax IR](https://deepwiki.com/apache/tvm/2.2-relax-ir).

 
## Frontend Architecture Overview

 TVM's other model format importers follow a common architectural pattern: they parse framework-specific model formats, convert operators to TVM's operator primitives, and construct computation graphs in either Relay or Relax IR. These frontends leverage the transform operations system for fundamental tensor manipulation primitives.

## TensorFlow Lite Frontend

 The TensorFlow Lite (TFLite) frontend imports `.tflite` model files, which use Google's FlatBuffers serialization format. It is one of the most widely used alternative importers due to TensorFlow Lite's popularity for mobile and embedded deployments.

 
### TFLite Model Structure and Parsing

 A TFLite model contains subgraphs composed of operators, tensors, and buffers storing weights or constants. The frontend uses FlatBuffers schema parsing and FlexBuffer decoding for custom options.

 
 - **`ExprTable`**: Manages Relax expressions identified by tensor names. It tracks parameters and constants generated during conversion [python/tvm/relax/frontend/tflite/tflite_frontend.py50-84](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/tflite/tflite_frontend.py#L50-L84)
 - **`TensorWrapper`**: Wraps TFLite tensor information including the tensor index, buffer data, and quantization parameters [python/tvm/relax/frontend/tflite/tflite_frontend.py86-93](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/tflite/tflite_frontend.py#L86-L93)
 - **`OperatorConverter`**: The core class mapping TFLite operators to Relax operators. It maintains a `convert_map` for dispatching TFLite opcodes to specific conversion logic [python/tvm/relax/frontend/tflite/tflite_frontend.py96-204](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/tflite/tflite_frontend.py#L96-L204)
 
 
### Conversion Process

 
 - **Model Entry**: The `from_tflite` function accepts a `tflite.Model.Model` object and initiates the conversion [python/tvm/relax/frontend/tflite/tflite_frontend.py36](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/tflite/tflite_frontend.py#L36-L36)
 - **Expression Tracking**: `ExprTable` stores `relax.const` values for weights and `relax.Var` for intermediate activations [python/tvm/relax/frontend/tflite/tflite_frontend.py59-66](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/tflite/tflite_frontend.py#L59-L66)
 - **Operator Dispatch**: `OperatorConverter` iterates through the TFLite subgraph, retrieving operators and mapping them via `convert_map`. Supported ops include standard math (ABS, ADD), neural network layers (CONV_2D, FULLY_CONNECTED), and quantized variants [python/tvm/relax/frontend/tflite/tflite_frontend.py99-155](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/tflite/tflite_frontend.py#L99-L155)
 - **Custom Options**: For operators with complex attributes, `FlexBufferDecoder` parses the `custom_options` field in the TFLite FlatBuffer [python/tvm/relax/frontend/tflite/tflite_flexbuffer.py68-161](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/tflite/tflite_flexbuffer.py#L68-L161)

## Keras Frontend

 The Keras frontend imports models saved in Keras's legacy HDF5 format or SavedModel format. It parses layer configurations and weights, converting the Keras layer graph to Relay backend-compatible programs.

 
### Supported Model Formats

 
 - Keras HDF5 (`.h5`) files embedding architecture and weights.
 - TensorFlow SavedModel directories.
 - Keras JSON architecture + weights split (legacy).
 
 
### Key Implementation Points

 
 - The frontend builds Relay expressions corresponding to Keras layers such as `Dense`, `Conv2D`, `LSTM`, `BatchNorm`, etc.
 - Attributes like kernel size, activation types, and units are mapped precisely into Relay operator attributes.
 - Supports `Sequential`, `Functional`, and subclassed Keras models.
 - Parameter extraction yields a parameters dictionary separate from the graph IR.

## MXNet Frontend

 The MXNet frontend imports models created with the MXNet Symbol API, processing symbol JSON graph definitions and matching parameter files.

 
### Model Components

 
 - **Symbol JSON**: Describes computation graph nodes and attributes.
 - **Params File**: Binary NDArray file with tensor weights.
 
 
### Key Features

 
 - Converts MXNet operators like `Convolution`, `FullyConnected`, `BatchNorm`, and `Activation` to corresponding Relay ops.
 - Handles reshape and flattening logic consistent with MXNet internals.
 - Maps auxiliary states as constants in Relay.
 - Recognizes output nodes for correct function building.
 
 Sources: Project structure and standard TVM frontend patterns.

## PaddlePaddle Frontend

 The PaddlePaddle frontend imports models encoded in protobuf format containing a program description and separate parameter files.

 
### Model Structure

 
 - `__model__`: Serialized protobuf graph containing blocks, variables, and operators.
 - Separate binary files for parameter tensors.
 - Metadata describing inputs and outputs.
 
 
### Key Details

 
 - Converts PaddlePaddle blocks with variables and operators into Relay function scopes and expressions.
 - Converts protobuf attributes to Relax-compatible attributes.
 - Supports tensor persistability indicating const parameters versus model inputs.
 
 Sources: Project structure and standard TVM frontend patterns.

## NNEF Frontend

 The Neural Network Exchange Format (NNEF) is an open standard used to express trained neural networks. TVM supports NNEF v1.0.8, facilitating import from various tools.

 
### NNEF Model Format

 
 - Packaged as a `.nnef` archive containing `graph.txt` (syntax) and `.dat` files (tensor data).
 - NNEF operators map to Relay operators such as convolution, pooling, relu, softmax, add, and multiply.

## StableHLO Frontend

 StableHLO is a stable intermediate representation designed for portability between compilers for machine learning models, such as JAX and TensorFlow XLA.

 
### Key Points

 
 - StableHLO operations lower directly to Relax IR, taking advantage of Relax's support for first-class functions and control flow.
 - Examples of lowered ops include `dot_general`, `convolution`, `reduce_window`, `broadcast_in_dim`, `reshape`, and `transpose`.
 - Designed to preserve functional program semantics and support dynamic shapes and control flow naturally.
 
 Sources: Based on Relax IR evolution and StableHLO integration design.

## Common Frontend Utilities

 
### IR Construction Utilities

 Frontends utilize the Relax IRBuilder and standard operator sets to construct the target IR.

 
 - **`tvm.relax.op`**: Provides a comprehensive set of operators (e.g., `add`, `reshape`, `nn.conv2d`) used by frontends to build the computation graph [python/tvm/relax/script/builder/ir.py43-197](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/script/builder/ir.py#L43-L197)
 - **`to_vdevice`**: Used to specify device placement for tensors within the IR [python/tvm/relax/script/builder/ir.py233-256](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/script/builder/ir.py#L233-L256)
 - **`function` and `arg`**: Primitives for defining the `main` entry point and its parameters [python/tvm/relax/script/builder/ir.py262-298](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/script/builder/ir.py#L262-L298)
 
 
### Parameter Management

 Frontends typically separate weights from the computation graph.

 
 - **`detach_params`**: A common utility (in Relay/Relax) that replaces constant parameters with function arguments, returning a tuple of the new module and a dictionary of parameters.
 - **`ExprTable.new_const`**: Specifically in the TFLite Relax frontend, this creates a `relax.const` and tracks it in a internal parameter map [python/tvm/relax/frontend/tflite/tflite_frontend.py59-66](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/tflite/tflite_frontend.py#L59-L66)
