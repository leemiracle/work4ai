  The LLVM Backend is TVM's primary code generation system that compiles TensorIR (TIR) functions into optimized machine code. It supports diverse hardware targets including CPU architectures (x86, ARM, RISC-V, Hexagon) and GPU platforms (NVIDIA NVPTX, AMD AMDGPU). The backend leverages LLVM's optimization infrastructure to generate high-performance native code.

 The LLVM backend is implemented primarily in `src/target/llvm/` with target-specific code generators inheriting from the base `CodeGenLLVM` class.

## Core Components

 
### CodeGenLLVM Base Class

 The `CodeGenLLVM` class serves as the foundation for all LLVM-based code generation in TVM. It provides common functionality for converting TIR expressions and statements into LLVM IR by inheriting from `ExprFunctor` and `StmtFunctor`.

 **Key Responsibilities:**

 
 - **IR Translation**: Converts TIR expressions (`PrimExpr`) to LLVM values via `VisitExpr_()` methods [src/target/llvm/codegen_llvm.h94-95](https://github.com/apache/tvm/blob/b16cdecb/src/target/llvm/codegen_llvm.h#L94-L95)
 - **Statement Compilation**: Processes TIR statements (`Stmt`) through `VisitStmt_()` methods [src/target/llvm/codegen_llvm.h95](https://github.com/apache/tvm/blob/b16cdecb/src/target/llvm/codegen_llvm.h#L95-L95)
 - **Type System**: Maps TVM data types to LLVM types via internal members like `t_int32_` and `t_void_p_` [src/target/llvm/codegen_llvm.cc161-172](https://github.com/apache/tvm/blob/b16cdecb/src/target/llvm/codegen_llvm.cc#L161-L172)
 - **Target Factory**: Creates target-specific generators via `CodeGenLLVM::Create` by looking up global factory functions [src/target/llvm/codegen_llvm.cc132-148](https://github.com/apache/tvm/blob/b16cdecb/src/target/llvm/codegen_llvm.cc#L132-L148)

## Target Support and Specialization

 
### CPU Runtime Integration

 `CodeGenCPU` implements the logic to interface with the TVM C backend API:

 
 - **Parallelism**: Generates calls to `TVMBackendParallelLaunch` for parallel loops [src/target/llvm/codegen_cpu.cc147-149](https://github.com/apache/tvm/blob/b16cdecb/src/target/llvm/codegen_cpu.cc#L147-L149)
 - **Packed Calls**: Handles calls to external PackedFuncs via `TVMFFIFunctionCall` [src/target/llvm/codegen_cpu.cc118-121](https://github.com/apache/tvm/blob/b16cdecb/src/target/llvm/codegen_cpu.cc#L118-L121)
 - **System Lib**: If `system_lib_prefix` is provided, it registers symbols via `TVMFFIEnvModRegisterSystemLibSymbol` [src/target/llvm/codegen_cpu.cc155-157](https://github.com/apache/tvm/blob/b16cdecb/src/target/llvm/codegen_cpu.cc#L155-L157)
 
 
### Scalable Vectors (SVE)

 The backend supports scalable vector types, used for AArch64 SVE. The logic in `BufferAccessType` ensures boolean vectors are backed by `int8` for proper load/store lowering [src/target/llvm/codegen_llvm.cc114-120](https://github.com/apache/tvm/blob/b16cdecb/src/target/llvm/codegen_llvm.cc#L114-L120) Assembly verification for SVE instructions like `ld1w` and `mul` is performed in AArch64 tests [tests/python/codegen/test_target_codegen_aarch64.py61-68](https://github.com/apache/tvm/blob/b16cdecb/tests/python/codegen/test_target_codegen_aarch64.py#L61-L68)

 
### Binary Blobs

 `CodeGenBlob` allows embedding opaque binary data (like compiled GPU kernels) as a global variable in the LLVM module. It handles platform-specific sections like `.lrodata` for large blobs on ELF systems [src/target/llvm/codegen_blob.cc88-94](https://github.com/apache/tvm/blob/b16cdecb/src/target/llvm/codegen_blob.cc#L88-L94)
