## Overview

 The ONNX to Relay import path is the traditional frontend for converting ONNX models into TVM's Relay intermediate representation. This system provides operator converters that translate ONNX operators into equivalent Relay expressions, enabling TVM to compile and optimize models exported from frameworks like PyTorch, TensorFlow, and others via the ONNX format.

 For the modern ONNX import path that targets Relax IR with versioning support, see [ONNX to Relax](https://deepwiki.com/apache/tvm/4.1.2-onnx-to-relax). For information about other model format importers, see [Other Model Format Importers](https://deepwiki.com/apache/tvm/4.3-other-model-format-importers).

 
## Import Architecture

 The ONNX to Relay frontend converts ONNX's protobuf-based graph representation into a Relay IRModule. While the legacy Relay importer is a distinct path, it shares conceptual similarities with the modern Relax importer in how it maps ONNX nodes to TVM IR operations. The importer uses an operator registry to map ONNX operator names to specific converter classes.

## Image Operator Support

 ONNX models frequently utilize image-related operators like `Resize`, `GridSample`, and `AffineGrid`. In TVM, these are handled by high-level Relax ops that are later legalized to TOPI implementations.

## Core Transform Operations Detail

 
### Dimension Manipulation

 **expand_dims**: Inserts new dimensions of length 1 at specified axis positions.

 Key implementation details:

 
 - Accepts negative axis indices (offsets from last dimension) [include/tvm/topi/transform.h160-165](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/transform.h#L160-L165)
 - Can insert multiple new axes with `num_newaxis` parameter [include/tvm/topi/transform.h156-158](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/transform.h#L156-L158)
 - Returns compute operation with injective tag.
 
 **squeeze**: Removes dimensions with constant size of 1.

 Key implementation details:

 
 - Can remove all size-1 dimensions or specific axes [include/tvm/topi/transform.h415-420](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/transform.h#L415-L420)
 - Silently skips non-1 dimensions in axes list.
 - Optional `atleast1d` parameter ensures output has at least one dimension [include/tvm/topi/transform.h419](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/transform.h#L419-L419)

### Shape Transformations

 **transpose**: Permutes array dimensions according to specified axes.

 Implementation characteristics:

 
 - Default behavior reverses all dimensions if no axes specified [include/tvm/topi/transform.h205-210](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/transform.h#L205-L210)
 - Validates that axes are unique and in valid range.
 - Computes new index mapping for dimension permutation [include/tvm/topi/transform.h225-240](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/transform.h#L225-L240)
 
 **reshape**: Transforms tensor to new shape while preserving element count.

 Implementation characteristics:

 
 - Handles empty shapes (returns tensor of zeros) [include/tvm/topi/transform.h330-335](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/transform.h#L330-L335)
 - Uses index transformation logic to map output indices back to input indices [include/tvm/topi/transform.h340-350](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/topi/transform.h#L340-L350)
 - Supports symbolic shapes through PrimExpr.

## Key Design Principles

 
### Dynamic Shape Support

 The ONNX importer retains dynamic shapes by default. It uses `UniqueNameSupply` for managing symbolic variables and attempts to resolve shapes at compile time when possible [python/tvm/relax/frontend/onnx/onnx_frontend.py31-37](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/onnx/onnx_frontend.py#L31-L37) [python/tvm/ir/supply.py63](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/ir/supply.py#L63-L63) The `parse_shape_name` function specifically handles converting ONNX dimension strings (including arithmetic expressions) into TVM `PrimExpr` or `tirx.Var` [python/tvm/relax/frontend/onnx/onnx_frontend.py162-209](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/onnx/onnx_frontend.py#L162-L209)
