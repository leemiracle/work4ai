  The CUDA Backend generates native CUDA C code from TVM's Tensor Intermediate Representation (TIR) and compiles it to executable kernels for NVIDIA GPUs. This backend is one of TVM's primary code generation targets for GPU acceleration, supporting a wide range of NVIDIA architectures from early SM versions to the latest Blackwell (SM 100) capabilities.

 For general code generation concepts, see [Code Generation](https://deepwiki.com/apache/tvm/6-code-generation). For target configuration, see [Target System](https://deepwiki.com/apache/tvm/6.1-target-system).

 
## Overview

 The CUDA Backend consists of three major components:

 
 - **Code Generator** (`CodeGenCUDA`): Translates TIR (PrimFunc) to CUDA C source code.
 - **Compiler Interface**: Invokes `nvcc` or `NVRTC` to compile CUDA C to PTX, CUBIN, or FATBIN.
 - **Runtime Module** (`CUDAModuleNode`): Loads and executes compiled kernels on the device.
 
 The backend supports advanced CUDA features including shared memory, warp-level operations, tensor cores (via wmma and mma), and modern data types such as `fp8`, `bf16`, and experimental `fp4/fp6`.

## Runtime Module

 The `CUDAModuleNode` manages the lifecycle of compiled CUDA code, including per-device lazy loading.

 
### Key Runtime Behaviors

 
 - **Lazy Loading**: The `CUmodule` is loaded via `cuModuleLoadData` only when a function is first requested on a specific device.
 - **Multi-GPU Safety**: It maintains a `module_` array of size `kMaxNumGPUs` (32) and uses a `std::mutex` to ensure thread-safe loading.
 - **Device Preservation**: The destructor ensures that the caller's current device is preserved after unloading per-device modules.

## TIR Transformations for CUDA

 Before code generation, several TIR passes prepare the IR for NVIDIA hardware:

 
 - **SplitHostDevice**: Separates the host-side launch code from the device-side kernel code. It also extracts launch bounds like `min_blocks_per_sm` and `max_registers`.
 - **LowerIntrin**: Lowers high-level intrinsics into target-specific calls (e.g., `T.cuda.ldg`).
 - **BindTarget**: Ensures every `PrimFunc` is annotated with the correct CUDA target.

## Synchronization and Memory Scopes

 The backend handles various CUDA memory scopes and synchronization primitives:

 
 - **Shared Memory**: Mapped to `__shared__` qualifiers.
 - **Local Memory**: Mapped to thread-local registers or stack.
 - **Global Barrier**: Implemented using atomic operations on a global state variable when `tirx.global_barrier` is present.
