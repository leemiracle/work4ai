  This system provides arithmetic analysis and symbolic simplification capabilities for TVM's intermediate representations. It analyzes integer expressions to determine value bounds, divisibility properties, and equivalences, then applies pattern-based rewriting and canonical simplification to reduce expression complexity while preserving semantic correctness.

 For information about TIR-level transformations that use these analyzers, see [TIR Transformations](https://deepwiki.com/apache/tvm/5.2-tir-transformations). For operator-level optimizations, see [Relax Transformations](https://deepwiki.com/apache/tvm/5.1-relax-transformations).

 
## Purpose and Scope

 The arithmetic analysis system serves three primary functions:

 
 - **Expression Simplification**: Transform complex expressions into simpler equivalent forms using pattern matching and canonical form conversion.
 - **Value Range Analysis**: Determine constant integer bounds and modular properties of expressions to enable optimizations and prove conditions.
 - **Iterator Pattern Detection**: Identify affine and quasi-affine iterator patterns in loop indices to enable loop transformations and memory layout optimizations.
 
 These capabilities are fundamental to nearly all compiler optimizations in TVM, from loop scheduling to memory planning to code generation.

## RewriteSimplifier

 The `RewriteSimplifier` [src/arith/rewrite_simplify.cc1-165](https://github.com/apache/tvm/blob/b16cdecb/src/arith/rewrite_simplify.cc#L1-L165) performs pattern-based expression rewriting using a large collection of algebraic identities. Most rewrite rules are adapted from the Halide compiler [src/arith/rewrite_simplify.cc24](https://github.com/apache/tvm/blob/b16cdecb/src/arith/rewrite_simplify.cc#L24-L24)

 
### Pattern Matching Infrastructure

 The simplifier uses a domain-specific pattern matching system. It defines macros to simplify the application of rules:

 
 - `TVM_TRY_REWRITE(SrcExpr, ResExpr)`: Matches a pattern and returns the evaluated result [src/arith/rewrite_simplify.cc95-100](https://github.com/apache/tvm/blob/b16cdecb/src/arith/rewrite_simplify.cc#L95-L100)
 - `TVM_TRY_RECURSIVE_REWRITE(SrcExpr, ResExpr)`: Matches and then recursively simplifies the result [src/arith/rewrite_simplify.cc103-108](https://github.com/apache/tvm/blob/b16cdecb/src/arith/rewrite_simplify.cc#L103-L108)
 
 
### Major Rewrite Categories

 The simplifier implements rewrites organized by operation type:

 
 - **Boolean Normalization**: `NormalizeBooleanOperators` simplifies logical expressions (e.g., `!(x < y)` to `y <= x`) [src/arith/rewrite_simplify.cc143-165](https://github.com/apache/tvm/blob/b16cdecb/src/arith/rewrite_simplify.cc#L143-L165)
 - **Constant Offset Extraction**: `ExtractConstantOffset` separates constant terms from expressions (e.g., `x + 5` returns `{x, 5}`) [src/arith/rewrite_simplify.cc167-182](https://github.com/apache/tvm/blob/b16cdecb/src/arith/rewrite_simplify.cc#L167-L182)
 - **Vector/Scalable Vector Rules**: Special handling for `tirx::builtin::vscale()` and vector expressions to ensure SIMD-friendly simplification. It uses `ExtractVscaleFactor` to identify multipliers of the scalable vector unit [src/arith/rewrite_simplify.cc47-74](https://github.com/apache/tvm/blob/b16cdecb/src/arith/rewrite_simplify.cc#L47-L74)
 
 
### Comparison Analysis

 The `TryCompare` function [src/arith/rewrite_simplify.cc184-197](https://github.com/apache/tvm/blob/b16cdecb/src/arith/rewrite_simplify.cc#L184-L197) leverages other analyzers to prove inequalities:

 
 - `TryCompareUsingConstIntBounds`: Uses range analysis.
 - `TryCompareUsingKnownInequalities`: Uses the transitive comparison analyzer.

## ConstIntBoundAnalyzer

### Bound Representation

 The `ConstIntBound` object [include/tvm/arith/analyzer.h90-112](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/arith/analyzer.h#L90-L112) stores:

## CanonicalSimplifier

 The `CanonicalSimplifier` [src/arith/canonical_simplify.cc1-210](https://github.com/apache/tvm/blob/b16cdecb/src/arith/canonical_simplify.cc#L1-L210) transforms expressions into a "Split Normal Form" to handle complex indexing patterns.

 
### Split Normal Form

 The internal representation uses `SplitExprNode` [src/arith/canonical_simplify.cc108-211](https://github.com/apache/tvm/blob/b16cdecb/src/arith/canonical_simplify.cc#L108-L211) which represents an expression as: `((index % upper_factor) / lower_factor) * scale`

 This form is particularly effective for simplifying flattened indices in nested loops [src/arith/canonical_simplify.cc101-107](https://github.com/apache/tvm/blob/b16cdecb/src/arith/canonical_simplify.cc#L101-L107)

 
### Cast Safety

 The simplifier includes logic to determine if a `Cast` operation can be safely pushed into sub-expressions without overflow or loss of precision [src/arith/canonical_simplify.cc86-98](https://github.com/apache/tvm/blob/b16cdecb/src/arith/canonical_simplify.cc#L86-L98)

## Z3 Prover Backend

### Integration and Lifecycle

 The `Z3Prover::Impl` [src/arith/z3_prover.cc110-180](https://github.com/apache/tvm/blob/b16cdecb/src/arith/z3_prover.cc#L110-L180) lazily materializes a `z3::context` and `z3::solver` only when a complex proof is required, avoiding initialization overhead for simple analyses [src/arith/z3_prover.cc182-193](https://github.com/apache/tvm/blob/b16cdecb/src/arith/z3_prover.cc#L182-L193)

 
 - **Memoization**: TVM expressions are mapped to Z3 handles via `memo_` and `z3_pool_` to ensure deterministic AST-ID recycling [src/arith/z3_prover.cc131-160](https://github.com/apache/tvm/blob/b16cdecb/src/arith/z3_prover.cc#L131-L160)
 - **Variable Naming**: A `Namespace` helper generates unique Z3 variable names by appending suffixes (e.g., `x$1`, `x$2`) to prevent name collisions in the solver [src/arith/z3_prover.cc66-96](https://github.com/apache/tvm/blob/b16cdecb/src/arith/z3_prover.cc#L66-L96)
 - **Resource Limits**: The solver uses `rlimit` instead of wall-clock timeouts to ensure deterministic behavior across different hardware [src/arith/z3_prover.cc191-192](https://github.com/apache/tvm/blob/b16cdecb/src/arith/z3_prover.cc#L191-L192)
