  The Relax Dataflow Pattern Language (DPL) is a declarative toolset used for structural pattern matching and graph rewriting within Relax IR. It provides a mechanism to identify specific subgraphs of operations—such as fused kernels or hardware-specific patterns—and replace them with optimized equivalents or external function calls. DPL is a core component for passes like `FuseOpsByPattern` and Bring Your Own Codegen (BYOC) backends.

 
## Overview and Purpose

 DPL allows developers to express complex IR structures using a set of pattern primitives. These patterns are matched against Relax expressions or entire `DataflowBlock` structures.

 Key use cases include:

 
 - **Fusion**: Identifying patterns like `conv2d -> add -> relu` to create composite functions [tests/python/relax/test_fuse_pytorch_conv2d_bias_pattern.py46-53](https://github.com/apache/tvm/blob/b16cdecb/tests/python/relax/test_fuse_pytorch_conv2d_bias_pattern.py#L46-L53)
 - **BYOC**: Offloading matched subgraphs to external engines (e.g., TensorRT, CUTLASS).
 - **Graph Rewriting**: Performing algebraic simplifications or structural transformations like combining parallel matmuls [src/relax/transform/combine_parallel_matmul.cc64-74](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/combine_parallel_matmul.cc#L64-L74)
 
 
## Core Pattern Types

 The language consists of several `DFPattern` subclasses, each targeting a specific Relax IR construct.

 
### Node-wise Patterns

 These patterns match individual Relax expressions based on their type or attributes.

 
| Pattern Class | Purpose | Python Constructor |
|---|---|---|
| VarPattern | Matches a Relax Var by name hint src/relax/ir/dataflow_pattern.cc101-105 | is_var(name) |
| DataflowVarPattern | Matches a DataflowVar src/relax/ir/dataflow_pattern.cc120-124 | is_dfv(name) |
| ConstantPattern | Matches any relax.Constant src/relax/ir/dataflow_pattern.cc154-160 | is_const() |
| WildcardPattern | Matches any expression python/tvm/relax/dpl/pattern.py456-463 | wildcard() |
| CallPattern | Matches a function call (Op or GlobalVar) src/relax/ir/dataflow_pattern.cc164-168 | is_op("name")(*args) |
| FunctionPattern | Matches a Relax Function src/relax/ir/dataflow_pattern.cc184-188 | FunctionPattern(params, body) |
| UnorderedTuplePattern | Matches a relax.Tuple regardless of element order src/relax/ir/dataflow_pattern.cc209-214 | is_tuple(fields, unordered=True) |

 
### Logic and Constraint Patterns

 Patterns can be composed using logical operators:

 
 - **OrPattern (`|`)**: Matches if either the left or right pattern matches [python/tvm/relax/dpl/pattern.py67-81](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/dpl/pattern.py#L67-L81)
 - **AndPattern (`&`)**: Matches if both patterns match the same expression [python/tvm/relax/dpl/pattern.py83-97](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/dpl/pattern.py#L83-L97)
 - **NotPattern (`~`)**: Rejects the match if the underlying pattern succeeds [python/tvm/relax/dpl/pattern.py99-108](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/dpl/pattern.py#L99-L108)
 - **AttrPattern**: Matches based on operation or call attributes [python/tvm/relax/dpl/pattern.py110-124](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/dpl/pattern.py#L110-L124)
 - **ShapePattern**: Matches based on the tensor shape [python/tvm/relax/dpl/pattern.py144-165](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/dpl/pattern.py#L144-L165)

## Pattern-Based Rewriting

 DPL provides high-level APIs for transforming Relax IR using matched patterns.

 
### Rewrite Mechanisms

 
 - **`rewrite_call`**: Performs expression-level replacement. It takes a pattern and a rewriter function that returns a new expression [python/tvm/relax/dpl/rewrite.py205-234](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/dpl/rewrite.py#L205-L234)
 - **`RewriteBindings`**: Performs block-level replacement within a function, allowing simultaneous replacement and more complex graph modifications [include/tvm/relax/dataflow_matcher.h72-75](https://github.com/apache/tvm/blob/b16cdecb/include/tvm/relax/dataflow_matcher.h#L72-L75)
 - **`PatternMatchingRewriter`**: A class-based rewriter that can be constructed from an `IRModule` containing `pattern` and `replacement` functions [python/tvm/relax/dpl/rewrite.py72-132](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/dpl/rewrite.py#L72-L132)
 
 
### Composition of Rewriters

 Rewriters can be composed using the OR operator (`|`), allowing multiple rewrite rules to be applied in a single transformation pass [python/tvm/relax/dpl/rewrite.py153-172](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/dpl/rewrite.py#L153-L172)

### Attribute Matching

 The matcher can inspect `DictAttrs` or reflected fields of an operation. It uses `ffi::StructuralEqual` to compare the expected attribute value in the pattern with the actual value in the IR [src/relax/ir/dataflow_matcher.cc66-81](https://github.com/apache/tvm/blob/b16cdecb/src/relax/ir/dataflow_matcher.cc#L66-L81)

 
### Variable Unwrapping

 A critical feature of the Relax DPL is `UnwrapBindings`. Because Relax functions often consist of fragmented bindings (e.g., `lv0 = add(x, y); lv1 = relu(lv0)`), the matcher automatically follows variable assignments to find the underlying expression when a `var2val` map is provided [src/relax/ir/dataflow_matcher.cc114-141](https://github.com/apache/tvm/blob/b16cdecb/src/relax/ir/dataflow_matcher.cc#L114-L141)
