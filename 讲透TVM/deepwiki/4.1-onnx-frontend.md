## Purpose and Scope

 The ONNX Frontend provides functionality to import models defined in the ONNX (Open Neural Network Exchange) format into TVM's intermediate representations. This enables TVM to compile and optimize models from various deep learning frameworks that export to ONNX, including PyTorch, TensorFlow, and others.

 This page covers the overall architecture and common components of ONNX model import. For specific implementation details:

 
 - For the traditional ONNX to Relay IR path, see [ONNX to Relay](https://deepwiki.com/apache/tvm/4.1.1-onnx-to-relay)
 - For the modern ONNX to Relax IR path, see [ONNX to Relax](https://deepwiki.com/apache/tvm/4.1.2-onnx-to-relax)
 
 The ONNX frontend is part of TVM's broader frontend ecosystem, which includes other model format importers documented in [Frontend Systems](https://deepwiki.com/apache/tvm/4-frontend-systems) and [Other Model Format Importers](https://deepwiki.com/apache/tvm/4.3-other-model-format-importers).

## Architecture Overview

 The ONNX frontend supports two main compilation paths: the traditional path targeting the Relay IR and the modern path targeting the Relax IR. Both share similar high-level design patterns but differ in their operator converter frameworks and IR targets.

 The core components of the ONNX frontend include:

 
 - Model parsers that consume ONNX protobuf `ModelProto` objects.
 - Operator converter registries that map ONNX operator names to TVM IR semantics.
 - Shared utility functions for type conversion, shape inference, and parameter loading.
 - Integration with TVM's tensor transform APIs used during conversion.

## ONNX to Relax Path (Modern)

 The ONNX to Relax import path represents the modern approach for importing ONNX models in TVM. It emphasizes first-class support for Relax's functional and dynamic IR features, enabling more expressive model representation and optimizations.

 
### Entry Point and Core Components

 The main entry is the `from_onnx()` function residing in `python/tvm/relax/frontend/onnx/onnx_frontend.py` [python/tvm/relax/frontend/onnx/onnx_frontend.py22](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/onnx/onnx_frontend.py#L22-L22) It orchestrates model parsing, operator conversion, and IR generation.

 Key components include:

 
 - `OnnxOpConverter` base class with virtual `_impl` methods supporting opset versioning [python/tvm/relax/frontend/onnx/onnx_frontend.py28-29](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/onnx/onnx_frontend.py#L28-L29)
 - Specialized converter classes for different operator categories (binary, unary, tensor ops).
 - Helper functions for type conversion (`get_type`), constant extraction (`get_constant`), and shape handling (`get_info`, `parse_shape_name`).
 - An operator registry mapping ONNX op names to converter classes via `_get_converter_map`.

### Dynamic Shape Handling

 The frontend supports dynamic shapes by parsing shape dimension annotations that can be integers, symbolic variables, or arithmetic expressions. This is done via the `parse_shape_name()` function which tokenizes the dimension strings and builds corresponding expressions using `tvm.tirx.Var` as symbolic variables [python/tvm/relax/frontend/onnx/onnx_frontend.py162-209](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/onnx/onnx_frontend.py#L162-L209)

## Common Utilities

 The ONNX frontend provides utility functions key to the import process, shared across various operator converters.

 
### Type and Parameter Handling

 
 - `get_type(elem_type)`: Converts ONNX integer datatypes to NumPy datatype strings [python/tvm/relax/frontend/onnx/onnx_frontend.py83-97](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/onnx/onnx_frontend.py#L83-L97)
 - `get_constant(var, params)`: Attempt to convert a variable to a constant if found in the parameter dictionary [python/tvm/relax/frontend/onnx/onnx_frontend.py100-134](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/onnx/onnx_frontend.py#L100-L134)
 - `get_value(token, value_dict)`: Decodes a token into an integer constant or a `tvm.tirx.Var` symbolic variable [python/tvm/relax/frontend/onnx/onnx_frontend.py136-160](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/frontend/onnx/onnx_frontend.py#L136-L160)
 
 
### Image Operator Integration

 TVM provides specialized Relax operators for image processing that align with ONNX requirements:

 
 - `resize2d` and `resize3d`: Support various interpolation methods (`linear`, `nearest_neighbor`, `cubic`) and coordinate transformation modes (`half_pixel`, `align_corners`, `asymmetric`) [python/tvm/relax/op/image/image.py31-133](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/op/image/image.py#L31-L133) [python/tvm/relax/op/image/image.py136-185](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/op/image/image.py#L136-L185)
 - `grid_sample`: Applies sampling to input feature maps using grid coordinates [python/tvm/relax/op/image/image.py188-217](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/relax/op/image/image.py#L188-L217)
 - `affine_grid`: Generates sampling grids for use with `grid_sample` [python/tvm/topi/image/grid_sample.py23-74](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/topi/image/grid_sample.py#L23-L74)

### Test Framework Components

 - Generating random inputs matching model input shapes using `generate_random_inputs()` [tests/python/relax/test_frontend_onnx.py64-79](https://github.com/apache/tvm/blob/b16cdecb/tests/python/relax/test_frontend_onnx.py#L64-L79)
