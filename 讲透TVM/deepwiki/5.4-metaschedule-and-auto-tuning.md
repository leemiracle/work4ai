  MetaSchedule is TVM's automated search framework for optimizing TensorIR (TIR) kernels. It provides a high-level API to explore the implementation space of a `PrimFunc` by applying a series of schedule primitives (e.g., tiling, vectorization, parallelization) and measuring their performance on physical hardware or using a cost model.

 
## Overview of the Tuning Pipeline

 The tuning pipeline bridges the gap between high-level Relax functions and optimized low-level TIR. When a Relax module is compiled, MetaSchedule can be invoked to transform unoptimized TIR functions into high-performance versions tailored for a specific `Target`.

## Key Classes and Interfaces

 MetaSchedule is implemented as a set of Relax transformation passes that wrap the underlying tuning infrastructure.

## DLight: Default Lightweight Schedules

 DLight serves as a faster alternative to full MetaSchedule tuning. Instead of an exhaustive search, DLight applies predefined, high-quality schedule templates based on the hardware target and the operator pattern (e.g., GEMV, Matmul).

 
### Key Components:

 
 - **GPUScheduleRule:** The base class for GPU-specific scheduling logic [python/tvm/s_tir/dlight/gpu/base.py](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/s_tir/dlight/gpu/base.py)
 - **GEMV Rule:** Specifically handles Matrix-Vector multiplication patterns, including `sch_inner_reduction` and `sch_outer_reduction` [python/tvm/s_tir/dlight/gpu/gemv.py78-87](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/s_tir/dlight/gpu/gemv.py#L78-L87)
 - **LowBatchGEMV:** A specialized rule for low-batch GEMM or decode-GEMM operations [python/tvm/s_tir/dlight/gpu/low_batch_gemv.py206-210](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/s_tir/dlight/gpu/low_batch_gemv.py#L206-L210)
 
 
### DLight Scheduling Process:

 
 - **Normalization:** The `normalize_prim_func` and `normalize` functions analyze the TIR `Block` structure to identify spatial and reduction loops [python/tvm/s_tir/dlight/gpu/gemv.py49-73](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/s_tir/dlight/gpu/gemv.py#L49-L73)
 - **Pattern Detection:** Functions like `is_gemv` check if a block meets the criteria for specific optimizations (e.g., reduction expressions, access patterns) [python/tvm/s_tir/dlight/gpu/low_batch_gemv.py67-126](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/s_tir/dlight/gpu/low_batch_gemv.py#L67-L126)
 - **Application:** The rule applies schedule primitives such as `rfactor`, `bind`, `vectorize`, and `cache_read` to optimize memory access and compute [python/tvm/s_tir/dlight/gpu/gemv.py105-180](https://github.com/apache/tvm/blob/b16cdecb/python/tvm/s_tir/dlight/gpu/gemv.py#L105-L180)

## Tuning Infrastructure Components

 The core of MetaSchedule consists of:

 
 - **Normalization:** Before tuning, TIR functions are normalized to a standard form using `normalize_mod` to ensure consistency in the database [src/relax/transform/meta_schedule.cc50-52](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/meta_schedule.cc#L50-L52)
 - **Database Lookup:** `MetaScheduleApplyDatabase` queries a `Database` (e.g., `JSONDatabase`) using the normalized `IRModule` and `Target` [src/relax/transform/meta_schedule.cc110-112](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/meta_schedule.cc#L110-L112)
 - **Trace Application:** If a record is found, the stored `Trace` is applied to a fresh `Schedule` to reproduce the optimized TIR [src/relax/transform/meta_schedule.cc123-126](https://github.com/apache/tvm/blob/b16cdecb/src/relax/transform/meta_schedule.cc#L123-L126)
