# 05 并行通信：all-reduce / all-gather / all-to-all

> 分布式训练/推理的通信基础 (14 篇的深化)。瓶颈常常是**通信**, 不是计算。
> 配套实验: `experiments/05_collective_communication.py` (CPU 模拟)
> 核心洞察: **DP/TP/PP/EP 各用不同的通信原语, 现代训练是多维并行的通信调度艺术**。

---

## 一、三大集体通信 (collective communication)

| 原语 | 语义 | 用于 |
|------|------|------|
| **all-reduce** | 所有卡拿到**元素级求和** | **DP** (梯度同步) |
| **all-gather** | 所有卡拿到**数据拼接** | **TP** (收集分片结果) |
| **all-to-all** | 每卡把数据**分发**给所有卡 (转置式) | **EP** (MoE 路由) |

**实验2 实测** (4 卡):
```
all-reduce: [1,2,3,4]+[2,4,6,8]+... → [10,20,30,40]  (求和)
all-gather: [0,1]+[10,11]+...       → [0,1,10,11,...] (拼接)
all-to-all: 转置式分发, 卡i的第j块→卡j的第i块
```

---

## 二、ring all-reduce: DP 的核心 (通信量 O(N²) → O(N))

### 问题
朴素 all-reduce: 每卡发给所有其他卡 → $O(N^2)$ 通信, 卡多了爆炸。

### ring 算法
把卡排成环, 两阶段:
1. **reduce-scatter** (N-1 步): 每步每卡传 1/N 数据给下一卡, 累加
2. **all-gather** (N-1 步): 传播累加结果, 让所有卡拿到完整和

**通信量**: 每卡总发送 $= \frac{2(N-1)}{N} \times \text{size} \approx 2 \times \text{size}$ (**与 N 无关!**)

**实验1 通信量分析**:
```
N=256 卡时, ring 比朴素省 128× 通信量
```
> 这是数据并行能 scale 到上千卡的基础——通信量不随卡数爆炸。

> 📌 实验脚本里的精确 ring 模拟有 chunk 索引实现细节, 本文展示的是**语义 + 通信量公式** (核心结论)。真正的 ring 实现在 NCCL 库 (C++/CUDA)。

## 三、DP / TP / PP / EP 的通信模式 (实验3)

以 70B 模型、80 层、batch=8、seq=2048 为例:

| 并行 | 通信原语 | 通信量 | 频率 | 瓶颈 |
|------|---------|--------|------|------|
| **DP** | all-reduce (梯度) | ~280 GB/步 | 每训练步 | 大模型梯度很重 |
| **TP** | all-reduce (激活) | ~537 MB/层 ×2 | 每层每前向 | 频繁, **必须 NVLink** (节点内) |
| **PP** | 点对点 (激活) | ~268 MB/stage | 每 stage | **气泡**闲置 |
| **EP** | all-to-all (路由) | ~268 MB/MoE层 | 每个 MoE 层 | MoE 主要开销 |

**关键洞察**:
- **TP 通信最频繁** (每层 2 次 all-reduce), 所以只在**节点内** (NVLink 高带宽) 用, 通常 TP=8
- **DP 通信量最大** (整个梯度), 但频率低 (每步一次)
- **PP 通信小但有气泡**, 适合跨节点
- **EP 的 all-to-all** 是 MoE 训练的主要开销

## 四、现代多维并行 = 通信调度艺术

实际训练 DeepSeek-V3 (2048 张 H800):
```
节点内:  TP=8      (NVLink, 切权重矩阵)
节点间:  PP=多     (切层, 通信小)
全局:    DP=多     (不同 batch, all-reduce 梯度)
MoE:     EP=多     (切专家, all-to-all)
```

**难点**: 不同并行的通信模式不同 (all-reduce/all-gather/all-to-all), 要**重叠计算和通信** (computation-communication overlap) 才不浪费 GPU。这是大模型训练"系统工程"的核心 (14 篇)。

---

## 五、连接: 为什么 GPU 比 CPU 擅长这个

- GPU 有 **NVLink/NVSwitch** (节点内 900GB/s) 和 **InfiniBand** (节点间 400GB/s) 的高速互联
- NCCL (NVIDIA Collective Communications Library) 把 all-reduce/all-gather/all-to-all 做成高度优化的 GPU kernel
- CPU 没有这种互联, 所以分布式训练离不开 GPU 集群
