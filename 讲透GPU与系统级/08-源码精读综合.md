## 一、统一视角: 三种抽象写同一个 attention

| 实现 | 语言 | 抽象层 | 你管什么 | 来源 |
|------|------|--------|---------|------|
| **CUDA hopper** | C++/CUDA | thread | 寄存器/共享内存/warp/sync/TMA | flash-attention `hopper/` |
| **Triton** | Python@jit | block | block 大小/循环/load-store | flash-attention `flash_attn/flash_attn_triton.py` (07篇) |

**共同内核** (01 篇): tiling (分块) + online softmax (流式) + 中间矩阵不物化到 HBM。

## 二、CUDA FlashAttention (hopper, SM90)

来源: `Dao-AILab/flash-attention/hopper/` (FlashAttention-3)。比 06 篇教学版复杂得多:

### Hopper (H100) 的硬件特性利用
- **TMA (Tensor Memory Accelerator)**: 硬件异步搬运数据 (CPU/GPU 不用管 DMA), 隐藏 HBM 延迟
- **GMMA (Grouped Matrix Multiply Accumulate)**: warp group 级 tensor core 矩阵乘 (比 mma 快)
- **异步流水线**: `mainloop_fwd_sm90_tma_gmma_ws.hpp` 用多级流水线重叠 TMA 搬运和 GMMA 计算
- **FP8**: SM90 原生支持 FP8 (E4M3) 矩阵乘

### 文件结构 (hopper/)
```
flash_fwd_kernel_sm90.h        # SM90 前向 kernel
mainloop_fwd_sm90_tma_gmma_ws.hpp  # 主循环 (TMA + GMMA + warp specialization)
tile_scheduler.hpp             # block 调度 (处理序列长度不齐)
softmax.h                      # online softmax 辅助
epilogue_fwd.hpp               # 输出处理
```

> **读 hopper 的感受**: 这不是"一个 kernel", 是一整套硬件协同的工程——TMA 搬数据、GMMA 算、warp specialization (生产者 warp 喂数据, 消费者 warp 算)。**这是 CUDA 的极限**: 精确利用每一代 GPU 的硬件特性。06 篇的教学版只是冰山一角。

## 三、Triton FlashAttention (07 篇精读回顾)

`_fwd_kernel` (07 篇逐段精读过):
```python
@triton.jit
def _fwd_kernel(..., BLOCK_M: tl.constexpr, BLOCK_N: tl.constexpr):
    start_m = tl.program_id(0)              # block 索引 (= blockIdx)
    q = tl.load(q_ptrs)                     # HBM → SRAM (显式)
    for start_n in range(0, end_n, BLOCK_N):
        k = tl.load(k_ptrs + start_n*...)
        qk = tl.dot(q, k, trans_b=True)     # 自动用 tensor core
        # online softmax (在 block 级变量里)
        ...
    tl.store(out_ptrs, acc_o)               # 写回 HBM
```

**Triton 的省力**: 你不写 thread/warp/shared memory/`__syncthreads()`——编译器自动生成。代价是极限性能略低于手写 CUDA hopper。

## 四、vLLM PagedAttention: 分页 + thread group

来源: `vllm/csrc/libtorch_stable/attention/attention_utils.cuh` + attention kernel。

### 核心差异: KV Cache 是【分页】的
普通 attention kernel: K/V 是连续张量, 直接索引。
PagedAttention: K/V 通过 **block table** 间接寻址——逻辑 token i 的 KV 在 `block_table[i//BLOCK_SIZE]` 的第 `i%BLOCK_SIZE` 个槽。

```
逻辑序列: [t0 t1 t2 ... t127]
           ↓ block_table 映射
物理 page: page5[t0..15] page12[t16..31] page3[t32..47] ...  (不连续!)
```

### 精读: QK^T 用 thread group 并行
`attention_utils.cuh` 的 `qk_dot_`:
```cpp
template <int THREAD_GROUP_SIZE, typename Vec, int N>
inline __device__ float qk_dot_(const Vec (&q)[N], const Vec (&k)[N]) {
  A_vec qk_vec = mul<A_vec, Vec, Vec>(q[0], k[0]);      // 每个 thread 算部分积
  for (int ii = 1; ii < N; ++ii)
    qk_vec = fma(q[ii], k[ii], qk_vec);                  // fused multiply-add
  float qk = sum(qk_vec);                                // 跨 lane 归约
  for (int mask = THREAD_GROUP_SIZE/2; mask >= 1; mask /= 2)
    qk += VLLM_SHFL_XOR_SYNC(qk, mask);                  // ★ warp shuffle 归约
  return qk;
}
```
**精读要点**:
- `THREAD_GROUP_SIZE` 个 thread 协作算一个 Q·K (head_dim 拆给多个 thread)
- `VLLM_SHFL_XOR_SYNC`: **warp shuffle**——thread 间直接交换寄存器值, 不经共享内存 (最快)
- `fma` (fused multiply-add): 一条指令算 a*b+c, 比 separate 快 + 精度高

### 分页寻址 + PagedAttention 的整体
```
对每个 query token:
  1. 通过 block_table 找到它的 K/V 在哪些物理 page    ← 分页核心
  2. 用 qk_dot_ 算 Q·K (thread group + warp shuffle)
  3. online softmax
  4. 累积输出
```

> **PagedAttention 的天才**: 把 OS 虚拟内存 (分页/页表) 和 GPU kernel (thread group/warp shuffle) 结合。每个 query 算 attention 时, K/V 通过 page table 间接寻址——不连续也行。这是 03 篇分页模拟的**真实 CUDA 实现**。

## 五、三个实现的工程现实对比

读真实源码看到的 (课本不教):

| 维度 | CUDA hopper | Triton | vLLM PagedAttention |
|------|-------------|--------|---------------------|
| 边界处理 | template + static_switch | 大量 EVEN_M/EVEN_N 分支 | block_table 越界 mask |
| 编译器 bug | 少 (C++ 成熟) | 多 (debug_barrier/scratchpad 绕路) | 少 |
| 硬件特性 | TMA/GMMA/FP8 (H100 专属) | 依赖编译器 | warp shuffle |
| 调优 | 手动 CUTLASS | `@triton.autotune` 自动 | 固定配置 |
| 可读性 | 极低 (C++ template 地狱) | 中 (Python, 但有边界噪声) | 低 (CUDA) |

> **ezyang 式洞察**: 真实生产 kernel 60% 是工程细节 (边界/race/编译器 bug/调优), 40% 是核心算法。读源码的价值在于看到这 60%——课本只教你 40%。
