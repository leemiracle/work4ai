# 03 推理引擎：vLLM PagedAttention + continuous batching

> 推理 (inference) 是训练之后——前向无反向, 服务给用户。推理引擎的核心创新, 几乎全是**操作系统思想**套到 Transformer 上。
> 配套实验: `experiments/03_inference_engine.py` (CPU 模拟)
> 核心洞察: **推理引擎 = OS 虚拟内存 + OS 进程调度 + 两阶段生成**。

---

## 一、PagedAttention: 分页 KV Cache (OS 虚拟内存)

### 问题: 碎片
多个请求序列长度不同, 朴素**连续分配** KV Cache 会碎片化:
- 请求 A 申请 200 token 空间, 只生成 50 → 150 浪费
- 释放后小块散落, 新请求即使总空闲够, 也因找不到连续大块而失败

### vLLM 的解法: 像虚拟内存分页
- KV Cache 分成固定大小 **page** (如 16 token/page)
- 每个请求的逻辑序列 → 通过 **page table** 映射到物理 page
- 物理 page **不必连续** → 零碎片

**实验1 实测** (模拟): 分页分配让"释放小块后分配大块"不再因碎片失败 (连续分配会)。

> **这是 OS 虚拟内存的直接套用**: 逻辑地址连续 / 物理地址离散 / page table 映射。vLLM 把这套搬进 LLM 推理, 是系统工程思维的典范。

---

## 二、continuous batching: 动态批处理 (OS 进程调度)

### 问题: static batching 的拖累
传统批处理: 一个 batch 里所有请求**必须同时结束**。长请求拖累短请求——短请求生成完了还得占着位置等 → GPU 算力空转。

### continuous batching
每步**动态调整 batch**: 完成的请求随时退出, 新请求随时插队。

**实验2 实测** (请求长度 [5,20,3,12]):
```
static batching:    所有请求等到 step 20, 有效利用率 50% (大量空转)
continuous:         活跃数 [4,4,4,3,3,2,2,1,1...] 逐步退出 → 利用率 ~100%
吞吐提升 ~2.0×
```
> 这是 OS 的**进程调度**思想——别让短任务等长任务, 能者多劳, 随到随走。

## 三、prefill vs decode 两阶段

LLM 生成分两阶段, 计算特性截然不同:

| 阶段 | 做什么 | 特性 | 瓶颈 |
|------|--------|------|------|
| **prefill** | 一次性处理整个 prompt, 算 KV Cache | 并行, compute-bound | 算力 |
| **decode** | 每步生成 1 token, 复用 KV Cache | 串行, memory-bound | HBM 带宽 |

**实验3 实测** (prompt=1000, 生成=200):
```
prefill FLOPs ≈ 259M  (compute-bound, GPU 打满)
decode FLOPs ≈ 39M    (但慢得多!)
FLOPs 比 prefill:decode = 6.7:1
```

> **关键反直觉**: decode 的 FLOPs 少 6.7×, 却更慢。因为 decode 是 **memory-bound**——每步只算 1 个 query, 却要**读整个 KV Cache**, 计算单元闲置在等数据。这正是 01 篇讲的"memory-bound"。

> **这就是投机解码 (09 篇) 的动机**: decode 时算力闲置, 用小模型猜多个 token, 大模型并行验证, 把闲置算力用起来。

## 四、推理引擎全景 = OS 思想 + Transformer

| OS 概念 | 推理引擎对应 | 解决 |
|---------|------------|------|
| 虚拟内存 / 分页 | PagedAttention | KV Cache 碎片 |
| 进程调度 | continuous batching | 长短请求混合 |
| 上下文切换 | prefill/decode 切换 | 两阶段计算特性不同 |
| 缓存 (cache) | KV Cache | 避免重算 |
| 抢占 (preemption) | 优先级调度 | 紧急请求插队 |

> **洞察**: 做好 LLM 推理, 不只要懂 Transformer, 还要懂操作系统。vLLM/SGLang 的核心贡献者很多是系统背景 (Charles Frye, Modal 团队, CS25 V6 讲过)。
