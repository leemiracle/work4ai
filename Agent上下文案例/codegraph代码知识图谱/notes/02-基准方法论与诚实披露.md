# 02 · 基准方法论与诚实披露：一套"评测不自欺"的工业范本

> 出处：上游 README "Benchmark Results / A note on cost / A note on context" + `docs/benchmarks/residual-context-occupancy.md`。
> 本篇同时是 [`欺骗动力学-AI纪实验包.md`](../../../欺骗动力学-AI纪实验包.md) 的跨层注脚：**评测方法本身就是反欺骗工程**。

## 1. 基准设置（2026-08-05 重测版）

- 7 个真实开源仓库 × 7 语言：VS Code（TS, ~11k 文件）、Excalidraw（TS）、Django（Python, ~3k）、Tokio（Rust, ~790）、OkHttp（Java, ~645）、Gin（Go, ~110）、Alamofire（Swift, ~110）。
- 每仓库一个**架构级问题**（如 "How does the extension host communicate with the main process?"）。
- Claude Code headless（Claude Opus 4.8），`--strict-mcp-config`：WITH = CodeGraph MCP 开，WITHOUT = 空 MCP 配置；两臂都保留内置 Read/Grep/Bash。**每臂 4 次，报告中位数**。
- 指标口径：Cost = run 的 `total_cost_usd`；Tokens = 逐 assistant turn 求和（input 含 cache reads + cache creation + output）；Tool calls 含 subagent 内部调用；File reads = 中位数文件打开数。

## 2. 关键防线：双臂封锁 CLI（反污染）

**问题**：不封锁时，WITHOUT 臂的 agent 会在 PATH 上发现 `codegraph` CLI 并从 Bash 偷用——实测 **28 次里 26 次**偷用。这使对照组根本不是对照组（CLI 调用不计为 tool call，但输出照样进窗口），污染是双向的。

**对策**：sanitized PATH + `PreToolUse` hook 拒绝任何对 CLI 的 Bash 调用，**两臂都封**。结果：WITHOUT 臂 28 次全部尝试、全部被拦，**污染 0/28**。README 明说"没有这个封锁，对照臂就不是对照臂"，且坦承**早期公布的数字没有这个封锁**（即撤回过旧基准）。

## 3. 结果（中位数）

| 仓库 | Tool calls (±) | 耗时 | 文件读取 | Tokens | Cost |
|---|---|---|---|---|---|
| VS Code | 2 vs 28 | 2.2× faster | 0 vs 12 | -77% | -71%（$0.53 vs $1.80） |
| Excalidraw | 2 vs 43 | 3.6× faster | 0 vs 18 | -84% | -78% |
| Django | 3 vs 14 | +35% faster | 0 vs 8.5 | -41% | -13%¹ |
| Tokio | 3 vs 29 | 2.6× faster | 0 vs 19 | -65% | -64% |
| OkHttp | 1 vs 6 | +43% faster | 0 vs 2 | -54% | -21%¹ |
| Gin | 1 vs 7 | +39% faster | 0 vs 4 | -52% | ~even¹ |
| Alamofire | 4 vs 33 | 2.6× faster | 0 vs 16.5 | -59% | -57% |

**总体：tool calls -88% · 时间 -53% · tokens -62% · cost -44% · 全部 7 仓库 file reads = 0。**
¹ 成本随"该问题的 discovery 需求"浮动：对照组要跑 28–43 次调用的仓库省 57–78%，对照组 7–14 次就答出来的只省 13% 甚至打平——**但 WITH 臂照样 1–3 次调用、零文件读取**。诚实解释了为什么成本列方差远大于其他列。

## 4. 最重要的诚实披露：residual context **+80%**

上面测的是**吞吐**（处理了多少 token、花了多少钱）。README 单独加了一节 "A note on context"：**多轮会话结束时，CodeGraph 的响应留在上下文窗口里的检索内容比文件阅读 agent 多约 80%**（VS Code 上 67k vs 18k tokens）。

机制恰是它快的原因：图返回一个**致密、verbatim、一次到位**的 payload，答完就驻留窗口；而 grep-and-read 的许多小结果会被逐轮驱逐。"**处理的 token 更少**"与"**驻留的 footprint 更大**"同时为真。README 直接建议：长会话 + 小窗口要为此做预算，并给出逐仓库测量文档链接。

> 这是教科书级的**反选择性披露**：营销上完全可以只讲 -62% tokens；他们主动讲了 +80% 驻留，并解释了机制。与欺骗动力学的 **D4（透明）** 对照——不透明是"用户看到的对话"与"真实账本"分离；这里是"宣传的数字"与"测得的数字"强制同源。

## 5. 信任工程全清单（供应链与遥测）

| 面 | 机制 | 验证命令（README 提供） |
|---|---|---|
| 发布 | 只从公开 Release workflow 发布，"从不从个人笔记本" | — |
| npm | trusted publishing（OIDC，无长期 token）+ provenance attestation（版本↔commit↔workflow run） | `npm audit signatures` |
| GitHub bundles | 签名 build attestations，**SLSA v1.0 Build L2** | `gh attestation verify codegraph-darwin-arm64.tar.gz -R colbymchenry/codegraph` |
| 遥测 | 匿名使用统计（哪些工具/语言被用）；**绝不**收集代码/路径/文件名/查询/IP；先本地聚合成日总量再发送；ingest 端点开源（`telemetry-worker/`）强制字段清单；装时先问、可关 | `codegraph telemetry off` / `DO_NOT_TRACK=1` |
| 历史诚实 | 明说 2026-07 之前的发布不带 attestation | — |

与 dsh 案例（vendored SHA 锁定 + `allowBuilds` 默认拒装）对照：**同一时代的开源基础设施已把"供应链反投毒"当成默认义务**——这是 [`欺骗动力学-AI纪实验包.md`](../../../欺骗动力学-AI纪实验包.md) 实验 4（Data Poisoning）反制沉淀在 2026 年的基线化。

## 6. 提炼：基准的反欺骗清单（可复用）

1. **封锁交叉感染**：对照组必须拿不到实验组的能力（PATH 封锁 + hook 拒绝），并**报告污染次数**（0/28）。
2. **中位数 + 多次重复**：4 runs/arm，抗单次运气。
3. **指标口径全公开**：token 怎么加总、cost 从哪读、subagent 怎么计——可复算。
4. **主动披露不利数字**：residual context +80% 与 -62% tokens 同页出现，并解释因果机制。
5. **承认历史版本错误**：旧基准无封锁 → 撤回重测。
6. **按条件解释方差**：成本列的 13%~78% 浮动不是噪音，是 discovery 需求的函数。
7. **商业信号与基准分离**：平台 beta（getcodegraph.com）不混入开源基准的叙事。

> 一句话：这份基准本身就是"识诈基础设施"——它防的第一种欺骗，是**自己骗自己**。
