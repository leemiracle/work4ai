# 12 · 不足与批判收尾：图税、本体腐化与"Is GraphRAG Needed?"

> 讲透Graph 第 12 章（五幕第四幕：不足）| 汇总 E1-E6 的全部负面结果

## 1. 图税：三笔账（E4 + E5 + E2）

- **构建税**：图索引 ≈ 向量索引的 **6×**（输出 token 单价 5× + 社区摘要层）；微软 GraphRAG 官方：小语料库索引 = 数百次 LLM 调用（E4）；
- **增量税**：更新一篇 = 抽取 + 消歧 + 作废扫描 ≈ **7×**（bi-temporal 的维护费，E4）；
- **可靠性税**：图要赢扁平检索，每跳精度必须 $\ge q^{1/k}$（q=0.90, k=5 时 = 0.979）——实体链接/消歧做不好，图遍历就是负资产（E5）；fan-out 并行的验证门把 B 拓扑成本抬回 1.4×（E2）。

**交税判据**：问题带隐藏动词（替代/依赖/因果/阻塞）吗？需要多跳吗？需要"当时什么为真"吗？需要证据链吗？——四个都"否"就别交图税。

## 2. "Is GraphRAG Needed?"——GEM 2026 的诚实答案

9 场景实测（aclanthology 2026.gem-main.40，半结构化医学知识库）：

- **简单/主题类问题：plain RAG 够用**，还更便宜；
- **复杂关系查询：GraphRAG 占优**；
- **整体最佳：Agentic RAG**（把检索组件当工具的极简 agent）——不堆图的复杂度，靠 agent 自主编排拿到最好结果；
- **retrieval-generation gap**：扩大检索不按比例提升生成质量（位置衰减/显著性偏好/基数效应）——**检索侧指标会撒谎，评测必须端到端**；
- 上下文优化（三元组 O(1) 表示 + 去重 + batch 检索）省 19-53% token 不掉点。

## 3. 本体腐化与 undead knowledge

- 类型系统没人维护就烂：新事实塞不进旧类型 → 乱标 → 类型分布熵漂移（Ch09 的监测信号）；
- **agent 写边必须可区分于人确认的边**，否则幻觉入库、不可溯源清除；
- 没有治理的活图 = undead knowledge：活的、持久的、不再连着真相的（Ch09 三铁律是解药）。

## 4. 什么时候别用图（四条反例）

1. **探索性任务**：LangChain 自曝 deep research 从 LangGraph 工作流迁回 agentic loop——硬塞确定性路径 = 把 agent 降级成工作流引擎（Ch02）；
2. **简单检索**：GEM：plain RAG 够用的场景占多数（Ch12 §2）；
3. **相似度就是答案**：主题聚类、模糊探索、"找像这个的"——向量是正解（Ch07 三路由）；
4. **精度上不去的长链**：每跳 0.9 的 10 跳 = 0.35——先救单跳或砍链，别急着上图（E5）。

## 5. 术语战争的诚实定价

34 天从推文到综述（07-18 → 08-21）。LangChain 自己说："这些术语半营销，但每个都对应真实的设计难题。"**判别独立收敛**：Neo4j（图库）、Zep（记忆创业）、LangChain（编排框架）利益完全不同，却在"结构化关系优于扁平相似"上独立收敛——迁移为真的最强信号。同时 Foundation Capital 的"trillion dollar opportunity"叙事当动量信号看，不当论据。

**本单元最终立场**：五环谱系是**分工**不是世系。Graph 不取代 Prompt/Context/Harness/Loop——它是让前四环的产出可组织、可审计、可演化的**骨架层**。*Representation, not prompting, is the leverage*——但 representation 也要交税，交不交换成问题。
