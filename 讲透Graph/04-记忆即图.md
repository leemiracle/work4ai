# 04 · 记忆即图：episodic+semantic 双子图与 SARO 四元组

> 讲透Graph 第 04 章 | 实验 E4（`experiments/E4_graph_tax.py`）

## 1. 直觉层：文件柜 → 日记 → 心智模型

Neo4j（Niels de Jong, 2026-04）给 agent 记忆的三级模型，一层比一层像"人"：

1. **文件柜**（向量库）：相关记忆按相似度取回——但每条记忆互相孤立，只有"像不像"，没有"然后呢"；
2. **日记**（时序日志）：按时间串起来——有了顺序，但没有结构；
3. **心智模型**（context graph）：决策、观察、结果连成网，挂在世界模型上——**从 recall（回忆）到 reasoning（推理）的桥**。

Zep 论文（arXiv 2501.13956）的实现是心理学双系统落地：

- **episodic 子图**：原始经历（对话、事件）——对应人的情节记忆；
- **semantic 子图**：从中抽取的实体、事实、关系——对应语义记忆；
- **community 节点**：实体聚类成社区（继承 GraphRAG 思路），撑全局理解。
- 层级：**episodes → facts → entities → communities**，一层层蒸馏。

## 2. SARO 四元组：把"经历"存成可推理的结构

Neo4j 的经验结构（也是 neo4j-labs/agent-memory 的设计）：每条经历登记四件事——

| 字段 | 问的是 | 例 |
|------|--------|-----|
| **S**ituation | 当时环境什么样（实体/地形） | 大促前夜，Redis 内存 90% |
| **A**ction | 我做了什么 | 把缓存策略从 LRU 换成 LFU |
| **R**ationale | 为什么这么做（假设） | 怀疑热 key 集中导致 LRU 污染 |
| **O**utcome | 结果如何（奖励/惩罚） | 命中率 +7%，假设成立 |

注意 **R（Rationale）是灵魂**——它是 Eifrem 说的"decision traces"、组织里最难传承的程序性知识（Jessica Talisman：知识管理界早就叫它 procedural knowledge）。四元组互相连边、再挂到实体上，agent 下次遇到相似 Situation 就能**沿着图**找到"上次为什么这么干、结果如何"——这是向量检索"找到相似段落"给不了的行动依据。

## 3. 数学层：图税测算（E4）

记忆选图不是免费的。成本模型（假设全列 `E4_result.json` PARAMS，结论对参数不敏感）：

- **向量索引**：每文档 1 次 embedding，只进不出；
- **图索引（GraphRAG 式）**：每文档 1 次三元组抽取（schema prompt + 文档进、三元组出）+ 消歧 + 每 50 实体 1 次社区摘要。

实测数字（mini 档价格）：

| 规模 | 向量 | 图 | 图税 |
|------|------|-----|------|
| 100 docs | $0.15 | $0.95 | 6× |
| 10K docs | $15 | $95 | 6× |
| 增量 1 篇 | $0.0015 | ~$0.011 | **7.2×** |

两个结构性原因：①图索引要**输出** token（三元组），输出单价是输入的 5 倍；②增量更新图还要消歧+作废扫描（bi-temporal 的维护费）。现实锚点：微软 GraphRAG 官方文档明示索引一个小语料库 = 数百次 LLM 调用。

**结论不是"图贵所以不用"，而是"先问问题类型"**：主题相似类问题，向量值回票价；多跳关系/时序/溯源类问题，图值回票价（GEM 2026 的 9 场景实测同判，见 Ch12）。

## 4. 代码层：三个存储的取舍

E3 已经跑了 bi-temporal 的正确性；E4 补经济账。工程上真正的分界线是**更新频率**：

- 语料基本静态（文档库）→ GraphRAG 批处理可接受，偶尔重建；
- 语料持续流动（对话记忆、业务数据）→ 必须增量式（Graphiti 路线），批处理等于每次全量重付图税。

## 5. 不足与坑

- **undead knowledge**：活图没有治理 = 活的、持久的、且不再连着真相的记忆（vanja.io）。agent 写的边和人确认的边必须可区分（source/timestamp/confidence/review state 全一等公民）——Ch09 展开；
- **记忆基准贫瘠**：Zep 论文自己吐槽：现有基准多是 needle-in-haystack 级别的简单事实检索，缺"跨会话综合 + 业务数据混合"的硬基准；
- **社区摘要的漂移**：增量更新下社区摘要怎么跟着改，仍是开放问题。
