# 10 · 活案例：work4ai 自己就是 proto-graph

> 讲透Graph 第 10 章 ★用户重点 | 实验 E6 + E6b（`experiments/E6_work4ai_graph_health.py`、`E6b_orphan_taxonomy.json`）

## 1. 直觉层：你的 wikilinks 就是边

vanja.io 对个人知识库的判断是本章的门票：

> 互链的 markdown 知识库 = **proto-graph-engineering**。你的 wikilinks 就是边。给它们类型（这条链接是 supersedes 还是 see_also）+ 一个检查目标存在/类型合法的 linter + 笔记正文上叠一层语义检索 = 一个真的混合系统，markdown 就是可检查的 source of truth。**人工维护的链接通常比机器抽取的更准**——这是平台不会替你广告的部分。

本仓完全符合：新卡必须挂网 = 加边操作；孤儿率 <10% 健康线 = 死节点监控；MATH_LOOP_ENGINE 知识森林（多父 DAG + Wave BFS）= 显式学习进度图；记忆块的 updated 时间戳 ≈ 朴素 bi-temporal。本章拿图论工具照镜子。

## 3. 关键修正：逻辑边 vs 物理边（E6b 分类）

初版 E6 报 31.5% 孤儿率后追问一层：**孤儿分三种**（`E6b_orphan_taxonomy.json`）：

| 类 | 数量 | 性质 |
|----|------|------|
| A 章节型（同目录有 README，篇目表"逻辑挂网"） | 136 | **测量伪影**——README 篇目表是逻辑边不是 markdown 物理链接 |
| B 工作流文件（RESUME/papers 未被链） | 9 | 半伪影（papers.md 常被引用，孤儿的是少数） |
| **C 真孤儿（无 README 的目录或散件）** | **831** | **真治理债** |

这个分类本身就是 graph engineering 的一课：**逻辑图（declared）≠ 物理图（materialized）**。篇目表声明了"这个单元有哪些章"，但机器（和未来的 agent 检索器）只能看见物理链接。逻辑边不落成物理边，对图工具就是不存在——**这正是本单元 README 篇目表带头把章节名改成真实链接的原因（自我治理示范）**。

## 4. 治理债排行（C 类按目录）

| 目录 | 真孤儿/总数 | 孤儿率 |
|------|------------|--------|
| 讲透Agent | 240/647 | 37% |
| 实例 | 217/330 | **66%** |
| top-math-courses | 146/495 | 29% |
| top-physics-courses | 64/158 | 41% |
| 前沿与媒体 | 34/108 | 31% |
| ad-mastery | 14/16 | 88% |

（另：notes 90%、deepseek-*-harness 90% 系小目录散件。）

**诊断**：
- **实例/（66%）**：330 个文件里 217 个无入度——大量一次性笔记从未被任何索引收编，是最典型的"死亡内容"；
- **讲透Agent（37% 绝对值最大）**：增长最快的单元，挂网速度跟不上生产速度——知识库的"城市化病"；
- **top-math-courses（29%）**：讽刺的是枢纽自己也有 146 个孤儿（大量资源文档深埋未被互链）——**枢纽的引力不等于全覆盖**。

## 5. 方法论沉淀：E6 作为挂网审计工具

E6 脚本即插即用（纯 stdlib），三步审计法：

1. **量**：节点/边/孤儿率/断链/枢纽（E6 主表）；
2. **分**：逻辑挂网（A 类伪影）与真孤儿（C 类）分开——否则指标失真且冤枉人；
3. **排**：真孤儿按目录排行 → 治理债从最大簇开始还（每还一簇 = 给那个目录的 README 补索引行）。

配套健康线（建议写进 AGENTS.md 的量化版）：
- 孤儿率（C 类）< 10%；断链 = 0 容忍（改名必须跟修，2,155 条是历史欠账，可以分批清）；
- 每个自产目录必须有 README（没有 README 的目录 = 无根子图，里面的文件全算孤儿）。

## 6. 对用户三线工作的映射

- **AI 工程师线**：proto-graph 经验直接迁移——做 RAG/agent 项目时，"先建逻辑索引再落物理链接"的教训 = "先设计本体再落数据库"（Ch09）；
- **数学家线**：MATH_LOOP_ENGINE 的知识森林（多父 DAG + Wave BFS + 22/30 卡 verified）已经是显式学习图——它的"五生成规则 R1-R5"就是 prescribed ontology 的生成式版本；
- **interp 线**：孤儿率作为知识库 rot 的度量，与 context rot（讲透Context）同构——**rot 是所有增量系统的宿命，差别只在于有没有仪表盘**。

## 7. 不足与诚实声明

- E6 只认 markdown 链接边：不认 mermaid 图里的引用、不认 frontmatter 的 refs 字段、不认"同目录=隐式归属"——测量口径偏保守（真实连通性好于数字）；
- 入度≠重要性：枢纽榜可能反映"被管理得多"而非"被用得多"（没有点击日志）；
- 本单元自己也是被审对象：讲透Graph 的章节在本轮已物理挂网，但 papers/RESUME 仍是工作流文件（B 类）——如实计入，不做例外。
