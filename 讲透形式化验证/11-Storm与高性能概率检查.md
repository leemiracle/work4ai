# 11 · Storm：高性能概率检查

> 卷三第二章：[10 章](./10-PRISM概率模型检测.md)把概率模型检查归约成"解方程/迭代"——P 格的算法在手，工程问题才刚开始：**状态数上量**（真实协议 10⁷–10⁹）、**数值要可信**（概率 0.6 与 3/5 在阈值边界是生死之差）、**引擎要选对**（同一个模型，稀疏与符号引擎可差几个数量级）。本章用 [`experiments/lab11_storm_sparse.py`](./experiments/lab11_storm_sparse.py) 把三件事钉在可复现的数字上：**稀疏直接解**十万态秒级（实测 0.02–0.05 秒；赌徒破产闭式解 i/N 当测试用例——数学是免费的测试集）；**价值迭代的两个陷阱**（Θ(N²) 扫描数 + "停机 ≠ 收敛"：停机阈值 1e−6 时真误差 1.6×10⁻²，相差 1.6 万倍——这正是 Storm 默认**区间迭代**的动机）；以及 PRISM 入门 / Storm 上量的分工。【P（大输入的工程战）】

## 一、上量的两个引擎

概率模型检查的线性系统 (I−Q)p = r 稀疏得漂亮（每行 ≤ 出度个非零），两条路线：

| | **稀疏引擎**（Storm 默认） | **符号引擎**（PRISM/Storm 的 MTBDD） |
|---|---|---|
| 表示 | 每状态一行，只存非零 | 决策图共享同构子结构（[12 章](./12-BDD与CUDD.md) 的 MTBDD） |
| 优势 | 稠密区域、随机结构 | 规整/对称结构（n 位计数器、网格） |
| 代价 | 状态数线性内存 | 变量序敏感——选错序图爆炸 |
| 战场 | 10⁷–10⁹ 随机协议 | 正则结构的 10²⁰⁺ |

何时谁赢没有定理，只有经验法则：**结构越"规整"符号越赚、越"随机"稀疏越稳**——同一模型两种引擎差 3 个数量级是常态，这也是 50 章选型决策树的分叉之一。Storm 的立场：稀疏为默认，符号（`--engine hybrid/symbolic`）为选项，且底层同用 CUDD（[12 章](./12-BDD与CUDD.md) 生态闭环的入口）。

## 二、精确 vs 浮点：0.6 与 3/5 的差别

[10 章](./10-PRISM概率模型检测.md)的 0.6 看似小数，本质是 **3/5**。当性质是 `P≥0.6` 而浮点解出 0.5999999999——**假阴性**；反之为 **假阳性**。在临界阈值（概率恰在边界）上，双精度就是不够用。Storm 的答案分三层：默认浮点（快）＋ `--exact` 有理数算术（把转移率写成整数的分数，全程精确——lab11 的 spsolve 误差 1.2×10⁻¹⁰ 是"浮点但很准"，有理模式则给出分毫不差的 37000/100000）＋ 区间算术（给上下界）。工程铁律：**阈值比较的最后一跳，用有理数或区间做**。

## 三、JANI/PRISM 双前端与 stormpy

Storm 的定位是"引擎专家"而非"建模入口"：**前端**吃 PRISM 语言与 JANI（JSON 格式的模型交换标准——工具间互通的通用语），**后端**才是它的主场。Python 绑定 **stormpy** 把稀疏模型构建、求解器选择、性质检查都暴露成 API——嵌入自己工具链（CI 里跑概率回归）比命令行顺手。与 PRISM 的分工一张表：

| | PRISM | Storm |
|---|---|---|
| 强项 | 入门/GUI/参数扫描实验 | 上量/精确算术/引擎选项/嵌入（stormpy） |
| 前端 | 自家语言 | PRISM 语言 + JANI 双前端 |
| 典型用法 | 建模探索、画参数曲线 | 定型模型的大规模验证、CI 集成 |

## 四、十万态现场：两台引擎的诚实对比（手推）

赌徒破产随机游走是免费的测试集——**闭式解 P(F 赢|i) = i/N** 摆在那里（公平游走的鞅性，一步可推），任何引擎跑出来的每个状态都能逐点对拍。lab11：

```
E1 · 稀疏直接解：十万态·秒级（闭式解 i/N 当测试用例，实测耗时见下一行）
模型：赌徒破产随机游走，N=100,000 态（三对角稀疏，nnz≈299,994）
  spsolve：0.05 秒；全状态最大误差 = 1.24e-10（vs 闭式解，容差 1e-09）
→ E1 自检通过：稀疏直接解十万态秒级、误差压进 1e-9——'上量'由直接引擎兑现

E2 · 价值迭代：Θ(N²) 扫描数 + 停机判据陷阱
模型同上，N=400，停机条件'相邻两轮差 < 1e-06'：
  扫描数 = 119,005（sweeps/N² = 0.74——Θ(N²)：信息每轮只推一步）
  耗时 1.49 秒；停机时【真】误差（vs 闭式解）= 1.62e-02
  陷阱：停机阈值 1e-06，真误差 1.6e-02——相差 16212 倍
  原因：吸收链的价值迭代收缩率 →1（谱半径随 N 增大），'两轮差小'≠'离真解近'
```

三个读数。**其一，同是"P 格"，常数天差地别**：直接解 0.05 秒 vs 迭代法在 N=400 就要 1.5 秒、在 N=10⁵ 需要 Θ(N²)=10¹⁰ 轮——多项式复杂度不保证工程可用，引擎选择是第一生产力。**其二，停机陷阱是正确性问题而非性能问题**：朴素的"相邻两轮差 < ε 就停"在收缩率趋 1 的链上会**提前宣告胜利**（本例真误差 1.6×10⁻²，比阈值大四个数量级）——这不是假设的场景，是 VI 文献反复记录的真实事故，也是 Storm 把**区间迭代**（从上下两面夹逼，停机时给出真解区间）设为默认的原因之一（Baier-Lamp/Klein 等 2017 一系）。**其三，闭式解当测试用例**是概率验证工程的独门习惯——每类随机结构几乎都有一维解析解（破产/生灭/排队），先跑玩具拿解析对拍、再跑真实模型，是从 PRISM 到 Storm 的通用工作流。（诚实注记：本 lab 用 `scipy.sparse` 复现 Storm 的稀疏路线；计划原稿想在十万态上跑价值迭代——实测 Θ(N²) 扫描数后改道直接解，教训照抄进 E2。）

## 五、状态空间压缩一句

上量除了换引擎还有第三招：**先变小**——对称性归并（旋转对称的环网只需商空间）、拟对称（对目标等价的状态合并）、占比极小的截断。Storm 的 `--symmetry` 与模型级 bisimulation minimization（对 PCTL 等价的概率双模拟）可把某些协议状态数砍掉数量级——思想与 [13 章](./13-进程代数与mCRL2.md)互模拟同源。

## 六、仪器

- **Python 保底**（本 lab）：`python experiments/lab11_storm_sparse.py`——三对角稀疏直接解十万态（0.05s / 1.2e−10）+ 价值迭代陷阱现场（Θ(N²) 与 1.6 万倍停机差）。
- **原生可选**：stormpy 走 WSL（`pip3 install stormpy` 若源内可用，或按 storm-checker.org 编译安装）；把 [10 章](./10-PRISM概率模型检测.md)的 `.pm` 交给 `storm --prism model.pm --prop 'P>=0.6 [F "target"]'`，与本 lab 的 0.6 对拍；`--exact` 看有理数输出。装不通不阻塞。
- 对照实验：同一模型在 PRISM `--symbolic` 与 Storm 稀疏模式下比内存/耗时——引擎分化的一手体验。

## 七、不足与边界

1. **精确算术的代价**：有理数运算不是免费的（分数膨胀），大模型 `--exact` 可能慢一个数量级——"何时值得精确"是工程判断。
2. **符号引擎的宿命**：变量序 NP-难（[12 章](./12-BDD与CUDD.md) 的主题），动态重排只能救一部分——正则结构之外的模型别指望符号奇迹。
3. **闭式解不是总有**：本章的"数学当测试"依赖一维结构；高维真实模型的正确性只能靠引擎间对拍（PRISM vs Storm vs 手推玩具）三角互证。
4. **模型本身仍是假设**：状态数再大，转移率是拍的，答案就继承误差——[10 章](./10-PRISM概率模型检测.md)边界第一条在此放大。
5. **P 格的"舒适"有边界**：PCTL 多项式是对**单个性质**；扫一万个参数点/一万个性质的原型系统分析，复杂度乘回去还是要工程化。
