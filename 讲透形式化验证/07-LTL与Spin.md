# 07 · LTL 与 Spin：显式状态的工艺

> 卷二开卷：卷一把断言喂给求解器（[03](./03-SMT求解与Z3cvc5.md)/[04](./04-有界模型检查CBMC.md) 章），本章换一个世界——**让所有路径说话**：不再找一条反例路径，而是断言"**每一条**无穷路径都……"。三件套：**LTL**（线性时间时序逻辑：U/F/G 三个算子沿**单条路径**读时间——与走分支树的 CTL 分家）；**检查 = 乘积 Büchi + nested-DFS**（反例的形状是 **lasso：茎 + 环**——lab07 双 DFS 栈演化手推，TS1 的反例 s0·(s1 s2)^ω 当场抓出）；**Spin 的工艺**（on-the-fly、偏序归约、Never claim——显式状态学派的全部手艺）。复杂度注记：**LTL 模型检查对公式长度 PSPACE-完全**、对系统尺寸线性——"性质难、系统便宜"是本格的形状。【PSPACE-complete（公式长度）】

## 一、线性时间 vs 分支时间：两条时间观

同一个"终将送达"，两种读法：

- **LTL（线性时间）**：沿**每一条**完整执行路径读——`G(req → F ack)`："任何时刻发了请求，则**这条路径往后**必有应答"。时间是一条线，量化词在路径外（ ∀ 全部路径）。
- **CTL（分支时间）**：站在每个状态看**树**——`AG(req → AF ack)`：所有状态的所有**分支未来**里都逃不出应答。时间是一棵树，量化词（A/E）钻进每一层。

两者不可互相定义（经典不可表达性结果），后来的统一者是 [13 章](./13-进程代数与mCRL2.md) 的 μ-演算。工程分野同样清楚：** Spin/LTL 派**（协议、通信、公平性——关心"执行流"）vs **SMV/CTL 派**（电路、状态机——关心"格局"）。本章走 LTL 线，CTL 的检查（标号算法，线性时间）在 [10 章](./10-PRISM概率模型检测.md) 的 PCTL 里以概率化身重逢。

## 二、LTL 语法：U/F/G 与五条换算

语法一页纸：`φ ::= p | ¬φ | φ∧ψ | X φ | φ U ψ`（原子/否定/合取/下一刻/直到）。F 与 G 是缩写：

| 换算 | 读法 |
|---|---|
| **F φ ≡ ⊤ U φ** | 终将（Future）——某时刻起 φ 成立 |
| **G φ ≡ ¬F¬φ** | 总是（Globally）——无一刻 ¬φ |
| **G F φ** | 无穷多次（每个后缀里都有 F）——活性语言 |
| **F G φ** | 终于永远（某后缀全 φ）——稳定性语言 |
| **φ U ψ → F ψ** | 直到蕴含终将（U 的"见证"必来） |

两个动词背下来受用：**安全性**（something bad never happens ≈ G¬bad）与**活性**（something good eventually happens ≈ F good）——互斥RESPONSE对 `G(req→F ack)` 是活性，而死锁自由是安全性。这对手套贯穿全部验证工具的属性分类。

## 三、检查 = 找 lasso：乘积 Büchi 与 nested-DFS（手推）

LTL 模型检查的标准三步（自动机理论的一次工程化）：

1. **¬φ 转 Büchi 自动机**（tableau 构造，§四一瞥）：接受"违反 φ"的无穷路径；
2. **乘积**：TS × ¬φ-自动机——反例存在于乘积里 ⟺ 原系统违反 φ；
3. **找 accepting lasso**：无穷路径被有限图折成"茎 + 环"——**Büchi 接受条件要求环上有接受态**，nested-DFS 找它。

对最简性质 **F p**，¬F p = G¬p，反例 = "全程 ¬p 的无穷路径" = **从初态可达的、全由 ¬p 组成的环**——不需要显式构造自动机，两遍 DFS 直接抓。lab07 的手推现场（TS：s0→s1→s2→s1）：

```
E1 · TS1（p 处处不成立）：F p 被违反，nested-DFS 抓环
  ('外层发现序', ['s0', 's1', 's2'])
  ('内层无环', 's0', ['s0', 's1', 's2'])        ← 从 s0 出发找回到 s0 的路：s2→s1 不回 s0，无环
  ('内层命中', 's1', ['s1', 's2', 's1'])         ← 换 s1 出发：s1→s2→s1 回边成环！
  反例 lasso：s0 → s1 · ( s1 → s2 → s1 )^ω
E2 · TS2（s2 ⊨ p）：外层发现序只剩 ['s0','s1']——s2 被 p 拦在门外；
  内层从 s0/s1 都无环 → F p 成立（环被 p 态拦腰截断）
```

读法两行：**外层 DFS 画可达域、内层 DFS 找回边**——两层栈各司其职，时空都是 O(|TS|+|¬φ|)；**反例永远长成 lasso**（茎进环、环无穷转）——模型检查器报的反例路径为什么总是"跑到某处开始原地转圈"，这就是原因。对照实验（lab07 E3）：把性质换成 **G p**，反例条件从"环"退化为"点"（任一可达 ¬p 态即可）——**G 查点、F 查环**，安全性检查天然比活性便宜一档。

## 四、LTL→Büchi tableau 一瞥

一般 φ 的 ¬φ-自动机构造（tableau/GPVW 算法）：状态 = φ 的子公式集（满足哪些"义务"），转移 = X 算子的逐轮兑现，接受条件 = "GF 义务"（活性子公式无穷多次被处理）。状态数最坏 **2^{O(|φ|)}**——这就是 **PSPACE-完全性**的来源（公式指数、系统线性，总账由公式主导）。实践安慰：手写性质的 tableau 通常几态到几十态（¬F p 的自动机**单态无接受条件**——它接受一切全 ¬p 路径）；Spin 内置的 LTL 编译器把这条流水线全自动。

## 五、Spin 的工艺：显式状态学派的手艺

**Spin**（Holzmann，Bell Labs，1980s–；软件工程最高荣誉之一）是 LTL 模型检查的工业旗舰，手艺全在"状态怎么省"：

- **Promela**：进程/信道/语句级非确定选择的建模语言（C 的表亲）；
- **Never claim**：LTL 编译出的监视自动机作为"幽灵进程"并排跑（§三乘积的 Promela 写照））；
- **on-the-fly**：状态边生成边查——反例在到达前就被截住，从不显式存整张乘积；
- **偏序归约**：独立动作的交错序只探一条（并发跑法的等价类压缩）；
- **位状态哈希**（bitstate）：不存状态存指纹——用可控假阴性换千亿状态可达（统计保证的近似，[11 章](./11-Storm与高性能概率检查.md)"近似引擎"的显式版亲戚）。

一句话定位：Spin 把"显式枚举"磨了三十年，磨出了这门学派的全部工艺——与 [12 章](./12-BDD与CUDD.md)的符号学派隔山相望。

## 七、不足与边界

1. **状态爆炸是宿命**：显式枚举 10⁷ 状态封顶；偏序/位状态是缓兵之计，符号化（[12 章](./12-BDD与CUDD.md)）是另一座山头。
2. **公平性要显式给**：`G(req→F ack)` 在"调度永不选某进程"的模型上必假——weak fairness 假设要写进性质或模型，Spin 用 `-f` 开关注入；忘了给的"假反例"是新手第一坑。
3. **PSPACE 在公式侧**：性质写长（嵌套 GF 交替）自动机指数炸——LTL 可读性与其自动机尺寸不成正比。
4. **只能查安全/活性这类ω-正则性质**：概率、时间、数据约束都要换语言（[10](./10-PRISM概率模型检测.md) PCTL、PTA）。
5. **反例是 lasso 不是解释**：模型检查器给你"哪条路错了"，不给你"为什么错"——诊断负担仍在人（[50 章](./50-复杂度动物园与选型.md) 的"语法不是水晶球"在工具侧的回声）。
