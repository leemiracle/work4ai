**2006 年 6 月。** Java 之父之一 Joshua Bloch 发了一篇短文,标题像号外:*Nearly All Binary Searches and Mergesorts are Broken*。他说的正是教科书级的二分查找:1986 年《Programming Pearls》印刷的版本、以及当时 JDK 标准库里跑着的 `Arrays.binarySearch`,全带着同一个 bug——`mid = (lo + hi) / 2` 在 `lo+hi` 溢出整数上界时给出**负数下标**。这个 bug 在最被审查的算法上安坐了二十年,被百万开发者读过、抄过,靠**人眼**谁也没抓到。修复只要一行(`mid = lo + (hi-lo)/2`)。抓到它的不是更多 code review,而是把"循环不变式 + 前后置条件"写下来的**契约方法**——这正是 15-414 课程名叫 Bug Catching 的底气:**漏洞捕捉是一门可以教的手艺,不是运气**。

## 二、契约:把"对"写成和代码一样精确的东西

**Hoare 三元组**(Hoare,1969):`{P} C {Q}`——若执行前 P 成立且 C 终止,则执行后 Q 成立。P 是前置条件(调用者的义务),Q 是后置条件(被调者的承诺)。二分查找开篇那个 bug,在契约语言里根本活不过第一次验证:

```
requires 0 ≤ lo ≤ hi ∧ a 排序          // 调用者义务
ensures  −1 ≤ result < hi ∧ ...         // 找到/未找到的精确承诺
mid := (lo + hi) / 2                    // 循环体里:lo+hi 可能溢出 → 义务破
```

**ghost 变量**(9/4 讲):只存在于证明里、不参与执行的变量。典型用途是"记住起点"——`ghost sum₀ := Σa[i]`,后置条件写成 `Σa[i] = sum₀`。它不改变程序行为,只让"验证者能看到的东西"和"数学上想说的话"对齐。[02 章](./02-从代码到规则-形式化的两层.md)形式化代码一脉的全部手艺,起点就是这一节。

## 三、语义:证明规则为什么可靠,要对着语义证

9/9-9/11 两讲是本系列此前跳过的一环:**证明规则本身也是数学对象,它的可靠性(soundness)是一条要对语义证明的定理**。小步操作语义给每条语句一个形式化的"下一步"关系 `⟨C, σ⟩ → ⟨C′, σ′⟩`(σ 是状态=变量到值的映射),赋值一条规则就够:

$$\langle x := e,\ \sigma\rangle \ \to\ \langle \text{skip},\ \sigma[x \mapsto \llbracket e \rrbracket_\sigma]\rangle$$

手推一遍(与 lab15 的 `run()` 解释器一一对应):状态 `σ = {x:3, y:4}`,语句 `x := y+1`:右边求值 `⟦y+1⟧ₛ = 5`,新状态 `σ′ = {x:5, y:4}`。if/while 的规则同样机械:if 按 `⟦b⟧ₛ` 选分支;while 展开成 `if b {body; while b body} else {skip}`——**语义先行之后,"Hoare 规则可靠"才能陈述成定理**:任何 `⊢ {P} C {Q}` 的推导,都对一切满足 P 的初始状态,执行真的到达满足 Q 的状态(或不停)。课程先讲 Contracts 再讲 Semantics 的顺序是教学法的让步;逻辑上,**没有语义的证明规则只是符号游戏**——这是 [00 章](./00-为什么形式化+Lean4SOTA.md)"TCB 包含语义定义"的展开。

## 四、循环与归纳:不变式是手艺,变式是终点

循环是演绎验证的房租——按月交,永远交不完(9/18 Loops、9/25 Induction、9/30 Convergence 三讲专治它)。核心一图:

```
入口 P ⟹ I                    ← 建立基例
循环头 I ∧ b ⟹ wp(body, I)     ← 归纳步:转一圈 I 保持
循环头 I ∧ ¬b ⟹ Q             ← 出口:I 足够强,推得出后置
```

**不变式 = 归纳假设**。它不是"循环里恰好为真的东西",而是"进圈前成立、每圈保持、出口够用"的数学命题——三条义务全过才算数。lab15 E3 用求和循环 `s = Σ₀ⁱ⁻¹ = i(i-1)/2` 演示:正确版三条义务全绿;把身体里 `s += i; i += 1` 换序成 `i += 1; s += i`,**保持义务立刻破在循环头 `σ={i:0,s:0,n:1}`,归纳步断,bug 被钉死**:

```
[正确版] 入口违例 0 | 保持违例 0 | 出口违例 0
[bug 版(先 i+1 再累加)] 入口违例 0 | 保持违例 21 | 出口违例 0
  保持义务破于循环头 σ={'i': 0, 's': 0, 'n': 1} → 身体执行 i := i+1 (=1) ; s := s+i (=1) → 终态 s=1,i=1(I 不再成立)
```

二分查找的 bug 属于同类:`lo ≤ mid < hi` 这个不变式在 `lo+hi` 溢出时破——契约方法不是"更仔细",是把"更仔细"变成机器检查。

**终止性(9/30 Convergence)**:循环正确 = 部分正确 + 终止。终止证明靠**变式(variant)**:一个整值函数 v,循环头有下界、每圈严格递减——整数上递减有界必到底,b 变假,循环出口。lab15 E4 的 `while i≠0 { i := i-2 }`:提名 v:=i,"每圈递减"恒真,但**下界保持义务** `wp(body, i≥0)` 在 i=1 破(1→−1,跳过 0):变式证毕的可能性排除,加上 50 步有界执行超步,双重信号指向不终止。注意判定语义:**变式是充分性证明**(给出即证毕),变式违规只是嫌疑——也许有更聪明的变式能证;终止性本身不可判定(停机问题),这格在 [50 章](./50-复杂度动物园与选型.md)最深处。

## 五、谓词变换子:从后往前算"要什么"

**最弱前条件**(Dijkstra,1975):`wp(C, Q)` = "执行 C 后保证 Q 成立的最弱前置"。它把"验证"变成"计算":`P ⟹ wp(C,Q)` 成立,程序就对。四规则(lab15 `wp()` 函数,闭包实现——代入退化为函数复合,不需要符号重写引擎):

| 语句 | 规则 | lab15 记号 |
|---|---|---|
| 赋值 | `wp(x:=e, Q) = Q[e/x]` | `z≥0[y/z]` |
| 顺序 | `wp(C₁;C₂, Q) = wp(C₁, wp(C₂, Q))` | 从后往前复合 |
| 条件 | `wp(if b T F, Q) = (b→wp(T,Q)) ∧ (¬b→wp(F,Q))` | 按 b 选支求值 |
| 循环 | **不动点,不可计算** → 人供不变式 I | `I ∧ (¬b→Q) ∧ (b→wp(body,I))` |

前三条是多项式时间的语法变换;第四条是全部困难所在——**循环的不变式没有完备算法**(等价于停机),所以 06 章 Dafny 能自动 discharge 一切义务、唯独不变式要人写。lab15 E1/E2 对同一程序跑两种后置:

```
E1(后置 z≥0):wp(程序, Q) = (y>0 → z≥0[y/z]) ∧ (¬y>0 → z≥0[-y/z])[x+1/y]
  有界检查(|x|≤5):全绿 —— wp 对每个 x 成立(此例它是重言式)
E2(期望 z≥1):有界检查:违反于 [-1] —— x=-1 时 y=0,z=-0=0,z≥1 破
  mini-BMC 反例轨迹(反例 = 模型,可独立复算):
  x = -1 ─┬─ y := x+1  (=0) ; z := -y  (=0)
          └─ 终态 z = 0 → 后置 z≥1 假
```

同一个 `if y>0 {z:=y} else {z:=-y}`,后置写 `z≥0` 就是对的,写 `z≥1` 就藏着一个 0 边界 bug——**WP 定位"哪类前置违反"(静),BMC 给"哪条具体轨迹"(动)**。mini-BMC 就是 [04 章](./04-有界模型检查CBMC.md)的三行缩影:程序展开 k 步、断言取反、找模型——**反例 = 模型**。

## 六、证明论一瞥:证明本身也要可检查

最后一块拼图(9/16 动态逻辑、10/7 序列演算、10/21 证书),点到为止但位置关键:

- **动态逻辑**(Pratt, 1976):把程序放进模态算子——`[C]φ` = "C 的所有执行终止后 φ 成立",`⟨C⟩φ` = "存在执行到达 φ"。Hoare 三元组 `P⟹[C]Q` 是它的特例:一阶逻辑 + 程序模态,**证明程序性质的逻辑本身是一阶逻辑的扩张**。
- **序列演算**(Gentzen, 1935):`Γ ⊢ Δ` 左假设右目标,推理规则一小撮。它是"证明的语法"——把证明本身变成可机械检查的对象。
- **证书**(10/21):求解器说 unsat,凭什么信?给一条可独立检查的证明链。这是 [03 章](./03-SMT求解与Z3cvc5.md) cvc5 证明输出、[00 章](./00-为什么形式化+Lean4SOTA.md) Lean4 内核"proof checker 不 proof search"的公共祖先——**信任的最小化:验证者只做检查,检查是多项式的**。

三块合起来是课程的暗线:**验证 = 语义(什么是对)+ 逻辑(怎么推)+ 证书(凭什么信)**。03 章讲了引擎,本章补了地面。

## 七、复杂度格与造桥

- **格籍**:程序正确性(全称、无界)= 不可判定(停机归约);WP 计算 = 多项式语法变换(但产出的公式交给 SMT 后回到 [03 章](./03-SMT求解与Z3cvc5.md) 的 NP/coNP 格);k 步有界反例 = NP(证书 = 那条轨迹);证书检查 = 多项式。
- **造桥**:→[03](./03-SMT求解与Z3cvc5.md)(WP 产出的 VC 正是 SMT 的输入,闭环);→[04](./04-有界模型检查CBMC.md)(没有不变式时的有界出路);→[06](./06-Dafny验证语言.md)(把本章全部手工自动化);→[00](./00-为什么形式化+Lean4SOTA.md)(证书检查者 = Lean4 内核的角色);→[50](./50-复杂度动物园与选型.md)(本章的格子归位)。
- **一句总结**:演绎验证的经济学 = 人只付两样钱——**契约(说清什么是对)与不变式(扛起循环)**,其余全部自动化;模型检测(04/07/10)连这两样也不收,收的是状态空间。
