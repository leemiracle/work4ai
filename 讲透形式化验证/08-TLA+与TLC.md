# 08 · TLA+：规约即数学

> 卷二第二章：[07 章](./07-LTL与Spin.md) 检查"系统满足性质吗"，本章问更上游的一问——**系统本身是什么**？TLA+（Lamport，2013 图灵奖背后的语言）的回答是数学原教旨主义的：**状态 = 值的元组，行为 = 满足下一状态关系的无穷序列**——没有对象、没有指针、没有调用栈，只有数学。三件套：**行为规约观**（PlusCal 伪代码层 → TLA+ 数学层的两级表达）；**TLC 工艺**（显式枚举 + 不变式 + 死锁检测——lab08 在两阶段提交模型上跑出完整账本：**18 个可达状态、原子性零反例、零死锁**；砍掉"有弃权即中止"动作后 **13 态 3 死锁**——经典 2PC 阻塞态连同计划手推都没想到的第三个 `(A,A,COLLECT)` 一起现形）；**AWS 战场**（S3 一致性后端/DynamoDB 复制——TLA+ 在工业界的最大规模证词）。【模型检查 PSPACE；TLC=显式枚举】

---

## 一、状态 = 值：行为规约观

程序员的系统观是对象的、指针的、栈帧的；TLA+ 全部扔掉：

- **状态变量**：`rm1 ∈ {W,P,C,A}`——就是一个值，没有身份没有地址；
- **行为**：`Init ∧ □[Next]_vars`——初始谓词 + "**每一步**都由 Next 关系生成"（□ 是 [07 章](./07-LTL与Spin.md)的 G 换装；`[...]_vars` 还允许"什么都不变"的 stuttering 步——时钟滴答，系统不动）；
- **性质**：`TypeInvariant`、`Atomicity` 等是状态的谓词；活性用 `⟨F⟩`（leads-to）写在同一门语言里。

这个选择换来一样千金的东西：**规约可以直接做数学**（精化映射、组合定理、TLAPS 证明全部顺理成章——§四）；付出一样：**门槛**（工程师要从"写代码"换到"写数学"——PlusCal 是给这个台阶的桥）。

## 二、PlusCal → TLA+：两阶段提交的两级表达

两阶段提交（2PC）：协调者 tm 收集两台资源管理器 rm 的投票，全票 COMMIT、见弃权 ABORT。PlusCal（伪代码层，过程式语法糖）：

```
-- algorithm TwoPhase {
  variables rm1 = "W", rm2 = "W", tm = "COLLECT";
  macro RM_PREPARE(rm)   either rm := "A"  or  rm := "P"  end either;
  process (TM = 0) { await rm1 ∈ {"P","A"} ∧ rm2 ∈ {"P","A"};
                     tm := IF rm1 = "P" ∧ rm2 = "P" THEN "COMMIT" ELSE "ABORT" }
  process (RM1 = 1) { RM_PREPARE(rm1); await tm ≠ "COLLECT";
                      if tm = "COMMIT" then rm1 := "C" else rm1 := "A" }
  process (RM2 = 2) { ... 同 RM1 ... }
}
```

`tlaplus` 翻译器把它展开成 TLA+ 的 Next 关系——**一堆析取的"动作"**（rm1 单方面弃权 ∨ rm1 投票 ∨ tm 决议 ∨ rm1 服从决议 ∨ ……）。lab08 的 `next_states` 就是这张动作表的 Python 直译（①单方面弃权 ②投票 ③全票 COMMIT ④见弃权 ABORT ⑤服从决议）。**动作是原子的、步与步任意交错**——并发语义一句话说清，这是 TLA+ 比伪代码更强的地方：交错语义不是隐含的，是写出来的数学。

## 三、TLC 工艺：枚举 + 不变式 + 死锁（先跑后写的手推账本）

TLC 的检查循环朴素到极点：**BFS 枚举全部可达状态，每个新生成的状态查三样**——类型不变式、用户不变式、有没有后继（死锁检测），外加覆盖检查（每条动作都被行使过吗）。lab08 在 2PC 模型上的完整账本：

```
E1 · 完整模型（动作①-⑤全开）：
  可达状态 18 个｜死锁 0 个｜Atomicity 反例 0 个
  终态 2 个：[(A,A,ABORT), (C,C,COMMIT)]
E2 · 砍掉④（tm 只认全票，不看弃权）：
  可达状态 13 个｜死锁 3 个 [(A,A,COLLECT), (A,P,COLLECT), (P,A,COLLECT)]｜Atomicity 反例 0 个
E3 · 理论空间 48 态（4·4·3），完整模型只达 18——"行为是空间的极小骨架"
```

三段读法。**其一**：完整模型里原子性是**免费**的——不是巧合，是动作表的必然（决议只有一种声音，RM 只服从）；18/48 的可达率展示了"行为=空间骨架"的规约观。**其二**：把④（见弃权即中止）砍掉，经典 **2PC 阻塞**当场现形——(A,P,COLLECT) 是教科书死锁（协调者等一张永远不来的票）；而 **(A,A,COLLECT) 是手推都容易漏掉的第三个**（双方都单方面弃权、一张票都没有，同样永堵）。诚实注记：本章计划稿的手推数字（22 态、2 个死锁）经 lab08 实测修正为 18/0 与 13/3——**先跑后写，数字以机器为准**。**其三**：死锁检测抓的是**协议裁决时机的缺陷**——不是实现 bug，是设计本身留了"等不到"的格局；这正是 TLC 类工具的杀手锏：设计期抓设计缺陷，不用等代码写出来。

## 四、TLAPS：TLC 查有限、TLAPS 证无限

TLC 只能枚举有穷状态空间（参数定了 2 台 RM 就是 18 态；换成 N 台、值域换成整数，TLC 直接出局）。**TLAPS**（TLA+ Proof System）是证明层：`THEOREM AtomicityInv ≜ ∀s ∈ States : Inv[s]` 配合交互式证明（Coq/Isabelle 风格的分层 OBVIGA……实为 SANY 解析 + 数学证明语言），机器查证明。**层级化验证**是 TLA+ 生态的独特风景：同一份规约，TLC 查玩具参数、TLAPS 证一般定理、精化映射（refinement）把实现规约接到抽象规约——查有限与证无限不是二选一，是两级火力。

## 五、AWS 战场：工业界最大规模的证词

AWS 的 TLA+ 战报（Newcombe et al., CACM 2015 "How Amazon Web Services Uses Formal Methods"）值得整段记住：**S3 一致性后端**的重写——TLA+ 规约暴露"看似无害的优化在罕见交错下违反一致性"的设计缺陷，复杂度对数级下降；**DynamoDB** 复制协议——TLC 枚举出 10¹⁰⁺ 状态（靠对称性归并与分布式 TLC）；团队反馈"TLA+ 教会我们系统实际如何运转"。另有 Azure（存储队列）与多家的跟进——TLA+ 是"从论文走向车间"最成功的规约语言，没有之一。

## 六、正交性：规格语言 × 检查工艺

与 [07 章](./07-LTL与Spin.md)对照的分水岭一句表：

| | Spin | TLA+ |
|---|---|---|
| 建模观 | 进程+信道（并发原语一等公民） | 状态=值（数学一等公民） |
| 检查工艺 | on-the-fly 乘积 Büchi | BFS 显式枚举 |
| 性质语言 | LTL（自动机化进 Never claim） | 不变式 + 时序公式（TLA 自己） |

但两根轴**可交叉**：TLA+ 也能写 LTL 性质（TLC 查 Liveness 靠 lasso 检测——与 07 章 §三同构）；Spin 也能写结构化协议——语言与工艺是两个旋钮（[50 章](./50-复杂度动物园与选型.md)选型树的一根分叉）。

## 七、仪器

- **Python 保底**（本 lab）：`python experiments/lab08_tla_tlc.py`——2PC 的 BFS 枚举三件套（18 态/死锁/原子性）+ 砍④实验（13 态 3 死锁）+ 48 态空间对照。
- **原生可选**：TLA+ Toolbox（Eclipse 系，需 JDK；命令行 `tlc2.jar`）——把 §二的 PlusCal 存成 `TwoPhase.tla`，`java -jar tlc2.jar TwoPhase` 应给出同款 18 态结论，与本 lab 对拍。装不通不阻塞。
- 进阶：给模型加 ` symmetry`（两 RM 可交换）看 TLC 状态数下降——[11 章](./11-Storm与高性能概率检查.md)对称性压缩的直系表亲。

## 八、不足与边界

1. **枚举爆炸是 TLC 的天花板**：18 态的玩具到 10⁷ 就要分布式 TLC + 归并；无限数据类型（整数计数器）直接不可枚举——上 TLAPS 或换符号工艺。
2. **类型弱**：TLA+ 的值域靠 TypeInvariant 约定（CHOOSE/集合运算没有静态类型系统）——2019 后的 SANY 有改善，仍不如 Dafny（[06 章](./06-Dafny验证语言.md)）的依赖类型舒服。
3. **工具链年久**：Toolbox 的 Eclipse 底座、报错措辞、调试体验都有年代感——工业成功与工具体验是两回事。
4. **PlusCal 不是全部**：一旦要精化映射与组合定理，必须直面 TLA+ 数学层——台阶始终在那，躲不过去。
5. **活性检查贵**：TLC 查 liveness（lasso + 公平性）远比不变式贵——工程上大量规约只查安全性，活性靠 TLAPS 或抽查。
