# 04 · 管理计量学转代码:把仪表盘、实验与前沿装进生产

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角)。

---

## 开篇:别的分支在"翻译",本分支在"部署"

理论学科转代码,是把纸面结论翻译成算法;管理计量学转代码,
是把它**部署成每天运行的生产系统**——指标管道凌晨跑批,
实验平台实时分流,效率评价季度跑一轮。
本学科的"定理"如果不跑在生产里,等于没说过。

所以本章的问题不是"能不能转"(几乎全能),而是"**怎么转得可信**":
管道要防静默错误(SRM/丢日志),指标要防漂移(口径版本化),
实验要防偷看(序贯校正)。**可信性工程**取代算法难度成为主战场。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 管理计量概念 | 代码化身 | 备注 |
|---------|---------|------|
| 指标口径 | 指标字典(语义层):唯一定义+版本号+负责人 | "活跃用户"全公司只有一种算法——政治问题工程化解决 |
| 显著性检验 | Welch t / z 检验、Bootstrap、FDR 校正 | 上游:[数理统计转代码](../../讲透数学/讲透数理统计/);大样本用正态近似(家族实验 Part 2) |
| 功效/样本量计算 | n=2σ²(z_α+z_β)²/δ² 一行公式 + 事前功效模拟 | 家族实验 Part 3:δ=2pp→每臂约 9000,先算后开实验 |
| 随机化分配 | 一致性哈希(user_id+layer+salt)→分流 | 分层实验(harness 层)防互踩;SRM 卡方检验当质检 |
| DEA 前沿 | 逐单元解 LP(分式规划线性化);对偶解=影子价格 | 单元数百内秒级;纯标准库可写小型求解(走廊 3) |
| AHP 权重 | 比较矩阵→幂迭代求主特征向量;CR 一致性闸门 | 30 行代码;挂靠读本 [量化武器库](../../讲透管理/03-代码-量化武器库.md) 已实测 CR=0.033 |
| 控制图/监控 | 中心线±3σ、指数加权移动平均、报警规则 | 判异规则随粒度调(大样本过敏,03 章家底表) |

**转不动/只能半转(红色区)**:

1. **口径的协商**:指标定义是利益分配(谁的渠道算转化)——
   工程能做的是把谈判结果**固化**(字典+评审+版本),不能替人谈。
2. **伦理审查**:实验即干预,豁免边界(知情同意/弱势群体/敏感变量)
   要人裁决;工程贡献的是事前登记与最小化采集。
3. **古德哈特监控**:错位角(代理 vs 真目标)可以定期回测(半自动),
   但"指标要不要换"是管理层决策——仪表盘只能报警,不能改方向盘。
4. **因果解释**:代码给出"效应=+2.4pp",**为什么**(机制)要人写;
   中介分析的代码能跑,解释的锅代码不背。

**边界的一句话**:绿色区负责**算得对**,红色区负责**用得对**——
本家族的失败案例几乎全在红色区(指标设计错了,统计再准也是精确的错误)。

## 二、代码走廊清单(三条走廊,每条=对象→数据结构→算法→真实系统)

### 走廊 1:绩效指标体系(从口径到看板)

```
管理目标 ──指标树拆解──▶ North Star + 输入/输出/护栏三层
   │
   └──口径评审──▶ 指标字典(语义层) ──▶ 采集管道(日志/数仓) ──▶ 看板+报警
```

- **对象→结构**:指标=带元数据的计算列(名称/口径 SQL/窗口/版本/负责人);
  指标树=目标的有向分解(北极星指标←输入指标),平衡计分卡四视角是其经典版
  (挂靠读本 [量化武器库](../../讲透管理/03-代码-量化武器库.md) E 区已实测 BSC 因果链)。
- **算法层**:流式/批式聚合、同环比、队列分析(留存曲线)、
  口径变更的**双跑期**(新旧定义并行一个月再切换)。
- **真实系统**:各类 BI 看板;语义层/指标平台(下文工程师落点)。
- **古德哈特防御工事**(本走廊的灵魂):
  ①指标成组(单一指标必被博弈,组合抬高作弊成本);
  ②护栏先行(赢主指标不许破护栏);
  ③定期回测(代理指标与真目标——长期留存/审计——的错位角);
  ④轮换与抽审(03 章"校准是慢变量"的工程化)。

### 走廊 2:A/B 实验(从分流到判决书)

```
假设+功效计算 ──▶ 一致性哈希分流(实验层) ──▶ 日志采集
   │                                            │
   └──护栏指标注册 ◀── SRM 卡方质检 ◀── Welch t/z 检验 ◀── 数据
                                  └──▶ 判决书五要素(02 章 §三)
```

- **对象→结构**:实验=假设+分流规则+指标集(主指标/护栏)+停止规则;
  用户-实验分配用一致性哈希保证稳定(同一用户每次进同一臂)。
- **算法层**:事前功效(家族实验 Part 3);事后 Welch t(大样本正态近似);
  序贯/多次检验校正(上游 FDR 课);CUPED 用实验前协变量缩方差(平台标配);
  SRM 卡方检验:设计 50/50 实测 51/49 就**停机查管道**——统计之前先验管道。
- **真实系统**:微软/谷歌/亚马逊的内部实验平台;开源栈可自攒
  (分流服务+数仓+检验库)。本家族 `experiments/00_goodhart_ab.py`
  是 12 万用户微缩版:分流→检验→两份判决书(代理赢、真目标输)。
- **性能工程要点**:分流判定在请求热路径上——一致性哈希必须 O(1) 无外部调用;
  检验全在离线;**热路径零统计、统计零热路径**。

### 走廊 3:DEA 效率前沿(从投入到名次+改进说明书)

```
决策单元 × (投入,产出)矩阵 ──▶ 逐单元 CCR 分式规划 ──线性化──▶ LP
   │                                              │
   └──同质性检查(口径统一)                          ├─▶ 效率 θ∈(0,1] 排名
                                                  └─▶ 对偶解=影子价格(差在哪)
```

- **对象→结构**:CCR 的原始形式是分式规划
  `max u·y₀ / v·x₀ s.t. u·yⱼ ≤ v·xⱼ(∀j), u,v ≥ 0`
  (单元₀ 自选权重 u,v,在所有单元约束下最大化自己的产出投入比);
  Charnes-Cooper 变换线性化后就是标准 LP——几百个单元秒级可解。
- **算法层**:每个单元解一个 LP;对偶解给出影子价格
  ("若人力投入减 8%,即达前沿");投入导向/产出导向两个方向。
- **真实系统**:银行网点/医院/学校/电网的绩效评价与资源配置;
  与挂靠读本武器库的 AHP/TOPSIS 排序工具互补——
  **DEA 不要权重(数据包络),AHP 全靠权重(专家判断),TOPSIS 折中**。
- **防御工事**:指标数 ≤ 决策单元数/3 的经验下限(维度灾难);
  超效率模型把"并列第一"排开;单元不同质先分层再各自包络。

## 三、工程师落点(指标平台与实验文化)

| 落点 | 内容 | 为什么是工程问题 |
|------|------|----------------|
| **指标平台** | 指标字典+语义层:口径唯一定义、版本化、API 化(headless BI) | 指标分裂(各部门"活跃"不同算法)是数据团队第一大事故源;字典=口径的单向数据流 |
| **实验文化** | 每员工每年实验数当北极星;实验评审委员会(设计+伦理);失败实验入册可查 | 实验平台的瓶颈从来不是统计,是**组织敢不敢让想法被否决**——Kohavi 的平台经验:信任(SRM 防护)+ 流速(自助开实验)缺一不可 |
| **回测管线** | 代理指标↔真目标错位角的定期回测;指标衰减报警 | 古德哈特防御的自动化半壁(03 章"校准是慢变量") |
| **审计留痕** | 口径变更评审、实验判决书归档 | 02 章"报告规范是治理"的存储层:证据要可追责到人 |

**性能工程的计量观**:指标管道是**延迟宽裕、正确性苛刻**的系统——
宁可慢跑批,不可静默错(错误指标会驱动真金白银的决策);
实验分流是**延迟苛刻、逻辑简单**的系统。两类系统的 SLO 完全相反,
别用同一套架构伺候。

## 四、可机械化的检验仪式(把本家族用成瑞士军刀)

遇到任何组织/产品系统,做三问:
1. **指标问**:结论里的每个数字,口径文档在哪?版本几?负责人谁?
2. **对照问**:每个"提升了",对照是哪一级(过去/他人/最优/反事实)?SRM 查了吗?
3. **前沿问**:每个排名,评委是权重(谁定的?)还是数据(怎么包的)?单元同质吗?

三问过完,系统的计量骨架就裸露了——剩下的才是真正的难点(口径政治与伦理)。
