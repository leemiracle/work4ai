# 04 · 区域经济管理转代码:把格子、流量与动能装进数据管道

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角)。

---

## 开篇:区域问题转代码,是"把账算清",不是"把规划自动化"

理论学科转代码,是把结论翻译成算法;区域经济管理转代码,
是把**账与指标**部署成可复现、可审计的数据系统——
区域账户年年跑批,集聚指标季度更新,转移支付公式按决算触发。
规划本身(画格子、定功能)转不动——但**一切为规划供数的管道**必须转,
而且必须转得可信:口径错了,规划、考核、转移支付全体跟着错,
错的还是真金白银。

所以本章的问题不是"能不能转"(账务与指标层几乎全能),
而是"**怎么转得可信**":口径版本化、边界版本化、双口径交叉、
考核防博弈。可信性工程是主战场——与 [管理计量学](../讲透管理计量学) 04 章
同一条战线,本家族是它的**空间方言**。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 区域管理概念 | 代码化身 | 备注 |
|---------|---------|------|
| 区位熵 | 分子=格子份额,分母=全国份额,一次除法 | 04 章走廊 1;**必须双口径并行**(就业/税收),单口径=古德哈特裸奔(家族实验 Part 3) |
| 转移份额分解 | ΔE=NS+IM+RS 的逐格会计,代数恒等零残差 | 走廊 2;全国基准要外生(域外锚定),防被评估区污染砝码 |
| 差距指数 | Theil 分解/Gini/β收敛回归 | 协调支核心件;多尺度输出(MAUP 防御) |
| 区域经济账户 | 带边界文件版本的空间数据库:单元版本+口径字段+回溯重建 | 走廊 3 的地基;行政区划变更是区域数据工程独有痛点 |
| 政策矩阵台账 | 工具×目标的关系型台账+评审留痕 | 走廊 3;匹配本身是人的判断,台账只负责可追责 |
| 空间权重矩阵 | 邻接/距离衰减的矩阵构造 | 空间计量的地基(上游 [统计学宇宙](../../讲透统计学/README.md) 与数量经济学) |
| 创新网络代理 | 合作专利/联合项目→图结构,度中心性/社群发现 | 图算法标准件;**可见≠重要**的告警必须写进输出(03 章) |

**转不动/只能半转(红色区)**:

1. **功能定位的价值判断**:承载力参数怎么定、哪块地划限制开发——
   工程能把参数敏感性算给你看,不能替你定参数。
2. **规划协商**:格子边界的谈判是利益分配——工程贡献的是
   多方案的可视化与影响测算,不是决策本身。
3. **S3 的发现程序组织**:EDP 是制度工程(谁来试探、怎么留痕、谁放大),
   代码只能承载记录与回溯,"发现"的真伪要制度保证(01 章主线 B)。
4. **区域预见的判断**:情景可以算(走廊外),选哪个情景当基准是政治选择。

**边界的一句话**:绿色区负责**算得清**,红色区负责**定得对**——
本家族的失败案例几乎全是"账算清了、格子画错了"。

## 二、代码走廊清单(三条走廊,每条=对象→数据结构→算法→真实系统)

### 走廊 1:区位熵与集聚识别(从口径到集聚判定)

```
区域×部门就业表 ──双口径采集──▶ {就业口径, 税收口径, 注册口径}
   │                                    │
   └──全国基准表(外生)                  ├─▶ LQ 矩阵(逐口径)
                                        └─▶ 口径交叉验证:|LQ注册−LQ就业|>阈值 → 报警
```

- **对象→结构**:LQ=(格子部门份额)/(全国部门份额);>1.25 判集聚(常用参考线)。
- **算法层**:一次除法;防御工事才是走廊的灵魂——**双口径交叉验证**
  (注册口径与就业/税收口径的比值超阈值即报警"名义集聚"),
  以及全国底数的口径一致性(否则邻区读数被反向稀释,家族实验 Part 3 全流程实拍)。
- **真实系统**:各地产业地图、产业集群监测平台、统计部门的行业集中度报表。
- **性能工程要点**:批量离线计算,毫秒级无压力;难点全在**采集口径治理**——
  企业的注册地/经营地/用地三址不一致,归并规则要写进账户构造文档(03 章)。

### 走廊 2:转移份额分解(从增长到机制诊断)

```
t0/t1 区域×部门表 + 外生全国基准 ──▶ 逐格 ΔE=NS+IM+RS
   │                                        │
   ├─▶ 恒等式自检(Σ三效应=ΔE, 全国ΣRS=0)      ├─▶ RS/E0=本地竞争优势率
   └─▶ 多窗口滚动(t−5, t−10)                 └─▶ 排名与警报(结构依赖型区域)
```

- **对象→结构**:三效应 NS=大势、IM=结构、RS=本事;代数恒等、零残差,
  天生适合做数据管道的**自检点**(断言写进作业:ΣRS=0 不成立=管道漏了)。
- **算法层**:表格逐格算;全国基准用"研究区+大域外"锚定,防被评估区污染
  (实验里域外是研究区的 34 倍,污染 <0.5pp);多窗口滚动看 RS 的持续性——
  一次 RS 高可能是噪声,五年连续 RS 高才是禀赋。
- **真实系统**:区域经济运行监测、产业结构的年度诊断报告、
  招商政策的事后评估(RS 有没有动是最诚实的读数)。
- **性能工程要点**:又是"延迟宽裕、正确性苛刻"的批处理系统;
  输出必须带口径与基准版本号,否则两年后没人知道数字对的是什么镜子。

### 走廊 3:政策矩阵与区域账户(从台账到考核)

```
区域经济账户(空间单元版本+双口径)──▶ 指标字典(区域版)
   │                                        │
   ├─▶ 政策矩阵台账:工具×目标+评审留痕        └─▶ 考核看板:集聚/差距/动能三层+护栏
   └─▶ 转移支付公式引擎:均等化公式→测算→决算对账
```

- **对象→结构**:区域指标=带空间元数据的计算列(指标名/口径/空间单元版本/
  归属规则/窗口/负责人)——比企业指标字典多两格:**空间单元版本**与**归属规则**。
- **算法层**:均等化转移支付的公式测算(标准收支缺口法,通说)、
  政策矩阵的 CRUD+留痕、考核看板的护栏(名义集聚报警接走廊 1)。
- **真实系统**:财政转移支付测算系统、各级区域经济监测平台、
  结构基金的合规与评估流水线(EU 侧,程序化程度最高的参照系)。
- **古德哈特防御工事**(本走廊的灵魂):①考核指标成组(集聚+就业+税收
  三口径互相咬合);②口径变更双跑期(03 章账户模板);③注册-经营口径差
  常态监测(差值突变=迁移造数嫌疑);④定期用灯光等外生锚回测(03 章回测字段)。

## 三、工程师落点(区域数据平台与考核治理)

| 落点 | 内容 | 为什么是工程问题 |
|------|------|----------------|
| **空间单元版本管理** | 边界文件版本化;区划变更的序列回溯重建(按新边界重算历史) | 县改区/合并是区域数据第一大事故源:不做版本化,一切趋势图都是断简残编 |
| **双口径数据管道** | 注册/经营/税收三口径并行采集与交叉验证 | 单口径考核必被口径博弈(实验 Part 3);双口径是区域指标体系的最低防线 |
| **考核看板护栏** | 名义集聚报警、差距的多尺度一致性检查(MAUP) | 考核指标是区域行为的方向盘——看板只报警不改方向,但报警必须自动 |
| **外生基准库** | 全国/行业基准的口径与版本管理 | 转移份额的镜子歪一度,所有区域的"本事"读数全体偏转 |

**性能工程的区域观**:区域数据系统几乎全是**批处理+正确性苛刻**型
(决算口径容不得静默错);唯一的准实时件是灾害/重大项目的应急调度——
那是公共管理侧(63044,波4待建)的地盘。别给账户系统上实时架构,
那是拿生产数据库练手。

## 四、可机械化的检验仪式(把本家族用成瑞士军刀)

遇到任何区域政策/报告/平台,做四问:
1. **口径问**:每个数字是注册口径还是经营口径?空间单元版本几?序列断没断?
2. **镜子问**:每个"强/弱/快/慢"对着什么基准(全国/行业/反事实)?基准外生吗?
3. **格子问**:每个结论挂在什么空间单元上?换一级单元(县并市/市并圈),结论稳吗?
4. **外生锚问**:有没有一个不依赖同一口径的外部读数(灯光/用电)能对上?
   (03 章"三个自检仪式"的现场版)

四问过完,区域叙事的账本骨架就裸露了——剩下的才是真难点(价值判断与协商)。
