# 04 · 公共管理转代码:把公共价值搬进机器(能搬多少搬多少)

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:公共管理的谱系左端(03 章)——流程 schema、指标产出端、
> 平台分层、预算结构——几乎可以无损转码;右端(公共价值、合法性、信任)
> 完全不可转码。三条走廊——**排队分流仿真**、**预算配置优化**、**法规文本解析**——
> 分别把"等待""花钱""依据"变成可跑、可断言、可做敏感性扫描的实验;
> 而性能工程的分布优先纪律(P90 优先于均值)在本家族不是习惯,是伦理。

---

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",公共管理转代码要解决"**授权与语义**":
一段公共管理语言("最多跑一次")先翻成模型(流程图+数据流+排队系统),
再翻成代码。翻译的全部损耗发生在第一步——哪些环节有法规依据、哪些材料
能被共享数据替代,这些不是技术问题。所以本章先划清哪些对象第一步走得通
(绿色区),哪些走不通(红色区),再给三条走通了的走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 公共管理概念 | 代码化身 | 备注 |
|------------|---------|------|
| 服务流程(03 章对象 1) | 流程引擎/状态机+校验规则 | BPMN 的公共版;环节-时限-材料全部字段化 |
| 政务大厅排队 | 多服务台排队仿真(到达-渠道-耐心) | 家族实验全流程纯标准库 |
| 预算配置 | 背包/LP(项目组合优化) | 边际绩效递减假设下的选片问题 |
| 法规条文 | 规则解析(要件-效果抽取)+校验器 | "若 A 且 B 则应 C"→约束检查 |
| 绩效产出端 | 指标计算+仪表盘+异常检测 | 产出可数;结果归因不在此层(03 章) |
| 指数合成(EGDI 类) | 加权合成+权重敏感性扫描 | 合成是公共选择,敏感性是诚实条款 |

**转不动/转不动的边界(红色区)**:

1. **公共价值的权衡**:多目标不可通约(03 章刚性 1)——把权重写死进代码
   就是把一次公共选择伪装成技术必然。工程对策:做**权重敏感性扫描**,
   让每个排名都自带"权重区间→名次区间"。
2. **合法性与信任**:没有状态方程,硬造参数只会把自己假设回去。
   工程对策:退到测量学(调查/行为数据),不当仿真变量。
3. **街头裁量**:一线判断空间是规范设计的一部分,不是待清除的噪声——
   自动化它之前先问哪些裁量是**有意的**(02 章构念词典)。
4. **危机的不确定性端**:预案(期望脚本)可编码,灾害的真实分布不可预设
   ——对策:情景集+压力测试,不做点预测(危机支)。

**边界的一句话**:绿色区=03 章谱系左端(流程/产出/平台/预算),
红色区=右端(价值/合法性/裁量/不确定性)——**先问构造学,再谈转码**。

## 二、代码走廊清单(三条主走廊+一条副走廊,每条=理论→模型→算法→真实系统)

### 走廊 1:政务服务排队与分流走廊(本家族实验所在地)

```
排队论(到达/服务/耐心) ──参数化──▶ 渠道分配(在线/预约/自助/窗口)
      │
      └──多日仿真──▶ 等待分布(均值+P90)+ 完成率分组 ──▶ 分流政策实验台
```

- **理论→模型**:泊松到达、对数正态服务、指数耐心(超时放弃=服务不可及);
  人群分数字能力/数字鸿沟两类,渠道分配比例参数化——这是 Kingman 公式
  (等待 ≈ 利用率项 × 变化性项 × 服务时间)的公共政策版:**数字分流
  三箭齐发**——线上化降利用率、预约平滑降到达变化性、自助终端降服务时间。
- **本家族实现**:[`experiments/service_queue_triage.py`](experiments/service_queue_triage.py)
  ——断言:分流使现场等待均值与 P90 双降;鸿沟人群被强制在线化后
  有效完成率坍塌。**分布双指标(均值+P90)与分组完成率是公共服务的 SLA**,
  不是锦上添花——这正是性能工程的分布优先纪律(P50/P90/P99)在公共场景的化身。
- **真实系统**:大厅窗口数与导办配置、预约名额分配、线上化推进的
  兜底通道设计(保留线下=韧性冗余)。
- **性能工程要点**:多日重复=独立种子可并行;指标与参数解耦
  (换指标不动仿真内核);敏感性别只扫均值——**尾部与分组完成率
  才是公共政策的相关输出**。

### 走廊 2:预算配置优化走廊(把"买结果"变成选片问题)

```
绩效预算(项目-绩效目标) ──参数化──▶ 项目组合(成本/加权绩效/政策优先级)
      │
      └──背包/LP 求解──▶ 预算约束下的选片 ──▶ 边际分析(下一块钱买哪个)
```

- **理论→模型**:各申报项目给出成本与多指标绩效,总量约束=背包;
  加总化(允许多买少买份额)=LP。多目标不可通约的处理:**不做单一权重,
  扫权重区间**——报告"选片对权重的稳定性"而非一个"最优解"。
- **算法层**:纯标准库即可做小规模(贪心+DP);真实规模(数千项目)
  上 LP 求解器——数学住在[../../讲透数学/讲透运筹学/](../../讲透数学/讲透运筹学/)。
- **真实系统**:部门项目库的编制辅助、绩效目标的边际排序。
- **性能工程要点**:贪心解与 LP 解的间隙=启发式损失,可断言;
  敏感性扫描(权重×预算总额)是天然可并行的网格。

### 走廊 3:法规文本解析走廊(把"依据"变成可执行规则)

```
法规条文 ──抽取──▶ 要件-效果对(若 A 且 B 则应 C) ──编译──▶ 校验规则集
      │                                              │
      └──条文冲突检测(同一要件两效果)◀──规则对撞测试 ──▶ 表单自动核验
```

- **理论→模型**:02 章法规层的语义="要件-效果"结构;解析=把自然语言条文
  映射为规则三元组;校验器=对申请材料字段跑规则集(03 章对象 1 的
  "前置校验"从约定变成代码)。
- **算法层**:规则可人工+模式抽取(小规模);规模化用文本分类/信息抽取
  (NLP 上游住在别的宇宙);**冲突检测是本走廊的灵魂**——两条规则对同一
  要件给出相反效果,机器比人眼稳定。
- **真实系统**:在线表单的实时校验、审批流的规则引擎、
  政策一致性的自动化体检。
- **性能工程要点**:规则集要版本化(修法=变更集);每条校验规则
  回链到条文号——**可追溯性是公共系统的第一非功能需求**。

### 副走廊:指数合成走廊(EGDI 类)

- 加权合成+权重敏感性:换三套权重重排名次,观察名次区间。
  教学量级一页代码;要义在批判——**指数是可构造物,排名是权重的函数**
  (01 章判读要点 2)。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:政务流程的"编译器工程师"

- 数字政府平台的工程本质=**把材料清单编译成数据流**:申请人提交的材料,
  大半是政府自己(或另一部门)已知事实的纸面副本——共享数据替代材料提交,
  就是把"人肉数据搬运"优化掉。你的工作对象是 03 章对象 1 的 schema:
  字段映射、共享命中、前置校验,全是编译器语义。
- 检查清单:每个"必须线下提交"的字段,写得出一条法规依据吗?
  写不出,它就是可消除的摩擦。

### 落点 2:分布优先的公共服务 SLA

- 你在性能工程里熟悉的纪律——P99 延迟比平均延迟诚实——在政务排队里
  逐字成立:**均值等待下降可以与最弱人群的体验恶化同时发生**(家族实验
  的断言 2)。任何"平均等待缩短 X 分钟"的汇报,补三个数才算完整:
  P90、分组完成率、放弃率。
- 兜底通道(保留线下窗口)=性能工程里的**降级路径**:主路径
  (线上)越自动化,降级路径越是系统韧性所在——砍兜底省的钱,
  是把风险记在账外。

### 落点 3:分配效应审计(上线前先测"谁做不成了")

- 每个自动化/线上化改版,先跑一次分组对照:老年/低设备/低技能用户的
  完成率变化。方法就是家族实验的骨架:分组-分流-完成率。
- 把"数字包容"从口号变成回归:可及性 = 完成率的组间差距,
  它是可以进监控大盘的指标(和 P90 并列)。

### 落点 4:指标即契约(Campbell 预检)

- 给任何公共 KPI 写实现前,先写它的 gaming 场景(拆件/拒收难件/口径滑动),
  再设计防扭曲(多指标对冲、抽查复核、口径冻结)。
- 这条纪律与工程师熟悉的一句反话同构:**"你度量什么就得到什么"——
  在公共场景,这句话的代价由公民支付**。

## 📌 收束 + 🧭 认知升维

本章给你的**新眼睛:编译器之眼+分布之眼**——公共服务的流程是可编译的
(材料→数据流,依据→规则),而编译产物必须按分布验收:P90 与分组完成率
优先于均值,兜底通道优先于自动化率。机器能搬走的是等待与重复,
搬不走的是价值与信任——**转码的边界画在哪,工程伦理就从哪开始**。
