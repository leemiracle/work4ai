# 03 · 可构造与结构:公共部门的什么东西能"造出来"

> **本章回答五问之四:哪些对象可构造?结构刚性从哪来?**
> **本质一句话**:公共管理的对象沿一条**可构造谱系**排开——
> 服务流程 schema 端**严格可构造**(字段、环节、时限写得全),
> 公共价值度量端**几乎不可构造**(只有测量学的尝试,没有设计学);
> 而全谱系共享三条结构刚性:**多目标不可通约**、**委托链损耗**、
> **生产者-付款者-使用者三分**。
>
> 三步法贯穿:**为什么可构造/不可构造 → 它是什么构造 → 亲手构造一次**。

---

## 开篇:一条谱系,两个极端

想象把公共管理的所有对象按"能不能直接造出来"排一条线:

```
服务流程schema ── 绩效指标体系 ── 平台分层 ── 预算项目结构 ── 公共价值度量 ── 合法性/信任
   │                                                                      │
严格可构造(字段+流程)                                    几乎不可构造(只可测量与培育)
   └── 写得出、校验得动、跑得通                             └── 只能量、只能养,不能装配
```

为什么会有这条谱系?**可构造的前提是"有限描述+确定语义"**(与管理理论家族
03 章同一条判据):流程的语义是"材料-环节-时限-结果",输入输出明确;
而"公共价值"的语义是集体偏好本身,描述它就是在做政治。本章先盘四个
可构造对象,再看三条结构刚性。

## 一、可构造对象 1:公共服务流程 schema(严格可构造)

一个政务服务事项的形式化描述:

```json
{
  "事项名": "不动产权属登记",
  "依据": ["物权法条", "登记条例条款"],
  "申请材料": [{"名称": "身份证明", "来源": "公安主数据", "可共享": true},
               {"名称": "契税完税凭证", "来源": "税务主数据", "可共享": true}],
  "环节": [{"名": "受理", "时限日": 0, "前置校验": ["材料齐备", "权限范围内"]},
           {"名": "审核", "时限日": 5},
           {"名": "登簿发证", "时限日": 2}],
  "结果形式": ["登记证明"], "收费": {"标准": "依规", "减免": ["首次"]},
  "渠道": ["窗口", "线上", "自助"], "兜底通道": ["窗口永久保留"]
}
```

**为什么可构造**:每个字段的语义由法规层授权(02 章 §一),校验规则
可以机械执行("材料齐备"=字段非空+格式合法+共享数据命中)。
**"最多跑一次"类改革的工程本质=流程图的拓扑压缩**:环节合并、
前置校验(把审核提前到提交瞬间)、数据共享代替材料提交(可共享字段
全部命中 → 材料清单清零)。压缩率即改革深度——这是可以画图、可以
度量、可以断言的工程,不是口号。

## 二、可构造对象 2:绩效指标体系(半可构造:产出端可造,结果端归因不可造)

**逻辑模型**(本家族最通行的构造):

```
投入 ──▶ 活动 ──▶ 产出 ──▶ 结果 ──▶ 影响
(钱/人)  (流程)   (可数件数)  (受众状态变化) (社会长期变化)
 └────── 可构造(字段+计数)──────┘└──── 不可构造(归因识别)────┘
```

产出一侧完全可构造:指标树(战略目标→绩效目标→指标→目标值)、
数据管道、仪表盘全部可编码(04 章走廊)。**刚性在结果端**:办件数
(产出)与生活改善(结果)之间隔着因果链,而归因需要准实验设计
(02 章证据规范)——**绩效体系可以装配,绩效归因不能装配**。
最诚实的设计因此是:产出指标用于管理,结果评估交给独立识别策略,
两轨永不混写(混写即 Campbell 定律现场,00 章 §四第三行)。

## 三、可构造对象 3:数字政府平台分层(可构造)

UN/OECD"政府即平台"通说的工程化身(01 章主线 B):

| 层 | 内容 | 构造物 |
|----|------|--------|
| 渠道层 | 门户/APP/窗口/自助终端 | 多渠道适配层(同事项多渠道) |
| 服务层 | 事项编排、一站式集成 | 流程引擎(对象 1 的运行时) |
| 数据层 | 共享交换、主数据、身份认证 | 数据契约+主数据字典 |
| 基础设施层 | 云、网络、安全 | 资源池与账号体系 |

**为什么可构造**:每一层的接口语义明确(渠道调服务、服务调数据)。
**这层结构是 POSDCORB 的重装**:组织与人事(Staffing)变成平台账号与权限,
报告(Reporting)变成数据层留痕,协调(Coordinating)变成接口契约——
七零件没换,装配方式从"科室对科室"变成"服务对服务"。

## 四、可构造对象 4:预算的项目结构(可构造,归因同 2)

绩效预算的可构造核心是**项目树**:部门→项目→活动→绩效目标(带指标与
目标值)。编制=在项目树上分钱;审查=对照绩效目标砍/保;审计=回看目标值。
(优化选片的数学住在 04 章走廊 2。)刚性同对象 2:钱可以按树编,
"值不值"的最终裁判(公共价值)不在树上。

## 五、结构刚性:三条规定了"造"的上限

1. **多目标不可通约**:效率/公平/回应性/问责没有公共单位——不能加总成
   单一目标函数,只能做约束式或字典序设计。工程后果:一切"综合得分"
   的权重都是公共选择(指数走廊 04 章的敏感性批判由此来)。
2. **委托链损耗**:公民→立法→行政→一线,每加一层,信息损耗一次、
   问责稀释一度(00 章 ASCII)。工程后果:扁平化(一站式=把多层审批
   压成一次数据流)的收益不仅是快,还有**信息保真**。
3. **生产者-付款者-使用者三分**:企业里三者重合(自己生产、自己付钱、
   自己消费),公共服务里天然三分(公共组织安排、财政付款、公民使用)——
   外包/PPP 都是在重构这个三角,而每次重构都在重造激励与风险结构
   (委托代理的公共版,上游住在[../讲透管理理论/README.md](../讲透管理理论/README.md))。

**判定流程**(把一个公共管理主张钉到谱系上):

```
该主张的机制能写成 schema/约束/流程吗?
  ├─ 能,且结果可校验 ──────────▶ 谱系左端:直接形式化+转码(04 章)
  ├─ 能,但结果靠归因评估 ──────▶ 指标端:装配产出指标+独立结果评估,两轨分立
  └─ 不能,是价值与关系 ────────▶ 右端:测量+培育+兜底通道,禁止硬造参数
```

(端点错配是数字政府项目的头号失败模式:给价值端上指标工具,
给流程端喊"以人为本"口号。)

## 六、谱系×刚性×两支总表

| 支 | 主战场对象 | 谱系位置 | 可构造等级 |
|----|-----------|---------|-----------|
| [行政管理](讲透行政管理/) | 流程 schema/指标体系/平台分层/预算结构 | 全谱系(左端最厚) | 高(产出端全链可造) |
| [危机管理](讲透危机管理/) | 预案结构/资源预置/情景集 | 中段(预案可造,灾害不可造) | 中(预案=期望脚本的树,不确定性端不可装配) |
| 家族层(兜底长尾) | 政策工具组合 | 中右(工具可分类,组合效果靠评估) | 中低 |

**读表法**:一支的"工程化深度"不取决于话题新旧,取决于它的对象
住在谱系哪一段——行政管理支因流程 schema 而成为全家族可构造性最厚的支;
危机支的可构造性被不确定性封顶(这正是它的学科个性)。

## ✨ 美之时刻(彩蛋:逻辑模型——一条箭头链的承诺与克制)

✨ **美之时刻:投入→活动→产出→结果→影响(一条链的两个世界)**(结构)
逻辑模型用五个箭头把"花钱"与"改变世界"连起来:左半段(投入→产出)
每一环可数、可审计、可优化;右半段(结果→影响)不可归因、只可评估。
为什么美:**它诚实地把自己的能力边界画在了链条正中间**——这条链同时是
绩效管理的施工图与自我批判书:任何声称"一条链全自动跑通到影响"的方案,
都在右半段作弊。亲历:拿任一份部门绩效表,找出它实际停在第几个箭头,
再用 02 章证据规范判断它对第五个箭头的说法是"评估"还是"许诺"。

## ✍️ 练习

1. ✋ 把你办过的一个事项写成对象 1 的 schema(简化版),标出三个可共享字段
   与一个必须线下核验的字段,计算"零材料跑一次"的拓扑压缩率
2. ✋ 给一项公共服务画逻辑模型五箭头,分别标注:哪两环有数据、
   哪一环的归因需要什么识别策略
3. ✋ 用三分(生产者/付款者/使用者)分析一个外包或 PPP 案例:
   重构后风险搬家到了谁身上
4. ✋ 用 §五判定流程给你手头一个"智慧治理"方案定位:它真在左端吗?
   若在右端,把"硬造指标"部分改写成"测量+兜底"方案

## 📌 收束 + 🧭 认知升维

本章给你的**新眼睛:可构造之眼**——看到任何公共管理主张,先问:
它是流程(可造)、指标(半造:产出一造一评)、平台(可造)、
还是价值与关系(只可养)?再问它撞上哪条刚性:
多目标不可通约?委托链损耗?三分三角?
分不清两端的改革方案,注定在价值端用流程工具空转。
