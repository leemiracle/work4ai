# 04 · 人力资源转代码:把"人的层"搬进机器

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:本学科的左端(筛选/漏斗/矩阵,03 章谱系)几乎可以无损转码,
> 右端(潜力/契合)几乎不可转码;而左端的明星对象——**算法筛选**——
> 的转码边界不是技术边界,是**数学边界**:公平标准互不相容,
> 代码只能替你把"选了哪种公平"显式化,不能替你选。

---

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",本家族转代码要解决"**测量化**":
把一段人事语言(这个测评能预测绩效)先翻成模型(信号+噪声+效度),
再翻成代码。翻译的损耗全部发生在第一步——所以本章先划清哪些对象
第一步就走得通(绿色区),哪些走不通(红色区),再给四条走通了的走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 本学科概念 | 代码化身 | 备注 |
|------------|---------|------|
| 历史标签筛选器 | 逻辑回归+录取率/准确率/组间差指标 | 本家族实验全流程纯标准库 |
| 胜任力评估 | schema(数据结构)+行为锚评分器 | 走廊 2;评分者信度可同步监控 |
| 人才管道 | 转化率连乘的漏斗计算器 | 走廊 3;继任=容量规划 |
| 人力演化 | 马尔可夫转移矩阵幂 | 走廊 3;断层预测=特征值直觉 |
| 教育回报 | OLS 回归(明瑟方程) | 走廊 4;正主在[../../讲透经济学/讲透劳动经济学/](../../讲透经济学/讲透劳动经济学/) |
| 激励合同 | 委托代理约束求解 | 住[../讲透管理理论/](../讲透管理理论/)家族(其实验可直接复用) |

**转不动/为什么转不动(红色区)**:

1. **"全面公平"的筛选器**:校准公平与统计均等在基础率不同时不可兼得
   (Kleinberg et al. 2016,学术通说)——这是**定理不是工程欠账**:
   多加数据、多调参数都绕不过。工程对策:把公平标准做成**显式配置项**
   (选哪种、谁批的、审计日志在哪),而不是藏在损失函数里。
2. **潜力/文化契合**:构念操作化未完成(02 章)——硬造"潜力参数"只会
   得到自己假设回去的结论。工程对策:退到测量与证据链,不当仿真变量。
3. **标签的自我实现循环**(03 章刚性 1):系统内预测改变被预测者的机会,
   离线评估天然高估自己——工程对策:留出不受干预的对照期/对照组
   (实验设计的思想,仪器在[../讲透管理计量学/](../讲透管理计量学/))。
4. **绩效效标污染**:拟合一个被政治/运气污染的靶子,越准越偏——
   工程对策:效标多路交叉(自评/上级/同级/硬指标),单效标模型不上线。

**边界的一句话**:绿色区=谱系左端,恰好是"信号+方程"覆盖的部分;
红色区的头号成员(公平)不是因为"难"而转不动,而是因为**数学上不存在
同时满足冲突目标的解**——转码的价值恰在于把这一点变成可跑、可演示的
事实(走廊 1 的使命)。

## 二、代码走廊清单(四条走廊,每条=理论→模型→算法→真实系统)

### 走廊 1:招聘公平走廊(本家族实验)

```
公平文献(均等/校准互斥) ──参数化──▶ 两群体同能力+信号偏移μ+代理变量p
      │
      └──三种筛选器对比──▶ 朴素(历史标签) vs 去代理 vs 去代理+阈值校准
```

- **理论→模型**:能力 θ 两组同分布;可见信号 s=θ+噪声−偏移(弱势组读数
  系统性偏低);代理变量 p 与组别强相关、与能力弱相关;历史录用规则
  偏爱高 s 与高 p——历史标签因此携带系统性偏移。
- **算法层**:逻辑回归(纯 math 实现的梯度下降)在历史标签上训练朴素筛选器;
  修正版去掉 p,再按目标录取率做阈值校准;蒙特卡洛评估录取率差与准确率。
- **本家族实现**:[`experiments/hiring_fairness.py`](experiments/hiring_fairness.py)
  ——断言朴素筛选器产生组间录取率差、修正后差异收窄且整体准确率损失有限;
  并演示"校准后的公平标准内部也不免费"(录取的组间合格率差被反向拉开)。
- **真实系统**:简历筛选器的上线前审计;AI 招聘工具的供应商评估问题清单。
- **性能工程要点**:仿真天然可并行(按 seed 分流);评估指标
  (录取率/准确率/组间差)与生成过程解耦,便于换分布做敏感性扫描。

### 走廊 2:胜任力模型走廊(schema→评分器)

```
胜任力理论(冰山/BARS) ──形式化──▶ schema(维度×行为锚×等级)
      │
      └──评分器──▶ 双评分者一致性(信度)监控 ──▶ 晋升/入池决策
```

- **理论→模型**:03 章构造 1 的 schema 落成数据结构;评分规则锚定行为证据,
  输出等级+证据链。
- **算法层**:评分器=加权规则(可解释);一致 性=评分者间 kappa;
  周期性输出"漂移警报"(某评分者系统性偏高/偏低)。
- **真实系统**:晋升材料预审、技术委员会入池、面试结构化平台。
- **要点**:**可解释是硬约束**——黑箱评分在人事场景不可审计;
  schema 的内容效度靠人,代码只保形式与信度。

### 走廊 3:人力管道走廊(漏斗+转移矩阵)

```
人力规划(存量-流量) ──形式化──▶ 漏斗(转化率连乘)+转移矩阵 P
      │
      └──矩阵幂 ──▶ 分层人力分布预测 ──▶ 断层年份/缺口反推
```

- **理论→模型**:03 章构造 2/美之时刻 4;五行职级转移矩阵即可教学
  (晋升/平移/流失概率行随机),分布×P 的 k 次幂= k 年后结构。
- **算法层**:矩阵乘(纯 python 五行足够);扫描流失率/晋升率,
  看断层年份的敏感性曲线。
- **真实系统**:继任计划容量测算、组织老化解诊断、招聘节奏规划。
- **要点**:参数是政策的函数——**改政策必改参数再重跑**,
  拿旧矩阵外推新政策是这类系统第一大误用。

### 走廊 4:教育回报走廊(明瑟方程)

```
人力资本理论 ──参数化──▶ ln(工资)=α+β·S+经验项+ε ──OLS──▶ β=教育回报率
```

- **理论→模型**:00 章美之时刻 1;β 是"看不见的投资"的定价。
- **算法层**:正规方程或梯度下降的 OLS(纯 math);合成数据自验
  (真 β 已知,断言估计量回收)。
- **真实系统**:培训 ROI 测算、薪酬公平审计(同教育同经验下的组别残差)。
- **要点**:相关性装置——能力遗漏偏差(受教育多的人能力也高)是
  明瑟方程的经典内生性;报告 β 必须带这一句免责声明。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:结构化面试=代码评审的 rubric

- 你给候选人出的面试题,就是一次**测量**;把"聊得来"换成本家族 03 章
  schema 的三个等级×两条行为锚,评分者信度立涨(结构化的效度优势,
  工业组织心理学通说)。写不出行为锚的题,先别用来做决策。

### 落点 2:招聘工具的审计问题清单

- 面对一个简历筛选/评测工具,问四件事:训练标签来自谁的历史决定(偏移)?
  公平标准选了哪种、谁批准的(互斥定理下必选边)?效度证据是增量效度
  还是相关表?离线指标在上线后怎么监控(自我实现循环)?
  四问答不出的工具,按 00 章假设表第三行处理:**它复制的是历史,不是未来**。

### 落点 3:团队的管道账

- 把你的团队当管道管:接手时算一遍存量(各层级人数)与流量
  (晋升/流失/招聘速率),用走廊 3 的五行矩阵推两年——
  大多数"突然没人了"的组织,断层在两年前的矩阵幂里就写得清清楚楚。

## 📌 收束 + 🧭 认知升维

本章给你的**新眼睛:审计者之眼**——你身边的每一个人事算法,
都是某个历史过程的产品;它的"客观"是统计意义上的客观,
不是正义意义上的客观。转码的意义不是让机器接管人事,
是让**假设显式化、公平选择显式化、代价显式化**——
这三样显式化之后,人来做的那个决定,才算真正由人负责。
