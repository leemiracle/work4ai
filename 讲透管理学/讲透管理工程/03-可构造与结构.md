# 03 · 可构造与结构:问题、流程与三库怎么造出来

> **本章回答五问之四:哪些对象可构造?结构刚性从哪来?**
> **本质一句话**:管理工程的三大产品——**决策问题 schema、流程模型、
> 三库架构**——全部可构造(有限步骤、可复现地造出来);而它们的结构刚性
> 来自三台引擎:**BOM 递归展开**(制造时间的刚性)、**反馈回路**(动力学的刚性)、
> **Petri 网可达性**(流程逻辑的刚性)。

---

## 开篇:从"画框图"到"造机器"

数学家构造对象,靠公理与定理;管理工程构造对象,靠**装配与对账**:
一道决策题不是"想出来的",是按 schema 装出来的(目标句+约束句+状态句+策略句);
一个流程不是"画出来的",是从事件日志或现场访谈里**对账**出来的;
一套 DSS 不是"买来的",是三个器官分别构造再缝合的。

**为什么"可构造"重要**:只有可构造,管理系统才**可移交、可审计、可持续运转**——
换一批人,系统照跑。这正是"能人治理"与"工程治理"的分界线:
能人离职,经验断电;构造在系统里,组织失忆也能开机。

但"能造出来"不等于"造得对"。本章先盘三大对象的家底,再看三台结构引擎。

## 一、可构造性家底盘点

| 对象 | 构造方式 | 成本 | 暗礁 |
|------|---------|------|------|
| 决策问题 schema | 目标+约束+状态+策略四句类填空 → 数学规划/决策树/仿真模型 | 低(一周成稿) | **约束采集贵**:隐性惯例不上纸面,模型世界与现实世界两套法律(02 章铁律) |
| 流程模型 | 事件日志→流程挖掘(算法);或访谈→BPMN/Petri 网(人工) | 中 | 日志质量(时间戳/案例标识)是地基;人工建模画的是应然,日志挖的是实然 |
| 三库架构 | 数据库(数仓/主数据)+模型库(求解器/算法服务)+对话(BI/前端)分别构造再集成 | 高 | 集成缝是事故带:口径不一致、模型版本漂移、对话层自助化绕过治理 |
| 排产方案 | schema 装上工单/工艺/日历数据 → 求解器 | 中 | NP 难:大规模只能启发式,"最优"降级为"可行+不差" |
| 库存策略 | 需求分布+成本参数 → (s,S)/订至点公式 | 低 | 参数平稳假设:分布一变,策略刻舟求剑(牛鞭的近亲) |
| 数字孪生 | 传感器+机理/数据模型+实时管道 | 很高 | 保真度与维护成本的军备竞赛(00 章 §四开放前沿) |

**决策问题 schema 的构造模板**(本家族的"对象构造器",04 章走廊全是它的填空题):

```
决策变量 x:   本周各产品投产量 x₁..ₓₙ(整数)      [可动的东西]
目标 f(x):    min 换型成本 + 库存持有 + 延期罚金   [往哪优化]
约束 g(x)≤b:  产能≤40h/周;物料齐套;交期窗         [墙在哪]
参数 θ:       加工时间、良率、需求均值/方差         [世界的数据]
策略 π(θ):    每周一滚动重排,冻结期 3 天           [以后怎么动]
```

**反直觉发现(本章铁律):构造易 ≠ 采集易**。
schema 一天填完,喂饱 schema 的数据要爬一年坡——
工时定额谁测的?良率是哪个月的?需求方差按哪个口径?
管理工程的预算大头从来不是建模,是**数据治理**;
这与数学"对象生来完备"相反:本家族的对象生来是空壳,**参数是组织的血肉**。

📖 **结构故事:MRP 的一步天才——给 BOM 加时间轴**。
物料清单(BOM)是树:A 产品由 B、C 组成,B 由 D 组成……
制造业用了几十年的静态配方表。1960 年代 Orlicky 做的事朴素而致命:
**沿这棵树倒排时间**——A 第 10 周要交,B 自制提前 2 周,则 B 第 8 周开工;
D 采购提前 3 周,则 D 第 5 周下单。同一张树,加一根时间轴,
"要造什么"就变成"何时造、何时买"——制造业的中央时间表由此进计算机,
ERP 的全部野心只是把这棵时间树扩张到人、财、设备(本家族 00 章节点 4)。

## 二、结构引擎 1:递归展开(BOM 的刚性)

**直觉图像**:家谱树沿时间倒着走——每往上一层,提前期就往过去推一段。

- **BOM 是严格的部分-整体结构**:树/有向无环图,环=设计错误(自造错误,
  系统直接报"循环引用")。展开=从需求节点沿边做带时间的深度优先遍历,
  每边累加提前期——**刚性来自图结构的无环性**:遍历必终止,展开唯一。
- **低层码**:同一物料出现在树的多个枝上,先归并到最低层再算需求
  ——避免重复计算,MRP 引擎的第一个工程巧思。
- **刚性外溢**:一切"倒排"结构都同构——项目管理里 CPM 的关键路径
  (活动网倒排最早/最晚开工)、排程里的工序倒排、课程先修网的拓扑序,
  全是这台引擎的亲戚。**有向无环+边权=时间**,这个组合一出现,
  本家族的机器就能开动(严格版本在 [运筹学](../../讲透数学/讲透运筹学/)的网络计划一支)。

## 三、结构引擎 2:反馈回路(动力学的刚性)

**直觉图像**:浴缸——水位(存量)由进水与出水(流量)改变;
阀门由水位感知器控制,就是反馈;感知有延迟,就会振荡。

- **存量-流量图**:Forrester 系统动力学的母结构
  (理论上游在[信息科学与系统科学宇宙](../../讲透信息科学与系统科学/README.md)的系统学侧):
  库存、在途、订单积压都是存量;发货、订货、到货都是流量;
  策略是阀门(订至点控制=感知存量偏差调流量)。
- **回路决定行为**:一阶负反馈=寻的与稳定(恒温器);
  **带延迟的负反馈=振荡**(淋浴水忽冷忽热)——牛鞭效应的全部秘密:
  四个"恒温器"串成一条链,每个的感知都延迟 L 周,
  于是终端一次温和脉冲,沿途被逐级放大(本家族实验 Part 1:
  放大倍数 3.8→13.4→44.8→173.1,教科书级的延迟振荡)。
- **刚性来源**:回路的**符号与延迟**是结构属性,不随参与者改变——
  所以 Sterman 的玩家换了一茬又一茬,啤酒游戏的重演一局不落:
  **把理性人放进坏结构,结构赢**。工程的解法因此也只能是结构性的:
  缩短提前期(减小延迟)、信息共享(砍掉一环误感知)、平滑策略(给阀门加阻尼)——
  本家族实验 Part 2/Part 3 分别验证后两条与第一条。

## 四、结构引擎 3:可达性(Petri 网与流程逻辑的刚性)

**直觉图像**:棋盘上的棋子——库所(place)是格子,
变迁(transition)是合法走法,令牌(token)是棋子;
流程=令牌按走法在格间流动。

- **Petri 网是流程的双 inflection**:BPMN 图、工作流引擎、
  流程挖掘的输出格式,内核都是这个1962 年 Petri 发明的结构
  (库所/变迁/令牌的有向二部图)——它让"流程"第一次有了
  **严格的可执行语义**,而不只是墙上的框图。
- **可达性分析=流程的体检**:从初始标识出发,令牌能到达哪些状态?
  **死锁**(两个活动互相等对方的输出)、**活锁**(空转不停)、
  **可达但不该达**(绕过审批的路径)——全部可以在网结构上静态查出。
  工作流引擎的"流程合法性检查"就是这一族算法的产品化。
- **流程挖掘的接口**:事件日志(案例-活动-时间戳三元组)→
  α 算法一族→Petri 网——03 章三大对象在这里扣环:
  **日志造出网,网做可达性体检,体检报告反哺流程再造**(01 章主线 B)。

**三台引擎的咬合**:BOM 展开管"时间从哪来"(无环刚性),
反馈回路管"行为从哪来"(动力学刚性),可达性管"路径合不合法"(逻辑刚性)——
一条产线、一个订单、一套审批流,同时活在三台引擎的管辖里。

## 五、与其他分支的结构联系表

| 引擎/结构 | 本家族形态 | 邻居家的形态 |
|-----------|----------|-------------|
| 递归/展开 | BOM 倒排、低层码、CPM 倒排 | [运筹学](../../讲透数学/讲透运筹学/)的网络计划;编译器的依赖解析 |
| 反馈/延迟 | 存量-流量、订至点控制、牛鞭 | [系统工程方法论](../../讲透信息科学与系统科学/讲透系统工程方法论/README.md)与控制论的回路分析 |
| 可达性 | Petri 网死锁/活锁检测、流程合规 | 自动机理论的可达集;模型检查 |
| 部分-整体 | BOM 树、产品结构 | [讲透集合](../../讲透数学/讲透集合/)的关系与划分 |
| 状态-迁移 | TPS 的状态登记、订单状态机 | 计算机宇宙的数据库事务与并发控制 |
| 三库分离 | DSS 数据-模型-对话 | 软件架构的分层原则(表示/逻辑/存储) |

**一句话**:本家族的每个结构动词(展开/反馈/可达/登记)都是
全宇宙同名动词的**组织投影**——数学给刚性,组织给摩擦与参数,
两样都拿得出手,才算会造管理工程的机器。

## ✍️ 练习

1. ✋ 给你业务里的一个重复决策(补货/排班/分配)填 schema 模板:
   变量/目标/约束/参数/策略五行,标出哪个参数最不可信
2. ✋ 画你部门的流程 Petri 网(简化到 5-8 个活动):找出一个潜在死锁
   (什么情况下两个环节互等)与一条"可达但不该达"的路径
3. ✋ 把你身边一个振荡现象(招聘/补货/扩容)画成存量-流量图:
   存量是什么?阀门策略是什么?延迟在哪?
4. 🐍 改 `experiments/bullwhip_beer_game.py`:给订货策略加阻尼
   (q ← q_prev + 0.5×(q_target − q_prev),平滑订货),看三台引擎里的
   "阀门阻尼"如何压制牛鞭
5. ✋ 手工展开一个两层 BOM:A←(B×2, C×1),B←(D×3),A 提前期 1 周、
   B 2 周、D 采购 3 周:第 10 周交 10 个 A,D 何时下单多少?
