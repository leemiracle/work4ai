# 04 · 管理工程转代码:把模型、流程与镜像装进生产

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角)。

---

## 开篇:本家族的代码不是脚本,是"开机就跑的车间"

理论学科转代码,是把结论翻译成算法;管理工程转代码,是把车间、仓库、
会议室的决策逻辑**部署成常驻系统**——排程引擎每天夜里重排,
补货服务随时计算订至点,流程引擎盯着每张单子的状态迁移,
孪生体与真实产线同步呼吸。本学科的模型如果不跑在生产里,等于没说过。

所以本章的问题不是"能不能转"(几乎全能),而是"**怎么转得可持续**":
参数谁来维护、数据口径谁来治理、模型与现实漂移谁来发现。
**运维与对账**取代算法难度成为主战场。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 管理工程概念 | 代码化身 | 备注 |
|---------|---------|------|
| 决策问题 schema | 求解器接口:变量/目标/约束的声明式建模(数学规划层) | LP/MIP 求解器工业级成熟;启发式兜大规模 |
| BOM 倒排 | 遍历+时间累加的纯函数:explode(bom, demand, lead_time) | 无环图展开,天然可测(03 章引擎 1,走廊 1) |
| 库存策略 | (s,S)/订至点/EOQ 的闭式公式服务 | 参数(μ,σ,K,h)从数据管道自动估计——**参数管道比公式贵十倍** |
| 流程逻辑 | 工作流引擎(Petri 网内核):状态迁移+可达性检查 | 死锁/越权路径静态可查(03 章引擎 3) |
| 流程挖掘 | 事件日志→α 算法族→Petri 网;一致性检验 | 纯算法区,日志质量是唯一命门 |
| 管理仿真 | 离散事件仿真/系统动力学引擎 | 本家族实验即最小样例(走廊 3) |
| 控制图 | ±3σ 判异+EWM A+规则引擎 | 大样本判异规则要调(上游:[数理统计](../../讲透数学/讲透数理统计/)) |

**转不动/只能半转(红色区)**:

1. **约束采集**:隐性惯例(哪些单子惹不起、谁先谁后)在人的脑子里——
   工程能做访谈留痕与例外登记,不能替现场说出没写下的法律(02 章铁律)。
2. **实施变革**:ERP 上线的难点是组织适配,不是软件安装——
   流程再设计、权责重划、数据补录全是人的工程(00 章 §四实施悖论)。
3. **保真度裁决**:孪生模型"像不像"要靠 V&V 与人对账;
   差异报告可以自动生成,"信不信这个模型"要人签字。
4. **自动化边界**:AI 建议给到哪一步、人保留哪些否决权——
   这是治理决策,代码只能执行边界,不能设定边界(01 章主线 C)。

**边界的一句话**:绿色区负责**跑得动**,红色区负责**用得成**——
本家族的失败案例几乎全在红色区:模型对了,组织没接住。

## 二、代码走廊清单(四条走廊,每条=对象→数据结构→算法→真实系统)

### 走廊 1:MRP 倒排(从需求到时间表)

```
主生产计划(MPS) ──▶ BOM 遍历展开(低层码归并) ──▶ 毛需求
   │                                              │
   └──库存/在途/在单扣减 ──▶ 净需求 ──提前期倒排──▶ 计划订单(何时/多少/下单)
```

- **对象→结构**:BOM=邻接表的有向无环图;计划订单=(物料, 周, 量)三元组流。
- **算法层**:深度优先遍历+提前期累加(03 章引擎 1);批量的三种策略
  (按需 lot-for-lot / EOQ / 周期订货)是策略参数,不是算法本体。
- **真实系统**:ERP 的 MRP 模块;APS 高级排程把容量约束加回来。
- **性能工程要点**:展开是纯函数,**极易测试**(给定 BOM 断言展开结果);
  生产级难点在数据齐套(工程日历/替代料/损耗率)而非遍历本身。

### 走廊 2:库存策略服务(从分布到订至点)

```
需求流水 ──▶ 参数估计(μ,σ;分布拟合) ──▶ 订至点 S=μ_{L+1}+z·σ_{L+1}
   │                                          │
   └──成本参数(K,h,p) ──▶ EOQ/批量 ──▶ (s,S) 策略下发 ──▶ 补货执行
```

- **对象→结构**:策略=参数化的决策规则;安全库存=L 期内需求分布的分位数
  (服务水平 = 分布函数值,数学本体:[运筹学·库存论](../../讲透数学/讲透运筹学/))。
- **算法层**:参数估计要滚动窗口+异常清洗;**参数漂移监控**(分布变了要重估)
  是本走廊的灵魂——牛鞭的近亲就是参数刻舟求剑。
- **真实系统**:WMS/补货引擎;VMI 把策略执行搬到供应商侧(信息共享的工程版)。
- **性能工程要点**:订至点计算在批处理侧(延迟宽裕、正确性苛刻);
  库存扣减在交易热路径上(一致性苛刻)——两类 SLO,别混布(同计量学家族之戒)。

### 走廊 3:啤酒游戏仿真(从延迟回路到决策实验)

```
结构假设(链长/提前期/策略参数) ──▶ 仿真引擎(逐期结算) ──▶ 订单轨迹
   │                                                    │
   └──实验设计(MC 重复/公共随机数/参数扫描) ──▶ 方差放大倍数 ──▶ 决策结论
```

- **对象→结构**:供应链=各级(净库存,在途管道,预测)的状态机;
  订单序列是输出统计量(本家族 `experiments/bullwhip_beer_game.py` 全量实现)。
- **算法层**:蒙特卡洛+参数扫描;方差缩减(公共随机数:对照与处理掷同一把骰子)
  是仿真实验设计的入门 Miracle;断言式自验(放大/共享/提前期三断言)。
- **真实系统**:供应链压力测试、孪生体的离线内核(01 章主线 A 的"两班倒")。
- **性能工程要点**:仿真是**吞吐型离线负载**,与热路径无关;
  它的正确性战场在 V&V——对账历史数据、极端工况测试(03 章第四级证书)。

### 走廊 4:流程挖掘(从事件日志到流程体检)

```
事件日志(案例,活动,时间戳) ──▶ 预处理(案例标识/活动名对齐)
   │
   ├──▶ 控制流发现(α 算法族) ──▶ Petri 网/BPMN
   ├──▶ 一致性检验(日志 vs 模型:拟合度) ──▶ 违规路径清单
   └──▶ 性能视角(瓶颈:活动间等待时间) ──▶ 改进清单
```

- **对象→结构**:日志=三元组表;发现结果=Petri 网(03 章引擎 3,可达性体检)。
- **算法层**:次序关系(先后/并发/选择)的统计判定;变体聚类(同一流程的
  几十种走法按频率聚簇)——"应然 vs 实然"的差异表是管理层要看的头号报表。
- **真实系统**:流程挖掘平台与企业 ERP 日志;RPA 用挖掘结果选自动化标的
  (01 章主线 B:"别给烂流程装加速器")。
- **性能工程要点**:日志清洗占八成工时——时间戳精度、案例标识断裂、
  活动命名不一致(主数据问题,不是算法问题)。

## 三、工程师落点(管理工程的产业地图)

| 落点 | 内容 | 为什么是工程问题 |
|------|------|----------------|
| **APS/MES** | 高级排程与制造执行:排产引擎、工序状态、OEE 采集 | NP 难排程的启发式军备竞赛+车间数据的实时采集 |
| **WMS/TMS** | 仓储与运输执行:波次、路径、在途可视化 | 策略服务(走廊 2)的执行现场;物理约束最硬 |
| **BI/指标平台** | 数仓+语义层+看板:DSS 三库的当代组装 | 口径治理是第一事故源(与[管理计量学](../讲透管理计量学/README.md)共享阵地) |
| **工作流/BPM 平台** | 流程引擎+挖掘+RPA 编排 | Petri 网内核+日志反哺;自动化边界的执行点 |
| **孪生平台** | 实时数据管道+机理/数据模型+what-if 服务 | 保真度运维(V&V 常态化)是全新岗位 |

**性能工程的实施观**:管理工程的代码有两条命——
一条在**批处理与离线**(排产/补货/仿真:延迟宽裕、正确性苛刻),
一条在**事务热路径**(状态登记/库存扣减/流程迁移:一致性与延迟双苛刻)。
ERP 实施灾难的常见技术形态,就是把两类负载塞进同一个架构。

## 四、可机械化的检验仪式(把本家族用成瑞士军刀)

遇到任何组织/管理系统,做三问:
1. **schema 问**:它的决策规则写下来了吗?参数谁维护、多久重估?
2. **流程问**:流程网做过可达性体检吗(死锁/越权/变体)?日志能对账吗?
3. **镜像问**:它看得见自己吗——实时状态、真实流程、决策回放?

三问过完,系统的工程骨架就裸露了——剩下的才是真正的难点(约束采集与变革)。

5. ✋ 给你公司的核心系统做三问检验:哪一问现形了最大的工程债?
