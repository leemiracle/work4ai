# 讲透决策支持系统 · 把模型装进决策现场:三库、BI 与决策智能

> **定位句**:这支负责"**支持系统的系统**"——DSS:数据、模型、对话三库的
> 集成工程,从 1971 年的框架矩阵到今天的 BI 平台与决策智能,
> 研究计算机怎么"支持"而非"替代"管理者决策。

## 诞生

- **谁/何时**:1971 年 Gorry & Scott Morton 的经典框架
  (Simon 的结构化谱系 × Anthony 的管理层级矩阵)提出 decision support 的
  分类学——DSS 术语的诞生地;1970s-80s 交互式财务规划系统(IFPS)黄金期;
  1980 年 Sprague 定型**三库架构**(数据库-模型库-对话管理);
  1980s 群体 DSS(GDSS)与执行信息系统(EIS);1990s 数据仓库(Inmon/Kimball)
  +OLAP 把 DSS 的数据腿拉长成 BI;2010s 自助分析与嵌入分析;
  2019 前后"决策智能"(decision intelligence)命名,AI+OR+行为科学合流。
- **因什么问题**:①半结构化决策——模型算一部分、人判一部分,系统怎么切分
  ②模型与数据怎么集成服务(不是两堆零件)③支持与替代的边界
  ④群体与组织场景的支持(会议室里的系统)。

## 核心问题

**已解决**:三库架构作为可分别建造的分解(数据/模型/对话四十年不变);
OLAP 维度建模(上钻下钻切片的立方体思维);what-if/goal-seeking 双向
对话模式(改参数看结果/给结果反求参数);BI 的指标-维度-管道标准栈。

**未解决/深水区**:**"决策不改进悖论"**——经典研究发现:给管理者更多模型
与信息,决策质量未必提升(信息过载/确认偏误/模型沦为会议修辞);
模型在组织里被谁使用、支持谁的立场,是政治问题不是技术问题;
决策智能的自动化边界(AI 建议+人回路怎么设计才不滑向橡皮图章或黑箱两端,
2021-2026 活跃);LLM 作为新对话层的幻觉与可审计红线。

## ✨ 这支最美的一个事实

**三库架构:一刀把"支持决策"切成三个器官**。
Sprague 1980:数据管事实、模型管计算、对话管人——三个子系统
分别建造、分别升级、分别排障。
为什么美:它给了"决策支持"这个模糊愿望一个**可施工的分解**——
此后四十年一切分析平台都是这个三角的转世:数仓+模型服务+BI 界面,
中台+算法平台+前端。诊断任何"BI 建了没用"的组织,
多半是模型库那格是空的——只剩报表,没有支持。
