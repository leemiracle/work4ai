# 04 · 企业管理转代码:把职能机器搬进代码

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:企业管理的可构造谱系(03 章)左端——价值链/BOM/库存/
> 控制图——几乎可以无损转码;文化与关系端几乎不可转码;四条代码走廊把
> "利润池怎么分、料怎么算、货怎么订、过程怎么监控"变成可跑、可断言、
> 可做敏感性扫描的实验。

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",管理理论家族要解决"形式化",本家族的
门槛低得多——它的对象**本来就是数据结构**(02 章:流程/复式/优化三种逻辑
全是算法气质)。真正的门槛在别处:**参数从哪来**(议价能力、需求分布、
目标成本都靠标定)。所以本家族转码的主旋律是"**结构照搬+参数扫描**":
结构是共识,参数是情境,结论看单调性不看绝对值。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 企业管理概念 | 代码化身 | 备注 |
|------------|---------|------|
| 价值链利润池 | 加权图+分配规则+参数扫描 | 本家族实验,全程纯标准库 |
| BOM 展开/MRP 核心 | 树遍历+提前期偏移 | 30 行核心(走廊 3 现码) |
| 库存策略 | EOQ 闭式+(s,S) 仿真/报童模型 | 数学上游:[../../讲透数学/讲透运筹学/](../../讲透数学/讲透运筹学) |
| 统计过程控制 | 控制限+判异规则 | 数学上游:[../../讲透数学/讲透应用统计数学/](../../讲透数学/讲透应用统计数学) |
| 标准成本差异 | 恒等式分解(价差+量差) | 代数恒等,零损耗 |
| KPI 树/杜邦分解 | 分解树+敏感性 | 每个叶子的"动一格,根动多少" |
| 排产优先级规则 | 启发式+滚动重排 | 最优排产 NP 难,工程用启发式 |
| 设备可靠性 | MTBF/MTTR/OEE 计算+更新权衡 | 更新理论入门 |

**转不动(红色区)**:

1. **品牌与质量文化**:没有状态方程——硬造"品牌力参数"只会把自己
   的假设算回去。对策:退到测量(声量/NPS)与叙事,不当仿真变量。
2. **部门政治与信任**:博弈结构可分析([../讲透管理理论/](../讲透管理理论)
   的地盘),不可仿真出真实政治。
3. **需求分布本身**:预测模型输出的是分布假设的函数——牛鞭效应的
   根子在"各环节各自预测",转码治标不治本,治本靠 S&OP 制度。
4. **最佳实践移植**:别家史+互补性咬合(03 章 §五)——代码只能
   造"如果"的世界,不能替你完成组织演化。

**边界一句话**:绿色区=03 章谱系左半段(数据结构端+策略端);
红色区=文化与历史端。**先问构造学,再谈转码**——与管理理论家族同一条铁律。

## 二、代码走廊清单(五条走廊,每条=理论→模型→算法→真实系统)

### 走廊 1:价值链利润池走廊(家族实验)

```
微笑曲线 ──参数化──▶ 环节(b,e,R)+分配规则 ──扫描──▶ 利润池迁移图
                └──蒙特卡洛──▶ 噪声稳健性 ──▶ 战略沙盘
```

- **理论→模型**:环节权重=议价能力×进入壁垒;利润池按权重瓜分;
  利润率=份额×池/营收基数(制造营收大,故摊薄)。
- **本家族实现**:[`experiments/value_chain_wz.py`](experiments/value_chain_wz.py)
  ——断言产能过剩→微笑加深、创新→零和重分配、微笑指数对壁垒严格单调、
  蒙特卡洛与解析一致。
- **真实系统**:自制 vs 外包的价值链定位、渠道直连的利润再分配推演。
- **性能工程要点**:解析解先行(闭式),蒙特卡洛只做稳健性;随机数
  按 seed 分流可复现。

### 走廊 2:库存与补货走廊(EOQ→(s,S))

```
EOQ:Q*=√(2DS/H) ──加提前期+波动──▶ (s,Q) 策略 ──仿真──▶ 服务水平-成本曲线
      └──单期不确定──▶ 报童模型(Cu/(Cu+Co) 分位数)──▶ 定价与备货
```

- **理论→模型**:年需求 D、单次订货成本 S、单位持有成本 H→最优批量;
  有提前期与需求波动→再订货点=提前期需求+安全库存;单期季节品→报童
  临界分位数=欠储成本/(欠储+过剩)。
- **算法层**:闭式+蒙特卡洛服务水平仿真(缺货率/周转率/总成本三指标)。
- **真实系统**:备件库、电商安全库存、**工程师的缓存与批量**
  (见落点 2)。
- **性能工程要点**:服务水平和成本是一对,单指标优化必翻车;
  参数敏感性>点估计。

### 走廊 3:BOM 展开与 MRP 核心走廊(30 行现码)

```
成品需求 ──树遍历(用量×父需求)──▶ 各级毛需求 ──减库存──▶ 净需求
        ──偏移提前期──▶ 计划下单(时间偏移的计划单序列)
```

MRP 的心脏完整实现(教学版,纯标准库):

```python
from collections import namedtuple

Item = namedtuple("Item", "name lead parent qty stock")   # qty=单位父件用量
BOM = [Item("X",   1, None, 1, 10),
       Item("A",   2, "X",  2, 20),    # 1 台 X 用 2 个 A
       Item("B",   1, "X",  1, 5),
       Item("a1",  3, "A",  3, 100),   # 1 个 A 用 3 个 a1
       Item("a2",  1, "A",  1, 40)]

def mrp(root, demand):
    """返回 {零件: (净需求, 计划下单时点)};root 的时点记为 0。"""
    plans, level = {}, [(root, demand, 0)]        # (件名, 毛需求, 需要时点)
    while level:
        nxt = []
        for name, gross, t in level:
            it = next(i for i in BOM if i.name == name)
            net = max(0, gross - it.stock)
            plans[name] = (net, t - it.lead)       # 提前期偏移:早下单
            nxt += [(p.name, net * p.qty, t - it.lead)
                    for p in BOM if p.parent == name]
        level = nxt
    return plans

# mrp("X", 100):A 净需 180、提前 2 期下单;a1 净需 440、提前 5 期……
```

- **真实系统**:ERP 的 MRP 模块(加上批次、替代料、损耗、能力校验
  就是工业版);**软件世界的同构**:依赖清单(构建树)就是 BOM,
  构建时间就是提前期,"领料"就是拉取依赖版本。
- **性能工程要点**:树遍历天然递归→注意深BOM的栈与重复子树(公共
  零件合并=图而非树,工业 MRP 的低阶码排序由此而来)。

### 走廊 4:SPC 控制图走廊(休哈特 3σ)

```
过程数据 ──中心线±3σ──▶ 控制限 ──判异规则──▶ 正常波动 vs 异常原因
        └──失控──▶ 追过程(不追人)──▶ 持续改进(PDCA)
```

- **理论→模型**:只有共同原因时,指标≈正态;越出±3σ 是"异常原因"
  的小概率事件(约千分之二点七)——**这是把假设检验画成车间挂图**。
- **算法层**:滑动均值/极差→控制限→八条判异规则(连续同侧、趋势等)。
- **真实系统**:制造良率监控、**服务的告警设计**(见落点 3)。
- **性能工程要点**:控制限要用"稳态期"数据估计,拿全历史数据算
  σ会把异常也平均进去——与基线选择同理。

### 走廊 5:KPI 树与杜邦走廊(最轻的一条)

- ROE 分解树的每个叶子动 1%,根动多少——一张敏感性表;
- 与价值链走廊联动:某环节壁垒↑→该环节利润率↑→净利率/周转率哪个
  先动?把战略叙事钉到 KPI 树上检查自洽。
- **要点**:算术无难度,难在**防止"各果最优"骗局**(03 章反直觉)。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:你身边就有 BOM

一个服务/一个模型的"物料清单":依赖清单、技能矩阵、提示词组件、
评测集构成——画出来,排期(提前期偏移)、预算(成本卷算)、招聘
(净需求=缺口)读同一棵树。**一树多读是 ERP 的全部魔法,搬进团队
只要一下午。**

### 落点 2:库存思维管缓冲

线程池大小、缓存容量、KV cache 预算、请求队列——全是"库存":
持有可能贬值(内存成本),不持有可能缺货(尾延迟/丢请求)。
EOQ 的平方根权衡(批量摊薄启动成本 vs 持有成本)与
"训练 batch size vs 迭代延迟"是同一道题的两个马甲。
先问:**这个缓冲掩护的是什么问题?能修根因就别加库存**(大野之眼)。

### 落点 3:告警即控制图

阈值告警的两大病:太灵敏(天天响,共同原因当异常)与太迟钝(异常
原因被平均掩盖)。SPC 的答案是**控制限随稳态基线走+判异规则**——
p99 延迟告警该问"这是过程的正常波动,还是分布变了?"
这是 SRE 的 SLI 设计与休哈特 1924 年同一件事:
**追过程,不追人;追分布,不追单点。**

### 落点 4:KPI 的多任务扭曲自查

关闭工单数、代码行数、评测分数——任何单一可测强激励都会把不可测的
努力挤走(评审质量、架构健康、真实用户体验)。设计自己的度量时,
把"哪个不可测任务会被牺牲"写进文档第一行
(机制原理:[../讲透管理理论/](../讲透管理理论) Holmström-Milgrom)。
