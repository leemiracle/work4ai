# 03 · 可构造与结构:哪些企业的东西能"造出来"

> **本章回答五问之四:哪些对象可构造?结构刚性从哪来?**
> **本质一句话**:企业管理的对象沿一条**可构造谱系**排开——
> 数据结构端**严格可构造**(价值链 schema/BOM/职能 KPI 树,写得出、
  算得动、跑得通),文化与关系端**几乎不可构造**(品牌、部门信任、
  供应商关系,只有培育学,没有装配学);而全谱系共享一条结构引擎:
  **互补性**(职能互相咬合,单点改革会被其余部分拉回来)。
>
> 三步法贯穿:**为什么可构造/不可构造 → 它是什么构造 → 亲手构造一次**。

---

## 开篇:一条谱系,两个极端

想象把企业管理的所有对象按"能不能直接造出来"排一条线:

```
价值链schema ── BOM ── KPI树 ── 排产规则 ── 库存策略 ── 部门信任 ── 品牌 ── 质量文化
  │                                                              │
严格可构造(数据结构+算法)                                  几乎不可构造(只有培育学)
  └── 写得出、算得动、ERP 里跑得通                          └── 只能养、只能测,不能装配
```

为什么会有这条谱系?**可构造的前提是"有限描述+确定语义"**(数学家族的
同一条判据在这里复用):BOM 的语义是"父子数量关系",输入输出明确;
"品牌"的语义是用户心智中的联想网络,描述它本身就改变它。
本章盘家底,再看结构引擎。

## 一、构造 1:价值链 schema(把企业写成一张加权图)

**为什么可构造**:价值链的全部要素——环节、流向、利润池——都有
自然的离散结构化身:环节=节点,上下游=有向边,利润分配=权重。

**构造**(本家族实验 [`experiments/value_chain_wz.py`](experiments/value_chain_wz.py)
的骨架):

```
环节(节点): {名称, 议价能力 b, 进入壁垒 e, 营收基数 R}
边(上下游): 有向,沿产品流动(研发→制造→品牌→渠道)
分配规则:   权重 w = b×e;份额 s = w/Σw;利润率 m = s×利润池/R
查询:       微笑指数=两端利润率均值/中段利润率;壁垒扫描=单调性检验
```

**能问的问题**:壁垒参数变一格,利润池迁到哪一环节?谁的创新
(抬 e)最能改写分配?——战略分析变成**可扫参数的桌面实验**。
**暗礁**:b 与 e 的标定靠判断(数据不直接给出"议价能力"),模型的价值
在**单调性与方向**(格局怎么随结构变),不在绝对数值。

## 二、构造 2:BOM 物料清单(一张树统一十个职能)

**为什么可构造**:产品结构天然是树——成品含部件、部件含零件、零件含材料,
每层带用量。**这是本家族可构造性的皇冠**(00 章美之时刻 2)。

**构造**(MRP 的心脏,几十行代码,04 章走廊 3 给全码):

```
BOM(树): 成品 X
          ├── 部件 A ×2
          │     ├── 零件 a1 ×3
          │     └── 零件 a2 ×1
          └── 部件 B ×1
MRP 展开: 独立需求(成品订单) ──乘BOM──▶ 各级相关需求 ──减库存──▶ 净需求
          ──偏移提前期──▶ 计划下单时间
```

**深刻之处**:一个查询("做 100 台 X 要多少 a1?"答案 600)同时回答了
采购(下单量)、生产(领料量)、财务(料成本)、仓管(备货量)四个职能的
问题——**可构造对象自带跨职能协调力**,这是 ERP 能成立的数学原因。
**暗礁**:工程变更(ECN)会让树长得比想象快;替代料/损耗率/版本管理
是 BOM 从教科书走向车间的三道坎。

## 三、构造 3:职能 KPI 树(把战略分解成一棵可核算的树)

**为什么可构造**:利润表本身就是一棵分解树,每个节点可指派到职能。

**构造**(杜邦分析是它的财务版原型):

```
净资产收益率 ROE
 ├── 净利率 ──────────── 成本管理/质量管理(减损)/营销(定价)
 │     ├── 收入(营销:份额×价格)
 │     └── 成本(成本管理:料工费差异)
 ├── 总资产周转率 ─────── 生产(节拍)/物资(库存)/设备(OEE)
 │     ├── 存货周转 ←── 物资管理(EOQ/安全库存)
 │     └── 固定资产周转 ← 设备管理(开动率)
 └── 权益乘数 ────────── 财务管理(资本结构)
```

**深刻之处**:一行等式 ROE=净利率×周转率×杠杆,把十大职能
**全部钉在一棵树上**——每个职能的 KPI 都能向上追溯到同一个根。
**暗礁**(结构刚性,见 §五):树上每个果子都被优化时,树整体可能受害
(压库存储货周转↑→缺货率↑→收入↓):**KPI 树可构造,但"各果最优"
不等于"树最优"**——互补性与互动被树状分解丢掉了。

## 四、谱系中段:规则与策略(半可构造)

- **排产规则**(生产):优先级规则(先到期先做/最紧先做)完全可构造;
  但最优排产是 NP 难(作业车间),工程实践=好启发式+滚动重排,数学上游在
  [../../讲透数学/讲透运筹学/](../../讲透数学/讲透运筹学)。
- **库存策略**(物资):(s,S)/(s,Q) 策略可构造、可仿真;需求分布的
  估计误差是主要暗礁(牛鞭效应:各环节独立预测放大噪声)。
- **维护策略**(设备):事后/预防/预测三档的期望成本权衡可构造
  (更新理论);"预测"档的数据门槛(故障标签稀缺)是现实暗礁。
- **门径流程**(技术):Stage-Gate 的阶段-门结构可构造;
  每道门的判据(继续/终止)只能半形式化(市场判断)。

## 五、结构引擎:互补性——为什么单点改革总失败

谱系上一切可构造物共享同一条刚性来源:**互补性咬合**。
排产规则依赖 BOM 准确,BOM 依赖工程变更纪律,变更纪律依赖考核口径,
考核口径又反过来决定排产者敢不敢说真话——**一环的改进必须与咬合环
配套**,否则被拉回(丰田导入看板用了近二十年,不是技术难,是咬合环
逐个成熟)。这给了"职能制 vs 流程制"母题(00 章)一个结构解释:
它不是偏好之争,是**两套互补集之争**——职能集(深专业+高接口成本)
与流程集(端到端+浅专业)各自内部咬合,跨集混搭最不稳定
(矩阵组织的双重汇报之痛)。

**判定流程**(把一个管理主张钉到谱系上):

```
该主张的机制能写成数据结构或规则吗?
  ├─ 能,且语义确定 ──────────▶ 数据结构端:直接构造+入系统(04 章转码)
  ├─ 能,但参数靠标定 ────────▶ 策略端:构造+参数扫描+敏感性(实验的做法)
  └─ 不能,只有信任与意义 ────▶ 文化端:测量+培育,禁止硬造参数
```

(端点错配是管理软件失败的头号模式:给品牌上 KPI 仪表盘,
给 BOM 开协调会。)

## 反直觉发现(本章铁律)

**KPI 树越精确,越可能骗人**。树的每个果子都可核算、可考核、可优化——
恰恰因此,组织会把努力精确地挪到"被量的果子"上(多任务扭曲),并精确地
利用果子间的**加总缝隙**(压库存涨了周转,缺货损失记在别人账上)。
树没有错,错在忘记树只是分解、不是系统——**分解丢掉的恰恰是互补性**。

## ✨ 美之时刻:一棵树回答四个部门的问题(必然)

MRP 展开"做 100 台 X 需要零件 a1 多少?"——600,一个数字,
采购的下单量、车间的领料量、财务的料成本、仓管的备货量同时落定。
为什么美:**这不是沟通的胜利,是数据结构的胜利**——十个职能的协调,
被压缩成一次对树的遍历(乘法+减法+提前期偏移);ERP 三十年神话的
全部数学,就是这一棵树加上账。亲历:04 章走廊 3 的 30 行代码
亲手展开一次 BOM。

## 📌 收束 + 🧭 认知升维

本章给你的**新眼睛:数据结构之眼**——看到任何管理对象,先问:
它是价值链 schema(图)、BOM(树)、KPI 树(分解树),还是策略(规则+参数)?
还是根本不该构造(信任/品牌/文化)?
以及它咬合着谁——单点改革会不会被互补环拉回?
分不清这些的数字化项目,注定把文化端的问题当成数据结构端的问题白费钱。
