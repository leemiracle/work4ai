# 04 · 可持续管理转代码:把口径、账本与评级搬进机器

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:本家族的可构造谱系左半段(03 章)几乎可以无损转码——
> 碳与物料的账本是守恒律的数据结构;四条代码走廊——**范围三双引擎估算、
> 物料平衡校验、评级分歧度量、披露-实质缺口监测**——把"口径怎么选、
> 账怎么闭、评级怎么读、漂绿怎么抓"分别变成可跑、可断言、可扫描的实验。

---

## 开篇:不是"能不能算",是"账本会不会说谎"

数学宇宙转代码要解决"离散化",本家族转代码要解决"**口径工程**":
把一段披露语言(范围三约 80% 在供应链)先翻成账本结构
(活动数据×因子×边界),再翻成代码。翻译的风险全在第一步——
所以本章先划清哪些对象第一步就走得通(绿色区),再给四条走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 可持续管理概念 | 代码化身 | 备注 |
|--------------|---------|------|
| 碳账户(范围一二三) | 活动数据×因子库(版本化)+分范围分账 | 恒等式结构,E=AD×EF;因子库快照=可复算性 |
| 范围三估算 | 双引擎并跑(活动法/支出法)+区间输出 | 04 章走廊 1 |
| 循环物料流(MFA) | 流量表+守恒断言(输入=输出+累积) | 03 章平衡律的机器版 |
| 披露数据链 | schema 映射管道:原始凭证→指标→GRI/ISSB 表 | 每跳留审计痕迹(append-only) |
| 评级分歧度量 | 多评级面板:两两相关/分位带/三分解模拟 | 本家族实验全程可复现 |
| 披露-实质缺口监测 | 双通道评级差分+时序报警(漂绿雷达) | 输出候选信号,不输出判决 |

**转不动/转不动的边界(红色区)**:

1. **重要性判定的终审**:可自动化初筛(同行词频/风险语料),终判是
   治理过程——硬造打分器只会把治理问题伪装成技术问题。
2. **评级方法学本身**:商业黑箱且无金标准——只能模拟其统计性质
   (分歧/自相关),不可复现其内部。
3. **"真实 ESG 水平"**:不可观测构念(02 章)——机器只能给出
   披露-实质缺口的**下界证据**,把候选名单交给人。
4. **监管对策评估**:涉及具体法域现行政策,超出工程问题范畴,
   本家族红线(00 章治理脚注)。

**边界一句话**:绿色区=03 章谱系左半段+测量学的机器版;红色区=无金标准的
构念裁决——**机器负责让账闭得上、让分歧看得见;裁决权留在治理**。

## 二、代码走廊清单(四条走廊,每条=口径→账本→算法→真实系统)

### 走廊 1:范围三估算走廊(双引擎+区间)

```
价值链活动数据/支出数据 ──×因子库(版本化)──▶ 排放量区间(路径标签)
      │活动法引擎                                 │
      └──支出法引擎 ──────交叉对照───────────────┘
```

- **口径→账本**:范围三=价值链排放,分 15 类(GHG Protocol 上游 8 下游 7);
  账本=(类别,活动数据,因子,路径标签)。
- **算法层**:双引擎各算一遍,输出区间与差值;差值>阈值⟹数据优先级
  (哪些类别值得升级为供应商初级数据)——**区间宽度就是数据投资的 ROI 排序**。
- **真实系统**:企业碳数据平台的范围三模块;CDP 式供应链问卷的校验器。
- **性能工程要点**:因子库版本化(快照不可变,保证历史报告可复算);
  支出数据是天然的高基数表格——按类别物化聚合,因子替换时只重算增量。

### 走廊 2:物料平衡走廊(MFA 守恒校验+循环指标)

```
工序流量表(输入/输出/库存) ──守恒断言──▶ 闭合误差
      │通过                                    │失败
      ▼                                       ▼
   循环率/再生含量指标                   损失率/口径错/数据缺失定位
```

- **口径→账本**:每种物料×每道工序的输入输出库存表;循环率等指标
  全部从表上读出(03 章平衡律:指标必须闭合)。
- **算法层**:断言 Σ输入−Σ输出−Δ库存≈0(容差内);超容差⟹定位最弱工序
  ——**审计的断点调试器**。
- **真实系统**:工厂物料台账/逆向物流回流分拣账(回流质量分级×折损率)。
- **性能工程要点**:流量表=稀疏矩阵;多物料多周期扫描向量化;
  守恒断言写成 unit test 进 CI——物料账与代码同规约。

### 走廊 3:评级分歧度量走廊(本家族实验)

```
企业真实水平(隐藏) ──各机构方法学偏移(权重/口径/非线性)+噪声──▶ 评级面板
      │评级面板
      ├──▶ 两两相关 vs 同机构自相关(分歧结构性:噪声归零仍在)
      ├──▶ 同企业跨机构分位带(排序不稳定)
      └──▶ 漂绿干预:披露信号↑实质不动 ──▶ 缺口可度量
```

- **理论→模型**:真实水平连续值;每家机构=支柱权重+披露/实质通道混合比+
  单调非线性+噪声(03 章:测量/范围/权重三分解的参数化)。
- **本家族实现**:[`experiments/esg_rater_divergence.py`](experiments/esg_rater_divergence.py)
  ——断言①结构性分歧②排序不稳定③披露-实质缺口可度量(对照 Berg 等 2022
  基准事实的数值版)。
- **真实系统**:多评级面板监控(机构间分位带宽度=评级的"误差棒");
  指数编制方的分歧处理规则。
- **性能工程要点**:蒙特卡洛按机构分流 seed(可复现);分位带用排序统计量
  而非参数假设(评级分布有界且有截断)。

### 走廊 4:披露-实质缺口监测走廊(漂绿雷达)

```
披露型评级通道 ─┐
                ├─差分──▶ 缺口时间序列 ──阈值/趋势报警──▶ 候选名单(人审)
实质型评级通道 ─┘
```

- **口径→账本**:双通道评级(或披露指标 vs 物质指标:能耗报告 vs 账单)。
- **算法层**:缺口=披露通道分位−实质通道分位;时序上"披露升实质平"
  的分叉形态触发报警;输出候选信号+置信带,不输出判决(红色区条款)。
- **真实系统**:内部"漂绿雷达"仪表盘:对外承诺指标 vs 内部运营指标的同屏差分。
- **性能工程要点**:两条通道的数据新鲜度不同(披露季度/运营日度)——
  对齐到同一时间粒度再做差分;报警阈值用分位带而非固定值。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:组织碳数据平台——数据工程的正义

- 碳账本本质是**带口径元数据的数据管道**:活动数据接入(电表/差旅/采购)→
  因子匹配→分范围记账→披露表映射。工程师的三件武器:
  因子库版本快照(可复算)、每跳审计痕迹(append-only)、口径元数据
  与数值同存(没有口径的数字不进库——02 章口径之眼的工程版)。
- 性能工程视角:披露周期性报告=批处理;监管化后向"持续对账"演进——
  增量计算与幂等重算的设计要提前埋。

### 落点 2:范围三热图——数据优先级的 ROI

- 用走廊 1 的双引擎差值给 15 类排热图:差值大=不确定性大=数据升级收益大。
  把"我们范围三是多少"的问句改成"哪个类别的区间最值得收窄"——
  这是工程师最擅长回答的排序问题。

### 落点 3:漂绿雷达的自用版——给自己装一个

- 团队/产品同样适用:对外宣称的指标(发布物里的性能/覆盖数)与
  内部实测指标同屏差分,分叉形态报警。**先扫自己,再扫别人**——
  本家族母题的个人版练习。
