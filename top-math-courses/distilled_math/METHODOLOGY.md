## 〇、蒸馏三问（本方法论的骨架）

| 问题 | 回答 | 规律来源 |
|------|------|---------|
| **蒸馏什么？** | 教师模型内隐的数学知识：直觉链、定理网络、反例库、学习路径——不是题解，是"模型看数学的方式" | R7 尾部富矿 + DED |
| **怎么保证对？** | 三层验证阶梯：L1 SymPy/NumPy 断言（机器把关）→ L2 出处核实（不凭记忆）→ L3 Lean 陈述（远程 Prover，增量） | R5 验证器独立于生成器 |
| **怎么进项目？** | 卡片宪法：frontmatter + 置信分层 + 挂网互链（FOREST 域双向锚定） | R3 结构对齐 + 项目孤儿率红线 |

## 一、本地十条规律 → 知识蒸馏的映射

（R 编号沿用 Prover 案例 README §一）

| 规律 | 原语境（证明蒸馏） | 知识蒸馏转译 | 本库落点 |
|------|------------------|-------------|---------|
| **R1 分解降跨度** | 定理→have 骨架→逐 sorry | 域→知识点→原子断言 三级分解；每条断言独立可验 | 卡内 §2 定理网络按"1-3 步可消化"粒度切 |
| **R2/R6 ZPD 策展** | 只收"跳一跳够得着"的题 | 卡片分层：L0 直觉（入门）/ L1 定理网（进阶）/ L2 边界与前沿（研究） | 每卡 §6 ZPD 路径 |
| **R3 结构对齐奖励** | 证明必须包含分解的 have | 模板强制八节结构，缺节=不合格卡 | README 蒸馏宪法 |
| **R4 课程学习** | 子目标是题目生成器 | 卡间显式依赖序（本卡前置=哪张卡） | frontmatter `prereq` 字段 |
| **R5 验证器把关** | Lean 二值判定，零标注 | **SymPy/NumPy 断言脚本**是知识蒸馏的"lean"：跑过才算数；sorry 式断言（`assert True`）必拒 | experiments/dm_*.py |
| **R7 尾部富矿** | 小模型的冷门 tactic | **反例与陷阱是模型知识里最值钱的部分**——教科书不写、模型见过大量用户栽坑 | 每卡 §3 专节 |
| **R8 双模式 prompt** | CoT 复杂 / non-CoT 简单 | 简明陈述模式（定理一句话）+ 深度直觉模式（为什么真）双栏呈现 | 卡内 §2 每条定理双行 |
| **R9 尺寸分工** | 671B 建筑师 + 7B 瓦工 | GLM-5.3 做知识蒸馏（建筑师）；Prover-V2@13节点做形式化锚点（瓦工，L3 增量） | 远程管线挂账 |
| **R10 诚实边界** | 区分已验证/未消融 | **置信分层**：★机器验证 / ☆教师高置信未核 / ⚠争议或简化 | 每条断言前缀 |

## 二、网络最新六法（2025-2026）→ 知识蒸馏的转译

| 方法 | 一句话核心（出处，2026-08-27 检索核实） | 本库转译 |
|------|--------------------------------------|---------|
| **DED**（Data-Efficient Distillation, arXiv:2508.09883） | 0.8k 精选样本达 SOTA——**少而精策展 > 海量堆料**；教师选择不能只看 benchmark 分 | 每域 1 张高密度卡，不追卡数；域选择看 FOREST 缺口队列而非"模型擅长什么" |
| **OPD 统一框架**（On-Policy Distillation survey, arXiv:2604.00626） | 学生在自己的轨迹上接受教师反馈，治 exposure bias | 蒸馏目标锚定**用户/项目的真实缺口**（FOREST 对账），不蒸馏"模型自嗨"的内容 |
| **SIKeD**（ACL 2025 Findings） | 多策略蒸馏 + 学生自选策略，避免单策略偏置 | 每个概念四策略呈现：直觉 / 反例 / 计算 / 形式化——读者按需取用 |
| **VCRD**（Validity-Calibrated, arXiv:2605.04078） | 监督信号按"局部有效性"逐点校准，非整轨迹均匀模仿 | **逐断言验证**而非"整卡可信"：一条 ★ 不能给邻条背书 |
| **DRP**（ACL 2026 Findings） | 技能感知的步骤分解 + 剪枝，token 减 64% 精度反升 | 卡内冗余直觉剪掉，保"技能单位"（能改变行动的知识）；每节必须回答"知道这个能干什么" |
| **Caprese**（PMLR v328, 2026） | ~1% 新参数恢复被高效化损伤的能力——外挂式恢复 | 蒸馏卡定位为**外挂知识层**：不重写既有单元（FOREST/讲透X），只补桥互链 |

> 六法共同指向一个元结论：**蒸馏质量的瓶颈在数据策展与信号校准，不在生成量**。这与本地 R2/R6（ZPD 贯穿全程）完全同构——2025 前后两条独立证据链收敛。

## 三、验证阶梯（R5 的工程化，蒸馏版）

```
L1 机器断言（默认全卡必须）
    SymPy 符号恒等式 / NumPy 数值抽检（随机种子固定）
    脚本: experiments/dm_<域>_check.py，assert 计数 ≥ 8
    铁律: 浮点断言必须带容差；符号断言必须 simplify 后判等
L2 出处核实（定理级）
    教材：写"作者+书名+章节"（不确定写"待核"）
    论文：arXiv ID 一律现场核实（项目铁律：凭记忆错误率 30-50%）
L3 形式化陈述（重点定理增量，远程）
    Prover-V2@13节点 生成 Lean 陈述 → lean421 编译通过 → 卡加 L3 徽章
    （管线复用 remote/ 脚本群 + C1 攻坚的容器 WS lean 环境）
```

## 五、流程（一次完整蒸馏批次）

```
选题（FOREST 缺口 + 用户点名）→ 域卡生成（八节模板）
  → L1 验证脚本生成 + 真跑（不过的断言：修/降级☆/删）
  → L2 出处抽查（arXiv ID 现场 webfetch）
  → 挂网（README 篇目表 + FOREST 域互链 + 至少一条讲透X/top-math 桥）
  → 对账（行数/断链/孤儿检查）→ commit
```

## 六、诚实边界（R10 的自我应用）

- 教师模型的知识有**截止日期**且训练分布偏（竞赛/教材级数学 ≠ 研究前沿）；卡内 §2 的"研究前沿"层必须 L2 核实后才能标 ★。
- L1 断言验证的是**陈述的数值/符号实例**，不是定理本身（有限实例 ≠ 证明）；所以 ★ 的准确含义是"机器抽查通过"，不是"已证明"。定理级确证归 L3 Lean。
- 蒸馏卡的"直觉链"是**模型的直觉**，不是历史上数学家的实际发现路径——两者对照请读 ../MATH_STORIES.md（那条线是思想史还原，与本库互补）。
