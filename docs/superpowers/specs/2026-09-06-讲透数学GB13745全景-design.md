## 5. 内容宪法「讲透本质九要件」(每家族五章固定构件;⑧⑨为用户 2026-09-06 执行中途追加)

| 构件 | 内容 | 主要落章 |
|---|---|---|
| ① 本质一句话 | 章头块:这个分支到底是什么,外行能懂的一句钉住 | 00 |
| ② 怎么产生的 | 驱动它诞生的 2-3 个原生问题 + 关键事件/人物/故事 | 00 |
| ③ 核心问题清单 | 已解决里程碑(带年代人物)+ 悬而未决大问题(带地位:千禧/悬赏/圣杯) | 00,01 |

| ⑤ 与其他的联系 | 谁喂养它/它喂养谁,至少一张联系表(互链兄弟系列) | 00,03 |
| ⑥ 反直觉发现 ≥1 | 讲透铁律(每个定理一个反直觉发现) | 全章 |
| ⑦ 章尾宇宙承接 | 读完这章该去哪个系列 | 全章 |
| ⑧ 美之时刻 ≥3 | 每家族五章合计至少 3 个「✨美之时刻」框,每个=定理/公式/构造的陈述+为什么美(极简/意外/统一/必然之一)+怎么亲历(动手小实验/可视化/自己推一遍的建议) | 分布全家族 |
| ⑨ 认知升维 | 每章尾「这章给了你什么新眼睛」:该分支改变你看问题方式的一至数条思维迁移(如:拓扑眼=看洞不看距离;代数眼=看结构不看个体) | 全章 |

概念呈现三步法(可读性规范强化):每个主要概念/定理=**直觉图像先行**(先给可感知的画面/类比,不许先甩符号)→严格陈述→最小具体例子。其余规范不变:故事化开篇;术语中文优先、首现中英对照;表格优先;📖 故事框穿插;02 章三栏(表达力/逻辑性质/规范化)与 04 章三件套(可机械化边界/代码走廊/工程师落点)每栏答「为什么是这样」。

**支层占位 README(×103,40-60 行/个)**:定位句(这支负责什么问题)→ 诞生(谁、何时、因什么问题开创)→ 核心问题 3-5 条(已解决/未解决)→ **这支最美的一个事实(一句)**→ 假设与依赖 → 教材锚 → 五问章目表📝 → 上下游互链。占位即种子。

体例锚:讲透分析家族五章(结构体例)+ top-math-courses/MATH_STORIES 与 HISTORY_OF_IDEAS(故事化笔法)+ 各已有系列 README(定位句笔法)。
