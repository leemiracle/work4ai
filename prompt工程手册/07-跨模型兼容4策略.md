# 07 · 跨模型兼容的 4 种策略

> **核心问题**：你写了一份 prompt，要在 Claude / GPT / Gemini / Llama 上都跑得好。怎么办？
> **本文是什么**：4 种工程化策略，按 ROI 排序。

---

## 🎯 4 策略速查

| 策略 | ROI | 维护成本 | 适合场景 |
|---|---|---|---|
| **A. 模型特化 prompt** | 最高 | 最高 | 关键生产 / 单一模型 |
| **B. 通用 + 兼容层** | 高 | 中 | **生产推荐** |
| **C. DSPy 自动优化** | 最高（长期）| 低 | 大规模生产 / 未来主流 |
| **D. 推理模型 + 少 prompt** | 中 | 最低 | o1 / R1 / Claude thinking |

---

## 🅰️ 策略 A · 模型特化 prompt

**核心**：每个模型写一份 prompt。Claude 版用 XML，GPT 版用 Markdown。

### 实现
```python
PROMPTS = {
    "claude": """
    <context>You are a code reviewer.</context>
    <code>{code}</code>
    <task>Find bugs.</task>
    """,
    
    "gpt": """
    # Code Reviewer
    
    ## Code
    ```
    {code}
    ```
    
    ## Task
    Find bugs.
    """,
    
    "gemini": """
    Task:
    1. Read the code
    2. Find bugs
    3. Return JSON
    
    Code: {code}
    """,
}

def get_prompt(model_name, **kwargs):
    if "claude" in model_name:
        return PROMPTS["claude"].format(**kwargs)
    elif "gpt" in model_name:
        return PROMPTS["gpt"].format(**kwargs)
    elif "gemini" in model_name:
        return PROMPTS["gemini"].format(**kwargs)
    else:
        return PROMPTS["gpt"].format(**kwargs)  # 默认 markdown
```

### 优点
- **每个模型都最优**
- 可以利用模型专属特性（Claude prefill / GPT JSON mode）

### 缺点
- **维护成本高**（N 个模型 = N 份 prompt）
- 改一处要改 N 处

### 适合场景
- 关键生产（如客服 / 法律 / 医疗）
- 单一模型（只跑 Claude 或只跑 GPT）
- 有充足工程资源

## 🅱️ 策略 B · 通用 prompt + 兼容层（**生产推荐**）

**核心**：写一份"核心 prompt"+ 模型适配器。

### 实现
```python
# 核心 prompt（模型无关）
CORE_PROMPT = """
You are a code reviewer.

Find bugs in the code below.

Return JSON: {"bugs": [{"line": int, "severity": "high|medium|low", "description": str}]}
"""

# 模型适配器
def adapt(prompt: str, model: str) -> dict:
    """Convert core prompt to model-specific request."""
    
    if "claude" in model:
        return {
            "messages": [
                {"role": "user", "content": f"""
                    <instructions>{prompt}</instructions>
                    
                    <code>{code}</code>
                    
                    Return JSON only.
                    """}
            ],
            "model": model,
            "max_tokens": 4096,
        }
    
    elif "gpt" in model:
        return {
            "messages": [
                {"role": "system", "content": prompt},
                {"role": "user", "content": f"Code:\n```\n{code}\n```"},
            ],
            "model": model,
            "response_format": {"type": "json_object"},  # JSON mode
        }
    
    elif "gemini" in model:
        return {
            "contents": f"{prompt}\n\nCode:\n{code}",
            "generation_config": {
                "temperature": 1.0,  # Gemini 必须 1.0
                "response_mime_type": "application/json",
            },
        }
    
    else:  # Llama / Qwen
        return {
            "messages": [
                {"role": "system", "content": prompt + "\nReturn ONLY valid JSON, no other text."},
                {"role": "user", "content": f"Code: {code}"},
            ],
            "model": model,
            "temperature": 0.0,
        }

# 统一调用
def call_model(prompt, code, model):
    request = adapt(prompt, model)
    # 用 LiteLLM 统一接口
    from litellm import completion
    response = completion(**request)
    return parse_json_safely(response.choices[0].message.content)
```

### 优点
- 维护 1 份核心 prompt
- 兼容 N 个模型
- 可独立优化适配器

### 缺点
- 不是每个模型的最优
- 兼容层有维护成本

### 适合场景
- **大多数生产环境（推荐）**
- 中等资源团队
- 多模型备份

### 工具
- **LiteLLM**（`github.com/BerriAI/litellm`）：统一 API
- **OpenRouter**（`openrouter.ai`）：商业统一 API

## 🅲️ 策略 C · DSPy 自动优化（**未来主流**）

**核心**：声明 input/output + metric，让 DSPy GEPA 自动找每个模型的最佳 prompt。

### 实现
```python
import dspy

class CodeReview(dspy.Signature):
    """Find bugs in code."""
    code: str = dspy.InputField()
    bugs: list[dict] = dspy.OutputField()

class Reviewer(dspy.Module):
    def __init__(self):
        self.prog = dspy.Predict(CodeReview)
    def forward(self, code):
        return self.prog(code=code)

# Metric
def bug_metric(gold, pred, trace=None):
    expected = {(b["line"], b["description"]) for b in gold.bugs}
    got = {(b["line"], b["description"]) for b in pred.bugs}
    correct = expected & got
    score = len(correct) / max(len(expected), 1)
    feedback = f"Got {len(got)} bugs, expected {len(expected)}. Correct: {len(correct)}."
    if expected - got:
        feedback += f" Missing: {expected - got}."
    return dspy.Prediction(score=score, feedback=feedback)

# 为每个模型自动优化
def compile_for_model(model_name):
    lm = dspy.LM(model_name)
    dspy.configure(lm=lm)
    
    optimizer = dspy.GEPA(
        metric=bug_metric,
        reflection_lm=dspy.LM("openai/gpt-5"),  # 用强模型反思
        auto="medium",
    )
    
    return optimizer.compile(
        Reviewer(),
        train=trainset,
        val=valset,
    )

# 编译所有模型
compiled_programs = {
    "claude": compile_for_model("anthropic/claude-opus-4"),
    "gpt": compile_for_model("openai/gpt-5"),
    "gemini": compile_for_model("google/gemini-2.5-pro"),
    "llama": compile_for_model("ollama/llama3.3:70b"),
}

# 用时
result = compiled_programs["claude"](code="def foo(): pass")
```

### 优点
- **完全自动**
- 每个模型有自己最优 prompt
- 长期 ROI 最高

### 缺点
- 需要黄金集
- 训练时计算成本
- 黑盒（不知道优化了什么）

### 适合场景
- 大规模生产
- 有黄金集
- 想长期投入

## 🅳 策略 D · 推理模型 + 少 prompt

**核心**：o1 / R1 / Claude thinking 类模型，**少写 prompt，多让它想**。

### 实现
```python
# 老方式（GPT-4 时代）
prompt = """
Step 1: Read the code carefully
Step 2: Identify patterns
Step 3: Find bugs
Step 4: Verify each bug
Step 5: Rank by severity
Step 6: Output JSON

Code: {code}
"""

# 新方式（o1 / R1 / Claude thinking）
prompt = f"""
Find all bugs in this code. Output JSON.

Code: {code}
"""

# 模型自己 thinking，不用你写步骤
response = openai.chat.completions.create(
    model="o1",
    reasoning_effort="high",  # 模型自己想
    messages=[{"role": "user", "content": prompt}]
)
```

### 优点
- prompt 短
- 跨模型一致（推理模型大同小异）
- 利用了模型的 thinking 能力

### 缺点
- **推理模型贵**（o1 / R1 比普通模型贵 5-10 倍）
- 延迟高
- 不是所有任务都需要（简单任务浪费）

### 适合场景
- 复杂推理（数学 / 代码 / 法律）
- 有预算
- 已经用推理模型

## 🎯 策略选型决策树

```
你的需求？
│
├─ 关键生产 + 单一模型
│  └─→ A（模型特化）
│
├─ 多模型备份 + 中等资源
│  └─→ B（通用 + 适配层）⭐ 生产首选
│
├─ 大规模 + 有黄金集 + 长期投入
│  └─→ C（DSPy 自动优化）
│
├─ 复杂推理 + 有预算
│  └─→ D（推理模型 + 少 prompt）
│
└─ 都不像
   └─→ 从 B 开始，按需升级到 A 或 C
```
