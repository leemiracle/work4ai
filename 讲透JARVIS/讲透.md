# 讲透 microsoft/JARVIS —— HuggingGPT 的官方开源本体

> 一句话定位：**JARVIS 是"LLM 当控制器、模型社区当执行器"的开创性系统**——ChatGPT 负责理解、拆解、调度与汇报，HuggingFace 专家模型负责干活。仓库即 NeurIPS 2023 论文 *HuggingGPT*（arXiv:2303.17580）官方代码，附带 TaskBench、EasyTool 两篇后续论文产物。

## 一、仓库鸟瞰

根 README（`README.md:40-44`）给出四阶段定义，三大子目录各司其职：`hugginggpt/` 系统本体（Python 服务端+Vue3 前端+Electron 壳+Gradio 演示+Jetson 镜像）；`taskbench/` 任务自动化基准（arXiv:2311.18760）；`easytool/` 简洁工具指令方法（arXiv:2401.06201）。三线共享同一内核：**把复杂任务拆成 LLM 可控的规划-选择-执行-汇报循环**。

## 二、四阶段管线：awesome_chat.py 精讲

`hugginggpt/server/awesome_chat.py`（1070 行）是全系统心脏：

**Stage 1 任务规划 `parse_task`（`awesome_chat.py:317-348`）**：请求+历史注入 few-shot 模板（demo 来自 `demos/demo_parse_task.json`），LLM 输出 `[{"task","id","dep","args"}]` JSON 数组；36 种任务类型枚举在系统提示词里约束输出空间。两个工程细节：历史裁剪循环（`awesome_chat.py:324-336`）从头部成对丢旧消息直至 token 余量 800；**logit_bias 约束解码**（`awesome_chat.py:343`）把任务关键词 token id 以 0.1 偏置注入（id 集合由 `get_token_ids.py:43-47` 预编码），从解码层压幻觉。

**跨任务资源协议 `<GENERATED>-id`（`awesome_chat.py:268-305`）**：args 写 `<GENERATED>-2` 即"取 2 号任务产出"。`fix_dep` 反向扫占位符补 dep 依赖；`unfold` 把一次引用多产出的任务拆成多个单依赖任务。DAG 调度建立在字符串约定上——简单但脆弱。

**Stage 2 模型选择 `choose_model`（`awesome_chat.py:350-374`）**：候选池来自 `data/p0_models.jsonl`（673 行注册表），启动时在 `awesome_chat.py:145-154` 加载为 MODELS/MODELS_MAP/METADATAS。每任务取前 10 候选（`awesome_chat.py:834`），把模型元数据（描述/点赞/下载量）交 LLM 挑选，输出 `{"id","reason"}`。**失败自动换下一候选重试**是隐藏亮点。

**Stage 3 执行 `run_task`（`awesome_chat.py:720-889`）**：先占位符回填（734-745 行替换为前序产出实际值），再三条路由——ControlNet 系任务（`awesome_chat.py:798`）强制本地 `lllyasviel/sd-controlnet-*`；纯 NLP 任务（`awesome_chat.py:815`）直接回退 ChatGPT 自答；其余走 Stage 2。`model_inference`（`awesome_chat.py:638-660`）按 hosted_on 分发双通道。

**Stage 4 响应生成 `response_results`（`awesome_chat.py:377-398`）**：结果按 id 注入模板，LLM 汇报所用模型与文件路径。

**总控 `chat_huggingface`（`awesome_chat.py:891-976`）**串起四阶段，暴露 `return_planning/return_results` 开关——即 `/tasks` 与 `/results` API 的基础（`awesome_chat.py:1014-1062`，Flask+waitress，8004 端口）。

## 三、双推理通道与调度矩阵

- **远程通道** `huggingface_model_inference`（`awesome_chat.py:400-530`）：131 行巨型分支，按 20+ 任务类型组装输入（NLP 文本/VQA base64 图/TTS 落盘），生成物统一写 `public/` 目录回传相对路径——"文件系统即消息总线"。
- **本地通道** `local_model_inference`（`awesome_chat.py:532-635`）转发给 `models_server.py`：独立 Flask（8005 端口），`load_pipes`（`models_server.py:81-341`）按档位预加载管线，暴露 `/running` `/status/<id>` `/models/<id>`（`models_server.py:350-365`）。**单卡显存管理**是核心：推理后立即 `pipe.to("cpu")+empty_cache()`，用完即逐出换全量模型池。

开合由 config 两键控制：`inference_mode`（`config.default.yaml:15`）×`local_deployment`（16 行）。`config.lite.yaml` 零显存入门；default 是 hybrid+full（磁盘 284GB+）；azure/gradio 各为 Azure 控制器与 HF Space 调优。启动按 local>azure>openai 探测端点并 ping 本地 `/running`（`awesome_chat.py:82-130`）。

提示词六层全配置化：三段系统提示词 tprompt（`config.default.yaml:30`）+三段用户模板 prompt+三个 few-shot demo JSON（`demos_or_presteps`），改 prompt 不动代码。

## 四、前端与交互层

Vue3 前端：入口 `web/src/main.ts`，主界面 `home.vue`（432 行）双模式聊天——默认走 `api/hugginggpt.ts`（POST `/hugginggpt`，**180 秒长超时**应对四阶段耗时），双击设置图标切换纯 ChatGPT 直连（`api/chatgpt.ts` 自带 key）。后端地址硬编码 `web/src/config/index.ts:1`。Gradio 演示（`run_gradio_demo.py:15-34`）用正则从消息抠出图/音/视频 URL。Electron 壳与 Jetson 镜像为部署外围。

## 五、姊妹项目

**TaskBench**：数据生产="图采样→LLM 转写"——`graph_sampler.py`（GraphSampler 8-30 行）按 chain 等模式采 DAG，`data_engine.py:48-223` 用 GPT-4 转写为自然语言指令；评测=`evaluate.py:55-58` scipy 匈牙利算法对齐预测图与金标图节点，再算节点/边 F1 与 Levenshtein。三域数据（dailylifeapis 时序依赖/huggingface/multimedia 资源依赖）即论文三赛道。

**EasyTool**：主张离线精简冗长 API 文档（`data_process.py:29-51`），执行器与 HuggingGPT 同构但走 LangChain。`funcQA.py:514-602` task_execution_mh 是标准多跳编排：choose_tool→task_decompose→task_topology（产出 dep DAG）→逐任务调用→汇总自检；`toolbench_retrieve.py:45-58` 加嵌入检索，应对数千 API 放不进 prompt。

## 六、演进关系与批判

时间线（`README.md:9-27`）：2023.03 论文→07 月推 langchain 轻量版并**宣布重建**→11 月 TaskBench→2024.01 EasyTool。两个事实：**仓库名 JARVIS、核心文件 awesome_chat.py，"HuggingGPT"只是论文名**；07 月后提交全转 TaskBench/EasyTool，四阶段本体处于**研究存档**，重建"near future"从未落地——引用须按 2023 水位校准。

时代局限：LLM 输出靠 `find_json`（`awesome_chat.py:222-228`）截花括号+正则抽取，无结构化护栏；`<GENERATED>-id` 协议无类型校验；logit_bias 是 GPT-3 时代特产，换模型即失效。但架构遗产直通今日：模型注册表+元数据选择=工具检索；失败换候选=router fallback；文件系统传产出=artifact 机制。

## 七、使用建议

1. **精读顺序**：chat_huggingface→run_task→parse_task（四阶段与占位符协议）→`config.default.yaml` 全文→models_server 显存逐出。
2. **最快跑通**：`config.lite.yaml` 零本地模型；但 api-inference 端点与 text-davinci-003 大半已下线，**当历史代码研读比当可运行系统更现实**。
3. **图谱导航**：本仓已建 understand 图谱（188 节点/297 边/15 批，在 `.understand-anything/intermediate/batch-*.json`）。
4. **复现锚点**：四阶段定义见 `README.md:40-44`；硬件需求（VRAM≥24GB、full 磁盘>284GB）在 `hugginggpt/README.md`。
