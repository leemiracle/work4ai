## 一、角色定位：容器内容在三点之间的搬运工

这四个模块是命令面的"数据搬运"一族：`backup` 把容器打成 tar 归档，`restore` 还原归档，`copy` 在宿主与容器间复制移动，`sync` 做 rsync 式镜像——覆盖宿主、容器、归档三点间全部流向。共同底座是 L01 三件套：dirfd 的按描述符寻址（见 02 篇）、paths 的端点解析与钉住、locking 容器锁。锁策略按语义分化成两派：backup 只持共享锁（backup.py:507）——归档不该逼用户关闭运行中的会话，代价是全程必须容忍 guest 并发改树；restore 持排它锁且获取时机后置（restore.py:592）；copy/sync 按端点拿锁——目标侧排它、源侧共享、两端同名则合并为一把，按容器名排序获取以防死锁（paths.py:852，copy.py:72、sync.py:890 消费）。文件头架构注释记录塑造实现的攻击，改前先读是硬习惯：backup 记共享锁下按名两步的换链攻击（backup.py:27-49），restore 记植入容器目录符号链接、让归档解进宿主目录的逃逸（restore.py:39-55）。

## 二、内部结构：四模块分区

**backup.py** 以走树器 `_walk_tree`（backup.py:131-200）为中心：先访问条目自身再下行（backup.py:134-137）——权限遍因此能"边开门边进"chmod-000 目录，而 os.walk 先列表后交付，只能静默跳过封死目录（:145-151 钉版此历史缺陷）。走树用显式栈替代递归（树深是 guest 说了算的），描述符预算靠 Levels 停放浅层（:172-173）。`_each_entry`（:203-232）叠加归档布局：manifest 可选、非规则跳过（:219-226），rootfs 走树时跳过 `.l2s`（:230-232）——link2symlink 后备文件会被内联进引用它的链接，不单独存档。`_add_path`（:264-383）按 lstat 分型入档：设备与管道丢弃、普通符号链接原样保存、l2s 链接解析后备文件按常规文件保存（:299-339）、所有权一律清零（:256-261——还原不能依赖宿主用户号）。

**restore.py** 的脊柱是 `_dest_path`（restore.py:184-243）：把成员名归一为"容器名 + 容器目录下分量"，拒绝 `..` 与空分量（:207-209），识别三种布局——新式、旧式 installed-rootfs 前缀（:215-222）、远古式兼容映射进 rootfs（:240-243）。`_Destinations`（:259-369）算成员落到哪个目录描述符与叶名，缓存一个父描述符（相邻成员几乎同父，:314-327）。四个写入器（:372-438）全走描述符相对调用。

**copy.py** 三层：入口拿锁（copy.py:63-74）、`_do_copy` 做路径预检与语义决策（:242-389）、两个执行体——树复制替代 copytree（:82-180）、移动走 renameat 快路径加跨设备回退（:183-239）。

**sync.py** 最大，核心是状态对象 `_Ctx`（sync.py:89-161）加三个走树遍：计数遍记录相对路径（:506-547）、镜像遍写入（:663-725）、剪枝遍清孤儿（:746-874）。比较逻辑集中在 `_needs_update`（:190-212）：类型与大小必比，校验和模式比 CRC32、否则比整秒时间戳——头注释明言这是"变更检测器而非完整性校验"（sync.py:22-23）。

## 三、外部连接：上游地基与下游围攻

上游：paths 的钉住与容器目录对（pin_path paths.py:771、open_container_pair paths.py:147），dirfd 的复制、建新 inode 与描述符 chmod（copy_tree_at dirfd.py:982、open_new_at dirfd.py:188、chmod_at dirfd.py:478），l2s 的身份判定与后备开启（resolve_l2s_target l2s.py:56、open_l2s_backing l2s.py:116），以及压缩、进度、消息三小件。下游测试是这族命令最好的说明书：test_backup_live_race.py 以确定性手法复现竞态（头注释 ：3-13）：把走树刚拿到的 stat 传进去，抢在消费前把条目换成指向宿主的链接——正是竞态输家的状态。覆盖权限遍不 chmod 换链目标（:55）、归档遍不打包换链目标（:205）、installed 检查后容器目录换链被拒（:312）、运行中段换链不影响已钉描述符（:336）。test_copy_pin_toctou.py 补钉住语义：检测组件换链（:44）、钉住描述符在目录改名后仍有效（:61）、resolve 后换链则 copy/sync 双中止（:159、:190）。

## 四、数据流：三条旅程

**backup 一次运行等于同一棵树走三遍**（backup.py:531-652）：共享锁内先拿容器目录与 rootfs 的双描述符并全程持有（backup.py:517；finally 关闭 :526-528）；第一遍放宽权限（:543），第二遍累计总量驱动进度条（:553-576），第三遍真正写 tar（:622-630）——三遍全走描述符链。

**restore 一个成员**（restore.py:556-711）：流式打开（按已消费压缩字节计进度，:558-561）→ 布局归一 → 首个合法成员定容器名并拿排它锁（:589-606），异名成员当场拒绝（:607-613）→ manifest 缓存在内存（:619-645，按实际读取量而非成员声明设 16MiB 闸，:630）→ rootfs 成员触发提交点：开容器目录、清空旧 rootfs（:663-675）→ 落位并按型分派写入器（:677-711）。

**sync 一次运行也是三遍走树**（sync.py:1062-1081）：计数遍填 `src_rels` 定总量（:1068）→ 镜像遍写入（:1069）→ 带删除标志则剪枝（:1072-1073）→ 最后补根目录元数据（:1077——mode 可能摘掉写位、前两遍都会改 mtime，所以必须收尾做）。文件写入走临时文件加原子改名：`open_new_at` 独占创建（:438），写完 `os.replace` 换入（:447），失败与中断都清理临时文件（:449-460）。

## 五、设计决策：六个机制

**1. backup 的共享锁与"一切描述符化"。** backup 是唯一与 login 并发的写者，每一步都可能被竞争。历史实现里"先 stat 一个名字再 chmod 它""先 lstat 再 open"都是两步两个文件（backup.py:37-43）：guest 在窗口内把条目换成指向宿主的链接，chmod 落在宿主文件上、宿主文件的字节被打进归档。现行实现把容器目录只打开一次——与 installed 检查走同一条 O_NOFOLLOW 走梯（backup.py:27-32、507-517），此后一切以"目录描述符加单名"寻址，每次调用都指向走梯自己打开的 inode。

**2. backup 的 l2s 双调用与 rootfs 钉。** l2s 链接（proot link2symlink 仿真的硬链接）在 backup 里被解析两次：测量遍（backup.py:564-573）解析后备文件取大小计总量，归档遍（:312-319）再次解析取内容入档——两遍都先判定链接身份，再经开后备文件的调用打开它，且都传入命令开头钉下的 rootfs 描述符。注释直言：再解析一次 rootfs 路径就等于解除钉住（:286-289）——解析与读取两步之间，共享锁下的 live 会话可换掉路径组件，后备文件必须穿过钉住的描述符打开。多个链接共享一个后备文件时，归档里成为独立常规文件：guest 侧硬链接语义丢失、内容保全、归档不含指向源 rootfs 的绝对路径（:304-311）。

**3. restore 的竞态处理四件套。** restore 面对另一侧威胁——"归档是陌生人的文件"（restore.py:98）：用户拿到什么就得恢复什么。(a) 锁后置：排它锁在流中首个合法成员出现时才获取（:589-606）；(b) 破坏性提交点后置：清空旧 rootfs 推迟到第一个真正物化的 rootfs 成员（:663-675），纯 manifest、空归档、错文件都留给目标原封不动，硬链接源与不可物化成员先甄别，全不落盘同样不触发清除（:647-662）；(c) manifest 缓存：rootfs 确认成功才落盘（:742-744，经原子替换发布 :541-554）；(d) 终态校验：rootfs 必须是真目录，用描述符上的 lstat 判断而非路径版 isdir（:774-786）——顶替 rootfs 的符号链接会逃出容器，校验失败则整个容器目录删除（:723-734）。与 backup 竞态同族的"解析后、写入前被换"窗口，由 `_Destinations` 的两步法封死：先按 guest 视角做语义解析——跟随归档早前成员带来的链接（rootfs 本来就长这样）、绝对目标重锚到 rootfs、`..` 钳制在内；解析答案再用 O_NOFOLLOW 逐级重走一遍才写（:262-273）——因为按名解析和按名写入是对可能已不同的两棵树的两个动作，解析之后的下一个成员可能正是种链接的那个。锚定基准是 rootfs 而非容器目录（:275-278）：否则归档自带的 `lib -> /usr/lib` 会把成员写到 rootfs 旁边。

**4. sync 的 src_rels 并集：防删除剪掉刚写的文件。** 计数遍与镜像遍看树的时刻不同：两遍之间源里新出现的条目会被镜像遍写下，删除遍若只信第一遍的清单，就会把"清单里没有"的这个文件当孤儿删掉——删的正是自己刚传输的。对策写在 `_Ctx.src_rels` 的注释里（sync.py:99-105）：计数遍填集合、镜像遍继续往里加（镜像每见一个名字就登记，:587），剪枝遍对着两遍的并集判定孤儿（:782）。登记时总量重算而非累加（:130-131），否则只增的计数会跑过自己的总量、进度条倒挂（:126-128 钉版）。

**5. --delete 的三重保险。** 除并集外还有两道：其一，源根不可列举则整体拒绝剪枝（sync.py:1093-1096）——src_rels 为空会使目标里每个条目都像孤儿，剪枝等于清空目标，rsync 在 I/O 错误时禁用删除同理；根级列目录失败时专设标志（:475-483）。其二，豁免集：镜像遍没能写的条目进 skipped_rels（:111），剪枝遍跳过它们（:774-775、860-861）——目标里立着的不是这次传输有权裁决的，删它等于以一次没发生的传输为据删数据；典型场景是源文件换不掉目标目录（:420-424）、源管道从不镜像（:600-607）。另加删除模式下的源目标重叠检查（:947）：源坐在目标里直接拒绝，而非把源当孤儿剪掉。

**6. copy 的 TOCTOU 防护与硬链接一票否决。** copy 的窗口在解析与使用之间：端点解析返回无链接分量的路径，但解析完再用是两步，容器进程可在窗口内把某级目录换成链接、让复制跟出容器（paths.py:777-786）。`pin_path` 的 O_NOFOLLOW 重走一石二鸟：检测换链——组件此刻是链接则抛拒链异常、命令中止（paths.py:724）；钉住已验证物——返回的描述符永远指它打开那刻的目录 inode，目录被改名也追不着（paths.py:707-713）。此后一切操作走钉住描述符加叶名，树内下行逐跳拒链；缺父目录也由同一条走梯顺路创建（copy.py:341-343）——先按路径建目录会穿过解析后植入的链接，目录落到容器外钉住才拒绝（paths.py:836-841）。硬链接一票否决是四模块共同红线：硬链接是同一文件的第二个名字，O_NOFOLLOW 对它无物可拒，guest 把宿主文件链进 rootfs 后无从分辨（dirfd.py:490-499）——backup 权限遍对多链接的不可读文件只警告不动手，链接数由描述符 chmod 从刚打开的 fd 重读而非走梯的旧 stat（backup.py:428-436，注释 :409-414 说明两次读各司其职）；sync 的元数据刷新遇多链接改走临时文件全重写，旧 inode 的另一个名字毫发无损（sync.py:347-353、367-368）；restore 写常规文件一律独占创建新 inode（restore.py:400）；copy 把硬链接复制成独立副本（copy.py:32-34）。

## 六、新人提示

- 评审口径照搬头注释："这个名字在我两次使用之间被换掉会怎样"——新增任何按名打开/chmod/删除都是回归。
- 改 backup 先跑竞态测试：共享锁下每个两步窗口都有确定性复现；新增走树遍历必须先访问后下行（backup.py:134-137），否则权限遍进不了封死目录。
- restore 记住"三个后置"：锁后置、清除后置、manifest 后置——往提交点之前塞任何触碰目标的代码，都会破坏"坏归档零痕迹"契约（restore.py:521-528 是契约原文）。
- sync 的集合语义：src_rels 是两遍并集、skipped_rels 兼"剪枝豁免+退出码非零"双语义（sync.py:106-114）、失败登记幂等（同一条目两遍都撞只计一次，:133-142）——动这三个集合前重读 _Ctx 注释。
- copy 与 sync 的端点语义不同：copy 在移动模式不解引用两端（mv 移链接本身，copy.py:248-249），sync 端点一律跟随、树内链接保全，且以 inside 模式钉根目录本身——根变成链接会被拒而非穿过（sync.py:955-974）；删除标志需要目录源，单文件源大声拒绝（sync.py:934-936）。
- 输出讲究：backup 进度走 stderr 不污染 stdout 归档流（backup.py:25）；展示给用户的名字一律转义——树里的名字是 guest 选的，带控制字符会重绘终端（backup.py:430-431）。
