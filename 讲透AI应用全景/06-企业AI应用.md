# 06 · 企业 AI 应用 — AI 做业务

> 企业 AI 是**最不性感但最赚钱**的方向——不是 Sora 那种震撼 demo，而是把 RAG/Agent 嵌进 CRM/ERP/客服/知识库。本章不讲技术（技术见 [`讲透RAG`](../讲透RAG/) 和 [`讲透Agent`](../讲透Agent/)），讲**技术之外的"最后一公里"**：为什么 80% 的 AI 项目失败、企业落地的真实障碍、ROI 怎么算。
>

## 一、企业 AI 的"80% 失败率"

麦肯锡、Gartner 多年调研：**企业 AI 项目 70-85% 失败**（从未上线 / 上线后废弃）。为什么？

| 失败原因 | 占比 | 本质 |
|---------|------|------|
| 数据问题（脏/孤岛/没标注）| 40% | 技术之外的工程债 |
| 没有真实业务场景（为 AI 而 AI）| 25% | 战略问题 |
| 员工不使用（流程没嵌入）| 20% | 变革管理 |
| ROI 算不平（成本 > 收益）| 10% | 经济问题 |
| 模型不够好 | **<5%** | **模型几乎不是问题** |

> 🎯 **关键洞察**：企业 AI 失败，**几乎从不是因为模型**。失败在数据、业务对齐、组织变革——这些是"最后一公里"。本章就讲这条最后一公里。

## 二、RAG 产品化：从 demo 到生产

### 2.1 RAG 的真实障碍（不讲数学，见 [`讲透RAG`](../讲透RAG/)）

[`讲透RAG`](../讲透RAG/) 讲了 RAG 的检索数学和架构。这里讲**生产化障碍**：

| 障碍 | 表现 | 解法 |
|------|------|------|
| 检索召回不够 | 用户问的找不到相关文档 | 混合检索（向量 + BM25）+ rerank |
| 文档分块错 | 答案被截断 | 语义分块 + 重叠 + 层级索引 |
| 数据时效 | 文档更新了向量没更新 | 增量索引 + 版本管理 |
| 多源异构 | PDF/数据库/Confluence/Slack | 统一 ingestion pipeline |
| 评估难 | 不知道检索准不准 | RAGAS / TruLens 评估框架 |

### 2.2 向量库选型（2024-2026 现状）

| 类型 | 代表 | 适用 |
|------|------|------|
| 专用向量库 | Milvus、Qdrant、Weaviate、Pinecone | 大规模 + 高 QPS |
| 数据库扩展 | pgvector（PostgreSQL）、Elasticsearch | 已有 DB，增量加 |
| 全托管 | Pinecone、Zilliz Cloud | 不想运维 |
| 嵌入式 | Chroma、LanceDB | 原型 / 单机 |

**选型铁律**：先从 pgvector（如果已有 PG）或 Chroma（原型）起步，**别一上来就上 Milvus 集群**——多数企业场景，单机 pgvector 性能就够了。

### 2.3 RAG 的失败模式

- **"看起来对，实际错"**：LLM 编造（hallucinate）即使检索对了
- **"答非所问"**：检索准但 LLM 不照着答 → 需要严格的 prompt 约束
- **"长尾爆炸"**：80% 问答能答，但 20% 长尾答得离谱 → 需要兜底（转人工）

## 三、Agent 落地：从 demo 到生产

### 3.1 Agent 的承诺与现实

- **承诺**：自然语言指令 → 自主完成任务
- **现实**：长任务崩溃、幻觉调用、死循环、成本爆炸

### 3.2 Agent 落地的核心问题

| 问题 | 表现 | 解法 |
|------|------|------|
| 可靠性 | 跑 20 步后崩溃 | 限定范围 + human-in-loop |
| 工具调用错误 | 调错 API / 参数错 | 严格 schema + 工具校验 |
| 可观测性 | 不知道 Agent 在干啥 | LangSmith / Langfuse / Arize Phoenix |
| 成本 | 长任务 token 爆炸 | 上下文压缩 + 缓存 |
| 安全 | Agent 误删数据 | 权限隔离 + 沙箱 + 审计 |

### 3.3 落地 Agent 的"现实主义"原则

1. **窄场景**：不要做"通用 Agent"，做"客服 Agent / 数据分析 Agent"等窄场景
2. **人在循环**：高风险动作（发钱、删数据）必须人确认
3. **可观测优先**：上线前先建监控（每次调用 + token + 成本 + 失败率）
4. **从副驾驶开始**：先做 Copilot，再逐步升 Agent

> 🔑 企业 Agent 不是"让 AI 自主"，而是"**把 AI 的能力嵌入既有业务流程**"。流程改造比 AI 难。

## 四、企业 AI 的"最后一公里"

### 4.1 数据治理（40% 失败原因）

- **数据孤岛**：CRM / ERP / 客服 / 知识库各自为政
- **数据质量**：脏数据 / 缺失 / 不一致
- **数据权限**：谁能看什么数据（合规 + 内部政治）
- **解法**：先做数据治理（data fabric / data mesh），再上 AI

### 4.2 业务对齐（25% 失败原因）

- **"为 AI 而 AI"**：CEO 说"我们要用大模型"，但没场景
- **解法**：从**痛点倒推**——哪个业务环节成本最高、效率最低？AI 能不能帮？

**好的场景特征**：
- 大量重复劳动（客服、文档处理、代码 review）
- 有明确 ground truth（可以评估）
- 容忍一定错误（不像医疗）
- ROI 可量化

### 4.3 组织变革（20% 失败原因）

- 员工**不会用** / **不敢用** / **不想用**
- **解法**：培训 + 激励 + 流程嵌入（让 AI 成为工作流的强制环节）

### 4.4 ROI 算账（10% 失败原因）

企业 AI 的真实成本：
- 模型 API：表面成本（可见）
- **隐藏成本**：prompt 工程、数据治理、运维、评估、合规、组织培训（往往是 API 成本的 3-10 倍）

**ROI 怎么算**：
```
收益 = 节省的人力 + 增长的业务（更难量化）
成本 = API + 工程团队 + 数据治理 + 运维 + 培训
```

多数企业的 ROI 错在**只算 API 成本**，忽略工程/治理/运维——结果预算超支。

## 五、企业 AI 的三种部署形态

| 形态 | 代表 | 适用 |
|------|------|------|
| **API 调用** | GPT-4 / Claude API | 快速起步，数据出公司 |
| **私有部署** | vLLM 部署开源模型（Llama/Qwen）| 数据敏感 / 大规模 |
| **混合** | API + 本地路由（小模型过滤）| 成本优化 |

**2024-2026 趋势**：数据敏感 + 成本压力 → 越来越多企业**自部署开源模型**（Llama-3 / Qwen2.5 / DeepSeek）。这就是 [`讲透公开课/03`](<../讲透公开课/03-AI Infra 源码导读清单.md>) 里 vLLM/SGLang 的企业市场。

## 六、深入：RAG 失败模式 + Agent 落地四模式 + ROI 计算

### 6.1 RAG 的失败模式深挖

[二节](#二rag-产品化从-demo-到生产) 列了 RAG 障碍，这里深挖**失败模式 + 解法**：

**失败 1：检索准但 LLM 幻觉**
- 现象：找到了正确文档，LLM 仍编造
- 根因：LLM 没"严格遵循"检索内容
- 解法：
  - Prompt 强约束："只根据以下文档回答，找不到就说不知道"
  - **citation 强制**：每句话标注来源 chunk
  - **faithfulness 检查**：用另一个 LLM 验证"回答是否支持"

**失败 2：长尾问题答得离谱**
- 现象：高频问题（80%）答得好，长尾（20%）胡说
- 根因：训练数据偏 + 检索召回差
- 解法：
  - **置信度阈值**：模型不确定时转人工
  - **澄清式提问**：让用户补充信息
  - **fallback**：明确说"这个我不熟，建议联系 X"

**失败 3：多跳推理崩**
- 现象：问"哪个部门的预算超 10 万"——要检索多份文档拼接
- 根因：单次检索不够，要多步
- 解法：**Agentic RAG**——让 LLM 自主多轮检索（见 Agent 落地）

### 6.2 Agent 落地的四种模式

不是所有"用 LLM"都是 Agent。按自主性分四档：

| 模式 | 自主性 | 例子 | 适合 |
|------|--------|------|------|
| **Copilot（副驾驶）** | 低 | GitHub Copilot、Notion AI | 增强人，人主导 |
| **Reviewer（审核）** | 中 | Code review bot、合规检查 | AI 检查，人决定 |
| **Autopilot（自动）** | 高 | 客服 Agent、数据处理流水线 | 窄场景 + 容错 |
| **Orchestrator（编排）**| 最高 | Devin、多 Agent 系统 | 复杂任务，仍需监督 |

**落地铁律**：**从 Copilot 起步，验证可行再升 Autopilot**。一上来做 Orchestrator（最复杂）必死——长任务可靠性 < 50%。

### 6.3 ROI 计算实例

**场景**：客服 RAG，每月 10 万次问答，现人工处理，每次 5 美元。

**收益**：
- AI 解决 60%（简单问题）→ 省 6 万次 × $5 = **$30 万/月**
- 剩 40% 仍人工，但 AI 辅助提速 30% → 再省 40% × 30% × $5 × 4万 = $2.4 万/月
- 总收益：**$32.4 万/月 ≈ $390 万/年**

**成本**：
| 项 | 月成本 |
|----|--------|
| API（GPT-4，10万次 × $0.05）| $5000 |
| 工程团队（3 人）| $6 万 |
| 向量库 + 运维 | $5000 |
| 评估 + 监控 + 迭代 | $1 万 |
| **合计** | **$8 万/月 ≈ $96 万/年** |

**ROI = 390 / 96 ≈ 4x**——看起来好。但**隐性成本**（流程改造、培训、合规、组织变革）通常再加 $50-100 万/年——**真实 ROI 可能只有 2x**。

> ⚠️ **企业 AI 的常见错误**：只算 API 成本（$6 万/年）说 ROI 60x，忽略工程/治理（实际 $96 万+/年）。**真实 ROI 通常比预期低 3-5 倍**。

## 七、挑战与开放问题

1. **评估**：企业 AI 没有公开 benchmark，怎么知道"好"？
2. **数据飞轮**：用户反馈怎么变成训练数据
3. **合规**：欧盟 AI Act（2024）按风险分级，企业 AI 合规成本上升
4. **组织适配**：每家企业的流程不同，AI 怎么"定制化"
5. **AI 的"内部政治"**：员工怕被替代，怎么处理

---

## 七、一句话总结

> 🎯 **三句话**：
> 1. 企业 AI 失败率 80%，**几乎从不是因为模型**——失败在数据治理（40%）、业务对齐（25%）、组织变革（20%）。
> 2. RAG / Agent 落地的关键是**评估 + 可观测 + 失败兜底**，不是堆模型能力。
> 3. 趋势：数据敏感 + 成本压力 → 企业自部署开源模型（vLLM/SGLang 部署 Llama/Qwen）。
