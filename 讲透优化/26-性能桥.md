# 26 · 性能优化总纲：从数学到系统的方法论之桥

> **一句话**：数学优化（min f(x)）与性能优化（让系统更快）共享同一套深层结构——约束、瓶颈、局部 vs 全局、可证性——但方法论气质截然相反。本章造桥，桥那头是 [`讲透高性能计算`](../讲透高性能计算/README.md) 的完整大陆。

---

**两个世界各自的男人。** Dantzig 问"什么配置最优"——他建模、求解、得到证书；Brendan Gregg 问"时间都去哪了"——他 profile、火焰图、找到热点。前者从模型出发走向世界，后者从测量出发走向模型。**系统优化师与数学优化师的思维冲突**是每个工程组织的日常：前者嫌后者"不建模就调参"，后者嫌前者"建模忽略真实系统"。本章的立场：两者是同一枚硬币（约束下的改进搜索），但**搜索空间的语法不同**——数学的空间是连续向量，系统的空间是配置组合+代码变体+物理布局的混合体。

---

## 一、同构与差异（一张表看两个宇宙）

| 维度 | 数学优化 | 性能优化 |
|---|---|---|
| 目标 | min f(x)（显式公式） | min 延迟/成本（**目标=真实系统的测量**） |
| 约束 | 写进问题（g≤0） | 物理定律（Amdahl/Roofline/内存墙）+ 预算 + 兼容性 |
| 评估 | 便宜（函数调用） | **贵**（真实运行——甚至生产环境） |
| 梯度 | ∇f 可得/可估 | 不存在——profile 给方向暗示 |
| 最优性证书 | 对偶间隙/KKT | **上界对照**（roofline 距离/手写 kernel gap） |
| 噪声 | SGD 的可控噪声 | 环境/邻居/工具链噪声（方差政治） |
| 局部陷阱 | 鞍点/局部极小 | 局部最优配置（改一处反而全局变差） |
| 停机 | gap<ε | SLO 达成 or 预算耗尽（**满意化**而非最优化） |

**深层同构**：两者都在做"约束下的改进搜索"；都靠结构（凸性/物理定律）免于盲目；都吃噪声的亏；都要证书才可信。**方法论差异的根源只有一条：评估成本的悬殊**（微秒 vs 分钟小时）——这决定了数学可迭代百万次而系统只能迭代千次，于是系统优化必须**把昂贵评估用在刀刃上**（22 章贝叶斯优化的主场）。

## 二、profile-first 律（系统侧的第一公理）

数学优化的"先建模"在系统侧翻转为"**先测量**"——因为系统模型永远不完备（讲透高性能计算 09 章的测量宪法）。三条转化律：

1. **直觉得假设，profile 做判决**：Data Movement Is All You Need 的选题=一次 profiling（反直觉即论文）
2. **每个优化候选过总账**：梯度压缩的通信节省别被别处吃回（MLSys 2022 清算的总账审计）——数学的"目标函数完整性"在系统侧的对应物
3. **报数带证书**：达 roofline 97% 比快 2× 有力（上界对照=对偶间隙的工程化身）

## 三、数学优化解系统问题的三个案例（桥的承重梁）

1. **Checkmate**（MLSys 2020）：显存不够 → tensor 重计算调度形式化为 ILP → 求解器给最优调度。**系统问题→整数规划的教科书翻译**（挂讲透高性能计算 03 章）
2. **Alpa**（MLSys 2022）：并行策略组合爆炸 → 层级化搜索空间+代价模型 → 两级合成。**搜索空间的形式化=Alpa 的全部贡献**（SOAP 血统）
3. **Young-Daly 公式**：checkpoint 间隔的权衡 → √(2CT)闭式解。**约束权衡→解析最优**的最纯样本（08 章）

**反向桥**（系统方法解数学问题）：L-BFGS 的有限内存=缓存思想进优化器；异步 SGD=流水线容忍；Adam=每坐标自适应资源分配。**两个宇宙在互相搬运方法**。

## 附 A：性能优化七步循环（工程万能环，2026-09 增补）

$$\boxed{\text{Observe} \to \text{Model} \to \text{Identify} \to \text{Hypothesize} \to \text{Optimize} \to \text{Measure} \to \text{Learn}}$$

①**Observe**：profile/benchmark/monitor——先看后动；②**Model**：T = T_compute + T_memory + T_comm + T_sync + T_overhead（性能第一公式）；③**Identify**：找 max(T_i)——真正的瓶颈只有一个；④**Hypothesize**：为什么是它？（假设要可证伪）；⑤**Optimize**：x→x'（对应瓶颈层的变换）；⑥**Measure**：T'<T？**必须带误差棒**（讲透高性能计算 09 章宪法）；⑦**Learn**：规律入库（下界意识+可复用变换）。——与"profile-first 三律"同构，但补全了 Model/Hypothesize/Learn 三环（01 章七要素的 Feedback 化身）。

## 附 B：性能优化金字塔（L0-L3）

- **L0 需求优化**：最好的计算 = **不计算**（缓存/记忆化/预计算/近似/早退——应用层 60-65 章的心法源头）
- **L1 算法复杂度**：O(n²)→O(nlogn)，n=10⁶ 时即 1000×——最高杠杆
- **L2 数据结构**：多数"代码慢"实为"数据组织错"（hash/B-tree/heap 的选择）
- **L3 内存访问**：现代 CPU 常 memory-bound——"数据在哪比算什么更重要"（讲透高性能计算 03 章主场）

## 附 C：因果链六层追问

Code →（重复计算?）→ 编译（向量化/内联?）→ 指令（SIMD/FMA?）→ CPU（停顿/依赖?）→ Cache（miss?）→ Memory（带宽饱和?）——**逐层问"时间死在哪层"，而非笼统问"怎么改代码"**。
