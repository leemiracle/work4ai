# 场景手册：十二个实战场景的优化思路与步骤

> **怎么用**：你正面对一个具体问题 → 按特征找到场景 → 照步骤走（每步有锚点章）。步骤设计遵循统一框架（01 章）：诊断（What/Metric/Constraint）→ 建模 → 选法（Search）→ 执行与验证（Execution/Feedback）。

---

## 场景 1：训练不收敛 / 收敛太慢

**特征**：loss 不降、震荡、NaN、或降得比预期慢。
**思路**：先分类病情（发散/平台/震荡三症不同药），再动优化器——多数"优化器问题"其实是数据/初始化/学习率问题。
**步骤**：
1. **看梯度**：打印各层梯度范数——爆炸（>1e3）→梯度裁剪；消失（<1e-7）→初始化/归一化检查
2. **查 loss 曲线形状**：发散→lr÷10 或 warmup；平台→可能鞍点（06 章逃鞍：加噪声/动量）；震荡→lr 减或 batch 增
3. **学习率扫描**：lr 从 1e-5 到 1 等比扫 5 点跑 100 步——找 loss 下降最陡档（别信默认值）
4. **优化器升级**：SGD+momentum→AdamW（17 章）；仍卡→检查数据管线（Plumber 教训：瓶颈常在数据不在模型）
**坑**：NaN 先查 fp16 溢出（loss scaling）和数据里有没有 inf。
**锚**：04/06/16/17 章 + experiments/sgd_lab.py

## 场景 2：超参调优（HPO）

**特征**：n 个旋钮（lr/层数/正则…），每次评估=一次训练（分钟到天）。
**思路**：昂贵黑箱评估→样本经济学（22 章贝叶斯优化）；预算意识→Hyperband 早停。
**步骤**：
1. 定预算（总训练次数）与搜索空间（对数尺度！lr 用 log-uniform）
2. <50 次评估→**贝叶斯优化**（skopt/Optuna TPE）；>200 次→随机搜索+Hyperband
3. 并行可用→异步 BO 或 successive halving
4. 收尾：最优区域局部精搜（信任域思想）
**坑**：搜索空间给错（线性扫 lr）浪费一半预算；把结构超参和数值超参混在一个 BO 里（不同尺度）。
**锚**：22/24 章 + hpc-agent ②

## 场景 3：CPU 程序太慢

**特征**：单机代码跑不动，怀疑"需要优化"。
**思路**：性能金字塔从上往下问（26 章附 B）——L0 不算>L1 换算法>L2 换数据结构>L3 内存；**profile-first 铁律**。
**步骤**：
1. **先测量**：py-spy/perf/gprof 找热点（80/20：通常 20% 代码占 80% 时间）
2. **L0/L1 检查**：结果能缓存吗？算法复杂度能降吗（n²→nlogn 常有 1000×）？
3. **L3 内存**：roofline 判断（02 章）——memory-bound 则改访问模式（行序/分块/SIMD 化），compute-bound 才优化计算
4. 每改一处→**重测+误差棒**（讲透高性能计算 09 章宪法）
**坑**：优化没测量的代码；优化非热点。
**锚**：26 章+讲透高性能计算 02/03/09 + experiments（讲透高性能计算/cache_vectorize.py 的 549× 实测）

## 场景 4：GPU kernel 慢

**特征**：kernel 利用率低（nvidia-smi 或 profiler 显示）。
**思路**：roofline 定位（AI<脊点=memory-bound）→ 对症：搬少数据 vs 榨算力。
**步骤**：
1. 算 kernel 的 AI=FLOPs/Bytes → 与硬件脊点比较（讲透高性能计算 02 章）
2. memory-bound→减搬运：融合（讲透GPU与系统级 FlashAttention 思想）、tile 进 SRAM、重计算换回写
3. compute-bound→降精度（FP16/FP8，讲透高性能计算 07 章）、tensor core 对齐（8 的倍数）
4. 占用率调平（block/warp 配置）；warp divergence 消分支
**坑**：decode 阶段天生 memory-bound（AI≈1）——别试图"算力优化"它，该上 batching/量化。
**锚**：讲透GPU与系统级 06/07 + 讲透高性能计算 02/04/07

## 场景 5：分布式训练通信瓶颈

**特征**：加卡不加速（scaling 差）、GPU 大量时间在等。
**思路**：通信量公式先行（Ring AllReduce 2(N−1)K/N——讲透高性能计算 06 章）→ 三个杠杆：减量/重叠/分层。
**步骤**：
1. 测通信占比（profiler 时间线：compute vs comm）
2. **减量**：梯度压缩（Top-k+误差反馈——42 章）、混精梯度（FP16 通信）
3. **重叠**：梯度分桶+反向传播中异步发（bucket/overlay）
4. **分层**：节点内 NVLink ring→节点间；仍差→梯度累积（少同步次数）
**坑**：overlap 需要参数分桶调优；压缩太狠伤收敛（误差反馈必须开）。
**锚**：讲透高性能计算 06/01 + 41/42 章

## 场景 6：有约束的资源分配/排班/组合决策

**特征**：决策变量离散或混合、约束一堆、要"最优方案"（排产/排班/选址/路径）。
**思路**：先 LP 建模（09 章）→ 看要不要整数 → 选精确/近似路线。
**步骤**：
1. 写成标准形：变量/目标/约束三列表（01 章 5W）
2. 连续且线性→**LP 求解器**（scipy/CVXPY）；有整数变量→MILP（分支定界，Gurobi/CBC）
3. 规模太大 MILP 超时→LP 松弛+舍入（12 章）或启发式+下界证书
4. 输出**对偶/影子价格**做灵敏度（资源变动的影响——03 章经济学）
**坑**：非线性强行线性化的建模误差；忘约束（现实约束常比目标重要）。
**锚**：09/10/11/12 章 + experiments/convex_lab.py 的 LP 对偶验证

## 场景 7：黑箱/仿真优化（工艺参数/AB 测试）

**特征**：目标=真实系统/仿真输出（无梯度、评估贵、可能有噪）。
**思路**：0 阶方法+实验设计（22 章）；噪声场景重复测量入预算。
**步骤**：
1. 定预算（能做多少次实验）与维度（>20 维先降维/分组）
2. 前几个点 Latin 超立方采样 → 剩余预算 **BO**（Optuna/GPflow）；有噪→重复评估或噪 GP
3. 在线/不可重放（AB 测试）→ regret 框架（25 章 EXP3/Thompson）
4. 找到满意区后局部网格精修
**坑**：维度>30 BO 失效；忽略评估噪声把噪声当好信号。
**锚**：22/25 章 + hpc-agent ②

## 场景 8：推理服务延迟/吞吐不达标

**特征**：P99 延迟超标或 GPU 利用率低、成本高。
**思路**：相位分析（prefill 算力型/decode 带宽型——Splitwise 思想）+ 三杠杆：量化/批处理/缓存。
**步骤**：
1. 分相测延迟（TTFT vs TPOT）——不同瓶颈不同药
2. decode 慢→**量化**（W4A8/KV 量化——讲透高性能计算 07 章）+ continuous batching
3. TTFT 慢→prefill 并行度/前缀缓存（系统 prompt 复用——CachedAttention）
4. 成本角度→PD 分离判据（Beyond the Buzz：什么负载值得分）
**坑**：量化精度损失测部署态不只测 benchmark（SysNoise 教训）。
**锚**：讲透高性能计算 C02 簇 + 应用层 60/63 章

## 场景 9：缓存/存储优化

**特征**：DB 压力大、读多写少、命中率低。
**思路**：多级缓存架构+三害防护（应用层 63 章）；命中率的数学（MRC/工作集）。
**步骤**：
1. 量化：命中率/穿透率/DB QPS 基线
2. 分级：本地（Caffeine）→分布式（Redis）→DB；TTL=基础+随机（防雪崩）
3. 热点 Key→互斥重建+SWR（防击穿）；不存在 Key→布隆前置（防穿透）
4. 效果验证：DB QPS 下降+P99 不劣化（误差棒！）
**坑**：缓存一致性（先更新 DB 再失效缓存）；大 Key 拖垮序列化。
**锚**：应用层 63 章 + 62 章 IO

## 场景 10：多目标取舍（速度/成本/能耗/精度）

**特征**："既要快又要省"——目标冲突，没有单一最优。
**思路**：Pareto 前沿思维（51' 章）——不做单点决策，画前沿给决策者选。
**步骤**：
1. 明确各目标的量纲与约束（精度≥95% 是约束不是目标！）
2. 扫权重/扫配置生成前沿点（量化档×batch×并行度的网格）
3. 画 Pareto 前沿→找 knee point（边际收益骤降点——通常性价比最优）
4. 报告带不确定性（每点 n 次重复）
**坑**：把约束当目标优化（浪费搜索）；Pareto 点太少画不出前沿。
**锚**：51'/50' 章 + 26 章（性能-成本天然双目标）

## 场景 11：在线决策（不可重放/未来未知）

**特征**：每次决策影响后续（推荐/调度/竞价），没有"重新来过"。
**思路**：regret 框架（25 章）——不比最优，比"平均比最优差多少"；探索-利用平衡。
**步骤**：
1. 建模为在线问题：每轮选动作→观察损失→总 regret 目标
2. 有反馈结构→bandit（UCB/Thompson）；有状态→在线梯度/MDP
3. 冷启动→先验/随机探索期；非平稳→滑动窗口/衰减
4. 上线后持续监控 regret 代理指标（CTR/延迟 vs 历史最优）
**坑**：离线评估在线策略（分布偏移）；忽略非平稳（用户行为漂移）。
**锚**：25 章 + hpc-agent ② win/trap

## 场景 12：需要鲁棒性（噪声/对抗/分布漂移）

**特征**：参数不确定、数据有噪、或有人恶意扰动。
**思路**：鲁棒优化（30' 章）——最坏情况思维 vs 平均思维的抉择。
**步骤**：
1. 定不确定集（参数波动范围/扰动球半径 ε）
2. **随机噪声**→期望优化（SGD 的噪声处理够用）；**有界不确定**→min-max 鲁棒对应；**对抗**→对抗训练（53' 章：内层最大扰动+外层最小损失）
3. 检查鲁棒-性能权衡曲线（鲁棒没有免费的精度）
4. 分布漂移→持续监控+触发再训练（讲透Loop 遗忘地板）
**坑**：鲁棒集给太大（解过度保守无实用）；对抗训练伤干净精度是已知代价要量化。
**锚**：30'/53'/31' 章 + 16 章噪声政治学
