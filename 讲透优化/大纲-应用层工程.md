# 应用层工程 · 大纲部（60-65 六篇）

> 应用层优化的本质：**在业务逻辑、数据流转和用户感知之间做精密的资源调度与策略设计**。机械细节不是芯片指令，而是架构模式、框架参数、数据结构与交互协议的排列组合。三组心法贯穿全部：**空间换时间**（缓存/预计算）、**时间换空间**（压缩/批聚合）、**一致性换可用性**（最终一致/异步削峰）。

## 60 并发与异步模型 🟡
①压榨 CPU 核的第一战场——多线程不是万能药，模型选错全盘皆输。
②**线程池反直觉配置**：CPU 密集型 `N_cores+1`（页错误余量）；IO 密集型 `N_cores×(1+阻塞系数/计算系数)`；Java `ThreadPoolExecutor` 的核心/最大线程×**有界队列**联动陷阱（队列过大→max 形同虚设；过小+拒绝策略不当→雪崩）。**事件驱动**：NIO+EventLoop（epoll/kqueue 单线程监听）——铁律"EventLoop 业务逻辑绝不阻塞"（卡死全 IO），耗时操作必须甩给业务线程池。**协程**：M:N 用户态调度，切换只存几个寄存器+几百字节栈（vs 线程内核态 1-2μs 完整上下文）——多下游 RPC 并发 await 把串行等待压成最慢 RTT。
③→32 马尔可夫链（讲透图：状态机建模线程池）/ 讲透高性能计算 09（测量这些机制的 profiling 面）。
④补全位：线程池三配置（对/过大/过小）的延迟-吞吐曲线实测；协程 vs 线程切换开销微基准。

## 61 内存生命周期 🟡
①内存管理决定**尾延迟**（tail latency）——GC 毛刺是 P99 杀手。
②**对象池化**：连接池大小公式（HikariCP 经验 `CPU×2+磁盘数`——过大反而上下文切换+连接风暴）；DirectBuffer 池化减 Young GC。**零拷贝**：传统 read+write 内核/用户态 4 次拷贝 → `transferTo/sendfile` 由 DMA 直接 PageCache→网卡（吞吐 +50%，CPU 只递描述符）。**GC 退避**：ZGC/Shenandoah <10ms 暂停；禁 `System.gc()`；MMAP 场景 `mlock` 锁物理内存防 swap 换出。
③→03 内存层级（讲透高性能计算：金字塔原理的应用版）/ 62 IO。
④补全位：sendfile vs 传统拷贝的 strace 对照；mlock 前后 P99 对比。

## 62 IO 与序列化博弈 🟡
①网络传输的带宽利用率=协议与批量策略的乘积。
②**批量阈值**：Kafka `batch.size`(16KB) × `linger.ms`(5ms)——**时间换带宽**（小包合并减 TCP/IP 头占比）；linger 过长=人为延迟——延迟-吞吐最经典权衡。**序列化速度差**：JSON 反射建树（Jackson）vs **Protobuf** TLV 编码+Varint 变长整数（快 5×/体积 1/3）vs **FlatBuffers** 零拷贝解析（不反序列化直接访问——游戏属性同步）。**压缩分级**：Snappy（快，比 1.5-2×）/ Zstd（1-22 级可调）——按 CPU 闲置率动态选级。
③→42 通信压缩（讲透高性能计算 06：分布式侧同门）/ 07 ADMM（批量=通信频率的优化学亲缘）。
④补全位：三序列化编解码延迟-体积散点；linger 扫参曲线。

## 63 多级缓存架构 🟡
①缓存是万金油也是潘多拉——命中率每 1% 都是钱，三防做错就是事故。
②**三级穿透防护**：Caffeine（本地，ms）→ Redis（远程，百 μs）→ DB；本地缓存用 Weigher 权重淘汰防堆溢出。**三害微观**：雪崩（大批 Key 同刻失效→**基础 TTL+random(0,600)s 打散**）；击穿（热 Key 重建→**互斥锁**：单线程回填，他人等或拿旧值——Stale-While-Revalidate 策略）；穿透（不存在的 Key 恶意攻击→**布隆过滤器**前置过滤 99% 无效查询）。
③→05 图算法（讲透图：Bloom 的哈希图本质）/ 22 无梯度（缓存参数=黑箱调优现场）。
④补全位：三害的最小复现实验（并发打穿透 Key 观察 DB QPS 暴涨→加布隆后归零）。

## 64 短路与降级 🟡
①最好的优化是"不做无用功"——请求越早死，系统越健康。
②**Fail-Fast**：入口参数验签/格式校验（订单 ID 非 UUID 直接 400——0.1ms 拦截避免 DB 连接+序列化全链浪费）。**熔断器状态机**（closed→open→half-open：错误率 >50% 打开，直接返回降级 Fallback，half-open 探活恢复）。**限流三器**：令牌桶（Guava——允许突发 Burst）/滑动窗口（Sentinel 多 Bucket——精度高内存多）/漏桶（强制平滑——保护 DB）。**预计算**：低峰期（凌晨 2-4 点）定时算 Top-N 入缓存——O(nlogn)→O(1)。
③→31 状态机（讲透图：熔断器正是三态 DFA）/ 25 在线优化（限流=在线资源博弈）。
④补全位：三限流器对突发流量的响应曲线对比；熔断状态机转移实验。

## 65 自适应自治 🟡
①静态配置的死刑——现代应用按运行时指标动态调策略。
②**动态线程池**：CPU>80% 降 IO 并发防切换风暴，空闲时升并发清积压。**执行计划干预**：SQL Hint（`WITH(INDEX)` 强制索引/`MAX_EXECUTION_TIME` 杀慢查询——一条坏 SQL 不许拖垮实例）。**优雅降级**：大促自动关非核心（"猜你喜欢"个性化→热门列表）释放 50% 算力给交易链路。
③→48 学习型系统（规则自适应→学习自适应的进阶）/ ALPS（ATC24——学习式 OS 调度的生产实证）。
④补全位：双阈值（CPU/队列深度）迟滞控制的动态池仿真。

## 💡 应用层心法（收束）
1. **空间换时间**：缓存、预计算——最立竿见影
2. **时间换空间**：压缩、批量聚合——带宽瓶颈时
3. **一致性换可用性**：最终一致、异步削峰——CAP 约束下的极致性能必经之路
> 顶级的优化不是堆技术而是**深入理解业务用例**："读多写少"提缓存命中率、"最终一致"削峰填谷，胜过把循环快几纳秒——**算法与架构，永远大于微小指令调优**（与讲透高性能计算 02/03 章同一灵魂）。
