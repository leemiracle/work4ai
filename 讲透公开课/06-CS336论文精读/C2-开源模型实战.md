> 把理论变成可用模型的关键工程报告——LLaMA/Mistral/DeepSeek 等怎么炼成。

## C2.1. PaLM (2022) ⭐⭐⭐

- **链接**：[arxiv.org/abs/2204.02311](https://arxiv.org/pdf/2204.02311.pdf) · Google

**核心**：540B 参数。**确立了现代 LLM 的工程配方**：
- **SwiGLU**（B6）+ **RoPE**（B7）+ **并行 attention/FFN**（GPT-J 式）
- **Multi-Query Attention**（MQA，GQA 前身）
- **去 bias**、**RMSNorm** 思想
- 6144 TPUv4，**46.2% MFU**（首次大规模报告 MFU）

**💡 工程经验**：
1. **🔴 PaLM 配方 = 现代 LLM 的工程圣经**——后续 LLaMA/Mistral/Qwen 几乎照抄。CS336 A1 实现的正是这套配方。
2. **提出 MFU 概念**——PaLM 论文首次系统定义"Model FLOPs Utilization"，成为训练效率的标准度量（见 [F 类](./F-分布式训练.md)）。
3. 用 **Adafactor**（不是 AdamW）省显存——大模型工程妥协的范例。

---

## C2.2. GPT-NeoX-20B (2022) ⭐

- **链接**：[arxiv.org/abs/2204.06745](https://arxiv.org/pdf/2204.06745.pdf) · EleutherAI

**核心**：20B，用 The Pile 训练。RoPE + 并行 attention/FFN（吞吐 +15%）。12×8 A100。

**💡 经验**：早期开源大模型代表，验证了 PaLM 配方在 A100 集群上的可行性。其训练框架 **GPT-NeoX** 被广泛复用。

---

## C2.3. OPT-175B (2022) ⭐⭐

- **链接**：[arxiv.org/abs/2205.01068](https://arxiv.org/pdf/2205.01068.pdf) · Meta

**核心**：复刻 GPT-3 (175B) 的**完全开源**尝试。The Pile + Reddit，去重。992×A100 80GB 训 2 个月。

**💡 工程经验**：
1. **诚实的失败报告**——OPT 详细记录了**大量硬件故障**（GPU 烧、网络断），这是大模型训练的真实痛点，论文常美化。
2. 用 **FSDP + Megatron-LM + fp16 loss scaling**——混合精度的早期实践。
3. OPT 质量略逊 GPT-3，但**开源**让社区能研究——催生了后续改进。教训：**复刻闭源模型比想象难**。

---

## C2.4. BLOOM (2022) ⭐

- **链接**：[arxiv.org/abs/2211.05100](https://arxiv.org/abs/2211.05100) · BigScience

**核心**：176B，多语言（ROOTS 数据集，59 种语言）。48×8 A100 在 Jean Zay 超算训 3.5 个月。ZeRO-1。

**💡 经验**：**众包科研**的实验——1160 人协作。证明大模型不一定要大公司，但**多语言训练效率低**（低资源语言稀释数据）。

---

## C2.5. LLaMA-1 (2023) ⭐⭐⭐

- **链接**：[arxiv.org/abs/2302.13971](https://arxiv.org/pdf/2302.13971.pdf) · Meta

**核心**：**开源革命的开端**。7B/13B/33B/65B，**只用公开数据**（CommonCrawl/C4/GitHub/Wikipedia/Books/ArXiv/StackExchange），配方为 RedPajama 复刻。**优化推理效率**（7B 为主打）。2048×A100 80GB 训 21 天。

**关键架构**（定型现代开源 LLM）：**pre-norm + RMSNorm + SwiGLU + RoPE**。

**💡 工程经验**：
1. **🔴 "开源 + 小而精"策略颠覆业界**——LLaMA-1 7B 用 1T tokens（略超 Chinchilla 最优 20×7B=140B），在同等推理成本下质量超 GPT-3 175B。
2. **数据配方透明**——LLaMA 公开数据来源比例（CC 67%, C4 15%, GitHub 4.5%, Wikipedia 4.5%, Books 4.5%, ArXiv 2.5%, StackExchange 2%），被 RedPajama 等复刻。
3. **CS336 A1 实现的就是 LLaMA 架构**——RMSNorm/SwiGLU/RoPE 全是 LLaMA 配方。
4. **推理优先**的教训：训练成本是一次性的，推理成本是持续的。所以宁可过训练小模型（呼应 Overtrained Scaling Laws）。

**📍 CS336 角色**：贯穿全课的架构参照。

## C2.6. LLaMA-2 (2023) ⭐⭐⭐

- **链接**：[arxiv.org/abs/2307.09288](https://arxiv.org/pdf/2307.09288.pdf) · Meta

**核心**：**2T tokens**，7B/13B/70B。70B 用 **GQA**（8 KV head / 64 query head）。带 **chat 版本**（RLHF 对齐）。商用许可（LLaMA-1 仅研究用）。

**💡 工程经验**：
1. **GQA 工业化**——LLaMA-2-70B 是首批大规模采用 GQA 的开源模型，证明推理加速有效。
2. **RLHF 对齐的开源范本**——LLaMA-2-Chat 用 SFT + RLHF（两轮），详细公开了偏好数据收集流程。
3. **商用许可是关键**——让企业敢用，催生整个开源 LLM 生态（至今 LLaMA 是最广泛部署的开源模型族）。

---

## C2.7. LLaMA-3 (2024) ⭐⭐⭐

- **链接**：[arxiv.org/abs/2407.21783](https://arxiv.org/abs/2407.21783) · Meta

**核心**：**15T tokens**（LLaMA-2 的 7.5 倍），8B/70B/405B。词表扩到 **128256**（为多语言）。8B/70B 用 GQA。

**💡 工程经验**：
1. **🔴 "过训练"策略的工业巅峰**——LLaMA-3 8B 训 15T tokens，$D/N \approx 1875$（Chinchilla 最优的 90 倍）。目的是让 8B 部署成本极低但能力接近 70B。
2. **15T 数据的工程奇迹**——Meta 公开说数据 pipeline 是 LLaMA-3 质量的核心，但**没公开数据细节**（这是回归闭源的信号）。
3. **405B 训练成本**——16384 H100，54 天，估计 $>6500$ 万美元。这是单一最大开源模型训练投入。
4. **处理 loss spike** 的工程细节（LLaMA-3 报告 §3）是大模型训练的实战手册。

## C2.8. Mistral 7B (2023) ⭐⭐⭐

- **链接**：[arxiv.org/abs/2310.06825](https://arxiv.org/pdf/2310.06825.pdf) · Mistral AI

**核心**：7B，**GQA + 滑动窗口 attention (SWA)**。以 7B 之躯打平 LLaMA-2 13B。

**💡 工程经验**：
1. **SWA 的工业验证**——滑动窗口 attention（Longformer B4 的简化）在 7B 上既快又好。
2. **"小而强"路线的代表**——Mistral 证明精心设计架构能让小模型超远超参数量的大模型。
3. 推理快（GQA+SWA），成为 2023-2024 部署最广的开源 7B 之一。

## C2.9. Mixtral 8x7B (2024) ⭐⭐

- **链接**：[arxiv.org/abs/2401.04088](https://arxiv.org/pdf/2401.04088.pdf) · Mistral

**核心**：**稀疏 MoE**——8 个专家，每个 token 选 top-2。总参数 47B，激活参数 ~13B。性能匹敌 LLaMA-2 70B 但推理只花 ~13B 的算力。

**💡 工程经验**：MoE 的开源里程碑——证明 MoE 在开源社区可行。但**显存占用大**（所有专家驻留），小 batch 推理不划算。

## C2.10. DeepSeek-67B (2024) ⭐⭐

- **链接**：[arxiv.org/abs/2401.02954](https://arxiv.org/pdf/2401.02954.pdf) · DeepSeek

**核心**：67B，2T tokens。架构类 LLaMA 但**加深**（更多层）+ GQA。**自研 scaling law**：用 non-embedding FLOPs + IsoFLOP 方法（Chinchilla 思路改进）。

**💡 经验**：DeepSeek 系列的开场，展示中国团队的工程实力。其 scaling law 实验方法被后续报告借鉴。

## C2.11. DeepSeek-V2 (2024, MLA) ⭐⭐⭐

详见 [B15 MLA](./B-Transformer架构.md#b15)。**MLA + MoE** 让 DeepSeek-V2 推理极快、质量匹敌 LLaMA-3 70B 但算力只 1/5。

## C2.12. DeepSeek-V3 (2024) ⭐⭐⭐

- **链接**：[arxiv.org/abs/2412.19437](https://arxiv.org/pdf/2412.19437.pdf)

**核心**：671B 总参数（37B 激活）的 MoE。MLA + 细粒度专家 + **Multi-Token Prediction (MTP)**。14.8T tokens。2048×H800，**57% MFU**（超越 Megascale）。

**💡 工程经验**：
1. **MoE + MLA 的极致效率**——37B 激活参数做到稠密 70B 的质量，推理成本极低。
2. **FP8 训练**——大规模 FP8 训练的成功案例（省一半显存/带宽）。
3. **Auxiliary-loss-free 路由**（[B18](./B-Transformer架构.md#b18)）——解决 MoE 路由负载均衡的 aux loss 干扰主 loss 的问题。

## C2.13. OLMo-7B (2024) ⭐⭐

- **链接**：[arxiv.org/abs/2402.00838](https://arxiv.org/pdf/2402.00838.pdf) · AI2

**核心**：**全开源**——模型权重 + Dolma 数据 + 训练代码 + 训练日志全公开。无 bias、非参数 LayerNorm、SwiGLU（隐藏维取 8/3d 向最近的 128 倍数取整）。AMD MI250X + A100。

**💡 工程经验**：
1. **"科学可复现" 的旗帜**——OLMo 是第一个**真正全开源**的大模型（连数据都开源），服务于学术研究。
2. **隐藏维对齐 128**——为 GPU Tensor Core 效率，FFN 隐藏维取 128 的倍数。这种细节是大模型工程的"隐藏税"。

## C2.19. Multi-Token Prediction / MTP (2024) ⭐⭐

- **链接**：[arxiv.org/abs/2404.19737](https://arxiv.org/abs/2404.19737)

**核心**：传统 LM 一次预测 1 个 token；MTP 让模型**一次预测多个未来 token**（如 4 个）。训练信号更密集，提升数据效率。可用于**推理时 speculative decoding**。

**💡 工程经验**：DeepSeek-V3 采用 MTP。它让训练效率提升（更多监督信号），且推理时可做 draft 模型加速（speculative decoding）。

## C2 总结：开源模型配方的收敛

```
PaLM (2022) 确立配方 → LLaMA-1 (2023) 开源定型 → 全行业采用:
  pre-norm + RMSNorm + SwiGLU + RoPE + GQA

效率优化路线:
  GQA (LLaMA-2) → MLA (DeepSeek-V2) → MoE (Mixtral/DeepSeek-V3) → MTP

数据策略:
  The Pile (多领域) → 分阶段喂 → 过训练 (LLaMA-3 15T)
```

> **核心经验**：看开源模型报告，重点不是"又大了多少"，而是**工程取舍**——为什么用 GQA 不用 MHA？为什么 MoE 不用稠密？为什么过训练？每个选择背后都是训练成本 vs 推理成本 vs 质量的权衡。
