# 11 · 活案例：本仓库自己的上下文工程

> 讲透Context 第 11 章 ★用户重点 | 现场 = `~/ai/work4ai`

Ch00 立的军令状：本单元的第三增量是"活案例——本仓库自己就是 context engineering 现场"。收官对账：AGENTS.md、memory blocks、RESUME、skills、会话启动流程，逐个用本单元的镜头照。

## 1. AGENTS.md：常驻 system 的最小高信号集

**现场**：AGENTS.md ≈ 2K 字，每次会话全量进 system 位。
**镜头**：这正是 E1 的 S3 档（system 82 tok 的放大版）。设计上它守住了 Anthropic 三原则的第一条——**最小高信号**：项目直觉（是什么）+ 写入规范（宪法）+ 红线（不可重排的坐标系），没有废话。但有两个 Ch04 级的隐患：①**日期锚不在里面**——"今天是周几"这类相对时间推理靠运行时注入（对）；②它和 memory blocks 有少量重复表述（重复组件近似冗余，E4 的累积消融视角：可以砍）。

## 2. memory blocks：分层记忆的 proto 形态

**现场**：`human`（全局画像 ~4.9K chars）+ `project`（项目备忘 ~4.7K chars）常驻；journal/RESUME 冷存。
**镜头**：这是一套手工维护的 **三层记忆**：
- 常驻层（memory blocks）= working memory，每轮可读；
- 断点层（RESUME-*.md）= episodic + 结构化笔记——**E7 的结论直接命中它的设计**：RESUME 是自由笔记式（"下一步执行清单"+ 关键坑），不是表单模板——E7 实测自由笔记 91.7% > 结构化模板 83.3%，**丢字段会诱发幻觉**，而 RESUME 允许灰度表述（"约""待核"），交接时模型诚实弃权而非编造；
- 归档层（.workbuddy-ai 历史、journal）= cold storage，eviction 但不删除。

**bi-temporal 的朴素实现**：记忆块的 `updated` 时间戳 + "已完成/断点/冻结"状态标记 ≈ valid time + review state 的手写版（讲透Graph Ch03 的正规军在下一楼）。

## 3. RESUME 断点续传：compaction 的人肉形态

**现场**：长任务三件套——执行前建 RESUME，每轮完成后更新，新会话先读。
**镜头**：这就是 **compaction 的离线版**：把"数万 token 的会话历史"压成"已完成清单 + 下一步 + 坑"。它天然规避了 E5 的三种失败：F1（压缩前决策错）由人审清单防；F2（信息损失）由"勿重做"负面清单防（丢的是已验证结论的**过程**，保的是**结论**——正是 E8 的"结论+关键数字+未决问题"三段回传）；F3（访问失败）由"新会话第一条指令=读 RESUME"防。**成本**：每轮多一次文件写（~1K tok 级）——Ch09 算术二的盈亏平衡在"会话必断"的前提下永远为正。

## 4. Skills 渐进披露：省 93.1% 的三层协议

**现场**：30+ skills，系统提示只进 name+description（~100 tok/个），SKILL.md 正文按需 load。
**镜头**：E1 的 L0/L1/L2 三层的生产实现。讲透Skills E2 实测**省 93.1%**（全量 55K → 常驻 3.8K）。这里有个 E4 级的细节：description 就是"是否加载"的检索器——**它的写法是召回问题不是描述问题**（trigger 词要全、要贴用户语言），这是全仓最值钱的每 token 房产之一。

## 5. 会话启动流程：冷启动的组装序列

**现场**（AGENTS.md 规定）：读 `.agent/MEMORY.md` + `.agent/USER.md`；长任务先查 `.research/`。
**镜头**：冷启动 = 无历史时的**组装**（Ch04）。这个序列实质是"C1+C2 混合"：项目 schema（哪类信息在哪）+ 时间锚（记忆块的 updated）。对照 E4 的教训——它缺一个显式的"**今天日期+当前分支状态**"注入位（日期锚 30 tok 买日期题全对），目前靠 AGENTS.md 之外的环境信息补。

## 6. 一个闭环数字：本单元自己的会话

写本单元的会话本身就是案例：讲透Graph 的 E6 扫描（3058 文件）产生大量中间输出——全部走 sub-agent/文件外移（结果存 json，会话里只留结论行）。若把 E6 的原始扫描输出留在对话历史里，本会话在 20 轮后每轮重发 ~50K 无用 token——**外移让本会话的历史税≈0**。这是 E8 结论（状态外移有理）的现场版。

## 7. 不足与改进位（诚实清单）

1. **memory blocks 无淘汰机制**：human 块 4.9K/5K 近上限（铁律 5：近上限先清理）——缺一个"遗忘地板"的自动建议（讲透Loop E5 的 $e^*=f/(r+f)$ 数学可直接搬：写入频率低于地板的条目该归档）；
2. **AGENTS.md 与 project 记忆有重复**（跨会话的 dedup 没人管）；
3. **RESUME 版本链无 diff**：多个 RESUME-0826.md 并存时（Graph/Context/Prompt 各一），没有"哪个最新"的机器可读标记——人工靠目录区分，是个断链温床（讲透Graph E6 的 2155 断债同源）。
