# 00 - 开场白：从 Prompt 到 Context——同一门实验科学的升维

> 讲透Context 第 00 章 | 上游：[../讲透Prompt/](../讲透Prompt/README.md) | 证据：本单元 experiments E1-E7

## 一、一次改名背后的行业共识

2025 年，业内发生了一次静悄悄的改名：Karpathy、Anthropic、Cognition 的工程师们不约而同地说——我们做的不是 prompt engineering，是 **context engineering**。Anthropic 的定义最完整：

> "Context engineering refers to the set of strategies for curating and maintaining the optimal set of tokens (information) for LLM inference... the art and science of curating what will go into the limited context window from that constantly evolving universe of possible information."
> ——《Effective Context Engineering for AI Agents》

拆开看三个关键词：

1. **curating（策展）**：像博物馆策展人，从仓库里无穷的藏品中挑出这次展览要挂上墙的那几十件；
2. **limited context window（有限窗口）**：预算不是软约束，是硬边界；
3. **constantly evolving universe（不断膨胀的宇宙）**：agent 每跑一轮，历史、工具结果、中间推理都在增殖。

而 prompt engineering 研究的是"单次调用里这一句话怎么写"。当对象从一句话变成整个窗口，问题的性质变了。

## 二、为什么必须升维：一个 1% 的实测

本单元 E1 实验（`experiments/e1_anatomy.py`）组装了一个真实深度研究 agent 的上下文，五档策略实测 token 构成：

| 组装策略 | 总 token | user query 占比 |
|---------|---------|----------------|
| S1 极简（光杆 query） | 17 | 100% |
| S2 标准（+system+历史） | 234 | 7.3% |
| S3 +3 个工具 schema | 472 | 3.6% |
| S4 厨房水槽（+10 工具+RAG） | 1669 | **1.0%** |
| S5 渐进披露（10 工具只给清单） | 453 | 3.7% |

**在真实 agent 的窗口里，用户的问题只占 1%，其余 99% 全是你（工程师）策展进去的东西。** prompt engineering 优化的是那 1%；context engineering 管的是剩下 99% ——以及它们会不会把那 1% 挤死、淹死、糊死。

两个后续数字：

- 3 个工具的 JSON schema（238 tok）比 4 轮对话历史（135 tok）还贵——**工具定义是隐藏的 token 大户**；
- 10 个工具从全量 schema 改为"名字+一句话"清单：997 → 219 tok，省 78%（与讲透Skills E2 实测的 93.1% 互证，那边是 38 个 skill 的更极端场景）。

## 三、心智模型：窗口是预算，信息是候选手

```
            候选信息宇宙（无限增长）
  ┌─────────────────────────────────────────┐
  │ system prompt · tools/MCP · RAG 检索     │
  │ 对话历史 · 记忆 · 工具结果 · agent 自述   │
  └──────────────────┬──────────────────────┘
                     │  策展（本单元全部内容）
                     ▼
        ┌──────────────────────────┐
        │   上下文窗口（有限预算）    │   ← Context Rot：
        │   开头◆◆◆◆◆◆◆◆◆结尾    │      放进去 ≠ 用得上
        └──────────────────────────┘
                     │
                     ▼  三大逃生通道（Anthropic 长时程三技术）
        compaction（窗口内压缩）      → Ch05/06
        note-taking/memory（窗口外）  → Ch07
        sub-agent（上下文隔离+蒸馏）  → Ch08
```

这张图就是全单元的目录：Ch01-03 讲"预算为什么难花"（解剖、位置、退化），Ch04 讲"怎么组装"，Ch05-08 讲"满了怎么办"（压缩及其数学、记忆、隔离），Ch09 算钱，Ch10-11 看前沿与活案例。

## 四、本单元的方法论立场

继承讲透Prompt 的宪法，三条：

1. **实验化**：每个论断配可跑实验。本日已落盘 E1（解剖）、E2（位置）、E3（Rot）、E5（压缩保真）、E6（Bloom 对决）、E7（笔记接力），全部本地+API 真跑，json+png 存档；
2. **诚实报告零结果**：E2 没测出位置效应——这本身是重要证据（NIAH 式任务太容易，测不出真实退化），见 Ch02；
3. **数学下场**：Ch06 用通信复杂度和 Bloom filter 给 compaction 一个下界视角——2026-08 的 arXiv 2608.01326 开了头，我们用玩具实验把它踩实。

## 五、和讲透Prompt 的分工

| 问题 | 讲透Prompt | 本单元 |
|------|-----------|--------|
| 研究对象 | 单条 prompt 的措辞/结构 | 整个窗口的信息构成 |
| 典型技巧 | CoT/few-shot/ToT/ReAct | compaction/memory/sub-agent/组装 |
| 失败模式 | 注入/词汇敏感性 | Context Rot/绑定混淆/压缩失真 |
| 数学接口 | OPRO 优化循环 | 通信复杂度/Bloom filter |

两单元共用一套实验基座（`experiments/common.py` 三通道），Prompt 是 Context 的子问题：一句话也是窗口的一部分。
