# 08 · Sub-agent：上下文隔离与蒸馏率

> 讲透Context 第 08 章 | 实验 E8（`experiments/e8_distill.py` → `results/e8_distill.json`）

## 1. 直觉层：派出去的是特工，回来的是情报

Anthropic 长时程三技术的第三件：**sub-agent**——开一个干净窗口去探索，回传蒸馏摘要。原话："sub-agent 探索数万 token 的文献，只回传 1-2K 摘要"。这个模式同时解决两个问题：

- **隔离**：探索过程的海量中间产物（搜索结果、死胡同、全文材料）留在子窗口，**不污染主窗口**——这是上下文的"进程隔离"；
- **蒸馏**：回传的是理解后的结论而非原材料——这是上下文的"函数返回值"。

关键问题：**蒸馏率多少才安全？** E8 用受控实验回答。

## 2. E8 实测：蒸馏悬崖

~1,050 字调研报告（实测 1048 字；12 个可测事实：版本号/日期/人名/公司/数字），9 个条件 × 12 题（答题器固定 glm-4-flash temp=0）：

| 条件 | 回传字数 | QA 保持 | 蒸馏率（对源文实测） |
|------|---------|---------|--------------------|
| full 原文 | 1,048 | **12/12** | 1× |
| 抽取式 1/2（均匀保句） | 551 | 8/12 | 1.9× |
| 抽取式 1/5 | 219 | 2/12 | 4.8× |
| 抽取式 1/10 | 64 | **0/12** | 16× |
| glm 摘要（目标按 4500 字设定：2250/900/450，实际源文仅 1048 字，1/2 档目标失真） | 实际 208-392 | 3/12 | 2.7-5× |
| 头截 1/5 / 尾截 1/5 | 各 209 | 各 2/12 | 5× |

四条结论：

1. **蒸馏悬崖真实存在**：抽取式从 1/2 的 67% 保持率掉到 1/5 的 17%、1/10 的 0%——**5× 蒸馏是朴素方法的死亡线**，而 Anthropic 的"数万→1-2K"恰好在 5-10× 区间——**说明生产级蒸馏不能朴素**；
2. **截断不是蒸馏**：头截尾截同样 2/12——位置无关地丢句子，等于随机丢事实；
3. **相近压缩比下理解式 > 抽取式**：glm 摘要实际压到 ~2.7-5× 仍有 3/12（25%），优于抽取式同档（4.8×）的 2/12（17%）、更优于 16× 档的 0%——**抽象压缩的每 token 信息密度更高**，这是 sub-agent 模式用 LLM 蒸馏的理由；
4. **但 LLM 压缩器预算失控**（E5 同款病，方向相反）：1/5 档指令"字数必须在 810-900 之间（硬性下限）"只产出 386 字（低于下限 52%）——**brevity bias：压缩指令下模型系统性地过度压缩**（1/2 档目标按 4500 字设定为 2250、超出源文本身，该档目标失真不计）。生产必须在压缩器外层加预算执行器（不够就追加"继续扩展"轮次，或分层摘要拼装）。

## 3. 数学层：蒸馏的信息论下界

事实集合 $F = \{f_1..f_n\}$ 均匀分布（每个 $|f_i| \approx s$ 字）。抽取式保留率 $r$ 时，单个事实存活概率 $\approx r$，期望存活数：

$$\mathbb{E}[\text{存活}] = n \cdot r \quad \Rightarrow \quad \text{QA 保持} \approx r \ (\text{线性衰减})$$

E8 抽取式实测：1/2→67%（预测 50%，略好因为句子级保留有局部性）、1/5→17%（预测 20%，吻合）、1/10→0%（预测 10%，题太少取整为 0）。**朴素蒸馏的线性衰减无法避免**——这正是 Context Compaction Theory（2608.01326，Ch06）的 Thm 1 在"事实袋"源上的具体化：要打破线性衰减，必须让摘要器**理解哪些事实会被问到**（任务感知压缩），而这正是 LLM 蒸馏的优势所在——前提是治好它的 brevity bias。

**Sub-agent 的完整账**：蒸馏收益（主窗口省 $W(1-1/k)$）vs 蒸馏损失（回传只保 $\rho(k)$ 的事实）vs 隔离收益（探索污染不进主窗口，无法量化但往往是主要动机——E3 的 distractor 伤害就是污染的微观机制）。

## 4. 工程配方：安全蒸馏四原则

1. **蒸馏率目标 2×-3×**（保持 67%+），超过 5× 必须任务感知（明确告诉摘要器"下游要答什么类型的问题"）；
2. **预算外层执行**：字数下限用代码检查+追加轮强制，不信指令；
3. **回传带结构**：不是一段散文，而是"结论+关键数字表+未决问题"三段——E7 的教训（模板即过滤器）在这里反过来用：**回传模板的每个字段都是下游会问的问题**；
4. **分层回传**：1-2K 摘要常驻主窗口，原文留在子窗口句柄里可追问（eviction ≠ 删除，讲透Graph 的地址锚定同构）。

## 5. 不足与坑

- **12 题 × 1 文档的样本量**：悬崖位置（5× vs 8×）会随事实密度变化，结论的**形状**（线性衰减+理解式上移）比具体数字稳；
- **QA 保持 ≠ 任务保持**：sub-agent 的下游常是"继续推理"而非"答题"——推理对摘要的容忍度更低（丢的是推理链不是孤立事实）；
- **答题器与压缩器同模型**（都是 glm-4-flash）：摘要的措辞偏向答题器口味，保持率或有虚高（换答题器是留给读者的消融）。
