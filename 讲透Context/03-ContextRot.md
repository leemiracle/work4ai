# 03 - Context Rot：越长越蠢的实证

> 讲透Context 第 03 章 | 实验：E3（`experiments/e3_rot.py`，results/e3_rot.json/png）| 素材：Chroma《Context Rot》（2025-07-14，tech report，无 arXiv ID）

## 一、直觉：会议室里的第 47 个人

一个 10 人会议室里，每人说一句，你记得谁说了什么。47 个人各说 10 分钟后，你连"谁支持方案 A"都开始混淆——不是因为信息不在场（都在），而是**每条信息的信噪比被总量稀释了**。

Chroma 团队给这个现象起了名字：**context rot**。他们对 18 个前沿模型做了 4 组控制变量实验（任务难度恒定、只变输入长度），结论：

1. 性能随输入长度**单调退化**，且发生在窗口远未占满之前；
2. needle 与问题**语义相似度越低**，退化越快（词面匹配是简单模式）；
3. **distractor（形近干扰）的伤害非均匀**，且随长度放大；
4. 反直觉发现：**haystack 有序连贯反而伤性能，打乱（shuffle）反而更好**——局部连贯让模型误入语义歧途。

E2 已经证明"词面检索"测不出退化。本章的 E3 换上真实 agent 轨迹里最常见的杀伤条件：**同形干扰绑定**。

## 二、数学：绑定问题为什么难于检索

设上下文含 $n$ 个"主键→值"对（KX-2076→王倩，KX-2077→林澈，…）。词面检索只需激活 needle 自身；**绑定查询要求模型对主键 $q$ 与值 $v$ 做精确的逐对关联**，等价于在注意力里实现一个近似哈希表查找。干扰项与 needle 共享句式模板和值域（同为人名/同为数字），softmax 的分布质量会被"形近候选"分流：

$$P(\text{correct value} \mid q) = \frac{e^{s(q,v^*)}}{e^{s(q,v^*)} + \sum_{i} e^{s(q,v_i)} + Z_{\text{filler}}}$$

分母里的 $\sum_i e^{s(q,v_i)}$（形近干扰项得分）随干扰数量与上下文总长增长——**这就是"干扰 × 长度"双重打击的机制草图**：长度增加 filler 项 $Z$（稀释），干扰提供高得分假候选（分流）。二者相乘，绑定精度崩塌。这也是 E1 里 99% 策展物的真正风险：它们不只是占预算，还在给每个查询制造分母。

## 三、代码：E3 实验

**设计**：needle 固定 50% 位置（E2 已证 clean 下位置无关）；条件 {clean, +8 条同形干扰}；长度 {1K, 4K, 8K}；干扰句均匀撒在 needle ±10% 之外。

```bash
cd 讲透Context/experiments
python3 e3_rot.py --model qwen --lengths 1000,4000        # ~12 min
python3 e3_rot.py --model qwen --lengths 8000 --conds clean        # ~15 min
python3 e3_rot.py --model qwen --lengths 8000 --conds distractor   # ~17 min
python3 e3_rot.py --model glm --lengths 1000,4000,8000    # ~1 min
python3 e3_rot.py --plot
```

**实测结果（答对率 %，n=4/格）**：

| 条件 | 1K | 4K | 8K |
|------|-----|-----|-----|
| Qwen clean | 100 | 100 | 75 |
| Qwen distractor | 100 | **75** | **50** |
| glm clean | 100 | 100 | 100 |
| glm distractor | 100 | 100 | 100 |

三个结论，一个比一个重要：

1. **长度单独（clean）在 8K 才开始咬 Qwen**（75%）——与 E2 一致，词面任务对长度有韧性；
2. **同形干扰把退化提前并加深**：4K 就掉到 75%，8K 掉到 50%。"干扰 × 长度"相乘，非相加；
3. **glm-4-flash 六格全对**——rot 严格模型依赖，小模型先烂。这正是讲透Prompt Ch08"模型适配"在 context 维度的镜像：**同一个上下文策略，在不同规模模型上的安全边际完全不同**。给 0.5B 用"往窗口里堆"的策略，4K 就出事。

（诚实声明：n=4/格，功效低；但方向与 Chroma 18 模型大样本结论一致，且我们提供了他们没有的双模型同网格对照。）

## 五、工程启示：rot 防御清单

按"每 token 信噪比"重新理解所有 context 策略：

1. **加长度之前先加精度**：RAG 的 reranker、工具结果的截断、日志的过滤——每个"少放 1000 个 filler token"的动作都在缩小分母 $Z$；
2. **同形信息要显式消歧**：多个配置文件/多个版本的代码并置时，给每段加唯一锚（文件名+版本+时间戳），把"形近候选"变成"可区分候选"；
3. **eval 里必须有干扰绑定题**：纯 NIAH 的绿灯是假安全（E2/E3 联合证据）；
4. **小模型配小窗口**：0.5B 在 4K+ 干扰环境开始失准——蒸馏/端侧场景的硬约束；
5. **70% 线**：工业实测（redhat survey 综合 Factory.ai 等）agent 上下文超 ~30K 后退化加速，**利用率 70% 时主动压缩优于 95% 被动触发**——这是 Ch05 compaction 的登场理由。

## 六、不足与批判

- Chroma 是厂商技术报告（非同行评审），但其方法学（任务难度恒定、只变长度）被后续工作广泛引用；我们的复现是玩具规模，方向一致、幅度不可比；
- 干扰项 8 条是手工设计的"最坏情况"（同句式同值域）；真实轨迹的干扰密度更低但更杂；
- "为什么 glm 不烂"只给了现象没给机制——参数量/训练数据/对齐后处理都可能贡献，本单元不展开（讲透模型/讲透微调的领地）。
