# 12 教学简化与生产实践对照：从 490 行服务端到真实 RDMA 栈差多远

> 收束全系列｜对照对象：`src/` 全部 4 个文件（约 1470 行）

## ① 角色定位

本系列前 11 篇把这套代码的机制讲透了；本篇换一个批判视角：**作者在每个"该多写 50 行"的地方都明智地少写了**。文件头 TODO（`src/rdma_server.c:7`）自曝的第一条就是"error condition 下不清理"——这不是疏漏，是教学代码的自觉取舍：把 1470 行全部预算花在 verbs 主线上。但把它当模板复用的人必须知道每一处简化在哪里、生产世界的对应做法是什么。下表化对照不唱衰——能跑通"连接→交换→单边读写→干净拆除"全闭环的最小代码，恰恰是最好的教材。

## ② 内部结构（简化点清单与生产对照）

**架构层**
1. **单连接一次性进程**：`main` 线性调用五个阶段函数（`src/rdma_server.c:463-483`），服务完一个客户端即退出；`rdma_listen(id, 8)` 的 backlog（`:160`）无人兑现。生产：accept 循环 + 每连接一个状态结构体（本仓所有资源都是 static 全局 `:14-26`，连接数=1 是写死的），线程池或 reactor。
2. **全阻塞单线程**：`process_rdma_cm_event` 内 `rdma_get_cm_event`（`src/rdma_common.c:112`）与收割器内 `ibv_get_cq_event`（`:148`）都是无限期阻塞——任何一环卡死全进程卡死。生产：CM 通道 fd + 完成 fd 一起进 epoll，事件驱动状态机（参考 rping 的做法）。

**容量与能力层**
3. **容量写死**：CQ_CAPACITY=16/MAX_SGE=2/MAX_WR=8（`src/rdma_common.h:47-51`），代码自己承认"can be probed from the device"（`src/rdma_server.c:100-102`）却没探测。生产：`ibv_query_device`/`ibv_query_port` 取 max_qp_wr/max_cqe 再钳位。
4. **深度协商拍脑袋**：initiator_depth/responder_resources=3（`src/rdma_server.c:241-243`）注释自供"small number for this exercise"。生产：按在飞单边操作数实测调优。

**内存层**
5. **一缓冲一注册**：7 次 `ibv_reg_mr`（全经 `src/rdma_common.c:70`）每次都为几十字节小缓冲付出 pin+映射成本，用完即 dereg。生产：内存池 + 一次注册大块 MR 后按偏移切片（MR 内 offset 访问免重复注册），或 fastreg/MW 动态窗口。
6. **注册长度随手写**：dst 缓冲按 `strlen(src)` 注册（`src/rdma_client.c:313-315`），零余量。生产按 MTU 对齐/页对齐，且考虑 inline 优化（小包 IBV_SEND_INLINE 免注册——本仓未演示）。

**协议层**
7. **元数据协议裸奔**：16 字节结构无魔数/版本/字节序（第 09 篇勘误③）、单缓冲单语义（没有第 09 篇开头说的"类型"字段）、lkey 当 rkey 发（第 02 篇勘误③，多数 provider 数值相同侥幸跑通）。生产：协议头带版本与类型、`htobe64/be64toh` 显式转序、发 `mr->rkey`。
8. **length 无校验**：服务端照客户端报的 length 直接 alloc（`src/rdma_server.c:298-302`）——恶意/失控客户端一句 4GB 就把服务端打 OOM。生产：上限钳位+拒绝策略。

**数据面层**
9. **同步一问一答**：4 次 post_send 每次都跟一次收割（第 11 篇④），WR 深度永远 1，QP 的流水线能力全闲置。生产：批量 post、深度灌满 MAX_WR、按序收割回调。
10. **收割器可忙等**：do-while 凑 WC 的循环（`src/rdma_common.c:167-177`）在 WC 分批到达时空转烧 CPU（第 05 篇勘误①）。生产：按事件数收割+超时兜底。

**健壮性层**
11. **错误路径零清理且坑对端**：任一阶段失败 `main` 直接 return（`src/rdma_server.c:464-487`），资源泄漏且不给对端发 disconnect——对端永久阻塞在等 DISCONNECTED（`:367`）。生产：goto 错误链统一跳拆除段（第 10 篇勘误①）。
12. **拆除吞错**：8 步销毁步步"continue anyways"（`:388-416`），函数末尾无条件 `return 0`（`src/rdma_client.c:453`）。生产：拆除错误至少计数上报。

**可移植层**
13. **地址解析盲拷**：`get_addr` 把 getaddrinfo 结果 `memcpy(addr, ..., sizeof(sockaddr_in))`（`src/rdma_common.c:206`）——若解析出 IPv6 结果即越界写（第 06 篇已详）。生产：校验 `res->ai_addrlen` 与 `ai_family`。
14. **字符串边界**：`calloc(len,1)+strncpy(len)` 不留 NUL（`src/rdma_client.c:478-484`），`strlen` 全靠 calloc 零尾侥幸（第 01 篇勘误⑥）。
15. **构建面怪癖**：g++ 编 .c + `-Ofast -ffast-math -march=native`（`CMakeLists.txt:19,21`）、HINTS 硬编码作者机器路径 `/home/atr/local`（`:25-26,30`）（第 01 篇已详）——教学仓无碍，分发前要洗。

## ③ 外部连接（向上生长的路径）

把这 15 条简化按"改造成本"排序，正好构成一条学习晋升线：本仓 → librdmacm 自带示例（`rping.c` 是本仓 `get_addr` 的出处，`src/rdma_common.c:196` 注释致谢；它演示了事件循环+多连接）→ perftest（带宽压测，WR 流水线灌满）→ UCX/SPDK 等生产栈（内存池、多线程 CQ、容错重连）。图谱视角：本仓 31 节点里没有并发、没有配置、没有可观测性节点——向外连接的第一步不是加功能，而是把 static 全局（`src/rdma_server.c:14-26`）收进 per-connection 结构体。

## ④ 数据流（一次运行暴露的三处简化时刻）

对照运行日志能直接看见简化：① README 示例输出（`README.md:36-46`）从 connect 到 SUCCESS 总共 7 行——真实栈同场景要打满 negotiated 深度的事件流；② 客户端等 2 个 WC 一次收齐（`src/rdma_client.c:292`）——生产收割器每次醒来的 WC 数是波动的；③ 服务端收线后进程直接退出（`src/rdma_server.c:483-488`）——生产服务端的第 2 个 CONNECT_REQUEST 已在 backlog 里排队。简化的代价不在正常路径，全在**异常路径与第二次循环**。

## ⑤ 设计决策

- **简化的最大价值是"可见性"**：正因为每个 post 后立刻等 WC，读者才能在 `src/rdma_client.c:339→348` 之间看清一次 WRITE 的完整生命周期；一旦改成流水线，教学清晰度立刻崩塌。作者在第 5 篇讲过的收割器注释里甚至自比 pthread 条件变量——他清楚自己在写教材不是写库。
- **rdma_cm 路线本身就是一个决策**：放弃裸 ibverbs 的代价是隐藏了 QP 状态机（第 11 篇勘误①的差集），收益是连接管理代码量砍半。教学上选 rdma_cm 是对的；但理解 RTR/RTS 迁移的工程师必须去读 `ibv_rc_pingpong` 补课。
- **15 条简化没有一条是"错误"**：勘误与简化的分界线本系列始终在划——错的是照抄进生产的人，不是少写的作者。

## ⑥ 新人提示（演进 checklist）

把本仓改造成"最小生产骨架"的最短路径（按依赖顺序）：
1. static 全局 → `struct connection`，main 只留骨架（解②-1）；
2. main 改 goto 错误链统一拆除（解②-11，模板在第 10 篇②）；
3. 等待原语加超时：CM 与 CQ 两处阻塞各配 epoll+timerfd（解②-2/10）；
4. 服务端 accept 循环 + length 钳位（解②-1/8）；
5. 协议头加版本与 rkey（解②-7，参照第 09 篇）；
6. 内存池化（解②-5，最后做——它是性能优化不是正确性问题）。
每步都可独立验证（memcmp 语义不变，`src/rdma_client.c:31-34` 的成功判据跨所有改造稳定成立）。演进前先跑通 SoftiWARP 无硬件环境（`README.md:50-51`），演进后用第 11 篇速查表对照回归。
