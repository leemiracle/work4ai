# 06 · qp.rs：QueuePair——类型化传输、状态机与门铃批量

> 源码：`ibverbs/src/qp.rs`（3520 行，全库最大，下文锚均指此文件）+ `ibverbs/examples/loopback.rs`｜行号锚全源码核实

## ① 角色定位

QP 是 RDMA 的"套接字"——发送队列+接收队列+CQ 关联的网卡资源（qp.rs:2508-2512 文档）。本文件承载四件事：**①传输类型系统**（sealed trait 把 verbs 非法组合变编译错）；**②建连状态机**（builder→Prepared→handshake/activate 驱动 RESET→INIT→RTR→RTS）；**③数据面**（SendBatch/SendOp 门铃接口 + RecvRequest/post_recv 链表接口）；**④EINVAL 翻译器**（复刻内核状态表）。它是 16 步 tour 的深潜重心（onboard ⑦ step-09："Transport 类型系统与 SendBatch Drop 语义是核心考点"）。

## ② 内部结构

- **类型层（qp.rs:15-125）**：`sealed::Sealed`（:16-22）+ 四 trait——`Transport`（:72）、`Connected`（:76，RC/UC）、`Reliable`（:81，仅 RC）、`Datagram`（:85，UD/SRD）——三标记 Rc/Uc/Ud（:92/:97/:106）。Transport 文档内嵌 **5 个 compile_fail**（:34-71）：UD 上 set_timeout、QueuePair 上 batch.to、UD 批次上 op()、Uc 上 fenced、UD 上 handshake，全部 E0599。
- **建连层**：`QueuePairBuilder<T>`（:477-509）与 `new`（:517-573，按传输种子 INIT/RTR/RTS 三组属性）；`BringUp`（:1056-1060）携三组属性随构造传递；`PreparedQueuePair<T>`（:1033）；`QueuePairEndpoint`（:1076，28 字节 wire 格式 :1103-1143）。
- **数据面**：`RecvRequest<'a>`（:1407，repr(transparent) 包 ibv_recv_wr）；`SendBatch<'qp,T>`（:1517）；`SendOp<'b,'qp,T>`（:1640）；`Payload<'a>` 三变体 Sges/Inline/InlineList（:2029-2038）。
- **属性层**：`QueuePairAttribute`（:2063，set 即记 mask 位）、`QueuePairState`（:134）、`AckTimeout`（:271，4.096µs×2^n 级数）、`RnrTimer`（:350，**非单调**编码 0=655.36ms 最大）、`SendOps`（:421）。
- **成品 `QueuePair<T = Rc>`（:2514-2532）**：pd/_srq/_send_cq/_recv_cq 四父引用 + qp/qp_ex 双指针 + 两道容量闸；`SendQueue`（:2814）是 split 的发送半句柄。

## ④ 数据流：loopback.rs 74 行全链走读

**控制面五步（loopback.rs:29-39）**：

1. `pd.create_qp::<Rc>(&cq,&cq,1)`（→pd.rs:174）——此刻查端口并要求 ACTIVE（pd.rs:182-183）；RC 默认 timeout=65.536µs、retry=6、rnr_retry=6、min_rnr=2.56ms（qp.rs:539-544）。
2. `.set_gid_index(gid)`（loopback.rs:32→qp.rs:600）——RoCE 必经，挑选逻辑见 03 篇。
3. `.build()`（→qp.rs:895→build_impl :798）：check_same_context（:799）→`ibv_create_qp_ex`（:805，经 sys shim）→`ibv_qp_to_qp_ex` 拿门铃视图——**null 即 `Error::Unsupported`**（:849-854）：provider 收了 SEND_OPS_FLAGS 却没装 WR 表的 QP 永远 post 不进去，当场销毁。
4. `.endpoint()`（→qp.rs:1175）：现查 query_gid 组 `{qp_num,lid,gid,psn,max_dest_rd_atomic}`；psn 配对——本端 send 起点即对端 recv 起点。
5. `.handshake(endpoint)`（→qp.rs:1364-1398）：依序 apply init/rtr/rts。`rtr_attributes`（:1264）构路途地址向量（GID→set_grh hop limit 0xff；RoCE 无 GID 直接 `Error::GidRequired` :1291-1294）；**RTR 失败的 RoCE 特判**（:1370-1395）把 ETIMEDOUT/ENETUNREACH 翻成"远端 GID 不应答或防火墙丢 UDP 4791"；`rts_attributes`（:1320）把本端 max_rd_atomic **压到对端广告容量**（:1328，超出是协议错误）。

**数据面三步（loopback.rs:46-49，unsafe 仅两处）**：

```
unsafe { qp.post_recv([RecvRequest::new(2, &[mr.slice(..8)])]) }  // 先挂接收
let mut batch = qp.start_send();                                   // wr_start
batch.op().signaled().send(1, &[mr.slice(8..)]);                   // 立即入块
unsafe { batch.submit() }                                          // 单次门铃
```

- `post_recv`（qp.rs:2710-2724）：`link`（:1439-1448）在**调用者切片上原地**串链（:1435-1438 注释：重复索引切片会作废先前的链）。失败时 `post_recv_error`（:1958-1982）按 bad_wr 指针差算**已 post 数量**；挂 SRQ 的 QP 得具名错误"post receives there"（:1973-1978）。
- `start_send`→`open_batch`（:2751→:2789）：wr_start 返回的 SendBatch **独占借用** qp——第二个批次编译不过（compile_fail :1469-1475）。
- 修饰符链：signaled（:1653）改 flags，`send`（:1669）以 op 闭包（`send_op` :1791，imm 走 `wr_send_imm` 且 `to_be()`）收尾进 `build`（:1700-1787）。build 四件事：**容量预检**（:1720-1725，注释点名三家 provider 不查容量就写队列）；设 wr_id/wr_flags（补 INLINE 位，rxe 需要 :1731-1736）；跑 opcode 闭包；按 Payload 分发 setter——单 sge 走免循环 `wr_set_sge`（:1746-1748），**空切片传真 NULL 而非 dangling**（:1749-1759）。`#[inline(always)]`（:1699）：多调用点会让 LLVM outline，每请求白付调用+分支。
- `submit`（:1607-1618）：**先 forget 再 wr_complete**（:1610-1612，否则 Drop 会 abort 掉即将 complete 的块）。失败也返回 Err，但 safety 契约（:1589-1600）列三种"已收不回"：rxe 先交设备再报错、mlx5 队满**覆写上一条请求**、hns owner-doorbell 在 opcode 返回时可能已执行。**Drop=abort**（:1621-1627）：未 submit 的批次 drop 调 wr_abort——忘 submit 整批蒸发（onboard ⑧第 6 条）。

**收割（loopback.rs:53-72）**：`cq.poll()` 迭代 WC，`wc.ok()` 翻错、`wc.wr_id()` 分派（1=发/2=收），收侧断言字节落了（loopback.rs:66）。

## ⑤ 设计决策

1. **能力进类型、非法组合进编译错**：5 个 compile_fail（:34-71）+ 4 个借用检查 compile_fail（:1469-1504，含 E0505"handle 被批次借用中不许 drop"）是 crate 三承诺之二（onboard ①）的可执行证明；sealed 防外部实现。
2. **门铃批量是性能核心**：一次 wr_complete 提交整块（doorbell_batching 示例演示收益）；每请求在 opcode 调用时已写入 WQE（:1458-1460），submit 只响铃——与 legacy ibv_post_send"整链一次调用"是两种 batching 哲学。
3. **EINVAL 翻译器**：`qp_transition_masks`（:2377-2498）复刻内核 `ib_modify_qp_is_ok` 位表，`diagnose_modify`（:2633-2679）把裸 EINVAL 升格为 `InvalidQueuePairTransition`/`InvalidQueuePairAttributeMask`；test_kernel_table（:3487-3518）**逐格对照**内核表——绑定层自带内核一致性测试。
4. **四父引用钉出依赖序**（:2515-2520）：Drop（:2826-2840）destroy 失败 keep 全部四个；QP 未 detach 多播组时返 EBUSY（:2828 注释），panic 好过静默泄漏。`query` 取 `&mut self`（:2599-2601）：libibverbs 无锁写缓存 state，rxe/EFA/hns 每次 post_recv 都读它。
5. **容量与位宽双闸**：max_send_sge/max_inline_data 由 build 强制（:2526-2530，所有 provider 按请求量造 WQE），panic 走 `#[cold]`（:1984-2012）不污染热路径；24 位字段（qp_num/psn）在 setter（:2149-2151）、endpoint 解码（:1133-1135）、rtr（:1265-1273）拦截——ionic/EFA/irdma/mana 会把超宽 PSN 原样传给设备（:1062-1064）。
6. **split 解 send/recv 并发**（:2781-2783）：send 批需 `&mut`、post_recv 只需 `&`；split 后双线程各持一半。同时如实标注 ionic/hns 的锁耦合例外（:1506-1515、:2757-2761）。

## ⑥ 新人提示

- **读 qp.rs 正确顺序**：trait 层（15-125）→ loopback 对照第④节 → SendBatch/SendOp（1517-1931）→ 再碰 builder/handshake；从 477 行顺读会在千行 setter 里迷路。
- 练习三连（onboard ⑦）：改两条 wr_id 各发一次；换 `<Ud>` 体会 E0599；批量 8 条对比逐条 submit（doorbell_batching.rs 现成）。
- **EFA 特例**（qp.rs:102-105）：UD send 必须 signaled、禁止 solicited——Srd 每请求必产完成。UD 收到的 WC `len()` 含 40 字节 GRH（sys lib.rs:67-70），payload 从 offset 40 起（qp.rs:2688-2690）。
- inline 字节在 opcode 调用中**已拷进 WQE**（qp.rs:1761-1763），缓冲随用随弃；Sges 引用的 MR 须活到 WC——两种 Payload 生命周期契约不同（:2014-2027）。
- handshake 失败先读错误文案：RoCE 路由诊断（:1383-1391）点名 GID 不应答/防火墙 UDP 4791 两大元凶。手动状态机才用 `into_queue_pair`（:1156）+ modify（:2581）——普通应用永远 handshake/activate。
- 死锁红旗（:1506-1515）：ionic 上开着批次别 poll/arm 它的 send CQ、别经同一 CQ post_recv；hns 上 polling 失败完成会拿 send 队列锁。跨 provider 移植前读完这段。
