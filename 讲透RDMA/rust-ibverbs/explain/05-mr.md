# 05 · mr.rs：MemoryRegion 泛型所有权与顺序 Drop

> 源码：`ibverbs/src/mr.rs`（399 行）｜行号锚全源码核实

## ① 角色定位

RDMA 网卡只认**注册过的内存**：注册把虚拟页 pin 住（或 ODP 下建立按需映射），换回一对钥匙——`lkey`（本地钥匙，贴在 scatter/gather 条目）与 `rkey`（远端钥匙，单边操作的"指针"）。`mr.rs` 就是这对钥匙的世界：`MemoryRegion<O>` 用**泛型参数 O 编码缓冲所有权**——`Box<[u8]>` 表示 crate 替你分配，`()` 表示内存另有其主（外部指针或 DMA-BUF）——并用两段 `ManuallyDrop` 手工编排"先注销、后释放"。另产两个切片：`LocalMemorySlice`（本地侧可直接 post）与 `RemoteMemorySlice`（远端侧可序列化），覆盖 verbs 两侧数据面。

**任务书前提甄别**：所指 "sync/async mr 差异"——源码核实：本仓库（82e8e65c）**不存在 `ibv_reg_mr_async` 调用**（grep 全库零命中），pd.rs 三入口（pd.rs:255/295/327）全走同步 `ffi::ibv_reg_mr`（pd.rs:214），rdma-core 的异步注册动词未封装。语义上最接近"异步注册"的是 **ODP**：`AccessFlags::ON_DEMAND`（mr.rs:30）注册不 pin 页、访问按需 fault-in，配 `advise_mr` 预取（pd.rs:129）——本文按此实际状况论述。

## ② 内部结构

**AccessFlags**（flags_newtype，mr.rs:11-40）：12 个 `IBV_ACCESS_*` 位。文档埋着关键工程信息：`RELAXED_ORDERING` 允许 PCIe 写乱序落盘，会破坏"轮询末字节判到达"的接收器（mr.rs:52-53）；EFA 拒绝其设备不支持的远端位（mr.rs:47-50）。便捷包 `PERMISSIVE`（mr.rs:54-56）= LOCAL_WRITE|REMOTE_WRITE|REMOTE_READ。

**MemoryRegionInner**（mr.rs:59-63）：`_pd`（反向持有父 PD）、`mr` 裸指针、`addr`（注册基址，供 slice 计算与 remote 打包）。Drop（mr.rs:68-76）调 `ibv_dereg_mr`，失败经 `destroyed` panic 并 `keep(&self._pd)` 漏引用防 unwind 连锁。

**MemoryRegion<O>**（mr.rs:87-92）：

```
pub struct MemoryRegion<O> {
    inner: ManuallyDrop<MemoryRegionInner>,   // mr.rs:90
    owner:  ManuallyDrop<O>,                  // mr.rs:91
}
```

`impl Drop`（mr.rs:94-101）手工按序：**先 drop inner（dereg），后 drop owner（释放缓冲）**。字段注释（mr.rs:88-89）写明动机：dereg 失败会 panic，此时 owner 已无法正常 drop——**故意泄漏缓冲**，设备可能仍持 DMA 引用，宁漏内存不可释放后被网卡写入。

**两个切片**：`LocalMemorySlice`（mr.rs:198，`#[repr(transparent)]` 包 `ffi::ibv_sge`——与 C 的 sge 零成本互转，`From` 双向 mr.rs:206-216）；`RemoteMemorySlice`（mr.rs:261-268，三个**公开**字段 addr/len/rkey——它就是要序列化上线的数据）。

## ④ 数据流：一把钥匙的两种花法

**本地侧 `slice()` 铸 sge（mr.rs:160-169）**：`calc_addr_len` 把 RangeBounds 折成 (addr,length)（空区间/越界 mr.rs:334-336 assert），打上 lkey 装 `LocalMemorySlice`。文档的关键让步（mr.rs:152-155）：切片**不借用** MR——sge 里只有裸地址，"别在 dereg 后继续用切片"只能写进 post 方法 safety 契约靠人守。`LocalMemorySlice::slice`（mr.rs:244）可再切，lkey 沿用。

**远端侧 `remote()` 打包指针（mr.rs:134-140）**：`(addr, mr.length, rkey)` 三元组——远端拿到即可发起 RDMA READ/WRITE，本地 CPU 不经手。`to_bytes`（mr.rs:279-285）定长 20 字节网络序（WIRE_LEN mr.rs:272）；`from_bytes`（mr.rs:293-305）两道校验：`addr+len-1` 不得回绕 u64（mr.rs:297-299——对端给的地址不可信），len 须塞得进本机 usize（mr.rs:302）。

**收尾 `into_inner()`（mr.rs:143-149）**：dereg 后取回 owner（`ManuallyDrop::take`）——allocate 的 `Box<[u8]>` 可还给调用者继续当普通内存。O 参数设计的回报：同一代码路径对三种 owner 一视同仁。

**bytes/bytes_mut 的边界约束（mr.rs:172-191）**：`impl<O: Deref<Target=[u8]>>` 才有 `bytes()`——`MemoryRegion<()>` **没有**这两个方法，类型系统禁止把 crate 不拥有的内存当 Rust 切片摸。`bytes_mut` 文档（mr.rs:182-187）复述竞速契约：接收/RDMA 写 outstanding 期间读写目标字节=与设备竞速，必须等对应 WC。

## ⑤ 设计决策

1. **泛型 O 替代继承/枚举**：三入口共用一个类型，编译期决定 Drop 行为与可用方法（bytes 系列只对 Deref owner 存在），零运行时分支、零自引用风险。
2. **顺序 Drop 是安全承诺不是优化**：先 dereg 后释放，任何反序都开 use-after-free 窗口——dereg 前释放缓冲，网卡 DMA 可能写进已复用内存。dereg 失败 panic+泄漏（mr.rs:88-89，onboard ⑧第 7 条），把"生产环境须接 unwind"变成部署要求。
3. **Remote 公开字段、Local 私有字段**：远端结构是**数据**（要上线 20 字节），公开+Copy 是正解；本地结构是**能力**（lkey+地址，post 凭证），私有 `_sge` 强迫走构造器，`From<ffi::ibv_sge>`（mr.rs:206）给"crate 外注册的 MR"留正门逃生舱（mr.rs:202-205 文档说明该用例）。
4. **不封 ibv_reg_mr_async，但留 ODP 通道**：异步注册（后台 pin）未入封——上游语义与错误面尚不稳；ON_DEMAND+advise_mr 预取覆盖"大注册不想同步等"的真实需求，且都走 `Error::Unsupported` 干净降级。
5. **定长 wire 格式**：不用 serde、不发明变长——与 QueuePairEndpoint（28 字节，qp.rs:1094）同走"定长数组+大端"零依赖序列化，跨版本可解码（mr.rs:275-278）。

## ⑥ 新人提示

- lkey/rkey 一图流：**lkey 给本地 post（sge），rkey 给对端单边操作（remote）**。rkey 泄给不可信对端=交出内存写权限；PERMISSIVE 含 REMOTE_WRITE 时尤其如此。
- 切片生命周期靠纪律：`slice()` 不带借用（mr.rs:152-155），post outstanding 期间 drop MR 是 UB——契约在 qp.rs:2698-2701。先收割 WC 再动缓冲。
- `remote()` 返回**整个** MR 的句柄；远端只想摸一段，用 `RemoteMemorySlice::slice`（mr.rs:312）在任一侧再切。
- ODP 注册首访页故障，延迟毛刺可预测落在数据面；`advise_mr(Prefetch,...)` 预取是配套解法（pd.rs:117-121）。
- `bytes_mut()` 能写不能扩（mr.rs:182-183："can be written but not resized"）——注册长度创建时钉死。
- 纯逻辑测试四类（mr.rs:342-398：wire 往返/回绕拒绝/sge 互转/PERMISSIVE 组成）不依赖硬件，本地 `cargo test` 即跑。
