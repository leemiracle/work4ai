# 05 · 发送引擎 SQ 流水：从 WQE 到 TCP 字节的四层加工线

> 仓库 zrlio/softiwarp @ 5d8a418 · 本文行号锚全部经源码核实

## 一、角色定位

siw_qp_tx.c（1413 行）是 siw 的"硬件发送 DMA"替身：把 SQ 里的 WQE 按序取出，套上 MPA/DDP/RDMAP 头尾，切成适配 MSS 的 FPDU，推进 TCP socket。它决定 siw 的发送吞吐模型——**per-CPU 内核线程为主、用户态直发为辅**的混合执行架构。理解本篇是理解 siw 性能行为（burst 限流、零拷贝条件、低延迟忙等）的钥匙。需要先钉死一个高频误读：`USE_SQ_KTHREAD` 在 siw.h:542 **默认 #define，是活代码**；被 `#ifndef USE_SQ_KTHREAD`（siw_qp_tx.c:1212）排除在编译之外的才是 workqueue 备选路径（siw_sq_work_handler）。本仓默认构建里 TX 线程模型就是 kthread。

## 二、内部结构：四层流水

**第 1 层——执行体（谁在跑）**。三个入口殊途同归进 `siw_qp_sq_process`：①用户态 doorbell（siw_verbs.c:920-994 的 siw_doorbell_sq，mapped 模式下 post_send 后敲铃，内核直接在 syscall 上下文跑一轮，置 `in_syscall=1` :969）；②post_send 的直接发送分支（siw_verbs.c:1195-1202，同样用户上下文）；③per-CPU kthread。kthread 主循环 `siw_run_sq`（siw_qp_tx.c:1295-1366）：模块加载时每颗合格 CPU 一个（siw_main.c:294-300 的 kthread_create+kthread_bind，tx_cpu_list 可指定子集）；`low_delay_tx=1` 时（:70-72）不走睡眠等待，而是 cond_resched 忙等一个 HZ 窗口（:1310-1324）以压低唤醒延迟；醒来 `llist_del_all` 取出本 CPU 的 QP 链（:1326），逐个 `siw_sq_run`（:1263-1286：trylock state_lock、验 RTS 且未 suspend、调主循环、错误则 cm_drop）。投递侧 `siw_qp_to_tx`（:1368-1398）：QP 记住自己的 cpu（创建时 `(smp_processor_id()+1)%NR_CPUS`，siw_verbs.c:697），若该 CPU 队列忙则**顺手负载均衡**到任意空闲 CPU（:1379-1389），llist_add 后 wake_up。`siw_sq_queue_work`（:1402-1413）是统一门面：kthread 模式转发 siw_qp_to_tx（:1406-1407），workqueue 分支（queue_work+siw_sq_work_handler :1409-1411/:1220-1260）被编译排除。

**第 2 层——WQE 主循环 `siw_qp_sq_process`**（:1040-1188）：`wait_event(!in_use)` 拿独占令牌（:1048-1057，两 waiter 并发属 bug，WARN_ON）；tx_suspend 即停（:1062）；`SIW_WQE_IS_TX` 恒为 1（siw.h:262），故 local 分支（:1005-1010，"not yet implemented"+BUG）是防御性死代码。四种出口：rv==0——WQE 完成，SEND/WRITE 若 SIGNALED 出 CQE（:1079-1085），READ 已在 ORQ 记账只需跳过（:1087-1091），然后锁内 `siw_activate_tx` 取下一件并 goto next_wqe（:1101-1109）；-EAGAIN——socket 发送缓冲满，**游标留在 c_tx 里**（ctrl_sent/bytes_unsent/sge_idx/sge_off），等 write_space 回调唤醒（siw_qp.c:285-286→siw_sq_queue_work）；-EINPROGRESS——burst 额度用尽，交棒 kthread 接力（:1118-1119）；错误——READ 先回滚 ORQ 槽（:1142-1146，loopback 下响应可能已到），cm_drop 断连 + 出 LOC_QP_OP_ERR 完成 + IB_EVENT_QP_FATAL（:1151-1163）。

**第 3 层——单 WQE 推进 `siw_qp_sq_proc_tx`**（:890-1002）：WR_QUEUED 起步先 `siw_check_sgl_tx` 解析并锁定各 SGE 的内存对象（:913-918，lkey>>8 查 idr），inline 则改指向 WQE 内嵌缓冲（:922-927）；`siw_qp_prepare_tx`（:176-323）按 opcode 从 `iwarp_pktinfo` 拷控制字模板（:188/:213-218/:233/:246——SOLICITED 的 SEND 换用 SEND_SE 模板 :211-218），小载荷（≤MAX_HDR_INLINE 且单 SGE）由 `siw_try_1seg`（:90-163）直接拼进头缓冲一次成型返回 PKT_COMPLETE，否则 PKT_FRAGMENTED 进入分段模式；每发一段 burst 减一（默认 SQ_USER_MAXBURST=10，siw.h:84），归零返回 -EINPROGRESS（:944-948）；`siw_prepare_fpdu`（:763-816）按 MSS 预算裁段——`tcp_seglen` 不够就削减 bytes_unsent 并清 DDP_FLAG_LAST（:788-801），MSG_MORE 决策在 siw_tx_hdt 尾部（:630-635：剩余 seglen ≥ MPA_MIN_FRAG 且还有活干就攒段，否则立刻吐出）。

**第 4 层——socket 推送 `siw_tx_hdt`**（:480-719）：组一个 kvec 数组（上限 MAX_ARRAY=64KB/PAGE_SIZE+2*(SGE-1)+2，:474），头、各 SGE 逐页（kmap 或 page_array）、pad+CRC trailer 各占 iovec 槽；三类源：内核 KVA 直引（:532-547）、用户页 kmap 拷贝（:562-564）、sendpage 零拷贝（:637-646 走 `siw_0copy_tx`→`siw_tcp_sendpages` :369-425，优先调用内核 do_tcp_sendpages 整页数组推送，未导出则逐页 sendpage）。部分发送时按实际字节数重算游标（:687-714）。CRC 与数据同程流式计算（siw_crc_array/crc_page，:540-574）。

## 三、外部连接

上游四路触发：doorbell（用户快路径）、post_send 直发（内核态走 siw_sq_queue_work :1193-1194）、write_space 回调（缓冲恢复）、接收侧 RRESP 工单（`siw_init_rresp` 在 TX 空闲时直接占用 tx_wqe 并 siw_sq_queue_work，siw_qp_rx.c:716-717；忙则挂 IRQ，由 `siw_activate_tx` 优先于 SQ 消费，siw_qp.c:800-821）。下游：kernel_sendmsg/sendpage 进 TCP；错误出口连 CM（siw_qp_cm_drop）。共享：iwarp_pktinfo 模板、CQ 完成出口（siw_sqe_complete）。

## 四、数据流

单 WQE 的一生：`SQE（用户环/内核环）→ activate_tx 抄入 wqe_active（含 inline 数据与 ORQ 记账）→ check_sgl 锁内存 → prepare_tx 出头模板 → [完整短包一次 sendmsg] 或 [prepare_fpdu 循环：算段→tx_hdt 推送→EAGAIN 存档/write_space 续传] → SIGNALED 出 CQE → 取下一件`。burst 10 段用尽即让出 CPU 交棒 kthread——用户上下文不做长工是设计而非缺陷。

## 五、设计决策

1. **kthread 为主 workqueue 为备**：kthread 可绑核（与 RSS/应用核亲和）、可忙等降延迟；workqueue 代码保留为编译期备选（:1212）。耐人寻味的是 `siw_sq_worker_init` 无条件分配 "siw_sq_wq"（:1192-1200，siw_main.c:666 必调）而 kthread 模式下它没有任何消费者——纯粹的装配线残留。
2. **零拷贝三条件**（:314-320 + IMPLEMENTATION.txt:47-57）：zcopy_tx 开、载荷>SENDPAGE_THRESH(PAGE_SIZE)、非 SIGNALED 且非 READ——完成语义只保证"已交 TCP"，TCP 重传窗口内用户改缓冲会毁数据毁 CRC，SIGNALED 的 WR 不能冒这个险。
3. **burst 限流防饿死**：单 WQE 最多连发 10 段就让出，长 WRITE 不准独占执行体。
4. **游标续传**：-EAGAIN 时所有进度存在 c_tx，恢复时从断点继续而非重发——TCP 字节流的有序性使这成为可能。
5. **SIW_TX_FULLSEGS 是死代码**（:805-808/:818-833/:954-958 永假分支），别把"整段预检发送空间"当成已实现行为。

## 六、新人提示

1. 排查发送卡死看三个旋钮：tx_cpu_list（TX 线程在哪些核，dmesg "Started siw TX thread on CPU n" :1307）、zcopy_tx（对照 perftest 带宽差异可能巨大）、low_delay_tx（吞吐 vs CPU 占用）。
2. 读 -EAGAIN 续传逻辑先认清四个游标：ctrl_sent（头已发）、bytes_unsent（本段剩余）、sge_idx/sge_off（SGE 内位置）——siw_tx_hdt:687-714 的重算代码是全文件最烧脑一段，配合 dprint DBG_TX 单步。
3. in_syscall 标志（:539）决定 siw_try_1seg 取用户数据用 copy_from_user 还是 kmap（:109-116）——上下文敏感，改代码时别弄丢。
4. 错误注入实验：用 `iptables -j DROP` 制造对端无响应，观察 sq_process 错误出口→cm_drop→QP_FATAL→CQ FLUSH 的完整链条，比读十遍代码记得牢。
5. 主线版（内核 5.x）已删 workqueue 备选与 siw_sq_wq 残留、kthread 改为每 CPU 单实例 llist 轮转——对照阅读能看清这条流水线的演化方向。
