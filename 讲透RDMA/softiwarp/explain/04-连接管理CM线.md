# 04 · 连接管理 CM 线：TCP 之上再握一次手，socket 回调的两级易主

> 仓库 zrlio/softiwarp @ 5d8a418 · 本文行号锚全部经源码核实

## 一、角色定位

RDMA 消费者眼里的"建连"是 rdma_connect/rdma_listen/rdma_accept，落到 siw 就全部进 siw_cm.c（1952 行）。它要做两层翻译：**协议层**，在 TCP 三次握手之上再跑一遍 MPA request/reply 握手（协商 CRC、交换 private data、互相验明 MPA revision 与魔数 key）；**事件层**，把 socket 的四个内核回调翻译成 iw_cm 事件上抛给 OFA CM。核心对象是 CEP（Connection EndPoint，siw_cm.h:74-108）——CM 阶段的 socket 代理人，握完手把 socket 移交 QP。IMPLEMENTATION.txt:69-73 作者自评："三个状态机（socket、QP、CEP）的交互趋于混乱，现有 CM 代码已知有 bug"——读这篇既看机制也看作者留给后人的警示。

## 二、内部结构

**CEP 八态**（siw_cm.h:48-57）：IDLE→LISTENING→CONNECTING→AWAIT_MPAREP（主动侧）或 AWAIT_MPAREQ→RECVD_MPAREQ（被动侧）→RDMA_MODE→CLOSED。CEP 自带 kref 引用计数、in_use 互斥（:235-269 自旋等待）、4 个预分配 work、MPA 收包游标（bytes_rcvd 支持分片到达）与保存的原生 socket 回调。

**socket 回调劫持与还原**：`siw_cep_socket_assoc`（siw_cm.c:165-173）把 sk_user_data 指向 CEP 并 save+install 四回调（state_change/data_ready/write_space/error_report，:102-110）；解散时 `siw_socket_disassoc` 还原（:134-150）。sk_to_cep/sk_to_qp 两个宏（siw_cm.h:150-151）靠 sk_user_data 区分当前主人——这是两级易主的全部机关。

**五类延迟工作**（siw_cm.h:113-119）由 `siw_cm_work_handler`（siw_cm.c:890-1122）消费：ACCEPT（TCP_ESTABLISHED 后接受新连）、READ_MPAHDR（MPA 头到达）、CLOSE_LLP（本端要求断连）、PEER_CLOSE（对端关闭）、MPATIMEOUT（10s/5s，siw_cm.h:110-111）。工作队列是 **create_singlethread_workqueue("siw_cm_wq")**（:1939）——单线程保证 CEP 状态迁移严格串行。

**回调→工作翻译表**：`siw_cm_llp_state_change`（:1219-1265）把 TCP_ESTABLISHED 译成 ACCEPT（:1247）、TCP_CLOSE/CLOSE_WAIT 译成 PEER_CLOSE（:1251-1256，顺带 tx_suspend）；`siw_cm_llp_data_ready`（:1162-1196）只在 AWAIT_MPAREQ/REP 状态关心数据（:1184-1188），RDMA_MODE 下静默忽略——因为此时回调已归 QP。

**MPA 握手三部曲**：

- 主动侧 `siw_connect`（:1298-1449）：sock_create→`kernel_bindconnect`（:1268-1295，SO_REUSEADDR+阻塞 connect，注释自承"为简化用阻塞模式"）→ nodelay → 建 CEP 并互挂 qp/cep → 组 MPA 头（revision 1、key "MPA ID Req Frame"，:1397-1403，iwarp.h:52）→ `siw_send_mpareqrep` 送出（:1405）→ 进 AWAIT_MPAREP 并上 10s 超时（:1412）。
- 被动侧 accept 线：`siw_accept_newconn`（:785-887）在 LISTENING CEP 上 kernel_accept(O_NONBLOCK)（:811），新 socket 配新 CEP、继承监听者的原回调、进 AWAIT_MPAREQ（:848）；**若 accept 时数据已排队则立即尝试解析 MPA req**（:859-875）——快路径消化"握完 TCP 马上发 MPA"的正常客户端。`siw_proc_mpareq`（:619-693）收头验 key/revision（:630-638），对 MARKERS 一律拒绝、对 CRC 按 mpa_crc_required/mpa_crc_strict 两参数矩阵处置（:644-673，默认 strict=1/required=0：对端要 CRC 且本端没要求——按 RFC 5044 必须接受），随后 upcall CONNECT_REQUEST 把决定权交给 IWCM/应用（:688）。
- 应答线：应用调 `siw_accept`（:1465-1609）——校验 RECVD_MPAREQ、ord/ird 上限（:1510），然后**先把 socket 回调交给 QP（经 siw_qp_modify 的 socket_assoc），再发 MPA reply**（:1557-1573）——函数头注释（:1460-1464）解释了顺序：reply 可能让对端立刻发出首个 RDMA 消息，回调必须先就位。主动侧 `siw_proc_mpareply`（:696-779）收 reply、验 key/REJECT 位/CRC 矩阵（:711-742），以五属性掩码推 QP 直达 RTS（:743-765），CEP 进 RDMA_MODE（:770）。

## 三、外部连接

上抛：`siw_cm_upcall`（:336-376）组装 iw_cm_event（CONNECT_REQUEST 携 private_data、ird/ord 与 provider_data=cep；CONNECT_REPLY/ESTABLISHED/CLOSE/DISCONNECT 等）交给 cm_id->event_handler。下发：iw_cm 八回调在 siw_main.c:460-467 注册。横切：`siw_qp_cm_drop`（:385-454）是全仓断连总闸——TX/RX 引擎错误路径（siw_qp_tx.c:1151-1152、siw_qp_rx.c:1339）都汇聚到它；schedule=1 时（softirq 上下文）排队 CLOSE_LLP 工作延后处理，schedule=0 时（进程上下文）原地关 socket、按 CEP 状态补报事件（:412-438）。监听侧多宿主：wildcard 监听为每个本机 IP 各建一个监听 socket（`siw_create_listen` :1830-1909 的 for_ifa 循环 :1869-1894），listener 的 id->provider_data 指向 CEP 链表（三种用法见 :1723-1742 注释）；IPv6 直接 -EAFNOSUPPORT（:1900-1904）。

## 四、数据流

主动侧全时序：`rdma_connect → siw_connect：TCP SYN/ACK（阻塞）→ MPA req[16B key+params+private] → (对端 proc_mpareq→upcall→应用 accept→MPA rep) → siw_proc_mpareply：QP→RTS、socket 回调易主、CEP→RDMA_MODE → upcall CONNECT_REPLY → 应用收到"已建连"`。此后同一 socket 的 data_ready 不再进 CM（:1179-1182 的 break 分支），而是 siw_qp_llp_data_ready（siw_qp.c:156）直接驱动接收引擎。拆除：FIN 到达→PEER_CLOSE 工作→RDMA_MODE 下连发 DISCONNECT+CLOSE 两事件（:998-1007）→release 路径调 siw_qp_llp_close 推 QP 入 ERROR、flush 全部队列（:1089-1104）→关 socket 还原回调。

## 五、设计决策

1. **MPA 握手不能省**：TCP 只给字节流，MPA 用 16 字节魔数 key 互相确认"对面真的是 iWARP 对端"，并一次性谈定 CRC——这是 RFC 5044 的设计，siw 忠实照搬且把协商矩阵做成模块参数可调（mpa_crc_required/mpa_crc_strict，:58-61）。
2. **回调易主而非新建 socket**：CM 与数据面共用一条 TCP 连接，靠替换 sk_data_ready 实现阶段切换，零迁移成本；代价是所有回调都要先判 sk_user_data 归属。
3. **单线程 workqueue 保序**：CEP 状态迁移不允许并发重入，in_use 互斥+单线程队列双保险。
4. **accept 先装回调后发 reply**：防竞态的顺序敏感设计（:1460-1464），改动此处前先读懂这条注释。
5. **阻塞 connect**：简化实现，连接风暴下主动侧建连延迟不可控——作者标注"可能要重考虑"（:1331-1335）。

## 六、新人提示

1. 调连接问题盯三个状态机各在哪态：CEP 态在 debugfs `<dev>/ceps`；QP 态在 `qps`；TCP 态用 ss 看。三者错位（如 CEP 已 CLOSED 而 QP 还 RTS）就是竞态或 bug 现场。
2. **private data 上限 MPA_MAX_PRIVDATA = RDMA_MAX_PRIVATE_DATA**（iwarp.h:51），rdma_cm 用户传入超限会在 connect/accept 入口被拒（:1309/:1521）。
3. `siw_recv_mpa_rr`（:527-610）自带协议违规探测：private data 收满后再 MSG_DONTWAIT 试读 4 字节（:568-581/:594 的 to_rcv+4），对端多发一个字节即 -EPROTO——精细但易被误读成 bug，读代码时注意。
4. tcp_nodelay 默认 0（:62）：MPA 头这类小包会被 Nagle 攒住，低延迟场景可 `insmod siw.ko tcp_nodelay=1`。
5. 动手：在 siw_cm_upcall（:375 附近）加 dprint 打印 reason，跑一次 perftest，可按序看到 CONNECT_REQUEST/CONNECT_REPLY（或 ESTABLISHED）/DISCONNECT/CLOSE 的完整事件流。
