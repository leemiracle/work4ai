# 07 · 内存管理线：pin 页、散射表与一场善意的 DMA 欺骗

> 仓库 zrlio/softiwarp @ 5d8a418 · 本文行号锚全部经源码核实

## 一、角色定位

siw_mem.c（428 行）是 siw 的"硬件 MMU+DMA 引擎"替身，回答两个问题：**应用注册的用户内存如何被内核安全地长期持有**（pin 页）；**没有 DMA 硬件时"DMA 地址"是什么**（答案：一场身份冒充）。RDMA 的核心承诺是"内核不碰数据"，但内核必须先保证数据所在的页不会被换出、被迁移、被 COW——这正是本篇的主线。IMPLEMENTATION.txt:80-84 自述设计立场：siw **抛弃了 OFA core 的用户页管理框架**，改用私有函数 pin 页并维护，访问权限只在网络路径真正访问的那一刻才校验（惰性校验）——与硬件 RNIC 在 MR 注册时预验的模型相反。文件后半的 20 来个 DMA 函数全是恒等映射或空操作，是理解"软件 RDMA 到底软件在哪"的钥匙。

## 二、内部结构

**支柱一：`siw_umem_get`（siw_mem.c:114-185，整 72 行）——用户内存变内核驻留页**。流程五步：① `can_do_mlock()` 门槛（:121，无 CAP_IPC_LOCK 的进程受 RLIMIT_MEMLOCK 约束）；② 页数计算——首页向下对齐 `start & PAGE_MASK`（:127），尾部 `PAGE_ALIGN` 进位（:128），跨越两个半页的注册会产生 num_pages+1；③ **配额闸门**（:137-147）：持 `current->mm->mmap_sem` 写锁读 `RLIMIT_MEMLOCK >> PAGE_SHIFT`，`num_pages + mm->pinned_vm` 超限即 -ENOMEM——dprint 会打出"pages req/limit/pinned"三元组，是排查注册失败的第一现场；④ chunk 数组分配（:150，`num_chunks = (num_pages >> CHUNK_SHIFT) + 1`）；⑤ 双层循环钉页（:156-175）：外层按 512 页一个 chunk 切，内层调 `get_user_pages(first_page_va, nents, 1, 1, plist, NULL)`——两个 1 分别是 write/write_force，**可写钉死**；返回值 got 可能小于请求量，循环用 `first_page_va += rv * PAGE_SIZE` 推进重试（:163-172），`mm->pinned_vm += rv` 同步记账（:169）。

**二维页表**：`struct siw_umem`（siw.h:207-216）持 `page_chunk` 数组，每 chunk 512 个 `struct page *`（CHUNK_SHIFT=9，siw.h:698-701）。地址→页的翻译由 `siw_get_upage`（siw.h:711-717）完成：`page_idx = (addr - fp_addr) >> PAGE_SHIFT`，`chunk_idx = page_idx >> CHUNK_SHIFT`，两级位移即得。这是为收发路径（06 篇的 siw_rx_umem、05 篇的 TX sge 遍历）准备的 O(1) 查页表，等价于硬件 RNIC 的 MR 页表（PBL），只是存在主机内存里。

**释放路径 `siw_umem_release`（:77-112）**：先逐 chunk `put_page`（siw_free_chunk :67-75），再处理记账回滚。妙处在 :93-107——若 `down_write_trylock(&mm->mmap_sem)` 拿不到锁（释放常发生在 MR destroy 的进程上下文，锁可能被持有），不阻塞等待而是**挂 work 延迟记账**（siw_umem_update_stats :50-65）：拿锁、`pinned_vm -= num_pages`、`mmput`、再 kfree 整个 umem。注意 mm 引用是在 :90 `get_task_mm(task)` 时取得、由延迟路径消费的——失败路径（:179-184，rv<=0 时）也会走完整 release，钉了多少回滚多少，无泄漏。

**支柱二：DMA 欺骗层（:188-428）**。两套 ops：`siw_dma_mapping_ops`（:296-308，挂进 ib_device 供 verbs 核心调用）与 `siw_dma_generic_ops`（:413-428，挂在 siw_main.c 的 `siw_generic_dma_device` 上供内核 DMA 子系统查询）。内容高度一致且"什么都没做"：

- `siw_dma_map_single`（:199-204）：返回 `(u64)kva`——注释直言"siw 用内核虚拟地址做数据传输"；
- `siw_dma_map_page`（:213-227）：`page_address(page) + offset`，但**跨页即返回 0**（:221 的 `offset+size <= PAGE_SIZE` 检查），调用方会当作 mapping error（:194-197 判 dma_addr==0）；
- `siw_dma_map_sg`（:236-254）：散射表逐项填 `sg->dma_address = page_address(sg_page(sg))`，唯一动作是**有效性检查**（:246，page_address 为 NULL 即弃）——注释"just a validity check"点破其存在意义；
- `siw_dma_alloc_coherent`（:275-288）：`alloc_pages + page_address`，"coherent"名不副实——本无设备缓存一致性问题；
- 全部 unmap/sync（:206-273）是 NOP；
- `.is_phys = 1`（:427）向内核声明这是**物理连续地址 DMA 设备**——对内核 DMA API 而言这是最老实的软件设备。

## 三、外部连接

上游：`siw_reg_user_mr`（siw_verbs.c:1559-）在 verbs 层收到 ibv_reg_mr 后于 :1601 调 `siw_umem_get(start, len)`，失败时 dprint 打印"LOCKED:%lu, LIMIT:%lu"（:1603）。下游：收发引擎消费 `siw_get_upage` 查页（siw_qp_rx.c 的 siw_rx_umem :125-199 逐页 kmap_atomic 放置；siw_qp_tx.c 的 siw_sge_... 遍历发送）；siw_obj.c 的 `siw_mem_id2obj`（siw_obj.h:92）按 STag 反查内存对象（STag>>8 是 obj id，见 06 篇 WRITE 路径）。横切：debugfs 无内存视图，MM 调试走 DBG_MM 掩码（siw_debug.h）；perm 校验在 siw_check_mem（访问时校验 PD/边界/rwrite 权限）。userlib 侧的 siw_mr（userlib/src/siw.h:76-81）只存 fbo/len/pbl_addr 元数据，页表完全在内核——mapped 快路径（10 篇）的 post_send 直接传 laddr/lkey，数据搬运仍由内核完成，用户态只是省了提交 WQE 的 syscall。

## 四、数据流

注册流：`ibv_reg_mr → uverbs → siw_reg_user_mr → siw_umem_get：[mlock 限额检查 → chunk 数组 → get_user_pages 钉页（writable）→ pinned_vm 记账] → 返回带 STag 的 MR`。此后数据面访问该 MR 的页全部直抵物理页：RX 放置（06 篇）kmap+skb_copy_bits 一步写入；TX 发送经 `siw_dma_map_sg` 的恒等映射拿到 KVA，kernel_sendpage 直接以页为单位送 TCP——**绕过 page cache 与协议栈的用户态拷贝**。释放流：`dereg_mr → siw_umem_release：[put_page × N → pinned_vm 回滚（或延迟 work）→ kfree]`。

## 五、设计决策

1. **私有页管理而非 OFA core 框架**（IMPLEMENTATION.txt:80-84）：2008 年代的 OFA 核心页管理 API 演进快、抽象重；siw 自带 72 行小实现，换来对记账与锁时序的完全掌控。代价是本篇这些代码与后来内核的 mm API（如 pinned_vm 记账规则、gup 参数签名）耦合紧——主线内核版 siw 此函数已随 upstream API 重写。
2. **惰性权限校验**：注册时不验 VMA 权限，访问时由 siw_check_mem 兜底——简化注册快路径，错误延迟暴露（攻击面考量上，硬件 RNIC 通常在注册时即验）。
3. **512 页 chunk**：二维结构限制单次 kzalloc 不超过 512 指针（4KB），1GB MR 需要 512 个 chunk——避免大 MR 一次分配大块连续内存。
4. **trylock 失败走延迟 work**（:93-107）：释放路径不冒进睡眠等锁，宁可延后记账——工程上保守正确，代价是 pinned_vm 短暂滞后。
5. **DMA ops 保留完整形状**：明知全空仍实现两套 ops 接口，因为 ib_device 与内核 DMA 核心都按接口多态调用——**软件设备对内核的礼貌**，删除它们 siw 将无法注册为 ib_device。

## 六、新人提示

1. **"DMA 地址 == 内核虚拟地址"不是 bug 是设定**：读任何 siw 数据面代码遇到 dma_addr 直接当 KVA 理解；反之在真 RNIC 驱动（如 mlx5）读到的 bus address 语义在这里不存在。
2. `siw_dma_map_page` 跨页返回 0 的边界（:221）值得琢磨：为什么单页 API 不处理跨页？——调用方（TX 引擎）保证 SGE 已按页边界切好（siw_check_sgl 的职责），跨页请求本身就是契约违反。
3. 调试内存注册失败：先看 ulimit -l，再看 dprint 的"pages req/limit/pinned"（:142-144）；注意 pinned_vm 是**整个 mm 累计**——多个进程/多个 MR 共享一份配额。
4. `get_user_pages(first_page_va, nents, 1, 1, ...)` 的两个 1 表示 FOLL_WRITE|FOLL_FORCE 老语义（按 3.x 内核位置参数）；对照新内核 GUP API 迁移时这是必改点。
5. 动手：在 siw_umem_get 返回前打印 num_pages/num_chunks，跑一个注册 2MB+1 字节 buffer 的程序，验证页数进位与 chunk 数组的关系。
