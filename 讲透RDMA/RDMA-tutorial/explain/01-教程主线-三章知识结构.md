# 01 教程主线：三章知识结构

> 对象：`tutorial.md`（343 行）；行号锚均于 2026-11-11 对照 commit `c760004` 源码核实。

## 一、角色定位

`tutorial.md` 是整个仓库的脊柱——四板块（example code/interview/paper）全部由它派生或被它索引，根 `README.md:3` 一句「详细的内容见tutorial」把主话语权交给本文件。它在图谱中独占 L02 层（教程线），是 16 步 tour 第 2-4 步的宿主。定位上它是**中文 RDMA 入门的叙事主线**：从「为什么需要 RDMA」讲到「怎么写 RDMA 程序」再讲到「学术界在研究什么」，一份文件完成动机→动手→前沿的三级跳。

## 二、内部结构

全篇按「三主章+三附属章」组织，主章承载知识递进：

二章内部又是一条精密的递进链：2.1（L63）用六步文字+微观传输图拆解一次 send/recv；2.2（L80）抛出五参数（QP 类型/verb/inline/signal/poll 策略，L84-L88）；2.3（L96）按建连（L100）→注册内存（L159）→发起接收（L167）→发起发送（L181）→poll 完成（L197）五小节把参数逐一落进代码；2.4（L220）叠加 write/read 单边语义；2.5（L237）交棒给示例代码；2.6（L243）做 inline/verb/poll 三组性能对比实验；2.7（L283）以 TensorFlow 分布式训练收束到应用。**「概念→参数→代码→实验→应用」五级递进**是本章的骨架设计。

三章三分法对应三个研究层次：3.1 传输层/应用层（L305，加速应用、编程库、QP 共享、自动化工具）、3.2 网络层/链路层（L312，拥塞控制、多路径）、3.3 虚拟化（L317，容器云）——恰好是 paper 板块 11 篇笔记的分类骨架。

## 三、外部连接

本文件是全仓的链接枢纽：2.5 节（L237-L241）两个链接分别指向 rdma_send_recv 与 rdma_write_read 两组示例，即教程线→示例线的官方入口；三章（L303）与四章（L321）合起来构成 paper 板块的目录与阅读理由；五章（L325）指向 interview。文末 11 条参考（L331-L341）与 paper 笔记一一呼应：1=HERD、6=RFP、7=Resource Sharing、8=Revisiting Network Support for RDMA、9=HPCC、10=Multi-Path、11=FreeFlow，引文可当 paper 线的检索表用。插图全部走 GitHub URL 形式（如 L12 软件协议栈图），本地对应 `image/` 目录 17 个文件——**离线阅读时图挂掉，去 image/ 找同名原图**。教程与代码的连接是双向的：示例文件里没有任何注释回指教程，映射关系只存在于 2.5 节与 `example code/README.md:3-4` 两处索引里。

## 四、数据流

学习者的知识流动路径为：一章建立词汇表（QP/CQ/RNIC，L32-L34）→ 2.1 微观流程给 QP/CQ 第一次动态画像（L67-L72 六步）→ 2.2 五参数成为后续所有内容的「索引键」→ 2.3/2.4 代码逐行用参数键查落点 → 2.6 用实验验证参数选择的性能后果（L245 明言「设计大量对比实验观察参数影响」）→ 2.7/三章把参数选择问题升级为研究问题（L291 点破「忽略了应用自己的特性以及服务器的资源状态」——这句正是 LITE/HERD 等 paper 笔记的问题意识来源）。参数是贯穿全篇的数据总线：一章末尾的 RNIC 组成（L30-L34）为 2.1 的队列行为供硬件落点，2.6 的实验图为 2.7 的工程结论供证据。

## 五、设计决策

①**参数为纲**而非 API 为纲：2.2 把 RC/UC/UD、verb、inline、signal、poll 五个「选择题」前置（L84-L88），后面 2.3-2.6 全部围绕「这些题怎么选、选了会怎样」展开——这是性能工程师视角的教程组织法，区别于 man page 式罗列。②**perftest 先行**：二章开头（L50-L61）先给 `ib_send_lat` 实测 1.5us 的震撼，再进入编程细节，「先尝甜头再付学费」的教学排序。③**代码即教材**：2.3 五小节的代码块直接摘自示例（如 L202-L217 的 poll_cq 与 rdma-common.c:242-257 同构），但 2.4 的四行单边骨架（L227-L230，`M.remote_addr`/`M.rkey` 写法）是 rdma-common.c:215-226 的浓缩——语义一致、变量名不同，`M` 即 `conn->peer_mr`，**并非逐字拷贝**（ONBOARDING 称「一字不差落地」，此处再勘误）。④两处已知笔误：节号 2.6.2 重复（L259 与 L271，后者应为 2.6.3）；L90 承诺「具体参数选择处会用黄色背景标注」，但 markdown 源码无任何高亮标记，承诺未兑现。⑤2.3.4 示例代码含 `IBV_SEND_INLINE`（L187），而两组示例实际只用 `IBV_SEND_SIGNALED`（rdma-common.c:320、send_recv/client.c:239）——教程展示的是参数全集，代码取的是默认子集。

## 六、新人提示

按 1→2.1→2.2→2.3→2.4 顺序读，2.5 处停下转到 `example code/` 对照，再回来读 2.6/2.7。读 2.2 时把五参数抄成卡片——后面每篇 paper 笔记都在回答其中某一题（HERD 答 verb+poll、HPCC 答拥塞、LITE 答资源共享）。三个易踩点：图挂时去 image/ 目录找原图；2.6.2 有两个，第二个才是 poll 实验；教程代码块与示例代码存在「浓缩改写」，逐行核对时以示例源码为准。面试前直接跳五章转 interview 板块，三章的三分法可当答题框架。
