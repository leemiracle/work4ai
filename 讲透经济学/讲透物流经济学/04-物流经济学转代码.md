# 04 · 物流经济学转代码：从公式到仓网

> **本章回答五问之五（本家族：讲透物流经济学）。**
> 三件套：**可机械化边界**、**代码走廊**、**工程师落点**。
> 物流是经济学家族里代码化最深的领域之一——因为它天生就是优化问题。

---

## 一、可机械化边界（为什么边界画在这里）

| 问题类 | 可机械化程度 | 边界原因 |
|--------|-------------|---------|
| EOQ/报童/安全库存 | ✅ 完全 | 闭式解，几行代码 |
| (s,Q)/(s,S) 连续检查 | ✅ 完全 | 策略仿真+网格搜索即得 |
| 啤酒游戏/牛鞭复现 | ✅ 完全 | 确定性结构+随机需求仿真 |
| 仓网选址（设施定位 MILP） | ✅ 完全 | NP-难但可解（OR-Tools/CPLEX） |
| 多级多期库存协调 | 🟡 半机械 | 维度灾难；近似（保证服务水平传播）可行 |
| 需求预测 | 🟡 ML 接管 | 预测≠决策：预测误差→库存决策的映射仍靠闭式 |
| 供应链博弈（多主体谈判） | ❌ 尚未 | 无势函数，均衡存在性无保证 |
| 供应链金融风控 | ❌ 尚未 | 信息结构与激励问题未定形 |

**判据一句话**：单主体权衡全部闭式（优化），多级树状结构可 MILP，
带博弈与信息不对称的留给机制设计（未来）。

## 二、代码走廊（五条）

### 走廊①：EOQ 与报童（本家族实验）

[`experiments/eoq_newsvendor.py`](experiments/eoq_newsvendor.py)：纯 numpy/math
实现——EOQ 闭式 vs 百万格点数值解；成本曲线平坦性断言（1.5Q*→≤1.084）；
报童正态需求分位数解 vs 期望利润格点。核心模式：

```python
Q_star = np.sqrt(2*D*S/H)                    # EOQ
TC = lambda q: D/q*S + q/2*H                 # 成本曲线（凸）
Q_nv = mu + sigma*norm_ppf(cu/(cu+co))       # 报童：分位数（norm_ppf 手写）
```

### 走廊②：√n 法则三行验证与网络模拟

```python
n = np.arange(1, 101)
central = z*np.sqrt(L)*sigma                 # 1 仓安全库存
decentral = n*z*np.sqrt(L)*sigma             # n 仓（独立需求）
assert central / decentral[99] == 1/10       # 100仓并1仓 = 1/√100
```
扩展为仓网模拟：n 仓→k 仓的重定位决策，输出（库存成本，时效）前沿。

### 走廊③：啤酒游戏（牛鞭复现）

四层（零售-批发-分销-工厂），每层"订货=预测（移动平均）− 在库−在途"的
**理性规则**，需求端一个 5% 脉冲。100 行 numpy/纯 python，输出各层订单方差
序列——断言**工厂方差 > 零售方差 4 倍**（Lee 悖论的机器复现）。
教学价值大于工业价值：它是"结构产生波动"的实验证明。

### 走廊④：仓网选址 MILP（工业级入口）

```python
# min Σ_j f_j y_j + Σ_ij c_ij x_ij ; s.t. 需求覆盖、仓库容量、y∈{0,1}
solver = pywraplp.Solver(...)               # Google OR-Tools
```
参数化即真实问题：f_j=仓库固定成本（设施轴）、c_ij=运费+碳（空间轴）、
服务水平约束（时间轴）。电商仓网规划部的日常就是这个模型的放大版。

### 走廊⑤：与预测系统的接口

ML 预测输出 μ̂、σ̂（SKU×仓×周），库存引擎把 (μ̂,σ̂) 喂给走廊①公式输出
补货单——**AI 出参数，闭式出决策**。这条接口是"AI 供应链"的诚实架构，
也是 01 章参数眼的落地。

## 三、工程师落点（这些东西在谁家产线上）

1. **电商补货引擎**：百万 SKU 的 (s,Q) 自动补货+人工豁免清单（大促/新品）。
2. **仓网规划系统**：年度性 MILP 重跑+情景压力测试（韧性约束）。
3. **快递路由与分单**：与[讲透交通运输经济学](../讲透交通运输经济学/)
   04 章共管的网络流世界。
4. **供应链控制塔**：在途/在库可视化+牛鞭预警（订单-销售方差比监控）。

## 四、✨美之时刻（⑧要件）：啤酒游戏的方差瀑布

**陈述**：给零售端一个 ±5 的需求脉冲，跑完四层供应链，把每层的订货方差
画成瀑布图：5%→13%→28%→55%——**没有一次人为操纵，只有每层的最优预测**。
**为什么美**：*意外*——理性与秩序在系统层面合谋制造混乱；把不可见的
信息结构变成可见的方差阶梯。**怎么亲历**：走廊③改一个参数（预测窗口
长度）重跑，看瀑布如何变陡变缓——信息透明度（共享 POS 数据）是唯一的
"泄洪道"。

## 五、反直觉发现（⑥要件）

代码化边界再次反直觉：**最难的不是百万 SKU 的补货（闭式+并行，一晚跑完），
而是四个主体之间的信任设计（信息共享的激励）**——前者是计算问题，
后者是机制问题；物流学的最后一公里在制度，不在算法。

## 👁 认知升维（⑨要件）

**接口眼**：评估任何"AI+X"系统时，把 X 拆成"参数部分"与"决策部分"——
AI 只该接管参数（μ̂、σ̂），决策结构（闭式/优化）保持可解释。这条纪律
让系统既吃到 AI 的红利，又不失去审计能力。
