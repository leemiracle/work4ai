# 04 · 微观经济学转代码：均衡求解、剩余计算与机制设计走廊

> **本章回答五问之五（本家族：讲透微观经济学）。**
> 微观资产的代码化分五条走廊：**均衡求解（供需/CGE）→ 剩余与福利计算
> → 拍卖与机制（VCG/组合）→ 离散选择与需求估计（logit）→ 显示偏好
> 检验（GARP/Afriat）**。微观的可机械化边界出奇地清晰：
> **凡能写成"最优化+均衡"的部分几乎全自动，凡涉及"调整过程与
> 均衡选择"的部分无门**——恰是 03 章三幕剧的代码投影。

## 一、五条走廊总表

| # | 走廊 | 输入→输出 | 代表工具/方法 | 自动化档位 |
|---|------|----------|--------------|-----------|
| 1 | 均衡求解 | 供需/偏好技术→价格数量 | scipy.optimize.root（局部）；CGE 求解器/MCP | ✅ 局部全自动 / ⚠️ CGE 半自动 |
| 2 | 剩余与福利 | 均衡+扰动→CS/PS/DWL | 数值积分（梯度/自适应）；对偶恢复 | ✅ 全自动 |
| 3 | 拍卖与机制 | 估值分布→分配与支付 | VCG/组合拍卖 LP（SotS）；近似机制 | ✅ 小规模全自动 / ⚠️ 规模爆炸 |
| 4 | 离散选择 | (特征,选择)面板→需求弹性 | Logit 族（MNL/混合）、BLP 估计 | ✅ 全自动（统计性质好） |
| 5 | 显示偏好检验 | (价格,购买)数据→理性判定 | GARP 环检测（Warshall 传递闭包） | ✅ 全自动 O(n³) |

## 二、逐条速写

### 走廊 1：均衡求解——z(p)=0 的工程学

**最小版（本家族实验主场）**：线性供需两条线，均衡=一次求根。

```python
# z(p) = demand(p) − supply(p)；均衡 ⟺ z(p*)=0
p_star = scipy.optimize.brentq(z, lo, hi)     # 单调 z 时区间法稳如泰山
```

[experiments/supply_demand_surplus.py](experiments/supply_demand_surplus.py)
的三件套：①数值均衡 vs 解析均衡（断言）；②税收楔子后买方/卖方价
（断言 vs 结构公式）；③需求端扰动后均衡比较静态（断言方向）。
**为什么"局部均衡"全自动**：一个市场一个未知数，单调性保证唯一根。

**工业版（CGE/MCP）**：n 个市场一般均衡=混合互补问题
（MCP：z(p)⊥p 约束），PATH 求解器是事实标准；GAMS/GEMPACK 是
老牌载体。半自动的原因：规模上去后不动点求解要初始点运气+结构
利用（如 SAM 校准），且 03 章的多重均衡风险回来了。

### 走廊 2：剩余与福利——把"好多少"算成数

```
消费者剩余 CS = ∫₀^Q* [D(q) − p*] dq     （需求曲线下、价格线上的面积）
生产者剩余 PS = ∫₀^Q* [p* − S(q)] dq
无谓损失 DWL = 税收后的剩余损失 = ½·t·ΔQ（线性情形三角形）
```

**为什么这条走廊全自动**：一维定积分，数值精度即答案精度。
**工程要点**：非线性需求下 DWL 对 t 是凸函数（"小税便宜大税贵"的
数学版）——拉弗曲线的微观根基。剩余计算的妙处是把政策辩论
（"关税好不好"）变成可分解的账本（谁赚谁亏多少）。

### 走廊 3：拍卖与机制——博弈规则的代码化

| 机制 | 代码本体 | 规模边界 |
|------|---------|---------|
| VCG（说实话的拍卖） | 每人付"外部性"：求解 n 次福利最大化 | 组合爆炸（NP-hard 分配问题） |
| 二价拍卖 | 排序+一行 max | O(n log n)，网页级 |
| GSP（广告位） | 排序计费 | O(n log n)，但有非说实话均衡 |
| 组合拍卖（CA） | 整数规划+定价（Solver 调用） | 频谱级：求解器战场 |

**为什么机制设计天然可代码化**：机制=算法（规则→分配与支付），
经济学与计算机科学在此完全重叠（算法博弈论）。
数学母港：[讲透数学·讲透博弈论](../../讲透数学/讲透博弈论/)
13-14 章（拍卖与机制设计）。

### 走廊 4：离散选择与需求估计——微观计量的骨架

```
Logit：选 i 的概率 = exp(V_i/σ) / Σ_j exp(V_j/σ)   （V=可观测效用）
估计：极大似然（凸问题，收敛可靠）；弹性解析可导
BLP（1995）：内生价格用工具变量+嵌套不动点——随机系数需求系统，
反垄断实务标准（合并模拟）
```

**自动化档位**：MNL 全自动；BLP 半自动（不动点+广义矩，良初值依赖）。
需求估计是"看不见的需求曲线"的实证化身——与走廊 1 咬合：
估计出 D(p)，才能算均衡与福利。

### 走廊 5：显示偏好检验——03 章 Afriat 的算法版

```python
# 直接显示偏好矩阵 DRP：x_i ≽ x_j ⟺ p_i·x_i ≥ p_i·x_j
# GARP：DRP 的传递闭包中不得出现 x_i ≽ x_i 的"间接选择环"（且严格超支）
# Warshall 传递闭包 O(n³) —— 理性检验即图算法
```

**为什么它值得一条走廊**：这是"把哲学命题变成可执行检查"的完整样板
（03 章 §2）——需求分析的最诚实前置步骤：先验数据，再谈效用。

## 三、可机械化边界（03 章三幕的代码投影）

| 任务 | 档位 | 边界由谁把守 |
|------|------|-------------|
| 局部均衡+剩余+税负 | 全自动 | 单调性+一维求根理论 |
| 需求估计（MNL） | 全自动 | 凸似然 |
| GARP 检验 | 全自动 | 图算法 |
| CGE/MCP 大规模 | 半自动 | 多重均衡+初始点（03 章 §1.2） |
| 组合拍卖最优分配 | 半自动 | NP-hard（近似机制的理论代价） |
| 均衡选择/调整过程 | 无门 | 03 章 §3（tatonnement 悬案） |
| 内生偏好/塑造 | 无门 | 理论空缺（01/02 章不足层） |

**边界总纲**：微观的自动化程度=问题的"凸性与维度"——凸、低维、
静态的全自动；组合、高维、动态的半自动；过程与选择的无门。

## 四、工程师落点（性能工程视角）

1. **求根先于搜索**：均衡问题写成 z(p)=0 用 brentq（有界+保证收敛），
   而不是裸 minimize——一维单调问题的区间法是数值最稳的武器
   （数值纪律见 [讲透数学·讲透数值分析](../../讲透数学/讲透分析/讲透数值分析/)）
2. **断言结构公式**：本家族实验的税负分担断言=比较静态解析式；
   把"理论预言"写进 assert 是防数值漂移的最好护栏
3. **机制的延迟预算**：广告实时竞价（RTB）在 ~100ms 内完成
   拍卖——机制设计的工程实现是一门性能工程（缓存特征、预排序、
   简化机制换延迟）
4. **GARP 是数据质检**：任何偏好数据集入库先跑 O(n³) 传递闭包——
   "垃圾进垃圾出"在微观多了一道理性闸门

## 五、裂缝清单（原则上/工程上的不可转）

| 裂缝 | 性质 |
|------|------|

| 价格调整过程的模拟 | 原理性——理论未定（tatonnement 悬案） |
| 组合拍卖的精确最优 | 计算性——NP-hard（近似带理论保证） |

| 计划者偏好的加总 | 原理性——阿罗不可能定理（社会福利泛函数的禁区） |
