# 问题转 code 路由 · 讲透经济学（GB/T 790）

> **定位**：把经济学的**真实问题/任务**逐条翻译成可接单的 code 任务。
> 分工：各家族 04 章管**边界与走廊**——什么能机械化、走哪条计算走廊、
> 自动化档位在哪；本表管**具体问题怎么接单**——一句话问题 → 形式化 →
> code 任务 → 算法锚点 → 落点家族。宇宙全景见 [README](README.md)。

## 使用方法

1. **找最近邻行**：把问题在路由表扫一遍，找最像的一行（不必精确匹配；
   找不到，说明问题可能尚未形式化，先过第 2 步再回来）
2. **过形式化关**：把问句改写成数学对象——估计什么参数？解什么方程？
   比较什么反事实？写不出形式化，就还不是 code 任务
3. **按档位接单**：
   - **[A 可直接编码]**：形式化基本唯一 → 直接写代码+断言
   - **[B 需先建模]**：形式化有多种选择（识别假设/函数形式/校准）→
     先写设定页再动手，走廊选择决定成败
   - **[C 研究级开放]**：识别/校准/外推至少一环无共识 → 先读文献，
     把问题降级成可行的 A/B 子问题
4. **算法/库只是锚点不是背书**：换库自由，断言不自由（见尾部工作流）

## 三层占比与读法

| 档位 | 行数 | 占比 | 接单纪律 |
|---|---|---|---|
| A 可直接编码 | 19 | 53% | 断言先行，直接写 |
| B 需先建模 | 13 | 36% | 设定页先于代码；识别假设要人签字 |
| C 研究级开放 | 4 | 11% | 先降级成 A/B 子问题；报告尝试次数 |

**读法**：A 层占多数是方法论成熟学科的常态——成熟走廊（求根/积分/凸
优化/估计量）覆盖了大部分日常问题；但价值最高的问题多在 B/C 层。B 层的
识别假设与函数形式是"脚注里那句话的责任"（数量经济学 04 章：LLM 能跑
平衡性检验，不能替你承担识别的辩护）；C 层预测类任务先过三问过滤器——
Q 世界还是 P 世界？输入多少是估计的？试了几次？（金融 04 章）。

## 通用工作流（问题→形式化→选走廊→写断言）

```text
1 问题     一句自然语言+判断标准（"效应多大算答案"先说清）
2 形式化   四选一：参数估计 / 方程求解 / 反事实比较 / 机制仿真
3 选走廊   对照家族 04 章走廊总表，锁定工具链与自动化档位
4 写断言   三选一，先于实现：
           ① 解析解对账——理论预言写进 assert
           ② 退化情形——参数推到边界退回已知结果
           ③ 方向/单调——比较静态的符号断言
5 接单     A 直接写；B 设定页先于代码；C 先降级再接
```

**走一遍样例**（第 10 行）："这笔消费税谁承担"→形式化为线性供需+从量税
的分担公式→微观 04 章走廊 1/2（均衡求根+剩余积分）→断言三件：税负分担
解析式、t→0 时 DWL→0、两个半 t 的 DWL 之和 ≥ 一个 t（凸性）→照
supply_demand_surplus 式脚本落地。

**断言先于实现**：数值对不上时，assert 给出"先怀疑理论还是先怀疑实现"
的仲裁顺序——这是本宇宙所有家族实验的公共纪律。
