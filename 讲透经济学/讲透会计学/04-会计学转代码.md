# 04 · 会计学转代码：把恒等式写成程序

> **本章回答五问之五（本家族：讲透会计学）。**
> 三件套：**可机械化边界**（什么能自动）→**代码走廊**（怎么写）→
> **工程师落点**（写完放哪）。核心判断一句话：
> 复式记账是史上第一个"自带断言的生产系统"——转代码不是
> 隐喻，是把 500 年前的不变量翻译成今日的类型系统。

---

## 一、可机械化边界（先划清，再动手）

| 环节 | 可机械化 | 形态 |
|------|---------|------|
| 分录生成（模板业务） | ✅ | 业务事件→借贷模板的映射表（ERP 自动凭证） |
| 借贷平衡校验 | ✅ | 应作**类型/约束**而非事后检查（见下） |
| 折旧/摊销/汇兑 | ✅ | 确定性公式 |
| 结账/试算/四表生成 | ✅ | 线性聚合+模板 |
| 发票查验/对账 | ✅（政策已铺路） | 数电发票结构化数据直连（01 章） |
| 五步法步骤 5（进度确认） | 🟡 | 可计量输入（工时/里程碑）可自动，"单项义务"拆分靠人 |
| 减值、公允 L3、持续经营 | ❌ | 判断——机器只配做情景计算器，签字必须是人 |

**判据**（03 章的复述）：准则答案唯一→机械；答案多重且选择重大→
必须留人。**边界不是能力边界，是责任边界。**

## 二、代码走廊

### 走廊①：总账内核——不变量当类型用（本家族实验）

```python
# 借贷不相等的分录在类型层就不存在（伪码，思想是数据库 CHECK 约束）
class Entry:
    def __init__(self, legs):           # legs = [(科目, 借|贷, 金额), ...]
        assert sum(a for _, s, a in legs if s == "借") == \
               sum(a for _, s, a in legs if s == "贷")
        # 业务不变量：任何时刻 资产 ≡ 负债+权益+净利（每笔分录后归纳保持）
```

真实系统里这个断言下沉为：数据库事务+CHECK 约束+科目余额表
双向记账（ledger 表只允许通过存储过程写入）。跑
[experiments/double_entry_depreciation.py](experiments/double_entry_depreciation.py)
看最小版本：7 笔业务、逐步断言、试算平衡输出。

### 走廊②：折旧计算器——三法一接口

直线/双倍余额递减/年数总和实现为同一签名 `(cost, salvage, life) -> schedule`；
断言三法总额相等（=cost−salvage）、期末账面=残值；
再叠加税盾现值比较（税率+折现率参数化）——
"会计政策选择"由此变成可计算的敏感性分析。

### 走廊③：RPA/数电票管道——事件驱动记账

数电发票（XML/结构化）→ 校验（金税接口）→ 自动生成采购/销售分录 →
银行流水自动对账。技术栈是平凡的 ETL+规则引擎，
不平凡的是**源数据被监管标准化了**（01 章）——
会计信息化的真正瓶颈从来不是算法，是凭证的数据结构。

## 三、工程师落点

| 场景 | 落点 | 与谁接 |
|------|------|--------|
| 企业财务中台 | 总账引擎+自动化凭证+对账 | ERP/共享中心（[计算机信息管理系统](../../讲透计算机科学技术/讲透计算机应用/讲透计算机信息管理系统/)支的工程侧） |
| 智能合规 | 发票查验、费用政策校验、异常分录预警 | [决策支持系统](../../讲透计算机科学技术/讲透计算机应用/讲透计算机决策支持系统/)支 |
| 报表自动化 | 四表一注生成、多准则换算（CAS/IFRS） | 模板引擎+XBRL 标签 |
| 数据资源入表估值 | 数据成本归集、摊销模拟 | 01 章新规的配套工具空白区 |

**为什么"总账引擎"至今没有被通用数据库原生解决**：
恒等式约束跨表（科目余额是分录流的物化视图）、
期间语义（开账/结账/反结账）是有状态的协议——
主流做法仍是专门的总账模块而非 SQL 约束，
这是"领域不变量高于通用约束"的标准案例。

## 四、反直觉发现（⑥）

**"自动记账"消灭的不是会计，是"记"——"计"反而更贵了。**
核算自动化后，价值与责任全部压向确认计量判断与准则解读：
凭证分录岗位收缩，**准则工程师/数据资产会计师**岗位出现
（01 章数据入表催生的活需求）。历次会计技术革命
（打孔机→电算化→ERP→AI）都重复同一模式：
**体力环节消失，判断环节溢价**。

## 五、✨美之时刻（⑧要件）：断言即审计（连续审计的种子）

**陈述**：把 00 章的不变量断言从"期末跑一次"改成"每笔分录实时跑"，
账本就从"期末审计的对象"变成"自证清白的流"——
持续审计（continuous auditing）的全部技术前提，
就是 500 年前的借贷规则恰好是可机械化的不变量。

**为什么美**：*统一*——帕乔利的规则、数据库的 CHECK 约束、
区块链的平衡交易，三个时代的"防错设计"是同一个代数结构；
会计的转代码史就是这条结构的载体演化史。

**怎么亲历**：在走廊①的 Entry 类里故意删掉一行断言，喂一笔
不平衡分录——观察错误延迟到试算平衡才爆炸（错误定位从"笔"退化为
"期"）；再加回来，看错误当场被拦截。**一条断言的位置，
就是审计成本的量级。**

## 📌 收束与认知升维（⑨要件）

**这章给了你什么新眼睛**：
- **约束前移眼**：校验越靠近写入点，错误成本越低——
  从期末对账到写入即断言，这个前移动作适用于一切数据系统。
- **责任接口眼**：自动化设计的关键文档是"哪些环节必须留人签字"
  ——接口清单即责任拓扑。
