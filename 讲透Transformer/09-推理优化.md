# 09 推理优化：KV Cache、量化、投机解码

> 推理 (inference) 是训练之后的事——前向无反向, 服务给用户。
> 推理优化的三大支柱: **KV Cache 管理 / 量化 / 投机解码**。

> 💡 **CS25 连接**: Charles Frye (Modal, CS25 V6) "Serving Transformers: Lessons from the Trenches"——生产推理系统的实战经验。

## 一、KV Cache: 基础 (01 篇详谈)

每生成一个 token, 只算它自己的 K/V, 复用历史缓存。复杂度每步 $O(t^2) \to O(t)$。

**显存管理**是头号难题 (LLaMA-70B 32K 上下文 ~40GB KV Cache):
- **PagedAttention** (vLLM): 把 KV Cache 像操作系统虚拟内存一样**分页管理**, 消除碎片, 支持动态 batch
- **KV Cache 量化**: 存成 FP8/INT4 (KIVI 等), 省 4-8×
- **KV Cache 压缩**: MLA (03 篇)、token 剪枝 (SnapKV)

## 二、量化: 把 FP16 压成 INT4/INT8

### 权重量化
$$W_{\text{int}} = \text{round}(W_{\text{fp}} / \text{scale})$$
- **GPTQ** (训练后): 一层一层用二阶信息校准
- **AWQ** (你学过的激活函数课 04 篇提过): 保护重要通道 (激活大的权重), 更鲁棒
- **GGUF/llama.cpp**: CPU/边缘部署的量化格式

### 精度档位
| 精度 | 显存 (相对 FP16) | 质量损失 | 场景 |
|------|-----------------|---------|------|
| FP16 | 1× | 0 | 训练/高质量推理 |
| INT8 | 0.5× | 极小 | 通用推理 |
| **INT4** | 0.25× | 小 | **本地部署主流** |
| FP8 | 0.5× | 极小 | H100 训练 (DeepSeek-V3) |

### 量化难点: 激活函数的 outlier
LLM 激活里有少数**极大 outlier** (你学过的: LLM 权重范围宽, ReLU/量化价值在 LLM)。直接量化会被 outlier 主导。AWQ 的解法: 识别 outlier 通道, 给它们单独 scale。

## 三、投机解码 (Speculative Decoding, 2022+) — 推理最大加速

### 问题: 推理是 memory-bound
生成时每步只算 1 个 token, GPU 计算单元闲置, 瓶颈是"把权重和 KV Cache 从显存读到计算单元"。这是**延迟, 不是算力**。

### 解法: 大小模型协作
1. **小模型 (draft)** 先快速猜 $k$ 个 token
2. **大模型 (target)** 并行验证这 $k$ 个 token (一次前向算 $k$ 个, 利用空闲算力)
3. 接受小模型猜对的前缀, 纠正第一个错的, 继续猜

**收益**: 大模型生成速度 **2-3×**, 输出**完全一致** (无损)。
**前提**: 小模型要猜得准 (常见: 用同家族更小的模型, 或 n-gram)。

### 变体
- **Medusa**: 给大模型加多个预测头, 同时预测多个未来 token (无需小模型)
- **EAGLE**: 用大模型自己的特征预测, 更准

## 四、连续批处理 (Continuous Batching)

传统: 一个 batch 里所有请求必须同时结束 (长短不一就浪费)。
**连续批处理 (Inflight Batching, vLLM/SGLang)**: 每步动态调整 batch——新请求随时插队, 完成的随时退出。吞吐 **2-4×**。

## 推理引擎对比

| 引擎 | 强项 |
|------|------|
| **vLLM** | PagedAttention, 高吞吐, 生态最广 |
| **SGLang** | RadixAttention (前缀复用), 复杂程序快 |
| **TensorRT-LLM** | NVIDIA 官方, 极致 GPU 优化 |
| **llama.cpp** | CPU/消费级 GPU, 本地部署 |
| **MLC-LLM** | 跨平台 (手机/浏览器) |
