# 🚀 第 5 幕 · 应用：缓存经济学

## 价格即真理（2024-2026 厂商定价）

| 方案 | 机制 | 成本节省 | 失效条件 |
|---|---|---|---|
| **Anthropic Prompt Caching** | 前缀 KV 持久化 5 分钟 | cache read 比 input 便宜 **90%**, write 贵 25% | 5 分钟 TTL；前缀改一字全失效 |
| **Gemini Context Caching** | 显式创建缓存对象 | 类似 90% off | 用户显式管理 TTL |
| **vLLM PagedAttention** | OS 虚拟内存思路管 KV | 吞吐 2-4× | 自部署 |
| **SGLang RadixAttention** | 基数树共享前缀 | 多请求共享前缀极大 | 前缀需公共 |
| **DeepSeek Context Cache** | 命中自动复用 | 显著降本 | 命中率依赖负载 |
| **Augment Context Engine** | 大规模代码语义索引 | 60 万 token 真实可用 | coding agent 专用 |

## 盈亏平衡公式

cache 命中 $k$ 次后划算的条件：

$$c_{\text{write}} + k \cdot c_{\text{cache\_read}} < (k+1) \cdot c_{\text{input}}$$

Anthropic：$1.25 + 0.1k < (k+1) \cdot 1.0$ → $k > 0.28$ → **命中 1 次就划算**。

## 三角权衡（核心决策图）

```
        RAG（外部检索）
         /  低成本
        /   高延迟（检索）
       /
       ⊙──── 长上下文（全塞进去）
        \   高成本
         \  低延迟
          \
    缓存（复用）
      命中省 90%
      未命中亏
```

**三者不是替代，是组合**：
- 长上下文 = 舞台
- 缓存 = 省**固定**成本（system prompt / few-shot / 代码库）
- RAG = 塞**动态**相关（用户查询相关）

## 场景选型

| 场景 | 推荐组合 |
|---|---|
| 客服（固定 FAQ）| prompt caching + 短会话记忆 |
| coding agent | Augment 式索引 + 缓存（整个代码库当 context）|
| 文档问答 | RAG + prompt caching（system prompt + 知识库 prefix）|
| 长对话 | prompt caching + 记忆层（超长部分转记忆）|

## 五条生产铁律

1. **确定性 prefix → prompt caching**（安全，90% off）。
2. **语义相似 → 语义缓存（高风险）**，阈值偏高（0.95+），宁可 miss 不要假命中。
3. **长期知识 → 记忆层**（`讲透记忆/`），不是缓存。
4. **监控命中率**——波动大说明工作负载不稳。
5. **隐私隔离**——多租户 cache 严格分键。

## Augment 60 万 token 的启示

不是窗口大，是 **context 管理**：大规模语义索引 + 智能检索 + 缓存。**未来长 context 的竞争力，不在窗口大小，在 context 管理**。

## 🎬 五幕收束

> 缓存是「无思考的负熵」——只认字面，不理解语义。所以分工：**prompt caching 解决重复，语义缓存试图解决相似（危险），长期记忆（`讲透记忆/`）才解决理解**。三者是认知复杂度递进。
>
> 用熵论收尾：**缓存 = 把已算好的有序状态保留 = 负熵注入**。但激进缓存（语义）会赌正确性——**生产铁律：宁可 miss 不要假命中**。
