# 01 — 检索数学：相似度、embedding、ANN

> 00 篇展示了 RAG 靠"检索"找相关文档。这一篇钻进检索的数学：**用什么度量"相似"、文本怎么变成向量、大数据怎么快速检索**。
>
> 配套实验：`experiments/01_retrieval_math.py`。

---

## 1. 相似度度量：为什么主流是余弦

三个候选：

| 度量 | 公式 | 特点 |
|---|---|---|
| **余弦相似度** | $\cos(a,b)=\frac{a\cdot b}{\|a\|\|b\|}$ | 只看**方向**，归一化到 [−1,1] |
| **点积** | $a\cdot b$ | 受模长影响，模长大的向量天然得分高 |
| **欧氏距离** | $\|a-b\|$ | 看绝对距离，受模长和方向双重影响 |

### 实验（`01_retrieval_math.py` Part 1）

```
v1=[1,2,3]  v2=[2,4,6](=2·v1,同向)  v3=[6,4,2](不同向)
        余弦    点积    欧氏
v1-v2   1.000    28     3.74    ← 同向, 余弦=1(最相似), 欧氏却最大!
v1-v3   0.714    20     5.48
```

**关键洞察**：v1 和 v2 方向完全一致（同向），语义上"最相似"，余弦=1 正确反映这点。但欧氏距离反而最大（因模长不同）。

**结论**：RAG 检索用余弦，因为"语义相似 = 向量方向相近"，**不该被文本长度（反映在模长）干扰**。点积在向量都归一化后等价余弦（所以很多系统先归一化再用点积加速）。

---

## 2. Embedding：从文本到向量

检索的前提是把文本变成向量（embedding）。两类：

### 稀疏：TF-IDF / BM25（词面匹配）

- 把文本表示成"词频权重"的高维稀疏向量。
- **只懂词面**：词不重叠就匹配不到。

### 稠密：神经 embedding（语义匹配）

- 用训练好的模型（bge、m3e、OpenAI text-embedding）把文本映成几百维稠密向量。
- **懂语义**：同义词、近义词、不同语言表达相同意思 → 映到相近向量。

### 实验（Part 2）：TF-IDF 的词面局限

```
Q: 轿车价格 → [小轿车:0.28] [其余:0.00]   ← 只匹配含"轿车"字面的
Q: automobiles → 全 0.00                    ← 中英文词面不重叠
Q: 宠物吃什么 → 全 0.00                     ← 知识库无此词
```

"轿车"和"汽车"语义同义，但 TF-IDF 词面不重叠 → 相似度低。**神经 embedding 能弥补**：它把"轿车""汽车""automobile"映到相近向量，即使词面不同也能匹配。

> 本机无神经 embedding 模型，TF-IDF 演示词面局限。**真实 RAG 几乎都用神经 embedding**（稠密语义），TF-IDF/BM25 只在关键词精确匹配（产品编号、人名）或混合检索时有价值（02 篇）。

## 3. ANN：大数据的快速检索

文档库小（几百篇）时，暴力算 query 与每个文档的相似度（$O(n)$）够快。但百万级文档时，每次查询扫百万向量太慢。

### ANN（Approximate Nearest Neighbor，近似最近邻）

牺牲一点点精度，换大幅加速。主流算法：

| 算法 | 原理 | 代表实现 |
|---|---|---|
| **HNSW** | 层次化小世界图，沿图快速逼近最近邻 | Milvus、Qdrant、pgvector、FAISS |
| **IVF** | 先聚类分桶，只搜最近的几个桶 | FAISS |
| **LSH** | 局部敏感哈希，相似项大概率同桶 | 较少用 |

### 实验（Part 3）与诚实声明

```
N=1000:   暴力 0.0087s, ANN(ball_tree) 0.0014s   ← ANN 快
N=10000:  暴力 0.0186s, ANN 0.0039s              ← ANN 快
N=100000: 暴力 0.0232s, ANN 0.0317s              ← ANN 反而慢!
```

> ⚠️ 诚实说明：N=10万时 ball_tree 反而慢——因为 **d=128 高维下 ball_tree 遇到"维度灾难"**，查询退化；同时 numpy 的暴力矩阵乘法（X@q）用了高度优化的 BLAS。**这正是工业界不用 sklearn 而用专门向量数据库的原因**：HNSW（图索引）在高维下鲁棒，能稳定做到百万级毫秒检索。

---

## 4. 向量数据库：RAG 的存储引擎

| 类型 | 代表 | 特点 |
|---|---|---|
| 专用向量库 | Milvus、Qdrant、Weaviate | 高性能、支持 HNSW/IVF、过滤 |
| 数据库插件 | pgvector(PostgreSQL)、Redis Search | 与业务库一体，省一套 |
| 库内 | FAISS、Chroma、LanceDB | 轻量，单机/嵌入式 |

选择：小项目用 Chroma/FAISS；生产用 Milvus/Qdrant；已有 PostgreSQL 用 pgvector。

---

## 5. 一句话总结

> **RAG 检索三件套：①用余弦相似度衡量"方向相近"（不受文本长度干扰）；②用神经 embedding 把文本映成语义向量（克服 TF-IDF 只懂词面的局限）；③百万级文档用 ANN（HNSW/IVF）把检索从 O(n) 降到毫秒级（注意 sklearn 的 ball_tree 高维会退化，生产用专门向量库）。embedding 质量 + 检索速度，决定 RAG 的上限。**
