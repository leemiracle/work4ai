# 00 — 为什么需要 RAG？

> 这是「讲透 RAG」的第一篇。RAG（Retrieval-Augmented Generation，检索增强生成）的本质是给 LLM 接一个"外部记忆"。这一篇讲透：LLM 到底缺什么，RAG 怎么补，以及它和微调/prompt 的边界。
>
> 配套实验：`experiments/00_why_rag.py`。

---

## 1. LLM 的知识三问题

LLM 很强，但有三个根植于其架构的**知识问题**：

| 问题 | 表现 | 例子 |
|---|---|---|
| **幻觉** | 编造看似合理但错误的事实 | 问"DeepSeek-V3 参数量"，可能自信地说 175B（错的） |
| **时效** | 训练截止后的事不知道 | 问"今天股市"，瞎编或拒答 |
| **私有** | 没见过的内部/专有数据 | 问"我们公司 Q3 营收"，完全不懂 |

### 根因：知识是「参数化」的

LLM 的知识**固化在权重里**（参数化知识，见《讲透基础模型》00）。训练结束那一刻，知识就"冻结"了——**无法事后更新、无法核实、不知道自己不知道**。这就是三问题的总根源。

---

## 2. RAG 的解法：接「非参数化」知识

RAG（Lewis et al. 2020）给 LLM 接一个**外部知识库**（可实时更新、可溯源）：

```
用户提问 → ① 检索知识库, 找相关文档 → ② 把文档塞进 prompt → ③ LLM 基于文档生成回答
```

知识不在权重里（非参数化），而在外部库——**可更新、可核实、可引用**。

### 实验：最小 RAG 检索（`00_why_rag.py`）

一个 6 篇文档的迷你知识库，TF-IDF 字符级检索：

```
Q: DeepSeek V3 参数量?  → [0.40] DeepSeek-V3 671B参数MoE...     ✅ 命中
Q: 公司Q3营收多少?      → [0.33] 公司2025年Q3营收8.2亿元...      ✅ 命中
Q: 怎么用少参数微调?    → [0.22] LoRA低秩分解只训1%参数...       ✅ 命中
```

检索精准定位。把这些文档注入 prompt："基于以下资料回答：{检索文档} 问题：{query}"，LLM 就能基于事实回答，而非幻觉。

> 注：本机无本地 LLM，检索用 TF-IDF（字符级 n-gram 处理中文）。真实 RAG 用神经网络 embedding（下一篇）+ LLM 生成，但**检索逻辑一致**。

---

## 3. 为什么检索，而不是把全部文档塞进 prompt？

这是初学者常问的。四个理由：

1. **上下文长度限制**：虽已支持百万 token，但超长时注意力质量下降（lost in the middle）。
2. **成本**：input token 按量计费，每次对话塞 1 万篇文档 = 烧钱。
3. **噪声**：无关文档干扰判断，LLM 可能被误导。
4. **时效**：文档库可实时更新，检索即时反映最新；全塞 prompt 每次要重传。

**检索的本质是"用相关性筛选"**——把海量文档压成少数相关的，兼顾质量与成本。

---

## 4. 知识注入三选一（核心决策）

| | 改的是什么 | 适合 | 代价 | 知识更新 |
|---|---|---|---|---|
| **Prompt** | 不改模型，塞上下文 | 临时、可溯源 | 推理贵（长 input） | 实时 |
| **RAG** | 不改模型，检索注入 | **大量动态知识、需引用** | 建检索系统 | **实时** |
| **微调（LoRA）** | 模型的行为/格式/风格 | 固定能力、领域语感 | 训练 | 需重训 |

**关键区分**：
- **改"行为/风格/格式"** → 微调（如让模型用某种语气、固定输出 JSON）。
- **注"知识/事实/最新信息"** → RAG（如问答、客服、文档查询）。
- **临时适应、要可溯源** → Prompt。
- **常组合**：LoRA 调行为 + RAG 注知识。

> 经验法则：**"要模型知道新事实"几乎总该用 RAG，不该用微调**——微调学知识又贵又易幻觉，且无法溯源、无法实时更新。

---

## 5. RAG 不是万能（局限）

1. **检索失败则全盘皆输**：检索不到相关文档，RAG 就退化为幻觉（甚至更糟，因为模型会"假装基于文档"）。
2. **文档矛盾**：多源文档冲突时，LLM 不知信哪个。
3. **依赖 embedding 质量**：检索效果取决于 embedding 模型对"语义相似"的捕捉（下篇）。
4. **延迟**：检索 + 生成两步，比纯生成慢。
5. **长文档处理**：chunk 切分不当会割裂语义（02 篇）。

---

## 6. 一句话总结

> **LLM 的知识固化在参数里（参数化），导致幻觉、过时、不懂私有数据三大问题。RAG 给它接外部知识库（非参数化）：检索相关文档→注入 prompt→基于文档生成。检索是"用相关性筛选"，兼顾质量与成本。决策上：改行为用微调，注知识用 RAG，临时用 prompt——三者常组合。RAG 的命门在检索质量，检索失败则全盘皆输。**

## 费曼回炉记录（L2 自检 · 已迭代）

- **F2 卡壳点**：
  - **卡点 A**：长期不理解"LLM 为什么会幻觉"——以为是个 bug，调一调就能修。重读第 1 节才钉死根因：**LLM 的知识是"参数化"的**——训完那一刻知识就冻结在权重里，**无法事后更新、无法核实、不知道自己不知道**。幻觉不是 bug，是这种架构的必然副产物。要修只能从外部接知识（RAG 的动机）。
  - **卡点 B**：一直分不清"什么时候该用 RAG、什么时候该用微调"。重读第 4 节那张三选一表才顿悟核心区分：**改"行为/风格/格式"用微调，注"知识/事实/最新信息"用 RAG**。让模型说东北话是改行为→微调；让模型知道公司 Q3 营收是注知识→RAG。**用微调学知识又贵又易幻觉又无法溯源**，这是初学者最常犯的错。

- **F3 术语翻译**：
  - "参数化知识" → **知识被烤进模型的"脑子"（权重）里**——训完就定型，要改只能重训。
  - "非参数化知识" → **知识存在模型"外面"的笔记本（知识库）里**——要查就翻笔记本，要更新就改笔记本，不用动脑子。
  - "检索（Retrieval）" → **用相关性从海量文档里筛出少数几篇相关的**——兼顾质量（只看相关的）和成本（不必每次都传 1 万篇）。

- **F4 回炉**：
  - **v1（错误直觉）**：以为"模型答错了，再训一次让它记住就好"——把幻觉当成记忆问题。
  - **v2（修正后）**：钉死第 5 节那句"**检索失败则全盘皆输**"——RAG 的命门在检索质量，不在生成。同时区分了"参数化 vs 非参数化"两条路：靠权重记知识（参数化）有幻觉/过时/私有三大死穴；靠外部库查知识（非参数化）可实时更新、可核实、可引用。diff 在于把"修幻觉"从"再训一次"重定义为**架构选择**——RAG 不是补丁，是用非参数化知识绕开参数化的根本限制。

### 三问

1. **讲透RAG 防的是什么欺骗？** → 检索到的文档本身是错的、被篡改的或不相关。
2. **被什么攻破？** → 检索噪声 / 混淆检索 / 幻觉冒充检索结果。
3. **沉淀进哪条主链？** → 验证主链——知识源可信度审计 + 检索结果可溯源。

### 一句话

> RAG 不是反诈，它只是把「模型自己编」换成「模型引用」，引用可信仍需独立验证。
