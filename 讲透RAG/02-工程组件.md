# 02 — 工程组件：chunk、混合检索、rerank

> 00/01 讲了 RAG 原理和检索数学。这一篇讲把检索质量拉满的**工程手段**——文档怎么切、多种检索怎么混合、怎么精排。
>
> 配套实验：`experiments/02_engineering.py`。

---

## 1. Chunk：文档切分（必做）

长文档必须切分成小块再 embedding，原因：
- embedding 模型有输入长度上限（512/8192 token）。
- 短块检索更精准（长文档里只有一句相关，整篇会稀释信号）。

### 切分策略

| 策略 | 做法 | 适用 |
|---|---|---|
| **固定长度 + overlap** | 每 N 字一块，相邻块重叠 M 字 | 最常用，简单稳 |
| **递归切分** | 按段落→句子→字符逐级切 | 保留语义边界（LangChain 默认） |
| **语义切分** | 按语义连贯性切（embedding 相似度跳变处） | 质量高但慢 |
| **按结构** | Markdown 标题、代码函数 | 结构化文档 |

### 实验（`02_engineering.py` Part 1）

```
原文 117 字, chunk_size=24, overlap=6 → 切成 7 块
chunk0: DeepSeek-V3是2024年12月发布的大
chunk1: 2月发布的大模型。它有671B总参数采用MoE架   ← overlap"2月发布的大"衔接
...
```

**overlap（重叠）的作用**：防止关键信息被切到两块的边界而丢失。

## 2. 混合检索：词面 + 语义

单一检索各有短板：
- **向量检索（神经 embedding）**：懂语义，但精确关键词（产品编号、人名）可能漏。
- **BM25/TF-IDF（词面）**：精确匹配关键词，但同义词/语义不懂。

**混合**：两路各检索 top-k，用 **RRF（Reciprocal Rank Fusion）** 融合排名：

$$\text{RRF}(d) = \sum_{r \in \text{检索路}} \frac{1}{k + \text{rank}_r(d)}$$

（$k$ 常取 60，按排名倒数加权，避免某路分数量纲不一致。）

### 实验（Part 2）

```
Q: '模型有多少参数'
        词面   语义(LSA)  混合
doc1    0.27   0.99       0.70   LoRA低秩微调省参数
doc4    0.29   1.00       0.71   大模型参数量决定能力
```

> ⚠️ 诚实说明：这里用 LSA（TF-IDF+SVD）做神经 embedding 的廉价替身，**在 5 个文档的小数据上 LSA 不稳定**（doc0"671B参数"本该最相关却被压低）。真实场景用 bge/m3e 等训练好的神经 embedding，语义捕捉可靠得多。本实验只演示"词面+语义融合"的机制。

## 3. Rerank：检索后精排

两阶段检索已成工业标配：

```
query → ① 向量检索 top-20(召回多, bi-encoder 快) → ② reranker 精排 top-3(cross-encoder 准)
```

### Bi-encoder vs Cross-encoder

| | Bi-encoder（检索） | Cross-encoder（rerank） |
|---|---|---|
| 方式 | query、doc **分别**编码再算相似 | query+doc **拼一起**送模型联合编码 |
| 交互 | 浅（只比向量） | 深（token 级交互） |
| 速度 | 快（doc 可预编码） | 慢（每对都要前向） |
| 精度 | 中 | 高 |

代表 reranker：bge-reranker、Cohere Rerank、jina-reranker。

**为什么两阶段**：cross-encoder 太慢，不能对百万文档都跑；先用快的 bi-encoder 筛出候选，再用慢的 cross-encoder 精排——**召回率 + 精度双高**。

---

## 4. Query 重写/扩展（可选但有效）

用户原始 query 往往模糊/口语。常见增强：
- **Query 重写**：让 LLM 把口语 query 改写成更利于检索的（"那个微调方法" → "参数高效微调 LoRA"）。
- **Multi-query**：生成多个变体 query 分别检索，合并结果。
- **HyDE**：让 LLM 先生成一个"假设答案"，用答案的 embedding 检索（答案比问题更像文档）。
- **Step-back**：先问更抽象的问题（"参数高效微调有哪些方法"），再具体。

---

## 5. 工业级 RAG 流水线

```
文档库 → chunk切分 → 神经embedding → 向量库(ANN索引)
                                           ↓
用户query → [query重写] → 向量检索 ┐
                              BM25检索 ┤→ RRF融合 → top-20
                                           ↓
                                      reranker精排 → top-3
                                           ↓
                                  注入prompt → LLM生成 → 引用溯源
```

---

## 6. 一句话总结

> **RAG 工程三板斧：①chunk 把文档切成带 overlap 的小块（兼顾长度上限和检索精度）；②混合检索（神经向量+BM25 用 RRF 融合）召回全；③rerank 用 cross-encoder 对 top-k 精排提精度。再辅以 query 重写/HyDE 等增强。这套"切分→混合检索→重排"是工业级 RAG 的标准流水线。**

---

## ✍️ 练习（`02_engineering.py`）

1. **overlap 必要性**：把 overlap 设为 0，看是否会有关键信息被切到边界丢失。
2. **融合权重**：调整混合检索的 α（词面/语义权重），看排名如何变化。
3. **chunk 大小**：把 chunk_size 从 24 调到 60，看大块是否稀释检索精度。
