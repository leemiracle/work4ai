# 07 — 生产坑与多模态 RAG

> 「讲透 RAG」第八篇。05-06 讲了选型和 chunking。本篇讲**把 RAG 推上生产**的踩坑经验，以及 2025 起的多模态 RAG（文档里有图/表/公式）。

---

## 1. 灵魂：Demo 能跑 ≠ 生产能用

$$
\boxed{\text{生产 RAG 的难点} = \underbrace{\text{文档杂乱}}_{\text{PDF/扫描/表格}} + \underbrace{\text{查询多变}}_{\text{口语/错字/多轮}} + \underbrace{\text{运维}}_{\text{更新/监控/成本}}}
$$

---

## 2. 文档解析（被低估的难点）

### 2.1 PDF 不是文本

PDF 是**布局描述**（字体/坐标），不是结构化文本。提取时：
- **文字层 OK**：直接读（pdfplumber/PyMuPDF）
- **扫描件**：要 OCR（Tesseract/PaddleOCR）
- **表格**：专用解析（Camelot/Table Transformer）
- **公式**：LaTeX 还原（MathPix/Nougat）

### 2.2 图文混排

文档里的图表承载关键信息（如财务报告的柱状图）。纯文本 RAG 丢掉这些。需要：
- 图片单独抽出来，用多模态模型描述（"这是一张显示增长的柱状图"）
- 把描述作为文本 chunk 入库

---

## 3. 查询处理（用户不会好好问）

### 3.1 查询改写

- **口语化**："那个东西多少钱" → 改写为 "产品价格"
- **多轮指代**："它支持中文吗" → 改写为 "{上一话题}支持中文吗"
- **HyDE**：让 LLM 先假设一个答案，用假答案去检索（语义更接近目标文档）

### 3.2 查询扩展

- 同义词扩展（"iPhone" → "苹果手机 / Apple smartphone"）
- 子查询分解（复杂问题拆成多个简单检索）

---

## 4. 多模态 RAG

### 4.1 为什么需要

现实文档（论文/合同/说明书）= 文字 + 图表 + 公式 + 表格。纯文本 RAG 会漏掉图表信息。

### 4.2 三种方案

| 方案 | 思路 | 代表 |
|---|---|---|
| **图转文** | 用 VLM 把图片描述成文本，按文本检索 | 简单实用 |
| **统一 embedding** | 用多模态 embedding（CLIP）同时编码图文 | 中等 |
| **ColPali** | 直接在文档页面（视觉 token）上检索 | 2024 前沿 |

### 4.3 ColPali（2024 突破）

传统流程：PDF → 解析 → 文本 → embedding。ColPali 跳过解析：**直接把 PDF 页面当图片输入视觉模型，检索最相关页面**。

- ✅ 不怕复杂版式（表格/图表/公式直接视觉处理）
- ⚠️ 粒度是"页面"级，不如文本 chunk 细

---

## 5. 运维与监控

### 5.1 索引更新

- 文档变了 → 增量更新（别全量重建）
- 删除：旧文档要标记失效（否则检索到过期信息）

### 5.2 质量监控

- **检索 Recall**：定期跑评测集
- **用户反馈**：点赞/点踩 → 标注坏案例 → 迭代
- **LLM 回答质量**：faithfulness（是否忠于检索内容）/ relevance（是否切题）

### 5.3 成本

- embedding 调用（一次性，但文档多就贵）
- 向量库存储（按维度 × 条数计）
- LLM 推理（每次 query 都调）

**省钱**：小文档用本地 embedding；大文档用 API 但缓存。

---

## 6. 高级架构（简介）

| 架构 | 什么时候用 |
|---|---|
| **GraphRAG** | 文档间有复杂关系（知识图谱）|
| **Self-RAG** | 让 LLM 自己判断要不要检索 |
| **CRAG**（Corrective RAG）| 检索质量低时自动改写 query 重试 |
| **Agentic RAG** | Agent 决定检索策略（多步/多源）|

这些在 [03-高级架构](03-高级架构.md) 有简介，深入看论文。

---

## 7. 批判性：RAG 不是万能

- **检索不到就没有**：如果知识不在库里，RAG 答不出（和预训练知识互补，不替代）
- **检索到了 LLM 可能忽略**：context 太长时 LLM "中间遗忘"
- **维护成本被低估**：索引更新 + 评测 + 监控，是持续投入

> **诚实结论**：RAG 是 LLM 落地最实用的模式，但"demo 到生产"有巨大鸿沟。文档解析 + 查询改写 + 质量监控是三个被低估的工程量。
