# 03 · 安全分析与加固（攻击实录 → 补救落地 → 重走验证）

> 任务：说明整个过程是否可能被 hack、补救措施是什么；**把补救补进服务，再走一遍流程**。
> 授权边界：全部演示只针对自建教学服务 `luowz-netlab`（我方资产），属合法安全教学。
> 时间线：r1 攻击实录（20:13–20:18）→ 补救实现 → r2 加固验证（20:22–20:27）。

---

## 1. 威胁模型：谁能在哪一层攻击这个服务？

```
攻击者位置          攻击面                     难度
─────────────────────────────────────────────────────
同宿主其他容器      L2 直连 8080/8443（横向）    极低（已实测直达）
宿主机本机用户      127.0.0.1:8188 映射端口      低
网络路径上的抓包者  L7 明文载荷（嗅探）          低（前提是能上路径）
任意匿名客户端      无认证 + 路径遍历 + DoS      零门槛
```

**结论先行：v1 是"可能被 hack"的教科书样本**——五个漏洞 A1–A5 外加架构性问题 A6/A7，每个都在自己的容器里实测利用成功（不是纸上谈兵）。

## 2. 攻击实录（v1，data-r1/attack_demo.txt）

### A1 明文嗅探——抓包文件里直接捞出密码 ⚠️ 最严重

```
grep 抓包 JSONL:
"payload": "POST /api/login HTTP/1.1..Host: 127.0.0.1:8188..Content-Type: ...user=alice&pass=S3cret!"
```

攻击者条件：只需在网络路径上（同网段/镜像口/被攻陷的相邻容器）能抓包。**无需破解任何东西**——r1 轮我们自己抓的包，密码就是明文字节。共享宿主机上任何一个容器被攻陷，都可对同网段流量做这件事（结合 A6 横向直达，风险叠加）。

### A2 路径遍历——`/files/../../../../etc/hostname`（CWE-22）

```
错误深度(3层)→ 404 泄露绝对路径 '/root/luowz/netlab/files/../../../etc/hostname'（信息泄露加成）
正确深度(4层)→ 读出容器 ID  ad63e6e3d4c3
              再读 /proc/version → 宿主内核 "4.19.90-89.11.v2401.ky10 + gcc 7.3.0"
```

两个教学点：① `curl` 会自动规范化 URL 里的 `../`，攻击须 `--path-as-is`；② 服务把 `os.path.join` 的结果直接 open，`../` 未过滤即可逃出文件根；404 错误页还把服务器内部路径结构回吐给攻击者（情报加成）。

### A3 零认证——匿名者=全权用户

`curl http://.../api/time` 直接 200。所有端点（含登录、文件读取）对任何来源开放。

### A4 指纹收集

```
Server: tracehttp/1.0 Python/3.11.6
```

Python 版本都送上门——攻击者据此检索已知 CVE、裁剪 payload，攻击成本骤降。

### A5 慢速 DoS（slowloris 原理）

```
攻击前服务线程: 1  →  挂 12 个"半截请求头"连接  →  线程 13
```

ThreadingHTTPServer 每连接一线程；连接发一半请求头然后挂着，线程就被占住。几十个连接即可耗尽线程/内存，正常用户被拒服务——**DoS 不需要任何凭据**。r1_lo.jsonl（283KB）里完整记录了这些半开会话的 SYN/SYN-ACK 序列。

### A6 架构层：端口映射 ≠ 网络隔离

```
luowz-dev(172.17.0.3) → curl 172.17.0.4:8080/api/time → 200 成功
```

`-p 127.0.0.1:8188:8080` 只约束**宿主机侧**入口；docker bridge 网段（172.17.0.0/16）内所有容器对目标端口是**直连**。共享机上这意味着：其他人的容器（或被攻陷的容器）可以绕过一切端口映射策略直达你的服务。

### A7 数据面：pcap 本身就是战利品

抓包文件权限 `-rw-r--r--`（其他用户可读）+ 里面躺着 A1 的明文密码。**观测基础设施自己会成为泄露源**。

## 3. 补救措施 → 逐一落地进服务（tracehttp_tls.py）

| 攻击面 | 补救 | 实现锚点 |
|---|---|---|
| A1 嗅探 | **TLS 1.2+**（自签证书，python ssl；拒绝古董版本） | `SSLContext(PROTOCOL_TLS_SERVER)` + `minimum_version=TLSv1_2` + `load_cert_chain` |
| A2 遍历 | **realpath 归一化 + 前缀校验**；错误页不带系统细节 | `os.path.realpath(...).startswith(real_root)`；404 只回 `{"error":"not found"}` |
| A3 零认证 | **Bearer Token + 常时比较**（抗时序侧信道） | `hmac.compare_digest(h[7:], TOKEN)` |
| A4 指纹 | 覆写 `version_string()` → `Server: netlab`；HSTS/nosniff 头 | Handler 覆写 + 安全响应头集合 |
| A5 慢速 DoS | ① accept 即 settimeout(5s)（**覆盖 TLS 握手期**）② 请求体 ≤8KB ③ 并发信号量 16（超出立即断） | `GatedServer.get_request/_reject/process_request` + `MAX_BODY` |
| A6 横向直达 | **应用层 IP 白名单**（本机 + 宿主网关 172.17.0.1；容器无 iptables 时的等效防火墙） | `ALLOW_NETS` + `_ip_allowed()` |
| A7 数据面 | token 文件 chmod 600；日志凭据脱敏（`pass=***`） | `mask()` + token.txt 权限 |

两个实现期的新认知（比清单本身更值钱）：

1. **TLS 服务的过载拒绝无法发明文 503**——过载闸门工作在握手之前，此时任何明文 HTTP 状态码对 TLS 客户端都是协议违规字节。正确形态是直接 close，客户端表现为握手失败。这是 L4（传输层拒绝）与 L7（应用层 503）两种拒绝语义的真实分界。
2. **慢连接超时必须从 accept 时刻起算**——若只在 `handle_one_request` 里设超时，攻击者在 TLS 握手前挂连接照样占死线程（握手阶段还没进入请求处理）。防护要在最早的层介入。

## 4. r2 轮：补救后的服务重走全流程（同一环境、同一剧本、唯一变量=服务版本）

### 防护验证矩阵（全部实测）

| 攻击重放 | v1 结果 | v2 结果 | 判定 |
|---|---|---|---|
| A1 嗅探：抓包 grep `pass=` | 明文密码 1 处 | **0 处**（应用数据全密文；仅 ClientHello 的 SNI "netlab.local" 明文——套件协商必须可见，ECDHE 保证密钥不落抓包） | ✅ |
| A2 遍历 4 层 | 读出 /etc/hostname | `{"error":"path out of root"}` 403，且不泄露路径 | ✅ |
| A3 无凭证访问 | 200 全开 | `{"error":"unauthorized"}` 401；带 token → 200 | ✅ |
| A4 指纹 | `Python/3.11.6` | `Server: netlab` | ✅ |
| A5 slowloris 半开连接 | 挂住不放（线程 1→13） | **5.0s 精确被断**（服务端超时的时戳级证据） | ✅ |
| A5b 16 槽压满后新连接 | （无闸门） | 服务线程恒 17（16 工作线程被占）期间 3 次探测连接全部被断开 | ✅ |
| A6 dev 容器(172.17.0.3) 带合法 token 直连 | 200 | `{"error":"forbidden"}` 403；同刻宿主代理(172.17.0.1)访问 → 200（白名单精确放行） | ✅ |
| 正常流量（token+TLS） | — | 200，`openssl s_client` 验证证书链 Verify 0，TLSv1.3 + AES_256_GCM | ✅ |

### 数据视角的对比（最能说明"加密改变了什么"）

| 观察 | r1（明文） | r2（TLS） |
|---|---|---|
| L5 会话时间线（flows.py） | 12 包 1.5ms：握手→数据→挥手 | 17 包 43.9ms：**结构完全同形**，多出的包=TLS 握手自身的往返与记录层分段 |
| L4 段头 | seq/ack/window 全可见 | **同样全可见**（TCP 头从不加密） |
| payload ASCII dump | `POST /api/login ... pass=S3cret!` | 乱码；唯一明文=ClientHello 里的 SNI 与套件列表字节 |
| 抓包者能学到什么 | 你的密码 | 你在和谁、用哪种加密、传了多少字节 |

**七层追踪在 r2 的意义反而更大**：它同时演示了"加密保护了什么"（L7 内容）与"加密保护不了什么"（元数据：谁与谁、何时、多大流量——L3/L4/L5 全透明）。这是流量分析（traffic analysis）与内容保密的边界。

## 5. 残余风险（诚实清单——加固不是终点）

1. **自签证书**的教学代价：客户端必须显式信任（`--cacert`）。生产环境应换 CA 签发 + 证书轮转；自签若被"无脑 `-k`"习惯化，反而养出容忍中间人的用户。
2. **IP 白名单是应用层方案**：容器拿到 NET_ADMIN 后可用 iptables/nftables 在 L3/L4 前置过滤（更早、更难绕）；当前方案在 TCP/TLS 之后才拒绝，攻击者仍能消耗握手资源。
3. **Token 是演示级固定值**：无过期、无轮转、无按客户端分发。真实场景最小改进=HMAC 时戳 token 或 mTLS（双向证书认证，直接消灭"带 token"这个层）。
4. **单机防御**：A6 的根治是 docker 自定义网络/网络策略（`--internal`、network policy），把"同网段直达"这个前提拆掉，而不只是拒绝它。
5. **观测数据生命周期**：pcap/JSONL 含行为元数据，实验结束应归档加密或销毁（本实验数据已随容器重建失去时效价值，仅留教学样本）。

## 6. 一页总结（给未来的自己）

```
明文 HTTP 的世界        加密+认证+限额的世界
──────────────         ──────────────
抓包=拿到密码           抓包=只拿到元数据
知道端口=全权用户       知道端口+偷到token 才是用户
半个请求头=锁一个线程   5 秒不说话就被请出去
错误消息=送情报         错误消息=三五个字
同宿主容器=邻居即内网   白名单说谁行谁才行
（但元数据永远透明——加密从不隐藏"谁在和谁说话"）
```
