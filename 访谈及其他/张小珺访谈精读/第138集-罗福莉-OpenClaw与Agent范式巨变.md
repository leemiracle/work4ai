## 嘉宾定位

罗福莉是 2026 年最一线的中国大模型女性研究者。访谈发生在 OpenClaw 引爆全球、MiMo-V2 系列发布之后。她说这是"人生第一次长时间技术访谈"。不喜欢"AI 天才少女"标签。本集是理解**2026 年 Agent 范式巨变**最一线的复盘。

## 核心论点速览（对接 work4ai）

1. **2026 是范式巨变年**：从 Pre-train 主导的 **Chat 时代** → Post-train 主导的 **Agent 时代**。→ 全系列元洞察
2. **OpenClaw 是"划时代的 Agent 框架"**——通过 Agent 编排弥补模型短板，三天内把她从排斥者变重度用户。→ `讲透Agent`
3. **Anthropic 路径是当下共识**，国内加速追赶，Pre-train 代差基本没有了。→ `讲透基础模型` 中国侧
4. **用卡比例巨变**：Chat 时代 研究:Pre:Post = **3:5:1** → Agent 时代 **3:1:1**，顶尖团队 Pre:Post = **1:1**。→ `讲透微调` 工业实践
5. **MiMo V2 坚持用 Hybrid Attention + MTP 而非主流 MLA**——为 Long Context 效率设计，Flash 100-150 TPS、Pro 60-100 TPS。→ `讲透基础模型` 架构
6. **1T 模型只是入场券**——要达到 Claude Opus 4.6 水平，总参至少 1T。→ `讲透基础模型` 规模
7. **Agent 框架 ≠ 产品**——它是"人和模型之间厚重的中间层"，定义了模型调度、记忆、workflow。→ `讲透Agent`
8. **平权组织文化**：小米大模型团队没有职级、没有组、没有 deadline，靠热爱驱动。→ 元洞察

## 主题精读

### 主题 1：OpenClaw——从排斥到三天上瘾

罗福莉对 OpenClaw 的认知转变（2026 春节，三天）：
- **第一天**：感觉"脑内多巴胺持续分泌"，它有"灵魂"、会主动提醒"天晚了该休息"。
- **第二天**：把团队管理难题交给它（如何激发团队创造力），聊一个多小时，整理出体系化方案。
- **第三天**：把研究任务交给它（构建模拟真实用户的 User Agent），本以为要折腾几天，结果一两个小时做出来了。

**OpenClaw vs Claude Code 关键差异**（来源：CSDN/80aj）：

| 维度 | OpenClaw | Claude Code |
|------|----------|-------------|
| Memory | 分层分级持久记忆 | 有限记忆/session 补丁 |
| 模型调度 | 多模型联合自动选择 | 单一模型 |
| 框架编排 | 主动弥补模型短板 | 依赖模型原生能力 |
| 开放性 | 开源可改（激发群体智慧）| 闭源黑盒 |
| 设计目标 | for 端到端完成所有任务 | for 软件工程（写好代码）|

**关键洞察**："Claude Code 的一切设计都是 for 软件工程的（session 满了做压缩、根据 plan 做记忆、跨 session 共享 context）。OpenClaw 的设计初衷是 for 端到端完成所有任务，通过框架弥补当下模型短板。"

> **对接 `讲透Agent`**：这是 Agent 框架作为"独立变量"的最佳案例——框架本身重新定义了任务完成率。

### 主题 2：为什么不是 Claude Code

罗福莉对比：
- Claude Code 是黑盒，改不了记忆系统、workflow。
- OpenClaw 开源，她让 Claude Opus 4.6 帮她重新设计 Memory 系统和 Multi Agent 逻辑。
- "我去用 Claude Code 时，默认是要用 Claude Opus 4.6 这代模型的能力。我去用 OpenClaw 时，不关注模型能力——因为框架设计之初就想通过编排弥补模型短板。"

**开源的真正价值**：不是"能看源码"，而是"真能当实验底盘，按需求重构 Agent 框架"。OpenClaw 释放的不只是 Claude Opus 4.6 的能力，还有"人去改造框架本身的创造力"——这就是群体智慧参与 Agent 框架演化。

### 主题 3：MiMo V2 的架构反共识——Hybrid Attention + MTP

**主流选择 MLA**：DeepSeek V2/V3/R1、Kimi K2、GLM-5 都用 MLA。罗福莉承认 MLA 在 Chat 时代优秀（减少 KV Cache，H 系列芯片上计算访存完美平衡）。

**MiMo V2 选 Hybrid Attention 的逻辑**（来源：CSDN 万字长文）：
1. **Sliding Window 层大幅省 KV Cache**——局部注意力替代全局，长文本成本更低。
2. **MTP 把节省的算力富余填上**——Sliding Window 减少 attention 计算量，留下算力富余，MTP 把它利用起来。
3. **达到新平衡**——既省 KV Cache（利于长上下文），又通过 MTP 提升推理速度。
4. **Pro 这代比例更极致**：Full Attention : Sliding Window = **7:1**。

**实测**：Flash 100-150 TPS，Pro 60-100 TPS。"一旦体验到更快的模型，且智能水平相当，就回不到更慢的模型了。"

**MTP 分阶段使用**：Mid Train/Post Train 阶段训额外 MTP 层用于推理加速。

> **对接 `讲透基础模型` 架构章节**：与《论文探索之旅》板块二的 DeepSeek MLA 对照，呈现"Agent 时代长上下文效率"的两种路线之争。

### 主题 4：用卡比例的范式变化

- **Chat 时代**：研究:Pre-train:Post-train = **3:5:1**（极不平衡，Pre-train 占大头）
- **Agent 时代**：**3:1:1**（合理）
- **顶尖团队**：Pre-train : Post-train = **1:1**
- **训练 MiMo-V2-Pro/Flash 各需几千卡**，但前期结构研究 + 中后期 Post-train 算法研究投入是 3-5 倍

> **对接 `讲透微调`**：这是工业界真实用卡比例的最佳数据点。

### 主题 5：1T 模型是入场券

"要达到 Claude Opus 4.6 水平，总参至少 1T。这是硬门槛。" DeepSeek V3 只有 600-700B。

**权衡**：激活参数越大推理成本越高。艺术在于如何在 1T 总参前提下，通过架构设计（更极致稀疏比）控制长文本推理效率——"既能想得复杂，又能跑得快"。

**下一个阶段的决策**：不会在 1T 水平走太久，要寻求更大 scaling——"到底 scaling 参数量还是 scaling 什么？在什么芯片上 scaling？这决定了大半年后谁领先。"

### 主题 6：组织平权——没有职级、没有组、没有 deadline

小米大模型团队 ~100 人（含实习生/开发/产品），核心迭代 20-30 人。
- **没有职级**——平权有利于创新
- **没有小组**——层级是约束，约束压制创造力
- **没有 deadline**——技术突破不靠催促

"让预训练的人做后训练，是好的多样性补充。"——后训练需要 diversity。

### 主题 7：Agent 的自进化——"左脚踩右脚"

罗福莉原话："我之前认为我们自己做的工作已经足够有创造力、足够不会被 Skill 化、不会被 Workflow 化。但我现在发现，它竟然也能！那它可不可以训出更强的模型？自己左脚踩右脚就提升了？——这是这一两年会发生的事情。"
