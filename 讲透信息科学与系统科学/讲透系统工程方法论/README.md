# 讲透系统工程方法论 · 把大问题切成能做的小问题,再把答案缝回去

> **本质一句话**:系统工程方法论=**分解、建模、迭代、反馈的工程纪律**——它不生产具体技术,它回答"这么多技术怎么组织起来不散架"。
>
> GB/T 13745-2009:120 **系统工程方法论**(GB/T 列三级"系统建模";决策分析/决策支持/管理信息系统归 63050→挂靠管理侧)。家族:[讲透信息科学与系统科学](../README.md)·12050。

## 〇、家族树(Q1 的答案 = 这棵树)

```
讲透系统工程方法论/
├── 讲透系统建模/      📝 抽象的纪律:模型为什么可信、何时骗人(含 GB/T 三级"系统建模")
├── 讲透系统生命周期/  📝 从瀑布到敏捷:V 模型、螺旋、DevOps(自定主干支)
└── 讲透需求工程/      📝 从模糊愿望到可验证规格:需求的社会学(自定主干支)
```

三支=方法论的三个动作:建模(把世界变模型)、生命周期(把模型变产品)、需求(把愿望变合同)。
