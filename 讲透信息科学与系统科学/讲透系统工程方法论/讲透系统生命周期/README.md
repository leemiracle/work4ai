# 讲透系统生命周期 · 从瀑布到敏捷的七十年战争

> **定位**:这支负责方法论的时间维——**V 模型、螺旋、Rational 统一过程、敏捷、DevOps**:过程模型如何演化、每代信条付出什么。
> 自定主干支(GB/T 12050 未单列;2026-09-07 立宪)。

## 诞生

Royce 1970 论文被误读成"瀑布"(他本人画的是带反馈的迭代图)→ Boehm 螺旋模型(1988,风险驱动)→ 敏捷宣言(2001,17 人雪鸟会议反叛文档重型过程)→ DevOps(2009-,开发运维一体)。

## 核心问题(3-5 条)

| 问题 | 状态 |
|------|------|
| 过程能否统一建模 | ✅ 螺旋/RUP 把过程本身做成模型 |
| 需求不确定时该用什么过程 | ✅ 敏捷宣言(2001):拥抱变化优于遵循计划 |
| 快速迭代与架构质量可兼得吗 | 🔄 持续重构/架构跑道实践,无终解 |
| 过程模型本身如何演化 | ✅ 每代解决上代死穴+引入新穴(见家族 00 章假设代价表) |

**这支最美的一个事实**:**瀑布是个误读**——Royce 1970 原文明确说单向瀑布"有风险且不可行",他画的是带回环的迭代图;业界用了二十年才发现自己在执行一个不存在的主张。**方法论的历史也是误读史**——教条多数是传播压缩的产物。

## 假设与依赖

瀑布假设需求可先行冻结;敏捷假设迭代可收敛且架构熵可控;DevOps 假设自动化测试可信。前置:家族层 [`../00-体系结构.md`](../00-体系结构.md)。
