> 形式化成什么、写成什么代码任务、用什么算法库、坑在哪、归哪个家族管。

## 使用方法

1. 拿到问题，在「领域问题/任务」列找**最近邻**——本宇宙问题常以"现象/指标"
   形态到达（"怎么稳住""会不会崩""谁更优"），先对上号再谈翻译。
2. 看「形式化后」列：**形式化即定价**——控制问题译成优化、评估问题译成打分，
   都是最常见的译错方向。
3. 看分层标预定预期：
   - **[A 可直接编码]**：规格明确，天到周级出活；
   - **[B 需先建模]**：必须先补模型（方程/结构/准则树），**建模占一半以上工作量**；
   - **[C 研究级开放]**：无成熟算法或定义仍在竞争，只能出研究原型，**别承诺工期**。
4. 「落点家族」是深钻入口：进该家族 04 章读这条走廊的完整边界分析与裂缝清单。
5. C 层问题的正确姿势：把"解决它"改写成"**度量代理指标+诚实标注边界**"——
   本仓库不把研究包装成工程。

口径说明：本表每行给的是**最小可接单形态**——真实工程常是多行组合
（例：一台无人机的姿态控制 ≈ #15 LQR + #16 滤波 + #18 约束），
组合时按行分别核对形式化与坑，不要只取并集。

## 分层怎么判（三问）

1. **规格能否今天写出来？** 能——A；要补方程/准则树/结构——B；"对"的定义还在争——C。
2. **有没有生产级库？** 有（python-control/filterpy/scikit-criteria 族）——A/B；只有论文复现——C。
3. **验收断言写得出吗？** 写得出（已知解对拍/守恒律校验）——A/B；只能"曲线像"——退回重定义。

## 三层占比（一句话）

31 题中 **A 14 / B 14 / C 3**——"可直接编码"与"需先建模"平分秋色：本宇宙的
主旋律是**先把现象翻成模型**（方程/结构/准则树），代码只是模型的执行器。
分家族看：信息科学基础/系统评估 A 为主（泛函与算子已定型），控制理论/系统工程
B 为主（每个对象都要单独建模）；C 层集中在三条前线——涌现判定、学习证书、
大系统结构——全是"定义或算法未收敛"处。

## 通用工作流（问题→形式化→选走廊→写断言）

1. **问题→形式化**：把口语问题写成数学对象——分布与熵、微分方程/差分方程、
   传递函数/状态空间、转移矩阵、准则树、LP/QP。判据：能否交给别人而不产生歧义。
2. **形式化→选走廊**：查落点家族 04 章的走廊表，确认**承诺强度**——
   模拟只"跑得出"，度量才"算得准"，只有证书"证得明"；按强度打折结论。
3. **选走廊→写码**：算法照抄走廊清单，**库优先于自写**（自写仅限教学或验证目的）；
   B 层任务的模型（方程/结构/准则树）必须与代码一起入档——模型是交付物的一半。
4. **写码→写断言**：开工前先写断言——已知解对照（如 LQR 增益对拍）、
   不变式守恒（如概率归一）、极限情形退化（如 λ→0）。

> **任务完成的定义是断言绿，不是"曲线看起来对"**——本宇宙的图最会骗人：
   模拟跑得出、指标算得出，都不等于机制证得明。
