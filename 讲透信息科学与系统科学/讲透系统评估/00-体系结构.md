# 00 · 体系结构:评估的三层架构——测量、聚合、程序

> **本章回答五问之一(家族层):整个体系结构长什么样。**
> 答案一句话:评估是一座三层楼——**底层测量**(把价值变成数)、**中层聚合**(把多个数变成一个排序)、**顶层程序**(让整个过程在争议中站得住)。所有方法都是这三层的不同搭法。

---

## 一、怎么产生的(②要件):三个原生问题

**直觉图像先行**:想象你是 1960 年美国国防部官员,面前三个导弹方案——射程远的贵、便宜的慢、快的维护差。你说"综合来看"?每个将军的"综合"都不一样。评估学科就是被这种**多维僵局**逼出来的。

| 原生问题 | 关键事件 | 催化的方法 |
|---------|---------|-----------|
| 武器系统选谁(RAND, 1950s) | 成本效益分析 CBA 制度化 | 效费比、约束优化选型 |
| 公共工程值不值(美国 NEPA 1970) | 环境影响评价立法 | 环评程序、多准则清单 |
| 中国工程上不上(1980s 引入可行性研究) | 联合国工发组织《工业可行性研究手册》 | 可行性研究制度 |

📖 故事框:RAND 的经济学家 Charles Hitch 1960 年出任国防部长助理,把"花钱买战力还是花钱买保险"的吵架变成 PPBS(规划-计划-预算系统)——**评估第一次成为国家制度**。中国 1980s 把可行性研究写进基建程序,"先评估后上马"从此是工程宪法。

## 二、三层架构(Q1 主干)

```
┌────────── 顶层:程序层 ──────────┐
│ 谁参与?权重谁定?争议怎么裁决?     │   ← 程序正义(参与式评估、Delphi)
├────────── 中层:聚合层 ──────────┤
│ 多个数 → 一个排序:加权?字典序?    │   ← AHP/TOPSIS/OUTRANKING
│ Arrow 不可能定理在此设卡           │
├────────── 底层:测量层 ──────────┤
│ 价值 → 数:量表、效用、两两比较     │   ← 测量论、效用理论
└──────────────────────────────────┘
```

- **测量层**:把"好"变成数。三步法例子:直觉——"便宜的 5 分";严格——效用函数 u:方案×准则→ℝ,需通过偏好传递性等公理;最小例子——三档打分 1/3/5。
- **聚合层**:把一列数变成一个排序。权重和(WSA)、两两比较特征向量(AHP)、距离理想解(TOPSIS)、包络前沿(DEA)、级别高于关系(outranking/ELECTRE)。
- **程序层**:Delphi 专家轮询、参与式评估、利益相关者权重谈判——**评估结论的合法性一半来自程序而非数学**。

## 三、核心问题清单(③要件)

| 问题 | 状态 | 一句意义 |
|------|------|---------|
| 偏好可否两两量化并提取权重 | ✅ Saaty 1977:AHP 特征向量法 | 两两比较矩阵的主特征向量=权重(Perron–Frobenius 意外应用) |
| 效率可否免权重评估 | ✅ Charnes–Cooper–Rhodes 1978:DEA | 线性规划包络出效率前沿——权重内生 |
| 完美聚合程序存在吗 | ✅ **否定式**:Arrow 1951 不可能定理 | 满足四条无害公理的聚合不存在——评估方法全部在"违反哪条"上分野 |
| 排序对新方案稳定吗 | ✅ **否定式**:Belton–Gear 1983 rank reversal | 加入新方案可翻转旧排序(实验复现) |
| 指标会反噬目标吗 | ✅ Goodhart 定律(定性) | 指标一旦成为目标就不再是好指标 |

## 四、假设与代价(④要件)

| 假设 | 买到什么 | 付出什么 |
|------|---------|---------|
| 偏好可分解(总目标→准则树) | 结构清晰、可分工 | 准则间独立性假设常常虚假 |
| 价值可基数化(打分/两两比较) | 可计算 | 序数偏好被强行压成基数 |
| 专家判断可聚合 | 群体结论 | Arrow 卡:聚合必违反某条公理 |
| 指标可代理目标 | 可考核 | Goodhart 反噬:被考核者优化指标而非目标 |
