# 04 · 系统学转代码：从模拟到涌现检测的走廊与裂缝

> **本章回答五问之五（家族层）：这个分支的问题怎么变成 code 问题？**
> 系统学是六学科里**转码最顺**的家族之一——它的一半理论本来就是
> 以"程序"的形态存在（元胞自动机/ABM）。但要分清三条走廊的
> **不同承诺强度**：跑得出（模拟）、算得准（度量）、证得明
> （涌现判定）——最后一条是裂缝。

## 一、代码走廊总表

| 走廊 | 问题类型→算法→库 | 承诺强度 |
|------|-----------------|---------|
| ① 演化走廊 | "系统随时间怎么走" → ODE 积分/迭代映射 → scipy.integrate.solve_ivp, numpy | 算得准（数值误差可控，借 [数值分析](../../讲透数学/讲透分析/讲透数值分析/)） |
| ② 分岔/混沌走廊 | "参数变到哪、行为质变" → 分岔扫描/李雅普诺夫(Benettin)/盒计数维数 → 自写 100 行 | 算得准（本章实验） |
| ③ 多主体走廊 | "局部规则长出什么全局" → ABM/元胞自动机 → Mesa（Python ABM 框架）/自写 | 跑得出（现象级，机制欠定——02 章） |
| ④ 网络走廊 | "结构如何决定动力学" → 生成模型+图度量+传播模拟 → NetworkX/igraph | 算得准（度量）+跑得出（动力学） |
| ⑤ 粗粒化/因果走廊 | "因果住在哪个尺度" → EI 计算/PID/转移熵 → 自写（新兴，无标准库） | 实验级（定义仍在竞争——01 章方向二） |

## 二、逐条速写（为什么是这样）

### 走廊①②：这些是"穿马甲的数值分析"

演化与分岔走廊的严格性全部来自数值分析：稳定性（刚性方程用 BDF）、
精度阶、CFL 类约束——系统学自己不提供任何一条数值定理。
**工程师心智模型**：把 logistic/洛伦兹/B-Z 方程当作普通 workload，
一切数值决策按 [讲透数学/讲透分析/讲透数值分析](../../讲透数学/讲透分析/讲透数值分析/)
的纪律走。性能工程侧的熟人：混沌系统的长时间积分是**误差指数放大**的
工作负载——双精度 1e-16 的初值误差在 λ≈0.9 时 ~35 个时间单位后放大到 O(1)
（这就是"可预测时窗 ≈ (1/λ)ln(1/ε)"的工程含义：**更多算力买不回
被指数吃掉的精度，只能买系综统计**）。

### 走廊③：ABM——系统学的"原生代码"

ABM 的祖师爷 Schelling 1971 年是在纸板和硬币上跑的——**这门学科的
原型工作负载本来就不是方程而是规则**。转码要点：

```python
# ABM 的三件套骨架（以 Schelling 为例）
# ① agent 状态袋  ② 局部规则函数  ③ 全局统计器
# 完整可跑版见本章练习/支层后批
agent = {"pos": (i,j), "group": 0 or 1}
def unhappy(agent, grid, threshold=1/3): ...   # 规则
def step(grid): 移动所有 unhappy 的 agent      # 调度
segregation_index = 同类邻居比例的均值          # 全局统计
```

**为什么 ABM 没有标准验证算法**：模拟的"涌现"与"实现 artifact"
（调度顺序/边界条件/各向异性网格）在输出层面不可区分——
03 章第三档构造力的代码侧落点。

### 走廊④⑤⑥：从"结构度量"走向"因果测量"

- 网络走廊最成熟：NetworkX 一行代码算出度分布/聚类/中心性；
  传播模拟（SIR/SIS）是流行病学的生产工具
- 因果走廊最年轻：有效信息 EI 的计算没有任何门槛（转移概率矩阵的
  do-干预散度，30 行 numpy），**门槛在于解释**——EI 增大是否等于
  涌现，取决于你接受哪派定义（01 章方向二的竞争在代码层完全透明）
- 高阶走廊：GUDHI 做单纯复形构造与持久同调——"群体交互"第一次
  有了可计算形状

## 三、可机械化边界（三件套之一）

| 任务 | 可机械化？ | 说明 |
|------|-----------|------|
| 给定规则跑出全局行为 | ✅ 全自动 | 这就是模拟 |
| 度量（分岔点/指数/维数/网络不变量） | ✅ 全自动 | 数值例程+收敛检查 |
| 从时间序列重建动力学 | 🟡 半自动 | SINDy 等符号回归给候选，人裁决（与 [讲透动力系统](../../讲透数学/讲透分析/讲透动力系统/) 04 章共享走廊） |
| 从数据反推高阶交互结构 | 🟡 半自动 | PRX 2024 类方法起步（01 章方向一） |
| 判定"这是真涌现" | ❌ 无算法 | 定义未共识——永远的半人工判断 |
| 机制唯一性判定 | ❌ 原则上欠定 | 02 章：同现象多机制，逻辑不可判 |

## 四、工程师落点（三件套之二；性能工程视角）

1. **大规模 ABM 的 GPU 化**是系统学×性能工程的活战场：
   10⁸ agent 的城市/流行病模拟——邻居查找并行化、规则评估向量化
   （active matter 社群的 GPU 模拟框架是现成参照系）
2. **系综计算代替单轨计算**：混沌系统买精度不如买样本——
   大规模并行采样的 embarrassingly parallel 结构（每个样本独立），
   是最友好的并行 workload 之一
3. **分岔扫描 = 参数空间的 embarrassingly parallel**：
   上万组参数各自独立积分——GPU 一次启动全扫
4. **网络分析吃图计算栈**：大图的中心性/社区发现——
   邻接矩阵稀疏算术（对齐 [讲透数值线代](../../讲透数学/讲透数值线代/) 的 SpMV）

## 五、裂缝清单（三件套之三：原则上/工程上的不可转）

1. **涌现判定不可转**：无算法定义输出"真涌现"证书——
   能转的是"度量涌现候选物"（EI/复杂度指标），
   **裁决永远在人**（这是 01 章方向二的核心开放问题）
2. **机制反推欠定不可转**：数据→机制的映射一对多，
   任何"自动发现机制"的输出本质是候选清单不是结论
3. **模型验证的循环性**：ABM 校准用真实数据，但"拟合好"≠"机制对"——
   欠定性在验证环节原样出现
4. **历史不可重放**：演化/社会的单次历史没有对照组——
   计算只能给"可能世界系综"，这本身就是信息损失

## 📌 收束

系统学转码的图景：**模拟天然顺（走廊③是它的母语）、度量全可算
（①②④⑥）、因果测量在青春期（⑤）、涌现判定是永久裂缝**。
按承诺强度选走廊，按裂缝清单打折结论——这套纪律比任何单个工具重要。

**🧠 认知升维**：
- **承诺分层眼**：看到任何"复杂系统模拟"结果，先问它站在哪条走廊
  （跑得出/算得准/证得明）——承诺强度决定证据折扣
- **系综替代眼**：指数敏感的问题不要恋战单条轨迹——
  把算力换成样本量是复杂系统的通用工程策略
- **人工裁决眼**：自动化能送到裁决桌前的一切都该自动化，
  但要清楚最后一步（涌现/机制的解释权）永远坐在桌边等人
