# 04 · 计算机系统结构转代码:架构即代码,与三堵墙的工程学

> **本章回答五问之五:这个分支的问题怎么变成 code 问题。**
> 本质一句话:系统结构是**「转代码」转得最彻底的分支**——
> 架构本身就能是代码(QEMU/gem5/RTL),而性能工程的全部日常,
> 就是把「为什么慢」翻译成三堵墙(访存墙/频率墙/ILP 墙)上的测量。

---

## 一、可机械化边界

| 问题类 | 可机械化吗 | 说明 |
|--------|-----------|------|
| ISA 语义模拟 | ✅ 全自动 | QEMU 类模拟器=合同的可执行化身 |
| 微架构时序模拟 | ✅(模型精度有限) | gem5/自建分析模型(roofline/McPAT) |
| RTL→网表→FPGA | ✅ 全自动 | 综合/布局布线工具链 |
| 程序性能归因 | 🔄 半自动 | perf/PMU 给计数,「为什么」仍需人判 |
| 微架构漏洞发现 | ❌ 基本靠攻防 | Spectre 类侧信道:合同外行为,自动检测是开放问题 |

**为什么是这样**:合同内的一切(语义)可全自动,因为合同就是规格;
合同外的一切(时延、干扰、泄漏)只有测量没有定理——性能是物理不是逻辑。

## 三、工程师落点:三堵墙(性能工程的系统结构宪法)

写给以性能工程为业的读者(本仓库读者画像):**系统结构对工程业的全部
折旧,最终都折在这三堵墙上**——

### 墙 1:访存墙(2026 年的第一墙)
- 计算/访存速度差 1980s 起拉大两个数量级;LLM decode 的算术强度
  ~1-10 FLOP/Byte,**GPU 十位数的 TFLOPS 全部闲置,瓶颈是 HBM 的 TB/s**。
- 工程动作:数据布局(SoA/分块)、算子融合(把访存合并进片上)、
  KV-cache 的容量×带宽预算、prefetch 与 stride 的对症下药。
- 口诀:**先测算术强度,再谈优化**——roofline 之下,一切优化都是搬运学。

### 墙 2:频率墙(Dennard 之死)
- 2005 年前后功耗密度封顶频率(~4-5 GHz 停滞至今);单核性能改为靠
  ILP+缓存+专用指令(SIMD/矩阵指令)挤牙膏。
- 工程动作:SIMD 化(向量化宽度=免费倍速,若数据连续)、
  AVX/RVV 内核、译码友好循环形态。
- 口诀:**频率不涨,宽度来凑——数据连续性就是 SIMD 的入场券**。

### 墙 3:ILP 墙(指令级并行的隐墙)
- 乱序窗口与依赖链限制 IPC;分支预测错一次≈清空流水线。
- 工程动作:减少依赖链(展开/重结合)、分支去除(查表/位技巧/cmov)、
  `llvm-mca` 静态看流水线占用。
- 口诀:**指令再快也要排队——依赖链是隐形的串行段**(Amdahl 的微架构版)。

✨ **美之时刻(04-1)**:**roofline 一页纸**——横轴算术强度、
纵轴可达性能,两条线(带宽斜线×峰值平线)一个交点,
**把三堵墙里的两堵(访存/峰值)压成一张二维地图**,
任何 kernel 一个坐标点定位「还能快几倍」。亲历:跑
[`experiments/roofline_cache.py`](experiments/roofline_cache.py),
给你的环境实测一次带宽,再算你自己代码的坐标。

## 四、Python 层:性能工程的最小工具箱

本家族实验演示三件事,全部纯 numpy 可跑:
1. **roofline 实测**:流式访存带宽+算术强度→定位墙;
2. **缓存行收费**:同行/跨行访问的延迟差(64B 效应);
3. **Amdahl 显形**:不同串行占比下的并行上界曲线。
(把三件事串起来:「测墙→定位墙→算上界」的完整闭环。)

## 不足层

- 三墙模型把热/功耗/尾延迟三线折叠进「墙」的比喻——
  真实系统的多租户干扰( noisy neighbor)在单人微基准里不存在。
- 模拟器忠实度鸿沟:gem5 时序≠硅片;设计级结论要跨 QEMU(功能)、
  gem5(时序)、A64FX/真机(物理)三层验证。

## 这章给了你什么新眼睛(认知升维)

1. **墙眼**:看到任何「慢」,先问哪堵墙;看到任何硬件发布,
  先问它翻的是哪堵墙(HBM=墙 1、chiplet=墙 2 的封装续命、DSA=三墙全绕)。
2. **强度眼**:一切优化前先测算术强度——它是你坐标系的横轴。
3. **测量眼**:架构主张必须可执行;性能主张必须可复现。
   (本仓库性能工程读者已在实践的宪法,这里是它的学科出处。)

## ✍️ 练习

1. 给 GEMM(N³ 计算/N² 访存)与 LLM decode(~每 token 全读 KV)各算
   算术强度,在 roofline 上定位,解释为什么训练卡爱 FLOPS、推理卡爱 HBM。
2. 把一段按列遍历的代码改为按行,预测加速比并实测(实验脚本可复现);
   解释你买到的是墙 1 的哪一段。
3. 反直觉:为什么加更多核反而可能让总吞吐下降?(窥探流量/内存带宽争用
   ——并行的负和效应)
