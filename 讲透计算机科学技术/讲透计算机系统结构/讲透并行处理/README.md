# 讲透并行处理 · 从流水线到 GPU 的并行谱系(52030·20)

> 定位句:这支负责的问题是「**怎么把并行性从程序里挤出来、在硬件上跑起来**」——
  指令级(流水线/乱序/SIMD)→ 线程级(多核/同步)→ 数据级(GPU/脉动阵列)。
> GB/T 13745-2009:520·52030·20 并行处理。
> 家族:[讲透计算机系统结构](../README.md)

## 诞生

📖 1961 IBM Stretch/1964 CDC 6600(乱序执行的鼻祖,Cray 设计的
「scoreboard」比现代 ROB 早 30 年);1985 后流水线+缓存成为标配;
2005 频率墙后多核强行登场;2012 Keccak…不对——2012 年后 GPU 通用化
(CUDA 2007 播种),机器学习把 GPU 并行推成时代主旋律。

## 核心问题

已解决:
- **流水线/乱序**:单线程 IPC 从 <1 推到 4-6(依赖链内的极限工程)
- **缓存一致性协议**(MESI 族):共享内存的合法性工程
- **GPU 执行模型**:SIMT——硬件把「数千线程」映射到「数千 ALU」的调度宪法

未解决:
- 内存模型的统一(RVWMO/TSO 各自为政,跨平台编程仍靠 seq_cst 保险丝)
- 并行软件的「默认正确」(并发 bug 至今无系统化解法)

## ✨ 这支最美的一个事实

MESI 四态协议用「修改/独占/共享/无效」四个字母+窥探总线,
让**任意多核共享一个「假内存」**——每个核都以为自己独占,
协议在幕后合谋。一页状态转换图=现代多核的合法性出生证。
