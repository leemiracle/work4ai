# 讲透计算机网络 · 分层、分组与端到端之争(52030·40)

> 定位句:这支负责的问题是「**比特怎么可靠地穿过不可靠的世界**」——
  分层解耦、分组交换、协议栈;从 ARPANET 四机实验到今天数据中心
  的 RDMA/参数面网络。
> GB/T 13745-2009:520·52030·40 计算机网络。
> 家族:[讲透计算机系统结构](../README.md)

## 诞生

📖 1969 ARPANET 四节点;1974 Cerf-Kahn TCP 论文(网络中立原则的出生纸:
  「网络只管搬运,不懂内容」);1983 TCP/IP 切换;1989 WWW;
  2010s 数据中心网络(TCP 拥塞控制进化/ECN/RDMA)成为 AI 集群的血管。

## 核心问题

已解决:
- **分层解耦**(OSI 七层→事实 TCP/IP 四层):每层只解决本层问题,
  接口稳定使整栈各层独立演进 50 年
- **分组交换**胜出电路交换:统计复用+无损降级
- 拥塞控制的进化史(KCP/TCP Reno→CUBIC→BBR):从「丢包=拥塞」到
  「测量带宽×时延积」的范式转移

未解决:
- 跨域路由的策略性(BGP 的信任模型=互联网的阿喀琉斯之踵)
- 尾延迟(tail latency)的系统性治理(见 [性能评价支](../讲透性能评价/))

## ✨ 这支最美的一个事实

**端到端原则**(Saltzer-Reed-Clark 1984):「功能放尽可能低的层,
除非只有端点能做对」——一句话给整座协议塔定了立法哲学:
网络的智能该住在边缘。TCP 的可靠性在端点不在网络,恰是这条原则的化身。

## 假设与依赖

- 分层的代价:每层头开销+跨层信息失语(DCN 时代被 ECN/INT 局部打破)
- 假设链路会丢包(最坏情况设计)——数据中心无损网(RoCE)是
  对该假设的局部背叛,换来的是 PFC 死锁的新问题
