  一致性模型、共识、容错:在「没有全局时钟、消息会丢、机器会死」的
  三个悲观假设上,建出可靠系统。

## 诞生

📖 1978 Lamport「分布式快照」之前的岁月;1982 Lamport-Shostak-Pease
拜占庭将军;1985 FLP 不可能定理(异步共识在哪怕一台机宕机时不可达!);
1998-2001 Google 用 GFS/MapReduce 把分布式从理论变成印钞机;
2013 后 Raft/Paxos 进入每一家数据库。

## 核心问题

已解决:
- **共识算法**(Paxos/Raft):多数派在部分失败下对「谁说了算」达成一致
- **CAP 定律**(2000 Brewer/2012 Gilbert-Lynch 证明):分区时,
  一致性与可用性二选一——不可兼得是定理不是工程失误
- 向量时钟/CRDT:无共识的最终一致路径

未解决:
- 高效拜占庭容错(BFT)的性能墙(区块链是它的社会实验场)
- 跨数据中心的低延迟一致性(物理光速为界)

## ✨ 这支最美的一个事实

FLP 不可能定理:**异步系统里,哪怕只允许一台机器宕机,
共识也不存在总是终止的确定性算法**——一个「不可能」的证明
反而给整个领域指路:要么放弃确定性(随机化)、要么放宽活性(阻塞)、
要么放宽故障模型。** impossibility 是这个领域的地图**。

## 假设与依赖

- 三大悲观假设(无全局时钟/消息可丢/机器可死)——放弃任何一个,
  系统立刻退化成玩具
- 单机并行(本家族 [并行处理支](../讲透并行处理/))是它的地基
