# 讲透计算机系统设计 · ISA 合同与整机组织(52030·10)

> 定位句:这支负责的问题是「**机器对程序承诺什么**」——ISA 作为合同的定义、
> 微架构作为履约方式的选择、整机(总线/中断/IO)作为合同的配套设施。
> GB/T 13745-2009:520·52030·10 计算机系统设计。
> 家族:[讲透计算机系统结构](../README.md)

## 诞生

📖 1964 年 IBM System/360:「architecture」一词首次=「程序员可见的机器属性」,
一份合同、一族实现——软件投资从此可以跨代保值。1980s RISC 革命
(Berkeley RISC/Stanford MIPS)证明:**合同可以更瘦,履约可以更猛**——
简化指令集把腾出的芯片面积还给流水线与缓存。

## 核心问题

已解决:
- **ISA 兼容族**(360 血统):抽象层级成为产品
- **RISC vs CISC 之辩**(定论:合同瘦+编译器聪明>合同胖+硬件硬译)
- 存储管理(虚地址/页表/TLB)把「每程序独立内存」的假象工程化

未解决:
- 安全如何在合同中表达(Spectre 后仍在补丁式演进)
- DSA 时代「合同」的粒度(指令级?算子级?图级?)

## ✨ 这支最美的一个事实

同一份 ARM 合同,Apple P 核与低端微控制器相差 **10 倍以上性能**——
合同只规定语义,不规定速度;**「兼容」与「等速」的分离**,是 1964 年
最大的商业发明,也是一切微架构创新的空间所在。

## 假设与依赖

- 抽象的代价:合同隐藏性能(见家族 [02 章](../02-语言特征.md)「谎言表」)
- 二进制兼容的市场前提:软件生态价值>硬件差异价值
