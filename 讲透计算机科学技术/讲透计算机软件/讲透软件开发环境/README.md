## 诞生

McIlroy 1969（管道——组件复用的第一枪）；Make 1976（Feldman，构建自动化
鼻祖）；git 2005（Torvalds 十天写出的分布式版本控制，Linus 与 BitKeeper
决裂的副产品——愤怒驱动的杰作）；CI 普及（2010s）；语言服务器协议 LSP
（2016，微软——"编辑器×语言"的接口标准化，AI 结对编程的地基之一）。

## 核心问题（已解决/未解决）

- ✅ 分布式版本控制（git 的 DAG 模型——时间线可分叉可合并）
- ✅ 增量构建与依赖解析（Make/Bazel 系）
- ✅ LSP：一次实现，所有编辑器受益（接口标准化的胜利）
- 🔄 依赖地狱（传递依赖的组合爆炸——Log4j 事件的机制）
- 🔄 AI 原生开发环境（Copilot/Agent 进 IDE——生成/审读/验证的新分工）
- ❌ "重构工具的语义正确性"（文本 diff 与语法树之间的永恒错位）

## 这支最美的一个事实

**git 的对象模型只有一个核心：不可变对象 + 内容寻址**（blob/tree/commit
的哈希链）——一个纯函数式的数据库设计，撑起了全球软件协作。
（对照：区块链是同一思想的慢速重演。）

## 假设与依赖

假设代码=文本（diff/merge 的前提）；假设构建可重现（可重现构建是
供应链安全的基石，也是持续攻坚的目标）。
