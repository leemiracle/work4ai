# 04 · 软件转代码：本域即本体——怎么把软件家族变成你的手艺

> **本章回答五问之五（家族层）。** 计算机软件这个分支的特殊性：
> 它**本身就是"问题→代码"的工业化现场**——所以本章不问"能不能转码"，
> 问"**怎么把这门手艺变成你的**"：可机械化边界在哪、代码走廊怎么走、
> 工程师落点在哪。（三件套，每栏答"为什么是这样"。）

---

## 一、可机械化边界：什么能自动，什么必须你出手

| 环节 | 机械化档位 | 为什么 |
|---|---|---|
| 源码→目标码（编译） | ✅ 全自动 70 年 | 输入是形式语言，变换规则可完全形式化 |
| 测试生成 | 🔄 半自动（LLM 生成+覆盖率引导） | 语义不可判定（Rice），只能保守近似 |
| 正确性证明 | 🔄 半自动（SMT 解决策过程；循环不变式靠人） | 不变式是创造，不是推导 |
| 架构/重构决策 | ❌ 人（+LLM 建议） | 结构是约束下的价值选择（00 章"架构不可构造"） |
| 需求→规格 | ❌ 人（本质上） | 自然语言的歧义消除=领域理解 |

**为什么是这样**：越靠近**形式**（语言/文法/类型）越可机械化，
越靠近**意图**（架构/需求）越不可——这条边界就是 02 章 Rice 定理的工程投影。
LLM 压缩了中间两档（测试/局部证明），但两端的边界纹丝不动。

## 二、代码走廊：每支一条"自己写一个"的经典线

软件家族学"转码"的方式独一无二：**写玩具复刻**（toy reimplementation）——
每支都有公认的"亲手写一遍胜读十年书"项目线：

| 支 | 走廊（难度升序） | 工作量 | 你会获得 |
|---|---|---|---|
| 程序设计语言 | 本家族 [`experiments/04_toy_interpreter.py`](experiments/04_toy_interpreter.py) → *Crafting Interpreters*（Nystrom，树遍历+字节码两遍） | 周末→一月 | 语言的全部神秘感消失 |
| 编译系统 | *Writing a C Compiler*（Nora Sandler）/ chibicc（Rui Ueyama，可自举的 C 教学编译器） | 1-2 月 | 优化=保守近似的直觉 |
| 操作系统 | xv6（MIT 6.1810，RISC-V 教学内核）→ *Operating Systems: Three Easy Pieces* 配套实验 | 一学期 | 虚拟内存/并发从名词变手感 |
| 数据库 | CMU 15-445（BusTub 迷你库）/ *SQLite Database System*（源码解析书） | 一学期 | 事务/B+树/查询计划的真实重量 |
| 软件理论 | *Types and Programming Languages*（Pierce）前半 + 一个玩具类型检查器 | 一学期 | 类型=证明的手感 |
| 软件工程 | 给一个真实开源项目提 PR（从 good-first-issue 起） | 持续 | 协作纪律是练出来的 |
| 软件开发环境 | 自建一个 dotfiles+CI 流水线 | 一周 | 工具链思维 |

**为什么"写玩具"有效**：软件的复杂度来自**规模**，而理解来自**结构**——
玩具剥离规模、保留结构。这正是讲透范式"直觉→数学→代码跑通"的软件版。

## 三、工程师落点（性能工程视角）

本家族的三大高性能战场——恰好是用户背景（CUDA/编译/性能优化）的天然主场：

1. **编译器即性能引擎**：一切"AI 编译器"（XLA/TVM/Inductor/Triton）= 编译系统支
   的直接延伸——图层→算子→SASS 的多级中间表示，每一级的合法变换规则
   都是编译原理。[`../../讲透高性能计算/`](../../讲透高性能计算/) 是纵深现场。
2. **数据库=一切 AI 应用的存储引擎**：向量检索的 ANN 索引（HNSW/IVF）=
   数据库支的新经典结构——工程上"P99 延迟"的战场。
3. **OS/运行时=性能的地板**：io_uring、NUMA、eBPF——性能优化的尽头
   是系统调用层。[`../../讲透vLLM/`](../../讲透vLLM/) 展示了"一个 Python 应用
   如何一路挖到 CUDA graph"的全链路。

✨ **美之时刻：LLVM 的一点中间表示（IR）哲学**
一句话：一个机器无关的中间语言，让 N 种语言 × M 个目标机从 N×M 个编译器
变成 N+M 个前端/后端。
为什么美：**极简**（一条软件工程浩劫的分治答案）+ **统一**（AI 时代
MLIR 把同一思想抬到张量层，GPT 级模型的编译栈仍是这条走廊的延伸）。
怎么亲历：装一个 `llvmlite`，用 30 行 Python 构造 IR 并 JIT 执行——
"中间表示"从名词变亲手。

## 四、Python 层

[`experiments/04_toy_interpreter.py`](experiments/04_toy_interpreter.py) 全流程：
```
python experiments/04_toy_interpreter.py
```
断言 fib(15)=610（递归闭包求值）+ 词法/语法自检。
扩展走廊（每条 ≤20 行，都是一次"转码"练习）：
- 加 `while` 特殊形式（语法+eval 各 5 行）——文法先行
- 加整数运算的短路求值——操作语义的修改
- 把 Environment 换成 immutable 链（copy-on-write）——指称语义的味道

## 五、不足层

- 玩具线偏系统软件；应用框架（Web/移动）的"写玩具"传统较弱
- LLM 时代的"转码"含义在漂移：生成不再是瓶颈，**审读与验证**成为新瓶颈——
  本家族的走廊清单尚未吸收这一转变（01 章方向一的余波）
- 性能工程落点以训练/推理栈为主；嵌入式/车载软件另有走廊未列

## ✍️ 练习

1. 从走廊表选一条，排进你未来 4 周的日程——写下来（承诺装置）。
2. 用 `llvmlite`（或任何 IR）写一个 30 行 JIT：乘法表函数的编译→执行→断言。
3. 反直觉题：为什么"学编译器"对一个不写编译器的工程师仍是高回报投资？

## 📌 收束

软件家族的"转码"答案：**别学软件，做软件**——每支的玩具线就是最短的
"问题→代码"回路。走完一两条，你对所有软件的判断力都会换挡。

**👀 这章给了你什么新眼睛**：看到任何中间件/框架，先想"它的玩具版我能写吗、
要几天"——能估算的那一刻，它对你的信息不对称就破除了。
