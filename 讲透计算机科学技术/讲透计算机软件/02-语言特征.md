# 02 · 语言特征：表达、逻辑与规范化的软件方言

> **本章回答五问之三（家族层）：表达？逻辑？规范化？**
> 软件家族的母语不是自然语言也不是数学——是**形式语言**：先声明文法、
> 再定义语义、最后立标准。三栏分别答：形式语言能说什么、程序的性质能否推理、
> 这门产业为什么是"标准帝国"。

---

## 一、表达力：图灵完备 ≠ 好用

直觉图像：想象"表达力"是一架钢琴——图灵完备只是"能弹出所有音符"，
**好不好弹（抽象机制）才是乐器的品质**。

| 表达层 | 能说 | 说不说得好 |
|---|---|---|
| 机器码 | 一切（图灵完备） | 苦役：人类不可读 |
| 汇编 | 一切 | 仍是一个个寄存器搬砖 |
| C（1972） | 一切 | 手动内存——"可移植汇编" |
| 函数式/类型化语言 | 一切 + **不变式进类型** | Rust：所有权让"数据竞争"**在类型层写不出来** |

**为什么是这样**：表达力的真正度量不是"能算什么"（丘奇-图灵论题下大家都能算），
而是"**什么错误在编译期就写不出来**"。类型系统 50 年的进化史 =
把运行时错误逐步搬进编译期的历史（空指针→Optional、数据竞争→所有权）。

**反直觉发现**：最强的表达力未必是好事——图灵完备让优化不可判定
（Rice 定理：程序的任何非平凡语义性质都不可判定），所以 Halide/Cirq 类
**故意用受限语言**（无循环/受限控制流）换回可判定优化与验证。
**少说一点，机器才能多懂一点。**

## 二、逻辑性质：程序的性质能否推理

程序语义三大流派——"这个程序是什么意思"的三种回答：

| 流派 | 一句话 | 招牌工具 | 回答的问题 |
|---|---|---|---|
| 操作语义（1964 Plotner 起，Structural 1981 Kahn） | 意义 = **怎么算**（小步/大步规则） | 推理规则 | "跑起来会发生什么" |
| 指称语义（1964 Strachey/Scott） | 意义 = **数学对象**（函数/域） | 不动点理论 | "等价于什么数学函数" |
| 公理语义（1969 Hoare） | 意义 = **满足什么断言** | Hoare 三元组 {P}C{Q} | "执行后什么成立" |

**为什么是这样**：三种语义对应三种使用场景——写解释器用操作语义、
证明两个编译阶段等价用指称语义、验证程序正确性用公理语义。
它们不是竞争而是**同一对象的三视图**（一致性定理证明其协调）。

✨ **美之时刻：Hoare 三元组 {P} C {Q}（1969）**
一句话：程序 C 是从前置条件 P 到后置条件 Q 的证明规则——**程序即证明步骤**。
为什么美：**统一**（把"跑程序"与"证明定理"变成同一件事，Curry–Howard 的程序侧）
+ **必然**（为什么测试永远不完：测试验证 P→Q 的一条路径，证明验证全部路径）。
怎么亲历：手写整数除法的三元组推演（前置 x≥0, y>0，后置商余关系），
你会第一次"不用运行就知结果"。

**可判定性档位**（逻辑性质小结）：
- 文法：可判定（LR 分析器自动生成）
- 类型检查：主流系统可判定（Hindley–Milner 线性时间）
- 等价性/优化合法性：不可判定（Rice 定理）——编译器优化全是"保守近似"
- 程序验证：半自动（SMT 解码决策过程）——正是形式化验证家族的用武之地

## 三、规范化：标准帝国为什么存在

软件是**人类历史上最规范化的工程学科**——每层都有法规级标准：

| 层 | 标准 | 后果 |
|---|---|---|
| 语言 | ISO C（C89→C23）、ECMAScript、Python（PEP/de facto） | 同一份源码跨平台三十年 |
| OS 接口 | POSIX、Linux syscall ABI 稳定性 | 1990 年的二进制今天还能跑（向后兼容的奇迹） |
| 数据 | SQL 标准（ISO 9075）、Unicode、JPEG/AV1 | 数据的宪法——跨厂商跨年代 |
| 网络 | RFC 体系（TCP/IP/HTTP/QUIC） | 互联网的地基是文档，不是代码 |

**为什么是这样**：软件的边际成本近零 + 网络效应 → **赢家通吃 → 锁定 →
标准成为战场**。标准不是学术洁癖，是产业的地契。（对照：数学的"规范化"
靠公理系统自我约束；软件的规范化靠**合同**——标准文档即多方合同。）

📖 故事框：**Unicode 之战**。一个"字符如何编码成字节"的问题，
牵动全球四十年的文字系统、字体厂商与操作系统——UTF-8 的胜利
（Thompson/Pike 1992，一页草稿纸）是"简单方案穿越政治"的稀有案例。

## 五、不足层

- 形式语义覆盖的仍是软件的"顺序核心"；并发语义（内存模型）是标准化的
  重灾区（C++/Java 内存模型各不相同且都在演化）
- 标准滞后于实践：de facto 标准（如 Python 的 PEP 流程）与 de jure 标准
  （ISO）的张力是永恒主题
- 本章三栏以系统软件为纲；领域语言（DSL）的表达力问题归编译系统支

   被挡住的？（类型？所有权？纯度？）
2. 用 Hoare 三元组给 `swap(a,b)` 写规格；注意别名（a=b 时）会怎么毁掉它。
3. 反直觉题：为什么"更严格的类型系统"反而往往**提高**表达力上限的**实用值**？

它把什么错误从运行时搬到了编译时？它的语义有没有形式定义？它有没有标准（或成为标准的路径）？
三个都有答案的才值得投入。
