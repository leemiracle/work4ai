# 讲透数据库 · 数据的宪法

> 这支负责：**数据凭什么比程序活得久**——关系模型、事务、查询优化、
> 存储引擎、分布式一致性。数据库是软件家族里"宪法"最成文的一支：
> ACID 与 CAP 是两部成文法。
>
> GB/T 13745：52040·数据库。家族：[讲透计算机软件](../README.md)。

## 诞生

Codd 1970《A Relational Model of Data for Large Shared Data Banks》——
IBM 内部一篇论文，把数据从"指针导航"解放进"集合代数"，立起一个产业；
System R（1970s，SQL 与事务的原型）；Oracle/Ingres 商业化；NoSQL 运动
（2000s，CAP 站位多样化）；NewSQL/云原生（2010s）；向量数据库（2020s，
LLM 的记忆层）。

## 核心问题（已解决/未解决）

- ✅ 关系模型与关系代数（数据独立于程序）
- ✅ ACID 事务与并发控制（2PL/MVCC——"隔离级别"光谱）
- ✅ 查询优化（基于代价的优化器——声明式的回报）
- ✅ B+ 树与 LSM 树（读写不对称的两条存储路线）
- ✅ CAP 定理（Brewer 2000 / Gilbert-Lynch 证明——分布式一致性的物理边界）
- 🔄 HTAP（事务与分析合一）、存算分离（云原生）
- 🔄 语义检索（向量索引 HNSW/IVF 与传统索引的融合——正定型中）
- ❌ "最优 schema 设计"（领域问题，无通用解）

## 这支最美的一个事实

**你只说"要什么"（SQL 声明式），优化器决定"怎么拿"（查询计划）**——
一句 SELECT 背后是关系代数等价变换的全自动搜索。声明式的胜利是
数据库送给全部软件家族的范式礼物。
