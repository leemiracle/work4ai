# 00 · 体系结构：软件家族的全图

> **本章回答五问之一（家族层）：整个体系结构长什么样。**
> 软件 = 让硬件可编程的一切中间层。硬件是晶体管的海洋，人类无法直接住在海上——
> 我们住在五层中间层里：**语言、操作系统、数据库、编译器、工程纪律**。
> 本章给这七支的地盘、它们怎么互相喂养、以及这一切是怎么被三个原生问题逼出来的。

---

## 一、三个原生问题（怎么产生的）

📖 **故事开篇：1945 年的飞蛾**。Grace Hopper 的团队把一只飞蛾从继电器里夹出来，
贴在日志本上写"第一个真 bug"。那个年代"软件"这个词还不存在——程序是硬件的附属品。
三个问题把它变成了独立宇宙：

| # | 原生问题 | 逼出的分支 | 关键人物/事件 |
|---|---------|-----------|--------------|
| 1 | **怎么让人类写得动机器指令？**（汇编读不下去） | 程序设计语言 + 编译系统 | FORTRAN 1957（Backus，32 人年写出的第一个编译器）；Lisp 1958；Algol 60 报告——语法的形式化描述（BNF）从此语言有了"文法" |
| 2 | **怎么让多个程序共享一台机器？** | 操作系统 | Atlas 1962（虚拟内存）；UNIX 1969（Thompson/Ritchie，"一切皆文件"）；Multics 的教训→UNIX 的简洁 |
| 3 | **数据凭什么比程序活得久？** | 数据库 | Codd 1970 关系模型（一篇论文立一个产业）；System R 与 Oracle 的商业化；事务 ACID |

第四个问题 1968 年才爆发——**软件危机**：NATO 会议（Garmisch）上"软件工程"
这个词被造出来，承认"我们写不动大软件了"。OS/360 的教训（Brooks《人月神话》1975：
**向进度落后的项目加人只会更落后**——Brooks 定律）把"工程纪律"立为第七支。

## 三、相互喂养图（家族内的依赖经济）

```
软件理论 ──给骨架──▶ 程序设计语言（类型系统的数学）
                    ▶ 程序验证（形式化验证家族，就地成员）
程序设计语言 ──给语法树──▶ 编译系统（编译=语言的自动翻译器）
编译系统 ──给执行格式──▶ 操作系统（可执行文件/ABI）
操作系统 ──给进程/文件──▶ 数据库（存储引擎建在文件与页缓存上）
数据库 ──给持久层──▶ 一切应用（AI 时代：向量数据库=LLM 的记忆）
软件工程 ──给纪律──▶ 全家（没有它，六件套=六个坑）
```

**反直觉发现**：层次是**倒金字塔**——硬件层最薄（一套指令集），越往上越厚
（语言生态、框架、应用）。软件史的主旋律不是"造更好的硬件"，而是
**在薄硬件上垒出千层中间件**。你每天的工作几乎全部发生在最厚的顶层。

✨ **美之时刻：Codd 的关系模型（1970）**
一句话：数据 = 关系（集合）上的命题，操作 = 关系代数。
为什么美：**极简**（一张二维表 + 五种代数操作，撑起五十年的产业）+
**必然**（第五范式之后的 NoSQL 运动，兜兜转转又回到 SQL——2020s 的
"SQL 回潮"证明这层抽象选对了）。
怎么亲历：手写 30 行 Python 实现选择/投影/连接，你会立刻明白
"声明式"为什么赢——你只说**要什么**，不说**怎么拿**。

## 四、核心问题清单（③已解/未解）

| 问题 | 状态 | 一句意义 |
|------|------|---------|
| 结构化程序定理（Böhm–Jacopini 1966） | ✅ 已解 | 顺序/选择/循环三件套图灵完备——结构化编程的合法性证明 |
| 关系模型与 SQL 标准化 | ✅ 已解 | 数据独立于程序——"数据比程序活得久"的宪法保障 |
| 编译器全自动构造（自举） | ✅ 已解 | C 编译器用 C 写（自举 1958 起）——翻译器可以翻译自己 |
| 并发程序的正确性推理 | 🔄 前线 | 线程交错的状态爆炸——线性化/不变式是部分答案，验证仍是圣杯 |
| 软件工程的生产力度量 | ❌ 未解 | "加人更慢"（Brooks 1975）至今没有根治——人月不是人月 |
| 程序综合（从规格自动生成程序） | 🔄 前线 | LLM 正在逼近但"对不对"仍无保证——形式化验证家族的用武之地 |

## 五、假设与代价（④每个假设买到什么、付出什么）

| 假设 | 买到 | 付出 |
|------|------|------|
| 分层抽象（每层只信下一层的契约） | 组合性：上层可独立演进 | 性能损失 + 调试距离（bug 可能藏在任一层） |
| 图灵完备的语言表达力 | 什么都能写 | 什么都能写错——不可判定性：没有通用程序检查器（停机定理） |
| 数据与程序分离（数据库的存在前提） | 数据长寿、独立审计 | 对象-关系阻抗失配（ORM 之痛） |
| 文本代码 + 版本控制 | diff/merge 可行、协作民主 | 语义操作难（重构工具永远在补文本→结构的映射） |
