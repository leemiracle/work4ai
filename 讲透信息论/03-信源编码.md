## 1. 灵魂：Shannon 极限怎么工程化

00 实验证明：算术编码几乎完美逼近 Shannon 熵 $H$。但工程上有一堆细节：

| 算法 | 工程难点 | 解决思路 |
|------|---------|---------|
| 霍夫曼 | 整数位限制（高概率符号浪费） | 分组（k 元组） |
| 算术编码 | 浮点精度（区间下溢）| 整数 renormalization |
| LZ77 | 不利用概率，靠序列重复 | 滑动窗口匹配 |
| DEFLATE/LZMA/Brotli | 组合多种技术 | 各家工程优化 |

**核心论断**：现代压缩格式 = LZ77（利用重复）+ 霍夫曼/算术（利用概率）+ 上下文建模（利用条件概率）。

## 2. 霍夫曼编码：简单但有"整数位"限制

### 2.1 算法

[David Huffman 1952](https://en.wikipedia.org/wiki/Huffman_coding) 提出。每次合并两个频率最低的符号，建一棵最优二叉树。

```
符号频率: A:0.7  B:0.15  C:0.1  D:0.05
                       │
建树:        ●  ←根
           /   \
         A(0.7)  ●  ← B+C+D=0.3
                / \
              B(0.15) ●
                     / \
                   C(0.1) D(0.05)
码本: A=1, B=00, C=011, D=010
```

### 2.2 实测：霍夫曼 vs 理论 H

分布 $P = \{A:0.7, B:0.15, C:0.1, D:0.05\}$，$H = 1.319$ bit：

| 符号 | $P$ | 理论位 $-\log_2 P$ | 霍夫曼位 |
|:--:|:--:|:--:|:--:|
| A | 0.7 | **0.515** | **1** ← 浪费 0.485！ |
| B | 0.15 | 2.737 | 2 |
| C | 0.1 | 3.322 | 3 |
| D | 0.05 | 4.322 | 3 |

**平均 = 1.450 bit**，比理论 $H = 1.319$ 多 **0.131 bit（9.9% 浪费）**。

### 2.3 整数位限制的本质

霍夫曼的码长必须是整数（1, 2, 3, ...），但 $-\log_2 P$ 通常不是整数（如 $-\log_2 0.7 = 0.515$）。

**浪费主要在高概率符号上**：A 概率 0.7，理论只需 0.515 bit，但霍夫曼最少给 1 bit。

### 2.4 解法：分组霍夫曼

把 $k$ 个连续符号当一个"超级符号"，建霍夫曼。实测（英文文本）：

| $k$ | 平均 bit/字符 | 与 H 差距 |
|:--:|:----------:|:--------:|
| 1 | 4.09 | 1% |
| 4 | 1.68 | — |
| 8 | 0.87 | — |

**$k$ 越大越逼近 H**——因为分组让"超级符号"的概率更分散，整数位浪费被均摊。但 codebook 大小指数膨胀（$|alphabet|^k$）。

## 3. 算术编码：分数位编码

### 3.1 思想

不用单独编码每个符号，把整串符号映射到 $[0, 1)$ 区间内的一个**小数**。

```
区间 [0, 1)
   ├─ [0, 0.3)     ← A 占 30%
   │     ├─ [0, 0.15)   ← AA
   │     └─ [0.15, 0.3) ← AB
   ├─ [0.3, 0.7)   ← B 占 40%
   └─ [0.7, 1)     ← C 占 30%

编码 "ABC..." = 找到最深的子区间, 用该子区间内任一数表示
```

### 3.2 为什么能完美逼近 H

每个符号占的区间大小 $\propto$ 其概率。一串符号最终的区间大小 = $\prod_i P(x_i)$。

$$
\text{编码长度} = -\log_2(\text{区间大小}) = -\log_2 \prod_i P(x_i) = \sum_i -\log_2 P(x_i) = \mathbb{E}[I]
$$

完美等于 $H$！

### 3.3 工程难点：浮点精度

朴素浮点实现，区间收缩太快下溢（实测 batch=20 时已下溢）。解决方案：
1. **小 batch**（如本实验的 batch=10）
2. **整数 renormalization**（每收缩到一半就输出位，工业实现标配）
3. **二进制算术编码**（用 64 位整数模拟）

### 3.4 实测对比

| 文本 | 经验 H | 霍夫曼 1-gram | 霍夫曼 8-gram | **算术** | LZ77 |
|------|:----:|:----------:|:----------:|:------:|:--:|
| 英文 | 4.06 | 4.09 | 0.87 | **4.15** | 0.50 |
| 中文 | 5.12 | 5.20 | 0.30 | **5.21** | 0.76 |

**算术编码 ≈ H（差距 ~2%）**——这就是 Shannon 极限的工程化。

## 4. LZ77：突破 symbol-wise 上限

### 4.1 思想

[Lempel-Ziv 1977](https://en.wikipedia.org/wiki/LZ77_and_LZ78) 不依赖概率，只依赖**序列重复**。用滑动窗口找已出现过的子串，编码成 `(距离, 长度)` 对。

```
文本: abcdefg...abcdefg...
                ↑
        在窗口 (前 12 字) 里找最长匹配
        找到 "abcdefg" 出现在 dist=12, len=7
        编码: (12, 7) ← 只用 2 个数字代替 7 个字符
```

### 4.2 为什么 LZ77 能突破 H

$H$ 是 **symbol-wise** 的极限（假设符号独立）。但自然语言**符号不独立**——"qu" 后必跟 "ick/een/..."。LZ77 直接利用这种序列重复，**编码长度可低于 H**。

实测：英文重复文本 LZ77 = 0.50 bit/字符（远低于 H=4.06）。

### 4.3 LZ77 的弱点

- 对**第一次出现**的内容无能为力（必须字面编码）
- 对**概率分布**不敏感（不像熵编码能自适应）

→ 这就是为什么现代压缩都是 **LZ77 + 熵编码**的组合。

## 5. 现代压缩格式：组合拳

| 格式 | 算法 | 英文压缩比 | 中文压缩比 | 应用 |
|------|------|:--------:|:--------:|------|
| 原始 | 无 | 100% | 100% | — |
| 霍夫曼 | symbol-wise | 35% | 16% | 早期 |
| 算术 | 单字符 | ~75% | ~100% | JPEG2000, H.264 |
| LZ77 | 滑动窗口 | ~50% | ~75% | 早期 |
| **DEFLATE** | LZ77 + 霍夫曼 | 35% | 55% | **gzip/zip** |
| **LZMA** | LZ77 + 算术 + Markov | 27% | 45% | **7z/xz** |
| **Brotli** | LZ77 + 霍夫曼 + 上下文 | 25% | 42% | **Web (HTTP)** |
| **zstd** | LZ77 + FSE/ANS | 28% | 48% | **Facebook, Linux 内核** |

**核心组合**：LZ77（利用重复）+ 熵编码（利用概率）+ 上下文建模（利用条件概率）。

### 5.1 ANS：2014 年的新革命

[Asymmetric Numeral Systems](https://arxiv.org/abs/1311.2540)（Jarek Duda 2014）结合了霍夫曼的速度和算术的精度，是 zstd/FSE 的基础。**现代压缩几乎都从算术迁到 ANS**。

## 6. 信息论 → AI：Compression is Intelligence

### 6.1 LLM 是上下文自适应熵编码器

LLM 训练 loss = $-\log p_\theta(x_t | x_{<t})$。这是**条件熵**——给定上文，下个 token 的平均码长。

- 训练越好 → loss 越低 → 等价于越来越好的"上下文熵编码器"
- 比 LZ77 / Brotli 都强：能利用**任意长 context + 自然语言统计**

### 6.2 实测：DeepMind 2024

[DeepMind 2024 论文](https://arxiv.org/abs/2405.17070) 在 enwik8（100MB 维基百科）上测：

| 压缩器 | bit/字符 |
|--------|:------:|
| bzip2 | 1.20 |
| LZMA (7z) | 1.01 |
| **Chinchilla 70B** | **0.88** ← LLM 最强 |

**LLM 在压缩上击败了专用工具**。这就是 "Compression is Intelligence" 的实证——能压得越短 = 越理解语言 = 越智能。

### 6.3 信息论→AI 的桥

- **next-token CE = 编码长度**（02 已证）
- **MDL = 模型复杂度 + 编码长度**（06 详讲）
- **Tokenizer = 字符压缩到 token**（高频 token 短，低频 token 长，本质是霍夫曼）

## 7. 一句话总结

> **霍夫曼 symbol-wise 简单但整数位限制（高概率符号浪费 ~10%）；算术编码让"分数位编码"成为可能，几乎完美逼近 H；LZ77 利用序列重复，能突破 symbol-wise 上限（实测重复文本压到 0.5 bit/字符）；现代格式（DEFLATE/LZMA/Brotli/zstd）都是 LZ77 + 熵编码 + 上下文建模的组合。LLM 训练 = 学一个比任何手工压缩都强的上下文自适应熵编码器——DeepMind 2024 实测 Chinchilla 70B 在 enwik8 上击败 LZMA。Compression is Intelligence。**
