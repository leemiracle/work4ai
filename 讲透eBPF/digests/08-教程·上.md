## [98] bcc Reference Guide

- **是什么**：iovisor/bcc 官方参考手册（本地克隆 master 版），BPF C 侧 + bcc Python 侧的完整 API 字典，2643 行。
- **核心内容**：三大部分——①BPF C：12 类挂载点（kprobes/kretprobes/tracepoints/uprobes/uretprobes/USDT/raw tracepoints/syscall tracepoints/kfuncs/kretfuncs/LSM probes/BPF iterators）+ data helpers（bpf_probe_read_kernel/_str、bpf_ktime_get_ns、bpf_get_current_pid_tgid/uid_gid/comm/task、bpf_get_ns_current_pid_tgid 等）+ 输出（bpf_trace_printk、BPF_PERF_OUTPUT、BPF_RINGBUF_OUTPUT 及 ringbuf_reserve/submit/discard/query 全套）+ 18 种 map 类型（HASH/ARRAY/HISTOGRAM/STACK_TRACE/PERCPU_*/LPM_TRIE/PROG_ARRAY/DEVMAP/CPUMAP/XSKMAP/QUEUE/SOCKHASH/map-in-map 等）及其 lookup/update/push/pop 等 34 个操作。②bcc Python：BPF() 构造器（text/src_file/usdt_contexts/cflags/debug 位掩码）、attach 系列、USDT API。③**Rewriter 机制**：bcc 把隐式内存访问改写为显式 helper 调用；`ARCH_HAS_NON_OVERLAPPING_ADDRESS_SPACE`（x86/arm 有、s390 无）决定隐式访问默认用 bpf_probe_read 还是 bpf_probe_read_kernel——跨架构移植 bcc 程序时的关键坑。
- **亮点**：LSM probes、BPF iterators、kfuncs 这些新挂载点的权威说明；每个 API 都带可运行片段。
- **对学习者**：写 bcc 程序时的案头字典，按目录跳读即可，不必通读。
- **对 AI agent**：本地 /usr-data/data2/kylin/network/awesome-ebpf/web/md/98.md，可 grep 具体 helper 名（如 `bpf_probe_read_user_str`、`BPF_RINGBUF_OUTPUT`、`attach_uprobe`）拿权威签名与示例，比网上博客可靠。

## [100] Building BPF applications with libbpf-bootstrap

- **是什么**：Andrii Nakryiko（libbpf 维护者）2020-11 官方博客，讲 libbpf-bootstrap 脚手架，是从 bcc 转向现代 CO-RE 开发的标准入门。
- **核心内容**：两个示例 app——`minimal`（不用 CO-RE，旧内核可跑：SEC("tp/syscalls/sys_enter_write") + bpf_printk + BPF 全局变量 my_pid 过滤自身 PID）和 `bootstrap`（生产范式：vmlinux.h + BPF CO-RE + BPF ring buffer + 只读配置变量）。关键机制拆解：**BPF skeleton**（bpftool gen skeleton 生成，把 .bpf.o 嵌进头文件，open→load→attach 生命周期，bss/data/rodata 段允许用户态 mmap 直读直写全局变量零 syscall）；**Makefile 四步流水**（libbpf 静态库 → clang -g -O2 -target bpf 编 .bpf.o（-g 是为了 BTF，DWARF 随后 strip）→ bpftool gen skeleton → 链接出 ~200KB 自包含二进制，即 Brendan Gregg 期望的形态）；**const volatile 只读变量**（volatile 防 Clang 把变量整个优化掉，值在 verify 时已知→verifier 可剪枝死代码，须在 open 与 load 之间赋值）；**BTF-defined map**（struct + SEC(".maps") + __uint/__type 宏）；**BPF_CORE_READ(task, real_parent, tgid)** 链式读取内核结构体。
- **亮点/坑**：vmlinux.h 不能与系统内核头混用（类型重定义冲突）；RLIMIT_MEMLOCK 必须 bump；多数程序类型 libbpf 能凭 SEC() 自动 attach；bpf_printk/trace_pipe 只用于调试不用于生产。
- **对学习者**：现代 BPF 工程的第一篇必读，所有惯例（命名约定 <app>.bpf.c/<app>.c/<app>.h）都在这定调。
- **对 AI agent**：本地 web/md/100.md，可 grep `skel->rodata\|bpf_ringbuf_reserve\|preserve_access_index` 取标准写法；文末链接 Nakryiko 的 CO-RE/ringbuf/bcc-to-libbpf 三篇姊妹文（本知识库其他批次）。

## [101] How I ended up writing opensnoop in pure C using eBPF

- **是什么**：Michael Bolin（Facebook/EdenFS）2018-09 的学习长文：为了搞懂 eBPF 底层，剥掉 BCC 抽象层，用纯 C 重写 opensnoop（bolinfest/opensnoop-native）。是"把 BCC 拆开看内脏"的最佳一手材料。
- **核心内容**：五段式学习叙事——①动机：从 Brendan Gregg USE method / Linux Perf in 60s 入门性能工程；②用 Rust+LLVM 编译 eBPF（Geoffroy Couprie 路线），逐行注释 14 条指令的字节码（写栈 → r1/r2 传参 → call 6=bpf_trace_printk → r0=0 退出）；③裸调 bpf(2)：没有 libc 包装函数，必须 `syscall(__NR_bpf, BPF_PROG_LOAD, &attr, sizeof(attr))`；程序不是二进制而是 `struct bpf_insn` 数组（code + dst_reg:4/src_reg:4 位域 + off + imm，8 字节/条，小端）；**关键坑：BPF_PROG_TYPE_KPROBE 必须设 kern_version == LINUX_VERSION_CODE 否则 EINVAL**——man page 示例没写、靠读 kernel/bpf/syscall.c 源码才找到；attach kprobe 走 perf_event_open + PERF_EVENT_IOC_SET_BPF ioctl；④用 BCC 的 DEBUG_PREPROCESSOR/DEBUG_SOURCE 导出 BCC 改写后的 C（map 操作被重写为 bpf_map_update_elem 等 helper 调用 + bpf_pseudo_fd 内联 map fd）与反汇编，逆向出生成路径后手工内嵌进纯 C 程序；⑤结论：跨 abstraction 学习的方法论价值。
- **亮点**：整篇就是"如何用 gdb/内核源码/dmesg/log_buf 定位 EINVAL"的实战教程；BCC /virtual/include 虚拟头文件机制（exported_files.cc 内存映射）的揭秘。
- **对学习者**：想理解 libbpf 出现之前 BPF 加载全流程（raw syscall + bpf_attr + perf_event 关联）没有比这更好的文档；也适合学"啃一手源码"的 debugging 方法。
- **对 AI agent**：本地 web/md/101.md，grep `kern_version\|__NR_bpf\|bpf_insn\|DEBUG_PREPROCESSOR` 拿裸加载代码骨架；opensnoop 完整 C 代码在 bolinfest/opensnoop-native 仓。

## [103] Tracing a packet journey using Linux tracepoints, perf and eBPF

- **是什么**：Jean-Tiare Le Bigaut（yadutaf）2017-07 经典博文：构建"L2 版 mtr"——追踪一个网络包穿过 docker0/veth/netns 的完整路径，perf 探路 + bcc 落地。
- **核心内容**：①方法论：先 `perf trace --no-sysballs --event 'net:*' ping <ip>` 观察 skbaddr 在各 tracepoint 间的流转（同一 skb 地址 = 零拷贝移动；地址变化点 = reply 包生成），从 4 种目标（localhost/Docker 容器/USB tethering/WiFi）归纳出最小无重复的 4 个 tracepoint：**net_dev_queue、netif_receive_skb_entry、netif_rx、napi_gro_receive_entry**；②为什么用 tracepoint 而非 kprobe：内核内部 API 不稳定、网络内层函数大量 inline/static 不可探测（作者前一版用 kprobe 的失败复盘）；③bcc 实现：TRACEPOINT_PROBE(net, netif_rx) 宏、BPF_PERF_OUTPUT 事件、BPF_HASH(若按 skbaddr 聚合)、读 skb 字段拿 dev name、用 struct net 嵌套读 netns inode 做命名空间标签；④最终输出形如 `[netns] vethXXXX request/reply seq src -> dst`，是容器网络排障的利器。
- **亮点**："tracepoint 挑选要靠 perf 先人肉观察去重"这个工作流本身就是可复用的方法论；同 skbaddr 追踪 = 免费获得零拷贝证明。
- **对学习者**：容器/虚拟网络排障与"从内核视角看包"思维的最佳入门文；前置姊妹文（kprobe 转 syscall 事件）也值得读。
- **对 AI agent**：本地 web/md/103.md，grep `TRACEPOINT_PROBE\|net_dev_queue\|napi_gro_receive` 拿 bcc 挂网络 tracepoint 的模板与 4-point 选择依据。

## [108] All your tracing are belong to BPF

- **是什么**：Trail of Bits（Alessandro Gario，2021-11）长篇教程：不用 libbpf/bcc/任何外部库，用 LLVM C++ API 在运行时生成 BPF 字节码 + 裸 syscall 加载，配套代码仓 trailofbits/bpf_tutorials_code（00-empty/01-*/02-syscall_counter/03-*）。
- **核心内容**：①BPF 程序限制清单（单函数、无全局变量/字符串字面量、512 字节栈、5.3 起才允许向后跳转（verifier 须能证明终止）、4096 指令上限 BPF_MAXINSNS、循环须展开）；②事件源二分法：动态插桩（kprobes/kretprobes/uprobes/uretprobes，只有 pt_regs，需自己按 ABI 映射参数）vs 静态插桩（tracepoints/USDT，稳定接口；每个 syscall 有 sys_enter/sys_exit 两个 tracepoint）；③LLVM 路线：IRBuilder 造 IR → setTargetTriple("bpf-pc-linux") → ExecutionEngine JIT 成 bpf 字节码 → 从自定义 SectionMemoryManager 收回 section 字节 → BPF_PROG_LOAD（log buffer 只在失败后提供，否则可能超长导致加载失败）；④挂载全流程：读 /sys/kernel/debug/tracing/events/<tp>/id → perf_event_open(PERF_TYPE_TRACEPOINT) → PERF_EVENT_IOC_SET_BPF/ENABLE 两个 ioctl；⑤syscall 计数器（BPF_MAP_TYPE_PERCPU_ARRAY，**坑：per-CPU map 大小须按 /sys/devices/system/cpu/possible 而非 get_nprocs_conf**——VMware vcpu.hotadd 会虚报 128）；⑥syscall 耗时 profiling（enter/exit 双程序 + 时间戳 map + PERF_EVENT_ARRAY/PERF_COUNT_SW_BPF_OUTPUT 每 CPU 一个环形缓冲 mmap 读取）；⑦收尾章"Writing a BPF program to do ANYTHING"。
- **亮点**：是理解"BPF 程序如何从零被构造、加载、挂载"最完整的 C++ 一手实现（osquery 的 fuzzing 目标生成技术同源）；把 verifier 拒载的每条规则都提前讲清。
- **对学习者**：适合已读过 bcc/libbpf 教程、想看"无框架裸奔"底层机制的进阶者；安全研究员背景视角（Trail of Bits 客户是审计/加固场景）。

- **是什么**：Nurkholish Halim（2022-09，Medium，本地为 Wayback 快照）实战教程：用 bcc/Python 写一个"知道是哪个进程发的"的 DNS 监控器，动机是安全场景（判断主机是否正向攻击者域名外泄数据），明确否决 tcpdump/packetbeat/Osquery/Zeek 各替代方案的理由。
