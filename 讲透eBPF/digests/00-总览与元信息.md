## [3] an introduction to eBPF (what-is-ebpf)

- 是什么：ebpf.io/what-is-ebpf 官方权威入门长文，eBPF 概念框架的最佳单一来源。
- 核心机制链（全文骨架）：①eBPF=在内核等特权上下文运行沙箱程序的技术，不改内核源码/不加载内核模块；②程序事件驱动，挂在 syscall/函数出入口/tracepoint/网络事件等预定义 hook，不够用可自建 kprobe/uprobe 挂几乎任意位置；③开发路径=LLVM/clang 把伪 C 编译成字节码，经 bpf() syscall 加载；④加载后过两关——**Verification**（特权检查/不会崩溃/必定跑完如 bounded loop 有保证退出的出口/无未初始化访问/复杂度有限）与 **JIT**（字节码翻译为机器码，效率等同原生内核代码）；⑤**Maps** 提供 kernel↔userspace 共享状态（Hash/Array/LRU/RingBuffer/StackTrace/LPM，多有 per-CPU 变体）；⑥**Helper Calls** 是内核提供的稳定 API（eBPF 不能调任意内核函数，否则绑定内核版本）；⑦**Tail calls** 类似 execve 语义替换执行上下文、function calls 程序内组合。
- eBPF Safety 四层（本篇最有价值的一节）：Required Privileges（root/CAP_BPF）、Verifier（明确说"是安全工具不是安全审计工具"）、Hardening（程序内存只读，被篡改宁可内核崩溃/Spectre 缓解：访存掩码+投机路径验证+Retpolines/**constant blinding** 防 JIT spraying）、Abstracted Runtime Context（不能直接访问任意内核内存）。
- 亮点：GeoCities→JavaScript 类比解释"可编程性"革命（安全/持续交付/性能三要素在 JS 与 eBPF 一一对应）；BPF 名源（原 Berkeley Packet Filter，现 eBPF 已是独立术语，cBPF 指经典 BPF；蜜蜂 logo 名叫 eBee）；工具链清单一网打尽（bcc/bpftrace/eBPF Go lib/libbpf/aya 与 libbpf-rs(Rust)/hello-ebpf(Java)）。
- 对人类学习者价值：必读第一文；文末 Further Reading 是精选书单（Liz Rice《Learning eBPF》《What is eBPF?》、Brendan Gregg《BPF Performance Tools》《Systems Performance 2e》）+ 分主题演讲列表（Borkmann/Gregg/Starovoitov/Graf），可作 3-6 个月学习路线的骨架。
- 对 AI agent 用法：本地 /usr-data/data2/kylin/network/awesome-ebpf/web/md/3.md；答 eBPF 原理题的权威引文源，可 grep "verifier\|JIT\|constant blinding\|bounded loop\|tail call\|helper" 定位机制段落，grep "O'Reilly\|Addison-Wesley" 拿书单。

## [255] eBPF: Block Linux Fileless Payload "Malware" Execution with BPF LSM

- 是什么：Djalal Harouni（bpflock 作者）2022-02 技术博文，讲如何用 BPF LSM 检测并**阻断** Linux fileless 恶意载荷执行。
- 核心机制链：①攻击面——`memfd_create()` 创建匿名内存文件（RAM 驻留、不落盘、引用归零自动释放，语义等同 MAP_ANONYMOUS），恶意 loader 把 ELF 写进 memfd 后经 `/proc/self/fd/N` 直接 execve，绕过只读文件系统防护；文中复现了 pathtofile 的 Go loader（还能伪造 argv[0]，`ps` 只显示 "from_loader AAAA"）。②传统检测全被绕过：`/proc/pid/comm` 可被任意改、`/proc/pid/exe` 可用 `prctl(PR_SET_MM_EXE_FILE)` 指向别的二进制、`/proc/pid/maps` 有 TOCTOU 竞态（读完进程已 execv 换身）。③正确姿势=挂在 **binfmt 匹配后、进程执行 point of no return 前**的钩子——此时 ELF header 已可访问且不可伪造（控制权尚未移交），`mm_struct` 还挂在 `linux_binprm` 上。④落地=bpflock 项目的 `filelesslock.bpf.c`，挂 **LSM hook `bprm_creds_from_file`**，检查被执行文件是否链接在文件系统上，memfd: 前缀即 log + 返回 -EPERM 阻断；实测 loader 与 injector（Silvio Cesare 1998 ELF parasite 注入术）双双被拦，日志含 tgid/pid/ppid/uid/cgroupid/comm/pcomm 全上下文。
- 亮点：给了一条完整可复现命令（docker 跑 bpflock + BPFLOCK_FILELESSLOCK_PROFILE=restricted）；点出 SysmonForLinux/Tracee/Falco 只能"检测" memfd: 前缀而 BPF LSM 能"阻断"；bpflock 还有 kimglock（内核镜像锁）/bpfrestrict（限制 bpf() syscall 本身）/kmodlock（限制加载内核模块）等模块。
- 对人类学习者价值：BPF LSM 防御用法的最佳入门案例——把"检测类 eBPF"与"强制阻断类 eBPF"的分界讲清楚了；也是理解 fileless 攻击原理（memfd+argv 伪造+ELF 注入）的一手材料。
- 对 AI agent 用法：本地 /usr-data/data2/kylin/network/awesome-ebpf/web/md/255.md；可 grep "memfd\|bprm_creds_from_file\|PR_SET_MM\|filelesslock\|EPERM" 定位机制段落与日志样例，grep "docker run" 拿复现命令。

## [257] eBPF, I thought we were friends ! (DEF CON 29)

- 是什么：DEF CON 29 官方 speakers 页快照，目标锚点 #fournier 指向 Datadog 三人组（Guillaume Fournier / Sylvain Afchain / Sylvain Baubeau）的 45 分钟演讲（Demo, Tool 类，Virtual only）。
- 核心内容：**用 eBPF 实现全功能 rootkit**。论证起点：eBPF 自 Kernel 3.18 起从网络监控扩展到可监控/追踪任意内核活动，Cilium/Calico/Cloudflare/Netflix/Facebook 月抛复杂网络用例，Google 又贡献了 Kernel Runtime Security Instrumentation（用 eBPF 写 LSM 的门），大量公司在生产环境跑有 eBPF 权限的服务——于是追问"这类服务被攻陷后会糟到什么程度"。答案：rootkit 全家桶——多种混淆技术、带远程持久访问的 C2、数据窃取与外传、RASP（Runtime Application Self-Protection）逃逸、**两种原创容器逃逸技术**；结论是"rogue kernel modules 终于遇到了对手"（eBPF rootkit 可替代恶意内核模块且更隐蔽）。演讲同时给出检测与防护方法。
- 亮点：参考文献链是 eBPF 攻防的一手地图——NSA/FBI Drovorub 报告（rootkit 现实威胁）、bpf_probe_write_user helper（篡改用户态内存的关键原语）、DEF CON 27 Jeff Dileo "Evil eBPF In-Depth"（前作）、SSTIC 三连（process-level 网络安全监控/SSH 会话监控与保护，作者自己的前序工作，即后来 Tracee 的血统）。
- 坑：本文件是会议页快照，除目标条目外还混入 DEF CON 29 全部约百个演讲条目（TrustZone-M/RSA 弱密钥/Exchange RCE 等，与 eBPF 无关），grep 时注意限定。
- 对人类学习者价值：eBPF 攻击面研究的标志性演讲（与 BlackHat 版 id=256 同源）；防御者必读的"威胁建模=拿到 CAP_BPF 的攻击者能做什么"。
- 对 AI agent 用法：本地 /usr-data/data2/kylin/network/awesome-ebpf/web/md/257.md；可 grep "eBPF, I thought\|Fournier\|rootkit\|Drovorub\|bpf_probe_write_user\|breakout" 直达目标条目与参考文献；speaker index 在文件头部。
