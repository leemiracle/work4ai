## 2. Normal Mode: Dispatch and Combine

 In V2, `dispatch` and `combine` are unified. `dispatch` performs the all-to-all routing, while `combine` performs the reduction back to the original token order [README.md17-18](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/README.md?plain=1#L17-L18)

## 4. Resource Tuning and SM Allocation

 V2 introduces analytical formulas to replace the trial-and-error auto-tuning of V1 [README.md20](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/README.md?plain=1#L20-L20)

 
### Automatic SM Tuning

 The method `get_theoretical_num_sms` uses hardware-specific bandwidth models (RDMA GB/s, NVLink GB/s) to find the minimum number of SMs needed to saturate the bottleneck [deep_ep/buffers/elastic.py217-226](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/elastic.py#L217-L226)
