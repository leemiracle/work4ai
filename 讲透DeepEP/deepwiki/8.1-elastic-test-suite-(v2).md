# Elastic Test Suite (V2)

  This page documents the DeepEP V2 test suite located in `tests/elastic/`. These tests validate the correctness, performance, and functionality of the `ElasticBuffer` and its associated features, including expert parallelism (EP), remote memory access (Engram), pipeline parallelism (PP), and all-gather reduce-scatter (AGRS).

 
---

 
## Overview

 The Elastic Test Suite (V2) is designed for a distributed environment and uses the `NCCL Gin` backend. Unlike V1, which focused on manual tuning and NVSHMEM, the V2 suite leverages analytical resource allocation and JIT-compiled kernels. It includes stress tests for complex session lifecycles and performance profiling for low-latency primitives.

 **Key Test Scripts:**

 
 - `test_ep.py`: Core Expert Parallelism (dispatch/combine) correctness and benchmarking. [tests/elastic/test_ep.py59-150](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_ep.py#L59-L150)
 - `test_engram.py`: Remote KV cache fetch (Engram) correctness and latency. [tests/elastic/test_engram.py14-72](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_engram.py#L14-L72)
 - `test_pp.py`: Pipeline Parallelism send/recv stress testing, utilizing `generate_stress_ops` to simulate complex communication patterns. [tests/elastic/test_pp.py20-56](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_pp.py#L20-L56)
 - `test_agrs.py`: All-Gather and Reduce-Scatter session management and correctness. [tests/elastic/test_agrs.py89-140](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_agrs.py#L89-L140)
 - `test_barrier.py`: Distributed barrier latency profiling. [tests/elastic/test_barrier.py12-35](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_barrier.py#L12-L35)

## Expert Parallelism Tests (`test_ep.py`)

 `test_ep.py` is the primary test for the `ElasticBuffer.dispatch` and `ElasticBuffer.combine` APIs.

 
### Key Features Tested

 
 - **Correctness**: Compares kernel outputs against `ref_dispatch` and `ref_combine`. [tests/elastic/test_ep.py108-140](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_ep.py#L108-L140)
 - **FP8 Round-trip**: Validates the `use_fp8_dispatch` flag and per-token scaling using `per_token_cast_to_fp8` and `per_token_cast_back`. [tests/elastic/test_ep.py95-106](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_ep.py#L95-L106)
 - **EP Modes**: Uses `enumerate_ep_modes` to sweep through direct and hybrid (RDMA+NVLink) communication modes, varying alignment and bias counts. [tests/elastic/test_ep.py22-31](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_ep.py#L22-L31)
 - **Async Execution**: Validates `async_with_compute_stream` and `allocate_on_comm_stream` for overlapping. [tests/elastic/test_ep.py37-41](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_ep.py#L37-L41)
 - **Analytical Tuning**: Verifies `get_theoretical_num_sms` and `get_theoretical_num_qps` for automatic resource allocation. [tests/elastic/test_ep.py65-66](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_ep.py#L65-L66)
 - **Handle Caching**: Tests the ability to reuse `EPHandle` for subsequent combine operations to save metadata overhead. [tests/elastic/test_ep.py144-150](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_ep.py#L144-L150)

## Remote Memory Access Tests (`test_engram.py`)

 Engram provides remote memory access (RDMA) for features like KV cache fetching, minimizing SM overhead by using NCCL Gin.

 
 - **Correctness**: Each rank writes its local storage into the NCCL window via `engram_write`. Other ranks then fetch data using `engram_fetch`, which returns a hook that performs the wait and returns fetched data. [tests/elastic/test_engram.py39-53](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_engram.py#L39-L53)
 - **FP8 Support**: Tests fetching with replicated scaling factors (`sf`) and TMA-aligned column-major layouts. [tests/elastic/test_engram.py66-72](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_engram.py#L66-L72)
 - **Latency Profiling**: Uses `bench_kineto` to measure `engram_fetch_impl` (issue) and `engram_fetch_wait_impl` (wait) durations. [tests/elastic/test_engram.py84-96](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_engram.py#L84-L96)

## All-Gather Reduce-Scatter Tests (`test_agrs.py`)

 AGRS tests validate the experimental collective communication session management and batched operations.

 
 - **Stress Testing**: `generate_stress_ops` randomly selects between `ag` (all-gather), `fetch` (waiting for handles), and session lifecycle ops (`create_session`, `destroy_session`) to ensure robustness. [tests/elastic/test_agrs.py20-54](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_agrs.py#L20-L54)
 - **Batched Mode**: Tests `ElasticBuffer.all_gather` with multiple tensors simultaneously, returning a single handle for the batch when `is_batched=True`. [tests/elastic/test_agrs.py75-77](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_agrs.py#L75-L77)
 - **In-place Operations**: Validates `agrs_get_inplace_tensor` where tensors are copied into the buffer before communication to optimize memory usage. [tests/elastic/test_agrs.py62-65](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_agrs.py#L62-L65)
 - **Session Lifecycle**: Uses the `agrs_new_session` context manager to manage resources during communication. [tests/elastic/test_agrs.py170-174](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_agrs.py#L170-L174)

## Pipeline Parallelism and Barrier Tests

 
### Pipeline Parallelism (`test_pp.py`)

 
 - **Stress Operations**: `generate_stress_ops` creates a sequence of randomized send/recv tasks to simulate heavy pipeline bubbles. [tests/elastic/test_pp.py20-56](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_pp.py#L20-L56)
 - **Ring Topology**: Validates that data correctly flows between `prev_rank` and `next_rank` in the distributed group. [tests/elastic/test_pp.py88-120](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_pp.py#L88-L120)
 - **Config Management**: Uses `pp_set_config` to initialize buffer slots for pipeline stages. [tests/elastic/test_pp.py86](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_pp.py#L86-L86)
 
 
### Barrier Latency (`test_barrier.py`)

 
 - **Latency Profiling**: Executes `ElasticBuffer.barrier()` in a loop to measure the overhead of the NCCL Gin-based synchronization. [tests/elastic/test_barrier.py25-35](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_barrier.py#L25-L35)
 - **Implementation**: The barrier ensures all outstanding RDMA operations are complete across the group, typically involving `ncclGinQuiet` internally. [tests/elastic/test_barrier.py12-23](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/tests/elastic/test_barrier.py#L12-L23)
