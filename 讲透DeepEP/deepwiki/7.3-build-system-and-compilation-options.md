  This page documents the DeepEP V2 build system, centered around `setup.py`, and the compilation options available to developers. DeepEP uses a hybrid build approach: a primary Python-based build for the library and a Just-In-Time (JIT) compilation system for performance-critical kernels.

 
---

 
## Build System Architecture

 DeepEP V2 employs `setuptools` and PyTorch's `CUDAExtension` to compile the C++ and CUDA backend. The build process orchestrates dependency discovery, source file selection, and the generation of persistent environment configurations.

 
### Dependency Discovery

 The build system uses a utility module `find_pkgs` to locate required libraries without triggering a full package import [setup.py15-18](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/setup.py#L15-L18)

 
 - **NCCL**: Discovered via the `EP_NCCL_ROOT_DIR` environment variable or system paths using `find_pkgs.find_nccl_root()` [setup.py95](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/setup.py#L95-L95) The build system dynamically resolves the versioned `.so` filename (e.g., `libnccl.so.2`) to support pip wheels [setup.py46-123](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/setup.py#L46-L123)
 - **NVSHMEM**: Discovered via `find_pkgs.find_nvshmem_root()`, used for legacy V1 features [setup.py94](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/setup.py#L94-L94) Similar to NCCL, it resolves versioned host library names [setup.py42-116](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/setup.py#L42-L116)
 
 
### Source File Selection

 The build compiles a set of core C++ and CUDA files into a shared library.

 
 - **Python API**: `csrc/python_api.cpp` provides the `pybind11` bindings [setup.py100](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/setup.py#L100-L100)
 - **V2 Backend**: `csrc/kernels/backend/nccl.cu` and `csrc/kernels/backend/cuda_driver.cu` [setup.py121-127](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/setup.py#L121-L127)
 - **Legacy V1**: Files in `csrc/kernels/legacy/` (e.g., `layout.cu`, `intranode.cu`, `internode.cu`) and `csrc/kernels/backend/nvshmem.cu` are included for backward compatibility [setup.py100-112](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/setup.py#L100-L112)
 
 
### Persistent Environment Generation

 A unique feature of DeepEP is the `CustomBuildPy` class, which captures specific environment variables at build time and writes them into `deep_ep/envs.py` [setup.py70-90](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/setup.py#L70-L90) This ensures that settings like `EP_NCCL_ROOT_DIR` or `EP_NUM_TOPK_IDX_BITS` persist in the installed package even if the environment changes later. The variables tracked are defined in `persistent_env_names` [setup.py13](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/setup.py#L13-L13)

## Compilation Options and Flags

 DeepEP's behavior can be significantly altered through environment variables during the build process.

 
| Variable | Description | Impact |
|---|---|---|
| TORCH_CUDA_ARCH_LIST | Target GPU architecture. | Defaults to 9.0 (Hopper) or 8.0 (Ampere) if DISABLE_SM90_FEATURES is set setup.py132-142 |
| DISABLE_SM90_FEATURES | Disables Hopper-specific features (TMA, FP8). | Forces 8.0 architecture and adds -DDISABLE_SM90_FEATURES to compiler flags setup.py130-136 |
| DISABLE_NVSHMEM | Disables NVSHMEM-based kernels. | Note: NVSHMEM is currently treated as a required dependency in setup.py setup.py93-94 |
| DISABLE_AGGRESSIVE_PTX_INSTRS | Disables specialized PTX instructions (e.g., .L1::no_allocate). | Required for non-SM90 architectures; defaults to 1 for non-9.0 setup.py148-155 |
| EP_NUM_TOPK_IDX_BITS | Sets the bit-width for topk_idx (32 or 64). | Informs the topk_idx_t type definition in C++ setup.py163-165 |
| TOPK_IDX_BITS | Legacy alias for EP_NUM_TOPK_IDX_BITS. | Automatically mapped to the new variable if present setup.py158-160 |

## CMake Integration

 While `setup.py` is the primary entry point for Python installation, the codebase includes `CMakeLists.txt` for structured library definition, typically used for standalone C++ builds or debug paths.

 
### `add_deep_ep_library` Function

 This CMake function standardizes the creation of static libraries within the project [csrc/kernels/CMakeLists.txt1-12](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/CMakeLists.txt#L1-L12)

 
 - **Standards**: Enforces C++17 and CUDA 17 [csrc/kernels/CMakeLists.txt7-8](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/CMakeLists.txt#L7-L8)
 - **Separable Compilation**: Enables `CUDA_SEPARABLE_COMPILATION` to allow device-side function calls across translation units [csrc/kernels/CMakeLists.txt9](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/CMakeLists.txt#L9-L9)
 - **Linking**: Automatically links against `nvshmem_host`, `nvshmem_device`, `cudart`, `cudadevrt`, and `mlx5` [csrc/kernels/CMakeLists.txt11](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/CMakeLists.txt#L11-L11)
 
 
### Library Hierarchy

 The CMake system is organized hierarchically, with the root at `csrc/CMakeLists.txt` [csrc/CMakeLists.txt1](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/CMakeLists.txt#L1-L1) calling into `csrc/kernels/CMakeLists.txt` [csrc/kernels/CMakeLists.txt14-15](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/CMakeLists.txt#L14-L15) which then processes the `legacy` and `backend` subdirectories.

## Formatting and Linting

 DeepEP uses standardized formatting tools to maintain code quality, configured via `pyproject.toml`.

 
 - **Python Formatting**: Managed by `yapf` using the `pep8` style with a column limit of 140 [pyproject.toml1-4](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/pyproject.toml#L1-L4)
 - **Python Linting**: Managed by `ruff`, targeting common errors (Pyflakes), style violations (pycodestyle), and logic bugs (flake8-bugbear) [pyproject.toml6-20](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/pyproject.toml#L6-L20) Certain rules like module-level imports (`E402`) and star imports (`F403`) are ignored for specific use cases [pyproject.toml21-36](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/pyproject.toml#L21-L36)
 
 **Sources:** [pyproject.toml1-39](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/pyproject.toml#L1-L39)
