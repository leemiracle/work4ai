  This page explains the FP8 quantization and compression mechanisms in DeepEP V2 and V1. DeepEP provides high-performance, low-precision communication primitives to reduce bandwidth requirements in Mixture-of-Experts (MoE) dispatch and combine operations.

 
## Overview

 DeepEP V2 introduces a unified `ElasticBuffer` interface with native FP8 support, utilizing the Hopper (SM90) architecture's hardware acceleration. It also maintains legacy support for V1's specialized formats like UE8M0 and LogFMT.

 
| Feature | Version | Description | Key Code Entities |
|---|---|---|---|

| UE8M0 Scales | V1 | 8-bit unsigned exponent scale factors. | kUseUE8M0, internode_ll::dispatch |
| LogFMT | V1 | 10-bit logarithmic compression for combine. | kUseLogFMT, internode_ll::combine |

## FP8 Support in V2 (ElasticBuffer)

 In V2, FP8 support is integrated into the `ElasticBuffer` and `EPHandle` workflow. When `use_fp8_dispatch` is enabled, the dispatch kernels are configured to handle FP8 input tensors and their corresponding scale factors.

 
### Scale Factor Management (`sf_pack_t`)

 DeepEP uses per-token scaling to maintain precision during low-bitwidth communication. The scale factors are managed as `sf_pack_t` structures, which represent packed scale factors for quantized blocks.

### Key API Parameters

 
 - **`use_fp8_dispatch`**: A boolean flag in the `ElasticBuffer` constructor. If `True`, the communication kernels expect FP8-formatted tensors and handle the necessary metadata for quantized transfer. [deep_ep/buffers/elastic.py132](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/elastic.py#L132-L132)
 - **`kNumSFPacks`**: A template parameter used in dispatch kernels (e.g., `dispatch_copy_epilogue_impl`). It defines the number of scale factor packs processed per iteration to saturate memory bandwidth and ensure optimal SM utilization. [deep_ep/include/deep_ep/impls/dispatch_copy_epilogue.cuh15](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/include/deep_ep/impls/dispatch_copy_epilogue.cuh#L15-L15)
 - **`allow_multiple_reduction`**: A precision control flag in `ElasticBuffer`. If disabled, the system avoids intermediate reductions that could lead to precision loss in FP8/BF16, ensuring the most accurate results at the cost of potential communication overhead. [deep_ep/buffers/elastic.py107-109](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/elastic.py#L107-L109)

## Per-Token Cast Utilities

 DeepEP provides high-performance utilities in `deep_ep/utils/math.py` (referenced via `deep_ep/buffers/elastic.py`) for quantization management. These utilities allow users to prepare tensors before calling the communication primitives.

 
### `per_token_cast_to_fp8`

 This function converts a high-precision tensor (BF16 or FP32) to FP8 (E4M3) and extracts the required scale factors. It is a prerequisite for using the FP8 dispatch path in `ElasticBuffer`.

 
### `per_token_cast_back`

 This utility reverses the process, converting FP8 data back to BF16/FP32 using the provided scale factors. This is typically used on the receiving end after a `combine` operation if the expert outputs were returned in quantized form.

## Legacy Formats (V1 Reference)

 V1 (the legacy `Buffer` class) introduced specialized compression formats for low-latency RDMA communication, primarily used with the NVSHMEM/IBGDA backend.

 
### UE8M0 (Unsigned Exponent 8-bit)

 UE8M0 is a specialized 8-bit format for scale factors used in legacy dispatch to minimize metadata overhead.

 
 - **Kernel Integration**: Controlled via the `kUseUE8M0` template parameter in legacy dispatch kernels. [csrc/kernels/legacy/internode_ll.cu128](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode_ll.cu#L128-L128)
 - **Functionality**: It allows for 8-bit representation of scales, which is sufficient for many MoE workloads while saving bandwidth compared to higher-precision scales.
 
 
### LogFMT (Logarithmic Format)

 LogFMT is a compression scheme for the combine operation, where expert outputs often have a wide dynamic range that benefits from logarithmic quantization.

 
 - **Kernel**: Controlled by template flags in the `internode_ll::dispatch` and `internode_ll::combine` kernels. [csrc/kernels/legacy/internode_ll.cu128-155](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode_ll.cu#L128-L155)

## Implementation Primitives

 
### Vectorized Memory Access

 To achieve peak bandwidth during quantization and communication, DeepEP uses PTX-level vectorized instructions.

 
 - **`VecInt`**: A template trait in the legacy utilities that maps byte sizes to CUDA vector types (e.g., `int4` for 16 bytes). [csrc/kernels/legacy/utils.cuh33-54](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/utils.cuh#L33-L54)
 - **`UNROLLED_WARP_COPY`**: A macro that implements unrolled warp-level copies using custom load/store functions, essential for moving quantized data between global and shared memory. [csrc/kernels/legacy/utils.cuh6-29](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/utils.cuh#L6-L29)
 
 
### Hardware-Accelerated Quantization (SM90)

 In V2, the JIT kernels utilize SM90-specific features for FP8 conversion and data movement.

 
 - **`st.bulk` and `cp.async.bulk`**: These PTX instructions are used to move blocks of data (including FP8 tensors) efficiently through the memory hierarchy. [deep_ep/include/deep_ep/common/ptx.cuh93-139](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/include/deep_ep/common/ptx.cuh#L93-L139)
 - **`mbarrier`**: Used to synchronize asynchronous memory operations during the quantization and dispatch pipeline. The `mbarrier_wait_and_flip_phase` function is critical for ensuring data visibility after TMA (Tensor Memory Accelerator) loads. [deep_ep/include/deep_ep/common/ptx.cuh77-90](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/include/deep_ep/common/ptx.cuh#L77-L90)
 - **`dispatch_copy_epilogue_impl`**: This kernel handles the final placement of received tokens, supporting both expanded and non-expanded layouts while processing `sf_pack_t` scale factors. [deep_ep/include/deep_ep/impls/dispatch_copy_epilogue.cuh22-33](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/include/deep_ep/impls/dispatch_copy_epilogue.cuh#L22-L33)
