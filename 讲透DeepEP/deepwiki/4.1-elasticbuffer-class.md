## Purpose and Scope

 The `ElasticBuffer` class is the primary interface for expert-parallel (EP) communication in DeepEP V2 [deep_ep/buffers/elastic.py25-98](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/elastic.py#L25-L98) It unifies high-throughput and low-latency communication modes into a single abstraction, replacing the legacy V1 `Buffer` class [deep_ep/buffers/elastic.py97-98](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/elastic.py#L97-L98)

 Key features include:

 
 - **Unified Interface**: Single API for training, inference prefilling, and decoding [deep_ep/buffers/elastic.py92-93](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/elastic.py#L92-L93)
 - **Analytical Resource Allocation**: Automatic calculation of optimal SM and QP counts based on topology and workload [deep_ep/buffers/elastic.py110-111](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/elastic.py#L110-L111)
 - **NCCL Gin Backend**: Lightweight backend that reuses existing NCCL communicators and implements symmetric memory windows [csrc/elastic/buffer.hpp107-114](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/elastic/buffer.hpp#L107-L114)
 - **Flexible Topologies**: Supports both direct and hybrid (hierarchical RDMA + NVLink) modes for massive scale-out [deep_ep/buffers/elastic.py104-106](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/elastic.py#L104-L106)

## Analytical Resource Management

 DeepEP V2 eliminates manual tuning by analytically calculating hardware requirements based on the topology and available bandwidth (RDMA vs NVLink).

 
### Method: `get_theoretical_num_sms`

 Calculates the optimal number of SMs for a given MoE configuration to saturate hardware bandwidth while minimizing SM occupancy [deep_ep/buffers/elastic.py535-559](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/elastic.py#L535-L559) It uses the internal `prefer_overlap_with_compute` flag to choose between performance and resource efficiency [deep_ep/buffers/elastic.py554-555](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/elastic.py#L554-L555)

 
 - **Signature**: `get_theoretical_num_sms(self, num_experts: int, num_topk: int) -> int`
 
 
### Method: `get_theoretical_num_qps`

 Calculates the required number of RDMA Queue Pairs based on the number of scaleout ranks and SMs [deep_ep/buffers/elastic.py561-565](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/elastic.py#L561-L565)

 
 - **Signature**: `get_theoretical_num_qps(self) -> int`
