  DeepEP V2 transitions from the legacy NVSHMEM-based memory model to a unified memory architecture built on **NCCL Symmetric Memory**. This system manages a single contiguous GPU buffer (the `ElasticBuffer`) and uses NCCL's window-based primitives to enable zero-copy RDMA and NVLink access across the cluster.

### Key Components

 
 - **NCCL Window Allocation**: DeepEP uses `ncclCommWindowRegister` to create a symmetric memory window [csrc/kernels/backend/nccl.cu140](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L140-L140) This function is collective and internally performs a bootstrap barrier, ensuring all ranks are synchronized before the window is used. Local and peer pointers within the NVLink domain (LSA) are retrieved using `ncclGetLsaDevicePointer` [csrc/kernels/backend/nccl.cu141-147](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L141-L147)
 - **Symmetric Memory Backend**: Memory is allocated via the `deep_ep::symmetric` namespace. It supports two modes: 
 - `GPUSymmetricMemory`: Pure GPU allocation using `ncclMemAlloc` [csrc/kernels/backend/symmetric.hpp124-140](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/symmetric.hpp#L124-L140)
 - `ElasticSymmetricMemory`: A hybrid GPU+CPU allocation using the CUDA Driver VMM API. It reserves a contiguous Virtual Address (VA) range and maps segments to both GPU VRAM and CPU RAM (NUMA-local) [csrc/kernels/backend/symmetric.hpp145-174](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/symmetric.hpp#L145-L174)
 - **QP Allocation**: The number of RDMA Queue Pairs is controlled by `num_allocated_qps` and passed to the NCCL device communicator via `reqs.ginContextCount` [csrc/kernels/backend/nccl.cu92](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L92-L92) DeepEP configures `ginExclusiveContexts` to ensure high-performance RDMA operations [csrc/kernels/backend/nccl.cu93](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L93-L93)
 - **Service Level (sl_idx)**: Virtual lanes for RDMA traffic are managed via `sl_idx`, which maps to the NCCL `ginTrafficClass` [csrc/kernels/backend/nccl.cu95](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L95-L95) This allows traffic prioritization at the network layer.
 - **Domain Management**: The context calculates physical (RDMA vs NVLink) and logical (Scaleout vs Scaleup) domain sizes [csrc/kernels/backend/nccl.cu49-60](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L49-L60) If `allow_hybrid_mode` is disabled, the scaleup domain encompasses the entire world [csrc/kernels/backend/nccl.cu122-123](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L122-L123)

### Initialization Sequence

 The initialization of the symmetric memory involves a strict sequence to ensure all ranks have mapped the global address space:

 
 - **NCCL Comm Creation**: A host communicator is initialized via `ncclCommInitRank` [csrc/kernels/backend/nccl.cu28-41](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L28-L41)
 - **Symmetric Allocation**: `deep_ep::symmetric::alloc` is called to create the underlying memory object (GPU or Hybrid) [csrc/kernels/backend/nccl.cu129-133](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L129-L133)
 - **Window Registration**: `ncclCommWindowRegister` registers the contiguous VA range across the NCCL communicator [csrc/kernels/backend/nccl.cu140](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L140-L140)
 - **Device Comm Creation**: `ncclDevCommCreate` is called with specific `ncclDevCommRequirements_t`, including `ginQueueDepth` and `ginSignalCount` for RDMA barriers [csrc/kernels/backend/nccl.cu83-108](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L83-L108)
 - **LSA Pointer Mapping**: Peer pointers for the local NVLink domain are cached in `nvl_window_ptrs` for fast access [csrc/kernels/backend/nccl.cu145-147](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L145-L147)

## Resource Management and Tuning

 
### Timeout and Error Handling

 To prevent system-wide hangs, DeepEP relies on NCCL and CUDA driver timeout mechanisms. The context handles initialization and destruction phases with safety checks, such as verifying Gin support via `ncclCommQueryProperties` [csrc/kernels/backend/nccl.cu83-91](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L83-L91)

 
### Service Level (SL) Configuration

 The `sl_idx` (Service Level) is used to map traffic to specific InfiniBand virtual lanes.

 
 - **Configuration**: Set during `NCCLSymmetricMemoryContext` construction [csrc/kernels/backend/nccl.cu66](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L66-L66)
 - **Override**: Users can typically override RDMA SL settings via environment variables like `EP_OVERRIDE_RDMA_SL`.
 - **RDMA Barrier**: DeepEP utilizes a customized RDMA barrier that requires extra signals, configured via `reqs.ginSignalCount` [csrc/kernels/backend/nccl.cu97](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L97-L97)
 
 
### Fast RDMA Atomic Support

 DeepEP checks for atomic operation support during initialization. Specifically, it asserts that GPUDirect RDMA with CUDA VMM is supported on the device [csrc/kernels/backend/symmetric.hpp52-61](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/symmetric.hpp#L52-L61)

 
### Comparison: V1 vs V2 Memory Models

 
| Feature | Legacy (V1) | Elastic (V2) |
|---|---|---|
| Backend | NVSHMEM + Custom IPC | NCCL Symmetric Memory (Gin/LSA) |
| Buffer Type | Split (NVL / RDMA) | Unified (Contiguous VA Window) |
| Allocation | nvshmem_malloc | ncclMemAlloc / CUDA VMM |
| Registration | Automatic (NVSHMEM) | ncclCommWindowRegister |
| Hybrid Memory | Not Supported | Supported (GPU + CPU NUMA) |
| LSA Support | Manual IPC Handles | ncclGetLsaDevicePointer |
