## Purpose and Scope

 This page documents the NCCL-based backend integration in DeepEP V2, which replaces the legacy NVSHMEM-based transport for the primary communication path. It covers the C++ and CUDA implementation in `csrc/kernels/backend/nccl.cu`, the integration with the CUDA driver in `csrc/kernels/backend/cuda_driver.cu`, and the legacy path in `csrc/kernels/backend/nvshmem.cu`.

 Key components include the `NCCLSymmetricMemoryContext` for managing cross-node memory visibility, the `NCCLCommHandle` Python wrapper, and the analytical domain size helpers.

 
---

 
## NCCL Symmetric Memory Management

 The core of the V2 backend is the "Symmetric Memory" abstraction, which allows buffers on different GPUs to be accessed via global virtual addresses or RDMA-capable windows.

 
### NCCLSymmetricMemoryContext

 Defined in `csrc/kernels/backend/nccl.cu` and declared in `csrc/kernels/backend/api.cuh`, this class manages the lifecycle of NCCL communicators and memory registrations. It stores physical topology information (NVLink vs RDMA) and logical domain mapping.

 
| Function | Role |
|---|---|
| get_local_unique_id | Generates a ncclUniqueId on the local rank to be broadcast. csrc/kernels/backend/nccl.cu20-26 |
| create_nccl_comm | Initializes a new ncclComm_t from a unique ID. csrc/kernels/backend/nccl.cu28-41 |
| destroy_nccl_comm | Safely tears down the communicator via ncclCommAbort. csrc/kernels/backend/nccl.cu43-47 |
| NCCLSymmetricMemoryContext | Constructor that creates device communicators and registers symmetric memory windows. csrc/kernels/backend/nccl.cu62-148 |
| get_sym_ptr | Calculates the device pointer for a specific rank's symmetric memory window by offset. csrc/kernels/backend/nccl.cu150-153 |

## Domain Size and Topology

 DeepEP V2 distinguishes between **Physical** and **Logical** domains to support hierarchical topologies (NVLink + RDMA). Physical ranks are determined by `ncclTeamWorld` and `ncclTeamLsa`.

 
| Function | Description |
|---|---|
| get_physical_domain_size | Returns {num_rdma_nodes, num_nvl_ranks_per_node}. csrc/kernels/backend/nccl.cu49-54 |
| get_logical_domain_size | Returns {num_scaleout_ranks, num_scaleup_ranks} based on allow_hybrid_mode. csrc/kernels/backend/nccl.cu56-60 |

 If `allow_hybrid_mode` is false, the logical domain treats the entire cluster as a single scale-up group (num_scaleout = 1, num_scaleup = total_ranks). [csrc/kernels/backend/nccl.cu58-59](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L58-L59)

## Backend Drivers

 
### CUDA Driver Integration

 The file `csrc/kernels/backend/cuda_driver.cu` (interfaced via `api.cuh`) provides batched operations for synchronization primitives using the CUDA Driver API.

 Key functions:

 
 - `batched_write`: Sets values across multiple device pointers. [csrc/kernels/backend/api.cuh99](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/api.cuh#L99-L99)
 - `batched_wait`: Blocks a stream until multiple pointers reach a specific value. [csrc/kernels/backend/api.cuh101](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/api.cuh#L101-L101)
 - `batched_write_and_wait`: Atomic combined operation for signaling. [csrc/kernels/backend/api.cuh103](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/api.cuh#L103-L103)
 
 Sources: [csrc/kernels/backend/api.cuh97-105](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/api.cuh#L97-L105)

 
### Legacy NVSHMEM Backend

 The file `csrc/kernels/backend/nvshmem.cu` (interfaced via `api.cuh`) maintains compatibility for the V1 `Buffer` class. It wraps NVSHMEM for symmetric heap management.

 Key functions:

 
 - `nvshmem::init`: Initializes the NVSHMEM runtime. [csrc/kernels/backend/api.cuh18-21](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/api.cuh#L18-L21)
 - `nvshmem::alloc`: Allocates from the symmetric heap. [csrc/kernels/backend/api.cuh23](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/api.cuh#L23-L23)
 - `nvshmem::barrier`: Synchronizes the NVSHMEM team. [csrc/kernels/backend/api.cuh27](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/api.cuh#L27-L27)

## Implementation Details

 
### NCCL Gin Configuration

 During initialization, the context queries `ncclCommQueryProperties` to ensure Gin support is available for the requested mode (Railed vs Full). It configures `ncclDevCommRequirements_t` with:

 
 - `ginContextCount`: Set to `num_allocated_qps`. [csrc/kernels/backend/nccl.cu92](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L92-L92)
 - `ginQueueDepth`: Set to `kGinQPDepth`. [csrc/kernels/backend/nccl.cu94](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L94-L94)
 - `ginTrafficClass`: Mapped to the InfiniBand Service Level (`sl_idx`). [csrc/kernels/backend/nccl.cu95](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L95-L95)
 - `ginSignalCount`: Set to `num_ranks + 2 * 2` for customized RDMA barrier. [csrc/kernels/backend/nccl.cu97](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L97-L97)
 - `ginConnectionType`: Configured as `RAIL` or `FULL` based on `allow_hybrid_mode`. [csrc/kernels/backend/nccl.cu98](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L98-L98)
 
 
### Device Communicator Lifecycle

 The device-side communicator `dev_comm` is created via `ncclDevCommCreate` [csrc/kernels/backend/nccl.cu108](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L108-L108) It supports different NCCL versions, using `devCommRuntimeVersionSize` for NCCL 2.31+ [csrc/kernels/backend/nccl.cu100-103](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L100-L103) It is destroyed via `ncclDevCommDestroy` during the `finalize()` call [csrc/kernels/backend/nccl.cu158](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/backend/nccl.cu#L158-L158)
