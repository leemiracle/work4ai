## Purpose and Scope

 This page documents the `deep_ep::elastic::ElasticBuffer` C++ class defined in `csrc/elastic/buffer.hpp` and registered via `csrc/python_api.cpp`. It serves as the primary C++ engine for DeepEP V2, managing communication state, memory windows, and JIT kernel orchestration for Expert Parallelism (EP), Pipeline Parallelism (PP), and Engram (remote KV cache) operations.

 Unlike the V1 `Buffer` class which relied on NVSHMEM, `ElasticBuffer` utilizes the **NCCL Gin** backend for high-performance communication across both NVLink and RDMA domains.

 
---

 
## Class Overview

 `deep_ep::elastic::ElasticBuffer` is the central C++ object for V2 communication. It manages a contiguous symmetric memory region across all ranks and handles the mapping between logical/physical domains.

## Public Methods and JIT Kernel Mappings

 Each Python-facing method in `ElasticBuffer` maps to a JIT-compiled CUDA kernel. The JIT system allows DeepEP to specialize kernels based on runtime parameters like `kNumSMs`, `kNumExperts`, and `kNumQPs`.

 
### EP Dispatch and Combine

 These methods implement the core MoE routing.

 
| C++ Method | JIT Kernel Implementation | Purpose |
|---|---|---|
| dispatch | dispatch_impl / hybrid_dispatch_impl | Routes tokens to experts across ranks |
| combine | combine_impl / hybrid_combine_impl | Collects expert outputs back to source tokens |

## Memory Layout and Workspace

 The buffer manages a single large allocation of `num_buffer_bytes`. This space is partitioned into:

 
 - **Workspace**: Located at the start of the GPU segment, used for metadata exchange and RDMA notifications. Managed by `layout::WorkspaceLayout` [csrc/elastic/buffer.hpp126-130](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/elastic/buffer.hpp#L126-L130)
 - **GPU Buffer**: User data space for EP and Engram operations [csrc/elastic/buffer.hpp101](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/elastic/buffer.hpp#L101-L101)
 - **CPU Buffer**: Optional tail portion of the symmetric memory located in host memory [csrc/elastic/buffer.hpp108-110](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/elastic/buffer.hpp#L108-L110)
 
 The `nccl::NCCLSymmetricMemoryContext` handles the actual window registration and QP allocation [csrc/elastic/buffer.hpp111-114](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/elastic/buffer.hpp#L111-L114)
