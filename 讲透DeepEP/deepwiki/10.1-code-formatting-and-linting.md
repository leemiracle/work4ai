  Relevant source files

  DeepEP maintains a high standard of code quality and consistency through automated formatting and linting tools. The repository provides a unified entry point, `format.sh`, which orchestrates Python formatting, Python linting, and C++/CUDA formatting.

 
## Toolchain Overview

 The development environment relies on three primary tools, with versions pinned in `requirements-lint.txt` to ensure consistency across different development environments and CI runners.

 
| Tool | Purpose | Version |
|---|---|---|
| yapf | Python Code Formatting | 0.40.2 |
| ruff | Python Linting and Static Analysis | 0.6.5 |
| clang-format | C/C++/CUDA Formatting | 15.0.7 |

 
### Tool Version Pinning

 The `format.sh` script includes a `tool_version_check` function that compares the installed version of a tool against the requirements [format.sh120-125](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L120-L125) If a mismatch is detected, it automatically attempts to reinstall the correct versions using `pip install -r requirements-lint.txt` [format.sh123](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L123-L123) Initial checks for `yapf` and `ruff` existence also trigger a dependency install if they are missing [format.sh17-20](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L17-L20)

## Formatting Workflow

 The `format.sh` script is designed to be efficient by supporting both incremental formatting (for local development) and full-repository formatting (for CI or major refactors).

 
### Incremental Formatting

 By default, the script identifies changed files by calculating the `git merge-base` between the current `HEAD` and the `main` (or `origin/main`) branch [format.sh54-60](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L54-L60) It uses `git diff --diff-filter=ACM` to target only files that were Added, Copied, or Modified, preventing errors on deleted files [format.sh62-65](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L62-L65)

 
### Full Formatting

 Passing the `--all` flag bypasses the git diff logic and applies formatting/linting to the entire codebase [format.sh70-71](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L70-L71) For Python, this calls `format_all` which excludes the `build/` directory [format.sh32-34](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L32-L34) For C++, it calls `clang_format_all` which similarly ignores `./build/*` [format.sh136-148](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L136-L148)

 
### Git Diff Exit-Code Check

 At the end of the execution, the script performs a final `git diff --quiet` check [format.sh181](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L181-L181) If the formatting tools introduced any changes, the script prints the diff and exits with code `1` [format.sh181-192](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L181-L192) This mechanism is critical for CI pipelines to detect and reject unformatted code.

## Python Formatting and Linting

 
### yapf (Formatting)

 Python files (`.py`, `.pyi`) are formatted using `yapf` with the `--recursive` and `--parallel` flags [format.sh27-30](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L27-L30) Parallel execution uses `xargs -P 5` to speed up processing of multiple files [format.sh63](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L63-L63)

 
### ruff (Linting)

 Linting is handled by `ruff`, which checks for logical errors and style violations [format.sh81](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L81-L81) The `lint_changed` function includes a guard to ensure the file list is not empty, preventing `ruff` from hanging on `STDIN` [format.sh86-105](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L86-L105)

## C++/CUDA Formatting

 DeepEP uses `clang-format` for all C++ and CUDA source files (`.c`, `.cc`, `.cpp`, `.h`, `.hpp`, `.cu`, `.cuh`) [format.sh138-141](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L138-L141)

 
### Configuration Settings

 The repository defines strict style rules in `.clang-format` based on the Google C++ Style Guide [.clang-format1](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/.clang-format#L1-L1)

 
| Setting | Value | Description |
|---|---|---|
| BasedOnStyle | Google | Inherits Google C++ style defaults .clang-format1 |
| IndentWidth | 4 | Standard indentation size .clang-format3 |
| ColumnLimit | 140 | Maximum line width .clang-format4 |
| PointerAlignment | Left | Pointers align to the type (e.g., float* ptr) .clang-format9 |
| UseTab | Never | Forces spaces over tabs .clang-format2 |
| AccessModifierOffset | -4 | Aligns public:/private: with class keyword .clang-format5 |

 
### Pragma-Unroll Masking Workaround

 `clang-format` often struggles with CUDA-specific `#pragma unroll` directives, sometimes breaking their alignment or syntax. To prevent this, `format.sh` implements a masking workaround using `perl`:

 
 - **Mask**: Replaces `#pragma unroll` with `// #pragma unroll` (commenting it out) [format.sh140](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L140-L140)
 - **Format**: Runs `clang-format -i` on the file [format.sh143](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L143-L143)
 - **Unmask**: Replaces `// #pragma unroll` back with `#pragma unroll` [format.sh147](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L147-L147)
 
 This logic is applied both in `clang_format_all` [format.sh136-148](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L136-L148) and `clang_format_changed` [format.sh151-165](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L151-L165)
