## Purpose and Scope

 The Legacy Test Suite documents the validation procedures for DeepEP V1, which relies on the **NVSHMEM** backend for internode communication and specialized **IBGDA** (InfiniBand GPU Direct Async) primitives. While the library has shifted to the `ElasticBuffer` (V2) architecture using the NCCL Gin backend, the V1 tests remain critical for maintaining the `deep_ep.buffers.legacy.Buffer` interface and verifying performance on older configurations.

 **Scope**: This page covers the following test modules located in `tests/legacy/` and `tests/utils/`:

 
 - `test_intranode.py`: Validates single-node NVLink dispatch and combine correctness, including TMA (Tensor Memory Accelerator) support on SM90.
 - `test_internode.py`: Validates multi-node RDMA-based communication using NVSHMEM and `get_dispatch_layout`.
 - `test_low_latency.py`: Validates pure-RDMA low-latency kernels with specialized FP8 formats (UE8M0, LogFMT) and the `enable_shrink` mask buffer.
 - `tests/utils/test_gate.py`: Validates MoE routing utility functions used to generate top-k indices.

## Intranode Testing (`test_intranode.py`)

 The intranode test suite focuses on **NVLink-only** communication within a single physical node. It verifies the correctness of the legacy `Buffer.dispatch` and `Buffer.combine` methods when operating in a scale-up domain.

 
### Key Features Tested

 
 - **NVLink Dispatch/Combine**: Validates data integrity across NVLink peer-to-peer transfers.
 - **FP8 Support**: Tests E4M3 quantization and scaling factor (SF) handling for intranode transfers.
 - **Config Tuning**: Explores the `Config` space (number of SMs, chunk sizes) to find optimal performance points.
 - **Async Event Handling**: Verifies that `async_finish=True` correctly returns an `EventHandle` for stream synchronization.
 - **Benchmarking**: Uses `bench_kineto` to profile kernel execution time and calculate NVLink bandwidth.
 
 
### Implementation Detail: Config Object

 The legacy V1 API requires manual tuning via a `Config` object [deep_ep/buffers/legacy.py9](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/legacy.py#L9-L9) which is passed to the dispatch/combine methods. The test suite iterates through various `num_sms` and `nvl_chunk_size` values to populate this object.

## Internode Testing (`test_internode.py`)

 The internode test suite validates multi-node communication features using **NVSHMEM**. It verifies that RDMA-based communication across physical nodes functions correctly, coordinating token routing between nodes.

 
### Test Architecture

 The suite uses `torch.multiprocessing.spawn` to launch processes across multiple nodes. It requires a strict initialization sequence:

 
 - **Distributed Init**: `init_dist()` sets up the PyTorch process group.
 - **Buffer Allocation**: `deep_ep.Buffer()` initializes symmetric memory and NVSHMEM [deep_ep/buffers/legacy.py105-136](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/legacy.py#L105-L136)
 - **Layout Calculation**: `get_dispatch_layout()` is called to compute the routing metadata before dispatch [deep_ep/buffers/legacy.py173-190](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/legacy.py#L173-L190)
 
 
### Feature Coverage

 
| Feature | Validation Method |
|---|---|
| Layout Calculation | Compares GPU get_dispatch_layout against a CPU reference implementation. |
| FP8/BF16 Hybrid | Tests dispatching in FP8 and combining in BF16 (common MoE pattern). |
| Async Chaining | Uses previous_event to chain multiple communication operations. |
| RDMA Tuning | Optimizes rdma_chunk_size for InfiniBand throughput. |

## Low-Latency Testing (`test_low_latency.py`)

 The low-latency suite validates the **Pure-RDMA** path designed for minimal overhead in inference scenarios. This mode bypasses the hierarchical (NVLink+RDMA) approach in favor of direct node-to-node transfers using `internode_ll.cu`.

 
### Specialized Formats and Primitives

 
 - **FP8 / UE8M0 / LogFMT**: Validates specialized low-precision formats [csrc/kernels/legacy/internode_ll.cu128-135](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode_ll.cu#L128-L135) used to saturate RDMA bandwidth.
 - **Async Finish**: Heavily tests `async_finish` to allow the CPU to overlap computation while kernels run.
 - **Return Recv Hook**: Validates the V1 pattern where communication returns a hook that must be called to finalize the receive [deep_ep/buffers/legacy.py314-325](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/legacy.py#L314-L325)
 - **Zero-Copy Combine**: Tests the ability to combine directly into the output buffer without intermediate copies.
 - **Enable Shrink**: Validates the mask buffer feature which allows the communication domain to be dynamically "shrunk" based on active tokens [csrc/kernels/legacy/internode_ll.cu10-19](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode_ll.cu#L10-L19)

## V1 Performance Tuning Methodology

 In the legacy suite, performance is measured using `bench_kineto` and reported as logical bandwidth.

 
### Metrics Calculation

 
 - **RDMA Bandwidth**: Logical throughput based on `num_rdma_bytes` and kernel duration.
 - **NVLink Bandwidth**: Logical throughput based on `num_nvl_bytes` and kernel duration.
 - **FP8 Scaling**: For FP8 tests, the byte calculation accounts for the scale factor overhead stored in the `packed_recv_x_scales` buffer [csrc/kernels/legacy/internode_ll.cu130](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode_ll.cu#L130-L130)
 
 
### Tuning Parameters

 The tests perform a grid search over:

 
 - `nvl_chunk_size`: Typically tuned for NVLink P2P efficiency.
 - `rdma_chunk_size`: Typically tuned for IBGDA/RDMA throughput.
 - `num_sms`: Controlled via `Buffer.set_num_sms` [deep_ep/buffers/legacy.py154-162](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/legacy.py#L154-L162)
 - **Memory Fencing**: Testing different memory ordering primitives like `memory_fence_sys` vs `memory_fence_gpu` for correctness [csrc/kernels/legacy/utils.cuh69-79](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/utils.cuh#L69-L79)
