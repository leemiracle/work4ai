  DeepEP utilizes GitHub Actions to maintain code quality and style consistency across the repository. The Continuous Integration (CI) pipeline is designed to automatically validate that all contributions adhere to the project's formatting standards before they are merged into the `main` branch.

 
## CI Workflow Overview

 The CI process is defined in [.github/workflows/format.yml1-28](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/.github/workflows/format.yml#L1-L28) It executes a single primary job, `format-check`, which ensures that Python, C++, and CUDA source files are correctly formatted and linted.

 
### Workflow Triggers

 The workflow is triggered by the following events:

 
 - **Push**: Any direct push to the `main` branch [.github/workflows/format.yml4-5](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/.github/workflows/format.yml#L4-L5)
 - **Pull Request**: Any pull request targeting the `main` branch [.github/workflows/format.yml6-7](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/.github/workflows/format.yml#L6-L7)
 
 
### Runner Environment

 The job runs on an `ubuntu-latest` runner [.github/workflows/format.yml11](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/.github/workflows/format.yml#L11-L11) It requires a full git history to calculate the merge base for incremental formatting, which is achieved by setting `fetch-depth: 0` during the checkout step [.github/workflows/format.yml17](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/.github/workflows/format.yml#L17-L17)

 
## Implementation Details

 The CI pipeline acts as a wrapper around the `format.sh` script. The script performs three main tasks: Python formatting, Python linting, and C++/CUDA formatting.

### Incremental vs. Full Checks

 The CI job runs `bash ./format.sh` without arguments [.github/workflows/format.yml26](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/.github/workflows/format.yml#L26-L26) In this mode, the script performs **incremental formatting**:

 
 - It determines the `BASE_BRANCH` (usually `origin/main`) [format.sh54-58](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L54-L58)
 - It calculates the `MERGEBASE` between the current `HEAD` and the base branch [format.sh60](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L60-L60)
 - It identifies files that have been Added, Copied, or Modified (`--diff-filter=ACM`) since the merge base [format.sh62-63](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L62-L63)
 - Only these changed files are passed to the formatting tools.
 
 If the `--all` flag were passed, the script would instead format every file in the repository [format.sh70-75](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L70-L75)

 
## Toolchain and Requirements

 The CI environment installs dependencies specified in `requirements-lint.txt` if they are not already present in the runner [format.sh18-20](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L18-L20)

 
| Tool | Purpose | Files Targeted |
|---|---|---|
| yapf | Code Formatting | .py, .pyi |
| ruff | Linting / Static Analysis | .py, .pyi |
| clang-format | Code Formatting | .c, .cc, .cpp, .h, .hpp, .cu, .cuh |

 
### The Pragma Unroll Workaround

 A specific technical constraint exists for CUDA files: `clang-format` often handles `#pragma unroll` poorly. The `format.sh` script implements a workaround:

 
 - It replaces `#pragma unroll` with `//#pragma unroll` before formatting [format.sh161](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L161-L161)
 - It runs `clang-format` [format.sh162](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L162-L162)
 - It restores the original `#pragma unroll` syntax after formatting [format.sh163](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L163-L163)
 
 Sources: [format.sh129-176](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L129-L176)

 
## Gating and Pull Request Merges

 The CI job serves as a gatekeeper for the repository. The exit code of `format.sh` determines the success or failure of the GitHub Action.

 If any tool modifies a file (meaning the contributor did not format it locally), `git diff --quiet` will return a non-zero exit code [format.sh181-192](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/format.sh#L181-L192) This causes the GitHub Action to fail, which in turn prevents the Pull Request from being merged until the contributor applies the suggested formatting changes.
