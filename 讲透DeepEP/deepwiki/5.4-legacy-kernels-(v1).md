# Legacy Kernels (V1)

  Relevant source files 
 - [csrc/kernels/legacy/internode_ll.cu](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode_ll.cu)

## Purpose and Scope

 This page documents the V1 legacy kernel implementations in DeepEP, located in `csrc/kernels/legacy/`. These kernels represent the original communication architecture of DeepEP, which relies heavily on **NVSHMEM** for internode RDMA and **NVLink** for intranode data movement.

 While DeepEP V2 (the current standard) has transitioned to a NCCL-based Gin backend for better elasticity and integration, the V1 kernels are preserved for compatibility with the legacy `Buffer` class [deep_ep/buffers/legacy.py14-29](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/deep_ep/buffers/legacy.py#L14-L29) This architecture includes:

 
 - **Internode Kernels**: Multi-node token dispatch/combine using a three-phase pipeline (notify, dispatch, combine) [csrc/kernels/legacy/internode.cu346-434](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode.cu#L346-L434)
 - **Low-Latency Kernels**: Pure-RDMA implementations optimized for small payloads and specific data formats like FP8/UE8M0 and LogFMT [csrc/kernels/legacy/internode_ll.cu128-155](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode_ll.cu#L128-L155)
 - **Intranode Kernels**: High-bandwidth NVLink-only kernels utilizing TMA (Tensor Memory Accelerator) on SM90 hardware [csrc/kernels/legacy/intranode.cu1-20](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/intranode.cu#L1-L20)
 - **Layout Logic**: Analytical calculation of token placement for dispatch operations [csrc/kernels/legacy/layout.cu17-80](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/layout.cu#L17-L80)

## Core Infrastructure and Utilities

 The legacy kernels share a set of device-side utilities that abstract hardware primitives and memory layouts.

 
### Buffer Abstractions (`buffer.cuh`)

 Legacy kernels use three primary buffer types to manage distributed memory:

 
 - **`SymBuffer<T>`**: Manages NVSHMEM-visible symmetric buffers. It provides `send_buffer(rank)` and `recv_buffer(rank)` views to simplify RDMA write logic [csrc/kernels/legacy/buffer.cuh43-100](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/buffer.cuh#L43-L100)
 - **`AsymBuffer<T>`**: Used for NVLink peer-to-peer memory. It is typically partitioned by NVL rank and channel [csrc/kernels/legacy/buffer.cuh103-131](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/buffer.cuh#L103-L131)
 - **`Buffer<T>`**: A simple linear buffer wrapper for local memory [csrc/kernels/legacy/buffer.cuh10-40](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/buffer.cuh#L10-L40)
 
 
### IBGDA Device Layer (`ibgda_device.cuh`)

 For internode RDMA, V1 kernels use the IBGDA (InfiniBand GPU Direct Async) transport. Key primitives include:

 
 - `nvshmemi_ibgda_put_nbi_warp`: Warp-level non-blocking RDMA put [csrc/kernels/legacy/ibgda_device.cuh14-25](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/ibgda_device.cuh#L14-L25)
 - `nvshmemi_ibgda_quiet`: Ensures all prior RDMA operations to a specific rank are complete [csrc/kernels/legacy/ibgda_device.cuh40-45](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/ibgda_device.cuh#L40-L45)
 
 
### Launch and Config (`launch.cuh`)

 
 - **`SETUP_LAUNCH_CONFIG`**: A macro that calculates grid dimensions and shared memory requirements based on the number of RDMA ranks and channels [csrc/kernels/legacy/launch.cuh20-40](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/launch.cuh#L20-L40)
 - **`SWITCH_RDMA_RANKS`**: A compile-time dispatch macro that instantiates kernels for specific RDMA rank counts (e.g., 2, 4, 8, 16) to allow for loop unrolling [csrc/kernels/legacy/launch.cuh67-90](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/launch.cuh#L67-L90)

## Internode Communication (`internode.cu`)

 The internode implementation uses a **Warp Role Model** to interleave RDMA (internode) and NVLink (intranode) data movement within the same kernel.

 
### The Three-Phase Pipeline

 
 - **`notify_dispatch`**: Synchronizes all ranks and exchanges token counts (`num_tokens_per_expert`) via RDMA. It builds prefix-sum arrays used for slot allocation [csrc/kernels/legacy/internode.cu346-434](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode.cu#L346-L434)
 - **`dispatch`**: Moves token data from source ranks to the ranks hosting the target experts.
 - **`combine`**: Reverses the dispatch path to collect expert outputs back to the original source ranks.
 
 
### Warp Roles in `dispatch`

 The `dispatch` kernel assigns specialized roles to warps within a CTA to maximize hardware utilization:

 
| Role | SM Type | Responsibility |
|---|---|---|
| kRDMASender | Sender SM | Reads local tokens and issues RDMA writes to remote nodes csrc/kernels/legacy/internode.cu582-700 |
| kRDMAAndNVLForwarder | Forwarder SM | Receives RDMA tokens and forwards them to NVL peers within the node csrc/kernels/legacy/internode.cu482-511 |
| kNVLReceivers | Sender SM | Reads from NVL peer buffers and writes final tokens to local memory csrc/kernels/legacy/internode.cu482-511 |

## Low-Latency Kernels (`internode_ll.cu`)

 The low-latency path is designed for pure-RDMA communication, bypassing the hierarchical NVLink forwarding when possible. It supports specialized data formats for MoE:

 
 - **FP8 / UE8M0**: Support for 8-bit floating point formats to reduce bandwidth [csrc/kernels/legacy/internode_ll.cu128-155](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode_ll.cu#L128-L155)
 - **LogFMT**: A custom logarithmic format for further compression [csrc/kernels/legacy/internode_ll.cu128-155](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode_ll.cu#L128-L155)
 
 These kernels utilize `nvshmemi_ibgda_rma_p` for single-element writes and `nvshmemi_ibgda_quiet` to ensure completion [csrc/kernels/legacy/internode_ll.cu31-50](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode_ll.cu#L31-L50) A custom `barrier` implementation handles synchronization across ranks using a `sync_buffer_ptr` and `mask_buffer_ptr` for rank-level fault tolerance (shrink mode) [csrc/kernels/legacy/internode_ll.cu22-69](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/internode_ll.cu#L22-L69)

## Intranode Kernels (`intranode.cu`)

 For communication within a single NVLink domain, `intranode.cu` provides optimized kernels that leverage SM90 (H100/H800) features.

 
### TMA (Tensor Memory Accelerator)

 On SM90 hardware, the intranode kernels use TMA for asynchronous data movement between global memory and shared memory [csrc/kernels/legacy/intranode.cu1-20](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/intranode.cu#L1-L20)

 
 - `tma_load_1d`: Asynchronously loads token chunks into SMEM [csrc/kernels/legacy/utils.cuh400-420](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/utils.cuh#L400-L420)
 - `mbarrier_wait`: Coordinates warp execution with TMA completion [csrc/kernels/legacy/utils.cuh430-450](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/utils.cuh#L430-L450)
 
 
### Layout Calculation (`layout.cu`)

 Before dispatching, the `get_dispatch_layout` function calculates the exact destination offsets for every token. This logic is implemented as a legacy kernel here [csrc/kernels/legacy/layout.cu17-80](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/layout.cu#L17-L80)

## Shared Utilities (`utils.cuh`)

 The `utils.cuh` header provides low-level PTX wrappers and memory primitives:

 
 - **Unrolled Copy**: `UNROLLED_WARP_COPY` macro for high-performance vector memory operations [csrc/kernels/legacy/utils.cuh6-29](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/utils.cuh#L6-L29)
 - **Memory Fences**: System, GPU, and CTA-level memory consistency primitives [csrc/kernels/legacy/utils.cuh69-79](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/utils.cuh#L69-L79)
 - **Acquire/Release Semantics**: `ld_acquire_sys_global` and `st_release_sys_global` for fine-grained synchronization over RDMA [csrc/kernels/legacy/utils.cuh81-103](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/utils.cuh#L81-L103)
 - **Vector Types**: `VecInt` template for mapping byte sizes to CUDA types (int8_t to int4) [csrc/kernels/legacy/utils.cuh33-54](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/kernels/legacy/utils.cuh#L33-L54)
