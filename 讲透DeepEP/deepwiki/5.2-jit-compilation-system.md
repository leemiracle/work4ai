  The DeepEP JIT (Just-In-Time) compilation system is a core component of the V2 architecture that enables high-performance communication kernels by specializing them at runtime. Instead of providing a massive library of pre-compiled kernels for every possible combination of expert counts, SM counts, and data types, DeepEP uses header-only implementations in `deep_ep/include/deep_ep/impls/` and compiles them on-demand using NVRTC (NVIDIA Runtime Compilation).

 
### Overview of the JIT Subsystem

 The JIT system bridges the gap between flexible Python-level configurations and highly optimized CUDA kernels. It manages kernel templating, compilation caching, and hardware-specific optimizations.

 **Key Components:**

 
 - **`Compiler`**: The primary engine interface that interacts with NVRTC to transform C++/CUDA source into PTX or SASS.
 - **`KernelRuntime`**: Manages the lifecycle of a specific compiled kernel, including its binary representation and launch parameters.
 - **`LaunchRuntime`**: A template-based base class (e.g., `DispatchRuntime`, `BarrierRuntime`) that handles kernel-specific string generation and launch logic.
 - **`IncludeParser`**: Resolves dependencies and recursively bundles header files into a single compilation unit.
 - **`DeviceRuntime`**: Provides the device-side environment and utilities required for JIT-compiled kernels.
 - **`cache.hpp`**: Implements the disk-based cache that uses SHA-256 hashes of the source and template parameters to avoid redundant compilations.
 - **`handle.hpp`**: Defines the unified abstraction for CUDA Driver and Runtime API handles.

### The `Compiler` Class and Environment Variables

 The `jit::Compiler` class handles the heavy lifting of NVRTC management. It is configured via several environment variables that control debugging, performance, and caching behavior. Persistent environment variables are captured during the build process and stored in `deep_ep/envs.py` to ensure consistency.

 
| Environment Variable | Description |
|---|---|
| EP_JIT_CACHE_DIR | Directory for storing compiled .cubin files. Defaults to ~/.cache/deep_ep. |
| EP_JIT_DEBUG | If set to 1, enables debug symbols and disables aggressive optimizations. |
| EP_JIT_WITH_LINEINFO | Adds line information to the compiled binary for profiling with Nsight Systems. |
| EP_JIT_DUMP_SASS | Dumps the generated SASS (Streaming Assembler) code for inspection. |
| EP_JIT_PTXAS_CHECK | Runs ptxas to verify the generated PTX before final binary generation. |
| EP_JIT_PTXAS_VERBOSE | Enables verbose output from the ptxas compiler. |

### Signature and Hash-based Caching

 To minimize overhead during model initialization or first-run, DeepEP implements a robust caching mechanism. Every kernel launch request is transformed into a unique signature based on:

 
 - The base source code of the implementation (e.g., `dispatch_impl.cuh`).
 - The template parameters (e.g., `kNumSMs`, `kNumQPs`, `kNumExperts`).
 - The hardware architecture (e.g., SM90a).
 - Compiler flags and environment settings.

### Include Parsing and Argument Handling

 The `IncludeParser` (used within the `Compiler`) ensures that all header dependencies are available to NVRTC. The system also features a specialized argument handling mechanism for kernel launches.

 **Kernel Argument Processing:** When launching a kernel via `jit::launch_kernel`, the `get_kernel_arg_ptr` function determines how to pass each argument. If an argument inherits from `jit::NoRefPtr`, the raw pointer value is passed directly. Otherwise, the address of the argument is taken to be passed to the CUDA launch call [csrc/jit/handle.hpp13-20](https://github.com/deepseek-ai/DeepEP/blob/01dc3aaa/csrc/jit/handle.hpp#L13-L20)
