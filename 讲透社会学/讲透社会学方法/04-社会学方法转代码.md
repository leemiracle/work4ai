# 04 · 社会学方法转代码:把证据生产线搬进机器

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:社会学方法的设计端(03 章三张卡)几乎可以无损
> 转码,判断端(编码的意义、饱和的时机)几乎不可转码;三条代码
> 走廊——**抽样方差预算**、**量表信度监控**、**调查数据管道**——
> 把"开工文件"变成可跑、可断言、可做参数扫描的实验,
> 最实用的出口是一份**样本量报价单**。

---

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",社会学方法转代码要解决"**工艺的
参数化**":把一段方法语言("这个设计够不够严谨")先翻成参数与
预算(SE/deff/α/κ/权数),再翻成代码。翻译的损耗全部发生在第一步
——所以本章先划清哪些对象第一步就走得通(绿色区),哪些走不通
(红色区),再给三条走通了的走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 方法学概念 | 代码化身 | 备注 |
|-----------|---------|------|
| 抽样误差预算 | SE=σ/√n 的账单计算+MC 互证 | 实验幕一;n↔精度的定价表 |
| 设计效应 | deff=1+(m−1)ρ;整群模拟 | 实验幕二;复杂设计的方差膨胀器 |
| 样本量功效 | 效应量→n₀→×deff→÷(1−无应答率) | 走廊 1;上线前的报价单 |
| 量表信度 | α=kr̄/(1+(k−1)r̄)+单因子模拟 | 实验幕三;题量-题质兑换率 |
| 评分者一致性 | Cohen's κ=(P_o−P_e)/(1−P_e) | 走廊 4(轻);双人编码的质检仪 |
| 调查数据管道 | 受访者×题项×权数 schema+缺失三问 | 走廊 3;三张卡的字段直通 ETL |
| 权数与校准 | 设计权数 1/p_i 的设计还原 | 统计骨架链[../../讲透统计学/讲透社会统计学/README.md](../../讲透统计学/讲透社会统计学/README.md) |
| 痕迹数据采集纪律 | 快照+API 版本+去标识的复现包 | CSS 支;落点 4 |

**转不动/转不动的边界(红色区)**:

1. **编码的意义判断**:手册可存档、κ 可计算,但"这段资料该归哪个
   码"的判断不可外包——硬造"自动编码即真理"只会把偏见自动化。
   工程对策:机器预编码+人工终审,κ 只做质检。
2. **理论饱和的时机**:停采判据是理论敏感性的判断;代码只能给
   "新码发现率"曲线当仪表,不能替研究者踩刹车。
3. **覆盖误差的发现**:抽样框漏了谁是社会知识,不是数据内部的
   统计量——框外之人不在任何表里,算法看不见沉默。
4. **伦理判断**:知情同意与二次使用边界是规范问题;代码只能
   执行既定红线(字段级访问控制),不能生成红线。

**边界的一句话**:绿色区=03 章三张卡的字段与预算,恰好覆盖
"开工文件"的可计算部分;判断端的可审计性(手册/备忘/留痕)
可以**记录**进代码,不能**产生**于代码。

## 二、代码走廊清单(三条主走廊+一条轻走廊,每条=理论→模型→算法→真实系统)

### 走廊 1:抽样方差走廊(样本量报价单——本家族招牌)

```
尼曼理论 ──参数化──▶ SE=σ/√n;deff=1+(m−1)ρ ──预算链──▶ n₀×deff÷(1−r_nr)
      │
      ├──拨 n ──▶ 精度账单(×4 钱买 ×2 精度)──▶ 民调定价表
      └──拨 m/ρ ─▶ 整群偷样本(等效 n 骤减)──▶ 复杂设计的代价表
```

- **理论→模型**:两个参数轴——样本量 n 与设计参数(m, ρ);
  无应答率 r_nr 作乘法补偿。
- **算法层**:闭式预算+蒙特卡洛互证(经验 SE/经验方差对上理论值,
  家族实验幕一二的 assert 就是验收标准)。
- **本家族实现**:[`experiments/sampling_deff_alpha.py`](experiments/sampling_deff_alpha.py)
  幕一二——断言:理论减半律精确成立、MC 偏差<5%;deff=1.95 时
  等效样本近乎减半。
- **真实系统**:调查投标的样本量核算、A/B 测试与实验的功耗预算、
  任何"我们需要多大样本"的立项答辩。
- **性能工程要点**:预算计算是纯闭式(微秒级),**贵在参数知识**——
  ρ 与 r_nr 的历史值是组织的资产,应当沉淀成查询表而不是每次拍脑袋;
  MC 互证按 seed=base+情景号分流,保证可复现。

### 走廊 2:信度走廊(量表的兑换率模拟器)

```
Cronbach 理论 ──参数化──▶ α=kr̄/(1+(k−1)r̄)
      │
      ├──拨 k ──▶ 边际递减曲线(2→4→8 题的增益表)
      └──拨 r̄ ──▶ 第一杠杆展示(r̄ 0.3→0.5=加题 4→10 的效果)──▶ 改题优先于加题
```

- **理论→模型**:两旋钮——题量 k 与题间平均相关 r̄(题质);
  单因子模型(题=√r̄·潜特质+√(1−r̄)·噪声)生成模拟量表。
- **算法层**:闭式 α+经验 α(逐题累加 Σx、Σx²,在线计算内存 O(1));
  断言:闭式锚值 1e-3 容差、2→4→8 增量逐段缩小、阈值 k=21(r̄=0.30)
  对 k=9(r̄=0.50)、MC 经验 α 与闭式差<0.01。
- **本家族实现**:同实验幕三。
- **真实系统**:问卷上线前的题量决策(加题还是改题)、量表移植的
  预期信度评估、题库淘汰的量化依据。
- **性能工程要点**:经验 α 用在线累加(不存矩阵);模拟受访者数
  控制 α 估计噪声(4 万受访者时 SE≈0.002 量级,断言余量足够)。

### 走廊 3:调查数据管道走廊(schema 纪律)

```
三张结构卡 ──字段直通──▶ ETL schema:
  一行=一受访者;列=题项(码本对齐)+权数列+分层/PSU 标识列+时戳
      │
      ├──缺失三问 ─▶ MCAR/MAR/NMAR 的处理分叉(删除/插补/模型)
      └──权数纪律 ─▶ 一切汇总先乘权数;PSU 列保留=方差可分层
```

- **理论→模型**:03 章三张卡的字段**就是**列定义——设计卡给构念列,
  抽样卡给权数与 PSU 列,访谈卡给编码列。
- **算法层**:校验规则(行权限和、题项取值域、缺失标记与原因码);
  汇总层的加权均值与方差(可分层估计)。
- **真实系统**:纵向调查数据库、面板数据的波次对齐、行政记录链接。
- **性能工程要点**:PSU/分层列**必须进 schema**——删掉它等于烧掉
  deff 修正的可能(04 章落点 4 的姊妹坑);缺失原因与缺失本身
  分列存储(NMAR 的分析线索)。

### 走廊 4(轻):编码一致性走廊(κ 计算器)

```
双人编码 ──混淆矩阵──▶ P_o(观察一致率), P_e(随机一致率)
      └──κ=(P_o−P_e)/(1−P_e) ──▶ 判读表(<0.4 低/0.4-0.75 中/>0.75 高,通说)
```

- 教学用 30 行标准库可实现(混淆矩阵+两行算术);不另设实验
  (留作 ✍️练习 3),但它在真实定性 pipeline 里是**双人抽检的
  标配质检仪**。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:样本量报价单——上线前先算账

- 任何要"收集反馈/跑实验/做调查"的项目,立项时先跑走廊 1:
  预期效应量多大?检验要用多少 n?整群了吗(deff)?预期流失多少?
  **四个数字不齐的项目,样本量都是拍出来的**。性能工程的习惯
  (先 profile 再优化)在这里复用为先预算再采样。

### 落点 2:量表质控面板——别等收完数据再看信度

- 多题项测量(用户满意度、态度量表、问卷打分)上线后监控:
  在线 α(幕三算法)、题项-总分相关(区分度)、地板/天花板效应
  (打分挤在一端的题先预警)。发现低区分题,下次迭代**改题**
  而不是**加题**(强旋钮是 r̄)。

### 落点 3:调查数据管道——schema 即合同

- 03 章三张卡直通 ETL:一行一受访者+权数列+PSU 列+缺失原因码;
  汇总层一律加权。**schema 里省掉的标识列,分析时要花十倍代价
  找回**——这是"多保留一列"在数据工程里的复利。

### 落点 4:痕迹数据的复现纪律——CSS 工程化

- 平台/日志数据的采集包:快照存档(平台随时改规则)、API 版本号、
  去标识化字段表、获取日期与条款依据。**没有快照的痕迹分析
  不可复现**——复现纪律是 CSS 合格证的三分之一(01 章主线 A);
  伦理红线(获取边界/敏感字段)在采集层硬编码,不靠自觉。

## ✍️ 练习

1. 🐍 把走廊 1 扩成"报价单函数":输入效应量/α 水平/功效/m/ρ/r_nr,
   输出接触样本量与费用敏感度(对 ρ 从 0.02 扫到 0.10)——你的
   组织第一份样本量报价单
2. ✋ 用落点 2 的面板指标审一份你见过的问卷:哪道题会先被
   区分度筛掉?它的措辞哪里制造了模糊?
3. 🐍 实现走廊 4 的 κ 计算器(两位编码员×10 段文本的混淆矩阵),
   并手工验算一例
4. ✋ 用落点 3 的纪律体检一个你接触过的数据集:权数列在吗?
   PSU 在吗?缺失有原因码吗?三问全过再谈结论

## 📌 收束 + 🧭 认知升维

数字(效应量/n/deff/流失率);看到任何多题项测量,先问两个旋钮
(k 与 r̄,改题优先于加题);看到任何数据表,先看三列(权数/PSU/
缺失原因)。转码让这些追问从修辞变成可跑的断言。
