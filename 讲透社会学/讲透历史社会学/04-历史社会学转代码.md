# 04 · 历史社会学转代码:把时间机制搬进机器

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角
> 贯穿)。
>
> **本章一句话**:历史社会学的谱系左端(03 章)几乎可以无损转码,
> 右端几乎不可转码;三条代码走廊——**强化**(锁定与翻盘价码的
> 蒙特卡洛)、**丛集**(事件时间的统计指纹)、**证据链**(取证
> 记录的数据结构)——把"早期偶然滚成既得格局""大变动年代丛集"
> "历史证据可复核"变成可跑、可扫、可断言的实验。

---

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",历史社会学转代码要解决"**时间的
登记**":把一段历史直觉("老系统锁死了")先翻成时序量(状态、
强化参数、价码、丛集指数,02 章/03 章卡片),再翻成代码。翻译的
合法性损耗全部发生在第一步——所以本章先划清哪些对象第一步就走得
通(绿色区),哪些走不通(红色区),再给三条走通了的走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 研究对象 | 代码化身 | 备注 |
|---------|---------|------|
| Polya/Arthur 强化过程 | 逐事件蒙特卡洛(比例抽样/logit 选择) | 家族实验幕一/二全程纯标准库 |
| 锁定与翻盘价码 | δ 网格扫描×MC 求反转概率 | 幕二;sweep 天然可并行,seed=base+格号 |
| 阈值-释放/纪元模型 | 带漂移游走+阈值+释放的步进模拟 | 幕三 |
| 丛集指数/Fano | 分箱计数的方差/均值,流式单遍 | 幕三;泊松对照一行 Knuth |
| 事件史/hazard | 离散时间的风险表 | 支2 的常规仪表(方向级) |
| 序列距离(OM 简化版) | 替换/插入代价的动态规划 | 生命历程表的常规件(方向级) |
| 结构卡 schema | 定长字段记录+完整性断言 | 03 章三张卡;元数据工程 |
| 证据链登记 | provenance 图+每环损耗字段 | 卡 3 的数据结构化(走廊 3) |

**转不动(红色区)**:

1. **史料的真伪与解读**:外证内证的判断辅助可自动化,裁决不可
   (归[历史学宇宙](../../讲透历史学/README.md)的工艺与训练)。
2. **编码方案的社会判断**:什么算一次"事件"、状态怎么划分——
   划分即理论,代码只执行不发明(02 纪律 2 的对应)。
3. **关键节点的"重要性"**:结构松紧可登记(卡 2),但"这个节点
   值得研究"是选题判断。
4. **反事实的合法性**:机器可以跑反事实分支,但"哪个反事实最近
   可能世界"是史学的节制,不是算力问题(韦伯式纪律)。
5. **规范之问**:锁定该不该打破、遗产该不该清偿——代码定价,
   不裁应然。

**边界的一句话**:绿色区=机制骨架+时间度量+登记结构,覆盖
"时序直觉的推演与检验";红色区提醒:**代码是机制的沙盘,不是
历史的替身**。

## 二、代码走廊清单(三条主走廊,每条=理论→模型→算法→真实系统)

### 走廊 1:强化走廊(锁定与翻盘价码)

```
"锁死了" ──登记──▶ 强化过程(收益=基础+α×存量;logit 选择) ──MC──▶ 终局份额分布
      │
      └──扫描──▶ δ 网格×领先深度×出手时机 → δ*(翻盘价码)曲面
```

- **理论→模型**:规格卡字段直译:状态=两技术份额,规则=按含 α×
  份额的收益做 logit 选择,异质性=±ξ 内在偏好(幕二全套)。
- **算法层**:逐采纳者一个 logit(一次 exp);锁定判据=终局份额
  阈值;价码=δ 网格上翻盘概率过 0.75 的最小 δ。O(采纳者数×MC 数)。
- **本家族实现**:[`experiments/path_and_moment.py`](experiments/path_and_moment.py)
  幕二——断言对称五五开、δ* 3 倍、时机 100% vs 0%。
- **真实系统**:技术选型的锁定审计(迁移成本不只是工时,还有
  生态递增)、标准战争的沙盘、"先发优势"的定价。
- **性能工程要点**:logit 的 exp 是热点,指数差先算再除(避免两次
  exp);MC 批结构天然并行,逐格 seed 保证复现;**别把 share-based
  的强化改成 count-based**"优化"——两者的锁定尺度不同,换底盘
  要重新验收(01 章判读要点 1 的工程版)。

### 走廊 2:丛集走廊(事件时间的统计指纹)

```
"动荡的年代" ──登记──▶ 事件时刻表 ──分箱──▶ 计数序列 ──Fano──▶ 丛集指数
      │
      └──对照──▶ 泊松(同总数重撒)≈1 / 恒压定时器 ≪1 / 纪元模型 >1
```

- **理论→模型**:压力游走+阈值+部分释放+纪元变量(幕三全套);
  断言锚在分布性质(过度散布),不锚单点。
- **算法层**:步进模拟 O(步数);Fano 流式单遍(累计箱计数、平方
  和);泊松对照小 λ 用 Knuth 乘积法。变点/纪元检测可用箱计数的
  滑窗差(方向级)。
- **本家族实现**:同实验幕三——断言 1.75/3.23>1、泊松 0.97、
  定时器 0.07。
- **真实系统**:故障/事故报警的纪元语义(报警丛集≠发生率上升,
  可能是进入了压力纪元)、内容热点的时间结构、组织变革的窗口
  识别。
- **性能工程要点**:Fano 用 Welford 式单遍(均值/方差同时更新,
  免二次遍历);大时间轴先粗箱后细箱(两遍多分辨率);**纪元变量
  的切换率参数要扫描**,单点参数的丛集结论不报(幕三的纪律)。

### 走廊 3:证据链走廊(取证记录的数据结构)

```
"这条历史数据可信吗" ──登记──▶ provenance 图(记录→存留→转录→编码→度量)
      │
      └──断言──▶ 每环损耗字段+沉默字段+独立链交叉 → 置信等级
```

- **理论→模型**:03 章卡 3 的字段直译成节点属性;断言=链完整性
  (每环非空且损耗≤阈值)+独立链读数一致。
- **算法层**:链是 DAG,完整性是拓扑检查;交叉是两条链的终端
  度量差检验。全部 O(链长)。
- **本家族实现**:schema 在 03 章卡 3,未做代码(登记结构无算法
  深度)——留作 ✍️练习 2 的最小实现。
- **真实系统**:数据治理的血统(lineage)系统、AI 训练数据的来源
  分级(一手/转引/合成)、审计追踪。
- **性能工程要点**:provenance 图用追加日志(不可变)而非可变
  记录;沉默字段是**必填默认空**,不是可选注释——数据结构即纪律。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:技术选型的锁定审计——先问 δ*,再问好不好

任何长周期技术决策(数据库/框架/供应商),除了功能对比,强制加
一页**锁定审计**:递增强度 α 在哪(生态/技能池/数据格式)、当前
时龄的领先滚到多少、δ* 大概多大(替代品要持续好多少才翻得动)。
幕二的教训:δ* 随时龄自己长(0.55→0.69→…),**想换的窗口在
早期,不在"等它再烂一点"**——坑不是等出来的,是滚出来的。

### 落点 2:报警的纪元语义——丛集不等于恶化

监控里报警突然扎堆,第一反应通常是"事故变多了"。先算一步:同
总数重撒的泊松基线,丛集指数>1 说明系统进入了压力纪元(负载/
债技/人事慢变量的临界段)——该修的是纪元变量,不是逐个报警。
恒定压力下的"规律报警"反而是定时器(欠散布),不是稳定。

### 落点 3:决策留痕的过程追踪——hoop 与冒烟枪的取证设计

重大技术决策(架构变更/事故响应)的文档,按四测验设计留痕:
**哪些记录能证伪我们的决策依据(箍:失败指标与阈值)**,**哪些
能确证(冒烟枪:关键实验数据)**。事后复盘时,链断在哪一环看
得到——决策的"历史"也该可复核(03 章卡 1 的工程版)。

### 落点 4:机会的时机核算——同因不同时不同果

同样的投入(重构/扩张/换血),在稳态里和在窗口期里后果不同
(02 章时序纪律 2)。给重大动作加一行**时机核算**:现在处于什么
纪元(压力累积到哪)?窗口开着还是关着(约束松紧三档,03 章卡 2)?
——"做什么"与"什么时候做"要分开定价。

   为高

证据不足"的判断,先问三件事:翻盘价码多少且还在涨吗(强化走廊)、
事件的时间指纹是均匀/定时/丛集哪种(丛集走廊)、证据链哪一环
最弱(证据链走廊)。转码让这三问从修辞变成可跑的断言。
