# 04 · 比较社会学转代码:把比较设计搬进机器

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:比较社会学的谱系左端(03 章)几乎可以无损转码,
> 右端几乎不可转码;三条代码走廊——**辛普森分解**、**等价性模拟**、
> **QCA 真值表**——把「聚合会翻案」「尺子有方言」「覆盖度要扣重叠」
> 变成可跑、可断言、可做参数扫描的实验。

---

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",比较社会学转代码要解决两步翻译:
先把设计语言("这两国可比")翻成模型(分层结构/集合隶属),再把
模型翻成代码。损耗全部发生在第一步——所以本章先划清哪些对象第一
步就走得通(绿色区),哪些走不通(红色区),再给三条走通了的走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 比较概念 | 代码化身 | 备注 |
|---------|---------|------|
| 辛普森分解/直接标准化 | 分组率+共同权重加权 | 实验幕一全程纯标准库 |
| DIF 的产生与校准 | 潜特质模拟(同分布+题偏移)+题目级群体差 | 实验幕二;MC 固定种子 |
| 真值表构建 | 案例按组态聚合(2^k 行,计数+一致性) | 实验幕三 |
| 布尔最小化 | 吸收律+素蕴涵项(Quine-McCluskey) | 小 k 可全量;断言解一致 |
| 一致性/覆盖度/必要性 | 子集包含的计数运算 | 幕三断言三律 |
| 案例选择卡/等价性卡/真值表卡 | 定长字段记录+完整性断言 | 03 章 schema 的数据化 |
| 回译差异比对 | 困难词清单的文本 diff/对齐 | 只做"发现差异",不做"处置" |

**转不动(红色区)**:

1. **配平清单的裁定**:哪些背景"算相似"是理论判断——代码能校验
   配平清单**非空且双人独立填过**,不能生成清单。
2. **校准锚点**:把变量转成集合隶属的三锚(0.5 交叉点)是质性
   判断;机器只负责锚点给定后的诚实计算(QCA 的稳健性审计正是对
   这个人工环节的系统性复查)。
3. **语境与路径**:"为什么恰是英国"没有状态方程——硬造"路径
   指数"只会得到自己假设回去的结论(03 章右端)。
4. **等价性不通过的处置**:代码能算出哪题带方言,处置(改题/删题/
   限定比较范围)是设计决策,不是拟合问题。
5. **应然之问**:"哪国制度更好"的规范判断不进实验台——代码算
   分解与包含,算不了好坏。

**边界的一句话**:绿色区=分解类+集合类+卡片类,覆盖"比较纪律的
校准";红色区提醒:**转码是比较的使用说明书,不是比较的替身**。

## 二、代码走廊清单(三条主走廊,每条=理论→模型→算法→真实系统)

### 走廊 1:辛普森分解走廊(聚合审计的全机械化)

```
跨国/跨区聚合数据 ──参数化──▶ 分组(率ᵢ, nᵢ) ──双算──▶ 聚合率 vs 分层率
      │                                                        │
      └──对照──▶ 直接标准化(共同权重) ──▶ 方向一致性断言 ◀────┘
```

- **理论→模型**:聚合率 = Σ通过ᵢ/Σ申请ᵢ;结构分布 {nᵢ/Σn} 是
  隐藏变量;标准化率 = Σwᵢ·率ᵢ(共同权重 w)。
- **算法层**:分组统计 O(n);方向断言(分层方向 vs 聚合方向符号
  是否一致)。
- **本家族实现**:[`experiments/comparison_pitfalls.py`](experiments/comparison_pitfalls.py)
  幕一——部门内 88.9%<90%、20%<33.3% 而聚合 82%>39%,标准化
  (50/50)后翻回。
- **真实系统**:跨地区运营报表的**分层审计列**(每行聚合指标旁
  强制附分层方向);跨国用户研究的发表前检查。
- **性能工程要点**:计算量微不足道——价值全在**断言的位置**:把
  「聚合方向=分层方向」做成 CI 里的固定检查项,聚合报表与分解
  报表同一次提交生成,防止"先看哪个先信哪个"。

### 走廊 2:等价性模拟走廊(尺子的方言检测)

```
量表+两群体 ──参数化──▶ 潜特质 θ~N(0,1) 同分布+载荷+题偏移 δ ──模拟──▶ 总分差
      │                                                                              │
      └──检测──▶ 题目级群体差(哪题带 δ)──校准──▶ 校准后总分差≈0 ◀──────────────┘
```

- **理论→模型**:总分差 = Σ题期望差;无 DIF 题贡献 0,带 DIF 题贡献
  δ——**假差异可解析**;MC 用固定种子复现。
- **算法层**:两组各 n 个 (θ, e₁..e₅) 抽样;题目级群体差扫描=最简
  DIF 检测;校准=扣除带偏题的群体差。
- **本家族实现**:同实验幕二——0.3 假差异(解析+MC 双证),校准后
  归零。
- **真实系统**:国际化产品的问卷本地化 QA 管道(上线前跑各语言版
  本的题目级分布比对);跨国员工调研的 DIF 监控。
- **性能工程要点**:每群体 n 次独立抽样,**天然可并行**(按
  replicate 分流 seed=base+rep 编号保证可复现);真数据侧把 MC 换成
  多组不变性检验(估计技术归
  [../../讲透统计学/讲透社会统计学/README.md](../../讲透统计学/讲透社会统计学/README.md),
  本走廊管它的设计与判定语义)。

### 走廊 3:QCA 真值表走廊(组态逻辑的全机械化)

```
案例清单 ──校准──▶ 条件隶属 ──聚合──▶ 2^k 真值表 ──最小化──▶ 解(A·B+C)
    │                                                        │
    └────审计──▶ 一致性/必要性/原始覆盖/解覆盖(重叠扣减) ◀──────┘
```

- **理论→模型**:案例→组态(布尔向量);一致性/覆盖度=包含计数;
  最小化=布尔吸收(Y=A·B+C 已最简,幕三的最小性检查三断言)。
- **算法层**:组态聚合 O(n·k);最小化用 Quine-McCluskey 或启发式
  (k 小时全量素蕴涵项)。
- **本家族实现**:同实验幕三——一致性 1.0;原始覆盖 55>解覆盖 50;
  A 非必要(0.6)。
- **真实系统**:风控/审批**规则库的组态覆盖审计**(每条规则=一组
  条件组态;重叠覆盖=冗余规则=幕三重叠扣减的工程版);特征组合的
  策略分析。
- **性能工程要点**:**2^k 指数爆炸是第一约束**——k≤15 全量真值表
  可行(32768 行),再大必须转 CSP/启发式最小化;断言只锚一致性、
  覆盖度关系与必要性,不锚浮点尾数;校准锚点作为**输入参数**显式
  注入,不许埋进代码(红色区纪律的工程表达)。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:跨地区面板的分层审计——先问加出来的是什么

- 任何按国家/地区聚合的指标(通过率/转化率/满意度),报表层强制
  加一列**分层方向**:抽样分布 {nᵢ} 相差悬殊的地区间比较,聚合行
  随时可能翻案(幕一的 43 个百分点翻转)。**读数规则**:聚合方向
  与分层方向不一致时,聚合行作废,只报分层+标准化。

### 落点 2:问卷本地化的 DIF 监控管道

- 多语言产品调研上线前:对每题跑语言组间的分布比对(控制总分的
  题目级差异),标记"方言题";发布门槛=**方言题处置完毕**。幕二
  是这个管道的最小验收用例:**潜特质同分布的两群体,量表仍能稳定
  "测出"差异——差异在题,不在人**。

### 落点 3:规则库的组态覆盖审计

- 把每条业务规则表达为条件组态,定期跑真值表:统计各规则的原始
  覆盖与解覆盖(并集)——**原始覆盖之和与解覆盖之差就是重叠度**,
  即冗余规则的重灾区(幕三 55>50 的工程版);顺带做必要性扫描:
  哪些条件在所有触发案例里都在(必要),哪些只是搭车的。

### 落点 4:选样复盘——你也在"只研究成功者"

- A/B 上线城市的选择、案例研究的客户选择,都逃不过格迪斯式的
  选择偏差:**只看成功案例推出的经验规则,天然高估**。给重要决策
  配一张 03 章案例选择卡:池子、策略、配平、**负案例在哪**——
  把"为什么选这些城市"从口述传统变成可审计字段。

## ✍️ 练习

1. 🐍 给走廊 3 实现最小最小化器:输入为幕三的真值表,输出素蕴涵项;
   断言 Y=A·B+C 无法再省任一字面量(提示:逐项删减后检查错盖与漏盖)
2. 🐍 在实验幕一里交换两国部门人数(部门1 与部门2 的申请量互换,
   通过率不动),预测并验证聚合方向是否翻转;再换标准化权重
   (30/70)看结论对权重的敏感度
3. ✋ 把落点 2 写成一页 runbook:方言题的判定阈值、处置选项(改题/
   删题/限定)、复检频率;注明哪一步永远留给人(红色区)
4. ✋ 用落点 3 的思路审计一个你熟悉的规则系统(优惠/风控/审批任选):
   估计有多少条规则的触发集是其他规则的子集(冗余下界)
