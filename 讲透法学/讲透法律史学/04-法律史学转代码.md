# 04 · 法律史学转代码——编年·对读·断代统计的最小走廊

> **本章回答五问之 Q5(问题→代码转换)**。
> **本质一句话**:法律史学的问题一旦变成"关于法典/档案数据的计算",
> 就能进代码——编年变时间轴、律疏变对读表、法系兴衰变密度曲线;
> **唯一不可外包给代码的,是史学判断本身(选样、归因、断代、反事实)**。

---

## 0. 开篇:三十九条记录检验两个百年直觉

「罗马法在《学说汇纂》编成后休眠了五百余年」「十九-二十世纪之交
两系合流(修律与法典化叠加)」——两个教科书级叙事,能不能用数据说话?

`experiments/00_dual_code_timeline.py` 内置 39 条
「年份×法系×人物×事件」里程碑(中华法系/罗马法系/两系相遇三轨),
结构化后做三件事:世纪×法系切片、**休眠期检测**(533-1070 之间
罗马轨事件数应为零,且这 537 年正是罗马轨的最大间隔)、
**合流窗口密度断言**(1900-1930 三十年密度应为两千年基线的十倍以上,
实测 16 倍)。跑一遍,两个直觉都拿到数据支撑——外加一条你没料到的:
**中华法系轨两千年间的最大事件间隔(363 年,汉魏之际)远小于罗马休眠期**
——不间断的成文法传统,在点列上表现为"无罗马级深谷"。

但脚本同时打印选样声明:这 40 条是"入选正史的著名事件",
密度度量的是**正史关注度**,不是"法制产出"。**代码替你算数,
替不了你解释数**——数字人文的第一课。

## 1. 可机械化边界(三件套之一)

**能进代码的**(史料数据化后的一切统计与可视化):

| 任务 | 机械化形式 |
|------|-----------|
| 编年密度/休眠期检验 | 事件点列 → 世纪直方图、间隔序列、断代密度比 |
| 法典结构解析 | 条文文本 → (行为要件, 刑等, 但书, 引用边) 的树/图 |
| 律疏对读 | 律文×疏议逐条配对 → 释义覆盖率、问答密度统计 |
| 条文存续 diff | 两部法典条文对齐 → 存/改/废/增 矩阵(03 章 §5) |
| 五服函数实现 | 服制表 → penalty(act, degree, direction) 查表程序 |
| 人物-仕历网络 | CBDB 导出 → 官员迁转图、刑部/大理寺人员构成时序 |
| 术语首见检测 | 语料年代分层 → 词首现年份(移植链的语言信号) |

**不能进代码的**(法律史的"不可判定域"):

1. **选样正当性**——哪些事件算"里程碑"是史学判断;代码只能做
   敏感性分析(§4.5)
2. **归因与动机**——"缇萦上书导致废肉刑"的因果强度,代码给不出;
   相关(同年发生)永远推不出因果
3. **断代裁定**——"中华法系何时解体"的截止刻度(1902?1911?1920s?)
   是概念决定,不是数据决定;代码只能给"密度骤降点"作参考
4. **价值排序**——"唐律比明律先进"没有客观函数;重要性加权=
   把史观伪装成超参数(01 章 ABM 热线的同一警告)

> 边界的一句话:**代码是法典的显微镜,不是史学家**。
> 放大倍数越高,越要记得镜头是谁选的。

## 2. 代码走廊清单(三件套之二:三条走廊)

### C1 编年数据结构化走廊(✅ 已实现)

| 字段 | 类型 | 约束/坑 |
|------|------|--------|
| year | int | 负数=公元前;无 0 年——跨元前后差值计算要 −1 |
| system | 枚举 {中华, 罗马, 相遇} | 枚举表本身=史学选样判断;增删须记变更 |
| actor | str | "传说"人格显式标注(如皋陶);群体作者合法("波伦亚注释法学派") |
| text | str | 不带形容词——数据与叙事分离 |
| source_tier | T1..T6 | 证据等级(02 章 §2.5);缺此字段的编年库一律视为 T4 |

成品 = `experiments/00_dual_code_timeline.py`(数据+断言一体)。

### C2 文本对读走廊(律-疏对读,最小示例)

对读是法律史独门的"双栏阅读":律文(规定)×疏议(解释)×
异代对应条文(沿革)。最小可运行示例——把一条律文按句法切开,
抽出"行为要件/刑等/调制因子":

```python
TANG_STATUTE = "诸殴兄姊者，徒二年半；伤者，徒三年。"   # 《斗讼》条文(节写)

def parse_statute(s):
    """律文三段式:行为模式(诸……者)/ 刑等(徒X年)/ 但书(；……)。"""
    body, *escalation = s.replace("。", "").split("；")
    act, pen = body[:-1].split("者，")            # 行为要件 / 基本刑
    return {"act": act.lstrip("诸"), "penalty": pen,
            "escalation": escalation}              # 加重档(伤者……)

r = parse_statute(TANG_STATUTE)
assert r["act"] == "殴兄姊" and r["penalty"] == "徒二年半"
assert r["escalation"] == ["伤者，徒三年"]         # 伤害结果升档
print(r)   # {'act': '殴兄姊', 'penalty': '徒二年半', 'escalation': ['伤者，徒三年']}
```

十行代码完成的事:一条条文 → 结构化记录(03 章 §1.5 statute 模式的
真正落地)。扩展方向:把《唐律》502 条全部解析后,
"但书密度""刑等分布""引用边"三张统计表自动生成——
**法典计量学(codemetrics)的最小闭环**。史学红线:解析器输出的
是"文本结构",不是"运行实态"——后者要接判例档案。

### C3 断代统计走廊(密度、间隔与骤降点)

编年数据的最深问题不是"有什么",而是"**何时密、何时疏**"。
三件工具(纯标准库可写全):

```python
def gaps(events):                       # 事件间隔序列(断代统计的地基)
    ys = sorted(y for y, *_ in events)
    return [b - a for a, b in zip(ys, ys[1:])]

def window_density(events, lo, hi):     # 窗口密度:断代对比
    n = sum(1 for y, *_ in events if lo <= y <= hi)
    return n / max(hi - lo, 1)          # 件/百年

def cliff(events):                      # 密度骤降点:休眠/解体的数据信号
    ys = sorted(y for y, *_ in events)
    return max(zip(ys, ys[1:]), key=lambda p: p[1] - p[0])  # 最大间隔
```

在实验数据上:`cliff(罗马轨)` 应返回 (533, 1070)——**休眠期
在数据里表现为点列的最大间隔**,一个最大值函数就把它检测出来了;
`cliff(中华轨)` 落在明清之间但远小于 537 年——"两千年无深谷"的
量化表达。这就是断代统计走廊的全部思想:**断代假设 → 密度/间隔
假设 → 可断言**。

## 3. 工程落点(三件套之三,性能工程视角)

1. **数据管道落点**:法典/档案数字化 → 结构化(JSON/关系表,03 章
   schema)→ 分析脚本。关键纪律:**数据与叙事分离**(text 字段不带
   形容词);引用编号(卷-篇-条 / D.x.x.x)作为主键贯穿全管道——
   相当于给每条史料一个 URI
2. **性能落点**:CBDB 约 37 万人 × 仕历记录是十万边的图计算负载;
   清代档案全文检索是标准的倒排索引问题;条文对齐 diff 是
   序列比对(与 bioinformatics 的多序列同源——见
   [讲透科学技术史](../../讲透科学技术史/)文本计量横断面互链)。
   这些都是可缓存、可增量的正经工程问题
3. **AI 工程落点**(接 01 章 §1.3):LLM 流水线处理司法档案的
   转写/要素抽取,**评估器必须按史学纪律设计**——逐字对照、
   引用回链、幻觉零容忍:编造一条不存在的判例比漏读十行更糟
   (假阳性代价不对称,01 章 §3 的工程化)。设计模式:
   模型只许输出"编号+引文",引文必须在原文中 exact match——
   把"可验证性"做成输出格式的硬约束

## 4. 一个完整的心智案例:验证"法典化浪潮"叙事

四步走(三条走廊+人):

1. **C1**:`00_dual_code_timeline.py` 数据就位(39 条,三轨)
2. **C3**:窗口密度对比——合流窗口(1900-1930)对两千年基线
   (前 536-1799),计算件/百年;脚本断言密度比 ≥10×(实测 16×)
3. **C2**(对读扩展):把 1804《法国民法典》与 1911《大清刑律》的
   章节目录对齐——"总则出现/罪名抽象化/刑等简化"三个结构信号
   在两典中的出现情况(移植的结构证据)
4. **解释层(人)**:密度跃升 + 结构同构,支持"十九-二十世纪
   全球法典化"的外史解释(民族国家+成文宪法制度扩散);
   但**选样偏差警告**:"法典颁行"是高显影度事件,
   非法典机制(普通法/习惯法)的同期演化被系统性低计——
   结论必须写进这条限制条款

——这个案例就是本家族对"讲透范式(直觉→结构→代码→不足→应用)"的完整走法。

## 4.5 敏感性分析:史学计算的"测试框架"

- **换选样**:把"法典里程碑"换成"法学著作出版"再跑密度——
  同向=稳健;分叉=结论只属于某个选样
- **留一检验**:随机抽掉 10% 事件重跑——密度比波动 <20% 说明
  结论不依赖个别大事件
- **零点检验**:休眠期窗口从 (533,1070) 移到 (500,1100)/(600,1000)
  各跑一遍——"休眠"结论对窗口切口不敏感才可断言
- **双轨对照**:中华轨与罗马轨用同一套工具各自跑——工具不偏向
  任何法系,是双系比较可信的前提

这四招之于法律史计算,正如 property-based test 之于软件:
**不是证明结论对,而是让结论的可错性显形**。

## 4.6 走廊×断言阶梯对照(哪条走廊能支撑哪级断言)

| 走廊 | 最高可支撑 | 常被误用于 |
|------|-----------|-----------|
| C1 编年 | T2(事件见于文献) | 被当 T3"法制产出结论"——密度是关注度 |
| C2 对读 | T1(条文结构本身) | 被当 T4"运行实态"——纸面≠行动 |
| C3 断代 | T3(断代密度规律) | 被当"断代裁定"——骤降点≠解体时刻(§1.3) |

(阶梯见 02 章 §2.5;每条走廊的产品都贴着自己的证据上限。)
