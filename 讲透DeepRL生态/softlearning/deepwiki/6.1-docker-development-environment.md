  This document covers the Docker-based development environment setup for the softlearning framework. The Docker environment provides isolated, reproducible development containers with all dependencies pre-installed, supporting both CPU and GPU configurations for deep reinforcement learning development.

 For information about cloud deployment using these Docker images, see [Cloud Deployment](https://deepwiki.com/rail-berkeley/softlearning/6.2-cloud-deployment). For distributed training setup, see [Distributed Training with Ray](https://deepwiki.com/rail-berkeley/softlearning/5.3-distributed-training-with-ray).

 
## Overview

 The softlearning repository provides a comprehensive Docker development environment that eliminates the complexity of managing dependencies like MuJoCo, CUDA drivers, and various Python packages. The system uses a two-stage approach: base images containing all dependencies, and development containers that mount the source code as volumes for live editing.

### Volume Mounts and Ports

 The development containers expose several ports and mount critical directories:

 **Port Mappings:**

 
 - `6006`: TensorBoard visualization
 - `5000`: Viskit plotting tool
 - `8888`: Jupyter notebook server
 
 **Volume Mounts:**

 
 - `~/.aws:/root/.aws`: AWS credentials for S3 storage
 - `~/.config/gcloud:/root/.config/gcloud`: Google Cloud credentials
 - `~/.mujoco/mjkey.txt:/root/.mujoco/mjkey.txt`: MuJoCo license
 - `..:/root/softlearning`: Source code directory
 - `~/ray_results/softlearning-dev-{cpu,gpu}:/root/ray_results`: Experiment results

## Base Image Dependencies

 
### System-Level Dependencies

 The base containers install comprehensive system dependencies required for deep RL development:

 **Core Build Tools:**

 
 - `build-essential`, `cmake`, `make`: Compilation tools
 - `curl`, `wget`, `git`: Network and version control utilities
 - `swig`: SWIG wrapper generator for Python bindings
 
 **Graphics and Rendering:**

 
 - `libglfw3`, `libgl1-mesa-dev`: OpenGL libraries
 - `libglew-dev`, `libosmesa6-dev`: Graphics extensions
 - `xvfb`, `xserver-xorg-dev`: Virtual display for headless operation
 
 **MuJoCo Physics Engine:**

 
 - Versions 1.50 and 2.00 installed to `/root/.mujoco/`
 - Library paths configured in `LD_LIBRARY_PATH`
 - License file mounted via Docker secrets

## GPU Configuration

 The GPU variant extends the CPU base with NVIDIA CUDA support:

 **CUDA Dependencies:**

 - cuDNN: `libcudnn7=7.4.1.5-1+cuda10.0`

## Cloud Build Integration

 The repository includes Google Cloud Build configuration for automated image building:

 **Build Steps:**

 
 - Build GPU and CPU images using docker-compose
 - Tag images for Google Container Registry
 - Push both `latest` and commit-hash tagged versions
 - Encrypt MuJoCo license using Google KMS
 
 The cloud build process handles both development and production image variants automatically.
