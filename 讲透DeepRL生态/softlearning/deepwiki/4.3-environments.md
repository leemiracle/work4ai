  The environment system in softlearning provides a unified interface for integrating different reinforcement learning environment libraries. This system uses the adapter pattern to standardize interaction with environments from OpenAI Gym, DeepMind Control Suite, and Robosuite, enabling seamless switching between different simulation backends while maintaining consistent API semantics.

 For information about using environments in custom training scenarios, see [Custom Environments](https://deepwiki.com/rail-berkeley/softlearning/5.1-custom-environments). For details on how environments integrate with the sampling system, see [Sampling and Data Collection](https://deepwiki.com/rail-berkeley/softlearning/4.4-sampling-and-data-collection).

## SoftlearningEnv Interface

 The `SoftlearningEnv` abstract base class defines the core interface that all environment adapters must implement. This interface closely follows the OpenAI Gym API but includes additional functionality specific to softlearning's requirements.


 
### Core Interface Methods

 The `SoftlearningEnv` interface requires implementation of several core methods:

 
| Method | Purpose | Return Type |
|---|---|---|
| step() | Execute one environment step | (observation, reward, terminal, info) |
| reset() | Reset environment to initial state | observation |
| render() | Render environment visualization | varies by mode |
| seed() | Set random seed | list of seeds |
| unwrapped | Access underlying environment | base environment object |

### Key Properties

 The interface standardizes access to environment properties:

 
 - **observation_space**: Always a `gym.spaces.Dict` containing named observation components
 - **action_space**: Flattened action space (1D vectors only)
 - **observation_shape**: TensorFlow tensor shapes for neural network integration
 - **action_shape**: TensorFlow tensor shape for action vectors

## Gym Environment Adapter

 The `GymAdapter` integrates OpenAI Gym environments into the softlearning framework. It handles action/observation rescaling, time limit unwrapping, and observation space standardization.

 
### Key Features

 
 - **Action Rescaling**: Rescales continuous action spaces to specified ranges (default `[-1, 1]`)
 - **Observation Rescaling**: Optional rescaling of observation values
 - **Time Limit Handling**: Removes `TimeLimit` wrappers to maintain Markovian properties
 - **Observation Dictionary**: Converts single observations to dictionary format with configurable keys
 - **Pixel Observations**: Supports pixel-based observations through `PixelObservationWrapper`

### Time Step Integration

 The adapter converts dm_control's `TimeStep` format to standard RL tuples:

 
 - `time_step.reward` → reward (defaults to 0.0 if None)
 - `time_step.last()` → terminal flag
 - `time_step.observation` → filtered observation dictionary
 - Non-observation data moved to info dictionary

## Common Features Across Adapters

 All environment adapters share several common features and capabilities:

 
### Observation Management

 
 - Dictionary-based observation spaces for consistent data structure
 - Configurable observation and goal keys for filtering relevant data
 - Automatic observation space validation and filtering via `_filter_observation()`
 
 
### Action Space Standardization

 
 - Support for action rescaling to standard ranges (typically `[-1, 1]`)
 - Validation that action spaces are flat (1D vectors)
 - Action clipping to prevent numerical issues
 
 
### Diagnostic Integration

 
 - `get_path_infos()` method for aggregating environment diagnostics
 - Consistent info dictionary structure across different backends
 - Integration with softlearning's logging and evaluation systems
