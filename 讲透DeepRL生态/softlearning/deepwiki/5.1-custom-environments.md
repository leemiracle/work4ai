  This document covers the custom environment system in softlearning, which provides a framework for creating and registering custom reinforcement learning environments. The system focuses primarily on MuJoCo-based environments with specialized reward functions and observation spaces.

 For information about the general environment adapter system that integrates these custom environments with the framework, see [Environments](https://deepwiki.com/rail-berkeley/softlearning/4.3-environments). For details on how environments are used in training workflows, see [Sampling and Data Collection](https://deepwiki.com/rail-berkeley/softlearning/4.4-sampling-and-data-collection).

 
## Environment Registration System

 The softlearning framework provides a centralized registration system for custom environments through the `gym` package integration. The system defines environment specifications and provides registration functions to make them available to the training framework.

 
```

```

 The environment specifications define the environment ID, entry point, and any additional parameters needed for registration. The system supports two main categories of environments:

 
| Category | Description | Example Environments |
|---|---|---|
| MuJoCo Environments | Physics-based environments using MuJoCo simulator | Pusher2d-Default-v0, Swimmer-Parameterizable-v3 |
| General Environments | Non-physics specific environments | MultiGoal-Default-v0 |

## MuJoCo Environment Hierarchy

 The custom MuJoCo environments follow an inheritance hierarchy that allows for specialized reward functions and observation spaces while maintaining compatibility with the standard gym interface.

 
```

```

 The base `Pusher2dEnv` class provides:

 
 - 3-DOF manipulator control
 - Configurable reward coefficients for arm-object and goal-object distances
 - Customizable goal positions (including 'any' coordinate specification)
 - Standard state-based observations

## Environment Variants and Specializations

 
### Pusher2d Environment Family

 The `Pusher2dEnv` serves as the foundation for a family of manipulation environments with different observation modalities and reward structures:


 
### Key Environment Features

 
| Environment Class | Observation Space | Reward Function | Special Features |
|---|---|---|---|
| Pusher2dEnv | Joint positions/velocities + body positions | Distance-based costs | Configurable goal masking |
| ForkReacherEnv | Extended state + goal position | Arm-goal distance focus | Randomized target positioning |
| ImagePusher2dEnv | Flattened RGB images + joint state | Computed from true state | Configurable image dimensions |
| BlindForkReacher2dEnv | Joint positions/velocities only | Arm-goal distance focus | Minimal observation space |

## Model Files and Physics Configuration

 Custom environments utilize MuJoCo XML model files that define the physics simulation parameters, robot morphology, and environmental constraints.

 The model files define:

 
 - **Bodies and Joints**: Robot morphology and degrees of freedom
 - **Actuators**: Motor specifications with control ranges
 - **Collision Geometry**: Environmental obstacles and constraints
 - **Initial Conditions**: Default positions and velocities

## Creating Custom Environments

 To create a new custom environment in the softlearning framework:

 
### 1. Environment Class Implementation

 Extend the appropriate base class and implement required methods:

 
 - `__init__()`: Initialize environment parameters and call parent constructor
 - `step()`: Execute one environment step and return observation, reward, done, info
 - `compute_reward()`: Calculate reward based on observations and actions
 - `reset_model()`: Reset environment state and return initial observation
 - `_get_obs()`: Construct observation vector from simulation state
 
 
### 2. Registration Process

 Add environment specification to the appropriate list in [softlearning/environments/gym/__init__.py14-64](https://github.com/rail-berkeley/softlearning/blob/13cf187c/softlearning/environments/gym/__init__.py#L14-L64):

### 3. Key Implementation Patterns

 
 - **Reward Computation**: Implement both single-step and batch reward computation
 - **State Management**: Use `self.set_state()` for state initialization
 - **Observation Construction**: Concatenate relevant state components into flat arrays
 - **Parameter Configuration**: Use `utils.EzPickle` for proper serialization support
