  This document covers the distributed training capabilities in the softlearning framework using Ray's autoscaler functionality. The system enables scaling reinforcement learning experiments across cloud infrastructure with automatic resource management and fault tolerance.

 For general experiment execution and configuration, see [Execution Modes](https://deepwiki.com/rail-berkeley/softlearning/3.2-execution-modes). For containerized deployment strategies, see [Cloud Deployment](https://deepwiki.com/rail-berkeley/softlearning/6.2-cloud-deployment).

 
## Architecture Overview

 The distributed training system uses Ray's autoscaler to manage clusters of compute nodes that can dynamically scale based on workload demands. The architecture consists of a head node that coordinates training and worker nodes that execute distributed sampling and computation.

### Command Options

 The cluster launch commands support several configuration options:

 
| Option | Default | Purpose |
|---|---|---|
| --config_file | None | Custom autoscaler configuration |
| --stop/--no-stop | True | Terminate cluster after completion |
| --start/--no-start | True | Start cluster if needed |
| --screen/--no-screen | False | Run in screen session |
| --tmux/--no-tmux | True | Run in tmux session |
| --override-cluster-name | None | Custom cluster identifier |
| --port-forward | None | Port forwarding configuration |

## Resource Management and Scaling

 The autoscaler manages cluster resources based on utilization metrics and configurable thresholds.

 
### Scaling Parameters

 
 - **Target Utilization**: `target_utilization_fraction: 0.99` maintains near-maximum resource usage [config/ray-autoscaler-gce.yaml30](https://github.com/rail-berkeley/softlearning/blob/13cf187c/config/ray-autoscaler-gce.yaml#L30-L30)
 - **Idle Timeout**: `idle_timeout_minutes: 5` removes unused nodes quickly [config/ray-autoscaler-gce.yaml33](https://github.com/rail-berkeley/softlearning/blob/13cf187c/config/ray-autoscaler-gce.yaml#L33-L33)
 - **Initial Workers**: `initial_workers: 0` starts with head node only [config/ray-autoscaler-gce.yaml15](https://github.com/rail-berkeley/softlearning/blob/13cf187c/config/ray-autoscaler-gce.yaml#L15-L15)
 - **Max Workers**: `max_workers: 100` allows substantial scaling [config/ray-autoscaler-gce.yaml10](https://github.com/rail-berkeley/softlearning/blob/13cf187c/config/ray-autoscaler-gce.yaml#L10-L10)
 
 
### Cost Optimization

 Both configurations use cost-effective instance options:

 
 - **GCP**: Preemptible instances with `preemptible: true` [config/ray-autoscaler-gce.yaml86](https://github.com/rail-berkeley/softlearning/blob/13cf187c/config/ray-autoscaler-gce.yaml#L86-L86)
 - **AWS**: Spot instances via `MarketType: spot` [config/ray-autoscaler-ec2.yaml78](https://github.com/rail-berkeley/softlearning/blob/13cf187c/config/ray-autoscaler-ec2.yaml#L78-L78)
