  This document covers the tools and utilities for simulating trained reinforcement learning policies in the softlearning framework. The primary focus is on loading trained policy checkpoints, reconstructing the training environment, and running evaluation rollouts to assess policy performance.

 For information about training policies, see [Algorithms](https://deepwiki.com/rail-berkeley/softlearning/4.1-algorithms) and [Policies](https://deepwiki.com/rail-berkeley/softlearning/4.2-policies). For details on environment setup, see [Environments](https://deepwiki.com/rail-berkeley/softlearning/4.3-environments).

## Checkpoint Loading and Metadata Extraction

 The simulation system loads trained models from Ray Tune experiment checkpoints. The `load_variant_progress_metadata` function extracts three key components needed for policy reconstruction:

 
| Component | File Location | Purpose |
|---|---|---|
| Variant | trial_path/params.pkl | Experiment configuration and hyperparameters |
| Progress | trial_path/progress.csv | Training metrics and performance history |
| Metadata | checkpoint_path/.tune_metadata | Ray Tune checkpoint metadata |

### Policy Reconstruction

 The `load_policy` function rebuilds the policy network architecture and loads trained weights. Key steps include:

 
 - **Parameter Configuration**: Copies policy parameters from variant and updates them with environment-specific information:

 
 - Action space bounds (`action_range`)
 - Observation shapes (`input_shapes`)
 - Action dimensions (`output_shape`)
 - **Policy Instantiation**: Uses the policy factory `policies.get()` to create the policy instance
 - **Weight Loading**: Loads trained weights from the checkpoint using the ExperimentRunner's policy save path convention

## Running Simulation Rollouts

 The core simulation functionality uses the `rollouts` function from the sampling utilities to execute policy rollouts in the reconstructed environment. The simulation process:

 
 - **Rollout Execution**: Runs `num_rollouts` episodes, each up to `max_path_length` steps
 - **Rendering**: Supports different render modes including 'human' for display and 'rgb_array' for video recording
 - **Path Collection**: Returns episode data including observations, actions, rewards, and rendered frames

## Video Recording and Evaluation

 When render mode is set to 'rgb_array', the simulation system can record videos of policy performance:

 
### Video Generation Process

 
 - **Frame Collection**: Rendered frames are stored in the `images` field of each episode path
 - **FPS Calculation**: Frame rate is determined from environment timestep (`dt` attribute) with a default of 30 FPS
 - **Video Saving**: Uses `save_video` utility to encode frames into MP4 format
 
 
```

```

 
### Render Configuration

 The rendering system supports flexible configuration through `render_kwargs`:

 
| Parameter | Default | Purpose |
|---|---|---|
| mode | 'human' | Render mode ('human', 'rgb_array', etc.) |
| Custom kwargs | {} | Environment-specific rendering options |

## Command Line Interface

 The simulation script provides a command-line interface for easy policy evaluation:

 
### Required Arguments

 
 - `checkpoint_path`: Path to the Ray Tune checkpoint directory containing the trained policy
 
 
### Optional Arguments

 
| Argument | Short | Type | Default | Description |
|---|---|---|---|---|
| --max-path-length | -l | int | 1000 | Maximum steps per episode |
| --num-rollouts | -n | int | 10 | Number of episodes to simulate |
| --render-kwargs | -r | JSON | '{}' | Rendering configuration as JSON string |
| --video-save-path |  | Path | None | Directory to save video files |
