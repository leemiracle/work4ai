  This document covers the different execution modes available in the softlearning framework for running reinforcement learning experiments. These modes provide flexibility for development, debugging, and large-scale training across different computational environments.

 For information about experiment configuration parameters, see [Configuration System](https://deepwiki.com/rail-berkeley/softlearning/3.1-configuration-system). For deployment strategies and containerization, see [Development and Deployment](https://deepwiki.com/rail-berkeley/softlearning/6-development-and-deployment).

 
## Overview

 The softlearning framework supports five primary execution modes, each optimized for different use cases and computational requirements. These modes are implemented through the `examples.instrument` module and exposed via the CLI interface in `softlearning.scripts.console_scripts`.

## Mode Selection and Command Interface

 Execution modes are selected through the `--mode` argument and corresponding CLI commands. The mode determines Ray initialization parameters, resource allocation, and infrastructure setup.

 
| Mode | CLI Command | Function | Target Environment |
|---|---|---|---|
| Local | run_example_local | run_example_local() | Single machine |
| Debug | run_example_debug | run_example_debug() | Development/debugging |
| Cluster | run_example_cluster | run_example_cluster() | Ray cluster |
| GCE | launch_example_gce | launch_example_gce() | Google Cloud |
| EC2 | launch_example_ec2 | launch_example_ec2() | AWS |

## Local Mode

 Local mode executes experiments on a single machine with optional parallelization across available CPUs and GPUs. It initializes Ray with local resources and runs the `ExperimentRunner` directly.

 
```

```

 The `run_example_local()` function in `examples.instrument` handles local execution:

 
 - Initializes Ray with specified CPU/GPU resources
 - Configures local directories for experiment results
 - Runs `tune.run()` with the `ExperimentRunner` trainable class
 - Supports resource specification via `--cpus`, `--gpus`, and `--resources-per-trial`
 
 **Sources:** [examples/instrument.py220-245](https://github.com/rail-berkeley/softlearning/blob/13cf187c/examples/instrument.py#L220-L245) [examples/utils.py19-53](https://github.com/rail-berkeley/softlearning/blob/13cf187c/examples/utils.py#L19-L53)

 
## Debug Mode

 Debug mode is specifically designed for development and debugging workflows. It modifies execution parameters to enable debugger usage and provides immediate feedback for development iterations.

 Key characteristics of debug mode:

 
 - Forces `local_mode=True` in Ray initialization
 - Sets `tf.config.experimental_run_functions_eagerly(True)` by default
 - Allocates all available CPUs to a single trial
 - Disables features incompatible with debugging (server ports, upload directories)
 - Sets `fail_fast=True` for immediate error reporting
 
 
```

```

 The debug mode implementation in `run_example_debug()` automatically adjusts parameters:

 
 - `trial_cpus = multiprocessing.cpu_count()`
 - `server_port = None`
 - `max_failures = 0`
 - `upload_dir = None`
 - `fail_fast = True`

## Cluster Mode

 Cluster mode executes experiments on an existing Ray cluster, enabling distributed training across multiple machines. It connects to a Ray head node and distributes work across worker nodes.

 The `run_example_cluster()` function configures Ray to connect to an existing cluster:

 
 - Sets Ray address to `<head_node_ip>:6379`
 - Enables `queue_trials=True` for efficient resource utilization
 - Supports autoscaling worker nodes based on demand

## Cloud Modes (GCE and EC2)

 Cloud modes leverage Ray autoscaler to launch and manage cloud infrastructure automatically. These modes use predefined cluster configurations and handle the full lifecycle of cloud resources.

 
### GCE Mode

 GCE mode uses Google Cloud Platform with configuration from `config/ray-autoscaler-gce.yaml`:

 
 - Supports preemptible instances for cost optimization
 - Configures machine types: `n1-standard-4` (head), `n1-standard-8` (workers)
 - Automatically handles authentication and Docker image deployment
 
 
### EC2 Mode

 EC2 mode uses AWS with configuration from `config/ray-autoscaler-ec2.yaml`:

 
 - Supports spot instances for cost optimization
 - Configures instance types: `c5.2xlarge` for both head and worker nodes
 - Integrates with AWS IAM for authentication

 - Check for `upload_dir` configuration to prevent data loss

## Resource Configuration

 All execution modes support resource specification through command-line arguments that map to Ray and Tune parameters:

 
| Argument | Purpose | Applies To |
|---|---|---|
| --cpus | Ray process CPUs | All modes |
| --gpus | Ray process GPUs | All modes |
| --trial-cpus | CPUs per trial | Local, Debug, Cluster |
| --trial-gpus | GPUs per trial | Local, Debug, Cluster |
| --resources-per-trial | Custom resources | All modes |

 The `_normalize_trial_resources()` function in `examples.instrument` consolidates these parameters into the format expected by `tune.run()`.
