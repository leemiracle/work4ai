  This document describes the configuration system used in softlearning for experiment orchestration and parameter management. The configuration system provides a hierarchical, flexible way to define and override experiment parameters through variant specifications (`variant_spec`) that integrate with Ray Tune for hyperparameter sampling and distributed execution.

 For information about running experiments with different execution modes, see [Execution Modes](https://deepwiki.com/rail-berkeley/softlearning/3.2-execution-modes). For details about the core algorithmic components configured by this system, see [Core Components](https://deepwiki.com/rail-berkeley/softlearning/4-core-components).

 
## Overview

 The configuration system centers around **variant specifications** - hierarchical dictionaries that define all parameters needed for an experiment. These specifications are built dynamically based on environment characteristics, command-line arguments, and predefined parameter hierarchies.

## Integration with ExperimentRunner

 The generated variant specifications are consumed by the `ExperimentRunner` class:

 
```

```

 
### Component Initialization Flow

 The `ExperimentRunner._build()` method follows this initialization sequence:

 
 - **Environment Setup**: Create training and evaluation environments from `environment_params`
 - **Q-Function Configuration**: Update input shapes based on environment observation/action spaces
 - **Policy Configuration**: Set action ranges and input shapes from environment
 - **Replay Pool Setup**: Configure with environment reference
 - **Sampler Configuration**: Link environment, policy, and replay pool
 - **Algorithm Assembly**: Combine all components into final algorithm
