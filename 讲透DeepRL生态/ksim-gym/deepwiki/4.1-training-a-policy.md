## Training Configuration Options

 The training process is controlled by the `HumanoidWalkingTaskConfig` class, which provides various configuration options:

 
| Category | Parameter | Default | Description |
|---|---|---|---|
| Model Parameters | hidden_size | 128 | Hidden dimension size for the neural networks |
|  | depth | 5 | Number of GRU cells in the recurrent layers |
|  | num_mixtures | 5 | Number of Gaussian mixtures for the actor distribution |
|  | var_scale | 0.5 | Scale factor for action distribution variance |
|  | use_acc_gyro | True | Whether to use IMU acceleration and gyroscope data |
| Training Parameters | num_envs | 2048 | Number of parallel environments for training |
|  | batch_size | 256 | Batch size for optimization |
|  | rollout_length_seconds | 8.0 | Duration of each rollout in seconds |
|  | learning_rate | 3e-4 | Learning rate for the optimizer |
|  | adam_weight_decay | 1e-5 | Weight decay for the Adam optimizer |
| Curriculum Parameters | num_curriculum_levels | 100 | Number of difficulty levels |
|  | increase_threshold | 5.0 | Threshold to increase difficulty |
|  | decrease_threshold | 1.0 | Threshold to decrease difficulty |
|  | min_level_steps | 1 | Minimum steps before changing curriculum level |
| Simulation Parameters | dt | 0.002 | Simulation timestep in seconds |
|  | ctrl_dt | 0.02 | Control timestep in seconds |
|  | action_latency_range | (0.003, 0.01) | Range of action latency to simulate |

## Step-by-Step Training Workflow

 
### 1. Environment Initialization

 When you start training, the system:

 
 - Creates the MuJoCo simulation environment with the KBot humanoid model
 - Initializes the reward system, observation space, and termination conditions
 - Sets up the curriculum learning system
 - Initializes the Actor-Critic model
 
 Sources: [train.py359-369](https://github.com/kscalelabs/ksim-gym/blob/3e92db5c/train.py#L359-L369) [train.py370-377](https://github.com/kscalelabs/ksim-gym/blob/3e92db5c/train.py#L370-L377)

 
### 2. Training Loop

 The training loop consists of these main steps:

 
 - Rolling out trajectories in parallel environments
 - Computing advantages using the critic network
 - Optimizing the policy using PPO
 - Updating the curriculum difficulty based on performance
 - Periodically saving checkpoints and logging metrics

### 3. Observation System

 The observation space includes various sensors and state information:

 
| Observation Type | Description |
|---|---|
| Joint Positions | Current angles of all robot joints |
| Joint Velocities | Angular velocities of all joints |
| Actuator Forces | Forces applied by actuators |
| Center of Mass | Information about the robot's center of mass |
| Base Position/Orientation | Position and orientation of the robot's base |
| Projected Gravity | Gravity vector projected in the robot's frame |
| IMU Data | Accelerometer and gyroscope readings |

### 4. Reward System

 The reward function is a combination of several components:

 
| Reward Component | Description |
|---|---|
| Forward Progress | Reward for moving forward |
| Upright Orientation | Reward for maintaining upright posture |
| Stay Alive | Reward for not terminating |
| Movement Penalties | Penalties for unnecessary movements |
| Posture Penalties | Penalties for poor posture (e.g., bent arms, straight legs) |

## Best Practices for Training

 
 - **Hardware Requirements**: Use a GPU for faster training. An RTX 4090 can train a walking policy in approximately 30 minutes.
 - **Training Duration**: A basic walking behavior typically emerges within ~80 training steps.
 - **Configuration Tuning**:

 
 - Increase `num_envs` if you have sufficient GPU memory for faster training
 - Adjust `hidden_size` and `depth` to balance model capacity and training speed
 - Modify reward scales if the robot is focusing too much on one aspect of the task
 - **Continuing Training**: To continue training from a checkpoint:

 - **Physics Randomization**: The system automatically applies physics randomization to ensure robustness:

 
 - Joint friction variations
 - Mass variations
 - Joint damping randomization
 - Initial position randomization

## Extending the Training System

 To extend or customize the training system, you can modify the following aspects:

 
 - **Reward Components**: Add or modify rewards in the `get_rewards` method of `HumanoidWalkingTask`
 - **Observation Space**: Customize observations in the `get_observations` method
 - **Model Architecture**: Modify the `Actor` and `Critic` classes to experiment with different neural network architectures
 - **Curriculum**: Implement a custom curriculum by creating a new class that inherits from `ksim.Curriculum`
