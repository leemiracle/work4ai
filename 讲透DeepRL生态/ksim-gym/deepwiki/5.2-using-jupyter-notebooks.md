## Best Practices and Tips

 When working with the Jupyter notebooks in K-Sim Gym, keep the following in mind:

 
 - **JIT Compilation Delays**: The first execution will trigger JAX's just-in-time compilation, which may appear to disconnect your notebook. Be patient during this initial compilation phase.
 - **Resource Requirements**: The default configuration (`num_envs=2048`) requires significant computational resources. Adjust these parameters based on your available hardware.
 - **Checkpointing Frequency**: By default, checkpoints are saved every 60 seconds. You can adjust this with the `save_every_n_seconds` parameter.
 - **Task Path Warning**: You may see a warning like "Could not resolve task path for task_name" which can be safely ignored in the notebook environment.
 - **Custom Rewards**: The notebook demonstrates how to create custom rewards (like `BentArmPenalty` and `StraightLegPenalty`) that you can use as templates for your own reward functions.

## Notebook vs. Command-Line Interface

 The following table compares using Jupyter notebooks versus the command-line interface:

 
| Feature | Jupyter Notebook | Command-Line Interface |
|---|---|---|
| Interactivity | High - can modify and rerun cells | Low - requires editing files and rerunning |
| Visualization | Integrated (TensorBoard in-notebook) | Separate window/browser |
| Documentation | Markdown cells with explanations | Comments in code |
| Iteration Speed | Quick for parameter tuning | Better for production runs |
| Resource Monitoring | Can monitor in same interface | Requires separate tools |
| Version Control | Less convenient (JSON format) | More convenient (Python files) |

 Sources: [train.ipynb1-904](https://github.com/kscalelabs/ksim-gym/blob/3e92db5c/train.ipynb#L1-L904)
