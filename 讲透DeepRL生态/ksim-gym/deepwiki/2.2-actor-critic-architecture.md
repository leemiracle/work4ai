  This page provides a detailed explanation of the Actor-Critic architecture used in K-Sim Gym for training humanoid robot controllers. The Actor-Critic approach is a core component of the training system that enables effective learning of complex locomotion policies. For information about the reward system that shapes the learning process, see [Reward System](https://deepwiki.com/kscalelabs/ksim-gym/2.3-reward-system), and for details on the observation space, see [Observation System](https://deepwiki.com/kscalelabs/ksim-gym/2.4-observation-system).

 
## Overview

 The Actor-Critic architecture in K-Sim Gym implements a recurrent neural network-based policy and value function approximator for reinforcement learning. The architecture consists of two primary components:

 
 - **Actor**: Produces a probability distribution over actions given observations
 - **Critic**: Estimates the expected value (return) of states given observations
 
 These two networks work together within the Proximal Policy Optimization (PPO) algorithm to learn optimal control policies for humanoid robots.

## Actor Component

 The Actor component is responsible for mapping observations to a probability distribution over actions. It learns a policy that determines which actions to take in different states.

 The Actor is implemented in the `Actor` class which consists of:

 
 - **Input Projection Layer**: Transforms observation vectors to the hidden representation size
 - **Recurrent GRU Cells**: Provide temporal memory across timesteps
 - **Output Projection Layer**: Maps hidden state to parameters for a mixture of Gaussians distribution
 - **Mixture of Gaussians Distribution**: Models a multimodal action distribution
 
 
### Implementation Details

 The Actor network outputs parameters for a mixture of Gaussians distribution, which provides a rich representation of the action space and allows for multimodal behavior.

 Key components of the Actor implementation:

 
 - **Hidden State**: The GRU cells maintain a hidden state across timesteps, allowing the policy to use temporal information
 - **Action Distribution**: The `MixtureOfGaussians` distribution models the policy with multiple modes
 - **Variance Control**: The network includes parameters like `min_std`, `max_std`, and `var_scale` to control exploration

## Critic Component

 The Critic component estimates the value function, which represents the expected future reward from each state following the current policy.

 The Critic is implemented in the `Critic` class which has a structure similar to the Actor:

 
 - **Input Projection Layer**: Transforms observation vectors to the hidden representation size
 - **Recurrent GRU Cells**: Provide temporal memory across timesteps
 - **Output Projection Layer**: Maps hidden state to scalar value estimates
 
 
### Implementation Details

 The Critic receives a more comprehensive set of observations than the Actor, as it needs to accurately evaluate the current state. While the Actor focuses on information needed to determine actions, the Critic uses additional state information to provide accurate value estimates.

### Observation Processing

 Both the Actor and Critic networks process observations differently:

 
 - **Actor Observations**:

 
 - Timestep (sine and cosine)
 - Joint positions
 - Joint velocities
 - Projected gravity
 - IMU acceleration and gyroscope (optional)
 - **Critic Observations**:

 
 - All Actor observations
 - Center of mass inertia
 - Center of mass velocity
 - Actuator forces
 - Base position and orientation
 - Additional sensor data

## Key Parameters and Configuration

 The Actor-Critic architecture is configured through several parameters defined in the `HumanoidWalkingTaskConfig` class:

 
| Parameter | Default | Description |
|---|---|---|
| hidden_size | 128 | Hidden dimension size for both Actor and Critic networks |
| depth | 5 | Number of stacked GRU cells in both networks |
| num_mixtures | 5 | Number of Gaussian components in the mixture distribution |
| var_scale | 0.5 | Scaling factor for the variance of the action distribution |
| use_acc_gyro | True | Whether to include accelerometer and gyroscope data in Actor observations |

 Additional parameters related to the action distribution:

 
| Parameter | Value | Description |
|---|---|---|
| min_std | 0.001 | Minimum standard deviation for action distribution |
| max_std | 1.0 | Maximum standard deviation for action distribution |

## Model Initialization and Hidden State Management

 The Actor-Critic model maintains a hidden state (carry) across timesteps which is initialized to zeros at the beginning of each episode:

 
```

```

 Sources: [train.py629-633](https://github.com/kscalelabs/ksim-gym/blob/3e92db5c/train.py#L629-L633) [train.py572-611](https://github.com/kscalelabs/ksim-gym/blob/3e92db5c/train.py#L572-L611)

 The model carry consists of:

 
 - Actor carry: Shape `(depth, hidden_size)`
 - Critic carry: Shape `(depth, hidden_size)`
 
 Each carry is reset to zeros at the end of an episode, ensuring that temporal information doesn't leak between episodes.
