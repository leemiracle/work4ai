  This page explains the process of converting trained policy checkpoints to the K-Infer format for deployment. After training a policy (as described in [Training a Policy](https://deepwiki.com/kscalelabs/ksim-gym/4.1-training-a-policy)), the trained model needs to be converted to a format that can be deployed on real robots or in the K-Infer simulator. This conversion process transforms JAX model checkpoints into the optimized K-Infer format.

 
## Conversion Process Overview

 The conversion process takes a trained checkpoint file (.bin) and transforms it into a deployable K-Infer model file (.kinfer). This conversion involves several steps, including extracting the policy functions, converting them to ONNX format, and packaging everything into the K-Infer model format.

## Implementation Details

 
### Model Function Components

 The conversion process extracts two critical functions from the policy model:


 Sources: [convert.py48-76](https://github.com/kscalelabs/ksim-gym/blob/3e92db5c/convert.py#L48-L76)

 
### Function Definitions

 
 - **Initialization Function (`init_fn`)**

 
 - Creates the initial hidden state (carry) for the recurrent neural network
 - Returns zeros with shape determined by model depth and hidden size
 - **Step Function (`step_fn`)**

 
 - Takes current robot state observations
 - Processes them through the policy network
 - Returns action values (joint targets) and updated hidden state
 
 The conversion process:

 
 - Loads the saved checkpoint using the `HumanoidWalkingTask.load_task()` method
 - Extracts the model from the checkpoint
 - Creates JIT-compiled versions of `init_fn` and `step_fn`
 - Converts both functions to ONNX format using the `export_fn` utility from K-Infer
 - Packages the ONNX models with joint information into a single K-Infer model file
 
 Sources: [convert.py37-99](https://github.com/kscalelabs/ksim-gym/blob/3e92db5c/convert.py#L37-L99)

 
### Input/Output Specification

 The step function processes these inputs:

 
| Input | Description | Shape |
|---|---|---|
| joint_angles | Current joint positions | (num_joints,) |
| joint_angular_velocities | Current joint velocities | (num_joints,) |
| projected_gravity | Gravity vector in robot frame | (3,) |
| accelerometer | Linear acceleration measurements | (3,) |
| gyroscope | Angular velocity measurements | (3,) |
| time | Current time (used for periodic features) | (1,) |
| carry | Hidden state from previous step | (depth, hidden_size) |

 And produces these outputs:

 
| Output | Description | Shape |
|---|---|---|
| actions | Target joint positions | (num_joints,) |
| new_carry | Updated hidden state | (depth, hidden_size) |

### ONNX Export and Packaging

 The conversion uses K-Infer's export utilities:

 
 - `export_fn`: Converts JAX functions to ONNX format
 - `pack`: Packages the exported functions with metadata (joint names) into a single binary file

## Technical Implementation Details

 The conversion process carefully preserves the structure of the policy network while optimizing it for deployment:

 
 - Only the actor network is exported (the critic is only needed during training)
 - The distribution output is converted to deterministic mode output (using `dist.mode()`)
 - The conversion automatically handles batched inputs through `jax.vmap`
 - Joint names are extracted from the MuJoCo model to ensure correct mapping to robot joints
 
 The converted model maintains the same neural network architecture but is optimized for inference performance on deployment hardware.
