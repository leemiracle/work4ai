# Environment Creation

  Relevant source files 
 - [slm_lab/env/__init__.py](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py)
 - [slm_lab/spec/demo.json](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/spec/demo.json)
 
  This page covers how SLM Lab creates and configures Gymnasium environments from a spec file. It documents the public entry point `make_env`, the internal helpers `_make_single_env` and `_make_vector_env`, the vectorization mode selection logic, the wrapper pipeline applied to each environment type, and the attributes injected onto the final environment object.

 For documentation of the custom wrapper classes (`ClockWrapper`, `TrackReward`, `VectorFullGameStatistics`, etc.) that are applied during this process, see [Environment Wrappers](https://deepwiki.com/kengz/SLM-Lab/6.2-environment-wrappers). For the full `env` block of the spec format, see [Spec Format Reference](https://deepwiki.com/kengz/SLM-Lab/7.1-spec-format-reference).

 
---

 
## Overview

 All environment construction is handled in [slm_lab/env/__init__.py](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py) The single public function is `make_env`, which accepts the full experiment spec and returns a fully configured, wrapped `gym.Env` instance ready for use by the `Session`.

 The spec's `env` block drives every decision:

 
| Spec field | Effect |
|---|---|
| name | Gymnasium environment ID; ALE/ prefix triggers Atari path |
| num_envs | 1 → single env, >1 → vectorized env |
| max_t | Episode step limit (falls back to registry default or 108000) |
| max_frame | Total training frame budget |
| normalize_obs | Enables running-mean observation normalization |
| normalize_reward | Enables running-mean reward normalization |
| clip_obs | Clips observations to [-clip_obs, clip_obs] (defaults to 10.0 if normalize_obs is set) |
| clip_reward | Clips rewards; scalar or [min, max] list |
| Any other key | Passed directly to gym.make / gym.make_vec as keyword arguments |

 Keys that `make_env` consumes internally and does **not** forward to Gymnasium are defined in `RESERVED_KEYS` [slm_lab/env/__init__.py51-60](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L51-L60)

## Atari Detection

 Atari environments are identified by a name prefix check:

 
```
is_atari = name.startswith("ALE/")
```

 This boolean controls whether Atari-specific preprocessing wrappers (`AtariPreprocessing`, `FrameStackObservation`) and reward clipping (`VectorClipReward` at `[-1, 1]`) are applied. The `ALE/` prefix is the canonical form used by `ale-py` when registered with `gym.register_envs(ale_py)` [slm_lab/env/__init__.py39-46](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L39-L46)

 Key notes:

 
 - Atari-specific kwargs (`life_loss_info`, `reward_clipping`) are removed from `make_kwargs` before calling `gym.make` to avoid Gymnasium errors.
 - `TrackReward` is always applied on the single-env path (no equivalent exists for vector envs, which use `VectorRecordEpisodeStatistics` instead).

## Vector Environment Path (`_make_vector_env`)

 Called when `num_envs > 1`. Gymnasium's `gym.make_vec` is used with a `vectorization_mode` selected by `_get_vectorization_mode`.

 
### Vectorization Mode Selection

 [slm_lab/env/__init__.py74-87](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L74-L87)

 
| Environment type | num_envs | Rendering | Mode selected |
|---|---|---|---|
| ALE (Atari) | any | no | vector_entry_point (native AtariVectorEnv) |
| ALE (Atari) | any | yes | sync (rendering not supported in AtariVectorEnv) |
| Classic control / Box2D | any | any | sync |
| Other | < 8 | any | sync |
| Other | >= 8 | any | async |

 `vector_entry_point` mode uses Gymnasium's native `AtariVectorEnv` which handles all Atari preprocessing internally. When falling back to `sync` for Atari rendering, `AtariPreprocessing` and `FrameStackObservation` are applied per-env via the `wrappers` argument to `gym.make_vec`.

### `state_dim` derivation

 
| observation_space type | env.state_dim value |
|---|---|
| spaces.Box, 1-D shape | obs_space.shape[0] (integer) |
| spaces.Box, multi-D shape | obs_space.shape (tuple) |
| Other | getattr(obs_space, 'n', obs_space.shape) |

 
### `action_dim` and `is_discrete` derivation

 
| action_space type | env.action_dim | env.is_discrete | env.is_multi |
|---|---|---|---|
| spaces.Discrete | action_space.n | True | False |
| spaces.Box, 1-D | action_space.shape[0] | False | shape[0] > 1 |
| spaces.Box, multi-D | action_space.shape | False | True |
| spaces.MultiDiscrete | action_space.nvec.tolist() | True | True |
| spaces.MultiBinary | action_space.n | True | True |

 
### `max_t` fallback chain

 `max_t` is resolved as:

 
 - `env_spec.get("max_t")` — explicit spec value
 - `env.spec.max_episode_steps` — Gymnasium registry default
 - `108000` — hard-coded fallback
 
 
### Distributed `max_frame` adjustment

 When `spec["meta"]["distributed"]` is not `False`, `max_frame` is divided by `max_session` to ensure each session covers an equal share of the total frame budget [slm_lab/env/__init__.py148-149](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L148-L149)

 
### Vector env canonical spaces

 For `VectorEnv` instances, `env.observation_space` and `env.action_space` are overwritten with `single_observation_space` and `single_action_space` respectively, so that all downstream code can access spaces uniformly regardless of whether the env is vectorized [slm_lab/env/__init__.py106-108](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L106-L108)
