  This page documents the `Agent` class and the `MetricsTracker` class, both defined in [slm_lab/agent/__init__.py](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py) Together they form the agent-side of the RL loop: `Agent` coordinates algorithm, memory, and environment interactions, while `MetricsTracker` records every measurable quantity produced during training and evaluation.

 For the algorithms that `Agent` delegates to, see [Algorithms](https://deepwiki.com/kengz/SLM-Lab/5.2-algorithms). For the memory classes, see [Memory](https://deepwiki.com/kengz/SLM-Lab/5.3-memory). For how `Session` drives the RL loop and calls into `Agent`, see [Control Flow](https://deepwiki.com/kengz/SLM-Lab/4.1-control-flow:-experiment-trial-and-session). For how the metrics recorded here feed into plots and reports, see [Metrics and Analysis](https://deepwiki.com/kengz/SLM-Lab/4.2-metrics-and-analysis).

## Construction and Ownership

 The `Session` creates instances in a fixed order via `make_agent_env` [slm_lab/experiment/control.py21-26](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/control.py#L21-L26):

 
 - `env = make_env(spec)` – instantiate the environment
 - `mt = MetricsTracker(env, spec)` – attach the tracker to the env
 - `agent = Agent(spec, mt=mt, global_nets=global_nets)` – attach the agent to both
 
 `MetricsTracker` is constructed first because `Agent.__init__` requires a fully-constructed `mt`. After `Agent.__init__` runs, the cross-reference `mt.agent = self` is set, giving the tracker access back to the agent.

## Agent

 
### Class Summary

 `Agent` is defined in [slm_lab/agent/__init__.py24-120](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py#L24-L120) and exposes four public methods decorated with `@lab_api`:

 
| Method | Signature | Role |
|---|---|---|
| act | (state) → action | Forward pass through algorithm.act; always runs under torch.no_grad() |
| update | (state, action, reward, next_state, done, terminated, truncated) | Records to tracker, stores in memory, triggers training |
| save | (ckpt=None) | Delegates to algorithm.save; skipped in eval mode |
| close | () | Calls save() at session end |

 
### Initialization

 [slm_lab/agent/__init__.py30-71](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py#L30-L71)

 `Agent.__init__` reads `spec["agent"]` (the `agent_spec`) and performs the following in order:

 
 - **Space attributes** – copies `observation_space`, `action_space`, `state_dim`, `action_dim`, `is_discrete` from `env`.
 - **Action distribution** – determines `action_type`, `action_pdtype`, and `ActionPD` via `policy_util.get_action_type` and `policy_util.get_action_pd_cls`.
 - **Exploration state** – initializes `explore_var`, `entropy_coef`, `entropy` to `np.nan` (overwritten by the algorithm).
 - **Memory** – instantiates the class named by `agent_spec["memory"]["name"]`, looked up from the `memory` module.
 - **Algorithm** – instantiates the class named by `agent_spec["algorithm"]["name"]`, looked up from the `algorithm` module, passing `self` and `global_nets`.
 
 The class and instance names come directly from the spec, so adding new algorithms or memory types requires no changes to `Agent`.

 
### `act`

 [slm_lab/agent/__init__.py73-78](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py#L73-L78)

## MetricsTracker

 
### Class Summary

 `MetricsTracker` is defined in [slm_lab/agent/__init__.py123-414](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py#L123-L414) It is responsible for:

 
 - Maintaining `train_df` and `eval_df` as time-indexed DataFrames of per-checkpoint metrics.
 - Computing rolling reward moving average (`total_reward_ma`).
 - Persisting the best model threshold (`best_total_reward_ma`).
 - Providing per-checkpoint log output and TensorBoard summaries.
 - Supplying the `metrics` dict to Ray Tune via `calc_log_metrics`.
 
 
### State Variables

 
| Variable | Type | Description |
|---|---|---|
| loss | float | Set by agent.update() after each algorithm.train() call |
| total_reward_ma | float | Rolling mean of recent total_reward; updated on every ckpt() call |
| best_total_reward_ma | float | High-water mark used in Session.try_ckpt to trigger best-model saves |
| train_df | DataFrame | One row per checkpoint, df_mode='train' |
| eval_df | DataFrame | One row per checkpoint, df_mode='eval'; shares reference with train_df when rigorous_eval=False |
| algo_vars | dict | Registry of {var_name: source_obj} for dynamically tracked quantities |
| metrics | dict | Flat scalar dict populated by calc_log_metrics; read by search.report |

 
### DataFrame Columns

 Both `train_df` and `eval_df` share the same column schema [slm_lab/agent/__init__.py145-156](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py#L145-L156):

 
| Column | Source |
|---|---|
| total_reward | np.nanmean(env.total_reward) |
| total_reward_ma | Rolling mean over last PLOT_MA_WINDOW rows |
| loss | mt.loss |
| fps | frame / wall_t |
| frame | env.get("frame") |
| wall_t | env.get_elapsed_wall_t() |
| t | env.get("t") |
| epi | env.get("epi") |
| opt_step | env.get("opt_step") |
| lr | Mean of all lr_scheduler.get_last_lr() values in the algorithm |
| grad_norm | Mean gradient norm (dev/test mode only) |
| (dynamic) | Any variable registered via register_algo_var |

### `log_summary`

 [slm_lab/agent/__init__.py327-351](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py#L327-L351)

 Logs the most recent DataFrame row as a grid of `key:value` pairs (4 per line). Log output is suppressed inside a Ray Tune context to reduce noise. In `dev` mode, also calls `log_tensorboard()`.

 
### `log_tensorboard`

 [slm_lab/agent/__init__.py353-404](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py#L353-L404)

 Activated only in `lab_mode == "dev"` for session 0. Logs:

 
 - All scalar values from the last row of `train_df`
 - Network parameter histograms for each non-global, non-target network
 - Action histograms collected between log calls
 - The network computation graph (once, at frame 0)
 
 The TensorBoard writer is lazily initialized on first call with a path derived from `spec["meta"]["log_prepath"]`.

 
### `calc_log_metrics`

 [slm_lab/agent/__init__.py308-325](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py#L308-L325)

 Computes session metrics from the current DataFrame and stores them in `self.metrics` for use by `search.report`. Calls `analysis.analyze_session` in no-plot mode to get the scalar metrics dict, then merges them with the latest row's `time_attr` and `metric` fields expected by the Ray Tune scheduler.

 
### `register_algo_var`

 [slm_lab/agent/__init__.py181-183](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py#L181-L183)

 Algorithms can register extra variables for tracking by calling:

 
```
mt.register_algo_var("explore_var", self.agent)
```

 On each `calc_df_row` call, `MetricsTracker` reads `getattr(source_obj, var_name)` and includes it in the DataFrame row. The column is added dynamically to `train_df` and `eval_df` if not already present.

## Resuming Training

 When `spec["meta"]["resume"]` is `True` and a previous `train_df` file exists at the path returned by `util.get_session_df_path(spec, 'train')`, `MetricsTracker.__init__` reloads it and calls `env.load(self.train_df)` to restore the environment clock state [slm_lab/agent/__init__.py166-171](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py#L166-L171) This allows interrupted training runs to continue from the last checkpoint without losing metrics history.

 
---

 
## Rigorous Eval Mode

 When `spec["meta"]["rigorous_eval"]` is `True`, `eval_df` is initialized as a separate copy of `train_df` [slm_lab/agent/__init__.py174-177](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py#L174-L177) This means training and evaluation checkpoints are tracked independently.

 When `rigorous_eval` is `False` (the default), `eval_df` and `train_df` are the same object, and the final `analysis.analyze_session` call at session close uses the shared DataFrame for both modes.

 `Session.run` always calls `analysis.analyze_session` on `agent.mt.eval_df` [slm_lab/experiment/control.py141](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/control.py#L141-L141) when producing the final session metrics.
