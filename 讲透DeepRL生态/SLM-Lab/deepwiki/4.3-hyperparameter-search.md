  This page covers the hyperparameter search system in SLM Lab: how search experiments are launched, how the search space is specified in spec files, how Ray Tune orchestrates and potentially prunes trials, and how results are gathered and stored afterward.

 For the broader experiment hierarchy (Experiment, Trial, Session), see [4.1](https://github.com/kengz/SLM-Lab/blob/d3128a8a/4.1) For metrics computation, see [4.2](https://github.com/kengz/SLM-Lab/blob/d3128a8a/4.2) For spec file structure and the `search` block schema, see [7.1](https://github.com/kengz/SLM-Lab/blob/d3128a8a/7.1)

## Overview

 When the lab mode is `search`, the `Experiment` class delegates to the `search` module (`slm_lab/experiment/search.py`), which uses [Ray Tune](https://docs.ray.io/en/latest/tune/index.html) with an Optuna search algorithm to sample hyperparameter configurations and run each one as a `Trial`. Optionally, an ASHA (Asynchronous HyperBand) scheduler is enabled to terminate underperforming trials early.

 The output of the search is a ranked `experiment_df` (sorted by `strength`) and, optionally, disk cleanup of low-performing trial model checkpoints.

## Entry Point: `Experiment.run()`

 The `Experiment` class in `slm_lab/experiment/control.py` is the only caller of the search module:

 [slm_lab/experiment/control.py228-235](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/control.py#L228-L235)

 
```
def run(self):
    trial_data_dict = search.run_ray_search(self.spec)
    experiment_df = analysis.analyze_experiment(self.spec, trial_data_dict)
    if self.keep_trials != -1:
        search.cleanup_trial_models(self.spec, experiment_df, keep_top_n=self.keep_trials)
    self.close()
    return experiment_df
```

 `keep_trials` defaults to `3`. Set it to `-1` to skip cleanup.

## Defining the Search Space in Spec Files

 The `search` block in a spec file specifies which parameters to vary and how. The format is:

 
```
"search": {
    "<dot.path.to.param>__<space_type>": [args]
}
```

 `build_param_space` in `slm_lab/experiment/search.py` reads this block, flattens it (using `util.flatten_dict`), splits each key on `__` to get the path and distribution type, and calls the corresponding `ray.tune` function.

 [slm_lab/experiment/search.py39-77](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/search.py#L39-L77)

 
### Distribution Types

 
| Spec key suffix | Ray Tune function | Args format | Description |
|---|---|---|---|
| uniform | tune.uniform | [low, high] | Float uniformly in [low, high] |
| loguniform | tune.loguniform | [low, high] | Float in log space |
| quniform | tune.quniform | [low, high, q] | Uniform, rounded to multiples of q |
| qloguniform | tune.qloguniform | [low, high, q] | Log-uniform, rounded |
| randint | tune.randint | [low, high] | Integer uniformly in [low, high) |
| lograndint | tune.lograndint | [low, high] | Integer in log space |
| randn | tune.randn | [mean, sd] | Float from normal distribution |
| choice | tune.choice | [v1, v2, ...] | Uniform sample from discrete list |

 
> **Note on `choice`:** The full list `[v1, v2, ...]` is passed as a single list argument to `tune.choice`, not unpacked. All other distributions unpack their args list with `*`.

 
> **`grid_search` is not supported** with the Optuna backend. Use `choice` instead.

## ASHA Early Stopping Scheduler

 ASHA (Asynchronous HyperBand) terminates low-performing trials early based on intermediate metric reports, saving compute for promising trials.

### ASHA and `max_session`

 ASHA requires periodic metric reporting during training, which means it only works with **single-session trials** (one session per trial). If `meta.max_session > 1` and `search_scheduler` is set, `run_ray_search` automatically overrides `max_session` to `1` and logs a warning.

### `inject_config`

 `inject_config` does three things:

 
 - Deep-copies `base_spec` and removes the `search` block (so the spec is clean for the trial).
 - Reads the Ray Tune trial directory name to determine the trial index, then sets `spec["meta"]["trial"]` appropriately so that `spec_util.tick(spec, "trial")` advances to the correct 0-based index.
 - Iterates over the sampled `config` dict and uses `pydash.set_` to write each value into the spec at its dot-path location.

## Extracting Trial Results

 After `tuner.fit()` returns a `tune.ResultGrid`, `extract_trial_results` maps each Ray Tune result to the trial metrics saved to disk by the `Trial`.

 [slm_lab/experiment/search.py143-164](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/search.py#L143-L164)

 It looks for files in two naming patterns (accounting for single-session vs. multi-session trials):

 
 - `{info_dir}/{spec_name}_t{i}_trial_metrics_scalar.json`
 - `{info_dir}/{spec_name}_t{i}_s0_trial_metrics_scalar.json`
 
 Each entry in the returned `trial_data_dict` is a merge of `result.config` (the hyperparameter values) and the trial metrics scalars (strength, efficiency, stability, consistency, etc.). This dict is passed to `analysis.analyze_experiment` to produce the final `experiment_df`.

## Model Cleanup: `cleanup_trial_models`

 After the search, `Experiment.run()` calls `cleanup_trial_models` to reduce disk usage by deleting model files for trials not in the top-N.

 [slm_lab/experiment/search.py239-278](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/search.py#L239-L278)

 
### Behavior

 
 - Sorts `experiment_df` by `total_reward_ma` descending.
 - Identifies the set of trial indices to keep (`keep_top_n`, default `3`).
 - Scans the `{predir}/model/` directory for `.pt` files matching `*_t{idx}_*` for each removed trial index.
 - Deletes matched files and logs the count.
 
 To disable cleanup entirely, pass `keep_trials=-1` to `Experiment.__init__`.

 
### File Patterns

 
```
data/{spec_name}_{ts}/model/{spec_name}_t{idx}_*.pt
data/{spec_name}_{ts}/model/{spec_name}_t{idx}_s{s}_*.pt
```

 Both patterns (with and without session suffix) are matched by the glob `*_t{trial_idx}_*.pt`.
