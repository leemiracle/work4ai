## Purpose

 The memory module is responsible for storing agent experiences collected during environment interaction and providing batches of those experiences to the algorithm for training. Memory sits between the environment loop and the training step: the agent calls `memory.update()` after each environment step, and the algorithm calls `memory.sample()` when it is ready to train.

 Different RL algorithm families have different requirements for how experiences are stored and retrieved. Value-based off-policy methods (DQN, SAC) use a large circular buffer and sample randomly. Policy gradient on-policy methods (REINFORCE, A2C, PPO, SARSA) require that only the most recently collected data is used for training. The memory module encapsulates these differences behind a common interface.

## Abstract Base Class: `Memory`

 The `Memory` abstract base class is defined in [slm_lab/agent/memory/base.py7-33](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/memory/base.py#L7-L33) It declares three abstract methods that all subclasses must implement:

 
| Method | Signature | Description |
|---|---|---|
| reset | reset() | Fully clears all stored experiences and reinitializes tracking variables. |
| update | update(state, action, reward, next_state, done, terminated, truncated) | Accepts a single timestep of experience. For vectorized environments, implementations handle batched inputs internally. |
| sample | sample() | Returns a dict of experience arrays to be consumed by the algorithm for a training step. |

 The constructor stores `memory_spec` (the raw spec dict) and `agent` (a reference to the owning agent) as instance attributes, and declares the list of `data_keys` that will be stored.

 The standard `data_keys` across all implementations are:

 
```
['states', 'actions', 'rewards', 'next_states', 'dones', 'terminateds', 'truncateds']
```

 `PrioritizedReplay` appends `'priorities'` to this list.

## Memory Types and Algorithm Pairing

 Each memory class is designed for a specific class of algorithm. The correct memory type is selected via the `"name"` field in the `memory` block of the spec.

 
| Memory Class | name in spec | Storage Style | Cleared on Sample | Typical Algorithm |
|---|---|---|---|---|
| Replay | "Replay" | Circular buffer, off-policy | No | DQN, DoubleDQN, SAC |
| PrioritizedReplay | "PrioritizedReplay" | Circular buffer + SumTree | No | DQN with PER |
| OnPolicyReplay | "OnPolicyReplay" | Episode-nested lists | Yes | REINFORCE |
| OnPolicyBatchReplay | "OnPolicyBatchReplay" | Flat lists | Yes | SARSA, A2C, PPO, REINFORCE |
| OnPolicyCrossEntropy | "OnPolicyCrossEntropy" | Episode-nested lists + filter | Yes | REINFORCE with CEM |

## `to_train` Signaling

 Memory implementations are responsible for signaling the algorithm when it is time to train by setting `algorithm.to_train = 1`. The trigger logic differs by memory type:

 
 - **`Replay` / `PrioritizedReplay`**: In `add_experience()`, sets `to_train` when `seen_size > training_start_step` and `head % training_frequency == 0`. Uses `head` and `seen_size` counters rather than the clock, because vectorized environments step the clock by `num_envs` per tick. See [slm_lab/agent/memory/replay.py168-173](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/memory/replay.py#L168-L173)
 - **`OnPolicyReplay`**: Sets `to_train = 1` when the number of completed episodes stored equals `algorithm.training_frequency`. See [slm_lab/agent/memory/onpolicy.py78-80](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/memory/onpolicy.py#L78-L80)
 - **`OnPolicyBatchReplay`**: Sets `to_train = 1` when the number of stored experiences equals `algorithm.training_frequency`. See [slm_lab/agent/memory/onpolicy.py130-131](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/memory/onpolicy.py#L130-L131)
 
 After the training step, the algorithm resets `to_train` to 0.

## Key Design Properties

 
| Property | Replay | OnPolicyReplay | OnPolicyBatchReplay |
|---|---|---|---|
| is_episodic | False | True | False |
| Episode nesting in batch | No | Yes (nested lists) | No (flat lists) |
| Memory cleared after sample() | No | Yes | Yes |
| max_size enforced | Yes (circular) | No (grows per episode) | No (grows per step) |
| Supports use_cer | Yes | No | No |
| Supports priorities | Only PrioritizedReplay subclass | No | No |
