## Return Generation

 Before metrics can be computed, the agent must be evaluated to obtain episode returns.

 
### `gen_return`

 [slm_lab/experiment/analysis.py26-41](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/analysis.py#L26-L41)

 Runs a full evaluation loop using a vectorized eval environment (`eval_env`). The agent's environment reference is temporarily swapped so `agent.act` reads from the eval env. Every environment slot in the vector env runs until `done`, and the mean of `env.total_reward` across slots is returned.

 
```
gen_return(agent, env) -> float
  swap agent.env = env
  reset env, loop until all vec slots done
  return mean(env.total_reward)
```

 
### `gen_avg_return`

 [slm_lab/experiment/analysis.py43-51](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/analysis.py#L43-L51)

 Wraps `gen_return` with two additional behaviors:

 
 - Enters `eval` lab mode via `util.ctx_lab_mode('eval')`, which causes `algorithm.update()` to set exploration variables (e.g., epsilon, tau) to their terminal values.
 - Disables gradient computation with `torch.no_grad()`.
 - After return, calls `algorithm.update()` again to restore training-mode exploration variables.
 
 
```
gen_avg_return(agent, env) -> float
  with ctx_lab_mode('eval'): algorithm.update()   # set explore_var to end_val
  with torch.no_grad():      gen_return(agent, env)
  algorithm.update()                               # restore training explore_var
```

## Metrics Definitions

 The standard metric columns are defined at module level:

 [slm_lab/experiment/analysis.py13-19](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/analysis.py#L13-L19)

 
```

```

 Each metric is computed from a series of checkpoint values, where each checkpoint corresponds to a log/eval interval during training.

 
### Strength

 [slm_lab/experiment/analysis.py56-66](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/analysis.py#L56-L66)

 Measures how much better the agent performs than a random policy.

 $$\text{str} = \frac{1}{N} \sum_{i=0}^{N} \overline{R}*i - \overline{R}*{\text{rand}}$$

 
 - `mean_returns`: series of mean returns at each checkpoint (from `session_df['total_reward']`)
 - `mean_rand_returns`: the random baseline mean from `random_baseline.get_random_baseline(env_name)`
 - Returns scalar `str_` and per-checkpoint series `local_strs`
 - `max_strength` = `local_strs.max()`, `final_strength` = `local_strs.iloc[-1]`
 
 
### Efficiency

 [slm_lab/experiment/analysis.py69-81](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/analysis.py#L69-L81)

 Measures how quickly strength is gained relative to time spent.

 $$\text{eff} = \frac{\sum_{i} \frac{1}{t_i} \cdot \text{str}*i}{\sum*{i} \frac{1}{t_i}}$$

 Two variants are computed:

 
 - **sample_efficiency**: `ts = frames`
 - **training_efficiency**: `ts = opt_steps`
 
 Infinite ratios (from `t=0` at the first checkpoint) are dropped before summing.

 
### Stability

 [slm_lab/experiment/analysis.py84-98](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/analysis.py#L84-L98)

 Measures how monotonically strength increases (penalizes drops).

 $$\text{sta} = 1 - \left| \frac{\sum_{i} \min(\text{str}_{i+1} - \text{str}*i,\ 0)}{\sum*{i} \text{str}_i} \right|$$

 Only negative diffs (drops in strength) contribute to the penalty. A perfectly non-decreasing strength curve yields `sta = 1.0`.

 
### Consistency

 [slm_lab/experiment/analysis.py101-111](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/analysis.py#L101-L111)

 Measures agreement across sessions within a trial — a trial-level metric only.

 $$\text{con} = 1 - \frac{2 \sum_{i} \text{std}*j(\text{str}*{i,j})}{\sum_{i} \text{avg}*j(\text{str}*{i,j})}$$

 `local_strs_list` is a list of `local_strs` series, one per session. The calculation uses `util.calc_srs_mean_std` which truncates series to the minimum length before computing per-step mean and std.

 
### Summary Table

 
| Metric | Level | Formula basis | Range |
|---|---|---|---|
| strength | session, trial | mean of (returns − random baseline) | unbounded |
| max_strength | session, trial | max of local_strs | unbounded |
| final_strength | session, trial | last value of local_strs | unbounded |
| sample_efficiency | session, trial | strength weighted by 1/frame | [0, ∞) |
| training_efficiency | session, trial | strength weighted by 1/opt_step | [0, ∞) |
| stability | session, trial | penalizes drops in strength | (-∞, 1] |
| consistency | trial only | cross-session std of strength | (-∞, 1] |
| total_reward_ma | session, trial | rolling mean of last 100 rewards | environment-dependent |

## Session Analysis

 
### `calc_session_metrics`

 [slm_lab/experiment/analysis.py119-184](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/analysis.py#L119-L184)

 Takes a `session_df` DataFrame (columns: `total_reward`, `frame`, `opt_step`) and computes all scalar and local metrics for a single session.

 **Input:** `session_df` rows correspond to evaluation checkpoints (written by `MetricsTracker.ckpt()`).

 **Output structure:**

 
```
{
  'scalar': {
    'total_reward_ma': float,
    'strength': float,
    'max_strength': float,
    'final_strength': float,
    'sample_efficiency': float,
    'training_efficiency': float,
    'stability': float,
  },
  'local': {
    'mean_returns': Series,
    'strengths': Series,
    'sample_efficiencies': Series,
    'training_efficiencies': Series,
    'stabilities': Series,
    'frames': Series,
    'opt_steps': Series,
  }
}
```

 If `info_prepath` is provided, saves:

 
 - `{info_prepath}_session_metrics_{df_mode}.json`
 - `{info_prepath}_session_metrics_scalar_{df_mode}.json`
 
 The `total_reward_ma` uses the last `min(len, PLOT_MA_WINDOW)` rows, where `PLOT_MA_WINDOW = 100` (from `viz.py`).

 
### `analyze_session`

 [slm_lab/experiment/analysis.py264-276](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/analysis.py#L264-L276)

 The public interface called by `Session.run()` and `Session.try_ckpt()`:

 
 - Copies `session_df` to avoid mutation.
 - Writes `session_df` to disk via `util.write(session_df, util.get_session_df_path(session_spec, df_mode))`.
 - Calls `calc_session_metrics`.
 - If `plot=True`, calls `viz.plot_session` twice: once raw, once with moving-average (`ma=True`).
 
 **Call sites:**

 
 - `Session.run()` → `analyze_session(..., eval_df, 'eval')` — final session analysis
 - `Session.try_ckpt()` → `analyze_session(..., train_df, 'train', plot=True)` — periodic checkpoint analysis

## Trial Analysis

 
### `calc_trial_metrics`

 [slm_lab/experiment/analysis.py187-242](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/analysis.py#L187-L242)

 Aggregates session metrics from multiple sessions into trial-level metrics.

 **Input:** `session_metrics_list` — a list of dicts, one per session, each with `scalar` and `local` sub-dicts.

 **Computation:**

 
 - Scalar metrics: computed as `mean` across sessions via `pd.DataFrame(scalar_list).mean()`.
 - `consistency`: computed from the list of `local_strs` series using `calc_consistency`.
 - Local series: collected into lists for trial-level plotting (mean ± std envelopes).
 
 **Output structure** matches session metrics but adds `consistency` and `frame` to scalars.

 Saves to:

 
 - `{info_prepath}_trial_metrics.json`
 - `{info_prepath}_trial_metrics_scalar.json`
 - `{info_prepath.replace("info/", "")}_trial_metrics_scalar.json` (top-level copy)
 
 
### `analyze_trial`

 [slm_lab/experiment/analysis.py279-301](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/experiment/analysis.py#L279-L301)

 Public interface called by `Trial.run()`. If `session_metrics_list` is not passed, it loads session metric files from disk using glob:

 
```
{abs_info_prepath}_s*_session_metrics_train.json
```

 This fallback enables offline re-analysis. After computing trial metrics, calls `viz.plot_trial` twice (raw and MA).

 A guard at the top detects if a session spec was accidentally passed instead of a trial spec (i.e., `meta.session >= 0`) and corrects the prepath accordingly.

## MetricsTracker and Checkpoint Integration

 `MetricsTracker` (in `slm_lab/agent/__init__.py`) accumulates the per-step data that `analyze_session` consumes.

 **Key methods:**

 
| Method | Called from | Purpose |
|---|---|---|
| ckpt(env, df_mode) | Session.try_ckpt() | Appends one row to train_df or eval_df; computes total_reward_ma |
| calc_log_metrics(spec, df_mode) | Session.try_ckpt() | Calls analyze_session(..., plot=False); stores scalar metrics for Ray Tune reporting |
| log_summary(df_mode) | Session.try_ckpt() | Logs the last row of train_df/eval_df to the logger |

## Retro Analysis

 `slm_lab/experiment/retro_analysis.py` provides functions to re-run the full analysis pipeline on an existing experiment directory without re-training.

 **Entry point:** `retro_analyze(predir)` — callable via `slm-retro <data_dir>`.

 **Execution order:**

 
```

```

 The retro functions reuse the same `analyze_session`, `analyze_trial`, `analyze_experiment` functions as the live training path. The only difference is data is loaded from disk rather than passed in memory.

 **Use cases:**

 
 - Regenerating plots after a `viz.py` change.
 - Recomputing metrics after updating the random baseline.
 - Recovering analysis data from a failed or interrupted experiment.
