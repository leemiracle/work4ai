  This document provides a complete field-by-field reference for the SLM Lab spec format: the JSON (or YAML) configuration files that drive every subsystem from agent hyperparameters to environment setup to search space definition. It also documents the `spec_util` API functions that load, validate, mutate, and persist specs.

 For an overview of how specs fit into the broader experiment pipeline, see [Configuration and Spec Files](https://deepwiki.com/kengz/SLM-Lab/7-configuration-and-spec-files). For descriptions of the bundled benchmark spec files, see [Benchmark Specifications](https://deepwiki.com/kengz/SLM-Lab/7.2-benchmark-specifications).

## `agent` Block

 The `agent` block identifies the agent by name and contains three sub-blocks for algorithm, memory, and network configuration.

 
| Field | Type | Required | Description |
|---|---|---|---|
| name | string | Yes | Human-readable agent label (e.g. "PPO") |
| algorithm | dict | Yes | Algorithm class name and hyperparameters |
| memory | dict | Yes | Memory class name and buffer parameters |
| net | dict | Yes | Network architecture and training parameters |

 Sources: [slm_lab/spec/spec_util.py22-26](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/spec/spec_util.py#L22-L26) [slm_lab/agent/__init__.py38-71](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/__init__.py#L38-L71)

### `agent.algorithm` Sub-block

 The `name` field selects the algorithm class from `slm_lab/agent/algorithm/`. All other fields are read directly by that class's `__init__` or `init_algorithm_params`.

 **Common fields across all algorithms:**

 
| Field | Type | Description |
|---|---|---|
| name | string | Class name: PPO, ActorCritic, REINFORCE, DQN, DoubleDQN, SARSA, SoftActorCritic |
| action_pdtype | string | Action distribution type: "default", "Categorical", "Normal", "GumbelSoftmax" |
| action_policy | string | Policy function: "default", "epsilon_greedy", "boltzmann" |
| explore_var_spec | dict or null | Decay spec for exploration variable (ε or τ); see Decay Spec Structure |
| gamma | float | Discount factor |
| training_frequency | int | Steps between training calls |
| training_start_step | int | Minimum steps collected before first training |
| training_iter | int | Training iterations per call |
| training_batch_iter | int | Minibatch iterations per training iteration |

 **PPO-specific fields** (from `slm_lab/spec/demo.json`):

 
| Field | Type | Description |
|---|---|---|
| lam | float | GAE λ for advantage estimation |
| clip_eps_spec | dict | Decay spec for PPO clipping ε |
| entropy_coef_spec | dict | Decay spec for entropy bonus coefficient |
| val_loss_coef | float | Weight for value loss relative to policy loss |
| clip_val_loss | bool | Whether to clip the value function loss |
| time_horizon | int | Rollout length before each update |
| minibatch_size | int | Minibatch size for PPO epochs |
| training_epoch | int | PPO update epochs per rollout |

### `agent.net` Sub-block

 The `type` field selects the network class from `slm_lab/agent/net/`. The remaining fields configure architecture and training.

 
| Field | Type | Description |
|---|---|---|
| type | string | MLPNet, HydraMLPNet, DuelingMLPNet, ConvNet, DuelingConvNet, RecurrentNet |
| shared | bool | Share weights between actor and critic heads |
| hid_layers | list[int] | Hidden layer sizes, e.g. [64, 64] |
| hid_layers_activation | string | Activation function: "relu", "tanh", "sigmoid" |
| clip_grad_val | float or null | Gradient norm clipping threshold; null disables clipping |
| use_same_optim | bool | Apply a single optim_spec to all network heads |
| loss_spec | dict | Loss function spec: {"name": "MSELoss"} or {"name": "SmoothL1Loss"} |
| optim_spec | dict | Optimizer spec: {"name": "Adam", "lr": 0.001} |
| lr_scheduler_spec | dict or null | LR scheduler spec: {"name": "StepLR", "step_size": 1000} |
| gpu | string or bool | "auto" (use GPU if available), true, or false |

 **For ConvNet / DuelingConvNet:**

 
| Field | Type | Description |
|---|---|---|
| conv_hid_layers | list | Conv layer specs: [[out_ch, kernel, stride, padding], ...] |
| fc_hid_layers | list[int] | Fully connected layers after conv |

 **For RecurrentNet:**

 
| Field | Type | Description |
|---|---|---|
| rnn_hidden_size | int | RNN hidden state size |
| rnn_num_layers | int | Number of RNN layers |

## `env` Block

 The `env` block is consumed by `make_env()` in `slm_lab/env/__init__.py`. The fields `name`, `max_t`, and `max_frame` are formally validated by `SPEC_FORMAT`.

 
| Field | Type | Required | Description |
|---|---|---|---|
| name | string | Yes | Gymnasium environment ID, e.g. "CartPole-v1", "Hopper-v5", "ALE/Pong-v5" |
| max_t | int, float, or null | Yes | Max timesteps per episode; null uses the environment's own limit |
| max_frame | int or float | Yes | Total training frames; supports scientific notation e.g. 3e6 |
| num_envs | int | No | Number of parallel environments for vectorized training; default 1 |

## `meta` Block

 The `meta` block has two layers: fields specified by the user in the JSON file and fields injected at runtime by `extend_meta_spec` and `tick`.

 
### User-specified fields

 
| Field | Type | Description |
|---|---|---|
| max_session | int | Number of repeated sessions per trial |
| max_trial | int or null | Number of trials for hyperparameter search; null or 1 for single trial |
| distributed | bool or string | false for standard training; "synced" for A3C/Hogwild distributed training |
| log_frequency | int | Frames between training log checkpoints |
| eval_frequency | int | Frames between evaluation checkpoints |
| rigorous_eval | int or bool | Use a separate eval environment; default 0 (false) |
| search_scheduler | dict or null | ASHA scheduler config for early stopping; e.g. {"grace_period": 200000} |
| search_resources | dict | Per-trial Ray Tune resources; e.g. {"cpu": 2, "gpu": 0.5} |

 
### Runtime-injected fields

 These are added by `extend_meta_spec()` and `tick()` and should not be set in JSON files.

 
| Field | Injected by | Description |
|---|---|---|
| experiment_ts | extend_meta_spec | Timestamp string YYYY_MM_DD_HHMMSS for this run |
| experiment | extend_meta_spec / tick | Integer experiment index |
| trial | extend_meta_spec / tick | Integer trial index |
| session | extend_meta_spec / tick | Integer session index |
| resume | extend_meta_spec | True when resuming from a prior experiment_ts |
| git_sha | extend_meta_spec | Git SHA of the current commit |
| random_seed | extend_meta_spec | Reserved for reproducibility |
| cuda_offset | extend_meta_spec | From CUDA_OFFSET env var; offsets GPU selection |
| predir | tick | data/{spec_name}_{experiment_ts} |
| prepath | tick | Base path for all output files at this unit level |
| graph_prepath | tick | Path prefix for graph output files |
| info_prepath | tick | Path prefix for metrics JSON files |
| log_prepath | tick | Path prefix for log files |
| model_prepath | tick | Path prefix for saved model .pt files |

## `search` Block

 The `search` block defines the hyperparameter search space consumed by `build_param_space()` in `slm_lab/experiment/search.py`. It is only required when running an experiment with `max_trial > 1`.

 Each key in the `search` block uses the format `"{dot.path.to.field}__{space_type}"` where `dot.path.to.field` is the pydash-style path into the spec (e.g. `agent.algorithm.gamma`), and `space_type` is a Ray Tune sampling function.

 
### Supported space types

 
| space_type | Argument format | Description |
|---|---|---|
| uniform | [low, high] | Float uniform in [low, high] |
| loguniform | [low, high] | Float log-uniform in [low, high] |
| quniform | [low, high, q] | Uniform rounded to multiples of q |
| qloguniform | [low, high, q] | Log-uniform rounded to q |
| randn | [mean, sd] | Normal distribution |
| qrandn | [mean, sd, q] | Normal rounded to q |
| randint | [low, high] | Integer uniform in [low, high) |
| qrandint | [low, high, q] | Integer rounded to q |
| lograndint | [low, high] | Log-scale integer |
| qlograndint | [low, high, q] | Log-scale integer rounded to q |
| choice | [v1, v2, ...] | Uniform sample from a list of values |

## Decay Spec Structure

 Several algorithm fields use a decay spec dict to schedule values that change over training time. The structure is the same across all decay types.

 
| Field | Type | Description |
|---|---|---|
| name | string | Decay function: "no_decay", "linear_decay", "rate_decay", "periodic_decay" |
| start_val | float | Initial value |
| end_val | float | Final value |
| start_step | int | Frame at which decay begins |
| end_step | int | Frame at which decay ends |

 **Decay function behavior:**

 
| name | Description |
|---|---|
| no_decay | Constant start_val; end_val is ignored |
| linear_decay | Linearly interpolates from start_val to end_val over [start_step, end_step] |
| rate_decay | Exponential decay from start_val toward end_val |
| periodic_decay | Oscillates between start_val and end_val |

### `spec_util.tick`

 [slm_lab/spec/spec_util.py278-330](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/spec/spec_util.py#L278-L330)

 
```

```

 Advances the lab unit counter in `spec["meta"]` and injects file system paths. Must be called before constructing `Session`, `Trial`, or `Experiment`.

 
| unit | Effect |
|---|---|
| "experiment" | Increments meta.experiment; resets trial and session to -1; generates new experiment_ts |
| "trial" | Increments meta.trial; resets session to -1 |
| "session" | Increments meta.session; in enjoy mode, selects the best session by reward |

 After ticking, these keys are set in `meta`: `predir`, `prepath`, `graph_prepath`, `info_prepath`, `log_prepath`, `model_prepath`. Output directories are created on disk.
