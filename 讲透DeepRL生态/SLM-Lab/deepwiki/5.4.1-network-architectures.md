  This page documents the neural network classes available in SLM Lab: `MLPNet`, `HydraMLPNet`, `DuelingMLPNet`, `ConvNet`, `DuelingConvNet`, and `RecurrentNet`. It covers how each is constructed from `net_spec` fields, how the forward pass works, and which algorithms use which architecture.

 For information on the utility functions that support these networks (layer builders, optimizers, weight initialization, target net updates), see [Network Utilities](https://deepwiki.com/kengz/SLM-Lab/5.4.2-network-utilities). For how `net_spec` is written in spec files, see [Spec Format Reference](https://deepwiki.com/kengz/SLM-Lab/7.1-spec-format-reference).

## Common net_spec Fields

 All network types share a core set of `net_spec` fields. Additional type-specific fields are documented in each section below.

 
| Field | Type | Default | Description |
|---|---|---|---|
| type | str | required | Network class name (e.g. "MLPNet") |
| shared | bool | — | Whether actor and critic share this net (used by algorithms) |
| hid_layers_activation | str | — | Activation for hidden layers (e.g. "relu", "tanh") |
| out_layer_activation | str or null | null | Activation for output layer(s) |
| init_fn | str or null | null | Weight init (e.g. "xavier_uniform_", "orthogonal_") |
| clip_grad_val | float or null | null | Gradient norm clipping value |
| loss_spec | dict | {"name": "MSELoss"} | Loss function config |
| optim_spec | dict | {"name": "Adam"} | Optimizer config |
| lr_scheduler_spec | dict or null | null | LR scheduler config |
| update_type | str | "replace" | Target net update: "replace" or "polyak" |
| update_frequency | int | 1 | Timesteps between target net hard-replace updates |
| polyak_coef | float | 0.0 | Old-weight ratio for polyak update |
| gpu | bool | false | Move network to GPU if available |

## MLPNet

 `MLPNet` is a generic feedforward network. It is the default architecture for low-dimensional state inputs.

 
### Structure

 **MLPNet data flow**

 
```

```

 Sources: [slm_lab/agent/net/mlp.py101-113](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/mlp.py#L101-L113)

 
 - `self.model`: a `nn.Sequential` of `nn.Linear` + activation layers, built by `build_fc_model([in_dim] + hid_layers, hid_layers_activation)`.
 - `self.tails`: the output head(s), built by `build_tails(hid_layers[-1], out_dim, out_layer_activation)`. See [Output Head Construction](https://github.com/kengz/SLM-Lab/blob/d3128a8a/Output Head Construction) below.
 - `self.log_std`: an optional `nn.Parameter` if `log_std_init` is set.
 
 
### net_spec Fields

 
| Field | Description |
|---|---|
| hid_layers | List of hidden layer widths, e.g. [256, 128] |
| log_std_init | If set, creates a state-independent log_std parameter (CleanRL-style continuous control) |
| actor_init_std | Std for orthogonal reinit of actor output head (e.g. 0.01) |
| critic_init_std | Std for orthogonal reinit of critic output head (e.g. 1.0) |

## DuelingMLPNet

 `DuelingMLPNet` extends `MLPNet` for Q-learning. It splits the final body representation into a state-value stream V(s) and an advantage stream A(s, a), then combines them via `calc_q_value_logits`.

 Reference: [Dueling Network Architectures (Wang et al., 2016)](http://proceedings.mlr.press/v48/wangf16.pdf)

 
### Structure

 **DuelingMLPNet data flow**

 
```

```

 Sources: [slm_lab/agent/net/mlp.py301-349](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/mlp.py#L301-L349)

 
 - `self.model_body`: shared hidden layers.
 - `self.v`: linear layer producing a scalar state value.
 - `self.adv`: linear layer producing per-action advantages.
 - `calc_q_value_logits` (from `math_util`) combines them as: `Q = V + A - mean(A)`.
 - `out_dim` must be an integer (action count).
 
 **Used by:** `DQN`, `DoubleDQN` when `type` is set to `DuelingMLPNet`.

 Sources: [slm_lab/agent/net/mlp.py269-349](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/mlp.py#L269-L349)

 `RecurrentNet` processes sequences of states using an RNN cell. The input is expected as `(batch_size, seq_len, state_dim)`. When a 2D input `(batch_size, state_dim)` is received, the network auto-expands it by repeating the state `seq_len` times.

## Output Head Construction

 All network types delegate output head construction to two shared utilities in `net_util`:

 
### `build_tails`

 [slm_lab/agent/net/net_util.py456-473](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L456-L473)

 Determines the structure of output heads based on `out_dim`:

 
| out_dim type | Result |
|---|---|
| int | Single nn.Sequential (one linear layer), log_std = None |
| [action_dim, action_dim] + log_std_init set | Single nn.Sequential for mean, nn.Parameter for log_std |
| list of different ints | nn.ModuleList of separate nn.Sequential tails |

 
### `forward_tails`

 [slm_lab/agent/net/net_util.py476-480](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L476-L480)

 Applies the tails built above during the forward pass:

 
| Tail type | Returns |
|---|---|
| nn.ModuleList | [t(x) for t in tails] — list of tensors |
| Single nn.Sequential + log_std | [tails(x), log_std.expand_as(tails(x))] |
| Single nn.Sequential | tails(x) — single tensor |

 This means that for actor-critic networks with `out_dim = [action_dim, 1]`, the forward pass returns `[action_logits, value]` as a list.

 Sources: [slm_lab/agent/net/net_util.py456-480](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L456-L480)

## Shared vs. Separate Networks

 For actor-critic algorithms (A2C, PPO, A3C, SIL), the `shared` field in `net_spec` determines whether actor and critic share a single network instance:

 
 - **`"shared": true`**: One network with multiple output tails via `build_tails`. The `out_dim` passed in will be a list like `[action_dim, 1]`, so `tails` becomes an `nn.ModuleList`.
 - **`"shared": false`**: Two separate network instances: one for the actor, one for the critic. Each has a single scalar or vector output.
 
 For `HydraMLPNet`, multiple inputs (from multiple environments) are processed by separate heads before joining a shared body.

 Sources: [slm_lab/agent/net/mlp.py10-113](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/mlp.py#L10-L113) [slm_lab/agent/net/net_util.py456-480](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L456-L480)

## Weight Initialization

 All networks call `net_util.init_layers(self, self.init_fn)` after construction. The `init_fn` field maps to a `torch.nn.init.*` function name:

 
| init_fn value | Applied to |
|---|---|
| "xavier_uniform_" | Conv, Linear layers |
| "xavier_normal_" | Conv, Linear layers |
| "kaiming_uniform_" | Conv, Linear (relu/leaky_relu only) |
| "orthogonal_" | Conv, Linear, GRU weights |
| null | No initialization applied |

 For shared actor-critic networks, `net_util.init_tails` can re-initialize the output heads with different standard deviations via `actor_init_std` and `critic_init_std`. This follows the CleanRL convention of using `std=0.01` for the actor head and `std=1.0` for the critic head.

 Sources: [slm_lab/agent/net/net_util.py137-223](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L137-L223)
