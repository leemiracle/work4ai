## Overview

 Standard replay memory samples experiences with uniform probability. Prioritized Experience Replay (PER), based on [Schaul et al. 2015](https://arxiv.org/pdf/1511.05952.pdf), instead samples experiences proportional to a priority value — typically derived from the TD error — so that experiences the agent finds more surprising are replayed more frequently.

 The implementation consists of two classes:

 
| Class | File | Role |
|---|---|---|
| SumTree | slm_lab/agent/memory/prioritized.py7-81 | Binary tree for O(log n) priority storage and proportional sampling |
| PrioritizedReplay | slm_lab/agent/memory/prioritized.py84-183 | Extends Replay with priority-weighted sampling and update logic |

 
---

 
## SumTree Data Structure

 `SumTree` is a complete binary tree where each leaf node stores the priority of one experience, and each internal node stores the sum of all priorities in its subtree. The root therefore always holds the total priority sum.

 **Tree layout for `capacity = N`:**

 
 - `tree` array of size `2N - 1` 
 - Indices `0` to `N-2`: internal nodes (sums)
 - Indices `N-1` to `2N-2`: leaf nodes (individual priorities)
 - `indices` array of size `N`: maps each leaf slot to the corresponding experience buffer index
 - `write` integer: circular write pointer (0 to N-1)

### SumTree Methods

 
| Method | Signature | Description |
|---|---|---|
| total | total() | Returns tree[0], the total priority sum |
| add | add(p, index) | Writes priority p at current write position, stores index in indices, then calls update |
| update | update(idx, p) | Sets tree[idx] = p, propagates the delta to all ancestors via _propagate |
| get | get(s) | Traverses from root to find the leaf satisfying s, returns (tree_idx, priority, experience_idx) |
| _propagate | _propagate(idx, change) | Recursively adds change to all parent nodes up to the root |
| _retrieve | _retrieve(idx, s) | Recursively descends the tree: goes left if s <= tree[left], otherwise subtracts left and goes right |

## Priority Calculation

 New experiences are inserted with a large default error (`error=100000`) to ensure every experience is sampled at least once before its real TD error is known.

 The priority formula applied by `get_priority` is:

 
```
priority = (|error| + epsilon)^alpha
```

 
 - `epsilon`: a small non-negative constant added to prevent zero probability. Stored as a 1-element `ndarray`.
 - `alpha`: exponent controlling the degree of prioritization. `alpha=0` recovers uniform sampling; `alpha=1` gives full proportional prioritization. Stored as a 1-element `ndarray`.
 
 [slm_lab/agent/memory/prioritized.py145-147](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/memory/prioritized.py#L145-L147)

 Both parameters are read from `memory_spec` and converted to numpy arrays of shape `(1,)` so that `.squeeze()` in `get_priority` correctly handles both scalar and array inputs.

 [slm_lab/agent/memory/prioritized.py117-118](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/memory/prioritized.py#L117-L118)

## Proportional Sampling

 `sample_idxs(batch_size)` selects `batch_size` experience indices proportional to their stored priorities using the SumTree.

 **Sampling procedure:**

 For each of the `batch_size` slots:

 
 - Draw a uniform random number `s` in `[0, tree.total()]`
 - Call `tree.get(s)`, which traverses the tree to find the leaf whose cumulative priority range contains `s`
 - Record the returned `tree_idx` (for later priority update) and the `experience_idx` (for fetching data)

## Adding an Experience

 `add_experience` delegates all base storage to `Replay.add_experience` (circular buffer write, `head` update, `ns_buffer` update) and then computes and records the priority:

 
```
super().add_experience(...)
priority = self.get_priority(error=100000)
self.priorities[self.head] = priority
self.tree.add(priority, self.head)
```

 [slm_lab/agent/memory/prioritized.py127-143](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/memory/prioritized.py#L127-L143)

 The `priorities` list mirrors the `states`, `actions`, etc. lists — same index space, same `max_size` capacity, same circular overwrite behavior. On `reset()`, a fresh `SumTree` is allocated and `priorities` is re-initialized to `[None] * max_size`.

## Updating Priorities After Training

 After each training step, the algorithm calls `memory.update_priorities(errors)` with an array of TD errors (one per sampled experience). This keeps the tree consistent with the latest network estimates.

 `update_priorities(errors)` [slm_lab/agent/memory/prioritized.py172-183](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/memory/prioritized.py#L172-L183):

 
 - Converts errors to priorities via `get_priority(errors)`
 - Updates `self.priorities[idx]` for each `batch_idx` (the flat buffer)
 - Calls `tree.update(tree_idx, p)` for each entry — which sets the leaf value and propagates the delta upward

## CER Interaction

 When `use_cer=True`, `sample_idxs` calls `apply_cer` (inherited from `Replay`) after performing the priority-weighted tree sampling. `apply_cer` replaces the last `num_new` indices in `batch_idxs` with the most recently added experience indices.

 Because these CER-inserted indices were not sampled from the `SumTree`, they have no corresponding `tree_idx`. The code handles this by setting the corresponding positions in `tree_idxs` to `-1`:

 [slm_lab/agent/memory/prioritized.py161-168](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/memory/prioritized.py#L161-L168)

 In `update_priorities`, any entry with `tree_idx == -1` is skipped — the priority in `self.priorities` is still updated (for consistency in the flat array), but `SumTree.update` is not called for those entries.

 [slm_lab/agent/memory/prioritized.py180-183](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/memory/prioritized.py#L180-L183)

 
| Scenario | tree_idx value | update_priorities behavior |
|---|---|---|
| Normal tree-sampled experience | >= 0 | Both self.priorities list and SumTree are updated |
| CER-injected experience | -1 | Only self.priorities list is updated; tree is skipped |

## Data Keys

 `PrioritizedReplay` extends the standard `Replay` `data_keys` by appending `'priorities'`. This means `sample()` (inherited from `Replay`) will include `priorities` in the returned batch dict.

 
```
data_keys = ['states', 'actions', 'rewards', 'next_states', 'dones',
             'terminateds', 'truncateds', 'priorities']
```

 [slm_lab/agent/memory/prioritized.py120](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/memory/prioritized.py#L120-L120)

 The `'priorities'` field in the batch allows the algorithm to compute importance-sampling weights if needed, though the current DQN implementation uses the priorities primarily to select which errors to feed back into `update_priorities`.
