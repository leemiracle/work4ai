### `venv_unpack(batch_tensor)`

 [slm_lab/lib/math_util.py45-56](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/lib/math_util.py#L45-L56)

 Collapses the `num_envs` dimension into the batch dimension:

 
 - **Scalar data** `(b, num_envs)` → `(b * num_envs,)` via `.view(-1)`
 - **Non-scalar data** `(b, num_envs, *shape)` → `(b * num_envs, *shape)` via `.view([-1] + shape[2:])`
 
 
### `venv_pack(batch_tensor, num_envs)`

 [slm_lab/lib/math_util.py35-42](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/lib/math_util.py#L35-L42)

 Reverses `venv_unpack`. Restores the `num_envs` dimension:

 
 - **Scalar data** `(b * num_envs,)` → `(b, num_envs)` via `.view(-1, num_envs)`
 - **Non-scalar data** `(b * num_envs, *shape)` → `(b, num_envs, *shape)` via `.view([-1, num_envs] + shape[1:])`

## Policy Gradient Calculations

 These four functions implement the core return and advantage estimators used by policy gradient algorithms. All operate on `torch.Tensor` objects to avoid unnecessary device transfers (e.g., GPU → CPU → GPU).

 
### The `terminateds` vs. `dones` Distinction

 
> **Critical:** All three return/advantage functions take a `terminateds` tensor, **not** a `dones` tensor.

 The difference matters when an episode ends due to a **time limit truncation** vs. a **true terminal state**:

 
| Signal | Meaning | Correct bootstrap behavior |
|---|---|---|
| dones | episode is over (truncation or termination) | zero out future returns (incorrect for truncation) |
| terminateds | episode ended by reaching a true terminal state | zero out future returns |
| truncated | episode ended by time limit | bootstrap from V(next_state), do not zero out |

 Using `dones` where `terminateds` is required causes value estimates to be incorrectly zeroed at truncation boundaries, leading to biased gradients.

 Sources: [slm_lab/lib/math_util.py62-120](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/lib/math_util.py#L62-L120)

### `calc_returns(rewards, terminateds, gamma)`

 [slm_lab/lib/math_util.py62-76](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/lib/math_util.py#L62-L76)

 Computes the **full Monte Carlo return** for each timestep over a complete rollout:

 
```
G_t = r_t + γ * G_{t+1} * (1 - terminated_t)
```

 The backward pass sets `future_ret = 0` at true terminations, but carries it forward through truncations.

 **Used by:** `REINFORCE`, `ActorCritic` (when n-step is not used).

 
---

 
### `calc_nstep_returns(rewards, terminateds, next_v_pred, gamma, n)`

 [slm_lab/lib/math_util.py79-94](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/lib/math_util.py#L79-L94)

 Computes **n-step bootstrapped returns** as described in Algorithm S3 of the A3C paper:

 
```
R^(n)_t = r_t + γ*r_{t+1} + ... + γ^(n-1)*r_{t+n-1} + γ^n * V(s_{t+n})
```

 `next_v_pred` is the value estimate at the state following the n-step window. Terminations within the window zero out the bootstrap contribution.

 **Used by:** `ActorCritic` with `n_step_returns = True`.

 
---

 
### `calc_gaes(rewards, terminateds, v_preds, gamma, lam)`

 [slm_lab/lib/math_util.py97-120](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/lib/math_util.py#L97-L120)

 Implements **Generalized Advantage Estimation (GAE)** from [Schulman et al., 2015](https://arxiv.org/pdf/1506.02438.pdf), equations 10 and 16.

 Requires `v_preds` of length `T + 1` (one value estimate per state, including the final next-state):

 
```
δ_t   = r_t + γ * V(s_{t+1}) * (1 - terminated_t) - V(s_t)
GAE_t = δ_t + (γλ) * (1 - terminated_t) * GAE_{t+1}
```

 Any standardization of the resulting advantages is done **outside** this function by the calling algorithm.

 **Used by:** `ActorCritic` with `use_gaes = True`, `PPO`.

 
---

 
### `calc_q_value_logits(state_value, raw_advantages)`

 [slm_lab/lib/math_util.py123-125](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/lib/math_util.py#L123-L125)

 Combines a scalar state value with per-action advantage estimates into Q-value logits for the **Dueling network** architecture:

 
```
Q(s, a) = V(s) + A(s, a) - mean_a[A(s, a)]
```

 The mean is subtracted to enforce the identifiability constraint that prevents the network from learning redundant V and A decompositions.

 **Used by:** `DuelingMLPNet`, `DuelingConvNet`.

## Decay Schedule Functions

 These four functions implement variable annealing schedules. They share a common signature and are consumed by `VarScheduler` in `policy_util` to decay exploration parameters (e.g., epsilon in epsilon-greedy, temperature in Boltzmann).

 
### Common Signature

 All decay functions accept:

 
| Parameter | Type | Description |
|---|---|---|
| start_val | float | Value at start_step |
| end_val | float | Minimum (floor) value |
| start_step | int | Step at which decay begins |
| end_step | int | Step at which decay reaches end_val |
| step | int | Current training step |

 Before `start_step`, all functions return `start_val`. After `end_step`, all return `end_val`.

 
---

 
### `no_decay`

 [slm_lab/lib/math_util.py130-132](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/lib/math_util.py#L130-L132)

 Returns `start_val` unconditionally. Used as a no-op placeholder to maintain API consistency when a parameter should not change.

 
---

 
### `linear_decay`

 [slm_lab/lib/math_util.py135-141](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/lib/math_util.py#L135-L141)

 Anneals linearly from `start_val` to `end_val`:

 
```
val = slope * (step - start_step) + start_val
slope = (end_val - start_val) / (end_step - start_step)
```

 Output is clamped to `end_val` from below.

 
---

 
### `rate_decay`

 [slm_lab/lib/math_util.py144-153](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/lib/math_util.py#L144-L153)

 Applies **exponential (compounding) decay** with a configurable `decay_rate` (default `0.9`) over `frequency` (default `20`) discrete decay intervals:

 
```
decay_step = (step - start_step) / step_per_decay
val = max(decay_rate^decay_step * start_val, end_val)
```

 The default settings divide the `[start_step, end_step]` window into 20 intervals, each multiplying the value by 0.9.

 
---

 
### `periodic_decay`

 [slm_lab/lib/math_util.py156-173](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/lib/math_util.py#L156-L173)

 A **linearly-decaying sinusoid** that oscillates while trending downward. The envelope decays over approximately 10 half-cycles within `[start_step, end_step]`:

 
```
val = end_val + 0.5 * (start_val - end_val) * (1 + cos(x)) * (1 - x / frequency)
```

 where `x` is the normalized step within the decay window. Output is clamped to `end_val`.
