## Overview

 `net_util` provides stateless helper functions consumed by every network class in `slm_lab/agent/net/`. It sits between the raw PyTorch API and the network constructors, centralizing recurring patterns like building fully-connected stacks, resolving string-based class names, initializing weights, and managing target network synchronization.

## Layer Construction

 
### `build_fc_model`

 [slm_lab/agent/net/net_util.py33-44](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L33-L44)

 Constructs an `nn.Sequential` fully-connected model from a list of dimension sizes. Adjacent pairs in `dims` define each `nn.Linear` layer. If `activation` is provided, an activation module is inserted after each linear layer except the last.

 
```
dims = [128, 64, 32]
→ Linear(128→64) → Activation → Linear(64→32) → Activation
```

 Called by every network class to build hidden bodies and tail layers.

 
### `get_nn_name`

 [slm_lab/agent/net/net_util.py47-52](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L47-L52)

 Case-insensitive lookup of a class name in `torch.nn.__dict__`. Used internally so that spec strings like `"relu"` or `"MSELoss"` resolve to the correct PyTorch class names (`ReLU`, `MSELoss`).

 
### `get_activation_fn`

 [slm_lab/agent/net/net_util.py55-58](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L55-L58)

 Instantiates an activation function by name using `get_nn_name`. Called by `build_fc_model` to insert activation layers.

 
### `build_tails` and `forward_tails`

 [slm_lab/agent/net/net_util.py456-480](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L456-L480)

 Handles the output head construction for all three output modes:

 
| out_dim type | Behavior | Returns |
|---|---|---|
| int | Single nn.Linear tail | (Sequential, None) |
| [action_dim, action_dim] with log_std_init set | State-independent log_std (CleanRL style) | (Sequential, nn.Parameter) |
| list | nn.ModuleList of separate tails | (ModuleList, None) |

 `forward_tails` performs the corresponding forward pass, expanding `log_std` if it is an `nn.Parameter`, or mapping each element of an `nn.ModuleList` across the input.

## Loss, Optimizer, and LR Scheduler Construction

 
### `get_loss_fn`

 [slm_lab/agent/net/net_util.py61-66](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L61-L66)

 Reads a `loss_spec` dict with a `name` key (e.g., `{"name": "MSELoss"}`), strips the key, and instantiates the corresponding `torch.nn` loss class with any remaining fields as keyword arguments.

 
### `get_optim`

 [slm_lab/agent/net/net_util.py94-102](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L94-L102)

 Reads an `optim_spec` dict (e.g., `{"name": "Adam", "lr": 0.001}`), resolves the class from `torch.optim`, and instantiates it on the network's parameters. Handles both plain networks and raw tensors (used for SAC's `log_alpha` parameter).

 
### `get_lr_scheduler`

 [slm_lab/agent/net/net_util.py69-91](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L69-L91)

 Wraps PyTorch's `lr_scheduler` classes. Three paths:

 
| lr_scheduler_spec | Result |
|---|---|
| Empty / None | NoOpLRScheduler — no-op with consistent API |
| {"name": "LinearToZero", "frame": N} | LambdaLR that decays to zero over N total frames |
| Any other PyTorch scheduler name | Direct instantiation via torch.optim.lr_scheduler |

 The `steps_per_schedule` argument converts a frame-count spec into scheduler update counts. For PPO this is `training_frequency * num_envs`.

 
#### `NoOpLRScheduler`

 [slm_lab/agent/net/net_util.py17-30](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L17-L30)

 A stub class providing `.step()` and `.get_last_lr()` so all code that calls a scheduler can do so unconditionally regardless of whether one was configured.

 [slm_lab/agent/net/net_util.py105-121](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L105-L121)

### `init_layers`

 [slm_lab/agent/net/net_util.py137-159](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L137-L159)

 Entry point. Reads `net.hid_layers_activation` to determine the correct gain/nonlinearity argument for the chosen initializer:

 
 - `kaiming_*` → passes `nonlinearity` argument
 - `orthogonal_` / `xavier_*` → passes `gain` computed from activation

### `init_params`

 [slm_lab/agent/net/net_util.py162-180](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L162-L180)

 Applied to each `nn.Module`. Skips net-level containers and `BatchNorm2d`. Applies `init_fn` to weights and sets biases to `0.0` for:

 
 - `Conv*` layers
 - `Linear` layers
 - `GRU` / RNN layers (per named parameter)
 
 
### `init_tails`

 [slm_lab/agent/net/net_util.py183-223](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L183-L223)

### `polyak_update`

 [slm_lab/agent/net/net_util.py292-298](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L292-L298)

 Soft update (exponential moving average):

 
```
target ← old_ratio × source + (1 − old_ratio) × target
```

 `old_ratio` is read from `src_net.polyak_coef`. Smaller values mean faster tracking; SAC typically uses values near `0.995`.

## Distributed Training Support (Hogwild / A3C)

 These utilities support A3C-style asynchronous training where multiple worker processes share a common global network in CPU shared memory.

 
> **Note:** Hogwild is CPU-only. PyTorch's `share_memory_()` requires CPU tensors. For GPU-accelerated parallel training, use A2C or PPO instead.

 **Hogwild initialization and usage flow:**

 
```

```

 
### `init_global_nets`

 [slm_lab/agent/net/net_util.py397-431](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L397-L431)

 Creates shared-memory versions of all trainable nets. Two modes, set in `spec.meta.distributed`:

 
| Mode | Behavior |
|---|---|
| shared | Workers use the global net directly (same attribute name) |
| synced | Workers keep a local net and a separate global_{net} reference |

 
### `set_global_nets`

 [slm_lab/agent/net/net_util.py434-443](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L434-L443)

 Sets the `global_{net}` attributes on a worker algorithm from the dict produced by `init_global_nets`. Called during algorithm initialization for each worker session.

 
### `push_global_grads`

 [slm_lab/agent/net/net_util.py446-453](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L446-L453)

 Transfers computed gradients from the local worker net to the global net's parameters. Called between `loss.backward()` and `optim.step()` in the training step. Skips if global parameter already has gradients.

 
### Custom Optimizers: `GlobalAdam` / `GlobalRMSprop`

 These are registered on `torch.optim` at import time from `slm_lab.lib.optimizer`. They extend standard optimizers with `share_memory()` support so that optimizer state (momentum buffers, etc.) can also live in shared memory across processes.

## Training Step Verification

 
### `dev_check_train_step`

 [slm_lab/agent/net/net_util.py328-384](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L328-L384)

 A decorator applied to `train_step` methods. Active only in `dev` lab mode or when `PY_ENV=test`. Checks:

 
 - Loss is not NaN.
 - If loss > 0, at least one parameter changed after the update.
 - All gradient norms fall within `(0, 1e5)`.
 
 This catches common bugs like detached tensors, zero gradients, and exploded gradients during development. In production (`train` mode) it is a no-op via the `to_check_train_step` guard.

 
### `get_grad_norms`

 [slm_lab/agent/net/net_util.py387-394](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/net_util.py#L387-L394)

 Collects stored gradient norms from all nets in an algorithm. Used for debugging after `dev_check_train_step` has run `net.store_grad_norms()`.
