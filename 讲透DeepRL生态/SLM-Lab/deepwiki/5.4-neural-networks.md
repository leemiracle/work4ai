## Role in the Agent

 Every algorithm in SLM Lab maintains one or more neural networks. These networks are instantiated by the algorithm during `init_nets` and configured entirely through the `net` block of the spec file. The network object handles its own optimizer, loss function, learning rate scheduler, and target-network update logic. The algorithm calls the network's `train_step` for gradient updates and reads its `forward` output to compute policy parameters or Q-values.

## Network Selection via `net_spec`

 The `"type"` field in `net_spec` selects the class to instantiate. All other fields configure that class. Here is a summary of each network type and its primary use case:

 
| "type" value | Class | Typical use |
|---|---|---|
| "MLPNet" | MLPNet | State-vector inputs; any algorithm |
| "HydraMLPNet" | HydraMLPNet | Multi-environment / multi-task with separate input heads |
| "DuelingMLPNet" | DuelingMLPNet | DQN-family on state-vector inputs |
| "ConvNet" | ConvNet | Image inputs (Atari, pixel-based envs) |
| "DuelingConvNet" | DuelingConvNet | DQN-family on image inputs |
| "RecurrentNet" | RecurrentNet | Sequential state inputs with temporal memory |

## Common `net_spec` Fields

 These fields apply to all or most network types and form the shared configuration interface.

 
### Architecture

 
| Field | Type | Description |
|---|---|---|
| hid_layers | list[int] | Hidden layer sizes (MLPNet, DuelingMLPNet) |
| conv_hid_layers | list[list] | Conv layer specs [out_d, kernel, stride, padding, dilation] (ConvNet) |
| fc_hid_layers | list[int] | FC layers after conv or before RNN |
| hid_layers_activation | str | Activation for hidden layers (e.g. "relu", "tanh") |
| out_layer_activation | str\|null | Activation for output layer(s) |
| shared | bool | Whether actor and critic share this network body |

 
### Initialization

 
| Field | Type | Description |
|---|---|---|
| init_fn | str\|null | Weight init function from nn.init (e.g. "xavier_uniform_", "orthogonal_") |
| actor_init_std | float\|null | Orthogonal init std for actor output head |
| critic_init_std | float\|null | Orthogonal init std for critic output head |
| log_std_init | float\|null | Initial value for state-independent log_std parameter (continuous actions) |

 
### Optimization

 
| Field | Type | Description |
|---|---|---|
| loss_spec | dict | Loss function; requires "name" (e.g. {"name": "MSELoss"}) |
| optim_spec | dict | Optimizer; requires "name" (e.g. {"name": "Adam", "lr": 0.001}) |
| lr_scheduler_spec | dict\|null | LR scheduler; requires "name", supports PyTorch schedulers and custom "LinearToZero" |
| clip_grad_val | float\|null | Gradient norm clipping threshold |

 
### Target Network

 
| Field | Type | Description |
|---|---|---|
| update_type | str | "replace" (hard copy) or "polyak" (EMA) |
| update_frequency | int | Frames between hard-replace updates |
| polyak_coef | float | Old-weight retention ratio for polyak update |

 
### Hardware

 
| Field | Type | Description |
|---|---|---|
| gpu | bool | Move network to CUDA device if available |

## RecurrentNet-Specific Fields

 `RecurrentNet` has additional fields that do not appear in other types:

 
| Field | Type | Default | Description |
|---|---|---|---|
| cell_type | str | "GRU" | Recurrent cell type: "RNN", "LSTM", or "GRU" |
| rnn_hidden_size | int | — | Hidden state size of the RNN |
| rnn_num_layers | int | 1 | Number of stacked recurrent layers |
| bidirectional | bool | false | Use a bidirectional RNN |
| seq_len | int | — | Number of timesteps in each input sequence |

 When a 2D input `(batch_size, state_dim)` is passed to `RecurrentNet.forward`, it is automatically expanded to `(batch_size, seq_len, state_dim)` before being fed to the RNN.

## HydraMLPNet-Specific `hid_layers` Format

 `HydraMLPNet` uses a three-element `hid_layers` list instead of a flat list:

 
```
hid_layers = [
    [[32], [32]],   # per-input head hidden layers
    [64],           # shared body hidden layers
    []              # per-output tail hidden layers
]
```

 This creates one input-processing head per element of `in_dim` and one output tail per element of `out_dim`, all connected through a shared body. Both `in_dim` and `out_dim` must be lists.

 Sources: [slm_lab/agent/net/mlp.py116-266](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/net/mlp.py#L116-L266)

## Relationship to Algorithms

 The table below shows which algorithms typically use which network types. The algorithm spec sets `"type"` in its `net` block to select the network.

 
| Algorithm | Common Network Type | Notes |
|---|---|---|
| REINFORCE, ActorCritic, PPO | MLPNet | shared=true with two-element out_dim for actor+critic |
| SARSA, DQN, DoubleDQN | MLPNet or DuelingMLPNet | Single Q-value output |
| SAC | MLPNet (×3–4) | Separate actor, twin Q-nets, twin target nets |
| Atari DQN | ConvNet or DuelingConvNet | normalize=false (wrapper handles it) |
| A3C (Hogwild) | MLPNet | share_memory() called via init_global_nets |

 For details on how each algorithm calls `init_nets` and sets up its network references, see [Algorithms](https://deepwiki.com/kengz/SLM-Lab/5.2-algorithms).

## Distributed Training Support

 For A3C-style Hogwild training, `net_util.init_global_nets` calls `net.share_memory()` on each trainable network so that its parameters reside in shared CPU memory accessible across worker processes. The `GlobalAdam` and `GlobalRMSprop` optimizer classes (registered at module load time in `net_util.py`) extend standard optimizers to support parameter sharing across processes.
