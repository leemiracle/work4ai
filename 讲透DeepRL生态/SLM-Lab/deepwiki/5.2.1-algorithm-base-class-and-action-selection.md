  This page documents the abstract `Algorithm` base class in `slm_lab/agent/algorithm/base.py` and the action selection utilities in `slm_lab/agent/algorithm/policy_util.py`. Together these two modules define the shared API and infrastructure that every concrete algorithm in SLM Lab builds on.

 For details on concrete algorithm implementations (SARSA, DQN, PPO, SAC, etc.) see pages [5.2.2](https://deepwiki.com/kengz/SLM-Lab/5.2.2-value-based-methods:-sarsa-and-dqn), [5.2.3](https://deepwiki.com/kengz/SLM-Lab/5.2.3-policy-gradient-methods:-reinforce-actor-critic-and-ppo), and [5.2.4](https://deepwiki.com/kengz/SLM-Lab/5.2.4-soft-actor-critic-(sac)). For the `Agent` class that instantiates and calls algorithms, see page [5.1](https://deepwiki.com/kengz/SLM-Lab/5.1-agent-and-metricstracker). For the decay functions (`linear_decay`, `rate_decay`, etc.) used by `VarScheduler`, see page [8.1](https://deepwiki.com/kengz/SLM-Lab/8.1-math-utilities).

### `init_nets` and `end_init_nets`

 `init_nets` is abstract and must be implemented by every algorithm. A typical implementation:

 
 - Instantiates one or more network objects using a class from `slm_lab.agent.net`.
 - Sets `self.net_names` to a list of the attribute names (e.g., `['net']`, `['net', 'target_net']`).
 - Creates optimizers and LR schedulers via `net_util`.
 - Calls `net_util.set_global_nets(self, global_nets)`.
 - Calls `self.end_init_nets()` as the final step.
 
 `end_init_nets` [slm_lab/agent/algorithm/base.py44-55](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/algorithm/base.py#L44-L55) enforces the naming convention (all names in `net_names` must end with `"net"`) and, if the session is in `resume` or `enjoy` mode, calls `self.load()` automatically.

### `to_action`

 [slm_lab/agent/algorithm/base.py64-91](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/algorithm/base.py#L64-L91)

 Converts a PyTorch tensor action output to the correct numpy format expected by Gymnasium. The logic handles 8 distinct cases based on the combination of `is_venv`, `is_discrete`, and action dimensionality:

 
| Environment | Action Type | Input Shape | Output |
|---|---|---|---|
| Single | Discrete | (1,) | scalar int |
| Vectorized | Discrete | (num_envs,) | (num_envs,) |
| Single | Continuous 1D | (1, 1) | (1,) |
| Vectorized | Continuous 1D | (num_envs, 1) | (num_envs, 1) |
| Single | Continuous nD | (1, action_dim) | (action_dim,) |
| Vectorized | Continuous nD | (num_envs, action_dim) | (num_envs, action_dim) |

 The key rule is: single-env discrete actions become Python scalars; single-env continuous actions drop the batch dimension; vectorized continuous actions are reshaped to `(num_envs, action_dim)` if needed.

 [slm_lab/agent/algorithm/base.py117-136](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/algorithm/base.py#L117-L136)

### Action Type and Distribution Class

 [slm_lab/agent/algorithm/policy_util.py17-55](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/algorithm/policy_util.py#L17-L55)

 `ACTION_PDS` maps each action type to an ordered list of compatible distributions. The first entry is the `"default"` choice when `action_pdtype` is set to `"default"` in the spec.

 
| Action Type | Available Distributions | Default |
|---|---|---|
| continuous | Normal, Beta, Gumbel, LogNormal | Normal |
| multi_continuous | Normal, MultivariateNormal | Normal |
| discrete | Categorical, Argmax, GumbelSoftmax | Categorical |
| multi_discrete | MultiCategorical | MultiCategorical |
| multi_binary | Bernoulli | Bernoulli |

 **`get_action_type(env)`** returns the action type string by inspecting `env.is_discrete`, `env.is_multi`, and the type of `env.action_space`.

 **`get_action_pd_cls(action_pdtype, action_type)`** asserts that the requested `action_pdtype` appears in `ACTION_PDS[action_type]` and returns the class from `torch.distributions` (or a custom distribution registered at module load time).

 Custom distributions registered at import are: `Argmax`, `GumbelSoftmax`, `MultiCategorical` (from `slm_lab.lib.distribution`).

### `init_action_pd`

 [slm_lab/agent/algorithm/policy_util.py91-115](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/algorithm/policy_util.py#L91-L115)

 Constructs an instantiated distribution object from `ActionPD` class and `pdparam` tensor.

 **Discrete path** (distribution has `'logits'` in `arg_constraints`):

 
 - Passes `logits=pdparam` to the constructor.
 - If the class has a `temperature` attribute (i.e., `GumbelSoftmax`), also passes `temperature=tensor(1.0)`.
 
 **Continuous path**:

 
 - If `pdparam` is a Python `list` (multi-head network output), unpacks to `loc, scale`.
 - If `pdparam` is a single tensor, splits the last dimension in half: `loc, log_scale = pdparam.split(1, dim=-1)`.
 - Applies `scale = clamp(log_scale, -5, 2).exp()` to ensure a positive standard deviation.
 - If `'covariance_matrix'` is in `arg_constraints` (for `MultivariateNormal`), wraps `scale` in a diagonal matrix.
 - Otherwise, constructs `ActionPD(loc=loc, scale=scale)`.

### Policy Functions

 [slm_lab/agent/algorithm/policy_util.py137-174](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/agent/algorithm/policy_util.py#L137-L174)

 Each policy function has the same signature: `(state, algorithm) -> torch.Tensor`.

 
| Function | Behavior | Exploration Variable |
|---|---|---|
| default | Sample directly from ActionPD | None |
| random | action_space.sample() for each env | None |
| epsilon_greedy | Random with prob epsilon, greedy argmax otherwise | agent.explore_var (epsilon) |
| boltzmann | Divide logits by temperature tau before sampling | agent.explore_var (tau) |

 **`default`** is the standard stochastic policy: compute `pdparam` → construct `ActionPD` → sample.

 **`epsilon_greedy`** takes the greedy action with `pdparam.argmax(dim=-1)`, not a stochastic sample. This ensures it is a true greedy policy when not exploring.

 **`boltzmann`** divides the raw network output by `tau` before sampling. Higher `tau` → more uniform distribution; lower `tau` → more peaked around the best action.
