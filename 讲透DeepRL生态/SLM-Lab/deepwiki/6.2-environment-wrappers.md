# Environment Wrappers

  Relevant source files 
 - [slm_lab/env/__init__.py](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py)
 
  This page documents the wrapper stack applied to Gymnasium environments in SLM Lab. It covers both the custom wrappers defined in `slm_lab/env/wrappers.py` and the standard Gymnasium wrappers composed in `slm_lab/env/__init__.py`. For how environments are instantiated and how the spec drives wrapper selection, see [Environment Creation](https://deepwiki.com/kengz/SLM-Lab/6.1-environment-creation).

 
---

 
## Overview

 Environments in SLM Lab are constructed as a layered stack of Gymnasium-compatible wrappers. Each wrapper adds a single responsibility (observation normalization, reward clipping, episode timing, etc.) and the final wrapped object is returned to the `Session` as the `env`. All wrappers are applied inside `make_env`, `_make_single_env`, and `_make_vector_env` in [slm_lab/env/__init__.py](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py)

 The wrappers fall into two categories:

 
| Category | Source | Applied to |
|---|---|---|
| Custom SLM Lab wrappers | slm_lab/env/wrappers.py | Single and vector envs |
| Gymnasium built-in wrappers | gymnasium.wrappers / gymnasium.wrappers.vector | Single and vector envs |

## Custom SLM Lab Wrappers

 These are imported from `slm_lab/env/wrappers.py` at [slm_lab/env/__init__.py25-33](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L25-L33)

 
### `ClockWrapper` / `VectorClockWrapper`

 Applied as the **outermost** wrapper around every environment, single or vector. Constructed with a `max_frame` budget taken from the spec.

 Responsibilities:

 
 - Tracks the total number of frames (steps) elapsed across all episodes.
 - Exposes a clock interface used by `Session.try_ckpt` to trigger checkpointing and evaluation.
 - Signals training termination when `max_frame` is reached.
 
 `ClockWrapper` wraps single `gym.Env` instances. `VectorClockWrapper` wraps `VectorEnv` instances and accounts for `num_envs` when advancing the frame counter (each `step` call advances the clock by `num_envs` frames).

### `TrackReward`

 Applied to single environments only (not vector). Inserted after action rescaling and before normalization wrappers.

 Responsibilities:

 
 - Accumulates per-episode rewards.
 - Provides episode return data accessible to the agent's `MetricsTracker`.
 
 `VectorEnv` pipelines use Gymnasium's built-in `VectorRecordEpisodeStatistics` for the equivalent functionality.

 
### `VectorFullGameStatistics`

 Applied to Atari vector environments only, after `VectorRecordEpisodeStatistics` at [slm_lab/env/__init__.py263](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L263-L263)

 Atari environments often use life-loss as a pseudo-terminal signal to produce shorter, denser episodes during training. `VectorRecordEpisodeStatistics` then reports per-life scores rather than full-game scores. `VectorFullGameStatistics` accumulates scores across life losses and records the full-game return when all lives are exhausted.

 
### `VectorRenderAll`

 Applied only when a `render_mode` is active (i.e., `render()` returns `True`), at [slm_lab/env/__init__.py282](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L282-L282)

 Responsibilities:

 
 - Calls `render()` on the underlying vector environment.
 - Ensures all parallel sub-environments are rendered each step.
 
 
### `ClipObservation` / `VectorClipObservation`

 Applied when `clip_obs` is set in the env spec (defaulting to `10.0` when `normalize_obs` is `True`). See [slm_lab/env/__init__.py171](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L171-L171)

 Responsibilities:

 
 - Clips each observation element to `[-bound, bound]`.
 - Typically used after `NormalizeObservation` to prevent outlier observations from destabilizing training.
 
 
| Wrapper | Env type | Trigger |
|---|---|---|
| ClipObservation | Single | clip_obs set in spec |
| VectorClipObservation | Vector | clip_obs set in spec |

## Gymnasium Built-in Wrappers

 These are standard Gymnasium wrappers composed into the pipeline. They are imported at [slm_lab/env/__init__.py9-23](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L9-L23)

 
### Atari Preprocessing

 
| Wrapper | Where applied | Purpose |
|---|---|---|
| AtariPreprocessing | Single env; Atari sync vector mode | Grayscale + resize to 84×84, max-pool frames, frame skip |
| FrameStackObservation | Single env and Atari sync vector mode | Stacks 4 frames into a single observation |

 Parameters used:

 
 - `frame_skip=1` — frame skipping is handled by `AtariVectorEnv` natively in `vector_entry_point` mode.
 - `scale_obs=False` — pixel values remain `uint8`; the network normalizes by dividing by 255.
 - `stack_size=4`, `padding_type="zero"` — zero-pad initial frames.
 
 For `vector_entry_point` mode (the default non-rendering Atari path), `AtariVectorEnv` applies all preprocessing internally; no explicit `AtariPreprocessing` or `FrameStackObservation` wrappers are added.

 
### Action Rescaling

 
| Wrapper | Env type | Trigger |
|---|---|---|
| RescaleAction | Single | Action space not already [-1, 1] |
| VectorRescaleAction | Vector | Action space not already [-1, 1] |

 The helper `_needs_action_rescaling` at [slm_lab/env/__init__.py63-71](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L63-L71) checks whether the `Box` action space bounds are already `[-1, 1]`. If not, the wrapper rescales agent outputs to the environment's native range.

 
### Observation and Reward Normalization

 
| Wrapper | Env type | Trigger spec field |
|---|---|---|
| NormalizeObservation | Single | normalize_obs: true |
| VectorNormalizeObservation | Vector | normalize_obs: true |
| NormalizeReward | Single | normalize_reward: true |
| VectorNormalizeReward | Vector | normalize_reward: true |

 Both normalization wrappers maintain running statistics (mean and variance) to standardize their respective signals. `NormalizeReward` / `VectorNormalizeReward` accept a `gamma` argument (drawn from `spec.agent.algorithm.gamma`) to compute the discounted return variance used for normalization.

 
### Reward Clipping

 
| Wrapper | Env type | Trigger |
|---|---|---|
| ClipReward | Single | clip_reward set, or Atari |
| VectorClipReward | Vector | clip_reward set, or Atari |

 Atari environments always apply reward clipping to `[-1.0, 1.0]`. For non-Atari environments, clipping is applied only if `clip_reward` is specified in the spec. The clip bounds can be a scalar (applied symmetrically) or a `[min, max]` list.

 
### Episode Statistics Recording

 `VectorRecordEpisodeStatistics` (Gymnasium built-in) is always applied to vector environments at [slm_lab/env/__init__.py261](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L261-L261) It records per-episode returns and lengths into `info["episode"]`. For Atari, `VectorFullGameStatistics` is stacked on top to aggregate across lives.

## Spec Fields That Activate Wrappers

 The following env spec fields control which optional wrappers are applied. These are consumed by `make_env` and stripped from kwargs before being passed to `gym.make` (see `RESERVED_KEYS` at [slm_lab/env/__init__.py51-60](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L51-L60)).

 
| Spec field | Type | Default | Wrappers activated |
|---|---|---|---|
| normalize_obs | bool | false | NormalizeObservation / VectorNormalizeObservation |
| normalize_reward | bool | false | NormalizeReward / VectorNormalizeReward |
| clip_obs | float or null | 10.0 if normalize_obs, else null | ClipObservation / VectorClipObservation |
| clip_reward | float, list, or null | 10.0 if normalize_reward, else null (always [-1,1] for Atari) | ClipReward / VectorClipReward |

 `clip_reward` can be a scalar `N` (producing bounds `[-N, N]`) or a two-element list `[min, max]`. See [slm_lab/env/__init__.py169-173](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/env/__init__.py#L169-L173) for how defaults are computed.

 For full spec field documentation, see [Configuration and Spec Files](https://deepwiki.com/kengz/SLM-Lab/7-configuration-and-spec-files) and [Spec Format Reference](https://deepwiki.com/kengz/SLM-Lab/7.1-spec-format-reference).
