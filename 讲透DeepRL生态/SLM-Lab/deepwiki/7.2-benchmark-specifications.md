  This page catalogs the ready-to-run benchmark spec files shipped with SLM Lab under `slm_lab/spec/benchmark/`. Each file maps directly to a named spec that can be passed to the `slm-lab` CLI. The page covers what algorithms are benchmarked, which environments each targets, and how to adapt these files as starting points for new experiments.

 For the full field-by-field reference of the spec format itself, see [Spec Format Reference](https://deepwiki.com/kengz/SLM-Lab/7.1-spec-format-reference). For the CLI commands used to launch a spec, see [Running Your First Experiment](https://deepwiki.com/kengz/SLM-Lab/2.2-running-your-first-experiment). For the hyperparameter search system that some of these specs activate, see [Hyperparameter Search](https://deepwiki.com/kengz/SLM-Lab/4.3-hyperparameter-search).

## PPO Benchmarks

 
### PPO on Atari (`ppo_atari.json`)

 [slm_lab/spec/benchmark/ppo/ppo_atari.json1-318](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/spec/benchmark/ppo/ppo_atari.json#L1-L318)

 The base spec `ppo_atari` uses a shared `ConvNet` with three convolutional layers followed by a 512-unit FC layer. The `${env}` placeholder in the `env.name` field allows this spec to be used with any Atari game by substituting the variable at launch time.

 
| Parameter | Value |
|---|---|
| algorithm.name | PPO |
| net.type | ConvNet (shared) |
| net.optim_spec.name | AdamW |
| net.optim_spec.lr | 2.5e-4 |
| net.lr_scheduler_spec | LinearToZero over 10M frames |
| algorithm.time_horizon | 128 |
| algorithm.minibatch_size | 256 |
| algorithm.training_epoch | 4 |
| algorithm.lam | 0.95 |
| algorithm.clip_eps_spec.start_val | 0.1 |
| env.num_envs | 16 |
| env.max_frame | 10,000,000 |
| meta.max_session | 4 |

 Three named variants are included in the same file, differing only in `lam`:

 
| Spec name | lam |
|---|---|
| ppo_atari | 0.95 (with search) |
| ppo_atari_lam85 | 0.85 |
| ppo_atari_lam70 | 0.70 |
| ppo_atari_nosticky | 0.95, repeat_action_probability: 0.0 |

 The search block in `ppo_atari` sweeps over `lam`, `entropy_coef`, and `optim_spec.lr` using Ray Tune.

## A3C Benchmarks

 A3C runs the `ActorCritic` algorithm with `distributed: "synced"`, meaning multiple sessions share gradient updates via `GlobalAdam`. The standard configuration uses `max_session: 16`.

 [slm_lab/spec/benchmark/a3c/a3c_gae_atari.json1-177](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/spec/benchmark/a3c/a3c_gae_atari.json#L1-L177) [slm_lab/spec/benchmark/a3c/a3c_nstep_pong.json1-176](https://github.com/kengz/SLM-Lab/blob/d3128a8a/slm_lab/spec/benchmark/a3c/a3c_nstep_pong.json#L1-L176)

 
| Spec | num_step_returns / lam | gpu | distributed |
|---|---|---|---|
| a3c_gae_atari | lam: 0.95 | false | "synced" |
| gpu_a3c_gae_atari | lam: 0.95 | false | "shared" |
| a3c_nstep_atari | num_step_returns: 5 | "auto" | "synced" |
| gpu_a3c_nstep_atari | num_step_returns: 5 | "auto" | "shared" |
| a3c_gae_pong | lam: 0.95 | false | "synced" |
| a3c_nstep_pong | num_step_returns: 5 | "auto" | "synced" |

 The `gpu_` prefixed variants set `distributed: "shared"` (Hogwild-style asynchronous updates) instead of `"synced"`.

## DQN Benchmarks

 All DQN specs use `ConvNet` with three convolutional layers and `epsilon_greedy` exploration that decays linearly from `1.0` to `0.01` between steps 10,000 and 1,000,000. Target networks use hard replacement (`update_type: "replace"`) every 1,000 steps.

## Async-SAC Benchmarks

 To adapt a benchmark spec for a new environment:

 
 - Copy the JSON file to a new location under `slm_lab/spec/experimental/` or any accessible path.
 - Change `env.name` to the target environment identifier (e.g., `ALE/SpaceInvaders-v5`).
 - Adjust `env.max_frame` to match the expected convergence horizon.
 - Optionally add a `search` block using the dot-path syntax described in [Spec Format Reference](https://deepwiki.com/kengz/SLM-Lab/7.1-spec-format-reference) (e.g., `"agent.net.optim_spec.lr__loguniform": [1e-4, 5e-4]`).
 - Set `meta.max_trial` to the number of random hyperparameter samples desired.
 
 To convert a single-process spec into a distributed A3C-style run, change:

 
 - `meta.distributed` from `false` to `"synced"`
 - `meta.max_session` to the desired number of parallel workers (typically `16`)
 - All `optim_spec.name` values from `Adam`/`AdamW` to `GlobalAdam`
