## PPO (Proximal Policy Optimization) Trainer

 PPO is an on-policy algorithm that uses a clipped surrogate objective to prevent large policy updates, making training more stable.

 
### PPO Implementation Details

 The `PPOTrainer` manages the training loop for PPO. It processes trajectories by calculating value and advantage targets using Generalized Advantage Estimation (GAE) [mlagents/trainers/ppo/trainer.py68-74](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/ppo/trainer.py#L68-L74)

 
 - **Advantage Calculation**: Uses `get_gae` with hyperparameters like `lambd` and `gamma` [mlagents/trainers/ppo/trainer.py135-141](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/ppo/trainer.py#L135-L141)
 - **Update Buffer**: Processed trajectories are converted to `AgentBuffer` and appended to the `update_buffer` for the optimizer [mlagents/trainers/ppo/trainer.py161](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/ppo/trainer.py#L161-L161)
 - **Optimizer**: `TorchPPOOptimizer` handles the clipped objective and entropy regularization [mlagents/trainers/ppo/optimizer_torch.py17](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/ppo/optimizer_torch.py#L17-L17)
 
 **Sources:** [ml-agents/mlagents/trainers/ppo/trainer.py68-171](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/ppo/trainer.py#L68-L171) [ml-agents/mlagents/trainers/ppo/optimizer_torch.py17](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/ppo/optimizer_torch.py#L17-L17)

 
## SAC (Soft Actor-Critic) Trainer

 SAC is an off-policy algorithm that maximizes expected return while also maximizing entropy, promoting exploration.

 
### SAC Implementation Details

 The `SACTrainer` inherits from `OffPolicyTrainer` [mlagents/trainers/sac/trainer.py30](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/sac/trainer.py#L30-L30)

 
 - **Replay Buffer**: SAC relies on a replay buffer; `SACTrainer` handles loading and saving this buffer across sessions [mlagents/trainers/sac/trainer.py168](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/sac/trainer.py#L168-L168)
 - **Trajectory Processing**: Unlike PPO, SAC doesn't calculate advantages during trajectory processing. It evaluates reward functions and value estimates primarily for reporting [mlagents/trainers/sac/trainer.py102-129](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/sac/trainer.py#L102-L129)
 - **Normalization**: Updates actor and critic normalization based on trajectory data [mlagents/trainers/sac/trainer.py98-100](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/sac/trainer.py#L98-L100)
 
 **Sources:** [ml-agents/mlagents/trainers/sac/trainer.py30-143](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/sac/trainer.py#L30-L143) [ml-agents/mlagents/trainers/sac/trainer.py168](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/sac/trainer.py#L168-L168)

 
## POCA (Partially Observable Centralized Actor) Trainer

 POCA is a multi-agent algorithm that uses a centralized critic to train agents that may only have partial local observations.

 
### POCA Implementation Details

 The `POCATrainer` processes trajectories with centralized baseline estimates [mlagents/trainers/poca/trainer.py30-31](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/poca/trainer.py#L30-L31)

 
 - **Centralized Value Estimates**: Calls `get_trajectory_and_baseline_value_estimates` to get global critic values [mlagents/trainers/poca/trainer.py92-99](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/poca/trainer.py#L92-L99)
 - **Lambda Returns**: Computes `lambda_return` and subtracts the baseline estimate to calculate `local_advantage` [mlagents/trainers/poca/trainer.py153-161](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/poca/trainer.py#L153-L161)
 - **Group Rewards**: Specifically tracks `collected_group_rewards` separate from individual environment rewards [mlagents/trainers/poca/trainer.py68](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/poca/trainer.py#L68-L68)
 
 **Sources:** [ml-agents/mlagents/trainers/poca/trainer.py30-170](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/poca/trainer.py#L30-L170) [ml-agents/mlagents/trainers/poca/trainer.py68](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/poca/trainer.py#L68-L68)

 
## Ghost Trainer and Self-Play

 The `GhostTrainer` acts as a wrapper for adversarial games (teams in opposition) using a self-play mechanism [mlagents/trainers/ghost/trainer.py28-30](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/ghost/trainer.py#L28-L30)

 
 - **Ghosting**: While one team learns, the other team is "ghosted," executing fixed policies from snapshots [mlagents/trainers/ghost/trainer.py31-33](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/ghost/trainer.py#L31-L33)
 - **Snapshots**: Maintains `policy_snapshots` to be used as fixed policies [mlagents/trainers/ghost/trainer.py116](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/ghost/trainer.py#L116-L116)
 - **ELO Rating**: The `GhostController` coordinates trainers and calculates ELO to track relative skill [mlagents/trainers/ghost/trainer.py38-39](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/ghost/trainer.py#L38-L39)
 - **Training Team Rotation**: The learning team ID is cycled throughout the run to ensure all behaviors improve [mlagents/trainers/ghost/trainer.py127-132](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/mlagents/trainers/ghost/trainer.py#L127-L132)
 
 **Sources:** [ml-agents/mlagents/trainers/ghost/trainer.py28-40](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/ghost/trainer.py#L28-L40) [ml-agents/mlagents/trainers/ghost/trainer.py116-132](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/ghost/trainer.py#L116-L132)

### Implementation Requirements

 To implement a custom trainer, developers must:

 
 - **Extend Base Classes**: Inherit from `OnPolicyTrainer` or `OffPolicyTrainer` [docs/Tutorial-Custom-Trainer-Plugin.md12](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Tutorial-Custom-Trainer-Plugin.md?plain=1#L12-L12)
 - **Implement Abstract Methods**: 
 - `create_policy`: Define the network architecture (e.g., using `SimpleActor`) [docs/Tutorial-Custom-Trainer-Plugin.md19-44](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Tutorial-Custom-Trainer-Plugin.md?plain=1#L19-L44)
 - `create_optimizer`: Define the learning logic [docs/Tutorial-Custom-Trainer-Plugin.md54-59](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Tutorial-Custom-Trainer-Plugin.md?plain=1#L54-L59)
 - `_process_trajectory`: Handle advantage and return calculations [docs/Tutorial-Custom-Trainer-Plugin.md61-108](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Tutorial-Custom-Trainer-Plugin.md?plain=1#L61-L108)
 - `_update_policy`: Execute the optimization step [docs/Tutorial-Custom-Trainer-Plugin.md61](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Tutorial-Custom-Trainer-Plugin.md?plain=1#L61-L61)
 - **Register Entry Point**: Define the plugin in `setup.py` under the `mlagents.stats_writer` or trainer-specific entry points [docs/Training-Plugins.md19-28](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Training-Plugins.md?plain=1#L19-L28)
