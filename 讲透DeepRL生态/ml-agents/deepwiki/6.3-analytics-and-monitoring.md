  This document covers the analytics and monitoring system within the ML-Agents toolkit, which tracks usage patterns, model deployments, and training configurations. It also details the Python-side `StatsReporter` pipeline for monitoring training metrics like rewards, entropy, and ELO via TensorBoard and console output.

 
## Overview

 The ML-Agents monitoring system consists of two main branches:

 
 - **Unity Client Analytics**: Telemetry data regarding model deployment and environment initialization, sent to Unity's analytics backend.
 - **Training Metrics (StatsReporter)**: Real-time training data (e.g., Cumulative Reward) processed on the Python side and dispatched to TensorBoard, the console, or custom writers.

## Python Stats Pipeline

 The Python-side `StatsReporter` is the central hub for all training metrics. It aggregates values over time and distributes them to multiple `StatsWriter` implementations.

 
### StatsReporter and StatsSummary

 The `StatsReporter` maintains a collection of `StatsWriter` objects. When `add_stat` is called, it updates internal distributions. Periodically, `write_stats` is called to aggregate these distributions into a `StatsSummary` and pass them to writers. [ml-agents/mlagents/trainers/stats.py22-68](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/stats.py#L22-L68)

 **Aggregation Methods:** Defined in `StatsAggregationMethod`, these determine how multiple values in a summary window are reduced:

 
 - `AVERAGE`: Mean of all values.
 - `SUM`: Total sum of values.
 - `MOST_RECENT`: The last value received.
 - `HISTOGRAM`: Full distribution (used by TensorBoard).
 
 Sources: [ml-agents-envs/mlagents_envs/side_channel/stats_side_channel.py10-21](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents-envs/mlagents_envs/side_channel/stats_side_channel.py#L10-L21) [ml-agents/mlagents/trainers/stats.py42-72](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/stats.py#L42-L72)

 
### StatsWriter Implementations

 Writers handle the actual output of aggregated data:

 
| Class | Output Destination | Behavior |
|---|---|---|
| TensorboardWriter | .tfevents files | Uses torch.utils.tensorboard.SummaryWriter to log scalars and text. ml-agents/mlagents/trainers/stats.py246-300 |
| ConsoleWriter | Terminal / Logs | Prints formatted strings including Step, Time, Mean Reward, and ELO. ml-agents/mlagents/trainers/stats.py157-197 |
| GaugeWriter | Timer Gauges | Sanitizes keys (replacing / with .) and writes to internal timers. ml-agents/mlagents/trainers/stats.py131-155 |

## Metric Collection Points

 Metrics enter the `StatsReporter` from two primary sources:

 
### 1. AgentProcessor (Internal Metrics)

 The `AgentProcessor` automatically reports training-specific metrics during the trajectory collection loop.

 
 - **Policy/Entropy**: Reported whenever a policy generates actions. [ml-agents/mlagents/trainers/agent_processor.py104-109](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/agent_processor.py#L104-L109)
 - **Environment/Cumulative Reward**: Calculated at the end of an episode and reported via the reporter. [ml-agents/mlagents/trainers/agent_processor.py210-225](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/agent_processor.py#L210-L225)
 
 
### 2. StatsSideChannel (Custom User Metrics)

 Users can report custom metrics from Unity using the `StatsRecorder`.

 
 - **Unity side**: `StatsRecorder.Add("MyMetric", 1.0f)` sends data through the `StatsSideChannel`. [com.unity.ml-agents/Runtime/StatsRecorder.cs67-73](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/StatsRecorder.cs#L67-L73)
 - **Python side**: `StatsSideChannel.on_message_received` parses the key, value, and aggregation type, which the `AgentManager` then pushes to the `StatsReporter`. [ml-agents-envs/mlagents_envs/side_channel/stats_side_channel.py41-52](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents-envs/mlagents_envs/side_channel/stats_side_channel.py#L41-L52)

## Training Analytics

 `TrainingAnalytics` tracks the lifecycle of a training session. It generates a unique `TrainingSessionGuid` per session to correlate events. [com.unity.ml-agents/Runtime/Analytics/TrainingAnalytics.cs37-66](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Analytics/TrainingAnalytics.cs#L37-L66)

 
### Key Events

 
 - **TrainingEnvironmentInitialized**: Sent once per session. Includes `MLAgentsVersion`, `PythonVersion`, and `TorchVersion`. [com.unity.ml-agents/Runtime/Analytics/Events.cs181-205](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Analytics/Events.cs#L181-L205)
 - **RemotePolicyInitialized**: Sent when a `RemotePolicy` is first used. Captures the `ActionSpec` and `ObservationSpecs` used for training. [com.unity.ml-agents/Runtime/Analytics/TrainingAnalytics.cs126-160](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Analytics/TrainingAnalytics.cs#L126-L160)
 - **TrainingBehaviorInitialized**: Captures the trainer configuration (e.g., whether GAIL or Curiosity is enabled). [com.unity.ml-agents/Runtime/Analytics/TrainingAnalytics.cs188-215](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Analytics/TrainingAnalytics.cs#L188-L215)

## Performance Profiling

 In addition to stats, the toolkit includes a hierarchical timer system for Python profiling.

 
 - **Usage**: Developers use the `@timed` decorator or `hierarchical_timer` context manager. [docs/Profiling-Python.md17-34](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Profiling-Python.md?plain=1#L17-L34)
 - **Output**: Timers are saved as `{run_id}_timers.json` in the summaries directory. This JSON includes `total`, `self`, and `count` for each code block. [docs/Profiling-Python.md40-54](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Profiling-Python.md?plain=1#L40-L54)
 - **Parallelism**: The system handles subprocesses (e.g., `SubprocessEnvManager`) by aggregating timers from child processes back to the main process. [docs/Profiling-Python.md57-66](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Profiling-Python.md?plain=1#L57-L66)
