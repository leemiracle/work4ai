  This page details the main training loop orchestrated by `learn.py` and `TrainerController`, focusing on how the Python training components execute the core training pipeline. For information about the Unity-side components such as the Agent and Academy, see [Unity SDK Components](https://deepwiki.com/Unity-Technologies/ml-agents/2-unity-sdk-components).

 The training pipeline represents the execution flow from the `mlagents-learn` command through the main training loop, experience collection, policy updates, and model saving.

 
## Training Pipeline Overview

 The ML-Agents training pipeline is orchestrated by two main components: `learn.py` which handles setup and orchestration, and `TrainerController` which manages the main training loop. The pipeline executes in the following sequence:

 
 - **Entry Point**: `mlagents-learn` CLI command invokes `learn.py` via the `parser` defined in `cli_utils.py`.
 - **Setup Phase**: Environment creation, trainer factory setup, and parameter management in `run_training()`.
 - **Training Loop**: `TrainerController.start_learning()` executes the main training loop.
 - **Experience Processing**: Agent experiences are collected by `AgentProcessor` and organized into trajectories.
 - **Policy Updates**: Trainers (e.g., `PPOTrainer`) update policies based on collected experiences.
 - **Model Persistence**: Trained models are saved as checkpoints and exported to ONNX.

### Experience Processing Pipeline

 Agent experiences are collected via `AgentProcessor`, which maintains buffers for each agent and groups them into `Trajectory` objects once a `max_trajectory_length` or terminal state is reached.

 
 - **Experience Collection**: `AgentProcessor.add_experiences()` is called during `TrainerController.advance()` with the latest `DecisionSteps` and `TerminalSteps` [ml-agents/mlagents/trainers/agent_processor.py90-102](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/agent_processor.py#L90-L102)
 - **Trajectory Assembly**: When a trajectory is complete, it is put into an `AgentManagerQueue` [ml-agents/mlagents/trainers/agent_processor.py206-215](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/agent_processor.py#L206-L215)
 - **Trainer Consumption**: Trainers subscribe to these queues to pull trajectories for buffer updates [ml-agents/mlagents/trainers/trainer_controller.py155](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/trainer_controller.py#L155-L155)

 - **Final Save**: `TrainerController._save_models()` is called to write the final neural network state [ml-agents/mlagents/trainers/trainer_controller.py72-81](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/trainer_controller.py#L72-L81)
