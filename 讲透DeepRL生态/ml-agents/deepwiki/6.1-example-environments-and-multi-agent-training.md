## Multi-Agent Training Patterns

 ML-Agents supports complex multi-agent scenarios, ranging from zero-sum competition to team-based cooperation.

 
### Cooperative Training with SimpleMultiAgentGroup

 For cooperative scenarios, agents are often grouped to share rewards or be treated as a single entity for episode management. The `SimpleMultiAgentGroup` class is the primary utility for this.

 **Key Functions:**

 
 - `RegisterAgent(Agent agent)`: Adds an agent to the group [com.unity.ml-agents/Runtime/SimpleMultiAgentGroup.cs40-50](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/SimpleMultiAgentGroup.cs#L40-L50)
 - `AddGroupReward(float reward)`: Distributes a reward to all agents currently in the group [com.unity.ml-agents/Runtime/SimpleMultiAgentGroup.cs72-82](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/SimpleMultiAgentGroup.cs#L72-L82)
 - `EndGroupEpisode()`: Ends the episode for all agents in the group simultaneously [com.unity.ml-agents/Runtime/SimpleMultiAgentGroup.cs110-120](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/SimpleMultiAgentGroup.cs#L110-L120)

## MA-POCA (Multi-Agent Post-Adversarial Critical Architecture)

 MA-POCA is a centralized-critic trainer designed for cooperative multi-agent tasks where agents may be added or removed during an episode.

 
### Training Configuration

 To use MA-POCA, the `trainer_type` must be set to `poca` in the YAML configuration [docs/Training-Configuration-File.md31](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Training-Configuration-File.md?plain=1#L31-L31)

 **Key MA-POCA Parameters:**

 
| Setting | Description |
|---|---|
| trainer_type | Set to poca docs/Training-Configuration-File.md31 |
| time_horizon | Steps to collect before adding to buffer (default 64) docs/Training-Configuration-File.md33 |
| max_steps | Total steps for the training run docs/Training-Configuration-File.md34 |

 
### Self-Play for Competitive Scenarios

 For competitive environments like Soccer, **Self-Play** allows agents to train against past versions of themselves. This is configured in the YAML file under the `self_play` section [docs/Training-Configuration-File.md18](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Training-Configuration-File.md?plain=1#L18-L18)

 **Self-Play Mechanism:**

 
 - The trainer maintains a pool of past policy snapshots.
 - During training, the agent's opponent is sampled from this pool.
 - This ensures the agent learns to counter a variety of strategies rather than over-fitting to a single opponent [docs/ML-Agents-Overview.md23](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/ML-Agents-Overview.md?plain=1#L23-L23)
