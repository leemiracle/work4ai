  This page details how trained neural network models are loaded, managed, and executed for real-time inference within the Unity environment. It focuses on the `ModelRunner` orchestration, the transition to the Unity Sentis inference engine, and the utilities provided for model deployment and validation.

 
## Core Inference Architecture

 The inference system bridges Unity simulation data (observations) with neural network execution. It is designed to handle multiple agents sharing the same model by batching their observations into tensors.

## Data Flow and Tensor Management

 The inference loop follows a strict "Prepare -> Execute -> Fetch" pattern.

 
### The Inference Loop

 
 - **Observation Gathering**: `ModelRunner.PutObservations` collects data from all agents sharing the same behavior [com.unity.ml-agents/Runtime/Inference/ModelRunner.cs173-186](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Inference/ModelRunner.cs#L173-L186)
 - **Input Generation**: `TensorGenerator` iterates through registered `IGenerator` implementations (e.g., `ObservationGenerator`, `RecurrentInputGenerator`) to populate Sentis tensors [com.unity.ml-agents/Runtime/Inference/TensorGenerator.cs65-92](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Inference/TensorGenerator.cs#L65-L92)
 - **Execution**: The `Worker.Execute` method (or implicit execution via output fetching) runs the forward pass [com.unity.ml-agents/Runtime/Inference/ModelRunner.cs108](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Inference/ModelRunner.cs#L108-L108)
 - **Action Application**: `TensorApplier` processes outputs. For discrete actions, this may involve stochastic sampling or deterministic selection [com.unity.ml-agents/Runtime/Inference/TensorApplier.cs51-54](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Inference/TensorApplier.cs#L51-L54)

## Model Deployment Utilities

 
### ModelOverrider

 The `ModelOverrider` is a utility component used primarily in automated testing and validation (e.g., Yamato CI). It allows a build to override an Agent's internal model with an external ONNX file via command-line arguments.

 **Key Command Line Flags:**

 
 - `--mlagents-override-model-directory`: Path to the directory containing new models [Project/Assets/ML-Agents/Examples/SharedAssets/Scripts/ModelOverrider.cs27](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/Project/Assets/ML-Agents/Examples/SharedAssets/Scripts/ModelOverrider.cs#L27-L27)
 - `--mlagents-override-model-extension`: Specifies `nn` or `onnx` [Project/Assets/ML-Agents/Examples/SharedAssets/Scripts/ModelOverrider.cs28](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/Project/Assets/ML-Agents/Examples/SharedAssets/Scripts/ModelOverrider.cs#L28-L28)
 - `--mlagents-quit-after-episodes`: Terminates the application after a set number of evaluations [Project/Assets/ML-Agents/Examples/SharedAssets/Scripts/ModelOverrider.cs29](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/Project/Assets/ML-Agents/Examples/SharedAssets/Scripts/ModelOverrider.cs#L29-L29)
 
 
### Inference Analytics

 ML-Agents tracks model performance and configuration via the `InferenceAnalytics` system. When a model is set, it gathers metadata such as memory size, weight size, and the number of layers to help Unity improve the Sentis engine and ML-Agents toolkit [com.unity.ml-agents/Runtime/Analytics/InferenceAnalytics.cs73-80](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Analytics/InferenceAnalytics.cs#L73-L80)
