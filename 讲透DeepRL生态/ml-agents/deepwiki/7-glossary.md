  This page provides definitions for the core terminology, technical jargon, and domain-specific concepts used within the Unity ML-Agents Toolkit. It serves as a reference for onboarding engineers to map abstract Reinforcement Learning (RL) concepts to their specific implementations in the C# and Python codebases.

 
## Core Architectural Concepts

 The toolkit is divided into the Unity SDK (C#) and the Trainer (Python). The following terms describe the high-level bridge between these two domains.

 
| Term | Definition | Code Pointer |
|---|---|---|
| Academy | A singleton that orchestrates the simulation step and manages the connection to the Python communicator. | com.unity.ml-agents/Runtime/Academy.cs66-67 |
| Agent | The base class for any Unity GameObject that perceives observations and performs actions. | com.unity.ml-agents/Runtime/Agent.cs (Implicit in docs/Learning-Environment-Design-Agents.md44-49) |
| Behavior | A unique identifier for a set of Agents that share the same observation and action spaces. | ml-agents/mlagents/trainers/behavior_id_utils.py28 |
| Communicator | The interface responsible for sending observations/rewards to Python and receiving actions/commands back via gRPC. | com.unity.ml-agents/Runtime/Communicator/ICommunicator.cs |
| Side Channel | A communication bridge for sending non-RL data (like environment configurations or custom stats) between Unity and Python. | com.unity.ml-agents/Runtime/SideChannels/SideChannel.cs |

## Unity SDK Terms (C#)

 These terms relate to the components living inside the Unity Engine that define the simulation logic.

 
### Sensor & Observation

 
 - **Vector Observation**: A feature vector of floats representing the state of the world [docs/Learning-Environment-Design-Agents.md91-96](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Learning-Environment-Design-Agents.md?plain=1#L91-L96)
 - **Sensor**: A component that implements `ISensor` to produce observations (e.g., `RayPerceptionSensor`, `CameraSensor`) [docs/Learning-Environment-Design-Agents.md11](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Learning-Environment-Design-Agents.md?plain=1#L11-L11)
 - **Stacking**: The process of concatenating observations from previous time steps to provide the agent with temporal information [docs/Learning-Environment-Design-Agents.md15](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Learning-Environment-Design-Agents.md?plain=1#L15-L15)
 
 
### Action & Actuator

 
 - **ActionBuffers**: A container for both `ContinuousActions` and `DiscreteActions` sent to an agent [com.unity.ml-agents/Runtime/Agent.cs](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Agent.cs) (Referenced in [docs/Learning-Environment-Create-New.md132](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Learning-Environment-Create-New.md?plain=1#L132-L132)).
 - **Actuator**: A component implementing `IActuator` that translates numerical actions from the brain into physical movements or logic in Unity [docs/Learning-Environment-Design-Agents.md31](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Learning-Environment-Design-Agents.md?plain=1#L31-L31)
 - **Action Masking**: A feature for discrete actions that allows the environment to tell the agent which actions are currently invalid [docs/Learning-Environment-Design-Agents.md30](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Learning-Environment-Design-Agents.md?plain=1#L30-L30)
 
 
### Decision Making

 
 - **Decision Requester**: A component that automatically calls `Agent.RequestDecision()` at a fixed step interval [com.unity.ml-agents/Runtime/DecisionRequester.cs](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/DecisionRequester.cs)
 - **Heuristic**: A manual implementation of a policy (e.g., keyboard input) used for debugging or player control [docs/Learning-Environment-Design-Agents.md78-83](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Learning-Environment-Design-Agents.md?plain=1#L78-L83)

## Python Trainer Terms

 These terms relate to the `mlagents` Python package and the machine learning algorithms.

 
### Training Infrastructure

 
 - **TrainerController**: The main loop that coordinates environment stepping and trainer updates [ml-agents/mlagents/trainers/trainer_controller.py34](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/trainer_controller.py#L34-L34)
 - **EnvManager**: Abstract layer for managing one or multiple Unity instances (e.g., `SubprocessEnvManager`) [ml-agents/mlagents/trainers/subprocess_env_manager.py27](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/subprocess_env_manager.py#L27-L27)
 - **Trajectory**: A sequence of steps (observations, actions, rewards) collected from an agent until a terminal state or time horizon is reached [ml-agents/mlagents/trainers/trajectory.py](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/trajectory.py) (Referenced in [ml-agents/mlagents/trainers/ppo/trainer.py68-74](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/ppo/trainer.py#L68-L74)).
 
 
### Algorithms (Trainers)

 
 - **PPO (Proximal Policy Optimization)**: An on-policy reinforcement learning algorithm [ml-agents/mlagents/trainers/ppo/trainer.py29-30](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/ppo/trainer.py#L29-L30)
 - **SAC (Soft Actor-Critic)**: An off-policy reinforcement learning algorithm [ml-agents/mlagents/trainers/sac/trainer.py](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/sac/trainer.py)
 - **MA-POCA (Multi-Agent Posthumous Credit Assignment)**: An algorithm for cooperative multi-agent training [ml-agents/mlagents/trainers/poca/trainer.py](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/poca/trainer.py)
 - **GhostTrainer**: Implementation for Self-Play where an agent trains against past versions of itself [ml-agents/mlagents/trainers/ghost/trainer.py](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/trainers/ghost/trainer.py)

## Domain Jargon Table

 
| Jargon | Definition | Reference |
|---|---|---|
| Brain | (Legacy) Now referred to as Behavior Name. Represents the logic that maps observations to actions. | ml-agents/mlagents/trainers/behavior_id_utils.py |
| Lesson | A specific stage in Curriculum Learning where environment parameters are fixed. | ml-agents/mlagents/trainers/learn.py173 |
| Reward Signal | A module (e.g., Extrinsic, Curiosity, GAIL) that provides scalar values to the trainer to encourage specific behaviors. | ml-agents/mlagents/trainers/ppo/trainer.py112-118 |
| Run ID | A unique string identifier for a specific training session, used to name folders for models and logs. | ml-agents/mlagents/trainers/learn.py130 |
| Time Horizon | The number of steps an agent takes before the collected experiences are processed by the trainer. | ml-agents/mlagents/trainers/trainer_controller.py147 |
