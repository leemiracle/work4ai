This documentation is intended for developers who want to contribute code, documentation, or report issues.

 
## Bug Reporting Process

 The ML-Agents project uses GitHub Issues for bug tracking with a structured template system. Bug reports must include specific environment information and reproduction steps. Note that the team is unable to help reproduce bugs with custom environments; issues should be reproduced with example environments [.github/ISSUE_TEMPLATE/bug_report.md33](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ .github/ISSUE_TEMPLATE/bug_report.md?plain=1#L33-L33)

## Feature Request Process

 Feature requests follow a structured template that requires clear problem definition and solution description.

 
### Feature Request Requirements

 The feature request template requires:

 
 - **Problem Description**: Clear articulation of the issue being addressed.
 - **Proposed Solution**: Detailed description of the desired functionality.
 - **Alternative Solutions**: Consideration of other approaches.
 - **Additional Context**: Supporting information and use cases.

## Code Quality Standards

 The project enforces strict code quality standards through automated tools and configuration files.

 
### Code Style and Formatting

 
 - **Python**: Formatted using `black` [com.unity.ml-agents/CONTRIBUTING.md69-70](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/CONTRIBUTING.md?plain=1#L69-L70)
 - **C#**: Formatted using `dotnet-format` [com.unity.ml-agents/CONTRIBUTING.md72-74](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/CONTRIBUTING.md?plain=1#L72-L74)
 - **Type Annotations**: We use `mypy` for static type checking. New or refactored code must include type annotations [com.unity.ml-agents/CONTRIBUTING.md78-89](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/CONTRIBUTING.md?plain=1#L78-L89)

## Trainer Plugin System

 ML-Agents provides an extensible plugin system to define custom trainers, optimizers, and stats writers. This allows users to implement new RL algorithms (like A2C or DQN) and integrate them with the `mlagents-learn` CLI [docs/Python-Custom-Trainer-Plugin.md3-8](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Python-Custom-Trainer-Plugin.md?plain=1#L3-L8)

### Key Plugin Interfaces

 
 - **Trainer and Optimizer**: Users can extend `OnPolicyTrainer` or `OffPolicyTrainer` [docs/Tutorial-Custom-Trainer-Plugin.md12-13](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Tutorial-Custom-Trainer-Plugin.md?plain=1#L12-L13) Custom optimizers must implement the `update` method which calculates losses from an `AgentBuffer` [docs/Tutorial-Custom-Trainer-Plugin.md134-142](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Tutorial-Custom-Trainer-Plugin.md?plain=1#L134-L142)
 - **StatsWriter**: Receives information from the training process (e.g., rewards). Registered via the `mlagents.stats_writer` entry point [docs/Training-Plugins.md46-59](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Training-Plugins.md?plain=1#L46-L59)
 - **Registration**: Plugins are registered via `entry_points` in `setup.py`. For example, `ML_AGENTS_STATS_WRITER` is a constant for `mlagents.stats_writer` [docs/Training-Plugins.md19-29](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/docs/Training-Plugins.md?plain=1#L19-L29)
 
 
### StatsWriter Plugin Discovery

 The `mlagents.plugins.stats_writer.register_stats_writer_plugins` function uses `importlib.metadata` to find and load external plugins, falling back to default writers (Tensorboard, Console, Gauge) if none are found [ml-agents/mlagents/plugins/stats_writer.py32-63](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents/mlagents/plugins/stats_writer.py#L32-L63)

## Pull Request Requirements

 All contributions must follow the established pull request process.

 
### Pull Request Checklist

 
 - **Detailed Description**: Explain changes and the problem solved [com.unity.ml-agents/CONTRIBUTING.md35](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/CONTRIBUTING.md?plain=1#L35-L35)
 - **Testing**: Include unit tests and a summary of validation performed [com.unity.ml-agents/CONTRIBUTING.md36-38](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/CONTRIBUTING.md?plain=1#L36-L38)
 - **CLA**: Contributors must acknowledge the Contributor License Agreement via CLA Assistant [com.unity.ml-agents/CONTRIBUTING.md90-94](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/CONTRIBUTING.md?plain=1#L90-L94)
 - **CI**: All PRs run continuous integration; all tests must pass before merging [com.unity.ml-agents/CONTRIBUTING.md51](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/CONTRIBUTING.md?plain=1#L51-L51)
 
 
### Branch Strategy

 
 - **Main Branch**: The `main` branch corresponds to the most recent version of the project, which may be ahead of the latest release [com.unity.ml-agents/CONTRIBUTING.md28-30](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/CONTRIBUTING.md?plain=1#L28-L30)
