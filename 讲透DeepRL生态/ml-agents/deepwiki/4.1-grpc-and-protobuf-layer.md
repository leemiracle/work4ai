  The gRPC and Protobuf layer provides the low-level communication infrastructure between the Unity simulation (C#) and the Python training process. This layer ensures that complex simulation data, such as high-dimensional observations and multi-agent actions, are serialized efficiently and transmitted across a network socket with minimal overhead.

 
## System Architecture

 The communication follows a client-server model where the **Python process acts as the gRPC Server** and the **Unity process acts as the gRPC Client** [ml-agents-envs/mlagents_envs/rpc_communicator.py37](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents-envs/mlagents_envs/rpc_communicator.py#L37-L37) This design allows the Python trainer to manage multiple Unity environment instances (workers) by assigning unique ports to each [ml-agents-envs/mlagents_envs/rpc_communicator.py40-46](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents-envs/mlagents_envs/rpc_communicator.py#L40-L46)

## Key Components

 
### RpcCommunicator (C# and Python)

 The `RpcCommunicator` implements the `ICommunicator` interface on both sides, serving as the primary gateway for data exchange.

 
 - **C# Implementation**: Responsible for gathering observations from sensors and mapping them to protobuf messages via `PutObservations` [com.unity.ml-agents/Runtime/Communicator/RpcCommunicator.cs164](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Communicator/RpcCommunicator.cs#L164-L164) It manages the gRPC `Channel` and `UnityToExternalProtoClient` [com.unity.ml-agents/Runtime/Communicator/RpcCommunicator.cs52-53](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Communicator/RpcCommunicator.cs#L52-L53)
 - **Python Implementation**: Inherits from `Communicator` and manages the `grpc.server` instance [ml-agents-envs/mlagents_envs/rpc_communicator.py34-51](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents-envs/mlagents_envs/rpc_communicator.py#L34-L51) It uses a `multiprocessing.Pipe` to bridge the gRPC servicer thread with the main training loop [ml-agents-envs/mlagents_envs/rpc_communicator.py23](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents-envs/mlagents_envs/rpc_communicator.py#L23-L23)
 
 
### GrpcExtensions (C#)

 This utility class contains extension methods for converting native Unity objects into Protobuf messages.

 
 - **ToAgentInfoProto**: Converts `AgentInfo` (rewards, completion status, IDs) into `AgentInfoProto` [com.unity.ml-agents/Runtime/Communicator/GrpcExtensions.cs71-105](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Communicator/GrpcExtensions.cs#L71-L105)
 - **ToProto (BrainParameters)**: Maps brain configurations, including action space types and sizes, to `BrainParametersProto` [com.unity.ml-agents/Runtime/Communicator/GrpcExtensions.cs136-157](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Communicator/GrpcExtensions.cs#L136-L157)
 - **Capabilities Mapping**: Handles the negotiation of feature support (e.g., Hybrid Actions, Multi-Agent Groups) between the trainer and the C# SDK [com.unity.ml-agents/Runtime/Communicator/GrpcExtensions.cs175-180](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Communicator/GrpcExtensions.cs#L175-L180)
 
 
### Protobuf Message Hierarchy

 The communication is encapsulated in a `UnityMessageProto` which contains headers and payloads [com.unity.ml-agents/Runtime/Communicator/ICommunicator.cs117-124](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/com.unity.ml-agents/Runtime/Communicator/ICommunicator.cs#L117-L124)

 
| Message Level | Components | Purpose |
|---|---|---|
| Header | Status Codes (200, 400) | Indicates success or shutdown signals ml-agents-envs/mlagents_envs/rpc_communicator.py129-154 |
| UnityOutput | UnityRLOutputProto, UnityRLInitializationOutputProto | Data sent from Unity to Python (Observations, Rewards) com.unity.ml-agents/Runtime/Communicator/ICommunicator.cs119-121 |
| UnityInput | UnityRLInputProto, UnityRLInitializationInputProto | Data sent from Python to Unity (Actions, RNG Seeds) com.unity.ml-agents/Runtime/Communicator/ICommunicator.cs122-124 |

## Protocol Versioning and Compatibility

 ML-Agents uses semantic versioning for the communication API to ensure compatibility between different versions of the Unity package and the Python library.

 
 - **API_VERSION**: The current protocol version (e.g., "1.5.0") [ml-agents-envs/mlagents_envs/environment.py68](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents-envs/mlagents_envs/environment.py#L68-L68)
 - **Compatibility Check**: During initialization, the system compares the major and minor versions. If the major versions mismatch, a `UnityEnvironmentException` is raised [ml-agents-envs/mlagents_envs/environment.py91-117](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents-envs/mlagents_envs/environment.py#L91-L117)
 - **Capability Flags**: Features like `variableLengthObservation` or `multiAgentGroups` are toggled based on the `UnityRLCapabilitiesProto` exchanged during the handshake [ml-agents-envs/mlagents_envs/environment.py120-129](https://github.com/Unity-Technologies/ml-agents/blob/d52b0062/ml-agents-envs/mlagents_envs/environment.py#L120-L129)
