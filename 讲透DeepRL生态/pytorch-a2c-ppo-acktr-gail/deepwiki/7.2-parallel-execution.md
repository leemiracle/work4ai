  This page documents the parallel execution system in the pytorch-a2c-ppo-acktr-gail repository, which enables running multiple reinforcement learning experiments simultaneously using tmux. This functionality is particularly useful for conducting reproducibility studies across different random seeds and environments, allowing for more efficient hyperparameter tuning and algorithm evaluation.

 
## Purpose and Overview

 When evaluating reinforcement learning algorithms, it's essential to run experiments with multiple random seeds to assess the robustness and statistical significance of results. The parallel execution system automates this process by generating a tmux configuration that runs multiple instances of training scripts with different parameters.

 
## Components

 The parallel execution system consists of two main components:

 
 - **Configuration Generator** (`generate_tmux_yaml.py`): A Python script that generates a YAML configuration file for tmux.
 - **tmux Configuration** (`run_all.yaml`): The generated YAML file that defines the tmux session structure with multiple windows and panes.
 
 Sources: [generate_tmux_yaml.py](https://github.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/blob/41332b78/generate_tmux_yaml.py) [run_all.yaml](https://github.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/blob/41332b78/run_all.yaml)

 
## How the System Works

 The parallel execution system follows a two-step process:

 
 - **Generate Configuration**: First, you generate a tmux configuration using `generate_tmux_yaml.py` with your desired parameters.
 - **Execute Experiments**: Then, you load this configuration with tmux to run multiple experiments in parallel.

## Configuration Generator

 The `generate_tmux_yaml.py` script takes command-line arguments to customize the parallel execution setup:

 
```
--num-seeds    Number of random seeds to generate (default: 4)
--env-names    Environment names separated by semicolons (default: "PongNoFrameskip-v4")
```

 The script contains templates for different environment types:

 
| Environment Type | Template Variable | Purpose |
|---|---|---|
| MuJoCo | ppo_mujoco_template | Template for MuJoCo environments with appropriate hyperparameters |
| Atari | ppo_atari_template | Template for Atari environments with appropriate hyperparameters |

## Command-Line Arguments in Parallel Experiments

 The experiments run by the parallel execution system use specific command-line arguments tuned for each environment type:

 
### Common Arguments

 
| Argument | Description |
|---|---|
| --env-name | The environment to run (e.g., "Reacher-v2") |
| --algo | The RL algorithm to use (default: ppo) |
| --use-gae | Enable Generalized Advantage Estimation |
| --seed | Random seed for reproducibility |
| --log-dir | Directory to save logs |

 
### Environment-Specific Arguments

 Different environment types use different hyperparameters:

 
| Parameter | MuJoCo Value | Atari Value |
|---|---|---|
| Learning rate | 3e-4 | 2.5e-4 |
| Num processes | 1 | 8 |
| Num steps | 2048 | 128 |
| Num mini-batch | 32 | 4 |

## Benefits of Parallel Execution

 The parallel execution system provides several advantages:

 
 - **Efficiency**: Run multiple experiments simultaneously to significantly reduce total experiment time.
 - **Reproducibility**: Test algorithms with multiple random seeds to ensure robust results.
 - **Comparative Analysis**: Easily compare performance across different environments.
 - **Resource Utilization**: Better utilize available computing resources by running multiple experiments in parallel.
