  This document explains the experience collection system in the PyTorch A2C/PPO/ACKTR/GAIL codebase. Experience collection is a critical component of reinforcement learning algorithms, responsible for gathering and organizing agent-environment interaction data to be used by the learning algorithms. This page covers how experiences are collected during training, stored in memory, and prepared for algorithm updates.

 For information about the main training loop that uses these experiences, see [Main Training Loop](https://deepwiki.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/2.1-main-training-loop).

 
## 1. Experience Collection in Reinforcement Learning

 In reinforcement learning, an agent interacts with the environment by taking actions and observing the resulting states and rewards. These interactions generate "experiences" that are used to improve the agent's policy. In this codebase, experiences are systematically collected, stored, and processed to train the various RL algorithms.

## 2. RolloutStorage Class

 The core component for experience collection is the `RolloutStorage` class, which serves as a buffer that stores and manages all experiences gathered during training.

 
### 2.1 Purpose and Structure

 `RolloutStorage` is designed to:

 
 - Store trajectories (sequences of states, actions, rewards, etc.)
 - Compute returns and advantages
 - Generate mini-batches for training updates
 - Handle both feed-forward and recurrent policies

```

 The storage uses a 3D tensor structure:

 
 - First dimension: Time steps (length = `num_steps` + 1)
 - Second dimension: Parallel environments (length = `num_processes`)
 - Third dimension: Actual data (varies depending on the type of data)
 
 This structure allows the system to collect experiences from multiple parallel environments simultaneously, which improves training efficiency.

## 4. Processing Collected Experiences

 
### 4.1 Computing Returns

 After collecting a fixed number of experiences, the system computes returns (discounted sum of future rewards) which are used to update the policy.

 The `compute_returns` method supports two approaches:

 
 - Standard discounted returns
 - Generalized Advantage Estimation (GAE)

```

 The computation handles episode terminations via masks and also has special handling for episodes that terminate due to time limits (controlled by `use_proper_time_limits`).

 - `feed_forward_generator` - For feed-forward policies
 - `recurrent_generator` - For recurrent policies

## Summary

 The experience collection system in this codebase efficiently gathers, stores, and processes agent-environment interactions. The `RolloutStorage` class serves as the central component that manages these experiences and prepares them for policy updates. By supporting multiple parallel environments, proper handling of episode terminations, and flexible return computation methods, the system provides a robust foundation for implementing various reinforcement learning algorithms.
