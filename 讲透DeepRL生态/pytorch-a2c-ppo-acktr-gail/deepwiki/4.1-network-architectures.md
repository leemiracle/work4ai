## Overview of Network Design

 The codebase implements a modular neural network architecture system where different network types are selected based on the nature of the observation space. The system is built around a base policy class that automatically chooses the appropriate network architecture and action distribution.

## Policy Class

 The `Policy` class serves as the main interface for all neural network interactions. It automatically selects the appropriate network architecture based on observation shape and creates the correct action distribution based on action space type.

 
```

```

 The policy creation process follows these steps:

 
 - Determine the base network type based on observation shape 
 - 3D observations (images) → CNNBase
 - 1D observations (vectors) → MLPBase
 - Create appropriate action distribution based on action space 
 - Discrete action space → Categorical distribution
 - Continuous action space → DiagGaussian distribution
 - Binary action space → Bernoulli distribution
 
 Sources: [a2c_ppo_acktr/model.py15-79](https://github.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/blob/41332b78/a2c_ppo_acktr/model.py#L15-L79)

 
## Base Network Architecture (NNBase)

 All network architectures inherit from the `NNBase` class, which provides common functionality:

 
 - Support for recurrent networks through GRU (Gated Recurrent Unit)
 - Management of hidden states
 - Interface definition for derived network classes
 
 The recurrent mechanism handles sequences of observations efficiently by processing steps with non-zero masks together, which improves performance.

 Sources: [a2c_ppo_acktr/model.py82-166](https://github.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/blob/41332b78/a2c_ppo_acktr/model.py#L82-L166)

 
## CNN Architecture

 The `CNNBase` class implements a convolutional neural network designed for processing image-based observations (like Atari games).

 
### CNN Structure

 
```

```

 Key features of the CNN architecture:

 
 - Input is normalized by dividing by 255.0
 - Three convolutional layers with decreasing filter sizes and stride
 - Flattened output is passed through a fully connected layer
 - Default hidden size is 512 (configurable)
 - Orthogonal initialization for weights
 
 Sources: [a2c_ppo_acktr/model.py169-195](https://github.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/blob/41332b78/a2c_ppo_acktr/model.py#L169-L195)

 
## MLP Architecture

 The `MLPBase` class implements a multi-layer perceptron designed for vector-based observations (like MuJoCo environments).

 
### MLP Structure

 
```

```

 Key features of the MLP architecture:

 
 - Separate actor and critic networks with identical structure
 - Each network has two hidden layers with Tanh activations
 - Default hidden size is 64 (smaller than CNN's default)
 - Orthogonal initialization for weights
 - If recurrent, inputs pass through GRU first

## Recurrent Network Support

 Both network architectures can be configured to use recurrent layers (GRU). When recurrent networks are used:

 
 - The GRU processes the input/features, maintaining a hidden state across time steps
 - The hidden state is masked during environment resets (when episodes terminate)
 - For efficiency, time steps are processed in batches where possible
 
 The GRU implementation handles variable-length sequences efficiently by identifying "zero mask" points (typically at episode boundaries) and processing contiguous segments of the sequence together.
