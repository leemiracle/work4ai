## Purpose and Scope

 This document details the environment creation system in the PyTorch A2C/PPO/ACKTR/GAIL framework. The environment system is responsible for creating, configuring, and wrapping reinforcement learning environments from various sources (OpenAI Gym, Atari, DeepMind Control Suite, PyBullet) to make them compatible with the deep reinforcement learning algorithms implemented in this codebase.

 For information about environment wrappers and preprocessing, see [Environment Wrappers](https://deepwiki.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/3.2-environment-wrappers).

 
## Environment Creation Architecture

 The environment creation system is built around two core functions:

 
 - `make_env` - Creates a single environment with appropriate wrappers
 - `make_vec_envs` - Creates multiple environments and vectorizes them

### Atari-Specific Preprocessing

 Atari environments receive special preprocessing to improve learning:

 
 - **NoopResetEnv**: Performs random number of no-ops on reset (up to 30)
 - **MaxAndSkipEnv**: Skips 4 frames and returns max of last 2 frames
 - **EpisodicLifeEnv**: Treats loss of life as episode termination
 - **FireResetEnv**: Presses FIRE button on reset for games that require it
 - **WarpFrame**: Resizes frames to 84x84 and converts to grayscale
 - **ClipRewardEnv**: Clips rewards to {-1, 0, 1}

### Vectorized Environment Types

 The system supports two types of vectorized environments:

 
 - **SubprocVecEnv**: Multiple environments running in separate processes (parallel execution)
 - **DummyVecEnv**: Multiple environments running sequentially in the same process
 
 The choice depends on `num_processes` - if greater than 1, SubprocVecEnv is used for parallel execution.

## Vectorized Environment Wrappers

 After creating the vectorized environments, additional wrappers are applied:

 
### VecNormalize

 Normalizes observations and optionally rewards. This makes learning more stable by standardizing inputs to the neural network. It's only applied to environments with 1D observation spaces (typical for non-image inputs).

 Sources: [a2c_ppo_acktr/envs.py101-105](https://github.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/blob/41332b78/a2c_ppo_acktr/envs.py#L101-L105) [a2c_ppo_acktr/envs.py193-213](https://github.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/blob/41332b78/a2c_ppo_acktr/envs.py#L193-L213)

 
### VecPyTorch

 Converts observations and other data to PyTorch tensors and moves them to the specified device (CPU or GPU). This wrapper is essential for compatibility with the PyTorch-based policy networks.

 Sources: [a2c_ppo_acktr/envs.py107](https://github.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/blob/41332b78/a2c_ppo_acktr/envs.py#L107-L107) [a2c_ppo_acktr/envs.py167-190](https://github.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/blob/41332b78/a2c_ppo_acktr/envs.py#L167-L190)

 
### VecPyTorchFrameStack

 Stacks multiple frames together along the channel dimension, which is important for environments where the current frame doesn't provide full information (partially observable environments). For image observations (3D), 4 frames are stacked by default if no custom value is provided.

 Sources: [a2c_ppo_acktr/envs.py109-112](https://github.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/blob/41332b78/a2c_ppo_acktr/envs.py#L109-L112) [a2c_ppo_acktr/envs.py218-259](https://github.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/blob/41332b78/a2c_ppo_acktr/envs.py#L218-L259)

 
## Environment Wrappers

 The system includes several custom environment wrappers:

 
| Wrapper | Purpose |
|---|---|
| TimeLimitMask | Identifies episodes that terminated due to time limits rather than failure conditions |
| MaskGoal | Masks goal information after the first step (for testing recurrent policies) |
| TransposeImage | Transposes image observations to the format expected by PyTorch (CHW) |
| VecPyTorch | Converts observations to PyTorch tensors and handles device placement |
| VecNormalize | Extends the stable-baselines3 VecNormalize with training/evaluation modes |
| VecPyTorchFrameStack | Stacks observations over time to handle partial observability |

 Sources: [a2c_ppo_acktr/envs.py118-259](https://github.com/ikostrikov/pytorch-a2c-ppo-acktr-gail/blob/41332b78/a2c_ppo_acktr/envs.py#L118-L259)

 
## Integration with the Training System

 The environment creation system is primarily used in two contexts:

 
 - **Training**: Called from `main.py` to create environments for collecting experience
 - **Evaluation**: Called from `evaluation.py` to create separate environments for agent evaluation

## Custom Environment Support

 The system supports custom environments but has special handling for:

 
 - **Atari Environments**: Automatically detected and given specialized preprocessing
 - **DeepMind Control Suite**: Detected by "dm" prefix in the environment ID
 - **Image Observations**: Non-Atari environments with 3D observations require custom wrappers
 
 The system will raise an error if a non-Atari environment has 3D observations without custom wrappers, as noted in the code:

 
```
"CNN models work only for atari,
please use a custom wrapper for a custom pixel input env.
See wrap_deepmind for an example."
```
