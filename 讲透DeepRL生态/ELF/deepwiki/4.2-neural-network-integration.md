  This document explains how neural networks are integrated with Monte Carlo Tree Search (MCTS) in the ELF OpenGo platform. Neural networks serve as evaluation functions for both policy (move probabilities) and value (win probability) predictions, which guide the MCTS algorithm's decision-making process. For information on the MCTS algorithm itself, see [Tree Search Algorithm](https://deepwiki.com/pytorch/ELF/4.1-tree-search-algorithm).

 
## Overview

 ELF OpenGo's architecture closely follows the AlphaGo Zero approach, where deep neural networks replace traditional heuristics in MCTS. The neural network evaluates board positions and guides the selection and expansion of nodes in the search tree, dramatically improving the efficiency and strength of the search process.

## Key Components

 The integration between neural networks and MCTS involves several key components that work together to evaluate positions and guide the search process.

 
### MCTSActor

 The `MCTSActor` class serves as the critical bridge between MCTS and the neural network. Located in the Go-specific MCTS implementation, this class handles:

 
 - Evaluating board positions by extracting features
 - Calling the neural network for predictions
 - Processing the neural network's output to guide MCTS
 
 Key methods:

 
 - `evaluate(const GoState& s, NodeResponse* resp)`: Evaluates a single state
 - `evaluate(const vector<const GoState*>& states, vector<NodeResponse>* p_resps)`: Batch evaluation
 - `pi2response()`: Processes policy outputs, removes invalid moves, and normalizes the distribution

## Neural Network Inference During Tree Search

 The integration of neural networks with MCTS follows this specific flow:

 
```

```

 The critical steps in this process:

 
 - When a new node is visited during MCTS, the `MCTSActor` evaluates the position
 - Features are extracted from the board position
 - The neural network produces both policy (π) and value (v) predictions
 - The policy output is processed to handle invalid moves and normalize probabilities
 - The node is expanded using the processed policy
 - The value prediction is backpropagated through the search tree

## Neural Network Architecture

 The neural network in ELF OpenGo uses a dual-headed architecture:

 
```

```

 The network's architecture includes:

 
 - **Input layer**: Receives board features extracted from the current game state
 - **Residual convolutional layers**: Process the spatial features of the board
 - **Policy head**: Outputs a probability distribution over all possible moves
 - **Value head**: Outputs a scalar value estimating the probability of winning from the current position

## Neural Network Training Pipeline

 The neural network is trained using data from self-play games. This process forms a reinforcement learning loop:

 
```

```

 The training process follows these steps:

 
 - Self-play games generate training data

 
 - Board positions
 - MCTS policy distributions (targets)
 - Game outcomes (win/loss)
 - The `MCTSPrediction.update()` method processes batches of this data:

 
 - Forward pass produces policy and value predictions
 - Policy loss is calculated between MCTS policy and neural network policy
 - Value loss is calculated between game outcome and predicted value
 - Total loss is the sum of policy and value losses
 - Loss is backpropagated to update network weights
 
 This creates a reinforcement learning feedback loop where the neural network continually improves based on its own self-play games.

## UCT and Neural Network Integration

 The MCTS algorithm uses the Upper Confidence Bound for Trees (UCT) formula to balance exploration and exploitation. Neural network predictions enhance this process:

 
 - **Policy predictions (π)** are used to bias the node selection toward promising moves
 - **Value predictions (v)** serve as initial value estimates for new nodes
 - As more simulations are performed, MCTS gradually relies more on actual search results than neural network estimates

## Connection to Other System Components

 The neural network integration connects to other parts of the ELF OpenGo system:

 
 - **Feature extraction** ([Feature Extraction](https://deepwiki.com/pytorch/ELF/3.2-feature-extraction)): Converts board states into neural network inputs
 - **Self-play** ([Self-Play](https://deepwiki.com/pytorch/ELF/5.1-self-play)): Uses neural network-enhanced MCTS to generate training data
 - **Model training** ([Model Training](https://deepwiki.com/pytorch/ELF/5.2-model-training)): Updates neural network weights based on self-play results
 
 The neural network integration is a core component that enables the reinforcement learning loop that powers ELF OpenGo's learning process.
