## Overview of Monte Carlo Tree Search

 Monte Carlo Tree Search is a heuristic search algorithm that builds an asymmetric search tree through sampling. It is particularly effective for games with large branching factors like Go. The ELF implementation uses a UCT (Upper Confidence Bound for Trees) variant integrated with neural network evaluation, similar to the approach used in AlphaGo Zero.

### TreeSearchT Class

 The `TreeSearchT` class is the primary entry point for the MCTS algorithm. It coordinates multiple search threads and manages the overall search process.

 Key methods:

 
 - `run(const State&)`: Performs full MCTS search from the given state
 - `runPolicyOnly(const State&)`: Uses only the policy network without search
 - `treeAdvance(const Action&)`: Advances the search tree to a new state after an action

### TreeSearchSingleThreadT Class

 The `TreeSearchSingleThreadT` class manages the actual search process for a single thread. It performs rollouts that traverse, expand, and update the search tree.

 Key methods:

 
 - `batch_rollouts()`: Executes multiple rollouts in batch
 - `single_rollout()`: Performs a single MCTS rollout (select-expand-evaluate-backpropagate)

### Node and Edge Structure

 The tree is composed of nodes (states) connected by edges (actions). Each edge stores statistics about its traversals:

| EdgeInfo | prior_probability, reward, num_visits | Stores statistics for each action |
| Score | q, unsigned_q, prior_probability | Used for UCT calculation |

### Selection and Expansion

 During the selection phase, the algorithm traverses the tree using UCT selection:

 
 - At each node, select action with highest UCT score:

 
 - UCT score = Q-value + exploration bonus
 - Where exploration bonus is based on prior probability and visit count
 - When an unvisited node is encountered, expansion occurs:

 
 - Create a new node
 - Evaluate the state using neural network (done in batch)
 - Initialize edge statistics with policy network probabilities
 
 Sources: [src_cpp/elf/ai/tree_search/tree_search.h266-318](https://github.com/pytorch/ELF/blob/e851e786/src_cpp/elf/ai/tree_search/tree_search.h#L266-L318)

 
### Evaluation and Backpropagation

 After expanding a node:

 
 - Neural network evaluation provides:

 
 - Value estimate (V) for the current state
 - Policy probabilities (π) for all legal actions
 - Backpropagation updates all edges in the traversed path:

 
 - Increment visit counts
 - Update Q-values based on evaluation results
 - Remove virtual loss added during selection

## Parallelization Strategy

 ELF OpenGo implements an efficient parallel MCTS algorithm using multiple techniques:

 
### Multi-threaded Search


 
 - Multiple threads perform rollouts on a shared search tree
 - Virtual loss mechanism prevents threads from exploring the same paths
 - Lock-free statistics updates for better performance
 - Batch neural network evaluation across threads
 
 Key implementation details:

 
 - Each thread has its own `TreeSearchSingleThreadT` instance
 - Communication occurs through shared memory and atomic operations
 - Evaluation is batched to maximize GPU utilization

## Action Selection

 After completing the search, the final action is selected using one of several methods:

 
 - **Most Visited (`most_visited`)**: Select the action with the most visits
 - **Strongest Prior (`strongest_prior`)**: Select the action with highest prior probability
 - **Uniform Random (`uniform_random`)**: Select a random action
 
 The selection method is specified in the `options_.pick_method` parameter and implemented in the `chooseAction()` method.

## Performance Considerations

 The implementation includes several optimizations for performance:

 
 - **Virtual Loss**: Prevents thread collision during parallel search
 - **Batched Evaluation**: Evaluates multiple states in a single neural network forward pass
 - **Lock-Free Updates**: Minimizes thread contention during backpropagation
 - **Memory Management**: Efficient node allocation and deallocation
 - **Tree Reuse**: Preserves the search tree between moves using `treeAdvance()`
