## Overview

 Analysis Mode in ELF OpenGo enables detailed evaluation of existing Go games using the platform's powerful MCTS (Monte Carlo Tree Search) engine and neural networks. It allows users to process SGF (Smart Game Format) files to analyze positions, find optimal moves, and examine the AI's decision-making process. This feature is particularly valuable for game study, professional match analysis, and understanding the AI's evaluation of specific board positions.

 For information about playing against the AI through GTP (Go Text Protocol), see [GTP Mode](https://deepwiki.com/pytorch/ELF/6.3-gtp-mode). For training new models, refer to [Training Mode](https://deepwiki.com/pytorch/ELF/6.1-training-mode).

 
## How Analysis Mode Works

 Analysis Mode loads a pre-trained model and an existing SGF file, then processes the game move by move, running the MCTS algorithm at each position to evaluate the board state. For each position, it can generate detailed search trees showing the AI's thought process.

## Command Usage

 To use Analysis Mode, navigate to the `scripts/elfgames/go/` directory after building ELF and setting up the Python path. The basic command structure is:

 
```
./analysis.sh /path/to/model --preload_sgf /path/to/sgf [options]
```

 
### Core Parameters

 
| Parameter | Description |
|---|---|
| /path/to/model | Path to the trained model file (*.bin) |
| --preload_sgf | Path to the SGF file to analyze |
| --preload_sgf_move_to | Move number to analyze up to (default: analyze whole game) |
| --dump_record_prefix | Prefix for output tree files (default: "tree") |

 
### MCTS Configuration Parameters

 
| Parameter | Description | Recommended Value |
|---|---|---|
| --mcts_puct | PUCT constant for exploration | 1.50 |
| --batchsize | Neural network batch size | 16 |
| --mcts_rollout_per_batch | Rollouts per batch | 16 |
| --mcts_threads | Number of search threads | 2 |
| --mcts_rollout_per_thread | Rollouts per thread (controls thinking depth) | 8192 |
| --mcts_virtual_loss | Virtual loss for thread coordination | 1 |
| --resign_thres | Resignation threshold | 0.0 (disabled for analysis) |

## Example Command

 Here's a complete example command for analyzing a game:

 
```
./analysis.sh /path/to/model --preload_sgf /path/to/sgf --preload_sgf_move_to 50 --dump_record_prefix analysis_output --verbose --gpu 0 --mcts_puct 1.50 --batchsize 16 --mcts_rollout_per_batch 16 --mcts_threads 2 --mcts_rollout_per_thread 8192 --resign_thres 0.0 --mcts_virtual_loss 1 --num_games 1
```

 This command will:

 
 - Load the model from the specified path
 - Analyze the SGF file up to move 50
 - Output tree files with prefix "analysis_output"
 - Run on GPU 0
 - Use the recommended MCTS parameters

## Output Format

 Analysis Mode produces two primary types of output:

 
 - **Console Output**: Displayed in real-time as the analysis progresses, showing:

 
 - Current move number and player
 - AI's suggested move
 - Win rate estimation (value)
 - Policy prior probabilities
 - Search statistics
 - **Tree Files**: Detailed search tree data saved to disk with the specified prefix. Each position generates a separate tree file containing:

 
 - Complete MCTS search tree structure
 - Prior probabilities from the neural network
 - Value estimates for each node
 - Visit counts and action statistics
 
 The tree files can be used for deeper offline analysis or visualization of the AI's decision process.

## Common Use Cases

 
 - **Professional Game Analysis**: Studying high-level professional games to understand the AI's evaluation of key positions
 - **Personal Game Review**: Analyzing your own games to find mistakes and better alternatives
 - **Opening Study**: Examining various opening patterns and their evaluations
 - **Joseki Analysis**: Understanding modern joseki (standard corner sequences) and their variations
 - **Whole-board Evaluation**: Getting insights on positions that are difficult for human players to evaluate
 
 
## Tips for Effective Analysis

 
 - **Adjust Search Depth**: Increase `--mcts_rollout_per_thread` for deeper analysis of critical positions
 - **Analyze Specific Segments**: Use `--preload_sgf_move_to` to focus on particular game sections
 - **Compare Different Models**: Run analysis with different models to compare evaluations
 - **Look for Disagreements**: Pay special attention to positions where the AI's choice differs significantly from the played move
 - **Examine Tree Files**: For complex positions, examine the generated tree files to understand the AI's complete thinking process
 
 
## Limitations

 
 - Analysis may take significant time and computational resources for deep searches
 - The evaluation is based on the specific trained model used and may differ between models
 - The process runs to the end of the game automatically; to stop early, you must terminate the process manually
