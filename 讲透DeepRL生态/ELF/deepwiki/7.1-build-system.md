## 2. Root CMake Configuration

 The root `CMakeLists.txt` serves as the entry point for the build system and sets up global configuration parameters.

 
### 2.1 Compiler Requirements

 The build system performs sanity checks on the compiler version:

 
 - Requires at least GCC 7.1 when using GNU C++ compiler
 - Sets C++17 as the required C++ standard for both main code and pybind11
 
 
```

```

 Sources: [CMakeLists.txt20-50](https://github.com/pytorch/ELF/blob/e851e786/CMakeLists.txt#L20-L50)

 
### 2.2 Global Build Settings

 The root configuration sets important global build parameters:

 
 - Default build type is set to Release if not specified
 - Optimization level is set to -O3 for Release builds
 - Architecture-specific optimizations with `-march=native`
 - Includes warning flags: `-Wall -Werror -Wextra`
 - Uses Position Independent Code (`-fPIC`)
 
 Sources: [CMakeLists.txt43-50](https://github.com/pytorch/ELF/blob/e851e786/CMakeLists.txt#L43-L50)

## 4. Component Build Configuration

 The ELF OpenGo platform consists of multiple components, each with its own build configuration.

 
### 4.1 ELF Core Library

 The ELF core library is built from source files in the `src_cpp/elf` directory. It provides the fundamental components like tree search and context management.

 Sources: [CMakeLists.txt73-75](https://github.com/pytorch/ELF/blob/e851e786/CMakeLists.txt#L73-L75)

 
### 4.2 Go Game Implementation

 The Go game implementation is built from source files in the `src_cpp/elfgames/go` directory. It has two primary library targets:

 
 - `elfgames_go`: Main library for training and playing
 - `elfgames_go_inference`: Library optimized for inference

 The build system supports configuring the Go board size:

## 6. Build Process Variables

 The build system captures various variables during the build process:

 
### 6.1 Git Information

 The build system extracts Git information to include in the binary:

 
 - `GIT_COMMIT_HASH`: Current Git commit hash
 - `GIT_STAGED_STRING`: Indicates whether there are unstaged changes
 
 These variables can be used to identify the exact version of the code used to build the binary.

 Sources: [CMakeLists.txt29-39](https://github.com/pytorch/ELF/blob/e851e786/CMakeLists.txt#L29-L39)

 
## 7. Building the Project

 
### 7.1 Standard Build Process

 The standard process for building ELF OpenGo is:

 
 - Create a build directory: `mkdir build && cd build`
 - Configure with CMake: `cmake ..`
 - Build: `make -j$(nproc)`
 
 
### 7.2 Build Types

 You can specify the build type when configuring with CMake:

 
```
cmake -DCMAKE_BUILD_TYPE=Debug ..  # Debug build
cmake -DCMAKE_BUILD_TYPE=Release .. # Release build (default)
```

 
### 7.3 Custom Build Options

 You can customize the build with various options:

 
 - `-DBOARD9x9=ON`: Build with 9x9 board support instead of 19x19
