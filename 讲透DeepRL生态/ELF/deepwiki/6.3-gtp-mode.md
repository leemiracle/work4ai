## Purpose and Scope

 This document explains ELF OpenGo's GTP (Go Text Protocol) Mode, which enables the trained AI model to communicate with standard Go applications using the Go Text Protocol. GTP Mode allows the ELF OpenGo engine to be used for playing games against humans or other Go programs through a standardized text-based interface.

 For information about analyzing existing games, see [Analysis Mode](https://deepwiki.com/pytorch/ELF/6.4-analysis-mode). For details on training the model, see [Training Mode](https://deepwiki.com/pytorch/ELF/6.1-training-mode).

 
## What is GTP Mode?

 GTP Mode transforms the ELF OpenGo engine into a standard Go Text Protocol-compliant server that accepts commands through a text interface. This allows the AI to:

 
 - Integrate with any GTP-compatible Go client or GUI
 - Play against humans or other AI systems
 - Analyze board positions
 - Be used in tournaments and competitions

## System Architecture in GTP Mode

 In GTP Mode, ELF OpenGo loads a pre-trained model and initializes the Monte Carlo Tree Search (MCTS) engine to respond to GTP commands. This mode directly interfaces with the TreeSearch component to generate moves and evaluate board positions.

## Running GTP Mode

 
### Basic Usage

 To run ELF OpenGo in GTP Mode, use the `gtp.sh` script in the `scripts/elfgames/go/` directory:

 
```
./gtp.sh path/to/modelfile.bin [options]
```

 You'll need to either train a model or download a pretrained model before using GTP Mode.

 
### Command-line Parameters

 The GTP Mode accepts various parameters to configure its behavior:

 
| Parameter | Description | Default/Example |
|---|---|---|
| --verbose | Enable verbose output | -- |
| --gpu | GPU device ID to use | 0 |
| --num_block | Number of residual blocks in the neural network | 20 |
| --dim | Dimension of the neural network | 256 |
| --mcts_puct | PUCT constant for MCTS | 1.50 |
| --batchsize | Batch size for neural network evaluation | 16 |
| --mcts_rollout_per_batch | Number of rollouts per batch | 16 |
| --mcts_threads | Number of MCTS threads | 2 |
| --mcts_rollout_per_thread | Rollouts per MCTS thread | 8192 |
| --resign_thres | Resignation threshold | 0.05 |
| --mcts_virtual_loss | Virtual loss for MCTS | 1 |

 Sources: [README.rst147-148](https://github.com/pytorch/ELF/blob/e851e786/README.rst#L147-L148)

 
### Complete Example Command

 A recommended configuration for playing against the bot:

 
```
./gtp.sh path/to/modelfile.bin --verbose --gpu 0 --num_block 20 --dim 256 --mcts_puct 1.50 --batchsize 16 --mcts_rollout_per_batch 16 --mcts_threads 2 --mcts_rollout_per_thread 8192 --resign_thres 0.05 --mcts_virtual_loss 1
```

 This configuration works well for gameplay. The thinking time per move can be adjusted by changing the `mcts_rollout_per_thread` parameter.

## Performance Tuning

 The performance and playing strength of ELF OpenGo in GTP Mode can be adjusted through several key parameters:

 
### MCTS Configuration

 The Monte Carlo Tree Search is the core component that determines the strength of the engine:

 
| Parameter | Effect | Recommended Range |
|---|---|---|
| mcts_rollout_per_thread | Thinking time per move (higher = stronger but slower) | 1024-16384 |
| mcts_threads | Parallel search threads | 1-8 |
| mcts_puct | Exploration constant (higher = more exploration) | 1.0-2.0 |
| resign_thres | Threshold for resignation (lower = less likely to resign) | 0.01-0.1 |

 
### Hardware Recommendations

 For optimal performance in GTP Mode:

 
 - Use a GPU with at least 4GB of VRAM
 - Adjust batch size according to your GPU memory
 - For CPU-only usage, reduce `mcts_rollout_per_thread` and `batchsize`
 
 
## Practical Examples

 
### Starting a Game

 
 - Launch ELF OpenGo in GTP Mode with the command shown above
 - Enter GTP commands to set up and play the game:
 
 
```
boardsize 19
clear_board
komi 7.5
time_settings 1800 30 5
genmove b
```

 
### Playing Against Other GTP Engines

 ELF OpenGo can be used with Go GUI applications that support GTP, such as Sabaki, GoGui, or Lizzie. Configure these applications to use the `gtp.sh` script as the GTP engine.

 
## Troubleshooting

 
| Issue | Possible Solution |
|---|---|
| Slow move generation | Reduce mcts_rollout_per_thread or increase batch size |
| GPU out of memory | Reduce batchsize or use a GPU with more memory |
| Poor play quality | Ensure you're using a fully trained model file |
| Unrecognized GTP command | Check command syntax or consult GTP specification |
