## Core Requirements

 ELF OpenGo has several fundamental requirements for building and running:

 
 - **C++ Compiler with C++17 Support**: The codebase requires at least GCC 7.1 or an equivalent compiler with full C++17 support.
 - **CMake**: Version 3.3 or higher is required for the build system.
 - **Python**: Required for the neural network training components and various scripts.

## Detailed Dependency Descriptions

 
### Threading Building Blocks (TBB)

 TBB is used for parallel programming to efficiently utilize multi-core processors. The library provides task scheduling, concurrent containers, and parallel algorithms.

 Configuration:

 
 - Built from source located in `third_party/tbb/`
 - Configured with CMake via TBBBuild.cmake
 
 Sources: [third_party/CMakeLists.txt26-33](https://github.com/pytorch/ELF/blob/e851e786/third_party/CMakeLists.txt#L26-L33)

 
### ZeroMQ (ZMQ)

 ZeroMQ is a high-performance asynchronous messaging library used for the distributed communication architecture in ELF OpenGo. It enables the server-client architecture where the server handles model training and clients generate self-play games.

 Configuration:

 
 - Expected to be installed on the system
 - Found through CMake's find_path and find_library commands
 
 Sources: [third_party/CMakeLists.txt37-49](https://github.com/pytorch/ELF/blob/e851e786/third_party/CMakeLists.txt#L37-L49)

 
### cppzmq

 C++ bindings for the ZeroMQ library, providing a more C++-friendly interface.

 Configuration:

 
 - Header-only library included from `third_party/cppzmq/`
 - Linked with the system ZeroMQ library
 
 Sources: [third_party/CMakeLists.txt53-55](https://github.com/pytorch/ELF/blob/e851e786/third_party/CMakeLists.txt#L53-L55)

 
### concurrentqueue

 A lock-free concurrent queue implementation for efficient thread-safe data exchange.

 Configuration:

 
 - Header-only library included from `third_party/concurrentqueue`
 - Linked with pthread
 
 Sources: [third_party/CMakeLists.txt16-22](https://github.com/pytorch/ELF/blob/e851e786/third_party/CMakeLists.txt#L16-L22)

 
### googletest

 The Google Testing and Mocking Framework used for unit testing the C++ components.

 Configuration:

 
 - Built from source located in `third_party/googletest`
 - Configured to not add a debug postfix to the library name
 
 Sources: [third_party/CMakeLists.txt5-9](https://github.com/pytorch/ELF/blob/e851e786/third_party/CMakeLists.txt#L5-L9)

 
### nlohmann/json

 A modern JSON library for C++ used for configuration files and data serialization.

 Configuration:

 
 - Included as a subdirectory from `third_party/json`
 
 Sources: [third_party/CMakeLists.txt10](https://github.com/pytorch/ELF/blob/e851e786/third_party/CMakeLists.txt#L10-L10)

 
### pybind11

 Seamless operability between C++ and Python, essential for integrating the C++ game logic with Python-based neural network training.

 Configuration:

 
 - Included as a subdirectory from `third_party/pybind11`
 - Configured to use C++17 standard
 
 Sources: [third_party/CMakeLists.txt11](https://github.com/pytorch/ELF/blob/e851e786/third_party/CMakeLists.txt#L11-L11) [CMakeLists.txt44](https://github.com/pytorch/ELF/blob/e851e786/CMakeLists.txt#L44-L44)

 
### spdlog

 A fast C++ logging library that provides both synchronous and asynchronous logging capabilities.

 Configuration:

 
 - Included as a subdirectory from `third_party/spdlog`
 
 Sources: [third_party/CMakeLists.txt12](https://github.com/pytorch/ELF/blob/e851e786/third_party/CMakeLists.txt#L12-L12)

 
## Dependency Management

 ELF OpenGo manages dependencies through a combination of:

 
 - **Git Submodules**: Most third-party libraries are included as git submodules in the `third_party/` directory.
 - **System Dependencies**: ZeroMQ is expected to be installed on the system.
 - **CMake**: The build system uses CMake to find, configure, and build dependencies as needed.

## Compiler Requirements and Flags

 The ELF OpenGo codebase requires specific compiler features and flags:

 
 - **C++17**: The codebase uses C++17 language features
 - **GCC 7.1+**: If using GCC, version 7.1 or newer is required
 - **Compiler Flags**: The build uses `-Wall -Werror -Wextra` and other flags for strict error checking
 - **Optimization**: Release builds use `-O3` optimization
 - **Architecture**: Compiled with `-march=native` for architecture-specific optimizations
 
 Sources: [CMakeLists.txt21-50](https://github.com/pytorch/ELF/blob/e851e786/CMakeLists.txt#L21-L50)
