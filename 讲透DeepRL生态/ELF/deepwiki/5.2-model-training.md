## Model Loading Architecture

 Model loading is a critical part of the training process, as it handles initialization of new models or loading of existing models for continued training. The `ModelLoader` class serves as the primary interface for loading model parameters and configurations.

### ModelLoader Class

 The `ModelLoader` class is responsible for loading models from saved files, applying configuration options, and preparing models for training. Key features include:

 
 - **Configuration Options**: Manages options for model loading, including file paths, GPU settings, and FP16 support
 - **Model Initialization**: Creates model instances based on provided model classes
 - **State Loading**: Loads model states from saved files, with support for key omission and prefix replacement
 - **GPU Support**: Handles moving models to GPU if specified
 
 The class provides a clean interface between model files and the training system, abstracting away the complexities of model loading and configuration.

## Environment Setup

 The `load_env` function in the model loader module provides a comprehensive way to set up the training environment. It loads the game module, model classes, and method classes based on environment variables and configures them with appropriate options.

 Key components initialized during environment setup:

 
| Component | Purpose |
|---|---|
| Game | Handles game rules and board representation |
| Method | Implements the learning algorithm |
| Sampler | Manages data sampling from game records |
| ModelInterface | Provides interface to neural network models |
| ModelLoaders | Loads and configures models for training |

 The function returns an environment dictionary containing all these components, ready for use in the training loop.

## Model Checkpoint and Loading Options

 The ModelLoader provides flexible options for checkpoint management:

 
| Option | Description | Default |
|---|---|---|
| load | Path to the model file to load | '' (empty) |
| onload | Functions to call after loading (e.g., reset layers) | [] |
| omit_keys | Keys to omit when loading the model | [] |
| replace_prefix | Prefixes to replace in the state dict | [] |
| gpu | Which GPU to use (-1 for CPU) | -1 |
| use_fp16 | Whether to use FP16 precision | False |
| check_loaded_options | Check consistency of loaded vs. current options | True |

 These options provide fine-grained control over how models are loaded and initialized during training.
