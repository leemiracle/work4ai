  This page documents the non-Atari environments supported by Dopamine, including standard Gym environments, MuJoCo continuous control environments, and Brax physics-based environments. For information about Atari-specific environments, see [Atari Environments](https://deepwiki.com/google/dopamine/3.1-atari-environments).

 
## Environment Support Overview

 Dopamine supports multiple environment types beyond Atari games to enable research across a variety of reinforcement learning domains. These include:

 
 - **Gym Environments** - Classic control problems like CartPole, Acrobot, and MountainCar
 - **MuJoCo Environments** - Continuous control physics simulations like Ant, HalfCheetah, and Humanoid
 - **Brax Environments** - Accelerated physics environments that run efficiently on accelerators

 Key parameters for `create_gym_environment`:

 
 - `environment_name`: Name of the Gym environment (e.g., 'CartPole', 'Acrobot')
 - `version`: Environment version (typically 'v0' or 'v1')
 - `use_legacy_gym`: Whether to use the legacy Gym API instead of Gymnasium
 - `use_ppo_preprocessing`: Whether to apply PPO-specific preprocessing like observation and reward normalization

 Dopamine provides specialized network architectures for various Gym environments:

 Sources: [dopamine/discrete_domains/gym_lib.py56-57](https://github.com/google/dopamine/blob/bec5f4e1/dopamine/discrete_domains/gym_lib.py#L56-L57) [dopamine/discrete_domains/gym_lib.py60-101](https://github.com/google/dopamine/blob/bec5f4e1/dopamine/discrete_domains/gym_lib.py#L60-L101)

 MuJoCo environments are accessed using the standard Gym interface, but they differ from classic control problems in that they:

 
 - Require continuous action spaces
 - Have higher-dimensional state and action spaces
 - Are designed for physics-based locomotion and manipulation tasks

## Common Environment Interface

 All environment types in Dopamine implement a common interface to ensure compatibility with agents:

 
```

```

 Key methods and properties for environment compatibility:

 
 - `observation_space`: Shape of observations returned by the environment
 - `action_space`: Shape or number of valid actions
 - `reset()`: Resets the environment and returns initial observation
 - `step(action)`: Executes action and returns (observation, reward, done, info)
 - `game_over`: Flag indicating true termination (vs timeout)

## Network Architecture Selection

 Dopamine provides specialized network architectures for different environment types. These networks handle the unique input/output requirements of each environment:

 
```

```

 Each network architecture is designed to handle the specific observation space and normalization requirements of its target environment:

 
 - **Basic Discrete Domain Network**: Foundation for Gym environments, normalizes inputs to [-1, 1]
 - **Fourier Network Architecture**: Alternative approach using Fourier basis functions
 - **Actor-Critic Networks**: Used for continuous control environments
