## Purpose and Scope

 The Atari 100k benchmark is a data-efficient reinforcement learning evaluation protocol where agents are trained for only 100,000 environment steps (equivalent to 400,000 frames of interaction) and then evaluated. This system represents Dopamine's implementation of various data-efficient RL algorithms designed specifically for this benchmark. It focuses on achieving high performance with limited training samples rather than unlimited environment interactions.

 For the implementation of core RL algorithms used as building blocks for these data-efficient variants, see [Agent Implementations](https://deepwiki.com/google/dopamine/2-agent-implementations).

## Supported Data-Efficient Agents

 The Atari 100k framework supports several agent types that have been specifically optimized for data-efficient learning:

 
| Agent Name | Description | Key Features |
|---|---|---|
| DER | Data Efficient Rainbow | Modified Rainbow agent with adjusted hyperparameters and update frequency |
| OTRainbow | Over-trained Rainbow | Rainbow variant that performs multiple updates per step (8x) |
| DrQ | Data-regularized Q | Uses data augmentation to improve sample efficiency |
| DrQ(ε) | DrQ with epsilon exploration | Variant of DrQ with different exploration strategy |
| SPR | Self-Predictive Representations | Uses self-supervised representation learning |

 All agents (except SPR) are based on the `Atari100kRainbowAgent` class, which extends the full Rainbow implementation with data-efficiency improvements.

## Runner System

 The Atari 100k module introduces specialized runners to handle the unique requirements of the data-efficient RL evaluation protocol.

 
### DataEfficientAtariRunner

 The primary runner in the Atari 100k system is the `DataEfficientAtariRunner`, which enforces a strict cap on the number of training steps and provides parallel evaluation capabilities.

 
```

```

 Key features of `DataEfficientAtariRunner`:

 
 - **Strict Step Counting**: Ensures exactly 100k environment steps (400k frames) are used for training
 - **Parallel Environments**: Supports running multiple environments in parallel for more efficient evaluation
 - **Episode-Based Evaluation**: Evaluates agents based on 100 complete episodes after training
 - **No-op Starts**: Implements random no-op starts at the beginning of episodes for more robust evaluation
 
 The runner also handles:

 
 - Checkpointing and logging of experiment progress
 - Computing and reporting normalized scores for cross-game comparison (optional)
 - Integration with TensorBoard for visualizing training progress
 
 Sources: [dopamine/labs/atari_100k/atari_100k_runner.py46-621](https://github.com/google/dopamine/blob/bec5f4e1/dopamine/labs/atari_100k/atari_100k_runner.py#L46-L621)

 
### Legacy MaxEpisodeEvalRunner

 For compatibility and simpler debugging, the system also includes a legacy runner (`MaxEpisodeEvalRunner`) that doesn't use parallel evaluation environments. This runner is easier to understand but slower and doesn't guarantee that a precise number of training steps will be collected.

## Training and Evaluation Process

 The Atari 100k training and evaluation process follows a specific protocol to ensure reproducibility and fair comparison across implementations.

 
```

```

 
### Training Configuration

 The training process has several standardized settings across all agents:

 
 - **Training Steps**: 100,000 environment steps (400,000 frames)
 - **Maximum Episode Length**: 27,000 steps per episode
 - **Evaluation Protocol**: 100 complete episodes after training
 - **Replay Buffer Size**: 1,000,000 transitions (effectively unbounded)
 - **Batch Size**: 32 transitions per update
 - **No Sticky Actions**: The benchmark specifically disables sticky actions

## Performance Considerations

 When running Atari 100k experiments, there are several important considerations:

 
 - **Runner Selection**: The legacy runner (`MaxEpisodeEvalRunner`) is easier to understand but slower and less precise than `DataEfficientAtariRunner`.
 - **Parallel Evaluation**: Using parallel evaluation environments (`parallel_eval=True`) significantly speeds up the evaluation phase but requires more memory.
 - **Random Seed**: The random seed is set based on the run number (`--run_number` flag) to ensure reproducibility across experiments.
 - **Normalized Scores**: For comparing performance across different games, the system can log normalized scores that account for different score ranges in different games.

## References

 The Atari 100k benchmark and the agents implemented in this system are based on several academic papers:

 
 - **DER** (Data Efficient Rainbow): "When to use parametric models in reinforcement learning?" (van Hasselt et al., 2019)
 - **OTRainbow** (Over-trained Rainbow): "Importance of using appropriate baselines for evaluation of data-efficiency in deep reinforcement learning for Atari" (Kielak, 2020)
 - **DrQ** (Data-regularized Q): "Image Augmentation Is All You Need: Regularizing Deep Reinforcement Learning from Pixels" (Yarats et al., 2020)
 - **DrQ(ε)**: "Deep Reinforcement Learning at the Edge of the Statistical Precipice" (Agarwal et al., 2021)
 - **SPR** (Self-Predictive Representations): Implemented as a specialized agent type
 
 The original Atari 100k benchmark was introduced in "Model-based reinforcement learning for Atari" (Kaiser et al., 2019).
