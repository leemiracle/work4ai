  **Purpose**: This page describes how rewards are defined and computed in MAgent. It covers both constant rewards assigned to agent types and dynamic event-based reward rules using symbolic expressions. For information about how rewards are retrieved during training, see [Training Workflow](https://deepwiki.com/geek-ai/MAgent/4.1-training-workflow).

 MAgent provides a flexible reward system that supports both simple constant rewards and complex event-triggered reward rules with boolean composition. Rewards can be assigned to specific agents, any agent matching a condition, or all agents in a group.

 
## Overview of Reward Types

 MAgent supports two categories of rewards:

 
| Reward Type | Definition Location | When Evaluated | Examples |
|---|---|---|---|
| Constant Rewards | Agent type attributes | Every step or on specific actions | step_reward, attack_penalty, kill_reward, dead_penalty |
| Event-Based Rewards | Config reward rules | When events are triggered | Cooperative attack, reaching goals, collision |

 Both types are configured in Python during environment setup and serialized to the C++ engine for efficient runtime evaluation.

## Constant Rewards from Agent Type Attributes

 Constant rewards are defined as attributes when registering an agent type using `Config.register_agent_type()`. These rewards are automatically applied by the C++ engine without requiring explicit reward rules.

 
### Available Constant Reward Attributes

 
```

```

 
| Attribute | Type | Description |
|---|---|---|
| step_reward | float | Added to agent's reward every simulation step |
| kill_reward | float | Reward gained when agent successfully kills another agent |
| dead_penalty | float | Reward assigned when agent dies (typically negative) |
| attack_penalty | float | Reward for performing attack action (used to discourage wasteful attacks) |

 These constant rewards are processed by the C++ engine during each step and accumulated into the agent's total reward, which can be retrieved via `env.get_reward(handle)`.

### AgentSymbol: Representing Agents in Rules

 The `AgentSymbol` class [python/magent/gridworld.py654-676](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L654-L676) represents agents that participate in reward rules. It can refer to specific agents or patterns of agents.

 
```

```

 
| Index Value | Type | Meaning | Use Case |
|---|---|---|---|
| 'any' | str | Matches any single agent in group | Pattern matching in events |
| 'all' | str | Matches all agents in group | Conditions requiring group coordination |
| integer | int | Specific agent ID | Deterministic rules for specific agents |

 When `index='any'` is used, the symbol acts as a variable that matches any agent satisfying the event condition. This enables flexible pattern-based reward rules.

 Event predicates define conditions that can trigger rewards. The `EventNode` class [python/magent/gridworld.py571-652](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L571-L652) implements these as an expression tree.

#### Available Event Predicates

 
| Predicate | Syntax | Description | C++ Op Code |
|---|---|---|---|
| 'kill' | Event(subject, 'kill', object) | Subject kills object | OP_KILL = 3 |
| 'attack' | Event(subject, 'attack', object) | Subject attacks object | OP_ATTACK = 7 |
| 'at' | Event(subject, 'at', (x, y)) | Subject is at position (x, y) | OP_AT = 4 |
| 'in' | Event(subject, 'in', [(x1,y1), (x2,y2)]) | Subject is in rectangular region | OP_IN = 5 |
| 'collide' | Event(subject, 'collide', object) | Subject collides with object | OP_COLLIDE = 6 |
| 'die' | Event(subject, 'die') | Subject dies | OP_DIE = 8 |
| 'in_a_line' | Event(subject, 'in_a_line') | Agents form a line | OP_IN_A_LINE = 9 |
| 'align' | Event(subject, 'align') | Agents align in formation | OP_ALIGN = 10 |

## Serialization Process

 The event expressions and reward rules defined in Python are serialized and sent to the C++ engine for efficient runtime evaluation. This happens automatically during `GridWorld` initialization.

 
```

```

 
### Serialization Algorithm

 The serialization process [python/magent/gridworld.py493-565](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L493-L565) performs the following steps:

 
 - **Collect Agent Symbols**: Traverse all reward rules and collect unique `AgentSymbol` instances, assigning each a unique integer ID (`symbol2int` dict)
 - **Collect Event Nodes**: Traverse event expression trees and collect all `EventNode` instances, assigning unique IDs (`event2int` dict)
 - **Send Symbol Definitions**: For each symbol, call `_LIB.gridworld_define_agent_symbol(game, id, group, index)` to register it in C++
 - **Send Event Definitions**: For each event node:

 
 - Convert symbolic inputs to integer IDs
 - Call `_LIB.gridworld_define_event_node(game, id, op, inputs, n_inputs)`
 - This reconstructs the expression tree in C++
 - **Send Reward Rules**: For each rule:

 
 - Convert receivers and event to integer IDs
 - Call `_LIB.gridworld_add_reward_rule(game, on_event_id, receiver_ids, values, n_receivers, terminal)`

## Reward Rules in Built-in Scenarios

 MAgent provides several built-in configurations with pre-defined reward rules. These are located in `python/magent/builtin/config/`:

 
### Battle Scenario

 
 - Constant rewards: `step_reward`, `kill_reward`, `dead_penalty`, `attack_penalty`
 - No additional event-based rules (relies on constant rewards)
 - Agents learn to maximize kills while minimizing deaths
 
 
### Pursuit Scenario

 
 - Predators get `kill_reward` for killing prey
 - Predators get `attack_penalty` to discourage empty attacks
 - Prey get survival bonus via positive `step_reward`
 
 
### Arrangement Scenario

 
 - Uses `'at'` event predicate for goal reaching
 - Terminal rewards when agents reach target positions
 - Formation rewards using `'align'` or `'in_a_line'` predicates

## Performance Considerations

 
 - **Pre-compilation**: Reward rules are serialized once during initialization, eliminating Python overhead during simulation
 - **Pattern Matching Efficiency**: The C++ engine uses optimized data structures for matching `'any'` symbols against actual agents
 - **Batch Evaluation**: Rewards are computed for all agents simultaneously during the step, leveraging spatial indexing
 - **Memory Layout**: Rewards are accumulated directly in agent objects and batch-copied to Python only when requested
 
 These optimizations enable MAgent to efficiently handle complex reward rules for millions of agents.

## Summary

 The MAgent reward system provides two complementary mechanisms:

 
 - **Constant Rewards**: Simple attributes defined on agent types, automatically applied by the C++ engine
 - **Event-Based Rewards**: Complex symbolic rules with pattern matching and boolean composition
 
 The system achieves flexibility through Python configuration while maintaining performance through C++ runtime evaluation. Symbolic agent references and event predicates enable expressing sophisticated multi-agent coordination rewards with concise, readable code.
