## Deep Q-Network (DQN)

 
### Algorithm Characteristics

 DQN is an **off-policy, value-based** algorithm that learns a Q-function approximating the expected cumulative reward for each action. Key features:

 
 - **Experience Replay**: Stores transitions in a replay buffer and samples randomly for training
 - **Target Network**: Uses a separate target network updated periodically for stability
 - **ε-greedy Exploration**: Balances exploration and exploitation
 - **Batch Training**: Trains after each episode completes
 
 
### Hyperparameters

|---|---|---|

| memory_size | 2^20 (1M) | Replay buffer capacity |
| learning_rate | 1e-4 to 3e-4 | Adam optimizer learning rate |
| target_update | 1200 | Target network update frequency (steps) |
| train_freq | 5 | Training frequency (steps) |

## Deep Recurrent Q-Network (DRQN)

 
### Algorithm Characteristics

 DRQN extends DQN with **recurrent layers (LSTM/GRU)** to handle:

 
 - **Partial Observability**: Agents may not see the full state
 - **Temporal Dependencies**: Current action depends on history
 - **Sequential Decision Making**: Memory of past observations
 
 The key difference from DQN is that DRQN processes **sequences of observations** rather than individual transitions.

 
### Hyperparameters

 
```

```

 
| Parameter | Typical Value | Description |
|---|---|---|
| batch_size | 32 (256/8) | Number of sequences per batch |
| unroll_step | 8-16 | Length of each sequence (timesteps) |
| memory_size | 8 * 625 | Replay buffer size (sequences, not transitions) |
| learning_rate | 1e-4 to 3e-4 | Optimizer learning rate |
| target_update | 1200 | Target network update frequency |
| train_freq | 5 | Training frequency |

 **Key Difference**: `memory_size` is much smaller than DQN because it stores sequences rather than individual transitions.

 **Sources:** [examples/train_battle.py179-184](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_battle.py#L179-L184) [examples/train_against.py198-203](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_against.py#L198-L203)

## Advantage Actor-Critic (A2C)

 
### Algorithm Characteristics

 A2C is an **on-policy, policy gradient** algorithm that:

 
 - **Learns Policy Directly**: Outputs action probabilities rather than Q-values
 - **On-policy Training**: Trains on current policy samples (no replay buffer)
 - **Value Function Baseline**: Reduces variance using advantage estimation
 - **Synchronous Updates**: Multiple actors collect data synchronously
 
 A2C differs fundamentally from DQN/DRQN in that it trains **during the episode** rather than after.

 
### Hyperparameters

 
```

```

 
| Parameter | Typical Value | Description |
|---|---|---|
| learning_rate | 1e-3 | Higher than DQN due to on-policy nature |
| step_batch_size | ~10 * n_agents | Trigger training after collecting N agent transitions |

 **Note**: A2C does **not** use `memory_size`, `target_update`, or `train_freq` because it doesn't maintain a replay buffer.

 **Sources:** [examples/train_against.py205-209](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_against.py#L205-L209)

 
### Training Pattern

 
```

```

 A2C trains **during the episode** when enough transitions are collected, unlike DQN which trains after episode completion.

 **Sources:** [examples/train_against.py99-118](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_against.py#L99-L118)

### Feature Comparison Table

 
| Feature | DQN | DRQN | A2C |
|---|---|---|---|
| Framework | TensorFlow | TensorFlow | MXNet |
| Policy Type | Value-based (Q-function) | Value-based (Q-function) | Policy gradient |
| Memory Type | Replay buffer (transitions) | Replay buffer (sequences) | No replay buffer |
| Training Time | After episode | After episode | During episode |
| Observation | Single frame | Sequence of frames | Single frame |
| Sample Efficiency | High | High | Low |
| Memory Usage | High (~4-8 GB) | Medium (~0.5-1 GB) | Low (no buffer) |
| Adaptation Speed | Slow | Slow | Fast |
| Best For | Fully observable | Partial observability | Fast convergence |

## Algorithm Selection Guide

 
### Decision Tree

 
```

```

 
### Scenario Recommendations

 
#### Use DQN when:

 
 - Environment is **fully observable** (agents see relevant information)
 - **Sample efficiency** is important (limited compute budget)
 - Environment dynamics are **relatively stationary**
 - Large replay buffer memory is available
 
 
#### Use DRQN when:

 
 - Environment has **partial observability** (fog of war, limited view)
 - Actions depend on **temporal patterns** (history matters)
 - Agents need to **remember past observations**
 - Willing to trade sample efficiency for memory handling
 
 
#### Use A2C when:

 
 - Need **fast convergence** (fewer episodes to good performance)
 - Training against **non-stationary opponents** (opponent adapts)
 - **Memory constraints** (limited RAM for replay buffer)
 - Can afford **less sample efficiency** (more interactions needed)
 - Implementing **cooperative** multi-agent scenarios
 
 **Sources:** [examples/train_battle.py145-196](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_battle.py#L145-L196) [examples/train_against.py148-209](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_against.py#L148-L209)

```

```

 - **Rounds 0-700**: ε = 1.0 (pure exploration)
