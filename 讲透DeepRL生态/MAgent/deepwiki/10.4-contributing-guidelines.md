## Code Style Guidelines

 MAgent uses a mixed Python and C++ codebase. Contributors should follow the established conventions in each language.

 
### Python Code Style

 The Python codebase follows PEP 8 conventions with some project-specific patterns.

 **Import Organization**:

 
```

```

 **Naming Conventions**:

 
| Entity Type | Convention | Example |
|---|---|---|
| Classes | PascalCase | GridWorld, ProcessingModel, AgentSymbol |
| Functions/Methods | snake_case | get_observation(), set_action(), add_reward_rule() |
| Private Methods | _snake_case | _get_obs_buf(), _serialize_event_exp() |
| Constants | UPPER_SNAKE_CASE | OBS_INDEX_VIEW, OP_ATTACK |
| Module Variables | snake_case | group_handles, obs_bufs |

 **Docstring Format**: The codebase uses NumPy-style docstrings with sections for Parameters, Returns, Examples, and Notes.

 
```

```

 **Type Handling**:

 
 - NumPy arrays should have explicit dtype specifications: `np.empty((n,), dtype=np.float32)`
 - ctypes conversions should use helper functions: `as_float_c_array()`, `as_int32_c_array()`
 - Handle objects are `ctypes.c_int32()` types

### C++ Code Style

 The C++ engine follows standard C++ conventions with emphasis on performance.

 **File Organization**:

 
 - Header files (`.h`) contain class declarations and inline functions
 - Implementation files (`.cc`) contain method definitions
 - Source code is located in [src/](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/)
 
 **Naming Conventions**:

 
| Entity Type | Convention | Example |
|---|---|---|
| Classes | PascalCase | GridWorld, Map, Agent |
| Methods | camelCase or snake_case | step(), reset(), clear_dead() |
| Member Variables | snake_case with _ suffix | agent_types_, groups_ |
| Constants | UPPER_SNAKE_CASE | OP_KILL, OP_ATTACK |

 **Performance Considerations**:

 
 - Use OpenMP pragmas for parallelizable loops: `#pragma omp parallel for`
 - Prefer stack allocation for small objects
 - Use move semantics for large object transfers
 - Minimize memory allocations in hot paths

### Contribution Type Guidelines

 **Adding New RL Algorithms**:

 
 - Implement in [python/magent/builtin/tf_model.py](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/builtin/tf_model.py) (TensorFlow) or [python/magent/builtin/mx_model.py](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/builtin/mx_model.py) (MXNet)
 - Follow the interface pattern of existing algorithms (DQN, DRQN, A2C)
 - Required methods: `infer_action()`, `sample_step()`, `train()`, `save()`, `load()`
 - Add example training script in [examples/](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/) demonstrating usage
 
 **Adding New Game Scenarios**:

 
 - Create configuration file in [python/magent/builtin/config/](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/builtin/config/)
 - Define agent types with `register_agent_type()`
 - Set up groups with `add_group()`
 - Define reward rules using `add_reward_rule()`
 - Create training script in [examples/](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/) (e.g., `train_newgame.py`)
 - Add interactive demo if applicable (e.g., `show_newgame.py`)
 
 **Modifying C++ Engine**:

 
 - Changes to simulation logic: [src/GridWorld.cc](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/GridWorld.cc) [src/GridWorld.h](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/GridWorld.h)
 - Changes to spatial operations: [src/Map.cc](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/Map.cc) [src/Map.h](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/Map.h)
 - Update ctypes bindings in [python/magent/c_lib.py](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/c_lib.py) if adding new API functions
 - Update Python wrapper in [python/magent/gridworld.py](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py) for new functionality
 
 **Extending Python API**:

 
 - Add methods to [python/magent/gridworld.py14-482](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L14-L482) for GridWorld class
 - Ensure ctypes calls match C++ function signatures
 - Add appropriate docstrings following NumPy style

### Minimum Testing Requirements

 
| Change Type | Required Tests |
|---|---|
| Python API Changes | Run examples/api_demo.py, verify output matches expected behavior |
| C++ Engine Changes | Full rebuild with bash build.sh, run at least two different examples |
| New Algorithm | Training script runs for 100+ rounds without errors, agents show learning |
| New Scenario | Environment initialization succeeds, step execution completes, rendering works |
| Bug Fix | Original failing case now passes, related functionality unaffected |

 **Testing Checklist**:

 
 - Build succeeds on target platform (Linux or macOS)
 - Python imports work: `import magent; env = magent.GridWorld("battle")`
 - At least one example script runs to completion: `python examples/api_demo.py`
 - No memory leaks or segmentation faults during execution
 - Performance regression: FPS not significantly degraded for existing scenarios
 - Documentation updated to reflect changes

## Documentation Requirements

 All contributions should include appropriate documentation updates.

 
### Documentation Locations

 
| Documentation Type | Location | When to Update |
|---|---|---|
| API Documentation | Docstrings in .py files | Any API change |
| Getting Started | doc/get_started.md | New features, workflow changes |
| README | README.md | Installation changes, new examples |
| Example Comments | examples/*.py | New example scripts |
| Inline Comments | Source code | Complex algorithms, non-obvious logic |

 
### Docstring Requirements

 For Python functions and classes, include:

 
 - One-line summary
 - `Parameters` section with types and descriptions
 - `Returns` section with types and descriptions
 - `Examples` section showing usage
 - `Notes` section for implementation details or warnings

### Documentation for New Features

 When adding new features, document:

 
 - **Purpose**: What problem does it solve?
 - **Usage**: How to use it with code examples
 - **Configuration**: Any new configuration parameters
 - **Limitations**: Known constraints or edge cases
 - **Integration**: How it interacts with existing systems

### Code Review Process

 **What Reviewers Look For**:

 
 - **Correctness**: Does the code do what it claims?
 - **Style**: Does it follow established conventions?
 - **Performance**: Are there obvious inefficiencies?
 - **Safety**: Memory management, null checks, bounds checking
 - **Documentation**: Are changes adequately documented?
 - **Tests**: Are there sufficient tests?
 
 **Responding to Reviews**:

 
 - Address all comments, even if just to acknowledge
 - If disagreeing, explain reasoning respectfully
 - Make requested changes in new commits (don't force-push until approved)
 - Mark conversations as resolved when addressed

## Special Considerations

 
### Multi-Language Changes

 When changes span Python and C++:

 
 - **Update C++ first**: Implement engine changes in [src/](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/)
 - **Rebuild**: Run `bash build.sh`
 - **Update ctypes bindings**: Modify [python/magent/c_lib.py](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/c_lib.py) if new functions added
 - **Update Python wrapper**: Modify [python/magent/gridworld.py](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py) to expose functionality
 - **Update documentation**: Document in both code and [doc/](https://github.com/geek-ai/MAgent/blob/2144dbd4/doc/) as needed
 - **Test end-to-end**: Verify Python to C++ communication works
 
 
### Performance-Critical Changes

 For changes affecting simulation performance:

 
 - **Benchmark before**: Record FPS for relevant scenarios
 - **Implement change**: Make modifications
 - **Benchmark after**: Compare performance
 - **Document impact**: Include benchmark results in PR
 - **Consider OpenMP**: Ensure thread-safety if parallelizing

### Breaking Changes

 Breaking changes should be avoided when possible. If necessary:

 
 - **Justify**: Explain why breaking change is needed
 - **Document**: Clearly mark as breaking in PR title: `[BREAKING] Description`
 - **Migration guide**: Provide instructions for updating existing code
 - **Deprecation period**: If possible, add deprecation warnings first
 - **Version bump**: Ensure version number reflects breaking change

## Communication

 
### Reporting Issues

 Before contributing, search existing issues. When reporting new issues:

 **Bug Reports** should include:

 
 - MAgent version/commit hash
 - Operating system and version
 - Python version
 - Steps to reproduce
 - Expected vs actual behavior
 - Error messages and stack traces
 - Minimal code example
 
 **Feature Requests** should include:

 
 - Clear description of proposed feature
 - Use case explanation
 - Example API or usage pattern
 - Willingness to implement
 
 
### Getting Help

 For questions about contributing:

 
 - Check existing documentation in [doc/](https://github.com/geek-ai/MAgent/blob/2144dbd4/doc/)
 - Search closed issues and PRs for similar questions
 - Open a new issue with the "question" label
 - Reference specific code locations in your question
