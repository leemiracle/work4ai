## Purpose and Scope

 This document describes MAgent's browser-based visualization system, which provides a web frontend for viewing simulations remotely. The web renderer operates independently from the local PyGame renderer and communicates with a backend server via WebSocket protocol to receive and display simulation frames. This system enables headless training with remote viewing, replay of recorded simulations, and sharing of visualization data without requiring local installation of rendering dependencies.

 For information about local visualization with PyGame, see [PyGame Renderer](https://deepwiki.com/geek-ai/MAgent/6.1-pygame-renderer). For details on the server implementations that provide data to renderers, see [Server Implementations](https://deepwiki.com/geek-ai/MAgent/6.4-server-implementations).

### Message Protocol

 
| Message Type | Format | Description |
|---|---|---|
| i | i<frame_count>\|<config_json> | Initialization with total frames and style configuration |
| f | f<events>;<agents>;<breads>;<obstacles>;<pixels>;<numbers> | Frame data containing all entities |
| e | e<error_message> | Error notification |
| l | l<config_file>,<map_file> | Load file request (client to server) |
| p | p<frame_id> <x1> <y1> <x2> <y2> | Request specific frame with viewport bounds |

#### Frame Data Message (`f`)

 Frame data is sent as a semicolon-separated string containing five sections:

 
| Section | Format | Purpose |
|---|---|---|
| Events | type id x y\|... | Attack events (type 0) with agent ID and target coordinates |
| Agents | id x y group dir hp\|... | All agents with position, group, direction, and health |
| Breads | x y type\|... | Resource items (for gather scenarios) |
| Obstacles | x y\|... | Wall/obstacle positions |
| Pixels | rgba rgba ... | Raw pixel data for minimap (packed 32-bit integers) |
| Numbers | count count ... | Agent count per group |

## Animation and Interpolation

 The web renderer implements smooth animation between discrete simulation frames using linear interpolation.

 
### Animation State Variables

 
| Variable | Purpose |
|---|---|
| _mapAnimateTick | Current animation progress (0 to TOTAL_STEP) |
| _mapSpeed | Animation speed increment per frame (default 250) |
| ANIMATE_STEP | Total animation steps (typically 1000) |
| TOTAL_STEP | Threshold before requesting next frame |
| _mapStatus | Current state: 'STOP', 'PLAY', 'PAUSE', 'WAITING' |

## Performance Considerations

 
### Viewport Culling

 Frame requests include viewport bounds to reduce data transfer:

 
```

```

 The server only sends entities within the specified viewport, reducing bandwidth for large simulations [src/render/frontend/js/render-handle.js269-272](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/render/frontend/js/render-handle.js#L269-L272)

 
### Adaptive Rendering

 Certain visual elements are only drawn when the grid size is sufficiently large:

 
 - **Attack ranges**: Only drawn when `gridSize >= 4` [src/render/frontend/js/render-handle.js454](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/render/frontend/js/render-handle.js#L454-L454)
 - **HP bars**: Only drawn when `gridSize >= 6` [src/render/frontend/js/render-handle.js493](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/render/frontend/js/render-handle.js#L493-L493)
 - **Event lines**: Only drawn when `gridSize >= 4` [src/render/frontend/js/render-handle.js546](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/render/frontend/js/render-handle.js#L546-L546)
 
 This optimization improves performance when zoomed out to view many agents.

 
### Canvas Management

 The system uses separate canvases for static vs. dynamic content:

 
 - **Static layers** (`_staticCTX`, `_gridCTX`): Only redrawn when viewport or grid size changes [src/render/frontend/js/render-handle.js659-664](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/render/frontend/js/render-handle.js#L659-L664)
 - **Dynamic layers** (agents, events, HP): Redrawn every animation frame [src/render/frontend/js/render-handle.js671-674](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/render/frontend/js/render-handle.js#L671-L674)
 
 This minimizes unnecessary redrawing of unchanged content.

 
### Frame Rate Monitoring

 The system tracks both FPS (frames per second) and IPS (images per second):

 
 - **FPS**: Browser rendering frame rate (via `requestAnimationFrame`) [src/render/frontend/js/render-handle.js152](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/render/frontend/js/render-handle.js#L152-L152)
 - **IPS**: Simulation frame processing rate [src/render/frontend/js/render-handle.js151](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/render/frontend/js/render-handle.js#L151-L151)
 
 These metrics are displayed in the status overlay and updated every `STATUS_FPS_PERIOD` milliseconds [src/render/frontend/js/render-handle.js148-157](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/render/frontend/js/render-handle.js#L148-L157)
