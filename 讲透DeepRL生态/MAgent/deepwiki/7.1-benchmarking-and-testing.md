## Purpose and Scope

 This document covers the performance testing and benchmarking infrastructure in MAgent. It explains how to measure simulation throughput (FPS), evaluate scalability across different agent counts, and analyze the impact of various hardware configurations (CPU threads, GPU utilization). The focus is on the built-in benchmarking scripts that systematically test MAgent's performance characteristics.

 For information about general parallelization strategies and optimization techniques, see [Parallelization Strategies](https://deepwiki.com/geek-ai/MAgent/7.2-parallelization-strategies). For guidance on scaling to very large simulations, see [Scaling to Millions of Agents](https://deepwiki.com/geek-ai/MAgent/7.3-scaling-to-millions-of-agents).

## Testing Infrastructure Overview

 MAgent provides dedicated performance testing scripts in the `scripts/test/` directory. These scripts create controlled environments to measure throughput under different conditions, helping users understand the performance characteristics before deploying large-scale simulations.

 
### Available Test Scripts

 
| Script | Purpose | Key Metrics |
|---|---|---|
| test_1m.py | Single benchmark run with configurable agent count | Per-operation timing, FPS, agent survival |
| test_fps.py | Automated benchmarking across multiple configurations | FPS across agent counts and GPU counts |

 These scripts use a simplified predator-prey scenario to isolate performance measurement from complex game logic.

 **Sources:** [scripts/test/test_1m.py1-130](https://github.com/geek-ai/MAgent/blob/2144dbd4/scripts/test/test_1m.py#L1-L130) [scripts/test/test_fps.py1-49](https://github.com/geek-ai/MAgent/blob/2144dbd4/scripts/test/test_fps.py#L1-L49)

### FPS Calculation

 Final throughput is calculated as:

 
```
FPS = (n_step - skip) / total_time
```

 This represents the number of complete simulation steps executed per second, where each step involves:

 
 - Observation retrieval for all agents
 - Action inference for all agents
 - Environment stepping (collision detection, reward calculation, agent updates)
 - Reward retrieval
 - Dead agent cleanup
 
 **Sources:** [scripts/test/test_1m.py129](https://github.com/geek-ai/MAgent/blob/2144dbd4/scripts/test/test_1m.py#L129-L129)

## The test_fps.py Script

 The `test_fps.py` script automates the execution of `test_1m.py` across multiple configurations to generate comprehensive performance profiles.

 
### Automated Benchmarking Matrix

 
```

```

 **Diagram: test_fps.py Benchmarking Workflow**

 **Sources:** [scripts/test/test_fps.py1-49](https://github.com/geek-ai/MAgent/blob/2144dbd4/scripts/test/test_fps.py#L1-L49)

 
### Test Configuration Matrix

 The script defines two arrays that form a testing matrix:

 
| Variable | Values | Description |
|---|---|---|
| number | [1000, 10000, 100000, 1000000] | Agent populations to test |
| gpus | range(0, max_gpu+1) | GPU configurations (0 = CPU-only) |

 For each combination, it:

 
 - Calculates adaptive step count: `n_step = 30000000 / n` (maintains constant total agent-steps)
 - Sets OpenMP thread count based on population size
 - Executes `test_1m.py` with appropriate parameters
 - Extracts FPS from output
 
 **Sources:** [scripts/test/test_fps.py22-44](https://github.com/geek-ai/MAgent/blob/2144dbd4/scripts/test/test_fps.py#L22-L44)

 
### Thread Count Strategy

 
```

```

 The script uses fewer threads for smaller populations to reduce threading overhead, and more threads for large populations to maximize parallelism. This aligns with the C++ engine's OpenMP implementation in the simulation step.

 **Sources:** [scripts/test/test_fps.py33-36](https://github.com/geek-ai/MAgent/blob/2144dbd4/scripts/test/test_fps.py#L33-L36)

 
### Output Processing

 The script captures FPS values by:

 
 - Redirecting `test_1m.py` output to `/dev/shm/aha` (in-memory filesystem for speed)
 - Extracting the FPS line with `grep FPS`
 - Writing to temporary file `tmp-{name}`
 - Parsing with `eval(line)[1]` to extract the numeric value
 
 The final output is a matrix printed using `magent.round()` for clean formatting.

 **Sources:** [scripts/test/test_fps.py31-42](https://github.com/geek-ai/MAgent/blob/2144dbd4/scripts/test/test_fps.py#L31-L42) [scripts/test/test_fps.py47-48](https://github.com/geek-ai/MAgent/blob/2144dbd4/scripts/test/test_fps.py#L47-L48)

## Performance Metrics

 
### Key Measurements

 The benchmarking scripts track multiple performance dimensions:

 
| Metric | Description | Units | Typical Range |
|---|---|---|---|
| FPS | Complete simulation steps per second | steps/sec | 10-1000 |
| get obs | Time to retrieve all observations | seconds | 0.001-0.1 |
| infer act | Time for action inference | seconds | 0.001-0.5 |
| set act | Time to set all actions | seconds | 0.0001-0.01 |
| step | Core simulation step time | seconds | 0.001-0.1 |
| get reward | Time to retrieve rewards | seconds | 0.0001-0.01 |
| clear | Dead agent cleanup time | seconds | 0.0001-0.01 |

 
### Bottleneck Identification

 By examining individual operation timings, you can identify performance bottlenecks:

 
 - **step dominates**: C++ engine is the bottleneck (spatial operations, collision detection)
 - **infer act dominates**: Model inference is slow (consider GPU, batch size tuning)
 - **get obs dominates**: Observation extraction overhead (channel count, view range)
 
 **Sources:** [scripts/test/test_1m.py99-113](https://github.com/geek-ai/MAgent/blob/2144dbd4/scripts/test/test_1m.py#L99-L113)

### Scalability Analysis

 Ideal scalability would show:

 
 - **Linear scaling with GPUs**: 2x GPUs → 2x FPS (for inference-heavy workloads)
 - **Sublinear scaling with agents**: 10x agents → 5-7x reduction in FPS (spatial algorithms are O(n log n))
 
 Real-world results typically show:

 
 - **Strong scaling**: Adding GPUs helps significantly for large populations with neural network models
 - **Weak scaling**: FPS decreases faster than linear as agent count increases due to interaction complexity
 
 
### Per-Operation Analysis

 Examine the timing breakdown printed by `test_1m.py`:

 
```
===== step 25 =====
get obs 1   0.01234
infer act 1 0.00156
set act 1   0.00023
get obs 2   0.01189
infer act 2 0.00145
set act 2   0.00021
step        0.05678
get reward  0.00089

all time: 0.09
```

 In this example:

 
 - `step` (0.057s) is the dominant operation → C++ simulation is the bottleneck
 - Observation retrieval (0.012s each) is the second major cost
 - Inference is fast (0.0015s) → GPU is well-utilized or RandomActor is used

## Performance Considerations

 
### Factors Affecting Throughput

 
| Factor | Impact | Optimization Strategy |
|---|---|---|
| Agent count | O(n log n) | Limit population or use simpler scenarios |
| View range | Quadratic in range | Reduce view_range in AgentType config |
| Observation channels | Linear | Minimize feature count in observation space |
| GPU count | Linear (inference) | Add GPUs for large neural network models |
| CPU threads | Sublinear | Tune OMP_NUM_THREADS (typically CPU_count / 2) |
| Map size | Weak impact | Should be proportional to agent count |
| Model complexity | Linear in params | Use smaller networks for real-time requirements |

 
### Memory Considerations

 For very large populations:

 
 - Observation arrays scale as `(agent_count, view_size, view_size, channels)`
 - Consider using `infer_batch_size` parameter to control GPU memory usage
 - The test scripts use `infer_batch_size=100000` which is suitable for most GPUs
 
 **Sources:** [scripts/test/test_1m.py85-86](https://github.com/geek-ai/MAgent/blob/2144dbd4/scripts/test/test_1m.py#L85-L86)

 
### Comparison with Real Training

 Benchmark results represent **best-case performance** because:

 
 - No actual training occurs (no backward passes)
 - No model checkpointing or logging overhead
 - Simplified environment with minimal reward rules
 - No visualization or rendering
 
 Real training scenarios typically achieve 50-70% of benchmark FPS due to these additional costs.

## Summary

 The MAgent benchmarking infrastructure provides:

 
 - **test_1m.py**: Detailed single-run benchmarks with per-operation timing
 - **test_fps.py**: Automated multi-configuration performance profiling
 - **Granular metrics**: Separate timing for observation, inference, stepping, and rewards
 - **Scalability testing**: Support for 1K to 1M+ agent populations
 - **Hardware comparison**: Systematic testing across CPU-only and multi-GPU configurations
 
 Use these tools to:

 
 - Validate hardware setup before large experiments
 - Compare different model architectures
 - Identify performance bottlenecks
 - Set realistic expectations for training time
 - Guide resource allocation decisions
 
 For deeper performance optimization, see [Parallelization Strategies](https://deepwiki.com/geek-ai/MAgent/7.2-parallelization-strategies) and [Scaling to Millions of Agents](https://deepwiki.com/geek-ai/MAgent/7.3-scaling-to-millions-of-agents).
