## Purpose and Scope

 This document describes the structure and organization of agent observations in MAgent. Observations consist of two components: a **spatial local view** and a **non-spatial feature vector**. This page explains how observation spaces are configured, how channels are organized, and how observations are retrieved from the environment.

 For information about configuring agent types and their view ranges, see [Agent Types and Groups](https://deepwiki.com/geek-ai/MAgent/2.2-agent-types-and-groups). For details about the environment lifecycle and simulation stepping, see [GridWorld Environment](https://deepwiki.com/geek-ai/MAgent/2.1-gridworld-environment).

## Spatial View Channels

 The spatial view provides a local window around each agent, showing nearby walls, agents, and other environmental features. The view is organized into multiple channels, similar to image channels in computer vision.

 
### View Dimensions and Masking

 The spatial view size is determined by the agent's `view_range` configuration. For a circular view with radius `r`, the view dimensions are `(2*r + 1) × (2*r + 1)`. The view is then masked according to the range type (circle or sector).

 **View Range Types**

 
 - `CircleRange(radius)`: Full circular view around the agent
 - `SectorRange(radius, angle)`: Sector-shaped view in the agent's facing direction
 
 Sources: [doc/get_started.md22-23](https://github.com/geek-ai/MAgent/blob/2144dbd4/doc/get_started.md?plain=1#L22-L23)

 
### Channel Organization

 The `n_channel` dimension organizes different types of spatial information. The total number of channels depends on the number of groups and enabled modes.

 **Channel Calculation**

 
```

```

 The channel layout is computed by `group2channel()`:

 
```
n_channel = 1 (wall) + [1 if food_mode] + n_groups × (2 or 3)
```

 where the multiplier is 2 for basic mode (has, hp) or 3 for minimap mode (has, hp, minimap).

 Sources: [src/gridworld/GridWorld.cc915-924](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L915-L924)

 
### Per-Group Channel Details

 For each group in the environment, the observation includes multiple channels:

 
| Channel Index | Channel Name | Data Type | Description |
|---|---|---|---|
| Base | Wall | Binary (0/1) | Indicates presence of walls |
| Base+1 | Food (optional) | Binary (0/1) | Indicates food locations if food_mode=True |
| Base+N | Group N Presence | Binary (0/1) | Indicates presence of agents from group N |
| Base+N+1 | Group N HP | Normalized (0-1) | Health points of agents from group N |
| Base+N+2 | Group N Minimap (optional) | Normalized (0-1) | Minimap view of group N agents |

 The channel indices are permuted per group to make the observation **agent-centric**: the observing agent's own group always appears at the first group channel position. This permutation is handled by `make_channel_trans()`.

## Non-Spatial Feature Vector

 The feature vector contains agent-specific information that is not spatially organized.

 **Feature Vector Layout**

 

### Feature Components

 
| Component | Size | Type | Description |
|---|---|---|---|
| ID Embedding | embedding_size | Binary | Binary representation of agent's unique ID |
| Last Action | n_action | One-hot | Last action taken by the agent |
| Last Reward | 1 | Float | Reward received in the last step |
| Position X | 1 | Normalized (0-1) | Normalized x-coordinate (if minimap_mode=True) |
| Position Y | 1 | Normalized (0-1) | Normalized y-coordinate (if minimap_mode=True) |

 **Feature Size Calculation**

 
```
feature_size = embedding_size + n_action + 1
               + [2 if minimap_mode]
               + [2 if goal_mode]
```

### ID Embedding

 Each agent has a unique integer ID. The ID embedding is the binary representation of this ID, providing a fixed-size encoding that helps the agent maintain identity consistency across episodes.

 The embedding is filled by `Agent::get_embedding()`.

 Sources: [src/gridworld/GridWorld.cc387](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L387-L387)

 
### Last Action (One-Hot)

 The last action is encoded as a one-hot vector over the agent's action space. This allows the agent to condition current decisions on previous actions, which is important for learning temporal policies.

 Sources: [src/gridworld/GridWorld.cc390](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L390-L390)

 
### Last Reward

 The scalar reward received in the previous timestep. This provides immediate feedback signal in the observation.

 Sources: [src/gridworld/GridWorld.cc392](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L392-L392)

 
### Absolute Position (Optional)

 When `minimap_mode=True`, the agent's absolute position on the map is included as normalized coordinates (x/width, y/height). This complements the minimap by providing precise self-localization.

## Configuration Options

 Several configuration options affect the observation space structure. These are set via `GridWorld.set_config()` or in agent type registration.

 **Configuration Parameters**

 
| Parameter | Type | Effect on Observation |
|---|---|---|
| embedding_size | int | Sets size of ID embedding in feature vector |
| minimap_mode | bool | Adds minimap channel and position features |
| food_mode | bool | Adds food channel to spatial view |
| goal_mode | bool | Adds goal position to feature vector (deprecated) |
| view_range | Range | Determines spatial view dimensions |

## Summary

 MAgent's observation space provides rich spatial and non-spatial information to agents:

 
 - **Spatial View**: Multi-channel grid showing walls, agents (by group), HP, and optional minimap
 - **Feature Vector**: ID embedding, last action, last reward, and optional position
 
 The observation structure is highly configurable through agent types and environment modes. All observation extraction is parallelized in C++ for efficient handling of large numbers of agents.

 Key implementation details:

 
 - Channel permutation makes observations agent-centric
 - Minimap provides global awareness while maintaining local detail
 - Feature vector enables temporal reasoning through last action/reward
 - OpenMP parallelization enables efficient batch observation extraction
