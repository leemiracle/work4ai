## Purpose and Scope

 This document describes the interactive demonstration applications provided with MAgent, where users can actively control and interact with agents during simulation. These demos showcase the platform's rendering capabilities and provide hands-on experience with trained models.

 For information about the underlying rendering system, see [PyGame Renderer](https://deepwiki.com/geek-ai/MAgent/6.1-pygame-renderer). For server architecture details, see [Server Implementations](https://deepwiki.com/geek-ai/MAgent/6.4-server-implementations). For web-based visualization, see [Web-Based Rendering](https://deepwiki.com/geek-ai/MAgent/6.2-web-based-rendering).

 
## Overview

 MAgent provides two primary interactive demos that allow users to control agents in real-time:

 
| Demo Script | Server | Purpose | User Role |
|---|---|---|---|
| show_battle_game.py | BattleServer | Two-team combat | Act as general, dispatch soldiers |
| show_arrange.py | ArrangeServer | Pattern formation | Provide target text/patterns |

 These demos differ from passive visualization tools by enabling direct user interaction with the simulation. They load pre-trained models from checkpoints and allow users to influence agent behavior through keyboard and mouse controls.

 **Key Characteristics:**

 
 - Load trained models from `data/models/` directory
 - Use `PyGameRenderer` for real-time display
 - Implement user input handling through `Server` classes
 - Run synchronously with user interaction
 
 Sources: [examples/show_battle_game.py1-16](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/show_battle_game.py#L1-L16) [examples/show_arrange.py1-23](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/show_arrange.py#L1-L23)

## Battle Game Demo

 
### Purpose

 The Battle Game demo (`show_battle_game.py`) provides an interactive two-team combat scenario where the user acts as a general commanding one team of soldiers against an opponent team.

 
### Running the Demo

 
```

```

 **Prerequisites:**

 
 - Pre-trained battle models must exist in `data/models/battle-game/`
 - Pygame must be installed
 - The script automatically checks model existence via `magent.utility.check_model('battle-game')`
 
 Sources: [examples/show_battle_game.py1-16](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/show_battle_game.py#L1-L16)

 
### Implementation Details

 
```

```

 The implementation consists of three key steps [examples/show_battle_game.py14-15](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/show_battle_game.py#L14-L15):

 
 - **Model Validation**: `magent.utility.check_model('battle-game')` verifies checkpoint files exist
 - **Server Instantiation**: `Server()` creates a `BattleServer` instance with loaded models
 - **Renderer Start**: `PyGameRenderer().start(Server())` initializes display and enters interactive loop
 
 Sources: [examples/show_battle_game.py1-16](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/show_battle_game.py#L1-L16)

 
### User Controls

 The Battle Game demo supports these interactions:

 
| Control | Action |
|---|---|
| Mouse Click | Select/target agents |
| Keyboard | Issue movement/attack commands |
| Zoom/Pan | Navigate battlefield view |
| Pause/Resume | Control simulation flow |

 The `BattleServer` interprets user input and translates it into environment actions for the controlled team.

 Sources: [examples/show_battle_game.py1-16](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/show_battle_game.py#L1-L16)

 
## Arrange Demo

 
### Purpose

 The Arrange demo (`show_arrange.py`) demonstrates cooperative multi-agent learning by having agents form target patterns or spell words provided by the user.

 
### Running the Demo

 
```

```

 **Command-Line Arguments:**

 
| Argument | Type | Default | Description |
|---|---|---|---|
| --mess | str[] | required | Words/characters to display |
| --mode | int | 0 | 0: open space, 1: with maze obstacles |

 Sources: [examples/show_arrange.py15-18](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/show_arrange.py#L15-L18)

 
### Implementation Details

 
```

```

 The arrange demo extends the basic pattern with configuration [examples/show_arrange.py15-22](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/show_arrange.py#L15-L22):

 
 - **Argument Parsing**: Extracts user-provided messages and mode setting
 - **Model Validation**: `magent.utility.check_model('arrange')` verifies checkpoint files
 - **Server Configuration**: `Server(messages=args.mess, mode=args.mode)` creates server with user parameters
 - **Custom Grid Size**: `grid_size=3.5` parameter adjusts display scaling for better visibility
 
 Sources: [examples/show_arrange.py1-23](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/show_arrange.py#L1-L23)

 
### Interactive Features

 The Arrange demo provides:

 **Target Setting:**

 
 - User specifies target text via command-line arguments
 - Multiple words can be provided as separate arguments
 - Agents receive goals to move to positions forming these characters
 
 **Environment Modes:**

 
 - **Mode 0**: Open space - agents navigate freely to target positions
 - **Mode 1**: Maze mode - obstacles added, requiring pathfinding
 
 **Visual Feedback:**

 
 - Goal positions highlighted on screen
 - Agent progress toward targets visualized
 - Formation success indicated by color/position
 
 Sources: [examples/show_arrange.py15-22](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/show_arrange.py#L15-L22)

### Model Checkpoint Requirements

 Before running interactive demos, ensure model checkpoints exist:

 **Directory Structure:**

 
```
data/
└── models/
    ├── battle-game/
    │   ├── model.ckpt
    │   └── config.json
    └── arrange/
        ├── model.ckpt
        └── config.json
```

 The `check_model()` utility function validates this structure:

 
 - Verifies checkpoint directory exists
 - Checks for required model files
 - Exits gracefully with error message if models missing
 
 To generate models, run corresponding training scripts (see [Training Workflow](https://deepwiki.com/geek-ai/MAgent/4.1-training-workflow)).

## Common Controls and Interface

 
### Renderer Control Keys

 While specific controls vary by demo, the `PyGameRenderer` provides these standard controls:

 
| Key/Control | Function |
|---|---|
| ESC | Exit demo |
| SPACE | Pause/unpause simulation |
| +/- | Zoom in/out |
| Arrow Keys | Pan view |
| Mouse Wheel | Zoom control |
| Left Click | Select/interact with agents (demo-specific) |

 
### Display Elements

 The renderer shows multiple information layers:

 
 - **Grid Background**: Environment terrain and obstacles
 - **Agent Layer**: Colored dots/sprites representing agents
 - **HP Bars**: Health status above agents
 - **Minimap**: Overview of entire environment (bottom-left)
 - **Info Panel**: Statistics and control hints (top)
 
 For detailed rendering architecture, see [PyGame Renderer](https://deepwiki.com/geek-ai/MAgent/6.1-pygame-renderer).

| Component | Role in Demos | Reference |
|---|---|---|

 - **User-facing applications**: Showcase trained agents and allow interaction
