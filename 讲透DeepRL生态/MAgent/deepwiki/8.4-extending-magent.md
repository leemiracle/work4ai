### ProcessingModel Communication Protocol

 The `ProcessingModel` uses a **command-based protocol** over pipes/sockets:

 
| Command | Parameters | Purpose |
|---|---|---|
| 'act' | policy, eps, NDArrayPackage(view, feature, ids) | Request action inference |
| 'sample' | NDArrayPackage(rewards, alives) | Record transition |
| 'train' | print_every | Trigger training |
| 'save' | save_dir, epoch | Save checkpoint |
| 'load' | save_dir, epoch, name | Load checkpoint |
| 'quit' | - | Shutdown subprocess |

## Summary: Extension Points

 
| Extension Type | Files to Modify | Key Classes/Functions |
|---|---|---|
| New RL Algorithm | your_algorithm.py | BaseModel, infer_action, train |
| Custom Observations | GridWorld.cc | GridWorld::get_observation, group2channel, get_feature_size |
| New Agent Properties | AgentType.h/cc, GridWorld.cc | AgentType, register_agent_type |
| New Actions | GridWorld.cc | set_action, step |
| Custom Map Features | Map.h/cc | Map class methods |
| Backend Visualization | GridWorld.cc | get_info |
| Frontend Visualization | render-handle.js, index.html | Canvas context, drawing functions |

 **General workflow for C++ extensions:**

 
 - Modify C++ source files
 - Run `bash build.sh` to recompile
 - Update Python bindings if adding new C++ functions
 - Test with Python training scripts
 
 **General workflow for algorithm extensions:**

 
 - Implement `BaseModel` interface
 - Test standalone (without `ProcessingModel`)
 - Integrate with `ProcessingModel` for parallel training
 - Verify with multi-agent scenarios
