## Purpose and Scope

 This page explains how to design complex reward rules in MAgent using the event expression system. Custom reward functions allow you to specify rewards based on symbolic agent references and boolean event predicates that are compiled to efficient C++ code at runtime.

 For basic reward concepts (constant rewards defined in agent types), see [Reward System](https://deepwiki.com/geek-ai/MAgent/2.5-reward-system). For defining complete custom environments, see [Creating Custom Environments](https://deepwiki.com/geek-ai/MAgent/8.1-creating-custom-environments).

 
---

 
## Overview

 MAgent's reward system supports two mechanisms:

 
 - **Constant rewards**: Defined as agent type attributes (`step_reward`, `kill_reward`, `dead_penalty`, `attack_penalty`)
 - **Event-based rules**: Defined using symbolic expressions that trigger rewards when specific conditions occur
 
 This page focuses on event-based rules, which enable sophisticated multi-agent reward shaping such as:

 
 - Cooperative rewards (e.g., "two agents must attack simultaneously")
 - Spatial rewards (e.g., "agent reaches specific location")
 - Conditional rewards (e.g., "reward if agent A kills agent B but not agent C")
 
 **Architecture**: Reward rules are defined in Python using symbolic expressions, serialized to integer arrays, and transmitted to the C++ engine where they are evaluated efficiently during simulation.

### Available Event Predicates

 [python/magent/gridworld.py596-632](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L596-L632)

 
| Predicate | Syntax | C++ Op Code | Description |
|---|---|---|---|
| 'kill' | Event(a, 'kill', b) | OP_KILL = 3 | Agent a reduces agent b's HP to 0 |
| 'attack' | Event(a, 'attack', b) | OP_ATTACK = 7 | Agent a performs attack action on b |
| 'die' | Event(a, 'die') | OP_DIE = 8 | Agent a's HP reaches 0 |
| 'at' | Event(a, 'at', (x, y)) | OP_AT = 4 | Agent a is at exact position (x, y) |
| 'in' | Event(a, 'in', ((x1,y1), (x2,y2))) | OP_IN = 5 | Agent a is within rectangle |
| 'collide' | Event(a, 'collide', b) | OP_COLLIDE = 6 | Agent a collides with b |
| 'in_a_line' | Event(a, 'in_a_line') | OP_IN_A_LINE = 9 | Agent a is aligned in a line |
| 'align' | Event(a, 'align') | OP_ALIGN = 10 | Agent a is part of aligned formation |

 
### Boolean Composition

 Events can be combined using Python operators:

 
| Python Operator | EventNode Method | C++ Op Code | Semantics |
|---|---|---|---|
| e1 & e2 | __and__() | OP_AND = 0 | Both events must occur |
| `e1 | e2` | __or__() | OP_OR = 1 |
| ~e1 | __invert__() | OP_NOT = 2 | Event does not occur |

 **Phase 1: Symbol Collection** [python/magent/gridworld.py497-517](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L497-L517)

 
 - Traverse all reward rules
 - For each rule, recursively traverse the `EventNode` tree via `inputs`
 - Assign unique integer ID to each `AgentSymbol`
 - Store mapping in `symbol2int` dictionary
 
 **Phase 2: Event Node Collection** [python/magent/gridworld.py519-532](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L519-L532)

 
 - Traverse all reward rules
 - Depth-first traversal of `EventNode` tree
 - Assign unique integer ID to each `EventNode`
 - Store mapping in `event2int` dictionary

## Performance Considerations

 
### Efficient Rule Design

 
| Recommendation | Rationale |
|---|---|
| Minimize rule count | Each rule adds overhead to C++ evaluation loop |
| Use constant rewards for simple cases | Agent type attributes (step_reward, etc.) are faster than event rules |
| Avoid redundant predicates | Event(a, 'kill', b) already implies Event(b, 'die') |
| Prefer simple boolean expressions | Deep expression trees increase evaluation time |

 
### Serialization Overhead

 
 - Serialization happens once during environment initialization: [python/magent/gridworld.py89](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L89-L89)
 - Runtime evaluation is purely C++: no Python overhead
 - Complex event trees are flattened to efficient integer-based structures
 
 
### Debugging Tips

 When reward rules don't behave as expected:

 
 - **Check agent symbol scope**: Ensure symbols used in events appear in `receiver` list
 - **Test incrementally**: Add one rule at a time
 - **Verify group handles**: Use correct handles from `config.add_group()`
 - **Print reward values**: Use `env.get_reward(handle)` to inspect actual rewards received
