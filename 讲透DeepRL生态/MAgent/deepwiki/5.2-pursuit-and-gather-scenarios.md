## Purpose and Scope

 This page documents the **Pursuit** and **Gather** scenarios, two fundamental multi-agent reinforcement learning environments provided with MAgent. These scenarios demonstrate predator-prey dynamics and resource gathering behavior in large-scale agent populations.

 For information about competitive team battles, see [Battle Scenario](https://deepwiki.com/geek-ai/MAgent/5.1-battle-scenario). For cooperative formation tasks, see [Arrangement Task](https://deepwiki.com/geek-ai/MAgent/5.3-arrangement-task).

 
---

 
## Overview

 MAgent provides two related but distinct scenarios that explore different multi-agent behaviors:

 
| Scenario | Agents | Objective | Key Challenge |
|---|---|---|---|
| Pursuit | Predators, Prey | Predators hunt prey through cooperation | Coordination and encirclement tactics |
| Gather | Gatherers | Collect food resources efficiently | Resource competition and exploration |

 Both scenarios emphasize emergent cooperative behavior and scale to thousands of agents simultaneously.

## Pursuit Scenario

 
### Concept and Objectives

 The **Pursuit scenario** implements predator-prey dynamics where multiple predator agents learn to cooperatively hunt prey agents. Predators receive rewards for attacking prey, incentivizing them to coordinate their movements to surround and eliminate targets.

 The environment demonstrates **emergent cooperative behavior**: trained predators learn to encircle prey and execute coordinated attacks without explicit communication protocols.

### Reward Structure

 Rewards are configured through both **agent type attributes** and **event-based rules**:

 - `kill_reward`: Positive reward when this agent type is killed (for prey)
 - `dead_penalty`: Negative reward when agent dies
 - `step_reward`: Reward per simulation step

## Gather Scenario

 
### Concept and Objectives

 The **Gather scenario** focuses on resource collection behavior. Agents must explore the environment to locate and collect food resources while potentially competing with other agents for the same resources.

 This scenario emphasizes:

 
 - **Exploration strategies**: Balancing exploration vs. exploitation
 - **Resource competition**: Multiple agents competing for limited food
 - **Efficient path planning**: Minimizing steps to maximize collection

### Agent Configuration

 Gatherer agents are typically configured with:

 
| Attribute | Value | Purpose |
|---|---|---|
| width | 1 | Smaller body for dense environments |
| length | 1 | Smaller body for dense environments |
| hp | 1 | Simple health model |
| speed | 1 | Standard movement |
| view_range | CircleRange(6) | Larger view for food detection |
| step_reward | -0.01 | Small penalty encourages efficiency |

 The larger `view_range` compared to pursuit helps agents detect distant food sources. The negative `step_reward` incentivizes efficient collection paths.

### Reward Structure

 Gathering rewards are primarily event-based:

 **Food Collection Events:**

 
 - **Collect food**: Positive reward when agent reaches food location
 - **Step penalty**: Small negative reward per step (efficiency incentive)
 - **Exploration bonus**: Optional reward for discovering new areas
 
 The reward system must balance:

 
 - **Collection efficiency**: Maximize food per step
 - **Exploration**: Discover new food sources
 - **Competition**: Outperform other agents in resource acquisition

### Model Selection

 All three RL algorithms work with these scenarios:

 **DQN (Recommended for Pursuit):**

 
 - Best performance for dense agent interactions
 - Parameter sharing across agents
 - Off-policy learning from replay buffer
 
 **DRQN:**

 
 - Adds recurrent layer for temporal reasoning
 - Useful when partial observability matters
 - Higher memory requirements
 
 **A2C:**

 
 - On-policy actor-critic method
 - Lower sample efficiency but stable training
 - Better for gather scenarios with sparse rewards

## Performance Considerations

 
### Training Time

 Both scenarios train in approximately **1 day on GTX1080-Ti** for convergence:

 
 - Pursuit: ~2000 rounds
 - Gather: ~2000 rounds
 
 Training time scales with:

 
 - Number of agents (linear with parallelism)
 - Map size (quadratic in C++ step complexity)
 - Model complexity (DRQN > DQN > A2C)
 
 **Memory Management:**

 If encountering out-of-memory errors, adjust `infer_batch_size` in model configuration to process fewer agents per GPU batch.

 Sources: [README.md57-59](https://github.com/geek-ai/MAgent/blob/2144dbd4/README.md?plain=1#L57-L59)

 
### Scalability

 These scenarios demonstrate MAgent's scalability claims:

 
| Metric | Pursuit | Gather |
|---|---|---|
| Typical Agent Count | 50-100 | 100-500 |
| Max Tested | 1000+ | 5000+ |
| C++ Parallelism | OpenMP across agents | OpenMP across agents |
| Python Parallelism | ProcessingModel | ProcessingModel |

 The combination of C++ simulation parallelism ([C++ Engine Implementation](https://deepwiki.com/geek-ai/MAgent/3.2-c++-engine-implementation)) and Python model parallelism ([ProcessingModel and Parallelism](https://deepwiki.com/geek-ai/MAgent/4.2-processingmodel-and-parallelism)) enables large-scale training.
