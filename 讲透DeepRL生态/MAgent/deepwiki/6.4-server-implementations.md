## Purpose and Scope

 The server layer provides a standardized interface between the MAgent simulation environment and visualization systems. Servers encapsulate environment state management, simulation stepping logic, and data formatting for renderers. This abstraction allows multiple rendering backends (PyGame, web-based) to visualize different scenarios without directly coupling to GridWorld internals.

 For information about using servers with PyGame visualization, see [PyGame Renderer](https://deepwiki.com/geek-ai/MAgent/6.1-pygame-renderer). For web-based rendering, see [Web-Based Rendering](https://deepwiki.com/geek-ai/MAgent/6.2-web-based-rendering). For running interactive demos that use servers, see [Interactive Demos](https://deepwiki.com/geek-ai/MAgent/6.3-interactive-demos).

## BaseServer Interface

 All server implementations must inherit from `BaseServer` and implement a standard set of methods. The interface is defined implicitly through the methods that `PyGameRenderer` expects to call.

 
### Required Methods

 
| Method | Purpose | Return Type |
|---|---|---|
| get_info() | Returns map dimensions, group metadata, and static elements | (tuple, list, dict) |
| get_data(frame_id, x_range, y_range) | Returns agent positions and events for a specific frame and viewport | (dict, list) |
| get_status(frame_id) | Indicates if simulation is active or complete | bool or None |
| get_banners(frame_id, resolution) | Returns text banners to display at top of screen | list |
| get_endscreen(frame_id) | Returns end-of-episode overlay text | list |
| keydown(frame_id, key, mouse_x, mouse_y) | Handles keyboard input events | bool |
| mousedown(frame_id, key, mouse_x, mouse_y) | Handles mouse button events | bool |
| get_map_size() | Returns map dimensions | tuple |
| add_agents(x, y, g) | Adds agents at specified position (for interactive modes) | None |

### get_data(frame_id, x_range, y_range)

 Called every frame to retrieve current agent positions and events within the viewport.

 **Parameters:**

 
 - `frame_id`: Sequential frame number (incremented by renderer)
 - `x_range`: Tuple `(x_min, x_max)` of visible x-coordinates
 - `y_range`: Tuple `(y_min, y_max)` of visible y-coordinates
 
 **Return Format:**

 
 - **Positions:** Dictionary mapping agent ID to `[x, y, group_id]`
 - **Events:** List of tuples `(agent_id, event_x, event_y)` for attack visualizations
 
 The server should step the simulation when this method is called, ensuring new data is available for each frame request.

### get_status(frame_id)

 Returns whether the simulation should continue stepping. Used by the renderer to determine animation state.

 **Return Values:**

 
 - `True`: Simulation is active, continue rendering
 - `None` or `False`: Simulation is complete, pause or stop
