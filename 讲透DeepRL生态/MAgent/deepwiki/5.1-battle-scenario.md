## Purpose and Scope

 This page documents the **Battle scenario**, one of the built-in environments in MAgent. The Battle scenario is a two-team competitive combat environment where agents learn to coordinate attacks and defend against opponents. This page covers the environment setup, agent configuration, training workflow, and evaluation methods specific to the Battle scenario.

 For information about other scenarios, see [Pursuit and Gather Scenarios](https://deepwiki.com/geek-ai/MAgent/5.2-pursuit-and-gather-scenarios) and [Arrangement Task](https://deepwiki.com/geek-ai/MAgent/5.3-arrangement-task). For general training concepts that apply across scenarios, see [Training Workflow](https://deepwiki.com/geek-ai/MAgent/4.1-training-workflow) and [Multi-Agent Training Strategies](https://deepwiki.com/geek-ai/MAgent/4.4-multi-agent-training-strategies).

## Scenario Overview

 The Battle scenario is a symmetric competitive environment where two teams of agents face each other in combat. Key characteristics:

 
 - **Two groups**: Left team and right team, initialized on opposite sides of the map
 - **Objective**: Eliminate opposing team members while surviving
 - **Combat mechanics**: Agents can attack enemies within range, receive damage, and die when HP depletes
 - **Coordination**: Success requires agents to coordinate attacks and avoid being outnumbered
 - **Self-play capable**: Same model can control both teams for self-play training
 
 The scenario is defined by the environment name `"battle"` passed to `GridWorld` initialization.

 **Sources**: [examples/train_battle.py152](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_battle.py#L152-L152)

### Key Map Parameters

 
| Parameter | Formula | Description |
|---|---|---|
| init_num | map_size * map_size * 0.04 | Number of agents per team (4% of map area) |
| side | int(sqrt(init_num)) * 2 | Side length of agent square formation |
| gap | 3 | Separation between teams at map center |
| spacing | 2 | Cell spacing between agents in formation |

 For a 125×125 map:

 
 - `init_num = 625` agents per team (1,250 total)
 - `side = 50` cells for square formation
 - Teams separated by 6 cells (3-cell gap on each side of center)
 
 **Side Swapping**: The function alternates which team appears on left vs. right between episodes using the global `leftID`/`rightID` swap. This prevents positional bias during training.

## Agent Configuration

 
### Agent Type Properties

 The Battle scenario uses a pre-configured agent type defined in the C++ backend. Key properties include:

 
 - **View range**: Circular or sector-based field of view
 - **Attack range**: Distance within which agents can damage enemies
 - **Movement**: Agents can move in cardinal/diagonal directions
 - **HP system**: Agents have health points, die when HP reaches zero
 - **Attack mechanics**: Agents deal damage to enemies in range
 
 The exact agent type configuration is loaded from the C++ engine when `"battle"` is specified.

 
### Reward Structure

 The Battle scenario implements the following reward components:

 
| Event | Reward | Recipient |
|---|---|---|
| Attack enemy | Small negative (penalty) | Attacker |
| Kill enemy | Positive reward | Agent that dealt killing blow |
| Die | Negative penalty | Agent that died |
| Survive step | Small positive (step reward) | All living agents |

 This reward structure encourages:

 
 - **Selective aggression**: Attack penalty discourages mindless attacking
 - **Finishing kills**: Reward for eliminations incentivizes coordinated attacks
 - **Survival**: Step reward values staying alive
 - **Offensive play**: Kill rewards outweigh attack penalties
 
 **Sources**: Referenced from general architecture knowledge of MAgent reward systems

### Supported Algorithms

 The training script supports two RL algorithms:

 
#### DQN (Deep Q-Network)

 
```

```

 
 - **Off-policy**: Learns from replay buffer
 - **Target network**: Updated every 1,200 steps
 - **Training frequency**: Train every 5 steps
 - **Memory size**: 1,048,576 transitions
 
 **Sources**: [examples/train_battle.py173-178](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_battle.py#L173-L178)

 
#### DRQN (Deep Recurrent Q-Network)

 
```

```

 
 - **Recurrent**: Uses LSTM to handle partial observability
 - **Unroll step**: Processes sequences of 8 timesteps
 - **Smaller memory**: 5,000 sequences (40,000 transitions)
 - **Batch processing**: 32 sequences per batch
 
 **Sources**: [examples/train_battle.py179-184](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_battle.py#L179-L184)

| learning_rate | 1e-4 | 1e-4 | Optimizer step size |
| target_update | 1200 | 1200 | Target network update frequency |
| train_freq | 5 | 5 | Steps between training iterations |

 **Sources**: [examples/train_battle.py168-184](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_battle.py#L168-L184)

 
### Exploration Strategy

 The training uses ε-greedy exploration with piecewise linear decay:

 
```

```

 
| Round Range | Epsilon Value | Exploration Rate |
|---|---|---|
| 0 - 700 | 1.0 → 0.2 | Linear decay from 100% to 20% |
| 700 - 1,400 | 0.2 → 0.05 | Linear decay from 20% to 5% |
| 1,400+ | 0.05 | Fixed at 5% exploration |

 **Sources**: [examples/train_battle.py217](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_battle.py#L217-L217)

### Episode Termination

 Episodes end when:

 
 - All agents of one team die (`done = True` from `env.step()`)
 - Maximum step count reached (550 steps)
 
 The 550-step limit prevents infinite stalemates in balanced matchups.
