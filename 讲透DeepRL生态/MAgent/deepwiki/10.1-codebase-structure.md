### Core Python Modules

 
#### `gridworld.py`

 The main entry point for creating and interacting with simulation environments. Contains:

 
 - `GridWorld` class [python/magent/gridworld.py14-483](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L14-L483): Main environment interface
 - `Config` class [python/magent/gridworld.py678-767](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L678-L767): Configuration builder
 - `AgentSymbol` class [python/magent/gridworld.py654-676](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L654-L676): Symbolic agent references for reward rules
 - `EventNode` class [python/magent/gridworld.py571-652](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L571-L652): AST nodes for event expressions
 - `CircleRange` and `SectorRange` [python/magent/gridworld.py769-801](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L769-L801): Spatial range definitions
 
 Key responsibilities:

 
 - Initialize C++ engine via ctypes
 - Register agent types and groups
 - Serialize reward rules to C++ format
 - Provide observation, action, and reward interfaces
 
 **Sources:** [python/magent/gridworld.py1-801](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L1-L801)

 
#### `c_lib.py`

 Manages the Python-C++ interface using ctypes. Provides:

 
 - `_LIB` singleton: Loads `libmagent.so` or `libmagent.dylib`
 - Array conversion functions: `as_float_c_array()`, `as_int32_c_array()`
 - Platform-specific library loading logic
 
 **Sources:** [python/magent/gridworld.py10](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L10-L10)

 
#### `processingModel.py`

 Implements the multi-process training infrastructure:

 
 - `ProcessingModel` class: Wraps RL models in separate processes
 - Non-blocking inference via pipes/sockets
 - Asynchronous training execution
 - `NDArrayPackage` for efficient NumPy serialization
 
 **Sources:** [doc/get_started.md62-90](https://github.com/geek-ai/MAgent/blob/2144dbd4/doc/get_started.md?plain=1#L62-L90)

 
#### `utility.py`

 Provides helper utilities:

 
 - `EpisodesBuffer`: Replay buffer for experience storage
 - `piecewise_decay()`: Learning rate schedulers
 - `sample_observation()`: Evaluation set sampling
 - `check_model()`: Model checkpoint management
 - `init_logger()`: Logging configuration
 
 **Sources:** [examples/train_against.py155-169](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_against.py#L155-L169)

### Training Scripts

 Training scripts follow a common pattern:

 
 - Initialize environment with built-in or custom config
 - Create `ProcessingModel` instances for each agent group
 - Execute training loop: observe → infer → act → step → reward → train
 - Save checkpoints periodically
 - Optionally render episodes for visualization
 
 **Example: `train_against.py` structure:**

 
 - `generate_map()` [examples/train_against.py17-40](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_against.py#L17-L40): Initialize agent positions
 - `play_a_round()` [examples/train_against.py43-132](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_against.py#L43-L132): Execute one episode
 - Main loop [examples/train_against.py227-248](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_against.py#L227-L248): Coordinate training rounds

## Build System

 
### Build Script

 The `build.sh` script [build.sh1-19](https://github.com/geek-ai/MAgent/blob/2144dbd4/build.sh#L1-L19) automates compilation:

 
 - Creates `build/` directory
 - Invokes CMake to generate build files
 - Runs `make` with parallel jobs (platform-specific)
 - Outputs `libmagent.so` (Linux) or `libmagent.dylib` (macOS)
 
 **Platform detection:**

 
 - Linux: Uses `nproc` for CPU count
 - macOS: Uses `sysctl -n hw.ncpu`
 
 
### Dependencies

 External libraries required (installed via package manager):

 
 - `cmake`: Build system generator
 - `libboost-system-dev`: Boost C++ libraries
 - `libjsoncpp-dev`: JSON parsing
 - `libwebsocketpp-dev`: WebSocket support for web renderer
 
 **Sources:** [README.md24-50](https://github.com/geek-ai/MAgent/blob/2144dbd4/README.md?plain=1#L24-L50) [build.sh1-19](https://github.com/geek-ai/MAgent/blob/2144dbd4/build.sh#L1-L19)

## Key Entry Points

 
### For Users

 **Running a pre-built scenario:**

 
```

```

 **Entry point flow:**

 
 - Training script imports `magent` package
 - Creates `GridWorld` with scenario name (e.g., `"battle"`)
 - `GridWorld.__init__()` loads built-in config from `builtin/config/battle.py`
 - Config registers agent types and reward rules
 - Python serializes config to C++ engine via ctypes
 
 **Sources:** [README.md62-82](https://github.com/geek-ai/MAgent/blob/2144dbd4/README.md?plain=1#L62-L82) [doc/get_started.md91-96](https://github.com/geek-ai/MAgent/blob/2144dbd4/doc/get_started.md?plain=1#L91-L96)

 
### For Developers

 **Adding a new scenario:**

 
 - Create config file in `python/magent/builtin/config/`
 - Define `get_config()` function returning `Config` object
 - Register agent types with `config.register_agent_type()`
 - Add groups with `config.add_group()`
 - Define reward rules with `config.add_reward_rule()`
 
 **Implementing a new RL algorithm:**

 
 - Create model class in `python/magent/builtin/` (e.g., `custom_model.py`)
 - Implement required interface: `infer_action()`, `sample_step()`, `train()`
 - Wrap with `ProcessingModel` for multi-process execution
 - Use in training scripts similar to existing algorithms
 
 **Sources:** [doc/get_started.md10-18](https://github.com/geek-ai/MAgent/blob/2144dbd4/doc/get_started.md?plain=1#L10-L18) [python/magent/gridworld.py697-729](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L697-L729)
