## Purpose and Scope

 This page explains how to create custom multi-agent environments in MAgent, including defining agent types, configuring reward structures, and generating maps. Custom environments enable researchers to design novel scenarios beyond the built-in examples.

 For information about using built-in scenarios, see [Built-in Scenarios](https://deepwiki.com/geek-ai/MAgent/5-built-in-scenarios). For extending the C++ engine with new observation spaces or mechanics, see [Extending MAgent](https://deepwiki.com/geek-ai/MAgent/8.4-extending-magent).

## Configuration Serialization Process

 Understanding how Python config translates to C++ engine:

 
```

```

 The serialization happens automatically during `GridWorld.__init__()`:

 
 - **Agent types**: Range objects are split into `radius` and `angle` fields
 - **Symbols**: Each unique `AgentSymbol` is assigned an integer ID
 - **Events**: Event expression tree is flattened into integer arrays
 - **Rules**: References to symbols/events are replaced with integer IDs
 
 **Sources:** [python/magent/gridworld.py66-89](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L66-L89) [python/magent/gridworld.py493-565](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L493-L565)

 
## Key Considerations

 
### Performance

 
 - **Agent count**: Test with gradually increasing agent counts to identify bottlenecks
 - **Map size**: Larger maps increase spatial query overhead
 - **Observation frequency**: Frequent `get_observation()` calls are expensive
 - **Reward complexity**: Complex event expressions add evaluation cost
 
 
### Design Patterns

 **Symmetric scenarios** (e.g., battle):

 
 - Two groups with mirrored configurations
 - Balanced initial positions
 - Competitive reward structure
 
 **Cooperative scenarios** (e.g., double attack):

 
 - Multi-agent reward dependencies
 - Shared objectives through event composition
 - Individual and group-level incentives
 
 **Goal-based scenarios** (e.g., arrangement):

 
 - Goal agents with `can_absorb` attribute
 - Collision-based completion detection
 - Distance-based intermediate rewards
