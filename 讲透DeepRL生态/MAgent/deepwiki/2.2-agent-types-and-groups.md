  This page explains how agents are organized in MAgent through the agent type system and group-based control mechanism. Agent types define shared physical and behavioral properties, while groups organize agents of the same type for batch operations. For information about how groups are used in the training workflow, see [Training Workflow](https://deepwiki.com/geek-ai/MAgent/4.1-training-workflow). For details on specific properties like observation and action spaces, see [Observation Spaces](https://deepwiki.com/geek-ai/MAgent/2.3-observation-spaces) and [Action Spaces](https://deepwiki.com/geek-ai/MAgent/2.4-action-spaces).

 
## Overview

 MAgent uses a **two-level hierarchy** for agent organization:

 
 - **Agent Types**: Templates that define shared properties (physical characteristics, capabilities, intrinsic rewards)
 - **Groups**: Collections of agents that share an agent type and are controlled together as a batch
 
 This design enables efficient batch operations on thousands of agents while allowing different agent types to coexist in the same environment with distinct properties and behaviors.

## Agent Types

 An **agent type** is a template that defines the physical properties, perception capabilities, action capabilities, and intrinsic reward structure for a class of agents. All agents of the same type share these properties.

 
### Agent Type Properties

 Agent types are defined using a dictionary of properties passed to `Config.register_agent_type()`. The table below lists all available properties:

 
| Property | Type | Description |
|---|---|---|
| width | int | Width of agent body in grid cells |
| length | int | Length of agent body in grid cells |
| hp | float | Maximum health points |
| speed | float | Maximum movement speed (radius of move range) |
| view_range | CircleRange or SectorRange | Defines observable area around agent |
| attack_range | CircleRange or SectorRange | Defines attackable positions |
| damage | float | Attack damage dealt per hit |
| step_recover | float | HP recovered (or lost if negative) per step |
| kill_supply | float | HP gained when killing another agent |
| step_reward | float | Intrinsic reward received each step |
| kill_reward | float | Intrinsic reward for killing an agent |
| dead_penalty | float | Intrinsic reward (typically negative) when dying |
| attack_penalty | float | Intrinsic reward (typically negative) for attacking |

## Groups

 A **group** is a collection of agents that share the same agent type. Groups are the fundamental unit of control in MAgent - all operations (getting observations, setting actions, getting rewards) are performed on entire groups at once.

### Group Operations

 All major operations in MAgent work at the group level:

 
| Operation | Method | Description |
|---|---|---|
| Get agent count | env.get_num(handle) | Returns number of alive agents in group |
| Get observations | env.get_observation(handle) | Returns observations for all agents |
| Set actions | env.set_action(handle, actions) | Sets actions for all agents |
| Get rewards | env.get_reward(handle) | Returns rewards for all agents |
| Get agent IDs | env.get_agent_id(handle) | Returns unique IDs of all agents |
| Get positions | env.get_pos(handle) | Returns (x, y) positions |

 This batch-oriented API enables efficient processing of large numbers of agents.

## Agent Type to Group Channel Mapping

 Each agent type occupies specific channels in the observation space. The `group2channel()` function computes the base channel index for a group:

 
```
base_channel = 1 + (group_handle * scale)
where scale = 2 (or 3 if minimap_mode is enabled)
```

 Channel 0 is reserved for walls. Each group gets 2-3 channels:

 
 - Channel N: Presence indicator (1 if agent present, 0 otherwise)
 - Channel N+1: Health point values (normalized 0-1)
 - Channel N+2: Minimap (if enabled)
 
 This layout ensures each group can observe all other groups in relative order.

## Summary

 The agent type and group system in MAgent provides:

 
 - **Type-based templates** for defining shared agent properties
 - **Batch operations** through group handles for efficiency
 - **Flexible placement** strategies (random, custom, fill)
 - **Type safety** by binding groups to specific agent types
 - **Scalable architecture** supporting thousands of agents per group
 
 This design enables efficient multi-agent simulation while maintaining clear separation between agent specification (types) and runtime organization (groups).
