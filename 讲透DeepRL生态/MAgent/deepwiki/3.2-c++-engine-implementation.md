## Purpose and Scope

 This document describes the internal implementation of MAgent's C++ simulation engine, which forms the performance-critical core of the platform. The C++ engine handles all simulation logic including agent movement, combat, spatial queries, and reward calculation. This page focuses on the engine's architecture, execution flow, and optimization techniques.

## GridWorld Class

 The `GridWorld` class is the main orchestrator of the simulation engine. It manages the game state, coordinates all agents, and executes the simulation loop.

 
### Initialization and Configuration

 The engine supports multiple operational modes configured through `set_config()`:

 
| Configuration Key | Type | Purpose |
|---|---|---|
| map_width, map_height | int | Grid dimensions |
| food_mode | bool | Dead agents leave food |
| turn_mode | bool | Enable turn left/right actions |
| minimap_mode | bool | Add minimap to observations |
| goal_mode | bool | Agents have specific goals (deprecated) |
| embedding_size | int | Embedding dimension in features |
| render_dir | string | Video output directory |
| seed | int | Random seed |

### Action Buffer System

 Actions are buffered before execution to enable parallelization. The system uses separate buffers based on action type and spatial location:

 
```

```

 **Key Implementation Details:**

 
 - **Spatial Separation** [src/gridworld/GridWorld.cc407-438](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L407-L438): Large maps are divided into bands along the x-axis. Actions are assigned to buffers based on agent x-coordinate, with boundary regions (within 4 cells of band edge) handled separately.
 - **Bandwidth Calculation** [src/gridworld/GridWorld.cc407](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L407-L407): `bandwidth = (width + NUM_SEP_BUFFER - 1) / NUM_SEP_BUFFER`
 - **Buffer Selection** [src/gridworld/GridWorld.cc418-424](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L418-L424):

 
 - If agent x-position modulo bandwidth is near edges (< 4 or > bandwidth - 4), use boundary buffer
 - Otherwise, use buffer `[x / bandwidth]`
 
 **Sources:** [src/gridworld/GridWorld.cc403-454](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L403-L454) [src/gridworld/GridWorld.cc75-85](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L75-L85)

### Channel ID Optimization

 The separate `channel_ids` array enables vectorized operations during view extraction. Instead of dereferencing `slots[i].channel_id`, the system can directly access `channel_ids[i]`, improving cache hit rates.

## Summary

 The C++ engine achieves high performance through:

 
 - **Spatial Data Structures**: Flat array for O(1) position lookups
 - **OpenMP Parallelization**: Parallel processing of independent agents and spatial regions
 - **Action Buffering**: Decouple action collection from execution for batch processing
 - **Cache Optimization**: Separate channel_ids array for better locality
 - **Large Map Optimization**: Spatial partitioning to enable parallel movement processing
 
 The design balances flexibility (supporting various game modes) with performance (achieving high throughput for large agent populations).
