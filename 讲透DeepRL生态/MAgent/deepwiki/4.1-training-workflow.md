## Purpose and Scope

 This document describes the step-by-step training loop workflow in MAgent, covering the sequential operations that occur during a single training round: observation collection, action inference, environment stepping, reward collection, and model training. This page focuses on the **mechanics of the training loop** and the order of operations.

 For details on parallel execution with `ProcessingModel`, see [ProcessingModel and Parallelism](https://deepwiki.com/geek-ai/MAgent/4.2-processingmodel-and-parallelism). For multi-agent training strategies and competitive/cooperative scenarios, see [Multi-Agent Training Strategies](https://deepwiki.com/geek-ai/MAgent/4.4-multi-agent-training-strategies). For replay buffer implementation details, see [Experience Buffers and Sampling](https://deepwiki.com/geek-ai/MAgent/4.6-experience-buffers-and-sampling).

### Observation Collection

 Observations are retrieved for each group handle. The observation consists of two components: spatial views and non-spatial features.

 **API Method:** `env.get_observation(handle)`

 **Returns:** `(view_buf, feature_buf)`

 
 - `view_buf`: NumPy array of shape `(n_agents, view_height, view_width, n_channels)`
 - `feature_buf`: NumPy array of shape `(n_agents, feature_size)`

 **Implementation Details:**

 
 - Observations are pre-allocated in internal buffers for efficiency ([python/magent/gridworld.py215-220](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L215-L220))

### Action Inference (Non-Blocking)

 Action inference is performed **non-blocking** to enable parallel execution across multiple models. Each model processes observations independently in separate processes.

 **API Method:** `model.infer_action(obs, ids, policy, eps, block=False)`

 **Parameters:**

 
 - `obs`: Observation tuple from `get_observation()`
 - `ids`: Agent IDs from `get_agent_id()`
 - `policy`: Action selection policy (e.g., `'e_greedy'`)
 - `eps`: Epsilon value for exploration
 - `block`: If `False`, returns immediately; inference happens asynchronously

## Non-Blocking Execution Pattern

 MAgent's training workflow leverages non-blocking operations to maximize parallelism. This pattern enables multiple models to infer and train simultaneously.

 
### Non-Blocking Operations Summary

 
```

```

 **Key Non-Blocking Operations:**

 
| Operation | Blocking Call | Purpose |
|---|---|---|
| model.infer_action(..., block=False) | model.fetch_action() | Parallel action inference |
| model.sample_step(..., block=False) | model.check_done() | Parallel buffer writing |
| model.train(..., block=False) | model.fetch_train() | Parallel model training |

 **Synchronization Points:**

 
 - After non-blocking `infer_action()` calls, must call `fetch_action()` before setting actions
 - After non-blocking `sample_step()` calls, can optionally call `check_done()` to verify completion
 - After non-blocking `train()` calls, must call `fetch_train()` to retrieve training metrics
 
 **Sources:** [examples/train_battle.py67-102](https://github.com/geek-ai/MAgent/blob/2144dbd4/examples/train_battle.py#L67-L102) [doc/get_started.md72-88](https://github.com/geek-ai/MAgent/blob/2144dbd4/doc/get_started.md?plain=1#L72-L88)

## Key Workflow Characteristics

 
### Sequential and Parallel Operations

 The training workflow carefully balances sequential and parallel operations:

 **Sequential Operations (Must Execute in Order):**

 
 - Get observations → Infer actions → Set actions → Step → Get rewards
 - Within main process, environment operations are strictly sequential
 
 **Parallel Operations (Can Execute Simultaneously):**

 
 - Multiple models infer actions at the same time (`block=False`)
 - Multiple models train at the same time (`block=False`)
 - Buffer sampling can overlap with inference (`block=False`)
 
 
### Performance Optimization

 **Key optimization strategies in the workflow:**

 
 - **Non-blocking inference**: Multiple models compute actions in parallel processes
 - **Observation buffer reuse**: Pre-allocated NumPy buffers avoid memory allocation overhead ([python/magent/gridworld.py203-213](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L203-L213))
 - **Batch operations**: All agents in a group processed together via group handles
 - **C++ parallelism**: OpenMP parallelizes agent updates within `env.step()`
 
 
### Error Handling and Validation

 **Important checks and validations:**

 
 - **Action array validation**: Actions must be `np.int32` dtype ([python/magent/gridworld.py259-260](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L259-L260))
 - **Dead agent cleanup**: Must call `clear_dead()` after each step to maintain consistency
 - **Non-blocking operation completion**: Call `check_done()` to verify async operations completed
 - **Buffer overflow prevention**: `EpisodesBuffer` automatically manages capacity

## Summary: Training Workflow Phases

 
| Phase | Key Operations | API Calls | Blocking/Non-Blocking |
|---|---|---|---|
| 1. Setup | Reset environment, generate map, add agents | env.reset(), generate_map(), env.add_agents() | Blocking |
| 2. Episode Loop | Observation, inference, action, step, reward | get_observation(), infer_action(), set_action(), step(), get_reward() | Mixed (inference non-blocking) |
| 3. Training | Sample from buffer, compute gradients, update weights | model.train(), model.fetch_train() | Non-blocking (parallelized) |
| 4. Checkpoint | Save model state, log metrics | model.save() | Blocking |
