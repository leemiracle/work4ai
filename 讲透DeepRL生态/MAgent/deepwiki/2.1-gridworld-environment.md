## Purpose and Role

 `GridWorld` is the central simulation environment class in MAgent. It serves as:

 
 - A **spatial manager** for a 2D grid-based world with walls and agents
 - A **simulation engine** that executes discrete time steps
 - A **Python-C++ bridge** that provides a high-level API while delegating computation to optimized C++ code
 - A **configuration container** that manages agent types, groups, and reward rules
 
 The GridWorld class exists in two layers:

 
 - **Python layer**: `magent.GridWorld` [python/magent/gridworld.py14-483](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L14-L483) - provides the user-facing API
 - **C++ layer**: `magent::gridworld::GridWorld` [src/gridworld/GridWorld.cc17-952](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L17-L952) - implements the simulation logic
 
 Sources: [python/magent/gridworld.py1-483](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L1-L483) [src/gridworld/GridWorld.cc1-970](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L1-L970)

## Environment Modes and Features

 
### Food Mode

 When `food_mode=True`, dead agents leave food on the map that can be consumed by living agents to restore HP. This creates scavenging dynamics.

 Configured: [python/magent/gridworld.py48](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L48-L48) [src/gridworld/GridWorld.cc131-132](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L131-L132)

 
### Turn Mode

 When `turn_mode=True`, agents have explicit direction and can perform turn actions (turn left, turn right). This adds two actions to the action space and affects observations (direction-relative views).

 Without turn mode, all agents face North and views are absolute.

 Configured: [python/magent/gridworld.py48](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L48-L48) [src/gridworld/GridWorld.cc133-134](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L133-L134)

 
### Minimap Mode

 When `minimap_mode=True`, a global minimap is added to each agent's observation, providing long-range spatial awareness. The minimap is downsampled to fit the view dimensions [src/gridworld/GridWorld.cc327-360](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L327-L360)

 Additionally, agents' absolute coordinates are added to the feature vector [src/gridworld/GridWorld.cc393-396](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L393-L396)

 Configured: [python/magent/gridworld.py48](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L48-L48) [src/gridworld/GridWorld.cc135-136](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L135-L136)

 
### Large Map Mode

 Automatically enabled for maps larger than 99×99. Uses spatial partitioning to enable parallel processing of move and turn actions [src/gridworld/GridWorld.cc75-85](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L75-L85)

 The number of partitions (`NUM_SEP_BUFFER`) is:

 
 - 16 for maps > 1000×1000
 - 8 for maps > 99×99 but ≤ 1000×1000
 - 1 otherwise

## Memory Management and Performance

 
### Buffer Reuse

 The Python layer maintains persistent observation buffers that are resized as needed rather than reallocated [python/magent/gridworld.py203-220](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L203-L220) This reduces memory allocation overhead in tight training loops.

 The C++ implementation extensively uses OpenMP for parallelization:

 
 - Observation extraction [src/gridworld/GridWorld.cc363-397](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L363-L397)

## Python-C++ Interface Details

 The GridWorld class bridges Python and C++ through several mechanisms:

 
 - **ctypes Game Handle**: The `self.game` attribute is a `ctypes.c_void_p` pointer to the C++ GridWorld instance [python/magent/gridworld.py41-43](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L41-L43)
 - **Array Conversion**: NumPy arrays are converted to C pointers using helper functions:

 
 - `as_float_c_array()` for float32 arrays
 - `as_int32_c_array()` for int32 arrays
 
 These are defined in [python/magent/c_lib.py](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/c_lib.py) and enable zero-copy data transfer.
 - **Library Loading**: The C++ shared library is loaded via ctypes as `_LIB` [python/magent/c_lib.py](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/c_lib.py) and functions are called with appropriate argument type conversions.
 - **Event Serialization**: Complex Python reward rule expressions are serialized into flat integer arrays via `_serialize_event_exp()` [python/magent/gridworld.py493-566](https://github.com/geek-ai/MAgent/blob/2144dbd4/python/magent/gridworld.py#L493-L566) This converts the symbolic expression tree into a format the C++ engine can evaluate efficiently.
 
 For more details on the interface layer, see [Python-C++ Interface](https://deepwiki.com/geek-ai/MAgent/3.4-python-c++-interface).
