  This document describes how the `Map` class manages the grid-based spatial state of the simulation, including agent positions, wall placements, coordinate system transformations, and spatial queries. The Map is the core spatial data structure that enables efficient agent observation extraction, collision detection, and action execution.

 For information about how the Map integrates with the overall simulation engine, see [C++ Engine Implementation](https://deepwiki.com/geek-ai/MAgent/3.2-c++-engine-implementation). For details on how spatial observations are exposed to the Python API, see [GridWorld Environment](https://deepwiki.com/geek-ai/MAgent/2.1-gridworld-environment) and [Observation Spaces](https://deepwiki.com/geek-ai/MAgent/2.3-observation-spaces).

 
## Core Data Structures

 The Map uses a grid-based representation where each cell can contain walls, agents, or food. The design separates structural properties (slot type) from occupancy information for flexibility.

 
### MapSlot Structure

 
```

```

 Each grid cell is represented by a `MapSlot` [src/gridworld/Map.h23-29](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/Map.h#L23-L29):

 
 - `slot_type`: Indicates if the cell is `BLANK` or an `OBSTACLE` (wall)
 - `occ_type`: When occupied, specifies whether it contains an `OCC_AGENT` or `OCC_FOOD`
 - `occupier`: Void pointer to the occupying entity (Agent* or Food*)

## Coordinate Systems

 The Map implements multiple coordinate systems to handle agent direction and view transformations. Understanding these systems is critical for working with spatial operations.


 **Sources:** [src/gridworld/Map.cc515-607](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/Map.cc#L515-L607)

 
### Absolute Map Coordinates

 Standard (x, y) coordinates in the grid. The origin (0, 0) is at the top-left corner. The map uses **row-major order** for memory layout:

 
```
PositionInteger = y * width + x
```

 Implementation: [src/gridworld/Map.h89-97](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/Map.h#L89-L97)

 
### Relative Coordinates

 Coordinates from an agent's perspective, accounting for its direction. This enables direction-agnostic action execution:

 
 - Forward movement always increases y in relative space
 - Left/right movements adjust x in relative space
 
 The transformation depends on the agent's direction (NORTH, SOUTH, EAST, WEST):

 
| Direction | Relative to Absolute Transformation |
|---|---|
| NORTH | abs_x = c_x + rela_x, abs_y = c_y + rela_y |
| SOUTH | abs_x = c_x - rela_x, abs_y = c_y - rela_y |
| WEST | abs_x = c_x + rela_y, abs_y = c_y - rela_x |
| EAST | abs_x = c_x - rela_y, abs_y = c_y + rela_x |

 Implementation: [src/gridworld/Map.cc515-551](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/Map.cc#L515-L551)

## Agent Observation Extraction

 The `extract_view()` method is one of the most complex spatial operations, responsible for generating agent observations with proper coordinate transformations.

 
```

```

 **Key Steps** [src/gridworld/Map.cc129-207](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/Map.cc#L129-L207):

 
 - **Coordinate Transformation Setup**: Convert agent's view specification (relative coordinates) to absolute map coordinates
 - **View Bounds Calculation**: Determine which map cells fall within the view range
 - **Direction-Dependent Projection**: Setup iteration variables to scan the map in a direction-aware manner
 - **Map Scanning**: Iterate through visible map cells
 - **Channel Translation**: Apply `channel_trans` to make observations symmetric (agent's own group always appears in the same channel)
 - **Buffer Filling**: Write cell information to the observation buffer
 
 The method handles four directions (NORTH, SOUTH, EAST, WEST) with different iteration patterns to maintain consistent relative observations regardless of agent orientation.

 **Sources:** [src/gridworld/Map.cc129-207](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/Map.cc#L129-L207) [src/gridworld/GridWorld.cc292-401](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L292-L401)

 
## Action Execution

 
### Attack Actions

 
```

```

 Attack execution involves two phases [src/gridworld/Map.cc209-310](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/Map.cc#L209-L310):

 
 - **`get_attack_obj()`**: Determines the target of an attack

 
 - Converts relative attack coordinates to absolute map position
 - Validates the target (in-bounds, occupied, different group if required)
 - Returns `PositionInteger` of target or -1 if invalid
 - **`do_attack()`**: Executes the attack

 
 - Reduces target HP by attacker's damage
 - If target dies: 
 - Removes agent from map
 - Optionally creates food at the position (`food_mode`)
 - Returns `kill_reward`
 - Records operation in agent's history (`set_last_op`, `set_op_obj`)
 
 **Sources:** [src/gridworld/Map.cc209-310](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/Map.cc#L209-L310) [src/gridworld/GridWorld.cc474-509](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L474-L509)

### Turn Actions

 
```

```

 The `do_turn()` method [src/gridworld/Map.cc361-406](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/Map.cc#L361-L406) rotates an agent around a configurable anchor point:

 
 - **Calculate new direction**: `(current_dir + wise) % DIR_NUM`
 - **Find rotation anchor**: Defined by `turn_x_offset` and `turn_y_offset` in agent type
 - **Rotate agent position**: Apply 2D rotation transformation around anchor
 - **Check if new area is blank**: After rotation, dimensions swap (width ↔ length for 90° turns)
 - **Update map**: Clear old area, update agent direction, fill new area
 
 The rotation math for clockwise (wise=1) and counter-clockwise (wise=-1):

 
```
If wise == -1 (counter-clockwise):
    new_x = anchor_x - dy
    new_y = anchor_y + dx
If wise == 1 (clockwise):
    new_x = anchor_x + dy
    new_y = anchor_y - dx
```

 **Sources:** [src/gridworld/Map.cc361-406](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/Map.cc#L361-L406) [src/gridworld/GridWorld.cc544-571](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L544-L571)

 
## Performance Optimizations

 
### Separate Channel IDs Array

 
```

```

 The `channel_ids` array is separated from `MapSlot` [src/gridworld/Map.h73](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/Map.h#L73-L73) for performance reasons:

 
 - During `extract_view()`, only `channel_ids` are accessed for most cells
 - Separating it allows sequential memory access patterns
 - Reduces cache misses compared to accessing full `MapSlot` structures
 - Comment in code: "channel_id is supposed to be a member of MapSlot, extract it out from MapSlot for faster access of memory"
 
 **Sources:** [src/gridworld/Map.h72-76](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/Map.h#L72-L76)

 
### Large Map Spatial Partitioning

 For large maps (> 99×99), GridWorld enables `large_map_mode` [src/gridworld/GridWorld.cc75-85](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L75-L85) which partitions the map for parallel action processing:

 
```

```

 **Partitioning Strategy** [src/gridworld/GridWorld.cc407-454](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L407-L454):

 
 - **NUM_SEP_BUFFER** is set based on map size:

 
 - Maps > 1000×1000: 16 buffers
 - Maps > 99×99: 8 buffers
 - Maps ≤ 99×99: 1 buffer (no partitioning)
 - **Action Distribution**:

 
 - Actions are assigned to buffers based on agent x-coordinate
 - `bandwidth = (width + NUM_SEP_BUFFER - 1) / NUM_SEP_BUFFER`
 - `buffer_index = agent->get_pos().x / bandwidth`
 - **Boundary Handling**:

 
 - Agents within 4 units of buffer boundaries go to `move_buffer_bound` or `turn_buffer_bound`
 - These are processed sequentially after parallel buffers to avoid race conditions
 - **Parallel Execution**:

 
 - Each buffer is processed in parallel using OpenMP: `#pragma omp parallel for`
 - This applies to both move and turn actions [src/gridworld/GridWorld.cc564-611](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L564-L611)
 
 **Why This Works:**

 
 - Non-boundary agents in different buffers cannot interact (too far apart)
 - Parallel processing is safe for these regions
 - Boundary agents are handled sequentially to prevent conflicts
 
 **Sources:** [src/gridworld/GridWorld.cc75-85](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L75-L85) [src/gridworld/GridWorld.cc407-454](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L407-L454) [src/gridworld/GridWorld.cc562-613](https://github.com/geek-ai/MAgent/blob/2144dbd4/src/gridworld/GridWorld.cc#L562-L613)
