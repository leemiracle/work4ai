  Environment wrappers in DI-engine provide a flexible and modular way to modify the behavior of reinforcement learning environments. These wrappers allow users to standardize interfaces, preprocess observations, transform actions, modify rewards, and add additional functionality without changing the underlying environment implementation. This page documents the environment wrapper system, its key components, and how to use it within the DI-engine framework.

 For information about environment managers that handle parallel environment execution, see [Environment Managers](https://deepwiki.com/opendilab/DI-engine/3.2-environment-managers).

 
## Overview of Environment Wrapper System

 The environment wrapper system in DI-engine consists of three main components:

 
 - **DingEnvWrapper**: The main environment wrapper that provides a consistent interface for all environments
 - **Specialized Wrappers**: A collection of modular wrappers that perform specific transformations
 - **Default Wrapper Configurations**: Predefined sets of wrappers for common environment types

## DingEnvWrapper

 The `DingEnvWrapper` class is the central component of the environment wrapper system. It wraps any environment from OpenAI Gym or Gymnasium to provide a consistent interface for the rest of the DI-engine framework.

 
### Key Features

 
 - **Consistent Interface**: Implements the `BaseEnv` interface, ensuring all environments have the same methods and behavior
 - **Environment Compatibility**: Supports both Gym and Gymnasium environments
 - **Flexible Configuration**: Accepts configuration for various wrappers and transformations
 - **Action Space Handling**: Automatically handles different action space types (Discrete, Box, Tuple)
 - **Observation Space Handling**: Normalizes observation spaces for consistent usage

### Initialization and Configuration

 The `DingEnvWrapper` can be initialized in two ways:

 
 - **Direct Environment Instance**: By passing an existing environment instance
 - **Configuration-based**: By providing a configuration dictionary with an `env_id`

 The configuration can include:

 
 - `env_id`: The ID of the environment to create
 - `env_wrapper`: The wrapper configuration to apply (string name or list of wrappers)
 - `act_scale`: Whether to scale actions to the environment's action space
 - `rew_clip`: Whether to clip rewards

## Specialized Environment Wrappers

 DI-engine provides a wide range of specialized wrappers that can be applied to environments. Each wrapper is designed to perform a specific transformation or add functionality.

 
### Common Wrappers

 
| Wrapper | Purpose | Typical Use Case |
|---|---|---|
| NoopResetWrapper | Executes random no-op actions on reset | Adding stochasticity to initial states |
| MaxAndSkipWrapper | Performs frame skipping with maxpool | Reducing temporal correlation and computation |
| WarpFrameWrapper | Resizes observations to a standard size | Preprocessing for convolutional networks |
| ScaledFloatFrameWrapper | Normalizes observations to [0,1] range | Input normalization for neural networks |
| ClipRewardWrapper | Clips rewards to {-1, 0, 1} | Stabilizing training with varied reward scales |
| DelayRewardWrapper | Accumulates rewards and returns them periodically | Handling delayed rewards |
| FrameStackWrapper | Stacks consecutive frames as a single observation | Capturing temporal information |
| ObsTransposeWrapper | Transposes observations for channel-first format | Preparing inputs for PyTorch models |
| EvalEpisodeReturnWrapper | Tracks episode returns during evaluation | Monitoring performance |

## Default Wrapper Configurations

 DI-engine provides default wrapper configurations for common environment types through the `get_default_wrappers` function. This allows users to quickly set up appropriate wrappers without manually configuring each one.

 
### Available Default Configurations

 
| Configuration | Environment Type | Included Wrappers |
|---|---|---|
| mujoco_default | MuJoCo environments | EvalEpisodeReturnWrapper |
| atari_default | Atari games | NoopResetWrapper, MaxAndSkipWrapper, EpisodicLifeWrapper, FireResetWrapper (for some games), WarpFrameWrapper, ScaledFloatFrameWrapper, ClipRewardWrapper (for collection), FrameStackWrapper, EvalEpisodeReturnWrapper |
| gym_hybrid_default | Environments with hybrid action spaces | GymHybridDictActionWrapper, EvalEpisodeReturnWrapper |
| default | Any other environment | EvalEpisodeReturnWrapper |

## Summary

 Environment wrappers in DI-engine provide a flexible and modular way to customize environment behavior:

 
 - **DingEnvWrapper** serves as the main wrapper that provides a consistent interface.
 - **Specialized wrappers** perform specific transformations like observation preprocessing or reward modification.
 - **Default wrapper configurations** offer pre-configured wrapper stacks for common environment types.
 - **The wrapper registry** allows for declarative configuration of wrapper stacks.
 - **Custom wrappers** can be created to implement specialized functionality.
 
 Proper use of environment wrappers can significantly impact the performance and stability of reinforcement learning algorithms by providing standardized interfaces, appropriate preprocessing, and domain-specific modifications.
