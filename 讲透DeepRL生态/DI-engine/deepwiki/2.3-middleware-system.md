  The Middleware System in DI-engine is a flexible and extensible framework for building reinforcement learning algorithms through composable, reusable components. This document describes the architecture, components, and usage patterns of the middleware system, which serves as the execution backbone for implementing various RL algorithms like DQN, PPO, and others.

 
## Core Concepts

 The middleware system is built around three fundamental concepts:

 
 - **Task**: The central orchestrator that manages the execution flow
 - **Context**: The shared data container that passes information between middlewares
 - **Middleware**: The functional components that implement specific operations in the RL pipeline

## Task System

 The `Task` class is the central orchestrator of the middleware system. It manages middleware registration, execution order, and controls the execution flow.

 
```

```

 The task system provides the following key functionalities:

 
 - **Middleware Registration**: `use()` method to register middlewares
 - **Execution Flow Control**: `forward()` and `backward()` methods to control execution
 - **Role-Based Execution**: Support for assigning roles to tasks for distributed processing
 - **Synchronous/Asynchronous Execution**: Support for both execution modes
 - **Parallel/Serial Composition**: Methods to combine middlewares in parallel or serial execution

## Context System

 The context is a data container passed between middlewares. It maintains state during a single iteration and can selectively preserve attributes across iterations.

 
```

```

 DI-engine provides two specialized context types:

 
 - **OnlineRLContext**: For online reinforcement learning algorithms
 - **OfflineRLContext**: For offline reinforcement learning algorithms
 
 Each iteration, the context is renewed with `renew()`, carrying over only attributes marked with `keep()`.

 - [ding/framework/context.py8-105](https://github.com/opendilab/DI-engine/blob/c290a673/ding/framework/context.py#L8-L105)
 
 
## Middleware Architecture

 Middlewares are the functional building blocks of RL pipelines. Each middleware performs a specific operation on the context.

 
```

```

 The middleware architecture follows these execution principles:

 
 - **Forward Execution**: Middlewares are executed in the order they are registered
 - **Generator-Based Flow Control**: Middlewares can yield to pause execution
 - **Backward Execution**: After a complete forward pass, yielded middlewares are resumed
 - **Context Renewal**: At the end of each iteration, the context is renewed

## Parallel Execution

 The middleware system integrates with the `Parallel` class to support distributed execution across multiple processes or machines.

 
```

```

 Key components for parallel execution:

 
 - **Parallel Class**: Manages communication between distributed tasks
 - **Router**: Routes messages between nodes
 - **ContextExchanger**: Synchronizes context between nodes
 - **ModelExchanger**: Synchronizes model parameters between nodes
 - **Role Assignment**: Nodes can have specific roles (LEARNER, COLLECTOR, EVALUATOR)

## Conclusion

 The Middleware System in DI-engine provides a flexible and extensible framework for building reinforcement learning algorithms. By composing middlewares, you can implement complex algorithms with reusable components, execute them in parallel across multiple processes, and customize behavior as needed.

 The system's modular design allows for rapid prototyping of new algorithms while maintaining performance and scalability. For more information on specific components that can be used within this middleware framework, refer to the [Environment System](https://deepwiki.com/opendilab/DI-engine/3-environment-system), [Policy System](https://deepwiki.com/opendilab/DI-engine/4-policy-system), and [Model System](https://deepwiki.com/opendilab/DI-engine/5-model-system) documents.
