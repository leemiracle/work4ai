## Introduction

 The Configuration System in DI-engine provides a structured, flexible approach to configuring reinforcement learning experiments. It serves as the bridge between user-defined parameters and the execution of RL algorithms, handling the reading, compilation, and saving of configurations for various components like policies, environments, collectors, and more.

 This page explains how to use the Configuration System, its internal structure, and how it integrates with other components in DI-engine. For information about specific algorithm configurations, see the respective algorithm pages under [Policy System](https://deepwiki.com/opendilab/DI-engine/4-policy-system).

## Configuration Structure

 In DI-engine, configurations are typically defined as Python dictionaries or EasyDict objects. There are three main types of configuration:

 
 - **Main Configuration (`main_config`)**: Contains all experiment parameters including environment, policy, and experiment settings
 - **Create Configuration (`create_config`)**: Specifies what types of components to create (environment, policy, buffer, etc.)
 - **System Configuration (`system_config`)**: Used for parallel/distributed training to configure system-related parameters

## Reading and Compiling Configurations

 
### Reading Configurations

 The configuration system provides several functions to read configurations:

 
| Function | Description |
|---|---|
| read_config(path) | Reads a Python file and extracts main_config and create_config |
| read_config_with_system(path) | Also extracts system_config for distributed training |
| read_config_yaml(path) | Reads configuration from a YAML file |
| read_config_directly(path) | Reads a file and returns the config dictionary directly |

 - Load configurations using the CLI or `read_config`
 - Let the system compile the configuration

## Conclusion

 The Configuration System in DI-engine provides a flexible, structured approach to configuring reinforcement learning experiments. It handles the complexity of ensuring all components have proper configuration by merging user-provided settings with sensible defaults. This system enables researchers and practitioners to focus on the parameters that matter for their specific experiments while the system handles the rest.
