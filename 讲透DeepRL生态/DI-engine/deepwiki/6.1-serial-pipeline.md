## Purpose and Scope

 The Serial Pipeline in DI-engine is a fundamental orchestration mechanism that manages the complete training workflow for reinforcement learning algorithms in a single process. It handles the initialization of all necessary components, coordinates their interactions, and executes the main training loop that involves collecting experience, training the policy, and evaluating its performance.

 This document explains the structure, workflow, and usage of the Serial Pipeline. For information about parallel training or specialized variants, see [Training Pipelines](https://deepwiki.com/opendilab/DI-engine/6-training-pipelines) and [Collectors and Evaluators](https://deepwiki.com/opendilab/DI-engine/6.2-collectors-and-evaluators).

### Component Details

 The Serial Pipeline creates and manages the following key components:

 
 - **Environment**: Interface for agent interaction
 - **Policy**: Implementation of RL algorithm (DQN, PPO, SAC, etc.)
 - **Replay Buffer**: Storage for experience data
 - **Collector**: Gathers experience from environment interactions
 - **Learner**: Updates policy based on collected experience
 - **Evaluator**: Assesses policy performance periodically
 
 Each component is configured through the passed configuration dictionary and created accordingly.

### Data Flow Between Components

 The data flow within the Serial Pipeline involves several key steps:

 
 - **Collection Phase**: The Collector uses the current policy to interact with the environment, gathering transitions (state, action, reward, next state) that are stored in the replay buffer.
 - **Learning Phase**: The Learner samples batches of experience data from the replay buffer and updates the policy parameters using the appropriate reinforcement learning algorithm.
 - **Evaluation Phase**: The Evaluator periodically tests the updated policy in the environment to measure its performance without exploration, reporting metrics like average episode rewards.
 
 This cycle continues until either the maximum number of iterations is reached or the policy achieves a target performance level.

## Serial Pipeline Variants

 DI-engine provides several specialized variants of the Serial Pipeline to address different training paradigms:

 
| Pipeline Variant | Purpose | Key Differences |
|---|---|---|
| serial_pipeline | Standard RL training | Basic collect-train-evaluate loop |
| serial_pipeline_offline | Offline RL | Uses pre-collected data instead of environment interaction |
| serial_pipeline_onpolicy | On-policy algorithms | Modified data collection for on-policy methods like PPO |
| serial_pipeline_onpolicy_ppg | PPG algorithm | Specialized for Phasic Policy Gradient |
| serial_pipeline_ngu | NGU algorithm | Supports Never Give Up exploration |
| serial_pipeline_dqfd | DQfD algorithm | Deep Q-learning from Demonstrations |

 Each variant maintains the core structure of the Serial Pipeline but adapts the workflow to suit specific algorithm requirements.

## Conclusion

 The Serial Pipeline is a fundamental component of DI-engine that simplifies the implementation of reinforcement learning algorithms. By handling the complex orchestration of environment interaction, data collection, policy learning, and evaluation, it allows researchers and practitioners to focus on algorithm development rather than infrastructure concerns.

 The pipeline's modular design supports a wide range of algorithms and can be extended with custom components when needed. For more complex training scenarios, variants of the Serial Pipeline or the parallel pipeline might be more appropriate.
