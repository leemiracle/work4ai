## Overview

 Model Wrappers in DI-engine are components that add extra functionality to neural network models by using a decorator pattern. They provide a clean way to extend model behavior without modifying the original model implementation. This page explains the wrapper architecture, available wrapper types, and their usage patterns.

 Model Wrappers are used throughout DI-engine to implement features such as:

 
 - Maintaining hidden states for RNN-based models
 - Managing transformer memory states
 - Action selection strategies (argmax, epsilon-greedy, etc.)
 - Adding noise for exploration
 - Handling different action space types
 
 For information about the model components that these wrappers enhance, see [Model Components](https://deepwiki.com/opendilab/DI-engine/5.1-model-components). For model templates that use these wrappers, see [Model Templates](https://deepwiki.com/opendilab/DI-engine/5.2-model-templates).

 At the core of the model wrapper architecture is the `IModelWrapper` interface class that defines the common methods all wrappers should implement. The main methods include:

 
 - `__init__(model)`: Initializes the wrapper with a model to wrap
 - `__getattr__(key)`: Allows accessing the wrapped model's attributes
 - `reset(data_id)`: Resets stateful variables when needed
 - `forward(*args, **kwargs)`: Processes the model's forward method
 
 Each wrapper class inherits from `IModelWrapper` and can be composed with other wrappers to provide multiple functionalities to a single model.

## State Management Wrappers

 
### HiddenStateWrapper

 The `HiddenStateWrapper` maintains hidden states for RNN-based models, allowing each sample in a batch to have its own persistent state.

 
```

```

 **Diagram: HiddenStateWrapper Flow**

 Sources: [ding/model/wrapper/model_wrappers.py100-188](https://github.com/opendilab/DI-engine/blob/c290a673/ding/model/wrapper/model_wrappers.py#L100-L188)

 Key features:

 
 - Maintains a dictionary of hidden states for multiple data samples
 - Automatically provides previous states to the model and captures next states
 - Supports selective reset of states for specific data IDs
 - Can optionally include previous states in the output
 
 
### Transformer Wrappers

 DI-engine provides three specialized wrappers for transformer models:

 
 - **TransformerInputWrapper**: Maintains a sliding window of past observations to provide the required context sequence length to transformer models.
 - **TransformerSegmentWrapper**: Splits long trajectories into fixed-length segments for transformer processing, padding the last segment if necessary.
 - **TransformerMemoryWrapper**: Manages transformer memory across different execution phases (evaluate, collect, learn), preventing interference between phases.

## Action Selection Wrappers

 Action selection wrappers implement different strategies for selecting actions from model outputs. They generally process the `logit` field in the model output to produce an `action` field.

 
```

```

 **Diagram: Action Selection Wrappers**

 Sources: [ding/model/wrapper/model_wrappers.py402-828](https://github.com/opendilab/DI-engine/blob/c290a673/ding/model/wrapper/model_wrappers.py#L402-L828)

 DI-engine provides specialized wrappers for different action spaces:

 
 - **Discrete action spaces**:

 
 - `ArgmaxSampleWrapper`: Selects the action with the highest logit value
 - `MultinomialSampleWrapper`: Samples actions probabilistically from logits
 - `EpsGreedySampleWrapper`: Balances exploration and exploitation using an epsilon parameter
 - **Continuous action spaces**:

 
 - `ReparamSampleWrapper`: Implements reparameterization for sampling continuous actions
 - `DeterministicSampleWrapper`: Uses the mean value directly for evaluation
 - **Hybrid action spaces** (combining discrete and continuous):

 
 - `HybridArgmaxSampleWrapper`
 - `HybridEpsGreedySampleWrapper`
 - `HybridReparamMultinomialSampleWrapper`

## Wrapper Types Reference

 The following table summarizes the main model wrappers available in DI-engine:

 
| Wrapper | Purpose | Common Usage |
|---|---|---|
| BaseModelWrapper | Placeholder with no extra operations | Default wrapper for consistency |
| HiddenStateWrapper | Maintains hidden states for RNNs | RNN-based policies |
| TransformerInputWrapper | Manages sliding window of observations | Transformer-based policies |
| TransformerSegmentWrapper | Splits sequences into segments | Transformer training |
| TransformerMemoryWrapper | Preserves memory across phases | Transformer model phases |
| ArgmaxSampleWrapper | Selects maximum logit value | Evaluation phase |
| MultinomialSampleWrapper | Samples actions probabilistically | Training phase |
| EpsGreedySampleWrapper | Balances exploration/exploitation | Collection phase |
| ActionNoiseWrapper | Adds noise to continuous actions | Exploration in continuous domains |
| HybridArgmaxSampleWrapper | Handles mixed action spaces | Evaluation in hybrid action spaces |
| ReparamSampleWrapper | Implements reparameterization trick | Continuous action sampling |

## Creating Custom Wrappers

 To create a custom wrapper, inherit from `IModelWrapper` and implement the required methods:

 
 - `__init__(self, model, ...)`: Initialize the wrapper with the model and any additional parameters
 - `forward(self, *args, **kwargs)`: Process the model's forward method
 - `reset(self, data_id=None, **kwargs)`: Reset any stateful variables (if needed)

## Conclusion

 Model Wrappers provide a flexible and modular way to extend model functionality in DI-engine. By composing multiple wrappers, complex behaviors can be implemented without modifying the underlying model architecture. This pattern is extensively used throughout DI-engine, particularly in policies that require stateful processing or specialized action selection strategies.

 For more information on how model wrappers are used in specific policies, refer to the policy implementation documentation and examples in the repository.
