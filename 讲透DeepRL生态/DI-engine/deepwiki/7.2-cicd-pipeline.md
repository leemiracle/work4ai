## Introduction

 This document provides a comprehensive overview of the Continuous Integration and Continuous Deployment (CI/CD) pipeline implemented in DI-engine. The CI/CD pipeline automates testing, code quality verification, documentation generation, and package distribution processes. It ensures that all code changes are properly tested and validated before being merged into the main codebase or released.

 The CI/CD infrastructure is implemented using GitHub Actions with workflow definitions stored in YAML files under the `.github/workflows/` directory. For information about Docker-based deployment options, see [Docker Integration](https://deepwiki.com/opendilab/DI-engine/7.1-docker-integration).

## Workflow Execution Control

 DI-engine's CI/CD workflows include mechanisms to skip certain jobs based on commit messages:

 
| Skip Pattern | Workflows Skipped |
|---|---|
| ci skip | All workflows |
| ut skip | Unit tests only |

 This allows contributors to bypass specific CI steps when making minor changes.

## Contributor Development Workflow

 When contributing to DI-engine, the CI/CD pipeline helps ensure code quality. A typical development workflow includes:

 
 - Fork and clone the repository
 - Create a feature branch
 - Make changes and commit them
 - Run local tests: 
```
make unittest         # Run unit tests
make format_test      # Check code formatting
make flake_check      # Check code style
```
 - Push changes and create a pull request
 - Address any issues flagged by the CI/CD pipeline
 
 
## Conclusion

 DI-engine's CI/CD pipeline provides a robust framework for ensuring code quality, compatibility, and reliability across different environments. It automates testing, documentation, and release processes, allowing developers to focus on implementation while maintaining high quality standards.

 The pipeline's modular structure allows for targeted testing of specific components, efficient use of computing resources, and flexible release strategies for both PyPI and Conda packages.
