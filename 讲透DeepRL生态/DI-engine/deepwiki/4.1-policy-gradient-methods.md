  This wiki page provides a detailed explanation of Policy Gradient methods implemented in DI-engine. Policy Gradient methods are a family of reinforcement learning algorithms that directly optimize policy parameters by computing gradients of expected returns. Unlike value-based methods (covered in [Value-Based Methods](https://deepwiki.com/opendilab/DI-engine/4.2-value-based-methods)), policy gradient methods directly parameterize the policy and update it using gradient ascent.

 
## 1. Overview of Policy Gradient Methods

 Policy Gradient methods work by parameterizing the policy πθ(a|s) with parameters θ and updating these parameters in the direction of greater expected returns. The fundamental policy gradient theorem provides the mathematical foundation:

 ∇θJ(θ) = E[∇θ log πθ(a|s) · Q(s,a)]

 In DI-engine, several policy gradient methods are implemented, with Proximal Policy Optimization (PPO) being the primary and most complete implementation.

## 3. PPO (Proximal Policy Optimization)

 Proximal Policy Optimization (PPO) is the main policy gradient implementation in DI-engine. It uses a clipped objective function to ensure stable policy updates.

 
### 3.1 Key Features

 
 - Supports discrete, continuous, and hybrid action spaces
 - On-policy algorithm with stable learning characteristics
 - Uses clipping to constrain policy updates
 - Incorporates Generalized Advantage Estimation (GAE)
 - Supports value normalization
 - Implements entropy regularization

## 5. Action Space Support

 PPO in DI-engine supports multiple types of action spaces through different model wrappers:

 
### 5.1 Discrete Action Spaces

 For discrete action spaces, PPO uses:

 
 - `multinomial_sample` wrapper in collect mode (exploration)
 - `argmax_sample` wrapper in eval mode (exploitation)
 
 
### 5.2 Continuous Action Spaces

 For continuous action spaces, PPO uses:

 
 - `reparam_sample` wrapper in collect mode
 - `deterministic_sample` wrapper in eval mode
 
 
### 5.3 Hybrid Action Spaces

 For hybrid action spaces (combining discrete and continuous actions), PPO uses:

 
 - `hybrid_reparam_multinomial_sample` wrapper

## 6. PPO Training Process

 The PPO training process follows these steps:

 
 - **Data Collection**: Collect trajectories using the current policy
 - **Advantage Calculation**: Compute advantages using GAE
 - **Policy Update**: Update the policy with the clipped objective
 - **Value Function Update**: Update the value function
 - **Repeat**: Collect new data and continue the process

## 7. Pure Policy Gradient Variant (PPO-PG)

 DI-engine also implements a pure policy gradient variant of PPO that doesn't use a value function. This variant is simpler but may be less sample-efficient than the full PPO algorithm.

 
### 7.1 Key Differences from PPO

 
 - No value network - only a policy network
 - Simpler implementation
 - Uses reinforcement signal directly rather than advantage estimates

## 9. Conclusion

 Policy Gradient methods, particularly PPO, are a core part of DI-engine's reinforcement learning toolkit. The implementation is flexible, supporting various action spaces and providing numerous configuration options. By separating the policy, model, and utility components, DI-engine achieves a modular design that allows for easy extension and customization.

 For more information on other reinforcement learning algorithms implemented in DI-engine, see [Value-Based Methods](https://deepwiki.com/opendilab/DI-engine/4.2-value-based-methods) and [Actor-Critic Methods](https://deepwiki.com/opendilab/DI-engine/4.3-actor-critic-methods).
