## Purpose and Scope

 This document describes the Neural LinUCB agent implementation in TF-Agents, which combines neural networks with the LinUCB algorithm for contextual bandit problems. Neural LinUCB applies LinUCB on top of an encoding network to capture non-linear relationships between context features and expected rewards. For information about other bandit agents, see [Bandit Agents](https://deepwiki.com/tensorflow/agents/4-bandit-agents) or [Greedy Reward Prediction](https://deepwiki.com/tensorflow/agents/4.1-greedy-reward-prediction).

## Algorithm Overview

 Neural LinUCB enhances the classic LinUCB algorithm by adding a neural network encoder. This approach allows the algorithm to learn rich feature representations from complex observations before applying the linear bandit algorithm. The method operates in two phases:

 
 - **Neural Network Training Phase**: Initially uses epsilon-greedy exploration while training the encoding network
 - **LinUCB Phase**: Switches to LinUCB-based exploration after the network is sufficiently trained
 
 The algorithm was introduced in the paper "Deep Bayesian Bandits Showdown: An Empirical Comparison of Bayesian Deep Networks for Thompson Sampling" (Riquelme et al., ICLR 2018).

## Algorithm Operation

 Neural LinUCB operates in two phases controlled by the `actions_from_reward_layer` variable, which depends on the `encoding_network_num_train_steps` parameter:

 
### Phase 1: Neural Network Training

 During this phase:

 
 - Actions are selected based on the reward layer's output, optionally with epsilon-greedy exploration
 - The encoding network and reward layer are trained using supervised learning
 - The objective is to learn good feature representations from observations
 
 
### Phase 2: LinUCB Operation

 After the network is sufficiently trained:

 
 - The encoder network is frozen
 - Actions are selected using LinUCB computation
 - The agent maintains covariance matrices and data vectors for each arm
 - Exploration is guided by the confidence bounds provided by LinUCB

## Training Process

 The training process updates different components depending on the current phase:

 
### Phase 1: Reward Layer Training

 When `actions_from_reward_layer` is True:

 
 - The agent takes the encoded observation and passes it through the reward layer
 - It computes the loss between predicted and actual rewards for the chosen actions
 - It updates the encoder network and reward layer weights using backpropagation
 
 
### Phase 2: LinUCB Updates

 When `actions_from_reward_layer` is False:

 
 - The agent uses the encoder to get feature representations
 - For each arm that was selected in the batch, it updates: 
 - The covariance matrix (A)
 - The data vector (b)
 - The count of samples for that arm
 
 The update equations for the LinUCB phase are:

 
```
A_new = gamma * A + x * x^T
b_new = gamma * b + r * x
```

 where:

 
 - `x` is the encoded observation
 - `r` is the reward
 - `gamma` is the forgetting factor

## Specialized Features

 
### Per-Arm Features Support

 Neural LinUCB supports contextual bandits with per-arm features, where each arm has its own observation. In this case:

 
 - A specialized encoding network is used that processes both global and per-arm features
 - The agent maintains a single set of LinUCB parameters for all arms
 - The encoder network outputs features of shape `[batch_size, num_actions, encoding_dim]`
 
 The per-arm feature support is enabled via the `accepts_per_arm_features` parameter.

### Distributed Training Support

 Neural LinUCB can be trained in a distributed setting with special handling for the LinUCB updates:

 
 - Each replica computes local updates to the covariance matrices and data vectors
 - These updates are aggregated using `merge_call`
 - The aggregated updates are applied to the global variables
 
 This is implemented in the `compute_loss_using_linucb_distributed` method.

## Performance Considerations

 
 - The LinUCB phase requires matrix inversion which can be expensive for large `encoding_dim`
 - TF-Agents uses conjugate gradient methods to efficiently compute the required matrix operations
 - The forgetting factor (`gamma`) can be used to handle non-stationary reward distributions
 - The `alpha` parameter controls the exploration-exploitation trade-off
