## TimeStep

 The `TimeStep` is a named tuple that represents a single step within an environment. It captures the observation, reward, discount factor, and step type at a specific point in time.

 
```

```

 Sources: [tf_agents/trajectories/time_step.py54-98](https://github.com/tensorflow/agents/blob/2a236d30/tf_agents/trajectories/time_step.py#L54-L98)

 The `TimeStep` structure contains:

 
| Field | Description |
|---|---|
| step_type | Enum value indicating position in episode: FIRST (0), MID (1), or LAST (2) |
| observation | The observation from the environment (can be nested tensors/arrays) |
| reward | The reward received after the previous action (can be nested tensors/arrays) |
| discount | Discount factor for future rewards (between 0 and 1) |

 Helper methods:

 
 - `is_first()`: Returns true if this is the first step in an episode
 - `is_mid()`: Returns true if this is a middle step in an episode
 - `is_last()`: Returns true if this is the final step in an episode
 
 Factory functions for creating TimeStep instances:

 
 - `restart(observation, batch_size, reward_spec)`: Creates a TimeStep with FIRST step_type
 - `transition(observation, reward, discount)`: Creates a TimeStep with MID step_type
 - `termination(observation, reward)`: Creates a TimeStep with LAST step_type and zero discount
 - `truncation(observation, reward, discount)`: Creates a TimeStep with LAST step_type and specified discount
 
 Sources: [tf_agents/trajectories/time_step.py135-412](https://github.com/tensorflow/agents/blob/2a236d30/tf_agents/trajectories/time_step.py#L135-L412)

 
## PolicyStep

 The `PolicyStep` is a named tuple that encapsulates the output of a policy when asked to generate an action based on an observation.

 
```

```

 Sources: [tf_agents/trajectories/policy_step.py31-77](https://github.com/tensorflow/agents/blob/2a236d30/tf_agents/trajectories/policy_step.py#L31-L77)

 The `PolicyStep` structure contains:

 
| Field | Description |
|---|---|
| action | The action to take, which can be either a concrete action or a distribution over actions |
| state | The state of the policy (e.g., RNN state) to feed back into the next policy call |
| info | Additional information from the policy (e.g., log probabilities) |

 Utility functions:

 
 - `replace(**kwargs)`: Creates a new PolicyStep with specified fields replaced
 - `set_log_probability(info, log_probability)`: Helper to add log probability to info
 - `get_log_probability(info, default_log_probability)`: Helper to extract log probability from info
 
 Sources: [tf_agents/trajectories/policy_step.py97-134](https://github.com/tensorflow/agents/blob/2a236d30/tf_agents/trajectories/policy_step.py#L97-L134)

 
## Trajectory

 The `Trajectory` is a named tuple that represents a sequence of aligned time steps, connecting observations with actions and their consequences.

 
```

```

 Sources: [tf_agents/trajectories/trajectory.py36-124](https://github.com/tensorflow/agents/blob/2a236d30/tf_agents/trajectories/trajectory.py#L36-L124)

 The `Trajectory` structure contains:

 
| Field | Description |
|---|---|
| step_type | Step type of the current time step (FIRST, MID, LAST) |
| observation | Observation from the current time step |
| action | Action taken at the current time step |
| policy_info | Policy information related to the action |
| next_step_type | Step type of the next time step |
| reward | Reward received after taking the action |
| discount | Discount factor for future rewards |

 Helper methods:

 
 - `is_first()`: Returns true if step_type is FIRST
 - `is_mid()`: Returns true if step_type is MID and next_step_type is MID
 - `is_last()`: Returns true if next_step_type is LAST
 - `is_boundary()`: Returns true if step_type is LAST (episode boundary)
 - `replace(**kwargs)`: Creates a new Trajectory with specified fields replaced
 
 Factory functions for creating Trajectory instances:

 
 - `first(observation, action, policy_info, reward, discount)`: Creates a Trajectory from FIRST to MID
 - `mid(observation, action, policy_info, reward, discount)`: Creates a Trajectory from MID to MID
 - `last(observation, action, policy_info, reward, discount)`: Creates a Trajectory from MID to LAST
 - `single_step(observation, action, policy_info, reward, discount)`: Creates a Trajectory from FIRST to LAST
 - `boundary(observation, action, policy_info, reward, discount)`: Creates a Trajectory from LAST to FIRST
 - `from_episode(observation, action, policy_info, reward, discount=None)`: Creates a Trajectory from tensors representing a full episode
 - `from_transition(time_step, action_step, next_time_step)`: Creates a Trajectory from a Transition
 
 Sources: [tf_agents/trajectories/trajectory.py262-647](https://github.com/tensorflow/agents/blob/2a236d30/tf_agents/trajectories/trajectory.py#L262-L647)

 
## Transition

 The `Transition` is a named tuple that represents a state-action-state transition in an MDP (Markov Decision Process).

 
```

```

 Sources: [tf_agents/trajectories/trajectory.py128-195](https://github.com/tensorflow/agents/blob/2a236d30/tf_agents/trajectories/trajectory.py#L128-L195)

 The `Transition` structure contains:

 
| Field | Description |
|---|---|
| time_step | The initial time step (S) |
| action_step | The action step (A) |
| next_time_step | The resulting next time step (S') |

 Helper methods:

 
 - `replace(**kwargs)`: Creates a new Transition with specified fields replaced
 
 Functions for converting between Trajectory and Transition:

 
 - `to_transition(trajectory, next_trajectory=None)`: Converts a Trajectory to a Transition
 - `to_n_step_transition(trajectory, gamma)`: Creates an n-step Transition with discounted rewards
 - `to_transition_spec(trajectory_spec)`: Creates a Transition spec from a Trajectory spec
 
 Sources: [tf_agents/trajectories/trajectory.py650-875](https://github.com/tensorflow/agents/blob/2a236d30/tf_agents/trajectories/trajectory.py#L650-L875)

## Data Converters

 TF-Agents provides data converters to make it easier to work with different data structures:

 
```

```

 Sources: [tf_agents/agents/data_converter.py68-574](https://github.com/tensorflow/agents/blob/2a236d30/tf_agents/agents/data_converter.py#L68-L574)

 The `DataContext` class stores specifications needed for data conversion operations. The data converters facilitate moving between different representations, validating data, and pruning unnecessary information:

 
 - `AsTrajectory`: Converts other data types to Trajectory
 - `AsTransition`: Converts other data types to Transition
 - `AsNStepTransition`: Creates n-step Transitions with discounted rewards
 - `AsHalfTransition`: Creates a special type of Transition for particular algorithms
