  This document describes the testing infrastructure and practices used in the TF-Agents codebase. The testing system ensures that components work as expected, changes don't cause regressions, and the library maintains compatibility with different versions of TensorFlow and related dependencies.

 
## Testing Infrastructure Overview

 TF-Agents employs a comprehensive testing approach that combines unit tests, integration tests, and compatibility testing across different environments. The testing system is built on Python's unittest framework with custom extensions to handle TensorFlow-specific requirements.

## Test Structure and Organization

 TF-Agents organizes its tests into three main categories:

 
 - **Regular Unit Tests**: Standard unit tests discovered and run together
 - **Separated Tests**: Tests that need to be run individually (listed in `test_individually.txt`)
 - **Broken Tests**: Tests that are currently known to be broken (listed in a specified broken tests file)
 
 
### Test Discovery

 Tests are discovered using the custom `TestLoader` class, which extends Python's unittest loader and adds exclusion capabilities for specific tests.

### Test Files

 Test files in TF-Agents follow a consistent naming pattern, with unit test files named with a `_test.py` suffix. The test discovery process searches for files with this pattern within the `tf_agents` directory.

## Test Execution

 
### Running Tests with setup.py

 The primary method for running tests is using the `setup.py test` command, which executes the custom `Test` class. This command:

 
 - Imports the necessary modules (including absl and TensorFlow)
 - Sets up GPU memory allocation constraints
 - Loads and excludes test lists (separated and broken tests)
 - Discovers and runs the regular tests
 - Runs separated tests individually in separate subprocesses
 - Reports the results of all tests

### GPU Configuration

 To manage GPU memory effectively, the testing system configures TensorFlow to limit each GPU to 1GB of memory. This is crucial for running separated tests, as by default TensorFlow would allocate all GPU memory to the main process, causing out-of-memory errors in subprocess tests.

### Handling Separated Tests

 Some tests need to run in isolation due to resource conflicts or other requirements. These tests are listed in the `test_individually.txt` file and are executed one by one in separate subprocesses.

 - Testing different release types (nightly or stable)
 - Installing appropriate dependencies

 - Building and installing TF-Agents packages

### Testing Different Dependencies

 The release testing script allows for testing TF-Agents with different versions of dependencies by specifying flags:

 
 - `--tf_version`: TensorFlow version
 - `--reverb_version`: Reverb version
 - `--tfp_version`: TensorFlow Probability version
 - `--rlds_version`: RLDS version
 - `--tf_keras_version`: TF-Keras version
 
 This enables validation of TF-Agents across different versions of its dependencies.

## Continuous Integration

 TF-Agents uses continuous integration to run tests automatically for:

 
 - Pull requests
 - Nightly builds
 - Release candidates
 
 The CI system runs the release testing script with various configurations to ensure compatibility across different environments and dependency versions.

 
### Broken Tests Management

 The testing infrastructure includes a mechanism for managing broken tests. A file (default: `broken_tests.txt`) contains a list of tests that are currently known to be broken. These tests are excluded from the regular test execution to prevent false test failures.

## Best Practices for Writing Tests

 When writing tests for TF-Agents, follow these practices:

 
 - Place test files in the same directory as the module being tested
 - Name test files with a `_test.py` suffix
 - Use TensorFlow's test utilities for testing TensorFlow-specific functionality
 - For tests that need isolation, add them to `test_individually.txt`
 - For temporarily broken tests, add them to the broken tests file
 
 
## Troubleshooting Common Test Issues

 
### GPU Memory Issues

 If you encounter GPU memory issues when running tests, try:

 
 - Ensuring you have the appropriate GPU drivers installed
 - Running tests with CPU only using `CUDA_VISIBLE_DEVICES=""`
 - Increasing the GPU memory limit in the test configuration if available resources allow
 
 
### Missing Dependencies

 If tests fail due to missing dependencies:

 
 - Install test-specific dependencies with `pip install -e .[tests]`
 - For environment tests, ensure you have the necessary environment packages (e.g., `pybullet`)
