## Base Policy Interfaces

 TF-Agents has two fundamental policy interfaces:

 
### TFPolicy

 `TFPolicy` is the base interface for TensorFlow-based policies. These policies are implemented using TensorFlow operations and form the foundation for most TF-Agents policies.

 **Key attributes**:

 
 - `time_step_spec`: Specification of time steps
 - `action_spec`: Specification of actions
 - `policy_state_spec`: Specification of policy state
 - `info_spec`: Specification of policy info
 
 **Key methods**:

 
 - `action(time_step, policy_state, seed)`: Returns a policy step with the selected action
 - `distribution(time_step, policy_state)`: Returns a policy step with a distribution over actions
 - `update(policy)`: Updates this policy with weights from another policy
 
 Sources: [tf_agents/policies/tf_policy.py](https://github.com/tensorflow/agents/blob/2a236d30/tf_agents/policies/tf_policy.py)

 
### PyPolicy

 `PyPolicy` is the base interface for Python-based policies. These policies are implemented in Python and can be used with Python environments.

 **Key attributes**:

 
 - `time_step_spec`: Specification of time steps
 - `action_spec`: Specification of actions
 - `policy_state_spec`: Specification of policy state
 - `info_spec`: Specification of policy info
 
 **Key methods**:

 
 - `action(time_step, policy_state)`: Returns a policy step with the selected action
 - `get_initial_state(batch_size)`: Returns initial policy state
 
 Sources: [tf_agents/policies/py_policy.py](https://github.com/tensorflow/agents/blob/2a236d30/tf_agents/policies/py_policy.py)

 
## Core Concepts

 
### PolicyStep

 All policies return a `PolicyStep` object from their `action` and `distribution` methods. It contains:

 
 - `action`: The selected action or distribution over actions
 - `state`: The updated policy state
 - `info`: Additional policy information (e.g., log probabilities)

## Action Selection Policies

 TF-Agents provides specialized policies for different action selection strategies:

 
### QPolicy

 `QPolicy` selects actions greedily based on Q-values computed by a Q-network. It's commonly used with value-based reinforcement learning methods like DQN.

 **Key parameters**:

 
 - `time_step_spec`: Specification of time steps
 - `action_spec`: Specification of actions
 - `q_network`: The Q-network that computes Q-values

### EpsilonGreedyPolicy

 `EpsilonGreedyPolicy` implements the epsilon-greedy exploration strategy, selecting a random action with probability epsilon, and the greedy action with probability 1-epsilon.

 **Key parameters**:

 
 - `policy`: The policy to wrap
 - `epsilon`: The probability of selecting a random action
 - `exploration_mask`: Optional mask for restricting which actions to explore

 **Key parameters**:

 
 - `policy`: The policy to wrap

## Policy Selection Table

 The following table summarizes when to use each policy type:

 
| Policy Type | When to Use | Key Features |
|---|---|---|
| QPolicy | With value-based algorithms (DQN) | Selects actions based on Q-values |
| GreedyPolicy | During evaluation/deployment | Always selects highest-valued action |
| EpsilonGreedyPolicy | During training | Balances exploration/exploitation with epsilon parameter |
| BoltzmannPolicy | For controlled exploration | Applies temperature to action distribution |
| RandomTFPolicy | For baselines or initial exploration | Selects actions randomly |
| PyTFPolicy | For deploying in Python environments | Converts TF policies to Python |
| TFPyPolicy | For using Python policies in TF | Converts Python policies to TF |
