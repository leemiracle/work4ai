  Drivers in TF-Agents are components that manage the interaction between policies and environments, forming a core part of the reinforcement learning loop. They are responsible for collecting experience data by running policies in environments for a specified number of steps or episodes, and distributing the collected trajectories to observers like replay buffers and metrics.

 For information about other components that interact with drivers, see [Policies](https://deepwiki.com/tensorflow/agents/2.3-policies), [Environments](https://deepwiki.com/tensorflow/agents/2.2-environments), and [Replay Buffers](https://deepwiki.com/tensorflow/agents/2.5-replay-buffers).

## Core Driver Types

 TF-Agents provides four main types of drivers, each designed for different use cases:

 
| Driver Type | Environment Type | Policy Type | Control Flow | Use Case |
|---|---|---|---|---|
| DynamicStepDriver | TF Environment | TF Policy | tf.while_loop | Collect fixed number of steps |
| DynamicEpisodeDriver | TF Environment | TF Policy | tf.while_loop | Collect fixed number of episodes |
| PyDriver | Python Environment | Python Policy | Python loop | Python-based data collection |
| TFDriver | TF Environment | TF Policy | tf.function | Alternative to dynamic drivers |

 
### DynamicStepDriver

 `DynamicStepDriver` takes a fixed number of steps in a TensorFlow environment using a TensorFlow policy, implemented with a `tf.while_loop`. It only counts transitions that result in an actual step in the environment, excluding reset steps.

```

```

 The drivers are built on two key functions:

 
 - `_loop_condition_fn`: Determines when to stop the loop based on the number of steps or episodes
 - `_loop_body_fn`: Performs one iteration of the driver's operation, including: 
 - Getting an action from the policy
 - Stepping the environment
 - Creating a trajectory
 - Notifying observers
 - Updating counters

## Observers

 Observers are a crucial part of the driver architecture, allowing for flexible data processing. There are two types of observers:

 
 - **Trajectory Observers**: Process complete `Trajectory` objects
 - **Transition Observers**: Process tuples of `(time_step, action_step, next_time_step)`
 
 Common uses for observers include:

 
 - Adding data to replay buffers
 - Computing metrics
 - Visualizing agent behavior
 - Logging statistics
