## Contribution Best Practices

 
 - Break your work into small, single-purpose updates
 - Submit the update as a GitHub pull request against the `master` branch
 - Provide docstrings for all new methods and classes
 - Add unit tests for new functionality
 - Update `CHANGELOG.md` to record your changes
 - Follow the codestyle guidelines

## CI/CD Pipeline

 Catalyst uses GitHub Actions for continuous integration and testing. Understanding the CI pipeline helps ensure your contributions pass all required checks.

 
```

```

 The CI pipeline includes:

 
 - **Codestyle tests**: Checks if code follows the Catalyst style guide
 - **Documentation tests**: Verifies documentation builds correctly
 - **Unit tests**: Runs the test suite across different Python versions and operating systems
 - **Integration tests**: Tests the integration with various optional dependencies
 
 Each PR must pass these tests before being reviewed.

## Common Contribution Types

 
### Bug Fixes

 
 - Go to [GitHub issues](https://github.com/catalyst-team/catalyst/blob/e99f9065/GitHub issues)
 - Find an issue or report a new one
 - Comment on the issue that you want to work on it
 - Implement a fix and submit a PR

## Core Dependencies and Extension System

 Catalyst has a modular architecture that allows for flexible installation of dependencies based on your needs.

 
```

```

 The extension system is managed through the `SETTINGS` object in [catalyst/settings.py186-372](https://github.com/catalyst-team/catalyst/blob/e99f9065/catalyst/settings.py#L186-L372) which detects available dependencies and enables features accordingly.

 When contributing to extensions, make sure to add appropriate tests in [bin/workflows/check_settings.sh1-224](https://github.com/catalyst-team/catalyst/blob/e99f9065/bin/workflows/check_settings.sh#L1-L224) to verify that your extension works with and without the required dependencies.
