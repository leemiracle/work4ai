## Overview

 This document describes the built-in callbacks provided by the Catalyst framework. Callbacks in Catalyst serve as an extensible mechanism to customize and enhance the training loop behavior. They allow for modular integration of functionality like metrics computation, optimization steps, model checkpointing, logging, and more without modifying the core training loop.

 For information about creating custom callbacks, see [Creating Custom Callbacks](https://deepwiki.com/catalyst-team/catalyst/3.2-creating-custom-callbacks).

 
## Callback System Architecture

 Catalyst uses an event-driven callback system that hooks into various stages of the training process. The Runner system dispatches events at specific points in the training loop, and registered callbacks can respond to these events.

### Training Process Callbacks

 These callbacks handle the core training operations:

 
| Callback | Purpose | Order |
|---|---|---|
| BackwardCallback | Performs backward pass using specified loss | CallbackOrder.Backward |
| OptimizerCallback | Handles optimizer step and zero_grad operations | CallbackOrder.Optimizer |
| SchedulerCallback | Updates learning rate using scheduler | CallbackOrder.Scheduler |
| CriterionCallback | Computes loss using criterion | CallbackOrder.Metric |

## Summary

 Catalyst's built-in callbacks provide a comprehensive set of tools for model training, evaluation, and monitoring. The callback system's event-driven architecture allows for flexible customization of the training process without modifying the core training loop.

 The main categories of callbacks include:

 
 - Training process callbacks (backward, optimizer, scheduler)
 - Metrics and evaluation callbacks
 - Utility and monitoring callbacks
 - Checkpointing and model management callbacks
 - Data processing callbacks
 
 By leveraging these built-in callbacks and combining them as needed, users can create sophisticated training pipelines with minimal code while maintaining full control over the training process.
