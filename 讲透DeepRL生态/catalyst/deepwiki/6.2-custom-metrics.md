  This page explains how to create and use custom metrics in the Catalyst framework. Custom metrics allow you to define your own performance evaluation measures beyond the built-in metrics provided by Catalyst. You'll learn about the metric interfaces, how to implement your own metrics, and how to integrate them with Catalyst's callback system.

 For information about built-in metrics, see [Built-in Metrics](https://deepwiki.com/catalyst-team/catalyst/6.1-built-in-metrics).

## Metric Types

 Catalyst supports two main types of metrics based on how they accumulate and compute values:

 
 - **Batch Metrics**: Calculate values for each batch independently, then aggregate across batches (typically averaged)
 - **Loader Metrics**: Accumulate data from all batches, then calculate a single metric value at the end of the loader

 This distinction is important when implementing custom metrics, as it affects how your metric handles data and when calculations are performed.

## Best Practices for Custom Metrics

 
 - **Choose the Right Base Class**: Select between batch or loader metrics based on whether your metric can be calculated on individual batches or requires the entire dataset.
 - **Handle Edge Cases**: Ensure your metric handles edge cases like empty batches, NaN values, or boundary conditions.
 - **Naming Convention**: Use clear and consistent naming for your metrics, and leverage the prefix/suffix system.
 - **Optimization**: For large datasets, optimize your metric computation to avoid excessive memory usage.
 - **Testing**: Create unit tests for your custom metrics to verify their correctness:

## Summary

 Creating custom metrics in Catalyst follows a structured approach through the metric interfaces and callback system. You can create batch or loader metrics depending on your needs, and leverage functional interfaces for quick integration with existing metric functions.

 The flexibility of Catalyst's metric system allows you to easily monitor and optimize your models using any performance measure relevant to your task, whether it's a standard metric or a domain-specific one.

 For specific metrics implementation examples, refer to the source code of built-in metrics like `AccuracyMetric`, `R2Squared`, or `AUCMetric`.
