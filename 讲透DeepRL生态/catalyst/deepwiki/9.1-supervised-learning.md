  This page documents Catalyst's implementation of supervised learning workflows. Supervised learning is a fundamental machine learning approach where models are trained on labeled data. In Catalyst, supervised learning is implemented through the core Runner system with specific components for handling labeled data, common metrics, and optimization techniques. For other training approaches, see [Self-Supervised Learning](https://deepwiki.com/catalyst-team/catalyst/9.2-self-supervised-learning) or [Reinforcement Learning](https://deepwiki.com/catalyst-team/catalyst/9.3-reinforcement-learning).

 
## Overview of Supervised Learning in Catalyst

 Supervised learning in Catalyst follows a data-driven, event-based workflow where a model is trained to predict targets based on input features. The framework provides specialized components to streamline the supervised learning process while leveraging Catalyst's core architecture.

## Key Components for Supervised Learning

 
### Data Handling and Preprocessing

 In supervised learning, Catalyst expects data to be organized in PyTorch `DataLoader` objects with appropriate input features and target labels. The framework provides utilities to handle class imbalance and various data augmentation techniques.

 
### Runner Configuration

 When setting up a `SupervisedRunner`, users need to specify:

 
 - `input_key`: Key in the batch dictionary that contains input features
 - `output_key`: Key where model outputs will be stored
 - `target_key`: Key containing ground truth labels
 - `loss_key`: Optional key for storing loss values
 
 
### Metrics and Callbacks for Supervised Learning

 Catalyst offers a rich set of callbacks and metrics specifically designed for supervised learning tasks:

 
| Callback | Purpose | Application |
|---|---|---|
| AccuracyCallback | Computes accuracy@topk | Classification |
| PrecisionRecallF1SupportCallback | Computes precision, recall, and F1 | Classification |
| MultilabelAccuracyCallback | Accuracy for multi-label problems | Multi-label classification |
| CMCScoreCallback | Cumulative Matching Characteristics | Re-identification tasks |
| HitrateCallback, MAPCallback, MRRCallback, NDCGCallback | Recommendation system metrics | Ranking systems |
| MixupCallback | Mixup data augmentation | Regularization technique |
| SklearnModelCallback | Integration with sklearn models | Quick baselines or post-processing |

## Typical Supervised Learning Workflow

 A typical supervised learning workflow in Catalyst consists of the following steps:

 
 - **Data preparation**: Create PyTorch datasets and data loaders
 - **Model definition**: Define a PyTorch model
 - **Loss and optimizer**: Select appropriate loss function and optimizer
 - **Runner configuration**: Configure the `SupervisedRunner` with appropriate keys
 - **Callbacks selection**: Choose callbacks for metrics, logging, checkpointing, etc.
 - **Training execution**: Run the training process
 - **Evaluation and inference**: Evaluate the trained model on test data

### Recommendation Systems

 Catalyst provides specialized metrics for recommendation system evaluation:

 
 - `HitrateCallback`: Computes hit rate at top-K positions
 - `MAPCallback`: Computes Mean Average Precision
 - `MRRCallback`: Computes Mean Reciprocal Rank
 - `NDCGCallback`: Computes Normalized Discounted Cumulative Gain
 
 These metrics are essential for evaluating ranking quality in recommendation systems.

## Best Practices for Supervised Learning in Catalyst

 
 - **Key naming convention**: Use consistent key naming across your project (e.g., "features", "logits", "targets")
 - **Batch size**: Balance between memory usage and speed; larger batches often provide more stable gradients
 - **Validation monitoring**: Use appropriate validation metrics for early stopping and model selection
 - **Logging**: Leverage Catalyst's logging capabilities to track training progress
 - **Callbacks**: Choose appropriate callbacks for your specific task and evaluation needs
 - **Engine selection**: Select the appropriate engine based on your hardware (CPU, GPU, TPU)
 
 By following these practices, you can create efficient and effective supervised learning workflows using the Catalyst framework.
