  This page explains how to use Catalyst's distributed training capabilities, which enable training models across multiple GPUs and nodes. Distributed training can significantly speed up the training process for large models or datasets. For information about running on XLA (TPU) devices, see [XLA and Special Engines](https://deepwiki.com/catalyst-team/catalyst/4.3-xla-and-special-engines).

 
## Overview of Distributed Training in Catalyst

 Catalyst provides a flexible engine abstraction to support different hardware accelerators and distributed training configurations. The framework implements two main approaches for distributed training:

 
 - **Data Parallel (DP)**: Simpler approach that runs on a single machine with multiple GPUs
 - **Distributed Data Parallel (DDP)**: More efficient approach that can run across multiple machines and GPUs

### DataParallelEngine

 The `DataParallelEngine` provides a simpler form of data parallelism that works on a single machine with multiple GPUs. It uses PyTorch's `nn.DataParallel` to split each batch across available GPUs.

 Key features:

 
 - Simplicity: Easier to use and debug
 - Single process: Runs in a single Python process
 - Overhead: Has more overhead in GPU communication
 
 Sources: [catalyst/engines/torch.py36-47](https://github.com/catalyst-team/catalyst/blob/e99f9065/catalyst/engines/torch.py#L36-L47)

 
### DistributedDataParallelEngine

 The `DistributedDataParallelEngine` implements a more efficient form of data parallelism using PyTorch's Distributed Data Parallel (DDP). It supports both single-machine multi-GPU and multi-node multi-GPU setups.

 Key features:

 
 - Efficiency: Less overhead compared to DataParallel
 - Scalability: Can scale across multiple nodes
 - Process-based: Uses multiple processes (one per GPU)
 - Synchronization: Automatically handles gradient synchronization
 
 The engine manages:

 
 - Process group initialization
 - Environment variable setup
 - Inter-process communication
 - Metric synchronization across processes
 
 Sources: [catalyst/engines/torch.py50-158](https://github.com/catalyst-team/catalyst/blob/e99f9065/catalyst/engines/torch.py#L50-L158)

 
## Setting Up Distributed Training

 
### Configuration Options

 The `DistributedDataParallelEngine` accepts several parameters to configure the distributed training:

 
| Parameter | Description | Default Value |
|---|---|---|
| address | Master node's address (IP or hostname) | "127.0.0.1" |
| port | Communication port for the master node | 2112 |
| world_size | Total number of processes across all nodes | None (auto-detected) |
| workers_dist_rank | Rank of the first process on the node | 0 |
| num_node_workers | Number of processes to launch on the node | None (uses number of GPUs) |
| process_group_kwargs | Additional kwargs for torch.distributed.init_process_group | {} |

## Process Spawning and Coordination

 In distributed training mode, Catalyst spawns multiple processes (one per GPU) using PyTorch's multiprocessing utilities. The `spawn` method of the `DistributedDataParallelEngine` handles this process:

 
```

```

 Sources: [catalyst/engines/torch.py98-120](https://github.com/catalyst-team/catalyst/blob/e99f9065/catalyst/engines/torch.py#L98-L120) [catalyst/engines/torch.py122-147](https://github.com/catalyst-team/catalyst/blob/e99f9065/catalyst/engines/torch.py#L122-L147)

 The distributed training process follows these steps:

 
 - The main process creates a Runner with a distributed engine
 - When `run()` is called, the engine spawns worker processes (one per GPU)
 - Each worker process: 
 - Sets up environment variables (MASTER_ADDR, MASTER_PORT, WORLD_SIZE, RANK)
 - Initializes the distributed process group
 - Performs its portion of the training
 - Synchronizes gradients with other processes after each backward pass
 - Metrics are synchronized across processes using `mean_reduce_ddp_metrics`
 - At the end of training, process groups are cleaned up with `cleanup()`

## Best Practices for Distributed Training

 
 - **Batch Size**: Consider the batch size per GPU. The effective batch size is `batch_size * num_gpus`. You may need to adjust learning rates accordingly.
 - **Data Sampling**: Always use `DistributedSampler` with DDP to ensure each GPU gets a different subset of data.
 - **Memory Usage**: Monitor memory usage on each GPU. Different GPUs may have different memory usage patterns.
 - **Network Bottlenecks**: For multi-node training, be aware of network bandwidth limitations that might affect training speed.
 - **Synchronization Points**: Minimize operations that require synchronization across processes, as these can become bottlenecks.
 
 
## Conclusion

 Catalyst's distributed training support makes it easy to scale your training across multiple GPUs and nodes. The abstraction provided by the Engine system allows you to focus on your model and training logic while the framework handles the complexities of distributed computation.
