## Metric Types Overview

 Catalyst provides two primary types of metrics:

 
 - **Batch Metrics**: Calculated on each batch during training and validation. These metrics are typically faster to compute but may be less accurate across the entire dataset.
 - **Loader Metrics**: Accumulated over an entire data loader, providing a more accurate measure of model performance on the complete dataset.
 
 Every metric in Catalyst implements one of the following interfaces:

 
 - `ICallbackBatchMetric`: For metrics that can be computed on each batch individually
 - `ICallbackLoaderMetric`: For metrics that need to accumulate statistics across the entire loader

### Accuracy Metrics

 - **AccuracyMetric**: Computes multiclass accuracy@topk for specified `topk` values. It calculates the percentage of predictions where the correct class is among the top-k predicted classes.
 - **MultilabelAccuracyMetric**: Computes multilabel accuracy with a specified threshold. It calculates the percentage of instances where predicted labels (after thresholding) match the true labels.

## Segmentation Metrics

 For image segmentation tasks, Catalyst provides region-based metrics that evaluate the overlap between predicted and ground truth masks:

 
 - **IOUMetric (Intersection over Union)**: Also known as the Jaccard index, calculates the overlap between predicted and ground truth masks divided by their union
 - **DiceMetric**: Also known as the F1 score for segmentation, calculates 2 * overlap / (area1 + area2)
 - **TrevskyMetric**: A generalization of the Dice coefficient that allows for weighted false positives and false negatives

## Metrics Naming Convention

 Catalyst follows a consistent naming convention for metrics:

 
 - For top-K metrics (like accuracy, hitrate): `{metric_name}{K:02d}` (e.g., `accuracy01`, `hitrate05`)
 - For statistics metrics: `{metric_name}_{statistic}` (e.g., `precision_macro`, `recall_micro`)
 - Prefixes and suffixes can be added to all metrics through the corresponding parameters in callbacks
 
 These metrics can be accessed through `runner.batch_metrics`, `runner.loader_metrics`, or `runner.epoch_metrics` depending on when they are calculated.

 
## Integration with Runner and Logging Systems

 Metrics in Catalyst are designed to work seamlessly with the Runner system and various logging backends. The typical workflow is:

 
 - Create metric callbacks with appropriate parameters
 - Add callbacks to the Runner's callback list
 - Metrics are automatically calculated and logged during training
 - Access final metrics through the Runner's metric dictionaries
 
 This integration allows for easy monitoring of model performance and early stopping based on metric values.
