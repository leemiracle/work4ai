## Purpose and Overview

 This document covers the learning rate scheduling implementations available in the Catalyst framework. Learning rate schedulers are essential tools for optimizing neural network training by dynamically adjusting the learning rate based on predefined rules or training progress. Catalyst provides seamless integration with PyTorch's schedulers while adding custom implementations with enhanced functionality.

 For information about callbacks that use these schedulers, see [Callback System](https://deepwiki.com/catalyst-team/catalyst/3-callback-system) and [Built-in Callbacks](https://deepwiki.com/catalyst-team/catalyst/3.1-built-in-callbacks).

 
## Scheduler Architecture

 Schedulers in Catalyst are designed to integrate smoothly with the Runner system and training loop. They can be used directly with the optimizer or, more commonly, through the `SchedulerCallback` which handles scheduler updates at appropriate intervals during training.

## Scheduler Types

 Catalyst supports two main categories of schedulers:

 
 - **PyTorch Built-in Schedulers**: All schedulers from `torch.optim.lr_scheduler` module are re-exported by Catalyst
 - **Catalyst Custom Schedulers**: Enhanced schedulers with additional functionality
 
 
### Scheduler Base Classes

 Catalyst defines two base classes for scheduling:

 
 - **BaseScheduler**: The foundation for epoch-based schedulers
 - **BatchScheduler**: Extended class for batch-based schedulers that update more frequently

### PyTorch Schedulers

 Catalyst seamlessly integrates with all PyTorch schedulers, including:

 
| Scheduler | Description |
|---|---|
| StepLR | Decreases learning rate by gamma every step_size epochs |
| MultiStepLR | Decreases learning rate by gamma at specific milestones |
| ExponentialLR | Decreases learning rate by gamma every epoch |
| CosineAnnealingLR | Adjusts learning rate following a cosine curve |
| ReduceLROnPlateau | Reduces learning rate when a metric has stopped improving |
| CyclicLR | Cycles learning rate between two boundaries |
| OneCycleLR | PyTorch's implementation of the one-cycle policy |
| CosineAnnealingWarmRestarts | Cosine annealing with warm restarts |

## OneCycleLRWithWarmup Scheduler

 Catalyst implements a custom version of the One Cycle learning rate policy with additional features for warmup and decay stages.

 
### One Cycle LR Policy

 The One Cycle policy, introduced by Leslie Smith, involves cycling the learning rate between a minimum and maximum value, while simultaneously cycling the momentum in the opposite direction.


 Sources: [catalyst/contrib/schedulers/onecycle.py11-55](https://github.com/catalyst-team/catalyst/blob/e99f9065/catalyst/contrib/schedulers/onecycle.py#L11-L55)

 
### Implementation Details

 The `OneCycleLRWithWarmup` class provides:

 
 - **Customizable Phase Durations**:

 
 - Warmup phase (steps or fraction)
 - Annealing phase (calculated automatically)
 - Optional decay phase (steps or fraction)
 - **Flexible Configuration**:

 
 - Learning rate range: (max_lr, min_lr, [final_lr])
 - Momentum range: (min_momentum, max_momentum, [final_momentum])
 - Initial values can be taken from the optimizer
 - **Runtime Behavior**:

 
 - Can recalculate schedules for batch-based updates
 - Handles both learning rate and momentum updates

### Scheduler Update Modes

 The `SchedulerCallback` supports two update modes:

 
| Mode | Description |
|---|---|
| "batch" | Updates scheduler after every batch (suitable for BatchScheduler) |
| "epoch" | Updates scheduler after every epoch (suitable for BaseScheduler and PyTorch schedulers) |

## Best Practices

 
 - **Choose the right update frequency**: Batch-based updates provide finer control but incur more overhead. Epoch-based updates are more efficient for longer training runs.
 - **Combine with monitoring**: Use metrics monitoring callbacks alongside schedulers to adapt learning rates based on model performance.
 - **Warmup for stability**: Consider using warmup periods (as in OneCycleLRWithWarmup) when training with large batch sizes or high learning rates to improve stability.
 - **Test different schedulers**: Different tasks may benefit from different scheduling strategies. Experiment with various schedulers to find what works best for your specific task.
