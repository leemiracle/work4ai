## Purpose and Scope

 This document explains the policy gradient agent implementations in the rlpyt framework. Policy gradient agents directly parameterize a policy (action distribution) and use gradient ascent on the expected return to improve it, as opposed to Q-learning agents that learn state-action values (see [Q-Learning Agents](https://deepwiki.com/astooke/rlpyt/4.1-q-learning-agents)). The agents described here serve as the interface between algorithms like PPO and A2C (see [Policy Gradient Algorithms](https://deepwiki.com/astooke/rlpyt/3.2-policy-gradient-algorithms)) and the environment.

 
## Overview of Policy Gradient Agents

 Policy gradient agents in rlpyt are classified by:

 
 - **Action space type**: Categorical (discrete) or Gaussian (continuous)
 - **State representation**: Standard (feedforward) or recurrent
 - **Sampling pattern**: Standard or alternating (for specialized parallel sampling)

## Basic Operation

 Policy gradient agents follow this flow:

 
 - Receive observations, previous actions, and previous rewards
 - Process through neural network model to obtain distribution parameters
 - Create probability distribution (Categorical or Gaussian)
 - Sample actions from this distribution during exploration
 - Return action and agent info (containing distribution parameters and value estimates)

## Distribution Types

 Policy gradient agents use specific probability distributions for different action spaces:

 
 - **Categorical Distribution** - For discrete action spaces (e.g., Atari games)

 
 - Parameters: Action probabilities
 - Used by: `CategoricalPgAgent` and recurrent variants
 - **Gaussian Distribution** - For continuous action spaces (e.g., MuJoCo robotics environments)

 
 - Parameters: Mean and log standard deviation
 - Supports optional action clipping and squashing transformations
 - Used by: `GaussianPgAgent` and recurrent variants

## Categorical Policy Gradient Agents

 Categorical policy gradient agents are used for discrete action spaces. They work with models that output action probabilities.

 
### Key Methods

 
 - `__call__`: Forward pass during training/optimization
 - `step`: Action selection during sampling (environment interaction)
 - `initialize`: Sets up the agent and initializes the categorical distribution
 
 
### Code Structure

 The `CategoricalPgAgent` class performs the following operations:

 
 - Converts previous actions to one-hot representation
 - Passes inputs through model to get action probabilities and value estimate
 - Uses categorical distribution to sample actions
 - Returns action and agent information (distribution parameters and value)
 
 Sources: [rlpyt/agents/pg/categorical.py11-51](https://github.com/astooke/rlpyt/blob/f04f23db/rlpyt/agents/pg/categorical.py#L11-L51)

 
## Gaussian Policy Gradient Agents

 Gaussian policy gradient agents are used for continuous action spaces. They work with models that output action means and log standard deviations.

 
### Key Methods

 
 - `__call__`: Forward pass during training/optimization
 - `step`: Action selection during sampling
 - `initialize`: Sets up the agent and initializes the Gaussian distribution
 
 
### Important Features

 
 - Supports action clipping within environment bounds
 - Can use fixed or learned standard deviations
 - Handles proper scaling and transformation of actions
 
 Sources: [rlpyt/agents/pg/gaussian.py14-66](https://github.com/astooke/rlpyt/blob/f04f23db/rlpyt/agents/pg/gaussian.py#L14-L66) [rlpyt/distributions/gaussian.py](https://github.com/astooke/rlpyt/blob/f04f23db/rlpyt/distributions/gaussian.py)

 
## Recurrent Agents

 For environments requiring memory, rlpyt provides recurrent variants of both categorical and Gaussian policy gradient agents.

 
### Key Differences

 
 - Maintain recurrent state (hidden state) across time steps
 - Handle state reset at environment episode boundaries
 - Pass and manage recurrent state between components
 - Properly track state across different modes (training/sampling/evaluation)
 
 The recurrent mixins provide common functionality for:

 
 - Tracking and advancing recurrent states
 - Resetting states at the start of episodes
 - Managing state during mode transitions

## Alternating Recurrent Agents

 Alternating recurrent agents are specialized versions designed to work with alternating samplers. These samplers divide environments into two sets, with each set taking turns computing actions while the other is stepping environments.

 
### Key Features

 
 - Maintain two sets of recurrent states
 - Toggle between states automatically
 - Efficiently support parallelized sampling patterns
 - Compatible with `AlternatingSampler` for potential 2x speedup
 
 Sources: [rlpyt/agents/base.py307-371](https://github.com/astooke/rlpyt/blob/f04f23db/rlpyt/agents/base.py#L307-L371) [rlpyt/samplers/parallel/gpu/alternating_sampler.py](https://github.com/astooke/rlpyt/blob/f04f23db/rlpyt/samplers/parallel/gpu/alternating_sampler.py)

 Policy gradient agents provide outputs needed specifically for policy gradient algorithms:

 
 - Action distribution parameters for policy gradient computation
 - Value estimates for advantage calculation
 - Entropy of action distribution for optional entropy regularization
 - Interfacing between models and algorithms for proper loss calculation

## Integration with Other Framework Components

 Policy gradient agents are one part of the rlpyt framework. They interact with:

 
 - **Models** - Neural networks that process observations and output action distributions
 - **Samplers** - Collect experiences using the agent's action selection
 - **Algorithms** - Use the agent's outputs to compute gradients and update the model
 - **Distributions** - Handle the mathematical operations for action sampling and likelihood calculations
