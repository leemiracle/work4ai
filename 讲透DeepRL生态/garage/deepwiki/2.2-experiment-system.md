  The Experiment System in Garage provides a structured way to define, run, track, and resume reinforcement learning experiments. It handles experiment organization, logging, snapshotting, and reproducibility. This document explains how to use the experiment system, understand its internal components, and work with its lifecycle.

 For information about the Trainer that uses this system to manage training loops, see [Trainer](https://deepwiki.com/rlworkgroup/garage/2.3-trainer).

 
## Purpose and Core Components

 The Experiment System's primary purpose is to make the research workflow easier by:

 
 - Organizing experiment files in a consistent directory structure
 - Logging experiment progress and metadata
 - Capturing code snapshots for reproducibility
 - Providing mechanisms to resume experiments
 - Managing TensorBoard output

## The wrap_experiment Decorator

 The `wrap_experiment` decorator is the primary entry point for defining experiments in Garage. It transforms a function into an experiment template that handles directory creation, logging, and snapshots.

 
### Basic Usage

 
```

```

 When called, `my_experiment(seed=1)` will:

 
 - Create a unique experiment directory
 - Set up logging to that directory
 - Call your function with an ExperimentContext instance
 - Capture metadata for reproducibility
 
 
### Configuration Options

 The `wrap_experiment` decorator accepts several optional parameters:

 
| Parameter | Type | Description |
|---|---|---|
| log_dir | str | The full log directory path. Computed from name if omitted. |
| name | str | Name of the experiment. Defaults to the function name. |
| prefix | str | Directory under data/local for experiment data. Default: "experiment" |
| snapshot_mode | str | "all", "last", "gap", or "none". Determines which iterations to save. |
| snapshot_gap | int | How many iterations between snapshots when mode is "gap". |
| archive_launch_repo | bool | Whether to save an archive of the git repo. |
| name_parameters | str | Parameters to include in experiment name: "all", "passed", or None. |
| use_existing_dir | bool | If true, reuse an existing directory. |
| x_axis | str | Key for the x-axis in plots. Default: "TotalEnvSteps" |

### Experiment Directory Structure

 When an experiment is run, the following directory structure is created:

 
```
data/local/<prefix>/<name>/
├── debug.log           # Text logs
├── progress.csv        # Tabular data for metrics 
├── variant.json        # Experiment parameters
├── metadata.json       # Git info and other metadata
├── launch_archive.tar.xz  # Archive of the git repo
└── snapshots/          # Snapshots for resuming experiments
```

## Reproducibility Features

 The experiment system includes several features to ensure reproducibility:

 
 - **Seed handling**: Random seeds are captured and can be restored.
 - **Parameter logging**: All experiment parameters are saved in variant.json.
 - **Git information**: The git commit hash is saved in metadata.json.
 - **Code archiving**: An archive of the experiment's code can be saved.

## Common Pitfalls and Solutions

 
| Issue | Solution |
|---|---|
| Missing experiment logs | Check if the correct log_dir was specified |
| Snapshots not being saved | Verify snapshot_mode is not set to "none" |
| Cannot resume experiment | Ensure snapshots were saved during training |
| Experiment names colliding | Use name_parameters to distinguish between runs |
| Large repo causing slow archiving | Set archive_launch_repo=False for large repos |
