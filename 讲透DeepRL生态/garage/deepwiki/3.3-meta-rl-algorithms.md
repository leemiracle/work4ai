## Purpose and Scope

 This document provides an overview of the Meta-Reinforcement Learning (Meta-RL) algorithms implemented in the Garage framework. Meta-RL algorithms are designed to learn policies that can quickly adapt to new tasks with minimal additional training. The page covers the key Meta-RL algorithms in Garage, their architecture, components, and usage patterns. For standard RL algorithms, see [On-Policy Algorithms](https://deepwiki.com/rlworkgroup/garage/3.1-on-policy-algorithms) and [Off-Policy Algorithms](https://deepwiki.com/rlworkgroup/garage/3.2-off-policy-algorithms).

 
## Introduction to Meta-RL

 Meta-RL addresses the challenge of sample efficiency in reinforcement learning by enabling an agent to leverage experience across multiple tasks to quickly adapt to new, unseen tasks. Unlike standard RL algorithms that train a policy for a single task, Meta-RL algorithms learn a meta-policy that encodes knowledge across a distribution of tasks.

## MAML (Model-Agnostic Meta-Learning)

 MAML is a meta-learning technique that allows for rapid adaptation to new tasks through gradient-based optimization. The key insight is to find parameters that can be quickly adapted to new tasks with just a few gradient steps.

 
### Architecture and Components

 
```

```

 MAML in Garage is implemented as a class that wraps around an inner RL algorithm (typically VPG, PPO, or TRPO). It performs:

 
 - **Inner Loop Adaptation**: Adapts policy parameters to specific tasks using gradient descent
 - **Meta Optimization**: Updates the initial policy parameters to optimize performance across tasks after adaptation
 
 Key components:

 
 - **Inner Algorithm**: Base RL algorithm (VPG, PPO, TRPO) used for task adaptation
 - **Task Sampler**: Provides tasks for meta-training
 - **Inner Optimizer**: Typically a differentiable SGD for the inner loop updates
 - **Meta Optimizer**: Optimizes the initial policy parameters
 
 
### Implementation Details

 The MAML class is implemented in [src/garage/torch/algos/maml.py21-531](https://github.com/rlworkgroup/garage/blob/2d594803/src/garage/torch/algos/maml.py#L21-L531) The core methods include:

 
 - `train()`: Manages the meta-training process
 - `_train_once()`: Performs one meta-update iteration
 - `_adapt()`: Performs the inner loop adaptation for a single task
 - `_meta_optimize()`: Updates the initial policy parameters
 - `adapt_policy()`: Public method to adapt a policy to a new task during meta-testing
 
 MAML uses `DifferentiableSGD` from [src/garage/torch/optimizers/differentiable_sgd.py9-69](https://github.com/rlworkgroup/garage/blob/2d594803/src/garage/torch/optimizers/differentiable_sgd.py#L9-L69) for the inner loop optimization, which allows gradients to flow through the adaptation process.

## PEARL (Probabilistic Embeddings for Actor-Critic RL)

 PEARL is an off-policy meta-RL algorithm that uses a latent context variable to encode task information. It combines off-policy RL with probabilistic encoder networks for efficient meta-learning.

 
### Architecture and Components

 
```

```

 PEARL leverages a probabilistic encoder to extract task-specific information from experience and condition a policy on this information, allowing for rapid adaptation to new tasks.

 Key components:

 
 - **Context Encoder**: Encodes task-relevant information into a latent variable z
 - **Context-Conditioned Policy**: Policy conditioned on the latent context
 - **Off-Policy Learning**: Uses SAC-style components (dual Q-functions, value function)
 - **Replay Buffers**: Task-specific replay buffers for experience storage
 
 
### Implementation Details

 The PEARL class is implemented in [src/garage/torch/algos/pearl.py24-691](https://github.com/rlworkgroup/garage/blob/2d594803/src/garage/torch/algos/pearl.py#L24-L691) The core methods include:

 
 - `train()`: Manages the meta-training process
 - `_train_once()`: Performs one training iteration
 - `_optimize_policy()`: Updates policy and value function parameters
 - `_sample_context()`: Samples context from replay buffers for tasks
 - `adapt_policy()`: Adapts a policy to a new task during meta-testing
 
 PEARL also includes a custom worker class `PEARLWorker` for sampling with context accumulation.

## Implementing Custom Meta-RL Algorithms

 To implement a custom Meta-RL algorithm in Garage, you should:

 
 - Extend the appropriate base class (typically `MetaRLAlgorithm` for PEARL or implement a similar pattern to MAML)
 - Implement the meta-learning interface methods (`get_exploration_policy`, `adapt_policy`)
 - Implement the training loop that handles task sampling, adaptation, and meta-updates
 - Ensure compatibility with Garage's `Trainer` and `MetaEvaluator`
 
 The key challenge in implementing Meta-RL algorithms is correctly handling the dual optimization: the inner loop for task adaptation and the outer loop for meta-optimization.
