## Purpose and Scope

 This document outlines the testing infrastructure in the garage framework, explaining how to write, run, and understand the test suite. The testing system helps ensure that new code additions maintain compatibility and performance standards. For information about continuous integration pipelines, see [CI Pipeline](https://deepwiki.com/rlworkgroup/garage/5.4-ci-pipeline).

 
## Testing Architecture Overview

 The garage testing framework uses pytest as its primary testing tool and includes specialized fixtures, custom test classes, and performance benchmarks. Tests are organized to mirror the structure of the main codebase, with specific tests for each algorithm, policy, environment integration, and other components.

## Test Fixtures

 Test fixtures provide reusable test components and setup/teardown functionality. Garage includes several custom fixtures designed specifically for testing reinforcement learning algorithms.

 
### Key Test Fixtures

 
 - **TfTestCase**: Base class for tests requiring a TensorFlow session

 
 - Sets up and tears down a TensorFlow session for each test
 - Handles proper cleanup of TensorFlow resources
 - **TfGraphTestCase**: Extends TfTestCase with additional graph management

 
 - Creates a new TensorFlow graph for each test
 - Ensures proper isolation between tests
 - Handles deterministic seeding for reproducibility
 - **snapshot_config**: Configuration for snapshots during tests

 
 - Used by trainers to save and restore experiment state
 - Configured to use a test-specific directory

## Writing Tests

 
### Guidelines for Writing Tests

 
 - Create a new test file in the appropriate test directory
 - Use the naming convention `test_<component_name>.py`
 - Extend the appropriate test base class if needed (e.g., `TfGraphTestCase`)
 - Use pytest fixtures and markers appropriately
 - For algorithm tests, verify performance meets minimum thresholds
 
 
### Algorithm Test Example

 Algorithm tests typically:

 
 - Create an environment
 - Initialize a policy and other required components
 - Create and configure the algorithm
 - Train for a small number of epochs
 - Assert that performance exceeds a minimum threshold

## Custom Test Classes

 Garage provides custom test classes to handle common test setup and teardown operations, particularly for TensorFlow-based tests.

 
### TfTestCase

 Base class for tests requiring a TensorFlow session, handling:

 
 - Session creation and cleanup
 - Memory management for TensorFlow resources
 
 
### TfGraphTestCase

 Extended test class that:

 
 - Creates a new TensorFlow graph for each test
 - Sets up a deterministic seed for reproducibility
 - Configures the logger with a null output for clean test logs
 - Handles proper cleanup to prevent memory leaks

## Test Coverage and Requirements

 
### Test Coverage Goals

 New code should include tests for:

 
 - New functionality (unit tests)
 - Integration with existing components
 - Performance verification for algorithms
 
 
### Test Requirements for Pull Requests

 As stated in [CONTRIBUTING.md241-246](https://github.com/rlworkgroup/garage/blob/2d594803/CONTRIBUTING.md?plain=1#L241-L246):

 
 - New functionality should always include unit tests and integration tests
 - Bug fixes should include tests that replicate the fixed bug
 - All tests must pass before a PR can be merged
