## StepType Enum

 The `StepType` enum represents the status of a time step within an episode sequence, which is crucial for correctly handling episode boundaries in reinforcement learning algorithms.

 
```

```

 The enum has four possible values:

 
 - `FIRST (0)`: Denotes the first step in an episode
 - `MID (1)`: Denotes any step in the middle of an episode (not the first or last)
 - `TERMINAL (2)`: Denotes the last step in an episode that terminates successfully
 - `TIMEOUT (3)`: Denotes the last step in an episode truncated by time limit
 
 For example, in an episode with max_episode_length = 5:

 
 - A successful sequence terminating at step 4: FIRST, MID, MID, TERMINAL
 - A sequence truncated by time limit: FIRST, MID, MID, MID, TIMEOUT
 
 The `get_step_type` class method determines the appropriate step type based on the current step count, maximum episode length, and done signal from the environment.

## TimeStep

 The `TimeStep` class represents a single transition in an environment, corresponding to a SARS (State-Action-Reward-State) tuple. It captures all information for one agent-environment interaction.

 
```

```

 Key features of `TimeStep`:

 
 - Implemented as a frozen dataclass (immutable)
 - Contains both the observation before an action (`observation`) and after an action (`next_observation`)
 - Contains agent information (`agent_info`) and environment information (`env_info`)
 - Has properties to easily check the status of a step (first, mid, terminal, timeout, last)
 - Can be created from an `EnvStep` using the `from_env_step` class method

## TimeStepBatch

 The `TimeStepBatch` class represents a batch of time steps, primarily used for off-policy algorithms, imitation learning, and batch reinforcement learning.

 
```

```

 Key features of `TimeStepBatch`:

 
 - Contains numpy arrays instead of single values
 - Provides utility methods for batch manipulation: 
 - `concatenate`: Combines multiple batches
 - `split`: Splits a batch into individual time steps
 - `to_time_step_list`: Converts to a list of dictionaries
 - `from_time_step_list`: Creates a batch from a list of time step dictionaries
 - Has a `terminals` property for easy access to termination information

## EpisodeBatch

 The `EpisodeBatch` class extends `TimeStepBatch` and represents a batch of complete episodes, used primarily for on-policy algorithms.

 
```

```

 Key features of `EpisodeBatch`:

 
 - Inherits all attributes and methods from `TimeStepBatch`
 - Adds episode-specific functionality: 
 - `last_observations`: Final observations for each episode
 - `lengths`: Lengths of each episode
 - Episode padding methods for fixed-length batch processing (`padded_observations`, `padded_actions`, etc.)
 - `actions_list` and `observations_list` for easy access to actions and observations by episode
 - Methods tailored for episode-based data: 
 - `to_list`: Converts to a list of episode dictionaries
 - `from_list`: Creates a batch from a list of episode dictionaries

## PathBuffer (Replay Buffer)

 The `PathBuffer` class implements a replay buffer that efficiently stores and samples complete episodes or transitions, primarily used for off-policy algorithms.

 
```

```

 Key features of `PathBuffer`:

 
 - Efficiently stores complete episodes in a fixed-size buffer
 - Handles circular buffer management with wraparound semantics
 - Provides methods to: 
 - Add episodes (`add_episode_batch`) or individual paths (`add_path`)
 - Sample complete paths (`sample_path`) or individual transitions (`sample_transitions`)
 - Sample transitions as a `TimeStepBatch` (`sample_timesteps`)
 - Intelligently manages the buffer to maximize memory utilization

## InProgressEpisode

 The `InProgressEpisode` class represents an episode currently being collected by a worker, before it's converted to an `EpisodeBatch`.

 
```

```

 Key features of `InProgressEpisode`:

 
 - Lightweight, using lists instead of numpy arrays for faster append operations
 - Maintains the current state of an episode being collected
 - Provides a `step` method to record a single environment step
 - Converts to an `EpisodeBatch` when completed using `to_batch()`
 - Provides access to the last observation through the `last_obs` property

## Data Structure Relationships

 The following table summarizes the key data structures and their primary uses:

 
| Data Structure | Primary Use | Algorithm Type | Implementation |
|---|---|---|---|
| StepType | Representing step status | All | Enum |
| TimeStep | Single agent-environment interaction | All | Frozen dataclass |
| TimeStepBatch | Batch of transitions | Off-policy | Frozen dataclass |
| EpisodeBatch | Batch of complete episodes | On-policy | Frozen dataclass extending TimeStepBatch |
| InProgressEpisode | Episode being collected | Sampling | Class |
| PathBuffer | Storing experience for replay | Off-policy | Class |
