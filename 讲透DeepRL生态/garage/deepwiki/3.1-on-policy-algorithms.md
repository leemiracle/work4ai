  This document provides an in-depth explanation of on-policy reinforcement learning algorithms implemented in the garage framework. On-policy algorithms learn by collecting data using the current policy and then updating that same policy. This is in contrast to off-policy algorithms (covered in [Off-Policy Algorithms](https://deepwiki.com/rlworkgroup/garage/3.2-off-policy-algorithms)), which can learn from data collected by different policies.

 
## What are On-Policy Algorithms?

 On-policy reinforcement learning algorithms follow a specific pattern:

 
 - Collect experience (states, actions, rewards) by running the current policy in the environment
 - Use this experience to update the policy
 - Discard the collected data (since it's no longer "on-policy" after the update)
 - Repeat
 
 The key characteristic of on-policy methods is that they only use data collected from the current policy for updates, making them conceptually simple but potentially sample-inefficient compared to off-policy methods.

## On-Policy Algorithm Implementations

 Garage implements several on-policy algorithms with variations in both TensorFlow and PyTorch.

 
### VPG (Vanilla Policy Gradient)

 Vanilla Policy Gradient, also known as REINFORCE, is the simplest form of policy gradient methods. It directly optimizes the policy by calculating gradients of the expected return with respect to policy parameters.

 Key characteristics:

 
 - Simple gradient ascent on policy parameters
 - No constraints on policy updates
 - Often has high variance in gradient estimates

### NPO (Natural Policy Optimization)

 Natural Policy Optimization is a framework that uses natural gradient for policy updates. It considers the curvature of the policy distribution to make more efficient updates.

 Key characteristics:

 
 - Uses Fisher Information Matrix to compute natural gradients
 - Enforces constraints on policy updates
 - Serves as the foundation for TRPO and other algorithms
 
 NPO offers several policy loss options:

 
 - `vanilla`: Standard policy gradient
 - `surrogate`: Importance-weighted surrogate objective
 - `surrogate_clip`: Clipped surrogate objective (used in PPO)

### TRPO (Trust Region Policy Optimization)

 TRPO is a special case of NPO that enforces a trust region constraint using KL divergence between the old and new policies.

 Key characteristics:

 
 - Uses a max KL divergence constraint to limit policy updates
 - Often uses Conjugate Gradient and line search for optimization
 - Generally more stable than VPG

### PPO (Proximal Policy Optimization)

 PPO is another variant of NPO that uses a clipped surrogate objective to constrain policy updates. It's simpler to implement than TRPO while achieving similar performance.

 Key characteristics:

 
 - Uses a clipped surrogate objective
 - Can be optimized with standard gradient descent methods
 - Often more sample-efficient than TRPO

### TNPG (Truncated Natural Policy Gradient)

 TNPG is a variant of natural policy gradient that uses a truncated approach to compute the natural gradient.

 Key characteristics:

 
 - Uses Conjugate Gradient to approximate the natural gradient
 - Often more computationally efficient than full NPO
 
 Sources:

 
 - [tests/garage/tf/algos/test_tnpg.py15-46](https://github.com/rlworkgroup/garage/blob/2d594803/tests/garage/tf/algos/test_tnpg.py#L15-L46)
 
 
### REPS (Relative Entropy Policy Search)

 REPS is an on-policy method that frames policy optimization as a relative entropy minimization problem.

 Key characteristics:

 
 - Optimizes policy while minimizing KL divergence to the previous policy
 - Uses a dual optimization procedure
 - Incorporates explicit constraints on policy updates
 
 Sources:

 
 - [src/garage/tf/algos/reps.py22-550](https://github.com/rlworkgroup/garage/blob/2d594803/src/garage/tf/algos/reps.py#L22-L550)

### ERWR (Episodic Reward Weighted Regression)

 ERWR is an on-policy algorithm that treats policy learning as a weighted regression problem, where the weights are derived from the returns.

 Key characteristics:

 
 - Formulates policy learning as a weighted maximum likelihood problem
 - Weights examples by their returns
 - Often simpler to implement than other methods

## Algorithm Comparison

 The following table summarizes the key differences between on-policy algorithms in garage:

 
| Algorithm | Policy Update Mechanism | Constraint Type | Optimization Method |
|---|---|---|---|
| VPG | Direct gradient ascent | None | First-order gradient descent |
| NPO | Natural gradient | Variable (framework) | Depends on variant |
| TRPO | Natural gradient | Hard KL constraint | Conjugate gradient + line search |
| PPO | Surrogate objective | Clipped objective | First-order gradient descent |
| TNPG | Truncated natural gradient | Approximate KL | Conjugate gradient |
| REPS | Relative entropy | KL divergence | Dual optimization |
| ERWR | Weighted regression | Implicit via weights | Weighted maximum likelihood |

### Implementation Differences

 While the algorithmic principles remain the same, there are some implementation differences between TensorFlow and PyTorch versions:

 
 - **Interface**: PyTorch implementations often have a more object-oriented interface
 - **Optimization**: TensorFlow implementations typically use symbolic computation, while PyTorch uses dynamic computation
 - **Meta-Learning**: Meta-learning algorithms like MAML are primarily implemented in PyTorch

## Conclusion

 On-policy algorithms in garage provide a comprehensive suite of policy optimization methods with different trade-offs in terms of sample efficiency, stability, and complexity. The framework's implementations across both TensorFlow and PyTorch allow for flexible experimentation while maintaining a consistent interface.

 When selecting an on-policy algorithm, consider:

 
 - TRPO or PPO for general-purpose policy optimization with good stability
 - VPG for simplicity and when sample efficiency is less critical
 - REPS or ERWR for problems where explicit constraints may be beneficial
 - TNPG when computational efficiency is important
 
 For more details about off-policy algorithms, see the [Off-Policy Algorithms](https://deepwiki.com/rlworkgroup/garage/3.2-off-policy-algorithms) page.
