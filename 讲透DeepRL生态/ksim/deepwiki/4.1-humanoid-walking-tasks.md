## Purpose and Scope

 This document describes the implementation and configuration of the basic humanoid walking task in KSIM. The humanoid walking task is a foundational example that demonstrates how to create locomotion agents using the KSIM framework. This page focuses on the standard feedforward policy implementation, while more advanced implementations like RNN-based tasks are covered in [RNN-based Walking Tasks](https://deepwiki.com/kscalelabs/ksim/4.2-rnn-based-walking-tasks) and AMP-based implementations in [AMP-based Walking Tasks](https://deepwiki.com/kscalelabs/ksim/4.3-amp-based-walking-tasks).

 
## Architectural Overview

 The humanoid walking task is implemented as a concrete class that inherits from `ksim.PPOTask`. It defines all the components necessary for training a humanoid to walk using Proximal Policy Optimization (PPO), including the physics model, observations, rewards, terminations, and a neural network policy.

## Task Configuration

 The humanoid walking task is configured through the `HumanoidWalkingTaskConfig` class, which extends `ksim.PPOConfig`. This configuration object defines parameters for:

 
 - Model architecture (hidden size, network depth, number of mixtures)
 - Reward parameters (target velocities)
 - Optimizer parameters (learning rate, weight decay)
 - Curriculum parameters (levels, thresholds for progression)
 - Rendering parameters
 
 
```

```

 Sources: [examples/walking.py159-222](https://github.com/kscalelabs/ksim/blob/9d26400d/examples/walking.py#L159-L222)

 The key configuration parameters are:

 
| Parameter | Default | Description |
|---|---|---|
| hidden_size | 128 | Hidden layer size for the neural networks |
| depth | 5 | Number of layers in the MLPs |
| num_mixtures | 5 | Number of Gaussian mixtures in action distribution |
| target_linear_velocity | 2.0 | Target forward velocity in m/s |
| target_angular_velocity | 90° | Target angular velocity in radians/s |
| learning_rate | 1e-3 | Learning rate for PPO |
| num_curriculum_levels | 10 | Number of difficulty levels |

 Sources: [examples/walking.py159-222](https://github.com/kscalelabs/ksim/blob/9d26400d/examples/walking.py#L159-L222)

### Randomization and Events

 To improve policy robustness, the task includes several randomizers that vary the physics parameters:

 
| Randomizer | Purpose |
|---|---|
| StaticFrictionRandomizer | Varies floor friction |
| ArmatureRandomizer | Varies motor armature (inertia) |
| MassMultiplicationRandomizer | Varies body mass |
| JointDampingRandomizer | Varies joint damping |
| JointZeroPositionRandomizer | Varies joint rest positions |

 The task also includes a push event that applies random forces to the humanoid at random intervals:

### Terminations

 The episode terminates under the following conditions:

 
| Termination | Description |
|---|---|
| BadZTermination | Humanoid's COM is too high or too low (0.9-1.6m range) |
| FarFromOriginTermination | Humanoid has wandered too far (>10m from origin) |
