## Purpose and Overview

 This document describes the `AMPTask` class in ksim, which implements Adversarial Motion Priors (AMP) for reinforcement learning. AMP is a framework that uses adversarial training to teach agents to produce realistic motions by comparing their behaviors against reference motion data. The `AMPTask` system extends the PPO (Proximal Policy Optimization) framework with discriminator-based rewards to encourage natural movements.

 For information about the base reinforcement learning task system, see [RLTask and PPOTask (2.1)](https://deepwiki.com/kscalelabs/ksim/2.1-rltask-and-ppotask).

### Policy Model

 The policy model in AMP is responsible for generating actions that control the simulated character:

 
 - Abstract method `get_policy_model()` must be implemented to create the policy network
 - Typically an actor-critic architecture as in PPO tasks
 - Can include recurrent networks (RNNs) for temporal modeling
 - Trained using PPO with additional rewards from the discriminator
 
 Sources: [ksim/task/amp.py173-175](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/task/amp.py#L173-L175) [examples/walking_amp.py532-542](https://github.com/kscalelabs/ksim/blob/9d26400d/examples/walking_amp.py#L532-L542)

 
### Discriminator Model

 The discriminator distinguishes between real and simulated motions:

 
 - Created through `get_discriminator_model()`
 - Processes motion data (e.g., joint positions over time)
 - Outputs logits that indicate how realistic the motion is
 - Used by `AMPReward` to encourage realistic movements
 
 The discriminator is trained to maximize the score for real motions and minimize it for simulated ones.

### Reference Motion System

 AMP requires reference motion data as ground truth for realistic movements:

 
 - Provided through `get_real_motions()` method
 - Can come from motion capture (MoCap) data, often in BVH format
 - Processed to match the simulation model's joints
 - Used to train the discriminator as the positive examples

### Training Loop and Updates

 The AMP training loop extends the PPO update process with specialized processing:

 
 - **Trajectory Collection**: Standard PPO rollouts generate trajectories
 - **Motion Conversion**: Convert trajectories to the motion format using `trajectory_to_motion()`
 - **Discriminator Evaluation**: Pass motions through discriminator and add results to auxiliary outputs
 - **Discriminator Training**: Train the discriminator to differentiate real and simulated motions
 - **Policy Training**: Train the policy using PPO with the additional AMP reward

## Implementation Details

 
### Required Methods

 To implement an `AMPTask` subclass, you must define these abstract methods:

 
| Method | Purpose |
|---|---|
| get_policy_model() | Creates the policy network |
| get_discriminator_model() | Creates the discriminator network |
| get_policy_optimizer() | Creates the optimizer for the policy |
| get_discriminator_optimizer() | Creates the optimizer for the discriminator |
| get_real_motions() | Loads reference motion data |
| call_discriminator() | Applies discriminator to motion data |
| trajectory_to_motion() | Converts trajectories to motion format |

 Sources: [ksim/task/amp.py173-255](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/task/amp.py#L173-L255)

 
### Trajectory Processing

 The `postprocess_trajectory` method adds discriminator outputs to trajectories:

 
 - Extracts policy-generated motion using `trajectory_to_motion()`
 - Passes the motion through the discriminator
 - Adds the resulting logits to the trajectory's auxiliary outputs
 - These outputs are then used by `AMPReward` to compute rewards

## Using AMPTask in Your Project

 To create a custom AMP task:

 
 - Subclass `AMPTask` and implement all required abstract methods
 - Create appropriate policy and discriminator models
 - Prepare reference motion data in a suitable format
 - Include `AMPReward` in your rewards list
 - Implement proper conversion between trajectories and motions
 
 Sources: [ksim/task/amp.py86-94](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/task/amp.py#L86-L94) [ksim/task/amp.py437-453](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/task/amp.py#L437-L453)

 
## Best Practices

 
 - **Reference Data Quality**: The quality of reference motions significantly impacts results
 - **Discriminator Architecture**: Design the discriminator to effectively process temporal motion patterns
 - **Motion Representation**: Choose a consistent representation for both simulated and reference motions
 - **Balanced Training**: Ensure the discriminator and policy training are balanced to avoid mode collapse
 - **Reward Mix**: Combine AMP rewards with task-specific rewards for goal-directed behavior
