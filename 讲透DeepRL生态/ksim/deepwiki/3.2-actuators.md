## Purpose and Scope

 This document covers the actuator system in KSIM, which is responsible for translating abstract control actions into physical forces or torques applied to robot joints during simulation. Actuators serve as the interface between control policies and the physics engine, implementing various control schemes such as direct torque control, position control, or position-velocity control.

 The actuator system handles:

 
 - Converting normalized policy actions to physical control signals
 - Implementing PD controllers and other control schemes
 - Applying realistic control constraints like torque limits
 - Adding noise to simulate real-world actuator imperfections
 
 For topics related to physics engines that use these actuators, see [Physics Engine and Data Structures](https://deepwiki.com/kscalelabs/ksim/3.1-physics-engine-and-data-structures).

 Sources: [ksim/actuators.py1-10](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/actuators.py#L1-L10)

 
## Actuator Architecture

 The actuator system is designed with a clear class hierarchy to support different control approaches while maintaining a consistent interface for the physics engine.

 
```

```

 The base `Actuators` class defines the core interface for translating actions to control signals. The `StatefulActuators` specialization adds state tracking for actuators that need to maintain information between timesteps. Three concrete implementations are provided:

 
 - `TorqueActuators`: Direct torque control (simplest model)
 - `PositionActuators`: Position-based PD control (MIT Cheetah-style)
 - `PositionVelocityActuator`: Extended PD control for both position and velocity targets

## Integration with Physics Engine

 Actuators are a core component of the physics simulation pipeline. The `PhysicsEngine` uses actuators to apply control signals at each simulation step.

 
```

```

 During initialization, the engine links to a specific actuator implementation. When running the simulation:

 
 - The policy outputs an action vector
 - The engine passes this action to the actuators
 - The actuators transform the action into physical control signals
 - The control signals are applied to the simulation
 - The physics engine steps forward in time
 
 For stateful actuators, the engine also tracks and updates the actuator state with each step.


 Sources: [ksim/actuators.py71-83](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/actuators.py#L71-L83)

 
### PositionActuators

 Implements a PD (Proportional-Derivative) controller that converts target joint positions into torques. This is similar to the controller used in the MIT Cheetah robot.

 
```

```

 The PD formula used is:

 
```
torque = Kp * (target_pos - current_pos) + Kd * (target_vel - current_vel)
```

 Where:

 
 - `Kp` and `Kd` are the proportional and derivative gains from joint metadata
 - Target velocity is assumed to be zero unless specified
 
 The resulting torque is clipped to the joint's torque limits.

 Sources: [ksim/actuators.py86-166](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/actuators.py#L86-L166)

 
### PositionVelocityActuator

 An extended version of `PositionActuators` that accepts both position and velocity targets in the policy output. The first half of the action vector specifies target positions, and the second half specifies target velocities.

 
```

```

 This actuator allows for more sophisticated control strategies that can specify both static positions and dynamic movements.

## Actuator Configuration and Metadata

 Actuators rely on metadata about each joint to properly apply control. This metadata is defined in the `JointMetadata` and `ActuatorMetadata` classes.

 
### Key Joint Parameters

 
| Parameter | Description | Used By |
|---|---|---|
| kp | Proportional gain | Position-based actuators |
| kd | Derivative gain | Position-based actuators |
| armature | Motor inertia | Physics model |
| friction | Joint friction | Physics model |
| actuator_type | Type of actuator | Actuator selection |
| soft_torque_limit | Max torque limit | All actuators |

 
```

```

 When initializing position-based actuators, the constructor extracts parameters from the provided metadata and converts them into arrays for efficient vectorized computation.

## Noise Models

 All actuator implementations support adding noise to simulate real-world imperfections. Three noise types are available:

 
 - **None**: No noise is added
 - **Uniform**: Random uniform noise in range [-noise, noise]
 - **Gaussian**: Random normal noise with standard deviation of `noise`
