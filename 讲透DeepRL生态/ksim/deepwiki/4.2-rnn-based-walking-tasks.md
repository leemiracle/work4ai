## Overview

 This page documents the recurrent neural network (RNN) implementation for humanoid walking tasks in the KSIM framework. The RNN-based approach enables the agent to maintain memory of past states, which is particularly beneficial for controlling complex robotic systems like humanoids where temporal dependencies are important. This implementation extends the basic walking task (see [Humanoid Walking Tasks](https://deepwiki.com/kscalelabs/ksim/4.1-humanoid-walking-tasks)) with recurrent neural networks to enhance control capabilities.

 The RNN-based implementation is specifically designed for scenarios requiring temporal context and memory, providing improved stability and performance for complex movement patterns.

 Sources: [examples/walking_rnn.py1-15](https://github.com/kscalelabs/ksim/blob/9d26400d/examples/walking_rnn.py#L1-L15)

## RNN Model Architecture

 The RNN-based walking task implements both an actor and a critic, each using GRU (Gated Recurrent Unit) cells for maintaining temporal state across timesteps. This enables the model to capture sequential patterns and maintain memory of past observations.

### Actor Architecture

 The actor model is responsible for generating actions based on observations. It uses a multi-layer GRU network followed by a mixture of Gaussians output distribution, which provides a more expressive policy representation compared to a single Gaussian.

 Key components:

 
 - Input projection layer: Maps observation vectors to the hidden dimension
 - GRU layers: Process sequential information and maintain state
 - Output projection layer: Maps hidden states to distribution parameters
 - Mixture of Gaussians distribution: Models complex, multi-modal action distributions
 
 Sources: [examples/walking_rnn.py25-108](https://github.com/kscalelabs/ksim/blob/9d26400d/examples/walking_rnn.py#L25-L108)

 
### Critic Architecture

 The critic model estimates the value function, which is used for advantage estimation in the PPO algorithm. Like the actor, it also uses GRU cells to maintain temporal context.

 Key components:

 
 - Input projection layer: Maps observation vectors to the hidden dimension
 - GRU layers: Process sequential information and maintain state
 - Output projection layer: Maps hidden states to scalar value estimates
 
 Sources: [examples/walking_rnn.py111-165](https://github.com/kscalelabs/ksim/blob/9d26400d/examples/walking_rnn.py#L111-L165)

 
### Mixture of Gaussians Output

 The actor's output layer parameterizes a mixture of Gaussians distribution, which allows the model to represent multi-modal and more complex action distributions than a simple Gaussian.

 The output layer produces three sets of parameters for each joint and mixture component:

 
 - Means: The center of each Gaussian component
 - Standard deviations: The width of each Gaussian component
 - Logits: The weight of each Gaussian component

### Carry Initialization and Reset

 The model's recurrent state (carry) is initialized with zeros at the beginning of each episode and is reset when an episode terminates. This ensures that the model begins each new episode with a clean state.

### Carry State Updates

 During rollout, the carry state is updated at each timestep and passed to the next timestep. The updated carry state is returned alongside the model's outputs (actions or values) and is part of the `Action` object.

## Observation Processing

 The RNN-based task processes a rich set of observations, including:

 
 - Joint positions and velocities
 - Center of mass information
 - Projected gravity
 - Actuator forces
 - Base position, orientation, and velocities
 - Joystick commands
 
 These observations are preprocessed (normalized, concatenated) before being fed to the actor and critic networks.

 Sources: [examples/walking_rnn.py246-263](https://github.com/kscalelabs/ksim/blob/9d26400d/examples/walking_rnn.py#L246-L263) [examples/walking_rnn.py289-306](https://github.com/kscalelabs/ksim/blob/9d26400d/examples/walking_rnn.py#L289-L306)

 
## PPO Training Integration

 The RNN-based task integrates with the PPO (Proximal Policy Optimization) algorithm for training. It provides methods to compute PPO variables (log probabilities, values) and processes trajectories while maintaining recurrent state.

 The `get_ppo_variables` method scans through a trajectory, computing log probabilities and values while properly handling the RNN state across timesteps and episode boundaries.

 Sources: [examples/walking_rnn.py310-352](https://github.com/kscalelabs/ksim/blob/9d26400d/examples/walking_rnn.py#L310-L352)

 
## Sample Action Implementation

 The `sample_action` method runs the actor model to obtain action distributions, samples actions, and returns both the action and the updated carry state. It supports both sampling and taking the mode of the distribution (for deterministic evaluation).
