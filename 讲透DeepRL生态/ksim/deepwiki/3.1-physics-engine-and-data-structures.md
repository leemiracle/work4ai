## Purpose and Scope

 This document details the physics simulation system at the core of the KSIM framework, including the physics engine interface, engines implementations, and essential data structures. The physics simulation system provides the foundation upon which reinforcement learning tasks operate by simulating the physical interactions of robots with their environment.

 For information about the specific components that build on this foundation, see [Actuators](https://deepwiki.com/kscalelabs/ksim/3.2-actuators), [Reset System](https://deepwiki.com/kscalelabs/ksim/3.3-reset-system), and [Physics Randomization](https://deepwiki.com/kscalelabs/ksim/3.4-physics-randomization).

### PhysicsState Dataclass

 The `PhysicsState` dataclass encapsulates all necessary information for the physics engine to step the simulation:

 
```

```

 Sources: [ksim/types.py37-47](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/types.py#L37-L47)

 The `PhysicsState` includes:

 
 - `most_recent_action`: The last action applied to the environment
 - `data`: The actual physics data (MjData or mjx.Data)
 - `event_states`: States of all registered events
 - `actuator_state`: State of the actuators (used for stateful actuators)
 - `action_latency`: Simulated latency for action application

## Conclusion

 The physics engine and its associated data structures form the foundation of the KSIM simulation framework. By supporting both standard MuJoCo and JAX-accelerated MJX engines, KSIM provides flexibility for different use cases - from interactive visualization to GPU-accelerated batch simulation for reinforcement learning.

 The physics engine handles the core simulation loop, while integrated systems for resets, events, and actuators provide specialized functionality for different aspects of the simulation. The `PhysicsState` data structure encapsulates all necessary information for the simulation to advance, providing a clean interface between the physics engine and higher-level RL framework.
