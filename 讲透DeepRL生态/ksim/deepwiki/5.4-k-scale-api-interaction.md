## Purpose and Scope

 This document details the utilities provided in KSIM for interacting with the K-Scale API, which enables access to robot models and their associated metadata. These utilities facilitate the retrieval and caching of MuJoCo models for use in simulation tasks within the KSIM framework. For information about dataset utilities, see [Dataset Utilities](https://deepwiki.com/kscalelabs/ksim/5.3-dataset-utilities).

## Core API Functions

 The K-Scale API integration is built around three primary functions:

 
### Model Path Retrieval

 The `get_mujoco_model_path` function downloads and caches robot models in MuJoCo format when they aren't available locally.

## Usage in KSIM

 Within the KSIM framework, these API interaction utilities are typically used when initializing a simulation task that requires a specific robot model. The workflow usually follows these steps:

 
 - A task class requests a model and its metadata using `get_mujoco_model_and_metadata`
 - The function retrieves and caches the model and metadata from K-Scale
 - The task loads the model into the physics engine using the returned path
 - The task configures the simulation based on the returned metadata
 
 
### Example Usage Pattern

 The following table illustrates the typical pattern for using these functions in KSIM tasks:

 
| Step | Description | Typical Function |
|---|---|---|
| 1 | Task initialization | __init__ of task class |
| 2 | Model and metadata retrieval | get_mujoco_model_and_metadata |
| 3 | Model loading | mujoco.MjModel.from_xml_path |
| 4 | Simulation configuration | Custom task configuration code |
| 5 | Simulation execution | RLTask.run |

 Sources: [ksim/utils/api.py74-90](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/utils/api.py#L74-L90)

 
## Caching Mechanism

 The K-Scale API interaction utilities implement a caching system to avoid redundant downloads and improve performance:

 
 - By default, all downloaded models and metadata are cached locally
 - The cache can be bypassed by setting `cache=False` in function calls
 - For metadata, the system checks if cached files should be refreshed based on their age
 - Downloaded models are stored in a directory structure mirroring the K-Scale repository organization
 
 Sources: [ksim/utils/api.py23-90](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/utils/api.py#L23-L90)

## Summary

 The K-Scale API interaction utilities provide a seamless way to access and utilize robot models within the KSIM framework. They handle the complexities of model retrieval, metadata processing, and caching, allowing KSIM tasks to focus on simulation logic rather than resource management.

 Key features:

 
 - Asynchronous API interaction
 - Automatic caching with refresh capabilities
 - Parallel retrieval of models and metadata
 - Conversion between K-Scale and KSIM metadata formats
 - Integration with the broader KSIM framework
