  This document provides detailed documentation of the `RLTask` and `PPOTask` classes, which form the core reinforcement learning framework in KSIM. These abstract base classes define the interface for training reinforcement learning agents in robotic simulation. For information about the AMP extension to PPO, see [AMPTask (Adversarial Motion Priors)](https://deepwiki.com/kscalelabs/ksim/2.2-amptask-(adversarial-motion-priors)).

 
## Purpose and Overview

 The `RLTask` class serves as the foundation for all reinforcement learning tasks in KSIM, providing:

 
 - A standardized interface for defining RL tasks
 - Environment setup and management
 - Training, visualization, and dataset collection
 - Rollout execution and reward computation
 
 The `PPOTask` class extends `RLTask` to implement Proximal Policy Optimization (PPO), a popular policy gradient method for reinforcement learning.

## Configuration and Data Structures

 Both `RLTask` and `PPOTask` have corresponding configuration classes:

 
### RLConfig

 `RLConfig` contains parameters for basic RL task execution:

 
 - Run mode control (`train`, `view`, `collect_dataset`)
 - Environment parameters (number of environments, batch size)
 - Rollout parameters (length, frequency)
 - Rendering options (height, width, camera settings)
 - Physics engine parameters (time step, solver type, integrator)
 
 Source: [ksim/task/rl.py327-545](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/task/rl.py#L327-L545)

 
### PPOConfig

 `PPOConfig` extends `RLConfig` with PPO-specific parameters:

 
 - PPO clipping parameter (`clip_param`)
 - Value loss coefficient (`value_loss_coef`)
 - Entropy coefficient (`entropy_coef`)
 - KL divergence coefficient (`kl_coef`)
 - Discount factor (`gamma`)
 - GAE lambda parameter (`lam`)
 - Number of optimization passes (`num_passes`)
 
 Source: [ksim/task/ppo.py247-297](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/task/ppo.py#L247-L297)

 
### Core Data Structures

 The framework uses several data structures to manage the RL training process:

 
 - `RolloutConstants`: Constants for the rollout loop
 - `RolloutSharedState`: Variables shared across all environments
 - `RolloutEnvState`: Per-environment variables for the rollout
 - `PPOInputs`: Advantages, value targets, GAE, and returns
 - `PPOVariables`: Log probabilities, values, entropy, and auxiliary losses

## PPO Algorithm Implementation

 The `PPOTask` class implements Proximal Policy Optimization with these key components:

 
### Computing PPO Inputs

 The `compute_ppo_inputs` function calculates Generalized Advantage Estimation (GAE):

 
 - Computes temporal difference (TD) errors
 - Performs a reverse scan to compute advantages and returns
 - Optionally normalizes advantages for training stability
 
 Source: [ksim/task/ppo.py53-106](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/task/ppo.py#L53-L106)

 
### Computing PPO Loss

 The `compute_ppo_loss` function computes the PPO objective:

 
 - Policy loss with clipping to constrain policy updates
 - Value loss (optionally clipped)
 - Entropy bonus to encourage exploration
 - KL penalty to prevent large distribution shifts

## Run Modes

 The `RLTask` class supports three run modes:

 
 - **Train**: Run the full training loop with periodic model updates and visualization
 - **View**: Run an interactive visualization loop for debugging and demonstration
 - **Collect Dataset**: Collect a dataset of trajectories for offline analysis or training
 
 These modes are selected through the `run_mode` configuration parameter.

 Source: [ksim/task/rl.py1005-1030](https://github.com/kscalelabs/ksim/blob/9d26400d/ksim/task/rl.py#L1005-L1030)

 
## Extension Pattern for Custom Tasks

 To create a custom reinforcement learning task with KSIM, you typically:

 
 - Extend `PPOTask` (or `RLTask` if not using PPO)
 - Implement all required abstract methods
 - Create a configuration class extending `PPOConfig`/`RLConfig`
 
 Most KSIM examples follow this pattern, such as humanoid walking tasks that build on these base classes.

 
## Visualization and Logging

 `RLTask` provides built-in visualization capabilities:

 
 - `render_trajectory_video()`: Renders a trajectory as video frames
 - `_log_logged_trajectory_graphs()`: Creates plots of observations, commands, rewards, etc.
 - `log_train_metrics()`: Logs training metrics to the logger

## Relationship to Other Components

 `RLTask` and `PPOTask` interact with many other KSIM components:

 
| Component | Relationship |
|---|---|
| Physics Engine | Simulates the environment dynamics |
| Actuators | Translates agent actions to physical controls |
| Observation System | Extracts environment state information for the agent |
| Command System | Provides goal or target information to the agent |
| Reward System | Computes rewards based on agent behavior |
| Termination System | Determines when episodes should end |
| Curriculum System | Controls task difficulty during training |

 For details on these systems, see their respective documentation pages ([Reward System](https://deepwiki.com/kscalelabs/ksim/2.3-reward-system), [Observation System](https://deepwiki.com/kscalelabs/ksim/2.4-observation-system), etc.).
