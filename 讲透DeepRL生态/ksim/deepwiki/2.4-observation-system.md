  The Observation System is a core component of the KSIM reinforcement learning framework that extracts useful information from the physics simulation environment. It provides a standardized interface for defining what information is accessible to the agent during training and inference, allowing for realistic modeling of robot sensors and enabling noise addition to simulate real-world conditions.

 
## Overview

 In reinforcement learning, observations represent the information that an agent can perceive about its environment. The Observation System in KSIM is designed to:

 
 - Extract relevant state information from the physics simulation
 - Apply realistic sensor characteristics (including noise and latency)
 - Provide a unified interface for accessing different types of observations
 - Support both stateless and stateful observation types

## Creating Custom Observations

 To create a custom observation, subclass either `Observation` or `StatefulObservation` and implement the required methods:

 
 - For `Observation`, implement:

 
 - `observe(self, state, curriculum_level, rng)`: Extract relevant data and return observation array
 - Optionally override `add_noise` for custom noise models
 - Optionally override `get_markers` for visualization
 - For `StatefulObservation`, implement:

 
 - `observe_stateful(self, state, curriculum_level, rng)`: Extract data and update state
 - `initial_carry(self, rng)`: Initialize state

## Best Practices

 
 - **Observation Noise**: Always include appropriate noise in observations to ensure policies are robust to real-world sensor noise
 - **Observation Efficiency**: Keep observations minimal and relevant to the task
 - **Curriculum Learning**: Use the `curriculum_level` parameter to progressively introduce noise during training
 - **Stateful Observations**: Use `StatefulObservation` when implementing filtering or other state-dependent processes
 - **Factory Methods**: Implement `create` class methods for convenient instantiation that handles index lookups
