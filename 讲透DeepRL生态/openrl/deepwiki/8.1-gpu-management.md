## Purpose and Scope

 This document describes how OpenRL manages GPU resources for reinforcement learning training. It covers the GPU detection, allocation strategies, and configuration options available to optimize GPU usage during training. For information about logging and visualization of GPU metrics, see [Logging and Visualization](https://deepwiki.com/OpenRL-Lab/openrl/8.2-logging-and-visualization).

 
## Overview of GPU Management in OpenRL

 OpenRL provides a GPU management system through the `opengpu` module, which handles GPU resource detection, allocation, and monitoring. This system allows users to efficiently utilize available GPU resources for training reinforcement learning agents across various hardware configurations.

## GPU Information Collection

 OpenRL uses the `gpustat` tool to gather information about available GPUs on the local system. This information includes:

 
 - GPU ID
 - Product name
 - Total memory
 - Used memory
 - Free memory
 
 The system respects the `CUDA_VISIBLE_DEVICES` environment variable, allowing users to specify which GPUs should be available to the training process.

## GPU Management Classes

 
### GPUInfo Class

 The `GPUInfo` class represents information about a single GPU device:

 
| Attribute | Description |
|---|---|

| product_name | The name of the GPU model |
| memory_total | Total GPU memory in GB |
| memory_used | Used GPU memory in GB |

## GPU Allocation Strategies

 OpenRL supports several GPU allocation strategies through the `gpu_usage_type` configuration parameter:

 
 - **Auto Mode** (`gpu_usage_type="auto"`): In this mode, the system automatically assigns GPUs to learners and workers based on availability. Different learners may be assigned to different GPUs.
 - **Single Mode** (`gpu_usage_type="single"`): All learners and workers use the same GPU (the first one).
 
 The allocation strategy also respects the `disable_cuda` flag, which, when set to `True`, causes no GPU to be used (CPU-only mode).

## Configuration Parameters

 The GPU management system is configured through the following parameters, which are passed to the `LocalGPUManager` constructor as an `argparse.Namespace` object:

 
| Parameter | Description | Default |
|---|---|---|
| disable_cuda | Whether to disable CUDA and use CPU only | False |
| gpu_usage_type | GPU allocation strategy ("auto" or "single") | "auto" |
| learner_num | Number of learners | 0 |

## Best Practices and Considerations

 When configuring GPU usage in OpenRL, consider the following best practices:

 
 - **Resource Allocation**: Choose the appropriate `gpu_usage_type` based on your hardware setup and training requirements. Use "auto" for multi-GPU systems to take advantage of all available resources, or "single" for single-GPU systems or when you want to control which GPU is used.
 - **Memory Requirements**: Be mindful of memory requirements when training multiple agents on the same GPU. The `GPUInfo` class provides memory usage information that can help determine whether a GPU has sufficient resources.
 - **Environment Variable**: You can use the `CUDA_VISIBLE_DEVICES` environment variable to control which GPUs are visible to OpenRL.
 - **Logging**: Use the `log_info()` method to log GPU information for debugging and monitoring purposes.
