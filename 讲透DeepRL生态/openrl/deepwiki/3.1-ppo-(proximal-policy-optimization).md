  This page describes the Proximal Policy Optimization (PPO) implementation in OpenRL. PPO is an on-policy reinforcement learning algorithm that uses a clipped surrogate objective to prevent excessively large policy updates, making it more stable and sample-efficient than many other policy gradient methods.

 
## Overview of PPO in OpenRL

 PPO in OpenRL is implemented as a modular system with several key components that work together to provide a complete algorithm implementation. The framework follows an agent-based design where a `PPOAgent` coordinates the training process using a neural network model (`PPONet`) and an on-policy driver for experience collection.

## Key Components

 
### PPOAgent

 The `PPOAgent` class serves as the main interface for users. It initializes and coordinates the training process, and provides methods for action selection during evaluation.

 Key responsibilities:

 
 - Setting up the training environment
 - Initializing algorithm components (network, buffer, trainer)
 - Managing the training loop
 - Providing inference capabilities (`act` method)
 
 
### PPONet

 The `PPONet` class manages the neural network architecture for PPO. It provides methods for:

 
 - Processing observations and selecting actions
 - Managing recurrent state (if using recurrent networks)
 - Initializing and resetting network states
 
 
### OnPolicyDriver

 The `OnPolicyDriver` handles the training loop for PPO, coordinating:

 
 - Experience collection through environment interaction
 - Computing returns and advantages
 - Updating the policy and value networks

### Experience Collection

 The experience collection process begins in `OnPolicyDriver.actor_rollout()`, which:

 
 - Collects state observations from the environment
 - Gets actions from the policy network
 - Executes actions in the environment
 - Stores transitions (observations, actions, rewards, etc.) in the buffer
 
 Key code paths:

 
 - Action selection: `OnPolicyDriver.act()` [openrl/drivers/onpolicy_driver.py235-279](https://github.com/OpenRL-Lab/openrl/blob/4c92aa44/openrl/drivers/onpolicy_driver.py#L235-L279)
 - Experience storage: `OnPolicyDriver.add2buffer()` [openrl/drivers/onpolicy_driver.py80-152](https://github.com/OpenRL-Lab/openrl/blob/4c92aa44/openrl/drivers/onpolicy_driver.py#L80-L152)
 
 
### Advantage Computation

 After collecting a batch of experiences, the driver computes returns and advantages in `OnPolicyDriver.compute_returns()`:

 
 - Uses Generalized Advantage Estimation (GAE) when enabled
 - Bootstraps from the value function to estimate returns
 - Computes advantages to guide policy updates
 
 
### PPO Update

 The PPO update involves multiple optimization epochs on the collected data:

 
 - Computing the ratio between new and old policy probabilities
 - Clipping the ratio to prevent excessive updates (based on clip_param)
 - Computing policy loss, value loss, and entropy bonus
 - Updating networks via gradient descent
 
 
## Configuration Parameters

 PPO in OpenRL has numerous configurable parameters:

 
| Parameter | Description | Default | Config Path |
|---|---|---|---|
| ppo_epoch | Number of optimization epochs per batch | 10 | cfg.ppo_epoch |
| clip_param | PPO clipping parameter | 0.2 | cfg.clip_param |
| value_loss_coef | Value function loss weight | 0.5 | cfg.value_loss_coef |
| entropy_coef | Entropy bonus coefficient | 0.01 | cfg.entropy_coef |
| lr | Learning rate | 5e-4 | cfg.lr |
| gamma | Discount factor | 0.99 | cfg.gamma |
| gae_lambda | GAE lambda parameter | 0.95 | cfg.gae_lambda |
| use_gae | Whether to use GAE | True | cfg.use_gae |
| max_grad_norm | Gradient clipping threshold | 10 | cfg.max_grad_norm |
| num_mini_batch | Number of mini-batches | 1 | cfg.num_mini_batch |
| use_valuenorm | Normalize value function | True | cfg.use_valuenorm |
| use_adv_normalize | Normalize advantages | False | cfg.use_adv_normalize |
