  This page documents the environment registration system in OpenRL, which is responsible for creating and configuring reinforcement learning environments. The system provides a unified interface for working with various environment types (Gymnasium, PettingZoo, MPE, NLP, etc.) through a centralized factory function.

 For information about creating custom environments, see [Custom Environments](https://deepwiki.com/OpenRL-Lab/openrl/2.3-custom-environments). For details on vectorized environments, see [Vectorized Environments](https://deepwiki.com/OpenRL-Lab/openrl/2.2-vectorized-environments).

 
## Overview of Environment Registration

 OpenRL's environment registration system allows users to create environments using a simple, consistent API regardless of the underlying environment implementation. The system is built around the `make` function, which serves as a central factory method that:

 
 - Identifies the environment type based on the provided ID
 - Creates the appropriate environment(s)
 - Vectorizes the environments for parallel execution
 - Applies wrappers to customize behavior

## Environment Type Determination

 The `make` function determines the type of environment to create based on the `id` parameter using a series of conditionals:

 
 - If `make_custom_envs` is provided, it uses that function to create environments
 - Otherwise, it checks the `id` against various environment registries: 
 - PyBullet drones environments (starting with "pybullet_drones/")
 - Snake environments (starting with "snakes_")
 - Old Gymnasium environments (starting with "GymV21Environment-v0:" or "GymV26Environment-v0:")
 - Standard Gymnasium environments (registered in `gym.envs.registry`)
 - MPE environments (listed in `openrl.envs.mpe_all_envs`)
 - NLP environments (listed in `openrl.envs.nlp_all_envs`)
 - Toy environments (listed in `openrl.envs.toy_all_envs`)
 - Super Mario environments (starting with a prefix in `openrl.envs.super_mario_all_envs`)
 - Connect environments (listed in `openrl.envs.connect_all_envs`)
 - Gridworld environments (listed in `openrl.envs.gridworld_all_envs`)
 - Offline environments (listed in `openrl.envs.offline_all_envs`)
 - Crafter environments (starting with "Crafter")
 - PettingZoo environments (listed in `openrl.envs.pettingzoo_all_envs` or `pettingzoo_env_dict`)
 
 The system then calls the appropriate environment-specific maker function (e.g., `make_gym_envs`, `make_PettingZoo_envs`, etc.).

## Supported Environment Types

 OpenRL supports a wide range of environment types, including:

 
| Environment Category | Identifier Format | Examples |
|---|---|---|
| Gymnasium | Standard Gym ID | "CartPole-v1", "MountainCar-v0" |
| PettingZoo | PettingZoo ID | "tictactoe_v3", "snakes_1v1" |
| MPE | MPE name | "simple_spread" |
| NLP | NLP name | "daily_dialog", "fake_dialog_data" |
| Super Mario | Prefix + ID | "SuperMarioBros-v0" |

| Toy | Toy name | "BitFlippingEnv", "IdentityEnv" |
| Gridworld | Gridworld name | "GridWorldEnv", "GridWorldEnvRandomGoal" |
