  Drivers in OpenRL are core components that orchestrate the training process by handling environment interactions, data collection, and coordinating between agents, buffers, and algorithms. They manage the training loop and ensure data flows correctly between different parts of the system.

 For information about the callback system that hooks into the training process, see [Callback System](https://deepwiki.com/OpenRL-Lab/openrl/4.1-callback-system). For information about how experience data is stored, see [Replay Buffers](https://deepwiki.com/OpenRL-Lab/openrl/4.2-replay-buffers).

### RLDriver Base Class

 The `RLDriver` is an abstract base class that defines the common interface and functionality for all drivers. It handles:

 
 - Setting up the training environment
 - Managing the training loop
 - Coordinating interactions between agents, buffers, and algorithms
 
 Key methods that must be implemented by subclasses include:

 
 - `_inner_loop()`: Core training loop implementation
 - `add2buffer()`: Adding collected data to the replay buffer
 - `actor_rollout()`: Collecting environment data through agent interactions
 - `compute_returns()`: Computing returns for learning
 - `act()`: Getting actions from the agent for environment steps
 
 Sources: [openrl/drivers/rl_driver.py27-180](https://github.com/OpenRL-Lab/openrl/blob/4c92aa44/openrl/drivers/rl_driver.py#L27-L180)

 
## Driver Types

 OpenRL provides two specialized driver implementations for different reinforcement learning paradigms:

 
### On-Policy Driver

 The `OnPolicyDriver` implements the driver logic for on-policy algorithms like PPO (Proximal Policy Optimization). On-policy methods learn from recently collected data and then discard it.

 Key characteristics:

 
 - Collects trajectories using the current policy
 - Computes returns using value function estimations
 - Updates the policy using collected data
 - Discards data after the update
 
 Sources: [openrl/drivers/onpolicy_driver.py31-279](https://github.com/OpenRL-Lab/openrl/blob/4c92aa44/openrl/drivers/onpolicy_driver.py#L31-L279)

 
### Off-Policy Driver

 The `OffPolicyDriver` implements driver logic for off-policy algorithms like DQN (Deep Q-Network) and VDN (Value Decomposition Network). Off-policy methods can learn from data collected by any policy.

 Key characteristics:

 
 - Supports experience replay for data efficiency
 - Often uses ε-greedy exploration strategy
 - Can update multiple times from stored experiences
 - Maintains target networks for stability
 
 Sources: [openrl/drivers/offpolicy_driver.py31-287](https://github.com/OpenRL-Lab/openrl/blob/4c92aa44/openrl/drivers/offpolicy_driver.py#L31-L287)

 The `actor_rollout()` method handles environment interaction, which differs between on-policy and off-policy drivers.

 For on-policy methods like PPO, the driver:

 - Collects observations, rewards, and other data

## Summary

 Drivers are a central component in OpenRL's training pipeline, responsible for:

 
 - Orchestrating the training process
 - Handling environment interactions
 - Collecting experience data
 - Managing data flow between agents, environments, buffers, and algorithms
 - Implementing exploration strategies
 - Computing returns for learning
 
 The two main driver implementations, `OnPolicyDriver` and `OffPolicyDriver`, are tailored to the specific requirements of on-policy and off-policy algorithms respectively, ensuring efficient training for different reinforcement learning paradigms.
