## Core Policy Types

 
### MLP Policies

 Multi-Layer Perceptron policies use fully connected layers for feature extraction from flat observation spaces.

 
| Policy Class | Feature Extraction | Layer Normalization | Use Case |
|---|---|---|---|
| MlpPolicy | MLP | No | Standard vector observations |
| MlpLstmPolicy | MLP + LSTM | No | Sequential vector observations |
| MlpLnLstmPolicy | MLP + LSTM | Yes | Sequential observations with normalization |

 **Default Architecture:** Two hidden layers with 64 units each, using `tanh` activation.

 **Sources:** [stable_baselines/common/policies.py645-661](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/common/policies.py#L645-L661) [stable_baselines/common/policies.py664-681](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/common/policies.py#L664-L681) [stable_baselines/common/policies.py684-701](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/common/policies.py#L684-L701)

 
### CNN Policies

 Convolutional Neural Network policies use the Nature CNN architecture for image-based observations.

 
| Policy Class | Feature Extraction | Layer Normalization | Use Case |
|---|---|---|---|
| CnnPolicy | Nature CNN | No | Image observations (Atari, etc.) |
| CnnLstmPolicy | Nature CNN + LSTM | No | Sequential image observations |
| CnnLnLstmPolicy | Nature CNN + LSTM | Yes | Sequential images with normalization |

 **Nature CNN Architecture:**

 
 - Conv Layer 1: 32 filters, 8x8 kernel, stride 4
 - Conv Layer 2: 64 filters, 4x4 kernel, stride 2
 - Conv Layer 3: 64 filters, 3x3 kernel, stride 1
 - Fully Connected: 512 units
 
 **Sources:** [stable_baselines/common/policies.py586-602](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/common/policies.py#L586-L602) [stable_baselines/common/policies.py16-29](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/common/policies.py#L16-L29) [stable_baselines/common/policies.py605-622](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/common/policies.py#L605-L622) [stable_baselines/common/policies.py625-642](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/common/policies.py#L625-L642)

 
### LSTM Policies

 LSTM policies add recurrent connections to handle partial observability and temporal dependencies.

 **Key Features:**

 
 - **State Shape:** `(2 * n_lstm,)` for cell and hidden states
 - **Default LSTM Units:** 256
 - **Sequence Processing:** Batch-to-sequence conversion for training
 - **Layer Normalization:** Optional layer normalization within LSTM cells

### DQN Policies

 DQN policies output Q-values for discrete action selection:

 **Features:**

 
 - **Dueling Architecture:** Optional separate value and advantage streams
 - **Action Selection:** Argmax for deterministic, softmax sampling for stochastic
 - **Action Space:** `gym.spaces.Discrete` only
 
 **Dueling Architecture:**

 
```
Q(s,a) = V(s) + A(s,a) - mean(A(s,·))
```

## Policy Interface Methods

 All policies implement these core methods:

 
| Method | Purpose | Returns |
|---|---|---|
| step(obs, state, mask, deterministic) | Single step action selection | actions, values, states, neglogp |
| proba_step(obs, state, mask) | Action probabilities | probability distributions |
| value(obs, state, mask) | Value function evaluation | state values |

 **Recurrent Policy Extensions:**

 
 - `initial_state`: Property returning initial hidden states
 - `states_ph`: Placeholder for LSTM hidden states
 - `dones_ph`: Placeholder for episode termination masks
