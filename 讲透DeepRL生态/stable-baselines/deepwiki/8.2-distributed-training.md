  This page covers multi-process training strategies, MPI usage, and performance optimization techniques in stable-baselines. The library implements two primary approaches for distributed reinforcement learning: MPI-based distribution for algorithms like PPO1 and TRPO, and vectorized environment parallelization for algorithms like PPO2, A2C, and ACER.

 For information about environment vectorization details, see [Environment Management](https://deepwiki.com/hill-a/stable-baselines/5-environment-management). For algorithm-specific implementations, see [Core Algorithms](https://deepwiki.com/hill-a/stable-baselines/3-core-algorithms).

## MPI-Based Distribution

 
### Architecture and Communication Patterns

 MPI-based algorithms use the Message Passing Interface for inter-process communication and synchronization. This approach distributes complete RL workers across multiple processes.

 
```

```

 
### MPI Implementation Details

 The MPI-based algorithms implement several key communication patterns:

 **Worker Initialization and Rank Assignment:**

 
 - Each process gets a unique rank via `MPI.COMM_WORLD.Get_rank()`
 - Total worker count obtained via `MPI.COMM_WORLD.Get_size()`
 - Rank 0 typically handles logging and coordination
 
 **Gradient Synchronization:**

 
 - Gradients are averaged across all workers using `MPI.COMM_WORLD.Allreduce`
 - The `allmean` function implements distributed averaging
 - Parameter updates are synchronized before each training step
 
 **Experience Aggregation:**

 
 - Episode statistics are gathered using `MPI.COMM_WORLD.allgather`
 - Trajectory segments are collected independently per worker
 - Final statistics combine results from all processes

## Vectorized Environment Distribution

 
### VecEnv Architecture

 Vectorized environment algorithms achieve parallelization through the `VecEnv` interface, which batches multiple environment instances for efficient processing.

 
```

```

 
### Batch Size Calculations

 The vectorized approach uses batch sizes calculated as `n_envs * n_steps`:

 **PPO2 Configuration:**

 
 - `self.n_batch = self.n_envs * self.n_steps`
 - Minibatch size: `self.n_batch // self.nminibatches`
 - Training iterations scale with batch size
 
 **A2C Configuration:**

 
 - `self.n_batch = self.n_envs * self.n_steps`
 - Direct batch processing without minibatching
 - Simpler synchronous updates

|---|---|---|---|

### Best Practices

 **For MPI-based algorithms (PPO1, TRPO):**

 
 - Set `n_cpu_tf_sess=1` for deterministic results
 - Use `mpirun -np N` to control worker count
 - Ensure OpenMPI is properly installed
 - Monitor rank 0 for training logs
 
 **For vectorized algorithms (PPO2, A2C, ACER):**

 
 - Use `SubprocVecEnv` for CPU-bound environments
 - Use `DummyVecEnv` for simple environments
 - Adjust `n_envs` based on available CPU cores
 - Balance `n_envs` and `n_steps` for optimal batch sizes
 
 **General optimization:**

 
 - Tune `n_cpu_tf_sess` based on hardware
 - Profile memory usage with experience replay
 - Consider GPU utilization for PPO2
 - Monitor CPU utilization across all cores
