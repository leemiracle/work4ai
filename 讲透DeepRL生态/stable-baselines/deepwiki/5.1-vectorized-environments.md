  This page covers the vectorized environment system in stable-baselines, which allows running multiple environment instances in parallel to improve training efficiency. The system provides both single-process and multi-process implementations for different use cases.

 For information about creating custom environments that work with vectorized environments, see [Custom Environments](https://deepwiki.com/hill-a/stable-baselines/5.2-custom-environments). For environment wrappers that work with vectorized environments, see [Environment Wrappers](https://deepwiki.com/hill-a/stable-baselines/5.3-environment-wrappers).

 
## Overview

 Vectorized environments enable training reinforcement learning agents on multiple environment instances simultaneously. Instead of processing one environment step at a time, vectorized environments process `n` environments per step, where actions, observations, rewards, and done signals are all batched as vectors or arrays.

## VecEnv Base Class

 The `VecEnv` abstract base class defines the interface for all vectorized environments. It implements an asynchronous step pattern where environment steps can be initiated and results collected separately.

 
### Core Interface

 
| Method | Purpose | Parameters | Returns |
|---|---|---|---|
| step_async(actions) | Initiate environment steps | actions: Array of actions for each env | None |
| step_wait() | Wait for and collect step results | None | (obs, rewards, dones, infos) |
| reset() | Reset all environments | None | obs array |
| close() | Clean up resources | None | None |

## DummyVecEnv Implementation

 `DummyVecEnv` provides single-process vectorization by sequentially calling each environment on the current Python process. This implementation is suitable for computationally simple environments where multiprocessing overhead would outweigh benefits.

### Key Implementation Details

 The `DummyVecEnv` maintains pre-allocated buffers for observations, rewards, and done flags:

 
 - `buf_obs`: OrderedDict of observation arrays
 - `buf_rews`: Reward array
 - `buf_dones`: Done flags array
 - `buf_infos`: Info dictionaries list
 
 When `step_wait()` is called, it iterates through all environments sequentially, executing each step and storing results in the buffers.

## SubprocVecEnv Implementation

 `SubprocVecEnv` provides true parallel processing by running each environment in a separate subprocess. This implementation is beneficial for computationally intensive environments.

### Worker Communication Protocol

 Each worker process runs the `_worker()` function which listens for commands:

 
| Command | Purpose | Data | Response |
|---|---|---|---|
| 'step' | Execute environment step | action | (obs, reward, done, info) |
| 'reset' | Reset environment | None | observation |
| 'seed' | Set random seed | seed | Seed result |
| 'render' | Render environment | mode | Rendered output |
| 'get_spaces' | Get observation/action spaces | None | (obs_space, action_space) |
| 'env_method' | Call environment method | (method_name, args, kwargs) | Method result |
| 'get_attr' | Get environment attribute | attr_name | Attribute value |
| 'set_attr' | Set environment attribute | (attr_name, value) | None |

 Sources: [stable_baselines/common/vec_env/subproc_vec_env.py12-49](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/common/vec_env/subproc_vec_env.py#L12-L49)

 
### Process Start Methods

 `SubprocVecEnv` supports different multiprocessing start methods:

 
 - **`'forkserver'`**: Thread-safe, recommended for TensorFlow/GPU usage
 - **`'spawn'`**: Thread-safe, works on all platforms, requires `if __name__ == "__main__"`
 - **`'fork'`**: Default on Linux, not thread-safe, may cause deadlocks
 
 The implementation automatically selects `'forkserver'` if available, otherwise `'spawn'`.

## Observation Space Handling

 Both vectorized environment implementations handle complex observation spaces through the `_flatten_obs()` function, which processes observations based on space type:

 
### Observation Space Types

 
| Space Type | Handling | Output Format |
|---|---|---|
| gym.spaces.Dict | Stack each key's observations | OrderedDict with stacked arrays |
| gym.spaces.Tuple | Stack each tuple element | tuple of stacked arrays |
| Simple spaces | Direct stacking | Single stacked array |

## VecEnvWrapper Base Class

 The `VecEnvWrapper` class provides a base for creating environment wrappers that work with vectorized environments. It implements the full `VecEnv` interface by delegating to the wrapped environment.

 
### Wrapper Features

 
 - **Attribute forwarding**: Automatically forwards attribute access to wrapped environment
 - **Recursive attribute lookup**: Supports nested wrapper chains
 - **Attribute shadowing detection**: Prevents ambiguous attribute access in complex wrapper hierarchies

## Usage Patterns

 
### Basic Usage Comparison

 
| Scenario | Recommended Implementation | Reason |
|---|---|---|
| Simple environments (CartPole, etc.) | DummyVecEnv | Low computational cost, no multiprocessing overhead |
| Complex environments (Atari, robotics) | SubprocVecEnv | High computational cost benefits from parallelization |
| Environments with external dependencies | SubprocVecEnv | Process isolation prevents interference |
| Debugging/development | DummyVecEnv | Easier to debug, no multiprocessing complexity |
