  This document covers the creation and registration of custom neural network policies in stable-baselines. Custom policies allow users to define specialized architectures beyond the built-in `MlpPolicy`, `CnnPolicy`, and `LstmPolicy` options.

 For information about using the built-in policy types, see [Built-in Policies](https://deepwiki.com/hill-a/stable-baselines/4.1-built-in-policies). For environment-specific considerations, see [Environment Management](https://deepwiki.com/hill-a/stable-baselines/5-environment-management).

### Method 2: Policy Architecture Specification

 
#### Network Architecture Format

 The `net_arch` parameter uses a specific format for on-policy algorithms:

 
| Format | Description | Example |
|---|---|---|
| [int, int, ...] | Shared layers only | [64, 64] |
| [int, dict(pi=[...], vf=[...])] | Shared + separate layers | [128, dict(pi=[64], vf=[64, 64])] |
| [dict(pi=[...], vf=[...])] | Separate layers only | [dict(pi=[128, 128], vf=[64])] |

## Policy Integration with Algorithms

 
### Algorithm-Policy Compatibility

 Different algorithms support different policy types:

 
| Algorithm | Supported Base Classes | Notes |
|---|---|---|
| PPO2, A2C, TRPO | ActorCriticPolicy, FeedForwardPolicy, LstmPolicy | Standard on-policy |
| DQN | DQNPolicy | Q-learning specific |
| DDPG | DDPGPolicy | Actor-critic with continuous actions |
| SAC | SAC-specific policies | Maximum entropy |

 **Sources:** [docs/modules/dqn.rst14-18](https://github.com/hill-a/stable-baselines/blob/45beb246/docs/modules/dqn.rst#L14-L18) [docs/modules/ddpg.rst15-18](https://github.com/hill-a/stable-baselines/blob/45beb246/docs/modules/ddpg.rst#L15-L18) [docs/modules/sac.rst15-18](https://github.com/hill-a/stable-baselines/blob/45beb246/docs/modules/sac.rst#L15-L18)

### Policy Validation and Error Handling

 The policy system includes validation for:

 
 - **Inheritance validation**: Policies must inherit from correct base classes
 - **Parameter validation**: Using `_kwargs_check()` to validate feature extraction parameters
 - **Name conflicts**: `register_policy()` prevents overwriting existing names
 - **Loading validation**: Ensures loaded policies match expected signatures
