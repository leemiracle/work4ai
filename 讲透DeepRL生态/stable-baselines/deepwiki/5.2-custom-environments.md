For environment wrappers and transformations, see [Environment Wrappers](https://deepwiki.com/hill-a/stable-baselines/5.3-environment-wrappers).

 
## Environment Interface Requirements

 Custom environments in stable-baselines must follow the OpenAI Gym interface by inheriting from `gym.Env` and implementing specific required methods. This ensures compatibility with all reinforcement learning algorithms in the library.

### Required Attributes and Methods

 Every custom environment must define:

 
 - **`action_space`**: A `gym.spaces` object that defines the format and constraints of valid actions
 - **`observation_space`**: A `gym.spaces` object that defines the format and constraints of observations
 - **`step(action)`**: Execute an action and return `(observation, reward, done, info)` tuple
 - **`reset()`**: Reset the environment to initial state and return the initial observation
 - **`render(mode='human')`**: Optionally visualize the current environment state
 - **`close()`**: Clean up any resources when the environment is destroyed

## Space Definitions

 
### Action and Observation Spaces

 Stable-baselines supports various space types through the `gym.spaces` module:

 
| Space Type | Use Case | Example |
|---|---|---|
| Discrete(n) | Discrete actions (0 to n-1) | Game moves, button presses |
| Box(low, high, shape) | Continuous actions/observations | Motor controls, sensor readings |
| MultiDiscrete([n1, n2, ...]) | Multiple discrete choices | Multi-agent discrete actions |
| MultiBinary(n) | Binary choices | On/off switches, boolean features |

### Image Input Considerations

 For environments using images as observations, special requirements apply:

 
 - Input values must be in range [0, 255] as observations are normalized by dividing by 255
 - Use `dtype=np.uint8` for image observations
 - Minimum resolution of 36x36 pixels for default CNN policies
 - Shape should be `(HEIGHT, WIDTH, N_CHANNELS)`
 
 The environment checker validates these requirements and issues warnings for non-compliant image inputs.

### Validation Categories

 The checker performs several types of validation:

 
 - **Required Interface Compliance**: Ensures the environment has required methods and attributes
 - **Return Value Validation**: Verifies `step()` returns 4 values and `reset()` returns only observation
 - **Space Compatibility**: Checks that returned observations and accepted actions match declared spaces
 - **Stable-Baselines Compatibility**: Issues warnings for features not fully supported by the library
 
 
### Common Validation Failures

 The test suite demonstrates common failure patterns that the checker catches:

 
 - **Wrong observation shape**: Returning observations that don't match `observation_space`
 - **Incorrect return format**: `step()` not returning exactly 4 values `(obs, reward, done, info)`
 - **Type mismatches**: Reward not being float/int, done not being boolean, info not being dict
 - **Space violations**: Observations or actions outside declared space bounds

## Best Practices and Tips

 
### Observation and Action Space Normalization

 Key recommendations for robust custom environments:

 
| Aspect | Recommendation | Rationale |
|---|---|---|
| Observation Space | Normalize to known bounds when possible | Helps neural network training stability |
| Action Space | Use symmetric range [-1, 1] for continuous actions | Most RL algorithms assume Gaussian action distribution centered at 0 |
| Reward Design | Start with shaped rewards | Provides learning signal to guide agent behavior |
| Environment Complexity | Begin with simplified versions | Easier to debug and validate before adding complexity |

 
### Common Pitfalls

 The documentation highlights several important considerations:

 
 - **Action Space Symmetry**: Algorithms like PPO2 and SAC assume Gaussian action distributions. Asymmetric action spaces can harm learning
 - **Image Input Format**: CNN policies expect images in [0, 255] range with specific dtype requirements
 - **Space Validation**: Use `check_env()` early and often during development to catch interface violations
 
 **Sources:** [docs/guide/rl_tips.rst172-221](https://github.com/hill-a/stable-baselines/blob/45beb246/docs/guide/rl_tips.rst#L172-L221)
