## Purpose and Scope

 This document covers the off-policy reinforcement learning algorithms implemented in stable-baselines. Off-policy algorithms learn from experiences stored in replay buffers, allowing them to reuse past experiences and learn from data generated by different policies. The covered algorithms include DQN, DDPG, SAC, and TD3.

 For information about on-policy algorithms that learn directly from current policy experiences, see [On-Policy Algorithms](https://deepwiki.com/hill-a/stable-baselines/3.1-on-policy-algorithms). For advanced extensions like HER and GAIL, see [Advanced Extensions](https://deepwiki.com/hill-a/stable-baselines/3.3-advanced-extensions).

## Algorithm Implementations

 
### DQN (Deep Q-Network)

 `DQN` handles discrete action spaces using Q-value estimation with experience replay and target networks.

 
| Feature | Implementation |
|---|---|
| Action Space | Discrete only |
| Network Architecture | Q-function approximator |
| Extensions | Double-Q, Dueling, Prioritized Replay |
| Policy Class | DQNPolicy |

 Key components:

 
 - `build_train()` function constructs the training graph [stable_baselines/deepq/build_graph.py](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/deepq/build_graph.py)
 - `act()` function for action selection with epsilon-greedy exploration
 - `update_target()` for periodic target network updates

### SAC (Soft Actor-Critic)

 `SAC` implements maximum entropy reinforcement learning with stochastic policies and automatic entropy tuning.

 
| Component | Purpose | Implementation |
|---|---|---|
| Actor | Stochastic policy with entropy regularization | policy_tf.make_actor() |
| Critic | Twin Q-functions (QF1, QF2) | policy_tf.make_critics() |
| Value Function | State value estimation | policy_tf.make_critics() |
| Entropy Coefficient | Automatic tuning of exploration | log_ent_coef variable |

 Key features:

 
 - Entropy regularization: `policy_loss = ent_coef * logp_pi - qf1_pi`
 - Twin Q-functions to reduce overestimation bias
 - Soft target updates with `tau` parameter

## Common Training Patterns

 
### Experience Collection and Storage

 All off-policy algorithms follow a similar pattern for collecting and storing experiences:

 
 - **Environment Interaction**: Execute action in environment
 - **Experience Storage**: Store `(obs, action, reward, next_obs, done)` tuple
 - **Replay Sampling**: Sample batch from replay buffer
 - **Network Updates**: Update networks using sampled batch

### Target Network Updates

 Off-policy algorithms use target networks for stable learning:

 
| Algorithm | Update Method | Update Frequency |
|---|---|---|
| DQN | Hard copy | Every target_network_update_freq steps |
| DDPG | Soft update (Polyak) | Every training step |
| SAC | Soft update (Polyak) | Every target_update_interval steps |
| TD3 | Soft update (Polyak) | Every policy_delay steps |

 Target update implementations use `get_target_updates()` for soft updates or direct assignment for hard updates.

### Policy-Specific Features

 Each algorithm implements unique policy mechanisms:

 
 - **DQN**: Epsilon-greedy exploration with linear schedule
 - **DDPG**: Action noise (Ornstein-Uhlenbeck, Normal) and parameter noise
 - **SAC**: Entropy regularization with automatic tuning
 - **TD3**: Target policy smoothing and delayed policy updates
 
 The learning process integrates these features through algorithm-specific `learn()` methods that handle the training loop, logging, and callback integration.
