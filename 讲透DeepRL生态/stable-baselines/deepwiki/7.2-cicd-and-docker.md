## CI/CD Pipeline Overview

 The stable-baselines project uses Travis CI for continuous integration, with a multi-stage pipeline that runs tests, documentation builds, and code quality checks in parallel Docker containers.

 
### Travis CI Configuration

 The CI pipeline is defined in `.travis.yml` and uses a Docker-based testing strategy with the following key characteristics:

 
 - **Base Environment**: Python 3.5 with Docker service enabled
 - **Docker Image**: `stablebaselines/stable-baselines-cpu:v2.10.0` for all CI jobs
 - **Parallel Execution**: Tests are split into multiple parallel jobs to reduce wall-clock time and prevent out-of-memory errors
 
 The pipeline includes these stages:

 
| Stage | Job Name | Purpose | Test Glob Pattern |
|---|---|---|---|
| Test | Unit Tests a-h | First test batch | [a-h]* |
| Test | Unit Tests i-l | Second test batch | [i-l]* |
| Test | Unit Tests m-sa | Third test batch | {[m-r]*,sa*} |
| Test | Unit Tests sb-z | Fourth test batch | {s[b-z]*,[t-z]*} |
| Test | Unit Tests determinism | Determinism tests | 0deterministic.py |
| Test | Sphinx Documentation | Documentation build | N/A |
| Test | Type Checking | Static type analysis | N/A |
| Codacy Trigger | Coverage Analysis | Code coverage report | N/A |

 - `python3-dev` - Python development headers

 - `default-jre` - Java runtime for Codacy coverage reporter
 - Various system libraries for GUI support
 
 **Python Environment**:

 
 - Virtual environment at `/root/venv`
 - stable-baselines installed in development mode with `[mpi,tests,docs]` extras
 - All testing and documentation dependencies
 
 **Additional Tools**:

 
 - Codacy coverage reporter JAR for code coverage analysis

## Testing Integration

 
### Docker-Based Testing

 The testing infrastructure uses Docker containers to ensure consistent test environments across different systems. Two shell scripts provide convenient interfaces for running tests:

 **GPU Testing** (`run_docker_gpu.sh`):

 
 - Detects nvidia-docker version (legacy vs. modern)
 - Uses `--runtime=nvidia` for older nvidia-docker2
 - Uses `--gpus all` for newer Docker with NVIDIA Container Toolkit
 - Mounts source code and executes test commands
 
 **CPU Testing** (`run_docker_cpu.sh`):

 
 - Uses standard Docker runtime
 - Same mounting and execution pattern as GPU version

### Integration with CI

 The Docker images used in CI are pre-built and hosted on Docker Hub. The CI pipeline:

 
 - Pulls the appropriate image (`stablebaselines/stable-baselines-cpu:v2.10.0`)
 - Mounts the source code into the container
 - Executes test commands within the containerized environment
 - Collects and reports coverage data
 
 This approach ensures that:

 
 - Tests run in identical environments locally and in CI
 - Dependencies are pre-installed and cached
 - Different Python/system configurations don't cause test failures
 - GPU and CPU testing can use appropriate base images
