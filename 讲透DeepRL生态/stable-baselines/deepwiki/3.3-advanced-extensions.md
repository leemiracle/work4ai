  This document covers specialized reinforcement learning algorithms that extend the core on-policy and off-policy methods with advanced techniques. These extensions address specific problem domains: imitation learning from expert demonstrations and goal-conditioned reinforcement learning.

 For information about basic RL algorithms, see [On-Policy Algorithms](https://deepwiki.com/hill-a/stable-baselines/3.1-on-policy-algorithms) and [Off-Policy Algorithms](https://deepwiki.com/hill-a/stable-baselines/3.2-off-policy-algorithms). For policy network architectures used with these extensions, see [Policy Networks](https://deepwiki.com/hill-a/stable-baselines/4-policy-networks).

 
## Overview

 Advanced extensions in stable-baselines implement meta-learning approaches that augment standard RL algorithms:

 
 - **GAIL (Generative Adversarial Imitation Learning)**: Learns policies from expert demonstrations using adversarial training
 - **HER (Hindsight Experience Replay)**: Enables learning in sparse-reward, goal-conditioned environments by relabeling experiences
 
 These extensions wrap or modify base algorithms rather than implementing entirely new learning paradigms.

## GAIL (Generative Adversarial Imitation Learning)

 
### Architecture and Design

 GAIL implements imitation learning by training a discriminator to distinguish between expert and agent trajectories, while the policy generator learns to fool the discriminator. The implementation extends TRPO as the base policy optimization algorithm.

 
#### GAIL System Architecture

 
```

```

 The `GAIL` class inherits from `TRPO` and adds adversarial training components. Key parameters control the training balance between generator and discriminator:

 
 - `g_step`: Number of policy optimization steps per training iteration
 - `d_step`: Number of discriminator training steps per training iteration
 - `hidden_size_adversary`: Architecture of the discriminator network
 - `adversary_entcoeff`: Entropy coefficient for adversarial loss

### Expert Dataset Management

 The `ExpertDataset` class handles loading and preprocessing expert demonstrations stored in `.npz` format. It supports both file-based and memory-based loading with trajectory limitation and train/validation splitting.

 
#### Expert Data Structure

 
| Key | Description | Shape |
|---|---|---|
| obs | Observations | (N*L, observation_dim) |
| actions | Actions taken | (N*L, action_dim) |
| rewards | Rewards received | (N*L,) |
| episode_returns | Total episode returns | (N_episodes,) |
| episode_starts | Episode boundary markers | (N*L,) |

 Where `N` is the number of episodes and `L` is the average episode length.

 The dataset supports image-based observations by storing image file paths and using the `DataLoader` class for on-demand loading and preprocessing.

## HER (Hindsight Experience Replay)

 
### Architecture and Design

 HER addresses sparse reward problems in goal-conditioned environments by relabeling failed experiences with alternative goals that were actually achieved. It wraps existing off-policy algorithms rather than implementing a new learning algorithm.

 
#### HER System Architecture

 
```

```

 The `HER` class acts as a meta-algorithm that:

 
 - Wraps any `OffPolicyRLModel` implementation
 - Adds hindsight experience replay to the training process
 - Handles goal-conditioned observation spaces
 - Manages replay buffer modifications
 
 Sources: [stable_baselines/her/her.py11-55](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/her/her.py#L11-L55)

 
### Goal-Conditioned Environment Handling

 HER requires environments with goal-conditioned observation spaces (typically `gym.GoalEnv` interface). The `HERGoalEnvWrapper` converts standard environments to the required format:

 
 - Observation space becomes a dictionary with `observation`, `desired_goal`, and `achieved_goal` keys
 - Reward computation uses goal-specific reward functions
 - Episode termination considers goal achievement
 
 The wrapper ensures compatibility with HER's experience relabeling mechanism.

 Sources: [stable_baselines/her/utils.py](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/her/utils.py) [stable_baselines/her/her.py56-73](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/her/her.py#L56-L73)

 
### Replay Buffer Integration

 The `HindsightExperienceReplayWrapper` modifies the standard replay buffer used by off-policy algorithms:

 
#### Goal Selection Strategies

 
| Strategy | Description | Implementation |
|---|---|---|
| future | Sample goals from future states in same episode | Default strategy, most effective |
| episode | Sample goals from any state in same episode | Alternative for exploration |
| random | Sample goals randomly from replay buffer | Baseline comparison |

 The `n_sampled_goal` parameter controls how many additional goal-relabeled transitions are added to the replay buffer for each original transition.

## Integration and Testing

 
### Test Coverage

 Both GAIL and HER have comprehensive test suites covering:

 
 - **Algorithm Integration**: Tests with multiple base algorithms
 - **Data Pipeline**: Expert dataset loading and trajectory generation
 - **Environment Compatibility**: Various observation and action spaces
 - **Serialization**: Save/load functionality with proper metadata handling
 
 The identity environment tests validate that algorithms can learn simple mappings, serving as smoke tests for the extensions.

 Sources: [tests/test_gail.py1-171](https://github.com/hill-a/stable-baselines/blob/45beb246/tests/test_gail.py#L1-L171) [tests/test_identity.py1-137](https://github.com/hill-a/stable-baselines/blob/45beb246/tests/test_identity.py#L1-L137)

 
### Performance Validation

 Test environments include:

 
 - **Continuous Control**: Pendulum-v0 for GAIL imitation learning
 - **Discrete Control**: CartPole-v1 for behavior cloning validation
 - **Visual Observations**: Atari environments for image-based learning
 - **Goal-Conditioned**: Custom environments for HER validation
 
 Each extension maintains compatibility with the broader stable-baselines ecosystem including vectorized environments, monitoring, and evaluation utilities.
