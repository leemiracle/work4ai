## On-Policy Algorithms

 On-policy algorithms learn from experience generated by the current policy. They typically use actors that collect trajectories and update both policy and value functions based on these trajectories.

 
### PPO2 (Proximal Policy Optimization)

 `PPO2` is the main GPU-optimized implementation of Proximal Policy Optimization, designed for vectorized environments.

 **Key Components:**

 
 - **Policy Network**: Produces both action probabilities and state values
 - **Clipped Surrogate Loss**: Prevents large policy updates via ratio clipping
 - **Generalized Advantage Estimation (GAE)**: Balances bias-variance in advantage computation

### A2C (Advantage Actor-Critic)

 `A2C` implements the synchronous version of A3C (Asynchronous Advantage Actor-Critic) using multiple parallel environments.

 **Key Features:**

 
 - **Actor-Critic Architecture**: Shared network producing policy and value outputs
 - **N-step Bootstrap**: Uses n-step returns for value updates
 - **Entropy Regularization**: Encourages exploration through policy entropy
 
 **Sources:** [stable_baselines/a2c/a2c.py33-69](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/a2c/a2c.py#L33-L69) [stable_baselines/a2c/a2c.py151-158](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/a2c/a2c.py#L151-L158)

 
### TRPO (Trust Region Policy Optimization)

 `TRPO` constrains policy updates using KL divergence to ensure stable learning.

 **Key Mechanisms:**

 
 - **Conjugate Gradient**: Efficiently solves trust region constraint
 - **Line Search**: Ensures constraint satisfaction and improvement
 - **Natural Policy Gradients**: Uses Fisher Information Matrix
 
 **Sources:** [stable_baselines/trpo_mpi/trpo_mpi.py23-49](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/trpo_mpi/trpo_mpi.py#L23-L49) [stable_baselines/trpo_mpi/trpo_mpi.py384-404](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/trpo_mpi/trpo_mpi.py#L384-L404)

| A2C | Direct gradients | Fast, lightweight | Simple environments |
| TRPO | Trust region | Theoretical guarantees | Continuous control |

## Off-Policy Algorithms

 Off-policy algorithms can learn from experience generated by different policies, typically using replay buffers to store and reuse past transitions.

 
### Deep Q-Network (DQN)

 `DQN` learns action-value functions for discrete action spaces using experience replay and target networks.

 **Core Components:**

 
 - **Experience Replay**: `ReplayBuffer` stores transitions for batch sampling
 - **Target Network**: Stabilizes learning with periodic updates
 - **Double-Q Learning**: Reduces overestimation bias (when `double_q=True`)

### DDPG (Deep Deterministic Policy Gradient)

 `DDPG` extends DQN to continuous action spaces using deterministic policies and critic networks.

 **Architecture:**

 
 - **Actor Network**: Deterministic policy μ(s)
 - **Critic Network**: Q-function Q(s,a)
 - **Target Networks**: Both actor and critic have target counterparts
 - **Ornstein-Uhlenbeck Noise**: Exploration in action space
 
 **Sources:** [stable_baselines/ddpg/ddpg.py141-198](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/ddpg/ddpg.py#L141-L198) [stable_baselines/ddpg/ddpg.py454-462](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/ddpg/ddpg.py#L454-L462)

 
### SAC (Soft Actor-Critic)

 `SAC` maximizes both reward and policy entropy for robust learning in continuous control.

 **Key Innovations:**

 
 - **Maximum Entropy Objective**: Balances reward and exploration
 - **Automatic Temperature Tuning**: Learns entropy coefficient α
 - **Twin Critics**: Uses two Q-functions to reduce overestimation
 
 **Sources:** [stable_baselines/sac/sac.py16-59](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/sac/sac.py#L16-L59) [stable_baselines/sac/sac.py213-248](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/sac/sac.py#L213-L248)

 
### TD3 (Twin Delayed DDPG)

 `TD3` improves upon DDPG with three key modifications for better performance.

 **Improvements over DDPG:**

 
 - **Twin Critics**: Two Q-functions, use minimum for updates
 - **Delayed Policy Updates**: Update policy less frequently than critics
 - **Target Policy Smoothing**: Add noise to target actions
 
 **Sources:** [stable_baselines/td3/td3.py16-57](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/td3/td3.py#L16-L57) [stable_baselines/td3/td3.py173-189](https://github.com/hill-a/stable-baselines/blob/45beb246/stable_baselines/td3/td3.py#L173-L189)

 
### Off-Policy Algorithm Comparison

 
| Algorithm | Action Space | Key Feature | Sample Efficiency |
|---|---|---|---|
| DQN | Discrete | Experience replay | Medium |
| DDPG | Continuous | Deterministic policy | Medium |
| SAC | Continuous | Maximum entropy | High |
| TD3 | Continuous | Improved stability | High |
