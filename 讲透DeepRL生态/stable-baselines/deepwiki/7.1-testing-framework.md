  This document describes the comprehensive testing framework used in stable-baselines to validate reinforcement learning algorithms, environments, and core functionality. The testing framework ensures algorithm correctness, model persistence, and environment compatibility through automated test suites using pytest.

 For information about the CI/CD pipeline and automated testing infrastructure, see [CI/CD and Docker](https://deepwiki.com/hill-a/stable-baselines/7.2-cicd-and-docker). For details about custom environment creation and validation, see [Custom Environments](https://deepwiki.com/hill-a/stable-baselines/5.2-custom-environments).

## Test Organization and Execution

 
### Test Markers and Categorization

 The testing framework uses pytest markers to categorize tests by execution time and resource requirements:

 
| Marker | Description | Usage |
|---|---|---|
| @pytest.mark.slow | Tests requiring longer execution time | Algorithm convergence tests |
| @pytest.mark.expensive | Resource-intensive tests | LSTM training validation |
| @pytest.mark.parametrize | Parameterized tests across algorithms/configurations | Cross-algorithm validation |

### Testing Utilities and Helpers

 The framework provides several utility functions for common testing operations:

 
 - `evaluate_policy()`: Evaluates trained models with specified reward thresholds
 - `DummyVecEnv`: Wrapper for single environments in vectorized interface
 - `Monitor`: Environment wrapper for episode statistics collection
 - `_assert_eq()`: Custom assertion helper for subprocess return codes
