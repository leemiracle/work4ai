  This glossary defines codebase-specific terms, jargon, and domain concepts used throughout the Ray project. It serves as a technical reference for onboarding engineers to navigate the implementation of Ray Core, Ray Data, Ray Serve, and other subsystems.

 
## Core System Components

 
### CoreWorker

 The `CoreWorker` is the primary process-level entity that manages task submission, execution, and object lifecycle. Every Ray driver and worker process contains a `CoreWorker` instance. It handles the interface between the language-specific frontend (Python, Java, C++) and the Ray backend (Raylet, GCS).

 
 - **Implementation**: `CoreWorker` is implemented in C++ [src/ray/core_worker/core_worker.cc15-16](https://github.com/ray-project/ray/blob/bf129559/src/ray/core_worker/core_worker.cc#L15-L16) and exposed to Python via Cython [python/ray/_raylet.pyx193-195](https://github.com/ray-project/ray/blob/bf129559/python/ray/_raylet.pyx#L193-L195)
 - **Key Components**: 
 - `TaskManager`: Manages state for tasks submitted by this worker [src/ray/core_worker/task_manager.cc](https://github.com/ray-project/ray/blob/bf129559/src/ray/core_worker/task_manager.cc)
 - `ReferenceCounter`: Tracks local and remote references to objects for distributed GC [src/ray/core_worker/core_worker.cc114-126](https://github.com/ray-project/ray/blob/bf129559/src/ray/core_worker/core_worker.cc#L114-L126)
 - `TaskCounter`: Maintains metrics for tasks by state (Running, In-Get, In-Wait) [src/ray/core_worker/core_worker.cc168-172](https://github.com/ray-project/ray/blob/bf129559/src/ray/core_worker/core_worker.cc#L168-L172)
 
 
### Raylet

 The `Raylet` is the node-manager process that runs on every node in a Ray cluster. It is responsible for resource management, local task scheduling, and managing the local object store (Plasma).

 
 - **Implementation**: The logic resides in the `NodeManager` class.
 - **Worker Pool**: Manages a pool of worker processes, including specialized workers like `SPILL_WORKER` and `RESTORE_WORKER` [python/ray/_raylet.pyx123-126](https://github.com/ray-project/ray/blob/bf129559/python/ray/_raylet.pyx#L123-L126)
 
 
### GCS (Global Control Service)

 The GCS is the cluster-wide metadata store and control plane. It manages cluster layout, resource usage, and actor registration.

 
 - **Client**: Workers interact with it via the `GcsClient` [python/ray/includes/gcs_client.pxi](https://github.com/ray-project/ray/blob/bf129559/python/ray/includes/gcs_client.pxi) and `GlobalStateAccessor` [python/ray/_raylet.pyx178-182](https://github.com/ray-project/ray/blob/bf129559/python/ray/_raylet.pyx#L178-L182)
 
 
### Plasma / Object Store

 The distributed shared-memory object store. Objects are identified by `ObjectID` and accessed via `ObjectRef`s.

 
 - **Code Pointers**: `ObjectRef` definition in [python/ray/includes/object_ref.pxi](https://github.com/ray-project/ray/blob/bf129559/python/ray/includes/object_ref.pxi) and [python/ray/_raylet.pyx187](https://github.com/ray-project/ray/blob/bf129559/python/ray/_raylet.pyx#L187-L187)

## Ray Data Terminology

 
### Dataset

 The primary abstraction in Ray Data for distributed data loading and processing. It represents a pipeline producing `ObjectRef[Block]` outputs.

 
 - **Definition**: [python/ray/data/dataset.py202-208](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/dataset.py#L202-L208)
 - **Blocks**: The unit of data parallelism. Blocks can be in Arrow or Pandas format [python/ray/data/dataset.py118-128](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/dataset.py#L118-L128)
 
 
### LogicalPlan & PhysicalOperator

 Ray Data uses a lazy execution model. Operations are recorded as `LogicalOperator` nodes and then translated into a physical execution graph.

 
 - **Logical Operators**: Includes `MapBatches`, `Filter`, `Join`, and `Sort` [python/ray/data/dataset.py67-88](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/dataset.py#L67-L88)
 - **Physical Operators**: Concrete execution implementations like `ActorPoolMapOperator` [python/ray/data/_internal/execution/operators/actor_pool_map_operator.py86-100](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/_internal/execution/operators/actor_pool_map_operator.py#L86-L100)
 
 
### StreamingExecutor

 The engine that executes the physical operator graph. It manages task scheduling and backpressure.

 
 - **Implementation**: [python/ray/data/_internal/execution/streaming_executor.py](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/_internal/execution/streaming_executor.py)
 - **DataContext**: Singleton containing global configuration for Data execution (e.g., `target_max_block_size`) [python/ray/data/context.py33-48](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/context.py#L33-L48)

## Ray Serve Terminology

 
### Deployment & Replica

 A `Deployment` is a managed group of `Replica` actors.

 
 - **Replica**: The `Replica` class wraps user-defined code, handling request metadata and metrics [python/ray/serve/_private/replica.py46-58](https://github.com/ray-project/ray/blob/bf129559/python/ray/serve/_private/replica.py#L46-L58)
 - **DeploymentState**: The `DeploymentStateManager` in the controller reconciles the desired vs. actual number of replicas [python/ray/serve/_private/deployment_state.py27-36](https://github.com/ray-project/ray/blob/bf129559/python/ray/serve/_private/deployment_state.py#L27-L36)

## Execution Concepts

 
### Task vs. Actor

 
 - **Task**: A stateless execution unit. Types include `TASK_TYPE_NORMAL_TASK` [python/ray/_raylet.pyx120](https://github.com/ray-project/ray/blob/bf129559/python/ray/_raylet.pyx#L120-L120)
 - **Actor**: A stateful, long-lived process. Types include `TASK_TYPE_ACTOR_CREATION_TASK` and `TASK_TYPE_ACTOR_TASK` [python/ray/_raylet.pyx121-122](https://github.com/ray-project/ray/blob/bf129559/python/ray/_raylet.pyx#L121-L122)
 
 
### Compiled DAG (CGraph)

 An accelerated path for task graphs using persistent "channels" for low-latency communication.

 
 - **Implementation**: Managed via `CompiledDAGNode` [python/ray/dag/compiled_dag_node.py11-19](https://github.com/ray-project/ray/blob/bf129559/python/ray/dag/compiled_dag_node.py#L11-L19)
 - **Execution**: Actors run an infinite loop in `do_exec_tasks` to process the schedule [python/ray/dag/compiled_dag_node.py186-203](https://github.com/ray-project/ray/blob/bf129559/python/ray/dag/compiled_dag_node.py#L186-L203)
 - **Channels**: Primitives like `SharedMemoryChannel` and `IntraProcessChannel` [python/ray/dag/compiled_dag_node.py53-68](https://github.com/ray-project/ray/blob/bf129559/python/ray/dag/compiled_dag_node.py#L53-L68)
