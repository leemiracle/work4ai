  Ray Train provides a unified interface for distributed training across multiple deep learning and gradient boosting frameworks. It leverages **Ray Data** for high-throughput, distributed data ingestion, ensuring that training workers remain saturated even with large-scale datasets.

 
## Data Ingestion with DataConfig

 The `DataConfig` class is the primary mechanism for configuring how Ray Data interacts with Ray Train workers. It handles dataset sharding, resource reservation, and locality-aware data placement.

 
### Implementation and Data Flow

 When `trainer.fit()` is called, the `DataConfig` system orchestrates the transition from a global `Dataset` to worker-local `DataIterator` instances.

 
 - **Resource Reservation**: `DataConfig` calculates the resources (CPUs/GPUs) used by training workers and can exclude them from Ray Data's execution pool to prevent resource contention.
 - **Streaming Split**: The system uses `streaming_split` to divide the dataset into `world_size` shards. This enables "just-in-time" data loading, which is critical for datasets that do not fit in memory [python/ray/data/iterator.py129-133](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/iterator.py#L129-L133)
 - **Locality Awareness**: If `enable_shard_locality` is set to `True`, the sharding logic uses worker node information as locality hints to ensure data blocks are processed on the same nodes where they are stored [release/train_tests/benchmark/ray_dataloader_factory.py141-144](https://github.com/ray-project/ray/blob/bf129559/release/train_tests/benchmark/ray_dataloader_factory.py#L141-L144)

## Framework Integrations

 Ray Train integrates with major ML frameworks by wrapping their distributed backends and providing specialized Dataloader factories.

 
### PyTorch Integration

 Ray Train's PyTorch integration focuses on the `iter_torch_batches` API, which converts Ray Data blocks into Torch tensors efficiently.

 
 - **`iter_torch_batches`**: This method provides a seamless bridge between Ray Data and PyTorch. It supports `prefetch_batches` for pipelining, `local_shuffle_buffer_size` for randomness, and `pin_memory` for faster GPU transfers [python/ray/data/iterator.py149-188](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/iterator.py#L149-L188)
 - **Collate Functions**: Users can provide a `CollateFn` to customize how individual rows are aggregated into batches. Ray provides defaults like `DefaultCollateFn` and specialized versions for Arrow or Pandas [python/ray/data/iterator.py27-36](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/iterator.py#L27-L36)
 - **Device Management**: `ray.train.torch.prepare_data_loader` can be used to wrap standard loaders, though `iter_torch_batches` is preferred for Ray Data sources [release/train_tests/benchmark/torch_dataloader_factory.py156-158](https://github.com/ray-project/ray/blob/bf129559/release/train_tests/benchmark/torch_dataloader_factory.py#L156-L158)
 
 
### TensorFlow and JAX Integration

 
 - **TensorFlow**: The `to_tf` API converts a Ray `DataIterator` into a `tf.data.Dataset`. This allows for native Keras compatibility where the resulting dataset is passed directly to `model.fit()` [python/ray/data/tests/test_iterator.py173-180](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/tests/test_iterator.py#L173-L180)
 - **JAX**: Integration via `JaxTrainer` manages multi-host TPU topologies and coordinates with `ray.train.get_dataset_shard` to feed JAX-compatible data to each worker [python/ray/train/v2/tests/test_jax_trainer.py210-217](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/tests/test_jax_trainer.py#L210-L217)
 
 
### Gradient Boosting (XGBoost/LightGBM)

 These integrations utilize Ray Data to load distributed DataFrames. The `XGBoostTrainer` and `LightGBMTrainer` handle the conversion of Ray Datasets into the internal distributed formats required by the respective frameworks.

### The streaming_split Pattern

 The `streaming_split` pattern is the standard for distributed training in Ray Train. Unlike traditional static sharding, it creates a set of output streams that consume from a shared execution graph.

### Resource and Performance Management

 For high-performance training, Ray Train allows fine-tuning of the data consumption pipeline:

 
 - **Prefetching**: `prefetch_batches` uses a separate threadpool to fetch objects to the local node and format them before the training loop requests them [python/ray/data/iterator.py185-188](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/iterator.py#L185-L188)
 - **Memory Safety**: The `StreamingExecutor` can be shut down eagerly if an iteration loop is broken early, preventing object store bloat [python/ray/data/iterator.py122-137](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/iterator.py#L122-L137)
 - **Spill Monitoring**: In large-scale benchmarks, a `SpillMetricsMonitor` actor is often used to track object store pressure during data loading [release/train_tests/benchmark/ray_dataloader_factory.py24-35](https://github.com/ray-project/ray/blob/bf129559/release/train_tests/benchmark/ray_dataloader_factory.py#L24-L35)
