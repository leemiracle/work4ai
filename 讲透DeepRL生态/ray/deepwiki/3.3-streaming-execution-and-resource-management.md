  This document describes Ray Data's streaming execution engine and resource management system. The streaming executor runs Dataset DAGs by continuously scheduling tasks to physical operators while managing cluster resources and applying backpressure to prevent out-of-memory errors.

 For information about the Dataset API and logical plan optimization, see [Dataset API and Transformations](https://deepwiki.com/ray-project/ray/3.1-dataset-api-and-transformations). For details on data sources and sinks, see [3.2 Data Sources and Sinks](https://github.com/ray-project/ray/blob/bf129559/3.2 Data Sources and Sinks)

 
## Overview

 The streaming execution system consists of several interconnected components:

 
 - **StreamingExecutor**: The main control loop that schedules operator tasks [python/ray/data/_internal/execution/streaming_executor.py100-162](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/_internal/execution/streaming_executor.py#L100-L162)
 - **Topology and OpState**: Tracks operator execution state and inter-operator queues [python/ray/data/_internal/execution/streaming_executor_state.py51-53](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/_internal/execution/streaming_executor_state.py#L51-L53)
 - **ResourceManager**: Monitors and allocates CPU, GPU, memory, and object store resources [python/ray/data/_internal/execution/resource_manager.py88-157](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/_internal/execution/resource_manager.py#L88-L157)
 - **BackpressurePolicy**: Controls task submission to prevent resource exhaustion [python/ray/data/_internal/execution/backpressure_policy/backpressure_policy.py25-27](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/_internal/execution/backpressure_policy/backpressure_policy.py#L25-L27)
 - **Physical Operators**: Execute the actual data transformations (map, filter, etc.) [python/ray/data/_internal/execution/interfaces/physical_operator.py290-310](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/_internal/execution/interfaces/physical_operator.py#L290-L310)
 
 The executor runs in a separate thread, continuously polling for completed tasks and dispatching new ones based on resource availability and backpressure policies [python/ray/data/_internal/execution/streaming_executor.py161-162](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/_internal/execution/streaming_executor.py#L161-L162)
