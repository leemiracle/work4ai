  Ray Data for LLMs, primarily implemented in the `ray.data.llm` module, provides a high-performance, multi-stage pipeline for large-scale batch inference. It abstracts the complexities of distributed GPU management, model loading, and request orchestration, allowing users to run inference engines like vLLM and SGLang at scale [doc/source/data/working-with-llms.rst6-11](https://github.com/ray-project/ray/blob/bf129559/doc/source/data/working-with-llms.rst#L6-L11)

 
## Processor Architecture

 The core abstraction in Ray Data for LLMs is the **Processor**. A Processor defines a logical pipeline of stages that transform an input dataset into an output dataset containing LLM-generated content [doc/source/data/working-with-llms.rst64-69](https://github.com/ray-project/ray/blob/bf129559/doc/source/data/working-with-llms.rst#L64-L69)

 
### Data Flow and Pipeline Stages

 The pipeline follows a structured flow where data is passed through specialized stages. Each stage typically runs as a separate Ray actor pool, enabling independent scaling and backpressure management [doc/source/data/working-with-llms.rst87-97](https://github.com/ray-project/ray/blob/bf129559/doc/source/data/working-with-llms.rst#L87-L97)

 
| Stage | Purpose | Code Entity |
|---|---|---|
| Preprocess | User-defined logic to format rows (e.g., creating OpenAI messages). | wrap_preprocess python/ray/llm/_internal/batch/stages/base.py12 |
| PrepareMultimodal | Extracts and prepares multimodal inputs for VLM/Omni models. | PrepareMultimodalStage python/ray/llm/_internal/batch/processor/vllm_engine_proc.py30 |
| ChatTemplate | Applies model-specific Jinja templates to convert messages into prompt strings. | ChatTemplateStage python/ray/llm/_internal/batch/stages/chat_template_stage.py128-133 |
| Tokenize | Converts text prompts into integer token IDs. | TokenizeStage python/ray/llm/_internal/batch/processor/vllm_engine_proc.py31 |
| LLM Engine | Executes distributed inference using vLLM or SGLang. | vLLMEngineStage python/ray/llm/_internal/batch/stages/vllm_engine_stage.py270-275 |
| Detokenize | Converts output token IDs back into human-readable text. | DetokenizeStage python/ray/llm/_internal/batch/processor/vllm_engine_proc.py29 |
| Postprocess | User-defined logic to extract specific fields from the LLM output. | wrap_postprocess python/ray/llm/_internal/batch/stages/base.py11 |

## Batch Inference Engines

 Ray Data supports multiple backends for executing inference. The most common is the `vLLMEngineStage`, which manages vLLM engine instances across the cluster [python/ray/llm/_internal/batch/stages/vllm_engine_stage.py270-275](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/stages/vllm_engine_stage.py#L270-L275)

 
### vLLM Integration

 The `vLLMEngineStage` manages the lifecycle of vLLM replicas. It handles:

 
 - **Model Downloading**: Automatically fetches models from HuggingFace or S3 using `download_model_files` [python/ray/llm/_internal/batch/stages/vllm_engine_stage.py39-40](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/stages/vllm_engine_stage.py#L39-L40)
 - **Resource Scheduling**: Uses `PlacementGroupSchedulingStrategy` to ensure that for Tensor Parallelism (TP) or Pipeline Parallelism (PP), workers are co-located correctly [python/ray/llm/_internal/batch/stages/vllm_engine_stage.py42](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/stages/vllm_engine_stage.py#L42-L42)
 - **Request Orchestration**: Uses a `vLLMEngineWrapper` to submit requests to the engine and manage `max_pending_requests` to prevent memory exhaustion [python/ray/llm/_internal/batch/stages/vllm_engine_stage.py404-430](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/stages/vllm_engine_stage.py#L404-L430)

## Multimodal and Advanced Features

 
### Multimodal Pipeline

 For Vision-Language Models (VLM) or Omni models, the processor includes a `PrepareMultimodalStage`. This stage utilizes vLLM's `parse_chat_messages_async` to process images, videos, or audio URLs into the `MultiModalDataDict` format required by the engine [release/llm_tests/batch/test_batch_vllm.py118-145](https://github.com/ray-project/ray/blob/bf129559/release/llm_tests/batch/test_batch_vllm.py#L118-L145) It is enabled by setting `prepare_multimodal_stage=True` in the `vLLMEngineProcessorConfig` [python/ray/llm/_internal/batch/processor/vllm_engine_proc.py171-177](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/processor/vllm_engine_proc.py#L171-L177)

 
### HTTP and Serve Integration

 Beyond local engines, Ray Data can query remote endpoints:

 
 - **HttpRequestProcessor**: Sends batches of data to external OpenAI-compatible APIs using `HttpRequestStage` [python/ray/data/llm.py52-63](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/llm.py#L52-L63)
 - **ServeDeploymentProcessor**: Queries a model already deployed via Ray Serve, allowing for shared engine resources between online serving and offline batch jobs [python/ray/data/llm.py153-160](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/llm.py#L153-L160)
 
 
### Error Handling and Fault Tolerance

 The `OfflineProcessorConfig` includes a `should_continue_on_error` flag [python/ray/llm/_internal/batch/processor/base.py161-168](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/processor/base.py#L161-L168) When enabled:

 
 - Failed inference rows do not crash the entire dataset job.
 - Errors are captured in a special `__inference_error__` column [python/ray/llm/_internal/batch/stages/vllm_engine_stage.py138-144](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/stages/vllm_engine_stage.py#L138-L144)
 - Faulty rows bypass the user's `postprocess` function to prevent secondary failures [python/ray/llm/_internal/batch/processor/vllm_engine_proc.py72](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/processor/vllm_engine_proc.py#L72-L72)

## Scaling and Resource Management

 Ray Data LLM supports both fixed and autoscaling worker pools for inference replicas [python/ray/llm/_internal/batch/processor/base.py41-49](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/processor/base.py#L41-L49)

 
 - **Concurrency**: Defined as an integer `n` (autoscales 1 to `n`) or a tuple `(m, n)` (autoscales `m` to `n`) [python/ray/llm/_internal/batch/processor/base.py92-130](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/processor/base.py#L92-L130)
 - **Placement Groups**: For distributed inference (e.g., `tensor_parallel_size > 1`), the `vLLMEngineProcessor` automatically configures a `PlacementGroup` with strategies like `STRICT_PACK` or `SPREAD` to ensure high-bandwidth communication between GPU shards [python/ray/llm/_internal/batch/processor/vllm_engine_proc.py87-95](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/processor/vllm_engine_proc.py#L87-L95) [python/ray/llm/_internal/batch/stages/vllm_engine_stage.py42](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/stages/vllm_engine_stage.py#L42-L42)
 - **Metrics**: vLLM engine metrics (e.g., KV cache utilization, TTFT, TPOT) are exported via Ray's Prometheus endpoint when `log_engine_metrics` is enabled [python/ray/llm/_internal/batch/processor/vllm_engine_proc.py70-77](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/batch/processor/vllm_engine_proc.py#L70-L77)
 
 **Key Implementation Classes:**
