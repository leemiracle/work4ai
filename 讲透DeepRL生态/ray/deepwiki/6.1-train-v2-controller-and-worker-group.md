  Ray Train v2 introduces a revamped architecture designed for robustness, elasticity, and improved observability. The core of this architecture is the decoupling of training orchestration (the `TrainController`) from the execution environment (the `WorkerGroup`).

 
## TrainController and State Machine

 The `TrainController` is the central orchestrator for a distributed training job [python/ray/train/v2/_internal/execution/controller/controller.py105-114](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L105-L114) It manages the lifecycle of training by transitioning through a set of formal states defined in `ray.train.v2._internal.execution.controller.state` [python/ray/train/v2/_internal/execution/controller/controller.py39-51](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L39-L51)

 
### Lifecycle State Machine

 The controller operates as an asynchronous state machine. Each iteration of the control loop evaluates the current state and triggers transitions based on worker health, scaling decisions, or user code completion [python/ray/train/v2/_internal/execution/controller/controller.py221-236](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L221-L236)

 
| State | Responsibility |
|---|---|
| InitializingState | Initial setup of the controller and policies python/ray/train/v2/_internal/execution/controller/state.py43 |
| SchedulingState | Requesting resources and instantiating the WorkerGroup python/ray/train/v2/_internal/execution/controller/state.py48 |
| RunningState | Monitoring an active WorkerGroup and processing reported metrics/checkpoints python/ray/train/v2/_internal/execution/controller/state.py47 |
| ResizingState | Transition state when the ScalingPolicy requests a change in worker count python/ray/train/v2/_internal/execution/controller/state.py45 |
| RestartingState | Triggered by the FailurePolicy to recover from worker failures python/ray/train/v2/_internal/execution/controller/state.py46 |
| ShuttingDownState | Graceful termination of workers and cleanup of resources python/ray/train/v2/_internal/execution/controller/state.py49 |

 
### Control Loop Logic

 The `_run_control_loop_iteration` method is the heart of the controller [python/ray/train/v2/_internal/execution/controller/controller.py221](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L221-L221) It performs three primary actions:

 
 - **Poll Status**: Checks the health and progress of the `WorkerGroup` [python/ray/train/v2/_internal/execution/controller/controller.py230](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L230-L230)
 - **Handle Transitions**: Executes the logic associated with the current `TrainControllerState` [python/ray/train/v2/_internal/execution/controller/controller.py231](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L231-L231)
 - **Policy Consultation**: Consults the `ScalingPolicy` and `FailurePolicy` to decide if the group needs resizing or restarting [python/ray/train/v2/_internal/execution/controller/controller.py134-135](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L134-L135)
 
 **Sources:** [python/ray/train/v2/_internal/execution/controller/controller.py105-236](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L105-L236) [python/ray/train/v2/_internal/execution/controller/state.py39-51](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/state.py#L39-L51)

 
## WorkerGroup Lifecycle Management

 The `WorkerGroup` represents the collection of Ray Actors (`RayTrainWorker`) executing the training function [python/ray/train/v2/_internal/execution/worker_group/worker_group.py88-89](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/worker_group/worker_group.py#L88-L89)

 
### Initialization and Startup

 A `WorkerGroup` is created via the `WorkerGroup.create` factory method [python/ray/train/v2/_internal/execution/worker_group/worker_group.py92-117](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/worker_group/worker_group.py#L92-L117)

 
 - **Resource Allocation**: It manages a `PlacementGroupHandle` (e.g., `DefaultPlacementGroupHandle` or `SlicePlacementGroupHandle` for TPUs) to ensure gang-scheduling of workers [python/ray/train/v2/_internal/execution/worker_group/worker_group.py48-52](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/worker_group/worker_group.py#L48-L52)

## Checkpoint and Validation Management

 Train v2 separates checkpoint persistence from the training loop to minimize GPU idle time.

 
### Async Checkpoint Validation

 When `ray.train.report` is called with a checkpoint and `validation=True` [python/ray/train/v2/api/train_fn_utils.py23-31](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/api/train_fn_utils.py#L23-L31) the `ValidationManager` handles the lifecycle:

 
 - **Reporting**: Workers report the checkpoint to the `TrainController`.
 - **Async Validation**: The `ValidationManager` triggers a non-blocking validation task (defined in `ValidationConfig`) [python/ray/train/v2/_internal/execution/controller/controller.py35-37](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L35-L37)
 - **Consistency**: The `CheckpointConsistencyMode` determines when a checkpoint is considered "ready" for consumption (e.g., `VALIDATED` vs `REPORTED`) [python/ray/train/v2/api/report_config.py36-38](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/api/report_config.py#L36-L38)
 
 
### Synchronization Actor

 The `SynchronizationActor` is a specialized actor that facilitates collective operations and metadata sharing among workers without involving the controller for every operation [python/ray/train/v2/_internal/execution/checkpoint/sync_actor.py20-23](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/checkpoint/sync_actor.py#L20-L23) It is used by `ray.train.collective.barrier()` and for broadcasting checkpoint metadata [python/ray/train/v2/api/train_fn_utils.py173-174](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/api/train_fn_utils.py#L173-L174)

## Scaling and Failure Handling

 
### Scaling Policies

 The `ScalingPolicy` determines the target number of workers [python/ray/train/v2/_internal/execution/controller/controller.py56-60](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L56-L60)

 
 - **Fixed**: A static number of workers requested via `ScalingConfig(num_workers=N)`.
 - **Elastic**: Allows the `WorkerGroup` to resize dynamically based on cluster resource availability [python/ray/train/v2/api/data_parallel_trainer.py118-121](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/api/data_parallel_trainer.py#L118-L121) When a `ResizeDecision` is made, the controller transitions to `ResizingState` [python/ray/train/v2/_internal/execution/controller/controller.py58](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L58-L58)
 
 
### Failure Handling

 The `FailurePolicy` monitors the status of the training run [python/ray/train/v2/_internal/execution/controller/controller.py52-55](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L52-L55)

 
 - **Worker Failure**: If a worker actor dies or throws an exception, the policy decide whether to restart the worker group or terminate training [python/ray/train/v2/_internal/execution/controller/controller.py112](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/_internal/execution/controller/controller.py#L112-L112)
 - **Max Failures**: Controlled by `FailureConfig(max_failures=N)` [python/ray/train/v2/api/data_parallel_trainer.py170](https://github.com/ray-project/ray/blob/bf129559/python/ray/train/v2/api/data_parallel_trainer.py#L170-L170)
