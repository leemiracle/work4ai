  Ray Serve LLM provides a high-performance, extensible framework for serving Large Language Models (LLMs) on Ray. It abstracts complex distributed serving patterns like continuous batching, LoRA multiplexing, and KV cache management into a unified system that integrates deeply with engines like vLLM.

 
## Core Architecture and Data Flow

 The architecture is built around the `LLMServer`, which acts as the primary deployment actor, and the `OpenAiIngress`, which provides a standardized API entry point.

### Request Lifecycle

 
 - **Ingress**: The `OpenAiIngress` receives an HTTP request (e.g., `/v1/chat/completions`) and validates it against OpenAI-compatible Pydantic models [python/ray/llm/_internal/serve/core/ingress/ingress.py119-133](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/serve/core/ingress/ingress.py#L119-L133)
 - **Routing**: The `LLMRouter` parses the request body into a `routing_payload` and picks a target replica [python/ray/llm/_internal/serve/core/ingress/router.py134-160](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/serve/core/ingress/router.py#L134-L160)
 - **Execution**: The `LLMServer` replica passes the request to its internal `LLMEngine` instance [python/ray/llm/_internal/serve/core/server/llm_server.py194-199](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/serve/core/server/llm_server.py#L194-L199)
 - **Streaming**: Responses are yielded as an `AsyncGenerator`, allowing the server to stream tokens back to the client immediately [python/ray/llm/_internal/serve/core/server/llm_server.py214-225](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/serve/core/server/llm_server.py#L214-L225)

## Engine Integrations

 Ray Serve LLM utilizes an `LLMEngine` protocol to maintain engine-agnostic logic while supporting optimized backends.

 
### vLLM Integration

 The `VLLMEngine` implementation bridges Ray Serve with vLLM's `AsyncLLMEngine`. It handles:

 
 - **Initialization**: Resolves model paths from mirrors and configures `AsyncEngineArgs` [python/ray/llm/_internal/serve/engines/vllm/vllm_engine.py157-182](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/serve/engines/vllm/vllm_engine.py#L157-L182)
 - **Distributed Execution**: Configures `distributed_executor_backend` to "ray" for GPU workloads or "mp" for CPU [python/ray/llm/_internal/serve/engines/vllm/vllm_models.py148-162](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/serve/engines/vllm/vllm_models.py#L148-L162)
 - **Environment Propagation**: Automatically propagates critical environment variables (e.g., `VLLM_RAY_PER_WORKER_GPUS`) to workers [python/ray/llm/_internal/serve/engines/vllm/vllm_models.py169-185](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/_internal/serve/engines/vllm/vllm_models.py#L169-L185)

## LoRA Multiplexing

 Ray Serve LLM supports serving multiple LoRA adapters using a shared base model deployment.

 
 - **Request Identification**: Requests are tagged with a `multiplexed_model_id` [python/ray/llm/tests/serve/cpu/deployments/llm/test_llm_server.py63](https://github.com/ray-project/ray/blob/bf129559/python/ray/llm/tests/serve/cpu/deployments/llm/test_llm_server.py#L63-L63)
