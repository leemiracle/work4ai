  This page documents RLlib's training architecture, focusing on how the `Algorithm` class orchestrates distributed reinforcement learning training. It covers the configuration system (`AlgorithmConfig`), experience collection via `EnvRunnerGroup` and `EnvRunner` actors, distributed learning via `LearnerGroup` and `Learner` actors, connector pipelines for data transformation, multi-agent support, and fault tolerance mechanisms.

 For information about specific RLModule implementations and model architectures, see the RLModule documentation. For details on the underlying Ray Core infrastructure that enables distributed execution, see [2.1](https://github.com/ray-project/ray/blob/bf129559/2.1)

 
## Training Loop Overview

 RLlib's training architecture follows a distributed actor-based pattern where the `Algorithm` orchestrates parallel experience collection and model updates. The system separates environment interaction (handled by `EnvRunner` actors) from learning (handled by `Learner` actors), enabling efficient scaling.

## Algorithm Class

 The `Algorithm` class is the central orchestrator for RLlib training. It manages the training loop, coordinates between `EnvRunnerGroup` and `LearnerGroup`, handles checkpointing, and aggregates metrics.

 
```

```

 
### Training Iteration Lifecycle

 The `Algorithm.train()` method orchestrates a single training iteration [rllib/algorithms/algorithm.py825-850](https://github.com/ray-project/ray/blob/bf129559/rllib/algorithms/algorithm.py#L825-L850):

 
 - **Sampling Phase**: `EnvRunnerGroup.sample()` collects episodes from parallel EnvRunners [rllib/algorithms/algorithm.py832-835](https://github.com/ray-project/ray/blob/bf129559/rllib/algorithms/algorithm.py#L832-L835)
 - **Learning Phase**: `LearnerGroup.update()` performs gradient updates on the collected data [rllib/algorithms/algorithm.py836-838](https://github.com/ray-project/ray/blob/bf129559/rllib/algorithms/algorithm.py#L836-L838)
 - **Synchronization Phase**: Updated weights are broadcast to EnvRunners [rllib/algorithms/algorithm.py840-842](https://github.com/ray-project/ray/blob/bf129559/rllib/algorithms/algorithm.py#L840-L842)
 - **Metrics Phase**: Results from all components are aggregated via `MetricsLogger` [rllib/algorithms/algorithm.py844-846](https://github.com/ray-project/ray/blob/bf129559/rllib/algorithms/algorithm.py#L844-L846)
 
 The specific implementation of step 2 is defined by the algorithm-specific `training_step()` method. For example:

 
 - **Synchronous algorithms (PPO, SAC)**: Wait for all EnvRunners to complete sampling, then perform a fixed number of gradient updates.
 - **Asynchronous algorithms (IMPALA, APPO)**: Continuously consume samples from a queue and update as they arrive [rllib/algorithms/impala/impala.py530-650](https://github.com/ray-project/ray/blob/bf129559/rllib/algorithms/impala/impala.py#L530-L650)

## Experience Collection Architecture

 RLlib's experience collection system uses the `EnvRunnerGroup` to manage parallel `EnvRunner` actors. Each `EnvRunner` contains its own copy of the environment(s) and RLModule for action inference.

 
### EnvRunnerGroup

 The `EnvRunnerGroup` manages a pool of remote `EnvRunner` actors using `FaultTolerantActorManager`. It provides high-level APIs for parallel operations across all workers [rllib/env/env_runner_group.py70-142](https://github.com/ray-project/ray/blob/bf129559/rllib/env/env_runner_group.py#L70-L142)

### Sampling Process

 The `EnvRunner.sample()` method implements the core sampling loop [rllib/env/single_agent_env_runner.py149-250](https://github.com/ray-project/ray/blob/bf129559/rllib/env/single_agent_env_runner.py#L149-L250):

 - **Connector Phase**: Run `env_to_module` connector to prepare observations for RLModule [rllib/env/single_agent_env_runner.py300-310](https://github.com/ray-project/ray/blob/bf129559/rllib/env/single_agent_env_runner.py#L300-L310)
 - **Inference Phase**: Call `module.forward_exploration()` or `module.forward_inference()` to compute actions [rllib/env/single_agent_env_runner.py315-325](https://github.com/ray-project/ray/blob/bf129559/rllib/env/single_agent_env_runner.py#L315-L325)
 - **Connector Phase**: Run `module_to_env` connector to post-process actions [rllib/env/single_agent_env_runner.py330-340](https://github.com/ray-project/ray/blob/bf129559/rllib/env/single_agent_env_runner.py#L330-L340)

## Connector Pipelines

 Connector pipelines transform data between components. RLlib uses three types of connectors:

 
| Connector Type | Purpose | Input | Output |
|---|---|---|---|
| env_to_module | Prepare observations for RLModule | Raw env observations | Processed observations rllib/env/single_agent_env_runner.py106-108 |
| module_to_env | Post-process actions for environment | RLModule action outputs | Clipped/unsquashed actions rllib/env/single_agent_env_runner.py124-126 |
| learner_connector | Prepare training batches | Episode data | Training batch rllib/core/learner/learner.py331-345 |

 Connectors are configured via `AlgorithmConfig` methods and can be customized by users [rllib/algorithms/algorithm_config.py325-366](https://github.com/ray-project/ray/blob/bf129559/rllib/algorithms/algorithm_config.py#L325-L366)

## Fault Tolerance

 RLlib implements comprehensive fault tolerance for actors through the `FaultTolerantActorManager` [rllib/utils/actor_manager.py42-100](https://github.com/ray-project/ray/blob/bf129559/rllib/utils/actor_manager.py#L42-L100)

 
### Fault Tolerance Configuration

 Configure fault tolerance behavior via `AlgorithmConfig.fault_tolerance()` [rllib/algorithms/algorithm_config.py587-603](https://github.com/ray-project/ray/blob/bf129559/rllib/algorithms/algorithm_config.py#L587-L603):

 
| Setting | Purpose | Default |
|---|---|---|
| restart_failed_env_runners | Auto-restart failed EnvRunner actors | True |
| max_num_env_runner_restarts | Max restart attempts per actor | 1000 |
| delay_between_env_runner_restarts_s | Delay between restarts | 60.0 |
| num_consecutive_env_runner_failures_tolerance | Max consecutive failures before stopping | 100 |

 
### Actor Restart Process

 When an actor fails, `FaultTolerantActorManager` detects the failure and initiates a restart [rllib/utils/actor_manager.py244-300](https://github.com/ray-project/ray/blob/bf129559/rllib/utils/actor_manager.py#L244-L300) New actors are created with the same configuration, and their state is restored from the last checkpoint.
