  This page documents the primary system components of a Ray node: the **Raylet** (node manager and scheduler), the **Global Control Service (GCS)** (cluster metadata and control plane), and the **Plasma Object Store** (shared memory and object management).

 
## 1. Raylet: Node Management and Scheduling

 The Raylet is the per-node daemon responsible for worker process management, local resource scheduling, and object management. Its primary component is the `NodeManager`.

 
### 1.1 NodeManager and Worker Lifecycle

 The `NodeManager` manages a pool of worker processes via the `WorkerPool` class. It handles requests for worker leases, starts new worker processes when needed, and monitors their health.

 
 - **Worker Pool**: `WorkerPool` maintains sets of idle and busy workers, categorized by language (Python, Java, C++) and runtime environment [src/ray/raylet/worker_pool.h158-184](https://github.com/ray-project/ray/blob/bf129559/src/ray/raylet/worker_pool.h#L158-L184)
 - **Worker Process Startup**: When a task requires a worker that isn't available, `WorkerPool::StartWorkerProcess` is called to fork/exec a new process using the commands defined in `NodeManagerConfig` [src/ray/raylet/worker_pool.cc540-600](https://github.com/ray-project/ray/blob/bf129559/src/ray/raylet/worker_pool.cc#L540-L600)
 - **Resource Isolation**: If enabled, the Raylet uses `CgroupManager` to enforce CPU and memory limits on worker processes [src/ray/raylet/node_manager.cc133-140](https://github.com/ray-project/ray/blob/bf129559/src/ray/raylet/node_manager.cc#L133-L140)
 
 
### 1.2 Resource Scheduling

 The Raylet performs local scheduling decisions using the `ClusterResourceScheduler`.

 
 - **Lease Requests**: Core workers request a "lease" to execute tasks on a node via the `RequestWorkerLease` RPC [src/ray/protobuf/node_manager.proto43-55](https://github.com/ray-project/ray/blob/bf129559/src/ray/protobuf/node_manager.proto#L43-L55)
 - **Local Scheduling**: The `NodeManager` checks if local resources are sufficient. If not, it may "spill back" the request to another node [src/ray/raylet/node_manager.cc2000-2050](https://github.com/ray-project/ray/blob/bf129559/src/ray/raylet/node_manager.cc#L2000-L2050)

## 2. Global Control Service (GCS)

 The GCS is the cluster's centralized control plane. It manages cluster-wide metadata and coordinates global operations like actor creation and node heartbeats.

 
### 2.1 Metadata Management

 The GCS maintains several managers for different Ray entities:

 
 - **Actor Manager**: Handles actor registration, lifecycle, and reconstruction [src/ray/gcs/gcs_server.cc27](https://github.com/ray-project/ray/blob/bf129559/src/ray/gcs/gcs_server.cc#L27-L27) The `GcsActorManager` class is responsible for this [src/ray/gcs/actor/gcs_actor_manager.h](https://github.com/ray-project/ray/blob/bf129559/src/ray/gcs/actor/gcs_actor_manager.h)
 - **Node Manager**: Tracks the status (Alive/Dead) of all nodes in the cluster [src/ray/gcs/gcs_server.cc89-94](https://github.com/ray-project/ray/blob/bf129559/src/ray/gcs/gcs_server.cc#L89-L94) This is handled by `GcsNodeManager` [src/ray/gcs/gcs_node_manager.h](https://github.com/ray-project/ray/blob/bf129559/src/ray/gcs/gcs_node_manager.h)
 - **Placement Group Manager**: Manages the lifecycle of resource bundles [src/ray/gcs/gcs_server.cc30](https://github.com/ray-project/ray/blob/bf129559/src/ray/gcs/gcs_server.cc#L30-L30) The `GcsPlacementGroupManager` and `GcsPlacementGroupScheduler` classes are involved [src/ray/gcs/gcs_placement_group_scheduler.h](https://github.com/ray-project/ray/blob/bf129559/src/ray/gcs/gcs_placement_group_scheduler.h)
 
 
### 2.2 Storage Backends

 GCS state can be persisted in different backends defined by `StorageType` [src/ray/gcs/gcs_server.cc49-60](https://github.com/ray-project/ray/blob/bf129559/src/ray/gcs/gcs_server.cc#L49-L60):

 
 - **In-Memory**: Used for testing or non-HA clusters. Implemented by `InMemoryStoreClient` [src/ray/gcs/store_client/in_memory_store_client.h](https://github.com/ray-project/ray/blob/bf129559/src/ray/gcs/store_client/in_memory_store_client.h)
 - **Redis**: The standard persistent store for cluster metadata. Implemented by `RedisStoreClient` [src/ray/gcs/store_client/redis_store_client.h](https://github.com/ray-project/ray/blob/bf129559/src/ray/gcs/store_client/redis_store_client.h)
 
 
### 2.3 Pub/Sub Infrastructure

 The GCS acts as a centralized publisher for cluster-wide events (e.g., node failures, resource updates) using the `pubsub::GcsPublisher` [src/ray/gcs/gcs_server.cc150-151](https://github.com/ray-project/ray/blob/bf129559/src/ray/gcs/gcs_server.cc#L150-L151)

## 3. Object Store (Plasma)

 Ray uses the Plasma object store for high-performance shared memory communication between workers on the same node.

 
### 3.1 Object Management

 The `ObjectManager` coordinates object movement between nodes and interaction with the local Plasma store.

 
 - **Plasma Store**: A shared memory server (`PlasmaStoreRunner`) that allows multiple processes to read the same memory without copying [src/ray/object_manager/object_manager.cc33-50](https://github.com/ray-project/ray/blob/bf129559/src/ray/object_manager/object_manager.cc#L33-L50)
 - **Pull/Push Manager**: Handles fetching objects from remote nodes (`PullManager`) and sending local objects to remote nodes (`PushManager`) [src/ray/object_manager/object_manager.cc101-134](https://github.com/ray-project/ray/blob/bf129559/src/ray/object_manager/object_manager.cc#L101-L134)
 
 
### 3.2 Object Spilling

 When the object store is full, Ray spills objects to external storage (e.g., local disk or S3).

 
 - **LocalObjectManager**: Orchestrates the spilling process. It identifies spillable objects and invokes the spilling callback [src/ray/raylet/local_object_manager.h45-50](https://github.com/ray-project/ray/blob/bf129559/src/ray/raylet/local_object_manager.h#L45-L50)
 - **Spilling Logic**: The `SpillObjects` function handles the asynchronous transfer of object data to the configured spill URL [src/ray/raylet/local_object_manager.cc169](https://github.com/ray-project/ray/blob/bf129559/src/ray/raylet/local_object_manager.cc#L169-L169)
