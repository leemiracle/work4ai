## Purpose and Scope

 This document covers Ray Data's Dataset API for applying transformations to distributed data. It explains the lazy execution model, transformation methods like `map`, `map_batches`, and `filter`, and the internal architecture that converts user transformations into optimized physical execution plans.

 For information about data sources and sinks, see [Data Sources and Sinks](https://deepwiki.com/ray-project/ray/3.2-data-sources-and-sinks). For details on execution and resource management, see [Streaming Execution and Resource Management](https://deepwiki.com/ray-project/ray/3.3-streaming-execution-and-resource-management).

## Overview: Dataset Transformation Pipeline

 Ray Data implements a multi-stage pipeline that transforms user API calls into optimized physical operators. The Dataset class provides a lazy execution model where transformations build up a logical plan that is only executed when data is consumed.

## Dataset Class and Lazy Execution

 The `Dataset` class is the primary user-facing API for distributed data processing. It holds a `LogicalPlan` that represents pending transformations.

 
```

```

 **Key Characteristics**

 
| Aspect | Description |
|---|---|
| Lazy Execution | Transformations build a logical plan; execution happens on consumption (e.g., take(), materialize()) python/ray/data/dataset.py203-207 |
| Immutability | Each transformation returns a new Dataset with updated plans python/ray/data/dataset.py437-438 |
| Block Management | Data is partitioned into ObjectRef[Block] shards, where each block holds data in Arrow or Pandas format python/ray/data/dataset.py205-207 |
| Schema Inference | Schema determined without full execution using the logical plan python/ray/data/block.py161-173 |

 Execution is triggered by methods like `take()` or `materialize()`, which initiate the streaming execution pipeline [python/ray/data/dataset.py102-104](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/dataset.py#L102-L104)

## Transformation APIs

 
### Core Transformation Methods

 The Dataset class provides several transformation methods, each creating specific logical operators:

 
| Method | Logical Operator | Purpose | Row Count Change |
|---|---|---|---|
| map() | MapRows | Apply function to each row python/ray/data/_internal/logical/operators.py75 | No |
| map_batches() | MapBatches | Apply function to batches python/ray/data/_internal/logical/operators.py74 | Optional |
| filter() | Filter | Keep rows matching predicate python/ray/data/_internal/logical/operators.py69 | Yes (decreases) |
| flat_map() | FlatMap | Emit multiple rows per input row python/ray/data/_internal/logical/operators.py70 | Yes (increases) |
| project() | Project | Add/replace/select columns via expressions python/ray/data/_internal/logical/operators.py78 | No |
| repartition() | Repartition | Change the number of blocks python/ray/data/_internal/logical/operators.py81 | No |

## All-to-All Operations: Shuffling and Sorting

 Operations like `sort`, `groupby`, and `repartition` require data movement across all blocks, known as "All-to-All" operations.

 
### Hash Shuffle

 The `HashShuffle` operator is used for repartitioning and joins.

 
 - **Partitioning**: Input blocks are split into $N$ partitions based on a hash key [python/ray/data/_internal/arrow_ops/transform_pyarrow.py139-150](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/_internal/arrow_ops/transform_pyarrow.py#L139-L150)
 - **Aggregation**: The `HashShuffleAggregator` actor collects shards and applies a `ShuffleAggregation` (e.g., `ConcatAggregation`) [python/ray/data/_internal/execution/operators/hash_shuffle.py115-140](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/_internal/execution/operators/hash_shuffle.py#L115-L140)
 
 
### Sorting

 Sorting is implemented via a distributed sample-based sort:

 
 - **Sampling**: Samples are taken to determine quantile boundaries.
 - **Shuffle**: Data is partitioned based on these boundaries.
 - **Local Sort**: Each resulting block is sorted locally using PyArrow or Polars [python/ray/data/_internal/arrow_block.py78-83](https://github.com/ray-project/ray/blob/bf129559/python/ray/data/_internal/arrow_block.py#L78-L83)
