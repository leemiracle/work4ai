## Purpose and Scope

 This page documents Ray Data's I/O system, which provides abstractions for reading from and writing to various data sources and formats. The system supports file formats (Parquet, CSV, JSON), databases (MongoDB, BigQuery, Snowflake, SQL), streaming sources (Kafka), and modern table formats (Iceberg, Delta Lake, Hudi). It also handles conversions from other data processing frameworks (Pandas, Dask, Spark) and machine learning frameworks (TensorFlow, PyTorch, Hugging Face).

 For information about how datasets are transformed after reading, see [Dataset API and Transformations](https://deepwiki.com/ray-project/ray/3.1-dataset-api-and-transformations). For details on execution and resource management during I/O operations, see [Streaming Execution and Resource Management](https://deepwiki.com/ray-project/ray/3.3-streaming-execution-and-resource-management).

 
## Datasource Architecture

 The Ray Data I/O system is built around two core abstractions: `Datasource` for reading and `Datasink` for writing. These abstractions enable parallel, distributed I/O operations that integrate with Ray's task execution model.
