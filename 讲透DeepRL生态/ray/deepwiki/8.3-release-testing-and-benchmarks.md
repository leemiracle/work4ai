  This page documents the Ray release testing framework and benchmark suite. This infrastructure is responsible for validating Ray's functionality, performance, and scalability on real cloud environments before official releases. The system supports multi-cloud execution, specialized ML workload benchmarks, and automated lifecycle management for flaky tests.

 
---

 
## Purpose and Scope

 The release testing framework provides:

 
 - **Functional Validation**: Integration tests across AWS, GCP, and Azure to ensure component reliability.
 - **Performance Benchmarking**: Tracking of throughput and latency metrics for Ray Data, Train, and Serve.
 - **Stability Testing**: Long-running workloads (24h+) to detect memory leaks and actor lifecycle issues.
 - **Automation**: A state machine that monitors test results and automatically creates GitHub issues or "jails" flaky tests.

 The execution of release tests is managed by the `ray_release` package, primarily through `glue.py` and the `AnyscaleJobRunner`.

## CI Automation and State Machine

 To manage hundreds of tests, Ray uses an automated state machine (`CITestStateMachine`) to track test health.

 
### Test States and Transitions

 The state machine reads historical results from S3 and transitions tests between states.

 
| State | Definition | Transition Logic |
|---|---|---|
| PASSING | Test is stable | Default state release/ray_release/test.py78 |
| FAILING | Recent failure detected | Single failure detected in latest run release/ray_release/test.py75 |
| CONSISTENTLY_FAILING | Fails multiple times in a row | 3+ continuous failures release/ray_release/test.py76 |
| FLAKY | Intermittent failures | Transitions if failure rate is inconsistent release/ray_release/test.py77 |
| JAILED | Manually disabled via GitHub | Triggered when a test is quarantined due to excessive instability release/ray_release/test.py74 |

 
### Automated Actions

 
 - **GitHub Integration**: The system can check for open GitHub issues associated with a test to determine if it should remain in a `JAILED` state [release/ray_release/test.py189-219](https://github.com/ray-project/ray/blob/bf129559/release/ray_release/test.py#L189-L219)
 - **Bisect Support**: The framework includes logic to limit daily bisections per platform to manage CI resources [release/ray_release/test.py49-52](https://github.com/ray-project/ray/blob/bf129559/release/ray_release/test.py#L49-L52)
