  The Ray Runtime Environment system allows users to dynamically specify dependencies (packages, files, environment variables) for a job, task, or actor [doc/source/ray-core/handling-dependencies.rst58-68](https://github.com/ray-project/ray/blob/bf129559/doc/source/ray-core/handling-dependencies.rst#L58-L68) Unlike static cluster-wide environments, runtime environments are installed on-the-fly, cached, and isolated to specific Ray processes [doc/source/ray-core/handling-dependencies.rst64-67](https://github.com/ray-project/ray/blob/bf129559/doc/source/ray-core/handling-dependencies.rst#L64-L67)

 
## System Architecture

 The runtime environment system is orchestrated by the `RuntimeEnvAgent`, a sidecar process running on every node [python/ray/_private/runtime_env/agent/runtime_env_agent.py165-180](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/agent/runtime_env_agent.py#L165-L180)

 
### Component Interaction

 
 - **Submission**: A user submits a `RuntimeEnv` dict via `ray.init()`, `@ray.remote()`, or the Jobs API [python/ray/runtime_env/runtime_env.py157-183](https://github.com/ray-project/ray/blob/bf129559/python/ray/runtime_env/runtime_env.py#L157-L183)
 - **Request**: The `Raylet` on a node receives a task requiring a specific environment. If the environment is not cached, it sends a `GetOrCreateRuntimeEnv` RPC to the local `RuntimeEnvAgent` [src/ray/raylet/runtime_env_agent_client.cc48-62](https://github.com/ray-project/ray/blob/bf129559/src/ray/raylet/runtime_env_agent_client.cc#L48-L62)
 - **Creation**: The `RuntimeEnvAgent` invokes specific plugins (Pip, Conda, WorkingDir, Uv) to install the environment [python/ray/_private/runtime_env/agent/runtime_env_agent.py433-450](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/agent/runtime_env_agent.py#L433-L450)
 - **Execution**: Once setup is complete, the agent returns a `RuntimeEnvContext` containing environment variables and command prefixes [python/ray/_private/runtime_env/context.py18-33](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/context.py#L18-L33) The worker process is then started using these parameters [python/ray/_private/runtime_env/context.py42-108](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/context.py#L42-L108)

## Packaging and URI Protocols

 Ray uses URIs to identify and track dependencies. The `packaging.py` module handles the hashing and uploading of local resources to the cluster storage [python/ray/_private/runtime_env/packaging.py1-13](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/packaging.py#L1-L13)

 
### Supported Protocols

 Ray supports several protocols for fetching resources, managed by the `ProtocolsProvider` [python/ray/_private/runtime_env/protocol.py10-40](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/protocol.py#L10-L40):

 
 - `gcs://`: Packages managed by Ray's Global Control Service.
 - `conda://`, `pip://`, `uv://`: Local environment definitions.
 - `s3://`, `gs://`, `azure://`, `abfss://`: Remote cloud storage.
 - `http://`, `https://`: Publicly accessible zip files.
 - `file://`: Local filesystem paths.
 
 
### Hashing and Determinism

 To enable caching, Ray generates a deterministic hash for directories by traversing files and XORing their content hashes [python/ray/_private/runtime_env/packaging.py211-230](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/packaging.py#L211-L230) This hash forms part of the URI (e.g., `gcs://_ray_pkg_<hash>.zip`) [python/ray/_private/runtime_env/packaging.py51](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/packaging.py#L51-L51) For `uv` or `pip` environments, the hash is derived from the serialized package list or requirements [python/ray/_private/runtime_env/uv.py23-27](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/uv.py#L23-L27)

## Plugin System

 The `RuntimeEnvAgent` uses a plugin architecture to handle different dependency types. Every plugin must implement the `RuntimeEnvPlugin` interface [python/ray/_private/runtime_env/plugin.py24-28](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/plugin.py#L24-L28)

 
| Plugin | Key | Description |
|---|---|---|
| WorkingDirPlugin | working_dir | Downloads and unpacks a zip/directory into the worker's execution path python/ray/_private/runtime_env/working_dir.py |
| PipPlugin | pip | Creates a virtualenv and installs packages via pip install python/ray/_private/runtime_env/pip.py |
| UvPlugin | uv | Uses uv for high-performance package installation and environment management python/ray/_private/runtime_env/uv.py |
| CondaPlugin | conda | Creates a Conda environment from a YAML or existing name python/ray/_private/runtime_env/conda.py |
| ContainerPlugin | container | Runs the worker inside a specified Docker/Podman image python/ray/_private/runtime_env/image_uri.py184-187 |
| EnvVarsPlugin | env_vars | Sets environment variables in the worker process python/ray/_private/runtime_env/context.py24 |
| PyExecutablePlugin | py_executable | Overrides the Python command, allowing usage of uv run or custom wrappers python/ray/_private/runtime_env/py_executable.py |

 
### Container Isolation (Podman/Docker)

 The `ContainerPlugin` (and `ImageURIPlugin`) allows Ray workers to run inside containers. It pulls the image, identifies the internal `default_worker.py` path, and modifies the `py_executable` to use `podman run` or `docker run` as a prefix [python/ray/_private/runtime_env/image_uri.py76-137](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/image_uri.py#L76-L137)

## Lifecycle and Reference Counting

 To prevent disk bloat, the `RuntimeEnvAgent` maintains a `ReferenceTable` to track URI usage across the node [python/ray/_private/runtime_env/agent/runtime_env_agent.py63-70](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/agent/runtime_env_agent.py#L63-L70)

 
### Garbage Collection Flow

 
 - **Increase Reference**: When a Raylet requests an environment, the agent increments the count for that `serialized_env` and its associated URIs via `ReferenceTable.increase_reference` [python/ray/_private/runtime_env/agent/runtime_env_agent.py136-143](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/agent/runtime_env_agent.py#L136-L143)
 - **Decrease Reference**: When the task or actor finishes, the Raylet notifies the agent to decrement the count via `ReferenceTable.decrease_reference` [python/ray/_private/runtime_env/agent/runtime_env_agent.py145-153](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/agent/runtime_env_agent.py#L145-L153)
 - **Deletion**: When a URI's reference count reaches zero, `_decrease_reference_for_uris` triggers the `unused_uris_callback` [python/ray/_private/runtime_env/agent/runtime_env_agent.py98-112](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/agent/runtime_env_agent.py#L98-L112)

## Working Directory Management

 The `working_dir` option is a specialized case where files are synced to the node.

 
 - **Hashing**: The client hashes the local directory using `get_uri_for_directory` [python/ray/_private/runtime_env/packaging.py211-222](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/packaging.py#L211-L222)
 - **Uploading**: If the hash doesn't exist in the GCS KV store, the client zips and uploads the directory via `upload_package_to_gcs` [python/ray/_private/runtime_env/packaging.py438-443](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/packaging.py#L438-L443)
 - **Setup**: On the worker node, the `WorkingDirPlugin` downloads the zip from the GCS, unpacks it into a unique directory under the Ray session folder, and adds this path to the `PYTHONPATH` in the `RuntimeEnvContext` [python/ray/_private/runtime_env/working_dir.py](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/working_dir.py) [python/ray/_private/runtime_env/context.py112-117](https://github.com/ray-project/ray/blob/bf129559/python/ray/_private/runtime_env/context.py#L112-L117)
