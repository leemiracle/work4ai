  This document describes Ray's package management architecture, including how the project defines, resolves, and distributes dependencies across multiple optional components. It covers the core dependency set, the extras system for optional features, dependency lock files for reproducible builds, the `raydepsets` locking system, and the GPU/CUDA environment provisioning for LLM workloads.

 
---

 
## Package Distribution Model

 Ray produces two distinct wheel packages from the same repository, controlled by environment variables during the build process.

 
### Primary Package Types

 
```

```

 **Sources:** [python/setup.py65-138](https://github.com/ray-project/ray/blob/bf129559/python/setup.py#L65-L138)

 The `SetupSpec` class [python/setup.py78-101](https://github.com/ray-project/ray/blob/bf129559/python/setup.py#L78-L101) determines package characteristics based on build configuration. The `ray-cpp` wheel uses a custom `RayCppBdistWheel` class [python/setup.py769-783](https://github.com/ray-project/ray/blob/bf129559/python/setup.py#L769-L783) to produce Python-agnostic wheels with `py3-none-platform` tags, allowing the same wheel to work across Python versions while maintaining platform-specific binary compatibility.

### Key Extras Definitions

## Dependency Resolution and Locking (raydepsets)

 Ray uses a specialized dependency management system called `raydepsets` to generate reproducible lock files via `uv`.

 
### The raydepsets System

 `raydepsets` is a CLI tool [ci/raydepsets/cli.py30-34](https://github.com/ray-project/ray/blob/bf129559/ci/raydepsets/cli.py#L30-L34) that manages dependency sets defined in YAML configuration files. It supports operations like `compile` (resolving transitive dependencies), `subset` (filtering a larger set), and `expand` (adding new requirements to an existing set) [ci/raydepsets/cli.py175-199](https://github.com/ray-project/ray/blob/bf129559/ci/raydepsets/cli.py#L175-L199)

 
```

```

 **Key Components:**

 
 - **DependencySetManager** [ci/raydepsets/cli.py91-119](https://github.com/ray-project/ray/blob/bf129559/ci/raydepsets/cli.py#L91-L119): Orchestrates the build process, loading configs and building a `DiGraph` of dependencies.
 - **UV Integration** [ci/raydepsets/cli.py114-115](https://github.com/ray-project/ray/blob/bf129559/ci/raydepsets/cli.py#L114-L115): Uses the `uv` binary for high-performance dependency resolution.
 - **Topological Sorting** [ci/raydepsets/cli.py124-127](https://github.com/ray-project/ray/blob/bf129559/ci/raydepsets/cli.py#L124-L127): Ensures that base dependency sets are compiled before the sets that depend on them.
 - **Default Flags** [ci/raydepsets/cli.py19-27](https://github.com/ray-project/ray/blob/bf129559/ci/raydepsets/cli.py#L19-L27): Uses `--generate-hashes` and `--index-strategy unsafe-best-match` to ensure secure and flexible package resolution.

## Vendoring Strategy

 Ray vendors specific third-party packages directly into the wheel to ensure availability and avoid runtime installation issues.

 
### Vendored Locations

 
 - **`ray/thirdparty_files/`** [python/setup.py38](https://github.com/ray-project/ray/blob/bf129559/python/setup.py#L38-L38): Contains core utilities like `psutil` and `colorama` [python/setup.py555](https://github.com/ray-project/ray/blob/bf129559/python/setup.py#L555-L555)
 - **`ray/_private/runtime_env/agent/thirdparty_files/`** [python/setup.py39-41](https://github.com/ray-project/ray/blob/bf129559/python/setup.py#L39-L41): Contains `aiohttp` for the Runtime Environment agent [python/setup.py570](https://github.com/ray-project/ray/blob/bf129559/python/setup.py#L570-L570)
 
 The build process uses `pip install --target` [python/setup.py556-567](https://github.com/ray-project/ray/blob/bf129559/python/setup.py#L556-L567) to populate these directories before wheel assembly.

## GPU/CUDA Environment Provisioning

 The `ray-llm` Docker image provides a specialized environment for high-performance LLM serving, specifically integrating `vLLM` and hardware-accelerated kernels.

 
### LLM Docker Provisioning Flow

 
```

```

 **Key Implementation Details:**

 
 - **Lock Selection** [docker/ray-llm/Dockerfile18-28](https://github.com/ray-project/ray/blob/bf129559/docker/ray-llm/Dockerfile#L18-L28): Selects the correct lock file based on Python version. `ray-llm` currently supports Python 3.12 only, using `cu130` locks [docker/ray-llm/Dockerfile20-21](https://github.com/ray-project/ray/blob/bf129559/docker/ray-llm/Dockerfile#L20-L21)

## Build System Integration (Bazel & setup.py)

| Target | Purpose |
