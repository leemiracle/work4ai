These examples demonstrate how to implement and train various reinforcement learning algorithms on the classic Atari 2600 games using both the procedural API and high-level API of Tianshou.

 
## Overview

 The Atari examples showcase implementations of popular reinforcement learning algorithms for solving Atari games using pixel observations. They serve as practical demonstrations of how to use Tianshou for training agents in complex visual environments.

## Environment Setup

 The Atari examples use the OpenAI Gym (now Gymnasium) Atari environments with custom wrappers to preprocess observations and make the environments suitable for reinforcement learning.

 
### Atari Environment Wrapper Structure

 
```

```

 Sources: [examples/atari/atari_wrapper.py](https://github.com/thu-ml/tianshou/blob/90846f6b/examples/atari/atari_wrapper.py)

 The environment setup process includes:

 
 - **NoopResetEnv**: Performs a random number of no-ops at the start of each episode to provide stochasticity.
 - **MaxAndSkipEnv**: Applies frame skipping and returns the maximum pixel value over the skipped frames.
 - **EpisodicLifeEnv**: Treats losing a life as the end of an episode, but only for training.
 - **FireResetEnv**: Presses the FIRE button to start games that require it.
 - **WarpFrame**: Resizes observations to 84x84 and converts them to grayscale.
 - **ClipRewardEnv**: Clips rewards to {-1, 0, 1} to improve stability.
 - **FrameStack**: Stacks the specified number of frames to capture temporal information.
 
 For high-level API examples, the `AtariEnvFactory` class encapsulates this environment creation logic.

 
## Network Architecture

 The examples use various convolutional neural network architectures based on the requirements of different algorithms.

 
### DQN Network Architecture

 
```

```

 Sources: [examples/atari/atari_network.py](https://github.com/thu-ml/tianshou/blob/90846f6b/examples/atari/atari_network.py)

 For value-based methods like DQN, a CNN processes the stacked frames to output Q-values for each action. The network architecture typically consists of:

 
 - Three convolutional layers with ReLU activations
 - A flatten operation
 - A fully connected layer to output action values
 
 For distributional algorithms (C51, QR-DQN, IQN), the architecture is extended to output distributions over values rather than single value estimates.

## Training Process

 The training process in the Atari examples follows a common pattern regardless of the algorithm used:

 
```

```

 Sources: [examples/atari/atari_dqn.py234-255](https://github.com/thu-ml/tianshou/blob/90846f6b/examples/atari/atari_dqn.py#L234-L255) [examples/atari/atari_ppo.py264-281](https://github.com/thu-ml/tianshou/blob/90846f6b/examples/atari/atari_ppo.py#L264-L281) [examples/atari/atari_sac.py247-264](https://github.com/thu-ml/tianshou/blob/90846f6b/examples/atari/atari_sac.py#L247-L264)

 The training process includes several key components:

 
 - **Experience Collection**: The `Collector` interacts with the environment using the policy and stores transitions in the replay buffer.
 - **Policy Updates**: The trainer samples batches from the buffer and updates the policy.
 - **Evaluation**: Periodically evaluates the current policy on test environments.
 - **Callbacks**: Various callbacks handle tasks like epsilon decay, logging, and saving checkpoints.

## Running Atari Examples

 
### Required Command-line Arguments

 Most Atari examples support the following key arguments:

 
| Argument | Description | Default |
|---|---|---|
| --task | Name of the Atari game | PongNoFrameskip-v4 |
| --seed | Random seed | 0 |
| --epoch | Number of training epochs | 100 |
| --step-per-epoch | Environment steps per epoch | 100000 |
| --batch-size | Batch size for training | 32/64/256 |
| --training-num | Number of training environments | 10 |
| --test-num | Number of test environments | 10 |
| --frames-stack | Number of frames to stack | 4 |
| --lr | Learning rate | Varies by algorithm |
| --gamma | Discount factor | 0.99 |
| --n-step | N-step return | 3 |

### Logging and Visualization

 The examples support multiple logging backends:

 
 - **TensorBoard** (default): Logs metrics to TensorBoard format
 - **Weights & Biases**: Enabled with `--logger wandb`
 
 The logged metrics include:

 
 - Training rewards
 - Testing rewards
 - Episode lengths
 - Learning rates
 - Exploration parameters (e.g., epsilon)
 - Various algorithm-specific metrics
 
 
## Conclusion

 The Atari examples in Tianshou demonstrate the flexibility and power of the framework for deep reinforcement learning research. They provide ready-to-use implementations of popular algorithms and patterns for both beginners and experienced users, with options for both a detailed procedural API and a more abstracted high-level API.

 For information about other environments such as MuJoCo, see the [Mujoco Examples](https://deepwiki.com/thu-ml/tianshou/8.2-mujoco-examples) page.
