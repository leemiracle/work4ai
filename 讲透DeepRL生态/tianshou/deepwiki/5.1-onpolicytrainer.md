## Purpose and Scope

 The OnpolicyTrainer is a specialized training loop implementation designed specifically for on-policy reinforcement learning algorithms such as PPO, A2C, TRPO, and others. It manages the interaction between the policy, environment, and data collection, implementing the on-policy training paradigm where data is collected, used for updates, and then discarded. For off-policy training methods, see [OffpolicyTrainer](https://deepwiki.com/thu-ml/tianshou/5.2-offpolicytrainer).

 In contrast to off-policy methods which sample mini-batches with replacement from the replay buffer, the OnpolicyTrainer:

 
 - Uses the entire buffer for updates
 - Allows the policy to handle mini-batching internally
 - Resets the buffer after each update (discarding old experiences)
 - Can perform multiple passes over the same data using the `repeat_per_collect` parameter
 
 
## Implementation Details

 The OnpolicyTrainer implementation is relatively concise but has important specific behaviors:

 
 - **Buffer Usage**: The entire buffer is passed to the policy's update method, which is expected to handle the data efficiently, potentially in mini-batches.
 - **Buffer Reset**: After each update, the buffer is reset with `keep_statistics=True`, which means episode-level statistics are retained but individual transitions are discarded.
 - **Gradient Step Tracking**: The trainer keeps track of the gradient steps taken, which is useful for logging and debugging.
 - **Repeat Updates**: On-policy algorithms often perform multiple updates on the same data before collecting new experiences, controlled by the `repeat_per_collect` parameter.

## Configuration Parameters

 The OnpolicyTrainer inherits all parameters from BaseTrainer but pays special attention to:

 
| Parameter | Description | Importance for On-policy Training |
|---|---|---|
| repeat_per_collect | Number of times to update policy on the same data | Critical: controls data efficiency vs. bias trade-off |
| batch_size | Size of mini-batches used during policy update | Important: affects update stability and speed |
| step_per_collect | Number of environment steps to collect before each update | Critical: controls exploration vs. exploitation |
| episode_per_collect | Number of episodes to collect before each update | Alternative to step_per_collect, useful for sparse rewards |

 Sources: [tianshou/trainer/base.py153-237](https://github.com/thu-ml/tianshou/blob/90846f6b/tianshou/trainer/base.py#L153-L237)

 
## Key Differences from Other Trainers

 The OnpolicyTrainer differs from other trainers in several important ways:

 
 - **Complete Buffer Processing**: Unlike OffpolicyTrainer which samples mini-batches with replacement, OnpolicyTrainer passes the entire buffer to the policy.
 - **Buffer Reset**: After each update, the buffer is cleared, implementing the on-policy paradigm where old experiences are discarded.
 - **Repeated Learning**: On-policy algorithms often perform multiple updates on the same data, controlled by `repeat_per_collect`.
 - **Mini-batch Handling**: The mini-batching is done internally by the policy's update method, not by the trainer.
