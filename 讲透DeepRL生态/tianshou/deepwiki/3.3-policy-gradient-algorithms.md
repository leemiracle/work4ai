  This page documents the policy gradient algorithms implemented in Tianshou. Policy gradient methods are a family of reinforcement learning algorithms that directly optimize the policy by following the gradient of expected return. This page covers the base policy gradient algorithm (REINFORCE), Advantage Actor-Critic (A2C), and Proximal Policy Optimization (PPO). For actor-critic algorithms that don't fall strictly in the policy gradient family, see [Actor-Critic Algorithms](https://deepwiki.com/thu-ml/tianshou/3.4-actor-critic-algorithms).

## REINFORCE (Vanilla Policy Gradient)

 REINFORCE is the most basic policy gradient algorithm. It updates the policy parameters in the direction of the gradient of expected return.

 
### Key Features

 
 - Uses Monte Carlo sampling to estimate returns
 - Updates directly based on return-weighted log probabilities
 - Simple but can have high variance in gradients
 
 
### Implementation Details

 In Tianshou, REINFORCE is implemented in the `PGPolicy` class:

 
```

```

 The core implementation of REINFORCE is in the `learn` method of `PGPolicy`:

 
 - Forward pass through the policy network to get action distributions
 - Calculate log probabilities of the actions taken
 - Weight log probabilities by the returns
 - Optimize the policy to maximize expected returns
 
 
```

```

 The policy gradient update is simply: `-∇θ (log π(a|s) * G)` where G is the return.

 Sources: [tianshou/policy/modelfree/pg.py210-235](https://github.com/thu-ml/tianshou/blob/90846f6b/tianshou/policy/modelfree/pg.py#L210-L235)

 
## Advantage Actor-Critic (A2C)

 A2C improves upon REINFORCE by using a value function (critic) to reduce variance in the gradient estimates.

 
### Key Features

 
 - Uses an actor (policy) and critic (value function)
 - Employs advantages instead of raw returns
 - Supports Generalized Advantage Estimation (GAE)
 - Includes entropy regularization
 
 
### Implementation Details

 A2C is implemented in the `A2CPolicy` class, which inherits from `PGPolicy`:

 
```

```

 The key improvements in A2C include:

 
 - **Advantage estimation**: Using `A(s,a) = Q(s,a) - V(s)` to reduce variance
 - **Value function learning**: Training a critic to estimate state values
 - **Entropy regularization**: Encouraging exploration by maximizing policy entropy

## Proximal Policy Optimization (PPO)

 PPO further improves A2C by using a clipped surrogate objective to ensure stable policy updates, preventing too large policy changes in a single update.

 
### Key Features

 
 - Clip probability ratio to constrain policy updates
 - Multiple optimization epochs per data collection
 - Optional value function clipping
 - Advantage normalization
 
 
### Implementation Details

 PPO is implemented in the `PPOPolicy` class, which inherits from `A2CPolicy`:

 PPO has several advanced features:

 
 - **Clipped surrogate objective**: Prevents too large policy updates
 - **Multiple epochs**: Performs multiple optimization passes over the same data
 - **Value clipping**: Optionally clips value function updates
 - **Advantage normalization**: Normalizes advantages for more stable training
 - **Dual clipping**: An extension to handle negative advantages better

## Common Parameters and Their Effects

 
| Parameter | Description | Typical Values | Effect |
|---|---|---|---|
| discount_factor (γ) | Discount factor for future rewards | 0.9-0.999 | Higher values make agent consider longer time horizons |
| gae_lambda (λ) | GAE parameter for advantage estimation | 0.9-0.98 | Controls bias-variance tradeoff in advantage estimation |
| vf_coef | Value function loss coefficient | 0.25-1.0 | Weights importance of value function accuracy |
| ent_coef | Entropy bonus coefficient | 0.0-0.01 | Encourages exploration; higher values increase exploration |
| eps_clip (PPO) | Clipping range for probability ratio | 0.1-0.3 | Limits policy update size; smaller values are more conservative |
| max_grad_norm | Gradient norm clipping | 0.5-1.0 | Prevents exploding gradients |
| reward_normalization | Whether to normalize returns | True/False | Can stabilize training but may affect performance |
| advantage_normalization (PPO) | Whether to normalize advantages | True/False | Stabilizes updates but may introduce bias |
| repeat_per_collect | Training iterations per data collection | 5-20 | Higher values extract more from each batch of experience |

## Performance Considerations

 
### PPO Optimization Parameters

 PPO's performance is highly sensitive to its hyperparameters:

 
 - **Clip Range** (`eps_clip`): Smaller values (0.1-0.2) result in more conservative updates but may slow learning
 - **Normalization**: Both advantage and observation normalization significantly impact stability
 - **Batch Size**: Larger batches provide more reliable gradient estimates but require more memory
 - **Learning Rate**: Often requires careful tuning and scheduling for best performance
 
 
### Value Function Training

 In A2C and PPO, value function accuracy is crucial:

 
 - **Value Coefficient** (`vf_coef`): Balances policy vs value function learning
 - **Value Clipping** (PPO): Keeps value predictions from changing too rapidly
 - **Multiple Value Iterations**: In PPO, you can optionally perform more critic updates per actor update

## Extending Policy Gradient Algorithms

 To implement a new policy gradient algorithm in Tianshou, you would typically:

 
 - Choose an appropriate base class to inherit from (`BasePolicy`, `PGPolicy`, `A2CPolicy`)
 - Override the `learn` method to implement your learning algorithm
 - Optionally override `process_fn` if you need custom data processing
 - Implement any additional methods or features specific to your algorithm
 
 The most important methods to understand are:

 
 - `process_fn`: Prepares data from the replay buffer for learning
 - `learn`: Updates the policy based on the processed data
 - `forward`: Computes actions from observations
