  The ReplayBuffer in Tianshou is a specialized data structure that stores transitions from agent-environment interactions for reinforcement learning algorithms. It serves as a fundamental component in the [Data Handling System](https://deepwiki.com/thu-ml/tianshou/2-data-handling-system) by efficiently collecting, storing, and sampling experience data.

 For information about collecting data from environments, see the [Collector](https://deepwiki.com/thu-ml/tianshou/2.3-collector) documentation.

 
## Overview and Purpose

 The ReplayBuffer manages agent experiences in a circular queue format, providing stable and efficient sampling. This helps address several challenges in reinforcement learning:

 
 - **Sample Efficiency**: Allows reusing past experiences multiple times for training
 - **Decorrelation**: Breaks temporal correlations in sequential data by random sampling
 - **Stable Learning**: Enables mini-batch training with diverse experiences

## Core ReplayBuffer

 The base ReplayBuffer is a circular buffer that stores experiences in the form of transitions. Each transition includes:

 
 - Observation (`obs`)
 - Action (`act`)
 - Reward (`rew`)
 - Next observation (`obs_next`)
 - Terminal state flags (`terminated`, `truncated`, `done`)
 - Additional information (`info`)
 
 
### Key Attributes and Parameters

 
| Parameter | Type | Default | Description |
|---|---|---|---|
| size | int | - | Maximum buffer capacity |
| stack_num | int | 1 | Number of frames to stack (for frame-stacking) |
| ignore_obs_next | bool | False | Whether to not store next observations |
| save_only_last_obs | bool | False | Only save last observation when temporal stacking |
| sample_avail | bool | False | Sample only available indices with frame-stacking |

 
### Internal Data Structure

 ReplayBuffer uses a Batch object internally to store all transitions. The implementation uses a circular buffer approach, where once the buffer is full, new transitions overwrite the oldest ones.

## Specialized ReplayBuffers

 
### Prioritized Experience Replay

 `PrioritizedReplayBuffer` implements prioritized experience replay, where transitions are sampled based on their TD error or other priority measures.

 Key features:

 
 - Maintains a priority weight for each transition
 - Uses a Segment Tree data structure for efficient sampling
 - Has tunable parameters `alpha` (prioritization exponent) and `beta` (importance sampling coefficient)

### Hindsight Experience Replay (HER)

 `HERReplayBuffer` is designed for goal-based environments, where it retroactively changes the goal of an episode to make failed attempts successful for learning.

 Key features:

 
 - Works with goal-based environments (observations with `achieved_goal` and `desired_goal`)
 - Implements the "future" strategy from the HER paper
 - Recomputes rewards based on the new goals

### Vector Replay Buffer

 `VectorReplayBuffer` manages multiple separate replay buffers, typically one for each environment in vectorized training.

 Key features:

 
 - Maintains multiple buffers with a shared interface
 - Supports adding transitions to specific buffers
 - Samples proportionally from all buffers

## Integration with Training Loop

 In the typical Tianshou training workflow, the ReplayBuffer bridges the data collection and policy update steps:

 
 - The Collector interacts with the environment and stores transitions in the ReplayBuffer
 - The training loop samples batches from the ReplayBuffer
 - The policy is updated using the sampled batches
 - For prioritized replay, priorities are updated based on the TD error
 
 This design enables efficient experience collection and reuse, which is crucial for sample-efficient reinforcement learning.
