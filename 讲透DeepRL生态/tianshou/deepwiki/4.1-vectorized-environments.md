## Purpose and Scope

 This document describes Tianshou's vectorized environment system, which enables parallel execution of multiple environments simultaneously. This is essential for modern reinforcement learning algorithms to efficiently collect experience data. The vectorized environment system handles the management of multiple environment instances, their synchronization, and communication with the agent.

 This page covers the core components of the vectorized environment system, including the base class, different implementations (sequential, parallel, distributed), environment workers, and wrappers. For information about environment wrappers that modify environment behavior, see [Environment Wrappers](https://deepwiki.com/thu-ml/tianshou/4.2-environment-wrappers).

 
## Overview and Architecture

 Vectorized environments in Tianshou allow running multiple environment instances in parallel, greatly increasing the throughput of interaction data collection. This parallelization can be achieved through different mechanisms: in-process sequential execution, multiprocessing, shared memory, or distributed execution via Ray.

## Core Components

 
### BaseVectorEnv

 The `BaseVectorEnv` class serves as the foundation for all vectorized environment implementations. It manages a collection of environment workers and provides a unified interface for interacting with multiple environments simultaneously.

 Key functionality:

 
 - Manage environment workers
 - Reset environments (all or specific ones)
 - Step environments with vectorized actions
 - Support both synchronous and asynchronous execution

## Performance Considerations

 The choice of vectorized environment implementation depends on specific use cases:

 
| Implementation | Use Case | Pros | Cons |
|---|---|---|---|
| DummyVectorEnv | Testing, debugging | Simple, predictable | No parallelism |
| SubprocVectorEnv | General use | True parallelism | IPC overhead |
| ShmemVectorEnv | Large observations | Efficient data transfer | Setup complexity |
| RayVectorEnv | Distributed training | Scales across machines | Requires Ray setup |

 Sources: [tianshou/env/venvs.py365-473](https://github.com/thu-ml/tianshou/blob/90846f6b/tianshou/env/venvs.py#L365-L473)

 
## Best Practices

 
 - For most single-machine setups, `ShmemVectorEnv` provides the best balance of simplicity and performance.
 - Use asynchronous execution (`wait_num` < total environments) when environments have variable step times.
 - Consider observation normalization (`VectorEnvNormObs`) for environments with varying scales.
 - For very large-scale training, `RayVectorEnv` can distribute environments across multiple machines.
 - When debugging, `DummyVectorEnv` provides deterministic, sequential execution.
