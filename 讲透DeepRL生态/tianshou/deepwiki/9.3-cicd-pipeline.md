## Purpose and Scope

 This document details the Continuous Integration and Continuous Deployment (CI/CD) pipeline used in the Tianshou reinforcement learning framework. It explains how automated testing, code quality checking, and documentation building are implemented to maintain code quality and reliability. For information about the testing framework itself, see [Testing Framework](https://deepwiki.com/thu-ml/tianshou/9.2-testing-framework).

 
## Pipeline Overview

 Tianshou employs GitHub Actions to implement its CI/CD pipeline. The pipeline automatically runs tests and quality checks whenever code changes are pushed or pull requests are created. This ensures all contributions maintain the project's quality standards.

## CI/CD Components

 The pipeline consists of four main workflows, each defined in a separate YAML file:

 
| Workflow | File | Purpose |
|---|---|---|
| Ubuntu Tests | pytest.yml | Main test suite on Ubuntu with coverage reporting |
| Windows/MacOS Tests | extra_sys.yml | Cross-platform compatibility testing |
| GPU Tests | gputest.yml | Tests requiring GPU acceleration |
| Code Quality & Docs | lint_and_docs.yml | Linting, type checking, and documentation building |

 All workflows are triggered on pull requests to the master branch, pushes to the master branch, and manual triggers (workflow_dispatch). They can be skipped by including "ci skip" in the commit message.

### Ubuntu Tests (Main Workflow)

 The main test workflow runs on Ubuntu with Python 3.11. It:

 
 - Sets up the Python environment
 - Installs dependencies via Poetry
 - Runs the full test suite with pytest
 - Uploads coverage to Codecov
 
 This workflow is defined in the `pytest.yml` file and installs the project with "envpool" and "eval" extras.

 Sources: [.github/workflows/pytest.yml19-67](https://github.com/thu-ml/tianshou/blob/90846f6b/.github/workflows/pytest.yml#L19-L67)

 
### Windows/MacOS Tests

 This workflow ensures cross-platform compatibility by running on both Windows and macOS with Python 3.11. It:

 
 - Uses a matrix strategy to run on both operating systems
 - Runs a reduced test suite (via `poe test-reduced`)
 - Handles potential Poetry installation issues with retries
 
 The reduced test suite accommodates platform-specific limitations.

 Sources: [.github/workflows/extra_sys.yml18-57](https://github.com/thu-ml/tianshou/blob/90846f6b/.github/workflows/extra_sys.yml#L18-L57)

 
### GPU Tests

 The GPU test workflow runs on self-hosted runners that have GPU capabilities. It:

 
 - Uses a self-hosted runner with Linux and X64 architecture
 - Installs the project with the "envpool" extra
 - Runs the full test suite, utilizing GPU acceleration where applicable
 
 Sources: [.github/workflows/gputest.yml19-55](https://github.com/thu-ml/tianshou/blob/90846f6b/.github/workflows/gputest.yml#L19-L55)

 
### Code Quality and Documentation

 This workflow enforces code quality standards and ensures documentation builds properly. It:

 
 - Runs linting checks via `poe lint`
 - Performs type checking via `poe type-check`
 - Builds documentation via `poe doc-build`
 
 These checks help maintain code quality and keep documentation up-to-date.

 Sources: [.github/workflows/lint_and_docs.yml19-54](https://github.com/thu-ml/tianshou/blob/90846f6b/.github/workflows/lint_and_docs.yml#L19-L54)

 
## Dependency Management

 Tianshou uses Poetry for dependency management in its CI/CD pipeline. The workflow:

 
 - Installs Poetry using the `abatilo/actions-poetry@v2` action
 - Configures Poetry to use local virtual environments
 - Caches the virtual environment based on the poetry.lock file hash
 - Installs dependencies with appropriate extras for each workflow

## Poetry Commands

 The workflows use Poetry's run command with custom scripts defined as "poe" tasks:

 
| Command | Purpose | Used In |
|---|---|---|
| poetry run poe test | Run full test suite | Ubuntu and GPU workflows |
| poetry run poe test-reduced | Run reduced test suite | Windows/MacOS workflow |
| poetry run poe lint | Run linting checks | Lint & Docs workflow |
| poetry run poe type-check | Perform type checking | Lint & Docs workflow |
| poetry run poe doc-build | Build documentation | Lint & Docs workflow |

 These commands are likely defined in a `pyproject.toml` file as Poe-the-Poet tasks for convenient execution of common development operations.
