## Purpose and Scope

 This document explains the Builder Pattern implementation in Tianshou's high-level API. The Builder Pattern is used to simplify the creation of complex reinforcement learning experiments by providing a fluent, readable interface for configuring numerous components. This page covers the architecture of experiment builders, how they're used to construct experiments, and how to customize various aspects of the experimental setup.

 For information about the overall High-Level API, see [High-Level API](https://deepwiki.com/thu-ml/tianshou/6-high-level-api). For Agent and Environment Factories, see [Agent and Environment Factories](https://deepwiki.com/thu-ml/tianshou/6.3-agent-and-environment-factories).

 
## Overview of the Builder Pattern in Tianshou

 The Builder Pattern in Tianshou allows users to create complex reinforcement learning experiments with chainable method calls that make the code more readable and maintainable. It separates the construction logic (how components are created and connected) from the representation (the actual experiment objects), enabling algorithm-specific configuration through specialized builders.

### Core Components

 
 - **ExperimentBuilder (Abstract Base Class)**

 
 - Provides the foundation for all builders
 - Manages common configuration parameters
 - Defines the interface for customization through `with_*` methods
 - **Builder Mixins**

 
 - `_BuilderMixinActorFactory`: Adds actor creation capabilities
 - `_BuilderMixinCriticsFactory`: Adds critic creation capabilities
 - Specialized variants for different actor/critic types
 - **Algorithm-Specific Builders**

 
 - Inherit from `ExperimentBuilder` and appropriate mixins
 - Implement algorithm-specific configuration methods
 - Override `_create_agent_factory()` to create the appropriate agent
 - **Agent Factories**

 
 - Created by builders to handle the construction of policy objects
 - Implement algorithm-specific logic for creating policies and trainers

## Benefits of the Builder Pattern in Tianshou

 
 - **Readability**: Method chaining creates readable, declarative code for experiment setup
 - **Modularity**: Separates complex component creation from the experiment representation
 - **Flexibility**: Allows for different configuration approaches for different algorithms
 - **Reusability**: Common configuration logic is abstracted into the base builder
 - **Consistency**: Ensures all necessary components are properly configured

## Conclusion

 The Builder Pattern in Tianshou provides a clean, flexible way to create complex reinforcement learning experiments. By using a fluent interface with method chaining, it simplifies the process of configuring the many components needed for an RL experiment while keeping the code readable and maintainable. The pattern is particularly valuable in this domain where experiments have many configurable parts and algorithm-specific requirements.
