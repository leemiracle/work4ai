## Purpose and Scope

 This document details the common neural network components provided by Tianshou as building blocks for reinforcement learning algorithms. These components serve as the foundation for creating policy and value networks used in various RL algorithms. This page focuses on the base network architectures in Tianshou, such as MLPs and recurrent networks, while specialized actor-critic architectures are covered in [Actor-Critic Networks](https://deepwiki.com/thu-ml/tianshou/7.2-actor-critic-networks).

### Net

 The `Net` class is a wrapper around `MLP` that provides additional functionality for reinforcement learning tasks, such as support for distributional RL and dueling network architectures.

 Key features of `Net`:

 
 - Support for concatenating state and action inputs
 - Optional softmax output layer
 - Support for dueling network architecture (separate value and advantage streams)
 - Support for distributional RL (multiple atoms)

### DataParallelNet

 The `DataParallelNet` class is a wrapper that enables multi-GPU training by distributing network computation across multiple GPUs using PyTorch's `nn.DataParallel`.

 Key features:

 
 - Transparent handling of numpy arrays and torch tensors
 - Automatic conversion to CUDA tensors
 - Compatible with Tianshou's network interface

### EnsembleLinear

 The `EnsembleLinear` class implements a linear layer for ensemble networks, which are used in some model-based RL algorithms.

 Key features:

 
 - Maintains multiple sets of weights for ensemble members
 - Compatible with PyTorch's module interface
 - Efficient parallel computation of ensemble outputs

## Actor Implementations

 
### BaseActor

 The `BaseActor` class is an abstract base class that defines the interface for actor networks in Tianshou.

 Key methods:

 
 - `get_preprocess_net()`: Returns the preprocessing network
 - `get_output_dim()`: Returns the output dimension
 - `forward()`: Implements the forward pass for action selection
 
 Sources: [tianshou/utils/net/common.py616-632](https://github.com/thu-ml/tianshou/blob/90846f6b/tianshou/utils/net/common.py#L616-L632)

 
### RandomActor

 The `RandomActor` class is a simple implementation of `BaseActor` that returns random actions. It's useful for exploration or as a baseline.

 Key features:

 
 - Support for both discrete and continuous action spaces
 - Uniform sampling from the action space
 - Compatible with Tianshou's policy interface
 
 Sources: [tianshou/utils/net/common.py637-688](https://github.com/thu-ml/tianshou/blob/90846f6b/tianshou/utils/net/common.py#L637-L688)

## Integration with the Policy Framework

 The network components in Tianshou are designed to be integrated with the policy framework. Here's how they typically fit into the larger system:

 
```

```

 Key points:

 
 - `MLP` and `Net` serve as the base feature extractors
 - Specialized actor and critic networks build upon these base classes
 - Policy implementations combine actors and critics as needed
 - Networks handle state processing and action generation
 - Policies handle the learning and update logic

## Specialized Networks and Customization

 Tianshou provides several specialized network implementations for specific algorithms:

 
| Network Class | Purpose | File Location |
|---|---|---|
| CosineEmbeddingNetwork | Embeds scalar values for IQN | discrete.py |
| ImplicitQuantileNetwork | Implements Implicit Quantile Networks | discrete.py |
| FractionProposalNetwork | Proposes fractions for FQF | discrete.py |
| FullQuantileFunction | Implements Fully parameterized Quantile Function | discrete.py |
| NoisyLinear | Implements noisy networks for exploration | discrete.py |
| IntrinsicCuriosityModule | Implements intrinsic curiosity module | discrete.py |
| ActorProb | Probabilistic actor for SAC, PPO, etc. | continuous.py |
| Perturbation | Perturbation network for BCQ algorithm | continuous.py |
| VAE | VAE for modeling action distributions in BCQ | continuous.py |

 Users can extend these base classes or create custom network architectures by:

 
 - Inheriting from `NetBase` or `nn.Module`
 - Implementing the required interface methods
 - Integrating with the policy framework
