## Purpose and Scope

 This document describes the Agent and Environment Factories in Tianshou's high-level API. These factories are responsible for creating agent policies and environments, respectively, and are key components used by the Experiment framework. They abstract away the complexity of initializing reinforcement learning components, enabling users to easily configure and run experiments without dealing with low-level implementation details.

 For information about the overall Experiment framework, see [Experiment Framework](https://deepwiki.com/thu-ml/tianshou/6.1-experiment-framework), and for details on the Builder pattern used with these factories, see [Builder Pattern](https://deepwiki.com/thu-ml/tianshou/6.2-builder-pattern).

### Key Concepts in AgentFactory

 
 - **SamplingConfig**: Contains parameters for controlling replay buffer size, batch size, and other sampling-related configurations
 - **OptimizerFactory**: Configures the optimization algorithm used for training
 - **Policy Wrappers**: Allows the original policy to be extended with additional functionality
 
 
### Core Methods

 
 - **create_train_test_collector**

 
 - Creates collectors for gathering samples during training and testing
 - Configures the replay buffer based on sampling configuration
 - **create_policy**

 
 - Creates the specific policy (agent) implementation based on the algorithm
 - Applies any specified policy wrappers
 - **create_trainer**

 
 - Creates a trainer appropriate for the policy type (on-policy or off-policy)
 - Configures callbacks for epoch events

### Agent Factory Types

 There are two main categories of agent factories:

 
 - **OnPolicyAgentFactory**

 
 - Used for on-policy algorithms like PG, A2C, PPO
 - Creates an `OnpolicyTrainer` with appropriate configuration
 - **OffPolicyAgentFactory**

 
 - Used for off-policy algorithms like DQN, DDPG, SAC
 - Creates an `OffpolicyTrainer` with appropriate configuration
 
 Each specific algorithm has its own factory implementation, which configures the policy with algorithm-specific parameters.

### EnvFactoryRegistered

 `EnvFactoryRegistered` is a concrete implementation of `EnvFactory` for environments registered with Gymnasium. It provides a convenient way to create environments by their registered name.

 Key features:

 
 - Creates environments using `gymnasium.make`
 - Supports environment creation with EnvPool for improved performance
 - Configures environment seeds and render modes based on the environment mode
 
 Sources:

 
 - [tianshou/highlevel/env.py417-501](https://github.com/thu-ml/tianshou/blob/90846f6b/tianshou/highlevel/env.py#L417-L501)
 
 
### Domain-Specific Environment Factories

 The codebase includes examples of domain-specific environment factories:

 
 - **MujocoEnvFactory**: For continuous control environments

 
 - Extends `EnvFactoryRegistered`
 - Adds observation normalization
 - Includes persistence for observation normalization statistics
 - **AtariEnvFactory**: For Atari game environments

 
 - Extends `EnvFactoryRegistered`
 - Applies Atari-specific wrappers like frame skipping and stacking
 - Supports EnvPool for improved performance

## Summary

 Agent and Environment Factories are essential components of Tianshou's high-level API that:

 
 - Abstract away the complexity of creating RL components
 - Provide a consistent interface for different algorithms and environments
 - Enable flexible configuration of experiments
 - Support extension for custom algorithms and environments
 
 The factory pattern allows for clear separation of concerns and makes the code more modular and maintainable. When combined with the Experiment and ExperimentBuilder classes, they provide a powerful and flexible way to set up and run reinforcement learning experiments.
