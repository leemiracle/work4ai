  This document covers ChainerRL's training infrastructure, which orchestrates the interaction between agents, environments, and evaluation systems during the learning process. The training systems provide three main paradigms: single-environment training, batch/vectorized training, and asynchronous multi-process training.

 For information about specific RL agents and their algorithms, see [Reinforcement Learning Agents](https://deepwiki.com/chainer/chainerrl/2-reinforcement-learning-agents). For details about evaluation metrics and performance measurement, see [Training and Evaluation Infrastructure](https://deepwiki.com/chainer/chainerrl/4-training-and-evaluation-infrastructure).

## Single Environment Training

 The single environment training system in [chainerrl/experiments/train_agent.py](https://github.com/chainer/chainerrl/blob/7eed3756/chainerrl/experiments/train_agent.py) provides sequential interaction between an agent and a single environment instance. This is the simplest training paradigm and is suitable for debugging and small-scale experiments.

 
### Core Training Function

 The `train_agent` function [chainerrl/experiments/train_agent.py22-84](https://github.com/chainer/chainerrl/blob/7eed3756/chainerrl/experiments/train_agent.py#L22-L84) implements the basic training loop:

 
| Parameter | Type | Purpose |
|---|---|---|
| agent | Agent | The RL agent to train |
| env | Environment | Single environment instance |
| steps | int | Total training timesteps |
| outdir | str | Output directory for logs and models |
| checkpoint_freq | int | Frequency for saving checkpoints |
| max_episode_len | int | Maximum episode length |
| evaluator | Evaluator | Optional evaluation system |

 The training loop follows this sequence:

 
 - Get action from agent: `action = agent.act_and_train(obs, r)`
 - Step environment: `obs, r, done, info = env.step(action)`
 - Handle episode termination: `agent.stop_episode_and_train(obs, r, done=done)`
 - Periodic evaluation and checkpointing
 
 
### Training with Evaluation

 The `train_agent_with_evaluation` function [chainerrl/experiments/train_agent.py87-160](https://github.com/chainer/chainerrl/blob/7eed3756/chainerrl/experiments/train_agent.py#L87-L160) wraps the basic training with built-in evaluation using the `Evaluator` class. It creates an `Evaluator` instance and passes it to `train_agent`.

## Batch Training

 The batch training system in [chainerrl/experiments/train_agent_batch.py](https://github.com/chainer/chainerrl/blob/7eed3756/chainerrl/experiments/train_agent_batch.py) enables training with vectorized environments, allowing multiple environment instances to run in parallel and agents to process batches of observations efficiently.

 Key differences from single-environment training:

 
 - Uses `agent.batch_act_and_train(obss)` instead of `agent.act_and_train(obs, r)`
 - Processes arrays of observations, rewards, and done flags
 - Handles selective environment resets with `env.reset(not_end)`
 - Tracks multiple episodes simultaneously
 
 
### Batch Training Data Structures

 The batch training loop maintains several NumPy arrays to track state across multiple environments [chainerrl/experiments/train_agent_batch.py42-49](https://github.com/chainer/chainerrl/blob/7eed3756/chainerrl/experiments/train_agent_batch.py#L42-L49):

 
| Variable | Shape | Purpose |
|---|---|---|
| episode_r | (num_envs,) | Cumulative reward per environment |
| episode_idx | (num_envs,) | Episode index per environment |
| episode_len | (num_envs,) | Current episode length per environment |
| obss | (num_envs, obs_shape) | Current observations |
| rs | (num_envs,) | Current rewards |

### Shared Object Management

 The asynchronous system uses two key functions for managing shared state:

 
 - `extract_shared_objects_from_agent(agent)` [chainerrl/experiments/train_agent_async.py112-114](https://github.com/chainer/chainerrl/blob/7eed3756/chainerrl/experiments/train_agent_async.py#L112-L114) - Extracts shareable attributes from an agent

### Training Loop Process

 Each process runs the `train_loop` function [chainerrl/experiments/train_agent_async.py10-110](https://github.com/chainer/chainerrl/blob/7eed3756/chainerrl/experiments/train_agent_async.py#L10-L110) which:

 
 - Maintains local episode state
 - Updates global counters with locks
 - Coordinates evaluation through `AsyncEvaluator`
 - Handles early termination when success criteria are met

## Evaluation Infrastructure

 The evaluation infrastructure provides systematic performance measurement during training through two main classes in [chainerrl/experiments/evaluator.py](https://github.com/chainer/chainerrl/blob/7eed3756/chainerrl/experiments/evaluator.py)

 
### Evaluator Class

 The `Evaluator` class [chainerrl/experiments/evaluator.py269-354](https://github.com/chainer/chainerrl/blob/7eed3756/chainerrl/experiments/evaluator.py#L269-L354) handles synchronous evaluation for single and batch training:

 
| Method | Purpose |
|---|---|
| evaluate_if_necessary(t, episodes) | Checks if evaluation should run based on interval |
| evaluate_and_update_max_score(t, episodes) | Runs evaluation and updates best score |
| save_agent(agent, "best", outdir, logger) | Saves best-performing agent |

## Integration with Agents

 Different agent types integrate with the training systems through specific interfaces:

 
### Batch-Compatible Agents

 Agents like `A2C` [chainerrl/agents/a2c.py48-301](https://github.com/chainer/chainerrl/blob/7eed3756/chainerrl/agents/a2c.py#L48-L301) implement batch training methods:

 
 - `batch_act_and_train(batch_obs)` - Process batch of observations and return actions
 - `batch_observe_and_train(batch_obs, batch_reward, batch_done, batch_reset)` - Learn from batch of transitions
 
 
### Training System Selection

 The choice of training system depends on agent capabilities:

 
| Agent Type | Single Training | Batch Training | Async Training |
|---|---|---|---|
| Standard agents | ✓ | ✗ | ✓ |
| Batch agents (A2C, etc.) | ✗ | ✓ | ✗ |
| Async agents (A3C, etc.) | ✗ | ✗ | ✓ |
