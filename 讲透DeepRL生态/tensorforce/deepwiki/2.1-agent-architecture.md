## Agent Class Hierarchy

 The Tensorforce framework uses a structured class hierarchy for its agent system. At the top level, the `Agent` abstract base class defines the common interface for all agents. The `TensorforceAgent` extends this with a configurable architecture based on the `TensorforceModel`. Specific agent implementations like PPO, DQN, and others inherit from `TensorforceAgent`.

## Core Components of the Agent Architecture

 An agent in Tensorforce is composed of several key components that work together to implement reinforcement learning algorithms:

 
```

```

 
 - **Model**: The central component that orchestrates learning and decision making
 - **Policy**: Determines action selection based on the current state
 - **Baseline/Critic**: Optional component for value estimation (useful for advantage-based methods)
 - **Memory**: Stores experiences for batch updates
 - **Optimizer**: Performs parameter updates to improve the policy
 - **Reward Estimation**: Processes rewards into returns/advantages for learning

## Agent-Environment Interaction

 The agent interacts with the environment through a well-defined interface:

 
```

```

 The core interaction methods are:

 
 - **act()**: Selects actions based on current states
 - **observe()**: Processes feedback (rewards, terminals) from the environment
 - **experience()**: Stores trajectories for learning (in TensorforceAgent)
 - **update()**: Performs policy updates based on stored experiences

## Agent Internals and State Management

 Agents maintain internal states across timesteps, which is particularly important for recurrent policies. The agent provides methods to:

 
 - Get initial internals at the beginning of episodes
 - Pass and update internals during sequential decision-making
 - Reset internals when needed
 
 Parallel interactions allow the agent to simultaneously handle multiple environment instances, with dedicated internal state tracking for each.

## Memory and Experience Storage

 Agents use memory components to store experiences for batch learning:

 
```

```

 The memory workflow:

 
 - Agent buffers collect experiences via the `observe()` method
 - Experiences are transferred to the model's memory
 - The memory provides batches of experience for updates
 - Different memory types (recent, replay, prioritized replay) offer various sampling strategies

## Agent Saving and Loading

 Tensorforce agents support saving and loading of their state, which includes:

 
 - Model parameters
 - Optimizer states
 - Agent configuration
 - Internal counters (timesteps, episodes, updates)
 
 Multiple formats are supported:

 
 - TensorFlow Checkpoint (default)
 - NumPy format
 - HDF5 format
 - SavedModel format (for export only)

## Special Agent Features

 
### Independent Mode

 Agents can operate in independent mode for evaluation or when collecting offline data, where experiences aren't directly stored or used for updates.

 
### Deterministic vs. Stochastic Actions

 Agents can select actions deterministically (e.g., for evaluation) or stochastically (e.g., for exploration during training).

 
### Parallel Interactions

 Agents can handle multiple parallel environment interactions, which is useful for distributed training and vectorized environments.

 
### Action Masking

 Discrete action spaces can have invalid actions masked out during the selection process.

## The Model-Agent Relationship

 The Agent class primarily serves as an interface and coordinator, while the Model handles the actual learning algorithms:

 
```

```

 The Agent handles:

 
 - Interface with the environment
 - Experience buffering
 - Save/load functionality
 - High-level coordination
 
 The Model handles:

 
 - Neural network operations
 - Policy implementation
 - Optimization steps
 - Value estimation

## Summary

 The Tensorforce agent architecture provides a flexible and modular design for implementing reinforcement learning algorithms. The class hierarchy allows for code reuse while enabling algorithm-specific optimizations. The separation between the Agent interface and the underlying Model implementation creates a clean architecture that simplifies the development of new agent types.
