  The Isaac Gym integration system provides comprehensive support for NVIDIA's Isaac Gym physics simulation environments, including Isaac Gym Preview releases, Isaac Lab, and Omniverse Isaac Gym. This system includes specialized environment wrappers, loaders, and utilities for visualization, control, and debugging that enable seamless integration of Isaac Gym-based robotic simulations with **skrl**'s reinforcement learning framework across PyTorch, JAX, and Warp backends.

 For information about environment wrappers that provide unified interfaces to Isaac Gym environments, see [Environment Wrappers](https://deepwiki.com/Toni-SM/skrl/4.1-environment-wrappers). For details about the broader environment integration system, see [Environments](https://deepwiki.com/Toni-SM/skrl/4-environments).

## Isaac Lab Integration

 Isaac Lab environments are integrated using specialized wrappers and loaders that handle the conversion between simulation tensors (typically PyTorch) and the agent's backend (PyTorch, JAX, or Warp).

 
### Isaac Lab Wrapper Implementation

 The `IsaacLabWrapper` normalizes Isaac Lab's dictionary-based observation and action spaces into flattened tensors compatible with RL agents. It supports both single-agent and multi-agent configurations.

 
| Feature | PyTorch Wrapper | JAX Wrapper | Warp Wrapper |
|---|---|---|---|
| Class | IsaacLabWrapper skrl/envs/wrappers/torch/isaaclab_envs.py14 | IsaacLabWrapper skrl/envs/wrappers/jax/isaaclab_envs.py38 | IsaacLabWrapper skrl/envs/wrappers/warp/isaaclab_envs.py15 |
| Data Flow | Direct PyTorch tensors | DLPack conversion (_torch2jax) | Warp-Torch interop (wp.from_torch) |
| Space Handling | flatten_tensorized_space | flatten_tensorized_space | flatten_tensorized_space |
| Device Sync | Same device | Cross-backend (GPU/CPU) | Shared GPU memory |

 
### Multi-Agent Support

 The `IsaacLabMultiAgentWrapper` provides a dictionary-based interface for multi-agent environments, mapping agent UIDs to their respective observation and action tensors [skrl/envs/wrappers/torch/isaaclab_envs.py105-179](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/torch/isaaclab_envs.py#L105-L179)

## MuJoCo Playground Integration

 MuJoCo Playground environments are supported through a common loader that bridges JAX-based simulations to PyTorch or Warp backends.

 
### MuJoCo Playground Loader

 The `load_playground_env` function provides a unified interface for loading tasks like `CartpoleBalance` or `LeapCubeReorient`. It handles command-line argument parsing for `num_envs`, `episode_length`, and `randomization` [skrl/envs/loaders/jax/playground_envs.py8-150](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/loaders/jax/playground_envs.py#L8-L150)

 
| Backend | Loader Function | Implementation Detail |
|---|---|---|
| JAX | load_playground_env | Uses mujoco_playground.registry and wrapper.wrap_for_brax_training skrl/envs/loaders/jax/playground_envs.py65-132 |
| PyTorch | load_playground_env | Imports and calls the JAX loader, then wraps with PlaygroundWrapper skrl/envs/loaders/torch/playground_envs.py61-73 |
| Warp | load_playground_env | Bridges via JAX loader with Warp-compatible device management skrl/envs/loaders/warp/playground_envs.py61-73 |

## ManiSkill Integration

 ManiSkill environments are supported across all backends, featuring automatic environment resets and tensorized space handling.

 
 - **JAX Wrapper**: Uses DLPack for zero-copy tensor transfer between ManiSkill (PyTorch) and JAX [skrl/envs/wrappers/jax/mani_skill_envs.py19-36](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/jax/mani_skill_envs.py#L19-L36)
 - **Warp Wrapper**: Uses `wp.to_torch` and `wp.from_torch` for efficient GPU memory sharing [skrl/envs/wrappers/warp/mani_skill_envs.py64-74](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/warp/mani_skill_envs.py#L64-L74)
 - **Auto-Reset**: The wrappers automatically detect terminated/truncated environments and call `env.reset(options={"env_idx": ...})` to maintain parallel execution [skrl/envs/wrappers/jax/mani_skill_envs.py94-98](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/jax/mani_skill_envs.py#L94-L98)

## Inverse Kinematics Solutions

 The integration provides multiple inverse kinematics implementations optimized for different Isaac Gym variants and use cases.

 
### Isaac Gym IK Implementation

 The standard Isaac Gym IK solver uses damped least squares method for end-effector control, utilizing `quat_mul` and `quat_conjugate` for orientation error calculation [skrl/utils/isaacgym_utils.py388-437](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/utils/isaacgym_utils.py#L388-L437)

 
### Omniverse IK Enhancement

 The Omniverse Isaac Gym version provides multiple IK methods with enhanced configurability:

 
| Method | Description | Configuration |
|---|---|---|
| "damped least-squares" | Standard damped least squares | {"damping": 0.05, "scale": 1} |
| "transpose" | Jacobian transpose method | {"scale": 1} |
| "pseudoinverse" | Moore-Penrose pseudoinverse | {"scale": 1} |
| "singular-vale decomposition" | SVD-based solution | {"min_singular_value": 1e-5, "scale": 1} |

## Environment Instance Creation

 The `get_env_instance` function provides a factory pattern for creating Omniverse Isaac Gym environment instances with proper configuration, supporting both single-threaded (`_OmniIsaacGymVecEnv`) and multi-threaded (`_OmniIsaacGymVecEnvMT`) modes [skrl/utils/omniverse_isaacgym_utils.py184-362](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/utils/omniverse_isaacgym_utils.py#L184-L362)

 
### Multi-threaded Environment Features

 The multi-threaded variant (`_OmniIsaacGymVecEnvMT`) includes additional components for concurrent operation:

 
 - **Action Queue**: `queue.Queue(1)` for action buffering.
 - **Data Queue**: `queue.Queue(1)` for observation buffering.
 - **Trainer Integration**: `_OmniIsaacGymTrainerMT` for training coordination.
