  Model mixins provide a flexible architecture for defining neural network models with different action sampling behaviors in reinforcement learning. They implement the strategy pattern through Python multiple inheritance, allowing users to combine domain-specific action sampling logic with custom neural network architectures.

 
## Overview

 The mixin system separates action sampling behavior from neural network architecture definition. Each mixin implements a specific type of policy behavior by providing an `act()` method that defines how actions are computed from neural network outputs. Users combine mixins with the base `Model` class to create complete model implementations.

## Gaussian Mixin

 The `GaussianMixin` implements continuous stochastic policies. It uses the **reparameterization trick** via `rsample()` in PyTorch to allow gradients to flow through the sampling process.

 
 - **Reparameterization**: Samples are generated as `mean + std * epsilon` [skrl/models/jax/gaussian.py46](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/jax/gaussian.py#L46-L46)
 - **Action Clipping**: Actions can be clipped to the action space limits defined by `_g_min_actions` and `_g_max_actions` [skrl/models/torch/gaussian.py99-100](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/torch/gaussian.py#L99-L100)
 - **Log-Std Handling**: Log standard deviations are typically clipped to a range (default -20 to 2) to ensure numerical stability [skrl/models/torch/gaussian.py22-23](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/torch/gaussian.py#L22-L23)
 - **Taken Actions**: If `taken_actions` is provided in the `inputs` dictionary, the mixin computes the log probability of those specific actions instead of the sampled ones, which is essential for off-policy updates [skrl/models/torch/gaussian.py103](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/torch/gaussian.py#L103-L103)

## Categorical Mixin

 The `CategoricalMixin` handles discrete action spaces.

 
 - **Unnormalized Log Prob**: If `unnormalized_log_prob` is `True`, the model output is treated as logits [skrl/models/torch/categorical.py45-46](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/torch/categorical.py#L45-L46)
 - **Entropy**: Provides `get_entropy()` to return the Shannon entropy of the discrete distribution, often used as a regularizer in algorithms like PPO or A2C [skrl/models/torch/categorical.py59-68](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/torch/categorical.py#L59-L68)

## Deterministic Mixin

 The `DeterministicMixin` is used for continuous policies that do not involve sampling (e.g., DDPG, TD3) or for value functions (Critics).

 
 - **Direct Mapping**: The `act()` method directly returns the output of `compute()` after optional clipping [skrl/models/torch/deterministic.py36-42](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/torch/deterministic.py#L36-L42)
 - **Clipping**: Uses `compute_space_limits` to determine bounds from the `action_space` [skrl/models/torch/deterministic.py18-20](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/torch/deterministic.py#L18-L20)

## Multivariate Gaussian Mixin

 Unlike the standard `GaussianMixin` which assumes a diagonal covariance matrix (independent actions), the `MultivariateGaussianMixin` can represent correlations between action dimensions.

 
 - **Covariance**: It constructs a `MultivariateNormal` distribution. In the current implementation, it still uses a diagonal covariance derived from `log_std`, but through the `MultivariateNormal` API [skrl/models/torch/multivariate_gaussian.py79-80](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/torch/multivariate_gaussian.py#L79-L80)

## Backend Specifics: PyTorch vs. JAX

 
### PyTorch Mixins

 PyTorch mixins (e.g., in `skrl/models/torch/gaussian.py`) rely on the `torch.distributions` module. They maintain an internal `_distribution` object after `act()` is called, which can be accessed via the `distribution()` method [skrl/models/torch/gaussian.py124-131](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/torch/gaussian.py#L124-L131)

 
### JAX Mixins

 JAX mixins (e.g., in `skrl/models/jax/gaussian.py`) are designed for functional purity and JIT compatibility.

 
 - **JIT Compilation**: They use `jax.jit` on helper functions like `_gaussian` to optimize the sampling and log-prob calculation [skrl/models/jax/gaussian.py22-35](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/jax/gaussian.py#L22-L35)
 - **Random Keys**: They handle JAX's explicit PRNG state by folding in a counter `_g_i` to the base `config.jax.key` during every `act()` call [skrl/models/jax/gaussian.py142-145](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/jax/gaussian.py#L142-L145)
