  PyTorch Agents are the core decision-making components in the skrl reinforcement learning library that implement various RL algorithms using PyTorch as the backend. This page covers the architecture, lifecycle, and specific implementations of PyTorch-based agents, including configuration dataclasses, GAE computation, and optimization loops.

 For JAX-based agent implementations, see [JAX Agents](https://deepwiki.com/Toni-SM/skrl/2.2-jax-agents). For the base model classes used by agents, see [Model Base Classes](https://deepwiki.com/Toni-SM/skrl/3.1-model-base-classes). For training orchestration, see [Trainers](https://deepwiki.com/Toni-SM/skrl/5-trainers).

 
## Agent Architecture Overview

 PyTorch agents in skrl follow a unified architecture where all concrete agent implementations inherit from a base `Agent` class and implement specific RL algorithms. Each agent manages models, memory, optimizers, and handles the full training lifecycle.

## Base Agent Interface

 All PyTorch agents inherit from the base `Agent` class and implement a common interface for environment interaction and training. The key methods define the agent lifecycle:

 
### Core Interface Methods

 
| Method | Purpose | Implementation |
|---|---|---|
| init() | Initialize agent and create memory tensors | skrl/agents/torch/ppo/ppo.py166-198 |
| act() | Process states and return actions | skrl/agents/torch/ppo/ppo.py200-221 |
| record_transition() | Store environment transitions in memory | skrl/agents/torch/ppo/ppo.py223-263 |
| pre_interaction() | Called before environment step | skrl/agents/torch/sarsa/sarsa.py154-160 |
| post_interaction() | Called after environment step; triggers update() | skrl/agents/torch/ppo/ppo.py280-302 |
| update() | Main algorithm update step (optimization loop) | skrl/agents/torch/ppo/ppo.py304-444 |

## Individual Agent Implementations

 
### Policy Gradient Agents

 
 - **PPO (Proximal Policy Optimization)**: Implements clipped surrogate objectives. Supports multiple epochs and mini-batches per update. [skrl/agents/torch/ppo/ppo.py67-78](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/ppo/ppo.py#L67-L78)
 - **A2C (Advantage Actor Critic)**: A synchronous, deterministic version of A3C using GAE for advantage estimation. [skrl/agents/torch/a2c/a2c.py67-78](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/a2c/a2c.py#L67-L78)
 - **TRPO (Trust Region Policy Optimization)**: Uses natural policy gradient with a KL-divergence constraint, implemented via conjugate gradient and line search. [skrl/agents/torch/trpo/trpo.py186-197](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/trpo/trpo.py#L186-L197)
 - **AMP (Adversarial Motion Priors)**: Combines PPO with a discriminator trained on reference motions to imitation movement patterns. [skrl/agents/torch/amp/amp.py68-83](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/amp/amp.py#L68-L83)
 - **RPO (Relaxed Proximal Policy Optimization)**: A variant of PPO that modifies the policy update to handle complex action distributions.
 
 
### Actor-Critic Agents

 
 - **SAC (Soft Actor-Critic)**: Off-policy algorithm that maximizes entropy for better exploration. Features automatic entropy coefficient tuning. [skrl/agents/torch/sac/sac.py23-34](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/sac/sac.py#L23-L34)
 - **TD3 (Twin Delayed DDPG)**: Improves DDPG by using twin critics, delayed policy updates, and target policy smoothing. [skrl/agents/torch/td3/td3.py23-34](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/td3/td3.py#L23-L34)
 - **DDPG (Deep Deterministic Policy Gradient)**: An off-policy algorithm for continuous action spaces using target networks and exploration noise. [skrl/agents/torch/ddpg/ddpg.py22-33](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/ddpg/ddpg.py#L22-L33)
 
 
### Value-Based and Tabular Agents

 
 - **DQN (Deep Q-Network)**: Standard off-policy Q-learning using neural networks and experience replay. [skrl/agents/torch/dqn/dqn.py20-31](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/dqn/dqn.py#L20-L31)
 - **DDQN (Double Deep Q-Network)**: Mitigates overestimation bias in DQN by decoupling action selection from action evaluation. [skrl/agents/torch/ddqn/ddqn.py20-31](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/ddqn/ddqn.py#L20-L31)
 - **CEM (Cross-Entropy Method)**: An evolutionary strategy that samples actions and updates the policy based on "elite" trajectories. [skrl/agents/torch/cem/cem.py20-31](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/cem/cem.py#L20-L31)
 - **SARSA**: A tabular on-policy algorithm that updates Q-values based on the action actually taken in the next state. [skrl/agents/torch/sarsa/sarsa.py17-28](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/sarsa/sarsa.py#L17-L28)
 - **Q-Learning**: A tabular off-policy algorithm that updates Q-values based on the maximum possible next-state value.
 
 
### RNN Variants

 Most PyTorch agents have RNN variants (e.g., `PPO_RNN`, `SAC_RNN`, `TD3_RNN`) designed to handle sequences and maintain hidden states across environment steps. These variants typically include logic to handle sequence sampling and hidden state management in the `update()` loop.
