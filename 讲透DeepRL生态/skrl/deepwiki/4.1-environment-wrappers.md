  Environment wrappers provide a unified interface for integrating diverse reinforcement learning environments with `skrl` agents. This system abstracts away the differences between various environment APIs (Isaac Lab, Gymnasium, ManiSkill, PettingZoo, MuJoCo Playground, etc.) and presents them through a common interface that works seamlessly across PyTorch, JAX, and Warp backends.

 
## Architecture Overview

 The wrapper system acts as an adapter layer between external RL environments and `skrl`'s internal agent infrastructure. It automatically detects environment types and applies appropriate transformations to observations, actions, and episode lifecycle management.

 
### Data Flow and Normalization

 The wrappers ensure that all environments, regardless of their native format (NumPy, PyTorch tensors, JAX arrays), return data in the format expected by the selected `skrl` backend.

## Core Interface Standardization

 All wrappers implement a consistent interface to handle the following:

 
### Observation and Action Handling

 Wrappers use utility functions from `skrl.utils.spaces` to normalize data:

 
 - **`tensorize_space`**: Converts environment output to the backend's tensor format [skrl/envs/wrappers/jax/gymnasium_envs.py75](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/jax/gymnasium_envs.py#L75-L75)
 - **`flatten_tensorized_space`**: Flattens complex spaces (like Dict or Tuple) into a single vector for the agent [skrl/envs/wrappers/jax/gymnasium_envs.py75](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/jax/gymnasium_envs.py#L75-L75)
 - **`untensorize_space`**: Converts agent actions back to the format expected by the environment [skrl/envs/wrappers/jax/gymnasium_envs.py64-68](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/jax/gymnasium_envs.py#L64-L68)
 
 
### Vectorized Environment Support

 Wrappers automatically detect if an environment is vectorized (e.g., `gymnasium.vector.VectorEnv`) and adjust the `observation_space` and `action_space` to return the `single_` space versions [skrl/envs/wrappers/torch/gymnasium_envs.py42-55](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/torch/gymnasium_envs.py#L42-L55)

 
### Device Management

 The `Wrapper` base class parses the environment's device or defaults to the framework's configured device using `config.torch.parse_device` or `config.jax.parse_device` [skrl/envs/wrappers/jax/base.py27-30](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/jax/base.py#L27-L30)

## Implementation Details

 
### Gymnasium Wrapper

 The `GymnasiumWrapper` handles modern Gymnasium APIs, including the `terminated` and `truncated` signal separation [skrl/envs/wrappers/jax/gymnasium_envs.py77-78](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/jax/gymnasium_envs.py#L77-L78) It also manages auto-resetting logic for vectorized environments by storing the last observation and info when a reset is triggered internally by the environment [skrl/envs/wrappers/jax/gymnasium_envs.py103-112](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/jax/gymnasium_envs.py#L103-L112)

 
### Gym Wrapper (Legacy)

 The `GymWrapper` provides backward compatibility for OpenAI Gym. It includes a "hack" to handle the `TimeLimit.truncated` info key from older Gym versions to maintain the `terminated`/`truncated` API expected by `skrl` [skrl/envs/wrappers/jax/gym_envs.py84-95](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/jax/gym_envs.py#L84-L95)

 
### PettingZoo Wrapper

 This wrapper supports the PettingZoo **Parallel API**. It converts dictionary-based multi-agent responses into tensorized dictionaries and handles the global `state()` view by duplicating it across all possible agents if necessary [skrl/envs/wrappers/jax/pettingzoo_envs.py44-75](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/envs/wrappers/jax/pettingzoo_envs.py#L44-L75)
