  This glossary defines technical terms, architectural components, and domain-specific jargon used throughout the **skrl** codebase. It serves as a reference for onboarding engineers to understand how reinforcement learning concepts are mapped to specific code entities across the supported backends (PyTorch, JAX, and Warp).

 
## Core Abstractions

 
### Agent

 The high-level entity implementing a reinforcement learning algorithm. It manages models, memories, and the optimization logic.

 
 - **Base Class**: `skrl.agents.torch.base.Agent` [skrl/agents/torch/base.py83-104](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/base.py#L83-L104)
 - **Key Lifecycle Methods**: 
 - `act()`: Computes actions given observations [skrl/agents/torch/base.py279-299](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/base.py#L279-L299)
 - `record_transition()`: Stores environment transitions in memory [skrl/agents/torch/base.py328-356](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/base.py#L328-L356)
 - `pre_interaction()` / `post_interaction()`: Hooks for logic before/after environment steps [skrl/agents/torch/base.py263-277](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/base.py#L263-L277) [skrl/agents/torch/base.py382-396](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/base.py#L382-L396)
 
 
### Model

 A neural network or tabular representation used by an agent (e.g., Policy, Value function). Models in **skrl** use a mixin-based architecture to handle different action distributions.

 
 - **Base Class**: `skrl.models.torch.base.Model` [skrl/models/torch/base.py15-40](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/torch/base.py#L15-L40)
 - **Initialization**: Lazy modules are initialized via `init_state_dict()` [skrl/models/torch/base.py42-74](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/torch/base.py#L42-L74)
 
 
### Memory

 A storage system for experience transitions.

 
 - **Base Class**: `skrl.memories.torch.base.Memory` [skrl/memories/torch/base.py12-14](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/memories/torch/base.py#L12-L14) (implied by usage in agents).
 - **Random Memory**: Implements experience replay with circular buffers [skrl/memories/torch/random.py13-15](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/memories/torch/random.py#L13-L15)
 
 
### Trainer

 Orchestrates the RL loop, managing interactions between agents and environments.

 
 - **Base Class**: `skrl.trainers.torch.base.Trainer` [skrl/trainers/torch/base.py72-87](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/trainers/torch/base.py#L72-L87)
 - **Sequential Trainer**: Executes agent steps one after another [skrl/trainers/torch/sequential.py22-39](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/trainers/torch/sequential.py#L22-L39)

## Domain Concepts & Jargon

 
### GAE (Generalized Advantage Estimator)

 A method to compute advantages by balancing bias and variance, used extensively in on-policy agents like PPO.

 
 - **Implementation**: `compute_gae` function [skrl/agents/torch/ppo/ppo.py23-64](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/ppo/ppo.py#L23-L64)
 - **Parameters**: Uses `gae_lambda` (lambda coefficient) and `discount_factor` (gamma) [skrl/agents/torch/ppo/ppo.py30-31](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/ppo/ppo.py#L30-L31)
 
 
### Polyak Averaging (Soft Update)

 A technique for updating target networks by slowly tracking the weights of the online networks.

 
 - **Method**: `Model.update_parameters(source_model, polyak)` [skrl/models/torch/base.py246-261](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/models/torch/base.py#L246-L261)
 - **Usage**: Common in off-policy algorithms like TD3 [skrl/agents/torch/td3/td3.py137-139](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/td3/td3.py#L137-L139) and SAC [skrl/agents/torch/sac/sac.py137-138](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/sac/sac.py#L137-L138)
 
 
### Scopes

 A mechanism to partition a vectorized environment so that different agents can operate on specific subsets of parallel environments simultaneously.

 
 - **Logic**: Handled in the `Trainer._setup_agents()` method [skrl/trainers/torch/base.py131-171](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/trainers/torch/base.py#L131-L171)
 - **Generation**: `generate_equally_spaced_scopes` [skrl/trainers/torch/base.py18-35](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/trainers/torch/base.py#L18-L35)
 
 
### Mixed Precision (AMP)

 The use of both 16-bit and 32-bit floating-point types during training to speed up computation and reduce memory usage.

 
 - **Implementation**: Agents utilize `torch.amp.GradScaler` [skrl/agents/torch/ppo/ppo.py121-125](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/skrl/agents/torch/ppo/ppo.py#L121-L125)
