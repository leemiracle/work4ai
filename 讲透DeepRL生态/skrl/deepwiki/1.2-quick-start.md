  This page provides a practical introduction to training reinforcement learning agents using **skrl**. It covers the essential workflow from environment setup to agent training, with simple examples to get you started quickly. The library supports multiple backends including **PyTorch**, **JAX**, and **NVIDIA Warp** [docs/source/index.rst37-39](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/docs/source/index.rst#L37-L39)

 For detailed installation instructions, see **1.1 Installation and Setup**. For comprehensive examples across different environments, see the full [Examples documentation](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/Examples documentation)().

 
## Basic Training Workflow

 The core **skrl** training workflow follows these steps: environment wrapping, model definition, agent configuration, and training execution. ## Simple Training Example

 The following snippets demonstrate the implementation of a PPO agent training in the **MuJoCo Playground** environment. Note that while the model definition syntax varies by backend, the overall structure is identical.

 
### PyTorch, JAX, and Warp Comparison

 
| Feature | PyTorch | JAX (Flax) | NVIDIA Warp |
|---|---|---|---|
| Base Model | skrl.models.torch.Model | skrl.models.jax.Model | skrl.models.warp.Model |
| Mixins | GaussianMixin, DeterministicMixin | GaussianMixin, DeterministicMixin | GaussianMixin, DeterministicMixin |
| Layer Def | torch.nn.Sequential | @nn.compact method | warp_nn.nn.Sequential |
| Config | PPO_CFG() | PPO_CFG() | PPO_CFG() |

## Key Configuration Parameters

 Each agent offers an `experiment` configuration key within its configuration dataclass (e.g., `ExperimentCfg`) to control data persistence and logging [docs/source/intro/data.rst21-27](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/docs/source/intro/data.rst#L21-L27)

 
| Parameter | Default | Description |
|---|---|---|
| directory | "runs" | Parent directory for experiment data docs/source/intro/data.rst29-31 |
| write_interval | "auto" | Interval for writing metrics to TensorBoard/WandB docs/source/intro/data.rst36-38 |
| checkpoint_interval | "auto" | Interval for saving agent state to disk docs/source/intro/data.rst158-160 |
| store_separately | False | Whether to save models/optimizers in separate files docs/source/intro/data.rst162-164 |
