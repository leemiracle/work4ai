  This document covers the installation and initial configuration of the **skrl** reinforcement learning library, including dependency management, backend-specific setup for PyTorch, JAX, and NVIDIA Warp, and the configuration system exposed via `skrl.config`.

 
## System Requirements and Dependencies

 The **skrl** library supports a multi-backend architecture. Since version 2.0.0, it requires Python 3.10 or higher [pyproject.toml6](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/pyproject.toml#L6-L6) The library differentiates between general dependencies and framework-specific extras.

## Installation Methods

 
### Python Package Index (PyPI)

 The most common way to install **skrl** is via `pip` using framework-specific extras:

 
| Target Backend | Command |
|---|---|
| PyTorch | pip install skrl[torch] |
| JAX | pip install skrl[jax] |
| NVIDIA Warp | pip install skrl[warp] |
| All Backends | pip install skrl[all] |
| Core Only | pip install skrl |

 *Note: It is recommended to install JAX manually before the library to ensure correct CUDA/CUDNN support [docs/source/intro/installation.rst37-39](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/docs/source/intro/installation.rst#L37-L39)*

## Configuration and Device Management

 **skrl** provides a unified configuration system via `skrl.config`. This system handles device parsing, distributed training detection, and backend-specific global settings.

 
### The Config System

 The `skrl.config` module exposes configuration objects for each backend:

 
 - `skrl.config.torch`: Configuration for PyTorch.
 - `skrl.config.jax`: Configuration for JAX.
 - `skrl.config.warp`: Configuration for NVIDIA Warp.
 
 A key utility is `parse_device`, which normalizes device strings across frameworks [CHANGELOG.md90-91](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/CHANGELOG.md?plain=1#L90-L91)

 
### Distributed Training Setup

 The library automatically detects distributed environments (e.g., multi-GPU setups). In JAX, the library forces the use of the device local to the process in distributed runs [CHANGELOG.md84-85](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/CHANGELOG.md?plain=1#L84-L85)

## Logging and Experiment Setup

 **skrl** integrates with TensorBoard and Weights & Biases (wandb) for experiment tracking.

 
### Experiment Configuration

 Each agent is configured via an `ExperimentCfg` dataclass (or dictionary in older versions) [CHANGELOG.md42](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/CHANGELOG.md?plain=1#L42-L42) Key parameters include:

 
 - `directory`: Root folder for logs [docs/source/intro/data.rst29-31](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/docs/source/intro/data.rst#L29-L31)
 - `write_interval`: Frequency of writing to TensorBoard [docs/source/intro/data.rst36-38](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/docs/source/intro/data.rst#L36-L38)
 - `checkpoint_interval`: Frequency of saving model weights [docs/source/intro/data.rst158-160](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/docs/source/intro/data.rst#L158-L160)
 
 
### TensorBoard Implementation

 Since version 2.0.0, **skrl** includes a custom `SummaryWriter` implementation to log data without requiring large third-party library dependencies [CHANGELOG.md32](https://github.com/Toni-SM/skrl/blob/3cdc7f3b/CHANGELOG.md?plain=1#L32-L32)
