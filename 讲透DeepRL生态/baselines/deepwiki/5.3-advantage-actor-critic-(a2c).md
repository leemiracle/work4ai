## Purpose and Scope

 This document explains the implementation of the Advantage Actor-Critic (A2C) algorithm in the OpenAI Baselines repository. A2C is a synchronous variant of the Asynchronous Advantage Actor-Critic (A3C) algorithm, which provides better performance with similar sample efficiency and stability. The document covers the architecture, components, implementation details, and usage of the A2C algorithm. For information about related actor-critic methods like ACKTR, see [Actor-Critic with Kronecker-Factored Trust Region (ACKTR)](https://deepwiki.com/openai/baselines/5.5-actor-critic-with-kronecker-factored-trust-region-(acktr)).

 
## Algorithm Overview

 A2C is a policy gradient method that combines the policy-based and value-based approaches. It maintains both a policy (actor) that determines which actions to take and a value function (critic) that evaluates how good those actions are. The advantage function helps reduce the variance of policy gradient updates by using the value function as a baseline.

## Implementation Details

 
### Loss Function

 The A2C loss function consists of three components:

 
 - **Policy Gradient Loss**: Weighted by the advantage function
 - **Value Function Loss**: Mean squared error between predicted values and returns
 - **Entropy Bonus**: Encourages exploration by penalizing deterministic policies
 
 The total loss is calculated as:

 
```
Loss = pg_loss - entropy * ent_coef + vf_loss * vf_coef
```

 Where:

 
 - `pg_loss` = mean(advantage * neglogpac)
 - `vf_loss` = mean_squared_error(value_pred, returns)
 - `entropy` = mean of policy entropy
 
 Sources: [baselines/a2c/a2c.py54-68](https://github.com/openai/baselines/blob/ea25b9e8/baselines/a2c/a2c.py#L54-L68)

 
### Training Process

 The training process in A2C follows these steps:

 
 - Collect a batch of experiences using the `Runner` class
 - Calculate advantages (rewards - values)
 - Update the policy and value networks based on the loss function
 - Repeat until reaching the total number of timesteps

### Advantage Calculation

 The advantage function is calculated as:

 
```
Advantage = R - V(s)
```

 Where:

 
 - `R` is the discounted return
 - `V(s)` is the predicted value of the state
 
 For multi-step returns, the rewards are discounted with the `discount_with_dones` function, which handles episode terminations correctly.

## Technical Implementation

 
### Network Initialization

 A2C uses two separate but identical policy networks:

 
 - **Step Model**: Processes a single step for each environment (nenvs, 1)
 - **Train Model**: Processes a batch of steps for training (nenvs*nsteps, nsteps)
 
 
```
step_model = policy(nenvs, 1, sess)
train_model = policy(nbatch, nsteps, sess)
```

 Sources: [baselines/a2c/a2c.py37-47](https://github.com/openai/baselines/blob/ea25b9e8/baselines/a2c/a2c.py#L37-L47)

 A2C uses RMSProp as the optimizer, with configurable learning rate, decay, and epsilon parameters:

### Vectorized Execution

 A2C uses vectorized environments to process multiple environments in parallel, which increases throughput and stabilizes learning. The `Runner` class handles this parallel execution, collecting batches of experiences from all environments simultaneously.

 
```
nbatch = nenvs * nsteps  # Batch size
```

## Differences from A3C

 Unlike A3C, which uses asynchronous parallel workers that each maintain their own copy of the model, A2C is synchronous. In A2C:

 
 - Multiple environments run in parallel to collect experiences
 - All experiences are gathered to update the policy and value networks synchronously
 - This synchronous approach provides more stable updates and can be more efficient with GPUs
 
 This synchronous design makes A2C simpler to implement and often results in more stable training.
