## Purpose and Scope

 The Configuration System in AgileRL provides a YAML-based approach for defining algorithm hyperparameters, evolutionary mutation settings, and neural network architectures. This system enables users to specify complete experimental setups declaratively, supporting reproducible research and easy parameter sweeps across different algorithms and environments.

 For information about the evolutionary optimization process itself, see [Evolutionary Hyperparameter Optimization](https://deepwiki.com/AgileRL/AgileRL/4-evolutionary-hyperparameter-optimization). For details about specific mutation operators, see [Mutation System](https://deepwiki.com/AgileRL/AgileRL/4.1-mutation-system). For training orchestration, see [Training Framework](https://deepwiki.com/AgileRL/AgileRL/3-training-framework).

 
## Configuration File Structure

 AgileRL configurations are organized into YAML files with three primary sections that control different aspects of the training and evolution process:

 
| Section | Purpose | Key Components |
|---|---|---|
| INIT_HP | Initial hyperparameters and training settings | Algorithm selection, environment setup, learning parameters, evolutionary settings |
| MUTATION_PARAMS | Evolutionary mutation probabilities and constraints | Mutation type probabilities, parameter bounds, random seeds |
| NET_CONFIG | Neural network architecture specifications | Layer dimensions, architectural constraints, encoder/decoder configurations |

## Integration with Training System

 The configuration system serves as the primary interface between user specifications and AgileRL's training components:

 
### Algorithm Instantiation

 Configuration keys map directly to algorithm constructor parameters:

 
| Config Key | Algorithm Parameter | Purpose |
|---|---|---|
| BATCH_SIZE | batch_size | Training batch size |
| LR_ACTOR | lr_actor | Actor network learning rate |
| LR_CRITIC | lr_critic | Critic network learning rate |
| GAMMA | gamma | Discount factor |
| TAU | tau | Target network update rate |
| MEMORY_SIZE | Memory buffer initialization | Replay buffer capacity |

 
### Evolutionary Parameter Integration

 Configuration parameters control the evolutionary optimization process:

 
| Config Key | System Component | Function |
|---|---|---|
| POP_SIZE | create_population() | Population initialization size |
| TOURN_SIZE | TournamentSelection | Tournament selection size |
| EVO_STEPS | Training loop | Evolution frequency |
| ELITISM | TournamentSelection | Elite preservation flag |

## Configuration Validation and Processing

 The configuration system implements validation to ensure parameter consistency and algorithm compatibility:

 
### Parameter Bounds Validation

 Mutation parameters include explicit bounds checking:

 
 - Learning rate bounds: `MIN_LR` to `MAX_LR`
 - Batch size bounds: `MIN_BATCH_SIZE` to `MAX_BATCH_SIZE`
 - Learning frequency bounds: `MIN_LEARN_STEP` to `MAX_LEARN_STEP`
 
 
### Algorithm-Specific Validation

 Different algorithms require specific parameter sets:

 
 - Off-policy algorithms require `MEMORY_SIZE` for replay buffers
 - Actor-critic methods need both `LR_ACTOR` and `LR_CRITIC`
 - Policy gradient methods may require different noise parameters
 
 
### Environment Compatibility

 Configuration validation ensures environment and algorithm compatibility:

 
 - Continuous action spaces require appropriate noise parameters (`O_U_NOISE`, `EXPL_NOISE`)
 - Multi-agent environments need compatible algorithm selection
 - Image-based environments require appropriate channel ordering (`CHANNELS_LAST`)
