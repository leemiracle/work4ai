  This document covers the Q-network implementations in AgileRL, which are neural networks that approximate state-action value functions for value-based reinforcement learning algorithms. These networks predict the expected return for taking specific actions in given states and are fundamental components of algorithms like DQN, Rainbow DQN, DDPG, and TD3.

 For information about actor networks that output actions or action distributions, see [Actor Networks](https://deepwiki.com/AgileRL/AgileRL/5.3-actor-networks). For the base evolvable network infrastructure, see [Evolvable Networks](https://deepwiki.com/AgileRL/AgileRL/5.1-evolvable-networks).

 
## Overview

 AgileRL provides three main Q-network implementations that inherit from the `EvolvableNetwork` base class, enabling architectural evolution during training. All Q-networks automatically build appropriate encoders based on the observation space and use evolvable MLP heads for value prediction.

 The basic `QNetwork` class handles discrete and multi-discrete action spaces, outputting Q-values for each possible action.

## RainbowQNetwork (Distributional)

 The `RainbowQNetwork` implements distributional Q-learning with dueling architecture and noisy networks from the Rainbow DQN paper. It outputs probability distributions over value supports rather than point estimates.

 
### Key Features

 
 - **Distributional Values**: Uses `support` tensor and `num_atoms` for value distribution
 - **Dueling Architecture**: Separates value and advantage estimation via `DuelingDistributionalMLP`
 - **Noisy Networks**: Supports noisy linear layers with `noise_std` parameter
 - **Layer Normalization**: Enhanced stability for encoder and head networks
 
 
### Architecture Components

 
| Component | Type | Purpose |
|---|---|---|
| head_net | DuelingDistributionalMLP | Dueling network with distributional outputs |
| support | torch.Tensor | Value support for distribution |
| num_atoms | int | Number of atoms in value distribution |
| noise_std | float | Standard deviation for noisy layers |

 
### Forward Pass Options

 The `forward` method [agilerl/networks/q_networks.py252-268](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/networks/q_networks.py#L252-L268) accepts additional parameters:

 
 - `q`: Return Q-values (default) or raw distributions
 - `log`: Return log probabilities instead of probabilities

## Evolution Capabilities

 All Q-networks inherit mutation capabilities from `EvolvableNetwork`, enabling architectural evolution during training:

 
### Mutation Types

 
| Mutation | Target | Effect |
|---|---|---|
| add_latent_node | Latent dimension | Increases representational capacity |
| remove_latent_node | Latent dimension | Reduces network complexity |
| encoder.* | Encoder architecture | Modifies feature extraction |
| head_net.* | MLP head | Changes value prediction capacity |

## Integration with RL Algorithms

 Q-networks integrate with AgileRL algorithms through standardized interfaces:

 
### Usage Patterns

 
| Algorithm | Q-Network Type | Purpose |
|---|---|---|
| DQN | QNetwork | Action-value estimation |
| Rainbow DQN | RainbowQNetwork | Distributional value learning |
| DDPG | ContinuousQNetwork | Critic network |
| TD3 | ContinuousQNetwork | Twin critic networks |
| CQL | ContinuousQNetwork | Conservative Q-learning |

 
### Configuration

 Q-networks are configured through `head_config` and `encoder_config` parameters, with automatic encoder selection based on observation space type detected in the `EvolvableNetwork` base class.
