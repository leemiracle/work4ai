  This page documents the actor network implementations in AgileRL, which serve as policy networks in policy gradient algorithms. Actor networks take observations as input and output actions or action distributions, providing the core policy functionality for algorithms like DDPG, TD3, and PPO. For information about value networks and Q-networks, see [Q-Networks and Value Functions](https://deepwiki.com/AgileRL/AgileRL/5.2-q-networks-and-value-functions).

 
## Actor Network Overview

 Actor networks in AgileRL are evolvable neural networks that implement the policy function in reinforcement learning algorithms. They are designed to handle various observation and action spaces while supporting evolutionary hyperparameter optimization. The library provides two main types of actor networks:

 
 - **DeterministicActor**: Outputs deterministic actions (used in DDPG, TD3)
 - **StochasticActor**: Outputs probability distributions over actions (used in PPO, SAC)
 
 Both actor implementations inherit from `EvolvableNetwork`, making them compatible with AgileRL's evolutionary optimization framework.

## Actor Network Architecture

 Actor networks in AgileRL follow a modular architecture with two main components:

 
 - **Encoder**: Extracts features from observations, automatically constructed based on the observation space
 - **Head Network**: Processes the features to produce actions or action distribution parameters
 
 This design allows for flexibility in handling different observation spaces while maintaining a consistent interface.

## Deterministic Actor Networks

 The `DeterministicActor` class implements a deterministic policy that directly outputs action values without sampling. This is typically used in off-policy algorithms like DDPG and TD3.

 
### Key Features

 
 - Deterministic output (single action value)
 - Support for Box (continuous) and Discrete action spaces
 - Action scaling to match environment action bounds
 - Configurable output activation function (default: Tanh for continuous spaces)

## Stochastic Actor Networks

 The `StochasticActor` class implements a stochastic policy that outputs a distribution over actions. This is typically used in on-policy algorithms like PPO.

 
### Key Features

 
 - Stochastic output (distribution over actions)
 - Support for Box, Discrete, MultiDiscrete, and MultiBinary action spaces
 - Can compute log probabilities and entropy for policy optimization
 - Configurable action distributions (e.g., Gaussian for continuous spaces)
 - Uses `EvolvableDistribution` wrapper to convert network outputs to action distributions
 - Support for action masking in discrete action spaces
 
 
### EvolvableDistribution Wrapper

 The `StochasticActor` uses an `EvolvableDistribution` wrapper around its head network to handle different action space types and provide distribution functionality. This wrapper:

 
 - Converts network logits to appropriate distributions based on action space
 - Handles action sampling with optional action masking
 - Computes log probabilities and entropy for policy optimization
 - Supports action squashing for continuous spaces when `squash_output=True`

## Action Space Compatibility

 Both actor types handle different action spaces differently:

 
| Actor Type | Action Space | Output Treatment | Activation |
|---|---|---|---|
| DeterministicActor | Box (Continuous) | Rescaled to action bounds | Tanh |
| DeterministicActor | Discrete | Action logits | Softmax |
| StochasticActor | Box (Continuous) | Distribution parameters | None (for logits) |
| StochasticActor | Discrete | Distribution parameters | None (for logits) |
| StochasticActor | MultiDiscrete | Distribution parameters | None (for logits) |
| StochasticActor | MultiBinary | Distribution parameters | None (for logits) |

## Integration with RL Algorithms

 Actor networks integrate with various RL algorithms in AgileRL:

 
| Algorithm | Actor Type | Purpose |
|---|---|---|
| DDPG | DeterministicActor | Generate deterministic actions for continuous action spaces |
| TD3 | DeterministicActor | Generate deterministic actions with twin critics |
| PPO | StochasticActor | Generate stochastic actions with probability distributions |
| MADDPG | DeterministicActor | Generate deterministic actions in multi-agent setting |
| MATD3 | DeterministicActor | Generate deterministic actions with twin critics in multi-agent setting |
| IPPO | StochasticActor | Generate stochastic actions in multi-agent setting |

 Each actor network type is tailored to the needs of its respective algorithm, with features designed to support the specific policy gradient approach.

## Observation Space Handling

 Actor networks automatically build appropriate encoder architectures based on the observation space:

 
| Observation Space | Encoder Type | Notes |
|---|---|---|
| Box (1D) | EvolvableMLP | For vector observations |
| Box (3D) | EvolvableCNN | For image observations |
| Box (2D) | EvolvableLSTM or EvolvableMLP with Flatten | Based on recurrent flag |
| Dict | EvolvableMultiInput | Handles heterogeneous observations |
| Tuple | EvolvableMultiInput | Converted to Dict internally |

 The ability to automatically select and configure encoders based on observation spaces makes these actor networks highly versatile across different environments.

## Customization Options

 Actor networks support extensive customization:

 
 - Custom encoders via the `encoder_cls` parameter
 - Configurable network architectures via `encoder_config` and `head_config`
 - Adjustable latent dimension
 - Support for multi-agent settings via the `n_agents` parameter
 - Recurrent network support via the `recurrent` parameter
 
 These options allow for fine-tuned policy networks that can be adapted to specific environment requirements.
