# Mutation System

  Relevant source files 
 - [agilerl/hpo/mutation.py](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/hpo/mutation.py)
 - [agilerl/utils/utils.py](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/utils/utils.py)
 
  The Mutation System implements evolutionary operators for neural network architectures, parameters, and reinforcement learning hyperparameters within AgileRL's evolutionary hyperparameter optimization framework. This system enables automatic optimization of both network structures and learning parameters through biologically-inspired mutation operators applied to populations of RL agents.

 For information about tournament selection (the complementary evolutionary operator), see [Tournament Selection](https://deepwiki.com/AgileRL/AgileRL/4.2-tournament-selection). For details about the evolvable network architectures that support mutation, see [Evolvable Networks](https://deepwiki.com/AgileRL/AgileRL/5.1-evolvable-networks).

 
## Mutation Types Overview

 The mutation system supports five distinct mutation types, each targeting different aspects of RL agent optimization:

 
| Mutation Type | Target | Description |
|---|---|---|
| No Mutation | - | Preserves agent unchanged (maintains elite) |
| Architecture | Network Structure | Adds/removes layers or nodes |
| Parameter | Network Weights | Applies noise to weight matrices |
| Activation | Activation Functions | Changes activation function types |
| RL Hyperparameter | Learning Parameters | Modifies learning rates, batch sizes, etc. |

 The system uses probabilistic selection to choose which mutation to apply to each agent in the population, with configurable relative probabilities for each mutation type.

## Architecture Mutations

 Architecture mutations modify the structure of neural networks by adding or removing layers and nodes. This system works with `EvolvableModule` networks that expose mutation methods.

 **Architecture Mutation Process**

 
```

```

 The architecture mutation process involves several key steps:

 
 - **Offspring Extraction**: The `get_offspring_eval_modules()` function separates policy networks from other evaluation modules
 - **Mutation Sampling**: Uses `sample_mutation_method()` on the evolvable modules to determine the specific architecture change
 - **Consistent Application**: Applies the same mutation to all network modules to maintain architectural consistency
 - **Special Handling**: Bandit algorithms require gradient reinitialization via `_reinit_bandit_grads()`

## Parameter Mutations

 Parameter mutations apply stochastic noise to network weights using a sophisticated scheme that includes normal mutations, super mutations, and reset mutations.

 **Parameter Mutation Algorithm**

 
```

```

 The parameter mutation uses three different noise strategies:

 
 - **Normal Mutation**: Adds noise proportional to current weight magnitude
 - **Super Mutation**: Adds larger noise (10x strength) for exploration
 - **Reset Mutation**: Completely resets weights using standard normal distribution

## Hyperparameter Mutations

 RL hyperparameter mutations modify learning parameters like learning rates, batch sizes, and algorithm-specific parameters. The system uses a configuration-driven approach to determine which hyperparameters can be mutated.

 **Hyperparameter Mutation Flow**

 
```

```

 The hyperparameter mutation system:

 
 - **Samples** a hyperparameter to mutate from the configured options
 - **Applies** the mutation using the parameter's specific mutation method
 - **Reinitializes** optimizers if learning rates were modified
 - **Tracks** the mutation type in `individual.mut`

## Activation Mutations

 Activation mutations change the activation functions used in neural networks, but are disabled for certain algorithms that require stable activation functions.

 **Activation Mutation Constraints**

 
```

```

 Restricted algorithms that don't support activation mutations:

 
 - PPO, DDPG, TD3, IPPO, MADDPG, MATD3, GRPO
 
 The system prevents activation mutations for policy gradient methods where activation function stability is critical for convergence.

## Integration with Evolutionary Training

 The mutation system integrates with AgileRL's broader evolutionary training loop through the `tournament_selection_and_mutation()` function, which coordinates tournament selection and mutation application.

 **Evolutionary Training Integration**

 
```

```

 Key integration points:

 
 - **Population Management**: Works with lists of `EvolvableAlgorithm` agents
 - **Device Handling**: Manages GPU/CPU placement and distributed training
 - **Accelerator Support**: Handles HuggingFace Accelerate for multi-GPU training
 - **Elite Preservation**: Optionally preserves best-performing agent without mutation
 - **Checkpointing**: Saves intermediate states for distributed training recovery
 
 The mutation system uses configurable probabilities during pre-training vs. training phases, with pre-training typically having zero probability for no-mutation to ensure all agents start with some variation.
