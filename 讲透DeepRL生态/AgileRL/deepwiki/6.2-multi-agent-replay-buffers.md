## Purpose and Scope

 This document covers AgileRL's specialized replay buffer system for multi-agent reinforcement learning environments. The multi-agent replay buffer extends the concept of experience replay to scenarios where multiple agents interact simultaneously, requiring agent-specific data management and coordinated sampling strategies.

 For standard single-agent replay buffers, see [Replay Buffers](https://deepwiki.com/AgileRL/AgileRL/6.1-replay-buffers). For multi-agent training orchestration, see [Multi-Agent Training](https://deepwiki.com/AgileRL/AgileRL/3.4-multi-agent-training). For multi-agent algorithm implementations, see [Multi-Agent Algorithms](https://deepwiki.com/AgileRL/AgileRL/2.3-multi-agent-algorithms).

 
## Overview

 Multi-agent replay buffers address the unique challenges of storing and sampling experiences in environments where multiple agents act simultaneously. Unlike single-agent scenarios, multi-agent experiences require:

 
 - **Agent-specific data organization**: Each experience contains data for all agents
 - **Coordinated sampling**: Maintaining temporal relationships between agents' actions
 - **Flexible data structures**: Supporting various observation and action space types per agent
 
 The system handles both discrete and continuous action spaces, supports vectorized environments, and maintains compatibility with AgileRL's evolutionary optimization framework.

## Data Structure and Storage

 
### Experience Format

 Each experience stored in the buffer follows a standardized format where each field contains a dictionary mapping agent IDs to their respective data:

 
```
Experience(
    state={agent_1: state_1, agent_2: state_2, ...},
    action={agent_1: action_1, agent_2: action_2, ...},
    reward={agent_1: reward_1, agent_2: reward_2, ...},
    next_state={agent_1: next_state_1, agent_2: next_state_2, ...},
    done={agent_1: done_1, agent_2: done_2, ...}
)
```

### Output Format

 The `sample` method returns a tuple of dictionaries where each dictionary corresponds to a field name, and within each dictionary, agent IDs map to their batched data:

 
```
(
    {'agent_1': state_batch_1, 'agent_2': state_batch_2},      # states
    {'agent_1': action_batch_1, 'agent_2': action_batch_2},    # actions
    {'agent_1': reward_batch_1, 'agent_2': reward_batch_2},    # rewards
    ...
)
```

 
### Special Field Handling

 Binary fields such as `done`, `termination`, `terminated`, `truncation`, and `truncated` receive special treatment:

 
 - Converted to `uint8` dtype when no NaN values are present
