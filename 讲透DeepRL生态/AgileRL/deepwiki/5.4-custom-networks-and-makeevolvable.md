# Custom Networks and MakeEvolvable

  Relevant source files 
 - [agilerl/wrappers/make_evolvable.py](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/wrappers/make_evolvable.py)
 
  This document covers the `MakeEvolvable` wrapper class and AgileRL's approach to making arbitrary PyTorch neural networks evolvable. The `MakeEvolvable` wrapper enables evolutionary hyperparameter optimization on custom network architectures by automatically detecting their structure and providing mutation capabilities.

 For information about pre-built evolvable network architectures, see [Evolvable Networks](https://deepwiki.com/AgileRL/AgileRL/5.1-evolvable-networks). For specific network types like Q-networks and actor networks, see [Q-Networks and Value Functions](https://deepwiki.com/AgileRL/AgileRL/5.2-q-networks-and-value-functions) and [Actor Networks](https://deepwiki.com/AgileRL/AgileRL/5.3-actor-networks).

 
## Overview and Purpose

 The `MakeEvolvable` class serves as a bridge between standard PyTorch neural networks and AgileRL's evolutionary optimization system. It automatically analyzes the architecture of an existing network and reconstructs it as an evolvable module capable of structural and parametric mutations.

 **Important Deprecation Notice**: The `MakeEvolvable` class will be deprecated in future releases. The recommended approach is to define evolvable networks directly through the `EvolvableModule` and `EvolvableNetwork` class hierarchies.

 The detection process captures:

 
 - **Convolutional layers**: Channel sizes, kernel sizes, stride, padding
 - **Linear layers**: Input/output feature dimensions
 - **Normalization layers**: BatchNorm, LayerNorm, InstanceNorm
 - **Pooling layers**: MaxPool, AvgPool configurations
 - **Activation functions**: ReLU, Tanh, Sigmoid, etc.

## Network Building and Reconstruction

 After architecture detection, `MakeEvolvable` reconstructs the network using evolvable components that support mutation operations.

 
### Network Components

 
| Component | Purpose | When Created |
|---|---|---|
| feature_net | Main feature extraction network | Always |
| value_net | Value estimation (for Rainbow DQN or CNN architectures) | CNN or Rainbow configurations |
| advantage_net | Advantage estimation (for Rainbow DQN) | Rainbow DQN only |

### Rainbow DQN Integration

 The wrapper provides special support for Rainbow DQN distributional reinforcement learning:

 
 - **Distributional outputs**: Creates separate value and advantage networks
 - **Atom support**: Configurable number of atoms for value distribution
 - **Noisy layers**: Uses `NoisyLinear` layers for exploration

## Network Reconstruction and Parameter Preservation

 During mutations, networks are reconstructed while preserving learned parameters where possible.

 
### Reconstruction Process

 
| Step | Function | Purpose |
|---|---|---|
| 1 | build_networks() | Create new network structure |
| 2 | preserve_parameters() | Transfer compatible weights |
| 3 | shrink_preserve_parameters() | Handle size reductions |
| 4 | Network replacement | Update instance networks |

 The reconstruction system ensures evolutionary changes don't completely discard learned representations, maintaining training stability across generations.

## Alternative Approaches and Migration

 Given the deprecation warning, users should consider migrating to direct `EvolvableModule` implementations:

 
### Recommended Migration Path

 
 - **Analyze current architecture**: Use `MakeEvolvable` temporarily to understand structure
 - **Create custom EvolvableModule**: Implement network directly inheriting from `EvolvableModule`
 - **Define mutation methods**: Implement specific mutations for your architecture
 - **Test compatibility**: Ensure evolutionary operations work correctly
 
 This approach provides better control over the evolutionary process and eliminates the architecture detection overhead.
