## Off-Policy Algorithms

 Off-policy algorithms learn from experiences that may have been generated by a different policy than the one being updated. These algorithms typically use a replay buffer to store and sample past experiences.

 
### DQN (Deep Q-Network)

 DQN is a value-based algorithm that learns the optimal action-value function (Q-function) using neural networks. It uses experience replay and target networks to stabilize learning.

 
```

```

 Key features:

 
 - Uses Q-learning with neural networks
 - Experience replay buffer to break correlations between consecutive samples
 - Target network to provide stable learning targets
 - Optional double Q-learning to reduce overestimation bias
 
 Implementation:

 
 - Class: `DQN` in [agilerl/algorithms/dqn.py22-408](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/algorithms/dqn.py#L22-L408)

### DDPG (Deep Deterministic Policy Gradient)

 DDPG is an actor-critic, model-free algorithm that extends DQN to work with continuous action spaces. It learns a deterministic policy that directly maps states to actions.

 
```

```

 Key features:

 
 - Actor-critic architecture with deterministic policy
 - Exploration using Ornstein-Uhlenbeck noise or Gaussian noise
 - Uses replay buffer and target networks for stability
 - Soft updates to target networks
 
 Implementation:

 
 - Class: `DDPG` in [agilerl/algorithms/ddpg.py32-514](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/algorithms/ddpg.py#L32-L514)

### TD3 (Twin Delayed Deep Deterministic Policy Gradient)

 TD3 is an extension of DDPG that addresses overestimation bias by using twin critics, target policy smoothing, and delayed policy updates.

 
```

```

 Key features:

 
 - Twin critics to reduce overestimation bias
 - Delayed policy updates (actor updates less frequently than critics)
 - Target policy smoothing by adding noise to target actions
 - Uses replay buffer and target networks like DDPG
 
 Implementation:

 
 - Class: `TD3` in [agilerl/algorithms/td3.py27-539](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/algorithms/td3.py#L27-L539)

### Rainbow DQN

 Rainbow DQN combines multiple improvements to DQN, including distributional RL, prioritized experience replay, dueling networks, multi-step learning, and noisy networks.

 
```

```

 Key features:

 
 - Distributional RL (C51) to model the distribution of returns
 - Prioritized experience replay to focus on important transitions
 - Noisy networks for exploration without explicit epsilon-greedy
 - Multi-step learning for better bootstrapping

## On-Policy Algorithms

 On-policy algorithms learn directly from recent experiences generated by the current policy. These algorithms typically collect experiences in batches and update the policy based on those specific batches.

 
### PPO (Proximal Policy Optimization)

 PPO is a policy gradient method that uses a surrogate objective function with clipped probability ratios to constrain policy updates, preventing too large policy changes.

 
```

```

 Key features:

 
 - Clipped surrogate objective to constrain policy updates
 - Generalized Advantage Estimation (GAE) for variance reduction
 - Multiple epochs of minibatch updates on the same trajectory
 - Supports both discrete and continuous action spaces
 - Optionally shares encoder parameters between actor and critic
 
 Implementation:

 
 - Class: `PPO` in [agilerl/algorithms/ppo.py31-547](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/algorithms/ppo.py#L31-L547)
 - Core methods: `get_action()` [agilerl/algorithms/ppo.py321-362](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/algorithms/ppo.py#L321-L362) `learn()` [agilerl/algorithms/ppo.py364-495](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/algorithms/ppo.py#L364-L495)
 - Compatible with all action space types (Discrete, Box, MultiDiscrete, MultiBinary)

## Multi-Agent Algorithms

 Multi-agent algorithms extend single-agent algorithms to environments with multiple learning agents. AgileRL implements several multi-agent variants.

 
### MADDPG (Multi-Agent Deep Deterministic Policy Gradient)

 MADDPG extends DDPG to multi-agent settings, where each agent has its own actor but uses critics that consider the joint observations and actions of all agents.

 
```

```

 Key features:

 
 - Each agent has its own actor network for decentralized execution
 - Centralized critics consider joint observations and actions
 - Extends DDPG to multi-agent settings
 - Uses a multi-agent replay buffer
 
 Implementation:

 
 - Class: `MADDPG` in [agilerl/algorithms/maddpg.py37-1233](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/algorithms/maddpg.py#L37-L1233)
 - Core methods: `get_action()` [agilerl/algorithms/maddpg.py405-508](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/algorithms/maddpg.py#L405-L508) `learn()` [agilerl/algorithms/maddpg.py543-633](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/algorithms/maddpg.py#L543-L633)
 - Supports discrete and continuous action spaces
 
 Sources:

 
 - `agilerl/algorithms/maddpg.py`
 
 
### MATD3 (Multi-Agent Twin Delayed DDPG)

 MATD3 extends TD3 to multi-agent settings with twin critics for each agent and delayed policy updates.

 
```

```

 Key features:

 
 - Twin critics for each agent to reduce overestimation bias
 - Delayed policy updates like TD3
 - Centralized critics with joint observations and actions
 - Decentralized execution with individual actor networks
 
 Implementation:

 
 - Class: `MATD3` in [agilerl/algorithms/matd3.py36-1112](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/algorithms/matd3.py#L36-L1112)
 - Similar structure to MADDPG but with twin critics and delayed updates
 - Supports discrete and continuous action spaces

## Offline Algorithms

 Offline algorithms are designed to learn from pre-collected datasets without additional environment interaction during training.

 
### CQL (Conservative Q-Learning)

 CQL addresses the overestimation issue in offline RL by learning conservative Q-functions that lower-bound the true value. AgileRL implements CQN, which is CQL applied to DQN.

 
```

```

 Key features:

 
 - Conservative value function estimation
 - Additional regularization term to penalize overestimation
 - Learns from offline datasets without environment interaction
 - Can be applied to different base algorithms (CQN is CQL + DQN)
 
 Implementation:

 
 - Class: `CQN` in [agilerl/algorithms/cqn.py21-319](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/algorithms/cqn.py#L21-L319)

## Summary

 This page has provided an overview of the reinforcement learning algorithms implemented in AgileRL, including their classification, action space compatibility, architecture, and implementation details. The algorithms range from standard off-policy methods like DQN and DDPG to on-policy methods like PPO, as well as specialized algorithms for multi-agent settings, offline learning, and more.

 Each algorithm is designed with a similar structure, inheriting from base classes that provide common functionality, but with specific implementations tailored to their unique characteristics. The modular design allows for easy extension and customization of algorithms for different environments and requirements.
