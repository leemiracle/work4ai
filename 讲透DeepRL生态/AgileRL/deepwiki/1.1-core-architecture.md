 AgileRL's architecture is built around a hierarchy of base classes that provide the foundation for all algorithms in the framework. The root class `EvolvableAlgorithm` defines the core evolutionary capabilities, while specialized subclasses handle different RL paradigms.

### NetworkGroup Configuration

 The `NetworkGroup` class defines collections of related networks that should be treated as a unit during evolution:

 
| Component | Purpose | Required | Example |
|---|---|---|---|
| eval | Network optimized during training | Yes | Actor network in DDPG |
| shared | Networks sharing parameters with eval | No | Target networks |
| policy | Marks network as policy for action selection | No | True for actor networks |
| multiagent | Indicates multi-agent network group | No | True for MADDPG actors |

 **Sources**: [agilerl/algorithms/core/registry.py204-293](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/algorithms/core/registry.py#L204-L293)

### Multi-Agent Specializations

 The `MultiAgentRLAlgorithm` class provides specialized handling for multi-agent environments:

 
| Method | Purpose | Key Features |
|---|---|---|
| get_homo_id() | Extract homogeneous agent groups | Splits agent_id on '_' pattern |
| stack_critic_observations() | Prepare centralized critic input | Handles Dict, Tuple, and Box spaces |
| extract_inactive_agents() | Handle variable agent participation | Filters NaN observations |
| assemble_homogeneous_outputs() | Batch outputs for shared policies | Optimizes computation for identical agents |
