  This document covers on-policy reinforcement learning algorithms available in AgileRL. On-policy algorithms learn from data collected by the current policy and require fresh experience collection for each learning update, unlike off-policy methods that can reuse historical data. For off-policy algorithms like DQN and DDPG, see [Off-Policy Algorithms](https://deepwiki.com/AgileRL/AgileRL/2.1-off-policy-algorithms). For multi-agent extensions of these algorithms, see [Multi-Agent Algorithms](https://deepwiki.com/AgileRL/AgileRL/2.3-multi-agent-algorithms).

 
## Overview of On-Policy Learning

 On-policy algorithms collect experience data using the current policy and immediately use that data for learning updates. This approach ensures that the learning data distribution matches the current policy, but requires more environment interactions compared to off-policy methods that can reuse stored experiences.

 AgileRL currently implements Proximal Policy Optimization (PPO) as the primary on-policy algorithm, providing support for both discrete and continuous action spaces across various observation types.

## PPO Implementation

 PPO (Proximal Policy Optimization) is implemented in the `PPO` class which inherits from `RLAlgorithm`. The algorithm uses a clipped objective function to prevent large policy updates while maintaining stable learning.

 **Key Components:**

 
 - **Actor Network**: `StochasticActor` for policy representation
 - **Critic Network**: `ValueNetwork` for value function estimation
 - **GAE**: Generalized Advantage Estimation for advantage computation
 - **Clipped Objective**: Prevents destructively large policy updates

### Learning Process

 The PPO learning process implements several key algorithmic components:

 **1. Experience Collection** The `get_action()` method samples actions from the current policy and returns action, log probability, entropy, and value estimates.

 **2. GAE Computation** Generalized Advantage Estimation computes advantage estimates using the formula:

 
```
A_t = δ_t + (γλ)δ_{t+1} + (γλ)²δ_{t+2} + ...
```

 where `δ_t = r_t + γV(s_{t+1}) - V(s_t)`

 **3. Clipped Policy Objective** The policy loss uses a clipped objective to prevent large updates:

 
```

```

 where `r_t(θ) = π_θ(a_t|s_t) / π_{θ_old}(a_t|s_t)`

## On-Policy vs Off-Policy Training

 The key architectural difference between on-policy and off-policy algorithms in AgileRL lies in their data collection and usage patterns:


 **Key Differences:**

 
| Aspect | On-Policy (PPO) | Off-Policy (DQN/DDPG) |
|---|---|---|
| Experience Usage | Fresh data only | Reuse stored experiences |
| Replay Buffer | Temporary storage | Persistent ReplayBuffer |
| Sample Efficiency | Lower | Higher |
| Policy-Data Match | Guaranteed | May diverge |
| Training Frequency | After episode collection | Every step |
