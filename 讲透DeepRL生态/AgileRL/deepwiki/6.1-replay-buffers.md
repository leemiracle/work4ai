## Purpose and Scope

 Replay buffers are core memory components in AgileRL that store and sample experiences for off-policy reinforcement learning algorithms. This document covers the standard, multi-step, and prioritized replay buffer implementations, along with their sampling mechanisms. For multi-agent replay buffers, see [Multi-Agent Replay Buffers](https://deepwiki.com/AgileRL/AgileRL/6.2-multi-agent-replay-buffers). For information about how replay buffers integrate with training loops, see [Off-Policy Training](https://deepwiki.com/AgileRL/AgileRL/3.1-off-policy-training) and [Offline Training](https://deepwiki.com/AgileRL/AgileRL/3.3-offline-training).

 
## System Overview

 AgileRL provides three main replay buffer implementations that handle experience storage and sampling for different off-policy learning scenarios. All replay buffers use TensorDict as the underlying storage format and support circular buffering for memory efficiency.

## Standard ReplayBuffer

 The `ReplayBuffer` class provides the foundation for experience storage in off-policy learning. It implements a circular buffer that automatically overwrites old experiences when the buffer reaches capacity.

 
### Core Features

 
| Feature | Implementation |
|---|---|
| Storage | TensorDict-based circular buffer |
| Initialization | Lazy initialization on first add() |
| Device Support | Automatic device placement |
| Sampling | Uniform random sampling |
| Data Types | Support for scalar and multi-dimensional observations |

## MultiStepReplayBuffer

 The `MultiStepReplayBuffer` extends the base replay buffer to compute n-step returns, which can improve learning efficiency by providing longer-horizon reward signals.

 
### N-Step Return Computation

 
```

```

 The n-step return calculation follows the formula: `R_t^(n) = Σ(i=0 to n-1) γ^i * R_(t+i)` where computation stops early if a terminal state is encountered [agilerl/components/replay_buffer.py235-256](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/components/replay_buffer.py#L235-L256)

 
### Key Parameters

 
| Parameter | Purpose | Default |
|---|---|---|
| n_step | Number of steps to accumulate | 3 |
| gamma | Discount factor | 0.99 |
| n_step_buffer | Temporary storage for transitions | deque(maxlen=n_step) |

 **Sources:** [agilerl/components/replay_buffer.py143-258](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/components/replay_buffer.py#L143-L258)

 
## PrioritizedReplayBuffer

 The `PrioritizedReplayBuffer` implements prioritized experience replay, which samples transitions based on their temporal difference (TD) errors rather than uniformly. This allows the agent to learn more efficiently from surprising or important experiences.

### Priority Update Process

 The prioritized replay buffer maintains two segment trees for efficient priority-based sampling:

 
 - **Sum Tree**: Stores priority^α values for efficient proportional sampling [agilerl/components/replay_buffer.py367-380](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/components/replay_buffer.py#L367-L380)
 - **Min Tree**: Tracks minimum priorities for importance sampling weight calculation [agilerl/components/replay_buffer.py397-408](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/components/replay_buffer.py#L397-L408)
 
 
### Key Methods

 
| Method | Purpose |
|---|---|
| _update_priority(idx, priority) | Updates priority in both segment trees |
| _sample_proportional(batch_size) | Samples indices based on priority distribution |
| _calculate_weights(indices, beta) | Computes importance sampling weights |
| update_priorities(indices, priorities) | Updates priorities after learning |

### Sampling Method Selection

 The sampler automatically selects the appropriate sampling method during initialization based on buffer type detection [agilerl/components/sampler.py66-102](https://github.com/AgileRL/AgileRL/blob/03307c7b/agilerl/components/sampler.py#L66-L102):

 
| Buffer Type | Detected Method | Key Features |
|---|---|---|
| PrioritizedReplayBuffer | sample_per | Requires β parameter for importance sampling |
| MultiStepReplayBuffer | sample_n_step | Samples from specific indices |
| Standard buffers | sample_standard | Uniform random sampling |
| Distributed setup | sample_distributed | Uses DataLoader with custom collate function |
