  This page documents the actor-critic algorithms implemented in the ReAgent reinforcement learning framework. Actor-critic methods combine policy-based and value-based approaches to reinforcement learning, where an actor (policy) determines which actions to take and a critic (value function) evaluates those actions. For related DQN-based approaches, see [DQN and Variants](https://deepwiki.com/facebookresearch/ReAgent/3.1-dqn-and-variants).

 
## Overview of Actor-Critic Architecture

 Actor-critic methods in ReAgent consist of two primary components that work together during training:

 
 - **Actor Networks**: Policy networks that map states to actions
 - **Critic Networks**: Value or Q-function networks that evaluate states or state-action pairs

### Soft Actor-Critic (SAC)

 SAC is an off-policy actor-critic algorithm that incorporates entropy maximization to encourage exploration. It's particularly effective for continuous action spaces.

 Key characteristics:

 
 - Uses a stochastic policy with Gaussian noise
 - Employs twin Q-networks to reduce overestimation bias
 - Optionally uses a separate value network
 - Includes entropy regularization with optional automatic temperature adjustment
 
 The algorithm's training process follows these steps:

 
 - Compute target Q-values using target networks
 - Update Q-networks to minimize TD error
 - Update actor to maximize expected Q-value and entropy
 - Optionally update entropy coefficient (alpha)
 - Perform soft updates of target networks

### Twin Delayed DDPG (TD3)

 TD3 is an off-policy algorithm that addresses limitations of DDPG by using twin critics and delayed policy updates to reduce overestimation bias.

 Key characteristics:

 
 - Uses a deterministic policy with noise for exploration
 - Employs two Q-networks with the minimum used for targets
 - Implements delayed policy updates
 - Applies target policy smoothing by adding noise to actions
 
 The training process includes:

 
 - Compute target Q-values using both target networks and taking the minimum
 - Update both Q-networks to minimize TD error
 - On specified iterations, update actor to maximize Q-value
 - Perform soft updates of target networks

### Proximal Policy Optimization (PPO)

 PPO is an on-policy actor-critic algorithm that uses clipped importance sampling to prevent large policy updates, making training more stable.

 Key characteristics:

 
 - Uses a stochastic policy
 - Optionally employs a value network as a baseline
 - Implements clipped surrogate objective
 - Supports entropy bonus to encourage exploration
 
 The training process includes:

 
 - Collect trajectories using current policy
 - Compute advantages using rewards and value function
 - Optimize the clipped PPO objective
 - Optionally optimize the value network to better predict returns

## Network Architectures

 
### Actor Networks

 ReAgent provides multiple actor network implementations for different types of action spaces and stochasticity requirements:

 
 - **FullyConnectedActor** [reagent/models/actor.py44-110](https://github.com/facebookresearch/ReAgent/blob/9e707c09/reagent/models/actor.py#L44-L110):

 
 - Deterministic actor for continuous action spaces
 - Optionally adds Gaussian noise for exploration
 - Returns actions and optional log probabilities
 - **GaussianFullyConnectedActor** [reagent/models/actor.py113-261](https://github.com/facebookresearch/ReAgent/blob/9e707c09/reagent/models/actor.py#L113-L261):

 
 - Stochastic actor that outputs mean and standard deviation for Gaussian sampling
 - Primarily used in SAC
 - Uses reparameterization trick for differentiable sampling
 - Applies tanh squashing to bound actions
 - **DirichletFullyConnectedActor** [reagent/models/actor.py264-324](https://github.com/facebookresearch/ReAgent/blob/9e707c09/reagent/models/actor.py#L264-L324):

 
 - Stochastic actor that samples from a Dirichlet distribution
 - Useful when actions must sum to 1 (e.g., resource allocation)
 
 All actor networks in ReAgent inherit from the `ModelBase` class and implement the standard interface with `input_prototype()` and `forward()` methods.

### Critic Networks

 The primary critic implementation in ReAgent is `FullyConnectedCritic` [reagent/models/critic.py37-92](https://github.com/facebookresearch/ReAgent/blob/9e707c09/reagent/models/critic.py#L37-L92) which:

 
 - Takes both state and action as input
 - Concatenates state and action features
 - Processes the combined features through fully connected layers
 - Outputs a scalar Q-value or value estimate
 
 The network can be customized with different layer sizes, activation functions, and normalization options.

## Training Framework

 All actor-critic algorithms in ReAgent leverage PyTorch Lightning for standardized training through the `ReAgentLightningModule` base class [reagent/training/reagent_lightning_module.py19-203](https://github.com/facebookresearch/ReAgent/blob/9e707c09/reagent/training/reagent_lightning_module.py#L19-L203)

 Key aspects of the training framework:

 
 - **Generator-based Training Step**:

 
 - Each trainer implements `train_step_gen()` which yields losses
 - `training_step()` in the base class manages the generator
 - **Optimizer Configuration**:

 
 - Each trainer defines its optimizers in `configure_optimizers()`
 - Typically includes optimizers for actor, critic(s), and target network updates
 - **Soft Updates for Target Networks**:

 
 - Implemented via `SoftUpdate` optimizer
 - Controls the rate of update through the `tau` parameter

## Common Configuration Parameters

 Actor-critic methods in ReAgent share several important configuration parameters:

 
| Parameter | Description | Default | Used In |
|---|---|---|---|
| gamma | Discount factor for future rewards | 0.99 | All algorithms |
| tau | Target network soft update rate | 0.005 | SAC, TD3 |
| learning_rate | Learning rate for optimizers | Algorithm-specific | All algorithms |
| entropy_temperature | Temperature parameter for entropy regularization | 0.01 (SAC) | SAC |
| target_entropy | Target entropy for automatic temperature tuning | -1.0 (SAC) | SAC |
| noise_variance | Variance of exploration noise | 0.2 (TD3) | TD3 |
| delayed_policy_update | Frequency of policy updates | 2 (TD3) | TD3 |
| ppo_epsilon | Clipping parameter for importance sampling | 0.2 (PPO) | PPO |
| update_epochs | Number of epochs to train on collected data | 1 (PPO) | PPO |

## Integration with ReAgent Framework

 Actor-critic methods integrate with the broader ReAgent framework through several key interfaces:

 
 - **Model Managers**: Manage the training workflow and configuration
 - **Data Modules**: Handle preprocessing and batching of training data
 - **PyTorch Lightning**: Provides training loop infrastructure
 - **Evaluation**: Offers offline and online policy evaluation
 
 The typical workflow involves:

 
 - Creating actor and critic networks
 - Initializing the appropriate trainer
 - Setting up a PyTorch Lightning Trainer
 - Running training with data from ReAgent's data modules

## Summary

 ReAgent's actor-critic implementations provide a flexible framework for reinforcement learning across different environments and requirements:

 
 - **SAC**: Best for continuous control tasks requiring exploration
 - **TD3**: Suitable for stable learning in continuous action spaces
 - **PPO**: Good for on-policy learning with controlled policy updates
 
 These implementations leverage modern deep learning practices through PyTorch Lightning integration and provide customizable network architectures to adapt to different problem domains.
