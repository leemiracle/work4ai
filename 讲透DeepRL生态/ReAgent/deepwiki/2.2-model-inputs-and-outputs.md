## Input Types

 ReAgent models use different input types depending on the algorithm being used. All input types derive from `BaseInput` and add fields specific to their algorithm needs.

 
### BaseInput

 The `BaseInput` class serves as the foundation for all model inputs, containing common fields like:

 
 - `state`: Current state features
 - `next_state`: Next state features
 - `reward`: Received reward
 - `time_diff`: Time difference between states
 - `not_terminal`: Boolean flag indicating if the state is non-terminal
 
 
```

```

 Sources: [reagent/core/types.py692-1027](https://github.com/facebookresearch/ReAgent/blob/9e707c09/reagent/core/types.py#L692-L1027)

 
### Algorithm-Specific Inputs

 Different ReAgent algorithms use specialized input classes that inherit from `BaseInput`:

 
| Input Type | Description | Key Fields |
|---|---|---|
| DiscreteDqnInput | For DQN with discrete action space | action, next_action, possible_actions_mask |
| SlateQInput | For slate recommendation | action, next_action, reward_mask |
| ParametricDqnInput | For DQN with continuous action space | action, next_action, possible_actions, possible_actions_mask |
| PolicyNetworkInput | For policy-based methods | action, next_action |
| PolicyGradientInput | For policy gradient methods | state, action, reward, log_prob |
| MemoryNetworkInput | For memory-based networks | action, valid_step |

 Sources: [reagent/core/types.py776-1027](https://github.com/facebookresearch/ReAgent/blob/9e707c09/reagent/core/types.py#L776-L1027)

 For special use cases like ranking, additional input structures like `PreprocessedRankingInput` are available. These contain fields for source sequences, target sequences, and related information needed for sequence-to-sequence modeling.

 Sources: [reagent/core/types.py454-673](https://github.com/facebookresearch/ReAgent/blob/9e707c09/reagent/core/types.py#L454-L673)

## Model Outputs

 Model outputs vary by algorithm type but follow consistent patterns based on the task.

 
### Common Output Structures

 Several common output structures are used across models:

 
| Output Type | Description | Key Fields |
|---|---|---|
| ActorOutput | Output from actor models | action, log_prob, squashed_mean |
| SyntheticRewardNetworkOutput | From reward prediction models | predicted_reward, mask, output |
| Raw Q-values | From Q-learning models | Tensor of Q-values for each action |
| Probabilities | From policy models | Action probabilities |

## Summary

 ReAgent's model I/O system provides a consistent interface across different RL algorithms through:

 
 - **Standardized input/output data structures**: Based on `TensorDataClass`, providing tensor-like functionality
 - **Algorithm-specific input types**: Each inheriting from `BaseInput` with specialized fields
 - **Flexible preprocessing pipeline**: Transform components that can be composed to handle various data formats
 - **Consistent serving interface**: Predictor wrappers that standardize the deployment interface
 
 This design enables ReAgent to support a wide range of RL algorithms while maintaining a consistent developer experience.
