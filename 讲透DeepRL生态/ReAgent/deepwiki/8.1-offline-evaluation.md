  Offline Evaluation in ReAgent is a system for evaluating trained or in-training reinforcement learning policies without requiring live environment interaction. This document focuses on the implementation and usage of offline evaluation methods in ReAgent, particularly for Contextual Bandits (CB).

 For information about model training, see [Training System](https://deepwiki.com/facebookresearch/ReAgent/4-training-system).

 
## 1. Overview of Offline Evaluation

 Offline evaluation allows researchers and practitioners to evaluate the performance of RL policies using historical data (logs). This is particularly useful for:

 
 - Evaluating policy performance before deployment
 - Comparing multiple policies without live testing
 - Monitoring policy learning during training
 - Detecting potential issues before deployment
 
 ReAgent implements offline evaluation based on importance sampling techniques, which allows for unbiased evaluation of policies using logged data from a different policy.

 - Processes incoming batches of data
 - Keeps track of rewards and weights
 - Aggregates metrics across distributed training instances

## 4. Metrics and Data Tracking

 The offline evaluator tracks a comprehensive set of metrics to assess policy performance:

 
| Metric | Description | Buffer Name |
|---|---|---|
| Average Reward | Average reward obtained by the policy | sum_reward_importance_weighted_accepted / sum_importance_weight_accepted |
| Acceptance Rate | Fraction of data points where logged action matches model action | frac_accepted |
| Total Weight | Total weight of processed data points | sum_weight_all_data |
| Used Weight | Weight of data points where logged action = model action | sum_weight_accepted |
| Avg Reward (Accepted) | Average reward on data points where actions match | avg_reward_accepted |
| Avg Reward (Rejected) | Average reward on data points where actions don't match | avg_reward_rejected |
| Reward Ratio | Ratio of rewards between accepted and rejected data | accepted_rejected_reward_ratio |
| Avg Size | Average action slate size for accepted data | avg_size_accepted |
| Model Updates | Number of times the evaluated model was updated | num_eval_model_updates |

 The evaluator maintains both local buffers (for the current training instance) and global buffers (aggregated across distributed training). This design supports distributed training scenarios.

### 5.2 Training-Evaluation Cycle

 The integration creates a cycle where:

 
 - The trainer processes a batch of data
 - The model is updated
 - The evaluator processes the same batch with the current model
 - Periodically, the evaluator's model is updated to match the current training model
 - Metrics are logged throughout this process
 
 This approach allows for tracking how policy performance evolves during training.

## 7. Limitations and Considerations

 When using offline evaluation in ReAgent, consider these important limitations:

 
 - **Support Overlap**: Importance sampling requires support overlap - the logging policy must have non-zero probability for actions that the evaluated policy would take.
 - **High Variance**: Importance weights can have high variance, especially with deterministic policies. Consider using `max_importance_weight` to cap these values.
 - **Model Updates**: The frequency of model updates affects the evaluation results. Too frequent updates might not reflect deployment scenarios accurately.
 - **Distributional Shift**: Offline evaluation assumes the data distribution is stationary. If the environment changes over time, evaluation results may not be reliable.
 - **Action Matching**: The current implementation primarily focuses on exact action matching. For continuous action spaces or slate recommendations, more sophisticated techniques may be needed.
 
 
## 8. Summary

 ReAgent's offline evaluation system provides a robust framework for assessing policy performance without requiring environment interaction. By leveraging importance sampling and tight integration with the training loop, it enables reliable policy evaluation throughout the training process.

 The system is particularly well-suited for contextual bandit scenarios but can be extended to other reinforcement learning paradigms. Its distributed design supports scaling to large datasets across multiple training instances.
