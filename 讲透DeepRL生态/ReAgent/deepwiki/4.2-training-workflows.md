  This page documents the training workflows in ReAgent, focusing on how the framework orchestrates the end-to-end process from feature identification to model training, validation, and publishing. For information about specific model types, see [Models and Algorithms](https://deepwiki.com/facebookresearch/ReAgent/3-models-and-algorithms). For details about the base training module, see [ReAgentLightningModule](https://deepwiki.com/facebookresearch/ReAgent/4.1-reagentlightningmodule).

 
## Overview

 Training workflows in ReAgent manage the complete machine learning lifecycle, connecting data extraction, preprocessing, model configuration, training, evaluation, and deployment. The framework is designed to be modular, allowing different algorithms to share a common training infrastructure while implementing their unique aspects.

## Key Components

 
### ModelManager

 The `ModelManager` class is the central abstraction for training algorithms in ReAgent. Each RL algorithm implementation (DQN, Actor-Critic, etc.) extends this class to define algorithm-specific behavior while reusing the common training infrastructure.

### Training Entry Points

 ReAgent provides functions that orchestrate the training process:

 
 - `identify_and_train_network()` - Main entry point that:

 
 - Takes a table specification (`TableSpec`) and model configuration
 - Performs feature identification
 - Calls `query_and_train()`
 - `query_and_train()` - Orchestrates the core training flow:

 
 - Queries data based on the table specification
 - Builds the trainer module
 - Runs the training process
 - Handles validation and publishing
 - `train_workflow()` - Executes the actual training:

 
 - Sets up TensorBoard logging
 - Initializes the data module
 - Builds the trainer
 - Trains the model using PyTorch Lightning
 - Saves trained models as TorchScript modules

### Feature Identification

 The feature identification process:

 
 - Uses `identify_normalization_parameters()` to determine statistics of the input features (mean, stddev, etc.)
 - Creates normalization parameters for each feature
 - Stores the parameters in a `NormalizationData` object
 
 
### Data Modules

 ReAgent uses `ReAgentDataModule` and its subclass `ManualDataModule` to handle data processing:

 
 - **Data Preparation**:

 
 - `prepare_data()` - Runs feature identification and queries data
 - `setup()` - Prepares the data for training
 - **Data Loading**:

 
 - `train_dataloader()` - Returns training data
 - `test_dataloader()` - Returns testing data
 - `val_dataloader()` - Returns validation data
 - **Preprocessing**:

 
 - `build_batch_preprocessor()` - Creates a preprocessor for batches
 - Each algorithm defines its own batch preprocessor (e.g., `DiscreteDqnBatchPreprocessor`)

 The model training process uses PyTorch Lightning for standardized training loops:

 
 - Each `ModelManager` implementation defines `build_trainer()` which:

 
 - Creates neural networks specific to the algorithm
 - Returns a `ReAgentLightningModule` (e.g., `DQNTrainer`, `SACTrainer`)
 - The `train_eval_lightning()` function:

 
 - Sets up the PyTorch Lightning trainer
 - Calls `trainer.fit()` to execute training
 - Optionally runs testing with `trainer.test()`
 - Saves checkpoints if specified
 - After training, `build_serving_modules()` converts the trained model to TorchScript for deployment

## Model Validation and Publishing

 After training, models can be validated and published:

 
 - **Validation**:

 
 - The `run_validator()` function passes the trained model to a `ModelValidator`
 - The validator evaluates the model and returns validation results
 - **Publishing**:

 
 - The `run_publisher()` function passes the trained model to a `ModelPublisher`
 - The publisher handles deployment of the model

## Conclusion

 ReAgent's training workflows provide a unified system for training different reinforcement learning algorithms. The main components are:

 
 - **ModelManager** - Abstract class defining how algorithms are built and trained
 - **Training Functions** - Orchestration of the training process
 - **Data Modules** - Handling data preprocessing and loading
 - **Training Process** - Using PyTorch Lightning for standardized training
 
 This design allows for easy implementation of new algorithms while reusing the common training infrastructure.
