# 05 — 稀疏注意力：Longformer 与 BigBird

> 04 讲长卷积（换范式）。本篇讲**不动 attention 范式，只减少 attention 看的位置**——稀疏 attention。Longformer（2020）和 BigBird（2020）是代表：让每个 token 只看"局部窗口 + 少量全局"，把 O(n²) 降到 O(nk)。

---

## 1. 灵魂：不必看全部，看够就行

$$
\boxed{\text{稀疏 attention} = \text{每个 token 只看 } k \text{ 个位置，而非 } n \text{ 个} \Rightarrow O(nk)}
$$

观察：标准 attention 里，大部分 attention 权重集中在一小部分位置。**扔掉那些接近 0 的连接，精度几乎不变**。

---

## 2. Longformer（2020）：窗口 + 全局 token

### 2.1 两种 pattern 叠加

- **滑动窗口（sliding window）**：每个 token 只看前后各 $w/2$ 个邻居（局部上下文）→ $O(nw)$
- **扩张空洞（dilated）**：窗口里跳着看（每隔 $d$ 个看一个），扩大感受野
- **全局 token（global attention）**：少数关键 token（如 [CLS]、标题）看所有位置

### 2.2 为什么有效

长文档里，大部分 token 只和**局部**相关（段落内语义）；少数关键位置（标题/问题）需要**全局**视野。Longformer 精准覆盖这两种需求。

---

## 3. BigBird（2020）：随机 + 窗口 + 全局

BigBird 把稀疏 pattern 拆成三部分：

$$
\text{BigBird} = \underbrace{\text{窗口}}_{\text{局部}} + \underbrace{\text{全局}}_{\text{关键节点}} + \underbrace{\text{随机}}_{\text{打破局部性}}
$$

**为什么加随机**：纯窗口 + 全局是"规则图"，有理论局限（某些图灵计算模拟不了）。**随机连接打破局部性**，让 BigBird 成为**图灵完备**的（理论上能模拟任意计算）。

---

## 4. 复杂度对比

| 方法 | 复杂度 | 32K 序列显存 | 质量 |
|---|---|---|---|
| 标准 attention | $O(n^2)$ | 爆 | 最好 |
| Longformer（w=512）| $O(nw)$ | 可承受 | 接近标准 |
| BigBird | $O(nk)$ | 可承受 | 接近标准 |
| Linear Attention（02）| $O(n)$ | 极省 | 略降 |

**稀疏 attention 的定位**：介于标准（精确）和 linear（近似）之间——**不近似 softmax，只稀疏化连接**。

---

## 5. 工程实用

稀疏 attention 是**最早落地**的长上下文方案：
- Longformer 支持文档级任务（>4K token）
- BigBird 用于基因组分析（序列超长）
- 2022 前的"长上下文 LLM"多用稀疏 attention

但 2023 后，**FlashAttention + 旋转位置编码**让标准 attention 能处理 32K-128K，稀疏 attention 的优势被压缩。

---

## 6. 批判性

- **稀疏 pattern 是手工设计**：窗口/全局/随机——为什么这么选？靠经验，不靠理论（BigBird 的图灵完备性是事后证明）
- **不解决根本问题**：O(n²) 变 O(nk)，但 k 仍随需求增长（要更长上下文 → k 越大）
- **被 FlashAttention 边缘化**：FlashAttention 用 tiling 让标准 attention 的显存可控，稀疏 attention 的"省显存"优势不再独特

> **诚实结论**：稀疏 attention 是"工程时代的过渡方案"——在 FlashAttention 出现前，它是长上下文的唯一选择。现在它退居特定场景（超长序列 + 低算力）。
