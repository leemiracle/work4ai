# 10 — 神经符号 AI：神经网络 + 符号逻辑的融合

> 09 讲连续生成模型。本篇跳到**非深度学习范式**——神经符号 AI（Neuro-Symbolic）。NN 擅长**感知**（看图/听声），符号逻辑擅长**推理**（三段论/数学证明）。融合两者是 AI 的"圣杯"之一。

---

## 1. 灵魂：感知 + 推理

$$
\boxed{\text{神经符号} = \underbrace{\text{NN（感知）}}_{\text{模式识别}} + \underbrace{\text{符号（推理）}}_{\text{逻辑规则}}}
$$

- 纯 NN：感知强但推理弱（hallucination / 不保证正确）
- 纯符号：推理可靠但感知弱（brittle，处理不了噪声）
- **融合**：感知用 NN，推理用符号，各取所长

---

## 2. 三种融合范式

### 2.1 松耦合（Pipelining）

NN 做感知 → 输出符号 → 符号引擎推理。

例：OCR（NN）→ 提取文字 → 规则引擎做逻辑校验。

LLM + Tool Use（如 ReAct）是这种——LLM 调用计算器/数据库（符号工具）。

### 2.2 紧耦合（Differentiable Programming）

把符号逻辑**嵌入可微计算图**，端到端训练。

代表：**DeepProbLog**（Neural LP）——概率逻辑编程，NN 输出概率 → 逻辑推理 → loss 反传。

### 2.3 嵌入式（Vectorized Symbols）

把符号表示成**向量**，在向量空间做"推理"。

代表：TransE（知识图谱嵌入）/ Neural Theorem Prover。LLM 的 in-context reasoning 某种程度是这种——符号"溶解"进向量。

---

## 3. LLM 是"弱神经符号"

LLM 用**自然语言**做"符号"——它在 token 空间里做推理（CoT 就是"内部独白"）。但：
- **没有保证**：推理链可能错（hallucination）
- **没有显式规则**：LLM 不"知道"三段论，它只是学到了"看起来像推理"的模式

真正的神经符号需要**显式逻辑约束**（如让 LLM 的输出必须满足一阶逻辑公式）。

---

## 4. 应用

- **数学证明**：LLM + Lean/Coq（Google Minerva / DeepMind AlphaProof）
- **法律推理**：NN 抽取事实 → 规则引擎判决
- **科学发现**：NN 提假设 → 符号系统验证（AI-Feynman）
- **知识图谱**：NN 补边 + 逻辑推理回答查询

---

## 5. 批判性

- **融合是"老问题"**（GOFAI vs 连接主义之争 40 年），至今没有公认最优解
- **可微编程工程难**：把逻辑嵌入梯度，常导致训练不稳/不可导点
- **LLM 让"弱融合"够用**：ReAct/Tool Use 的松耦合已经很强，纯神经符号的工程投入是否值得？

> **诚实结论**：神经符号是 AI 的"长期方向"，但 LLM + Tool Use 的"弱融合"已经覆盖了大部分需求。纯神经符号的价值在**高可靠性场景**（数学证明/法律/安全）。
