## 二、五级阶梯（资源可得性易→难 × 代价低→高，同层内按尝试序）

### Tier 0 · 免训练（成本≈0，今天就能跑）

| 方法 | 代价 | 本仓入口 | 已试 |
|---|---|---|---|
| In-Context Learning / 系统提示 | 0 | 讲透Prompt 全单元 | ✅ |
| **推理时对齐：Best-of-N** | N 次前向 | mevo/mason 已在用（采样+筛选）；**KL 上界 log n−(n−1)/n 实为上界非等式（PMLR 2025 修正）**；win rate ≤ n/(n+1)，n<1000 即有好 tradeoff | ✅ |
| 解码干预（pre/in/post-decoding 三段式，arXiv:2508.09016） | ~0 | 讲透Prompt E1（temp/top_p） | ✅ |
| 检索增强（RAG，六维分类中独立于微调） | 建索引 | 讲透RAG | ✅ |

**边界（2508.09016 三挑战）**：泛化差（不见对抗例）/ 推理延迟 / 通用能力可能被 in-decoding 干扰——**TF 是权宜不是替代**。

### Tier 1 · 生成数据 + 免权重更新（API 成本，1-3 天）

| 方法 | 代价 | 本仓入口 |
|---|---|---|
| Self-Instruct / Evol-Instruct（自产数据） | API 生成 | GLM 通道现成 |
| RLAIF（AI 反馈替代人工） | API | mason/GLM 当 judge |
| STaR（生成-筛选-微调的"筛选"半部） | API+验证器 | **数学域天然版：Lab v2 win/trap 库** |

### Tier 2 · 轻量权重更新（单卡级，本机 CPU 即可 0.5B；C500 可 7B）

| 方法 | 参数量 | 代价 | 本仓入口 | 排序理由 |
|---|---|---|---|---|
| **LoRA（+QLoRA 需 bitsandbytes，未装→先纯 LoRA）** | 0.1-1% | 本机 0.5B CPU 小时可训 | peft 0.20 ✓ 就绪 | **第一试**：生态最成熟 |
| Prompt/Prefix/P-Tuning v2 | 极小 | 同上 | peft 全支持 | 第二试：连续前缀 |
| BitFit / IA³ | 最小 | 同上 | peft ✓ | 学术对照用 |
| **SFT（指令/多任务/对话/领域四变体）** | 全参 | 0.5B 本机 / 7B 走 C500 | datasets+transformers Trainer | LoRA 的载体；数学域=SFT 冷启动（#102 判据：看泛化 loss 非看 SFT 分） |

### Tier 3 · 偏好优化（需偏好数据，成对标注是主要成本）

**排序（按数据标注成本从低到高）**：KTO（好/坏二元标签，最便宜）→ SimPO（无参考模型，省一份显存）→ DPO（成对）→ IPO（DPO+正则，防过拟合）→ ORPO（SFT+偏好一步，省阶段）→ RSO（拒绝采样造偏好对，借 Tier 1 生成）→ SLiC/Cringe（学术线）→ **PPO-RLHF（最贵：RM+策略+参考三模型）**
- **本仓第一试：KTO 或 SimPO**（trl 支持——注意 trl 未装，`pip install trl` 或手写 loss，DPO loss 20 行可手写）
- **数学域捷径：RLVR 天然偏好对**——同一猜想 PASS/FAIL 即 chosen/rejected（验证器免费造偏好数据，跳过人工标注）
- #102 铁律带入：RSFT 先于 PPO；RM<70% 准确率不上 RLHF

### Tier 4 · 自我改进闭环（Tier 1+2+3 组合，计算型研究）

| 方法 | 本仓对应 |
|---|---|
| STaR/ReST/SPIN（自生自筛自训） | **Lab v2 的正式形态**：bandit 选支→生成猜想→五通道验证→win/trap 入库→（下一版）回灌 SFT |
| RLVR/GRPO（可验证域 RL） | 13 节点 C500 可跑 GRPO（数学域 reward=z3/lean 判定）；#102 判据全部适用 |
| 工具/Agent 微调 | 讲透Agent 实战案例群 |

### Tier 5 · 精准干预与治理（效果高但工程/风险成本高，按需）

模型编辑 ROME/MEMIT（事实级，定位-编辑）｜遗忘学习 Unlearning（合规）｜宪法 AI+红队（安全）｜持续预训练（=mid-training，#101 已全解）｜模型合并 TIES/DARE（后处理）｜多模态指令微调（需新数据模态，本仓暂无此需求）

## 四、六维分类法对位（arXiv:2608.06246，治理视角）

mechanism（改权重/改输入/改检索）× goal × data × **persistence（权重持久 vs 推理瞬时）** × scope × model type——本卡阶梯与其 persistence 维正交：Tier 0=瞬时，Tier 2+=持久。**术语混淆警示**（该综述核心贡献）：fine-tuning≠adaptation≠prompting——治理文档必须按六维报。
