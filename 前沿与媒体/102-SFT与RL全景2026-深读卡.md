## 〇、一句话

**2026 年的裁决：SFT-then-RL 顺序流水线仍是王者——但 SFT 的目标被重新定义为"为 RL 准备最好的初始化"，而不是"拿最高 SFT 分"；且整整一代 mixed-policy 文献的增益被证明大部分来自被两个框架 bug 压低的 baseline。**

## 一、谱系与坐标（五级阶梯）

```
SFT（模仿演示）→ RSFT/RAFT（拒绝采样微调：采样像 RL、训练像 SFT）
→ DPO（偏好对直接优化，免 RM 免 PPO）→ GRPO/RLVR（免 RM 的在线 RL，验证器即奖励）
→ 混合范式（interleave/unified objective——2026 被打回，见 §二1）
```

- **统一理论**（2603.13985 综述）：**SFT = RL 的特例**（indicator reward：复现离线轨迹=1）；两范式共享优化结构，技术可互相迁移——这是 KD-RL 合流（#100 蒸馏卡 OPD=dense-reward RL）之后的第二场合流
- **RSFT 的枢纽地位**（ai-infrastructure 一手）：采样像 RL（生成 N 个、打分）+训练像 SFT（只训保留集）——WebGPT/Anthropic HH/Llama2-3/Tülu 3 管线全用它；**BoN 是它的推理侧孪生**（不改权重，KL 有闭式 log N −(N−1)/N）

## 二、2026 四大裁决（全部一手）

### 1. Baseline 审判日（2604.23747，最爆炸）

mixed-policy 方法（interleave SFT/RL）的已发表增益，大部分源于**两个框架 bug 压低的 SFT baseline**：DeepSpeed CPU-offload 优化器静默丢 micro-batch（殃及 TRL/OpenRLHF/Llama-Factory）+ OpenRLHF loss 聚合错权。修复后标准 SFT-then-RL **反超全部 5 个 mixed-policy 方法**（Qwen2.5-Math-7B +3.8 / Llama-3.1-8B +22.2），且 **50 步 RL 就够**（更少 FLOPs）。机理：SFT 先把模型 bootstraps 进"能稳定产出正确解"的区域，RL 从第一步就有 dense reward；混合法在模型还不会做题时 RL 信号≈0。**教训：跨框架验证是刚需——静默 bug 足以掀翻一代文献**（本仓 E2/E3 解析器 bug 三连的领域级版本）。

### 2. Quagmires：高 SFT 分会骗人（2510.01624，1M GPU 小时/12B/数百模型）

RL 后终局与 SFT 分数**不相关甚至负相关**：SFT 分偏向简单/同质数据；短样本训出的 SFT 分更高但 RL 后更差；同预算 1 epoch 全集 < 2 epoch 半集的反直觉反转。**可靠预测指标**：held-out 泛化 loss + Pass@large k（R²/Spearman +0.5，翻倍）。工程含义：选 SFT 配方别看 SFT 榜，看泛化余量与多样性。

### 3. PEAR：离线-在线分布错配的修正（2602.01058）

强 SFT checkpoint 在 RL 后可能被弱者反超（rank reversal）——根因=offline 数据分布（behavior policy）≠ 在线 rollout 分布（target policy）。**解法**：OPE 启发的重要性采样 reweight SFT loss（token/block/sequence 三级，plug-in 兼容 SFT 与 KL 蒸馏），AIME-2025 pass@8 +14.6%。**原则：offline 阶段应优先"目标策略下可复现的成功"，不是离线分**。（与 OPD 暴露偏置 O(εT²) 同一根病的 SFT 侧药方。）

### 4. 生产实践法则（TildAlice 一手，三部署复盘）

SFT 赢 ~60% 场景：数据效率 500 例 vs 5000 偏好对、迭代快 6-8×、一个旋钮（loss 降不降）vs RLHF 五个失败点。**RSFT > PPO**（一周 PPO → 4 小时 RSFT+过夜 SFT，成本 -90%）；多任务混 10-20% 通用数据防遗忘（比 KL 便宜）；reward model 排名准确率 <70% 就别上 RLHF。前 3-4 轮迭代全是数据质量问题，不是算法选择问题。

## 三、与 RLHF/DPO/GRPO 家族的对位（本仓 03 章骨架 + 增量）

| 方法 | 奖励来源 | 稳定性 | 天花板 | 何时选 |
|---|---|---|---|---|
| SFT | 演示数据 | ★★★ | 模仿上限 | 冷启动/数据少/前几轮迭代 |
| RSFT/RAFT | RM 或验证器（离线筛） | ★★★ | 单轮筛选上限 | 有 RM 但怕 RL 工程复杂度 |
| DPO | 偏好对 | ★★ | 偏好数据上限 | 有成对标注、要快 |
| GRPO/RLVR | 确定性验证器 | ★★ | **base 已有能力**（RLVR 极限） | 数学/代码等可验证域 |
| OPD（#100） | teacher dense 信号 | ★★ | teacher 上限-分布差 | 有强 teacher logits |
| mixed | 以上混合 | ★ | — | **2026 裁决：先修 baseline 再谈** |

## 四、失败模式与铁律

1. **SFT 过训伤 RL**：多 epoch SFT 分涨但泛化 loss 爆、RL 潜力降（Quagmires）——早停看泛化
2. **熵塌缩/长度膨胀**（GRPO 系）——KL mixing/熵门控（#100 §2.2 同款药）
3. **Reward hacking**：RM 准确率 <70% 放大错误；长度与质量被混淆——RSFT 只筛不优化进 RM 面，天然免疫
4. **一致性缺失**：binary reward 被走捷径绕过（本仓 Prover R3——过程结构本身值得奖励）
5. **静默框架 bug**：跨框架验证（verl vs OpenRLHF 对账）；本仓同构教训=E1/E3 解析器 bug 曾污染结论
6. **SFT 通用性损失**：混 10-20% 通用数据（生产法则）；mid-train 混通用数据防遗忘（#101 同构）

## 六、决策树

```
你的奖励从哪来？
├─ 有高质量演示（<5k）→ SFT（混 10-20% 通用数据；早停看 held-out 泛化 loss）
├─ 有验证器/可编程 checker
│   ├─ 怕工程复杂 → RSFT（N=10-30/prompt，生成与训练解耦，vLLM 生成）
│   └─ 要推到极限 → SFT 冷启动 → GRPO/RLVR（SFT 目标=为 RL 初始化：PEAR 式 reweight）
├─ 只有偏好对 → DPO
├─ 有强 teacher logits → OPD（#100 配方）
└─ 想要 mixed-policy → 先跑修好 bug 的 SFT-then-RL baseline（50 步 RL 版），赢过再发
通用收尾三问：熵塌了吗？被 gaming 吗？baseline 换框架复算过吗？
```
