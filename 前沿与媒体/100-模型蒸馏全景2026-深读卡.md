## 〇、一句话

**蒸馏已经从"让小模型模仿大模型输出"的压缩技巧，演化成 LLM 后训练的主范式——on-policy distillation（OPD）本质上是用 teacher 的 dense token 信号做 on-policy RL，KD 与 RL 在 2026 年正式合流。**

## 二、OPD 理论核心（2026 四大成果，全部一手核实）

### 2.1 为什么必须 on-policy：暴露偏置（arXiv:2604.00626 综述）

off-policy（SFT on teacher 数据）训的是"完美 teacher 前缀上的下一步"，推理时 student 面对自己的错误前缀——误差随序列长度**平方级复合 O(εT²)**。OPD 让 teacher 在 **student 自己访问的状态**上给反馈，把复合项压回线性——理论根基即经典 DAgger（Ross et al. 2011）。三维分类：**反馈信号**（logit/outcome/self-play）× **teacher 访问**（白盒/黑盒/teacher-free）× **损失粒度**（token/序列/混合）。

### 2.2 解耦定理：四目标统一（arXiv:2605.16826，2026-05）

此前范式隐式捆绑了两个正交选择——**prefix 来源 × KL 方向**。解耦后四格全部合法且各有其名：

| | forward KL | reverse KL |
|---|---|---|
| **teacher prefix** | off-policy SFT（=R1/s1 配方） | offline-RL 式蒸馏（几乎无人研究） |
| **student prefix** | DAgger 式 on-policy SFT | **OPD**（=dense log-ratio reward 的 on-policy RL） |

梯度级恒等式：forward KL ⇒ SFT 式交叉熵软目标；reverse KL ⇒ RL 式策略梯度（teacher-student log-ratio 当 dense reward）。**KD 与 RL 的合流在此被数学钉死。**

三大 tradeoff（受控实验，Qwen3-4B/8B→0.6B）：①KL 方向=精度-熵（rev-KL 提 Avg@k 但熵塌缩伤 Pass@k）②prefix 来源=质量-算力 ③训练长度=精度-稳定。**落地两招**：KL mixing（长序列蒸馏需显著 fwd-KL 权重防熵塌缩）；**entropy-gated length curriculum**（熵门槛控制训练长度爬坡：Avg@k +3.6、长度 ÷3）。

### 2.3 病理学：OPD 是探索催化剂不是能力天花板（arXiv:2607.13399，2026-07）

- **OPD 的角色**：dense token 级引导把 student 导向正确推理路径——**不扩展能力上限**（与 RLVR 极限论文"蒸馏扩边界、RLVR 榨取"互为镜像：蒸馏引入 teacher 有的新模式，OPD 在 student 分布内导航）
- **两病**：Student-Teacher Mismatch（分布差距大时引导信号与任务正确性错位，把探索带沟里）；**Length Exploitation**（聚合 token 目标制造长度捷径：截断/冗余填充刷分）
- **两药**：advantage clipping + log-scale 信号压缩——"信号质量而非 teacher 规模决定探索成败"
- prompt 多样性 > 单题采样数（数据策展再次压过算力堆叠）

### 2.4 公式驱动分类（arXiv:2606.22793）：feedback-to-update 问题观

OPD 不是损失函数家族而是**反馈→更新的管线**，五变量必须一起设计：状态来源 × 支持集 × 散度 × **时间 credit**（immediate/return-to-go/discounted/baseline-corrected；提出 GAE-OPD 假设）× **词表路由**（负采样反馈只压制不替代→提出 CR-OPD：把概率质量路由到 teacher 支持且 student 可达的替代 token）。工业四管线（Qwen/MiMo/GLM-5/DeepSeek-V4）全部落地为基础设施。

## 三、工程配方（按约束选路，2026-08 速查）

**按 teacher 访问**：
- 白盒：**full-vocabulary logit KL**（DeepSeek-V4：cache teacher hidden states + 在线重构 logits，10T+ teacher/100K 词表可行——比 sampled-token 稳但贵；综述转引）；Lightning-OPD 预计算 teacher log-probs **4× 加速**（teacher 一致性条件下）；跨词表用 DSKD/ULD（综述转引）
- 黑盒 API：Lion（teacher 当课程设计师+弱点标注）/ GAD（判别器隐式建模 teacher 分布）/ LUFFY
- teacher-free：SPIN（自举）；**OPSDC**（同模型"简洁指令版"当 teacher，推理链压缩 **41-59%** 长度不掉点）；GATES（多采样共识门控自蒸馏，无标签无验证器场景）；**SDPO**（编译器报错/测试输出/judge 评语等**文本反馈**经自蒸馏转 dense token 信号——直击 RLVR credit assignment 瓶颈）

**按算力**（<500 GPU-h：prefix 截断 rollout + offline 缓存｜中：全 on-policy + 自适应散度｜>5000：off-policy 热身→on-policy 精修→RL 探索，Qwen3 路线）

**按任务**（数学/推理=mode-seeking reverse-KL｜开放生成=mode-covering forward-KL｜指令跟随≈λ≥0.5 混合 JSD｜多轮 agent=序列级+轨迹 credit）

## 四、与 RL 的关系（本仓一手结论 + 网络互证）

1. **RLVR 极限论文发现 6**（讲透RL/05 档案）：蒸馏**一致高于 base=边界扩展**；RLVR 只能榨取 base 已有能力——DeepSeek-R1 正式版用 R1 蒸馏到小模型传播能力，不是让小模型自己 RL
2. 2605.16826 解耦定理：OPD = dense-reward on-policy RL——**"蒸馏 vs RL"是假对立，真光谱是 reward 密度与来源**
3. 2607.13399 补镜像：OPD 不扩天花板（在 student 分布内导航）——与 1 合起来：**off-policy 蒸馏注入新模式 + OPD 导航 + RLVR 边界内榨取 = 完整流水线**（Qwen3 三段式正是它）
4. SDPO：文本反馈当桥梁，把 RLVR 的稀疏 binary reward 换成可蒸馏的 dense 信号

## 五、数学域蒸馏（本仓主场，权重之外的规律）

**Prover-V2 逆向蒸馏十条规律**（讲透Agent/实战案例，一手；ZIB The Agentic Researcher arXiv:2603.15914 ICML 2026 Oral 外部互证——科学方法论可写成戒律注入 agent）：

| 规律 | 内容 | 与 OPD 理论的对读 |
|---|---|---|
| R1 递归子目标分解 | 难度在**跨度**不在深度；V3 分解 formalize 成 have 骨架，7B 逐 sorry 填空 | 状态分解=把 teacher 可达状态变成 student 可达（mismatch 的结构性解法） |
| R2 ZPD 策展 | 冷启动只收"端到端失败但分解后子目标全解"的题 | prompt 多样性>采样数的数学版：**样本难度策展压过数量** |
| R3 一致性奖励 | binary reward 会被走捷径绕过；结构对齐本身值得奖励 | length exploitation 同族：聚合指标必被 gaming |
| R4 课程 | 子目标再生成"猜想定理"渐进爬坡 | entropy-gated curriculum 同构 |
| R5 专家迭代 | win/trap 库只追加（本仓 proof_bank 即其实现） | 数据飞轮=蒸馏与 RL 的公共基础设施 |
| R9 尺寸分工 | architect（大）×mason（小）各司其职 | teacher-student 分工不必是"蒸馏权重"，可以是**运行时协作**（universal-harness deep_plan 即此） |

本仓消费端现状：mason@C500（Prover-V2 服务化）+ 13 节点 31G 蒸馏产物（base/DPO/RLVR/SFT）= B/C 线的完整实验床；`distilled_math/` 是 D 线的概念借用（课程→人脑的"蒸馏"）——**2026-08-27 已落地**：16 域知识卡 + 16 个 SymPy 验证脚本（230+ 断言全过），方法论与产物的分工见 [top-math-courses/distilled_math/](../top-math-courses/distilled_math/README.md)（本卡=HOW 的 2026 前沿深读版；distilled_math/METHODOLOGY=本仓操作规程 + 域卡产物层）。

## 八、开放问题（四综述共识）

distillation scaling laws（尚无 Chinchilla 级定律）｜uncertainty-aware feedback（teacher 不确定时的门控）｜**agent-level distillation**（多轮、状态依赖、工具环境——OPD 综述点名的前沿，正是本仓 universal-harness 的场景）｜teacher 持续演化下的 student 适配｜低频知识保真度量

## 九、一页决策树

```
你的 teacher 能给什么？
├─ 有 logits（白盒/自托管）
│   ├─ 大算力 → full-vocab logit KL（DeepSeek-V4 式，配 hidden-state 缓存）
│   └─ 小算力 → GKD/DistiLLM 式 + Lightning-OPD 缓存
├─ 只有 API 文本（黑盒）
│   ├─ 要推理能力 → 强 teacher CoT 数据 SFT（R1 式）+ ZPD 策展
│   └─ 要持续提升 → Lion 课程 / GAD 对抗 / LUFFY
└─ 没有 teacher（self）
    ├─ 有验证器 → SDPO（文本反馈→dense 信号）
    ├─ 有文档/共识 → GATES
    └─ 要压缩推理链 → OPSDC
任何路线的收尾问句：熵塌缩了吗？长度膨胀了吗？被 gaming 了吗？（铁律 2/3/8）
```
