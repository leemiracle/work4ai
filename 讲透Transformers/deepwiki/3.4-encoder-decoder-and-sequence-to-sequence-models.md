  Encoder-decoder architectures (often referred to as Sequence-to-Sequence or Seq2Seq) are designed to map an input sequence to an output sequence of potentially different lengths. This page details the implementation of these models within the `transformers` library, focusing on the structural patterns found in models like T5, BART, mBART, and their specialized variants.

 
## Core Architecture Overview

 In the `transformers` library, Seq2Seq models typically consist of two distinct sub-modules: an **Encoder** that processes the source sequence into a latent representation, and a **Decoder** that generates the target sequence token-by-token, conditioned on the encoder's output via **cross-attention**.

 
### Data Flow and Interaction

 The interaction between the encoder and decoder is managed through the `forward` method of the top-level model class (e.g., `BartModel` or `T5Model`).

 
 - **Encoder Forward**: The `input_ids` are passed through the encoder to produce `encoder_hidden_states`.
 - **Decoder Input Preparation**: During training, `labels` are shifted right to create `decoder_input_ids` using `shift_tokens_right` [src/transformers/models/bart/modeling_bart.py58-71](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/bart/modeling_bart.py#L58-L71) For mBART, this includes wrapping the language ID token by gathering the last non-pad token [src/transformers/models/mbart/modeling_mbart.py59-76](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/mbart/modeling_mbart.py#L59-L76)
 - **Cross-Attention**: The decoder layers attend to the `encoder_hidden_states` using a cross-attention mechanism, often implemented within the `forward` pass of attention modules like `BartAttention` [src/transformers/models/bart/modeling_bart.py143-182](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/bart/modeling_bart.py#L143-L182)

## Key Model Implementations

 
### T5 and MT5

 T5 (Text-to-Text Transfer Transformer) treats every NLP task as a text-to-text problem.

 
 - **Layer Norm**: Uses `T5LayerNorm`, which is a Root Mean Square (RMS) normalization without mean subtraction or bias [src/transformers/models/t5/modeling_t5.py50-72](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/t5/modeling_t5.py#L50-L72)
 - **Gated Activations**: Supports gated-GELU variants via `T5DenseGatedActDense` [src/transformers/models/t5/modeling_t5.py97-124](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/t5/modeling_t5.py#L97-L124)
 - **Weight Tying**: T5 often ties word embeddings; in `T5Config`, the `tie_word_embeddings=False` flag (introduced in V1.1) is used to prevent scaling of decoder outputs [tests/models/t5/test_modeling_t5.py184-188](https://github.com/huggingface/transformers/blob/8f542025/tests/models/t5/test_modeling_t5.py#L184-L188)
 
 
### BART and mBART

 BART is designed for sequence-to-sequence tasks like summarization and translation.

 
 - **Positional Embeddings**: Uses `BartLearnedPositionalEmbedding`, which implements a specific offset of 2 for padding index handling [src/transformers/models/bart/modeling_bart.py74-83](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/bart/modeling_bart.py#L74-L83)
 - **Scaling**: Word embeddings are scaled by `embed_scale` via `BartScaledWordEmbedding` [src/transformers/models/bart/modeling_bart.py101-112](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/bart/modeling_bart.py#L101-L112)
 - **mBART Shifting**: Unlike BART, mBART's `shift_tokens_right` handles language-specific end-of-sentence tokens by wrapping the last non-pad token (the `<LID>` token) to the start [src/transformers/models/mbart/modeling_mbart.py59-76](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/mbart/modeling_mbart.py#L59-L76)
 
 
### SwitchTransformers (MoE)

 SwitchTransformers extends T5 into a Mixture-of-Experts (MoE) architecture.

 
 - **Router**: Implements `SwitchTransformersTop1Router`, which uses a jitter-noise mechanism during training for load balancing [src/transformers/models/switch_transformers/modeling_switch_transformers.py52-107](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/switch_transformers/modeling_switch_transformers.py#L52-L107)
 - **Expert Capacity**: Tokens are routed until an expert's `expert_capacity` is reached; `expert_capacity_mask` is used to handle overflows [src/transformers/models/switch_transformers/modeling_switch_transformers.py102-105](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/switch_transformers/modeling_switch_transformers.py#L102-L105)

## Cross-Attention Mechanism

 Cross-attention is the bridge where the decoder queries the encoder's output. In `transformers`, this is managed via `EncoderDecoderCache` during generation [src/transformers/models/bart/modeling_bart.py26](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/bart/modeling_bart.py#L26-L26)

 
| Component | Source | Role |
|---|---|---|
| Query | Decoder Hidden States | Represents the current generation context. |
| Key/Value | Encoder Hidden States | Represents the source sequence information. |
| Cache | EncoderDecoderCache | Stores cross-attention keys/values to avoid re-computation src/transformers/models/t5/modeling_t5.py26 |

 In `BartAttention`, the module distinguishes between self-attention and cross-attention based on whether `encoder_hidden_states` are passed to the forward method [src/transformers/models/bart/modeling_bart.py143-182](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/bart/modeling_bart.py#L143-L182)

## Specialized Architectures

 
### LongT5 (Local & Global Attention)

 LongT5 handles long sequences by replacing standard self-attention with more efficient variants.

 
 - **Local Attention**: Splits the sequence into blocks via `_split_into_blocks` [src/transformers/models/longt5/modeling_longt5.py105-118](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/longt5/modeling_longt5.py#L105-L118) and concatenates neighboring blocks for local context using `_concatenate_3_blocks` [src/transformers/models/longt5/modeling_longt5.py120-142](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/longt5/modeling_longt5.py#L120-L142)
 - **Radii Enforcements**: Uses `_mask_local_attention_mask` to ensure tokens do not attend beyond a defined `block_len` [src/transformers/models/longt5/modeling_longt5.py154-161](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/longt5/modeling_longt5.py#L154-L161)
 
 
### UDOP (Multimodal Seq2Seq)

 UDOP integrates visual information into the Seq2Seq framework.

 
 - **Visual Bounding Boxes**: Generates spatial coordinates for image patches using `get_visual_bbox` [src/transformers/models/udop/modeling_udop.py135-155](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/udop/modeling_udop.py#L135-L155)
 - **Output Dataclass**: Uses `BaseModelOutputWithAttentionMask` to manage multimodal attention masks [src/transformers/models/udop/modeling_udop.py97-134](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/udop/modeling_udop.py#L97-L134)
 
 
### BioGPT (Causal & Cross-Attention)

 BioGPT is a domain-specific model that uses `BioGptLearnedPositionalEmbedding` with a cumulative sum mechanism for `position_ids` based on the `attention_mask` [src/transformers/models/biogpt/modeling_biogpt.py51-76](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/biogpt/modeling_biogpt.py#L51-L76)

 
### Pop2Piano (Audio-to-MIDI)

 A T5-based architecture specialized for music. It utilizes `Pop2PianoLayerNorm` and `Pop2PianoDenseActDense`, which are RMS-based components cloned from the T5 implementation [src/transformers/models/pop2piano/modeling_pop2piano.py78-124](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/pop2piano/modeling_pop2piano.py#L78-L124)
