  Multimodal Omni models represent a class of architectures capable of processing and generating across multiple modalities—text, image, video, and audio—within a single unified framework. Unlike specialized vision-language models, Omni models often integrate multiple encoders and complex fusion strategies to handle diverse input streams simultaneously. This section also covers domain-specific specialized architectures like ESM for protein sequences, SAM for segmentation, and ModernBERT for high-efficiency encoding.

 
## Unified Multimodal Architecture: Qwen & Omni Variants

 Omni architectures typically integrate specialized encoders for different modalities which are then fused into a central LLM "Thinker" core.

 
### Vision and Rotary Embeddings

 Qwen-VL and its successors (Qwen2.5-VL, Qwen3-VL) use Multimodal Rotary Positional Embeddings (mROPE). While standard RoPE handles a single sequence dimension, mROPE expands inverse frequencies to handle temporal (T), height (H), and width (W) dimensions simultaneously [src/transformers/models/qwen2_vl/modeling_qwen2_vl.py155-163](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/qwen2_vl/modeling_qwen2_vl.py#L155-L163) The `Qwen2_5_VisionRotaryEmbedding` computes these frequencies using a `theta` parameter, typically 10000.0 [src/transformers/models/qwen2_5_vl/modeling_qwen2_5_vl.py124-133](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/qwen2_5_vl/modeling_qwen2_5_vl.py#L124-L133)

 
### Audio Pipeline in Omni Models

 The audio pipeline in Omni-style models, such as `Qwen2_5Omni`, involves sophisticated chunking and sequence reduction to align high-frequency audio data with the LLM's token space:

 
 - **Feature Chunking**: `chunk_and_pad_features` splits audio features into fixed-size windows of `n_window * 2` frames [src/transformers/models/qwen2_5_omni/modular_qwen2_5_omni.py79-111](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/qwen2_5_omni/modular_qwen2_5_omni.py#L79-L111)
 - **Convolutional Reduction**: A stride-2 convolution reduces the temporal dimension. Cumulative sequence lengths are computed via `get_audio_cu_seqlens` for Flash Attention compatibility [src/transformers/models/qwen2_5_omni/modular_qwen2_5_omni.py114-130](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/qwen2_5_omni/modular_qwen2_5_omni.py#L114-L130)
 - **Encoder Layers**: Layers like `Qwen2AudioEncoderLayer` process the features [src/transformers/models/qwen2_5_omni/modular_qwen2_5_omni.py72](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/qwen2_5_omni/modular_qwen2_5_omni.py#L72-L72)
 - **Pooling**: `get_pool_indices` identifies positions for post-encoder stride-2 average pooling to further compress the sequence [src/transformers/models/qwen2_5_omni/modular_qwen2_5_omni.py151-162](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/qwen2_5_omni/modular_qwen2_5_omni.py#L151-L162)

## MusicGen: Audio Generation

 MusicGen is a specialized auto-regressive model designed for music generation, utilizing a Transformer decoder conditioned on text or melody features.

 
### Codebook Interleaving

 MusicGen generates multiple streams of discrete acoustic units (codebooks) simultaneously. The `MusicgenSinusoidalPositionalEmbedding` produces embeddings that account for the sequence position across these parallel codebooks [src/transformers/models/musicgen/modeling_musicgen.py106-112](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/musicgen/modeling_musicgen.py#L106-L112) It dynamically expands weights via `make_weights` if the sequence length exceeds the cached embedding size [src/transformers/models/musicgen/modeling_musicgen.py145-146](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/musicgen/modeling_musicgen.py#L145-L146)

 
### Classifier-Free Guidance (CFG)

 To improve adherence to text prompts, MusicGen employs `ClassifierFreeGuidanceLogitsProcessor` during generation, which balances conditional and unconditional logits [src/transformers/models/musicgen/modeling_musicgen.py32](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/musicgen/modeling_musicgen.py#L32-L32)

## Specialized Domain Architectures

 
### ESM (Evolutionary Scale Modeling)

 The ESM family (e.g., `EsmModel`) is specialized for protein sequences. It uses a BERT-like encoder but is optimized for biological data. A key feature is the `EsmContactPredictionHead`, which performs symmetrization and Average Product Correction (APC) to predict physical distances between amino acids [src/transformers/models/esm/modeling_esm.py163-172](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/esm/modeling_esm.py#L163-L172) It utilizes a custom RoPE implementation, `EsmRotaryEmbedding` [src/transformers/models/esm/modeling_esm.py106-122](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/esm/modeling_esm.py#L106-L122)

 
### ModernBERT

 ModernBERT represents an evolution of the encoder-only architecture. It replaces the traditional BERT intermediate and output blocks with `ModernBertMLP`, which applies a GLU (Gated Linear Unit) [src/transformers/models/modernbert/modeling_modernbert.py74-91](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/modernbert/modeling_modernbert.py#L74-L91) It also supports alternating between `full_attention` and `sliding_attention` layers via its configuration [src/transformers/models/modernbert/modular_modernbert.py138-142](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/modernbert/modular_modernbert.py#L138-L142)

 
### Deepstack & Mixture-of-Experts (MoE)

 Recent Omni models like `Qwen3-VL` and `Qwen3-Omni-MoE` incorporate "Deepstack" features, which are hidden-states extracted from specific intermediate layers (e.g., layers 8, 16, 24) to provide multi-scale visual representations [src/transformers/models/qwen3_vl/modular_qwen3_vl.py85-122](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/qwen3_vl/modular_qwen3_vl.py#L85-L122) MoE variants like `Qwen3OmniMoe` use sparse blocks where `Qwen3OmniMoeThinkerTextSparseMoeBlock` routes tokens to specialized experts [src/transformers/models/qwen3_omni_moe/modeling_qwen3_omni_moe.py138-141](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/qwen3_omni_moe/modeling_qwen3_omni_moe.py#L138-L141)

 
## Key Implementation Details

 
### T5Gemma: Hybrid Seq2Seq

 T5Gemma combines the T5 encoder-decoder framework with Gemma 2 components. It uses `T5GemmaSelfAttention` (non-causal in encoder, causal in decoder) and `T5GemmaCrossAttention` for the sequence-to-sequence bridge [src/transformers/models/t5gemma/modular_t5gemma.py172-195](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/t5gemma/modular_t5gemma.py#L172-L195)

 
### Audio Codec Integration

 Specialized models like `Qwen3OmniMoe` include a `Qwen3OmniMoeCode2Wav` head, which maps predicted acoustic codes back to waveform representations using a codebook offset mechanism [src/transformers/models/qwen3_omni_moe/modeling_qwen3_omni_moe.py142-146](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/qwen3_omni_moe/modeling_qwen3_omni_moe.py#L142-L146)
