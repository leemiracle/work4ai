  Key-Value (KV) caching is a critical optimization for autoregressive generation. By storing the `key` and `value` vectors calculated during the attention mechanism for previous tokens, the model avoids redundant computations in subsequent steps [docs/source/en/kv_cache.md19-21](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/kv_cache.md?plain=1#L19-L21)

 The `transformers` library provides a pluggable architecture for KV caches, centered around the `Cache` abstract base class. This system supports various memory-efficiency and performance-optimization strategies, including dynamic resizing, static pre-allocation for `torch.compile`, and quantization [src/transformers/cache_utils.py243-255](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L243-L255)

 
## Core Abstractions

 The caching system is built on two primary levels of abstraction: the `Cache` class (which manages the entire model's state) and the `CacheLayerMixin` (which manages the state for a single attention layer) [src/transformers/cache_utils.py27-243](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L27-L243)

 
### Cache Abstract Base Class

 The `Cache` class defines the interface for all concrete implementations. Key methods include:

 
 - `update()`: Appends new key/value states to the cache for a specific layer [src/transformers/cache_utils.py244](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L244-L244)
 - `get_seq_length()`: Returns the number of tokens currently stored in the cache [src/transformers/cache_utils.py246](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L246-L246)
 - `early_initialization()`: Pre-allocates memory for static caches to avoid re-allocation during generation [src/transformers/cache_utils.py245](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L245-L245)
 - `reorder_cache()`: Reorders the cache according to beam indices during beam search [src/transformers/cache_utils.py250](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L250-L250)
 - `crop()`: Removes a specified number of tokens from the end of the cache [src/transformers/cache_utils.py251](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L251-L251)

## Concrete Implementations

 
### DynamicCache

 `DynamicCache` is the default implementation. It stores KV states as a list of `DynamicLayer` objects (one per layer). It grows dynamically as generation progresses, concatenating new tokens to existing tensors [src/transformers/cache_utils.py113-345](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L113-L345)

 
 - **Use Case:** General purpose, standard autoregressive generation [docs/source/en/kv_cache.md35-37](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/kv_cache.md?plain=1#L35-L37)
 - **Behavior:** On each `update()`, it performs a `torch.cat` operation along the sequence length dimension [src/transformers/cache_utils.py144-145](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L144-L145)
 
 
### StaticCache

 `StaticCache` uses `StaticLayer` to pre-allocate tensors of a fixed maximum length (`max_cache_len`). This allows the generation loop to have a fixed computation graph, making it compatible with `torch.compile()` [src/transformers/cache_utils.py531-535](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L531-L535) [docs/source/en/kv_cache.md70-72](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/kv_cache.md?plain=1#L70-L72)

 
 - **Update Mechanism:** Uses in-place `copy_` operations into the pre-allocated tensor rather than concatenation [src/transformers/cache_utils.py560-562](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L560-L562)
 - **Masking:** Requires an `attention_mask` to ignore the unused "future" parts of the pre-allocated buffer [docs/source/en/kv_cache.md72](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/kv_cache.md?plain=1#L72-L72)
 
 
### QuantizedCache

 `QuantizedCache` (via `QuantoQuantizedLayer` or `HQQQuantizedLayer`) reduces the memory footprint by quantizing the KV tensors. This is particularly useful for long-context generation where KV cache size can exceed weights size [src/transformers/cache_utils.py33-242](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L33-L242)

 
 - **Backends:** Supports `optimum-quanto` and `HQQ` [src/transformers/cache_utils.py8-20](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L8-L20)
 
 
### SlidingWindowCache

 Used for models like Mistral or Gemma2 that implement sliding window attention. It automatically evicts old tokens once the window size is reached [src/transformers/cache_utils.py195-200](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L195-L200)

 
 - **Entity:** Often implemented as `DynamicSlidingWindowLayer` or `StaticSlidingWindowLayer` [src/transformers/integrations/executorch.py21-25](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/executorch.py#L21-L25)
 
 
### EncoderDecoderCache

 A specialized wrapper for Seq2Seq models. It maintains separate caches for the `self_attention` (decoder) and `cross_attention` (encoder outputs) [src/transformers/cache_utils.py32-1025](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L32-L1025)

## Cache API Operations

 
### Initialization and Selection

 Users can specify the cache implementation via `GenerationConfig` or by passing an initialized object to `generate()` [docs/source/en/kv_cache.md54-55](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/kv_cache.md?plain=1#L54-L55)

 
| cache_implementation String | Concrete Class | Optimized For |
|---|---|---|
| "dynamic" | DynamicCache | Flexibility, default |
| "static" | StaticCache | torch.compile, Latency |
| "quantized" | QuantizedCache | Memory usage |
| "offloaded" | OffloadedCache | CPU offloading |

### Advanced APIs

 
 - **Early Initialization:** `StaticCache.early_initialization` allows pre-allocating memory for a specific batch size and sequence length before the first forward pass. This is crucial for hardware accelerators like TPUs or Neurons that require fixed shapes [src/transformers/cache_utils.py867-875](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L867-L875)
 - **Cropping:** The `crop(tokens_to_remove)` method is used during speculative decoding or when handling prompt lookups to discard rejected candidate tokens [src/transformers/cache_utils.py165-175](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L165-L175)
 - **Reordering:** During beam search, `reorder_cache(beam_idx)` uses `torch.index_select` to align the cache with the surviving beams [src/transformers/cache_utils.py100-104](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/cache_utils.py#L100-L104)
