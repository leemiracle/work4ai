  The Hugging Face Transformers library provides a pluggable attention system that allows models to utilize optimized hardware kernels for scaled dot-product attention. This system decouples the high-level modeling logic from the low-level kernel implementation, enabling seamless switching between `eager` (manual PyTorch), `sdpa` (PyTorch's `scaled_dot_product_attention`), `flash_attention_2/3/4`, and `flex_attention` backends.

 
## The Attention Registry and Selection

 The `attn_implementation` selection is governed by the `PreTrainedModel` lifecycle. Models indicate support for specific backends using class attributes like `_supports_sdpa`, `_supports_flash_attn`, and `_supports_flex_attn` [src/transformers/models/kyutai_speech_to_text/modeling_kyutai_speech_to_text.py94-97](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/kyutai_speech_to_text/modeling_kyutai_speech_to_text.py#L94-L97)

 The `ALL_ATTENTION_FUNCTIONS` registry maps implementation names to their respective forward callables [src/transformers/modeling_utils.py43](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/modeling_utils.py#L43-L43) This allows models to dynamically dispatch the attention computation at runtime based on the configuration or user overrides via `from_pretrained(..., attn_implementation="...")` [docs/source/en/attention_interface.md36-44](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/attention_interface.md?plain=1#L36-L44)

## Scaled Dot Product Attention (SDPA)

 `sdpa_attention_forward` is the primary wrapper for PyTorch's native `scaled_dot_product_attention`. It handles device-specific quirks and fallback logic:

 
 - **GQA Support**: It checks if Grouped Query Attention (GQA) can be used directly in the kernel via `use_gqa_in_sdpa` [src/transformers/integrations/sdpa_attention.py27-36](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/sdpa_attention.py#L27-L36)
 - **Causal Masking**: It re-evaluates `is_causal` based on sequence length and mask presence to ensure compatibility with `torch.compile` dynamic shapes. It checks `q_length > 1` and `attention_mask is None` to determine if the kernel's `is_causal` flag can be safely set [src/transformers/integrations/sdpa_attention.py108-124](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/sdpa_attention.py#L108-L124)
 - **NPU/XPU Adaptation**: On Ascend NPU, it converts masks to boolean to force the use of the `FlashAttentionScore` operator [src/transformers/integrations/sdpa_attention.py134-138](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/sdpa_attention.py#L134-L138)

## Flash Attention Integration

 The Flash Attention integration supports versions 2, 3, and 4. The `FLASH_ATTENTION_COMPATIBILITY_MATRIX` defines the requirements for each version, including minimum CUDA compute capabilities:

 
 - **Flash Attention 2**: Supports CUDA, MLU, NPU, and XPU [src/transformers/modeling_flash_attention_utils.py86-91](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/modeling_flash_attention_utils.py#L86-L91)
 - **Flash Attention 3**: Requires CUDA Compute Capability 8.0+ (Ampere) [src/transformers/modeling_flash_attention_utils.py100-110](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/modeling_flash_attention_utils.py#L100-L110)
 - **Flash Attention 4**: Requires CUDA Compute Capability 9.0+ (Hopper) [src/transformers/modeling_flash_attention_utils.py111-121](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/modeling_flash_attention_utils.py#L111-L121)

## Flex Attention

 `flex_attention` (introduced in PyTorch 2.5) provides a framework for custom attention patterns without writing manual CUDA kernels. Transformers wraps this in `WrappedFlexAttention`, a singleton class that ensures the kernel is compiled exactly once using `torch.compile` [src/transformers/integrations/flex_attention.py59-72](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/flex_attention.py#L59-L72)

 Key features include:

 
 - **Version Agnostic LSE**: Handles the transition from boolean `return_lse` (Torch < 2.9) to `AuxRequest` objects (Torch >= 2.9) via `get_flex_attention_lse_kwargs` [src/transformers/integrations/flex_attention.py100-111](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/flex_attention.py#L100-L111)
 - **Block Masking**: Uses `BlockMask` for compressed representations of causal or document-level masks [src/transformers/integrations/flex_attention.py143-168](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/flex_attention.py#L143-L168)
 - **Compilation Strategy**: On PyTorch 2.6.0, it uses `mode="max-autotune-no-cudagraphs"` to avoid known compilation issues during training [src/transformers/integrations/flex_attention.py86-89](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/flex_attention.py#L86-L89)

## Paged Attention Variants

 For high-throughput inference and continuous batching, Transformers supports "paged" variants of the attention backends. These are identified by the `paged|` prefix in the `attn_implementation` string [docs/source/en/attention_interface.md28-31](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/attention_interface.md?plain=1#L28-L31)

 
| Implementation | Paged Variant | Description |
|---|---|---|
| sdpa | paged\|sdpa | SDPA with paged KV cache management |
| flash_attention_2 | paged\|flash_attention_2 | Flash Attention 2 kernels for non-contiguous memory |
| eager | paged\|eager | Manual implementation for debugging paged logic |

 The `split_attention_implementation` utility is used to parse these strings into the `is_paged` boolean and the base `implementation` name [src/transformers/modeling_flash_attention_utils.py162](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/modeling_flash_attention_utils.py#L162-L162)
