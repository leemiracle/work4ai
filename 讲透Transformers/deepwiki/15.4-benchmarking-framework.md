  The Transformers benchmarking framework provides a standardized suite for measuring the performance of model inference, with a particular focus on modern LLM optimizations such as **Continuous Batching**, **Attention Backends** (FlashAttention-2, SDPA, FlexAttention), and **Hardware Efficiency**. The framework is primarily housed in the `benchmark_v2/` directory and integrates with GitHub Actions for automated performance regression tracking.

 
## Core Components

 The framework is built around a decoupled architecture where configurations, execution logic, and metric collection are handled by specialized classes.

 
### BenchmarkConfig

 The `BenchmarkConfig` class defines the parameters for a single execution scenario. It handles the validation of optimization combinations, such as ensuring that `flex_attention` is not used with `continuous_batching` [benchmark_v2/framework/benchmark_config.py123-127](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/framework/benchmark_config.py#L123-L127) It also manages `torch.compile` settings via `CompileConfig` [benchmark_v2/framework/benchmark_config.py94](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/framework/benchmark_config.py#L94-L94)

 Key attributes include:

 
 - **Workload**: `batch_size`, `sequence_length`, and `num_tokens_to_generate` [benchmark_v2/framework/benchmark_config.py83-85](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/framework/benchmark_config.py#L83-L85)
 - **Optimizations**: `attn_implementation` (eager, sdpa, flash_attention_2, flex_attention), `compile_config`, and `kernelize` [benchmark_v2/framework/benchmark_config.py87-95](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/framework/benchmark_config.py#L87-L95)
 - **Distributed**: `tp_plan` for Tensor Parallelism, which is translated into a `DistributedConfig` for `from_pretrained` [benchmark_v2/framework/benchmark_config.py146-158](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/framework/benchmark_config.py#L146-L158)
 
 
### BenchmarkRunner

 The `BenchmarkRunner` orchestrates the model lifecycle and execution. It is responsible for:

 
 - **Model Loading**: Initializing models using `AutoModelForCausalLM` and `AutoTokenizer` [benchmark_v2/framework/benchmark_runner.py18-20](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/framework/benchmark_runner.py#L18-L20)
 - **Memory Management**: Invoking `flush_memory` to clear CUDA caches and `torch.compile` artifacts (`torch._dynamo.reset()`, `FxGraphCache.clear()`) between runs to ensure measurement isolation [benchmark_v2/framework/benchmark_runner.py82-109](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/framework/benchmark_runner.py#L82-L109)
 - **Warmup & Measurement**: Executing the specified number of iterations to stabilize performance before recording metrics [benchmark_v2/run_benchmarks.py37-38](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/run_benchmarks.py#L37-L38)
 
 
### Metrics & Monitoring

 Metrics are captured using two primary mechanisms:

 
 - **BenchmarkResult**: Tracks high-level performance like `e2e_latency`, `time_to_first_token` (TTFT), and `inter_token_latency` (ITL) [benchmark_v2/framework/data_classes.py92-101](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/framework/data_classes.py#L92-L101)
 - **GPUMonitor**: A background process that samples GPU utilization and memory usage at a specified interval (default 0.05s) using `pynvml` (NVIDIA), `amdsmi` (AMD), or `torch.xpu` (Intel) [benchmark_v2/framework/hardware_metrics.py132-158](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/framework/hardware_metrics.py#L132-L158)

## GitHub Actions Workflows

 The framework is automated via two main workflows: `benchmark.yml` for PR/Push testing and `benchmark_v2.yml` for scheduled daily runs.

 
### Workflow Configuration

 
 - **benchmark.yml**: Triggers on pushes to `main` or when the `run-benchmark` label is added to a PR [.github/workflows/benchmark.yml3-7](https://github.com/huggingface/transformers/blob/8f542025/.github/workflows/benchmark.yml#L3-L7) It uses the `transformers-all-latest-gpu` Docker image [.github/workflows/benchmark.yml34](https://github.com/huggingface/transformers/blob/8f542025/.github/workflows/benchmark.yml#L34-L34)
 - **benchmark_v2.yml**: A reusable workflow for scheduled benchmarks, allowing configurable runners (e.g., A10) and container images [.github/workflows/benchmark_v2.yml4-30](https://github.com/huggingface/transformers/blob/8f542025/.github/workflows/benchmark_v2.yml#L4-L30)
 - **Reporting**: Results are pushed to the Hugging Face Hub as datasets (e.g., `hf-benchmarks/transformers`) for long-term tracking [.github/workflows/benchmark.yml15-58](https://github.com/huggingface/transformers/blob/8f542025/.github/workflows/benchmark.yml#L15-L58)
 
 
### Execution Steps

 
 - **Environment Setup**: Uninstalls pre-installed transformers and installs the current branch in edit mode with `[torch,kernels]` extras [.github/workflows/benchmark.yml46-47](https://github.com/huggingface/transformers/blob/8f542025/.github/workflows/benchmark.yml#L46-L47)
 - **Config Discovery**: `run_benchmarks.py` generates configurations based on a `--level` argument (1-4) or a provided `--config-file` [benchmark_v2/run_benchmarks.py45-113](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/run_benchmarks.py#L45-L113)
 - **Benchmark Run**: The `BenchmarkRunner` executes the matrix of configs and captures `GPURawMetrics` and `BenchmarkResult` [benchmark_v2/run_benchmarks.py130-133](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/run_benchmarks.py#L130-L133)

## Writing New Benchmarks

 To add new benchmark coverage, developers should interact with the `run_benchmarks.py` entry point and the `framework/` subpackage.

 
### Core Utilities

 
| Component | Responsibility |
|---|---|
| run_benchmarks.py | CLI entry point, argument parsing, and result Hub uploading benchmark_v2/run_benchmarks.py31-137 |
| BenchmarkConfig | Configuration dataclass handling validation and TP planning benchmark_v2/framework/benchmark_config.py55 |
| HardwareInfo | Collects system-level metadata (CPU count, memory total, Python/Torch versions) benchmark_v2/framework/hardware_metrics.py38-57 |
| flush_memory | Utility to prevent OOM and ensure clean measurement states by resetting torch._dynamo and clearing CUDA caches benchmark_v2/framework/benchmark_runner.py82-110 |

 
### Adding a Scenario

 
 - **Define Coverage**: Update the `all_attn_implementations` list or the `get_config_by_level` logic in `benchmark_config.py` to include new variants [benchmark_v2/framework/benchmark_config.py58](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/framework/benchmark_config.py#L58-L58)
 - **Custom Logic**: If a model requires specialized initialization, modify `BenchmarkRunner` or add a new script in `benches/` that implements the benchmark interface [benchmark_v2/README.md133-138](https://github.com/huggingface/transformers/blob/8f542025/benchmark_v2/README.md?plain=1#L133-L138)
