  This page details the architectural principles of the Hugging Face Transformers library, the significant breaking changes introduced in Version 5 (v5), and the technical implementation of the new dynamic weight loading and modular modeling systems.

 
## Design Philosophy

 Transformers is an opinionated library built on three core tenets designed to ensure maintainability and readability at scale.

 
### 1. Single-File-per-Model (Legacy)

 Traditionally, Transformers enforced a "single model, single file" policy [docs/source/en/modular_transformers.md18](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/modular_transformers.md?plain=1#L18-L18) Every model architecture (e.g., BERT, Llama) has its own `modeling_<model_name>.py` file containing all necessary code to run the model. This avoids deep inheritance trees that make debugging difficult for users.

 
### 2. Composition over Over-Abstraction

 The library prioritizes composition. Specific model heads (e.g., `ForSequenceClassification`) call a base model in their `forward` pass rather than inheriting from it to keep the abstraction level low. Models are limited to at most two levels of abstraction: the specific model class and the `PreTrainedModel` base class [src/transformers/models/vits/modeling_vits.py31](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/vits/modeling_vits.py#L31-L31)

 
### 3. Explicit Code & Readability

 
 - **No `nn.Sequential`**: Subclassing `nn.Module` is preferred to allow for easier debugging with print statements and breakpoints [src/transformers/models/cpmant/modeling_cpmant.py36](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/cpmant/modeling_cpmant.py#L36-L36)
 - **Descriptive Naming**: Abbreviations are avoided (e.g., `activation` instead of `act`) to remain accessible to non-English users.
 - **Duplicate Code**: Code duplication is accepted if it improves the readability of a specific model file [docs/source/en/modular_transformers.md18](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/modular_transformers.md?plain=1#L18-L18) Historically, this was managed via `# Copied from` markers [AGENTS.md48](https://github.com/huggingface/transformers/blob/8f542025/AGENTS.md?plain=1#L48-L48)

## V5 Migration: Core Changes

 Version 5 introduces breaking changes to streamline the library for modern PyTorch workflows and heterogeneous hardware.

 
### Removal of TensorFlow and JAX

 Version 5 removes support for TensorFlow and JAX backends [MIGRATION_GUIDE_V5.md21-23](https://github.com/huggingface/transformers/blob/8f542025/MIGRATION_GUIDE_V5.md?plain=1#L21-L23) This allows the maintainers to focus exclusively on `torch` and reduces the maintenance burden of keeping three parallel implementations for every model architecture [MIGRATION_GUIDE_V5.md23-26](https://github.com/huggingface/transformers/blob/8f542025/MIGRATION_GUIDE_V5.md?plain=1#L23-L26)

 
### Tokenizer Consolidation

 V5 eliminates the strict separation between "Slow" (Python/SentencePiece) and "Fast" (Rust) tokenizers [MIGRATION_GUIDE_V5.md120-121](https://github.com/huggingface/transformers/blob/8f542025/MIGRATION_GUIDE_V5.md?plain=1#L120-L121)

 
 - A single `tokenization_<model>.py` file now handles all backends [MIGRATION_GUIDE_V5.md126-127](https://github.com/huggingface/transformers/blob/8f542025/MIGRATION_GUIDE_V5.md?plain=1#L126-L127)
 - New backends include `TokenizersBackend` (Rust-based), `SentencePieceBackend`, `PythonBackend`, and `MistralCommonBackend` [MIGRATION_GUIDE_V5.md128-138](https://github.com/huggingface/transformers/blob/8f542025/MIGRATION_GUIDE_V5.md?plain=1#L128-L138)
 - The `AutoTokenizer` automatically selects the appropriate backend based on available files and dependencies [MIGRATION_GUIDE_V5.md139-140](https://github.com/huggingface/transformers/blob/8f542025/MIGRATION_GUIDE_V5.md?plain=1#L139-L140)
 - Tokenizers are now designed to be initialized empty and trained directly, similar to models [MIGRATION_GUIDE_V5.md79-82](https://github.com/huggingface/transformers/blob/8f542025/MIGRATION_GUIDE_V5.md?plain=1#L79-L82)

### Key Components

## Modular Transformers System

 To address the maintenance overhead of the "single-file" policy, V5 introduces `modular_<name>.py` files. This system allows for code reuse via inheritance while still providing users with a standalone modeling file [docs/source/en/modular_transformers.md18-20](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/modular_transformers.md?plain=1#L18-L20)

## Contributing Guidelines

 
### Code Agent Policy

 Due to a high volume of low-quality automated PRs, first-time contributors are **prohibited** from using code agents (LLMs/autonomous agents) to submit PRs or issues [.github/PULL_REQUEST_TEMPLATE.md19-22](https://github.com/huggingface/transformers/blob/8f542025/.github/PULL_REQUEST_TEMPLATE.md?plain=1#L19-L22) PRs that appear agent-written may be closed without review [.github/PULL_REQUEST_TEMPLATE.md24-27](https://github.com/huggingface/transformers/blob/8f542025/.github/PULL_REQUEST_TEMPLATE.md?plain=1#L24-L27) Contributors are encouraged to focus on tasks agents cannot do, such as `git bisect` for bug diagnosis [CONTRIBUTING.md40-42](https://github.com/huggingface/transformers/blob/8f542025/CONTRIBUTING.md?plain=1#L40-L42)

 
### PR Checklist

 Before submitting a PR, contributors must:

 
 - Verify the PR title reflects the contribution [.github/PULL_REQUEST_TEMPLATE.md6-7](https://github.com/huggingface/transformers/blob/8f542025/.github/PULL_REQUEST_TEMPLATE.md?plain=1#L6-L7)
 - Run `make fix-repo` to synchronize repository state, modular conversions, and docstrings [CONTRIBUTING.md61](https://github.com/huggingface/transformers/blob/8f542025/CONTRIBUTING.md?plain=1#L61-L61) [AGENTS.md4](https://github.com/huggingface/transformers/blob/8f542025/AGENTS.md?plain=1#L4-L4)
 - Verify changes using `utils/tests_fetcher.py` to identify and run relevant tests [CONTRIBUTING.md61-62](https://github.com/huggingface/transformers/blob/8f542025/CONTRIBUTING.md?plain=1#L61-L62)
 - Run type checking via `make typing` or `make check-repo` [AGENTS.md3-5](https://github.com/huggingface/transformers/blob/8f542025/AGENTS.md?plain=1#L3-L5)
 - Coordinate on existing issues before starting work to avoid duplicate effort [AGENTS.md17-22](https://github.com/huggingface/transformers/blob/8f542025/AGENTS.md?plain=1#L17-L22)
