  The `examples/pytorch/` directory serves as the primary repository for production-ready training scripts. These scripts demonstrate how to use the Transformers library for a wide variety of tasks, ranging from standard Natural Language Processing (NLP) to Computer Vision (CV) and Speech Recognition.

 The repository provides two primary patterns for training:

 
 - **Trainer-based scripts**: Utilize the high-level `Trainer` or `Seq2SeqTrainer` API to handle the training loop, distributed setup, and evaluation [examples/pytorch/text-classification/run_classification.py52-53](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/text-classification/run_classification.py#L52-L53)
 - **No-trainer scripts**: Utilize the `Accelerate` library to provide a transparent, customizable training loop while still supporting distributed training and mixed precision [examples/pytorch/language-modeling/run_clm_no_trainer.py50-51](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/language-modeling/run_clm_no_trainer.py#L50-L51)
 
 
## Script Taxonomy and Supported Tasks

 The scripts are organized by task domain. Each domain typically contains a `run_task.py` (Trainer-based) and a `run_task_no_trainer.py` (Accelerate-based).

 
| Domain | Key Tasks | Primary Model Classes Used |
|---|---|---|
| Language Modeling | CLM, MLM, FIM, PLM | AutoModelForCausalLM, AutoModelForMaskedLM |
| Text Classification | GLUE, Sentiment, NER | AutoModelForSequenceClassification, AutoModelForTokenClassification |
| Seq2Seq | Summarization, Translation | AutoModelForSeq2SeqLM |
| Question Answering | SQuAD, Beam Search QA | AutoModelForQuestionAnswering |
| Vision | Classification, Segmentation | AutoModelForImageClassification, AutoModelForSemanticSegmentation |
| Audio | ASR (CTC/Seq2Seq), Classification | AutoModelForSpeechSeq2Seq, AutoModelForAudioClassification |

## The No-Trainer Pattern (Accelerate)

 The "no-trainer" scripts are designed for users who need full control over the training loop. They follow a standardized structure powered by `accelerate.Accelerator`.

 
### Implementation Flow

 
 - **Initialization**: The `Accelerator` is initialized to handle device placement and distributed logic [examples/pytorch/language-modeling/run_clm_no_trainer.py246](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/language-modeling/run_clm_no_trainer.py#L246-L246)
 - **Data Loading**: Datasets are loaded via `datasets.load_dataset` and preprocessed using `AutoTokenizer` or `AutoImageProcessor` [examples/pytorch/language-modeling/run_clm_no_trainer.py307](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/language-modeling/run_clm_no_trainer.py#L307-L307)
 - **Model & Optimizer**: The model is instantiated via `AutoModel` classes, and a standard PyTorch optimizer (e.g., `AdamW`) is created [examples/pytorch/language-modeling/run_clm_no_trainer.py465](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/language-modeling/run_clm_no_trainer.py#L465-L465)
 - **Preparation**: The model, optimizer, and dataloaders are passed to `accelerator.prepare()` to be wrapped for the specific environment (DDP, FSDP, etc.) [examples/pytorch/language-modeling/run_clm_no_trainer.py511](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/language-modeling/run_clm_no_trainer.py#L511-L511)
 - **Training Loop**: A manual `for epoch in range(num_epochs)` loop handles `loss.backward()` through `accelerator.backward(loss)` [examples/pytorch/language-modeling/run_clm_no_trainer.py568](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/language-modeling/run_clm_no_trainer.py#L568-L568)

## The Trainer Pattern

 Trainer-based scripts rely on `HfArgumentParser` to parse three distinct categories of arguments:

 
 - `ModelArguments`: Parameters for model configuration and path [examples/pytorch/language-modeling/run_clm.py82](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/language-modeling/run_clm.py#L82-L82)
 - `DataTrainingArguments`: Parameters for dataset selection and preprocessing [examples/pytorch/language-modeling/run_clm.py164](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/language-modeling/run_clm.py#L164-L164)
 - `TrainingArguments`: Standardized training hyperparameters (learning rate, batch size, etc.) provided by the core library [examples/pytorch/language-modeling/run_clm.py59](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/language-modeling/run_clm.py#L59-L59)

## Specialized Objectives

 
### Causal Language Modeling (CLM) & FIM

 Scripts like `run_clm.py` and `run_fim.py` implement standard autoregressive training and "Fill-in-the-Middle" (FIM) objectives. FIM is particularly used for code models, where a sequence is split into Prefix, Middle, and Suffix, then rearranged to train the model to fill the middle part [examples/pytorch/language-modeling/run_fim_no_trainer.py31-36](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/language-modeling/run_fim_no_trainer.py#L31-L36) The `fim_rate` parameter controls the proportion of sequences transformed into the FIM format [examples/pytorch/language-modeling/run_fim_no_trainer.py201-206](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/language-modeling/run_fim_no_trainer.py#L201-L206)

 
### Speech Recognition (ASR)

 The ASR scripts support two primary architectures:

 
 - **CTC (Connectionist Temporal Classification)**: Used for models like Wav2Vec2, requiring a `Wav2Vec2Processor` and `CTCLoss`.
 - **Seq2Seq**: Used for models like Whisper, utilizing `Seq2SeqTrainer` to handle autoregressive decoding during evaluation [examples/pytorch/speech-recognition/run_speech_recognition_seq2seq.py51-52](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/speech-recognition/run_speech_recognition_seq2seq.py#L51-L52) These scripts often include options to `freeze_feature_encoder` to improve training stability on small datasets [examples/pytorch/speech-recognition/run_speech_recognition_seq2seq.py123-126](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/speech-recognition/run_speech_recognition_seq2seq.py#L123-L126)
 
 
### Vision and Semantic Segmentation

 Vision scripts demonstrate the use of `AutoImageProcessor` for resizing and normalization [examples/pytorch/image-classification/run_image_classification_no_trainer.py59](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/image-classification/run_image_classification_no_trainer.py#L59-L59) They utilize `torchvision.transforms` or `albumentations` for data augmentation [examples/pytorch/image-classification/run_image_classification_no_trainer.py46-55](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/image-classification/run_image_classification_no_trainer.py#L46-L55) Semantic segmentation scripts specifically handle label reduction (e.g., ignoring background) via `reduce_labels_transform` to map the background class to a `255` ignore index [examples/pytorch/semantic-segmentation/run_semantic_segmentation_no_trainer.py71-83](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/semantic-segmentation/run_semantic_segmentation_no_trainer.py#L71-L83)
