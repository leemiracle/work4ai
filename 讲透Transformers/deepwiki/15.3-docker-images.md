  The `docker/` directory contains a comprehensive suite of Dockerfiles used to provide reproducible environments for development, continuous integration (CI), and specialized hardware testing (NVIDIA GPU, AMD GPU, DeepSpeed). These images ensure that the complex dependency tree of the Transformers library—spanning multiple deep learning frameworks, quantization backends, and hardware-specific kernels—remains consistent across different execution contexts.

 
## GPU-Accelerated Development & CI Images

 The primary images are built on top of NVIDIA CUDA or AMD ROCm base images and include a full set of optional dependencies for testing vision, audio, and multimodal models.

 
### Transformers All-Latest GPU

 The `transformers-all-latest-gpu` image is the flagship environment for general model CI. It targets the latest stable versions of PyTorch and CUDA while including extensive third-party integrations like `peft`, `accelerate`, `optimum`, and `bitsandbytes` [docker/transformers-all-latest-gpu/Dockerfile1-106](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-all-latest-gpu/Dockerfile#L1-L106)

 Key implementation details include:

 
 - **Version Management**: Uses `ARG` to pin `PYTORCH`, `CUDA`, and `TORCHCODEC` versions, ensuring ABI compatibility between PyTorch and its extensions like `torchaudio` [docker/transformers-all-latest-gpu/Dockerfile12-55](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-all-latest-gpu/Dockerfile#L12-L55)
 - **Flash Attention**: Supports optional installation of `flash-attn` via the `FLASH_ATTN` build argument. It explicitly handles `ninja` and `wheel` versioning to avoid build isolation failures common in Ubuntu 22.04 environments [docker/transformers-all-latest-gpu/Dockerfile117-124](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-all-latest-gpu/Dockerfile#L117-L124)
 - **Package Awareness**: To ensure the local checkout is recognized correctly in editable mode, the build executes `python3 setup.py develop` [docker/transformers-all-latest-gpu/Dockerfile151](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-all-latest-gpu/Dockerfile#L151-L151)
 - **Smoke Tests**: Includes a runtime check at the end of the build to verify that `torch` and `torchaudio` are correctly loaded and that the CUDA runtime is initialized, preventing the shipment of images with broken ABI links [docker/transformers-all-latest-gpu/Dockerfile153-156](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-all-latest-gpu/Dockerfile#L153-L156)
 
 
### Quantization Latest GPU

 This image focuses on the ecosystem of quantization backends. It maintains a specific torch stack (e.g., `PYTORCH='2.11.0'`) required by modern backends like `compressed-tensors` [docker/transformers-quantization-latest-gpu/Dockerfile12-17](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-quantization-latest-gpu/Dockerfile#L12-L17)

 It integrates a wide array of quantization libraries:

 
 - **Backends**: `bitsandbytes`, `hqq`, `optimum-quanto`, `compressed-tensors`, `amd-quark`, `auto-round`, and `torchao` [docker/transformers-quantization-latest-gpu/Dockerfile58-83](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-quantization-latest-gpu/Dockerfile#L58-L83)
 - **Special Handling (fouroversix)**: Installs `fouroversix` with `SKIP_CUDA_BUILD=1` to support reference Triton backends on non-Blackwell hardware (like A10G) while maintaining package availability for integration tests [docker/transformers-quantization-latest-gpu/Dockerfile98-115](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-quantization-latest-gpu/Dockerfile#L98-L115)
 - **ABI Guarding**: Implements a strict smoke test to catch ABI mismatches in `torchaudio` caused by floating dependencies that might clobber the pinned torch stack [docker/transformers-quantization-latest-gpu/Dockerfile120-125](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-quantization-latest-gpu/Dockerfile#L120-L125)
 
 
### AMD ROCm GPU

 The `transformers-pytorch-amd-gpu` image provides support for AMD hardware using the ROCm stack (e.g., `rocm7.2.2`). It specifically rebuilds `torchvision` from source to ensure that `decode_image` operations and other ops stay on the GPU using ROCm-specific kernels [docker/transformers-pytorch-amd-gpu/Dockerfile1-24](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-pytorch-amd-gpu/Dockerfile#L1-L24) It also includes AMD-specific mirrors for `flash-attention` wheels pinned to the ROCm ABI [docker/transformers-pytorch-amd-gpu/Dockerfile52-56](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-pytorch-amd-gpu/Dockerfile#L52-L56)

## DeepSpeed Specialized Images

 DeepSpeed images are built from NVIDIA's PyTorch containers (e.g., `nvcr.io/nvidia/pytorch:24.08-py3`) to leverage pre-optimized stacks [docker/transformers-pytorch-deepspeed-latest-gpu/Dockerfile1-2](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-pytorch-deepspeed-latest-gpu/Dockerfile#L1-L2)

 
 - **Pre-compilation**: These images pre-build DeepSpeed kernels (e.g., `DS_BUILD_CPU_ADAM=1`, `DS_BUILD_FUSED_ADAM=1`) to prevent timeouts during the first test execution in CI environments [docker/transformers-pytorch-deepspeed-latest-gpu/Dockerfile46-51](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-pytorch-deepspeed-latest-gpu/Dockerfile#L46-L51)
 - **Environment Cleanup**: They explicitly uninstall `transformer-engine`, `torch-tensorrt`, and outdated `nvtx` versions shipped in the base NVIDIA images to avoid conflicts with the Transformers testing suite [docker/transformers-pytorch-deepspeed-latest-gpu/Dockerfile28-37](https://github.com/huggingface/transformers/blob/8f542025/docker/transformers-pytorch-deepspeed-latest-gpu/Dockerfile#L28-L37)

## Lightweight CI Dockerfiles

 For CircleCI and GitHub Actions that do not require full GPU acceleration (e.g., linting, documentation, or basic CPU tests), a set of lightweight `python:3.10-slim` based images are used, often utilizing `uv` for faster dependency resolution [docker/consistency.dockerfile1-7](https://github.com/huggingface/transformers/blob/8f542025/docker/consistency.dockerfile#L1-L7)

 
| Dockerfile | Purpose | Key Dependencies |
|---|---|---|
| consistency.dockerfile | Repository integrity and quality checks. | transformers[quality,testing], GitPython docker/consistency.dockerfile1-10 |
| torch-light.dockerfile | Fast CPU-based unit tests. | torch (CPU), timm, accelerate, tiktoken docker/torch-light.dockerfile1-10 |
| custom-tokenizers.dockerfile | Testing exotic tokenizers (Jumanpp, etc.). | jumanpp, transformers[ja,testing,sentencepiece], unidic docker/custom-tokenizers.dockerfile1-22 |
| exotic-models.dockerfile | Testing models with niche dependencies. | detectron2, pytesseract, opencv-python, natten docker/exotic-models.dockerfile1-15 |
| examples-torch.dockerfile | Testing example scripts. | seqeval, albumentations, jiwer docker/examples-torch.dockerfile1-10 |

 
### CI Optimization: `fetch_hub_objects_for_ci.py`

 To reduce network latency and potential Hub downtime during CI runs, many lightweight Dockerfiles execute `utils/fetch_hub_objects_for_ci.py` during the build phase. This pre-downloads necessary test data and Hub objects into a `/test_data` directory within the image [docker/torch-light.dockerfile17-20](https://github.com/huggingface/transformers/blob/8f542025/docker/torch-light.dockerfile#L17-L20) [docker/pipeline-torch.dockerfile17-20](https://github.com/huggingface/transformers/blob/8f542025/docker/pipeline-torch.dockerfile#L17-L20) [docker/exotic-models.dockerfile22-25](https://github.com/huggingface/transformers/blob/8f542025/docker/exotic-models.dockerfile#L22-L25)
