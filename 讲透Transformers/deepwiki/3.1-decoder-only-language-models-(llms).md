  Modern autoregressive Language Models (LLMs) in the Transformers library follow a decoder-only architecture. This design pattern, popularized by models like GPT-2 and Llama, processes input sequences through a stack of transformer layers using causal masking to ensure that the prediction for a given token only depends on known previous tokens.

 
## Core Architecture Pattern

 The implementation of LLMs such as Llama, Mistral, and Gemma shares a common structural blueprint:

 
 - **Embedding Layer**: Maps input token IDs to a high-dimensional vector space.
 - **Transformer Block Stack**: A series of identical layers containing a self-attention mechanism and a feed-forward (MLP) network.
 - **Normalization**: Typically `RMSNorm` or `LayerNorm` applied before or after layers.
 - **Language Modeling Head**: A linear layer that projects the final hidden states back to the vocabulary size for token prediction.

## Shared Components and Implementation Details

 
### Rotary Positional Embeddings (RoPE)

 Modern LLMs (Llama, Mistral, Qwen2, Phi) use RoPE instead of absolute positional embeddings. RoPE encodes relative position by rotating the query and key representations in the complex plane.

 
 - **Implementation**: `LlamaRotaryEmbedding` computes the `cos` and `sin` frequencies [src/transformers/models/llama/modeling_llama.py73-127](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/llama/modeling_llama.py#L73-L127)
 - **Application**: The `apply_rotary_pos_emb` function performs the actual rotation using `rotate_half` [src/transformers/models/llama/modeling_llama.py130-152](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/llama/modeling_llama.py#L130-L152)
 - **Scaling**: Variants like Llama 3.1 use advanced RoPE scaling (e.g., dynamic scaling) to handle long contexts [tests/models/llama/test_modeling_llama.py77-100](https://github.com/huggingface/transformers/blob/8f542025/tests/models/llama/test_modeling_llama.py#L77-L100)
 
 
### Root Mean Square Layer Normalization (RMSNorm)

 Most modern LLMs favor `RMSNorm` over standard `LayerNorm` for its computational efficiency, as it avoids calculating the mean of the hidden states.

 
 - **Llama Implementation**: `LlamaRMSNorm` scales inputs by the reciprocal of the square root of the mean of squares [src/transformers/models/llama/modeling_llama.py53-67](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/llama/modeling_llama.py#L53-L67)
 - **Gemma Implementation**: `GemmaRMSNorm` includes a specific offset `(1.0 + self.weight.float())` applied to the normalized output [src/transformers/models/gemma/modeling_gemma.py64-79](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/gemma/modeling_gemma.py#L64-L79)
 
 
### SwiGLU MLP

 The standard Feed-Forward Network (FFN) is replaced in models like Llama, Mistral, and Gemma by the SwiGLU activation variant.

 
 - **Structure**: Consists of three linear layers: `gate_proj`, `up_proj`, and `down_proj` [src/transformers/models/mistral/modeling_mistral.py41-43](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/mistral/modeling_mistral.py#L41-L43)
 - **Logic**: The output is computed as `down_proj(act_fn(gate_proj(x)) * up_proj(x))` [src/transformers/models/mistral/modeling_mistral.py47-48](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/mistral/modeling_mistral.py#L47-L48)
 
 
### Grouped-Query Attention (GQA)

 To reduce memory overhead during inference, models like Mistral and Llama 3 use GQA. In GQA, multiple query heads share a single key/value head pair.

 
 - **Implementation**: Controlled by `num_key_value_heads` in the config. If this is less than `num_attention_heads`, the model uses `repeat_kv` to broadcast KV heads to match the query heads during the attention calculation [src/transformers/models/mistral/modeling_mistral.py84-93](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/mistral/modeling_mistral.py#L84-L93)

## Advanced Multimodal LLMs

 Recent architectures like **Gemma 3** extend the decoder-only LLM pattern to multimodal inputs (Vision).

 
 - **Multimodal Outputs**: `Gemma3CausalLMOutputWithPast` handles the inclusion of `image_hidden_states` alongside standard text logits [src/transformers/models/gemma3/modeling_gemma3.py82-103](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/gemma3/modeling_gemma3.py#L82-L103)
 - **Layer-Specific Masking**: Gemma 3 supports heterogeneous layer types, interleaving `sliding_attention` and `full_attention` layers [src/transformers/models/gemma3/modular_gemma3.py122-126](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/gemma3/modular_gemma3.py#L122-L126)
 - **Scaled Embeddings**: Gemma models use `GemmaTextScaledWordEmbedding` which multiplies embeddings by a scale factor [src/transformers/models/gemma/modeling_gemma.py50-61](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/gemma/modeling_gemma.py#L50-L61)
