  This section covers the architecture and implementation of vision-centric and multimodal vision-language models (VLMs) in the `transformers` library. These models range from pure vision encoders like ViT and SigLIP to complex multimodal systems like LLaVA, PaliGemma, and Idefics2 that bridge visual perception with large language models.

 
## Vision-Language Model Architectures

 Vision-Language Models typically consist of three primary components: a **Vision Tower** (encoder), a **Multimodal Projector** (connector), and a **Language Model** (decoder).

 
### Component Overview

 
 - **Vision Tower**: A pre-trained vision model (often CLIP or SigLIP) that extracts features from raw images or video frames. These are often instantiated via `AutoModel.from_config` using a nested configuration [src/transformers/models/llava/modeling_llava.py133](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/llava/modeling_llava.py#L133-L133) [src/transformers/models/paligemma/modeling_paligemma.py127](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/paligemma/modeling_paligemma.py#L127-L127)
 - **Multimodal Projector**: A module that aligns vision features with the language model's embedding space. Common implementations include simple linear layers or MLP blocks.
 - **Language Model**: A decoder-only transformer (e.g., Llama, Qwen2, Gemma) that processes the interleaved vision and text embeddings to generate responses [src/transformers/models/llava/modeling_llava.py136](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/llava/modeling_llava.py#L136-L136) [src/transformers/models/paligemma/modeling_paligemma.py132](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/paligemma/modeling_paligemma.py#L132-L132)

## Implementation Patterns

 
### LLaVA (Large Language-and-Vision Assistant)

 LLaVA models implement a direct feature alignment strategy.

 
 - **Projector**: The `LlavaMultiModalProjector` consists of a two-layer MLP with an activation function (defined by `config.projector_hidden_act`) to project vision features into the text hidden dimension [src/transformers/models/llava/modeling_llava.py87-106](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/llava/modeling_llava.py#L87-L106)
 - **Feature Selection**: `LlavaModel.get_image_features` allows selecting hidden states from specific layers of the vision tower (e.g., the penultimate layer) via `vision_feature_layer` [src/transformers/models/llava/modeling_llava.py144-163](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/llava/modeling_llava.py#L144-L163)
 - **VipLLaVA**: A variant that uses multiple feature layers from the vision tower, concatenated before being passed to the `VipLlavaMultiModalProjector`, which includes an initial `nn.LayerNorm` [src/transformers/models/vipllava/modeling_vipllava.py89-110](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/vipllava/modeling_vipllava.py#L89-L110)
 
 
### PaliGemma

 PaliGemma is designed for efficient transfer learning and uses a simpler projection mechanism.

 
 - **Projector**: Uses `PaliGemmaMultiModalProjector`, which is a single `nn.Linear` layer [src/transformers/models/paligemma/modeling_paligemma.py90-98](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/paligemma/modeling_paligemma.py#L90-L98)
 - **Token Handling**: The model uses a dedicated `image_token_id`. `get_placeholder_mask` identifies these tokens in the input sequence to facilitate the replacement of text embeddings with projected image features [src/transformers/models/paligemma/modeling_paligemma.py151-167](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/paligemma/modeling_paligemma.py#L151-L167)
 
 
### Video & Any-Resolution Support

 Modern VLMs like LLaVA-NeXT and Video-LLaVA extend these capabilities to dynamic resolutions and temporal data.

 
 - **Any-Resolution (NaViT style)**: `LlavaNext` uses `select_best_resolution` and `get_anyres_image_grid_shape` to handle images of variable aspect ratios by partitioning them into multiple patches plus a global thumbnail [src/transformers/models/llava_next/modeling_llava_next.py41-69](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/llava_next/modeling_llava_next.py#L41-L69)
 - **Video Processing**: `VideoLlavaModel` supports both `image` and `video` modalities simultaneously [src/transformers/models/video_llava/modeling_video_llava.py128](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/video_llava/modeling_video_llava.py#L128-L128)
 - **Pooling**: `LlavaNextVideoPooler` provides spatial pooling (average, max, or convolutional) to reduce the token count of high-resolution video frames before they enter the language model [src/transformers/models/llava_next_video/modeling_llava_next_video.py107-138](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/llava_next_video/modeling_llava_next_video.py#L107-L138)
 
 
## Vision Encoders & Feature Extraction

 
### SigLIP & Idefics2

 `Idefics2` implements a vision embedding strategy optimized for variable resolutions.

 
 - **Idefics2VisionEmbeddings**: This class modifies the standard `SiglipVisionEmbeddings` to enable images of variable resolution without resizing to a fixed square. It calculates 2D position IDs based on the actual number of patches in height and width [src/transformers/models/idefics2/modeling_idefics2.py100-149](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/idefics2/modeling_idefics2.py#L100-L149)
 - **SigLIP Interpolation**: `SiglipVisionEmbeddings.interpolate_pos_encoding` allows the model to adapt pre-trained position encodings to higher resolution inputs during inference [src/transformers/models/siglip/modeling_siglip.py137-155](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/models/siglip/modeling_siglip.py#L137-L155)
 
 
### Object Detection

 Object detection models (DETR, RT-DETR) utilize transformer encoders and decoders to predict sets of bounding boxes.

 
 - **DETR Family**: Models like `DeformableDetr` and `RtDetr` use object queries that attend to image features.
 - **Grounding DINO**: `GroundingDinoModel` extends this by conditioning the detection on text prompts, requiring cross-modal attention between vision and text features within the encoder and decoder.
