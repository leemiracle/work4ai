  The `transformers` library provides a unified quantization framework built around the `HfQuantizer` abstraction. This system allows for seamless integration of various quantization backends like **bitsandbytes**, **GPTQ**, and **AWQ**. These methods reduce the memory footprint of Large Language Models (LLMs) by representing weights in lower precision (8-bit, 4-bit, or even lower) while maintaining performance through advanced calibration or hardware-specific kernels.

 
## Quantization Framework Architecture

 Quantization in `transformers` is orchestrated during the model loading process within `from_pretrained`. The `AutoHfQuantizer` factory resolves the appropriate quantizer class based on the `quantization_config` provided by the user or found in the model's configuration file.

## BitsAndBytes (8-bit & 4-bit)

 The `bitsandbytes` integration supports `LLM.int8()` and 4-bit NormalFloat (NF4) / Float4 (FP4) quantization. It is primarily used for reducing memory during inference and enabling QLoRA (Quantized LoRA) fine-tuning.

 
### Implementation Details

 
 - **8-bit (Bnb8BitHfQuantizer):** Replaces `nn.Linear` layers with `bnb.nn.Linear8bitLt`. It uses mixed-precision decomposition where outlier features are kept in FP16 while the rest are quantized to 8-bit [src/transformers/quantizers/quantizer_bnb_8bit.py114-118](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_bnb_8bit.py#L114-L118)
 - **4-bit (Bnb4BitHfQuantizer):** Replaces layers with `bnb.nn.Linear4bit`. It supports `compute_dtype` (e.g., BF16) for the actual matrix multiplication while weights remain in 4-bit [src/transformers/quantizers/quantizer_bnb_4bit.py91-95](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_bnb_4bit.py#L91-L95)
 - **Offloading:** Supports `llm_int8_enable_fp32_cpu_offload` to handle models larger than available GPU VRAM by keeping some modules in FP32 on the CPU [src/transformers/quantizers/quantizer_bnb_4bit.py71-81](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_bnb_4bit.py#L71-L81)

## GPTQ & AWQ Quantizers

 GPTQ (Generalized Post-Training Quantization) and AWQ (Activation-aware Weight Quantization) are 4-bit quantization methods that require a calibration step but often result in higher accuracy than zero-shot methods like standard 4-bit quantization.

 
### Layer Replacement and Weight Conversion

 Unlike `bitsandbytes`, which often quantizes on-the-fly, GPTQ and AWQ models are typically loaded from pre-quantized checkpoints. The quantizers use `WeightConverter` and `ConversionOps` to map quantized weights (like `qweight`, `qzeros`, and `scales`) from the checkpoint to the specialized linear layers.

## TorchAo Integration

 `torchao` is a newer integration providing high-performance kernels for FP8, Int8, and Int4 quantization, designed to be composable with `torch.compile`.

 
 - **Flexible Configuration:** `TorchAoConfig` allows per-module quantization settings using `FqnToConfig` [src/transformers/quantizers/quantizer_torchao.py135-145](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_torchao.py#L135-L145)
 - **Compilation:** Setting `cache_implementation="static"` in `generate()` triggers `torch.compile` for significant speedups on quantized models [docs/source/en/quantization/torchao.md85-90](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/quantization/torchao.md?plain=1#L85-L90)
 - **Training Support:** Unlike some backends, `torchao` 8-bit quantization (e.g. `Int8WeightOnlyConfig`) supports training [src/transformers/quantizers/quantizer_torchao.py153-155](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_torchao.py#L153-L155)
 - **Metadata Handling:** `TorchAoHfQuantizer` flattens the state dict of tensor subclasses for compatibility with the safetensors format [src/transformers/quantizers/quantizer_torchao.py88-92](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_torchao.py#L88-L92)

## MXFP4 Quantization

 MXFP4 (Microscaling Formats) provides 4-bit quantization using specialized Triton kernels for high-throughput inference on supported hardware.

 
 - **Quantizer:** `Mxfp4HfQuantizer` [src/transformers/quantizers/quantizer_mxfp4.py43](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_mxfp4.py#L43-L43)
 - **Kernel Integration:** Uses `gpt-oss-triton-kernels` loaded via the `hub_kernels` system [src/transformers/quantizers/quantizer_mxfp4.py55-64](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_mxfp4.py#L55-L64)
 - **Hardware Support:** Requires CUDA compute capability >= 7.5, XPU, or CPU with specific Triton versions [src/transformers/quantizers/quantizer_mxfp4.py92-104](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_mxfp4.py#L92-L104)
 - **Swizzling:** Weights are swizzled during loading to match Triton kernel expectations [src/transformers/integrations/mxfp4.py74-76](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/mxfp4.py#L74-L76)
 - **Experts Support:** Specifically handles `Mxfp4GptOssExperts` for Mixture-of-Experts architectures [src/transformers/integrations/mxfp4.py67-76](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/mxfp4.py#L67-L76)

## Summary of Conversion Operations

 The library uses `ConversionOps` to handle the transition between standard PyTorch tensors and quantized formats during checkpoint loading.
