  The Text and Conversational pipelines provide high-level abstractions for generating text and conducting multi-turn dialogues. These pipelines encapsulate the complexities of tokenization, chat templating, model inference (including autoregressive generation), and the parsing of structured model outputs into formats like tool calls or reasoning blocks.

 
## TextGenerationPipeline

 The `TextGenerationPipeline` is designed for autoregressive language models (e.g., GPT-2, Llama, Mistral). It handles both single-prompt completion and multi-turn chat interactions [src/transformers/pipelines/text_generation.py23-70](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/pipelines/text_generation.py#L23-L70)

 
### Key Behaviors

 
 - **Padding Configuration**: The pipeline automatically sets `tokenizer.padding_side = "left"` for decoder-only models to ensure correct batched generation [src/transformers/pipelines/text_generation.py105-106](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/pipelines/text_generation.py#L105-L106)
 - **Chat Mode**: When the input is a list of dictionaries (a "chat"), the pipeline applies the model's chat template and continues the conversation by adding an assistant response [src/transformers/pipelines/text_generation.py27-28](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/pipelines/text_generation.py#L27-L28)
 - **Prefix Handling**: For specific models like `XLNet` or `TransfoXL`, a default `XL_PREFIX` is prepended to short prompts to provide better context [src/transformers/pipelines/text_generation.py76-84](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/pipelines/text_generation.py#L76-L84)
 - **Default Generation Config**: Unless overridden, the pipeline uses a default `GenerationConfig` with `max_new_tokens=256`, `do_sample=True`, and `temperature=0.7` [src/transformers/pipelines/text_generation.py93-97](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/pipelines/text_generation.py#L93-L97)

## Multimodal Pipelines: ImageTextToText & AnyToAny

 Modern conversational models often support multiple modalities. The `ImageTextToTextPipeline` and `AnyToAnyPipeline` extend text generation to include images, video, and audio.

 
### ImageTextToTextPipeline

 Specifically targets `AutoModelForImageTextToText` architectures. It processes inputs consisting of an image and a text prompt (e.g., for captioning or visual Q&A) [src/transformers/pipelines/image_text_to_text.py53-113](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/pipelines/image_text_to_text.py#L53-L113) It uses `load_images` and `valid_images` utilities to handle input image data [src/transformers/pipelines/image_text_to_text.py34](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/pipelines/image_text_to_text.py#L34-L34)

 
### AnyToAnyPipeline

 A versatile pipeline for `AutoModelForMultimodalLM` that supports arbitrary combinations of text, image, audio, and video [src/transformers/pipelines/any_to_any.py50-65](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/pipelines/any_to_any.py#L50-L65)

 
 - **Modality Support**: Dynamically checks input types to require necessary backends like `torchvision` [src/transformers/pipelines/any_to_any.py143-147](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/pipelines/any_to_any.py#L143-L147)
 - **Internal Chat Wrapper**: Uses an internal `Chat` class to distinguish between conversation history and a batch of samples [src/transformers/pipelines/any_to_any.py54-65](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/pipelines/any_to_any.py#L54-L65)

## Chat Templating and Response Parsing

 The library uses a dual-template system to handle conversational logic: **Chat Templates** for input and **Response Templates** for output.

 
### Chat Templates (Input)

 Chat templates indicate how models expect chats to be formatted, typically converting a list of `role` and `content` dictionaries into a token sequence [docs/source/en/chat_templating.md23-29](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/chat_templating.md?plain=1#L23-L29)

 
 - **Roles**: Common roles include `user` (messages from user), `assistant` (messages from model), and `system` (directives) [docs/source/en/chat_templating.md78-83](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/chat_templating.md?plain=1#L78-L83)
 - **apply_chat_template**: This method in `PreTrainedTokenizerBase` formats the chat. Setting `add_generation_prompt=True` appends tokens indicating the start of an `assistant` response [docs/source/en/chat_templating.md129-132](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/chat_templating.md?plain=1#L129-L132)
 
 
### Response Parsing (Output)

 `ResponseParser` and `ResponseTemplate` perform the inverse operation: converting raw tokens back into structured message dictionaries.

 
 - **Response Templates**: Defined in `response_templates.py`, these guide the parser on how to identify segments like "thinking" or "tool calls" [src/transformers/utils/chat_parsing/response_templates.py](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/utils/chat_parsing/response_templates.py)
 - **Streaming Generation**: The `ResponseParser` is stateful and can process chunks of text to emit events in real-time [src/transformers/utils/chat_parsing/response_parser.py](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/utils/chat_parsing/response_parser.py)

## Implementation Details

 
### Parameter Sanitization

 All pipelines implement `_sanitize_parameters` to separate arguments into three categories:

 
 - **preprocess_params**: Arguments for the tokenizer/processor (e.g., `prefix`, `continue_final_message`).
 - **forward_params**: Arguments for the model's `generate()` method (e.g., `max_new_tokens`, `stop_strings`).
 - **postprocess_params**: Arguments for decoding and formatting (e.g., `return_full_text`, `clean_up_tokenization_spaces`).
 
 **Sources:** [src/transformers/pipelines/text_generation.py128-145](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/pipelines/text_generation.py#L128-L145) [src/transformers/pipelines/image_text_to_text.py131-150](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/pipelines/image_text_to_text.py#L131-L150)

 
### Tool-Call Parsing

 The system supports parsing tool calls by converting Python function metadata into JSON schemas.

 
 - **Type Hint Mapping**: Python types are mapped to JSON schema types (e.g., `int` to `integer`, `float` to `number`) [src/transformers/utils/chat_template_utils.py80-95](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/utils/chat_template_utils.py#L80-L95)
 - **Recursive Parsing**: `_parse_type_hint` handles complex types like `Union`, `Literal`, `list`, and `dict` [src/transformers/utils/chat_template_utils.py98-173](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/utils/chat_template_utils.py#L98-L173)
 
 **Sources:** [src/transformers/utils/chat_template_utils.py80-173](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/utils/chat_template_utils.py#L80-L173)
