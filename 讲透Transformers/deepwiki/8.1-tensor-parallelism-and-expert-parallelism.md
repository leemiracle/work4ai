  This section describes the distributed infrastructure in Hugging Face Transformers for scaling models across multiple accelerators using Tensor Parallelism (TP) and Expert Parallelism (EP). The library leverages PyTorch `DTensor` and `DeviceMesh` to provide a declarative, plan-based approach to model sharding, allowing models to exceed the memory and compute limits of a single device.

 
## Overview and Design Philosophy

 The distributed system is built around the `DistributedMixin`, which provides models with the ability to manage `tp_plan`, `ep_plan`, and `fsdp_plan` dictionaries [src/transformers/distributed/mixin.py52-60](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/distributed/mixin.py#L52-L60) Unlike legacy sharding methods that manually partitioned parameters, the new system uses a "shard-on-read" approach via `DtensorShardOperation` [src/transformers/distributed/sharding_utils.py21](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/distributed/sharding_utils.py#L21-L21)

 
### Key Abstractions

 
 - **DeviceMesh**: A PyTorch abstraction that defines the layout of the distributed cluster (e.g., a 1D mesh for TP, or a 2D mesh for TP+DP) [src/transformers/distributed/utils.py166-175](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/distributed/utils.py#L166-L175)
 - **DTensor (Distributed Tensor)**: Tensors that are logically global but physically distributed across the `DeviceMesh`. The library uses `is_dtensor` to check for these objects during loading and inference [src/transformers/distributed/utils.py42-47](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/distributed/utils.py#L42-L47)
 - **Parallel Styles**: Strategies like `ColwiseParallel` (splitting weights by column) and `RowwiseParallel` (splitting weights by row) that dictate how linear layers are partitioned [src/transformers/distributed/tensor_parallel.py23-28](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/distributed/tensor_parallel.py#L23-L28) [src/transformers/integrations/tensor_parallel.py23-38](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/tensor_parallel.py#L23-L38)

## Tensor Parallelism (TP) Implementation

 Tensor Parallelism splits individual layers across multiple GPUs. Transformers supports TP for models with a predefined plan or a manual plan passed via `DistributedConfig` [docs/source/en/perf_infer_gpu_multi.md33-38](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/perf_infer_gpu_multi.md?plain=1#L33-L38)

 
### Supported Parallel Styles

 The `ParallelInterface` class maps string identifiers to strategy implementations [docs/source/en/perf_infer_gpu_multi.md107-128](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/perf_infer_gpu_multi.md?plain=1#L107-L128)

 
| Style | Description | Implementation Class |
|---|---|---|
| colwise | Partitions weights and biases column-wise. | ColwiseParallel |
| rowwise | Partitions weights and biases row-wise. | RowwiseParallel |
| packed_colwise | Supports packed weights (e.g., fused up_proj and gate_proj). | PackedColwiseParallel |
| sequence_parallel | Supports sequence-level sharding. | SequenceParallel |
| ep_router | Expert parallelism router sharding. | EpRouterParallel |

### The Shard-on-Read Mechanism

 During model loading, `DtensorShardOperation` calculates the local shard based on the `DeviceMesh`. The system intercepts weight loading in `convert_and_load_state_dict_in_model` to apply sharding before the parameter is set on the model [docs/source/en/weightconverter.md36-49](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/weightconverter.md?plain=1#L36-L49)

 
## Expert Parallelism (EP) and MoE Scaling

 Expert Parallelism is a specialized form of parallelism for Mixture-of-Experts (MoE) models where different experts are hosted on different devices.

 
### MoE Parallel Entities

 The `MoeExpertsParallel` style shards the expert stack across the `DeviceMesh`. The router logic uses `EpRouterParallel` to coordinate token routing across the expert-parallel ranks [src/transformers/integrations/tensor_parallel.py27-29](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/tensor_parallel.py#L27-L29) [docs/source/en/perf_infer_gpu_multi.md119-122](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/perf_infer_gpu_multi.md?plain=1#L119-L122)

## Core Implementation Details

 
### DistributedMixin

 The `DistributedMixin` is the primary interface for distributed configuration. It manages `tp_plan`, `ep_plan`, and `fsdp_plan`. The `tp_plan` property includes validation logic that checks for invalid parallel styles and issues warnings for patterns that do not match any model parameters [src/transformers/distributed/mixin.py107-131](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/distributed/mixin.py#L107-L131) [tests/tensor_parallel/test_tensor_parallel.py61-107](https://github.com/huggingface/transformers/blob/8f542025/tests/tensor_parallel/test_tensor_parallel.py#L61-L107)

 
### Plan Initialization and Merging

 The `init_parallel_plans` method copies class-level plans onto the instance and merges them with plans from `model.config` and sub-modules [src/transformers/distributed/mixin.py62-84](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/distributed/mixin.py#L62-L84)

 
### FSDP2 Integration

 Hugging Face Transformers integrates with PyTorch FSDP2 (Fully Sharded Data Parallel). The `fsdp_plan` allows specifying which modules should be wrapped with `fully_shard`. Strategies include `free_full_weight` and `keep_full_weight` [src/transformers/distributed/fsdp.py153-161](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/distributed/fsdp.py#L153-L161)

 
### Expert Backends

 MoE models can use different expert execution backends via `experts_implementation`, including `eager`, `batched_mm`, `grouped_mm`, and `deepgemm` [docs/source/en/experts_interface.md23-30](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/experts_interface.md?plain=1#L23-L30) The `deepgemm_megamoe` backend fuses expert-parallel dispatch with computation on Blackwell architectures [docs/source/en/experts_interface.md29](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/experts_interface.md?plain=1#L29-L29)
