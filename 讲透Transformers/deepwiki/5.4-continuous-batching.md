  Continuous batching is an optimization for high-throughput inference that allows the engine to schedule new requests and retire finished ones at the token level, rather than waiting for an entire batch to finish. This system relies on a paged KV cache mechanism to manage memory dynamically and a sophisticated scheduler to maximize hardware utilization.

 
## System Architecture

 The continuous batching subsystem is orchestrated by the `ContinuousBatchingAPI` (or `ContinuousBatchingAsyncAPI` for asynchronous workloads). It bridges high-level generation requests with underlying hardware-optimized attention kernels.

## Request Scheduling

 The `Scheduler` class and its primary implementation, `FIFOScheduler`, manage the transition of requests from `PENDING` to `PREFILLING` and `DECODING` statuses [src/transformers/generation/continuous_batching/scheduler.py22-48](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/scheduler.py#L22-L48)

 
### Scheduling Logic

 
 - **Token Budgeting**: The scheduler respects a `token_budget` limit in `schedule_batch`, ensuring the total number of query tokens in a single forward pass does not exceed hardware capacity [src/transformers/generation/continuous_batching/scheduler.py67-75](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/scheduler.py#L67-L75)
 - **Cache Budgeting**: It tracks available KV cache blocks. New requests are only scheduled if there is a `safety_margin` of free blocks (e.g., 0.1 means 10% free blocks must remain) [src/transformers/generation/continuous_batching/scheduler.py30-36](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/scheduler.py#L30-L36)
 - **Block Allocation**: The scheduler uses `_allocate_blocks_if_needed` to dynamically request blocks from the `CacheAllocator` as sequences grow [src/transformers/generation/continuous_batching/scheduler.py122-128](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/scheduler.py#L122-L128)
 - **Starvation Prevention**: If a request cannot be allocated blocks, it is marked as "starved," prompting the `OffloadingManager` to evict lower-priority cache entries [src/transformers/generation/continuous_batching/scheduler.py57-60](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/scheduler.py#L57-L60)

## Paged KV Cache Management

 Continuous batching solves memory fragmentation using **Paged Attention**. Memory is partitioned into fixed-size "blocks," which are allocated dynamically as sequences grow.

 
### Key Components

 
 - **PagedAttentionCache**: The top-level manager that holds physical cache tensors of shape `[num_blocks * block_size, num_heads, head_size]`. It groups layers by attention type (full vs. sliding) to reduce fragmentation [src/transformers/generation/continuous_batching/cache.py89-106](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/cache.py#L89-L106)
 - **BlockManager**: Tracks which blocks are `free`, `in_use`, or `initialized`. It manages a hash table for block re-use/prefix sharing [src/transformers/generation/continuous_batching/cache_manager.py58-86](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/cache_manager.py#L58-L86)
 - **Allocators**: `FullAttentionCacheAllocator` handles standard sequences with shareable blocks, while `SlidingAttentionCacheAllocator` manages sliding window attention where older tokens are evicted [src/transformers/generation/continuous_batching/cache_manager.py23](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/cache_manager.py#L23-L23) [src/transformers/generation/continuous_batching/cache_manager.py71-73](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/cache_manager.py#L71-L73)

## Model Execution and Attention Backends

 The `ModelRunner` prepares the batch for the model's forward pass. It utilizes `ContinuousBatchingIOs` to manage inputs like `input_ids`, `position_ids`, and `cu_seq_lens_q` [src/transformers/generation/continuous_batching/input_outputs.py31-52](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/input_outputs.py#L31-L52)

 
### Supported Backends

 The system supports multiple paged attention backends via `attn_implementation` selection:

 
| Backend | File Pointer | Description |
|---|---|---|
| Flash Paged | flash_paged.py | Uses flash_attn_with_kvcache for fused attention and cache updates during decoding. Optimized for NVIDIA GPUs src/transformers/integrations/flash_paged.py7-42 |
| SDPA Paged | sdpa_paged.py | Uses PyTorch's scaled_dot_product_attention. Manages cache updates via cache.update() before the SDPA call src/transformers/integrations/sdpa_paged.py18-43 |
| Eager Paged | eager_paged.py | Standard PyTorch implementation for hardware without SDPA/Flash support src/transformers/integrations/eager_paged.py7-20 |

 
### CUDA Graph Integration

 To minimize CPU overhead, `ContinuousBatchingIOs` manages static tensors and CUDA graphs. Since CB has dynamic dimensions, the system uses "padding intervals" (`q_padding_interval_size` and `kv_padding_interval_size`) to group requests into a finite set of graph signatures, stored in `CudaGraphBuffer` [src/transformers/generation/continuous_batching/continuous_api.py49-66](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/continuous_api.py#L49-L66) [src/transformers/generation/continuous_batching/utils.py27-43](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/utils.py#L27-L43)

## Distributed Coordination

 For Tensor Parallel (TP) deployments, the `DistributedHelper` coordinates execution across ranks [src/transformers/generation/continuous_batching/continuous_api.py38](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/continuous_api.py#L38-L38)

 
 - **Status Sync**: `BackgroundThreadStatus` tracks whether the TP group should `DONT_STOP`, `FLUSH_AND_STOP`, or `HARD_STOP` [src/transformers/generation/continuous_batching/continuous_api.py138-151](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/continuous_api.py#L138-L151)
 - **Output Routing**: The `OutputRouter` uses `deliver_batch` to route generated `GenerationOutput` objects to their registered async handlers or a shared queue, minimizing cross-thread overhead [src/transformers/generation/continuous_batching/continuous_api.py84-129](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/generation/continuous_batching/continuous_api.py#L84-L129)
