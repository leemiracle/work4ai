  This section covers the integration of advanced and emerging quantization backends within the Hugging Face Transformers library. Unlike standard 4-bit/8-bit methods, these backends focus on fine-grained precision (FP8, MXFP4), hardware-specific optimizations (TorchAO, EETQ), and cross-ecosystem interoperability (GGUF/GGML).

 
## Fine-Grained FP8 Quantization

 Fine-grained FP8 quantization utilizes `torch.float8_e4m3fn` for weights and activations, often employing sub-tensor scaling (block-wise or row-wise) to maintain accuracy in large-scale models like DeepSeek-V3.

 
### Implementation Details

 The `FineGrainedFP8Quantizer` coordinates the conversion of linear layers into specialized FP8 variants. It leverages Triton kernels for high-performance matrix multiplication [src/transformers/integrations/finegrained_fp8.py72-80](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/finegrained_fp8.py#L72-L80)

 
 - **Scaling Formats**: Supports `ue8m0` scales, which require `torch.float8_e8m0fnu` (available in PyTorch >= 2.7). UE8M0 scales are stored and consumed as a single native dtype to avoid mixed container overhead [src/transformers/integrations/finegrained_fp8.py51-62](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/finegrained_fp8.py#L51-L62)
 - **Kernel Loading**: The `load_finegrained_fp8_kernel` function dynamically fetches and loads Triton-based matmul kernels (`matmul_2d`, `matmul_batched`, `matmul_grouped`) from the `kernels-community/finegrained-fp8` repository using the `lazy_load_kernel` utility [src/transformers/integrations/finegrained_fp8.py88-144](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/finegrained_fp8.py#L88-L144)
 - **DeepGEMM Integration**: For NVIDIA Blackwell (SM100) architectures, the backend can dispatch to DeepGEMM for optimized FP8/FP4 expert kernels, supporting both standard linear and MegaMoE expert forwards [src/transformers/integrations/finegrained_fp8.py31-37](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/finegrained_fp8.py#L31-L37)
 - **Expert Allocation**: The `_alloc_expert_proj` utility manages the allocation of weight and scale-factor parameters for MoE experts, handling FP4-packed storage and block-level granularity (`sf_gran_n`, `sf_gran_k`) [src/transformers/integrations/finegrained_fp8.py152-177](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/finegrained_fp8.py#L152-L177)

## GGUF & GGML Interoperability

 Transformers provides native support for loading GGUF (GPT-Generated Unified Format) files, enabling interoperability with the `llama.cpp` ecosystem. This includes both model weights and tokenizer configurations.

 
### Model Loading & Tensor Processing

 The loading process involves mapping GGUF keys to Transformers-compatible keys using `GGUF_TO_TRANSFORMERS_MAPPING` [src/transformers/modeling_gguf_pytorch_utils.py39-51](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/modeling_gguf_pytorch_utils.py#L39-L51)

 
 - **TensorProcessor**: A base class for handling architecture-specific weight permutations [src/transformers/modeling_gguf_pytorch_utils.py62-87](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/modeling_gguf_pytorch_utils.py#L62-L87)
 - **LlamaTensorProcessor**: Specifically handles the reverse permutation of Query (Q) and Key (K) weights using `_reverse_permute_weights` to match PyTorch expectations [src/transformers/modeling_gguf_pytorch_utils.py88-115](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/modeling_gguf_pytorch_utils.py#L88-L115)
 - **MoE Support**: `Qwen2MoeTensorProcessor` manages the splitting and interleaving of fused expert weights. It handles the merging of `gate_up_proj` weights per expert by doubling the size of the second dimension and interleaving `gate` and `up` shards [src/transformers/modeling_gguf_pytorch_utils.py118-169](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/modeling_gguf_pytorch_utils.py#L118-L169)
 - **Configuration Mapping**: The `GGUF_CONFIG_MAPPING` provides a translation layer for architecture-specific hyper-parameters like `context_length` to `max_position_embeddings` and `block_count` to `num_hidden_layers` [src/transformers/integrations/ggml.py35-167](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/ggml.py#L35-L167)
 
 
### Tokenizer Conversion

 GGUF tokenizers are converted to `tokenizers.Tokenizer` (Fast) objects. The library maps GGUF-specific special tokens (BOS, EOS, UNK, PAD) to the corresponding Transformers fields [src/transformers/integrations/ggml.py159-164](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/ggml.py#L159-L164)

## TorchAO Backend

 `torchao` is a PyTorch-native library for quantization and sparsity. The `TorchAoHfQuantizer` integrates these features into the `from_pretrained` workflow.

 
### Key Capabilities

 
 - **Weight Formats**: Supports `Int4WeightOnlyConfig`, `Int8WeightOnlyConfig`, and `Float8WeightOnlyConfig`. The quantizer uses `_fuzzy_match_size` to determine the bit-width from the TorchAO config class names [src/transformers/quantizers/quantizer_torchao.py41-52](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_torchao.py#L41-L52) [src/transformers/quantizers/quantizer_torchao.py50-57](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_torchao.py#L50-L57)
 - **Static Compilation**: Integrates with `torch.compile` via `cache_implementation="static"` for significant speedups during inference [docs/source/en/quantization/torchao.md85-90](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/quantization/torchao.md?plain=1#L85-L90)
 - **State Dict Handling**: Uses `flatten_tensor_state_dict` to ensure compatibility between complex tensor subclasses (like `Float8Tensor` or `Int4Tensor`) and the `safetensors` format [src/transformers/quantizers/quantizer_torchao.py88-92](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_torchao.py#L88-L92)
 - **Targeted Quantization**: Supports module-level configuration via `FqnToConfig`, allowing users to include or exclude specific layers like embeddings (`include_input_output_embeddings`) [src/transformers/quantizers/quantizer_torchao.py110-117](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_torchao.py#L110-L117) [src/transformers/quantizers/quantizer_torchao.py133-145](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_torchao.py#L133-L145)

## MXFP4 Quantization

 The `Mxfp4HfQuantizer` provides support for Microscaling Formats (MX) using E2M1 (FP4) quantization.

 
### Implementation Details

 
 - **Environment Validation**: Requires a GPU with compute capability >= 7.5 (T4, A100, H100) or Intel XPUs. If hardware support is missing, it can automatically fallback to dequantizing to `bf16` if `quantization_config.dequantize` is set [src/transformers/quantizers/quantizer_mxfp4.py92-137](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_mxfp4.py#L92-L137)
 - **Kernel Dependency**: Relies on the `kernels` package and Triton (>= 3.4.0 for CUDA, >= 3.5.0 for XPU/CPU). Kernels are lazily imported from `kernels-community/gpt-oss-triton-kernels` [src/transformers/quantizers/quantizer_mxfp4.py55-64](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_mxfp4.py#L55-L64) [src/transformers/quantizers/quantizer_mxfp4.py143-152](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_mxfp4.py#L143-L152)
 - **Linear Conversion**: Similar to other backends, it identifies `nn.Linear` layers for conversion via `get_module_from_name` [src/transformers/quantizers/quantizer_mxfp4.py31](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/quantizers/quantizer_mxfp4.py#L31-L31)

## Summary of Additional Backends

 
| Backend | Key Class / File | Primary Use Case |
|---|---|---|
| MXFP4 | Mxfp4HfQuantizer | Microscaling formats (E2M1) for OCP standards using Triton kernels. |
| Quanto | QuantoHfQuantizer | Versatile PyTorch-native quantization (INT4/8, FP8). |
| HQQ | HqqQuantizer | High-quality 4-bit quantization without calibration data. |
| EETQ | EetqQuantizer | High-performance INT8 weight-only quantization for GPUs. |
| AQLM | AqlmQuantizer | Additive Quantization for Language Models (extremely low bitrates). |
| CompressedTensors | CompressedTensorsQuantizer | Unified format for storing quantized weights via compressed-tensors lib. |
| VPTQ | VptqQuantizer | Vector Post-Training Quantization for extremely high compression. |
