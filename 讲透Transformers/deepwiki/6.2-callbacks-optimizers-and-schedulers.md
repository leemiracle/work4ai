  This page details the extensible components of the training loop within the Hugging Face Transformers library. It covers the `TrainerCallback` system for injecting custom logic into the `Trainer`, the optimization utilities for parameter updates, and the learning rate scheduling infrastructure.

 
## Callback System

 The `TrainerCallback` system allows users to hook into specific points of the training loop without modifying the `Trainer` class directly [src/transformers/trainer_callback.py15-16](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/trainer_callback.py#L15-L16) The `CallbackHandler` orchestrates these calls across all registered callbacks [src/transformers/trainer_callback.py47](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/trainer_callback.py#L47-L47)

 
### TrainerCallback Interface

 A `TrainerCallback` receives three primary objects at each hook:

 
 - `TrainingArguments`: The configuration for the current training run [src/transformers/trainer_callback.py27](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/trainer_callback.py#L27-L27)
 - `TrainerState`: The internal state of the trainer (e.g., current step, log history, best metric) [src/transformers/trainer_callback.py35-93](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/trainer_callback.py#L35-L93)
 - `TrainerControl`: A set of flags that the callback can modify to influence the `Trainer` flow (e.g., `should_training_stop`, `should_save`, `should_log`) [src/transformers/trainer_callback.py47](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/trainer_callback.py#L47-L47)

### Built-in Callbacks

 Transformers provides several standard callbacks for logging and flow control:

 
 - **`DefaultFlowCallback`**: Handles default logging, saving, and evaluation timing based on `TrainingArguments` [src/transformers/trainer_callback.py26](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/trainer_callback.py#L26-L26)
 - **`EarlyStoppingCallback`**: Monitors a metric and sets `control.should_training_stop` if the metric stops improving [src/transformers/trainer_callback.py26](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/trainer_callback.py#L26-L26)
 - **`ProgressCallback`**: Handles the `tqdm` progress bar updates during training and evaluation [src/transformers/integrations/integration_utils.py97](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/integration_utils.py#L97-L97)
 - **`TensorBoardCallback`**: Logs scalars and histograms to TensorBoard [docs/source/en/main_classes/callback.md49](https://github.com/huggingface/transformers/blob/8f542025/docs/source/en/main_classes/callback.md?plain=1#L49-L49)
 - **`WandbCallback`**: Integrates with Weights & Biases for experiment tracking [src/transformers/integrations/integration_utils.py104-112](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/integration_utils.py#L104-L112)
 
 
### State Persistence

 Callbacks can be stateful by inheriting from `ExportableState`. Their state is saved within the `TrainerState` and persisted in checkpoints [src/transformers/trainer_callback.py114-141](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/trainer_callback.py#L114-L141)

## Optimizers

 The `Trainer` supports a wide range of optimizers through the `TrainingArguments`. The selection is typically controlled via the `optim` argument [src/transformers/training_args.py91](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/training_args.py#L91-L91)

 
### Supported Optimizer Types

 
| Optimizer Identifier | Implementation / Backend | Integration Check |
|---|---|---|
| adamw_torch | torch.optim.AdamW | src/transformers/training_args.py91 |
| adafactor | transformers.optimization.Adafactor | docs/source/ja/main_classes/callback.md31 |
| adamw_bnb_8bit | bitsandbytes 8-bit AdamW | src/transformers/integrations/integration_utils.py104 |

 
### Integration with External Libraries

 The library uses utility functions to detect the availability of specialized optimizers and logging frameworks, such as `is_wandb_available`, `is_mlflow_available`, and `is_comet_available` [src/transformers/integrations/integration_utils.py104-180](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/integrations/integration_utils.py#L104-L180)

## Learning Rate Schedulers

 Learning rate scheduling is managed via `SchedulerType` enums in `TrainingArguments` [tests/trainer/test_training_args.py11-12](https://github.com/huggingface/transformers/blob/8f542025/tests/trainer/test_training_args.py#L11-L12)

 
### Scheduler Types

 The system supports several schedules including:

 
 - `linear`: Linear decrease from the initial LR to 0 [tests/trainer/test_training_args.py90](https://github.com/huggingface/transformers/blob/8f542025/tests/trainer/test_training_args.py#L90-L90)
 - `cosine`: Cosine curve decrease.
 - `constant`: LR remains fixed.
 - `inverse_sqrt`: LR decreases following the inverse square root of the step count.

## Training Examples & No-Trainer Patterns

 While the `Trainer` is the primary interface, the library also provides `no_trainer` scripts (e.g., `run_glue_no_trainer.py`) which use the `accelerate` library directly for users who need full control over the training loop [examples/pytorch/test_accelerate_examples.py82](https://github.com/huggingface/transformers/blob/8f542025/examples/pytorch/test_accelerate_examples.py#L82-L82)

 
### Execution Flow in Examples

 
 - **Initialization**: Loading model and tokenizer via `Auto` classes.
 - **Data Loading**: Using `datasets` and `DataCollator` [tests/trainer/test_trainer_checkpointing.py51](https://github.com/huggingface/transformers/blob/8f542025/tests/trainer/test_trainer_checkpointing.py#L51-L51)
 - **Optimization Setup**: Defining the optimizer and scheduler based on `TrainingArguments`.
 - **Training Loop**: Iterating through epochs and steps, triggering `TrainerCallback` hooks at boundaries [tests/trainer/test_trainer_callback.py72-118](https://github.com/huggingface/transformers/blob/8f542025/tests/trainer/test_trainer_callback.py#L72-L118)
 - **Checkpointing**: Saving `TrainerState`, model weights, and optimizer states [tests/trainer/test_trainer_checkpointing.py49-50](https://github.com/huggingface/transformers/blob/8f542025/tests/trainer/test_trainer_checkpointing.py#L49-L50)
