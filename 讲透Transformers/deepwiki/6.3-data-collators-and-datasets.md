  Data Collators are specialized strategy objects used to form batches from a list of dataset elements. They are responsible for applying dynamic padding, applying task-specific transformations (like random masking for Language Modeling), and converting raw data structures into framework-specific tensors (PyTorch or NumPy) [src/transformers/data/data_collator.py30-34](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/data/data_collator.py#L30-L34)

 
## Data Collator Architecture

 The library defines a base `DataCollator` as a `Callable` that transforms a list of samples into a dictionary of tensors [src/transformers/data/data_collator.py34](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/data/data_collator.py#L34-L34) The `DataCollatorMixin` provides the standard interface for handling different return types via `torch_call` and `numpy_call` [src/transformers/data/data_collator.py37-47](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/data/data_collator.py#L37-L47)

 
### The Default Data Collator

 The `default_data_collator` is the simplest implementation. It performs basic batching for dictionary-like objects, with specific logic for `label` and `label_ids` keys to ensure they are cast to the correct dtypes (e.g., `torch.long` for classification or `torch.float` for regression) [src/transformers/data/data_collator.py71-81](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/data/data_collator.py#L71-L81) [src/transformers/data/data_collator.py133-142](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/data/data_collator.py#L133-L142)

## Specialized Task Collators

 
### 1. DataCollatorWithPadding

 This collator is used for sequence classification and other tasks where inputs must be padded to the length of the longest sequence in the batch [tests/trainer/test_data_collator.py39](https://github.com/huggingface/transformers/blob/8f542025/tests/trainer/test_data_collator.py#L39-L39) It uses the provided `tokenizer` to perform the padding operation via `pad_without_fast_tokenizer_warning` to suppress sub-optimal padding warnings when using fast tokenizers [src/transformers/data/data_collator.py49-68](https://github.com/huggingface/transformers/blob/8f542025/src/transformers/data/data_collator.py#L49-L68)

 
### 2. DataCollatorForLanguageModeling

 Designed for Masked Language Modeling (MLM) and Causal Language Modeling (CLM).

 
 - **MLM**: Randomly masks tokens (default 15%) in the input sequence to create training targets [tests/trainer/test_data_collator.py33](https://github.com/huggingface/transformers/blob/8f542025/tests/trainer/test_data_collator.py#L33-L33)
 - **Whole Word Masking**: Variants like `DataCollatorForWholeWordMask` ensure that if one token of a word is masked, all tokens belonging to that word are masked [tests/trainer/test_data_collator.py37](https://github.com/huggingface/transformers/blob/8f542025/tests/trainer/test_data_collator.py#L37-L37)
 - **Permutation LM**: `DataCollatorForPermutationLanguageModeling` is used for models like XLNet that require specific permutation masking [tests/trainer/test_data_collator.py34](https://github.com/huggingface/transformers/blob/8f542025/tests/trainer/test_data_collator.py#L34-L34)
 
 
### 3. DataCollatorForSeq2Seq

 Specifically handles encoder-decoder models (e.g., T5, BART). It pads both the `input_ids` and the `labels`. Crucially, it replaces padding tokens in the labels with `-100` so they are ignored by the standard loss functions in PyTorch [tests/trainer/test_data_collator.py35](https://github.com/huggingface/transformers/blob/8f542025/tests/trainer/test_data_collator.py#L35-L35)

 
### 4. DataCollatorForTokenClassification

 Used for tasks like NER. It pads the labels alongside the input IDs, ensuring that label sequences match the length of the padded input sequences [tests/trainer/test_data_collator.py36](https://github.com/huggingface/transformers/blob/8f542025/tests/trainer/test_data_collator.py#L36-L36)

## Immutability and Testing

 A core requirement for Data Collators in the `transformers` library is **immutability**. Collators must not modify the input `features` list in-place, as this list is often reused by the `DataLoader` or caching mechanisms. The `DataCollatorTestMixin` provides a `_check_immutability` helper to enforce this during development by comparing deep copies of inputs before and after collation [tests/trainer/test_data_collator.py67-81](https://github.com/huggingface/transformers/blob/8f542025/tests/trainer/test_data_collator.py#L67-L81)

 
| Collator Class | Primary Task | Key Logic |
|---|---|---|
| DefaultDataCollator | General | Simple stacking of tensors, handles label and label_ids src/transformers/data/data_collator.py95-104 |
| DataCollatorWithPadding | Classification | Dynamic padding to max batch length using tokenizer.pad tests/trainer/test_data_collator.py39 |
| DataCollatorForLanguageModeling | MLM/CLM | Random token masking (15%) or shifting for CLM tests/trainer/test_data_collator.py33 |
| DataCollatorForSeq2Seq | Translation/Summ | Label padding with -100 to ignore in loss tests/trainer/test_data_collator.py35 |
| DataCollatorForTokenClassification | NER/POS | Label alignment and padding to match input IDs tests/trainer/test_data_collator.py36 |
| DataCollatorWithFlattening | Multiple Choice | Flattens input dimensions (e.g., for Roberta) tests/models/roberta/test_modeling_roberta.py19 |
