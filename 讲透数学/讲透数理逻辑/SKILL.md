## 一、何时用此分支(触发特征)

- 「这个命题/性质能不能被**证明系统**自动推出?」「有没有**算法**判定?」
- 「这个语言的**表达力**够不够?」「公理系统**一致/完备**吗?」
- 听到:**不完备性、紧致性、Löwenheim–Skolem、停机问题、可判定、不可判定**
- 「存在性证明**拿得出东西**吗?」(构造 vs 反证的成色之问)
- 形式验证:模型检查、SAT/SMT、定理证明助手、类型系统
- 「AI 说它证明了 X」——要问「经过机器检查吗?」(Lean/Isabelle)
- 想给某个数学分支**公理化定级**(自然语言→一阶→形式系统→机器可检)

## 二、核心思维模式

1. **语法 vs 语义对译**:证不出来,先分清是「语言说不出」(表达力)还是
   「推理规则够不着」(完备性)还是「根本没有模型」(一致性)。三者药方完全不同。
2. **编码与自指**:让系统谈论自己(Gödel 数、Quine 程序)是本分支的万金油——
   遇到悖论/不确定性,先找编码通道。
3. **对角化**:枚举 × 取反 = 越界证明的标准动作(Russell/Gödel/Cantor/停机共用)。
4. **价目表思维**:任何更强语言的每次扩容,都在卖掉某条元定理(完备性/紧致性/可判定性)。
5. **成色思维**:听到「存在」,追问是构造的(带算法)还是经典的(只保不矛盾)。

## 三、工具箱(定理/方法 + 什么时候用)

| 工具 | 一句话何时用 |
|------|-------------|
| 紧致性定理 | 证「有限可满足⟹可满足」;造非标准模型(*ℝ 的发动机) |
| LST 定理 | 判断「一阶语言能锁住基数吗」——答案:不能 |
| Gödel 完备性(FO) | 要把「语义有效」兑现为「可形式证明」时 |
| Gödel 不完备 I/II | 评估任何形式系统的能力天花板与一致性自证禁区 |
| 停机不可判定 | 反驳「万能分析器/万能验证器」的存在;归约的基础 |
| 可判定孤岛表(Presburger/实闭域可判;PA 不可判) | 选 SMT 背景理论;选规格语言 |
| Herbrand 定理 | 把一阶问题落地成命题 SAT(SAT 求解工作流的理论根基) |
| Craig 插值 | 模块化验证:两个模块间只谈公共接口 |
| Curry–Howard | 把「证明」当「程序」处理(类型系统设计/证明助手) |
| 归约(≤m/≤T) | 把新问题挂到已知不可判定/NP-完全问题上 |

## 四、常见误区与禁忌

- ❌ **不完备 ≠ 不可知**:不完备只说「存在不可证句」,不阻止任何具体定理被证明
- ❌ **独立性 ≠ 无意义**:CH 独立于 ZFC 恰恰说明 ZFC 是个「小公理系统」,不是数学崩塌
- ❌ **LST ≠ 集合论矛盾**:「可数模型内谈不可数」是语言局限的展览,不是悖论
- ❌ 「可判定」≠「算得动」:命题逻辑可判定但 NP-完全;复杂度是第二道关卡
- ❌ 把 Curry–Howard 读成哲学口号:它是带消歧规则的精确对应(切消=范式)
