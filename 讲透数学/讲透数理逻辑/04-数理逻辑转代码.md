# 04 · 数理逻辑转代码:把推理装进机器

> **本章回答五问之五(家族层):这个分支的问题怎么变成 code 问题?**
> 本质一句话:**数理逻辑是唯一「定理即程序、证明即代码」的分支**——
> 它的每条元定理都直接对应一个软件品类;本家族四条代码走廊,
> 全宇宙没有第二个分支有这样的产业映射。

---

## 〇、先给直觉:元定理 = 产品需求书

别的分支「转代码」要走「数学对象→数据结构」的翻译(见 ../讲透分析/04-分析转代码.md
的浮点化身);本家族不用——**它的对象本来就是语法**(公式、证明、计算)。
所以它的历史就是一部「理论先行、产品殿后」的年表:

| 元定理(年代) | 30-90 年后变成的产品 |
|--------------|---------------------|
| 完备性+Herbrand(1930) | SAT/SMT 求解器(1990s-今) |
| 图灵机(1936) | 一切计算机与编程语言 |
| Curry–Howard(1934/1958/1969) | 类型系统(ML/Rust/TypeScript 的每一行) |
| 切消/自然演绎(1934) | Lean/Coq/Agda 证明助手 |
| 模型检查理论(1977/1981) | SPIN/TLA+/NuSMV(芯片、航天、协议验证) |

## 一、可机械化边界(三件套之一):哪条线机器迈不过去

这是本家族给**全部宇宙**划的红线——每条都来自 00-02 章的定理:

| 边界 | 定理依据 | 工程含义 |
|------|---------|---------|
| **停机红线** | 停机问题不可判定(1936) | 不存在万能程序分析器:任何静态分析必在「漏报/误报/不终止」三选二 |
| **算术红线** | Gödel 不完备 I(1931) | 足够强的形式系统必有真不可证句 ⟹ 证明助手永远有 sorry 填不完的坑(但每个具体定理仍可证) |
| **二阶红线** | SOL 无完备系统 | 「验证所有正确程序」不可全自动化——规格语言选 FO 就别指望表达一切 |
| **可判定孤岛** | 理论的可判定性分类:Tarski 实闭域可判(1951);Presburger 算术可判(1929);PA(含乘法)不可判(Church 1936) | SMT 求解器的「背景理论菜单」直接照抄这张表:线性算术✓、数组✓、非线性算术✗(实闭域特例✓) |
| **复杂度红线** | FO 可判定但仅有 NEXPTIME 上界;SAT 是 NP-完全(Cook–Levin 1971) | 「可判定」≠「算得动」:工业 SAT 靠 CDCL 启发式在相变区外横行 |

**判据口诀**:*「先查可判定(孤岛表),再查复杂度(动物园),最后查表达力(价目表 02 章)」*——
三关都过,才轮到写代码。

## 二、代码走廊清单(三件套之二):四条路,各走各的定理

### 走廊 A:SAT/DPLL——Herbrand 桥的工业化

- **理论**:命题逻辑可判定(DPLL 1960/1962);CDCL=DPLL+冲突学习(1996-2001)。
- **代码化身**:CNF 求解器(minisat/cadical/kissat);本家族实验
  [`experiments/00_dpll_sat.py`](experiments/00_dpll_sat.py) 就是零依赖祖师爷版:
  单位传播 + 回溯 + 随机 3-SAT 相变实测 + 暴力对拍。
- **性能工程落点**(对 CUDA/系统工程师):CDCL 的核心是** watched literals**
  双指针懒惰传播——一次赋值只碰两个观察字;这不是「数学趣闻」,是每秒百万次传播的
  缓存友好数据结构设计课。相变点(子句/变元 ≈ 4.26)实测在实验脚本里。

### 走廊 B:模型检查——时序逻辑的穷举艺术

- **理论**:CTL/LTL 的模型检查多项式可判(CTL, Clarke–Emerson 1981);LTL 转 Büchi 自动机(Vardi–Wolper 1986)。
- **代码化身**:SPIN(协议)、TLA+(Lamport,分布式系统)、NuSMV。
- **实绩**:AWS 用 TLA+ 验证 S3/S3C;欧洲火车调度信号系统;1995 年 Pentium FDIV
  事故后浮点单元的验证流程。../讲透形式化验证/(隔壁宇宙)有 50 章实战现场。
- **边界提醒**:状态空间爆炸 ⟹ 对称约简/偏序约简/抽象——全是绕开停机红线的「侧门」。

### 走廊 C:证明助手——Curry–Howard 的产品线

- **理论**:命题=类型,证明=程序(→../讲透证明/ 04 章);切消=计算的确定性。
- **代码化身**:Lean 4 + mathlib(../讲透Lean4数学/ 是上手路径);
  mathlib 百万行=史上最大「可机检数学」(01 章已实拍 LTE/FLT/AlphaProof)。
- **工程师读法**:把 Lean 当「带数学库的编译器」——类型检查就是证明检查,
  `sorry` 是 TODO,`rfl` 是单元测试。

### 走廊 D:递归→复杂度——从「可不可算」到「多贵」

- **理论**:归约(≤m/≤T)、算术层级(../讲透证明/ 03 章呼应);NP-完全的归约动物园。
- **代码化身**:任何「把 X 问题多项式归约到 SAT 再丢给求解器」的日常工作流——
  电路布线、排班、蛋白质折叠的粗粒度模型全这么干。
- **互链**:[../讲透计算复杂度/](../讲透计算复杂度/) 是这条走廊的整座展览馆(610 类图鉴)。

## 三、工程师落点(三件套之三):本家族在工程世界的四个化身

| 化身 | 逻辑件 | 产业 |
|------|--------|------|
| **验证** | 模型检查/SMT | 芯片(Cadence/Synopsys 流水线内嵌)、航天(NASA 用 SPIN)、云服务(TLA+) |
| **类型系统** | Curry–Howard 的工程方言 | ML/Rust/Haskell/TypeScript;线性逻辑→资源管理(Rust 借用检查的逻辑血统) |
| **数据库** | 关系演算=FO;SQL 的表达力牌照 | 查询优化=逻辑等价变换;Datalog=受限制 FO 保可判定 |
| **AI×逻辑** | 一阶推理×神经 | AlphaProof(Lean 环境 RL)、定理证明基准、LLM 的形式化输出校验(01 章) |

**性能工程特别注**(读者领域):SAT 求解器是「单线程思考、纳秒级动作」的极致软件——
CDCL 的 watched literals、VSIDS 决策启发式(冲突计数衰减=注意力机制的远房表亲)、
重启策略(escape 局部陷阱)。研究它的数据结构,等于上一门「缓存与分支预测友好设计」课。

## 四、亲手跑:本家族实验

[`experiments/00_dpll_sat.py`](experiments/00_dpll_sat.py)(纯标准库,<200 行):

1. 实现 DPLL:单位传播、纯文字省略、回溯;
2. 随机 3-SAT 实例族:扫描子句/变元比 α∈[3,6],实测可满足率与代价曲线——
   **亲眼看相变**(α≈4.26 处可满足率断崖);

(你跑的每个 CNF 就是某个一阶问题落地后的命题骨架)。

## 六、走廊选型速查(把问题送进哪条走廊)

```
你的问题
 ├─ 有限状态系统,要验证时序性质(「永远不发两个 grant」)
 │    └─▶ 走廊 B 模型检查:性质写成 LTL/CTL,SPIN/TLA+ 穷举状态空间
 ├─ 组合约束求解(排班/布线/配置)
 │    └─▶ 走廊 A SAT/SMT:问题编译成 CNF,丢给 minisat/z3
 ├─ 要数学级保证(不只是性质检查,是定理证明)
 │    └─▶ 走廊 C 证明助手:Lean/Coq;优先找 mathlib 有没有现成引理
 └─ 想知道「这问题本质上难不难」
      └─▶ 走廊 D 归约:找已知 NP-完全/不可判定问题归约过去(→../讲透计算复杂度/)
```

**预算口径**(经验数量级,供立项参考):走廊 A/B=天到周;走廊 C=周到月(LTE 花了半年,6 人核心);走廊 D=纸笔。
