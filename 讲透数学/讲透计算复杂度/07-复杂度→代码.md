## 1 直觉：归约是一段代码

复杂度理论最核心的动作——**归约**（reduction）——的工程定义就是：

> **归约 = 一个确定性多项式时间的函数 `trans`，把问题 A 的实例映射成问题 B 的实例，使得 `solveA(x) = solveB(trans(x))`。**

它不是抽象概念，是一段可以写、可以跑、可以测试的代码。本章把这个定义钉死在两件事上：

1. **亲手实现 SAT → 3-SAT 归约**（Cook-Levin 世界观的 30 行化身）；
2. **亲手实现 DPLL**（"指数最坏"与"实践可行"的张力现场）。

然后给出工程师视角的收口：复杂度类是什么（资源契约）、不是什么（性能预言）。

## 2 数学→代码：三段可跑的实现

### 2.1 SAT ↔ 3-SAT：归约即代码变换

SAT 实例：子句列表，每子句是文字（正/负变量）列表。归约把任意长子句拆成 3-CNF（Tovey 标准化）：

```python
def sat_to_3sat(clauses):
    """任意子句 SAT → 恰 3 文字子句 3-SAT。多项式时间、保持可满足性。"""
    out, fresh = [], 0                       # fresh: 新变量计数器
    for cl in clauses:
        while len(cl) > 3:                   # 长子句：引入 1 个新变量 z 链式截断
            fresh += 1; z = ("z", fresh)
            out.append(cl[:2] + [z])         # (l1 ∨ l2 ∨ z)
            cl = [neg(z)] + cl[2:]           # (¬z ∨ l3 ∨ l4 ∨ …) 继续拆
        out.extend(pad(cl))                  # 短子句：重复文字填充到恰 3
    return out

def neg(lit):                                # 文字取反
    return (lit[0], not lit[1])

def pad(cl):
    """≤3 文字的子句 → 恰 3 文字（重复任一文字不改变可满足性）。"""
    if not cl: return []                     # 空子句=不可满足，原样保留（哨兵）
    while len(cl) < 3: cl = cl + [cl[0]]
    return [cl]
```

**走读三个点**（对应 01 章 Cook-Levin 的"计算变成公式"）：

1. `while len(cl) > 3` 的链式拆分：`(a∨b∨c∨d)` 变 `(a∨b∨z)(¬z∨c∨d)`——**新变量 z 是"接力证据"**：原句满足 ⟺ 两句联立满足。归约的正确性证明 = 这两行注释的展开；
2. 多项式性一眼可见：每子句至多放大 2 倍。**"多项式归约"的'多项式'在代码里就是循环不嵌套**；
3. 反方向 3-SAT → SAT 是恒等映射（3-SAT ⊆ SAT）——**SAT 的 NP-完全性=任何 NP 问题都能走到这里**，链路的最后一环永远长这样。

### 2.2 DPLL：最坏指数与实践可行

```python
def dpll(clauses, assign):
    """最小 DPLL：单位传播 + 纯文字 + 分支。最坏 O(2^n)，工业实例常近多项式。"""
    while True:                              # 单位传播：单文字子句直接定值
        units = [c[0] for c in clauses if len(c) == 1]
        if not units: break
        lit = units[0]
        clauses = [ [l for l in c if l != neg(lit)] for c in clauses if lit not in c ]
        assign = {**assign, lit[0]: lit[1]}
        if [] in clauses: return None        # 空子句=冲突
    for v, s in assign.items(): pass         # (纯文字省略——教学版)
    if not clauses: return assign            # 全满足
    lit = clauses[0][0]                      # 分支：猜第一个文字
    for guess in (lit, neg(lit)):
        cl2 = [ [l for l in c if l != neg(guess)] for c in clauses if guess not in c ]
        res = dpll(cl2, {**assign, guess[0]: guess[1]})
        if res is not None: return res
    return None
```

**理论读法**：递归树深度 ≤ 变量数——**最坏 O(2^n)，这就是"NP ⊆ EXP"的一行证明**（01 章谱系定理的代码侧）。**实践读法**：单位传播在真实实例上剪掉绝大多数分支——工业 SAT 求解器（CDCL = DPLL + 冲突子句学习 + VSIDS 启发式）在百万变量实例上常秒解。**同一个算法，两种时间**——复杂度类刻画的是**契约的最坏端**，不是你的实例。

## 3 Lean 展望（形式化接口）

**Mathlib 现状**（2026）：图灵机与可计算性理论已形式化（`Turing.Computability`、`Complexity` 命名空间起步），但**复杂度类（P、NP、NP-完全）尚无 Mathlib 级 API**——社区正在进行的工作包括时间谱系与 Cook-Levin 的形式化攻坚（[讲透Lean4数学](../讲透Lean4数学/README.md) 系列的 Natural Number Game 路线是入口，`sorry` 填空式练习复杂度证明正缺这类地基）。

**值得跟踪的三个方向**：① 复杂度基本引理（对角化、放大、 Cook-Levin 的历史表构造）的形式化——历史表恰是 SAT 编码，本系列 2.1 的 30 行代码可以直译 Lean；② **形式化验证工具链（SAT/SMT/BDD）与复杂度类的互证**——[讲透形式化验证 50-复杂度动物园与选型](../../讲透形式化验证/50-复杂度动物园与选型.md) 从工具侧已架好桥；③ MIP*=RE 级"跨领域大定理"的形式化（谱与表示论部分远超当前 Mathlib 覆盖）——复杂度理论的形式化落差本身就是研究前沿。

## 4 不足：复杂度类不是什么

1. **不是性能预言**：CDCL/启发式/平均情形与最坏契约的落差是常态（07.2 的现场）——把 NP-难当"会慢"是初级误读；
2. **不是常数因子盲区**：O(n log n) vs O(n) 在大 n 工程里是生死线，复杂度类的多项式等价类完全无视它——**复杂度理论与性能工程（本仓 [讲透高性能计算](../../讲透高性能计算)、[讲透GPU与系统级](../../讲透GPU与系统级) 的主场）是相邻层而非同一层**；
3. **AI 时代的诚实边界**：LLM 的"推理链长度 ↔ 计算步数"类比只能给直觉——CoT 展开把深度换长度，与 NC vs P 的权衡**同构但不等同**（没有定理，只有隐喻）；复杂度理论对"涌现能力"暂无成形刻画，任何强主张都超出本章证据。

## 5 应用：工程师决策表

拿到一个计算问题时的复杂度决策树（本系列的最终交付物之一）：

| 情形 | 动作 | 章节依据 |
|------|------|---------|
| 判定在 P | 找最快多项式算法 + 常数优化 | 01 |
| NP-难，参数小（k ≤ ~40） | FPT/核化/分支 | 06 |
| NP-难，要近似 | APX/PTAS 地图 + 硬度红线 | 06/05 |
| NP-难，最坏罕见 | SAT/CP 求解器 + 平均情形分析 | 07.2 |
| 全函数搜索（保证有解） | TFNP 家族谱系（PPAD/PLS 启发式） | 06 |
| 可判定边界之外 | RE/不可判定：寻求半自动+人工闭环 | 00/05 |
| 要"可信外包" | 零知识/PCP 系（SNARK 工具链） | 05 |

**最后一句判词**：复杂度动物园的 610 个类，对工程师是一张**资源契约目录**——每个类是一份"在这个预算内保证能做到/做不到什么"的合同。读合同是为了不被忽悠：既不被"NP-难所以放弃"忽悠，也不被"我们实测很快"忽悠。**理论给边界，工程在边界内跳舞**——这正是讲透范式第五幕"应用"的复杂度版。
