# 04 · 计算机数学转代码:领域的转码,就是领域本身

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 本质一句话:别的分支「转代码」是**翻译**(把对象编码、把定理变实验),
   本域的转代码是**本体**——它研究的对象就是程序,所以它的每条定理天然可执行。
   本章给三条工业级代码走廊 + 一张工程落点地图(性能工程视角)。

---

## 开篇:一个「翻译为零」的领域

📖 讲透分析要转代码,先造「可计算实数」;讲透几何要转代码,先做「浮点网格」——
每个分支都要跨一道编码鸿沟。本域没有这道鸿沟:**停机问题是关于程序的,
证明程序性质的程序也是程序**。当 Gödel 给「程序」编号(每个程序一个自然数)时,
翻译已经完成——而且这次翻译是**完美无损**的(程序与编号一一对应)。
所以本章不问「怎么转」,问「**转到哪条走廊、停在哪个边界**」。

## 一、可机械化边界(哪些问题机器可解,哪些永不可)

| 领域问题 | 可机械化? | 边界定理 |
|---|---|---|
| 验证给定证明(检查证明项) | ✅ 完全 | 类型检查可判定——Lean 内核的全部生意 |
| 证明可判定理论中的命题(命题逻辑/SAT/线性算术/Presburger) | ✅ 完全 | 各理论判定算法(DPLL/单纯形/Cooper) |
| 寻找证明(自动定理证明) | ⚠️ 半 | 一阶逻辑半可判定:枚举证明能找到真定理的证明,但可能永不停 |
| 判定程序任意语义性质 | ❌ 永不 | Rice 定理(停机问题的全称版) |
| 验证「验证器自身正确」 | ❌(系统内) | 哥德尔第二不完备性 |
| 判定两个程序等价 | ❌ 永不 | Rice 定理特款 |

**边界地图一句话**:**检查永远可行,搜索永远没底,全局判定永无可能**——
这就是「证明助手存在而『万能证明机』不存在」的完整数学解释。

## 二、代码走廊清单(三条工业级走廊)

### 走廊 A:证明助手(Lean / Coq / Agda)——「人机分工」走廊

```lean
-- Lean 4:恒等定理=恒等函数(Curry–Howard 现场直播)
theorem id_theorem (A : Type) : A → A := fun a => a

-- 不变式练手:归纳即递归
def add : Nat → Nat → Nat
  | 0, n => n
  | m+1, n => (add m n) + 1
termination_by m   -- 良基性:第一参数下降(03 章骨架三)
```
**适用**:数学定理形式化、程序与其规格一起证明、数据结构不变式。
**成本**:学习曲线 1-3 月;形式化速度约纸笔证明的 1/10(回报:零差错)。
**入口**:[`../讲透Lean4数学/`](../讲透Lean4数学/)(NNG 起)、
[`../讲透证明/`](../讲透证明/)04 章(证明转代码)。

### 走廊 B:模型检查器(TLA+ / SPIN / NuSMV)——「穷举状态宇宙」走廊

```
---- MODULE TwoPhaseCommit ----   (TLA+ 风格伪码)
Inv == ∀ t ∈ Transactions : ¬(Prepared(t) ∧ Aborted(t))
Spec == Init ∧ □[Next]_vars          \* 时序逻辑:永远安全
====
```
**适用**:协议/并发/硬件控制状态机;性质用时序逻辑(LTL/CTL)写,检查器穷举或抽象。
**边界**:状态爆炸——理论 PSPACE 完全,实践靠符号方法(04 章 01 节的裂隙)。
**工业案例**:AWS 用 TLA+ 验证 S3/EC2 关键协议;seL4 内核完整形式验证。

### 走廊 C:SAT/SMT 求解器(MiniSat / Z3)——「约束即问题」走廊

```python
# Z3(Python API):程序验证的自动化背骨
from z3 import *
x, y = Ints('x y')
s = Solver()
s.add(x >= 0, y >= x, 2*y - x <= 10)      # 路径条件
s.add(Not(3*y - 2*x >= 0))                # 目标的否定(找反例)
print(s.check())  # unsat ⟹ 一切满足路径条件的输入都满足目标 ⟹ 该路径验证通过
```
**适用**:循环不变式自动合成、反例搜索(验证的对偶=测试的机械化)、
密码协议分析、调度/配置约束。
**边界**:线性算术可判定、非线性半可判定——喂错片段,check 可能永不停机。

### 走廊间的选择表

| 你的问题 | 走道 |
|---|---|
| 数学定理要绝对可靠 | A(Lean) |
| 并发/协议的「永远不做坏事」 | B(TLA+) |
| 程序片段/约束的快速判定与反例 | C(Z3/SAT) |
| 大型既有 C/Java 代码 | B/C 的混合(Dafny/Verifast 在源码级缝合 A 的逻辑与 C 的自动化) |

## 三、工程师落点(性能工程视角,写给做系统/算子的你)

> 用户领域对齐:CUDA 算子/编译/模型优化。本域对你不是「另一门数学」,
> 是性能工程的**保险单与放大器**。

| 落点 | 数学内容 | 工程回报 |
|---|---|---|
| **编译器正确性** | 语义保持 = 证明变换;CompCert(C 编译器)每步优化带语义等价证明 | 优化越激进,越需要「变换不改行为」的定理;O3 的每一 pass 都是一次 Hoare 三元组 |
| **算子替换/融合的等价性** | 两程序等价不可判定(Rice)⟹ 实务用:受限 IR 片段上 SMT 等价检查(XLA/TVM 的 pattern 改写) | 融合合法性自动证明;不能判定的退化成「保守白名单」——你现在知道那是什么妥协 |
| **性能模型的保证** | 加速定理:没有全胜优化器 ⟹ auto-tuning 必须留逃逸通道 | 解释了为什么 TVM/Ansor 的搜索空间永远需要 fallback;「最优化编译」有数学天花板 |
| **并行正确性** | 不变式+时序逻辑:数据竞争=不变式破坏的特例 | GPU kernel 的 memory consistency 验证(工业:KIND/GPUVerify 路线) |
| **AI 生成代码的审计** | 生成不可信 ⟹ 验证需求激增:类型即规格的第一道闸 | 用最窄类型/断言围住 LLM 产物;能形式化的核心路径走走廊 B/C |

**一句话**:性能工程的每一步「更快」,都该配一句「且不变」——
那句「且不变」的数学,全在本域三条走廊里。

## 四、反直觉发现

1. **测试的数学地位**:测试=构造存在性证明(找到一个坏输入 ⟹ 程序错),
   但**永远构不成正确性证明**(穷举=停机)。TDD 的数学本质是「快速找反例」,
   不是「逼近证明」——两者不可通约。
2. **验证越自动,规格越贵**:走廊 B/C 的检查几乎免费,难在写出 Inv/断言——
   形式化成本从「检查」转移到「规格」(01 章开问题的工程版)。
3. **`unsat` 是好消息**:Z3 返回 unsat(目标否定无解)⟹ 验证通过——
   「找不到反例」在可判定片段内**等于**「正确」,这是可判定性买到的
   唯一一处「不存在=存在」的翻转。

## ✨ 美之时刻

**✨ trusted kernel 的极简之美**。Lean 的全部信任基础是数千行内核代码
(检查证明的规则表);其上是百万行库与 AI,但**一行都不必信任**——
信任面被压缩到可人工审计的极限。这是「小内核大世界」的结构美学,
与性能工程里「热路径最小化」异曲同工。亲历:读 Lean 内核的 `whnf`/`isDefEq`
主循环(数千行),再对照 mathlib 的两百万行——杠杆比约 1:500。

## 🧠 认知升维

- **走廊眼**:拿到「要保证对」的需求,先分类走哪条走廊——
  定理(Lean)/协议(TLA+)/片段(Z3),选错走廊比不验证更浪费
- **对偶眼**:验证与反例搜索是同一台机器的两个方向——
  写 Not(goal) 喂求解器,是把「证明题」翻成「找茬题」的日常操作
- **信任预算眼**:信任像内存,要显式分配——内核/规格/测试各占多少,
  说得清的团队才是真的在做工程
