# 02 · 语言特征:程序即语言,类型即命题

> **本章回答五问之三:这个分支的语言长什么样——表达力、逻辑性质、规范化程度。**
> 本质一句话:计算机数学的「母语」是**自指的**——它用语言谈论语言,
   用程序研究程序,用证明检查证明。

---

## 开篇:三个教堂,一个上帝

📖 1936 年前后,三个人在互不通气的情况下各自发明了「计算」的定义:
- 丘奇:**λ 演算**——函数抽象与应用的两符号语言(程序设计语言之祖)
- 图灵:**图灵机**——纸带与状态机的机械模型(计算机之祖)
- 哥德尔(经 Herbrand 提示):**一般递归函数**——数论函数的生成式定义(数学之祖)

三种语言气质迥异,计算的函数类却**分毫不差**。这不是巧合,是「算法」这个概念
客观存在的证据(丘奇-图灵论纲)。本家族的语言学,就是从这次三教堂等价开始的。

## 一、表达力(能说什么,不能说什么)

**直觉图像**:把程序语言想成一张渔网——网眼大小=表达能力。
λ 演算与图灵机是**同一张最密的网**(图灵完备);更弱的语言(正则表达式、上下文无关文法)
是网眼更粗的网,捕不到全部可计算函数,但换来可判定性。

**严格陈述**:按 Chomsky 层次,形式语言分四级——正则 ⊂ 上下文无关 ⊂ 上下文有关 ⊂ 递归可枚举;
每级恰好对应一类自动机(有限自动机/下推自动机/线性有界自动机/图灵机)。

**最小例子**:语言 L={aⁿbⁿ : n≥0} 不是正则的(泵引理可证),
但一行上下文无关文法 S→aSb | ε 就能生成——「配对/嵌套」结构天然越出正则之力。

**表达力的天花板与地板**:

| 层 | 语言 | 能表达 | 永远表达不了 |
|---|---|---|---|
| 最密 | 图灵机/λ 演算/一般递归 | 一切可计算函数 | 停机判定(Rice 类的一切语义判断) |
| 中 | 上下文无关文法 | 嵌套结构(括号匹配、语法树) | aⁿbⁿcⁿ(三重计数) |
| 粗 | 正则表达式 | 有限状态的模式 | 任意计数与配对 |
| 特殊 | **类型系统**(依值类型) | 命题与证明本身 | 不完备系统内的全部真命题(哥德尔) |

**为什么是这样**:表达力每升一级,买来新结构,必失去一条可判定性——
语言与元语言(谈论语言的语言)之间永远隔着一条对角化天堑。
**没有免费的表达力**,这是本域语言经济学的第一定律。

## 二、逻辑性质(完备?一致?可判定?)

三步法讲最关键的一条——「 Curry–Howard 对应」:

- **直觉图像**:命题是「形状」(类型),证明是「 inhabitant」(该类型的居民/值)。
  「A 蕴涵 B」=「从 A 的居民造出 B 的居民」= 一个函数。「证明 B」=「写出类型 B 的程序」。
- **严格陈述**:构造类型系统中,A true ⟺ A inhabited;⟹-引入=λ 抽象,
  ⟹-消解=函数应用,∧=积类型,∨=和类型,∀=依值积(Π),∃=依值和(Σ)。
  证明的规范化(切消)⟺ 程序的求值。
- **最小例子**:命题 `A → A` 的证明就是恒等函数 `fun a => a`。
  在 Lean 里输入 `example (A : Type) : A → A := fun a => a`——你刚写下一个
  拉姆达,也刚证明一个定理,二者是**同一个符号串**。

| 性质 | 状态 | 意义 |
|---|---|---|
| 图灵完备语言的**成员资格**判定 | 半可判定(递归可枚举不递归) | 「这段代码是否产出 x」只能正向搜索,无法否证 |
| 一阶逻辑的有效性(validity) | 半可判定(图灵 1936:可枚举不可判) | 自动定理证明器的「不完备但不停机希望」 |
| 命题逻辑/正则语言/Hoare 逻辑的可判定片段 | **可判定** | 模型检测/SAT 的产业基础 |
| 类型检查(依值类型) | 可判定(对 restricted 系统,如 Lean 的可判定层) | 「证明检查」之所以能自动化,全靠这条 |
| 系统一致性 | 不能在系统内自证(哥德尔第二) | Lean 相信 ZFC+不可达基数——信任最终有一层人工地基 |

**反直觉**:一阶逻辑 validity 不可判定(Church-Turing 1936),但**实践中 SAT 求解器
屠杀了指数最坏情形**——CDCL 求解器在百万变量工业实例上畅通无阻。
语言的可判定性分级给的是**数学保证**,不是**性能预测**;
两者之间的裂隙正是「理论 CS 与工程 CS」的搞笑日常(也是本域与
[`../讲透计算复杂度/`](../讲透计算复杂度/)的分工线)。

## 三、规范化程度(公理化到哪一级)

本域可能是全数学**规范化程度最高**的分支——它卖的就是规范化:

| 规范化层级 | 内容 |
|---|---|
| 计算模型级 | 三个等价定义(图灵机/λ/递归)互相翻译,殊途同归——「算法」的定义无争议 |
| 程序语义级 | 操作/指称/公理三种语义在核心语言上等价;Hoare 逻辑与操作语义可靠且完备(相对完备,需要回环规则) |
| 证明系统级 | Curry–Howard:逻辑系统 ⟷ 类型系统逐条对应(直觉主义逻辑=简单类型 λ;一阶=依值类型;经典逻辑=控制算子/续延) |
| 工业标准级 | Lean 的 `theorem`/`sorry`/`#check`;Coq 的 Gallina——证明的每一步是**语法事实**,检查器代码极小(TCNV:trusted kernel 数千行) |

**为什么能到这级**:因为对象本来就是符号串——数学对象即符号,
不需要先做「数学对象的编码」。别的分支形式化要先翻译(把函数翻成数),
本域生来就是母语。

## 四、与其他分支的语言对比(联系表)

| 分支 | 语言气质 | 对比 |
|---|---|---|
| 数理逻辑(母) | 研究语言的语言 | 本域是它的「工程部」:逻辑给语法,本域给机器 |
| 讲透证明 | 切消=证明的规范化 | 对应本域:β-归约=程序的求值——同一个定理的两副面孔 |
| 讲透计算复杂度 | 语言分级+资源计数 | 它问「这张网多贵」,本域问「这张网捕什么」 |
| 讲透优化/算法(工程侧) | 伪代码+不变式 | 伪代码的严格化就是 Hoare 三元组;「跑得对」的数学化 |

## 五、反直觉发现

1. **恒等函数是定理**:`fun a => a` 既是程序也是 `A → A` 的证明——
   「写代码」与「做证明」在类型论里是**同一个动作**,这是 Curry–Howard 最锋利的一刀。
2. **停机问题半可判定**:「会停」能被验证(跑给它看),「不停」**原则上无法验证**
   (等多久都不够)——所以「证明 bug 不存在」比「证明 bug 存在」本质上更难,
   软件验证的目标天然是硬的那半。
3. **表达力即不可判定性**:每个图灵完备语言都自动继承停机不可判定性——
   你的模板引擎图灵完备的那一刻,「这段模板会不会死循环」就数学上无解了
   (C++ 模板、HTML+CSS 的争论皆此定理的注脚)。

## ✨ 美之时刻

**✨ Curry–Howard 对应表**。抄在卡片上:

| 逻辑 | 程序 |
|---|---|
| 命题 | 类型 |
| 证明 | 程序(值) |
| A→B | 函数 A→B |
| A∧B | 二元组 (a,b) |
| A∨B | 带标签的和 `inl a \| inr b` |
| ∀x:P(x) | 依值函数 Π |
| ∃x:P(x) | 依值对 Σ(携带见证) |
| 证明规范化 | 求值 |

两门学科各修各的路,修到山顶发现是同一条——为什么美:**必然性**(并非类比,
是严格同构)。亲历:在 [`../讲透Lean4数学/`](../讲透Lean4数学/) 任一 sorry 填空里
认出你在函数式编程里天天写的东西。

## 🧠 认知升维

- **类型眼**:看类型签名即看命题强度——签名就是规格说明,
  「让类型非法状态不可表示」是 Curry–Howard 的工程口诀
- **分层眼**:拿到任何 DSL/配置/查询语言,先测它在 Chomsky 哪一级、
  是否图灵完备——这决定你能对它做什么保证
- **元语言眼**:谈论系统的语言必比系统强;想验证一切,先问「验证器的验证器」在哪层打住
