# 计算机数学思维技能卡

> 全卡总纲见 [README.md](README.md);本卡是可复用的**思维模式摘要**,
> 供人肉快速调用,也供 agent 在处理相关问题时代入本分支的视角。

## ① 何时用此分支(触发特征,一眼对号)

- 「写个程序/脚本**判断**某个程序/配置/模板的性质」→ 先问可判定性(多半不可)
- 「这个算法**快不快/能再快吗**」「为什么优化总留 fallback」→ 复杂度分析+加速定理
- 「怎么**证明**这段代码是对的」「测试多少才够」→ Hoare 逻辑/不变式;测试≠证明
- 「AI 生成的代码/证明能信吗」→ 可验证 vs 可信任两路线;验证需求上升
- 「DSL/模板引擎/查询语言设计」→ 先定 Chomsky 层级;图灵完备=继承不可判定
- 「编译器/优化 pass/算子融合的合法性」「形式化规格(形式验证)」→ 语义保持证明
- 「自举/quines/反射/元编程」→ Kleene 不动点定理
- 「P vs NP/归约/NP 完全」→ 走 [../讲透计算复杂度/](../讲透计算复杂度/) 分类学

## ② 核心思维模式

- **归约证难**:难题不硬刚,翻译给已知难题(A ≤ B:B 难 ⟹ A 难)
- **不变式证对**:不追亿万状态,焊一条轨道(循环不变式/类型不变量)
- **类型即命题**(Curry–Howard):证明=程序、命题=类型、规范化=求值;
  「让非法状态不可表示」是它的工程口诀
- **对角化证不可能**:「你列你的,我反着做」——从康托到停机的万能模板
- **信任预算**:任何验证栈必有一个不可再缩的人肉内核(TCB),
  诚实工程=显式声明这个内核在哪

## ③ 工具箱(方法+何时用)

| 工具 | 何时用 |
|---|---|
| 停机问题/Rice 定理 | 「能否自动判定程序语义」类需求的一票否决器 |
| 归约(多一/图灵) | 证明不可判定或 NP 难;难度传递 |
| Hoare 三元组 {P}S{Q} + 循环不变式 | 证明命令式程序部分正确性 |
| 时序逻辑(LTL/CTL)+ 模型检查 | 并发/协议「永远不做坏事」(安全性/活性) |
| SAT/SMT(DPLL/CDCL/Z3) | 可判定片段的自动验证与反例搜索;`unsat`=通过 |
| Curry–Howard/依值类型 | 数学定理形式化;证明助手工作流(Lean/Coq) |
| 主定理/摊还分析/势能法 | 算法成本计量;数据结构均摊代价 |
| Kleene 递归定理 | 一切自指合法性的来源(自举/quines) |

## ④ 常见误区与禁忌

- **能算 ≠ 算得起**:可计算性是存在性,复杂度是价格;先问「多快」,再谈「有没有」
- **测试 ≠ 验证**:测试找反例(存在性),永远不构成正确性证明(穷举=停机)
- **图灵完备是负债**:DSL 追求表达力时,别忘了同时进口了停机不可判定
- **「形式验证了」要追问**:验证到什么模型?内核信任面多大?规格谁写的?
  (规格错误=验证明了错的东西)
- **别拿最坏情况预测性能**:SAT 是指数最坏却横扫工业实例——理论保证与实践可用是两张图
