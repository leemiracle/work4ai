# 讲透程序验证数学 · 怎么保证对:正确性的证明学

> 定位句:这支负责的问题是「**程序凭什么是对的**」——把「正确」从测试的
> 统计安慰升级为逻辑证明,并让机器检查这个证明。
> GB/T 13745-2009:110·11085 计算机数学(GB/T 未列三级,**自定主干支**)。
> 家族:[讲透计算机数学](../README.md)

## 诞生

📖 1968 年 NATO「软件危机」会议把「程序错误」从玄学升级为危机;
1969 年 Hoare《计算机程序的公理基础》给出答案:每条语句一条公理,
正确性=可推导命题;同一时期 Floyd 的断言法+Dijkstra 的最弱前置条件;
1980s 起 Curry–Howard 成熟,证明检查器=类型检查器——验证工业化起步。

## 核心问题

已解决:
- **Hoare 逻辑**(相对)完备——{P}S{Q} 推理体系的可靠性
- **不变式法**:循环正确性=归纳法的程序版
- **Curry–Howard**:证明即程序,检查证明=类型检查(可判定!)
- 工业级战果:seL4 微内核、CompCert 编译器完整验证

未解决:
- **规格的自动生成**——验证自动化后,瓶颈移到了「写规格」这一端
- 状态爆炸的普适解(模型检测 PSPACE 完全,靠符号方法续命)
- AI 生成代码的可信封装:生成不可证,验证如何跟上

## ✨ 这支最美的一个事实

Curry–Howard 对应:「A 蕴涵 A」的证明就是恒等函数 `fun a => a`——
逻辑与程序设计两门学科各自修路,山顶会师发现是同一条路。
证明的规范化(切消)=程序的求值:证明会「跑」。

## 假设与代价

- 验证相对规格:证对了规格≠规格写对了(规格错误=验明白了错的东西)
- 信任内核(TCB)不可再缩:内核自身正确靠人工审计(哥德尔第二不完备性的工程投影)
- 成本假设:验证投入 < 事故代价(内核>脚本,但 90% 软件不值得)
