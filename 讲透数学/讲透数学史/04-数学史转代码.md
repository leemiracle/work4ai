# 04 · 数学史转代码——数字人文的最小走廊

> **本章回答五问之 Q5(问题→代码转换)**。
> **本质一句话**:数学史的问题一旦变成「关于史料数据的计算」,就能进代码——编年变时间轴、书信念网络、版本变进化树;**唯一不可外包给代码的,是史学判断本身(选样、归因、反事实)**。

---

## 0. 开篇:101 条记录检验一个百年直觉

「文艺复兴之后数学加速发展」——这是每个教科书都默认的叙事。它对吗?

`experiments/00_timeline.py` 用 101 条大事记录(从前 1800 到 2024,领域×人物×事件)做了最朴素的检验:按世纪切片、数事件、对比 1550 年前后的平均密度。跑一遍,你会看到**事件密度在后 500 年比前 3300 年高出一个数量级**——直觉被数据确认。

但脚本同时打印了**选样声明**:这 101 条是「入选正史的著名事件」,密度曲线度量的是**史料与正史的关注度**,不只是「数学产出」。脚本的最后一行 assert 的是前者,不是后者——**这正是数字人文的第一课:代码替你算数,替不了你解释数**。

## 1. 可机械化边界(三件套之一)

**能进代码的**(史料数据化后的一切统计与可视化):

| 任务 | 机械化形式 |
|------|-----------|
| 编年密度/分期检验 | 事件点列 → 世纪直方图、变点检测 |
| 传播链重建 | 事件/译本/留学记录 → 有向图、最短路、中心性 |
| 合作网络分析 | 发表记录 → 图,度分布、社团检测、时间切片 |
| 版本谱系 | 抄本异文表 → 距离矩阵 → 层次聚类(进化学方法移植) |
| 文本断代 | 用词/记号特征 → 分类器(辅助断代,输出是「证据」不是「判决」) |

**不能进代码的**(这是史学的「不可判定域」):

1. **选样正当性**——哪些事件「值得」入库是史学判断;代码只能做敏感性分析(换选样规则,结论稳不稳?稳=结构刚性,见 03 章 §3)。
2. **归因与动机**——相关(两人同年在同一城市)永远推不出因果(谁影响了谁);代码给相关,人给归因。
3. **反事实评估**——「若《方法》未失传」不可模拟;凡是「模拟历史进程」的程序,模拟的都是**作者的史观**,不是历史。
4. **价值排序**——「重要不重要」没有客观函数;重要性加权=把史学判断伪装成超参数。

> 边界的一句话:**代码是史料的显微镜,不是史学家**。显微镜的放大倍数越高,越要记得镜头是谁选的。

## 2. 代码走廊清单(三件套之二)

本家族的四条走廊(由浅入深):

| 走廊 | 输入 | 输出 | 对应实验/章 |
|------|------|------|------------|
| C1 编年走廊 | 事件列表 (年份, 领域, 人物, 事件) | 世纪×领域切片表、密度断言 | `experiments/00_timeline.py`(✅ 已实现) |
| C2 谱系走廊 | 师承边表 (导师→学生, 年份) | DAG、祖先收束率、1933 年裂缝检测 | 04 章 §4 示例代码(下文) |
| C3 文本走廊 | 标点化史籍/信件集 | 词频时间线、人名共现网络 | 拓展方向(见 §5) |
| C4 对勘走廊 | 同一故事的多源记载 | 证据等级表(一手/二手/传说三色) | 02 章方法的数据化 |

**C1 数据字典**(`00_timeline.py` 的 TIMELINE 即此模式的实例;扩展方向就写在约束列):

| 字段 | 类型 | 约束/坑 |
|------|------|--------|
| year | int | 负数=公元前;**没有 0 年**——跨元前后的差值计算要 −1(02 章 §5.5) |
| domain | 枚举 | 枚举表本身=史学选样判断;增删领域必须记入变更说明 |
| person | str | 「传说」人物显式后缀;机构/群体作者(如「有限单群分类」)合法 |
| text | str | **不带形容词**——数据与叙事分离(§3 工程落点) |
| source_tier | T1..T6 | 证据等级(02 章 §2.5);无此字段的编年库一律视为 T4 |

**C3 文本走廊入门**(五行的词频时间线,史籍断代的日器):

```python
from collections import Counter
text_by_decade = {"1870s": "……", "1880s": "……", "1890s": "……"}   # 分段文本
for decade, text in sorted(text_by_decade.items()):
    words = Counter(w for w in text.split() if len(w) > 3)
    print(decade, words.most_common(5))     # 高频词的时代漂移=概念兴衰曲线
```

跑在标点化的信件集/期刊卷上,它回答的问题包括:某术语何时挤掉竞争对手(矩阵 vs 阵)、某人物名何时淡出——**词频曲线是概念史的体温计**;但解读权永远在史学家手里(02 章边界)。

**C2 最小示例**(纯标准库,谱系走廊的 10 行核心——对应 03 章 §0 的谱系收束):

```python
from collections import defaultdict

ADVISORS = {  # 学生: 导师(年份为博士年,示意)
    "Hilbert": ["Lindemann"], "Minkowski": ["Hilbert"],
    "Weyl": ["Hilbert"], "Courant": ["Hilbert"], "Noether": ["Gordan"],
    "Artin": ["Hilbert" and "Weyl"][0:1] or ["Weyl"],  # 实际师承示意
}

def lineage(student, depth=8):
    """沿导师指针回溯——谱系=链,森林=并查集;环=检测器报错(历史无环!)"""
    seen, chain = set(), [student]
    for _ in range(depth):
        advisors = ADVISORS.get(chain[-1])
        if not advisors or advisors[0] in seen:
            break
        seen.add(advisors[0]); chain.append(advisors[0])
    return chain

print(" → ".join(lineage("Minkowski")))   # 两步到 Lindemann:收束速度可测
```

历史无环假设(老师不可能教过自己的学生)让谱系数据**天然可验证**——这是它比一般人文数据更适合代码处理的原因(结构刚性,03 章 §3)。

## 3. 工程落点(三件套之三,性能工程视角)

数字人文的工程问题与一般数据工程同构,本家族给三个落点:

1. **数据管道落点**:史籍数字化→结构化(JSON/关系表)→分析脚本。关键工程纪律:**数据与叙事分离**(数据文件不带形容词)——与 讲透宇宙「篇目表=宪法」同构:数据层一旦污染观点层,可复算性即死。
2. **性能落点**:大规模书目/引文网络(数百万节点)的分析是正经的图计算负载——邻接表、社区检测的并行化;[../讲透图/](../讲透图) 网络科学部的方法直接可用。19 世纪期刊网络的「十年切片」计算就是典型可缓存、可增量的问题。
3. **AI 工程落点**(与 01 章 §1.2 对接):LLM 辅助古文献转写/翻译的流水线,**评估器是史学纪律的化身**——逐字对照、置信分级、幻觉零容忍(编造一个不存在的抄本比漏读十行更糟)。这就是为什么数学史是 AI 方法的安全试验场:定理可验证,断言可对勘。

## 4. 一个完整的心智案例:验证「知识加速」叙事

把四条走廊串起来回答一个真问题:

1. **C1**:编年密度——确认事件频率在 1450 后加速(打印曲线,断言密度比)。
2. **C2**:师承网络——确认 19-20 世纪「导师制+期刊制」把知识传递从师徒链变成校园网(收束率骤变)。
3. **C3**:文本走廊——印刷术之后新记号(如 +、=、√)的首用扩散周期从数百年缩到数十年。
4. **解释层(人)**:三组数字支持「制度(印刷+大学+期刊)是加速器」的外史解释——但**选样偏差警告**:正史密度≠全体产出;真正的检验要用藏书目录、通信总量等**不依赖「重要性」的选样**。

——这个案例就是本家族对「讲透范式(直觉→数学→代码→不足→应用)」的完整走法。

## 4.5 敏感性分析:数字人文的「测试框架」

代码有单元测试,史学计算对应物是**敏感性分析**——同样的三步,可复用为任何史学问的检查器:

- **换选样**:把「正史大事」换成「期刊创刊+教科书出版」两种选样,各跑一遍密度曲线——三条曲线同向=结论稳健(结构刚性);分叉=结论只属于某个选样,**必须写进结论的限制条款**。
- **留一检验**:随机抽掉 10% 事件重跑——密度比波动 <20% 说明结论不依赖个别「大事件」。
- **零点检验**:把 CENTURY_SPLIT 从 1550 移到 1450/1650 各跑一遍——结论对切口不敏感才可断言「加速」而非「某世纪爆发」。

这三招之于史学计算,正如 property-based test 之于软件:**不是证明结论对,而是让结论的可错性显形**。`00_timeline.py` 的读者练习:给它加一个 `--split YEAR` 参数,扫 1400-1700 的密度比曲线,找出最陡的十年——你会看见「长期趋势」和「单点事件」在数据里的分界。

## 4.6 走廊×断言阶梯对照(哪条走廊能支撑哪级断言)

| 走廊 | 最高可支撑 | 常被误用于 |
|------|-----------|-----------|
| C1 编年 | T2(事件在文献中) | 被当 T3「产出结论」——密度是关注度 |
| C2 谱系 | T2(师承关系) | 被当 T4「影响因果」——边不是影响 |
| C3 文本 | T2(词出现) | 被当 T4「概念含义变迁」——需要人读语境 |
| C4 对勘 | T3(多源一致性) | 被当 T1「真相」——一致也可能同源抄错 |

(阶梯定义见 02 章 §2.5;这张表是它的计算版——**每条走廊的产品都贴着自己的证据上限**。)
