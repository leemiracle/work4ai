# 04 · 模糊数学转代码:口语规则的编译之旅

> **本章回答五问之五:模糊数学的问题怎么变成 code 问题?**
> 三件套:可机械化边界 / 代码走廊清单 / 工程师落点。
> 本家族的特殊体质:**它天生就是为"可算"而生的**——推理即求值,规则即程序。

---

## 一、开篇:一条 IF-THEN 的编译之旅

"IF 温度偏高 AND 温升偏快 THEN 风扇功率大。"
这句没有公式的话,怎么让风扇听懂?编译成五步:

```
口语规则 ──①模糊化──▶ 隶属度 ──②推理(min-蕴含)──▶ 规则输出模糊集
        ──③聚合(max)──▶ 总输出模糊集 ──④解模糊(重心)──▶ 一个数 ──▶ DAC─▶ 电机
```

**直觉图像先行**:整个流程像一场**选举**——每个规则是一位候选人,票仓是输入隶属度;
min-蕴含=候选人立场由最弱议题决定;max-聚合=多党联合取各议题最高纲领;
重心解模糊=按"得票分布"的质心定国策。**一次推理 = 一次加权投票**,全程没有一处
需要"求解"——只有求值。这就是模糊系统 1980s 就能跑在 8 位单片机上的原因。

## 二、第一件:可机械化边界(什么能全自动化/什么不能)

| 环节 | 可机械化? | 说明 |
|------|----------|------|
| 隶属函数求值 μ(x) | ✅ 完全 | 查表/算式,一次乘加级 |
| 规则求值(min/max/t-norm) | ✅ 完全 | 逐规则 O(1),共 R 条 |
| 聚合与解模糊(重心) | ✅ 完全 | 数值积分,离散网格 O(N·R) |
| 整个 Mamdani 推理 | ✅ 完全 | **模糊推理天然可机械化——这就是它工程上活下来的原因** |
| **隶属函数的选取** | ⚠️ 半 | 专家画的自动化不了;但"从数据学 μ"(ANFIS/FCM)可机械化 |
| **规则库的生成** | ⚠️ 半 | 专家规则靠访谈;规则归纳(clustering 提取)可机械化但需人审 |
| type-2 降型 | ⚠️ 有代价 | 精确降型是优化问题(迭代 Karnik-Mendel);近似可实时代价 |
| **语义对齐**("安全"是什么意思) | ❌ 不能 | 这是建模问题不是计算问题——模糊数学只接管"定好 μ 之后"的一切 |

**边界一句话**:**μ 和规则库"从哪来"是人机协作区;"怎么算"是全自动区**。
这与 [../讲透应用数学/](../讲透应用数学/)的"翻译生产环"完全同构——
模糊系统把"翻译"集中到了建模端,算术端彻底自动化。

**反直觉发现 ⑥**:模糊控制器的输出曲面**一定是逐段连续的**(在常用隶属函数下),
而且**规则库极简(7~几十条)却常优于精细调校的线性控制器**——
仙台地铁案例里,模糊控制停车误差方差小于传统 PID,规则只有 24 条。
为什么?因为 min-max 推理天然做**分段平滑插值**,鲁棒性来自"粗而不脆"。
亲历:`experiments/00_mamdani.py` 的连续性断言就是这句话的数值形态。

## 三、第二件:代码走廊清单(从对象到系统的五条走廊)

1. **走廊 A · 隶属函数库**(对象层):三角/梯形/高斯/广义钟形;语言变量封装
   (词集→曲线组)。输入标量,输出隶属度向量。
2. **走廊 B · 推理机**(语言层):Zadeh(min-max)或乘积/Ł t-norm 谱系切换;
   Mamdani(输出模糊集)与 TSK(输出函数 af+b)两型。
3. **走廊 C · 解模糊器**:重心法(centroid)/最大平均(MOM)/加权平均(TSK 闭式)。
4. **走廊 D · 学习器**(数据反哺):ANFIS(梯度下降学 μ 参数)、FCM 软聚类、
   规则归纳(Wang-Mendel 两步法:聚类定前件+LS 定后件)。
5. **走廊 E · 高阶对象**:模糊数算术(扩展原理离散化)、模糊关系 max-min 合成、
   type-2(区间型)与近似降型。

**典型堆栈**:`scikit-fuzzy`(Python 五条走廊全覆盖)/ MATLAB Fuzzy Logic Toolbox
(工业设计台)/ 嵌入式 C 查表实现(家电量产形态:离线算好控制曲面,ROM 里放一张表——
**运行时连推理都不做,只查表**。这是模糊控制的量产秘密:把"可机械化"推到极致=
离线机械化)。

## 四、第三件:工程师落点(性能工程视角)

- **控制系统**:暖通空调、洗衣机负载判断、地铁自动驾驶(仙台 1987)、相机防抖、
  电动汽车能量管理——**共同画像**:被控对象非线性 + 专家经验可口语化 + 传感器噪声容忍。
- **决策融合**:多传感器/多专家意见的 soft fusion(隶属度当权重,max-min 合成当融合律);
  AHP-模糊混合(层次分析法的模糊化)在工程决策里是标配论文格式。
- **ML 混合系统**:ANFIS(可解释小模型)、模糊聚类(FCM 分割)、
  深度网络里的模糊层/模糊损失——**用结构先验换参数量与可解释性**(对照
  [../讲透统计学习理论/](../讲透统计学习理论/)的泛化-可解释权衡)。
- **性能工程要点**(本仓库用户的主场):
  - 在线推理成本 O(R) 随规则数线性涨——量产方案是**离线预计算控制曲面+查表**,O(1);
  - 重心解模糊是数值积分——嵌入式常用增量式/查表近似,精度换时延;
  - type-2 的降型是迭代算法(KM 算法),实时场景用区间近似或直接退化为 type-1;
  - 规则库的**稀疏激活**:每步真正激活(非零)的规则通常 ≪ R——实现时按输入分区索引规则。

## 五·五、五步编译的成本表(每步多少算力)

| 步骤 | 计算量 | 嵌入式实现 |
|------|--------|-----------|
| ①模糊化 | 每输入查 2 条活跃曲线 × 乘加 | 直接算式(μ 是分段线性) |
| ②min-蕴含 | R_active × O(1) | 稀疏激活:按输入分区索引规则(R_active ≪ R) |
| ③max-聚合 | O(N_grid) | 与②融合(逐点取 max) |
| ④重心解模糊 | O(N_grid) 乘加 | 查表/增量近似 |
| 全离线(量产) | 0(运行时) | **ROM 控制曲面查表,O(1) 确定时延** |

**读数**:在线推理成本随规则数**线性**、随输出网格**线性**——两项都可用结构消掉:
规则靠稀疏激活,网格靠离线预计算。模糊控制的量产形态把"可机械化"推到极限:
**智能全部住在编译期,运行期只剩一次内存访问。**

## 五·六、scikit-fifty 行走廊示例(伪代码骨架)

```python
# pip install scikit-fuzzy —— 五条走廊全覆盖
import numpy as np, skfuzzy as fuzz
from skfuzzy import control as ctrl

e  = ctrl.Antecedent(np.linspace(-3, 3, 61), 'error')     # 走廊A:输入语言变量
u  = ctrl.Consequent(np.linspace(0, 100, 401), 'power')   # 走廊A:输出
e.automf(5, names=['NB','NS','ZE','PS','PB'])             # 五词自动铺曲线
u.automf(5, names=['L','ML','M','MH','H'])

rules = [ctrl.Rule(e['NB'], u['L']), ctrl.Rule(e['NS'], u['ML']),   # 走廊B:规则库
         ctrl.Rule(e['ZE'], u['M']),  ctrl.Rule(e['PS'], u['MH']),
         ctrl.Rule(e['PB'], u['H'])]
sys = ctrl.ControlSystemSimulation(ctrl.ControlSystem(rules))       # 走廊B+C:推理+重心
sys.input['error'] = 1.5; sys.compute(); print(sys.output['power'])
```

与本家族 `experiments/00_mamdani.py`(纯标准库手写版)逐行对照:
库版把五步编译封装进 `compute()`,手写版让你看见 min/max/重心的每一行——
**先读手写版再读库版**,是这门数学最舒服的转代码路径。

## ✨ 美之时刻(本章)

**离线预计算控制曲面 = 模糊推理的"完全体"**:一条 IF-THEN 口语,最终被编译成
ROM 里一张二维表——**知识的表达(口语)、知识的证明(逼近定理)、知识的执行(查表)
三态合一**。工程师看到的是 O(1) 的确定性时延,数学家看到的是通用逼近定理的有限采样,
语言学家看到的是一句人话的物化。三方在同一张表上会师。
亲历:`experiments/00_mamdani.py` 末尾的曲面扫描就是这张表的生成器。
