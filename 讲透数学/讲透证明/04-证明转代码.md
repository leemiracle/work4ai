# 04 · 证明转代码：从 kernel 到 CDCL 到 LLM——产业的解剖图

> **本章回答五问之五：怎么将该领域的问题转换为 code 问题？**
> 证明论的工程化不是一条走廊，是**四条生产线**：证明助手（kernel 路线）、
> SAT/CDCL（搜索路线）、程序提取（Curry–Howard 路线）、AI 证明器（神经+符号路线）。
> 每条线最后都撞同一堵墙——本章把墙的位置画准。

---

## 一、四条生产线总表

| # | 生产线 | 数学侧 → 代码侧 | 代表产品 | 成熟度 |
|---|--------|----------------|---------|--------|
| 1 | **证明助手** | 证明=树（00 章实验）→ kernel 检查的项 | Lean/Coq/Agda/Isabelle | 工业级 |
| 2 | **SAT/CDCL** | 命题反驳=消解证明 → 搜索+学习 | Kissat/CaDiCaL + DRAT 证书 | 工业级 |
| 3 | **程序提取** | 构造性证明=程序（03 章）→ 提取器 | Coq→OCaml（CompCert） | 工程级 |
| 4 | **AI 证明器** | 证明搜索=策略序列 → LLM 生成+kernel 裁决 | AlphaProof/DeepSeek-Prover/Seed-Prover | 竞赛级（01 章） |

## 二、生产线 1：证明助手解剖（以 Lean 为例）

```
你写的 tactic 脚本
   ↓  elaborator（unification/隐参/类型类解析——复杂的"编译前端"）
证明项（proof term，03 章的 λ-项）
   ↓  kernel（~1万行的极小检查器）
✓/✗ ——只有它有最终裁决权
```

**De Bruijn 判据**：信任基必须极小且独立可审查。Lean 的 kernel 可以被
独立实现重写（第三方 checker 复核整个 Mathlib）——**"生成的证明不必信，检查的代码必须信"**。
LCF 架构（Milner 1979）：一切对象经由抽象类型墙 birth，只进不改——
00 章实验的 `check()` 就是微缩 kernel。
tactic = 证明搜索的脚本化：`intro`=→I、`exact`=规则应用、`simp`/`omega`=专门决策程序——
**决策程序内嵌进证明系统**是现代助手的标配（一阶线性算术的 `omega` 完全可判定）。

## 三、生产线 2：SAT/CDCL——消解证明的工业化

命题不可满足性的**证明系统就是消解**（resolution，Robinson 1965——切消的命题投影）：
从 CNF 出发，`C∨x` 与 `D∨¬x` 得 `C∨D`，推出空子句 ⟺ UNSAT。
CDCL 求解器 = **消解证明的启发式搜索器** + 子句学习（学到的子句=搜索历史的证明摘要），
DRAT 证书让第三方**独立验证**求解器的答案——SAT 界的 De Bruijn 判据。

> **反直觉发现 #1**：鸽笼公式 PHP(n+1,n) 是 UNSAT 的"显然"命题，
> 但 Haken 1985 证明：**任何**消解证明都指数长——"显然"与"短证明"是两回事。
> 证明系统有内在强度等级（消解 < Frege < 扩展 Frege），
> 这是**命题世界的证明论**——与 03 章的序数标价构成对偶：
> 那边量理论的强度，这边量证明系统的强度。
> （实验 `04_resolution_cdl.py`：亲手跑通 PHP(3,2) 的消解反驳 + 迷你 DPLL。）

## 四、生产线 3：程序提取——Curry–Howard 的兑现

构造性证明的计算内容=程序：Coq 从证明里提取 OCaml；
**CompCert**（Leroy）从验证的 C 编译器证明中提取可运行编译器——
"编译器无 bug"从口号变成定理+工件。代价与边界：提取的程序**慢**
（证明结构未优化）、经典证明（用 RAA/选择公理）无计算内容可直接提取——
只有直觉主义侧的对应是完美的（02/03 章）。

## 五、生产线 4：AI 证明器——kernel 裁决的神经搜索

01 章的军备竞赛在证明论上的读法：

```
LLM 提议（tactic 序列/整证明）──→ kernel 检查 ──通过──→ RL 奖励
                                        │                       
                                        └─拒绝──→ 负反馈（重新提议）
```

**"生成≠判别"**（[`../讲透神经符号/`](../../讲透神经符号/) 第一公理）：
LLM 可以幻觉证明，kernel 不会幻觉检查——闭环的安全性完全押在 De Bruijn 判据上。
这解释了为什么 AI 证明器全部选择 Lean/Isabelle 落地：**不是为了时尚，是为了裁决权分离**。

## 六、边界：不可机械化的精确墙（与讲透集合 04 章对读）

1. **一阶证明搜索不可判定**（Church–Turing）：半可判定——能找到就能验证，
   找不到就永远别等（02 章半可判定现象的姊妹版）
2. **证明长度下界**（Haken/PHP）：即使存在证明，最短证明可能指数长——
   "可证"≠"可搜索"
3. **切消爆炸**（Orevkov）：证明变换本身可以非初等代价——规范化理论温柔、实践暴政（02 章）
4. **不完备性**（Gödel）：一致理论的自动证明器永远漏掉某个真命题——
   与讲透集合 04 章的哥德尔层是同一堵墙的两个剖面
5. **实践墙**：Mathlib 百万行依赖图的证明搜索状态空间远超现有 LLM 上下文——
   竞赛级 ≠ 数学研究级（01 章 Seed-Prover 的 PutnamBench 88% 之后仍是大荒原）

## 七、Python 层

```bash
python3 -u experiments/04_resolution_cdl.py
```

1. **消解反驳检查器**：逐条验证手写 PHP(2,1) 反驳链，空子句落地
2. **迷你 DPLL**：单元传播+分裂，求解可满足实例（给出模型）与 PHP(3,2)（报 UNSAT），
   统计决策数/冲突数——证明搜索成本的显微观测

## 八、Lean 层

- `#print axioms your_theorem`——查看证明的公理依赖（信任基审计的日常入口）
- `Nat.decEq`/`omega`——内嵌决策程序的活标本
- Mathlib 的 `Mathlib.Tactic.*` 是 tactic=证明搜索 的生态现场
