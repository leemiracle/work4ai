# 04 · 计算数学转代码:从定理到可跑、可信的数

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 统一结构=三件套:**可机械化边界**(什么能自动/什么必须人来)→**代码走廊清单**(每类数学对象走哪条库链路)→**工程师落点**(性能工程视角:GPU 确定性、混合精度误差预算、复现性)。

---

## 开篇:一个转换的解剖

拿到数学问题 "解 −u''=f, u(0)=u(1)=0",计算数学的转译不是"直接写代码",而是四步流水线,每步都在本家族的各支里有专门工位:

```
连续问题(PDE) ──离散化〔数值分析支〕──▶ 线代系统 Ax=b
              ──求解器选择〔数值线代成员〕──▶ 原始解 x̂
              ──误差审计〔误差分析支〕──▶ x̂ + 可信度
              ──规模化〔并行算法支〕──▶ 一万张卡上的 x̂
```

这条流水线就是"转代码"的本质:**数学对象不直接变成代码,先变成带结构的问题(稀疏/对称/病态程度已知),再对号入座走走廊。** 下面把走廊画全。

## 一、可机械化边界:什么能自动,什么必须人来

| 能机械化(定理在手) | 边界处(半自动) | 必须人来(无定理代办) |
|--------------------|----------------|---------------------|
| 微分:自动微分(AD)链式法则机械化,精确到机器精度 | 网格自适应:误差指示子给建议,策略人来定 | **建模**:哪个方程描述世界(去 [`../讲透数学建模/`](../讲透数学建模/)) |
| 数值积分:自适应求积(区间折半到达标) | 正则化参数 λ:L 曲线/偏差原理给候选,取舍人来 | **算法选型**:定理给类别的界,不给"你的实例"的答案 |
| 线代:BLAS/LAPACK 全自动(给定问题) | 收敛判停:相对残差阈值是习惯而非定理 | **误差预算分配**:哪里可以粗哪里必须细(见 §三 GPU) |
| 多项式系统:Gröbner 基可全自动终止(Buchberger) | 符号-数值混合:何时放弃符号转数值 | **可信度主张**:结果敢不敢写进论文/产品 |

**边界的深层原因**(呼应 02 章):方言只会说 ∀ 的界,不会说"你的这个实例"——所以凡是要**对具体实例作判断**的环节(选型、停机、预算、背书),定理止步,人接手。可机械化边界≈可判定边界投影到工程上。

## 二、代码走廊清单:数学对象 → 库链路

| 数学对象/操作 | 首选走廊(Python 生态) | 备选/上游 | 本家族对应支/成员 |
|--------------|----------------------|----------|------------------|
| 实数运算(注意非结合) | `float`(IEEE 754 双精度) | `numpy.float32/64`、`mpmath`(任意精度) | 误差分析支 |
| 向量/矩阵 | `numpy`(BLAS 插座) | `scipy.linalg`(LAPACK) | 数值线代成员 |
| 大型稀疏系统 | `scipy.sparse.linalg`(CG/GMRES/AMG) | PETSc(生产级) | 数值线代成员+并行支 |
| 微分 | JAX/torch `autograd`(AD) | 有限差分(仅作对照) | — |
| 积分(低维) | `scipy.integrate.quad`(自适应 Gauss-Kronrod) | tanh-sinh(端点奇异) | 数值分析成员 |
| 积分(高维) | 蒙特卡洛(`numpy.random`)/QMC(`scipy.stats.qmc`) | Vegas/MCuba | **随机数值支** |
| 微分方程 | `scipy.integrate.solve_ivp`(自适应步长) | FEniCS/deal.II(有限元,生产级) | 数值分析成员 |
| 傅里叶 | `scipy.fft`(FFTW 级) | pyFFTW | 调和分析归属 |
| 病态/正则化 | `scipy.linalg.lstsq`+Tikhonov(手写,见实验) | 正则化工具包(reginv/pylops) | **反问题支** |
| 区间/带证计算 | `mpmath.iv`、`pyinterval` | CAPD(C++ 验证式 ODE) | **误差分析与区间算法支** |
| 符号代数 | `sympy` | Singular(Gröbner 基权威)/Mathematica | **符号计算支** |
| 多卡 | `jax.pmap`/`torch.distributed`/NCCL 归约 | MPI(经典 HPC) | **并行算法支** |

**走廊使用心法**(三条,全家族通用):
1. **先看结构再进门**:对称?稀疏?病态?结构决定走廊,规模决定参数。
2. **每条走廊自带方言**:进 `quad` 要会说容差(tol),进 CG 要会说残差,进 MCMC 要会说混合时间——02 章的条件句文化在 API 上的投影。
3. **默认值是别人的假设**:库的默认容差/精度/方法=别人的误差预算,与你无关时才是方便,有关时是地雷。

## 三、工程师落点(性能工程视角)

本家族对性能工程师不是"另一门课",而是**同一门手艺的数学面**:优化吞吐=控制误差预算的分配。

### 3.1 GPU 内核里的数值稳定性

| 现象 | 数学原因 | 工程动作 |
|------|---------|---------|
| 归约结果逐位不定 | 浮点加法无结合律(02 章)+原子加归约顺序随调度变化 | 确定性归约(树形/固定分块)换 5-30% 吞吐;或接受统计复现 |
| 大数组求和精度差 | 顺序累加误差 ~n·ε;灾难时有效位耗尽 | Kahan 补偿求和/成对归约(pairwise)——误差 log n·ε |
| 混合精度算不准 | fp16 舍入+溢出窗窄 | 累加必须升精度(TensorCore 的 fp32 累加器就是这么来的) |
| 长训跑崩(loss=NaN) | 误差在万步复合下越界+上溢 | loss scaling(动态放大→缩小);梯度裁剪 |

**心法**:内核优化的每一步(重排、分块、向量化)都是一次**结合律的改判**——性能工程师每天都在做 02 章的 (a+b)+c vs a+(b+c) 选择,只是没人这么叫它。

### 3.2 混合精度训练=一份显式误差预算表

现代大模型训练的标准配置读作一份计算数学文档:

```
计算(fp16/bf16,粗):矩阵乘——量大,可粗
累加(fp32,细):求和与主权重更新——误差复合点,必须细
存储(fp32 主权重):长期记忆,防漂移
归约(高精度+确定性策略):多卡同步,复现性 vs 吞吐的谈判点
```

这就是 Tikhonov 式思维在硅上的日常:**预算有限,分配给谁**。反过来,阅读任何训练框架的精度文档,你就是在读一份误差预算书。

### 3.3 可复现性:三种口径,先声明再追求

| 口径 | 含义 | 成本 |
|------|------|------|
| 逐位复现(bitwise) | 两次运行输出完全一致 | 确定性归约,吞吐税 5-30% |
| 统计复现 | 分布/指标一致(误差<ε 概率保证) | 默认态 |
| 验证式复现 | 结果带区间证书 | 区间算术,计算量×数倍 |

**✨ 美之时刻:复现性悖论**——同一份代码、同一组卡、同一种子,两次运行逐位不同;但误差落在统计口径的带内。**为什么美**:它把 02 章的抽象定律(无结合律)变成一条可重复观察的实验事实——数学定理在硅上"活"了。**怎么亲历**:写一个 `torch.cuda` 的 atomicAdd 归约小程序连跑两次比较 hash;再开 deterministic 开关比较吞吐差。

## 四、把本家族的公理写进工程清单(收束版)

给任何数值系统做 review,本家族给出五问(可与 00-03 章对照):
1. 输入的**条件数**量级?(问题定价)
2. 算法的**向后误差**?(算法品格)
3. 收敛判停依据残差还是步长?(**相对**于什么?)
4. 精度分配表在哪(哪些 fp16 哪些 fp32)?
5. 复现口径是逐位/统计/验证式中的哪一种,写在文档里了吗?

五问全答,数值系统的"误差宪法"就位——这是计算数学对工程的最大贡献:**让"差不多"变成"差多少,凭什么"**。
