## 📚 课程定位

CS202 是斯坦福**为计算机科学专业学生量身定制的法律入门课**。它不是法学院课程，而是一门面向工程师的**"法律生存指南"**：

> **核心命题**：技术人才不仅需要写出好代码，还需要理解**围绕代码的法律框架**——你的代码归谁所有？你能用它做什么？别人能复制它吗？你签的合同意味着什么？

这门课的开设反映了一个现实：**CS 毕业生最常见的职业陷阱不是技术问题，而是法律盲区**——开源协议的误解、专利的忽视、竞业协议的轻率签署。

**David Hansen** 是国际顶级律所 **Skadden, Arps, Slate, Meagher & Flom** 的合伙人，专攻知识产权和技术法。Skadden 是全球最具影响力的律所之一，"Skadden" 这个名字在华尔街和法律界如雷贯耳。由执业律师而非纯学者授课，意味着课程内容**高度贴近商业现实**。

## 🎯 学习目标

完成 CS202 后，学生应能够：

1. **区分** 四种知识产权类型（专利 / 版权 / 商标 / 商业秘密）的适用范围与保护机制
2. **理解** 软件版权——代码作为"表达"的法律地位，开源协议的法律含义
3. **识别** 专利保护——算法/发明的可专利性，软件专利的争议
4. **评估** 合同条款——许可证（License）、NDA（保密协议）、竞业禁止协议
5. **分析** 商业实体——公司类型（LLC、C-Corp、S-Corp）与所有权结构
6. **了解** 争议解决——诉讼 vs 仲裁 vs 调解的基本路径
7. **关注** 时事热点——AI 生成内容的版权、开源运动、平台责任

## 📅 完整模块（基于课程大纲 + 法律体系重构）

### Part 1: 知识产权基础（IP Fundamentals）⭐ 核心
- **M1** — 知识产权全景：四种类型对比
  - **专利 (Patent)**: 保护发明，20 年，需公开 + 审查
  - **版权 (Copyright)**: 保护表达，终身+70 年，自动获得
  - **商标 (Trademark)**: 保护品牌识别，10 年可续
  - **商业秘密 (Trade Secret)**: 保护机密，无限期，需保密措施
- **M2** — **专利深入** ⭐
  - 可专利性要求：新颖性、非显而易见性、实用性
  - 软件专利的特殊争议（Alice Corp v. CLS Bank）
  - 发明披露书 (Invention Disclosure) 的撰写
  - 专利流氓 (Patent Troll) 问题
- **M3** — **版权深入** ⭐
  - 思想-表达二分法（idea-expression dichotomy）
  - 合理使用 (Fair Use) 四因素测试
  - 软件版权：代码作为文字作品
  - DMCA（数字千年版权法）与避风港条款

### Part 2: 开源与自由软件
- **M4** — **开源协议生态** ⭐
  - Copyleft vs Permissive：GPL vs MIT/BSD/Apache
  - 传染性条款：GPL 的衍生作品要求
  - 开源 != 免费商业使用
- **M5** — 自由软件运动
  - Richard Stallman 与 FSF 的哲学
  - GNU 项目与 Linux 的版权结构
  - Creative Commons 的多层次许可

### Part 3: 合同与协议
- **M6** — 软件许可证
  - EULA（终端用户许可协议）
  - SaaS 条款
  - API 使用条款
- **M7** — 保密与竞业
  - NDA（保密协议）的范围与例外
  - 竞业禁止协议（各州法律差异，加州基本不可执行）
  - 知识产权转让协议（IP Assignment）
- **M8** — 雇佣中的 IP 归属
  - "职务作品"(Work for Hire) 原则
  - 雇员发明归属（加州 Labor Code 2870）

### Part 4: 商业实体与争议
- **M9** — 商业实体类型
  - 独资 (Sole Proprietorship) / 合伙 (Partnership)
  - LLC（有限责任公司）
  - C-Corp / S-Corp（创业公司标准选择）
  - 股权结构基础
- **M10** — 争议解决
  - 诉讼（联邦法院 vs 州法院）
  - 仲裁（Arbitration）—— 快速但不可上诉
  - 调解（Mediation）—— 非约束性
- **M11** — 当代热点
  - P2P 文件共享与版权（Napster → Grokster 案）
  - 平台责任（Section 230）

### Part 5: AI 时代的法律前沿（当代扩展）
- **M12** — **AI 生成内容的版权** ⭐（2026 法律现状）
  - 完全 AI 生成：一般不受版权保护（US Copyright Office 立场）
  - AI 辅助 + 人类创作性贡献：受保护
  - 训练数据版权：仍在诉讼中（NYT vs OpenAI）
- **M13** — AI 与专利
  - AI 作为发明人？（DABUS 案——美国法院拒绝）
  - AI 辅助发明的专利归属
- **M14** — AI 监管与合规
  - 企业使用 AI 的法律风险
  - 数据隐私法（GDPR / CCPA）对 AI 的影响

## 🧮 核心法律框架

### 1. 四种知识产权对比

| 类型 | 保护对象 | 保护期限 | 获得方式 | 示例 |
|------|---------|---------|---------|------|
| **专利 Patent** | 发明（方法/装置）| 20 年（从申请日）| 申请 + 审查 | 新算法、药物、硬件 |
| **版权 Copyright** | 原创表达 | 终身+70 年 | **自动获得** | 代码、文章、音乐 |
| **商标 Trademark** | 品牌识别 | 10 年（可无限续）| 使用 + 注册 | Logo、品牌名、标语 |
| **商业秘密 Trade Secret** | 机密信息 | **无限期**（保密即保护）| 保密措施 | Coca-Cola 配方、算法 |

### 2. 思想-表达二分法（版权核心原则）

> **版权保护表达，不保护思想。**

```
想法（不受保护）→ 实现（受保护）
  "一个用注意力机制的翻译模型"  →  Transformer 的具体代码
  "一个社交网络"               →  Facebook 的代码与设计
```

**含义**：你可以合法地"借鉴想法"，但不能复制代码。

### 3. 合理使用（Fair Use）四因素

| 因素 | 考量 |
|------|------|
| **使用目的与性质** | 商业 vs 教育/研究；转化性使用有利 |
| **版权作品性质** | 创意性强（小说）vs 事实性（新闻）|
| **使用部分的数量与重要性** | 用了多少？是否是核心部分？|
| **对原作品市场的影响** | 是否替代原作品的市场？|

### 4. 开源协议谱系

```
强 Copyleft          弱 Copyleft          宽容型(Permissive)
    |                    |                      |
  GPL v3             LGPL              MIT / BSD / Apache 2.0
    |                    |                      |
衍生作品必须         库链接可例外          几乎无限制
同样开源              商业使用友好
```

### 5. AI 生成内容的版权（2026 现状）

```
完全 AI 生成（无人类创作性投入）  → 一般不受版权保护
       ↓
AI 辅助 + 人类创作性贡献          → 受保护（人类部分）
       ↓
AI 训练数据使用受版权作品         → 诉讼中（合理使用争议）
```

## 📊 关键案例与资源

### 🔴 里程碑案例
1. **Alice Corp v. CLS Bank (2014)**——软件专利的"抽象概念"测试，大幅限制了软件专利
2. **Google v. Oracle (2021)**——API 是否受版权保护？最高法院判定 Google 的使用属合理使用
3. **Authors Guild v. Google (2015)**——Google Books 扫描属合理使用
4. **MGM v. Grokster (2005)**——P2P 文件分享诱导侵权责任
5. **Thaler v. Vidal (DABUS 案, 2022)**——AI 不能作为发明人

### 🟡 法规与指南
6. **DMCA（数字千年版权法, 1998）**——避风港条款 + 反规避条款
7. **Section 230 of CDA**——平台对用户内容免责（AI 时代受挑战）
8. **GDPR（欧盟通用数据保护条例）**——数据隐私标杆
9. **CCPA（加州消费者隐私法）**——美国最强隐私法

### 🟢 实务资源
10. **USPTO（美国专利商标局）**——专利申请入口
11. **Creative Commons**——开源协议选择器
12. **Electronic Frontier Foundation (EFF)**——数字权利倡导

## 💡 反思

### 课程优势
1. **实务讲师**——Skadden 合伙人授课，内容直接来自一线法律实践
2. **轻量高效**——1 学分覆盖 CS 专业最核心的法律知识
3. **时效性强**——每年加入当下热点（AI 版权、平台责任）
4. **风险预防**——教的是"如何避免踩坑"，而非事后救济
5. **低门槛**——无需法学背景，专为 CS 学生设计

### 潜在局限
1. **深度有限**——1 学分意味着只能覆盖基础，复杂案件需深挖
2. **美国法中心**——主要讲美国法律体系，国际视角不足
3. **内容可能过时**——官网显示 Fall 2006 版本，AI 时代法律已大变
4. **非互动式**——研讨课形式可能缺乏案例练习
5. **无法替代律师**——了解框架 ≠ 能自己处理法律事务

### 给学生的建议
> **最重要的三条法律常识**：
> 1. **签任何合同前，读完全文**——尤其是 IP 归属和竞业条款
> 2. **你的代码可能不属于你**——雇佣关系下默认归雇主
> 3. **开源 ≠ 可以随便用**——GPL 传染性可能影响你的整个项目
