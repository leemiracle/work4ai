## Overview of Parameter Lifecycle and States

`ShardedState`

| State | Description | Code Reference |
|---|---|---|
| SHARDED | Parameter is sharded (typically over dimension 0) and registered to the module. It solely accounts for parameter memory. | torch/distributed/fsdp/_fully_shard/_fsdp_param.py:149-149 |
| UNSHARDED | The parameter is unsharded (restored for forward/backward) and registered to the module. Both sharded and unsharded versions exist and use memory. | torch/distributed/fsdp/_fully_shard/_fsdp_param.py:151-151 |
| SHARDED_POST_FORWARD | After forward, some unsharded parameters may be temporarily resharded to a smaller world size for memory savings. These are not registered to the module. | torch/distributed/fsdp/_fully_shard/_fsdp_param.py:150-150 |

### Important Details on Tensor Aliasing and Autograd

- Storage Resizing : FSDP dynamically resizes the storage underlying parameters to free and reallocate unsharded parameters while preserving autograd correctness. Since autograd nodes can hold references to views, resizing preserves aliasing and avoids breaking autograd graphs. torch/distributed/fsdp/_fully_shard/_fsdp_param.py:93-101
- Parameter Types : FSDP distinguishes between the "Original parameter" (passed at init), "Sharded parameter" (the DTensor shard), "All-gather inputs/outputs", and the "Unsharded parameter" used for computation. torch/distributed/fsdp/_fully_shard/_fsdp_param.py:67-79
- In-place Construction : The unsharded parameter object is constructed once and updated in-place thereafter to maintain functional consistency for autograd. torch/distributed/fsdp/_fully_shard/_fsdp_param.py:97-100

## Interaction with Activation Checkpointing

`TrainingState`

- Stream Management : FSDP uses get_all_gather_streams to determine if separate streams are needed for implicit prefetching. torch/distributed/fsdp/_fully_shard/_fsdp_param_group.py:117-127
- State Tracking : The system tracks TrainingState.FORWARD vs TrainingState.PRE_BACKWARD . If not an async op and in forward/pre-backward, FSDP utilizes the separate all_gather_copy_in_stream and all_gather_stream to maximize overlap. torch/distributed/fsdp/_fully_shard/_fsdp_param_group.py:120-125
- Reference Management : To avoid holding onto memory after forward (critical when AC is storing many activation tensors), the last FSDP state flushes references to all-gather outputs. torch/distributed/fsdp/_fully_shard/_fsdp_param_group.py:62-70
