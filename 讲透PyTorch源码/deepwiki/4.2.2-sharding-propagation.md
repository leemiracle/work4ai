### OpStrategy and OpSpec

strategy enumeration and selection

- OpStrategy ( torch/distributed/tensor/_op_schema.py 15-17 _op_schema.py 166-226 ) represents all valid sharding strategies for a single operator invocation on a given device mesh.
- OpSpec ( torch/distributed/tensor/_op_schema.py 14 _op_schema.py 122-163 ) describes one valid sharding configuration pairing input and output DTensorSpec s with an associated cost for redistributions required to realize it.
- DTensorSpec ( torch/distributed/tensor/_dtensor_spec.py 22-25 ) details the full sharding placement for one tensor, including placements per dimension, underlying device mesh, and meta information such as shape, stride, and dtype.
- TupleStrategy ( torch/distributed/tensor/_op_schema.py 19-20 _op_schema.py 214-226 ) aggregates multiple OpStrategy instances for multi-output operators (e.g., batch norm or foreach ops).

## Sharding Propagation Workflow

### High-Level Execution Flow

`ShardingPropagator`

```

```

- The dispatch creates an OpSchema ( torch/distributed/tensor/_op_schema.py 13 ) instance describing the operator and input/output tensor meta (sharding specs).
- The propagator checks registries for propagation rules first.
- If no direct propagation rule matches, it falls back on full operator strategies enumerating valid sharding configurations or single-dimension strategy expansions.
- The minimum cost redistributive strategy is selected via generate_redistribute_costs ( torch/distributed/tensor/_ops/utils.py 24 ).
- Necessary communication and redistribution nodes are inserted via redistribute_local_tensor ( torch/distributed/tensor/_redistribute.py 28-29 ) before local computation proceeds.

## Registration Mechanisms

### 1. Propagation Rules ( register_prop_rule )

- For operations where output distribution directly follows inputs without complex alternatives.
- These rules implement fast direct mapping from input DTensorSpec to output DTensorSpec .
- Example: aten.clone , aten.detach just propagate the input spec as output with same sharding.
- Registered using @register_prop_rule(op) decorator ( torch/distributed/tensor/_ops/utils.py 29 ).

### 2. Op Strategies ( register_op_strategy )

- For operations supporting multiple valid sharding configurations.
- Returns a full OpStrategy listing candidate OpSpec s with redistribution costs.
- The system chooses the lowest-cost plan for communication.
- Supports runtime specialization according to static arguments (e.g., memory_format , dtype ).
- Registered via @register_op_strategy(op) decorator ( torch/distributed/tensor/_ops/utils.py 29 ).

### 3. Single-Dim Strategies ( register_single_dim_strategy )

- Designed for ops with dimensionwise behavior (e.g., pointwise ops, reductions).
- Defines a template “single-dim strategy” with placeholders for sharding along a dimension.
- The placeholder is replaced by concrete Shard or _StridedShard based on input sharding.
- Expanded to all mesh dimensions via Cartesian product or shortest path (Dijkstra-based) search ( torch/distributed/tensor/_redistribute.py 78-127 ).
- Registered by @register_single_dim_strategy(op) decorator ( torch/distributed/tensor/_ops/single_dim_strategy.py 20 ).
- Uses the _ShardingPlaceholder class ( torch/distributed/tensor/_ops/single_dim_strategy.py 22 ) to represent a generic shard along a dimension prior to expansion.

## Mathematical Logic in Propagation

### Pointwise and Broadcasting

- Pointwise ops use _common_pointwise_single_dim_strategy ( torch/distributed/tensor/_ops/_pointwise_ops.py 23 ) which considers broadcasting semantics.
- If an output dimension maps to an input dimension, that input dimension is sharded correspondingly.
- If output dimension is broadcasted from input, input is replicated along that dimension ( torch/distributed/tensor/_ops/_pointwise_ops.py 55-65 ).
- Also handles appending Partial placement rules for partial reductions in pointwise contexts (e.g., _BINARY_ADDITIVE_RULES in _pointwise_ops.py 166-171 ).

torch/distributed/tensor/_ops/_pointwise_ops.py 23-171

### Reductions

- Reduction operations (sum, mean, max, min, etc.) convert sharding along reduction dims into partial aggregations ( Partial placements).
- Linear reductions support partial placements with commutative accumulation.
- Non-linear norms (e.g., p-norm) use specialized _NormPartial partial placements ( torch/distributed/tensor/_ops/_math_ops.py 63 ), handling mathematical transformations: Pre-reduction transform raises tensor to power p ( torch/distributed/tensor/_ops/_math_ops.py 108-109 ). Post-reduction transform applies p-th root ( torch/distributed/tensor/_ops/_math_ops.py 111-112 ).
- After reduction, map_placements_after_reduction ( torch/distributed/tensor/_ops/_math_ops.py 203 ) remaps placements to output shape dimensions since reduced dims disappear or shrink.

torch/distributed/tensor/_ops/_math_ops.py 63-209

# Summary

- Well-defined data abstractions: DTensorSpec , OpSpec , OpStrategy .
- Multiple, composable registration patterns for various complexity levels.
- Ability to enumerate, cost, and select optimal distributed strategies per op.
- Single-dim templating facilitating systematic expansion to mesh.
- Validation frameworks ensuring correctness against concrete full tensor semantics.
