## The torch.library Operator System

`torch.library`
`torch.library.custom_op`

### Operator Registration and Dispatch

`torch.ops.<namespace>.<op_name>`

- Definition : The @torch.library.custom_op decorator torch/_library/custom_ops.py 67-76 creates a CustomOpDef object. It requires a name (e.g., "mynamespace::myop" ) and a mutates_args specification torch/_library/custom_ops.py 94-96
- Schema Inference : PyTorch can automatically infer the operator schema from Python type hints torch/_library/infer_schema.py 24-31 Supported types include Tensor , int , float , bool , str , torch.dtype , torch.device , and lists/optionals thereof torch/_library/custom_ops.py 115-129
- Implementation : The base implementation (typically the CPU/CUDA eager implementation) is provided by the decorated function. Device-specific implementations can be registered using the device_types argument torch/_library/custom_ops.py 97-102
- Side Effects : Operators that perform non-functional operations (like stream synchronization) must be explicitly marked using torch.fx.has_side_effect to prevent them from being dead-code eliminated during graph optimization torch/_dynamo/variables/streams.py 110-126

### Fake Tensor Support (register_fake)

`FakeTensor`

- Registration : Abstract implementations are registered via torch.library.register_fake torch/library.py 35 or the impl_abstract method torch/library.py 33
- Automatic Registration : For simple operators, custom_op can sometimes infer the fake implementation if the logic is purely based on shape propagation torch/_library/custom_ops.py 132-135
- Validation : The torch.library.opcheck utility torch/library.py 194 validates that the custom operator's implementation matches its schema, checking for incorrect mutations or aliasing test/test_custom_ops.py 214-235

### Specialized Schema Tags

- torch.Tag.inplace : Requires the first positional argument to be a mutable Tensor ( Tensor(a!) ) and returns exactly that Tensor torch/library.py 138-169
- torch.Tag.out : For operators where mutable arguments are keyword-only output buffers. All returns must alias these mutable args in declaration order torch/library.py 67-115

## Inductor Autotuning and Stream Management

### User Stream Support

- Stream Utilities : get_stream_name and get_raw_stream_name map stream indices to generated variable names (e.g., stream1 , raw_stream1 ) torch/_inductor/stream_utils.py 32-33
- Codegen Integration : The WrapperCodegen emits EnterCudaStreamContextLine and ExitCudaStreamContextLine to wrap kernel launches in the appropriate stream contexts test/inductor/test_user_streams.py 19-25
- Device Overrides : CUDADeviceOpOverrides and XPUDeviceOpOverrides provide the backend-specific logic for creating streams and events in the generated wrapper code test/inductor/test_user_streams.py 18-26

- Fake Implementation Validation : During torch.compile , the system verifies that the FakeTensor implementation produces the same metadata as the real implementation test/test_custom_ops.py 214-235
