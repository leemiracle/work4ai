## Memory Management: CUDACachingAllocator

### Design Overview

- Stream-association: Allocations are linked to CUDA streams; freed memory is reusable on the same stream without additional sync c10/cuda/CUDACachingAllocator.cpp 106-107
- Block Search and Splitting: Upon allocation, the allocator finds the smallest fitting cached block. Larger cached blocks can be split to fulfill smaller requests c10/cuda/CUDACachingAllocator.cpp 108-110
- Separate Pools: Large (>1MB) and small allocations are managed in separate pools; small allocations are packed into 2MB buffers c10/cuda/CUDACachingAllocator.cpp 115-117
- Fragmentation Control: Blocks above a configured max_split_size are not allowed to be split to reduce fragmentation c10/cuda/CUDACachingAllocator.cpp 120-122
- Freeing Strategy: On allocation failure, the allocator attempts to free cached blocks to reclaim memory before failing the allocation c10/cuda/CUDACachingAllocator.cpp 111-114
- Synchronization Strategy: Programmer must synchronize explicitly when sharing memory across streams; the allocator assists with recordStream() to track stream uses and insert sync c10/cuda/CUDACachingAllocator.cpp 129-132

## BLAS and Matrix Multiplication Operations

### Features

- Supports common GEMM operations: mm , addmm , bmm , as well as grouped and scaled matrix multiplications.
- Advanced precision formats including FP8 variants on NVIDIA H100 (SM89/SM90 and newer) test/test_cuda.py 46-52
- Dispatch is dynamically selected among multiple backends including cuBLAS and cuBLASLt.
- A tunable GEMM infrastructure enables autotuning kernel launches to optimize performance per device and operation.
