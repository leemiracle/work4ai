## Architecture Overview and Data Flow

- State Dict: A mapping from Fully Qualified Names (FQNs) to tensor objects, typically representing model parameters or optimizer states. These tensors may be plain torch.Tensor , DTensor , or other custom variants.
- Planner Interface: Coordinators called SavePlanner and LoadPlanner determine metadata exchange and distribution of shards across ranks for saving/loading torch/distributed/checkpoint/planner.py
- Storage Backends: StorageReader and StorageWriter interfaces abstract physical storage, such as filesystems or remote object stores torch/distributed/checkpoint/storage.py

### Core Components

| Component | Description |
|---|---|
| State Dict | The dictionary mapping parameter names to tensors; often contains sharded tensors like DTensor objects. |
| SavePlanner | Coordinates checkpoint saving metadata and orchestrates shard distribution for writing. |
| LoadPlanner | Coordinates checkpoint loading metadata and orchestrates redistribution and resharding on load. |
| StorageWriter | Abstraction for writing checkpoint data to backend storage (e.g., filesystem, remote storage). |
| StorageReader | Abstraction for reading checkpoint data from storage during load. |

## Resharding and Redistribution on Load

- The LoadPlanner computes how to redistribute shards according to the current mesh.
- DTensor's advanced redistribution transforms abstract the network communication and local copy mechanics needed to match new sharding specifications.
- DeviceMesh encapsulates global process groups and mesh topologies, enabling reshaping and permutation of distributed shards torch/distributed/fsdp/_fully_shard/_fsdp_param.py 26-27
