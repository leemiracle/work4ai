## Purpose and Scope

- Triton : Inductor's primary GPU backend, generating Triton kernels for CUDA, ROCm, and XPU targets.
- C++ : CPU backend generating vectorized C++ code with optional OpenMP parallelization.
- Pallas : A JAX-targeted backend primarily for TPU devices or research JAX integration.
- CUTLASS : Integration for high-performance GEMM kernels on NVIDIA GPUs leveraging CUTLASS templates.

## Triton Code Generation

### TritonKernel and SIMDKernel

- TritonKernel ( torch/_inductor/codegen/triton.py 128 ) extends SIMDKernel ( torch/_inductor/codegen/simd.py 128 ), which manages generic SIMD iteration and compute patterns.
- It translates Inductor IR using Python source with triton.language operations such as tl.load , tl.store , and tl.constexpr .
- The kernel generation respects hardware constraints, e.g., maximum block sizes ( TRITON_MAX_BLOCK ) and warp configurations ( torch/_inductor/codegen/triton.py 58-64 ).

### Combo Kernels

Combo Kernels
torch/_inductor/codegen/triton_combo_kernel.py 1-20

- Nodes are partitioned horizontally by heuristics considering tile sizes and memory patterns.
- The TritonComboKernel manages the sub-kernels and their shared resources ( torch/_inductor/codegen/triton_combo_kernel.py 1-20 ).

### Runtime Heuristics and Autotuning

- Autotuning logic evaluates kernel configurations to optimize runtime performance.
- The autotuner checks for cached configurations using lookup_autotune_config ( torch/_inductor/runtime/triton_heuristics.py 178-192 ).
- It uses generate_lookup_hash_from_source_code to key the cache by kernel source and size hints ( torch/_inductor/runtime/triton_heuristics.py 169-175 ).

## C++ and CPU Code Generation

### CppKernel and Vectorization

- Uses vectorization architectures supported by at::vec::Vectorized abstractions.
- Checks CPU ISA feature sets (AVX2, AVX512) via cpu_vec_isa ( torch/_inductor/config.py 29-34 ).
- The kernel code supports OpenMP parallelism for CPU execution.
- Vectorized overrides are defined in CppVecOverrides ( test/inductor/test_cpu_repro.py 23-31 ).

### C++ Wrappers (AOTInductor)

- Enabled by config.cpp_wrapper ( torch/_inductor/config.py 196-197 ), the backend generates full C++ source code wrappers.
- CppWrapperCpu ( torch/_inductor/codegen/cpp_wrapper_cpu.py 1-60 ) handles launching kernels and managing inputs/outputs for AOT (Ahead-of-Time) compilation.
- It uses DeferredCpuTritonCallWrapper to manage Triton kernels executed on CPU ( torch/_inductor/codegen/cpp_wrapper_cpu.py 88-103 ).

## Pallas Code Generation

### PallasKernel Implementation

- Utilizes a custom PallasPrinter that overrides standard PyTorch ops to equivalent JAX jnp operations.
- The backend is implemented in torch/_inductor/codegen/pallas.py .
- It integrates with the Inductor scheduler to lower IR nodes into Pallas-compatible kernels.

Sources:

## CUTLASS and GEMM Templates

- Uses templated C++ code generators for GEMM, enabling autotuning and configuration specialization.
- CUTLASSTemplate ( torch/_inductor/ir.py 148-155 ) provides the base for these high-performance implementations.
- Autotuning chooses block sizes and kernel configs leveraging CUTLASS's performance.

## Wrapper Code and Kernel Launching

### PythonWrapperCodegen

- Generates Python source code to launch kernels compiled by various backends.
- Found in torch/_inductor/codegen/wrapper.py .
- Manages buffer reuse via buffer_reuse_key ( torch/_inductor/codegen/wrapper.py 154-169 ) and comm_buffer_reuse_key ( torch/_inductor/codegen/wrapper.py 172-184 ).
- Handles symbolic shape solutions for integer codegen using _rewrite_symbol_solution_for_int_codegen ( torch/_inductor/codegen/wrapper.py 114-119 ).

### C++ Wrappers and AOTI

- For AOTInductor, CppWrapperCpu manages the generation of C++ launch code ( torch/_inductor/codegen/cpp_wrapper_cpu.py 172-183 ).
- It generates template-based signatures for kernel functions to handle different input types efficiently ( torch/_inductor/codegen/cpp_wrapper_cpu.py 158-166 ).
