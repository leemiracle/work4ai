## Overview

Core Features:

- Direct Peer-to-Peer (P2P) Memory Access: GPUs can directly read/write other GPUs’ allocated buffers within the same process group inside CUDA or Triton kernels torch/csrc/distributed/c10d/symm_mem/SymmetricMemory.hpp 9-14
- Multicast Support: Hardware multicast capabilities (e.g., NVLink SHARP) provide efficient one-to-many communication when supported torch/csrc/distributed/c10d/symm_mem/SymmetricMemory.hpp 56-57
- Device-Side Synchronization: Synchronization primitives including barriers and signal pads are provided for intra- and inter-GPU coordination torch/csrc/distributed/c10d/symm_mem/SymmetricMemory.hpp 76-78
- Custom Collective Primitives: The system enables new communication-computation fusion collectives like nccl_all_gather_offset and nccl_all_to_all_nd torch/csrc/distributed/c10d/symm_mem/nccl_extension.hpp 46-62
- Persistent Allocations: Backend allocators provide persistent symmetric allocations that minimize runtime overhead in iterative workloads torch/csrc/distributed/c10d/symm_mem/SymmetricMemory.cpp 133-152

Multiple Backend Implementations:

- NVSHMEM Backend: Leverages PGAS-style remote memory access and device-side communication APIs for high performance torch/csrc/distributed/c10d/symm_mem/NVSHMEMSymmetricMemory.cpp 10-25
- NCCL Backend: Uses NCCL’s ncclMemAlloc and ncclDevComm APIs (NCCL >= 2.27) to create symmetric memory windows with hardware-accelerated collective primitives torch/csrc/distributed/c10d/symm_mem/NCCLSymmetricMemory.cu 32-74
- CUDA Backend: Uses CUDA Virtual Address management with IPC handles and peer memory access to implement symmetric memory regions torch/csrc/distributed/c10d/symm_mem/CUDASymmetricMemory.cu 36-73

## Core Concepts

### Allocation and Rendezvous Protocol

- Allocation Phase : Each rank allocates an identically sized symmetric memory buffer using symm_mem.empty() . This maps to backend-specific low-level virtual memory or MMIO allocations, such as ncclMemAlloc for the NCCL backend torch/csrc/distributed/c10d/symm_mem/NCCLSymmetricMemory.cu 68-72
- Rendezvous Phase : To enable peer access, ranks perform a collective rendezvous ( symm_mem.rendezvous(tensor) ) to exchange necessary handles (e.g., CUDA IPC handles, NCCL communicator info) via a key-value Store torch/csrc/distributed/c10d/symm_mem/SymmetricMemory.hpp 142-146
