## Purpose and Scope

- Test organization in the test/ directory.
- The orchestration logic driven by run_test.py .
- Patterns in common_utils.py and common_device_type.py for test parametrization.
- Hardware classification and device-type specialization.
- The OpInfo testing framework which drives systematic operator coverage for correctness validation across devices and dtypes.

## Test Orchestration: run_test.py

`run_test.py`

- Discovery : Scans the test/ directory for Python modules and C++ binaries.
- Sharding : Calculates test shards based on historical timing data to balance CI load.
- Parallelism : Launches multiple processes. On ROCm, it dynamically assigns HIP_VISIBLE_DEVICES to ensure pool workers do not oversubscribe a single GPU.
- Blocklisting : Filters out tests known to be unstable on specific platforms (e.g., WINDOWS_BLOCKLIST ).
