## 1. Serialization Schema and Versioning

`ExportedProgram`

### 1.1. Schema Definitions

- ScalarType, Layout, MemoryFormat : Enums for tensor properties.
- SymInt, SymFloat, SymBool : Unions that handle both concrete values and symbolic expressions for dynamic shapes.
- TensorMeta : Metadata describing tensor properties like dtype , sizes , strides , and device .
- Node : The basic unit of the FX graph, containing the target operator, inputs (as NamedArgument ), and outputs.

### 1.2. Versioning and Compatibility

- Automatic code generation ensures that C++ headers and Python classes stay in sync with the schema definition.
- The system validates that version numbers are not downgraded and maintains bindings for JSON serialization.
- In torch.export , strictness levels (strict vs non-strict) impact how the graph is traced and subsequently serialized, often requiring specific suffixes for identification during testing test/export/test_export.py 220-230

## 2. The Serializer and Deserializer

`ExportedProgram`

### 2.1. Implementation Flow

- Graph Normalization : Constants are lifted, and state dicts are prepared. This includes cleaning up artifacts like _export_root references in nn_module_stack metadata which are artifacts of the export process torch/_dynamo/functional_export.py 92-118
- Schema Mapping : Python objects are mapped to the defined schema dataclasses.
- Artifact Cleaning : The clean_export_root function removes internal Dynamo artifacts from the FX graph in-place to ensure the serialized graph represents the user's original model structure torch/_dynamo/functional_export.py 184-187

### 3.1. Tensor and Storage Serialization

`torch.save`

- _rebuild_tensor : A core utility used during deserialization to reconstruct tensors from saved metadata and storage torch/test_serialization.py 30
- Storage Alignment : Tensors are aligned (default 64 bytes) within the archive to allow for efficient memory mapping ( mmap ) during inference torch/serialization.py 215-227
- Weights-Only Loading : By default, PyTorch 2.6+ uses weights_only=True in torch.load to prevent arbitrary code execution during deserialization torch/serialization.py 76-81
