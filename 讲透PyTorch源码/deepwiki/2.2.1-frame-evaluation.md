## Frame Evaluation Hook Mechanism

### Hook Installation and Dispatch

- The hook registration is done via set_eval_frame in torch._dynamo.eval_frame torch/_dynamo/eval_frame.py 63 This is a C-extension interface implemented in C++ ( eval_frame_cpp ) that registers a callback with the Python interpreter.
- The _maybe_set_eval_frame wrapper provides a safety check via justknobs_check to allow disabling the compiler via feature flags torch/_dynamo/eval_frame.py 176-185
- When Python executes a code object, it calls the registered frame evaluation callback instead of the default _PyEval_EvalFrameDefault .
- TorchDynamo's callback decides whether to: Skip tracing the frame and run it eagerly. Invoke bytecode analysis to construct an FX graph or use a cached compiled graph.

## Bytecode Analysis Pipeline

### Bytecode Extraction and Cleaning

- Several analyses and transformations are applied: Dead Code Removal ( remove_dead_code ): Eliminate unreachable or ineffective instructions torch/_dynamo/convert_frame.py 90 Exception Table Propagation ( propagate_inst_exn_table_entries ): Maintain exception handling metadata consistent with modified bytecode torch/_dynamo/convert_frame.py 95 Jump Optimization ( remove_pointless_jumps ): Cleans up control flow torch/_dynamo/convert_frame.py 90
- Transformations are orchestrated by transform_code_object() , which applies these passes in sequence to produce a cleaned and optimized code object variant ready for symbolic conversion torch/_dynamo/convert_frame.py 91-97

- Simulates Python VM stack as a stack of VariableTracker objects, rather than concrete Python objects.
- Tracks local variables ( symbolic_locals ), cell variables, and the ExceptionStack during symbolic execution torch/_dynamo/convert_frame.py 149-151
