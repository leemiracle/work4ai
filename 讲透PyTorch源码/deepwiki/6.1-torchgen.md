### Key Schema Fields

- func: The operator signature, including argument names, types, and alias annotations (e.g., Tensor(a!) self ).
- variants: Specifies if the op is a function , method , or both torchgen/model.py 25-35
- dispatch: A dictionary mapping DispatchKey (e.g., CPU , CUDA , CompositeExplicitAutograd ) to the specific C++ function name implementing the kernel.
- tags: Metadata used by the compiler and autograd (e.g., pointwise , view ). Tags are defined in aten/src/ATen/native/tags.yaml aten/src/ATen/native/tags.yaml 1-10
- autogen: Instructions for torchgen to automatically generate variants like .out versions torchgen/native_function_generation.py 1-25

## Functionalization and Decompositions

`torchgen`

### Functionalization and Schema Analysis

- Functionalization Codegen: torchgen generates the Functionalization dispatch key implementations, which wrap tensors in FunctionalTensor to track aliases and mutations torchgen/gen_functionalization_type.py 20-60
- View Inversion: For view-based operators, torchgen infrastructure helps generate the logic to propagate updates back to the base tensor.

### Decompositions

- register_decomposition: This decorator in torch/_decomp/decompositions.py maps complex ATen ops (like aten.tanh_backward ) to simpler operations torch/_decomp/decompositions.py 125-130
- Meta Kernels: Meta kernels for shape and dtype propagation are registered via register_meta to allow the compiler to perform symbolic shape analysis without executing full kernels torch/_meta_registrations.py 66-76 These are critical for FakeTensor and torch.compile torch/_meta_registrations.py 116-128
