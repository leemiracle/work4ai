### Structure and Key Fields

```

```

- func : Declares the operator name, input and output types, mutability indicated (e.g. Tensor(a!) for in-place), and default arguments. This entire signature is parsed by the torchgen code generator to create C++ bindings, dispatch tables, and Python bindings.
- variants : Specifies whether the operator is available as a free function, tensor method, or both, influencing the user API surface.
- dispatch : Maps individual dispatch keys (e.g., CPU , CUDA , MPS ) to backend-specific kernel function names. Each key corresponds to a backend or functional layer, providing extensible multi-backend support.
- manual_cpp_binding : Indicates if the function has manually written C++ bindings, instructing the generator to skip automatic binding generation.
- tags : Metadata tags provide supplemental information to influence compilation and transformation passes, e.g., marking inplace variants or decomposition hints.

### Additional Fields

- device_check : Some operators specify custom device checks to validate input tensor placement before dispatch.
- autogen : Signals automatic generation of output variants or derivative operations like .out functions.

### How Dispatch Keys Are Selected

- The Dispatcher examines input tensor types (device, layout) and functional layers active (e.g., Autograd).
- It determines the best dispatch key representing the current backend or wrapper.
- Kernels registered for that dispatch key are invoked.
- If no kernel matches, fallback keys like CompositeExplicitAutograd are used.

## Summary

- Operators are defined in native_functions.yaml with schema and backend dispatch info.
- The c10 dispatcher uses dispatch keys to route to backend kernels (CPU, CUDA, MPS, Meta, etc.) torch/csrc/utils/python_dispatch.cpp 139-168
- Backends register kernels in C++ or Python (meta/decomposition).
- Meta kernels registered via register_meta enable metadata propagation for tracing torch/_meta_registrations.py 66-76
- Decompositions registered via register_decomposition enable graph lowering torch/_decomp/decompositions.py 21-22
- The OpInfo testing framework drives end-to-end validation through sample inputs and device-specific test instantiation.
