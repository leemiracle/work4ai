## PipelineStage Abstraction

`PipelineStage`

### Key Classes and Infrastructure

- _PipelineStageBase : An abstract base class defining the interface for pipeline stages. it manages Point-to-Point (P2P) communication handles, device state, and caches for forward/backward activations and gradients torch/distributed/pipelining/stage.py 96-141
- PipelineStage : The standard implementation that wraps an nn.Module . It handles the orchestration of dist.send and dist.recv for activations and gradients torch/distributed/pipelining/stage.py 53-58
- _RecvInfo : A descriptor for stage inputs. It tracks whether an input is a "root" argument (provided by the user) or received from a previous stage, and maintains the necessary buffers and TensorMeta for validation torch/distributed/pipelining/stage.py 96-130

- Downstream Group : Carries traffic for forward activations ($r \rightarrow r+1$) torch/distributed/pipelining/stage.py 156-170

|---|---|---|
| GPipe | ScheduleGPipe | Executes all forward microbatches, then all backward microbatches torch/distributed/pipelining/schedules.py 44 |

## Composability with FSDP and DTensor

### FSDP Integration

`PipelineStage`
`FSDPModule`

- Pipeline parallelism handles inter-stage communication (activations/gradients).
- FSDP handles intra-stage parameter sharding and synchronization (all-gather/reduce-scatter).
- The PipelineStage uses specialized backward functions like stage_backward_input and stage_backward_weight to coordinate with FSDP's unshard/reshard lifecycle torch/distributed/pipelining/_backward.py 177-184
