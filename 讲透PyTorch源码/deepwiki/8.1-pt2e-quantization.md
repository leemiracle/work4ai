## Overview of the PT2E Workflow

- Prepare : The exported graph is transformed to include observers or fake-quantize nodes via prepare_pt2e .
- Calibrate/Train : The model is run with sample data (PTQ) or trained (QAT) to compute quantization parameters (scale and zero-point).
- Convert : The observed graph is transformed via convert_pt2e into a quantized graph where floating-point operations are replaced with quantized equivalents (typically using quantized_decomposed ops).

### Dequant Promotion and Fusion

`aten.mm`
`aten.conv2d`

- Dequant-Conv-Quant : Fused into a single quantized convolution kernel.
- Weight Prepacking : Weights are pre-transformed into a layout optimized for the backend.
- Pointwise Fusion : Quantized versions of operations are fused to avoid unnecessary dequant/requant cycles.

### Mixed Precision and Specialized Formats

- FP8 : Supports float8_e4m3fn and float8_e5m2 types, with specialized scaling logic for H100+ and MI300+ devices test/inductor/test_fp8.py 99-102
- Scaled MM : Inductor lowers torch.nn.functional.scaled_mm to efficient Triton or cuBLAS kernels, handling scales for inputs and outputs test/inductor/test_fp8.py 18
- Int8 Matmul : Fused integer matrix multiplications can be matched to Triton templates, identified by strings like triton_tem_fused__int in generated code test/inductor/test_pattern_matcher.py 159-164
