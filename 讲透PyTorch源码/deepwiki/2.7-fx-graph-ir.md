## FX IR Core Components and Symbolic Tracing

- Node : Represents a single operation in the computation graph, such as calls to functions or methods, module attribute accesses, placeholders (inputs), and outputs. Each Node includes an operation type ( op ), a target (callable or attribute), arguments ( args and kwargs ), and metadata such as shape, type, or stack trace information torch/fx/node.py 33-42
- Graph : A container maintaining an ordered, directed acyclic graph (DAG) of Node instances, representing the entire computation. It manages node insertion, deletion, and preserves execution order torch/fx/graph.py 164-171
- GraphModule : A subclass of torch.nn.Module that wraps a Graph and provides a Python-executable module interface with generated source code for its forward method derived from the graph torch/fx/graph_module.py 1-20

## How FX IR Fits into the PyTorch Compilation Pipeline

`torch.compile`

- TorchDynamo transforms Python bytecode frames into FX graphs using tracing and symbolic execution.
- AOT Autograd operates on FX graphs to produce joint forward-backward graphs, partitioning for efficient backward passes.
- TorchInductor consumes FX graphs for lowering to low-level kernels, applying fusion and scheduling passes driven by pattern matching torch/_inductor/fx_passes/post_grad.py 177-183
