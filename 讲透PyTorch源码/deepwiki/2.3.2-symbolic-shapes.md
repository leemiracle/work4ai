## Dimension Dynamism Classification: DimDynamic

`DimDynamic`
torch/fx/experimental/symbolic_shapes.py 32

| Value | Description |
|---|---|
| DUCK | Duck-type specialization: attempt to share an existing symbol when dimension sizes match; otherwise allocate a new one. |
| DYNAMIC | Always allocate a fresh "backed" symbolic variable with no reuse; dimension is fully dynamic. |
| STATIC | Dimension treated as static (concrete integer). No symbol allocated; value used directly. |

## Backed vs Unbacked Symbolic Variables

| Category | How Created | Concrete Hint | Guard Strategy |
|---|---|---|---|
| Backed | Created from tensor metadata (shapes, strides) at trace time. | Yes, recorded in backed_var_to_val . | Guarded statically with equality or range guards. |
| Unbacked | Created from data-dependent operations (e.g., tensor.item() call). | No hint available. | Static guards disallowed; instead, runtime assertions inserted dynamically. |

## Guard Generation and Constraint Violation

`ShapeGuard`

### Guard Lifecycle

- Tracing : Boolean comparisons involving SymInt or SymBool are intercepted.
- Recording : ShapeEnv records the comparison as a ShapeGuard or updates ValueRanges .
- Production : ShapeEnv.produce_guards() generates Python code snippets for runtime verification.
- Execution : The RootGuardManager torch/_dynamo/output_graph.py 204 and GuardManager torch/_dynamo/guards.py 64 execute these checks.

## Integration in Export and Compile Pipelines

- torch.export() : Wraps inputs in FakeTensorMode [torch/_subclasses/fake_tensor.py] with a ShapeEnv to generate symbolic metadata.
- torch.compile() : Uses symbolic reasoning via Dynamo to track dynamic input shapes and insert runtime guards torch/_dynamo/output_graph.py 7-8
- AOT Autograd : Propagates symbolic shapes through forward and backward graphs.
- TorchInductor : Uses symbolic expressions for indexing and kernel dimension calculation test/inductor/test_torchinductor_dynamic_shapes.py
