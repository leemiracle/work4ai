## Overview

`cudaMalloc`
`cudaFree`

c10/cuda/CUDACachingAllocator.cpp 101-133

- Stream-scoped Allocations : A cached block freed on one stream can only be re-allocated on the same stream, but not on any other stream without synchronization.
- Size-based Pools : Large (>1MB) and small allocations are stored in separate pools. Small requests are packed into 2MB buffers.
- Fragmentation Reduction : Requests between 1MB and 10MB will allocate and split a 20MB block if no suitable free block exists.
- Split Prevention : Blocks $\ge$ max_split_size are not allowed to be split to reduce fragmentation.
- Synchronization : The library provides recordStream() to ensure blocks used on multiple streams are not reused before work on those streams completes.

## Allocation Lifecycle and Stream Safety

### Allocation Procedure

- Size Rounding : Requests are categorized into small ($\le$ 1MB) or large pools c10/cuda/CUDACachingAllocator.cpp 115-117
- Best-fit Search : The allocator attempts to find the smallest cached block that fits the requested size on the specified stream c10/cuda/CUDACachingAllocator.cpp 108-110
- Splitting : If a block is larger than requested, it may be split into an allocated portion and a free remainder c10/cuda/CUDACachingAllocator.cpp 109-110
- Fallback/OOM Recovery : If no block is found, it calls cudaMalloc . If that fails, it attempts to free unused cached blocks or calls registered FreeMemoryCallback s c10/cuda/CUDACachingAllocator.cpp 111-114

### Stream Safety via recordStream

`recordStream()`
c10/cuda/CUDACachingAllocator.cpp 129-132

- Mechanism : When a tensor is used on a stream other than its allocation stream, recordStream ensures the block is not reused until all recorded streams complete their work.
- Implementation : The allocator inserts CUDA events on the streams using the block. The block is only returned to the free pool once these events have been processed.
