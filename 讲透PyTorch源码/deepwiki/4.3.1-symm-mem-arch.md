## Purpose and Scope

## Core Abstractions

`c10d::symmetric_memory`

### SymmetricMemory (abstract interface)

- Represents a handle to a symmetric memory allocation established across a group of peers.
- Exposes APIs to retrieve: A host-side array of pointers to every peer’s buffer ( get_buffer_ptrs ) torch/csrc/distributed/c10d/symm_mem/CUDASymmetricMemory.cu 137-139 A device-side array of pointers ( get_buffer_ptrs_dev ) torch/csrc/distributed/c10d/symm_mem/CUDASymmetricMemory.cu 145-147 Signal pad pointers for synchronization ( get_signal_pad_ptrs , get_signal_pad_ptrs_dev ) torch/csrc/distributed/c10d/symm_mem/CUDASymmetricMemory.cu 141-143 Hardware multicast support and related multicast pointer ( has_multicast_support , get_multicast_ptr ) torch/csrc/distributed/c10d/symm_mem/CUDASymmetricMemory.cu 157-166
- Provides barrier synchronization primitives for kernel-level coordination ( barrier ) torch/csrc/distributed/c10d/symm_mem/CUDASymmetricMemory.cu 172-203

### SymmetricMemoryAllocator (abstract interface)

- Responsible for allocating symmetric memory regions exposed as tensors.
- Implements an alloc method to allocate symmetric memory of a specified size on a given device torch/csrc/distributed/c10d/symm_mem/SymmetricMemory.cpp 177-179
- Implements the rendezvous step to collectively establish symmetric memory across a group, exchanging handles via a Store torch/csrc/distributed/c10d/symm_mem/CUDASymmetricMemory.cu 33-35

### Backend implementations

- CUDA backend : Uses the CUDA driver API to allocate memory and establish peer-to-peer mappings. Supports hardware multicast on supported GPUs torch/csrc/distributed/c10d/symm_mem/CUDASymmetricMemory.cu 59-65
- NCCL backend : Uses NCCL internal mechanisms ( ncclMemAlloc , ncclMemFree ) to manage memory windows for symmetric access torch/csrc/distributed/c10d/symm_mem/NCCLSymmetricMemory.cu 68-72
- NVSHMEM backend : Integrates NVIDIA SHMEM to allocate and expose symmetric memory via NVSHMEM primitives.

## Memory Layout and Signal Pads

Signal Pad Region
Data Buffer Region

- Signal Pad : Dedicated memory for synchronization signals between ranks. It contains an array of uint32_t or uint64_t atomic flags torch/csrc/distributed/c10d/symm_mem/nccl_extension.cu 104-113
- Channels : The signal pad is logically divided into channels to support multiple concurrent communication streams. The slot index is calculated as world_size * channel + peer_rank torch/csrc/distributed/c10d/symm_mem/CUDASymmetricMemory.cu 173-174

### Optimized Kernels

- nccl_put : Directly writes to a peer's symmetric buffer using vectorized 128-bit stores ( st_vec<16> ) torch/csrc/distributed/c10d/symm_mem/nccl_extension.cu 76-102
- all_gather_offset : Fuses all-gather with a copy-out reorder. It can use either "LSA push" (writing to every peer) or "Multimem broadcast" (writing once to a multicast mapping) torch/csrc/distributed/c10d/symm_mem/ops/nccl_all_gather_offset.cu 23-29
