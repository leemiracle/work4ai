- The primary build entry point is via pyproject.toml , which specifies scikit-build-core as the build backend and defines build-time requirements like numpy , pyyaml , and typing-extensions pyproject.toml 3-24
- The setup.py file is now a shim that forwards install and develop commands to pip while issuing deprecation warnings setup.py 20-60

- The root CMakeLists.txt serves as the entry point for native builds, initializing the project and forwarding toolchain environment variables for cross-compilation CMakeLists.txt 3-74

### CMake Build Configuration and Dependencies

Dependency Resolution Logic

```

```

- Accelerator Backends : Enabling USE_CUDA triggers the inclusion of cmake/public/cuda.cmake and configures dependencies like cuDNN , cuSPARSELt , and cuFile cmake/Dependencies.cmake 22-57 Similarly, USE_XPU includes cmake/public/xpu.cmake for Intel GPU support cmake/Dependencies.cmake 83-84
- BLAS Selection : The system defaults to MKL for non-mobile builds and Eigen for mobile cmake/Dependencies.cmake 174-180
- Sanitizers : Support for ASAN , LSAN , and TSAN is integrated into the dependency resolution, with specific workarounds for ROCm/Clang compatibility cmake/Dependencies.cmake 100-148
- Installation Path : The CMAKE_INSTALL_PREFIX is strictly enforced to be the torch package directory to ensure that extension modules can resolve C++ libraries via $ORIGIN/lib RPATH CMakeLists.txt 116-132
