# NativeRT Architecture

NativeRT is a flexible C++ inference runtime designed to execute models exported via the PyTorch 2.0 export pipeline (`torch.export`). It utilizes a graph-centric execution model that operates on a serialized representation of the `ExportedProgram`, providing a high-performance path for deploying models in environments where a full Python runtime is unavailable or undesirable.

## Graph-Centric Execution Model

NativeRT's core is built around an Intermediate Representation (IR) that mirrors the structure of the exported FX graph. This IR consists of `Graph`, `Node`, and `Value` entities, reconstructed from serialized artifacts.

### Graph, Node, and Value IR

- **Graph**: Represents the top-level executable unit, containing a sequence of nodes, input arguments, output arguments, and a registry of tensor/symbolic values.
- **Node**: A single operation within the graph. It maps to a specific `target` (such as an ATen operator or a custom kernel) and maintains a list of `NamedArgument` inputs and `Argument` outputs.
- **Argument**: A union type representing tensors, scalars (int, float, bool), symbolic expressions (`SymInt`, `SymBool`, `SymFloat`), or even sub-graphs for higher-order operators.
- **TensorMeta**: Describes the metadata for tensor values, including `dtype`, `sizes`, `strides`, `storage_offset`, and `layout`.

## OpKernel Dispatch and Delegation

Execution in NativeRT is performed by iterating through the nodes of a graph and invoking their corresponding `OpKernel`. In the AOTInductor (AOTI) implementation, this dispatch is often lowered to direct C function calls via a stable ABI shim.

### Kernel Types and Dispatch

1. **AOTI C Shim Kernels**: Dispatches to ATen operators via the stable C ABI defined in `shim.h`. This avoids dependency on the full ATen/LibTorch library for the model DSO (torch/csrc/inductor/aoti_torch/c/shim.h:1-50)
2. **Statically Launched Triton Kernels**: Executes kernels compiled by Triton, loaded from `.cubin` or `.hsaco` files. The `StaticallyLaunchedTritonKernel` class manages loading and execution (torch/_inductor/runtime/static_triton_launcher.py:69-86)
3. **Specialized C++ Kernels**: For CPU backends, Inductor generates C++ wrappers that launch optimized CPU kernels

### Triton Kernel Management

Triton kernels use metadata to determine grid dimensions, shared memory requirements, and constant arguments (torch/_inductor/runtime/static_triton_launcher.py:146-165)

| Backend | Runtime Handler | Artifact Type |
|---|---|---|
| CUDA | `StaticCudaLauncher` | `.cubin` |
| XPU | `StaticXpuLauncher` | `.spv` / Intel Graphics Binaries |
| CPU | `CppWrapperCpu` | Generated C++ source |

## Execution Pipeline and ModelRunner

The `AOTIModelContainerRunner` serves as the primary entrypoint for NativeRT/AOTI in C++. It manages model loading from shared libraries (`.so`) and orchestrates execution across multiple model instances.

### Constant Folding and Memory Planning

- **Constant State Management**: The runtime tracks constants through states: `NONE`, `INITIALIZED`, and `FOLDED` (torch/csrc/inductor/aoti_runtime/model_container.h:26-41)
- **Constant Folding**: `run_const_fold` (accessible via `AOTInductorModelContainerRunConstantFolding`) pre-computes constant subgraphs (torch/csrc/inductor/aoti_runner/model_container_runner.cpp:175-176)
- **Memory Allocation**: The `ConstantBufferSet` manages blobs for both GPU and CPU constants, using `RAIIDataPtr` for lifecycle management

### Threading and Concurrency

- **Model Pool**: `AOTInductorModelContainer` maintains a pool of `AOTInductorModel` instances to allow concurrent inference requests
- **Single-Threaded Variant**: A specialized `RunSingleThreaded` API exists for latency-sensitive applications
- **No-Grad Context**: The runtime enforces a `no_grad` state using `AOTINoGradGuard` to ensure that operators like `addmm` do not attempt to record gradients (torch/_inductor/codegen/aoti_runtime/interface.cpp:74-86)

## Serialization and Stable ABI

NativeRT relies on a stable ABI to allow models compiled with one version of the compiler to run on a runtime built with a different (but compatible) version.

- **AtenTensorHandle**: An opaque pointer (`void*`) that masks the underlying `at::Tensor` object, allowing it to cross the DSO boundary safely
- **ArrayRefTensor**: A C-compatible struct for passing tensor metadata (data pointer, sizes, strides, dtype) without requiring the full `at::Tensor` class
- **External Constants**: Models can be initialized with externally-provided weights (e.g., via CUDA IPC) using `AOTInductorModelContainerCreateWithExternalConstants`, enabling zero-copy weight sharing

### C-Shim Implementation

The shim (`shim_common.cpp`) implements the C-linkage functions that the generated model code calls:

- **Exception Translation**: Catches C++ exceptions and converts them to `AOTIRuntimeError` codes
- **Dtype/Layout Mapping**: Provides stable integer mappings for PyTorch enums like `ScalarType` and `Layout` (torch/csrc/inductor/aoti_torch/shim_common.cpp:92-147)
