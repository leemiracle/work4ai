## Interception of Operations and Metadata-only Execution

`FakeTensorMode`
`FakeTensorMode.__torch_dispatch__`
meta kernel

- Meta kernels are registered using decorators like @register_meta in torch/_meta_registrations.py torch/_meta_registrations.py 66-76
- When the meta kernel is found, it constructs an output tensor on the "meta" device with appropriate metadata shape but without data allocation.
- The output is wrapped in a FakeTensor referencing the current FakeTensorMode instance, maintaining symbolic information.

### Exception handling for limitations

- DynamicOutputShapeException : Output shape depends on actual tensor values (e.g., torch.nonzero ) — cannot be traced symbolically torch/_subclasses/fake_tensor.py 170-172
- DataDependentOutputException : Operation requires data to produce results, no meta kernel available torch/_subclasses/fake_tensor.py 175-177
- UnsupportedOperatorException : No meta kernel or decomposition found; the op is unsupported in FakeTensorMode torch/_subclasses/fake_tensor.py 180-182

## Role of FakeTensor in Export and Compilation

### Export Pipeline ( torch.export )

`FakeTensorMode`

- Creates symbolic placeholders for tensors to trace purely shape/dtype computation.
- Enables building static FX graphs with symbolic shape tracking test/test_fake_tensor.py 108-127
- Interacts with symbolic constraints and guards to represent arbitrary dynamic shapes.

### torch.compile (Dynamo) and AOT Autograd

- Dynamo uses FakeTensorMode to materialize metadata for inputs and outputs while tracing kernels.
- AOT Autograd traces joint forward-backward graphs inside FakeTensorMode to collect metadata and mutation information.
- Functionalization of in-place operations is often performed within FakeTensorMode to ensure the resulting graph is clean for downstream compilers torch/_decomp/decompositions.py 58-97
