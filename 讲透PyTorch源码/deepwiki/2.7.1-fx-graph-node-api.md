## Core Data Structures

### Node

`Node`

- Operation types ( op ): placeholder : Input to the graph. call_function : Call to a standalone Python function, e.g., torch.add . call_method : Call to a method of a tensor or object. call_module : Call to a submodule within a GraphModule . get_attr : Access to a module attribute such as a parameter or buffer. output : The output from the graph.
- Each node tracks its input values ( args , kwargs ) and users (other nodes consuming its output) torch/fx/node.py 53-58
- Metadata ( meta dictionary) stores extra information such as example tensor values ( val or example_value ) or symbolic shapes to aid graph analysis and transformation torch/fx/passes/runtime_assert.py 34-45
- Side-effects are identified via @torch.fx.has_side_effect annotations and are preserved during optimizations like Dead Code Elimination (DCE) test/fx/test_fx.py 213-218 torch/functorch/compile_utils.py 174-178

### Graph

`Graph`
`Node`

- Offers creation methods like create_node , call_function , call_method , call_module , placeholder , and output for building graphs torch/fx/graph.py 68-70 test/expect/TestFXAPIBackwardCompatibility.test_function_back_compat-fx_backcompat_function_signatures.expect 10-24
- Maintains name uniqueness via an internal _Namespace that avoids Python keyword and builtin shadowing, ensuring valid and meaningful variable names during code generation torch/fx/graph.py 94-98 torch/fx/graph.py 164-206
- Supports graph transformations: node copying, erasing, dead code elimination ( eliminate_dead_code ), and deep inspection APIs like print_tabular test/expect/TestFXAPIBackwardCompatibility.test_function_back_compat-fx_backcompat_function_signatures.expect 15-25

### GraphModule

`GraphModule`
`nn.Module`

- An FX Graph that defines the computation.
- A hierarchy of submodules corresponding to the original model.
- Dynamic source code generation via _forward_from_src enabling GraphModule to behave like a normal PyTorch module while preserving symbolic structure torch/fx/graph_module.py 148-167
- Recompilation support via recompile() , which updates the forward method based on the current state of the Graph torch/fx/graph_module.py 31

## Tracing and Graph Construction

Symbolic Tracing

### Symbolic Tracing Workflow

- Proxy Wrap: Inputs are wrapped in Proxy objects that override Python operators torch/fx/experimental/proxy_tensor.py 67
- Operation Intercept: When operations are invoked on Proxy s, the Tracer intercepts them.
- Node Creation: The tracer creates a corresponding Node in the Graph to represent the operation torch/fx/_symbolic_trace.py 163-165
- Leaf Modules Control: is_leaf_module determines if a module should be traced through or treated as a single call_module node test/expect/TestFXAPIBackwardCompatibility.test_function_back_compat-fx_backcompat_function_signatures.expect 5
