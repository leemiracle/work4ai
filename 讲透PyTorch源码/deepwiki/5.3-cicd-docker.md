### .ci/docker/build.sh : Image Build Script

Main Responsibilities:

- Parse the image tag to extract versions (CUDA, ROCm, Python, GCC, Clang, etc.) using extract_version_from_image_name and extract_all_from_image_name [.ci/docker/build.sh:17-45] .
- Select the appropriate Dockerfile based on the tag details (Ubuntu base, ROCm, XPU, linter, cross-compile) [.ci/docker/build.sh:68-82] .
- For production images, parameters are set via case statements to enforce precise versions and optional features like TRITON , KATEX , and INDUCTOR_BENCHMARKS [.ci/docker/build.sh:93-236] .
- Run the docker build with computed build args and tag.

## Build Pipeline: _linux-build.yml and .ci/pytorch/build.sh

### .ci/pytorch/build.sh : In-Container Build Script

Key Aspects:

- ROCm: Sources rocm_utils.sh and runs build_amd.py for hipification [.ci/pytorch/build.sh:13-15, 155] .
- XPU: Sources Intel oneAPI variables (compiler, umf, ccl, mpi, pti) and sets USE_XCCL=1 [.ci/pytorch/build.sh:158-170] .
- CUDA: Installs libclang for CUPTI codegen if needed and sets USE_FBGEMM=0 for CUDA 13 [.ci/pytorch/build.sh:53-61] .
- Sccache: Automatically caps MAX_JOBS to nproc - 1 when using sccache for CUDA builds to avoid failures [.ci/pytorch/build.sh:182-186] .

## Test Pipeline: _linux-test.yml and .ci/pytorch/test.sh

### .ci/pytorch/test.sh : In-Container Test Dispatcher

Key Dispatch and Logic:

- Sharding: Respects SHARD_NUMBER and NUM_TEST_SHARDS [.ci/pytorch/test.sh:73-74] .
- ROCm Specifics: Caps TORCHINDUCTOR_COMPILE_THREADS to 16 and sets a timeout of 300s for compile workers to prevent multi-pod resource thrashing [.ci/pytorch/test.sh:85-99] .
- Valgrind: Selectively disabled for clang9 , xpu , and s390x due to known miscompilations or warnings [.ci/pytorch/test.sh:103-147] .
- Cleanup: Uses a trap_add to ensure workspace ownership is returned to the original ID after running as the jenkins user [.ci/pytorch/test.sh:22-36] .
