### Hierarchy Highlights

- TensorVariable : Symbolizes torch.Tensor objects. Supports tensor operations by generating corresponding FX nodes variables/tensor.py 4-6
- UserFunctionVariable : Symbolizes user-defined Python functions, supporting inlining for efficient compilation variables/functions.py 179
- ConstantVariable : Represents simple Python constants like numbers, booleans, and None, supporting eager constant folding variables/constant.py 91-92
- NNModuleVariable : Represents torch.nn.Module objects and tracks parameters for compilation variables/nn_module.py 199
- BuiltinVariable : Handles Python built-in functions and operations with special semantics variables/builtin.py 13
- UserDefinedObjectVariable : Fallback tracker for arbitrary Python objects not accounted for by specialized trackers variables/user_defined.py 7-8

### Example: TensorVariable Features

- Contains metadata such as dtype, device, and shape (symbolic or concrete) variables/tensor.py 4-6
- Implements arithmetic and method calls as FX graph nodes (e.g., add , view , reshape ) variables/tensor.py 115-124

`VariableBuilder`

- It determines the Source of the value (e.g., LocalSource , GlobalSource , AttrSource ), which tracks how to access the original Python object at runtime variables/builder.py 132-169

## Symbolic Execution of Operations

`VariableTracker`

### Tensor Operations

- Upon encountering tensor operations like BINARY_ADD , the InstructionTranslator pops corresponding TensorVariable instances from the stack torch/_dynamo/symbolic_convert.py 39-41
- It dispatches to specialized operations implemented in TorchInGraphFunctionVariable ( variables/torch.py 6-9 ) which represent torch.* functions within the FX graph.
- The OutputGraph creates a new fx.Proxy node representing the operation torch/_dynamo/variables/builder.py 161
- A new TensorVariable representing the output tensor is created and pushed back onto the symbolic stack.

### Function Inlining

- To avoid graph breaks and optimize performance, Dynamo attempts to inline user-defined functions.
- When the symbolic executor calls a UserFunctionVariable instance: A new InliningInstructionTranslator is instantiated to trace the callee function symbolic_convert.py 11 The callee's arguments are bound with bind_args_cached ( variables/functions.py 202-208 ). The callee's bytecode is executed symbolically, but all graph nodes are added to the same parent OutputGraph . The return value is placed back onto the caller's symbolic stack.

## Side Effects and Mutation Tracking

- The SideEffects manager ( torch/_dynamo/side_effects.py ) collects mutation events like AttributeMutationNew or ValueMutationNew that describe how variables change variables/builder.py 208-212
- Mutable VariableTracker subclasses (e.g., ListVariable ) update their internal state and record mutations into SideEffects as tracing proceeds.
- In the presence of a graph break or deoptimization, the recorded side effects allow Dynamo to generate Python bytecode that replays state mutations so execution can resume correctly variables/base.py 125-131
