# 02 · AI 驱动的软件可解释性（用 AI 解释复杂软件行为）

> 本章是"可解释性"系列的**视角扩展**。[00](./00-为什么AI是黑箱.md) 和 [01](./01-Probing归因机理.md) 讲的是"**解释 AI 模型内部**"（Probing / SHAP / Mechanistic，AI 是被解释对象）。本章讲对偶问题："**用 AI 解释复杂软件行为**"（AI 是解释工具，软件是被解释对象）——这是 2024-2026 随 LLM 兴起的新赛道，从 Datadog Bits AI 到学术 TAAF/AgentSight/Lean4Agent。核心洞察：**LLM 软件解释的主导失败模式是"解释性幻觉"（71.2%），需要形式化验证才能根治**。

## 一、两个"可解释性"：对偶问题

### 1.1 容易混淆的两个方向

| 方向 | 被解释对象 | 解释工具 | 代表方法 | 本系列位置 |
|------|-----------|---------|---------|-----------|
| **模型可解释性**（XAI）| AI 模型内部 | Probing / SHAP / 电路分析 | "这个神经元在干什么" | [00](./00-为什么AI是黑箱.md) / [01](./01-Probing归因机理.md) |
| **软件可解释性**（AI-driven）| 复杂软件行为 | LLM + trace + 形式化 | "这个 OS 为什么崩了" | **本章** |

> 🎯 **一句话**：模型可解释性是"解释 AI"，软件可解释性是"用 AI 解释"。两者在 2024-2026 开始合流——用 LLM 解释软件，但 LLM 自己又会幻觉，所以需要形式化（Lean4）来保证解释可信。

### 1.2 为什么"软件可解释性"突然重要

每个重要软件（Linux / 浏览器 / 编译器 / 数据库 / K8s）都只有少数内部人真懂，外部人被术语墙挡住。2024-2026 三件事让"AI 解释软件"成为热门：

1. **LLM 能力到位**：GPT-4 / Claude 终于能读懂 trace 并生成解释
2. **eBPF 成熟**：Linux 内核级 trace 采集变得高效（[讲透GPU与系统级](../讲透GPU与系统级/)）
3. **可观测性厂商商业化**：Datadog / Honeycomb 把 NLQ（自然语言查询）做到生产级

## 三、解释性幻觉：LLM 软件解释的主导失败模式

这是理解"为什么软件可解释性需要形式化"的关键。

### 3.1 数据：71.2% 的失败是"解释性幻觉"

2026 年最新 RCA 研究（多篇 LLM-RCA 论文）显示，LLM RCA agent 的失败模式分布：

| 失败模式 | 占比 | 说明 |
|---------|------|------|
| **解释性幻觉**（Hallucination in Interpretation）| **71.2%** 🟥 | LLM 编造不存在的因果链 / 错误归因 / 臆测根因 |
| 工具调用错误 | 15.3% | 调错 API / 参数错 |
| 上下文不足 | 8.1% | trace 不够全 |
| 其他 | 5.4% | — |

> 🟥 **关键结论**：**LLM 软件解释的主导失败模式（71.2%）是"解释性幻觉"——LLM 自信地编造因果链**。而且研究表明 **prompt engineering 无法根治**（换 prompt 只能把幻觉从一种形态换成另一种）。

### 3.2 为什么 prompt engineering 解决不了

| 试图 | 为什么不行 |
|------|-----------|
| "请仔细检查再回答" | LLM 没有"检查"的 ground truth，只能再生成一遍（同样会幻觉）|
| "给出证据 trace 段" | LLM 会编造 trace 段或误读真实 trace |
| "多 agent 互相验证" | 多个幻觉的 LLM 互相"验证"，可能收敛到同一个错误（群体幻觉）|

### 3.3 正解：形式化验证交叉检查

研究结论是：**需要独立的验证模块交叉检查 LLM 的解释**。这正是形式化（Lean4）的用武之地：

```
LLM 生成候选解释（含因果链）
    ↓
Lean4 形式化检查（因果无环？不变式满足？）
    ↓ 通过 → 可信解释
    ↓ 失败 → 标"低置信度"，降级或丢弃
```

> 🎯 **核心洞察**：**形式化不是锦上添花，是刚需**。LLM 软件解释的 71.2% 幻觉率，只有形式化（[讲透形式化验证](../讲透形式化验证/)）能根治——因为它提供 LLM 不具备的 ground truth。

这与 [讲透神经符号](../讲透神经符号/) 的"LLM 生成 + Lean4 验证"闭环完全一致：**LLM 给"可能对的"，Lean 给"绝对对的"**。

## 四、三件套：AI 软件可解释性的开放问题

把四类竞品画在三维空间（**L0 硬件 trace** × **L2.5 形式化** × **L3 教学级英文**），存在五个"单点簇"，但**没有竞品占据三者交集**：

| 单点簇 | 代表 | 有 | 没有 |
|--------|------|----|----|
| eBPF + LLM | AgentSight / Kgent | L0 | L2.5 / L3 教学 |
| Trace + KG + LLM | TAAF | L0 + L2 | L2.5 / L3 教学 |
| Lean4 + 软件行为 | Lean4Agent / LeanCTX | L2.5 | L0 / L3 教学 |
| Lean4 + 数学 | AlphaProof 系 | L2.5 | 非软件域 |
| NLQ + RCA | Datadog / Honeycomb | L3（flat）| L0 硬件 / L2.5 形式化 |

> 📌 **开放问题**：**"形式化保证的教学级解释" × "硬件级 ground-truth trace" × "领域无关"** 的三件套，**截至 2026-08 无竞品占据**。这是 AI 软件可解释性的前沿开放问题——谁能整合这三层，谁就占据下一个 niche。

### 4.1 为什么"教学级解释"是最难复制的

在三层里，**L3 教学级英文解释是最深的壁垒**——因为它不是技术问题，是**内容方法论 + 认知科学**问题：

| 层 | 壁垒类型 | 复制难度 |
|----|---------|---------|
| L0 eBPF trace | 技术（开源基础设施）| 低（eunomia 生态已成熟）|
| L2.5 Lean4 形式化 | 技术 + 形式化人才 | 中（Lean4 开源，但软件因果规则是新领域）|
| **L3 教学级解释** | **内容方法论（直觉→数学→证据 + 费曼门）** | **高**（需要长周期教学法积累，不是算力/数据能买到的）|

全部竞品的 L3 都停留在"flat 问答/RCA 报告"（一次性、无认知阶梯），**无人做 pedagogical**（直觉→数学→代码、费曼门、17 视角）。这是本知识库（work4ai 讲透范式）的方法论核心——教学深度是 LLM 软件解释里最被低估的差异化维度。

## 五、与模型可解释性的合流

### 5.1 两个方向的交叉点

| 交叉 | 含义 |
|------|------|
| 用 Probing 解释 LLM 自己 → 再用该 LLM 解释软件 | "解释工具本身可解释" → 解释更可信 |
| 用 LLM 解释软件 + 用形式化验证解释 | [讲透神经符号](../讲透神经符号/) 的闭环 |
| 用 mechanistic 分析找 LLM 幻觉的电路原因 | 从根本理解"71.2% 幻觉"是怎么产生的 |

### 5.2 实践建议

如果你要做"AI 解释软件"的项目：
1. **数据源选硬件级 trace**（eBPF / Intel PT），不要用应用层 SDK 遥测（[类别 B](#类别-bobservability--llm可观测性--llm--l3-商业化冠军) 的盲区）
2. **必须有形式化验证层**（Lean4 或 Z3），否则陷入 71.2% 幻觉（[§三](#三解释性幻觉llm-软件解释的主导失败模式)）
3. **解释要做教学级**（直觉→数学→证据），不要 flat QA（这是 [类别 A/B](#类别-aai-for-code-understanding代码理解) 的盲区）
4. **领域无关内核**（Event/State/Causality/Invariant/DecisionPoint 五原子），不要为单一 benchmark 定制

## 六、一句话总结

> 🎯 **三句话**：
> 1. **两个"可解释性"是对偶问题**：模型可解释性（[00](./00-为什么AI是黑箱.md)/[01](./01-Probing归因机理.md)，解释 AI 内部）vs 软件可解释性（本章，用 AI 解释软件行为）——两者在 2024-2026 因 LLM 幻觉问题开始合流。
> 2. **四类竞品各有单点突破但无人三件套集成**：代码理解（Sourcegraph）/ 可观测性+LLM（Datadog，L3 商业化冠军）/ 学术 RCA（TAAF，ICSE 2026）/ 形式化+LLM（Lean4Agent）——"硬件 trace × 形式化 × 教学级英文"的交集是开放 niche。
> 3. **解释性幻觉（71.2%）是 LLM 软件解释的主导失败模式，prompt engineering 治不好，形式化验证是刚需**——这正是 [讲透形式化验证](../讲透形式化验证/) + [讲透神经符号](../讲透神经符号/) 的用武之地。
