## 2. 不存在的（社区传闻 vs 代码实测——DeepSpec 教科书案例）

底稿 E 全仓 grep 确认 DeepSpec **没有**：hint 机制、fuzz 测试、trace 生成、统计显著性检验、clock 同步处理、墙钟加速比基准、woodpecker/自投机/MTP baseline。社区文章常把这些"应有之物"写成"已有之物"——**正确性由拒绝采样构造保证（accept=min(1,p_t/p_d)+残差采样），加速比按理论接受率报告**。引用任何仓库前先 grep，是本宇宙的方法论纪律。

同类纠偏（底稿 C/G）：
- 3FS 传闻有 DPDK 网络与 batch load/file insight 工具——实测网络层纯 RDMA verbs；对应实际为 admin_cli 60+ 命令 + fio_usrbio/storage_bench
- dsh 传为"Claude Code 开源替代"——实测是**无特权核心的插件运行时**，且通过 Hook 双桥主动兼容 Claude Code/Codex 存量配置（定位不同）

## 3. 有分歧的（论文 vs README vs 仓内注释）

- Prover-V2 PutnamBench：论文 47/658 vs README 49/658（底稿 F 已注记）
- TileKernels：README 说"kernel library"，当前 HEAD 已无 GEMM/attention 内核，转向 gating/MoE 路由/量化/Engram 内核——**仓库在快速转向，快照会过期**

## 4. 本深读自身的局限

1. `--depth 1` 克隆：无 git 历史，**改动雪崩分布（power law）无法在组织内验证**——复杂系统三支柱的可证伪预测之一在本标本上暂缺数据
2. 抽样精读（每仓 3-15 个核心文件），非 10,692 文件全量
3. star/时间快照 2026-08-15；dsh 仓龄极短，生态数字（59 个 dsh-plugin 仓等）变动快
4. 浅克隆默认分支：ko3n1g/ci 等开发分支未读
