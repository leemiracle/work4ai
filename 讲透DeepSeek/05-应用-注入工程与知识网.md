## 2. 工程决策注入（怎么做——可直接借用的七条）

1. **选择与加权解耦**（aux-loss-free 的通用化）：任何"路由/推荐/调度"模块，把控制流（选谁）与数值流（权重多少）分开实现——bug 面最小、可审计。适用：RAG 路由、技能调度。
2. **解析 cost model 优先于 autotune**：已知封闭环境（自己的机器/固定的模型档位）时，把硬件常数写进公式（DeepGEMM 式），而非网格搜索。适用：`.tools/` 各脚本的模型选档。
3. **事件溯源 + "可见即记录"断言**（dsh）：会话状态唯一权威=append-only 事件日志，模型可见内容与日志记录在运行时强制一致。适用：opencode 会话复现、dual-chat。
4. **fail-closed 审批**（dsh）：审批组件缺席=拒绝执行，而非放行。适用：一切带 hook/审批的自动化。
5. **keyless snapshot 回归测试**（dsh）：录模型响应快照，无 API key 也能回归 harness 行为。适用：prompt-library 的版本回归。
6. **Model Experience 三段式 README**（dsh 每包强制）：模型看到什么 / Token 效应 / **KV Cache 效应**——给 agent 消费的文档新文体。适用：skills工程手册 的技能卡模板。
7. **负结果入档**：DeepSeek 五处公开负结果的对照——本项目的 `.agent/MEMORY.md` 已执行（错误也入库），继续对齐。
