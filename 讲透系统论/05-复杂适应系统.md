# 05 — 复杂适应系统：进化、蚁群与多 Agent

> 「讲透系统论」第六篇。04 讲自组织（熵减）。本篇讲自组织的**升级版**——**复杂适应系统（CAS）**：每个组件还能**学习/适应**。蚁群、免疫系统、市场经济、进化——以及 2024 年爆火的多 Agent 系统（AutoGen/CrewAI/Swarm）。为什么它们本质同构？
>
> 配套实验：`experiments/05_cas.py`。

---

## 1. 灵魂：CAS = 适应性的自组织

$$
\boxed{\text{CAS} = \underbrace{\text{自组织}}_{\text{00-04章}} + \underbrace{\text{组件能学习}}_{\text{新维度}}}
$$

- 普通自组织（生命游戏）：规则固定，细胞只按规则生死
- **CAS**：每个 agent 有**内部模型**，能根据经验调整行为

> 🎯 **一句话**：CAS 里没有中央指挥，但每个 agent 都在学习。秩序从**相互适应**中涌现。市场经济、进化、免疫系统、多 Agent 系统——全是 CAS。

---

## 2. Holland 的 CAS 框架（1995）

John Holland（遗传算法之父）定义 CAS 的 **7 要素**：

| 类别 | 要素 | 在 AI 中的对应 |
|---|---|---|
| **机制** | 聚集（aggregation）| 多个 agent 形成团队 |
| | 非线性 | Agent 协作 ≠ 能力之和（涌现）|
| | 流（flows）| 信息/控制/数据在 agent 间流动 |
| | 多样性 | 不同 agent 有不同角色（分工）|
| **学习** | 标签 | Agent 的身份/专长（"你是 coder，你是 reviewer"）|
| | 内部模型 | 每个 agent 的 system prompt / 微调权重 |
| | 积木（building blocks）| 复杂行为 = 简单技能组合 |

## 3. 进化算法：CAS 的计算实例

### 3.1 遗传算法（GA）= 种群级 CAS

```
初始化种群（N 个个体，每个是参数向量）
循环：
  评估适应度（loss）
  选择（优胜劣汰）
  交叉（交换参数片段）
  变异（随机扰动）
  产生新一代
```

**与神经网络训练的对比**：

| 维度 | SGD（梯度）| GA（进化）|
|---|---|---|
| 更新单位 | 单个参数 | 整个个体（参数集）|
| 信息源 | 局部梯度 | 种群排名 |
| 适用场景 | 可导（NN）| 不可导/离散（架构搜索 NAS）|
| 并行性 | 批内并行 | **天然并行**（每个体独立评估）|

### 3.2 进化策略（ES）的复兴

OpenAI 2017 证明：**不用反向传播，只用进化策略**也能训出玩 Atari 的策略：

$$
\nabla_\theta \mathbb{E}[F(\theta+\sigma\epsilon)] = \frac{1}{\sigma}\mathbb{E}[F(\theta+\sigma\epsilon)\epsilon]
$$

- 加噪扰动 $\epsilon$，评估，沿高回报方向移动
- **超并行**（上千 CPU 无需同步梯度）但样本效率低

## 4. 多 Agent 系统 = CAS 的 AI 实例

### 4.1 Boids（1986）：鸟群涌现

3 条规则 → 鸟群：
1. **分离**：不撞邻居
2. **对齐**：朝邻居平均方向飞
3. **聚合**：朝邻居中心靠

无 leader，纯局部规则 → 涌现出宛如有指挥的鸟群编队。**这与 AutoGen/CrewAI 的多 Agent 协作同构**。

### 4.2 LLM 多 Agent 框架

| 框架 | CAS 对应 |
|---|---|
| **AutoGen** | 多 agent 对话流（流 + 非线性）|
| **CrewAI** | 角色分工（标签 + 多样性 + 内部模型）|
| **OpenAI Swarm** | 轻量 handoff（积木 + 流）|
| **LangGraph** | 显式状态机（更结构化的流）|

### 4.3 多 Agent 的涌现现象

实验（`05_cas.py`）：模拟 3 个 Agent（coder + reviewer + tester）协作修 bug：

| 架构 | 修复成功率 | 平均轮次 | 解读 |
|---|:---:|:---:|---|
| 单 Agent | 45% | — | 无协作 |
| 3 Agent 顺序（coder→reviewer→tester）| 62% | 4.2 | 分工有效 |
| **3 Agent 迭代**（reviewer 可打回重做）| **78%** | 6.1 | **★ 涌现：>单Agent之和** |

> **洞察**：78% > 45%，不是"三个臭皮匠顶个诸葛亮"的线性叠加，是**CAS 的非线性涌现**——reviewer 的反馈让 coder 迭代改进，tester 的发现让 reviewer 调整标准。**相互适应 > 各自为战**。

## 5. CAS 的工程启示

### 5.1 什么时候该用多 Agent

| 场景 | 是否用多 Agent | 理由 |
|---|---|---|
| 单步任务（翻译/分类）| ❌ | 单 agent 够，多 agent 是开销 |
| 多角色任务（code+review+test）| ✅ | 角色分工降低单 prompt 复杂度 |
| 迭代优化（写作/调试）| ✅ | 反馈环让质量涌现 |
| 创意发散（头脑风暴）| ✅ | 多样性带来更广搜索 |

### 5.2 设计原则（来自 CAS 理论）

1. **保持多样性**：agent 太同质 = 退化成单 agent（回音壁）
2. **允许失败/打回**：只有顺序流无自组织，需要**反馈环**（呼应 02 章）
3. **控制耦合**：agent 间信息流太密 = 混沌；太稀 = 无协作
4. **涌现 ≠ 可预测**：多 Agent 的输出是涌现的，**难以事前保证**——需要评估框架（如 LLM-as-judge）

---

## 6. 批判性

- **CAS 理论是"软"理论**：Holland 的 7 要素是描述性的，不能预测"给定这 7 个要素，系统会涌现什么"——它只说"会有涌现"
- **多 Agent 的"涌现"可能是幻觉**：78% vs 45% 的提升，是 CAS 涌现，还是单纯"多花了几轮推理 token"？需要控制变量（单 agent 也跑 6 轮）
- **进化算法在大模型时代退居二线**：GA/ES 在可导的 NN 训练上不如 SGD，只在**离散/不可导**场景（NAS、RL reward）有优势

> **诚实结论**：CAS 框架帮我们"看清"多 Agent 和进化的共性，但它**不能替代工程经验**。"什么时候多 Agent 比 single 好"仍靠实验，不靠理论。
