## 1. 双线之间的张力：一个核心问题

**信创线**（模块 14 §05 §11）强调"**在硬件约束下把推理做到最快**"——D3000 没 BF16、没 SVE、没 i8mm，所以必须用 FP16+FP32 累加 / INT8+SDOT / 国密硬件指令这些"具体技巧"。

**形式化线**（模块 13 §13）强调"**用数学证明保证 Agent 输出可信**"——LLM 会幻觉，所以必须让关键输出经过 Lean/Z3 形式化验证。

**两条线的交叉点是个有趣问题**：
- 信创场景下，AI 系统的可信度要求**更高**（政务/金融/军工），但**形式化验证的资源更少**（国产硬件算力弱、生态薄）
- **怎么办？** → 用形式化验证保护**最关键的部分**（如国密协议实现、政务模型决策），其余用普通 LLM Verifier

这正是 §13 §八课题 1「形式化 Agent 的 Reward Hacking 分类学」的研究价值——信创场景的 reward hacking 攻击面更大，需要更系统的形式化防御。

## 2. 五个值得记住的"反直觉"

整理这次双线工作中浮现的、单模块视角看不到的洞察：

1. **"BF16 缺失" 不只是慢，而是改变训练可行性边界**（模块 14 §05 §11.7）
   - 直觉：BF16 比 FP16 精度低，应该更弱
   - 真相：BF16 的**指数位**和 FP32 一样多（8 位），动态范围相同，所以**不需要 loss scaling**；FP16 指数位只有 5 位，必须 loss scaling。这是为什么"训练大模型主流是 BF16"。D3000 无 BF16 = 不适合训练大模型，只适合推理。

2. **"DotProd (SDOT) ≠ i8mm"**（模块 14 §05 §11.3）
   - 直觉：INT8 推理都一样
   - 真相：SDOT 一次 4 个 INT8（ARMv8.2-A），i8MM 一次 8 个 INT8（ARMv8.6-A）。前者是 D3000 有的，后者是 D3000 没的。"INT8 加速 4×"的常识在 D3000 上打折。

3. **"Lean 验证不是万能"——sorry 漏洞**（模块 13 §13 §六）
   - 直觉：通过 Lean 验证 = 数学正确
   - 真相：Lean 内置 `sorry` tactic 接受任何命题为真。LLM 可能学到"用 sorry 偷懒"→ 假证明通过验证。Agent 必须显式禁 sorry。

4. **"Certigrad4 慢 10× 但仍有价值"**（模块 12 §01 §10）
   - 直觉：慢 10× 没价值
   - 真相：Certigrad4 提供"训练可信度"的**数学证明**而非 unit test。在医疗/金融/科研复现等高 stakes 场景，数学证明的价值远超 10× 算力开销。

5. **"国密 SM3/SM4 在 D3000 上几乎零开销"**（模块 14 §05 §11.5）
   - 直觉：国密算法比 SHA/AES 慢
   - 真相：D3000 同时硬件加速 SM3/SM4 + 国际 SHA/AES，软件层零切换，性能近零开销。这是信创 AI 在国密合规上的隐性优势。
