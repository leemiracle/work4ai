## 锚点 4：4-wide 超标量 + 实测微架构参数（17 篇反复引用）

| 参数 | 实测值 | 来源 |
|------|--------|------|
| Issue Width | **4-wide** | `[实测 Lab00 null_loop IPC=4.00]` |
| ALU 端口 | 2/cycle（loop_add IPC=2.00） | `[实测 Lab00]` |
| 核数/频率 | 8 核 / **2500 MHz**（performance governor） | `[实测]` |
| L1 D-Cache | 64KB / **4-way** / 64B / 256 sets @ 1.6 ns | `[实测 Lab03/associativity 反推 4-way]` |
| L2 | **512 KB** / 8-way / 1024 sets @ 5-8 ns（数据手册标 1M 不符） | `[实测 Lab03]` |
| L3 | **4 MB（核0-3）+ 8 MB（核0-7）分级**共享 @ 14 ns | `[实测 Lab03]` |
| DRAM | 130-140 ns | `[实测 Lab03]` |
| 重命名拐点 | n≥12 IPC saturate 3.45（发射带宽，非 PRF） | `[实测 Lab04]` |
| ROB/LDQ | LDQ 下界 ≈ 32（rob_size 拐点） | `[实测 Lab04]` |
| SMT | **SMT=1，未实现** | `[实测]` |
| fmadd latency | 4 cyc | `[实测 Lab02]` |

**权威含义**：D3000M 是**主流级 4-wide 乱序**（对标 A72/A76 级别，非旗舰）。L2=512K（非手册 1M）是写作必引的诚实点。无 SMT 是关键判断点（服务器 CPU 罕见）。

**视角分工**：E02（架构：PPA 决策）、E09（建模：Roofline/CPI 栈）、E04（OS：页表/TLB/syscall）独家展开各自侧面；**其余只引用本表数字，不重测**。

## 锚点 5：ARM v9 不授权中国厂商 → 被迫停留 v8.4（17 篇）

| 项 | 内容 | 来源 |
|----|------|------|
| 事实 | ARM v9 架构不向中国厂商授权 | `[官方-ARM政策]` |
| 后果 | 飞腾理论上 ISA 天花板锁在 v8.x（v8.4 是当前最高实现） | `[推理]` |
| 退路 | 转 RISC-V（无授权限制）或自研 ISA | `[推测]` |

**权威含义**：这不是纯工程决策（不是"飞腾选 v8.4"），而是**政治铁幕**强制。BF16/I8MM 属 v8.6 扩展、理论 v8.x 许可获得，**飞腾为何没拿到**是真正待解问题（技术差距 or 谈判筹码，见 E01 §1.7）。

**视角分工**：E19（地缘：出口管制/ISA 授权政治）独家展开成因；E22（开源：RISC-V 退路）、E01（研究：v9 锁死的研究影响）展开各自推论；**其余只引用**。

## 锚点 7：UDOT（v8.4 INT8 点积，14 篇）—— 伤疤里的一线生机

| 项 | 内容 | 来源 |
|----|------|------|
| 实测 | int8 UDOT **14.73 GMACS**，vs NEON v8.0 widen **4.41× 加速** | `[实测 Lab01 dot_product]` |
| 定位 | 有 INT8 点积，**但无 I8MM 矩阵乘**（I8MM 一条 SMMLA 顶多条 UDOT） | `[实测]` |

**权威含义**：UDOT 让 D3000M 能做量化 CNN（int8 推理有 4× 加速），但**做不了 Transformer 的 GEMM**（那需要 I8MM/BF16 矩阵单元）。这是"伤疤里的一线生机"——不是完全不能做 AI，是做不了大模型。

**视角分工**：E05/E21（合并后 AI）独家展开算子下沉与代价；**其余只引用**。

## 写作纪律小结（给所有 Expert 作者）

1. **先读本文件**：动笔前查你要写的事实是否已是锚点。是 → 引用 + 独特推论。
2. **视角分工表是硬约束**：表里标"只引用"的视角，**禁止展开该锚点的含义**，只写"详见战略锚点 + 本视角的独到之处"。
3. **数字不重测**：本文件的实测数字是项目权威，各 Expert 直接引用，不各自复测/复述。
4. **新锚点准入**：若发现新的跨多 Expert 重复事实，加到本文件而非各写各的。
5. **元叙述克制**：对偶/盲区/特异性段允许一句话带过（如"本视角的盲区：不见 X，见 E0Y"），不必每篇大段模板化（详见阶段 4 瘦身指南）。

### 甄别原则（2026-07-16 去重复盘得出，避免误删独到内容）

**"某锚点在 N 个 Expert 出现" ≠ "重复 N 次"**。本项目是多视角剖析，同一个事实（如 BF16 缺失）被不同视角从不同侧面分析，是设计意图，不是冗余。去重时必须区分三类：

| 类别 | 特征 | 处理 | 案例 |
|------|------|------|------|
| **① 独到视角分析** | 该 Expert 给出只有本视角才有的剖析（数值精度/DFT代价/商业模型/地缘成因...） | **保留**，只引用锚点事实 | E08 §3.4 FP16 静默饱和实测、E17 §2.7 补指令的硅后验证代价 |
| **② 真正同名双写** | 两个 Expert 有几乎相同的章节名 + 重叠内容 | **删一方，改引用** | 旧 E05/E21 的"算力上界推算""UDOT 代价"（已处理） |
| **③ 纯基础事实复述** | 重复"4-wide""L2 512K"等参数，无本视角推论 | **改引用锚点表**，不留复述 | 锚点 4 微架构参数表已收敛 |

**铁律：去重只能动 ②③，绝不能动 ①**。甄别方法是问一句"删掉这段，该视角是否丢失只有它才有的洞察？"——是 → 保留；否 → 可去重。

> 复盘数据：诊断时 BF16 在 22 篇"出现"，但逐篇甄别（E08 45 行、E17 10 次"战略伤疤"）证明**绝大多数是 ① 独到视角**。真正属 ②③ 的只有 E05/E21 同名双写（已处理）+ 基础参数复述（锚点 4 已收敛）。**多视角项目里，"高频出现"是视角丰富的证据，不是冗余的罪证。**
