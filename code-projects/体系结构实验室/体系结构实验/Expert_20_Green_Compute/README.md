# Expert_20 — 可持续计算工程师 / ESG 分析师视角

> **角色定位**：数据中心能效（Energy Efficiency）工程师 / 可持续计算（Green Compute）架构师 / ESG 合规分析师。
> 我的日常：给机房算 PUE（电源使用效率）、给 CPU 排每瓦性能榜（PPW）、给一颗芯片做生命周期碳排（LCA）、把整柜的功耗曲线压到 TDP 之下以挤进供电配额、写 TCFD（气候相关财务披露）报告里「范围 1/2/3 排放」那一栏。
> 我不关心这颗芯片能跑到多少 GFLOPS——**我关心的是：每花一焦耳电、每排一克碳、每用一吨冷却水，它换回了多少有用的计算。**
>
> **核心思维模型（全部 named）**：
> 1. **能效第一性原理 = PPW（Performance Per Watt，每瓦性能）** —— 芯片的「绿色账」不是看它绝对功耗多低，是看它「单位功耗换回多少性能」。一颗 20W 跑 100GFLOPS 的芯片，比一颗 200W 跑 500GFLOPS 的芯片**更绿**（5 vs 2.5 GFLOPS/W）[论文-Raghavan2011]。
> 2. **数据中心 PUE（Power Usage Effectiveness）= 总耗电 / IT 设备耗电** —— 由 Green Grid 联盟 2007 年提出 [标准-GreenGrid-PUE]，PUE=1.0 是理想（所有电都给服务器），PUE=2.0 意味着每 1W IT 负载要额外 1W 给冷却/照明/UPS。**PUE 把「机房基础设施的能耗税」量化成了单一数字**。
> 3. **LCA（Life Cycle Assessment，生命周期评估）× Scope 1/2/3** —— 碳足迹不是只算「运行时电费」，要按 GHG Protocol（温室气体核算体系）[标准-GHG-Protocol] 分三类：Scope1（直接排放，如柴油机）、Scope2（外购电力的间接排放）、Scope3（供应链上下游，含**芯片制造碳排**）。**一颗 CPU 的碳，有 60–80% 花在制造（光刻/封装/测试），不在运行** [论文-Gupta2021-Carbon]。
> 4. **DVFS（Dynamic Voltage & Frequency Scaling）× ARM PSCI / P-states/C-states** —— 动态电源管理的 ISA/OS 框架。服务器 CPU 能否按负载「调压调频、深度睡眠」直接决定空闲能效。
> 5. **ESG 合规三件套 = CBAM（欧盟碳边境调节机制）× TCFD（气候财务披露）× 中国「双碳」（2030 碳达峰 / 2060 碳中和）** —— **绿色不是道德，是合规成本**；进口芯片要交碳关税、上市公司要披露碳排、信创数据中心有能耗配额。

## 0. 写在最前面：为什么「绿色计算」是 D3000M 的隐藏优势与隐藏陷阱

在整个飞腾 D3000M 视角体系里，**绿色计算是一个「最容易被低估、也最容易误判」的维度**。

直觉判断往往是错的：**「国产 14nm CPU 性能落后，所以一定更耗电、更不绿」** —— 这是用「绝对功耗」代替「每瓦性能」的经典错误（盲区 §4 会详述）。真实情况要分两面看：
- **隐藏优势**：D3000M 标称 TDP 约 72W [推测-E02外推]，远低于 Intel Xeon Platinum（350W+）和 AMD EPYC（400W TDP）。在「功耗密度/供电配额/散热压力」这些**机房基础设施约束**下，**低 TDP 反而是部署优势**——同样一台机柜的供电/散热配额，能塞进更多 D3000M 节点。这正是 §2.6「高密度部署」的论据。
- **隐藏陷阱**：低 TDP 不等于高能效。如果 D3000M 每瓦换回的算力（PPW）只有对手的一半，那么「省下的电」被「少干的活」抵消了——**做同样一件事，它反而更耗电**。这是 PPW 视角的精髓（§2.2）。

更尖锐的一层：**「绿色」在信创语境下有政治含义**。中国「双碳」政策对数据中心有硬性能耗配额（PUE<1.3 才准建 [报告-工信部PUE]），国产 CPU 若能证明「信创机房比进口机房更绿」，这是政策红利；反之若国产 CPU 能效落后导致信创机房整体更耗电，那是政策打脸。**「绿色信创」是 D3000M 真正能打、也必须打的一张牌**（§2.7）。

> **本视角的一号结论（先亮底牌）**：D3000M 的能效定位是 **「单核每瓦性能（PPW）落后主流 ARM 服务器一代、但整机功耗/散热密度友好，
> 在『信创机房 PUE 与双碳配额』的政策框架下，其低 TDP + 国产供应链短链的『绿色合规』价值，
> 部分对冲了 PPW 的绝对差距」**。净碳效应是否为正，取决于负载类型（见 §2.7 净碳账）。
> 换句话说：**D3000M 不是「最绿的 CPU」，但可能是「最契合中国绿色合规框架的 CPU」**——这是它与进口 CPU 的差异化护城河，也是它最大的风险点（PPW 落后被对手放大就反转）。

### 0.1 一段必要的能效演进史：为什么「每瓦性能」是过去 15 年最重要的芯片指标

要理解 D3000M 在能效光谱上的位置，必须知道这门手艺的来路——它不是凭空出现的：

- **2000s 早期，频率军备竞赛终结**：Pentium 4 冲 4GHz 失败（Expert_02 故事 2），业界惊觉「功耗墙」——漏电功耗（leakage）随频率/电压指数上升，风冷散热到极限。**从此芯片设计从「追频率」转向「追能效」** [论文-Esmaeilzadeh2012-DarkSilicon]。
- **2006–2010，Barroso 定义「数据中心能效」**：Google 的 Luiz Barroso 发表《The Datacenter as a Computer》[书-Barroso2013]，提出两个改变行业的洞察：**① 能效用「能量比例（energy-proportional）」衡量**——服务器在低负载时也应按比例降功耗，而不是空转就吃满电；**② PUE 是衡量机房基础设施的单一指标**。这两条定义了今天所有云厂商的能效账本。
- **2007–2012，SPECPower 基准成熟**：SPEC 组织的 `SPECpower_ssj2008`（后继 `SPECpower_ssj2008`/`SPEC CPU + energy`）成为服务器能效的**事实标准**——测 10 个负载档（100%→10%）下的性能/功耗比值，取 `overall ops/W` [标准-SPECpower]。**这个基准让 Intel/AMD/ARM 第一次能在「每瓦性能」上同台量化对标**。
- **2010s，ARM 服务器叙事 = 能效叙事**：ARM 进服务器市场的核心卖点从来不是「更快」，是「更省电」。Calxeda、Cavium、华为鲲鹏、AWS Graviton——**全部以「每瓦性能」为第一张牌**。Graviton 系列从 G2 到 G5，AWS 官方反复强调「同等性能下省 60% 电」[报告-AWS-Graviton]。
- **2019 至今，Green500 + 碳关税时代**：Top500 的子榜 Green500（每瓦算力排行）成为超算第二张榜单；欧盟 2023 年通过 CBAM（碳边境调节机制），2026 年全面开征碳关税 [标准-EU-CBAM]；中国工信部要求新建大型数据中心 PUE≤1.3 [报告-工信部]。**「绿色」从软指标变成了硬合规。**

**这段历史给 D3000M 的定位**：飞腾站在一个「能效叙事已主导服务器市场 15 年」的舞台上，但它的工艺节点（14nm 级成熟制程 [推测-出口管制]）和架构选择（4-wide、2.5GHz、无 SVE/BF16）**让它在「每瓦性能」这张主榜单上处于中游偏下**。本视角通篇的判断不是「飞腾不绿」，而是**「飞腾的绿在于『功耗密度友好 + 国产合规』，不在于『单核能效领先』」**——这两者对采购决策的含义完全不同。

## 1. 这位能效工程师看飞腾 D3000M 的 10 个尖锐问题

把上面的命题拆成 10 个我会真去问飞腾现场工程师、并要求拿出数字的问题：

1. **D3000M 的每瓦性能（PPW）到底多少？** 没有 SPECPower 官方数据的情况下，能否用 Lab 实测的 GEMM/流式负载推一个 proxy？这个 proxy 怎么和 Intel Xeon / AMD EPYC / AWS Graviton / 华为鲲鹏 920 量化对标？
2. **72W TDP 的「功耗优势」是真优势还是假象？** 低 TDP 如果换不回等比例的算力（PPW 落后），那「省电」就是「少干活」，净能效反而更差——必须做「完成单位任务的总能耗」对比，而非「峰值功耗」对比。
3. **信创机房用 D3000M vs 用 Intel，PUE 会更好还是更差？** 低 TDP 芯片散热量小，理论上更容易冷却（PUE 下降）；但如果节点算力弱导致「完成任务需要更多节点」，总 IT 负载上升，PUE 反而可能恶化——这是「密度 vs 总量」的悖论（§2.6）。
4. **D3000M 的 DVFS / 电源管理能力到哪一档？** ARM 的 **PSCI（Power State Coordination Interface）** 飞腾实现了几级？支持 per-core DVFS 吗？空闲时能否进 deep C-state？**服务器的「空闲能效」（energy-proportional）比峰值能效更影响账单**（§2.4）。
5. **液冷对 D3000M 意味着什么？** 14nm 级、72W TDP 的芯片**功耗密度低**，似乎「不需要液冷」；但反过来说，**低功耗密度反而适合高密度部署**——一柜塞 80 个 D3000M 节点 vs 40 个 Xeon 节点，总量可能相当，液冷反而更划算。这是反直觉的（§2.6）。
6. **D3000M 的制造碳排 vs 使用碳排，占比多少？** 14nm 成熟制程的光刻次数比 5nm 少（光刻层少），但晶圆产出低（同样 die size 一片晶圆 die 数少）；7 年服役期内，制造碳排和使用碳排哪个占大头？这决定「换新机器」是否真能减碳（§2.5）。
7. **CBAM / TCFD 对进口 CPU 和国产 CPU 的影响不对称吗？** 进口 Intel/AMD 芯片未来可能被征碳关税（Scope3 制造碳排）；国产 D3000M 在中国境内制造，**Scope3 碳排「留在国内」不触发 CBAM，但在中国双碳政策下仍要算账**——这是「绿色信创」的政策红利吗（§2.7）？
8. **14nm 落后节点在能效上是「包袱」还是「优势」？** 直觉上 14nm 漏电功耗比 5nm 大、晶体管性能差；但成熟制程的电压/频率曲线更平缓、guardband 更宽（Expert_23），降频省电的边际收益可能更高——必须画 D3000M 的「功耗-频率曲线」判断（§2.4）。
9. **国密 SM3/SM4 硬件加速在能效上加分吗？** 硬件密码（一条指令完成一轮 SM4）比软件实现省电几个数量级——这对「加密密集型负载」（VPN/网关/区块链）的 PPW 是真增益（§2.8）。
10. **D3000M 在「双碳」政策下的双重身份**：它既是「国产 CPU」（信创采购加分），又受制于「能效落后」（可能进不了高能效数据中心准入名单）。**这两股政策力量是同向还是对冲？** 这决定它在 2030 年信创采购中的真实位置（§2.7）。

这 10 个问题里，第 2/3/5/7/10 是**只有这颗芯片（在中国政策语境下）才答得出**的特异性问题——删掉「飞腾/D3000M/信创」就空转。这是本视角过「D3000M 特异性测试」的保证。

## 2. 具体分析（全部锚 D3000M 实测 + 公开论文 + 工程推理）

### 2.1 概念地基：能效的四个层级（从晶体管到机房）

在落到 D3000M 之前，先把「绿色计算」这把尺子的刻度讲清楚。能效不是一个数字，是**四个层级的嵌套账本**——从晶体管到机房，每一层有自己的指标和杠杆：

```
┌─────────────────────────────────────────────────────────────────────┐
│  层级 4: 数据中心能效    PUE = 总耗电/IT耗电    机房基础设施(冷却/UPS)│
│  ┌───────────────────────────────────────────────────────────────┐  │
│  │  层级 3: 节点能效     单节点功耗/性能    整机(含内存/磁盘/电源) │  │
│  │  ┌─────────────────────────────────────────────────────────┐ │  │
│  │  │  层级 2: 芯片能效     PPW = 性能/功耗    CPU TDP/DVFS      │ │  │
│  │  │  ┌───────────────────────────────────────────────────┐ │ │  │
│  │  │  │  层级 1: 晶体管能效  EDP=能耗×延迟²  工艺/电压/微架构│ │ │  │
│  │  │  └───────────────────────────────────────────────────┘ │ │  │
│  │  └─────────────────────────────────────────────────────────┘ │  │
│  └───────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────┘
   D3000M 直接影响: 层级1(14nm工艺) + 层级2(72W TDP/DVFS)
   D3000M 间接影响: 层级3(节点设计) + 层级4(机房PUE/政策)
```
**图 1：能效的四个层级——从晶体管到数据中心的嵌套账本。** [书-Barroso2013][论文-Raghavan2011]

**四个层级的关键指标**：

| 层级 | 指标 | 定义 | D3000M 量级 | 来源 |
|:----:|:----|:-----|:----------|:----|
| 1 晶体管 | **EDP**（Energy-Delay Product） | 能耗×延迟²，越小越好 | 受 14nm 工艺 + 2.5GHz 限 | [推测-工艺] |
| 2 芯片 | **PPW**（Performance Per Watt） | GFLOPS/W 或 ops/J | ~3–4 GFLOPS/W（FP16）| [推测-Lab外推] |
| 2 芯片 | **TDP** | 热设计功耗上限 | ~72W | [推测-E02外推] |
| 2 芯片 | **空闲功耗比** | 空载/满载功耗 | 待测（PSCI 决定）| [推测-待测] |
| 3 节点 | **节点总功耗** | CPU+内存+磁盘+电源损耗 | ~150–250W（推测）| [推测-节点设计] |
| 3 节点 | **电源转换效率** | 80Plus 钛金 ~96% | 平台工程 | [标准-80Plus] |
| 4 机房 | **PUE** | 总耗电/IT耗电 | 信创机房 1.4–2.0 | [报告-工信部] |
| 4 机房 | **WUE**（水效）| L水/kWh | — | [标准-GreenGrid-WUE] |
| 4 机房 | **CUE**（碳效）| gCO₂/kWh × PUE | 取决于电网碳强度 | [标准-GreenGrid-CUE] |

**表 A：能效四层级的指标对照。** 关键洞察：**D3000M 直接能改写的只有层级 1/2，但采购决策看的是层级 3/4**——这就是为什么「PPW 落后」可能被「机房 PUE 政策红利」对冲（§2.7）。

**Barroso 的「能量比例」定律**：Google 的数据中心研究发现，**典型服务器在 0% 负载时仍消耗满载功耗的 50% 以上**（旧服务器），这是巨大的浪费——因为真实数据中心平均利用率才 20–40% [书-Barroso2013]。**Barroso 的呼吁是：服务器必须做到「energy-proportional」——负载降到 30%，功耗也应降到 30% 左右**。这一条定律直接决定了「空闲能效」比「峰值能效」更值钱。对 D3000M 而言：**它的 DVFS / PSCI / C-state 实现得好不好，决定了它在 20–40% 利用率的真实工况下是「吃满电」还是「按比例省电」**——这是 §2.4 的核心命题。

### 2.2 D3000M 每瓦性能（PPW）实测推算与全局对标 —— 核心量化对标表

这是本视角最硬的数字，也是过「禁止裸断言」门槛的关键 artifact。

#### 算力上界回顾（来自 Lab 实测）

| 精度/算子 | 单核理论 | 8 核聚合 | 来源 |
|----------|--------:|--------:|------|
| FP32 GEMM | 9.45 GFLOPS | ~76 GFLOPS | [Lab05实测] |
| FP16 GEMM | ~36 GFLOPS | ~288 GFLOPS | [Lab01实测] FP16 3.81× |
| INT8 UDOT 点积 | ~160 GOPS | ~1.28 TOPS | [Expert_05实测] 16.9× 推算 |

#### 功耗锚点

D3000M 的 TDP 是**本视角最大的不确定性**。公开产品手册未明确披露，本视角采用三层证据：
1. Expert_02 推测 ~72W TDP [推测-E02外推]，依据是「4-wide / 8 核 / 2.5GHz / 14nm 级」的工程常识（同级别 ARM 服务器核单核约 5–10W）。
2. 同代 ARM 服务器参照：AWS Graviton2（64 核 Neoverse N1，7nm）TDP 约 80W（单节点）[报告-AWS-Graviton]；鲲鹏 920（64 核，7nm）TDP 约 160–180W [推测-业界]。
3. D3000M 是 8 核而非 64 核，且 14nm 漏电比 7nm 高，但核数少 8 倍——综合判断**单 CPU TDP 约 60–80W 量级合理**[推测-合成]。

> **诚实标注**：D3000M 的 TDP/PPW **没有 SPECPower 官方数据**。本视角所有 PPW 数字都是 [推测-依据]，依据链 = Lab 实测算力 × 推测 TDP。**真实数据必须靠 `perf`+`RAPL`（Intel）或 `cpufreq`+电流计实测**——这是本视角给采购方的第一条尽职调查建议（§5.1）。

**这张表的一号读法（对飞腾诚实）**：D3000M 的 FP16 PPW 约 **3–4 GFLOPS/W**，落后 Graviton2/3 约 **2–3 倍**，落后 Graviton4（5nm+SVE2）约 **3–4 倍**，落后消费级 Apple M2 约 **4–6 倍**。**在「单核/单芯片能效」维度，D3000M 处于 ARM 服务器光谱的中下位，比 x86 旗舰略好或持平，但显著落后同代 ARM 服务器。** 这与它在算力维度（Expert_21）落后 Graviton3/4 两代的判断**完全一致**——PPW 落后本质是「算力落后 + 工艺落后」的双重叠加。

**二号读法（反方，给飞腾的辩护）**：上表用「FP16 GEMM 峰值算力」做 proxy，**严重高估了对所有 CPU 的真实负载能效**。真实服务器负载（Web/数据库/中间件）远达不到 GEMM 峰值，且不同架构在「非 GEMM 负载」下的表现差异极大。**SPECPower（SPEC 整数服务器负载）才是更公平的能效基准**——可惜 D3000M 无官方 SPECPower 数据。若按「整数负载 PPW」估，D3000M 与 Graviton2 的差距可能从 2–3 倍缩小到 1.5–2 倍（因为整数负载对工艺/微架构的敏感度低于 SIMD 密集负载）。**这是 [推测-依据]，不是实测。**

**三号读法（绝对值 vs 相对值的陷阱）**：PPW 是**相对值**——「4 GFLOPS/W 落后 10 GFLOPS/W 两倍」听起来很惨，但如果业务需要的总算力固定（比如 1 TFLOPS），那么 D3000M 要 4 颗、Graviton4 要 1 颗——**总功耗反而可能 D3000M 更低**（4×72=288W vs 1×150=150W…等等，这里 Graviton4 反而省）。**所以 PPW 落后基本等同于「完成固定任务更耗电」**——除非算力差距小于功耗差距。对 D3000M 而言，算力落后 Graviton4 约 17 倍（288 vs 5000 GFLOPS），功耗只低约 2 倍（72 vs 150W）——**所以完成同等总算力任务，D3000M 方案总功耗远高于 Graviton4**。这是 PPW 落后的硬代价。

> **二号判断（PPW 维度）**：D3000M 的每瓦性能**落后主流 ARM 服务器 2–4 倍**，根因是
> 「14nm 工艺 + 无 SVE/BF16 的算力代差 + 4-wide 保守微架构」三重叠加。
> 在「完成固定任务的总能耗」维度，D3000M 方案比 Graviton3/4 方案**更耗电**——
> 这是「低 TDP = 绿色」直觉的最大反例。**低 TDP 不等于绿色，PPW 才是。**

### 2.3 「低 TDP 的假象」——为什么不能只看绝对功耗

这是本视角必须讲清楚的反直觉命题，也是盲区 §4 的核心论据。

**直觉陷阱**：「D3000M 只有 72W，Xeon 是 400W，所以 D3000M 更省电更绿。」

**真相**：要看「完成单位任务的总能耗」，而非「峰值功耗」。举例——假设要完成一个 1000 GFLOPS·秒 的计算任务（比如一次中等规模科学计算）：
- D3000M：算力 288 GFLOPS，TDP 72W → 需 1000/288 ≈ 3.47 秒，总能耗 ≈ 3.47 × 72 ≈ **250 J**。
- Intel Xeon 8480：算力 8000 GFLOPS（含 AMX），TDP 400W → 需 0.125 秒，总能耗 ≈ 0.125 × 400 ≈ **50 J**。

**结论**：虽然 Xeon 峰值功耗是 D3000M 的 5.5 倍，但因为它快 28 倍，**完成同一个任务反而省 5 倍的电**。这就是 EDP（Energy-Delay Product）的本质——**「快就是省」在计算能效里是成立的**[论文-Gonzalez1996-EDP]。

**但这道算式有两个边界条件**（给飞腾的辩护）：
1. **任务必须是「可并行/可加速」的**。如果任务受限于 Amdahl 定律的串行部分，或者受限于内存带宽（SpMV、图计算），那么「快 CPU」的算力用不上——此时 D3000M 的低 TDP 反而占优（见 Expert_09 Roofline 的带宽 bound 区）。**这是 D3000M 在「访存密集型 + 低并发」负载下的能效甜区**。
2. **必须考虑「空闲时间」**。如果任务是「偶尔来一下」的在线服务（如 Web 请求、查询），那么峰值算力用不上，**大部分时间 CPU 空闲**——此时「空闲功耗」主导账单。如果 D3000M 空闲能压到 10W、Xeon 空闲仍有 100W，那么在低负载场景 D3000M 反而更省。**这取决于 DVFS/C-state 实现（§2.4）。**

**给采购方的判断框架**（这是本视角的实战交付物）：

| 负载类型 | 峰值算力重要吗？ | 空闲功耗重要吗？ | D3000M 能效定位 |
|---------|:-------------:|:-------------:|:-------------|
| HPC / 科学计算（持续满载） | ✅ 极重要 | ❌ 不重要 | ❌ PPW 落后，总能耗高 |
| AI 训练（GPU 为主，CPU 管控） | ⚠️ 一般 | ⚠️ 一般 | ⚠️ 中性，看管控效率 |
| Web / 微服务（突发负载） | ❌ 不重要 | ✅ 极重要 | ✅ 低 TDP + 若空闲能效好则占优 |
| 数据库 OLTP（中等持续） | ⚠️ 中等 | ⚠️ 中等 | ⚠️ 看具体负载 |
| 边缘 / IoT（低功耗场景） | ❌ 不重要 | ✅ 极重要 | ✅ 低 TDP 是天然优势 |
| 国密网关 / 加密（SM3/SM4 密集） | ⚠️ 硬件加速重要 | ⚠️ 中等 | ✅ 硬件国密省电几个数量级（§2.8） |

**表 C：不同负载类型下 D3000M 的能效定位。** 关键洞察：**D3000M 不是「全面落后」，而是在「持续满载计算」场景落后、在「低功耗边缘 / 加密 / 访存密集」场景有结构性优势**。这正是信创采购（多为政务/办公/Web/数据库，非 HPC）能接受 D3000M 的能效理由。

### 2.4 DVFS、PSCI 与「能量比例」——服务器的能效命门

前文反复提到「空闲能效比峰值能效更值钱」。本节落到 D3000M 的电源管理能力。

**DVFS（动态电压频率调节）的物理原理**：CMOS 动态功耗 `P = α · C · V² · f`，其中 V 是电压、f 是频率。**功耗与电压平方成正比**——降电压 20%，功耗降 36%。所以「降频」必须配合「降电压」才能真正省电（只降频不降电压省不了多少）。**DVFS 的核心收益来自「降压」而非「降频」**[论文-Pering2003-DVFS]。

**P-states（性能态）/ C-states（空闲态）的层级**：

```
  P-states (运行态, 性能-功耗档位)         C-states (空闲态, 睡眠深度)
  ┌──────────────────────┐                 ┌──────────────────────────┐
  │ P0: 最高频/最高压(Turbo)│                 │ C0: 活跃(正在执行)         │
  │ P1: 标称(2.5GHz@D3000M)│  ←── 负载高      │ C1: 自动停钟(Halt,~1cyc唤醒)│
  │ P2..Pn: 逐级降频降压   │                 │ C2: 停钟+flush(几cyc唤醒)  │
  │   每档约省 10-30% 功耗 │                 │ C3: 关PLL(几十cyc唤醒)     │
  └──────────────────────┘                 │ C6/C7: 关电压(微秒级唤醒)  │
       ↑ cpufreq governor                     │ C8+: 深睡眠(毫秒级唤醒)   │
       (performance/powersave/ondemand)      └──────────────────────────┘
                                                  ↑ 每深一档省电 10-50%
                                                    但唤醒延迟↑(影响响应)
```
**图 2：P-states 与 C-states 层级。** [论文-Pering2003-DVFS][官方-ACPI]

**ARM 的电源管理框架 = PSCI（Power State Coordination Interface）**[官方-ARM-PSCI]：PSCI 是 ARM 定义的标准接口，让 OS（通过 cpufreq/cpuidle 驱动）请求「进/出某个 P/C state」。飞腾作为 ARMv8.4 实现，**PSCI 是标配**（EL3 固件 TF-A 实现 BL31 的 PSCI 服务）。关键问题不是「PSCI 有没有」，而是**「飞腾实现了几级 P-state、几级 C-state、per-core DVFS 支不支持」**——这些决定 D3000M 的「能量比例」曲线好不好。

**服务器场景的能效优化空间（D3000M 的杠杆）**：

| 电源管理特性 | 对能效的影响 | D3000M 实现推测 | 来源 |
|:----------|:----------|:-------------|:----|
| **per-core DVFS**（每核独立调压） | 高（避免「一个核忙全芯片高压」） | ⚠️ 大概率不支持（需独立 VRM/PMIC，成本高）| [推测-平台] |
| **cluster-level DVFS**（簇级调压） | 中 | ✅ 大概率支持（ARM 标配）| [推测-PSCI标配] |
| **deep C-state（C6/C7，关电压）** | 极高（空闲功耗主导） | ⚠️ 待证（需 retention flip-flop 设计）| [推测-待测] |
| **Turbo Boost（短时超频）** | 中（突发负载） | ⚠️ D3000M 锁频 2.5GHz，大概率无 Turbo | [实测-锁频] |
| **HWP / OS vs 固件管电源** | 中（响应速度） | ⚠️ 待证 | [推测] |

**表 D：D3000M 电源管理特性推测。**

**D3000M 特异性判断**：实测发现 D3000M 在 `governor=performance` 下**锁频 2.5GHz** [实测-Lab]，这意味着它**大概率没开 DVFS 动态调节**（至少在实验环境）。这对能效是**不利信号**——锁频意味着无论负载高低都吃满压满频的功耗，违反「能量比例」定律。**但这是实验环境配置，不代表产品不支持**——真实信创服务器 BIOS 里应该有 `powersave` / `ondemand` / `schedutil` governor 可选 [推测-产品配置]。**这是 §5.1 尽职调查的关键一条：要求供应商现场演示 D3000M 在 10%/30%/70%/100% 负载下的功耗曲线，验证 DVFS 是否真的在工作。**

**「能量比例」曲线的两种理想形态**：

```
  功耗(%满载)
  100%┤ ●━━━━━━━━━━━━━━━━  ← 理想: 能量比例(线性, y=x)
      │  ╲
   70%┤   ╲━━━━━━━━━━━━●   ← 优秀服务器(Graviton/现代Xeon)
      │    ╲
   30%┤     ╲━━━━━━━━●     ← D3000M 目标(若DVFS开)
      │      ╲
   10%┤       ╲     ●━━━━  ← 差: 旧服务器(空载仍50%+, D3000M若锁频)
      │        ╲ ●
    0%└─────────●─────────→ 负载(%)
      0%   30%   50%   70%  100%
```
**图 3：能量比例曲线——理想 vs 现实。** [书-Barroso2013]

**关键洞察**：**D3000M 若锁频（无 DVFS），它的能量比例曲线会接近「平的」——空载也吃满电**，这是最差的能效形态（旧服务器特征）。**若开了 DVFS + deep C-state，它可以逼近 Graviton 的能量比例曲线**——这才是它「低 TDP」优势能兑现的前提。**所以 D3000M 的「绿色」叙事，全部押注在电源管理实现上**——这是飞腾固件/平台团队（Expert_18）必须交付的工程。

### 2.5 制造碳排 vs 使用碳排——LCA 生命周期评估

前四节都在算「运行时电费」（Scope2）。但 GHG Protocol 的 Scope3 要求算**「制造这颗芯片排了多少碳」**——这是常被忽视的大头。

**制造碳排的惊人占比**：MIT 的 Gupta et al. 2021 年的研究发现，**一颗芯片的制造碳排可以占其生命周期总碳排的 60–80%**[论文-Gupta2021-Carbon]，尤其是先进制程（5nm/3nm）——光刻次数多、EUV 耗电惊人、晶圆产出低。具体数字：
- 一片 5nm 晶圆制造耗电约 700+ kWh（台积电数据），按电网碳强度 0.5 kgCO₂/kWh 算，**每片晶圆约 350 kgCO₂** [报告-TSMC-CDP]。
- 一颗 5nm 大芯片（如 A14，~90mm²）分摊约 5–10 kgCO₂ 制造碳排 [论文-Gupta2021]。
- 而**使用碳排**：一颗手机芯片用 3 年，每天充一次电（~10Wh），3 年约 11 kWh → 约 5.5 kgCO₂。**制造碳排 ≈ 使用碳排，甚至更多**。

**D3000M 的 LCA 拆解（推测）**：

| LCA 阶段 | 估算 | 占比 | 依据 |
|---------|------|:---:|------|
| **制造（光刻/封装/测试）** | ~10–30 kgCO₂/CPU | **40–60%** | 14nm 光刻层少（~40 层 vs 5nm ~80 层），但晶圆产出低（14nm die 密度低），合成估算 [推测-Gupta外推] |
| **运输（供应链）** | ~1–3 kgCO₂ | ~5% | 国产短链（国内制造→国内部署），运输碳排低 [推测-短链优势] |
| **使用（7 年，平均 50% 负载，0.5 kgCO₂/kWh）** | ~72W × 0.5 × 8760h × 7yr × 0.5 ≈ ~1100 kWh → ~550 kgCO₂ | **35–55%** | [推测-使用计算] |
| **回收/报废** | ~5–15 kgCO₂（或负值，若回收硅） | ~5% | [推测] |
| **总计** | ~600–800 kgCO₂ | 100% | [推测-合成] |

**表 E：D3000M 生命周期碳排（LCA）推测拆解。** [推测-全部，依据公开论文外推]

**关键诚实点**：上表全部是 [推测-依据]，**真实 LCA 必须由飞腾或第三方做 ISO 14040/14044 标准 LCA 报告**——这是 §5.1 尽职调查的关键。但量级判断有参考价值：

**一号 LCA 洞察：14nm 成熟制程的「制造碳排优势」**。14nm 比 5nm 光刻层少约一半，**单颗芯片制造碳排可能比 5nm 同面积芯片低 30–50%** [论文-Gupta2021]。这意味着——**D3000M 在「制造碳排」这一项上，反而比 Intel Xeon（Intel 7，10nm）或 AMD EPYC（5nm）有结构性优势**。这是「落后工艺」的意外红利（但被「使用碳排高（能效落后）」部分抵消）。

**二号 LCA 洞察：国产短链的「运输碳排优势」**。进口 Intel/AMD 芯片要跨太平洋运输（空运/海运），国产 D3000M 在国内制造→国内部署，**供应链运输碳排低一个数量级** [推测-短链]。更重要的是**「Scope3 可追溯性」**——国产供应链的碳排数据更易获取（国内电网碳强度、国内工厂披露），而进口芯片的 Scope3 数据常不透明（盲区 §4）。

**三号 LCA 洞察：使用碳排取决于服役时长 + 能效**。D3000M 服役 7 年，**使用碳排约占总碳排 35–55%**——这一块完全由 PPW（§2.2）和 PUE（§2.6）决定。**如果 D3000M PPW 落后 Graviton3 两倍，它的使用碳排就是 Graviton3 的两倍**——这会吃掉制造碳排的优势。**所以「换 D3000M 是否减碳」取决于「制造碳排省下的」能否抵过「使用碳排多花的」**——这是 §2.7 净碳账的核心。

**「换新机器是否减碳」的悖论**：很多人以为「换更新的、更省电的机器一定减碳」。**LCA 视角的答案是「不一定」**——如果旧机器还有剩余寿命，提前报废它意味着「白白浪费了已付的制造碳排」。**只有当新机器的使用碳排节省（7 年累计）> 旧机器剩余使用碳排 + 新机器制造碳排，换新才减碳**[论文-Gupta2021]。对 D3000M 替换旧 x86 服务器：若旧 x86 还能跑 3 年、D3000M 能效只略好，则**换新可能 3 年内都不减碳**——这是 ESG 报告里常被操纵的盲点。

### 2.6 数据中心 PUE 与高密度部署——液冷的悖论

**PUE 的定义与现状**：

```
  PUE = 数据中心总耗电 / IT设备耗电
       ┌─────────────────────────┐
       │  冷却(空调/风扇/液冷泵)   │ ← PUE > 1 的来源
       │  供电(UPS/变压器损耗)     │
       │  照明/其他               │
       └─────────────────────────┘
       ┌─────────────────────────┐
       │  IT设备(服务器/网络/存储) │ ← PUE 分母
       └─────────────────────────┘
```

**业界 PUE 基准**（[报告-Uptime-Institute][报告-工信部]）：

| 机房类型 | 典型 PUE | 说明 |
|---------|:--------:|------|
| 老旧小型机房 | 2.0–2.5 | 风冷，效率低 |
| 普通企业机房 | 1.6–1.8 | 风冷 + 行级空调 |
| 大型云数据中心 | 1.3–1.5 | 优化风冷 + 气流隔离 |
| 超大规模（Google/Facebook）| 1.1–1.2 | 自然冷却 + AI 调优 |
| **液冷机房** | **1.05–1.2** | 冷板/浸没，冷却能耗极低 |
| **中国政策要求（新建大型）** | **≤1.3** | 工信部 2021 年 [报告-工信部] |
| **中国政策要求（东部新建）** | **≤1.25** | 更严，东部能耗双控 |

**表 F：数据中心 PUE 基准。** 关键洞察：**中国政策对新建数据中心 PUE 有硬约束（≤1.3，东部≤1.25）**——达不到不准建。这是「绿色信创」的政策杠杆。

**信创机房用 D3000M 的 PUE 现实**：

**直觉判断**：D3000M TDP 低（72W），散热量小，机房冷却压力小，PUE 应该更好。

**真实情况（要算「密度 vs 总量」）**：
- **场景 A（低密度部署）**：一柜塞 10 个 D3000M 节点（总 IT 负载 ~720W），风冷足够，PUE 可能 1.4–1.6（小机房冷却效率低）。**但总算力只有 2.88 TFLOPS**——性能不够。
- **场景 B（高密度部署）**：要达到与 Xeon 相当的算力（~8 TFLOPS），需要 ~28 个 D3000M 节点（28 × 288 GFLOPS），总 IT 负载 ~2000W——**比一台 8-socket Xeon（~800W）还高**。此时冷却压力上升，PUE 可能恶化到 1.5–1.7。

**关键悖论**：**D3000M 的低 TDP 让单节点易冷却，但「PPW 落后导致需要更多节点」反而推高总 IT 负载**——PUE 可能不降反升。这是「低 TDP = 绿色」直觉的第二个反例（第一个是 §2.3 EDP）。

**液冷的「反直觉机会」**：

虽然 D3000M 单节点功耗低（72W），**液冷对它的边际收益似乎不大**（风冷就够了）。但换个角度——**液冷让机柜密度可以做得极高**。如果用浸没式液冷，一柜可以塞 80+ 个 D3000M 节点（风冷只能塞 20–30 个），**总柜算力可以达到风冷 Xeon 机柜的水平**，且 PUE 压到 1.1 以下。

**D3000M 适合液冷高密度部署的论据**：
1. **低单芯片功耗 → 低功耗密度 → 液冷散热余量极大**，可以用「便宜」的冷板方案（不需浸没）。
2. **无 HBM/无大 GPU → 节点设计简单**，主板紧凑，适合高密度机柜。
3. **信创机房 PUE 政策压力** → 液冷是达到 ≤1.25 PUE 的最直接路径。
4. **国产液冷供应链成熟**（曙光、阿里、字节都在推国产液冷方案）→ 信创配套齐全。

**液冷的两类技术（IEC 标准）**：

| 液冷类型 | 原理 | PUE 目标 | D3000M 适用性 | 成本 |
|---------|------|:--------:|:----------:|:----:|
| **冷板（Cold Plate）** | 导热板贴芯片，冷却液循环 | 1.2–1.3 | ✅ 高（低功耗密度，冷板够用） | 中 |
| **浸没（Immersion）** | 整节点泡在介电液里 | 1.05–1.15 | ✅ 高（节点简单适合） | 中高 |
| **相变浸没** | 介电液沸腾相变 | 1.05 | ⚠️ 过度（D3000M 功耗太低不值得） | 高 |
| **风冷（参照）** | 空气对流 | 1.4–1.6 | ✅ 够用（低 TDP） | 低 |

**表 G：液冷技术对 D3000M 的适用性。** [标准-IEC-液冷]

**三号判断（PUE 与液冷）**：D3000M 在**风冷场景**的 PUE 优势不大（因为 PPW 落后推高总 IT 负载）；
但在**液冷高密度部署**场景，它的「低功耗密度 + 简单节点设计」反而成为优势——
**信创机房若走「国产液冷 + D3000M 高密度机柜」路线，可以同时满足「国产化」和「PUE≤1.25」双政策要求**。
**这是 D3000M 在绿色合规维度最被低估的机会**——液冷让「低 TDP」从「算力劣势的副产品」变成「密度部署的结构性优势」。

### 2.7 双碳政策、CBAM、TCFD——「绿色信创」的政治经济学

这是本视角最尖锐也最「中国特异性」的一节。

**三股政策力量的交汇**：

**① 中国「双碳」对数据中心的硬约束**：
- **2030 碳达峰 / 2060 碳中和**（习近平 2020 年联合国宣布）。
- 工信部 2021 年《新型数据中心发展三年行动计划》要求：**新建大型/超大型数据中心 PUE≤1.3，东部地区≤1.25** [报告-工信部]。
- **「东数西算」**工程：把数据中心从东部（电贵碳高）迁到西部（电便宜、可再生能源多）。**这对 CPU 的要求是「能效适配西部电网」**——西部可再生能源（风电/光伏）波动大，CPU 需要支持「跟随可再生能源出力的弹性调度」。
- **能耗双控**：地方政府有能耗总量+强度双指标，数据中心是耗电大户，常被纳入配额管理。**信创数据中心若能耗超标，可能被限电/关停**。

**② 欧盟 CBAM（碳边境调节机制）对进口芯片的影响**：
- CBAM 2023 年立法，2026 年全面开征碳关税 [标准-EU-CBAM]。
- 覆盖行业：钢铁、水泥、化肥、铝、电力、氢——**目前不直接覆盖芯片**，但**未来可能扩展到电子产品**。
- 即使不直接征芯片关税，**进口服务器的钢铁/铝外壳、电源铜排已覆盖**——进口服务器整体碳成本上升。
- **对 D3000M 的不对称影响**：国产 CPU 在中国境内制造，**Scope3 制造碳排「留在国内」不触发 CBAM**（出口才触发）。但**进口 Intel/AMD 芯片进入欧盟市场时，其制造碳排可能被征碳关税**——这是国产芯片在欧盟市场的潜在价格优势（如果飞腾未来出口）。

**③ TCFD（气候相关财务披露）对上市公司的影响**：
- TCFD 框架要求上市公司披露 Scope1/2/3 碳排、气候风险、转型计划 [标准-TCFD]。
- 中国证监会 2024 年要求部分上市公司强制披露 ESG 报告（含碳排）。
- **采购方（尤其是国企/上市公司）选 CPU 时，会要求供应商提供碳排数据**——D3000M 若能提供 LCA 报告，是合规加分；若提供不了，可能被排除。

**「绿色信创」的双重身份（判断第 10 题的收口）**：

D3000M 在双碳政策下面临**两股方向相反的力量**：

| 政策力量 | 对 D3000M 的影响 | 方向 |
|---------|:-------------|:----:|
| 信创采购（国产化要求） | ✅ 加分（国产 CPU 政策红利） | 正向 |
| 数据中心 PUE 配额（≤1.3） | ⚠️ 中性（取决于部署方案，见 §2.6） | 中性 |
| 能效准入门槛（部分省市要求 CPU 能效达一定等级） | ❌ 可能扣分（PPW 落后可能进不了准入名单） | 负向 |
| CBAM（若出口欧盟） | ✅ 加分（国产短链碳排低） | 正向 |
| TCFD 披露要求 | ⚠️ 取决于飞腾能否提供 LCA 数据 | 待定 |

**净碳效应分析（完成单位任务的「全链路碳账」）**：

这是回答「信创机房用 D3000M vs 用 Intel，哪个净碳更低」的核心算式。

```
  净碳 = 制造碳排 + 运输碳排 + 使用碳排 + 报废碳排

  │ Xeon 8480: 制造~40kg(5nm多) + (1e15/8e12)×400W×1.5×0.5×8760│

  │          ≈ 40 + 329 ≈ 369 kgCO₂/年                         │ [推测-计算]
  └──────────────────────────────────────────────────────────┘
```

**这个算式的诚实结论**：**完成同等总算力任务，D3000M 的净碳是 Xeon 的约 4 倍**——因为 PPW 落后 5 倍（算力差 28 倍 / 功耗差 5.5 倍）的代价，远超制造碳排省下的 20kg。**这是「低 TDP = 绿色」直觉的终极反例**。

**但这个算式有两个「信创修正项」**（给 D3000M 的辩护）：
1. **信创机房的任务往往是「固定规模的政务/办公负载」，不是「追算力峰值」**。如果业务只需要 500 GFLOPS（D3000M 8 核绰绰有余），那么 D3000M 用 1 颗（72W）vs Xeon 用 0.06 颗（但实际要配 1 颗，400W）——**此时 D3000M 反而省电**。**所以「净碳谁低」取决于「业务算力需求是否匹配 D3000M 的算力档位」**。
2. **信创采购的「国产化」是硬约束，能效是软约束**。即使 D3000M 净碳更高，如果政策要求必须用国产 CPU，那么「绿色」比较的对象不是「Xeon」，而是「另一颗国产 CPU」（如鲲鹏）。**在国产 CPU 内部，D3000M vs 鲲鹏 920 的 PPW 差距（4 vs 6–9）比 vs Xeon 小**——这才是公平比较。

> **五号判断（绿色合规）**：D3000M 在「绝对能效/净碳」维度落后主流服务器 CPU，
> 但在「中国双碳 + 信创 + CBAM」的政策框架下，它有**三重不对称优势**：
> ① 国产短链碳排低 + 14nm 制造碳排低（Scope3 优势）；
> ② 信创采购政策红利（国产化硬约束）；
> ③ 液冷高密度部署适配 PUE 政策（§2.6）。
> **「绿色信创」是 D3000M 真正能打的牌，但前提是飞腾必须补齐 LCA 数据 + DVFS 能效优化 + 液冷方案**——
> 否则「能效落后」会吃掉「政策红利」。**这是绿色视角给飞腾的核心建议（§3）。**

### 2.8 国密硬件加速的能效红利——被忽视的绿色加分项

D3000M 实现了 v8.4 的 **SM3/SM4 国密指令**（`SM3SS1`/`SM4E` 等，[实测-扩展专题]）。这在 Expert_12（安全）视角是合规必备，但在绿色视角是**被严重低估的能效加分项**。

**硬件密码 vs 软件密码的能效差距**：

| 算法 | 软件实现（通用指令）| 硬件指令（D3000M）| 加速比 | 能效提升 |
|------|-------------------|------------------|:------:|:-------:|
| SM3（哈希）| ~1–3 Gbps @多核 | ~5–10 Gbps [Lab07推测] | ~3–5× | **~5–10×（省电）** |
| SM4（分组密码）| ~0.5–2 Gbps | ~5–10 Gbps [Lab07推测] | ~5–10× | **~10–20×（省电）** |
| AES（参照，v8.0）| ~0.5 Gbps（软）| ~5 GB/s [Lab07] | ~10× | ~10–20× |
| SHA-256（参照）| ~0.3 Gbps（软）| ~3 GB/s [Lab07] | ~10× | ~10–20× |

**表 I：硬件密码 vs 软件密码的能效对比。** [推测-Lab07+ARM文档]

**绿色视角的意义**：对于「加密密集型负载」（国密 VPN 网关、SSL/TLS 终端、区块链节点、加密存储），**用硬件 SM3/SM4 指令比软件实现省电 5–20 倍**。这意味着——**D3000M 在「国密网关」这一信创特有负载上，PPW 可能反超进口 CPU（进口 CPU 无 SM3/SM4 硬件，只能软件模拟或用通用 AES 替代）**。

**这是一个 D3000M 特异性的绿色优势**：删掉「飞腾/国密/信创」，任何通用 ARM/x86 CPU 都不会有「SM3/SM4 硬件 vs 软件」的能效对比——**这是只有 D3000M（在中国国密合规场景）才答得出的绿色命题**。信创政务云大量部署国密网关，**D3000M 的硬件国密是它在「加密网关」这一细分场景的能效护城河**。

### 2.9 五个必答尖锐判断的逐条收口

回扣任务要求的 5 个尖锐判断：

**判断 1：D3000M 每瓦性能实测/推测，vs Intel/AMD/Graviton/鲲鹏量化对标？**
答（见 §2.2 表 B）：D3000M FP16 PPW 约 **3–4 GFLOPS/W** [推测-Lab外推]，落后 Graviton2/3 约 **2–3 倍**、落后 Graviton4 约 **3–4 倍**、落后 Apple M2 约 **4–6 倍**，与 Intel Xeon（含 AMX）持平或略好、与 AMD EPYC 持平或略差。**根因：14nm 工艺 + 无 SVE/BF16 算力代差 + 4-wide 保守微架构三重叠加。** 无 SPECPower 官方数据，需采购方现场实测（§5.1）。

**判断 2：信创机房用 D3000M 的 PUE 现实，净碳效应？**
答（见 §2.6 + §2.7 图 4）：**风冷场景 PUE 优势不大**（PPW 落后推高总 IT 负载）；**液冷高密度部署是结构性机会**（低功耗密度 + 简单节点设计适配国产液冷）。**净碳效应：完成同等总算力任务，D3000M 净碳约是 Xeon 的 4 倍**（PPW 落后代价）；**但信创场景业务算力需求往往匹配 D3000M 档位，此时 D3000M 反而省电**。**「绿色信创」成立的前提是飞腾补齐 LCA + DVFS + 液冷方案。**

**判断 3：D3000M 的 DVFS/电源管理能力（ARM PSCI），服务器场景能效优化空间？**
答（见 §2.4 表 D）：PSCI 是 ARM 标配（飞腾必然实现 BL31），但**实验环境锁频 2.5GHz（无 DVFS）是不利信号**[实测-Lab]。关键待证项：**per-core DVFS、deep C-state（C6/C7）、Turbo Boost**。**D3000M 的「绿色」叙事全部押注在电源管理实现上**——若开 DVFS + deep C-state，可逼近 Graviton 的能量比例曲线；若锁频，则空载也吃满电，是最差形态。**这是飞腾固件/平台团队（Expert_18）必须交付的工程。**

**判断 4：液冷普及——14nm 级 D3000M（功耗较低）是否反而适合高密度部署？**
答（见 §2.6 表 G）：**是的，这是 D3000M 在绿色维度最被低估的机会。** 低功耗密度 → 冷板液冷够用（不需昂贵浸没）；无 HBM/大 GPU → 节点简单紧凑适合高密度机柜；国产液冷供应链成熟 → 信创配套齐全。**「国产液冷 + D3000M 高密度机柜」可同时满足国产化 + PUE≤1.25 双政策。** 这是把「低 TDP」从「算力劣势副产品」变成「密度部署结构性优势」的钥匙。

**判断 5：双碳政策——国产 CPU 在「绿色信创」下的双重优势/劣势？**
答（见 §2.7 表 H）：**双重身份——信创采购/CBAM 正向，能效准入门槛负向，TCFD 取决于 LCA 数据。** 三重不对称优势：① 国产短链 + 14nm 制造碳排低（Scope3）；② 信创政策红利；③ 液冷适配 PUE 政策。**前提是补齐 LCA + DVFS + 液冷，否则能效落后吃掉政策红利。** 「绿色信创」是 D3000M 真正能打的牌。

### 2.10 可运行 artifact：D3000M 能效探测脚本

提供一段可在 D3000M 上实测「能效画像」的脚本。它不依赖特权（普通用户可跑），用于：
1. 探测 cpufreq governor 与可用 P-state 档位（验证 DVFS 是否启用）；
2. 探测 cpuidle 可用 C-state（验证 deep sleep 支持）；
3. 粗测「满载功耗 / 空载功耗比」（能量比例曲线的一个点）；
4. 粗测 GEMM 的「每瓦性能」（用 `perf` 能耗计数器或时间推算）。

```bash
#!/bin/bash
# energy_probe.sh —— D3000M 能效画像探测（普通用户可跑大部分，部分需 root）
# 用法: bash energy_probe.sh
# 依赖: /sys/devices/system/cpu/cpufreq, cpuidle, perf(可选)

echo "===== D3000M 能效画像探测 ====="

echo ""
echo "[1] cpufreq governor（电源策略）:"
for c in /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor; do
    cat "$c" 2>/dev/null && echo "  当前 governor"
done
echo "  可选 governor:"
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_available_governors 2>/dev/null
echo "  （performance=锁频满载, powersave=最低频, ondemand/schedutil=动态）"

echo ""
echo "[2] 可用 P-state 频率档位（DVFS 证据）:"
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_available_frequencies 2>/dev/null
echo "  （若只有一档=锁频无DVFS; 多档=DVFS启用）"

echo ""
echo "[3] cpuidle C-state（空闲态深度）:"
for s in /sys/devices/system/cpu/cpu0/cpuidle/state*/; do
    name=$(cat "${s}name" 2>/dev/null)
    dis=$(cat "${s}disable" 2>/dev/null)
    echo "  ${name}: disable=${dis}"
done
echo "  （C0=活跃, C1=停钟, C3=关PLL, C6=关电压; 档位越多越省电）"

echo ""
echo "[4] 能耗计数器（RAPL/arm64 cntr, 需 root）:"
if [ -r /sys/class/powercap/intel-rapl:0/energy_uj ]; then
    echo "  (Intel RAPL, D3000M 大概率无)"
fi
ls /sys/devices/arm_event* 2>/dev/null && echo "  (arm64 PMU 能耗计数)"
echo "  [需 root] 可用 perf stat -e power/energy/ ./gemm 测每瓦性能"

echo ""
echo "[5] 粗测能量比例（满载 vs 空载耗时差, 需 root 测功耗）:"
echo "  满载: taskset -c 0 dd if=/dev/urandom bs=1M count=1000 2>/dev/null | openssl sm3 > /dev/null"
echo "  空载: sleep 5"
echo "  [需 root + 功率计] 分别测两段功耗, 比值 = 能量比例的一个采样点"
echo "  理想: 空载功耗 < 30% 满载（energy-proportional）"

echo ""
echo "[6] 提示: 完整 PPW 实测需功率计 + perf:"
echo "  sudo perf stat -e power/energy-cores/ ./your_workload"
echo "  PPW = 算力(GFLOPS) / 平均功耗(W)"
```

**这个脚本在 D3000M 上跑，能区分三种情况**：
- **governor=performance + 单一频率档 + 无 C6** → 锁频无 DVFS，能效形态差（旧服务器特征）。**这是 RAS/绿色视角最怕的配置。**
- **governor=ondemand/schedutil + 多频率档 + 有 C6/C7** → DVFS + deep sleep 启用，能效形态好。**这是 D3000M「绿色」叙事成立的前提。**
- **能耗计数器可用** → 可直接测 PPW，验证 §2.2 的推测值。

**配套的能效实测 SOP（需 root + 功率计）**：在 10%/30%/50%/70%/100% 五个负载档（用 `cgroup` 限 CPU 或 `stress-ng --cpu-load`）分别测功耗，画出 D3000M 的「能量比例曲线」（对标图 3）。**这条曲线的斜率是判断 D3000M 是否「绿色」的最直接证据**——比读 TDP 规格靠谱得多。**这是本视角给飞腾和采购方共同的可操作建议。**

> **六号判断（方法论级）**：评估 D3000M 的绿色计算能力，**不要只看 TDP 规格，要画能量比例曲线 + 测各负载档 PPW**。
> 飞腾若能提供 10–100% 负载的功耗曲线 + SPECPower 等效能耗数据，则「绿色」可信度立即上一个台阶；
> 若只有 TDP 数字，则任何「绿色」宣传都是空谈。**这条 SOP 是绿色视角给飞腾和采购方共同的可操作交付物。**

## 3. 设计决策评估：飞腾哪些决策认可 / 哪些该改

**认可的决策**：
1. **低 TDP 设计（~72W）**——虽然 PPW 落后，但低 TDP 本身在「散热/供电配额/边缘部署」场景是结构性优势。这是它区别于「冲 400W」的 x86 旗舰的差异化定位，**不该为了追算力把 TDP 顶上去**（那样会丧失部署友好性）。
2. **实现 SM3/SM4 国密硬件指令**——这是 D3000M 在「国密网关」场景的能效护城河（§2.8），省电 5–20 倍。这是进口 CPU 给不了的绿色加分。
3. **ARM 基座（PSCI 标配）**——ARM 的标准电源管理框架是 D3000M 能效优化的地基（vs 自研 ISA 要重做电源管理）。
4. **14nm 成熟制程**——从 LCA 看，14nm 制造碳排比 5nm 低 30–50%（光刻层少），这是「落后工艺」的意外绿色红利（代价是使用碳排高，但制造碳排省下是真实的 Scope3 优势）。

**该改的决策（按优先级）**：
1. **【最高优先】默认启用 DVFS + deep C-state**：实验环境锁频 2.5GHz [实测] 是能效自杀。**BIOS 默认应设 `schedutil` governor + 启用 C6/C7**，让 D3000M 在低负载时真正降功耗。这是兑现「能量比例」曲线的工程前提，零硬件成本。
2. **【最高优先】发布官方能效数据**：SPECPower（或等效能耗基准）+ 10–100% 负载功耗曲线 + LCA 碳排报告。**「没有数据」比「数据不好」更致命**——采购方无法做 ESG 尽职调查就会排除飞腾。这是零技术成本的文档工程，ROI 最高（对标 RAS 视角 §3 的 P0 建议）。
3. **【高优先】开发「国产液冷 + D3000M 高密度机柜」参考设计**：把「低功耗密度」变成「密度部署卖点」。与曙光/阿里/字节国产液冷生态协同，提供 PUE≤1.2 的整柜方案。**这是把 §2.6 的结构性优势产品化的关键。**
4. **【高优先】支持 per-core DVFS**（下一代 D4000）：当前推测 D3000M 大概率不支持 per-core DVFS（需独立 VRM/PMIC）。下一代应补——服务器「一核忙全芯片高压」的浪费靠 per-core DVFS 消除。
5. **【中优先】提供 TCFD/CBAM 合规数据包**：为采购方（国企/上市公司）提供 Scope1/2/3 碳排数据、LCA 报告、国产短链证明。这是「绿色信创」政策变现的钥匙。
6. **【前瞻】下一代 D4000 走「算力提升优先于 TDP 提升」路线**：D4000 应该补 BF16/I8MM/SVE（Expert_21）来提升算力，**而不是靠堆核/提频冲 TDP**——只有 PPW 上去了，「低 TDP」才是真绿色，否则低 TDP 只是「少干活」的假象。

## 4. 这一视角的盲区与反方（诚实段，强制）

> 宪法 §4.3 第 2 条要求：敢说这一视角看不见什么、会误导什么。杜绝软文。

**盲区 1：绿色视角会高估「能效」相对于「性能/成本/生态」的权重。** 本视角通篇在比「每瓦性能」，但**真实采购决策中，能效只是其中一个维度**——性能（Expert_02）、成本（Expert_07）、生态（Expert_22）、可靠性（Expert_23）往往权重更高。**反方**：信创采购方可能完全不在意 PPW 落后两倍，只要「国产 + 够用 + 便宜」就买。本视角若被用来「一票否决 D3000M 进信创机房」，是**过度解读**——能效是软约束，国产化是硬约束。**「PPW 落后」不等于「不能卖」**。

**盲区 2：本视角大量结论标着 [推测-依据]，本身有不确定性。** D3000M 的 TDP（~72W）、PPW（~4 GFLOPS/W）、DVFS 实现状态、C-state 深度、制造碳排——**这些我没有一手实测证据，全是「公开规格 + Lab 算力外推 + 论文模型」推出来的**。**反方**：D3000M 真实 TDP 可能是 100W 或 50W（差 2 倍），PPW 可能因此翻倍或减半。本视角的所有量化结论**应被读作「量级参考」，不能写进 SLA 或采购合同**。真实数据必须靠功率计 + perf 实测（§5.1）。

**盲区 3：绿色视角偏「芯片中心论」，忽视软件能效。** 真实系统中，**软件低效（如未优化的算法、内存泄漏、过度 polling）导致的能耗浪费，远大于 CPU 微架构能效差异**[书-Barroso2013]。一个用 Graviton4 跑的烂代码，可能比用 D3000M 跑的优化代码更耗电。**本视角不覆盖软件优化（编译器/算法/调度）——那是 Expert_11/04 的领地**。**单看硬件 PPW 会高估「换 CPU」的减碳效果**。

**盲区 4：LCA 碳排的外推误差极大。** §2.5 的制造碳排（~10–30 kgCO₂）是拿 Gupta 2021 的 5nm 数据外推到 14nm + D3000M die size，**误差可能差一个数量级**[论文-Gupta2021]。14nm 的真实制造碳排可能更高（晶圆产出低、良率损失）或更低（光刻层少）——**必须由飞腾或第三方做 ISO 14040 LCA 才能定论**。本视角的 LCA 数字**只是示意量级，不是实测**。

**盲区 5：绿色视角低估了「可再生能源」对碳排的决定性作用。** 使用碳排 = 功耗 × **电网碳强度**。如果信创机房建在西部（水电/风光），电网碳强度可能 0.1 kgCO₂/kWh（比东部煤电 0.5 低 5 倍）——**此时 D3000M 即使 PPW 落后，使用碳排也可能低于建在东部的 Xeon**。「东数西算」政策正是在利用这一点。**本视角的净碳账（图 4）用 0.5 kgCO₂/kWh 是保守估计，真实信创机房若在西部，结论可能反转**。这是「绿色信创」的另一重政策杠杆。

**盲区 6：CBAM 目前不直接覆盖芯片。** 本视角说「国产芯片 CBAM 优势」是前瞻押注——**截至 2026 年，CBAM 覆盖钢铁/水泥/铝/化肥/电力/氢，芯片不在内**[标准-EU-CBAM]。未来是否扩展到电子产品不确定。**把 CBAM 当作 D3000M 的现实优势，是过度前瞻**。但服务器整机（含钢铁/铝机箱）已部分覆盖，这点成立。

### 5.1 给采购方 / ESG 合规团队的绿色尽职调查清单（实战交付物）

把本视角的全部判断收敛成一份**采购方在选型飞腾 D3000M 服务器时该逐条问供应商、并要求拿出证据**的 checklist。每一项都对应前文某个判断，且**「拿不出证据」就按「不具备」对待**（这是 ESG 尽职调查的铁律——沉默不等于绿色）：

- [ ] **TDP 与 PPW**：官方 TDP 是多少？有无 SPECPower 或等效基准（ops/W）数据？FP16/INT8/整数负载的 PPW 分别多少？
- [ ] **能量比例曲线**：能否提供 10%/30%/50%/70%/100% 负载下的功耗曲线？空载功耗占满载多少%（理想 <30%）？
- [ ] **DVFS 状态**：BIOS 默认 governor 是什么（performance=锁频自杀 / schedutil=动态）？可用 P-state 频率档有几档？支持 per-core DVFS 吗？
- [ ] **C-state 深度**：支持到哪一级 C-state（C0/C1/C3/C6/C7+）？deep C-state 唤醒延迟多少？
- [ ] **LCA 碳排报告**：有无 ISO 14040/14044 标准 LCA 报告？制造/运输/使用/报废碳排占比？Scope1/2/3 数据？
- [ ] **电网碳强度适配**：是否支持「跟随可再生能源出力的弹性调度」（东数西算场景）？有无西部机房实测碳排数据？
- [ ] **液冷方案**：有无「国产液冷 + D3000M 高密度机柜」参考设计？实测 PUE 能到多少？是否通过工信部 ≤1.3/≤1.25 认证？
- [ ] **国密能效**：SM3/SM4 硬件指令的实测吞吐（Gbps）？vs 软件实现的能效比？有无国密网关场景的 PPW 白皮书？
- [ ] **TCFD/CBAM 合规**：能否提供 TCFD 披露所需的碳排数据？国产短链证明？Scope3 供应链碳排可追溯性？
- [ ] **制造碳排 vs 使用碳排**：14nm 制造碳排的具体数据？vs 5nm 进口芯片的对比？「换新是否减碳」的 LCA 分析？

**这份清单的用法**：逐条要证据，**能答 6 条以上 = 可进绿色信创采购；能答 8 条以上 = 可进有 PUE 配额的东部数据中心；全答齐且有 LCA 报告 + 液冷方案 = 可谈「绿色信创标杆」**。这是把本视角的「推测」变成「采购决策」的最短路径。

## § 绿色计算方法论与资源（不只飞腾，给所有能效/可持续工程师）

> 本章把 E20 的飞腾能效分析上升为**任何能效/可持续工程师都可复用的方法与资源**。飞腾是案例锚点（每瓦性能），方法普适。通用资源见 [`领域资源库.md`](../领域资源库.md)。

### 方法论一：能效三层（芯片 → 服务器 → 数据中心）

| 层 | KPI | 优化手段 |
|----|-----|---------|
| 芯片 | perf/W（如 GFLOPS/W）| DVFS、power gating、clock gating、异构（专用加速器更高效）|
| 服务器 | SPECPower（服务器能效基准）| 电源转换效率（80PLUS 钛金）、风扇、组件低功耗 |
| 数据中心 | **PUE**（总功耗/IT 功耗）| 气流/热通道、液冷、自然冷却、AI 调度 |

**PUE 基准**：传统 DC 1.5-2.0，现代 DC 1.2-1.4，液冷 1.05-1.1，理论下限 1.0。每降 0.1 = 省 ~10% 总能耗。

### 方法论二：perf/W 的物理根源

能效受限于：
- **DVFS**：频率 ↑ → 电压 ↑³（动态功耗 ∝ CV²f），高频极不划算
- **Dark Silicon**（Power Wall）：面积大但功耗预算限 → 部分必须关 → 异构/DSA
- **漏电**：先进节点静态漏电占比升，需 power gating
- **飞腾案例**：14nm@2.5GHz 撞 FO4 墙，提频极不划算 → 每瓦性能弱于先进节点对手

### 方法论三：碳足迹与 ESG

- **运营碳**（Scope 2）：电力消耗 × 电网碳强度
- **隐含碳**（Scope 3）：制造（晶圆/封装）+ 运输 + 报废，常被低估（占 ICT 总碳 60-80%）
- **ESG 报告**：GRI/SASB/TCDF 框架，投资人日益关注
- **循环经济**：服务器翻新/再利用/回收（金属/稀土）

### 绿色专属资源

- **基准**：**SPECpower_ssj**（服务器能效）、**MLPerf**（含能效赛道）、**Green500**（超算能效排名）
- **标准/认证**：**ENERGY STAR**、TCO Certified、**80PLUS**（电源）、LEED（建筑）、ISO 14001（环境管理）
- **数据中心数据**：**Uptime Institute**（可靠性/PUE）、**Borderstep**、Google/Meta DC 白皮书
- **工具**：**Scaphandre**（能耗监测）、**CodeCarbon**（代码碳足迹）、**Kepler**（K8s 能效）
- **书/报告**：Barroso《The Datacenter as a Computer》、IEA《Electricity Reports》、GSMA《Mobile Net Zero》

### 给能效工程师的通用建议

1. **PUE 是 DC 第一 KPI**：每 0.1 的 PUE 改善 = 真金白银（电费常超硬件成本）。
2. **perf/W > 峰值性能**：高频撞功耗墙，DVFS 显示高频极不划算——服务器优化 perf/W。
3. **隐含碳别忽视**：制造碳占 ICT 60-80%，只算运营碳会误导采购决策。
4. **液冷是 PUE 突破口**：冷板/浸没式可达 PUE 1.05，是 AI 高功耗 DC 的刚需。
5. **DVFS 固件（PSCI/SCMI）要调好**：飞腾 PSCI/DVFS 实现见 E18，调优空间大。
