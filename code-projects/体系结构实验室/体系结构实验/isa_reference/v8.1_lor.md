## 0. 一句话

6 条 "弱 LL/SC" 指令 —— 比 LDAR/STLR 更轻，专为低争用 read-mostly 场景设计。


---
## 1. 现象：为什么需要它？

`LDLAR` 是 restricted-load-exclusive：与 LDXR 不同，它**不允许配对 STXR**，专门做"读取最近一次 STLUR 写入的值"。

**典型用法**：RCU 风格的 publish-subscribe
```asm
// writer
STLLR w0, [x1]      // store-release，发布新数据
// reader (RCU 风格)
LDLAR w0, [x1]      // load-limited，保证读到 publish 的值
```

实际上是 v8.1 引入的"低开销 load-acquire/store-release 变体"，主要用于支持 v8.1 weak memory model 修订后的一些 corner case。


---
## 2. 引入版本 & 飞腾状态

**版本**：ARMv8.1-A mandatory。


**飞腾 D3000M 状态**：

## 6. 性能预期（飞腾 D3000M @ 2.5 GHz）

| 指令 | latency |
|------|---------|
| LDLAR | ~4 cyc (同 LDAR) |
| STLLR | ~2 cyc (同 STLR) |

通常和 LDAR/STLR 性能相同；区别在 memory model 语义保证更严格。


---
## 7. 缺陷与陷阱

1. **不能与 STXR 配对**：LDLAR 只是 load，没有 store-exclusive 等价物
2. **使用场景极少**：用户态几乎不用，内核态 RCU 才用
3. **memory model 修订后引入**：解决 v8.0 LDAR/STLR 的某些 corner case
