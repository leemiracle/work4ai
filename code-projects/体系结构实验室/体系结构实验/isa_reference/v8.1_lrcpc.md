## 0. 一句话

LDAPR: 单条 load-acquire（比 LDAR+额外 barrier 更轻） —— C++ memory_order_consume / acquire 的硬件实现。


---
## 1. 现象：为什么需要它？

v8.0 的 LDAR 是 load-acquire，但实际 ARMv8 memory model 早年被发现 RCsc（不是 RCpc）—— 即 LDAR/STLR 不能重排，但 LDAPR 是 RCpc 版本，允许某些重排，性能更好。

```cpp
// C++ 代码
std::atomic<int> flag{0};
int data = 0;

// thread A
data = 42;
flag.store(1, std::memory_order_release);   // -> STLR

// thread B
while (!flag.load(std::memory_order_acquire))  // -> LDAPR (RCpc) 或 LDAR (RCsc)
  ;
assert(data == 42);   // 保证
```

LDAPR 用于 memory_order_acquire（C++），LDAR 用于更强的 RCsc 模式。

## 2. 引入版本 & 飞腾状态

**版本**：ARMv8.1-A mandatory。


**飞腾 D3000M 状态**：

飞腾 D3000M 实测支持（HWCAP_LRCPC=1）。

- 编译：`-march=armv8.1-a+rcpc` 或 `-mcpu=ftc86x`
- LLVM/GCC 自动用 LDAPR 替代 LDAR 当 memory_order_acquire 时


**杀手级应用**：std::atomic<T>::load(acquire) / mutex fast path / RCU read-side

## 6. 性能预期（飞腾 D3000M @ 2.5 GHz）

| 指令 | latency | 备注 |
|------|---------|------|
| LDR (relaxed) | ~4 cyc | 普通 load |
| LDAR (acquire, RCsc) | ~5-6 cyc | 含 barrier 开销 |
| LDAPR (acquire, RCpc) | ~4-5 cyc | 比 LDAR 快 ~1 cyc |
| LDAPUR (v8.3+, 带 offset) | ~4-5 cyc | 改进版支持 imm offset |

**实测（Lab06）**：LDAPR vs LDAR 在 MP pattern 下快 5-10%。


---
## 7. 缺陷与陷阱

1. **LDAPR 只 load，STLURR (RCpc store) 不存在**：v8.1 只有 load-acquire 的 RCpc 变体
2. **memory model 差异**：RCpc 允许 (LD,ST) 重排，比 RCsc 弱，C++ acquire/consume 可用 RCpc，seq_cst 必须 RCsc
3. **地址必须有 offset=0**：LDAPR 不支持立即数偏移（要 v8.3 LDAPUR 才支持）
4. **size 只有 32/64 bit**：LDAPRB/LDAPRH（byte/halfword）不存在于 v8.1，v8.3 LRCPC2 才有
