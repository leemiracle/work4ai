## 0. 一句话

一条指令把 4×int8 点积累加到 int32 —— CNN 量化推理的硬件神器。


---
## 1. 现象：为什么需要它？

CNN 卷积本质是 int8 矩阵乘。v8.4 之前做 int8 推理必须用 SSHLL+MUL+ADD 拼装，每 4 个 int8 乘加需要 ~6 条指令：

```asm
// 朴素：4×int8 → int32 累加，需要 6 条
SSHLL  v0.8h, v1.8b, #0      ; int8 → int16
SSHLL2 v2.4s, v0.8h, #0      ; int16 → int32
MUL    v3.4s, v2.4s, v4.4s
ADD    v5.4s, v5.4s, v3.4s
```

UDOT 把这一坨压成 1 条：
```asm
UDOT v5.4s, v1.16b, v4.16b   ; 4 路 4×int8 → int32 累加
```

**实测吞吐**：~4× 相对 fp32 GEMM，~10× 相对纯软件 int8。

### 4.1 `SDOT (by element)` (C7.2.237)

**语义**：Dot Product signed arithmetic (vector, by element). This instruction performs the dot product of the four 8-bit elements in each 32-bit element of the first source register with the four 8-bit elements of an indexed 32-bit element in the second source register, accumulating the result into the corresponding 32-bit element of the destination register.


**汇编模板**：
```
SDOT <Vd>.<Ta>, <Vn>.<Tb>, <Vm>.4B[<index>]
```

**版本/限制**：In Armv8.2 and Armv8.3, this is an OPTIONAL instruction. From Armv8.4 it is mandatory for all implementations

**检测字段**：`ID_AA64ISAR0_EL1.DP` (1 表示支持)

 boolean signed = (U == '0');

 integer n = UInt(Rn); 
 integer m = UInt(M:Rm); 
 integer index = UInt(H:L); 
  
 integer esize = 8 << UInt(size); 
 integer datasize = if Q == '1' then 128 else 64; 
 integer elements = datasize DIV esize;

## 7. 缺陷与陷阱

1. **只支持 int8/int32**：UDOT 累加到 int32，要 fp32 输出还得 CVT
2. **元素布局严格**：4 个 int8 必须连续在 32-bit lane 内
3. **没有 fp16/bf16 dot product**：飞腾不支持 FEAT_FHM/BF16，FMLA fp16 替代
4. **by element index 编码**：`<Vm>.4B[<index>]` 的 index 在编码中是 H:L 位，最大 7
5. **不支持 int16 → int64**：上层量化需自行扩位
6. **UDOT vs I8MM 差异**：I8MM (v8.6) 是 8×8 → int32 矩阵 tile (1 指令 4×4)，UDOT 是 dot product (1 指令 4×1 累加)，I8MM 吞吐高 4×，但飞腾没有
