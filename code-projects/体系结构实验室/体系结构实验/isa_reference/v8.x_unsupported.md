## 1. 现象：为什么需要它？

飞腾 D3000 (FTC663) 是 ARMv8.1，D3000M (FTC862) 是 ARMv8.4。**不支持以下 5 个 AI/向量扩展**：

| 扩展 | 引入版本 | 飞腾替代 | 备注 |
|------|---------|---------|------|
| **SVE** (Scalable Vector Extension) | v8.4 (FEAT_SVE) | NEON 128-bit 固定宽度 | SVE 是可变长向量 (256/512/1024/2048-bit) |
| **SVE2** | v8.6 (FEAT_SVE2) | 同上 | SVE 的增强版，含更多字符/DSP 指令 |
| **BF16** (Brain Float) | v8.6 (FEAT_BF16) | FP16 + 自行 CVT | 数据中心 AI 主流格式，但 fp16 也够 |
| **I8MM** (int8 matrix multiply) | v8.6 (FEAT_I8MM) | UDOT/SDOT 手动展开 | I8MM 是指令级矩阵乘，UDOT 是 dot product |
| **FHM** (fp16→fp32 FMLA) | v8.4 (FEAT_FHM) | FP16 NEON + extra CVT | fp16 输入累加到 fp32 的横向乘加 |

**性能影响**：
- LLM 推理 (LLaMA/Qwen)：BF16 缺失意味着要用 fp16，精度损失可控但吞吐减半
- int8 CNN (ResNet/MobileNet)：UDOT 完全够用，I8MM 优势在 4×4 矩阵 tile，飞腾 UDOT 也能展开
- SVE 缺失：标准 NEON 128-bit 已经覆盖 80% 工作负载，缺的是 ≥256-bit 的并行

## 6. 性能预期（飞腾 D3000M @ 2.5 GHz）

| 替代方案 | 性能损失 | 备注 |
|---------|---------|------|
| NEON 替代 SVE (256-bit) | ~50% 理论峰值 | 实际工作负载损失 ~20-30% |
| FP16 替代 BF16 | ~10-20% 精度风险 | 需 Mixed Precision 训练 |
| UDOT 替代 I8MM | ~5-10% 性能 | 手动展开 4×4 tile |
| FP16 NEON + CVT 替代 FHM | ~30% 性能 | 多一次 cvt + 拆位


---
## 7. 缺陷与陷阱

1. **不要假设 SVE 可用**：跨平台代码用 NEON fallback
2. **BF16 vs FP16 精度差异**：BF16 是 8 位 exp + 7 位 mantissa，FP16 是 5 位 exp + 10 位 mantissa，应用场景不同
3. **I8MM 指令不存在≠int8 GEMM 不能做**：飞腾完全可以用 UDOT 做 int8 GEMM，只是更费力
4. **跨平台兼容**：QNNPACK/XNNPACK/MLC-LLM 等库都做 HWCAP dispatch，自动 fallback

## 9. 附录：v8.6 矩阵乘指令详解（飞腾不支持，作为对比参考）

> 这一节详解 v8.6 FEAT_I8MM / FEAT_BF16 / FEAT_FHM 引入的"矩阵乘指令"。
> 飞腾 D3000M 不支持，但理解它们有助于**看懂为什么这些指令很重要**以及**飞腾的替代方案有何劣势**。

### 9.1 I8MM (FEAT_I8MM) — int8 矩阵乘

#### 9.1.1 SMMLA / UMMLA / USMMLA（matrix tile）

`SMMLA Vd.4S, Vn.16B, Vm.16B` — 4×4 int8 矩阵乘累加到 4×4 int32，**一条指令做 64 个 int8 乘加**（vs UDOT 16 个，4× 加速）。

数学定义：
```
Vd.S[i,j] += Σ_{k=0..3} Vn.B[4i+k] * Vm.B[4k+j]
```

#### 9.1.2 USDOT / SUDOT（dot product with mixed signedness）

类似 UDOT/SDOT，但 Vn 和 Vm 的符号性可以不同（uint8 × int8 或 int8 × uint8）。这解决了**CNN 量化的不对称问题**：权重 int8 (-128..127) × 激活 uint8 (0..255)。

#### 9.1.3 I8MM vs UDOT/SDOT 对比

| 维度 | UDOT (v8.4, 飞腾支持) | SMMLA (v8.6 I8MM, 飞腾不支持) |
|------|---------------------|------------------------------|
| 一条指令的 MAC 数 | 16 | **64** (4×) |
| 数据布局 | vector dot product | matrix tile (需 reshape) |
| 符号性 | uint8×uint8 或 int8×int8 | uint8×int8 混合 |
| 飞腾替代 | 手动展开 4×4 tile (8-12 条 UDOT) | - |

**飞腾上手动实现 SMMLA 4×4 tile**：
```c
// 一个 4x4 输出元素需要 4 条 UDOT
int8x16_t row0 = vld1q_s8(A);       // A[0,0..3]
int8x16_t row1 = vld1q_s8(A+4);     // A[1,0..3]
int8x16_t row2 = vld1q_s8(A+8);     // A[2,0..3]
int8x16_t row3 = vld1q_s8(A+12);    // A[3,0..3]
int8x16_t col0 = vld1q_s8(B);       // B[0..3,0]
// ... 16 次 UDOT 替代 1 次 SMMLA，~4× 慢
```

### 9.2 BF16 (FEAT_BF16) — BFloat16 矩阵乘

#### 9.2.1 BFMMLA（matrix tile）

`BFMMLA Vd.4S, Vn.8H, Vm.8H` — 4×4 bf16 矩阵乘累加到 4×4 fp32，一条指令做 **32 个 bf16 乘加**。

#### 9.2.2 BFDOT / BFMLALB / BFMLALT（dot product）

```asm
BFDOT Vd.4S, Vn.8H, Vm.8H     ; 2-lane bf16 dot → fp32
BFMLALB Vd.4S, Vn.8H, Vm.4H   ; bottom half bf16 × fp16 → fp32
BFMLALT Vd.4S, Vn.8H, Vm.4H   ; top half
```

#### 9.2.3 BF16 vs FP16 关键差异

| 维度 | FP16 (飞腾支持) | BF16 (飞腾不支持) |
|------|----------------|------------------|
| 总位数 | 16 | 16 |
| Exponent | 5 (range ±65504) | **8 (range ±3.4×10^38)** |
| Mantissa | **10** (高精度) | 7 (低精度，同 fp32 头部) |
| 训练可用性 | 受限于范围，常需 loss scaling | **直接训练，几乎无损** |
| Transformer 主流 | 不太用 | **数据中心默认** |

**飞腾上 LLM 推理策略**：
- 模型权重：fp16 存储（节省带宽）
- 计算：fp16 GEMM（v8.2 FEAT_FP16 支持）
- 累加：fp16 → 偶尔升 fp32 累加（避免溢出）
- 性能：相对 BF16 慢 1.3-2×（因 fp16 范围有限需额外处理）

### 9.3 FHM (FEAT_FHM) — fp16→fp32 横向乘累加

#### 9.3.1 FMLAL / FMLSL（fp16 输入，fp32 累加）

`FMLAL Vd.4S, Vn.4H, Vm.4H` — 4×fp16 × 4×fp16 → 4×fp32（单指令扩位 + 乘加）。

**vs FP16 FMLA**：
- FMLA: fp16 × fp16 → fp16（精度损失）
- FMLAL: fp16 × fp16 → **fp32**（无精度损失）

**飞腾替代**（FHM 不可用）：
```c
// 朴素：fp16 GEMM 累加到 fp32 需要 4-6 条指令
float16x8_t a = vld1q_f16(A);
float16x8_t b = vld1q_f16(B);
// 拆 fp16 为 fp32，乘加，再合并
float32x4_t a_lo = vcvt_f32_f16(vget_low_f16(a));   // 4×fp32
float32x4_t a_hi = vcvt_f32_f16(vget_high_f16(a));
// ... 4-6 倍指令数
```

性能损失 ~30%（实测大块 GEMM）。

### 9.4 SVE / SVE2 — 可变长向量

#### 9.4.1 SVE 核心思想

SVE 不是固定 128-bit，而是**运行时发现向量长度 (VLA)**：
```c
svuint32_t a = svld1_u32(svptrue_b32(), p);   // 加载"全部" lane
// 飞腾不支持，但 Cortex-A78/X2/V1/N2 等支持
// 在 256-bit 实现上一条指令处理 8 lane (vs NEON 4 lane)
```

#### 9.4.2 SVE 关键能力

| 能力 | NEON (飞腾) | SVE |
|------|------------|-----|
| 向量长度 | 128-bit 固定 | 128/256/512/1024/2048-bit 可变 |
| Predicate（掩码） | ❌（需用 SEL 指令） | ✅（每 lane 一个 predicate 位） |
| Gather-Load | ❌ | ✅（不规则访存加速） |
| 故障抑制 (First-fault) | ❌ | ✅（处理跨页边界） |

#### 9.4.3 SVE2 vs SVE

SVE2 = SVE + 更多指令（字符处理、DSP、INT16 复数、INT8 dot product 等）。SVE2 主要面向**手机/嵌入式**，SVE 主要面向**HPC/AI 训练**。

### 9.5 飞腾 D3000 缺失的实际影响

| 工作负载 | 影响 | 飞腾缓解策略 |
|---------|------|-------------|
| LLM 推理 (LLaMA-7B/13B) | 中等（BF16 缺失） | 用 fp16 + mixed precision，性能损失 30-50% |
| Stable Diffusion | 低（fp16 够用） | 直接 fp16 GEMM |
| ResNet/MobileNet CNN | 极低（UDOT 够用） | 直接 UDOT，性能损失 < 10% |
| BERT int8 量化 | 极低 | UDOT 替代 I8MM，性能损失 ~10% |
| 科学计算 HPC | 高（SVE 缺失） | 用 NEON + 多核，无法用 VLA |
| 区块链 SHA256 mining | 极低 | SHA256 硬件指令足够 |
| 国密 TLS | 极低 | SM3/SM4 全套支持 |

**结论**：飞腾 D3000 的 v8.4 配置在**通用 AI 推理 + 国密合规**场景下接近完美，仅在**大模型训练**（需 BF16/SVE）场景明显受限。下一代 FTC870/880 预计补齐。
