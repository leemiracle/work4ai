## 0. 一句话

LDAPUR 9 条带 offset 的 RCpc load；FJCVTZS 给 JS 用的特殊 fp→int；PAuth 指针签名 15 条指令。


---
## 1. 现象：为什么需要它？

**FEAT_LRCPC2 (LDAPUR/STLUR)**：v8.1 LDAPR 不支持立即数 offset，v8.3 加上：
```asm
LDAPUR w0, [x1, #16]    ; load-acquire with offset
STLUR  w0, [x1, #16]    ; store-release with offset
```
更紧凑（一条 vs LDR+DMB），LLVM 用 LDAPUR 替换 LDR+DMB 序列。

**FEAT_JSCVT (FJCVTZS)**：JavaScript 标准 fp→int 转换有特殊语义（饱和到 int32 范围，超出转 0x80000000）：
```asm
FJCVTZS w0, s0          ; "JS-aware" float-to-int
```
仅 1 条指令，浏览器 V8/SpiderMonkey 用。

**FEAT_PAuth (Pointer Authentication)**：返回地址/函数指针签名，防 ROP/JOP 攻击：
```asm
PACIA x30, x0           ; sign link register with key A
AUTIA x30, x0           ; authenticate before RET
RETAA                    ; RET + authenticate (alias)
```
Linux ARM64 默认开启 kernel PAC，用户态可选。

## 2. 引入版本 & 飞腾状态

**版本**：ARMv8.3-A mandatory。


**飞腾 D3000M 状态**：

飞腾 D3000M：v8.3+ 全部 mandatory 支持。
- LRCPC2: HWCAP_ILRCPC
- JSConv: HWCAP_JSCVT
- PAuth: HWCAP_PACA + HWCAP_PACG
- **均建议在 Lab01 加 HWCAP 探测**


**杀手级应用**：LRCPC2: C++ acquire load / JSConv: V8 引擎 / PAuth: Linux kernel 强化

## 6. 性能预期（飞腾 D3000M @ 2.5 GHz）

| 指令 | latency |
|------|---------|
| LDAPUR | ~4 cyc |
| FJCVTZS | ~3 cyc |
| PACIA/AUTIA | ~3-5 cyc |
| RETAA | ~5 cyc (含 PAC + AUT) |

PAC/AUT 性能开销很小（密码学专用算法），但增加代码大小 ~5%。

## 7. 缺陷与陷阱

1. **LDAPUR 与 LDAPR 并存**：v8.3 实现两者都有，编译器根据 offset 选择
2. **FJCVTZS 只支持标量 fp32**：没有 fp64 版本（JS Number 内部是 fp64 但转换时降到 fp32）
3. **PAC key 选择**：PACIA/PACDA 用不同 key，混淆攻击
4. **PAuth 失败 trap 行为**：v8.3 默认失败不 trap（数据 corrupt），v8.7 FPAC 才 trap
5. **二进制兼容性**：PAuth 改变 ABI（指针高位带 tag），跨架构调用要注意
