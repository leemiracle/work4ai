## 关键洞察

- **p99/p50 > 1.5** 表示有明显长尾（OS 抢占 / 中断 / cache 污染）
- **大算子（GEMM）** p99/p50 应接近 1（计算时间 >> OS 噪声）
- **小算子（elem-add）** p99/p50 可能很大（OS 噪声占比高）
- **max vs p99**：若 max 远超 p99，是偶发大抢占（context switch）

**实时性结论**：
- D3000 + 麒麟 V10 不是 RTOS，**不适合硬实时**（p99/p50 不可控）
- 对**软实时**（语音/视频 30ms deadline）：算子选小一点 + 留 50% 余量
- 对**.batch 推理**：tail 不重要，关注平均吞吐

**优化方向**：
- `taskset` 绑核 / `chrt` 提优先级 / `isolcpus` 隔离核 → 减小长尾
- `mlockall` 锁内存 → 避免 page fault
- 关闭 IRQ 路由到目标核 → 减少 context switch
