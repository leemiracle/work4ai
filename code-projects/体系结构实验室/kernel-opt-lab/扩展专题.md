## 1. NEON（ASIMD）— 一切 SIMD 算子的基础

### 关键事实
- 128-bit 向量，32 个寄存器 V0-V31
- FP32：每条向量指令处理 4 个 lane（4×FP32）
- INT32：同样 4 lane；INT8：16 lane；FP16：8 lane
- D3000 有 **4 个 FVU（Flexible Vector Unit）**，理论峰值 = 4 FVU × 2.5GHz × 4 lane × 2（FMA 算两次）= **40 GFLOPS FP32**

### 在本项目里
所有算子的"v5 MR=8"实现，本质就是**用满 4 FVU**：
- MR=8 = 8 个微内核行，分给 4 FVU 各 2 行
- 每条 `vfmaq_laneq_f32` 同时算 4 lane × 触发多 FVU

### 关键 intrinsic
```c
#include <arm_neon.h>
float32x4_t a = vld1q_f32(ptr);          // 加载 4 个 FP32
float32x4_t c = vfmaq_laneq_f32(c, a, b, 0);  // FMA：c += a × b[0]
vst1q_f32(ptr, c);                        // 存回
```

完整 267 条 NEON 指令见 [`isa_reference/v8.0_asimd.md`](./isa_reference/v8.0_asimd.md)。

## 2. FP16（v8.2）— 2× 宽度的诱惑与反直觉陷阱

### 理论收益
- FP16：每向量 8 lane（vs FP32 的 4 lane）→ 理论 2× 吞吐
- D3000 FP16 峰值：4 FVU × 2.5GHz × 8 lane × 2 = **50 GFLOPS**（vs FP32 的 40）

### ⚠️ 反直觉发现（本项目 v0.8 实测，必读）
**FP16 用 MR=8 反而比 MR=2 慢**（35 vs 39 GFLOPS）！

原因：D3000 单条 `vfmaq_laneq_f16` 指令的实际吞吐 < 4/cyc（4 FVU × 8 lane 是理论，实际单条指令只有 1-2/cyc）。

**结论**：
- FP32/INT8 → 用 MR=8（4 FVU 全开，98% 利用率）
- FP16 → 用 MR=2（避开吞吐瓶颈，78% 利用率）

### FP16 累加精度 bug（算法科学家 lens 发现）
FP16 直接累加会丢精度。正确做法：**FP16 输入 → FP32 累加 → FP16 输出**。
本项目 `gemm_f16.c` v4_dual 已部分处理，P0 待彻底修。

详见 [`isa_reference/v8.2_fp16.md`](./isa_reference/v8.2_fp16.md)（68 条 FP16 指令）。

## 3. UDOT/SDOT（v8.4）— INT8 量化算子的核心

### 算子作用
`UDOT`：4×4 INT8 矩阵 → 1 个 INT32 累加值，一条指令完成 16 次乘加。

```c
int32x4_t acc = vdupq_n_s32(0);
uint8x16_t a = vld1q_u8(ptr_a);   // 16 个 INT8
uint8x16_t b = vld1q_u8(ptr_b);   // 16 个 INT8
acc = vdotq_u32(acc, a, b);        // acc += sum(a[i]*b[i])，16 次乘加 1 条指令
```

### 在本项目里
`gemm_s8.c` v5 MR=8 用 UDOT 达 **77.74 GOPS（97.2% of 80 峰值）**——这是 D3000 上效率最高的算子。

### 为什么 INT8 是边缘 AI 的主力
- 边缘设备内存带宽紧张，INT8 是 FP32 的 1/4 数据量
- 量化 CNN/Transformer 推理几乎不丢精度（INT8 充分）
- D3000 INT8 峰值 80 GOPS，是 FP32 的 2 倍

### ⚠️ 缺失项：I8MM（v8.6）
D3000 **不支持 I8MM**（`SMMLA/UMMLA`，INT8 矩阵乘 intrinsic）。想做 INT8 GEMM 必须用 UDOT 手动实现（本项目正是这么做的）。详见 [`isa_reference/v8.x_unsupported.md`](./isa_reference/v8.x_unsupported.md)。

## 4. FCMLA/FCADD（v8.3）— 复数运算压缩（未实现的潜力项）

### 算子作用
`FCMLA`：一条指令完成复数乘法（正常需要 4 条 FMUL/FADD）。

```c
// 复数乘法 (a+bi)*(c+di) = (ac-bd) + (ad+bc)i
// FCMLA rot0: acc_re += a*c
// FCMLA rot90: acc_re += b*(-d)  // 旋转 90°
float32x4_t r = vcmlaq_rot90_f32(acc, a, b);
```

### 在本项目里（潜力）
**尚未实现**。适用场景：
- 信号处理（FFT、数字预失真 DPD）
- 5G/雷达信号链
- 某些 Attention 变体（复数注意力）

如果要做信号处理算子，FCMLA 是 D3000 上的差异化点。详见 [`isa_reference/v8.3_fcma.md`](./isa_reference/v8.3_fcma.md)。

## 5. LSE 原子（v8.1）— 多核并行的基础

### 算子作用
单条原子指令（vs LL/SC 循环），多核同步更快。

### 在本项目里
`multicore*.c` 用 OpenMP，OpenMP runtime 底层用 LSE 实现原子。手写无锁队列时直接用：
```c
#include <arm_acle.h>
__atomic_fetch_add_n(&counter, 1, __ATOMIC_RELAXED);  // 编译为 LDADD
```

### D3000 实测（姊妹项目 Lab02）
- 低争用：LSE 比 LL/SC 略快
- 高争用：LSE 大胜（LL/SC 的 livelock 问题）

详见 [`isa_reference/v8.1_lse.md`](./isa_reference/v8.1_lse.md)（55 个助记符）。

## 6. D3000 缺失但对 AI 关键的扩展（战略伤疤）

| 扩展 | 引入版本 | 算子优化影响 | 替代方案 |
|------|:-------:|------------|---------|
| ❌ **BF16** | v8.6 | LLM 推理的标准精度，缺失 = 原生做不了现代 LLM | FP16 替代（精度风险）或 FP32（慢）|
| ❌ **I8MM** | v8.6 | INT8 矩阵乘 intrinsic 缺失 | UDOT 手动实现（本项目已做）|
| ❌ **SVE/SVE2** | v8.4+ | 可变长向量，未来算子库主流 | NEON 固定 128-bit（够用但不如 SVE 灵活）|
| ❌ **FHM** | v8.4 | FP16→FP32 横向乘累加 | FP16 NEON + 额外指令组合 |

**这是 D3000 的战略伤疤**（专家 02 算法 + Lens_05 未来 + Lens_21 AI 定位共同指出）：
边缘 AI 还能撑，数据中心 AI 已掉队。本项目算子优化能做的，是在"缺这些扩展"的前提下把 NEON/UDOT 榨到极致。

详见 [`isa_reference/v8.x_unsupported.md`](./isa_reference/v8.x_unsupported.md)。
