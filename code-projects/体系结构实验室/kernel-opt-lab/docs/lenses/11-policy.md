## 1. 视角定位（政策分析口径）

我不看 GFLOPS，我看这个项目能否进入**党政信创采购目录**、能否通过**自主可控等级评估**、是否触碰**出口管制红线**、底层算子库作为"双用途技术"有何**合规义务**。当前项目技术过硬、政策裸奔。

## 2. 八个盲区（信创产品合规缺口）

### ① 完全没有"技术自主可控声明"——P0 致命缺失

信创评审的核心打分项之一是**自主可控等级**（业内三级划分：一级完全自研 ISA / 二级自研微架构+商业 ISA 授权 / 三级买 IP 核）。FTC862 属**二级**——飞腾持有 ARMv8 **架构授权**（architecture license，非直接买 Cortex IP），自研"火星/银河"FTC 核心。本项目的**4 FVU 实测**恰恰是"自研微架构差异化"的软件层实证（ARM 公版 Cortex-A78 仅 2 FVU），这是支撑飞腾"自主"叙事的稀缺证据——**但 README 只字未提**。党政采购评审专家看不到这层论证，项目在自主可控打分上白白丢分。

### ② 出口管制分类（ECCN）未声明——P0 双用途风险

算子优化库涉及高性能计算底层技术，按瓦森纳协定 / 美国 EAR 可能归入 **ECCN 4D003 / 5D002**（密码/信息安全相关软件）或 **4E001**（计算机"开发"技术）。FTC862 本体作为集成电路更可能归 **3A001**。更关键：**飞腾（天津飞信息技术有限公司）自 2020-12-18 起被列入美国 Entity List**（联邦公报 85 FR 82616），任何含美国技术超 de minimis 的物项禁止向飞腾输出。本项目若要开源 / 对外发布，**必须明确 ECCN 分类 + 最终用户/最终用途声明**，否则可能被视为"技术协助"（"technical assistance"，EAR §744.17）违规。仓库现在零声明。

### ③ 信创目录 / 央采认证状态未标注——P0 采购门槛

飞腾 CPU 虽已进入**央采目录**和**信创产品名录**，但本算子库作为独立软件资产是否随整机认证、是否在**麒麟软件适配名录**登记、是否通过**飞腾+麒麟"同心"生态认证**——README 全无交代。党政机关 2027 全替换窗口下，未登名录的算子库即使性能第一也**进不了采购清单**。

### ④ 供应链国产化率未披露——P0 受制点隐藏

FTC862 三大受制点本项目完全回避：**(a) ARM ISA 授权**（软银旗下英国公司，2020 后曾限制对飞腾服务）；**(b) 流片代工**（历史 TSMC 7nm，实体清单后转单传闻国产代工，具体未披露）；**(c) EDA 工具**（Synopsys/Cadence 美企，实体清单后转华大九天等国产 EDA）。算子库无法验证这三点，但**至少应在文档中诚实声明"本项目验证范围限于软件层微架构自主度，硬件供应链自主度不在验证范围"**——现在既不声明也不否认，给评审留下模糊地带。

### ⑤ 等保 2.0 合规缺口——P1

麒麟 V10 SP1 已通过**等保 2.0 四级**测评，但本算子库引入的安全盲区（安全视角 09 已点出：malloc 零 NULL check、整数溢出、NaN 链路、**Spec store bypass Vulnerable**）在等保测评中属"**安全计算环境**"控制项。特别是硬件视角实测的 `Spec store bypass: Vulnerable`，对**机密计算 / 政务云 / TEE 推理**场景是**合规红线**——项目把这条埋在硬件 lens 附录里，没有上升到合规章节。

### ⑥ 数据安全法 / PIPL 合规义务未声明——P1

《数据安全法》（2021-09 生效）第 31 条、《个人信息保护法》（PIPL，2021-11 生效）对处理"**重要数据**"和个人的技术产品有合规义务。算子库作为底层组件本身不直接处理数据，但**一旦被集成进处理政务数据 / 人脸识别 / 语音的推理引擎**，开发者需声明"本组件不存储 / 不传输数据，数据合规义务由集成方承担"。现在零声明，责任边界不清。

### ⑦ 节能 / 绿色计算认证缺位——P2

党政采购强制要求**节能产品认证**（国家发改委《节能产品政府采购清单》）。算子库把 4 核 tiled 从 61% 效率提到 92%，本质是**单位算力能耗下降 ~30%**——这是绝佳的绿色计算叙事，但项目只讲性能不讲能效，**没有把性能数据换算成 TOPS/W、没有对接节能认证数据格式**，白白浪费一个政策加分项。

### ⑧ 开源许可证 + 出口管制例外条款缺失——P1

仓库**无 LICENSE 文件**（git 扫描确认）。若选 MIT/Apache，需附加**"出口管制例外条款"**（参照 Google AOSP / oneDNN 做法：明示受 EAR 约束、禁止向被制裁实体再分发）。对涉及飞腾实体清单身份的项目，**许可证条款缺失本身是合规风险**——可能被解读为"无授权技术扩散"。

## 4. 关键洞察

**对飞腾"自主可控"叙事的真实支撑——强但有限**。本项目最大政策价值是：**4 FVU 实测是飞腾自研微架构差异化的稀缺软件层实证**。ARM 公版 Cortex-A78/A715 全系 2 FVU，FTC862 跑出 4 FMLA/cyc，软件层证明硬件自研——这种"用算子优化反推微架构自主度"的论证在公开资料里几乎为零（开发者布道视角 06 已点出稀缺性）。但必须诚实：**这只能支撑"微架构自研"，无法触及三大硬受制点**（ARM ISA 授权、TSMC/国产流片、美系 EDA）。把这点讲清楚，反而让自主可控论证更扎实。

**信创政策红利窗口期——2027 是硬截止**。党政信创替代节奏要求 2027 年完成"2+8"行业全替换（工信部规划），2024–2026 是软件生态适配的**密集落地期**。本项目作为"飞腾+麒麟算子优化实战记录"恰好踩在窗口期，但**政策红利只给进入名录的产品**——技术再强，不补合规文档就吃不到采购红利。这是技术项目最常见的"最后一公里"失分。
