## 0. 一句话

1 cycle 算 CRC32（vs 软件 table lookup 10+ cycles）—— 网络包/Zlib/iSCSI 的隐形加速器。


---
## 1. 现象：为什么需要它？

**软件 CRC32 (Sarwate table)**：
```c
uint32_t crc32_sw(const uint8_t *p, size_t n) {
    uint32_t crc = ~0;
    while (n--) crc = table[(crc ^ *p++) & 0xff] ^ (crc >> 8);
    return ~crc;
}
// 每字节：1 ldr + 1 eor + 1 lsr + 1 eor + loop ≈ 5-8 cycles
```

**硬件 CRC32W**：
```c
uint32_t crc32_hw(const uint8_t *p, size_t n) {
    uint32_t crc = ~0;
    for (; n>=4; n-=4, p+=4)
        crc = __crc32cw(crc, *(uint32_t*)p);   // 1 cycle / 4 bytes
    // ...
}
// 每字（4B）：1 cycle
```

**实测加速比（Lab07）**：14.26×（crc32c 4 字节块 vs software table）

## 4. 每条指令详解（按章节顺序）


### 4.1 `CRC32B, CRC32H, CRC32W, CRC32X` (C6.2.66)

**语义**：CRC32 checksum performs a cyclic redundancy check (CRC) calculation on a value held in a general-purpose register. It takes an input CRC value in the first source operand, performs a CRC on the input value in the second source operand, and returns the output CRC value. The second source operand can be 8, 16, 32, or 64 bits. To align with common usage, the bit order of the values is reversed as part of the operation, and the polynomial 0x04C11DB7 is used for the CRC calculation.

## 6. 性能预期（飞腾 D3000M @ 2.5 GHz）

| 实现 | 吞吐 (4B 块) | 加速比 |
|------|------------|--------|
| Software table (Sarwate) | ~1.2 GB/s | 1.0× |
| Software pclmul (类似 PCLMULQDQ) | ~3 GB/s | 2.5× |
| **Hardware __crc32cw** | **~10 GB/s** | **8.3×** |
| **Hardware __crc32cx** (8B) | **~18 GB/s** | **14.3×** |

**注**：单核数据。10 GbE 线速 (1.25 GB/s) 用硬件 CRC32 几乎零开销。

## 7. 缺陷与陷阱

1. **两种多项式**：`CRC32B/H/W/X` 用 IEEE 802.3 多项式 (0xEDB88320)；`CRC32CB/CH/CW/CX` 用 Castagnoli (0x82F63B78) — 后者是 SCTP/iSCSI/BTRFS/Ext4 用的
2. **逐字节 vs 逐字**：硬件 `__crc32cw` 是 4 字节粒度，末尾不足 4 字节要降级到 `__crc32cb` 逐字节
3. **intrinsics 在 `<arm_acle.h>`**，不是 `<arm_neon.h>`！
4. **不能直接 64-byte unroll**：CRC 是依赖链，ILP 受限于 latency（虽然 1 cycle throughput）
5. **PCLMULQDQ 模拟**：飞腾上做 CRC32 over 4KB 块可以用 PMULL 做更激进并行（参考 zkCrc / intel crc32_pclmul）
