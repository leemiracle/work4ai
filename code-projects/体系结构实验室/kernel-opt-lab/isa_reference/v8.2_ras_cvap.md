## 0. 一句话

ESB 错误同步屏障 + DC CVAP 持久化写 —— 服务器 RAS 与 NVM (PMEM) 的硬件支撑。


---
## 1. 现象：为什么需要它？

**RAS (Reliability/Availability/Serviceability)**：
服务器 CPU 必须能精确报告硬件错误（CPU/内存/PCIe）。ARMv8.2 引入：
- `ESB` (Error Synchronization Barrier)：强制之前的指令全部完成，确保错误被发现
- ERR* 系统寄存器：错误记录、状态、注入
- 内存 ECC 报告（ERRIDR/ERRSELR/ERXSTATUS 等）

**DC CVAP (Data Cache Clean by VA to Point of Persistence)**：
NVM (Intel Optane PMEM / 持久化内存) 需要"刷到持久化点"的写屏障。DC CVAP 把指定 cacheline 刷到持久化域。

```c
// 持久化写入的典型序列
*pmem_addr = data;           // 普通 store
dc cvap, [pmem_addr];       // 刷到持久化点
dsb st;                      // 等待完成
```

## 2. 引入版本 & 飞腾状态

**版本**：ARMv8.2-A mandatory (RAS)；DC CVAP 是 v8.2 OPTIONAL。


**飞腾 D3000M 状态**：

飞腾 D3000M 实测支持（HWCAP/RAS 通过 ERR* 寄存器存在判断）。

- 编译：DC CVAP 需 `.arch_extension ccsel` 或直接 inline asm
- 系统寄存器访问：需 EL1 权限


**杀手级应用**：服务器 RAS / 数据中心 PMEM (Persistent Memory) / 内存数据库 (Redis AEP mode)

## 7. 缺陷与陷阱

1. **DC CVAP 需要 root**：用户态不可执行，需通过 syscall 或 driver
2. **持久化点定义平台相关**：飞腾的"持久化点"由 BIOS/固件决定
3. **RAS 报告机制复杂**：要看 ERR* 寄存器 + IRQ/SEI 信号
4. **ESB 性能开销大**：仅在 RAS 关键路径使用
