## 0. 一句话

128-bit 固定宽度 SIMD：一条指令处理 4×fp32 / 2×fp64 / 16×int8 —— 飞腾向量化的全部基础。


---
## 1. 现象：为什么需要它？

```
朴素 C（4 个 float 加法）：
  for (i=0;i<4;i++) c[i]=a[i]+b[i];     // 4 条 FADD, 4 cycle

NEON（1 条指令）：
  FADD v0.4s, v1.4s, v2.4s              // 1 cycle

→ 4 倍 ILP 压缩成 1 倍 DLP，飞腾 4-wide Issue + NEON 4-wide SIMD = 峰值 16 ops/cycle
```

NEON 寄存器：V0-V31 共 32 个，每个 128-bit。可按 8B/16B/4H/8H/2S/4S/2D/1Q 等形态访问。

**关键寄存器分配规则**：
- 函数前 8 个浮点参数走 V0-V7
- V8-V15 是 callee-saved（**低 64 位**必须保存）
- V16-V31 是 caller-saved


---
## 2. 引入版本 & 飞腾状态

**版本**：ARMv8.0-A mandatory（所有 ARMv8 实现都必须支持）。


**飞腾 D3000M 状态**：

飞腾 D3000M 实测支持（HWCAP_ASIMD=1）。128-bit 固定宽度，**不支持 SVE**。

- 编译：`-march=armv8-a+simd` 或 `-mfpu=neon-fp-armv8`（AArch32）/ 默认开启（AArch64）
- intrinsic 头：`<arm_neon.h>`（约 6000+ 函数）
- 链接到 Lab：所有 Lab05 GEMM 优化都基于 NEON


**杀手级应用**：GEMM / CNN / 图像处理 / 音视频编解码 / 任何数据并行循环

## 6. 性能预期（飞腾 D3000M @ 2.5 GHz）

| 指令类 | 飞腾 D3000M @ 2.5GHz | 备注 |
|--------|-------------------|------|
| FADD/FMUL/FMLA v.4s | 1 cycle throughput | 4-wide Issue，单周期 |
| FMLA latency | 4 cycles | Lab02 dep_chain 实测 |
| LD1/ST1 (1 reg, aligned) | 1 cycle | 单寄存器 128-bit load |
| LD1 (4 regs) | ~4 cycles | 4×128b = 512b，超 issue 宽度 |
| MLU/Zip/Uzp 等 permutation | 1-2 cycles | 大部分 1 cycle |
| FMAXNMV/ADDV (horizontal) | ~3-4 cycles | 跨 lane 归约，多周期 |

**NEON fp32 GEMM 实测峰值（Lab05）**：9.45 GFLOPS = 23.6% of 4-wide×2FMA×2.5GHz×2(arm+macc)=40 GFLOPS peak

## 7. 缺陷与陷阱

1. **V8-V15 只有低 64 位 callee-saved**：高 64 位 (D8-D15 之外的 V8-V15 上半) 可被 caller 破坏 — ABI 陷阱
2. **没有 4×fp32 横向加法**：要 `ADDV` 或 `VADDV` (多周期)，不像 x86 有 `_mm_hadd_ps`
3. **跨 lane 操作慢**：FMAXP/ADDV 等横向归约是 ~3-4 cycle，能避开就避开
4. **VCVT 在 fp32↔int 转换有舍入模式**：默认 round-to-nearest-even
5. **alignment**：16-byte 对齐的 LD1/ST1 走 fast path；未对齐可能走慢路径
6. **fmov immediate 只能编码有限的 fp16/fp32 立即数**（8-bit fraction encoded）
7. **不要混淆 ftype=.2d/.4s/.8h**：FADD v0.2d 是 2 个 double，v0.4s 是 4 个 float
8. **tiger-cpu 的 fscale 陷阱**：FLA>4 倍宽度的 fp32 GEMM 需要 register tile 否则吞吐下降
