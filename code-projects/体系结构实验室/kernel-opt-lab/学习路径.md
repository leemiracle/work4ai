# 学习路径 — 从 Naive 到峰值的算子优化之旅

> 本文件是 Kernel-Lab 的**教学化导览**：把 `src/` 里 18 个算子按学习顺序组织成 8 个阶段，
> 每个阶段都遵循体系结构研究的标准范式——**先写假设 → 再跑代码 → 后解释 → 记陷阱**。
>
> 不移动 `src/` 的任何文件（保护构建系统），这里只是"怎么读、按什么顺序读、会看到什么"。
> 配套：[`CODE_INDEX.md`](./CODE_INDEX.md)（程序清单）+ [`项目宪法.md`](./项目宪法.md)（实验纪律）+ [`扩展专题.md`](./扩展专题.md)（ISA 锚点）+ **[`labs/`](./labs/README.md)（代码级详细 Lab 导览）**。

## 阶段 0：测量基础（1 周）

> *"你必须先有度量衡，才能做实验。" —— 项目宪法 §7*

### 学习目标
能回答：
- 怎么测一个算子跑了多久才可信？（中位数 vs 平均，warmup 的作用）
- 怎么防止编译器把我的循环优化掉？（DCE / escape）
- D3000 的 FP32 理论峰值是多少？怎么推？

### 关键实验
1. **读 [`common/bench.h`](./common/bench.h)**：理解 `now_ns` / `escape` / `pin_to_cpu` / `median_u64`
2. **读 [`项目宪法.md`](./项目宪法.md) §5**：记住 4 FVU → FP32 峰值 40 GFLOPS 的推导
3. **跑基线**：
   ```bash
   make bench_gemm && ./bin/bench_gemm
   ```
   记录你看到的 GFLOPS，对比 40 GFLOPS 峰值，算利用率。

### 陷阱（先写你的假设，再看答案）
- ❓ 假设：不绑核、不锁频，跑 1 次，结果可信吗？
  - 答案（先别看）：<details>不可信。调度漂移 + DVFS + 无 warmup，误差可达 30%+。见项目宪法 §7。</details>
- ❓ 假设：`for(i) c[i]=a[i]*b[i]` 不加 escape，编译器会怎么处理？
  - 答案：<details>编译器发现 c 从未被读取，直接删除整个循环（DCE）。你测到的是 0 ns。</details>

## 阶段 1：FP32 GEMM（1-2 周，核心）

> *"矩阵乘是所有算子优化的母题。" —— Goto & Van de Geijn 2008*

### 学习目标
能回答：
- GEMM 怎么分块才高效？（MR/NR/KC 的含义）
- D3000 为什么是 MR=8？（4 FVU 怎么用满）
- Roofline 上 GEMM 是 compute-bound 还是 memory-bound？为什么？

### 关键算子
[`src/gemm_f32.c`](./src/gemm_f32.c) — 从 v1 naive 到 v5 MR=8 的完整演进。

### 假设 → 实验 → 解释

**假设 1**：naive 三重循环（i,j,k），1024³，能跑到多少 GFLOPS？
```bash
make gemm_f32 && ./bin/gemm_f32   # 看 naive 基线
```
**解释**：<details>naive 约 1-3 GFLOPS（~3-8% 利用率）。瓶颈：最内层 k 循环每次跨列访问 B，cache 不友好；C 重复读写。</details>

**假设 2**：分块（i,j 两层分块 + k 做 panel）能提升多少？
**解释**：<details>分块后 A/B 的子块能放进 L1/L2，cache 命中率暴增。Goto 论文的核心洞察。</details>

**假设 3**：MR=8（8 行微内核）为什么是最优？
**解释**：<details>D3000 有 4 FVU，MR=8 让 8 行分配给 4 FVU 各 2 行，每个 FVU 用 `vfmaq_laneq_f32` 算 4 lane。MR<8 浪费 FVU，MR>8 寄存器溢出。实测 v5 MR=8 = 39.45 GFLOPS（98.6%）。</details>

### 必读论文
- *Anatomy of High-Performance Matrix Multiplication* (Goto & Van de Geijn, 2008) — GEMM 分块的圣经

### 陷阱
- 不要在没绑核、没锁频的情况下比较 v1 和 v5——误差会吞掉真实差异
- `objdump -d ./bin/gemm_f32 | grep -A20 <hot_loop>` 确认 v5 的 FMA 指令真的在

### 下一步
阶段 1 通过的标准：能画出 gemm_f32 v1→v5 每一步的 GFLOPS 柱状图，并解释每步改了什么。

## 阶段 2：数据类型扩展（1 周）

### 学习目标
- INT8 + UDOT 为什么是边缘 AI 的主力？
- FP16 的反直觉陷阱是什么？

### 关键算子
- [`src/gemm_s8.c`](./src/gemm_s8.c) — INT8 GEMM v5（vdotq，77.74 GOPS）
- [`src/gemm_f16.c`](./src/gemm_f16.c) — FP16 GEMM（v4_dual MR=2）

### 假设 → 实验 → 解释

**假设 1**：INT8 峰值是 FP32 的 2 倍（80 vs 40 GOPS），对吗？
```bash
make gemm_s8 && ./bin/gemm_s8
```
**解释**：<details>对。INT8 每向量 16 lane（vs FP32 的 4 lane），4 FVU × 16 lane × 2.5GHz × 2 = 80 GOPS。UDOT 一条指令算 16 次乘加。</details>

**假设 2（反直觉！）**：FP16 峰值是 50 GFLOPS（8 lane），用 MR=8 应该比 MR=2 快？
```bash
make gemm_f16 && ./bin/gemm_f16   # 比较 MR=2 vs MR=8
```
**解释**：<details>❌ 错！FP16 用 MR=8 反而慢（35 vs 39 GFLOPS）。原因：D3000 单条 `vfmaq_laneq_f16` 实际吞吐 < 4/cyc，4 FVU×8 lane 是理论值。结论：FP16 用 MR=2。这是本项目最重要的反直觉发现之一（v0.8）。</details>

### ISA 锚点
- UDOT：见 [`扩展专题.md`](./扩展专题.md) §3 + [`isa_reference/v8.4_dotprod.md`](./isa_reference/v8.4_dotprod.md)
- FP16 陷阱：见 [`扩展专题.md`](./扩展专题.md) §2

### 陷阱
- FP16 累加会丢精度（算法科学家 lens 发现的 bug）→ 应 FP16 输入、FP32 累加、FP16 输出

## 阶段 4：卷积优化（1 周）

### 学习目标
- im2col + GEMM 为什么比 direct 快？
- Winograd 为什么比 im2col 还快？F(4,4) 比 F(2,3) 又快在哪？

### 关键算子（按性能递增）
1. [`src/conv_benchmark.c`](./src/conv_benchmark.c) — Direct（基线，1.22 GFLOPS）
2. im2col + GEMM（6.3×）
3. [`src/conv_winograd.c`](./src/conv_winograd.c) — F(2,3)（14.8×）
4. [`src/conv_winograd_f44.c`](./src/conv_winograd_f44.c) — ⭐ F(4,4)（21.5×）

### 假设 → 实验 → 解释

**假设**：Winograd 用更多乘法换更少乘法（数学魔术），为什么反而更快？
**解释**：<details>Winograd 把卷积的乘法次数从 O(K²) 降到 O(K)，用加法换乘法。在 compute-bound 的卷积里（乘法是瓶颈），这是净赢。F(4,4) 比 F(2,3) tile 更大，分摊开销更低。</details>

### 必读论文
- *Fast Algorithms for Convolutional Neural Networks* (Lavin & Gray, 2016)

## 阶段 5：Flash Attention（1 周）

### 学习目标
- Attention 为什么是 LLM 的性能瓶颈？（N² softmax）
- Flash Attention 的核心技巧是什么？（分块 + online softmax）

### 关键算子
- [`src/attention.c`](./src/attention.c) — Naive（基线）
- [`src/attention_neon.c`](./src/attention_neon.c) — ⭐ NEON Flash（单核 6.58× / 多核 16×）

### 假设 → 实验 → 解释

**假设**：Attention 的瓶颈是 N² 的 QK^T 矩阵太大放不进 cache？
**解释**：<details>对。Naive 要实例化整个 N×N attention 矩阵，N=1024 时是 4MB，爆 L2。Flash 的核心：分块算 softmax（online softmax），永远不实例化完整 N×N 矩阵。</details>

### 必读论文
- *FlashAttention: Fast and Memory-Efficient Exact Attention* (Dao et al., 2022)

## 阶段 6：多核并行（1 周，关键突破点）

### 学习目标
- 为什么 flat 多核只有 57% 效率？
- MC×NC 分块为什么能到 92%？

### 关键算子
- [`src/multicore.c`](./src/multicore.c) — flat（57%）
- [`src/multicore_tiled.c`](./src/multicore_tiled.c) — ⭐ MC×NC tiled（92%，143 GFLOPS）

### 假设 → 实验 → 解释

**假设 1**：8 核 flat 应该接近 8× 单核 = 316 GFLOPS？
```bash
make multicore && OMP_NUM_THREADS=8 ./bin/multicore
```
**解释**：<details>❌ 错！实际只有 ~170 GFLOPS（57%）。瓶颈：flat 分配让各核写同一块 C，L3 双段（核 0-3 / 4-7）跨段一致性开销巨大。</details>

**假设 2**：MC×NC 分块（每个核负责 C 的一块）能解决？
```bash
make multicore_tiled && OMP_NUM_THREADS=4 ./bin/multicore_tiled
```
**解释**：<details>对！MC=NC=256 让每个核独立写自己的 C 子块，跨核一致性开销消失。4 核 143 GFLOPS（92%）。这是 v0.9 的关键突破。</details>

### 陷阱（必读）
- `OMP_PROC_BIND=close` 在 D3000 上**反而慢**！拓扑特殊，通用 OS 调优必须本机验证（v0.9 实测盲区⑥）
