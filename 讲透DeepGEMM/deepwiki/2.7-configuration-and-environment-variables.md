  This document provides a comprehensive reference for runtime configuration functions and environment variables supported by DeepGEMM. Configuration functions allow dynamic control of GPU resource usage, while environment variables control JIT compilation behavior, debugging output, cache management, and compiler settings.

 
## Overview

 DeepGEMM provides two primary mechanisms for controlling runtime behavior:

 
 - **Runtime Configuration Functions**: Python API functions that control GPU resource allocation, programmatic dependency, and performance tuning.
 - **Environment Variables**: Shell variables with the `DG_` prefix that configure compilation and debugging behavior.
 
 
### Configuration Scope

 
| Mechanism | Scope | When Set | Primary Use Cases |
|---|---|---|---|
| Configuration Functions | Per-process, dynamic | Runtime via Python API | SM allocation, tensor core utilization, PDL control |
| Environment Variables | Per-process, static | Before import | JIT compilation, debugging, cache management |

 All environment variables are read during library initialization and affect the behavior of the JIT compilation system and kernel execution. Configuration functions can be called at runtime but affect all subsequent kernel launches.

## Runtime Configuration Functions

 DeepGEMM exposes configuration functions through the Python API to control GPU resource utilization. These functions modify the state of the `DeviceRuntime` and `HeuristicsRuntime` singletons in the C++ backend.

 
### SM (Streaming Multiprocessor) Allocation

 
#### `deep_gemm.set_num_sms(num_sms: int) -> None`

 Sets the maximum number of SMs (Streaming Multiprocessors) to use for kernel execution. This updates the internal `num_sms` field in the `DeviceRuntime` class [csrc/jit/device_runtime.hpp15](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L15-L15)

 **Parameters:**

 
 - `num_sms`: Maximum SM count. 
 - `0`: Use all available SMs (default).
 - `> 0`: Limit kernel execution to the specified number of SMs.
 
 Sources: [csrc/apis/runtime.hpp12-14](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/runtime.hpp#L12-L14) [csrc/jit/device_runtime.hpp103-106](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L103-L106)

 
#### `deep_gemm.get_num_sms() -> int`

 Gets the current maximum SM count setting. If not set, it returns the `multiProcessorCount` from the device properties [csrc/jit/device_runtime.hpp108-112](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L108-L112)

### Tensor Core Utilization Control

 
#### `deep_gemm.set_tc_util(tc_util: int) -> None`

 Sets the approximated tensor core utilization ratio as a percentage. This controls how aggressively the kernel uses tensor cores, allowing for power and frequency management by injecting idle cycles.

 **Parameters:**

 
 - `tc_util`: Tensor core utilization percentage. Must satisfy `0 <= tc_util <= 100`. 
 - `0` or `100`: Full utilization (default).
 - `< 100`: Inject idle cycles between UMMA/WGMMA instructions.
 
 Sources: [csrc/apis/runtime.hpp18-20](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/runtime.hpp#L18-L20) [csrc/jit/device_runtime.hpp118-121](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L118-L121)

 Gets the current tensor core utilization ratio. Defaults to 100 if unset [csrc/jit/device_runtime.hpp123-125](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L123-L125)

### Programmatic Dependency (PDL)

 
#### `deep_gemm.set_pdl(enable_pdl: bool) -> None`

 Enables or disables Programmatic Stream Serialization (PDL). When enabled, kernels are launched with the `cudaLaunchAttributeProgrammaticStreamSerialization` attribute, allowing for more efficient stream synchronization on supported hardware.

 Sources: [csrc/apis/runtime.hpp24-26](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/runtime.hpp#L24-L26) [csrc/jit/device_runtime.hpp127-129](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L127-L129)

 
#### `deep_gemm.get_pdl() -> bool`

 Gets the current status of PDL enablement.

### Heuristics and Compilation Tuning

 
#### `deep_gemm.set_ignore_compile_dims(ignore: bool) -> None`

 Configures the heuristic system to ignore specific matrix dimensions during kernel selection, which can be used to force more general kernel reuse and reduce compilation overhead.

 Sources: [csrc/apis/runtime.hpp30-32](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/runtime.hpp#L30-L32)

 
#### `deep_gemm.set_block_size_multiple_of(multiple: Union[int, Tuple[int, int]]) -> None`

 Sets alignment requirements for block size selection in the heuristic system. This ensures that the chosen GEMM block sizes (M, N) are multiples of the specified values. This is particularly useful for TMA alignment requirements.

 Sources: [csrc/apis/runtime.hpp33-41](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/runtime.hpp#L33-L41)
