  This page provides detailed technical documentation of CUDA kernel implementations targeting the SM90 architecture (NVIDIA Hopper H100/H200 GPUs). SM90 kernels leverage hardware features including Tensor Memory Accelerator (TMA), Warp Group Matrix Multiply-Accumulate (WGMMA) instructions, and cluster-level barrier synchronization to achieve high performance on FP8 and BF16 GEMM operations.

 For SM100 (Blackwell) architecture enhancements including UMMA instructions and tensor memory accumulators, see [4.2](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/4.2) For general memory management patterns applicable to both architectures, see [4.5](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/4.5)

## Architecture Overview

 SM90 kernels target NVIDIA Hopper architecture GPUs (compute capability 9.0) and require CUDA 12.3+. The implementation exploits several key hardware capabilities:

 
| Feature | Description | Usage in DeepGEMM |
|---|---|---|
| TMA (Tensor Memory Accelerator) | Asynchronous global→shared memory transfers with address pattern support | All data loading operations via make_tma_a_desc csrc/jit_kernels/impls/sm90_fp8_gemm_1d1d.hpp105-108 make_tma_sf_desc csrc/jit_kernels/impls/sm90_fp8_gemm_1d1d.hpp113-114 |
| WGMMA | Warp-group matrix multiply instructions (64×N×K) | Core matrix multiplication via FP8MMASelector deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh59 and BF16MMASelector deep_gemm/include/deep_gemm/impls/sm90_bf16_gemm.cuh60 |
| Cluster Barriers | Hardware-accelerated synchronization across thread blocks | Producer-consumer pipeline coordination via ClusterTransactionBarrier deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh60 |
| Shared Memory | ~230KB per SM, swizzled for bank conflict avoidance | Staging area with alignment and swizzle mode handling deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh93-94 |
| Scaling Factors | FP32 format per 128-element channel | FP8 quantization/dequantization, handled in 1D1D/1D2D kernels deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh52 |

## Hardware Feature Utilization

 
### TMA (Tensor Memory Accelerator)

 TMA operations in SM90 kernels follow this pattern:

 
 - **Descriptor Creation**: Host-side functions encode transfer parameters into `CUtensorMap` via specialized helpers like `make_tma_a_desc` [csrc/jit_kernels/impls/sm90_fp8_gemm_1d1d.hpp105-108](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/sm90_fp8_gemm_1d1d.hpp#L105-L108)
 - **Device-side Issue**: TMA descriptors are prefetched at the beginning of the kernel to reduce latency [deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh83-89](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh#L83-L89)
 - **K-Grouped Handling**: For grouped GEMMs, descriptors are loaded into shared memory (`smem_tensor_map_a/b`) [deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh129-132](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh#L129-L132)
 - **Synchronization**: Producer threads initialize barriers using `full_barriers[i]->init(1)` [deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh139](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh#L139-L139) and consumer threads wait on them.

## Kernel Implementations

 
### FP8 GEMM 1D1D vs 1D2D

 DeepGEMM implements two primary variants for SM90 FP8 GEMM:

 
 - **1D1D Variant** (`sm90_fp8_gemm_1d1d_impl`):

 
 - Supports `GemmType::Normal` and `GemmType::KGroupedContiguous` [deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh53](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh#L53-L53)
 - Shared memory is partitioned for descriptors, accumulators (D), A/B tiles, and scaling factors (SFA/SFB) [deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh69-75](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh#L69-L75)
 - Uses `SM90FP8Gemm1D1DRuntime` for JIT compilation and launching [csrc/jit_kernels/impls/sm90_fp8_gemm_1d1d.hpp15-31](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/sm90_fp8_gemm_1d1d.hpp#L15-L31)
 - **1D2D Variant** (`sm90_fp8_gemm_1d2d_impl`):

 
 - Supports BF16 output without accumulation [deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d2d.cuh64](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d2d.cuh#L64-L64)
 - Manages scaling factors (SFB) with a flexible major mode (`kMajorSFB`) [deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d2d.cuh38](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d2d.cuh#L38-L38)
 - Includes an `epilogue_type_t` for customizable result processing [deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d2d.cuh48](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d2d.cuh#L48-L48)

### BF16 GEMM Implementation

 The `sm90_bf16_gemm_impl` kernel optimizes BF16 matrix multiplication:

 
 - **Warp Specialization**: Divides warps into TMA loading groups and Math execution groups [deep_gemm/include/deep_gemm/impls/sm90_bf16_gemm.cuh148-154](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_bf16_gemm.cuh#L148-L154)
 - **Register Configuration**: TMA threads deallocate registers (`kNumTMARegisters = 48`) while Math threads use up to 248 [deep_gemm/include/deep_gemm/impls/sm90_bf16_gemm.cuh128-150](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_bf16_gemm.cuh#L128-L150)
 - **Einsum Support**: Dispatched via `csrc/apis/einsum.hpp` for patterns like `bhr,hdr->bhd` [csrc/apis/einsum.hpp75-76](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/einsum.hpp#L75-L76)

## Shared Memory and Synchronization

 
### Shared Memory Layout

 Shared memory is manually managed and aligned to 1024 bytes for swizzle-128B support [deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh93-94](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh#L93-L94)

 
| Buffer Component | Pointer Calculation | Alignment |
|---|---|---|
| Accumulators (D) | reinterpret_cast<float*>(smem_buffer + SMEM_TENSOR_MAP_SIZE) | 1024B deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh103 |
| A/B Tiles | utils::PatternVisitor over SMEM_A_SIZE_PER_STAGE | Per-stage deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh104-109 |
| Scaling Factors | SMEM_SF_OFFSET based on stage count | 128B (TMA requirement) deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh110-116 |
| Barriers | SMEM_BARRIER_OFFSET at the end of buffer | sizeof(Barrier) deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh119-125 |

 
### Synchronization Patterns

 
 - **Barrier Initialization**: One thread group initializes barriers; `cutlass::arch::fence_barrier_init()` makes them visible to the async proxy [deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh138-142](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_gemm_1d1d.cuh#L138-L142)
 - **Cluster Sync**: Uses `comm::cluster_sync_with_relaxed_arrive()` or `__syncthreads()` depending on multicast configuration [deep_gemm/include/deep_gemm/impls/sm90_bf16_gemm.cuh125](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_bf16_gemm.cuh#L125-L125)
 - **Grid Dependency**: `cudaGridDependencySynchronize()` is called to ensure primary kernel completion before scheduling [deep_gemm/include/deep_gemm/impls/sm90_bf16_gemm.cuh132](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_bf16_gemm.cuh#L132-L132)
