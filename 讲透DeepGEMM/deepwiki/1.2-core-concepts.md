## Purpose and Scope

 This page explains the fundamental concepts underlying DeepGEMM's design and operation. It covers the data types, operation types, memory layouts, and specialized kernel categories that form the foundation of the library. DeepGEMM is designed as a lightweight JIT-compiled library that targets NVIDIA SM90 (Hopper) and SM100 (Blackwell) architectures specifically.

 
---

 
## Data Types and Precision Formats

 DeepGEMM operates on multiple numeric data types, each serving specific purposes in the GEMM computation pipeline.

 
### Input Data Types

 
| Data Type | Description | Usage | Hardware Support |
|---|---|---|---|
| FP8 E4M3 | 8-bit floating point (4-bit exponent, 3-bit mantissa) | Primary input matrices (A, B) | SM90, SM100 |
| FP8 E5M2 | 8-bit floating point (5-bit exponent, 2-bit mantissa) | Alternative FP8 format | SM90, SM100 |
| BF16 | 16-bit brain floating point | Higher precision GEMMs | SM90, SM100 |
| FP4 | 4-bit floating point | Ultra-low precision GEMMs (E2M1) | SM100 |
| TF32 | Tensor Float 32 | Used for HyperConnection kernels | SM90, SM100 |

## GEMM Operations and Memory Layouts

 
### Operation Convention

 DeepGEMM follows the convention: **`D = C + A @ B`**, where:

 
 - `A`: Left-hand side (LHS) input matrix
 - `B`: Right-hand side (RHS) input matrix
 - `C`: Bias matrix (optional, can be zero)
 - `D`: Output matrix
 
 
### Layout Notation

 The library uses a two-letter suffix to indicate the memory layout (transpose state) of the input matrices:

 
| Suffix | Meaning | A Layout | B Layout | Python Function Example |
|---|---|---|---|---|
| NT | Non-Transposed × Transposed | Row-major | Column-major | fp8_gemm_nt |
| NN | Non-Transposed × Non-Transposed | Row-major | Row-major | fp8_gemm_nn |
| TN | Transposed × Non-Transposed | Column-major | Row-major | fp8_gemm_tn |
| TT | Transposed × Transposed | Column-major | Column-major | fp8_gemm_tt |

 **Hardware Support**: While the SM90 implementation natively supports the NT memory layout (row-major, col-major), the SM100 implementation supports all memory layouts (NT, TN, NN, TT) without internal transposition overhead.

## Grouped GEMM Operations for MoE

 Grouped GEMMs are specialized variants designed for Mixture-of-Experts (MoE) model architectures. DeepGEMM groups only the M-axis (or K-axis for backward), while other dimensions remain fixed across experts.

 
### M-Axis Grouped GEMM

 M-axis grouping splits the batch/sequence dimension (M) while keeping feature dimensions (N, K) fixed across all groups. This is the primary pattern for MoE forward passes.

 **M-Grouped Layouts**:

 
 - **Contiguous Layout** (`m_grouped_*_contiguous`): Input tokens are concatenated into a single tensor. Each expert segment must be aligned to the GEMM M block size, queried via `get_mk_alignment_for_contiguous_layout()`.
 - **Masked Layout** (`m_grouped_*_masked`): Used during inference decoding with CUDA graphs. By providing a mask tensor, the kernel computes only the valid portions for each expert when the CPU is unaware of token counts.

### K-Axis Grouped GEMM

 K-axis grouping (`k_grouped_fp8_gemm_tn_contiguous`) splits the reduction dimension (K) while keeping M and N fixed. This pattern is specifically used for MoE weight backward passes.

## Mega MoE Fused Kernel

 Mega MoE is a highly specialized concept in DeepGEMM that fuses the entire MoE computation block into a single kernel to overlap communication and computation.

 
### Fused Execution Model

 The kernel overlaps:

 
 - **EP Dispatch**: Moving tokens to the correct expert.
 - **Linear 1**: FP8 x FP4 GEMM.
 - **Activation**: SwiGLU with FP8 requantization.
 - **Linear 2**: FP8 x FP4 GEMM.
 - **EP Combine**: Moving results back to the original sequence order.
 
 This uses a **Symmetric Buffer** for zero-copy communication across NVLink.

## Summary of Operation Types

 The `GemmType`, `MmaKind`, and `KernelType` enums define the operational modes and precision paths of the library:

 
| Enum Value | Description |
|---|---|
| GemmType::Normal | Standard single-matrix GEMM. |
| GemmType::MGroupedContiguous | MoE forward/prefill layout. |
| GemmType::MGroupedMasked | MoE decoding layout with masks. |
| GemmType::KGroupedContiguous | MoE weight gradient layout. |
| MmaKind::BF16 | Standard 16-bit brain float MMA path. |
| MmaKind::MXFP8FP4 | Mixed precision FP8/FP4 MMA path. |
| KernelType::Kernel1D1D | Standard 1D-partitioned scaling factors. |
| KernelType::Kernel1D2D | 2D-partitioned scaling factors. |
