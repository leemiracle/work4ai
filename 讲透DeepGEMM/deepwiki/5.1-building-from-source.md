  This document provides comprehensive instructions for building DeepGEMM from source code. It covers the complete build process, including dependency management, environment configuration, the JIT-optimized header aggregation, and specialized build scripts for developers.

 
## Prerequisites

 Building DeepGEMM requires several system-level dependencies and development tools. The build system uses PyTorch's `CUDAExtension` framework and requires a compatible CUDA toolkit installation.

 
### Required Dependencies

 
| Component | Requirement | Purpose |
|---|---|---|
| CUDA Toolkit | 12.3+ (Recommended) | NVCC compiler, NVRTC, and CUDA driver/runtime libraries setup.py43 |
| PyTorch | 2.1+ | CUDAExtension build framework and tensor operations setup.py8-9 |
| Python | 3.9+ | Primary runtime environment setup.py86 |
| C++ Compiler | C++17 support | Compilation of the _C Python API wrapper setup.py28 |

 
### CUDA Environment

 The build system requires `CUDA_HOME` to locate the CUDA toolkit. It links against `cudart` and `nvrtc` [setup.py43](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/setup.py#L43-L43) DeepGEMM supports two JIT backends: the standard Driver API and the newer Runtime API (enabled via `DG_JIT_USE_RUNTIME_API=1`) [setup.py25-31](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/setup.py#L25-L31)

## Build System Architecture

 The build process uses a custom `setuptools` configuration defined in `setup.py`. It extends `build_py` to handle header aggregation and `bdist_wheel` to support cached wheel downloads.

 
### Build Configuration Variables

 
| Variable | Default | Description |
|---|---|---|
| DG_SKIP_CUDA_BUILD | 0 | If 1, skips compiling the deep_gemm._C extension setup.py22-106 |
| DG_FORCE_BUILD | 0 | If 1, forces a local build even if a cached wheel is available setup.py23-170 |
| DG_USE_LOCAL_VERSION | 1 | If 1, appends the git commit hash to the version string setup.py24-70 |
| DG_JIT_USE_RUNTIME_API | 0 | Enables cudaLibraryLoadFromFile instead of cuModuleLoad setup.py25-31 |

## Development Workflows

 DeepGEMM provides specialized shell scripts to streamline the build process for different use cases.

 
### `install.sh`: Production/Clean Install

 This script performs a clean build and forces a reinstall of the generated wheel [install.sh7-10](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/install.sh#L7-L10)

 
 - Removes `build/`, `dist/`, and `*.egg-info`.
 - Runs `python setup.py bdist_wheel`.
 - Runs `pip install dist/*.whl --force-reinstall`.
 
 
### `develop.sh`: Fast Iteration

 This script is designed for developers who are frequently modifying C++ or CUDA code [develop.sh1-22](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/develop.sh#L1-L22)

 
 - **Header Symlinking**: Instead of copying, it creates symlinks for `cutlass` and `cute` into `deep_gemm/include` [develop.sh7-8](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/develop.sh#L7-L8)
 - **Build**: Runs `python setup.py build` [develop.sh13](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/develop.sh#L13-L13)
 - **SO Symlinking**: Finds the compiled `.so` file in the `build/` directory and symlinks it directly into the `deep_gemm/` package folder [develop.sh16-18](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/develop.sh#L16-L18) This allows changes to the Python code to take effect immediately without a reinstall.
 
 
### `build.sh`: Distribution

 A simple wrapper to generate a wheel without installing it [build.sh7-9](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/build.sh#L7-L9)

 
## Header Aggregation for JIT

 DeepGEMM's JIT system requires access to CUTLASS and internal headers at runtime. The `prepare_includes` function in `setup.py` ensures these are bundled correctly [setup.py149-167](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/setup.py#L149-L167)

 
 - It identifies `third-party/cutlass/include/cute` and `third-party/cutlass/include/cutlass` via `third_party_include_dirs` [setup.py45-48](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/setup.py#L45-L48)
 - It copies these directories into the `build_lib/deep_gemm/include` directory [setup.py151-166](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/setup.py#L151-L166)
 - This ensures that when the package is installed, the JIT compiler can find the necessary templates to instantiate kernels.
 
 
## IDE Support (CMake)

 While the real compilation for kernels is done via JIT, a `CMakeLists.txt` is provided primarily for IDE indexing (e.g., CLion, VS Code) [CMakeLists.txt1](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/CMakeLists.txt#L1-L1)

 
 - It defines a dummy target `deep_gemm_indexing_cuda` using `csrc/indexing/main.cu` to trigger CUDA language support in the IDE [CMakeLists.txt32](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/CMakeLists.txt#L32-L32)
 - It includes directories for `third-party/cutlass/include`, `third-party/fmt/include`, and PyTorch headers [CMakeLists.txt23-24](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/CMakeLists.txt#L23-L24)
 - It sets `CMAKE_CXX_STANDARD` and `CMAKE_CUDA_STANDARD` to 20 [CMakeLists.txt20-21](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/CMakeLists.txt#L20-L21)

### Lazy Loading

 When using the Driver API, DeepGEMM uses a lazy loading mechanism for `libcuda.so.1` [csrc/jit/handle.hpp14-21](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/handle.hpp#L14-L21) The `get_driver_handle` function uses `dlopen` with `RTLD_LAZY` to load the driver library [csrc/jit/handle.hpp17](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/handle.hpp#L17-L17) The `DECL_LAZY_CUDA_DRIVER_FUNCTION` macro wraps driver calls like `cuModuleLoad` and `cuLaunchKernelEx`, resolving symbols via `dlsym` only when first called [csrc/jit/handle.hpp24-44](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/handle.hpp#L24-L44) This minimizes overhead for processes that may not immediately require GPU execution.
