  DeepGEMM's testing framework provides a comprehensive suite for validating the correctness and performance of high-performance GEMM kernels across multiple data types (FP8, BF16, FP4), architectures (SM90, SM100), and operation variants (Grouped, Attention, Einsum, Mega MoE).

 
## Test Organization and Purpose

 The testing suite is organized into specialized modules targeting specific kernel families and system utilities.

 
| Test File | Purpose | Key Operations Tested |
|---|---|---|
| test_fp8.py | FP8 specific kernels | SM90/SM100 FP8 GEMM, Grouped GEMMs, Scaling factors |
| test_fp8_fp4.py | Mixed precision kernels | FP8/FP4 mixed GEMM, UE8M0 packing validation |
| test_bf16.py | BF16 GEMM kernels | BF16 GEMM, Grouped BF16 GEMM, cuBLAS comparison |
| test_attention.py | Attention operations | MQA Logits, Paged MQA, Skip-head-mid variants |
| test_einsum.py | Einsum abstractions | Batched GEMM, complex tensor contractions |
| test_hyperconnection.py | DeepSeek-specific ops | TF32 Hyperconnection prenorm GEMM |
| test_mega_moe.py | Fused MoE kernels | Fused EP-dispatch, Dual-Linear, SwiGLU, EP-combine |
| test_layout.py | Utility validation | TMA alignment, UE8M0 packing, SF transformations |
| test_legacy.py | Backward compatibility | Triton-based A100 kernels |
| test_sanitizer.py | Memory/Sync safety | Compute Sanitizer integration (memcheck, synccheck) |

### Data Generation Logic

 Generators handle the creation of both the input tensors and the ground-truth reference results using high-precision PyTorch operations.

 
 - **`QuantConfig`**: Manages quantization recipes, including granularity (K-block size) and data types (FP8/FP4). It determines the maximum allowed numerical difference (`max_diff`) based on precision [tests/generators.py43-80](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/generators.py#L43-L80)
 - **`generate_normal`**: A utility in `generators.py` (referenced by tests) that creates input tensors `a`, `b`, and `c`, applies quantization/scaling, and returns the reference `ref_d` computed in FP32/BF16 [tests/test_bf16.py33](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_bf16.py#L33-L33) [tests/test_attention.py48](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_attention.py#L48-L48)
 - **UE8M0 Support**: Detects architecture and applies UE8M0 packing for SM100 scaling factors via `get_ue8m0_usage` [tests/generators.py88-91](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/generators.py#L88-L91)
 
 
## Validation Strategies

 
### Numerical Correctness

 Correctness is validated by comparing DeepGEMM outputs against PyTorch reference results using a custom similarity metric.

 
 - **`calc_diff(x, y)`**: Computes the difference based on the formula $1 - \text{similarity}$, where similarity is $\frac{2 \sum(xy)}{\sum(x^2 + y^2)}$. Tensors are cast to `double` for the calculation [deep_gemm/testing/numeric.py5-11](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/testing/numeric.py#L5-L11)
 - **Tolerance**: Standard BF16 tests typically use a threshold of `1e-5` [tests/test_bf16.py41](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_bf16.py#L41-L41) while FP4 tests allow up to `0.02` due to quantization error [tests/generators.py65-70](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/generators.py#L65-L70)
 - **`assert_bitwise_equal`**: Used for strict validation of bit-patterns, raising an `AssertionError` with detailed coordinate and byte-level mismatch info if tensors differ [deep_gemm/testing/numeric.py24-44](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/testing/numeric.py#L24-L44)
 
 
### Sanitization and Safety

 The `test_sanitizer.py` script automates the execution of the entire test suite under NVIDIA's `compute-sanitizer`.

 
 - **Tools**: Supports `memcheck` for out-of-bounds access and `synccheck` for race conditions [tests/test_sanitizer.py32-33](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_sanitizer.py#L32-L33)
 - **Environment**: Forces `CUDA_LAUNCH_BLOCKING=1`, `DG_JIT_PTXAS_CHECK=1`, and `DG_USE_NVIDIA_TOOLS=1` to ensure reliable error reporting and avoid crashes during shutdown [tests/test_sanitizer.py52-58](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_sanitizer.py#L52-L58)

### Metrics and Comparison

 The framework automatically calculates and prints performance statistics:

 
 - **TFLOPS**: Computed as $(2 \times M \times N \times K) / \text{time} / 10^{12}$ [tests/test_bf16.py49](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_bf16.py#L49-L49) [tests/test_attention.py60](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_attention.py#L60-L60)
 - **Bandwidth**: Computed using `count_bytes` utility which sums the size of all input/output tensors [deep_gemm/testing/numeric.py14-21](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/testing/numeric.py#L14-L21)
 - **cuBLAS Comparison**: BF16 tests include a baseline comparison against `cublaslt_gemm_nt` to report speedup factors [tests/test_bf16.py46-54](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_bf16.py#L46-L54)
 
 
## Specialized Testing Modules

 
### Attention and Masking

 `test_attention.py` validates specialized kernels like Multi-Query Attention (MQA) and "skip-head-mid" GEMMs.

 
 - **MQA Validation**: Uses `ref_fp8_mqa_logits` to verify the weighted ReLU logit computation against the optimized CUDA kernel [tests/test_attention.py84-113](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_attention.py#L84-L113)
 - **Skip-Head-Mid**: Validates kernels that insert padding into output heads via `apply_skip_head_mid` [tests/test_attention.py19-31](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_attention.py#L19-L31) [tests/test_attention.py52-54](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_attention.py#L52-L54)
 
 
### Mega MoE

 `test_mega_moe.py` provides end-to-end validation for the fused MoE kernel, comparing `fp8_fp4_mega_moe` against baselines.

 
 - **Symmetric Memory**: Uses `get_symm_buffer_for_mega_moe` for multi-GPU communication buffers [tests/test_mega_moe.py93-99](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_mega_moe.py#L93-L99)
 - **Expert Stats**: Validates `cumulative_local_expert_recv_stats` to ensure correct token routing and counting [tests/test_mega_moe.py126-130](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_mega_moe.py#L126-L130)
 - **Baseline Comparison**: Optionally loads `deep_ep` and `tilelang_ops` for comparative benchmarking [tests/test_mega_moe.py15-33](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_mega_moe.py#L15-L33)
 
 
### Einsum Operations

 `test_einsum.py` (and the C++ API in `einsum.hpp`) validates various tensor contraction patterns.

 
 - **Supported Expressions**: Validates `bmk,bnk->mn`, `bhr,hdr->bhd`, and `bhd,hdr->bhr` [csrc/apis/einsum.hpp123-134](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/einsum.hpp#L123-L134)
 - **Casting**: Handles implicit FP32-to-BF16 casting for batched matrix multiplications [csrc/apis/einsum.hpp26-39](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/einsum.hpp#L26-L39)
 
 
### Layout and Padding
