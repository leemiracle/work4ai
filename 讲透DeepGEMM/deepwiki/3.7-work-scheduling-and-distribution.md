  This document explains how DeepGEMM distributes GEMM computation blocks across GPU streaming multiprocessors (SMs) to maximize performance. The core mechanism is the `Scheduler` template class, which implements persistent thread scheduling with sophisticated swizzling patterns for L2 cache optimization, alongside specialized schedulers for MQA and Mega MoE operations.

 
---

 
## Scheduler Template Class

 The `Scheduler` template class in `deep_gemm/include/deep_gemm/scheduler/gemm.cuh` is the central abstraction for work distribution. It is instantiated once per cooperative thread array (CTA/thread block) and manages the iteration through multiple GEMM output tiles in a persistent scheduling model.

 
### Template Parameters

 The `Scheduler` is parameterized to specialize for different GEMM types and hardware configurations:

 
| Parameter | Type | Purpose |
|---|---|---|
| kGemmType | GemmType | Selects scheduling logic: Normal, MGroupedContiguous, MGroupedMasked, MGroupedContiguousWithPsumLayout, KGroupedContiguous, Batched |
| BLOCK_M | uint32_t | M-dimension tile size (e.g., 64, 128, 256) |
| BLOCK_N | uint32_t | N-dimension tile size (e.g., 128, 256) |
| kNumGroups | uint32_t | Number of groups for grouped operations or batch size |
| kNumMulticast | uint32_t | TMA multicast factor: 1 (no multicast) or 2 (2-CTA multicast) |
| kIsMulticastOnA | bool | If true, multicast on A matrix (group on N); if false, multicast on B (group on M) |
| kNumSMs | uint32_t | Number of SMs available for scheduling |
| kKAlignment | uint32_t | Alignment for psum k-group start (default 128u) |
| kSFKSpan | uint32_t | K covered by one k-grouped scale factor row (default 512u) |

## Block Indexing and Swizzling

 To optimize L2 cache hit rates, DeepGEMM applies a swizzling pattern that groups spatially adjacent blocks together.

 
### Swizzle Pattern Algorithm

 The algorithm groups blocks into 1D strips to minimize the memory footprint of active tiles. The group size is determined by `get_num_1d_blocks_per_group`, which selects between 8 and 16 based on minimizing combined M and N block usage.

## Specialized Schedulers

 
### MegaMoEScheduler (SM100)

 The `MegaMoEScheduler` manages the fused Expert Parallel (EP) dispatch + dual-linear computation pipeline. It implements a core state machine that transitions between `Linear1` and `Linear2` phases.

 
 - **Phase Management:** Uses `BlockPhase` (None, Linear1, Linear2, SharedLinear1, SharedLinear2) to track the current computation stage [deep_gemm/include/deep_gemm/scheduler/mega_moe.cuh83-89](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/scheduler/mega_moe.cuh#L83-L89)
 - **Deadlock Prevention:** The function `get_num_l1_warmup_waves` calculates the minimum number of L1 (Linear1) waves required to ensure no L1 -> L2 deadlock occurs due to L2 tasks waiting for L1 tasks that haven't been issued yet [deep_gemm/include/deep_gemm/scheduler/mega_moe.cuh18-45](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/scheduler/mega_moe.cuh#L18-L45)
 - **Task Information:** The `TaskInfo` struct encapsulates all metadata for a scheduled block, including its phase, expert index, and valid dimensions [deep_gemm/include/deep_gemm/scheduler/mega_moe.cuh92-134](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/scheduler/mega_moe.cuh#L92-L134)
 - **Ring Buffer Scheduling:** Uses `get_num_max_live_pool_blocks` to calculate the required capacity for the symmetric buffer ring to overlap NVLink communication with computation [deep_gemm/include/deep_gemm/scheduler/mega_moe.cuh48-80](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/scheduler/mega_moe.cuh#L48-L80)

### MQA Logits Schedulers

 For Attention operations, DeepGEMM provides specialized schedulers for both SM90 and SM100.

 
 - **SM100MQALogitsScheduler:** A contiguous-KV scheduler that translates row bounds into core task geometry. It uses `next_q_block` to dynamically assign query blocks to SMs and calculate `kv_token_base` and `num_kv_splits` based on the sequence lengths provided in `cu_seq_len_k_start` and `cu_seq_len_k_end` [deep_gemm/include/deep_gemm/scheduler/sm100_mqa_logits.cuh11-82](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/scheduler/sm100_mqa_logits.cuh#L11-L82)
 - **SM100 Paged Scheduler:** Uses a separate metadata kernel `sm100_paged_mqa_logits_metadata` to balance work. It computes a prefix sum of work (KV splits * Q tokens) across requests and uses binary search to find the starting request for each SM [deep_gemm/include/deep_gemm/scheduler/sm100_paged_mqa_logits.cuh70-175](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/scheduler/sm100_paged_mqa_logits.cuh#L70-L175)
 - **SM90 Paged Scheduler:** Similarly uses `sm90_paged_mqa_logits_metadata` to distribute work. It supports both standard and variable-length (varlen) sequences, performing work distribution by partitioning the prefix-summed KV segments across SMs [deep_gemm/include/deep_gemm/scheduler/sm90_paged_mqa_logits.cuh9-127](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/scheduler/sm90_paged_mqa_logits.cuh#L9-L127)
