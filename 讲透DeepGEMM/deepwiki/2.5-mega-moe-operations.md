# Mega MoE Operations

  Relevant source files 
 - [csrc/apis/mega.hpp](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/mega.hpp)

  Mega MoE is a highly optimized, fused kernel designed for multi-GPU MoE (Mixture-of-Experts) inference on SM100 (Blackwell) architectures. It fuses several distinct operations—Expert Parallel (EP) dispatch, two linear layers (Linear1 and Linear2), the SwiGLU activation function, and EP combine—into a single, unified execution flow to minimize memory overhead and maximize communication-compute overlap.

 
### Purpose and Scope

 The Mega MoE API provides the necessary primitives to execute a full MoE block with minimal kernel launches. It leverages **Symmetric Memory** (via `SymmBuffer`) to enable zero-copy or low-latency communication across GPUs using NVLink. The kernel specifically supports FP8/FP4 mixed-precision compute, where weights are stored in FP4 to reduce memory bandwidth requirements while activations remain in FP8 for precision.

 
---

 
## The SymmBuffer Class

 The `SymmBuffer` class is a specialized memory management utility used to allocate symmetric memory across multiple GPUs in a cluster. This is critical for the Mega MoE operation as it allows SMs on one GPU to directly access buffers on another GPU via NVLink without explicit `cudaMemcpy` or complex collective calls during the kernel execution.

### Symmetric Memory Layout

 The buffer size is calculated based on the number of ranks, experts, and tokens. It includes space for a workspace, input tokens, scaling factors (SF), Top-K indices/weights, and intermediate activation buffers for the fused layers. The C++ implementation in `get_symm_buffer_size_for_mega_moe` defines the exact byte offsets for these contiguous regions [csrc/apis/mega.hpp34-87](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/mega.hpp#L34-L87) The layout handles both shared experts and routed experts [csrc/apis/mega.hpp55-56](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/mega.hpp#L55-L56)

## Weight Preprocessing

 Before executing the Mega MoE kernel, expert weights must be transformed into a layout optimized for the SM100's Tensor Memory (TMEM) and the specific requirements of the fused kernel.

## Fused Execution Model

 The `fp8_fp4_mega_moe` function is the primary entry point for the fused operation. It implements a complex warp-specialization strategy to handle communication and computation simultaneously.

 
### Execution Flow

 The kernel follows a "Mega" fused pipeline:

 
 - **EP-Dispatch**: Tokens are routed to their respective experts across the GPU cluster using the `SymmBuffer`.
 - **Linear 1 (FP8xFP4)**: Computes the first linear projection (Up-projection and Gate-projection) using the interleaved weights.
 - **SwiGLU**: Applies the activation function and combines the gate and up-projections.
 - **Linear 2 (FP8xFP4)**: Computes the second linear projection (Down-projection).
 - **EP-Combine**: Tokens are gathered back from the experts to their original order/locations.

## Implementation Details

 
### Symmetric Memory Allocation

 The `get_symm_buffer_for_mega_moe` function ensures that every GPU in the Expert Parallel group allocates an identical size of memory at a reachable address for its peers. It aligns the token count to `get_token_alignment_for_mega_moe()` (which returns `kLCMCandidateBlockM`) to ensure compatibility with kernel block sizes [deep_gemm/mega/__init__.py78](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/mega/__init__.py#L78-L78) [csrc/apis/mega.hpp19-21](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/mega.hpp#L19-L21)

 
### Warp Specialization

 The underlying CUDA kernel (`sm100_fp8_fp4_mega_moe_impl`) utilizes a multi-role warp specialization strategy. This is reflected in the internal headers where specialized roles for dispatch, MMA, and epilogue are defined to enable the NVLink communication overlap [csrc/apis/mega.hpp14-15](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/mega.hpp#L14-L15) The `get_block_m_for_mega_moe` function queries the scheduler to determine the optimal block size for a given token count and hardware configuration [csrc/apis/mega.hpp23-32](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/mega.hpp#L23-L32)
