  The Mega MoE kernel is a highly specialized Blackwell-optimized (SM100) fused kernel that integrates the entire MoE inference pipeline into a single execution unit. It fuses Expert Parallel (EP) dispatch, the first linear layer (Linear 1), SwiGLU activation with requantization, the second linear layer (Linear 2), and EP combine [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh21-77](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh#L21-L77)

 
## Warp Specialization and Three-Role Architecture

 The `sm100_fp8_fp4_mega_moe_impl` kernel utilizes a complex warp specialization strategy to manage the multi-stage compute pipeline. Threads are divided into three distinct functional roles to ensure maximum hardware utilization and overlap [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh33-48](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh#L33-L48)

 
### 1. Dispatch Warps (`kNumDispatchWarps`)

 These warps manage the data movement and synchronization for the EP-dispatch phase [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh44](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh#L44-L44) They handle the communication and buffer management required to bring tokens from the symmetric buffer into the local compute pipeline by pulling source token and top-k indices [deep_gemm/include/deep_gemm/layout/mega_moe.cuh158-165](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/layout/mega_moe.cuh#L158-L165)

 
### 2. MMA Non-Epilogue Warps (`kNumMMANonEpilogueWarps`)

 These warps are responsible for the core UMMA (Unbound Matrix Multiply-Accumulate) operations on the SM100 architecture [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh45](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh#L45-L45) They execute the GEMM logic for both Linear 1 and Linear 2. For the FP8/FP4 variant, they process FP8 inputs and FP4 weights [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh165-167](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh#L165-L167)

 
### 3. Epilogue Warp Groups (`kNumEpilogueWarpgroups`)

 The epilogue warps handle the final stages of the computation, including the SwiGLU activation, FP8 requantization (to prepare for Linear 2), and the final EP-combine write-backs [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh46-47](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh#L46-L47)

## Mixed-Precision Compute Pipeline

 The Mega MoE implementation is specifically designed for mixed FP8 and FP4 precision, a key feature of the Blackwell architecture.

 
 - **Inputs:** Primary inputs are in FP8 (E4M3) format [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh97-101](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh#L97-L101)
 - **Weights:** Expert weights are stored in FP4 format to reduce memory bandwidth [csrc/jit_kernels/impls/sm100_fp8_fp4_mega_moe.hpp178-185](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/sm100_fp8_fp4_mega_moe.hpp#L178-L185)
 - **Scaling Factors:** Uses the SM100-specific UE8M0 format. The kernel handles complex scaling factor layouts, including 2D TMA descriptors for both activation and weight scales [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh61-72](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh#L61-L72)
 - **Fused Activation:** SwiGLU activation is performed immediately after Linear 1. The result is requantized back to FP8 to serve as the input for Linear 2 [csrc/jit_kernels/impls/sm100_fp8_fp4_mega_moe.hpp211-215](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/sm100_fp8_fp4_mega_moe.hpp#L211-L215)

## Symmetric Buffer and NVLink Overlap

 A critical component of Mega MoE performance is the `SymmBuffer` and the `MegaMoEScheduler`. This system enables the overlap of NVLink communication with GEMM computation.

 
### Symmetric Buffer Layout

 The `SymmBuffer` provides a globally consistent memory space across multiple GPUs [deep_gemm/include/deep_gemm/layout/sym_buffer.cuh1-12](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/layout/sym_buffer.cuh#L1-L12) This allows for efficient EP dispatch and combine using `nvlink_barrier` which performs cross-rank signaling via `ptx::red_add_rel_sys` [deep_gemm/include/deep_gemm/comm/barrier.cuh60-69](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/comm/barrier.cuh#L60-L69)

 
### MegaMoEScheduler

 The `MegaMoEScheduler` manages the distribution of work blocks across SMs [deep_gemm/include/deep_gemm/scheduler/mega_moe.cuh1-14](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/scheduler/mega_moe.cuh#L1-L14) It is designed to prioritize blocks that can overlap with incoming or outgoing data via NVLink.

## Execution Flow: The Two-Linear-Layer Fusion

 The kernel executes two distinct linear layers in a single grid launch. This fusion is enabled by SM100's Tensor Memory (TMEM), which acts as a high-speed scratchpad for intermediate results [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh79-80](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh#L79-L80)

 
 - **Linear 1:** Performs computation using `tensor_map_l1_acts` and `tensor_map_l1_weights` [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh60-63](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh#L60-L63)
 - **Activation & Requant:** The output of Linear 1 is processed by SwiGLU and requantized to FP8. This is stored in `l2_acts` which uses a specialized TMA descriptor with halved swizzle mode for the post-SwiGLU output [csrc/jit_kernels/impls/sm100_fp8_fp4_mega_moe.hpp202-207](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/sm100_fp8_fp4_mega_moe.hpp#L202-L207)
 - **Linear 2:** Performs the second GEMM using the requantized FP8 inputs and `tensor_map_l2_weights` [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh65-68](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_mega_moe.cuh#L65-L68)
 - **EP-Combine:** Final results are written back using `TokenSrcMetadata` to map pooled tokens back to their original rank and index [deep_gemm/include/deep_gemm/layout/mega_moe.cuh34-173](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/layout/mega_moe.cuh#L34-L173)
