  This document describes how DeepGEMM organizes tensor data in memory, manages alignment constraints for optimal hardware performance, and schedules blocks to maximize cache utilization. Topics include tensor memory layouts (row-major vs column-major), TMA alignment requirements, scaling factor storage formats, UE8M0 packing, memory swizzling patterns, and the symmetric memory layout used by Mega MoE.

 
## Tensor Memory Layouts

 DeepGEMM supports different tensor memory layouts based on the operation type and hardware architecture. The layout determines how matrix elements are stored in global memory and accessed via TMA (Tensor Memory Accelerator).

 
### Layout Types: Major::K vs Major::MN

 The `cute::UMMA::Major` enum defines two fundamental layout types:

 
 - **Major::K**: Elements are contiguous along the K dimension (inner product dimension).
 - **Major::MN**: Elements are contiguous along the M or N dimension (outer dimensions).

## TMA Alignment Requirements

 TMA (Tensor Memory Accelerator) imposes strict alignment constraints on tensor dimensions to enable efficient coalesced memory transfers.

 
### TMA Alignment Rules

 The minimum TMA box size is 16 bytes. For a given data type, the aligned dimension must satisfy: `aligned_elements = ceil_div(16_bytes, element_size_bytes)`

 DeepGEMM provides utility functions to calculate and enforce these alignments:

 
 - `get_tma_aligned_size(size, element_size)`: Returns the smallest size $\ge$ `size` that satisfies the 16-byte alignment [csrc/jit_kernels/impls/smxx_layout.hpp116](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L116-L116)
 - `get_mn_major_tma_aligned_tensor`: Transforms a tensor into a column-major (MN-major) layout with the required TMA padding [csrc/jit_kernels/impls/smxx_layout.hpp120-153](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L120-L153)
 
 
### TMA Descriptor Creation

 TMA descriptors are created via `CUtensorMap` structures using CUDA driver APIs. The key function is `make_tma_2d_desc`:

 
| Parameter | Description |
|---|---|
| gmem_inner_dim | Global memory inner dimension size |
| gmem_outer_dim | Global memory outer dimension size |
| smem_inner_dim | Shared memory inner dimension size (tile size) |
| smem_outer_dim | Shared memory outer dimension size (tile size) |
| gmem_outer_stride | Stride in elements between outer dimension entries |
| swizzle_mode | Memory swizzling pattern (0, 32, 64, 128 bytes) |

 The descriptor is encoded using `lazy_cuTensorMapEncodeTiled` with L2 promotion set to 256 bytes [csrc/jit_kernels/impls/runtime_utils.hpp143-147](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/runtime_utils.hpp#L143-L147) For FP4, specific alignment checks ensure the inner dimension is a multiple of 64B [csrc/jit_kernels/impls/runtime_utils.hpp124-130](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/runtime_utils.hpp#L124-L130)

## Scaling Factor Layouts and UE8M0 Packing

 Scaling factors (SF) are used in FP8/FP4 GEMM operations. The storage format differs significantly between architectures and involves specific packing kernels.

 
### SM90 Scaling Factor Format (FP32)

 On SM90, scaling factors are typically stored as **FP32 values**. The `TransposeFP32Runtime` [csrc/jit_kernels/impls/smxx_layout.hpp15-42](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L15-L42) is used to transform standard row-major SFs into the MN-major TMA-aligned layout required by the GEMM kernels. The implementation uses a shared memory buffer with padding to avoid bank conflicts [deep_gemm/include/deep_gemm/impls/smxx_layout.cuh10-50](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/smxx_layout.cuh#L10-L50)

 
### SM100 Scaling Factor Format (UE8M0)

 SM100 (Blackwell) introduces the **UE8M0** format for scaling factors. In this format, four scales are packed into a single 32-bit `uint32_t`. DeepGEMM provides high-performance CUDA kernels for this transformation:

 
 - **`TransposeAndPackFP32IntoUE8M0Runtime`**: A fused kernel that reads FP32 scales, transposes them to MN-major, and packs them into UE8M0 `uint32_t` [csrc/jit_kernels/impls/smxx_layout.hpp44-75](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L44-L75) It handles PSUM layout gaps by writing safe finite scale codes [deep_gemm/include/deep_gemm/impls/smxx_layout.cuh140-142](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/smxx_layout.cuh#L140-L142)
 - **`PackFP32IntoUE8M0Runtime`**: A specialized kernel for grouped GEMMs that handles variable group sizes (K-grouped) while packing [csrc/jit_kernels/impls/smxx_layout.hpp77-106](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L77-L106)

## Shared Memory Swizzling and TMEM (SM100)

 SM100 introduces Tensor Memory (TMEM) and specific swizzling patterns for the UMMA (Universal Matrix Multiply-Accumulate) instructions.

 
### UMMA Descriptors and Swizzling

 On SM100, `cute::UMMA::SmemDescriptor` is used to describe shared memory layouts to the hardware. The `make_umma_desc` function [deep_gemm/include/deep_gemm/common/sm100_utils.cuh93-132](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/common/sm100_utils.cuh#L93-L132) configures these descriptors:

 
 - **Swizzle Modes**: Supported modes include `SWIZZLE_32B`, `SWIZZLE_64B`, and `SWIZZLE_128B` [deep_gemm/include/deep_gemm/common/sm100_utils.cuh62-79](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/common/sm100_utils.cuh#L62-L79)
 - **Base 32B**: A special layout mode `SWIZZLE_128B_BASE32B` is used for certain float types or specific MN-major configurations [deep_gemm/include/deep_gemm/common/sm100_utils.cuh68-71](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/common/sm100_utils.cuh#L68-L71)

## Symmetric Memory Layout (Mega MoE)

 For multi-GPU MoE inference, DeepGEMM utilizes a symmetric memory layout to optimize peer-to-peer NVLink accesses.

 
### SymBuffer

 The `SymBuffer` struct [deep_gemm/include/deep_gemm/layout/sym_buffer.cuh10-42](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/layout/sym_buffer.cuh#L10-L42) facilitates addressing across multiple GPU ranks. It stores a `base` address for the local rank and an array of `offsets` to other ranks.

 
 - **Mapping**: The `map` function [deep_gemm/include/deep_gemm/layout/sym_buffer.cuh34-40](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/layout/sym_buffer.cuh#L34-L40) allows a kernel to calculate the pointer for a specific `dst_rank_idx` by adding the pre-computed offset to a local pointer.
 - **Capacity**: It supports up to 72 ranks [deep_gemm/include/deep_gemm/layout/sym_buffer.cuh7](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/layout/sym_buffer.cuh#L7-L7)
 
 This layout is fundamental to the Mega MoE implementation, allowing kernels to fetch expert weights or dispatch tokens from remote GPUs with minimal overhead.

## TMA Utilities and Descriptor Manipulation

 DeepGEMM provides low-level utilities for interacting with the TMA hardware across SM90 and SM100.

 
 - **`tma_copy`**: A unified interface for 2D and 3D TMA loads, supporting multicast and 2-SM (SM100) load variants [deep_gemm/include/deep_gemm/common/tma_utils.cuh17-88](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/common/tma_utils.cuh#L17-L88)
 - **Descriptor Modification**: Kernels can dynamically update descriptors in shared memory using `tensor_map_replace_global_addr_in_smem` [deep_gemm/include/deep_gemm/common/tma_utils.cuh100-104](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/common/tma_utils.cuh#L100-L104) or `tensor_map_replace_global_inner_dim_stride_in_smem` [deep_gemm/include/deep_gemm/common/tma_utils.cuh106-114](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/common/tma_utils.cuh#L106-L114)
 - **Fencing**: Synchronization between TMA and other units is handled via `tensor_map_release_cta` and `tensor_map_acquire_cta` [deep_gemm/include/deep_gemm/common/tma_utils.cuh91-98](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/common/tma_utils.cuh#L91-L98)
 - **Matrix Load/Store**: Specialized PTX wrappers like `SM90_U32x4_LDSM_N` [deep_gemm/include/deep_gemm/ptx/ld_st.cuh31-38](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/ld_st.cuh#L31-L38) and `SM100_U8x8_STSM_T` [deep_gemm/include/deep_gemm/ptx/ld_st.cuh76-84](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/ld_st.cuh#L76-L84) are used for efficient shared memory matrix access.
