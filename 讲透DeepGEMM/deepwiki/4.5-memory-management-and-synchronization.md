  This page documents the memory management strategies and synchronization primitives used in DeepGEMM's CUDA kernel implementations. It covers the Tensor Memory Accelerator (TMA) for asynchronous data transfers, multi-stage pipeline buffering for overlapping computation and memory access, barrier-based synchronization patterns (including grid and NVLink barriers), shared memory allocation strategies, and SM100's dedicated Tensor Memory (TMEM).

 For information about the overall kernel architecture and implementations, see [Kernel Implementations](https://deepwiki.com/deepseek-ai/DeepGEMM/4-kernel-implementations). For SM90-specific optimizations, see [SM90 Kernel Implementations](https://deepwiki.com/deepseek-ai/DeepGEMM/4.1-sm90-kernel-implementations). For SM100-specific features including TMEM usage, see [SM100 Kernel Implementations](https://deepwiki.com/deepseek-ai/DeepGEMM/4.2-sm100-kernel-implementations).

 The memory hierarchy consists of:

 
 - **Global Memory (GMEM)**: Input matrices, scaling factors, and output results.
 - **Shared Memory (SMEM)**: 228KB on-chip staging area for multi-stage pipeline buffering. DeepGEMM uses specialized `ld_shared` and `st_shared` functions for low-level access, including bulk stores [deep_gemm/include/deep_gemm/ptx/ld_st.cuh101-160](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/ld_st.cuh#L101-L160)
 - **Tensor Memory (TMEM)**: Dedicated accumulator storage on SM100 architectures.
 - **Register File**: Thread-local storage for accumulators (SM90) and intermediate values.
 - **Workspace**: Global memory counters used for `grid_sync` and `nvlink_barrier` [deep_gemm/include/deep_gemm/comm/barrier.cuh47-89](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/comm/barrier.cuh#L47-L89)
 
 
## TMA (Tensor Memory Accelerator)

 The Tensor Memory Accelerator is a hardware unit that performs asynchronous, efficient data transfers between global memory and shared memory. TMA operations require proper descriptor creation and alignment.

 
### TMA Operations and PTX Wrappers

 DeepGEMM wraps TMA and asynchronous memory operations in PTX-level utilities. For example, `st_async_cluster` allows storing data to a remote CTA's shared memory within a cluster, mapped via `mapa_shared` [deep_gemm/include/deep_gemm/ptx/ld_st.cuh156-173](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/ld_st.cuh#L156-L173)

 
## Barrier Synchronization Patterns

 DeepGEMM implements several synchronization patterns to coordinate threads within a CTA, across a grid, and across multiple GPUs.

 
### Intra-CTA and Cluster Barriers

 
 - **Cluster Sync**: `cluster_sync_with_relaxed_arrive` provides a faster alternative to `cute::cluster_sync` by using `cute::cluster_arrive_relaxed` followed by `cute::cluster_wait` [deep_gemm/include/deep_gemm/comm/barrier.cuh14-19](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/comm/barrier.cuh#L14-L19)
 - **PTX Barriers**: Low-level wrappers for `sync_aligned` (using `bar.sync`) and `sync_unaligned` (using `barrier.sync`) are used for thread synchronization [deep_gemm/include/deep_gemm/ptx/utils.cuh22-29](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/utils.cuh#L22-L29)
 
 
### Grid Synchronization

 The `grid_sync` function provides a global barrier across all SMs in a grid using atomic counters in the workspace [deep_gemm/include/deep_gemm/comm/barrier.cuh21-44](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/comm/barrier.cuh#L21-L44)

 
 - **Implementation**: It uses `ptx::atomic_add_rel` to increment a counter and `ptx::ld_acq` to poll for completion [deep_gemm/include/deep_gemm/comm/barrier.cuh30-35](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/comm/barrier.cuh#L30-L35)
 - **Timeout**: A 60s timeout mechanism (defined by `kNumTimeoutCycles`) prevents kernel hangs during synchronization [deep_gemm/include/deep_gemm/comm/barrier.cuh12-36](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/comm/barrier.cuh#L12-L36)
 
 
### NVLink Cross-Rank Barrier

 For multi-GPU operations like Mega MoE, `nvlink_barrier` provides a cross-rank synchronization mechanism [deep_gemm/include/deep_gemm/comm/barrier.cuh46-89](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/comm/barrier.cuh#L46-L89)

 
 - **Symmetric Memory**: It uses `sym_buffer.map` to resolve remote pointers for signaling via NVLink [deep_gemm/include/deep_gemm/comm/barrier.cuh68](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/comm/barrier.cuh#L68-L68)
 - **Signal Logic**: Only SM 0 participates in the cross-rank signal exchange. It updates a signal pointer (determined by a phase and status) using `ptx::red_add_rel_sys` and waits for arrival using `ptx::ld_acq_sys` [deep_gemm/include/deep_gemm/comm/barrier.cuh60-76](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/comm/barrier.cuh#L60-L76)
 
 
## Shared Memory Management

 Shared memory is managed through low-level PTX instructions for maximum control over data movement and swizzling patterns.

 
### Shared Memory Load/Store

 DeepGEMM provides overloaded `ld_shared` and `st_shared` functions for various data types (`float`, `float2`, `float4`, `uint32_t`, `uint4`, `__int128_t`) [deep_gemm/include/deep_gemm/ptx/ld_st.cuh101-153](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/ld_st.cuh#L101-L153)

 
### Matrix Instructions (LDSM/STSM)

 The library utilizes hardware-specific matrix load and store instructions for Hopper and Blackwell:

 
 - **SM90 (Hopper)**: `SM90_U32x2_LDSM_N` and `SM90_U32x4_LDSM_N` for loading tiles [deep_gemm/include/deep_gemm/ptx/ld_st.cuh25-41](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/ld_st.cuh#L25-L41) `SM90_U32x2_STSM_T` and `SM90_U32x4_STSM_T` are used for efficient transposed shared memory stores [deep_gemm/include/deep_gemm/ptx/ld_st.cuh55-77](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/ld_st.cuh#L55-L77)
 - **SM100 (Blackwell)**: `SM100_U8x4_STSM_T` and `SM100_U8x8_STSM_T` support `stmatrix.sync.aligned.m16n8` instructions for FP8/FP4 mixed-precision layouts [deep_gemm/include/deep_gemm/ptx/ld_st.cuh79-99](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/ld_st.cuh#L79-L99)
 
 
## Pipeline Staging and Register Communication

 DeepGEMM kernels use register-level communication primitives to optimize data flow between threads:

 
 - **Exchange**: The `exchange` template uses `__shfl_sync` to swap data between lanes within a warp [deep_gemm/include/deep_gemm/ptx/utils.cuh31-41](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/utils.cuh#L31-L41)
 - **SM Indexing**: `get_sm_idx` and `get_lane_idx` retrieve hardware identifiers for work distribution and synchronization [deep_gemm/include/deep_gemm/ptx/utils.cuh11-21](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/utils.cuh#L11-L21)
 
 
## Epilogue Pipeline

 The epilogue pipeline handles the final processing of results, including activations and accumulation.

 
### Epilogue Configuration

 The JIT system selects epilogue types, defaulting to `epilogue::transform::EpilogueIdentity` if not specified [csrc/jit_kernels/impls/epilogue.hpp8-10](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/epilogue.hpp#L8-L10)

 
### SM100 Specific Math and Accumulation

 On SM100, the epilogue may involve fused cast and add operations. DeepGEMM uses the `add.rn.f32.bf16` PTX instruction to perform fused (cast + add) operations directly on the hardware [deep_gemm/include/deep_gemm/ptx/utils.cuh52-61](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/utils.cuh#L52-L61) It also provides `cvt_relu_bf16x2_f32` which uses the `cvt.rn.relu.bf16x2.f32` instruction on SM100 for optimized activation handling [deep_gemm/include/deep_gemm/ptx/utils.cuh43-51](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/ptx/utils.cuh#L43-L51)
