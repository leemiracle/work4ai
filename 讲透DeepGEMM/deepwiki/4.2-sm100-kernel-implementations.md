  This page documents the CUDA kernel implementations specifically optimized for NVIDIA's Blackwell architecture (SM100/SM101). These kernels leverage SM100-specific hardware features such as Unified MMA (UMMA) instructions, Tensor Memory (TMEM) accumulators, UTCCP transpose units, and 2x1SM multicast capabilities. For SM90 (Hopper) kernels, see [SM90 Kernel Implementations](https://deepwiki.com/deepseek-ai/DeepGEMM/4.1-sm90-kernel-implementations).

## SM100 GEMM Kernel Variants

 SM100 provides specialized GEMM kernels for different data types and scaling granularities.

 
### 1D1D Implementation (FP8/FP4 Mixed-Precision)

 The `sm100_fp8_fp4_gemm_1d1d_impl` kernel performs block-scaled matrix multiplication. It is a unified implementation supporting pure FP8 and mixed FP8/FP4 variants where scaling factors are applied per block (e.g., 1x32 or 1x128).

 **Key characteristics:**

 
 - **Scaling format**: Packed UE8M0 (`cutlass::float_ue8m0_t`) with 4 scales per `uint32_t` [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh88-89](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L88-L89)
 - **Granularity Support**: Supports `kGranK` of 32 or 128 [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh67-68](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L67-L68)
 - **Block K constraint**: `BLOCK_K == 128` to align with hardware scaling requirements [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh55](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L55-L55)
 - **TMEM Mapping**: Allocates specific TMEM columns for scaling factors (SFA and SFB) alongside the accumulation columns [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh97-102](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L97-L102)

### BF16 GEMM Implementation

 The `sm100_bf16_gemm_impl` performs BF16 GEMM without scaling factors. It includes a unique "Stage Merging" optimization to reduce synchronization overhead.

 **Stage Merging Logic:** When `kNumStages >= 8`, the kernel merges stages to increase the effective `BLOCK_K`, reducing the frequency of `umma_arrive()` synchronization [deep_gemm/include/deep_gemm/impls/sm100_bf16_gemm.cuh43-50](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_bf16_gemm.cuh#L43-L50)

 **Tensor Core Utilization Control:** This kernel supports `kTensorCoreUtilControl` to manage hardware throughput and potential frequency drops [deep_gemm/include/deep_gemm/impls/sm100_bf16_gemm.cuh33](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_bf16_gemm.cuh#L33-L33)

### TF32 Hyperconnection GEMM

 The `sm100_tf32_hc_prenorm_gemm_impl` is a specialized kernel for DeepSeek hyperconnections. It performs a TF32 GEMM while simultaneously computing squared sums for normalization [deep_gemm/include/deep_gemm/impls/sm100_tf32_hc_prenorm_gemm.cuh43-47](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_tf32_hc_prenorm_gemm.cuh#L43-L47)

 **Key characteristics:**

 
 - **Warp Specialization**: Dispatches warps into `kNumMMAThreads` and `kNumCastAndReduceThreads` roles [deep_gemm/include/deep_gemm/impls/sm100_tf32_hc_prenorm_gemm.cuh41-42](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_tf32_hc_prenorm_gemm.cuh#L41-L42)

### UMMA Instructions and Tensor Memory (TMEM)

 SM100 uses Unified MMA (UMMA) instructions that accumulate results directly into **Tensor Memory (TMEM)** instead of registers.

 
```

```

 **TMEM Allocation:** TMEM is allocated dynamically within the kernel using `cute::TMEM::Allocator1Sm` or `cute::TMEM::Allocator2Sm` [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh43](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L43-L43) The kernel ensures valid column counts (between 32 and 512) before allocation [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh103](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L103-L103)

### UE8M0 Scaling Factor Handling

 For FP8/FP4 GEMM, scaling factors (SF) are stored in the specialized `UE8M0` format and managed through TMEM.

 
 - **Format**: Scales are typically packed as 4 elements per 32-bit word [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh88-89](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L88-L89)
 - **TMEM Buffering**: Scaling factors for both A and B matrices are loaded into TMEM columns designated by `kTmemStartColOfSFA` and `kTmemStartColOfSFB` [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh101-102](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L101-L102)
 - **Hardware Integration**: The UMMA hardware applies these scaling factors during the MMA operation using the indices stored in TMEM via `make_runtime_instr_desc_with_sf_id` [deep_gemm/include/deep_gemm/mma/sm100.cuh151-155](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/mma/sm100.cuh#L151-L155)

### 2x1SM Multicast

 SM100 supports launching two CTAs that share data via TMA multicast. This is controlled by the `kNumMulticast` parameter [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh27](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L27-L27)

 
 - **Cluster Sync**: When multicast is used (`kNumMulticast > 1`), `comm::cluster_sync_with_relaxed_arrive()` is called to synchronize the cluster before TMEM allocation [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh106](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L106-L106)
 - **Load Balancing**: `LOAD_BLOCK_M` and `LOAD_BLOCK_N` are adjusted based on whether multicast is performed on matrix A or B [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh53-54](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L53-L54)

## Epilogue and Synchronization

 The epilogue in SM100 kernels handles moving data from TMEM back to global memory via shared memory staging.

 
 - **Descriptor Prefetch**: TMA descriptors for A, B, and CD (and scaling factors for FP8/FP4) are prefetched by `warp_idx == 0` at kernel start [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh114-120](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L114-L120)
 - **Pipelining**: The epilogue uses `kNumTMAStoreStages` (typically 2) to overlap the movement from TMEM to shared memory with the movement from shared memory to global memory via TMA [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh75](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L75-L75)
 - **Swizzle Modes**: Supports various `kSwizzleCDMode` configurations to optimize L2 cache access and bank conflict reduction [deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh24](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_fp8_fp4_gemm_1d1d.cuh#L24-L24)
