  This page documents the layout transformation and utility functions provided by DeepGEMM for preparing tensors for optimal GEMM execution. These functions handle TMA (Tensor Memory Accelerator) alignment, scaling factor layout transformations, and data packing required by different GPU architectures.

 
## Overview

 Layout utilities serve two critical roles in DeepGEMM:

 
 - **TMA Alignment**: Ensuring tensors meet 512-byte alignment requirements for optimal TMA performance on Hopper (SM90) and Blackwell (SM100) architectures [csrc/jit_kernels/impls/smxx_layout.hpp116](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L116-L116)
 - **Scaling Factor Transformation**: Converting FP32 scaling factors into architecture-specific formats, such as FP32 for SM90 or packed UE8M0 for SM100 [csrc/jit_kernels/impls/smxx_layout.hpp159-175](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L159-L175)
 
 These transformations are automatically invoked by high-level GEMM operations but can also be called directly via the Python API for pre-processing tensors [deep_gemm/utils/layout.py1-18](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/utils/layout.py#L1-L18)

 **Key Functions Overview**

 
| Function | Purpose | Architecture |
|---|---|---|
| get_tma_aligned_size | Calculate TMA-aligned dimension size | SM90, SM100 |

| get_k_grouped_mn_major_tma_aligned_packed_ue8m0_tensor | Pack K-grouped scaling factors into UE8M0 | SM100 |

 The Tensor Memory Accelerator (TMA) requires tensor dimensions to be aligned to 512-byte boundaries for efficient asynchronous memory transfers. The alignment calculation depends on the element size of the data type.

### TMA Alignment Functions

 
 - **`get_tma_aligned_size(size, element_size)`**: Returns the minimum size $\ge$ `size` such that `size * element_size` is a multiple of 512 bytes [csrc/jit_kernels/impls/smxx_layout.hpp116](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L116-L116)
 - **`get_mn_major_tma_aligned_tensor(sf)`**: Takes a scaling factor tensor and ensures it is stored in MN-major layout with TMA-aligned strides. If the input is already MN-major, it verifies the alignment; otherwise, it performs a transpose using the `TransposeFP32Runtime` kernel [csrc/jit_kernels/impls/smxx_layout.hpp120-153](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L120-L153)
 - **`get_mk_alignment_for_contiguous_layout()`**: Returns the required alignment for M and K dimensions to ensure compatibility with contiguous memory layouts in grouped GEMMs. This is often aliased to `get_m_alignment_for_contiguous_layout` or `get_k_alignment_for_contiguous_layout` [deep_gemm/utils/layout.py14-21](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/utils/layout.py#L14-L21)

### Implementation Details

 
 - **`TransposeFP32Runtime`**: A JIT-compiled kernel that performs an MN-major transpose for FP32 scaling factors [csrc/jit_kernels/impls/smxx_layout.hpp15-42](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L15-L42)
 - **`PackFP32IntoUE8M0Runtime`**: A JIT-compiled kernel that converts FP32 scaling factors into UE8M0 and packs them while applying the required TMA-aligned layout [csrc/jit_kernels/impls/smxx_layout.hpp77-106](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L77-L106)
 - **`get_mn_major_tma_aligned_packed_ue8m0_tensor`**: Orchestrates the packing of scaling factors. It uses a Python-side fallback `get_mn_major_tma_aligned_packed_ue8m0_tensor_torch` for non-contiguous or unaligned cases, but defaults to the high-performance `PackFP32IntoUE8M0Runtime` kernel for standard contiguous inputs [csrc/jit_kernels/impls/smxx_layout.hpp155-181](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L155-L181)
 - **`get_k_grouped_mn_major_tma_aligned_packed_ue8m0_tensor`**: Specifically handles packing for MoE kernels where scaling factors are grouped along the K-dimension. It supports both standard and `psum` (partial sum) layouts required by SM100 UMMA instructions [tests/test_layout.py93-98](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_layout.py#L93-L98) [tests/test_layout.py108-144](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_layout.py#L108-L144)

### Implementation Details

 
 - **Conversion**: The FP32 exponent is extracted by right-shifting the integer representation of the float by 23 bits. In the PyTorch fallback, this is implemented as `ue8m0_tensor = (x.view(torch.int) >> 23).to(torch.uint8)` [tests/test_layout.py24](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_layout.py#L24-L24) [csrc/jit_kernels/impls/smxx_layout.hpp159](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L159-L159)
 - **Packing**: Four UE8M0 values (8-bit each) are packed into a single 32-bit integer. This results in a 4x reduction in memory footprint for scaling factors compared to FP32 [csrc/jit_kernels/impls/smxx_layout.hpp164-171](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L164-L171) [tests/test_layout.py32-36](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_layout.py#L32-L36)
 - **Layout**: The packed tensor is stored in an MN-major layout with TMA-aligned strides to satisfy SM100 hardware requirements. This is enforced by `get_mn_major_tma_aligned_packed_ue8m0_tensor` which creates the output with specific strides [csrc/jit_kernels/impls/smxx_layout.hpp173-176](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_layout.hpp#L173-L176)
 - **K-Grouped Packing**: For MoE kernels using K-grouped scaling factors, the library provides specialized packing that handles irregular K-segments while maintaining TMA alignment for each group [tests/test_layout.py93-98](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_layout.py#L93-L98) [tests/test_layout.py131-141](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/tests/test_layout.py#L131-L141)

## Quantization Utilities

 DeepGEMM provides several Python utilities in `deep_gemm.utils.math` for quantizing tensors to FP8 and FP4 formats, which are essential for testing and preparation.

 
 - **`per_token_cast_to_fp8`**: Quantizes a 2D tensor to FP8 using per-token (row-wise) scaling factors. Supports UE8M0 packing for SM100 [deep_gemm/utils/math.py26-49](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/utils/math.py#L26-L49)
 - **`per_block_cast_to_fp8`**: Quantizes a 2D tensor to FP8 using block-wise scaling factors based on `gran_k` [deep_gemm/utils/math.py62-72](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/utils/math.py#L62-L72)
 - **`per_token_cast_to_fp4`**: Quantizes a 2D tensor to FP4 E2M1 format, packing two FP4 values into a single `int8` byte [deep_gemm/utils/math.py96-123](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/utils/math.py#L96-L123)
 - **`ceil_to_ue8m0`**: Utility to round a float tensor to the nearest value representable in UE8M0 (exponent-only) format [deep_gemm/utils/math.py13-16](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/utils/math.py#L13-L16)
