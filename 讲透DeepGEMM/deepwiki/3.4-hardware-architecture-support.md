  This page explains DeepGEMM's architecture-specific optimizations for SM90 (Hopper) and SM100 (Blackwell) GPUs. The system uses runtime architecture detection to select appropriate kernels and applies architecture-specific heuristics through the `ArchSpec` abstraction pattern.

 DeepGEMM's architecture support includes:

 
 - Runtime architecture detection via `DeviceRuntime` [csrc/jit/device_runtime.hpp14-134](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L14-L134)
 - Architecture-specific compilation flags in `Compiler` and its derived classes [csrc/jit/compiler.hpp23-164](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/compiler.hpp#L23-L164)
 - Hardware-specific kernel implementations with different instruction sets (WGMMA for SM90, UMMA for SM100).
 - Architecture-specific heuristics for block sizes, clusters, and pipeline stages via `SM90ArchSpec` [csrc/jit_kernels/heuristics/sm90.hpp13-118](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm90.hpp#L13-L118) and `SM100ArchSpec` [csrc/jit_kernels/heuristics/sm100.hpp14-148](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm100.hpp#L14-L148)
 - A compatibility layer for different CUDA and PyTorch versions [csrc/utils/compatibility.hpp1-17](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/utils/compatibility.hpp#L1-L17)
 
 
## Runtime Architecture Detection

 DeepGEMM detects the target GPU architecture at runtime using the `DeviceRuntime` class, which wraps CUDA device queries and provides architecture information throughout the system. A global `device_runtime` instance is initialized lazily [csrc/jit/device_runtime.hpp136](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L136-L136)

 The `DeviceRuntime` class provides architecture query methods to the JIT system:

 
| Method | Return Type | Purpose | Example Output |
|---|---|---|---|
| get_arch_pair() | std::pair<int, int> | Returns compute capability as (major, minor) csrc/jit/device_runtime.hpp83-86 | (9, 0) for H100 |
| get_arch_major() | int | Returns major compute capability csrc/jit/device_runtime.hpp99-101 | 9 for Hopper, 10 for Blackwell |
| get_arch(number_only, support_arch_family) | std::string | Returns architecture string for compiler csrc/jit/device_runtime.hpp88-97 | "90a", "100f" |

 The `get_arch()` method has special handling for SM100:

 
 - For SM100 devices (major=10, minor≠1), it returns `"100"` (if `number_only` is true), `"100f"` (if `support_arch_family` is true), or `"100a"` otherwise [csrc/jit/device_runtime.hpp91-95](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L91-L95)
 - For other architectures, it returns the major and minor versions concatenated with an `"a"` suffix (e.g., `"90a"` for SM90) [csrc/jit/device_runtime.hpp96](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L96-L96)

## Architecture-Specific Heuristics (ArchSpec)

 DeepGEMM uses an `ArchSpec` pattern to encapsulate hardware-specific constraints and tuning parameters. This allows the heuristic system to select optimal block sizes and cluster configurations based on the detected hardware. The `get_best_config` function uses these specs to evaluate candidates [csrc/jit_kernels/heuristics/common.hpp13-52](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/common.hpp#L13-L52)

 
### SM90 (Hopper) Heuristics

 The `SM90ArchSpec` handles Hopper-specific constraints:

 
 - **Block Sizes**: Favoring `BlockM` of 64 or 128 [csrc/jit_kernels/heuristics/sm90.hpp23](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm90.hpp#L23-L23) Smaller blocks (16, 32) are used for small `M` to avoid TMA L2 OOB bounds [csrc/jit_kernels/heuristics/sm90.hpp24-26](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm90.hpp#L24-L26)
 - **Clusters**: Supports Cluster M/N of up to 2, ensuring total cluster size is 2 [csrc/jit_kernels/heuristics/sm90.hpp71-75](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm90.hpp#L71-L75)
 - **Pipeline**: Requires at least 3 stages to hide TMA latency, or 4 stages for smaller matrices [csrc/jit_kernels/heuristics/sm90.hpp106-108](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm90.hpp#L106-L108)
 
 
### SM100 (Blackwell) Heuristics

 The `SM100ArchSpec` adapts to Blackwell's unified matrix architecture:

 
 - **Block K**: Fixed at `128 / element_size` [csrc/jit_kernels/heuristics/sm100.hpp29](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm100.hpp#L29-L29)
 - **Swizzle Alignment**: Enforces strict swizzle alignment (64B or 128B) depending on the data type (e.g., 128B for `kPackedFP4`) [csrc/jit_kernels/heuristics/sm100.hpp96-112](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm100.hpp#L96-L112)
 - **TMEM Constraints**: Validates that the combination of `UMMA_N` and scaling factor columns does not exceed Tensor Memory capacity (512 columns) [csrc/jit_kernels/heuristics/sm100.hpp123-128](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm100.hpp#L123-L128)

## Architecture-Specific Compilation

 The `Compiler` class and its specialized implementations use architecture information from `DeviceRuntime` to generate appropriate GPU code.

 The `Compiler` base class sets up general flags, including C++ standard (defaulting to C++20 via `DG_JIT_CPP_STANDARD`) and ptxas optimizations [csrc/jit/compiler.hpp53-62](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/compiler.hpp#L53-L62) It configures register usage levels (`--ptxas-options=--register-usage-level=10`) and diagnostic suppression [csrc/jit/compiler.hpp55-57](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/compiler.hpp#L55-L57)

 Key compilation features:

 
 - **JIT Caching**: Kernels are cached based on a signature that includes the architecture flags [csrc/jit/compiler.hpp101-106](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/compiler.hpp#L101-L106)
 - **Disassembly**: Uses `cuobjdump` to provide SASS disassembly for debugging if `DG_JIT_DUMP_SASS` is set [csrc/jit/compiler.hpp151-161](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/compiler.hpp#L151-L161)

## Device Management and cuBLASLt

 The `DeviceRuntime` class also manages the `cublasLt` handle and workspace, which is used for fallback or comparison purposes.

 
 - **Handle Management**: DeepGEMM can use a self-managed `cublasLtHandle_t` or a PyTorch-managed one [csrc/jit/device_runtime.hpp31-37](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L31-L37) By default, it uses a self-managed handle to avoid CPU overhead found in some PyTorch versions [csrc/jit/device_runtime.hpp32-34](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L32-L34)
 - **Workspace**: A fixed workspace of 32MB (`kCublasLtWorkspaceSize`) is allocated [csrc/jit/device_runtime.hpp20](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L20-L20) For `compute-sanitizer` compatibility, `DG_USE_TEMP_CUBLASLT_WORKSPACE` can be set to create workspace tensors on each call, avoiding issues during CUDA driver shutdown [csrc/jit/device_runtime.hpp39-42](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/device_runtime.hpp#L39-L42)

## Compatibility Layer

 DeepGEMM includes a compatibility layer in `csrc/utils/compatibility.hpp` to handle variations in environment, CUDA versions, and PyTorch versions.

 
| Feature | Macro | Requirement |
|---|---|---|
| FP8 Support | DG_FP8_COMPATIBLE | PyTorch ≥ 2.1 csrc/utils/compatibility.hpp8 |
| TMA Support | DG_TENSORMAP_COMPATIBLE | CUDA ≥ 12.1 csrc/utils/compatibility.hpp11 |
| Advanced cuBLASLt | DG_CUBLASLT_ADVANCED_FEATURES_COMPATIBLE | CUDA Runtime ≥ 11.8 csrc/utils/compatibility.hpp17 |
| PyTorch cuBLASLt | PYTORCH_SUPPORTS_GET_CUBLASLT_HANDLE | PyTorch ≥ 2.3 csrc/jit/device_runtime.hpp10 |
