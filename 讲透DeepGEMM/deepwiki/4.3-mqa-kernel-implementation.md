## Purpose and Scope

 This page documents the Multi-Query Attention (MQA) logits kernels in DeepGEMM, which compute attention scores in FP8 and mixed FP8/FP4 precision for transformer models. These kernels perform the operation `Q @ K^T` with per-head ReLU weighting and per-token scaling, optimized for both Hopper (SM90) and Blackwell (SM100) architectures.

 The implementation covers several variants:

 
 - **Standard MQA**: For contiguous KV sequences [[deep_gemm/include/deep_gemm/impls/sm90_fp8_mqa_logits.cuh30-38](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm90_fp8_mqa_logits.cuh#L30-L38) [deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh61-68](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L61-L68)].
 - **Paged MQA**: For paged KV cache management in inference [[deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh30-38](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh#L30-L38) [deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh16-17](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L16-L17)].
 - **Mixed Precision**: FP8/FP4 variants for Blackwell (SM100) enabled via the `kIsFP4` template parameter in the core implementation [[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh69](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L69-L69)].
 
 A key feature is the support for the **weighted ReLU logit formula** used in DeepSeek v3.2 lightning indexer, where logits are computed as `ReLU(Q @ K^T) * head_weight * scale_kv`.

 
## Architecture Overview

 The MQA kernel employs a **warp-specialized architecture** where different warp groups perform distinct roles: TMA loading, UMMA instruction issuing (SM100), and math/epilogue computation.

 **Key Design Principles:**

 
 - **Producer-Consumer Pattern**: TMA warp loads data into SMEM; UMMA/Math warps consume it.
 - **Register Allocation**: Specialized warps use minimal registers (e.g., 56-64), while math warps allocate more (up to 224 on SM100) to handle accumulation and activation [[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh144-145](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L144-L145) [deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh131-132](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh#L131-L132)].
 - **Persistent Scheduling**: SM100 kernels use a block scheduler to process multiple query tiles per SM for better load balancing [[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh146-163](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L146-L163)].

## Warp Group Specialization

 The kernel assigns roles via `warp_idx` and `warpgroup_idx` [[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh72-73](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L72-L73) [deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh46-47](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh#L46-L47)].

 
### TMA Load Warp

 **Identification:** `warp_idx == kSpecWarpStart` (where `kSpecWarpStart` follows math warpgroups) [[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh75](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L75-L75) [deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh54](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh#L54-L54)].

 **Responsibilities:**

 
 - **TMA Descriptor Prefetching**: Uses `cute::prefetch_tma_descriptor` to warm up L1 cache for Q, KV, Scales, and Weights [[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh76-83](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L76-L83) [deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh55-58](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh#L55-L58)].
 - **Barrier Initialization**: Initializes `full_q_barriers`, `empty_q_barriers`, and KV barriers [[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh114-129](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L114-L129) [deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh108-123](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh#L108-L123)].
 - **Data Orchestration**: Issues asynchronous TMA loads for the pipeline.
 
 
### UMMA Warp (SM100 Only)

 **Identification:** `warp_idx == kSpecWarpStart + 1` [[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh114-134](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L114-L134)].

 **Responsibilities:**

 
 - **Tensor Memory Allocation**: Allocates TMEM columns for accumulators and scaling factors using `cute::TMEM::Allocator1Sm().allocate(kNumTmemCols, &smem.tmem_ptr_in_smem)` [[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh134-135](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L134-L135)].
 - **Instruction Issuing**: Executes Blackwell UMMA instructions (via `tcgen05`) to perform matrix multiplication directly into TMEM.
 
 
### Math Warp Groups

 **Identification:** `warpgroup_idx < kNumMathWarpGroups` [[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh60](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L60-L60) [deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh51](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh#L51-L51)].

 **Responsibilities:**

 
 - **Epilogue Processing**: Reads dot products from TMEM/Registers, applies ReLU, and multiplies by `smem_weights` and `smem_kv_scales`.
 - **Type Conversion**: Converts internal high-precision accumulators to `logits_dtype_t` (e.g., FP32 or FP16) for storage [[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh61](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L61-L61) [deep_gemm/include/deep_gemm/impls/sm90_fp8_mqa_logits.cuh28](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_mqa_logits.cuh#L28-L28)].

### Synchronization Barriers

 The kernels utilize `cutlass::arch::ClusterTransactionBarrier` for fine-grained producer-consumer synchronization [[deep_gemm/include/deep_gemm/layout/mqa_logits.cuh19](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/layout/mqa_logits.cuh#L19-L19) [deep_gemm/include/deep_gemm/impls/sm90_fp8_mqa_logits.cuh46](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/sm90_fp8_mqa_logits.cuh#L46-L46)].

 
 - **Full Barriers**: Signaled by TMA when data is ready in SMEM [[deep_gemm/include/deep_gemm/layout/mqa_logits.cuh50-52](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/layout/mqa_logits.cuh#L50-L52)].
 - **Empty Barriers**: Signaled by Math warps when they finish consuming a stage, allowing reuse of the buffer [[deep_gemm/include/deep_gemm/layout/mqa_logits.cuh51-53](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/layout/mqa_logits.cuh#L51-L53)].
 - **TMEM Barriers**: (SM100 only) Synchronize the UMMA hardware with the Math warps reading from TMEM [[deep_gemm/include/deep_gemm/layout/mqa_logits.cuh54-55](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/layout/mqa_logits.cuh#L54-L55)].

## Paged MQA Implementation

 The paged variant handles non-contiguous KV caches by using a `block_table` and `context_lens` [[deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh31-33](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh#L31-L33)].

 
### Scheduler and Metadata

 The kernel uses specialized schedulers to map GPU blocks to the correct batch and KV block indices.

 
 - **SM90 Scheduler**: `sched::SM90PagedMQALogitsScheduler` handles block mapping and TMA descriptor preparation for paged layouts [[deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh138-139](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh#L138-L139)].
 - **KV Splitting**: Supports `SPLIT_KV` to distribute the KV dimension of a single sequence across multiple math warpgroups for improved parallelism [[deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh26-53](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh#L26-L53)].
 - **Metadata Kernel**: A separate `sm90_paged_mqa_logits_metadata` kernel prepares the scheduling information before the main attention kernel runs [[csrc/jit_kernels/impls/sm90_fp8_mqa_logits.hpp181-184](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[csrc/jit_kernels/impls/sm90_fp8_mqa_logits.hpp#L181-L184)].
 
 
### Next-N Optimization

 The paged kernel supports `kNextN`, allowing it to process multiple query tokens (Next-N) simultaneously against the same KV cache block, maximizing data reuse [[deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh22-64](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/[deep_gemm/include/deep_gemm/impls/sm90_fp8_paged_mqa_logits.cuh#L22-L64)].

## Weighted ReLU Logit Formula

 The kernel implements the specific activation and weighting logic required for DeepSeek lightning indexers.


 **Implementation Details:**

 
 - **Activation**: The ReLU and weighting are typically fused into the epilogue.
