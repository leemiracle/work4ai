## Purpose and Scope

 This page documents all General Matrix Multiplication (GEMM) functions exposed by the DeepGEMM Python API. These functions implement high-performance matrix-matrix multiplication operations with support for FP8, BF16, and FP4 data types, targeting both standard dense workloads and specialized Mixture-of-Experts (MoE) scenarios.

### Layout and Architecture Support Matrix

 DeepGEMM utilizes NVIDIA's TMA (Tensor Memory Accelerator) and UMMA (Universal Matrix Multiply-Accumulate) instructions. Support for specific layouts varies by hardware generation.

 
| Operation Type | Layout | SM90 (Hopper) | SM100 (Blackwell) | Data Types |
|---|---|---|---|---|
| Standard GEMM | NT | ✅ | ✅ | FP8, BF16, FP4 (SM100) |
| Standard GEMM | NN | ❌ | ✅ | FP8, BF16, FP4 |
| Standard GEMM | TN | ❌ | ✅ | FP8, BF16, FP4 |
| Standard GEMM | TT | ❌ | ✅ | FP8, BF16, FP4 |
| M-Grouped | NT | ✅ | ✅ | FP8, BF16 |

| K-Grouped | NT | ✅ | ❌ | FP8 |

## Standard GEMM Operations

 Standard GEMM operations perform dense matrix multiplication on single matrix pairs. These functions handle the dispatch between SM90 and SM100 implementations and manage scaling factor transformations.

 
### FP8 and FP4 GEMM

 The `fp8_fp4_gemm_*` family of functions supports both FP8 (E4M3) and FP4 (on SM100) data types.

 
#### `fp8_fp4_gemm_nt`

 Performs `D = C + A @ B.T` where A and B are FP8/FP4 tensors [csrc/apis/gemm.hpp73-81](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/gemm.hpp#L73-L81)

 **Parameters:**

 
 - `a`: `pair<Tensor, Tensor>` - Input A data and its scaling factor (SFA).
 - `b`: `pair<Tensor, Tensor>` - Input B data and its scaling factor (SFB).
 - `d`: `Tensor` - Output tensor (in-place). Must be BF16 or FP32 [csrc/apis/gemm.hpp99](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/gemm.hpp#L99-L99)
 - `c`: `optional<Tensor>` - Optional accumulation tensor.
 - `recipe`: `optional<tuple<int, int, int>>` - Manual block size override `(M, N, K)`.
 - `recipe_a`/`recipe_b`: `optional<tuple<int, int>>` - Manual scaling factor granularity override.
 - `compiled_dims`: `string` - JIT compilation hints for M, N, K.
 - `disable_ue8m0_cast`: `bool` - If true, skips automatic conversion to SM100's packed UE8M0 scaling format [csrc/apis/gemm.hpp107-108](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/gemm.hpp#L107-L108)
 
 **Data Flow and Dispatch:**

 
 - **Layout Check:** Verifies if A/B are K-major (required for FP8 on certain paths) [csrc/apis/gemm.hpp85-88](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/gemm.hpp#L85-L88)
 - **Early Return:** Handles cases where M, N, or K are 0 [csrc/apis/gemm.hpp102-103](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/gemm.hpp#L102-L103)
 - **SF Transformation:** Calls `layout::transform_sf_pair_into_required_layout` to align scaling factors for TMA [csrc/apis/gemm.hpp106-108](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/gemm.hpp#L106-L108)
 - **Dispatch:** 
 - **SM90:** Dispatches to `sm90_fp8_gemm_1d1d` (per-token/per-channel scale) or `sm90_fp8_gemm_1d2d` (block-scaled) [csrc/apis/gemm.hpp110-117](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/gemm.hpp#L110-L117)
 - **SM100:** Dispatches to `sm100_fp8_fp4_gemm_1d1d` [csrc/apis/gemm.hpp118-120](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/gemm.hpp#L118-L120)

## Grouped GEMM Operations

 Grouped GEMMs are designed for Mixture-of-Experts (MoE). They allow processing multiple experts with different M (tokens per expert) or K (weight gradient computation) dimensions in a single kernel launch.

 
### M-Grouped GEMM (Forward/Inference)

 DeepGEMM supports two layout types for M-grouped GEMMs:

 
 - **Contiguous:** All tokens for all experts are concatenated in a single buffer. Each expert segment must be aligned to the GEMM M block size.
 - **Masked:** Tensors have fixed sizes (max tokens), and a mask/count tensor defines the actual work per expert. This is optimized for inference decoding.
 
 
#### `m_grouped_fp8_fp4_gemm_nt_contiguous`

 Used when tokens are already sorted and packed by expert.

 
 - **`grouped_layout`**: A tensor containing layout metadata for each expert in the M-dimension.
 - **Implementation**: Validates grouped arguments using `check_k_grouped_args` for alignment and shape consistency [csrc/apis/gemm.hpp48-69](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/gemm.hpp#L48-L69)

### K-Grouped GEMM (Backward Weight Gradient)

 Specifically for computing expert weight gradients where each expert's contribution has a different K dimension.

 
#### `k_grouped_fp8_gemm_nt_contiguous` (SM90)

 
 - **`ks_cpu`**: Optional vector of K-dimensions for each group.
 - **`grouped_layout`**: Contiguous tensor describing the grouping.
 - **Alignment**: Requires K-dimension to be a multiple of `k_alignment` [csrc/apis/gemm.hpp62-63](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/gemm.hpp#L62-L63)

## cuBLASLt Wrapper

 For baseline comparisons or operations not yet optimized in JIT kernels, DeepGEMM provides a wrapper around `cublasLt`.

 
#### `cublaslt_gemm`

## Layout and Scaling Requirements

 
### Scaling Factor Transformation

 DeepGEMM kernels require scaling factors (SF) to be TMA-aligned. The transformation process involves:

 
 - **Alignment**: Ensuring tensors meet `k_alignment` and TMA constraints [csrc/apis/gemm.hpp52-53](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/gemm.hpp#L52-L53)
 - **UE8M0 Casting**: For SM100, scaling factors are often cast to UE8M0 format unless `disable_ue8m0_cast` is set [csrc/apis/gemm.hpp107-108](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/gemm.hpp#L107-L108)
 
 
### Vectorization and TMEM

 DeepGEMM utilizes vectorized memory access and Tensor Memory (TMEM) on SM100.

 
 - **Vectorized Access**: Supports 4, 8, and 16-byte vectorization for global memory loads [csrc/jit_kernels/impls/sm100_fp8_fp4_gemm_1d1d.hpp1-10](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/sm100_fp8_fp4_gemm_1d1d.hpp#L1-L10)
 - **TMEM Alignment**: Tensor memory columns are aligned to power-of-two boundaries for efficient UMMA operations [csrc/jit_kernels/impls/sm100_fp8_fp4_gemm_1d1d.hpp1-10](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/sm100_fp8_fp4_gemm_1d1d.hpp#L1-L10)
