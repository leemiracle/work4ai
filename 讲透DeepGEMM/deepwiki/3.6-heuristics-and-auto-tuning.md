  This page explains the heuristic system in DeepGEMM used to select optimal kernel configurations, including block sizes, pipeline stages, thread counts, and shared memory allocation. The system supports both SM90 (Hopper) and SM100 (Blackwell) architectures, as well as the specialized Mega MoE kernels.

 
## Overview

 DeepGEMM employs a heuristic-driven approach to determine the best `GemmConfig` for a given problem shape $(M, N, K)$. Unlike exhaustive search tuners, DeepGEMM uses architecture-specific constraints and performance models to prune the search space of tile sizes and pipeline depths.

## Heuristic Workflow

 The selection process is encapsulated in the `get_best_config<ArchSpec>` function. It iterates through valid candidate configurations and selects the one that maximizes estimated performance (typically by minimizing the number of waves or maximizing occupancy).

## Architecture-Specific Heuristics

 
### SM90 (Hopper)

 The `SM90ArchSpec` focuses on WGMMA (Warp Group MMA) alignment and TMA (Tensor Memory Accelerator) efficiency.

 
 - **Block Sizes**: Typically $64, 128$ for $M$ (with $16, 32$ for small shapes) and multiples of $16$ for $N$ up to $256$. [csrc/jit_kernels/heuristics/sm90.hpp18-57](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm90.hpp#L18-L57)
 - **Constraints**: 1D2D kernels have specific unroll requirements where $N$ and $K$ blocks must be compatible to avoid bank conflicts. [csrc/jit_kernels/heuristics/sm90.hpp84-85](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm90.hpp#L84-L85)
 - **Multicast**: Logic determines if TMA multicast is legal based on $N$ divisibility and GPU SM count. [csrc/jit_kernels/heuristics/sm90.hpp71-79](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm90.hpp#L71-L79)
 - **Pipeline**: To hide TMA latency, the system requires at least 3 stages, or 4 stages for smaller matrices ($< 128 \times 192$). [csrc/jit_kernels/heuristics/sm90.hpp106-108](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm90.hpp#L106-L108)
 
 
### SM100 (Blackwell)

 `SM100ArchSpec` heuristics account for UMMA instructions, Tensor Memory (TMEM), and UE8M0 scaling factors.

 
 - **Swap A/B**: SM100 supports swapping A and B operands to optimize for different layout majors. [csrc/jit_kernels/heuristics/sm100.hpp47-59](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm100.hpp#L47-L59)
 - **TMEM Constraints**: Validates that the combined size of UMMA $N$ tiles and scaling factor columns does not exceed TMEM capacity (512 entries). [csrc/jit_kernels/heuristics/sm100.hpp123-128](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm100.hpp#L123-L128)
 - **Block K**: Fixed based on the element size of the MMA kind (e.g., $128 / \text{get_element_size(mma_kind)}$). [csrc/jit_kernels/heuristics/sm100.hpp28-29](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm100.hpp#L28-L29)
 - **Swizzling**: Enforces 128B swizzle modes for $K$-major layouts to ensure high memory throughput. [csrc/jit_kernels/heuristics/sm100.hpp133-137](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/sm100.hpp#L133-L137)

## Mega MoE Heuristics

 The Mega MoE system uses a specialized heuristic to select `MegaMoEConfig`, which governs the fused EP-dispatch, dual-linear compute, and EP-combine pipeline.

 
### Block and Wave Configuration

 
 - **Block M**: Selected via `get_block_config_for_mega_moe` based on `num_expected_tokens_per_expert`. Values range from 16 (very small batches) to 192 (prefill). [csrc/jit_kernels/heuristics/mega_moe.hpp81-102](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/mega_moe.hpp#L81-L102)
 - **Block K**: Adjusted based on the number of bytes per element for the specific `MmaKind`. [csrc/jit_kernels/heuristics/mega_moe.hpp103](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/mega_moe.hpp#L103-L103)
 - **Warp Specialization**: The heuristic assigns specific counts to `num_dispatch_threads`, `num_non_epilogue_threads` (MMA), and `num_epilogue_threads`. [csrc/jit_kernels/heuristics/mega_moe.hpp38-39](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/mega_moe.hpp#L38-L39)
 
 
### Shared Memory Allocation

 `get_pipeline_config_for_mega_moe` partitions shared memory into:

 
 - **Dispatch Region**: Expert counts and send buffers for NVLink communication. [csrc/jit_kernels/heuristics/mega_moe.hpp132-137](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/mega_moe.hpp#L132-L137)
 - **C/D Output Region**: Stages for TMA stores, handling both FP8 L1 and BF16 L2 outputs. [csrc/jit_kernels/heuristics/mega_moe.hpp141-143](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/mega_moe.hpp#L141-L143)
 - **Barriers**: Synchronization objects for dispatch, TMEM, and epilogue warps. [csrc/jit_kernels/heuristics/mega_moe.hpp150-151](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/mega_moe.hpp#L150-L151)
 - **Scaling Factors**: Buffers for `sf_block_m` and `sf_block_n` aligned to UTCCP 128-element granularity. [csrc/jit_kernels/heuristics/mega_moe.hpp161-162](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/mega_moe.hpp#L161-L162)

## Shared Memory and Threading

 The system calculates shared memory requirements dynamically based on the architecture's pipeline stages and alignment needs.

 
| Component | SM90 Calculation | SM100 Calculation |
|---|---|---|
| C/D Buffers | Aligned to 1024B for TMA swizzling. csrc/jit_kernels/heuristics/sm90.hpp154-155 | Scaled by swizzle_cd_mode. csrc/jit_kernels/heuristics/sm100.hpp236-237 |
| Barriers | num_stages * 8 * 2. csrc/jit_kernels/heuristics/sm90.hpp156 | Includes SF and TMEM barriers: num_stages * 8 * 3 + 2 * 8 * 2 + 8. csrc/jit_kernels/heuristics/sm100.hpp240-241 |
| Block Sizes | $M \in {16, 32, 64, 128, 256}$. csrc/jit_kernels/heuristics/sm90.hpp18-30 | $M \in [step, 256]$ where $step = \text{lcm}(16, \text{block_m_multiple_of})$. csrc/jit_kernels/heuristics/sm100.hpp52-55 |

 
## Debugging and Environment Variables

 
### DG_PRINT_CONFIGS

 When `DG_PRINT_CONFIGS` (or `DG_JIT_DEBUG`) is enabled, `get_best_config` prints the selected `GemmConfig` and `LayoutInfo` for every unique `GemmDesc` encountered. This is implemented using a static `std::unordered_set<std::string> printed` to ensure each configuration is logged only once. Sources: [csrc/jit_kernels/heuristics/common.hpp40-50](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/common.hpp#L40-L50)

 
### Auto-tuning Control

 The `HeuristicsRuntime` class provides global control over heuristic behavior:

 
 - `set_ignore_compile_dims`: Ignores specific dimension constraints during configuration selection. [csrc/jit_kernels/heuristics/runtime.hpp18-20](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/runtime.hpp#L18-L20)
 - `set_block_size_multiple_of`: Forces block $M$ and $N$ to be multiples of specific values. [csrc/jit_kernels/heuristics/runtime.hpp26-29](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/runtime.hpp#L26-L29)
 - `set_mk_alignment_for_contiguous_layout`: Configures alignment for $M$-grouped GEMMs. [csrc/jit_kernels/heuristics/runtime.hpp39-41](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/heuristics/runtime.hpp#L39-L41)
