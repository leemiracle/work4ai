## Purpose and Scope

 This document provides a comprehensive overview of DeepGEMM's system architecture, describing how the major components interact to provide high-performance GPU matrix operations. This page focuses on the structural organization, component responsibilities, and data flow through the system from Python API calls to GPU kernel execution.

 DeepGEMM is designed for clean and efficient General Matrix Multiplications (GEMMs), supporting FP8, BF16, and FP4 for both normal and Mixture-of-Experts (MoE) grouped scenarios. It leverages a lightweight Just-In-Time (JIT) module to compile all kernels at runtime, matching or exceeding expert-tuned libraries while maintaining a simplified codebase.

### Layer 3: JIT Compilation System

 The JIT system handles the transformation of C++ templates into optimized GPU binaries (`.cubin`).

 
#### Compiler and Driver Interaction

 DeepGEMM supports two primary ways to interact with the CUDA driver: the CUDA Runtime API and the CUDA Driver API. It uses lazy loading for driver symbols to minimize overhead [csrc/jit/handle.hpp13-21](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/handle.hpp#L13-L21)

 
| Feature | Implementation Detail | Source |
|---|---|---|
| Lazy Loading | `dlopen("libcuda.so.1", RTLD_LAZY | RTLD_LOCAL)` |
| Driver API Wrapper | DECL_LAZY_CUDA_DRIVER_FUNCTION macro | csrc/jit/handle.hpp24-34 |
| Driver Functions | cuModuleLoad, cuModuleGetFunction, cuLibraryLoadFromFile | csrc/jit/handle.hpp39-42 |
| Runtime API | cudaLibraryLoadFromFile, cudaLibraryGetKernel | csrc/jit/handle.hpp62-63 |

 The choice between APIs is controlled by the `DG_JIT_USE_RUNTIME_API` environment variable/macro [setup.py25-31](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/setup.py#L25-L31) [csrc/jit/handle.hpp48](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/handle.hpp#L48-L48)

 
#### Compilation Pipeline

 DeepGEMM uses `nvrtc` for runtime compilation and `cudart` for execution. The build process in `setup.py` prepares include directories for third-party dependencies like CUTLASS and fmt to ensure they are available to the JIT compiler at runtime [setup.py149-166](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/setup.py#L149-L166)

### Layer 4: Runtime Management

 This layer manages hardware abstraction and the logical execution flow of kernels.

 
#### Kernel Handle Management

 DeepGEMM abstracts kernel management through `LibraryHandle` and `KernelHandle` types. Depending on the CUDA version and configuration, these map to either Driver API types (`CUmodule`, `CUfunction`, `CUlibrary`) or Runtime API types (`cudaLibrary_t`, `cudaKernel_t`) [csrc/jit/handle.hpp51-52](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/handle.hpp#L51-L52) [csrc/jit/handle.hpp119-131](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/handle.hpp#L119-L131)

 
#### Kernel Launch Configuration

 The `construct_launch_config` function prepares the execution parameters:

 
 - **Shared Memory**: Sets the dynamic shared memory size attribute for the kernel [csrc/jit/handle.hpp78-79](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/handle.hpp#L78-L79) [csrc/jit/handle.hpp177-178](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/handle.hpp#L177-L178)
 - **Clusters**: Configures `cudaLaunchAttributeClusterDimension` for SM90/SM100 multi-processor clusters [csrc/jit/handle.hpp94-98](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/handle.hpp#L94-L98)
 - **Programmatic Stream Serialization (PDL)**: Enables dependency-based scheduling between kernels if requested [csrc/jit/handle.hpp101-105](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/handle.hpp#L101-L105)
 
 **Sources**: [csrc/jit/handle.hpp51-180](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit/handle.hpp#L51-L180)

### Layer 5: Kernel Execution

 DeepGEMM provides highly optimized kernels for SM90 (Hopper) and SM100 (Blackwell).

 
#### Architecture Specifics

 
 - **SM90**: Utilizes WGMMA (Warpgroup Matrix Multiply-Accumulate) and TMA (Tensor Memory Accelerator).
 - **SM100**: Utilizes UMMA and Tensor Memory (TMEM). It specifically handles the **UE8M0** packed scaling factor format and supports mixed-precision FP8/FP4 operations.
