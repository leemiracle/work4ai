# Attention Operations

  This page documents the specialized attention operations provided by DeepGEMM. These operations are optimized for Multi-Query Attention (MQA) and related patterns commonly used in large language models like DeepSeek-V3 and v3.2. For general matrix multiplication operations, see [GEMM Operations](https://deepwiki.com/deepseek-ai/DeepGEMM/2.1-gemm-operations). For batched Einstein summation operations, see [Einsum Operations](https://deepwiki.com/deepseek-ai/DeepGEMM/2.3-einsum-operations).

 
## Overview

 DeepGEMM provides specialized attention-related operations, including legacy FP8-only kernels and new mixed-precision FP8/FP4 variants for Blackwell (SM100).

 
| Operation | Purpose | Key Features |
|---|---|---|
| fp8_gemm_nt_skip_head_mid | GEMM with selective head skipping | Optimized epilogue for attention projection layers csrc/apis/attention.hpp19-25 |
| fp8_mqa_logits | Multi-Query Attention logits | Standard MQA with per-token KV scaling csrc/apis/attention.hpp76-82 |
| fp8_paged_mqa_logits | Paged MQA logits | Efficient KV cache management with block table indirection csrc/apis/attention.hpp165-173 |
| fp8_fp4_mqa_logits | Mixed FP8/FP4 MQA logits | Support for FP4-quantized Q and KV on SM100 csrc/apis/attention.hpp76-83 |
| fp8_fp4_paged_mqa_logits | Mixed FP8/FP4 Paged MQA logits | Support for FP4-quantized paged KV cache deep_gemm/__init__.py65 |
| get_paged_mqa_logits_metadata | Metadata for Paged MQA | Pre-calculates work distribution and prefix sums csrc/apis/attention.hpp157-163 |

 All operations support FP8 (E4M3) or FP4 computation with scaling factors, targeting Hopper (SM90) and Blackwell (SM100) architectures.

## fp8_gemm_nt_skip_head_mid

 
### Purpose

 This operation performs FP8 GEMM with a specialized epilogue that skips certain attention heads in the middle dimension. This pattern is used in attention projection layers where the output dimension is divided into three segments: left heads, middle heads (skipped), and right heads [csrc/apis/attention.hpp48-50](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L48-L50)

### Shape Requirements

 
 - **Input A:** `[M, K]` in FP8 E4M3 format [csrc/apis/attention.hpp38-43](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L38-L43)
 - **Input B:** `[N, K]` in FP8 E4M3 format (transposed during computation) [csrc/apis/attention.hpp39-44](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L39-L44)

 - **Head splits:** `(left, mid, right)` where `N % (left + right) == 0` [csrc/apis/attention.hpp48-49](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L48-L49)
 
 
### Implementation Details

 The function dispatches to different GEMM kernels based on architecture and scaling factor layout:

 
 - **SM90 with FP32 scales and gran_k != 1:** Uses `sm90_fp8_gemm_1d2d` with `EpilogueHeadSplits` [csrc/apis/attention.hpp64-66](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L64-L66)
 - **SM100 with UE8M0 packed scales:** Uses `sm100_fp8_fp4_gemm_1d1d` with `EpilogueHeadSplits` [csrc/apis/attention.hpp67-70](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L67-L70)
 
 The epilogue type is formatted as `EpilogueHeadSplits<left, mid, right>` and compiled into the kernel [csrc/apis/attention.hpp63](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L63-L63)

## MQA Logits (FP8 and Mixed FP8/FP4)

 
### Purpose

 Computes attention logits for Multi-Query Attention where each query attends to a variable-length sequence of key-value pairs. The mixed FP8/FP4 variant is specifically optimized for Blackwell (SM100) using 4-bit quantization for high-throughput inference.

### Mixed-Precision Support

 The kernel detects FP4 usage based on the presence of scaling factors for Q (`q_sf.has_value()`) [csrc/apis/attention.hpp86-89](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L86-L89)

 
 - **FP4 Path:** Q and KV must use `kPackedFP4` data type and `torch.kInt32` scaling factors [csrc/apis/attention.hpp97-116](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L97-L116)
 - **FP8 Path:** Q and KV use `torch.kFloat8_e4m3fn` with `torch.kFloat` scaling factors [csrc/apis/attention.hpp123-137](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L123-L137)

### Operation Description

 The function computes a weighted ReLU MQA logit:

 
```
logits[q_idx, kv_idx] = sum_h(relu(Q[q_idx, h, :] @ KV[kv_idx, :].T) * weights[q_idx, h]) * kv_scales[kv_idx]
```

 
 - Each query `q_idx` attends to keys `[cu_seq_len_k_start[q_idx], cu_seq_len_k_end[q_idx])`.
 - ReLU is applied per-head before weighting.
 - Results are scaled by per-KV scaling factors.

## Paged MQA Logits

 
### Purpose

 Computes MQA logits for paged key-value cache, where KV pairs are stored in non-contiguous memory blocks. This is used for efficient KV cache management in serving systems like the DeepSeek lightning indexer [csrc/apis/attention.hpp165-173](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L165-L173)

 
### Metadata and Scheduling

 DeepGEMM uses a two-step process for paged attention:

 
 - **`get_paged_mqa_logits_metadata`**: A metadata kernel (`smxx_paged_mqa_logits_metadata`) calculates the work distribution across SMs. It computes prefix sums and varlen atom token starts in shared memory [csrc/jit_kernels/impls/smxx_fp8_paged_mqa_logits.hpp11-52](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_fp8_paged_mqa_logits.hpp#L11-L52) [csrc/jit_kernels/impls/smxx_fp8_paged_mqa_logits.hpp66-67](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_fp8_paged_mqa_logits.hpp#L66-L67)
 - **`fp8_fp4_paged_mqa_logits`**: The main computation kernel uses the `schedule_meta` to process tiles [csrc/jit_kernels/impls/smxx_fp8_paged_mqa_logits.hpp86-159](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/jit_kernels/impls/smxx_fp8_paged_mqa_logits.hpp#L86-L159)

## Clean Logits Option

 Both MQA operations support a `clean_logits` flag. When enabled, it triggers a post-processing kernel (`smxx_clean_logits`) to zero out invalid logit entries beyond the actual context length for each sequence, ensuring correctness for subsequent softmax operations [csrc/apis/attention.hpp134-136](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L134-L136) [csrc/apis/attention.hpp249-252](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/csrc/apis/attention.hpp#L249-L252)

 
### Clean Logits Implementation

 The kernel `smxx_clean_logits` fills a shared memory buffer with negative infinity and uses `SM90_BULK_COPY_S2G` to overwrite invalid regions in the output logits tensor [deep_gemm/include/deep_gemm/impls/smxx_clean_logits.cuh23-51](https://github.com/deepseek-ai/DeepGEMM/blob/559d79fb/deep_gemm/include/deep_gemm/impls/smxx_clean_logits.cuh#L23-L51)
