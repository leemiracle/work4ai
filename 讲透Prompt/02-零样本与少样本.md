# 02 - 零样本与少样本

> 讲透Prompt 第 02 章 | 实验：E2（`experiments/e2_fewshot.py`，results/e2_fewshot.json/png）+ E3 的 few-direct 臂 | 素材：`_source/techniques/zeroshot.zh.mdx`、`_source/techniques/fewshot.zh.mdx`

## 一、直觉：示例是"卷子上的答题卡"

给模型看几个"输入→输出"的例子，就像考前发答题卡：它学到的第一是**格式**（答案长什么样、写在哪），第二才是**任务**（这题该怎么做）。E2 的随机标签消融把这两层拆开：把示例的标签全部打乱（正变负、负变正），如果模型学的是"任务"，正确率应该崩到随机；如果学的是"格式"，正确率应该几乎不动。

**实测：glm-4-flash 打乱标签后 100% 正确（完全无视标签），Qwen2.5-0.5B 掉到 75%（还看一点标签）**——Min et al.（2022, 据 _source 引用）的结论在 2026 的 API 模型上更极端成立：**强模型的 in-context learning 大头是格式对齐，不是任务学习**。

## 二、数学：为什么标签打乱了还有用

把 few-shot 看成对输出分布的条件化。示例 $E$ 出现时，模型输出 $y$ 的概率：

$$P(y \mid x, E) \propto P(y \mid x) \cdot e^{\lambda \cdot \text{format}(y, E)}$$

示例把"格式正确"的输出簇整体抬升（$\text{format}$ 项），而标签信息只通过 $P(y|x)$ 的任务通路起作用。当模型的任务能力已经够强（glm-4-flash 做二分类），任务通路饱和，剩下的增益全来自格式通路——所以打乱标签不掉分。当模型弱（Qwen 0.5B），它对任务通路也不确定，会被错误标签带偏一点。

这就预告了 E3 的陷阱：**如果示例只给答案不给推理（few-direct），你强化的是格式模仿——模型学会的是"抄数字"**。glm-4-flash 在 10 道算术题上：zero-direct 40% → few-direct **10%**。示例里"答案是：12"的 12，教会它输出一个像答案的数字，而不是做计算。

## 三、代码：E2 的 k 曲线 + 消融

```bash
cd 讲透Prompt/experiments && python3 -u e2_fewshot.py   # ~4 min
```

任务：中文短评情感二分类（k = 示例条数；正确示例 vs 随机标签消融）。

| k | Qwen2.5-0.5B | glm-4-flash |
|---|--------------|-------------|
| 0 | 0% | 55% |
| 1 | **80%** | 95% |
| 2+ | 90% | 95% |

三条读数：

1. **k=0→1 是悬崖，k≥2 是平台**。一条示例提供格式+任务的完整骨架；第二条以后边际收益趋零。工程含义：**k=2 是性价比点，k>5 基本是安慰剂**（还占上下文预算——讲透Context E1 的成本）。
2. **few-shot 救的是弱模型**（0%→80%，+80pp）；强模型自带格式理解（55%→95%，+40pp 且 k=1 就到位）。
3. **随机标签消融分出了两个世界**：glm 100%（纯格式学习者）、Qwen 75%（还带一点任务学习）。模型越强，示例里的"知识"越不重要，"格式"越重要——与讲透Agent harness 章的"强模型只需要接口约定"互证。

## 四、few-shot 的四门功课（指南清单 + 我们的注）

| 维度 | 指南建议 | 我们的注（E2/E3 证据） |
|------|---------|----------------------|
| 示例质量 > 数量 | ✓ | k=2 已饱和 |
| 示例要覆盖边界情况 | ✓ | 分类任务的负类示例至少 1 条 |
| 格式一致 | ✓ | 这是示例的主要通路 |
| **示例要带推理** | 指南未强调 | **E3 铁证：无推理的示例在推理任务上是毒药（40%→10%）** |

## 五、不足与批判

- E2 的分类任务太简单（强模型 k=0 已 55%）。few-shot 的真实价值区在**格式复杂**的任务（JSON 嵌套、代码生成、Lean）——那儿的悬崖更陡。
- 示例有**位置效应**：首尾示例权重更高（ACL 2026 Lost in the Prompt Order：CQO vs QOC 差 14pp，见 10 章）。k=2 恰好规避了排序问题，k 大了要考虑示例顺序。
- 示例即上下文污染源：示例里的数字会被抄进答案（E3 的 few-direct 错误模式：题目说 240 页，答案就写 240）。

## 六、应用清单

- 新任务冷启动：先 k=2 正确示例跑基线，再决定加不加。
- **推理/算术任务：示例必须带完整推理链**（否则见 E3 翻车），或者干脆别给示例、直接上 CoT 指令（03 章）。
- 弱模型（<1B 本地部署）：few-shot 是救命稻草；强模型：一条就够，预算省下来给任务描述。
