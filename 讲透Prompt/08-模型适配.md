# 08 - ★ 模型适配：不同模型怎么吃 prompt

> 讲透Prompt 第 08 章（重点章）| 实验：E9（`experiments/e9_adapt.py`，results/e9_adapt.json/png）+ E3 双模型矩阵 + E11 策略矩阵 | 素材：`_source/guides_reasoning-llms.en.mdx`（模型适配金矿）、Google Cloud "Thinking vs Reasoning"；论文：2505.11423（reasoning 伤指令跟随）、ACL 2026 Lost in the Prompt Order、arXiv 2608.18539（交互分解降敏）

## 一、直觉：同一个方子，不同体质

前面七章每个技巧都埋了同一句伏笔："要看模型"。本章收账。Prompt 技巧不是物理定律，是**模型体质的函数**：few-shot 是弱模型的救命稻草、强模型的冗余开销；CoT 咒语是弱模型的杠杆、thinking 模型的干扰源。把 2023 年 GPT-3.5 时代的技巧清单直接套在 2026 年的 thinking 模型上，轻则浪费预算，重则反向扣分。

## 二、机理：为什么技巧不跨模型迁移

1. **能力水位决定技巧收益**。zero-cot 触发的是预训练里"草稿纸模式"的检索——模型没见过足够的草稿纸（0.5B），咒语无效（E3：Qwen zero-cot 17%）；见过（flash+），一句就爆（+60pp）。
2. **约束叠加脆弱性随规模非对称**。"一步步思考"叠加在格式约束上：弱模型反正顾不上格式（IF 恒低，咒语无感）；强模型本来能同时满足双约束，被咒语把算力引向推理、格式反而崩（E9：glm-4.7 IF 3/3→1/3）。
3. **thinking 模型自带推理，外挂 CoT 是重复指令**。Google Cloud 官方建议直接写："用 thinking 模型时删掉手写 step-by-step"。机理：内部 reasoning 流已经占了推理预算，外挂指令与之竞争输出格式——模型要同时服务两个主人。
4. **2026 新证据链**：2505.11423 系统测得 reasoning 模式**降低指令跟随**（长 CoT 训练挤掉了格式遵循能力）；ACL 2026 实测 prompt 里选项顺序（CQO vs QOC）能差 14pp（因果注意力的位置效应）；2608.18539 把敏感性分解为四个可降因素（SFT/规模/dense 注意力/few-shot 格式锚定）——**"敏感"不是玄学，是可分解、可工程化的性质**。

## 三、代码：E9 适配矩阵

```bash
cd 讲透Prompt/experiments && python3 -u e9_adapt.py   # 4配置×3风格×6任务, ~7 min
```

四配置（glm-4-flash / glm-4.7 / glm-5[thinking 开] / glm-5[thinking 关]）× 三风格（zero-direct / zero-cot / few-cot）× 双任务族（3 推理 + 3 指令遵循）：

**推理题（/3）**

| 配置 | zero-direct | zero-cot | few-cot |
|------|------------|----------|---------|
| glm-4-flash | 0 | **3** | 3 |
| glm-4.7 | **3** | 2 | 3 |
| glm-5 [think开] | 3 | 2 | 3 |
| glm-5 [think关] | 2 | **3** | 3 |

**指令遵循题（/3）**

| 配置 | zero-direct | zero-cot | few-cot |
|------|------------|----------|---------|
| glm-4-flash | 1 | 1 | 1 |
| glm-4.7 | **3** | **1** ⚠️ | 3 |
| glm-5 [think开] | 2 | 2 | 2 |
| glm-5 [think关] | 3 | 2 | 2 |

四条规律（每条都有格子撑腰）：

1. **同一句咒语，同号不同命**："请一步一步思考"把 flash 推理 0→3（救），同时把 4.7 的指令遵循 3→1（杀）。**不存在全局最优 prompt，只存在 (模型, 任务) 格子的最优**。
2. **thinking 开关切换最优策略**：glm-5 开思考时 zero-direct 已 3/3（内部推理补齐，外挂多余且干扰：zero-cot 反而 2/3）；关思考后 zero-direct 掉 2/3、需要显式 zero-cot 拉回 3/3。**同一个模型，配置开关一拨，prompt 策略就要换**——这是"模型适配"最硬的证据。
3. **few-cot 是推理任务的通用安全牌**（推理列全 3/3）：带推理链示例对弱模型是脚手架、对强模型是无害冗余。代价在指令遵循列（波动 1-3）——示例自带格式，会和新格式约束打架。
4. **指令遵循是全表洼地**（最高 3/3 只出现在 4.7/think关 的 direct）：越强的推理配置越不擅守格式——2505.11423 的方向在我们 4 配置上全部复现（cot 列 IF 全部 ≤ direct 列或持平）。

（判分诚实声明：IF 三题的裁判是确定性规则（恰好 10 汉字 / 全大写精确匹配 / 拼音序），首版裁判把"按拼音首字母排序"的期望序写错（b<f<m<p），修正后重跑——裁判 bug 也是 harness bug，与 E10 的解析器教训同源。）

## 四、适配决策树（合并 E3/E9/E11 全部数字）

```
你的模型是什么？
├─ 本地小模型（≤1B，如 Qwen-0.5B）
│    ├─ 推理题：few-cot（E3: 17%→50%；zero-cot 只到 17%）
│    └─ 分类/格式：few-shot k=1-2（E2: 0%→80%）
├─ 中档 API（glm-4-flash 级）
│    ├─ 推理题：zero-cot（E3: +60pp；E11: 1/8→8/8）
│    └─ 千万别给无推理示例：few-direct 是毒药（E3: 40%→10%）
├─ 高档非思考（glm-4.7 级）
│    └─ 直接把任务说清楚（zero-direct 全绿）；咒语是负资产
└─ 思考模型（glm-5 thinking 开）
     ├─ 删掉手写 step-by-step（Google Cloud 官方建议 + E9）
     ├─ 给足 max_tokens（reasoning 吃预算，E8 空输出坑）
     └─ 复杂任务仍可 few-cot（无害且有锚定作用）
```

## 五、不足与批判

- 每格 3 题，**格子内数字是方向的指示牌，不是效应量的估计器**——决策树的置信来自多实验交叉（E3/E9/E11 三组独立网格同号），不是单格 n。
- 模型谱系只有智谱一家（+Qwen 本地）。跨厂商（GPT/Claude/Gemini 系）的适配矩阵是天然的扩展实验——指南 reasoning-llms 篇的证据显示方向一致（thinking 模型少吃 prompt 技巧）。
- 位置效应（order sensitivity）本章没测：ACL 2026 的 14pp 差距提示 prompt 内部顺序是独立变量，值得单独网格。

> ✍️ 练习：在 E9 矩阵里加 glm-5[think开] + few-cot + max_tokens=512 的格子（截断思考）——它应该比 max_tokens=1024 的同格更差，量化"思考预算"这个隐藏变量。
