# 11 - ★ 数学领域应用：GSM8K 矩阵、Persona 与 Lean/Prover 模板

> 讲透Prompt 第 11 章（重点章）| 实验：E11（`experiments/e11_math.py`，results/e11_math.json/png）| 模板：`讲透Agent/实战案例-Prover数学Agent/prompts.py`（DeepSeek-Prover-V2 官方逐字保真）；对照研究：Springer 2026 数学教育 persona 研究、arXiv 2604.18897（SAIR 单 prompt 天花板）

## 一、直觉：数学是 prompt 工程的"测功台"

分类任务的对错有灰度（情感本来就连续），数学没有——**要么算对要么算错，裁判零成本**。这使数学域成为 prompt 策略的终极考场：策略间的差距被二元判分放大到最清晰。同时数学是 LLM 公认短板（心算不稳、多步依赖、符号严格），prompt 技巧的收益区间也最大。

## 二、E11 实测：策略矩阵 + Persona

```bash
cd 讲透Prompt/experiments && python3 -u e11_math.py   # 2模型×5策略×8题 + 4persona, ~9 min
```

8 道 GSM8K 风格题（自造，答案全部 Python 验算）× 5 策略 × 2 模型：

**准确率（/8）**

| 策略 | glm-4-flash | glm-5[think关] |
|------|-------------|----------------|
| zero-direct | **1** | 6 |
| zero-cot | **8**（+87.5pp！） | 7 |
| few-cot | **8** | 8 |
| PAL（写代码） | 6 | 7 |
| persona-老师 | 7 | **8** |

**Persona 四角色专项（glm-4-flash，准确率 / 平均推理行数）**

| 角色 | 准确率 | 推理行数 |
|------|--------|---------|
| 普通 | **8**/8 | 5.4 |
| 数学老师 | 7/8 | 6.1 |
| 严谨教授 | 7/8 | **8.5** |
| 费曼（大白话） | 7/8 | **3.9** |

四条结论：

1. **zero-cot 是弱模型在数学域的最大单杠杆**（1/8 → 8/8，+87.5pp）——比 03 章的 +60pp 更陡（数学题对"草稿纸"的依赖更重）。
2. **few-cot 是全配置最稳策略**（双模型 8/8）——08 章决策树在数学域的再现。
3. **PAL 不是数学银弹**（6-7/8）：两处沙箱/代码错误拖后腿。04 章失败分类学在此复现——数学题里"语义翻译"（余数条件、倍数关系）比"精确计算"更常见，恰是 PAL 弱区。
4. **Persona 调的是过程量，不是对错**：严谨教授推理行 8.5 vs 费曼 3.9（2.2 倍跨度），但准确率全在 7-8，普通版反而最高。**角色设定买得到"怎么讲"，买不到"算得对"**——这与 Springer 2026（4 模型 × 4 技术 × 2880 解，persona 让**过程性质量**七倍提升而结论质量增益有限）方向一致；我们把它压到了最干净的最小实验。

## 三、单 prompt 天花板在数学域的残酷性

arXiv 2604.18897 的 SAIR 竞赛数据（数学推理任务、45+ prompt 变体）显示：**变体间差距小、家族间差距大，且多变体合并只到均值**。映射到我们的矩阵：zero-direct→zero-cot 这种"换家族"是 +87.5pp 级；同一家族里磨措辞（"请仔细一步步思考" vs "请一步一步思考"）是天花板下的钢镚。**数学域 prompt 工程的第一决策是选家族（direct / CoT / few-cot / PAL），第二决策才是措辞**——第二决策的期望收益比第一决策低一个数量级。

## 四、Lean/Prover：数学 prompt 的工业级形态

数学 prompt 的尽头是形式化证明：答案对错由 Lean 编译器判定（0 sorry = 通过），prompt 与验证器无缝焊接。直接复用 `实战案例-Prover数学Agent/prompts.py`（DeepSeek-Prover-V2 官方逐字保真 + 分解重构）的三模板：

**① COT 模式（复杂定理：先计划后证明）**
```
Complete the following Lean 4 code:
```lean4
{statement}
```
Before producing the Lean 4 code..., provide a detailed proof plan outlining
the main proof steps and strategies. The plan should highlight key ideas,
intermediate lemmas, and proof structures...
```

**② NONCOT 模式（简单定理/专家迭代：直接补全）**
```
Complete the following Lean 4 code:
```lean4
{statement}
```
```

**③ DECOMPOSE 模式（"建筑师"分解：have 骨架 + sorry 占位，输出 JSON）**——把定理拆成 1-3 步可证的子目标链，由"瓦工"模型逐个填。

三点与前面章节的呼应：

- **NONCOT → COT → DECOMPOSE 是 CoT 谱系的形式化版本**：不思考/整段思考/结构化分解，03 章的家族选择在证明域原样重演；
- **验证不对称性拉满**：Lean 编译器是完美裁判，所以这套 prompt 敢于"只给 statement 不给示例"——**当验证免费且可靠时，few-shot 都可以省**（02 章"k=0 就够"的极限版）；
- 深入这条线（蒸馏 24 题、DCU 断点续跑）见 `讲透Agent/实战案例-Prover数学Agent/`。

## 五、数学 prompt 设计清单（可直接抄）

1. **先选家族**：直答→CoT→few-cot→PAL→分解，按 08 章决策树走；磨措辞放最后。
2. **Persona 用于教学/解释场景**（过程质量 2 倍跨度），别指望它涨准确率。
3. **凡是能 Python 验算的，答案一律本地算**（E5/E11 的 gold 全部运行时计算）——judging 也要防自己手滑。
4. **形式化域（Lean）**：验证在模型外，prompt 极简 + 验证器极严，是所有场景的最优架构预览。
5. 批量评测用 GSM8K 风格自造题（可验证、可控制难度梯度），比直接抄数据集更能隔离变量（经典题有记忆污染——E6 教训）。
