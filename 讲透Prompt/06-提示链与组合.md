# 06 - 提示链与组合

> 讲透Prompt 第 06 章 | 实验：E-mini（`experiments/emini_chain.py`，results/emini_chain.json）| 素材：`_source/techniques/prompt-chaining.zh.mdx`；链式思想的工程化终点在 09 章（自动优化）与 `讲透Loop`（迭代）

## 一、直觉：一条流水线 vs 一个全能工人

任务："从混合文本抽取结构化 JSON（人名/金额/日期），金额统一数字、日期统一 YYYY-MM-DD"。单发 prompt = 雇一个全能工人一次交货；链式 = 流水线三站——**抽取 → 标准化 → 组装**。

链式的赌注：每站更简单（单点错误率降），但站点之间有交接损耗（3 次调用、3 次解析）。E-mini 用 5 条含中文数字（"三千五百元"、"伍佰元"）、混合日期格式（2026/7/22、"8月底前"）的文本称这个赌。

## 二、机理：为什么拆开能赢

单发 prompt 的失败模式是**约束叠加**：格式约束（JSON）+ 语义约束（否定词判断）+ 规范化约束（中文数字→阿拉伯数字）同时压在一个分布上，模型顾此失彼——E9 里"一步步思考"叠加格式约束导致 IF 全崩是同一机制。链式把 $k$ 个约束摊到 $k$ 步，每步的输出空间被上一步的结果**锚定**：标准化站只面对"把'三千五百'变成 3500"这一个变换，分布窄、错误率低。

代价也明确：每步的输出都要被下一步**解析**，解析器是新的失败点（E10 的教训：解析器也是 harness）；且错误沿链传播——抽取站漏了，后面全白搭。

## 三、代码：E-mini 实测

```bash
cd 讲透Prompt/experiments && python3 -u emini_chain.py   # ~3 min
```

5 条文本，字段级判分（人名/金额/日期各 1/3）：

| 文本 | 单发 | 链式 |
|------|------|------|
| 张三…三千五百元…2026年8月15日 | **0%** | **100%** |
| 王五…12000…2026-09-03 | 100% | 100% |
| 赵六…¥1,842.50…2026/7/22 | 100% | 100% |
| 钱七没有提交任何单据 | 0% | 0% |
| 孙八…伍佰元…2026年8月31日 | 100% | 67% |
| **总账** | **60%** | **73%** |

三处读数比总账更重要：

1. **链式的胜利恰好发生在规范化难点**：张三条（中文大写数字"三千五百"），单发 0%、链式 100%——标准化站把"中文数字→3500"隔离成单一变换，稳了。
2. **null 语义两法全灭**：钱七条（无信息应输出 null）——"没有提交任何单据"里的"没有"触发了模型的抽取本能。**链式救不了语义歧义**，这类边界要靠 few-shot 示例或后处理规则。
3. **链式也有翻车格**：孙八"伍佰元"链式 67%（标准化站把"伍佰"译成 50 或 5000 之类的错字），单发反而对——**每多一站就多一份"模型不认识中文大写数字"的暴露面**。

## 四、什么时候拆链（决策表）

| 特征 | 拆 | 不拆 |
|------|-----|------|
| 约束多且互相干扰（格式×语义×规范化） | ✓ | |
| 各步有独立质量要求（可分别评测/回归） | ✓ | |
| 中文数字/单位/日期等**可枚举规范化难点** | ✓（单发必挂） | |
| 任务一步能说清、约束 <3 个 | | ✓（E7：简单任务付不起协议开销） |
| 中间结果需要人审（合规/高风险） | ✓ | |
| 调用成本敏感（每链翻倍） | | 权衡 |

工程要点（我们踩过的）：

- **站间接口用结构化文本**（上一步输出直接可解析），别让下一步"重新理解"上一步的自由文本；
- **每站保留独立可跑的测试**（emini 的判分器就是三站的合同）；
- 链的长度克制在 2-4 站：错误传播近似 $1-(1-e)^{k}$，五站以后单站再准也兜不住。

## 五、不足与批判

- n=5、单模型、字段级判分粗糙（严格序列不评顺序）——**效应方向可信（+13pp），效应量不可外推**。
- 我们的"链"是手写死的。真实生产里链的拓扑（哪步拆、怎么接）本身是设计变量——DSPy/OPRO（09 章）做的就是**用优化器搜链和指令**，把"拆链"从手艺变成搜索问题。
- 链式与 06 章之外的世界：多站链=退化版 agent 循环（无分支无工具），与 ReAct 的分界是"拓扑固定 vs 运行时决定下一步"。中间形态（条件分支链）见 `讲透Loop` E4 的路由循环。
