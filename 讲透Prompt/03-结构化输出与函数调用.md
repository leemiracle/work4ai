# 03 — 结构化输出与函数调用

> 真实应用里，LLM 的输出要给程序解析（JSON）、要触发动作（调 API）。自由文本不行。这一篇讲透怎么让 LLM 稳定输出结构化数据、怎么让它"调用工具"——这是 Agent 的基础。本篇概念为主。

---

## 1. 为什么需要结构化输出

对话场景 LLM 输出自然语言没问题。但工程场景：
- 把 LLM 结果存数据库 → 要 JSON。
- 让 LLM 触发动作（发邮件、查库存）→ 要函数调用。
- 多步流水线（LLM → 解析 → 下一步）→ 输出必须可机器解析。

**自由文本会带格式漂移、多余寒暄、转义错误**，解析易崩。所以需要"结构化输出"。

---

## 2. 三代结构化输出技术

### ① Few-shot 约束格式（最朴素）
prompt 里放几个 JSON 例子，让模型模仿。**问题**：不保证 100% 合法 JSON（模型可能漏括号、加注释）。

### ② JSON Mode / Response Format（API 层）
OpenAI/DeepSeek 等提供 `response_format={"type":"json_object"}`，强制输出合法 JSON。但仍不保证 schema（字段名/类型）。

### ③ Structured Output / Schema 约束（最强，2024 主流）
给一个 JSON Schema（定义字段名、类型、枚举），模型输出**保证符合 schema**。OpenAI 的 Structured Outputs、DeepSeek 的 JSON Schema、 instructors 库都走这条路。

```python
# OpenAI Structured Outputs (伪代码)
response = client.chat.completions.create(
    model="gpt-4o",
    response_format={
        "type": "json_schema",
        "json_schema": {
            "schema": {
                "type": "object",
                "properties": {
                    "sentiment": {"type": "string", "enum": ["正面","负面","中性"]},
                    "score": {"type": "number"}
                },
                "required": ["sentiment","score"]
            }
        }
    })
# 输出保证是 {"sentiment": "正面"|"负面"|"中性", "score": <数字>}
```

底层原理：**约束解码**（constrained decoding）——生成时只在合法 token 里采样（schema 等价的有限状态机），物理上保证合法。

---

## 3. Function Calling（函数调用）

让 LLM 决定"调用哪个函数 + 传什么参数"：

```python
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "查某城市天气",
        "parameters": {"city": {"type":"string"}}
    }}]
# 模型收到"北京天气如何" → 输出 tool_call: get_weather(city="北京")
# 你的代码执行真实函数 → 把结果返回模型 → 模型生成最终回答
```

**流程**：用户问 → 模型判断要调工具 → 输出结构化 tool_call → 程序执行 → 结果回填 → 模型答。

这本质上也是"结构化输出"（tool_call 是结构化的），只是语义是"调用"。

---

## 4. 与 Agent 的关系

Function Calling 是 **Agent 的基础积木**：
- Agent = LLM + 多个工具（函数）+ 规划循环
- LLM 靠 Function Calling 决定"下一步用哪个工具"
- 多轮工具调用 + 中间推理 = Agent

```
用户任务 → Agent(LLM) 规划 → Function Call(工具1) → 看结果
       → 再规划 → Function Call(工具2) → ... → 完成
```

**结构化输出 + Function Calling 让 LLM 从"只会说话"变成"能干活"**。这是 2023 后 Agent 爆发的基础设施。（深度内容留待「讲透 Agent」）

---

## 5. 实践要点

1. **Schema 要明确**：字段、类型、枚举写清楚，模型才稳定。
2. **description 是 prompt 的一部分**：schema 里每个字段的 description 会被模型读到，认真写。
3. **工具描述要好**：Function Calling 的 `description` 决定模型何时选这个工具——写不清模型就乱调。
4. **加 fallback**：模型可能不调工具直接答，代码要处理"没有 tool_call"的情况。
5. **JSON Mode ≠ Schema 保证**：JSON Mode 只保证合法 JSON，不保证字段对；要 Structured Outputs 才保证 schema。

---

## 6. 一句话总结

> **结构化输出让 LLM 从"自由文本"变成"可程序解析的数据"：JSON Mode 保证合法 JSON，Structured Outputs（schema 约束 + 约束解码）保证字段/类型合规。Function Calling 让 LLM 输出"调用哪个函数+参数"，是 Agent 调用工具的基础积木。这两项让 LLM 能接入工程系统、触发动作，是 2023 后 Agent 爆发的基础设施。**
