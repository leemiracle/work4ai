# 05 - 搜索与行动：ToT 与 ReAct

> 讲透Prompt 第 05 章 | 实验：E6（`experiments/e6_tot.py`，results/e6_tot.json/png）+ E7（`experiments/e7_react.py`，results/e7_react.json/png）| 素材：`_source/techniques/tot.zh.mdx`、`_source/techniques/react.zh.mdx`、`_source/guides_reasoning-llms.en.mdx`；论文：Yao et al. 2305.10601（ToT）、Yao et al. 2210.03629（ReAct）

## 一、直觉：走迷宫时，CoT 是闭眼直走，ToT 是带粉笔回头

24 点题 `[3,3,8,8]` 的解是 $8/(3-8/3)$——中间态是分数 $8/3$、$1/3$。平铺 CoT 一条路写到底，第一步写下 $3 \times 8$ 就基本宣判死刑，**它没有"退回上一步换条路"的机制**。ToT（Tree of Thoughts）给模型三件套：**提议**（当前局面有哪几种走法）、**评估**（哪个走法有戏）、**回头**（不行就回到树的上层）。它不是更强的直觉，是带粉笔的迷宫走法。

ReAct 解决另一个缺陷：模型的"世界知识"是冻结的（不知道今天几号、算不准大数）。它把 **Action（调工具）** 插进 **Thought（推理）** 之间：想一步、做一个动作、看一眼观察结果、再想。

## 二、数学：ToT 的预算账

设提议器质量 $q$（一次生成含有效走法的概率）、评估器精度 $v$、搜索深度 $d$、每层分支保留 $b$。找到解的概率上界：

$$P(\text{solve}) \leq 1 - (1 - q_{\text{needle}})^{b \cdot d}$$

其中 $q_{\text{needle}}$ 是"提议出通往解的关键走法"（如 $8/3$）的概率。**这个公式读出一个残酷事实：$q_{\text{needle}}$ 低时，加深度、加分支都救不回来**——指数预算花在低质量提议的排列组合上。Yao et al. 的 74% 是 GPT-4 级提议器+评估器（2023 年最强模型）+ 约百倍 token 预算换来的。**ToT 是能力放大器，不是能力注入器**——与讲透Loop 十定律的"harness 只放大已有的"同构。

## 三、代码：E6 三臂对照 + E7 工具循环

```bash
cd 讲透Prompt/experiments
```

**E6：5 道全分数 24 点（本地 Fraction 暴力验证可解）三臂对决**

| 臂 | 预算 | 解出率 |
|----|------|--------|
| CoT（3 样本任一解出，机械验证等式） | 3 次调用 | **40%** |
| ToT（提议+评估+剪枝 BFS） | 8 次调用 | **0%** |
| ToT-无剪枝（纯提议 BFS） | 8 次调用 | **0%** |

反直觉但机理清楚：

1. **ToT 全灭的第一嫌疑人是剪枝**：glm-4-flash 评估器看到 $[3, 8, 8/3]$ 这种分数中间态，一句"impossible"就把唯一通关路径剪了。
2. **无剪枝臂排除嫌疑**：同样 0%——提议器在预算内根本提不出 $8/3$ 这类关键走法。**病灶在提议质量，剪枝是并发症。**
3. CoT 40% 的成分要拆开：解出的 $5(5-1/5)$、$(10 \times 10-4)/4$ 都是最著名经典题——**部分是训练记忆，不是现场推理**（这批题在语料里出现过亿万次）；两轮采样解出的题还不稳定（T=0.7 波动）。

**定向干预复查（E6-R，0826 补）**：给提议 prompt 加一句"优先考虑能产生分数的除法走法"重跑双臂——提议分布**确实被移动**（分数走法 0→6/8/3 条），但解出率仍 **0%/0%**。**分布移动 ≠ needle 可达**：8 次调用预算内，即使模型肯提 $8/3$，beam=2 的 BFS 也遍历不到正确的组合链。一句话总结两次实验：**救 ToT 的不是更好的提示词，是更多预算或更好的评估器**——prompt 移动分布，架构决定可达性。

**E7：ReAct 三任务（计算器 today/days_until 三工具，max 5 步）**

| 任务 | zero-cot | ReAct |
|------|----------|-------|
| 纯算术 (17×23+89)/5 | ✓ | **✗（10 步协议失焦）** |
| 今天距 2027-01-01 几天（需知道今天日期） | **✗（知识冻结，必败）** | ✓（today[] + days_until[]） |
| 999 连涨 3 天 3.3%（E5 同款） | ✗（心算精度） | ✓（calc[]） |

总账 33% → 67%，但单格更有教益：

- **ReAct 的胜利区 = 缺口在模型外**（日期、精确计算）：工具即插即用，一步到位；
- **ReAct 的失败区 = 任务太简单**：简单直答题上，Thought/Action/Observation 的三轮格式反而是踩雷点——glm-4-flash 在 10 步里纠缠于格式，忘了收敛。**协议是开销，简单任务付不起。**

**E6 的真正遗产**：24 点这种"验证便宜、状态空间小"的问题，正确架构根本不是让模型搜索，而是**本地 20 行暴力枚举**（我们的 Fraction 裁判秒解全部 5 题）。**模型该做的是出题和理解，不是算题**——这是 MATH_DISCOVERY_ENGINE「验证不对称性」在 prompt 层的回声。

## 五、不足与批判

- E6 的 8 次调用预算低于论文一个量级——这是**故意的**：我们要测的是"预算受限时框架的真实性价比"，而真实工程永远是预算受限的。预算放大 10 倍 ToT 能不能爬起来？值得期权实验（提提议器提示词、加自一致性评估），但方向已经清楚：先有质量，再谈搜索。
- E7 只给了 3 个玩具工具。真实 agent 的工具箱有几十个，错误模式（选错工具、参数幻觉）完全不同——那是 讲透Agent/harness 的地盘。
- ReAct 的 trajectory 会被低质量 Observation 污染（工具报错文案写得好不好直接影响下一轮 Thought）——prompt 工程延伸到了**工具返回值设计**，指南没讲，工程里是大头。

> ✍️ 练习：给 E6 的提议 prompt 加一句"优先考虑产生分数的除法"，重跑 ToT——提议分布被定向移动后，无剪枝臂能起来吗？（这是 prompt 影响搜索的最小实验。）
