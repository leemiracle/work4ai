# 01 - 基础：模型设置与提示词要素

> 讲透Prompt 第 01 章 | 实验：E1（`experiments/e1_params.py`，results/e1_params.json/png）| 素材：`_source/introduction_basics.zh.mdx`、`_source/introduction_elements.zh.mdx`、Google Cloud prompt 组件表

## 一、直觉：温度是麦克风增益，不是音色

把 LLM 的输出分布想成演讲现场：候选词是听众里举手的人，采样就是闭眼点一个。**temperature 调的是麦克风的增益**——增益低（T→0），只有最前面的几个人声够大，永远点同一批头排；增益高（T 大），后排小声音也有机会被点到。但增益改变的是"点谁"，不改变"谁坐在前排"（模型的知识与能力）。指望调温度让模型"变聪明"，等于指望调大增益让跑调的歌手不跑调。

E1 要验证的就是这件事的另一半：**采样参数影响多样性，不影响正确性的中心**。

## 二、数学：softmax 温度与核采样

解码时模型对词表输出 logits $z_i$，温度 $T$ 重整化分布：

$$P_T(i) = \frac{e^{z_i/T}}{\sum_j e^{z_j/T}}$$

- $T \to 0$：分布坍缩到 argmax（贪心）；
- $T \to \infty$：分布趋于均匀。

**top-p（核采样）**换一个干预点：不调高度，调宽度——按概率从大到小累积到 $p$ 为止，只在核内重新归一化：

$$\text{nucleus}(p) = \min\left\{k : \sum_{i=1}^{k} P(i) \geq p\right\}, \quad P'(\cdot) = P(\cdot)/\textstyle\sum_{i \in \text{nucleus}} P(i)$$

关键性质：**top-p 的核大小随分布形状自适应**。分布尖时核小（保守），分布平时核大（多样）。这就是 E1 里 top_p=0.1 能"压过" temperature=1.2 的原因——核采样直接掐掉了长尾，温度怎么放大都放大不进核外的候选。

## 三、代码：E1 实测

```bash
cd 讲透Prompt/experiments && python3 -u e1_params.py   # ~3 min
```

三组条件（本地 Qwen2.5-0.5B）：开放生成（写一句诗）× 12 次采样看互异数；翻译任务（正确率）；温度交叉核采样。

| 条件 | 12 次生成互异数 | 翻译正确率 |
|------|---------------|-----------|
| T=0.0（贪心） | 1/12 | 100% |
| T=0.7 | 12/12 | 100% |
| T=1.5 | 12/12 | 100% |
| T=1.2 + top_p=0.1 | **1/12** | 100% |

两个结论：

1. **温度只买到多样性，买不到正确率**：翻译这种"模型本来就会"的任务，全档 100%；反过来，"模型不会的题"（见 E3 里 Qwen 直答算术 0%），加温也还是 0%。
2. **top_p 压过温度**：T=1.2 的高温被 top_p=0.1 强行拉回互异 1/12——两个旋钮不独立，核采样作用于温度之后的分布。工程上：**调一个就够，同时调两个是给自己埋雷**。

## 四、提示词要素：Google Cloud 组件表

采样之外，prompt 本身的解剖学（Google Cloud 官方组件表，Gemini 平台实践）：

| 组件 | 作用 | 我们的实验对应 |
|------|------|--------------|
| Objective（目标） | 一句话说明要什么 | E-mini 的任务句 |
| Instructions（指令） | 步骤、约束 | E9 的"恰好10个汉字"约束 |
| Constraints（硬约束） | 格式/长度/禁止项 | E8 的"必须输出 JSON" |
| Tone（语气/角色） | persona 设定 | E11 四角色实验 |
| Few-shot（示例） | 格式与推理示范 | E2/E3 的 k 曲线 |
| Reasoning steps（推理要求） | 显式要求 step-by-step | E3/E9（**对 thinking 模型要删**，见 08 章） |
| Recap（复述任务） | 长任务防跑偏 | 讲透Context 的"重申"策略 |

这张表的隐藏信息：**Reasoning steps 是组件之一而不是万能前缀**——它和模型架构有交互（thinking 模型内置了它，外挂反而干扰），这是 08 章的主题。

## 五、不足与批判

- E1 的翻译任务是"易任务"——采样参数对**难任务**的正确率影响其实非零（高温会放大边缘错误），但方向不变：那是方差，不是能力。
- 我们的互异数是最粗糙的多样性度量（字符串全等）。语义多样性（12 次都说"月亮"但措辞不同）它测不出。
- 贪心解码 ≠ 确定性：API 端 even T=0 常有批间抖动（E5 里 PAL 两次跑 t1 输出从"星期一"变"星期六"）——复现实验要留这个心眼。

## 六、应用清单

- 要稳定（评测、抽取、分类）：T=0，别碰 top_p。
- 要多样（头脑风暴、SC 采样）：T=0.7-1.0，top_p 0.9-1.0。
- 出现"高温胡说"又想要多样：优先收 top_p 而不是降 T（核采样保头砍尾，温度是全域缩放）。
