# 04 - 知识增强与程序辅助（PAL）

> 讲透Prompt 第 04 章 | 实验：E5（`experiments/e5_pal.py`，results/e5_pal.json/png）| 素材：`_source/techniques/pal.zh.mdx`；论文：Gao et al. 2211.10435（PAL）、Chen et al. 2211.10435 同刊 RoT 据指南

## 一、直觉：把计算外包给从不犯错计算器

LLM 心算 123456789 × 987654321 必错——不是因为不懂乘法，是因为**token 生成器不是计算器**：每一步数值推理都在有噪声的分布上采样。PAL（Program-Aided LM）的思路简单粗暴：**让模型只做它擅长的（把题意翻译成 Python），让解释器做它擅长的（精确执行）**。

分工后的错误面就换了一层：模型不再需要"算得对"，只需要"译得对"。E5 要测的就是这个分工的真实收益——以及翻译层自己的新坑。

## 二、数学：验证不对称性与执行保真

PAL 利用的核心不对称性：

$$\underbrace{\text{生成代码的成本}}_{\text{一次生成}} \ll \underbrace{\text{执行代码的成本}}_{\text{纳秒级}} \quad\text{且}\quad \underbrace{\text{执行结果的正确性}}_{=1 \text{（给定代码语义正确）}} \gg \underbrace{\text{心算正确性}}_{<1}$$

形式化地：设模型把题意翻译成正确语义程序的概率为 $s$，程序执行正确率为 1；心算路径每步正确率 $c$，$k$ 步推理总正确率 $c^k$。PAL 赢当且仅当 $s > c^k$。**注意 $s$ 不随题目的计算复杂度变化**（乘积位数多不增加翻译难度），而 $c^k$ 随步数指数衰减——这就是 PAL 的理论优势区：计算密集、语义简单的题。反过来，语义本身绕（排列 vs 组合）的题，$s$ 掉下去，优势蒸发。E5 会精确地踩中这两侧。

## 三、代码：E5 五题对决

```bash
cd 讲透Prompt/experiments && python3 -u e5_pal.py   # ~4 min（含沙箱）
```

5 道"心算高风险"题（gold 全部由本地 Python 运行时计算）：日期推算 / 大数乘积数字和 / 连续涨价百分比 / 排列组合 / 阶乘尾零。PAL 通道：模型生成代码 → 白名单沙箱 exec（`__import__` 只放行 math/itertools/datetime，signal.alarm 20s 防死循环）→ 捕获 print。

| 题 | gold | CoT（心算） | PAL（写代码） | 失败层 |
|----|------|------------|--------------|--------|
| t1 日期推算 | 星期四 | ✗ 星期五 | ✗ 星期六 | **双方都错在语义建模**（日期锚点/间隔换算） |
| t2 大数数字和 | 63 | ✗ 68 | **✓ 63** | CoT 心算崩；PAL 经典胜利区 |
| t3 连续涨价 | 1101.2 | ✗ 1101.22（差0.02） | **✓ 1101.20** | CoT 精度崩；PAL 胜利区 |
| t4 相邻排列 | 720 | ✓ 720 | ✗ 35 | **PAL 把"排列"译成了"组合"**（C(7,3)=35），解释器忠实执行了错误语义 |
| t5 阶乘尾零 | 24 | ✓ 24（背了 Legendre 公式） | ✗ 死循环 | PAL 生成 while 未收敛，被 alarm 击杀 |

**总账：CoT 40% vs PAL 40%——平手。** 但这个平手比"PAL 碾压"值钱得多，因为它拆出了失败分类学：

1. **PAL 的胜利区 = 计算密集、语义直白**（t2/t3）：错误从指数级心算堆栈里消失。
2. **PAL 的失败区 = 语义翻译**（t1/t4）：解释器保证"按你说的算"，不保证"你说的是题意"。**错误没有消失，只是搬家：从算术层搬到了建模层。**
3. **PAL 的新失败模式：执行风险**（t5 死循环、以及开发中亲历的两版沙箱漏洞——见下）。CoT 最多答错，PAL 可以挂死、甚至在你没隔离好的环境里执行任意代码。

### 沙箱工程三课（我们踩过的坑，直接可用）

1. **白名单 builtins 不够**：模型habit性写 `import math`，沙箱没有 `__import__` 就全盘 ImportError——正确做法是自定义 `__import__` 只放行准许库。
2. **剥 import 行也不对**：`from datetime import datetime` 被剥后裸调用 `datetime()` 变成调用模块——TypeError。**让白名单 `__import__` 处理一切，别动模型代码。**
3. **必须有超时**：`signal.alarm(20)` 逮住 while 死循环。生成代码是任意代码，exec 前按敌意代码设防。

## 四、PAL vs CoT 决策表

| 任务特征 | 选 | 依据 |
|---------|-----|------|
| 大数/多步精确计算、直白语义 | PAL | E5 t2/t3；$s > c^k$ 优势区 |
| 语义绕（需识别排列/组合/边界） | CoT 或 CoT+验算 | E5 t4：翻译错误率 > 心算错误率 |
| 纯知识回忆（公式/事实） | CoT | E5 t5：模型直接背 Legendre |
| 高安全场景 | PAL 只读沙箱（无网络/文件/长时） | 沙箱三课 |
| 有验证器的场景 | **模型提议 + 代码验证**（E6 的教训） | 下一章 ToT 对照 |

## 五、不足与批判

- PAL 论文报 GSM8K 上大幅领先，我们的 5 题平手——差异在任务选择：论文集的计算密集度远高于语义歧义度；自选题把翻译层暴露出来了。**两边都是真的，合起来才是全景。**
- 我们的 PAL prompt 只有一次生成机会，没有"运行报错回传重试"（自修复循环）。带错误反馈的重试能把死循环/ImportError 拉回来一部分——但那是 agent 循环（05 章 ReAct / 讲透Loop），不是单发 prompt 了。
- n=5、单模型（glm-4-flash），效应量不可外推；但失败**模式**（算术层→建模层搬家）是结构性的，可外推。

> ✍️ 练习：给 E5 加一个 `retry_on_error` 臂——PAL 报错时把 traceback 塞回 prompt 让模型修一版。t5 的死循环能被修好吗？t4 的语义错误呢？（预告：报错能修 bug，修不了误解。）
