# 00 — 为什么 Prompt 是控制信号？

> 这是「讲透 Prompt 工程」第一篇。Prompt 工程常被当成"玄学技巧"，但它的本质极其清晰：**LLM 是条件概率模型 P(输出|输入)，Prompt 就是那个"条件"——改 prompt 就是改输出分布**。理解这一点，prompt 工程就从"碰运气"变成"有依据的调试"。
>
> 配套实验：`experiments/00_why_prompt.py`。

---

## 1. Prompt 的本质：它是条件概率里的「条件」

LLM（解码器）生成文本的数学定义就是条件概率链：

$$P(\text{输出} \mid \text{输入}) = \prod_t P(y_t \mid y_{<t}, \underbrace{\text{输入}}_{\text{Prompt}})$$

**Prompt 就是那个"输入/条件"**。改 prompt，整个输出分布就变。模型权重一个参数都没动，但输出可以截然不同。

### 实验（`00_why_prompt.py` Part 1）

用一个固定的小 trigram 模型，不同 prompt（条件）→ 不同输出分布：

```
P(next | 'cats are')  = {animals: 1.0}
P(next | 'cars are')  = {machines: 1.0}
P(next | 'roses are') = {plants: 1.0}
```

**模型没变，只因条件（prompt）不同，输出完全不同。** 这就是 prompt 的本质——它是控制 LLM 输出分布的旋钮。

---

## 2. Prompt 的三要素

真实 prompt 不是简单的前缀，而是三部分组合：

| 要素 | 作用 | 例子 |
|---|---|---|
| **指令 (Instruction)** | 定任务 | "把句子翻译成英文" |
| **上下文 (Context)** | 给背景/知识 | RAG 检索到的文档、背景说明 |
| **例子 (Examples)** | 示范格式/模式 | Few-shot 的"输入A→输出B" |

三者拼成条件。**Prompt 工程就是调这三者**，让输出分布落在你想要的区域。

> 注意：RAG（讲透RAG 00）本质就是把"上下文"这一要素做强（检索注入知识）。所以 RAG 是 Prompt 工程的一个子集/强化。

---

## 3. Prompt = 用自然语言「编程」

| | 传统编程 | Prompt 工程 |
|---|---|---|
| 语言 | 代码（Python/C） | 自然语言 |
| 执行器 | 编译器/解释器 | LLM |
| 输出 | 确定 | 概率 |
| 调试 | 改代码 | 改 prompt |

**Prompt 工程师 = 用自然语言写"程序"的人**。模型是解释器，prompt 是代码。好 prompt 像好代码：清晰、无歧义、给足必要信息、有适当"约束"。

不同点：代码精确，prompt 是概率的——所以 prompt 需要像调代码一样反复测试、迭代。

---

## 4. 为什么 Prompt 工程值得专门学

1. **零成本切换任务**：同一个模型，换 prompt 就能做翻译/摘要/代码/推理——不用重训（对比微调的成本）。
2. **是其他技术的接口**：RAG 把检索结果塞进 prompt；Agent 把工具说明写进 prompt；微调后的模型仍要靠 prompt 驱动。**Prompt 是人机交互的统一接口。**
3. **投入产出比极高**：改一行 prompt 可能让效果翻倍，而改模型要几天训练。

---

## 5. 局限与诚实声明

- **概率性**：prompt 不是确定性程序，同一 prompt 多次运行可能不同（温度>0）。需要采样多次/设温度 0 提稳定性。
- **依赖模型能力**：复杂 prompt 技术（Few-shot ICL、CoT）依赖大模型的**涌现能力**，小模型上效果差（讲透基础模型 03）。
- **本实验局限**：trigram 只演示"prompt 是条件"这个最底层原理；真实的指令遵循/ICL/CoT 需要大模型，后续篇用文献证据 + 大模型现象讲透。

---

## 6. 一句话总结

> **Prompt 的本质是条件概率 P(输出|输入) 里的"条件/输入"——改 prompt 就是改输出分布，模型权重不变。它由指令+上下文+例子三要素组成，RAG 就是把"上下文"做强。Prompt 工程是用自然语言"编程"LLM：投入产出比极高（换一行 prompt 顶几天训练），但概率性 + 依赖模型涌现能力是其局限。**
