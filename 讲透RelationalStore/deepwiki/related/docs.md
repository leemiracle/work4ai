## Application Package Structure

 OpenHarmony applications are distributed as **APP packages** containing one or more modules. Understanding the packaging model is fundamental to application development.

 
### Package Types

 OpenHarmony supports three module types:

 
| Package Type | File Extension | Purpose | Independent Distribution |
|---|---|---|---|
| HAP (Harmony Ability Package) | .hap | Contains executable code, resources, and configuration. Can be entry module or feature module. | Yes, with APP package |
| HSP (Harmony Shared Package) | .hsp | Dynamic shared library providing code and resources to other modules at runtime. | Yes, with APP package |
| HAR (Harmony Archive) | .har | Static shared library compiled into dependent modules at build time. | No, compiled into HAP/HSP |

 **Sources:** [zh-cn/application-dev/quick-start/in-app-hsp.md9-10](https://github.com/openharmony/docs/blob/ccb97ec3/zh-cn/application-dev/quick-start/in-app-hsp.md?plain=1#L9-L10) [zh-cn/application-dev/quick-start/har-package.md9](https://github.com/openharmony/docs/blob/ccb97ec3/zh-cn/application-dev/quick-start/har-package.md?plain=1#L9-L9) [zh-cn/application-dev/quick-start/application-package-overview.md](https://github.com/openharmony/docs/blob/ccb97ec3/zh-cn/application-dev/quick-start/application-package-overview.md?plain=1)

### 1. ArkUI Framework (UI Development)

 ArkUI is OpenHarmony's declarative UI framework, supporting two development paradigms:

 **ArkTS Declarative Paradigm:**

 
 - Component-based UI construction using `@Component` decorator
 - Reactive state management with `@State`, `@Link`, `@Prop` decorators
 - Declarative syntax: `build() { Column() { Text() } }`
 
 **NDK C/C++ Paradigm:**

 
 - Native UI development using C/C++ APIs
 - Direct access to rendering pipeline via `ArkUI_NativeModule` APIs
 - Performance-critical scenarios
 
 
```

```

 **Key APIs:**

 
 - `@Component`: Defines a reusable UI component
 - `@State`: Declares reactive local state that triggers re-renders on change
 - `@Builder`: Custom rendering function for component composition
 - `OH_ArkUI_CreateNode()`: NDK function to create native UI nodes

## Summary

 OpenHarmony application development follows a structured, layered architecture:

 
 - **Packaging**: Applications are distributed as APP packages containing HAP/HSP modules with hierarchical configuration (`app.json5` → `module.json5`)
 - **Framework Layers**:

 
 - **ArkUI**: Declarative UI with reactive state management
 - **Window System**: Manages visual surfaces and lifecycle
 - **Ability Framework**: Defines application entry points and components
 - **Bundle Manager**: Handles installation and metadata
 - **Security**: Multi-level permission system with runtime checks
 - **Lifecycle Flow**: User interaction → Bundle Manager → UIAbility → WindowStage → Window → ArkUI → Display
 - **Key Integration Points**:

 
 - `WindowStage.loadContent()` bridges UIAbility to UI rendering
 - `module.json5` declares capabilities and permissions
 - State management synchronizes data between UI components
 - Permission checks protect sensitive system services
 
 For implementation details of each subsystem, refer to the section-specific wiki pages linked in the Purpose and Scope section.
