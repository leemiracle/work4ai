  This document describes the build system structure, configuration, and dependencies for the OpenHarmony Distributed Relational Database Management System (RDBMS). It explains how the codebase is built across different platforms and outlines the key dependencies required for compiling and running the system.

 
## Build System Overview

 The relational store component uses the GN (Generate Ninja) build system, which generates Ninja build files that are then executed to compile the code. The build system supports multiple platforms, including OpenHarmony, Windows, macOS, Android, and iOS.

## Key Build Configuration Files

 
### bundle.json

 The `bundle.json` file serves as the component manifest, defining metadata such as:

 
 - Component name ("relational_store")
 - Subsystem name ("distributeddatamgr")
 - System capabilities provided by the component
 - Component dependencies
 - Build targets (sub_components)
 
 The file structure includes:

 
```
{
  "name": "@ohos/relational_store",
  "version": "3.1.0",
  "component": {
    "name": "relational_store",
    "subsystem": "distributeddatamgr",
    "syscap": [...],
    "deps": {...},
    "build": {
      "sub_component": [...],
      "inner_kits": [...]
    }
  }
}
```

## Compilation Configuration

 
### Key Compiler Flags and Defines

 
| Flag/Define | Purpose | Used In |
|---|---|---|
| RELATIONAL_STORE | Enable relational store functionality | All platforms |
| SQLITE_HAS_CODEC | Enable SQLite encryption support | All platforms |
| SQLITE_DISTRIBUTE_RELATIONAL | Enable distributed database functionality | OpenHarmony |
| RDB_TRACE_ON | Enable tracing for RDB operations | OpenHarmony |
| CROSS_PLATFORM | Indicates cross-platform build | Non-OpenHarmony platforms |
| WINDOWS_PLATFORM, MAC_PLATFORM, etc. | Platform-specific code paths | Respective platforms |

### Security Features

 For OpenHarmony builds, additional security features are enabled:

 
```
branch_protector_ret = "pac_ret"
sanitize = {
  boundary_sanitize = true
  ubsan = true
  cfi = true
  cfi_cross_dso = true
  debug = false
}
```

 These settings provide protection against memory corruption, undefined behavior, and control-flow integrity attacks.

## Conclusion

 The build system for the relational store is designed to support multiple platforms with different configurations. It handles the compilation of native C++ code, JavaScript bindings, and platform-specific adaptations. The component has a comprehensive set of dependencies to provide its functionality, including access to the SQLite database engine, system services, and security features.

 For information about the core RDB implementation, see [RDB Store Core](https://deepwiki.com/openharmony/distributeddatamgr_relational_store/2-rdb-store-core). For information about the JavaScript API, see [JavaScript API](https://deepwiki.com/openharmony/distributeddatamgr_relational_store/6-javascript-api).
