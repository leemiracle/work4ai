## Purpose and Overview

 This document details the RDB Service and Service Proxy components of the OpenHarmony Distributed Relational Database Management System. These components form the foundation for distributed database operations, enabling data synchronization, remote queries, and subscription mechanisms across devices.

 For information about the core RDB Store implementation, see [RDB Store Core](https://deepwiki.com/openharmony/distributeddatamgr_relational_store/2-rdb-store-core). For details on how synchronization works, see [Synchronization and Remote Queries](https://deepwiki.com/openharmony/distributeddatamgr_relational_store/7.2-synchronization-and-remote-queries).

 
## Component Architecture

 The RDB Service and Service Proxy provide an IPC (Inter-Process Communication) mechanism that enables distributed database operations across process boundaries. The architecture follows a client-server model where:

 
 - `RdbService`: Defines the interface for distributed database operations
 - `RdbServiceProxy`: Implements the proxy pattern to send requests to the actual service implementation

## Interface Definition

 The `RdbService` interface defines the contract for all distributed database operations. This interface is implemented by the actual service and proxied by the `RdbServiceProxy`.

 
### Key Operations

 
| Operation | Description |
|---|---|
| ObtainDistributedTableName | Gets the distributed name for a table across devices |
| SetDistributedTables | Configures which tables should be synchronized |
| Sync | Synchronizes data between devices |
| Subscribe/UnSubscribe | Registers/unregisters for data change notifications |
| RemoteQuery | Executes queries on remote devices |
| RegisterAutoSyncCallback | Registers callbacks for auto-sync progress |

 The proxy uses a common IPC send mechanism pattern implemented as a macro (`IPC_SEND`) that handles:

 
 - Creating message parcels for request and reply
 - Writing the interface token for security
 - Marshalling parameters
 - Sending the request to the remote service
 - Unmarshalling the response
 - Error handling

## Conclusion

 The RDB Service and Service Proxy components provide the foundation for distributed database capabilities in the OpenHarmony Distributed Relational Database Management System. They enable:

 
 - Distributed table management across devices
 - Data synchronization with various modes (push, pull, etc.)
 - Remote query execution on connected devices
 - Subscription mechanisms for data change notifications
 - Progress tracking for synchronization operations
 
 These components use IPC mechanisms to enable cross-process communication and follow established design patterns like Proxy, Observer, and Callback to create a robust distributed database system.
