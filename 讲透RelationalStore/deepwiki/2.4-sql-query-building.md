## Purpose and Scope

 This page documents the SQL query building functionality within the OpenHarmony Distributed Relational Database Management System. It covers the components responsible for constructing SQL query strings using predicates, including the implementation of SQL condition builders, SQL statement constructors, and how they work together to generate valid SQL statements for database operations. This page focuses on the internal mechanisms of SQL query construction rather than how to use the query API from applications. For information about database connection management, see [Connection Management](https://deepwiki.com/openharmony/distributeddatamgr_relational_store/3-connection-management).

 
## Overview

 The SQL query building system provides a structured approach to construct complex SQL statements programmatically. It enables both native C++ code and JavaScript applications to build queries without directly writing SQL strings, thereby reducing SQL injection risks and making query construction more maintainable.

 The foundation of SQL query building is the predicate system, which consists of:

 
 - **AbsPredicates**: Abstract base class that provides methods to build SQL conditions like `EqualTo`, `NotEqualTo`, etc.
 - **AbsRdbPredicates**: Extends AbsPredicates with RDB-specific functionality
 - **RdbPredicates**: Implements AbsRdbPredicates for actual use in applications

 - Create and configure a predicate object with desired conditions

## Predicate Operations

 The following SQL operations are supported through predicate methods:

 
| Predicate Method | SQL Equivalent | Description |
|---|---|---|
| EqualTo | field = value | Equality comparison |
| NotEqualTo | field <> value | Inequality comparison |
| Contains | field LIKE '%value%' | Field contains the value |
| NotContains | field NOT LIKE '%value%' | Field does not contain the value |
| BeginsWith | field LIKE 'value%' | Field starts with the value |
| EndsWith | field LIKE '%value' | Field ends with the value |
| IsNull | field IS NULL | Field is NULL |
| IsNotNull | field IS NOT NULL | Field is not NULL |
| Like | field LIKE value | Pattern matching |
| NotLike | field NOT LIKE value | Negated pattern matching |
| Glob | field GLOB value | Wildcard matching |
| Between | field BETWEEN low AND high | Range inclusion |
| NotBetween | field NOT BETWEEN low AND high | Range exclusion |
| GreaterThan | field > value | Greater than comparison |
| LessThan | field < value | Less than comparison |
| GreaterThanOrEqualTo | field >= value | Greater than or equal comparison |
| LessThanOrEqualTo | field <= value | Less than or equal comparison |
| In | field IN (values) | Value in a set |
| NotIn | field NOT IN (values) | Value not in a set |

### Logical Operators

 Predicates can be combined with logical operators:

 
 - **And()**: Adds an AND condition (default between conditions)
 - **Or()**: Adds an OR condition
 - **BeginWrap()** / **EndWrap()**: Adds parentheses for grouping conditions
 
 
```
// SQL Equivalent: WHERE (field1 = 'value1' OR field2 = 'value2') AND field3 = 'value3'
predicates.BeginWrap()
    .EqualTo("field1", "value1")
    .Or()
    .EqualTo("field2", "value2")
    .EndWrap()
    .EqualTo("field3", "value3");
```

## Internal Implementation Details

 
### WhereClause Construction

 When constructing WHERE clauses, the `AbsPredicates` class manages:

 
 - The SQL string accumulation in `whereClause`
 - The bind arguments in `bindArgs`
 - Logical operators (AND, OR) and brackets for complex conditions
 
 
```
// Internal implementation flow:
EqualTo("field", value) -> 
    CheckIsNeedAnd() [adds "AND" if needed] -> 
    Append "field = ?" to whereClause -> 
    Add value to bindArgs
```

### SQL Assembly in SqliteSqlBuilder

 The `SqliteSqlBuilder` assembles the final SQL query by:

 
 - Creating the SELECT clause with columns and DISTINCT flag
 - Adding the FROM clause with table name
 - Adding Join, Where, Group By, Having, Order By clauses from predicates
 - Adding LIMIT and OFFSET clauses
 
 This is done through methods like:

 
 - `GetSelectClause`: Creates the SELECT part
 - `AppendClause`: Adds a clause to the SQL string
 - `AppendColumns`: Adds columns to the SELECT clause
 - `AppendLimitAndOffset`: Adds LIMIT and OFFSET clauses

## Conclusion

 The SQL Query Building system in OpenHarmony's Distributed Relational Database Management System provides a comprehensive, object-oriented approach to constructing SQL queries. It abstracts the complexities of SQL syntax while allowing for powerful query expressions. The system supports a wide range of SQL features including conditions, joins, grouping, ordering, and pagination. The architecture separates the query building concerns across different components, with predicates handling the logical conditions and SQL builders handling the final query assembly.
