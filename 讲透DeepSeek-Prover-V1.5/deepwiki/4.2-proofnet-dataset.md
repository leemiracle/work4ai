  The ProofNet Dataset is a collection of undergraduate-level mathematical problems formalized in the Lean theorem prover, used for training and evaluating the DeepSeek-Prover-V1.5 system. This page describes the dataset's structure, content, and its role in the theorem proving workflow within the DeepSeek-Prover ecosystem.

 For information about the miniF2F dataset, which contains high-school level problems, see [miniF2F Dataset](https://deepwiki.com/deepseek-ai/DeepSeek-Prover-V1.5/4.1-minif2f-dataset).

 
## Dataset Overview

 ProofNet was introduced in the research paper "ProofNet: Autoformalizing and Formally Proving Undergraduate-Level Mathematics" by Zhangir Azerbayev et al. It serves as a more advanced benchmarking dataset compared to miniF2F, allowing for evaluation of the system's ability to prove more complex theorems. In the DeepSeek-Prover system, this dataset is stored as `datasets/proofnet.jsonl`.

## Comparison with miniF2F

 The following table highlights the key differences between ProofNet and miniF2F datasets:

 
| Feature | ProofNet | miniF2F |
|---|---|---|
| Difficulty Level | Undergraduate | High School |
| Mathematical Domains | More advanced domains including topology and abstract algebra | Basic algebra, geometry, calculus |
| Problem Complexity | Higher conceptual and technical complexity | More straightforward applications |
| Formalization | Lean 4 formalization | Lean 4 formalization |
| Typical Use Case | Advanced capability testing | Basic capability verification |

 Together, these datasets provide a comprehensive evaluation framework for DeepSeek-Prover across different levels of mathematical complexity.

 
## Usage in Benchmarking

 The ProofNet dataset serves as a benchmark for evaluating the theorem-proving capabilities of the different DeepSeek-Prover model variants. Success rates on ProofNet theorems provide insights into how well the models can handle undergraduate-level mathematical reasoning.

 When running experiments with ProofNet, users can select different configurations and models to compare their performance. The configuration parameters control aspects like the sampling strategy, search depth, and other algorithm-specific settings that affect the proof search process.
