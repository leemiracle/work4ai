## Purpose and Scope

 Few-Shot Sampling is a proof generation approach within the DeepSeek-Prover-V1.5 system that enhances the basic sampling algorithm by incorporating example proofs to guide the language model. This technique leverages a set of previously solved theorems and their formal proofs to improve the model's ability to generate valid proofs for new, unseen theorems. This document explains the implementation, configuration, and workflow of Few-Shot Sampling in the DeepSeek-Prover-V1.5 system. For information about the basic Sampling algorithm without examples, see [Sampling Algorithm](https://deepwiki.com/deepseek-ai/DeepSeek-Prover-V1.5/3.1-sampling-algorithm).

## Overview

 Few-Shot Sampling works by prepending a small number of example theorem-proof pairs to the input prompt before asking the model to generate a proof for a new theorem. This provides the model with relevant context and solution patterns that it can adapt to solve the target problem.

## Few-Shot Examples Dataset

 The Few-Shot Sampling approach relies on a curated set of example theorems and their proofs from the `minif2f_valid_few_shot.jsonl` dataset. Each example contains:

 
 - A problem name
 - An informal problem description
 - A formal statement in Lean 4
 - A formal proof in Lean 4

## Workflow

 The Few-Shot Sampling workflow consists of the following steps:

 
```

```

 
 - The system loads the configuration and initializes the sampling algorithm
 - For each target theorem: 
 - The system loads 3 example problems from the few-shot dataset
 - A prompt is constructed with the examples and the target theorem
 - The DeepSeek-Prover-V1.5-Base model generates 128 proof candidates
 - Each candidate is verified by the Lean 4 verifier
 - The first valid proof (or failure) is returned

## Comparison with Other Approaches

 Few-Shot Sampling differs from other proof search algorithms in the DeepSeek-Prover-V1.5 system:

 
| Feature | Few-Shot Sampling | Basic Sampling | RMaxTS |
|---|---|---|---|
| Example incorporation | Yes | No | No |
| Model used | Base | SFT/RL | RL |
| Search strategy | Independent samples | Independent samples | Monte Carlo tree search |
| Feedback mechanism | Verification only | Verification only | Intrinsic rewards |
| Sample count | 128 | 128 | 6400 |
| Primary advantage | Guided by examples | Simplicity | Exploration effectiveness |

 Few-Shot Sampling is particularly well-suited for scenarios where:

 
 - The base model (without fine-tuning) is being used
 - Similar theorems have been proven before
 - The problem domain benefits from seeing solution patterns

## Implementation Details

 Few-Shot Sampling uses the Sampling algorithm class but enhances it with the few-shot examples capability. The key parameters that enable this functionality are:

 
 - `few_shot_dataset`: Specifies the dataset containing example theorems and proofs
 - `few_shot_num`: Determines how many examples to include in each prompt
 
 These parameters allow the system to dynamically select and incorporate appropriate examples before generating proofs for new theorems.

## Conclusion

 Few-Shot Sampling is a specialized proof generation technique that leverages example theorems and proofs to guide the DeepSeek-Prover-V1.5-Base model. By incorporating three carefully selected examples from the `minif2f_valid_few_shot.jsonl` dataset, the system provides the model with context and patterns that can help it generate valid proofs for new theorems. This approach is particularly valuable when using the base model without fine-tuning, as it simulates the benefits of specialized training through in-context learning.
