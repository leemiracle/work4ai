# Sampling Algorithm

  Relevant source files 
 - [configs/sampling.py](https://github.com/deepseek-ai/DeepSeek-Prover-V1.5/blob/2c4ba911/configs/sampling.py)
 
  The Sampling Algorithm is a straightforward approach to theorem proving in the DeepSeek-Prover-V1.5 system. This document explains the basic sampling method used for generating proofs, its configuration parameters, and how it functions within the proof generation pipeline. For information about the more advanced RMaxTS algorithm, see [RMaxTS Algorithm](https://deepwiki.com/deepseek-ai/DeepSeek-Prover-V1.5/3-rmaxts-algorithm), and for sampling with examples, see [Few-Shot Sampling](https://deepwiki.com/deepseek-ai/DeepSeek-Prover-V1.5/3.2-few-shot-sampling).

 
## Overview

 The Sampling Algorithm generates multiple proof attempts for a given theorem using a language model. Unlike the more complex RMaxTS algorithm that employs intrinsic rewards and exploration strategies, the basic sampling approach simply generates a specified number of proof candidates and verifies them using the Lean 4 proof assistant. This approach is simpler and requires fewer computational resources, making it suitable for initial experimentation or scenarios where resource constraints are a concern.

 The Sampling Algorithm configuration is defined in `configs/sampling.py` and consists of four main components:

 
 - **Dataset settings** - Specifies which theorems to prove
 - **Verifier settings** - Configures the Lean 4 prover parameters
 - **Model settings** - Defines the language model and generation parameters
 - **Algorithm settings** - Controls the sampling behavior

## Key Parameters

 The Sampling Algorithm has several key parameters that control its behavior and performance:

 
| Parameter | Default Value | Description |
|---|---|---|
| sample_num | 128 | Number of proof attempts generated for each theorem |
| log_interval | 32 | Frequency of logging progress during sampling |
| n_search_procs | 64 | Number of parallel search processes |
| lean_max_concurrent_requests | 64 | Maximum number of concurrent requests to Lean verifier |
| lean_timeout | 300 | Maximum time (in seconds) allowed for Lean to verify a proof |
| mode | "cot" | Proof generation mode ("cot" = chain-of-thought) |
| temperature | 1 | Controls randomness in proof generation |
| max_tokens | 2048 | Maximum length of generated proofs |
| top_p | 0.95 | Top-p sampling parameter for language model |

## Comparison with Other Algorithms

 The DeepSeek-Prover-V1.5 system implements three main proof search algorithms, each with different characteristics:

 
| Algorithm | Complexity | Exploration Strategy | Resource Requirements | Use Case |
|---|---|---|---|---|
| Sampling (Basic) | Low | Random sampling | Moderate | Quick experimentation, baseline evaluation |
| Few-Shot Sampling | Medium | Example-guided sampling | Moderate | Leveraging similar proofs as examples |
| RMaxTS | High | Intrinsic reward exploration | High | Advanced proof search with exploration |

 The basic Sampling Algorithm serves as a simpler alternative to RMaxTS, requiring fewer computational resources while still capable of proving many theorems. However, it lacks the sophisticated exploration capabilities of RMaxTS, which may lead to lower success rates on more complex theorems.

## Usage Example

 To use the Sampling Algorithm in DeepSeek-Prover-V1.5, you would run the system with the sampling configuration:

 
 - Ensure the repository is properly set up (see [Installation and Setup](https://deepwiki.com/deepseek-ai/DeepSeek-Prover-V1.5/1.1-installation-and-setup))
 - Run the proof search using the sampling configuration
 - Review the results to see which theorems were successfully proven
 
 The configuration is defined in [configs/sampling.py1-31](https://github.com/deepseek-ai/DeepSeek-Prover-V1.5/blob/2c4ba911/configs/sampling.py#L1-L31) which sets up the Sampling algorithm with the DeepSeek-Prover-V1.5-RL model to generate 128 proof attempts per theorem, using 64 parallel search processes.

 For practical guidance on running experiments with this algorithm, see [Running Experiments](https://deepwiki.com/deepseek-ai/DeepSeek-Prover-V1.5/5.2-running-experiments) and [Evaluating Results](https://deepwiki.com/deepseek-ai/DeepSeek-Prover-V1.5/5.3-evaluating-results).
