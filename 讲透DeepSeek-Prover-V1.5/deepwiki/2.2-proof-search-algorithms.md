## Purpose and Scope

 This document provides a detailed overview of the proof search algorithms implemented in the DeepSeek-Prover-V1.5 system. These algorithms are responsible for exploring the proof space and generating formal proofs for mathematical theorems in Lean 4. For information about the DeepSeek-Prover models themselves, see [DeepSeek-Prover Models](https://deepwiki.com/deepseek-ai/DeepSeek-Prover-V1.5/2.1-deepseek-prover-models), and for details about integration with Lean 4, see [Integration with Lean 4](https://deepwiki.com/deepseek-ai/DeepSeek-Prover-V1.5/2.3-integration-with-lean-4).

 
## Overview of Proof Search Algorithms

 DeepSeek-Prover-V1.5 implements three main proof search algorithms, each with distinct characteristics:

 
 - **RMaxTS** (Reward Maximizing Tree Search) - An advanced algorithm that combines Monte Carlo Tree Search with an intrinsic reward mechanism for diverse proof exploration
 - **Basic Sampling** - A simple sampling approach for proof generation
 - **Few-Shot Sampling** - Enhanced sampling that uses example proofs to guide the generation process

## RMaxTS Algorithm

 RMaxTS (Reward Maximizing Tree Search) is the most advanced proof search algorithm in DeepSeek-Prover-V1.5. It combines Monte Carlo Tree Search with an intrinsic reward mechanism to explore diverse proof paths more effectively.

 
### Configuration and Parameters

 The RMaxTS algorithm is configured with the following key parameters:

 
| Parameter | Value | Description |
|---|---|---|
| gamma | 0.99 | Discount factor for future rewards |
| sample_num | 6400 | Total number of proof attempts |
| concurrent_num | 32 | Number of concurrent proof attempts |
| tactic_state_comment | True | Whether to include tactic state comments in the proof |
| n_search_procs | 256 | Number of search processes |

 Sources: [configs/RMaxTS.py26-35](https://github.com/deepseek-ai/DeepSeek-Prover-V1.5/blob/2c4ba911/configs/RMaxTS.py#L26-L35)

 
### How RMaxTS Works

 
```

```

 RMaxTS maintains a search tree where:

 
 - Nodes represent states in the proof process
 - Edges represent proof steps (tactics)
 - Intrinsic rewards are assigned based on the novelty and promise of proof paths
 - The algorithm balances exploration of new proof paths with exploitation of promising ones
 
 The algorithm runs multiple concurrent search processes (up to 256 as configured) to efficiently explore the proof space. For each theorem, it attempts up to 6400 proof generations, selecting actions based on the accumulated intrinsic rewards.

## Basic Sampling Algorithm

 The basic sampling algorithm is a simpler approach that generates multiple proof attempts without the advanced exploration strategy of RMaxTS.

 
### Configuration and Parameters

 
| Parameter | Value | Description |
|---|---|---|
| sample_num | 128 | Total number of proof attempts |
| log_interval | 32 | Interval for logging progress |
| n_search_procs | 64 | Number of search processes |

 Sources: [configs/sampling.py25-31](https://github.com/deepseek-ai/DeepSeek-Prover-V1.5/blob/2c4ba911/configs/sampling.py#L25-L31)

 
### How Basic Sampling Works

 
```

```

 The basic sampling algorithm:

 
 - Loads a theorem from the dataset
 - Generates a proof candidate using the language model
 - Verifies the proof using Lean 4
 - If successful, records the proof and stops
 - If unsuccessful, continues until reaching the maximum number of attempts
 
 This algorithm doesn't maintain a search tree or intrinsic rewards, making it simpler but potentially less effective for complex theorems.

 Sources: [configs/sampling.py](https://github.com/deepseek-ai/DeepSeek-Prover-V1.5/blob/2c4ba911/configs/sampling.py)

 
## Few-Shot Sampling Algorithm

 Few-shot sampling enhances the basic sampling approach by incorporating example proofs to guide the model's generation process.

 
### Configuration and Parameters

 
| Parameter | Value | Description |
|---|---|---|
| sample_num | 128 | Total number of proof attempts |
| log_interval | 32 | Interval for logging progress |
| few_shot_dataset | 'datasets/minif2f_valid_few_shot.jsonl' | Dataset containing example proofs |
| few_shot_num | 3 | Number of examples to include |
| n_search_procs | 64 | Number of search processes |

 Sources: [configs/sampling_few_shot.py26-33](https://github.com/deepseek-ai/DeepSeek-Prover-V1.5/blob/2c4ba911/configs/sampling_few_shot.py#L26-L33)

 
### How Few-Shot Sampling Works

 
```

```

 Few-shot sampling:

 
 - Loads example proofs from the specified dataset
 - Prepares a prompt that includes these examples along with the target theorem
 - Generates a proof candidate using the language model
 - Verifies the proof using Lean 4
 - If successful, records the proof and stops
 - If unsuccessful, continues until reaching the maximum number of attempts
 
 This approach leverages the model's ability to learn from examples in-context, which can be particularly effective when using base models with less specialized training.

 Sources: [configs/sampling_few_shot.py](https://github.com/deepseek-ai/DeepSeek-Prover-V1.5/blob/2c4ba911/configs/sampling_few_shot.py)

## Performance Comparison

 Based on the evaluation results mentioned in the repository, the algorithms show different performance levels on benchmark datasets:

 
| Algorithm | miniF2F-test | ProofNet |
|---|---|---|
| Basic Sampling with DeepSeek-Prover-V1.5-Base | 42.2% | 13.2% |
| Basic Sampling with DeepSeek-Prover-V1.5-SFT | 57.4% | 22.9% |
| Basic Sampling with DeepSeek-Prover-V1.5-RL | 60.2% | 22.6% |
| RMaxTS with DeepSeek-Prover-V1.5-RL | 63.5% | 25.3% |

 This comparison demonstrates that while the quality of the language model is crucial (as seen in the progression from Base to SFT to RL), the search algorithm also makes a significant difference. The RMaxTS algorithm combined with the RL model achieves the best performance, highlighting the importance of sophisticated proof search strategies.
