# 11 · 不足与批判：这门学科自己的账

> 讲透Loop 第 11 章（五幕宪法的批判幕）| 给前十章泼冷水，按伤害程度排序

## 一、证据账：声量与采用的两个数量级

2608.21884 的硬数据是本学科最清醒的一盆水：

- **0.59%**：36,645 仓中确认自主循环运行的比率；
- **2 个**：满足内容标准的 state file 总数（配置进了 git，状态没进）；
- **0**：stop condition 文件 / 预算文件 / 循环引用的 verifier subagent；
- **6,290 次零命中**：xpk 的心跳型分诊从未匹配到任何活——定时器忠诚地空转。

读法：**话语（7 月前的博客浪潮）领先实践（0.59%）约两个数量级**。学科的存在性没问题（217 个真循环、概念一致性已被两篇论文整理），但它现在的身份是"有希望的研究议程 + 可用的工程模式"，不是"被验证的生产范式"。2608.21884 自己说：实践共识与证据真空并存（stable vocabulary paired with an almost complete absence of evidence）。

**对本单元读者的含义**：前十章的模式（五件套/阶梯/守卫）当作**设计检查表**用是安全的（防止已知的死法），当作**收益保证**用是危险的（没人测过 ROI——Willison 警告的原文还挂在那）。

## 二、经济账：循环把一切相乘，包括账单

三笔没人替你算的账：

1. **空转税**：heartbeat 的检查费与有无活无关（E3 定律 1；xpk 是极端案例）。10 分钟周期 + 500 tok/次检查 = 432k tok/月固定成本，在干活之前；
2. **验证费**：L4-L5 验证不是免费的（03 章冷水 1）——测试要写、Lean 规约要写、verifier subagent 每次跑都是钱。E4 Phase A 的守卫从 8% 提到 53%，代价是 token 均值 18.5k→39.4k（+113%）。**质量是买来的**；
3. **组合爆炸**： Osmani 的提醒——"same loop, opposite results"。同一个循环，理解工作的人用来加速，逃避理解的人用来慢性放弃理解。技术不区分两者，账单也不。

**定价纪律**：给任何循环开工前写一行——"这个循环的月成本上限 X，替代的人工时间 Y"。写不出 Y > X 的流程不配循环化（11 章练习 2 的理论依据）。

## 三、认知账：comprehension debt 与认知投降

2607.00038 的 limits 节给了本学科最深的两个警告：

1. **理解债（comprehension debt）**：循环产出的代码/文档/决策，人类团队成员越来越读不过来。代码能合并 ≠ 团队理解了它——债务在复利，清偿日是灾难日（事故时的 debug 时间）；
2. **认知投降（cognitive surrender）**：与理解债互为因果——因为读不过来所以不读，因为不读所以更读不过来。循环的效率恰恰来自它替你做了你不愿做的理解，这个"不愿"从任务溢出到领域，最后你只会按启动键。

对抗设计（不是鸡汤，是机制）：**循环必须产出人类可审的 diff 而非成品**（verifier 替你挡错误，不替你获得理解）；**每个循环保留一个人工复核终态**（哪怕 5% 抽查）；**定期亲手做一遍循环做的活**（MATH_LOOP_ENGINE 的七阶段循环里"①理论：复述问题（不看答案）"就是这条的实例——机器验证执行，人保留手感）。

## 四、安全账：无人值守是攻击面的最大化

E2-E4 全在讲"循环怎么失控"，还有一类死法是"循环怎么被骗"：

- **observe 是注入点**：内循环的信息必经之路（01 章冷水 3）——循环无人值守 = 注入的成功率上限从"骗过人肉验证"升到"骗过机器验证"。讲透Prompt 08 红队实验里所有注入技术在循环场景全部加倍危险（一次注入持续生效，state file 都可能被污染——06 章冷水 1）；
- **验证器是最高价值目标**：maker-checker 分离后，攻击者不骗 maker 骗 checker（改测试断言比改代码更隐蔽）。独立验证的独立性（异构模型/物理隔离的验证环境）是安全属性，不只是质量属性；
- **预算是最后的 DoS 防线**：恶意输入让循环空转烧钱——cap 之外，输入侧限速（事件队列上限）是循环特有的安全件。

## 五、理论账：四个没解决的问题

1. **循环级评估不存在**：单 run 有 benchmark（SWE-bench 等），循环没有（2608.21884 明确点名：评估单位该从单 run 变成"随时间运行的循环"——收敛性/累积成本/漂移/升级质量）。**谁先做出 loop benchmark，谁定义下一代工具**；
2. **reward 的层级问题没有闭式解**：03/08 章的阶梯是定性规律（文献综合），不是定理——"L2 信号驱动 L4 改动必坏"是强先验，没有证明；
3. **非平稳性**：模型一升级，$g$（IMPROVE 算子）全变，昨天的最优配置今天未必收敛（09 章冷水 2）——版本锁定是权宜，理论缺口是真缺口；
4. **多循环交互**：本单元全程假设单循环。两个 goal loop 改同一个仓库、一个循环的产出是另一个的输入——组合行为（死锁/共振/资源竞争）完全未研究，是 Agent 多智能体文献与循环工程的未接壤地带（讲透Graph 的 Task Org 支柱是邻接尝试）。

## 六、总账：这门学科值不值得学

**值**，理由三条，按权重：

1. **模式层即刻可用**：五件套/阶梯/守卫/形状是防死检查表——E2-E5 证明的每种死法都有对应的便宜保险。0.59% 的低采用率对早期学习者是**红利**（蓝领稀缺期），不是劝退信号；
2. **结构层正在定形**：两篇论文（2607.00038/2608.21884）已经把词汇表钉死，2026-2027 的实证空位（loop benchmark/循环级评估/状态版本控制）是研究者红利窗口；
3. **它是三部曲的必然收口**：Prompt（问）→ Context（喂）→ Loop（转）——控制权逐层上交的终点是"设计那个替你按下一次交给的系统"。学完本单元，你对每个 AI 工具的读法都变了：**看见的是四层塔，不只是聊天框**。

不值的部分也说清：**别指望它现在就省钱**——没有 ROI 研究，你的循环账单是你自己的实验数据。把它当工程判断力的投资，不是当效率工具的采购。
