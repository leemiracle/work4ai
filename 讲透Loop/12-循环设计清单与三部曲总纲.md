## 一、循环设计清单（12 问，开工前过一遍）

来自前十一章的浓缩。**任何一格答不上来，循环不开工**（02 章模板 + 全单元定律）：

### 结构（02 章）
- [ ] 1. Trigger：谁按启动键？（人/定时/事件——自动化程度是有意选择，不是默认）
- [ ] 2. Goal：目标写成机器可验证的形态了吗？（"质量变好"❌，"测试全绿"✅）
- [ ] 3. 五终态命名了吗？（success / no-op / blocked / stalled / exhausted——循环不许无声消失）

### 验证（03 章）
- [ ] 4. 验证在阶梯第几级？（L1 自评 → L3 判官 → L4 测试 → L5 形式）
- [ ] 5. maker ≠ checker 了吗？（判卷的不能是干活的，连"停止判定"也算判卷）
- [ ] 6. 单轮漏检率 p 与任务轮数 T 满足 p < ε/T 吗？（30 轮要 <5% 早停 → p < 0.0017）

### 守卫（05 章）
- [ ] 7. Cap 装了吗？（轮数+token 双 cap，设在时长分布 p95-p99 内，不设远尾）
- [ ] 8. 熔断装了吗？（K 轮无**外部可观测**进展 → stalled；信号不能是自评）
- [ ] 9. 三守卫成套？（cap 防伪进展 / 熔断防无进展 / 独立验证防假完成——缺一必有对应死法）

### 状态与形状（04/06 章）
- [ ] 10. State file：读帧写验 + 事实非 vibes + resume 一行？进版本控制了吗？
- [ ] 11. 形状对位？（监控→heartbeat（加锁！）；批处理→cron；响应→hook；未知范围→goal（强制 cap））

### 经济与认知（11 章）
- [ ] 12. 账算过了吗？（月成本上限 X vs 替代人工 Y，Y > X 才开工；人审终态留了吗？）

**反着用也行**：拿现有循环对清单做减法——哪格空着，哪个死法在路上。

## 二、三部曲总纲：Prompt × Context × Loop

一个任务穿过四层塔时，每一层问的问题（本三部曲的最终一图）：

```
┌─ L3 Loop（讲透Loop）────────────────────────────────────────┐
│ 谁触发？怎么验证？何时停？状态在哪？怎么越转越强？              │
│ 公理：验证到哪里，自治就到哪里；循环把一切相乘，包括账单        │
│ 数学：p<ε/T · 1/p_leak · q^t · e*=f/(r+f)                    │
├─ L2 Harness（讲透Agent/讲透Skills）─────────────────────────┤
│ 单次 run 里：给什么工具？挂什么钩子？载什么技能？              │
│ 公理：skills 是写下来的意图，让循环不必每次重推导你的项目       │
├─ L1 Context（讲透Context）──────────────────────────────────┤
│ 每一轮窗口里：放什么？怎么压？什么留在盘上？                   │
│ 公理：放进去 ≠ 用得上（Context Rot）；策展是预算问题          │
│ 数学：单向通信复杂度 · Bloom filter 与摘要的对决              │
├─ L0 Prompt（讲透Prompt）────────────────────────────────────┤
│ 单次调用里：这句话怎么写？                                     │
│ 公理：prompt 是条件概率里的条件——控制信号，不是咒语            │
│ 数学：OPRO 优化循环 · few-shot 的 ICL 贝叶斯观                │
└──────────────────────────────────────────────────────────────┘
```

三部曲的**分工表**（README 的扩展版，终章定稿）：

| 问题 | Prompt | Context | Loop |
|------|--------|---------|------|
| 研究对象 | 单条指令的措辞 | 窗口的信息构成 | 跨运行的控制结构 |
| 时间尺度 | 单次调用 | 单次 run 内 | 多 run 之间 |
| 核心公理 | 指令=条件 | 策展≠堆料 | 验证定自治 |
| 典型失败 | 注入/敏感 | Rot/压缩失真 | 早停/失控/失忆/自欺 |
| 数学工具 | ICL/OPRO | 通信复杂度 | 不动点/累积律/成本期望 |
| 代表实验 | SelfConsistency 消融 | Bloom vs LLM 摘要（97.9% vs 77.1%） | 三守卫蒙特卡洛（87.3% 早停） |
| 姊妹学科 | 语言学/修辞学 | 信息论/图书馆学 | 控制论/运筹学 |

**三部曲的一句话收口**：Prompt 教你怎么**问**，Context 教你怎么**喂**，Loop 教你怎么**放手**——而放手的全部艺术是：先造一个值得信任的"查"，再把"停"交给它。

## 三、本单元定律速查（全数值验证过）

| 定律 | 一句话 | 数字 |
|------|--------|------|
| 自评不可停 | 模型对完成度系统性过度自信 | 87.3% 早停（E2a） |
| 漏检复利 | 单轮 p，T 轮后 ≈ pT | 1% → 19.4%（理论 20.5%） |
| 验证-成本耦合 | 验证越强，卡死越贵 | 1/p_leak = 100 轮（E2b） |
| 形状税 | goal 无上限 = hook 的 5.7 倍 | 1550k vs 271k（E3） |
| Cap 定位律 | cap 设远尾 = 心理安慰 | P(超25轮)=0.13%（E3） |
| 守卫税与退法 | 熔断误杀可从 trace 诊断 | K 8→14：42.8→53.3%（E4） |
| Goodhart 剪刀差 | 坏 reward 完美地优化到全错 | 产出率 +193%，真成功 53→8.6%（E4） |
| 遗忘地板 | e*=f/(r+f)，state file 降 f | 0.2222 精确命中（E5-D2） |
| 步长分界 | 改过头=振荡，r<2 收敛 | q=|1-r|（E5-D1） |
| 成本期望 | E[T]=W/p | 偏差 0.1%（E5-D3） |

## ✍️ 毕业练习（30 分钟，做完全单元才算数）

1. **从零造一个真的循环**：选一个 5 分钟可完成的小任务（如"每天检查某目录的 md 是否全挂网"），用 12 问清单 + opencode 零件（schedule_job + bash 检查 + 输出到 inbox）组装成完全体。跑三天，记录：成本、命中、误报。
