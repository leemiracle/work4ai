# 02 · 循环规格五件套：trigger / goal / verification / stopping / memory

> 讲透Loop 第 2 章 | 数据基座：Loop Library 50-loop 语料（2607.00038）+ 36,710 仓挖掘（2608.21884）

## 一、直觉层：循环的最小完整定义

外循环不是"跑个 while true"。2607.00038 给出学科化的定义——**循环规格（loop specification）**：

> 一个有界的、可复用的工件，由**触发器、目标、验证、停止规则、记忆**五部分组成，人类把它交给 harness，agent 借此独立追求目标，取代逐步人工 prompting。

五件套逐个说人话：

| 件 | 回答的问题 | 反面（缺了会怎样） |
|----|-----------|------------------|
| **Trigger 触发** | 谁按启动键？人/定时/事件 | 没有它 = 你还是调度器 |
| **Goal 目标** | 干什么？最好可验证 | "把网站弄好点" = 循环朝任意方向跑 |
| **Verification 验证** | 怎么确认真做完了？（03 章阶梯） | 模型自评 = 87% 早停（E2a） |
| **Stopping rule 停止规则** | 何时进哪个终态？ | 永不停止或错称胜利 |
| **Memory 记忆** | 进度和决策记在哪？（必须盘上，不是对话里） | 每次 run 从失忆开始，重复劳动 |

**五终态命名**（2607.00038 的贡献——循环不许"无声消失"）：`success`（真完成）/ `no-op`（检查了，没活干）/ `blocked`（被外部卡住，需升级人类）/ `stalled`（无进展，熔断）/ `exhausted`（预算烧穿）。给终态命名 = 给循环的死亡开死亡证明——每个终态对应不同的后续动作（success→合并，blocked→人类介入，stalled→换策略，exhausted→加预算还是放弃？）。

## 二、数据层：实践者到底在用什么（50-loop 语料 + 36,710 仓）

### 2.1 Loop Library：成熟在哪、幼稚在哪

2607.00038 手工编码了公开 Loop Library 的 50 个真实循环：

| 元素 | 采用率 | 判词 |
|------|--------|------|
| 命名终态 | **74%** | 成熟 |
| 自主验证（阶梯 L3+） | **70%** | 成熟 |
| 可验证目标 | **66%** | 成熟 |
| 持久记忆 | 32% | 幼稚 |
| 自动触发 | 22% | 幼稚 |
| 调用具名 skills | 20% | 幼稚 |

**一句话读法**：实践者解决了"怎么知道做完了"（验证侧 70%+），远没解决"怎么没人也能跑"（自治侧 20-32%）。这正是年轻学科的合理形态——先保命（验证），再放手（自治）。也预言了下一轮工程投入方向：**state file、自动触发、skill 化**——恰好是 06 章和讲透Skills 的交叉点。

### 2.2 36,710 仓：真实世界的采用率

2608.21884（2026-08-25 提交，JAWs@ASE 2026 workshop）的挖掘研究：

- 36,645 有效仓扫描，**253 个**有 trigger（35 scheduled / 205 event / 13 both），几乎全是 GitHub Actions workflow；
- 256 抽检人工确认 **217 个真跑循环** → **0.59% 采用率**（精确率 0.868）；
- **合格 state file：全部 36,645 仓里只有 2 个**；零 stop condition 文件、零预算文件、零循环引用的 verifier subagent；
- 反例警示：AI-Hypercomputer/xpk 的每小时 Gemini 分诊 **6,290 次运行零命中**（gating issue search 从没匹配到东西）——定时器在转，活从来没来过。**heartbeat 的成本下限是检查费，且它不问你有没有活**；
- 结论："宣传声量与真实采用差两个数量级；循环的配置进了版本控制，运行时状态完全在外面。"

### 2.3 两份数据的合读

学术定义（五件套）与实践（50-loop 语料）之间：验证/终态已经收敛为共识，**memory/trigger/skill 化是 2026-2027 的主战场**。你可以把这个差距当作路线图——谁能便宜地做对 state file 和自动触发，谁就吃到下一波红利。

## 三、设计层：五件套的填写模板

拿到任何"让 agent 自动干活"的需求，先填这张表（空着任何一格就不许开工）：

```yaml
trigger:      cron "0 9 * * *" | webhook pr-opened | manual | goal-loop-self
goal:         "讲透Loop 单元 00-12 章全部完成且 experiments 全绿"   # 可验证形态
verification: # 03 章阶梯选级
  - L4: ls 讲透Loop/0*.md 0[1-9]*.md 1[0-2]*.md | wc -l == 13
  - L4: python 讲透Loop/experiments/XX.py 退出码 0
  - L3: 独立判官 subagent 对照篇目表核对
stopping:
  success:    全部 L4 检查通过
  stalled:    连续 2 次运行无新文件产出 → 升级人类
  exhausted:  累计 token > 2M 或 wall-time > 6h
  no_op:      篇目已齐且实验已绿 → 直接退出
memory:
  file:       讲透Loop/RESUME-0826.md      # 盘上，不是对话
  protocol:   读帧（run 开始读）→ 写验（run 结束写）→ resume-point 一行
budget:       2M tok / 6h / p95 单任务 < 120k
escalation:   stalled|blocked → 人类 triage inbox
```

（这张表不是假想——它就是本单元自己被构建的方式：RESUME-0826.md = memory，篇目表 = goal，experiments 退出码 = L4 验证，todowrite = stopping 的可视化。10 章活案例逐项对号。）

**反模式速查**（2607.00038 锚定在 reward hacking / model-as-judge 文献）：

1. **不可验证目标**（"提升质量"）→ 循环把它翻译成最容易满足的代理指标，然后优化代理；
2. **无名终态**（没有 stalled/exhausted 命名）→ 每次失败都是"某种成功"，学习信号丢失；
3. **记忆在对话里**→ 每次 run 重付理解成本，且无法断点续传；
4. **触发靠人**→ 五件套缺一，你不是在做循环，是在做一次性脚本。

## 四、与四形状的关系（04 章预告）

五件套回答"循环由什么组成"，四形状（heartbeat/cron/hook/goal）回答"循环怎么被点燃和停止"——trigger × stopping 的 2×2 组合拳。五件套是名词，四形状是动词。

## 五、不足与批判

1. **五件套是规格不是科学**：2607.00038 自陈"position paper 锚定描述性语料"——没有受控实验、没有 ROI 数据。"70% 自主验证更好"是实践共识，不是因果证据（2608.21884 计划中的 C1/C2/C3 对照实验才是第一步）；
2. **语料偏差**：Loop Library 是自愿公开的循环——活下来的循环。死掉的循环（烧穿预算、删库跑路）不进语料，幸存者偏差天然存在；
3. **"有界可复用"的理想 vs 一次性现实**：50-loop 语料里很多"循环"其实是跑一次就扔的长任务。规格的复用性在实践里可能是伪需求——值得你自己用 E3 的成本模型反问：这个循环值得复用吗，还是 hook 一次性更便宜？

## ✍️ 练习（15 分钟）

1. 把 2.3 的 YAML 模板套在你手头一个真实任务上（比如"MATH_LOOP_ENGINE Wave 4 完成"）。五件套哪格最难填？难填的那格就是任务不适合全自动的地方——把它降级成 report-only 循环（人审出口）。
2. 用 2608.21884 的方法自查本仓库：`grep -r "RESUME" --include="*.md" -l | wc -l`——你有几个"合格 state file"？对照"36,645 仓只有 2 个"，你的实践超过全世界多少百分位？
3. 思考题：xpk 的 6,290 次零命中运行，该怪 trigger 还是 goal？（答案方向：goal 的 gating 条件写得永远不可满足——五件套里最便宜的一格，毁掉最贵的循环。）
