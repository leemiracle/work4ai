# 01 · 内循环解剖：Agent Loop 就是 while not done

> 讲透Loop 第 1 章 | 三层宪法：直觉 → 数学 → 代码 | 实验：E1（`experiments/01_loop_dynamics.py`）

## 一、直觉层：三行代码的 agent

eesel 对 agent 的定义直白到粗暴：**"an LLM in a `while` loop with tools"**（一个在 while 循环里带工具的 LLM）。循环转一圈五件事：

```
perceive  感知   —— 收进新信息（用户输入/工具结果/环境变化）
reason    推理   —— 想清楚现在什么状况
plan      规划   —— 决定下一步干什么
act       行动   —— 调工具（写文件/跑命令/发请求）
observe   观察   —— 看行动结果，喂回 perceive
```

转到的唯一出口是 `done`。**agent 与 chatbot 的全部区别就在这个循环上**：chatbot 一次过（单次感知→推理→回答），agent 持续多步、边走边改。

## 二、三个易混对象（2607.00038 的地基区分）

这门学科最大的术语地雷：三个东西都叫"循环"。2607.00038 专门用一节掰开：

| 对象 | 定义 | 谁设计 | 例子 |
|------|------|--------|------|
| **编程循环** | 语言级控制流语句 | 程序员 | `for`/`while` |
| **内循环**（agent loop） | harness 自带的 perceive→act→observe 圈，**单次 run 内** | 工具厂商 | Claude Code/Codex 的主循环 |
| **外循环**（loop specification） | 触发→验证→停止→记账的规格，**跨 run** | 循环工程师（你） | `/goal`、cron 自动化、MATH_LOOP_ENGINE |

为什么必须区分：**内循环是 plumbing（管道），外循环才是设计对象**。你买的 harness 已经会转内循环——Loop Engineering 问的是这个内循环何时被谁点燃、烧多久、怎么验收。混淆两者的典型症状：把"agent 能多步推理"误当"agent 能自主运行"——前者是内循环（厂商给你了），后者是外循环（没人给你，你得设计）。

另一个易混对象（2607.00038 同节）：**bare scheduled prompt（裸定时 prompt）不是循环**。每天 cron 打一次 prompt、跑完即弃——没有验证、没有停止规则、没有状态记账，只是定时器。循环的最小完整定义见 02 章五件套。

## 三、数学层：内循环是一个随机过程的实现

内循环每一步本质是从策略分布采样：

$$a_t \sim \pi_\theta(a \mid s_t), \qquad s_{t+1} = f(s_t, a_t, \epsilon)$$

- $s_t$：状态 = 上下文窗口的全部内容（讲透Context 的研究对象在这进入循环数学）
- $\pi_\theta$：LLM 即策略（温度>0 时是随机策略）
- $f$：环境（工具执行 + 结果回填）
- 停止：内循环的 `done` 由 harness 判（通常 = 模型不再调工具 / 达到轮数上限）

三个直接推论：

1. **轨迹是随机的**：同一任务重跑，token 成本和结果都不同——所以循环的评估必须看分布（E2/E3 用蒙特卡洛 N=10,000/2,000 而不是单次 run 的原因）；
2. **这是 MDP**（无折扣、episode 制）：内循环就是 RL episode 的工程化表亲——RL 训练时梯度穿过 $\pi_\theta$，推理时 $\theta$ 冻结、循环照转。这就是为什么 RL 文献里的 failure mode（探索不足、局部最优、奖励黑客）全部会在工程循环里原样复发；
3. **同构族**（同一棵数学树的四个名字）：

| 域 | 同构循环 |
|----|---------|
| 控制论 | 反馈回路（sensor→controller→actuator→sensor） |
| 军事决策 | OODA（Observe→Orient→Decide→Act） |
| 学习理论 | Kolb 经验学习圈（经验→反思→概念化→实验→…） |
| 科学方法 | 假设→实验→分析→理论→… |
| RL | episode：$s_0,a_0,r_0,\dots,s_T$ |

MATH_LOOP_ENGINE §〇 说"验证信号驱动的一切学习都是这个循环"——内循环解剖给出了它的数学形状：**带外部验证信号的离散时间迭代过程**。收敛性留到 09 章用不动点理论处理。

## 四、代码层：E1 最小实现（已跑通）

`experiments/01_loop_dynamics.py` 的 E1 部分——一个带停止判定的四行内循环：

```python
W, t = 8, 0
while t < 40:                      # cap（守卫，05 章）
    t += 1
    progressed = rng.random() < 0.35   # act：真实推进（概率性）
    if progressed and W > 0: W -= 1    # observe：世界状态更新
    claim = rng.random() < (0.95 if W == 0 else 0.10)  # 自评停止（L1 验证）
    if claim: break                # ← 停止判定：全部学科押注处
```

实测轨迹（seed=7）：第 2 轮自报完成，真实剩余工作 W=7 → **PREMATURE（早停）**。四行代码就演示了内循环的全部要素与最经典的失败——停止判定交给模型自评。

复现：

```bash
python 讲透Loop/experiments/01_loop_dynamics.py   # E1 demo 在输出第一段
```

## 五、内循环的工程参数表

把内循环当作可调机器，它的旋钮与归属：

| 参数 | 谁控制 | 讲透位置 |
|------|--------|---------|
| 工具集（能做什么） | harness 配置 | 讲透Agent Ch02 |
| 每步上下文构成（看见什么） | context engineering | 讲透Context 全单元 |
| 每步的指令（怎么想） | prompt/skills | 讲透Prompt / 讲透Skills |
| 轮数上限/步预算 | harness + 守卫 | 本章 cap，05 章展开 |
| 停止判定 | **外循环设计者** | 03 章验证阶梯 |

注意最后一行：**内循环的出口归外循环管**。这就是两层循环的接口——也是本单元接下来 11 章的入口。

## 六、不足与批判

1. **"while not done" 的 done 是软的**：harness 的默认 done（模型不再调工具）≠ 任务完成——模型说完了不等于做对了。这个 gap 是 03 章验证阶梯的出发点；
2. **内循环有内在退化**：轮数越多上下文越长，Context Rot 使单步决策质量下降（讲透Context E3 的曲线）。Ralph Loop 的"每轮重置上下文"设计就是对这个退化的直接回应——用外循环的重启换内循环的清醒；
3. **同构不等于等价**：OODA/Kolb 的类比帮助直觉，但人类循环有内化的世界模型，agent 循环的世界模型全靠 observe 喂——信息必经之路就是攻击面（prompt 注入的循环版：污染 observe 等于污染整个后续轨迹，见讲透Prompt 08 红队实验）。
