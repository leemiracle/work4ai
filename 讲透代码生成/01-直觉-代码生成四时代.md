# 💻 第 1 幕 · 直觉：代码生成的四个时代

## 一个残酷的真相：AI 写代码看起来对，跑起来错

你让 Copilot 写一个调用 Stripe API 退款的函数。它写得**行云流水**——导入库、设 client、调 `refunds.create()`、处理异常、返回结果。你扫一眼：完美。

你跑起来——**崩了**。它调用的 `stripe.refunds.create()` 方法在 2025 年的 SDK 里早就改签名了，那个参数叫 `payment_intent` 不叫 `paymentId`。它**自信地幻觉了一个不存在的 API**。

这就是代码生成的核心张力，用一句话：

> **自然语言的统计流畅性 ≠ 程序的语义正确性。** LLM 在「写出来像对的」这件事上世界级，在「跑起来是对的」这件事上仍不可靠。

整部「讲透代码生成」在追踪：**人类花了 60 年，怎么把「写得像」变成「跑得对」？**

---

## 四个时代：每代换一个核心信念

```
第 1 代 模板/宏         第 2 代 AST 规则        第 3 代 统计生成        第 4 代 Agentic
(1960s-)              (2010s-)              (2021-)               (2024-)
确定性但死板           可分析但不会写         流畅但不可靠           能写能改能验证
"能查不能写"          "能查不能写"          "能写不能信"          "能写能验证"
```

### 第 1 代 · 模板与宏（1960s-）

**核心信念**：代码生成 = 把参数填进预定义模板。

Lisp 宏、C 预处理器、代码生成器（如 gRPC stub、ORM scaffold）——**确定性 100%，但只能生成你预先想到的所有变体**。

**崩溃点**：现实的需求是无限的，模板是有限的。模板覆盖不到的，就回到手写。

**遗产**：今天依然活在每个 `create-react-app`、`rails generate`、OpenAPI codegen 里。它没死，只是退守到「确定性骨架生成」这个 niche。

### 第 2 代 · AST 规则分析（2010s-）

**核心信念**：代码生成不够，还要**代码理解**——把代码解析成抽象语法树（AST），用规则做查询/变换/检查。

CodeQL（GitHub）、Semgrep、tree-sitter、AST-grep——**能精准定位「所有用了不安全函数 `eval()` 的地方」，但本身不会写新代码**。

**崩溃点**：规则是人写的，覆盖不到新型 bug。且只能匹配，不能创造。

**遗产**：今天活在所有 linter、静态分析、重构工具里。它是第 4 代 Agentic 的**眼睛**——agent 改完代码用 AST 工具验证。

### 第 3 代 · 统计生成（2021-）

**核心信念**：用海量代码训练一个语言模型，让它**统计地预测下一个 token**。

Codex（OpenAI 2021）、GitHub Copilot、CodeT5、StarCoder——**第一次，AI 能写出它没见过的、连贯的、看起来对的代码**。

**崩溃点**：就是开头那个故事——**统计流畅 ≠ 语义正确**。它会幻觉 API、漏边界条件、多步推理跑偏。SWE-bench（解决真实 GitHub issue）2024 年初只有 ~13%——**「看起来会写」和「真的会解决工程问题」之间有条深渊**。

**遗产**：今天活在所有 IDE 的 tab 补全里。它把「写一行」的成本降到了接近 0。

### 第 4 代 · Agentic（2024-）

**核心信念**：**不指望一次写对，让 LLM 在「生成→执行→看报错→再改」的闭环里迭代**。

CodeAct（Wang 2024，用代码本身当 action）、Cursor、Claude Code、OpenCode、Aider、Devin——**LLM 主动跑代码、读错误、改、再跑**，像人类工程师一样 debug。

**为什么这是质变**：它把代码生成从「一次射击」变成了「**耗散结构**」——每轮测试都是负熵注入，把统计噪声泵出系统。SWE-bench 从 13% 涨到 50%+ 靠的不是模型变强，是**引入了执行反馈闭环**。（这正是 `故事原语/02-熵论辩证` 的直接体现：迭代即熵泵。）

**当前崩溃点**：长任务（>1 小时）仍会跑偏；评估难（通过测试 ≠ 正确）；成本高（多轮调用）；安全（agent 能改文件能跑命令=能搞破坏）。

## 一个关键判据：你能「验证」吗

四代演化的背后是一条暗线——**验证能力的演化**：

| 代 | 能生成 | 能验证吗 |
|---|---|---|
| 1 模板 | 只能生成模板覆盖的 | ✅ 模板对就对（确定性） |
| 2 AST | 不生成，只分析 | ✅ 规则匹配即对 |
| 3 统计 | 能生成任意 | ❌ **没有内建验证**——靠人 |
| 4 Agentic | 能生成任意 | ✅ **跑测试/编译器/类型检查** |

**第 3 代之所以不可信，是因为它割裂了「生成」和「验证」**。第 4 代把它们重新焊上了。这是为什么 2024 年后所有认真做代码生成的，都在往 Agentic 走。

---

## 2024-2026 的真实标尺（别被营销骗了）

- **SWE-bench Verified**（解决真实 GitHub issue，有人工验证）：2024 初 ~13% → 2024 末 Claude 3.5 Sonnet ~49% → 2026 顶尖系统破 70%。**这仍是「半自动」，远未到「全自动」**。媒体常拿 70% 说「AI 工程师来了」——但那 30% 失败的往往是最难的。
- **真实开发工作流**：Cursor / Claude Code / OpenCode / Aider 已是日常工具，但**主流用法是「AI 写+人审」**，不是「AI 独立交付」。Devin 那种「全自动 demo」离生产还远。
- **MCP（Model Context Protocol）**：Anthropic 2024 推的开放协议，让 LLM 标准化接工具/数据源——是 code agent 的「USB-C」。2025 年快速成为事实标准。
- **CodeAct 范式**：用「代码作为 action」取代 JSON function calling，更灵活——LLM 直接写一段 Python 来调用工具，而不是填表。

## Agentic 代码生成的最小回路（剧透第 3 幕）

第 4 代的本质是这个循环：

```
while not done:
    1. 读上下文（文件/报错/任务）
    2. 决定下一步（改哪个文件/跑什么命令）
    3. 执行（写文件/跑测试）
    4. 看反馈（编译错误/测试失败/diff）
    5. 如果对了→下一步，错了→修正
```

**这个循环就是费曼学习法的 F1-F4**（见项目 `费曼学习法/`）：做→卡壳→修正→回炉。代码 agent 在自动跑这个循环。第 3 幕我们会用 150 行 Python 把它实现出来。

## 与其他宇宙的连接

- **`Karpathy经典代码精读/`**（已有）：那边读别人的代码（理解），这边让 AI 写代码（生成）。理解是生成的逆问题。
- **`讲透多Agent协作/`**：并行多 agent coding 的核心难题是 **file ownership**——两个 agent 同时改一个文件会冲突。这是第 5 幕的应用主题。
- **`讲透上下文缓存/`**：coding agent 的瓶颈往往是 context 管理。Augment 的 60 万 token 之所以震撼，是因为它让 agent 能「记住整个代码库」。
- **`故事原语/02-熵论辩证`**：第 3→4 代的跃迁，本质是**把代码生成从「开环」变成「耗散结构」**——引入执行反馈作为负熵泵。

---

## 🎬 本幕收束

> **代码生成的 60 年，是「让机器写得越来越像」到「让机器跑得越来越对」的 60 年。** 前 3 代都在改进「写得像」，第 4 代才真正攻克「跑得对」——靠的不是更聪明的模型，而是把生成和验证焊成闭环。**这就是为什么 Agentic 不是噱头：它第一次让代码生成变成了耗散结构。**
