# 📐 第 2 幕 · 数学：代码为什么会生成，如何让它正确

## 1. 代码 = AST 上的概率分布

一段代码 $c$ 可解析为抽象语法树 $T(c)$。代码生成 = 在 AST 上学一个概率分布：

$$P(c) = \prod_{i=1}^{n} P(\text{token}_i \mid \text{token}_{<i})$$

这是自回归分解。**LLM 学的不是「语法」，是 token 序列的统计延续**——但语法恰好是这种统计的结构性副产物。

## 2. BPE 对代码的影响

代码不是自然语言。BPE 分词对代码有几个坑：

- **空格敏感**：Python 缩进、JS 的 ASI。BPE 可能合并跨空格的 token，破坏缩进语义。
- **标识符切碎**：`getUserInfo` 可能被切成 `get`/`User`/`Info`，模型看不到完整标识符。
- **数字/运算符**：`x += 1` 的 `+=` 是否是单 token 影响生成质量。

**代码专用分词器**（如 StarCoder 的）针对这些优化。但仍非完美——这就是为什么 LLM 偶尔生成语法错的代码。

## 3. Infill vs Prefix Completion

两种生成模式：

**Prefix（补全）**：给定前缀 $x_{<t}$，续写。
$$P(x_t \mid x_{<t})$$

**Infill（填充）**：给定前缀 $x$ 和后缀 $y$，填中间 $z$。
$$P(z \mid x, y)$$

Infill 更难——要双向看。Cursor/Copilot 的「编辑中间代码」需要它。Codex/FIM（Fill-in-the-Middle）用特殊 token 标记前后缀。

## 4. 约束解码：让输出可解析

朴素采样可能生成语法无效的代码/JSON。**约束解码**在采样时强制遵守语法：

$$\text{token}_t = \arg\max_{v \in \text{Valid}(\text{grammar}, \text{prefix})} P(v \mid \text{prefix})$$

其中 $\text{Valid}$ 是「在当前前缀下，语法允许的下一个 token 集合」。

**实现路线**：
- **outlines**（2024）：把正则/CFG 编译成状态机，引导采样
- **XGrammar**（2024）：把 JSON schema 编译成高效 mask
- **tokenizer-level**：直接在词表上算合法集

**收益**：JSON/代码生成从「90% 可解析」到「100% 可解析」。代价是少量生成多样性。

## 5. Agentic 闭环：把误差率压下去

第 1 幕说「Agentic = 耗散结构」。数学化：

设单步正确率为 $p$。$k$ 步全对概率 $p^k$ 指数下降。**开环（一次写完）长任务必然崩**。

引入执行反馈后，每步可以**修正**。若反馈让错误率从 $1-p$ 降到 $\epsilon$，$k$ 步累积错误率：

$$P(\text{fail}) \leq k\epsilon \quad \text{(union bound)}$$

线性而非指数。**这就是 Agentic 的本质红利**：把指数衰减变成线性可控。

## 6. 温度与探索-利用

采样温度 $T$ 控制探索：

$$P_T(v) = \frac{\exp(\logit_v / T)}{\sum_v \exp(\logit_v / T)}$$

- $T \to 0$：贪婪，确定性（exploit）
- $T \to \infty$：均匀随机（explore）

代码生成通常 $T \in [0, 0.3]$——要确定性强。debug 时偶尔提 $T$ 探索新思路。**这就是 RL 的 explore-exploit 在生成层的投影**。
