## Purpose and Scope

 This page describes the internal architecture of vision-language models (VLMs) as implemented in SGLang. It covers the structure of `*ForConditionalGeneration` model classes, vision encoder components, the shared `VisionAttention` module, multimodal projectors, and the data structures used to transport multimodal features (`MultimodalInputs`, `MultimodalDataItem`). It also explains how visual features are merged into the text embedding stream via `general_mm_embed_routine`.

 For details on how images, videos, and audio are loaded and preprocessed, see [Multimodal Input Processing](https://deepwiki.com/sgl-project/sglang/18.2-multimodal-input-processing). For a listing of specific supported VLM architectures, see [Supported Vision-Language Models](https://deepwiki.com/sgl-project/sglang/18.3-supported-vision-language-models).

## Multimodal Data Structures

 SGLang uses two primary data structures to represent multimodal inputs: `MultimodalDataItem` and `MultimodalInputs`.

 
### `MultimodalDataItem`

 Defined in `python/sglang/srt/managers/schedule_batch.py`, `MultimodalDataItem` encapsulates inputs for a single modality (image, video, or audio).

 
| Field | Type | Description |
|---|---|---|
| modality | Modality enum | IMAGE, MULTI_IMAGES, VIDEO, or AUDIO python/sglang/srt/managers/schedule_batch.py59-62 |
| hash | int | Hash of the feature tensor for cache lookup |
| pad_value | int | Unique integer derived from hash, used to replace placeholder tokens |
| format | MultimodalInputFormat | NORMAL, PROCESSOR_OUTPUT, or PRECOMPUTED_EMBEDDING |
| feature | Tensor or ndarray | Raw features from processor (e.g., pixel_values) |

## Vision Encoder Architecture

 Vision encoders typically follow a three-stage pipeline: Patch Embedding, Transformer Blocks, and Projector/Merger.

 
### Patch Embedding

 Most vision encoders use a **3D convolution** (`Conv3d`) or **2D convolution** (`Conv2d`) to handle spatial and temporal dimensions.

 
 - **Qwen2.5-VL**: Uses `Qwen2_5_VisionPatchEmbed` [python/sglang/srt/models/qwen2_5_vl.py86-120](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/models/qwen2_5_vl.py#L86-L120)
 - **Qwen3-VL**: Uses `Qwen3VLVisionPatchEmbed` with `Conv3dLayer` [python/sglang/srt/models/qwen3_vl.py171-202](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/models/qwen3_vl.py#L171-L202)
 - **InternVL**: Uses `InternVisionEmbeddings` with `Conv2dLayer` [python/sglang/srt/models/internvl.py107-179](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/models/internvl.py#L107-L179)
 
 
### Transformer Blocks

 The blocks stack self-attention and MLP layers. SGLang uses `VisionAttention` for the self-attention mechanism.

 
 - **Qwen2.5-VL**: `Qwen2_5_VisionBlock` uses `VisionAttention` and `Qwen2_5_VLMLP` [python/sglang/srt/models/qwen2_5_vl.py183-220](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/models/qwen2_5_vl.py#L183-L220)
 - **Qwen3-VL**: `Qwen3_VisionBlock` uses `VisionAttention` and `Qwen3_VisionMLP` [python/sglang/srt/models/qwen3_vl.py204-250](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/models/qwen3_vl.py#L204-L250)
 - **InternVL**: `InternVisionBlock` integrates `InternAttention` [python/sglang/srt/models/internvl.py202-243](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/models/internvl.py#L202-L243)
 
 
### Patch Merger / Projector

 The merger reduces the token count and projects the features to the LLM hidden dimension.

 
 - **Qwen2.5-VL Merger**: `Qwen2_5_VisionPatchMerger` uses `RMSNorm` followed by `ColumnParallelLinear` and `RowParallelLinear` [python/sglang/srt/models/qwen2_5_vl.py53-58](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/models/qwen2_5_vl.py#L53-L58)
 - **Qwen3-VL Merger**: `Qwen3VLVisionPatchMerger` [python/sglang/srt/models/qwen3_vl.py29](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/models/qwen3_vl.py#L29-L29)

## `VisionAttention` Module

 `VisionAttention` ([python/sglang/srt/layers/attention/vision.py233-240](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/vision.py#L233-L240)) is the shared attention module used by vision encoders. ## Multimodal Feature Transport (CUDA IPC)

 For high-performance serving, SGLang supports transporting multimodal features across processes using CUDA IPC. This avoids expensive CPU-GPU copies when the multimodal processor and model runner reside in different processes.

 
 - **`TransportProxyTensor`**: A `torch.Tensor` subclass that carries metadata and implements `__getstate__`/`__setstate__` for efficient CUDA IPC handle sharing [python/sglang/srt/managers/mm_utils.py114-180](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/mm_utils.py#L114-L180)
 - **Feature Buffer**: A preallocated GPU buffer (`_GPU_FEATURE_BUFFER`) is used to store features, reducing allocation overhead [python/sglang/srt/managers/mm_utils.py59-82](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/mm_utils.py#L59-L82)

## Data-Parallel Vision Encoding

 When `ServerArgs.mm_enable_dp_encoder` is enabled, vision encoders run in **data-parallel mode** rather than tensor-parallel mode. Each DP rank runs the full vision encoder on a subset of images to maximize throughput.

 
 - For models with MRoPE, `run_dp_sharded_mrope_vision_model` is used [python/sglang/srt/multimodal/mm_utils.py73-74](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/multimodal/mm_utils.py#L73-L74)
 - Models like Qwen3-VL utilize `materialize_multimodal_features` to coordinate features before the language backbone [python/sglang/srt/models/qwen3_vl.py71-74](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/models/qwen3_vl.py#L71-L74)
