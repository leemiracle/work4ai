  SGLang Diffusion provides a high-performance infrastructure for serving image and video generation models. This page documents the OpenAI-compatible interface, the mechanisms for loading and managing LoRA adapters, and the advanced FSDP-based model loading and quantization strategies used for large Diffusion Transformer (DiT) architectures.

 
## OpenAI-Compatible API and CLI

 SGLang Diffusion exposes an OpenAI-compatible API for seamless integration with existing tools and ecosystems. This interface supports both image and video generation tasks, as well as the management of LoRA adapters at runtime.

 
### Generation Interface

 The primary entry point for generation is the `DiffGenerator` class [python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py68](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py#L68-L68) It provides a unified interface for generating images and videos, abstracting the underlying `Scheduler` and `GPUWorker` communication. The `DiffGenerator.from_server_args` method initializes the runtime, starting a local server if needed [python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py117-145](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py#L117-L145)

 The framework supports a variety of sampling parameters, including prompt, negative prompt, resolution, and steps, encapsulated in the `SamplingParams` class [python/sglang/multimodal_gen/configs/sample/sampling_params.py98](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/configs/sample/sampling_params.py#L98-L98) These parameters are mapped from user requests via internal utilities. For performance validation, the system uses a `BaselineConfig` to track `expected_e2e_ms` and `denoise_step_ms` across different hardware platforms [python/sglang/multimodal_gen/test/server/testcase_configs.py105-143](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/test/server/testcase_configs.py#L105-L143)

 
### API Endpoints and CLI Options

 The server implements several key routes:

 
 - **Image API**: Handles `ImageGenerationsRequest`. It supports base64 and URL response formats.
 - **Video API**: Processes `VideoGenerationsRequest` for models like WanVideo and LTX-2 [python/sglang/multimodal_gen/runtime/entrypoints/openai/protocol.py92-137](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/entrypoints/openai/protocol.py#L92-L137)
 - **LoRA Management**: Endpoints allow setting adapters via `SetLoraReq` [python/sglang/multimodal_gen/runtime/entrypoints/utils.py26](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/entrypoints/utils.py#L26-L26)
 
 The CLI supports advanced model resolution through an **Overlay Registry**. If a `--model-path` points to a supported non-diffusers source, SGLang resolves it through an overlay repo to materialize a standard componentized directory under `~/.cache/sgl_diffusion/materialized_models/` [docs/docs/sglang-diffusion/api/cli.mdx9-43](https://github.com/sgl-project/sglang/blob/94183a8d/docs/docs/sglang-diffusion/api/cli.mdx?plain=1#L9-L43)

## LoRA Adapter Support

 SGLang Diffusion allows users to apply LoRA (Low-Rank Adaptation) adapters to base models to modify generation styles or characteristics without retraining the entire model.

 
### Adapter Loading and Management

 The `LoRAPipeline` class manages the lifecycle of LoRA adapters [python/sglang/multimodal_gen/runtime/pipelines_core/lora/pipeline.py16](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/pipelines_core/lora/pipeline.py#L16-L16) It handles the mapping of LoRA weights to the appropriate model components. The `Scheduler` maintains a registry of handlers for LoRA operations, including `SetLoraReq`, `MergeLoraWeightsReq`, and `UnmergeLoraWeightsReq` [python/sglang/multimodal_gen/runtime/managers/scheduler.py142-146](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/scheduler.py#L142-L146)

 
### Key Features

 
 - **Merge Modes**: Controlled via `--lora-merge-mode`. `auto` statically merges regular weights and uses dynamic LoRA for FSDP-sharded weights to avoid full-gather peaks [docs/docs/sglang-diffusion/api/cli.mdx86](https://github.com/sgl-project/sglang/blob/94183a8d/docs/docs/sglang-diffusion/api/cli.mdx?plain=1#L86-L86)
 - **Multi-LoRA Support**: Multiple adapters can be active simultaneously. Test cases like `zimage_image_t2i_multi_lora` validate this by loading two distinct style adapters [python/sglang/multimodal_gen/test/server/gpu_cases.py166-176](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/test/server/gpu_cases.py#L166-L176)
 - **Metadata Application**: PEFT `adapter_config.json` semantics are applied automatically, supporting RSLoRA and per-layer `alpha_pattern` [docs/docs/sglang-diffusion/api/cli.mdx85](https://github.com/sgl-project/sglang/blob/94183a8d/docs/docs/sglang-diffusion/api/cli.mdx?plain=1#L85-L85)

## FSDP Model Loading and Quantization

 For large-scale DiT models, SGLang Diffusion implements specialized loading and quantization strategies using FSDP and custom component loaders.

 
### FSDP and Sharding

 SGLang uses PyTorch FSDP (Fully Sharded Data Parallel) to shard model weights across GPUs. The `fully_shard` utility is used to distribute parameters [python/sglang/multimodal_gen/runtime/loader/fsdp_load.py24](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/loader/fsdp_load.py#L24-L24)

 Key FSDP features include:

 
 - **Shard Conditions**: Blocks are sharded based on conditions like `_is_common_numbered_block`, which targets layers such as `transformer_blocks`, `layers`, or `double_blocks` [python/sglang/multimodal_gen/runtime/loader/fsdp_load.py148-162](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/loader/fsdp_load.py#L148-L162)
 - **Mixed Precision**: Uses `MixedPrecisionPolicy` to define `param_dtype` and `reduce_dtype` [python/sglang/multimodal_gen/runtime/loader/fsdp_load.py23](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/loader/fsdp_load.py#L23-L23)
 
 
### Quantization System

 SGLang-Diffusion treats component path selection and quantized checkpoint materialization as separate capabilities [docs/docs/sglang-diffusion/quantization.mdx8-12](https://github.com/sgl-project/sglang/blob/94183a8d/docs/docs/sglang-diffusion/quantization.mdx?plain=1#L8-L12)

 
| Quant Family | Checkpoint Form | Platform / Notes |
|---|---|---|
| modelopt_fp4 | NVFP4 Safetensors | Specialized for NVIDIA Blackwell (SM100) python/sglang/multimodal_gen/runtime/layers/quantization/modelopt_quant.py20 |
| fp8 / mxfp4 | Online Quantization | MXFP4 requires ROCm and MI350+ (gfx95x) docs/docs/sglang-diffusion/quantization.mdx122 |
| kitchen_int8 | Online Quantization | Data-free INT8 ConvRot at load time via comfy-kitchen docs/docs/sglang-diffusion/quantization.mdx130 |
| gguf | GGUF Component | Supports layerwise offload but not FSDP/LoRA docs/cookbook/diffusion/MiniMax/MiniMax-H3.mdx93 |

 
### Component-Specific Loading

 
 - **Transformer**: Managed by `TransformerLoader`, which resolves the specific quantization spec (e.g., `TransformerQuantLoadSpec`) before invoking the FSDP loader [python/sglang/multimodal_gen/runtime/loader/component_loaders/transformer_loader.py153-200](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/loader/component_loaders/transformer_loader.py#L153-L200)
 - **VAE**: The VAE loader can convert `Conv3d` weights to `channels_last_3d` (NDHWC) for performance on CUDA/ROCm [python/sglang/multimodal_gen/runtime/loader/component_loaders/vae_loader.py94-110](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/loader/component_loaders/vae_loader.py#L94-L110)
 - **Text Encoder**: Supports online quantization for `fp8`, `kitchen_int8`, and `mxfp4` [python/sglang/multimodal_gen/runtime/loader/component_loaders/text_encoder_loader.py123](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/loader/component_loaders/text_encoder_loader.py#L123-L123)
