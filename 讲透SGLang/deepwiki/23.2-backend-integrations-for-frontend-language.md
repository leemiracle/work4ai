  The SGLang frontend language provides a high-level domain-specific language (DSL) for programming LLMs. This page documents how these frontend programs interface with different execution backends, specifically the native **Runtime Endpoint** and the **OpenAI API**. It details the mapping of high-level IR primitives to server-side calls and the management of execution state.

 
## Overview of Backend Architecture

 SGLang separates the program definition (Frontend) from the execution environment (Backend). The frontend defines a computation graph using primitives like `gen`, `select`, and `fork`, which are interpreted by a `run_program` call. The backend interface ensures that these IR primitives are translated into specific API calls recognized by the target inference server.

## Runtime Endpoint Backend

 The `RuntimeEndpoint` is the primary backend for interacting with the SGLang **Structured Runtime (SRT)**. It communicates via RESTful HTTP requests, typically targeting the `/generate` and `/get_model_info` endpoints.

 
### Key Implementation Details

 
 - **Sampling Parameter Mapping**: The `SglSamplingParams` object is converted to a format compatible with SRT. For the OpenAI entrypoints, this conversion happens in `_build_sampling_params` within `OpenAIServingCompletion` [python/sglang/srt/entrypoints/openai/serving_completions.py142-179](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_completions.py#L142-L179) and `OpenAIServingChat` via its initialization [python/sglang/srt/entrypoints/openai/serving_chat.py200-205](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_chat.py#L200-L205)
 - **Regex and Constraint Handling**: For constrained generation, the backend maps Python types to regular expressions. The OpenAI serving layer handles `json_schema` by converting it to a string using `convert_json_schema_to_str` [python/sglang/utils.py90-117](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/utils.py#L90-L117) before passing it to the runtime.
 - **LoRA Support**: LoRA adapters are resolved in the base class `OpenAIServingBase` using `_resolve_lora_path`, which handles model names and explicit paths [python/sglang/srt/entrypoints/openai/serving_completions.py109](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_completions.py#L109-L109)
 
 
### Data Flow for a Request

 
 - The frontend executor encounters a generation primitive.
 - It calls the backend's generate method.
 - The request is packaged into a `GenerateReqInput` [python/sglang/srt/managers/io_struct.py73](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/io_struct.py#L73-L73)
 - A POST request is sent to the runtime via `http_request` [python/sglang/utils.py196-204](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/utils.py#L196-L204)
 - The result is parsed, and metadata like `cached_tokens_details` is processed via `process_cached_tokens_details_from_ret` [python/sglang/srt/entrypoints/openai/utils.py57](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/utils.py#L57-L57)

## OpenAI Backend Integration

 The `OpenAI` backend allows SGLang programs to run on OpenAI's models or any OpenAI-compatible API. This is facilitated by the `OpenAIServingChat` [python/sglang/srt/entrypoints/openai/serving_chat.py194-195](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_chat.py#L194-L195) and `OpenAIServingCompletion` [python/sglang/srt/entrypoints/openai/serving_completions.py44-45](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_completions.py#L44-L45) classes.

 
### Implementation Patterns

 
 - **Endpoint Routing**: The backend routes requests to `/v1/chat/completions` or `/v1/completions` handled by `OpenAIServingChat` and `OpenAIServingCompletion` respectively.
 - **Protocol Mapping**: Frontend parameters are mapped to Pydantic models in `python/sglang/srt/entrypoints/openai/protocol.py`, such as `ChatCompletionRequest` [python/sglang/srt/entrypoints/openai/protocol.py270-271](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/protocol.py#L270-L271) and `CompletionRequest` [python/sglang/srt/entrypoints/openai/protocol.py245-246](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/protocol.py#L245-L246)
 - **Logprobs Handling**: Internal logprob formats are converted to OpenAI style using `to_openai_style_logprobs` [python/sglang/srt/entrypoints/openai/utils.py62-63](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/utils.py#L62-L63)
 - **SSE Streaming**: For streaming responses, the backend builds Server-Sent Events (SSE) chunks using `build_sse_content` [python/sglang/srt/entrypoints/openai/sse_utils.py53](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/sse_utils.py#L53-L53)

## CLI and Multi-Backend Selection

 The SGLang CLI supports multiple backend types (LLM and Diffusion) via a unified `sglang serve` entry point [python/sglang/cli/serve.py166-207](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/cli/serve.py#L166-L207)

 The `ServeBackendRegistry` [python/sglang/cli/serve_backends.py79-80](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/cli/serve_backends.py#L79-L80) manages both built-in backends and out-of-tree plugins registered via the `sglang.serve_backends` entry point group [python/sglang/cli/serve_backends.py23](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/cli/serve_backends.py#L23-L23)

 
 - **Auto-Detection**: When `--model-type auto` is used, the registry invokes `detect()` functions for all registered backends [python/sglang/cli/serve_backends.py173-194](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/cli/serve_backends.py#L173-L194)

## Multimodal and Advanced Integrations

 SGLang backends handle multimodal inputs (images and videos) and specialized model behaviors like reasoning and tool use.

 
### Multimodal Pipeline

 
 - **Dynamic Patching**: The `_extract_max_dynamic_patch` function [python/sglang/srt/entrypoints/openai/serving_chat.py147-170](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_chat.py#L147-L170) parses message content to determine resolution constraints for vision models.
 - **Normalization**: Tool message content is normalized from OpenAI array format to plain strings in `normalize_tool_content` [python/sglang/srt/entrypoints/openai/serving_chat.py87-106](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_chat.py#L87-L106)
 
 
### Reasoning and Thinking

 For reasoning models (e.g., DeepSeek-V3/R1), SGLang provides specific infrastructure:

 
 - **Thinking Mode**: The `ThinkingMode` enum defines `CHAT` vs `THINKING` modes for message encoding [python/sglang/srt/entrypoints/openai/serving_chat.py14-18](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_chat.py#L14-L18)
 - **Reasoning Parser**: The `ReasoningParser` handles incremental parsing of thinking blocks, integrated into the `OpenAIServingChat` workflow [python/sglang/srt/entrypoints/openai/serving_chat.py76](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_chat.py#L76-L76)
 
 
### Tool Call Parsing

 Assistant history tool call arguments are normalized in-place via `normalize_assistant_tool_call_arguments` [python/sglang/srt/entrypoints/openai/serving_chat.py126-144](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_chat.py#L126-L144)

 
### PD Disaggregation Support

 The entrypoints support **Prefill and Decoding (PD) Disaggregation**. Requests are converted to `GenerateReqInput` which includes routing fields such as `bootstrap_host`, `bootstrap_port`, and `routed_dp_rank` [python/sglang/srt/entrypoints/openai/serving_completions.py120-123](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_completions.py#L120-L123)
