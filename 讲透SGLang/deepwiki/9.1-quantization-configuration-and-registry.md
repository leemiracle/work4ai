  SGLang implements a comprehensive quantization framework that enables flexible support for diverse quantization methods across multiple hardware backends such as NVIDIA GPUs, AMD GPUs, NPUs (Ascend), CPUs, and others. This system centers around a well-structured registry of quantization configuration classes and factory methods that manage the instantiation and selection of quantization schemes based on user input and model checkpoint metadata.

 Quantization plays a crucial role in making inference efficient and enabling deployment of large models on memory- and compute-constrained environments. SGLang’s design offers extensibility and fine-grained control for model authors, hardware adaptors, and runtime configuration.

## Quantization Registry Overview

 The quantization registry is a centralized dictionary mapping string keys (quantization scheme names) to their respective `QuantizationConfig` classes.

 
### Registry Implementation Details

 
 - The registry is defined primarily in `python/sglang/srt/layers/quantization/__init__.py`.
 - A core dictionary called `BASE_QUANTIZATION_METHODS` maps known quantization method strings to concrete subclasses of `QuantizationConfig`.
 - The full registry `QUANTIZATION_METHODS` incorporates platform-specific entries. For example, `mxfp4` is added conditionally for CPU, CUDA, HIP, and NPU.
 - CPU-supported quantization methods are additionally maintained in `CPU_QUANTIZATION_METHODS`.
 - The registry supports dynamic platform extension by querying the current runtime platform via `current_platform.get_quantization_config`, allowing out-of-tree/experimental methods integration.
 
 
| Registry Key | Config Class | Hardware Support |
|---|---|---|
| "fp8" | Fp8Config | NVIDIA (SM89+), AMD (MI300+), NPU, CPU |
| "modelopt_fp4" | ModelOptFp4Config | NVIDIA Blackwell (SM100+) |
| "mxfp4" | Mxfp4Config / Mxfp4W4A4Config | NVIDIA Blackwell, AMD, CPU, NPU |
| "awq" | AWQConfig | GPU |
| "gptq" | GPTQConfig / GPTQAscendConfig | GPU / NPU |
| "compressed-tensors" | CompressedTensorsConfig | Multi-scheme general |
| "w8a8_int8" | W8A8Int8Config | NVIDIA, AMD, NPU, CPU |
| "modelslim" | ModelSlimConfig | Ascend NPU specific |
| "quark" | QuarkConfig | AMD / NVIDIA |
| "auto-round" | AutoRoundConfig | Intel AMX (CPU), NPU, GPU |

 
### Factory Method

 The function `get_quantization_config(quantization: str)` [python/sglang/srt/layers/quantization/__init__.py146-170](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/__init__.py#L146-L170) retrieves the appropriate `QuantizationConfig` class by key.

 
 - It validates input string against supported keys.
 - On CPU with AMX instruction set, it restricts to CPU-supported methods via `CPU_QUANTIZATION_METHODS` [python/sglang/srt/layers/quantization/__init__.py154-161](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/__init__.py#L154-L161)
 - On custom platforms, it will delegate to platform-specific quant config providers when possible via `current_platform.get_quantization_config(quantization)` [python/sglang/srt/layers/quantization/__init__.py163-169](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/__init__.py#L163-L169)
 - Returns the class implementing the chosen quant method.

## Configuration Class Hierarchy

 The base interface for all quantization configurations is the abstract class `QuantizationConfig` defined in `base_config.py` [python/sglang/srt/layers/quantization/base_config.py126-210](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/base_config.py#L126-L210) Every concrete quantization type extends this class.

 
### Key Interface Methods in `QuantizationConfig` include:

 
| Method | Purpose |
|---|---|
| get_name() | Returns the string name of the quant config. |
| get_supported_act_dtypes() | List supported torch dtypes for activations. |
| get_config_filenames() | Lists config JSON filenames to detect presence of scheme. |
| from_config(config) | Construct config instance from dict. |
| get_quant_method(layer, prefix) | Returns quantization method instance for specific layer. |

## Quantization Method Selection Flow

 Quantization methods are dynamically assigned to model layers during model loading and initialization, based on the chosen quantization configuration and layer prefix matching.

 
### Factory and Layer Method Selection

 
 - The central factory `get_quantization_config` returns a `QuantizationConfig` subclass [python/sglang/srt/layers/quantization/__init__.py146-170](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/__init__.py#L146-L170)
 - During model loading in `_get_quantization_config` [python/sglang/srt/model_loader/loader.py167-221](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_loader/loader.py#L167-L221) the quant config instance is created from metadata or command line.
 - For each model layer (e.g., instances of `LinearBase` or `FusedMoE`), the method `get_quant_method(layer, prefix)` is called on the quant config instance to retrieve the proper quantization method object: 
 - `LinearBase` calls `quant_config.get_quant_method(self, prefix=prefix)` during `__init__` [python/sglang/srt/layers/linear.py191](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/linear.py#L191-L191)
 - `Fp8Config.get_quant_method` returns `Fp8LinearMethod` or `Fp8MoEMethod` [python/sglang/srt/layers/quantization/fp8.py](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8.py)
 - `ModelOptFp4Config.get_quant_method` returns `ModelOptFp4LinearMethod` or `ModelOptNvFp4FusedMoEMethod` [python/sglang/srt/layers/quantization/modelopt_quant.py](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelopt_quant.py)
 
 
### Quantization Skipping and Overrides

 
 - `is_layer_skipped` utility detects if a layer’s prefix is in the ignore list, supporting exact and regex matches [python/sglang/srt/layers/quantization/utils.py57-79](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/utils.py#L57-L79)
 - `QuantizationConfig.override_quantization_method` allows detection of specific checkpoint formats (e.g. ModelOpt) to override user-specified generic methods [python/sglang/srt/layers/quantization/base_config.py171-180](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/base_config.py#L171-L180)

## Quantization Config Classes and Key Examples

 
### Fp8Config

 
 - Supports standard FP8 (E4M3) quantization for both linear layers and MoE experts [python/sglang/srt/layers/quantization/fp8.py](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8.py)
 - Handles platform-specific logic for NVIDIA (CUTLASS/DeepGEMM), AMD (AITER), and Intel (AMX) [python/sglang/srt/layers/quantization/fp8.py85-104](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8.py#L85-L104)
 - Integrates with `MoeRunner` backends for optimized Mixture-of-Experts execution [python/sglang/srt/layers/quantization/fp8.py31-36](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8.py#L31-L36)
 
 
### ModelOptFp4Config

 
 - Designed for NVIDIA Blackwell architecture supporting NVFP4 quantization [python/sglang/srt/layers/quantization/modelopt_quant.py34-37](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelopt_quant.py#L34-L37)
 - Manages specific weight padding and alignment requirements for FP4 GEMM kernels (typically 32-byte alignment) [python/sglang/srt/layers/quantization/modelopt_quant.py163-176](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelopt_quant.py#L163-L176)
 - Can fall back to Marlin or FlashInfer backends depending on hardware capabilities [python/sglang/srt/layers/quantization/modelopt_quant.py48-55](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelopt_quant.py#L48-L55)
 
 
### Linear and MoE Method Abstractions

 
 - `LinearMethodBase` defines the interface for linear layer quantization, requiring `create_weights` and `apply` [python/sglang/srt/layers/quantization/base_config.py46-84](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/base_config.py#L46-L84)
