  This page documents the **L3 storage backends** and **asynchronous transfer optimization** mechanisms in SGLang's multi-tier KV cache architecture, detailing the implementation of key storage backends (Mooncake, HF3FS, LMCache, NIXL), transfer queues, async operations, and object storage loading strategies.

 
## Overview

 SGLang is designed to extend the KV cache hierarchy beyond GPU and CPU memory, enabling efficient offload and reuse at larger capacities and distributed scenarios. The framework supports:

 
 - **Cold data offloading:** Evicted CPU pages can be backed up to external storage for extending effective cache size [python/sglang/srt/mem_cache/hiradix_cache.py76-184](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/hiradix_cache.py#L76-L184) [python/sglang/srt/managers/cache_controller.py119-234](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/cache_controller.py#L119-L234)
 - **Cross-instance sharing:** Distributed backends like Mooncake allow sharing and reuse of KV cache across multiple server instances or nodes, improving throughput and fault tolerance [python/sglang/srt/mem_cache/storage/mooncake_store/mooncake_store.py30-170](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/storage/mooncake_store/mooncake_store.py#L30-L170)
 - **Prefill-decode disaggregation:** Specialized transfer engines support asynchronous low-latency transfer of KV cache data between prefill and decode nodes (e.g., Mooncake, HF3FS, NIXL), enabling efficient disaggregated serving [python/sglang/srt/managers/cache_controller.py173-224](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/cache_controller.py#L173-L224)
 - **Capacity extension:** Systems like HF3FS provide TB-scale hierarchical cache using performant user-level filesystem interfaces and batch I/O [python/sglang/srt/mem_cache/storage/hf3fs/storage_hf3fs.py32-112](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/storage/hf3fs/storage_hf3fs.py#L32-L112)

## Storage Backend Architecture

 
### HiCacheStorage Interface

 All supported storage backends implement the `HiCacheStorage` abstract interface [python/sglang/srt/mem_cache/hicache_storage.py140-212](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/hicache_storage.py#L140-L212) providing a uniform key-value API tailored to the KV cache structure. The interface features batched operations (`batch_get_v2` and `batch_set_v2`) to handle multi-pool transfers efficiently, crucial when backing up or loading full KV states that include auxiliary components like Mamba or SWA states.

 
### Initialization Flow

 The initialization chain begins in `HiRadixCache.__init__` which parses storage backend configs from `ServerArgs`. ## Transfer Queue Architecture

 `HiCacheController` orchestrates asynchronous data transfers across cache tiers by maintaining several key queues:

 
 - **write_queue**: for device (GPU) → host (CPU) transfers during eviction [python/sglang/srt/managers/cache_controller.py160-190](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/cache_controller.py#L160-L190)
 - **load_queue**: for host → device retrieval upon cache hit [python/sglang/srt/managers/cache_controller.py100-130](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/cache_controller.py#L100-L130)
 - **prefetch_queue**: asynchronous storage → host prefetch to hide latency [python/sglang/srt/managers/cache_controller.py190-220](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/cache_controller.py#L190-L220)
 - **backup_queue**: asynchronous host → storage backup to persist evicted CPU pages [python/sglang/srt/managers/cache_controller.py130-180](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/cache_controller.py#L130-L180)

## Backend Transfer Implementations

 
### MooncakeStore Backend

 The `MooncakeStore` backend implements a networked distributed storage system leveraging RDMA and ROCE technologies. It tightly integrates with SGLang via a zero-copy host memory allocator called `MooncakeHostTensorAllocator` [python/sglang/srt/mem_cache/storage/mooncake_store/mooncake_store.py55-67](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/storage/mooncake_store/mooncake_store.py#L55-L67)

 
### NIXL Backend

 The NIXL backend utilizes the `NixlKVManager` and `NixlKVSender/Receiver` to handle high-performance transfers. It supports both `VRAM` and `DRAM` memory kinds for KV segments [python/sglang/srt/disaggregation/nixl/conn.py70-85](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/nixl/conn.py#L70-L85) Transfers are coordinated via `TransferInfo` and `KVArgsRegisterInfo` structures sent over ZMQ for control plane synchronization [python/sglang/srt/disaggregation/nixl/conn.py154-206](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/nixl/conn.py#L154-L206)

## Transfer Optimization with JIT Kernels

 High-performance transfer between device and host KV caches is accelerated using custom JIT-compiled kernels when possible, reducing kernel launch overhead and minimizing copies.

 
### JIT Kernel Usage in Host Pools

 For hierarchical KV caches host buffers, the system attempts to use JIT kernels such as:

 
 - `transfer_kv_all_layer_mla`: Transfers MLA KV states efficiently [python/sglang/srt/mem_cache/memory_pool_host.py26](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/memory_pool_host.py#L26-L26)

## Prefetching and Timeout Policies

 To hide the latency of L3 storage reads and avoid blocking the scheduler, SGLang employs a **linear prefetch timeout check** policy in its `HiRadixCache`.

 
### Prefetch Timeout Parameters

 
| Parameter | Default Value | Description |
|---|---|---|
| base | 2.0 seconds | Fixed overhead time before the check starts python/sglang/srt/mem_cache/hicache_storage.py52 |
| per_ki_token | 0.1 seconds | Additional timeout per 1024 tokens prefetched python/sglang/srt/mem_cache/hicache_storage.py53 |
| max | 30.0 seconds | Upper bound timeout cap to avoid indefinite waiting python/sglang/srt/mem_cache/hicache_storage.py54 |
