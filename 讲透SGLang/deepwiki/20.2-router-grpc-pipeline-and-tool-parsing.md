  This page documents the technical implementation of the gRPC request pipeline, tool call parsing, and streaming response handling within the SGLang Model Gateway (`sgl-model-gateway`) and the Rust-based frontend runtime.

 
## Frontend Runtime Architecture

 SGLang utilizes a multi-threaded Rust frontend to handle high-concurrency I/O and CPU-bound preprocessing (tokenization/parsing) without contending for the Python Global Interpreter Lock (GIL).

 
### Thread Layout and Pipeline Stages

 The Rust runtime organizes work into specialized components to prevent CPU-bound tasks from stalling I/O operations:

 
 - **API Server**: Built on `axum`, managing HTTP and gRPC entry points [sgl-model-gateway/src/server.rs9-15](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L9-L15)
 - **Worker Registry**: A centralized registry for workers with model-based indexing and pre-computed `HashRing` for $O(\log n)$ consistent hashing [sgl-model-gateway/src/core/worker_registry.rs9-13](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker_registry.rs#L9-L13)
 - **Tokenizer Manager**: Coordinates the transformation of text into tokens and handles ingress request flow.
 - **Detokenizer Manager**: Processes generated token IDs back into text or structured objects.

## gRPC Router Pipeline Architecture

 In the `sgl-model-gateway`, the gRPC interface is designed for high-throughput scenarios where the router acts as a high-performance proxy performing load balancing or Prefill-Decode (PD) disaggregation.

 
### Request Pipeline Orchestration

 The gateway logic is organized into a modular pipeline that coordinates execution through several stages:

 
 - **Preparation**: Resolves the tokenizer and model ID. If `enable_igw` is true, the gateway supports multi-model routing [sgl-model-gateway/src/routers/http/router.rs140-149](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/router.rs#L140-L149)
 - **Worker Selection**: Uses `PolicyRegistry` to select workers. In PD mode, it identifies distinct `Prefill` and `Decode` workers [sgl-model-gateway/src/routers/http/pd_router.rs94-102](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/pd_router.rs#L94-L102)
 - **Execution**: Dispatches the request via `GrpcClient` or `reqwest::Client`.
 - **Streaming & Breakers**: Wraps responses in `BreakerTrackedStream` to monitor worker health and trigger circuit breakers on failures [sgl-model-gateway/src/routers/http/router.rs41-43](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/router.rs#L41-L43)

## Tool Call Parsing and Reasoning

 The gateway integrates specialized parsers to handle complex model outputs without returning control to the Python layer.

 
### Reasoning and Tool Parsers

 The gateway uses external Rust crates for high-performance parsing:

 
 - **Reasoning Parser**: Handles blocks (e.g., `<thought>`) to separate reasoning from content [sgl-model-gateway/Cargo.toml82](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/Cargo.toml#L82-L82)
 - **Tool Parser**: Detects and extracts structured tool calls from the stream [sgl-model-gateway/Cargo.toml84](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/Cargo.toml#L84-L84)
 
 These are invoked during the `Response` handling phase of the router to provide structured data to the end user via `parse::parse_function_call` and `parse::parse_reasoning` [sgl-model-gateway/src/server.rs80-92](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L80-L92)

 
### Cache-Aware Routing Tree

 A core component of the tool/parsing pipeline is the `Tree` structure in the `CacheAwarePolicy`. It maintains an approximate radix tree of request prefixes to optimize KV cache hits [sgl-model-gateway/src/policies/cache_aware.rs19-33](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L19-L33)

 
 - **Tree Isolation**: Separate trees are maintained per `(pool, model)` (e.g., `prefill::llama-3`) to prevent prefill and decode workers from evicting each other's cache tenants [sgl-model-gateway/src/policies/cache_aware.rs84-90](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L84-L90)
 - **LRU Eviction**: Background tasks periodically evict least recently used nodes based on `max_tree_size` [sgl-model-gateway/src/policies/cache_aware.rs128-147](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L128-L147)

## gRPC Streaming and Response Handling

 Streaming responses are managed through `axum` and `tonic` (gRPC) to ensure low-latency token delivery.

 
### Performance Optimizations

 
 - **String Interning**: The `intern_string` function uses a `DashMap` and `Arc<str>` to avoid repeated heap allocations for frequent labels like model IDs and worker URLs in metrics [sgl-model-gateway/src/observability/metrics.rs35-47](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/observability/metrics.rs#L35-L47)
 - **Zero-Copy Metrics**: Uses static string constants for common HTTP methods and status codes to minimize allocation overhead during high-throughput routing [sgl-model-gateway/src/observability/metrics.rs73-92](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/observability/metrics.rs#L73-L92)
 - **Token Buckets**: For rate limiting, the `TokenGuardBody` ensures tokens are returned to the bucket only after the entire stream is consumed or dropped [sgl-model-gateway/src/middleware.rs52-82](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/middleware.rs#L52-L82)
 
 
### Load Balancing Policies

 The gateway supports several policies for worker selection:

 
| Policy | Implementation | Description |
|---|---|---|
| cache_aware | CacheAwarePolicy | Routes based on prefix match in an approximate radix tree sgl-model-gateway/src/policies/cache_aware.rs103-112 |
| power_of_two | PowerOfTwoPolicy | Selects two random workers and picks the one with the least load. |
| prefix_hash | PrefixHashPolicy | Consistent hashing based on the first $N$ tokens. |
| manual | ManualPolicy | Sticky routing based on a provided routing key sgl-model-gateway/src/main.rs150-180 |
