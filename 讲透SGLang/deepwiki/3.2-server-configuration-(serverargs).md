  This page documents the `ServerArgs` dataclass, the central configuration object for the SGLang runtime. It covers the parameters, configuration options, and their effects on the server behavior, including validation, auto-configuration, and the transition to the structured `RuntimeContext` system. It also describes `PortArgs`, the companion dataclass that carries IPC endpoints and network port configurations.

 For contextual system architecture and IPC communication, refer to [Multi-Process Architecture and IPC (3.1)](https://github.com/sgl-project/sglang/blob/94183a8d/Multi-Process Architecture and IPC (3.1)) For environment variable integration, see [Environment Variables System (14.1)](https://github.com/sgl-project/sglang/blob/94183a8d/Environment Variables System (14.1))

## ServerArgs Dataclass Overview

 `ServerArgs` is the primary configuration entity for the inference server, defined as a Python `@dataclass` in [python/sglang/srt/server_args.py276-710](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/server_args.py#L276-L710) It encapsulates all runtime, model-loading, scheduling, parallelism, quantization, and backend options.

 Each parameter has a default value, making most options optional except for critical ones like `model_path`. Instantiation typically occurs via CLI argument parsing using `add_cli_args_from_dataclass` [python/sglang/srt/server_args.py36](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/server_args.py#L36-L36) or direct construction in `Engine.__init__` [python/sglang/srt/entrypoints/engine.py207-215](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/engine.py#L207-L215)

 
### Argument Groups and Declaration System

 The codebase uses a declarative model-override system. Parameters in `ServerArgs` are marked with metadata (`NS`, `A`, `Arg`) which facilitates the publication of configuration "bags" into the `RuntimeContext` [python/sglang/srt/server_args.py36](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/server_args.py#L36-L36) Model-specific adjustments are declared in `overrides.py` rather than mutating the raw `ServerArgs` instance directly [python/sglang/srt/arg_groups/overrides.py14-32](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/arg_groups/overrides.py#L14-L32)

## RuntimeContext Config Bags

 The `RuntimeContext` provides a single structured accessor for process-static state. It separates configured state from live parallel groups [python/sglang/srt/runtime_context.py14-49](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/runtime_context.py#L14-L49)

 
| Accessor | Purpose | Code Entity |
|---|---|---|
| get_exec() | Execution settings (kernels, MoE backends) | _ConfigBag runtime_context.py35 |
| get_model() | Model-specific configuration (architectures, dtype) | _ConfigBag runtime_context.py36 |
| get_parallel() | Live topology (tp_size, tp_group) vs configured | ParallelContext runtime_context.py120 |
| get_memory() | KV cache and memory pool settings | _ConfigBag runtime_context.py35 |
| get_disagg() | Disaggregation (Prefill/Decode) modes | _ConfigBag runtime_context.py37 |
