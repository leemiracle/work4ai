## Purpose and Scope

 This page details the FP8 (8-bit floating-point) quantization system within SGLang, including standalone FP8 (E4M3) quantization, integration with NVIDIA ModelOpt, block-wise quantization strategies, and the DeepGEMM wrapper. FP8 quantization enables reduced memory footprint and faster inference by compressing weights and activations into 8-bit floating-point representation, with support for both per-token and block-wise scaling. These features are optimized for high-performance GPUs such as NVIDIA Hopper/Blackwell (SM90/SM120) and AMD MI300/MI350.

 The document covers:

 
 - FP8 configuration and quantization schemes.
 - ModelOpt integration and NVFP4 support on Blackwell GPUs.
 - Linear and MoE quantization methods using FP8 and FP4.
 - Kernel implementations including sgl-kernel, Triton, DeepGEMM, and AITER.
 - Hardware-specific optimizations and environment variables.

## FP8 Configuration and Data Flow

 
### Fp8Config and Quantization Schemes

 The `Fp8Config` class encapsulates configuration for standalone FP8 (E4M3) quantization. It manages:

 
| Parameter | Type | Description |
|---|---|---|
| is_checkpoint_fp8_serialized | bool | Indicates if model weights are serialized already as FP8 python/sglang/srt/layers/quantization/fp8.py225 |
| activation_scheme | str | static or dynamic activation quantization scheme (dynamic per-token quantization) python/sglang/srt/layers/quantization/fp8.py226 |
| weight_block_size | List[int] | Dimensions for block-wise quantization (e.g., [128, 128]) python/sglang/srt/layers/quantization/fp8.py228 |
| is_fp4_experts | bool | Flag to enable support for DeepSeek-V4 FP4 experts, which requires torch.float4_e2m1fn_x2 dtype python/sglang/srt/layers/quantization/fp8.py231 |

 This configuration sets up quantization parameters for weight and activation tensors, enabling both static per-channel quantization and dynamic per-token quantization.

 
### Weight Loading and Processing

 During model weight loading, if checkpoints are not serialized in FP8 format, weights are dynamically quantized using `scaled_fp8_quant`. For AMD ROCm (MI300+) GPUs, SGLang applies a normalization step converting standard `e4m3fn` to `e4m3fnuz` format (adjusting NaN bit patterns and scaling) to comply with AMD's FP8 requirements.

## Linear and MoE Implementations

 
### Linear Layer Dispatch

 The `Fp8LinearMethod` manages forward computation for linear layers quantized with FP8:

 
 - **Activation Quantization**
 Activations are quantized dynamically per token using functions such as `scaled_fp8_quant` or `per_token_group_quant_fp8` [python/sglang/srt/layers/quantization/fp8.py18-20](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8.py#L18-L20) Per-token grouping enables fine-grained scaling which improves quantization accuracy.
 - **Hardware Kernel Backend Selection**
 The `apply_fp8_linear` utility prioritizes backends optimized for different hardware:

 
 - **DeepGEMM**: Preferred for NVIDIA Hopper (SM90), invoked via `w8a8_block_fp8_matmul_deepgemm` [python/sglang/srt/layers/quantization/fp8_utils.py34](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L34-L34)
 - **CUTLASS**: Reliable for SM90+ with native block scale support, using `fp8_blockwise_scaled_mm` [python/sglang/srt/layers/quantization/fp8_utils.py178](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L178-L178)
 - **Triton**: Fallback kernel via `w8a8_block_fp8_matmul_triton` [python/sglang/srt/layers/quantization/fp8_utils.py35](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L35-L35)
 - **AITER**: An AMD ROCm-specific optimized kernel path [python/sglang/srt/layers/quantization/fp8_utils.py148-165](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L148-L165) utilizing HIP-tuned FP8 kernels.
 
 This backend dispatch optimizes quantized matrix multiply performance while supporting fallback for hardware without native FP8 support.

## Kernel Implementations

 
### Per-Token Quantization Kernels

 The per-token quantization kernel computes quantization scales dynamically for groups of tokens, improving fidelity over per-tensor scales:

 
 - **Algorithm**:

 
 - For each token or group, compute the maximum absolute value.
 - Derive scaling factors by clamping the dynamic range to FP8 limits.
 - Perform quantization with `scaled_fp8_quant` or optimized functions like `per_token_group_quant_fp8`.
 - **Implementation**:

 
 - `per_token_group_quant_fp8` is a high-performance kernel in `sgl-kernel` for block-wise FP8 quantization, supporting padded row layouts [python/sglang/srt/layers/quantization/fp8_utils.py10-13](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L10-L13)
 - It is utilized by methods like `apply_fp8_linear` and MoE quantization handlers.
 
 
### Block-wise Scaled GEMM Kernels

 SGLang supports block-wise FP8 GEMM kernels optimized for major GPU platforms:

 
 - **NVIDIA Hopper (SM90) & Blackwell (SM100+)**:

 
 - CUDA kernels include: 
 - `w8a8_block_fp8_matmul_deepgemm`: DeepGEMM JIT-compiled block-scaled FP8 GEMM [python/sglang/srt/layers/quantization/fp8_utils.py34](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L34-L34)
 - `fp8_blockwise_scaled_mm`: CUTLASS-backed reliable native FP8 block-scale GEMM [python/sglang/srt/layers/quantization/fp8_utils.py178](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L178-L178)

## Hardware-Specific Features

 
### NVIDIA Hopper and Blackwell

 
 - **FP8 Block-wise Quantization**
 Uses `fp8_blockwise_scaled_mm` and DeepGEMM to efficiently perform matrix multiplies with FP8 weights and activations.
 - **NVFP4 (FP4) on Blackwell**
 Supports NVIDIA's new NVFP4 format, which packs two FP4 values per byte with microscaling:

 
 - The `fp4_gemm` op dispatches to FlashInfer's `mm_fp4` kernel to handle FP4 GEMM [python/sglang/srt/layers/quantization/modelopt_quant.py132-150](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelopt_quant.py#L132-L150)
 - Weights are padded for alignment requirements (`FP4_GEMM_ALIGNMENT = 32`) to meet CUDA kernel constraints during GEMM operations [python/sglang/srt/layers/quantization/modelopt_quant.py163-207](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelopt_quant.py#L163-L207)
 
 
### AMD ROCm (MI300/MI350)

 
 - **Custom FP8 Format (e4m3fnuz)**

 
 - AMD ROCm uses the `float8_e4m3fnuz` format that differs slightly from standard FP8 (`e4m3fn`).
 - SGLang normalizes incoming standard FP8 weights to this format by rearranging NaN bits and scaling weights accordingly during weight loading [python/sglang/srt/layers/quantization/fp8_utils.py213-230](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L213-L230)
 - **AITER Backend**

 
 - AMD-specific FP8 kernels for ROCm platforms (GFX95 and newer) are enabled via environment variable `SGLANG_USE_AITER`.
 - These kernels include `aiter_w8a8_block_fp8_linear` and use the bpreshuffle GEMM algorithm to optimize FP8 GEMM performance [python/sglang/srt/layers/quantization/fp8_utils.py148-150](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L148-L150)
 - **GFX95 Support**

 
 - Special support exists for MI35x (gfx95) with ROCm 7.2+ to enable bpreshuffle FP8 GEMMs [python/sglang/srt/layers/quantization/fp8_utils.py68](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L68-L68)

# Detailed Explanation

 
### FP8 Quantization (E4M3)

 SGLang's standalone FP8 quantization fully supports E4M3 formats for checkpointed weights and runtime activations. The system supports static and dynamic quantization schemes:

 
 - **Static** quantization performs per-channel weight scaling at load time.
 - **Dynamic** (`activation_scheme = "dynamic"`) performs per-token group quantization at runtime for activations, which better preserves accuracy for varying token distributions.
 
 Weights are loaded, and if not serialized in FP8 already, dynamically quantized using `scaled_fp8_quant`. AMD ROCm platforms normalize FP8 weights to their native `e4m3fnuz` format.

 
### ModelOpt Quantization

 ModelOpt quantization supports advanced formats including FP4 (NVFP4) for Blackwell GPUs. It performs block-wise quantization with microscale correction, adapted to Blackwell's hardware GEMM requirements:

 
 - Supports tensor padding to align kernel inputs [python/sglang/srt/layers/quantization/modelopt_quant.py172-192](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelopt_quant.py#L172-L192)
 - `ModelOptNvFp4FusedMoEMethod` embodies the FP4 quantization method optimized for Blackwell MoE experts [python/sglang/srt/layers/quantization/modelopt_quant.py756](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelopt_quant.py#L756-L756)
 - Integration with FlashInfer's FP4 GEMM kernel provides efficient FP4 matrix multiplies.
 
 
### Block-wise Quantization and DeepGEMM

 Block-wise quantization is a core technique, especially for MoE layers:

 
 - Weights are quantized into blocks (e.g., `[128, 128]`) rather than flat tensors, enabling better scaling and compression [python/sglang/srt/layers/quantization/fp8.py228](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8.py#L228-L228)
 - DeepGEMM provides a JIT-compiled wrapper with state-of-the-art block-wise FP8 GEMM performance, utilized by both linear and MoE FP8 methods [python/sglang/srt/layers/quantization/fp8_utils.py34](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L34-L34)
 - The DeepGEMM wrapper is exposed transparently and manages expert weight quantization and dispatch.
 
 
### DeepGEMM Wrapper

 The DeepGEMM wrapper abstracts the deployment of FP8 block GEMMs for MoE layers. It integrates with the dispatcher and normalized quantized weights to execute expert parallelism efficiently. It uses a JIT pre-compilation session to optimize kernels for specific matrix shapes [python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py162-171](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py#L162-L171)
