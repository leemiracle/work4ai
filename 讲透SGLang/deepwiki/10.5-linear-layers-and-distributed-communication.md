## Purpose and Scope

 This page documents the implementation of linear layers with tensor parallelism in SGLang, focusing on distribution and communication strategies. We cover the core `LinearBase` class and its tensor-parallel subclasses: `ColumnParallelLinear` and `RowParallelLinear`. Additionally, the page delves into the communication abstractions managed by `LayerCommunicator` which orchestrates efficient all-reduce, all-gather, and scatter/gather collectives used during the forward pass.

 Distributed communication patterns are crucial for scaling large models across multiple GPUs/nodes. This page explains the dataflow for model parallel linear layers, how weights are sharded and gathered/reduced, and the fusion of communication operations with neighboring computation for performance. For the process group and distributed environment management behind these operations, see the `GroupCoordinator` in `parallel_state.py` [python/sglang/srt/distributed/parallel_state.py164-213](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/distributed/parallel_state.py#L164-L213)

## Linear Layer Class Hierarchy

 All linear layers derive from the abstract `LinearBase` class defined in `python/sglang/srt/layers/linear.py` [python/sglang/srt/layers/linear.py146-191](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/linear.py#L146-L191) The subclasses implement different sharding strategies on the weight tensor:

|---|---|---|---|
| ReplicatedLinear | [output, input] | None | Small layers, LM head, MoE gates |
| ColumnParallelLinear | [output//tp, input] | All-gather on output | MLP up/gate layers, Q projection |
| MergedColumnParallelLinear | [sum(sizes)//tp, input] | All-gather on output | Fused gate+up (SwiGLU) |

| RowParallelLinear | [output, input//tp] | All-reduce on output | MLP down, attention output |

## Tensor Parallel Weight Sharding and Dataflow

 
### Column Parallel Linear

 `ColumnParallelLinear` shards the weight tensor along the output dimension. The weight local shape per rank is `[output_size_per_partition, input_size]` [python/sglang/srt/layers/linear.py244-351](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/linear.py#L244-L351)

 
 - All ranks receive the full input `[batch_size, input_size]`.
 - Each rank performs a local matrix multiplication to compute partial output `[batch_size, output_size_per_partition]`.
 - If `gather_output=True`, all partial outputs are gathered with `tensor_model_parallel_all_gather` to produce final output `[batch_size, output_size]` [python/sglang/srt/layers/linear.py20-23](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/linear.py#L20-L23)

### Row Parallel Linear

 `RowParallelLinear` shards the weight tensor along the input dimension. The weight local shape per rank is `[output_size, input_size_per_partition]` [python/sglang/srt/layers/linear.py536-642](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/linear.py#L536-L642)

 
 - Input must be already sharded along last dimension: `[batch_size, input_size_per_partition]`.
 - Each rank computes partial output `[batch_size, output_size]` by local GEMM.
 - Partial results are reduced across TP ranks via `tensor_model_parallel_all_reduce` to produce final output [python/sglang/srt/layers/linear.py20-23](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/linear.py#L20-L23)
 
 The `reduce_results` flag determines whether reduction happens inside the layer or deferred.

## Weight Loading and Configuration

 SGLang supports advanced quantization and sharding during model weight loading. Each linear layer subclass defines a `weight_loader` method responsible for extracting the correct shard from the checkpoint based on `loaded_shard_id` and copying it into parameters [python/sglang/srt/layers/linear.py311-327](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/linear.py#L311-L327)

 The system maintains a list `WEIGHT_LOADER_V2_SUPPORTED` of quantization schemes compatible with the new v2 API inclusive for `LinearBase` subclasses [python/sglang/srt/layers/linear.py58-80](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/linear.py#L58-L80)

 Model parallel and other configuration parameters like `tp_size` and `dtype` are derived declaratively from model configs and combined with runtime server arguments [python/sglang/srt/model_loader/loader.py51-56](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_loader/loader.py#L51-L56)

## Distributed Communication: LayerCommunicator and All-Reduce Fusion

 
### LayerCommunicator

 The `LayerCommunicator` in `python/sglang/srt/layers/communicator.py` manages communication patterns needed by tensor parallel layers.

 Key responsibilities:

 
 - Efficient all-reduces and all-gathers over tensor model parallel groups [python/sglang/srt/layers/communicator.py23-29](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/communicator.py#L23-L29)
 - Support for various backends and fused communication kernels.
 - Handling data parallel attention scatter/gather when DP attention is enabled [python/sglang/srt/layers/communicator.py39-55](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/communicator.py#L39-L55)
 - Managing symmetric memory allocation for performance via `use_symmetric_memory` [python/sglang/srt/layers/communicator.py30-32](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/communicator.py#L30-L32)
 
 
### All-Reduce Fusion

 SGLang implements fusion of all-reduce operations with other layer operations like RMSNorm or residual addition to reduce kernel overhead. Two prominent backends for fused all-reduce:

 
 - **FlashInfer Allreduce Fusion**: Available on NVIDIA SM90/SM100 GPUs. Dynamically selects backend (`mnnvl` or `trtllm`) based on platform and multi-node setup [python/sglang/srt/layers/flashinfer_comm_fusion.py38-75](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/flashinfer_comm_fusion.py#L38-L75) Includes a `TorchDistBackend` workaround for graph capture compatibility with NCCL/Gloo [python/sglang/srt/layers/flashinfer_comm_fusion.py127-154](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/flashinfer_comm_fusion.py#L127-L154)
 - **AITer Allreduce Fusion**: For AMD GPUs using `aiter` fused FP8 quant kernels. Includes specialized fused RMSNorm + FP8 per-token quantization kernels such as `_aiter_add_rmsnorm_quant` [python/sglang/srt/layers/communicator.py98-106](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/communicator.py#L98-L106)
 
 The functions `apply_flashinfer_allreduce_fusion` and `apply_aiter_all_reduce_fusion` check conditions like batch size, hardware support, and environment variables to enable fusion [python/sglang/srt/layers/communicator.py165-194](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/communicator.py#L165-L194)

## Data Parallel Attention Communication

 When data-parallel (DP) attention is enabled (`is_dp_attention_enabled()` true), `LayerCommunicator` supports scatter/gather communication modes beyond TP all-reduce:

 
 - **ScatterMode Enum** defines the scatter/gather approaches such as: 
 - `SCATTERED`: Input/output tensors are scattered among DP ranks.
 - `TP_ATTN_FULL`: TP attention group with full sequences.
 - `FULL`: replicated full sequence data [python/sglang/srt/layers/communicator.py197-205](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/communicator.py#L197-L205)
 - **DpPaddingMode** determines how tokens are handled across DP ranks, either padding to `MAX_LEN` for symmetric collectives or `SUM_LEN` to minimize communication volume [python/sglang/srt/layers/dp_attention.py80-135](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/dp_attention.py#L80-L135)
 - Buffer management for DP attention uses `_DpGatheredBufferWrapper` to allocate intermediate gathered buffers, potentially using symmetric memory allocation for performance [python/sglang/srt/layers/dp_attention.py138-193](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/dp_attention.py#L138-L193)

## Summary

 
 - `LinearBase` is the foundation for different tensor parallel linear layers, such as `ColumnParallelLinear` and `RowParallelLinear`, implementing output and input dimension sharding respectively [python/sglang/srt/layers/linear.py146-191](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/linear.py#L146-L191)
 - Distributed communication is managed by `LayerCommunicator`, which abstracts all-reduce, all-gather, and scatter/gather patterns required for forward passes [python/sglang/srt/layers/communicator.py23-55](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/communicator.py#L23-L55)
 - Communication operations are fused with layer computations where possible to reduce overhead, employing specialized backends like FlashInfer and AITER [python/sglang/srt/layers/communicator.py165-194](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/communicator.py#L165-L194)
