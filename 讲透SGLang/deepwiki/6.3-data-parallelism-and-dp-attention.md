## Purpose and Scope

 This page documents SGLang's **Data Parallelism (DP)** and **DP Attention** features, which allow horizontal scalability by running multiple independent schedulers to process different requests in parallel, thereby increasing serving throughput and queries-per-second (QPS).

 
 - **Data Parallelism (DP):** Replicated model instances across multiple GPU workers or groups, each processing a subset of incoming requests independently.
 - **DP Attention:** An advanced optimization that shards attention KV cache across workers within an attention context parallel group to reduce per-GPU memory usage while maintaining independent request processing.
 
 This page covers the implementation of the `DataParallelController`, load balancing mechanisms, communication patterns for DP Attention, and its integration within the SGLang Runtime (SRT), including Ray-based distributed execution.

## Configuration Parameters

 
### Core Server Arguments

 Data parallelism is configured via `ServerArgs`. Key parameters include:

 
| Parameter | Type | Default | Description |
|---|---|---|---|
| dp_size | int | 1 | Number of data parallel workers (schedulers) running in parallel. |
| enable_dp_attention | bool | False | Enables DP attention optimization. |
| load_balance_method | string | "auto" | Load balancing strategy for distributing requests: "round_robin" or "follow_bootstrap_room". |
| attn_cp_size | int | 1 | The size of attention context parallelism, used in DP attention coordination. |

## DP Attention Optimization

 
### Concept and KV Sharding

 Standard DP replicates the KV cache on all workers. **DP Attention** shards the KV cache across an **Attention Context Parallel (CP)** group. This reduces per-GPU memory usage for the KV cache by a factor of the `attn_cp_size`.

 
 - **MLP Layers:** Remain standard Data Parallel (independent computation).
 - ** Attention Layers:** Perform collective communication (All-Gather/Reduce-Scatter) to share KV shards during computation.
 
 
### Communication and Process Groups

 The function `compute_dp_attention_world_info` [python/sglang/srt/layers/dp_attention.py25](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/dp_attention.py#L25-L25) calculates the mapping between global ranks and parallel groups. ### DpPaddingMode

## Communication and Symmetric Memory

 Efficiency in DP Attention relies on fast inter-GPU communication. SGLang supports symmetric memory access via `use_symmetric_memory` [python/sglang/srt/layers/dp_attention.py189](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/dp_attention.py#L189-L189)

 
 - `is_allocation_symmetric()`: Checks if the memory pool is configured for symmetric access [python/sglang/srt/layers/dp_attention.py214](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/dp_attention.py#L214-L214)
 - `get_global_dp_buffer()`: Allocates or retrieves the buffer used for gathered tokens, utilizing symmetric memory if enabled [python/sglang/srt/layers/dp_attention.py185-199](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/dp_attention.py#L185-L199)
