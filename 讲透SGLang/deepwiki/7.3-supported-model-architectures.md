  This page details the text-only generation model architectures natively supported by the SGLang inference runtime, their registration mechanisms, implementation interfaces, and shared building blocks. It focuses on families such as LLaMA, Qwen (2.x / 3.x / 3.5), Mistral, DeepSeek, GLM, Kimi, Bailing, ERNIE, Step, MiniMax, Gemma, Falcon, Nemotron, and how models are resolved from configs in the internal model registry.

 For vision-language (multimodal) model architectures, see [Supported Vision-Language Models (18.3)](https://github.com/sgl-project/sglang/blob/94183a8d/Supported Vision-Language Models (18.3))

## Forward Pass Contract and Model Interface

 Every native SGLang model class adheres to a standard interface to integrate with the inferencing runtime.

 
 - **Constructor**: Must accept a `PretrainedConfig` and an optional `QuantizationConfig`.
 - **Forward Method**: Accepts input token IDs, position IDs, and a `ForwardBatch` context for batch metadata.

## MoE Model Layer Architecture

 MoE models replace the dense feed-forward MLP block with a sparse expert routing module. Tokens are dispatched to expert sub-networks using backends like `FusedMoE` or `DeepEPMoE`.

 **Mixture-of-Experts Logic Flow:**

 
```

```

 The `FusedMoE` [python/sglang/srt/layers/moe/fused_moe_triton/layer.py20](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L20-L20) class handles the high-performance execution of routed experts. For expert parallelism, `DeepEPMoE` [python/sglang/srt/layers/moe/ep_moe/layer.py63](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/ep_moe/layer.py#L63-L63) utilizes the DeepEP library for all-to-all communication.
