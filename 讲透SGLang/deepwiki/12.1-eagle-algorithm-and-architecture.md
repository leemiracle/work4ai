## Purpose and Scope

 This document describes the EAGLE (Extrapolation Algorithm for Greater Language-model Efficiency) speculative decoding implementation in SGLang. EAGLE is a high-performance speculative decoding algorithm that accelerates inference by predicting multiple tokens ahead using a lightweight draft model and verifying them in parallel with the target model. Unlike standard speculative decoding which uses a linear sequence of draft tokens, EAGLE employs a tree-based structure to explore multiple high-probability paths simultaneously. This page covers the architecture of EAGLE, EAGLE2, and EAGLE3, including multi-layer implementations, tree-based verification, and adaptive speculative decoding.

 
---

 
## Architecture Overview

 EAGLE in SGLang is implemented via specialized worker classes like `EagleDraftWorker` [python/sglang/srt/speculative/eagle_worker_v2.py130](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_worker_v2.py#L130-L130) which coordinates between a draft model and a target model. The architecture is centered around a **tree-based draft-verification cycle** using a multi-process or single-process model runner configuration.

## Core Components and Data Flow

 
### EagleDraftWorker Class

 The `EagleDraftWorker` manages the lifecycle of speculative requests. It maintains a separate `TpModelWorker` instance specifically for the draft model [python/sglang/srt/speculative/eagle_worker_v2.py172-181](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_worker_v2.py#L172-L181)

 **Key Responsibilities:**

 
 - **Initialization**: Configures speculative parameters such as `topk`, `speculative_num_steps`, and the specific `speculative_algorithm` (e.g., EAGLE, EAGLE3) [python/sglang/srt/speculative/eagle_worker_v2.py149-157](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_worker_v2.py#L149-L157)
 - **Memory Management**: Allocates and manages draft KV cache pools via `alloc_memory_pool`, which delegates to the draft worker [python/sglang/srt/speculative/eagle_worker_v2.py197-208](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_worker_v2.py#L197-L208)

## Draft Model and Tree Generation

 
### Drafting Process

 The draft model generates tokens iteratively. In the V2 implementation, this is often handled by `EAGLEDraftCudaGraphRunner` [python/sglang/srt/speculative/eagle_draft_cuda_graph_runner.py80](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_draft_cuda_graph_runner.py#L80-L80)

 
 - **Input Preparation**: The `EagleDraftInput` carries the current `topk_p`, `topk_index`, and `hidden_states` [python/sglang/srt/speculative/eagle_info.py142-157](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_info.py#L142-L157)
 - **Iterative Speculation**: The worker builds a tree by repeatedly sampling and expanding nodes. For the `topk=1` case, a fast path is used with pre-allocated buffers [python/sglang/srt/speculative/eagle_worker_v2.py159](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_worker_v2.py#L159-L159)
 - **Tree Construction**: Draft results are organized and mapped using utilities like `organize_draft_results` [python/sglang/srt/speculative/eagle_utils.py79](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_utils.py#L79-L79) and `per_step_draft_out_cache_loc` [python/sglang/srt/speculative/eagle_utils.py80](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_utils.py#L80-L80)

## Verification and Acceptance

 
### Tree-Based Verification

 The target model receives an `EagleVerifyInput` containing the tree structure [python/sglang/srt/speculative/eagle_info.py16-32](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_info.py#L16-L32)

 **Verification Components:**

 
 - **Retrieve Indices**: `retrieve_index`, `retrieve_next_token`, and `retrieve_next_sibling` guide the kernel in traversing the accepted paths [python/sglang/srt/speculative/eagle_info.py20-22](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_info.py#L20-L22)

## CUDA Graph Optimizations

 EAGLE utilizes specialized CUDA Graph runners to minimize host-side overhead during drafting.

 
### EAGLEDraftCudaGraphRunner

 This runner captures the draft forward pass. It uses `EagleDraftInputBuffers` to manage static tensors for `input_ids`, `req_pool_indices`, and `hidden_states` [python/sglang/srt/speculative/eagle_draft_cuda_graph_runner.py60-77](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_draft_cuda_graph_runner.py#L60-L77)

 
### EAGLEDraftExtendCudaGraphRunner

 Handles the "draft-extend" phase. It manages `num_correct_drafts` and `num_accept_tokens` to update sequence lengths within the graph [python/sglang/srt/speculative/eagle_draft_extend_cuda_graph_runner.py59-74](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_draft_extend_cuda_graph_runner.py#L59-L74)
