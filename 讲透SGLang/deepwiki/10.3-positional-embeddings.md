  This page documents the implementation and integration of positional embedding mechanisms in SGLang. It covers Rotary Positional Embeddings (RoPE), scaling techniques like YaRN, and specialized hardware-accelerated implementations for various platforms including NVIDIA (CUDA), AMD (ROCm), Intel (XPU), and Huawei (Ascend NPU).

 
## Overview

 Positional embeddings are critical for Transformer models to understand the order and relative positions of tokens. SGLang primarily focuses on **Rotary Positional Embeddings (RoPE)**, which encode absolute position with a rotation matrix and naturally incorporate relative position dependency in the self-attention mechanism.

 In SGLang's model executor, positional embeddings are generally applied to the Query ($Q$) and Key ($K$) tensors after linear projection but before the attention kernel executes. SGLang provides highly optimized kernels for these operations, including specialized versions for GPU (CUDA/ROCm/NPU) and CPU execution, and fused operations that combine RoPE with normalization or handle decoupled attention dimensions (MLA).

 
---

 
## Core Architecture and Class Hierarchy

 The positional embedding logic is built around the `RotaryEmbedding` class, which serves as a base for various scaling and hardware-specific implementations. The system supports various layouts, including standard RoPE, Multimodal RoPE (M-RoPE), and scaling variants for long-context or decoupled attention (MLA) used in DeepSeek models.

## Positional Embedding Types

 
### 1. Rotary Positional Embeddings (RoPE)

 Standard RoPE rotates pairs of features in the hidden dimension to encode position information.

 
 - **Standard RoPE:**
 Implemented by the `RotaryEmbedding` class, which stores a precomputed cosine-sine cache. The cache is computed in FP32 for numerical stability unless overridden by `SGLANG_ROPE_CACHE_FP32` [python/sglang/srt/layers/rotary_embedding/base.py102-105](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/base.py#L102-L105) The cache is lazily and incrementally extended if the sequence length exceeds the current cache via `_ensure_cos_sin_cache_length` [python/sglang/srt/layers/rotary_embedding/base.py184-192](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/base.py#L184-L192)
 - **Styles:** Supports both **NeoX style** (splitting the head dimension into two halves) and interleaved rotation styles [python/sglang/srt/layers/rotary_embedding/base.py87-95](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/base.py#L87-L95)
 - **Hardware Fallbacks:** If a specialized kernel is not available for a specific head size (e.g., outside 64, 128, 256, 512 on CUDA), it falls back to a generic `rotary_embedding` implementation from `sgl_kernel` or `vllm._custom_ops` [python/sglang/srt/layers/rotary_embedding/base.py107-127](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/base.py#L107-L127)

### 2. YaRN Scaling RoPE

 `YaRNScalingRotaryEmbedding` extends RoPE with the **YaRN** method to improve extrapolation for long contexts.

 
 - **Parameters:** Controls scaling via `scaling_factor`, `extrapolation_factor`, and oscillation bands `beta_fast`/`beta_slow` [python/sglang/srt/layers/rotary_embedding/yarn.py89-94](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/yarn.py#L89-L94)
 - **Correction Range:** Uses `yarn_find_correction_range` to calculate which dimensions require interpolation vs. extrapolation based on rotation frequency [python/sglang/srt/layers/rotary_embedding/yarn.py118-125](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/yarn.py#L118-L125)
 - **M-Scale:** Applies magnitude scaling (`mscale`) to the cos/sin values to maintain activation variance, supporting both simple and HuggingFace-compatible multi-dim scaling [python/sglang/srt/layers/rotary_embedding/yarn.py96-105](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/yarn.py#L96-L105)

### 3. Multimodal Rotary Embeddings (M-RoPE)

 Used in vision-language models (e.g., Qwen2-VL, GLM-V), `MRotaryEmbedding` handles spatial and temporal dimensions.

 
 - **Sections:** The rotary dimension is divided into sections (e.g., for Temporal, Height, Width) via `mrope_section`. If the sum of sections doesn't match `rotary_dim // 2`, SGLang automatically adjusts them [python/sglang/srt/layers/rotary_embedding/mrope.py75-101](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/mrope.py#L75-L101)
 - **Interleaving:** Supports interleaved application where rotations are mixed across sections. For models like GLM-V, it uses a round-robin `axis_map` to cycle through axes [python/sglang/srt/layers/rotary_embedding/mrope.py117-131](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/mrope.py#L117-L131)
 - **Triton Optimization:** If the backend supports it, uses `apply_interleaved_rope_triton` for performance; otherwise falls back to a Python implementation [python/sglang/srt/layers/rotary_embedding/mrope.py146-153](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/mrope.py#L146-L153)

### 4. Specialized Variants

 SGLang implements several other scaling techniques in `rope_variant.py`:

 
 - **Llama 3 Scaling:** Implements the specific frequency scaling used in Llama 3 models, involving `low_freq_factor` and `high_freq_factor` [python/sglang/srt/layers/rotary_embedding/rope_variant.py252-270](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/rope_variant.py#L252-L270)
 - **Phi-3 LongRoPE:** Uses two different caches (`short_cos_sin_cache` and `long_cos_sin_cache`) and switches based on whether the position exceeds the original training length [python/sglang/srt/layers/rotary_embedding/rope_variant.py83-100](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/rope_variant.py#L83-L100)
 - **Fourier RoPE:** Implements trainable Fourier features for positional encoding, often used in models like GLM [python/sglang/srt/layers/rotary_embedding/rope_variant.py172-210](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/rope_variant.py#L172-L210)
 - **Dual Chunk RoPE:** Specialized for models using dual-chunk attention mechanisms [python/sglang/srt/layers/rotary_embedding/rope_variant.py650-670](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/rope_variant.py#L650-L670)

## The RoPE Factory and Caching

 The `get_rope` function in `factory.py` manages a process-wide cache `_ROPE_DICT` [python/sglang/srt/layers/rotary_embedding/factory.py60](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/factory.py#L60-L60)

 
 - **Caching Logic:** Modules are shared across layers to save memory. However, if a module's buffers are moved to the "meta" device or the storage is released (e.g., during model teardown), the factory invalidates the cache entry and rebuilds it via `_get_live_rope_cache_entry` [python/sglang/srt/layers/rotary_embedding/factory.py63-92](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/factory.py#L63-L92)
 - **Dispatching:** The factory parses the `rope_scaling` dictionary to decide which subclass to instantiate (e.g., `Llama3RotaryEmbedding` for `scaling_type == "llama3"`) [python/sglang/srt/layers/rotary_embedding/factory.py171-196](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/rotary_embedding/factory.py#L171-L196)
