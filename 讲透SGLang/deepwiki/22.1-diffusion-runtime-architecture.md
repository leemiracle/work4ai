  The SGLang diffusion runtime provides a high-performance framework for serving Diffusion Transformers (DiT) for image and video generation. It utilizes a multi-process architecture consisting of a centralized scheduler and specialized GPU workers to handle compute-intensive denoising tasks.

 
## System Overview

 The architecture is divided into three main layers:

 
 - **Entrypoints**: High-level APIs (OpenAI-compatible, CLI, or Python) that receive user requests via `DiffGenerator` [python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py101-107](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py#L101-L107)
 - **Scheduler**: A coordinator that manages the request queue and broadcasts tasks to workers [python/sglang/multimodal_gen/runtime/managers/scheduler.py80-85](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/scheduler.py#L80-L85)
 - **GPU Workers**: Execution engines that run the model pipelines (VAE, Text Encoders, and DiT) [python/sglang/multimodal_gen/runtime/managers/gpu_worker.py131-135](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/gpu_worker.py#L131-L135)

## Request Lifecycle and Data Flow

 Generation requests flow from the `DiffGenerator` or HTTP entrypoints to the `Scheduler`, which then coordinates execution across one or more `GPUWorker` instances.

 
 - **Request Initialization**: The `DiffGenerator` creates a `SamplingParams` object from user input [python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py109-118](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py#L109-L118)
 - **Scheduling**: The request is wrapped in a `Req` object and sent to the `Scheduler` via the `sync_scheduler_client` [python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py175-176](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py#L175-L176)
 - **Queueing**: The `Scheduler` maintains a `waiting_queue` of `Req` objects [python/sglang/multimodal_gen/runtime/managers/scheduler.py162](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/scheduler.py#L162-L162)
 - **Batch Admission**: The `BatchAdmissionController` evaluates the queue to determine which requests can be admitted based on hardware constraints [python/sglang/multimodal_gen/runtime/managers/scheduler.py167](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/scheduler.py#L167-L167)
 - **Execution**: The `Scheduler` dispatches tasks to the `GPUWorker` which initializes the pipeline and runs the forward pass [python/sglang/multimodal_gen/runtime/managers/scheduler.py131-135](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/scheduler.py#L131-L135)
 - **Output**: Results are collected in an `OutputBatch` and returned to the client [python/sglang/multimodal_gen/runtime/pipelines_core/schedule_batch.py49-65](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/pipelines_core/schedule_batch.py#L49-L65)

## Core Components

 
### DiffGenerator

 The `DiffGenerator` is the primary entrypoint for local or remote generation. It handles server lifecycle management via `launch_server` [python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py187](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py#L187-L187) and provides the `generate()` method for image/video tasks [python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py210](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py#L210-L210) It clones per-prompt parameters without losing model-internal state via `_replace_sampling_params_for_prompt` [python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py68-98](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/entrypoints/diffusion_generator.py#L68-L98)

 
### Scheduler

 The `Scheduler` runs on Rank 0 and acts as the cluster coordinator. It uses a `zmq.ROUTER` socket to handle multiple client connections [python/sglang/multimodal_gen/runtime/managers/scheduler.py113-119](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/scheduler.py#L113-L119) It manages server warm-up by preparing synthetic requests for specified resolutions [python/sglang/multimodal_gen/runtime/managers/scheduler.py80-85](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/scheduler.py#L80-L85) It also includes a `BatchAdmissionController` to manage dynamic batching and hardware utilization [python/sglang/multimodal_gen/runtime/managers/scheduler.py167](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/scheduler.py#L167-L167)

 
### GPU Worker

 Each `GPUWorker` manages a specific GPU device. It is responsible for:

 
 - Initializing the distributed environment including Tensor Parallel (TP), Sequence Parallel (SP), Data Parallel (DP), and Classifier-Free Guidance (CFG) parallel [python/sglang/multimodal_gen/runtime/managers/gpu_worker.py26-46](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/gpu_worker.py#L26-L46)
 - Building the model pipeline using `build_pipeline` [python/sglang/multimodal_gen/runtime/managers/gpu_worker.py62](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/gpu_worker.py#L62-L62)
 - Managing layerwise offloading for DiT models (e.g., `transformer`, `vae`) via `configure_layerwise_offload_modules` [python/sglang/multimodal_gen/runtime/managers/gpu_worker.py52-54](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/gpu_worker.py#L52-L54)
 - Handling memory occupation and "sleep/wake" states for RL/training integration via `MemoryOccupationController` [python/sglang/multimodal_gen/runtime/managers/gpu_worker.py169-170](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/gpu_worker.py#L169-L170)
 
 
### Req and OutputBatch

 The `Req` class is the central state object passed through the pipeline. It stores intermediate tensors such as `prompt_embeds`, `latents`, `timesteps`, and audio-specific latents for models like LTX-2 [python/sglang/multimodal_gen/runtime/pipelines_core/schedule_batch.py85-155](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/pipelines_core/schedule_batch.py#L85-L155) It delegates sampling parameter access to an internal `SamplingParams` instance [python/sglang/multimodal_gen/runtime/pipelines_core/schedule_batch.py80](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/pipelines_core/schedule_batch.py#L80-L80)

 `OutputBatch` encapsulates the results, including the generated tensors and performance metrics [python/sglang/multimodal_gen/runtime/pipelines_core/schedule_batch.py49-65](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/pipelines_core/schedule_batch.py#L49-L65)

## Performance and Optimization

 The runtime includes several advanced optimizations for DiT models:

 
 - **Platform Abstraction**: The runtime detects hardware via `current_platform` and dispatches appropriate attention backends like `SDPA`, `FlashAttention`, `SageAttention`, or `SlidingTileAttention` [python/sglang/multimodal_gen/runtime/platforms/cuda.py79-192](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/platforms/cuda.py#L79-L192)
 - **Layerwise Offloading**: To support large models on hardware with limited VRAM, weights are loaded/unloaded layer-by-layer [python/sglang/multimodal_gen/runtime/managers/gpu_worker.py52-54](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/gpu_worker.py#L52-L54) The system uses a recommendation order for disabling offload starting with the VAE and encoders [python/sglang/multimodal_gen/runtime/managers/gpu_worker.py95-101](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/managers/gpu_worker.py#L95-L101)
 - **Sequence Parallelism (SP)**: Shards latents and rotary embeddings along the sequence dimension to handle high-resolution generation across multiple GPUs [python/sglang/multimodal_gen/runtime/configs/pipeline_configs/base.py166-176](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/multimodal_gen/runtime/configs/pipeline_configs/base.py#L166-L176)
