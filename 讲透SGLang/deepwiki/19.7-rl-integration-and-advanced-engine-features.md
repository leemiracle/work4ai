  SGLang provides specialized features for Reinforcement Learning (RL) systems and advanced engine capabilities, including deterministic inference, weight refitting, and sophisticated memory management. It is widely adopted as a rollout backend for training frontier models by frameworks such as **verl**, **Miles**, **slime**, **AReaL**, and **ROLL**.

 
## RL Integration and Training Support

 RL workflows typically alternate between rollout (inference) and training (weight updates). SGLang optimizes this cycle through efficient weight synchronization and specialized loading formats.

 
### FlashRL and Weight Refit

 The `flash_rl` load format is designed for RL training with quantized models. It enables efficient weight reloading and the application of rollout-specific quantization profiles. The `LoadConfig` class manages these parameters, including `rl_quant_profile`, which allows users to specify paths to rollout quantization profiles (e.g., `.pt` files).

 
### R-Fork (Tensor Remote Fork)

 R-Fork is a methodology that leverages inter-node GPU-to-GPU data transfer to load tensors from a running "seed" instance to a new "client" instance with zero-copy.

 
 - **Backends**: Supports `remote` and `remote_instance` load formats.
 - **Implementation**: Managed via the `RemoteInstanceWeightTransporter`.
 - **Memory Registration**: Uses `MooncakeTransferEngine` to register model parameters for high-speed RDMA access.
 - **Initiation**: Tensors are requested via `InitWeightsSendGroupForRemoteInstanceReqInput` [python/sglang/srt/managers/tokenizer_control_mixin.py39](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/tokenizer_control_mixin.py#L39-L39) which is handled by the `Scheduler`.
 
 
### Deterministic Inference and Expert Routing

 To ensure reproducibility in RL experiments, SGLang supports deterministic behavior across distributed ranks. This is critical when collecting trajectories for policy gradients.

 
 - **Deterministic Inference**: Enabled via `ServerArgs.enable_deterministic_inference` [python/sglang/srt/server_args.py464](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/server_args.py#L464-L464) When active, it ensures that attention backends and sampling remain stable. For example, in DeepSeek-V3, it forces the use of the `MLA` absorbed attention path to avoid the shape-dependent variance of MHA chunked-KV.
 - **Expert Routing**: For MoE models, SGLang can return the selected expert IDs per token. This is facilitated by the `RoutedExpertsCapturer` [python/sglang/srt/state_capturer/routed_experts.py23-31](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/state_capturer/routed_experts.py#L23-L31) which captures `topk_ids` into a host buffer [python/sglang/srt/state_capturer/base.py118-125](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/state_capturer/base.py#L118-L125)
 - **Expert Distribution**: The `ExpertDistributionRecorder` monitors expert utilization, which can be queried via `ExpertDistributionReq` [python/sglang/srt/managers/tokenizer_control_mixin.py30-32](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/tokenizer_control_mixin.py#L30-L32) It captures `topk_ids` during the `on_select_experts` hook.

## Advanced Engine Features

 
### Dynamic Weight Updates

 The engine supports in-place weight updates without restarting the service. This allows RL trainers to push new policy weights to the inference workers. The `SchedulerWeightUpdaterManager` [python/sglang/srt/managers/scheduler_components/weight_updater.py76-86](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/scheduler_components/weight_updater.py#L76-L86) handles the coordination between the scheduler and workers.

 
| Update Request Type | Input Structure | Description |
|---|---|---|
| Disk Update | UpdateWeightFromDiskReqInput python/sglang/srt/managers/scheduler_components/weight_updater.py35 | Triggers a reload from the filesystem python/sglang/srt/managers/scheduler_components/weight_updater.py113-115 |
| Tensor Update | UpdateWeightsFromTensorReqInput python/sglang/srt/managers/scheduler_components/weight_updater.py41 | Direct weight update from CPU/GPU tensors python/sglang/srt/managers/scheduler_components/weight_updater.py159-161 |
| Distributed Update | UpdateWeightsFromDistributedReqInput python/sglang/srt/managers/scheduler_components/weight_updater.py37 | Updates weights across distributed nodes python/sglang/srt/managers/scheduler_components/weight_updater.py143-145 |
| IPC Update | UpdateWeightsFromIPCReqInput python/sglang/srt/managers/scheduler_components/weight_updater.py39 | Updates weights via IPC for checkpoint-engine integration python/sglang/srt/managers/scheduler_components/weight_updater.py175-177 |

 
### Weight Checker

 To ensure consistency during weight updates and distributed loading, a `WeightChecker` utility computes checksums and compares model states.

 
 - **Snapshot**: Captures current model state (parameters and buffers) to CPU.
 - **Compare**: Validates current weights against a snapshot, supporting `allow_quant_error` for quantized models.
 - **Checksum**: Generates a SHA-256 hash of all model tensors. The `SchedulerWeightUpdaterManager` provides methods like `check_weights` to verify consistency [python/sglang/srt/managers/scheduler_components/weight_updater.py23-28](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/scheduler_components/weight_updater.py#L23-L28)
 
 
### Engine Lifecycle: Sleep and Wake

 The engine can manage its memory footprint dynamically based on activity, useful for co-locating training and inference on the same hardware.

 
 - **Release Memory**: The engine can release memory occupation via `ReleaseMemoryOccupationReqInput` [python/sglang/srt/managers/tokenizer_control_mixin.py54-55](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/tokenizer_control_mixin.py#L54-L55)
 - **Resume Memory**: It can be woken up and re-occupy memory via `ResumeMemoryOccupationReqInput` [python/sglang/srt/managers/tokenizer_control_mixin.py58-59](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/tokenizer_control_mixin.py#L58-L59)
 
 
### Expert Parallelism Load Balancing (EPLB) and Elastic EP

 For MoE models, SGLang provides advanced expert management:

 
 - **EPLB**: The `EPLBManager` dynamically rebalances expert locations based on utilization metrics. It uses `ModelConfigForExpertLocation` [python/sglang/srt/models/longcat_flash.py49](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/models/longcat_flash.py#L49-L49) to map logical experts to physical ranks.
 - **Elastic EP**: Supports scaling expert parallelism ranks dynamically. The `scale_elastic_ep` [python/sglang/srt/managers/tokenizer_control_mixin.py130](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/tokenizer_control_mixin.py#L130-L130) command triggers scaling phases.

## Checkpoint Engine and Framework Integration

 SGLang integrates with external checkpointing systems for rapid state persistence.

 
 - **Checkpoint Engine**: Integration allows for high-performance weight loading and saving, specifically utilizing `UpdateWeightsFromIPCReqInput` for low-latency transfers [python/sglang/srt/managers/scheduler_components/weight_updater.py175-180](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/scheduler_components/weight_updater.py#L175-L180)
 - **Forward Hooks**: The engine supports forward hooks for advanced observability, such as capturing expert routing IDs during the forward pass.
 - **Partial Rollout**: The system supports extending existing sequences, effectively supporting partial rollouts with KV cache reuse.
 - **Load Snapshot**: The `SchedulerLoadInquirer` [python/sglang/srt/managers/scheduler_components/load_inquirer.py34-59](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/scheduler_components/load_inquirer.py#L34-L59) provides a detailed `LoadSnapshot` [python/sglang/srt/managers/load_snapshot.py192-205](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/load_snapshot.py#L192-L205) including memory usage (weight, KV cache, CUDA graph) and speculative decoding metrics to assist in RL workload balancing [python/sglang/srt/managers/scheduler_components/load_inquirer.py97-150](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/scheduler_components/load_inquirer.py#L97-L150)
