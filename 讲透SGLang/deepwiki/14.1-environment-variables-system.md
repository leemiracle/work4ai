## Purpose and Scope

 The Environment Variables System provides a centralized, type-safe mechanism for managing runtime configuration through environment variables in SGLang. This system uses Python descriptors via the `EnvField` class hierarchy to enable type-checked access, default values, and context-based overrides for all environment variables used throughout the codebase.

 This document covers the architecture and implementation of the environment variable management system found in `python/sglang/srt/environ.py` [python/sglang/srt/environ.py1-494](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/environ.py#L1-L494) For hardware-specific runtime configuration, see [Hardware Detection and Platform Configuration](https://deepwiki.com/sgl-project/sglang/14.2-hardware-detection-and-platform-configuration).

 
## System Architecture

 The environment variables system is built around a descriptor-based pattern that provides type safety and consistent access patterns. The `Envs` class acts as a container for these descriptors [python/sglang/srt/environ.py229-494](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/environ.py#L229-L494) and a global singleton `envs` is provided for system-wide access [python/sglang/srt/environ.py494](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/environ.py#L494-L494)

 **Key Implementation Details**:

 
| Method | Purpose | Implementation Detail |
|---|---|---|
| get() | Retrieve and parse value | Returns self.default (or resolves callable default) if os.getenv is None python/sglang/srt/environ.py57-72 |
| set(value) | Update environment | Handles None by setting _set_to_none flag and stringifying the value python/sglang/srt/environ.py86-89 |
| override(value) | Temporary change | Uses a @contextmanager to backup and restore previous state python/sglang/srt/environ.py90-101 |
| parse(value) | Type conversion | Abstract method overridden by subclasses python/sglang/srt/environ.py54-55 |

 To prevent logic errors, `EnvField` raises a `RuntimeError` if evaluated directly as a boolean or in a `len()` call, forcing developers to use `.get()` [python/sglang/srt/environ.py107-116](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/environ.py#L107-L116)

 
### Type-Specific Variants

 
| Class | Parse Logic | Sources |
|---|---|---|
| EnvStr | Returns the string as-is. | python/sglang/srt/environ.py123-125 |
| EnvBool | Parses "true", "1", "yes", "y" as True; "false", "0", "no", "n" as False. | python/sglang/srt/environ.py138-146 |
| EnvInt | Wraps int() with error handling. | python/sglang/srt/environ.py148-154 |
| EnvFloat | Wraps float() with error handling. | python/sglang/srt/environ.py191-197 |
| EnvTuple | Splits string by commas and strips whitespace. | python/sglang/srt/environ.py118-120 |
| EnvJSON | Parses string as JSON or loads from a file path if the path exists. | python/sglang/srt/environ.py128-136 |

 
### Deprecated Fallbacks

 The system includes `_DeprecatedEnvFallback` mixins (e.g., `EnvBoolWithAlias`) to handle renamed variables while emitting warnings [python/sglang/srt/environ.py156-180](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/environ.py#L156-L180) For example, `SGLANG_DSA_FUSE_TOPK` provides a fallback to the deprecated `SGLANG_NSA_FUSE_TOPK` [python/sglang/srt/environ.py302-304](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/environ.py#L302-L304)
