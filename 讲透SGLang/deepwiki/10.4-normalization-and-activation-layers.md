  This document describes the normalization and activation layer implementations in SGLang that provide efficient, hardware-optimized operations crucial for transformer models. These layers leverage platform-specific kernels and fused operations to maximize performance across NVIDIA CUDA, AMD ROCm, Ascend NPU, Intel XPU, MUSA, and CPU backends.

 This page details the implementation, data flow, and key classes/functions of **RMSNorm**, **LayerNorm**, **SiLUAndMul (SwiGLU activation)**, **GeluAndMul (GeGLU activation)**, and various fused kernels that integrate normalization with residual addition or all-reduce communication.

Attention Mechanisms and Backends)

## Overview and Architecture

 SGLang implements normalization and activation layers using a **multi-platform dispatch pattern** that selects the optimal kernel implementations at runtime based on the underlying hardware platform.

 All normalization and activation layers derive from `BaseFusedOp` [python/sglang/kernels/fused_op.py22-24](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/kernels/fused_op.py#L22-L24) providing automatic platform detection and method dispatch. This enables writing one interface that is automatically dispatched to optimized device or CPU implementations.

## RMSNorm (Root Mean Square Normalization)

 `RMSNorm` normalizes the input tensor based on its RMS value instead of centering on its mean. This is the standard normalization layer for LLaMA-based architectures.

 
### Key Parameters and Options

 
 - `hidden_size` (int): Dimension over which RMS is computed.
 - `eps` (float): Stability epsilon.
 - `cast_x_before_out_mul` (bool): If `True`, matches HuggingFace `LlamaRMSNorm` semantics by casting to activation dtype before weight multiplication [python/sglang/srt/layers/layernorm.py141-144](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/layernorm.py#L141-L144)
 - `quant_config`: Used for FP8/INT8 quantized normalization paths [python/sglang/srt/layers/layernorm.py206](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/layernorm.py#L206-L206)
 
 
### Implementation Backends

 
 - **CUDA (AOT)**: Uses `sgl_kernel.rmsnorm` [python/sglang/srt/layers/layernorm.py105](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/layernorm.py#L105-L105)
 - **CUDA (JIT)**: Uses `sglang.kernels.ops.layernorm.rmsnorm_hf` for specific hidden sizes to ensure numerical identity with HuggingFace [python/sglang/srt/layers/layernorm.py145-155](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/layernorm.py#L145-L155)
 - **ROCm (HIP)**: Dispatches to `aiter.rmsnorm2d_fwd` [python/sglang/srt/layers/layernorm.py113](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/layernorm.py#L113-L113) or `vllm._custom_ops.rms_norm` [python/sglang/srt/layers/layernorm.py120](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/layernorm.py#L120-L120)
 - **NPU**: Uses `sgl_kernel_npu.norm.add_rmsnorm_bias` [python/sglang/srt/layers/layernorm.py175](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/layernorm.py#L175-L175)
 
 
### Fused Operations

 SGLang implements several fused variations to reduce memory bandwidth:

 
 - **Fused Residual Addition**: `output = RMSNorm(x + residual)`. Triggered in `RMSNorm.forward` when a `residual` tensor is provided [python/sglang/srt/layers/layernorm.py334](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/layernorm.py#L334-L334)
 - **Fused All-Reduce + RMSNorm**: Used in distributed inference to fuse the communication step with normalization [python/sglang/srt/layers/layernorm.py191-207](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/layernorm.py#L191-L207) This dispatches to `tensor_model_parallel_fused_allreduce_rmsnorm` [python/sglang/srt/distributed/communication_op.py28-40](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/distributed/communication_op.py#L28-L40)

## LayerNorm

 LayerNorm is primarily used in architectures like MoE routers or specific multimodal models.

 
 - **Implementation**: SGLang attempts to use `flashinfer.norm.layernorm` for optimized execution on CUDA [python/sglang/srt/layers/layernorm.py75-82](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/layernorm.py#L75-L82)
 - **Fallback**: Falls back to `torch.nn.functional.layer_norm` if FlashInfer is unavailable [python/sglang/srt/layers/layernorm.py86](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/layernorm.py#L86-L86)
 - **Platform Support**: Dispatched via platform-specific wrappers in the `layernorm` function [python/sglang/srt/layers/layernorm.py76](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/layernorm.py#L76-L76)

## Activation Functions

 Transformer MLPs use Gated Linear Units (GLU) where the activation is fused with a multiplication of a linear projection.

 
### SiLUAndMul (SwiGLU)

 
 - **Logic**: `silu(x[..., :d]) * x[..., d:]` where `d = x.shape[-1] // 2`.
 - **Kernel Selection**: 
 - CUDA: Dispatches between JIT (`_jit_silu_and_mul`) and AOT (`_sgl_silu_and_mul`) based on vector alignment checks (`_jit_act_supported`) [python/sglang/srt/layers/activation.py85-99](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/activation.py#L85-L99)
 - NPU: Uses `torch_npu.npu_swiglu` [python/sglang/srt/layers/activation.py164](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/activation.py#L164-L164)
 
 
### GeluAndMul (GeGLU)

 
 - **Logic**: `gelu(x[..., :d]) * x[..., d:]`.
 - **Implementations**: Similar to SiLU, it uses JIT/AOT CUDA kernels or `torch_npu.npu_geglu` [python/sglang/srt/layers/activation.py101-218](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/activation.py#L101-L218)
 
 **Sources:** [python/sglang/srt/layers/activation.py59-238](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/activation.py#L59-L238)

## All-Reduce and Normalization Fusion

 For high-performance distributed serving, SGLang supports fusing the Tensor Parallel (TP) all-reduce communication with the subsequent normalization layer. This is particularly effective for small batch sizes (decode phase).

 
### FlashInfer Fusion (NVIDIA)

 On NVIDIA GPUs, SGLang uses FlashInfer's `allreduce_fusion` API [python/sglang/srt/layers/flashinfer_comm_fusion.py94-102](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/flashinfer_comm_fusion.py#L94-L102) It supports:

 
 - `kAllReduce`: Standard fused all-reduce.
 - `kARResidualRMSNorm`: Fused All-Reduce + Residual Add + RMSNorm.
 
 
### Aiter Fusion (AMD)

 On AMD ROCm, SGLang leverages the `aiter` library to perform fused all-reduce and normalization [python/sglang/srt/layers/communicator.py182-194](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/communicator.py#L182-L194) This is especially useful for FP8 workflows where normalization is fused with per-token or per-group quantization [python/sglang/srt/layers/communicator.py114-157](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/communicator.py#L114-L157)
