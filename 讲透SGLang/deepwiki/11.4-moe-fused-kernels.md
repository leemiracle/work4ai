## Purpose and Scope

 This document covers the specialized CUDA kernels and Triton implementations in `sgl-kernel` and `sglang` designed for efficient Mixture of Experts (MoE) operations. These kernels fuse multiple operations—such as gating, hierarchical selection, token alignment, and grouped GEMM—to minimize memory bandwidth and kernel launch overhead, particularly for large-scale models like DeepSeek-V3/V4 and GLM-4.

 **Scope includes:**

 
 - Fused gating and hierarchical expert selection (Top-K routing).
 - Grouped GEMM kernels (Triton, DeepGEMM, and CUTLASS-based).
 - Token routing, permutation, and alignment utilities (`moe_align_block_size`).
 - Batch overlap optimizations (TBO/SBO) for MoE communication.
 - Support for advanced quantization formats including FP8, MXFP4, and NVFP4.
 - Hardware-specific optimizations for NVIDIA (SM90/Blackwell), AMD (ROCm/Aiter), and Intel (XPU).

## Kernel Categories and Data Flow

 MoE fused kernels are organized into functional stages that transform input hidden states into final expert-processed outputs.

 
| Category | Role | Key Entities |
|---|---|---|
| Gating/Top-K | Expert selection and weight calculation | fused_topk_deepseek, topk_softmax, topk_sigmoid, aiter_fused_topk |
| Dispatch/Align | Reordering tokens for expert processing | moe_align_block_size, PackTopkIds, DeepEPDispatcher |
| Expert GEMM | Computation of expert layers (W1, W2, W3) | FusedMoE (Triton), DeepGemm, flashinfer_fp4_gemm, aiter_w8a8_block_fp8_linear |
| Combine/Finalize | Merging expert outputs back to original order | moe_finalize_fuse_shared, StandardCombineInput, silu_and_mul_clamp |

## Gating and Hierarchical Selection

 SGLang implements specialized gating kernels to handle complex routing logic, such as DeepSeek's grouped Top-K routing where experts are partitioned into groups.

 
### Fused Top-K Implementations

 
 - **DeepSeek Gating**: The `fused_topk_deepseek` kernel (via FlashInfer) calculates routing weights and IDs in a single pass, applying optional renormalization and scaling [python/sglang/srt/layers/moe/topk.py158-180](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/topk.py#L158-L180)
 - **XPU Gating**: For Intel hardware, `topk_sigmoid` and `topk_softmax` are imported from `sgl_kernel` to perform hardware-accelerated routing [python/sglang/srt/layers/moe/topk.py185-189](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/topk.py#L185-L189)
 - **HashTopK**: Maps tokens to experts based on a hash-based lookup table (`tid2eid`) rather than learned logits, used for specific balancing strategies [python/sglang/srt/layers/moe/hash_topk.py34-77](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/hash_topk.py#L34-L77)
 - **Aiter Gating**: For AMD ROCm, `aiter_biased_grouped_topk` and `aiter_fused_topk` provide optimized routing paths [python/sglang/srt/layers/moe/topk.py197-202](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/topk.py#L197-L202)

## Grouped GEMM and Expert Execution

 Grouped GEMM is the core computational engine for MoE, allowing multiple experts to be processed simultaneously.

 
### Triton and FlashInfer Backends

 
 - **Triton**: The `FusedMoE` layer supports various quantization formats and uses `moe_align_block_size` to prepare token indices for the Triton kernels [python/sglang/srt/layers/moe/fused_moe_triton/layer.py46-52](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L46-L52)
 - **FlashInfer/TRTLLM**: Uses `trtllm_fp8_block_scale_moe_out_wrapper` for FP8 block-scaled experts. It includes specific logic for padding intermediate sizes to satisfy kernel alignment (e.g., 16 for gated, 128 for non-gated) [python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py27-31](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py#L27-L31) [python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py150-182](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py#L150-L182)
 
 
### DeepGEMM and NVFP4

 
 - **DeepGEMM**: Optimized for SM90/Hopper, DeepGEMM handles W8A8 block-scaled FP8 MoE. It manages JIT compilation for specific expert shapes [python/sglang/srt/layers/moe/ep_moe/layer.py114-122](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/ep_moe/layer.py#L114-L122)
 - **NVFP4 (Blackwell)**: Support for NVIDIA's FP4 format via `flashinfer_fp4_gemm`. Weights are padded to 32-column alignment (`FP4_GEMM_ALIGNMENT`) to satisfy hardware constraints [python/sglang/srt/layers/quantization/modelopt_quant.py146-152](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelopt_quant.py#L146-L152) [python/sglang/srt/layers/quantization/modelopt_quant.py164-176](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelopt_quant.py#L164-L176)

## Token Dispatch and Alignment

 Efficient MoE requires moving tokens to the correct expert rank (Expert Parallelism) or reordering them locally for grouped GEMM.

 
### moe_align_block_size

 This utility (often implemented in Triton or CUDA) calculates the mapping from expert IDs to token indices, producing `expert_offsets` and `sorted_token_ids` to ensure contiguous memory access during expert computation [python/sglang/srt/layers/moe/fused_moe_triton/layer.py80-88](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L80-L88)

 
### Distributed Dispatchers

 
 - **DeepEP**: A low-latency dispatcher used for Expert Parallelism. It supports `low_latency` and `normal` modes, with `low_latency` being preferred for decode phases [python/sglang/srt/layers/moe/ep_moe/layer.py170-180](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/ep_moe/layer.py#L170-L180)
 - **MaybeTboDeepEPDispatcher**: A wrapper that handles Two-Batch Overlap (TBO) integration with DeepEP communication [python/sglang/srt/layers/moe/fused_moe_triton/layer.py181-192](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L181-L192)

## Batch Overlap and Advanced Optimizations

 SGLang optimizes MoE performance by overlapping computation and communication.

 
 - **TBO/SBO (Two/Single Batch Overlap)**: Overlaps Expert Parallel communication (All-to-All) with GEMM computation. `MaybeTboDeepEPDispatcher` manages this by initiating asynchronous transfers while the GPU is busy with local expert GEMMs [python/sglang/srt/layers/moe/fused_moe_triton/layer.py181-192](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L181-L192)
 - **Fused Shared Expert Finalization**: The `moe_finalize_fuse_shared` kernel merges the output of the MoE experts with the output of "shared experts" (common in DeepSeek architectures) in a single fused operation, reducing memory traffic [python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py79-92](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py#L79-L92)
 - **PDL (Predictive Data Loading)**: For supported architectures, MoE kernels can enable PDL to prefetch expert weights based on predicted routing, reducing latency [python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py54-57](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py#L54-L57)
