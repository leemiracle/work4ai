  This document describes how SGLang and its core kernel library, `sgl-kernel`, integrate third-party libraries to provide optimized compute primitives for LLM inference. The integration covers dependency management, build configuration, kernel selection, and runtime dispatch mechanisms across different hardware platforms.

 
---

 
## Integration Architecture

 SGLang integrates several major third-party libraries to provide state-of-the-art performance for attention, GEMM, and communication. The integration uses CMake `FetchContent` for dependency management and compile-time configuration to select optimal implementations based on GPU architecture (SM80, SM89, SM90, SM100, etc.).

## Library-Specific Integration

 
### CUTLASS Integration

 SGLang leverages CUTLASS for template-based GEMM operations, particularly for Mixture-of-Experts (MoE) and Multi-head Latent Attention (MLA) decoding.

 
 - **MLA Decoding**: The `cutlass_mla_decode` kernel utilizes CUTLASS to perform latent attention decoding for DeepSeek-style models [sgl-kernel/include/sgl_kernel_ops.h99-108](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-kernel/include/sgl_kernel_ops.h#L99-L108).
 - **Backend Class**: The `CutlassMLABackend` handles the Python-side lifecycle, including workspace allocation via `cutlass_mla_get_workspace_size` [python/sglang/srt/layers/attention/cutlass_mla_backend.py30-34](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/cutlass_mla_backend.py#L30-L34).
 - **Page Size**: Cutlass MLA implementation in SGLang specifically targets a `PAGE_SIZE` of 128 [python/sglang/srt/layers/attention/cutlass_mla_backend.py34](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/cutlass_mla_backend.py#L34-L34).
 
 **Sources:** [sgl-kernel/include/sgl_kernel_ops.h99-113](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-kernel/include/sgl_kernel_ops.h#L99-L113), [python/sglang/srt/layers/attention/cutlass_mla_backend.py30-51](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/cutlass_mla_backend.py#L30-L51).

 
### DeepGEMM Integration

 SGLang provides a comprehensive wrapper for DeepSeek's DeepGEMM, specifically optimized for FP8 operations on SM90 (Hopper) and SM100 (Blackwell).

 
 - **JIT Compilation**: SGLang uses a `compile_utils.py` infrastructure to manage DeepGEMM JIT compilation, including a `_BUILTIN_M_LIST` for pre-compiling common batch sizes [python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py37-70](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py#L37-L70).
 - **Execution Hook**: Kernels are launched within a `deep_gemm_execution_hook` that manages SM occupancy and JIT status [python/sglang/srt/layers/deep_gemm_wrapper/entrypoint.py70-75](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/deep_gemm_wrapper/entrypoint.py#L70-L75).
 - **Alignment**: SGLang uses `get_mn_major_tma_aligned_tensor` to ensure scales are compatible with Blackwell's TMA (Tensor Memory Accelerator) [python/sglang/srt/layers/deep_gemm_wrapper/entrypoint.py25-42](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/deep_gemm_wrapper/entrypoint.py#L25-L42).
 - **Kernel Selection**: The `DeepGemmKernelType` enum categorizes kernels such as `GROUPED_GEMM_NT_F8F8BF16_MASKED` and `GEMM_NT_F8F8BF16` for different execution paths [python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py108-114](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py#L108-L114).
 
 **Sources:** [python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py31-114](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py#L31-L114), [python/sglang/srt/layers/deep_gemm_wrapper/entrypoint.py25-99](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/deep_gemm_wrapper/entrypoint.py#L25-L99).

 
### FlashInfer Integration

 FlashInfer is a primary backend for both MHA and MLA attention architectures.

 
 - **Backend Wrappers**: SGLang implements `FlashInferAttnBackend` and `FlashInferMLAAttnBackend` to interface with FlashInfer's `BatchDecodeWithPagedKVCacheWrapper` and `BatchMLAPagedAttentionWrapper` [python/sglang/srt/layers/attention/flashinfer_backend.py75-80](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/flashinfer_backend.py#L75-L80), [python/sglang/srt/layers/attention/flashinfer_mla_backend.py71-75](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/flashinfer_mla_backend.py#L71-L75).
 - **Workspace Sharing**: A global workspace buffer is reused across FlashInfer wrappers to minimize memory fragmentation [python/sglang/srt/layers/attention/flashinfer_backend.py165-171](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/flashinfer_backend.py#L165-L171).
 - **TRTLLM MLA**: The `TRTLLMMLABackend` integrates specialized TRTLLM-style MLA kernels provided by FlashInfer, supporting both prefill and decode modes [python/sglang/srt/layers/attention/trtllm_mla_backend.py187-205](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/trtllm_mla_backend.py#L187-L205).
 
 **Sources:** [python/sglang/srt/layers/attention/flashinfer_backend.py71-108](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/flashinfer_backend.py#L71-L108), [python/sglang/srt/layers/attention/flashinfer_mla_backend.py66-85](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/flashinfer_mla_backend.py#L66-L85), [python/sglang/srt/layers/attention/trtllm_mla_backend.py1-205](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/trtllm_mla_backend.py#L1-L205).

 
### Flash-Attention and FlashMLA Integration

 SGLang utilizes Flash-Attention (FA) for standard attention and FlashMLA for DeepSeek-style models.

 
 - **FlashAttentionBackend**: Implements the `AttentionBackend` interface using `flash_attn_varlen_func` and `flash_attn_with_kvcache` [python/sglang/srt/layers/attention/flashattention_backend.py53-56](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/flashattention_backend.py#L53-L56), [python/sglang/srt/layers/attention/flashattention_backend.py130-146](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/flashattention_backend.py#L130-L146).
 - **FlashMLA**: The `FlashMLABackend` uses `flash_mla_with_kvcache` and `get_mla_metadata` from `sgl_kernel.flash_mla` [python/sglang/srt/layers/attention/flashmla_backend.py13-18](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/flashmla_backend.py#L13-L18). It supports a `PAGE_SIZE` of 64 [python/sglang/srt/layers/attention/flashmla_backend.py33](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/flashmla_backend.py#L33-L33).
 
 **Sources:** [python/sglang/srt/layers/attention/flashattention_backend.py46-143](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/flashattention_backend.py#L46-L143), [python/sglang/srt/layers/attention/flashmla_backend.py13-63](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/flashmla_backend.py#L13-L63).

 
### AITER and AMD ROCm Integration

 For AMD hardware, SGLang integrates the AITER library.

 
 - **AiterAttnBackend**: Provides AMD-specific attention implementations using `aiter.mla_prefill_fwd` and `aiter.mla_decode_fwd` [python/sglang/srt/layers/attention/aiter_backend.py49-61](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/aiter_backend.py#L49-L61).
 - **Quantization Support**: Aiter supports FP8 per-tensor quantization kernels for prefill [python/sglang/srt/layers/attention/aiter_backend.py76-79](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/aiter_backend.py#L76-L79).
 - **Vectorized Operations**: SGLang uses `forward_decode_vectorized_5d` and `forward_extend_vectorized_5d` for optimized AMD execution [python/sglang/srt/layers/attention/aiter_backend.py82-85](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/aiter_backend.py#L82-L85).
 
 **Sources:** [python/sglang/srt/layers/attention/aiter_backend.py44-89](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/aiter_backend.py#L44-L89).

 
### TokenSpeed Integration

 For NVIDIA Blackwell (SM100), SGLang integrates `tokenspeed-mla`.

 
 - **CuTe DSL Kernels**: `TokenspeedMLABackend` subclasses `TRTLLMMLABackend` to provide Blackwell-optimized FP8 KV cache kernels using CuTe DSL [python/sglang/srt/layers/attention/tokenspeed_mla_backend.py23-29](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/tokenspeed_mla_backend.py#L23-L29).
 - **Workspace Management**: Allocates specialized `_tokenspeed_workspace` buffers based on `num_heads` and `kv_lora_rank` [python/sglang/srt/layers/attention/tokenspeed_mla_backend.py84-108](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/tokenspeed_mla_backend.py#L84-L108).
 - **Pre-JIT Warmup**: The backend performs a JIT compilation warmup for causal and non-causal kernel variants during initialization to avoid runtime stalls [python/sglang/srt/layers/attention/tokenspeed_mla_backend.py156-176](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/attention/tokenspeed_mla_backend.py#L156-L176).
