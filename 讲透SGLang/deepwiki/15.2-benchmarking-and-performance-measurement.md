## Overview

 SGLang provides a comprehensive benchmarking framework designed to measure performance at various levels of the serving stack. These tools allow developers to isolate bottlenecks in kernels, scheduling, or network I/O.

 
 - **Online Serving Benchmarks**: Measuring latency (TTFT, ITL, TPOT) and throughput under realistic load with dynamic arrival rates [python/sglang/bench_serving.py1-22](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/bench_serving.py#L1-L22)
 - **Single Batch Performance**: Measuring end-to-end latency for isolated batches through the HTTP stack [python/sglang/benchmark/one_batch_server.py1-13](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/benchmark/one_batch_server.py#L1-L13)
 - **Kernel-level Latency Profiling**: Low-level timing of a single static batch bypassing the scheduler and server entirely [python/sglang/bench_one_batch.py1-22](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/bench_one_batch.py#L1-L22)
 - **Offline Throughput**: Measuring maximum engine capacity by submitting all requests at once in-process [python/sglang/bench_offline_throughput.py1-22](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/bench_offline_throughput.py#L1-L22)
 
 The benchmarking system is integrated with hardware-specific profilers and provides detailed metrics for specialized architectures like speculative decoding [scripts/playground/bench_speculative.py1-10](https://github.com/sgl-project/sglang/blob/94183a8d/scripts/playground/bench_speculative.py#L1-L10)

### 1. Online Serving Benchmark (`bench_serving`)

 The `bench_serving` module is an asynchronous HTTP load-testing client [python/sglang/benchmark/serving.py16-41](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/benchmark/serving.py#L16-L41) It supports various backends (sglang, vllm, trt-llm, lmdeploy, openai) and measures realistic online serving metrics [python/sglang/benchmark/serving.py51-53](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/benchmark/serving.py#L51-L53)

 **Key Metrics Tracked in `RequestFuncOutput` [python/sglang/benchmark/serving.py98-116](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/benchmark/serving.py#L98-L116):**

 
 - **TTFT (Time to First Token)**: Latency from request submission to the first generated token.
 - **ITL (Inter-Token Latency)**: List of latencies between consecutive tokens.
 - **Latency**: Total end-to-end request time.
 - **Speculative Decoding Metrics**: Includes `spec_accept_length`, `spec_cap_length`, and `spec_block_accept_length` [python/sglang/benchmark/serving.py112-115](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/benchmark/serving.py#L112-L115)

### Cache Performance Measurement

 SGLang tracks KV cache efficiency through specific metrics. The `cache_hit_kit.py` utility demonstrates how to extract these from the server response [python/sglang/test/kits/cache_hit_kit.py1-10](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/test/kits/cache_hit_kit.py#L1-L10)

 
 - **`cached_tokens`**: Returned in the `meta_info` of the first token chunk for SGLang native protocol [python/sglang/test/kits/cache_hit_kit.py64-66](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/test/kits/cache_hit_kit.py#L64-L66)
 - **OpenAI Compatibility**: Extracted from `usage.prompt_tokens_details.cached_tokens` in the chat completions response [python/sglang/test/kits/cache_hit_kit.py149-154](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/test/kits/cache_hit_kit.py#L149-L154)
 - **Server Cache Flushing**: The benchmark tool can trigger a cache flush via `/flush_cache` (SGLang) or `/reset_prefix_cache` (vLLM) to ensure clean-state measurements [test/registered/bench_fn/test_benchmark_datasets_api.py164-202](https://github.com/sgl-project/sglang/blob/94183a8d/test/registered/bench_fn/test_benchmark_datasets_api.py#L164-L202)
