## Purpose and Scope

 This document covers the quantization kernels in the `sgl-kernel` library and the SGLang runtime, which provide high-performance GPU implementations for quantizing neural network activations and weights to lower precision formats (INT8, FP8, NVFP4, INT4, AWQ). These kernels enable efficient inference by reducing memory bandwidth and utilizing specialized hardware instructions such as NVIDIA Tensor Cores on Hopper (SM90) and Blackwell (SM100) architectures, as well as AMD MI300 series (gfx942/gfx950) and Moore Threads (MUSA) architectures.

 The `sgl-kernel` library acts as the compute engine for SGLang, exposing optimized primitives through a PyTorch-compatible C++ extension layer.

 The SGLang quantization system implements multiple strategies organized by granularity, data type, and target architecture.

## FP8 and INT8 Quantization

 FP8 and INT8 support is a core optimization for Hopper and Blackwell GPUs, as well as AMD and MUSA hardware.

 
### Per-Token and Group Quantization

 The `per_token_group_quant_fp8` kernel computes scale factors and converts values to 8-bit formats.

 
 - **Group Quantization**: SGLang provides `sglang_per_token_group_quant_fp8` and its row-padded variant to handle specific alignment requirements in MoE layers [python/sglang/srt/layers/quantization/fp8_utils.py16-19](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L16-L19)
 - **DeepSeek MLA Support**: MLA (Multi-head Latent Attention) projections in models like DeepSeek-V3 utilize `w8a8_block_fp8_matmul_deepgemm` for high-performance block-scaled matmuls [python/sglang/srt/layers/quantization/fp8_utils.py23-25](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L23-L25)
 - **Architecture Support**: Specific logic handles the conversion of MXFP8 checkpoints to block-fp8 [128, 128] for AMD gfx942 (MI300) and gfx950 (MI35x) architectures [python/sglang/srt/layers/quantization/fp8.py120-128](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8.py#L120-L128)
 
 
### Scaled Matrix Multiplication (GEMM)

 SGLang dispatches 8-bit GEMMs through various backends including Triton, DeepGEMM, and Aiter.

 
 - **Triton Backend**: `triton_scaled_mm` provides a portable implementation for scaled FP8 multiplication [python/sglang/srt/layers/quantization/fp8_utils.py22](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L22-L22)
 - **Aiter (ROCm)**: For AMD hardware, SGLang uses `aiter_w8a8_block_fp8_linear` and `ck_gemm_a8w8_blockscale_bpreshuffle` to optimize throughput [python/sglang/srt/layers/quantization/fp8_utils.py148-162](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8_utils.py#L148-L162)
 - **DeepGEMM**: A specialized JIT-compiled backend for DeepSeek-style models, supporting W8A8 and block-scaled operations [python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py108-115](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py#L108-L115)

## AWQ and Marlin Kernels

 For 4-bit weight-only quantization, SGLang integrates AWQ and Marlin kernels to maintain high throughput on older architectures.

 
### Implementation Details

 
 - **Marlin Integration**: SGLang supports Marlin via `prepare_fp8_layer_for_marlin` and `prepare_nvfp4_layer_for_marlin` for efficient 4-bit/8-bit execution [python/sglang/srt/layers/quantization/modelopt_quant.py50-55](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelopt_quant.py#L50-L55)
 - **DeepSeek-V4 FP4 Experts**: Specifically for DeepSeek-V4, the system includes a `cast_e2m1fn_to_e4m3fn` function to losslessly cast FP4 experts to FP8 for compatibility with existing W8A8 compute paths [python/sglang/srt/layers/quantization/fp8.py180-220](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8.py#L180-L220)
 - **Dequantization Tables**: The `DSV4_DEQUANT_FP4_TABLE` is used to map 4-bit values to float32 during weight loading and processing [python/sglang/srt/layers/quantization/fp8.py157-177](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8.py#L157-L177)
