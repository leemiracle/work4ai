  This page provides technical definitions and implementation details for advanced concepts in SGLang, focusing on distributed execution, Mixture-of-Experts (MoE) optimizations, quantization schemes, and the model gateway architecture.

 
## Distributed Execution and Parallelism

 SGLang utilizes multiple levels of parallelism to scale model execution across hardware.

 
### Parallelism Strategies (TP/PP/DP/EP)

 
 - **Tensor Parallelism (TP):** Splits individual layers (e.g., `ColumnParallelLinear`, `RowParallelLinear`) across multiple GPUs within a node. Communication is handled by `LayerCommunicator` which manages operations like `all_reduce` and `all_gather` [python/sglang/srt/layers/communicator.py23-29](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/communicator.py#L23-L29) The `GroupCoordinator` manages the process groups for TP [python/sglang/srt/distributed/parallel_state.py163-165](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/distributed/parallel_state.py#L163-L165)
 - **Pipeline Parallelism (PP):** Partitions model layers across different GPUs or nodes. Requests flow through "stages" of the pipeline. SGLang uses `PPProxyTensors` to manage metadata across pipeline boundaries [python/sglang/srt/model_executor/forward_batch_info.py155](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_executor/forward_batch_info.py#L155-L155) The `SchedulerPPMixin` implements the event loop for PP, coordinating work across stages via `event_loop_pp` [python/sglang/srt/managers/scheduler_pp_mixin.py74-97](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/scheduler_pp_mixin.py#L74-L97)
 - **Data Parallelism (DP):** Replicated model execution. SGLang supports `dp_attention` where different ranks handle different sequences or parts of sequences, coordinated by `get_attention_dp_size` [python/sglang/srt/layers/dp_attention.py97](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/dp_attention.py#L97-L97)
 - **Expert Parallelism (EP):** Used for Mixture-of-Experts (MoE) models. Experts are distributed across ranks. SGLang supports multiple backends for token dispatch including `DeepEP`, `Mooncake`, `NIXL`, and `MORI` [python/sglang/srt/layers/moe/fused_moe_triton/layer.py174-180](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L174-L180)
 - **Elastic EP:** Allows for dynamic adjustment of expert ranks during runtime, supported by `update_dp_attention_post_scale` to switch to WORLD group communication [python/sglang/srt/layers/dp_attention.py64-73](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/dp_attention.py#L64-L73)
 - **ExpertPack:** A binary format (`SGLANG-EXPERTPACK-v1`) used for building and validating expert weights for MoE models, optimized for loading into specialized dispatchers.
 
 
### Prefill-Decode Disaggregation

 A specialized architecture that separates the "Prefill" phase (computation-bound) from the "Decode" phase (memory-bound) onto different sets of servers to improve throughput and latency.

 
 - **KV Transfer Backends:** Mechanisms to move KV cache from prefill nodes to decode nodes. 
 - **Mooncake:** A distributed KV cache management system utilizing RDMA and shared memory. Managed by `MooncakeKVManager` [python/sglang/srt/disaggregation/mooncake/conn.py198-209](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/mooncake/conn.py#L198-L209)
 - **NIXL:** A high-performance communication library for cross-node KV transfer, used in token dispatch and disaggregation [python/sglang/srt/disaggregation/nixl/conn.py53-65](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/nixl/conn.py#L53-L65)
 - **MORI:** An optimized transfer backend for disaggregated serving, often used in conjunction with high-speed interconnects.
 - **PD-Multiplexing:** Coordination of prefill and decode tasks across workers. Prefill nodes and decode nodes communicate via a `BaseKVBootstrapServer` [python/sglang/srt/disaggregation/base/conn.py20](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/base/conn.py#L20-L20)
 - **EPD Disaggregation:** Extension of disaggregation to Multimodal/Vision-Language Models (VLM), where prefill nodes handle heavy visual encoding before transferring KV cache to decode workers.
 
 
### Expert Load Balancing (EPLB)

 A mechanism to mitigate hot-spots in MoE models by monitoring expert utilization.

 
 - **Heatmap Collection:** SGLang collects metrics on physical expert selection via `get_global_expert_distribution_recorder` [python/sglang/srt/models/deepseek_v2.py58](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/models/deepseek_v2.py#L58-L58)
 - **Expert Location Dispatch:** Maps logical expert IDs to physical ranks based on utilization data using `ExpertLocationDispatchInfo` [python/sglang/srt/models/deepseek_v2.py60](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/models/deepseek_v2.py#L60-L60)

## Quantization System

 SGLang supports various quantization schemes to reduce memory footprint and increase compute throughput.

 
### FP8 and MXFP4 Quantization

 
 - **FP8 (E4M3):** High-performance 8-bit floating point kernels for NVIDIA Hopper (SM90) and Blackwell (SM100) GPUs. Supported via `Fp8Config` [python/sglang/srt/layers/quantization/fp8.py124](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8.py#L124-L124)
 - **MXFP4 / NVFP4:** 4-bit floating point formats with microscaling. SGLang supports `fp4_quantize` for SM100 and ROCm platforms [python/sglang/srt/layers/quantization/modelopt_quant.py34-37](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelopt_quant.py#L34-L37)
 - **Quantized KV Cache:** Reducing the memory footprint of the KV cache using FP8 or FP4 types, managed by `BaseKVCacheMethod` [python/sglang/srt/layers/quantization/fp8.py69](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8.py#L69-L69)

## Multimodal and Vision-Language Models (VLM)

 SGLang provides an extensible framework for processing multimodal inputs.

 
### Multimodal Processing Components

 
 - **MmFamilyProcessor:** The core architecture for handling vision-language model preprocessing, accelerated by the `sglang-mm` Rust library.
 - **sglang-mm:** A Rust-accelerated multimodal preprocessing pipeline that performs fused image decoding, resizing, patchifying, and normalization.
 - **HiSparse:** A specialized memory pool optimization for large-scale multimodal context handling.
 - **Multi-head Latent Attention (MLA):** Optimized attention mechanism used in DeepSeek models to reduce KV cache size. ## Gateway and Routing Terms

 The `sgl-model-gateway` (implemented in Rust) acts as the high-performance entry point for request routing and load balancing.

 
 - **Worker:** An individual SGLang server instance. The gateway manages a `WorkerRegistry` [sgl-model-gateway/src/core/worker_registry.rs1-10](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker_registry.rs#L1-L10) Workers are selected based on health (`is_available`) and policy [sgl-model-gateway/src/routers/http/router.rs151-158](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/router.rs#L151-L158)
 - **Job Queue:** Manages incoming requests before they are dispatched to workers.
 - **KV-Event Routing:** Cache-aware routing that uses `KV Events` to track prefix availability across workers.
 - **sgl-router:** A slim, KV-event-driven router written in Rust that supports prefix-aware routing and PD disaggregation [sgl-model-gateway/src/routers/http/pd_router.rs50](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/pd_router.rs#L50-L50)
 - **llm-d:** A Kubernetes-native fleet orchestration component for distributed KV-cache management at scale.
 
 
### Advanced Features

 
 - **Object Storage Loading:** Support for loading model weights directly from S3/GCS backends, integrated into the `ModelLoader` pipeline.
 - **Post-Training Integration:** Hooks for frameworks like `verl`, `Miles`, `slime`, `AReaL`, and `ROLL` to integrate SGLang for RLHF and fine-tuning.
 - **Production Metrics:** Real-time tracking of TTFT, TPOT, and cache hit rates via Prometheus. Metrics are interned via `intern_string` to optimize performance [sgl-model-gateway/src/observability/metrics.rs35-47](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/observability/metrics.rs#L35-L47)
 - **sglang-server Rust frontend:** A high-performance gRPC and HTTP frontend implemented in Rust.
 - **sglang.kernels:** A unified kernel namespace providing `KernelSpec` and `KernelRegistry` for optimized hardware dispatch.
