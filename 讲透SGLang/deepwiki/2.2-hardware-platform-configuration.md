## Supported Hardware Platforms

 SGLang supports a diverse range of hardware platforms, each with distinct runtime detection methods, build configuration files, and kernel packages. The supported platforms include NVIDIA CUDA GPUs, AMD ROCm GPUs, Intel's XPU GPUs, Ascend NPUs, Intel CPUs, Moore Threads GPUs, Apple Silicon (MPS/MLX), and Blackwell-specific architectures.

 
| Platform | Device Type | Detection Function | Build Config File | Kernel Package |
|---|---|---|---|---|
| NVIDIA CUDA | GPU | is_cuda() | python/pyproject.toml | sglang-kernel (PyPI) |
| AMD ROCm (HIP) | GPU | is_hip() | python/pyproject_other.toml | sglang-kernel (ROCm) |
| Intel XPU | GPU | is_xpu() | python/pyproject_xpu.toml | sgl-kernel-xpu |
| Intel CPU | CPU | is_cpu() | python/pyproject_cpu.toml | sglang-kernel-cpu |
| Ascend NPU | NPU | is_npu() | python/pyproject_npu.toml | sgl-kernel-npu |
| Moore Threads GPU | GPU | is_musa() | python/pyproject_other.toml | srt_musa extra |
| Apple Silicon MPS | GPU | is_mps() | python/pyproject_other.toml | srt_mps extra |
| Apple Silicon MLX | GPU | import mlx | python/pyproject_other.toml | srt_mps extra |

 Platform detection is primarily handled through the `sglang.srt.utils` utilities and the `sglang.srt.platforms` abstraction layer.

## Platform Build Configuration System

 SGLang uses separate platform-specific `pyproject.toml` files for dependency and package configuration tailored for each hardware platform. These files declare the necessary dependency sets optimized and verified for the specific hardware environment, whether CUDA, ROCm, CPU-only, XPU, or NPU.

 At install time or within CI pipelines, the target platform is detected, and the appropriate config file is selected for pip installations or Docker image builds. This architecture enables streamlined builds, avoids incompatible dependency conflicts, and provides platform-optimized kernel packages.

 
### Build Config Files and Kernel Packages

 
| Build Config File | Target Platform | Kernel Package |
|---|---|---|
| python/pyproject.toml | CUDA (NVIDIA GPUs) | sglang-kernel (PyPI) |
| python/pyproject_other.toml | ROCm, MUSA, MPS, Moore Threads | sglang-kernel (ROCm) or srt_musa, srt_mps |
| python/pyproject_xpu.toml | Intel XPU | sgl-kernel-xpu |
| python/pyproject_cpu.toml | Intel CPU (Xeon etc.) | sglang-kernel-cpu |
| python/pyproject_npu.toml | Ascend NPU | sgl-kernel-npu |

 
### Dependency Specification Highlights

 
 - The CUDA requisites specify PyCUDA and CUDA toolkit versions, plus compatible `flashinfer-python`, `nvidia-cutlass-dsl`, `humming-kernels`, and `sglang-kernel`.
 - ROCm configurations pin `torch`, `triton`, and `sglang-kernel` versions compatible with AMD devices and ROCm driver versions.
 - The XPU build includes `sgl-kernel-xpu`, `torch==2.13.0+xpu`, and Intel-specific libraries.
 - The CPU build optimizes dependencies for CPU execution and includes `intel-openmp` for x86 builds.
 - The NPU build relies on Ascend CANN libraries, `sgl-kernel-npu`, and additional runtime packages for integration with Huawei NPUs.

## CUDA Platform Support

 SGLang supports NVIDIA CUDA GPUs fully with runtime detection, kernel dispatch, and build configurations optimized for CUDA architectures.

 
 - **Detection**: The `is_cuda()` function detects CUDA availability by PyTorch's `torch.cuda.is_available()` and presence of `torch.version.cuda`.
 - **Kernel Support**: Uses the `sglang-kernel` Python wheel available on PyPI, built for multiple CUDA versions.
 - **Docker Support**: The base Docker image and build time install scripts include CUDA toolkit, CUDNN libraries, and NVIDIA drivers integration.
 - **Advanced Features**: Enables CUDA Graphs, Fast FP8 support (E4M3), and leverages CUTLASS for GEMM operations.
 
 With hardware detection, all CUDA-specific runtime helpers are routed to the CUDA kernels and memory allocators.

 Sources: [python/sglang/srt/utils/common.py149-153](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/utils/common.py#L149-L153), [python/pyproject.toml9-95](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject.toml#L9-L95), [docker/Dockerfile1-180](https://github.com/sgl-project/sglang/blob/94183a8d/docker/Dockerfile#L1-L180)

## ROCm (HIP) Platform Support

 ROCm platform support targets AMD GPUs with ROCm drivers, managed through HIP APIs.

 
 - **Detection**: `is_hip()` returns true if `torch.version.hip` exists indicating ROCm support.
 - **Dependencies**: Packages include `sglang-kernel` built for ROCm, compatible `torch` versions, and ROCm-specific PyTorch wheels (pinned in configs).
 - **Kernel Build**: ROCm kernel packages rely on ROCm 7.0+ toolchain.
 - **Docker Support**: ROCm compatible Docker images are built for AMD architectures.
 - **Features**: Includes support for flash attention, DeepEP, and other AMD-optimized kernels.
 
 Installation and CI steps adapt to ROCm by switching dependency sets accordingly.

 Sources: [python/sglang/srt/utils/common.py130-155](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/utils/common.py#L130-L155), [python/pyproject_other.toml69-90](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_other.toml#L69-L90), [3rdparty/amd/wheel/sglang/pyproject.toml1-100](https://github.com/sgl-project/sglang/blob/94183a8d/3rdparty/amd/wheel/sglang/pyproject.toml#L1-L100)

## Ascend NPU Platform Support

 SGLang supports Huawei Ascend NPUs via specific runtime patches, kernels, and optimized packages.

 
 - **Detection**: The `is_npu()` function confirms Ascend NPU presence by checking if `torch` has the `npu` attribute and if the device is available.
 - **Custom Kernels**: Uses `sgl-kernel-npu` and DeepEP for expert parallelism on NPU.
 - **Profiling Support**: Patches the PyTorch profiler to support NPU activities by overriding CUDA profiler hooks.
 - **Triton Kernel Backend**: Includes triton kernels for NPU (`triton-ascend`) to accelerate execution.
 - **Docker Environment**: The NPU Dockerfile installs Ascend CANN runtime, custom builds, and sets environment variables for NPU execution.
 - **Memory Fabric**: Supports special memory fabric modules (`memfabric-hybrid`, `memfabric-zbal`) for optimized memory management on NPU.

## Intel XPU Platform Support

 Intel XPU hardware support is integrated with specialized PyTorch builds and kernels.

 
 - **Detection**: `is_xpu()` checks PyTorch `torch.xpu.is_available()`.
 - **Packages**: Uses `python/pyproject_xpu.toml` specifying installation of `sgl-kernel-xpu` and Intel-specific libraries.
 - **Docker Setup**: Intel GPU runtime libraries and OpenCL drivers are installed in the `docker/xpu.Dockerfile`.
 - **Profiling**: Patches the profiler with XPU CUDA-analog activity enumeration for proper tracing.
 - **Kernel Builds**: The kernel package `sgl-kernel-xpu` is either installed from GitHub or built during Docker builds.

## Intel CPU Platform Support (Xeon)

 Support for Intel Xeon CPUs is provided with optimizations for AMX and CPU-tuned kernels.

 
 - **Detection**: `is_cpu()` checks environment variable `SGLANG_USE_CPU_ENGINE` and CPU architecture (x86 or ARM).
 - **Kernel Package**: Uses `sglang-kernel-cpu` with AMX support for efficient CPU matrix operations.
 - **Installation**: Declared in `python/pyproject_cpu.toml` with dependencies like `intel-openmp` for multi-threading.
 - **CI Checks**: The CI workflow ensures AMX support via `torch.cpu._is_amx_tile_supported()` and CPU kernel-related sanity checks.
 - **Build Environment**: The `docker/xeon.Dockerfile` configures a CPU-only execution environment with appropriate compiler flags.
 
 Sources: [python/sglang/srt/utils/common.py192-214](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/utils/common.py#L192-L214), [python/pyproject_cpu.toml19-74](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_cpu.toml#L19-L74), [.github/workflows/pr-test-xeon.yml120-130](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/pr-test-xeon.yml#L120-L130)

## Moore Threads GPU and Apple Silicon Platforms

 
 - **Moore Threads GPU (MUSA)**: Detected by `is_musa()` function which checks for presence of `torchada` and `torch.version.musa`. Requires `srt_musa` extra dependencies including `deep-gemm`, `flash_attn_3`, and `mthreads-ml-py`.
 - **Apple Silicon MPS and MLX**: Detected by `is_mps()` and by the presence of `mlx` library. Require `srt_mps` extra dependencies including `mlx`, `mlx-lm`, `torchcodec`, and `torchvision`.
 
 These are handled as optional extras in the ROCm/Other pyproject extensions.

# Further Notes

 
 - Runtime platform detection utilities (`sglang.srt.utils.common`) and build configurations (`python/*.toml`) together enable SGLang to dynamically select the appropriate runtime environment, install necessary dependencies, and dispatch to optimized kernel backends.
 - Dockerfiles organize platform-specific environment preparation, including system package installs, device drivers, and runtime libraries.
 - The hardware abstraction facilitates portability and efficient usage of multiple backend devices without manual user intervention.
