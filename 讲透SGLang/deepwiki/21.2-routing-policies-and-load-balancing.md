  The SGLang Model Gateway (SMG) employs a sophisticated routing subsystem designed to maximize cache hits while maintaining balanced load across backend workers. It supports various policies ranging from simple round-robin to complex cache-aware algorithms using approximate radix trees and consistent hashing.

 
## Overview of Routing Architecture

 Routing decisions in SMG are decoupled from the protocol handlers. Whether a request arrives via HTTP or gRPC, it eventually interacts with the `PolicyRegistry` to select an appropriate `Worker`.

 
### Core Entities

 
| Entity | Description |
|---|---|
| Worker | A trait representing a backend instance (SGLang, vLLM, etc.) tracked by the gateway sgl-model-gateway/src/core/worker.rs143 |
| WorkerRegistry | Manages the lifecycle and health of all workers, providing model-based indexing and consistent hash rings sgl-model-gateway/src/core/worker_registry.rs180-202 |
| LoadBalancingPolicy | Trait defining the select_worker interface for different routing strategies sgl-model-gateway/src/policies/mod.rs42-94 |
| PolicyRegistry | A central repository mapping model IDs to specific policy instances sgl-model-gateway/src/policies/registry.rs15-18 |
| WorkerRoutingKeyLoad | Tracks active routing keys per worker to prevent "hotspotting" on specific session IDs or prefixes sgl-model-gateway/src/core/worker.rs72-75 |
| CircuitBreaker | Protects workers by monitoring success/failure rates and opening the circuit if thresholds are exceeded sgl-model-gateway/src/core/circuit_breaker.rs103-116 |

## Cache-Aware Routing

 The `CacheAwarePolicy` is the flagship routing strategy in SGLang. It aims to route requests to workers that likely have the request's prefix in their KV cache without requiring real-time cache state queries from the backends [sgl-model-gateway/src/policies/cache_aware.rs4-7](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L4-L7)

 
### Implementation: Approximate Radix Tree

 The gateway maintains an internal `Tree` structure (an approximate radix tree) for each model [sgl-model-gateway/src/policies/cache_aware.rs21-23](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L21-L23) This tree stores raw text characters from previous requests to predict cache affinity [sgl-model-gateway/src/policies/tree.rs230-250](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/tree.rs#L230-L250)

 
 - **Prefix Matching**: When a request arrives, the policy performs a `prefix_match` against the trees of all available workers [sgl-model-gateway/src/policies/cache_aware.rs26](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L26-L26)
 - **Match Threshold**: If the highest match ratio exceeds the `cache_threshold` (default 0.3 in CLI), the request is routed to that worker [sgl-model-gateway/src/main.rs153-155](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/main.rs#L153-L155) [sgl-model-gateway/src/policies/cache_aware.rs41-43](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L41-L43)
 - **Fallback**: If no worker meets the threshold, the request is routed to the worker with the smallest tree size, indicating the most available cache capacity [sgl-model-gateway/src/policies/cache_aware.rs29-30](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L29-L30)
 - **Maintenance**: A background `PeriodicTask` performs LRU eviction on the trees based on `max_tree_size` to prevent memory exhaustion [sgl-model-gateway/src/policies/cache_aware.rs127-149](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L127-L149)
 - **Mesh Synchronization**: The policy supports cluster-wide synchronization of tree operations via `OptionalMeshSyncManager` [sgl-model-gateway/src/policies/cache_aware.rs160-165](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L160-L165)
 
 
### Load-Aware Switching

 To prevent "hotspotting" (where one worker gets all requests due to high cache hits), the policy monitors load imbalance. It switches from cache-aware routing to **Shortest Queue** routing if [sgl-model-gateway/src/policies/cache_aware.rs13-15](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L13-L15):

 
 - `(max_load - min_load) > balance_abs_threshold` (default 64 in CLI) [sgl-model-gateway/src/main.rs158-159](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/main.rs#L158-L159)
 - `max_load > balance_rel_threshold * min_load` (default 1.5 in CLI) [sgl-model-gateway/src/main.rs162-163](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/main.rs#L162-L163)

## Power-of-Two Selection (P2C)

 The `PowerOfTwoPolicy` implements the "Power of Two Choices" algorithm. Instead of scanning all workers or using simple Round Robin, it:

 
 - Randomly selects two workers from the available pool [sgl-model-gateway/src/policies/power_of_two.rs1-20](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/power_of_two.rs#L1-L20)
 - Compares their current `load()` (active request count) [sgl-model-gateway/src/core/worker.rs202](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker.rs#L202-L202)
 - Routes the request to the worker with the lower load.
 
 This provides a mathematically proven balance that is nearly as good as "Least Loaded" but with $O(1)$ complexity relative to the total number of workers.

## PD Routing (Prefill-Decode Disaggregation)

 In PD disaggregated mode, the `PDRouter` coordinates requests across two distinct tiers of workers: **Prefill** and **Decode** [sgl-model-gateway/src/routers/http/pd_router.rs50-57](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/pd_router.rs#L50-L57)

 
### Execution Flow

 
 - **Worker Selection**: The router selects a pair of workers. Prefill workers are selected using the configured `prefill_policy`, and Decode workers via `decode_policy` [sgl-model-gateway/src/routers/http/pd_router.rs84-87](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/pd_router.rs#L84-L87)
 - **KV Cache Transfer**: The gateway facilitates the transfer of KV cache from the Prefill worker to the Decode worker. This involves passing the `bootstrap_host` and `bootstrap_port` of the Prefill worker to the Decode worker's API [sgl-model-gateway/src/core/worker.rs158-166](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker.rs#L158-L166)
 - **Policy Isolation**: The `CacheAwarePolicy` uses a `pool_tag` to isolate prefill, decode, and regular worker pools in the cache tree key so they do not evict each other's tenants [sgl-model-gateway/src/policies/cache_aware.rs83-89](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L83-L89)
 - **Error Handling**: The `PDRouter` includes specialized logic to record prefill and decode breaker outcomes independently, ensuring failures are attributed to the correct stage [sgl-model-gateway/src/routers/http/pd_router.rs75-82](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/pd_router.rs#L75-L82)

## Multi-Model Inference Gateway (IGW) Mode

 When `enable_igw` is set to true, the gateway operates in multi-model mode, coordinating requests across workers serving different models [sgl-model-gateway/src/server.rs106-122](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L106-L122)

 
 - **Model Isolation**: The `WorkerRegistry` indexes workers by `model_id` using a `ModelIndex` (an `Arc<DashMap<String, Arc<[Arc<dyn Worker>]>>>`) for lock-free reads [sgl-model-gateway/src/core/worker_registry.rs173-186](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker_registry.rs#L173-L186)
 - **Consistent Hashing**: The registry maintains a `HashRing` per model using 150 virtual nodes per worker and `blake3` hashing for $O(\log n)$ lookup [sgl-model-gateway/src/core/worker_registry.rs31-48](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker_registry.rs#L31-L48)
 - **Service Discovery**: In Kubernetes environments, the gateway can automatically discover workers via label selectors and annotations [sgl-model-gateway/src/service_discovery.rs66](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/service_discovery.rs#L66-L66)

## Observability and String Interning

 To maintain high throughput, SMG uses a global string interner for metric labels like `model_id` and worker URLs. This avoids repeated heap allocations during metrics collection [sgl-model-gateway/src/observability/metrics.rs17-28](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/observability/metrics.rs#L17-L28)
