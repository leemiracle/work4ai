  This document describes the Python Engine API, which provides programmatic access to SGLang's inference capabilities. The `Engine` class offers synchronous and asynchronous methods for text generation, embeddings, and session management, enabling direct integration of SGLang into Python applications.

 
## Overview

 The `Engine` class is the primary entry point for using SGLang programmatically. It abstracts the multi-process architecture (TokenizerManager, Scheduler, DetokenizerManager) and provides a clean Python API for:

 
 - **Text Generation**: Synchronous and asynchronous completion generation via `generate` and `async_generate`.
 - **Embeddings**: Text encoding via `encode` and cross-encoder reranking via `rerank`.
 - **Session Management**: Multi-turn conversations with shared context using `open_session` and `close_session`.
 - **Advanced Features**: Cache management, LoRA adapters, weight updates, and performance profiling.

## Engine Architecture

 The `Engine` implementation bridges the gap between high-level Python calls and the underlying distributed runtime (SRT). It manages the lifecycle of worker processes and orchestrates communication between them.

 **Architecture Notes**:

 
 - **Process Model**: The `Engine`, `TokenizerManager`, and `TemplateManager` run in the main process, while the `Scheduler` and `Detokenizer` run in separate subprocesses [python/sglang/srt/entrypoints/engine.py212-215](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/engine.py#L212-L215).
 - **IPC**: Communication between the main process and worker processes is handled via ZMQ sockets using different ports defined in `PortArgs` [python/sglang/srt/entrypoints/engine.py111](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/engine.py#L111-L111), [python/sglang/srt/utils/network.py132](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/utils/network.py#L132-L132).

## Text Generation APIs

 
### generate() and async_generate()

 The engine provides both synchronous (`generate`) and asynchronous (`async_generate`) methods.

 **Method Signatures**:

 
 - `generate(...) -> Union[Dict, Iterator[Dict]]` [python/sglang/srt/entrypoints/engine.py315-403](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/engine.py#L315-L403)

 **Data Flow**:

 
 - Input (text, images, or token IDs) is wrapped into a `GenerateReqInput` object [python/sglang/srt/managers/io_struct.py68](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/io_struct.py#L68-L68).
 - The `TokenizerManager` tokenizes the prompt and assigns a request ID [python/sglang/srt/managers/tokenizer_manager.py15](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/tokenizer_manager.py#L15-L15).
 - If `stream=True`, an `AsyncIterator` (or `Iterator` for sync) yields partial results as they are detokenized [python/sglang/srt/entrypoints/engine.py392-400](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/engine.py#L392-L400).
