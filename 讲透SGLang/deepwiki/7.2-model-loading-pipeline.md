  This document describes the detailed model loading pipeline in SGLang, covering the end-to-end flow from model configuration loading to tokenizer/processor integration, remote weight loading, object storage access, and checkpoint engine integration. It explains how models are initialized and prepared for serving in the SRT runtime, with a focus on technical implementation, data flow, and key classes/functions.

 The pipeline is designed for:

 
 - Fetching and parsing model configurations from HuggingFace or local paths.
 - Loading tokenizers or processors (including multimodal processors) robustly.
 - Mapping model architecture names to implementation classes.
 - Instantiating models and loading weights efficiently from various sources.
 - Supporting advanced scenarios such as remote instance weight loading (R-Fork), RunAI object storage streams, and distributed checkpoint engines.
 
 
## Overview

 The model loading pipeline is triggered during the SRT server initialization or client model loading. It consists of four main logical phases:

 
 - **Configuration Phase** — Load HuggingFace configuration files and instantiate a `ModelConfig` object representing the model metadata and tuning parameters.
 - **Tokenizer/Processor Loading** — Load or build tokenizers and feature processors used for input encoding, including fallbacks and special cases like Mistral common tokenizers and multimodal processors.
 - **Architecture Discovery** — Determine the model implementation class based on the architecture name in the configuration via mapping functions.
 - **Model Instantiation and Weight Loading** — Create the model instance and load the weights into GPU/CPU memory, supporting multiple loading backends and formats.

## HuggingFace Configuration Loading

 SGLang relies on the HuggingFace transformers config system for model metadata, architecture information, and tokenizer hints.

 
### Config Loading Flow

 The core function `get_config()` (calls into HF's config and internal wrappers) fetches model config files from a HuggingFace Hub repo or local directory and constructs a `ModelConfig` instance that holds the raw HuggingFace config, text-specific config, and derived properties like context length and default dtype.

## Tokenizer and Processor Loading

 Tokenizers and processors convert natural language or multimodal inputs into tensors for the model.

 
### Loading Pipeline

 
 - `get_tokenizer()` attempts to load a tokenizer from a model path or repo.
 - The system first tries to load by the class declared in `tokenizer_config.json` via `_load_tokenizer_by_declared_class()`.
 - For Mistral models, `patch_mistral_common_tokenizer()` is used to handle specific requirements of the Mistral-common library.
 - Multimodal processors are handled via `get_processor()`, which can resolve to an `AutoProcessor` or specific multimodal implementations like `MmFamilyProcessor`.

## Weight Loading Pipeline

 The core of turning a model config and architecture into a runnable model is loading the model weights.

 
### Supported LoadFormats

 SGLang supports several `LoadFormat` enums for weight loading, adapting to different model weight packaging and backends:

 
| LoadFormat | Description |
|---|---|
| auto | Automatically detect safetensors, then fallback to PyTorch format. |
| safetensors | Load from safetensors files. |
| fastsafetensors | Optimized fastsafetensors loader using SafeTensorsFileLoader. |
| gguf | Load using llama.cpp compatible GGUF format. |
| dummy | Initialize with random dummy weights, useful for profiling. |
| npcache | Load PyTorch weights caching a numpy version for speedup. |
| remote_instance | Load weights from a remote running SGLang instance (R-Fork). |
| runai_streamer | Load weights from RunAI object storage streamer. |
| ipc_cache | Load weights using IPC shared memory cache. |

 Sources: [python/sglang/srt/configs/load_config.py17-39](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/configs/load_config.py#L17-L39) [python/sglang/srt/model_loader/weight_utils.py105-125](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_loader/weight_utils.py#L105-L125) [python/sglang/srt/model_loader/loader.py105-125](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_loader/loader.py#L105-L125)

 
### Weight Loading Flow

 
 - Use weight iterators specialized for the format: `safetensors_weights_iterator`, `pt_weights_iterator`, or `gguf_quant_weights_iterator`.
 - The iterators yield tensors lazily, avoiding loading entire weights into RAM.
 - The model's `load_weights()` method is called with these iterators to initialize model parameters.
 - `device_loading_context` is used to manage temporary GPU memory during loading, moving parameters back to CPU or pinned memory if necessary.

### Quantization Loading (Quark/MXFP4)

 SGLang supports advanced quantization loading, including online requantization to MXFP4 for Blackwell GPUs.

 
 - `QuarkLinearMethod` and `QuarkFusedMoEMethod` handle the loading logic for Quark-quantized models.
 - If the checkpoint is not already serialized in the target format (e.g., loading FP8 into MXFP4), the pipeline resolves target quant specs like `_MXFP4_TARGET_SPEC`.

## Remote Weight Loading (R-Fork)

 SGLang supports remote weight loading to enable multi-node or multi-instance weight sharing dynamically.

 
### Mechanism:

 
 - **R-Fork** stands for Tensor Remote Fork, a technique to share weights from a running instance.
 - The system uses a backend abstraction `RemoteInstanceWeightLoaderBackend` to transport weights.
 - Memory regions are registered for efficient transfers via `register_memory_region`.
 - The transfer is triggered through `trigger_transferring_weights_request` coordinating requests and data transfer across rank groups.

## Object Storage Loading

 SGLang integrates with object storage systems like RunAI to fetch models that reside remotely as URIs.

 
 - `set_runai_streamer_env` prepares the system for streaming model data.
 - Weights are tagged with `RUNAI_STREAMER_TENSOR_ATTR` to handle streaming-specific cloning logic during loading.
 - `is_runai_obj_uri` checks if the model path points to an object storage location, triggering `ObjectStorageModel` to resolve the local path.

## Checkpoint Engine and Weight Preprocessing

 SGLang includes utilities for prefetching and preparing checkpoints to minimize startup latency.

 
 - `_prefetch_all_checkpoints` warms the OS page cache by reading checkpoint files in the background.
 - `filter_files_not_needed_for_inference` removes non-essential files (e.g., optimizer states) from the loading queue.
 - `convert_bin_to_safetensor_file` provides a utility to convert legacy PyTorch bin files to the faster safetensors format.

# Summary

 The SGLang model loading pipeline is a multi-stage system designed for efficient ingestion of pretrained models. It leverages HuggingFace configuration standards, robust tokenizer loading paths, and versatile weight loading backends including R-Fork, object storage streaming, and optimized quantization loaders for Blackwell (MXFP4). The system ensures that weights are loaded with minimal memory overhead while supporting a wide array of distributed and quantized configurations.
