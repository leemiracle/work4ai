  The SGLang Model Gateway (SMG) utilizes a robust workflow engine to manage complex, multi-step operations such as worker registration, Model Context Protocol (MCP) server integration, and WebAssembly (WASM) module lifecycle management. This system is complemented by a WASM-based middleware layer and a high-performance request pipeline for model routing and transformation.

 
## Workflow Engine Architecture

 The gateway utilizes a "Workflow-as-a-Service" (WfaaS) model to handle asynchronous, long-running, or multi-stage tasks. This is primarily managed through the `WorkflowEngines` class and executed via the `JobQueue`.

 
### Core Components

 
 - **WorkflowEngines**: A container for specialized workflow definitions, including worker registration, tokenizer loading, and WASM module management [sgl-model-gateway/src/core/steps.rs31](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/steps.rs#L31-L31)
 - **JobQueue**: Manages the submission and status tracking of control plane operations using a dispatcher task with semaphore-based concurrency control [sgl-model-gateway/src/core/job_queue.rs30](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/job_queue.rs#L30-L30)
 - **WorkerManager**: Orchestrates health checks and engine metrics collection from the `WorkerRegistry` [sgl-model-gateway/src/server.rs155-158](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L155-L158)
 
 
### Worker Registration Workflows

 The registration process is a multi-stage workflow involving metadata discovery and validation:

 
 - **Metadata Discovery**: Fetches server and model information (e.g., `model_id`, `tp_size`) to populate `WorkerMetadata` [sgl-model-gateway/src/core/worker.rs159-166](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker.rs#L159-L166)
 - **Health Checking**: Probes the worker URL via `check_health_async` to determine availability [sgl-model-gateway/src/core/worker.rs175](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker.rs#L175-L175)
 - **Registry Integration**: Commits validated workers to the `WorkerRegistry`, which maintains model-based indexing and `HashRing` structures [sgl-model-gateway/src/core/worker_registry.rs180-190](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker_registry.rs#L180-L190)
 
 
### Tokenizer Registration Workflow

 The `TokenizerRegistry` serves as the single source of truth for tokenizers [sgl-model-gateway/src/server.rs67](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L67-L67) The workflow handles:

 
 - **Deduplication**: Ensures that multiple workers sharing the same model ID do not trigger redundant loads.
 - **Caching**: Optionally wraps tokenizers with a `CachedTokenizer` to speed up repeated requests [sgl-model-gateway/src/main.rs10](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/main.rs#L10-L10)
 - **Multi-model Support**: Managed via `TokenizerRegistry` to support Inference Gateway (IGW) mode [sgl-model-gateway/src/server.rs106-122](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L106-L122)

## WASM Middleware and Pipeline System

 The gateway integrates custom logic into the request/response pipeline using a WASM plugin system and a structured routing pipeline.

 
### Request Routing and Execution

 Requests flow through specialized routers depending on configuration, such as `PDRouter` for prefill-decode disaggregation [sgl-model-gateway/src/routers/http/pd_router.rs50-57](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/pd_router.rs#L50-L57) or `Router` for regular load balancing [sgl-model-gateway/src/routers/http/router.rs47-54](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/router.rs#L47-L54)

 
 - **Preparation**: Resolves the model and identifies if the request is streaming or non-streaming [sgl-model-gateway/src/server.rs172-182](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L172-L182)
 - **Worker Selection**: Uses `WorkerRegistry` and policies like `CacheAwarePolicy` or `PowerOfTwoPolicy` to pick a target worker [sgl-model-gateway/src/policies/cache_aware.rs111-116](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L111-L116) [sgl-model-gateway/src/main.rs149-152](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/main.rs#L149-L152)
 - **Execution**: Executes the call via `reqwest::Client` (HTTP) or `GrpcClient` (gRPC) [sgl-model-gateway/Cargo.toml50](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/Cargo.toml#L50-L50) [sgl-model-gateway/src/core/worker.rs23](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker.rs#L23-L23)
 - **Response Processing**: Handles streaming responses and tracks tokens via `TokenGuardBody` to manage rate limiting [sgl-model-gateway/src/middleware.rs52-69](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/middleware.rs#L52-L69)
 
 
### WASM Middleware Integration

 The gateway allows injecting WASM modules into the HTTP middleware stack using `wasmtime` [sgl-model-gateway/Cargo.toml129](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/Cargo.toml#L129-L129) These modules intercept requests and responses at specific `MiddlewareAttachPoint` locations [sgl-model-gateway/src/middleware.rs37-46](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/middleware.rs#L37-L46)

 
 - **WasmModuleAttachPoint**: Defines where a module runs (e.g., `PreAuth`, `PostAuth`, `PreRouting`, `PostRouting`) [sgl-model-gateway/src/middleware.rs38](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/middleware.rs#L38-L38)
 - **WasmComponentInput**: Provides the WASM environment with access to request headers and body data [sgl-model-gateway/src/middleware.rs45](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/middleware.rs#L45-L45)
 - **Management Routes**: Modules are managed via dedicated API endpoints like `add_wasm_module`, `list_wasm_modules`, and `remove_wasm_module` [sgl-model-gateway/src/server.rs68](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L68-L68)

## MCP Integration and Service Discovery

 The gateway serves as a high-performance model routing gateway with integrated service discovery and tool support via the Model Context Protocol (MCP).

 
### Service Discovery

 The `start_service_discovery` function monitors infrastructure (like Kubernetes Pods) to dynamically update the worker pool [sgl-model-gateway/src/server.rs66](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L66-L66)

 
 - **Discovery Backends**: Supports Kubernetes-based discovery via the `kube` crate [sgl-model-gateway/Cargo.toml69-70](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/Cargo.toml#L69-L70)
 - **WorkerType Support**: Supports `Prefill`, `Decode`, and `Regular` types for PD-disaggregation [sgl-model-gateway/src/server.rs106-117](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L106-L117)
 
 
### MCP (Model Context Protocol)

 The gateway manages external tool providers via integrated MCP support using `rmcp` and `smg-mcp` [sgl-model-gateway/Cargo.toml89](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/Cargo.toml#L89-L89) [sgl-model-gateway/Cargo.toml95-102](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/Cargo.toml#L95-L102)

 
 - **Tool Parsing**: Uses the `tool-parser` crate to parse tool calls from model outputs [sgl-model-gateway/Cargo.toml84](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/Cargo.toml#L84-L84)
 - **Reasoning Extraction**: Specialized parsers like `reasoning-parser` separate chain-of-thought from final responses [sgl-model-gateway/Cargo.toml82](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/Cargo.toml#L82-L82)
 
 
### Conversation Connectors and History

 The gateway centralizes chat history and provides detailed metrics for the entire workflow.

 
 - **History Backends**: Supports multiple backends including `Memory`, `Oracle`, `Postgres`, and `Redis` [sgl-model-gateway/bindings/python/src/lib.rs30-36](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/bindings/python/src/lib.rs#L30-L36)
 - **Connectors**: Managed via `data-connector` to enable state persistence across model loops [sgl-model-gateway/Cargo.toml88](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/Cargo.toml#L88-L88)
 - **Observability**: Uses `intern_string` for high-throughput metric label management to avoid repeated allocations [sgl-model-gateway/src/observability/metrics.rs35-47](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/observability/metrics.rs#L35-L47)
