  The SGLang frontend language is a domain-specific language (DSL) designed for composing LLM programs with complex control flow, multi-modal inputs, and structured outputs. It uses an Intermediate Representation (IR) to define operations and an interpreter (the `StreamExecutor`) to manage the execution of these operations across various backends.

 
## Intermediate Representation (IR) Primitives

 SGLang defines its program structure through a set of IR classes that represent the fundamental building blocks of an LLM prompt and response lifecycle. These are defined primarily in `python/sglang/lang/ir.py`.

 
### Core IR Primitives

 
| Class | Description |
|---|---|
| SglGen | Represents a generation operation where the model completes the current prompt python/sglang/lang/ir.py534-558 |
| SglSelect | Represents a selection from a predefined list of choices python/sglang/lang/ir.py612-623 |
| SglImage | Represents the insertion of an image into the prompt python/sglang/lang/ir.py643 |
| SglVideo | Represents the insertion of a video into the prompt python/sglang/lang/ir.py643 |
| SglVariable | Represents a reference to a previously generated value python/sglang/lang/ir.py515-519 |
| SglRoleBegin/End | Defines the boundaries for chat roles (system, user, assistant) python/sglang/lang/ir.py643 |

 
### Interpreter Execution Model

 The `StreamExecutor` is the core interpreter that executes an `SglFunction` [python/sglang/lang/interpreter.py71-79](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/interpreter.py#L71-L79) It maintains the current state of the prompt (`text_`), collected multi-modal data, and generated variables [python/sglang/lang/interpreter.py80](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/interpreter.py#L80-L80)

 When a program is run via `run_program`, the interpreter can execute in a blocking fashion or as a background thread for streaming [python/sglang/lang/interpreter.py82-90](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/interpreter.py#L82-L90) Program states can be executed in batches using `run_program_batch`, which supports multi-threaded execution and prefix caching via program tracing [python/sglang/lang/interpreter.py93-108](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/interpreter.py#L93-L108)

## Program Composition and Parallelism

 SGLang allows for complex program composition using standard Python control flow (if/else, loops) and explicit parallelism via `fork`.

 
### Fork and Program State

 The `fork` primitive creates multiple copies of the current `StreamExecutor` state [python/sglang/lang/interpreter.py1098](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/interpreter.py#L1098-L1098) This allows the model to explore different generation paths in parallel. Because generation calls are non-blocking within the interpreter's thread model, multiple `gen` calls following a `fork` can be issued to the backend simultaneously.

 
### Program State Management

 The `ProgramState` object stores the results of the execution, including any variables captured by `gen(name="...")` [python/sglang/lang/interpreter.py80](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/interpreter.py#L80-L80) Users can access these variables directly from the state object after the function execution. The `ProgramState.text()` method provides the full accumulated prompt and generated text [python/sglang/lang/interpreter.py80](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/interpreter.py#L80-L80)

## Multi-Modal and Reasoning Support

 
### Multi-Modal Inputs

 The IR supports `SglImage` and `SglVideo`. When the interpreter encounters these:

 
 - It handles the data insertion into the stream [python/sglang/lang/interpreter.py1098](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/interpreter.py#L1098-L1098)
 - The `StreamExecutor` tracks multi-modal data for the next generation call [python/sglang/lang/interpreter.py1098](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/interpreter.py#L1098-L1098)
 - Backends like `RuntimeEndpoint` include these in the payload to the server via `_add_images` [python/sglang/lang/backend/runtime_endpoint.py107-118](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/backend/runtime_endpoint.py#L107-L118)
 
 
### Chat Templates

 SGLang uses a `ChatTemplate` system to format messages for different model families. The `ChatTemplate` registry stores role prefixes and suffixes [python/sglang/lang/chat_template.py57-62](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/chat_template.py#L57-L62) The interpreter uses these templates to wrap content when `SglRoleBegin` and `SglRoleEnd` are used [python/sglang/lang/chat_template.py43-54](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/chat_template.py#L43-L54) The `RuntimeEndpoint` backend automatically selects the template based on the model path [python/sglang/lang/backend/runtime_endpoint.py52-54](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/backend/runtime_endpoint.py#L52-L54)

 
### Constrained Decoding

 The `gen` primitive supports `regex` and `dtype` to enforce structural constraints on the output [python/sglang/lang/ir.py36-40](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/ir.py#L36-L40) The `RuntimeEndpoint` backend handles the mapping of high-level types (like `int`, `float`, `bool`) to specific regex patterns via `_handle_dtype_to_regex` before sending the request to the server [python/sglang/lang/backend/runtime_endpoint.py127-157](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/backend/runtime_endpoint.py#L127-L157)

## Execution Backends

 The Frontend Language supports multiple backends through the `BaseBackend` interface.

 
### RuntimeEndpoint

 The `RuntimeEndpoint` connects to a running SGLang SRT server. It performs model info discovery via `/get_model_info` [python/sglang/lang/backend/runtime_endpoint.py41-47](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/backend/runtime_endpoint.py#L41-L47) It supports both blocking `generate` [python/sglang/lang/backend/runtime_endpoint.py159-196](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/backend/runtime_endpoint.py#L159-L196) and streaming `generate_stream` [python/sglang/lang/backend/runtime_endpoint.py198-232](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/lang/backend/runtime_endpoint.py#L198-L232) calls.

 Key methods include:

## Optimization and Kernel Integration

 While the DSL manages program flow, the underlying interpreter interacts with a runtime that utilizes highly optimized kernels for execution.

 
### Kernel Dispatch and JIT

 SGLang uses a combination of Just-In-Time (JIT) and Ahead-Of-Time (AOT) kernels. Lightweight kernels like element-wise activations are often implemented as JIT kernels for rapid iteration [.claude/skills/add-jit-kernel/SKILL.md20-22](https://github.com/sgl-project/sglang/blob/94183a8d/.claude/skills/add-jit-kernel/SKILL.md?plain=1#L20-L22) Heavier operations involving CUTLASS or DeepGEMM are handled AOT [.claude/skills/add-sgl-kernel/SKILL.md21-23](https://github.com/sgl-project/sglang/blob/94183a8d/.claude/skills/add-sgl-kernel/SKILL.md?plain=1#L21-L23)

 
### Fused Operations

 The runtime employs fused operators for efficiency. For example, `SiluAndMul` is a common activation pattern used in SwiGLU layers, with platform-specific implementations for CUDA, NPU, and XPU [python/sglang/srt/layers/activation.py130-185](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/activation.py#L130-L185) These kernels are often dispatched dynamically based on the hardware capability and tensor alignment [python/sglang/srt/layers/activation.py85-96](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/activation.py#L85-L96)
