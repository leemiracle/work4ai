  The SGLang Model Gateway (SMG) is a high-performance, Rust-based control plane and data plane designed to manage clusters of inference workers. It orchestrates fleets of workers, balances traffic across HTTP and gRPC backends, and exposes OpenAI-compatible APIs while remaining deeply optimized for the SGLang serving runtime [sgl-model-gateway/README.md1-4](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/README.md?plain=1#L1-L4) It supports both regular inference and Prefill-Decode (PD) disaggregated execution modes [sgl-model-gateway/src/main.rs98-114](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/main.rs#L98-L114)

 
## Gateway Control Plane

 The gateway acts as the entry point for all client requests, abstracting the underlying worker pool. It maintains the `AppContext`, which serves as the central state container for the registry, policies, and configuration [sgl-model-gateway/src/app_context.rs18-30](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/app_context.rs#L18-L30)

 
### Data Flow and Request Handling

 Requests enter through an `axum` server [sgl-model-gateway/src/server.rs9-15](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L9-L15) Depending on the configuration, requests are handled by the `RouterManager` and routed through a `RouterTrait` implementation (e.g., `Router` for regular mode or `PDRouter` for PD mode) [sgl-model-gateway/src/server.rs71-78](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L71-L78)

 
 - **Entry**: Requests arrive at endpoints like `/v1/chat/completions` or `/v1/generate` [sgl-model-gateway/src/server.rs172-193](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L172-L193)
 - **Validation**: Authentication is performed via `auth_middleware`, which validates Bearer tokens using constant-time comparison to prevent timing attacks [sgl-model-gateway/src/middleware.rs114-148](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/middleware.rs#L114-L148)
 - **Job Queueing**: The gateway can utilize a `JobQueue` to manage concurrency and buffer requests during spikes [sgl-model-gateway/src/server.rs30-36](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/server.rs#L30-L36)
 - **Selection**: The router queries the `WorkerRegistry` to find available workers. The `select_worker_for_model` function filters workers by `model_id`, `WorkerType`, and `ConnectionMode` [sgl-model-gateway/src/routers/http/router.rs133-148](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/router.rs#L133-L148)
 - **Execution**: The request is proxied to the selected worker using a `reqwest::Client` [sgl-model-gateway/src/routers/http/router.rs103-126](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/router.rs#L103-L126)

## Worker Registry and Management

 The `WorkerRegistry` is the central repository for all backend inference nodes. It provides lookups for workers by ID and model indexing.

 
### Performance Optimizations

 The `WorkerRegistry` uses several techniques for high-concurrency performance:

 
 - **Lock-Free Reads**: The model index uses immutable `Arc` snapshots instead of `RwLock` to allow lock-free reads during high-concurrency request spikes [sgl-model-gateway/src/core/worker_registry.rs5-12](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker_registry.rs#L5-L12)
 - **Consistent Hash Ring**: The registry maintains a pre-computed `HashRing` per model for $O(\log n)$ worker selection [sgl-model-gateway/src/core/worker_registry.rs188-190](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker_registry.rs#L188-L190) It uses 150 virtual nodes per worker and `blake3` for stable hashing [sgl-model-gateway/src/core/worker_registry.rs29-41](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker_registry.rs#L29-L41)
 
 
### Worker Health and Circuit Breakers

 
 - **Health Checks**: The `Worker` trait defines `check_health_async` to perform periodic liveness probes [sgl-model-gateway/src/core/worker.rs175-180](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker.rs#L175-L180)
 - **Circuit Breakers**: Implemented using lock-free atomics for hot paths [sgl-model-gateway/src/core/circuit_breaker.rs98-105](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/circuit_breaker.rs#L98-L105) It tracks `consecutive_failures` and transitions between `Closed`, `Open`, and `HalfOpen` states [sgl-model-gateway/src/core/circuit_breaker.rs40-48](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/circuit_breaker.rs#L40-L48)
 - **Load Tracking**: Workers track active requests via `increment_load` and `decrement_load` [sgl-model-gateway/src/core/worker.rs205-208](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker.rs#L205-L208) They also track specific routing key loads to support session affinity via `WorkerRoutingKeyLoad` [sgl-model-gateway/src/core/worker.rs72-130](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker.rs#L72-L130)

## Routing Policies and Load Balancing

 The `PolicyRegistry` manages various `LoadBalancingPolicy` implementations that determine how requests are distributed across healthy workers [sgl-model-gateway/src/policies/registry.rs1-15](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/registry.rs#L1-L15)

 
### Cache-Aware Routing

 The `CacheAwarePolicy` optimizes for KV cache reuse by maintaining an approximate radix tree of request history [sgl-model-gateway/src/policies/cache_aware.rs19-23](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L19-L23)

 
 - **Approximate Tree**: Stores raw text characters in a `Tree` structure instead of token IDs to avoid tokenization overhead [sgl-model-gateway/src/policies/cache_aware.rs21-23](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L21-L23) The `Tree` uses `NodeText` to store text and its character count efficiently [sgl-model-gateway/src/policies/tree.rs126-132](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/tree.rs#L126-L132)
 - **Imbalance Detection**: The policy switches from cache-aware routing to shortest-queue load balancing if the system is detected to be imbalanced (e.g., `(max_load - min_load) > abs_threshold`) [sgl-model-gateway/src/policies/cache_aware.rs13-16](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L13-L16)
 - **LRU Eviction**: A background task periodically evicts least recently used nodes from the tree to bound memory usage [sgl-model-gateway/src/policies/cache_aware.rs127-149](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L127-L149) This eviction uses a global `EPOCH_COUNTER` for efficient LRU ordering [sgl-model-gateway/src/policies/tree.rs218-227](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/tree.rs#L218-L227)

## Service Discovery and Observability

 
### Kubernetes Integration

 The gateway includes logic for service discovery via the Kubernetes API, monitoring `Pod` resources to dynamically update the `WorkerRegistry` [sgl-model-gateway/src/service_discovery.rs206-224](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/service_discovery.rs#L206-L224) It uses selectors and annotations to identify prefill and decode workers in disaggregated setups [sgl-model-gateway/src/service_discovery.rs145-160](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/service_discovery.rs#L145-L160)

 
### Metrics Infrastructure

 SMG uses a high-performance metrics system with string interning to avoid allocations in the hot path [sgl-model-gateway/src/observability/metrics.rs16-25](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/observability/metrics.rs#L16-L25)

 
 - **String Interning**: Uses a `DashMap` named `STRING_INTERNER` and `Arc<str>` to reuse labels like `model_id` and `worker_url` [sgl-model-gateway/src/observability/metrics.rs26-47](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/observability/metrics.rs#L26-L47)
 - **Layered Metrics**: Tracks HTTP-level metrics (e.g., `smg_http_requests_total`), Router-level metrics (e.g., `smg_router_request_errors_total`), and Worker-level metrics [sgl-model-gateway/src/observability/metrics.rs149-210](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/observability/metrics.rs#L149-L210)
 
 
### Middleware Pipeline

 The gateway implements a sophisticated middleware stack using `tower` layers:

 
 - **Request ID**: Generates OpenAI-compatible request IDs (e.g., `chatcmpl-...`) via `generate_request_id` [sgl-model-gateway/src/middleware.rs154-178](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/middleware.rs#L154-L178)
 - **Token Guard**: A `TokenGuardBody` wrapper ensures that rate-limiting tokens are only returned to the `TokenBucket` after a streaming response is fully consumed or dropped [sgl-model-gateway/src/middleware.rs52-82](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/middleware.rs#L52-L82)
 - **WASM Middleware**: Supports dynamic request/response modification via WebAssembly plugins attached at points like `MiddlewareAttachPoint` [sgl-model-gateway/src/middleware.rs37-47](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/middleware.rs#L37-L47)
