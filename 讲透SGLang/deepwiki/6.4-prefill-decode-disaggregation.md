## Purpose and Scope

 This document details the **Prefill-Decode (PD) Disaggregation** architecture in SGLang, which separates Transformer-based inference workloads into dedicated prefill and decode server instances. This split enables independent and specialized optimization of both the computation-heavy **prefill** stage (processing input tokens to fill the KV cache) and the memory-sensitive **decode** stage (incrementally generating new tokens). Prefill-Decode disaggregation thus avoids performance interference suffered by unified scheduling, particularly addressing:

 
 - **Prefill Interruption**: Where incoming new requests can delay or block ongoing decode sequences due to shared batch resources.
 - **Data Parallel (DP) Attention Imbalance**: Synchronization stalls arising from DP workers processing heterogeneous pipeline stages (prefill vs decode) asynchronously.
 
 This page describes the disaggregation architecture, the bootstrap server handshake protocol, the KV cache transfer mechanisms, the request lifecycle coordination on both prefill and decode sides, specialized EPD disaggregation supporting Vision-Language Models (VLMs), and the PD-Multiplexing feature.

## High-Level Architecture

 Prefill-Decode disaggregation partitions the end-to-end generation pipeline into:

 
 - **Prefill Servers**: Process input token sequences, run full forward passes to populate KV cache, manage KV cache metadata, and push KV cache contents via `KVSender` [python/sglang/srt/disaggregation/base/conn.py119](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/base/conn.py#L119-L119)
 - **Decode Servers**: Engage for incremental token generation, pulling KV caches provided by prefill servers via `KVReceiver` [python/sglang/srt/disaggregation/base/conn.py188](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/base/conn.py#L188-L188) managing decode-specific caches, and producing output tokens.
 - **Bootstrap Server**: Coordinates address and topology discovery between prefill and decode processes via `BaseKVBootstrapServer` [python/sglang/srt/disaggregation/base/conn.py20](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/base/conn.py#L20-L20) mediating initial handshake and connectivity.
 
 Communication between the two roles occurs over a dedicated **KV cache transfer layer**, optimized with RDMA, NVLink, UCX, or QP-based RDMA depending on the selected `TransferBackend` [python/sglang/srt/disaggregation/utils.py45](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/utils.py#L45-L45)

## Prefill Server Request Lifecycle

 The Prefill server manages requests through `PrefillBootstrapQueue` [python/sglang/srt/disaggregation/prefill.py119](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/prefill.py#L119-L119) execution, and inflight phases.

 
 - **Bootstrap Queue**: Initializes a sender for each request and polls for handshake completion [python/sglang/srt/disaggregation/prefill.py4-9](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/prefill.py#L4-L9)
 - **Waiting Queue**: Popped by `PrefillAdder` to run the model forward pass [python/sglang/srt/disaggregation/prefill.py10-14](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/prefill.py#L10-L14)
 - **Inflight Queue**: Polls (non-blocking) the `CommonKVSender` [python/sglang/srt/disaggregation/common/conn.py:23] until the transfer to the decode node finishes [python/sglang/srt/disaggregation/prefill.py15-18](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/prefill.py#L15-L18)

## Decode Server Request Lifecycle

 The Decode server processes requests through specialized queues to decouple transfer from execution:

 
 - **PreallocQueue**: Handshakes with the prefill node and pre-allocates KV slots once memory is available [python/sglang/srt/disaggregation/decode.py4-8](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/decode.py#L4-L8)
 - **TransferQueue**: Polls the `CommonKVReceiver` [python/sglang/srt/disaggregation/common/conn.py:22] to check transfer state [python/sglang/srt/disaggregation/decode.py9-12](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/decode.py#L9-L12)
 - **WaitingQueue**: Constructs a `PrebuiltExtendBatch` to skip prefill computation but populate necessary metadata [python/sglang/srt/disaggregation/decode.py13-16](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/decode.py#L13-L16)
 - **RunningBatch**: Merges resolved requests into the active decoding batch [python/sglang/srt/disaggregation/decode.py17-19](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/decode.py#L17-L19)

## Pipeline Parallelism and Consensus

 SGLang supports running disaggregated roles across complex pipeline-parallel topologies:

 
 - **Pipeline Parallelism (PP)**: The `SchedulerPPMixin` [python/sglang/srt/managers/scheduler_pp_mixin.py72](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/scheduler_pp_mixin.py#L72-L72) manages the `event_loop_pp` [python/sglang/srt/managers/scheduler_pp_mixin.py74](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/scheduler_pp_mixin.py#L74-L74) In disaggregated mode, it coordinates `recv_requests` [python/sglang/srt/managers/scheduler_pp_mixin.py107](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/scheduler_pp_mixin.py#L107-L107) and `_pp_launch_batch` [python/sglang/srt/managers/scheduler_pp_mixin.py140](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/scheduler_pp_mixin.py#L140-L140) across stages while maintaining KV transfer readiness.
 - **Consensus**: `poll_and_all_reduce_pp` [python/sglang/srt/disaggregation/utils.py52-67](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/utils.py#L52-L67) maps authoritative PP consensus to poll states, ensuring all stages agree on request completion.
 - **Unified Memory Gate**: The `unified_memory_disagg_move_gate` [python/sglang/srt/disaggregation/utils.py115-156](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/utils.py#L115-L156) prevents memory compaction from relocating pages while RDMA engines are active.
