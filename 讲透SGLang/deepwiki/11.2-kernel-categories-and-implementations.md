  This page documents the comprehensive kernel library (`sgl-kernel`) and the JIT kernel infrastructure that powers SGLang's high-performance inference. The library contains optimized CUDA and HIP kernels organized into functional categories, covering matrix operations, attention mechanisms, quantization, MoE routing, and more. These kernels are either pre-compiled (AOT) or compiled on-the-fly (JIT) to enable architecture-specific optimizations (e.g., SM90 vs SM100+ GPUs).

 
---

 
## Kernel Organization Overview

 SGLang employs a dual-path kernel strategy: **AOT (`sgl-kernel`)** for heavyweight dependencies like CUTLASS, and **JIT (`jit_kernel`)** for lightweight, rapidly iterating operations.

## 1. GEMM (General Matrix Multiply) Kernels

 The GEMM category implements highly optimized matrix multiplication kernels. SGLang supports standard formats and specialized Blackwell (SM100) kernels.

 
### DeepGEMM and SM100 Support

 SGLang integrates **DeepGEMM** for high-performance JIT-compiled GEMMs on NVIDIA GPUs.

 
 - **Warmup and Pre-compilation**: DeepGEMM kernels are pre-compiled during server launch to avoid latency spikes during serving [python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py122-155](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py#L122-L155). The `compile_deep_gemm` utility facilitates this by launching a temporary server to capture required shapes [python/sglang/compile_deep_gemm.py4-10](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/compile_deep_gemm.py#L4-L10).
 - **M-List Sampling**: In fast warmup mode, SGLang samples a representative set of batch sizes (M) to reduce compilation time while ensuring coverage [python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py61-87](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py#L61-L87).
 - **JIT Configuration**: The system allows forcing NVCC over NVRTC for 9x faster JIT speeds and better performance [python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py48-51](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/deep_gemm_wrapper/compile_utils.py#L48-L51).

## 2. Quantization and Activation Kernels

 Quantization kernels prepare tensors for efficient execution, often fusing activation functions.

 
### Per-Token Group Quantization

 SGLang provides optimized JIT kernels for per-token group quantization (`sgl_per_token_group_quant_8bit`).

 
 - **Features**: Supports FP8 (E4M3) and INT8 quantization [python/sglang/kernels/jit/csrc/gemm/per_token_group_quant.cuh43-75](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/kernels/jit/csrc/gemm/per_token_group_quant.cuh#L43-L75).
 - **Scaling**: Implements both standard FP32 scales and Blackwell-optimized **UE8M0** (unsigned exponent 8-bit mantissa) scales [python/sglang/kernels/jit/csrc/gemm/per_token_group_quant.cuh77-83](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/kernels/jit/csrc/gemm/per_token_group_quant.cuh#L77-L83).
 - **Alignment**: Handles unaligned group sizes by zero-filling pack-tail bytes in 4-aligned buffers [python/sglang/kernels/jit/csrc/gemm/per_token_group_quant.cuh140-153](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/kernels/jit/csrc/gemm/per_token_group_quant.cuh#L140-L153).
 
 
### Activation Function Implementations

 Activation functions like `SiluAndMul` are implemented with platform-specific dispatch:

 
 - **CUDA**: Dispatches to JIT-compiled `_jit_silu_and_mul` if the hidden size is vector-aligned (16B or 32B), otherwise falls back to the AOT `_sgl_silu_and_mul` [python/sglang/srt/layers/activation.py85-99](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/activation.py#L85-L99).
 - **NPU**: Uses `torch_npu.npu_swiglu` [python/sglang/srt/layers/activation.py166-168](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/activation.py#L166-L168).
 - **ROCm/HIP**: Supports `aiter` backend for SiLU fusion [python/sglang/srt/layers/activation.py152-157](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/activation.py#L152-L157).
 - **CPU**: Includes AMX-optimized kernels [python/sglang/srt/layers/activation.py159-162](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/activation.py#L159-L162).

## 3. Mixture of Experts (MoE) Fused Kernels

 MoE execution involves complex routing, permutation, and grouped GEMM operations.

 
### Fused MoE Backends

 SGLang supports multiple backends for MoE execution, selected based on hardware and quantization:

 
 - **DeepEP**: High-performance all-to-all communication and token dispatch backend. It manages process-wide buffers and supports Low Latency (LL) dispatch modes [python/sglang/srt/layers/moe/token_dispatcher/deepep.py175-207](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/token_dispatcher/deepep.py#L175-L207).
 - **CUTLASS FP8**: Implements `cutlass_fused_experts_fp8`, a SwiGLU-fused MoE layer using grouped matrix multiplication with per-block scales [python/sglang/srt/layers/moe/cutlass_moe.py27-52](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/cutlass_moe.py#L27-L52).
 - **CUTLASS W4A8**: Implements `cutlass_w4a8_moe`, supporting int4-quantized weights with int8-quantized activations [python/sglang/srt/layers/moe/cutlass_w4a8_moe.py44-107](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/cutlass_w4a8_moe.py#L44-L107).
 
 
### Token Dispatch and Routing

 
 - **DeepEP Dispatch**: Handles `DEEPEP_NORMAL` and `DEEPEP_LL` (Low Latency) output formats, managing the number of received tokens per expert [python/sglang/srt/layers/moe/token_dispatcher/deepep.py109-137](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/token_dispatcher/deepep.py#L109-L137).
 - **Permutation**: `deepep_permute_triton_kernel` and `deepep_post_reorder_triton_kernel` are used to reorder tokens for efficient expert computation [python/sglang/srt/layers/moe/cutlass_w4a8_moe.py28-32](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/cutlass_w4a8_moe.py#L28-L32).

### JIT Kernel Infrastructure

 JIT kernels in SGLang leverage a set of device-side abstractions in `sgl_kernel/` to ensure safety and performance:

 
 - **`Vec32B`**: A packed vector abstraction for 32-byte memory operations (e.g., loading 16 BF16 elements) [python/sglang/kernels/jit/csrc/gemm/per_token_group_quant.cuh157-177](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/kernels/jit/csrc/gemm/per_token_group_quant.cuh#L157-L177).
 - **`ScaleStoreArgs`**: A unified accessor for scale tensors that handles row-major, col-major, and packed UE8M0 layouts [python/sglang/kernels/jit/csrc/gemm/per_token_group_quant.cuh84-138](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/kernels/jit/csrc/gemm/per_token_group_quant.cuh#L84-L138).
 - **`LaunchKernel`**: A host-side utility that automatically resolves CUDA streams from TVM-FFI and provides RAII error checking [.claude/skills/add-jit-kernel/SKILL.md68-71](https://github.com/sgl-project/sglang/blob/94183a8d/.claude/skills/add-jit-kernel/SKILL.md?plain=1#L68-L71).
