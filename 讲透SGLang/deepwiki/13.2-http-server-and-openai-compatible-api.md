  This page documents the HTTP server implementation and OpenAI-compatible API endpoints in SGLang. The server provides REST APIs for inference requests and integrates with the `Engine` to coordinate request processing across `TokenizerManager`, `Scheduler`, and worker processes.

 For information about the Engine Python API and internal request processing, see [Python Engine API](https://github.com/sgl-project/sglang/blob/94183a8d/Python Engine API) For chat template formatting, see [Chat Templates and Conversation Formatting](https://github.com/sgl-project/sglang/blob/94183a8d/Chat Templates and Conversation Formatting)

 
## Overview

 The HTTP server is implemented using FastAPI and serves as the primary external interface for SGLang [python/sglang/srt/entrypoints/http_server.py49-60](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/http_server.py#L49-L60) It provides:

 
 - **OpenAI-compatible** `/v1/chat/completions`, `/v1/completions`, and `/v1/embeddings` endpoints [python/sglang/srt/entrypoints/http_server.py87-100](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/http_server.py#L87-L100)
 - **Anthropic Claude API** compatibility via `/v1/messages` and specialized protocol handling [python/sglang/srt/entrypoints/http_server.py70-74](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/http_server.py#L70-L74)
 - **Ollama API** compatibility for generate and chat endpoints [python/sglang/srt/entrypoints/http_server.py81-86](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/http_server.py#L81-L86)
 - **Reasoning model support** (e.g., DeepSeek-R1) via specialized `ReasoningParser` which handles reasoning tags like `<think>` [python/sglang/srt/parser/reasoning_parser.py71](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/parser/reasoning_parser.py#L71-L71) [python/sglang/srt/entrypoints/openai/serving_chat.py93](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_chat.py#L93-L93)
 - **Advanced tool use** and function calling capabilities via `FunctionCallParser` [python/sglang/srt/function_call/function_call_parser.py60](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/function_call/function_call_parser.py#L60-L60)
 - **OpenAI Responses API** support via `/v1/responses` for advanced conversation management [python/sglang/srt/entrypoints/http_server.py96](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/http_server.py#L96-L96)
 
 The server runs in the main process and communicates with the `TokenizerManager` (or `MultiTokenizerRouter` in multi-process mode) which orchestrates request processing across backend processes using ZMQ IPC [python/sglang/srt/entrypoints/http_server.py199-204](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/http_server.py#L199-L204) [python/sglang/srt/managers/tokenizer_manager.py44-46](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/tokenizer_manager.py#L44-L46)

### Request Routing

 The FastAPI application routes requests to specialized serving classes based on the endpoint. These classes translate external protocol models into internal SGLang structures.

 
| Endpoint Pattern | Serving Class | Purpose |
|---|---|---|
| /v1/chat/completions | OpenAIServingChat | Chat-style completions with message history python/sglang/srt/entrypoints/http_server.py88 |
| /v1/completions | OpenAIServingCompletion | Raw text completions python/sglang/srt/entrypoints/http_server.py90 |
| /v1/embeddings | OpenAIServingEmbedding | Text embeddings generation python/sglang/srt/entrypoints/http_server.py92 |
| /v1/rerank | OpenAIServingRerank | Reranking queries against documents python/sglang/srt/entrypoints/http_server.py99 |
| /v1/messages | AnthropicServing | Anthropic-style message interface python/sglang/srt/entrypoints/http_server.py74 |
| /api/chat | OllamaServing | Ollama-compatible chat endpoint python/sglang/srt/entrypoints/http_server.py86 |

## OpenAI-Compatible Endpoints

 
### Chat Completions Endpoint

 The `/v1/chat/completions` endpoint implements OpenAI's chat completion API. It supports complex features like:

 
 - **Thinking Mode**: Support for models that output reasoning before final answers (e.g., DeepSeek-R1) via `ThinkingMode` [python/sglang/srt/entrypoints/openai/serving_chat.py14-19](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_chat.py#L14-L19)
 - **Tool Calling**: Automated detection and parsing of tool calls. SGLang supports `ToolStrictLevel` for varying levels of validation strictness [python/sglang/srt/environ.py212-224](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/environ.py#L212-L224)
 - **JSON Constraints**: Enforcement of JSON schemas on model output via `xgrammar` or `llguidance` integrated into `SamplingParams` [python/sglang/srt/sampling/sampling_params.py15-45](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/sampling/sampling_params.py#L15-L45)
 
 **Response Processing:** SGLang tracks token consumption using `UsageProcessor` [python/sglang/srt/entrypoints/openai/usage_processor.py18-20](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/usage_processor.py#L18-L20) and uses `sse_utils` for streaming Server-Sent Events [python/sglang/srt/entrypoints/openai/serving_chat.py68](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_chat.py#L68-L68)

### Tool and Reasoning Parsing

 - **FunctionCallParser**: Maps model output to tool calls. It handles parsing of arguments from JSON strings [python/sglang/srt/entrypoints/openai/serving_chat.py127-141](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/serving_chat.py#L127-L141)

## Response Formats and SSE

 Streaming responses use the Server-Sent Events (SSE) protocol. Usage information is tracked via `UsageInfo` pydantic model [python/sglang/srt/entrypoints/openai/protocol.py205-212](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/openai/protocol.py#L205-L212) For non-streaming requests, the server returns an `ORJSONResponse` for high performance [python/sglang/srt/entrypoints/http_server.py63](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/http_server.py#L63-L63)
