## Purpose and Scope

 This page documents the procedures for installing SGLang and its core kernel library (`sgl-kernel`) across various hardware architectures. It details the multi-platform build system, dependency management via `pyproject.toml` variants, and platform-specific installation procedures. SGLang is designed as a fast serving framework for large language and vision language models, requiring tight integration between Python-level logic and hardware-optimized kernels.

 For containerized deployment, see **2.3 Docker Deployment**. For hardware-specific configuration, see **2.2 Hardware Platform Configuration**.

## Installation Architecture Overview

 SGLang employs a modular installation strategy supporting diverse hardware backends including NVIDIA CUDA, AMD ROCm/HIP, Intel Xeon/XPU, Ascend NPU, Moore Threads MUSA, and Apple Silicon MPS. The core Python package is distributed via PyPI with platform-specific dependency variants managed by separate `pyproject.toml` files. Performance-critical kernels are housed in the `sgl-kernel` package.

## Method 1: PyPI Installation

 The primary method for installing SGLang is using `pip` from PyPI, with optional extras to select dependencies optimized for the target hardware platform.

 
### Standard Runtime Dependencies (NVIDIA CUDA)

 The default `pyproject.toml` targets NVIDIA GPU platforms and includes:

 
 - Core ML stack: `torch==2.13.0`, `transformers==5.12.1`, `torchaudio==2.11.0` [python/pyproject.toml81-87](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject.toml#L81-L87)
 - Performance-optimized kernels: `sglang-kernel==0.4.6.post1` (compatible with CUDA 13.0), `sgl-deep-ep==0.1.2`, `sgl-deep-gemm==0.1.5.post3`, and `flashinfer_python[cu13]==0.6.17` [python/pyproject.toml36-73](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject.toml#L36-L73)
 - Structured output libraries: `xgrammar==0.2.1`, `llguidance>=1.7.6,<2.0.0`, and `outlines==0.1.11` [python/pyproject.toml42-91](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject.toml#L42-L91)
 
 
### Runtime Extras

 
 - `sglang[diffusion]`: Enables image/video diffusion model support with dependencies like `diffusers`, `opencv-python-headless`, `moviepy`, and `imageio` [python/pyproject.toml104-125](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject.toml#L104-L125)
 - `sglang[ray]`: Adds the Ray library for distributed execution capabilities [python/pyproject.toml135-137](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject.toml#L135-L137)
 - `sglang[tracing]`: Provides OpenTelemetry API and SDK packages for observability [python/pyproject.toml139-144](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject.toml#L139-L144)
 - `sglang[checkpoint-engine]`: Installs `checkpoint-engine==0.1.2`, enhancing model weight loading performance for large distributed scenarios [python/pyproject.toml101-102](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject.toml#L101-L102)

## Platform-Specific Installation Procedures

 SGLang offers specialized `pyproject.toml` variants to address the unique requirements and dependencies of each hardware platform.

 
### 1. AMD ROCm (HIP)

 
 - **Config file:** `python/pyproject_other.toml`
 - **Characteristics:** 
 - Contains ROCm-specific dependencies including `wave-lang==3.8.2`, `petit_kernel==0.0.2`, and `compressed-tensors==0.15.0` linked to ROCm 7.2 environment [python/pyproject_other.toml111-120](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_other.toml#L111-L120)
 - Includes integration with `sgl-flash-attn3` for ROCm GPUs.
 - Requires special build steps for native kernels and Aiter Wave-lang [python/pyproject_other.toml111](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_other.toml#L111-L111)
 
 
### 2. Intel XPU

 
 - **Config file:** `python/pyproject_xpu.toml`
 - **Characteristics:** 
 - Uses Intel's XPU-optimized PyTorch build `torch==2.13.0+xpu` and corresponding `torchvision` and `torchaudio` packages [python/pyproject_xpu.toml62-67](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_xpu.toml#L62-L67)
 - The `sgl-kernel` package comes from a dedicated git repository for XPU targets rather than PyPI [python/pyproject_xpu.toml57-58](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_xpu.toml#L57-L58)
 - Excludes CUDA-dependent libraries such as `xgrammar` which relies on Triton and CUDA.
 
 
### 3. Intel CPU (Xeon)

 
 - **Config file:** `python/pyproject_cpu.toml`
 - **Characteristics:** 
 - Tailored for CPU-only deployment with pins to `torch==2.12.0` and `triton==3.7.0` [python/pyproject_cpu.toml63-68](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_cpu.toml#L63-L68)
 - Includes Intel OpenMP runtime `intel-openmp` on x86_64 platforms for better CPU performance [python/pyproject_cpu.toml30-31](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_cpu.toml#L30-L31)
 - Activation is optionally controlled by the environment variable `SGLANG_USE_CPU_ENGINE=1` [python/sglang/srt/utils/common.py213-215](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/utils/common.py#L213-L215)
 
 
### 4. Ascend NPU

 
 - **Config file:** `python/pyproject_npu.toml`
 - **Characteristics:** 
 - Integrates `hf_transfer` and other Huawei Ascend-compatible dependencies for accelerated model weight loading [python/pyproject_npu.toml31-73](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_npu.toml#L31-L73)
 - Includes packages common for NPU support such as `huggingface_hub` and `modelslim` for quantization and optimization.
 
 
### 5. Moore Threads MUSA

 
 - **Config file:** `python/pyproject_other.toml` with the `srt_musa` extra.
 - **Characteristics:** 
 - Includes dependencies like `torchada`, `flash_attn_3`, and `deep-gemm` suited for the MUSA architecture [python/pyproject_other.toml136-146](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_other.toml#L136-L146)
 - Runtime availability detected via `is_musa()` utility that verifies torchada presence [python/sglang/srt/utils/common.py219-224](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/utils/common.py#L219-L224)

### Versioning System

 
 - **Runtime Versioning:** Managed via `setuptools_scm`, dynamically generating `python/sglang/_version.py` to embed repository state and semantic versioning [python/pyproject.toml242-245](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject.toml#L242-L245)
 - **Kernel Versioning:** The `sgl-kernel` package version is pinned explicitly in the platform PyPI specs (e.g., `sglang-kernel==0.4.6.post1` for CUDA builds) ensuring binary compatibility. The kernel wheel builds are published separately and referenced in Docker build ARGs [python/pyproject.toml73](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject.toml#L73-L73) [docker/Dockerfile7](https://github.com/sgl-project/sglang/blob/94183a8d/docker/Dockerfile#L7-L7)

### CLI Entry Points

 The installation registers command-line interface entrypoints that serve as primary user interfaces:

 
| Command | Module | Description |
|---|---|---|
| sglang | sglang.cli.main:main | Main SGLang CLI to launch engine etc. |
| killall_sglang | sglang.cli.killall:main | Utility to terminate running SGLang processes |

 These provide straightforward shell access to inference server control and maintenance operations [python/pyproject.toml202-203](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject.toml#L202-L203)

## Summary

 SGLang provides a flexible multi-platform installation framework that adapts dependencies and build mechanisms according to the target hardware backend. NVIDIA CUDA is the default support with comprehensive kernel acceleration (FlashInfer, DeepEP, DeepGEMM), while AMD ROCm, Intel XPU, Intel CPU, Ascend NPU, and Moore Threads MUSA platforms are supported through specialized `pyproject.toml` variants that handle distinct dependencies and native extensions.

 Users can choose pre-built PyPI packages for ease or build from source for development or advanced customization. The package declares CLI entrypoints that interact with hardware detection logic to initialize the runtime engine accordingly.
