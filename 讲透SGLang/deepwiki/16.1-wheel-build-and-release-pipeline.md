  This page describes the automated build and release processes for the SGLang ecosystem, focusing on the `sgl-kernel` library and the `sglang` framework. It details the platform matrix, the build orchestration for kernels across multiple hardware backends (CUDA, ROCm, MUSA, XPU, CPU), and the GitHub Actions workflows that publish artifacts to PyPI and the custom wheel index.

 For information about Docker image building and release, see page [16.2](https://github.com/sgl-project/sglang/blob/94183a8d/16.2) For version numbering scheme and release branch management, see page [16.3](https://github.com/sgl-project/sglang/blob/94183a8d/16.3)

## Package Overview

 The repository produces multiple Python packages released in tandem. The `sglang` framework depends on `sgl-kernel` for optimized model execution. The project uses dynamic versioning handled by `setuptools-scm`, which references `scripts/release/get_version_tag.py` [python/pyproject.toml243-246](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject.toml#L243-L246)

 
| Package | Directory | PyPI Name | Description |
|---|---|---|---|
| SGLang framework | python/ | sglang | Pure Python framework, server, and model code |
| SGL kernel library | python/sglang/kernels/aot | sglang-kernel | CUDA/ROCm/MUSA/CPU C++ extension with optimized kernels |

## sgl-kernel Build System

 The `sgl-kernel` package is a compiled extension providing optimized compute primitives. It supports multiple hardware backends through backend-specific build logic and environment configurations.

 
### Build Configuration Variants

 
 - **CUDA:** Supports CUDA 12.9 and 13.0. The 13.0 variant is the default for PyPI releases [.github/workflows/release-whl-kernel.yml37-148](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/release-whl-kernel.yml#L37-L148)
 - **ROCm:** Integrated into the release pipeline for AMD hardware, covering versions like `rocm700` and `rocm720` [.github/workflows/release-whl-kernel.yml20-21](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/release-whl-kernel.yml#L20-L21) AMD wheels often use a custom index at `repo.radeon.com` [3rdparty/amd/wheel/sglang/pyproject.toml74-77](https://github.com/sgl-project/sglang/blob/94183a8d/3rdparty/amd/wheel/sglang/pyproject.toml#L74-L77)
 - **MUSA:** Supported for Moore Threads hardware. The build involves executing `setup_musa.py` and requires MUSA-specific dependencies like `torch_musa` and `torchada` [scripts/ci/musa/musa_install_dependency.sh88-89](https://github.com/sgl-project/sglang/blob/94183a8d/scripts/ci/musa/musa_install_dependency.sh#L88-L89) [python/pyproject_other.toml150-160](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_other.toml#L150-L160)
 - **XPU:** Supported for Intel hardware, released via a dedicated workflow utilizing the `sgl-kernel-xpu` repository [.github/workflows/release-whl-kernel-xpu.yml1-10](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/release-whl-kernel-xpu.yml#L1-L10) [python/pyproject_xpu.toml57](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_xpu.toml#L57-L57)
 - **CPU:** Includes a `pyproject_cpu.toml` variant targeting `sglang-cpu` on PyPI, with specific support for Intel® AMX® via `intel-openmp` [python/pyproject_cpu.toml1-30](https://github.com/sgl-project/sglang/blob/94183a8d/python/pyproject_cpu.toml#L1-L30)
 
 
### Build Orchestration

 The build process uses a `build.sh` script to orchestrate compilation. For MUSA, a specific `rename_wheels_musa.sh` script is used to align wheel filenames with internal metadata versioning and platform tags (e.g., ensuring `manylinux2014` compatibility) [scripts/ci/musa/rename_wheels_musa.sh1-8](https://github.com/sgl-project/sglang/blob/94183a8d/scripts/ci/musa/rename_wheels_musa.sh#L1-L8)

## Release Pipeline (GitHub Actions)

 The release process for kernels is triggered by changes to `python/sglang/kernels/aot/python/sgl_kernel/version.py` or via `workflow_dispatch` [.github/workflows/release-whl-kernel.yml3-10](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/release-whl-kernel.yml#L3-L10)

 
### Stable vs. Legacy Releases

 
 - **CUDA 13.0 (Stable):** Released to PyPI. The workflow includes a step to strip the `+cu130` local version suffix from the wheel metadata to meet PyPI's naming requirements [.github/workflows/release-whl-kernel.yml185-197](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/release-whl-kernel.yml#L185-L197)
 - **CUDA 12.9 (Legacy):** Published exclusively to the `sgl-project/whl` index on GitHub [.github/workflows/release-whl-kernel.yml37-39](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/release-whl-kernel.yml#L37-L39)
 
 
### Release Automation Bots

 The pipeline includes automated bots to synchronize versions across the monorepo:

 
 - **`Bot Bump Kernel Version to SGLang`**: Checks if the `sgl-kernel` version in SGLang's requirements needs updating and creates a PR if sync is required [.github/workflows/bot-bump-kernel-version-to-sglang.yml11-16](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/bot-bump-kernel-version-to-sglang.yml#L11-L16)
 - **`Bot Bump SGLang Version`**: Manually triggered to bump the framework version, which then kicks off nightly tests across NVIDIA, AMD, NPU, and Intel platforms to validate the new version [.github/workflows/bot-bump-sglang-version.yml56-89](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/bot-bump-sglang-version.yml#L56-L89)
 
 
### Hardware-Specific Testing (MUSA)

 The MUSA backend undergoes specific PR and Nightly testing.

 
 - **PR Test (MUSA):** Detects changes in `python/sglang/kernels/aot/csrc/musa/` to trigger kernel unit tests [.github/workflows/pr-test-musa.yml84-87](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/pr-test-musa.yml#L84-L87)

## Index Management

 The project maintains a PEP 503 compliant wheel index at `sgl-project/whl` for hosting wheels that cannot be uploaded to PyPI.

 
### Indexer Logic (`update_kernel_whl_index.py`)

 
 - **Backend Detection:** The script filters wheels by backend (CUDA, ROCm, MUSA, XPU) based on the filename suffix or package name [scripts/update_kernel_whl_index.py13-20](https://github.com/sgl-project/sglang/blob/94183a8d/scripts/update_kernel_whl_index.py#L13-L20)
 - **Default Versioning:** CUDA 13.0 is treated as the default; its wheels on the custom index do not carry a version suffix, whereas others (like `cu129`) do [scripts/update_kernel_whl_index.py23-31](https://github.com/sgl-project/sglang/blob/94183a8d/scripts/update_kernel_whl_index.py#L23-L31)
 - **HTML Generation:** Iterates through `python/sglang/kernels/aot/dist`, calculates SHA256 hashes, and appends download links to the `index.html` for the corresponding backend/version [scripts/update_kernel_whl_index.py34-50](https://github.com/sgl-project/sglang/blob/94183a8d/scripts/update_kernel_whl_index.py#L34-L50)

## CI Monitoring and Infrastructure

 To maintain the release pipeline's health, the project uses several monitoring utilities:

 
 - **`AMD CI Job Monitor`**: A daily scheduled job that fetches GitHub Actions snapshots to report on the status of AMD-specific workflows (ROCm 7.0 and 7.2) [.github/workflows/amd-ci-job-monitor.yml1-59](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/amd-ci-job-monitor.yml#L1-L59)
 - **`Runner Utilization Report`**: Analyzes GitHub API data to calculate runner idle time, active time, and utilization percentage per label (e.g., `mi300`, `h200`). This ensures build nodes are sized correctly for the release matrix [.github/workflows/runner-utilization.yml1-5](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/runner-utilization.yml#L1-L5) [scripts/ci/utils/runner_utilization_report.py5-7](https://github.com/sgl-project/sglang/blob/94183a8d/scripts/ci/utils/runner_utilization_report.py#L5-L7)
 - **`AMD AITER Scout`**: A weekly scout job that resolves the latest `AITER` (AMD Infer Toolkit for Efficient Runtime) commit and triggers shadow CI runs to detect regressions before they hit the main release branch [.github/workflows/amd-aiter-scout.yml1-43](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/amd-aiter-scout.yml#L1-L43)

## MUSA Compatibility and Tooling

 Because MUSA wheels require specific local versioning (`+musa43`) for `pip` compatibility, the pipeline uses specialized scripts:

 
 - **`rename_wheels_musa.sh`**: Unpacks the wheel, updates the `Version:` field in `METADATA`, updates the `Tag:` in `WHEEL` to `manylinux2014`, and repacks it [scripts/ci/musa/rename_wheels_musa.sh60-97](https://github.com/sgl-project/sglang/blob/94183a8d/scripts/ci/musa/rename_wheels_musa.sh#L60-L97)
 - **`musa_install_dependency.sh`**: Handles CI environment setup, including cleaning stale `torchada` locks and installing the MUSA-specific `sgl-kernel` [scripts/ci/musa/musa_install_dependency.sh27-89](https://github.com/sgl-project/sglang/blob/94183a8d/scripts/ci/musa/musa_install_dependency.sh#L27-L89)
