## Purpose and Scope

 The logits processing pipeline transforms raw model logits before token sampling occurs. This page documents the sequence of modifications applied to logits including custom processors, penalties, grammar masking, and bias adjustments. It also covers the extraction of logprobs for both standard and speculative decoding paths. For configuration of these parameters, see [Sampling Parameters and Configuration](https://deepwiki.com/sgl-project/sglang/17.1-sampling-parameters-and-configuration). For the actual sampling algorithms that operate on processed logits, see [Sampling Algorithms](https://deepwiki.com/sgl-project/sglang/17.3-sampling-algorithms).

 
## Pipeline Overview

 The logits processing pipeline applies a fixed sequence of transformations to model output logits before sampling. Each transformation modifies the logits tensor in-place to adjust token probabilities according to user-specified constraints and preferences.

## LogitsProcessor and LM Head

 The `LogitsProcessor` class is responsible for the final model head computation, transforming hidden states into logits. It handles quantization methods for the LM head, such as FP8, FP4, and ModelOpt-specific formats. It also manages special modes like `autotune_dummy_run_mode` to skip LM head all-gathers during FlashInfer autotuning to prevent OOM [python/sglang/srt/layers/logits_processor.py86-94](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/logits_processor.py#L86-L94)

## Logprob Computation

 The pipeline computes logprobs for generated output tokens and input tokens using the `InputLogprobProcessor` and `OutputLogprobProcessor` [python/sglang/srt/layers/logprob_processor.py44-46](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/logprob_processor.py#L44-L46) [python/sglang/srt/layers/sampler.py87](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/sampler.py#L87-L87)

 
### Logsumexp Kernels

 To maintain numerical stability, SGLang uses a custom `row_logsumexp` function. It returns `(max, logsumexp - max)` in fp32 to prevent rounding errors when rows carry a large common offset [python/sglang/srt/layers/logprob_processor.py66-83](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/logprob_processor.py#L66-L83)

 
### Chunked Processing

 For very long sequences, SGLang implements a chunked logprob processing strategy. The `InputLogprobProcessor` handles stitching logprobs across these chunks, which is essential for prefill-only requests like scoring [python/sglang/srt/layers/logprob_processor.py188-200](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/logprob_processor.py#L188-L200) The chunk size can be controlled via the `SGLANG_LOGPROB_CHUNK_SIZE` environment variable [test/registered/core/test_srt_endpoint.py57](https://github.com/sgl-project/sglang/blob/94183a8d/test/registered/core/test_srt_endpoint.py#L57-L57)

### Deterministic and RL-On-Policy Mode

 In RL on-policy mode, deterministic inference is enabled, and `log_softmax` is used to compute logprobs to match training conditions [python/sglang/srt/layers/sampler.py78-84](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/sampler.py#L78-L84) This ensures consistency for on-policy RL algorithms.

 
### Synchronization
