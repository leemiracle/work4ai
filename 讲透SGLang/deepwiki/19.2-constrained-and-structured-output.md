  This page documents SGLang's constrained decoding and structured output system. The system provides token-level enforcement of formats during generation using vocabulary masks derived from JSON schemas, regular expressions, or EBNF grammars.

 Grammar constraints are applied during sampling by masking invalid tokens from the vocabulary before each generation step. This ensures the model's output strictly adheres to the specified structure while maintaining the performance of the underlying inference engine.

## System Entry Point: GrammarManager

 The `GrammarManager` class [python/sglang/srt/constrained/grammar_manager.py26](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/grammar_manager.py#L26-L26) is the scheduler-level interface to the constrained decoding system. It is initialized once per scheduler process [python/sglang/srt/constrained/grammar_manager.py27-38](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/grammar_manager.py#L27-L38)

 `GrammarManager` responsibilities:

 
 - Creates and caches the global `BaseGrammarBackend` instance via `create_grammar_backend` [python/sglang/srt/constrained/grammar_manager.py32-38](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/grammar_manager.py#L32-L38)
 - Manages a `grammar_queue` of requests waiting for asynchronous grammar compilation [python/sglang/srt/constrained/grammar_manager.py30](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/grammar_manager.py#L30-L30)
 - Synchronizes ready/failed grammar requests across distributed ranks (TP/DP/PP) using the `grammar_sync_group` and `_pp_sync_ready_failed` [python/sglang/srt/constrained/grammar_manager.py48-51](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/grammar_manager.py#L48-L51) [python/sglang/srt/constrained/grammar_manager.py77-107](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/grammar_manager.py#L77-L107)
 - Dispatches grammar creation requests based on `SamplingParams` fields such as `json_schema`, `regex`, `ebnf`, or `structural_tag` [python/sglang/srt/constrained/grammar_manager.py131-151](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/grammar_manager.py#L131-L151)

## XGrammar Backend

 `XGrammarGrammarBackend` [python/sglang/srt/constrained/xgrammar_backend.py206](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/xgrammar_backend.py#L206-L206) is the default high-performance backend. It uses the `xgrammar` library to compile schemas into `CompiledGrammar` objects and produces `GrammarMatcher` instances per request.

 
### Per-Request State: `XGrammarGrammar`

 Each request gets an `XGrammarGrammar` wrapping a `GrammarMatcher` [python/sglang/srt/constrained/xgrammar_backend.py73-83](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/xgrammar_backend.py#L73-L83)

 
 - **`fill_vocab_mask`**: Populates a bitmask using `matcher.fill_next_token_bitmask` [python/sglang/srt/constrained/xgrammar_backend.py119-120](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/xgrammar_backend.py#L119-L120)
 - **`apply_vocab_mask`**: Applies the mask to logits. On NVIDIA GPUs, it uses `apply_token_bitmask_inplace_triton` [python/sglang/srt/constrained/xgrammar_backend.py131](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/xgrammar_backend.py#L131-L131) On AMD (HIP), it uses `apply_token_bitmask_inplace_cuda` from `sgl_kernel` [python/sglang/srt/constrained/xgrammar_backend.py129](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/xgrammar_backend.py#L129-L129) On NPU, it uses `torch.ops.npu.apply_token_bitmask` [python/sglang/srt/constrained/xgrammar_backend.py135](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/xgrammar_backend.py#L135-L135)
 - **`try_jump_forward`**: Attempts to skip ahead in the grammar if the next sequence of tokens is deterministic [python/sglang/srt/constrained/xgrammar_backend.py164-168](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/xgrammar_backend.py#L164-L168)

## Outlines Backend

 The `OutlinesGrammarBackend` [python/sglang/srt/constrained/outlines_backend.py114](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/outlines_backend.py#L114-L114) integrates with the `outlines` library for constrained generation. It converts JSON schemas or regex patterns into finite state machine (FSM) guides.

 
### Per-Request State: `OutlinesGrammar`

 Each request uses an `OutlinesGrammar` instance, which holds an `outlines.fsm.guide.RegexGuide` [python/sglang/srt/constrained/outlines_backend.py42-51](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/outlines_backend.py#L42-L51)

 
 - **`fill_vocab_mask`**: The `RegexGuide` determines the next valid tokens via `get_next_instruction(self.state).tokens`, and `fill_vocab_mask` sets the corresponding bits in the vocabulary mask [python/sglang/srt/constrained/outlines_backend.py65-71](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/outlines_backend.py#L65-L71)
 - **`apply_vocab_mask`**: Applies the mask by setting invalid token logits to negative infinity [python/sglang/srt/constrained/outlines_backend.py74-75](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/outlines_backend.py#L74-L75)
 - **`try_jump_forward`**: Utilizes `OutlinesJumpForwardMap` to identify potential jump-forward opportunities [python/sglang/srt/constrained/outlines_backend.py80-102](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/outlines_backend.py#L80-L102)

## Reasoner Grammar Backend

 `ReasonerGrammarBackend` [python/sglang/srt/constrained/reasoner_grammar_backend.py205](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/reasoner_grammar_backend.py#L205-L205) enables constrained output for models that generate a "thinking" section (Chain-of-Thought) before the structured answer. It wraps a standard grammar backend to handle the state transition at `think_end_ids`.

 
### State Machine Transitions

 `ReasonerGrammarObject` [python/sglang/srt/constrained/reasoner_grammar_backend.py35](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/reasoner_grammar_backend.py#L35-L35) tracks the lifecycle:

 
 - **THINKING**: `tokens_in_think >= 0`, `tokens_after_end == -1`. Constraints are generally bypassed, but specific tokens can be filtered (e.g., tool calls) [python/sglang/srt/constrained/reasoner_grammar_backend.py84-93](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/reasoner_grammar_backend.py#L84-L93)
 - **GENERATION**: `tokens_after_end >= 0`. The underlying grammar (JSON/Regex) is consulted for bitmasking and token acceptance [python/sglang/srt/constrained/reasoner_grammar_backend.py122-124](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/reasoner_grammar_backend.py#L122-L124)
 
 
### Strict Thinking Mode

 If `enable_token_filter` is active [python/sglang/srt/constrained/reasoner_grammar_backend.py56](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/reasoner_grammar_backend.py#L56-L56) the `ReasonerGrammarObject` enforces a `max_think_tokens` budget. Once exhausted, it forces the model to generate the `think_end_ids` sequence by masking out all other tokens [python/sglang/srt/constrained/reasoner_grammar_backend.py162-168](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/reasoner_grammar_backend.py#L162-L168) This logic is implemented in `fill_vocab_mask` [python/sglang/srt/constrained/reasoner_grammar_backend.py150-172](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/constrained/reasoner_grammar_backend.py#L150-L172)
