## Purpose and Scope

 This page documents SGLang's INT8 quantization and additional weight-only quantization methods that complement FP8 and FP4 approaches. These techniques offer a range of trade-offs balancing model accuracy, memory footprint, and inference speed. They support diverse hardware platforms including CPUs with AMX, NVIDIA GPUs, AMD ROCm GPUs, and Ascend NPUs.

 Key highlights include:

 
 - INT8 weight-activation quantization (W8A8)
 - 4-bit weight-only quantization schemes: AWQ, GPTQ, QServe
 - Compressed Tensors unified quantization schemes
 - NPU-optimized ModelSlim quantization method
 - MoE model quantization schemes: WNA16, MXFP4, NVFP4, MxInt4
 - Quantized KV cache support using FP8 and FP4 formats
 - Integration with Marlin and FlashInfer kernels
 
 This page assumes familiarity with the core SGLang quantization framework overview in Section 9.1, FP8 methods in Section 9.2, and FP4 methods in Section 9.3.

## INT8 (W8A8) Quantization

 SGLang's W8A8 quantization supports 8-bit static weight quantization combined with 8-bit dynamic activation quantization.

 
### Key Implementation Points

 
 - **NPU Backend:** Uses `NPUW8A8Int8LinearMethod` and `NPUW8A8Int8DynamicLinearMethod` for linear layers [python/sglang/srt/hardware_backend/npu/quantization/linear_method_npu.py65-156](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/hardware_backend/npu/quantization/linear_method_npu.py#L65-L156)
 - **Weight Loading:** On NPU, weights are transposed and cast to `npu_format_cast` after loading [python/sglang/srt/hardware_backend/npu/quantization/linear_method_npu.py68-69](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/hardware_backend/npu/quantization/linear_method_npu.py#L68-L69)
 - **Dynamic Quantization:** The dynamic method uses `torch.ops.npu.npu_dynamic_quant` on the input tensor `x` before performing `npu_quant_matmul` [python/sglang/srt/hardware_backend/npu/quantization/linear_method_npu.py147-155](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/hardware_backend/npu/quantization/linear_method_npu.py#L147-L155)

## AWQ and GPTQ Quantization

 
### AWQ (Activation-Aware Weight Quantization)

 
 - Provides 4-bit weight-only quantization.
 - On Ascend NPU, AWQ uses CANN kernels for execution [docs/docs/advanced_features/quantization.mdx88-93](https://github.com/sgl-project/sglang/blob/94183a8d/docs/docs/advanced_features/quantization.mdx?plain=1#L88-L93)
 
 
### GPTQ (Generative Pretrained Transformer Quantization)

 
 - Supports multiple bit-widths (2, 4, 8-bit) for weight-only quantization.
 - **Marlin Support:** Marlin kernels are preferred for performance on NVIDIA GPUs, handled via `GPTQMarlinState` and associated repacking logic [python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_wNa16_moe.py60-64](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_wNa16_moe.py#L60-L64)
 - **MoE Repack:** Uses `gptq_marlin_moe_repack` to prepare weights for the Marlin kernel [python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_wNa16_moe.py11-13](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_wNa16_moe.py#L11-L13)

## Other Quantization Methods

 
### AutoRound

 
 - Post-training quantization technique optimizing rounding.
 - Platform-agnostic (Intel auto-round) but uses CANN kernels when running on Ascend [docs/docs/advanced_features/quantization.mdx116-121](https://github.com/sgl-project/sglang/blob/94183a8d/docs/docs/advanced_features/quantization.mdx?plain=1#L116-L121)
 
 
### ModelSlim (NPU-specific Quantization)

 ModelSlim is a quantization framework specifically designed for Ascend NPUs, providing native optimizations for models like DeepSeek-V4 and Qwen3.

 
 - **Config Handling:** `ModelSlimConfig` [python/sglang/srt/layers/quantization/modelslim/modelslim.py90-184](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelslim/modelslim.py#L90-L184) parses NPU-specific descriptions and handles module aliases (e.g., mapping `block_sparse_moe` to `mlp`).
 - **Normalization Patches:** Injects NPU-specific bias handling into `RMSNorm` using `apply_module_patch` [python/sglang/srt/layers/quantization/modelslim/modelslim.py132-141](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/modelslim/modelslim.py#L132-L141)
 - **MXFP8 Support:** `NPUMXFP8LinearMethod` implements block-wise (size 32) MXFP8 matmuls for dense and MoE layers [python/sglang/srt/hardware_backend/npu/quantization/linear_method_npu.py158-187](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/hardware_backend/npu/quantization/linear_method_npu.py#L158-L187)
 
 
### MoeWNA16 Quantization

 
 - MoE-specific quantization method supporting WNA16 (weighted n-bit asymmetric 16-bit) quantization.
 - Implemented in `CompressedTensorsWNA16MoE` scheme [python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_wNa16_moe.py65-100](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_wNa16_moe.py#L65-L100)
 - Supports sharding for TP along transposed dimensions [python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_wNa16_moe.py110-113](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_wNa16_moe.py#L110-L113)
 
 
### NVFP4 and MxInt4 (Blackwell Support)

 
 - **NVFP4:** Supported on Blackwell GPUs (SM100) via `CompressedTensorsW4A4Nvfp4MoE` [python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_w4a4_nvfp4_moe.py33-53](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_w4a4_nvfp4_moe.py#L33-L53)

## Compressed Tensors Integration

 The `CompressedTensorsConfig` integrates many quantization schemes into a unified interface.

 
### Features

 
 - **Linear Dispatch:** Dynamically selects linear methods like `Fp8LinearMethod` if mixed precision is configured, or specific `CompressedTensorsLinearScheme` implementations [python/sglang/srt/layers/quantization/compressed_tensors/compressed_tensors.py183-192](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/compressed_tensors/compressed_tensors.py#L183-L192)

## Quantized KV Cache (FP8 and FP4 KV)

 SGLang supports quantization of the KV cache to reduce memory bandwidth and footprint.

 
### Highlights

 
 - **FP4 KV:** Uses FlashInfer for quantization. The `fp4_quantize` implementation selects between `cute-dsl` (for SM100) and standard `cuda` backends [python/sglang/srt/layers/quantization/fp4_utils.py22-49](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp4_utils.py#L22-L49)
 - **FP4 GEMM Backend:** The system can automatically select the best GEMM backend (e.g., `marlin` for older CUDA, `flashinfer_cutedsl` for Blackwell) [python/sglang/srt/layers/quantization/fp4_utils.py143-156](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp4_utils.py#L143-L156)
 - **Layout Shuffling:** FlashInfer TRT-LLM FP4 GEMM requires specific weight layout shuffling using `shuffle_matrix_a` and `shuffle_matrix_sf_a` [python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_w4a4_nvfp4.py102-121](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_w4a4_nvfp4.py#L102-L121)
