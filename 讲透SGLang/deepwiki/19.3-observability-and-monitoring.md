  This page documents SGLang's observability and monitoring infrastructure, which provides visibility into system performance, request lifecycle, and resource utilization. The system supports multiple observability backends including Prometheus metrics, OpenTelemetry tracing, and custom request metrics exporters across the Python SRT (SGLang Runtime), distributed disaggregation components, and the Rust-based SGLang Model Gateway.

 
## Overview

 SGLang provides a multi-layered observability system designed for production monitoring and debugging:

 
 - **Prometheus Metrics** - Real-time metrics exposed via HTTP endpoints. In the Python SRT, these track engine throughput and KV cache; in the Rust Gateway, they track routing decisions and upstream health.
 - **Production Metrics (TTFT/TPOT)** - Detailed tracking of Time To First Token (TTFT), Time Per Output Token (TPOT), and cache hit rates [python/sglang/srt/observability/metrics_collector.py70-71](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/observability/metrics_collector.py#L70-L71)
 - **Disaggregation Observability** - Specialized monitoring for Prefill-Decode disaggregation, including KV transfer speeds, latency, and queue depths [python/sglang/srt/observability/metrics_collector.py127-134](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/observability/metrics_collector.py#L127-L134)
 - **Scheduler Runtime Monitoring** - Real-time tracking of KV cache pool utilization, token usage, and session-held resources [python/sglang/srt/observability/metrics_collector.py82-112](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/observability/metrics_collector.py#L82-L112)
 - **Request Lifecycle Tracing** - A structured stage-based tracing system (`RequestStage`) that follows requests from tokenization through various forward pass modes [python/sglang/srt/observability/req_time_stats.py105-225](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/observability/req_time_stats.py#L105-L225)
 - **Performance Profiling** - Integration with PyTorch Profiler and custom profiling utilities for deep dives into kernel execution and scheduling overhead [python/sglang/srt/model_executor/runner/eager_runner.py68](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_executor/runner/eager_runner.py#L68-L68)
 - **Gateway Observability** - The Rust `sgl-model-gateway` provides high-throughput metrics for HTTP/gRPC traffic, worker health, and circuit breaker states [sgl-model-gateway/src/observability/metrics.rs148-210](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/observability/metrics.rs#L148-L210)

### Request Stages

 SGLang defines a hierarchy of `RequestStageConfig` objects to trace requests through the pipeline [python/sglang/srt/observability/req_time_stats.py88-103](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/observability/req_time_stats.py#L88-L103) Key stages include:

## Gateway Observability (sgl-model-gateway)

 The Rust-based model gateway includes a robust observability stack optimized for high-throughput routing.
