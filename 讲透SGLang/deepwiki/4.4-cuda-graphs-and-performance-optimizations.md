## Purpose and Scope

 This page documents SGLang's CUDA graph system and associated performance optimizations for GPU and NPU inference. CUDA graphs eliminate kernel launch overhead by capturing and replaying sequences of GPU operations, providing significant latency improvements in decoding and speculative decoding. The page covers CUDA graph capture/replay mechanics, piecewise and breakable CUDA graphs, batch size selection, and specialized speculative decoding optimizations including EAGLE, N-gram, and Two-Batch Overlap (TBO).

 For broader context on request processing, see [4.3 Model Execution and Forward Pass](https://github.com/sgl-project/sglang/blob/94183a8d/4.3 Model Execution and Forward Pass) For scheduling before graph execution, see [4.2 Scheduler and Batch Formation](https://github.com/sgl-project/sglang/blob/94183a8d/4.2 Scheduler and Batch Formation)

 
---

 
## CUDA Graphs Overview

 CUDA Graphs capture sequences of GPU kernels and memory operations into a single executable unit, which can be replayed with minimal CPU overhead. This reduces kernel launch latency from microseconds to nanoseconds and is critical for low-latency inference, especially during decode and speculative phases.

 
### Benefits and Trade-offs

 
| Feature | Description |
|---|---|
| Reduced Latency | Significant reduction in kernel launch overhead per forward pass. |
| Increased Throughput | Lower CPU overhead permits higher batch concurrency in GPU execution. |
| Memory Overhead | Static buffers and dedicated GPU memory required for each captured batch size graph. |
| Fixed Topology | Graph execution cannot accommodate dynamic control flow or branching decisions on GPU data. |

 SGLang uses CUDA graphs primarily during:

 
 - **Decode** phase: single-token generation per request [python/sglang/srt/model_executor/runner/decode_cuda_graph_runner.py18-19](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_executor/runner/decode_cuda_graph_runner.py#L18-L19)
 - **Prefill/Extend** phase: accelerated via specialized backends like `breakable` or `tc_piecewise` [python/sglang/srt/model_executor/runner/prefill_cuda_graph_runner.py14-36](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_executor/runner/prefill_cuda_graph_runner.py#L14-L36)
 - **Speculative** phases: draft token proposals and verification (e.g., EAGLE draft-extend and draft-decode) [python/sglang/srt/speculative/eagle_worker_v2.py44-47](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_worker_v2.py#L44-L47)
 
 The `ForwardMode.is_cuda_graph()` method indicates when CUDA graph execution is applicable [python/sglang/srt/model_executor/forward_batch_info.py181-188](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_executor/forward_batch_info.py#L181-L188)

## Shared Slot Registry: CudaGraphBufferRegistry

 The `CudaGraphBufferRegistry` mirrors `ForwardBatch` attributes in GPU buffers allocated statically for CUDA graph replay [python/sglang/srt/model_executor/cuda_graph_buffer_registry.py59-62](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_executor/cuda_graph_buffer_registry.py#L59-L62)

 
 - **Registration**: Binds named slots to tensors. The registry coalesces buffers by name, size, and dtype, allowing different runners to share physical allocations when their execution is sequential.
 - **Filling**: The `.fill_from(forward_batch)` method copies live data into static buffers.
 - **Input Buffers**: Specific buffer classes exist for different phases, such as `DecodeInputBuffers` [python/sglang/srt/model_executor/runner_utils/buffers.py90-91](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_executor/runner_utils/buffers.py#L90-L91) and `EagleDraftExtendInputBuffers` [python/sglang/srt/speculative/eagle_draft_extend_cuda_graph_runner.py58-74](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_draft_extend_cuda_graph_runner.py#L58-L74)

## Advanced CUDA Graph Execution Modes

 
### Piecewise CUDA Graphs (tc_piecewise)

 Uses `torch.compile` to wrap the model. Per-shape compiled/captured pieces live in the internal cache of `torch.compile`. This mode supports multi-request prefill by wrapping the transformer body [python/sglang/srt/model_executor/runner/prefill_cuda_graph_runner.py31-34](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_executor/runner/prefill_cuda_graph_runner.py#L31-L34)

 
### Breakable CUDA Graphs

 The `BreakableCudaGraphBackend` implements segmented capture without `torch.compile`. It captures the transformer body with one request slot and replays it with live batch metadata [python/sglang/srt/model_executor/runner/prefill_cuda_graph_runner.py17-22](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_executor/runner/prefill_cuda_graph_runner.py#L17-L22)

 
 - **Segmented Capture**: Graphs break at attention or Mamba boundaries.
 - **Eager Markers**: Uses `@eager_on_graph` decorators to mark sections that should not be captured [python/sglang/srt/model_executor/runner_backend/breakable_cuda_graph_backend.py95-97](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_executor/runner_backend/breakable_cuda_graph_backend.py#L95-L97)
 
 
### Full CUDA Graphs

 The default mode for decode. One graph is captured per shape (batch size bucket). Replay involves padding the input batch to the nearest captured bucket size [python/sglang/srt/model_executor/runner/decode_cuda_graph_runner.py18-19](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/model_executor/runner/decode_cuda_graph_runner.py#L18-L19)

## Speculative Decoding Optimizations

 Speculative decoding relies heavily on CUDA graphs to hide the overhead of multiple draft steps.

 
### EAGLE and Multi-Layer EAGLE

 EAGLE uses specialized graph runners to manage the draft-verify cycle:

 
 - **Draft-Extend**: Captures the target model's hidden state projection and the first draft step [python/sglang/srt/speculative/eagle_draft_extend_cuda_graph_runner.py77-83](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_draft_extend_cuda_graph_runner.py#L77-L83)
 - **Draft-Decode**: Captures subsequent draft steps. It uses a static capture width (full tree width) [python/sglang/srt/speculative/eagle_draft_cuda_graph_runner.py154-156](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_draft_cuda_graph_runner.py#L154-L156)
 - **Multi-Layer EAGLE**: Supports chain-style MTP (Multi-Token Prediction) where each step propagates its own hidden states to the next [python/sglang/srt/speculative/multi_layer_eagle_worker_v2.py180-186](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/multi_layer_eagle_worker_v2.py#L180-L186)
 
 
### N-gram Speculative Decoding

 The `NGRAMWorker` provides a CPU-side corpus-based draft mechanism that avoids GPU draft model overhead [python/sglang/srt/speculative/ngram_worker.py147-149](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/ngram_worker.py#L147-L149) It uses `reconstruct_indices_from_tree_mask` to build verify trees on the host [python/sglang/srt/speculative/ngram_worker.py47-55](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/ngram_worker.py#L47-L55)

 
### Two-Batch Overlap (TBO)

 TBO overlaps the computation of two different micro-batches to improve GPU utilization. It splits the `ForwardBatch` into two chunks (`child_a` and `child_b`) and executes them concurrently using different streams or specialized kernels [python/sglang/srt/batch_overlap/two_batch_overlap.py12-15](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/batch_overlap/two_batch_overlap.py#L12-L15)
