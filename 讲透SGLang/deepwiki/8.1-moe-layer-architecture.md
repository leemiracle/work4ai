  This page documents the core Mixture-of-Experts (MoE) layer architecture in SGLang, including the `FusedMoE` implementation, the MoE forward pass data flow, expert weight organization, expert computation, and integration with FlashInfer, TrtLLM, and DeepEP backends.

 
---

 
## MoE Layer Overview

 MoE layers dynamically route input tokens to a set of expert networks for conditional computation. The core components are:

 
 - **Router Component**: Computes gating logits and selects top-k experts per token.
 - **Expert Layers**: Perform expert computations on dispatched tokens.
 - **Shared Experts (Optional)**: Always-active experts whose outputs are combined additively.

## Expert Weight Organization

 Expert weights are organized to optimize GPU compute efficiency. The Gate and Up projection weights are fused in a single tensor `w13_weight` to reduce kernel launches and memory overhead.

 
### Expert Weight Layout and Quantization

 Title: Expert Weight Tensors and Mapping

 
```

```

 
 - `w13_weight` fuses gate and up projection weights for efficient fused computation [python/sglang/srt/layers/moe/fused_moe_triton/layer.py296-310](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L296-L310)

## Token Dispatch and Expert Computation

 
### Token Dispatch

 The dispatcher is responsible for distributing token embeddings to experts based on `topk_ids`. Some dispatchers also handle inter-GPU communication for Expert Parallelism (EP):

 
 - `StandardDispatcher`: Default dispatcher for non-EP or simple cases [python/sglang/srt/layers/moe/fused_moe_triton/layer.py149](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L149-L149)
 - `MaybeTboDeepEPDispatcher`: For DeepEP/DeepSeek models with token batch overlap and EP [python/sglang/srt/layers/moe/fused_moe_triton/layer.py157-168](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L157-L168)
 - `FlashinferDispatcher`: For FlashInfer kernels with specific routing [python/sglang/srt/layers/moe/fused_moe_triton/layer.py169-176](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L169-L176)
 - `AscendTPDispatcher`: For NPU Ascend devices, bypassing dispatcher abstraction [python/sglang/srt/layers/moe/fused_moe_triton/layer.py138-140](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L138-L140)
 
 
### Expert Computation Backends

 
 - **Triton Backend**: `FusedMoE` uses Triton kernels for fused gate and expert computations, efficient for unquantized or FP8 MoE layers [python/sglang/srt/layers/moe/utils.py124-126](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/utils.py#L124-L126)
 - **FlashInfer / TrtLLM Backend**: Supports efficient FP8 and FP4 quantized MoE kernels. Weight preparation involves padding and shuffling for MMA hardware efficiency [python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py145-220](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py#L145-L220)
 - **DeepEP / DeepGEMM Backend**: Specialized for DeepSeek models, includes a low-latency mode that optimizes A2A communication and gemm overlapping [python/sglang/srt/layers/moe/ep_moe/layer.py63-127](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/ep_moe/layer.py#L63-L127)
 - **Aiter Backend**: Optimized for ROCm/AMD platforms, supporting block-fp8 and MXFP8 paths [python/sglang/srt/layers/quantization/fp8.py126-130](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/quantization/fp8.py#L126-L130)
 - **Intel XPU Backend**: Optimized for Intel GPUs using `topk_sigmoid` and `topk_softmax` from `sgl_kernel` [python/sglang/srt/layers/moe/topk.py185-189](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/topk.py#L185-L189)

## FlashInfer / TrtLLM MoE Backends

 The FlashInfer/TrtLLM backend provides optimized kernels for FP8 and FP4 quantized MoE models with fused gate and expert computation.

 
### Weight Alignment and Shuffling

 
 - Weights (`w13_weight`, `w2_weight`) are aligned to kernel-specific dimension requirements (e.g., multiples of 16 or 128) [python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py145-178](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py#L145-L178)
 - The backend may swap gate and up halves of `w13_weight` for compatibility with ModelOpt FP8 checkpoints [python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py180-207](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py#L180-L207)
 - Uses FlashInfer's `shuffle_matrix_a` to reorder rows for gated fused activations in order to achieve MMA alignment [python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py215-220](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py#L215-L220)
 
 
### Deferred Finalize Context

 This backend supports a deferred finalize mode, guarded by a context manager `flashinfer_trtllm_deferred_finalize_context`, to delay output fusion for performance gains [python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py62-70](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py#L62-L70) Finalization is performed by `moe_finalize_fuse_shared` [python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py83-92](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py#L83-L92)
