  The `sgl-router` (implemented primarily within the `sgl-model-gateway` Rust crate and supported by `experimental/sgl-router`) is an experimental, high-performance router designed to optimize Large Language Model (LLM) serving. It provides a slim, KV-aware control plane that orchestrates requests across distributed SGLang worker nodes. Its primary objective is to maximize KV cache reuse through intelligent routing while maintaining balanced load across the cluster.

 
## Architecture Overview

 The router is built in Rust to provide the low latency required for high-throughput inference. It acts as a gateway that intercepts incoming HTTP or gRPC requests and dispatches them to a fleet of backend workers. The system is designed around a `WorkerRegistry` for membership and a `PolicyRegistry` for decision-making.

 
### System Components

 
 - **WorkerRegistry**: Centralized registry providing model-based indexing and O(log n) consistent hashing via `HashRing` [sgl-model-gateway/src/core/worker_registry.rs180-190](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker_registry.rs#L180-L190)
 - **PolicyRegistry**: Manages the selection of load balancing strategies (e.g., `CacheAwarePolicy`, `PowerOfTwoPolicy`) [sgl-model-gateway/src/policies/registry.rs1-20](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/registry.rs#L1-L20)
 - **CircuitBreaker**: Each worker is protected by a circuit breaker to prevent routing to failing nodes [sgl-model-gateway/src/core/worker.rs15-24](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker.rs#L15-L24)

## KV-Aware and Cache-Aware Routing

 The core innovation of the `sgl-router` is its ability to track the state of KV caches across workers. This is achieved through real-time event synchronization using the `KVEventBatch` stream.

 
### KV Event Stream

 The router subscribes to events published by SGLang workers. The `ZmqEventPublisher` in the Python runtime emits `KVEventBatch` payloads containing `BlockStored`, `BlockRemoved`, and `AllBlocksCleared` events [python/sglang/srt/disaggregation/kv_events.py112-145](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/kv_events.py#L112-L145)

 
 - **Wire Format**: Events are encoded using `msgspec.msgpack` as arrays. The Rust implementation provides a `decode_event_batch` utility to deserialize these into `KvEventBatch` structs [experimental/sgl-router/src/policies/kv_events/wire.rs37-60](https://github.com/sgl-project/sglang/blob/94183a8d/experimental/sgl-router/src/policies/kv_events/wire.rs#L37-L60)
 - **Safety Caps**: To prevent memory amplification, the Rust decoder enforces `MAX_HASHES_PER_EVENT` (65,536) and `MAX_TOKENS_PER_EVENT` (1,048,576) [experimental/sgl-router/src/policies/kv_events/wire.rs94-99](https://github.com/sgl-project/sglang/blob/94183a8d/experimental/sgl-router/src/policies/kv_events/wire.rs#L94-L99)
 - **DP Rank Handling**: In Data Parallel (DP) attention modes, each rank publishes on its own port. The `select_kv_publisher_dp_rank` function determines the correct rank index to avoid duplicate events [python/sglang/srt/disaggregation/kv_events.py39-58](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/kv_events.py#L39-L58)
 
 
### Cache-Aware Policy Implementation

 The `CacheAwarePolicy` combines prefix matching with load balancing thresholds. It maintains an approximate radix tree for each worker based on incoming events.

 
 - **Prefix Matching**: The policy uses a `Tree` structure to store request history and find workers with the highest prefix match [sgl-model-gateway/src/policies/cache_aware.rs25-30](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L25-L30)
 - **Imbalance Detection**: The router dynamically switches from cache-aware routing to shortest-queue balancing if the system load is imbalanced (determined by `balance_abs_threshold` and `balance_rel_threshold`) [sgl-model-gateway/src/policies/cache_aware.rs13-16](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/policies/cache_aware.rs#L13-L16)

 The router supports multiple policies configured via the CLI or configuration files [sgl-model-gateway/src/main.rs149-152](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/main.rs#L149-L152)

|---|---|---|

| active_load | ActiveLoadPolicy | Routes to the worker with the lowest number of currently processing requests. |

## Service Discovery and Worker Management

 The router supports dynamic worker discovery to enable scaling in cloud-native environments.

 
 - **Kubernetes EndpointSlice**: Integration with `kube-rs` allows the router to watch `EndpointSlice` resources and update the `WorkerRegistry` automatically [sgl-model-gateway/src/service_discovery.rs1-50](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/service_discovery.rs#L1-L50)
 - **Static URL Pools**: For non-K8s environments, workers can be defined as a static list of URLs in the configuration.
 - **Worker Health Monitoring**: The `HealthChecker` performs periodic async checks. If a worker fails, the `CircuitBreaker` trips [sgl-model-gateway/src/core/worker.rs168-175](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker.rs#L168-L175)

## PD Disaggregation Support

 The router natively supports Prefill-Decode (PD) disaggregation, where prefill and decode phases are handled by different worker pools [sgl-model-gateway/src/routers/http/pd_router.rs50-57](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/routers/http/pd_router.rs#L50-L57)

 
 - **KV Metrics**: The `SchedulerKvEventsPublisher` in the Python scheduler emits metrics such as `kv_active_blocks` and `gpu_prefix_cache_hit_rate` to the router [python/sglang/srt/managers/scheduler_components/kv_events_publisher.py30-40](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/scheduler_components/kv_events_publisher.py#L30-L40)
 - **Coordination**: The router uses these metrics to select the best prefill worker and coordinate the KV cache transfer to a decode worker.
 - **Worker Types**: Workers are registered as `WorkerType::Prefill` or `WorkerType::Decode` [sgl-model-gateway/src/core/worker.rs148-150](https://github.com/sgl-project/sglang/blob/94183a8d/sgl-model-gateway/src/core/worker.rs#L148-L150)
