  This page documents the development tools and debugging utilities available to SGLang contributors and maintainers. It covers CI control via slash commands, the tensor dumping infrastructure, numerical comparison tools, CUDA coredump handling, and internal playbooks for development.

 
---

 
## Overview of Developer Tools

 SGLang provides several categories of developer tools:

 
 - **Slash Commands** – Comment-based commands on pull requests to trigger CI tests selectively.
 - **CI Permissions System** – Access control and rate limiting for CI resource usage.
 - **The Tensor Dumper** – A system for capturing intermediate tensors during model execution for numerical verification.
 - **Dump Comparator** – Tools to compare captured tensors across different runs or hardware backends.
 - **CUDA Coredump Handling** – Automated capture and reporting of GPU-level failures.
 - **Internal Playbooks** – Located in `scripts/` and `.claude/` for maintainer-specific workflows and LLM-assisted development.
 
 
---

 
## Slash Commands for CI Control

 Slash commands allow developers to control CI execution by posting special comments on GitHub pull requests. These commands are processed by the `Slash Command Handler` workflow and the `slash_command_handler.py` script.

 
### Available Commands

 
| Command | Description | Permission Required |
|---|---|---|
| /tag-run-ci-label | Adds the run-ci label to enable CI on future commits | Defined in CI_PERMISSIONS.json .github/MAINTAINER.md113 |
| /rerun-failed-ci | Reruns workflows with failure, flaky, or skipped conclusions | PR author or maintainer .github/MAINTAINER.md109-114 |
| /rerun-stage <stage> | Reruns a specific test stage (e.g., unit-test-backend-4-gpu) | Maintainer .github/MAINTAINER.md116-122 |
| /tag-and-rerun-ci | Adds the label and kicks off CI on the current commit | Authorized user .github/MAINTAINER.md115 |
| /rerun-test | Dispatches a specific test command to a runner | Authorized user scripts/ci/utils/slash_command_handler.py161-182 |

 
### Dispatch and Gating Logic

 The handler script implements logic to prevent wasting runner time on PRs. Authorized users are defined in `CI_PERMISSIONS.json` [.github/CI_PERMISSIONS.json1-20](https://github.com/sgl-project/sglang/blob/94183a8d/.github/CI_PERMISSIONS.json#L1-L20). PR authors can always use `/rerun-failed-ci` on their own PRs even if not listed in the permissions file [.github/MAINTAINER.md109-110](https://github.com/sgl-project/sglang/blob/94183a8d/.github/MAINTAINER.md?plain=1#L109-L110). Before dispatching, the script checks a "rebase gate" mirroring maintenance status in issue #21065 [scripts/ci/utils/slash_command_handler.py35-52](https://github.com/sgl-project/sglang/blob/94183a8d/scripts/ci/utils/slash_command_handler.py#L35-L52).

## The Tensor Dumper System

 The `_Dumper` system provides a robust infrastructure for capturing intermediate tensors during model execution. This is primarily used for cross-checking numerical consistency between implementations.

 
### `DumperConfig` and Initialization

 `DumperConfig` is a frozen dataclass [python/sglang/srt/debug_utils/dumper.py132-164](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dumper.py#L132-L164) that defines the dumper's behavior. Configuration can be loaded from environment variables using the `DUMPER_` prefix [python/sglang/srt/debug_utils/dumper.py168-169](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dumper.py#L168-L169) or from key-value pairs via `from_kv_pairs` [python/sglang/srt/debug_utils/dumper.py97-98](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dumper.py#L97-L98).

 Key configuration fields:

 
 - `enable`: Master toggle for dumping [python/sglang/srt/debug_utils/dumper.py133](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dumper.py#L133-L133).
 - `filter`: A regex string to filter tensors by their tag names [python/sglang/srt/debug_utils/dumper.py134](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dumper.py#L134-L134).
 - `dir`: Output directory for `.pt` files, defaults to `/tmp/dumper` [python/sglang/srt/debug_utils/dumper.py135](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dumper.py#L135-L135).
 - `grafter_enable`: Enables "Grafting", which allows replacing tensors in one run with tensors dumped from another run [python/sglang/srt/debug_utils/dumper.py148](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dumper.py#L148-L148).
 - `include_parallel_rank_in_filename`: Prevents collisions in multi-GPU setups by appending rank tags to filenames [python/sglang/srt/debug_utils/dumper.py163-164](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dumper.py#L163-L164).
 
 
### The `_Dumper` Class

 The `_Dumper` class [python/sglang/srt/debug_utils/dumper.py208](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dumper.py#L208-L208) manages the dumping state. It supports:

 
 - **Manual Dumping**: Using `dumper.dump(name, value, **tags)`.
 - **Non-Intrusive Dumping**: Automatically hooking into model forward passes using plugins like `_SGLangPlugin` or `_MegatronPlugin` [python/sglang/srt/debug_utils/dumper.py441-450](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dumper.py#L441-L450).
 - **HTTP Control**: A built-in server allows toggling the dumper and changing filters at runtime [python/sglang/srt/debug_utils/dumper.py145](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dumper.py#L145-L145).

## Dump Comparator Tool

 The `comparator` package provides advanced utilities to compare two dump directories. It handles complex distributed execution scenarios by "unsharding" tensors and aligning tokens.

 
### Comparison Entrypoint

 The main entrypoint [python/sglang/srt/debug_utils/comparator/entrypoint.py68-73](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/comparator/entrypoint.py#L68-L73) orchestrates the comparison:

 
 - **Metadata Loading**: Reads metadata from both baseline and target directories using `read_meta` [python/sglang/srt/debug_utils/comparator/entrypoint.py55](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/comparator/entrypoint.py#L55-L55).
 - **Token Alignment**: Computes an alignment plan if token indices differ between runs (e.g., due to different tokenization or sampling) [python/sglang/srt/debug_utils/comparator/entrypoint.py125-129](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/comparator/entrypoint.py#L125-L129).
 - **Bundle Matching**: Groups related shards (e.g., across TP ranks) into `TensorBundleInfo` objects using `match_bundles` [python/sglang/srt/debug_utils/comparator/entrypoint.py134-137](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/comparator/entrypoint.py#L134-L137).
 - **Numerical Check**: Compares the resulting tensors using `compare_bundle_pair` [python/sglang/srt/debug_utils/comparator/bundle_comparator.py128-143](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/comparator/bundle_comparator.py#L128-L143).
 
 
### Unsharding and Numerical Comparison

 For distributed models, the `UnsharderPlan` [python/sglang/srt/debug_utils/comparator/aligner/unsharder/types.py27](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/comparator/aligner/unsharder/types.py#L27-L27) determines how to reconstruct a global tensor from shards (e.g., TP4 concat). The `execute_unsharder_plan` function [python/sglang/srt/debug_utils/comparator/aligner/unsharder/executor.py10-11](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/comparator/aligner/unsharder/executor.py#L10-L11) applies operations like `ConcatParams`, `ReduceSumParams`, or `PickParams`.

 Numerical metrics include:

 
 - **Difference Metrics**: Max Absolute Difference and Relative Difference [python/sglang/srt/debug_utils/dump_comparator.py192-196](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dump_comparator.py#L192-L196).
 - **Downcast Check**: If dtypes mismatch, it attempts to downcast to the smaller dtype to check if the error is due to precision loss [python/sglang/srt/debug_utils/dump_comparator.py169-182](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dump_comparator.py#L169-L182).
 - **Shape Unification**: Squeezes leading singleton dimensions via `_try_unify_shape` [python/sglang/srt/debug_utils/dump_comparator.py122](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/debug_utils/dump_comparator.py#L122-L122).

### Nightly Precision Regression Testing

 The CI registry system allows marking tests as `nightly`. This is used to run expensive numerical precision tests periodically to catch regressions in model outputs.

 
 - `register_cuda_ci(nightly=True)` [test/registered/debug_utils/test_dumper.py53](https://github.com/sgl-project/sglang/blob/94183a8d/test/registered/debug_utils/test_dumper.py#L53-L53)
 - `register_amd_ci(nightly=True)` [test/registered/debug_utils/test_dumper.py54](https://github.com/sgl-project/sglang/blob/94183a8d/test/registered/debug_utils/test_dumper.py#L54-L54)
 - `register_cpu_ci(nightly=True)` [test/registered/debug_utils/comparator/test_entrypoint.py33](https://github.com/sgl-project/sglang/blob/94183a8d/test/registered/debug_utils/comparator/test_entrypoint.py#L33-L33)
 - The `test_nightly_precision_regression.py` script [scripts/ci/utils/slash_command_handler.py30](https://github.com/sgl-project/sglang/blob/94183a8d/scripts/ci/utils/slash_command_handler.py#L30-L30) is the primary entry point for these checks.
 
 
### Offline Mode for CI

 The CI pipeline supports offline/rerun modes via the `rerun-test.yml` workflow. This allows maintainers to rerun specific test commands on selected hardware without triggering the full CI suite [.github/workflows/rerun-test.yml1-59](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/rerun-test.yml#L1-L59). It includes logic to handle dependencies and installation scripts for different modes like `cuda`, `multimodal_gen`, and `cpu` [.github/workflows/rerun-test.yml7-14](https://github.com/sgl-project/sglang/blob/94183a8d/.github/workflows/rerun-test.yml#L7-L14).
