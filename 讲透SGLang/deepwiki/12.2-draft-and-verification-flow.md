  This page documents the internal execution flow for speculative decoding in SGLang, covering EAGLE-family algorithms (EAGLE, EAGLE2, EAGLE3), DFLASH, and N-gram speculative decoding. It details the implementation of draft token generation, tree building, and verification against the target model.

 
---

 
## Architectural Position

 When speculative decoding is enabled via `ServerArgs.speculative_algorithm` [python/sglang/srt/server_args.py469-472](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/server_args.py#L469-L472) the engine coordinates a draft worker and a target worker. The draft worker manages draft generation (via a smaller LLM, MTP layers, N-gram lookups, or fused draft heads) and tree construction, while the `TpModelWorker` [python/sglang/srt/managers/tp_worker.py37](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/tp_worker.py#L37-L37) serves as the target model for verification.

## Execution Flow: Draft and Verify

 
### 1. Draft Token Generation (Tree Building)

 The draft worker generates a candidate tree.

 
 - **EAGLE Tree**: Candidates are organized into a tree. The function `build_eagle_verify_input` [python/sglang/srt/speculative/eagle_worker_common.py82-83](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_worker_common.py#L82-L83) constructs the verification metadata from the draft steps.
 - **Draft Forward**: The `EagleDraftWorker` executes a draft forward pass, which can be accelerated via CUDA graphs [python/sglang/srt/speculative/eagle_draft_cuda_graph_runner.py80-94](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_draft_cuda_graph_runner.py#L80-L94)
 - **N-gram Lookup**: `NGRAMWorker` retrieves tokens from a host-side corpus based on the sequence suffix via the `NgramCorpus` class [python/sglang/srt/speculative/ngram_worker.py115-124](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/ngram_worker.py#L115-L124)
 - **DFLASH Draft**: `DFlashWorkerV2` uses a `_DflashDraftSampler` to perform greedy argmax over the target LM head inside the draft CUDA graph [python/sglang/srt/speculative/dflash_worker_v2.py94-104](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/dflash_worker_v2.py#L94-L104)
 
 
### 2. Target Model Verification

 The target model verifies the draft tree in a single forward pass.

 
 - **Input Preparation**: `EagleVerifyInput.generate_attn_arg_prefill` creates the attention metadata, including `qo_indptr` and `kv_indices` using Triton kernels [python/sglang/srt/speculative/eagle_info.py82-138](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_info.py#L82-L138)
 - **Verification Logic**: The target model runs a forward pass in `ForwardMode.TARGET_VERIFY`. The results are then processed by `run_eagle_verify` [python/sglang/srt/speculative/eagle_worker_common.py86](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_worker_common.py#L86-L86) to determine which tokens are accepted.
 - **Sampling**: If rejection sampling is enabled, `sample_draft_proposal` is used to draw from the draft distribution `q` [python/sglang/srt/speculative/spec_utils.py167-176](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/spec_utils.py#L167-L176)
 
 
### 3. Synchronization

 
 - **KV Cache Management**: Accepted tokens are committed to the target KV cache. The draft model's KV cache is synchronized during the `draft_extend` phase [python/sglang/srt/speculative/eagle_draft_extend_cuda_graph_runner.py77-91](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_draft_extend_cuda_graph_runner.py#L77-L91)
 - **Hidden State Passing**: EAGLE algorithms pass hidden states from the target model back to the draft model to seed the next iteration [python/sglang/srt/speculative/eagle_info.py153-156](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_info.py#L153-L156)

## Multi-Layer Speculative Decoding (MTP)
