  The gRPC server interface in SGLang provides a high-performance, strongly-typed entry point for LLM and VLM serving. While the HTTP interface is commonly used for general web integration and OpenAI compatibility, the gRPC interface is designed for high-throughput environments, low-latency communication, and robust integration with microservices architectures.

 
## Overview and Purpose

 The gRPC implementation in SGLang acts as a thin wrapper that delegates core serving logic to specialized components capable of handling high-concurrency requests. It facilitates communication between external clients and the internal SGLang request management system, ensuring that inputs are correctly tokenized, scheduled, and processed by the model engine.

 The server is initiated via the `serve_grpc` entry point, which requires the `smg-grpc-servicer` package to handle the underlying protocol buffers and service definitions [python/sglang/srt/entrypoints/grpc_server.py156-166](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/grpc_server.py#L156-L166)

 
### Key Features

 
 - **Strong Typing**: Uses Protobuf definitions for request and response structures, reducing serialization overhead and parsing errors.
 - **Streaming Support**: Native gRPC streaming for real-time token delivery.
 - **High Throughput**: Optimized for low-latency overhead compared to standard REST/HTTP implementations.
 - **HTTP Sidecar**: A lightweight `aiohttp` sidecar is started alongside the gRPC server to expose metrics and admin controls [python/sglang/srt/entrypoints/grpc_server.py4-11](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/grpc_server.py#L4-L11)
 - **Rust-based Extension**: SGLang integrates a Rust-based gRPC pipeline via the `smg-grpc-servicer` package.
 - **Profiling Control**: Supports dynamic profiling via `/start_profile` and `/stop_profile` endpoints on the sidecar [python/sglang/srt/entrypoints/grpc_server.py78-84](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/grpc_server.py#L78-L84)

## Implementation Details

 The SGLang gRPC interface is encapsulated in `python/sglang/srt/entrypoints/grpc_server.py`.

 
### Administrative Endpoints and Profiling

 The gRPC sidecar provides admin routes for profiling the engine, even when the main interface is gRPC [python/sglang/srt/entrypoints/grpc_server.py78-84](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/grpc_server.py#L78-L84)

 
 - **`/start_profile`**: Constructs a `ProfileReq` with type `START_PROFILE`. It respects environment variables like `SGLANG_PROFILE_WITH_STACK` and `SGLANG_PROFILE_RECORD_SHAPES` [python/sglang/srt/entrypoints/grpc_server.py86-120](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/grpc_server.py#L86-L120)
 - **`ProfileReq` Handling**: Requests are sent via the `request_manager.send_communicator_req` to the `profile_communicator` on the scheduler [python/sglang/srt/entrypoints/grpc_server.py121-123](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/grpc_server.py#L121-L123)
 - **Result Validation**: The `_check_communicator_results` helper processes the list of results from the scheduler to ensure success across all distributed workers [python/sglang/srt/entrypoints/grpc_server.py67-75](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/grpc_server.py#L67-L75)
 
 
### Metrics and Sidecar

 The server starts an `aiohttp` sidecar on a port usually calculated as `--port + 1` [python/sglang/srt/entrypoints/grpc_server.py179-183](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/grpc_server.py#L179-L183)

 
 - **Prometheus Integration**: The `_add_metrics_routes` function adds a `/metrics` endpoint that uses `prometheus_client.multiprocess.MultiProcessCollector` to aggregate metrics from the various SRT processes [python/sglang/srt/entrypoints/grpc_server.py40-64](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/grpc_server.py#L40-L64)
 - **Lifecycle**: The sidecar is started via `_start_sidecar_server` which manages the `web.TCPSite` lifecycle [python/sglang/srt/entrypoints/grpc_server.py26-38](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/entrypoints/grpc_server.py#L26-L38)

### Server Launch Logic

 The `run_server` function in `launch_server.py` acts as the dispatcher. If `cfg.smg_grpc_mode` is enabled (via `--smg-grpc-mode` or the legacy `--grpc-mode`), it executes the `serve_grpc` entry point [python/sglang/launch_server.py36-43](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/launch_server.py#L36-L43)

## Rust Integration and sglang-server

 The gRPC ecosystem in SGLang is enhanced by Rust components for performance-critical pathing.

 
 - **sglang-server**: A Rust frontend pipeline that manages high-throughput request ingestion.
 - **sglang-grpc**: The Rust-based gRPC extension that provides the underlying servicer logic.
 - **IPC**: The bridge between the Rust frontend and Python backend utilizes efficient communication channels to minimize the overhead of cross-language boundaries.
