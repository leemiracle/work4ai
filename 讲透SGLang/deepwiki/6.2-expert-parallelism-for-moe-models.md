  Expert Parallelism (EP) is a distributed execution strategy for Mixture-of-Experts (MoE) models that partitions expert weights across multiple devices (typically GPUs). This reduces memory consumption per device and enables parallel computation by routing tokens dynamically to the appropriate device holding the corresponding expert weights. SGLang implements a robust, high-performance EP system supporting multiple communication backends, sophisticated expert load balancing (EPLB), and elastic infrastructure with overlap optimizations.

 
## Architecture Overview

 The Expert Parallelism pipeline comprises four sequential stages:

 
 - **TopK Routing:** Using a learned gating mechanism, tokens are routed to their top-K experts. The routing produces sparse top-K expert weights and corresponding expert indices.
 - **Token Dispatch:** Tokens are distributed (all-to-all communication) to physical devices based on their assigned experts. Various backends handle hardware-specific optimizations for this all-to-all communication.
 - **Expert Computation:** Each device locally computes its assigned experts’ forward pass on dispatched tokens utilizing optimized MoE kernels and quantization strategies.
 - **Output Combine:** The outputs computed by each expert-device are combined and reordered to match the input token order.
 
 This modular separation allows selecting different dispatch and computation backends independently.

## Expert Load Balancing (EPLB)

 EPLB mitigates hardware stragglers by dynamically remapping logical experts to physical ranks based on token traffic.

 
 - **`EPLBManager`**: Orchestrates the rebalancing process every `eplb_rebalance_num_iterations` [python/sglang/srt/eplb/eplb_manager.py30-73](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/eplb/eplb_manager.py#L30-L73) It triggers `rebalance()` which checks if the imbalance exceeds thresholds [python/sglang/srt/eplb/eplb_manager.py96-133](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/eplb/eplb_manager.py#L96-L133)
 - **`ExpertLocationMetadata`**: Tracks the `physical_to_logical_map` and `logical_to_all_physical_map` [python/sglang/srt/eplb/expert_location.py62-91](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/eplb/expert_location.py#L62-L91)
 - **ExpertDistributionRecorder**: Records expert utilization metrics during forward passes [python/sglang/srt/eplb/expert_distribution.py82-134](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/eplb/expert_distribution.py#L82-L134)
 - **Rebalance Logic**: Uses `logical_count` from the recorder to compute new metadata and updates the model via `update_expert_location_with_recovery` [python/sglang/srt/eplb/eplb_manager.py126-173](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/eplb/eplb_manager.py#L126-L173)

## Elastic Expert Parallelism

 Elastic EP allows the MoE system to scale or recover from rank changes without a full restart.

 
 - **`ElasticEPStateManager`**: Tracks `active_ranks`, `effective_ep_size`, and `pending_ep_size` [python/sglang/srt/elastic_ep/elastic_ep.py47-79](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/elastic_ep/elastic_ep.py#L47-L79)

 - **Expert Backup**: Works in tandem with `ExpertLocationUpdater` to fetch expert weights from redundant locations if a primary rank is unavailable.

## Expert Pack Utility

 The `tools/expert_pack` utility is used for building and validating expert pack files in the **SGLANG-EXPERTPACK-v1** format. This format optimizes model loading for MoE models by grouping expert weights to minimize disk I/O and facilitate distributed loading.
