## Purpose and Scope

 This page provides a detailed technical overview of the model execution pipeline in SGLang, focusing on the transformation of scheduler-level batches into GPU tensors, the handling of different forward pass modes (`prefill`, `decode`, `extend`, `mixed`), and the processing of outputs. Key components detailed here include `ModelRunner`, the forward pass modes defined by `ForwardMode`, and the processing stages involving `LogitsProcessor` and `Sampler`.

 This documentation builds on the batching strategy and memory management concepts introduced in [4.2 Scheduler and Batch Formation](https://github.com/sgl-project/sglang/blob/94183a8d/4.2 Scheduler and Batch Formation) and precedes performance optimizations detailed in [4.4 CUDA Graphs and Performance Optimizations](https://github.com/sgl-project/sglang/blob/94183a8d/4.4 CUDA Graphs and Performance Optimizations) It also connects with sampling mechanics explained in [17.3 Sampling Algorithms](https://github.com/sgl-project/sglang/blob/94183a8d/17.3 Sampling Algorithms)

 
## System Overview

 At a high level, model execution in SGLang converts a high-level CPU-resident batch (`ScheduleBatch`) into a serialized IPC-friendly batch (`ModelWorkerBatch`), which is then transformed into a low-level GPU-resident batch (`ForwardBatch`) that the model can process efficiently. The class `ModelRunner` orchestrates forward passes, switches between operational modes, and processes model outputs.

### ForwardMode Enumeration

 The `ForwardMode` enum defines modes controlling the model's forward pass behavior.

 
| Mode | Description | Use Case / Comments |
|---|---|---|
| EXTEND | Extend with new prompt tokens (prefill) | Initial batch forward for token prefix computation |
| DECODE | Decode one token per sequence | Standard autoregressive token decoding |
| MIXED | Contains both extend and decode | Overlapping prompt chunks + token decode phases |
| TARGET_VERIFY | Verify draft tokens in speculative decoding | Speculative token tree verification |
| DRAFT_EXTEND_V2 | Draft tokens generation (EAGLE v2) | Produces multi-token draft sequences |
| SPLIT_PREFILL | Prefill split for PD multiplexing | Partial prefill across layers |
| DLLM_EXTEND | Discrete Diffusion LLM prefill | Specific to diffusion LLM use cases |

## ModelRunner and Runner Backend

 `ModelRunner` orchestrates the execution, but the actual execution path (Eager vs. CUDA Graph) is handled by specialized `BaseRunner` implementations.

 
### EagerRunner

 `EagerRunner` handles non-CUDA-graph execution. It maintains a fixed-max static buffer (`_eager_registry`) to avoid frequent reallocations. It copies the live batch into these static buffers during `load_batch`.

 
### CUDA Graph Capture

 CUDA graphs are captured during startup to optimize the decode path. `capture_cuda_graphs` initializes the `EagerRunner` first so that subsequent graph captures can coalesce onto the same static buffers.

## Logits and Output Processing

 
### LogitsProcessor

 The `LogitsProcessor` computes logits from hidden states. It supports:

 
 - **Tensor Parallelism:** Gather logits across TP ranks.
 - **Logprob Computation:** Computing logprobs for input tokens (prefill) or next tokens (decode).
 - **Softcapping:** In-place logit softcapping for models like Gemma 2.
 
 
### Sampler

 The `Sampler` performs token selection. It handles:

 
 - **Logits Preprocessing:** Applying custom logit processors and sanitizing NaN values.
 - **Sampling Algorithms:** Greedy, Top-K, Top-P, and Min-P sampling using backends like `flashinfer` or `pytorch`.
 - **Deterministic Sampling:** Ensuring reproducibility for RL or testing.

## Specialized Execution: Split Prefill

 For disaggregation and PD-multiplexing, SGLang supports `forward_split_prefill`. This allows the prefill pass to be executed in chunks of layers rather than all at once, enabling finer-grained scheduling and memory management.

## Metrics Collection

 Model execution performance is monitored via the `SchedulerMetricsReporter`. It tracks:

 
 - **Wall Time:** Total time for the forward pass.
 - **Throughput:** Tokens per second for prefill and decode.
 - **GPU Execution Time:** Using `DeviceTimer` to measure actual kernel execution time.
