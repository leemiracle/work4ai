## Purpose and Scope

 This document describes the hierarchical multi-tier storage system implemented by HiCache in the SGLang codebase. HiCache extends the basic `RadixCache` to a multi-tiered KV cache architecture designed to increase caching capacity beyond the limits of GPU memory. It orchestrates storage across three tiers:

 
 - **L1 (Device/GPU memory):** Fastest access, smallest capacity.
 - **L2 (Host/CPU memory):** Larger capacity with slower access, acts as a staging area.
 - **L3 (Distributed Storage Backends):** Virtually unlimited capacity, highest latency.
 
 The `HiRadixCache` class ([python/sglang/srt/mem_cache/hiradix_cache.py81-184](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/hiradix_cache.py#L81-L184)) builds on `RadixCache` ([python/sglang/srt/mem_cache/radix_cache.py24-47](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/radix_cache.py#L24-L47)), tracking KV cache data locations and managing transitions between tiers. The `HiCacheController` ([python/sglang/srt/managers/cache_controller.py16-48](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/cache_controller.py#L16-L48)) manages data movement and coordinates interactions with storage backends.

 HiCache relies on specialized memory pools for each tier, including the `HiSparse` allocator to support large/sparse KV cache workloads, and employs an event-driven system to synchronize cache state changes and asynchronous I/O operations.

## HiCacheController: Orchestrating Tier Operations

 The `HiCacheController` class handles asynchronous transfers and coordinates between device, host, and storage.

 
### Core Responsibilities

 
| Responsibility | Description | Reference |
|---|---|---|
| Write to L2 | Transfers KV cache tokens evicted from device memory into host pool | CacheOperation execution (python/sglang/srt/managers/cache_controller.py102-173) |
| Load to L1 | Loads tokens from host pool into device KV cache on demand | HiCacheAck for transfer completion (python/sglang/srt/managers/cache_controller.py179-190) |
| Prefetch from L3 | Asynchronous fetching of tokens from external storage to host | PrefetchOperation (python/sglang/srt/managers/cache_controller.py209-210) |
| Backup to L3 | Asynchronous persistence of host tokens into storage backend | HiCacheStorageConfig (python/sglang/srt/mem_cache/hicache_storage.py28) |

 
### Layer Synchronization

 `LayerLoadingEvent` ([python/sglang/srt/managers/cache_controller.py53-70](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/cache_controller.py#L53-L70)) and `LayerDoneCounter` ([python/sglang/srt/managers/cache_controller.py71-99](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/cache_controller.py#L71-L99)) provide fine-grained synchronization for layer-wise token transfers, allowing overlap between computation and KV loading.

## L2 Host Memory Management

 The L2 tier is implemented with specialized host memory KV pools. These pools maintain host-side copies of KV cache to back the GPU device memory.

 
### Host Pool Classes

 
 - **MHA/MLA Host Pools:** `MHATokenToKVPoolHost` and `MLATokenToKVPoolHost` implement host memory pools for attention models ([python/sglang/srt/mem_cache/hiradix_cache.py92-119](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/hiradix_cache.py#L92-L119)).
 - **Logical Host Pool:** `LogicalHostPool` ([python/sglang/srt/mem_cache/memory_pool_host.py52-79](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/memory_pool_host.py#L52-L79)) manages page-aligned token slots but holds no KV tensor, acting as a stable anchor for compressed side pools.
 - **DeepSeek V4 Paged Host Pool:** `DeepSeekV4PagedHostPool` ([python/sglang/srt/mem_cache/memory_pool_host.py174-217](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/memory_pool_host.py#L174-L217)) implements host mirrors for DeepSeek V4 paged KV sub-pools.
 - **Custom Allocators:** `MooncakeHostTensorAllocator` ([python/sglang/srt/mem_cache/storage/mooncake_store/mooncake_store.py35-67](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/storage/mooncake_store/mooncake_store.py#L35-L67)) allows storage backends to provide specialized host memory (e.g., RDMA-registered memory).

## HiSparse Memory Pool

 HiSparse is a specialized memory allocation method for extremely sparse KV caches, enabling efficient handling of very long or sparse attention contexts.

 
 - `DeepSeekV4HiSparseTokenToKVPoolAllocator` ([python/sglang/srt/managers/schedule_policy.py46-48](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/schedule_policy.py#L46-L48)) manages sparse token-to-KV mapping for DeepSeek-V4 models.
 - `HiSparseHostPoolMixin` ([python/sglang/srt/mem_cache/memory_pool_host.py174](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/memory_pool_host.py#L174-L174)) adds host-side page-granular management to host memory pools.
 - Transfers for these sparse pools use optimized kernels like `transfer_cache_dsv4_mla` ([python/sglang/srt/mem_cache/memory_pool_host.py15](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/memory_pool_host.py#L15-L15)).

## KV Cache Events System

 HiCache uses an event-driven system to synchronize cache state changes and asynchronous I/O.

 
 - `StorageMedium` ([python/sglang/srt/disaggregation/kv_events.py24](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/kv_events.py#L24-L24)) defines where data resides (e.g., `DRAM`, `SSD`, `REMOTE`).
 - Events like `BlockStored` and `BlockRemoved` ([python/sglang/srt/disaggregation/kv_events.py22-23](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/kv_events.py#L22-L23)) are published when cache blocks move between tiers.
 - `HiRadixCache` uses a `load_cache_event` ([python/sglang/srt/mem_cache/hiradix_cache.py146](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/hiradix_cache.py#L146-L146)) to signal when a load-back operation from host/storage to device has completed, allowing the scheduler to proceed.
 
 **Sources:** [python/sglang/srt/disaggregation/kv_events.py21-25](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/disaggregation/kv_events.py#L21-L25) [python/sglang/srt/mem_cache/hiradix_cache.py146-184](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/hiradix_cache.py#L146-L184)

## Data Transfer and I/O Backends

 Efficient transfer between GPU and host memory uses platform-specific kernels selected at runtime ([python/sglang/srt/mem_cache/memory_pool_host.py23-32](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/mem_cache/memory_pool_host.py#L23-L32)):

 
 - **MLA Transfers:** `transfer_kv_all_layer_mla` and `transfer_kv_all_layer_mla_lf_pf`.
