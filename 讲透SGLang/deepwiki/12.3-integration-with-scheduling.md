## Purpose and Scope

 This page describes how speculative decoding (e.g., EAGLE, N-gram, MTP) integrates with the SGLang request scheduling system. It details the mechanisms by which speculative requests flow through the scheduler, how batches are formed for verification and drafting phases, and how specialized workers are orchestrated. This includes the management of the KV cache for cross-iteration data relay, the integration of specialized `ForwardMode` states, and the implementation of adaptive speculative decoding.

 For the core EAGLE algorithm and architecture, see [12.1 EAGLE Algorithm and Architecture](https://github.com/sgl-project/sglang/blob/94183a8d/12.1 EAGLE Algorithm and Architecture) For the detailed generation and verification logic, see [12.2 Draft and Verification Flow](https://github.com/sgl-project/sglang/blob/94183a8d/12.2 Draft and Verification Flow)

 
## Overview of Speculative Integration Points

 Speculative decoding integrates with the scheduling system at multiple levels: request initialization, batch formation, forward mode selection, and worker dispatch. The `Scheduler` orchestrates these components by determining whether to use a standard `TpModelWorker` or a specialized speculative worker.

## Request Initialization and Memory Reservation

 When speculative decoding is enabled, the system must reserve additional token slots in the KV cache to accommodate the draft tokens that will be verified in a single step.

 
 - **N-gram Reservation**: Reserves slots based on the `speculative_num_draft_tokens` parameter. The `NGRAMWorker` initializes its memory pool during `alloc_memory_pool` by retrieving the target worker's pools [python/sglang/srt/speculative/ngram_worker.py76-82](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/ngram_worker.py#L76-L82)
 - **EAGLE Reservation**: `EagleDraftWorker` manages its own KV cache pools. It uses `alloc_memory_pool` to initialize `req_to_token_pool` and `token_to_kv_pool_allocator` [python/sglang/srt/speculative/eagle_worker_v2.py197-208](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/eagle_worker_v2.py#L197-L208)
 - **Multi-Layer EAGLE**: For models using chain-style MTP (e.g., DeepSeek-V3 MTP), the `MultiLayerEagleDraftWorker` maintains a `draft_runner_list` and handles specialized hidden state propagation if `chain_mtp_hidden_states` is enabled [python/sglang/srt/speculative/multi_layer_eagle_worker_v2.py176-186](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/multi_layer_eagle_worker_v2.py#L176-L186)
 - **V2 Buffer Layout**: `EagleDraftInput.ALLOC_LEN_PER_DECODE` is set based on `speculative_num_steps * topk` or `speculative_num_draft_tokens` to prevent overflows during tree building [python/sglang/srt/speculative/multi_layer_eagle_worker_v2.py157-159](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/multi_layer_eagle_worker_v2.py#L157-L159)

## N-gram Worker Integration

 The `NGRAMWorker` provides a lightweight speculative mechanism using a local `NgramCorpus` implemented in C++.

 
 - **Drafting**: The worker retrieves potential suffixes from the corpus. It manages an external corpus via `add_external_corpus` [python/sglang/srt/speculative/ngram_worker.py164-165](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/ngram_worker.py#L164-L165)
 - **Verification**: Tokens are formatted into an `NgramVerifyInput`. It uses `reconstruct_indices_from_tree_mask` to align verification results with the KV cache [python/sglang/srt/speculative/ngram_worker.py6](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/ngram_worker.py#L6-L6)
 - **Corpus Management**: The `NgramCorpus` supports asynchronous loading and management of multiple named corpora [python/sglang/srt/speculative/ngram_worker.py115-124](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/ngram_worker.py#L115-L124)

## Batch Processing and Forward Modes

 The scheduler communicates the phase of speculative decoding to the `ModelRunner` via the `ForwardMode` attribute.

 
| ForwardMode | Phase | Description |
|---|---|---|
| DECODE | Standard Decode | Standard decoding step or target model verification python/sglang/srt/model_executor/forward_batch_info.py108-109 |
| DRAFT_EXTEND_V2 | Drafting (V2) | Fixed shape logits output in speculative V2 worker python/sglang/srt/model_executor/forward_batch_info.py118 |
| TARGET_VERIFY | Verification | Verification phase specifically for speculative candidates in the target model python/sglang/srt/model_executor/forward_batch_info.py115-116 |

## KV Cache Integration and Memory Management

 SGLang manages memory allocation for speculative verification using specialized kernels and allocators.

 
 - **Token Slot Allocation**: `assign_req_to_token_pool` maps request pool indices to the `req_to_token` table for the verification pass [python/sglang/srt/speculative/spec_utils.py43-48](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/spec_utils.py#L43-L48)
 - **Memory Safety**: `record_stream_for_v2_verify` ensures that GPU tensors used during speculative verification are not recycled by the PyTorch caching allocator while kernels are still executing on the forward stream [python/sglang/srt/speculative/spec_utils.py34](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/spec_utils.py#L34-L34)
 - **KV Indices Construction**: `generate_draft_decode_kv_indices` builds the indices for the EAGLE draft-decode phase, attending up to `max_context_len` slots [python/sglang/srt/speculative/spec_utils.py23-24](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/speculative/spec_utils.py#L23-L24)
 - **Two-Batch Overlap (TBO)**: `FutureMap` facilitates the relay of speculative extras (hidden states, topk indices) between overlapped batches to hide drafting latency [python/sglang/srt/managers/overlap_utils.py117-119](https://github.com/sgl-project/sglang/blob/94183a8d/python/sglang/srt/managers/overlap_utils.py#L117-L119)
