# 00 讲透AI for 职业 · 算法经验枢纽（应用延伸 1/4）

> **定位**：`讲透AI for 职业/` 已有 10 章（程序员/PM/设计师/...）。本文档萃取**AI 应用方法论**经验（AO1–AO8），与 371 条库联动——不是算法 DNA，是"AI 增强人类"的工程模式。

---

## §0 全局视角：AI for 职业 = "人类 + AI 协作模式"

```
不是 AI 替代职业, 是 AI 增强从业者
关键问题: 什么任务该交给 AI? 什么该留给人?
```

> 🔑 **核心 DNA**：**每个职业的 AI 应用本质都是"任务分解 + 人机分工"**——这是 AG7（规划-执行-反思）的职业化。

---

## §1 八条算法经验

### 算法经验 AO1：人机分工的决策框架

> ```
> 任务特性?
> ├── 高重复 + 低创造 → 全自动 (AI)
> ├── 高重复 + 高创造 → 半自动 (AI 草稿 + 人审)
> ├── 低重复 + 低创造 → 工具辅助 (人主导 + AI 查)
> └── 低重复 + 高创造 → AI 启发 (人主导 + AI 灵感)
> ```
>
> 算法本质：**与 T6 端到端 vs 流水线、R5 两阶段同构**——人机分工也是一种"流水线"。

### 算法经验 AO2：AI for 程序员 = 代码生成 + 审查

> - GitHub Copilot（行级补全）
> - Cursor（项目级重构）
> - Devin（ autonomous agent ）
>
> 算法本质：**从"补全"到"agent"的演化 = P1→P6→AG1 的工程化**（应用 P1 ICL、AG1 Agent 范式）。

### 算法经验 AO3：AI for PM = 文档 + 决策

> PRD 生成、用户反馈分析、A/B 测试设计。
>
> 算法本质：**结构化文档是 AI 最擅长的"格式化输出"**（应用 P7 结构化输出、FT8 SFT 格式）。

### 算法经验 AO4：AI for 设计师 = 创意发散 + 收敛

> Midjourney/DALL-E 发散，人收敛。
>
> 算法本质：**生成模型的"多样性"是创意工作的资产**（应用 GM9 CFG guidance、P4 Self-Consistency）。

### 算法经验 AO5：AI for 律师/医生 = 检索 + 警示

> RAG 检索案例/文献 + LLM 警示风险。
>
> 算法本质：**严肃领域必须"AI 辅助 + 人决策"**——合规与责任（应用 IN7 合规、G6 评估-纠错）。

### 算法经验 AO6：Prompt 工程的职业化

> 每个职业有自己的"prompt 模板"：
> - 程序员：代码 + 测试 + 文档
> - 律师：法条 + 案例 + 建议
> - 教师：知识点 + 例子 + 练习
>
> 算法本质：**模板 = 领域知识 + AI 通用能力的接口**（应用 P3 模板决定能力、FT8 SFT 格式）。

### 算法经验 AO7：AI 增强的"反退化"陷阱

> 长期用 AI 会让人**基础能力退化**（程序员不写样板代码、律师不查原始案例）。
>
> 算法本质：**与"过拟合"反向——人类能力"欠拟合"了**（应用 SL4 bias-variance、GE6 迁移学习）。

### 算法经验 AO8：职业演化的"收编规律"（强化 T10）

> LLM 收编职业的剧本（与 T10 同构）：
> - 高模式化任务 → 先被收编（客服、初稿）
> - 高创造任务 → 后被增强（设计、写作）
> - 高责任任务 → 难被替代（医生、法官）
>
> 算法本质：**职业被 AI 影响的速度 = 模式化程度 × 责任程度**（应用 T10 LLM 收编规律、F5 任务难度档）。
