# 03 · 可构造与结构——谱系、专利与维护记录:技术作为数据对象

> **本章回答五问之 Q4(可构造性与结构)**。
> **本质一句话**:技术史里"可构造"的不是技术本身,而是**技术的
> 组织方式**——专利是事件、谱系是树、采用是曲线、维护是记录
> 序列;而"结构"是技术生活自己的骨架:五段生命周期
> (生产-流通-挪用-维护-废弃)、S 形采用与系统锁定。

---

## 0. 开篇:一条专利是一个事件,一棵引用树是一部谱系

打开任何一项现代技术,你都会找到同一件东西:**一串专利号**。
一条专利=一个有日期、有权利主张、有分类号的法律事件;
把"本专利引用了谁"连起来,就得到一棵**技术谱系树**——
T 型车的祖先是stin gasoline carriage 的专利链,晶体管的
后代开枝散叶到整个信息产业。再把"每年有多少人开始用"
画出来,就是一条**采用曲线**。专利、谱系、曲线、维护工单
——技术虽是最日常的人类造物,其档案却出奇地结构化
(这是 01 章数字方法有浪可乘的根本原因)。

## 1. 什么是"可构造"的:五类技术对象

| 对象 | 数学化身 | 可构造性 | 构造中的坑 |
|------|---------|---------|-----------|
| **专利记录** | 事件 (日期, 分类, 权利人, 引用) | ✅ 完全可构造(公开 schema) | 专利≠实施(02 章降档):权利主张不是生产记录 |
| **技术谱系** | 树/引用图(父型→改型) | ✅ 高度可构造(04 章 C2) | 引用≠血缘:策略性引用(防诉讼)污染树 |
| **采用曲线** | 时间序列 {t, 渗透率} | ✅ 可构造(销量/存量数据) | 存量≠使用强度;官方统计口径随政权变 |
| **维护记录** | 事件序列 (工单/备件/岁修) | ✅ 可构造(02 章 T2 金矿) | 稀疏:多数维护不留痕,存档是幸存者 |
| **技术系统分层** | 休斯四层(器物/组件/系统/环境) | ✅ 半结构化(定性骨架) | 层间边界=判断;同物可多层 |

**不可构造的**:解释柔性的"弹性大小"、收束时刻的精确定位
(争论平息没有客观判据)、技术动量的"动量值"(00 章理论支的
定性概念——可排序,难定量)、"无缝之网"的无缝程度,
以及一切反事实(替代实验里"如果不"的分支,04 章边界)。

### 1.5 五类对象的最小数据模式(动手者的 schema)

```yaml
# 专利记录(04 章 C1 专利计量的字段源)
patent: {number: str, date: int, holder: str,
         ipc_class: [str],                # 分类号:跨库须声明版本
         cites: [str],                    # 被引专利→谱系边(04 章 C2)
         geo: str,                        # 申请地:流通研究的坐标
         source_tier: T3}                 # 专利默认 T3(02 章降档纪律)

# 谱系节点(技术家族树的节点)
lineage_node: {tech: str, parent: str,       # 父型(设计血缘或专利血缘,须声明哪种)
               first_commercial: int,        # 首次可证实施年(≠专利年)
               adopters_first_year: int, source_tier: T2..T4}

# 采用序列(一项技术在一个市场的渗透率时间序列)
adoption_series: {tech: str, market: str,
                  points: [[year, penetration]],   # 0..1
                  network_effect: float,           # 网络效应参数(实验断言②)
                  retrofitted: bool,               # 老技术是否加装新组件(断言③)
                  source_tier: T2..T4}

# 维护记录(技术的"病历";维护转向的数据地基)
maintenance_log: {artifact_id: str, date: str,
                  action: 保养|修理|升级|改装,     # retrofit=改装:改变替代动力学
                  parts: [str], downtime: str,
                  operator: str, source_tier: T2}
```

注意每条记录自带 `source_tier` 与"专利≠实施"的字段分离
(专利年与首次实施年是两个字段)——把 02 章的语言纪律写进
数据结构:**数据层自带证据等级,是技术史计算区别于普通
数据分析的第一特征**(法律史/军事史家族同款纪律,技术版
多了专利降档与实施年分离)。

## 2. 骨架一:五段生命周期(生产-流通-挪用-维护-废弃)

- 每项技术都可挂到五段上:生产(发明/设计/制造)、流通
  (贸易/授权/标准输出)、挪用(本土化/混血/改装)、维护
  (保养/修理/升级/retrofit)、废弃(拆解/二手/遗产化)
- 五段不是单向流水线:**二手市场让废弃回流流通**(00 章
  ASCII 图的回边);retrofit 让旧技术穿上新组件重返赛场
- 骨架的用法:叙事审计器——任何技术史叙事缺哪段,哪段就是
  它的意识形态(01 章 §8 框架眼)。传统创新叙事=只有生产段;
  维护转向=把后两段补齐;去殖民=把中间两段还给南方

## 3. 骨架二:采用曲线(扩散的时间形状)

- 通说(罗杰斯扩散理论/巴斯模型):采用随时间呈 **S 形**——
  慢启动(创新者)、拐点(早期大众)、饱和(滞后者的天花板);
  采用速度由感知属性决定:**相对优势/兼容性/可试用性/
  可观察性/复杂性**(家族实验的参数前三个即由此而来)
- **网络效应改写拐点**:价值随用户数增长的技术(电话/社交
  网络)拐点左移、更陡(实验断言②)——网络技术的采用是
  正反馈,不是普通 S
- **上限不是 100%**:采用天花板由互补品、基础设施与**旧技术
  的抵抗力**共同决定(实验断言③的伏笔)

## 4. 骨架三:维护与报废(技术的下游经济学)

- 维护记录=技术的**病历**:连续岁修(如都江堰)与断档
  修理本身就是兴衰曲线(00 章美之时刻③)
- **Retrofit 是结构操作**:老技术加装新组件(蒸汽机车加电控、
  燃油车改装、旧机床数控化)同时改变两件事——旧技术的
  有效寿命与新技术的市场上限:**替代不是替换,是协商**
  (实验断言③的史学含义;维护转向的核心命题之一)
- 报废的三条出路:拆解(材料回流)、二手(降级再用)、
  遗产化(博物馆化——回到幸存者偏置的源头,00 章④)

## 5. 从结构到比较:这套骨架买到了什么

- 五段生命周期 → 跨技术比较的坐标系(电动车与电灯的
  挪用段对照)
- S 形+网络效应 → "为什么有的技术十倍速普及"的可算答案
- 维护结构 → 兴衰的下游解释(技术不是死于被超越,
  常是死于没人修)
- 谱系树 → "发明中心主义"的可检验形态:把树画全
  (含失败分支),英雄叙事自动泄气

## 6. 构造合法性清单(动手前三问)

把任何技术材料变成数据结构之前,先过三问——本家族的
"类型检查":

1. **实施分离了吗**:专利年与首次可证实施年是两个字段吗?
   ——只有专利年的"技术史"是权利主张史(02 章 T3 降档)
2. **选样声明写了吗**:谱系收哪些分支、采用曲线取哪个市场
   口径,必须写在数据集头部——不同选样不可直接拼接比较
   (军事史家族同款纪律)
3. **快照与口径带了吗**:渗透率数据带统计机构与口径了吗?
   维护记录带执行者与停机时长了吗?——不带口径的数字
   是"还活着的曲线"

三问全过,数据才获得进入 [04 章走廊](04-技术史转代码.md)
的资格。**技术史计算的第一特征不是算法,是入库纪律**。

## 📌 收束

可构造的是**组织方式**(事件/树/曲线/病历),不可构造的是
**弹性与动量**;结构不是装饰,是比较研究的坐标系。
下一章把这些 schema 接上代码:专利计量/谱系构建/采用曲线
走廊:[04-技术史转代码](04-技术史转代码.md)。

**🧠 认知升维**:

- **病历眼**:读任何长命技术,先找它的维护记录——
  连续的岁修比辉煌的发明更能解释它的长寿
- **协商眼**:新旧技术相遇,先问协商条件(retrofit 空间、
  互补品、制度)——"替代"常是两个都活下来
- **分段眼**:任何技术叙事,先数它讲了几段——
  缺段处即立场
