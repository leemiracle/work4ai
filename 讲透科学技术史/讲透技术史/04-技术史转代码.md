# 04 · 技术史转代码——专利·谱系·采用曲线的最小走廊

> **本章回答五问之 Q5(问题→代码转换)**。
> **本质一句话**:技术史的问题一旦变成"关于专利/谱系/采用
> 数据的计算",就能进代码——专利变成计量、引用变成谱系、
> 扩散变成曲线;**唯一不可外包给代码的,是史学判断本身
> (选样、断代、归因、收束裁定)**。

---

## 0. 开篇:三条 S 曲线检验三个教科书直觉

「越优越的技术普及越快」「网络技术普及更凶猛」「老技术
加装新组件会推迟替代」——三个教科书级论断,能不能用数据说话?

[experiments/diffusion_s-curves.py](experiments/diffusion_s-curves.py)
内置三项技术的采用模拟(logistic 扩散,参数=相对优势/兼容性/
可试用性,呼应罗杰斯扩散理论;随机扰动用 random 固定种子),
跑出三个断言:

- **相对优势单调律**:其他属性不变,相对优势越高,
  到达 50% 渗透率的年份严格越早(断言①)
- **网络效应拐点左移**:网络效应参数调大,采用曲线的拐点
  在时间轴上左移(网络技术的正反馈——电话比冰箱凶猛的原因)
  (断言②)
- **Retrofit 现象**:老技术可加装新组件延长寿命时,新技术
  替代曲线整体右移,且**最终渗透率上限下移**——维护转向的
  定量面:替代不是替换,是协商(断言③)

但脚本同时打印史学纪律:模型输出是零模型(机器化 T6),
不是史实。**代码替你算形状,替不了你选参数**——
技术史数字化的第一课。

## 1. 可机械化边界(三件套之一)

**能进代码的**(技术数据化后的一切统计):

| 任务 | 机械化形式 |
|------|-----------|
| 专利计量 | 专利库 → 分类计数/共类网络/地理流向(政策研究标配) |
| 谱系构建 | 引用图 → 谱系树/分支截面积(技术家族的兴衰形状) |
| 采用曲线 | 销量/存量序列 → logistic 拟合/拐点定位/上限估计 |
| 维护挖掘 | 工单序列 → 故障间隔/停机成本/岁修连续度 |
| 报废与存活 | 技术存量表 → 存活曲线/退役年龄分布 |
| 时区/单位换算 | 古今计量 → 声明基准的统一量纲 |

**不能进代码的**(技术史的"不可判定域"):

1. **选样正当性**——哪些专利入谱系、哪个市场口径入曲线
   是史学判断;代码只能做敏感性分析(§7)
2. **收束裁定**——争论何时"算平息"没有客观判据
   (02 章SCOT 词汇;代码只能给讨论密度的衰减表)
3. **归因与动量**——"电气化重塑了城市"的因果强度,
   相关永远推不出因果
4. **模拟冒充档案**——S 曲线拟合输出是机器化 T6;
   当史实引用是数字时代新型硬错误(与军事史兵棋纪律同源)

> 边界的一句话:**代码是技术史的沙盘,不是车间**。
> 沙盘上推十遍,不如工单里对一次。

## 2. C1 专利计量走廊

| 字段 | 类型 | 约束/坑 |
|------|------|--------|
| patent_number / date | str / int | 优先权日 vs 申请日:跨库口径须声明 |
| ipc_class | [str] | 分类版本(IPC/CPC)是历史文件本身——类目随年代改 |
| cites | [str] | 策略性引用污染:防诉讼引用≠技术血缘 |
| geo / holder | str | 持有人≠发明人;跨国公司的申请地≠研发地 |
| source_tier | 固定 T3 | 专利=权利主张;实施证据须另接(02 章降档) |

典型问题:某技术领域三十年的地理重心迁移(去殖民研究的
计量面,01 章热线一)。红线:计量的是**声称的活动**,
向实施的外推每一步都要新的证据。

## 3. C2 谱系构建走廊(最小示例)

把引用关系压成树,先数分支——技术家族的兴衰在树形上
肉眼可见:

```python
# 谱系最小示例:cites 边 → 各世代分支数(04 章 C2 的种子)
LINEAGE = {"A": None, "B": "A", "C": "A", "D": "B", "E": "B", "F": "C"}

def generation(tech, memo={}):
    """返回世代深度(根=0);引用图成环则此函数不收敛——
    环=数据错误(策略性引用互引),须先检测后建树。"""
    if LINEAGE[tech] is None:
        return 0
    return 1 + generation(LINEAGE[tech])

def breadth_by_generation():
    """各世代的分支数:技术家族的'扩张速度表'。"""
    out = {}
    for tech in LINEAGE:
        out.setdefault(generation(tech), []).append(tech)
    return {g: len(v) for g, v in sorted(out.items())}

assert breadth_by_generation() == {0: 1, 1: 2, 2: 3}
# 树宽 1→2→3:扩张中;若某代宽度骤降,即'反向滞后'的谱系信号
```

十行代码完成的事:引用表 → 世代结构 + 扩张速度。
扩展方向:失败分支(无后代的节点)单列——**只画成功分支的
谱系是发明中心主义的几何形态**(00 章④偏置之二)。

## 4. C3 采用曲线走廊(✅ 已实现)

本家族实验 `experiments/diffusion_s-curves.py` 即本走廊成品:

- logistic 增长 + 罗杰斯感知属性参数(相对优势/兼容性/
  可试用性 → 内禀增长率)
- 网络效应项(增长率随渗透率提升——拐点左移,断言②)
- Retrofit 机制(旧技术存量分流出"加装新组件"的延长寿命仓,
  新技术上限被压——断言③)
- 全程 assert 自验 + 固定种子可复现

最小式:`x(t+1) = x(t) + r·x(t)·(1 − x(t)/K)`;
史学的用法不是预测,是**零模型**:与史实曲线对勘,
残差处即"该技术不普通的地方"(哪个参数被什么制度放大了)。

## 5. C4 维护记录挖掘走廊

维护工单序列 → 故障间隔分布、岁修连续度、停机成本线。
史学价值:技术的**兴衰下游指标**——发明记录会说谎
(专利≠实施),维护记录较诚实(没人白写工单)。
最小问题:某设备岁修记录连续 N 年后断档,断档年是
退役、迁址还是档案散失?三种假设三种检验(关联生产记录/
迁移档案/馆藏目录)——维护挖掘天然是交叉验证机。

## 6. C5 报废与存活走廊

技术存量表 → 存活曲线(某技术各年龄段的"仍在役"比例)。
与 C3 相对:C3 管进来(采用),C5 管离开(退役)。
retrofit 在 C5 里表现为**存活曲线的台阶抬升**(旧技术
加装新组件=续命),在 C3 里表现为**新技术的上限下移**
——同一机制的两面(实验断言③)。

## 7. §7 参数即史观:换参数重跑(使用本家族实验的正确姿势)

参数是史观的机器化(军事史兰彻斯特走廊同款警告):

- **相对优势谁定**:优劣是相关社会群体的判断(SCOT),
   不是物理量——换一群用户,r 变号都可能
- **网络效应强度**:基础设施密度、标准统一度都是历史变量;
   把 β 当常数等于假设制度环境不变
- **Retrofit 成本**:制度弹性(法规允不允许改装)决定
   ρ——政策一变,替代曲线整体换形(01 章热线三的定量面)

家族实验把纪律打印在结果之后——先看数字,再看声明,
这个顺序不许反。

## 8. 工程师落点(三件套之三)

- **今天的工程是明天的技术史**:API 文档、部署日志、
  postmortem 就是未来的 T2 档案——把它们写得可考
  (时间戳/版本/决策记录),是工程师对本学科的贡献面
  (与[工程与技术科学基础](../../讲透工程与技术科学基础/)
  的接口)
- **软件维护即维护转向的当代主战场**:维护占软件工程
  工作量一半以上是通说——legacy 系统的退休决策、
  refactor 与 retrofit 的边界,直接可用本家族的
  C3/C5 走廊思维
- **采用曲线思维做产品**:网络效应(断言②)与旧系统
  retrofit 阻力(断言③)不是历史趣闻,是迁移策略的
  两个一阶变量

## 📌 收束

五条走廊:C1(专利)管"谁声称",C2(谱系)管"谁传给谁",
C3(采用,已成)管"怎么进来",C4(维护)管"怎么活着",
C5(报废)管"怎么离开"——合起来正好是 00 章的五段生命
周期。五条共用一条边界:**选样、断代、归因、收束永远留在
人脑**。跑到这里,回头再看 00 章那句钉住本质的话:技术史
让器物开口说话;代码能帮你放大它的声音,发言稿还得史学来写。

**🧠 认知升维**:

- **零模型眼**:模拟的正确用法是"与史实对勘的对照物",
  不是"结论发生器"——残差处才是历史
- **参数即史观眼**:读任何计量结论,第一件事找参数来源,
  第二件事才是看输出
- **两面眼**:retrofit 在旧技术侧是续命、在新技术侧是天花板
  ——同一事件的两本账,工程决策(迁移/兼容)同款思维
