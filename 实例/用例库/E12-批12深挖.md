## 组内横断发现

1. **MCP+A2A 双协议成 agent 互操作标配**：go-micro（gateway/mcp + gateway/a2a，agent.go:L30）、adk-python（McpToolset + RemoteA2aAgent 按 well-known path 拉 agent card）、screenpipe（screenpipe-mcp 供 Claude/Cursor 查个人历史）三家从"服务框架/SDK/数据引擎"三个方向汇聚到同一组协议。
2. **确定性重放三部曲（本批最强共性）**：datasets 用指纹链命中缓存跳过计算、adk-python 用 ReplayInterceptor 对已完成节点 fast-forward、go-micro 用 checkpoint Resume 不重放已完成工具调用——三家互不相识的仓库都选择"历史扫描 + 内容/状态标识"实现幂等续跑，是 Agent 记忆系统设计的收敛解。
3. **对立设计：六行脚本 vs 事件溯源引擎**：gpt-crawler 全部业务 6 行（main.ts）与 L1B3RT4S 十行 README 走"数据即程序"极简极；adk-python/go-micro 则把可恢复性做到每节点/每 run 检查点——同为"为 LLM 服务"的工程在重量谱系两端，且都成立。
4. **版本化即治理**：onnx 的 IR/opset 双版本号 + VERSION_TABLE、L1B3RT4S 按模型代际（Gemini 1.0→3.0）归档攻击演化、excelize 对 ECMA-376 标准位级兼容——三者共同对抗"上游规范漂移"，其中 L1B3RT4S 是罕见地把"攻击面版本史"当正经版本矩阵维护的仓库。
5. **数据边界的两极分化**：screenpipe 把 100% 本地 + 自研 PII 模型当核心卖点，openui/recommenders 则天然云侧（token 记账/Azure operationalize）——同一批 LLM 应用工程在"数据出不出机器"上走向相反的产品哲学。
