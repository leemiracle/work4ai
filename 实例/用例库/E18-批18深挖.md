### n8n-io/self-hosted-ai-starter-kit（配置考古卡）
- **DeepWiki**：19 章全索引（1-Overview → 6-Glossary）；DW 指出这是"从 git clone 到可跑 AI 工作流的最快路径"，显式声明非生产用途（README:L138-141）。

- **工程决策**：DW 1.3 四原则"Simplicity Over Completeness / Learning-Focused / Opinionated but Extensible / Privacy-First"； opiniated 栈（n8n+Ollama+Qdrant+PG）用"替用户做完选型"换决策疲劳。
- **教学映射**：透视Agent系统工程（本地 AI 基础设施组装的最小标本）+ RAG（本地向量栈实物）
- **一句话本质**：把一台笔记本变成不出网的迷你 AI 机房，全部智慧浓缩在一份 compose 文件的依赖与 profile 里。

### kyegomez/OpenMythos
- **DeepWiki**：25 章；深读 2.3 LTI-Stable Injection
- **架构模式**：Recurrent-Depth Transformer（RDT）单文件实现：**Prelude(2 层标准块) → RecurrentBlock(循环 T 次) → Coda(2 层) → LM head**（OpenMythos 类 main.py:L1007-1011，RecurrentBlock L910-930，DW）；README 明言是对传闻中 "Claude Mythos" 的**独立理论重构**，与 Anthropic 无关（README:L30）——谣言驱动的开源复刻。
- **核心数据结构**：`MythosConfig` dataclass 全景（本地 main.py:L17-81）：`max_loop_iters=16`(推理期循环深度)、`attn_type="mla"` 默认（kv_lora_rank=512/q_lora_rank=1536/qk_rope 64+nope 128——DeepSeek MLA 同款签名）、MoE `n_experts=64, n_shared_experts=2, n_experts_per_tok=4, expert_dim=512` 细粒度专家、`act_threshold=0.99`(ACT 停机阈值)、`rope_theta=500000`、`lora_rank=16`(深度方向 LoRA)；`__init__.py` 导出 mythos_1b→mythos_1t 七档预设规模（L19-27）。
- **核心算法/协议**：① **构造性稳定递归**：`LTIInjection` 把转移矩阵参数化在连续时间——`A_c = -exp(log_A)` 保证特征值全负，ZOH 离散化 `A = exp(Δ·A_c)` 使 A∈(0,1)，从而 ρ(A)<1 **由参数化结构保证而非靠训练碰运气**（main.py:L443-459，DW 2.3）；更新律 `h_{t+1} = A·h_t + B·e + Transformer(h_t, e)`（README:L107-111）；② ACT halting 累积概率达 0.99 提前停环；③ loop-index embedding + 每深度 LoRA 让同一层"知道自己在第几圈"；④ 深度外推：训练少圈、推理多圈（DW 6.2）；测试强制断言 `get_A()∈(0,1)` 严格开区间（test_main.py:L261-267）。
- **设计模式与工程决策**：① flash_attn 可选导入 try/except 降级（main.py:L8-13）；② 本地 keyfile 快照仅 401 行（截到 MLAttention），完整版证据链走 DW 行号——单文件仓库的"考古断层"；③ README 示例直接演示 `torch.linalg.eigvals(A)` 自检谱半径（README:L99-103）。
- **教学映射**：世界模型（latent reasoning：在潜空间做思维链而非生成中间 token）+ 神经网络架构（循环深度/稳定递归）
- **一句话本质**：用控制论的 ZOH 离散化给"一层顶十层"的循环推理上了数学保险丝。

## 组内横断发现

1. **旧平台包袱 vs AI 追新的对立轴**：t8y2/dbx vendor 五个 crate + 三个 git patch 死保 Win7/国产库（Cargo.toml:L6-27），electerm 承诺 glibc 2.17+/LoongArch 新旧世界（README:L72），CARLA 却让 ue4-dev/ue5-dev 双分支并行（README:L20）——工具类仓库把"向后兼容"当第一工程约束，而 botpress 已在用 TypeScript 7 原生预览编译（package.json:L44）。同批两侧的"时间箭头"方向相反。

2. **MCP 正在吞噬桌面/DevOps 工具的 AI 接口层**：onedev 的 TodResource 让外部 agent 直查 Issue/PR/Build（DW 7.4），dbx 内置 dbx-mcp crate 让 Claude Code 直连数据库（README:L80-81），electerm 做 MCP Widget（DW 11.2），midscene 提供 Skills/MCP 通道（DW 6.5）——四仓不约而同把"被 AI 调用"做成一等能力，与"调用 AI"（各自内嵌的 LLM 助手）形成双向接口。

3. **AI 身份的工程化落地路径分化**：onedev 给 AI 发正式账号（`User.Type.AI` + `ai@onedev` + 防通知死循环 + 容器化 runAs 隔离，DW 7.4）；botpress 用 `bot.on.event` 把 AI 行为写成可 lint 幂等状态机（bugbuster 标签/评论生命周期）；两案共同点是把 AI 当"有权限、可审计、可重放"的系统公民而非黑盒 API。

4. **异构接入统一靠"归一化适配器 + 双向映射"**：midscene 的 LocateResultAdapter 把 [0,1]/[0,1000]/点式 bbox 统一为 PixelBbox（DW 4.3），botpress 的 ChatIdStore byFid/byId 双视图 + DynamoDB 条件写防 ID 冲突（dynamo-db-store.ts:L104-110），dbx 的 build_dsn 把五种 JDBC 方言折算为 ws/wss（config.rs:L82-108）——三仓面对的是同一类问题：外部世界的格式方言，只能靠边界处的翻译层消化。

5. **稳定性的三种写法**：OpenMythos 把稳定性写进**参数化结构**（ZOH 离散化构造性保证 ρ(A)<1，DW 2.3），electerm 写进**迁移楼梯**（v*.js 版本阶梯逐级执行，migrate/index.js:L36-82），dbx 写进**运行时卫生**（游标空闲超时+缓存 TTL+条件写，driver.rs:L23-54）——数学保证、数据演化、运维节律三条路殊途同归。
