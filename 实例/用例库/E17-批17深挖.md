- **核心算法/协议**：dvc.add 四步：建 Stage→哈希入缓存 ODB→写 .dvc 指针文件→原文件进 .gitignore（DW 1 Data Flow）；哈希算法路由：md5(3.x 默认)/md5-dos2unix(2.x 遗留，规范化换行符)/etag(S3/GS/Azure)/checksum(HDFS)，按 hash_name 自动分发到对应 ODB（output.py:L66-80, L407-423, data_cloud.py:L157-350）；`@locked` 装饰器包裹写操作：获取 repo.lock→`_reset()` 失效缓存属性（config/index/dvcfs/dvcignore）→执行→再 reset→释放，支持 `_lock_depth` 可重入（repo/__init__.py:L55-62, L664-675）；transfer() 在 staging ODB/本地缓存/远端 ODB 间搬对象（output.py:L752-820）。
- **设计模式与工程决策**：① 远程存储全插件化外置（dvc-s3/dvc-gs 独立包）+ fsspec entry point 注册，任何 fsspec 文件系统皆可当远端（pyproject.toml:L139-149）；② Facade(Repo)+Strategy(FileSystem)+Observer(Index)+Decorator(@locked/@scm_context) 六模式并用（DW 1 Design Patterns 表）；③ 数据住内容寻址缓存、Git 只存元数据指针——Git 对象模型向大数据的移植。

## 组内横断发现

1. **"为 LLM 压缩世界"三兄弟**：gitingest（仓库→文本）、Figma-Context-MCP（设计树→CSS 树）、dvc（大数据→内容寻址指针）本质同构——把巨大原始表示坍缩为 token 友好的有损表示；前两者甚至共享"统计+树骨架+内容"输出范式与树形序列化，是上下文工程的一体两面。
2. **确定性校验器外挂成为 Agent 工程共识**：plandex 用 tree-sitter 语法验证+XML 自纠协议+whole-file 兜底管代码正确性，ai-berkshire 用 `decimal.Decimal` 验算+双源交叉+随机抽样审计管金融数字——两家信条一致：LLM 输出不可直信，必须用非 LLM 的确定性闭环兜底。
3. **热状态与宿主解耦**：cockpit-tools 把 OAuth 凭证从 IDE 抽成可切换账号池、plandex 把对话与变更从工作区抽成可 rewind 的 plan 分支沙箱、open-saas 把 SaaS 通用件从业务代码抽成 DSL——三域共同模式：可管理的边界=可替换的模块。
4. **内容寻址/哈希去重跨域复现**：dvc 的 md5 分桶缓存（output.py:L529-533）、Figma MCP 的 SHA-1 截断样式去重（built-in.ts:L61-88）、Doris 的 rowset 版本合并去重——hash 驱动 dedup 是从设计工具到版本控制到分析数据库的通用物理层技术。
5. **内容型仓库的治理已工程化**：awesome-artificial-intelligence 用机器人周审+反配额编辑方针（README:L14-16）、ai-berkshire 用实盘业绩锚定+统一 Checklist、open-saas 用 dope.sh 模板同步脚本——"文档/清单仓库"的维护纪律（审计、同步、评分标准化）不输代码仓库，且 ai-berkshire 与 open-saas 均把 llms.txt/SKILL.md 类 Agent 接口当一等资产（apache/doris 的 12 个 AGENTS.md 同理）。
