### headroomlabs-ai/headroom
- **DeepWiki**：成功 — 1-Overview, 3.5-CCR: Compress-Cache-Retrieve（深读）
- **架构模式**：LLM 前置透明反向代理（FastAPI Python + Rust 重写双轨），只压"Live Zone"（工具输出/RAG结果）保"Frozen Prefix"命中 KV cache。
- **核心数据结构**：`CompressionEntry{content, token_counts, tool_name, tool_signature_hash, retrieval_count}`（compression_store.py:141-166）；`RetrievalEvent` 记录每次取回（:183-195）；CCR marker = `[100 items compressed... hash=abc123]`（tool_injection.py:49-50）。
- **核心算法**：CCR 五步：压缩存入 store(按内容 hash 索引)→注入短 marker→注入 `headroom_retrieve` 工具 schema→LLM 需要时调用 `headroom_retrieve(hash)`→`CCRResponseHandler` 拦截工具调用、取原文、透明续跑（response_handler.py:65-109）。TTL 默认 30min 滑动续期；Rust 后端 InMemory/Sqlite/Redis 三选。
- **设计模式与工程决策**：① "观测不改写"契约：TOIN 只 `record_compression/record_retrieval`，不动请求期决策以保 prompt cache 稳定（telemetry/toin.py:3-18）——每次 retrieve = 压缩过激的传感器信号；② PR9 用 DashMap 分片替换 `Mutex<HashMap>`，bench 文件内联 legacy 实现做 A/B（本地 ccr_store.rs:26-106, 192-216）；③ Rust proxy 无 `--compression` 时是严格 byte-pipe 且启动时大声警告 beta-header 粘性未生效（main.rs:41-54）；Bedrock SigV4 凭据启动时一次加载（main.rs:58-85）。
- **教学映射**：上下文缓存（Live Zone/Frozen Prefix 二分）；学习型Agent（retrieval 事件驱动压缩策略进化）。
- **一句话本质**：给有损上下文压缩装上"可逆性"——hash 锚点 + 取回工具把丢失的信息变成 LLM 可自主 fetch 的资源。

## 组内横断发现

1. **注册表+路由是通用骨架**：OpenBB entry points→provider、oh-my-openagent category→model 链、OpenSpec Skills→30+ CommandAdapter、TrendRadar 渠道适配——四家用同一"语义键→能力映射"模式隔离变化；对照 shanraisshan/leaks 仓可见 Claude Code 官方 `mcp__*`/namespace 也在收敛于此。
2. **有损 vs 可逆的对立设计**：唯一发明在 headroom——CCR 让压缩可逆（hash+retrieve 工具+TOIN 观测回路）；docling 反向同题：DoclingDocument 用 `$ref`+Prov 保证解析不丢溯源。两者都是"信息不能 silently 丢失"工程化。
3. **Markdown-as-database + 完整性脚本族**：career-ops（applications.md+merge/dedup）、OpenSpec（specs/+Validator 仲裁）、oh-my-openagent（AGENTS.md 注入+截断通知）——平面文件做事实源、确定性脚本做约束，替代传统 DB。
4. **把非确定性推出 LLM**：TrendRadar 服务端解析日期、OpenSpec 用声明序破拓扑平局、oh-my-openagent 用 realpath 门禁——共同工程哲学是"LLM 提意图，确定性层做决定"。
5. **生态镜像链**：leaks 仓的官方 prompt ↔ shanraisshan 的实践分类 ↔ oh-my-openagent/OpenSpec 的开源实现，三层构成同一 harness 范式（Command→Agent→Skill、plan-execute-verify）的原始素材-方法论-产品闭环。
