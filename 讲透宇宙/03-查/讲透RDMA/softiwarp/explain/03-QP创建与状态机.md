# 03 · QP 创建与状态机：verbs 最重对象的诞生、流转与分发表

> 仓库 zrlio/softiwarp @ 5d8a418 · 本文行号锚全部经源码核实

## 一、角色定位

QP（Queue Pair）是 RDMA 的执行主体：应用把意图（WR）投进 SQ/RQ 环，引擎按序兑现并出 CQE。本篇覆盖三块：`siw_create_qp`（siw_verbs.c:510-718）如何把 ibv_qp 变成带五条队列的 siw_qp；`siw_qp_modify`（siw_qp.c:381-644）八态状态机如何调度一切收发与拆除；以及收发共享的 `iwarp_pktinfo` 分发表（siw_qp.c:80-151）——它是 iWARP opcode 与处理函数之间的路由表，读懂它就掌握了协议面的全图。QP 状态机还是 CM 线（04 篇）与两条数据引擎（05/06 篇）的交汇点：CM 在 RTS 门上交接 socket，TX/RX 在每个 FPDU 上检查状态合法性。

## 二、内部结构

**siw_qp 的骨架**（siw.h:544-587）：五条环形队列——sendq（用户 WR）、recvq（接收缓冲）、orq（outbound read queue：已发 READ 请求的账本）、irq（inbound read queue：待答 READ 响应的工单）；外加 rx_ctx/tx_ctx 两个引擎上下文、cep 反向指针、state_lock 读写信号量与三条自旋锁。队列全部用"flags==0 即空位"的约定 + 取模索引，**长度强制 2 的幂**（`roundup_pow_of_two`，siw_verbs.c:589-590）保证取模廉价。

**创建闸门五道**（:526-557）：SIW_MAX_QP 配额（:526，原子计数先增后判）；**只收 IB_QPT_RC**（:531——iWARP 协议本就只定义可靠连接）；WR/SGE/inline 上限（:536-549，SGE 上限即 SIW_MAX_SGE=6，inline 上限 80 字节=5 个 sge 槽位，common/siw_user.h:133）；SQ+RQ 不能同时为零（:554，SRQ 场景豁免 RQ）。之后 kzalloc QP、初始化锁与等待队列（:575-580）、`siw_qp_add` 入 idr 拿 QP id（:585）、分配队列——**内核态 vmalloc、用户态 vmalloc_user**（:592-595），后者是 mmap 共享环的前提。SRQ 分支照 Verbs 6.3.7 忽略 RQ 尺寸（:615-624）。最后 uresp 携 sq_key/rq_key/qp_id 回用户（:658-685），`qp_num = QP_ID`（:688），初始态 IDLE（:651）。

**八态状态机**（siw.h:305-315）：IDLE/RTR/RTS/CLOSING/TERMINATE/ERROR/MORIBUND/UNDEF。ib_qp_state 的映射在 siw_verbs.c:54-62（RESET/INIT→IDLE，RTR→RTR，RTS→RTS，SQD→CLOSING，SQE→TERMINATE，ERR→ERROR）。**RTS 是全仓最重要的门**（siw_qp.c:433-490）：入口检查三件套——CRC 要开就先 `siw_qp_enable_CRC`（:435-436，两侧各挂一个 crc32c shash）、必须携带 LLP_HANDLE 与 MPA 属性（:440-449）；然后 TX/RX 两侧 MSN 归零/归一（:457-466，untagged 消息序号按 QN 分三列）、`siw_qp_readq_init` 分配 orq/irq（:472-473）、`siw_qp_socket_assoc` 把 socket 回调夺过来（:481，细节在 04 篇）、量初始 MSS 存 `tx_ctx.tcp_seglen`（:487-488，get_tcp_mss 见 siw_cm.h:157-170，gso_segs*mss_cache）。退出分支：RTS→CLOSING 看 tx WQE 是否空闲（:527-535），RTS→ERROR 是应急冲刷（:545-564），都会 `siw_qp_cm_drop` 掉连接（:640-641）。冲刷由 `siw_sq_flush`/`siw_rq_flush` 完成整队出 FLUSH_ERR 完成（siw_qp.c:1049-1161）。

**分发表 iwarp_pktinfo**（siw_qp.c:80-151）：`struct iwarp_msg_info` 三元组 {hdr_len, ctrl 模板, proc_data 函数指针}（siw.h:657-661），按 RDMAP opcode（iwarp.h:358-368，0-7 共 8 项）初始化。ctrl 模板预置了 DDP_FLAG_TAGGED/LAST、版本位与 opcode 的网络序组合，TX 构头时 memcpy 即得（siw_qp_tx.c:188/:213/:233/:246）；RX 收完头按 `iwarp_pktinfo[opcode].hdr_len` 补齐变长头（siw_qp_rx.c:981-982）。proc_data 列即接收处理器清单：WRITE→siw_proc_write、READ_REQ→siw_proc_rreq、READ_RESP→siw_proc_rresp、SEND→siw_proc_send、TERMINATE→siw_proc_terminate；**SEND_SE 复用 siw_proc_send（:131-132）而 SEND_INVAL/SEND_SE_INVAL 落 siw_proc_unsupp（:123/:141）**—— solicited 只是完成通知策略差异，INVAL 系列才真不支持。

## 三、外部连接

上游：RDMA core 的 create_qp/modify_qp/destroy_qp 调用；CM 线在 siw_accept/siw_proc_mpareply 里以五属性掩码推动 RTR→RTS（siw_cm.c:759-763/:1558-1562）。下游：TX 引擎每轮开工查 `state==RTS && !tx_suspend`（siw_qp_tx.c:1268-1269）；RX 回调同样只在 RTS 才进 tcp_read_sock（siw_qp.c:177）；doorbell 路径（siw_verbs.c:952）与 post_send（:1041）都先验状态。横向：ORQ/IRQ 与 READ 操作两半相互锁定——`siw_activate_tx` 把 READ 请求**先抄进 ORQ 再发**（siw_qp.c:870-890，为 loopback 下响应先至的竞态上保险，TODO 注释 :1031-1038 自述）；READ_FENCE 在 ORQ 非空时挂起 WQE（:853-869），由接收侧 `siw_check_tx_fence`（siw_qp_rx.c:1043-1087）在 RRESP 落地后放行——状态机与两条引擎由此咬合成闭环。

## 四、数据流

正常流：`create（IDLE）→ connect/accept 推 RTR → RTS（MSN 初始化+socket 接管+readq 就绪）→ 数据期 → CLOSE/ERROR → flush 出清 → destroy`。destroy_qp（siw_verbs.c:814-855）置 SIW_QP_IN_DESTROY、推 ERROR、放掉 cep/CQ/PD 引用。READ 全周期最能体现队列协作：SQE→activate_tx 抄入 ORQ→TX 发 RREQ→（对端回 RRESP）→RX 核对 ORQ 头槽放置数据→`siw_rdmap_complete` 出完成、`siw_check_tx_fence` 推进 orq_get→若有 fence 挂起的 WQE 则重新排队 TX。

## 五、设计决策

1. **队列 2 的幂 + flags 作空标记**：免去显式计数器，生产者写 smp_store_mb(flags,VALID)（:893），消费者清零——单字发布协议贯穿全仓。
2. **vmalloc_user 双轨**：同一函数对内核/用户态走不同分配器（:592-595），一个 if 换来零 syscall 快路径的物理基础。
3. **ORQ 先记账后发送**：应对 loopback READ 中 RRESP 在 sendmsg 返回前到达的极端时序（siw_qp_tx.c:1031-1038 注释），失败再回滚（siw_qp_tx.c:1142-1146）。
4. **MORIBUND/UNDEF 几乎不用**：MORIBUND（destroy 中仍被引用）在枚举后未见实质流转，UNDEF 被 modify 显式拒绝（siw_verbs.c:795-796）——状态空间的诚实冗余。
5. **SEND_SE 与 *_INVAL 的不对称处理**：分发表是协议能力边界的唯一权威声明，比文档更可信。

## 六、新人提示

1. 调 QP 问题先看状态：debugfs `/sys/kernel/debug/siw/<dev>/qps` 列活跃 QP；"post_send 返回 -ENOTCONN"几乎总是没到 RTS（连接未建立或已进入 CLOSING 以上状态，siw_verbs.c:1041）。
2. inline 数据住在 sge[1] 起的槽位里（siw_qp.c:848/:884-913），所以 SIW_MAX_SGE≥2 是编译期硬约束（common/siw_user.h:135-137）。
3. irq_size/orq_size 即 ird/ord（READ 并发额度），由 CM 在 RTS 时一并下发（siw_cm.c:747-748）；query_qp 的 max_rd_atomic/max_dest_rd_atomic 反映的就是这两值（siw_verbs.c:747-748）。
4. 词汇再钉一遍：ORQ/IRQ 与中断无关；MSNs 按 QN（SEND/READ/TERMINATE 三列，iwarp.h:325-330）独立计数。
5. 动手：在 siw_qp_modify 的 RTS 分支（:450）与 CLOSING 分支（:518）各加一行 dprint，跑 perftest 连接/断连各一次，可直观看到八态机的实际流转路径。
