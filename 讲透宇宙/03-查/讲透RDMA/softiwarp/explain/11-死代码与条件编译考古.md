# 11 · 死代码与条件编译考古：层积岩里的四条断层线

> 仓库 zrlio/softiwarp @ 5d8a418 · 本文行号锚全部经源码核实

## 一、角色定位

老内核栈代码的自然形态是"层积岩"：实验分支、版本兼容、构建残留层层堆叠。本篇做一次系统考古，把 siw 的条件编译分成四类——**活代码、真死代码、永假开关、构建残留**——并给出判别方法。考古的价值不是猎奇：05 篇已示范过一次（USE_SQ_KTHREAD 误读会让读者在 workqueue 路径上白费功夫），而 SIW_TX_FULLSEGS 的死代码间还有**数据依赖**（删错一处 #ifdef 会静默引入 bug）。读完本篇，面对任何一个 `#ifdef` 都能三问定型：宏在哪里定义？谁包含它？它的代码里引用的字段是否还活着？

## 二、内部结构

**断层一：USE_SQ_KTHREAD——默认定义的活开关**。siw.h:542 一行 `#define USE_SQ_KTHREAD`，紧跟 siw_qp 结构体内 `struct llist_node tx_list` 的 `#ifdef` 包裹（siw.h:566-568）。05 篇已详述其运行时含义（per-CPU kthread 为主、workqueue 为备），这里补编译事实：kthread 实现体 tx_task_g/siw_run_sq/siw_qp_to_tx（siw_qp_tx.c:1289-1406）被 `#ifdef USE_SQ_KTHREAD` 整体包住，workqueue 备选 siw_sq_work_handler（:1220-1260）被 `#ifndef`（:1212）排除；门面 `siw_sq_queue_work`（:1402-1413）内还有第二层 #ifdef 选路。**判活依据**：宏无条件定义于核心头文件，无任何 `#undef` 或 Kbuild 注入路径（EXTRA_CFLAGS 仅 -I common，kernel/Kbuild:1）——本仓所有构建形态下 kthread 路径必然编译。真正的死代码是被排除的 workqueue 分支，但它"死"得体面：完整可编译，删掉 542 行即可复活。

**断层二：SIW_TX_FULLSEGS——永假的真死代码，四处互锁**。全仓（kernel/+common/+userlib）grep 无任何 `#define SIW_TX_FULLSEGS`，四处 #ifdef 全部空转：

- siw_qp.c:276-286（siw_qp_llp_write_space）：死分支想"写空间 ≥ fpdu_len 才清 SOCK_NOSPACE 并排队"；活分支走 sk_stream_write_space+查 SOCK_NOSPACE 位（:283-286）。
- siw_qp_tx.c:805-807（siw_prepare_fpdu 尾部）：死分支记 `c_tx->fpdu_len`。
- siw_qp_tx.c:818-832：死分支的辅助函数 `siw_test_wspace`——`sk_stream_wspace < fpdu_len` 即置 SOCK_NOSPACE 返回 -EAGAIN。
- siw_qp_tx.c:954-957（burst 循环内）：死分支每轮测写空间，不足即跳出。

它的实验语义清晰可考：**保证每个 FPDU 不被 TCP 拆进多个段**（"FULL SEGS"=整段发送），代价是写空间不足时提前让出。**致命的数据依赖**：`fpdu_len` 字段（siw.h:531）在**活代码里从不写入**——kzalloc 后恒 0，唯一写点 siw_qp_tx.c:806 在死分支内。若有人"复活"了 :954 的 wspace 检查却漏掉 :806 的记录，比较 `wspace < 0` 恒假，整段保护静默失效——**死代码不是孤岛，删 #ifdef 等于动一个未维护的小状态机**。

**断层三：LOCK_WO_FLAG——永假但无害的锁策略开关**。siw.h:592-600 与 :617-623 两处：定义则 sq/orq 锁用 spin_lock_bh（下半部禁用版），否则 spin_lock_irqsave。无任何定义来源，恒走 irqsave 版。与 FULLSEGS 不同，它替换的两版语义等价安全（softirq 上下文加锁方都要求禁中断或禁下半部），属于"换了口味没换疗效"的遗留开关。同类还有 siw.c:58 `mpa_crc_required`（模块参数运行时可设，**活**）与 DPRINT_MASK（编译期调试等级，Makefile 可注入）——后者是活的编译旋钮而非死代码，分类时注意区分。

**断层四：构建残留**。kernel/Kbuild 的 siw-objs 列表 11 项里 **siw_cm.o 出现两次**（`siw_main.o siw_cm.o ... siw_cq.o siw_cm.o ...`）——kbuild 容忍重复（链接清单去重），但它是维护粗糙的化石：从函数命名推断，siw_cm.c 历史上可能拆过/合过一次。同类的还有 05 篇钉过的 siw_sq_worker_init：无条件创建 "siw_sq_wq" 工作队列（siw_qp_tx.c:1192-1200）而 kthread 模式下无消费者——纯粹的装配线残留。Makefile 的 OFA_DIR 分支（kernel/Makefile:8-12）则是**活的**兼容开关（对 OFED 头文件构建），不要错杀。

**版本兼容矩阵（活的考古层）**：LINUX_VERSION_CODE 判断散布全仓（siw_cm.c 4 处、siw_verbs.c 5 处等），最集中的两块是回调签名（sk_data_ready 在 3.15 前带 bytes 参数，siw_cm.h:101-105/siw_cm.c:95-97）与 create_cq 的 4.2 参数变更（siw_verbs.c:1325-1331 的双原型 + IS_RH_7_2——RHEL7.2 backport 识别，README_KERNEL_VERSIONS.txt 列支持 3.x-4.x 全线）。git 层面：`git log --oneline` 可见 ae550b5 "fixed SOLICITED flag in tx"、c5b96ea "fixes memory leak in umem de-registration"（正是 07 篇那条延迟记账路径）、3ec0e2f "fix qp reference for cq processing"（08 篇 kernel_verbs 引用对的修复）——**近顶几个提交恰好对应本系列 05/07/08 三篇的核心机制**，读史即读码。

## 三、外部连接

死代码的"社会关系"才是考古重点：SIW_TX_FULLSEGS 与 TCP 栈的 sk_stream_wspace/SOCK_NOSPACE 交互（活分支用 test_bit 的粗粒度判断替代了死分支的精确判断）；USE_SQ_KTHREAD 的复活开关在 siw.h 一行，影响 siw_qp_tx.c 约 200 行编译取舍；Kbuild 重复项与 Makefile 的 OFED 分支共同构成构建层的三种时代痕迹。userlib 侧没有对应死代码（SIW_IF_OFED/MAPPED 两模式都活），但 ABI 版本号 VERSION_ID_SOFTIWARP=2（common/siw_user.h:57）是两侧共同的"防腐层"——版本 bump 即宣告旧库不可用，正是防层积岩腐化的正面设计。

## 四、数据流

无运行时数据流——本篇对象是编译期分支。但给出**判活流程图**：遇到 #ifdef X → ①grep 全仓 `define X`（含 Kbuild/Makefile 的 -DX 注入与 kern-abi 头）→ ②无定义则查 X 内代码引用的字段是否有活代码写入点（FULLSEGS 教训）→ ③有定义则确认定义处是否被更早的 #undef/条件包裹 → ④构建残留类查 .o 清单与初始化函数的调用方。四步走完，每个分支归入：活/真死/可复活/残留。

## 五、设计决策

1. **实验分支保留为 #ifdef 而非删除**：作者刻意留下 FULLSEGS 的完整体（含辅助函数），便于未来用 MPA marker 等场景重新实验——但没料到 fpdu_len 数据依赖会成为复活陷阱，注释缺失是败笔。
2. **默认 kthread 而非运行时选择**：编译期定死避免双路径测试负担；workqueue 代码保留是给极端部署（无 kthread 权限环境）的后门。
3. **kbuild 容忍重复项**：不报错不警告，化石因此能存活多年——构建工具的宽容度决定层积岩厚度。
4. **版本宏而非多分支源码树**：单树 + LINUX_VERSION_CODE 散点判断，3.x-4.x 十余版本一线牵——维护成本换覆盖面，是内核外驱动生存的常规取舍。

## 六、新人提示

1. 改动 siw_qp_tx.c 的 write_space/burst 逻辑前，先决定对 FULLSEGS 四处 #ifdef 的处置：全删（连同 fpdu_len 字段）或全保——半删半留必引静默 bug。
2. 想 evaluate workqueue 模式：注释 siw.h:542 重编即可，但要同步检查 siw_sq_wq 是否被创建（siw_main.c:666 必调 siw_sq_worker_init——本仓恰好两模式都建，主线版已修）。
3. git log 是最快的"死代码断代"工具：`git log -S "SIW_TX_FULLSEGS" --oneline` 找引入提交，看 commit message 里的实验动机。
4. IS_RH_7_2 这类发行版 backport 宏只出现在 RHEL 系构建（-DIS_RH_7_2 由打包方注入），主线自编译恒无——见到它出现在判断里别以为版本判断错了。
5. 动手：在 Kbuild 的 EXTRA_CFLAGS 追加 `-DSIW_TX_FULLSEGS`（复活死分支）对比默认构建的预处理输出 diff，直观感受这 4 个分支的代码体积——比读源码更快建立"死代码占比"直觉。
