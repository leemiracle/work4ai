# 04 · pd.rs：ProtectionDomain——配额所有权的分叉点

> 源码：`ibverbs/src/pd.rs`（454 行）｜行号锚全源码核实

## ① 角色定位

ProtectionDomain（PD）是 verbs 的**命名空间与权限边界**：同一 PD 下创建的 QP/MR/AH/SRQ 才能互相配合，跨 PD 组合直接失败（pd.rs:223-225 文档："working with objects from group1 together with objects from group2 will not work"）。资源树里它是**分叉点**——Context 之下、一切工作资源之上：

```
Context ──alloc_pd──▶ ProtectionDomain ──┬─ create_qp          → QueuePairBuilder (qp.rs:174)
                                          ├─ allocate/register_* → MemoryRegion (pd.rs:255/295/327)
                                          ├─ create_srq          → SharedReceiveQueue (pd.rs:379)
                                          ├─ create_address_handle → AddressHandle (pd.rs:105)
                                          └─ advise_mr           → ODP 预取建议 (pd.rs:129)
```

PD 可 `Clone` 共享（`Arc<ProtectionDomainInner>`，pd.rs:70），克隆分发给各子资源——**每条所有权链向下创建、反向保活**。

## ② 内部结构

```
ProtectionDomain (derive Clone, pd.rs:69)
 └─ inner: Arc<ProtectionDomainInner>              pd.rs:70
     ├─ ctx: Context     ← 反向持有父 Context
     └─ pd: *mut ffi::ibv_pd
         Drop → ibv_dealloc_pd + keep(&ctx)        pd.rs:53-61
```

前段两个 advise 配套类型：`MrAdvice`（pd.rs:18-26，Prefetch/PrefetchWrite/PrefetchNoFault，`From` 转内核枚举 pd.rs:28-37）与 `MrAdviseFlags`（pd.rs:39-46，flags_newtype 产物，唯一旗标 FLUSHABLE=同步执行）。

公开方法：`as_raw`（pd.rs:86）、`context()`（pd.rs:91，回查父 Context）、`create_address_handle`（pd.rs:105）、`advise_mr`（pd.rs:129）、`create_qp`（pd.rs:174）、`allocate`（pd.rs:255）、`register_from_raw`（pd.rs:295）、`register_dmabuf`（pd.rs:327）、`create_srq`（pd.rs:379）。私有件：`reg_mr` 泛型助手（pd.rs:206）、`zeroed_buffer`（pd.rs:404）、`require_active`（pd.rs:417）。

## ④ 数据流：三个注册入口与 create_qp 前置检查

**三入口共用 `reg_mr<O>`（pd.rs:206-218）**：一次 `ibv_reg_mr`（pd.rs:214）+ nonnull + `MemoryRegion::new(self.clone(), mr, ptr, owner)`。差别全在 owner 与指针来源：

| 入口 | owner | 内存来源 | 签名 |
|---|---|---|---|
| `allocate`（pd.rs:255） | `Box<[u8]>` | zeroed_buffer 新分配 | 安全 |
| `register_from_raw`（pd.rs:295） | `()` | 调用者自管（mmap/大页） | unsafe，三契约（pd.rs:276-282） |
| `register_dmabuf`（pd.rs:327） | `()` | DMA-BUF fd（GPU 显存） | 安全，fd 仅借用 |

`zeroed_buffer`（pd.rs:404-414）值得单读：**拒绝** `vec![0; n]`——后者分配失败 abort 进程（pd.rs:402-403 注释）——改走 `Layout::array`+`alloc_zeroed`+`Box::from_raw`，失败返回 None 由调用方翻 ENOMEM（pd.rs:257-259）；零页不预触碰也意味着大缓冲不会立即 commit 物理内存。

**`create_qp` 三步前置（pd.rs:174-198）**：① `query_port` 现查端口属性（pd.rs:180-181 注释：属性会变——子网管理器会改 LID——每次建 builder 都现查）；② `require_active`（pd.rs:417-428）拒绝非 ACTIVE/ARMED，依据 RDMAmojo 经典结论：其他状态下 GID 表内容不确定（pd.rs:418-423 原文引用）；③ 仅 RC 查 `rd_atomic_limits`（pd.rs:185-189，clamp 到 u8）。通过后把 `self.clone()`、两个 CQ 克隆、端口参数交给 `QueuePairBuilder::new`——**"端口必须 ACTIVE"的闸在 builder 诞生前落下**，不推迟到 build。

**`advise_mr`（pd.rs:129-149）**：直调 sys shim；返回值语义特殊——成功是 0 而非指针，errno 以返回值携带（pd.rs:144-148），与 shim 的 `return EOPNOTSUPP`（sys lib.rs:438）咬合。

## ⑤ 设计决策

1. **所有权链方向**：verbs 内核侧资源是"PD 下配额"，Rust 侧以**子持父克隆**表达——MR 持 `_pd`、SRQ 持 `_pd`、QP 持 pd。drop 顺序天然正确：子先释放，PD dealloc 永远在最后子资源之后；destroyed 失败路径再 `keep(&self.ctx)`（pd.rs:58）漏一个父引用防 unwind 二次 panic（error.rs:407-419，03 篇已述）。
2. **`allocate` 的 panic 面**：`assert!(n > 0)`（pd.rs:256）——零长 MR 无意义；register_from_raw 同 assert（pd.rs:301）。越界早炸好过内核 EINVAL 猜谜。
3. **`register_dmabuf` 的 errno 升格**：EOPNOTSUPP（设备不支持）与 EPROTONOSUPPORT（内核太老）经 map_err 交给 `Error::Unsupported` 归一（pd.rs:345-348 注释）。
4. **advise 只公开一个旗标**：rdma-core 的 FLUSHABLE 之外暂无可移植位，宁缺毋滥——绑定层不发明 API 的克制。
5. **require_active 是产品级判断**：把"建 QP 时端口 DOWN"从遥远的 modify_qp EINVAL 提前到 create_qp 调用点，给具名 `Error::PortNotActive(port_num)`（pd.rs:426），排障路径短一截。

## ⑥ 新人提示

- **PD 克隆是浅共享**：两个 clone 同一内核 PD；MR/QP 全落同一 PD 是 verbs 硬要求——跨 PD 组合会在 WC 以 `IBV_WC_LOC_QP_OP_ERR` 等状态翻车（sys lib.rs:98-102 文档描述此类错误）。
- `allocate` 注册即耗时（pd.rs:226-227："avoid registering memory on the data path"）——控制面注册、数据面重用，RDMA 编程第一守则。
- 收发缓冲 `LOCAL_WRITE` 就够（mr.rs:50-51）；PERMISSIVE 含远端写，给不需要远写的大缓冲是过度授权（mr.rs:44-45 的"narrow it"）。
- `PortNotActive` 最常见于 rxe 没配好；先 `ibv_devinfo` 看 port state 再对号。
- `advise_mr` 只对 ODP 注册的 MR 有意义（pd.rs:117-118）；pinned MR 上调用是空转。
- 注册自管内存（hugepage/mmap）：`register_from_raw` 三条 safety 契约（pd.rs:276-282：指针有效、不可移动/释放、不得与设备竞速）一条不能省——正是 `ibv_dereg_mr` 前缓冲必须原样的 C 端义务。
