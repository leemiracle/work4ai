## ① 角色定位

QP 是 RDMA 的"套接字"——发送队列+接收队列+CQ 关联的网卡资源（qp.rs:2508-2512）。本文件承载四件事：sealed trait 传输类型系统（非法组合变编译错）、builder→handshake/activate 建连状态机（RESET→INIT→RTR→RTS）、SendBatch/post_recv 数据面、复刻内核表的 EINVAL 翻译器。16 步 tour 深潜重心（step-09："Transport 类型系统与 SendBatch Drop 语义是核心考点"）。

## ② 内部结构

- **类型层（qp.rs:15-125）**：`sealed::Sealed`（:16-22）+ 四 trait——`Transport`（:72）、`Connected`（:76，RC/UC）、`Reliable`（:81，仅 RC）、`Datagram`（:85，UD/SRD）——三标记 Rc/Uc/Ud（:92/:97/:106）。文档内嵌 **5 个 compile_fail**（:34-71，全 E0599）。
- **建连层**：`QueuePairBuilder<T>`（:477-509，`new` :517-573 种子三态属性）；`BringUp`（:1056-1060）；`PreparedQueuePair<T>`（:1033）；`QueuePairEndpoint`（:1076，28 字节 wire 格式 :1103-1143）。
- **数据面**：`RecvRequest<'a>`（:1407，repr(transparent) 包 ibv_recv_wr）、`SendBatch`（:1517）、`SendOp`（:1640）、`Payload` 三变体（:2029-2038）；属性层 `QueuePairAttribute`（:2063，set 即记 mask 位）、`QueuePairState`（:134）、`AckTimeout`（:271，4.096µs×2^n 级数）、`RnrTimer`（:350，编码 0 反而是最大值 655.36ms）、`SendOps`（:421）。
- **成品 `QueuePair<T = Rc>`（:2514-2532）**：四父引用 + qp/qp_ex 双指针 + 两道容量闸；`SendQueue`（:2814）为 split（:2781）的发送半句柄。

## ④ 数据流：loopback.rs 74 行全链走读

**控制面（loopback.rs:29-39）**：`pd.create_qp::<Rc>(&cq,&cq,1)`（→pd.rs:174）要求端口 ACTIVE（pd.rs:182-183），RC 种子默认 timeout=65.536µs/retry=6/rnr_retry=6/min_rnr=2.56ms（:539-544）；`.set_gid_index(gid)`（qp.rs:600，RoCE 必经）；`.build()`（qp.rs:895→:798）三连——check_same_context（:799）、`ibv_create_qp_ex`（:805，经 sys shim）、`ibv_qp_to_qp_ex` 拿门铃视图，**null 即 `Error::Unsupported`**（:849-854：没装 WR 表的 QP 永远 post 不进去）；`.endpoint()`（qp.rs:1175）现查 query_gid 组 `{qp_num,lid,gid,psn,max_dest_rd_atomic}`（本端 send 起点即对端 recv 起点）；`.handshake(endpoint)`（qp.rs:1364-1398）依序 apply init/rtr/rts——`rtr_attributes`（:1264）构路途地址向量（RoCE 无 GID 直接 `Error::GidRequired` :1291-1294）；**RTR 失败的 RoCE 特判**（:1370-1395）把 ETIMEDOUT/ENETUNREACH 翻成"远端 GID 不应答或防火墙丢 UDP 4791"；`rts_attributes`（:1320）压 max_rd_atomic 到对端容量（:1328）。

**数据面（loopback.rs:46-49）**——unsafe 仅 post_recv 与 submit 两处：

```
unsafe { qp.post_recv([RecvRequest::new(2, &[mr.slice(..8)])]) }   // 先挂接收
let mut batch = qp.start_send();                                   // wr_start
batch.op().signaled().send(1, &[mr.slice(8..)]);                   // 入块
unsafe { batch.submit() }                                          // 门铃
```

- `post_recv`（qp.rs:2710-2724）：`link`（:1439-1448）在**调用者切片上原地**串链（:1435-1438：重复索引会作废先前的链）；失败时 `post_recv_error`（:1958-1982）按 bad_wr 指针差算**已 post 数量**；挂 SRQ 的 QP 得具名错误（:1973）。
- 发送链三拍：`start_send`→`open_batch`（:2751→:2789）调 wr_start，SendBatch **独占借用** qp（第二个批次编译不过，compile_fail :1469-1475）；signaled（:1653）改 flags 后 `send`（:1669，imm 走 `wr_send_imm` 且 `to_be()`；`send_op` :1791）收尾进 `build`；`submit`（:1607-1618）**先 forget 再 wr_complete**（:1610-1612，否则 Drop 会 abort 即将 complete 的块）。
- `build`（:1700-1787）：**容量预检**（:1720-1725，三家 provider 不查容量就写队列）→设 wr_id/wr_flags（补 INLINE 位，rxe 需要 :1731-1736）→跑 opcode 闭包→按 Payload 分发 setter（单 sge 走免循环 `wr_set_sge` :1746-1748，**空切片传真 NULL 而非 dangling** :1749-1759）；`#[inline(always)]`（:1699）。
- **submit 失败也收不回**（:1589-1600）：rxe 先交设备再报错、mlx5 队满**覆写上一条请求**、hns owner-doorbell 在 opcode 返回时可能已执行；**Drop=abort**（:1621-1627）忘 submit 整批蒸发（onboard ⑧-6）。

**收割（loopback.rs:53-72）**：`cq.poll()` 迭代 WC，`wc.ok()` 翻错、`wc.wr_id()` 分派（1=发/2=收），断言字节落了（:66）。

## ⑤ 设计决策

1. **能力进类型、非法组合进编译错**：5 个 compile_fail（:34-71）+ 4 个借用检查 compile_fail（:1469-1504，含 E0505"handle 被批次借用中不许 drop"）是 crate 三承诺之二（onboard ①）的证明；sealed 防外部实现。
2. **门铃批量是性能核心**：一次 wr_complete 提交整块（doorbell_batching 示例演示收益）；每请求在 opcode 调用时已写入 WQE（:1458-1460），submit 只响铃。
3. **EINVAL 翻译器**：`qp_transition_masks`（:2377-2498）复刻内核 `ib_modify_qp_is_ok` 位表，`diagnose_modify`（:2633-2679）把裸 EINVAL 升格为具名错误；test_kernel_table（:3487-3518）**逐格对照**内核表。
4. **四父引用钉出依赖序**（:2515-2520）：Drop（:2826-2840）destroy 失败 keep 全部四个（未 detach 多播组返 EBUSY，:2828），panic 好过静默泄漏；`query` 因无锁缓存 state 取 `&mut self`（:2599-2601）。
5. **容量与位宽双闸**：max_send_sge/max_inline_data 由 build 强制（:2526-2530），panic 走 `#[cold]`（:1984-2012）不污染热路径；24 位字段在 setter/解码/rtr 三处拦截（:2149/:1133/:1265）——四家 provider 把超宽 PSN 原样传设备（:1062-1064）。

## ⑥ 新人提示

- **读 qp.rs 正确顺序**：trait 层（15-125）→ loopback 对照第④节 → SendBatch/SendOp（1517-1931）→ 再碰 builder/handshake。练习三连（onboard ⑦）：改 wr_id、换 `<Ud>` 体会 E0599、批量 8 条对比逐条 submit。
- **EFA 特例**（qp.rs:102-105）：UD send 必须 signaled、禁止 solicited；UD 的 WC `len()` 含 40 字节 GRH，payload 从 offset 40 起（:2688-2690）。
- inline 字节在 opcode 调用中**已拷进 WQE**（qp.rs:1761-1763）随用随弃；Sges 的 MR 须活到 WC（:2014-2027）。handshake 失败先读错误文案（:1383-1391）；手动状态机才用 `into_queue_pair`（:1156）+ modify（:2581）。
- 死锁红旗（:1506-1515）：ionic 上开着批次别 poll/arm 它的 send CQ、别经同一 CQ post_recv；hns 上 polling 失败完成会拿 send 队列锁。
