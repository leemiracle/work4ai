## [258] ebpfkit

- [repo] 攻击工具（rootkit）· Datadog 员工独立安全研究（明确声明非 Datadog 官方产品，GPL v2 + Apache 2.0 双许可）· 作者 Guillaume Fournier · BlackHat USA 2021 "With Friends Like eBPF, Who Needs Enemies?" + Defcon 29 "eBPF, I thought we were friends!"。
- 定位：利用多种 eBPF 特性实现进攻性技术的完整 rootkit，功能覆盖 obfuscation（对 bpf syscall 隐藏自身）、container breakout、持久访问、C2、pivoting、网络扫描、RASP bypass。开发环境 Ubuntu Focal / kernel 5.4 / clang 11.0.1 / golang 1.13+。
- 架构三件套：`ebpfkit` 主程序（root 权限加载）、`webapp`（C2 HTTP 服务器，默认 :8000）、`ebpfkit-client`（攻击者侧客户端，子命令 docker/fs_watch/network_discovery/pipe_prog/postgres）。C2 隧道走 HTTP User-Agent 字段伪装。
- README 三个完整攻击示例：①被动网络嗅探——启动即静默收集进出流量（含 TCP/UDP 字节统计），client 拉取后生成 Graphviz 网络发现图；②主动端口扫描——从 eBPF 层发 ARP + SYN 探测（trace_pipe 可见 "OPEN PORT 8000" 日志），证明 rootkit 自身能发起网络侦察；③fs_watch 窃取 /etc/passwd——hook 内核向进程回传文件内容的过程，原样复制文件数据（针对 read 路径的数据面拦截）。
- 顶层结构：cmd/{demo,ebpfkit,ebpfkit-client}、ebpf/（BPF 侧 C 源码）、pkg/、charts、dockerhub、graphs（graphviz 产物）。
- 本地克隆状态：损坏（README/Makefile 等 0 字节、refs/heads/master 空引用），但 pack 完整——已从 pack 恢复出唯一 commit 5727985e（GitHub 网页 merge，浅边界，2023-02-28），README 326 行全量恢复。上游实际最后活动即 2023 年初，属"研究完成即冻结"的演讲配套仓。

## [259] ebpfkit-monitor

- [repo] 防御/检测工具 · 与 ebpfkit 同作者（Guillaume Fournier，Datadog 员工研究项目）· 专为检测 ebpfkit 设计，但能力通用。
- 双模工作：①静态分析 eBPF 字节码——解析 ELF object 文件，列出 program sections、map、字节码 dump；可按特征查询，如"列出所有使用 `bpf_probe_write_user` helper 的程序"（该 helper 是 write 类 rootkit 的核心指标）、"列出所有交互 `piped_progs` map 的程序"（ebpfkit 的特征 map）；②运行时监控——`start` 子命令 trace bpf syscall 打印加载事件，支持 `--allowed-processes` 白名单（如只允许 bpftool 使用 bpf syscall，越界即异常信号）。
- 子命令集：graph（生成 ELF 的 graphviz 调用图）/ map / prog / report（map+program 摘要）/ start。Future work 明确记录两项目标：迁移到 BTF & CO-RE、用 `lsm` 程序替代 `bpf_override_return` 做访问控制——反映 2021 年 LSM-BPF 尚未成熟的技术边界。
- 价值定位：eBPF 恶意检测的早期参考实现（2021），"检测 eBPF 滥用要靠 eBPF 监控 bpf(2)"这一思路的直接出处之一；与 ebpfkit 构成攻防成对教材。
- 本地克隆状态：完全损坏（45 个 git 对象全部 missing，README/Makefile 0 字节，本地不可恢复），README 已从上游 master 分支 raw URL 恢复（约 130 行）。上游活跃度与 ebpfkit 同期（2021-2023）。

## [260] Bad BPF

- [repo] 攻击演示集合（教育用途）· 作者 pathtofile · 配套博客 blog.tofile.dev（2021-08-01）与 DEF CON 29 演讲 "Warping Reality" · 最后提交 2024-07-08。
- 定位：一组恶意 eBPF 示例程序，核心主题全部围绕 eBPF "在用户态与内核之间读写用户数据"的能力（BPF_PROBE_WRITE_USER / read 路径篡改）。CO-RE + BTF 构建（Ubuntu 20.10+，kernel 4.7+，clang/llvm 14），顶层自带 libbpf/bpftool/blazesym/vmlinux 全套依赖镜像。
- 六个程序（每个都是一类攻击的原型）：`bpfdos`——对调用 ptrace 的进程（如 strace）发 SIGKILL，反调试；`exechijack`——篡改 execve 参数使新进程实际执行 /a（恶意程序再补跑原程序避免察觉）；`pidhide`——hook getdents64 从 /proc 目录列表 unlink 目标 PID，ps 不可见；`sudoadd`——仅对 sudo 的读取覆写 /etc/sudoers 首行为 `<user> ALL=(ALL:ALL) NOPASSWD:ALL #`（cat/sudoedit 看到的文件不变，精准单进程提权）；`writeblocker`——fake write 返回假字节数（FD>2），可让 rsyslogd 静默丢 auth.log；`textreplace`——read 路径文本替换（隐藏 lsmod 内核模块、伪造 MAC 反沙箱检测）。
- `textreplace2` 是进阶版：配置存 eBPF map（bpftool 运行时改目标文件/查找串），支持 `--detach`——loader 退出后程序经 bpffs pin 持驻内核（rm /sys/fs/bpf/textreplace 才能卸载），演示无进程存留的常驻攻击形态。
- 通用参数 `--target-ppid` 限制作用范围到指定父进程的子进程，用于演示选择性攻击。整体是"内核态数据面篡改"最清晰的最小教学集。

## [261] TripleCross

- [repo] 攻击工具（eBPF rootkit）· 学术出身：h3xduck 的 UC3M 学士论文（thesis PDF 在 docs/ 内），明确致谢四项前作：Dileo DEFCON 27、Hogan DEFCON 29、Fournier & Afchain DEFCON 29（即 ebpfkit）、Kris Nóva 的 Boopkit · GPLv3 · 最后提交 2023-03-08（论文交付后冻结）· 测试环境 Ubuntu 21.04 / kernel 5.11 / clang 12。
- 六大模块：library injection（库注入）、execution hijacking（执行劫持）、本地提权、backdoor + C2、persistence（持久化）、stealth（隐藏）。
- 技术亮点一：GOT 劫持库注入五阶段——tracepoint hook syscall 后从栈上回溯定位 PLT 返回地址 → 找到 GOT → 动态生成 shellcode 绕 ASLR/PIE（dlopen 地址每运行都变）→ 借 /proc 文件系统向 .text code cave 写入 shellcode → 覆写 GOT，下次 PLT 调用即跳转恶意库（fork 出 reverse shell 后恢复原执行流）。绕过清单含 ASLR/Stack canaries/DEP/PIE/Full RELRO，兼容 Intel CET。README 对 .text→.plt→glibc→syscall 的 rip 保存位置分析（栈/不保存/rcx）是 eBPF 栈扫描的难得教材。
- 技术亮点二：C2 触发器直接复刻国家级植入物——pattern-based trigger 仿 NSA Equation Group 的 Bvp47（Pangu Lab 报告），multi-packet trigger 仿 CIA Hive（Vault 7 泄露文档）：payload 经 rolling XOR 分片藏进 TCP seq number 或 source port，对网络监管呈现随机流量。phantom shell 用 XDP/TC 改写既有包 payload 承载 C2 数据（eBPF 不能自发包，靠 TCP 重传恢复原始包，原流量不丢）。
- persistence 用 cron.d + sudoers.d 两个隐藏文件解决"重启后 eBPF 程序卸载 + 重载需 root"双问题；stealth 模块 hook sys_getdents 篡改目录项隐藏 "SECRETDIR" 目录与 "ebpfbackdoor" 文件。rootkit client（injector）支持 8 种远程命令（明文/加密/phantom 三种 pseudo-shell、激活/卸载全部 eBPF 程序等）。
- 工程形态完整：packager.sh/deployer.sh 模拟真实攻击者的一键部署；RawTCP_Lib（作者自制 raw socket 库，独立仓）承担客户端传输。仓库结构 src/{client,common,ebpf,helpers,libbpf,user,vmlinux} + apps + docs。与前两个仓相比，它是"前人技术集大成 + 学术系统化"的总结性作品，eBPF 攻击面的最全面单仓参考。
