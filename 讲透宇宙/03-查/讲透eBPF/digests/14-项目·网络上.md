## [172] P4_16 backend for eBPF（p4c/backends/ebpf/README）
- **是什么**：p4lang/p4c 官方 eBPF 后端文档——把 P4_16 程序编译成受限 C 子集，再由 clang/libbpf 或 BCC 编成 eBPF 字节码，挂到 Linux TC 或 XDP。
- **核心内容**：两种目标架构——`ebpf_model.p4`（纯分类器，只返回 pass/drop，无 deparser）与 `xdp_model.p4`（支持包编辑=有 deparser，复刻内核 XDP 能力）。P4→C 映射表是精华：table → 2 个 eBPF map（第二个专放 default action）、action → tagged union、counter → 额外 map、parser state → goto。已知限制：>32 位宽算术不支持、无 ternary 匹配、parser 不能有环（verifier 拒绝）。还支持 **C extern 扩展**（`--emit-externs`，可自带 BPF map、可用 BPF helper，但禁止碰 P4 表的 map）。
- **亮点/坑**：需要内核 ≥4.15 + libbpf；`ebpf_` 前缀标识符是保留字（结构体字段名也算）；生成的 C 单独编译不了，必须配 `runtime/kernel_ebpf.h`。
- **对学习者**：P4 程序员进入 eBPF 的最正规桥梁；也是"表驱动语言如何降级到 verifier 可接受子集"的教科书案例。
- **对 agent**：本地 `/usr-data/data2/kylin/network/awesome-ebpf/web/md/172.md`；grep `xdp_model`、`extern bool`、`REGISTER_TABLE`、`TC_ACT_SHOT` 可拿到全部关键约定。

## [174] cilium/cilium（GitHub 仓库）
- **是什么**：eBPF 数据面的 Kubernetes CNI/网络/安全/可观测全家桶，CNCF 毕业项目；本批乃至整个 awesome-ebpf 清单里最重要的活仓库。
- **规模/活跃度**：Go 为主 + `bpf/` 下 C 数据面；最后提交 2026-11-05（commit `00354062` clustermesh port validations），日更级活跃。当前稳定 v1.20.4 / v1.19.10 / v1.18.16（2026-10-23 同日发布），v1.21.0-pre.4 预发布中；AMD64+AArch64 双架构镜像，1.13.0 起带 SPDX SBOM。
- **数据面路径（三种全占）**：`bpf/bpf_lxc.c`（2634 行，容器 veth 上 TC clsact ingress/egress，主力策略+转发引擎）、`bpf/bpf_xdp.c`（323 行，XDP 早丢弃/LB/NodePort）、`bpf/bpf_host.c`（2033 行，宿主网卡对外流量）+ `bpf_sock.c`（socket 层/cgroup）、`bpf_overlay.c`（VXLAN/Geneve 封装）、`bpf_wireguard.c`。`bpf/lib/` 是 60+ 个头文件级库（conntrack/lb/lpm/encrypt/edt/egress_gateway/clustermesh...），学习工业级 BPF 代码组织的最佳素材。
- **核心能力**：L3 扁平网络（overlay VXLAN/Geneve 或 native routing）、identity-based（与 IP 解耦）L3-L7 策略、可完整替代 kube-proxy 的 eBPF 分布式 LB、ingress/egress gateway、带宽管理（edt）、service mesh、Hubble 可观测。
- **对学习者**：读 `bpf/lib/common.h` + `bpf_lxc.c` 入手最实惠；`Documentation/` 是官方完整文档树。
- **对 agent**：本地 `/usr-data/data2/kylin/network/awesome-ebpf/repos/cilium/cilium`；grep `cilium_ipv4_l3`、`TAIL_CALL`、`ENABLE_IPV6`、`POLICY_VERDICT` 可追踪完整转发路径；`bpf/complexity-tests/` 是 verifier 指令数预算管理的实例。

## [181] Google Open Source Blog "Cilium: Networking and security for containers with BPF and XDP"
- **是什么**：Daniel Borkmann（eBPF 内核维护者、Cilium 联创）2016-11-02 客座博文，Cilium 的准官方"出生公告"，全文完整落地。
- **核心内容**：四大设计问题（Scale/Extensibility/Simplicity/Performance）→ eBPF 方案；完整讲了 eBPF 工具链：C 子集→LLVM eBPF backend→ELF（程序+map+relocation）→tc 加载→verifier 验证→JIT（x86_64/arm64/ppc64/s390 已支持）→可整体 offload 到 NIC。Cilium 作为中间层接入 K8s/Docker/CNI，**按容器定制生成并原子更新 eBPF 程序、不中断连接、不需重启容器**，不需要的功能直接编译掉、配置变常量供 LLVM 深度优化。
- **亮点**：列举了当时已实现的构件——NAT64、带 DSR 的 L3/L4 LB、connection tracker、端口映射、ACL、NDisc/ARP responder、VXLAN/Geneve/GRE 封装；并给出 XDP 定位（driver 层最早 ingress、直访 DMA buffer、DPDK 级性能、复用内核安全模型、与 tc 互补）。
- **对学习者**：一篇读懂 eBPF 容器网络的"创世叙事"，尤其"per-container 定制编译"这一后来少有人强调的设计点。

## [183] Katran 开源公告（Facebook Engineering 博客，2018-05-22）
- **是什么**：Facebook 开源 Katran 的官宣长文（Nikita Shirokov / Ranjeeth Dasineni），全文完整——生产级 XDP L4 负载均衡器的最完整设计文档。
- **核心内容**：Facebook PoP 规模 L4LB 的四代际演进——一代基于 IPVS 内核模块（ExaBGP 宣告 VIP + ECMP 分流 + 5-tuple 一致性哈希 + IP-in-IP 封装 + DSR），痛点是 LB 与 backend 无法同机共存（CPU 密集、故障域耦合）；二代 Katran 用 XDP+eBPF 重造转发面：**driver 模式下 NIC 收包即触发 BPF、内核介入之前**，lockless + per-CPU map，随 RX 队列数线性扩展。
- **亮点**：四个工程细节都是教科书级——① 扩展版 Maglev 哈希（抗 backend 故障+非等权重+代码小到全进 L1 cache）；② 哈希比查 LRU cache 还快时把 5-tuple 状态表实现为 LRU 驱逐缓存（计算 vs 查找的权衡可调，极端内存压力下有 "compute only" 开关）；③ RSS 友好封装（不同流用不同外层源 IP、同流恒定，保证 NIC 多核分发）；④ 无包时几乎零 CPU（消灭 busy loop）。
- **坑/约束（文末自列）**：只支持 DSR 模式；要求 L3 路由拓扑；不转发 IP 分片也不自行分片（建议调 MTU/TCP MSS）；不支持带 IP options 的包；包上限 3.5KB；单臂（LB on a stick）场景假设。
- **对学习者**：XDP 生产化必读；仓库 facebookincubator/Katran。
- **对 agent**：本地 `/usr-data/data2/kylin/network/awesome-ebpf/web/md/183.md`；grep `Maglev`、`LRU`、`RSS`、`direct service return`、`3.5 KB` 取设计要点。

## [185] Droplet: DDoS countermeasures powered by BPF + XDP（netdev 2.1）
- **是什么**：netdevconf 2.1（2017-04）talk session 页；讲者 Huapeng Zhou、Doug Porter、Ryan Tierney、**Nikita Shirokov**（与 [183] Katran 同一作者，Facebook）。
- **核心内容**：Droplet 是 Facebook 的**通用 BPF policer 框架**——在网络栈最早阶段（尽量 line rate）丢包，天生为抗 DDoS 服务，是 Facebook 插接 DDoS 对策的首选基础设施。机制：用户用受限 C 写 policer → 运行时编译 → 挂入内核；框架抽掉所有 user/kernel 交互，用户只写 policer 逻辑；**BPF 程序可链式串联**（多对策同时生效）；**policer 代码作为配置下发**（攻击进行中快速响应）。附 slides 与 YouTube（youtu.be/YEU2ClcGqts）直链。
- **亮点**：与 [183] 互补——Katran 管"转发选路"（L4LB），Droplet 管"丢包防御"（policer），二者构成 Facebook XDP 双件套；"策略即配置、运行时编译、程序链"三个设计后来被业界广泛模仿。
- **对学习者**：设计 BPF 程序分发/热更新框架的最佳参照；与 Cilium 的 per-container 编译思路对照着读很有收获。
- **对 agent**：本地 `/usr-data/data2/kylin/network/awesome-ebpf/web/md/185.md`；全文 50 行，直接读；grep `policer`、`chain`、`configuration` 取设计词。
