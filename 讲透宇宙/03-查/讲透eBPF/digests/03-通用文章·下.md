## [38] BPF: A Tour of Program Types

- 是什么：Oracle Linux 内核开发者 Alan Maguire "Notes on BPF" 六部曲第 1 篇（2019-01），基于 Linux 4.14（UEK5），逐一讲解 `enum bpf_prog_type` 全部程序类型。
- 核心内容：对每类程序回答统一四问——干什么用/怎么 attach/拿到什么 context/何时被执行。覆盖 socket 类（SOCKET_FILTER/SOCK_OPS/SK_SKB）、tc（SCHED_CLS/SCHED_ACT）、XDP、kprobe/tracepoint/perf event、cgroup（CGROUP_SKB/CGROUP_SOCK）、轻量级隧道（LWT_IN/OUT/XMIT）六大类。
- 亮点：开头用 `tcpdump -d 'tcp'` 反汇编 cBPF 字节码逐条讲解过滤逻辑（jeq jt/jf 跳转、ret 65535=accept），是理解 cBPF→eBPF 演化的最佳入口；每个程序类型都给内核源码锚点（如 `sock_queue_rcv_skb()`、`tcp_call_bpf()`、`net/core/lwt_bpf.c`、bnxt 驱动的 `ndo_bpf`）。
- 关键事实：XDP 设计目标=在 sk_buff 分配之前处理包（driver 层 real XDP vs `net/core/dev.c` 的 generic XDP，后者不省 skb 开销）；SOCK_OPS 用 op 字段区分事件（连接建立/重传超时）且可 `bpf_setsockopt()` 反向设置；SK_SKB 配合 sockmap 做四层负载均衡（verdict = PASS/DROP/REDIRECT）；LWT 用 `ip route add encap bpf` 挂载。
- 学习者价值：程序类型全景图+四问框架，选型（XDP vs tc vs cgroup）判断力的地基。
- AI agent 用法：本地 `web/md/38.md`，可 grep `BPF_PROG_TYPE_`、`SO_ATTACH_BPF`、`xdp_md`、`bpf_sk_redirect_map` 查各类型 attach 方式与 context 结构。

## [39] BPF In Depth: BPF Helper Functions

- 是什么：六部曲第 2 篇（2019-01），按程序类型分组讲解 BPF helper functions 及其可用性矩阵。
- 核心内容：base 集（`bpf_map_lookup/update/delete_elem`、`bpf_tail_call`、`bpf_ktime_get_ns`、`bpf_trace_printk`、`bpf_get_prandom_u32`、`bpf_get_smp_processor_id`）+ 各类型专属 helpers：socket 类（`bpf_skb_load_bytes`、`bpf_setsockopt`、`bpf_sk_redirect_map`）、tc 类（csum 三件套 `bpf_csum_diff`/`bpf_l3/l4_csum_replace`、`bpf_skb_change_proto` NAT64、tunnel key/opt 四件套、`bpf_clone_redirect`）、XDP（`bpf_xdp_adjust_head`）、tracing 类（`bpf_probe_read[_str]`、`bpf_get_stackid`、`bpf_get_current_pid_tgid/comm/task`、`bpf_probe_write_user`）。
- 亮点：讲清了 verifier ops 三回调机制（`get_func_proto`/`is_valid_access`/`convert_ctx_access`，在 `net/core/filter.c` 的 `struct bpf_verifier_ops`）——每个程序类型能调哪些 helper 就是由此裁剪的；大量 helper 文档直接引用 Quentin Monnet 整理的 uapi 注释。
- 关键事实：`bpf_tail_call` 上限 MAX_TAIL_CALL_CNT=32；`bpf_trace_printk` 慢且打印告警，生产应用 `bpf_perf_event_output`；改包类 helper（store_bytes/pull_data/change_tail）会使 verifier 先前的指针检查全部失效需重验；`bpf_probe_write_user` 有 TOC-TOU 风险禁止用于安全机制，attach 时内核日志打警告；`bpf_get_stackid` 需 `sysctl kernel.perf_event_max_stack` 调大才能抓 Java 长栈。
- 学习者价值：helper 可用性矩阵是写程序前"这个 attach 点能做什么"的速查表。
- AI agent 用法：本地 `web/md/39.md`，可 grep `bpf_csum_diff`、`bpf_probe_read_str`、`BPF_F_RECOMPUTE_CSUM`、`bpf_verifier_ops` 获取各 helper 语义与使用限制。

## [40] BPF In Depth: Communicating with Userspace

- 是什么：六部曲第 3 篇（2019-01），讲 BPF 程序与用户空间通信的三条通道：BPF maps、perf events、bpf_trace_printk。
- 核心内容：① maps——枚举 4.14 全部 15 种 map 类型并逐个点评（ARRAY/PERCPU_ARRAY/PROG_ARRAY tail-call 跳表/PERF_EVENT_ARRAY/CGROUP_ARRAY/ARRAY_OF_MAPS/HASH/PERCPU_HASH/LRU_HASH/LPM_TRIE/STACK_TRACE/SOCKMAP/DEVMAP），给出 userspace 侧 `bpf_create_map`/`bpf_map_update_elem`/`bpf_map_get_next_key` 等 syscall wrapper；② perf events——mmap 共享内存+poll() 流式取数，适用于变长数据；③ bpf_trace_printk——仅调试用，`cat /sys/kernel/debug/tracing/trace_pipe` 读取。
- 亮点：map pinning 机制讲得细（iproute 的 `bpf_elf_map` 结构、PIN_NONE/PIN_OBJECT_NS/PIN_GLOBAL_NS 三档、PIN_GLOBAL_NS 落在 `/sys/fs/bpf/tc/globals/`、libbpf `bpf_obj_pin`/`bpf_obj_get` 配对）；map-in-map 只支持两层且 PROG_ARRAY 不允许 map-in-map（会加大 tail call 验证难度）；`array_map_lookup_elem()` 内核实现原文贴出（index & index_mask）。
- 关键事实：PERCPU map 的设计动机=热路径写 per-CPU 副本免锁、userspace 低频聚合；HASH map 持续新增会 E2BIG，应换 LRU_HASH；STACK_TRACE map 的 key 是栈指令指针的 32 位哈希，典型用法"内核侧拿 stackid 做 key、用户态再查符号表还原"（offwaketime 范例）；perf event 属性必须 PERF_TYPE_SOFTWARE + PERF_COUNT_SW_BPF_OUTPUT + PERF_SAMPLE_RAW；trace_printk 格式串必须预定义为变量否则 verifier 拒绝。
- 学习者价值："选哪种通道传数据"的决策树：共享状态/程序间交换→map，变长流→perf event，临时调试→trace_printk。
- AI agent 用法：本地 `web/md/40.md`，可 grep `BPF_MAP_TYPE_`、`PIN_GLOBAL_NS`、`bpf_obj_pin`、`RLIMIT_MEMLOCK`、`PERF_COUNT_SW_BPF_OUTPUT` 查 map 选型与 perf 通道搭建步骤。

## [41] BPF In Depth: Building BPF Programs

- 是什么：六部曲第 4 篇（2019-01，7 分钟短文），讲如何从零搭建内核外（out-of-tree）BPF 程序编译环境。
- 核心内容：① 前置内核配置检查（CONFIG_BPF/_SYSCALL/_JIT/_EVENTS、NET_CLS_BPF、NET_ACT_BPF），`grep BPF /boot/config-$(uname -r)`；② 依赖安装——clang/LLVM（>3.4/>3.7.1，`llc --version` 确认 bpf target）、iproute/tc 4.14+、kernel-devel 头文件；③ 目录布局 bpf/+include/+user/ 三层，本地拷贝 `bpf_helpers.h`/`bpf_endian.h`/`bpf_load.c` 等内核树文件；④ 完整 Makefile：clang `-emit-llvm` 出 IR 管道给 `llc -march=bpf -filetype=obj`，编译指向 `/usr/src/kernels/$(uname -r)` 的 uapi 头。
- 亮点：绕开 `/usr/include` 旧头文件的技巧（kernel-uek-headers 会全局覆盖引发兼容问题，改用 `-I$(linuxhdrs)/include/uapi` 指向 devel 包）；样例代码在 oracle/linux-blog-sample-code 仓。
- 关键事实（年代注意）：这是 2019 前后前-libbpf 时代的工作流——今天主流已是 libbpf + BTF + CO-RE（vmlinux.h 取代手抄内核头），但"ELF section 扫描→map/program 分离加载"的心智模型不变；文章明确说 BCC 非必需（clang 直接出 BPF 字节码）。
- 学习者价值：理解 BPF 程序"两半"结构（内核侧 .o + 用户态 loader）与编译管道 clang→LLVM IR→llc→ELF 的最原始形态；排障时（头文件版本错配）依然有用。
- AI agent 用法：本地 `web/md/41.md`，可 grep `CONFIG_BPF_SYSCALL`、`llc -march=bpf`、`LINUXINCLUDE`、`-emit-llvm` 获取环境检查清单与编译命令模板。

## [42] BPF In Depth: The BPF Bytecode and the BPF Verifier

- 是什么：六部曲第 5 篇（2019-01），讲 eBPF 指令集、寄存器模型与 BPF verifier 的两遍静态分析机制，以及如何解读 verifier 报错。
- 核心内容：① 11 个寄存器与 x86_64 的映射表（R0=rax 返回值、R1-R5=rdi/rsi/rdx/rcx/r8 函数参数、R6-R9=rbx/r13/r14/r15 callee-saved、R10=rbp 只读栈帧指针），helper 最多 5 个寄存器参数；② verifier 两遍分析——第一遍 DFS 验证程序是 DAG（拒绝 >BPF_MAXINSNS=4096 指令、回边循环、不可达指令、越界跳转），第二遍穷举所有条件分支路径做类型追踪（PTR_TO_PACKET + SCALAR_VALUE → PTR_TO_PACKET，指针+指针非法），分析上限 64k 指令处理量/1k 分支，状态等价（states_equal）时剪枝；③ 排障工具链 `llvm-objdump -S -no-show-raw-insn`（源码与 BPF 汇编交错）。
- 亮点：开篇贴出真实 verifier 报错（"math between pkt pointer and register with unbounded min value is not allowed"）逐字段解码 R8=inv(umin_value=28,umax_value=1048) 这类寄存器状态行，是少有的"verifier 日志阅读教程"；direct packet access 与 non-linear skb 一节解释了为何 `bpf_skb_pull_data()` 等改包 helper 之后必须重新做 data/data_end 边界检查（指针验证全失效）。
- 关键事实：eBPF 指令集形似 x86_64 是为了 JIT 映射简单（`arch/x86/net/bpf_jit_comp.c` 多趟收缩编译）；4.14 时代循环必须 `#pragma clang loop unroll(full)` 展开（bounded loop 是 5.3 才引入）；verifier 报错"通常是真 bug"——作者经验谈；对 packet pointer 做加法的值必须显式 unsigned（如 __u16）。
- 学习者价值：verifier 报错解读能力=写 BPF 程序最核心的生存技能，本篇是最佳入门。
- AI agent 用法：本地 `web/md/42.md`，可 grep `bpf_check()`、`BPF_MAXINSNS`、`states_equal`、`llvm-objdump`、`unroll(full)` 查 verifier 机制细节与排障命令。

## [43] BPF: Using BPF to do Packet Transformation

- 是什么：六部曲收官篇（2019-01），完整实战：用 tc BPF 在 ingress 把 IPv4 ICMP echo request 翻译成 ICMPv6、egress 把 IPv6 echo reply 翻回 IPv4——本机协议栈只见 IPv6，线上只见 IPv4。
- 核心内容：选型论证（要对称 ingress/egress 且需上送协议栈→选 tc 而非 XDP）；IPv4→IPv6 转换要点（IPv6 无头校验和、头 40 vs 20 字节、ICMPv6 有伪头而 ICMPv4 无、type/code 映射 ICMP_ECHO→ICMPV6_ECHO_REQUEST）；五步 ingress 代码逐段讲解——direct packet access 边界检查→`bpf_skb_load_bytes` 抄走 ethernet 头（`bpf_skb_change_proto` 会覆盖它）→构造 IPv6+ICMPv6 头→利用 Internet checksum 增量性质算 oldsum/newsum→`bpf_skb_change_proto`+三次 `bpf_skb_store_bytes`+`bpf_l4_csum_replace(BPF_F_PSEUDO_HDR)`。
- 亮点：sum16() 用 `#pragma clang loop unroll(full)` 展开求 16 位和，配合增量校验和只需知道新旧字段值即可修正 L4 checksum——网络协议数学与 BPF helper 的漂亮结合；完整可运行代码在 github.com/alan-maguire/bpf-test（本身是 BPF helper 单测仓）。
- 关键事实：改包失败路径返回 TC_ACT_SHOT 而非 OK（包已被改到不一致状态必须丢弃）；GSO/GRO offload 与隧道封装类 BPF 改包兼容性差，作者惯用 ethtool 关掉；IP options 未处理（示例简化）；ICMP 比 TCP/UDP 难转（TCP/UDP 只需改地址项的校验和差量）。
- 学习者价值：一个"非玩具"的改包全流程样本——把 program type 选型、direct packet access、改包 helper、增量 checksum 数学全部串起来。
- AI agent 用法：本地 `web/md/43.md`，可 grep `bpf_skb_change_proto`、`BPF_F_PSEUDO_HDR`、`TC_ACT_SHOT`、`sum16`、`eth_copy` 查改包流水线模板与 checksum 修正套路。

## [44] Linux Kernel Observability through eBPF

- 是什么：Sematext 工程博客（2019 首发页存至今，2025-03 更新），从可观测性厂商视角写的 eBPF 内核观测入门+Go 语言加载实战。
- 核心内容：BPF→eBPF 概念铺垫（verifier 保证安全/终止、稳定 ABI 跨内核版本）；`/proc/kallsyms` 与 hook 点全景（kprobes/XDP/uprobes 三类事件源）；从最小可运行的 kprobe/sys_setns 程序（SEC 宏+license/version section）到 clang→llc 编译命令、readelf 验证 ELF section；**Go 加载路线**——gobpf（iovisor）从预编译字节码加载 + packr 把 .o 嵌进 Go 二进制，实现零运行时依赖分发（对比 BCC 需在目标机装 LLVM+内核头的痛点）；perf event array map + Go channel 流式取数完整代码。
- 亮点：把"预编译 .o 嵌入二进制"的工程化思路讲得很实用，是 libbpf CO-RE 出现前 Go 圈的主流做法；用 `docker exec` 进容器触发 setns 来验证 kprobe 的测试设计巧妙。
- 关键事实：eBPF 程序默认随加载它的用户态进程退出而卸载；JIT 不可用时回退解释器执行；实例列举 Suricata（socket 负载均衡）、Cilium（容器安全策略）、Sematext Agent 自家（kill 信号/OOM/TCP-UDP 统计）三个生产应用。
- 学习者价值：Go 技术栈读者进入 eBPF 的最短路径样例；"为什么生产不裸用 BCC"的部署视角。
- AI agent 用法：本地 `web/md/44.md`，可 grep `gobpf`、`packr`、`InitPerfMap`、`kprobe__sys_setns`、`bpf_perf_event_output` 查 Go 加载器与 perf map 消费代码模板。

## [45] eBPF - From a Programmer's Perspective

- 是什么：哥本哈根 IT 大学 Niclas Hedam 的 preprint 综述（2023-05，CC BY 4.0，Quentin Monnet 参与校订），以 libbpf 视角系统讲 eBPF 架构，比 Oracle 系列更现代（kernel 5.19 + libbpf 1.2）。
- 核心内容：SEC 宏→ELF section→libbpf loader 推断 attach type 的机制链；两步编译（clang -target bpf -emit-llvm → llc -march=bpf）与每面 flag 的理由（-O2 必需否则栈膨胀、-g 让 bpftool 结构化读 map、-D__BPF_TRACING__ 开 PT_REGS 宏）；libbpf 加载五步 `bpf_object__open_file`→`find_program_by_name`→`load`→`attach`→`bpf_link__destroy`；程序类型子集讲解（socket filter/XDP 四种返回值、tracepoint vs raw tracepoint vs kprobe 上下文差异、perf event）；map 内核态/用户态双 API 对照（内核拿指针 vs 用户态拿拷贝）。
- 亮点：第 7 节"实际差异"用三个可复现的反例讲透 verifier——①直接解引用 ctx->rdi 指针 → "R1 invalid mem access"（必须 bpf_probe_read 先拷贝）；②概率上几乎必然终止的 while 随机循环（1/2^32 不终止）→ 仍被 "infinite loop detected" 拒绝（概率保证不够，要确定性保证）；③浮点运算直接编译失败（__adddf3 等 builtin 不支持，BPF 无 FPU）。附录 B/C 给出 kernel 6.2.11 的全部 33 种 program type 与 34 种 map type 枚举。
- 关键事实：verifier 规则集（512 字节栈上限、禁止有符号除法、寄存器/栈必须先初始化才能读——防内核内存泄漏到用户态）；hardening 阶段（程序内存只读化+常量盲化 constant blinding）；CVE-2017-16995 曾绕过 verifier 读写内核内存；GPL 兼容性取决于 program type 与所用 helper（tracing 类须 GPL，网络类可专有）；NVMe TP 4091 正在把 eBPF 定为计算存储 offload 标准指令集（作者自家 Delilah 项目即此方向）。
- 学习者价值：单篇 PDF 把"会写 C≠会写 eBPF"的三大陷阱（指针解引用/循环/浮点）讲成可亲手复现的实验，是 verifier 直觉训练的好教材；引用文献齐整（Fleming LWN、Calavera & Fontana 书、Starovoitov 原 commit）。
- AI agent 用法：本地 `web/md/45.md`，可 grep `bpf_object__open_file`、`PT_REGS_PARM1`、`infinite loop detected`、`__adddf3`、`CVE-2017-16995`、`BPF_PROG_TYPE_LSM` 查现代 libbpf 工作流与 verifier 拒绝案例。

## [47] Linux Extended BPF (eBPF) Tracing Tools

- 是什么：Brendan Gregg（Netflix/Intel 前，性能大师）个人站的 eBPF 追踪工具总目录页，BCC/bpftrace 生态的权威入口，配其著作《BPF Performance Tools》。

## [48] Beginner's guide to eBPF（repo: lizrice/ebpf-beginners）

- 是什么：Liz Rice（《Learning eBPF》作者、eBPF Summit 常驻讲者）的入门代码仓——eBPF Summit 2020 演讲 "The Beginner's Guide to eBPF Programming" 的现场编码配套。本地克隆 /usr-data/data2/kylin/network/awesome-ebpf/repos/lizrice/ebpf-beginners，最后提交 2023-05-08（"Clarifying what this repo is"），此后归档稳定。
- 规模与语言：极小教学仓——6 个文件（README/LICENSE + 3 个 Python + 1 个 C 头文件），Python+BCC 路线。核心三例：hello.py（kprobe 挂 execve syscall 打 "Hello World"，15 行）；ebpf.py（kprobe 挂 clone，BPF_HASH 按 UID 计数，38 行——演讲现场从零写出的主角）；packet.py（XDP 挂 eth0，按 IP 协议号计数包，配合 packet.h 的 lookup_protocol 内联函数）。
- 亮点：三个文件正好是三条主干线的最小样本——tracing kprobe / map 计数 / XDP 网络；`b.get_syscall_fnname()` 展示了跨内核版本挂 syscall 的正确姿势（不同内核 syscall 函数名可能带 __x64_ 前缀）。

- 学习者价值：半小时内从零跑通第一个 eBPF 程序的最短路径；跟着 YouTube 视频（youtu.be/lrSExTfS-iQ）边看边敲效果最佳。
