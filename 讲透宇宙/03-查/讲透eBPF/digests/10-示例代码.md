**总评**：本批是 awesome-ebpf 清单里"Examples"一节的全部示例代码资源，覆盖五类学习入口——内核自带示例（linux/samples/bpf）、内核自测试（selftests/bpf）、性能/功能基准原型（prototype-kernel）、BPF 工具大本营（bcc examples+tools）以及五个独立 GitHub 示例仓（Netronome/MPLS/ubpf/kill-example/zfw）。三条 git.kernel.org 链接（124/125/127）抓取时全部撞上 Anubis 反爬壳页，正文缺失，但其中两条（linux/samples/bpf、selftests）恰好是全批最权威的资源，好在 126（prototype-kernel）以其 fork+扩展的目录索引部分补位。BCC 两条（129/130）是本地克隆生成的目录索引，130 截断于 softirqs（缺 t~z 段工具）。独立仓整体质量分层明显：Netronome bpf-samples 与 vbpf/ebpf-samples 是成体系的参考实现集，ebpf-kill-example 是最小 CO-RE 教学样板，zfw 是真实产品级 XDP/TC 防火墙，MPLS 仓则是单点实验。对学习者价值排序：bcc/tools（现成 150+ 观测工具）> selftests（权威，但本批内容缺失需自行 clone）> prototype-kernel（性能基准方法论）> 独立小仓。

## [130] bcc/tools
- 是什么：iovisor/bcc 的 tools/ 目录索引——约 200+ 现成 BPF 观测工具清单，每工具配 `<name>.py` + `<name>_example.txt`（示例输出）成对出现。本批 md 抓取**截断于 softirqs**（字母序 s 处），缺 t~z 段（tcpaccept/tcpconnect/tcpdrop/tcpretrans/tcplife/tcptop/trace/ucall 系/vfs* /wakeuptime/xfs*/zfs* 等约 60 个未列入）。

- **对学习者的价值**：这是"生产系统观测工具箱"本体——按需取用即获得 Netflix/SRE 圈实战级排障能力；也是学"如何把 eBPF 包成 CLI 工具"的 200 份参考实现。
- **对 AI agent 的用法**：md 截断需注意 t~z 工具缺失；完整清单直接读上游 bcc 仓 tools/；grep md 关键词 `biolatency|runqlat|opensnoop|funclatency` 定位工具名再按 `*_example.txt` 学输出格式。

## [132] ebpf-samples
- 是什么：vbpf/ebpf-samples（最后提交 2026-07-03，仍活跃）——微软研究院 uBPF/vbpf 项目（Rust 实现的 eBPF verifier）的测试语料库，340 个文件。README 列三类：①从其他项目抽取的真实程序（bpf_cilium_test、falco、ovs、katran、suricata、linux-selftests 等 17 个来源目录）；②自带源码 src/（编译 ELF 在 build/）；③专用于验证解析/verifier 的 invalid/ 样本（11 个）。
- 核心内容：src/ 下每个 .c 对应一个 verifier 特性单点验证——exposeptr（指针逃逸）、infinite_loop/bounded_loop、map_in_map 全家族（anonymous/legacy/typedef）、lpm_trie、divzero、ctxoffset、correlated_branch 等，命名与内核 selftests/verifier 学术文献一一对应；asm/ 目录更是手写 eBPF 汇编级测试（packet_overflow、ringbuf_uninit、tail_call_bad 等 25 个 .asm）。
- 亮点：跨项目真实 ELF 语料（bcc 工具的 .bpf.o、Cilium、Falco、katran）+ 精心构造的边界用例，是"验证器实现/静态分析 eBPF"研究的一站式数据集。
- **第一个该读的示例文件**：`src/map_in_map.c`（map-in-map 三种写法对照）或 `src/exposeptr.c`（verifier 拒绝指针逃逸的最小样例）。
- **对学习者的价值**：想深入 Verifier 行为（为什么被拒/如何通过）时，按单特性最小样例逐个读，比读内核 selftests 大文件快得多；invalid/ 教"反面教材"。
- **对 AI agent 的用法**：本地 `repos/vbpf/ebpf-samples/`，grep `BPF_F_TIMER_CPU_CLOCK` 无意义，正确姿势=按目录浏览：`src/*.c` 特性名即检索键（loop/map_in_map/exposeptr）；asm/*.asm 可直接喂 llvm-objdump 语义分析；做 eBPF 静态分析工具时的标准回归集。

## [133] ebpf-kill-example
- 是什么：niclashedam/ebpf-kill-example（最后提交 2026-07-12，CI 活跃），自称 PoC 的最小 eBPF 教学样板：挂 `sys_enter_kill` tracepoint，捕获 SIGKILL 目标 PID 写入 BPF hash map，用户态 30 秒后读出打印。
- 核心内容：全仓只有 `src/kern.c`（内核态，含 BTF/CO-RE 风格定义）+ `src/user.c`（加载/attach/读 map）+ `docs/what-is-ebpf.md`（配套 eBPF 背景科普）+ Dockerfile + `test/test.sh` 端到端自测（起循环进程→kill→验证 eBPF 程序被触发，输出 `[ OK ]`）。
- 亮点：工程完整度极高的小仓——make deps/make/make test 三步走、CI 徽章、Docker --privileged 可复现构建（macOS/Windows 走 Docker VM 内核也能跑）、arm64 说明齐全。
- **第一个该读的示例文件**：`src/kern.c`（约百行，tracepoint + hash map 的全部要素）。
- **对学习者的价值：**零基础第一个 eBPF 程序的理想选择——10 分钟内从源码到运行验证，且带自动测试可确认环境 OK；docs/what-is-ebpf.md 可作入门第一页。
- **对 AI agent 的用法**：本地 `repos/niclashedam/ebpf-kill-example/`，grep `sys_enter_kill|BPF_MAP_TYPE_HASH|bpf_get_current`；作为生成其他 tracepoint 样例的模板仓最合适（结构即模板）。

## [135] XDP/TC-eBPF example
- 是什么：netfoundry/zfw（最后提交 2025-08-05），OpenZiti 生态的产品级有状态 IPv4/IPv6 防火墙——本批唯一"真实产品"而非玩具示例。TC-eBPF（ingress/egress）+ XDP（tun 口）双挂载点，README 近千行全是运维级细节。
- 核心内容：src/ 五个 C 文件分工明确——zfw_tc_ingress.c（ingress 过滤/tproxy 重定向）、zfw_tc_outbound_track.c（出站状态跟踪：TCP 60 分钟、UDP 30 秒老化）、zfw_xdp_tun_ingress.c（tun 设备 XDP 透明代理）、zfw_monitor.c（连接监控）、zfw.c（CLI 控制面，操作 40+ BPF map：zt_tproxy_map/tcp_map/udp_map/ddos_saddr_map/masquerade_map/modbus_state_map 等，README 的 --disable-ebpf 输出即完整 map 清单）。
- 亮点：功能密度惊人——原生 eBPF MASQUERADE（IPv4 Dynamic PAT + IPv6 static PAT）、DDoS 过滤、OT 工控协议深度过滤（DNP3 function code 白名单、MODBUS 响应校验）、最长前缀优先 + 同前缀按插入顺序的 deny 规则语义、规则容量 25 万条/prefix tuple 10 万条。
- **第一个该读的示例文件**：`src/zfw_tc_ingress.c`（数据面主干：packet parse→LPM 规则匹配→tproxy/passthrough 分流）。
- **对学习者的价值**：想看"eBPF 写成商业防火墙"长什么样（map 设计、规则引擎、状态表老化、CLI 控制面协作）的唯一样本；也适合研究 TC+XDP 协同。
- **对 AI agent 的用法**：本地 `repos/netfoundry/zfw/`，grep `BPF_MAP_TYPE_LPM_TRIE|bpf_fib_lookup|masquerade|dnp3`；map 命名规范（xxx_map）便于做数据面结构反推；配 BUILD.md 可编译。注意 README 明言部分功能依赖 OpenZiti 环境，standalone 模式需 ebpf_config.json 单接口配置。
