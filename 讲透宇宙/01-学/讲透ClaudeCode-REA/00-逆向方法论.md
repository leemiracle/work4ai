# 00 · 逆向方法论：从 claude.exe 到可读源码

> 目标产物：对 `/home/lwz/.nvm/versions/node/v22.23.2/bin/claude`（Claude Code v2.1.261）的完整逆向。
> 工具链：自研 Bun 单文件解包器 + REA (Reverse Engineer Anything) v6.5.0 应用图谱分析。
> 全程静态分析，不执行目标代码。日期：2026-10-16。

## 1. 目标识别

```
$ ls -la bin/claude          # → symlink 到 ../lib/node_modules/@anthropic-ai/claude-code/bin/claude.exe
$ file claude.exe
ELF 64-bit LSB executable, ARM aarch64, dynamically linked,
interpreter /lib/ld-linux-aarch64.so.1, not stripped, 215,211,432 bytes
```

关键判定：**Bun `--compile` 单文件可执行**。证据：

1. ELF section 表里存在 **`.bun` section**（offset `0x5340000`，size `0x79E0476` ≈ 128MB）——这是 Bun standalone 模块图的存放区；
2. 文件中存在 magic `\n---- Bun! ----\n`（两处：一处在 bun runtime 的 .rodata 字符串区，一处在 standalone payload 尾部）；
3. `readelf -lW` 显示非标准的 `__DATA,__wtf_config` / `__DCF` section 名（macOS 风格命名残留在 Linux ELF 上，Bun 的跨平台 section 写入器特征）。

也就是说：`claude.exe = Bun 运行时（~86MB）+ 独立模块图（~128MB：JS 源码 + JSC 字节码 + sourcemap + zstd 文档缓存 + 原生 .node 插件）`。

## 2. Bun standalone 格式（从 oven-sh/bun 源码还原）

权威来源：`src/standalone_graph/StandaloneModuleGraph.rs`（本仓 `/tmp/StandaloneModuleGraph.rs` 存档）+ `test/bundler/bundler_compile_splitting.test.ts` 的解析代码。

### 文件尾布局

```
[graph bytes ... ....................................]  ← [base, offsets_pos)
[Offsets struct (32 B)]                                ← offsets_pos = trailer_pos - 32
[TRAILER = "\n---- Bun! ----\n" (16 B)]                ← trailer_pos
(EOF)
```

### Offsets struct（repr(C)，小端）

| 字段 | 类型 | 含义 |
|---|---|---|
| `byte_count` | u64 | graph 长度；`base = offsets_pos - byte_count` |
| `modules_ptr` | StringPointer | 模块表 `{offset:u32, length:u32}`（相对 base） |
| `entry_point_id` | u32 | 入口模块在表中的下标 |
| `compile_exec_argv_ptr` | StringPointer | 编译期 argv |
| `flags` | u32 | 位标志（HAS_SOURCE_HASHES=1<<5 …） |

### 模块表 = N × CompiledModuleGraphFile（52 B/条，unaligned-safe）

```
name:                 StringPointer  {offset u32, length u32}
contents:             StringPointer
sourcemap:            StringPointer
bytecode:             StringPointer      // JSC bytecode（--bytecode 编译产物）
module_info:          StringPointer
bytecode_origin_path: StringPointer
encoding: u8   // 0=Binary, 1=Latin1(默认), 2=UTF-16LE ⚠️ 关键坑
loader: u8     // 1=js 等
module_format: u8
side: u8       // 0=server, 1=client
```

**坑（实证钉版）**：`Encoding` 枚举是 `Binary=0, Latin1=1, Utf16=2`。Latin1 文件若被当成 UTF-16 解码，ASCII 双字节折叠成 CJK 乱码（"/*" → "⼯"）。正确处理：encoding==1 → 逐字节 codepoint 转 UTF-8；encoding==2 → UTF-16LE 解码。

### claude.exe 的实际值

```
file size      : 215,211,432
trailer @      : 215,090,278
graph base @   : 87,293,960 (byte_count = 127,796,286)
modules table  : count = 94,536 / 52 = 1,818 个模块
entry_point_id : 5   →  /$bunfs/root/cli
flags          : 0x7FF (bit0-10 全开：含 source hashes、builtin bytecode、
                 string table、startup module count、module-info table、
                 prelinked graph、runtime options、linked bytecode payload)
```

模块名统一前缀 `/$bunfs/root/`（Bun 虚拟文件系统 bunfs 的根）。

## 4. REA 应用图谱分析

REA v6.5.0（`/data/usershare/ai/reverse/rea`，源码部署 + `npm ci --ignore-scripts && npm run build:cached` 构建）。

```bash
rea analyze-javascript-application "/extracted/$bunfs/root" \
    --max-heap-mb 4096 --max-semantic-nodes 100000 --max-semantic-nodes-per-file 1500 \
    --json > claude-app-evidence.json
```

### 坑（钉版）

1. **默认参数跑不完**：默认每文件 20,000 语义节点，57MB 的 minified 源码（单 chunk 最大 8.4MB）在 854/1640 处撞爆 parent result budget（1.95GB）报
   `The parent's result capacity was exhausted...`。解法：`--max-semantic-nodes-per-file 1500` 降采样（图谱用途足够，语义细节靠人工/子代理补）。
2. **noexec 文件系统**：REA 仓若放在 `noexec` 挂载区（如本机 `/usr-data/data1`、`/usr-data/data2`），turbo/esbuild 等原生二进制 `spawn EACCES`。解法：整个仓 cp -a 到可执行分区（本机 `/data`）。`npm ci --ignore-scripts` 可绕过 esbuild postinstall（vitepress 文档站用，分析链路不需要）。
3. REA 的 JS 分析**永不执行目标代码**（纯静态 parse + AST 投影），对 agent 产物做逆向时的安全边界友好。

## 5. 交叉验证策略（多源证据）

| 证据源 | 用途 | 局限 |
|---|---|---|
| Bun 模块图提取（源码） | 控制流/字符串/常量——ground truth | minified，符号名丢失 |
| 内嵌文档缓存（.zst/.md） | 官方口径的产品语义（Managed Agents/Skills/插件 API） | 可能滞后于代码 |
| npm 包 `sdk-tools.d.ts` | 49 个工具的输入/输出 schema 权威清单 | 仅 SDK 面 |
| REA 应用图谱 | 模块级依赖关系、跨文件结构 | 语义节点降采样后细节有限 |
| `claude --help` / 运行时行为 | CLI 面 sanity check | 动态行为，不进本报告主线 |

逆向结论的置信度分级：**[S]** = 源码直读（字符串/常量/结构）；**[D]** = 官方内嵌文档；**[I]** = 推断（标注依据）。

## 6. 复现手册

```bash
# 1. 解包
python3 /data/usershare/ai/pipeline-bin/bun/extract_bun_standalone.py \
    <claude.exe 路径> <outdir>

# 2. 解压内嵌文档（可选）
find <outdir> -name '*.zst' -exec zstd -dc {} -o docs-cache/$(basename {} .zst) \;

# 3. REA 图谱（在可执行分区跑）
cd /data/usershare/ai/reverse/rea
node scripts/rea.mjs analyze-javascript-application "<outdir>/\$bunfs/root" \
    --max-semantic-nodes-per-file 1500 --json > evidence.json

# 4. 字符串定位（minified 文件用字节偏移）
grep -abo 'You are Claude Code' <outdir>/\$bunfs/root/chunk-*.js
python3 -c "print(open('<file>').read()[<offset-500>:<offset>+2000])"
```
