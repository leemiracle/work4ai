# 讲透 awesome-opencode

> awesome-opencode（本地 `/usr-data/data2/repos/awesome-opencode`，最新提交 `6624a86 docs: auto-regenerate README and registry data`）——opencode 生态（终端 AI coding agent，官方仓在 anomalyco org）精选清单，10.7k star。约 20 个源文件构成一套教科书级「数据驱动 awesome 清单」流水线。行号锚均经源码核实（2026-11-02）。

## 一、仓定位：数据驱动，不是手维护清单

多数 awesome 清单是巨大手写 README，靠人肉编辑表格。本仓走另一条路：**README 是构建产物，源数据是 YAML**——`data/{category}/*.yaml`（111 条目）经 `validate.js` 校验，由 `generate-readme.js` 渲染替换模板占位符生成 README.md，由 `export-json.js` 产出 dist/registry.json。

三重证据：① README 全文是 HTML——每条目为 `<details><summary>` 折叠块（scripts/utils/template.js:61-68），六分区锚 id 从 official 到 resources（README.md:36-1069）；② 最新提交即自动再生，CI 以 `paths: data/**` 过滤触发（generate-readme.yml:7）；③ 模板只留五个占位符（README.template.md:55-111），OFFICIAL 区无占位符、是纯静态表格（README.template.md:43-45）。收益直接：贡献 PR 只需加一个 4 行 YAML，校验、字母序排序（generate-readme.js:64-68）、star 徽章、折叠 HTML 全自动。

## 二、机制解剖：schema、校验链与三条管线

**schema：四必填键 + 宽松扩展。** `data/schema.json` 必填仅 `["name","repo","tagline","description"]`（schema.json:61），盘上 themes/poimandres-theme.yaml 即四键极简样本。可选键五类：scope（枚举 global/project，对应 `~/.config/opencode/` 与 `.opencode/`，schema.json:33）、tags、min_version（semver 正则，schema.json:48）、homepage、installation。约束克制：repo/homepage 用 `format: uri`，tagline 限 maxLength 120（schema.json:21）。最关键决策是 `additionalProperties: true`（schema.json:62）——允许任意额外字段，类型由目录推导；代价是拦不住拼错的键名。

**校验链：Ajv 正主在 utils。** 定位漂移点：Ajv 不在 scripts/validate.js，正主在 scripts/utils/validation.js——require 与实例化在 L7-11，`getValidator()` 闭包单例懒编译在 L21-28。校验前有隐式协议：validateEntry 先 delete `_filePath`/`_fileName`（validation.js:41-42），这两键是 readYamlDir 注入的元数据（scripts/utils/yaml.js:35-36）。数据读取两入口：validate.js:21-22 递归 `data/**/*.yaml`（连 examples/ 也校验）；utils/yaml.js:30 单层非递归——因五类目录均无子目录，行为等价。

**三条管线。** validate（package.json:8）逐文件校验，任一失败 exit 1；CI 侧只校验 PR 改动文件且有 `if [[ -n ]]` 空值守护（validate-pr.yml:35-36）。generate-readme（package.json:7）：五类目录→校验过滤（坏条目跳过，generate-readme.js:51-61）→字母序→渲染→写 README，目录不存在 ENOENT 容错（generate-readme.js:42-44）；star 徽章靠负向前瞻正则提取 owner/repo 拼 badgen.net（template.js:47），gist 与 `/discussions/` 链接分流渲染不加徽章（template.js:39-41）。export-json 产出 dist/registry.json 平铺 111 条，productId 优先取 `_fileName`（export-json.js:26-27）——**文件名即产品标识**；有校验错误最终 exit 1（export-json.js:150-152）；log 按输出目标分流（export-json.js:112-118），管道输出 JSON 时日志走 stderr，永不污染数据流。

## 三、条目生态观察：111 个条目众生相

盘面实数：**plugins 68 + projects 32 + agents 4 + themes 4 + resources 3 = 111 条**，另 examples/ 6 个模板；dist/registry.json 恰 111 个 productId，与源数据零漂移对账。

**fork 血缘**：oh-my-opencode.yaml 与 oh-my-opencode-slim.yaml 构成 origin/fork 对，后者自述 "Slimmed-down fork"（oh-my-opencode-slim.yaml:4）。**跨资产双收录**：malhashemi 两仓库被两类同时收录——data/plugins/opencode-sessions.yaml:2 与 data/projects/opencode-sessions.yaml:2 的 repo 完全相同，opencode-skills 同构双录；但 PR 模板又要求 "Not a duplicate"（PULL_REQUEST_TEMPLATE.md:20），边界靠人工裁量。**命名碰撞对**：opencode-session.yaml（作者 GNITOAHC）与 opencode-sessions.yaml 仅一字母之差、作者仓库全不同，检索极易混淆。**作者集群**：kdcokenny 唯一跨目录集群共 5 条（plugins 四条 + projects 的 ocx）；oc-* 前缀集群作者各异，是命名惯性非血缘。**repo 四种形态**：GitHub 根 URL 之外，① Codeberg 托管（unmoji.yaml:2，全仓唯一非 GitHub 主机）；② 讨论帖——data/resources/debug-log-to-text-file.yaml:2 指 `.../discussions/19`，唯一非仓库 URL；③ 子目录 URL（themes/lavi.yaml）。**名实错位带**：目录名与仓库名错位是常态，梯度从 opencode-neovim vs opencode.nvim，到 xquik vs x-twitter-scraper（xquik.yaml:2），最重是 universal-llm-proxy vs LLM-API-Key-Proxy（universal-llm-proxy.yaml:2）。xquik/tokscale 等通用多 agent 资产被收进专属清单，口径是「可用」而非「专为其造」。

## 四、勘误精选：文档与盘上不一致六处

1. **「六类」实为五类，forks 未落地。** docs/schema-design.md:34 目录树、data/examples/README.md:18 映射表、examples/fork.yaml:2-3 头注释均指向 `data/forks/`，但仓库无此目录，generate-readme.js:16 与 export-json.js:14 的 CATEGORIES 均五类不含 forks——**即便提交 fork 条目也不进任何生成链**（宽松 schema 反而放它通过校验，静默失踪）。
2. **bootstrap.js 悬空。** package.json:9 注册 `npm run bootstrap` 指向不存在的 scripts/bootstrap.js。
3. **CoC v1.4 举报通道空置。** code-of-conduct.md:70 自述 Contributor Covenant 1.4（上游已 2.x）；code-of-conduct.md:58 举报邮箱是空占位符（"contacting the project team at ."）。
4. **两套重复 YAML 读取实现。** validate.js:30-38 的 loadYamlFile（catch 返 null 宽容语义）与 utils/yaml.js:15-22 的 readYamlFile（throw 语义）并存，演进残留。
5. **contributing.md 漏 examples 目录。** contributing.md:17-21 只列五个收录目录，实盘 data/ 还有第六个 examples/。
6. **文档滞后 + 双 org 并存。** schema-design.md:483-486 §8 只列两命令，export-json 在 §9.3 被列为 Future Work（schema-design.md:511），但脚本已实现且 registry.json 已是库内产物；另模板内 5 处链接指 awesome-opencode org，README 实际生效的官方仓链接全指 **anomalyco**（README.md:42-45）。

## 五、使用建议

**当生态地图用。** plugins(68)/projects(32) 是主料：通知、遥测、记忆、认证类插件翻 plugins 折叠块，GUI、代理、编辑器集成在 projects。三类噪声要心里有数：名实错位带、双收录对、通用资产混编。机器可读入口直接用 dist/registry.json——111 条平铺、productId 即文件名、type 字段齐全，不必解析 HTML README。

**收录口径评估。** 门槛实测宽松：四必填键 + kebab-case 文件名 + 过 Ajv 即入（PULL_REQUEST_TEMPLATE.md:3-7 五选一对应 CATEGORIES）。三类先例可援引：非 GitHub 托管、非仓库 URL、跨生态通用工具。两坑别踩：**别提交 fork 条目**——管线未实现，过了校验也不进 README（勘误 1）；description 多行折叠里别写 `-Additions` 这类连字符后无空格的行（fork.yaml:14），YAML 折叠后成字符串前缀而非列表项，schema 只查 minLength 拦不住。

**给想做同款清单的人。** 「YAML 源数据→schema 校验→占位符生成 README+JSON registry」三件套 + CI paths 过滤 + PR 增量校验，克隆成本极低（依赖仅 4 个，package.json:13-18）。值得照抄：export-json 的 stderr 日志与 exit 1 不出脏数据、validate-pr 的空值守护。要避免：文档与 CATEGORIES 同步演进、抽工具库后删旧实现、CoC 引用填真实邮箱。
