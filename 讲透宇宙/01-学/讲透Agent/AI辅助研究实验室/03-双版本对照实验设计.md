# 双版本对照实验：人类小组版 vs 多代理软件版（设计书 v1.0）

> 核心问题：**"AI 产出 + 独立验证 + 勘误沉淀"三环，由人类小组执行与由多代理流水线执行，产出质量与知识资产有何系统性差异？人在环中的不可替代部分究竟在哪里？**

## 一、理论基础：两版本的同构性

人类小组版（规约驱动）与多代理流水线（已在 63+25 批知识库生产中验证）在结构上一一同构：

| 功能环 | 人类小组版 | 多代理软件版 |
|---|---|---|
| 猜想/任务生成 | 猜想人主持研讨登记 | 派发模板生成任务书 |
| AI 分析 | 记录人提交 AI 获取分析 | file-analyzer 子代理 |
| 独立验证 | 检查人署名重走推理 | 主会话验收+锚终验抽验 |
| 勘误沉淀 | 共享文档证伪条目 | NOTES-DIGEST+台账钉版 |
| 完成判定 | "验证过的结论数" | validator 0 issues 外部化判据 |
| 失败恢复 | 角色轮换/中止条件 | 1308 断点续跑协议 |

**差异变量**（实验要测的）：验证激励来源（社会问责 vs 外部化判据）、错误记忆的持久性（人脑/文档 vs fingerprints+台账）、锚定抗性（人的框架依赖 vs 模板的甄别条款）。

## 二、实验设计

### 任务选择
同一组**可客观判分**的研究任务，例如：
- T1 文献断言核查：给定 N 条 AI 生成的领域断言（含已知比例的错误引用/错误数据/过度概括），核查并出具带证据的判定
- T2 代码库知识抽取：给定中小型代码库，产出"架构说明+勘误清单"（直接复用 understand 流水线的评分口径：锚命中率/错误发现数）
- T3 证明审查：给定若干形式化证明（含可复核的漏洞），验证或定位错误

### 分组与流程
- **A 组（人类小组）**：4-6 名研究生，按《使用规约》执行，2 周/任务
- **B 组（流水线）**：同等模型底座的多代理配置（生成/评估分离+甄别条款+锚终验），同等墙钟预算内运行
- **C 组（人机混合，可选）**：1-2 人监督流水线并拥有否决权——检验"监督者是否退化为橡皮图章"

### 控制变量
- 同一模型底座与 token 预算；同一任务材料；评分者盲评（不知产出源自哪组）
- 交叉设计：A 组被试在任务间轮换，控制个体差异

### 测量
| 维度 | 指标 |
|---|---|
| 产出质量 | 断言判定准确率 / 锚命中率 / 错误发现率（含注入错误） |
| 效率 | 墙钟时间、token 成本、人力小时 |
| 知识资产质量 | 事后第三方仅凭产出物复现结论的成功率 |
| 可迁移性 | 换任务领域后性能保持率（流水线模板 vs 人的领域知识） |
| 过程特征 | 错误类型分布（人有而 AI 无的错误类别，及反之） |

## 三、预期假设（可证伪）

- H1：B 组在**效率与锚密度**上显著占优（流水线的外部化判据强制每条结论可验证）
- H2：A 组在**跨领域迁移与异常敏感度**上占优（人对"哪里不对劲"的先验强于模板条款）
- H3：C 组若监督者可用最小时间（<A 组 20% 人力）截住 B 组关键错误类别，则混合模式帕累托占优
- H4：两版本的**错误类别互补**——流水线的错误集中于规格盲区（scanner 型系统性漏报），人的错误集中于确认偏误与疲劳

## 四、伦理与边界

1. 被试知情同意+可随时退出；产出匿名化处理
2. 不测量个体排名，只报告组级差异（保护验证激励不扭曲为表演）
3. 若 A 组表现显著劣于 B 组，结果披露须附"规约版本/培训时长"上下文，防止"人类无用论"的过度解读——本实验测的是**制度安排**，不是人的上限

## 五、产出与去向

- 数据集+分析报告 → 教学研究素材（AI 时代科研训练实证）
- 若 H3/H4 成立 → 直接反哺《使用规约》v2.0：把流水线的"外部化完成判定+错误类别清单"移植为人类小组的工具
- 与本会话知识库生产台账（CopilotKit 1892n/deer-flow 653n 等 88 批实证）可作 B 组的现成历史对照数据源
