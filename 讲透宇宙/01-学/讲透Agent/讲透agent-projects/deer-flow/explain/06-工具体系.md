# 06 · 工具体系：三段装配中枢与 MCP 双延迟缓存

## 角色定位

工具体系回答一个问题：**agent 每次装配时到底拿到哪些工具**。中枢是 `tools/tools.py:22` 的 `get_available_tools()`——一个函数把四个来源（config 工具、内置工具、视觉工具、MCP 工具）拼成最终列表，主 agent（agent.py:330）、子代理（task_tool.py:102）、bootstrap（agent.py:321）三处消费方都以它为唯一入口。`tools/__init__.py:1-3` 是纯 barrel（`from .tools import get_available_tools`），但这个"穿透"是刻意设计：task_tool.py:99 在函数体内 `from deerflow.tools import get_available_tools`，注释明示既避免循环依赖、又不让调用方感知 tools.py 的真实模块路径。

## 内部结构

**装配中枢**（tools/tools.py）三段拼接：

1. **config 工具段**：`config.tools` 逐条经 `resolve_variable(tool.use, BaseTool)` 反射装载（tools.py:43），`groups` 参数按 tool.group 过滤——自定义 agent 的 tool_groups 就在这里生效；沙箱五工具、社区搜索工具（tavily/jina 等）都是 config.yaml 里 `use: deerflow.sandbox.tools:bash_tool` 形式的条目。
2. **内置工具段**：模块级常量 `BUILTIN_TOOLS = [present_file_tool, ask_clarification_tool]`（tools.py:11-14）、`SUBAGENT_TOOLS = [task_tool]`（:16-19，注释钉版 task_status 已不暴露——轮询由后端内部完成）。运行时条件两个：`subagent_enabled=True` 才追加 task（:70-72）；模型 `supports_vision` 才追加 view_image_tool（:79-82，model_name 缺省取首个模型 :74-76）。
3. **MCP 工具段**（:50-64）：函数体内延迟 import `ExtensionsConfig` 与 `get_cached_mcp_tools`（tools.py:53-54），`ExtensionsConfig.from_file()` **直读磁盘**而非用带缓存的单例（:46-49 注释钉版：Gateway 是独立进程，其写入必须立即可见）——有启用的 server 才取缓存工具（:56-58），ImportError 降级为 warning（:61-62）。

**builtins 五工具**（tools/builtins/，`__init__.py:1-12` 统一再导出）：`ask_clarification_tool` 是 55 行的 return_direct 空壳（clarification_tool.py:6-7）——工具本体不做事，拦截语义全在 ClarificationMiddleware；`present_file_tool` 把文件路径归一到 `/mnt/user-data/outputs/*` 契约（present_file_tool.py:12）并维护 artifacts 状态供前端展示；`view_image_tool` 读图转 base64 写入 `viewed_images` 状态（view_image_tool.py:90-93），真正让模型"看见"的是 ViewImageMiddleware 的注入；`task_tool` 见 05 篇；`setup_agent` 仅 bootstrap 流程追加（agent.py:321）。

**MCP 三件套**（deerflow/mcp/）：

- **client.py** 纯参数翻译：`build_server_params` 把 McpServerConfig 翻成 MultiServerMCPClient 参数——stdio 要求 command（client.py:26-31）、sse/http 要求 url（:34-38），非法 transport 抛 ValueError（:40）；`build_servers_config`（:45）只取启用的 server，单 server 失败只记 error 不拖垮整批（:65-66）。
- **tools.py** `get_mcp_tools`（:14）：`MultiServerMCPClient` 在函数体内 try-import（:21-24），未装 langchain-mcp-adapters 返回空列表静默降级；同样 `ExtensionsConfig.from_file()` 直读（:26-30 注释）；OAuth 双注入——连接期把初始 Authorization 头塞进 server headers（:42-49），运行期给 client 传 `tool_interceptors` 实现每请求 token 刷新（:51-56）。
- **cache.py** 模块级缓存 + mtime 失效：`_mcp_tools_cache`/`_cache_initialized`/`_config_mtime` 三个全局（cache.py:11-14），`asyncio.Lock` 防并发初始化（:13）。**双延迟导入**在此文件成形：`_get_config_mtime` 延迟 import ExtensionsConfig（:23）、`initialize_mcp_tools` 延迟 import `deerflow.mcp.tools`（:71）——两条都是明示的避循环依赖模式。新鲜度靠 mtime 比较（`_is_cache_stale`:31，`current_mtime > _config_mtime` 即失效 :49），`get_cached_mcp_tools`（:82）先查 stale 再惰性初始化；**同步上下文调异步初始化的三路兜底**（:107-121）：事件循环未跑则 `run_until_complete`（:118）、已在跑（LangGraph 环境）则开 ThreadPoolExecutor 线程里 `asyncio.run`（:113-115）、无循环则直接 `asyncio.run`（:121）。

## 外部连接

上游消费方：make_lead_agent 传 groups+model_name+subagent_enabled 三参（agent.py:330）；task_tool 传 subagent_enabled=False 切断嵌套（task_tool.py:102）；客户端 `_ensure_agent` 重建时同路。配置双源：config.yaml 管 config 工具与分组，extensions_config.json 管 MCP server 与技能开关（`get_enabled_mcp_servers` extensions_config.py:177）；Gateway 的 `PUT /api/mcp` 写 json 文件但不重置 LangGraph 侧缓存（gateway/routers/mcp.py 注释钉版）——跨进程新鲜度完全依赖 mtime 检测链。反射底座 `deerflow.reflection.resolve_variable` 同时服务模型工厂与工具装载。

## 数据流

装配期数据流：make_lead_agent → get_available_tools → ①config.tools 反射实例化（含 env 变量解析）→ ②内置常量 + 条件追加 → ③ExtensionsConfig.from_file 读启用 server 列表 → get_cached_mcp_tools → stale?（mtime 比较，Gateway 改过就 reset）→ 未初始化则三路兜底跑 initialize_mcp_tools → MultiServerMCPClient 连接全部 server → get_tools() 返回 LangChain 工具 → 三段拼接返回。运行期数据流：模型挑工具 → 沙箱工具经 runtime state 拿 thread_data/sandbox（03 篇）；MCP 工具经 tool_interceptors 每调用刷新 OAuth 头；ask_clarification 在中间件层被截胡返回 Command。

## 设计决策

1. **from_file 直读 vs get_xxx 单例的分寸**：config（进程内一致即可）走单例缓存，extensions（跨进程可变）强制直读磁盘——同一仓里两套读取策略并存，判断标准只有"谁会在我之外改这个文件"。
2. **mtime 是双进程架构的最廉价 IPC**：Gateway 写、LangGraph 轮询 mtime，免掉消息总线；代价是检测粒度受调用频率限制（只在装配/取缓存时查）。
3. **可选依赖全 try-import 降级**：langchain-mcp-adapters 缺席只 warning + 空列表（tools.py:61、mcp/tools.py:23），核心链路永不因可选生态缺席而崩。
4. **壳工具模式贯穿**：ask_clarification（中间件拦截）、view_image（中间件注入）、task（后端轮询）三个"智能"工具的执行体都不在工具函数里——工具 schema 面向 LLM 声明能力，语义放编排层，是本仓反复出现的分层手法。

## 新人提示

- 加 config 工具不用改代码：config.yaml `tools:` 加一条 `use: 模块:变量` 即可，但记得 tool.group 要在某个 tool_groups 里，否则自定义 agent 过滤后看不见。
- MCP 工具不生效排查顺序：extensions_config.json enabled → langchain-mcp-adapters 装没装 → cache 是否 stale（看 "MCP config file has been modified" 日志）→ client.py 的 transport 参数校验报错。
- `get_cached_mcp_tools` 在事件循环内被同步调用时会临时开线程池线程（cache.py:113），偶发的一次性线程创建不是 bug。
- 改 tools.py 的 BUILTIN_TOOLS 常量会影响所有未显式配置 groups 的 agent；给自定义 agent 加专属工具优先走 config+group 路线。
