# 10 a2a 协议桥接：AgentCard 解析器四件套与 a2a-sdk 同名陷阱

> **三条勘误（任务指定必写，均以源码核实）**：①仓内 `src/agentscope/a2a/` 子包与 pip 包 a2a-sdk 的顶层模块 `a2a` **同名碰撞**——本包源码里 `from a2a.types import AgentCard`（如 `a2a/_file_resolver.py:65`）是绝对导入，指向 pip 包而非自家子包（`agentscope.a2a` 下没有 types 模块），阅读时极易看串；②nacos 导入根是反直觉的 `v2.nacos`（`a2a/_nacos_resolver.py:67`），但 pip 包名叫 nacos-sdk-python——"v2"不是笔误，是上游 SDK 的真实顶层包名；③`AgentCardResolverBase` 挂了 `@abstractmethod`（`a2a/_base.py:18`）但类声明**没有 ABCMeta**（`a2a/_base.py:12` 是纯 class）——装饰纯文档化，子类漏实现 `get_agent_card` 照样能实例化，调用时才炸。（其余锚相对 `src/agentscope/`）

## 1. 角色定位

a2a 子包只管 A2A 协议的"名片"环节：从四种来源把对端 agent 的 **AgentCard**（name/url/skills/capabilities 的 JSON 名片）取回并解析成 a2a-sdk 的类型——base 抽象、file 读本地 JSON、well-known 走 `/.well-known/` HTTP、nacos 走服务发现。真正的 A2A 通信（发任务、收流式事件）不在本包：那是 `agent/_a2a_agent.py` 与 a2a-sdk ClientFactory 的地盘。

## 2. 内部结构

`AgentCardResolverBase` 仅一个抽象方法 `get_agent_card`。`FileAgentCardResolver`（`a2a/_file_resolver.py:15`）零网络：读 JSON 文件，**运行时**才 import `a2a.types`（`a2a/_file_resolver.py:65`）并 `AgentCard.model_validate`（`a2a/_file_resolver.py:78`）。`WellKnownAgentCardResolver` 借力 SDK：import httpx 与 a2a-sdk 自带的 `A2ACardResolver`/`AGENT_CARD_WELL_KNOWN_PATH`（`a2a/_well_known_resolver.py:42`）；先把输入 URL 拆成 scheme://netloc 基座（`a2a/_well_known_resolver.py:58`），原 path 转为相对卡路径；httpx 客户端超时 600s（`a2a/_well_known_resolver.py:69`）；异常统一包成 RuntimeError 再抛（`a2a/_well_known_resolver.py:87`）。`NacosAgentCardResolver`（`a2a/_nacos_resolver.py:17` 签名处）构造时校验 agent 名与配置非空（`a2a/_nacos_resolver.py:45`），取卡时懒导入 `v2.nacos.ai`（`a2a/_nacos_resolver.py:67`，缺失时报安装指引 `:70`），走 `NacosAIService.create_ai_service` 短连接取卡（`a2a/_nacos_resolver.py:77`），finally 里 shutdown（`a2a/_nacos_resolver.py:89`）。

## 3. 外部连接

上游是 pip a2a-sdk（AgentCard/A2ACardResolver 类型），全以 TYPE_CHECKING 字符串占位（`a2a/_base.py:6` 一带）+ 方法内运行时导入，因此不装 SDK 也能 import 本包。下游消费者 `A2AAgent` 在运行时拉 `a2a.client.ClientFactory`（`agent/_a2a_agent.py:76`）；消息格式互转由 formatter 子系统的 `A2AChatFormatter` 承担（`formatter/_a2a_formatter.py:20`）。依赖声明在 pyproject 的 a2a extra（`pyproject.toml:48`），内含 nacos-sdk-python>=3.0.0 且留有"想拆分 card resolvers"的 TODO 注释。

## 4. 数据流

A2AAgent 构造 → 持有某 resolver → `await get_agent_card()` → AgentCard（含对端 url/skills）→ a2a-sdk 按卡建连并发任务 → 对端回 A2A Message/Task → `A2AChatFormatter` 转成内部 `Msg` 进 agent 主循环。四种 resolver 只影响"名片从哪来"这一步，之后的通信链路完全一致。

## 5. 设计决策

①**TYPE_CHECKING 占位 + 延迟导入**：协议 SDK 属重依赖，导入成本与版本冲突风险都隔离在方法体内。②**well-known 复用 SDK 解析器**而非自己拼 `/.well-known/agent-card.json` 路径——路径规范跟 SDK 版本走，避免双源漂移。③**file 实现保底**：测试与离线场景有零网络选项。④**nacos 支持版本锁定取卡**：构造参数 version 允许订阅特定版本的 agent card，服务发现语义对齐灰度发布。

## 6. 新人提示

- 坑 1（即勘误①）：排查 import 时记住两套 a2a——`agentscope.a2a`（本包，4 个 resolver）与顶层 `a2a`（pip SDK，类型与客户端）；IDE 自动补全经常跳错侧。
- 坑 2（即勘误②）：写 nacos 相关代码时 `pip install nacos-sdk-python` 装出的包根是 `v2.nacos`，别"修复"这个看起来像笔误的导入（`a2a/_nacos_resolver.py:67`）。
- 坑 3（即勘误③）：自定义 resolver 漏写 `get_agent_card` 不会有任何实例化期报错，直到首次调用拿到 None 才暴露；需要强约束请自行加 ABCMeta。
- 坑 4：nacos resolver 每次 `get_agent_card` 都 create→start→shutdown 一条连接（`a2a/_nacos_resolver.py:77`-`:89`），高频轮询场景会反复建连，需要自持长连接请绕过它直接用 NacosAIService。
- 坑 5：well-known 超时 600 秒（`a2a/_well_known_resolver.py:69`）对"取名片"而言极宽，弱网下 agent 启动可能长时间挂起，必要时提前 cancel。
