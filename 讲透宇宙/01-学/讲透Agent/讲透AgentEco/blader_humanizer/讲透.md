# 讲透 humanizer（blader/humanizer v2.7.0）

纯 Markdown 实现的 Claude Code / OpenCode skill，把 AI 生成文本改写得像人写的：运行时产物只有 SKILL.md，无构建无代码（AGENTS.md:7），知识源是 Wikipedia "Signs of AI writing"（WikiProject AI Cleanup 数千条 AI 文本观察沉淀，SKILL.md:24）。

## 一、定位：文风人性化改写 skill

一句话：**编辑器型 prompt 产品**，识别并清除 AI 写作痕迹，同时不许把文本改薄。

任务四原则（SKILL.md:30-33）：识别 pattern、改写而非删除、保留原意、匹配声音。最硬的是"覆盖原文覆盖的一切"——原文五段，改写稿还是五段（SKILL.md:31），即替换话术而非删内容。

理论根基是 Wikipedia 的洞察：LLM 用统计算法猜下一个词，输出滑向"适用面最广的最可能结果"（README.md:89）。AI 味的本质是**统计均值**——意义膨胀、推销腔、三连、均匀句长都是副作用；30 条规则即对均值反向拉扯。

## 二、技能结构与触发

仓库三层：`SKILL.md`（582 行，skill 本体与事实源，AGENTS.md:11）、`README.md`（197 行，人类向文档）、`AGENTS.md`（25 行，AI 维护者契约）。

**触发机制**全在 frontmatter（SKILL.md:1-20）：`name: humanizer`（SKILL.md:2）注册为 `/humanizer` 命令；`version: 2.7.0`（SKILL.md:3）；`description`（SKILL.md:4-10）声明"编辑或审阅文本使其更自然"时使用并枚举代表 pattern——触发靠宿主语义匹配，无正则；`compatibility: claude-code opencode`（SKILL.md:12）；`allowed-tools` 六工具 Read/Write/Edit/Grep/Glob/AskUserQuestion（SKILL.md:13-19），**没有 Bash**——权限面收窄到读写与提问，无副作用。

安装即 clone 到 `~/.claude/skills/humanizer/`（OpenCode 亦扫描该目录，README.md:39）。

**维护契约**（AGENTS.md:16-20）是工程亮点：pattern 增删/重编号必须同次变更同步 README 模式表（AGENTS.md:18）；两文件版本号一起 bump（AGENTS.md:19）。

## 三、改写规则体系：30 个编号 pattern

六大类，每条按"编号 + Words to watch + Problem + Before/After"组织：

| 类别 | 编号 | 要点 |
|---|---|---|
| 内容 | 1-6（SKILL.md:88-166） | 意义膨胀、-ing 伪分析、推销腔、暧昧归因、套路化"挑战与展望"节 |
| 语言 | 7-13（SKILL.md:170-254） | 24 词高频词表（SKILL.md:172）、系词回避（serves as→is）、否定平行、三连排比、同义词轮换、假区间、被动语态 |
| 风格 | 14-19、26-30 | em dash、粗体、行内标题列表、Title Case、emoji、弯引号、连字符对、权威话术、路标宣告、碎片标题、diff 锚定写作 |
| 沟通 | 20-22（SKILL.md:339-379） | 聊天残留（"I hope this helps"）、知识截止免责、谄媚语气 |
| 填充对冲 | 23-25（SKILL.md:384-414） | 填充短语、过度对冲、空洞光明尾巴 |

四条超出词表替换：

- **§14 em dash 是唯一硬约束**：终稿零 em/en dash，按句号>逗号>冒号>括号次序替换，交付前扫描 `—`/`–`，任一命中即未完成（SKILL.md:259-261、275）；v2.7.0 刚把它升级为"一律切除"（README.md:183）。
- **§26 有语法位置意识**：定语保留连字符（a high-quality report）、表语去掉（the report is high quality），人类连字符本就不一致（SKILL.md:417-427）。
- **§21 处理"无来源"元问题**：不止截止免责，还抓变体——查不到来源时写段"关于查不到"再编造补白（"maintains a low profile"），处方是"说不知道或删句，别把猜测打扮成事实"（SKILL.md:352-356）。
- **§30 面向代码场景**：文档别复述最近一次 commit，除非天生版本化如 changelog（SKILL.md:475-483）。

规则体系后半是**双向的**。防误报清单（SKILL.md:488-503）：孤立信号不算证据——完美语法、单个 however、孤立弯引号/em dash 都不是；判定看 **pattern 簇**："一个 em dash 什么都不是；em dash + 三连 + vibrant tapestry + Conclusion 节，就是自供状"（SKILL.md:503）。人类信号清单（SKILL.md:506-516）要求手下留情：难编造的怪细节、矛盾情绪、年代限定梗、句长方差、真诚自我打断，及 2022-11-30（ChatGPT 发布）前的文本默认非 AI 所写（SKILL.md:516）。这套判定论比规则更可迁移。

## 四、实现机制：纯 prompt 工程

没有脚本，全部智能由 prompt 结构承担，四个机制：

1. **draft → 自审计 → final 循环**（SKILL.md:521-528）：先初稿，再自问 "What makes the below so obviously AI generated?"（SKILL.md:525）列残留痕迹，据此出终稿。交付四件套：初稿、残留 bullets、终稿、可选变更摘要——self-critique 是固定工序。
2. **Voice Calibration**（SKILL.md:38-56）：给 2-3 段旧作，先分析句长/用词/标点/口头禅，再用样本 pattern 替换 AI pattern——"他们写短句你就别写长句，说 stuff 就别升级成 elements"（SKILL.md:50）。
3. **条件生效的人格注入**（SKILL.md:59-85）：PERSONALITY AND SOUL 只在博客/随笔类激活；百科/技术/法律文本"中性平实本身就是正确的人味"，不许硬塞观点（SKILL.md:63）。"无菌文本和 slop 一样露馅"（SKILL.md:81-85）。
4. **词表即数据**：Words to watch 是可维护枚举，配合 Before/After 构成语料库，升级只需扩表——11 个版本基本在做这件事（README.md:181-193）。

Full Example（SKILL.md:531-575）演示完整闭环：集齐各类 AI 痕迹的文本经初稿、三项自审到终稿，即机制的回归测试样例。

## 五、使用建议与局限

**建议**：中文效果打折——词表/弯引号/Title Case/em dash 都是英文指纹，中文需自建 pattern 表，但六大类框架与"簇判定"方法论可迁移；技术文档确认人格注入已门控；保留 voice 样本，否则产出是"通用干净腔"而非"你的腔"（README.md:79）。

**局限**：纯 prompt 实现，30 条规则一次全载，长文本遗漏率升，机械步骤（dash 扫描）也靠模型自觉；§21 处方"找到真来源"在权限内做不到——allowed-tools 无联网，只能删句不能查证；对 AI 辅助但人工重写的混合文本可能过度清洗；全仓无量化评测。
