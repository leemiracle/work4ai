1. 先会读每一行的格式
以会话#1 为例：

text
0.000s ← [SYN           ] seq=735774302 len=0
0.000s → [SYN/ACK       ] seq=3501541715 ack=735774303 len=0
0.000s ← [ACK           ] seq=735774303 ack=3501541716 len=0
每行大致是：

text
时间  方向  [TCP标志位]  seq=本端发送序号  ack=期望对端下一个序号  len=载荷字节数
← / →：方向。按端口看，172.17.0.1:55720 是客户端，172.17.0.4:8080 是服务端。

[SYN]、[SYN/ACK]、[ACK]、[PSH/ACK]、[FIN/ACK]：TCP 标志位。

seq：本端发送数据的起始序号。

ack：确认号，表示“我已收到对端直到 ack-1 的字节，下一个期望 ack”。

len：本包携带的应用层数据长度。len=0 通常表示纯控制包，但 SYN/FIN 虽然 len=0 也会消耗 1 个序号。


2. 怎么看出“三次握手”
三次握手的判定标准是：

客户端发 SYN，没有 ACK；

服务端回 SYN/ACK；

客户端再回 ACK。

会话#1 前三行就是：

text
0.000s ← [SYN     ] seq=735774302 len=0
0.000s → [SYN/ACK ] seq=3501541715 ack=735774303 len=0
0.000s ← [ACK     ] seq=735774303 ack=3501541716 len=0
逐步看：

第 1 行：[SYN]，客户端发起连接，初始序号 seq=735774302。SYN 占 1 个序号，所以对端应确认 735774303。

第 2 行：[SYN/ACK]，服务端同时置 SYN 和 ACK。ack=735774303 正好等于客户端 SYN 序号 +1，说明确认了客户端 SYN；服务端自己的初始序号是 seq=3501541715。

第 3 行：[ACK]，客户端确认服务端 SYN。ack=3501541716 正好等于服务端 SYN 序号 +1。

所以这三行合起来就是标准三次握手。不是看“发了三个包”就算，而是看 SYN → SYN/ACK → ACK 以及 ack 号是否等于对方 seq+1。

3. 怎么看出“数据传输”
数据传输主要看：

标志位有 PSH；

len > 0；

对端用 ACK 确认，ack 号随数据长度推进。

会话#1 中：

text
0.000s ← [PSH/ACK ] seq=735774303 ack=3501541716 len=78
0.001s → [ACK     ] seq=3501541716 ack=735774381 len=0
0.001s → [PSH/ACK ] seq=3501541716 ack=735774381 len=155
0.001s ← [ACK     ] seq=735774381 ack=3501541871 len=0
0.001s → [PSH/ACK ] seq=3501541871 ack=735774381 len=148
0.001s ← [ACK     ] seq=735774381 ack=3501542019 len=0
看第一组：

← [PSH/ACK] seq=735774303 len=78：客户端发来 78 字节应用数据，起始序号 735774303。

因为发了 78 字节，下一个序号应为 735774303 + 78 = 735774381。

下一行 → [ACK] ack=735774381：服务端确认收到这 78 字节，并期望下一个字节序号是 735774381。

第二组：

→ [PSH/ACK] seq=3501541716 len=155：服务端发 155 字节。

← [ACK] ack=3501541871：客户端确认。3501541716 + 155 = 3501541871。

第三组同理：len=148，3501541871 + 148 = 3501542019，所以客户端 ACK 是 ack=3501542019。

因此，看到 PSH/ACK 且 len>0，并且后续 ACK 号按长度增加，就是数据传输。 标题里的“数据段3”也对应这里有 3 个 PSH/ACK 数据段。

4. 怎么看出“FIN/ACK 礼貌关闭”
会话#1 结尾：

text
0.001s ← [FIN/ACK ] seq=735774381 ack=3501542019 len=0
0.001s → [FIN/ACK ] seq=3501542019 ack=735774382 len=0
0.002s ← [ACK     ] seq=735774382 ack=3501542020 len=0
看标志位：

[FIN/ACK] 表示这个包带 FIN，表示发送方没有更多数据要发了。

FIN 虽然 len=0，但会消耗 1 个序号。

第一行：客户端 FIN，seq=735774381。FIN 占 1 个序号，所以服务端应确认 735774382。

第二行：服务端也回 FIN/ACK，ack=735774382 正好确认客户端 FIN；服务端自己的 FIN 序号是 3501542019。

第三行：客户端最后 ACK，ack=3501542020，正好是服务端 FIN 序号 3501542019 + 1。

这就是“双方 FIN + 最后 ACK”的礼貌关闭。
如果看到 RST，那才是异常/强制重置；这里是 FIN/ACK，所以标题写“礼貌关闭”。
