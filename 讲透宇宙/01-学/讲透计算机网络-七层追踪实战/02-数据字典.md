## 2. sniffer JSONL 逐字段

一条 TCP 包的完整记录（r1 实例，行内换行便于阅读）：

```json
{"ts": 1793880223.553, "cap_len": 78,
 "eth": {"dst": "02:42:b3:d8:21:5c", "src": "02:42:ac:11:00:04",
          "ethertype": "0x0800(IPv4)", "vlan": null},
 "ip":  {"src": "172.17.0.1", "dst": "172.17.0.4", "ttl": 64, "proto": 6,
          "proto_name": "TCP", "id": 43830, "df": 1, "mf": 0,
          "frag_off": 0, "total_len": 78},
 "tcp": {"sport": 55720, "dport": 8080, "seq": 735774302, "ack": 3501541716,
          "flags": ["PSH","ACK"], "window": 502, "hlen": 20},
 "payload_len": 37,
 "payload": "GET /api/time HTTP/1.1..Host: 127.0.0.1:8188....."}
```

| 字段 | 层 | 含义与读法 |
|---|---|---|
| `ts` | — | 抓包时刻（Unix 浮点秒）。两条记录相减即包间隔/RTT 上界 |
| `cap_len` | L1 | 捕获字节数（含以太网头）。MTU 1500 附近的大包=接近线上限制 |
| `eth.dst/src` | L2 | 目的/源 MAC。`02:42:ac:11:00:04` = docker 按 IP 172.17.0.4 派生（ac11 0004 是 IP 的十六进制）；广播=ff:ff:ff:ff:ff:ff |
| `eth.ethertype` | L2 | 0x0800=IPv4、0x0806=ARP、0x86DD=IPv6；0x8100 会再剥 4 字节 VLAN tag |
| `arp.*` | L2.5 | `op`=request/reply；`sender`="IP is-at MAC"宣告；request 的 asking_about 是被问的 IP，target MAC 为全零（未知） |
| `ip.ttl` | L3 | 每过一台路由器减 1；抓包看到的 64 是发送方初值（Linux 默认）。traceroute 靠它制造 time-exceeded |
| `ip.id` | L3 | 同一 IP 包分片共用的标识（重组用）；不同包间近似递增可作"包序旁证" |
| `ip.df/mf/frag_off` | L3 | Don't Fragment / More Fragments / 片偏移——分片三件套。df=1 常见（现代路径 MTU 发现） |
| `ip.proto` | L3→4 | 1=ICMP、6=TCP、17=UDP（协议号即"层间的多路复用键"） |
| `icmp.type/code` | L3.5 | 8/0=echo请求/应答；11/0=TTL 归零（traceroute 的信号源）；3/3=端口不可达 |
| `tcp.seq/ack` | L4 | 字节流序号/确认号。`ack=对端seq+本次数据长度`=「下一个我期望的字节」。握手时各自随机 ISN |
| `tcp.flags` | L4 | SYN 开连接、ACK 确认、PSH 促交付、FIN 礼貌关、RST 立刻断。flags 组合是 TCP 状态机的语言 |
| `tcp.window` | L4 | 接收窗口（字节）——流控的实时值。观察它在会话中的涨落=观察应用消费速度 |
| `tcp.mss` | L4 | 仅 SYN 包有：最大段大小（1460=MTU1500−20−20），握手时协商一次定终身 |
| `payload_len` | L5+ | TCP/UDP 载荷字节数（0=纯控制段：握手/ACK/挥手） |
| `payload` | L6/L7 | 载荷 ASCII 可读化（不可打印字符→`.`，截断 200B）。**明文协议在此现形；TLS 轮只剩乱码+明文 SNI** |

## 3. pcap 文件格式（自产工业标准格式）

```
24B 全局头: magic a1b2c3d4 + 版本 2.4 + 时区/精度 + snaplen 65535 + linktype 1(Ethernet)
每包记录头: ts_sec + ts_usec + incl_len(实际存) + orig_len(线上原长)  ←两者不等=截断
```

价值：虽然本环境没有 Wireshark，但文件格式与业界完全互通——工具受限不等于数据孤岛。

## 4. 访问日志（access.log / access_tls.log）

r1 字段（tracehttp.py）：

| 字段 | 含义 |
|---|---|
| `ts / client / port_client` | 请求时刻 / 客户端 IP 与源端口（与抓包侧四元组可精确对上！） |
| `method / path / query` | HTTP 方法与 URL（L7 语义的核心） |
| `headers` | 全部请求头原样（User-Agent/Authorization 等取证素材） |
| `body` | 请求体前 500B（登录密码在 r1 里裸奔——A1 的另一份证据） |
| `resp_code / rt_ms` | 响应码与应用层处理耗时 |

r2 字段（tracehttp_tls.py）：`ts / client / line`（标准 combined 风格行），凭据类字段经 `mask()` 脱敏后才会入日志（A7 补救）。

**对照玩法**：在 access.log 找一条 POST /api/login（记下 client+ts），到 r1_eth0.jsonl 用时间窗+四元组定位同一请求的包序列——应用视角与网络视角对同一事件的两种陈述。

## 5. 七层快照文件（r*_L1..L7.txt）内容索引

| 文件 | 内嵌命令/工具 | 关键看点 |
|---|---|---|
| L1 | l1probe.py（/sys + ioctl） | veth 虚拟接口特征：无 PCI 设备、tx_queue_len=0、lo 收发恒等 |
| L2 | ip link / ip neigh / /proc/net/arp + 抓包 ARP | ARP 双向对话四帧；REACHABLE 状态 |
| L3 | ip addr/route、/proc/net/route、/proc/net/snmp(Ip/Icmp 计数器)、myping、mytraceroute、DNS 解析 | 默认路由+直连段；ICMP 计数器与抓包互证 |
| L4 | ss -ltnp / ss -s / /proc/net/tcp + 抓包 TCP 段 | LISTEN 状态 0A；TIME-WAIT 堆积（closed 53 条=keep-alive 对比实验的残留）；段头逐字段 |
| L5 | flows.py 会话时间线 | 每会话：握手 SYN×1 → 数据段 N → FIN×2/RST；keep-alive 与 close 的包数差异 |
| L6 | gzip 对比实验 / 字节序说明 / (r2) python ssl 协商观察 | identity vs gzip 字节数；(r2) TLSv1.3 + TLS_AES_256_GCM_SHA384 |
| L7 | curl -v 全程 + 访问日志 + 抓包 payload | 请求/响应全文字节级对照 |

注：快照执行于**栈停止后**，故 L4 的 `ss -ltnp` 监听行为空——服务在线证据见 01§部署节的实时输出（`LISTEN 0.0.0.0:8080 users:python3,pid=102`）。读数据先看时间戳与采集时机，是避坑基本功。

## 6. 数据可信度声明

- 全部数据为一手实测，未做任何"修饰"；失败与坑（myping 初版超时、遍历数错层、缓冲不落盘）均如实保留在 01§4 工程坑实录。
- r1/r2 两轮环境相同（同容器、同网段、同剧本），唯一变量=服务版本（v1 明文 vs v2 TLS+认证+限额），因此两轮数据可直接对比归因。
- pcap/JSONL 里的 IP/MAC 均为实验容器真实值（172.17.0.x 内网段，无脱敏必要）；token 为演示专用固定值，已随实验结束失效。
