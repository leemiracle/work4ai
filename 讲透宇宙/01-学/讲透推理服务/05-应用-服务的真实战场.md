# 五 · 应用：服务的真实战场

## 5.1 P/D 分离：一台服务器拆成两种生意

02.3 节的物理断层（prefill=compute-bound，decode=memory-bound）在产业层的兑现：

- **分离部署**：prefill 池用高算力卡、decode 池用高带宽卡（或干脆 decode 用廉价卡），中间靠**KV 传输**缝合——Mooncake（[蒸馏卡](../../03-查/讲透Mooncake/DISTILLED.md)：Kimi 生产动力，三层解耦+Segment 池化+TransferEngine 零拷贝）是这条路线的标杆；
- **收益边界**：分离不是免费——KV 跨池搬运有成本，负载低时分离反而亏；且对某些新架构（如 DeepSeek-V4 的先压缩再稀疏，[讲透DeepSeek-V4](../../04-研/讲透DeepSeek-V4/paper/PAPER-DEEPREAD.md) 精读：host offloading 对 V4 无收益——模型创新使系统优化失效的罕见反例）分离的前提条件本身被动摇。

## 5.2 KV 池化：从缓存到基础设施

- **单引擎内**：PagedAttention 块管理（04.3 的碎片权衡）；
- **跨引擎**：LMCache（[讲透LMCache](../../03-查/讲透LMCache/deepwiki/INDEX.md)，vLLM 生态 KV 复用）；
- **集群级**：Mooncake 把 DRAM/VRAM/CXL/SSD 池化成全局 KV 池——**KV cache 从"引擎内部状态"升格为"可独立调度的资源"**，这与操作系统把内存从进程私有变分页共享的历史同构。

## 5.3 投机解码：用算力换带宽

decode 是 memory-bound（02.3），于是反向操作：让小模型草拟 k 个 token，大模型一次并行验证——**权重读一遍验证 k 个 token**，等价带宽放大 k 倍（接受率打折后仍显著）。

- 产业实例：DSpark（[论文精读](../../04-研/讲透DSpark/paper/PAPER-DEEPREAD.md)：r=256 Markov 串行头治 suffix decay+置信度调度，V4 生产同吞吐每用户 +60-85%——**引用必须带 at matched throughput 口径**）；
- tokenspeed 类推理加速仓（[讲透tokenspeed](../../03-查/讲透tokenspeed/deepwiki/INDEX.md)）与 MTP（multi-token prediction，训练侧为投机解码铺路）是同一枚硬币的两面。

## 5.4 注意力自身的降本：DSA 线

服务层优化的尽头是模型层接管：DeepSeek V3.2 的 DSA（indexer+top-k 稀疏注意力，[讲透DeepSeek-V3.2-Exp](../../02-透/讲透DeepSeek-V3.2-Exp/README.md)）把长上下文的 KV 需求压掉一个数量级——02.2 公式的 $V_{kv}(s)$ 直接变小，批容量天花板抬升。**当系统工程师在堆 KV 池时，模型工程师在让 KV 不存在**——两条路线的赛跑定义了 2025-2026 的推理故事（V4"先压缩再稀疏"是集大成，见 04.4 引用的精读勘误：真稀疏实现仍在 FlashMLA PR 演进中）。

## 5.5 端侧与长尾：推理的民主化

- 浏览器端（[讲透WebLLM](../../02-透/讲透WebLLM/README.md)：WebGPU）、单文件分发（[讲透Llamafile](../../02-透/讲透Llamafile/README.md)）、单卡 671B（[讲透KTransformers](../../02-透/讲透KTransformers/README.md)）——批处理退场，延迟与内存成为唯一战场；
- 结构化输出（[讲透XGrammar](../../02-透/讲透XGrammar/README.md)）是 agent 时代的隐形刚需：每个工具调用都要合法 JSON，约束解码的效率直接决定 agent 的循环速度。

## 5.6 单元闭环：一条物理定律的产业史

回看五幕：异构请求注定 static 死刑（01）→ KV 显存是批容量真天花板、decode 免费午餐有公式（02）→ 调度粒度本身值 1.93x（03）→ 但每个收益都有暗面：TTFT 跷跷板、饥饿、碎片、引擎复杂度税（04）→ 产业用 P/D 分离、KV 池化、投机解码、稀疏注意力层层兑现与对冲（05）。**所有这些都建立在一条物理定律上：decode 读权重的成本与批大小无关**——理解这条定律，五个时代的引擎演进就都成了它的推论。

✍️ 结业练习：用 02.2 公式核算你最常用的模型+上下文长度的每请求 KV；再按 03 幕模拟器估算你的负载形态（长短比）下 continuous batching 的理论收益；最后挑一个 05 幕路线（池化/分离/投机/稀疏）写一页决策备忘录：什么条件下它对你的场景是负收益。
