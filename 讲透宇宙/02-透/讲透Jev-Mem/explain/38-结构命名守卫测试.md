## 角色定位

这四个文件测的不是运行时行为，而是**项目自身的不变量**——把"仓库永远可发布、可迁移、不骗老用户"写成可回归断言：test_project_layout.py 守包结构（旧名可用、import 零副作用、CLI 分发、gitignore 卫生）；test_backend_cache.py 守缓存铁律，docstring 立宪 "Backend switches must never silently relabel an existing graph"（tests/test_backend_cache.py:1）；test_naming.py 守 sys1mem→jev-mem 改名彻底性与元数据无损迁移；test_metric_resources.py 守资源卫生——import 项目模块零下载零模型加载。

为什么这样组织在一起：四者守护同一场迁移的正交切面——仓库更名、决策后端从单一 Jev 扩展为 jev/laya/laya-mlx、并公开发布。前向兼容（旧 import 名仍解析到同一对象）、后向兼容（旧缓存可读但不可跨后端混用）、改名完成度、资源卫生，缺一面都会在某条用户路径爆雷。CI 上四件随双矩阵 pytest 全量执行（.github/workflows/ci.yml:29），与 `--tracked` 扫描、build 接棒构成"可发布性"三段守卫。

## 内部结构

**test_project_layout.py——包结构与分发**。别名参数化钉死六对旧名→正名映射（tests/test_project_layout.py:11-18），断言用 `is` 同一性（tests/test_project_layout.py:20）——必须是同一模块对象而非符号复制；pickle 兼容测手工构造 GLOBAL 字节串反序列化出 QA 类（tests/test_project_layout.py:28-29），守护旧 pickle 写死旧模块名的路径。import 卫生测起子进程干净 import jev_mem，断言重量件与 provider 不入 sys.modules（tests/test_project_layout.py:32-40）；分发测断言 `--mode test` 退化为子进程 `python -m jev_mem.benchmarks.locomo` 且退出码透传（tests/test_project_layout.py:55-68）；gitignore 守卫证明五类敏感路径被忽略、sdist 无 .git 时跳过（tests/test_project_layout.py:71-77）。

**test_backend_cache.py——后端身份**。两组参数化让**两个独立校验器**（基准侧 validate_reuse_memory、库侧 validate_cached_backend）各跑一遍：换后端四向组合（tests/test_backend_cache.py:19-26）与 laya 构造扰动三件含 jev_mock（tests/test_backend_cache.py:29-37）都必须抛 ValueError，匹配后端则放行检索调参；历史缓存测（缺五个 laya 键、旧名 sys1mem_config.json）证明默认回填免重建、换后端仍拒（tests/test_backend_cache.py:48-59）。库级测用 `MemoryBuilder.__new__` 绕过构造器、graph_db.load 换 pytest.fail 哨兵，证明 ValueError 在图加载**之前**抛出（tests/test_backend_cache.py:62-72）。

**test_naming.py——改名彻底性**。canonical 名测横扫公开面（tests/test_naming.py:13-29）：pyproject 的 name/description、README 标题（先把 "System-One-Controlled" 归一为带空格版）、CITATION.bib 题名、公开类签名只认 jev_config 不认 sys1_config（tests/test_naming.py:24-26）、四个 sys1 旧模块名 find_spec 为 None——旧根名可用而旧包内名已死。迁移测验证 normalize_metadata 合并语义：证据原文保留、source 改写、sys1mem 字典并入 jev_mem 且现格式优先、加载不突变源字典（tests/test_naming.py:42-49）。Link 控制器名归一与新旧配置并存时新名优先收尾（tests/test_naming.py:52-67）。

**test_metric_resources.py——资源懒加载**。夹具手搓六个假模块注入 sys.modules，再 spec_from_file_location **重新执行** utils/utils.py（tests/test_metric_resources.py:29-34）——可选依赖在模块顶层 try/except 绑名，不重执行测不到"import 时刻零下载"。三个断言：重执行后可用标志真而调用记录空（tests/test_metric_resources.py:38-41）；显式调指标两轮，下载与建模只发生一次且调用序列精确相等（tests/test_metric_resources.py:44-51）；模型加载失败后不重试（tests/test_metric_resources.py:54-62）。

## 外部连接

四文件互不 import（仅共享 pytest），被测面织网：布局测压在根目录六个 shim 的 sys.modules 替换上（main.py:8、jev_mem_demo.py:9），shim 由 pyproject.toml:34 的 py-modules 打包，分发落点 jev_mem/cli.py:39-48，gitignore 断言对准 .gitignore:26；缓存测落点 memory/cache_compat.py:15-30（库校验器）与 jev_mem/benchmarks/locomo.py:38-58（基准校验器），库级顺序压在 memory/memory_builder.py:1328-1335；命名测落点 memory/cache_compat.py:33-44（normalize_metadata）在 memory/graph_db.py:92 与 memory/graph_db.py:248 两个 from_dict 里被调；资源测零仓内 import，按路径加载 utils/utils.py（懒加载器 utils/utils.py:64-91）。图谱记四文件为 tests/ 叶子（无 fanIn）实测一致；fanOut 远宽于静态 import 边——元测试测的是"仓库+发行物+环境"而非某模块。

## 数据流

布局测大量起子进程（tests/test_project_layout.py:33-40）——宿主 pytest 早已 import 重量件，"零副作用"只能隔离进程才测得了，CI 的 HF_HUB_OFFLINE=1 再防子进程偷跑下载。缓存测是**写盘→换配置→读回**：replace 只改一个字段（tests/test_backend_cache.py:26），库侧把缺失的 decision_backend 缺省视为 jev（memory/cache_compat.py:22），基准侧多校验十个字段。命名迁移只在 from_dict 反序列化边界发生，旧缓存文件永不重写。资源测断言模块级闩锁行为：两个全局布尔保证"每进程一次"、失败也置位（utils/utils.py:90），坏模型不反复重试。

## 设计决策

**`is` 同一性断言**排除"复制符号再转发"的整个错误家族——shim 的价值在 pickle GLOBAL、isinstance、monkeypatch 目标全部继续工作。**pytest.fail 哨兵**（tests/test_backend_cache.py:70）不是测"抛了 ValueError"而是测"抛错时图尚未加载"，把 load 的验证-加载顺序（memory/memory_builder.py:1333-1335）变成可执行契约；`__new__` 绕构造器免起真 TRG。**spec_from_file_location 重执行**解决"顶层 import 副作用不可回放"的难题。

批判三处：其一，**两校验器严格度不对称**——基准侧字段表含 jev_mock（jev_mem/benchmarks/locomo.py:54），库侧只在 laya 后端下核对 jev_mock 与 laya 三键（memory/cache_compat.py:25-30），jev 后端下翻转 jev_mock 的库侧加载不被拦截，而图元数据 controller 标签确实区分 mock 与真实后端（memory/memory_builder.py:166），"mock 决策建的缓存被真实配置复用"在库路径理论可行，且扰动参数化只覆盖 laya 系；其二，gitignore 守卫在 sdist 静默跳过（tests/test_project_layout.py:75-76）；其三，精确调用序列断言把资源清单顺序钉进测试，加资源或调序即误伤。
