# 10.3 · 服务化版图：Chromium 把什么拆进了服务，为什么，以及你的代码放哪

> `services/` 目录 30 个服务不是架构洁癖——每个都是一次"进程边界决策"的存档。读懂版图=理解 Chromium 的演进方向=知道自家代码该放哪个进程。10.1（mojo）/10.2（加服务）之后的收官篇。

## ① 角色定位

服务化的本质：**把"不需要 browser 进程特权的功能"搬出 browser 进程**——降崩溃爆炸半径（browser 挂=全挂）、隔离沙箱面（服务各有 sandbox type）、并行演进（接口稳定后实现随便换进程形态）。版图（`services/` 目录盘点，30 项）按动机分四类：

| 动机 | 代表服务 | 进程形态 |
|---|---|---|
| 解析不可信数据 | `data_decoder`（JSON/BSON/图像解码）、`image_annotation`、`shape_detection`、`screen_ai` | utility 独立、用完即走 |
| 网络/隐私边界 | `network`（6.1）、`proxy_resolver*`（6.3）、`cert_verifier`（6.4） | 独立服务进程（可回 in-process） |
| 硬件/系统中介 | `device`（传感器/蓝牙）、`audio`、`media_session`、`accessibility` | 常驻/按需 |
| 模型/智能 | `on_device_model`（端侧模型宿主！）、`passage_embeddings`（12.2 检索的嵌入服务）、`metrics`、`tracing`、`preferences`（残部，11.2 勘误）、`resource_coordinator` | 各按负载 |

## ③ 关键源码走读：一次服务化的解剖（以 passage_embeddings 为例）

它是 12.2 检索管线的执行件，也是"标准 utility 服务"的活样本：.mojom 接口（public/mojom）+ 服务实现（ServiceProcessHost::Launch 挂载，10.2 六跳链）+ 惰性生命周期（请求到才起进程，10.2 坑①）。**把它当模板看：一个"计算型无状态服务"的全部工程件就这么多**。

**版图的第二层读法**——`content/utility/services.cc` 的注册表（:406 起的 RegisterMainThreadServices 链→chrome/utility/services.cc:499 的 services.Add 群）：**这是服务版图的"户口本"**，新服务必须在这里报到（10.2 实操步骤③的落点）。

## ④ 实操：给自家功能做进程决策（决策树实操化）

以 12.x 的 LlmGateway 为例走一遍：
1. 有特权吗？（要读 profile/连内网）——要 → browser 侧 KeyedService（11.1 范式）；
2. 要给 renderer/WebUI 调吗？——要 → 接口走 mojo（10.1）+三入口暴露（10.2）；
3. 计算重/想隔离？——LLM 推理若端侧 → 学 `on_device_model` 独立服务+专属沙箱；
4. 不可信输入多吗？（用户任意文本）——解析/分块挪 utility 范式（data_decoder 精神）。
结论示例：网关 browser+Keyed（调度）+ 重负载下沉独立服务（执行）——**两层形态正是 network 服务自己的形态**（6.1 的 browser 调度+service 执行）。

## ⑥ 坑与勘误

- **services/ 目录 ≠ 在用清单**：`preferences`（README 自证已删）、`service_manager`（旧框架残部）——**以注册表（§3 户口本）为准**，目录里的历史项别当现行架构学。
- "全拆出去"的诱惑：browser 进程内 KeyedService 的启动成本远低于跨进程服务——**低频小功能服务化=纯亏**（IPC/进程/崩溃恢复三重税）。
- on_device_model 与 optimization_guide 的分工易混（前者宿主后者调度）——12.4 换芯时选错层会白做。
- 服务进程的启动时延（首请求多 ~100ms 级）：UX 敏感功能要预热（10.2 idle handler 的 Poke 语义）。
- Android 上部分服务并回宿主（webview 形态进程预算不同，2.2）——服务的"独立进程"承诺是平台相关的。
- 老资料里的 ServiceManager（服务注册中心）时代 API 已删（10.2 勘误①）——现行是 Launch+Factory 直连。

## ⑦ 验证方法

- chrome://process-internals / 任务管理器：服务进程群清单（对照 §1 版图）
- 服务化健康度：杀单一服务进程→浏览器功能降级不崩（爆炸半径验证）
- 新服务冒烟：10.2 §7 的 "Cannot run unknown service" 排错法+echo 服务样板
- 注册表一致性：户口本（§3）与实际进程对照，无幽灵项
