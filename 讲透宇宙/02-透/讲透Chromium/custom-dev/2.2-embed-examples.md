# 2.2 · 嵌入范例对比：content_shell / headless / android_webview / clank——四种"自制浏览器"活教材

> 嵌入一个浏览器最少做多少？四个官方 embedder 给出答案：最简 shell、去 UI 的 headless、并进宿主 app 的 WebView、完整产品的 clank。以 shell 为主线，其余只答"比 shell 多做什么"。

## ① 角色定位

Chromium 是"content 内核 + 嵌入者"结构（契约见姊妹篇 2.1）：内核不会自己变成进程，必须有人提供 `ContentMainDelegate` 调 `ContentMain()`、交出 ContentClient 四分身。四者分别证明：最少要做多少（shell）、UI 可整层拿掉（headless）、浏览器进程可塞进别人进程（WebView）、上限（clank）——体量见③对比表。

## ③ 关键源码走读

### 3.1 主线：content_shell 最简全链

**main 与 delegate**：`shell_main.cc:99-105` 建 `ShellMainDelegate` 调 `ContentMain()`；`shell_main_delegate.cc:473-510` 六个 Create* 工厂各两行。`RunProcess`（:321）桌面返回 params 交 content 跑 BrowserMain（:364）；Android/iOS（:343-360）只 `Initialize` 后**泄漏** `BrowserMainRunner`——控制权交还系统消息循环。

**组装与启动序**：`shell_content_browser_client.cc:380-387` `CreateBrowserMainParts()` 是 browser 侧组装点；其余覆写"够用即可"——`IsHandledURL`（:421-440）11 项 scheme 集合。`shell_browser_main_parts.cc:184-195` `PreMainMessageLoopRun()`：建正常+无痕两个 `ShellBrowserContext`（:140-148）→`Shell::Initialize`→开 DevTools（:192）→`CreateNewWindow`（:150-153）；无参启动默认 google.com（:88）。context 层 `shell_browser_context.cc` 仅 193 行：路径 CHECK（:76）、下载/权限 delegate 惰性 new（:99/:135）、push/SSL 返回 nullptr（:109-162）——**nullptr 是合法答案**，即嵌入面弹性。

**窗口**：`shell.cc:224-242` `CreateNewWindow()`=`WebContents::Create`→`CreateShell()`（:112-145）→`LoadURL`；平台差异隔离在 `ShellPlatformDelegate`（no-op 基类:51-56），Linux 走 views（`shell_platform_delegate_views.cc:366`）。

**最小嵌入清单（11 件套，全在 content/shell/ 下）**：①app/shell_main.cc ②app/shell_main_delegate.cc ③common/shell_content_client.cc ④browser/shell_content_browser_client.cc ⑤browser/shell_browser_main_parts.cc ⑥browser/shell_browser_context.cc ⑦browser/shell.cc ⑧browser/shell_platform_delegate*.cc ⑨renderer/shell_content_renderer_client.cc ⑩common/shell_switches.cc+shell_paths.cc ⑪pak+BUILD.gn（content_shell_lib:177）。共约 4600 行——"最少要做多少"的官方报价。

### 3.2 headless：把"窗口"换成一个回调

`headless_shell_main.cc:19-45` 传 **nullptr delegate**——真 delegate 由 `HeadlessShellMain()`（`headless_shell.cc:222`）补挂（:212-217）。三处分叉：①`RunProcess`（`headless_content_main_delegate.cc:449-470`）同步 `Initialize→Run→Shutdown`，退出码即浏览器退出码；②"窗口"=`HeadlessWebContentsImpl::Create`（`headless_web_contents_impl.cc:405-424`）：只建 WebContents+逻辑窗口，无 Widget；③embedder API 提炼成 `headless/public/` 六个头（`headless_browser.h:40-63`）。产物 chrome-headless-shell（`headless/BUILD.gn:884`）。

### 3.3 android_webview：交出进程与生命周期

WebView 没有 main()——framework WebView 经 glue（`WebViewChromiumFactoryProvider.java:640`）→`StartupTasks.java:229`→`startBrowserProcessesSync` 在**宿主 app 进程内**拉起 content；delegate 由 `webview_jni_onload.cc:13-19` 注册。`aw_main_delegate.cc` 三处反转：①`BasicStartupComplete`（:114-259）是二十多个 `kDisable*` **减法清单**（FileSystem/Notification/Push…）；②`:253` `ForceInProcessNetworkService()`；③`RunProcess`（:298-311）只 Initialize。窗口变 View：`AwContents.java:958-973` 收 `ViewGroup containerView`，宿主经 `ShouldOverrideUrlLoading`（`aw_content_browser_client.cc:879`）接管 URL；`AwBrowserContext`（:144-214）自建存储——数据在**宿主私有目录**（:417）。

### 3.4 clank：一切，加一个空目录

`chrome/android/BUILD.gn:72` 定义 `chrome_public_bundle`、:64-68 挂 Trichrome；:259-263/:962/:966 的 `//clank/...` 依赖由 `enable_chrome_android_internal` 等 flag 守护——`src/clank/` 公开仓**存在但为空**（实测），关 flag 回退 unbranded 资源。Java 壳 `ChromeTabbedActivity.java`；native 壳 `chrome_main_delegate_android.cc:87-120`（只 Initialize）。

**四形态对比表（核心交付）**

| 维度 | content_shell | headless | android_webview | clank |
|---|---|---|---|---|
| 进程模型 | browser+子进程 | 同左，无 UI 负担 | **browser 在宿主进程**；GPU/Network in-process | 全家桶多进程 |
| UI 栈 | ui/views 原生窗 | 无窗口，逻辑窗+CDP | 宿主 View 树 | Java/Views+内部 clank UI |
| 嵌入面 | 69 文件（四件套 513/925/237/193 行） | 62 文件 | 989 文件 | chrome/browser 23560 文件+空 //clank |
| 产物 | content_shell（**testonly**:757-759） | chrome-headless-shell | system_webview APK（:84） | chrome_public/Trichrome |
| 场景 | 学 content/回归/抄骨架 | 自动化/截图/Puppeteer | Web 嵌进 Android app | 完整浏览器产品 |

## ④ 实操：最小 patch 示例

**示例 1：换默认主页**（`shell_browser_main_parts.cc:88`）：把 `GURL("https://www.google.com/")` 一行改为自家 URL；只被 `:150-153` 消费，零扩散。

**示例 2：品牌化 UA**（`shell_content_browser_client.cc:744-745`）：

```cpp
// 改前
  base::StringPrintf("Chrome/%s.0.0.0", CONTENT_SHELL_MAJOR_VERSION);
// 改后
  base::StringPrintf("MyBrowser/%s", CONTENT_SHELL_MAJOR_VERSION);
```

`GetUserAgentMetadata()`（:756-758，独立实现 :348）须一起改，否则与 client hints 矛盾。

## ⑤ 依赖与数据流

主线：main→MainDelegate→ContentBrowserClient→BrowserMainParts→{双 BrowserContext，DevTools，CreateNewWindow}；headless/webview/clank 在 delegate/client 层换实现。输入：开关（`user-data-dir` 等）与启动 URL；输出：窗口/截图/View；契约：经 `content/public` 单向调用（2.1）。

## ⑥ 坑与勘误

1. **"shell_browser_main.cc" 不存在**（实际 `shell_browser_main_parts.cc`）；三种 RunProcess 别混：shell 桌面返回 params（:364）、headless 同步三段（:458-467）、aw 只 Initialize（:305-310）。（源码实证）
2. **headless 世代**：M132 后 Chrome 二进制不含 old headless，独立产物 chrome-headless-shell（README.md:11-16）。（文档对比）
3. **WebView"多进程"名不副实**：仅 renderer 可分离，Network 钉死 in-process（aw_main_delegate.cc:253+architecture.md）；且无 OTR/Push（aw_browser_context.cc:421-424）。（源码实证）
4. **clank 空目录≠checkout 缺损**：internal flag 守护+unbranded 回退（chrome/android/BUILD.gn:259-263）；WebView Shell 官方自认非产品级、不得作为浏览器基础（docs/webview-shell.md）。（源码实证+文档对比）

## ⑦ 验证方法

`autoninja -C out/Release content_shell`；`headless_shell --remote-debugging-port=9222`；`system_webview_apk`（android_webview/BUILD.gn:84）按 docs/build-instructions.md 装机。patch 生效：示例 1 无参启动看首导航；示例 2 经 chrome://inspect+CDP 对账 `navigator.userAgent`；开关窗确认 `Shell::Shutdown`（shell.cc:190-215）未破。
