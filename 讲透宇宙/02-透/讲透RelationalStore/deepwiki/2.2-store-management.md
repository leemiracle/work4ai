  This page documents the store management subsystem within the OpenHarmony Distributed Relational Database Management System. The store management components provide central mechanisms for creating, retrieving, caching, and deleting database store instances. These components ensure efficient reuse of database connections, proper configuration validation, and lifecycle management of database stores.

 For transaction management within stores, see [Transaction Management](https://deepwiki.com/openharmony/distributeddatamgr_relational_store/2.3-transaction-management). For details on the core RdbStore implementation, see [RdbStoreImpl](https://deepwiki.com/openharmony/distributeddatamgr_relational_store/2.1-rdbstoreimpl).

 
## Architecture Overview

 Store management is handled by two key components:

 
 - **RdbStoreManager**: A singleton that manages the lifecycle of database stores and maintains a cache of open store instances
 - **RdbHelper**: A utility class with static methods that provides a simplified API for applications to interact with stores

## RdbHelper

 RdbHelper serves as a facade for the more complex RdbStoreManager, providing a simple, static API for applications to work with database stores.

 
### Key Responsibilities

 
 - Initializing global SQLite configuration
 - Creating or retrieving database store instances
 - Deleting database stores
 - Clearing the store cache
 - Checking platform support for features like vector databases and tokenizers

## RdbStoreManager

 RdbStoreManager is a singleton class responsible for managing the lifecycle of database stores. It implements the following key functionalities:

 
### Store Caching Mechanism

 The manager maintains a cache (`storeCache_`) of weak references to RdbStoreImpl instances, indexed by their database paths. This mechanism:

 
 - Prevents multiple instances of the same database from being opened
 - Allows reuse of database connections
 - Automatically cleans up references when stores are no longer in use
 
 The manager also maintains a configuration cache (`configCache_`) using an LRU (Least Recently Used) bucket to track database configurations.

### Database Version Management

 When opening a database, RdbStoreManager handles database versioning through `ProcessOpenCallback()`:

 
 - Retrieves the current database version
 - Compares it with the requested version
 - Calls appropriate callbacks: 
 - `OnCreate()` if the database is new
 - `OnUpgrade()` if version is higher than current
 - `OnDowngrade()` if version is lower than current
 - Updates the database version if changes were successful
 - Calls `OnOpen()` to complete initialization
 
 This mechanism enables structured database schema evolution over time.

## Store Deletion and Cache Management

 
### Store Deletion

 The system provides two mechanisms for removing database stores:

 
 - **Remove**: Removes a store from the cache but doesn't delete the database file
 - **Delete**: Removes a store from cache and also deletes the database file
 
 
```

```

 For memory databases, only cache removal is performed. For disk databases, the system:

 
 - Removes the store from the cache
 - Deletes the database file
 - Removes encryption key files

### Cache Management

 The `Clear()` method removes all cached database stores, forcing new instances to be created on the next request. This is useful for releasing resources or when configuration changes require fresh connections.

 The store cache uses weak pointers (`std::weak_ptr<RdbStoreImpl>`) to automatically clean up references when no application code holds a reference to a store.

## Security Management

 RdbStoreManager applies security settings to database stores:

 
 - **Security Labels**: For stores with owner role, the manager sets security labels to control access
 - **Configuration Validation**: Prevents security downgrades by checking if security levels are being reduced
 - **Encryption Status**: Preserves encryption status between opens of the same database
 
 For distributed databases, the manager also verifies permissions through the RDB service.

## Summary

 The Store Management subsystem provides:

 
 - Centralized management of database store instances
 - Efficient caching to prevent duplicate connections
 - Configuration validation to ensure security and compatibility
 - Version management for database schema evolution
 - Clean lifecycle management for store creation and deletion
 
 Applications typically interact with this subsystem through the RdbHelper class, which provides a simplified API for common database operations.
