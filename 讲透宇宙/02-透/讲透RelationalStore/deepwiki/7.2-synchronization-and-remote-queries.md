## Purpose and Scope

 This document describes the synchronization and remote query capabilities of the OpenHarmony Distributed Relational Database Management System. These features enable data sharing and consistency across multiple devices in a distributed environment. Synchronization allows data to be kept consistent across devices, while remote queries enable reading data from remote devices without explicit synchronization.

 For information about general database operations, see [RDB Store Core](https://deepwiki.com/openharmony/distributeddatamgr_relational_store/2-rdb-store-core).

### Sync Modes and Options

 The system supports various synchronization modes through the `SyncOption` structure:

 
| Sync Mode | Description |
|---|---|
| PUSH | Send local changes to remote device |
| PULL | Retrieve remote changes to local device |
| PULL_PUSH | Bidirectional synchronization |
| TIME_FIRST | Prioritize by timestamp when resolving conflicts with cloud |
| NATIVE_FIRST | Prioritize local changes when resolving conflicts with cloud |
| CLOUD_FIRST | Prioritize cloud changes when resolving conflicts |

## Best Practices

 
 - **Choose the appropriate sync mode:**

 
 - Use PUSH when you want to send local changes to a remote device
 - Use PULL when you want to retrieve remote changes
 - Use PULL_PUSH for bidirectional synchronization
 - **Use asynchronous API for better performance:**

 
 - Asynchronous operations don't block the UI thread
 - Use callbacks to handle completion
 - **Configure distributed tables appropriately:**

 
 - Only distribute tables that need synchronization
 - Use references to maintain referential integrity
 - **Handle conflicts:**

 
 - Design your data model to minimize conflicts
 - Use appropriate conflict resolution modes
 - **Observe data changes:**

 
 - Subscribe to changes to keep your UI updated
 - Choose the appropriate observer mode
 - **Remote Queries vs. Synchronization:**

 
 - Use remote queries for read-only operations
 - Use synchronization when you need to modify data
 - **Security considerations:**

 
 - Be aware that distributed operations require appropriate permissions
 - Handle sensitive data appropriately
 
 
## Limitations and Constraints

 
 - The database must not be in memory-only mode for distributed features to work
 - The database must not be opened in read-only mode for synchronization features to work
 - Vector databases do not support distributed operations
 - Appropriate permissions must be granted for cross-device operations
 - Network connectivity is required for distributed operations
