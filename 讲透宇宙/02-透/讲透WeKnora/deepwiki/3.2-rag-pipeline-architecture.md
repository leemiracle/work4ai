## Purpose and Scope

 This document details the Retrieval-Augmented Generation (RAG) pipeline architecture in WeKnora, focusing on the end-to-end flow from document ingestion through chunking, embedding, indexing, retrieval, fusion, and grounded generation. The system employs an adaptive chunking strategy, asynchronous task processing via `Asynq` worker pools [internal/router/task.go24-51](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/task.go#L24-L51) hybrid retrieval (vector + keyword), parent-child chunk resolution, and resource-tracked lifecycle management.

 
---

 
## Document Ingestion and Processing

 The ingestion pipeline transforms raw files, URLs, or manual text into searchable knowledge units. WeKnora uses a multi-stage asynchronous pipeline orchestrated by `knowledgeService` [internal/application/service/knowledge_process.go116-152](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge_process.go#L116-L152)

 
### Ingestion Entry Points

 The system supports multiple input channels, each initializing a specific processing flow:

 
 - **File Upload**: Handled via `CreateKnowledgeFromFile` [internal/application/service/knowledge_create.go25-28](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge_create.go#L25-L28) which validates input safety, calculates file hashes for deduplication [internal/application/service/knowledge_create.go80-85](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge_create.go#L80-L85) stores the file using the KB-level file service [internal/application/service/knowledge_create.go183-188](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge_create.go#L183-L188) and triggers asynchronous parsing.
 - **URL Ingestion**: `CreateKnowledgeFromURL` downloads remote content before processing.
 - **Manual Entry**: `CreateKnowledgeFromManual` processes raw text or Markdown entries directly.
 - **Passage Processing**: `processDocumentFromPassage` [internal/application/service/knowledge_process.go154-191](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge_process.go#L154-L191) converts direct text strings into chunks.
 - **FAQ Batch Upsert**: `UpsertFAQEntries` handles asynchronous batch import of FAQ entries [internal/application/service/knowledge_faq.go121-124](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge_faq.go#L121-L124)

### Adaptive Chunking Strategy

 WeKnora uses an adaptive multi-tier chunking strategy to preserve document structure. The strategy is selected based on document profiling. The `SplitterConfig` defines parameters such as `ChunkSize`, `ChunkOverlap`, and `Separators`.

 
 - **Tier 1 (Heading)**: Splits Markdown documents with clear `#` hierarchies.
 - **Tier 2 (Heuristic)**: Processes unstructured docs with numbered sections or page breaks.
 - **Tier 3 (Legacy)**: Uses recursive character-based splitting as a fallback.
 
 A critical invariant in the `ParsedChunk` struct is that `End - Start == utf8.RuneCountInString(Content)`. The system also supports **Parent-Child Chunking** via `SplitParentChild`, which runs the tier selector for parent splitting, then re-splits each parent into children with smaller chunk configurations.

## Indexing, Embedding, and Enrichment

 Once text is split into chunks, the asynchronous worker pools process embeddings and enrichment tasks [internal/router/task.go24-51](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/task.go#L24-L51) across dedicated queues (`core`, `enrichment`, `summary`, `graph`, `multimodal`) [internal/types/task.go31-49](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/task.go#L31-L49)

 
 - **Vector Embedding & Indexing**: Chunks are passed to the embedding model specified by `EmbeddingModelID`, generating high-dimensional vectors stored in vector databases via `knowledgeBaseService.GetQueryEmbedding` [internal/application/service/knowledgebase_search.go26-54](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledgebase_search.go#L26-L54)
 - **Graph Entity Extraction**: If Neo4j is enabled (`NEO4J_ENABLE=true`), `NewChunkExtractTask` enqueues `TypeChunkExtract` tasks into `QueueGraph` to extract entities and relations from chunks [internal/application/service/extract.go90-126](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/extract.go#L90-L126)
 - **Table Summarization**: For tabular formats (`xlsx`, `csv`), `NewDataTableSummaryTask` enqueues `TypeDataTableSummary` into `QueueSummary` to generate structured metadata and descriptions [internal/application/service/extract.go128-158](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/extract.go#L128-L158)

### Deduplication, Parent-Child Resolution, and Fusion

 The `PluginMerge` component executes an eight-step merging pipeline [internal/application/service/chat_pipeline/merge.go33-46](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L33-L46):

 
 - **Input Selection**: Selects rerank results or falls back to vector/keyword search results sorted by score descending [internal/application/service/chat_pipeline/merge.go99-113](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L99-L113)
 - **Initial Deduplication**: Deduplicates chunks by ID and content signature [internal/application/service/chat_pipeline/merge.go58-60](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L58-L60)
 - **History Injection**: Appends relevant history references from session context [internal/application/service/chat_pipeline/merge.go130-145](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L130-L145)
 - **Parent Chunk Resolution**: Resolves child chunks back to their parent content [internal/application/service/chat_pipeline/merge.go76-78](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L76-L78)
 - **Grouping & Sequential Merge**: Groups chunks by `KnowledgeID` and `ChunkType`, merging sequential bodies [internal/application/service/chat_pipeline/merge.go149-192](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L149-L192)
 - **FAQ Population**: Populates associated FAQ answers.
 - **Context Expansion**: Expands short contexts with neighboring chunks [internal/application/service/chat_pipeline/merge.go85-86](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L85-L86)
 - **Final Dedup & Overlap Removal**: Removes exact duplicates and partial content overlaps [internal/application/service/chat_pipeline/merge.go91-93](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L91-L93)
 
 Furthermore, hybrid search results are fused using Reciprocal Rank Fusion via `fuseWithRRF` [internal/application/service/knowledgebase_search_fusion.go125-187](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledgebase_search_fusion.go#L125-L187) or deduplicated via `deduplicateByScore` [internal/application/service/knowledgebase_search_fusion.go68-81](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledgebase_search_fusion.go#L68-L81)

## Post-Processing and Lifecycle Management

 The pipeline manages document cloning, updates, and deletion with robust resource tracking.

 
 - **Clone & Move Lifecycle**: When cloning knowledge entries, `cloneKnowledge` performs a deep copy of source files and extracts images into independent tenant storage namespaces [internal/application/service/knowledge_process.go32-152](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge_process.go#L32-L152) It uses `cloneChunkImageInfo` and `rewriteContentImageURLs` to ensure copied chunks own their image resources without sharing state with the source document [internal/application/service/knowledge_clone_move.go39-184](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge_clone_move.go#L39-L184)
 - **Resource Deletion & Reference Counting**: Deleting a knowledge entry involves `resourceReleaser`, which tracks blob ownership bindings to safely reclaim storage only when the last claim on a file or extracted image is dropped [internal/application/service/knowledge_delete.go44-121](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge_delete.go#L44-L121)
