  This page documents the REST API endpoints for managing **knowledge entries** — the individual documents, URLs, and content items that reside within a knowledge base. It covers file upload, URL import, manual Markdown entry, retrieval, update, deletion, download, preview, and reparse operations.

 For knowledge **base** management (the containers for these entries), see [Knowledge Base Management APIs](https://github.com/Tencent/WeKnora/blob/10973ed3/Knowledge Base Management APIs) For chunk-level and FAQ entry APIs, see [FAQ and Chunk APIs](https://github.com/Tencent/WeKnora/blob/10973ed3/FAQ and Chunk APIs)

## Handler Overview

 All endpoints are implemented in `KnowledgeHandler` in [internal/handler/knowledge.go30-38](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/knowledge.go#L30-L38).

 `KnowledgeHandler` coordinates between several service interfaces to handle ingestion, storage, and permission resolution:

 
| Field | Interface | Role |
|---|---|---|
| kgService | interfaces.KnowledgeService | Core knowledge CRUD, file I/O, and search. |
| kbService | interfaces.KnowledgeBaseService | Knowledge base metadata lookup for access checks. |
| kbShareService | interfaces.KBShareService | Resolution of shared KB permissions. |
| agentShareService | interfaces.AgentShareService | Cross-tenant access via shared agents. |
| asynqClient | interfaces.TaskEnqueuer | Enqueueing asynchronous processing tasks. |

## Access Control and Multi-Tenancy

 Every endpoint executes an access-control helper to resolve the effective tenant ID and permission level.

 
 - **KB-Scoped Routes** (e.g., Create, List): Call `validateKnowledgeBaseAccessWithKBID` [internal/handler/knowledge.go95-105](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/knowledge.go#L95-L105). It checks if the caller is the KB owner, has shared access via an organization, or has access via a shared agent.
 - **Item-Scoped Routes** (e.g., Get, Update, Delete): Call `resolveKnowledgeAndValidateKBAccess` [internal/handler/knowledge.go131-163](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/knowledge.go#L131-L163). This first retrieves the knowledge metadata by ID and then validates the caller's relationship to the parent KB.
 
 **Required Roles:**

 
 - **Viewer:** List, Get, Download, Preview, Batch Get, Search.
 - **Editor/Admin:** Create, Update, Delete, Reparse, Tag Batch Update.
 
 Sources: [internal/handler/knowledge.go61-163](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/knowledge.go#L61-L163)

## Knowledge Data Model

 The `Knowledge` struct represents a document or content entry. Key status and type fields determine how the system processes the entry.

 
| Field | Type | Description |
|---|---|---|
| id | string | Unique identifier (UUID). |
| type | string | file, url, or manual. |
| title | string | Display title of the entry. |
| parse_status | string | pending, processing, finalizing, completed, failed, cancelled. |
| file_hash | string | SHA-256 hash used for deduplication within a KB. |
| tag_id | string | Associated category tag identifier. |
| error_message | string | Details if parse_status is failed. |
| folder_path | string | Relative path for organizing knowledge entries into folders. |

 Sources: [client/knowledge.go24-50](https://github.com/Tencent/WeKnora/blob/10973ed3/client/knowledge.go#L24-L50)

## Key Operations

 
### Create Knowledge from File

 **`POST /api/v1/knowledge-bases/:id/knowledge/file`**

 Uploads a physical file via `multipart/form-data`.

 
 - **Form Fields:** `file` (binary), `fileName` (optional), `tag_id` (optional), `enable_multimodel` (boolean string), and `process_config` (JSON string for `KnowledgeProcessOverrides`) [client/knowledge.go100-112](https://github.com/Tencent/WeKnora/blob/10973ed3/client/knowledge.go#L100-L112).
 - **Logic:** The service calculates a file hash. If the hash already exists in the same Knowledge Base, it returns `ErrDuplicateFile` [internal/application/service/knowledge.go38-41](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge.go#L38-L41).
 - **Async Processing:** Once the record is created, a parsing task is enqueued to handle chunking and embedding.
 
 Sources: `[internal/handler/knowledge.go:197-301]`, [client/knowledge.go100-167](https://github.com/Tencent/WeKnora/blob/10973ed3/client/knowledge.go#L100-L167)

 
### Create Knowledge from URL

 **`POST /api/v1/knowledge-bases/:id/knowledge/url`**

 Imports content from a web address.

 
 - **Automatic Mode Selection:** If the URL path contains a known file extension or `file_name` is provided, the system treats it as a direct download. Otherwise, it triggers a web crawl [internal/types/interfaces/knowledge.go27-42](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/knowledge.go#L27-L42).
 - **Security:** URLs are validated against SSRF to prevent internal network probing.
 
 Sources: [internal/types/interfaces/knowledge.go27-42](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/knowledge.go#L27-L42)

 
### Create Manual Knowledge

 **`POST /api/v1/knowledge-bases/:id/knowledge/manual`**

 Creates a knowledge entry from raw Markdown text.

 
 - **Logic:** The system saves the Markdown content as a file in the storage backend, allowing manual entries to be processed by the same pipeline as uploaded files [internal/types/interfaces/knowledge.go48-55](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/knowledge.go#L48-L55).
 
 Sources: [internal/types/interfaces/knowledge.go48-55](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/knowledge.go#L48-L55)

 
### Reparse Knowledge

 **`POST /api/v1/knowledge/:id/reparse`**

 Triggers a re-run of the parsing pipeline.

 
 - **Usage:** Used to update chunks after changing parsing rules or to recover from a failed parse state [internal/types/interfaces/knowledge.go123-130](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/knowledge.go#L123-L130).
 - **Overrides:** Callers can provide `process_config` to adjust chunking or embedding settings specifically for this reparse [client/knowledge.go89-98](https://github.com/Tencent/WeKnora/blob/10973ed3/client/knowledge.go#L89-L98).
 
 Sources: `[internal/types/interfaces/knowledge.go:123-130]`, [client/knowledge.go89-98](https://github.com/Tencent/WeKnora/blob/10973ed3/client/knowledge.go#L89-L98)

 
### Cancel Knowledge Parse

 **`POST /api/v1/knowledge/:id/cancel-parse`**

 Cancels an in-progress parsing task for a knowledge entry.

 
 - **Logic:** Updates the status to `cancelled` [internal/types/interfaces/knowledge.go131-133](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/knowledge.go#L131-L133).
 
 Sources: [internal/types/interfaces/knowledge.go131-133](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/knowledge.go#L131-L133)

## Error Handling

 Common technical errors returned by the service layer:

 
| Sentinel Error | Description | HTTP Status |
|---|---|---|
| ErrDuplicateFile | File content hash already exists in the target KB. | 409 Conflict |
| ErrDuplicateURL | The URL has already been ingested into the target KB. | 409 Conflict |
| ErrInvalidFileType | The uploaded file extension is not supported. | 400 Bad Request |
| ErrImageNotParse | Attempted image update without enabling multimodal features. | 400 Bad Request |
