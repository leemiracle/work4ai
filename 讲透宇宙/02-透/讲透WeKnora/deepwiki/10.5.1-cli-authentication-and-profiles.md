## Purpose and Scope

 The WeKnora CLI supports multiple authentication profiles to interact with different WeKnora servers or tenants. Secure credential storage, JWT token refresh, and environment-override support enable flexible workflows for both interactive users and automated agents.

 Key commands covered here:

 
 - `weknora auth login` — authenticate a named profile (username/password or API key).
 - `weknora auth refresh` — refresh JWT tokens using refresh tokens.
 - `weknora auth logout` — clear stored credentials.
 - `weknora auth list` — enumerate configured profiles.
 - `weknora auth status` — query the current authentication status.
 - `weknora profile` commands — manage named server profiles.
 - `weknora link` — bind the current directory to a knowledge base (KB), linking project context to profiles and KBs.

## 1. Authentication Profiles Overview

 WeKnora uses named **profiles** configured in `~/.config/weknora/config.yaml` [cli/internal/cmdutil/factory.go77-92](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L77-L92) Each profile stores:

 
 - Host endpoint URL (server base URL).
 - Credentials references (to OS keyring or file-based secrets) [cli/internal/cmdutil/factory.go165-174](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L165-L174)
 - Metadata such as the logged-in username, tenant ID, and credential mode.
 
 The CLI commands act on an *active profile*, selected by default or overridden via the global `--profile` flag or `WEKNORA_PROFILE` environment variable [cli/internal/cmdutil/factory.go51-54](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L51-L54)

 Credential storage abstraction supports both OS keyring and fallback to encrypted file storage under `$XDG_CONFIG_HOME/weknora/secrets`.

 
### Profile Structure (Conceptual)

 
| Field | Description |
|---|---|
| Name | Profile name, e.g. "prod" or "ci". |
| Host | Server base URL (https://...). |
| APIKeyRef | Reference to stored API key. |
| TokenRef | Reference to stored JWT access token. |
| RefreshRef | Reference to stored JWT refresh token. |
| User | Logged-in username/email. |
| TenantID | Tenant identifier scoped to profile. |

 Only the references are stored in config; the actual secrets reside in the keyring or fallback stores.

## 2. CLI Commands for Authentication and Profiles

 
### 2.1 `weknora auth login`

 
 - Authenticates the **active profile** by either: 
 - Interactive prompt for email/password.
 - Piping API key via `--with-token` flag.
 - Persists credentials securely.
 - Updates profile metadata (user email, tenant ID).
 - Enforces that profile is pre-created (`weknora profile add ...`) with host set [cli/internal/cmdutil/factory.go132-155](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L132-L155)
 
 
#### Key code flow:

 
 - Retrieve active profile from config (error if missing or corrupt) [cli/internal/cmdutil/factory.go124-152](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L124-L152)
 - If `--with-token` is set, read API key from stdin, validate via `/auth/me`.
 - Otherwise, prompt user for email and password.
 - Call the `Login` API (via SDK) with credentials.
 - On success, persist: 
 - API key or JWT tokens to secrets store.
 - User metadata into config profile.
 - Output summary (JSON or text).
 
 Sources: `cli/internal/cmdutil/factory.go:116-174`

 
---

 
### 2.2 `weknora auth refresh`

 
 - For JWT profiles only (not API keys).
 - Sends stored refresh token to `/auth/refresh` endpoint.
 - Retrieves new access + refresh tokens, saves them to secrets store.
 - Reports success with profile name.
 
 
#### Behavior highlights:

 
 - Validates profile and stored refresh token presence.
 - Rejects API-key profiles with error code `input.invalid_argument`.
 - Uses a fresh SDK client without auth headers for refresh calls.
 - Supports dry-run mode for safe testing.
 - Shows detailed hints on errors, e.g. missing token or invalid states.
 
 Sources: `cli/internal/cmdutil/exit.go:144-188`

 
---

 
### 2.3 `weknora auth logout`

 
 - Clears stored credentials for one or all profiles.
 - Does **not delete** profile configuration (host, user info remains).
 - Requires explicit user confirmation (not auto-skippable without `-y`).
 - Deletes secrets from keyring or file fallback.
 - Updates config to remove secret references for affected profiles.
 
 Sources: `cli/internal/cmdutil/exit.go:1-93`

 
---

 
### 2.4 `weknora auth list`

 
 - Enumerates profiles configured in config.yaml.
 - Shows: profile name, host, user, mode (Bearer or API Key), current active profile marker.
 - Supports JSON output for automation.
 
 Sources: `cli/internal/cmdutil/exit.go:1-257`

### 2.5 `weknora auth status`

 
 - Live check of the active profile credentials by calling `/auth/me`.
 - Shows detailed user and tenant info.
 - Reports exit code 3 (`auth.unauthenticated`) on invalid or missing token [cli/internal/cmdutil/exit.go35-70](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/exit.go#L35-L70)
 - Differentiates stateless env credentials (`WEKNORA_API_KEY/WEKNORA_TOKEN`) from profile credentials.

## 3. Credential Storage and Token Refresh Architecture

 
### 3.1 Credential Storage

 
 - Credentials are never stored as plain text config.
 - `~/.config/weknora/config.yaml` holds profile config with references:

 
 - `APIKeyRef`
 - `TokenRef` (JWT access token ref) [cli/internal/cmdutil/factory.go166-172](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L166-L172)
 - `RefreshRef` (JWT refresh token ref)
 - The actual secret values live in a **Secrets Store** abstraction:

 
 - Primary: OS keyring (macOS Keychain, Linux Secret Service, Windows Credential Manager).
 - Fallback: encrypted file storage in `$XDG_CONFIG_HOME/weknora/secrets/` [cli/internal/cmdutil/factory.go103-107](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L103-L107)
 - The CLI `Factory` type composes config, secrets, and SDK clients lazily respecting TTY/non-TTY contexts [cli/internal/cmdutil/factory.go23-55](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L23-L55)

### 3.2 Token Refresh Flow

 
 - `weknora auth refresh` reads stored refresh token from secrets.
 - Sends it to `/auth/refresh` to get new token pair.
 - The new access token and refresh token replace existing ones in secret store.
 - API key profiles lack refresh tokens, rejected by CLI.

## 4. Multi-Profile Configuration and Resolution

 
### 4.1 Profile Lifecycle and Resolution

 
 - Profiles are created with `weknora profile add <name> --host <url> --use` [cli/internal/cmdutil/factory.go134-135](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L134-L135)
 - Each CLI invocation resolves the **active profile** from: 
 - Global `--profile` flag (highest priority) [cli/internal/cmdutil/factory.go51-54](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L51-L54)
 - Environment variable `WEKNORA_PROFILE`.
 - Config's `CurrentProfile` [cli/internal/cmdutil/factory.go128](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L128-L128)
 - Commands requiring authentication error if no active profile or host configured [cli/internal/cmdutil/factory.go132-155](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L132-L155)
 - The active profile determines which credentials are loaded for SDK client creation [cli/internal/cmdutil/factory.go116-174](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L116-L174)
 
 
### 4.2 Environment Variables and Stateless Auth

 
 - Env vars `WEKNORA_TOKEN` or `WEKNORA_API_KEY` with `WEKNORA_HOST` override profile config [cli/internal/cmdutil/factory.go117-123](https://github.com/Tencent/WeKnora/blob/10973ed3/cli/internal/cmdutil/factory.go#L117-L123)
 - In this mode, no credential persistence or profile change occurs.
 - `auth refresh` disallows refresh for env-credential mode.
