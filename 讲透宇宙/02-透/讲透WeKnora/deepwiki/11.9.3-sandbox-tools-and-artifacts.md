## 1. Shell Execution Tool (`shell_exec`)

 
### Overview

 The `shell_exec` tool is the general shell command executor inside a session-scoped sandbox environment. Agents use it to inspect and manipulate files, run custom scripts, install dependencies, and perform arbitrary operations isolated per tenant session.

 
### Key Features and Safeguards

 
 - **Session Isolation:** Commands execute only inside the sandbox linked to the current session ID, preventing cross-session operations.
 - **Execution Environment:** Default working directory is `/workspace`. Work directories are restricted to subpaths of `/workspace` to avoid sandbox escapes.
 - **Command Size and Timeout Limits:** Commands are capped in length; typical timeout values restrict runaway executions.
 - **Blacklist Safety:** A blacklist rejects dangerous commands to prevent destructive actions like recursive root deletion, fork bombs, filesystem formatting, or backgrounding processes.
 - **Output Truncation:** Both stdout and stderr outputs are truncated and summarized to keep LLM context size manageable, preserving head and tail portions to retain critical error diagnostics.
 - **Error Handling:** Non-zero exit codes are returned as tool results for the LLM's inspection; only system-level execution failures return `Success=false`.

## 2. File Read/Write/Edit Tools

 
### Overview

 Tools for file manipulation inside the sandbox allow reading, writing, and editing files securely within sandbox boundaries. They complement `shell_exec` by providing atomic file operations where inline scripting is inconvenient.

 
 - They respect sandbox session isolation and restrict paths to `/workspace`.
 - File artifacts generated or modified by these tools are tracked for cleanup and audit.
 - Specific fields (such as raw binary contents and base64 payloads) are stripped from database persistence via `SanitizeToolDataForPersist` to avoid database bloat.

## 3. Data Analysis Tool (`data_analysis`)

 
### Purpose

 The `data_analysis` tool (`DataAnalysisTool`) enables executing SQL queries on tabular data loaded from CSV or Excel documents within the sandbox. It loads data into memory and executes SQL for data statistics.

 
### Implementation Details

 
 - **Input Struct:** `DataAnalysisInput` (fields: `KnowledgeID` and `Sql`) [internal/agent/tools/data_analysis.go106-109](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/tools/data_analysis.go#L106-L109)

## 4. Database Query Tool (`database_query`)

 
### Purpose

 Allows agents to run safe, tenant-scoped SELECT queries directly against the service's multi-tenant PostgreSQL database via `DatabaseQueryTool`.

 
### Key Components

 
 - **Input Struct:** `DatabaseQueryInput` containing the `SQL` string [internal/agent/tools/database_query.go95-97](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/tools/database_query.go#L95-L97)
 - **Automatic Security Enhancements:** Automatically injects `tenant_id` filters and `deleted_at IS NULL` conditions, restricts execution to read-only `SELECT` statements, and enforces a whitelist of safe tables (`knowledge_bases`, `knowledges`, `chunks`) [internal/agent/tools/database_query.go15-62](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/tools/database_query.go#L15-L62)
 - **Execution:** Uses GORM (`*gorm.DB`) to execute the validated and secured query string [internal/agent/tools/database_query.go102-171](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/tools/database_query.go#L102-L171)

## 5. Tool Policy and Scope Authorization

 Tool calls are heavily constrained by security policies and search scope enforcement:

 
 - The system manages policy enforcement and handles encoding/decoding for durable entity references via `modelcontext` registries and tool policies.
 - Tools like `DataAnalysisTool` and `DatabaseQueryTool` accept search targets and tenant context values (e.g., `types.TenantIDContextKey`) to ensure queries never breach multi-tenant barriers.

## 7. SQL Validation and Injection Mitigation (`internal/utils/inject.go`)

 
### Summary

 The codebase implements comprehensive parsing and validation of SQL statements using `pg_query_go` (`ParseSQL`, `ValidateSQL`) [internal/utils/inject.go8-178](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/utils/inject.go#L8-L178) It guards against SQL injection risks, disallows subqueries or CTEs where restricted, and enforces schema and table whitelists.
