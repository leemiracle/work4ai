## Purpose and Scope

 This page details the microservices architecture of WeKnora, describing container orchestration via Docker Compose, service dependencies, container communication, and backend initialization [docker-compose.yml1-35](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L1-L35) It explains how the services collaborate in a composable infrastructure, the role each container plays, startup ordering, and communication protocols.

 For deep dives into individual internal components and pipeline flows, refer to related architectural pages.

## Multi-Service Layout

 WeKnora architecture consists of multiple containerized services orchestrated using Docker Compose, defined primarily in the `docker-compose.yml` file [docker-compose.yml1-35](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L1-L35) Core services start unconditionally, while optional components are activated via Docker Compose profiles.

 The system includes frontend UI, backend app server, document parser, databases, vector stores, and observability tools.

 *Explanation:*

 
 - The `frontend` service serves the Vue.js SPA and handles HTTP requests on port 80 [docker-compose.yml2-16](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L2-L16) It proxies API calls to the backend `app` service via `APP_HOST` and `APP_PORT` environment variables [docker-compose.yml17-26](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L17-L26)
 - The `app` service exposes the REST API backend on port 8080 and communicates with storage and external services [docker-compose.yml36-46](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L36-L46)
 - `docreader` handles document parsing and extraction exposed via gRPC [.env.example94-96](https://github.com/Tencent/WeKnora/blob/10973ed3/.env.example#L94-L96)
 - Multiple storage services are used: `postgres` (ParadeDB PostgreSQL), `redis` (caching & streaming), and optional vector stores (`qdrant`, `milvus`, `neo4j` as a graph database) [docker-compose.dev.yml4-36](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.dev.yml#L4-L36)

|---|---|---|---|

| neo4j | neo4j, full | Knowledge graph (GraphRAG) | docker compose --profile neo4j up docker-compose.dev.yml212-213 |
| qdrant | qdrant, full | Vector database for embeddings | docker compose --profile qdrant up docker-compose.dev.yml118-120 |

| langfuse | langfuse | LLM observability and telemetry | docker compose --profile langfuse up .env.example146-150 |

## Startup Dependencies and Health Checks

 Proper startup order and readiness detection are enforced using `depends_on` and healthchecks [docker-compose.yml29-34](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L29-L34)

 
### Startup Dependencies

 The `frontend` container depends on the `app` container's health success condition, ensuring the backend is ready before proxying requests [docker-compose.yml29-34](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L29-L34)

 
### Health Checks

 Multiple containers expose health endpoints polled by Docker Compose:

 
| Service | Healthcheck Command | Parameters |
|---|---|---|
| app | curl -f http://localhost:8080/health | Interval 30s, Timeout 10s, Retries 3 docker-compose.yml59-64 |
| postgres | pg_isready -U ${DB_USER} | Interval 10s, Timeout 10s, Retries 3 docker-compose.dev.yml17-22 |
| minio | curl -f http://localhost:9000/minio/health/live | Interval 30s, Timeout 20s, Retries 3 docker-compose.dev.yml96-100 |
| milvus | curl -f http://localhost:9091/healthz | Interval 30s, Start 90s, Timeout 20s docker-compose.dev.yml188-192 |

 Sources: `docker-compose.yml:29-64`, `docker-compose.dev.yml:17-192`

## Configuration Architecture and Binding

 The application configuration layer utilizes `spf13/viper` and `gopkg.in/yaml.v3` to parse configuration files like `config/config.yaml` and environment variables [internal/config/config.go13-16](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/config/config.go#L13-L16) The struct `Config` aggregates all subsystem configurations including conversation parameters, server binding, database drivers, and model endpoints [internal/config/config.go18-42](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/config/config.go#L18-L42)
