  This document describes WeKnora's build system, Docker image creation, and continuous integration/deployment pipeline. It covers the Makefile-based local build tools, multi-stage Dockerfiles with version injection, GitHub Actions workflows, lite release packaging, and multi-architecture container creation.

## Docker Multi-Stage Builds

 
### Application Container (`docker/Dockerfile.app`)

 The application container uses a multi-stage pattern:

 
 - **Browserskill Stage**: Builds extension components on Node 24 and Rust [docker/Dockerfile.app2-14](https://github.com/Tencent/WeKnora/blob/10973ed3/docker/Dockerfile.app#L2-L14)
 - **Builder Stage**: Uses `golang:1.26-bookworm`, downloads Go modules via caching mounts, installs `migrate`, downloads DuckDB files, copies source files, and compiles the application via `make build-prod` [docker/Dockerfile.app17-86](https://github.com/Tencent/WeKnora/blob/10973ed3/docker/Dockerfile.app#L17-L86)
 - **Runtime Stage**: Based on `debian:12.12-slim`, creates non-root user `appuser`, installs system client utilities (`postgresql-client`, `default-mysql-client`), Python 3, `uv`, Node.js, and copies binaries, configs, and migrations [docker/Dockerfile.app89-157](https://github.com/Tencent/WeKnora/blob/10973ed3/docker/Dockerfile.app#L89-L157)
 
 
### Document Reader Container (`docker/Dockerfile.docreader`)

 
 - **Builder Stage**: Python 3.10 bookworm environment, installs `protoc` (offline or online fallback), resolves dependencies with `uv`, and compiles protobuf/gRPC definitions [docker/Dockerfile.docreader4-77](https://github.com/Tencent/WeKnora/blob/10973ed3/docker/Dockerfile.docreader#L4-L77)
 - **Runner Stage**: Minimal runtime with LibreOffice, Java 17 headless, graphics libraries, `grpc_health_probe`, and Playwright WebKit binaries [docker/Dockerfile.docreader82-159](https://github.com/Tencent/WeKnora/blob/10973ed3/docker/Dockerfile.docreader#L82-L159)

## Lite Release Packaging and Multi-Arch Image Creation

 
### Lite Release Packaging

 Lite mode eliminates external service dependencies (such as Redis and PostgreSQL) by utilizing SQLite with FTS5 and `sqlite-vec` extensions alongside in-memory queue management [website-docs/01-getting-started/02-installation.md12-37](https://github.com/Tencent/WeKnora/blob/10973ed3/website-docs/01-getting-started/02-installation.md?plain=1#L12-L37)

 
 - The GitHub Actions workflow `Release Lite Binaries` (`.github/workflows/release-lite.yml`) builds frontend assets once and uploads them as artifacts [.github/workflows/release-lite.yml27-49](https://github.com/Tencent/WeKnora/blob/10973ed3/.github/workflows/release-lite.yml#L27-L49)
 - A matrix job compiles the Web CLI binary (`WeKnora-lite`) per target platform (`linux/amd64`, `linux/arm64`, `darwin/amd64`, `darwin/arm64`) using native CGO [.github/workflows/release-lite.yml51-107](https://github.com/Tencent/WeKnora/blob/10973ed3/.github/workflows/release-lite.yml#L51-L107)
 - The packaging step creates a tarball bundle containing the binary, embedded web assets, `.env.lite.example`, licenses, configuration templates, and SQLite migration files [.github/workflows/release-lite.yml108-137](https://github.com/Tencent/WeKnora/blob/10973ed3/.github/workflows/release-lite.yml#L108-L137)
 
 
### Multi-Arch Container Creation

 Multi-architecture image builds are managed via GitHub Actions workflows (e.g., [.github/workflows/docker-image.yml1-206](https://github.com/Tencent/WeKnora/blob/10973ed3/.github/workflows/docker-image.yml#L1-L206)).

 
 - Leverages Docker Buildx (`docker/setup-buildx-action`) to compile images simultaneously for `linux/amd64` and `linux/arm64`.
 - Integrates `docker/metadata-action` for automatic tag and label management linked to git tags or branch pushes.
 - Caches build layers using GitHub Actions caching scopes (`cache-from: type=gha`, `cache-to: type=gha,scope=...`) to optimize pipeline execution time.

## CI/CD Workflows Summary

 WeKnora implements separate workflow files to isolate concerns:

 
 - **App Workflow** ([.github/workflows/app.yml1-124](https://github.com/Tencent/WeKnora/blob/10973ed3/.github/workflows/app.yml#L1-L124)): Triggers on Go file modifications, performs formatting checks (`gofmt`), `go vet`, unit tests, and license validation.
 - **DocReader Workflow** ([.github/workflows/docreader.yml1-105](https://github.com/Tencent/WeKnora/blob/10973ed3/.github/workflows/docreader.yml#L1-L105)): Runs Python unittest suites, Playwright WebKit installation, gRPC server readiness probes, and Go client integration tests.
 - **Docker Image Workflow** ([.github/workflows/docker-image.yml1-206](https://github.com/Tencent/WeKnora/blob/10973ed3/.github/workflows/docker-image.yml#L1-L206)): Builds and pushes multi-arch application, UI, docreader, and sandbox images to Docker Hub upon tagging or pushing to `main`.
