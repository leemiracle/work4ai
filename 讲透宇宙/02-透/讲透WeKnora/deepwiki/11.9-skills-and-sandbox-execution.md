## Sandbox Runtimes and Configuration

 Skill code execution occurs inside sandbox runtimes that isolate code for security, repeatability, and tenant separation [internal/sandbox/session_manager.go1-23](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/sandbox/session_manager.go#L1-L23) The subsystem supports multiple backend providers including Docker engines, E2B remote container services, and Tencent Cloud Cube container runtimes [internal/sandbox/session_manager.go4-8](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/sandbox/session_manager.go#L4-L8)

 Session sandbox lifecycle management ensures that each tenant session binds lazily to a persistent remote sandbox, coordinating creation, recovery, replacement, and deletion through a distributed lifecycle lock [internal/sandbox/session_manager.go12-17](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/sandbox/session_manager.go#L12-L17) Sandboxes execute skill scripts with controlled environment variables and filesystem isolation limits under writable workspace roots [internal/sandbox/session_manager.go58-60](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/sandbox/session_manager.go#L58-L60)

 For detailed information on sandbox backends, session lifecycle, templates, idle sweeping, and tenant sandbox policies, see [Sandbox Runtimes and Configuration](https://deepwiki.com/Tencent/WeKnora/11.9.1-sandbox-runtimes-and-configuration).

## Tenant Skill Catalog and Installation

 Each tenant manages their own catalog of skills packaged as zipped archives called skill bundles. These bundles contain metadata from the `SKILL.md` manifest, skill scripts, dependencies, and configuration. The skill catalog subsystem validates uploaded bundles, extracts metadata, supports multiple skill sources (local paths, Git, remote registries), and maintains skill lifecycle states.

 The install pipeline unpacks bundles, verifies files and declarations using an in-sandbox verification pass, and triggers image rebuilds with updated skill files stored under dedicated image roots [internal/sandbox/skill_paths.go10-20](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/sandbox/skill_paths.go#L10-L20) [internal/application/service/tenant_skill_verify.go63-98](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_verify.go#L63-L98)

 For details on skill sources, installation steps, bundle verification, environment declarations, reaper cleanup, and UI panels for managing skills, see [Tenant Skill Catalog and Installation](https://deepwiki.com/Tencent/WeKnora/11.9.2-tenant-skill-catalog-and-installation).

## Sandbox Tools and Artifacts

 Executed skills and agents interact with the sandboxed environment and external resources via specialized sandbox tools. The tooling infrastructure provides shell execution capabilities (`shell_exec`), file read/write/edit operations under `/workspace`, data analysis and database query tools, policy-based scope authorization, and artifact collection facilities targeting directories such as `/workspace/output` [internal/agent/tools/definitions.go28-62](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/tools/definitions.go#L28-L62) [internal/sandbox/session_manager.go39-47](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/sandbox/session_manager.go#L39-L47)

 Tool invocations follow strict validation and ownership rules to prevent illegitimate access or resource leaks. Artifacts deposited by skill executions are collected and made accessible for downstream processing or user retrieval.

 For a comprehensive guide to sandbox tooling APIs, command execution semantics, artifact handling, and authorization policies, see [Sandbox Tools and Artifacts](https://deepwiki.com/Tencent/WeKnora/11.9.3-sandbox-tools-and-artifacts).
