  This page documents WeKnora's authentication and authorization mechanisms, including bearer tokens, API keys, single sign-on (OIDC), multi-tenant permission models, and role-based access control (RBAC).

 
## Overview

 WeKnora implements a context-driven security architecture where tenant isolation and caller identity flow through application layers via `context.Context`. Security checks are enforced at multiple checkpoints—from HTTP middleware down to service and repository boundaries.

 **Key Architectural Characteristics:**

 
 - **Context-Driven Session Propagation:** Session attributes (User, Principal, SystemAdmin flag) are bound to the Gin request context via `applyAuthSession` [internal/middleware/auth.go107-113](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/middleware/auth.go#L107-L113)
 - **Multi-Tenant Isolation:** Strict tenant separation with support for explicit tenant switching via the `X-Tenant-ID` header and tenant resolution logic [internal/middleware/auth.go197-207](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/middleware/auth.go#L197-L207)
 - **Hybrid Authentication Channels:** Supports JSON Web Tokens (JWT) for interactive UI clients and cryptographically secured `X-API-Key` headers for programmatic access [internal/middleware/auth.go126-181](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/middleware/auth.go#L126-L181)
 - **Granular RBAC & Ownership:** Role hierarchies (Viewer, Contributor, Admin, Owner) combined with dynamic resource ownership lookups (`CreatorLookup`) [internal/router/rbac.go19-38](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/rbac.go#L19-L38)

## Authentication Model

 
### Context Keys and Session Structs

 Incoming requests that pass authentication populate the request context with an `authSession` containing the authenticated `types.User`, a `types.Principal` identifier, and administrative flags [internal/middleware/auth.go107-113](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/middleware/auth.go#L107-L113)

 
| Session Attribute | Type / Entity | Purpose |
|---|---|---|
| User | types.User | The underlying user entity retrieved from persistence internal/middleware/auth.go109 |
| Principal | types.Principal | Distinguishes between web user sessions and API key principals internal/middleware/auth.go110 |
| SystemAdmin | bool | Platform-wide administrative flag independent of tenant roles internal/middleware/auth.go111 |

## Authorization and RBAC

 WeKnora implements a centralized role-based access control matrix managed through `rbacGuards` [internal/router/rbac.go113-149](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/rbac.go#L113-L149)

 
### Tenant Roles

 
 - **Viewer:** Read-only access to tenant resources.
 - **Contributor:** Can create new resources and modify items they personally authored (`creator_id`).
 - **Admin:** Full management of tenant-level infrastructure, members, and configurations.
 - **Owner:** Ultimate authority over workspace lifecycle and settings.
 
 
### Guard Mechanisms & Ownership Lookups

 Guards enforce permissions by inspecting tenant memberships or resolving resource authors via `CreatorLookup` closures [internal/router/rbac.go119-132](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/rbac.go#L119-L132)

 
| Guard / Lookup Symbol | Code Entity & Role | Purpose |
|---|---|---|
| RequireRole | middleware.RequireRole internal/middleware/rbac.go67 | Enforces minimum tenant role floor |
| RequireSystemAdmin | middleware.RequireSystemAdmin internal/middleware/rbac.go147 | Restricts endpoints to platform administrators |
| kbCreator | middleware.CreatorLookup internal/router/rbac.go119 | Resolves Knowledge Base :id to creator_id |
| knowledgeKBCreator | middleware.CreatorLookup internal/router/rbac.go129 | Resolves document parent KB creator |

## System Administration

 Platform administration is strictly gated behind the `IsSystemAdmin` flag on the `types.User` model [internal/types/user.go23](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/user.go#L23-L23)

 
 - **Backend Enforcement:** The `RequireSystemAdmin` middleware aborts non-admin requests with `403 Forbidden` [internal/middleware/rbac.go147-170](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/middleware/rbac.go#L147-L170)
 - **Frontend Gating:** The Pinia store `useAuthStore` exposes an `isSystemAdmin` computed property [frontend/src/stores/auth.ts121-123](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/stores/auth.ts#L121-L123) which the menu store `useMenuStore` uses to conditionally render administrative navigation links [frontend/src/stores/menu.ts69-84](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/stores/menu.ts#L69-L84)
