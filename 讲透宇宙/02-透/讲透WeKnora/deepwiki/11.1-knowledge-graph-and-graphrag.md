## Purpose and Scope

 This page documents WeKnora's knowledge graph and GraphRAG (Graph-enhanced Retrieval-Augmented Generation) subsystems. It explains how unstructured document content is transformed into structured semantic entities and relationships, how graph stores and vector stores are integrated, how asynchronous extraction pipelines (`TypeChunkExtract`) operate via Asynq worker pools, and how graph-based retrieval tooling (`QueryKnowledgeGraphTool`) powers agentic multi-hop reasoning.

 
---

 
## System Architecture and Component Overview

 WeKnora bridges unstructured text chunks with structured knowledge graphs. The pipeline orchestrates document ingestion, asynchronous post-processing, entity/relation extraction, and hybrid retrieval.

## Configuration and Schema Definition

 Knowledge base graph extraction schemas are structured around explicit entity definitions, attributes, and typed interrelations.

 
### Schema Data Structures

 The core data structures governing extraction templates and schemas are defined in `internal/types/extract_graph.go`:

 
 - `ChunkContext`: Encapsulates chunk content along with preceding and succeeding text contexts (`PrevContent`, `NextContent`) to supply contextual boundaries for entity recognition. [internal/types/extract_graph.go4-9](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/extract_graph.go#L4-L9)
 - `GraphNode`: Represents an extracted entity type with a name (`Name`), associated chunk IDs (`Chunks`), and extracted attributes (`Attributes`). [internal/types/extract_graph.go18-22](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/extract_graph.go#L18-L22)
 - `GraphRelation`: Defines directed or undirected semantic relationships between two entities (`Node1`, `Node2`) annotated by a relation `Type`. [internal/types/extract_graph.go25-29](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/extract_graph.go#L25-L29)
 - `GraphData`: Bundles raw text snippets with arrays of `GraphNode` and `GraphRelation` instances. [internal/types/extract_graph.go31-35](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/extract_graph.go#L31-L35)
 - `NameSpace`: Manages namespace boundaries for knowledge bases and individual knowledge items. [internal/types/extract_graph.go37-53](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/extract_graph.go#L37-L53)

## Asynchronous Graph Extraction Pipeline

 Graph extraction executes asynchronously following text chunking and indexing.

 
### Task Queue Topology

 Tasks are routed through specialized Asynq worker queues managed by the server router:

 
 - `QueueGraph`: Associated with `WorkerPoolEnrichment`, executing chunk extraction tasks (`TypeChunkExtract`) with defined queue weights. [internal/types/task.go40-79](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/task.go#L40-L79)
 - `KnowledgePostProcessService`: Orchestrates post-processing steps after document parsing, triggering downstream enrichment tasks including graph entity extraction. [internal/application/service/knowledge_post_process.go21-54](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge_post_process.go#L21-L54)
 - In Lite mode, `SyncTaskExecutor` processes these tasks synchronously in background goroutines without requiring a Redis daemon. [internal/router/sync_task.go17-36](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/sync_task.go#L17-L36)

## Graph-Based Retrieval and Agent Tooling

 GraphRAG combines vector search with explicit graph traversals. Agents query the semantic graph using specialized tools.

 
### Query and Retrieval Flow

 
 - `QueryKnowledgeGraphTool`: Exposes graph querying capabilities to the ReAct agent engine, executing structured queries across nodes and relations. [internal/agent/tools/query_knowledge_graph.go1-100](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/tools/query_knowledge_graph.go#L1-L100)
 - Hybrid retrieval engines combine dense vector embeddings with sparse keyword search (BM25) to pinpoint entry-point chunks before graph expansion. [internal/application/service/retriever/hybrid_search.go20-60](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/retriever/hybrid_search.go#L20-L60)
