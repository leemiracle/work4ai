  This page documents the multi-database architecture of WeKnora, including how various databases are initialized, the multi-tenant storage configuration, file storage and proxy mechanisms, and the dynamic selection of retrieval engines. WeKnora utilizes a diverse set of storage backends to handle relational data, vector embeddings, document files, graph entities, and analytical queries.

 For how chunks are written into these stores during document ingestion, see [4.4 Chunk Management and Vector Indexing](https://github.com/Tencent/WeKnora/blob/10973ed3/4.4 Chunk Management and Vector Indexing) For retrieval configuration parameters such as top-k and thresholds, see [8.5 Retrieval Engine Configuration](https://github.com/Tencent/WeKnora/blob/10973ed3/8.5 Retrieval Engine Configuration) For how the dependency injection container wires these stores together, see [3.6 Dependency Injection and Service Layer](https://github.com/Tencent/WeKnora/blob/10973ed3/3.6 Dependency Injection and Service Layer)

## Storage Backends at a Glance

 WeKnora uses several distinct storage systems, each serving a different purpose.

 
| Backend | Role | Required | Config key |
|---|---|---|---|
| PostgreSQL | Relational data + optional pgvector | Yes | DB_DRIVER=postgres |
| SQLite | Lightweight alternative to PostgreSQL | Optional | DB_DRIVER=sqlite |
| Redis | Session context, async task queue (Asynq) | Optional | REDIS_ADDR |
| Local filesystem | File storage default | Default | STORAGE_TYPE=local |
| MinIO / S3 | S3-compatible object storage | Optional | STORAGE_TYPE=minio or s3 |
| Aliyun OSS | Alibaba Cloud Object Storage | Optional | STORAGE_TYPE=oss |
| Tencent COS | Tencent Cloud Object Storage | Optional | STORAGE_TYPE=cos |
| Qdrant | Dedicated vector database | Optional | RETRIEVE_DRIVER=qdrant |
| Milvus | Dedicated vector database | Optional | RETRIEVE_DRIVER=milvus |
| Elasticsearch v7/v8 | Keyword + vector search | Optional | RETRIEVE_DRIVER=elasticsearch_v7 or _v8 |
| Weaviate | Vector search with gse tokenization | Optional | RETRIEVE_DRIVER=weaviate |
| Tencent VectorDB | Dedicated vector database | Optional | RETRIEVE_DRIVER=tencent_vectordb |
| Doris | OLAP database with vector capabilities | Optional | RETRIEVE_DRIVER=doris |
| Neo4j | Knowledge graph (GraphRAG) | Optional | NEO4J_ENABLE=true |
| DuckDB | In-memory analytics (data table tool) | Bundled | Always started |

## PostgreSQL — Relational Store

 
### Schema Definition

 The relational database stores core entity metadata. Initialized via versioned migrations.

 
 - **Tenants**: Stores organization-level configurations including `retriever_engines`, `agent_config`, and storage quotas `[migrations/versioned/000000_init.up.sql:11-25]`.
 - **Models**: Stores configurations for various AI models (LLM, Embedding, Rerank). Each model has a `Type`, `Source`, and `Parameters` `[migrations/versioned/000000_init.up.sql:51-65]`.
 - **Knowledge Bases**: Links documents to specific embedding models and contains `chunking_config` `[migrations/versioned/000000_init.up.sql:73-89]`.
 - **Knowledges**: Metadata for individual documents, including `parse_status` (unprocessed, processing, completed) and file details `[migrations/versioned/000000_init.up.sql:96-119]`.
 - **Sessions**: Stores conversation session metadata, including retrieval thresholds and model IDs `[migrations/versioned/000000_init.up.sql:129-152]`.
 - **Messages**: Stores individual chat messages, including `content`, `knowledge_references`, and `agent_steps` `[migrations/versioned/000000_init.up.sql:160-172]`.
 
 
### Connection Initialization

 WeKnora supports PostgreSQL (with `pgvector`) for relational data.

 
 - **PostgreSQL**: Implemented via `postgresRepo` [internal/application/repository/retriever/postgres/repository.go20-22](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/postgres/repository.go#L20-L22). It supports both `KeywordsRetrieverType` (Full-text search) and `VectorRetrieverType` (pgvector) [internal/application/repository/retriever/postgres/repository.go36-38](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/postgres/repository.go#L36-L38).
 - **Storage Estimation**: The system estimates storage size based on content length and vector dimensions [internal/application/repository/retriever/postgres/repository.go41-61](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/postgres/repository.go#L41-L61).

## File Storage Layer

 WeKnora provides a unified `interfaces.FileService` interface for handling document binary storage, proxying, and presigned access [internal/types/interfaces/file.go1-31](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/file.go#L1-L31).

 
| Provider | Implementation Class | Scheme |
|---|---|---|
| Local FS | localFileService | local:// |
| Tencent COS | cosFileService | cos:// |
| Aliyun OSS | ossFileService | oss:// |
| AWS S3 | s3FileService | s3:// |
| MinIO | minioFileService | minio:// |

 
 - **Local Storage**: Files are stored under `baseDir/{tenantID}/{knowledgeID}/` and protected against path traversal via `secutils.SafePathUnderBase` [internal/application/service/file/local.go58-63](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/file/local.go#L58-L63).
 - **Tencent COS**: Uses `tencentyun/cos-go-sdk-v5` with SSRF-safe HTTP validation [internal/application/service/file/cos.go23-49](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/file/cos.go#L23-L49).
 - **Aliyun OSS**: Uses `alibabacloud-oss-go-sdk-v2`. Large files (>10MB) utilize multipart concurrent uploads via `NewUploader` [internal/application/service/file/oss.go25-189](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/file/oss.go#L25-L189).
 - **Presigned URLs and Security**: Handled via HMAC-SHA256 signatures derived from `SYSTEM_AES_KEY` or `SYSTEM_SIGNING_KEY` (`utils.SignFileURL` and `utils.VerifyFileURLSig`) [internal/utils/presign.go25-107](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/utils/presign.go#L25-L107). Path tenancy is strictly validated via `ValidateStoragePathTenant` and `ValidateKBScopedStoragePath` [internal/utils/presign.go119-143](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/utils/presign.go#L119-L143).

## Vector Store & Retrieval Layer

 WeKnora supports a pluggable retrieval architecture where workspaces can register multiple `types.VectorStore` instances [internal/types/vectorstore.go39-56](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/vectorstore.go#L39-L56).

 
### Multi-Database Management

 
 - **Env Stores**: Virtual stores defined via environment variables like `ELASTICSEARCH_ADDR` or `QDRANT_HOST`, identified by the `__env_` prefix [internal/types/vectorstore.go19-30](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/vectorstore.go#L19-L30). Built via `BuildEnvVectorStores` [internal/types/vectorstore_test.go44-50](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/vectorstore_test.go#L44-L50).
 - **DB Stores**: Persisted in the `vector_stores` table, allowing multi-tenant registration of external clusters [internal/types/vectorstore.go39-56](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/vectorstore.go#L39-L56). Sensitive fields like `Password` and `APIKey` are encrypted using AES-GCM at rest [internal/types/vectorstore.go122-127](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/vectorstore.go#L122-L127).
 - **Valid Engine Types**: Controlled by `validEngineTypes` restricting managed stores to robust standalone engines (Qdrant, Milvus, Elasticsearch, Weaviate, Doris, Tencent VectorDB, OpenSearch) [internal/types/vectorstore.go87-95](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/vectorstore.go#L87-L95).
 
 
### Retrieval Engines

 
 - **Elasticsearch (v7/v8)**: Supports keyword and vector search with automatic `.keyword` suffix resolution.
 - **Qdrant**: Manages collections dynamically by dimension (e.g., `weknora_embeddings_1536`) with payload indexes for filtering [internal/application/repository/retriever/qdrant/repository.go50-52](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/qdrant/repository.go#L50-L52).
 - **Tencent VectorDB**: Implemented by `repository` in `tencentvectordb` package, handling sparse vectors for BM25 and dynamic collections [internal/application/repository/retriever/tencentvectordb/repository.go39-46](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/tencentvectordb/repository.go#L39-L46).
 - **Doris**: OLAP vector retrieval using Stream Load APIs and partial updates [internal/application/repository/retriever/doris/repository_test.go51-60](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/doris/repository_test.go#L51-L60).

## Storage Size Estimation

 WeKnora provides logic to estimate the storage footprint of indexed documents across engines:

 
| Engine | Estimation Logic (per chunk) |
|---|---|
| PostgreSQL | content_size + (dim * 2) + 200 (metadata) |
| SQLite | content_size + 200 (metadata) |
| Elasticsearch | content_size + (dim * 4) + 250 (metadata) + overhead |
| Qdrant | content_size + (dim * 4) + metadata overhead |
| Tencent VectorDB | content_size + (dim * 4) + (content_size * 2) (sparse vector) |
