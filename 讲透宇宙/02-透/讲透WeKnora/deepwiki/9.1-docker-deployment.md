  This document provides a technical guide for deploying WeKnora using Docker and Docker Compose. It details the microservices architecture configured in `[docker-compose.yml]`, profile selection options defined in `[docker-compose.dev.yml]`, environment variable injection (`[.env.example]`), volume management for data persistence, and networking considerations. It also documents how core application components are initialized via dependency injection in `[internal/container/container.go]` and `[internal/config/config.go]`.

 
---

 
## 1. Service Architecture and Container Orchestration

 WeKnora is structured as a containerized microservices application where each runtime layer handles specific duties, orchestrated via Docker Compose. The application wiring and configuration loading are handled by `config.LoadConfig` and `container.BuildContainer` during startup.

 
### System-to-Code Entity Mapping

 
| System Name | Docker Container Name | Code Entity / Implementation Reference |
|---|---|---|
| Backend Application | WeKnora-app | cmd/server/main.go, internal/container/container.go104-142, internal/config/config.go19-42 |
| Frontend UI | WeKnora-frontend | Vue.js SPA built via frontend/Dockerfile1-50 and served by NGINX |
| Document Reader | weknora-docreader | Python gRPC parser service defined in docker/Dockerfile.docreader |
| Primary Database | postgres | ParadeDB (PostgreSQL 17) managed via internal/container/container.go123 |
| Task Queue | redis | Redis instance managing async tasks via Asynq in internal/container/container.go125 |

## 2. Core Services and Build Pipelines

 The backend container is built using [docker/Dockerfile.app](https://github.com/Tencent/WeKnora/blob/10973ed3/docker/Dockerfile.app), which compiles the Go server binary, links any optional parser libraries, and runs [scripts/docker-entrypoint.sh](https://github.com/Tencent/WeKnora/blob/10973ed3/scripts/docker-entrypoint.sh). The frontend container utilizes a multi-stage build in [frontend/Dockerfile](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/Dockerfile) where Node.js compiles Vite static assets into an NGINX image.

 
 - **`app` (`WeKnora-app`)**: Listens internally on port `8080`, performing health checks against `http://localhost:8080/health` ([docker-compose.yml59-64](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L59-L64)). It reads configuration properties defined in [internal/config/config.go](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/config/config.go) and injects database drivers and storage providers dynamically.
 - **`frontend` (`WeKnora-frontend`)**: Serves the compiled SPA, proxying API calls to the backend via `APP_HOST` and `APP_BACKEND_PORT` ([docker-compose.yml17-26](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L17-L26)).
 - **`docreader` (`weknora-docreader`)**: Communicates with the backend service via gRPC on `DOCREADER_ADDR` ([.env.example94](https://github.com/Tencent/WeKnora/blob/10973ed3/.env.example#L94-L94)).

 WeKnora uses Docker Compose profiles ([docker-compose.dev.yml](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.dev.yml)) to selectively launch auxiliary infrastructure such as vector databases (`qdrant`, `milvus`), graph databases (`neo4j`), search engines (`searxng`), object storage (`minio`), and observability tools (`langfuse`).

## 5. Networking, Volumes, and Runtime Persistence

 
 - **Networking**: All services communicate over a shared user-defined Docker network (`WeKnora-network`) ([docker-compose.yml32-33](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L32-L33)).
 - **Volume Persistence**: Named volumes ensure relational data, vector indices, and uploaded files survive container updates: 
 - `data-files`: Persistent storage for uploaded user documents ([docker-compose.yml48](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L48-L48)).
 - `docreader-tmp`: Ephemeral storage for file extraction ([docker-compose.yml49](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L49-L49)).

## 6. Build Workflows and Automation Scripts

 Building and operating the containers is managed via [Makefile](https://github.com/Tencent/WeKnora/blob/10973ed3/Makefile), [scripts/dev.sh](https://github.com/Tencent/WeKnora/blob/10973ed3/scripts/dev.sh), and GitHub Actions workflows ([github/workflows/docker-image.yml](https://github.com/Tencent/WeKnora/blob/10973ed3/github/workflows/docker-image.yml)).

 
 - **`make docker-build-app`**: Compiles the Go server binary with build tags and version details ([Makefile116-126](https://github.com/Tencent/WeKnora/blob/10973ed3/Makefile#L116-L126)).
 - **`scripts/dev.sh`**: Helper script to initialize development environments, validate `.env` settings, and run backend components locally ([scripts/dev.sh1-117](https://github.com/Tencent/WeKnora/blob/10973ed3/scripts/dev.sh#L1-L117)).
 - **CI/CD**: [github/workflows/docker-image.yml](https://github.com/Tencent/WeKnora/blob/10973ed3/github/workflows/docker-image.yml) builds multi-architecture images (`linux/amd64`, `linux/arm64`) for the app, UI, and docreader components ([github/workflows/docker-image.yml45-106](https://github.com/Tencent/WeKnora/blob/10973ed3/github/workflows/docker-image.yml#L45-L106)).
