## Pinia Store Architecture

 WeKnora uses **Pinia** for centralized state management in the Vue 3 frontend. The state layer is separated into domain-specific stores handling authentication, chat resources, settings, organization multi-tenancy, and editor subsystems.

## API Client and Request Interceptors

 
### Axios Instance Configuration

 All HTTP requests pass through a centrally configured Axios instance defined in `frontend/src/utils/request.ts`.

 
 - **Base URL:** Dynamically resolved via `getApiBaseUrl()` [frontend/src/utils/request.ts18](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/utils/request.ts#L18-L18).
 - **Default Headers:** 
 - `Content-Type: application/json` [frontend/src/utils/request.ts60](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/utils/request.ts#L60-L60)
 - `X-Request-ID`: Generated via `generateRandomString(12)` for request tracing [frontend/src/utils/request.ts61](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/utils/request.ts#L61-L61).
 - `Authorization`: Injected dynamically as `Bearer ${token}` from `localStorage` (skipped for explicit `Embed` tokens) [frontend/src/utils/request.ts71-83](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/utils/request.ts#L71-L83).
 - `X-Tenant-ID`: Injected from `weknora_selected_tenant_id` to enforce multi-tenant isolation across API calls [frontend/src/utils/request.ts97-102](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/utils/request.ts#L97-L102).

### Response Interceptor and Token Refresh Flow

 
 - The response interceptor unwraps successful HTTP status codes (`200-299`) and attaches a non-enumerable `$httpStatus` property to JSON payloads via `withHttpStatus()` [frontend/src/utils/request.ts127-133](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/utils/request.ts#L127-L133)
 - When an HTTP `401` or `403` error is encountered on non-public paths, the interceptor checks `originalRequest._retry` and invokes `refreshAccessTokenShared()` [frontend/src/utils/request.ts172-184](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/utils/request.ts#L172-L184).
 - Public authorization endpoints (`PUBLIC_AUTH_PATHS`) and embed token contexts bypass refresh logic to prevent unwanted redirection loops [frontend/src/utils/request.ts117-170](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/utils/request.ts#L117-L170).

## Streaming API Integration and SSE Data Flow

 
### The `useStream` Composable

 Real-time chat responses and agent event streams are managed by the `useStream` composable defined in `frontend/src/api/chat/streame.ts`.

 
 - **State Management:** Exposes reactive refs including `output`, `isStreaming`, `isLoading`, and `error` [frontend/src/api/chat/streame.ts28-34](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/api/chat/streame.ts#L28-L34).
 - **Request Payload Construction:** `startStream()` builds a structured JSON body containing the user query, knowledge base scopes (`knowledge_base_ids`), agent flags, multi-modal attachments, and `@mentioned` items [frontend/src/api/chat/streame.ts43-151](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/api/chat/streame.ts#L43-L151).
 - **Event Source Transport:** Utilizes `@microsoft/fetch-event-source` to maintain persistent SSE connections while forwarding authentication headers and `X-Tenant-ID` tracking parameters [frontend/src/api/chat/streame.ts1-154](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/api/chat/streame.ts#L1-L154).
