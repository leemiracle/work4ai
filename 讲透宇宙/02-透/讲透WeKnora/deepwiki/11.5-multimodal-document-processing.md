  WeKnora supports advanced multimodal document processing to enhance knowledge ingestion and retrieval by integrating image analysis, OCR, and Vision Language Model (VLM) capabilities. This page details the multimodal pipeline from document parsing, image extraction, asynchronous OCR/caption tasks, to multimodal chunk generation and retrieval-time context enrichment.

 
---

 
## Purpose and Scope

 This section explains how WeKnora processes multimodal documents containing images and scanned content by:

 
 - Extracting images and text from various document formats
 - Employing VLM-powered OCR and caption generation for images
 - Managing asynchronous task execution for multimodal enrichment
 - Integrating DocReader parsers as the initial extraction layer
 - Chunking and indexing multimodal content for retrieval
 - Enriching retrieval context with OCR/caption metadata dynamically
 
 It covers core components, data flows, key classes, and how multimodal processing complements WeKnora’s RAG system.

 
---

 
## 1. Document Parsing and Image Extraction

 Multimodal processing begins with document parsing, which transforms raw content into markdown text and extracts embedded images for enrichment. WeKnora supports multiple parser engines downstream of the upload process:

 
### DocReader Parsers

 The Python-based DocReader module provides `BaseParser` implementations for different file types, each extracting markdown text and image references:

 
 - **PDF Parser (`docreader/parser/pdf_parser.py`):**
 Uses pypdfium2 to analyze PDFs page-by-page, distinguishing native digital text pages from scanned image pages by image-area coverage ratio. Scanned pages are rendered to images with `image_source_type=scanned_pdf`, enabling OCR/VLM processing in Go.
 It also extracts embedded images from digital pages, filtering small logos/watermarks by size and frequency metrics.
 Flags such as `DOCREADER_PDF_FORCE_SCANNED` enable forcing all pages through OCR [docreader/parser/pdf_parser.py1-136](https://github.com/Tencent/WeKnora/blob/10973ed3/docreader/parser/pdf_parser.py#L1-L136)
 - **DOCX Parser (`docreader/parser/docx_parser.py`):**
 Processes DOCX files extracting text with markdown code blocks and converts inline images to base64-encoded references. Uses concurrency to handle large files efficiently and supports multimodal image extraction [docreader/parser/docx_parser.py111-187](https://github.com/Tencent/WeKnora/blob/10973ed3/docreader/parser/docx_parser.py#L111-L187)
 - **Web Parser (`docreader/parser/web_parser.py`):**
 Scrapes HTML web pages via Playwright with SSRF protection, extracting content using trafilatura or fallback text extraction. Converts to markdown with image inclusion [docreader/parser/web_parser.py150-188](https://github.com/Tencent/WeKnora/blob/10973ed3/docreader/parser/web_parser.py#L150-L188)
 - **Markdown Parser (`docreader/parser/markdown_parser.py`):**
 Normalizes tables and extracts images for markdown documents [docreader/parser/markdown_parser.py1-173](https://github.com/Tencent/WeKnora/blob/10973ed3/docreader/parser/markdown_parser.py#L1-L173)
 
 
### MinerUReader Integration

 The `MinerUReader` (Go) calls an external MinerU service for converting complex documents into enriched markdown with embedded base64 images. It supports hybrid modes combining pipeline, OCR, and VLM engines, returning markdown plus images. Image filtering excludes small icons before files are handed to the `ImageResolver` to save images in storage and unify image refs [internal/infrastructure/docparser/mineru_converter.go33-41](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/docparser/mineru_converter.go#L33-L41)

## 2. Image Resolution and Storage

 After parsing produces markdown with inline images or base64 blobs, the `ImageResolver` is responsible for:

 
 - Scanning markdown content for image references, including: 
 - `data:image` URIs and base64 blobs
 - HTML `<img>` tags embedded in markdown
 - Direct image URLs or resource links
 - Deduplicating images by filename or binary hash to avoid redundant storage
 - Uploading images to the tenant's configured `FileService` backend
 - Replacing local/base64 references with stable `provider://` URLs for the retrieval system
 
 This transformation occurs after parsing completes, converting the document into a form suitable for multimodal asynchronous processing [internal/infrastructure/docparser/image_resolver.go30-191](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/docparser/image_resolver.go#L30-L191)

## 3. Asynchronous Image Multimodal Processing

 Image multimodal enrichment is performed asynchronously via the `ImageMultimodalService` in Go, ensuring multimodal tasks do not block the main ingestion pipeline.

 
### Core Service (`internal/application/service/image_multimodal.go`)

 `ImageMultimodalService` implements the `TaskHandler` interface for `TypeImageMultimodal` tasks in the dedicated multimodal asynq queue:

 
 - Tasks contain references to the image chunk, knowledge ID, KB ID, URL, and flags enabling OCR and/or caption generation.
 - The service fetches or resolves the actual image bytes, using `FileService` or a resource catalog to locate storage.
 - It consults tenant and knowledge base configuration for OCR and caption enabling.
 - If OCR is enabled, it sends the image bytes and a detailed OCR prompt to the VLM for conversion to markdown text.
 - If captioning is enabled, it sends the image and a prompt requesting a concise description in the target language.
 - The service creates child chunks with types `ChunkTypeImageOCR` or `ChunkTypeImageCaption` linked to the parent knowledge chunk.
 - It enqueues or updates downstream tasks for indexing and finalizing multimodal results.
 - A span tracker is used for observability to trace multimodal stage lifecycles.
 
 The service also safely drops orphaned or user-cancelled knowledge processing to conserve queue capacity [internal/application/service/image_multimodal.go65-162](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/image_multimodal.go#L65-L162)

 
### VLM Prompts for OCR and Captioning

 Prompts guide the VLM models:

 
 - `vlmOCRPrompt`: Specifies instructions for extracting pure text content from document images in markdown, ignoring headers and irrelevant tags.
 - `vlmOCRScannedPDFPrompt`: Tailored for scanned PDFs preserving layout and hierarchy as markdown.
 - Caption prompt is dynamically built with the target language and optional instructions to generate concise image descriptions [internal/application/service/image_multimodal.go27-60](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/image_multimodal.go#L27-L60)

## 4. Vision Language Model (VLM) Integration

 The VLM interface abstracts interaction with external or self-hosted vision-language models used for OCR and captioning.

 
### Remote API VLM (`internal/models/vlm/remote_api.go`)

 
 - Implements calls to OpenAI-compatible completions with images converted to inline base64 Data URIs.
 - Supports Azure OpenAI and custom headers.
 - Default HTTP timeouts are 180s but configurable.
 - Handles batching multiple images and prompt context.
 - Returns text responses containing OCR results or captions.
 
 This integration powers the image multimodal pipeline [internal/models/vlm/remote_api.go42-165](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/vlm/remote_api.go#L42-L165)

## 5. Chunking and Multimodal Content Storage

 The OCR and caption outputs are saved as specialized **child chunks** linked under the main text chunk in the knowledge base. This allows:

 
 - Precise retrieval of image textual content as augmenting knowledge context
 - Indexing multimodal text for retrieval alongside native document text
 - Organizing multimodal sub-results by chunk types (`ChunkTypeImageOCR`, `ChunkTypeImageCaption`)
 
 Post-processing services such as `KnowledgePostProcessService` orchestrate the finalization, ensuring multimodal chunks are correctly generated and indexed after document parsing [internal/application/service/knowledge_post_process.go23-176](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge_post_process.go#L23-L176)

## 6. Retrieval-Time Multimodal Enrichment

 When retrieving relevant chunks for knowledge Q&A, the system dynamically attaches multimodal content for richer context:

 
 - Annotates text chunks with `<image_ocr>...</image_ocr>` or `<image_caption>...</image_caption>` tags containing the OCR or caption markdown.
 - The markdown image scanner parses image references robustly, handling escaped characters, nested parentheses, and angle bracket destinations.
 - This enrichment helps the LLM better understand and answer queries involving visual content.
 - The robust scanning logic comes from `markdown_image_scanner.go` which identifies valid image markdown regions even in complex cases [internal/infrastructure/docparser/markdown_image_scanner.go65-262](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/docparser/markdown_image_scanner.go#L65-L262)

## 7. Task Queue and Lifecycle Management

 All multimodal image processing tasks run within the asynq queue system:

 
 - Tasks of type `TypeImageMultimodal` are enqueued per image chunk.
 - The `asynqTaskInspector` allows inspection and cancellation of pending tasks referencing specific knowledge IDs.
 - Cancel API calls use `CancelTasksForKnowledge` to purge multimodal tasks on knowledge deletion or cancel events, preventing stranded workers [internal/router/task_inspector.go109-124](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/task_inspector.go#L109-L124)
 - The frontend runtime queue panel (`RuntimeQueues.vue`) shows live worker pool metrics for the `QueueMultimodal` queue which processes these long-running VLM tasks [frontend/src/views/system/RuntimeQueues.vue100-129](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/system/RuntimeQueues.vue#L100-L129)
 
 These queuing patterns preserve system responsiveness and resource isolation.

## Summary

 WeKnora’s multimodal document processing pipeline tightly integrates advanced Python-based parsing with Go-based asynchronous orchestration, image storage resolution, and VLM-powered OCR/caption inference. This enables rich, searchable, and contextually aware knowledge bases supporting documents with complex images and scanned pages. The modular architecture allows pluggable VLM backends and multi-stage chunk processing while maintaining system scalability and observability.
