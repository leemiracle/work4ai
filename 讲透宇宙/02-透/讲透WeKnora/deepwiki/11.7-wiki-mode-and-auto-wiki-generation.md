## Purpose and Scope

 Wiki Mode in WeKnora transforms standard RAG knowledge bases into a structured, interlinked encyclopedia. It uses an automated pipeline powered by Large Language Models (LLMs) to extract entities, concepts, and summaries from ingested documents, creating a persistent, compounding, and richly interlinked knowledge artifact that evolves continuously as new data arrives [internal/types/wiki_page.go188-210](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/wiki_page.go#L188-L210)

## Auto-Wiki Ingestion Pipeline

 The auto-wiki generation pipeline is triggered asynchronously after document uploads or updates and processes batches of pending operations for a knowledge base (KB). It follows a Map-Reduce style workflow integrated tightly with Redis-backed queues and optimistic concurrency control to handle high volumes and ensure global consistency.

 
### Data Flow and Task Scheduling

 
 - **Enqueue Pending Ops**
 When a document is ingested or updated, a pending operation for wiki ingestion is enqueued into the `task_pending_ops` table under the task type `wiki:ingest` [internal/application/service/wiki_ingest.go115-117](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/wiki_ingest.go#L115-L117)
 - **Batch Task Triggering & Debouncing**
 The system schedules an Asynq delayed task with the type `types.TypeWikiIngest`, initially delayed by 30 seconds (`wikiIngestDelay`) to debounce rapid uploads and batch work together [internal/application/service/wiki_ingest.go126-128](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/wiki_ingest.go#L126-L128) If upstream rate limits occur, a longer backoff of 60 seconds (`wikiRateLimitBackoff`) is used to throttle retries [internal/application/service/wiki_ingest.go136-143](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/wiki_ingest.go#L136-L143)
 - **Batch Claiming & Concurrency Control**
 In standard Redis mode, multiple ingest batches for the same KB can run in parallel. The record-level row claiming system in `task_pending_ops` ensures no two workers process the same items simultaneously. Claims stale beyond 90 minutes (`wikiClaimStaleAfter`) are recoverable to handle crashed workers. Per-slug locking (`wikiSlugLockPrefix`) prevents conflicting writes on the same wiki page slug [internal/application/service/wiki_ingest.go42-61](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/wiki_ingest.go#L42-L61) Lite mode serializes to one batch per KB using an in-process lock map.
 - **Map Phase: LLM-driven Extraction**
 Each claimed document is submitted to the LLM agent with `WikiKnowledgeExtractPrompt` to simultaneously extract entities and concepts in JSON format, enforcing slug stability by reusing existing slugs where possible [internal/agent/prompts_wiki.go87-113](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/prompts_wiki.go#L87-L113)
 - **Batch Taxonomy Planning**
 `planBatchTaxonomy` uses `WikiTaxonomyPlanPrompt` to assign folder/directory paths to each extracted entity and concept in the batch, aiming for a coherent, reusable directory structure that preserves existing folder labels and creates broad new folders as needed [internal/agent/prompts_wiki.go3-46](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/prompts_wiki.go#L3-L46)
 - **Reduce Phase: Page Materialization & Cross-Linking**
 The extracted and categorized knowledge is merged into the existing wiki repository via `wikiPageService`. Pages are created/updated with their content, links, metadata, and source references [internal/application/service/wiki_ingest_batch.go190-208](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/wiki_ingest_batch.go#L190-L208)
 - **Post-Processing & Follow-up Scheduling**
 After ingesting a batch, consumed ops are deleted from `task_pending_ops`. If remaining rows exist, a follow-up batch task is enqueued with a short debounce delay to progressively drain the backlog [internal/application/service/wiki_ingest_batch.go25-65](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/wiki_ingest_batch.go#L25-L65)
 
 
### Concurrency and Reliability Features

 
| Mechanism | Description |
|---|---|
| Row Claiming | Batches claim document ops from pending queue atomically, avoiding duplicate processing internal/application/service/wiki_ingest.go44-61 |
| Per-Slug Locking | Per-slug Redis locks enforce that concurrent batches cannot overwrite the same page simultaneously, with a 5-minute TTL internal/application/service/wiki_ingest.go58-98 |
| Claim Stale Timeout | Claims older than 90 minutes are considered abandoned and may be re-claimed by new workers to handle crashes/graceful recovery internal/application/service/wiki_ingest.go49-56 |
| In-Flight Caps | Limits the concurrent batches per KB slot set to default 4 workers, preserving cluster throughput fairness internal/application/service/wiki_ingest.go103-123 |
| Rate Limit Backoff | Detects HTTP 429 errors and applies a longer follow-up delay of 60 seconds to avoid request storms internal/application/service/wiki_ingest.go136-143 |
| Lite Mode Locking | Uses an in-process map lock per KB to serialize all batches for simpler deployments internal/application/service/wiki_ingest.go45-48 |

## WikiBrowser UI and Visualization

 The Frontend implements a sophisticated WikiBrowser UI component (`WikiBrowser.vue`) that enables users to explore their wiki knowledge base in multiple modes [frontend/src/views/knowledge/wiki/WikiBrowser.vue1-130](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/wiki/WikiBrowser.vue#L1-L130)

 
### Dual View Modes

 
 - **Directory Mode**: Classic hierarchical directory listing of wiki pages comprised of folder trees and paginated page lists.
 - **Graph View Mode**: Interactive force-directed graph visualization displaying wiki pages as nodes and their cross-links as edges. Supports: 
 - **Overview Mode**: Displays top-N important pages, filtered by page type such as "entity", "concept", or "summary" [internal/types/interfaces/wiki_page.go80-88](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/wiki_page.go#L80-L88)
 - **Ego Mode**: Focuses the graph on a single "center" page and its immediate neighborhood, supporting iterative exploration [frontend/src/views/knowledge/wiki/WikiBrowser.vue94-102](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/wiki/WikiBrowser.vue#L94-L102)
 
 
### UI Features & Filtering

 
 - Legend overlays allow toggling visibility by node types: Summary, Entity, Concept, Synthesis, and Comparison pages [frontend/src/views/knowledge/wiki/WikiBrowser.vue50-77](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/wiki/WikiBrowser.vue#L50-L77)
 - A search overlay triggers remote search queries to find specific wiki pages and center the graph on the results [frontend/src/views/knowledge/wiki/WikiBrowser.vue9-18](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/wiki/WikiBrowser.vue#L9-L18)
 - Status badges indicate pending indexing or linting issues in the graph [frontend/src/views/knowledge/wiki/WikiBrowser.vue38-47](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/wiki/WikiBrowser.vue#L38-L47)

## Wiki Page Management

 Wiki pages are persisted records representing core wiki documents generated by the ingestion pipeline or edited manually. They are managed by `wikiPageService` [internal/application/service/wiki_page.go43-67](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/wiki_page.go#L43-L67)

 
### WikiPage Schema and Key Types

 Wiki pages are stored in the `wiki_pages` table with the following core fields [internal/types/wiki_page.go188-210](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/wiki_page.go#L188-L210):

 
| Field | Description |
|---|---|
| ID | Unique UUID for the wiki page |
| Slug | Unique string slug of the page, URL-friendly and hierarchical (e.g., entity/tencent) |
| Title | Human-readable page title |
| Content | Markdown content body, may include `[[slug |
| Summary | Concise summary snippet of the page |
| PageType | One of summary, entity, concept, index, synthesis, or comparison |
| Aliases | Alternate names for auto-link detection |
| SourceRefs | IDs referencing original knowledge base documents feeding this page |
| FolderID | The parent folder organizing this page in the wiki browser |
| CategoryPath | A cached breadcrumb representing the folder hierarchy, limited to 3 levels (WikiCategoryMaxDepth) |
| WikiPath | Materialized path string with page type and breadcrumb path leg joined for sorting and display |
| Version | Integer version for optimistic locking and user-visible content revisions |
| Status | Published, Draft, or Archived |

 
### Versioning and Update Policies

 
 - The `version` field is incremented **only** when user-visible content fields change: Title, Content, Summary, PageType, or Status. This avoids noise from background bookkeeping updates [internal/application/service/wiki_page.go113-120](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/wiki_page.go#L113-L120)
 - `UpdatePage` methods write changes atomically with optimistic locking via `UpdateWithRevision` and snapshot previous versions in a separate `wiki_page_revisions` table [internal/application/repository/wiki_page.go108-130](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/wiki_page.go#L108-L130)
 - For background writes like injecting auto-links or cleaner metadata sync (`UpdatePageMeta`), the version remains unchanged to prevent false edit notifications.
 
 
### Link Extraction and Parsing

 Outbound wiki links `[[slug]]` or `[[slug|Display Title]]` are parsed from content and updated on page creation or update (`parseOutLinks`). Inline LLM chunk citation markers like `[c003]` are stripped before storage via `stripWikiInlineChunkCitations` so readers see clean Markdown [internal/application/service/wiki_page.go22-41](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/wiki_page.go#L22-L41)

## Link Maintenance and Linting

 Robust link maintenance ensures wiki coherence by managing outbound and inbound links and repairing dead or broken references.

 
### Key Features

 
 - **Cross-Link Injection**: `InjectCrossLinks` scans content and detects references to other wiki page titles or aliases, converting them into proper `[[slug|title]]` wiki links automatically [internal/types/interfaces/wiki_page.go93-95](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/wiki_page.go#L93-L95)
 - **Dead Link Cleanup**: The system periodically identifies and cleans references to pages that have been archived or deleted via `cleanDeadLinks` [internal/application/service/wiki_page.go193-195](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/wiki_page.go#L193-L195)
 - **Citation Stripping**: Machine-generated chunk citations are removed before content is persisted [internal/application/service/wiki_page.go31-41](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/wiki_page.go#L31-L41)
 - **RepairContentLinks**: Used by the agent and ingest pipeline, this function attempts best-effort rewriting of dead `[[slug]]` references into valid targets by consulting the current wiki repository [internal/types/interfaces/wiki_page.go42-47](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/wiki_page.go#L42-L47)
