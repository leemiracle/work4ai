  Platform-specific adapters are the concrete implementations of the `im.Adapter` interface, enabling WeKnora to communicate with various Instant Messaging (IM) platforms. These adapters handle the translation between platform-specific payloads (JSON/XML) and the unified `im.IncomingMessage` structure [internal/im/adapter.go48-85](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/adapter.go#L48-L85) as well as the delivery of responses via webhooks or long-running WebSocket connections.

 
---

 
## 1. Overview of Adapter Architecture

 Each platform adapter consists of a Factory, an Adapter for HTTP/REST interactions, and optionally a `LongConnClient` for WebSocket-based event subscriptions. The system uses a supervisor pattern to manage the lifecycle of these long-lived connections, ensuring they are proactively recycled [internal/im/supervisor.go10-16](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/supervisor.go#L10-L16)

## 2. Feishu and Lark

 Feishu (飞书) and Lark share the same API surface across isolated clouds (`open.feishu.cn` and `open.larksuite.com`), served by a unified implementation governed by a region selector [internal/im/feishu/adapter.go1-5](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/feishu/adapter.go#L1-L5)

 
 - **`Adapter` struct**: Manages credentials (`appID`, `appSecret`, `verificationToken`, `encryptKey`) and token caching with mutex synchronization [internal/im/feishu/adapter.go52-70](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/feishu/adapter.go#L52-L70)
 - **Signature Verification**: Validates webhook request tokens and handles decryption [internal/im/feishu/adapter.go193-211](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/feishu/adapter.go#L193-L211)
 - **Streaming**: Implements `im.StreamSender` and `im.FullOutputProgressSender` via Feishu CardKit [internal/im/feishu/adapter.go40-45](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/feishu/adapter.go#L40-L45)
 - **`LongConnClient`**: Manages WebSocket connections via `larkws.Client` with automatic reconnection and event dispatching [internal/im/feishu/longconn.go19-60](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/feishu/longconn.go#L19-L60)

## 3. WeCom (企业微信)

 WeCom provides Webhook Mode and Intelligent Bot (WebSocket) Mode.

 
 - **`WebhookAdapter`**: Handles encrypted XML callbacks, validating signatures via `token` and `encodingAESKey` using AES-CBC and SHA1 [internal/im/wecom/webhook_adapter.go83-168](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/wecom/webhook_adapter.go#L83-L168)
 - **`LongConnClient`**: Connects to `wss://openws.work.weixin.qq.com` to receive `aibot_msg_callback` frames and respond via `aibot_respond_msg` [internal/im/wecom/longconn.go7-37](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/wecom/longconn.go#L7-L37)
 - **Streaming Protocol**: Uses replace-based streaming where each chunk replaces the previous message text, managed via `streamBufs` [internal/im/wecom/longconn.go142-146](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/wecom/longconn.go#L142-L146)

## 4. DingTalk (钉钉)

 DingTalk integration supports webhook callbacks and the DingTalk Stream SDK over WebSockets.

 
 - **`Adapter`**: Implements `im.Adapter`, `im.StreamSender`, and `im.FileDownloader` [internal/im/dingtalk/adapter.go41-45](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/dingtalk/adapter.go#L41-L45)
 - **Message Parsing**: Maps payloads to `im.IncomingMessage` supporting text, files, images, and rich text elements [internal/im/dingtalk/adapter.go122-196](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/dingtalk/adapter.go#L122-L196)
 - **Streaming Cards**: Utilizes AI card streaming when a `cardTemplateID` is configured, enforcing a minimum update interval of 500ms [internal/im/dingtalk/adapter.go35-51](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/dingtalk/adapter.go#L35-L51)

## 6. Common Features Across Adapters

 
### Content Sanitization and Streaming Holdback

 Before delivery, answers undergo sanitization in `im` service functions:

 
 - **Citation Stripping**: Removes `<kb .../>` and `<web .../>` tags via `stripIMCitationTags` [internal/im/service.go70-79](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/service.go#L70-L79)
 - **Image XML Cleanup**: Converts `<image>` blocks back to Markdown via `stripImageXMLTags` [internal/im/service.go81-99](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/service.go#L81-L99)
 - **URL Rewriting**: Converts internal storage paths into HTTP URLs via `storageurl.Rewrite` [internal/im/service.go101-110](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/service.go#L101-L110)
 - **Streaming Holdback**: `holdbackCutoff` prevents flushing partial XML tags or URL fragments across stream intervals [internal/im/service.go115-141](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/service.go#L115-L141)
