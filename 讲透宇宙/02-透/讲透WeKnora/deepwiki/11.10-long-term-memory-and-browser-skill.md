## Purpose and Scope

 This document details two advanced subsystems in WeKnora: the cross-session long-term memory subsystem (responsible for persistent user profiling, background extraction, consolidation, vector recall, and recall traces) and the local `BrowserSkill` Chrome extension integration (enabling native browser automation, task previews, human-in-the-loop handoffs, and tab borrowing).

## 1. Cross-Session Long-Term Memory Architecture

 The long-term memory subsystem allows agents to remember user traits, workspace preferences, facts, tasks, and recurrent interests across different sessions and conversations. Memory operates under strict multi-tenant isolation defined by workspace `TenantID` and user `SubjectID` pairs (`MemoryScope`) [internal/types/interfaces/memory.go11-22](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/memory.go#L11-L22)

 
### Memory Kinds and Lifecycles

 Memories are classified into five distinct kinds [internal/types/memory.go21-35](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/memory.go#L21-L35):

 
 - `profile`: Stable personal traits injected into the resident block.
 - `preference`: Workspace or user formatting/interaction rules injected into the resident block.
 - `interest`: Derived topics of ongoing inquiry that condition query recall.
 - `fact`: Situational factual statements pulled in when matching a specific query.
 - `task`: Situational action items or goals pulled in contextually.
 
 Resident memories (`profile`, `preference`, `interest`) form an always-injected resident block, whereas situational memories (`fact`, `task`) use vector and lexical retrieval [internal/types/memory.go124-128](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/memory.go#L124-L128)

## 2. Memory Storage, Extraction, and Vector Recall

 The persistence layer manages memory subjects, items, extraction extraction sessions, and tombstones (`memory_subjects`, `memory_items`, `memory_extraction_sessions`) [internal/database/migration_sqlite_versioned_schema_test.go18-29](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/database/migration_sqlite_versioned_schema_test.go#L18-L29)

 
### Repository Contracts and Scoping

 Every database operation in `memoryRepository` enforces workspace isolation via `scoped(ctx, scope)` [internal/application/repository/memory.go32-35](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/memory.go#L32-L35)

 
 - `EnsureSubject`: Creates or retrieves a user's memory subject safely using `clause.OnConflict` upsert logic [internal/application/repository/memory.go51-79](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/memory.go#L51-L79)
 - `SaveItem`: Atomically inserts and resolves active/pending replacement chains (`replaces_id`) [internal/types/memory.go35](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/memory.go#L35-L35)
 - `AddTombstone`: Records explicitly forgotten statements using cryptographic fingerprints, preventing automatic re-derivation without storing raw sensitive transcripts [internal/types/interfaces/memory.go108-122](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/memory.go#L108-L122)

## 3. Local BrowserSkill Chrome Extension Integration

 WeKnora integrates with an unmodified official `BrowserSkill` daemon and a paired Chrome extension via the `local_browser` tool layer (`internal/browserskill`) [internal/browserskill/manager.go1-3](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/browserskill/manager.go#L1-L3)

 
### Connection Management and WebSocket Protocol

 The `Manager` struct owns transient WebSocket connections (`device`) associated with a user `Scope` [internal/browserskill/manager.go34-111](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/browserskill/manager.go#L34-L111)

 
 - **Authentication**: Uses a credential-bearing WebSocket subprotocol (`AuthProtocol`) with temporary pairing links [internal/browserskill/manager.go27-31](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/browserskill/manager.go#L27-L31)
 - **Task Isolation**: Manages independent `task` instances per chat session, tracking active actions, elapsed times, page URLs, error states, and interruption markers [internal/browserskill/manager.go61-81](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/browserskill/manager.go#L61-L81)
 
 
### Frontend Preview Component

 The Vue frontend renders live browser state using `BrowserTaskPreview.vue`, which polls the `/api/v1/sessions/{sessionId}/local-browser` endpoint, supports picture-in-picture (`DocumentPictureInPicture`), and provides drag-and-drop floating preview controls [frontend/src/views/chat/components/BrowserTaskPreview.vue1-60](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/chat/components/BrowserTaskPreview.vue#L1-L60)

## 4. Tool Execution, Handoffs, and Error Recovery

 The agent tool interface `BrowserSkillTool` exposes methods (`navigate`, `click`, `fill`, `observe`, `screenshot`, `request_help`, `tab_borrow`, `tab_select`) defined in `browserToolDescription` [internal/agent/tools/browserskill_prompt.go24-90](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/tools/browserskill_prompt.go#L24-L90)

 
### Human-in-the-Loop Handoffs (`request_help`)

 When encountering logins, CAPTCHAs, or SMS verifications, agents invoke `request_help` with a prompt and target `tab_id` [internal/agent/tools/browserskill_prompt.go49-62](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/tools/browserskill_prompt.go#L49-L62)

 
 - The conversation preview displays the help prompt.
 - The user completes the action in the browser extension overlay and confirms completion.
 - The tool receives outcome results (`completed`, `continued`, `cancelled`, `timed_out`) before the agent resumes observation [internal/agent/tools/browserskill_result_test.go13-36](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/tools/browserskill_result_test.go#L13-L36)
 
 
### Error Handling and Recovery Hints

 When CDP commands or tool executions fail (e.g., `not_found`, `permission_denied`, `timeout`), `browserToolFailure` decorates the error output with structured recovery hints (such as requesting fresh references or checking active dialogs) so the LLM can self-correct without crashing the conversation loop [internal/agent/tools/browserskill_result_test.go62-87](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/tools/browserskill_result_test.go#L62-L87)
