## Purpose and Scope

 This page documents the WeKnora system initialization and configuration process. It covers startup infrastructure, Ollama local model management, AI model registration, the knowledge base setup wizard, document chunking and storage configuration, and graph extraction setup.

 WeKnora uses a layered architecture:

 
 - Deployment environment variables and Docker Compose launch system services [docker-compose.yml1-160](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L1-L160).
 - Ollama hosts local LLM models with a dedicated API service [internal/handler/initialization.go29](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L29-L29).
 - Backend services provide model and knowledge base management via `InitializationHandler` and `ModelHandler` `[internal/handler/initialization.go:56-94]`, [internal/handler/model.go25-37](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/model.go#L25-L37).
 - Frontend components provide rich UI wizards to configure knowledge bases and models `[frontend/src/views/knowledge/KnowledgeBaseEditorModal.vue:15-35]`, [frontend/src/components/ModelEditorDialog.vue1-7](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/components/ModelEditorDialog.vue#L1-L7).

## Initialization Workflow Overview

 WeKnora’s initialization is composed of three main stages managed by the backend and surfaced to users via frontend UI:

 
 - **Infrastructure Setup**

 
 - Launch core services like PostgreSQL, Redis, DocReader, Ollama via Docker Compose using configured `.env` files [docker-compose.yml1-160](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L1-L160).
 - The system automatically performs database migrations on startup if `AUTO_MIGRATE` is enabled [docker-compose.yml89-90](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L89-L90).
 - **Model Registration and Ollama Setup**

 
 - Register models via `ModelHandler` and `ModelService`: LLMs, embedding engines, reranking models [internal/handler/model.go66-123](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/model.go#L66-L123).
 - If Ollama is used, connect and manage local Ollama models through `OllamaService` [internal/handler/initialization.go89](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L89-L89).
 - Users can remotely check Ollama service status and download models asynchronously via UI [frontend/src/api/initialization/index.ts198-209](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/api/initialization/index.ts#L198-L209).
 - **Knowledge Base Configuration**

 
 - Configure each knowledge base using `KBModelConfigRequest` which includes: 
 - AI models for LLM, embedding, VLM, ASR [internal/handler/initialization.go98-101](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L98-L101).
 - Document chunking and splitting strategies [internal/handler/initialization.go104-121](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L104-L121).
 - Storage provider selection (`local`/`minio`/`cos`) [internal/handler/initialization.go129-130](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L129-L130).
 - Optional features like graph extraction and question generation [internal/handler/initialization.go133-147](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L133-L147).

## Model Management and Registration

 WeKnora supports heterogeneous AI models registered via `ModelService` (`internal/types/model.go`) and handled by `ModelHandler` (`internal/handler/model.go`). Supported model types include Chat LLMs, Embedding models, Reranking models, Vision Language Models (VLM), and ASR models `[internal/handler/initialization.go:98-101]`, [internal/types/model.go14-23](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/model.go#L14-L23).

 
### Model Sources

 
 - **Local Ollama Models:** Hosted locally, managed through `OllamaService` [internal/handler/initialization.go29](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L29-L29).
 - **Remote Providers:** OpenAI, Azure, and others configured via provider strings and registered through `CreateModel` in [internal/handler/model.go66-123](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/model.go#L66-L123).

## Document Chunking and Storage Configuration

 The RAG knowledge ingestion pipeline requires configuration of document chunking and persistent storage.

 
### Chunking Configuration

 
 - **Chunk Size & Overlap:** Define the size of document chunks and their overlap [internal/handler/initialization.go105-106](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L105-L106).
 - **Splitting Strategy:** `"auto"`, `"heading"`, `"heuristic"`, or `"legacy"` to adjust chunk boundaries intelligently [internal/handler/initialization.go117](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L117-L117).
 - **Parent-Child Chunking:** Optional parent chunking creates a multi-level index structure [internal/handler/initialization.go109-111](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L109-L111).
 - **Token Limits:** Approximate token budget per chunk can be specified [internal/handler/initialization.go118](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L118-L118).
 
 
### Storage Engines

 
 - Supports multiple backends managed via `StorageEngineSettings.vue` and `KBStorageSettings.vue` `[frontend/src/views/settings/StorageEngineSettings.vue:1-30]`, [frontend/src/views/knowledge/settings/KBStorageSettings.vue33-64](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/settings/KBStorageSettings.vue#L33-L64).
 - Configured per knowledge base through the `StorageProvider` and `StorageBackendId` fields [internal/handler/initialization.go129-130](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L129-L130).

## Ollama Service Setup and Model Management

 WeKnora integrates Ollama local LLM hosting, enabling users to manage models installed on the Ollama server [internal/handler/initialization.go29](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L29-L29).

 
### Ollama Model Download and Status Tracking

 
 - The backend uses a global map `downloadTasks` with a read-write mutex to track model download status [internal/handler/initialization.go50-53](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L50-L53).
 - `OllamaService` acts as a client to the Ollama API, enabling model list, status checks, and downloads [internal/handler/initialization.go63](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L63-L63).

## Graph Extraction Configuration

 WeKnora supports knowledge graph extraction (GraphRAG) during document ingestion, configured via `GraphSettings.vue` [frontend/src/views/knowledge/settings/GraphSettings.vue30-43](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/settings/GraphSettings.vue#L30-L43) and managed under `NodeExtract` in [internal/handler/initialization.go133-140](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L133-L140).

 
 - Users can enable entity-relation extraction and define tags, nodes, and relations schema [internal/handler/initialization.go136-138](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L136-L138).
 - The configuration is part of the `KBModelConfigRequest` struct [internal/handler/initialization.go133-140](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L133-L140).
