  This page documents the internal event bus used for inter-component communication, the Server-Sent Events (SSE) mechanism that streams responses to the browser, and the plugin-based chat pipeline that processes queries through stages like query understanding, retrieval, and generation.

## 1. Event Bus System

 WeKnora utilizes a centralized `EventBus` to decouple high-level application logic from low-level communication protocols (like SSE). This is primarily used within the agent execution loop and the chat pipeline to broadcast progress updates, tool execution results, and final LLM answers.

 
### Key Components

 
 - **`EventBus`**: A pub-sub implementation defined at [internal/types/chat_manage.go141](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/chat_manage.go#L141-L141) that allows different parts of the system to subscribe to specific event types `[internal/types/chat_manage.go:141-141]`.
 - **`AgentStreamHandler`**: Subscribes to events on a dedicated `EventBus` per request and forwards them to the client via a `StreamManager`. It tracks event durations and handles superseded answer segments from non-terminal rounds `[internal/handler/session/agent_stream_handler.go:32-47]`.
 - **`EventManager`**: Manages the orchestration of events within the chat pipeline plugins `[internal/application/service/session.go:119-119]`.
 
 
### Event Types

 The system defines several event types to track the lifecycle of a chat request:

 
 - `IntentKBSearch`: Triggered when the pipeline identifies a knowledge base search intent `[internal/types/chat_manage.go:87-87]`.
 - `IntentWebSearch`: Triggered when the pipeline identifies a web search intent `[internal/types/chat_manage.go:88-88]`.
 - `EventAgentThought`: Emitted when the agent is thinking `[internal/handler/session/agent_stream_handler.go:140-140]`.
 - `EventAgentToolCall`: Emitted when the agent calls a tool `[internal/handler/session/agent_stream_handler.go:141-141]`.
 - `EventAgentToolResult`: Emitted with the result of a tool call `[internal/handler/session/agent_stream_handler.go:142-142]`.
 - `EventAgentReferences`: Emitted when knowledge references are found `[internal/handler/session/agent_stream_handler.go:144-144]`.
 - `EventAgentFinalAnswer`: Emitted when the agent provides a final answer `[internal/handler/session/agent_stream_handler.go:148-148]`.
 - `EventAgentComplete`: Emitted when the agent's task is complete `[internal/handler/session/agent_stream_handler.go:152-152]`.
 - `EventError`: Emitted when an error occurs `[internal/handler/session/agent_stream_handler.go:150-150]`.
 - `EventSessionTitle`: Emitted when a session title is generated `[internal/handler/session/agent_stream_handler.go:151-151]`.

## 2. Chat Pipeline and Pipeline States

 The chat pipeline is a modular system where a request is passed through a sequence of plugins. Each request is encapsulated in a `ChatManage` object, which serves as the primary data carrier.

 
### ChatManage Structure

 `ChatManage` integrates three core sub-structures:

 
 - **`PipelineRequest`**: Immutable configuration set at the entry point, including `SessionID`, `Query`, `KnowledgeBaseIDs`, and model parameters like `ChatModelID` `[internal/types/chat_manage.go:5-76]`.
 - **`PipelineState`**: Mutable intermediate data updated by plugins, such as `RewriteQuery`, `Intent`, `SearchResult`, and `RenderedContexts` `[internal/types/chat_manage.go:113-137]`.
 - **`PipelineContext`**: Runtime handles like the `EventBus` and `MessageID` `[internal/types/chat_manage.go:139-144]`.

## 3. Streaming and Event Architecture

 WeKnora uses a plugin-based execution model where each stage of the RAG or Agent process can emit events.

 
### Knowledge QA Pipeline Flow

 
 - **Request Parsing**: The `Handler` parses the incoming JSON into a `qaRequestContext` `[internal/handler/session/qa.go:125-145]`.
 - **Target Resolution**: Knowledge bases and models are resolved based on the session and agent configuration `[internal/handler/session/qa.go:38-93]`.
 - **SSE Subscription**: The `AgentStreamHandler` subscribes to the request's `EventBus` to capture thought chunks, tool calls, and references `[internal/handler/session/agent_stream_handler.go:136-157]`.
 
 
### Server-Sent Events (SSE)

 The frontend uses `fetchEventSource` [frontend/src/api/chat/streame.ts1](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/api/chat/streame.ts#L1-L1) to establish an SSE connection.

 
 - **`setSSEHeaders`**: Sets standard SSE headers for `Content-Type`, `Cache-Control`, `Connection`, and `X-Accel-Buffering` `[internal/handler/session/helpers.go:181-187]`.
 - **`buildStreamResponse`**: Constructs a `types.StreamResponse` from an `interfaces.StreamEvent`, including special handling for `agent_query` and `references` `[internal/handler/session/helpers.go:190-222]`.
 - **Resource URL Rewriting**: The `resource_urls` query parameter allows clients to request public, directly loadable URLs for internal `resource://` handles. This is handled by `storageurl.StreamRewriter` `[internal/handler/session/qa.go:68-71]`.

## 4. Session and Message Lifecycle

 Events in the pipeline are closely tied to the persistence of sessions and messages.

 
 - **Session Scoping**: Sessions are scoped to users or tenants. The `sessionService` honors the caller's per-user scope while providing an Admin+ read fallback for tenant channel sessions `[internal/application/service/session.go:62-101]`.
 - **Last Request State**: To allow the UI to restore context, the system persists the `SessionLastRequestState` (agent, model, and KB selections) on every successful QA interaction `[internal/types/interfaces/session.go:31-36]`.
 - **Agent Segment Accumulation**: The `AgentStreamHandler` uses `answerSegment` to track streamed content. If a non-terminal round streams a preamble (e.g., "Let me search...") but then calls a tool, that segment is marked as `superseded` and excluded from the final persisted message `[internal/handler/session/agent_stream_handler.go:76-103]`.

## 5. Multi-Turn and History Management

 WeKnora does not use a separate cross-turn cache layer for conversation history. Instead, it rebuilds history from the `messages` table on demand during chat pipeline execution `[internal/application/service/session.go:109-112]`.

 
 - **History Loading**: History is loaded from the message repository and passed into the `ChatManage` state `[internal/types/chat_manage.go:113-117]`.
 - **Intent Classification**: The pipeline classifies query intent (e.g., `IntentKBSearch`, `IntentWebSearch`, `IntentGreeting`) to determine if retrieval stages are necessary `[internal/types/chat_manage.go:83-109]`.
 - **Retrieval Logic**: The `NeedsRetrieval()` function checks the classified intent and `WebSearchEnabled` flag to decide whether to run search and rerank plugins `[internal/types/chat_manage.go:155-164]`.
