  This document describes WeKnora's session management system, which handles conversation lifecycle, context storage, message persistence, scoping, and title generation across multi-turn interactions. Sessions serve as the core entity tracking user conversations with knowledge bases and agent pipelines.

 
## Purpose and Scope

 The session and context management subsystem is responsible for:

 
 - **Session Lifecycle**: Creating, retrieving, updating, and deleting conversation sessions with tenant and principal-level isolation [internal/application/service/session.go62-101](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session.go#L62-L101)
 - **Conversation History**: Managing durable storage and paginated retrieval of chat turns in the `messages` table via `messageService` [internal/application/service/message.go131-159](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/message.go#L131-L159)
 - **Context Storage & Windowing**: Handling token limits, sliding window compression, and message history summarization via `ChatManage` and pipeline states [internal/types/chat_manage.go111-137](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/chat_manage.go#L111-L137)
 - **State Persistence**: Storing input-bar states (`LastRequestState`) in session records to restore UI agent/model configurations [internal/types/interfaces/session.go31-36](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/session.go#L31-L36)
 - **Title Generation**: Automatically summarizing conversation contexts into descriptive session titles synchronously or asynchronously via `SessionService` [internal/types/interfaces/session.go52-58](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/session.go#L52-L58)

## Session Data Architecture and Principal Scoping

 Sessions are stored in PostgreSQL (`sessions` table) and associated with messages in the `messages` table [internal/application/service/session.go112-141](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session.go#L112-L141) Multi-tenant and multi-user security is enforced through `tenant_id` and `user_id` scopes, where `user_id` captures Web console accounts, API keys, or embedded visitor principals evaluated by `loadSessionForRead` [internal/application/service/session.go62-101](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session.go#L62-L101)

 
| Data Structure | Storage Layer | Purpose & Scope | Retention |
|---|---|---|---|
| types.Session | PostgreSQL (sessions) | Persists session metadata, title, pinning status, and request configurations internal/types/interfaces/session.go73-105 | Until explicit deletion |
| types.Message | PostgreSQL (messages) | Durable storage of user/assistant utterances, token counts, and attachments internal/application/repository/message.go27-125 | Until session deletion |
| Principal | Runtime Context | Identifies the terminal caller (PrincipalIMUser, PrincipalAPITenant, PrincipalEmbedSession) internal/application/service/session.go34-55 | Request lifetime |

## Session Lifecycle and Repository Operations

 Sessions transition through creation, active querying, updating, and cleanup phases managed by `sessionService` and enforced by `SessionRepository` [internal/application/service/session.go108-141](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session.go#L108-L141)

 
### Creation and Scoping

 When a session is created, `sessionUserIDFromContext` determines the ownership scope based on the active principal [internal/application/service/session.go22-24](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session.go#L22-L24)

 
### Retrieval and Tenant Isolation

 Repository methods such as `Get`, `GetByTenantID`, and `Update` enforce that queries match both the workspace `tenant_id` and the caller's owner scope [internal/types/interfaces/session.go73-105](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/session.go#L73-L105) Admin users or authorized channel handlers may bypass specific user constraints when inspecting external channels via `runtimeMayBypassAdminConsoleRead` [internal/application/service/session.go26-55](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session.go#L26-L55)

## Context Management and Compression Strategies

 To respect LLM token windows during multi-turn chats, WeKnora manages context using `ChatManage` and pipeline state structures [internal/types/chat_manage.go111-137](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/chat_manage.go#L111-L137)

 
### Context Representation

 
 - `PipelineRequest`: Holds immutable configurations set once per request (max rounds, retrieval targets, model IDs) [internal/types/chat_manage.go5-76](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/chat_manage.go#L5-L76)
 - `PipelineState`: Holds mutable intermediate data including rewrite queries, classified intents, and loaded conversation history (`History`) [internal/types/chat_manage.go111-137](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/chat_manage.go#L111-L137)
 - `AgentStreamHandler`: Manages real-time event streaming, answer segment accumulation, and tool execution tracing [internal/handler/session/agent_stream_handler.go32-69](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/session/agent_stream_handler.go#L32-L69)

## Title Generation

 Sessions are initially created without descriptive titles. Titles are synthesized automatically from initial conversation turns.

 
### Implementation and Asynchronous Execution

 
 - `GenerateTitle`: Invokes a chat model to condense dialogue turns into a short title string [internal/types/interfaces/session.go52-54](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/session.go#L52-L54)
 - `GenerateTitleAsync`: Executes title generation asynchronously in a background goroutine and emits session title events via the event bus [internal/types/interfaces/session.go55-58](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/session.go#L55-L58)
 - `AgentStreamHandler`: Subscribes to `EventSessionTitle` to capture and stream generated titles back to clients [internal/handler/session/agent_stream_handler.go136-157](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/session/agent_stream_handler.go#L136-L157)
