# 01 轴体系与收敛判据：参数空间怎么定义、测量何时停

## 角色定位

轴（axis）与判据（stopping criterion）是 nvbench 的"前后刹车"：轴定义**测什么**——把一次基准变成 N×M 参数空间；判据决定**何时停**——state 采样到什么程度才算数。二者都挂在 benchmark_base 上（`nvbench/benchmark_base.cuh`，377 行，聚合 axes/stopping_criterion/元数据），用户在注册链上用链式 API 配置：`.add_int64_axis(...)`、`.set_stopping_criterion("stdrel")`。

## 内部结构

**轴家族六类文件**（`nvbench/axis_base.cuh` 抽象基类：轴名/输入数/克隆接口，int64/type/string 三族共同祖先）：

- 值轴三件套：`nvbench/int64_axis.cuh`+`nvbench/int64_axis.cxx`（set_inputs 解析输入串、轴值字符串化）、`nvbench/float64_axis.cxx`、`nvbench/string_axis.cxx`；
- 类型轴：`nvbench/type_axis.cuh` + `nvbench/type_axis.cxx:36` `set_active_inputs`（勾选启用类型）、`nvbench/type_axis.cxx:59` `get_type_index`（字符串反查索引）；
- 元数据容器：`nvbench/axes_metadata.cuh` 持有基准全部轴，被 benchmark 与 state_generator 共享（fanIn=8/fanOut=8）。

类型轴的底座是类型元编程：`nvbench/type_list.cuh`（157 行）提供 type_list/cartesian_product 与 `NVBENCH_TYPE_AXES` 宏；`nvbench/type_strings.cxx` 把 demangle 后的类型名转可读名；`nvbench/enum_type_list.cuh`（106 行）把 enum class 包装成可入轴类型并自动字符串化（`examples/enums.cu` 演示）。`nvbench/range.cuh` 是值轴便捷生成器。五种玩法见 `examples/axes.cu`（212 行）：`examples/axes.cu:36` 单基准注册、`examples/axes.cu:50` float64 区间轴、`examples/axes.cu:122` 类型 sweep、`examples/axes.cu:211` 双类型轴组合。

**判据三层**（抽象 → 注册表 → 实现）：`nvbench/stopping_criterion.cuh` 定义 `criterion_params` 与 `stopping_criterion_base`；`nvbench/criterion_manager.cxx:34-36` 注册三个内建实现——注意 `:36` 的注册名是 **"sample-count" 带连字符**，`nvbench/criterion_manager.cxx:74` 重名注册直接抛错；三个实现在 `nvbench/detail/` 下各一组 .cuh+.cxx。

## 外部连接

- 上游：`nvbench/create.cuh:40` `NVBENCH_BENCH` 与 `:47` `NVBENCH_BENCH_TYPES` 注册期收集轴；`nvbench/detail/state_generator.cxx:102` `build_axis_configs` 运行期对全部轴取笛卡尔积（`:131` 特意把 type 轴反序排列以对齐展开序），`:231` 逐设备生成 state。
- 下游：state 持有轴值快照（`nvbench/state.cuh:270` get_axis_values），测量器每批样本喂判据（`nvbench/detail/measure_cold.cu:174` add_measurement），判停后 `nvbench/detail/statistics.cuh`（533 行全模板）汇总成 summary。
- CLI：`nvbench/option_parser.cu:642` `--axis/-a` 过滤规约直接作用于轴（`:369` 非法轴值抛错），`--criterion` 按注册名切换判据。

## 数据流

注册期：链式声明 → axes_metadata 收集 → benchmark_base 持有。运行期：state_generator 展开轴积 → 每个 (设备,轴组合) 一个 state → 测量器逐批采样喂判据 → `is_finished()` 轮询 → 满足即出循环 → statistics 生成摘要 → summary（`nvbench/summary.cuh`）挂回 state。自定义判据走同一条路：派生 stopping_criterion_base 并注册进 criterion_manager（`examples/custom_criterion.cu`，77 行，即这条链的教学样本）。

## 设计决策

1. **类型轴而非宏矩阵**：type_axis 在一份二进制内实例化多类型基准——代价是类型元编程门槛，收益是结果文件里类型维度天然可比。
2. **判据做成注册表单例**而非编译期策略：运行时 `--criterion` 可切、用户可注册自定义判据；判据每批只调一次，虚调用开销无感。
3. **stdrel 的"噪声稳定窗口"兜底**（`nvbench/detail/stdrel_criterion.cxx:103-115`，窗口 64/检查间隔 16）：对天生噪声大的基准，噪声到不了 max-noise 阈值——检测到噪声长期稳定在阈值之上也放行结束，防止永不收敛。"统计判据必须给不收敛分布留出口"的教科书处理。
4. **entropy 判据参数名反直觉**：`nvbench/detail/entropy_criterion.cxx:30` 默认参数是 `max-angle 0.048 / min-r2 0.36`——"角度"指样本分布直方图与均匀分布的夹角，非熵阈值。
5. 值轴解析放 .cxx（`nvbench/int64_axis.cxx`），模板留 .cuh——编译边界清晰。

## 新人提示

- 先跑 `examples/axes.cu` 对照五个注册形态，再读 `nvbench/detail/state_generator.cxx` 看展开——轴"输入串"格式由各 axis 的 set_inputs 定义，报错在 `nvbench/option_parser.cu:369`。
- 判据调试用 `--criterion sample-count` 固定批次数；噪声分析用 `testing/device/noisy_bench.cu`（143 行专造抖动负载）。
- 别手搓停止条件：三个内建判据 + 稳定窗口兜底已覆盖绝大多数场景；确实要写，抄 `examples/custom_criterion.cu` 的注册姿势。
