# 11 skills/ 与 agent-first 资产层

## 一、角色定位

这个仓最不寻常的一层：DeepStream 9.1 把 **AI coding agent 的工程资产当作 SDK 一等公民发布**。三层资产互相咬合：`AGENTS.md`（9372 字节，仓库级 agent 行为契约）+ `skills/`（14 个 Agent Skills，每个是 SKILL.md+references+scripts 的结构化知识包）+ `example_prompts/`（14 份可复制的场景提示词）。`CLAUDE.md -> AGENTS.md` 符号链接（ls -la 实证 9 字节 symlink）让 Claude Code 与其他 agent 共享同一份契约——**不维护两份漂移的指令文件**。skills/README.md 开宗明义定位："A project showcasing how to leverage AI coding assistants for accelerated DeepStream SDK application development"，并强调 skills/prompts 无需 GPU 即可使用（生成在任意机器，运行才需要 SDK/GPU/驱动 595+）。更外围还有 `deploy/brev/`——DeepStream Code Agent Jupyter 实验室（3044 行的 ds_agent_lab.py 驱动"Claude Code 或 Codex 在 GPU 容器里生成并运行 DeepStream 项目"的完整闭环）。这层资产把"agent 会写 DeepStream"从愿望变成可测试的交付物。

## 二、内部结构

**AGENTS.md** 的内容骨架：Project overview（9.1 mono-repo 定位）→ Repository layout（逐目录一句话）→ GitHub Release Assets（四类包的选用规则，反复强调 all-in-one deb 优先、组件包是子集）→ Build & run（`bash build/build.sh` 分阶段 artifacts→deps→source→install，`--only/--resume` 快速迭代）→ Quick Reference 命令表 → **Conventions DOs and DON'Ts**（必须 --recurse-submodules、必须从 app 源码目录运行、SPDX 头保留、不提交构建产物、SBSA/DGX Spark 只能容器内构建、"not accepting external contributions"）→ Skills & prompts 发现指引 → 外部文档锚点表（8 个高价值子页链接 + "consult the public docs first instead of guessing from memory"）。**14 skills 分三族**（skills/README.md 表格）：开发族 7 个——deepstream-dev（200 行，pyservicemaker API 参考+16 篇 references/ 如 nvinfer_config.md/tracker_config.md/troubleshooting.md）、generate-pipeline（273 行，交互问卷+BM25 检索生成 gst-launch 管线）、profile-pipeline（347 行，Nsight Systems 测量后推导配置）、import-vision-model（259 行，HF/NGC 模型→TRT engine→基准→PDF 报告无人值守）、eval-and-finetune（289 行，mAP 评测+AutoML 微调+前后对比报告）、run-mv3dt（196 行）、sop（229 行，GEBD+VLM 工序合规微服务）；标定族 4 个——amc-setup/run-sample/run-video/run-rtsp（AutoMagicCalib 部署与三模式标定 runbook）；RTVI/VSS 族 3 个——cv-customize-model（338 行）、vlm-customize-model（437 行，三消费者换 VLM）、scaffold-vss-service（345 行）。**generate-pipeline 的检索器**是零依赖 BM25：scripts/generate_pipeline.py 618 行对 data/data.csv（272 行=270+ 验证管线）做文档长度归一化打分+同义词扩展，validate_pipeline.py 777 行负责验证；SKILL.md:109 明确约定"Always pass --format compact"省 token。**brev 实验室**：deploy/brev/{deepstream_code_agent_launchable.ipynb, scripts/ds_agent_lab.py 3044 行 79 个函数, tests/ 三件套}——函数覆盖提示组装（build_agent_prompt）、双后端认证（auth_backend_for）、容器工作区（ensure_install_container/sync_workspace_to_container）、agent 事件流式解析（_stream_agent_json）、产物高亮预览（show_generated_code）、Kafka 消费验证（consume_kafka）、端到端演示（run_demo）。

## 三、外部连接

对上连接 agent 生态：SKILL.md 是 Cursor/Claude Code 通用的技能约定（skills/README.md："Claude Code auto-discovers them via .claude/skills/"）；对下连接 DeepStream 主体——example_prompts 的 14 个场景（single_view_3d_tracker/parallel_infer_app/nvdsanalytics_config/msgbroker_nats/yolov26s_detection 等）多数指向本仓 reference_apps 的复现，rtvi_vlm_openapi_spec 连 VSS 蓝图。工具链依赖：import-vision-model 与 eval-and-finetune 在 `nvcr.io/nvidia/deepstream:9.1-triton-multiarch` 容器内跑（宿主只需 Docker+Toolkit）；amc 族连接 NGC 的 AutoMagicCalib 镜像；sop 连接 Cosmos Reason VLM 与 Basler 相机/SSE/Kafka。brev 连接 JupyterLab+GPU 容器+Claude Code/Codex CLI 三方（六步工作流：选场景→开容器→装 agent→认证→Generate→Run+Results），tests/ 三文件守护笔记本契约。

## 四、数据流

以 brev 实验室为主干看 agent 资产如何被消费：scenario_plan 加载提示目录 → set_selection 选场景 → auth_backend_for/build_cred_env 按 Claude/Codex 构造凭证环境 → ensure_install_container 起 GPU 容器并 sync_workspace_to_container 同步工作区 → prepare_services 拉起依赖服务 → build_agent_prompt 组装提示（注入 skills 上下文）→ dexec_stream/_stream_agent_json 流式执行 agent CLI 并解析事件 → 产物落容器工作区，show_generated_code 在 notebook 高亮预览 → run_demo/consume_kafka 拿运行证据（标注 MP4/Kafka 消息）→ 失败可 run_step 重试单步。skills 的消费路径更轻：agent 读到 SKILL.md 的 name/description 触发激活 → 按 SKILL.md 指引调 scripts（如 generate_pipeline.py --format compact）→ references/*.md 按需深读。example_prompts 最薄：复制→改→直接喂 agent。

## 五、设计决策

①**AGENTS.md 单源 + symlink**：CLAUDE.md 是符号链接而非拷贝，Claude Code 的自动发现机制与其他 agent 的手动加载共享同一真源——指令文件漂移问题在发布层被结构性消灭。②**skill 按"模式"而非"主题"切分**：README 的表格按 Mode 列组织（Reference-rich/交互问卷/Measure-then-derive/自主编排/Runbook）——同一主题（如模型）横跨 import/eval/rtvi-cv 三个 skill，因为 agent 需要的工作流形状不同；这比按技术领域切分更贴近使用场景。③**检索式生成优于纯生成**：generate-pipeline 用 270+ 验证管线的 BM25 检索做底、再让 agent 改写——把"幻觉管线"风险换成"检索偏差"风险，后者可用测试套件回归（该 skill 的 SKILL.md:250 要求跑检索质量测试）。④**证据链闭环设计**：brev 的每个场景都以"可检验产物"收尾（标注 MP4/Kafka 消息/PDF 报告），run_demo 与 consume_kafka 让 agent 生成的代码当场自证——生成代码不是终点，跑通才是；README 的 SDLC 免责声明与这个设计互为表里。⑤**token 经济学写进 SKILL.md**：--format compact 的约定（25 行 vs 150 行 JSON）说明 skill 作者把上下文成本当第一约束；79 函数里的 _compact_text（260 字符截断）同类。⑥**版本兼容的诚实声明**：skills/README.md 明说"部分 skill 文档写的容器版本可能非最新，用 skill 写的版本除非有理由"，把版本漂移的决定权交给用户而非静默升级。

## 六、新人提示

第一次接触别按 14 个 skill 全读：**从 example_prompts/ 的 video_infer_app 开始**（brev README 也推荐它——"shortest way to confirm the full Generate -> Run -> Results loop"），再读 skills/README.md 的模式表选自己工作流形状对应的 skill。给 agent 配环境时注意：skills 本身零硬件要求，但 import/eval 两个 skill 的脚本要在 Triton 容器里跑（宿主装 Docker 即可）；brev 实验室要 GPU。三个坑：(1) **AGENTS.md 的 DON'Ts 是硬约束**——"run from app source directory"与 sample_apps 篇的教训同源，agent 生成的项目也要遵守相对路径约定；(2) generate-pipeline 的 data.csv 是检索底座，自定义管线后想进语料要跑它家的测试套件防回归；(3) CLAUDE.md 是 symlink，改它=改 AGENTS.md，别当成两个文件误改出分叉。二次开发者想写自己的 skill：抄 rtvi-cv-scaffold-vss-service 的结构（SKILL.md 骨架+scripts 可执行+references 分层）最规整。甄别说明：本篇行数/函数数经源码实测——ds_agent_lab.py 为 3044 行 **79** 个函数（任务书称 70 函数，实测以 79 为准）；"14 skill"经目录清点确认（另有 README.md 非技能）；example_prompts 为 14 份 md（目录里的 png 是 OpenAPI 配图非提示词）。
