# 12 · 数据资产群：LeRobot parquet 三变体与仓内数据的甄别清单

## ① 角色定位

cosmos 仓一半的体积与大部分"开箱即跑"体验来自 checked-in 数据资产，分三群：**cookbooks/action 的 LeRobot 机器人数据样例**（7 个 `*_lerobot_example` + robomind 三合一）、**cookbooks/audiovisual 的结构化 caption 资产**（prompt+负向 prompt+条件图/参考视频）、**evaluation/generator 五套基准 prompt 清单**（08 篇已详述，本篇收尾对账）。这群资产是**教程与训练线的共同底座**——id notebook 读 LeRobot episode 画轨迹、finetune 配方读同格式数据、transfer 教程读与评测线同构的 specs。资产层的瑕疵（空任务文本、列名泄漏、字节级重复、零消费孤儿）会直接传导进下游，本篇逐条源码级实证。

## ② 内部结构

**LeRobot parquet 三变体**——每个 `*_lerobot_example` 固定三类 parquet（以 droid 为例，`meta/info.json` 实测 `codebase_version: v3.0`、total_episodes 1）：

1. `data/chunk-000/file-000.parquet`：**帧级主数据**，每帧一行。droid 列为 episode_index/frame_index/timestamp/index/task_index+5 特征列（cartesian_position/joint_positions/gripper_position×2/joint_position）；bridge 是 observation.state/action/image_0；agibotworld_beta 特征最宽（6 个 observation.states.*+3 相机）；umi 是右主相机轨迹+夹爪宽度；human_hand_pose 含双手状态+旋转+相机位姿。`videos/observation.images.*/chunk-000/*.mp4` 与帧表按 timestamp 对齐，帧表不存像素。
2. `meta/episodes/chunk-000/file-000.parquet`：**episode 索引**。标准版 schema 极简（episode_index/tasks/length+chunk_index/file_index）；human_hand_pose 版显著更肥——多出 task_description/environment_id 与每视频 from_timestamp/to_timestamp（手部标注元信息完整保留）。
3. `meta/tasks.parquet`：**任务文本表**（task_index→task 字符串），bridge 里是 "Put the pot to the left of the purple item."。

两个结构特例：robomind 没有顶层 meta，`franka/`、`franka_dual/`、`ur/` 三个子数据集各带完整 meta+data+videos；human_hand_pose 多一类 **`meta/subtasks.parquet`（第四变体）**——8 行 subtask_index/subtask（"unscrew nut with screwdriver" 等螺丝刀任务链），长程任务的分解标注。

**动作 JSON 资产**（`assets/actions/`）：av_traj_forward/left/right 与 camera_action 各 60×9 数组（AV 自车/相机位姿 9D×60 步@10FPS），umi.json 32×10（末端 9D+夹爪×chunk 32）——与 10 篇 embodiment 表维度一一对应。

**audiovisual 结构化 caption**：`prompts/{text2video(3), image2video(4), text2image(1)}` + `negative_prompts/` 两份。t2v prompt 完整 schema（以 car_colliding.json 为例）十数节：`subjects[]`（每主体 18 字段，人角色字段留空串）+ `background_setting`+`lighting{}`+`aesthetics`+`cinematography{}`+`context`+`actions[]` 时间轴逐段+`text_and_signage_elements[]`+`segments[]`+`temporal_caption` 整段时序+`resolution/aspect_ratio/duration/fps`。这就是 README 所说 `caption_json`"模型原生 prompt 格式"，训练推理共用（11 篇对齐原则）。

## ③ 外部连接

- **上游数据集**：样例目录是 HF 大数据集的"单 episode 切片"——LIBERO 对应 `nvidia/LIBERO_LeRobot_v3`、DROID 对应 `nvidia/Cosmos3-DROID`（success split）、RoboCasa 任务元组解析在 cosmos-framework 的 `robocasa_lerobot_dataset.py`（"single source of truth"）；跑全量走 finetune README 的 `uvx hf@latest download`。
- **读取器实现**：LeRobot 读取器/pose helpers 都在 cosmos-framework（`COSMOS3_REPO` 指向）；DROID 读取器按**目录名**识别 feature 布局（`COSMOS3_DROID_ROOT` 须指向以 DROID release 命名的目录）——样例目录名 `droid_lerobot_example` 正是此机制体现。
- **评测线资产对账**（与 08 篇互证）：paibench_c 600 条、paibench_g t2v/i2v 各 1044、physics_iq 各 198、rbench 合计 650、unigenbench prompt json（行含 index/prompt_en/sub_dims_en，后者是 literal_eval 字符串）+27 testpoint 判官词表。
- **NIM 许可清单**：`cookbooks/cosmos3/nim/acknowledgements/2.0.0.md` 实测 **34559 行**（README.md 仅 6 行索引，对应镜像 `nvcr.io/nim/nvidia/cosmos3:2.0.0`）——仓内最大单体文本资产，第三方许可全量转储。

## ④ 数据流

id（逆动力学）教程线最能体现三变体协作：notebook 定位 `*_lerobot_example` → 读取器用 `meta/info.json` 的 features 声明（列名→dtype→形状）打开帧级 parquet 取帧区间 → 按 timestamp 到 `videos/observation.images.*/` 切 mp4 喂模型 → 输出动作轨迹 → `meta/episodes` 长度校验对齐 → 任务文本进图题。finetune 侧同一读取器流式全量；audiovisual 的 i2v 是条件图+caption+负向 prompt 三元组进 payload（10 篇⑤的压缩序列化）。

## ⑤ 设计决策

1. **"单 episode 完整切片"而非抽帧样例**：每例保留完整 v3.0 目录骨架（meta/episodes/tasks/videos/data 全齐），教程代码对样例与全量数据集零差异——"教程→真数据"迁移成本只剩换路径。
2. **caption 结构化前倾**：18 字段 subjects+分段时序+镜头语言的 JSON 而非纯文本，既服务模型原生格式，也让人能按节改写重组（改主体保镜头）。
3. **列名即接口**：droid 的 `observation.state.cartesian_position` 这类点分层列名被读取器按名匹配，改名即断——fractal 的 `__index_level_0__`（见⑥）不是风格问题而是接口破损。
4. **许可资产全量随仓**：NIM ack 34559 行不外链，体积换离线合规确定性。
5. **动作资产与 embodiment 表对齐**：60×9/32×10 形状严格对应维度表。

## ⑥ 新人提示（坑与勘误）

以下六条全部实测钉版（pyarrow/md5/grep 于本仓当前 HEAD）：

1. **droid 样例任务文本为空**：`droid_lerobot_example/meta/tasks.parquet` 单行 `task=' |  | '`——三个空字段用竖线连接的占位串。id notebook 的 DROID 例任务描述实际不可用（模型 prompt 不依赖它），但任何"读 task 列做标题/过滤"的下游会拿到这串垃圾。
2. **fractal 的 tasks.parquet 索引列泄漏**：schema 是 `['task_index', '__index_level_0__']`——任务文本（"move orange near green rice chip bag"）不在标准 `task` 列而在 pandas 索引转储列 `__index_level_0__` 里；按 LeRobot 惯例读 `task` 列会 KeyError/拿到空。这是转换时 `reset_index` 缺失的典型痕迹，自建数据集转换时要引以为戒。
3. **car_colliding.json 零消费**：`prompts/text2video/car_colliding.json`（冬路口双车碰撞起火的完整结构化 caption）在全部 notebook/README/py 中**零引用**（grep 仅命中本图谱管线的扫描产物）。孤儿资产——内容完整、无人调用；t2v 教程实际用另外 2 个 prompt。
4. **coastal_road_audio.jpg 与 car_driving.jpg 字节级相同**：`images/image2video/` 下两文件 md5 同为 `1dd31d4d20b8f25fe724d3326f3b1135`（860765 字节）。i2v 音频演示与普通 car_driving.json 复用同一张条件图——名字里"coastal road"与画面内容无关，是刻意复用非命名错误；对比生成时两例唯一差异是 caption 与声音开关。
5. **robomind 三本体别找顶层 meta**：`meta/info.json` 在 `franka/`、`franka_dual/`、`ur/` 各自之下，顶层无聚合 info——按其它 7 例的路径习惯写代码会 FileNotFoundError。
6. **human_hand_pose 的 episodes 表是超集**：18 列远超标准 5-7 列，且多一类 subtasks.parquet；把它当标准 v3.0 episode 表做 schema 断言会假失败。帧级特征里有 `subtask_index`，帧→子任务归属查帧表即可。

## 小结

教程侧：8 个 LeRobot 样例（三变体 parquet+对齐 mp4）+8 个动作 JSON+8 个 caption 三元组+6 份 transfer spec；评测侧：600+1044×2+198×2+650 条 prompt 与 6 份 spec；文本侧：NIM 许可清单 34559 行+27 testpoint 判官词表。这批资产让全仓"clone 即可复现教程"，但六处甄别提醒：**checked-in ≠ 被代码消费**，资产层同样存在死引用与 schema 漂移。
