# 03 · 数据集基类框架：ImageBase/VideoBase 继承体系与 build_dataset 工厂

## 一、角色定位

`vlmeval/dataset/` 是评测栈最大的包（183 个条目），但定义协议的只有三个骨架文件：`image_base.py`（216 行）、`video_base.py`（264 行）、`__init__.py`（494 行注册中枢）。所有基准类都继承这两个基类之一（或题型特化子类），只需填 `DATASET_URL/DATASET_MD5` 字典和 `evaluate()` 即接入全管线。`build_dataset` 工厂与 `DATASET_TYPE/DATASET_MODALITY` 查询函数，是 run.py 分派推理管线（VIDEO/MT/普通）的判据来源。

## 二、内部结构

**ImageBaseDataset（image_base.py:39-216）**——类属性三件套：`MODALITY='IMAGE'`（image_base.py:41）、`DATASET_URL`/`DATASET_MD5`（image_base.py:42-43，**supported_datasets() 就是 `list(cls.DATASET_URL)`**，image_base.py:177-179——注册即声明 URL）。`__init__`（image_base.py:45-84）：`img_root_map`（image_base.py:13-36）把子数据集名归一到共享图片目录（MMBench_DEV_EN→MMBench）→ `load_data`（image_base.py:182-187，默认 prepare_tsv 下载+md5 校验）→ skip_noimg 过滤（image_base.py:54-56）→ **image 列引用去重**：单元格长度 ≤64 视为"指向另一行 index 的指针"，回填被指行真实 base64（image_base.py:62-73，tsv 省空间惯技）→ `meta_only` 标志（image_base.py:60/74）。可覆写钩子 load_data/post_build（image_base.py:190-191）。`build_prompt` 默认实现（image_base.py:194-211）：`dump_image` 解码 base64 落盘（四分支，image_base.py:129-168），返回 `[{type:'image',...},{type:'text',value:question}]` 消息列表——全栈统一中间格式。`evaluate` 是唯一抽象方法。

**VideoBaseDataset（video_base.py:17-227）**——构造器接受 `pack/nframe/fps/total_pixels`（video_base.py:21-27），`fps>0` 与 `nframe>0` 互斥（video_base.py:60-61），**两者都未设只警告**（video_base.py:62-67：VIDEO_LLM 模型自己处理视频没事，非 VIDEO_LLM 走数据集侧抽帧才失败）。三抽象方法 evaluate/build_prompt/prepare_dataset（video_base.py:214-227）——prepare_dataset 须返回 `{'root': 视频目录, 'data_file': tsv}`（video_base.py:222-227）。核心 `save_video_frames`（video_base.py:92-164）：fps 模式按 `video_fps/self.fps` 均匀采样（video_base.py:117-120）；nframe 模式按 `len(vid)/(nframe+1)` 去首尾取中（video_base.py:152-153）；**全程 portalocker 文件锁**防多进程互踩（video_base.py:99-103、146-147）；`total_pixels` 预算均摊每帧 LANCZOS 缩放（video_base.py:133-134、166-205）。

**__init__.py 注册中枢**：顶部 200 行 import（dataset/__init__.py:9-209，L11-18 "Fork-specific datasets" 注释标出 av_* 系列）；类按模态归入 IMAGE/VIDEO/TEXT/CUSTOM 四列表（dataset/__init__.py:326-394，L358-363 与 L384-385 有 "add by EASI team" 注释——外部团队贡献痕迹）；DATASET_COLLECTION 含 ConcatDataset 及动态合成的 Astro2DBenchDataset（dataset/__init__.py:397）；SUPPORTED_DATASETS 由各类 supported_datasets() 聚合（dataset/__init__.py:402-404）。`build_dataset`（dataset/__init__.py:448-478）三级匹配：supported_video_datasets（带默认采参，L450-451）→ 各类 supported_datasets（L452-453）→ **custom 兜底**（L455-478）：LMUData 下有同名 tsv 且含 question 列，按"有 A/B 选项列→MCQ、否则 VQA"猜类型。`ConcatDataset`（dataset/__init__.py:214-322）用 DATASET_SETS 定义聚合集（L218-231），build_prompt 委托子数据集（L268-275），evaluate 按 SUB_DATASET 拆文件逐判（L288-322）。

**题型特化**：`ImageVQADataset`（image_vqa.py:31，TYPE='VQA'）在 build_prompt 尾部追加"single word or phrase"指示（image_vqa.py:67-72），evaluate 按数据集名选打分器——TextVQA→vqa_score、ChartQA→relaxed_accuracy、DocVQA→anls（image_vqa.py:91-101）；`ImageYORNDataset`（image_yorn.py:9，TYPE='Y/N'）走 YOrN_Extraction；ImageMCQDataset（image_mcq.py:57）。

## 三、外部连接

基类向下依赖 smp（下载/解码/校验：image_base.py:9-10、video_base.py:10-12），video_base 硬检查 `decord`（video_base.py:30-34）并依赖 portalocker；>1GB 的 tsv 经 `vlmeval.tools.LOCALIZE` 本地化（image_base.py:124-125）。向上：run.py 用 build_dataset+MODALITY/TYPE 分派管线（run.py:326、348、358）；wrapper 用 DATASET_TYPE/MODALITY 决定自定义 prompt（qwen2_vl/prompt.py:27-42、internvl_chat.py:218-240）。

## 四、数据流

`build_dataset('MMBench_DEV_EN_V11')` → 逐类扫 supported_datasets 命中 ImageMCQDataset → prepare_tsv 下载/校验/本地化 → __init__ 图片列去引用 → 管线循环 `dataset.build_prompt(item)` 产出消息 → 模型 wrapper 消费 → 预测 tsv 落盘 → `dataset.evaluate(pred_file, **judge_kwargs)` 派生中间文件、build_judge 起 LLM judge → 返回结果给 run.py。视频路径多一步：prepare_dataset 就位 mp4，save_video_frames 首调抽帧缓存到 `LMUData/images/{dataset}/{video}/`（video_base.py:81-90），后续样本直接命中。

## 五、设计决策

1. **URL/MD5 即注册**：数据集类的"存在证明"就是 DATASET_URL 字典（image_base.py:177-179），无独立配置文件，新增基准=写一个类。
2. **消息列表作为通用货币**：build_prompt 输出的 `[{type,value}]` 同时被本地 wrapper、API wrapper、judge 消费，模态差异内化在 type 字段。
3. **数据集侧 vs 模型侧抽帧分界**：抽帧到磁盘是给非 VIDEO_LLM 模型准备的（video_base.py:62-67）；VIDEO_LLM 模型直接拿 mp4 路径自解码。
4. **并发抽帧上文件锁**（video_base.py:103）+ 锁内重查（video_base.py:126、148）：多 rank 并行零重复解码。
5. **custom 兜底无码扩展**（dataset/__init__.py:455-478）：自备 tsv 放 LMUData 即可被评测。

## 六、新人提示（坑/勘误）

- **43 个公开版剥离 stub**：fork 核心新增数据集（cosmos_cab_image/video、cosmos_erqa、cosmos_reason、metropolis 大部、videophy2、vantage 等）在公开仓是占位类——`supported_datasets()` 返回空、`__init__` 直接 `raise RuntimeError("... is not available in this public release.")`（cosmos_cab_image.py:15-17 模板；实测 grep 该标记串命中 43 个文件，非传闻的 45）。它们出现在 import 与 DATASET 列表里（dataset/__init__.py:35-39、375），但 build_dataset 永不命中。stub 不继承任何基类、无 MODALITY/TYPE——DATASET_TYPE 返回默认 'MCQ' 并告警（dataset/__init__.py:419-422）。
- **`dataset/cosmos_reason.py` 的 `class CosmosReason` 与 `api/cosmos_reason.py` 同名不同物**：前者是 stub 数据集（vlmeval/api/cosmos_reason.py:9-17），后者是真实 API wrapper 基类（vlmeval/api/cosmos_reason.py:234）。跨模块 grep 务必带路径。
- **image 列"≤64 字符=指针"约定**（image_base.py:67-70）是隐式协议：自备 tsv 的 image 列存短 URL 会被误判断言失败。
- **prepare_tsv 的 legacy 改名**（image_base.py:110-116，注释引上游 PR #1055）：下载文件从 URL 末段名改为 `{dataset_name}.tsv`，老缓存自动搬移。**video_base 与 image_base 的 prepare_tsv 是复制粘贴**（video_base.py:229-264 vs image_base.py:92-127）：修 bug 两处都要改。
