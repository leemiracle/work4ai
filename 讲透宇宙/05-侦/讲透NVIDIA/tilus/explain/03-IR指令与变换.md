# 03 · Tilus IR 指令体系与变换管线

## 1. 角色定位

`python/tilus/ir/`（图谱 L03+L05 层）是 tilus 的中间表示：DSL 的编译目标、全部 pass 的工作对象、后端发射的输入。CLAUDE.md:28-37 钉版其结构为"Program-Function-Stmt-Instruction-Tensor 五级"。它的核心取舍：**语句树管控制流，指令管计算，张量按存储层级分类**——三者都是 frozen dataclass（identity-based，`eq=False`），天然适配 memo 化的 visitor/rewriter。

## 2. 内部结构

**骨架五级**：`Program`（`python/tilus/ir/prog.py:25`）= `frozendict[str, Function]`；`Function`（`python/tilus/ir/func.py:84`）= name/params/body + `Metadata`（:45，GPU 指令属性）+ `Analysis`（:28，缓存分析结果）；`Stmt` 基类（`python/tilus/ir/stmt.py:27`）下挂控制流族 SeqStmt（:32）/ForStmt（:41）/IfStmt（:96）/WhileStmt（:106）/LetStmt（:134）与两个 tilus 特色节点——**ThreadGroupStmt**（:54，把语句限定在 warp/warpgroup/单线程域，`create` 工厂 :91）与 **InstStmt**（:167，把一条 Instruction 包进语句树）；张量桥 TensorItemPtrStmt（:154）/TensorItemValueStmt（:161）绑定 Hidet Var 与张量值。

**指令基类** `Instruction`（`python/tilus/ir/inst.py:25`）：`output: Optional[Tensor]` + `inputs: tuple[Tensor, ...]` + 类型专属字段。是否"功能性（纯计算、可删）"**不是**查 `output is None`，而是显式 allowlist——落点在 DCE：`FUNCTIONAL_INST_TYPES`（`python/tilus/transforms/dead_code_elimination.py:76`）+ isinstance 判定（:129）；副作用指令（StoreGlobalInst、SyncThreadsInst 等）永不消除（CLAUDE.md:35-36）。

**指令两族**：架构无关 `generic.py`（`python/tilus/ir/instructions/generic.py`，768 行约 50 类：AssignInst:31、LoadGlobalInst:71、StoreSharedInst:121、SliceRegisterInst:279、CastInst:300、AddInst:390、WhereInst:440、ReduceInst:501、ScanInst:526、ViewInst:564）；CUDA 扩展族（`python/tilus/ir/instructions/cuda/`）按硬件代际组织——Ampere `cp_async.py`、TMA 四向 bulk + commit/wait（`python/tilus/ir/instructions/cuda/cp_async_bulk.py:26-141`）、mbarrier 全家（`python/tilus/ir/instructions/cuda/mbarrier.py:27-111`，含 multicast/remote 变体）、Hopper wgmma（`python/tilus/ir/instructions/cuda/wgmma.py:36,59,96`）、Blackwell tcgen05 全家族（`python/tilus/ir/instructions/cuda/tcgen05.py:27-162`：Alloc/Dealloc/Relinquish/Slice/View/Load/Store/Wait/Copy/Commit/MmaSS/MmaTS）、CLC 集群工作窃取（`clc.py`）、代理栅栏（`python/tilus/ir/instructions/cuda/fence.py:23,37`——CLAUDE.md:69 钉版 store_shared→TMA 必插栅栏的 IR 形态）。另有零代码 hint 指令：`AnnotateLayoutInst`/`AssumeInst`（`python/tilus/ir/instructions/hints.py:26,41`）。

**变换管线**：Tilus 层 `Pass`（`python/tilus/transforms/base.py:68`）+ `PassContext`（:25，instrument 挂点）+ `apply_transforms`（:86）；默认 12 pass 序列在 `get_default_passes`（`python/tilus/transforms/__init__.py:31`）：declare_to_let → let_propagation → lower_assume → lower_param_only_expr → analyze_scalar → lower_print_tmem_tensor → **layout_inference** → lower_load_store → **layout_inference（二跑）** → bound_aware_simplify → analyze_scalar（二跑）→ dead_code_elimination。

## 3. 外部连接

上游：DSL 转译器 `Transpiler`（`python/tilus/lang/transpiler/transpiler.py:82`）经 `StmtBuilder`（`python/tilus/ir/builders/stmt_builder.py:437`，1699 行 127 方法，tilus 语句树的总构建 API）落成 Function。下游：`FunctionCodegen`（`python/tilus/backends/codegen.py:76`）逐 InstStmt 取发射器降 Hidet IR。横向支撑：分析器 `GridAnalyzer`（`python/tilus/ir/analyzers/grid_analyzer.py:431`，把 script 自由维归约为网格/循环，autotune 空间推导引擎）与 `ScalarSetAnalyzer`（`python/tilus/ir/analyzers/scalar_analyzer.py:321`，ScalarSet :78 取值集）供 `AnalyzeScalarPass`（`python/tilus/transforms/scalar_analyze.py`）灌入 `Function.Analysis`；`IRPrinter`（`python/tilus/ir/tools/printer.py:63`，530 行 39 方法）是 dump_ir 与错误报告的渲染层；`collect_instructions`（`python/tilus/ir/tools/instruction_collector.py`）是 pass 测试的标准入口（CLAUDE.md:60）。

## 4. 数据流（一条指令的一生）

以 matmul 循环体为例（`examples/matmul/matmul_v1.py:59-83`）：`self.load_global(ga, ...)` 转译为 InstStmt(LoadGlobalInst)——输出是缺布局的 RegisterTensor；进 optimize_program（`python/tilus/drivers.py:63`）后，第一轮 layout_inference 由 LoadGlobalRule 推出它的布局（`python/tilus/ir/layout/inference/inference_rules/ldst_global.py:93`）；lower_load_store 把 Generic 变体分派规范化（`python/tilus/transforms/lower_load_store.py`）；第二轮 layout_inference 处理新引入的张量；bound_aware_simplify 用取值集证伪守卫分支（`python/tilus/transforms/bound_aware_simplify.py`，ScalarSetBasedSimplifier）；最后 DCE 沿 `UsedTensorCollector` 删掉无消费者的功能指令链（python/tilus/transforms/dead_code_elimination.py:76 判定 + 296 行实现）。每 pass 前后有 `DumpIRInstrument`（`python/tilus/transforms/instruments/dump_ir.py`）可选落盘——`tilus.option.debug.dump_ir()`（`python/tilus/option.py:174`）一开，整条演化链可回放。

## 5. 设计决策

**InstStmt 包装而非指令即语句**：让 Instruction 保持纯数据（可直接哈希、比对、做映射键），控制流由 Stmt 统一——CLAUDE.md:44-46 钉版的 IRRewriter 协议正建立在这点上（`visit_InstStmt` 委托 `visit(stmt.inst)`，返回 None 则语句变空 SeqStmt）。**functional 用 allowlist 而非 output 判空**：副作用指令也可能有输出（如原子操作），判空会误删；allowlist 显式、可审计、失败响亮。**layout_inference 跑两遍**：访存下降会改写指令形状引入新张量，布局约束需要重新传播——简单粗暴但正确。**ThreadGroupStmt 进 IR 而非发射期约定**：warp/单线程域是语义（决定布局推断的 num_threads 上下文，`python/tilus/ir/layout/inference/rule.py:29` LayoutInferenceContext 携带 thread_begin/end），不只是代码生成细节。**Analysis 缓存进 Function**：标量取值集算一次多 pass 复用，避免重复整树遍历。

## 6. 新人提示

- 写 pass 前必读 CLAUDE.md:39-55 的 Pass 规范与四大陷阱：`visit_Expr` 不下钻 Hidet 子表达式（要用 `hidet.ir.tools.collect`）；memo 身份缓存不重访；指令属性里的 Var 必须扫 `inst.attributes`；张量活性要连 TensorItemValueStmt 绑定的 Var 一起看。
- 测试 pass 直接手搓 IR：`Function.create` + `SeqStmt` + `InstStmt(inst)` + 指令 `create()`，范本 `tests/transforms/test_dead_code_elimination.py`（CLAUDE.md:59）。
- 文件名陷阱：let 传播文件叫 `let_propogation.py`（propogation 拼错），函数名却是 `let_propagation_pass`（`python/tilus/transforms/__init__.py:23`）——import 时按函数名找。
- dump 看 IR 演化：`debug.dump_ir` 落盘在缓存目录 `ir/`（Tilus 层）与 `module/ir/`（Hidet 层），配合 `debug_block` 定位单个 block。
- 新增指令的完整清单：IR 类（generic 或 cuda/）→ `instructions/__init__.py` 导出 → 前端指令组方法 → 布局规则 + order.py 登记 → 发射器注册，五环缺一不可。
