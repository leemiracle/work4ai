# 07 存储与网络：NFS 单角色双形态、MOFED、Trident 与 RoCE 空壳甄别

## 一、角色定位

对应图谱 L07 存储与网络层（65 节点）：nfs/autofs/cachefilesd 组共享存储线，mofed/roce_backend 组 RDMA 网络线，netapp-trident 是 K8s 外部存储线，deepops_hosts/dns-config 是解析底座。落位由 inventory 分组驱动：NFS 服务端默认 `slurm-nfs[0]`（playbooks/slurm-cluster.yml:62），客户端 `slurm-nfs-client` 组（:68）。

## 二、内部结构

**nfs 是"单角色双形态布尔分流"样本**：`roles/nfs/tasks/main.yml` 装基础包（:15-31）后，三个 include_tasks 全用布尔分流——`when: nfs_is_server` 进 server.yml+firewall.yml（:43-48），`when: nfs_is_client` 进 client.yml（:51-52）。开关默认全关（roles/nfs/defaults/main.yml:3-4），由上层组变量点亮。服务端渲染 exports.j2 后 notify 重启（roles/nfs/tasks/server.yml:33-38）；模板就是 for 循环逐条输出 path+options（roles/nfs/templates/exports.j2:11-13）——一份代码两种形态。

**mofed**装 Mellanox OFED：`ofed_info | head -n1` 探测已装版本（roles/mofed/tasks/main.yml:21-24），`mofed_do_install` 布尔（:27-33）门控下载-解压-`mlnxofedinstall`（:42-63，清理 :69）；安装标志默认 `--all --without-fw-update`（roles/mofed/defaults/main.yml:10），版本锁 5.6-2.0.9.0（:2）；RHEL 前置包分文件（roles/mofed/vars/rhel8.yml:4-10）。

**netapp-trident** 命令行编排：helm repo add（roles/netapp-trident/tasks/main.yml:5）→update（:10）→upgrade --install --wait（:15）；后端创建带 retries:10/delay:30 轮询（:48-49）且全程 no_log 防凭据泄漏（:43,54）；快照 CRD/控制器/快照类 kubectl apply 远端 URL（:73,80,96），可 fetch tridentctl 回控制机（:103）。

## 三、外部连接

上游：generic/nfs-server.yml/nfs-client.yml 被 slurm-cluster.yml:59-69 import；roce.yaml 是 roce_backend 唯一入口。K8s 侧：nfs-client-provisioner 动态 PVC；trident 对接 NetApp；helm 由 scripts/k8s/install_helm.sh 预装。

## 四、数据流

Slurm 路径：分组点亮 nfs_is_server 导出 /home→客户端组挂载→autofs 渲染 /etc/auto.master（roles/autofs/tasks/main.yml:16，assert 强制变量必填 :2-9）。K8s 路径：roce.yaml 对 all 主机 `tasks_from: allhosts`（roce.yaml:8）——lspci 探测 Mellanox 卡数>0 才装 MOFED（roles/roce_backend/tasks/mofed-install.yaml:3-9），ISO 循环挂载安装（:27-28）后 reboot（:36）；再对 kube_control_plane `tasks_from: k8smaster`（roce.yaml:34）建 NetworkAttachmentDefinition——annotations 挂 `intel.com/<res_name>`（roles/roce_backend/tasks/nad4roce.yaml:25），CNI 配置经 `from_yaml | to_nice_json` 内嵌（:27）。

## 五、设计决策与甄别

1. **roce_backend 是"空壳占位"**：tasks/main.yml 仅 2 行注释零任务（roles/roce_backend/tasks/main.yml:1-2），分流文件由外部 playbook `tasks_from` 直调——常规 include_role 得到空角色，读懂它必须看调用方。
2. **MOFED 双实现并存**：roles/mofed（get_url+unarchive，较新）与 roce_backend/tasks/mofed-install.yaml（wget+mount ISO，较老）两代安装器共存，后者会 reboot（:36）。
3. nfs molecule 注入与本场景无关的 kerberos realm 变量（roles/nfs/molecule/default/molecule.yml:19）——四场景同源复制痕迹。
4. trident 后端 JSON 含阵列凭据，排障别 -vvv。

## 六、新人提示

1. 改 NFS 先看布尔变量：两开关默认 no，molecule 零动作是正常的。
2. roce_backend 部署前读其 README：SR-IOV 要 BIOS 层开关，Ansible 代劳不了。
3. deepops_hosts 重写 /etc/hosts 且先 `setup:` 重收 facts（roles/deepops_hosts/tasks/main.yml:4）——绕开 fact 缓存陈旧主机名的手法。
4. mofed 安装耗时且可能要求重启，放维护窗口。
