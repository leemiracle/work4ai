# 01 · 两大总编排：slurm-cluster.yml 与 k8s-cluster.yml

## 角色定位

DeepOps 把"一套 inventory、两条产线"收敛为两个顶层 playbook：`playbooks/slurm-cluster.yml`（155 行，31 个 import_playbook）面向裸机 HPC 调度栈，`playbooks/k8s-cluster.yml`（322 行，16 个 import_playbook）面向 Kubernetes GPU 云。它们是全仓唯一的用户入口——scripts/ 下的部署脚本（如 scripts/k8s/deploy_k8s_cluster.sh）最终都落到这两个文件。两者共享 bootstrap/generic/container 三组子 playbook，在"NVIDIA 软件层"分叉：Slurm 线走 nvidia-software/ 直装驱动，K8s 线默认交给 GPU Operator。

## 内部结构

slurm-cluster.yml 是一条线性管线：bootstrap 三连（`slurm-cluster.yml:5/8/11` 装 python/ssh 密钥/sudo）→ 基础设施（hosts:19、chrony:24）→ 容器 registry（:28 落 `hostlist=slurm-master`）→ NVIDIA 软件层（driver:44、cuda:51、dcgm:72）→ Slurm 本体（nhc:76、slurm:80）→ 生态（openmpi:83、lmod:87、hpc-sdk:91）→ 监控五件套（:97-126 全部收敛到 `slurm-metric` 组）→ 日志（rsyslog:129/135）→ 容器作业（pyxis:145、nv_peer_mem:153）。k8s-cluster.yml 前 30 行是运行时探测：`k8s-cluster.yml:9-15` 在 container_manager 非 docker 时 set_fact `deepops_gpu_operator_enabled: true` 并强制 `etcd_deployment_type: host`；:16-22 是 docker 分支。`:33-38` 用 delegate_to localhost 在控制机执行 `git submodule update --init` 锁 kubespray 版本；`:109-112` 直接 import `../submodules/kubespray/cluster.yml`。

## 外部连接

k8s 线与 kubespray 子模块深度耦合：`k8s-cluster.yml:92-104` 的 dpkg_selections purge（docker-ce/containerd.io）专为清除 DGX OS 预装环境的 hold 态；`:118-121` 在 kubespray 之后补刀关 swap（注释明言"kubespray method doesn't quite cut it"）。Slurm 线的外部依赖是 Galaxy 角色 nvidia.nvidia_driver（driver:44 引入）与 pyxis/nhc 等自有角色。两线在收尾共享 rsyslog 模式（k8s:313-322 默认落在 `kube_control_plane[0]`）。

## 数据流

两份 playbook 本质是"变量 → 主机落位"的映射器：hostlist 参数决定每个组件跑在哪个 inventory 组——NFS server 默认 `slurm-nfs[0]`（slurm-cluster.yml:62），监控默认 `slurm-metric`（:99），K8s registry 落 `kube_control_plane`（k8s-cluster.yml:66）。变量开关裁剪管线：`slurm_cluster_install_nvidia_driver|default(true)`（:45）控制驱动；CUDA playbook 自带驱动安装，故 :48-53 显式传 `cuda_playbook_install_driver` 旗标避免双跑。GPU 分叉点的条件最关键：`k8s-cluster.yml:166-167` ——operator 关闭或 `gpu_operator_preinstalled_nvidia_software` 为真（DGX 场景）才宿主机直装驱动，`|default(true)|bool` 的链式写法保证未定义时安全。

## 设计决策

① import_playbook + when 开关而非单巨型 playbook，使每段可独立重跑（tags 如 :149-150 pyxis、:154 nvidia-peer-memory）。② slurm.yml 是 31 个 import 中唯一无 when 的（:79-80）——Slurm 是该产线的存在理由。③ GFD/device plugin（:291-300）与 GPU Operator（:302-306）互斥部署，`deepops_gpu_operator_enabled` 一个变量决定走哪条 GPU 栈，避免 device plugin 双注册。④ taint 移除 `failed_when: false`（:288）容忍 control-plane 不在 kube_node 的拓扑。

## 新人提示

改这两个文件时先 `grep -c import_playbook` 对账（31/16）；新增组件务必带 when 默认值与 hostlist 重定向，否则会打到 all 主机。K8s 线升级 kubespray 后要逐一复核 config.example/group_vars/k8s_cluster.yml 里带 issue 链接的定点补丁（kubectl_localhost:8、flexvolume:21 等）是否已被上游修复。记住一个陷阱：submodule 锁定任务（:33）只在 playbook 内自动执行，直接跑子 playbook 不含此步。
