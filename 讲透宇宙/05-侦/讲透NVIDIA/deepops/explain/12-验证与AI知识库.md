# 12 验证与 AI 知识库：三工具双契约、skills/ agent 程序库与 epilog 回归测试

## 一、角色定位

对应图谱 L14 文档 CI 与验证层：scripts/validation/ 三个机器可读验证器（deepops_doctor/validate_slurm/validate_k8s）、skills/+AGENTS.md 组成的 **AI agent 操作知识库**、jenkins CI 冒烟矩阵（workloads/jenkins/）、run-tests.sh（603行）。

## 二、内部结构

**三验证器共享 human/json 双契约**：默认每检查一行人类可读，`--json` 输出单一 JSON 对象，退出码 0/1/2 各有语义（deepops_doctor.py:10-15,:77）。doctor 预检 Ansible/Galaxy/kubespray/config/inventory，--remote 验证全主机 SSH+GPU 可见性（check() :39-41）；validate_slurm.py 跑 sinfo 状态/GRES（parse_sinfo_states :60/parse_gres_gpus :90）并真实 `srun --gpus=1 nvidia-smi`（:194-202，--json :113）；validate_k8s.py 汇总节点与 GPU Pod（:52/:84），--cuda-smoke 起 CUDA Pod 实测（:120，门控 :253-254）。result 均以 `"ok": not failures` 收口——AGENTS.md 定为部署闸门（:35,:47,:58）。

**skills/ 是跨工具 agent 程序库**：遵循 emerging agent-skills 约定——YAML frontmatter+前置条件+精确命令+期望输出+失败分支（skills/README.md:1-26）。六技能中 deploy-airgapped 最重（**999 行**断网部署全程序），provision-with-maas 252 行，其余四个 54-82 行。deploy-airgapped 含**诚实自我警告**：Do not run `scripts/airgap/build_offline_cache.sh`——它调用已删除的 build-offline-cache.yml，在本树必失败（SKILL.md:30-32，残骸实证 build_offline_cache.sh:98）。skills/README 贡献规约：命令必须从 clean checkout 可照跑，失败分支来自真实观察而非臆测。

**run-tests.sh 是破坏性守卫的回归范式**：文件头自述动机——slurm 角色被 molecule CI 排除（容器跑不了 systemd），而 epilog 脚本干 `killall -9 -u`/`rm -fr`，失败模式**静默**："误伤旁观者"与"清理成功"看起来一样（:1-14）。解法：**只测判定守卫（whether to reap）不测执行（reap）**，零依赖 Slurm/root；模板先经 render.py 渲染成部署形态（:11-12,47-52）；logger 桩防"守卫拒绝"与"脚本早死"不可区分（:30-36）；squeue 桩从 $SQUEUE_FIXTURE 读应答（:67-73）；断言走"文件仍存在"而非"日志无删除字样"（:278-280——删了一切但忘打日志的脚本骗不过它）。

## 三、外部连接

- AGENTS.md 是总入口：仓库地图、golden path（:39-44,50-55）、操作规约（验证 GPU 用 `srun --gpus=1 nvidia-smi`，never with bare SSH :87——GPU 藏进 cgroup，裸 SSH 验证不到作业视角）。
- CI 矩阵：workloads/jenkins/ 4 个 Jenkinsfile+32 脚本（21 个 test-*），jenkins-common.sh 以 GPUDATA 解码锁定的 GPU/PCIe 总线（:23-26）。
- 契约自证：validation/tests/ 固化 GPU 任务契约——TransientExecutionContract（GPU 命令跑在 systemd-run 瞬态单元 :94-137）、MigApplyFailureContract（失败必须暴露 :139）、MigProbeBehaviour（探测退出码 :187）。

## 四、数据流

agent 读 AGENTS.md→调 skills/<procedure> 部署→每阶段跑验证器取 --json→`"ok": false` 按 failure branch 分诊→Jenkins 每夜回归。run-tests.sh 独立成环：渲染模板→桩环境→守卫用例→ok/no 计数（:27-28）。

## 五、设计决策与甄别

1. **双契约边界**：JSON 给 agent/CI，human 行给人排障——AGENTS.md 明文要求 agent 用 --json。
2. **诚实文档**：deploy-airgapped 直接标注仓内坏脚本而非删掉或假装能跑——知识库可信度优先于整洁。
3. **测试选择器哲学**："判是否该删"与"执行删除"分离后，测试才可能零依赖且有意义——与 epilog 编号前缀（40 杀→41 收 SSH→42 清目录）分层同源。
4. 甄别：validate_*/doctor 是 2026 年新代码（统一 PEP8/类型注解），与老 bash 世代断层鲜明——维护遵循新契约。

## 六、新人提示

1. playbook 失败先跑 `deepops_doctor.py --json`，detail 字段给修复线索。
2. 写新 skill 抄 deploy-airgapped 骨架：frontmatter 触发词覆盖用户变体说法。
3. 改 epilog 脚本必跑 `tests/slurm-epilog/run-tests.sh`，唯一自动化防线。
4. Jenkins 脚本本地调试需手工 export GPUDATA（`GPU-BUS` 格式），否则 jenkins-common.sh 直接 exit 1。
