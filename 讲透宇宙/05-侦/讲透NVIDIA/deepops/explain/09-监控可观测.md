# 09 监控可观测：Prometheus 双部署形态、EFK 六清单与 ipmi-exporter 甄别

## 一、角色定位

对应图谱 L10 监控可观测层（33 节点），"一套理念、两种载体"：Slurm/裸机路径用 Ansible 角色（prometheus/node-exporter/slurm-exporter/grafana/alertmanager）以 systemd+Docker 部署；K8s 路径用静态清单（prometheus-monitor.yml 592 行+logging/ EFK 六清单+ipmi-exporter.yml）。核心机制 **file_sd 目录自注册**：exporter 角色往 endpoints 目录投 yml 片段，主配置通配纳管。

## 二、内部结构

**prometheus 角色**（roles/prometheus/tasks/main.yml，62 行）：建目录（:8-9）→装告警规则（:20）→渲染主配置（:28）→docker_volume 持久化（:37,43-44）→systemd（:47）→收敛（:56）。主配置只认两件事：file_sd 通配发现与本地 Alertmanager（roles/prometheus/templates/prometheus.yml.j2:10 localhost:9093、:19 file_sd_configs、:24 自抓 localhost:9090）——新 exporter 接入零主配置改动。

**prometheus-slurm-exporter 是自研 Go exporter**（files/exporter/main.go，258 行纯标准库）：被抓取时执行 sinfo/squeue/scontrol，经 ParseNodeStates（main.go:40）/ParseCPUs（:80）/ParseQueueStates（:99）/ParseScheduler（:120）汇入 collect（:206）输出 slurm_nodes_*/queue_*/scheduler_*/cpus_* 指标族（入口 :248）；镜像 CGO_ENABLED=0 静态编译（files/docker/Dockerfile），运行时 bind-mount 宿主 Slurm 客户端；配 964 行 dashboard JSON 与 114 行单测。

**EFK 六清单**（workloads/examples/k8s/services/logging/）：es-service（18 行）+es-statefulset（131 行 RBAC+StatefulSet）+fluentd-es-configmap（428 行 fluent.conf，输出 :408-409）+fluentd-es-ds（116 行 DaemonSet 挂 /var/log 与 docker 日志）+kibana-deployment（44 行，镜像 5.6.4 :24，对接 elasticsearch-logging:9200 :33）+kibana-service（18 行）——k8s 官方 addon 的镜像副本。

## 三、外部连接

- **alertmanager** 与 prometheus 同构（配置 :8-15/volume :23-24/systemd :27-34），模板只有 Slack 占位符（alertmanager.yml.j2:1-11），落地必须替换。
- **grafana** provisioning 实现"面板即代码"：prometheus-datasource.yml.j2（8 行）+prometheus-dashboard.yml.j2（9 行）。
- **prometheus-monitor.yml**（592 行）K8s 独立版：RBAC（:4-42）+Deployment（:44，v2.1.0 :63）+侧车 Alertmanager（:88-91，v0.14.0）+两个 ConfigMap（:122 抓取规则、:470 alertmanager-config）+Service（:530）；首行注释给 curl 直发测试告警用法（:1）。

## 四、数据流

Slurm：node/slurm 两 exporter 投 endpoint 片段→file_sd 抓取→告警评估（rule_files :13）→Alertmanager→Slack。K8s：fluentd 采容器日志→elasticsearch-logging→Kibana；ipmi-exporter 补**带外管理口**盲区：挂 /dev/ipmi0（ipmi-exporter.yml:46-48）。

## 五、设计决策与甄别

1. **ipmi-exporter 的"重复键修复"**：首行注释 docker run 里 `--name` 出现两次（ipmi-exporter.yml:1）——历史 bug 化石；旧 Service 方案整体注释（:2-19），现行从 `---` 起（:20）改 DaemonSet+hostPort；**必须 privileged: true**，注释承认 `type: CharDevice` 在 hostPath 不工作（:42-43,:48）。
2. **file_sd 优于 static_configs**：exporter 解耦、新增目标不动主配置。
3. **版本刻意偏旧**：v2.1.0/v0.14.0/Kibana 5.6.4 均为 2018 年代镜像——示例定位"能跑的参考"，生产自行换新。
4. slurm-exporter 用显式输出格式执行命令（防长节点名/非 C locale 破坏解析），与 slurm prolog 脚本防御风格同源。

## 六、新人提示

1. 先跑首行注释的 curl 测试告警（prometheus-monitor.yml:1）验链路，再查 exporter。
2. slurm-exporter 容器内 slurm 用户必须可解析，否则 sinfo 拒解析 slurm.conf。
3. EFK 直接 apply 整目录，但 ES 数据随 Pod 消亡——演示栈。
4. Grafana 仪表盘改动走 provisioning 文件而非 UI 导出，保证可重放。
