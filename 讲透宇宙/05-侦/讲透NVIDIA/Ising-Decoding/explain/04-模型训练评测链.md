# 04 · 模型训练评测链

## 一、角色定位

`code/model/`、`code/training/`、`code/evaluation/` 构成主干：模型目录定义预解码器全部架构；训练是 Hydra 驱动的 1869 行单文件 `train.py`；评测按码族分派 PyMatching（surface）/Chromobius（color）两条 LER 线。"一套 Conv3D 骨架吃两种码"：factory 按 `cfg.model.version` 分派（`code/model/factory.py:37`），架构不要求正方晶格。

## 二、内部结构

**模型侧**：`predecoder.py` 定义四代类。v1 裸 Conv3d 堆叠（`code/model/predecoder.py:250`），末层无激活直出 logits；v2 残差块链（`code/model/predecoder.py:317`），filters 两两一组消费；v3 引入 NATTEN 三维邻域注意力（`code/model/predecoder.py:370`），natten 软导入、缺包到实例化才抛 ImportError；Cascade 是论文 Model B 的瓶颈残差变体（`code/model/predecoder.py:430`），`plain_stem=True` 时首块退化为普通 Conv3d 升维（`code/model/predecoder.py:461`），其后 `max(0, num_blocks-1)` 个等宽瓶颈块，残差支路 `1/sqrt(2*num_blocks)` 缩放。

**参数双口径勘误（非矛盾）**：`registry.py` 注释写 Model B ~2.94M，对应 `_MODEL_B_OVERRIDES` 的 embed_dim=512/num_blocks=6（`code/model/registry.py:67`）；公开 d17 配置（embed_dim=1024/num_blocks=12）被契约测试钉死 `EXPECTED_PARAMS = 25_397_764`（`code/tests/test_color_accurate_model_contract.py:27`）。两数字分属"论文复刻小模型"与"公开发布大模型"两套配置，同一 Cascade 类实例化。

**训练侧**：`train.py` 入口 `@hydra.main`（`code/training/train.py:731`），核心是三条按码族互斥的生成器延迟 import（函数体内）：multi-pair 走 `MultiQCDataGeneratorTorch`（`code/training/train.py:1034`）、color 走 `ColorQCDataGeneratorTorch`（`code/training/train.py:1085`；必须给 `precomputed_frames_dir`）、surface 走 `QCDataGeneratorTorch`（`code/training/train.py:1156`），chromobius 等重依赖只在对应路径触发。`precision.py` 是 AMP 纪律书：fp16/bf16 互斥、autocast 不改参数 dtype、channels_last_3d——半精度 Conv3d 默认布局 A100 单卷积 ~30ms，NDHWC 后 ~0.05ms（`code/training/precision.py:69`）。`logging.py` 41 行是替换 physicsnemo.launch.logging 的垫片（`code/training/logging.py:15`），与 stdlib `logging` 撞名但包内绝对导入仍指 stdlib，无害。

**评测侧**：`metrics.py` 对 surface/color 两 LER 模块 try/except 双导入（`code/evaluation/metrics.py:33`）。surface 主函数 `count_logical_errors_with_errorbar`（`code/evaluation/logical_error_rate.py:808`）与 color 的 `count_logical_errors_color`（`code/evaluation/logical_error_rate_color.py:1183`）分别用 pymatching/chromobius。`inference.py` 是公开推理口：只报 LER 与加速比；机器可读标记 `[Inference Summary]` 由环境变量 opt-in（`code/evaluation/inference.py:41`）打印于 L246 供冒烟解析。

## 三、外部连接

Lion/DebugLion 与 lr scheduler 来自 `training/optimizers.py`（`code/training/train.py:1397`）。1311 行的 `failure_analysis.py` 中，`decoder_ablation_study`（`code/evaluation/failure_analysis.py:888`）经 `_build_all_decoders` 构建 PyMatching 相关/不相关、LDPC 与 cudaq-qec 解码器组，同一残差综合征喂多复杂度解码器横比。`reference_color_baseline.py` 用 qec 的 superdense 噪声 oracle 造电路再以 Chromobius 解码（`code/evaluation/reference_color_baseline.py:34`），提供 color 线无预解码器基线。

## 四、数据流

典型训练：Hydra 加载 conf → PREDECODER_TRAIN_SAMPLES 等环境变量覆写样本数/epoch → 三选一建 train/val 生成器（val 用 `base_seed+VALIDATION_SEED_OFFSET`；color 线 val 关 superbatch，其步与训练不连续、缓冲必弃）→ train_epoch/validation_step 交替 → checkpoint 落盘。评测：`run_inference` 先探测 /dev/shm，容器小内存强制 num_workers=0；surface 线建 DEM+matcher，baseline 直接对 Stim detector 解码（`code/evaluation/logical_error_rate.py:1037`），实验组喂模型残差出 LER 与延迟表。color 结果汇入三胞胎聚合器（chromobius_timing/sdr/threshold）：flock 排他锁（`code/evaluation/color_threshold_results.py:229`）→ normalize → 逐 (d,p,basis) merge → append，多 rank 安全累加。

## 五、设计决策

①**同骨架双码族**：不为 color 另起架构，`model_overrides` 整块覆写非卷积口径（`code/model/registry.py:127`），factory 单一入口。②**tile padding 硬件妥协**：v1 末层可宽于 out_channels、forward 切掉多余通道（`code/model/predecoder.py:313`），只为 TensorRT 在 B200 选更好的 cutlass tile。③**魔数即契约**：25,397,764 写成断言而非注释，漂移即刻爆红。④**惰性重依赖**：pymatching/chromobius/natten/cudaq 全延后到使用点并降级，最小环境也能跑单测。⑤**评测禁静默回退**：TRT 缺失显式 RuntimeError 而非悄悄退回 PyTorch（测试钉死，见 05 篇）。

## 六、新人提示

先读 `registry.py`（164 行）再读 `predecoder.py`。改训练先看三个延迟 import 块：生成器参数全在彼处展开，签名长因一份配置喂三种码。跑 v3 前确认 natten 与 CUDA 匹配。看数：`[PyMatching Timing]` 区分纯 decode 与含 GPU→CPU 拷贝时间（`code/evaluation/logical_error_rate.py:1524`），加速比用前者。2.94M 与 25.4M 并存非 bug——先核对哪份配置。
