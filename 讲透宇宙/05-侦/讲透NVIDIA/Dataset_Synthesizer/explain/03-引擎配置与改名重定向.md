# 03 · 引擎配置：Vulkan 黑屏与三类改名重定向

## 角色定位

`Source/Config/DefaultEngine.ini` 加上三个兄弟 ini（DefaultEditor/DefaultEditorSettings/DefaultGame，后两者近乎空壳——DefaultGame.ini 仅 3 行 ProjectID）共 13 个文件构成 L01 层的配置面。别小看这一个 ini：它同时钉死了**渲染后端选择**、**启动地图**和**类名三代史**，是理解"为什么我的深度图全黑""为什么旧资产加载报 Unknown class"两大脑残问题的钥匙。

## 内部结构

DefaultEngine.ini 按节组织，与本主题相关的三节：

- **LinuxTargetSettings 节（`Source/Config/DefaultEngine.ini:12-17`）**：`12-15` 行是 NVIDIA 留下的四行注释——"`Using VULKAN RHI cause the Depth and ClassSegmentation feature extractor to be black` / `We should just use OpenGL 4.30 for now`"；`16` 行 `-TargetedRHIs=SF_VULKAN_SM5` 删 Vulkan、`17` 行 `+TargetedRHIs=GLSL_430` 增 OpenGL 4.3。**+/- 前缀是 UE4 ini 数组项的增删语法**（NOTES-DIGEST batch-24 钉版）：`-` 从数组移除所有匹配项、`+` 追加——不是数学正负。
- **GameMapsSettings 节（`:20-21`）**：EditorStartupMap 与 GameDefaultMap 双双指向 `/Game/Map/TestCapturer`——这就是 L08 层采集测试图成为"打开编辑器即见采集场景"的原因。
- **Engine 节（`:24-26`）**：三条 `+ActiveClassRedirects`（OldClassName→NewClassName），详见下文。
- 其余：RendererSettings（`:6-9`，CustomDepth=0 等）、RenderDoc 插件配置（`:29-36`）、iOS 朝向、PhysX 全量参数——与本主题无关但同文件共栖。

## 外部连接

改名重定向的另一端在 NVSceneCapturer 源码：`NVSceneFeatureExtractor_ImageExport.h` 的现类名 `UNVSceneFeatureExtractor_PixelData`（`:24`）、`UNVSceneFeatureExtractor_VertexColorMask`（`:148`）与 `NVSceneFeatureExtractor_DataExport.h:51` 的 `UNVSceneFeatureExtractor_AnnotationData`——三条 redirect 的 NewClassName 与之一一对应。Vulkan 约束的第二证在 `readme.md:28`："Although Vulkan doesn't get affected by this, Vulkan doesn't capture depth and class segmentation"（uniform buffer 问题 Vulkan 反而免疫，但深度/类分割采集不了）。

## 数据流（三条改名的因果链）

1. **ObjectSegmentation→VertexColorMask**（`DefaultEngine.ini:24`）：早期用自定义 stencil 做"对象分割"，后改顶点色方案——继承链实证：`UNVSceneFeatureExtractor_StencilMask`（`NVSceneFeatureExtractor_ImageExport.h:134`）与 `_VertexColorMask`（`:148`）并存，后者成为 redirect 终点。
2. **ImageExport→PixelData**（`:25`）：基类从"图像导出"语义改名"像素数据"——因为 AnnotationData 分支根本不导图像只导 JSON（`NVSceneFeatureExtractor_DataExport.h:51`），原名以偏概全。
3. **DataExport→AnnotationData**（`:26`）：对偶改名，JSON 分支获得准确语义。

引擎加载旧 uasset 时按 redirect 表自动换算类名，蓝图序列化兼容由此保证；但**源码里搜旧类名零命中**——读旧教程/旧 issue 时必须自己脑内换算。

## 设计决策

1. **渲染后端降级而非修 bug**：Vulkan 下深度/分割黑屏是提取器后处理材质管线在 Vulkan 的兼容缺陷（2018 年 UE4.22 时代），上游选择禁用后端而非修管线——快而糙，代价是丢 Vulkan 的 uniform buffer 优势（`readme.md:24-28` 记录的 4.22 内存问题恰是 OpenGL/DirectX 受影响、Vulkan 免疫——两害相权取其轻）。
2. **redirect 进 ini 而非代码**：类改名走引擎原生重定向机制，旧资产零迁移成本——UE4 生态标准做法，但代价是"类名考古"必须查 ini。
3. 启动地图即测试图（`:20-21`）：开箱即跑采集闭环，教程友好性设计。

## 新人提示

- 深度/分割全黑先查渲染后端：Linux 下 RHI 必须是 GLSL_430；若在别的平台复现，先确认没有被项目/命令行覆盖回 Vulkan。
- 读 2018-2019 年 NDDS 教程见到 ObjectSegmentation/ImageExport/DataExport 三类名，按上表换算成 VertexColorMask/PixelData/AnnotationData 再搜源码。
- ini 的 +/- 前缀别手滑写成普通 `=`：`-TargetedRHIs` 是删数组项（`DefaultEngine.ini:16`），`=TargetedRHIs` 是整个替换数组——语义完全不同。
- `Config=Engine` 的 UCLASS（`NVSceneCapturerActor.h:119`、`DRSceneManager.h:18`、`NVAnnotatedActor.h:17`）其默认值可被本文件覆盖——调参不见效时先来这里搜属性名。
- 想看 ini 覆盖了哪些类的默认值：搜全仓 UCLASS 里的 `Config=Engine` 标记共 7 处（采集器 `NVSceneCapturerActor.h:119`、场景管理器 `NVSceneManager.h:48`、`DRSceneManager.h:18`、`NVAnnotatedActor.h:17`、`NVCoordinateComponent.h:17`、两个 SceneMarker `NVSceneMarker_FocalPoint.h:17`/`NVSceneMarker_Path.h:17`）——这 7 类的属性默认值都可能被本文件悄悄改写。
