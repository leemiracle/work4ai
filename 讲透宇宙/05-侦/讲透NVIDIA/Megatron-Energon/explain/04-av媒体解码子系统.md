# 04 · av 媒体解码子系统

## 角色定位

`src/megatron/energon/av/` 是 Energon 的音视频解码层：把 webdataset 里的 mp4/mkv/avi/flac/mp3/wav 原始字节变成 torch 张量。它不绑 ffmpeg 命令行，而是在 PyAV（`av>=17.0.0`，pyproject.toml:75 的 `av_decode` extra）之上封装"可运行时调参"的 `AVDecoder`——clip 区间、单位、输出尺寸不在初始化固定，而是每次 `get_clips()` 指定（av_decoder.py:42-48 类 docstring 明说此动机），适配多模态训练的多样解码需求。配套 `media/` 子包不含解码逻辑，只做元数据（时长/帧数/采样率）探测与序列化，服务于 `energon prepare` 建索引。

## 内部结构

五个文件各司其职：`av_data.py` 是纯数据壳，`AVData` 用 `@edataclass` 承载 video_clips `(frames, channels, h, w)` / audio_clips `(channels, samples)` 与秒级时间戳（av_data.py:11-20）；`av_init.py` 是 PyAV 容器"开机仪式"；`av_reader.py` 实现帧级随机访问；`av_decoder.py` 是编排中枢；`utils.py` 提供等距采样糖函数。

`av_init.py` 最关键的是 `initialize_av_container`（av_init.py:30-44）：对每条流强制 `thread_type="NONE"; thread_count=0`。注释直言原因——ffmpeg 释放容器时多线程会死锁，且 torch DataLoader fork 多 worker 前父进程不能残留线程。所有容器必须经 `av_open`（av_init.py:15-27）进入，初始化失败则 close 后 re-raise，不留半开容器。

`av_reader.py` 解决"视频无真随机访问"的根本矛盾：解码只能从关键帧开始线性推进。`AVReader` 抽象基类的两个子类共享 `_previous_frame` 缓存——请求与上次连续时免 seek 直接续读（av_reader.py:172-180）。`AVProbeIndex` 是 AVI 这类 `stream.index_entries` 为空容器的兜底：全量 demux 记录每个 packet 的 pts 与 is_keyframe，`seek(0)` 归位后复用（av_reader.py:36-44）；查找用 `bisect_right` 二分（av_reader.py:74）。

## 外部连接

上游消费方：`flavors/webdataset/__init__.py` 的 `__getattr__` 惰性转发 AVData/AVDecoder；`media/extractor.py` 的 `_build_av_metadata` 对 bytes/IO/EPath 三种输入统一走 `AVDecoder(...).get_metadata(get_audio_num_samples=True)`（extractor.py:238-246）；`flavors/vid_qa.py` 与 `decoders/sample_decoder.py` 也直接 import。

**图谱勘误（假边）**：最终图谱 1814 条边里存在 `av_reader.py -> av/__init__.py` 自引用假边。成因是 av_reader.py:9-11 顶层 `import av / av.container / av.stream` 指**外部 PyAV 包**，裸名 `av` 恰与项目自身包 `src/megatron/energon/av/` 同名，被 scanner 误解析为项目内 import。判别证据：av_reader.py 从不引用本包符号。**scanner 盲区成因**：av_decoder.py:14-29 把 `import av/filetype` 与 `from .av_reader import ...` 全塞进 `try/except ImportError`，以支持"未装 PyAV 也能 import 本模块"（置 `AV_DECODE_AVAILABLE=False`，av_decoder.py:26-29），运行时才在构造函数抛带安装指引的 ImportError（av_decoder.py:54-59）；try 块内 import 对静态扫描天然不可靠，读图谱时 av 子系统的文件级依赖边须回源码复核。

## 数据流

一次 `get_video_clips`（av_decoder.py:89-217）：①`_inspect_index_mode` 按扩展名路由——mkv/webm 走 PTS 索引，mp4/mov/m4v 走帧索引，其余退 PROBE 全量探测（av_decoder.py:78-87）；②`match (video_unit, index_mode)` 四分支单位换算，如 seconds×FRAMES 索引乘 average_rate 转帧号并告警"结果可能偏移"（av_decoder.py:158-169）；③逐帧 `reformat(format="rgb24")`（可选双线性缩放）；④`torch.stack(...).permute((0,3,1,2))` 转 CHW（av_decoder.py:214-216）。音频路径 `get_audio_clips`（av_decoder.py:229-366）：seek 只能落帧边界，起始要裁前一帧尾部（av_decoder.py:316-326），结束按秒裁剪且与期望采样数差 <2 时主动对齐（av_decoder.py:340-347）——"时长截断"语义落点：clip 样本数由帧边界+微调共同决定，非精确切割。源码小瑕疵：av_decoder.py:337-338 是完全相同的两行赋值，第二行是死代码。

## 设计决策

为何按扩展名路由三种索引？容器索引可靠性参差：MP4 的 index_entries 有帧号但时间戳是 DTS，MKV 有 PTS 无帧号，AVI 两者皆无。ByFrames 的 seek 特意 `backward=False`——注释解释 DTS 下 backward=True 会过冲回上一关键帧（av_reader.py:172-176）。元数据与解码分家：`get_metadata` 是建库期高频操作，能读 header 就不解码，duration 缺失才 demux 全片数 packet（av_decoder.py:568-580），帧尺寸优先解首帧、失败回退流属性（av_decoder.py:597-604）。media 侧 `MediaFilterConfig.parse` 强制 GLOB/HEADER/EXTENSION 三选一（extractor.py:43-51），HEADER 策略因需读内容 `should_consider_all()` 恒真（extractor.py:65-69），序列化剔除 None 字段（metadata.py:40）。

## 新人提示

改 av 代码前必看 tests/test_av_decoder.py 的**基线对齐法**：`load_video_to_tensor` 用裸 PyAV 直解全片做 ground truth（test_av_decoder.py:32-55），位级相等用 `(a==b).all()` 断言（test_av_decoder.py:189），涉缩放用 `tensors_close`——归一化 [0,1] 后 MAE≤0.01（test_av_decoder.py:58-75），因 PyAV 与 torchvision resize 实现不同只保证数值接近（test_av_decoder.py:339-342 注释明说）。关键帧位置硬编码断言为 (0,0),(250,128000)...（test_av_decoder.py:114-124）。三注意：一，新容器入口必须走 `av_open` 而非 `av.open`，否则 fork 死锁防线被绕过；二，stream 是共享可变对象，每次操作前 `self.stream.seek(0)`（av_decoder.py:248 等）；三，test_wav_decode_against_soundfile 里还与 soundfile 做对齐和计时对比（test_av_decoder.py:634-670）。
