# 06 · 检测/分割插件群：三 NMS 共享一 kernel、MSDA 三档规约与 roiAlign 双源移植

## 角色定位

图谱 L08 层（102 节点）覆盖 two-stage/one-stage 检测、DETR 分割与 BEV 点云全家桶。本篇取三标本讲三种工程范式：`efficientNMSPlugin`——**一 kernel 三插件**模式；`multiscaleDeformableAttnPlugin`（MSDA，Deformable DETR 核心算子）——**六 kernel 三档规约**模式；`roiAlignPlugin`——**上游双源移植**（PyTorch ATen+ONNX Runtime）对照实现模式。家族其余成员（detectionLayer/proposal/multilevelProposeROI 等）共同消费 02 篇 maskRCNNKernels.cu 共享 kernel 库，多数已随 TRT 10.12 进废弃窗口。

## 内部结构

**efficientNMS 三胞胎**：基座 `EfficientNMSPlugin`（IPluginV2DynamicExt，注册名 `EfficientNMS_TRT`、版本 "1"，`efficientNMSPlugin.cpp:31-32`）持有 `EfficientNMSParameters`（`efficientNMSParameters.h:28`，:40 classAgnostic 唯一可选）。执行面只认一个 C 入口 `EfficientNMSInference`（`efficientNMSInference.h:28`）：基座两处调用（cpp:387 传 nullptr 的无锚框路径、:401 标准路径）；`EfficientNMSExplicitTFTRTPlugin`（`EfficientNMS_Explicit_TF_TRT`，tftrt/efficientNMSExplicitTFTRTPlugin.cpp:35）纯继承复用（:38-39 委托基座构造）；`EfficientNMSImplicitTFTRTPlugin`（`EfficientNMS_Implicit_TF_TRT`，:36）因 TF 隐式 batch 重排输出索引，:185 直调共享入口。序列化全仓最简：`write(d, mParam)` 一行裸 POD（cpp:107），零版本前缀，:108 长度断言对账。

**MSDA 六 kernel 三档**：前向 `ms_deform_attn_cuda_forward` 双重载（`multiscaleDeformableAttn.cu:39` float/:60 half），按 `mIm2colStep` 切片调 im2col（:52/:72）；im2col 主体 kernel 在 cuh:321（float）+:376（half 特化）。反向 col2im 六 kernel 分三档：**blocksize-aware**（cuh:450 v1/:541 v2，整除时免 smem 树规约）、**shm-reduce**（:635/:727，`extern __shared__` 缓存部分和再树合并）、**跨块**（:828 multi_blocks + :929 gm，末级 atomicAdd 全局内存 :913-915）。发射器 `ms_deformable_col2im_cuda`（:1013）三岔分派：`channels>1024` 且整除走 multi_blocks（:1022-1027，动态 smem），否则 `switch(channels)`（:1042）按 10..1024 选 blocksize-aware 变体，default 落 shm_reduce。V3/Legacy 双轨：版本 "2"（`multiscaleDeformableAttnPlugin.cpp:28-29`）/"1"（Legacy.cpp:35-36），V3 无状态 clone 直拷。

**roiAlign 双实现**：kernel 层 `roiAlignKernel.cu` 双上游血统 :18-24——「Modified from Pytorch」（Facebook）+「Modified from ONNX Runtime」（Microsoft）；三模板函数（:52/:120/:225）+:272-279 实例化。插件层 V3 `ROIAlignV3`（`roiAlignPlugin.h:58`，Creator :33）；V2 `ROIAlign`（`roiAlignPluginLegacy.h:33`，手写形状推断；Creator :96 继承 02 篇 BaseCreator）。ONNX 桥接：`coordinate_transformation_mode` 直映 `aligned` 布尔（cpp:40/:111-114/:117）。

## 外部连接

MSDA 血脉版权头自陈：`multiscaleDeformableAttn.cu:20-25` 与 cuh:18-24 标注 Modified from Deformable DETR（SenseTime）与 DCN（Microsoft）——社区 kernel 净化后反向成为官方插件，「透明开源汇流」又一样本。检测家族向 02 篇 maskRCNNKernels.cu（3101 行）回流：detectionLayerPlugin.cpp:304 与 proposalLayerPlugin.cpp:343 的 NMS kernel 调用。废弃轨道（README 钉版）：`EfficientNMS_ONNX_TRT` 已于 TRT 10.16 移除、并入核心层 `INMSLayer`（README.md:21）；`EfficientNMS_TRT` 自 10.12 弃用无替代（README.md:3）；detectionLayer/generateDetection 等同期挂废弃注。V2/V3 序列化分叉在此最直观：V3 走 `getFieldsToSerialize`，V2 Legacy 以 `read<int32_t>` 逐字段还原（roiAlignPluginLegacy.cpp:388-392 五连读）。

## 数据流

DETR 分割头：多尺度特征+采样点+注意力权重 → MSDA enqueue → im2col 把每 query 的 L×K 个采样点聚成矩阵 → 后接 GEMM 聚合；训练态反向 col2im 按 (batch,query,head,channel) 索引展开，规约档位由通道数运行时决定。one-stage 检测头：boxes/scores → EfficientNMS → `EfficientNMSInference` 排序+IoU 抑制。two-stage 链 proposalLayer→roiAlign→detectionLayer 全落共享 kernel 库。

## 设计决策

①**一 kernel 三插件**：算子逻辑与 ONNX 图形态解耦——TF 显式/隐式 batch 两种导出图共用一份 NMS 实现，差异全在插件壳的输入输出编排，改 kernel 一处生效三处。②**规约三档而非通用 kernel**：blocksize-aware 零 smem 树规约最快但要求整除；shm-reduce 兜奇数通道；multi_blocks+gm 突破单 block 上限——按形状选档是 CUDA「形状特化」教科书。③**裸 POD 序列化**：mParam 单块写入零版本头，长度断言自检，简洁但任何字段增删都是 ABI 断裂。④**移植保留版权链**：双 Modified 声明把开源义务写进文件头。⑤**ONNX 属性直通语义位**：coordinate_transformation_mode→aligned 让 ONNX 语义零翻译进入 kernel 分支。

## 新人提示

新项目别接 EfficientNMS_TRT——README 宣判弃用无替代，替换目标是核心层 INMSLayer；但三插件共享结构仍是学壳设计的最佳教材。调 MSDA 性能先看通道数落哪个规约档（:1013 发射器），channels>1024 与奇数通道的性能断层可能差一个量级；梯度全零查 multi_blocks 的 atomicAdd 竞争。roiAlign 的 `aligned` 与 torchvision/MaskRCNN 有半像素差，比对务必同源（本仓 kernel 是 PyTorch 系）。V2 死声明陷阱：`roiAlignPluginLegacy.h:53-55` 的 setClipParam/setScoreBits/setCaffeSemantics 声明零实现（跨插件复制残留），调用即链接失败——别当公开 API 用。
