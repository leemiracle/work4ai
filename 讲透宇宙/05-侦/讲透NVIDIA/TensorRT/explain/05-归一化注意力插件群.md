# 05 · 归一化与注意力插件群：cuDNN→Welford 迁移与 LN 家族的版本地铁图

## 角色定位

本篇覆盖四个目录（图谱 L07 层主力）：`instanceNormalizationPlugin`（分割/风格迁移归一化）、`embLayerNormPlugin`（BERT 嵌入+LN）、`skipLayerNormPlugin`（残差跳连 LN）、旁证 `disentangledAttentionPlugin`（DeBERTa）。它们展示插件库两条演进主轴：**实现迁移**——instanceNorm 从 cuDNN 调用整体重写为自研 Welford kernel，摆脱运行时依赖；**代际共存**——LN 双家族以「一个注册名×多版本号」并行维护 V2/V3、固定/变长序列、HFace/MTron kernel 口味，是 01 篇三代插件在算子层的全谱展开。

## 内部结构

**instanceNorm 双实现对照**：Legacy 版（`instanceNormalizationPluginLegacy.h:40`，IPluginV2DynamicExt，版本 "1"/"2" 于 :37-38）初始化时建 cuDNN 句柄与四个 descriptor（`instanceNormalizationPluginLegacy.cu:120-124`），核心执行是 `cudnnBatchNormalizationForwardTraining`（:300，模式 SPATIAL_PERSISTENT :287 / SPATIAL :297 按布局二选一）。V3 版（`instanceNormalizationPlugin.h:40`，版本 "3"，`instanceNormalizationPlugin.cu:35`）彻底自研：`instanceNormFwdDispatch`（`instanceNormFwd.h:160`）统一入口，`instanceNormalizationPlugin.cu:434` 调用；kernel 心脏 `instanceNormFwdImpl.cu`（856 行）——:53 注释直指 Welford 在线方差算法（引 Wikipedia Online_algorithm 条目），配套 `instanceNormCommon.h` 的 `PackedStorage`（:28-48，向量化打包）与 `ParallelSums` 特化（:737-757，按通道选 16/8 路），两段规约在 :320/:329，全局方差构建 :432-460。

**embLN 六版本**：注册名同为 `CustomEmbLayerNormPluginDynamic`（`embLayerNormVarSeqlenPlugin.cpp:38`），六个 Creator 靠版本号寻址——"1" Legacy 固定序列（`embLayerNormPluginLegacy.cpp:37`）、"2"/"3" Legacy HFace/MTron（`embLayerNormVarSeqlenPluginLegacy.cpp:36-37`）、"4"/"5" V3 HFace/MTron（`embLayerNormVarSeqlenPlugin.cpp:36-37`）、"6" V3 固定序列（`embLayerNormPlugin.cpp:36`）。V3 主类 `EmbLayerNormPluginDynamic`（`embLayerNormPlugin.h:48/:146`，cpp:40 注册）；变长序列经 `EmbLayerNormVarSeqlenPluginBase`（h:46）派生 HFace/MTron 双子类（:127/:157，cpp:131-132 双注册），kernel 入口 `embSkipLayerNormHFace/MTron`（h:37/:42）对应 HuggingFace 与 Megatron 两种权重布局。

**skipLN 版本地铁图**：同名 `CustomSkipLayerNormPluginDynamic`（`skipLayerNormPlugin.cpp:37`）下 "1"/"2" Legacy 固定/变长（`skipLayerNormPluginLegacy.cpp:38-40`）、"5"/"6" V3 固定/变长（`skipLayerNormPlugin.cpp:36/:38`，:41-42 双注册）、"7"/"8" V3 int8 交错 HFace/MTron（`skipLayerNormInt8InterleavedPlugin.cpp:37-38`）——V3 类族在 `skipLayerNormPlugin.h:46/:159`，交错基类 `SkipLayerNormInterleavedPluginBase`（`skipLayerNormInt8InterleavedPlugin.h:51/:126`）。四条分派线（固定/变长/交错×HF/MTron）由 ONNX 图改写工具按导出器选版本号。

## 外部连接

向上：embLN 与 skipLN 是 BERT/Transformer 图改写的固定搭配（demo/BERT 与 parser 优化 pass 都点名这两个注册名），maskIdx 语义与 03 篇 bertQKV 插件互认。向下：Legacy instanceNorm 是全插件库对 cuDNN 的**最后消费点**（经 02 篇 `createPluginCudnnWrapper` 句柄缓存），V3 迁移后 cuDNN wrapper 仅剩历史职责。横向：disentangledAttentionPlugin（DeBERTa，IPluginV3 双轨）与 06 篇 MSDA 同属注意力支线，其 README 输出名写 result、实际 output（图谱批 35 钉版）。

## 数据流

以 BERT 前两层为例：input_ids+token_mask → **embLN**（查表+position embedding+LN，变长序列经 HFace/MTron kernel 按实际 seqlen 收缩）→ bertQKV 插件（03 篇）→ 残差回来 → **skipLN**（skip+LN 融合，int8 图走交错变体）。插件内：Creator 解析 beta/gamma → V3 走 `getFieldsToSerialize`、V2 走二进制 serialize 持久化 → enqueue 按 `type_id` 分派 fp32/fp16 kernel。instanceNorm V3 的 enqueue（`instanceNormalizationPlugin.cu:434`）打包 context/params 交 `instanceNormFwdDispatch` 选 Welford kernel 实例。

## 设计决策

①**cuDNN→自研的动机链**：V2 借 cuDNN 快速获得正确性，但引入 dlopen+句柄生命周期+版本漂移三重负担（02 篇 wrapper 全为此存在）；V3 用 856 行 Welford kernel 一次性买断，PackedStorage/ParallelSums 特化把通道分档编译期化。②**同名多版本而非多注册名**：ONNX 节点不感知接口代际，版本号成为图改写工具与注册表间的秘密握手；代价是 README 类名常漂移（skipLN 文档仍写 V2 creator 名，图谱批 53 钉版）。③**HFace/MTron 双 kernel 口味**：同一 LN 数学、两种框架权重排布不同，宁可双实现也不在 kernel 里运行时判别——热路径零分支。④**embLN "6" 迟到**：固定序列 V3 版最晚补齐，说明迁移按使用频率排序（变长序列 BERT 推理更常见）。

## 新人提示

查 LN 插件先背版本表（embLN 1-6、skipLN 1/2/5/6/7/8），`grep "VERSION{" 各 .cpp` 五分钟绘全图；解析器报「plugin not found」九成是版本号没对上而非名字错。读 Welford kernel 从 `instanceNormFwdImpl.cu:53` 注释锚起步，对照 ParallelSums 特化理解通道分档；勿把 Legacy cuDNN 路径当现行实现引用。文档三坑（图谱钉版）：embLN README 输出名与 YAML 不一致（embedded_output vs embedded_input）；output_fp16 参数描述自相矛盾；skipLN changelog v6 行为笔误（实为复制 v2）——一律以 YAML+源码为准。调 HFace/MTron 选择问题时查 ONNX 导出器而非插件代码。
