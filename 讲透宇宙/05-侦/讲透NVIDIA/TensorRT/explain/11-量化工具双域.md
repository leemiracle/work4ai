# 11 · 量化工具双域：pytorch-quantization 与 tensorflow-quantization

> 图谱锚：L15「量化工具双域」（167 节点）。源码根 `tools/pytorch-quantization/`（QAT 主力）+ `tools/tensorflow-quantization/`（TF 侧镜像）。

## 一、角色定位

这对姊妹库解决同一件事：**训练框架内做 QAT（量化感知训练）产出 TRT 可直接消化的校准后模型**。pytorch-quantization 是主力——`quant_nn` 量化算子族、amax 校准器（max/histogram）、假量化前向与 ONNX 导出桥；数值心脏是 torch cpp_extension 编译的 **cuda_ext**（PYBIND11 扩展）。tensorflow-quantization 把同一理念搬到 tf.keras。两库皆工具定位：插进现有训练脚本即可。

## 二、内部结构

**pytorch-quantization 三层**：

- **数值核 `tensor_quant.py`**：tensor_quant.py:28 `from pytorch_quantization import cuda_ext`——无 .py 对应物，由 `setup.py:65-66` 的 `CUDAExtension` 从 `src/tensor_quant.cpp`+`src/tensor_quant_gpu.cu` 编译。扩展源 `src/tensor_quant.cpp:82` `PYBIND11_MODULE(TORCH_EXTENSION_NAME, m)` 导出 `fake_tensor_quant`（tensor_quant.cpp:34）、带 axis 逐通道版（tensor_quant.cpp:41）与 inplace 变体（tensor_quant.cpp:26）。Python 侧四个 autograd.Function 对应四种量化语义：`FakeTensorQuantFunction`（tensor_quant.py:303，前向在 tensor_quant.py:325 与 tensor_quant.py:329 分无轴/带轴调 cuda_ext，反向经 tensor_quant.py:252 STE 直通）、`ScaledE4M3Function`（tensor_quant.py:374，FP8）、`TensorQuantFunction`（tensor_quant.py:423，真量化占位）、`FakeAffineTensorQuantFunction`（tensor_quant.py:560）。文件尾 tensor_quant.py:620-624 以 `tensor_quant = TensorQuantFunction.apply` 等五行装成可调用别名。
- **模块层 `nn/modules/tensor_quantizer.py`**：单类 423 行 33 方法的 `TensorQuantizer`（tensor_quantizer.py:34）是运行时心脏——构造按 `calib_method` 字符串延迟实例化校准器（tensor_quantizer.py:98 histogram、tensor_quantizer.py:103 max）；tensor_quantizer.py:161-197 的 disable/enable 八连开关支撑分阶段冻结；**前向 tensor_quantizer.py:341 是全库最重要一段**：smoothquant 的 `pre_quant_scale` 预缩放（tensor_quantizer.py:351）→ disabled 直通（tensor_quantizer.py:357）→ 校准期 `calibrator.collect`（tensor_quantizer.py:368）→ clip（tensor_quantizer.py:375）→ 按 `_num_bits` 是否 tuple 分流（tensor_quantizer.py:379 int 走 `_quant_forward`；tuple (E,M) 走 `scaled_e4m3` 即 FP8，tensor_quantizer.py:381-383）。
- **替换层 `quant_modules.py`**：全局单例 `_quant_module_helper_object`（quant_modules.py:165）维持替换状态；namedtuple 三元组 `_quant_entry`（quant_modules.py:28）驱动 setattr 猴子补丁（quant_modules.py:115 与 quant_modules.py:123）——`initialize()` 后 `torch.nn.Conv2d` 全树静默换成 QuantConv2d。校准侧 `calib/histogram.py:340-341` 识别需通道置换的 QuantConvTranspose 族。

**tensorflow-quantization**：核心 `quantize_wrapper_base.py:49` `BaseQuantizeWrapper(tf.keras.layers.Wrapper)`——`__init_subclass__`（quantize_wrapper_base.py:54）强制子类注册，`__init__`（quantize_wrapper_base.py:58）按层名分派 `_configure_singular_quantize`（quantize_wrapper_base.py:93）或 `_configure_special_quantize`（quantize_wrapper_base.py:100），`_make_layer_name`/`_weight_name`（quantize_wrapper_base.py:144/148）统一权重命名；call() 内延迟 import 包级常量规避循环导入。`quantize_wrappers.py` 的 `DISABLED_LAYER_QUANTIZATION_DEFAULT` 默认对 MaxPool/BN/Add/Multiply/Concatenate 不量化。

## 三、外部连接

向上：PyTorch/torchvision（examples 量化版 resnet 与上游同构、仅卷积线性换 quant_nn 版）、TF2/keras。向下：QDQ ONNX 直落 TRT builder；`tensorflow_quantization/examples/infer_engine.py` 依赖 pycuda.autoinit、以 `TRT_DYNAMIC_DIM=-1` 标动态 batch 维。侧向：tests 依赖 apex.contrib.sparsity（缺失即跳过）。

## 四、数据流

QAT 全流程：`quant_modules.initialize()` 猴子补丁 → 模型实例化即量化层 → 前向过 TensorQuantizer（假量化=cuda_ext GPU 核，梯度 STE 直通）→ `enable_calib()` 跑校准集 → `load_calib_amax()` 固化 amax →（可选 disable_quant 冻结微调）→ ONNX 导出时 symbolic 翻译成 Q/DQ 节点对 → TRT builder 消费 QDQ 图出 INT8/FP8 引擎。cuda_ext 未编译时 import 即断——最常见安装期报错点。

## 五、设计决策

1. **数值核下沉 CUDA 扩展**：假量化每步都跑，Python 实现必成训练瓶颈；单文件 cpp+cu 换来逐元素全 GPU。代价是发行必须编 CUDA，且 cuda_ext 无 .py 使静态分析缺席。
2. **Function.apply 别名导出**（tensor_quant.py:620-624）：torch.autograd 调用惯例封装成普通函数名。
3. **全局猴子补丁 vs 逐层显式替换**：initialize() 一行换全网激进（污染全局 torch.nn），但让"三行代码改造现有训练脚本"成为可能。
4. **calib_method 字符串延迟实例化**：校准算法族可扩展而不膨胀构造签名。
5. **TF 侧 Wrapper 而非猴子补丁**：keras 惯用包装 + 默认不量化五类层——保守默认，与 PyTorch 侧激进对照。

## 六、给新人的提示

先跑 `examples/torchvision/classification_flow.py` 全流程再读代码，里程碑 initialize→calib→export。调试精度先查 `_amax`（三态 'dynamic'/标量/[min,max]）；TRT 侧精度不符优先核对 per-channel axis 与 QuantConvTranspose 通道置换（histogram.py:340 特判是历史踩坑点）。cuda_ext 编译失败多半是 CUDA 与 torch 版本不匹配。TF 线 `version.py` 构建时才生成（源码树没有），源码运行 ImportError 不是 bug。
