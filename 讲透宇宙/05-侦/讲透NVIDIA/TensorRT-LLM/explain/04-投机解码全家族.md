# 04 · 投机解码全家族：interface 枢纽与 DFlash/DSpark/EAGLE3/MTP/PARD/NGram 六路

## 角色定位

`tensorrt_llm/_torch/speculative/` 是解码加速的全部家当（图谱 82 节点）。中枢 `interface.py`（3081 行，wc -l 实证）定义模式枚举、请求级元数据与 worker 基类，各算法以 worker 子类插入。DFlash/DSpark（2026 新）是"并行 draft"路线（独立小模型+私有缓存），与单模型自 draft、免模型 draft 并存。

## 内部结构

**枢纽 interface.py**：`SpeculativeDecodingMode`（interface.py:308）是 IntEnum 位标志，现存 16 态——MTP=1 / MTP_EAGLE_ONE_MODEL=3 / EAGLE3_ONE_MODEL=5 / NGRAM=6 / SA=7 / DRAFT_TARGET=9 / USER_PROVIDED=10 / SAVE_HIDDEN_STATES=11 / PARD=12 / DFLASH=13 / DSPARK=14 / NONE=15 / AUTO=16。interface.py:311 注释钉死**枚举值禁止重编号**——它进 llmapi/serialization.py 跨进程白名单，2/4/8 已退役不得复用。判定族组织路由（is_parallel_draft/needs_kv_cache_rewind 等）。`SpecMetadata`（interface.py:478）管 RNG 窗口/拒绝采样缓冲/prompt lookahead；`SpecWorkerBase`（interface.py:1564，nn.Module+ABC）定义 forward 契约并经 `__init_subclass__` 自动注册。

**DFlash（DFLASH=13，dflash.py 2112 行）**：`DFlashWorker`（dflash.py:634）为独立 draft 模型维护**私有上下文缓存池（ctx arena）**——draft 不与 target 共享 KV 池，而是把 target 接受序列持续注入自己的缓存（块表由 `_init/_refresh_ctx_block_tables` 管理）；显存治理：`derive_dflash_ctx_memory_budget_bytes`（dflash.py:162）、`validate_dflash_ctx_buffer_budget`（dflash.py:204）、`_check_ctx_arena_fits`（dflash.py:788）。注意力后端按可用性装配（dflash_attention.py:30、dflash_attention.py:152）。

**DSpark（DSPARK=14，dspark.py 983 行，2026 新）**：`DSparkWorker`（dspark.py:831）继承 DFlashWorker 复用 ctx arena，`DSv4DSparkWorker`（dspark.py:221）是 V4 批量变体。两件新装备：其一 **Markov 偏置**，`_apply_dspark_markov_bias`（dspark.py:928）docstring 自证参照 DeepSpec VanillaMarkov.sample_block_tokens——第 i 步对共享 lm_head logits 加 `markov_w2 @ markov_w1[prev_i]`，处理 TP vocab 分片；其二**批量草稿生成**，`_draft_gen_block_batched`（dspark.py:528）CUDA-graph 安全（零 host 同步），全 gen 请求一次 forward 出 `[num_gens, K, vocab]` 块 logits；guided-decoding 专用 `_sample_draft_tokens_guided`（dspark.py:619）。

**EAGLE3/MTP 单模型线**：`Eagle3OneModelWorker`（eagle3.py:436）含常规与外部共享 target KV 两条 draft loop；`MTPEagleWorker`（eagle3.py:1302）是 MTP×EAGLE 组合；MTP 本体 `MTPWorker`（mtp.py:247）+`MTPHiddenStatesManager`（mtp.py:38）管隐状态池。动态树变体（eagle3_dynamic_tree.py:173、mtp_dynamic_tree.py:47）走 SpecTreeManager+FlashInfer 树算子。

**PARD/NGram/SA**：`PARDWorker`（pard.py:72）核心是共享 KV 借还语义——draft 后 `_apply_kv_rewind_after_draft` 回卷，避免污染 target 池。`NGramPoolManager`（ngram.py:14）维护 n-gram→续写池，`NGramDrafter`（ngram.py:161）免模型前向取草稿；进阶是 GPU 后缀自动机 `SuffixAutomatonManager`（suffix_automaton.py:76，718 行）+`SAWorker`（sa_worker.py:101）。

## 外部连接

- **工厂路由**：utils.py `get_spec_worker`（utils.py:723）按模式实例化；`update_draft_len`（utils.py:967）随 batch size 动态降 draft 长度。
- **上游**：llm_args.py 的 speculative_config（01 篇）→ 工厂 → pyexecutor 每步调度；`SpeculationGate`（speculation_gate.py:7）滑动窗口盯接受率，低于阈值**永久关闭**投机。
- **下游**：稀疏注意力的 `sparse_attn_predict` 钩子（06 篇）为 DFlash/DSpark 预测稀疏输入；`DFlashAcceptStatsRecorder`（accept_stats.py:117）记接受直方图，`calibration_table`（accept_stats.py:343）出校准表。

## 数据流

每解码步：SpecWorkerBase.forward →（MTP/EAGLE：捕获隐状态→draft loop 出 K 候选；DFlash/DSpark：隐状态注入 ctx arena→出块 logits+Markov 偏置→采样候选块）→ target 单次前向验证 → 拒绝采样对齐分布 → 接受回填 → KV 回卷 → 更新隐状态池。

## 设计决策

1. **枚举值即 ABI**：interface.py:311 把跨进程序列化稳定性写进注释，退役值不复用——配置兼容优先于枚举整洁。
2. **DFlash 独立 ctx arena 而非共享 KV**：draft 与 target 布局可能不同构，私有池+块表注入换解耦，代价是三段显存预算治理。
3. **置信度校准留接口不欠实现**：accept_stats.py:90 try/except 导入 `dspark_confidence`，失败仅不采校准行——**该模块当前不在树上**（accept_stats.py:62 注释明说随"DSpark confidence-scheduled verification MR"发货）。勘误：仓内已有 guided 采样与批量块生成，置信度调度阈值校准链路是半成品预留。
