# 02 · PyTorch 模型库百家谱：DeepSeek/GLM/Kimi/Qwen 五家新世代的落点

## 角色定位

`tensorrt_llm/_torch/models/` 是 PyTorch 后端的模型动物园（图谱 931 节点，全仓最大簇），`_torch/configs/` 是"上游 Transformers 未支持"的过渡带。新世代五家——DeepSeek V3.2/V4、GLM-5.3、Kimi K3、Qwen3.8-Flash——全在此落地。铁律：**模型文件只做装配，算力下沉到 attention/moe/custom_ops**。

## 内部结构

**DeepSeek 线（三代同堂）**：V3 与 V3.2 共居 `modeling_deepseekv3.py`——`DeepseekV3Attention`（modeling_deepseekv3.py:758）与 V3.2 变体（modeling_deepseekv3.py:809），顶层双注册（modeling_deepseekv3.py:1931）。V3.2 的 DSA 本体不在模型文件而在 `_torch/attention/backends/sparse/dsa/indexer.py`（2136 行 TopK，见 06 篇）。V4 独立成 `modeling_deepseekv4.py`：`_remap_deepseek_v4_checkpoint_keys`（modeling_deepseekv4.py:387，168 行键重映射）适配压缩 KV 新布局；mHC 残差经 hc_attn（modeling_deepseekv4.py:1789）与 hc_ffn（modeling_deepseekv4.py:1811）装配。mHC 算子本体是**跨模型共享模块** `_torch/modules/mhc/hyper_connection.py`（mHC:72/HCHead:253）——V4 与 GLM-5.3 共用。

**GLM-5.3（Glm5Next）**：配置直接继承 DeepSeek——`Glm5NextTextConfig(DeepseekV3Config)`（configs/glm5_next.py:14）。`modeling_glm5_next.py` 是复用经济范本：`Glm5NextLinearAttention(KimiKDALinearAttention)`（modeling_glm5_next.py:764）拿 Kimi 的 KDA 内核、`Glm5NextGate(DeepseekV3Gate)`（modeling_glm5_next.py:1423）拿路由、`Glm5NextIndexer`（modeling_glm5_next.py:887）+`Glm5NextSparseAttention`（modeling_glm5_next.py:977）实现 NoPE k-pool 稀疏 MLA（后端在 sparse/glm_kpool/）、mHC 经 modeling_glm5_next.py:1603 配置 GLM 语义。另有独家上下文优先打包调度（modeling_glm5_next.py:285）。

**Kimi K3**：文本核 `modeling_kimi_linear.py`——KDA 与 MLA 层按 `linear_attn_config["kda_layers"]` 交替（modeling_kimi_linear.py:286），MoE 走 `ConfigurableMoE`（:122 导入；:1202 断言必须开启），顶层 `KimiLinearForCausalLM`（modeling_kimi_linear.py:2090）。KDA kernel 群在 `_torch/cute_dsl_kernels/blackwell/kimi_k3_kda/`（fused_k1234.py 融合 K1-K4）。

**Qwen3.8-Flash（仓内名 Qwen4Exp）**：`modeling_qwen4_exp.py:15` docstring 自证对应 "Qwen3.8-Flash-Next checkpoints"。`Qwen4ExpTextConfig(Qwen3NextConfig)`（configs/qwen4_exp.py:85）继承 Qwen3-Next 的 GDN 混合基座，增量装备：PLE n-gram 旁路（`modules/qwen4_exp/ple.py`）与门控 Hyper-Connection（`hyper_connection.py`）。顶层 `Qwen4ExpForCausalLM`（modeling_qwen4_exp.py:1131）。

**vLLM 同源 workaround 带**：`configs/deepseek_v3.py:9`"temporary workaround for DeepSeek-V3.2 as HF does not support it yet"，`configs/deepseekv4.py:15` 同款；SPDX 版权行（configs/deepseek_v3.py:2）"Copyright contributors to the vLLM project"实锤拷贝自 vLLM。`DeepseekV4Config`（configs/deepseekv4.py:17）新字段 index_topk=512、compress_ratios、hash layer+mhc（configs/deepseekv4.py:63-154）即"先压缩再稀疏"的配置载体。

## 外部连接

- **注册与发现**：`tensorrt_llm/models/automodel.py`（97 行）的 AutoConfig/AutoModelForCausalLM 按 HF `architectures` 路由；`_torch/models/__init__.py:105` 的 PEP 562 `__getattr__` 配合 `_arch_index.py` 四张静态表（MODEL_ARCH_TO_MODULE:38 等）实现零启动成本懒加载，test_lazy_model_zoo.py 守护漂移。
- **权重映射层**：`checkpoints/hf/*_weight_mapper.py` 家族承担 HF 布局→TRT-LLM 布局转换。
- **上下游**：模型类实现 `get_model_defaults`（modeling_utils.py:652）给 01 篇供料；算力下沉 DSA→sparse/dsa、k-pool→sparse/glm_kpool、KDA→kimi_kda、MoE→fused_moe（05 篇）。

## 数据流

HF checkpoint 下载 → config 兜底（configs/ 过渡带或 HF 原生）→ weight_mapper/remap 键变换与量化 scale 拆装 → modeling 类实例化（meta init+PP 切分）→ 前向按层分派：全注意力→MLA/稀疏后端，KDA→线性注意力 kernel，MoE→ConfigurableMoE；投机解码统一走 SpecDecOneEngineForCausalLM（draft 与 target 同引擎）。

## 设计决策

1. **过渡带明示生命周期**：workaround 注释写明"HF 尚未支持"，SPDX 保留 vLLM 版权，上游合入后即删。
2. **复用优于新建**：GLM-5.3 继承 DeepSeek V3 配置与 Kimi KDA 内核，Qwen3.8 继承 Qwen3-Next。
3. **一个家族一个注意力子包**：DSA/glm_kpool/deepseek_v4 各有 cache_manager+indexer+module+params 四件套，模型文件不堆 per-model 分支。
