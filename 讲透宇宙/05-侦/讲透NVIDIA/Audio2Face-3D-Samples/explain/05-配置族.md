# 05 配置族：三角色 × 双模型与服务端/客户端两套方言

## 角色定位
本仓配置分两套不相通的方言。**服务端**：`configs/` 8 个 yaml——deployment_config.yaml（端口/并发/遥测）、advanced_config.yaml（输入消毒/队列/TRT 精度）、6 份 stylization 配置（claire/james/mark × regression/diffusion），被 quick-start 两 compose 经符号链接挂载消费。**客户端**：`scripts/{api_client,interaction_app}/config/config_{claire,james,mark}.yml` 各 257 行，直接喂给三套客户端脚本构造 proto 参数。

## 内部结构
**stylization 双族只差两键**（md5 级实证）：claire_stylization_config.yaml:43 `inference_type: regression` ↔ claire_diffusion_stylization_config.yaml:43 `diffusion`，且 diffusion 版仅多 :51 `constant_noise: true`——418 行文件 twins。结构四段：default_beginning_emotions（:18，10 情绪全零）→a2e（:30，enabled/live_transition_time/post_processing_params 六键）→a2f（:41，inference_type + regression_model.inference_model_id:46 / diffusion_model.{inference_model_id:49, identity:50} 双模型槽）→face_params 等微调段。**角色间**：james 与 mark 只差 inference_model_id（james_v2.3.1/mark_v2.3）+identity+5 个 face 系数（input_strength 1.0↔1.3 等）。**deployment_config.yaml**：common.stream_number:10（:21，与压测 --max-stream-nb 对齐）、端点默认 0.0.0.0:52000（:50）、telemetry 四键默认 false（:82-84）+prometheus_endpoint 0.0.0.0:9464（:96）。**advanced_config.yaml**：input_sanitization 采样率 16000-144000（:20-22）、low_fps:29/+7s 踢线（:38-39）、三级队列 1/300/1（:63-65）、TRT 精度 a2e 锁 fp32（:94）a2f fp16（:100）。**客户端 yml** 五段：face_parameters（camelCase：lowerFaceSmoothing 等 13 键）、blendshape_parameters（multipliers/offsets/enable_clamping）、post_processing_parameters、emotion_with_timecode_list、live_transition_time+beginning_emotion。

## 外部连接
消费链四条：①compose 以 `${A2F_3D_MODEL_NAME}_stylization_config.yaml` 模板串引用（docker-compose.yml:24,:43）——跑 diffusion 需设 A2F_3D_MODEL_NAME=claire_diffusion 或手动改名；②quick-start/configs 是指向 ../configs 的真符号链接（git mode 120000）；③migration 以根 configs 为 v1.2 模板基座（convert_configuration_files.py:170-172）；④config_fetching_app 反向拉取运行中服务的三份 YAML。客户端 yml 则在两目录**逐字节双拷贝**（三对 md5 全等：6bc7e102/55adb663/84a14965）。

## 数据流
静态配置流：根 configs →（符号链接）quick-start 挂载 /mnt/configs → init 容器 generate_trt_models.py 读 stylization+advanced → 服务容器 a2f_pipeline.run 读三件套。动态流：客户端 yml → write_to_stream 展开 → proto 消息字段（camelCase 键恰好就是 FaceParameters map 的合法键名）。

## 设计决策
①diffusion/regression 双模型共存于同一 schema（双槽+开关），一套配置管线服务两代推理引擎；②camelCase（客户端/proto）与 snake_case（服务端 yaml）两套命名并存是历史分层——proto map 键与 Python 侧 yaml 各自演化；③advanced 的队列-延迟权衡注释（:57-62）写得极诚实："Leave these values to default in case of doubt"；④observability compose 用 sed 原地改挂载文件开遥测（docker-compose-with-observability.yml:45-46）而非环境变量覆盖，因此根目录 deployment_config.yaml 会被运行时污染——README 特意警告。

## 新人提示
改配置三陷阱：双拷贝 yml 记得同步两处；sed 会真改你仓库里的 deployment_config.yaml（git checkout 恢复）；claire 的 face_params（lower_face_smoothing 0.006/lower_face_strength 1.25）与客户端 yml 的同义键（lowerFaceSmoothing 0.006/lowerFaceStrength 1.25）数值一致但属两份独立文件——服务端预置与客户端逐请求覆盖是两层，客户端 header 参数优先作用于当次流。
