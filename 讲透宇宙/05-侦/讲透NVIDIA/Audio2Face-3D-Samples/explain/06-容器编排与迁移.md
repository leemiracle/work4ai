# 06 容器编排与 v1.0→v1.2 迁移：部署两翼

## 角色定位
部署侧两翼：**quick-start/** 用两份 docker compose 把 NIM 容器拉起来（基础版/可观测版），**migration/** 用 dataclass 映射把 v1.0 旧配置升到 v1.2。一个管"怎么跑"，一个管"怎么从旧版迁过来"，共同上游都是根 configs/。

## 内部结构
**docker-compose.yml（72 行）**双容器接力：a2f-3d-init 跑 ./service/generate_trt_models.py（entrypoint :23-24，读 stylization+advanced 配置）把 TRT 引擎写进 a2f-3d-init-data 卷；a2f-3d-service 以 `condition: service_completed_successfully` 依赖（:40-42）后启动 a2f_pipeline.run（:43，三份 --config 全从 /mnt/configs/ 读），environment 四键（:44-48：LD_LIBRARY_PATH/USE_NEW_NVSTREAMMUX/NIM_DISABLE_MODEL_DOWNLOAD/NIM_SKIP_A2F_START），host 网络+GPU 预留（:52-59）。init-data 卷是 bind 型 local driver 锚定 ./a2f-3d-init-data（:61-67）——TRT 缓存落宿主机、删 *.trt 即重建。secrets 从 NGC_API_KEY 环境变量注入（:70-72）。**docker-compose-with-observability.yml（94 行）**三差异：service entrypoint 先两条 sed 把 metrics_enabled/traces_enabled 的 false 改 true（:44-47）；追加 jaeger all-in-one（ports 16686/4318/9411，:65-73）与 prometheus（:75-81，挂载 prometheus.yml:16-23——1s 抓取 0.0.0.0:9464，恰为 deployment_config.yaml:96 声明端点）。**migration/**：convert_configuration_files.py（339 行）双模式（CHOICE_CONVERT :30）：ucs 模式读 ucs_app_configs/a2f_config.yaml 经 UCSConfig（ucs_app_config.py:20-43，23 个 camelCase 字段）装载；docker_config 模式读两份旧 yaml 经 A2FConfig/A2FControllerConfig 两棵树（a2f_config.py:67-73 / a2f_controller_config.py:61-64）。装载器 load_yaml_to_dataclass（:104-117）按 field.metadata 的 yaml_key 递归映射；load_class 先把文本全局 replace("-","_")（:135）。角色路由 get_config_style_from_name_model（:152-162）从模型名/路径尾段认出 claire/james/mark 选 stylization 模板。核心转换两处：LIST_FACE_PARAM_ORDER 52 个 ARKit 名单（:39-92）把旧线性乘子列表 zip 成 weight_multipliers 字典（:285-286）；10 情绪线性表按索引回填 default_beginning_emotions（:214-216）。产出到 output_{N:06d}/ 三件套（:323-325）。

## 外部连接
镜像 nvcr.io/nim/nvidia/audio2face-3d:1.3（两份 compose 一致）；quick-start/configs 符号链接→根 configs；migration 模板基座 default_configs_v1_2——**git 里是 13 字节普通文本文件（内容 `../../configs`，mode 100644），不是符号链接**，convert_configuration_files.py:170-172 直接 join 读会 FileNotFoundError，须先 `ln -sfn ../../configs default_configs_v1_2` 手工还原（quick-start/configs 才是真链接 mode 120000）。

## 数据流
部署流：NGC_API_KEY→secrets→init 容器生成 TRT（挂载配置+GPU）→卷交接→service 容器起管线→52000 双向流端口就绪。迁移流：v1.0 旧 yaml→dataclass 字段映射→根 configs 模板逐键覆写（stream_number/队列/精度 fp16 开关 :238-239 等）→v1.2 三件套；docker 模式还交叉校验 a2f 与 controller 的 URL/并发一致性（:291-308 三处冲突打印）。

## 设计决策
①TRT 引擎生成独立成 init 容器而非启动时惰性编译——冷启动可缓存、服务容器无编译职责；②观测栈走"改文件+sidecar 容器"最简路径，不引入 operator；③迁移用 dataclass 显式 schema 而非逐键手抄，旧版缺键静默跳过（try/except :194-199）；④v1.2 是 NIM 1.3 的兼容基线（migration README 首句），版本链 v1.0→v1.2 config / 1.2.0 wheel / 1.3 镜像 / 根 README 已列 2.0 目录——四代版本号并存是本仓最大认知税。

## 新人提示
起服务三步：export NGC_API_KEY→cd quick-start→`A2F_3D_MODEL_NAME=claire docker compose up`；看指标 9090（Prometheus）/16686（Jaeger）；`docker compose down -v` 清缓存。迁移先补符号链接再跑 `python3 convert_configuration_files.py docker_config`；UCS 模式的 faceParams 是 JSON 字符串字段（:174 json.loads 解析），别当普通 map 用。
