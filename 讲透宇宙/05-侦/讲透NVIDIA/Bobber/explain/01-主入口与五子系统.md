# 01 · 主入口 bobber.py 与五子系统总览

## 角色定位

`bobber/bobber.py`（409 行）是整个框架的唯一用户入口——`setup.py:31` 的 `entry_points console_scripts` 把 `bobber` 命令绑定到 `bobber.bobber:main`。它不做测试也不做解析，只干三件事：把 CLI 参数变成 `Namespace`、把命令路由到正确子系统、把可复现性（config dump/load）管起来。五个子系统的分工：CLI 门面（本文件）、`lib/docker`（镜像与容器）、`lib/tests`（测试编排）、`lib/analysis`（解析聚合）、`lib/system`+`constants`+`exit_codes`（文件、常量、退出码）。

## 内部结构

- `parse_args(version)`（`bobber.py:65-253`）：单函数 189 行构建 12 个子命令。7 个 run-* 测试命令共享 `commands_parent` 父解析器（`bobber.py:87`），一次声明 `log_path`/`hosts` 两个位置参数（`bobber.py:91-95`）和约 20 个通用 flag；`build/export` 零参数，`cast` 多 `storage_path`+`--ignore-gpu`（`bobber.py:243-246`），`load` 多 `filename`（`bobber.py:251`），`parse-results` 自带 6 个输出选项（`bobber.py:206-236`）。
- `unique_hosts()`（`bobber.py:34-62`）：以 `type=` 校验器身份挂在 `--hosts` 上，`set` 去重比对（`bobber.py:59-61`），重复主机名即 `ArgumentTypeError`——Bobber 不允许同机并发。
- `load_settings()`（`bobber.py:312-358`）：参数合成三优先级——`--config-path` 指向的历史 JSON 一票通过（`bobber.py:339-340`）；否则 `--system` 预设先 `setattr` 进副本（`bobber.py:345-347`），用户显式 flag 再覆盖（`bobber.py:350-352`）；最后把 `--no-direct` 翻译成 `direct` 数值属性（`bobber.py:354-357`）。
- `execute_command()`（`bobber.py:361-393`）：parse/build/export/cast/load 五命令直连 docker 门面；测试命令走 `version.replace('.', '_')`（`bobber.py:389`）→ `load_settings` → `create_directory` → `save_config` → `test_selector`。

## 外部连接

上游 import `bobber.__version__`（`bobber.py:6`）与 `constants` 的 17 个命令常量/系统表（`bobber.py:7-27`）。下游三条边：`parse_results.main` 7 参数直传（`bobber.py:375-378`）、`bobber.lib.docker` 门面五方法（`bobber.py:380-386`）、`run_tests.test_selector`（`bobber.py:393`）。`lib/docker/__init__.py:9-13` 的模块级方法别名让门面调用形如普通函数。

## 数据流

一次 `run-all` 的控制流：CLI → `Namespace` → config 落盘 `{log_path}/command_parameters.json`（`bobber.py:308`）→ 逐迭代×逐节点组合派发六类测试（`run_tests.py:315-321` 固定顺序 nccl→meta→bw→dali→iops→125k）→ 每类测试在容器内跑脚本、日志按 `systems_N_version_X` 协议命名（如 `run_tests.py:82-90`）。`--sweep` 时节点列表从 1 台逐台累加（`run_tests.py:344-348`），产出扩展性曲线数据。

## 设计决策

- **位置参数+父解析器共享**：所有测试命令签名一致，降低记忆成本；代价是 `parse-results` 的 `log_path` 与测试命令的 `log_path` 语义不同（读 vs 写），同名不同义。
- **`--system` 预设字典注入而非 argparse default**：一份预设跨多 flag 生效，还能被单个 flag 部分覆盖。代价是键名必须与 argparse dest 完全一致——`constants.py:17` 用 `bw_threads`（下划线）而 `constants.py:41` 用 `bw-threads`（连字符），DGX_2 预设 setattr 出的连字符属性与消费端 `args.bw_threads`（`run_tests.py:84`）错位，预设等于失效，这是本仓最典型的一致性坑。
- **config dump 是验收可复现的支点**：文件名协议+参数 JSON 双保险，让"上次那个结果怎么跑出来的"永远可回答。

## 新人提示

改任何 flag 先 grep 三处：`bobber.py` 参数区、`run_tests.py` 文件名模板、对应 `*_multi.sh`。读入口从 `main()`（`bobber.py:396-405`）进，40 行内看完全部分发逻辑；不要从 `parse_args` 读起，189 行参数墙容易迷路。`command_parameters.json` 是调试参数合成问题的最快窗口——直接看最终生效值，不用推预设与覆盖的叠加。
