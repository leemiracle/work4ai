# 02 精讲：三策略族与拓扑探测层（任务书"rm 三后端族"的源码实态）

> 勘误钉版：本仓**没有 rm/ 目录**（全仓无该路径，find 实证）。任务书与图谱 L02 层的"静态/NVML/共享三后端"是错误前提——源码里真实的三族是 **Policy 接口的三个实现族**（Simple / BestEffort / StaticDGX×3），加上喂养它们的 **internal/links 拓扑探测层**。本文按实态讲。

## 角色定位

策略族是库的"大脑皮层"：全部实现同一个单方法接口 `Policy.Allocate(available, required, size)`（gpuallocator/allocator.go:31）。Allocator 完全不懂拓扑，只管账本；选哪几块 GPU 的智能全在策略里。internal/links 则是"感觉器官"——把 NVML/sysfs 的原始拓扑翻译成可评分的 P2PLinkType 枚举。

## 内部结构

**Simple**（simple_policy.go:13-35）：防御四连（size≤0/不够/required 超量/required 不在 available 中全返回空），然后 required 全要 + 按 Index 排序补足（simple_policy.go:32-33）。无拓扑感知。

**BestEffort**（besteffort_policy.go:37-98）：库的算法重心。三步走——① `iterateGPUPartitions`（:218-299）枚举全部等尺寸划分：先 padding 到能整除（:241），首元素固定法去重等价划分（:275-276），剪掉"部分 padding"集合（:282-285）；② 取**划分总分**最高者而非单集合最高分（:57-69）——注释（:26-36）说透了动机：链路非层次化，贪心不保证整体最优，且假设未来分配同尺寸；③ 最优划分内取最高分集合，且过滤含 padding 的（:74-83）。`iterateGPUSets`（:164-213）用 indices/level 数组迭代展开 size 层嵌套 for（注释 :173-186），零递归。

**StaticDGX×3**（staticdgx_policies.go）：三张硬编码 validSets 表（DGX-1 Pascal :50-55 双卡 {0,2},{1,3}…；DGX-1 Volta :74-79 双卡 {0,3},{1,2}…；DGX-2 :98-104 十六卡），`findGPUSet`（:111-156）查表分配。

## 外部连接

拓扑层两文件：internal/links/device.go 定义 P2PLinkType（:27-57，PCIe 7 档+NVLink 18 档）；`GetP2PLink`（:116-139）经 NVML 公共祖先层级映射（:131 注释记录了 NVML_TOPOLOGY_CPU→NODE 上游改名）；`GetNVLink`（:142-201）状态机式逐条累计，**尾部 TODO(klueska) 明言未处理 NVSwitch 语义**（:198）。pciinfo.go 用类型别名惯用法（:30）给 nvml.PciInfo 挂方法：BusID 规范化裁 0000 前缀（:34-48）、**NumaNode 绕过 NVML 直读 sysfs**（:65）。besteffort 以别名 `nvml` 导入 links 包（besteffort_policy.go:9-12，TODO 注明待迁入 go-nvlib）。

## 数据流

设备发现时（device.go:114-134）O(n²) 对每对 GPU 调 GetP2PLink+GetNVLink 填 Device.Links → BestEffort 评分时 `calculateGPUPairScore`（besteffort_policy.go:307-377）消费 Links：NVLink 每条 100 分（1-18 条=100-1800），PCIe 层级 10-60 分（CrossCPU=10…SameBoard=60），pair 双向不对称直接 panic（:316-319）。集合分=所有 pair 之和（:381-389），划分分=集合分之和（:393-401）。

## 设计决策

① **全局划分寻优 vs 贪心**：为"未来同尺寸分配"预留最优性，代价是组合爆炸（8 卡 4 组合尚小，大节点需警惕）。② **迭代器+回调替代物化**：全部组合枚举走 callback，不落盘中间切片。③ **StaticDGX 是 2019 年史前方案**：GPUType 只有 Pascal/Volta（staticdgx_policies.go:10-13），无 Ampere+；`NewStaticDGX1Policy` 非法类型**返回 nil 而非 error**（:28）；size 非表键（如 3）静默空手而归。④ **探测与策略解耦**：links 在 internal/，策略只认 P2PLinkType，未来迁移 go-nvlib 只动一处。

## 新人提示

- 新机型（Ampere 及以后）一律用 BestEffort；StaticDGX 仅历史兼容。
- DGX-2 策略零测试：`NewDGX2VoltaNode` 是 `return nil` 空壳（common_test.go:410-412），staticdgx_test.go 只覆盖 DGX-1 两代。
- 自研策略必须保证返回设备 ⊆ available 且不含 nil——违反即在 Allocator.Allocate 处 panic（allocator.go:90-91）。
- PciInfo.CPUAffinity 把 NUMA 节点号当亲和值（pciinfo.go:52-59），Details() 打印成 SocketAffinity（device.go:181）——三个名字一个数，读码别迷路。
