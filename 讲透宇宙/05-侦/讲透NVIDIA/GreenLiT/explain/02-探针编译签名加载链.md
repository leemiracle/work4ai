# 02 · 探针编译签名加载链：从 make 到 insmod 的内核观测闭环

## ① 角色定位

GreenLiT 最硬核的能力是"Python 测试现场编译并加载内核探针"。本篇以 PCIe ASPM saved-state 测试为标本：`src/modules/pci/glt_test_pci.py` 的 `test_pci_aspm_saved_state_update`（glt_test_pci.py:590）驱动 `aspm_saved_state_probe/` 下的 C 探针与 Makefile，签名由 `sign_kernel_module`（glt_utils.py:190）承接。验证缺陷 DGX-8962/commit 6d4266675279（glt_test_pci.py:597-598）：ASPM 重编程时 saved Link Control 未同步，错误恢复后用过期配置。mm/bingo、cppc、i2c kretprobes 皆同模式范式。

## ② 内部结构

**Python 驱动**四道门禁：policy sysfs 存在（L600）；内核 config 齐备（glt_test_pci.py:68-75 读 `/boot/config-$(uname -r)`，要求 CONFIG_PCIEASPM/KPROBES/KRETPROBES）；make/insmod/rmmod 可用（L622-626）；有候选策略（L56-65）。核心段在 chdir_managed 内（glt_test_pci.py:641）：`make`（L643）→签名（L644）→`insmod`（L650-656）。

**C 探针**：五个计数器+spinlock（aspm_saved_state_probe.c:52-57）；`greenlit_first_arg`（.c:59-70）条件编译取第一参数——`#if CONFIG_ARM64` 取 `regs->regs[0]`、`#elif CONFIG_X86_64` 取 `regs->di`、其他架构 pr_warn+NULL；内核私有结构**镜像定义**（.c:20-39，避开未导出符号）；kretprobe 表（.c:187-194）挂 `pcie_config_aspm_link`：entry 快照调用前 LNKCTL（.c:143-157），ret 差分并查 saved state（.c:159-185），两处 `NOKPROBE_SYMBOL` 防递归；计数经 procfs 导出（.c:196-226，含 nmissed）；init 注册 probe+proc_create_single（0600，.c:228-243）。Makefile 标准 out-of-tree：obj-m+`KDIR ?=/lib/modules/$(uname -r)/build`（Makefile:3）。

**签名工具**（glt_utils.py）：MOK 三常量（glt_utils.py:43-45，`/var/lib/shim-signed/mok` 下 MOK.priv/MOK.der）；`is_secure_boot_enabled`（L78-111）先 mokutil 再回退 efivars；`_find_sign_file`（L141-180）四级查找——`SIGN_FILE_OVERRIDE=/usr/local/bin/sign-file`（glt_utils.py:138，服务 Buildroot）→PATH→发行版 headers→glob 兜底；`chdir_managed`（L452-468）同步 `PWD` 环境变量（shell=False 子进程需要正确 cwd）。

## ③ 外部连接

向上经 `@GLTCore.GLTTestAttr()` 进调度体系，结果用 skip/fail 回传。四个外部触点：**sysfs**——读写 `/sys/module/pcie_aspm/parameters/policy`（L35；方括号解析 L41-53），写 policy 触发内核重调 `pcie_config_aspm_link`（探针的食物来源）；**procfs**——`/proc/greenlit_pci_aspm_saved_state`（L36），`_read_aspm_probe_hits`（glt_test_pci.py:186-193）按 key=int 逐行解析；**构建系统**——内核 headers+make；**Secure Boot 生态**——MOK 与 dkms/shim-signed 同路径（secure-boot.md:35：复用既有 DKMS 密钥），bingo.ko/kretprobe.ko 同模式。

## ④ 数据流

观测闭环：①insmod 后取基线计数（L665）；②对每个候选策略：写 alternate（L675）→写回 original（L677）→读 after 计数（L679）。内核随之重编程链路，entry/ret 各触发一次——ret：LNKCTL 调用前后与 MASK（.c:13，ASPMC+CLKREQ）按位与不同则 transition++；再遍历 `saved_cap_space` 找 PCIe cap 保存块（.c:72-90）与活值比对，相等 hits++、不等 mismatch++（.c:128-141）。③用户态五组 delta 判定（L681-749）：config/transition/inspection 任一 ≤0 或 missed>0→skip；mismatch>0→**fail**"apply commit 6d4266675279"（glt_test_pci.py:736-742）；saved_state_delta≤0→fail（L744-749）。④finally 清理：恢复策略→rmmod→make clean（glt_test_pci.py:78-101）。

内核侧单向流：handler→procfs seq_file→Python。

## ⑤ 设计决策

**观测与判定分离**：探针只数数，判读全在 Python delta——阈值可迭代无需重编模块，procfs 可直接 cat 调试。

**保守失败哲学**：仅两种 FAIL——看到 saved state 且与活值不一致、或链路变了 saved state 纹丝不动——都精确指向目标缺陷；一切"看不清"（无重编程/无 transition/丢实例）一律 skip，配合 `maxactive=64` 并导出 nmissed 供保守 skip。FAIL 的排查代价远高于 SKIP，宁可少报不误报。

**签名三态门**（glt_utils.py:190-241）：SB 未开→no-op 返回 True（L204-207）；SB 开但无 MOK→False+指路 secure-boot.md（L209-215）；SB 开且密钥齐→`sign-file sha256 MOK.priv MOK.der module`（L228），测试只看 bool。

**双架构显式化**：kretprobe 拿到的是 `struct pt_regs`，arm64 取 regs[0]、x86_64 取 di（.c:59-70）——ABI 编译期确定，写死比运行时探测诚实；未知架构返回 NULL 静默 no-op。

**镜像结构体同步义务**：.c:15-19 明言 keep in sync——零符号依赖的代价是上游结构变更须手动跟，out-of-tree 探针固有税。

## ⑥ 新人提示

1. 排查先 cat `/proc/greenlit_pci_aspm_saved_state`（root）——加载后手工切 policy 即见计数器跳动。
2. SB 关闭时签名 no-op；调试先 `mokutil --sb-state`（secure-boot.md:12），再按文档生成+enroll MOK。
3. insmod 失败是 skip 不是 fail（glt_test_pci.py:657-662）——常见于 kprobe 黑名单/符号不存在。
4. make 产物 .ko/.o 留在源码目录（cleanup 只 make clean），别提交。
5. 新探针照抄三件套：.c（计数器+procfs+NOKPROBE_SYMBOL）+Makefile（obj-m/KDIR 模板）+Python 测试（门禁→chdir→make→sign→insmod→基线→动作→delta→cleanup），CONFIG_* 依赖加进门禁常量。
6. docstring 的 JIRA+PATCH 是测试"户口"，拿不到 patch 源就先问（CLAUDE.md 边界）。
