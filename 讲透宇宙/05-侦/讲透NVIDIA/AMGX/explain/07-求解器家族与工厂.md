# 07 求解器家族与工厂（include/solvers/）

## 角色定位

`include/solvers/` 是 AMGX 全部迭代求解器与平滑器的家族驻地，28 个头文件覆盖四条线：Krylov 法（PCG/PBICGSTAB/GMRES/FGMRES/IDR）、点/块松弛（Jacobi 系、Gauss-Seidel 系、Kaczmarz、块 Jacobi、DILU/ILU）、多项式平滑（POLYNOMIAL/KPZ/CHEBYSHEV）与 AMG 门面（`algebraic_multigrid_solver.h:14` 把 AMG 层级核心包装成标准 Solver）。中枢是 `solver.h`（310 行）：前 247 行定义 Solver 基类契约（`solver.h:22` `class Solver : public AuxData`），后 40 行定义静态注册表工厂（`solver.h:271` SolverFactory）。图谱中该域 42 节点（28 file+14 class），13 条 inherits 边从各派生类跨批汇入 `solver.h:Solver`——KPZ/FGMRES/GMRES/Multicolor 系与基类分属不同批次，工厂把这条继承链缝合为全库 20+ 求解器的公共契约。

## 内部结构

生命周期三段式：`solve_init`（`solver.h:152` 默认空）/`solve_iteration`（`solver.h:154` 纯虚）/`solve_finalize`（`solver.h:156`）；setup 侧 `solver_setup` 纯虚在 `solver.h:133`。求解器反过来对矩阵提需求是本家族的关键协议：`isColoringNeeded()`（`solver.h:140`）与 `getReorderColsByColorDesired()`（`solver.h:143`）两个纯虚让 MULTICOLOR_GS 等向 Matrix 申请预着色与按色列重排。FGMRES（`fgmres_solver.h:49` 派生 Solver）的 Hessenberg 矩阵直接用内嵌 cusp 容器：`fgmres_solver.h:103` `cusp::array2d<ValueTypeB, cusp::host_memory, cusp::column_major> m_H`，配 Givens 旋转 m_cs/m_sn；GMRES（`gmres_solver.h:17`）则私藏双层结构 solve_one_iteration+solve_iteration（`gmres_solver.h:70-76`），重启参数 m_R（`gmres_solver.h:30`）驱动外循环，工厂 GMRES_SolverFactory 在 `gmres_solver.h:79`。多项式线 `polynomial_solver.h:28` PolynomialSolverBase 以谱区间驱动系数。块系统公共工具 `block_common_solver.h` 全 383 行零 class，是六个 `compute_block_inverse_{row,col}_major*` 模板函数（`block_common_solver.h:108/142/196/253/283/341`）组成的共享层——对角块 GE 求逆供块 Jacobi/DILU 复用（勘误：图谱摘要写的 blockAddTail/blockScalarNorm 全仓零命中，见 README）。

## 外部连接

注册不在 solver.cu 而在 `core.cu:596-623` 集中装配：AMG（`core.cu:562`）、PCG/PBICGSTAB/GMRES/FGMRES（`core.cu:599-604`）、MULTICOLOR_GS/ILU/DILU（`core.cu:615-617`）、POLYNOMIAL/KPZ/CHEBYSHEV/KACZMARZ（`core.cu:618-621`）逐行注册，其中 CG/IDR/POLYNOMIAL/KPZ/KACZMARZ 带 `//not exposed` 注释——库内可用但不进 C API 文档。registerFactory 实现体在 `solvers/solver.cu:1045`。基类向外交接：Convergence 判敛对象（`solver.h:237`）、Scaler 方程缩放（`solver.h:219`）、ThreadManager（`solver.h:267`）与 Operator 泛型矩阵（`solver.h:216`）。

## 数据流

setup 路径：`setup(Operator&, bool)`（`solver.h:129`）→ 派生类 solver_setup 构造自身工作区（如 FGMRES 的 Krylov 基存储）。solve 路径：外层循环反复调 solve_iteration，每步后基类 `compute_norm`（`solver.h:88`）+`converged`（`solver.h:94`）判敛，残差历史存 `m_res_history`（`solver.h:230`）；粗层求解走 `try_solve`（`solver.h:126`）统一异常翻译。性能计数靠 cudaEvent 六枚（`solver.h:258-260`）记 setup/solve/iter 三段耗时。

## 设计决策

其一，求解器即平滑器：`smooth()` 默认转发 solve（`solver.h:159`），AMG 层无须为平滑器单设接口。其二，引用计数自管生命周期（`solver.h:181-183` incr/decr），支持 AMG 层间共享求解器实例。其三，静态注册表+字符串实例化（`solver.h:295` allocate、`solver.h:307` getFactories），配置字符串直接落类名，与 coloring/eigensolver 工厂同构。其四，`user_solver.h` 留外部派生注入扩展点。牺牲是 core.cu 注册块成为全家族唯一改动热点。

## 新人提示

加新求解器的三步：派生 Solver、实现四纯虚（solver_setup/solve_iteration/isColoringNeeded/getReorderColsByColorDesired）、core.cu 注册一行；若只做平滑器，优先借用 block_common_solver 的块求逆模板族。读 FGMRES 注意 `fgmres_solver.h:102` 的 `//TODO: move those to device`——Hessenberg 仍在 host，这是 FGMRES 多卡小重启数下的隐藏同步点。排查"配置字符串不识别"先查 core.cu 是否带 not exposed，再查工厂 map。
