# 05 · 坐标系与变换线 — OpenCV / UE / OpenGL 三系桥接

覆盖文件：`nvdu/core/utils3d.py`、`nvdu/core/transform3d.py`、`nvdu/core/scene_object.py`、`nvdu/viz/utils3d.py`

## 角色定位

NVDU 的本质困难不在画图，在**三个坐标系的和平共处**：NDDS 用 Unreal Engine（左手系、Z up）合成并导出标注；NVDU 的数据层以 OpenCV 约定（右手系、Z 前/X 右/Y 下）为基准存储；渲染走 OpenGL（右手系、Y up）。这条变换线是三层之间的翻译官——理解了它，仓里所有"莫名其妙的负号"都会消失。

## 内部结构

### core/utils3d.py：约定与旋转数学

- `CoordinateSystem`（utils3d.py:12-28）：三向量描述一个坐标系，默认即 OpenCV 约定（forward=[0,0,1], right=[1,0,0], up=[0,-1,0]）；被 Cuboid3d 的自定义朝向路径使用。
- `Rotator`（utils3d.py:31-127）：X/Y/Z 弧度存储；`to_rotation_matrix`（utils3d.py:62-97）按注释钉板的 **Tait-Bryan Z1X2Y3 序**合成 3x3 矩阵，注释里明言"结果序反转，ZXY 必须按 YXZ 用"——UE 与 OpenCV 旋转序差异的一手证据；`to_quaternion`（utils3d.py:100-127）同序转四元数。
- 坏点：`yaw/pitch/roll` 属性读 `self.angle`（utils3d.py:43-53，应为 `self.angles`）；`create_from_yaw_pitch_roll` 系工厂返回未定义的 `rotator(...)`（utils3d.py:55-59）——两个便捷入口都是 NameError 级死代码，实际没人调用所以从未暴露。

### core/transform3d.py：位姿容器

位置/缩放/Rotator/四元数聚合，`is_changed` 脏标记 + `to_matrix` 惰性合成（transform3d.py:20-40）。**全仓最重要的一段 hack**：合成旋转矩阵前把四元数取负——

```python
qx, qy, qz, qw = self.quaternion
test_quaternion = Quaternion([-qx, -qy, -qz, qw])   # transform3d.py:35-36
rotation_matrix = Matrix44.from_quaternion(test_quaternion)
```

TODO 注释坦承"必须翻转但原因待查、要与 NDDS 坐标转换一起改"。工程语义：UE 导出的 (x,y,z) 与 OpenCV 的轴向镜像差恰好等价于向量分量取负，四元数向量部取负即完成这次镜像。类名小写 `transform3d` 违反 PEP8，但作为最常用类型反而成了仓内惯例。

### core/scene_object.py：场景图合成

`SceneObject`（scene_object.py:11-54）维护 parent/child 与相对变换；`get_world_transform_matrix` 递归父链**左乘**合成（scene_object.py:52-54：`parent_world * relative`）。挂接 API `attach_to_object` 处理换父时的摘除（scene_object.py:24-31）。`remove_child_object` 里残留一行调试 `print('***...***')`（scene_object.py:31）。

### viz/utils3d.py：渲染侧桥接

- `get_opengl_matrixf`（viz/utils3d.py:10-17）：pyrr Matrix44（行主序）→ `GLfloat*16`（OpenGL 列主序期望），所有 glMultMatrixf 的前置。
- `opencv_to_opengl_matrix`（viz/utils3d.py:26-32）：diag(1,-1,-1,1)——**Y、Z 双翻**，OpenCV→OpenGL 的标准基底变换，Scene2d/Scene3d 的 draw 里都要乘它。
- `convert_HFOV_to_VFOV`（viz/utils3d.py:19-24）：`vfov = 2·atan(tan(hfov/2)·ratio)` 视场角换算。
- `RenderMode`（viz/utils3d.py:33-36）：GL_FILL/GL_LINE/GL_POINT 三档，对应键盘 1/2/3。

## 外部连接

- utils3d/transform3d 是 core 层零依赖的数学底座（layer L02）；scene_object 是 L03 根基，Mesh/PivotAxis/Cuboid/AnnotatedObjectInfo 全部继承它。
- camera.py 的投影矩阵解析有第四处坐标修正：翻转 `cameraProjectionMatrix` 的 [2,0]/[2,1]/[2,3]/[3,2] 四元素（core/camera.py:75-78）——UE 投影行/深度轴符号的针对性修补。
- viz/utils3d 被 viz 层全体星号导入，`opencv_to_opengl_matrix` 出现在 Scene2d.draw（viz/scene.py:55-57，2D 还要另加 viewport_height 平移）与 Scene3d.draw（viz/scene.py:84）。

## 数据流：一次顶点的完整旅程

```
UE 合成 (左手系, Z up)
  → NDDS 导出 quaternion_xyzw/location (NDDS 侧已做部分转换)
  → transform3d: 四元数向量部取负 (UE→OpenCV 镜像) ──▶ T·S·R 矩阵 (OpenCV 约定)
  → SceneObject 世界矩阵 = Σ 父链左乘
  → Scene3d.draw: 乘 opencv_to_opengl_matrix (Y/Z 双翻) ──▶ OpenGL 顶点
  → Camera.draw 灌投影矩阵 (来自内参或 UE 矩阵符号修正版) ──▶ 屏幕
```

## 设计决策

1. **修正散落在消费端**：UE→OpenCV 的符号修正分布在四段代码（四元数取负、投影矩阵四元素翻转、OpenGL 双翻矩阵、Scene2d 的 Y 平移），没有统一的"进入即转换"关卡——每处修正都对，但整体是打补丁式演化，改动任何一环都要全局搜索其余三环。
2. **脏标记惰性求值**贯穿：transform3d 的 is_changed、相机投影矩阵的 None 检查——检视工具帧率低，惰性收益小但无害。
3. **Rotator/四元数双轨**：set_euler_rotation 经 Rotator 换算四元数（transform3d.py:58-64），四元数是唯一真源，欧拉只是入口糖。
4. **教训型反例**：便捷属性与工厂方法坏掉但长期无人发现——小仓无测试时，"没人调用的 API"等价于"不存在的 API"。

## 新人提示

调试"物体画反了/镜像了"类问题时，按上面数据流图从上游往下游逐环验证：先确认帧 JSON 的 quaternion 原始值，再核对 transform3d 取负后的矩阵，最后看场景矩阵。读代码时凡见到裸负号（`-qx`、`[2,0]` 翻转、diag(-1,-1)）都值得停一秒——它们不是 bug，是坐标系和谈的条款；反过来，若有人"清理"掉这些负号，四个地方的任何一个都会让整个可视化镜像翻转。
