# 04 · 测试体系与工程链（tests / .gitlab-ci / Makefile / pyproject）

## 角色定位

五包 monorepo 的纪律层：31 个 test_*.py、382 个测试函数守护契约；根 .gitlab-ci.yml 聚合五条子流水线；每包独立 pyproject+Makefile 保证"各自发布、同版本号"。这一层决定了开源仓（GitHub）与内部源流（GitLab）的双轨形态。

## 内部结构

测试分布高度不均：core 19 个文件（api 四件 config/one_logger_provider/telemetry_config/timed_span、recorder/default_recorder、exporter 五件、core.internal 七件全测）> training_telemetry 8 > wandb 2 > otel/lightning 各 1。契约测试是主范式：单例语义（core/internal/test_singleton.py 验 TypeError 封锁直接实例化、双检锁语义）、configure 只许一次（api/test_one_logger_provider.py）、配置三级优先级合并（exporter/test_export_config_manager.py）、exporter 状态机（NOT_INITIALIZED/READY/CLOSED 误用即抛，exporter/test_logger_exporter.py 同线）。training_telemetry 侧有跨模块 integration_test.py（integration_test.py:451,460 引 conftest 重置单例）。

## 外部连接

CI 总线 .gitlab-ci.yml 只声明 test/build_deploy 两 stage（.gitlab-ci.yml:2-4），include 五个子包 .gitlab-ci.yml（.gitlab-ci.yml:8-13）——每包独立出包独立过闸。Makefile（五包同构）提供 check/format/test/publish 四命令（one_logger_core/Makefile:6-9 注释）；GIT_URL 指向 gitlab-master.nvidia.com/hwinf-dcm（Makefile:19，内部源流实证，GitHub 是开源镜像）。构建栈 Poetry（build-system 统一 poetry-core + python-semantic-release，五包版本同号 2.3.1——one_logger_core/pyproject.toml:3——语义化自动升版）；dev 依赖 black/isort/mypy/flake8/pytest/pytest-cov（core pyproject dev-dependencies 段）。安全合规痕迹：wandb 包钉 urllib3>=2.5.0（NSPECT 要求，one_logger_wandb/pyproject.toml:23-24）。

## 数据流

提交流 → 五子流水线并行（lint→test→build）→ semantic-release 按约定式提交升版本 → publish 到内部 PyPI（E2E_PYTHON_REPO 三环境变量，Makefile:9 注释）。版本运行时获取走 version.py：向上遍历找 pyproject.toml（version.py:13-22），兜底 importlib.metadata——源码 checkout 与安装态两种形态都覆盖。

## 设计决策

1. **每包独立流水线**：namespace package 的发布单元是发行版不是仓，core 改动不该强制 otel 全量回归。
2. **契约测试优先于覆盖率**：382 个函数大头在验证"语义承诺"（单例、一次性 configure、优先级、状态机），而非行覆盖。
3. **测试隔离用 conftest 重置单例**：reset 函数定义在 tests/nv_one_logger/training_telemetry/api/utils.py:17——注意函数名是 `reset_singletong_providers_for_test`，上游拼写错误（正确拼写 singleton）；conftest.py:12,20 与 test_training_recorder.py:646 等四处文件引用它，改名需五处联动。
4. **同版本号策略**：五包 2.3.1 齐步走，避免 namespace 拼装后的版本矩阵问题。

## 新人提示

跑测试前先 `pip install -e` 五个包（namespace 合并依赖安装态）；改 singleton 相关代码必看 core/internal/test_singleton.py；贡献后端时先抄 test_file_exporter 的契约测试骨架（test_file_exporter.py 同目录另有 test_export_config_manager.py 的三级优先级用例）；test_training_telemetry_provider.py:29 也能看到那个拼错的 singletong import；看到 Makefile 的内网 GIT_URL 不必惊讶——这是开源仓的出身证明。
