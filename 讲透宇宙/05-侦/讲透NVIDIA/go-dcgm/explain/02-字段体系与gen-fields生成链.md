# 02 · 字段体系与 gen-fields 生成链（dcgm_fields.h → cmd/gen-fields → const_fields.go / fields.go）

## 角色定位

字段（field）是 DCGM 数据面的统一词汇——时钟/温度/ECC/功耗/NVLink 全部编号为 FieldID。本链路回答两个问题：**3300 行常量从哪来**（生成链）与**采集时分配怎么省**（fields.go 对象池），也是 CONTRIBUTING 字段更新五步流程的载体。

## 内部结构

- **唯一输入**：`pkg/dcgm/dcgm_fields.h`（4381 行）声明字段 ID/类型/单位/别名，废弃字段带 `Deprecated:` 块注释（dcgm_fields.h:157-166）——这些注释不是文档，是生成器的**语义输入**。
- **手写解析状态机**：`cmd/gen-fields/main.go`（549 行）`parseHeader`（cmd/gen-fields/main.go:161）逐块识别注释/ifdef 嵌套/deprecated 标记；`resolveDeprecatedFieldAliases`（cmd/gen-fields/main.go:377）把废弃名解析到目标 ID（结构体 cmd/gen-fields/main.go:47）；`TemplateData`（cmd/gen-fields/main.go:55）汇聚字段+别名交 template.go 渲染。
- **legacy 兜底**：`--legacy-fields` flag（cmd/gen-fields/main.go:68-71）读 `pkg/dcgm/legacy_fields.csv`——44 行含表头即 43 个数据行（legacy_fields.csv:2 起 `DCGM_FI_DEV_GPU_UTIL,203`），curated 旧名合并进兼容层（readLegacyFieldsCSV cmd/gen-fields/main.go:102）。
- **产物**：`pkg/dcgm/const_fields.go` 3301 行，const_fields.go:17 自带 `// Code generated by gen-fields; DO NOT EDIT.`；常量之后是手写别名解析——`GetFieldID`（const_fields.go:3267）/`GetFieldIDOrPanic`（:3283）/`IsLegacyField`（:3292）。main_test.go 902 行守护解析边界。
- **采集面（fields.go，701 行）**：`WatchFields`（fields.go:141）/`WatchFieldsWithGroupEx`（:186）/`WatchFieldsWithGroup`（:210）三档监控入口；拉取入口四类——`GetLatestValuesForFields`（:390）、`LinkGetLatestValues`（:420）、`EntityGetLatestValues`（:435）、`EntitiesGetLatestValues`（:459）。
- **对象池**：泛型 `pooledSlice[T]`（fields.go:329）+`acquirePooledSlice`（:334）/`releasePooledSlice`（:349），v1/v2 双池（:358-371），热路径成对使用（:289-290）。

## 外部连接

上游：gen-fields 只认 dcgm_fields.h（换 DCGM 版本=换头文件重跑生成）。下游：`appendConvertedValues`（field_values.go:83，按需扩容 :95）消费池化切片做 v1→v2 转换；`GetValuesSince`（field_values.go:176）时间点拉取；实体组织靠 gpu_group.go（`CreateGroup` :52/`NewDefaultGroup` :57/`AddToGroup` :79/`GetGroupInfo` :152）；field_scope.go 定适用矩阵。每条 v2 记录自带 4096 字节 payload（field_values.go:49）——池化动机正源于此。

## 数据流

字段 ID 生命周期：dcgm_fields.h 枚举→parseHeader→resolveDeprecatedFieldAliases→readLegacyFieldsCSV→template.go 渲染→const_fields.go 常量+别名表。采集生命周期：`WatchFields` 注册→DCGM 后台采集→`GetLatestValuesForFields` acquire（fields.go:289）→cgo 填充→Go 转换→release 归还（:290）。

## 设计决策

1. **生成而非手写 3300 行**：字段随 DCGM 版本增删，手写必然漂移；CSV 兜底"头文件没有但生态在用"的旧名。
2. **别名解析手写在生成文件尾部**：常量可生成，查找逻辑是活代码需测试——GetFieldID/IsLegacyField 划出生成物与手工物边界（const_fields.go:3267-3292）。
3. **手写对象池**：要"池化+按需扩容+泛型双版本"，sync.Pool 给不了 slice 语义（fields.go:329-371）。
4. **v1/v2 双轨**：旧 DCGM 只产 v1，转换器保新 API 形状不变——调用方永远面对 FieldValue_v2。

## 新人提示

加字段唯一正道是五步流程：改 dcgm_fields.h → 跑 gen-fields → diff const_fields.go 验证 → 评审 → alias_resolution_test 回归。**别手改 const_fields.go**——:17 的 DO NOT EDIT 会被 pre-commit 生成物一致性检查抓住。排查"字段值拿不到"按序查：FieldID 存在性（GetFieldID const_fields.go:3267）→ 是否已 Watch（fields.go:141）→ 组是否含该实体（gpu_group.go:152）→ 回调是否被背压熔断（field_values.go:63）。
