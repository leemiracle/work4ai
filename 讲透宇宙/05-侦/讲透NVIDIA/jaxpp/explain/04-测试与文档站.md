# 04 · 测试防线与文档站：fake_devices、功能对照与无 GPU CI

## 角色定位

JaxPP 的测试体系要解决一个先天矛盾：MPMD 流水线本质需要多设备多进程，但 CI 与开发者笔记本没有 GPU 集群。答案分三层：`tests/fake_devices.py` 用假设备骗过 JAX 分布式初始化让单进程跑通大部分套件；functional_testing/ 做"MPMD 化前后行为一致"的语义对照；`examples/maximoe/tests/` 承担真机数值验收。文档站（docs/）则是同一矛盾的另一个面——CI runner 无 GPU，notebook 页用仓内预渲染副本替代执行。

## 内部结构

`tests/fake_devices.py`（83 行）是全部单进程 MPMD 测试的地基：_FakeClient（`tests/fake_devices.py:24`）伪造分布式 client、_FakeMemory（`tests/fake_devices.py:31`）伪造内存、_FakeDevice（`tests/fake_devices.py:51`，device_kind 就叫 "fake gpu"）伪造设备，make_mesh（`tests/fake_devices.py:77`）组装出可用的 MpmdMesh。主套件全景：test_mpmd_api.py（2116 行，实验 API 最大测试集，覆盖 task/transfer 追踪、send/recv 生命周期、TaskPrimitive 等）；test_schedules.py（503 行，TestSchedules 在 `tests/test_schedules.py:54` 参数化全家族调度器）；test_dime2.py（547 行，SendRecvTest 在 `tests/test_dime2.py:61` 覆盖 NCCL send/recv 生命周期、缓冲复用与延迟读取）；test_transformations.py（522 行，replace_captured_meshes 系列）；test_licm.py（68 行）/test_training.py（52 行）两个小专项；test_task_compile.py/test_jit_shardings.py/test_mpmd_array.py/test_mpmd_mesh.py/test_reshard_utils.py/test_dlpack.py/test_utils.py 各守一域。功能对照层：`tests/functional_testing/test_dropout_enabled.py`（162 行，DropoutEnabledModel 验证开 dropout 的 Flax 模型 MPMD 化后与原始执行一致）与 test_passthrough_vars.py（未被流水线消费的直通变量保值）。MaxiMoE 侧：model_test.py（1899 行，优化路由 EP、context parallel attention、dedup 交换、RaggedDotCombine 数值对照）、ragged_dot_sm90/sm100_test.py 两代内核测试、backend_test.py（后端分派断言 primitive_names/xla_operation）；test_util.py 提供 MaximoeTestCase 基类与 kernel_launches/kernel_names 计数助手（`examples/maximoe/src/maximoe/test_util.py:26/:35/:41`）。

## 外部连接

运行器 `scripts/run_tests.sh`：先全量 pytest（隔离 test_mpmd_array），再按 JAXPP_FAST_INFER_SHARDINGS/LICM 等 flag 矩阵复跑关键用例——把编译开关组合当一等测试维度。多进程测试由 `src/jaxpp/distributed_utils.py` 支撑：distributed_main 装饰器（`src/jaxpp/distributed_utils.py:25`）负责各进程初始化，JaxDistributedTest 基类（`src/jaxpp/distributed_utils.py:46`）挂 setUp/tearDown 钩子。CI 侧 `.github/workflows/documentation.yml`：runner 是无 GPU 的 ubuntu-latest（`.github/workflows/documentation.yml:27`），`docs/compilation.md`/`docs/unreduced_gradients.md` 两个 MyST notebook 页在 build 时被 docs/rendered/ 预渲染副本替换（`.github/workflows/documentation.yml:49-51`），再 sphinx-build -W -D nb_execution_mode=off（`.github/workflows/documentation.yml:74`）；deploy job 仅 main 分支、持 pages:write 权限。供应链防御在这个仓做到少见的高度：步骤钉 SHA（harden-runner@4d991eb…，`:36`）、persist-credentials: false（`.github/workflows/documentation.yml:43`）、`scripts/setup-env.sh:8` 硬编码 UV 安装器 SHA256。

## 数据流

一次本地测试的标准路径：uv sync 装依赖（setup-env.sh 校验安装器哈希）→ run_tests.sh 起两轮（全量+flag 矩阵）→ fake_devices 提供假 mesh → 断言层分两类：调度/编译类断言 jaxpr 结构（TestSchedules 检查任务序列与约束，如 `tests/test_schedules.py:109` 验证 DualPipeV 拒绝 num_stages=4），数值类断言与参考实现对照（MaxiMoE 各 kernel test）。真机联调走 `scripts/jax-run`（单机多进程，按 --n-procs/--n-gpus-per-proc fork worker 并保留 per-rank 日志）或 `scripts/slurm/job.sh`（集群容器化，挂载 checkout 到 /workdir/jaxpp）；Docker 两层结构——Dockerfile.base 预装系统依赖+uv+NCCL，上层 Dockerfile 只删旧目录 COPY 源码（`scripts/docker/Dockerfile:17-20`），Slurm 挂载 checkout 时路径仍有效。

## 设计决策

三个决策：①测试金字塔以"离 GPU 越远越便宜"排序——结构断言（无 GPU）> 单进程数值（fake devices）> 真机对照（MaxiMoE）；②文档站"预渲染镜像"方案（docs/rendered/ 勿手编，由 docs build 生成）换取无 GPU CI 也能出带输出的 notebook 页，代价是文档与渲染副本可能短暂失同步；③functional_testing 的存在把 JaxPP 的正确性定义成"变换不变量"——MPMD 化是一种程序变换，dropout、passthrough 变量这类语义必须在变换前后保值，这是比单点断言更强的合同。

## 新人提示

跑测试前先 `bash scripts/setup-env.sh`；没有多卡就依赖 fake_devices 路径（大多数 tests/ 用例可跑）。阅读顺序建议：fake_devices.py 全文（83 行）→ test_schedules.py 的参数化模式 → test_dime2.py 的生命周期用例 → functional_testing 两篇。给库加功能时，同时准备三类断言：结构（jaxpr 形状）、单进程数值（fake mesh）、真机对照（MaxiMoE 或 examples/mpmd.py 复用）。改文档记得只改 docs/*.md 原件，rendered/ 由构建再生成，tutorial.ipynb（31 cell）同理。
