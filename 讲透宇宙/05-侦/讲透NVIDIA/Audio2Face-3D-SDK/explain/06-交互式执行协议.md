# 06 · 交互式执行协议——失效层、classifier/postprocess 双段与八算子后处理

> 锚点前缀：仓库根。行号锚全部从源码核实；本篇横跨 `audio2x-common/`、`audio2face-sdk/`、`audio2emotion-sdk/` 三域。

## 一、角色定位

交互式执行器是"编辑器工况"的执行协议：用户拖动时间轴、改参数、重算局部，而不是顺序推流。协议根在 audio2x 的 `IInteractiveExecutor`（audio2x-common/include/audio2x/interactive_executor.h:29-60）：失效层增量契约 `Invalidate/IsValid`（:36-38）、`ComputeFrame/ComputeAllFrames` 两级粒度（:48-50）、跨线程 `Interrupt`（:52-55）、可为负的 int64 样本时间戳（:43-45）。基座只定义 `kLayerNone=0/kLayerAll=1`（:33-34），具体层号由各 SDK 扩展：audio2face 的 IGeometryInteractiveExecutor 扩到 2-6（audio2face/interactive_executor.h:34-46）+ blendshape 101-103（:72-76）；audio2emotion 最简——`kLayerInference=2` 与 `kLayerPostProcessing=3` 两段（audio2emotion/interactive_executor.h:32-38），累加器别名把音频归推理段、偏好情感归后处理段（:36-38）。"双段"即 classifier 推理与 postprocess 后处理的显式分层。

## 二、内部结构

audio2emotion 的 `EmotionInteractiveExecutorBase`（interactive_executor.cpp）是协议范本。Invalidate 按层清位（:33-61：kLayerAll 落到 kLayerInference 级联清五标志，kLayerPostProcessing 单清后处理位）；ComputeFrame 严格两段——先 `ComputeInference()`（若推理结果有效则跳过，interactive_executor_classifer.cpp:107）再 `ComputePostProcessing(endFrameIndex, OnlyLastFrame)`（interactive_executor.cpp:108-112）；ComputeAllFrames 同构但回调全部帧并事后把后处理标为有效（:117-138，注释明言"不缓存后处理结果、但算完全部后标有效" :133-135）。参数写入即失效：SetInputStrength 变值才 Invalidate(kLayerInference)（:162-168），Set(PostProcessParams) 用 `AreEqual_INTERNAL` 比旧值变了才 Invalidate(kLayerPostProcessing)（:177-184）——**不变不失效**是该协议的省算关键。classifier 实现带批推理：`ComputeInference` 按 batchSize 分片跑 RunInference（interactive_executor_classifer.cpp:105-151，:128-135 分片循环），Get/SetInferencesToSkip 支持跳帧对齐（:31-56）。

## 三、外部连接

双段中的后处理段由 `PostProcessor` 承担（audio2emotion-core/postprocess.cpp:146-299）。其 Init 校验情感对应表（每项 ∈[-1, outputLength)，:161-168）并深拷贝数据（:172-179）——外部数组生命周期与处理器解耦。SetParameters 同样拷贝 beginning/preferredEmotion（:207-218），Reset 清首帧标志与两个历史缓冲（:227-235）。ComputePostProcessing 逐帧驱动 PostProcessor：帧号小于已算范围则先 Reset 后处理状态重放（interactive_executor.cpp:250），循环内取单帧推理结果 `GetInferenceOutputBuffer(0,1)`（:267）调 `RunPostProcess`（:289-291）。

## 四、数据流

`PostProcessor::PostProcess`（postprocess.cpp:237-295）是**八算子流水线**——匿名命名空间的八个纯函数（postprocess.cpp:36-142）按序施于情感向量：①`inplace_softmax` 数值稳定软化（:36-54）；②`ApplyEmotionContrast` 对比度放大后再 softmax（:56-61）；③`ApplyNullifyUnmappedEmotion` 把对应表为 -1 的情感清零（:63-71）；④`ApplyMaxEmotions` 用 nth_element 只留前 maxEmotions 大的情感（:73-92）；⑤`ApplyA2FEmotionIndexConversion` 按对应表从 a2e 索引散射到 a2f 索引（:94-109）；⑥`ApplyBlending` 与上一帧/首帧情感线性混合（:111-124）；⑦`ApplyTransitionSmoothing` 时间过渡平滑——w=dt/transitionTime 封顶 1（:126-136）；⑧`ApplyEmotionStrength` 总强度缩放（:138-142）。管线时序：首帧以 beginningEmotion 初始化 a2f 情感（:244-246）→ ②③④⑤（:250-258）→ 与首帧/上帧混合并存 prevEmotion（:261-266）→ 可选偏好情感混合（:269-271）→ 非首帧过渡平滑并存 prevBlendedEmotion（:274-282）→ ⑧（:285）→ 拷出并清 firstFrame（:287-292）。

## 五、设计决策

①**失效层而非脏标记对象**：一个整数层号即增量单位，kLayerAll 级联语义由 switch 落差实现（interactive_executor.cpp:36-44）——简单、可序列化、跨 DLL 边界只是 size_t。②**双段切在"推理贵、后处理便宜"的经济线上**：classifier 推理按批缓存复用，后处理每次全量重放（Reset+逐帧），交互改参数只重跑便宜段。③**八算子全为原地纯函数**：无分配、可单测，参数（contrast/maxEmotions/blendCoef 等）全在 PostProcessParams 一个结构里，改参只触发 kLayerPostProcessing 一层。④**勘误（上游注释笔误）**：internal/interactive_executor_postprocess.h 第 29 行开 `namespace IPostProcessModel`，第 54 行闭括号注释却写 `} // namespace IClassifierModel`——闭合的是 PostProcess 命名空间，注释抄错自同目录 classifier 头；另注意 classifier 交互实现文件名本身拼错为 interactive_executor_classifer.cpp（少一个 i），上游原样保留。

## 六、新人提示

实现自定义交互执行器先背三问：这个状态属于哪层？改它要不要 Invalidate？失效后 ComputeFrame 会不会重算到？漏 Invalidate 是"参数改了没反应"的最典型根因（对照 interactive_executor.cpp:177-184 的比较式失效写法）。读 PostProcessor 把 :250-295 的八次调用与八个匿名函数一一连线，注意 prevEmotion/prevBlendedEmotion 两次历史落盘语义不同，混用即出"情感拖影"。audio2face 侧层号拆到 2-6/101-103（audio2face/interactive_executor.h:34-46、:72-76）——层粒度随下游缓存成本递增。
