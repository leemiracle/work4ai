# 02 · 两阶段训练契约：context 先回归，render 后渲染

## 角色定位

`instant_nurec/training/` 四件（system/losses/renderer/data）+ `docs/TRAINING.md`（709 行）+ `configs/training/` 两份 yaml，共同钉死 InstantNuRec 的训练语义：**先 context（几何/外观回归）后 render（可微新视角渲染）的两阶段契约**。这是"理解与渲染解耦"哲学的代码化——phase 1 用密集监督把几何拉直，phase 2 只重初始化高斯头、冻结编码器，用可微渲染把外观磨光。

## 内部结构

**TrainingSystem**（training/system.py，LightningModule）：组装 KelvinInstantNuRec 模型（kelvin.py:44）+ TrainingLosses + 渲染监督 + PSNR 指标，含 DAv3 预训练权重初始化、BroadcastExceptions 分布式异常广播与优化器配置。

**TrainingLosses**（training/losses.py:78）：`forward` 统一入口按 phase 分流。`_context_losses`:95 覆盖上下文深度（:112-113 深度按 `distance_to_depth_scale` 换算）、置信度、RGB、法线（:162-167 余弦 `1-cos`）、语义（:153-158 cross-entropy，targets 来自 `_semantic_targets`:61）；`_render_losses` 管渲染监督。聚合工具 `_masked_mean`:28、`_weighted_masked_mean`:37、`_quantile_mean`:53（0.98 分位数聚焦难样本），`LossReturn`:22 统一返回值+skipped 字段记录跳过的损失项（如法线标签缺失时 :169）。

**渲染器**（training/renderer.py）：`render_supervision`/`_render_supervision_frame`:97 用 gsplat 3DGUT 对参考帧渲染，`RenderOutput`:29 输出 rgb/opacity/distance；相机参数适配在 `_camera_kwargs`:55-76（`_configure_gsplat_build`、`_external_distortion_gsplat_parameters`、`_ftheta_gsplat_parameters` 三路，:76 按需延迟 import `gsplat.rendering.RollingShutterType` 支持卷帘快门）；:135 注释钉版对齐参考 3DGUT 的"RGB-d"契约（opacity 加权距离）。

**断点续训**（training/data.py）：`SkipBatchSampler`:24 跳过已完成批，`TrainingDataModule`:55 的 state_dict/load_state_dict（:63-68）持久化进度，`ResumableDataModuleCallback`:147 在批末/epoch 末回写，支撑原子检查点与 Slurm 重排队。

## 外部连接

- 配方对：`configs/training/full_model_front_context.yaml`（phase 1，profile `full-model-front-v1`）与 `full_model_front_render.yaml`（phase 2），同一数据/日志结构。
- 契约文档：TRAINING.md:11-16 可训矩阵（dense 前相机两阶段可训；multiview 固定集；point-query 拒训；TokenGS 不含）；:25-26 参考配方就是 dense DAv3 前相机两阶段。
- 上游数据：NCoreInstantNuRecDataset（instantnurec_ncore.py:80）+ samplers.py 两采样器（:48/:129）喂数据。

## 数据流

InstantNuRecDataBatch（batch.py:713）→ TrainingSystem 前向 → KelvinInstantNuRec 输出 SupervisionPack → phase 1：_context_losses 对上下文帧算深度/RGB/法线/语义损失 → phase 2：renderer 对监督帧可微渲染 → _render_losses（RGB+distance）反传。phase 切换的物理动作：load phase-1 ckpt 到 `model.init_weights_paths.full`（TRAINING.md:442），Gaussian 头重新随机初始化、编码器冻结（TRAINING.md:57）。

## 设计决策

1. **两阶段而非端到端**：渲染损失梯度大而噪声，先回归后渲染更稳（TRAINING.md:25-26）。
2. **phase 2 冻结编码器**：感知底座不动的"预训练-精修"结构，Gaussian 头重init 从零学激活分布（TRAINING.md:57）。
3. **超参钉版**：每 phase 40 epochs（TRAINING.md:47）；context 损失权重法线余弦 0.2、速度 L1 1.0，render 期换天空等（TRAINING.md:63）；`ddp_find_unused_parameters_true` 两阶段都要（TRAINING.md:504）。
4. **JIT 预期管理**：phase-2 第一次渲染 JIT 编译 pinned CUDA kernel 需数分钟属正常（TRAINING.md:133，README.md:118 同款提示）。
5. **分布式异常广播**：多卡训练一张卡炸全组同步报错，避免挂死等超时。

## 新人提示

复现训练先读 TRAINING.md:11-16 对齐预期——multiview/point-query/TokenGS 都不在可训矩阵内，别按 README 的 pq-front profile 找训练配方。Waymo 数据要下载转换且转换器不产 dense 辅助 sidecar，须显式关闭对应损失（TRAINING.md:337）。看懂损失口径再调权重：quantile_mean 0.98 意味着损失只盯最差 2% 像素方向的加权（losses.py:53）。断点续训状态在 datamodule state_dict，恢复行为见 data.py:63-68。
