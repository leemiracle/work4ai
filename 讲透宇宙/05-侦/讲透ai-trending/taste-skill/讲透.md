## 一、定位：不是代码库，是"品味参数化"的提示词宪法

README 自我定名 "The Anti-Slop Frontend Framework for AI Agents"（`README.md:23`），专治 2025-2026 的具体痛点：模型会写代码，但默认审美是 AI-purple 渐变 + Inter + 三等分卡片的模板脸。交付物是 13 个可独立安装的 SKILL.md（`README.md:51`）：实现类 10 个（默认 `taste-skill` v2 及 v1 保留版、GPT 严格变体、图像先行、存量重设计、三种风格分支、反截断、Stitch 适配）与图像生成类 3 个（只产参考图）。安装名与目录名解耦：`--skill` 取 frontmatter `name:` 而非文件夹名（`README.md:54-58`），v1→v2 升级 install name 不变、原地覆盖（`README.md:70`）。

## 二、主 skill 的规则体系：四层宪法

主文件 `skills/taste-skill/SKILL.md`（1206 行 / 106 小节）是全仓精华。v2 重写动机写得直白：v1 "方向对但 agent 容易略读"，生产测试反复出现同样的 Tells（`CHANGELOG.md:91`），v2 用硬规则 + 规范骨架 + 强制检查表堵漏（`CHANGELOG.md:16-20`）。四层结构：

**1. 先读题再动笔（§0）**：生成前从六类信号（页面类型/氛围词/参考物/受众/品牌资产/静默约束）推断意图，输出一行 "Reading this as: ..." 的 Design Read（`skills/taste-skill/SKILL.md:26`）；歧义只准问一个问题（:34）；Anti-Default Discipline 明列六大 LLM 默认审美要求绕开（:39）。

**2. 三刻度盘参数化品味（§1）**：全仓最核心的抽象——把品味降维成三个 1-10 连续变量 DESIGN_VARIANCE / MOTION_INTENSITY / VISUAL_DENSITY（基线 8/6/4，:47-49），配"氛围词→刻度值"推断表与九用例预设（:53-75），后续规则按刻度分段生效（VARIANCE>4 禁居中 hero、MOTION>3 必须尊重 reduced-motion）。


**3. 诚实规则与硬禁令（§2/§4/§9）**：§2 规定 brief 读作 Material/Fluent/GOV.UK 等 12 个官方系统时必须装官方包、禁止手仿 CSS（:84），读作 glassmorphism/bento 等 8 个美学族时诚实手写；连 Apple Liquid Glass 也明确"无官方 liquid-glass.css，Web 实现一律标注近似"（:118，附录 C 给近似骨架 :1143-1202）。§4 密度最高：serif 默认禁用并封杀 LLM 最爱 Fraunces/Instrument_Serif（:180）；premium-consumer 品类的米色+黄铜 AI 默认调色板被逐 hex 封禁并给七个替代族（:193-207）；eyebrow 三节一现（:253-257）；假精确数字要么有出处要么标 mock（:327-330）。§9 AI Tells 是生产测试反推的指纹黑名单 40 余条，压轴的 9.G **em-dash 全面禁令**最具行为学洞察："agent 历史上会无视'少用'的措辞，所以这里用二值表述：零个"（:699-701），是 pre-v2 违规最多的单条 Tell（`CHANGELOG.md:36`）。

**4. 机械收口（§14）**：60+ 项 Pre-Flight 检查矩阵是最后一道闸（:910-979），eyebrow 计数甚至是机械化指令"数 `uppercase tracking` 实例，超 ceil(节数/3) 即失败"（:256）。配套 §10 模式词汇表与 §5 GSAP 规范骨架（:367-473），硬禁 `window.addEventListener('scroll')`（:509-515）。

"负面清单 + 词汇表 + 机械检查表"三件套是可复用的方法论骨架。变体各取一角放大：`gpt-tasteskill` 用模拟 Python 伪随机（prompt 字符数为种子）打破布局路径依赖（`skills/gpt-tasteskill/SKILL.md:14-20`），H1 两行铁律 + `grid-flow-dense` 无缝 bento（:34），代码前强制输出 `<design_plan>` 核验（:67-74）；`redesign-skill` 是九大类审计清单 + 七级修复优先级（`skills/redesign-skill/SKILL.md:159-169`），与主 skill §11 的 URL/导航词"永不静默变更"清单（:825-832）互为表里；`soft-skill` 的 Double-Bezel 双嵌套边框是微观工艺巅峰（`skills/soft-skill/SKILL.md:41-49`）。

## 四、与 humanizer 类 skill 的对比

两者是同一方法论的两个投影：都靠负面指纹清单起家（humanizer 禁 delve/elevate，taste-skill 禁 AI-purple/em-dash），都进化到正面词汇表。三点本质差异：**作用层**——humanizer 改文本语气，taste-skill 改视觉决策并输出可编译代码；**参数化程度**——humanizer 基本二值，taste-skill 拆成三刻度盘连续可调，"审美工程化"更进一步；**可验证性**——humanizer 只能主观评，taste-skill 的 §14 大量条目机械可数，更接近 lint 规则而非文风建议。

## 五、star 通胀视角：105k star 与 37 文件的落差

105k star 配 37 文件、零运行时依赖——每 star 不足 0.1 行代码，是 karpathy-skills 先例再现：**观点分发半径 ≠ 工程量**。价值密度在规则条目的辨识力（em-dash 禁令、米色黄铜 hex 黑名单来自作者反复跑真实生成，`CHANGELOG.md:91` 自述）而非系统复杂性；实质内容量约等于一个设计团队半年 code review 沉淀，包装成了可 npm 安装的资产。这也是 2026 star 通胀实况的标本："无官方代币"免责声明（`README.md:34`，暗示曾有人借名发币）与 sponsor 墙说明它已被当流量资产运营，绝大多数 star 是观点认同式的一次性收藏。正确姿势：读规则学方法论（可迁移），别当框架依赖（v2 experimental，`CHANGELOG.md:105`）。

## 六、使用建议

1. 主 skill v2 对落地页/作品集提升明显，但 §13 明确范围外：dashboard、数据表、多步表单不管（`skills/taste-skill/SKILL.md:896-906`），硬用反而劣化。
2. 最值得抄走的三件资产：三刻度盘参数化（任何生成类 skill 可复用）；AI Tells 黑名单 + 机械检查表（把品味变成可数断言）；output-skill 的 Scope-Build-Crosscheck + [PAUSED] 续写协议。
3. 风险：规则绑定英文排版惯例，中文站需改写 CJK 段；imagegen skill 依赖外部图像模型；保守场景锁 v1（`README.md:74-76`）。

📌 下一步：移植该仓方法论时，优先抽取"刻度盘 + 负面清单 + 机械检查表"三层骨架，并用你自己的生产失败样本替换 Tells 清单——指纹必须来自你自己的测试回合，这是 taste-skill 全仓最核心的经验。
