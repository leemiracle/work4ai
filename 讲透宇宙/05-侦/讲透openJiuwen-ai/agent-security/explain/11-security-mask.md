# 11 · foundation/security_mask：纯 stdlib 的流式脱敏状态机与全角星号

## 一、角色定位

foundation 子目录是四件套里最小的：一个 README、一份 pyproject、127 行 Python。`security_mask` 包只做一件事——**对流式文本做部分星号替换**（`foundation/security_mask/stream_mask.py:3-13`）。它是一个刻意"无策略"的库：调用方传入正则列表，脱什么、开不开，全在调用方；README 一句话钉死分工："规则和开关不在这里"（foundation/README.md:3）。

使用场景是 LLM 流式输出的实时脱敏：token 一段段到达，不能等全文到齐再过滤（那样流式就退化成批处理），也不能裸推给用户（密钥可能恰好在某个 chunk 里成形）。`StreamSensitiveMask` 就是这个"边流边脱"的小状态机。公开 API 只有两个：`StreamSensitiveMask`（流式）与 `mask_complete`（整段已到齐时的一次性捷径，stream_mask.py:115-120，实现就是 push+finish 的组合）。

值得先记录一个定位事实：**仓内零消费方**。全仓 grep 除 foundation 自身与测试外无任何 import（agent_shield/jiuwenbox/agent_ssas 均不用它）——它是按"跨项目共享基础件"预备的独立发布包（pyproject name `security-mask`），真正的调用方在仓外宿主。

## 二、内部结构

120 行里四组函数，自底向上：

1. **字符分类**（stream_mask.py:19-33）：`_TOKEN_CHARS` 是白名单——大小写字母、数字与 `._-+/=@%`，注释说明"这些字符可以出现在密钥、手机号、身份证、邮箱里"；不在集合内的字符都是分割字符（`_is_delimiter`，:25-26）。`_last_delimiter` 从 chunk 尾部倒序找第一个分割字符（:29-33）。
2. **展示规则**（stream_mask.py:36-56）：常量 `_HEAD=3 / _TAIL=4 / _MIN_HIDDEN=4`（:36-38），`_display_secret` 留前 3 后 4、中间固定四个全角星号 `＊＊＊＊`（:40）；长度 ≤4 全星号，5~10 字符时按 `shown = length - 4` 收缩两端、优先保 head（:46-53）。
3. **替换核心**（stream_mask.py:59-88）：`_mask` 先收集所有 pattern 的命中 span，按"长度降序、位置升序"排序（:69），贪心选出不重叠的命中集合——**重叠命中只留最长的一段**（:70-78）；再把选中区间按展示规则拼回去（:81-88）。
4. **流式状态机**（stream_mask.py:91-112）：`StreamSensitiveMask` 只有一个状态字段 `_pending`（待匹配段）。`push(chunk)`：chunk 里没有分割字符 → 整段并入 pending 返回空串（:101-104）；有 → 取最后一个分割字符，"pending + chunk 前缀（含该分割字符）"送进 `_mask` 输出，其后的尾巴成为新 pending（:105-107）。`finish()` 把 pending 清空并送替换（:109-112）。

模块 docstring（:5-8）用五句话讲完了整个算法，是仓内少有的"文档即规格"写法。

- **打包映射**：`package-dir = {"security_mask" = "security_mask"}`（pyproject.toml）——src 目录名与包名分离的显式映射。
- **测试**：foundation/tests/test_stream_mask.py 九个用例，覆盖缓冲语义四态（hold 到分割符/finish 收尾/无分割符/空 chunk）、最长重叠优先、非重叠全替换、短命中至少藏 4 字符、markdown 加粗共存、空 patterns 关闭语义。

## 四、数据流

一次流式脱敏的时序（对应 test_hold_until_delimiter_then_mask_key，test_stream_mask.py:8-12）：

```
patterns = [r"(?:sk|rk|pk|ak)-[A-Za-z0-9]{8,}"]

push("密钥是sk-abc")   → "密钥是"   # 最后分割符是"是"后的汉字边界；
                                 # "sk-abc" 全是 token 字符 → 留 pending
push("def999，请查收") → "sk-＊＊＊＊f999，请查收"
                                 # "，"是分割符："密钥是sk-abcdef999，"整体过 _mask
                                 # （pending 旧内容+chunk 前缀），命中完整密钥
finish()               → ""        # 无残余
```

正确性论证是本模块的灵魂：**任何由 token 字符构成的命中，必然完整落在两个分割字符之间的段内**。所以只要"最后分割符之后的内容"暂不输出，跨 chunk 边界的密钥就永远不会被截成两半而漏脱——这就是倒序找分割符（而非顺序）的原因：保留最长的可能未完成命中，同时尽早输出能确定安全的前缀。

## 五、设计决策与权衡

1. **分割符策略而非固定窗口/逐字符滑动**。替代方案（如保留尾部 N 字节缓冲）要么截断延迟不可控（N 小了漏长密钥），要么输出延迟随 N 线性增长。分割符策略的延迟上界 = "最长无分割符 token 的长度"，对自然语言（汉字、空格、标点都是分割符）通常只有几个字符。
2. **固定四颗全角星号——零长度泄漏**。星号数量不随密钥长度变化（:40），输出不泄露原文长度信息；配合"至少藏 4 字符"的收缩规则（:46-53），展示端永远遮住 ≥4 个原文字符。留前 3 后 4 是可辨识性与安全性的折中：用户能认出"这是我的 sk- 开头的 key"以便人工核对，但剩余熵不足以猜全。
3. **全角星号的 markdown 生存力**。注释两次强调不用半角 `*`：网页按 markdown 渲染时，半角星号会与模型自己写的 `**加粗**` 互相吞并（:12, :39）。测试 test_markdown_bold_keeps_mask_stars（test_stream_mask.py:55-59）固化了这条：`**sk-hppn87Eb9EY**` 脱敏后 `**** not in masked`——若用半角星号，`**sk-****b9EY**` 里的连续星号会被 markdown 解析器重新配对，脱敏标记直接消失。这是"输出环境的渲染语义反过来约束脱敏字符集"的典型案例。
4. **最长重叠优先的贪心**（:69-78）：多 pattern 命中同一区域时（宽 key 正则 vs 窄子串正则）保留信息量最大的一段，避免"宽命中被窄命中打碎、剩余片段反而露出更多"。贪心在此问题上有反例可能（最长选完可能挡住两个次长），但对密钥类场景（命中高度重叠）实践最优。
5. **空 patterns = 关闭开关**（test_stream_mask.py:62-63）：不加布尔参数，调用方传空列表即直通——库不持有任何开关状态，与"规则不在这里"的定位一致。
6. **`re` 正则作为唯一规则接口**：不内置任何密钥模式（没有 sk- 电话 身份证 任何硬编码），攻击面与维护面都留给调用方；代价是性能完全由调用方正则质量决定，且 `finditer` 对恶意回溯正则无防护。

## 六、新人提示与坑

- **正确性契约隐含在 `_TOKEN_CHARS` 里**：算法只保证"命中段全部由 token 字符构成"的 pattern 不跨 chunk 漏脱。如果你的正则会匹配含空格/汉字的内容（如 `138 0013 8000` 带空格手机号、中文地址），分割符切分可能把命中劈开而**静默漏脱**——这类 pattern 必须改写（去掉分隔符或把它们加进 `_TOKEN_CHARS`，后者会全面增大 pending）。这是使用本库最大的暗坑，模块注释只暗示未明说。
- **`push` 返回空串 ≠ 出错**。无分割符时合法返回空，消费端要能处理"流式输出暂时为空"；`finish` 忘记调用则 pending 里的尾段（恰好可能是未成形密钥）**永不脱敏**直接丢弃——若你的管道在 finish 前就把 pending 当垃圾丢掉没事，若你自己缓存了原始 chunk 拼接显示就漏了。
- **head/tail 暴露 7 个字符是设计而非缺陷**。对 `sk-` 这类格式前缀无害；但如果调用方用它脱"短 PIN 码"（≤4 已全遮）或"前缀即敏感"的场景（如手机号前三位归属地也算敏感），需要调用方自己包一层（先整体替换再展示）。
- **流式与整段结果一致性**：`mask_complete` 严格等于任意切分下 push×N + finish 的拼接（分割符在 chunk 边界的两种归属不改变输出，因为分割符本身不是 token 字符、不会被命中段包含）。写对拍测试时可以直接用这个性质。
- **别在性能敏感路径上每 chunk 编译正则**：`__init__` 只编译一次（:95），复用同一个 masker 实例；每个 chunk 新建实例会把编译成本放大 N 倍。
- **仓库定位提醒**：改这个包没有仓内调用方帮你兜回归，九个测试就是全部安全网；动 `_display_secret` 的展示规则（前 3 后 4）属于破坏性变更，应升主版本号。
