# 讲透 openai/whisper（v20250625）

Whisper 语音识别的官方 PyTorch 参考实现——论文《Robust Speech Recognition via Large-Scale Weak Supervision》(Radford et al., 2022) 配套代码。仓内只有推理与评测，无训练代码；41 个有效文件约 1.1 万行 Python，"论文即代码"的最小实现范本。

## 一、定位：这是谁、不是谁

**是**：官方 inference 参考 + 评测复现工具。核心 API：`whisper.load_model()`（`whisper/__init__.py:103`）、`model.transcribe()`（`whisper/transcribe.py:38`）、`model.decode()`（`whisper/decoding.py:793`）。**不是**：生产服务（无 batching 服务化、无流式）、非训练仓（全仓无 optimizer/backward）。生态位是"准确性基准"：faster-whisper/whisper.cpp 等加速实现都以它为对齐目标。

## 二、模型架构：mel 谱 → 双塔 Transformer → 多语言

**音频前端**（`whisper/audio.py`）：硬编码超参 `audio.py:13-22`——16kHz、N_FFT=400、HOP_LENGTH=160、30 秒块=3000 帧。`load_audio`（`audio.py:25`）不走 Python 音频库，直接 spawn ffmpeg 子进程解码（`audio.py:45-55`）再除以 32768。`log_mel_spectrogram`（`audio.py:110`）用 `torch.stft`（`audio.py:148`）+ `assets/mel_filters.npz` 预计算滤波器组（`audio.py:92`，librosa 离线产物，运行时零 librosa 依赖），三步归一化 `log10 → maximum(max-8.0) → (x+4)/4`（`audio.py:154-156`）压到约 [-1,1]。

**网络本体**（`whisper/model.py`，论文 Figure 1 直译）：`AudioEncoder`（`model.py:181`）两层 GELU 卷积（第二层 stride=2，`model.py:186-187`）把 3000 帧降到 1500 音频 token，加正弦位置编码过自注意力块栈；`TextDecoder`（`model.py:214`）用可学习位置编码、上三角 -inf 因果掩码（`model.py:231`）、交叉注意力，输出层与嵌入权重绑定（`model.py:253`）。fp16 数值稳定三件套：LayerNorm/Linear/Conv1d 覆写 forward 做 float 计算再转回 dtype（`model.py:39-59`）。`MultiHeadAttention`（`model.py:81`）双路径——SDPA 快路径（try-import 探测 `model.py:16-22`）与返回 qk 权重的手写慢路径（词级时间戳数据源）。KV 缓存用 forward hook（`model.py:317-348`）。多语言以 `n_vocab >= 51865` 判定（`model.py:311`）。`model.py:350-352` 的方法混入（transcribe/decode/detect_language 直接赋值为类属性）故 `model.transcribe()` 可用——非常规的模块组织。

## 三、tokenizer：双词汇表（勘误：非 Python+TS 双实现）

任务书原设"tokenizer 双实现（Python+TS）"——**源码实证勘误**：本仓 41 文件零 TS/JS。真正的"双"是**双词汇表**：`assets/gpt2.tiktoken`（50256 行，英文模型用 GPT-2 原版 BPE）与 `assets/multilingual.tiktoken`（50257 行），由 `get_encoding`（`tokenizer.py:331`）逐行 b64decode 构建 tiktoken.Encoding，拼上 `<|startoftranscript|>`、`<|zh|>` 语言 token 与 `<|0.00|>` 时间戳段。TS 实现在 OpenAI 的 web demo 仓，不在此仓。

`Tokenizer` dataclass（`tokenizer.py:132`）是 tiktoken 薄封装：`__post_init__` 构造 [SOT, 语言token, 任务token] 的 sot_sequence（`tokenizer.py:145-155`，语言 token id=sot+1+索引）；`decode` 过滤 >= timestamp_begin 的 token（`tokenizer.py:168`）。zh/ja/th/lo/my/yue 六个无空格语言按 Unicode 边界切词（`tokenizer.py:277`），其余按空格（`tokenizer.py:311`）。LANGUAGES 表 100 语言（`tokenizer.py:10-111`）+ 12 别名（mandarin→zh，`tokenizer.py:114-128`）。

## 四、transcribe 管线：滑窗 + 温度回退 + 幻觉防御

`transcribe()`（`transcribe.py:38`，477 行）是全仓灵魂：

1. **滑窗**：`clip_timestamps` 切片（`transcribe.py:53-58`），逐 30 秒窗 pad_or_trim + log_mel，seek 前进**依赖模型自己输出的时间戳 token**——Whisper 最巧的设计；
2. **温度回退**：`decode_with_fallback`（`transcribe.py:184`）按阶梯 (0.0,0.2,...,1.0)（`transcribe.py:43`）重试，t>0 关 beam、t=0 关 best_of；三阈值判定（`transcribe.py:208-220`）：gzip compression_ratio>2.4 判复读（`utils.py:45-47`）、avg_logprob<-1.0 判低置信、no_speech_prob>0.6 且低 logprob 判静音；
3. **上下文条件化**：前一窗输出作下一窗 prompt，作者注明关闭可防复读死循环（`transcribe.py:86-89`）；
4. **词级时间戳**：`add_word_timestamps`（`timing.py:279`）→ `find_alignment`（`timing.py:163`）在交叉注意力装 hook 抓 QK 权重、alignment_heads 稀疏掩码选头（默认解码器后半层 `model.py:279-283`；各模型精确头集硬编码于 `__init__.py:36-51` 的 base85+gzip 串），中值滤波后 DTW 对齐（CPU numba `timing.py:83` / CUDA 反对角并行 `timing.py:108` + triton kernel `triton_ops.py:14,44`）。

解码引擎 `decoding.py` 是教科书级策略模式：Inference/SequenceRanker/TokenDecoder/LogitFilter 四族抽象（`decoding.py:130/179/216/407`），`DecodingTask`（`decoding.py:508`）编排。最值得精读的是 `ApplyTimestampRules`（`decoding.py:441-505`）：时间戳成对、单调递增等语法约束直接写成 logits 掩码，滑窗机制的地基。

## 五、与论文的对应及三处勘误

论文 §2 模型→`model.py`；§2.1 前端→`audio.py:13-22`；§2.4 时间戳预测→`ApplyTimestampRules`；§3.6 词级 DTW→`timing.py`；WER 预处理→`normalizers/english.py:467`。

- **勘误一**：`normalizers` 模块包内**零消费**——`transcribe.py` 不 import 它（全仓 grep 实证），仅 `tests/test_normalizer.py:3` 与 LibriSpeech notebook（算 WER）使用，是评测专用资产而非转写管线一环；
- **勘误二**：主循环被作者刻意扁平化（`transcribe.py:149-153` 注释自认 "obscurely flattened"）；
- **勘误三**：权重 SHA256 内嵌在下载 URL 倒数第二段路径（`__init__.py:57`）非独立文件；`torch>=1.13` 才启用 `weights_only=True`（`__init__.py:150`）。

## 六、使用建议

- **选型**：`_MODELS` 13 个 checkpoint（`__init__.py:17-32`），large 与 large-v3/turbo 同 URL（`__init__.py:28-31`）；turbo=large-v3-turbo（4 解码层，≈8x 速度）；中文用 large-v3 而非 .en 系列。
- **防幻觉**：长音频设 `condition_on_previous_text=False` + `hallucination_silence_threshold`（`transcribe.py:118-120`）；`initial_prompt` 注入领域词汇是官方支持的 prompt 工程。
- **依赖**：ffmpeg 必须在 PATH；triton 仅 Linux x86_64 安装（`requirements.txt:7` 平台标记），无 CUDA 时 timing 自动走 numba CPU 路径（`timing.py:6-10`）。
- **阅读顺序**：`audio.py` → `model.py` → `tokenizer.py` → `decoding.py` → `transcribe.py` → `timing.py`，用 `tests/test_transcribe.py:11`（jfk.flac 端到端）验证理解。
