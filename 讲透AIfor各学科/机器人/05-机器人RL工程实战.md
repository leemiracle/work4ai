# 05 · 机器人 RL 工程实战 — 从仿真到真机的全链路

## §0 一张图：机器人 RL 的完整工程链路

```
┌──────────────────────────────────────────────────────────────┐
│              机器人 RL 全链路（从仿真到真机）                   │
├──────────────────────────────────────────────────────────────┤
│                                                               │
│  ① 仿真环境    ② 示教数据     ③ RL 训练     ④ 部署    ⑤ 迭代  │
│  ──────────    ──────────    ──────────    ────────   ──────  │
│  Isaac Lab     遥操作        SAC / PPO     ONNX 导出   线上数据│
│  MuJoCo MJX    ACT/DAgger    Dreamer       C++ runtime 回流   │
│  Domain Rand   BC cold-start Safety RL    安全 wrapper        │
│                                                               │
│       ←———— Sim2Real Gap（最难啃的骨头）—————→                 │
│                                                               │
└──────────────────────────────────────────────────────────────┘
```

**与 LLM RL 的根本差异**（[`讲透RL/09 §1`](../../讲透RL/09-工业实践与能力建设.md)）：
- LLM RL：数据是 token，环境是模型自己，部署就是 serving
- **机器人 RL：数据是物理交互，环境是真实世界，部署要上铁**——每一步都贵、都危险、都不可逆

## §1 仿真环境：RL 训练的"摇篮"

### 1.1 三大仿真器对比（2026）

| 仿真器 | 厂商 | 特点 | GPU 加速 | 适用 |
|--------|------|------|---------|------|
| **Isaac Lab**（Isaac Gym 继承者）| NVIDIA | 物理精确 + RTX 渲染 | ✅（大规模并行，数千环境）| 人形/机械臂主流 |
| **MuJoCo MJX**（2024 重写）| Google DeepMind | 快 + 准 + 可微 | ✅（JAX，GPU/TPU）| 学术首选 |
| **Genesis**（2024，待核）| CMU 等 | 统一物理 + 生成 | ✅ | 新生代，待验证 |

**2026 关键趋势**：**GPU 大规模并行**——Isaac Lab / MJX 能同时跑数千个环境，让 RL 样本量从"百万步"跃升到"十亿步"，这是 GR00T/Figure 训得动的 infra 基础。

## §2 示教数据：RL 的"冷启动燃料"

### 2.1 为什么 RL 不能从零开始（在真机上）

真机 RL 的致命约束（呼应 [`讲透RL/08 §2.1`](../../讲透RL/08-Actor-Critic-SACBased-OfflineRL.md)）：
- 真机每步采样 ~100ms + 物理磨损 → **几万步就到上限**
- 从零探索会撞坏机器人 / 人 / 环境
- 稀疏 reward（抓到才奖励）→ 从零学要百万步

**解法**：**先用示教数据 cold-start，再 RL 微调**。这是 2024-2026 机器人 RL 的主流范式（π0/OpenVLA/GR00T 都这么干）。

### 2.2 示教数据的三种获取方式

| 方式 | 怎么做 | 成本 | 质量 |
|------|--------|------|------|
| **遥操作（Teleop）** | 人戴 VR 手套/用空间鼠标遥控机器人 | 中（~$50/轨迹）| 高（人手精确）|
| **视频示教** | 录人做任务的视频，让模型学 | 低 | 中（无动作信号）|
| **仿真示教** | 仿真里用脚本/heuristic 生成 | 极低 | 中（仿真偏差）|

**2024 标杆**：Aloha / Mobile Aloha（斯坦福）用**双臂遥操作**，采数千条精细操作轨迹训 ACT。

### 2.3 模仿学习的三大算法

| 算法 | 核心 | 代表 |
|------|------|------|
| **BC**（Behavior Cloning）| 监督学习：$\max_\theta \mathbb{E}_{(s,a)\sim\mathcal{D}}[\log \pi(a|s)]$ | 经典基线 |
| **DAgger**（Dataset Aggregation）| 在线：策略犯错时人纠正，加进数据集 | Ross 2011 |
| **ACT**（Action Chunking Transformer）| Transformer + 动作块（一次预测多步）| Aloha 用，Zhao 2023 |

**BC 的致命问题**：**分布漂移（distribution shift）**——策略在训练分布外崩。这与 offline RL 的根本难题同构（[`讲透RL/08 §3.2`](../../讲透RL/08-Actor-Critic-SAC-ModelBased-OfflineRL.md)）。

### 2.4 示教 → RL 的过渡：AWAC 思想

[`讲透RL/08 §3.3.2`](../../讲透RL/08-Actor-Critic-SAC-ModelBased-OfflineRL.md) 的 AWAC：**用 advantage 加权的行为克隆**——好的示教克隆得多，差的克隆得少，但不出数据支持范围。这是"示教 + RL"的数学优雅解。

## §3 RL 训练：算法选择与超参

### 3.1 算法决策树

```
你的机器人任务是？
│
├─ 离散动作（如网格导航）
│   └─ DQN 家族（讲透RL/01）
│
├─ 连续动作（机械臂/人形关节）← 99% 机器人
│   │
│   ├─ 真机/样本极贵？
│   │   └─ Model-Based: Dreamer V3 / MBPO（讲透RL/08 §2）
│   │
│   ├─ 仿真/样本可承受？
│   │   └─ SAC（工业默认，讲透RL/08 §1.4）
│   │
│   └─ 只有示教数据，不能再采？
│       └─ Offline RL: AWAC / CQL（讲透RL/08 §3）
│
└─ VLA（视觉+语言+动作）← 2024-2026 新范式
    └─ 示教预训练 + RL 微调（π0/OpenVLA 路线）
```

### 3.2 SAC 在机器人的实战 knob（呼应 [`讲透RL/08 §1.4`](../../讲透RL/08-Actor-Critic-SAC-ModelBased-OfflineRL.md)）

| 超参 | 机器人推荐值 | 调参直觉 |
|------|------------|---------|
| **α（温度）** | 自动调节（SAC v2）| 不要手调，让熵维持目标 |
| **目标熵** | $-\dim(\mathcal{A})$（动作维度负值）| 连续控制的标准设定 |
| **γ（折扣）** | 0.99 | 长程任务用 0.995 |
| **replay buffer** | 1e6 | 机器人数据贵，不要扔 |
| **更新频率** | 每环境步更新 1 次 | GPU 并行时可加大 |
| **polyak τ** | 0.005 | target 软更新 |

### 3.3 训练崩溃的机器人特有模式

| 现象 | 根因 | 解法 |
|------|------|------|
| **策略发散到极端动作** | reward 尺度没归一 | reward scaling（SAC 自动）/ 动作限幅 |
| **仿真训得好真机崩** | Sim2Real gap | §4 domain randomization |
| **探索死亡** | 熵掉到 0 | 提高 target entropy / 用 curiosity |
| **Q 过估计** | deadly triad | clipped double-Q（SAC/TD3 自带）|

## §4 Sim2Real：最难的工程问题

### 4.1 Sim2Real Gap 的三个层面

| 层面 | 差异 | 解法 |
|------|------|------|
| **动力学 gap** | 仿真摩擦/质量/惯量 ≠ 真机 | **System Identification**：用真机数据校准仿真参数 |
| **视觉 gap** | 仿真渲染 ≠ 真实光照/纹理 | **Domain Randomization**：随机化仿真视觉 |
| **传感器 gap** | 仿真传感无噪声 ≠ 真机有噪声 | 加仿真噪声 / 用真实传感器数据训练 |

### 4.2 Domain Randomization 详解（呼应 [advanced/01 §5](./advanced/01-VLA数学.md)）

**核心思想**：在仿真里**大规模随机化物理 + 视觉参数**，让 policy 学到"对任何参数都鲁棒"的策略。真机只是分布中的一个采样。

```python
# 伪代码：Isaac Lab 里的 domain randomization
for each env:
    friction   ~ Uniform(0.5, 1.5)    # 摩擦
    mass       ~ Uniform(0.8, 1.2) * nominal_mass
    gravity    ~ Normal(9.81, 0.1)
    lighting   ~ random HDR env map
    texture    ~ random from library
    # 训练：policy 必须在所有组合下都工作
```

**关键洞察**：随机化范围要**覆盖真机的真实参数**。范围太小学不到鲁棒性，太大任务太难学不出。

### 4.3 Sim2Real 的三档成熟度

| 档位 | 表现 | 2026 现状 |
|------|------|----------|
| **✅ 仿真直接迁移** | 仿真训完上真机就能用 | 简单任务（抓取/推动）可达 |
| **🟡 仿真 + 少量真机微调** | 仿真 + 几十次真机 demo | 主流（π0/OpenVLA 路线）|
| **❌ 必须大量真机** | 仿真无用 | 高动力学任务（跑步/跳跃）|

### 4.4 2024-2026 的 Sim2Real 新思路

- **可微仿真**：仿真本身可微，policy 梯度直接穿过物理引擎（MuJoCo MJX）
- **真实数据蒸馏**：用真实视频蒸馏仿真（缩小视觉 gap）
- **Foundation Model 先验**：VLA 预训练给好的初始化，降低对仿真精度的依赖

## §5 部署：把 policy 推上铁

### 5.1 部署管线

```
PyTorch policy (训练)
    ↓ torch.onnx.export
ONNX 模型
    ↓ TensorRT / ONNX Runtime
C++ 推理引擎
    ↓ 接机器人控制器（ROS2 / 实时总线）
实时控制（≥100Hz）
```

### 5.2 部署的工程要求（呼应 [`讲透RL/09 §1④`](../../讲透RL/09-工业实践与能力建设.md)）

| 要求 | 数值 | 为什么 |
|------|------|--------|
| **控制频率** | ≥100Hz（人形 ≥500Hz）| 慢了机器人会震/不稳 |
| **推理延迟** | <10ms | 控制回路的硬约束 |
| **确定性** | 同输入→同输出 | 浮点不确定性导致复现失败 |
| **内存** | <2GB（边缘设备）| 人形机载算力有限 |

**工具链**：
- **ONNX**：PyTorch → 跨框架
- **TensorRT**（NVIDIA）：Jetson 边缘设备首选
- **Triton Inference Server**：多模型服务

### 5.3 安全 wrapper（[`讲透RL/06 铁律 3`](../../讲透RL/06-RL与系统软件.md) 的机器人版）

**policy 外必须包一层安全壳**：
```python
def safe_action(observation):
    raw_action = policy(observation)
    
    # 1. 动作限幅（关节角度/速度硬件极限）
    raw_action = clip(raw_action, joint_lower, joint_upper)
    
    # 2. 紧急停止（检测到碰撞/跌倒）
    if detect_collision(observation) or detect_fall(observation):
        return emergency_stop_action()
    
    # 3. 回退到经典控制（policy 不确定时）
    if uncertainty(policy, observation) > threshold:
        return pid_controller(observation)
    
    return raw_action
```

**Cold-RL 铁律在机器人域的翻译**（[`讲透RL/06`](../../讲透RL/06-RL与系统软件.md)）：**"为失败设计"** = 永远有 fallback 到 PID/阻抗控制。

## §6 2024-2026 机器人 RL 的范式转移

### 6.1 旧范式（2015-2023）：单任务 RL

```
每个任务一个 policy：抓杯子训一个、开门训一个
问题：不通用，每个任务都要百万步仿真
```

### 6.2 新范式（2024-2026）：VLA Foundation Model + RL 微调

```
1. 大规模示教预训练 → 通用 VLA（π0/GR00T/OpenVLA）
2. RL 在仿真/真机微调 → 适应具体 embodiment
3. 跨任务泛化 → 一个模型多任务
```

**这呼应了 LLM 的范式**：预训练 + 后训练（RLHF）。机器人正在重走 LLM 的路，只是把 token 换成 action。

### 6.3 2026 前沿速查

| 方向 | 代表工作 | 状态 |
|------|---------|------|
| **VLA 基础模型** | π0 / OpenVLA / GR00T / Octo | ✅ 已开源（详见 [06](./06-VLA模型谱系2026.md)）|
| **人形全身控制** | Berkeley Humanoid / Unitree G1 RL | 🟡 快速进展 |
| **灵巧手** | DexCap / Any-point Manipulation | 🟡 难度高 |
| **Sim2Real** | 可微仿真 / 真实数据蒸馏 | 🟢 持续突破 |
| **World Model for Robot** | Dreamer V3 / Genie 2 | 🟡 与 [`讲透世界模型`](../../讲透世界模型/) 交叉 |

## §7 一句话总结

> 🎯 **6 句话**：
> 1. **机器人 RL 全链路**：仿真 → 示教 cold-start → RL 训练 → Sim2Real → 部署 → 迭代，比 LLM RL 多了"上铁"的物理约束。
> 2. **算法选择**：连续控制默认 **SAC**（[`讲透RL/08 §1`](../../讲透RL/08-Actor-Critic-SAC-ModelBased-OfflineRL.md)）；样本极贵用 **Dreamer/MBPO**（model-based）；只有示教用 **AWAC**。
> 3. **Sim2Real 三层 gap**：动力学 / 视觉 / 传感器，解法是 **System ID + Domain Randomization + 真实数据**。
> 4. **示教 + RL 是 2024-2026 主流**：示教 cold-start（BC/ACT/DAgger）→ RL 微调（AWAC 思想）。
> 5. **部署要 ≥100Hz + <10ms + 确定性**，policy 外必须包**安全 wrapper**（fallback 到 PID）。
> 6. **范式转移**：单任务 RL → **VLA Foundation Model + RL 微调**，机器人正重走 LLM 的"预训练 + 后训练"之路。
