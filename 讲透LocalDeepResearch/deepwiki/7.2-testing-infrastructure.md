  This document describes the testing infrastructure for Local Deep Research, including pytest configuration, fixtures, mocking strategies, database setup, Puppeteer and Playwright UI testing, and security test suites. The project maintains a comprehensive suite of over 1700 tests across unit, integration, and end-to-end layers.

 
---

 
## Overview

 Local Deep Research uses **pytest** as its primary Python testing framework and a combination of **Puppeteer** and **Mocha** for frontend and UI automation. The infrastructure is designed for high concurrency using `pytest-xdist` and strict isolation via temporary encrypted databases and singleton reset mechanisms.

 **Key Features:**

 
 - **Pytest-based** Python test framework with extensive function-scoped fixtures [tests/conftest.py10-221](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/conftest.py#L10-L221)
 - **UI Testing Stack:** Puppeteer for functional UI, SSRF, and deep functionality tests [tests/puppeteer/package.json1-35](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/puppeteer/package.json#L1-L35) using `Mocha` and `Chai` for assertions [tests/puppeteer/package.json19-22](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/puppeteer/package.json#L19-L22)
 - **Parallel Execution:** Support for `pytest -n auto` with unique UUID-based test users to prevent collisions [tests/conftest.py48-54](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/conftest.py#L48-L54)
 - **Database Isolation:** Automatic creation of temporary SQLCipher databases per test with enforced busy timeouts [tests/conftest.py143-202](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/conftest.py#L143-L202)
 - **Mocking Infrastructure:** Centralized mock data for LLMs (Ollama, OpenAI) and search engines (arXiv, PubMed, Wikipedia, etc.) [tests/conftest.py28-42](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/conftest.py#L28-L42)
 - **Security Testing:** Dedicated suites for SSRF protection, XSS prevention, and API key UI validation [tests/puppeteer/package.json10-11](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/puppeteer/package.json#L10-L11)

## Pytest Configuration and Markers

 
### Custom Markers and Environment

 The test suite defines markers for conditional execution based on external dependency availability.

 
| Marker | Purpose | Usage |
|---|---|---|
| requires_llm | Test requires a real LLM (not a mock/fallback) | Skipped if LDR_TESTING_WITH_MOCKS=true tests/conftest.py165-170 |
| integration | Test requires live network access | Skipped by default in mock mode tests/conftest.py173-180 |

 The `pytest_configure` hook enforces a mock-first approach by default to ensure tests can run without API keys or local LLM instances [tests/conftest.py148-163](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/conftest.py#L148-L163)

### Singleton Reset Mechanism

 To support parallel testing (`pytest-xdist`), an `autouse` fixture resets global state before and after every test. This prevents state leakage between tests running on the same worker.

 
| Entity | Reset Target |
|---|---|
| SocketIOService | SocketIOService._instance = None tests/conftest.py68-72 |
| BackgroundJobScheduler | background.BackgroundJobScheduler._instance.stop(), then None tests/conftest.py77-89 |
| ProviderDiscovery | ProviderDiscovery._instance = None, _providers = {} tests/conftest.py98-112 |
| AccountLockoutManager | account_lockout._manager = None tests/conftest.py117-122 |

 **Sources:** [tests/conftest.py56-141](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/conftest.py#L56-L141)

## UI and Frontend Testing

 The project uses a multi-tier UI testing strategy primarily driven by Puppeteer.

 
### Puppeteer Functional Tests

 Located in `tests/puppeteer/` and `tests/ui_tests/`, these tests cover critical paths like research submission, export functionality, and SSRF protection [tests/puppeteer/package.json5-17](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/puppeteer/package.json#L5-L17) [tests/ui_tests/test_export_functionality.js53-113](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/ui_tests/test_export_functionality.js#L53-L113)

## Mocking Strategies

 
### Search Engine Mocks

 The system provides fixtures to mock responses from over a dozen search providers. These are centralized in `tests/conftest.py` and imported from `mock_fixtures.py`.

 
| Fixture Name | Target Service |
|---|---|
| get_mock_arxiv_response | arXiv API tests/conftest.py30 |
| get_mock_pubmed_response | PubMed API tests/conftest.py36 |
| get_mock_wikipedia_response | Wikipedia API tests/conftest.py41 |
| get_mock_google_pse_response | Google Programmable Search tests/conftest.py33 |

 
### LLM Response Mocks

 LLM interactions are mocked via `get_mock_ollama_response` to avoid external API costs and latency during standard CI runs [tests/conftest.py34](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/conftest.py#L34-L34)
