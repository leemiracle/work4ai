  The frontend build system manages JavaScript and CSS dependencies, asset bundling, and development workflows for the Local Deep Research web interface. It utilizes **npm** for package management and **Vite** as the primary build tool to ensure all frontend assets are bundled and served locally without external CDN dependencies, maintaining the project's local-first privacy policy.

## Design System: The `ldr-` Prefix

 The codebase utilizes a custom design system where all internal CSS classes and components are prefixed with `ldr-`. This prevents namespace collisions with third-party libraries like Bootstrap and establishes a clear boundary for custom logic.

### Frontend-Backend Integration

 The Flask application injects critical constants and asset helpers into Jinja2 templates:

 
 - **Vite Helpers**: `vite_hmr()` and `vite_asset('js/app.js')` are used in `base.html` to inject appropriate scripts for dev vs production [src/local_deep_research/web/templates/base.html35-41](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/templates/base.html#L35-L41)
 - **Constants Injection**: Python enums like `ResearchStatus` are injected as `window.RESEARCH_STATUS` to provide a single source of truth for frontend state management [src/local_deep_research/web/templates/base.html145-151](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/templates/base.html#L145-L151)
 - **FOUC Prevention**: A blocking script in the `<head>` detects the saved theme from `localStorage` and applies the `data-theme` attribute to `document.documentElement` before rendering [src/local_deep_research/web/templates/base.html13-33](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/templates/base.html#L13-L33)

## Security & XSS Protection

 The build system and frontend architecture prioritize security through a multi-layered XSS protection strategy, enforced by ESLint and specialized utility functions.

 
### Sanitization Pipeline

 
```

```

 **Implementation Details:**

 
 - **ESLint Enforcement**: The `no-unsanitized` plugin is configured to detect unsafe assignments to `innerHTML` and `outerHTML`, allowing only recognized sanitization methods like `DOMPurify.sanitize` or `escapeHtml` [eslint.config.js8-81](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/eslint.config.js#L8-L81)
 - **Safe HTML Setting**: The `ui.js` utility provides `safeSetHTML`, which uses `DOMPurify` if available, ensuring that even dynamic UI elements are rendered safely [src/local_deep_research/web/static/js/services/ui.js18-29](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/static/js/services/ui.js#L18-L29)
 - **Safe Logging**: `SafeLogger` is loaded as a blocking script in `base.html` to ensure that all subsequent frontend logs are handled securely from the start of the application lifecycle [src/local_deep_research/web/templates/base.html38-39](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/templates/base.html#L38-L39)
 - **News Rendering**: The news page implements `safeRenderHTML` which prioritizes `DOMPurify` but includes a safe fallback to `textContent` if the library is not yet initialized [src/local_deep_research/web/static/js/pages/news.js5-34](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/static/js/pages/news.js#L5-L34)
 - **URL Sanitization**: The `safeHref` function blocks dangerous schemes like `javascript:` or `data:` for all dynamic links generated in the UI [src/local_deep_research/web/static/js/pages/news.js37-50](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/static/js/pages/news.js#L37-L50)
