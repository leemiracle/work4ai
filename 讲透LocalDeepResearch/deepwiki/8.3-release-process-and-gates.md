  This document describes the automated release pipeline that enforces 17 security checks, runs comprehensive tests, and publishes artifacts only after all required gates pass. The release workflow orchestrates Docker image publishing and PyPI package publishing via `repository_dispatch` events to prevent security gate bypass.

## Release Trigger Mechanisms

 The release workflow [.github/workflows/release.yml1-10](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/release.yml#L1-L10) supports three trigger methods:

 
| Trigger | When Used | Behavior |
|---|---|---|
| push to main | Every merge to main | Automatic version detection from __version__.py |
| push to v*.*.* tag | Manual version tag | Uses tag version, bypasses duplicate check |
| workflow_dispatch | Manual re-run | Uses __version__.py, bypasses duplicate check |

 The workflow implements a concurrency policy [.github/workflows/release.yml16-18](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/release.yml#L16-L18) that prevents multiple releases from running simultaneously but queues new runs rather than canceling them:

## Build Job and Artifact Generation

 
### Version Extraction

 The build job [.github/workflows/release.yml193-330](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/release.yml#L193-L330) extracts the release version from `src/local_deep_research/__version__.py` [.github/workflows/release.yml228-235](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/release.yml#L228-L235)

 
### SBOM and Sigstore Signing

 The pipeline generates Software Bill of Materials (SBOM) using Trivy in both SPDX and CycloneDX formats [.github/workflows/release.yml265-287](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/release.yml#L265-L287) These are signed using **Cosign** with GitHub OIDC keyless signing [.github/workflows/release.yml293-306](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/release.yml#L293-L306)

 
### SLSA Provenance

 The `provenance` job [.github/workflows/release.yml332-345](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/release.yml#L332-L345) generates SLSA Level 3 build provenance using the official `slsa-framework/slsa-github-generator`. This attestation enables consumers to verify the build process was not tampered with.

## Dual-Token Strategy and Downstream Orchestration

 
### Dual-Token Strategy

 The pipeline uses two types of tokens to balance security and automation [.github/workflows/sync-main-to-dev.yml34-52](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/sync-main-to-dev.yml#L34-L52):

 
 - **`GITHUB_TOKEN`**: Used for standard operations, repository checks, and PR creation to ensure proper bot attribution [.github/workflows/release.yml54](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/release.yml#L54-L54) [.github/workflows/sync-main-to-dev.yml141-146](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/sync-main-to-dev.yml#L141-L146)
 - **`PAT_TOKEN`**: A Personal Access Token used to trigger downstream workflows [.github/workflows/release.yml391](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/release.yml#L391-L391) via `repository_dispatch` and to modify workflow files during sync operations [.github/workflows/sync-main-to-dev.yml52](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/sync-main-to-dev.yml#L52-L52)
 
 
### Repository Dispatch Orchestration

 Publishing to Docker Hub and PyPI is handled via `repository_dispatch` [.github/workflows/release.yml395-451](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/release.yml#L395-L451) This ensures that publishing only occurs after all gates in `release.yml` have passed.

 **Dispatch Types:**

 
 - `publish-docker`: Triggers `.github/workflows/docker-publish.yml` [.github/workflows/docker-publish.yml9](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/docker-publish.yml#L9-L9)
 - `publish-pypi`: Triggers `.github/workflows/publish.yml` [.github/workflows/publish.yml9](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/publish.yml#L9-L9)
 
 **Docker Publishing Process:**

 
 - **Multi-arch Build:** Builds `amd64` [.github/workflows/docker-publish.yml14](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/docker-publish.yml#L14-L14) and `arm64` [.github/workflows/docker-publish.yml57](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/docker-publish.yml#L57-L57) images using `docker buildx` [.github/workflows/docker-publish.yml35-79](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/docker-publish.yml#L35-L79)
 - **Security Scan:** Performs a final Trivy scan on the release image [.github/workflows/docker-publish.yml148-155](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/docker-publish.yml#L148-L155) failing on fixable HIGH/CRITICAL vulnerabilities [.github/workflows/docker-publish.yml158-166](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/docker-publish.yml#L158-L166)
 - **Manifest Creation:** Combines architectures into a single multi-platform manifest [.github/workflows/docker-publish.yml176-200](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/docker-publish.yml#L176-L200)
 
 **PyPI Publishing Process:**

 
 - **Frontend Build:** Runs `npm run build` to generate Vite assets and `manifest.json` [.github/workflows/publish.yml70-100](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/publish.yml#L70-L100)
 - **Package Build:** Uses `pdm build` to create the wheel, verifying frontend artifacts and the `.frontend-built` marker are present [.github/workflows/publish.yml141-174](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/publish.yml#L141-L174)
