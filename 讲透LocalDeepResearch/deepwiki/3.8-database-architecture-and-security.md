## Purpose and Scope

 This page documents the database architecture and security mechanisms in Local Deep Research, including per-user database isolation, SQLCipher encryption, password-derived keys, and thread-safe database access. It details the separation between the authentication database (`ldr_auth.db`) and individual user research databases (`research.db`). For web application structure and request handling, see [3.1](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/3.1) For settings management and configuration priority, see [4.1](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/4.1)

 
## Per-User Database Isolation

 Local Deep Research implements a **zero-knowledge architecture** where each user has a separate encrypted database. User isolation is enforced at the file level; there is no shared "master" research database for user content. [src/local_deep_research/database/encrypted_db.py48-55](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L48-L55)

 
### Database Separation: auth.db vs research.db

 The system maintains two distinct types of databases with different security profiles:

 
 - **Authentication Database (`ldr_auth.db`)**: A shared, unencrypted SQLite database used only for storing user metadata (usernames) and verifying existence. [src/local_deep_research/database/auth_db.py1-4](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/auth_db.py#L1-L4) It uses a global cached engine `_auth_engine` to prevent file descriptor leaks by reusing a single engine instance across the application lifecycle. [src/local_deep_research/database/auth_db.py23-45](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/auth_db.py#L23-L45)
 - **User Research Databases (`ldr_user_<hash>.db`)**: Individual SQLCipher-encrypted databases containing all research history, settings, and library data. These are only accessible after providing the correct password to derive the encryption key. [src/local_deep_research/database/encrypted_db.py182-200](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L182-L200)

## SQLCipher Encryption

 
### Encryption Parameters

 The system uses SQLCipher (AES-256-CBC) with hardened parameters. Encryption is verified at startup via `_check_encryption_available`; if the SQLCipher module is missing or non-functional, the system defaults to a security error unless unencrypted databases are explicitly allowed. [src/local_deep_research/database/encrypted_db.py141-180](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L141-L180)

 
| Parameter | Value | Implementation |
|---|---|---|
| Algorithm | AES-256-CBC | SQLCipher Default |
| KDF | PBKDF2-HMAC-SHA512 | _get_key_from_password src/local_deep_research/database/sqlcipher_utils.py132-169 |
| Iterations | 256,000 (Default) | get_sqlcipher_settings src/local_deep_research/database/sqlcipher_utils.py300-315 |
| Salt | 32-byte random | create_database_salt src/local_deep_research/database/sqlcipher_utils.py103 |
| Cipher Defaults | Applied before key | apply_cipher_defaults_before_key src/local_deep_research/database/sqlcipher_utils.py236-251 |

 
### Key Derivation Flow

 The system derives a raw hex key from the user's password using PBKDF2-HMAC-SHA512. This hex key is then passed to SQLCipher via `PRAGMA key`. This approach avoids SQL injection and escaping issues with special characters in passwords. [src/local_deep_research/database/sqlcipher_utils.py195-212](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/sqlcipher_utils.py#L195-L212)

## Thread Safety and Session Management

 
### File Descriptor Management

 To prevent "Database is locked" errors and file descriptor exhaustion (particularly in WAL mode where SQLite holds multiple handles), the system uses specific pool configurations. [src/local_deep_research/database/encrypted_db.py60-94](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L60-L94)

 
 - **`QueuePool`**: Default for the main application with `pool_size=20` and `max_overflow=40` (60 total). Fewer pooled connections reduce opportunities for out-of-order closes during `pool_recycle` which can leak file handles in SQLCipher + WAL mode. [src/local_deep_research/database/encrypted_db.py65-72](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L65-L72) [src/local_deep_research/database/encrypted_db.py107-113](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L107-L113)
 - **`StaticPool`**: Used during testing to ensure all threads share a single connection. [src/local_deep_research/database/encrypted_db.py95-96](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L95-L96)
 
 
### Thread-Local Sessions

 The `ThreadLocalSessionManager` provides persistent sessions for the lifetime of a thread. This avoids expensive SQLCipher decryption on every database access by reusing the session within the same thread. [src/local_deep_research/database/thread_local_session.py18-37](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/thread_local_session.py#L18-L37)

 
### Connection Cleanup and Resource Monitoring

 A background scheduler periodically runs `cleanup_idle_connections` to close database handles for users without active sessions or research. [src/local_deep_research/web/auth/connection_cleanup.py71-121](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/auth/connection_cleanup.py#L71-L121)

 Key maintenance tasks include:

 
 - **Pool Disposal**: Every 30 minutes, all `QueuePool` engines are disposed to release WAL/SHM file handles that accumulate due to out-of-order connection closes (ADR-0004). [src/local_deep_research/web/auth/connection_cleanup.py41-47](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/auth/connection_cleanup.py#L41-L47) [src/local_deep_research/web/auth/connection_cleanup.py154-171](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/auth/connection_cleanup.py#L154-L171)
 - **FD Monitoring**: The system monitors open file descriptors for the process to detect leaks. [src/local_deep_research/web/auth/connection_cleanup.py50-68](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/auth/connection_cleanup.py#L50-L68)
 
 
### Session Password Store

 For background tasks (like the `QueueProcessorV2`) that need to open an encrypted database without active user interaction, the `session_password_store` temporarily caches the password in memory for the duration of the user's session. [src/local_deep_research/web/auth/connection_cleanup.py115](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/auth/connection_cleanup.py#L115-L115)

## Security Implementation Details

 
### Database Integrity and Verification

 The system includes a `verify_sqlcipher_connection` utility that performs a `SELECT count(*) FROM sqlite_master` check immediately after applying the key. If this fails, it indicates an incorrect password or a corrupted database. [src/local_deep_research/database/sqlcipher_utils.py290-315](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/sqlcipher_utils.py#L290-L315)

 
### Per-Database Salts

 Every database is created with a unique 256-bit random salt stored in a `.salt` file. [src/local_deep_research/database/sqlcipher_utils.py23-38](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/sqlcipher_utils.py#L23-L38) This ensures that identical passwords across different users result in different encryption keys. [src/local_deep_research/database/sqlcipher_utils.py76-117](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/sqlcipher_utils.py#L76-L117)

 
### Alembic Migrations

 Each per-user database is individually versioned using a programmatic Alembic runner. [src/local_deep_research/database/alembic_runner.py1-7](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/alembic_runner.py#L1-L7) Migration files are validated for secure permissions (non-world-writable) to prevent arbitrary code execution during the upgrade process. [src/local_deep_research/database/alembic_runner.py52-92](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/alembic_runner.py#L52-L92)
