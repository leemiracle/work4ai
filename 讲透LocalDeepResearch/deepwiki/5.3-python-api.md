  This page documents the programmatic Python interface to Local Deep Research. It covers two primary access patterns:

 
 - **Direct Research Functions** (`quick_summary`, `generate_report`, `analyze_documents`): Run research in-process without a running server. These are suitable for enterprise integration, data pipelines, and standalone scripting.
 - **`LDRClient` HTTP Wrapper**: Connect to a running LDR Flask server over HTTP. This handles the complexities of authentication, session management, and CSRF token handling.
 
 Since version 2.0, all API access requires authentication due to the per-user encrypted database architecture [src/local_deep_research/api/client.py9-13](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/api/client.py#L9-L13)

## Direct Research Functions

 Direct functions run the full research pipeline in-process. These functions typically require a `settings_snapshot` to provide configuration context and may require a user database session.

 
### The `settings_snapshot` Pattern

 Programmatic access relies on a snapshot mechanism to ensure thread safety and avoid global state.

 
 - **Snapshot Creation**: A `settings_snapshot` is a dictionary of key-value pairs representing the application state (e.g., `rate_limiting.enabled`) [tests/rate_limiting/test_rate_limiting.py34-36](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/rate_limiting/test_rate_limiting.py#L34-L36)
 - **Thread Safety**: This snapshot is passed into core systems like `AdaptiveRateLimitTracker` to ensure consistent behavior without re-querying the database in high-concurrency environments [tests/rate_limiting/test_rate_limiting.py39-41](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/rate_limiting/test_rate_limiting.py#L39-L41)
 - **Override Support**: The `get_setting_from_snapshot` function is used throughout the codebase to prioritize snapshot values over defaults, particularly during testing and background tasks [tests/feature_tests/test_custom_context.py32-49](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/feature_tests/test_custom_context.py#L32-L49)

### Authentication and Security

 `LDRClient` manages a `SafeSession` which provides SSRF protection and allows connections to `localhost` [src/local_deep_research/api/client.py87](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/api/client.py#L87-L87)

 
 - **CSRF Extraction**: It uses regex to extract the `csrf_token` from the HTML login form [src/local_deep_research/api/client.py115-126](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/api/client.py#L115-L126)
 - **API CSRF**: After login, it fetches a dedicated API CSRF token from the `/auth/csrf-token` endpoint [src/local_deep_research/api/client.py148-154](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/api/client.py#L148-L154)
 - **Headers**: Subsequent requests include the `X-CSRF-Token` header for validation [src/local_deep_research/api/client.py165-169](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/api/client.py#L165-L169)
