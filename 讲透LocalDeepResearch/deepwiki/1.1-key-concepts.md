## Purpose and Scope

 This document defines the core architectural concepts of Local Deep Research (LDR). It outlines the system's "zero-knowledge" security model, the iterative research execution flow, the unified document management system (Library/RAG), and the hierarchical configuration system. This page serves as a technical foundation for understanding how data flows from a user query to an encrypted, searchable knowledge base.

 
---

 
## Zero-Knowledge Architecture

 LDR is designed with a **zero-knowledge architecture** where user data is isolated into per-user encrypted databases. The system does not store a central password hash; instead, the user's password is used directly as the decryption key for their SQLCipher database [src/local_deep_research/database/sqlcipher_utils.py172-192](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/sqlcipher_utils.py#L172-L192)

 
### Per-User Encrypted Databases

 Each user has a dedicated `.db` file located in the `encrypted_databases` directory within the data root [src/local_deep_research/database/encrypted_db.py54-55](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L54-L55) If a user forgets their password, the data is mathematically unrecoverable because the encryption key is derived from that password.

 
| Property | Implementation |
|---|---|
| Encryption Engine | SQLCipher (AES-256-CBC) src/local_deep_research/database/encrypted_db.py2-4 |
| Key Derivation | PBKDF2-HMAC-SHA512 src/local_deep_research/database/sqlcipher_utils.py132-169 |
| KDF Iterations | Configurable (Default: 256,000) src/local_deep_research/database/sqlcipher_utils.py191-192 |
| Salt Management | Per-database random .salt files src/local_deep_research/database/sqlcipher_utils.py76-116 |
| Isolation | One SQLite file per username src/local_deep_research/database/encrypted_db.py18 |

 
### Connection Pooling and FD Management

 LDR uses `QueuePool` for production environments to handle concurrent web requests while limiting File Descriptor (FD) usage [src/local_deep_research/database/encrypted_db.py61-94](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L61-L94) To prevent FD leaks in SQLCipher's WAL mode, the system implements a `pool_size=20` and periodic disposal of pooled connections [src/local_deep_research/database/encrypted_db.py68-81](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L68-L81) The `ThreadLocalSessionManager` further ensures that each background thread maintains its own session to avoid expensive decryption on every access [src/local_deep_research/database/thread_local_session.py18-37](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/thread_local_session.py#L18-L37)

## Research Execution Lifecycle

 
### Multi-Strategy Research

 Research is not a single LLM call but an iterative loop. LDR supports over 30 strategies (e.g., `focused-iteration`, `source-based`, `langgraph-agent`) created via the `create_strategy` factory [src/local_deep_research/search_system_factory.py32-177](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/search_system_factory.py#L32-L177)

 
### Thread-Safe Settings Snapshots

 To prevent race conditions where a user changes settings while a research task is running, the system captures a snapshot. This is an immutable dictionary of all settings at the moment the research thread is spawned [src/local_deep_research/api/research_functions.py20](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/api/research_functions.py#L20-L20) The `_get_setting` utility handles the extraction of values from this nested dictionary structure [src/local_deep_research/search_system_factory.py19-30](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/search_system_factory.py#L19-L30)

 
### Strategy Factory

 The `create_strategy` function in `search_system_factory.py` instantiates specific strategy classes based on the user's selected `strategy_name`. It handles mapping settings from the `settings_snapshot` (like `knowledge_summary_limit` or `adaptive_questions`) to the strategy's internal configuration [src/local_deep_research/search_system_factory.py83-145](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/search_system_factory.py#L83-L145)

## The Library and RAG System

 
### Unified Document Model

 The **Library** is a collection of document entities. A document can originate from a research download (e.g., an ArXiv PDF) or a manual user upload. Every research session finds valuable sources which are downloaded and indexed into an encrypted library [README.md108-118](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L108-L118)

 
### Strategy-Specific Performance

 Certain strategies are optimized for specific benchmarks or data structures. For example, `TopicOrganizationStrategy` organizes search results into topic clusters with lead sources [src/local_deep_research/advanced_search_system/strategies/topic_organization_strategy.py16-23](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/advanced_search_system/strategies/topic_organization_strategy.py#L16-L23)

 
| Entity | Role |
|---|---|
| SourceBasedSearchStrategy | Iterative question generation → parallel search → final synthesis src/local_deep_research/advanced_search_system/strategies/source_based_strategy.py22-57 |
| FocusedIterationStrategy | Progressive entity-focused exploration optimized for SimpleQA; uses adaptive questions src/local_deep_research/advanced_search_system/strategies/focused_iteration_strategy.py40-51 |
| TopicOrganizationStrategy | Organizes sources into topics using a TopicGraph and FindingsRepository src/local_deep_research/advanced_search_system/strategies/topic_organization_strategy.py148-150 |
| LangGraph Agent | Autonomous agentic research mode where the LLM decides search engine selection README.md104 |

## Settings Hierarchy and Priority

 LDR employs a multi-layered configuration system. Settings are often read from a frozen `settings_snapshot` to ensure thread safety during long-running research tasks [src/local_deep_research/api/research_functions.py98-111](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/api/research_functions.py#L98-L111)

 
 - **Bootstrap Settings**: Environment variables required before the database is opened (e.g., `LDR_BOOTSTRAP_ALLOW_UNENCRYPTED`) [README.md89](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L89-L89)
 - **Environment Overrides**: Prefixed with `LDR_`, these can override database values (e.g., `LDR_MAX_CONCURRENT`) [src/local_deep_research/defaults/default_settings.json122](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/defaults/default_settings.json#L122-L122)
 - **Database Settings**: Values stored in the user's encrypted database.
 - **Settings Snapshot**: A frozen dictionary passed to components like `AdvancedSearchSystem` to ensure consistent behavior throughout a research session [src/local_deep_research/search_system.py93-94](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/search_system.py#L93-L94)
