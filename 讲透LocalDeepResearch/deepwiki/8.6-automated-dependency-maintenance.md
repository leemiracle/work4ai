## Purpose and Scope

 This document describes the automated dependency maintenance system that keeps Local Deep Research's dependencies up-to-date. The system uses a staggered weekly schedule to update PDM dependencies, NPM dependencies, and pre-commit hooks through automated pull requests. Additionally, an auto-versioning workflow creates pull requests for version bumps after merges to the main branch, while image pinning validation ensures supply chain security.

 For information about the broader CI/CD pipeline, see [Continuous Integration Workflows](https://deepwiki.com/LearningCircuit/local-deep-research/8.1-continuous-integration-workflows). For details on security scanning of dependencies, see [Security Scanning Infrastructure](https://deepwiki.com/LearningCircuit/local-deep-research/8.2-security-scanning-infrastructure).

## Maintenance Schedule and Strategy

 Local Deep Research uses a **staggered weekly update strategy** where different dependency types are updated on specific days. This approach prevents conflicts between concurrent updates and allows each update to be tested in isolation.

 
### Weekly Schedule

 
| Day | Time (UTC) | Workflow | Artifacts Updated |
|---|---|---|---|
| Monday | 09:00 | Zizmor Security Scan | Workflow security audit .github/workflows/zizmor-security.yml8 |
| Wednesday | 08:00 | PDM Dependency Update | pdm.lock .github/workflows/update-dependencies.yml16 |
| Thursday | 08:00 | NPM Dependency Update | package-lock.json (Root & UI Tests) .github/workflows/update-npm-dependencies.yml16 |
| Friday | 08:00 | Pre-commit Hook Update | .pre-commit-config.yaml .github/workflows/update-precommit-hooks.yml5 |

### Security-First Update Process

 The NPM update workflow prioritizes security by performing vulnerability fixes before general updates:

 
 - **Security Audit**: Checks for vulnerabilities at moderate severity or higher using `npm audit` [.github/workflows/update-npm-dependencies.yml57](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/update-npm-dependencies.yml#L57-L57)
 - **Vulnerability Fix**: Applies automatic fixes to the lockfile using `npm audit fix --package-lock-only` [.github/workflows/update-npm-dependencies.yml65](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/update-npm-dependencies.yml#L65-L65)
 - **Version Update**: Updates to latest compatible versions with `npm update --package-lock-only` [.github/workflows/update-npm-dependencies.yml76](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/update-npm-dependencies.yml#L76-L76)
 - **Integrity Verification**: Installs from lockfile with `npm ci` to verify package integrity hashes [.github/workflows/update-npm-dependencies.yml85](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/.github/workflows/update-npm-dependencies.yml#L85-L85)

## Security and Compliance Summary

 The automated maintenance system incorporates multiple security measures to protect the software supply chain:

 
| Feature | Implementation |
|---|---|
| Harden Runner | All maintenance workflows use step-security/harden-runner with egress-policy: audit to monitor outbound network calls .github/workflows/update-npm-dependencies.yml35-37 |
| Integrity Checks | npm ci verifies lockfile integrity hashes against the downloaded packages .github/workflows/update-npm-dependencies.yml85 |
| Hash Pinning | Tools like pip and pre-commit-update are installed with fixed versions and hashes in CI workflows .github/workflows/update-precommit-hooks.yml35-38 |
| Workflow Security | zizmor scans GitHub Actions workflows for template injection, excessive permissions, and unpinned actions .github/workflows/zizmor-security.yml35-58 |
| Dual-Token Strategy | Uses PAT_TOKEN for workflow modifications and GITHUB_TOKEN for PR creation to prevent self-approval issues .github/workflows/sync-main-to-dev.yml34-52 |
