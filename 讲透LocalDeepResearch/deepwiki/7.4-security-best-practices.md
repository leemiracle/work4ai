## Purpose and Scope

 This page documents security best practices for contributors to Local Deep Research. It covers the security review process, critical security patterns (SSRF, XSS, CSRF), input validation, SQLCipher implementation details, and account lockout mechanisms. The codebase prioritizes encryption-at-rest, SSRF prevention, and strict input validation to maintain its privacy-focused, zero-knowledge architecture.

## Security Review Process

 The repository uses an automated system to flag PRs that modify security-critical files. This provides warnings and checklists to ensure that changes to authentication, encryption, or core security logic undergo rigorous scrutiny.

## Critical Security Patterns

 
### SSRF Protection (`safe_requests` and `ssrf_validator`)

 Local Deep Research enforces strict Server-Side Request Forgery (SSRF) protection for all outbound HTTP requests. This is critical as the application fetches data from user-provided URLs and third-party search engines.

 
#### SSRF Validation Logic

 The `validate_url` function in `ssrf_validator.py` performs the following checks:

 
 - **Scheme Check:** Only `http` and `https` are permitted [src/local_deep_research/security/ssrf_validator.py21](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/ssrf_validator.py#L21-L21) [src/local_deep_research/security/ssrf_validator.py136-140](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/ssrf_validator.py#L136-L140)
 - **IP Blocklist:** Hostnames are resolved to IPs and checked against `BLOCKED_IP_RANGES` [src/local_deep_research/security/ssrf_validator.py14-15](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/ssrf_validator.py#L14-L15) [src/local_deep_research/security/ssrf_validator.py164-185](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/ssrf_validator.py#L164-L185)
 - **AWS Metadata Protection:** The AWS metadata IP (`169.254.169.254`) is explicitly and always blocked [src/local_deep_research/security/ssrf_validator.py18](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/ssrf_validator.py#L18-L18) [src/local_deep_research/security/ssrf_validator.py78-79](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/ssrf_validator.py#L78-L79)
 - **Private Network Restrictions:** Loopback and private RFC1918 ranges are blocked by default unless `allow_private_ips` is True for trusted internal services like Ollama [src/local_deep_research/security/ssrf_validator.py52-67](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/ssrf_validator.py#L52-L67) [src/local_deep_research/security/ssrf_validator.py85-89](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/ssrf_validator.py#L85-L89)
 
 
#### Safe Request Execution

 The `safe_get` function wraps the `requests` library with additional guards:

 
 - **Manual Redirect Handling:** Standard `requests` auto-redirects are disabled. Each hop is manually validated against SSRF rules [src/local_deep_research/security/safe_requests.py177-195](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/safe_requests.py#L177-L195)
 - **Response Size Guard:** A `MAX_RESPONSE_SIZE` (1GB) is enforced to prevent memory exhaustion [src/local_deep_research/security/safe_requests.py27](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/safe_requests.py#L27-L27)
 - **Bounded Reader:** The `_install_body_guard` function wraps the raw reader to terminate connections if the size limit is exceeded during streaming [src/local_deep_research/security/safe_requests.py44-70](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/safe_requests.py#L44-L70)

### Notification Security and Webhooks

 Outbound notifications via Apprise carry a residual SSRF risk due to a DNS-rebinding TOCTOU window. To mitigate this, the system implements multi-layered gates.

 
| Security Layer | Implementation | Purpose |
|---|---|---|
| Master Switch | LDR_NOTIFICATIONS_ALLOW_OUTBOUND | Env-only gate; disables outbound requests by default src/local_deep_research/notifications/manager.py103-105 |
| URL Validation | NotificationURLValidator | Blocks unsafe schemes (file, data, javascript) and private IPs src/local_deep_research/security/notification_validator.py28-58 |
| Private IP Toggle | LDR_NOTIFICATIONS_ALLOW_PRIVATE_IPS | Env-only switch to allow local network notifications src/local_deep_research/notifications/manager.py93-95 |
| Service Isolation | NotificationService | Enforces master switch and performs validation before every send src/local_deep_research/notifications/service.py154-161 |

### File Write Verification

 To maintain the encryption-at-rest model, unencrypted file writes are strictly controlled. The system uses a "default-deny" approach for writing user data to disk.

 
 - **`write_file_verified`**: Checks a specific configuration setting (e.g., `api.allow_file_output`) before performing a write [src/local_deep_research/security/file_write_verifier.py64-128](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/file_write_verifier.py#L64-L128)
 - **`write_json_verified`**: Automatically redacts sensitive keys (passwords, API keys) from dictionaries before serialization [src/local_deep_research/security/file_write_verifier.py130-180](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/file_write_verifier.py#L130-L180)
 - **Sensitive Keys**: `SENSITIVE_KEYS` includes `api_key`, `secret`, `token`, `credentials`, etc [src/local_deep_research/security/file_write_verifier.py14-32](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/file_write_verifier.py#L14-L32)
 - **Automated Scanning**: The `.github/scripts/check-file-writes.sh` script scans for unauthorized uses of `open()`, `.write()`, or `Path.write_text()` in the codebase [github/scripts/check-file-writes.sh13-40](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/github/scripts/check-file-writes.sh#L13-L40)

## Authentication and Web Security

 
### Account Lockout and Brute Force Prevention

 The system implements a robust lockout mechanism to prevent credential stuffing:

 
 - **`AccountLockoutManager`**: Records failures and successes per username via `record_failure` and `record_success` [src/local_deep_research/web/auth/routes.py147-159](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/auth/routes.py#L147-L159)
 - **Lockout Check**: The login route checks `lockout_mgr.is_locked(username)` before verifying credentials [src/local_deep_research/web/auth/routes.py107-117](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/auth/routes.py#L107-L117)
 - **Rate Limiting**: Custom decorators like `@login_limit` restrict login attempts per IP [src/local_deep_research/web/auth/routes.py86-87](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/auth/routes.py#L86-L87)
 - **Session Management**: `session.clear()` is called during login to prevent session fixation [src/local_deep_research/web/auth/routes.py162](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/auth/routes.py#L162-L162)
 
 
### CSRF Protection

 
 - **Flask-WTF**: All POST requests require a CSRF token.
 - **Token Endpoint**: A dedicated `/auth/csrf-token` endpoint allows frontend components to fetch tokens programmatically [src/local_deep_research/web/auth/routes.py47-60](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/auth/routes.py#L47-L60)
 
 
### SQLCipher Encryption

 
 - **Password-Derived Keys**: Per-user databases are encrypted using the login password via PBKDF2-HMAC-SHA512 with 256,000 iterations [SECURITY.md59-62](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/SECURITY.md?plain=1#L59-L62)
 - **Error Handling**: `DatabaseInitializationError` is handled specifically to avoid locking users out for server-side configuration issues (like world-writable migration directories) while still failing securely [src/local_deep_research/web/auth/routes.py126-143](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/auth/routes.py#L126-L143)
 - **Memory Security**: The `cipher_memory_security` pragma can be enabled via `LDR_DB_CONFIG_CIPHER_MEMORY_SECURITY=ON` to zero internal buffers and prevent swapping, requiring `IPC_LOCK` capability in Docker [SECURITY.md75-106](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/SECURITY.md?plain=1#L75-L106)
