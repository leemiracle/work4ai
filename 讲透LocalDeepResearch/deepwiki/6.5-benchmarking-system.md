## Purpose and Scope

 The Benchmarking System provides automated evaluation of the Local Deep Research (LDR) system against standardized datasets such as **SimpleQA** (fact-checking) and **BrowseComp** (complex browsing). It executes research queries from benchmark datasets, evaluates the generated responses against ground truth answers using an evaluation LLM, and tracks accuracy metrics over time. This infrastructure allows systematic testing of different configurations, models, and search strategies to ensure high performance [src/local_deep_research/benchmarks/web_api/benchmark_service.py1-25](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/web_api/benchmark_service.py#L1-L25)

 The system is designed for both web-based interactive benchmarking via the Flask UI and high-throughput CLI/script-based optimization using **Optuna** to find ideal hyperparameters for specific hardware or model combinations [src/local_deep_research/benchmarks/web_api/benchmark_routes.py63-132](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/web_api/benchmark_routes.py#L63-L132) [src/local_deep_research/benchmarks/optimization/optuna_optimizer.py51-138](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/optimization/optuna_optimizer.py#L51-L138)

## System Architecture

 The benchmarking architecture bridges high-level evaluation requirements with low-level research execution. It utilizes a dedicated `BenchmarkService` to orchestrate runs and an in-memory `BenchmarkQueueTracker` for task lifecycle management.

## Core Components

 
### Benchmark Service and Queue Tracking

 The `BenchmarkService` manages the lifecycle of a benchmark run, including dataset loading, configuration hashing, and result persistence [src/local_deep_research/benchmarks/web_api/benchmark_service.py125-126](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/web_api/benchmark_service.py#L125-L126)

 
 - **Task Tracking:** The `BenchmarkQueueTracker` provides a thread-safe in-memory store for task status using `BenchmarkTaskStatus` (e.g., `QUEUED`, `PROCESSING`, `COMPLETED`, `FAILED`, `CANCELLED`) [src/local_deep_research/benchmarks/web_api/benchmark_service.py29-50](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/web_api/benchmark_service.py#L29-L50) It includes an opportunistic cleanup mechanism for old tasks via `cleanup_completed_tasks()` to prevent memory bloat [src/local_deep_research/benchmarks/web_api/benchmark_service.py92-93](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/web_api/benchmark_service.py#L92-L93)
 - **Configuration Hashing:** `generate_config_hash()` creates an MD5 hash of search parameters like `iterations`, `model_name`, and `search_strategy`. This ensures that benchmark results are only compared against compatible system configurations [src/local_deep_research/benchmarks/web_api/benchmark_service.py148-167](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/web_api/benchmark_service.py#L148-L167)
 - **Run Orchestration:** `create_benchmark_run()` initializes the database record in the user's encrypted `research.db` using `get_user_db_session` and prepares the environment for execution [src/local_deep_research/benchmarks/web_api/benchmark_service.py185-188](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/web_api/benchmark_service.py#L185-L188)

### Datasets and Evaluation

 The system supports multiple benchmark datasets and automated grading through LLM-based verification.

 
 - **Dataset Loading:** `load_dataset()` handles retrieval of benchmark data. It currently supports `SimpleQA` and `BrowseComp` [src/local_deep_research/benchmarks/web_api/benchmark_service.py23](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/web_api/benchmark_service.py#L23-L23)
 - **Automated Grading:** `grade_single_result()` uses an evaluation LLM to compare research output against the `ground_truth` answer [src/local_deep_research/benchmarks/web_api/benchmark_service.py24](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/web_api/benchmark_service.py#L24-L24) Structured answers are extracted from raw LLM responses using `extract_answer_from_response()` [src/local_deep_research/benchmarks/web_api/benchmark_service.py24](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/web_api/benchmark_service.py#L24-L24)

### Optuna-Based Optimization

 The `OptunaOptimizer` provides automated hyperparameter tuning to find optimal settings for research quality and speed [src/local_deep_research/benchmarks/optimization/optuna_optimizer.py51-52](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/optimization/optuna_optimizer.py#L51-L52)

 
 - **Search Space:** It explores parameters such as `search.iterations` and `search.questions_per_iteration` via `_get_default_param_space()` [src/local_deep_research/benchmarks/optimization/optuna_optimizer.py153](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/optimization/optuna_optimizer.py#L153-L153)
 - **Multi-Metric Optimization:** It balances `quality` and `speed` using configurable weights (default 60% quality, 40% speed) to ensure the system is both accurate and responsive [src/local_deep_research/benchmarks/optimization/optuna_optimizer.py109-110](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/optimization/optuna_optimizer.py#L109-L110)
 - **Persistence:** Optimization studies are stored in a SQLite database to allow pausing and resuming trials over long periods [src/local_deep_research/benchmarks/optimization/optuna_optimizer.py156-163](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/optimization/optuna_optimizer.py#L156-L163)

## Performance Measurement

 
### Resource Tracking and Concurrency

 Benchmarks are subject to the same resource constraints as standard research tasks to ensure realistic performance profiles.

 
 - **Concurrency Control:** Benchmark execution is governed by the `_global_research_semaphore`, ensuring benchmarks do not overwhelm the server's LLM or search capacity [src/local_deep_research/benchmarks/web_api/benchmark_service.py15](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/web_api/benchmark_service.py#L15-L15) [src/local_deep_research/web/services/research_service.py15](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/research_service.py#L15-L15)
 - **Latency Profiling:** The `SpeedProfiler` measures execution time for each trial, which is integrated into the Optuna objective function to penalize excessively slow configurations [src/local_deep_research/benchmarks/optimization/optuna_optimizer.py26-28](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/benchmarks/optimization/optuna_optimizer.py#L26-L28)
