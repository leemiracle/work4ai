## Purpose and Scope

 The Settings Management system in Local Deep Research provides a hierarchical configuration architecture that balances persistence, environment-based overrides, and thread-safe execution. The core of this system is the `SettingsManager` class, which interacts with an encrypted SQLCipher database to store user-specific preferences while respecting global server-wide constraints [src/local_deep_research/settings/manager.py150-185](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/settings/manager.py#L150-L185)

 This page details the implementation of the `SettingsManager`, the dual-mode submission system for web forms, validation logic, and the integrity checks used to maintain configuration consistency.

## Dual-Mode Submission (AJAX/POST)

 The settings interface supports two distinct submission modes to ensure accessibility (No-JS environments) while providing a modern user experience [src/local_deep_research/web/routes/settings_routes.py6-39](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L6-L39) This is particularly critical for handling HTML checkboxes, which do not submit a value when unchecked.

 
### Mode 1: AJAX/JSON Submission (Primary)

 Used when JavaScript is enabled. The `settings.js` component intercepts the form submission and reads values directly from the DOM.

 
 - **Endpoint**: `/settings/save_all_settings` [src/local_deep_research/web/routes/settings_routes.py10](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L10-L10)
 - **Checkbox Handling**: Values are read via `checkbox.checked` and sent as JSON booleans [src/local_deep_research/web/routes/settings_routes.py12-13](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L12-L13)
 
 
### Mode 2: Traditional POST (Fallback)

 Used in No-JS environments or for progressive enhancement [src/local_deep_research/web/routes/settings_routes.py17-23](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L17-L23)

 
 - **Endpoint**: `/settings/save_settings` [src/local_deep_research/web/routes/settings_routes.py17](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L17-L17)
 - **Hidden Fallback Pattern**: Each checkbox has a corresponding hidden input (managed by `checkbox_handler.js`). If the checkbox is unchecked, the hidden input provides the value `"false"` to ensure the key is captured [src/local_deep_research/web/routes/settings_routes.py20-23](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L20-L23)

## Type Validation and Coercion

 The system uses the `ui_element` metadata to determine how to validate and coerce incoming data. This ensures that a "number" input is never stored as a string in the database [src/local_deep_research/web/routes/settings_routes.py180-199](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L180-L199)

 
### Validation Logic

 The `validate_setting` function in `settings_routes.py` performs the following checks:

 
 - **Type Coercion**: Converts the input using `get_typed_setting_value` (which handles JSON parsing and numeric casting) [src/local_deep_research/web/routes/settings_routes.py172-178](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L172-L178)
 - **Numeric Constraints**: Checks `min_value` and `max_value` for `number`, `slider`, and `range` types [src/local_deep_research/web/routes/settings_routes.py186-194](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L186-L194)
 - **Option Constraints**: For `select` elements, ensures the value exists in the `options` list, excluding `DYNAMIC_SETTINGS` like `llm.provider`, `llm.model`, or `search.tool` [src/local_deep_research/web/routes/settings_routes.py197-201](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L197-L201)
 
 
### Namespace Validation

 New settings created via the web API are subject to prefix validation. Allowed prefixes include `app.`, `llm.`, `search.`, and `rag.` [src/local_deep_research/web/routes/settings_routes.py98-121](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L98-L121) Blocked prefixes include `auth.`, `security.`, and `server.` [src/local_deep_research/web/routes/settings_routes.py122-131](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L122-L131)

 
### Boolean Parsing Semantics

 The `parse_boolean` function implements specific HTML checkbox semantics where the presence of a value (even strings like "on" or "enabled") evaluates to `True`, while explicit "false", "off", "0", or empty strings evaluate to `False` [src/local_deep_research/settings/manager.py28-69](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/settings/manager.py#L28-L69)

## Integrity Checks and Golden Master

 To prevent configuration drift and ensure the system remains stable across updates, Local Deep Research employs "Golden Master" integrity checks.

 
### Golden Master Integrity Checks

 The codebase includes a `golden_master_settings.json` file which serves as the authoritative source for default configuration schemas [tests/settings/golden_master_settings.json1-15](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/settings/golden_master_settings.json#L1-L15)

 
 - **Purpose**: Validates that no essential settings are deleted or modified in a way that breaks backward compatibility.
 - **Enforcement**: Tests compare the active `default_settings.json` against the golden master to detect unauthorized schema changes.
 
 
### Thread-Safe Snapshots

 During research, the system uses `SnapshotSettingsContext` to freeze settings [src/local_deep_research/settings/manager.py12-13](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/settings/manager.py#L12-L13) This ensures that even if a user changes their LLM provider in the UI while a research thread is running, the active thread continues to use the parameters it was started with, preventing state corruption [src/local_deep_research/web/services/research_service.py11-12](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/research_service.py#L11-L12)

 
### Global Concurrency Control

 The server-wide research limit is enforced using a global semaphore `_global_research_semaphore` initialized from the `env_registry` or environment settings [src/local_deep_research/web/services/research_service.py36-40](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/research_service.py#L36-L40)
