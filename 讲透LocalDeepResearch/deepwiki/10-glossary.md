  This glossary defines core technical terms, architectural patterns, and domain-specific jargon used within the Local Deep Research (LDR) codebase. It is intended to assist onboarding engineers in navigating the relationship between conceptual system components and their implementations.

 
## Core Architectural Terms

 
### SQLCipher

 The primary security mechanism for data at rest. LDR uses SQLCipher to provide 256-bit AES encryption for all user databases [README.md15](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L15-L15) Unlike standard SQLite, SQLCipher requires a key (derived from the user's password using PBKDF2) to open the database file [src/local_deep_research/database/encrypted_db.py31-33](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L31-L33) LDR implements a "per-database salt" strategy where a `.salt` file is stored alongside each `.db` file to enhance cryptographic isolation [src/local_deep_research/database/sqlcipher_utils.py76-85](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/sqlcipher_utils.py#L76-L85)

 
 - **Code Pointer:** `DatabaseManager` [src/local_deep_research/database/encrypted_db.py48-55](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L48-L55) `set_sqlcipher_key` [src/local_deep_research/database/sqlcipher_utils.py195-212](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/sqlcipher_utils.py#L195-L212)
 - **Sources:** [src/local_deep_research/database/encrypted_db.py1-58](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L1-L58) [src/local_deep_research/database/sqlcipher_utils.py22-116](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/sqlcipher_utils.py#L22-L116)
 
 
### Settings Snapshot

 A point-in-time copy of a user's settings captured at the start of a research task. This ensures that if a user changes their LLM provider or search depth while a research task is running, the active task continues with its original configuration to maintain consistency.

 
 - **Code Pointer:** `SnapshotSettingsContext` [src/local_deep_research/web/services/research_service.py12](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/research_service.py#L12-L12) `get_setting_from_snapshot` [src/local_deep_research/config/llm_config.py25-28](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/config/llm_config.py#L25-L28)
 - **Sources:** [src/local_deep_research/web/services/research_service.py12](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/research_service.py#L12-L12) [src/local_deep_research/config/llm_config.py194-199](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/config/llm_config.py#L194-L199)
 
 
### NullPool vs QueuePool vs StaticPool

 SQLAlchemy pooling strategies. LDR typically uses `QueuePool` (pool_size=20, max_overflow=40) for production web operations to handle concurrent requests while limiting file descriptors and managing SQLCipher/WAL mode behavior [src/local_deep_research/database/encrypted_db.py61-94](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L61-L94) `StaticPool` is used during testing [src/local_deep_research/database/encrypted_db.py95-96](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L95-L96)

 
 - **Code Pointer:** `DatabaseManager.__init__` [src/local_deep_research/database/encrypted_db.py51-97](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L51-L97)
 - **Sources:** [src/local_deep_research/database/encrypted_db.py51-113](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/database/encrypted_db.py#L51-L113)
 
 
### Research Strategy

 A modular class that defines the logic for how a research task is executed. Strategies determine whether the research is sequential, parallel, or iterative. The system supports over 30 strategies including `source-based`, `iterdrag`, and `langgraph-agent` [README.md102-104](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L102-L104)

 
 - **Code Pointer:** `save_research_strategy` [src/local_deep_research/web/services/research_service.py131-139](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/research_service.py#L131-L139)
 - **Sources:** [README.md102-104](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L102-L104) [src/local_deep_research/web/services/research_service.py131-174](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/research_service.py#L131-L174)
 
 
### IntegratedReportGenerator

 The system responsible for synthesizing search results, library documents, and LLM analysis into a final Markdown report. It handles citation formatting and section-based synthesis.

 
 - **Code Pointer:** `IntegratedReportGenerator` [src/local_deep_research/web/services/research_service.py23](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/research_service.py#L23-L23)

## Research & Search Terms

 
### Source-Based Strategy

 The default comprehensive research strategy. It follows a high-level flow of iterative question generation, parallel searching, and final synthesis.

 
 - **Code Pointer:** `search.search_strategy` [src/local_deep_research/web/routes/research_routes.py186-188](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/research_routes.py#L186-L188)
 - **Sources:** [README.md102](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L102-L102) [src/local_deep_research/web/routes/research_routes.py184-201](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/research_routes.py#L184-L201)
 
 
### IterDRAG

 **Iterative Document Retrieval-Augmented Generation**. A specialized research strategy that performs multiple loops of searching, reading, and refining the research query based on what was previously found.

 
 - **Sources:** [README.md102-104](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L102-L104)
 
 
### AdvancedSearchSystem

 The central orchestrator for the search lifecycle. It coordinates different search strategies, manages citation handling, and interfaces with search engine implementations.

 
 - **Code Pointer:** `AdvancedSearchSystem` [src/local_deep_research/web/services/research_service.py24](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/research_service.py#L24-L24)

### LangGraph Agent Strategy

 An autonomous agentic research mode where the LLM decides what to search, which specialized engines to use (arXiv, PubMed, etc.), and when to synthesize [README.md104](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L104-L104)

 
 - **Code Pointer:** `langgraph-agent` [README.md104](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L104-L104)
 - **Sources:** [README.md104](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L104-L104)

## Library & RAG Terms

 
### LibraryRAGService

 The service that manages document indexing and retrieval. It handles the pipeline of text extraction, chunking, and vector storage using FAISS.

 
 - **Sources:** [README.md112-117](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L112-L117)
 
 
### PDF Storage Mode

 A configuration setting determining where PDF files are stored. Options include `database` (stored as encrypted BLOBs), `filesystem` (stored in the data directory), or `none` (metadata only).

 
 - **Sources:** [README.md117-118](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L117-L118)
 
 
### DownloadTracker

 A system that tracks the status of resource downloads to prevent redundant attempts and manage retries.

 
 - **Sources:** [README.md110-111](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/README.md?plain=1#L110-L111)
