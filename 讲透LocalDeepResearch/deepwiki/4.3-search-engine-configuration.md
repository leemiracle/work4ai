  This document provides a technical deep dive into the search engine configuration system. It covers the hierarchical settings architecture, the adaptive rate limiting mechanism, the security-hardened dynamic loading process, and the `search_engines.toml` configuration structure.

 
## Configuration Architecture Overview

 The configuration system follows a metadata-driven approach where each engine is defined by properties stored in the hierarchical settings database or provided via thread-safe snapshots. The system loads these definitions at runtime and dynamically registers additional engines from retrievers and document collections.

 
### Data Flow and Registry

 The `search_config` function in `search_engines_config.py` acts as the central orchestrator, merging static definitions from the `ENGINE_REGISTRY` with user-specific settings from the database or a `settings_snapshot` [src/local_deep_research/web_search_engines/search_engines_config.py93-132](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web_search_engines/search_engines_config.py#L93-L132)

## Adaptive Rate Limiting

 Local Deep Research implements an `AdaptiveRateLimitTracker` that learns optimal retry wait times for each search engine based on historical performance. This prevents aggressive polling while minimizing research latency.

 
### Implementation Details

 The tracker uses an exponentially weighted moving average (EWMA) to update estimates for wait times.

 
 - **Learning Rate:** Default `0.3`. This controls how quickly new rate limit events influence the wait time estimate [src/local_deep_research/web_search_engines/rate_limiting/tracker.py79-81](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web_search_engines/rate_limiting/tracker.py#L79-L81)
 - **Exploration Rate:** Default `0.1`. A small probability that the tracker will attempt a shorter wait time than estimated to "probe" if limits have been lifted [src/local_deep_research/web_search_engines/rate_limiting/tracker.py76-78](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web_search_engines/rate_limiting/tracker.py#L76-L78)
 - **Decay:** Estimates decay by `0.95` per day (`decay_per_day`) to ensure that temporary blocks don't permanently throttle an engine [src/local_deep_research/web_search_engines/rate_limiting/tracker.py82-84](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web_search_engines/rate_limiting/tracker.py#L82-L84)
 
 
### Persistence Flow

 Rate limit attempts and estimates are persisted to the user's encrypted `research.db` using the `RateLimitAttempt` and `RateLimitEstimate` models [src/local_deep_research/web_search_engines/rate_limiting/tracker.py171-180](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web_search_engines/rate_limiting/tracker.py#L171-L180) In `programmatic_mode`, database persistence is disabled, and the tracker operates in memory-only mode [src/local_deep_research/web_search_engines/rate_limiting/tracker.py146-153](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web_search_engines/rate_limiting/tracker.py#L146-L153)

## Dynamic Engine Loading & Security

 Search engines are instantiated via `create_search_engine` in `search_engine_factory.py` [src/local_deep_research/web_search_engines/search_engine_factory.py13-20](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web_search_engines/search_engine_factory.py#L13-L20) To prevent arbitrary code execution, the system uses a strict whitelist for module paths and class names.

 
### Module Whitelist Security

 The `get_safe_module_class` function in `module_whitelist.py` ensures that only trusted internal modules can be loaded.

 
 - **Relative Imports Only:** Module paths must start with a `.` (e.g., `.engines.search_engine_brave`) [src/local_deep_research/security/module_whitelist.py154-162](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/module_whitelist.py#L154-L162)
 - **Strict Whitelists:** Both the `module_path` and the `class_name` must exist in the security registry (`ALLOWED_MODULE_PATHS` and `ALLOWED_CLASS_NAMES`) [src/local_deep_research/security/module_whitelist.py26-112](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/security/module_whitelist.py#L26-L112)

## Configuration Settings

 While the system primarily uses a database-backed hierarchical setting model, the conceptual configuration for an engine follows this structure (mapped from `default_settings.json` and the database).

 
### Engine Configuration Schema

 
| Setting Key | Description | Default Value |
|---|---|---|
| search.tool | The default search engine to use. | searxng |
| search.max_results | Global limit for initial search results per engine. | 20 |
| search.max_filtered_results | Results kept after LLM relevance filtering. | 5 |
| search.snippets_only | Whether to retrieve only snippets or full content. | true |
| rate_limiting.learning_rate | Speed of wait-time adjustment. | 0.3 |
| rate_limiting.profile | Preset profile: conservative, balanced, aggressive. | balanced |

### Specialized Engine Variants

 
 - **Parallel Search:** Executes multiple engines simultaneously. It can be created via `create_search_engine` using `parallel` or `parallel_scientific` aliases [src/local_deep_research/web_search_engines/search_engine_factory.py39-60](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web_search_engines/search_engine_factory.py#L39-L60)
 - **Meta Search:** Uses an LLM to analyze the query via `analyze_query` and select the most appropriate engines (e.g., `arxiv` for scientific queries) [src/local_deep_research/web_search_engines/engines/meta_search_engine.py94-158](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web_search_engines/engines/meta_search_engine.py#L94-L158)
 - **Library RAG:** Integrated as a search engine that queries local vector collections using `LibraryRAGSearchEngine` [src/local_deep_research/web_search_engines/search_engines_config.py183-201](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web_search_engines/search_engines_config.py#L183-L201)
 - **LangChain Retrievers:** Custom retrievers can be registered via `retriever_registry` and are automatically wrapped in a `RetrieverSearchEngine` [src/local_deep_research/web_search_engines/search_engine_factory.py63-73](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web_search_engines/search_engine_factory.py#L63-L73)

## Unified Settings Access

 The system uses `_get_setting` in `search_engines_config.py` to abstract away the source of configuration. This allows the search system to function identically in a request context (reading from `db_session`) and in a background research thread (reading from `settings_snapshot`) [src/local_deep_research/web_search_engines/search_engines_config.py15-56](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web_search_engines/search_engines_config.py#L15-L56)
