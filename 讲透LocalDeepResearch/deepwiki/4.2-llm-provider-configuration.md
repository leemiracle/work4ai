  This page documents the LLM provider configuration system, which manages multiple language model backends (Ollama, OpenAI, Anthropic, etc.) and provides a unified factory interface for instantiating LLM clients.

 
## Overview

 The LLM configuration system ([src/local_deep_research/config/llm_config.py1-20](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/config/llm_config.py#L1-L20)) serves as the bridge between user settings and LangChain LLM instances. It handles:

 
 - **Dynamic Provider Discovery**: Auto-discovery of available backends on module import via `discover_providers` [src/local_deep_research/config/llm_config.py18-24](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/config/llm_config.py#L18-L24)
 - **Context Window Management**: Implementation of the **80% context rule** to prevent prompt overflow and manage local memory [src/local_deep_research/config/llm_config.py202-240](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/config/llm_config.py#L202-L240)
 - **Availability Checks**: Real-time validation of API keys and local endpoint connectivity for providers like Ollama, OpenAI, and LM Studio [src/local_deep_research/config/llm_config.py44-157](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/config/llm_config.py#L44-L157)
 - **Model Post-processing**: Automated think-tag removal for reasoning models via `remove_think_tags` [src/local_deep_research/config/llm_config.py9-11](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/config/llm_config.py#L9-L11)
 
 All configuration respects the `settings_snapshot` pattern for thread safety in background research execution, ensuring that settings do not change mid-research [src/local_deep_research/config/llm_config.py25-28](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/config/llm_config.py#L25-L28)

### ProcessingLLMWrapper and Post-processing

 All instantiated models are managed via the LLM configuration pipeline to ensure consistent behavior. A key component is the `ProcessingLLMWrapper` which handles response normalization.

 One critical post-processing step is **Think-Tag Removal**. Specialized reasoning models (e.g., DeepSeek-R1) often output internal "thought" blocks inside `<think>` tags. The `remove_think_tags` utility [src/local_deep_research/config/llm_config.py10-12](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/config/llm_config.py#L10-L12) uses regex to strip these blocks before text synthesis, ensuring final reports contain only the intended answer.

## Context Window and the 80% Rule

 The system enforces a strict **80% context rule** to prevent prompt overflow and ensure sufficient space for model reasoning and output tokens.

 
### Context Logic

 
 - **Local Providers** (`ollama`, `llamacpp`, `lmstudio`): Use a configurable local default (via `llm.local_context_window_size`) to prevent host memory issues [src/local_deep_research/config/llm_config.py211-218](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/config/llm_config.py#L211-L218)
 - **Cloud Providers**: Cap at the user-defined `llm.context_window_size` or default to provider-specific limits [src/local_deep_research/config/llm_config.py221-240](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/config/llm_config.py#L221-L240)
 - **The 80% Calculation**: The `max_tokens` parameter for the LLM is often derived as 80% of the calculated context window size to leave headroom for completions [src/local_deep_research/config/llm_config.py202-240](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/config/llm_config.py#L202-L240)
