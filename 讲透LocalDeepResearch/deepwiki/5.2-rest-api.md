## Purpose and Scope

 This document describes the HTTP REST API for Local Deep Research, which provides authenticated access to core functionality. The API supports research execution, settings management, history retrieval, and administrative operations. All endpoints require authentication and CSRF protection, as data is isolated within per-user encrypted databases.

 For programmatic Python access without HTTP, see [Python API](https://deepwiki.com/LearningCircuit/local-deep-research/5.3-python-api). For command-line tools, see [CLI Tools and MCP Server](https://deepwiki.com/LearningCircuit/local-deep-research/5.4-cli-tools-and-mcp-server).

## Settings and Configuration API

 Settings are managed via the `settings_bp` blueprint, supporting a dual-mode submission pattern.

 
### Submission Modes

 
 - **AJAX/JSON Mode (`/settings/save_all_settings`)**: Frontend calls like `saveMainConfig` or `saveLlmConfig` send JSON data [src/local_deep_research/web/static/js/services/api.js192-230](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/static/js/services/api.js#L192-L230) Values are converted using `get_typed_setting_value` to enforce types [src/local_deep_research/web/routes/settings_routes.py158-178](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L158-L178)
 - **Traditional POST Mode (`/settings/save_settings`)**: Fallback for non-JS environments [src/local_deep_research/web/routes/settings_routes.py98-131](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/routes/settings_routes.py#L98-L131)
 
 
### Namespace Validation

 The API enforces strict prefix validation. Settings must belong to namespaces like `llm.`, `search.`, or `rag.`. Critical namespaces like `auth.` or `db_config.` are protected from general API modification. ## Error Handling and Rate Limiting

 
### Adaptive Rate Limiting

 The API uses an adaptive rate limiter to protect LLM and Search providers from being overwhelmed.

 
 - **Pre-caching**: The `api_access_control` decorator reads `app.api_rate_limit` once and stores it in `g._api_rate_limit` to prevent redundant database hits [src/local_deep_research/web/api.py52-55](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/api.py#L52-L55)
 - **Learning Mechanism**: The `AdaptiveRateLimitTracker` records outcomes and adjusts wait times based on successes or `RateLimitError` responses [tests/rate_limiting/test_rate_limiting.py100-123](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/rate_limiting/test_rate_limiting.py#L100-L123)
 
 
### Response Serialization

 The API ensures consistent JSON responses. For RAG results, `_serialize_results` converts complex `Document` objects into serializable dictionaries containing `metadata` and `content` [src/local_deep_research/web/api.py164-184](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/api.py#L164-L184)

## v2.0 Authentication Migration Guide

 The transition to v2.0 introduced strict security requirements:

 
 - **Mandatory Authentication**: `api_access_control` returns a `401` if no user session is found [src/local_deep_research/web/api.py41-42](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/api.py#L41-L42)
 - **Settings Isolation**: API calls now utilize `SettingsManager` within a `get_user_db_session` context, ensuring that `api_enabled` checks are specific to the authenticated user's encrypted database [src/local_deep_research/web/api.py46-51](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/api.py#L46-L51)
 - **CSRF Enforcement**: All state-changing requests must include the CSRF token, typically via the `X-CSRFToken` header [src/local_deep_research/web/static/js/services/api.js50](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/static/js/services/api.js#L50-L50)
 - **Proxy Support**: `ProxyFix` middleware is used to correctly handle `X-Forwarded-For` headers, critical for IP-based rate limiting in production [src/local_deep_research/web/app_factory.py129-136](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/app_factory.py#L129-L136)
