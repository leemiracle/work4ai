  This page covers how local-deep-research downloads, stores, and manages research documents — primarily PDFs — from academic sources. It describes the modular downloader chain, the `PDFStorageManager`, the `DownloadTracker`, and the lifecycle of document deletion and cleanup.

 For RAG indexing of downloaded documents, see [6.1](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/6.1) For the broader library and collections data model, see [3.7](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/3.7) For configuration keys that affect this subsystem, see [4.4](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/4.4)

## System Overview

 When a research session completes, the sources it found (papers, PDFs, academic articles) are recorded as `ResearchResource` records. The download subsystem allows users to retrieve the actual binary content of those sources, extract their text, and add the results to the library for later searching.

## Modular Downloader Chain

 All downloaders inherit from `BaseDownloader` [src/local_deep_research/research_library/downloaders/base.py38-39](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/downloaders/base.py#L38-L39) This base class provides a `SafeSession` [src/local_deep_research/research_library/downloaders/base.py49](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/downloaders/base.py#L49-L49) for secure HTTP requests and an `AdaptiveRateLimitTracker` [src/local_deep_research/research_library/downloaders/base.py54](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/downloaders/base.py#L54-L54) to manage domain-specific rate limits.

 
### Specialized Downloader Logic

 
 - **ArxivDownloader**: Identifies arXiv URLs and converts them to direct PDF links (e.g., `https://arxiv.org/pdf/{id}.pdf`) [src/local_deep_research/research_library/downloaders/arxiv.py97-100](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/downloaders/arxiv.py#L97-L100) It also fetches metadata via the arXiv Atom API [src/local_deep_research/research_library/downloaders/arxiv.py152-162](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/downloaders/arxiv.py#L152-L162)
 - **BioRxivDownloader**: Handles bioRxiv and medRxiv preprints by converting landing page URLs to `.full.pdf` targets [src/local_deep_research/research_library/downloaders/biorxiv.py126-143](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/downloaders/biorxiv.py#L126-L143)
 - **DirectPDFDownloader**: A high-priority downloader that checks for `.pdf` extensions, `/pdf/` path segments, or `format=pdf` query parameters [src/local_deep_research/research_library/downloaders/direct_pdf.py15-39](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/downloaders/direct_pdf.py#L15-L39)
 - **GenericDownloader**: A fallback that attempts to download any URL. It uses `stream=True` to inspect `Content-Type` headers before committing to a full download, preventing memory spikes from large non-PDF files [src/local_deep_research/research_library/downloaders/generic.py94-111](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/downloaders/generic.py#L94-L111)

## PDF Storage Manager

 The `PDFStorageManager` abstracts the physical storage of PDF binaries [tests/research_library/services/test_pdf_storage_manager.py9-11](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/research_library/services/test_pdf_storage_manager.py#L9-L11) It supports three modes defined in the system settings:

 
| Mode | Description | Implementation Detail |
|---|---|---|
| database | Stores PDF as an encrypted blob. | Uses DocumentBlob table tests/research_library/services/test_pdf_storage_manager.py57-69 |
| filesystem | Stores PDF as a file on disk. | Uses library_root path tests/research_library/services/test_pdf_storage_manager.py73-91 |
| none | Discards binary after text extraction. | Returns None during save tests/research_library/services/test_pdf_storage_manager.py44-55 |

 The manager enforces a `max_pdf_size_bytes` limit (default 100MB) to prevent resource exhaustion [tests/research_library/services/test_pdf_storage_manager.py22-23](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/research_library/services/test_pdf_storage_manager.py#L22-L23)

## Document Deletion and Cleanup

 Deletion is handled by the `DocumentDeletionService` [src/local_deep_research/research_library/deletion/services/document_deletion.py24](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/deletion/services/document_deletion.py#L24-L24) which ensures that all related data is purged across the database and filesystem.

 
### Deletion Lifecycle

 
 - **Metadata Cleanup**: Removes the `Document` record.
 - **Binary Cleanup**: Deletes the `DocumentBlob` (if in database mode) or unlinks the file (if in filesystem mode) [src/local_deep_research/research_library/deletion/services/document_deletion.py104-123](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/deletion/services/document_deletion.py#L104-L123)
 - **Chunk Cleanup**: Manually deletes `DocumentChunk` records. Because `DocumentChunk.source_id` lacks a Foreign Key constraint, this must be handled explicitly by the `CascadeHelper` [src/local_deep_research/research_library/deletion/utils/cascade_helper.py31-49](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/deletion/utils/cascade_helper.py#L31-L49)
 - **Index Cleanup**: Deletes associated FAISS `.faiss` and `.pkl` files [src/local_deep_research/research_library/deletion/utils/cascade_helper.py169-205](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/deletion/utils/cascade_helper.py#L169-L205)
 - **Tracker Update**: Updates the `DownloadTracker` to reflect that the resource is no longer locally available [src/local_deep_research/research_library/deletion/services/document_deletion.py128](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/deletion/services/document_deletion.py#L128-L128)
 
 
### Blob-Only Deletion

 The service provides a `delete_blob_only` method [src/local_deep_research/research_library/deletion/services/document_deletion.py152](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/research_library/deletion/services/document_deletion.py#L152-L152) This removes the heavy PDF binary but preserves the extracted `text_content` and metadata, allowing the document to remain searchable in the RAG system while freeing up disk space [tests/deletion/test_document_deletion.py175-193](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/deletion/test_document_deletion.py#L175-L193)

## PDF Generation Service

 For exporting research reports, the `PDFService` utilizes **WeasyPrint** to convert Markdown to PDF [src/local_deep_research/web/services/pdf_service.py4-10](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/pdf_service.py#L4-L10)

 
 - **Security**: It implements a `_safe_url_fetcher` to block SSRF attacks by validating all URLs (images, stylesheets) before WeasyPrint attempts to fetch them [src/local_deep_research/web/services/pdf_service.py53-60](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/pdf_service.py#L53-L60)
 - **Styling**: A `minimal_css` profile is used to ensure readability, setting A4 margins and standard typography [src/local_deep_research/web/services/pdf_service.py102-155](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/pdf_service.py#L102-L155)
 - **Process**: The service first converts Markdown to HTML via the `markdown` library [src/local_deep_research/web/services/pdf_service.py185-187](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/pdf_service.py#L185-L187) and then renders the PDF into a `BytesIO` buffer [src/local_deep_research/web/services/pdf_service.py201-203](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/src/local_deep_research/web/services/pdf_service.py#L201-L203)
