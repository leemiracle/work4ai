## Purpose and Scope

 This page documents the GPU-accelerated deployment of Local Deep Research, specifically for running **Ollama** with hardware acceleration. It covers the `docker-compose.gpu.override.yml` architecture, NVIDIA GPU passthrough, AMD GPU support, and the `cookiecutter-docker` configuration generator which features automatic GPU detection via `check_gpu_linux` and `check_gpu_windows`.

 GPU acceleration significantly improves LLM inference speed for research synthesis and question generation. While the base configuration is CPU-only for maximum compatibility, hardware acceleration is enabled via Docker Compose overrides or custom-generated configurations.

 
---

## Automatic GPU Detection (Cookiecutter)

 The `cookiecutter-docker/` directory provides a way to generate deployment files tailored to the user's hardware. The logic resides in `hooks/pre_prompt.py` [cookiecutter-docker/hooks/pre_prompt.py1-112](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/hooks/pre_prompt.py#L1-L112)

 
### Detection Logic by Platform

 The system attempts to identify hardware before prompting the user for configuration values.

 
| Function | Platform | Implementation Detail | Code Reference |
|---|---|---|---|
| check_gpu_linux | Linux | Parses lspci output for "vga" and "NVIDIA"/"AMD" | cookiecutter-docker/hooks/pre_prompt.py27-58 |
| check_gpu_windows | Windows | Uses wmic path win32_VideoController get name | cookiecutter-docker/hooks/pre_prompt.py60-90 |

 
### Context Mapping

 Based on detection, the following context variables are updated:

 
 - `_nvidia_gpu`: Boolean flag for NVIDIA hardware [cookiecutter-docker/hooks/pre_prompt.py45](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/hooks/pre_prompt.py#L45-L45)
 - `_amd_gpu`: Boolean flag for AMD hardware [cookiecutter-docker/hooks/pre_prompt.py50](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/hooks/pre_prompt.py#L50-L50)
 - `enable_gpu`: Final toggle for including GPU blocks in the generated YAML [cookiecutter-docker/hooks/pre_prompt.py52](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/hooks/pre_prompt.py#L52-L52)

## AMD GPU Support (ROCm)

 The codebase includes support for AMD GPUs using the ROCm (Radeon Open Compute) platform. This is handled dynamically in the `cookiecutter` templates.

 
### Template Logic for AMD

 In the generated `docker-compose.yml`, the image and device mapping change if an AMD GPU is detected [cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml63-98](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml#L63-L98):

 
 - **Image Selection:** Uses `ollama/ollama:rocm` instead of `latest` [cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml64](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml#L64-L64)
 - **Device Mapping:** Maps `/dev/kfd` (Kernel Fusion Driver) and `/dev/dri` (Direct Rendering Infrastructure) directly into the container [cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml96-97](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml#L96-L97)

## GPU-Accelerated LLM Inference Configuration

 Hardware acceleration performance is tuned via environment variables passed to the Ollama service.

 
### Key Performance Variables

 
| Variable | Default | Role |
|---|---|---|
| OLLAMA_KEEP_ALIVE | 30m | Keeps the model in VRAM to avoid reload latency between research steps cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml77 |
| MODEL | gemma3:12b | The default model targeted for hardware acceleration cookiecutter-docker/hooks/pre_prompt.py16 |

 
### Resource Lifecycle in Compose

 The `ollama` service includes a healthcheck that verifies model availability [cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml70-75](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml#L70-L75) This ensures the `local-deep-research` service (which `depends_on` ollama) only starts once the GPU has successfully loaded the model into VRAM [cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml50-54](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml#L50-L54)

## Testing Environment GPU Restrictions

 In CI and Docker-based testing environments, GPU acceleration is explicitly disabled for the browser components (Puppeteer/Playwright) to prevent resource contention and ensure stability in headless environments.

 
 - **Puppeteer Config:** The `--disable-gpu` flag is passed to the browser launch options [tests/ui_tests/puppeteer_config.js41](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/ui_tests/puppeteer_config.js#L41-L41)
 - **Detection:** The configuration helper `getPuppeteerLaunchOptions` detects the environment using `process.env.DOCKER_ENV` [tests/ui_tests/puppeteer_config.js50](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/tests/ui_tests/puppeteer_config.js#L50-L50)
