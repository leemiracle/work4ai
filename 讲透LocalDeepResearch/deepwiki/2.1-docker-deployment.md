## Purpose and Scope

 This document explains Docker deployment for Local Deep Research (LDR), covering container architecture, deployment methods, and configuration. LDR is designed as a local-first, privacy-focused AI research assistant that orchestrates LLMs and search engines within a containerized environment.

### Multi-Stage Build

 The `Dockerfile` uses a multi-stage approach to separate build-time dependencies (Node.js, compilers) from the slim production runtime.

 **Build-to-Code Mapping Diagram** This diagram associates Docker build stages with specific code entities and output artifacts.

 
```

```

 **Build Stages:**

 
 - **`builder-base`**: Installs `libsqlcipher-dev`, `sqlcipher`, and Node.js 24.x LTS [Dockerfile4-45](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/Dockerfile#L4-L45) Pins `pdm`, `pip`, and `playwright` for reproducibility [Dockerfile51-52](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/Dockerfile#L51-L52)
 - **`builder`**: Runs `npm ci` and `npm run build` to compile the Vite frontend into static assets [Dockerfile90-91](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/Dockerfile#L90-L91) Executes `pdm install --prod` to create the production virtual environment [Dockerfile93-99](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/Dockerfile#L93-L99)
 - **`ldr-test`**: Specialized stage for CI. Installs Chromium dependencies and Playwright for UI testing [Dockerfile116-151](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/Dockerfile#L116-L151) It installs test-specific npm packages in `tests/ui_tests` and `tests/accessibility_tests` [Dockerfile154-166](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/Dockerfile#L154-L166)
 - **`ldr`**: The final production target. It copies the pre-built `.venv` and static assets from the `builder` stage.

### Security Model

 The deployment implements defense-in-depth through capability dropping and privilege separation.

 **Security Execution Flow** This diagram maps the security lifecycle from Docker configuration to the runtime execution.

 
```

```

 **Key Security Features:**

 
 - **Capability Management**: `cap_drop: ALL` is used in Compose, with only specific capabilities (`CHOWN`, `SETUID`, `SETGID`, `DAC_OVERRIDE`, `FOWNER`) added back to allow the entrypoint to fix volume permissions [cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml40-47](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml#L40-L47)
 - **Privilege Escalation Prevention**: `security_opt: ["no-new-privileges:true"]` prevents the process from regaining root [cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml38-39](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml#L38-L39)
 - **Memory Security**: `memlock: -1` (unlimited) allows SQLCipher's `mlock()` to protect encryption keys in RAM when memory security features are utilized [docs/docker-compose-guide.md89-91](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docs/docker-compose-guide.md?plain=1#L89-L91)

## Service Orchestration

 
### Ollama Initialization

 The `ollama` service uses a custom entrypoint to ensure the required model is available before the research engine attempts to connect.

 
 - **`ollama_entrypoint.sh`**: Starts `ollama serve`, waits for readiness via `ollama ls`, and then executes `ollama pull` for the specified model [scripts/ollama_entrypoint.sh25-37](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/scripts/ollama_entrypoint.sh#L25-L37)
 - **Health Checks**: The service is marked "healthy" once `ollama show` for the specified model succeeds [cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml70-75](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml#L70-L75)
 - **Dependencies**: `local-deep-research` uses `depends_on: service_healthy` for Ollama to prevent startup failures [cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml50-54](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml#L50-L54)
