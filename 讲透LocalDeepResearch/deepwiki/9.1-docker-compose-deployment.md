## Service Definitions

 
### local-deep-research Service

 The main application service runs the Flask web application. It handles research logic, user authentication via SQLCipher, and real-time updates via SocketIO.

 
| Setting | Value | Purpose |
|---|---|---|
| image | localdeepresearch/local-deep-research:latest | Multi-arch production image docker-compose.yml21 |
| ports | 5000:5000 | Expose web interface docker-compose.yml32 |
| networks | ldr-network | Isolated bridge network docker-compose.yml24 |
| restart | unless-stopped | Persistence across reboots docker-compose.yml168 |
| depends_on | ollama (healthy), searxng | Boot order management docker-compose.yml170-173 |

 **Sources:** [docker-compose.yml20-173](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L20-L173) [Dockerfile199-283](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/Dockerfile#L199-L283)

 
#### Entrypoint and Privilege Management

 The service utilizes a non-root user `ldruser` (UID 1000) for application execution, following the principle of least privilege. The entrypoint script performs initial setup before dropping privileges via `setpriv`.

## Network and Connectivity

 
### Internal DNS Resolution

 Docker Compose provides automatic service discovery. The LDR service is pre-configured via environment variables to reach its dependencies using their service names:

 
 - `LDR_LLM_OLLAMA_URL=http://ollama:11434` [docker-compose.yml75](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L75-L75)
 - `LDR_SEARCH_ENGINE_WEB_SEARXNG_DEFAULT_PARAMS_INSTANCE_URL=http://searxng:8080` [docker-compose.yml76](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L76-L76)
 
 
### Host Gateway

 To allow the container to reach services running directly on the host (like LM Studio), `extra_hosts` maps `host.docker.internal` to `host-gateway` [docker-compose.yml28-29](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L28-L29)

## Security and Resource Limits

 
### Capability Management

 The LDR service is hardened by dropping all Linux capabilities and adding back only the minimum required for the entrypoint to manage permissions and switch users.

 
 - **`cap_drop: ALL`**: Removes all default capabilities [docker-compose.yml144](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L144-L144)
 - **`cap_add`**: Includes `CHOWN`, `FOWNER`, `DAC_OVERRIDE`, `SETUID`, and `SETGID` [docker-compose.yml146-150](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L146-L150)
 - **`no-new-privileges: true`**: Prevents the container process from gaining new privileges [docker-compose.yml142](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L142-L142)
 
 **Sources:** [docker-compose.yml139-165](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L139-L165) [cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml37-48](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/cookiecutter-docker/{{cookiecutter.config_name}}/docker-compose.{{cookiecutter.config_name}}.yml#L37-L48)

 
### SQLCipher Memlock Ulimits

 To support SQLCipher's security features, the `memlock` ulimit is set to unlimited. This allows the `mlock()` system call to succeed, which prevents encryption keys from being swapped to disk when `cipher_memory_security` is enabled (an opt-in feature for enhanced database security) [docs/docker-compose-guide.md87-92](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docs/docker-compose-guide.md?plain=1#L87-L92)

## Configuration via Environment Variables

 Environment variables in `docker-compose.yml` serve as **forced overrides**. When a setting is defined in the compose file, it is locked in the Web UI and cannot be changed by users [docker-compose.yml39-42](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L39-L42)

 
 - **`LDR_WEB_HOST=0.0.0.0`**: Required for Docker networking [docker-compose.yml55](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L55-L55)
 - **`LDR_WEB_PORT=5000`**: Internal port must match Docker's expectation [docker-compose.yml56](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L56-L56)
 - **`LDR_DATA_DIR=/data`**: Aligns application data path with volume mount [docker-compose.yml57](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L57-L57)
 - **`LDR_APP_ALLOW_REGISTRATIONS`**: Recommended to set to `false` for public deployments after initial account creation [docker-compose.yml83](https://github.com/LearningCircuit/local-deep-research/blob/4a6a9088/docker-compose.yml#L83-L83)
