# 讲透安全协议 · 消息交换里藏的坑（GB/T 4132015）

> **这支负责的问题**：密码原语全对，协议为什么还是死？
> 一句钉住：**安全协议=把「刚认识的双方在线建立起信任」压进几条消息——
> 每条消息单独看都合法，会话整体却可能被骗。**

## 诞生

**Needham-Schroeder**（1978，分布式系统认证的开山协议）→
**BAN 逻辑**（1989，第一个协议形式化分析语言）→ **Lowe 1996**
用 CSP 模型检查抓出 NS 公钥版发布 **17 年后**仍潜伏的中间人攻击——
形式化方法首胜 → TLS 演化史（SSL 2.0 1995→TLS 1.0 1999→1.2 2008→
**TLS 1.3 2018**：每版死于上一版的教训，1.3 把前向保密与 AEAD 写死）。
因的问题：计算机网络让「从未谋面」的两端必须自行建立信任。

## 核心问题

| 问题 | 状态 |
|------|------|
| 协议安全性能否自动分析 | ✅ 符号模型下有界会话可判定（BAN→ProVerif/Tamarin 实战） |
| 中间人攻击的系统性防御 | ✅ 已解（身份绑定进密钥/签名，TLS 1.2+ 与 1.3 的强制做法） |
| 前向保密 | ✅ 已解（临时密钥，TLS 1.3 强制） |
| 安全模块的通用组合 | 🟡 UC 框架（2001）理论在、实践覆盖率低 |
| 无界会话数的可判定性 | ❌ 不可判定（符号模型已证） |

## 这支最美的一个事实

Lowe 1996：一个发表 17 年、被无数学者读过的安全协议，
被**模型检查器**在一台当年的工作站上几分钟抓出致命漏洞——
「人会犯的错，机器找得到」；协议验证从此从手工审查变成
可计算的工业流程。
