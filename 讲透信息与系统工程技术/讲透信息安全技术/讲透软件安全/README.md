# 讲透软件安全 · 漏洞住在代码里，也住在工具链里（GB/T 4132030）

> **这支负责的问题**：软件的缺陷如何变成对手的入口？
> 一句钉住：**软件安全=承认一切代码皆可能有洞，于是把赌注押在
> 语言、验证与流程上——让「有洞」不等于「可利用」。**

## 诞生

Anderson 报告（1972）已预言程序陷门 → **Thompson《对信任的反思》**
（1984，图灵奖演讲：会自复制的编译器后门——你审查了源码也信不过
二进制）→ 缓冲区溢出武器化（Aleph One 1996）→ 注入时代（SQL 注入
等，1990s 末起）→ **OWASP Top 10**（2003 首版，Web 漏洞的公共账本）→
**微软 SDL**（2004，安全开发生命周期）→ 内存安全语言重写
（Rust 进入浏览器/内核/TLS 栈，2010s-2020s）→ 供应链时代
（**XZ 后门 2024**：三年人格潜伏攻进构建链）。因的问题：
软件复杂度增长快于人工审查能力。

## 核心问题

| 问题 | 状态 |
|------|------|
| 注入类漏洞根除 | 🟡 参数化查询/类型系统大幅压缩；❌ 存量与动态构造长尾 |
| 内存安全 | 🟡 内存安全语言是正解；❌ 数十亿行 C/C++ 存量的迁移以十年计 |
| 供应链制品完整性 | 🟡 sigstore/可复现构建/SBOM 制度化中（XZ 案加速） |
| 工具链信任（Thompson 问题） | ❌ 原则上开放：多样化构建可检测、不可根除 |
| 漏洞的自动发现 | 🟡 fuzzer/静态分析+LLM 辅助半自动化（家族 01 章方向五） |

## 这支最美的一个事实

Thompson 1984：给 C 编译器植入「编译带后门的 login 时自我复制、
编译自己时抹去痕迹」的后门——源码干干净净，二进制代代带毒。
**信任链没有免费的第一环**：你能信任的从来不是代码，
而是「产生代码的整个过程」——四十年后 XZ 事件逐字应验。
