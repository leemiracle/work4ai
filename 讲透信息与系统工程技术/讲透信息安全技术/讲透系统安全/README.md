# 讲透系统安全 · 单机的保护机制（GB/T 4132020）

> **这支负责的问题**：一台机器如何在自己身上划出「谁能做什么」的边界？
> 一句钉住：**系统安全=把「信任」折叠成一个尽量小的可信计算基（TCB），
> 并让边界上的每一次跨越都被强制检查。**

## 诞生

**Anderson 报告**（1972，计算机安全威胁模型开山）→
**Saltzer-Schroeder 八原则**（1975，Proc. IEEE）：最小权限、完全调解、
失败安全默认、机制经济性、开放设计……——**50 年仍是第一性清单**；
**Bell-LaPadula 模型**（1973，军事情报的机密性形式化：不上读/不下写）
→ **TCSEC 橙皮书**（1983）→ 缓冲区溢出时代（Aleph One 1996 教科文）→
capabilities/seccomp/沙箱等最小权限机制的工程化。因的问题：
分时系统让互不信任的用户与程序共用一台机器。

## 核心问题

| 问题 | 状态 |
|------|------|
| 保护机制的设计原则 | ✅ 已解（Saltzer-Schroeder 1975，至今未过时） |
| 机密性的形式模型 | ✅ 已解（Bell-LaPadula 1973）；完整性侧（Biba/Clark-Wilson）多模型并存 |
| 最小权限的机制实现 | ✅ 机制存在（capabilities/沙箱）；❌ 主流系统仍默认过度授权 |
| 完全调解的性能代价 | 🟡 每次访问都查权限——安全与性能的永久谈判 |
| TCB 能压多小 | ❌ 未解：商用系统的 TCB 数百万行，形式化微内核是少数派路线 |

## 这支最美的一个事实

1975 年 Saltzer 与 Schroeder 写下的八条原则（「最小权限」「完全调解」
「机制要简单到一眼看懂」）——半个世纪的硬件、网络、云全部换代之后，
系统安全评审清单的第一页**仍然是这八条**：原则的半衰期远长于技术。
