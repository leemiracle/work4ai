# 讲透安全测评 · 给「更安全」发可复核的证书（GB/T 4132040）

> **这支负责的问题**：如何让第三方能复核「这东西够安全」的主张？
> 一句钉住：**测评=把不可观测的「安全度」翻译成可审计的过程与台账
> ——它的诚实之处是承认：证书证明的是过程，不是结果。**

## 诞生

**TCSEC 橙皮书**（1983，美国国防部：C1→A1 保密等级，第一个评估标准）
→ ITSEC（欧洲 1990）→ **Common Criteria / ISO 15408**（1999 国际统一：
保护轮廓-评估对象-保证等级 EAL1-7）→ **CVE 漏洞台账**（1999，MITRE：
全球共享一个编号系统）→ **CVSS 评分**（2005 首版，v4.0 2023）→
渗透测试职业化与**漏洞赏金**（网景 1995 首创，2010s 起成主流）。
因的问题：采购方无法自行验证安全主张，市场需要第三方信任中介。

## 核心问题

| 问题 | 状态 |
|------|------|
| 评估的过程化标准 | ✅ 成熟（CC/ISO 15408 三十年运转） |
| 漏洞的公共台账 | ✅ 成熟（CVE/CWE 生态） |
| 严重性的量化评分 | 🟡 CVSS 是沟通汇率不是测量仪——分与真实可利用性弱相关（头号争议） |
| 等级与真实安全的的相关性 | ❌ 未解：「已评估≠安全」，过程保证与结果安全的鸿沟 |
| 自动化渗透 | 🟡 LLM/CTF 战队逼近人类水平（家族 01 章），落地早期 |

## 这支最美的一个事实

1999 年起的 CVE 编号制度：全人类每一条公开漏洞共享同一本台账——
同一个编号（CVE-2024-3094）让北京、东京、加州的工程师在同一秒
谈论同一个洞。**安全从「各自保密」走向「公共会计」**，
这本台账是防御方少有的真正共享基础设施。

## 假设与依赖

- 假设「过程质量可外推结果安全」（橙皮书时代起的核心假设，
  也是最大争议源）；假设评分者与厂商无合谋（生态治理问题）
- 依赖全家族提供对象：原语/协议/系统/网络/软件都是受测物
