# 讲透信息安全工程 · 假设上一道防线已失守（GB/T 4132045）

> **这支负责的问题**：安全如何作为**系统属性**（而非组件属性）
> 在全生命周期里被设计、运营与迭代？一句钉住：**信息安全工程=
> 把「会失守」当设计输入——纵深防御、威胁建模、快速恢复，
> 三件套都建立在承认失败的前提上。**

## 诞生

Saltzer-Schroeder 原则（1975）提供设计律 → SSE-CMM（1996 起草，
后成 ISO/IEC 21827：安全工程能力成熟度）→ **Anderson
《Security Engineering》**（2001 成书：学科的总地图）→
安全经济学（Anderson「柠檬市场」2001：安全市场为何系统性投入不足）→
微软 SDL（2004）→ **NIST CSF**（2014：识别-保护-检测-响应-恢复框架）
→ DevSecOps（2010s：安全左移进 CI/CD）→ 零信任工程（2020s）。
因的问题：单点技术不断胜出而系统不断失守——安全是生命周期问题。

## 核心问题

| 问题 | 状态 |
|------|------|
| 安全的系统化框架 | ✅ NIST CSF/ISO 27001 族成熟运转 |
| 威胁建模方法 | ✅ STRIDE/攻击树（微软 1990s）成标准动作 |
| 组合安全（组件安全≠系统安全） | ❌ 未解——工程上以纵深防御缓解，理论上无通用定理 |
| 安全经济学 | 🟡 柠檬市场/外部性诊断成熟；❌ 投入不足的结构性纠偏未解 |
| 人因 | ❌ 钓鱼仍是第一大入口；培训-检测-响应是过程不是终态 |
| 风险的量化 | ❌ 「多安全才够安全」无算法（家族 00 章核心问题表） |

## 这支最美的一个事实

纵深防御把「失败」从禁忌词变成设计参数：**外层可以丢、丢得慢、
丢了能报警、报了警能恢复**——这是工程学科罕见的以承认无能
（无法造出不可破的系统）为前提建立起来的完整方法论。

## 假设与依赖

- 假设失守不可避免（与密码学的「可证明安全」构成家族两极：
  定理的自信与运营的谦卑）
- 全家族其余七支都是本支的积木；本宇宙控制工程（41310）的方法论
  （反馈、容错、余度）与本支共享「可靠性」基因——分界在有无敌手
