# 04 · 信息安全技术转代码：六条走廊与两道永久裂缝

> **本章回答五问之五（家族层）：这个分支的问题怎么变成 code 问题？**
> 信息安全是「攻击也是代码」的学科，转码天然双向：**防御的构造**
> 与**攻击的构造**都是程序。六条走廊各有承诺强度——用得对
> （标准库即安全）、算得准（密码分析）、证得明（形式化）、
> 跑得出（模糊测试）。两道永久裂缝：**证明与实现的鸿沟**
> 与**物理侧信道**——都不在模型里，都在 CPU 里。

---

## 一、代码走廊总表

| 走廊 | 问题类型→算法→库 | 承诺强度 |
|------|-----------------|---------|
| ① 经典密码分析走廊 | 「多表密码怎么破」→ 重合指数+卡方 → 纯标准库 | 算得准（本家族实验第 1 部分） |
| ② 密码应用走廊 | 「加密/认证/签名怎么用对」→ 标准库调用+footgun 检查 → hashlib/hmac/secrets、cryptography/PyCryptodome | 用得对（安全性外包给标准） |
| ③ 协议验证走廊 | 「协议有没有逻辑洞」→ 符号模型/状态空间搜索 → ProVerif/Tamarin | 证得明（理想化模型内） |
| ④ 漏洞挖掘走廊 | 「实现有没有洞」→ 模糊测试/ sanitizer/静态分析 → AFL++/libFuzzer/CodeQL | 跑得出（有界时间的证据） |
| ⑤ 格密码走廊 | 「后量子原语长什么样」→ toy LWE 加解密/误差预算 → 纯 Python 数十行 | 算得准（教学维数下） |
| ⑥ 测评走廊 | 「风险怎么排序」→ CVSS 向量计算/依赖扫描/SBOM → dependency-check/Grype | 半自动（评分≠现实危险） |

## 二、逐条速写（为什么是这样）

### 走廊①：破译也是程序——频率分析的完全机械化

古典密码分析是**可判定问题的标本**：给定足够长的密文，
重合指数（IC）定钥长、每列卡方对齐英文频率——60 行标准库
全自动恢复明文（实验第 1 部分 assert 恢复）。**为什么古典密码
可完全机械化**：它的泄漏是统计性的（字母频率是明文分布的指纹），
而自然语言分布与均匀分布的区分本身是多项式时间问题——
敌手优势≈1，游戏毫无悬念（02 章语言的反面教材）。

### 走廊②：密码应用的全部纪律=「别自作聪明」

```python
# 三行安全 vs 三个 footgun（应用密码学的全部日常）
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
key = AESGCM.generate_key(bit_length=256)      # ✅ 用库生成
ct  = AESGCM(key).encrypt(nonce, msg, aad)     # ✅ AEAD=加密+认证一体
# footgun ① ECB 模式（企鹅图片还能认出来）② nonce 重用（GCM 全塌）
# ③ hmac.compare_digest vs == （比较本身泄密——时序侧信道）
```

**纪律**：加密选 AEAD、哈希选 SHA-2/3、随机用 secrets（不是 random）、
比较用恒定时间函数——**安全性外包给标准**（03 章 Kerckhoffs 结构
的代码形态：保密的只有 key 一个对象）。

### 走廊③⑤：协议与格——证明与玩具之间

- 协议走廊的产出是**理想化模型内的定理**：Lowe 1996 用 CSP/FDR
  抓 Needham-Schroeder、TLS 1.3 与 Signal 的形式化分析是工业级案例；
  Tamarin/ProVerif 的符号世界把密码原语当完美黑箱——**找到的攻击
  是真攻击，没找到不等于没有**（02 章双轨裂缝的代码侧）
- 格走廊：数十行纯 Python 可跑通 toy LWE，教学价值在亲手摸到
  「误差预算」——维数/模数/噪声的三角（ML-KEM 参数表的直觉来源）：

```python
# toy LWE 解密骨架(教学维数;生产实现另有恒定时间要求)
# 秘密 s,公钥 (A, b = A·s + e mod q),消息位 m ∈ {0, q//2}
# 加密:u = A'·r + e1, v = b'·r + e2 + round(m)   (r 随机小向量)
# 解密:v - u·s ≈ m + (小误差) → 阈值判决
#      误差预算:|e2 + e1·s - ...| < q/4 才判对
#      —— 维数/模数/噪声三者的余量,就是 ML-KEM 参数表的全部秘密
```

  格的工程要点：正确性是**概率性**的（解密失败率 q^-ε 级），
  这是对称密码没有的新维度；恒定时间+防侧信道的模乘实现是
  2024-2029 迁移期的真实工程量（§四·工程师落点 4）

### 走廊④⑥：跑得出与半自动——工程侧的日常

- 模糊测试=「程序化地胡乱输入+看崩不崩」：覆盖引导（AFL++）使它
  从瞎猜进化为定向搜索；2024-2026 LLM 生成语料成为新潮流〔知识〕
- 测评走廊的 CVSS 计算是纯函数（向量→分），**难的不是计算是校准**——
  分数与实际可利用性的弱相关是测评支的头号争议

## 三、可机械化边界（三件套之一）

| 任务 | 可机械化？ | 说明 |
|------|-----------|------|
| 经典密码破译 | ✅ 全自动 | 频率/IC/卡方（实验） |
| 用密码学（AEAD/MAC/签名） | ✅ 全自动 | 标准库即安全 |
| 协议符号模型找攻击 | ✅ 大体全自动 | 有界情形可判定 |
| 漏洞发现 | 🟡 半自动 | fuzzer/静态分析给候选，人裁决 |
| 证明实现=规范 | 🟡 起步 | 验证密码库（HACL* 类）覆盖关键原语 |
| 侧信道检测 | 🟡 半自动 | 工具查已知模式（时序/缓存），未知模式漏 |
| 攻击面完备枚举 | ❌ 无算法 | 敌手是智能的（03 章第三档） |
| 「系统足够安全」判定 | ❌ 无算法 | 量化安全是开放问题（00 章核心问题表） |

## 四、工程师落点（三件套之二；性能工程视角）

1. **密码工程=性能工程的镜像纪律**：通用优化的一切手段——
   分支预测、查表、提前退出、缓存——在这里全是**侧信道**。
   AES 的查表实现快但泄密（缓存计时），恒定时间实现慢但安全；
   防御性的代码模式（无分支、无数据相关访存）与
   [高性能计算](../../讲透高性能计算/) 的手册逐条相反——
   **这是「优化」一词被重新定义为「不泄漏的执行」的唯一领域**
2. **硬件加速是安全与性能的双赢点**：AES-NI/SHA 扩展/随机数指令
   （RDRAND）——密码原语的吞吐上限由指令集决定；批量加密的
   热点 profiling 与任何 HPC workload 同法，只是**热点的形状
   必须恒定**（时间不随秘密变化）
3. **大规模攻击面的并行化**：密钥搜索/哈希碰撞的演示性 workload
   是 embarrassingly parallel（与 GPU 天然亲和——但注意 2¹²⁸ 的
   墙不是算力问题，是能量问题：GPU 农场买不回指数）
4. **后量子迁移是性能工程新战场**：ML-KEM 握手比 X25519 大
   数十倍（公钥+密文千字节级）〔知识〕——握手包大小、
   CPU 开销、连接复用策略是 2024-2029 的真实调优工作

## 五、裂缝清单（三件套之三：原则上/工程上的不可转）

1. **证明与实现的鸿沟**：定理挂在规范上，跑在 CPU 上的是实现——
   中间隔着内存损坏、整数溢出、随机数弱源、时序泄漏。
   「数学安全」到「部署安全」的每一跳都可能塌（验证实现只覆盖
   跳板中最贵的那块）
2. **侧信道不可全检**：物理观测维（时间/功耗/电磁/声/故障注入）
   开放枚举——每个新传感器都是新攻击面；模型永远追着物理跑
   （走廊③证明的完美黑箱假设在这里失真）
3. **人因不可编译**：钓鱼链一个链接即达；「培训+检测+响应」
   是组织过程不是代码
4. **量化安全不可判定**：CVSS/等级/风险矩阵是沟通工具不是
   测量仪器——「多安全才够安全」没有算法（测评支的存在理由）

## 📌 收束

信息安全转码的图景：**应用走廊全顺（标准库即安全）、分析走廊
可判定（古典）或半自动（现代）、证明走廊理想化内证得明、
实现与物理是两道永久裂缝**。按承诺强度选走廊，按裂缝清单
给结论打折——这套纪律比任何单个工具都重要。实战落地样本
见 [omega-guard](../../omega-guard/)（根级安全工程锚点）。

**🧠 认知升维**：
- **镜像眼**：看到「性能优化」先问这里的优化方向是不是反的——
   安全代码的优化目标是**恒定**，不是最快
- **外包眼**：写任何加密代码前先找标准库——你唯一该保密的
   对象是密钥，唯一该自研的是密钥管理流程
- **打折眼**：「验证过」「测评过」「跑过 fuzz」各打折多少——
   证据折扣表（02 章）是读一切安全报告的汇率表
