## 一、代码走廊总表

## 二、逐条速写（为什么是这样）

### 走廊①②：本家族实验的双标本

蒙特卡洛的严格性全部住在概率论（大数定律/CLT/方差缩减的
对偶变量与重要性抽样），离散事件的严格性住在排队论与 DEVS
语义——**引擎本身 100 行以内写完**（本家族实验脚本），
门槛全在实验设计与输出分析。核心骨架（事件调度世界观）：

```python
import heapq, random
# 事件表=带时间戳的最小堆；时钟=直接跳到下一事件
# ① push(到达)  ② 弹出最早事件  ③ 按类型转移状态并 push 后继
heap = [(random.expovariate(lam), 'arrival')]
busy_until, n_in_sys = 0.0, 0          # 状态袋（02 章 DEVS 的 S）
# 完整可跑版见 experiments/simulation_kernels.py
```

✨ **美之时刻 ⑤**：**时间跳变**——事件驱动仿真里，时钟永远
直接跳到下一个事件，两事件之间的"无事发生"**零成本**。
模拟一年的产线，计算量正比于事件数而不是时长：把空闲的
 8760 小时折叠成一次堆弹出。它美在"离散化的自由"：
连续仿真被步长绑架，事件仿真把时间的分辨率变成自适应。
亲历方式：实验脚本第 3 步，总模拟时长 4×10⁵ 时间单位，
 2×10⁵ 个完成事件，墙钟秒级。

### 走廊③④：穿马甲的计算数学+被引擎定义的语义

- 连续走廊的一切数值决策（步长/刚性方程用 BDF/精度阶）按
  计算数学纪律走，本家族不产数值定理；**实时仿真的特有约束是
  定步长**（变步长与硬实时 IO 冲突），于是"积分器的精度-帧时"
  权衡成为走廊⑤的核心矛盾
- 多范式走廊的语言（Simulink/Modelica）语义由商业引擎定义——
  "模型正确"的检查一半变成"按引擎语义复现模型"的流程问题；
  FMU（功能样机接口）是跨引擎搬运模型的标准容器〔知识〕

### 走廊⑤⑥：工程味最浓的两条

- 实时/半实物走廊的主战场不在 Python：C/RTOS 上跑定步长模型，
  真传感器真控制器接进回路（HIL）。**帧超时不是慢，是错**——
  详见工程师落点 4
- 孪生走廊是 01 章二分框架的代码面：同步管道（传感器→状态变量
  的映射与节拍）+代理模型（贵的物理模型 → 学出来的快速替身），
  承诺强度永远标"实验级"，除非加上物理项（PINN 类混合）

## 三、可机械化边界（三件套之一）

| 任务 | 可机械化？ | 说明 |
|------|-----------|------|
| 随机数生成 | ✅ 全自动 | 但质量认证要经验检验包（TestU01），不是证明 |
| 蒙特卡洛估计+置信区间 | ✅ 全自动 | CLT 背书，输出自带 ± |
| 离散事件调度 | ✅ 全自动 | 堆+时钟，语义由 DEVS 严格定义 |
| 不变量自查（Little/物料平衡） | ✅ 全自动 | **每个仿真工程都该默认装配**——免费的自检 |
| V 的机器部分（回归测试/一致性） | 🟡 半自动 | 断言+覆盖率+代码审查，人裁决 |
| V 的归纳部分（残差/灵敏度） | 🟡 半自动 | 统计工具给证据，结论带条件 |
| A（确认） | ❌ 无算法 | 机构授信（02 章），代码只能出证据页 |
| Sim2Real 鸿沟消除 | ❌ 原则上开放 | 封闭世界缺席不可枚举，只有域随机化的统计缓冲 |

## 四、工程师落点（三件套之二；性能工程视角）

1. **仿真负载=HPC 主战场**：CFD/分子动力学/系综天气预报吃掉
   [讲透高性能计算](../../讲透高性能计算/) 的最大份额——
   特征是"格点/粒子级的规则计算+巨大的通信面"，数值方法本体
   在 [讲透数学/讲透计算数学](../../讲透数学/讲透计算数学/)，
   并行化模式在 HPC 家族正讲
2. **系综与蒙特卡洛=最友好的并行**：每个样本独立——
   embarrassingly parallel，GPU 一次启动百万路径
   （cf. 分岔扫描同构，见系统学家族 04 章）；**先问方差缩减再买算力**：
   对偶变量把方差砍半的成本 << 样本翻四倍——
   **买样本不如买方差缩减**，这是蒙特卡洛的性能工程第一定律
3. **并行离散事件仿真（PDES）=因果律的工程化**：多核/多机各跑
   一段模型，同步是难点——保守同步（Chandy-Misra 1979）怕死锁，
   乐观同步 Time Warp（Jefferson 1985）靠回滚吞掉因果违例，
   回滚深度与负载的权衡是活跃工程问题；仿真时间≠墙上时间，
   **虚拟时间是可回滚的**——这是它最反直觉的架构财产
4. **实时仿真的确定性延迟**：帧时间预算（例：1ms 步长全链路
   <0.8ms）下，**抖动比均值更致命**；Python 的 GIL 与 GC 停顿
   使它只配做监视/后处理，控制回路必须让位 C/RTOS——
   详见 [讲透GPU与系统级](../../讲透GPU与系统级/) 的系统级纪律
5. **GPU 仿真与神经仿真器**：物理引擎万实例化（Isaac/Omniverse
   谱系）、GNN 学仿真（01 章方向二）——GPU 是仿真这五年的
   世代交替底座；Sim2Real 训练=GPU 系综采样的当代最大用户
6. **仿真实验也是实验（DOE 与输出分析）**：参数扫描不是 for 循环
   暴力——实验设计（一次一因子/全因子/拉丁超立方）决定信息的
   每单位算力产出；重复次数由置信区间半宽反推（不是拍脑袋跑十次）；
   贵的仿真配元模型+贝叶斯优化是当前性价比最优路线——
   **把仿真实验当统计实验设计，是本家族对工程师最实用的一条纪律**

## 五、裂缝清单（三件套之三：原则上/工程上的不可转）

1. **确认不可转**：可转的是证据页（残差/灵敏度/覆盖率报告），
   **许可证永远由人签发**——全自动"可信度评分"是这条裂缝上的
   常见伪产品
2. **Sim2Real 不可算法化**：能转的是统计缓冲（域随机化+真传仿真），
   "差距为零"没有算法——宣称消除鸿沟的产品在卖置信区间之外的东西
3. **保真度-成本权衡无最优解**：帧预算下砍哪块模型精度，
   是"问题×用途×容差"三元谓词（02 章）上的**人类决策**——
   可转的是帕累托前沿的扫描，不是选择本身
4. **验证的循环性**：对照真身的数据要么贵、要么不存在——
   裂缝与 00 章假设 4 同源，代码层表现为"验证集即真身"的悖论

## ✍️ 练习

1. **维数免疫亲测**（00 章练习 2 正式版）：把实验脚本的 π 估计
   改成 10 维超球体积估计，同 N 对比相对误差量级——
   然后**估算网格法同维度需要多少点**，写出数量级对比
2. **方差缩减性能实验**：给 π 估计加对偶变量（每个随机点
   v 的同时用 1-v），同误差目标下对比朴素版所需样本数——
   亲手验证"买样本不如买方差缩减"
3. **同步模式体验**：把 M/M/1 改成两级 tandem queue，再拆成
   两个"进程"（生产者-消费者）各带本地时钟跑——
   体会保守同步的死锁风险从哪来（提示：空队列+等对方推进）
4. **裂缝体验**：给你的仿真脚本写一个"确认证书生成器"的伪代码
   规范——写不出无歧义规范的原因就是裂缝 1（同系统学 04 章练习 3）

## 📌 收束

仿真转码的图景：**走廊①②是母语（百行引擎+自带不变量自查）、
③④穿计算数学的马甲、⑤是硬实时的纪律、⑥承诺永远标实验级**；
工程师落点浓缩成三句：仿真负载喂饱 HPC/GPU、蒙特卡洛先买
方差缩减再买样本、实时仿真里抖动即错误。
按承诺强度选走廊，按裂缝清单打折结论——这套纪律比任何单个工具重要。

**🧠 认知升维**：
- **承诺分层眼**：看到任何仿真结果先问它站在哪条走廊——
  算得准/跑得出/算得完/实验级，四档的证据折扣完全不同
- **方差优先眼**：蒙特卡洛的性能问题第一反应永远是"能砍方差吗"
  （对偶/分层/重要性抽样），其次才是"能加机器吗"
- **抖动眼**：实时系统里平均延迟是 vanity 指标，尾延迟才是
  真约束——仿真步长的 99.9 分位超时=控制器发散的开始
