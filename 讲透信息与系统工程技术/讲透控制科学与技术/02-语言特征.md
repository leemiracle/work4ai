# 02 · 语言特征：方块图、梯形图与标准族——工程学科怎么说话

> **本章回答五问之三（家族层）：表达？逻辑？规范化？三栏逐一交代。**
> **本质一句话**：控制工程的语言不是数学也不是软件，而是**画给所有工种
> 一起看的图**——方块图、P&ID、梯形图、层级行政图——以及把大家
> 钉在一起的**标准族**。一门"装置不可逆、百万件量产"的学科，
> 语言的第一要求不是表达力，是**人人可读、可审、可打官司**。

📖 **开篇故事**：同一台锅炉房，三类人说话完全不同——
控制理论出身的人说"二阶欠阻尼、相角裕度 45°"；仪表工程师指着一叠
P&ID 管道仪表流程图说"FT-101 测流量，FIC-101 是控制器，阀在管线 3 上"；
电工打开 PLC 柜，屏幕上是梯形图。**三个人说的是同一台机器、同一个回路**。
这门学科的语言学，就从"为什么一件事要说三遍、用三种话"讲起。

---

## 一、第一栏：表达力——能说什么

### 1.1 七种方言装备表

| 方言 | 说什么 | 代表句式 | 主要用户 |
|------|--------|---------|---------|
| 方块图 | 信号怎么流、环怎么闭 | 方框+箭头+求和点 | 全体工种的公共语 |
| 传递函数/频域 | 动态有多快、多稳（工程频域黑话） | G(s)=K/(τs+1)；裕度、带宽 | 回路设计（应用理论支） |
| P&ID 图例 | 工厂里哪台仪表在哪条管上 | FT/FIC/LV 三字母代号（ISA-5.1） | 仪表/工艺工程师 |
| 梯形图/IEC 61131-3 | 联锁与顺序逻辑 | 触点-线圈、SFC 步进 | 电工/PLC 程序员 |
| 状态空间 | 多变量系统的现代语言 | ẋ=Ax+Bu | 导航/机器人/高端装置 |
| 接口语言 | 信号与数据的物理形态 | 4-20mA、Modbus、OPC-UA | 仪表与系统集成 |
| 层级架构图 | 谁管谁（ISA-95 的世界） | L0 传感器…L4 ERP | 工厂 IT/OT 两界 |

### 1.2 说不出来的三件事（表达力边界）

1. **责任与成本**——方块图能画"控制精度 ±0.5%"，画不出
   "这套方案贵三倍、坏了算谁的"；这些住在商务合同与功能安全标准里，
   不住在工程图里
2. **物理世界的不礼貌**——粘滑摩擦、间隙回差、执行器饱和这些
   非线性"毛边"，线性方言只能近似；一说真话就要换非线性语言，
   而非线性没有统一方言（12030 的百年痛点在语言层的投影）
3. **跨层耦合**——回路层方言（传递函数）与体系层方言（OODA/决策环）
   之间没有自动翻译：C2 系统工程师和回路工程师开会要靠人肉翻译

**为什么是这样（第一栏）**：因为**读者比作者重要**。论文语言优化
"表达力"，工程语言优化"最少误读"——一张梯形图要在调试现场的
凌晨两点、由疲劳的电工读对，这才是它的设计工况。方言多的原因
不是学科不成熟，而是**一个工种一种最误读最小的图**。

## 二、第二栏：逻辑性质——工程师怎么推理

### 2.1 三种推理并存

1. **定理推理**（借来的）：稳定性判据、采样定理——从 12030 借来
   当"宪法条文"用；工程上默认"满足判据=免检项"
2. **规范符合性推理**（本学科母语）：结论的真值来自
   **"按 IEC/ISA/ISO 标准设计并通过型式试验"**——
   推理形式是核对清单（checklist），不是证明链
3. **验收试验推理**（终审法庭）：FAT/SAT（工厂/现场验收测试）、
   HIL——**跑一遍给你看**；证据地位类似科学的实验，但判据是
   合同规格书不是假设检验

### 2.2 概念三步法示范：串级控制（cascade control）

- **直觉图像**：淋浴调水温——水太烫，你不会直接拧阀门到底，
  而是先粗调（水温主环），发现"热水压力变了"就先稳住压力（副环）——
  **快的小环套在慢的大环里，小环先挡掉快扰动**
- **严格陈述**：两个控制器串接，主环控制器的输出作为副环的设定值；
  副环必须比主环快（一般 3 倍以上），副环把进入内回路的扰动
  在波及主变量之前消化掉
- **最小具体例子**：锅炉汽包水位"三冲量"控制——给水流量副环
  （快，挡给水压力波动）+水位主环（慢，管最终水位）+蒸汽流量前馈
  （预见负荷变化）。一个串级+前馈的标准结构，教科书级最小样本

### 2.3 为什么是这样（第二栏）

因为**装置不可逆**。软件可以发补丁，钢结构和产线一投产就是
百万件、二十年——所以推理必须**先于投产收敛**，且要能对第三方
（验收官、审计、法庭）重放。定理太贵（大多数工程对象证不动）、
试验太晚（不能拿产线做实验），于是**规范条文成了性价比最高的
推理载体**："按标准做"= 把前人踩过的坑预编译成清单。
这解释了本学科一个奇特现象：**最重要的"论文"是标准文本**。

📖 **故事框**：IEC 61131-3 把 PLC 语言定为五种（梯形图 LD、
功能块图 FBD、结构化文本 ST、指令表 IL、顺序功能图 SFC）——
一门学科把自己的"方言"用国际标准**立法**。后果是好与坏各半：
换任何厂家的 PLC 都能上手（positive）；但语言进化被冻结在 1993 年
的形态（negative）——工程语言用"不进化"买"不分裂"。

## 三、第三栏：规范化——标准族谱与户口

| 层次 | 状态 |
|------|------|
| 国家学科户口 | GB/T 13745：41310 控制科学与技术（三级八支）——制度完成 |
| 图纸与语言标准 | ISA-5.1（P&ID 图例）、IEC 61131-3（PLC 五语言）——**业内强制** |
| 工厂结构标准 | ISA-88（批处理）、ISA-95（企业-控制系统集成五层）——架构语法 |
| 接口与互操作 | 4-20mA/HART、现场总线（Profibus/FF）、OPC-UA——跨厂商缝合线 |
| 功能安全标准 | IEC 61508（母法）/ISO 26262（汽车）/DO-178C（航空）——**安全等级=SIL** |
| 理论公理化 | **不属地**：定理住 12030/41015；本家族只引用不生产 |

**为什么是这样（第三栏）**：与数学家族"公理化到 ZFC"对照，
本家族的规范化是**标准族谱**——因为它的"公理"不是集合论，
而是**多方信任**：仪表厂、PLC 厂、总包商、业主、验收官、保险公司
六方要在没有共同理论背景的情况下合作，唯一可行的"公共逻辑"
就是共同签署的标准文本。**标准=工程界的社会契约**，
SIL 等级=把"多安全"变成可定价、可投保的离散档位。

## 四、与其他学科语言的翻译表（⑤联系表）

| 对方 | 我方对应物 | 翻译时的信息损失 |
|------|-----------|----------------|
| 12030 控制理论（传函/状态空间） | 方块图+频域黑话 | 定理的前提条件（线性、无饱和）常被现场省略 |
| 软件工程（代码/测试） | 梯形图/SFC+验收试验 | 覆盖率测试≠安全论证；实时语义软件工程原生不表达 |
| 电子工程（原理图） | 回路图+信号标准 | 接地/屏蔽等模拟细节在方块图里隐形 |
| 管理科学（流程图） | ISA-95 层级图 | 物理时间约束在管理流程图里不可见 |
| 军事学（作战流程） | C2/OODA 环 | 交战规则的法律语义工程图不管 |

## 📌 收束

控制工程的语言=**图优先（多工种最小误读）+规范推理（标准条文）
+验收终审（跑给你看）**。听懂了"为什么说三遍"，你就能在
理论论文、标准文本、现场图纸之间自由穿越。
下一章看这门学科怎么"造"东西：[03-可构造与结构](03-可构造与结构.md)。

**🧠 认知升维**：
- **读者眼**：写任何工程文档先问"半夜两点谁在读"——
  语言选择的第一变量是读者工况，不是表达力
- **标准眼**：读标准文本像读法条——它不是技术建议，
  是多方签署的社会契约，每个"shall"背后是一次事故
- **证据分档眼**：听到任何工程断言，先分档——定理/规范/验收，
  三档的证据强度与失效方式完全不同
