# 04 · 控制科学与技术转代码：硬实时的走廊与裂缝

> **本章回答五问之五（家族层）：这个分支的问题怎么变成 code 问题？**
> **本质一句话**：控制回路是人类最古老的**硬实时程序**——
> 代码只是环上的一环，它的第一性质不是"算得对"而是"**到得准**"：
> 晚到的正确答案就是错误答案。本章给三件套：
> 可机械化边界 / 六条代码走廊 / 工程师落点，外加裂缝清单。

📖 **开篇故事**：一台化工厂的 DCS 里跑着上万个 PID 回路，
每个回路每秒执行 10-20 次。没有人惊叹它——直到某天一个工程师
把控制任务部署到了资源争用的系统上：控制量晚到 200ms，
阀门动作慢半拍，整个精馏塔开始晃。**代码一行没改，只是迟到了。**
这就是本学科转代码的第一课，也是它和普通软件工程的分水岭：
**普通程序的正确性=输出对；控制程序的正确性=输出对∧时刻对。**

---

## 一、可机械化边界（三件套之一）

| 任务 | 可机械化？ | 说明 |
|------|-----------|------|
| 回路离线仿真（阶跃/扰动/整定试验） | ✅ 全自动 | 数值积分+指标计算——家族实验即样本 |
| ZN 型整定 | ✅ 全自动 | 受控实验+查表，按钮级（1984 起产品化） |
| 回路性能监控（回路好不好要人看吗） | 🟡 半自动 | 指标（方差/振荡检测/阀行程统计）自动算，诊断裁决在人 |
| CBF 安全过滤（每拍小 QP） | ✅ 全自动 | 十几行代码的二次规划（走廊⑥） |
| PLC 联锁逻辑回归 | 🟡 半自动 | OpenPLC 类可跑仿真回归，但规范符合性仍人审 |
| 认证证据链生成（SIL/DO-178C） | ❌ 不可全自动 | 标准是自然语言社会契约——01 章方向四在攻窄门 |
| sim2real 缺口消解 | ❌ 原则上不可 | 物理世界的毛边（间隙/温漂/装配差）没有数字源 |
| 责任/权限分配（放权边界） | ❌ 不可 | 伦理与法律问题，代码只能执行不能决定 |

## 二、代码走廊总表（三件套之二）

| 走廊 | 问题类型→形态→栈 | 承诺强度 |
|------|-----------------|---------|
| ① 离散回路仿真 | "这个环稳不稳" → ZOH+数字 PID+数值积分 → 纯 python/numpy | 算得准（线性对象可对解析解） |
| ② 嵌入式实时 | "上真机" → 裸机/RTOS( FreeRTOS )/实时 Linux(PREEMPT_RT) → C | 到得准（WCET 分析配套） |
| ③ PLC/IEC 61131 | "工厂联锁与顺控" → 梯形图/SFC/ST → OpenPLC/商用 IDE | 确定性扫描（周期全读-全算-全写） |
| ④ 机器人中间件 | "多关节多节点" → ros2_control + 实时执行器 → C++ | 组件化实时（环路订阅/硬件接口抽象） |
| ⑤ 物理仿真/数字孪生 | "真机前体检" → MuJoCo/Isaac/Gazebo+ODE 求解器 | 算得近似（模型保真度=天花板） |
| ⑥ 安全过滤器 | "学习策略别闯祸" → CBF-QP 每拍小优化 → 自写/osqp | 算得快（QP 十几行、毫秒内） |

### 走廊①：离散回路的直译（本章主样本）

方块图到代码是**逐框直译**——求和点一行、控制器一段、对象一个
积分函数。家族实验 [experiments/pid_second_order.py](experiments/pid_second_order.py)
就是完整走廊：零阶保持（ZOH，控制周期 50ms）、对象高分辨积分（0.5ms）、
微分滤波、抗饱和，全部 <150 行纯标准库。三个工程细节是走廊的灵魂：

```python
# 数字 PID 的三个"工程必需"（缺一个就不是工业控制器）
e = r - x
d_raw = (x - pv_prev) / TC          # 微分取测量值:防设定值突跳(derivative kick)
d_filt += 0.4 * (d_raw - d_filt)    # 一阶滤波:微分是噪声放大器,必须滤
u_unsat = kp*e + integ - kd*d_filt
u = clamp(u_unsat, U_MIN, U_MAX)    # 执行器饱和
if 未饱和 or 误差拉离饱和: integ += ki*e*TC   # clamping 抗饱和
```

### 走廊②③：真机的两副面孔

- **嵌入式走廊**的纪律：控制任务最高优先级、看门狗、栈上限、
  **禁止动态内存**（不确定性来源）、浮点变定点（8 位 MCU 无 FPU 时）。
  WCET（worst-case execution time，最坏情况执行时间）是设计输入
  不是事后测量——"平均 3ms、最坏 50ms"的循环不能进 10ms 控制环
- **PLC 走廊**的纪律：**扫描周期架构**——每周期全读输入、全算逻辑、
  全写输出，任何一条逻辑的"执行时间"都是整个扫描周期。
  这故意放弃了事件驱动的效率，买到**全局确定性**：
  任何工程师都能在脑中按"上一拍状态→这一拍输出"推理——
  装置语言（02 章）与装置架构（03 章）在此合流

### 走廊④⑤：机器人的两段旅程

ros2_control 把"控制器算法"与"硬件接口"解耦——同一 LQR/
阻抗控制器既连仿真硬件也连真机关节；走廊⑤是 sim2real 的左岸：
物理引擎的接触模型精度直接决定过河的湿鞋程度（41320 仿真是主场，
机器人现场见 [讲透机器人](../../讲透机器人/)）。

### 走廊⑥：CBF-QP 安全过滤器（01 章方向三的代码形态）

```python
# CBF 安全过滤器骨架:控制器出什么都行,我这拍只做最小修改
# 安全集 h(x)>=0;要求每拍 dot_h >= -alpha*h
# u_des=任意控制器(含学习);u*=argmin ||u-u_des||^2  s.t. Lf*h(x)+Lg*h(x)*u >= -alpha*h(x)
# 单约束闭式解:若 u_des 可行→原样放行;否则投影到边界
lhs = Lf_h + Lg_h * u_des + alpha * h
if lhs >= 0: u_safe = u_des               # 安全,放行
else:        u_safe = u_des + (-lhs)/Lg_h # 最小修改,拉回边界
```

外挂式、不侵入、每拍常数时间——"加装安全带"架构的代码化身。

## 三、工程师落点（三件套之三；性能工程视角）

1. **控制环是硬实时负载**：抖动（jitter）吃相位裕度——
   50ms 周期 ±10ms 抖动的环，等效于设计了一个 60ms 环。
   措施：CPU 隔离（isolcpus）、优先级抢占（PREEMPT_RT）、
   关闭省电降频（频率漂移=时钟漂移）
2. **算力选型跟着控制律走**：PID 在 8 位 MCU 上跑了一百年；
   MPC 要解优化（QP 求解器，如 osqp，μs-ms 级）；神经策略要
   NPU/边缘 GPU——**控制律复杂度直接决定 BOM 成本**，
   这是与 [讲透高性能计算](../../讲透高性能计算/) 的接口现场
3. **系综与扫描的天然并行**：整定批量试验（03 章练习 1）、
   蒙特卡洛鲁棒性验证、CBF 参数扫描——全部 embarrassingly
   parallel，GPU 一次启动全扫（对齐
   [讲透GPU与系统级](../../讲透GPU与系统级/) 的经验）
4. **HIL 是 CI 的装置版**：真控制器+实时仿对象，每个固件版本
   跑回归——"验收试验推理"（02 章）的自动化形态；
   车规/航空工程里 HIL 台架是认证证据链的生产线
5. **定点化与溢出**：整数化定点控制器的溢出行为=飞控事故史
   （Ariane 5 的 64 位浮点转 16 位整数溢出是必修案例）——
   数值分析纪律在装置层的最后一公里

## 四、裂缝清单（原则上/工程上的不可转）

1. **sim2real 不可机械消除**：仿真没有装配公差、温漂、磨损的
   数字孪生源——每台真机都是"仿真+一台未建模机器"；
   域随机化是统计缓冲不是消除
2. **认证不可全自动**：标准条文是自然语言的社会契约——
   自动化只能做到"证据归档"，符合性判断在人（01 章三道门之第三道）
3. **责任分配不可编译**：自主系统出错的问责是法律问题——
   代码只能实现权限矩阵，不能生成权限矩阵
4. **最坏情况的不可知性**：现代硬件（缓存/分支预测/中断风暴）
   使 WCET 本身难封顶——硬件的"平均快"与控制的"最坏稳"天然相斥，
   这是本家族与性能工程最深的哲学分歧现场

## ✍️ 练习

1. **抖动实验**：家族实验里把控制周期加 ±30% 随机抖动，
   对比固定周期——量化"jitter 吃裕度"
2. **CBF 上环**：按走廊⑥骨架，给实验的 PID 外挂
   "位置不许超 1.1m"的屏障（h=1.1-x），把设定值改成 1.05 逼近边界，
   观察过滤器何时开始干预——✨③ 的亲手复现
3. **WCET 预算表**：为一个 1kHz 关节伺服环列预算（采样+滤波+控制律+
   通信+余量），合计不得超过 800μs——体会"时钟先行"的算术

## 📌 收束

控制转代码的图景：**仿真走廊全可算（①）、真机走廊以确定性为纲
（②③④）、物理走廊近似有价（⑤）、安全走廊一行不等式（⑥）；
裂缝在 sim2real、认证、责任、WCET 四处**。
选走廊看承诺强度，过裂缝靠证据不靠信念。

[八支家族树](README.md#一八支家族树)。

**🧠 认知升维**：
- **时刻眼**：读任何控制代码先问"它什么时候执行、最坏什么时候完"——
  时刻比数值更不可协商
- **承诺分档眼**：仿真=算得准、真机=到得准、孪生=算得近似、
  过滤器=算得快——不同走廊的证据力不同，别混用
- **裂缝眼**：看到"全自动认证/零 sim2real 差距"的宣传，
  先对着四条裂缝打对折——工程成熟度=承认裂缝的能力
