# landlock-run entry/main.c — 自限制后执行的原生沙箱启动器

> 原文件：[`native/landlock-run/packages/entry/src/main.c`](../../../explore/deepseek-ai/deepseek-harness/native/landlock-run/packages/entry/src/main.c)（298 行 · C11 · musl 静态链接）

## 角色定位

`landlock-run` 是一个独立的原生可执行文件，做的事可以用一句话讲完：**对自身施加 Linux Landlock 规则集，然后 exec 目标命令**（self-restrict-then-exec）。规则集经 `execve` 继承，目标命令从第一条指令起就被限制在允许列表内；而调用它的进程（sandbox-local 的 runner）自身不受影响。它是沙箱链条的最末端之一：Linux 上当 bwrap 不可用时，受限命令就是被这个 298 行的 C 文件包裹执行的。

选择用纯 C 写而不是走 Node addon 的 JS 路径，是因为这个程序的职责恰好是"在运行时环境建立之前就把边界画好"——它越小、越独立、依赖越少，边界越可信。

## 内部结构

**命令行契约**：`landlock-run [--ro <path>]... [--rw <path>]... -- <argv>...`，外加探测模式 `--probe`。`--ro` 路径授予读+执行；`--rw` 路径授予完全访问；**其余一切路径默认拒绝**——allow-list 语义，没有"默认放行"这个方向。`--` 之后是被包裹命令及其参数。

**自声明 UAPI**：文件内本地声明 Landlock 的系统调用接口（结构体、syscall 号、常量），不依赖系统头文件版本——内核 Landlock UAPI 演进时，这份声明自己管理兼容，构建环境不参与。

**ABI 协商**：创建规则集时按内核支持的 ABI 版本协商规则；遇到旧 ABI 时**部分接受**（某类规则内核不认识就降级掉）并在 stderr 报告被降级的部分——诚实告知"这份沙箱比要求的松在哪"，而不是静默假装满足。

**fail-closed 控制流**：规则集创建失败、或内核确认不会强制执行（`prctl` 返回不支持）时，以**退出码 125** 拒绝 exec——绝不带着未生效的限制执行目标。125 成为一个稳定的机器可判契约："沙箱建立失败"，与"目标命令自己失败"区分开。

**实现纪律**：纯 C11 单文件；仅依赖静态链接的 musl libc——没有动态库、没有运行时初始化，产出的二进制在任何 Linux 上行为一致。

## 外部连接

构建侧：`scripts/build.ts` 按目标架构编译，产物进入 `@deepseek-ai/node-addon-landlock-run` 平台包（native/README.md 是源码记录）。运行侧：`sandbox-local` 的 Linux runner 链在 bwrap 之后把它作为兜底 runner 探测（`--probe` 即探测协议）并在 confine 时生成 `--ro`/`--rw` 参数序列。图谱上它没有 import 边——一个自包含的原生入口，这也是它的设计要点之一。

构建产物按目标架构分别编译，随 `@deepseek-ai/node-addon-landlock-run` 平台包发布——宿主安装时按平台选中对应二进制，`native/README.md` 记录源码与构建产物的对应关系。探测协议（`--probe`）的输出是给机器读的：sandbox-local 的 runner 链据此判定 Landlock 兜底是否可用；探测失败与执行失败同样走 fail-closed，不存在"探测不过但先跑跑看"的分支。

## 数据流

正常路径：解析参数（收集 ro/rw 路径与目标 argv）→ 本地声明的 syscall 创建 ruleset（每条 path_beneath 规则对应一个授权路径）→ ABI 协商（旧内核降级部分规则并 stderr 记录）→ `prctl` 对**自身**应用限制 → `execve` 目标 argv——此刻起，目标进程继承规则集，只读路径可读可执行、读写路径全权、其余文件系统操作被内核拒绝。探测路径：`--probe` 只走到"创建+应用"为止，输出能力报告后退出，供上层 runner 链判定可用性。失败路径：任何一步建立不起来 → stderr 报告 + 退出码 125，目标命令从未开始。

## 设计决策

**self-restrict-then-exec 而非监督进程**：不需要常驻的监督者盯梢，限制随 exec 继承是 Landlock 的原生语义。启动器在 exec 后就退场——少一个组件，少一类攻击面（监督进程本身被攻破怎么办的问题不存在了）。

**allow-list 默认拒绝**：白名单外的世界不是"未定义"，是"拒绝"。写安全工具时的默认方向选择，这里给了教科书答案。

**退出码 125 的显式契约**：调用方（sandbox-local）凭它区分"包裹失败"与"命令失败"——后者可能是业务正常退出码，混淆两者会让 fail-closed 变成误报机器。

**自声明 UAPI**：把内核版本兼容从构建期搬到运行期协商，配合"旧 ABI 部分接受+stderr 报告"，同一份二进制跨内核版本部署而行为可预期。

**musl 静态链接**：运行时依赖为零。对于一个安全边界组件，"它的行为不依赖宿主环境"本身就是安全属性。

## 新人提示

第一次接触这个文件，先跑 `--probe` 看你本机内核的 Landlock 能力报告，再读参数解析——顺序反过来容易在 ABI 细节里迷路。理解"调用进程不受限"这句文档：限制作用在 landlock-run 自身与它 exec 出的后代，sandbox-local（调用者）不在其内——这是特性不是漏洞，沙箱策略本来就只该罩住模型引发的命令。排查"目标命令权限不够"时，把生成的 `--ro`/`--rw` 参数序列打出来对着路径查，九成是 allow-list 少放行了一个工作目录。看到 stderr 有降级报告不要忽略——那是内核旧 ABI 的诚实提示，说明实际隔离弱于策略要求，安全敏感场景应该当失败处理。读 C 代码时留意它刻意不用的东西：没有 malloc 大家庭、没有字符串格式化花活——每个"没用"都是攻击面的减法。还有一个对称性值得体会：退出码 125 只在"包裹失败"时出现，目标命令的退出码则原样透传——上层据此能精确区分"沙箱没建成"与"命令自己失败"，这个区分是 fail-closed 能落到运维层面的前提。
