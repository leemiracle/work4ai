  The API Proxy system serves as the unified communication gateway between the DeepSeek Harness (dsh) host (Node.js) and its clients (Browser/Web UI or In-Process). It defines a type-safe RPC protocol using a four-quadrant message model, handles SSE/WebSocket streaming, and enforces strict schema validation via Zod [packages/client/connection/README.md:10-12].

 
## System Architecture

 The architecture decouples the logical API contract from the physical transport carrier. The `HostConnectionService` (in `client-connection`) implements the business logic and trust boundaries on the host, while the `TypertGateway` manages the dispatching of calls to registered Cordis services [packages/client/connection/src/index.ts:108-112], [packages/api/gateway/src/index.ts:173-174].

## RPC Protocol Definition

 The protocol uses a discriminated union of message types, ensuring type safety across the wire. Every Host RPC method and WebSocket stream requires a valid browser session established via a signed cookie [packages/client/connection/README.md:33-35].

### RPC Method Domains

 The `TypertGateway` dispatches to various services registered in the Cordis context:

 
 - **`session.*`**: Handled by `SessionController`, including `follow` (stream), `page` (history), and `control` [packages/api/session-controller/src/history.ts:87-87], [packages/api/session-controller/src/history.ts:51-51].
 - **`settings.*`**: Handled by `SettingsController`, including `describe`, `update`, and `mutate` [packages/api/settings-controller/tests/settings-controller.host.spec.ts:81-91].
 - **`host.*`**: Core host facts and directory picking.
 
 
## Schema Validation & Type Safety

 Every message crossing the wire is validated using Zod schemas to ensure structural integrity and to brand types for internal use [packages/client/connection/src/index.ts:34-41].

 
### Schema Definitions

 
 - **`rpcMessageSchema`**: The top-level envelope for all RPC traffic [packages/client/connection/src/rpc-schema.ts:38-38].
 - **`clientRequestSchema`**: Validates the `RpcId`, `method`, and `params` of an incoming call [packages/client/connection/src/rpc-schema.ts:35-35].
 - **`sessionEventSchema`**: (In `dsh-session`) Strictly defines the sequence (`seq`) and payload of session updates [packages/api/session-controller/src/history.ts:6-6].

## Streaming & Event Muxing

 The system handles real-time updates through a combination of HTTP long-polling/SSE and a primary WebSocket Mux.

 
### Connection Generations

 A `ConnectionGeneration` represents a stable period of connectivity. It is established only after the Host sends a `{ type: 'ready' }` frame [packages/client/connection/README.md:42-44].

 
 - **Readiness**: The `ConnectionController` publishes the generation only after the `ready` item arrives, preventing baseline acquisition from racing ahead of incremental updates [packages/client/connection/README.md:44-44].
 - **Recovery**: If the `$events` stream ends or fails, the controller withdraws the generation and initiates a reconnect with backoff [packages/client/connection/README.md:45-46].
 
 
### Session History & Following

 The `SessionHistoryController` provides two main patterns for event consumption:

 
 - **`page()`**: Contiguous, message-aligned history pagination for "cold" session views [packages/api/session-controller/src/history.ts:51-51].
 - **`follow()`**: An `AsyncIterable` that yields a complete opening `snapshot` followed by live `event` frames [packages/api/session-controller/src/history.ts:87-87].
 
 
## Session Export & Binary Routes

 Beyond JSON-RPC, the `HostConnectionService` allows packages to register exact `GET` or `HEAD` routes for binary data [packages/client/connection/README.md:28-28].

 
 - **Registration**: Features like session-log downloads register their endpoints with the connection service [packages/client/connection/README.md:28-28].
 - **Trust Fence**: These binary routes are still protected by the Host/Origin browser-trust fence and authentication check [packages/client/connection/src/index.ts:93-95].
 - **Buffering**: The current HTTP bridge buffers request bodies in memory, with a default limit (`maxRequestBodyBytes`) of 300 MiB [packages/client/connection/README.md:61-61].
