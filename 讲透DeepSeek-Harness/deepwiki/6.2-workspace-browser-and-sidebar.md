  The Workspace Browser and Sidebar system is the central navigation and workspace/session management interface in the DeepSeek Harness (dsh) web client. It orchestrates the display and interaction of sessions grouped into workspaces, allows searching across sessions, supports operations like add/rename/reorder/fork/archive, and manages layout transitions between expanded and collapsed (rail) sidebar states. The system spans multiple UI packages, integrating reactive state management, slot-based UI composition, host API data, and capability-based directory picking.

 
---

 
## Overview

 The core architecture comprises three interrelated packages:

 
 - **`ui-sidebar`**
 Provides the sidebar shell component (`SidebarRoot`) which manages the sidebar's expanded/collapsed lifecycle, layout, and rail geometry. It implements a two-step transition that freezes content width while fading, preventing layout thrashing during collapse/expand.

## 1. Sidebar Lifecycle & Layout (`ui-sidebar`)

 The sidebar supports three major visual states, realized in CSS classes and React state:

 
| State | Description | CSS Class |
|---|---|---|
| Expanded | Full width sidebar (typically ~260px) showing full contents, including wordmark, workspace tree, controls. | .wide (SidebarRoot.module.css53-55) |
| Fading | Transitioning state during collapse: content fades opacity to 0 over 150 ms without reflow. | .fading (SidebarRoot.module.css47-50) |
| Rail (Collapsed) | Narrow rail mode (56px width) showing icons only; controls centered inside a 36px tall rail with padding. | .collapsed (SidebarRoot.module.css28-30) |

 **Transition Flow**
 The collapse/expand animation is not a fluid size morph but a two-phase animation:

 
 - Phase 1: Freeze sidebar width and fade content opacity.
 - Phase 2: Switch layout to the rail with no content; controls slide in from right edge. This prevents intermediate layout jitter or reflow.

## 2. Workspace Browser (`ui-workspace`)

 The `WorkspaceBrowser` component renders the hierarchy of sessions organized by workspaces, or a flat list, along with search results.

 
### 2.1 Data Model & Tree Derivation

 
 - Workspace data is sourced from the Host API via a global reactive hook `useWorkspaces()` which returns a `WorkspaceSnapshot` containing workspaces and their sessions.
 - Sessions belong to zero or one workspace identified by `workspaceId`. Sessions without a workspace are placed in a special **Ungrouped** bucket.
 - The tree structure is computed in the `tree.ts` file via `deriveGroups` and `deriveFlat`. These functions reconcile session order based on a mode: 
 - **Manual** (drag-and-drop adjusted order).
 - **Updated** (sorted by last interaction time).
 - Sessions flagged with `origin === 'subagent'` are filtered out of the sidebar tree view and surfaced in the parent's subagent page header instead.

### 2.2 Search Functionality

 The Workspace Browser offers a hybrid search experience:

 
 - **Local Matching**
 Instant substring match in session title and workspace label (case-insensitive). This provides instantaneous results to indicate matches.
 - **Host Backed Search**
 A debounced (250 ms) RPC request to the sessions service `sessions.search(query, signal)` retrieves content-based matches and ranked snippets.
 - **Sanitization**
 Queries are truncated at 500 UTF-16 code units to respect wire schema constraints and avoid breaking surrogate pairs.
 
 Selected search results include workspace context, and opening a result navigates to the session without clearing the search field.

## 3. Workspace Picker & Directory Flow (`ui-workspace` and directory-picker seam)

 The `WorkspacePicker` component (filling the `conversation.hero.workspace` slot) allows users to pick a workspace directory for creating or switching to a workspace. It supports the directory flow pattern with dedicated child holes in the slot system:

 
 - Two directory-flow holes are declared:

 
 - `'sidebar.workspaces.directoryFlow'` for the sidebar
 - `'conversation.hero.workspace.directoryFlow'` for the picker hero
 - These holes are filled by a composed directory picker package's client half, which depends on the host's directory picker capability seam: either a native OS chooser (`directory-picker-native`) or an in-app browsing flow (`directory-picker-browse`) [directory-picker capability seam decision: `.agents/notes/implemented/architecture/2026-07-28-directory-picker-capability-seam.md`].
 - Once a directory is picked, a sequence of callbacks (`open`, `busy`, `onPicked`, `onCancel`, `onError`) are emitted via the slot owner conversation to advance the flow.
 - The owner uses this to call `workspaces.create({path})` which triggers host workspace creation and refreshes the client cache.

## 4. App Layout & Column Management (`ui-layout`)

 The `AppFrame` component in `ui-layout` manages the high-level grid layout, particularly the sidebar column width and its transitions.

 
 - The sidebar width is controlled as a CSS grid track, toggling between wide (expanded) and narrow (rail) widths.
 - When collapsing, the sidebar content is frozen in width and opacity fades out before the grid track snaps to the narrow width, preventing layout shifts that would cause repaint or reflow spikes.
 - The `AppFrame` is the common composition root for sidebar, main conversation, and other side panels.

## In-Depth: Key Classes and Functions

 
### `WorkspaceBrowser` ([packages/client/ui-workspace/src/client/WorkspaceBrowser.tsx])

 
 - Renders the workspace tree or flat session listing.
 - Uses locale translation from injected context.
 - Integrates search field and per-session interaction states.
 - Reactively subscribes to workspaces and sessions via global hooks.
 - Calls into tree derivation functions `deriveGroups()` or `deriveFlat()` for rendering.
 
 
### `Rows.tsx` ([packages/client/ui-workspace/src/client/rows/Rows.tsx])

 
 - `ProjectRowItem` displays a workspace group header: folder icon, label, expand/collapse chevron, menu actions (rename/delete), draggable row with drag events for reordering.
 - `SessionNodeItem` displays sessions: title, time labels (relative/hover/created), status dots, and user menu actions (fork, archive, rename).
 - All hover interactions (tooltips, menus) are debounce and CSS-driven to optimize UX.
 - Drag and drop APIs enable reorderability of sessions and workspaces with precise insertion points (before/after half-row).
 
 
### `UiWorkspaceService` ([packages/client/ui-workspace/src/client/navigation.ts])

 
 - Coordinates session start, archive, fork.
 - Manages workspace creation lifecycle with adoption of new paths from directory picker flow.
 - Connects host client APIs to UI flows.
 
 
### `SidebarRoot` ([packages/client/ui-sidebar/src/client/SidebarRoot.tsx])

 
 - Controls expanded/collapsed states.
 - Listens to user input for toggling sidebar.
 - Applies CSS classes for fade and slide animations.
 - Hosts the slot where `WorkspaceBrowser` content is injected and rendered.
 
 
---

 
## Known Limitations and Deferred Work

 
 - No fuzzy search within session content; search is literal token/phrase matching only.
 - Archived sessions cannot be restored or deleted through the UI currently.
 - The native OS chooser is only available when running on local hosts (not remote or browser-only clients). Remote clients use the browse backend for directory selection.
 - Hidden files in directory listings rely on POSIX dot prefix; Windows hidden attribute is not detected due to Node.js dirent limitations.
