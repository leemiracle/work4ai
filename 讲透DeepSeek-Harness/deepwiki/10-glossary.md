  This glossary defines key codebase-specific terms, jargon, abbreviations, and domain concepts used throughout the DeepSeek Harness (dsh) repository. It serves as a technical reference for onboarding engineers to understand how natural language and domain concepts are mapped and implemented as code entities within the system.

 
---

 
## Core Concepts & Framework

 
### Cordis

 The foundational plugin framework used by dsh. Cordis organizes system functionality as injectible, reversible plugin units that work on a shared typed `Context` (`ctx`). All dsh subsystems (agent, tools, session, LLM adapters, etc.) are Cordis plugins, making the entire system extensible and composable [docs/architecture.md9-14](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/architecture.md?plain=1#L9-L14)

 
### Context (`ctx`)

 The central shared object representing the running environment. It is injected into any plugin and augmented with services. These services implement domain capabilities, e.g., `ctx.llm` for language model interaction, `ctx.tools` for tool execution, and `ctx.sessions` for session persistence. The context is the primary vehicle for passing state and functionality in dsh [docs/architecture.md43-51](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/architecture.md?plain=1#L43-L51)

 
### Service

 An interface and its implementation exposed on the `ctx` object. Each service represents a capability seam. For example, the tool registry and execution pipeline is the Tools service (`ctx.tools`), while the LLM interaction layer is the LLM service (`ctx.llm`). Services are implemented by plugins and may depend on each other [docs/architecture.md98-103](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/architecture.md?plain=1#L98-L103)

 
### Profile

 A named runtime configuration and composition of bundles and user patches stored in the Harness home (`DSH_HOME`). Profiles define which bundles to load and their layering order. Examples include `web`, `headless`, `sdk`, and `acp`. Profiles support live patch reload to modify behavior during runtime [docs/architecture.md19-27](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/architecture.md?plain=1#L19-L27)

 
### Bundle

 A self-contained distribution unit that encapsulates Cordis config rows and the code they mount, intended to be composable and patchable. Bundles represent subsystems or feature groups, e.g. `dsh-base` is shared foundational functionality, `dsh-web-app` adds the web UI layer [docs/architecture.md21-25](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/architecture.md?plain=1#L21-L25)

 
### Capability Seam

 An architectural pattern in dsh where a capability is represented by a service interface and its interchangeable implementations (providers). Consumers of that capability do not depend on the concrete implementation and communicate via the service interface. Common seams include filesystem (`ctx.fs`), tools (`ctx.tools`), and subprocess spawning (`ctx.subprocess`) [docs/architecture.md98-102](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/architecture.md?plain=1#L98-L102)

## Agent & Execution Loop

 
### Turn

 A unit of agent interaction starting when input messages are claimed and ending when the agent has no more output or pending work. It encompasses zero or more steps. Turns correspond to conversational turns or atomic reason-execute cycles [docs/architecture.md65-66](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/architecture.md?plain=1#L65-L66)

 
### Step

 An iteration within a turn consisting of sending a single request to the LLM and executing any tools invoked within that request. Steps produce messages and tool results appended to the session log [docs/architecture.md65](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/architecture.md?plain=1#L65-L65)

 
### Inbox

 The agent's input queue managing incoming messages, followups, steering, or injections. It ensures threadsafe and ordered delivery of communication to the agent loop [packages/core/agent-loop/src/agent.ts12-35](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/agent-loop/src/agent.ts#L12-L35)

 
### Waterfall

 A Cordis event type where listeners are called sequentially in order, each deciding whether to pass control via `next()`. Waterfall events allow interception or enrichment of the underlying operation, for example, `agent/pre-step` is a waterfall that plugins can hook into for step pre-processing [docs/architecture.md93-95](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/architecture.md?plain=1#L93-L95) [docs/event-producer-consumer.md18](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/event-producer-consumer.md?plain=1#L18-L18)

 
### Code Mode

 A tool execution mode where the agent operates by generating and running code (e.g., JavaScript or Python) using a special `run_code` tool. This allows complex logic to be expressed programmatically rather than through direct tool calls. The SDK representing tool APIs is generated for this purpose [packages/core/tools/src/code-mode.ts24](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/code-mode.ts#L24-L24)

## Data & Persistence

 
### Session Log

 An append-only durable log of all session events representing the conversation and state changes. It is the single source of truth for reconstructing the agent's memory and discourse history. Events include `user/message`, `assistant/message`, `tool/result`, and others [docs/architecture.md92-94](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/architecture.md?plain=1#L92-L94)

 
### Surface

 An in-memory projection of the session log events to provide derived, current-state views such as conversation threads or model-visible history. Surfaces are used by UI components and reasoning logic to interpret session data efficiently without replaying the full log on every access [packages/core/session/src/surface.ts13-45](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/surface.ts#L13-L45)

 
### deriveMessages()

 A core utility function that reads from the raw session event log and projects a message history consumable by the language model engine, filtering and annotating as needed [packages/core/session/src/surface.ts90-130](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/surface.ts#L90-L130)

 
### SESSION_FORMAT_VERSION

 A `number` constant representing the schema version of serialized session data on disk. It starts at `0` during pre-release and governs compatibility in session persistence [packages/core/session/src/types.ts15-35](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/types.ts#L15-L35)

## Tooling & Interaction

 
### Tool Registry

 The service `ctx.tools` managing the catalog of available model-facing tools, their schemas (input/output structures), and the guarded pipeline for tool invocation. It mediates tool calls for security, approval, and result processing [packages/core/tools/src/index.ts15-60](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L15-L60)

 
### Tool Execution Waterfall

 The tool invocation lifecycle is split into three waterfall events:

 
 - **Pre-execute**: For approval policies or access control.
 - **Execute**: The core tool function call.
 - **Post-execute**: For result processing, side effects, or blocking [packages/core/tools/src/index.ts140-175](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L140-L175)
 
 
### Approval Seam

 An interaction point where the system or user can approve or deny tool execution by listening to the `approval/request` waterfall event. This enables interactive permission control [docs/event-producer-consumer.md29](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/event-producer-consumer.md?plain=1#L29-L29)
