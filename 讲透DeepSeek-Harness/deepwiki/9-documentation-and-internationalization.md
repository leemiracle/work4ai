  The DeepSeek Harness (dsh) documentation system is designed for a bilingual environment supporting collaboration between human engineers and AI agents. It enforces a rigorous **Bilingual Pairing contract** and incorporates automated quality gates, ensuring that all technical documentation, type declarations, and translations remain consistent and accurate throughout development.

 This parent page provides a high-level overview of the main components of the documentation system: bilingual pairing, type equivalence verification, the VitePress doc site, and the use of agent notes as canonical records. Detailed explanations and technical specifics reside in linked child pages.

 
---

 
## Bilingual Documentation & Translation Pairing

 DeepSeek Harness maintains all in-scope documentation (including READMEs, architecture files, and Agent Notes) strictly in two languages: English and Simplified Chinese. Both languages have equal authority; a document may originate in either language and the counterpart is translated accordingly. The bilingual pairing consists of a *triplet* of files in the same directory:

 
 - The English source: `foo.md`
 - Its Chinese counterpart: `foo.zh.md`
 - A consistency record: `foo.i18n.yaml`
 
 This triplet ensures that both language versions say exactly the same thing, preserving the document’s structure and semantic integrity. The `.i18n.yaml` consistency record stores **Git blob hashes** of each side’s content from the last confirmed state to detect out-of-sync translations, even before committing [docs/i18n/README.md9-38](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/README.md?plain=1#L9-L38) A custom Git merge driver (`dsh-translation-pairing`) automates conflict resolution for these records with three-way merges over the recorded blobs [docs/i18n/README.md20-23](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/README.md?plain=1#L20-L23)

 **Structural checks** ensure strict equivalence of headings, list items, table dimensions, link targets (with query and fragment suffixes), and byte-identical fenced code blocks between language pairs. Special care is taken for *language switcher lines* that link each language file to its counterpart to facilitate seamless navigation.

 Additionally, the agent skill `dsh-translate-docs` supports minimal, patch-based bilingual updates by generating "briefs" of changes from one side and applying minimal edits to the other, drastically improving translation maintenance efficiency [.agents/skills/dsh-translate-docs/SKILL.md20-30](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/ .agents/skills/dsh-translate-docs/SKILL.md?plain=1#L20-L30)

## Type Equivalence & Documentation Verification Gates

 To maintain accurate, up-to-date documentation tightly coupled to the code, dsh employs *Type Equivalence* gates. Developers embed TypeScript declarations directly in Markdown files as fenced code blocks tagged with attributes like `ts type-equiv` or `ts public-api`. The `verify-type-equiv` gate continuously checks that these snippets exactly match the authoritative source code definitions, preventing documentation drift.

 Additional verification tools enforce quality and structural correctness:

 
 - **Wordcount budgets** (`doc-budgets.manifest.json`) limit file lengths to avoid excessive verbosity.
 - **Model Experience (MX) documentation standard** sets README quality expectations specifically oriented for LLM comprehension.
 - **Markdown verification scripts** (`verify-md-links`, `verify-md-wrap`, and `verify-md-mermaid`) check links, line wraps, and diagram correctness.
 - **Publint-all** aggregates all these checks alongside linting.
 
 The entire documentation corpus is projected into a **bilingual VitePress website**. The manifest file `website/docs.ts` maps repository Markdown sources to site routes per locale, ensuring coherent navigation and language consistency [website/docs.ts1-44](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/website/docs.ts#L1-L44) The script `scripts/project-doc-site.ts` generates the localized site source by rewriting links and file references to point to finalized published routes or specific GitHub blob snapshots, guarding against stale references [scripts/project-doc-site.ts1-50](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/scripts/project-doc-site.ts#L1-L50)

## Documentation Tiers and Agent Notes

 The dsh documentation system uses a clear and precise stratification of content types to avoid duplication and confusion—maintaining exactly one authoritative home per fact or contract.

 
| Tier | Purpose | File/Path |
|---|---|---|
| Standing Orders | Essential rules for agent behavior across all sessions | AGENTS.md (root of repository) |
| Architecture Docs | Conceptual overviews of seams, loops, and core packages | docs/architecture.md |
| Terminology Source | Centralized bilingual terminology definitions and style conventions | docs/i18n/terminology.md |
| Agent Notes | Authoritative records of implemented and proposed decisions, rationale | .agents/notes/ directory |
| Package Contracts | Configuration semantics and README for individual packages | packages/**/README.md |
| Website Manifest | Structured manifest controlling docs published to the bilingual site | website/docs.ts |

 Agent Notes are themselves bilingual paired documents that serve as formal, trackable decisions and history logs for the project’s design and implementation rationale.
