  This page documents the systems and tools for managing goals, todos, workflow runs, web environment observation, and temporal scheduling in DeepSeek Harness (dsh). Together, these subsystems enable autonomous agent planning, progress tracking, multi-step orchestration, external knowledge retrieval, and timed actions.

## 1. Goal System

 The goal domain implements durable long-running objectives that agents autonomously advance through multiple conversational rounds. This system enables a persistent goal state with phases and revision control supporting concurrency and human-agent collaboration.

 
### Implementation & Components

 
 - The goal system is registered by the `@deepseek-ai/dsh-tool-goal` plugin, which registers three core tools on the global tool registry (`ctx.tools`):

 
 - `create_goal` — initializes a new goal [packages/goal/tool-goal/src/index.ts](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/goal/tool-goal/src/index.ts)
 - `get_goal` — retrieves the current goal state and metadata
 - `update_goal` — transitions goal phases such as `edit`, `pause`, `resume`, `complete`, and `blocked`
 - The primary data model is a `GoalRef` consisting of a goal ID and a current revision number. This is used for "compare-and-set" semantics in tool calls to avoid race conditions when updating the goal concurrently [packages/goal/tool-goal/tests/tool-goal.spec.ts130-160](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/goal/tool-goal/tests/tool-goal.spec.ts#L130-L160)
 - The system enforces constraints: `create_goal` rejects non-human or subagent authority calls, while `update_goal` applies policy on phase transitions including requiring a blocking reason and a configurable persistence threshold before blocking is effective [packages/goal/tool-goal/tests/tool-goal.spec.ts120-160](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/goal/tool-goal/tests/tool-goal.spec.ts#L120-L160)
 
 
### Data Flow and Behavior

 
 - An autonomous agent implements rounds driving the goal forward. The system tracks the revision history in the session event log and enforces consistency through the `GoalRef` mechanism.
 - Tools use exclusive execution modes to serialize updates to prevent conflicting writes [packages/goal/tool-goal/tests/tool-goal.spec.ts115-130](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/goal/tool-goal/tests/tool-goal.spec.ts#L115-L130)

## 2. Todo Tracking & Standing Plans

 The Todo system provides a model-facing structured task list that agents update as a **whole snapshot**, facilitating task planning and progress reporting.

 
### Key Tool: `todo_write`

 
 - The `todo_write` tool appends a `todo/write` event to the currently active agent's session, which contains the entire task list as a snapshot. Each new call replaces the previous list atomically [packages/todo/tool-todo/src/index.ts2-10](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/todo/tool-todo/src/index.ts#L2-L10)
 - To ensure data integrity and reflect the model's beliefs exactly, the tool validates that tasks:

 
 - Have non-empty trimmed contents,
 - Have unique contents (no duplicates),
 - Use strictly enumerated statuses: `'pending'`, `'in_progress'`, or `'completed'`.
 - The deployment config defines the concurrency policy (`allowParallelInProgress`). If `false`, the tool rejects any list with more than one `'in_progress'` item, enforcing sequential working behavior. If `true`, concurrency of multiple active tasks is allowed, which suits agents running concurrent subagents or background commands [packages/todo/tool-todo/src/index.ts91-111](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/todo/tool-todo/src/index.ts#L91-L111)
 
 
### Session Projection Integration

 
 - The standing plan is folded into the `todos` projection key (via the session-projection seam). It holds either the last todo list snapshot or `null` before the first write or after a turn resets it [packages/todo/tool-todo/src/index.ts135-145](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/todo/tool-todo/src/index.ts#L135-L145)
 - The projection resets to `null` on `turn/start` events to force re-planning each turn.
 - UIs read this projection to stable display the current todo list.
 
 
### UI Presentation (Web Client)

 
 - The `TodoPanel` React component mounts inside the conversation input dock slot to render the live todo list as a persistent strip.
 - It shows counts of task statuses with localized text and uses figma glyph icons for status visualization.
 - The `todo_write` tool also renders a keyed `tool.call.toolview` row representing the todo state summary and details, opening a side details column on click.
 - This client-side rendering ensures that only the last snapshot is active, and the UI is synched efficiently via session events, avoiding replay issues from folding todos into surface nodes [packages/client/ui-conversation/src/client/skeleton/TodoPanel.tsx](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-conversation/src/client/skeleton/TodoPanel.tsx) [packages/todo/tool-todo/README.md](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/todo/tool-todo/README.md?plain=1)

## 3. Workflow Runs & UI

 Workflows represent multi-agent or multi-step executions that require orchestration and live status tracking. The `ui-workflow-run` package renders these complex progress states.

 
### WorkflowRunPanel Component

 
 - Displays the workflow run status and phases with member details.
 - Maps internal workflow statuses (`WorkflowRunStatus` like `running`, `completed`, `failed`, `interrupted`) into UI states and colored state dots.
 - Automatically expands phases containing active or abnormal member sessions (failed, interrupted) for visibility.
 - Clicking on a member jumps to a subagent session managed by the workflow to allow in-depth inspection [packages/client/ui-workflow-run/src/client/WorkflowRunPanel.tsx23-192](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-workflow-run/src/client/WorkflowRunPanel.tsx#L23-L192)

## 4. Web Fetch & Search Tools

 The `@deepseek-ai/dsh-tool-web` plugin provides environment observation tools through a robust capability seam named `ctx.web` that bridges external web search and fetch operations directly into the agent tooling system.

 
### Search Tool (`web_search`)

 
 - Accepts multiple queries (up to a configurable `searchMaxQueries`, default 4).
 - Queries are performed concurrently to multiple sources, responses are merged in round-robin fashion while removing duplicates.
 - Permanently disables sources failing on initial load to preserve resilience.
 - Search results carry structured metadata including `answer` and `sources` with rich bibliographic details. This metadata persists across the tool view lifecycle for user inspection.
 - Returns a `card: 'web'` with `kind: 'search'` distinguishing it from fetch results [packages/web/tool-web/src/search.ts30-130](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/web/tool-web/src/search.ts#L30-L130)
 
 
### Fetch Tool (`web_fetch`)

 
 - Retrieves the raw content of specific URLs and applies HTML-to-Markdown conversion with Turndown for summarization.
 - Enforces a `fetchMaxOutputChars` limit (default 200,000) to constrain result size.
 - The UI card is a `card: 'web'` with `kind: 'fetch'`. It highlights the main URL, with title, metadata, and any truncation notices.
 - Presentation metadata enriches user comprehension of sources as part of the session projections [packages/web/tool-web/src/fetch.ts](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/web/tool-web/src/fetch.ts) [packages/web/tool-web/README.md](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/web/tool-web/README.md?plain=1) [packages/web/tool-web/tests/tool-web.spec.ts](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/web/tool-web/tests/tool-web.spec.ts)

## 5. Schedule & Time Context System

 The combination of the `@deepseek-ai/dsh-time-context` and `@deepseek-ai/dsh-schedule` plugins provide a durable, session-local temporal awareness and scheduled reminder system with explicit time zone handling.

 
### Time Context

 
 - Captures the current moment as a durable snapshot appended as a special `user/message` source in the session at the beginning of each turn/step.
 - Reads the browser-local IANA time zone (e.g., "Asia/Shanghai") from user message metadata and formats timestamps accordingly.
 - Includes baseline elapsed time since the prior model-visible message, enabling temporal reasoning.
 - Enforces invariants for proper turn/step alignment of time context messages [packages/context/time-context/src/index.ts](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/context/time-context/src/index.ts) [packages/context/time-context/tests/time-context.spec.ts](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/context/time-context/tests/time-context.spec.ts)
 
 
### Durable Scheduling

 
 - Manages reminders as persistent `schedule/change` events in the session log, preventing loss across process restarts and cold agent states.
 - Supports three types of schedules: 
 - `after` — delay in seconds after creation
 - `at` — exact date/time with mandatory IANA time zone
 - `every` — fixed interval (minimum 5 minutes), aligned to the creation timestamp avoiding backlog accumulation.
 - The schedule agent scopes owners per root agent and observes durable session state to enqueue due reminders only when idle, injecting follow-up turns [./.agents/notes/implemented/feature/2026-08-05-durable-web-schedule.md](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/./.agents/notes/implemented/feature/2026-08-05-durable-web-schedule.md?plain=1)
 - Avoids external notification of cold sessions; reminders re-fire if overdue when session resumes.
 - Handles daylight savings gaps, validation of exact calendar shapes, and serialization of all timestamp states in canonical RFC 3339 [packages/context/time-context/tests/invariant.spec.ts](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/context/time-context/tests/invariant.spec.ts) [apps/web/tests/schedule-after.e2e.ts](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/apps/web/tests/schedule-after.e2e.ts)
