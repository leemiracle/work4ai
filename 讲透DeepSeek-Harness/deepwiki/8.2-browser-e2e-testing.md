  DeepSeek Harness (dsh) employs a hermetic Playwright-based end-to-end (E2E) testing infrastructure designed to validate the full stack, spanning from the browser UI to the host-side agent loop and tool execution. This system leverages a specialized test scaffold to boot the shipped web application composition in an isolated environment. To achieve CI determinism given LLM non-determinism, it uses a deterministic replay mechanism with well-defined barrier synchronization rules.

 
## The Web Scaffold

 The central entry point for browser E2E tests is the `launchWebScaffold` function, which boots the complete *REAL* web composition by applying the `dsh-base` and `dsh-web-app` bundle layers over an empty profile root. This ensures the environment exercises the exact HTTP/WebSocket API gateway, real persistence backends, and host-to-browser bridge used in production [apps/web/tests/scaffold.ts3-7](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/apps/web/tests/scaffold.ts#L3-L7) It is not a simple mock or injection but mounts the real Cordis host framework and the real client bundles inside Chromium via Playwright.

 
### Execution Modes

 The scaffold operates in three mutually exclusive modes, controlled by the `DSH_SNAPSHOT` environment variable:

 
| Mode | Description |
|---|---|
| replay | Default/CI mode. Uses the dsh-llm-replay package to fulfill all host LLM adapter calls from local recorded fixtures (i.e., no real LLM). |
| record | Authoring mode. Uses actual live LLM adapters with valid credentials to record new session fixtures from live user interactions. |
| refresh | Maintenance mode. Keyless replay mode that regenerates ARIA snapshot goldens without invoking real models or modifying fixtures. |

 These modes allow developing, maintaining, and validating robust, deterministic browser E2E coverage without external dependencies in CI [apps/web/tests/scaffold.ts85-97](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/apps/web/tests/scaffold.ts#L85-L97)

 
### Composition Divergences

 To maintain a hermetic and stable test environment, the scaffold applies a carefully curated set of Cordis include patches upon initialization [apps/web/tests/scaffold.ts14-24](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/apps/web/tests/scaffold.ts#L14-L24):

 
 - **Temporary Roots:** Redirects main persistence and workspace directories (`persistenceRoot`, `workspaceCwd`, and skill root directories like `dshHome` and `agentsHome`) into isolated temporary folders. This prevents test artifact pollution and ambiguous state [apps/web/tests/scaffold.ts16-17](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/apps/web/tests/scaffold.ts#L16-L17)
 - **Model Displacement:** In replay and refresh modes, disables `llm-deepseek` and instead installs the `installLlmReplay` seam helper to fill the LLM adapter registry in the settled root context, guaranteeing all model calls are served via recorded fixtures [apps/web/tests/scaffold.ts21-24](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/apps/web/tests/scaffold.ts#L21-L24)
 - **Title and Instructions Disabled:** Disables fire-and-forget LLM calls such as session titles and agent instructions reducing non-deterministic background noise and improving test stability [apps/web/tests/scaffold.ts17-20](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/apps/web/tests/scaffold.ts#L17-L20)

## The Determinism Barrier

 Browser E2E tests depend on a *determinism barrier* to avoid race conditions between asynchronous browser rendering and the host-side agent processing. This barrier enforces that all state mutations are durable and visible before assertions occur.

 The barrier is a two-step sequence:

 
 - **Host Idle Barrier:** Await `agent.whenIdle()` with timeout keyed to the in-process `turn/end` event. This confirms the Cordis host agent loop has processed all input, flushed all persistence writes (including JSONL logs and snapshots), and effectively closed the turn [apps/web/tests/scaffold.ts27](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/apps/web/tests/scaffold.ts#L27-L27)
 - **Browser Settled Polling:** Poll the browser UI to verify the streaming UI updates are detached (no more `[data-streaming]` flags present) and the final text content is displayed and stable. This ensures the browser promise chain for React commits is fully resolved before snapshotting [apps/web/tests/scaffold.ts27](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/apps/web/tests/scaffold.ts#L27-L27)
 
 Importantly:

 
 - Single-shot DOM checks or `networkidle` events are banned since open SSE streams never resolve `networkidle`.
 - Polling persisted files directly for turn completion is also banned due to filesystem latency and NFS slowness.
 - Tool-controlled temporary readiness files may only gate interaction before idle barriers, never replace them.

## ARIA Snapshot Goldens

 Instead of fragile raw HTML or screenshot snapshots, the dsh E2E tests capture **ARIA accessibility snapshots**. These represent the UI as a structured tree of accessible roles, names, states, and properties, which provide the following benefits:

 
 - **Stability:** Robust against styling or CSS module class hash changes.
 - **Functional Sensitivity:** Sensitive to regressions in user-visible accessibility and UI semantics.
 - **Maintainability:** Easier to author and review than large DOM dumps or screenshots.
 
 
### Implementation Details

 
 - The accessibility tree rooted at a UI region (e.g., the conversation pane) is flattened into a precise marked-down hierarchy with roles (e.g., `listbox`, `button`), states (e.g., `[disabled]`), and visible text content.
 - Logical react component boundaries are preserved by directly sampling aria attributes and screen reader computed properties.
 - To handle variances in timing, repeated polling captures stable trees only when consecutive polls yield identical results.
 - Variable data such as UUIDs, timestamps, workspace directory names, and durations are tokenized and normalized for stable diffs.

## Key E2E Scenarios and Implementation

 The dsh browser E2E tests cover a comprehensive set of end-to-end flows with different interaction patterns, persisted state, and feature combinations. These scenarios live mostly inside `apps/web/tests/*.e2e.ts` and share the scaffold.

 
### Subagent Conversations

 
 - Validate persistence and UI rendering of subagents, including interrupt scenarios and conversation history forks.
 - Tests exercise sidebar display, queueing, and activity flows ensuring subagent state integrates correctly.
 
 
### Tool Rounds

 The tool round scenarios verify the host to browser bridge of tool calls and responses:

 
 - **Code Mode:** Tests the complete `run_code` flow, validating bash output rendering and appropriate error handling for file access issues.
 - **Cordis Tools:** Cover interactions with dynamic plugin loading and tool calls such as `cordis_inspect_self`, `cordis_define`, and `cordis_run`, exercising user approval flows and persistence of tool results.
 - **Web Search:** Validates web search tool rounds, including user queries and result presentations.
 
 
### Live Interactions and Steering

 
 - **Steering:** Tests mid-turn user interjection or steering handling by the agent loop. These ensure interjections produce logged and rendered durable changes that appear immediately in the UI.
 - **Retries:** Covers retry policies, transient LLM errors, and error exhaustion cases with corresponding UI states.

## Web Snapshot CI Gate and Quality Infrastructure

 Browser E2E tests are integrated into GitHub Actions, primarily on a Node 24 Linux runner to ensure consistent environment and Chromium availability [tsconfig.host.json1-10](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/tsconfig.host.json#L1-L10)

 
 - **Replay Consumption Checks:** The scaffold calls `ReplayHandle.assertConsumed()` on teardown to ensure each recorded LLM interaction was fully consumed during test playback. This avoids silent fixture underrun bugs that cause stale results or missed flows.
 - **Failure Surface:** Any unexpected page errors or client-side connection loss warnings cause test failure, validating the reconnection and gap repair machinery is not hiding broken API bridges.
 - **Stable Fixture Philosophy:** Record once with keys, then replay keyless forever in CI for maximum determinism. Refresh goldens when interfaces evolve.
 
 The snapshot gate ensures no regressions in browser UI accessibility and user flows slip through undetected.

 
---

 Overall, the browser E2E testing layer acts as the highest-fidelity smoke test for dsh, shader-tight tying UI presentation to real host logic across a full network and persistence stack with deterministic replay and robust accessibility snapshots.
