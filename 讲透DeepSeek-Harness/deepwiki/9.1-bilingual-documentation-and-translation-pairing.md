  DeepSeek Harness (dsh) implements a rigorous bilingual documentation methodology where English and Simplified Chinese documents maintain equal authority and are mechanically enforced for consistency through a specialized sidecar system and a dedicated gate [docs/i18n/README.md9-38](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/README.md?plain=1#L9-L38) This page details the sidecar `.i18n.yaml` pairing system, the `verify-translation-pairing` gate, the custom Git merge driver, translation style rules, and the `dsh-translate-docs` agent skill.

## The Sidecar System & Pairing Contract

 Each bilingual documentation unit is a triplet of sibling files located in the same directory — the English source Markdown (`foo.md`), the Simplified Chinese counterpart (`foo.zh.md`), and a consistency record sidecar (`foo.i18n.yaml`) [docs/i18n/README.md10-18](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/README.md?plain=1#L10-L18)

 
### Consistency Record (.i18n.yaml)

 
 - The `.i18n.yaml` stores the Git blob hashes for the English and Chinese Markdown files as last confirmed consistent snapshots:

 - Blob hashes, computed via `git hash-object` on file content, enable verification of consistency even for uncommitted changes, allowing patch-based minimal updates rather than full re-translation [docs/i18n/README.md11-18](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/README.md?plain=1#L11-L18)
 - These blob hash records are stored in the Git object database and pinned under the `refs/dsh/translation-pairing/snapshots/` namespace for immutability and historic recovery [scripts/translation-pairing.ts70](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/scripts/translation-pairing.ts#L70-L70)
 
 
### Language Switcher Lines

 A strict interlinking pattern maintains navigation and pairing clarity:

 
| Language | Switcher line syntax |
|---|---|
| Chinese | `English |
| English | `English |

 This ensures bidirectional, unambiguous language navigation while respecting generated vs authored sources.

 
### Structural Mirroring Rules

 To prove consistent content structure between language pairs, the following must match byte-for-byte or by counted segments:

 
 - Markdown heading depths and order
 - List types, order starts, and item counts
 - Table row and column counts
 - Code fences: exact info string and code body (including comments) must be byte-identical [docs/i18n/README.md22](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/README.md?plain=1#L22-L22)
 - Semantic relative document links must use matching locale paths (`.md` vs `.zh.md`), preserving query and fragment suffixes [docs/i18n/README.md22](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/README.md?plain=1#L22-L22)
 
 This structural parity supports downstream tooling that treats Chinese fences as derivatives of their English siblings for code coverage and build correctness.

## Quality Gates & Verification

 
### The `verify-translation-pairing` Gate

 Integrated into the `doc-sync` aggregate and CI, this verification gate automates enforcement of the pairing contract [docs/i18n/README.md26-38](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/README.md?plain=1#L26-L38) [scripts/verify-translation-pairing.ts](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/scripts/verify-translation-pairing.ts)

 Key validations performed:

 
 - **Completeness Check**: Confirms for every in-scope document triplet that English Markdown, Chinese Markdown, and `.i18n.yaml` files exist.
 - **Blob Hash Identity**: Computes git blob hashes of current `.md` contents and matches them against the recorded hashes in `.i18n.yaml`. A mismatch flags out-of-sync pairs.
 - **Structural Signature Validation**: Confirms the exact match of heading sequences, list lengths, table structures, code fences, and semantic link targets. This guards against unaligned content structures even with similar wording.
 - **Exclusion Handling**: Files or directories listed as excluded (e.g., frozen archival notes, non-paired docs) in the manifest (`scripts/translation-pairing.manifest.json`) are skipped [scripts/translation-pairing.manifest.json2-12](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/scripts/translation-pairing.manifest.json#L2-L12)
 - **Language Switcher Enforcement**: Ensures language switcher lines exist in authored files and conform exactly per side.
 
 The gate supports scoped invocation by file or corpus-wide checks and produces actionable diff outputs to aid translators.

## Custom Git Merge Driver for `.i18n.yaml`

 Concurrent editing of `.i18n.yaml` files is handled by a bespoke Git merge driver named `dsh-translation-pairing` [docs/i18n/README.md20](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/README.md?plain=1#L20-L20)

 
### Behavior

 
 - Triggered on merge conflicts in `.i18n.yaml`.
 - Attempts to verify whether the respective English and Chinese `.md` files merged cleanly and retain a valid structural signature.
 - If validated, it automatically composes a merged `.i18n.yaml` with updated blob hashes matching the merged `.md` files.
 - If structural or hash verification fails, the conflict remains for manual resolution.

## Translation Rules & Style Guide

 
### Terminology Source (`terminology.md`)

 The repository maintains a canonical terminology mapping to ensure consistent bilingual translation of technical terms with three main categories:

 
 - **Abbreviations**: Kept in English, e.g., ACP, LLM [docs/i18n/terminology.md11-30](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/terminology.md?plain=1#L11-L30)
 - **English-only terms**: E.g., `agent`, `Cordis`, `Typert` remain untranslated even in Chinese [docs/i18n/terminology.md31-74](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/terminology.md?plain=1#L31-L74)
 - **Bilingual terms**: Terms with standard Chinese translations, e.g., adapter (适配器), capability (能力) [docs/i18n/terminology.md75-161](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/terminology.md?plain=1#L75-L161)
 
 Adherence to this table avoids terminology drift and enforces first-occurrence annotations and style consistency.

 
### Prose & Structural Requirements

 
 - Code fences (````` blocks) must be byte-identical across language pairs, including comments and info strings.
 - Sentence structures and paragraph boundaries may be re-grouped for natural translation but must not cross independent structural units (headings, list items, etc.).
 - Markdown links must preserve semantics exactly; internal links must point to the counterpart language path.
 - Language switchers are strictly required and must have the exact prescribed format.
 
 The detailed guide is documented in [translation-rules.md](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/translation-rules.md?plain=1) and style samples in [style-samples.md](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/style-samples.md?plain=1)

## The `dsh-translate-docs` Agent Skill

 Routine updates to bilingual pairs follow a lean workflow integrating the sidecar system and gate verification [docs/i18n/README.md60](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/README.md?plain=1#L60-L60) but for complex or full rewrites, the extended skill `dsh-translate-docs` exists [.agents/skills/dsh-translate-docs/SKILL.md](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/.agents/skills/dsh-translate-docs/SKILL.md?plain=1)

 
### Purpose & Invocation

 
 - This skill is user-invocable only and not automatically selected by normal translation needs.
 - Coordinates elaborate workflows including generation of minimal "translation briefs", delegation to translation subagents, and scoped verification.
 - Ensures translation updates minimize changes to non-edited parts, preserving reviewer-approved phrasing and style [docs/i18n/README.md30-34](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/i18n/README.md?plain=1#L30-L34)
 
 
### Workflow Overview

 
 - **Briefing Generation**: Run `pnpm run gen-translation-brief <pair>` to produce a granular diff summary of changes between the last confirmed state and current edits.
 - **Automatic Patch Application**: If all changes are inside code fences shared identically between languages, `--apply` splices these without invoking subagents.
 - **Delegated Translation**: For prose changes, a subagent receives the briefing to fully translate minimal segments without rereading the entire corpus.
 - **Verification & Re-recording**: After translation, run `pnpm run verify-translation-pairing --write <pair>` to update the `.i18n.yaml` with new blob hashes and verify pairing integrity.
 
 
### Prompt Engineering & Translation Pipeline

 The system provides LLM prompt templates with injected terminology and human-calibrated rules, orchestrated by `scripts/translation-prompt.ts`, to ensure translation fidelity and style consistency [scripts/snapshots/translation-prompt-v4/request-response.expected.json](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/scripts/snapshots/translation-prompt-v4/request-response.expected.json)

## Summary of Key Commands

 
| Command | Purpose |
|---|---|
| pnpm run verify-translation-pairing --list | List sync status of all pairs |
| pnpm run verify-translation-pairing --write <file> | Record current hashes, confirm sync |

| pnpm run gen-translation-brief --apply <file> | Apply fence-only diffs automatically |
