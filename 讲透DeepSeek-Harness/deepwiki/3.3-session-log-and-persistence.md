  The session system provides an event-sourced, append-only log that serves as the single source of truth for all agent interactions. Instead of storing mutable state, the system records discrete `SessionEvent` objects, from which the model-visible message history (the "Surface") and other projections are derived.

 
## Session Event Log

 A `Session` is a class that manages a sequence of immutable events [packages/core/session/src/index.ts149-152](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/index.ts#L149-L152) Each event in the log is a `SessionEvent`, which wraps a type-specific payload in a standard envelope containing a monotonic sequence number (`seq`) and a Unix epoch timestamp (`time`) [packages/core/session/src/types.ts58-79](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/types.ts#L58-L79)

 
### Event Envelope Structure

 The envelope is a discriminated union over the `type` field, allowing the TypeScript compiler to narrow the `data` payload [packages/core/session/src/types.ts58-79](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/types.ts#L58-L79)

 
| Field | Type | Description |
|---|---|---|
| type | SessionEventType | The unique key for the event type (e.g., user/message, turn/start). |
| seq | number | Monotonic sequence number within the session. |
| time | number | Unix epoch milliseconds. |
| data | SessionEventMap[K] | The actual payload for this event type. |
| sourceEventSeqs | number[]? | Seq numbers of earlier events that this event cites as sources. Only on SurfaceEventType. |
| surfaceOp | SurfaceOp? | Metadata for events that appear on the LLM-visible surface (append or replace). |

## Surface Projection & `deriveMessages()`

 The **Surface** is an ordered projection of events that produce LLM messages (currently `user/message`, `assistant/message`, and `tool/result`) [packages/core/session/src/surface.ts15-19](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/surface.ts#L15-L19) While the log is strictly append-only, the Surface supports **positional replacements** to allow for history compaction and refinement [packages/core/session/src/surface.ts58-68](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/surface.ts#L58-L68)

 
### `deriveMessages()`

 This function iterates over the `nodes` (sequence numbers) currently in the Surface and converts each corresponding event into a `Message` object for the LLM [packages/core/session/src/index.ts221-235](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/index.ts#L221-L235)

 
 - **Injected Context:** `user/message` events from plugins are projected as standard user roles, preserving the exact identified content [packages/core/session/src/surface.ts96-98](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/surface.ts#L96-L98)
 - **Assistant Chunks:** Individual `assistant/chunk` events are ignored by the surface; only the final `assistant/message` is projected to avoid partial turns in the provider transcript [packages/core/session/src/surface.ts99-105](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/surface.ts#L99-L105)
 - **Compaction & Replacement:** When a `SurfaceOp` of type `replace` is encountered, the `SurfaceManager` removes the shadowed range from the active nodes list and inserts the new event seq [packages/core/session/src/surface.ts117-126](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/surface.ts#L117-L126) This is used for tool result updates or history rewriting.

## Session Forking & Lineage

 The `SessionStore` (accessible via `ctx.sessions`) manages the lifecycle of sessions, including creating new ones and forking existing ones [packages/core/session/src/index.ts39-54](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/index.ts#L39-L54)

 
### Forking Mechanics

 `ctx.sessions.fork(source, boundary?)` creates a new session that inherits a prefix of events from a parent session [packages/core/session/README.md52-54](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/README.md?plain=1#L52-L54)

 
 - **Boundary:** An inclusive sequence number defining where the parent's history ends for the child.
 - **Lineage Metadata:** The new session's `SessionHeader` records the `parentSession` ID and `seedLength` [packages/core/session/src/types.ts74-80](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/types.ts#L74-L80)
 - **Safety:** Forking requires the boundary to end outside an open turn to ensure the child starts in a clean state [packages/core/session/README.md52-54](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/README.md?plain=1#L52-L54)

## Persistence Architecture

 Persistence is implemented as a plugin concern. Plugins subscribe to `session/event` to receive live updates and `session/flush` to ensure durability checkpoints [packages/core/session/src/index.ts42-86](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/session/src/index.ts#L42-L86) The `PersistenceCoordinator` provides shared buffering and crash-repair orchestration for backends [packages/session/session-persistence/src/coordinator.ts1-6](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/session/session-persistence/src/coordinator.ts#L1-L6)
