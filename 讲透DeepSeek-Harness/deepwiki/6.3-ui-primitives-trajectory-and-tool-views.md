These components bridge raw session events and execution logs into a structured, interactive debugging surface.

 
## 1. UI Primitives

 The `ui-primitives` package provides presentational React atoms that are independent of the Cordis framework, styled only through `--dsw-*` CSS tokens. These components handle complex rendering tasks such as ANSI-to-HTML conversion, LaTeX typesetting, and incremental Markdown parsing. They provide the atomic building blocks for agent output rendering and UI controls used throughout the web client [packages/client/ui-primitives/README.md1-75](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-primitives/README.md?plain=1#L1-L75)

 
### 1.1 TerminalBlock & ANSI Rendering

 `TerminalBlock` renders shell command outputs as a terminal-like surface with accurate ANSI escape sequence parsing and line-wise cursor management [packages/client/ui-primitives/README.md19-21](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-primitives/README.md?plain=1#L19-L21)

 Key implementation details:

 
 - **ANSI Parsing:** Uses the `anser` library to parse ANSI escape codes into a React span tree with inline styles [packages/client/ui-primitives/src/ansi.ts](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-primitives/src/ansi.ts)
 - **Cursor Management:** Implements a per-line column buffer to correctly process carriage returns (`\r`) and backspace sequences, ensuring proper overwrite behavior typical in terminal outputs.
 - **Run State Indicator:** Renders a single `StateDot` on the first line indicating the run state: running (animated), error (red), success (green).
 - **Height Capping and Expand Control:** Long outputs are truncated with a "head + tail" slice controlled by a collapsible UI to avoid excessively tall cards.
 - **No Soft Wrapping:** Uses `white-space: pre` and horizontal scrolling to preserve column alignment in outputs like tables or progress bars.
 
 This design enables faithful rendering of shell and tool outputs inline within chat rows and detailed panels, maintaining column alignment and color fidelity [packages/client/ui-primitives/README.md18-24](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-primitives/README.md?plain=1#L18-L24) [.agents/notes/implemented/feature/2026-07-28-web-terminal-card.md1-60](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/.agents/notes/implemented/feature/2026-07-28-web-terminal-card.md?plain=1#L1-L60)

 
### 1.2 MarkdownText & Incremental Rendering

 `MarkdownText` is the primary renderer for assistant output supporting GitHub-Flavored Markdown (GFM) plus TeX math rendered via KaTeX. It includes advanced support for streaming incremental rendering [packages/client/ui-primitives/README.md15-18](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-primitives/README.md?plain=1#L15-L18)

 
 - **Incremental Parser:** During streaming, it freezes all but the last two code blocks as stable React elements, re-parsing only the tail source on each chunk. This minimizes parsing overhead and updates only incremental changes.
 - **Fence Highlighting:** Supports incremental syntax highlighting via Shiki grammar state snapshots, enabling smooth streaming highlighting of code blocks.
 - **Safe Rendering:** Sanitizes links and image URLs, denies raw HTML, and transforms recognized file mention tokens into interactive buttons.
 - **Localization:** All user-facing labels are supplied through typed label props, since the atoms do not read global locale state.

## 2. Trajectory Inspection Ledger

 The trajectory inspection system provides a detailed turn-aware ledger visualizing the session's conversation and agent reasoning events, including tool invocations, assistant messages, and system prompts.

 
### 2.1 Trajectory Data Flow & Layout

 Trajectory data feeds off session snapshots representing event nodes, requests, partial/in-flight calls, and running calls. These raw events are folded into a structured layout of turns, groups (message or steps), and cells representing individual content blocks.

 
 - Input: `TrajectoryLayoutInput` aggregates the raw event nodes and associated metadata [packages/client/ui-trajectory/src/client/layout.ts39-45](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-trajectory/src/client/layout.ts#L39-L45)
 - The core layout function `deriveTrajectoryLayout` converts these into an ordered array of `TrajectoryTurnModel`, each with multiple `TrajectoryGroupModel` containing `TrajectoryCellProps` [packages/client/ui-trajectory/src/client/layout.ts148-152](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-trajectory/src/client/layout.ts#L148-L152)
 - The layout logic merges assistant messages by turn and step, attaches usage data, patterns for compacted turns, and aligns timing information for visual clueing.

### 2.2 TrajectoryTable Component

 `TrajectoryTable` is the main event ledger component rendering the entire session trajectory with high-performance virtualization and detailed row inspection [packages/client/ui-trajectory/src/client/TrajectoryTable.tsx1-250](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-trajectory/src/client/TrajectoryTable.tsx#L1-L250)

 
 - **Virtualization:** Uses `@tanstack/react-virtual` to efficiently manage large event logs. Virtualization kicks in for row counts over 100, with overscan row buffering to ensure smooth scroll [TrajectoryTable.tsx38-41](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/TrajectoryTable.tsx#L38-L41)
 - **Event Kinds:** Rows represent various event kinds: `system`, `user`, `context`, `message` (assistant), `tool`, `subtool`, and `compacted` for folded groups [TrajectoryTable.tsx42-50](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/TrajectoryTable.tsx#L42-L50)
 - **Icons and Labels:** Each kind has a corresponding icon and localization label mapping, allowing clear visual distinction between event types.
 - **Local Record Inspector:** Users can select rows to open a detailed inspector panel showing raw JSON, diffs, options, usage, and timing for the event. This leverages contextual tabs and resizing controls within the table pane.
 - **Pagination/History Loading:** Supports loading older session events on demand with a visual load spinner and history load trigger row at the top [TrajectoryTable.tsx25-35](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/TrajectoryTable.tsx#L25-L35)
 - **Row Grouping:** Rows for turn groups and compactions are grouped with their own toggle states for collapse/expand functionality.
 
 
### 2.3 TrajectoryTimeline Overview

 The `TrajectoryTimeline` component complements the table by providing a visual timeline overview of token usage and timing distributions over the entire session [packages/client/ui-trajectory/src/client/TrajectoryView.tsx10-25](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-trajectory/src/client/TrajectoryView.tsx#L10-L25)

 
 - Allows range selection to filter the visible rows in `TrajectoryTable` based on time intervals or turns.
 - Shows color-coded bars representing resource usage categories (input, output, reasoning tokens) to help understand where the conversation concentrated its budget.

## 3. Tool View Rendering via ui-tool

 The `ui-tool` plugin package manages rendering of tool call and result views in the UI, bridging the host-executed tool data to visual output components in the browser client.

 
### 3.1 Tool-Call Rendering & Logic

 
 - Tool execution results arrive with explicit rendering intents (`callView`, `resultView`), e.g. terminal, diff, search, or web snippet cards.
 - The client uses `ui-tool`'s `toolCallModel` abstractions to interpret these views and derive props for the appropriate presentational components [packages/client/ui-tool/src/client/tool/models/terminal-card-model.ts1-20](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-tool/src/client/tool/models/terminal-card-model.ts#L1-L20)
 - The terminal tool output is rendered via the `TerminalBlock` component from `ui-primitives`, with working directory (cwd) labels computed relative to the user’s session workspace.
 - For other tools, `ui-tool` chooses specialized blocks like `DiffBlock` for diffs, `SearchBlock` for search results, and `WebBlock` for web retrieval, applying consistent overflow handling, copy controls, and ANSI parsing where needed.
 
 
### 3.2 Specific Tool View Highlights

 
| Tool Type | Rendered By | Details & Capabilities |
|---|---|---|
| Terminal | TerminalBlock | Precise ANSI support, cwd labeling, exit status indicators, folding |
| Diff | DiffBlock | Inline diff with multi-hunk support, syntax highlighting |
| Search | SearchBlock | Handles grep-style matches and glob-style path results, truncation |
| Web Search | WebBlock | Shows snippet, date, source link with safe sandboxed anchors |
| Ask Question | AskQuestionCard | Interactive multi-select UI for user input to agent questions |

# Summary

 The combination of `ui-primitives`, `ui-trajectory`, and `ui-tool` packages delivers a robust, extensible frontend UI layer for the DeepSeek Harness.

 
 - `ui-primitives` provides foundational UI atoms including terminal rendering and markdown.
 - `ui-trajectory` offers an interactive, turn-aware session event ledger with rich inspection tooling.
 - `ui-tool` renders complex tool invocations and results with appropriate UI cards.
 
 This architecture cleanly separates concerns: raw session events fold into a trajectory model, which feeds performant visual components that integrate atomic renderers. The design supports streaming, localization, and extensible tooling output, enabling efficient, deep agent debugging and user interaction.
