  The Shell, Subprocess, and Terminal subsystems provide the harness with the capability to execute arbitrary code, manage process lifecycles, and maintain interactive sessions. This infrastructure is built on the **Capability Seam** pattern, allowing the agent to interact with either a local host or a remote sandboxed environment (like E2B) through a unified interface.

 
## Overview of the Subprocess Seam

 The `SubprocessRuntime` serves as the abstract base for all execution backends. It defines how the system resolves executables, spawns one-shot processes, and allocates persistent PTY (Pseudo-Terminal) handles.

 
### Key Data Structures

 
| Entity | Description |
|---|---|
| SubprocessSpawnSpec | Defines command arguments, working directory, environment variables, and stdio dispositions (pipe, inherit, or collect). packages/subprocess/subprocess/src/types.ts130-155 |
| SubprocessHandle | A handle to a running process, providing access to stdin (Writable), stdout/stderr (Readable), and a done promise. packages/subprocess/subprocess/src/types.ts182-205 |
| SubprocessOutcome | The final result of a process, containing the exitCode or the terminating signal. packages/subprocess/subprocess/src/types.ts210-215 |

## Local Subprocess Spawning

 The `LocalSubprocessRuntime` implements execution on the host machine. It manages detached process trees and ensures that child processes do not outlive the harness.

 
### Process Tree Management

 On Linux/macOS, the runtime uses POSIX process groups. On Windows, it utilizes `taskkill /T` (implemented via `taskkillProcessTree`) to ensure entire trees are reaped. [packages/subprocess/subprocess-local/src/spawn.ts2-8](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subprocess/subprocess-local/src/spawn.ts#L2-L8) [packages/subprocess/subprocess-local/src/spawn.ts53-54](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subprocess/subprocess-local/src/spawn.ts#L53-L54)

 
### Output Collection & Spilling

 To prevent memory exhaustion while allowing agents to read large logs, the `OutputCollector` implements a "tail-keep" strategy:

 
 - **In-Memory Tail**: A bounded buffer (e.g., 64KB) keeps the most recent output. [packages/subprocess/subprocess-local/src/spawn.ts115-116](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subprocess/subprocess-local/src/spawn.ts#L115-L116)
 - **Spill to Disk**: If a spill cap is provided, the full stream is written to a temporary file (created via `openSync` with `wx` flags for security) once the in-memory cap is exceeded. [packages/subprocess/subprocess-local/src/spawn.ts156-173](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subprocess/subprocess-local/src/spawn.ts#L156-L173)
 - **Truncation**: If the spill cap is also exceeded, the head of the stream is discarded, but the in-memory tail remains preserved by trimming the `chunks` array. [packages/subprocess/subprocess-local/src/spawn.ts137-152](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subprocess/subprocess-local/src/spawn.ts#L137-L152)
 
 
### Synchronous Host-Exit Cleanup

 A critical feature of the local runtime is the `terminateForHostExit` method. The `LocalSubprocessRuntime` attaches a listener to the Node.js `exit` event to force-kill all managed process trees synchronously. This listener is placed before other listeners to ensure cleanup happens even if the process is shutting down. [packages/subprocess/subprocess-local/src/index.ts62-77](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subprocess/subprocess-local/src/index.ts#L62-L77) [packages/subprocess/subprocess-local/tests/local.spec.ts32-47](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subprocess/subprocess-local/tests/local.spec.ts#L32-L47)

## Persistent PTY Sessions

 While one-shot `bash` calls are stateless, the `TerminalSessionService` (`ctx.terminals`) allows for interactive, stateful terminal sessions. This enables workflows like REPL exploration or multi-step debugging where environment variables and `cwd` must persist. [.agents/notes/implemented/feature/2026-07-16-persistent-pty-sessions.md9-15](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/.agents/notes/implemented/feature/2026-07-16-persistent-pty-sessions.md?plain=1#L9-L15)

 
### Implementation Details

 
 - **Ownership**: Every PTY session is owned by a specific `Agent`. The `TerminalSessionService` mints an opaque `TerminalSessionId` and rejects `list`/`read`/`signal`/`kill` calls from other owners. [.agents/notes/implemented/feature/2026-07-16-persistent-pty-sessions.md33-35](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/.agents/notes/implemented/feature/2026-07-16-persistent-pty-sessions.md?plain=1#L33-L35)
 - **Readiness Detection**: The `dsh-terminal-bash` backend uses OSC (Operating System Command) markers and shell prompt heuristics. It only declares prompt readiness if the trailing output matches the controlled `PS1` exactly. [.agents/notes/implemented/feature/2026-07-16-persistent-pty-sessions.zh.md75-76](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/.agents/notes/implemented/feature/2026-07-16-persistent-pty-sessions.zh.md?plain=1#L75-L76)
 - **Linux Syscall Inspection**: The `linuxProcessGroupHasLiveMembers` function inspects `/proc/<pid>/stat` and `/proc/<pid>/task/<tid>/syscall`. Tier 1 detection returns a positive result only if a thread is waiting on `stdin` (e.g., `read(0)` or `poll` with fd 0). [.agents/notes/implemented/feature/2026-07-16-persistent-pty-sessions.zh.md77-78](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/.agents/notes/implemented/feature/2026-07-16-persistent-pty-sessions.zh.md?plain=1#L77-L78) [packages/subprocess/subprocess-local/src/process-inspector.ts4-7](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subprocess/subprocess-local/src/process-inspector.ts#L4-L7)

## E2B Cloud Sandbox Backend

 The E2B backend (`subprocess-e2b`) projects remote cloud execution onto the local subprocess seam.

 
### Remote Environment Bootstrapping

 Because E2B execution happens in a fresh VM, the harness must bootstrap the environment:

 
 - **Environment Sync**: Local environment variables are scrubbed of secrets via `scrubbedParentEnv` and then serialized using `serializeRemoteEnvironment` to be sent to the sandbox. [packages/e2b/subprocess-e2b/src/process.ts113-115](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/e2b/subprocess-e2b/src/process.ts#L113-L115) [packages/e2b/subprocess-e2b/src/environment.ts1-10](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/e2b/subprocess-e2b/src/environment.ts#L1-L10)
 - **Wrapper Scripts**: Commands are wrapped in a bash bootstrap that handles PGID acquisition via `ps -o pgid=` and exit status reporting via remote files. [packages/e2b/subprocess-e2b/src/process.ts101-120](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/e2b/subprocess-e2b/src/process.ts#L101-L120)
 
 
### Output Encoding

 To handle binary data and large streams reliably over the E2B SDK, the backend uses a `PassThrough` stream and a base64 encoder (`OUTPUT_ENCODER_SOURCE`) running inside the sandbox to pipe stdout/stderr back to the host. [packages/e2b/subprocess-e2b/src/process.ts26-38](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/e2b/subprocess-e2b/src/process.ts#L26-L38) [packages/e2b/subprocess-e2b/src/process.ts94-100](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/e2b/subprocess-e2b/src/process.ts#L94-L100)

 
### Remote PTY Management

 The `spawnE2BTerminal` function allocates a PTY in the E2B sandbox. It manages session cleanup by removing remote temporary files and directories when the terminal is closed. [packages/e2b/subprocess-e2b/src/terminal.ts16-30](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/e2b/subprocess-e2b/src/terminal.ts#L16-L30) [packages/e2b/subprocess-e2b/src/terminal.ts180-195](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/e2b/subprocess-e2b/src/terminal.ts#L180-L195)

 
### Cleanup & Rollback

 If an E2B process spawn is cancelled before it finishes initializing, the `rollbackUnpublishedTerminal` function ensures that the remote process and its associated session are killed via `handle.kill()` to avoid leaking resources in the cloud sandbox. [packages/e2b/subprocess-e2b/src/terminal.ts198-215](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/e2b/subprocess-e2b/src/terminal.ts#L198-L215)
