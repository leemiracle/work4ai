  The DeepSeek Harness (dsh) integrates external tools and agent behaviors through three primary mechanisms: the **Model Context Protocol (MCP)** for bridging third-party tool servers, a **Hook Protocol** for intercepting agent actions (compatible with Codex and Claude Code), and a **Skill System** for loading durable instruction sets into the agent's context.

 
---

 
## 1. MCP Client Bridge

 The `mcp-client` plugin connects dsh to external MCP servers, projecting remote tools into the local `ctx.tools` registry. Each plugin instance manages one connection to a specific MCP server [packages/mcp/mcp-client/src/index.ts1-14](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/mcp/mcp-client/src/index.ts#L1-L14)

 
### 1.1 Implementation & Tool Namespacing

 To prevent collisions between multiple MCP servers or native tools, remote tools are registered under a server-qualified namespace following the pattern:

 
```
mcp__<serverName>__<rawName>
```

 The `publicToolName` function performs this normalization. It ensures that registered tool names conform to the DeepSeek function-name rules (ASCII alphanumeric, underscore, hyphen, maximum 64 characters). If normalization results in a changed or overly long name, a 12-hex-digit SHA-256 hash derived from `(serverName, rawName)` is appended after truncation to guarantee unique and deterministic tool names [packages/mcp/mcp-client/src/tools.ts98-117](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/mcp/mcp-client/src/tools.ts#L98-L117)

 This ensures stable naming across harness restarts and multiple MCP server connections.

 
### 1.2 Connection Lifecycle

 The client supports two transports for connecting to MCP servers:

 
 - **stdio**: Spawns a child process running the server executable, communicating over standard input/output pipes.
 - **streamable-http**: Uses Server-Sent Events (SSE) over HTTP to communicate with a remote MCP server endpoint.
 
 A reconnect policy with exponential backoff is implemented, configurable via plugin options; it retries failed connections with delays doubling up to a max interval [packages/mcp/mcp-client/src/index.ts49-105](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/mcp/mcp-client/src/index.ts#L49-L105)

 On startup, the client connects to the MCP server, performs initial tool discovery using `tools/list`, and registers those tools on `ctx.tools` under their namespaced public names. The client keeps synchronized with the server's toolset, updating registrations on tool list changes.

## 2. Hook Protocol

 The Hook Protocol enables interception of agent lifecycle events and tool execution via external commands. It is implemented as a core protocol library (`dsh-hook-protocol`) and dialect bridges for specific hook formats: `hooks-codex` and `hooks-claude-code`.

 
### 2.1 Dialect Bridges: Codex (`hooks-codex`)

 The `hooks-codex` package imports a Codex-compatible `hooks.json` and executes command hooks at five primary interception points:

 
| Event | Harness Extension Point | Description |
|---|---|---|
| SessionStart | Detached event during session initialization | Add context when a new session starts |
| UserPromptSubmit | agent/pre-step waterfall | Run before processing a user prompt |
| PreToolUse | tools/pre-execute waterfall | Run before a tool is executed |
| PostToolUse | tools/post-execute waterfall | Run after a tool completes, can block or add context |
| Stop | agent/turn-stopping listener | Intercept turn completion, can force continuation |

 Hooks execute as synchronous commands via `dsh-shell` (bash executor). They send inputs as snake_case JSON payloads without trailing newlines. Their exit codes determine their effect:

 
 - Exit code **2**: Block the action (deny)
 - Other exit codes (or failures): Logged but non-blocking
 - Standard output may add context to the agent's next prompt
 
 Hooks run serially in configuration order, and their outcomes fold into a `MergedHookOutcome` using an order-independent precedence: deny > ask > allow [packages/hooks/hooks-codex/src/index.ts113-160](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/hooks/hooks-codex/src/index.ts#L113-L160) complemented by shared hook protocol utilities [packages/hooks/hook-protocol/README.md5-78](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/hooks/hook-protocol/README.md?plain=1#L5-L78)

 
### 2.2 Hook Outcome and Agent Control

 When a hook blocks an action (e.g., `PreToolUse` denies tool execution), the tool is not run and an error message is surfaced to the user.

 Hooks can also add "additional context" text seen by the model in future requests.

## 3. Skill System

 Skills are durable, reusable instruction sets authored as Markdown documents that guide agent behavior in specific domains or workflows. The skill system comprises:

 
 - A **Skill Registry** service managing skill catalogs and lookups
 - Providers such as **SkillFileSystem** that contribute skills from files or other sources
 - The **tool-skill** plugin, which exposes a `skill` tool to fetch skill content and publishes a model-facing skill catalog to each session
 
 
### 3.1 Skill Registry

 The core skill package (`@deepseek-ai/dsh-skill`) manages skill metadata merging from multiple providers. Skills have the following metadata:

 
 - `name`: kebab-case validated skill identifier
 - `description`: short human-readable text
 - `invocation`: flags whether a skill is user-invocable and/or model-invocable
 - `provider`: string identifying the provider that owns the skill
 - `content`: the instruction Markdown body loaded on demand
 - `resourceBase`: optional base path or URL for resolving relative resources within the skill
 
 Full skill definitions are requested with references to the appropriate provider and contextual options, such as `cwd` and abort signals for lookup [packages/skill/skill/src/index.ts1-93](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/skill/skill/src/index.ts#L1-L93)

 
### 3.2 Skill Catalog and the `tool-skill` Plugin

 The `tool-skill` plugin maintains a durable catalog of available model-invocable skills emitted as session `user/message` events with a special `skill-catalog` source. The catalog lists skill names and short descriptions for the model's awareness.

 It hooks into the `agent/pre-step` event waterfall to ensure the catalog is up to date, re-publishing only when skills change. The catalog includes a `<system-reminder>` block wrapping the available skill list, injected into the agent's context [packages/skill/tool-skill/src/index.ts77-130](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/skill/tool-skill/src/index.ts#L77-L130)

 The same plugin also registers a `skill` tool that the model may call with the exact skill name to retrieve the full skill markdown content, serving as an on-demand skill loader. It validates skill names and model invocation permissions before resolving the skill from the registry [packages/skill/tool-skill/src/index.ts81-161](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/skill/tool-skill/src/index.ts#L81-L161)

 
### 3.3 User-Explicit Skill Invocation Gesture

 User messages starting with a slash followed by a skill name (e.g., `/edit-code`) are recognized as deterministic invocations of user-invocable skills, inserting their instructions as injected context for the model. This extends the skill system's interactivity beyond automated fetching to explicit user guidance [packages/skill/tool-skill/src/index.ts163-175](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/skill/tool-skill/src/index.ts#L163-L175)

# Summary

 This page detailed the implementations and data flows for:

 
 - The **MCP Client** bridge connecting remote MCP servers to the agent's tool runtime,
 - The **Hook Protocol**, especially the Codex-compatible hook bridge that intercepts and augments agent runs,
 - The **Skill System**, maintaining durable skill catalogs and providing skill loading as a tool and contextual injection.
 
 These mechanisms form critical subsystems in DeepSeek Harness enabling external integration, runtime interception, and extensible instruction management.
