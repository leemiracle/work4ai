  The Agent Client Protocol (ACP) is an automation-focused JSON-RPC protocol used in DeepSeek Harness (DSH) for programmatic communication with agents. It provides a standardized channel for parent agents, external providers, and subagent orchestration via IPC or network-transparent JSON-RPC streams.

 This page covers the detailed inner workings of ACP in DSH, focusing on the turn codec, disposal semantics, the `acp-agent` example, and how ACP enables out-of-process subagent orchestration and integration with external agents.

 
---

 
## Overview of ACP in DeepSeek Harness

 DSH uses ACP as a dedicated automation-only server protocol exposing a pure JSON-RPC 2.0 interface over streams such as `stdio`. The critical design considerations are:

 
 - **Pure transport:** ACP uses newline-delimited JSON-RPC frames strictly on `stdout`/`stdin`. No logging or spurious output contaminates the wire frames. Diagnostics must be sent on `stderr`.
 - **One process per run:** Each ACP child agent runs in a separate process with isolated runtime, session, model configuration, and tools.
 - **Protocol boundary:** ACP defines the serialization and ownership boundary. Parent and child processes exchange only well-defined ACP wire messages, which rigorously encode prompt requests, assistant responses, cancellations, and permission decisions.
 - **Focused message scope:** Only prompt text/images, assistant text/images, cancellation, and atomic permissions appear on the ACP wire. Intermediate messages, tooling calls, and session events remain internal.
 
 ACP facilitates interoperability with external agents speaking the same protocol and provides an isolated delegation backend for subagents.

## Turn Codec & Lifecycle Management

 ACP manages agent "turns" as atomic prompt-response lifecycles coordinated via the JSON-RPC protocol.

 
### Turn Correlation & Control Flow

 
 - The client invokes `session/prompt` on the ACP bridge to ask the agent to perform a reasoning or tool-using turn.
 - The bridge starts and observes the agent's `AgentLoop` to track turn progress and finalization.
 - The client's prompt call resolves only when the agent reaches an idle or terminal state, delivering the final stop reason.
 - Canceling a prompt causes a `session/cancel` notification to the ACP child agent.
 
 
### Internal Data Codec

 The ACP bridge translates between DSH internal session events and ACP content blocks:

 
| DSH Internal Event / Type | ACP Message Type | Details |
|---|---|---|
| Assistant text message chunks | agent_message_chunk (text) | Text blocks streamed in order |
| Assistant image attachments | agent_message_chunk (image) | Base64-encoded verified attachments |
| Stop reasons internal enumeration | ACP StopReason strings | Maps codes for completed, error, etc. |

 This codec ensures all assistant output aligns with the ACP wire format while preserving order and content fidelity.

## Dispose Semantics & Controlled Teardown

 The ACP plugin follows strict disposal protocols to ensure no resource leakage or dangling subprocesses on shutdown or cancellation.

 
### Disposal Sequence

 Upon disposal or connection close, the ACP bridge performs:

 
 - **Cancel active prompts:** Any running agent turns are immediately cancelled to unblock pending prompt requests [packages/acp/acp/tests/dispose.spec.ts16-27](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/acp/acp/tests/dispose.spec.ts#L16-L27)
 - **Drain continuable subagents:** The bridge invokes `drainContinuableDescendants` on the `subagents` service to orderly cancel and await teardown of all continuable (background or delegated) subagents before releasing the parent agent [packages/acp/acp/tests/dispose.spec.ts61-84](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/acp/acp/tests/dispose.spec.ts#L61-L84)
 - **Dispose owned agents:** The bridge disposes its owned agent instances child-first, allowing persistence flushes and consistent session state finalization [packages/acp/acp/tests/dispose.spec.ts139-152](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/acp/acp/tests/dispose.spec.ts#L139-L152)
 - **Handle disposal errors:** Any errors during disposal are aggregated and logged without blocking the full cleanup process.

## Usage of the `subagent-acp` Provider

 The `@deepseek-ai/dsh-subagent-acp` package provides a subagent provider implementing ACP client semantics for isolated, out-of-process child agents.

 
### Key Functionality

 
 - Spawns a fresh process per subagent run, configured with a command, args, and environment [packages/subagent/subagent-acp/src/index.ts26-85](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent-acp/src/index.ts#L26-L85)
 - Drives the child as an ACP client over JSON-RPC stdio with a full `initialize` and `newSession` handshake.
 - Auto-answers permission requests from the child (`allow` or `reject`) without human interaction.
 - Maps ACP stop reasons (`end_turn`, `max_tokens`, `refusal`, `cancelled`, etc.) to shared harness stop reason vocabulary (`completed`, `max-tokens`, `refusal`, `aborted`, `error`) [packages/subagent/subagent-acp/src/run.ts180-188](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent-acp/src/run.ts#L180-L188)
 - Implements strict dispose semantics: closes stdin, waits for EOF grace, escalates termination signals, and collects process outcomes [packages/subagent/subagent-acp/src/run.ts80-140](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent-acp/src/run.ts#L80-L140)

## Testing & Validation with ACP Snapshots and Mock Server

 DSH leverages a comprehensive testing strategy for ACP:

 
 - **Mock ACP Agent Server:** The `mock-acp-server.ts` simulates a minimal ACP agent speaking the protocol over `stdio` programmatically controlled by environment variables for tests. This server supports scripted assistant text, behaviors, permission requests, delays, crashes, and cancellation [packages/subagent/subagent-acp/tests/mock-acp-server.ts1-100](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent-acp/tests/mock-acp-server.ts#L1-L100)
 - **Snapshot Tests:** The `acp.snapshot.ts` suite records model and protocol transcripts for regression testing and deterministic replay using the `llm-replay` plugin. It validates serialization, turn lifecycle, stop reasons, and assistant message delivery [examples/acp-agent/tests/acp.snapshot.ts10-40](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/examples/acp-agent/tests/acp.snapshot.ts#L10-L40)
 - **End-to-End Protocol Sanity:** E2E tests spawn actual `acp-agent` subprocesses, verifying pure JSON-RPC line streams for protocol correctness and checking filesystem side effects like output files [examples/acp-agent/tests/acp.e2e.ts40-125](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/examples/acp-agent/tests/acp.e2e.ts#L40-L125)
 - **Disposal Tests:** Dedicated disposal tests ensure cancellation correctly interrupts running prompts and that subagent drains and session disposals occur in the proper order, even when errors happen [packages/acp/acp/tests/dispose.spec.ts8-140](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/acp/acp/tests/dispose.spec.ts#L8-L140)

# Summary

 The ACP Protocol in DeepSeek Harness cleanly separates process boundaries and streaming communication for agents. The `@deepseek-ai/dsh-acp` package implements the server bridge exposing internal agents over JSON-RPC stdio, with a robust turn lifecycle codec and error handling. The `@deepseek-ai/dsh-subagent-acp` provider drives out-of-process child ACP agents with strict process management and permission auto-answering.

 ACP enables secure and isolated delegation to child agents in separate processes, facilitates integration with external ACP-compatible agents, and supports testability via mock servers and snapshot-driven regression.

 This protocol's purity and strict disposal semantics ensure robust distributed agent orchestration in the DeepSeek Harness platform.
