  Typert is the type-safe Remote Procedure Call (RPC) system in DeepSeek Harness (`dsh`) that bridges the Node.js Host environment and the browser Client runtime. It eliminates manual boilerplate by automatically generating client-side proxy declarations from decorated Host service classes, ensuring compile-time type safety across the network boundary.

 
## Implementation Overview

 Typert operates as a build-time analyzer and a runtime registry. It identifies services intended for remote exposure, extracts their method signatures, and emits platform-independent TypeScript contracts used by the browser to invoke Host-side logic without importing Host implementation code.

 
### The Build Pipeline

 The Typert build pipeline is integrated into the workspace via a generator that coordinates discovery, analysis, and emission. It consists of two primary phases:

 
 - **Analysis**: The analyzer scans source files targeting classes that use the `@Remote` and `@RemoteScope` decorators [packages/api/gateway/tests/gateway.host.spec.ts11-12](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/tests/gateway.host.spec.ts#L11-L12) It constructs a model containing extracted types and `InvocationDescriptor` metadata [packages/api/gateway/src/index.ts18-22](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/src/index.ts#L18-L22)
 - **Emission**: The emitter transforms the analyzed model into generated artifacts, including TypeScript interfaces for the client and runtime reflection descriptors [packages/api/gateway/src/index.ts23-33](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/src/index.ts#L23-L33)

## Key Decorators and Service Registration

 Typert relies on Cordis-integrated decorators to mark services for remote exposure while maintaining strict separation between the Host and Client programs.

 
### `@Remote` and `@RemoteScope`

 
 - **`@Remote`**: Marks a method as remote-accessible [packages/api/gateway/tests/gateway.host.spec.ts59-60](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/tests/gateway.host.spec.ts#L59-L60) It supports both unary (Promise-based) and streaming (AsyncIterable-based) modes [packages/api/gateway/tests/gateway-stream.host.spec.ts73-74](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/tests/gateway-stream.host.spec.ts#L73-L74)
 - **`@RemoteScope(context)`**: Used when the service receiver must be resolved within a specific context scope (e.g., `gatewayFixture`) rather than the global root context [packages/api/gateway/tests/gateway.host.spec.ts70-71](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/tests/gateway.host.spec.ts#L70-L71)

## Invocation Descriptors and Codecs

 Typert generates runtime validation logic using `InvocationDescriptor` objects which contain metadata about the call structure.

 
### Descriptor Composition

 The `InvocationDescriptor` is the "source of truth" for a remote call [packages/api/gateway/tests/gateway.client.spec.ts139-162](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/tests/gateway.client.spec.ts#L139-L162) It contains:

 
 - **Routing**: The `id` (e.g., `@fixture/probe#probe/create`), `service`, and `method` [packages/api/gateway/tests/gateway.client.spec.ts141-144](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/tests/gateway.client.spec.ts#L141-L144)
 - **Parameters**: A list of arguments identifying their source (e.g., `json` or `lookup`) and their wire names [packages/api/gateway/tests/gateway.client.spec.ts147-158](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/tests/gateway.client.spec.ts#L147-L158)
 - **Codecs**: Zod-based schemas for strict validation of inputs and results [packages/api/gateway/tests/gateway.client.spec.ts152-160](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/tests/gateway.client.spec.ts#L152-L160)
 
 
### Lookup Resolution

 When a method defines a parameter as a business object, the client sends a "wire" identifier (e.g., `agentId`). The Host-side `TypertGatewayService` resolves this identifier into a live object before invoking the implementation [packages/api/gateway/tests/gateway.client.spec.ts146-152](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/tests/gateway.client.spec.ts#L146-L152)

## RPC Protocol and Execution

 When a client invokes a method on `ctx.remote`:

 
 - **Client Proxy**: The client runtime uses generated descriptors to validate arguments and identify the endpoint [packages/api/gateway/tests/gateway.client.spec.ts117-132](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/tests/gateway.client.spec.ts#L117-L132)
 - **Transport**: The call is delegated to `ClientConnectionRpc`, which handles the network transport [packages/client/connection/src/client/index.ts105-131](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/connection/src/client/index.ts#L105-L131) Unary calls typically use HTTP, while streams use a WebSocket multiplexer [packages/api/gateway/src/index.ts2-4](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/src/index.ts#L2-L4)
 - **Host Gateway**: `TypertGatewayService` intercepts the request [packages/api/gateway/src/index.ts202-208](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/src/index.ts#L202-L208) resolves `lookup` parameters, and validates the payload [packages/api/gateway/src/index.ts181-184](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/src/index.ts#L181-L184)
 - **Execution**: The gateway invokes the actual method on the registered Cordis service [packages/api/gateway/tests/gateway.host.spec.ts60-68](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/tests/gateway.host.spec.ts#L60-L68)
 - **Cancellation**: Typert supports cooperative cancellation by passing an `AbortSignal` to the business method [packages/api/gateway/tests/gateway.host.spec.ts60-62](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/api/gateway/tests/gateway.host.spec.ts#L60-L62)
