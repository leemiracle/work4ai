  This section provides a comprehensive technical overview of the user settings interface, the agent preset authoring system, and the onboarding flow in DeepSeek Harness (dsh). It covers the architecture and code entities involved in presenting and managing application settings (models, plugins, general preferences), authoring agent presets via the `ui-agent-preset` package, controlling session plan mode, and enabling onboarding UI flows.

 
---

 
## Settings UI & General Chrome

 The settings UI is architected as a modular shell with feature-specific cards and sections. The entry point for general settings UI is the **ui-settings-general** package, which provides the overall modal frame, navigation tabs, and anchors the onboarding and plan mode ledgers.

 
### Settings Shell Architecture

 
 - The **settings shell** occupies the `sidebar.settings` slot and exposes the root ledger that projects: 
 - **`settings.section` ledger**: driving side-nav sections in the settings modal.
 - **`settings.general.item` slot**: for individual general settings rows (toggles, inputs).
 - **`settings.onboarding` ledger**: sequential onboarding UI steps.
 - The shell handles privileged operations such as "Open configuration file", which triggers an RPC call to the Host to open the local `settings.yaml` document if running loopback [packages/client/ui-settings-general/README.md5-14](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-settings-general/README.md?plain=1#L5-L14)
 
 
### Mirror & Scope Pattern for Settings Data

 
 - `SettingsDescribeMirror` subscribes once over the wire to the host's `settings.describe` signal, caching the full configuration schema tree and current values to minimize wire usage.
 - `SettingsScopeController` creates isolated views scoped by namespace for card forms and plugin configuration. It orchestrates serialized writes with revision fencing (`expectedRevision`) to avoid clobbering concurrent host edits.
 - Write conflicts trigger a snapshot re-sync with `recover()` [packages/client/ui-settings/src/client/settings-scope.ts20-158](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-settings/src/client/settings-scope.ts#L20-L158)
 
 
### Locale & Language Preferences

 The locale subsystem uses `LocaleRuntime` to manage UI translations and a preferred language setting:

 
 - On startup, locale is resolved from browser policy (e.g., `navigator.language`) unless overridden by host settings.
 - Translations resolve through a fallback chain: active locale → English fallback → common namespaces.
 - Language changes update the `<html lang>` attribute for assistive tech compliance [packages/client/locale/src/client/index.ts1-164](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/locale/src/client/index.ts#L1-L164)

## Agent Preset Authoring (`ui-agent-preset`)

 Agent presets define the plugin stack, tools, prompts, and capabilities a session uses. The agent's preset is immutable for the lifetime of a session.

 
### Preset Concepts and UI

 
 - Presets are stored as plugin compositions in directories, each with an `agent.cordis.yml` file.
 - The UI exposes a roster of presets (built-in and user-authored) rendered as cards (rows).
 - Users can duplicate built-in presets to create writable copies and can open a preset's directory for manual editing.
 - A specialized "Creator mode" preset supports a complex authoring environment with runtime inspection and plugin experiments.
 - The default preset for new sessions is stored as a setting (`agent-presets.default`) on the host [packages/client/ui-agent-preset/src/client/AgentPresetSection.tsx1-150](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-agent-preset/src/client/AgentPresetSection.tsx#L1-L150) [packages/client/ui-agent-preset/src/client/settings-store.ts1-80](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-agent-preset/src/client/settings-store.ts#L1-L80)
 
 
### Key Code Entities

 
| Feature | Code Entity | Role & Description |
|---|---|---|
| Roster management | AgentPresetSectionController | Manages preset list, loading states, copy/delete dialogs. |
| Validation logic | draftBlocker | Ensures uniqueness, syntax correctness of new preset IDs. |

| UI Components | AgentPresetSection | React surface rendering the full preset management page. |
| Preset seat controls | AgentPresetSeatController | Handles session-global staged preset selection before starting. |

 
### Data Flow Overview

 
 - The browser queries the `agentPresets.list()` remote RPC to obtain the current roster.
 - Copying a preset issues an RPC `agentPresets.duplicate(id, from)` to the host, which clones the preset directory.
 - Setting the default preset writes a `default` key in the `agent-presets` settings namespace.
 - Opening preset folders invokes `agentPresets.openDocument(id)` triggering the Host's native editor launch.

## Onboarding Flow

 The onboarding UI is a sequential step controller implemented via the ledger `settings.onboarding`. Its core behavior:

 
 - Exactly one onboarding step is mounted at a time, in ascending order.
 - Visible steps set the `app-root` HTML `inert` attribute to block main UI interaction.
 - Steps read/write public settings for persistence across sessions, e.g., the welcome notice stores `welcomeNoticeVersion`.
 - This ledger is anchored in the general settings chrome [packages/client/ui-settings-general/README.md5-14](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/client/ui-settings-general/README.md?plain=1#L5-L14)
 
 
### Telemetry Opt-In Design

 
 - Telemetry starts disabled by default due to privacy requirements.
 - The environment variable `DSH_TELEMETRY_MODE` governs outbound telemetry consent (`DISABLED`, `FEEDBACK_ONLY`, `FULL`).
 - The consent is frozen before starting commands to prevent project self-authorization.
 - Telemetry consent is surfaced and controlled in onboarding or general settings (though product UI for this is minimal currently) [.agents/notes/implemented/feature/2026-08-10-telemetry-default-off.md1-31](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/.agents/notes/implemented/feature/2026-08-10-telemetry-default-off.md?plain=1#L1-L31)

## Plan Mode Control

 Plan Mode restricts the agent's use of tools to a planning phase before executing commands.

 
 - The `PlanModeController` injects special instructions into the system prompt when active.
 - It gates tool invocation using session event `plan/mode`.
 - The mode transitions through explicit instructions and is persisted in the session log.
 - It effectively splits agent reasoning into "plan" and "execute" phases [packages/plan/plan-mode/tests/plan-mode.spec.ts10-153](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/plan/plan-mode/tests/plan-mode.spec.ts#L10-L153)

## Summary

 
 - The **Settings UI** offers a modular, extensible shell based on slot and ledger systems with state mirrored from the host.
 - **Agent Preset management** enables users to duplicate, delete, and open presets, backed by host-managed directories and RPC calls.
 - The **Onboarding flow** uses a ledger-driven step system integrated tightly with settings concepts and scoped by namespaces.
 - **Plan Mode control** manages a specialized multi-step agent prompt and tool gating logic for session planning phases.
 
 This carefully architected UI and backend integration system balances host control, client performance, user configurability, and session consistency.
