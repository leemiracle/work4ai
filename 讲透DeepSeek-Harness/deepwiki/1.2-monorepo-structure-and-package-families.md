  The DeepSeek Harness (dsh) codebase is organized as a high-density pnpm monorepo. It utilizes a plugin-based architecture where functionality is decomposed into small, versioned packages that communicate via a service-oriented microkernel [packages/README.md5-9](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/README.md?plain=1#L5-L9) This structure enforces the "capability seam" pattern, ensuring that core logic remains decoupled from specific implementations like local filesystems or cloud sandboxes [packages/README.md67-68](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/README.md?plain=1#L67-L68)

 
## Directory Layout

 The repository is divided into several top-level directories, each serving a distinct role in the development and distribution lifecycle [docs/AGENTS.md9-56](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/AGENTS.md?plain=1#L9-L56)

 
| Directory | Purpose | Implementation Detail |
|---|---|---|
| apps/ | Entry-point applications. | Contains the main web frontend (apps/web) and CLI launcher (apps/cli) pnpm-lock.yaml127-208 |
| packages/ | The primary functional units. | Grouped into families (e.g., core/, llm/). All packages use the @deepseek-ai/dsh- prefix docs/module-graph.md6-9 |
| vendor/ | Local forks of upstream libraries. | Includes a customized version of the Cordis framework and schemastery pnpm-lock.yaml8-9 |
| native/ | Platform-specific binaries. | Contains components like landlock-run for Linux process confinement docs/AGENTS.md50 |
| python/ | Python SDK and runtimes. | Houses the deepseek-harness-sdk and bundled runtime logic docs/AGENTS.md49 |
| scripts/ | Tooling and quality gates. | Contains CI checks, module graph generators, and build automation knip.json26-31 |
| examples/ | Runnable demo configurations. | Runnable cordis.yml leaves that compose packages for specific use cases docs/AGENTS.md51 |

## Package Families

 Packages are organized into "families" located in `packages/<family>/<pkg>`. This grouping provides a logical hierarchy for the hundreds of small plugins in the system [docs/module-graph.md10-181](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/module-graph.md?plain=1#L10-L181)

 
### Core Family (`packages/core/`)

 The "Product API Spine." This family contains the essential services for running an agentic loop.

 
 - **`dsh-agent`**: Defines the `Agent` interface and `ctx.agents` service [docs/module-graph.md31](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/module-graph.md?plain=1#L31-L31)
 - **`dsh-agent-loop`**: The concrete implementation of the ReAct-style execution loop, managing `maxParallelToolCalls` [docs/config-catalog.md84-95](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/config-catalog.md?plain=1#L84-L95)
 - **`dsh-tools`**: The central registry for tool definitions and execution waterfalls [docs/module-graph.md38](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/module-graph.md?plain=1#L38-L38)
 
 
### LLM Family (`packages/llm/`)

 Provides the `LlmRuntime` (`ctx.llm`) service. It abstracts model providers into a unified streaming interface [docs/module-graph.md21-29](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/module-graph.md?plain=1#L21-L29)

 
 - **Adapters**: Concrete implementations like `dsh-llm-deepseek` and `dsh-llm-pi-ai` register via the LLM capability seam [docs/module-graph.md24-25](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/module-graph.md?plain=1#L24-L25)
 
 
### Session & Query Family (`packages/session/` & `packages/session-query/`)

 Manages the durable data plane.

 
 - **`dsh-session`**: Handles persistence backends and the `SessionEvent` log [docs/module-graph.md36](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/module-graph.md?plain=1#L36-L36)
 - **`dsh-session-query-sqlite`**: Provides logical retrieval and search via SQLite [docs/module-graph.md101](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/module-graph.md?plain=1#L101-L101)
 
 
### Capability Families

 These families follow the **Service Definition / Provider / Consumer** split [packages/README.md67-68](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/README.md?plain=1#L67-L68)

 
 - **`fs/`**: Filesystem capability (`dsh-fs`) and local implementation (`dsh-fs-local`) [docs/module-graph.md46-54](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/module-graph.md?plain=1#L46-L54)
 - **`subagent/`**: Subagent provider-registry and delegation tools like `tool-subagent` [docs/module-graph.md61-73](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/module-graph.md?plain=1#L61-L73)
 - **`web/`**: HTTP fetching (`web-fetch-http`) and search tools (`web-search-deepseek`) [docs/module-graph.md74-81](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/module-graph.md?plain=1#L74-L81)

## Rules for Adding New Packages

 The monorepo enforces strict constraints on new packages to maintain architectural integrity and quality [docs/AGENTS.md75](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/AGENTS.md?plain=1#L75-L75)

 
### 1. Structure and Naming

 
 - **Location**: New packages must join an existing family directory (e.g., `packages/util/`) or create a new one with a corresponding README update [docs/module-graph.md10-20](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/module-graph.md?plain=1#L10-L20)
 - **Naming**: Must use the `@deepseek-ai/dsh-` prefix in `package.json` [docs/AGENTS.md75](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/AGENTS.md?plain=1#L75-L75)
 - **Module Type**: All packages must be ESM (`"type": "module"`) [docs/AGENTS.md75](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/AGENTS.md?plain=1#L75-L75)
 
 
### 2. Dependency Rules

 
 - **Seam Dependency**: Extension plugins should depend on **Service Definitions** (interfaces), never on concrete providers [packages/README.md67-68](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/README.md?plain=1#L67-L68)
 - **Cordis Peer**: `@deepseek-ai/cordis` must be a `peerDependency` and `devDependency` of every harness package [docs/AGENTS.md75](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/AGENTS.md?plain=1#L75-L75)
 - **Invariants**: Every package should include an `invariant.ts` file. This "companion" is used for runtime validation and proves that the package can be safely disposed of [packages/hooks/hook-protocol/src/invariant.ts1-5](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/hooks/hook-protocol/src/invariant.ts#L1-L5) [docs/AGENTS.md75](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/AGENTS.md?plain=1#L75-L75)
 
 
### 3. Documentation Requirements

 
 - **Bilingual Docs**: Every package README must have a corresponding `.zh.md` and be tracked in a `.i18n.yaml` file to ensure translation parity [docs/module-graph.i18n.yaml1-6](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/docs/module-graph.i18n.yaml#L1-L6)
 - **Model Experience**: READMEs must document the "Model Experience"—how the package's tools and prompts appear to the LLM [packages/README.md70](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/README.md?plain=1#L70-L70)
