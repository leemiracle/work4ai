## 7.1 ACP Protocol & Agent Communication

 The **Agent Client Protocol (ACP)** is an automation-only bridge exposing DSH sessions to trusted programmatic clients over JSON-RPC stdio. It enables external systems to drive agents, manage turns, and control session lifecycles without the complexity of the full DSH web UI.

 The `acp` plugin acts as a server owning and creating agents, translating ACP protocol requests into agent turns, and enforcing complex disposal semantics. Importantly, it ensures all continuable subagents are drained safely by calling `drainContinuableDescendants` before the parent session is destroyed, preserving consistent shutdown behavior [packages/acp/acp/src/index.ts12-115](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/acp/acp/src/index.ts#L12-L115)

 Key highlights include:

 
 - **AcpSession & AcpAgent**: Protocol-level abstractions representing sessions and agents under ACP control [packages/acp/acp/src/index.ts40-55](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/acp/acp/src/index.ts#L40-L55)
 - **Turn Management**: Settles prompt completion only after asynchronous injections or autonomous assistant messages quiesce, ensuring orderly output delivery [packages/acp/acp/src/index.ts160-200](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/acp/acp/src/index.ts#L160-L200)
 - **Custom Codec**: Translates between internal `SessionEvent` streams and ACP wire messages, filtering to only committed assistant content to keep reasoning and trace data off the automation wire [packages/acp/acp/src/index.ts40-45](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/acp/acp/src/index.ts#L40-L45)
 
 Overall, ACP provides a stable JSON-RPC interface that external automation engines or subagents can use to control agents reliably.

 For details, see [ACP Protocol & Agent Communication](https://deepwiki.com/deepseek-ai/deepseek-harness/7.1-acp-protocol-and-agent-communication).

## 7.2 MCP Client, Hooks & Skills

 DSH integrates with the **Model Context Protocol (MCP)** to bridge external tool servers into its tool ecosystem. The `mcp-client` plugin connects to external MCP servers (via stdio or Streamable HTTP transports) and registers their tools under stable, server-qualified public names in the DSH tool registry (`ctx.tools`) [packages/mcp/mcp-client/src/index.ts1-80](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/mcp/mcp-client/src/index.ts#L1-L80)

 
### MCP Tool Naming & Synchronization

 A deterministic naming scheme ensures tool identity integrity:

 
| Naming Concept | Description |
|---|---|
| Raw public name | mcp__<serverName>__<rawName> (e.g., mcp__github__create_issue) |
| Normalization | Replaces invalid chars with _, truncates names to max 64 characters |
| Hash suffix | Appends 12 hex chars of SHA-256 hash to avoid collisions if normalization alters the name |

 This naming contract guarantees uniqueness and stability, crucial for permissions and session consistency [packages/mcp/mcp-client/src/tools.ts95-120](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/mcp/mcp-client/src/tools.ts#L95-L120)

 Tool synchronization is performed in two phases to guarantee atomic updates without inconsistent registry states:

 
 - **Fetch Phase**: Retrieves the full paginated tool list from the MCP server, validating uniqueness and schemas without mutating the local registry.
 - **Swap Phase**: Disposes the old tool registrations and replaces them with the new generation atomically. Any conflicts are detected here and handled gracefully to prevent partial registration [packages/mcp/mcp-client/src/tools.ts130-185](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/mcp/mcp-client/src/tools.ts#L130-L185)
 
 
### Hooks & Skills

 
 - **Hooks**: Protocols such as `hooks-codex` and `hooks-claude-code` provide pre-tool interception allowing modification or augmentation of behavior before tool execution. These extend the agent's decision and turn lifecycle.
 - **Skills**: The skill system provides a curated mechanism for loading agent instruction sets and durable catalogs of available skills. The `tool-skill` plugin registers a model-facing `skill` tool that can be called to load full instructions for defined skills [packages/skill/tool-skill/src/index.ts20-160](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/skill/tool-skill/src/index.ts#L20-L160) [packages/skill/skill/src/index.ts1-130](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/skill/skill/src/index.ts#L1-L130)
 
 For details, see [MCP Client, Hooks & Skills](https://deepwiki.com/deepseek-ai/deepseek-harness/7.2-mcp-client-hooks-and-skills).

## 7.3 Goals, Todos, Workflows & Web Tools

 DSH provides higher-level orchestration frameworks that move beyond simple chat turns into structured task management:

 
 - **Goal System**: Implements tracked, durable high-level objectives across multi-turn conversations using the `tool-goal` and the driver `goal-round-driver`. This system maintains persistent state around goals and plans.
 - **Todo Tracking**: Tracks subtasks and actionable items through the `tool-todo` plugin combined with UI components like `TodoPanel` for a visual todo list.
 - **Workflows**: Manages long-running multi-step processes using workers like `workflow-worker-thread` with UI progress monitors (`ui-workflow-run`) to coordinate complex automation.
 - **Web Tools**: Specialized tools enable agents to fetch web content and execute searches, integrated with time context and schedule plugins to contextualize browsing and search activities.
 
 Together, these packages enable DSH to support declarative goal pursuit, orchestration of subtasks, and integration with web-based knowledge sources.

 For details, see [Goals, Todos, Workflows & Web Tools](https://deepwiki.com/deepseek-ai/deepseek-harness/7.3-goals-todos-workflows-and-web-tools).

## 7.4 Python SDK & Runtime Distribution

 The Python SDK (`deepseek-harness-sdk`) provides a native Python interface to interact programmatically with DSH, especially in "Code Mode" workflows where agents generate and execute Python code:

 
 - **JSON-RPC Client**: Facilitates lightweight communication with the DSH host using JSON-RPC.
 - **Turns API**: Enables Python scripts to trigger new turns, inject conversation messages, or control the agent session.
 - **Runtime Distribution**: The runtime binary package (`deepseek-harness-runtime-bin`) bundles the DSH runtime into a single-file executable, easing deployment in varied environments from local dev to production.
 
 This separation of concerns makes DSH extensible and accessible for Python developers integrating natural language with code execution.

 For details, see [Python SDK & Runtime Distribution](https://deepwiki.com/deepseek-ai/deepseek-harness/7.4-python-sdk-and-runtime-distribution).
