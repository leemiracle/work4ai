  Subagent orchestration in DeepSeek Harness (dsh) is managed through a dedicated capability seam that allows a parent agent to delegate tasks to child agents. This system abstracts the underlying transport (in-process, forked, or out-of-process via ACP) while providing a unified interface for lifecycle management, policy inheritance, and result reporting.

 
## Overview of the Subagent Seam

 The `SubagentRuntime` service, registered under `ctx.subagents`, acts as a named-provider registry [packages/subagent/subagent/src/index.ts1-32](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent/src/index.ts#L1-L32) It handles the transition from a model's intent to delegate (via tools) to the actual execution of a child agent.

 
### Key Delegation Modes

 
| Mode | Lifecycle | Ownership |
|---|---|---|
| One-shot | Runs for a single turn and returns a final result. | Owned by the caller via a SubagentRun handle. |
| Continuable | Establishes a durable session that persists across multiple turns. | Managed by the SubagentContinuationManager. |

## Subagent Providers

 Providers implement the `SubagentProvider` interface and register themselves with a unique name. They advertise their capabilities (e.g., `outputSchema`, `depthLimit`) which the runtime validates before dispatching a request.

 
### Provider Types

 
 - **In-Process (`spawn`/`fork`)**: Runs the child agent within the same Node.js process using the local `AgentLoop`. 
 - `spawn`: A fresh agent context. [packages/subagent/subagent/tests/continuation.spec.ts73](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent/tests/continuation.spec.ts#L73-L73)
 - `fork`: Inherits the parent's completed turns. [packages/subagent/subagent/tests/continuation.spec.ts74](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent/tests/continuation.spec.ts#L74-L74)
 - **Agent Client Protocol (ACP)**: Spawns an external process (e.g., `mock-acp-server.ts`) that communicates via the ACP JSON-RPC protocol over stdio [packages/subagent/subagent-acp/tests/subagent-acp.spec.ts18-24](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent-acp/tests/subagent-acp.spec.ts#L18-L24) 
 - Implements a cooperative teardown ladder: `stdin.end()` -> `SIGTERM` -> `SIGKILL`. [packages/subagent/subagent-acp/src/run.ts147-163](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent-acp/src/run.ts#L147-L163)
 - Handles unattended permission decisions via `PermissionPolicy` ('allow' | 'reject'). [packages/subagent/subagent-acp/src/run.ts25-26](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent-acp/src/run.ts#L25-L26)
 - **Product Drivers**: 
 - **Claude Code**: Wraps the official `@anthropic-ai/claude-agent-sdk`. It manages a `ManagedClaudeCodeProcess` and maps SDK results to `SubagentResult` [packages/subagent/subagent-claude-code/src/run.ts2-6](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent-claude-code/src/run.ts#L2-L6) [packages/subagent/subagent-claude-code/src/run.ts204-219](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent-claude-code/src/run.ts#L204-L219)

 - `depthLimit`: Enables enforcement of `maxDepth`.

 - `agentOptions`: Allows overriding model selection and token limits.

## Continuable Subagents

 Continuable subagents are designed for long-running interactions where the parent and child can exchange multiple messages over time.

 
### The Continuation Manager

 The `SubagentContinuationManager` (internal to `SubagentRuntime`) tracks the residency of continuable children [packages/subagent/subagent/src/index.ts56](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent/src/index.ts#L56-L56)

 
 - **Activation**: A process-local residency epoch for a child agent [packages/subagent/subagent/tests/continuation.spec.ts138-143](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent/tests/continuation.spec.ts#L138-L143)
 - **Cold Resume**: If a child is not resident, the manager reconstructs it from the persisted session log (e.g., `JsonlSessionPersistence`) when a new message arrives [packages/subagent/subagent/tests/continuation.spec.ts60-71](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent/tests/continuation.spec.ts#L60-L71)
 - **Admission**: The manager ensures only one Activation exists per `SessionId` and handles the FIFO turn queue via the Agent's inbox.
 
 
### Communication Mechanism: Report and Followup

 
 - **`followup`**: The parent sends a message to the child [packages/subagent/subagent/src/index.ts120-123](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent/src/index.ts#L120-L123)
 - **`reportFrom`**: The child sends a message back to the parent [packages/subagent/subagent/src/continuation.ts60-63](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent/src/continuation.ts#L60-L63)
 - **Delivery Policy**: Reports can be `quiet` (injected into context) or `wakeup` (triggers a new parent turn).

## Policy Inheritance and Depth Control

 To prevent infinite recursion and ensure security, subagents inherit policies from their parents.

 
### Delegation Depth

 The system tracks `delegationDepth` by inspecting the session lineage.

 
 - `assertSubagentMaxDepth`: Throws a `SubagentDepthError` if the child would exceed the configured `maxDepth` (default is 3) [packages/subagent/subagent/src/depth.ts1-15](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent/src/depth.ts#L1-L15) [packages/subagent/tool-subagent/src/index.ts98](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/tool-subagent/src/index.ts#L98-L98)
 
 
### Policy Composition

 The function `applyChildComposition` is used for in-process agents to merge the parent's preset composition with the child's specific overrides [packages/subagent/subagent/src/child-agent.ts106-111](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent/src/child-agent.ts#L106-L111)

 
 - **Tool Filtering**: Tools can be explicitly allowed or denied for the child via `toolFilter` [packages/subagent/tool-subagent/src/index.ts63-68](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/tool-subagent/src/index.ts#L63-L68)

### Stop Reason Mapping

 Product-specific stop reasons are mapped to a canonical harness vocabulary (`completed`, `aborted`, `error`, `max-tokens`, `refusal`).

 
 - **ACP**: `acpStopReason` maps 'end_turn' to 'completed' and 'max_tokens' to 'max-tokens' [packages/subagent/subagent-acp/tests/subagent-acp.spec.ts182-189](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/subagent-acp/tests/subagent-acp.spec.ts#L182-L189)
 - **Tool Result**: A non-`completed` stop reason results in an `isError` tool result [packages/subagent/tool-subagent/src/index.ts157-170](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/subagent/tool-subagent/src/index.ts#L157-L170)
