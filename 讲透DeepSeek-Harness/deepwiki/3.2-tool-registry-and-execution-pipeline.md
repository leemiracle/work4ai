  The `ToolRuntime` service (ctx key: `tools`) is the central authority for tool registration, discovery, and execution within the DeepSeek Harness. It manages the lifecycle of tool calls, enforces concurrency policies, and handles the projection of tools into the LLM's context via **Native Function Calling** or **Code Mode**.

 
## Tool Registration & Discovery

 Tools are registered as `ToolDefinition` objects, which include a name, description, JSON Schema for parameters, and an `execute` function [packages/core/tools/src/index.ts110](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L110-L110) Registration is scope-aware: global registration on the root context makes tools available to all agents, while registration on an `agent.ctx` shadows global tools for that specific agent [packages/core/tools/README.md79-81](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/README.md?plain=1#L79-L81)

## Execution Pipeline

 The execution pipeline is a structured waterfall that wraps every tool call. It ensures that concerns like security, logging, and metrics are handled orthogonally to the tool's logic.

 
### The Waterfall Sequence

 
 - **`tools/pre-execute`**: An extensible waterfall for allow/deny/ask decisions (e.g., User Approval) [packages/core/tools/src/index.ts152](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L152-L152)
 - **Monotonic Guards**: Synchronous, non-bypassable checks registered via `ctx.tools.guard()` [packages/core/tools/README.md84-85](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/README.md?plain=1#L84-L85)
 - **`tools/execute`**: An around-dispatch wrapper used for timeouts, retries, and metrics [packages/core/tools/src/index.ts163](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L163-L163)
 - **Dispatch**: The actual execution of the tool's `execute` function [packages/core/tools/README.md53-56](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/README.md?plain=1#L53-L56)
 - **`tools/post-execute`**: Allows modification or enrichment of the result before it is finalized [packages/core/tools/src/index.ts173](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L173-L173)
 - **`finalizeContent`**: A tool-defined boundary for final model-facing content normalization [packages/core/tools/src/index.ts110](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L110-L110)
 - **`tools/result`**: A terminal, observe-only notification event [packages/core/tools/src/index.ts180](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L180-L180)

## Code Mode (run_code + SDK)

 Code Mode is an alternative tool presentation where the LLM writes a program to call tools rather than emitting individual tool calls.

 
 - **`run_code` Transport**: A reserved tool that acts as the entry point for programs [packages/core/tools/src/ptc.ts104](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/ptc.ts#L104-L104)
 - **SDK Generation**: The registry projects all available tools into a type-safe SDK (TypeScript or Python) included in the system prompt [packages/core/tools/src/index.ts60-63](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L60-L63)
 - **Mode Selection**: Configured via `tools.mode` (`native`, `ptc`, or `both`) [packages/core/tools/README.md63-64](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/README.md?plain=1#L63-L64)

## Scheduling: Parallel vs. Exclusive

 The registry determines the concurrency mode of a tool call via `ToolDefinition.isConcurrencySafe` [packages/core/tools/src/index.ts110](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L110-L110)

 
 - **Parallel**: Allowed only if the tool definition explicitly declares `isConcurrencySafe(args)` as `true` [packages/core/tools/src/index.ts110](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L110-L110)
 - **Exclusive**: The default mode. The registry ensures that exclusive tools do not overlap with other tool executions to prevent race conditions (e.g., multiple tools editing the same file) [packages/core/tools/src/index.ts110](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L110-L110)

## Cooperative Cancellation

 Tool execution in DeepSeek Harness is cooperative. Every execution context provides an `AbortSignal` via `exec.signal` [packages/core/tools/src/index.ts110](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/src/index.ts#L110-L110)

 
 - **Pre-dispatch**: If the signal is aborted before the tool body is called, the registry skips execution and returns `ABORTED_BEFORE_DISPATCH` [packages/core/tools/tests/tools.spec.ts9](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/tests/tools.spec.ts#L9-L9)
 - **In-flight**: Tool implementations must monitor `exec.signal` and cease operations (e.g., killing a subprocess) when triggered [packages/core/tools/README.md53-56](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/core/tools/README.md?plain=1#L53-L56)
