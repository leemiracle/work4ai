  The LLM subsystem in DeepSeek Harness (DSH) provides a provider-neutral abstraction for large language model interactions. It centers around a streaming protocol that enables real-time token delivery, reasoning transparency, and robust error recovery through a plugin-based adapter architecture.

 
## LlmRuntime & Adapter Registration

 The `LlmRuntime` service acts as the central registry and dispatching hub for all LLM operations. It defines a capability seam that decouples the agent loop and other plugins from specific provider implementations (e.g., DeepSeek, Pi.ai).

 
### Key Service Methods

 
 - **`registerAdapter(providers, adapter)`**: Mountes an `LlmAdapter` instance to specific provider route strings. Registration is atomic and captures the provider's retry policy [packages/llm/llm/src/index.ts167-178](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm/src/index.ts#L167-L178)
 - **`prepareCall(options)`**: A critical optimization that resolves model metadata (context window, reasoning efforts) and binds the exact adapter generation and retry policy into a one-shot executable object [packages/llm/llm/src/index.ts241-267](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm/src/index.ts#L241-L267)
 - **`stream(options)`**: The primary entry point for generating completions. It returns an `AsyncIterable<StreamChunk>` and triggers the `llm/stream` waterfall [packages/llm/llm/src/index.ts213-228](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm/src/index.ts#L213-L228)
 
 
### The LlmAdapter Seam

 Every provider backend must implement the `LlmAdapter` abstract class. This requires implementing metadata discovery (`listModels`), exact model resolution (`resolveModel`), and the core `stream` logic which yields normalized chunks [packages/llm/llm/src/types.ts291-325](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm/src/types.ts#L291-L325)

## Streaming Protocol & Chunk Assembly

 DSH uses a unified `StreamChunk` protocol to represent all LLM outputs, including text, reasoning, tool calls, and usage statistics.

 
### StreamChunk Types

 
 - **`block-start` / `block-end`**: Demarcates the beginning and end of a content block (e.g., `text`, `reasoning`, or `tool-call`) [packages/llm/llm/src/types.ts110-120](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm/src/types.ts#L110-L120)
 - **`text-delta`**: Contains a fragment of generated text [packages/llm/llm/src/types.ts122-126](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm/src/types.ts#L122-L126)
 - **`reasoning-delta`**: Contains a fragment of the model's internal reasoning process [packages/llm/llm/src/types.ts128-132](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm/src/types.ts#L128-L132)
 - **`usage`**: Provides token counts (input, output, and total) [packages/llm/llm/src/types.ts152-162](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm/src/types.ts#L152-L162)
 - **`finish`**: The terminal chunk indicating success (`stop`), `length` exhaustion, `content-filter`, or `error` [packages/llm/llm/src/types.ts164-184](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm/src/types.ts#L164-L184)
 
 
### BlockAssembler

 Since raw streams are fragmented, the `BlockAssembler` is used by consumers (like the Agent Loop) to reconstruct the full `Message` and track state during iteration. It handles the state machine for nested blocks and tool call parsing [packages/llm/llm/src/assembler.ts20-40](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm/src/assembler.ts#L20-L40)

## Implementation: Pi.ai Adapter

 The `PiAiAdapter` acts as a multi-provider gateway backed by the `@earendil-works/pi-ai` library. It allows DSH to support OpenAI, Anthropic, and other providers through a single adapter instance [packages/llm/llm-pi-ai/src/index.ts2-10](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm-pi-ai/src/index.ts#L2-L10)

 
 - **Dynamic Catalog**: Resolves a `PiAiProviderProfile` which can override endpoints, protocols, and model catalogs field-by-field [packages/llm/llm-pi-ai/src/config.ts87-115](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm-pi-ai/src/config.ts#L87-L115)
 - **Reasoning Dialects**: Maps DSH reasoning levels (`off`, `low`, `high`, `max`) to provider-specific wire spellings via `reasoningEfforts` configuration [packages/llm/llm-pi-ai/src/config.ts49-52](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm-pi-ai/src/config.ts#L49-L52)

## Retry Policies & Error Handling

 Retry logic is handled at two levels:

 
 - **Provider-Level Definition**: Captured during registration via `LlmAdapter.providerInfo()`. This policy defines the strategy (e.g., `normal` with `maxRetries`) for that specific provider [packages/llm/llm/src/retry-policy.ts39-55](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm/src/retry-policy.ts#L39-L55)
 - **Execution**: The `llm-retry` package intercepts the `llm/stream` waterfall. It uses `resolveRetryPolicy` to wrap the stream generation in a retry loop based on the materialised policy [packages/llm/llm-retry/src/index.ts30-50](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef814/packages/llm/llm-retry/src/index.ts#L30-L50)
