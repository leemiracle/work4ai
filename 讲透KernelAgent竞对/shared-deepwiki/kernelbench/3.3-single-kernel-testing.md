## Purpose and Scope

This page describes how to test and debug a single kernel implementation using `run_and_check.py`. This workflow evaluates a custom kernel against a reference PyTorch implementation, measuring both correctness and performance. It is designed for interactive development and debugging of individual kernels before batch evaluation.

For generating kernels using LLMs, see Generating Kernels with LLMs [/ScalingIntelligence/KernelBench/3.1-generating-kernels-with-llms]. For evaluating multiple generated kernels, see Batch Evaluation [/ScalingIntelligence/KernelBench/3.2-batch-evaluation]. For generating reference baseline timings, see Generating Baseline Timings [/ScalingIntelligence/KernelBench/3.4-generating-baseline-timings].

## Overview

The `run_and_check.py` script provides a streamlined workflow for testing a single kernel implementation. It:

- Loads a reference PyTorch implementation (from a local file or KernelBench problem)

- Loads a custom kernel implementation

- Optionally validates the kernel using static checks

- Evaluates correctness through multiple randomized trials

- Measures performance and computes speedup against baselines

- Supports both local GPU execution and Modal cloud execution

```
## Configuration System

The `ScriptConfig` class controls all aspects of single kernel testing. Configuration uses the `pydra` library for parameter management.

### Configuration Parameters

| | Parameter | Type | Default | Description
| `ref_origin` | str | REQUIRED | Source of reference code: `"local"` or `"kernelbench"`
| `ref_arch_src_path` | str | `""` | Path to local reference file (if `ref_origin="local"`)
| `dataset_src` | str | `"huggingface"` | Dataset source: `"huggingface"` or `"local"`
| `dataset_name` | str | `"ScalingIntelligence/KernelBench"` | HuggingFace dataset name
| `level` | str | `""` | Problem level (if `ref_origin="kernelbench"`)
| `problem_id` | str | `""` | Problem ID (if `ref_origin="kernelbench"`)
| `kernel_src_path` | str | `""` | Path to kernel implementation file
| `eval_mode` | str | `"local"` | Execution mode: `"local"` or `"modal"`
| `gpu` | str | `"L40S"` | GPU type for Modal (`L40S`, `H100`, `A100`, etc.)
| `num_correct_trials` | int | `5` | Number of correctness validation trials
| `num_perf_trials` | int | `100` | Number of performance measurement trials
| `timeout` | int | `300` | Timeout per trial (seconds)
| `timing_method` | str | `"cuda_event"` | Timing method (see Timing and Profiling [/ScalingIntelligence/KernelBench/2.5-timing-and-profiling])

| `check_kernel` | bool | `True` | Enable static validation checks
| `verbose` | bool | `False` | Enable verbose logging
| `build_dir_prefix` | str | `""` | Custom build directory prefix
| `clear_cache` | bool | `False` | Clear build cache before evaluation
```

```
## Evaluation Results

The script prints comprehensive results comparing the custom kernel against both baselines.

### Output Format

```
`========================================
[Eval] Kernel eval result: KernelExecResult(...)
----------------------------------------
[Timing] PyTorch Reference Eager exec time: X.XX ms
[Timing] PyTorch Reference torch.compile time: Y.YY ms
[Timing] Custom Kernel exec time: Z.ZZ ms
----------------------------------------
[Speedup] Speedup over eager: A.AAx
[Speedup] Speedup over torch.compile: B.BBx
========================================
`

### KernelExecResult Structure

The `KernelExecResult` dataclass contains:

| | Field | Type | Description
| `compiled` | bool | Whether kernel compiled successfully
| `correctness` | bool | Whether all correctness trials passed
| `metadata` | dict | Error messages, hardware info, etc.
| `runtime` | float | Mean execution time (ms)
| `runtime_stats` | dict | Detailed timing statistics (mean, std, min, max)

Speedup is only calculated when `correctness=True`. If correctness fails, speedup is reported as "Not Available".
