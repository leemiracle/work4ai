## Purpose and Scope

The Kernel Evaluation System tests generated GPU kernels for correctness and performance against reference PyTorch implementations. It supports evaluation on local GPUs via multiprocessing or on Modal cloud infrastructure for scalable execution across heterogeneous GPU types (L40S, H100, A100, T4, etc.). The system handles multiple backend DSLs (CUDA, Triton, CuTe, TileLang, ThunderKittens) and provides rigorous correctness validation with configurable timing methods.

## Timing Methods

The evaluation system supports four timing methods via `get_timing_function(timing_method)`:

| | Timing Method | Description | Use Case
| `cuda_event` | Device-side timing with CUDA events, includes L2 cache clearing | Default, precise GPU time measurement
| `do_bench` | Triton's adaptive benchmarking (warmup=25ms, rep=100ms) | Triton kernels, handles variable execution times
| `host_time` | CPU wall-clock time with `time.perf_counter()` | End-to-end latency including host overhead
| `nsight` | Hardware counter profiling via `nsight-python` | Deep performance analysis (requires sudo)

CUDA Event Timing with L2 Cache Clearing

```

The L2 cache clearing prevents cached data from artificially improving performance on repeated runs.
```

```
## Modal Cloud Execution

### ModalEvaluator Class

The `ModalEvaluator` class provides cloud GPU evaluation with automatic retry and error handling:

```

Retry Configuration:

- `max_retries=3`: Retry up to 3 times on failures

- `backoff_coefficient=2.0`: Exponential backoff (2x multiplier)

- `initial_delay=1.0`: Start with 1 second delay

GPU Corruption Handling:
When a CUDA error occurs, the container's GPU memory state may be corrupted. The system calls `stop_fetching_inputs()` to retire the container and allocate a fresh one for subsequent tasks.

```
## Performance Metrics and Analysis

### pass@k Metric

The `pass@k` metric measures the probability that at least one of `k` samples is correct:

```

Example:

- Problem has `n=10` total samples, `c=3` correct samples

- `pass@1 = 3/10 = 0.3` (30% chance 1 random sample is correct)

- `pass@5 = 1 - (7/10 * 6/9 * 5/8 * 4/7 * 3/6) ≈ 0.879` (87.9% chance at least 1 of 5 samples is correct)
