## Purpose and Scope

Level 2 contains approximately 100 problems that combine 2-5 Level 1 atomic operations into fused operation patterns. These problems evaluate LLM capability to generate kernels that optimize multi-operation sequences through operator fusion, reducing memory bandwidth and kernel launch overhead.

Key Characteristics:

- Operation Count: 2-5 chained operations per problem

- Fusion Complexity: Combines heterogeneous operation types (spatial, element-wise, reductions)

- Naming Convention: `{id}_{Op1}_{Op2}_{Op3}..._{OpN}.py`

- Interface: Identical to Level 1 (`Model` class, `get_inputs()`, `get_init_inputs()`)

For atomic single-operation problems, see page 5.2. For complete model architectures, see page 5.4. For dataset loading mechanisms, see page 5.1.

```
## Problem Structure and Interface

Level 2 problems inherit from `torch.nn.Module` and follow the identical interface pattern as Level 1. The distinguishing feature is the `forward()` method containing multiple chained operations representing fusion opportunities.

### Code Entity Interface

| | Component | Type | Purpose | Code Pattern
| `Model` | `class` inheriting `nn.Module` | Defines composite operation | `class Model(nn.Module):`
| `__init__(self, ...)` | Method | Constructs component layers | `self.conv = nn.Conv2d(...)`
`self.bn = nn.BatchNorm2d(...)`
| `forward(self, x)` | Method | Executes operation chain | `x = self.conv(x)`
`x = F.relu(x)`
`x = self.bn(x)`
| `get_inputs()` | Function | Generates test tensors | `return [torch.rand(batch_size, ...)]`
| `get_init_inputs()` | Function | Returns constructor arguments | `return [in_channels, out_channels, ...]`
| Module-level constants | Variables | Problem dimensions | `batch_size = 64`
`in_channels = 64`
```

```
### Pattern Categories with Code Entities

#### 1. Convolution Pipelines

Combine `nn.Conv2d`/`nn.Conv3d` with post-processing operations.

Pattern: Conv + Activation(s)

- level2/4_Conv2d_Mish_Mish.py10-16 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/level2/4_Conv2d_Mish_Mish.py#L10-L16]

- Code: `self.conv = nn.Conv2d(in_channels, out_channels, kernel_size)`

- Forward: `x = self.conv(x); x = F.mish(x); x = F.mish(x)`

Pattern: Conv + Normalization + Activation + Reduction

- level2/27_Conv3d_HardSwish_GroupNorm_Mean.py13-23 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/level2/27_Conv3d_HardSwish_GroupNorm_Mean.py#L13-L23]

- Code: `self.conv = nn.Conv3d(...); self.group_norm = nn.GroupNorm(num_groups, out_channels)`

- Forward: `x = self.conv(x); x = F.hardswish(x); x = self.group_norm(x); x = torch.mean(x, dim=[2,3,4])`

#### 2. Linear Algebra (GEMM) Chains

Matrix multiplication via `nn.Linear` followed by normalization/activation.

Pattern: Linear → GroupNorm → LeakyReLU → Add

- level2/62_Matmul_GroupNorm_LeakyReLU_Sum.py8-28 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/level2/62_Matmul_GroupNorm_LeakyReLU_Sum.py#L8-L28]

- Code: `self.fc = nn.Linear(input_size, hidden_size); self.gn = nn.GroupNorm(num_groups, hidden_size)`

- Forward: `x = self.fc(x); x = self.gn(x); x = self.leaky_relu(x); x = x + x`

Pattern: Linear → Sigmoid → Scale → Residual

- level2/70_Gemm_Sigmoid_Scaling_ResidualAdd.py8-28 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/level2/70_Gemm_Sigmoid_Scaling_ResidualAdd.py#L8-L28]

- Code: `self.gemm = nn.Linear(input_size, hidden_size)`

- Forward: `original_x = x; x = self.gemm(x); x = torch.sigmoid(x); x = x * scaling_factor; x = x + original_x`

#### 3. Spatial Transform Fusion

Combines `nn.ConvTranspose2d`/`nn.ConvTranspose3d` or pooling with other operations.

Pattern: AvgPool → ConvTranspose → Clamp → Softmax → Multiply

- level2/38_ConvTranspose3d_AvgPool_Clamp_Softmax_Multiply.py9-33 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/level2/38_ConvTranspose3d_AvgPool_Clamp_Softmax_Multiply.py#L9-L33]

- Code: `self.avg_pool = nn.AvgPool3d(pool_kernel_size); self.conv_transpose = nn.ConvTranspose3d(...)`

- Forward: 5-stage pipeline with reshape operations for spatial softmax

Pattern: ConvTranspose → Subtract → Tanh

- level2/5_ConvTranspose2d_Subtract_Tanh.py8-17 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/level2/5_ConvTranspose2d_Subtract_Tanh.py#L8-L17]

- Code: `self.conv_transpose = nn.ConvTranspose2d(...); self.bias = nn.Parameter(torch.randn(bias_shape))`

- Forward: `x = self.conv_transpose(x); x = x - self.bias; x = torch.tanh(x)`

#### 4. Arithmetic and Reduction Patterns

Element-wise operations combined with reductions.

Pattern: Conv → Scale → Min Reduction

- level2/32_Conv2d_Scaling_Min.py8-23 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/level2/32_Conv2d_Scaling_Min.py#L8-L23]

- Code: `self.conv = nn.Conv2d(in_channels, out_channels, kernel_size)`

- Forward: `x = self.conv(x); x = x * self.scale_factor; x = torch.min(x, dim=1, keepdim=True)[0]`
```

```
## Optimization Opportunities Through Fusion

Level 2 problems expose kernel fusion opportunities that reduce memory traffic and launch overhead compared to unfused Level 1 sequences.

### Memory Bandwidth Reduction Through Fusion

Title: Unfused vs Fused Memory Access Patterns

```

Memory Transaction Analysis:

- Unfused: 6 DRAM transactions (3 reads + 3 writes)

- Fused: 2 DRAM transactions (1 read + 1 write)

- Reduction: 3× fewer memory operations

### Kernel Launch Overhead Elimination

PyTorch Eager Execution Overhead:

- Each `nn.Module` operation launches separate CUDA kernel

- Kernel launch latency: ~5-10μs per launch

- CPU-GPU synchronization overhead per operation

- Python interpreter overhead for sequential operations

Fused Kernel Benefit:

- Single kernel launch for entire operation chain

- Eliminated synchronization between operations

- Example: level2/4_Conv2d_Mish_Mish.py13-15 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/level2/4_Conv2d_Mish_Mish.py#L13-L15] has 3 operations → single launch opportunity

## Integration with Prompting System

Level 2 problems benefit from few-shot prompting strategies (page 4.4) due to repeating fusion patterns.

### Why Few-Shot Works for Level 2

- Recurring Patterns: Conv+Norm+Activation appears in multiple problems with similar fusion strategies

- Template Adaptation: A Conv2d+ReLU fusion can be adapted to Conv3d+HardSwish with pattern matching

- Pipeline Complexity: Multi-operation chains require examples to demonstrate intermediate value management

### Prompt Construction for Level 2

The prompt system (page 4.1) leverages Level 2 problems in few-shot examples:

Example Fusion Strategies Taught:

- Shared Memory Tiling: Load spatial tile once, apply all element-wise operations

- Register Blocking: Keep intermediate values in registers for activation chains

- Cooperative Threads: Distribute normalization statistics computation across threadblock

Backend-Specific Patterns (page 4.2):

- Triton: Use `tl.load` once, apply operation sequence with `tl.store` at end

- CUDA: Allocate shared memory for tile, fuse operations in same kernel

- CuTe: Define composite operation as single `cute::Tensor` transformation

## Summary

Level 2 problems bridge the gap between atomic operations (Level 1) and complete architectures (Level 3) by presenting realistic fusion opportunities that appear in production models. The 100 problems cover diverse operation combinations across 2D/3D convolutions, linear algebra, activations, normalizations, and arithmetic operations. Each problem follows the standard `Model` interface and provides production-scale tensor dimensions to ensure performance measurements reflect real-world optimization scenarios.

Key characteristics:

- File naming: `{number}_{Op1}_{Op2}_{Op3}..._{OpN}.py`

- Interface: Identical to Level 1 (`Model`, `get_inputs()`, `get_init_inputs()`)

- Optimization goal: Kernel fusion to reduce memory traffic and launch overhead

- Importance range: 1.18 to 7.10 (based on dataset statistics)
