## Purpose and Scope

This document covers KernelBench's support for test-time inference frameworks - advanced systems that orchestrate multiple LLM calls, implement reasoning strategies, or apply ensemble methods during generation. Test-time frameworks differ from single-model inference by using techniques like multi-model voting, iterative refinement, or structured reasoning to improve generation quality.

For basic single-model LLM inference (OpenAI, DeepSeek, etc.), see LLM Integration [/ScalingIntelligence/KernelBench/2.2-llm-integration]. This page focuses specifically on integrating frameworks like Archon that execute more complex inference-time strategies.

Current Support:

- Archon - Multi-model reasoning framework that aggregates outputs from multiple LLMs

Extensibility: The system is designed to support additional test-time frameworks as they emerge.

## What Are Test-Time Frameworks?

Test-time frameworks enhance LLM generation by applying sophisticated reasoning strategies at inference time, rather than relying on a single forward pass through one model. Common patterns include:

| | Pattern | Description | Example
| Multi-Model Ensemble | Query multiple models and aggregate responses | Archon generates from 3+ models and selects best
| Iterative Refinement | Generate → critique → regenerate cycles | Self-reflection, constitutional AI
| Tree Search | Explore multiple reasoning paths | MCTS, beam search with verification
| Verification & Voting | Generate multiple candidates and vote/verify | Best-of-N sampling with validators

In KernelBench's context, test-time frameworks can potentially improve kernel generation by:

- Leveraging model diversity (e.g., GPT-4 for reasoning + DeepSeek for code)

- Applying verification steps to catch compilation errors

- Using ensemble voting to select more correct/efficient kernels

## Framework Integration Architecture

### System Design

KernelBench's test-time framework support mirrors the single-model LLM interface, providing drop-in compatibility with the generation pipeline.

```

Key Design Principles:

- Unified Interface: `query_framework_server()` matches signature of `query_server()` from LLM Integration [/ScalingIntelligence/KernelBench/2.2-llm-integration]

- Configuration-Driven: Frameworks are configured via JSON files and `SERVER_PRESETS` dictionary

- Factory Pattern: `create_inference_framework_server_from_presets()` returns a callable that can be passed to generation scripts

- Extensible: Match statement allows adding new frameworks without changing caller code

## Framework vs Single-Model Trade-offs

### When to Use Test-Time Frameworks

| | Scenario | Recommendation | Reason
| Benchmarking model capabilities | Single model | Isolates model performance
| Maximizing kernel quality | Framework | Ensemble/verification improves results
| Cost-sensitive experiments | Single model | Frameworks multiply API costs
| Research on reasoning strategies | Framework | Enables comparison of test-time methods
| Rapid prototyping | Single model | Simpler setup, faster iteration
| Production deployment | Depends | Consider latency, cost, quality needs

### Performance Characteristics

```

Empirical Considerations:

- Latency: Frameworks add overhead. If models are queried in parallel, latency ≈ slowest model. If serial, latency = sum of all models.

- Cost: Frameworks multiply API costs by number of models queried. Archon with 3 models costs ~3x a single call.

- Quality: Frameworks can improve quality through voting, but gains depend on model diversity and aggregation strategy.

- Caching: Framework responses typically aren't cached (too complex), unlike single-model calls.

## Future Framework Support

### Planned Integrations

The `frameworks.py` module is designed to support additional test-time frameworks. Promising candidates include:

| | Framework | Description | Integration Complexity
| Constitutional AI | Multi-step generation with critique | Medium - requires prompt chaining
| Tree of Thoughts | Explore multiple reasoning paths | High - needs search implementation
| Self-Consistency | Generate N samples, vote on answer | Low - similar to Archon
| Reflexion | Generate → evaluate → refine loop | Medium - requires evaluation step
| MCTS-based | Monte Carlo tree search over reasoning | High - complex search logic
