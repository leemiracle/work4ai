### Core Component Functions

The system consists of four primary components, each with specific responsibilities:

- Dataset Management (`src/dataset.py`): Loads and manages benchmark problems

- Prompt Construction (`src/prompt_constructor.py`): Builds prompts for LLMs

- LLM Interaction (`src/utils.py`): Handles API calls to various LLM providers

- Evaluation (`src/eval.py`): Tests kernels for correctness and performance

### Entry Points

KernelBench provides several scripts as entry points for different workflows:

| | Script | Purpose | Key Functions
| `scripts/generate_samples.py` | Generate kernels in batch | `generate_sample_single`, `maybe_multithread`
| `scripts/generate_and_eval_single_sample.py` | Generate and evaluate a single kernel | `eval_kernel_against_ref`
| `scripts/eval_from_generations.py` | Evaluate previously generated kernels | `eval_kernel_against_ref`
| `scripts/generate_baseline_time.py` | Generate performance baselines | `time_execution_with_cuda_event`

The workflow process consists of these key stages:

- A problem is loaded from the KernelBench dataset

- A prompt is constructed based on the reference architecture

- The LLM is queried to generate a CUDA kernel

- The generated code is extracted from the LLM response

- Both the reference model and custom kernel are run with identical inputs

- Outputs are compared for correctness

- If correct, performance is measured and speedup is calculated

## Configuration and Extension

KernelBench is designed to be configurable and extensible:

### LLM Provider Configuration

LLM providers are configured through the `SERVER_PRESETS` dictionary src/utils.py357-396 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/src/utils.py#L357-L396] which defines default parameters for each provider.

Adding a new provider requires:

- Updating the `query_server` function to handle the new provider

- Adding appropriate API key handling in src/utils.py37-44 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/src/utils.py#L37-L44]

- Creating a preset configuration in `SERVER_PRESETS`

### Evaluation Parameters

Evaluation parameters can be configured when calling `eval_kernel_against_ref` src/eval.py294-458 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/src/eval.py#L294-L458]:

- `seed_num`: Seed for reproducible inputs

- `num_correct_trials`: Number of trials for correctness checking

- `num_perf_trials`: Number of trials for performance measurement

- `verbose`: Whether to print detailed information

- `measure_performance`: Whether to measure performance

- `build_dir`: Directory for compiled binaries

## Summary

The core architecture of KernelBench provides a robust framework for evaluating LLMs' ability to generate efficient GPU kernels. It handles the entire pipeline from problem definition to performance evaluation, with extensible support for various LLM providers and evaluation metrics.
