## Purpose and Scope

This document explains how to generate baseline performance measurements for KernelBench reference problems. Baseline timings capture the execution time of PyTorch reference implementations across different hardware and compiler configurations. These measurements are essential for computing speedup ratios between reference implementations and LLM-generated kernels.

For information about using these baseline timings during evaluation, see Batch Evaluation [/ScalingIntelligence/KernelBench/3.2-batch-evaluation]. For details on computing speedup metrics from baseline times, see Evaluation Metrics [/ScalingIntelligence/KernelBench/7.1-evaluation-metrics].

## Overview

Baseline timing measures the wall-clock execution time of reference PyTorch implementations for each KernelBench problem. Since speedup is calculated as `baseline_runtime / custom_kernel_runtime`, accurate baseline measurements are critical for meaningful performance comparisons.

KernelBench supports profiling baselines across:

- Multiple hardware configurations: L40S, H100, A100, T4, A10G, etc.

- Multiple execution modes: PyTorch Eager, torch.compile with various backends (inductor, cudagraphs) and modes (default, reduce-overhead, max-autotune)

- Local or cloud execution: Direct GPU profiling or distributed profiling via Modal

Key Characteristics:

| | Metric | Configuration
| Warmup trials | 3 runs
| Measurement trials | 100 runs (configurable)
| Timing method | CUDA event timing
| Output statistics | mean, std, min, max, hardware info

```
## Best Practices

### Ensuring Reproducibility

- Set Deterministic Seeds: Both scripts use `set_seed(42)` for input generation

- Fixed Trial Count: Use consistent `num_trials=100` across runs

- GPU Warmup: 3 warmup runs prime GPU state before measurement

- Hardware Documentation: Record GPU power settings, cooling, and clock speeds

### Performance Considerations

Local Generation:

- Sequential execution (one problem at a time)

- Total time: ~30-60 minutes per level depending on hardware

- Requires exclusive GPU access for accurate measurements

Modal Generation:

- Parallel execution across problems

- Total time: ~10-20 minutes per level with `batch_size=10`

- Isolated GPU instances ensure clean measurements

### Validation

After generating baselines, validate results by checking:

```

Common Issues:

- High variance (>10%): GPU throttling, background processes, or insufficient warmup

- Missing problems: Timeout or memory errors (check Modal logs)

- Inconsistent hardware info: Multiple GPUs used during profiling
