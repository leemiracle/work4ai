## Purpose and Scope

This page documents the baseline timing system that measures reference PyTorch performance for KernelBench problems. Baselines are essential because KernelBench evaluates generated kernels by computing speedup = `baseline_time / generated_kernel_time`. Without accurate baselines, performance metrics would be meaningless.

The baseline system supports multiple PyTorch execution modes (eager, torch.compile with various backends/modes) across different GPU architectures. Pre-computed baselines are provided in results/timing/ [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/results/timing/] but users should generate custom baselines for their specific hardware and power configurations.

For information about how baselines are used in speedup calculations and the `fast_p` metric, see Evaluation Metrics [/ScalingIntelligence/KernelBench/7.1-evaluation-metrics]. For the complete evaluation workflow, see Batch Evaluation [/ScalingIntelligence/KernelBench/3.2-batch-evaluation].

## Baseline Configurations

KernelBench measures baseline performance under six different PyTorch configurations to enable comprehensive speedup comparisons:

| | Configuration | Backend | Mode | Description
| `baseline_time_torch.json` | - | - | PyTorch eager execution (no compilation)
| `baseline_time_torch_compile_inductor_default.json` | inductor | default | Default torch.compile behavior
| `baseline_time_torch_compile_inductor_reduce-overhead.json` | inductor | reduce-overhead | Optimized for reduced overhead
| `baseline_time_torch_compile_inductor_max-autotune.json` | inductor | max-autotune | Maximum autotuning enabled
| `baseline_time_torch_compile_inductor_max-autotune-no-cudagraphs.json` | inductor | max-autotune-no-cudagraphs | Maximum autotuning without CUDA graphs
| `baseline_time_torch_compile_cudagraphs.json` | cudagraphs | - | CUDA graphs with AOT Autograd

### Eager vs Compiled Baselines

PyTorch Eager represents the standard, unoptimized execution path. This is the most common baseline for evaluating hand-written kernel speedups.

Torch.compile variants represent different levels of automatic optimization. When evaluating LLM-generated kernels, you may compare against compiled baselines to assess whether the LLM can match or exceed PyTorch's compiler optimizations.

## Baseline Generation Workflow

```

### Baseline Generation Process

The `generate_baseline_time.py` script orchestrates baseline generation:

- 
Dataset Construction: For each level (1, 2, 3), constructs the full dataset using `construct_kernelbench_dataset()`.

- 
Problem Iteration: Iterates through all problems, fetching reference architecture code with `fetch_ref_arch_from_dataset()`.

- 
Model Loading: Executes the reference code to obtain `Model`, `get_init_inputs()`, and `get_inputs()` functions via `load_original_model_and_inputs()`.

- 
Timing Execution: Calls `measure_program_time()` which:

- Initializes the model with seed 42 for reproducibility

- Optionally applies `torch.compile()` with specified backend and mode

- Executes the timing function (default: `cuda_event`) for 100 trials

- Computes statistics via `get_timing_stats()`

- 
Result Aggregation: Stores timing statistics in nested dictionary structure: `level{N} -> problem_name -> runtime_stats`.

- 
Persistence: Saves to JSON file in `results/timing/{hardware_name}/baseline_time_{config}.json`.

The process repeats for each PyTorch configuration, generating 6 baseline files per hardware platform.

## Baseline File Structure

Baseline JSON files follow a hierarchical structure:

```

### Runtime Statistics Fields

Each problem's baseline contains:

| | Field | Type | Description
| `mean` | float | Mean runtime in milliseconds across all trials
| `std` | float | Standard deviation of runtime
| `min` | float | Minimum runtime observed
| `max` | float | Maximum runtime observed
| `num_trials` | int | Number of timing trials executed (default: 100)
| `hardware` | string | GPU model name (e.g., "NVIDIA H100 PCIe")
| `device` | string | CUDA device identifier (e.g., "cuda:0")

The `mean` field is used as the baseline time in speedup calculations. The `std`, `min`, and `max` fields provide insight into runtime stability.

## Integration with Evaluation Pipeline

```

### Baseline Lookup Process

The `benchmark_eval_analysis.py` script demonstrates how baselines are used:

- 
Load Baseline File: Reads the appropriate baseline JSON based on `hardware` and `baseline` parameters.

- 
Load Evaluation Results: Reads `runs/{run_name}/eval_results.json` containing LLM-generated kernel performance.

- 
Alignment by Problem Name: For each problem ID:

- Retrieves `Problem` object from dataset to get `problem.name`

- Looks up baseline: `baseline_results[f"level{level}"][problem.name]`

- Looks up evaluation: `eval_results[str(problem_id)]`

- 
Extract Runtime Values:

- Baseline: `baseline_entry["mean"]`

- Generated: `eval_entry["runtime"]`

- 
Compute Speedup: `speedup = baseline_time / generated_time`

- 
Calculate Aggregate Metrics: Passes speedup arrays to `geometric_mean_speed_ratio_correct_only()` and `fastp()` functions.

Important: Problem matching uses the problem name (filename) as the key, not the problem ID. This allows baselines to work across different dataset versions that may reorder problems.

## Timing Methodology

### Measurement Parameters

Baselines use consistent timing parameters for reproducibility:

- Timing Method: `cuda_event` (device-side timing with L2 cache clearing)

- Number of Trials: 100

- Warmup Iterations: Handled by `get_timing_function()`

- Seed: 42 (for deterministic input generation)

- Device: `cuda:0` (first available GPU)

### measure_program_time Function

The core timing function `measure_program_time()` encapsulates the measurement process:

```

Key steps:

- Loads model and input generators via `load_original_model_and_inputs()`

- Initializes model with reproducible inputs (seed 42)

- Optionally applies `torch.compile()` with specified backend/mode

- Executes timing function for specified trials

- Computes statistics via `get_timing_stats()`

- Returns dictionary with mean, std, min, max, num_trials, hardware, device

## Best Practices

### When to Generate Custom Baselines

Generate custom baselines when:

- Different Hardware: Your GPU model differs from pre-computed platforms

- Different Power Settings: GPU power limits affect performance significantly

- Different Software Stack: PyTorch version, CUDA version, or driver version differs

- Different System Configuration: Cooling, CPU-GPU interconnect, or memory speed varies

### Baseline Selection for Evaluation

Choose the appropriate baseline configuration based on your evaluation goals:

- PyTorch Eager: Most conservative baseline, measures pure kernel optimization

- Inductor Default: Compares against standard torch.compile optimization

- Max-Autotune: Most aggressive baseline, tests if LLMs can beat PyTorch's best effort
