## Purpose and Scope

This document demonstrates how KernelBench integrates custom CUDA kernels that depend on external libraries into PyTorch models using inline compilation. It focuses specifically on the `torch.utils.cpp_extension.load_inline` API, which allows embedding CUDA source code directly in Python files and compiling it at runtime. The primary example covered is ThunderKittens integration, but the patterns apply to any custom CUDA library.

For information about other backend integrations (Triton, CuTe, TileLang), see Backend Support [/ScalingIntelligence/KernelBench/2.4-backend-support]. For general kernel evaluation workflows, see Kernel Evaluation System [/ScalingIntelligence/KernelBench/2.1-kernel-evaluation-system].

## Inline Compilation Overview

KernelBench supports custom CUDA kernels through PyTorch's inline compilation mechanism, which eliminates the need for separate build systems. The workflow consists of:

- Source Definition: CUDA kernel code and C++ wrapper functions defined as Python strings

- Environment Configuration: Paths to external library headers and dependencies

- Compilation: Runtime compilation via `torch.utils.cpp_extension.load_inline`

- Integration: Compiled functions wrapped in `nn.Module` classes

This approach enables LLMs to generate complete, self-contained kernel implementations without managing external build files.

#### Global Memory Struct Pattern

ThunderKittens uses a `__grid_constant__` struct to pass global memory pointers to kernels:

src/kernelbench/prompts/model_new_ex_add_thunderkittens.py25-31 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/src/kernelbench/prompts/model_new_ex_add_thunderkittens.py#L25-L31]

This struct defines:

- `sub_tile`: Template alias for tile shape (`st_bf<16, 16>` = shared tile, bfloat16, 16×16)

- `tile_gl`: Template alias for global memory layout (`gl<bf16, ...>` with dynamic dimensions)

- Member tiles: `A`, `B`, `C` for input and output data

The `__grid_constant__` decorator enables efficient constant memory access across all blocks.

#### Kernel Implementation Details

The kernel follows ThunderKittens' hierarchical memory pattern:

| | Memory Level | Operation | ThunderKittens API
| Global → Shared | Load tile from DRAM | `warp::load(As, g.A, {batch, head, row, col})`
| Shared → Register | Load tile into registers | `warp::load(A_reg, As)`
| Register | Computation | `warp::add(C_reg, A_reg, B_reg)`
| Register → Global | Write result to DRAM | `warp::store(g.C, C_reg, {batch, head, row, col})`

Synchronization via `__syncthreads()` ensures memory consistency between warps sharing the same tile data.

### Critical Compilation Flags

| | Flag Category | Flags | Purpose
| C++ Standard | `-std=c++20` | Required for ThunderKittens template metaprogramming
| Optimization | `-O3`, `-DNDEBUG` | Maximum optimization, disable debug assertions
| Architecture | `-arch=sm_90a` | Target Hopper compute capability 9.0 with all features
| CUDA Extensions | `--expt-relaxed-constexpr`
`--expt-extended-lambda` | Enable advanced C++ features in device code
| Library Defines | `-DKITTENS_HOPPER`
`-DKITTENS_BLACKWELL` | Enable architecture-specific features
| Diagnostic Control | `-diag-suppress=20012` | Suppress benign warnings about inline functions
| Position Independent | `-Xcompiler -fPIC` | Generate relocatable code
| Type Support | `-U__CUDA_NO_HALF_OPERATORS__`
`-U__CUDA_NO_HALF_CONVERSIONS__`
`-U__CUDA_NO_BFLOAT16_CONVERSIONS__`
`-U__CUDA_NO_HALF2_OPERATORS__` | Enable half/bfloat16 intrinsics

The `-arch=sm_90a` flag is particularly critical—it must match the target GPU architecture. For other GPUs, this would change (e.g., `-arch=sm_80` for A100, `-arch=sm_89` for L40S).

## Error Handling Considerations

Common compilation failures and solutions:

| | Error Type | Symptom | Solution
| Missing Headers | `fatal error: kittens.cuh: No such file or directory` | Verify `THUNDERKITTENS_ROOT` is set and `extra_include_paths` includes header directory
| Architecture Mismatch | `error: unsupported gpu architecture 'compute_90a'` | Change `-arch=sm_90a` to match available GPU (e.g., `sm_80` for A100)
| Symbol Undefined | `undefined reference to kittens::warp::load` | Ensure all required source files are included or library is linked
| Type Conversion | `error: no operator '+' matches these operands` | Add `-U__CUDA_NO_*` flags to enable type operators
| Shared Memory Limit | `cudaErrorInvalidConfiguration` at runtime | Reduce `mem_size` or set `cudaFuncAttributeMaxDynamicSharedMemorySize`

The `verbose=True` flag in `load_inline` prints full compiler output for debugging.
