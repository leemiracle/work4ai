This document describes how to use `eval_from_generations.py` to evaluate multiple generated kernels in parallel. Batch evaluation is the primary workflow for measuring model performance on KernelBench, supporting both local GPU execution and distributed Modal cloud execution. For single kernel testing during development, see Single Kernel Testing [/ScalingIntelligence/KernelBench/3.3-single-kernel-testing].

## 1. Overview

Batch evaluation processes multiple generated kernels in parallel to:

- Verify Correctness - Check if kernels produce outputs matching the reference implementation

- Measure Performance - Time kernel execution and calculate speedup ratios

- Calculate Pass@k - Compute aggregate metrics across multiple samples per problem

- Support Scale - Evaluate hundreds of kernels efficiently using parallel GPU workers

## 2. Configuration with EvalConfig

The `EvalConfig` class specifies all parameters for batch evaluation. Key configuration options:

EvalConfig Configuration Options

| | Parameter | Type | Description | Default
| `run_name` | str | Name of generation run directory | REQUIRED
| `dataset_src` | str | Dataset source: "huggingface" or "local" | REQUIRED
| `level` | int | Problem level to evaluate (1, 2, or 3) | REQUIRED
| `subset` | tuple | Problem range to evaluate: (start_id, end_id) | (None, None)
| `eval_mode` | str | Execution mode: "local" or "modal" | "local"
| `gpu` | str | GPU type for Modal (L40S, H100, A100, etc.) | "A10G"
| `gpu_arch` | list | GPU architecture list (e.g., ["Ada"]) | ["Ada"]
| `num_correct_trials` | int | Correctness check trials per kernel | 5
| `num_perf_trials` | int | Performance measurement trials | 100
| `measure_performance` | bool | Whether to measure performance | True
| `build_cache` | bool | Pre-compile on CPU before GPU eval | False
| `num_cpu_workers` | int | CPU workers for cache building | 20
| `num_gpu_devices` | int | Number of GPUs for local evaluation | 1

| `precision` | str | Precision: "fp32", "fp16", "bf16" | "fp32"
| `num_samples_per_problem` | int | Samples per problem for pass@k | 1
| `pass_at_k_values` | list | k values for pass@k calculation | [1]

### 5.2 Pass@k Results

When `num_samples_per_problem > 1`, pass@k metrics are calculated and saved to `runs/{run_name}/pass_at_k_results.json`:

pass_at_k_results.json Structure

```

Pass@k calculation:
Pass@k is the probability that at least one of k samples is correct:

```
`pass@k = 1 - (n-c choose k) / (n choose k)
`

Where:

- n = total samples evaluated

- c = correct samples

- k = number of samples to consider

Implementation:

- `calculate_pass_at_k()` - Main calculation function scripts/eval_from_generations.py821-927 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/scripts/eval_from_generations.py#L821-L927]

## 8. Running Evaluations

To evaluate kernels:

- Single Evaluation: Use `scripts/generate_and_eval_single_sample.py` to generate and evaluate a single kernel

- Batch Evaluation: Use `scripts/eval_from_generations.py` to evaluate previously generated kernels

For batch evaluation, configure parameters such as:

- `run_name`: Name of the run with generated kernels

- `level`: Level of problems to evaluate

- `num_correct_trials`: Number of trials for correctness checking

- `num_perf_trials`: Number of trials for performance measurement

- `num_gpu_devices`: Number of GPUs to use for parallel evaluation
