This page documents the five GPU kernel Domain-Specific Languages (DSLs) supported by KernelBench and their integration into the system. It covers backend selection, configuration, precision constraints, architecture targeting, prompt construction, and compilation approaches for each backend. For information about prompt engineering across backends, see Prompt Engineering [/ScalingIntelligence/KernelBench/4-prompt-engineering]. For details on kernel compilation and caching, see Compilation and Caching [/ScalingIntelligence/KernelBench/2.6-compilation-and-caching].

## Overview of Supported Backends

KernelBench supports five GPU kernel programming languages, each with distinct programming models, compilation toolchains, and performance characteristics. The supported backends are:

| | Backend | Display Name | Programming Model | Compilation Approach | Default Precision
| `cuda` | CUDA operators | Custom C++/CUDA kernels with inline CUDA C++ code | `torch.utils.cpp_extension.load_inline()` | fp32
| `triton` | Triton kernels | Python-based kernel DSL with `@triton.jit` decorators | Triton JIT compiler | fp32
| `cute` | CuTe (CUTLASS) kernels | CUTLASS template-based kernels | `torch.utils.cpp_extension.load_inline()` with CUTLASS includes | fp32
| `tilelang` | TileLang kernels | Tile-based DSL for structured memory access patterns | TileLang compiler | fp16 (required)
| `thunderkittens` | ThunderKittens kernels | High-level abstractions using `kittens::` primitives | `torch.utils.cpp_extension.load_inline()` with ThunderKittens includes | bf16 (recommended)

## Backend-Specific Constraints

### Precision Requirements

Each backend has specific precision requirements based on its design and target hardware:

```

TileLang Precision Constraint: TileLang only operates with FP16 precision. The system automatically sets `config.precision = "fp16"` when TileLang is selected.

ThunderKittens Precision Constraint: ThunderKittens is designed for BF16 operations on Hopper architecture (H100). The system automatically sets `config.precision = "bf16"` when ThunderKittens is selected.

### GPU Architecture Targeting

Each backend supports compilation for specific GPU architectures through the `gpu_arch` parameter:

| | Architecture | GPU Models | SM Version | Backend Support
| Ada | L40S, L4 | sm_89 | All backends
| Hopper | H100 | sm_90a | All backends (required for ThunderKittens)
| Ampere | A100, A10G | sm_80 | All backends except ThunderKittens
| Turing | T4 | sm_75 | All backends except ThunderKittens

The `gpu_arch` parameter sets the `TORCH_CUDA_ARCH_LIST` environment variable during kernel compilation, enabling architecture-specific optimizations.
