The `Model` class inherits from `torch.nn.Module` and implements the operation to be optimized. It must define:

| | Method | Purpose | Returns
| `__init__(self, ...)` | Initialize parameters, layers, and constants | None
| `forward(self, ...)` | Execute the operation on input tensors | Output tensor(s)

### Input Generation Functions

Two functions define how to instantiate and execute the model:

`get_init_inputs() -> list`

- Returns a list of arguments for `Model.__init__(...)`

- Used to construct the model: `model = Model(*get_init_inputs())`

- Returns empty list `[]` if no initialization arguments required

- Example: KernelBench/level1/50_conv_standard_2D__square_input__square_kernel.py21-22 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/KernelBench/level1/50_conv_standard_2D__square_input__square_kernel.py#L21-L22]

`get_inputs() -> list`

- Returns a list of input tensors for the forward pass

- Used to execute: `output = model(*get_inputs())`

- Tensors are typically on CUDA with appropriate dtype

- Example: KernelBench/level1/97_ScaledDotProductAttention.py17-21 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/KernelBench/level1/97_ScaledDotProductAttention.py#L17-L21]

## File Naming Convention

KernelBench uses a structured naming convention for all problem files:

```
`<numerical_prefix>_<descriptive_name>.py
`

| | Component | Description | Example
| Numerical prefix | 1-indexed problem ID within level | `97`, `50`, `38`
| Descriptive name | Human-readable operation description | `ScaledDotProductAttention`, `conv_standard_2D__square_input__square_kernel`
| Extension | Python source file | `.py`

Naming Patterns:

- Basic operations: `23_Softmax.py`, `33_BatchNorm.py`, `26_GELU_.py`

- Convolutions: `50_conv_standard_2D__square_input__square_kernel.py`

- Includes dimensionality, input/kernel shape

- Double underscores separate major components

- Composite operations: `38_ConvTranspose3d_AvgPool_Clamp_Softmax_Multiply.py`

- Operations listed in execution order

- PascalCase for each operation

The numerical prefix ensures deterministic ordering when loading datasets src/dataset.py54-55 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/src/dataset.py#L54-L55]

The `Problem` dataclass provides a `hash` property for content-based identification src/kernelbench/dataset.py53-63 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/src/kernelbench/dataset.py#L53-L63]:

`Problem.hash -> str`

Computes an MD5 hash of the problem's source code, excluding comments and whitespace:

```

`get_code_hash(code: str) -> str`

Standalone function for computing code hashes src/kernelbench/dataset.py70-76 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/src/kernelbench/dataset.py#L70-L76]:

- Removes multi-line comments (`"""..."""` and `'''...'''`)

- Removes inline comments (`#...`)

- Strips all whitespace

- Computes MD5 hash of cleaned code

Use cases:

- Detecting functionally identical problems across dataset versions

- Caching compiled kernels by content hash

- Tracking problem evolution in version control

- Comparing local vs HuggingFace versions
