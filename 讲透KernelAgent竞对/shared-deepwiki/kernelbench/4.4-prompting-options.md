This page documents KernelBench's three prompting strategies: zero-shot, one-shot, and few-shot. These options control whether and how many example kernel optimizations are included in prompts sent to LLMs. The strategy significantly impacts generation quality and is configured via the `prompt_option` parameter.

For information about the overall prompt construction pipeline, see Prompt Construction System [/ScalingIntelligence/KernelBench/4.1-prompt-construction-system]. For backend-specific prompt variations, see Backend-Specific Prompts [/ScalingIntelligence/KernelBench/4.2-backend-specific-prompts]. For GPU-specific prompt enhancements, see Hardware-Aware Prompting [/ScalingIntelligence/KernelBench/4.3-hardware-aware-prompting].

## Overview

Prompting options determine the learning strategy by controlling example inclusion in prompts. Each option is defined in the TOML configuration at src/prompts/prompts.toml166-182 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/src/prompts/prompts.toml#L166-L182] and specifies which template components to assemble and whether examples are required.

| | Option | Examples Provided | Use Case | Components Included
| `zero_shot` | None | Model must infer from description only | `problem_statement`, `arch_block`, `precision_note`, `instruction`
| `one_shot` | Single example | Default strategy, balances context with efficiency | All zero-shot components + `examples_block`
| `few_shot` | Multiple examples (3+ for CUDA) | Maximum context, better for complex patterns | All one-shot components (uses multiple examples)

## Zero-Shot Prompting

Zero-shot prompting provides no example kernel optimizations. The LLM must infer the task entirely from the problem statement, architecture description, and instructions.

### Configuration

The zero-shot option is defined at src/prompts/prompts.toml168-170 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/src/prompts/prompts.toml#L168-L170]:

```

Note the absence of `requires_example` and `examples_block` in the component list. This produces the most minimal prompt.

### Component Composition

The zero-shot prompt includes only:

- `problem_statement`: Task description with backend-specific terminology (e.g., "custom CUDA operators")

- `arch_block`: The reference PyTorch architecture to optimize

- `precision_note`: Target precision specification (FP32/FP16/BF16)

- `instruction`: Output requirements ("Output the new code in codeblocks...")

### When to Use Zero-Shot

Zero-shot is appropriate when:

- Testing model's intrinsic kernel optimization knowledge

- Minimizing token consumption (shortest prompts)

- Evaluating baseline capability without guidance

- Models have been pre-trained extensively on kernel code

Trade-off: Lower success rates but faster inference and lower cost.

### When to Use One-Shot

One-shot is recommended when:

- Establishing baseline performance (default for reported results)

- Balancing example guidance with token efficiency

- Models need syntax demonstration for inline kernel embedding

- Backend uses unfamiliar DSL (Triton, CuTe, TileLang)

Trade-off: Better success rates than zero-shot with moderate token cost.

### When to Use Few-Shot

Few-shot is beneficial when:

- Optimizing Level 2/3 problems requiring fusion or algorithmic changes

- Model needs diverse pattern examples (element-wise, fusion, attention)

- Token budget permits longer prompts (3x token cost vs one-shot)

- Maximizing success rate is priority over inference speed

Trade-off: Highest success rates but increased token cost and latency.

## Comparison Table

The following table summarizes key differences between prompting options:

| | Attribute | Zero-Shot | One-Shot | Few-Shot
| Token Count | ~500 tokens | ~1,200 tokens | ~3,500 tokens (CUDA)
| Example Count | 0 | 1 | 3 (CUDA), 1 (fallback)
| Success Rate | Lowest | Medium | Highest
| Inference Time | Fastest | Medium | Slowest
| Backend Coverage | All backends | All backends | CUDA only (others fall back)
| Use Case | Model capability testing | Default baseline | Complex optimizations
| Component Count | 4 | 5 (adds `examples_block`) | 5 (with multiple examples)
| CLI Flag | `prompt_option=zero_shot` | `prompt_option=one_shot` | `prompt_option=few_shot`
| Default | No | Yes | No

### Common Errors

| | Error | Cause | Solution
| `KeyError: Unknown option: fewshot` | Typo in option name | Use underscore: `few_shot`
| `ValueError: Invalid prompt_option 'oneshot'` | Missing underscore | Use `one_shot`
| `No example entries could be constructed` | Missing example files | Check file paths in TOML
