## Overview

This document details the Level 1 component of KernelBench, which consists of 100 foundational atomic operations—the fundamental building blocks of neural networks. These operations represent individual tensor operations commonly used in deep learning frameworks, including convolutions, attention mechanisms, normalization layers, pooling operations, and loss functions. Level 1 serves as the baseline difficulty tier for evaluating LLM-generated GPU kernels.

For information about composite operation patterns, see Level 2: Composite Operations [/ScalingIntelligence/KernelBench/5.3-level-2:-composite-operations]. For complete model architectures, see Level 3: Complete Architectures [/ScalingIntelligence/KernelBench/5.4-level-3:-complete-architectures].

## Problem Files

Level 1 problems are stored in the `KernelBench/level1/` directory. Each problem follows a standardized file naming convention:

```
`{ID}_{Operation_Name}.py
`

The ID ranges from 1 to 100, and the operation name uses underscores to separate words. Each file contains:

- A `Model` class inheriting from `nn.Module`

- A `get_inputs()` function returning test input tensors

- A `get_init_inputs()` function returning model initialization parameters

## Evaluation Methodology

Level 1 operations are evaluated using the `eval_single_kernel()` function in `src/eval.py`. The evaluation has two phases:

### Phase 1: Correctness Check

The system runs multiple trials (default: 10) with randomly generated inputs:

- Execute reference PyTorch implementation

- Execute generated custom kernel

- Compare outputs using `torch.allclose()` with configurable tolerances

- Verdict: All trials must pass for correctness

Correctness Check Flow

```

### Phase 2: Performance Measurement

For kernels that pass correctness:

- Warmup: 10 warmup runs to stabilize GPU state

- Timing: Measure execution time over multiple trials using CUDA events

- Statistics: Calculate mean, std, min, max runtime

- Speedup: Compare against baseline timing from `baseline_time_{backend}.json`

Performance Metrics

- `runtime_ms`: Mean execution time in milliseconds

- `speedup`: Ratio of baseline time to custom kernel time

- `fast_p`: Binary indicator if speedup ≥ p (e.g., fast_1 means speedup ≥ 1.0)

### Baseline Timing Files

Baseline performance is pre-computed for different PyTorch configurations:

| | Baseline File | Configuration
| `baseline_time_torch.json` | PyTorch eager mode
| `baseline_time_torch_compile_inductor_default.json` | torch.compile with default inductor
| `baseline_time_torch_compile_cudagraphs.json` | torch.compile with CUDA graphs

Each baseline contains mean/std/min/max timing for all 100 Level 1 operations.

## Convolution Operation Variants

Convolutions comprise the largest category in Level 1 with 34 different variants (IDs: 54-87):

### Standard Convolutions

- Conv1D: 1D temporal convolutions

- Conv2D: 2D spatial convolutions (most common for images)

- Square input/kernel: KernelBench/level1/50_conv_standard_2D__square_input__square_kernel.py1-22 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/KernelBench/level1/50_conv_standard_2D__square_input__square_kernel.py#L1-L22]

- Rectangular variants

- Conv3D: 3D volumetric convolutions

### Specialized Convolutions

- Depthwise Convolution: Separate convolution per input channel

- Example: KernelBench/level1/83_conv_depthwise_2D_square_input_asymmetric_kernel.py1-47 [https://github.com/ScalingIntelligence/KernelBench/blob/2f65279d/KernelBench/level1/83_conv_depthwise_2D_square_input_asymmetric_kernel.py#L1-L47]

- Pointwise Convolution: 1x1 kernel for channel mixing

- Transposed Convolution: Learnable upsampling (deconvolution)

### Convolution Parameter Variations

Each convolution type tests different combinations of:

- Kernel sizes: Square (3x3, 5x5, 11x11) and asymmetric (3x1, 1x3)

- Strides: 1, 2, 4 for different downsampling rates

- Padding: Valid, same, custom padding values

- Dilation: Standard and dilated (atrous) convolutions

- Groups: Standard (groups=1) and grouped convolutions

## Conclusion

Level 1 operators represent the fundamental building blocks of neural networks and serve as the entry point for evaluating an LLM's ability to generate efficient CUDA kernels. Success at Level 1 is a prerequisite for handling more complex patterns and architectures in higher levels of the KernelBench benchmark.

By systematically testing a wide range of individual operators, KernelBench provides a comprehensive assessment of an LLM's understanding of parallel programming, CUDA optimization techniques, and deep learning operations.
