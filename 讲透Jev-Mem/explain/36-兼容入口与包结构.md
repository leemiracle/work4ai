## 角色定位

这一族回答一个问题：**旧入口如何零成本指向新包**。Jev-Mem 从根目录平铺脚本搬进 jev_mem/ 包，还整体改过名（sys1mem 是前身铁证，docs/architecture.md:78）。14 个文件构成"新骨架+旧入口"兼容层：六个根 shim 转发旧名、两个 PEP 562 惰性 barrel 分任产品面与研究面、四个一行 __init__.py 定义子包身份、setup.sh 引导环境；唯一原则是实现只在 jev_mem/ 与 memory/ 存一份，旧名字全是别名。

## 内部结构

### 六个根目录 shim：同一模板六次实例化

同构四步：docstring 声明目标 → import canonical → __main__ 分支执行 → else 分支装 sys.modules 别名。映射：main.py→jev_mem.cli（main.py:3，编排入口）、jev_mem_demo.py→jev_mem.demo（jev_mem_demo.py:3）、load_dataset.py→jev_mem.datasets.locomo（load_dataset.py:3）、load_longmemeval.py→jev_mem.datasets.longmemeval（load_longmemeval.py:3）、test_fixed_memory.py→jev_mem.benchmarks.locomo（test_fixed_memory.py:3）、test_longmemeval_chunked.py→jev_mem.benchmarks.longmemeval（test_longmemeval_chunked.py:3），被 tests/test_project_layout.py:11-18 参数化钉死。

关键机制 `sys.modules[__name__] = _implementation`（load_dataset.py:9）：import 后 shim 模块对象被整个换成 canonical 模块，类身份、模块全局、monkeypatch 目标天然保持（注释明言，jev_mem_demo.py:8、load_longmemeval.py:8）；脚本用法走 __main__ 直调 canonical main()（main.py:5-6、test_longmemeval_chunked.py:5-6）。

### jev_mem 门面：lazy barrel 与 -m 入口

jev_mem/__init__.py 的 _EXPORTS 只登记四名（jev_mem/__init__.py:7-12）：JevMemSystem 家在 jev_mem.system，JevMemConfig/MemoryBuilder/QueryEngine 全住 memory 包——jev_mem 是编排壳。__getattr__ 按表导入并缓存进 globals()，首次访问后零开销（jev_mem/__init__.py:15-20）。jev_mem/__main__.py 是新世界的等价物：两行转发（jev_mem/__main__.py:2）加 SystemExit 包装（jev_mem/__main__.py:4-5），支撑 python -m jev_mem。

### memory/__init__.py：研究 API 的 lazy barrel + 环境哨兵

三层：darwin 哨兵对 OMP/MKL setdefault，在 torch/FAISS 载入原生 OpenMP 前生效（memory/__init__.py:15-17）；_MODULES 把 13 个子模块映射到空格分隔导出名（memory/__init__.py:19-28）；__getattr__ 线性查找、命中即导入并缓存（memory/__init__.py:31-37），__all__ 罗列 32 名。顶层注释写死惰性目标：公共导入不初始化 API client、不下载 metric 模型（memory/__init__.py:7-8）。

### 四个一行 __init__：docstring 即包宪法

都是一行 docstring、零导出。jev_mem/benchmarks/__init__.py:1 双重定位："Benchmark command-line runners"+"regression tests live in tests/"——是什么与不是什么一句说完；jev_mem/datasets/__init__.py:1 定位为会话记忆基准的 schema 与 loader；scripts/__init__.py:1 定位为仓库维护诊断工具；utils/__init__.py:1 定位为共享 provider 适配器与评测工具。口径差异：packages.find 白名单只含 jev_mem、jev_mem.*、memory、utils（pyproject.toml:38），scripts 不进 wheel、只进源码发布集——"公开源码"与"可安装产物"两口径刻意分离。

### setup.sh：十六行引导

严格模式加 cd 脚本目录；PYTHON_BIN 默认 python3.11、断言至少 3.11（setup.sh:5-6）；建 .venv 装 requirements-dev.txt，其首行 -r requirements.txt 级联装全量依赖（setup.sh:7-9）；`pip install --no-deps -e .` 是关键决策——本体 editable 安装但禁止二次依赖解析（setup.sh:10）；缺 .env 时复制 .env.example 且 umask 077 保密钥仅属主可读（setup.sh:11-13）；收尾提示离线 demo 与填 key。

## 外部连接

grep 实测三层。打包层：六 shim 名全列进 py-modules（pyproject.toml:34）、收进 sdist 与发布集（MANIFEST.in:42-45）；四个子包 init 同样两头登记，utils/__init__.py:1 的包进 wheel、scripts/__init__.py:1 所在包只进源码发布。测试层：模块身份 is 断言；裸 pickle GLOBAL 字节流验证旧序列化对象仍解析——pickle 按 sys.modules 查模块，别名让旧缓存起死回生（tests/test_project_layout.py:23-29）；对 main.py 跑 --help 断言无 sys1 残留（tests/test_public_release.py:140-147）。barrel 分工：jev_mem 门面零副作用导入被子进程测试钉死（tests/test_project_layout.py:32-40）；memory barrel 业务消费稀少，业务代码直连子模块；setup.sh 与四个 console scripts（pyproject.toml:27-31）构成安装故事。

## 数据流

兼容导入流：`from load_dataset import QA` → shim 执行 → import canonical（load_dataset.py:3）→ 别名替换 → 拿到 canonical QA；旧脚本 `python test_fixed_memory.py` 走 __main__ 直调（test_fixed_memory.py:5-6）。惰性流：`from jev_mem import JevMemSystem` → __getattr__ 命中 → import jev_mem.system 才拉起 memory 全家（jev_mem/system.py:5-7）→ 类缓存进 globals()。引导流：断言版本 → venv → requirements 级联 → editable 本体 → umask 077 生成 .env。

## 设计决策

决策一：**sys.modules 别名替代 re-export**——`from jev_mem.cli import *` 会造两份命名空间（monkeypatch 打旧名不生效、pickle 因 __module__ 与路径不一致而失败），别名让新旧名是同一模块对象（main.py:8）；代价是 shim 不能携带额外属性，故严格九行内。决策二：**双层惰性 barrel**——memory/__init__.py:31-37（研究 API）与 jev_mem/__init__.py:15-20（产品门面）同构分工，理由同一条：import 副作用必须为零，是缺 key 环境可导入与测试启动速度的硬需求。决策三：**一行 __init__ 的极简定位语义**——docstring 即宪法，"是什么/不是什么"一句说完（jev_mem/benchmarks/__init__.py:1 是范本），包身份另有 packages.find 白名单这重机器定义。

批判点：其一，**双版本号双出口**——jev_mem/__init__.py:4 与 memory/__init__.py:79 各持 __version__，三个类双 barrel 重复导出，一致性靠 is 断言而非结构（tests/test_public_release.py:128）；其二，memory barrel __getattr__ 未命中扫完 13 键且未定义 __dir__，dir(memory) 看不到惰性名字；其三，darwin 哨兵只在 memory 先于 torch 导入时生效（memory/__init__.py:15-17），保护是概率性的；其四，"wrapper 不长胖"只有 docs 约定（docs/architecture.md:73-74）没有机械闸；其五，setup.sh 默认解释器钉 3.11 而断言只查下限（setup.sh:5-6），默认值与门槛有轻微口径差。
