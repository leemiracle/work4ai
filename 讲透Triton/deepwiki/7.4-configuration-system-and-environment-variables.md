## Purpose and Scope

 The Configuration System in Triton provides mechanisms for controlling compiler behavior, debugging output, optimization levels, and runtime characteristics through environment variables, Python-based knobs, and build-time settings. This system enables users to customize compilation without modifying source code and allows developers to inspect and debug the compiler pipeline.

 For information about the JIT caching mechanism that is affected by cache-invalidating environment variables, see [JIT Compilation and Caching](https://deepwiki.com/triton-lang/triton/2.2-jit-compilation-and-caching).

 
## Overview

 The Triton configuration system consists of three primary mechanisms:

 
 - **Environment Variables**: Control compilation, debugging, and runtime behavior.
 - **Python Knobs System**: Runtime configuration accessible from Python code via `triton.knobs`.
 - **Build-Time Configuration**: Settings that affect how Triton itself is built (e.g., `MAX_JOBS`, `TRITON_BUILD_WITH_CCACHE`).
 
 The system distinguishes between **cache-invalidating** and **cache-neutral** environment variables. Cache-invalidating variables affect the compiled output and must be included in the cache key computation, while cache-neutral variables only affect tooling behavior without changing the generated code.

## Environment Variable System

 
### Python Knobs Interface

 The `triton.knobs.py` module defines a descriptor-based system for accessing environment variables with proper type casting (bool, int, str) and default values. It uses `triton._C.libtriton.getenv` and `getenv_bool` for underlying access.

 
| Class | Functionality | Code Reference |
|---|---|---|
| env_base | Generic base for environment descriptors | python/triton/knobs.py68-100 |
| env_bool | Handles getenv_bool for truthy/falsy values | python/triton/knobs.py125-133 |
| env_int | Parses environment strings into integers | python/triton/knobs.py135-149 |
| env_nvidia_tool | Locates and versions binaries like ptxas or ptxas-blackwell | python/triton/knobs.py194-219 |

 **Sources:** [python/triton/knobs.py15-150](https://github.com/triton-lang/triton/blob/f893845b/python/triton/knobs.py#L15-L150) [python/triton/knobs.py194-219](https://github.com/triton-lang/triton/blob/f893845b/python/triton/knobs.py#L194-L219)

| TRITON_OVERRIDE_ARCH | Manually sets the GPU architecture for compilation | README.md176-178 |

### Cache-Neutral Environment Variables

 These variables control observability and do not affect the kernel binary hash.

 
| Variable | Purpose |
|---|---|
| TRITON_HOME | Changes the location of the .triton directory for cache and downloads |
| LLVM_BUILD_DIR | Specifies the path to a custom LLVM build directory |
| TRITON_BUILD_WITH_CLANG_LLD | Instructs the build system to use clang and lld |
| TRITON_BUILD_WITH_CCACHE | Enables ccache during the Triton build process |

## Build System Variables

 Build-time variables are set during `pip install` or `cmake` invocation.

 
| Variable | Description | Default |
|---|---|---|
| TRITON_BUILD_WITH_CLANG_LLD | Use clang and lld for faster builds | false |
| TRITON_BUILD_WITH_CCACHE | Enables ccache for C++ compilation | false |
| TRITON_HOME | Location for cache and build downloads | ~/.triton |
| MAX_JOBS | Limits the number of parallel compilation jobs | N/A |
| LLVM_INCLUDE_DIRS | Path to custom LLVM headers | N/A |
| LLVM_LIBRARY_DIR | Path to custom LLVM libraries | N/A |
| LLVM_SYSPATH | Base path for custom LLVM installation | N/A |

## Specialized Configuration Systems

 
### Specialized Kernel Generation

 The `triton_kernels` library uses a specialization system where kernels are dynamically created based on constants and tuples. While not strictly environment variables, these "knobs" control kernel generation at a higher level.

 
| Component | Functionality | Code Reference |
|---|---|---|
| specialize | Dynamically creates specialized Triton kernels from source strings | python/triton_kernels/triton_kernels/specialize.py81-175 |
| define_kernel | Low-level utility to exec kernel source and wrap in JITFunction | python/triton_kernels/triton_kernels/specialize.py32-65 |
| cacheable | Decorator to ensure dynamically defined kernels interact with Triton cache | python/triton_kernels/triton_kernels/specialize.py11-29 |

 **Sources:** [python/triton_kernels/triton_kernels/specialize.py11-175](https://github.com/triton-lang/triton/blob/f893845b/python/triton_kernels/triton_kernels/specialize.py#L11-L175)

 
### LLVM Build Metadata

 The build system tracks the specific LLVM version and repository via a JSON configuration file.

 
 - **File**: `cmake/llvm-build-info.json` (or `cmake/llvm-info.json`)
 - **Key Fields**: `llvm_hash`, `repository`, `build_number`
 
 **Sources:** [cmake/llvm-build-info.json1-5](https://github.com/triton-lang/triton/blob/f893845b/cmake/llvm-build-info.json#L1-L5) [.github/workflows/llvm-build.yml62-71](https://github.com/triton-lang/triton/blob/f893845b/.github/workflows/llvm-build.yml#L62-L71)
