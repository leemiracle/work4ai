## Purpose and Scope

 The Code Generator is responsible for transforming Python Abstract Syntax Trees (AST) into Triton's MLIR representation (TTIR - Triton Intermediate Representation). This is the first major compilation stage that bridges user-written Python code and the compiler's intermediate representation.

 This page covers the `CodeGenerator` class and the `ast_to_ttir` function that orchestrate AST traversal, operation emission, and control flow handling. For information about the semantic layer that provides type checking and operation lowering, see [2.3 Semantic Analysis and Type System](https://github.com/triton-lang/triton/blob/f893845b/2.3 Semantic Analysis and Type System) For the subsequent compilation stages that lower TTIR to GPU code, see [1.1 System Architecture and Compilation Flow](https://github.com/triton-lang/triton/blob/f893845b/1.1 System Architecture and Compilation Flow)

 **Sources:** [python/triton/compiler/code_generator.py1-1400](https://github.com/triton-lang/triton/blob/f893845b/python/triton/compiler/code_generator.py#L1-L1400)

## Variable Scoping and Name Resolution

 The `CodeGenerator` maintains dictionaries for variable management. The name resolution order is implemented to prioritize local definitions before falling back to global or builtin scopes.

 
### Scoping Mechanism

 
```

```

 **Scope Definitions:**

 
 - **`lscope`**: All local variables currently in scope (dict mapping name → value). [python/triton/compiler/code_generator.py332-340](https://github.com/triton-lang/triton/blob/f893845b/python/triton/compiler/code_generator.py#L332-L340)
 - **`local_defs`**: Variables defined in the current basic block, used for SSA construction. [python/triton/compiler/code_generator.py131-132](https://github.com/triton-lang/triton/blob/f893845b/python/triton/compiler/code_generator.py#L131-L132)

## Operation Emission

 Operations are emitted through two layers: the `builder` creates raw MLIR operations, while the `semantic` layer provides high-level, type-aware operation construction.

 
### Example: Binary Operation Translation

 For the Python expression `x + y`:

 
 - **AST Visit:** `visit_BinOp` is called with the `+` operator. [python/triton/compiler/code_generator.py750-755](https://github.com/triton-lang/triton/blob/f893845b/python/triton/compiler/code_generator.py#L750-L755)
 - **Semantic Layer:** Calls `semantic.add(x, y)`. [python/triton/compiler/code_generator.py774-775](https://github.com/triton-lang/triton/blob/f893845b/python/triton/compiler/code_generator.py#L774-L775)
 - **Type Checking:** `computation_type_impl` performs implicit type promotion (e.g., int32 + int64 → int64). [python/triton/language/semantic.py68-116](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L68-L116)
 - **Builder Dispatch:** Based on operand types, the builder creates the appropriate IR (e.g., `arith.addi` for integers or `arith.addf` for floats). [python/triton/language/semantic.py230-259](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L230-L259)

## Summary

 The Code Generator serves as the crucial bridge between Python syntax and MLIR semantics:

 
 - **Traverses** Python AST using the visitor pattern.
 - **Resolves** names through a hierarchical scope system (`lscope`, `gscope`).
 - **Emits** type-safe MLIR operations via the `TritonSemantic` layer.
 - **Translates** control flow to SCF dialect operations (`scf.if`, `scf.for`, `scf.while`).
 - **Manages** function inlining and call graph construction.
 - **Tracks** source locations for precise error reporting.
 
 The resulting TTIR module is ready for subsequent optimization passes in the Triton compiler pipeline.
