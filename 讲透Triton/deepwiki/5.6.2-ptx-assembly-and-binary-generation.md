## Purpose and Scope

 This page documents the final stages of the NVIDIA CUDA compilation pipeline: the translation of LLVM IR to PTX assembly and the subsequent assembly of PTX into executable cubin binaries. This covers the `make_ptx()` and `make_cubin()` methods in the CUDA backend, the invocation of LLVM's code generation machinery, and the `ptxas` assembler integration.

 For information about the earlier stages that produce LLVM IR, see [TritonGPU to LLVM Lowering Framework](https://deepwiki.com/triton-lang/triton/5.1-tritongpu-to-llvm-lowering-framework). For NVIDIA-specific optimizations applied before reaching LLVM IR, see [NVIDIA-Specific Optimizations and Passes](https://deepwiki.com/triton-lang/triton/5.6.1-nvidia-specific-optimizations-and-passes).

### Version and Target Rewriting

 The PTX version and target SM are injected via regex replacement:

 
| Directive | Regex Pattern | Replacement |
|---|---|---|
| .version | \.version \d+\.\d+ | .version {ptx_major}.{ptx_minor} |
| .target | \.target sm_\d+ | .target sm_{capability} |

 These replacements ensure the PTX matches the requested target configuration even if LLVM's PTX backend has version limitations.

## Debug Information and LLVM Pass Pipeline

 The backend utilizes specialized LLVM passes to generate and preserve debug information throughout the compilation process.

 
### LLVM Debug Info Passes

 The C++ backend initializes several passes specifically for debug information:

 
 - **LLVMDIScopePass**: Adds debug info scopes to `LLVM::LLVMFuncOp` operations. It handles inlined functions by creating `LLVM::DISubprogramAttr` and `LLVM::DICompileUnitAttr` based on the operation's `Location` [lib/Target/LLVMIR/LLVMDIScope.cpp26-147](https://github.com/triton-lang/triton/blob/f893845b/lib/Target/LLVMIR/LLVMDIScope.cpp#L26-L147)
 - **LLVMDILocalVariablePass**: Fuses local variable information into the LLVM IR. It inserts `LLVM::DbgValueOp` (the `llvm.intr.dbg.value` intrinsic) after operations that define values, associating them with `LLVM::DILocalVariableAttr` [lib/Target/LLVMIR/LLVMDILocalVariable.cpp32-96](https://github.com/triton-lang/triton/blob/f893845b/lib/Target/LLVMIR/LLVMDILocalVariable.cpp#L32-L96)
 
 
### MIR Dump and Scheduling DAGs

 For advanced hardware-level debugging, Triton supports dumping Machine IR (MIR) and Scheduling DAGs:

 
 - **TRITON_DUMP_MIR**: When this environment variable is set, the compiler dumps MIR content into files, including Scheduling Units (SU) and predecessor/successor info [python/src/llvm.cc159-183](https://github.com/triton-lang/triton/blob/f893845b/python/src/llvm.cc#L159-L183)
 - **Machine Scheduler Control**: The compiler can force LLVM to stop after the machine-scheduler and print DAGs using `ScopedLLVMOption` for options like `stop-after` and `misched-print-dags` [python/src/llvm.cc186-188](https://github.com/triton-lang/triton/blob/f893845b/python/src/llvm.cc#L186-L188)
 
 Sources: [python/src/llvm.cc152-195](https://github.com/triton-lang/triton/blob/f893845b/python/src/llvm.cc#L152-L195) [lib/Target/LLVMIR/LLVMDIScope.cpp26-147](https://github.com/triton-lang/triton/blob/f893845b/lib/Target/LLVMIR/LLVMDIScope.cpp#L26-L147) [lib/Target/LLVMIR/LLVMDILocalVariable.cpp32-96](https://github.com/triton-lang/triton/blob/f893845b/lib/Target/LLVMIR/LLVMDILocalVariable.cpp#L32-L96)

### Capability-Specific Features

 PTX features are determined based on capability:

 
 - Capabilities are passed through to determine PTX version support via `ptx_get_version()`.
 - The `get_features()` function translates this to LLVM feature strings (e.g., `+ptx86`).
