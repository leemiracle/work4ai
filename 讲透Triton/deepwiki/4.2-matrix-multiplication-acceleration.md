## Purpose and Scope

 This document describes the `AccelerateMatmul` compiler pass that transforms generic `tt.dot` and `tt.dot_scaled` operations into hardware-specific MMA (Matrix Multiply-Accumulate) operations. The pass is responsible for:

 
 - Selecting the appropriate MMA version (v1, v2, v3, or v5) based on GPU compute capability and operation characteristics.
 - Creating `NvidiaMmaEncodingAttr` or `AMDMfmaEncodingAttr` with optimal instruction shapes and warp configurations.
 - Converting operand layouts to formats required by MMA instructions, including shared memory and TMEM (Tensor Memory) allocations.
 - Handling both standard and mixed-precision scaled matrix multiplication operations.
 
 For operand layout optimization after MMA acceleration, see [Dot Operand Optimization](https://deepwiki.com/triton-lang/triton/4.3-dot-operand-optimization). For the actual lowering of MMA operations to PTX/LLVM, see [MMA and Dot Operation Lowering](https://deepwiki.com/triton-lang/triton/5.5-mma-and-dot-operation-lowering).

| 120 - 129 | v2 | Consumer Blackwell |

## Warp Distribution Strategy

 The pass computes optimal warp distribution across the output tile dimensions to balance register pressure and maximize parallelism.

 
### NVIDIA MMAv2/v3 Warp Distribution

 The algorithm prioritizes balancing `repM` and `repN` because register pressure is sensitive to the product of repetitions across dimensions.

 
 - **Chained Dot Optimization:** If a dot operation's result is consumed by another dot (e.g., in Attention), the pass prefers assigning warps to a single axis (usually `[numWarps, 1]`) to allow reductions within the same warp. `warpsPerTileV2` uses `getSlice` to detect these chains.
 
 Sources: `lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp:85-148`, `lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp:98-119`

 
## Encoding and Layout Creation

 
### NVIDIA MMA Encoding

 The `NvidiaMmaEncodingAttr` captures the version, instruction shape, and warp distribution. For MMAv3 (Hopper), instruction shapes like `[16, 16, 16]`, `[16, 64, 16]`, or `[16, 32, 16]` are selected based on data types and tensor shapes.

 Sources: `test/TritonGPU/accelerate-matmul.mlir:3-5`

 
## Operand Conversion and Mixed Precision

 
### Shared Memory and TMEM Allocations

 MMA instructions often require operands to be in specific memory spaces (Shared Memory or Blackwell's Tensor Memory - TMEM).

 
 - **`getSharedMemoryMMAOperand`:** Creates a shared memory allocation (`NVMMASharedEncodingAttr`) for a dot operand. It determines the memory order and handles transposes required by the hardware.
 - **MMAv5 (Blackwell) TMEM:** The pass lowers `tt.dot` to `ttng.tc_gen5_mma` which operates on `tensor_memory`. This requires `ttng.tmem_alloc` and `ttng.tmem_store` operations.
 
 Sources: `lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp:153-212`, `lib/Dialect/TritonNvidiaGPU/Transforms/TensorMemoryAllocation.cpp:25-31`

 
### Mixed-Precision and Scaled Dots

 Blackwell introduces hardware support for scaled matrix multiplication (`tc_gen5_mma_scaled`). The `MMALowering` pass handles converting scales from shared memory to TMEM using `lowerScaleToTmem`.

 Sources: `lib/Dialect/TritonNvidiaGPU/Transforms/MMALowering.cpp:56-114`, `test/TritonNvidiaGPU/mma_lowering.mlir:10-29`

 
## Optimization Passes and Pattern Implementation

 
### Accumulator Initialization Optimization

 The `OptimizeAccumulatorInitPass` looks for `tt.dot` or `ttng.tc_gen5_mma` operations where the accumulator is initialized to zero. Instead of loading zeros into registers/TMEM, it sets the `useAccumulator` flag to false (effectively `D = A*B` instead of `D = A*B + C`), saving memory bandwidth and initialization instructions.

 Sources: `lib/Dialect/TritonGPU/Transforms/OptimizeAccumulatorInit.cpp:17-55`, `lib/Dialect/TritonGPU/Transforms/OptimizeAccumulatorInit.cpp:124-136`

 
### TMEM Allocation Hoisting

 The `HoistTMEMAlloc` pass optimizes Blackwell TMEM usage by hoisting allocations out of loops. This is critical for performance as TMEM is a limited hardware resource. It uses a token-based dependency system (`ttg.async.token`) to ensure correct synchronization between asynchronous MMA operations and TMEM accesses.

 Sources: `lib/Dialect/TritonGPU/Transforms/HoistTMEMAlloc.cpp:103-118`, `test/TritonGPU/hoist-tmem-alloc.mlir:10-23`

 
### Dot Operand Optimization

 The `OptimizeDotOperands` pass applies patterns to reduce layout conversion overhead:

 
| Pattern Name | Purpose |
|---|---|
| SwizzleShmemConvert | Replaces convert_layout with a swizzled shared memory local_alloc + local_load. |
| FuseTransMMAV3Plus | Folds a tt.trans into the local_alloc by inferring a transposed shared memory layout. |
| ReshapeMemDesc | Folds a tt.reshape into a memdesc_reshape for MMAv3/v5 operands. |
