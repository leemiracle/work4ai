## Purpose and Scope

 This document describes the NVIDIA CUDA backend implementation in Triton, which handles the compilation of Triton programs to NVIDIA GPU binaries. The CUDA backend is responsible for transforming Triton IR through multiple stages—from high-level Triton IR (TTIR) to TritonGPU IR (TTGIR), then to LLVM IR, PTX assembly, and finally to CUBIN binaries executable on NVIDIA GPUs.

 For details on the LLVM lowering patterns and conversion framework, see [TritonGPU to LLVM Lowering Framework](https://deepwiki.com/triton-lang/triton/5.1-tritongpu-to-llvm-lowering-framework). For NVIDIA-specific optimizations like Hopper warp specialization or Blackwell TMEM, see [NVIDIA-Specific Optimizations and Passes](https://deepwiki.com/triton-lang/triton/5.6.1-nvidia-specific-optimizations-and-passes). For PTX assembly and binary generation details, see [PTX Assembly and Binary Generation](https://deepwiki.com/triton-lang/triton/5.6.2-ptx-assembly-and-binary-generation).

 **Sources:** [third_party/nvidia/backend/compiler.py1-551](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L1-L551)

 
## Backend Architecture

 The CUDA backend is implemented by the `CUDABackend` class in [third_party/nvidia/backend/compiler.py166-551](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L166-L551) which inherits from `BaseBackend` and provides NVIDIA-specific compilation logic. The backend is selected when the target GPU has backend type `'cuda'` via the `supports_target()` method [third_party/nvidia/backend/compiler.py170-171](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L170-L171)

## Compilation Options

 The `CUDAOptions` dataclass [third_party/nvidia/backend/compiler.py109-162](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L109-L162) defines all configurable parameters for CUDA compilation. These options control warp configuration, memory staging, debugging, and architecture-specific features.

 
| Option | Type | Default | Description |
|---|---|---|---|
| num_warps | int | 4 | Number of warps per CTA (must be power of 2) |
| num_ctas | int | 1 | Number of CTAs (requires SM90+ for >1) |
| num_stages | int | 3 | Software pipelining stages |
| warp_size | int | 32 | Threads per warp (NVIDIA constant) |
| maxnreg | Optional[int] | None | Max 32-bit registers per thread |
| ptx_version | int | None | PTX ISA version (auto-detected) |
| ptx_options | Optional[str] | From knobs | Additional ptxas options |
| enable_fp_fusion | bool | True | Enable FP multiply-add fusion |
| launch_cooperative_grid | bool | False | Use cooperative kernel launch |
| supported_fp8_dtypes | Tuple[str] | ("fp8e5", "fp8e4b15") | Supported FP8 formats |
| default_dot_input_precision | str | "tf32" | Tensor core precision mode |
| allowed_dot_input_precisions | Tuple[str] | ("tf32", "tf32x3", "ieee", "bf16x3", "bf16x6") | Available precision modes |
| debug | bool | False | Enable debug information |
| arch | str | None | Target architecture (e.g., "sm80") |
| instrumentation_mode | str | "" | Modes like "gsan", "consan", or "iisan" |

 **Sources:** [third_party/nvidia/backend/compiler.py109-162](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L109-L162)

### TTIR Stage: High-Level Optimization

 The `make_ttir()` method [third_party/nvidia/backend/compiler.py230-245](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L230-L245) applies high-level optimizations on Triton IR. This includes inlining, rewriting tensor pointers, and basic canonicalization. For architectures older than SM90, it converts tensor descriptors to pointers [third_party/nvidia/backend/compiler.py237-238](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L237-L238)

 
### TTGIR Stage: GPU-Specific Transformation

 The `make_ttgir()` stage [third_party/nvidia/backend/compiler.py247-337](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L247-L337) handles layout propagation and GPU-specific optimizations. It applies different pass pipelines based on the target architecture's compute capability. For example, SM90+ (Hopper) triggers warp specialization and TMA lowering [third_party/nvidia/backend/compiler.py273-275](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L273-L275) while SM100+ (Blackwell) adds TMEM-specific passes like `add_hoist_tmem_alloc` [third_party/nvidia/backend/compiler.py285](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L285-L285)

 
### LLIR Stage: LLVM IR Generation

 The `make_llir()` method [third_party/nvidia/backend/compiler.py339-433](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L339-L433) converts TritonGPU IR to LLVM IR. It registers NVIDIA-specific passes such as `add_allocate_shared_memory_nv` [third_party/nvidia/backend/compiler.py351](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L351-L351) and `add_to_llvmir` (TritonGPU to LLVM) [third_party/nvidia/backend/compiler.py365](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L365-L365) It also handles linking external libraries like `libdevice` [third_party/nvidia/backend/compiler.py413-415](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L413-L415)

 
### PTX and Binary Generation

 The final stages translate LLVM IR into PTX assembly using the LLVM NVPTX backend and then invoke `ptxas` to generate the final CUBIN binary.

 
 - For details on PTX translation and `ptxas` invocation, see [PTX Assembly and Binary Generation](https://deepwiki.com/triton-lang/triton/5.6.2-ptx-assembly-and-binary-generation).
 
 **Sources:** [third_party/nvidia/backend/compiler.py228-532](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L228-L532)

 
## NVIDIA-Specific Optimizations and Passes

 The NVIDIA backend leverages hardware-specific features through dedicated MLIR passes. These are registered in the compilation pipeline based on the target architecture's capability.

 
 - **Warp Specialization (SM90+)**: Partitions warps into specialized roles (e.g., producers and consumers) to overlap memory transfers with computation using `add_warp_specialize` [third_party/nvidia/backend/compiler.py273](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L273-L273)
 - **TMA Lowering (SM90+)**: Lowers tensor memory accelerator operations to specialized hardware instructions using `add_tma_lowering` [third_party/nvidia/backend/compiler.py301](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L301-L301)
 - **TMEM Optimization (SM100+)**: Optimizes Tensor Memory (TMEM) usage for Blackwell GPUs, including hoisting allocations and promoting operands to TMEM [third_party/nvidia/backend/compiler.py278-292](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L278-L292)
 
 For a detailed breakdown of these passes, see [NVIDIA-Specific Optimizations and Passes](https://deepwiki.com/triton-lang/triton/5.6.1-nvidia-specific-optimizations-and-passes).

 **Sources:** [third_party/nvidia/backend/compiler.py245-317](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L245-L317) [third_party/nvidia/triton_nvidia.cc128-200](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/triton_nvidia.cc#L128-L200)

 
## PTX Assembly and Binary Generation

 The final steps of the NVIDIA compilation pipeline involve generating PTX assembly and compiling it to a CUBIN binary.

 
 - **LLVM to PTX**: The `make_ptx` method uses `llvm.translate_to_asm` with the `nvptx64-nvidia-cuda` triple [third_party/nvidia/backend/compiler.py438-442](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L438-L442)
 - **CUBIN Assembly**: The `make_cubin` method identifies the correct `ptxas` binary (standard or Blackwell-specific) [third_party/nvidia/backend/compiler.py38-39](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L38-L39) and executes it with optimized flags such as `-lineinfo` and `--fmad` [third_party/nvidia/backend/compiler.py461-532](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L461-L532)
 
 For details on optimization flags and error handling during this stage, see [PTX Assembly and Binary Generation](https://deepwiki.com/triton-lang/triton/5.6.2-ptx-assembly-and-binary-generation).

 **Sources:** [third_party/nvidia/backend/compiler.py38-39](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L38-L39) [third_party/nvidia/backend/compiler.py435-532](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L435-L532)
