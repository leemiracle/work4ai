  **Purpose and Scope**: This page documents the CMake build system infrastructure and how Triton integrates with LLVM/MLIR as a critical dependency. It covers LLVM version management, CMake configuration, build options, plugin integration, and the compilation pipeline for the C++ components and Python extension module.

 
## Overview

 Triton's build system is based on CMake and requires LLVM/MLIR as an external dependency pinned to a specific commit. The build system:

 
 - Manages LLVM/MLIR at a specific commit hash for API stability. [README.md83-89](https://github.com/triton-lang/triton/blob/f893845b/README.md?plain=1#L83-L89)
 - Configures compilation of C++ MLIR dialects, passes, and transformations. [CMakeLists.txt1-16](https://github.com/triton-lang/triton/blob/f893845b/CMakeLists.txt#L1-L16)
 - Builds the Python extension module using `nanobind` (transitioned from pybind11). [setup.py23](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L23-L23) [setup.py209-216](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L209-L216)
 - Supports multiple backend plugins (NVIDIA, AMD, Proton). [setup.py58-126](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L58-L126)
 - Provides build options for optimization, caching, and debugging. [CMakeLists.txt18-43](https://github.com/triton-lang/triton/blob/f893845b/CMakeLists.txt#L18-L43)

## Main CMake Configuration

 
### Build Options

 Key CMake cache variables defined in the root configuration:

 
| Option | Default | Description |
|---|---|---|
| TRITON_BUILD_PYTHON_MODULE | OFF | Build Python Triton bindings. CMakeLists.txt20 |
| TRITON_BUILD_PROTON | ON | Build the Triton Proton profiler. CMakeLists.txt21 |
| TRITON_STABLE_ABI | OFF | Build with Python Stable ABI (abi3). CMakeLists.txt22 |
| TRITON_BUILD_UT | ON | Build C++ Triton Unit Tests. CMakeLists.txt23 |
| TRITON_BUILD_WITH_CCACHE | ON | Build with ccache if available. CMakeLists.txt24 |
| TRITON_OFFLINE_BUILD | OFF | Build without downloading dependencies. CMakeLists.txt25 |

## Backend Plugin System

 Backends are managed via the `BackendInstaller` class in `setup.py`. It handles both in-tree backends (in `third_party/`) and external plugins. [setup.py68-126](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L68-L126)

 
### Registration Flow

 
 - **Discovery**: `setup.py` checks `TRITON_PLUGIN_DIRS` and the `third_party/` directory. [setup.py108-126](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L108-L126)
 - **Submodule Init**: For in-tree backends, it initializes git submodules. [setup.py72-84](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L72-L84)
 - **External Plugins**: Expects to find a `backend/name.conf` file in the plugin directory. [setup.py122](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L122-L122)
