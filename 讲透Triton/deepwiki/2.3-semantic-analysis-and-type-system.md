  This page documents the semantic layer of Triton's Python frontend, which handles type checking, type promotion, and translation of Python operations to MLIR IR builder calls. The semantic layer sits between the AST traversal (see [Code Generator (AST to MLIR)](https://deepwiki.com/triton-lang/triton/2.4-code-generator-(ast-to-mlir))) and the IR construction, enforcing type safety and implementing Triton's type system semantics.

 For information about the high-level type definitions in `triton.language`, see [Triton Language Core (triton.language)](https://deepwiki.com/triton-lang/triton/2.1-triton-language-core-(triton.language)). For how the semantic layer is invoked during compilation, see [Code Generator (AST to MLIR)](https://deepwiki.com/triton-lang/triton/2.4-code-generator-(ast-to-mlir)).

 
## Overview

 The semantic layer is implemented primarily in the `TritonSemantic` class, which provides a unified interface for type-checking operations and generating MLIR IR. Each operation (addition, comparison, load, etc.) goes through:

 
 - **Type checking**: Validating operand types are compatible.
 - **Type promotion**: Determining the result type and inserting implicit casts.
 - **IR generation**: Calling the appropriate MLIR builder method via the C++ `ir.builder` bindings.

## The TritonSemantic Class

 The `TritonSemantic` class is a generic class parameterized by the tensor type it operates on. It maintains a reference to an `ir.builder` (a Python binding to MLIR's `OpBuilder` [python/src/ir.cc21-25](https://github.com/triton-lang/triton/blob/f893845b/python/src/ir.cc#L21-L25)) and implements methods for all operations supported in Triton kernels.

## Type Promotion and Implicit Casting

 The semantic layer implements comprehensive type promotion rules to determine result types for binary operations. This ensures compatibility with both NumPy/PyTorch semantics and C/C++ semantics where appropriate.

 
### Integer Promotion

 The `integer_promote_impl` method handles promotion between integer types following C/C++ "usual arithmetic conversions" [python/triton/language/semantic.py53-66](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L53-L66)


 Key rule: When mixing signed and unsigned integers of different widths, the unsigned type takes precedence if its bitwidth is greater than or equal to the signed type's bitwidth [python/triton/language/semantic.py60-65](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L60-L65)

 **Sources**: [python/triton/language/semantic.py53-66](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L53-L66)

 
### Computation Type Rules

 The `computation_type_impl` method determines the final computation type for binary operations, considering whether operands are scalars or tensors [python/triton/language/semantic.py68-116](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L68-L116)

 
| Priority | Rule | Example |
|---|---|---|
| 0 | Scalars of lower/equal kind don't promote | tensor[int32] + 1.0 → int32 |
| 1 | Double promotes everything | float16 + float64 → float64 |
| 2 | Float32 promotes non-double | int32 + float32 → float32 |
| 3 | Float16 promotes (except / and %) | int8 + float16 → float16 |
| 3.5 | Float16 / or % promotes to float32 | float16 / float16 → float32 |
| 4 | BFloat16 needs both operands bf16 | bfloat16 + bfloat16 → bfloat16 |
| 5 | Mixed FP8 types promote to float16 | fp8e5 + fp8e4nv → float16 |

 **Special handling**: Division (`/`) and modulo (`%`) operations on `float16` or `bfloat16` promote to `float32` because native hardware operations don't exist for these types in certain backend targets (like PTX) [python/triton/language/semantic.py93-102](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L93-L102)

 **Sources**: [python/triton/language/semantic.py68-116](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L68-L116)

 
### Scalar vs Tensor Semantics

 When one operand is a scalar and the other is a tensor, Triton follows PyTorch-like semantics where the scalar doesn't promote if its kind (bool < uint < int < fp) is lower than or equal to the tensor's kind [python/triton/language/semantic.py70-79](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L70-L79)

### Pointer Arithmetic Rules

 Pointer types have special rules enforced by `check_ptr_type_impl` [python/triton/language/semantic.py159-173](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L159-L173)

 
| Operation | Valid? | Result Type |
|---|---|---|
| ptr + int | ✓ | Same pointer type |
| ptr + ptr | ✗ | Error |
| ptr + float | ✗ | Error |
| ptr - int | ✓ | Same pointer type |

 When adding an unsigned offset to a pointer, the offset is zero-extended to `int64` to ensure positive interpretation [python/triton/language/semantic.py246-250](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L246-L250)

## Translation to IR Builder Calls

 Semantic methods translate Python operations to MLIR IR builder calls.

 
### Arithmetic Operations

 
| Python Op | Method | Int Signed IR | Int Unsigned IR |
|---|---|---|---|
| + | add() | create_add | create_add |
| - | sub() | create_sub | create_sub |
| * | mul() | create_mul | create_mul |
| // | floordiv() | create_sdiv | create_udiv |
| % | mod() | create_srem | create_urem |

 **Pointer addition** uses `create_addptr` instead of `create_add` [python/triton/language/semantic.py256](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L256-L256)

 **Sources**: [python/triton/language/semantic.py230-357](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L230-L357) [python/triton/language/core.py16-17](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/core.py#L16-L17)

 
### Comparison Operations

 
| Operation | Python | Float IR | Signed Int IR | Unsigned Int IR |
|---|---|---|---|---|
| == | == | create_fcmpOEQ | create_icmpEQ | create_icmpEQ |
| != | != | create_fcmpONE | create_icmpNE | create_icmpNE |
| > | > | create_fcmpOGT | create_icmpSGT | create_icmpUGT |

 All comparison operations return a `bool_like` type (tensor of `int1`) [python/triton/language/semantic.py130-131](https://github.com/triton-lang/triton/blob/f893845b/python/triton/language/semantic.py#L130-L131)
