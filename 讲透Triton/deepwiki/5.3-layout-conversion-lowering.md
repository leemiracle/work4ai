  This page documents how `ttg.convert_layout` operations are lowered to LLVM IR. Layout conversion is the process of transforming tensor data from one distributed memory layout to another, which may involve register reordering, warp shuffles, or shared memory transfers depending on the layouts involved.

 For information about layout encodings and the LinearLayout system, see [Layout Encoding Attributes (3.3)](https://github.com/triton-lang/triton/blob/f893845b/Layout Encoding Attributes (3.3)) and [LinearLayout System (3.4)](https://github.com/triton-lang/triton/blob/f893845b/LinearLayout System (3.4)) For the high-level optimization pass that removes unnecessary conversions, see [Layout Propagation and Conversion Removal (4.1)](https://github.com/triton-lang/triton/blob/f893845b/Layout Propagation and Conversion Removal (4.1))

 
## Overview

 The `ConvertLayoutOpConversion` pattern in [lib/Conversion/TritonGPUToLLVM/ConvertLayoutOpToLLVM.cpp26-91](https://github.com/triton-lang/triton/blob/f893845b/lib/Conversion/TritonGPUToLLVM/ConvertLayoutOpToLLVM.cpp#L26-L91) determines the appropriate lowering strategy by analyzing the minimal conversion layout between source and destination types. ## Within-Thread Conversion (Register Reordering)

 When data movement only involves reordering values within the same thread's registers (the conversion layout contains only the `register` dimension), the lowering is performed by `transferWithinThread` [lib/Conversion/TritonGPUToLLVM/ConvertLayoutOpToLLVM.cpp93-116](https://github.com/triton-lang/triton/blob/f893845b/lib/Conversion/TritonGPUToLLVM/ConvertLayoutOpToLLVM.cpp#L93-L116)

 The function unpacks the input LLVM elements, applies the register-to-register mapping defined by the `LinearLayout`, and repacks them into the destination structure.

## Within-Warp Conversion (Warp Shuffles)

 When data must be moved between lanes within the same warp (the conversion contains the `lane` dimension), the compiler attempts to use warp shuffle instructions.

 
### AMD Permlane Swap Optimization

 On AMD hardware (specifically GFX1250/CDNA4), certain intra-warp conversions can be optimized using `v_permlane_swap` instructions instead of general shuffles. This is implemented in `ConvertLayoutOpPermlaneSwap` [third_party/amd/lib/TritonAMDGPUToLLVM/ConvertLayoutOpToLLVM.cpp13-220](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/ConvertLayoutOpToLLVM.cpp#L13-L220)
