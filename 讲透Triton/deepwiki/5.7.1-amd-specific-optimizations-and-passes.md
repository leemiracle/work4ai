## Purpose and Scope

 This page documents the AMD-specific compiler passes and optimizations in the Triton compiler backend for AMD GPUs. These passes operate on TritonGPU IR (TTGIR) and during lowering to LLVM IR, targeting CDNA (MI200/MI300 series) and RDNA (RX 7000/8000 series) architectures.

 For general backend compilation and code generation concepts, see [Backend Compilation and Code Generation](https://deepwiki.com/triton-lang/triton/5-backend-compilation-and-code-generation). For AMD-specific memory operations like buffer loads/stores and LDS operations, see [AMD Load/Store and Memory Operations](https://deepwiki.com/triton-lang/triton/5.7.2-amd-loadstore-and-memory-operations). For AMD shuffle and reduction implementations, see [Shuffle and Warp Reduction on AMD](https://deepwiki.com/triton-lang/triton/5.7.3-shuffle-and-warp-reduction-on-amd).

 **Sources:** [third_party/amd/backend/compiler.py1-134](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/backend/compiler.py#L1-L134) [third_party/amd/python/triton_amd.cc47-136](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/python/triton_amd.cc#L47-L136)

## Pass Organization and Pipeline

 - **TTGIR Transformation Passes** - Operate on `TritonGPU` dialect before lowering to LLVM.
 - **LLVMIR Conversion Passes** - Handle AMD-specific lowering and LLVM-level transformations.

## Matrix Multiplication Acceleration Passes

 
### TritonAMDGPUAccelerateMatmul

 **Purpose:** Select and configure optimal matrix instruction layouts for AMD matrix cores (MFMA for CDNA, WMMA for RDNA).

 **Implementation:** [third_party/amd/lib/TritonAMDGPUTransforms/AccelerateAMDMatmul.cpp](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/AccelerateAMDMatmul.cpp)

 **Key Functions:**

 
 - `getMfmaVersion(ISAFamily isaFamily)`: Returns 1-4 based on CDNA generation [third_party/amd/lib/TritonAMDGPUTransforms/AccelerateAMDMatmul.cpp36-50](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/AccelerateAMDMatmul.cpp#L36-L50)
 - `getWmmaVersion(ISAFamily isaFamily)`: Returns 1-3 for RDNA3/4 and GFX1250 [third_party/amd/lib/TritonAMDGPUTransforms/AccelerateAMDMatmul.cpp52-65](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/AccelerateAMDMatmul.cpp#L52-L65)
 - `planWarps()`: Determines the 2D grid of warps for a given `dot` operation to minimize reduction overhead. It handles chained dots (like Flash Attention) by setting `warpsPerCTA` to `{numWarps, 1}` for head dots [third_party/amd/lib/TritonAMDGPUTransforms/AccelerateAMDMatmul.cpp106-167](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/AccelerateAMDMatmul.cpp#L106-L167)
 - `chooseMfmaInstruction()`: Selects the hardware-specific MFMA intrinsic based on input types and shapes, supporting OCP and UZ fp8 variants [third_party/amd/lib/TritonAMDGPUTransforms/AccelerateAMDMatmul.cpp172-230](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/AccelerateAMDMatmul.cpp#L172-L230)
 
 **Sources:** [third_party/amd/lib/TritonAMDGPUTransforms/AccelerateAMDMatmul.cpp36-230](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/AccelerateAMDMatmul.cpp#L36-L230) [third_party/amd/include/TritonAMDGPUTransforms/Passes.td41-62](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/include/TritonAMDGPUTransforms/Passes.td#L41-L62)

 **Purpose:** Generate software pipelining schedules for loops. This pass identifies operations that can be moved across loop iterations to hide latency.

 **Implementation:** [third_party/amd/lib/TritonAMDGPUTransforms/ScheduleLoops.cpp](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/ScheduleLoops.cpp)

### TritonAMDGPUBlockPingpong

 **Purpose:** Interleaves the execution of two warps on each SIMD unit by grouping instructions into "Dot" and "Memory" clusters. This is specifically enabled for `gfx942` and `gfx950` architectures.

 **Implementation:** [third_party/amd/lib/TritonAMDGPUTransforms/BlockPingpong.cpp](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/BlockPingpong.cpp)

 **Mechanism:**

 
 - Inserts `rocdl.s.setprio` to control warp priority (0/1) within a SIMD [third_party/amd/lib/TritonAMDGPUTransforms/BlockPingpong.cpp94-103](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/BlockPingpong.cpp#L94-L103)
 - Uses `amdgpu-synchronize-as` local fences via `createLocalMMRAFence` to synchronize warps [third_party/amd/lib/TritonAMDGPUTransforms/BlockPingpong.cpp33-41](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/BlockPingpong.cpp#L33-L41)
 - Prevents warps from entering the dot cluster while another warp is busy to maintain the ping-pong pattern [third_party/amd/lib/TritonAMDGPUTransforms/BlockPingpong.cpp97-101](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/BlockPingpong.cpp#L97-L101)
 
 **Sources:** [third_party/amd/lib/TritonAMDGPUTransforms/BlockPingpong.cpp31-103](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/BlockPingpong.cpp#L31-L103) [third_party/amd/include/TritonAMDGPUTransforms/Passes.td187-204](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/include/TritonAMDGPUTransforms/Passes.td#L187-L204) [third_party/amd/backend/compiler.py22-24](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/backend/compiler.py#L22-L24)

## Memory Operation Passes

 
### TritonAMDGPUCanonicalizePointers

 **Purpose:** Rewrites pointers as a `<basePtr, offset>` pair to isolate uniform and non-uniform updates. This pass is critical for revealing base pointers for buffer-op optimization.

 **Implementation:** [third_party/amd/lib/TritonAMDGPUTransforms/CanonicalizePointers.cpp](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/CanonicalizePointers.cpp)

 **Logic:**

 
 - Associative updates to pointers are tracked in a `FatPtr` structure containing a scalar `basePtr` and a tensor `offset` [third_party/amd/lib/TritonAMDGPUTransforms/CanonicalizePointers.cpp59-64](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/CanonicalizePointers.cpp#L59-L64)
 - Uniform updates (scalar) are added to the `basePtr`, while non-uniform updates (tensor) are added to the `offset` [third_party/amd/lib/TritonAMDGPUTransforms/CanonicalizePointers.cpp66-76](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/CanonicalizePointers.cpp#L66-L76)
 - Handles "small-tensors" (<= 2GB) specially by using the `tt.pointer_range=32` attribute to allow 32-bit offset optimizations [third_party/amd/lib/TritonAMDGPUTransforms/CanonicalizePointers.cpp99-151](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/CanonicalizePointers.cpp#L99-L151)
 
 **Sources:** [third_party/amd/lib/TritonAMDGPUTransforms/CanonicalizePointers.cpp48-153](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/CanonicalizePointers.cpp#L48-L153) [third_party/amd/include/TritonAMDGPUTransforms/Passes.td114-155](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/include/TritonAMDGPUTransforms/Passes.td#L114-L155)

 
### TritonAMDGPUConvertToBufferOps

 **Purpose:** Converts standard memory operations to AMD-specific buffer instructions (e.g., `llvm.amdgcn.raw.buffer.load`).

 **Implementation:** [third_party/amd/lib/TritonAMDGPUTransforms/ConvertToBufferOps.cpp](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUTransforms/ConvertToBufferOps.cpp)
