## Purpose and Scope

 This page documents the Python package structure, installation methods, and build system for Triton. It covers how users install Triton, how the Python package is configured and built, and the integration between Python's `setuptools` and the underlying CMake build system.

 **Sources:** [setup.py1-41](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L1-L41) [CMakeLists.txt1-29](https://github.com/triton-lang/triton/blob/f893845b/CMakeLists.txt#L1-L29)

## Installation Methods

 
### Binary Installation via pip

 The simplest installation method is via pip, which downloads pre-built binary wheels. Triton supports multiple Python versions and platforms, including specialized support for free-threaded Python 3.13 and stable ABI (abi3) for Python 3.12+.

 
 - **Stable Releases:** Available on PyPI via `pip install triton` [README.md33-37](https://github.com/triton-lang/triton/blob/f893845b/README.md?plain=1#L33-L37)
 - **Nightly Wheels:** Available for CPython 3.10-3.14 [README.md39](https://github.com/triton-lang/triton/blob/f893845b/README.md?plain=1#L39-L39)
 - **ABI Stability:** The build system supports `TRITON_STABLE_ABI` for Python 3.12+ [.github/workflows/wheels.yml110-113](https://github.com/triton-lang/triton/blob/f893845b/.github/workflows/wheels.yml#L110-L113)
 
 **Sources:** [README.md31-40](https://github.com/triton-lang/triton/blob/f893845b/README.md?plain=1#L31-L40) [CMakeLists.txt22](https://github.com/triton-lang/triton/blob/f893845b/CMakeLists.txt#L22-L22) [.github/workflows/wheels.yml105-113](https://github.com/triton-lang/triton/blob/f893845b/.github/workflows/wheels.yml#L105-L113)

 
### Source Installation

 Source installation involves cloning the repository and using `pip install -e .`. This triggers the `setup.py` script, which orchestrates the compilation of C++ components.

 
#### Basic Source Installation

 When running `pip install -e .`, the following occurs:

 
 - `setup.py` identifies the environment and build type [setup.py129-140](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L129-L140)
 - It prepares backends (NVIDIA, AMD, etc.) by initializing submodules if necessary [setup.py68-111](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L68-L111)
 - It invokes CMake to build the C++ extension `libtriton` [setup.py202-210](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L202-L210)
 
 **Sources:** [setup.py43-111](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L43-L111) [setup.py129-140](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L129-L140) [README.md41-49](https://github.com/triton-lang/triton/blob/f893845b/README.md?plain=1#L41-L49)

 
#### Building with Custom LLVM

 Triton uses LLVM to generate code for GPUs and CPUs. While it defaults to downloading a prebuilt LLVM, users can specify a custom build.

 
 - **Helper Script:** `make dev-install-llvm` automates building the specific LLVM version Triton requires [README.md72-75](https://github.com/triton-lang/triton/blob/f893845b/README.md?plain=1#L72-L75)
 - **Environment Variables:** Custom paths are passed via `LLVM_INCLUDE_DIRS`, `LLVM_LIBRARY_DIR`, and `LLVM_SYSPATH` [README.md110-113](https://github.com/triton-lang/triton/blob/f893845b/README.md?plain=1#L110-L113)
 - **Version Pinning:** The required LLVM commit is tracked in `cmake/llvm-build-info.json` [cmake/llvm-build-info.json1-5](https://github.com/triton-lang/triton/blob/f893845b/cmake/llvm-build-info.json#L1-L5)
 
 **Sources:** [README.md64-115](https://github.com/triton-lang/triton/blob/f893845b/README.md?plain=1#L64-L115) [CMakeLists.txt31-33](https://github.com/triton-lang/triton/blob/f893845b/CMakeLists.txt#L31-L33) [python/build_helpers.py42-57](https://github.com/triton-lang/triton/blob/f893845b/python/build_helpers.py#L42-L57) [cmake/llvm-build-info.json1-5](https://github.com/triton-lang/triton/blob/f893845b/cmake/llvm-build-info.json#L1-L5)

## Build System Integration

 
### setup.py and CMake Extension

 Triton uses a custom `CMakeBuildPy` class that inherits from `setuptools.command.build_py`. This ensures that `build_ext` is run before the Python modules are packaged, allowing the compiled `libtriton` to be included. The build system also supports `MAX_JOBS` to limit memory usage during compilation [README.md129-132](https://github.com/triton-lang/triton/blob/f893845b/README.md?plain=1#L129-L132)

 **Sources:** [setup.py202-207](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L202-L207) [README.md129-132](https://github.com/triton-lang/triton/blob/f893845b/README.md?plain=1#L129-L132)

 
### Backend Installation Logic

 The `BackendInstaller` class in `setup.py` manages the discovery and preparation of hardware backends. It handles:

 
 - **In-tree backends:** Located in `third_party/`, managed via git submodules [setup.py73-88](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L73-L88)
 - **External backends:** Discovered via the `TRITON_PLUGIN_DIRS` environment variable, which is a semicolon-separated list of paths [setup.py117-126](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L117-L126)
 - **Structure Validation:** Ensures `compiler.py` and `driver.py` exist in the backend directory [setup.py100-101](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L100-L101)
 
 **Sources:** [setup.py68-126](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L68-L126)

 
### libtriton Python Bindings

 The C++ extension `libtriton` is initialized in `python/src/main.cc`. It uses `nanobind` to expose various submodules:

 
| Submodule | Initialization Function | Purpose |
|---|---|---|
| ir | init_triton_ir | Triton IR management |
| passes | init_triton_passes | IR transformation passes |
| llvm | init_triton_llvm | LLVM lowering utilities |
| interpreter | init_triton_interpreter | Reference CPU execution |

 **Sources:** [python/src/main.cc39-64](https://github.com/triton-lang/triton/blob/f893845b/python/src/main.cc#L39-L64) [setup.py23](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L23-L23)

## Build Configuration Options

 
### Environment Knobs

 Triton manages build and runtime configurations via environment variables defined in the build helper logic and knobs.

 
| Knob/Variable | Usage | Source |
|---|---|---|
| TRITON_BUILD_WITH_CLANG_LLD | Use clang and lld for faster builds | README.md119-120 |
| TRITON_BUILD_WITH_CCACHE | Enable ccache integration | README.md122 |
| TRITON_OFFLINE_BUILD | Prevent dependency downloads | setup.py150-163 |
| TRITON_HOME | Custom path for cache and downloads | README.md124-127 |

 
### Build Type Selection

 The build type is determined by specific environment flags in the following priority order:

 
 - `DEBUG` -> `Debug`
 - `REL_WITH_DEB_INFO` -> `RelWithDebInfo`
 - `TRITON_REL_BUILD_WITH_ASSERTS` -> `TritonRelBuildWithAsserts`
 - `TRITON_BUILD_WITH_O1` -> `TritonBuildWithO1`
 
 **Sources:** [setup.py129-140](https://github.com/triton-lang/triton/blob/f893845b/setup.py#L129-L140)

### Key Functions in `python/triton/runtime/build.py`

 
 - `_find_compiler(language)`: Searches for `CC`/`CXX` environment variables, then falls back to `gcc`/`g++` or `clang`/`clang++` [python/triton/runtime/build.py22-48](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/build.py#L22-L48)
 - `_build(...)`: Invokes the system compiler with flags like `-O3`, `-shared`, and `-fPIC`. It also automatically includes Python headers and Triton backend directories [python/triton/runtime/build.py60-84](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/build.py#L60-L84)
 - `_compile_so(...)`: Manages the `CacheManager` to avoid redundant compilations of the same source [python/triton/runtime/build.py132-154](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/build.py#L132-L154)

## External Toolchain Integration

 Triton relies on several external NVIDIA tools for final binary generation. The paths for these tools can be overridden via CMake options or environment variables.

 
| Tool | CMake Variable | Environment Variable Override |
|---|---|---|
| ptxas | TRITON_PTXAS_PATH | TRITON_PTXAS_PATH |
| cuobjdump | TRITON_CUOBJDUMP_PATH | TRITON_CUOBJDUMP_PATH |
| nvdisasm | TRITON_NVDISASM_PATH | TRITON_NVDISASM_PATH |
| cupti | TRITON_CUPTI_INCLUDE_PATH | TRITON_CUPTI_INCLUDE_PATH |
