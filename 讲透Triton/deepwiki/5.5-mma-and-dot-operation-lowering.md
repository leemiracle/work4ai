## Purpose and Scope

 This page documents how Triton dot operations (`tt.dot`, `tt.dot_scaled`) are transformed and lowered to hardware matrix multiply-accumulate (MMA) instructions. This includes MMA version selection, encoding transformations, operand layout conversions, and optimizations that prepare dot operations for code generation targeting NVIDIA Tensor Cores and AMD MFMA instructions.

 For information about the actual LLVM IR lowering and PTX/AMDGCN instruction emission, see [NVIDIA CUDA Backend](https://deepwiki.com/triton-lang/triton/5.6-nvidia-cuda-backend) and [AMD HIP Backend](https://deepwiki.com/triton-lang/triton/5.7-amd-hip-backend). For general layout conversion mechanics, see [Layout Conversion Lowering](https://deepwiki.com/triton-lang/triton/5.3-layout-conversion-lowering). For the TTIR to TTGIR conversion that introduces GPU-specific concepts, see [System Architecture and Compilation Flow](https://deepwiki.com/triton-lang/triton/1.1-system-architecture-and-compilation-flow).

## AccelerateMatmul Pass

 The `AccelerateMatmul` pass is the primary transformation that converts high-level `tt.dot` operations with blocked encodings into MMA-accelerated operations. This pass runs at the TritonGPU dialect level (TTGIR).

 
### MMA Version Selection

 
```

```

 The function `getMMAVersionSafe()` determines the highest MMA version supported for a given dot operation based on hardware capability and operation characteristics.

 **Sources:** [lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp34-70](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp#L34-L70)

 
### Warp Distribution Strategy

 The pass computes how warps should be distributed across the output tile dimensions (M, N) to optimize register usage and parallelism.

 
#### MMAv2 Warp Distribution

 For MMAv2, `warpsPerTileV2()` balances the number of warps between M and N dimensions based on shape ratios and register pressure.

 **Sources:** [lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp72-134](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp#L72-L134)

 
#### MMAv3 Warp Distribution

 For MMAv3, `warpsPerTileV3()` uses a different strategy optimized for warp group operations, starting with a minimum unit of [4, 1] warps.

 **Sources:** [lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp135-161](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp#L135-L161)

 
## Pattern Rewrite Rules

 The AccelerateMatmul pass implements several pattern rewrite rules to transform dot operations for different MMA versions.

 
### BlockedToMMA Pattern

 Handles MMAv2 and MMAv3:

 
 - **MMAv2 Path**: Converts operands to `DotOperandEncoding`.
 - **MMAv3 Path**: Creates shared memory allocations with `NVMMASharedEncodingAttr` and generates `ttng.warp_group_dot`.
 
 **Sources:** [lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp359-446](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp#L359-L446)

 
### BlockedToMMAv5 Pattern

 Targets Blackwell (SM100) architecture with Gen5 Tensor Cores:

 
 - Allocates accumulator in **Tensor Memory** (TMEM) with `TensorMemoryEncodingAttr`.
 - Generates `ttng.tc_gen5_mma` operation that operates on TMEM.
 - Uses `ttng.tmem_load` to read results back to registers.
 
 **Sources:** [lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp520-600](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp#L520-L600)

 
## Scaled Dot Operations

 Triton supports scaled dot operations (`tt.dot_scaled`) for quantized matrix multiplication with per-block scaling factors.

 
### ScaledBlockedToMMA Pattern (SM120)

 For Blackwell SM120, scaled dots use MMAv2 with special linear layouts for scales.

 **Sources:** [lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp656-753](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp#L656-L753)

 
### ScaledBlockedToMMAv5 Pattern (SM100)

 For Blackwell SM100, scaled dots use Gen5 MMA with scales stored in TMEM. `ttng.tc_gen5_mma_scaled` performs the multiplication using `TensorMemoryScalesEncodingAttr`.

 **Sources:** [lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp755-894](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/Transforms/AccelerateMatmul.cpp#L755-L894)

 
## Lowering to LLVM IR (NVIDIA)

 The conversion from TritonGPU IR to LLVM IR involves translating MMA-specific operations into inline assembly or NVVM intrinsics.

 
### MMAv2 Lowering

 MMAv2 (`tt.dot` with `NvidiaMmaEncodingAttr`) is lowered using `ValueTableV2` to manage register mapping.

 
 - **Function**: `loadC` loads the accumulator tensor. [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv2.cpp21-65](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv2.cpp#L21-L65)
 - **Function**: `getValuesFromDotOperandLayoutStruct` extracts values from the operand struct for each MMA instruction. [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv2.cpp85-182](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv2.cpp#L85-L182)
 
 
### MMAv3 (WGMMA) Lowering

 Hopper WGMMA instructions are emitted via `ttng.warp_group_dot`.

 
 - **Type Selection**: `getMmaRetType` and `getMmaOperandType` determine the appropriate PTX types (f32, f16, bf16, etc.). [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/WGMMA.cpp40-70](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/WGMMA.cpp#L40-L70)
 - **Register Loading**: `loadReg` packs/unpacks values into 32-bit registers for the `nvg.wgmma` intrinsic. [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/WGMMA.cpp96-129](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/WGMMA.cpp#L96-L129)
 
 
### MMAv5 (Blackwell) Lowering

 Blackwell MMA operations utilize Tensor Memory (TMEM).

 
 - **Descriptor Generation**: `createInstDescriptor` builds the 32-bit hardware instruction descriptor (sparsity, types, transpositions, shapes) used by `tcgen05.mma`. [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv5.cpp154-200](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv5.cpp#L154-L200)
 - **TMEM Loading**: `DotOpMmaV5TmemLoader` handles loading operands from TMEM using `LinearLayout` inversions to map logical coordinates to TMEM offsets. [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv5.cpp20-73](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv5.cpp#L20-L73)
 
 
## Tensor Memory Operations

 Blackwell introduces TMEM as a dedicated memory space for Tensor Core operations. Lowering involves packing data into 32-bit registers and emitting PTX assembly.

 
| Operation | LLVM Lowering Description |
|---|---|
| ttng.tmem_alloc | Lowers to tcgen05.alloc PTX via TMemCopyAtom logic. third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/TensorMemoryToLLVM.cpp28-83 |
| ttng.tmem_load | Lowers to tcgen05.ld PTX using createTensorMemoryLoad, supporting optional reductions. third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/TensorMemoryToLLVM.cpp189-200 |
| ttng.tmem_store | Lowers to tcgen05.st PTX using createTensorMemoryStore with .unpack::16b support. third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/TensorMemoryToLLVM.cpp154-187 |

 **Sources:** `third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/TensorMemoryToLLVM.cpp`, `test/Conversion/tritongpu_to_llvm_blackwell.mlir`

 
## Shared Memory and Swizzling

 For MMA operands, shared memory must be swizzled to avoid bank conflicts.

 
 - **NVMMASharedEncodingAttr**: Describes the swizzling width (e.g., 32B, 64B, 128B) and transposition state. [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv5.cpp82-90](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv5.cpp#L82-L90)
 - **LdMatrix/StMatrix**: NVIDIA-specific patterns optimize loading into registers. [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/MemoryOpToLLVM.cpp75-127](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/MemoryOpToLLVM.cpp#L75-L127)
