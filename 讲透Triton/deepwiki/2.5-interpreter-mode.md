## Purpose and Scope

 Interpreter Mode is a CPU-based execution path for Triton kernels that enables debugging, testing, and rapid prototyping without requiring GPU hardware. It executes Triton language operations directly on the CPU using NumPy as the computational backend, bypassing the full compilation pipeline (TTIR → TTGIR → LLVM IR → PTX/AMDGCN).

 This mode is distinct from the standard GPU compilation and execution path. For information about the JIT compilation system that normally compiles to GPU code, see [JIT Compilation and Caching](https://deepwiki.com/triton-lang/triton/2.2-jit-compilation-and-caching).

 **Sources:** [python/triton/runtime/interpreter.py1-25](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L1-L25)

## Core Data Structures

 
### TensorHandle

 `TensorHandle` is the fundamental wrapper that bridges Triton tensor types with NumPy arrays. It stores numerical data, the Triton logical type, and metadata.

 
| Field | Type | Purpose |
|---|---|---|
| data | np.ndarray | The actual numerical data |
| dtype | tl.dtype | Triton type (pointer_type or scalar_type) |
| attr | Dict | Metadata attributes |

 The constructor validates that the NumPy data size is compatible with the Triton `dtype` bitwidth ([python/triton/runtime/interpreter.py40-43](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L40-L43)).

 **Sources:** [python/triton/runtime/interpreter.py28-59](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L28-L59)

 
### TensorDescHandle

 `TensorDescHandle` ([python/triton/runtime/interpreter.py61](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L61-L61)) represents tensor descriptors used with `load_tensor_descriptor` and `store_tensor_descriptor`. It manages base pointers, shapes, and strides, ensuring 16-byte alignment for hardware compatibility simulation ([python/triton/runtime/interpreter.py73-83](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L73-L83)).

## Type System and Conversions

 
### Triton to NumPy Type Mapping

 The `_get_np_dtype()` function maps Triton types to NumPy dtypes ([python/triton/runtime/interpreter.py146-175](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L146-L175)):

 
| Triton Type | NumPy Type | Notes |
|---|---|---|
| tl.int1 | np.bool_ | Boolean |
| tl.float16 | np.float16 | Half precision |
| tl.bfloat16 | np.uint16 | Stored as raw bits (NumPy lacks native BF16) |
| tl.pointer_type | np.uint64 | Pointers as 64-bit integers |

 **Sources:** [python/triton/runtime/interpreter.py146-175](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L146-L175)

 
### Float Type Conversions

 The `_convert_float()` function handles conversions between floating-point types with different precisions by manually adjusting exponent bias and mantissa widths ([python/triton/runtime/interpreter.py178-265](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L178-L265)). This is used to simulate hardware-specific formats like FP8.

 **Sources:** [python/triton/runtime/interpreter.py178-265](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L178-L265)

## Execution Model

 
### GridExecutor

 The `GridExecutor` class orchestrates kernel execution across grid dimensions ([python/triton/runtime/interpreter.py890](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L890-L890)). It iterates through the grid, sets the `program_id` values for each axis (0, 1, 2), and executes the kernel for each cell sequentially.

 **Sources:** [python/triton/runtime/interpreter.py890-950](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L890-L950)

 
### InterpreterBuilder Implementation

 `InterpreterBuilder` implements the semantic operations defined in the Triton language:

 
 - **Memory Ops**: `get_load` ([python/triton/runtime/interpreter.py500](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L500-L500)) and `get_store` ([python/triton/runtime/interpreter.py650](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L650-L650)) use NumPy indexing and `ctypes` for raw memory access.
 - **Program Metadata**: `create_get_program_id` ([python/triton/runtime/interpreter.py348](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L348-L348)) and `create_get_num_programs` ([python/triton/runtime/interpreter.py351](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L351-L351)) return the grid state managed by `GridExecutor`.
 - **Arithmetic**: Operations like `get_binary_op` ([python/triton/runtime/interpreter.py365](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L365-L365)) map directly to NumPy ufuncs.
 
 **Sources:** [python/triton/runtime/interpreter.py313-889](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L313-L889)

## Testing and Debugging

 
### Detection and Markers

 Tests detect if the interpreter is active using `is_interpreter()` ([python/test/unit/language/test_core.py30](https://github.com/triton-lang/triton/blob/f893845b/python/test/unit/language/test_core.py#L30-L30)). Specific tests can be isolated using the `@pytest.mark.interpreter` marker ([python/test/unit/language/test_core.py150](https://github.com/triton-lang/triton/blob/f893845b/python/test/unit/language/test_core.py#L150-L150)).

### Patching Kernels

 The `patch_kernel` function ([python/test/unit/language/test_core.py99](https://github.com/triton-lang/triton/blob/f893845b/python/test/unit/language/test_core.py#L99-L99)) allows the testing framework to modify the kernel source at runtime. In interpreter mode, it extracts the source code via `inspect.getsource`, performs string replacement, and executes the result in a local namespace ([python/test/unit/language/test_core.py102-106](https://github.com/triton-lang/triton/blob/f893845b/python/test/unit/language/test_core.py#L102-L106)).

 **Sources:** [python/test/unit/language/test_core.py99-114](https://github.com/triton-lang/triton/blob/f893845b/python/test/unit/language/test_core.py#L99-L114)

 
### Known Limitations

 
 - **Bfloat16**: `bfloat16` is not natively supported in the interpreter for all operations because NumPy lacks the type ([python/test/unit/language/test_core.py133-135](https://github.com/triton-lang/triton/blob/f893845b/python/test/unit/language/test_core.py#L133-L135)).
 - **Alignment**: The interpreter enforces strict 16-byte alignment checks for tensor descriptors to simulate hardware constraints ([python/triton/runtime/interpreter.py73](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/interpreter.py#L73-L73)).
