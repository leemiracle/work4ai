  This page provides technical details on the debugging and profiling tools integrated into the Triton compiler. It covers the Proton profiler, Concurrency Sanitizer (ConSan), Floating-Point Sanitizer (FPSan), Global Memory Sanitizer (GSan), and various IR inspection mechanisms.

 
## Proton Profiler

 Proton is a lightweight profiling framework for Triton that records Python context, user annotations, Triton launch metadata, and GPU kernel metrics.

 
### System Architecture and Data Flow

 Proton operates by intercepting kernel launches and collecting hardware metrics via backend-specific APIs (CUPTI for NVIDIA, RocTracer for AMD).

## Concurrency Sanitizer (ConSan)

 ConSan is an instrumentation-based tool designed to detect race conditions and synchronization errors in Triton kernels, particularly for advanced features like Hopper/Blackwell Warp Specialization and TMA.

 
### Instrumentation Logic

 ConSan works by inserting "locks" and "barriers" around shared memory accesses and asynchronous operations. It tracks "read visibility" and "write visibility" using global scratch memory.

## Floating-Point Sanitizer (FPSan)

 FPSan detects numerical instabilities such as NaNs or Infs by emulating high-precision arithmetic or inserting checks during kernel execution.

 
### Functional Flow

 
 - **Decomposition**: High-level operations like `tt.dot` are decomposed into smaller tiles or `i8` dots to allow fine-grained inspection when `supportsI8DotDecomposition` returns true [lib/Dialect/TritonInstrument/Transforms/FpSanitizer.cpp64-71](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonInstrument/Transforms/FpSanitizer.cpp#L64-L71)
 - **Scratch Management**: FPSan allocates scratch memory using `getOptimizedBlockedEncoding` to store intermediate scale factors or values for comparison [lib/Dialect/TritonInstrument/Transforms/FpSanitizer.cpp148-168](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonInstrument/Transforms/FpSanitizer.cpp#L148-L168)
 - **Instrumentation**: Injects checks after arithmetic operations. The pass uses `tti.experimental_fpsan_embed` to track floating-point state transitions [test/TritonGPU/fpsan.mlir38-45](https://github.com/triton-lang/triton/blob/f893845b/test/TritonGPU/fpsan.mlir#L38-L45)

## Global Memory Sanitizer (GSan)

 GSan (Global Sanitizer) is a tool for detecting out-of-bounds (OOB) accesses in global memory.

 
### Implementation

 
 - **Allocator Interception**: GSan provides a custom allocator that pads allocations with "redzones".
 - **Instrumentation**: The `GlobalSanitizer` MLIR pass instruments `tt.load` and `tt.store` operations.
 - **Runtime**: If an access falls into a redzone or unallocated memory, the kernel triggers a trap or returns a specific error code.
 
 
## IR Dumping and Inspection

 The Triton compiler provides several mechanisms to inspect the Intermediate Representation (IR) at different stages of the pipeline.

 
### Dumping Mechanisms

 
| Tool | Environment Variable | Description |
|---|---|---|
| MLIR Dump | MLIR_ENABLE_DUMP=1 | Dumps IR before/after every MLIR pass to stderr or MLIR_DUMP_PATH. |
| LLVM Dump | LLVM_IR_ENABLE_DUMP=1 | Dumps the generated LLVM IR before backend compilation. |
| Kernel Dump | TRITON_KERNEL_DUMP=1 | Saves all IR stages (.ttir, .ttgir, .llir) and assembly (.ptx, .amdgcn) to TRITON_DUMP_DIR. |

 
### Kernel Override Mechanism

 Users can override the compiler's generated code by providing custom IR files in a specific directory.

 
 - Set `TRITON_KERNEL_OVERRIDE=1`.
 - Place a modified IR file (e.g., `kernel.ttgir`) in the directory specified by `TRITON_OVERRIDE_DIR`.
 - The compiler will detect the file matching the kernel's hash and use it instead of proceeding with the standard compilation flow.
 
 
## Triton-to-Gluon Translator

 The `triton-to-gluon` tool is a translator utility that helps migrate standard Triton kernels to the experimental Gluon frontend, which offers more hardware-explicit control. It performs slicing and transformation of the Python AST to map high-level `triton.language` calls to `triton.experimental.gluon` primitives.
