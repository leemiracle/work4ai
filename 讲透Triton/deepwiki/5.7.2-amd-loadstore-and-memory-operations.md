  This page documents the AMD-specific implementation of memory load and store operations during the LLVM lowering phase. It covers regular pointer-based memory operations, AMD buffer operations using resource descriptors, direct-to-LDS (Local Data Share) optimizations, and the specialized Tensor Data Mover (TDM) system for GFX1250.

 For NVIDIA-specific memory operations, see [5.6.2](https://github.com/triton-lang/triton/blob/f893845b/5.6.2) For general memory operation lowering framework, see [5.2](https://github.com/triton-lang/triton/blob/f893845b/5.2) For AMD-specific shuffle and warp operations, see [5.7.3](https://github.com/triton-lang/triton/blob/f893845b/5.7.3)

 
## Overview

 AMD memory operations in Triton are lowered through several specialized patterns in the `TritonAMDGPUToLLVM` conversion pass. The implementation handles:

 
 - **Standard loads/stores**: Pointer-based global memory access with predication and cache modifiers [third_party/amd/lib/TritonAMDGPUToLLVM/LoadStoreOpToLLVM.cpp536-637](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/LoadStoreOpToLLVM.cpp#L536-L637)
 - **Buffer operations**: AMD-specific resource descriptor-based memory operations providing better bounds checking [third_party/amd/lib/TritonAMDGPUToLLVM/LoadStoreOpToLLVM.cpp639-721](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/LoadStoreOpToLLVM.cpp#L639-L721)

 - **Tensor Data Mover (TDM)**: Specialized asynchronous copy system for GFX1250 that uses multi-dimensional descriptors for high-performance memory movement [third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.cpp1-136](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.cpp#L1-L136)

## Tensor Data Mover (TDM) Operations

 TDM is a feature introduced for GFX1250 that allows asynchronous, multi-dimensional tensor transfers between global memory and LDS.

 
### TDM Descriptors

 TDM uses complex descriptors composed of multiple 32-bit words (SGPRs). These descriptors are handled as flat structs in MLIR and unpacked into vector groups for LLVM intrinsics.

 
 - **1D-2D Descriptors**: 2 vector groups (`<4 x i32>` and `<8 x i32>`) [third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.h18-20](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.h#L18-L20)
 - **3D-5D Descriptors**: 4 vector groups (additional `<4 x i32>` groups) [third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.h19-20](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.h#L19-L20)
 
 
### TDM Lowering Logic

 The `TDMUtility` handles the generation of TDM instructions. Key functions include:

 
 - `createTDMDescriptor`: Builds the base descriptor from tensor metadata (shape, strides, padding) [third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.cpp63-69](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.cpp#L63-L69)
 - `updateTensorDescriptor`: Implements `amdg.update_tensor_descriptor` by incrementally bumping `global_addr` or overwriting bounds [third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.cpp52-57](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.cpp#L52-L57)
 - `emitTDMLoadStore`: Emits the actual `llvm.amdgcn.tensor.load.to.lds` or `llvm.amdgcn.tensor.store.from.lds` intrinsics [third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.cpp110-120](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.cpp#L110-L120)
 
 
### TDM Warp Distribution

 To maximize throughput, TDM requires aligning warps to LDS partitions. `distributeTDMWarpsAlignToPartition` computes a warp distribution that ensures each warp's chunk stays within a single partition piece [third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.cpp81-130](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/TDMUtility.cpp#L81-L130)

## AMD Buffer Operations

 
### Resource Descriptors

## Direct-to-LDS Operations

 Direct-to-LDS allows memory loads to write directly to shared memory without using VGPRs for intermediate storage.

 
### Architecture Support and Scattering

 
| Architecture | Scattering Support | Supported Bit Widths |
|---|---|---|
| GFX9 (CDNA1) | No | Warp-coalesced only |
| CDNA3 | No | 32 |
| CDNA4 | No | 128, 32 |
| GFX1250 | Yes | 128, 64, 32 |

## Memory Synchronization and Fences

 
### Fence Emission

 The `emitFence` function generates `LLVM::FenceOp` based on the requested `MemSemantic` and `MemSyncScope`. It maps Triton scopes to AMD-specific strings:

 
 - `MemSyncScope::GPU` -> `"agent"` [third_party/amd/lib/TritonAMDGPUToLLVM/LoadStoreOpToLLVM.cpp38](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/LoadStoreOpToLLVM.cpp#L38-L38)
 - `MemSyncScope::CTA` -> `"workgroup"` [third_party/amd/lib/TritonAMDGPUToLLVM/LoadStoreOpToLLVM.cpp40](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/LoadStoreOpToLLVM.cpp#L40-L40)
 
 
### Atomic Operation Ordering

 For buffer-atomic instructions, fences are emitted pre- or post-atomic based on release/acquire semantics:

 
 - **Acquire (Agent)**: `s_waitcnt vmcnt(0)` followed by `buffer_inv sc1=1` to invalidate L1/L2 caches [third_party/amd/lib/TritonAMDGPUToLLVM/LoadStoreOpToLLVM.cpp109-117](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/LoadStoreOpToLLVM.cpp#L109-L117)
 - **Release (Agent)**: `buffer_wbl2 sc1=1` followed by `s_waitcnt vmcnt(0)` to ensure dirty lines are written back [third_party/amd/lib/TritonAMDGPUToLLVM/LoadStoreOpToLLVM.cpp130-141](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/LoadStoreOpToLLVM.cpp#L130-L141)

## Cache Modifiers and Control Bits

 AMD GPUs control caching through System Cache (SC) and Non-Temporal (NT) bits. The mapping depends on whether the operation is a load or a store:

 
| Modifier | Load Bits (SC0, SC1, NT) | Store Bits (SC0, SC1, NT) |
|---|---|---|
| CA / WB | 0, 0, 0 | 0, 0, 0 |
| CG | 1, 0, 1 | 0, 0, 0 |
| CS | 1, 0, 1 | 1, 0, 1 |
| CV / WT | 1, 1, x | 1, 1, x |
