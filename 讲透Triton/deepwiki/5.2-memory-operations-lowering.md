## Purpose and Scope

 This page describes how memory operations (load, store, atomic, and asynchronous copy operations) are lowered from Triton IR to LLVM IR during backend compilation. The lowering process transforms high-level tensor memory operations into target-specific load/store instructions with appropriate vectorization, predication, and cache control.

 For information about layout conversion operations that move data through shared memory, see [Layout Conversion Lowering](https://deepwiki.com/triton-lang/triton/5.3-layout-conversion-lowering). For general lowering infrastructure, see [TritonGPU to LLVM Lowering Framework](https://deepwiki.com/triton-lang/triton/5.1-tritongpu-to-llvm-lowering-framework).

## Load Operation Lowering

 
### Basic Load Lowering Process

 The `tt.load` operation is lowered by unpacking tensor pointers and values into scalars, determining vectorization based on memory contiguity, and generating predicated LLVM loads. In the NVIDIA backend, this is often implemented via `PTXBuilder` to emit specific `ld.global` instructions with cache modifiers.

 
```

```

 The lowering implementation uses `unpackUniqueTensorElements` [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/LoadStoreOpToLLVM.cpp183-184](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/LoadStoreOpToLLVM.cpp#L183-L184) to retrieve individual pointers and `packUniqueTensorElements` [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/LoadStoreOpToLLVM.cpp208-209](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/LoadStoreOpToLLVM.cpp#L208-L209) to assemble the final result.

 The vector size for loads is determined by analyzing memory access patterns, primarily looking at the contiguity of the layout and the alignment of pointers and masks. The `LoadStoreConversionBase` class provides helpers to compute these values.

### Masked Loads with Constant Fallbacks

 When a load has a mask and "other" value (for out-of-bounds elements), the compiler generates predicated code. If the "other" value is a constant, the compiler can optimize the initialization of the destination register.

 
```

```

 For scalar masked loads with constant zero fallbacks, the code uses `mov.u32 $0, 0x0` followed by a predicated load [test/Conversion/tritongpu_to_llvm.mlir34-36](https://github.com/triton-lang/triton/blob/f893845b/test/Conversion/tritongpu_to_llvm.mlir#L34-L36)
