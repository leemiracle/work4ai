## Purpose and Scope

 This document describes the NVIDIA-specific optimization passes and transformations applied during compilation for CUDA targets. These passes operate on the TritonGPU IR (TTGIR) and during lowering to LLVM IR, tailoring the code for specific NVIDIA GPU architectures (Ampere, Hopper, Blackwell). The pipeline is designed to exploit hardware-specific features like the Tensor Memory Accelerator (TMA), Warp Group MMA (WGMMA), and Blackwell's Tensor Memory (TMEM).

 **Sources:** [third_party/nvidia/backend/compiler.py1-35](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L1-L35) [python/src/passes.cc59-118](https://github.com/triton-lang/triton/blob/f893845b/python/src/passes.cc#L59-L118)

## Architecture Tiers and Feature Support

 NVIDIA-specific optimizations are applied based on the target GPU's compute capability. The compiler recognizes three major architecture tiers:

 
| Architecture | Compute Capability | Key Features | Specific Optimizations |
|---|---|---|---|
| Ampere and Earlier | < 90 | MMAv2, standard async copy | Standard pipeline, tensor descriptor rewriting |
| Hopper | 90 | TMA (Tensor Memory Accelerator), Warp Specialization, MMAv3 (WGMMA) | Hopper warp specialization, TMA lowering, multi-stage pipelining |
| Blackwell | ≥ 100 | TMEM (Tensor Memory), TCGen5 (MMAv5), Enhanced TMA | TMEM allocation/optimization, LHS TMEM promotion, TMEM interleaving |

 **Sources:** [third_party/nvidia/backend/compiler.py102-105](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L102-L105) [third_party/nvidia/backend/compiler.py252-323](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L252-L323)

## Hopper and Blackwell Core Operations

 
### Warp Group Dot (WGMMA)

 On Hopper (SM90), `ttng.warp_group_dot` leverages the `wgmma` instruction set.

 
 - **Requirements:** The number of warps must be divisible by 4 for warp-group operations [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/WGMMA.cpp96-128](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/WGMMA.cpp#L96-L128)
 - **Precision:** Supports `f16`, `bf16`, `tf32`, `s8`, `e5m2`, and `e4m3` operand types [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/WGMMA.cpp53-70](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/WGMMA.cpp#L53-L70)
 - **Async Execution:** Utilizes `nvgpu.wgmma` to overlap computation with memory transfers [test/Conversion/tritongpu_to_llvm_hopper.mlir22-30](https://github.com/triton-lang/triton/blob/f893845b/test/Conversion/tritongpu_to_llvm_hopper.mlir#L22-L30)
 
 
### TCGen5 MMA (Blackwell)

 Blackwell introduces `ttng.tc_gen5_mma`, targeting the MMAv5 architecture.

 
 - **Tensor Memory (TMEM):** Accumulators are stored in TMEM using `#ttng.tensor_memory_encoding` [test/Conversion/tritongpu_to_llvm_blackwell.mlir7](https://github.com/triton-lang/triton/blob/f893845b/test/Conversion/tritongpu_to_llvm_blackwell.mlir#L7-L7)
 - **Scaled MMA:** `ttng.tc_gen5_mma_scaled` provides hardware acceleration for scaled dot products, particularly for FP4/MX formats [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv5.cpp111-120](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv5.cpp#L111-L120)
 - **Instruction Descriptor:** The compiler generates a 32-bit `TCGen5InstructionDescriptor` to configure sparsity, data types, and negation for the `tcgen05.mma` PTX instruction [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv5.cpp159-179](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/DotOpToLLVM/MMAv5.cpp#L159-L179)

## NVIDIA-Specific Passes

 
### Plan CTA Pass

 The **Plan CTA** pass (`nvidia.passes.ttnvgpuir.add_plan_cta`) establishes Cooperative Thread Array (CTA) layouts. It is critical for multi-CTA kernels and cluster-scoped operations [third_party/nvidia/backend/compiler.py265](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L265-L265)

 
### TMA Lowering (SM90+)

 The **TMA Lowering** pass (`nvidia.passes.ttnvgpuir.add_tma_lowering`) converts high-level tensor descriptor operations into TMA-specific instructions.

 
 - **Implementation:** Lowers to `cp.async.bulk.tensor` PTX [third_party/nvidia/backend/compiler.py307](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L307-L307)
 - **Descriptor Management:** Manages the creation and encoding of `tensordesc` attributes [lib/Dialect/TritonNvidiaGPU/Transforms/TMALowering.cpp](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonNvidiaGPU/Transforms/TMALowering.cpp)
 
 
### Blackwell TMEM Optimizations

 
 - **`add_hoist_tmem_alloc`**: Hoists TMEM allocations out of loops to prevent repeated allocation overhead and maintain persistence of values in TMEM [include/triton/Dialect/TritonGPU/Transforms/Passes.td52-68](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Dialect/TritonGPU/Transforms/Passes.td#L52-L68)
 - **`add_promote_lhs_to_tmem`**: Moves the LHS operand of a dot operation into TMEM to utilize the higher bandwidth between TMEM and the TCGen5 MMA unit [third_party/nvidia/backend/compiler.py289](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L289-L289)
 - **`add_interleave_tmem`**: Optimizes the scheduling of TMEM accesses to overlap with computation [third_party/nvidia/backend/compiler.py310](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/backend/compiler.py#L310-L310)
 
 
### Warp Specialization

 NVIDIA targets support automatic warp specialization, where different warp groups within a CTA perform different tasks (e.g., one group for memory loading, another for MMA).

 
 - **`add_warp_specialize`**: Partitions the kernel into specialized regions [include/triton/Dialect/TritonGPU/Transforms/Passes.td99-108](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Dialect/TritonGPU/Transforms/Passes.td#L99-L108)
 - **`add_optimize_partition_warps`**: Reduces the number of warps assigned to specific partitions to save registers [include/triton/Dialect/TritonGPU/Transforms/Passes.td159-167](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Dialect/TritonGPU/Transforms/Passes.td#L159-L167)

## LLVM Lowering Implementation

 
### Memory Operations

 NVIDIA lowering uses `PTXBuilder` to emit specialized instructions for different memory spaces:

 
 - **Shared Memory:** Uses `ldmatrix` and `stmatrix` for efficient vector access [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/MemoryOpToLLVM.cpp76-114](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/MemoryOpToLLVM.cpp#L76-L114)
 - **TMEM Access:** Uses `tcgen05.st.sync.aligned` and `tcgen05.ld.sync.aligned`. The `TMemCopyAtom` determines the row/column shape and multicast properties for these accesses [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/TensorMemoryToLLVM.cpp28-52](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/TensorMemoryToLLVM.cpp#L28-L52) [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/TensorMemoryToLLVM.cpp154-187](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/TensorMemoryToLLVM.cpp#L154-L187)
 
 
### Synchronization

 
 - **MBarrier:** Implements `ttng.init_barrier` and `ttng.wait_barrier` using PTX `mbarrier` instructions [third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/MemoryOpToLLVM.cpp36-57](https://github.com/triton-lang/triton/blob/f893845b/third_party/nvidia/lib/TritonNVIDIAGPUToLLVM/MemoryOpToLLVM.cpp#L36-L57)
 - **NVVM Barriers:** Lowers synchronization points to `nvvm.barrier` and `nvvm.elect.sync` for warp-level control flow [test/Conversion/tritongpu_to_llvm_blackwell.mlir14-16](https://github.com/triton-lang/triton/blob/f893845b/test/Conversion/tritongpu_to_llvm_blackwell.mlir#L14-L16)
