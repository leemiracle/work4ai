## Purpose and Scope

 This page documents the Gluon type system and memory descriptor abstractions used in the experimental Gluon frontend. Gluon extends Triton's type system with hardware-aware types that explicitly model distributed tensors and GPU memory hierarchies (shared memory, tensor memory). These types enable fine-grained control over data layout and memory placement.

 For information about Gluon's layout system (BlockedLayout, NVMMASharedLayout, etc.), see [Layout Encoding Attributes](https://github.com/triton-lang/triton/blob/f893845b/Layout Encoding Attributes) For hardware-specific operations using these descriptors, see [Hardware-Specific Operations (Hopper, Blackwell)](https://github.com/triton-lang/triton/blob/f893845b/Hardware-Specific Operations (Hopper, Blackwell))

## Distributed Type

 
### Definition and Purpose

 The `distributed_type` represents a tensor that is distributed across GPU threads, warps, and CTAs according to a specific layout. It is the primary type for computational tensors in Gluon kernels.

 
```

```

 **Sources:** [python/triton/experimental/gluon/language/_core.py151-183](https://github.com/triton-lang/triton/blob/f893845b/python/triton/experimental/gluon/language/_core.py#L151-L183) [python/triton/experimental/gluon/language/_layouts.py11-120](https://github.com/triton-lang/triton/blob/f893845b/python/triton/experimental/gluon/language/_layouts.py#L11-L120)

 
### Construction and Usage

 Distributed types are constructed by specifying element type, shape, and layout. Gluon validates that the layout rank matches the tensor rank (unless using `AutoLayout` or `CoalescedLayout`).

 
```

```

 **Key Properties:**

 
 - **element_ty**: Scalar data type (e.g., `float16`, `int32`).
 - **shape**: Tensor dimensions as a list of integers.
 - **layout**: A `DistributedLayout` instance describing thread-to-data mapping.
 - **cga_layout**: Describes how CTAs tile dimensions in a Cluster Grid Array (CGA).
 
 **Sources:** [python/triton/experimental/gluon/language/_core.py151-183](https://github.com/triton-lang/triton/blob/f893845b/python/triton/experimental/gluon/language/_core.py#L151-L183) [python/test/gluon/test_frontend.py64-85](https://github.com/triton-lang/triton/blob/f893845b/python/test/gluon/test_frontend.py#L64-L85)

## Shared Memory Descriptors

 
### Overview

 Shared memory descriptors (`shared_memory_descriptor`) are handles to shared memory allocations with associated layout information. They enable explicit management of shared memory with operations like loading, storing, slicing, and indexing.

 
```

```

 **Sources:** [python/triton/experimental/gluon/language/_core.py185-406](https://github.com/triton-lang/triton/blob/f893845b/python/triton/experimental/gluon/language/_core.py#L185-L406)

 
### Type Structure

 The `shared_memory_descriptor_type` contains:

 
| Field | Description |
|---|---|
| element_ty | Scalar element type (e.g., float16, int32) |
| shape | Logical shape of the memory region |
| layout | SharedLayout instance (e.g., NVMMASharedLayout, SwizzledSharedLayout, SharedLinearLayout) |
| alloc_shape | Actual allocated shape (may differ from logical shape for subviews) |

 **Sources:** [python/triton/experimental/gluon/language/_core.py185-221](https://github.com/triton-lang/triton/blob/f893845b/python/triton/experimental/gluon/language/_core.py#L185-L221)

 
### Allocation and Initialization

 Shared memory is allocated using `allocate_shared_memory`. This generates a `ttg.local_alloc` operation in MLIR.

 
```

```

### Memory Operations

 
#### Load and Store

 Loading from shared memory converts it to a distributed tensor, while storing writes a distributed tensor to shared memory.

 
```

```

 **Sources:** [python/triton/experimental/gluon/language/_core.py259-280](https://github.com/triton-lang/triton/blob/f893845b/python/triton/experimental/gluon/language/_core.py#L259-L280) [python/test/gluon/test_core.py172-177](https://github.com/triton-lang/triton/blob/f893845b/python/test/gluon/test_core.py#L172-L177)

 
### Subview Operations

 Shared memory descriptors support creating subviews without copying data. These generate MLIR ops like `ttg.memdesc_subslice`, `ttg.memdesc_index`, and `ttg.memdesc_trans`.

 
| Operation | Description |
|---|---|
| slice(start, length, dim) | Create a slice along dimension dim. |
| index(idx) | Index the first dimension. |
| permute(order) | Permute dimensions (transposition). |
| reshape(shape) | Reshape to new logical shape. |

## Tensor Memory Descriptors (Blackwell)

 
### Architecture-Specific Type

 Tensor memory descriptors (`tensor_memory_descriptor`) are Blackwell-specific types for accessing on-chip tensor memory (TMEM). They follow a similar pattern to shared memory descriptors but with different layout constraints.

 
```

```

 **Sources:** [python/triton/experimental/gluon/language/nvidia/blackwell/__init__.py149-372](https://github.com/triton-lang/triton/blob/f893845b/python/triton/experimental/gluon/language/nvidia/blackwell/__init__.py#L149-L372)

 
### TensorMemoryLayout

 The `TensorMemoryLayout` class defines how data is organized in TMEM:

 
| Field | Description |
|---|---|
| block | (M, N) tuple defining tile size per CTA. |
| col_stride | Stride between adjacent columns. |
| cga_layout | CGA layout bases for multi-CTA access. |
| fp4_padded | Whether operand A uses padded MMAv5 FP4 layout. |

## Bidirectional Layout Mapping

 Gluon provides a bidirectional mapping between Python layout objects and MLIR encoding attributes.

 
| MLIR Encoding | Python Layout Class |
|---|---|
| ttg::BlockedEncodingAttr | BlockedLayout |
| ttg::SliceEncodingAttr | SliceLayout |
| ttg::LinearEncodingAttr | DistributedLinearLayout |
| ttg::NVMMASharedEncodingAttr | NVMMASharedLayout |
| ttng::TensorMemoryEncodingAttr | TensorMemoryLayout |
| ttag::AMDMFMAEncodingAttr | AMDMFMALayout |
