## Purpose and Scope

 The LinearLayout System provides a **canonical mathematical representation** for all layout encodings in TritonGPU. It acts as a universal intermediate representation that enables reasoning about data distribution across the GPU's compute hierarchy (threads, warps, blocks) in a uniform way, independent of the specific encoding format [include/triton/Tools/LinearLayout.h24-31](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Tools/LinearLayout.h#L24-L31)

 This page covers the structure and operations of the `LinearLayout` abstraction. For information about specific layout encoding attributes (e.g., `BlockedEncodingAttr`, `NvidiaMmaEncodingAttr`), see **3.3 Layout Encoding Attributes**. For shared memory layouts, see **3.5 Memory Descriptors and Shared Memory Layouts**.

 
---

 
## What is LinearLayout?

 `LinearLayout` is a mathematical structure that represents how tensor elements are distributed across GPU computational units using **linear algebra**. It maps from the GPU's hierarchical compute structure (registers, lanes, warps, blocks) to logical tensor coordinates [include/triton/Tools/LinearLayout.h24-31](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Tools/LinearLayout.h#L24-L31)

 The key insight is that most GPU layouts can be expressed as a **linear transformation** defined by a set of basis vectors [include/triton/Tools/LinearLayout.h33-49](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Tools/LinearLayout.h#L33-L49) This canonical representation enables:

 
 - **Layout comparison**: Determine if two different encodings represent the same data distribution [lib/Dialect/TritonGPU/IR/Dialect.cpp157-165](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/IR/Dialect.cpp#L157-L165)
 - **Layout composition**: Combine layouts (e.g., CTA layout + CGA layout) [lib/Dialect/TritonGPU/IR/LinearLayoutConversions.cpp95-96](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/IR/LinearLayoutConversions.cpp#L95-L96)
 - **Layout inference**: Deduce output layouts from input layouts for operations, such as reshape or transpose [lib/Dialect/TritonGPU/IR/Dialect.cpp106-112](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/IR/Dialect.cpp#L106-L112)
 - **Optimization**: Identify when layout conversions are no-ops or can be done efficiently [lib/Dialect/TritonGPU/IR/Dialect.cpp83-89](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/IR/Dialect.cpp#L83-L89)

## LinearLayout Structure

 
### Input and Output Dimensions

 A `LinearLayout` has two types of dimensions:

 **Input Dimensions** (for distributed/register layouts) [include/triton/Dialect/TritonGPU/IR/LinearLayoutConversions.h23-28](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Dialect/TritonGPU/IR/LinearLayoutConversions.h#L23-L28):

 
 - `"register"`: Elements held by a single thread.
 - `"lane"`: Threads within a warp (typically 32 for NVIDIA, 64 for AMD).
 - `"warp"`: Warps within a CTA/block.
 - `"block"`: Blocks in a cluster (CGA).
 
 **Input Dimensions** (for shared memory layouts) [include/triton/Dialect/TritonGPU/IR/LinearLayoutConversions.h30-36](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Dialect/TritonGPU/IR/LinearLayoutConversions.h#L30-L36):

 
 - `"offset"`: The n'th element in the allocation within a thread block.
 - `"block"`: Blocks in a cluster.
 
 **Output Dimensions** [include/triton/Dialect/TritonGPU/IR/LinearLayoutConversions.h38-42](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Dialect/TritonGPU/IR/LinearLayoutConversions.h#L38-L42):

 
 - `"dim0"`, `"dim1"`, ..., `"dimN"`: The location in the n'th logical dimension of the output tensor.

### BlockedEncodingAttr Conversion

 The conversion follows the `order` of the blocked layout, assigning bases to `"register"`, `"lane"`, `"warp"`, and `"block"` dimensions based on `sizePerThread`, `threadsPerWarp`, and `warpsPerCTA`.

 
### MMA Layout Conversions

 MMA layouts are specialized for hardware matrix engines.

 
 - **NVIDIA MMA**: Maps threads and registers to fragments based on instruction shape (e.g., 16x8x16) [unittest/Dialect/TritonGPU/DialectTest.cpp66-70](https://github.com/triton-lang/triton/blob/f893845b/unittest/Dialect/TritonGPU/DialectTest.cpp#L66-L70)
 - **AMD MFMA**: Configures layouts based on instruction shape and element bitwidth [unittest/Dialect/TritonGPU/LinearLayoutConversionsTest.cpp62-75](https://github.com/triton-lang/triton/blob/f893845b/unittest/Dialect/TritonGPU/LinearLayoutConversionsTest.cpp#L62-L75)
 
 
### Shared Memory Layout Conversions

 Shared memory layouts include swizzling to avoid bank conflicts.

 
 - **SwizzledShared**: Implements the `((c / vec) ^ (r / perPhase)) * vec` pattern (simplified) [lib/Dialect/TritonGPU/IR/LinearLayoutConversions.cpp80-84](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/IR/LinearLayoutConversions.cpp#L80-L84)
 - **NVMMAShared**: Uses `getCoreMatrixLinearLayout()` to define the 8x8 core matrix tiling [lib/Dialect/TritonGPU/IR/LinearLayoutConversions.cpp154-195](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/IR/LinearLayoutConversions.cpp#L154-L195)

## LinearEncodingAttr: MLIR Wrapper

 `LinearEncodingAttr` is an MLIR attribute that wraps a `LinearLayout` for use in the IR [include/triton/Dialect/TritonGPU/IR/TritonGPUAttrDefs.td908-915](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Dialect/TritonGPU/IR/TritonGPUAttrDefs.td#L908-L915) It implements the `DistributedEncodingTrait`, allowing it to participate in standard TritonGPU transformations.

 
### Key Methods

 
 - `getTotalElemsPerThread()`: Calculates the total registers required [lib/Dialect/TritonGPU/IR/Dialect.cpp126-129](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/IR/Dialect.cpp#L126-L129)
 - `getUniqueElemsPerThread()`: Calculates elements per thread ignoring register broadcasting [lib/Dialect/TritonGPU/IR/Dialect.cpp131-136](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/IR/Dialect.cpp#L131-L136)

 - **ViewOpToLLVM**: Uses `toLinearLayout` during `JoinOp` conversion to determine register mapping and contiguity [lib/Conversion/TritonGPUToLLVM/ViewOpToLLVM.cpp149-163](https://github.com/triton-lang/triton/blob/f893845b/lib/Conversion/TritonGPUToLLVM/ViewOpToLLVM.cpp#L149-L163)

## Summary of Operations

 The `LinearLayout` class supports several algebraic operations [include/triton/Tools/LinearLayout.h95-107](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Tools/LinearLayout.h#L95-L107):

 
| Operation | Method | Description |
|---|---|---|
| Multiplication | operator* | Combines two layouts by appending or merging input dimensions unittest/Tools/LinearLayoutTest.cpp68-77 |
| Composition | compose | Chains two layouts (L1 ∘ L2). |
| Inversion | invertAndCompose | Finds the mapping from one layout's output to another's input lib/Tools/LayoutUtils.cpp39-41 |
| Transpose | transposeOuts | Reorders the output dimensions unittest/Tools/LinearLayoutTest.cpp149-162 |
| Flattening | flattenIns / flattenOuts | Collapses multiple dimensions into a single linear dimension lib/Dialect/TritonGPU/IR/Dialect.cpp75-76 |
