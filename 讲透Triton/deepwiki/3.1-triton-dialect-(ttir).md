  The Triton Dialect (TTIR) is the high-level, layout-agnostic intermediate representation in the Triton compiler. It represents tensor operations without any GPU-specific layout information, serving as the first MLIR dialect in the compilation pipeline after Python AST parsing. TTIR operations capture the semantics of user-written kernel code using operations like `tt.load`, `tt.store`, `tt.dot`, and core control flow.

 For information about GPU-specific layout representations, see **3.2 TritonGPU Dialect and Layout System**. For the Python-to-TTIR generation process, see **2.4 Code Generator (AST to MLIR)**.

## Core Characteristics

 TTIR has the following properties:

 
| Characteristic | Description |
|---|---|
| Layout Agnostic | No GPU-specific data distribution information (registers vs. shared memory) |
| Tensor-based | Operations work on multi-dimensional tensors as primary units |
| Type Rich | Strong type system with pointers (tt.ptr), tensors, and specialized scalars |
| Target Independent | Can be lowered to NVIDIA, AMD, or CPU backends |
| Verifiable | Built-in verification logic ensures IR structural correctness |

 The dialect uses the prefix `tt` for operations (e.g., `tt.load`, `tt.dot`). It utilizes `TensorSizeTrait` and `VerifyTensorLayoutsTrait` to maintain IR integrity [include/triton/Dialect/Triton/IR/TritonOps.td27-30](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Dialect/Triton/IR/TritonOps.td#L27-L30)

## Canonicalization and Optimization

 TTIR includes a robust set of rewrite patterns to simplify the IR before layout assignment.

 
### Key Canonicalization Patterns

 
 - **Mask Folding**: `tt.load` or `tt.store` with a constant splat mask of `true` is simplified to a non-masked operation [lib/Dialect/Triton/IR/Ops.cpp64-99](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/Triton/IR/Ops.cpp#L64-L99)
 - **Pointer Arithmetic Folding**: Multiple `tt.addptr` operations are combined into a single offset calculation if they don't overflow [lib/Dialect/Triton/Transforms/Combine.cpp23-62](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/Triton/Transforms/Combine.cpp#L23-L62)
 - **Transpose Folding**: Consecutive `tt.trans` operations are merged by composing their permutation orders [lib/Dialect/Triton/IR/Ops.cpp176-201](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/Triton/IR/Ops.cpp#L176-L201)
 - **Select-Masked-Load Fusion**: Fuses `arith.select` into a `tt.load` mask to avoid redundant branching [lib/Dialect/Triton/Transforms/Combine.cpp71-108](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/Triton/Transforms/Combine.cpp#L71-L108)
 
 
### TTIR Combine Pass

 The `TritonCombineOps` pass applies more complex optimizations:

 
 - **Dot-Add Fusion**: Fuses `arith.addf` into the accumulator of a `tt.dot` [test/Triton/combine.mlir36-40](https://github.com/triton-lang/triton/blob/f893845b/test/Triton/combine.mlir#L36-L40)
 - **Broadcast-Mul-Reduce to Dot**: Recognizes patterns like `sum(x * y)` where `x` and `y` are broadcasted and converts them into an efficient `tt.dot` [lib/Dialect/Triton/Transforms/Combine.cpp112-195](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/Triton/Transforms/Combine.cpp#L112-L195)
