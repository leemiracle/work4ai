## Purpose and Scope

 This page documents AMD-specific implementations of warp-level shuffle operations and reduction algorithms in the Triton compiler. These operations enable efficient inter-thread communication within a warp (wavefront) and are fundamental building blocks for collective operations like reductions and layout conversions.

 For general layout conversion lowering mechanisms, see [Layout Conversion Lowering](https://deepwiki.com/triton-lang/triton/5.3-layout-conversion-lowering). For general reduction operation lowering, see [Reduction and Scan Operations Lowering](https://deepwiki.com/triton-lang/triton/5.4-reduction-and-scan-operations-lowering). For other AMD-specific memory operations, see [AMD Load/Store and Memory Operations](https://deepwiki.com/triton-lang/triton/5.7.2-amd-loadstore-and-memory-operations).

 **Key Topics Covered:**

 
 - Shuffle instruction selection and implementation (XOR, Up, Index-based).
 - Warp reduction strategies using DPP and permlane instructions.
 - Architecture-specific optimizations for CDNA and RDNA families.
 - Layout conversion optimizations using `permlane_swap`.

## Shuffle Operations

 
### Overview

 AMD GPUs provide multiple instruction types for shuffling data between lanes in a warp. The Triton compiler selects the appropriate instruction based on the ISA family, shuffle type, and distance/stride parameters. The main shuffle variants are:

 
| Shuffle Type | Function | Purpose |
|---|---|---|
| Butterfly (XOR) | shuffleXor(val, i) | XOR-based shuffle for tree-like communication patterns |
| Up | shuffleUp(val, i) | Read from lane at laneId - i |
| Index | shuffleIdx(val, i) | Read from specific lane i |
| Permute | permute(a, b, selector) | Byte-level permutation across two values |

 All shuffle operations handle data types by promoting values smaller than 32 bits to `i32`, splitting 64-bit values into two `f32` values, and recursively shuffling each part.

### DPP-Based Shuffle Patterns

 For modern AMD architectures (CDNA2+, RDNA3+), the compiler uses Data Parallel Primitives (DPP) instructions for efficient intra-row shuffles. DPP operations are performed using `ROCDL::DPPUpdateOp` with specific control codes defined in `DppCtrl`.

 
| Stride | DPP Pattern | Row Mask | Bank Mask | Description |
|---|---|---|---|---|
| 1 | QUAD_PERM 1,0,3,2 | 0xf | 0xf | Swap adjacent pairs in quads |
| 2 | QUAD_PERM 2,3,0,1 | 0xf | 0xf | Swap quad halves |
| 4 | ROW_SHR:4 + ROW_SHL:4 | 0xf | 0xa/0x5 | Right shift 4, combine with left shift 4 |
| 8 | ROW_SHR:8 + ROW_SHL:8 | 0xf | 0xc/0x3 | Right shift 8, combine with left shift 8 |

### Hardware Permlane-Based Reduction

 For CDNA4 and GFX1250, specialized reduction intrinsics provide efficient warp reductions for specific interleaved patterns. These are implemented via `permuteAndReduce` which wraps the `llvm.amdgcn.permlane32.swap` and `llvm.amdgcn.permlane16.swap` intrinsics.

 
 - **CDNA4 (`warpReduceSwap16or32`)**: Handles cases where `numLaneToReduce == 2` with `interleave == 32`, or `numLaneToReduce == 4` with `interleave == 16` [third_party/amd/lib/TritonAMDGPUToLLVM/TargetInfo.cpp292-322](https://github.com/triton-lang/triton/blob/f893845b/third_party/amd/lib/TritonAMDGPUToLLVM/TargetInfo.cpp#L292-L322)

### DPP-Based Full Warp Reduction

 For full warp reductions on GCN/CDNA/RDNA (where `reduceLaneIdMask == warpSize - 1`), the compiler emits a tree reduction using DPP instructions.

 **Reduction Steps for CDNA (64-lane warp):**

 
 - **Intra-row reduction**: Uses `ROW_SHR` with distances 8, 4, 2, and 1 to reduce within each 16-lane row.
 - **Cross-row reduction**: 
 - Uses `BCAST15` to reduce across the first two rows.
 - Uses `BCAST31` to reduce across the 32-lane halves.
 - **Final Broadcast**: Uses `ROCDL::ReadlaneOp` to broadcast the result from lane 63 to all threads.
