  This page describes the JIT (Just-In-Time) compilation system and caching mechanisms in Triton. It covers how the `@triton.jit` decorator transforms Python functions into GPU kernels, how specialization works based on argument types, and how compiled kernels are cached for reuse.

 
## Overview

 The JIT compilation system in Triton consists of several key components that work together to transform decorated Python functions into cached, specialized GPU kernels:

 
```

```

 **Diagram: High-level JIT compilation and caching flow**

 The system performs the following steps:

 
 - Decorator creates a `JITFunction` wrapper around the Python function [python/triton/runtime/jit.py612-647](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L612-L647)
 - On first invocation, arguments are analyzed to generate a specialized signature [python/triton/runtime/jit.py689-778](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L689-L778)
 - A cache key is computed from the function source, dependencies, and signature [python/triton/runtime/jit.py498-519](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L498-L519)
 - The cache is checked; if found, the cached kernel is used [python/triton/compiler/compiler.py226-362](https://github.com/triton-lang/triton/blob/f893845b/python/triton/compiler/compiler.py#L226-L362)
 - If not cached, the kernel is compiled and stored for future use [python/triton/compiler/compiler.py372-520](https://github.com/triton-lang/triton/blob/f893845b/python/triton/compiler/compiler.py#L372-L520)

## The @triton.jit Decorator

 The `@triton.jit` decorator is the entry point for marking Python functions as Triton kernels. It creates a `JITFunction` object that manages compilation, caching, and execution.

 
```

```

 **Diagram: Decorator transformation**

 The decorator accepts several optional parameters:

 
 - `do_not_specialize`: List of parameter names that should not be specialized on their runtime values [python/triton/runtime/jit.py612-615](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L612-L615)
 - `do_not_specialize_on_alignment`: List of parameter names that should not be specialized on pointer alignment [python/triton/runtime/jit.py616-619](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L616-L619)
 - `noinline`: If True, prevents the function from being inlined when called from other kernels [python/triton/runtime/jit.py620-621](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L620-L621)

## JITCallable and JITFunction Classes

 
### JITCallable Base Class

 `JITCallable` is the base class providing common functionality for source extraction, dependency tracking, and hashing.

 
| Attribute | Type | Description |
|---|---|---|
| fn | Callable | The original Python function python/triton/runtime/jit.py456 |
| _src | str | Cleaned source code without decorators python/triton/runtime/jit.py476 |
| hash | str | Cached hash value for the function python/triton/runtime/jit.py461 |
| used_global_vals | Dict | Tracked global variables and their values python/triton/runtime/jit.py463 |

 Key methods:

 
 - `cache_key`: Computes or returns cached SHA-256 hash of the function and dependencies [python/triton/runtime/jit.py498-519](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L498-L519)
 - `parse()`: Parses the source code into an AST [python/triton/runtime/jit.py527-532](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L527-L532)

## Specialization and Signature Generation

 Triton specializes kernels based on runtime types and properties of arguments. This allows the compiler to generate optimized code for specific configurations (e.g., specific integer values or pointer alignments).

 
### Specialization Components

 For each parameter, the system extracts:

 
 - **Type information**: The `tl.dtype` or pointer type.
 - **Value specialization**: For non-pointer types (unless `do_not_specialize` is set).
 - **Alignment**: Pointer alignment (unless `do_not_specialize_on_alignment` is set).
 
 The `create_function_from_signature()` function [python/triton/runtime/jit.py391-448](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L391-L448) generates a Python function that efficiently computes this specialization information using `native_specialize_impl` [python/triton/runtime/jit.py22](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L22-L22)

 **Sources:** [python/triton/runtime/jit.py391-448](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L391-L448) [python/triton/runtime/jit.py299-347](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L299-L347)

 
## Cache Key Computation

 The cache key uniquely identifies a compiled kernel. It is computed using the `DependenciesFinder` class, which performs an AST traversal to find transitively called functions and global variables.

 
### DependenciesFinder Class

 `DependenciesFinder` is an `ast.NodeVisitor` that computes a hash based on the source code and references.

## Caching System

 The caching system stores compiled kernels to disk (typically `~/.triton/cache`) to avoid recompilation.

 
### Cache Key Structure

 The final cache key is a SHA-256 hash of:

 
 - **Source code hash**: From `DependenciesFinder` [python/triton/runtime/jit.py54](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L54-L54)
 - **Signature**: Specialization information for the invocation [python/triton/compiler/compiler.py72-76](https://github.com/triton-lang/triton/blob/f893845b/python/triton/compiler/compiler.py#L72-L76)
 - **Constants**: `constexpr` parameter values [python/triton/compiler/compiler.py74](https://github.com/triton-lang/triton/blob/f893845b/python/triton/compiler/compiler.py#L74-L74)
 - **Attributes**: Kernel attributes like `num_warps` or `num_ctas` [python/triton/compiler/compiler.py75](https://github.com/triton-lang/triton/blob/f893845b/python/triton/compiler/compiler.py#L75-L75)
 - **Environment variables**: Vars returned by `get_cache_invalidating_env_vars` [python/triton/compiler/compiler.py4](https://github.com/triton-lang/triton/blob/f893845b/python/triton/compiler/compiler.py#L4-L4)
 
 
### Cache Manager

 The `get_cache_manager(hash)` function [python/triton/runtime/cache.py](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/cache.py) returns a manager for the specific kernel. It manages files like:

 
 - `metadata.json`: Compilation metadata.
 - `kernel.ttir`: Intermediate representation.
 - `kernel.cubin` or `kernel.hsaco`: Final GPU binary.
 
 **Sources:** [python/triton/compiler/compiler.py226-362](https://github.com/triton-lang/triton/blob/f893845b/python/triton/compiler/compiler.py#L226-L362) [python/triton/runtime/jit.py498-519](https://github.com/triton-lang/triton/blob/f893845b/python/triton/runtime/jit.py#L498-L519)
