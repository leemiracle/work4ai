  This document covers Triton's testing infrastructure, including unit tests, MLIR lit tests, and integration tests. The testing framework ensures correctness across the compiler pipeline—from Python AST to MLIR dialects (TTIR, TTGIR) and finally to GPU binaries—while providing utilities for performance benchmarking and autotuning validation.

 
## Test Organization and Structure

 Triton's test suite is organized into Python-based unit/integration tests and C++-based MLIR regression tests.

## Python Testing Framework

 Triton utilizes `pytest` for its Python test suite, integrating hardware-specific markers and deep integration with the JIT runtime.

 
### The `triton.testing` Module

 The `triton.testing` module provides the core utilities for performance measurement and correctness verification.

 
 - **`do_bench`**: Measures kernel execution time using GPU events. It includes a warmup phase and multiple repetitions to provide statistical quantiles [python/triton/testing.py125-130](https://github.com/triton-lang/triton/blob/f893845b/python/triton/testing.py#L125-L130)
 - **`do_bench_cudagraph`**: Minimizes host overhead by capturing the kernel launch into a `torch.cuda.CUDAGraph` and replaying it [python/triton/testing.py188-207](https://github.com/triton-lang/triton/blob/f893845b/python/triton/testing.py#L188-L207)
 - **`assert_close`**: A specialized utility to compare Triton outputs against PyTorch references, handling specific nuances of `bfloat16` and `float8` [python/triton/testing.py83](https://github.com/triton-lang/triton/blob/f893845b/python/triton/testing.py#L83-L83)

## MLIR Lit Tests

 The MLIR-based tests reside in the `test/` directory and are driven by LLVM's `lit` tool. These tests verify the IR transformation passes (e.g., layout conversion, pipelining).

 
### Build System Integration

 The C++ test suite is configured via CMake. It defines `check-triton-lit-tests` which depends on compiler tools like `triton-opt` and `triton-llvm-opt` [test/CMakeLists.txt15-28](https://github.com/triton-lang/triton/blob/f893845b/test/CMakeLists.txt#L15-L28)

 
### FileCheck Verification

 Tests use `FileCheck` to scan the output of `triton-opt` for expected IR patterns. For example, `test_int_annotation` in the Python suite also inspects generated TTIR for specific `arith` instructions [python/test/unit/language/test_annotations.py34-38](https://github.com/triton-lang/triton/blob/f893845b/python/test/unit/language/test_annotations.py#L34-L38)

 
## Performance and Tutorial Tests

 Triton kernels in the `tutorials/` directory act as high-level integration tests. They demonstrate best practices and are often used for benchmarking against vendor libraries (cuBLAS/rocBLAS).

 
 - **Vector Add**: Basic SPMD programming model test [python/tutorials/01-vector-add.py29-55](https://github.com/triton-lang/triton/blob/f893845b/python/tutorials/01-vector-add.py#L29-L55)
 - **Fused Softmax**: Tests SRAM-resident reductions and kernel fusion benefits [python/tutorials/02-fused-softmax.py84-110](https://github.com/triton-lang/triton/blob/f893845b/python/tutorials/02-fused-softmax.py#L84-L110)
 - **Matrix Multiplication**: Validates block-level tiling, pointer arithmetic, and L2 cache optimization via `GROUP_SIZE_M` [python/tutorials/03-matrix-multiplication.py164-178](https://github.com/triton-lang/triton/blob/f893845b/python/tutorials/03-matrix-multiplication.py#L164-L178)
 - **Fused Attention**: A complex test case for Flash Attention v2, testing warp specialization and hardware-specific TMA descriptors on Hopper/Blackwell [python/tutorials/06-fused-attention.py47-53](https://github.com/triton-lang/triton/blob/f893845b/python/tutorials/06-fused-attention.py#L47-L53) [python/tutorials/06-fused-attention.py178-188](https://github.com/triton-lang/triton/blob/f893845b/python/tutorials/06-fused-attention.py#L178-L188)
 
 
## Code Quality and CI Infrastructure

 Triton enforces strict code quality through a `pre-commit` configuration that orchestrates several tools:

 
 - **Ruff**: Used for linting Python code across the core library and backend directories [.pre-commit-config.yaml20-25](https://github.com/triton-lang/triton/blob/f893845b/.pre-commit-config.yaml#L20-L25)
 - **Clang-Format**: Ensures consistent C++ style for the compiler core [.pre-commit-config.yaml37-40](https://github.com/triton-lang/triton/blob/f893845b/.pre-commit-config.yaml#L37-L40)
 - **MyPy**: Performs static type checking on runtime components like `knobs.py` and `driver.py` [pyproject.toml5-15](https://github.com/triton-lang/triton/blob/f893845b/pyproject.toml#L5-L15)
 - **YAML Anchor Expansion**: A custom hook to manage complex GitHub Action workflows by exploding YAML anchors [.pre-commit-config.yaml50-64](https://github.com/triton-lang/triton/blob/f893845b/.pre-commit-config.yaml#L50-L64)
