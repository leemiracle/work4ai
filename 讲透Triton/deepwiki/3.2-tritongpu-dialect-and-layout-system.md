## Purpose and Scope

 The TritonGPU dialect (`ttg.*` operations) represents GPU-specific intermediate representation in the Triton compiler. It extends the hardware-agnostic Triton dialect (`tt.*`) with layout information that describes how tensor data is distributed across GPU threads, warps, and thread blocks. This page covers the core dialect structure, layout encoding attributes, the LinearLayout system, and layout propagation mechanisms.

 For information about specific layout optimization passes (e.g., pipelining, dot operand optimization), see section 4. For vendor-specific dialect extensions, see section 5.6 (NVIDIA) and 5.7 (AMD).

 
---

### Shared Memory Layout Attributes

 
#### SwizzledSharedEncodingAttr

 Layout for data in shared memory with swizzling to avoid bank conflicts. Elements are XORed based on row/column indices to distribute them across banks.

 **Swizzling Logic:**

 
 - `vec`: Elements swizzled in pairs.
 - `perPhase`: Rows that share the same swizzling phase.
 - `maxPhase`: Limits the maximum XOR value.
 
 **Sources:** [include/triton/Dialect/TritonGPU/IR/TritonGPUAttrDefs.td10-89](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Dialect/TritonGPU/IR/TritonGPUAttrDefs.td#L10-L89) [lib/Dialect/TritonGPU/IR/LinearLayoutConversions.cpp50-96](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/IR/LinearLayoutConversions.cpp#L50-L96)

## LinearLayout System

 The `LinearLayout` class provides a canonical representation of all layout encodings as linear transformations from input dimensions (register, lane, warp, block, offset) to output dimensions (tensor indices).

 
### Conversion to LinearLayout

 The dialect provides utility functions to convert any distributed or shared encoding to a `LinearLayout`.

### Layout Analysis via LinearLayout

 LinearLayout enables hardware-agnostic analysis of data distribution:

 
 - `hasPowerOfTwoBases()`: Checks if every non-broadcast basis maps to a single power-of-2 in the output [include/triton/Dialect/TritonGPU/IR/Dialect.h138-140](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Dialect/TritonGPU/IR/Dialect.h#L138-L140)
 - `isPermutationMatrixLayout()`: Checks if the layout is a bijection (bijective) after removing broadcasts [include/triton/Dialect/TritonGPU/IR/Dialect.h142-145](https://github.com/triton-lang/triton/blob/f893845b/include/triton/Dialect/TritonGPU/IR/Dialect.h#L142-L145)

### Canonicalization and Rewriting

 The dialect implements patterns to simplify the IR by folding redundant conversions and views.

 
 - **Convert Folding**: `isConvertTrivial()` checks if two layouts are structurally identical despite having different attributes [lib/Dialect/TritonGPU/IR/Ops.cpp62-70](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/IR/Ops.cpp#L62-L70)
 - **Reshape/Transpose**: `CanonicalizeConvertFromReshape` and `CanonicalizeConvertFromTranspose` pull conversions through view operations to enable further folding [lib/Dialect/TritonGPU/IR/Ops.cpp114-173](https://github.com/triton-lang/triton/blob/f893845b/lib/Dialect/TritonGPU/IR/Ops.cpp#L114-L173)
 - **Splat/Join**: `SplatOpConversion` and `JoinOpConversion` lower these high-level ops to LLVM by calculating contiguous register chunks based on the layout's `LinearLayout` [lib/Conversion/TritonGPUToLLVM/ViewOpToLLVM.cpp26-164](https://github.com/triton-lang/triton/blob/f893845b/lib/Conversion/TritonGPUToLLVM/ViewOpToLLVM.cpp#L26-L164)

## Layout Verification

 TritonGPU enforces strict invariants on layouts during IR verification:

 
 - **Power-of-Two**: Many layouts require dimensions to be powers of two [test/TritonGPU/invalid.mlir18-30](https://github.com/triton-lang/triton/blob/f893845b/test/TritonGPU/invalid.mlir#L18-L30)
 - **Permutation Matrices**: Generic Linear layouts must be permutation matrices after removing broadcasts [test/TritonGPU/invalid.mlir89-105](https://github.com/triton-lang/triton/blob/f893845b/test/TritonGPU/invalid.mlir#L89-L105)
 - **Warp Shuffles**: `force_warp_shuffle` on a conversion requires that the source and destination reside within the same warp [test/TritonGPU/invalid.mlir7-11](https://github.com/triton-lang/triton/blob/f893845b/test/TritonGPU/invalid.mlir#L7-L11)
