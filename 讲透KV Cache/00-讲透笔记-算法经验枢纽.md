## §0 全局视角：KV Cache = 自回归生成的"时间-空间权衡"

```
无 KV Cache:  每生成一个 token, 重算前面所有 token 的 K, V  → O(n²) 慢
有 KV Cache:  K, V 算一次存起来, 后续只算新 token 的 K, V   → O(n) 快
代价:         存所有层的 K, V → 显存爆炸 (长上下文瓶颈)
```

> 🔑 **核心 DNA**：**KV Cache 是 attention 的"内存化"**——用显存换计算，是自回归生成能实用的工程前提。

## §1 八条算法经验

### 算法经验 KV1：自回归生成 vs 并行训练的本质差异

> | | 训练 | 推理（生成）|
> |---|------|------------|
> | 方向 | 全位置并行 | 单向逐步 |
> | KV | 每次重算 | **缓存复用** |
> | 复杂度 | $O(n^2)$ / 全序列 | $O(n)$/新 token |
>
> 这是 LLM 训练 vs 推理的根本差异（应用 TS3 自回归瓶颈）。

### 算法经验 KV2：KV Cache 的内存账

> 对一个 L 层、H 头、d_head 维、batch B、序列长 S 的模型：
> $$\text{KV Cache} = 2 \cdot L \cdot H \cdot d_{head} \cdot S \cdot B \cdot \text{dtype\_size}$$
>
> 例：Llama-7B, S=4096, B=1, fp16 → ~1GB KV cache
>
> **经验**：**KV Cache 显存随序列长度线性增长，这是长上下文瓶颈**。

### 算法经验 KV3：PagedAttention = 操作系统的虚拟内存

> vLLM 的 PagedAttention 把 KV Cache 切成固定大小的 block（像 OS 的 page）：
> - **非连续存储**：逻辑连续，物理分散
> - **按需分配**：用多少分多少
> - **共享**：beam search 共享 prefix
>
> 算法本质：**虚拟内存 + 分页机制**（应用 PT2 nn.Module 层级、N3 参数共享）。

### 算法经验 KV4：MQA / GQA = KV 头共享

> | 架构 | Q 头 | K/V 头 | KV Cache |
> |------|------|--------|----------|
> | MHA（标准）| H | H | 100% |
> | MQA（多查询）| H | **1** | 1/H |
> | GQA（分组查询）| H | H/g | g/H |
>
> 算法本质：**用 Q-K 头对应关系的"漏斗"换 KV Cache 减小**（应用 A4 mask 定义任务、TR3 attention 变体）。

### 算法经验 KV5：量化 KV Cache

> 把 KV Cache 从 fp16 量化到 int8/int4 → 显存减半/4 倍。
>
> 算法本质：**数值精度 vs 显存的权衡**（应用 PT4 AMP、A6 温度）。

### 算法经验 KV6：KV Cache 重排（强化 Ch11 RAG）

> RAG 场景：同一个长文档被多个 query 检索。
> - **共享前缀 KV Cache**：文档部分算一次，多 query 复用
> - **Prompt cache**：系统 prompt 的 KV 缓存
>
> 算法本质：**RAG 的外部 K/V 库 + LLM 的内部 K/V Cache 是同构的**（应用 G1 RAG = 外部 K/V）。

### 算法经验 KV7：投机解码（Speculative Decoding）

> 用小模型快速生成 N 个 token，大模型并行验证：
> - 命中 → 接受 N 个 token
> - 不命中 → 拒绝并修正
>
> 算法本质：**用一致性换并行度**（应用 AG1 Agent 范式、OP3 SGD 噪声）。

### 算法经验 KV8：长上下文的工程极限

> 1M token 上下文的挑战：
> - KV Cache 显存爆（→ GQA + 量化 + offload）
> - Attention 计算慢（→ sparse / linear / sliding window）
> - Lost in the middle（→ rerank）
>
> 算法本质：**长上下文是 attention 架构的固有边界**（应用 A10 attention 边界、TR3 变体）。
