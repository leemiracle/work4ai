# 03 · 可构造与结构——战役计划作为数据对象

> **本章回答五问之 Q4(可构造性与结构)。**
> **本质一句话**:战役学里"可构造"的不是战争,而是**战役的
> 组织方式**——战役计划是阶段 DAG、决心是模板化文书、协同表是
> 矩阵、兵力簇是带约束的树;把这些结构显式化,参谋作业就从
> 手艺变成工程,可校验、可对表、可交接。

---

## 0. 开篇:一纸战役命令=一棵树+一张表+一幅有向图

拆开任何一份严肃的战役计划,都能拆出三件结构化家具:其一是
**兵力簇**(任务编组树:哪个集团军带哪几个军、加强什么);其二是
**协同表**(矩阵:谁在哪个时段配合谁);其三是**阶段流**
(有向图:准备→突破→发展→结束,边上挂着转换条件)。参谋手工
时代这三件家具画在地图与表格上;结构化之后它们是数据对象——
这是 04 章所有走廊的地基。

## 1. 什么是"可构造"的:五类战役对象

| 对象 | 数学化身 | 可构造性 | 构造中的坑 |
|------|---------|---------|-----------|
| **战役计划** | 阶段 DAG(节点=阶段,边=转换条件) | ✅ 高度可构造 | 阶段间出现环=计划自相矛盾;转换条件缺判断者=门无效 |
| **兵力簇(任务编组)** | 树+加强边(配属/支援) | ✅ 高度可构造 | 纸面编组≠战时实态;实力必带 as_of 快照(承军事史 OB 纪律) |
| **阶段-决心-协同表** | 矩阵(阶段×参与者×时段×动作) | ✅ 本家族主表 | 同一参与者同时段被排两处=冲突,须校验 |
| **计划树(分支/后续)** | 树/有向无环图 | ✅ 可构造 | 分支条件必须覆盖主要敌案,否则是"晴天计划" |
| **火力毁伤清单** | 目标列表×弹药×时段 | ✅ 可构造 | 目标值估计自带证据级(通说/侦察档) |

**不可构造的**:决心的"正确性"(没有最优函数)、对手适应
(敌案是活人写的)、摩擦的注入量(克劳塞维茨的 Friktion,
只能人为设定)、层间翻译的质量("信达雅"无度量)、
以及"决定性"的裁定(与军事史家族共享的悬而未决)。

### 1.5 最小数据模式(动手者的 schema)

```yaml
# 战役计划(00 章翻译层的直接形式化)
campaign: {name: str,
           strategic_objective: str,          # 引用上游(不得自创目的)
           phases: [phase],                    # 阶段序列(见下)
           branches: [ {trigger: str, phase_id: str} ],   # 分支计划
           sequels:   [ {trigger: str, phase_id: str} ]}  # 后续计划

# 阶段:计划的原子
phase: {id: str, objective: str,               # 阶段目的(唯一允许愿望态处)
        entry: {condition: str, judge: str},   # 转换门:条件+判断者,缺一即无效
        forces: [cluster_id],                  # 参与兵力簇
        duration_est: str,                     # D 日/H 时/昼夜
        exit:  {condition: str, judge: str}}   # 出口门(下一阶段的入口)

# 兵力簇:任务编组(01 章"被标定度"进正文后的三参数)
cluster: {id: str, hq: str, units: [unit],
          attached: [unit],                    # 配属(指挥权转移)
          supporting: [unit],                  # 支援(指挥权不转移)
          strength_as_of: str,                 # 实力快照日期(必填)
          signature_level: 低|中|高}           # 被标定度(01 章方向二)

# 协同表条目:时间咬合的原子
synch_entry: {phase_id: str, actor: cluster_id, action: str,
              time_window: str,                 # 可核对时段(H±min)
              coord_with: [cluster_id],         # 对表对象
              deconflict: [cluster_id]}         # 需避碰对象(空域/地带)
```

注意 `entry/exit` 的**条件+判断者**双字段与 `strength_as_of`
必填:把 02 章的语言纪律(转换条件规则/快照规则)写进数据结构——
**数据层自带校验点,是战役学计算区别于普通项目管理的第一特征**
(承军事史家族"数据层自带证据等级"同款精神)。

## 2. 骨架一:阶段结构(时间的切法)

阶段划分的通说四段(准备/突破/发展/结束)是外壳,内核是
**三个必须显式的结构位**:

1. **转换门**:阶段之间"什么时候算完"——天王星的快速集群
   在"突破口打开"后进入交战,门是条件不是钟点;
   钟点(H 时)只是初值,门才是控制器
2. **并行度**:阶段串行是特例,并行是常态(霸王的上陆与
   人工港拖运并行;巴格拉季昂的多路合围并行)——
   DAG 而非线性表,是战役计划区别于甘特图的第一点
3. **顶点管理**:攻势顶点(后勤与损耗共同决定)应作为
   全局变量显式声明——"跳到哪一步必须停"是计划的一部分,
   不是计划外的事故

## 3. 骨架二:兵力簇结构(力量的编法)

- **任务编组 ≠ 建制隶属**:配属(指挥权转移)与支援(不转移)
  是两种边,混写即埋冲突;加强单位(如坦克军配属步兵集团军)
  何时归建,必须写进阶段的出口门
- **三参数簇**(01 章方向二):兵力/地幅之外,被标定度成为
  第三设计参数——分散降低毁伤风险但抬高指挥与数据链依赖,
  集中反之;簇的形态是三参数约束下的选点
- **快照纪律**:实力数字必带 as_of——纸面序列是某日快照,
  补充与消耗天天在改(承[军事史 03 章](../讲透军事史/03-可构造与结构.md)OB 纪律)

## 4. 骨架三:协同表结构(时间的咬合)

协同表是本家族的招牌数据结构:**参与者×时段×动作×对表对象**
的矩阵,本质是把"谁配合谁"从人情话变成可校验的时间契约。

- **空域/地带避碰**(deconflict):两簇同时段邻近地幅即冲突——
  协同表校验器的第一类红旗(04 章 C2)
- **火力与机动的时窗咬合**:炮火准备窗口(如 05:30-06:15)与
  步兵冲击时刻必须齿合;窗口写"拂晓"即不可核对(02 章对表眼)
- **跨军种对表**:海军输送时刻表锁定登陆的 H 时;航空兵出动波次
  锁定炮压时段——跨军种协同表是"合同增益假设"(00 章)兑现的
  唯一路径,也是接口成本最贵的路径

## 5. 从结构到校验:这套骨架买到了什么

- 阶段 DAG → 计划一致性可机检(无环/门齐/可达)
- 兵力簇三参数 → 编组方案可枚举比较(不再是纯经验判断)
- 协同表 → 时间冲突可自动发现(空域避碰/时窗齿合)
- 计划树 → 敌案覆盖度可审计("晴天计划"自动露馅)

## 6. 构造合法性清单(动手前三问)

把任何战役构想变成数据结构之前,先过三问——本家族的"类型检查":

1. **门齐了吗**:每个阶段的入口/出口都有条件+判断者?
   ——缺门的阶段表是愿望清单
2. **快照带了吗**:兵力簇的实力与编组都标 as_of?
   ——不带日期的簇是"还活着的树"
3. **是 DAG 吗**:阶段流无环、分支条件互斥完备(覆盖主要敌案)?
   ——有环=自相矛盾,分支缺覆盖=晴天计划

三问全过,数据才获得进入 [04 章走廊](04-战役学转代码.md)的资格。
**战役学计算的第一特征不是算法,是入库纪律。**

## 📌 收束

可构造的是**计划的骨架**(阶段 DAG/兵力簇/协同表/计划树),
不可构造的是**决心的正确性与对手的适应**;结构化不是为了替代
参谋,是为了让参谋作业可校验、可交接、可复盘。下一章把骨架接上
代码:[04-战役学转代码](04-战役学转代码.md)。

**🧠 认知升维**:

- **门眼**:看任何流程图先找门(条件+判断者)——
  没有门的流程是幻灯片
- **三参数眼**:编组任何力量,兵力之外先问地幅容量与被标定度
- **契约眼**:协同不是关系话,是时间契约——写下时段与对表
  对象,才算协同时
