# 04 · 战役学转代码——网·校验·调度的走廊

> **本章回答五问之 Q5(问题→代码转换)。**
> **本质一句话**:战役学的问题一旦变成"关于阶段 DAG、协同表与
> 网络拓扑的计算",就能进代码——闭合时间可模拟、计划一致性可
> 机检、资源冲突可扫描、任务指派可优化;**唯一不可外包给代码的,
> 是翻译本身**(目的怎么变成序列)与**对手**(活人写的敌案)。

## 0. 开篇:一条链与一张网的蒙特卡洛

「中心化指挥链效率高,网状协同抗打」——这个教科书级论断,
能不能让数据说话?

`experiments/kill_web_closure.py` 内置两种拓扑:单链(F2T2EA 六环
串行,每环单节点,断一环即断)与杀伤网(六环各配双节点冗余,
任一存活配对可闭合)。蒙特卡洛跑出三组结论:网状平均闭合时间
约为单链的一半(min of exponentials 的解析对照内置)、单点打击
下网状存活率 1.0 对单链约 0.5、三点打击差距继续拉大。
**但脚本同时打印纪律提醒:节点参数是示意值,输出是推演级(D5)**
——代码替你算数,替不了你定参数。

## 1. 可机械化边界(三件套之一)

**能进代码的**(计划与网络数据化后的一切校验与计算):

| 任务 | 机械化形式 |
|------|-----------|
| 闭合时间模拟 | 拓扑+节点时延分布 → 闭合时间分布/存活率(家族实验) |
| 计划一致性校验 | 阶段流 → 无环检测/门完备性/可达性 |
| 资源冲突扫描 | 协同表 → 同簇同时段冲突/空域避碰红旗 |
| 敌案覆盖审计 | 计划树分支条件 → 覆盖度报告(晴天计划露馅) |
| 任务指派 | 兵力簇×目标清单 → 指派/运输优化([运筹学](../../讲透数学/讲透运筹学/)正主) |
| 阶段消耗聚合 | 兰彻斯特律在阶段粒度的序数比较(参数即史观) |

**不能进代码的**(战役学的"不可判定域"):

1. **翻译本身**——战略目的怎么变成兵力序列,没有最优函数;
   代码只能对已生成的计划做校验,不能生成"正确的"计划
2. **对手适应**——敌案是活人写的;推演里的"对手"是参数,
   把参数当对手是兵棋的百年老病(承军事史家族 C3 警告)
3. **摩擦的注入量**——Friktion 只能人为设定;不注噪声的计划
   推演输出的是教科书不是战役
4. **"决定性"的裁定**——与军事史共享的悬而未决(00 章问题表)

> 边界的一句话:**代码是协同表的校验器,不是统帅部的翻译器**。

## 3. C2 计划一致性校验走廊(最小示例)

03 章三问的代码化——把阶段表压成数据,跑"门齐吗/是 DAG 吗":

```python
# 阶段记录的最小校验(03 章 phase schema 的落地;示意数据)
PHASES = [
    dict(id="突破", entry=("突破口未开", "集团军司令员")),   # 缺判断者 → 红旗
    dict(id="发展", entry=("突破口正面达标", "方面军司令员")),
    dict(id="合围", entry=("快速集群渡河完毕", "方面军司令员")),
]
NEXT = {"突破": "发展", "发展": "合围", "合围": "突破"}      # 有环 → 红旗

def check_phases(phases, nxt):
    flags = []
    for p in phases:                       # 门齐吗:条件+判断者双字段
        cond, judge = p["entry"]
        if not cond or not judge:
            flags.append(f"{p['id']}: 门缺字段")
    seen, cur = set(), list(nxt)[0]        # 是 DAG 吗:沿边走必终止
    while cur not in seen:
        seen.add(cur); cur = nxt[cur]
    if cur in seen and len(seen) < len(nxt):
        flags.append("阶段流有环")
    return flags

assert check_phases(PHASES, NEXT) == ["突破: 门缺字段", "阶段流有环"]
print("两处红旗各就各位——计划未过类型检查,不得进入推演")
```

十行代码完成的事:一份构想 → 结构化记录 + 一致性红旗。
扩展方向:分支敌案覆盖度审计(计划树遍历+互补性检验);
协同表冲突扫描是同构问题(区间重叠检测)。**史学红线:红旗只
标记结构缺陷,判断"这样划阶段对不对"是参谋的事。**

## 4. C3 协同调度走廊(时窗冲突与指派)

- **冲突扫描**:协同表条目按 cluster_id 分组,组内 time_window
  区间重叠即红旗——日历系统的资源预订同构问题(工程师秒懂);
  带空域避碰约束的版本=区间图着色
- **任务指派**:兵力簇×目标清单的效益矩阵 → 匈牙利算法/贪心
  指派——本走廊的数学正主在
  [讲透数学/讲透运筹学](../../讲透数学/讲透运筹学/);
  战役学侧只补一条纪律:效益矩阵的每个数都带证据级,
  推演级参数的输出只做序数比较

**走廊三警告**(与 C1 共用):

1. 参数即史观:节点时延/效益值谁定,结论归谁——输出必附来源
2. 对手缺席:校验器里没有敌案适应;推演级(D5)标签不可拆
3. 批准逻辑不下沉:代码可发现更快的闭合路径,交战批准权限
   的设定是条令与伦理问题,不是优化问题(01 章方向一的组织面)

## 5. 工程师落点(把这门学科带回家)

- **计划校验**→ CI pipeline 的同构物:DAG+门+可达性,
  你的 deploy 流水线就是一份"阶段-决心-协同表"
- **杀伤网**→ 分布式系统可靠性:冗余路径/故障域/雪崩失效——
  kill web 的拓扑思维与多副本存储同源(家族实验可直接改造成
  服务降级模拟)
- **协同表**→ 资源预订系统:会议室/算力/带宽的时间契约,
  deconflict 就是日历冲突检测
- **C2 数据模型**→ 事件溯源:命令-报告-修订的流式记账,
  "命令是生成的"这条 D1 偏置,恰好是 event sourcing 的世界观

## 📌 收束

三条走廊:杀伤网(C1,已成)管"多快",计划校验(C2)管"通不通",
协同调度(C3)管"撞不撞";三条共用一条边界——**翻译、对手、
摩擦、裁定永远留在人脑**。跑到这里,回头再看 00 章那句钉住本质
的话:战役学把一句话的决心变成几十万人九十天的时间表;
代码能帮你查表,表还得参谋部来编。

**🧠 认知升维**:

- **校验器眼**:生成(翻译)与校验(一致性)是两种工作——
  任何领域都该先建校验器,再谈自动生成
- **参数即史观眼**:读任何推演结论,第一件事找参数来源,
  第二件事才是看输出(与军事史家族同款,战役版)
- **批准眼**:优化可以下沉,批准不该下沉——系统设计里
  "谁按按钮"是第一等参数
