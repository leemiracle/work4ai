# 03 · 可构造与结构——队形·规则·协同:交战作为数据对象

> **本章回答五问之 Q4(可构造性与结构)**。
> **本质一句话**:战术学里"可构造"的不是打仗本身,而是打仗的
> **组织件**——队形是相对坐标的 schema、交战规则是三值决策表、
> 协同是兵种×时间×地域的矩阵、火力配系是目标-单位-时刻的
> 指派;而"结构"是这门学科自己的骨架:三要素三角、攻防类型学、
> 蜂群拓扑。**把组织件形式化,正是"阵法→散兵线→合同→分布式"
> 四跳在数据层的重演**。

---

## 0. 开篇:一张协同计划表的构造量

打开任何一份师团进攻计划的附件,你会找到一张表:兵种×时间窗×
地域×行动,再加一栏信号规定。这张表就是合同战术的构造形态
——1917 年康布雷那张"对表"的数字化身。它有三条硬约束:
时间窗不得交叠出冲突(两个兵种同一时刻同一空域)、信号必须
唯一样本(同一个信号两义就是自毁)、每个行动必须能落回某个
建制(无主的行动是纸面行为)。**协同的可构造性,
就这三条约束的机器可查性**。

## 1. 什么是"可构造"的:五类战术对象

| 对象 | 数学化身 | 可构造性 | 构造中的坑 |
|------|---------|---------|-----------|
| **战术队形** | 相对坐标模式(schema) | ✅ 高度可构造(§1.1) | 队形是时点的快照,机动中它连续变形;纸面队形≠交战瞬间队形 |
| **交战规则(ROE)** | 三值决策表(§1.2) | ✅ 完全可构造 | 规则覆盖不了战场伦理时刻;空单元格=临机=人脑保留地 |
| **协同矩阵** | 兵种×时间×地域张量(§1.3) | ✅ 可构造(冲突可机器查) | 协同的"效果叠加"只可事后核算,不可事前保证 |
| **火力配系** | 指派(目标-单位-弹药-时刻) | ✅ 可构造(运筹学正主) | 目标价值排序=指挥员判断,参数即兵棋观 |
| **交战事件** | 结构化记录(时间/地点/双方/效果/来源) | ✅ schema 成熟 | 效果数字带宣称方,沿用军事史三栏纪律 |

**不可构造的**:时机感(00 章)、突然性的幅度(奇袭多大算
突然,无函数)、士气崩溃的临界、协同的"涌现性"(蜂群的
本地交互涌现,恰是 01 章辨析中不可预先计划的那一半)、
以及指挥决心本身。

### 1.1 战术队形 schema(动手者的第一格)

```yaml
# 队形模式:相对坐标+职能,实例化=具体分队落位
formation: {name: 楔形|横队|纵队|梯形|菱形|三角形,
  units: [ {callsign: str, role: 突破|火力|预备|警戒|保障,
            offset: [dx_m, dy_m],     # 相对基准点
            facing: deg, interval: m} ],
  as_of: str, terrain_ref: str,       # 快照时点+地形基准
  doctrine_ref: str}                  # 条令出处(操典中心主义的
                                      # 数据面:每个队形可溯源)
```

队形的四职能(突破/火力/预备/警戒)是合同战术的公共骨架
——楔形之于装甲、菱形之于防空、疏散队形之于无人机时代,
都是这四个 role 的不同参数化。**疏散队形是 01 章热线三
在 schema 层的落点:interval 从几十米放到公里级,
role 不变**。

### 1.2 交战规则(ROE)结构:三值决策表

```yaml
# ROE:目标类别 × 武器类别 × 条件 → 许可值
roe: {cells: [
  {target: 民用车辆, weapon: 反坦克导弹, cond: 默认,
   verdict: 禁止},
  {target: 敌装甲, weapon: 反坦克导弹, cond: 已识别确认,
   verdict: 允许},
  {target: 不明车辆, weapon: 火炮, cond: 越过管制线,
   verdict: 需批准(批准权: 营指)} ],
  completeness: 全表无空格}   # 空格=临机,须显式声明保留地
```

ROE 是**规范句的集合**(02 章:无真假,只有合规),它的
可构造红利是合规可机器查;它的边界是:无人机时代杀伤链
前置(01 章热线四)让"识别确认"这一格越来越难填——
自动化交战的伦理张力,在数据层就是这一格的 verdict
争夺战。

### 1.3 协同矩阵与火力配系

```yaml
# 协同矩阵:兵种×时间窗×地域×行动(冲突检查的对象)
coordination: [{arm: 步兵, window: [H-0, H+40], zone: A1,
                action: 冲击, signal: 红色信号弹一组},
               {arm: 炮兵, window: [H-0, H+40], zone: A1,
                action: 徐进弹幕, step_m_per_min: 100},
               deconflict: 同 zone 同 window 的
                           空域/弹道冲突必须机器可查]
# 火力配系(指派问题:目标-单位-弹药-时刻)
fire_plan: [{target: T-32, unit: 炮二营, ammo: 底凹弹,
             tot: "H+02:00", duration_min: 15,
             effect_requested: 压制|歼灭, source: 指挥员判断}]
```

徐进弹幕的 `step_m_per_min` 就是 02 章操典语言"协同写成
步速"的数据形态——**步兵步速钉住炮兵节奏,康布雷的对表
在 schema 里就这一个字段**。

## 2. 骨架一:三要素三角的刚性(结构的承重墙)

三要素三角(00 章 §二)是本学科的**刚性结构**:任何时代的
任何战术创新,都是三角上的一次权重重排,而不是推倒重来
——机枪是火力加权、坦克是机动+防护打包、无人机是火力小型化
+防护疏散化。**结构派的读法**:判断一个"新战术"的寿命,
先找它动的是哪个要素、动了多深;只动词汇不动权重的,
是改名不是创新(00 章逆境眼的另一面)。

## 3. 骨架二:攻防类型学(动作的有限生成集)

进攻四式(突破/迂回/包围/追击)与防御两式(阵地/机动)
是一个**有限生成集**:两千年战例的动作层,几乎全部可以
分解为这六式与三要素的组合——就像化学之于元素。类型学的
用途不是分类收藏,是**查重**:一个"全新战法"报上来,
先分解到六式×三要素,分解不掉的残余才是真新东西
(2020 年代的残余:多域同时性——火力/信息/机动在多个域
的时钟对表)。

## 4. 骨架三:蜂群拓扑(01 章热线一的构造面)

| 拓扑 | 结构 | 指挥含义 | 反制面 |
|------|------|---------|--------|
| 星形(集中遥控) | 一控多 | 链路即命脉 | 断链路(电子战) |
| 链形(中继) | 逐级传递 | 距离换鲁棒 | 打中继节点 |
| 网形(自治交互) | 本地交互涌现 | 真蜂群(01 章辨析) | 破坏交互基准(导航/时统) |
| 树形(母舰投放) | 平台分级 | 2025 母舰模式 | 打母舰(单点衰竭) |

**拓扑决定反制**:这是"蜂群 vs 集群使用"辨析的可操作版
——防御方识别出拓扑,才知道该买电子战(反星形)、买拦截
通道(反任何到达流)、还是买导航战(反网形)。
[家族实验](experiments/swarm_vs_defense.py)只建"到达流"
(对四种拓扑同构),拓扑差异是显式声明的模型边界。

## 5. 构造合法性清单(动手前三问)

把任何战术材料变成数据结构之前,先过三问——本家族的
"类型检查":

1. **快照时点**:队形的 as_of 与敌情判断的时点一致吗?
   ——敌情是昨天的,队形是今天的,拼起来就是自欺
2. **冲突查过了吗**:协同矩阵的空域/弹道/频谱三列,
   机器扫描过交叠吗?(§0 三条硬约束的自动版)
3. **规则表满格吗**:ROE 的目标×武器×条件全表无空格,
   或者空格已显式声明"临机保留地"?

三问全过,数据才获得进入 [04 章走廊](04-战术学转代码.md)
的资格。**战术学计算的第一特征不是算法,是把 02 章的
语言纪律(参数即兵棋观/决心非预言/规范句无真值)
写进数据结构。**

## 📌 收束

可构造的是**组织件**(队形/规则/矩阵/配系),不可构造的是
**时机与涌现**;三要素三角给刚性,六式类型学给查重,
蜂群拓扑给 01 章辨析的可操作落点。下一章把这些 schema
接上代码:交战几何/火力分配/饱和突防/交换比走廊:
[04-战术学转代码](04-战术学转代码.md)。

**🧠 认知升维**:

- **快照眼**:一切队形/敌情数据必须带 as_of——拼数据先拼时点
- **空格眼**:规则表的空格不是缺陷是临机保留地——
  显式声明胜过假装完备
- **拓扑眼**:看到多平台协同先画拓扑图——拓扑决定反制,
  数量只决定账单
