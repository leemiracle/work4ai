# 04 · 战术学转代码——几何·分配·饱和·交换的四条最小走廊

> **本章回答五问之 Q5(问题→代码转换)**。
> **本质一句话**:战术学的问题一旦变成"关于队形几何/火力指派/
> 通道容量/成本核算的计算",就能进代码——队形变相对坐标运算、
> 火力配系变指派问题、饱和突防变排队论、交换比变蒙特卡洛;
> **唯一不可外包给代码的,是战术判断本身(时机、突然、决心)**。
> 兄弟家族[军事理论实验](../讲透军事理论/experiments/lanchester_laws.py)
> 已管"两军对耗"(兰彻斯特两律),本章走廊避开它,专做
> 交战的组织面。

## 0. 开篇:三条教科书论断的一次跑通

「点防御拦得住饱和攻击吗」「加火力通道还是加拦截概率划算」
「廉价蜂群为什么在经济上无解」——三个战术经济学问题,
`experiments/swarm_vs_defense.py` 三分钟给出结构化答案:

- **饱和律**:突防数≈max(0, n−k·拦截轮次)(p=1 时严格成立;
  p<1 时为 n−p·k·C)——**数量买到线性,通道买到天花板**
- **时间压缩律**:同样 n 架,压缩到达(齐射/隐蔽抵近)比
  拉长到达突防多得多——**饱和的第一变量是到达速率 n/T,
  不是数量 n**
- **成本交换律**:攻击方"每突防一架的摊销成本"比防御方
  "每击落一架的导弹成本"低两个数量级(参数取公开研究
  口径的量级差)——**拦截弹单价≫来袭平台单价时,
  "打不光的最好办法是别让它找到你"**(01 章热线三的模型面)

但脚本同时打印概念边界:模型只建到达流,「蜂群 vs 集群使用」
的交互层差异(01 章热线一)是显式声明的模型边界——
**代码替你算容量,替不了你辨概念**。

## 1. 可机械化边界(三件套之一)

**能进代码的**(战术组织件数据化后的一切计算):

| 任务 | 机械化形式 |
|------|-----------|
| 交战几何 | 相对运动/射界/遮蔽角的三角学(队形 schema→几何量) |
| 火力分配 | 目标-单位指派问题(运筹学正主,贪心/匈牙利) |
| 通道容量 | 到达流 vs 服务率(排队论:火力通道=服务台) |
| 饱和突防 | 蒙特卡洛+解析对照(家族实验) |
| 协同冲突检查 | 时间窗×空域×频谱交叠扫描(03 章三问的自动版) |
| ROE 合规 | 决策表→规则引擎(02 章规范句的机器判定) |
| 交换比核算 | 成本/战果蒙特卡洛(01 章成本交换眼的落地) |
| 杀伤链计时 | 发现-决策-打击-评估各段时长分解(01 章热线四) |

**不能进代码的**(战术学的"不可判定域"):

1. **时机判断**——"再等两分钟"的价值无法条件化(00 章、
   02 章;一切自动化的保留地)
2. **突然性幅度**——奇袭多大算突然,没有函数;代码只能
   事后核算"对方反应延迟",不能事前宣称"必突然"
3. **协同涌现**——蜂群的本地交互涌现(03 章拓扑)在
   仿真里只能复现设定,不能保证预测
4. **决心**——承诺不是预言(02 章决心句);兵棋里
   "蓝军决心"是参数不是推论

> 边界的一句话:**代码是交战的组织学,不是指挥员**。
> 沙盘上算十遍,不如地图上判一次。

## 2. C1 交战几何走廊

队形 schema(03 章)的最小计算:相对坐标→射界与遮蔽。
```python
def can_engage(shooter, target, max_range):
    """射程判据(几何走廊的最小件):距离+遮蔽简化为射程检查。"""
    dx = target[0] - shooter[0]; dy = target[1] - shooter[1]
    return (dx*dx + dy*dy) <= max_range**2
```
扩展方向:高程遮蔽(通视计算)、交叉射界(队形的火力几何
——横队火力正面的代数)、相对运动解(空战几何的二维版)。
**空军支的正主是能量机动理论**(Boyd:单位剩余功率+转弯
速率把缠斗变成曲面),走廊在此只立坐标,深化见支。

## 3. C2 火力分配走廊

火力配系(03 章指派问题)的最小件:
```python
def greedy_assign(targets, batteries):
    """贪心指派:每个目标给"效能×剩余弹药"最优的火力单位。
    军事史纪律照用:目标价值排序=指挥员判断(参数即兵棋观)。"""
    plan = []
    for t in sorted(targets, key=lambda t: -t["value"]):
        best = max(batteries, key=lambda b: b["effect_on"](t))
        plan.append((t["id"], best["id"]))
        best["ammo"] -= 1
    return plan
```
军事用途:多目标多单位时的"谁打谁"初筛;运筹学正主在
[讲透运筹学](../../讲透数学/讲透运筹学/README.md)(指派/规划),
本走廊只消费。**纪律:effect_on 的系数谁定,结论归谁**。

## 4. C3 饱和突防走廊(✅ 家族实验已实现)

排队论视角:防御方是 k 个服务台、服务时间 τ 的排队系统,
攻击方是到达流。核心结论(实验断言):

- 拐点 n* = k·C(C=暴露窗内拦截轮次):**到达数过拐点,
  每增一架几乎必然突防**(线性段斜率→1)
- 时间压缩>数量:同样的 n,窗口压缩一半比数量翻倍
  对突防的边际贡献更大(01 章"蛛网"模板的抽象)
- 概率上限:p<1 时全拦靠多发齐打——漏拦率 (1−p)^m
  指数下降,但导弹消耗线性上升:**概率的账和钱的账
  不是一个斜率**(实验断言④)

扩展方向:非齐次到达(波次到达的排队论)、前出拦截
(把暴露窗 W 压短的防御改造)、诱饵识别率参数(真/假目标
混合到达流)。**与 C2 的接口**:拦截弹分配就是火力分配的
时限版——通道内的"谁打谁"是同一走廊。

## 5. C4 协同冲突检查走廊(03 章三问的自动版)

```python
def conflict_scan(coord):
    """协同矩阵冲突检查:同 zone 同 window 的空域行动交叠即红旗。"""
    flags = []
    for i in range(len(coord)):
        for j in range(i+1, len(coord)):
            a, b = coord[i], coord[j]
            if a["zone"] == b["zone"] and \
               a["window"][0] < b["window"][1] and \
               b["window"][0] < a["window"][1]:
                flags.append((a["arm"], b["arm"]))
    return flags
```
康布雷的对表(00 章美之时刻②)在数据层就是"冲突扫描
零红旗+时间表人手一份"。**本走廊的回报率最高**:
十行代码拦住的是协同事故,不是算出的是战术天才。

## 6. C5 交换比蒙特卡洛走廊(成本账的机器化)

把"赢"换成"赢得划算":`总成本/突防数`(攻方摊销单价)与
`导弹成本/击落数`(防方击落单价)之比,是 01 章成本交换眼
的全部计算。**纪律**:平台单价参数取公开研究口径量级,
结论只做序数比较(贵一个数量级 vs 贵两倍),不做基数宣称
——承军事史"构造性概念"待遇:可排序,难定量。

## 7. C6 杀伤链计时走廊(01 章热线四的接口)

发现→识别→决策→打击→评估,各段时长分解;战术问题:
**哪一段是瓶颈**。传感器前置(LP/OP 喂炮)压缩发现段、
AI 末制导压缩决策与制导段、光纤链路把"断链风险"从
时长项挪到可靠性项——01 章四条热线的统一计时框架。
扩展方向:与 C3 接口(防御方杀伤链时长=暴露窗 W 的组成项)。

## 8. 工程师落点

| 落点 | 用到的走廊 | 现实对应物 |
|------|-----------|-----------|
| 兵棋/推演引擎 | C1+C2+C3+C5 | 战术训练与方案初筛(LVC 仿真的火力与损耗内核) |
| 防空火控分配 | C2+C3 | 通道分配与齐射决策(火力通道=服务台的工程化) |
| 无人机任务规划 | C1+C4+C6 | 航线几何+空域去冲突+链路计时 |
| 协同计划工具 | C4 | 时间表与冲突扫描的参谋作业自动化 |
| 反无人机体系评估 | C3+C5 | 通道容量与成本交换的采购论证 |

**裂缝清单**(sim-to-real 的三道缝):

1. **参数=兵棋观**(承军事史/运筹学同款纪律):一切损耗系数、
   识别率、通道周期,引用必附来源;无来源的参数只能做
   敏感性扫描,不能做结论
2. **摩擦不可外购**(克劳塞维茨,军事思想史支):仿真必须
   人为注入延迟/误判/故障——**不注摩擦的兵棋,
   输出的是操典不是战斗**
3. **拓扑≠到达流**:家族实验对蜂群/集群同构的到达流,
   是简化不是等价(01 章辨析);工程化反无人机系统时,
   交互层(导航基准/链路拓扑)必须另行建模

## 📌 收束

四条主走廊:几何(C1)管"打得到",分配(C2)管"谁打谁",
饱和(C3)管"拦不拦得住",交换(C5)管"划不划算",
外加协同检查(C4)与杀伤链计时(C6)两根螺丝;共用一条
边界——**时机、突然、涌现、决心永远留在人脑**。跑到这里
回看 00 章那句钉住本质的话:一切战争计划都要通过一次次
交战兑现;代码能帮你算兑现的容量与账单,**兑现本身,
永远是分队的事**。

**🧠 认知升维**:

- **容量眼**:看任何防御体系先问通道容量(k×C)——
  拦截概率再高,过拐点后每增一架都突防
- **速率眼**:饱和的第一变量是到达速率——评估攻击方案
  先压缩时间窗,再谈数量
- **单价眼**:攻防对策的合法性由单价不对称决定——
  先算拦截弹/来袭平台的量级比,再谈战术选择
