# 03 · 可构造与结构——指挥关系、OODA 环与通用作战图:指挥作为数据对象

> **本章回答五问之 Q4(可构造性与结构)**。
> **本质一句话**:军队指挥学里"可构造"的不是决心与胆识,而是
> **指挥的组织形态**——指挥关系是带权树、OODA 是状态机、
> 通用作战图(COP)是航迹流、命令是五段式文档对象;而"结构"
> 是这门学科自己的骨架:语法层级(命令/指示/通报)、集中-分散谱、
> 节奏闭环。

---

## 0. 开篇:一场指挥=一棵树+一个状态机+一张置信度图

打开任何一级指挥所,你都会看到同一件东西:**标着隶属箭头的
指挥关系图**——谁指挥谁、谁支援谁、谁只协调谁(带权树);
加上随时间滚动的**通用作战图**——每条航迹自带位置、速度与
**置信度**(航迹流);再给这场仗装一个节拍器——**OODA 状态机**
(四阶段时延参数)。这就是指挥的可构造形态。军队是人类记录
最密的科层组织(番号/命令/日志),所以指挥虽是最依赖判断的
活动,其组织形态却出奇地结构化——这是 04 章有走廊可走的前提。

## 1. 什么是"可构造"的:五类指挥对象

| 对象 | 数学化身 | 可构造性 | 构造中的坑 |
|------|---------|---------|-----------|
| **指挥关系** | 带权树+横向边 | ✅ 高度可构造(§1.5 schema) | 纸面关系≠战时实态:配属/转隶天天在改,须带 as_of 快照 |
| **OODA 环** | 状态机(四阶段+时延参数) | ✅ 可构造(家族实验) | 独立时钟假设:敌对耦合未建模(00 章假设三) |
| **通用作战图(COP)** | 航迹流(身份-位置-速度-置信度-来源) | ✅ 可构造 | 置信度不是附注——丢掉它的 COP 是"图片"不是"情报" |
| **作战命令** | 五段式文档对象(嵌意图三元组) | ✅ schema 成熟 | 可校验"格式完备",不可校验"意图被理解"(02 章§2.6) |
| **指挥跨度** | 树的出度分布 | ✅ 可构造(通说 3-5) | 出度合理≠运转良好:跨度是能力×互信的函数 |

**半可构造的**:共同理解(可用"共享态势一致度"近似测度,
但一致≠正确);互信(借[军事心理学](../讲透军事心理学/README.md)
量表,组织内测量有霍桑效应)。

**不可构造的**:决心本身(目的生成的价值判断)、胆识与直觉、
"指挥艺术"的一切——可构造的是它的容器与流程,不是内容
(04 章可机械化边界的正主)。

### 1.5 五类对象的最小数据模式(动手者的 schema)

```yaml
# 指挥关系(带权边:类型即权责)
command_rel: {unit: str, superior: str,
              rel_type: 隶属|配属|作战控制|战术控制|支援|协调,
              as_of: date, source: 条令|命令文书}

# OODA 阶段(家族实验的最小参数)
ooda_phase: {side: str, phase: O|J|D|A,
             delay_mean: float, delay_dist: 指数|均匀,
             note: "信息优势→O;任务式指挥→D(决策+分发)"}

# COP 航迹(通用作战图的一条记录)
cop_track: {track_id: str, identity: 敌|友|中|未判,
            position: [lat, lon, alt], velocity: [vx, vy],
            confidence: 0.0-1.0, source: 传感器类型,
            as_of: datetime}          # 无时戳的航迹是废数据

# 意图三元组(02 章§2.6 的形式化;命令五段式中的"宪法段")
intent: {purpose: str,            # 为什么打(目的)
         end_state: str,          # 打成什么样(终态)
         constraints: [str]}      # 不可越界清单(约束)

# 作战命令(五段式文档对象)
oporder: {s1_situation: str, s2_mission: str,
          s3_execution: {concept, tasks[], intent},
          s4_sustainment: str, s5_command_control: {关系, 通信规定}}
```

注意 `intent` 嵌在 `oporder.s3` 里、`confidence` 挂在 `cop_track`
上、`as_of` 出现在两处——把 02 章的语言纪律写进数据结构:
**数据层自带意图不变式与置信度标注,是军队指挥学计算区别于
普通"状态跟踪系统"的第一特征**。

## 2. 骨架一:OODA 环结构(节奏的参数化)

- 四阶段×时延分布=一方的"组织脉搏";家族实验
  [experiments/ooda_race.py](experiments/ooda_race.py) 的全部参数面:
  信息优势缩观察(O)、任务式指挥缩决策分发(D)、链路脆弱加罚时
- 结构要点:环的总时延=四段之和(串行),**优化一段不如找到
  最长的一段**——排队论直觉:缩短非瓶颈阶段不改变系统吞吐
  (数学本体在[讲透数学/讲透运筹学](../../讲透数学/讲透运筹学/)排队论)
- 边界声明:OODA 的"环"是竞赛隐喻;真实敌对情境下两环耦合
  (你的行动改变对方观察)——结构化使用时必须注明这是
  独立时钟近似(00 章假设三)

## 3. 骨架二:指挥关系图(权责的拓扑)

- 六类关系(隶属/配属/作战控制/战术控制/支援/协调)构成
  一棵带权树+若干横向边:树边管"谁听谁的",横向边管
  "谁配合谁"——**横向边越密,协同成本越低,指挥所负担越重**
- 集中式 vs 去中心化在拓扑上的投影:星型(一切裁决过中心)
  vs 网状(边缘互连+弱中心)——拓扑决定指挥方式的上限:
  **星型网上跑不了任务式指挥**(断链即瘫痪),这是 00 章
  反直觉②的网络侧表述
- 指挥跨度(出度)是树的高度-宽度权衡:层数少(扁平)→
  意图衰减少但跨度爆炸;层数多→跨度舒适但意图层层打折
  (00 章问题清单"跨度多大"的结构面)

## 4. 骨架三:COP 数据模型(观察的公共底座)

- COP=多方传感器航迹的融合视图:同一条航迹,多源置信度按
  独立性假设融合(04 章最小实现:odds 相乘)
- **置信度的两条纪律**:①每条航迹必带来源与时戳(无来源的
  航迹=不可追责的流言);②融合假设(源间独立)本身要标注——
  两个传感器抄同一份通报,乘出来的置信度是假的
- COP 与意图的关系:COP 是"判断"的原料,不是判断本身——
  **图上一致(大家都看同一张图)≠判断一致(各自读出不同含义)**;
  把两者混同是网络中心战年代最常见的结构病(00 章§1.5 教训)

## 5. 从结构到比较:这套骨架买到了什么

- OODA 参数化 → "节奏优势"从修辞变成可跑的数(实验断言①-④)
- 指挥关系图 → 集中-分散谱的拓扑判据(星型/网状),
  比语汇争论(任务式 vs 详细式)更可检验
- COP 模型 → 信息优势的度量底座(置信度分布,而非"数据量")
- 意图三元组 → 共同理解的机器可读最小集(01 章热线五的
  "形式化前提"落点)

## 6. 构造合法性清单(动手前三问)

把任何指挥材料变成数据结构之前,先过三问——本家族的"类型检查":

1. **快照日期**:指挥关系带 as_of 了吗?——不带日期的隶属树是
   "还活着的树"(配属天天在改)
2. **置信度挂了吗**:航迹/情报断言必带来源与置信度——
   只给身份不给置信度的 COP,是把假设伪装成发现
   (军事情报学支的头号病)
3. **独立性假设声明了吗**:OODA 模拟、多源融合都必须注明
   "独立时钟/独立源"假设——不注明的输出按教科书处理,
   不按指挥学处理

三问全过,数据才获得进入 [04 章走廊](04-军队指挥学转代码.md)
的资格。**军队指挥学计算的第一特征不是算法,是权责与置信度的
入库纪律**——这一条把它与普通态势跟踪系统划开界河。

## 📌 收束

可构造的是**组织形态**(关系树/状态机/航迹流/命令对象),
不可构造的是**决心与理解**;结构不是装饰,是节奏论与集中-分散
之争的检验坐标系。下一章把这些 schema 接上代码:OODA 竞赛、
命令校验、航迹融合五条走廊:[04-军队指挥学转代码](04-军队指挥学转代码.md)。

**🧠 认知升维**:

- **瓶颈眼**:OODA 四段是串行的——优化一切不如找到最长一段;
  读任何"提速"宣称先问改的是哪一段
- **拓扑眼**:指挥方式的上限由网络拓扑决定——星型网上
  跑不了任务式指挥,网状网上想全集中也做不到
- **置信度眼**:态势数据没有"裸值"——每条航迹、每份情报
  都自带"我们有多相信它"的标签,丢标签即丢情报
