# 04 · 军事技术转代码——扩散、里程碑与反制窗口的最小走廊

> **本章回答五问之 Q5(问题→代码转换)**。
> **本质一句话**:军事技术的问题一旦变成"关于成熟度曲线、采办
> 状态机、扩散网络与反制响应对数据的计算",就能进代码——
> 扩散变 S 曲线模拟、采办变状态机校验、反制变窗口倒计时;
> **唯一不可外包给代码的,是技术路线的裁定与效能的最终判断**
> (选哪条技术路线、对手反制还有几年,是评估与决策,不是计算)。

---

## 0. 开篇:同一种潜力,两支部队,差在哪

「同一型新装备,甲军三年形成战斗力,乙军十五年还在试点——
差在哪?」——这是 00 章红线(技术必要而不充分)的标准问法。
它表面上像管理问题,实际上是**曲线参数问题**:两军的装备
相同(K 相同),差的是组织吸收率 r(训练/条令/编制改造速度)。

`experiments/adoption_scurve.py` 把这个问题做成可算的扩散
模拟:Logistic 采办曲线 + 对手反制钟。跑出的结论有三条:
①同样的技术潜力,吸收率决定战斗力形成的时间差(实测数十年
级,落在七纪元滞后列的包络内);②对手反制的响应延迟使
"使用即正常化"的红利窗口长度**可量化**——窗口 ≈ 响应延迟+
反制成熟期;③低吸收者的窗口近乎坍缩——技术到了,组织没到,
反制先到。代码替你算窗口,替不了你估延迟(对手反制还有几年
成熟,是情报评估,不是数学)。

## 1. 可机械化边界(三件套之一)

**能进代码的**(技术数据化后的一切演算、校验与推演):

| 任务 | 机械化形式 |
|------|-----------|
| 成熟度推演 | Logistic 曲线生成+吸收率敏感性扫描(03 章骨架一) |
| 形成时间换算 | 给定 r 与 K,解 T*(90% 潜力时刻);多方案对比 |
| 采办状态校验 | 状态机合法性(无跳级/无并发冲突)+里程碑时间统计 |
| 扩散模拟 | 网络上的边类型分层扩散(军贸/仿制/两用件) |
| 反制窗口量化 | 效能(t)=性能×(1−反制成熟度(t)) 的倒计时表 |
| 折旧敏感性 | 反制参数(延迟/成熟速度)扫描下的效能包络 |

**不能进代码的**(军事技术的"不可判定域"):

1. **技术路线裁定**——选高超音速还是选定向能:目标函数
   (威慑值/费效/产业)不可公度,模型只能给组合前沿
   (03 章不可构造清单)
2. **反制延迟的最终估值**——响应延迟 D 是情报评估:代码把
   W 写成 D 的函数,**D 本身永远来自建制与情报,不来自计算**
3. **革命定性**——"这算不算一场 RMA"是范式之争(革命论支的
   辩论场),不是阈值的自动判定
4. **效能的最终判断**——95% 还是 6%:口径与战场环境使数字
   本身存争议,代码只能枚举口径,不能替你选边(01 章热线三)

> 边界的一句话:**代码是技术评估科的曲线尺,不是路线决策的
> 签字笔**。

## 2. C1 扩散-反制窗口走廊(✅ 已实现,家族实验)

`experiments/adoption_scurve.py` 的机制与断言:

| 构件 | 设定 | 军事技术含义 |
|------|------|-------------|
| 采办曲线 | Logistic:y(t)=K/(1+A·e^(−rt)),年度吸收波动 ±15% | 03 章骨架一:潜力 K 是技术的,斜率 r 是组织的 |
| 吸收率对比 | r_high=0.50(危机压缩态)vs r_low=0.12(和平惯性态) | 同一技术潜力,唯一变量=组织吸收(训练/条令/编制速度) |
| 反制钟 | 对手在察觉(部署≥15%)后延迟 D 年启动反制,反制 logistic 成熟至上限 0.85 | "使用即正常化"的机制化:使用暴露原理,反制随后 |
| 效能 | e(t)=y(t)×(1−反制成熟度(t)) | 00 章假设三:效能=对手反制成熟度的函数 |
| 断言一 | T*(低吸收)−T*(高吸收)≥30 年,且落在 1-107 年的七纪元滞后列包络内 | 技术必要而不充分,组织是充分性的承运人(与军事史滞后列互证) |
| 断言二 | 高吸收者红利窗口(效能≥40% 潜力的年头)数倍于低吸收者;峰值效能高 25+ | 吸收率决定窗口:慢的组织在反制成熟前兑现不了多少 |
| 断言三 | 窗口长度随响应延迟 D 增大而近似线性延长(ΔW≈ΔD) | **"使用即正常化"窗口可量化**:窗口是对手响应延迟的函数 |

读输出的正确姿势:断言不是"谁会赢"的预言——它把 00 章的
命题(滞后列、反制依赖、正常化)做成**机器化的重述**;三个
建制参数(K/r/D)换成别的值,数值变而结构不变——**扫描建制
参数,是本走廊区别于新闻报道推算的第一特征**。

## 3. C2 采办状态机走廊(最小示例)

03 章状态机合法性的可运行核心:

```python
# 采办里程碑状态机片段:节点与合法转移
NODES = ["立项", "研制", "试验", "小批量", "列装", "退役"]
LEGAL = {("立项", "研制"), ("研制", "试验"), ("试验", "小批量"),
         ("小批量", "列装"), ("列装", "退役"),
         ("试验", "退役")}          # 试验不过可直接下马(降级边)

def check_transitions(history):
    for a, b in zip(history, history[1:]):
        assert (a, b) in LEGAL, f"非法跳级:{a}->{b}"
    assert history[0] == "立项", "生命从立项开始"
    return len(history)

steps = check_transitions(["立项", "研制", "试验", "小批量", "列装"])
assert steps == 5   # 五段履历,四步转移,全部合法
```

十行完成:一个项目的履历→合法性判定。扩展方向:并行路线
(多状态同时活动)、里程碑停留时间统计(采办节奏的量化史,
与[军制学 C5](../讲透军制学/04-军制学转代码.md)采办前沿走廊
对接)。

## 4. C3 反制窗口换算走廊(纸面→倒计时)

```python
def bonus_window(detect_year, response_delay, maturity_halfwidth):
    """红利窗口≈响应延迟+反制成熟期(03 章骨架四的速算版);
    response_delay 是情报评估声明值,不是计算值(04 章边界)。"""
    assert response_delay >= 0, "延迟非负"
    start = detect_year + response_delay        # 反制启动年
    end = start + 2 * maturity_halfwidth         # 成熟期(约 2 倍半宽)
    return end - detect_year

# 示例:2022 首次规模化使用,对手 2025 启动反制、约 4 年成熟
w = bonus_window(detect_year=2022, response_delay=3, maturity_halfwidth=2)
assert 7 <= w <= 8   # 窗口约 7 年:延迟 3+成熟 4
```

一行代数,两层纪律:入口断言(延迟非负)与来源纪律(延迟是
声明值)——家族实验把这条速算做成带波动的蒙特卡洛完整版
(C1 与 C3 是同一命题的精粗两版)。

## 6. 工程师落点(三件套之三)

- **数据工程**:成熟度台账/采办里程碑/扩散事件的 structured
  入库(03 章 schema);口径三元组(口径,条件,日期)是必带
  字段,不是元数据装饰
- **校验器/CLI**:状态机校验器、效能口径换算器做成小工具
  ——技术数据的第一价值是"让口径不明的数字进不了库"
- **推演服务**:S 曲线参数化(K/r/D)后挂参数扫描——把"新装备
  几年形成战斗力"的争论从形容词之争变成区间之争
- **可视化**:扩散 S 曲线族、反制窗口倒计时、技术簇依赖图
  ——本家族的三类标准图式
- **红线**:推演输出=机器化的反事实(承[军事史家族](../讲透军事史/04-军事史转代码.md)
  T6 纪律);一切输出携带参数来源与建制假设声明;模型非任何
  现实军队或项目的评估结论(敏感纪律)

## 📌 收束

六条走廊(已实现的 C1 扩散-反制窗口,最小示例 C2 状态机、
C3 窗口速算,待产的 C4-C6)共用一条边界:**口径不齐不入库、
组织参数显式声明、反制延迟来自情报不来自计算、路线裁定
永远留给人**。跑到这里,回头再看 00 章那句钉住本质的话:
技术是必要条件,组织吸收才是充分性的承运人——代码能帮你
算窗口,签路线的笔永远在人手里。

**🧠 认知升维**:

- **参数即建制眼**:推演结论先看 K/r/D 从哪来——潜力上限、
  吸收率、响应延迟三个建制假设比模型形式更决定结论
- **扫描眼**:任何"几年形成战斗力"的单点答案都是立场
  ——带吸收率区间的答案才是知识
- **倒计时眼**:武器列装之日起,红利窗口开始倒数——效能
  报告的第一栏应是窗口余量,不是峰值性能
