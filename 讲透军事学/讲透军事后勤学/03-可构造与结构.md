# 03 · 可构造与结构——补给网络、库存金字塔、配送周期:保障作为数据对象

> **本章回答五问之 Q4(可构造性与结构)**。
> **本质一句话**:军事后勤学里"可构造"的不是保障的好坏,
> 而是**保障的组织方式**——补给网是带三重属性(容量/时延/
> 风险)的流图、储量是分层的参数表、配送是可参数化的周期
> 模型;而"结构"是这门学科自己的骨架:库存金字塔、
> 网络最小割、批次-缓冲判据。
> 承接声明:[军事史 03 章](../讲透军事史/03-可构造与结构.md)
  已给 logistics_edge 的史学侧 schema 与"日流量表"——本章是
  它的**参数化升级**(加上风险属性与决策变量),互指不重复。

---

## 0. 开篇:一条补给线=一张流图+一座金字塔+一个周期

打开任何一级后勤指挥所,你都会看到同一件东西:**补给网络图**
——仓、港、枢纽、部队是节点,铁路/公路/水运/空运是弧,每条
弧上写着日容量与在途时延(对抗环境下再加一栏:风险);图旁边
立着**库存金字塔**——携行、预置、储备三层储量,每层一页参数
表;再给前送线装一个节拍器——**配送周期模型**(批次、间隔、
遭袭概率、缓冲)。这就是保障的可构造形态。军队是记账最密的
组织(基数/战备储量/日流量表),所以保障虽是最琐碎的活动,
其组织形态却出奇地结构化——这是 04 章有走廊可走的前提。

## 1. 什么是"可构造"的:五类保障对象

| 对象 | 数学化身 | 可构造性 | 构造中的坑 |
|------|---------|---------|-----------|
| **补给网络** | 节点-弧流图(容量×时延×风险) | ✅ 高度可构造(§1.5) | 民夫/驮兽等"软后勤"几乎不入档(承军事史注记) |
| **各级储量** | 分层参数表(基数×消耗率×天数) | ✅ 可构造 | 账实分离/质量劣化在表外(02 章§2 三重真值) |
| **配送周期** | (T, Q, p, L, 缓冲) 五元组 | ✅ 完全可构造(家族实验) | 独立遭袭假设:相关打击未建模(04 章警告) |
| **消耗标准表** | 代谢率矩阵(建制×物资×强度) | ✅ 可构造 | 战斗日/平时差一个量级——强度维度最易被抹平 |
| **伤员流/维修流** | 逆向流(发生率×后送时延×治愈返回率) | ✅ 可构造 | 卫生流的"黄金一小时"是时效函数不是统计量 |

**半可构造的**:保障需求预测(可用时序模型近似,对抗环境下
底座会被攻击——01 章热线二的边界);盟友枢纽的可达性(政治
变量,只能做情景假设)。

**不可构造的**:优先级裁定的价值判断("舍谁保谁")、
对手的打击策略选择、战场摩擦对消耗谱的畸变——可构造的是
保障的容器与流量,不是裁定与对抗本身(04 章可机械化边界的
正主)。

### 1.5 五类对象的最小数据模式(动手者的 schema)

```yaml
# 补给网络节点(仓储/枢纽/部队)
supply_node: {id: str, level: 战略|战役|战术,
              as_of: date,                      # 不带日期=还活着的账
              stock: {油料_日份: float, 弹药_基数: float, ...}}

# 补给网络的弧:三重属性(容量×时延×风险)
supply_edge: {from: node, to: node, mode: 铁路|公路|水运|空运|驮运,
              capacity_per_day: float,          # 吞吐量(02 章可测量)
              latency_days: float,
              risk: {p: float, L: float},       # 遭袭概率×损失率(家族实验参数)
              source_tier: T1..T6}              # 承军事史证据阶梯

# 储量参数表(库存金字塔的一层)
stock_param: {commodity: 油料|弹药|给养|备件,
              unit: 吨|件|基数|日份,            # 双轨度量,换算须显式(02 章)
              basic_load: float,                # 携行基数
              reserve_days: float,              # 战备储量(日份)
              consumption: {平时: float, 战斗日: float}}   # 强度假设必挂

# 配送周期(前送线的节拍器;家族实验的最小参数)
delivery_cycle: {T: int, Q: float,              # 批次间隔×批量
                 p: float, L: float,            # 对抗参数
                 safety_stock: float,           # 缓冲深度(日份)
                 compensated: bool}             # 是否按期望损失放大装载

# 伤员流(逆向流的一支)
casualty_flow: {incidence_per_day: float,       # 减员率(卫勤通说参数)
                evac_latency_h: float,          # 后送时效(黄金一小时)
                return_rate: float}             # 治愈返回(再生兵力)
```

注意 `risk` 挂在弧上、`consumption` 分强度两档、`stock` 带
as_of——把 02 章的语言纪律写进数据结构:**数据层自带风险属性、
强度假设与快照日期,是后勤计算区别于普通"库存管理系统"的
第一特征**(承军事史"数据层自带证据等级"同款精神)。

## 2. 骨架一:补给网络(三重属性的流图)

- 弧的三属性各管一件事:**容量**定吞吐上限(战区日供给的
  天花板=网络的最大流,卡在最小割——咽喉诊断,数学本体在
  [运筹学网络流](../../讲透数学/讲透运筹学/));**时延**定
  响应速度;**风险**定期望损耗与波动(00 章假设二的参数化)
- 结构要点:传统保障学只建前两栏(容量/时延),对抗性后勤
  的全部新增就是把第三栏(risk)从脚注升格为与容量同级的设计
  变量——**路径选择从"最短/最大"变为"多目标"**:绕远的
  低风险路可以优于捷径的高风险路(01 章热线一的图论面)
- 红球快运(00 章)的网络解读:不改容量属性,改**协议属性**
  (单向循环)——制度设计在网络模型里表现为对弧的重组织

## 3. 骨架二:库存金字塔(携行-预置-储备)

- 三层结构的两轴:**数量×距离**——离前线越远,储量越大、
  响应越慢、成本越低;离前线越近,储量越小、响应越快、
  风险越高
- 预置层的特殊性:它是**唯一同时占用"数量"与"位置"两个
  设计变量的层**——预置 vs 投送之争(00 章问题清单)的实质
  是金字塔第二层的厚度该怎么定;家族实验断言④(预置缓冲
  单调对冲断供风险)给出定量面:每加一天预置,断供期望
  单调下降,但边际递减
- 金字塔与信息的关系:预测越准,金字塔可以越薄(库存-信息
  替代,00 章假设三)——**预测性后勤=给金字塔瘦身的信息刀**

## 4. 骨架三:配送周期模型(批次-缓冲判据)

- 前送线 = 周期 T×批量 Q 的节拍器 + 缓冲 S 的蓄水池,在
  遭袭参数 (p, L) 下运转——这正是[家族实验](experiments/contested_resupply.py)
  的全部参数面,也是 2024 条令重写的最小数学模型
- **批次-缓冲判据**(实验断言②③的综合):大批次劣于小批次的
  条件 = 对抗强度 p 高**且**缓冲 S 盖不住"连续遭袭窗口"
  (约 k 个连续满损批次的缺口,k≈⌈S/Q⌉+1);缓冲够深时大批次
  的集约经济恢复——**策略优劣是 (p, S, Q) 的函数,不是属性**
- 边界声明:模型假设批次遭袭独立;真实对手会学习节奏做相关
  打击(专打间隔上的咽喉节点)——独立性失守时分篮逻辑部分
  失效,这是"随机干扰"与"对抗优化"的分界(04 章警告三)

## 5. 从结构到比较:这套骨架买到了什么

- 三重属性流图 → 补给线从"一条线"变成可诊断的系统
  (瓶颈在容量还是风险,对策完全不同)
- 库存金字塔 → 预置/投送之争的结构化(第二层厚度=距离×
  威胁×预置资产生存性的函数)
- 周期模型 → "该不该拆小批次"从经验直觉变成可算的判据
  (对抗强度×缓冲深度的二维表)
- 伤员/维修流 → 保障从"单向送货"补全为双向循环(再生能力
  入账:治愈返回率与修复返回率是战斗力的隐藏来源)

## 6. 构造合法性清单(动手前三问)

把任何保障材料变成数据结构之前,先过三问——本家族的"类型
检查":

1. **消耗标准哪来的**:操典定额/演习实测/战史回溯三档可信度
   完全不同——战斗日消耗尤其要问出处(平时数据外推战斗日
   是系统性低估)
2. **快照与对账**:储量数字带 as_of 了吗?账实核对状态
   标了吗?——不对账的储量表按信用等级打折使用
   (02 章§2.7)
3. **单位统一了吗**:吨/件/基数/日份是否单一制?混用必须
   显式换算——四把尺子量一个对象,加总即事故(02 章§2.5)

三问全过,数据才获得进入 [04 章走廊](04-军事后勤学转代码.md)
的资格。**后勤计算的第一特征不是算法,是入库纪律**——这一条
把它与普通库存管理划开界河。

## 📌 收束

可构造的是**组织方式**(流图/参数表/周期模型),不可构造的
是**裁定与对抗**;结构不是装饰,是预置之争与批次之争的检验
坐标系。下一章把这些 schema 接上代码:对抗前送、战备储量、
配送排队五条走廊:[04-军事后勤学转代码](04-军事后勤学转代码.md)。

**🧠 认知升维**:

- **三栏眼**:看一条补给线先看弧上三栏——容量(吞吐天花板)、
  时延(响应)、风险(损耗);只有前两栏的图是和平地图
- **金字塔眼**:库存不是数,是带层数的结构——问储量先问
  在哪一层:离前线多远、响应多快、被打了多心疼
- **判据眼**:批次大小没有普优解——(对抗强度×缓冲深度)
  二维判据在手,"拆不拆小批次"从争论变成查表
