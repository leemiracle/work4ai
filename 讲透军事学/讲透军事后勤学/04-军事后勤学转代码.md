## 0. 开篇:2024 条令换底的一个断言,三分钟跑出数

「对抗性后勤要重写配送规则」(01 章热线一)——重写到什么程度?
`experiments/contested_resupply.py` 把前送线建成一台 (T, Q, p, L)
节拍器加一个缓冲水池,400 次蒙特卡洛跑出四个断言:

- **安全基线**:p=0 时大批次以 1/15 的出动次数完成同样保障
  ——安全时大批次更省(省的是出动与管理)
- **对抗反转(核心)**:p=0.30+补偿发货,两策略期望送达率同为
  ~0.70(**均值不动**),断供 36 天 vs 8 天、库存波动 20.5 vs
  5.1——分篮改的是分布,不是均值
- **条件边界**:深缓冲(60 日份)+中低对抗(p=0.10)下,大批次
  断供回到 ≈0,与小批次同档——劣势是条件函数,不是教条
- **预置缓冲**:同策略同对抗,起点库存 10→25→45 日份,
  断供 36→25→14 天单调下降

但脚本同时打印建模边界:遭袭独立假设(对手的相关打击会部分
摧毁分篮逻辑)、消耗率取常数。**代码替你算风险,替不了你算
对手**——后勤学数字化的第一课(与[指挥学 04 章](../讲透军队指挥学/04-军队指挥学转代码.md)
"代码是沙盘不是指挥官"同款)。

## 1. 可机械化边界(三件套之一):优先级裁定之辩

**能进代码的**(保障数据化后的一切计算):

| 任务 | 机械化形式 |
|------|-----------|
| 批次策略评估 | (T, Q, p, L, S) → 断供分布/库存波动(家族实验) |
| 战备储量测算 | 消耗分布+代价 → 安全库存/再订货点(C2) |
| 网络吞吐诊断 | 补给网 → 最大流=日吞吐上限,最小割=咽喉(C3) |
| 配送/维修排队 | 到达率×服务率 → 等待时长(C4) |
| 需求预测 | 消耗时序 → 平滑/学习预测(C5) |
| 伤员流推演 | 减员率×后送时延×返回率 → 兵力再生曲线 |

**不能进代码的**(后勤学的"不可判定域"):

1. **优先级裁定之辩**:算法可以枚举分配方案、推演各自后果
   ——但"油给装甲兵还是油给直升机、弹药给东线还是西线"
   是价值判断,**方案生成可机械化,方案裁定不可**(与指挥学
   "决心生成之辩"同构:批准即担责,裁定权与责任是同一枚
   硬币的两面)
2. **消耗谱的战场畸变**:战斗日的真实消耗只有在战斗里生成
   ——演习外推战斗日是系统性低估(03 章三问之一);摩擦
   不可枚举,只能事后回填
3. **对手的对抗策略**:打击是策略不是噪声——对手会学习你的
   节奏、专打咽喉、攻击你的数据层(01 章热线五);仿真只能
   做情境扫描,博弈没有"算尽"

> 边界的一句话:**代码是补给网的沙盘,不是军需官**。
> 沙盘上推十遍,不如补给线上跑一趟。

## 2. C1 对抗性前送走廊(✅ 已实现)

## 3. C2 战备储量走廊(最小示例)

储量=报童问题:囤少了断供(代价高),囤多了铁山(代价低但
非零)——临界分位数定安全库存:

```python
from statistics import NormalDist

def war_reserve(mu_d, std_d, lead_days, cu, co):
    """战备储量:mu_d/std_d=日需求均值/波动,lead_days=补给周期;
    cu=断供代价(缺一件的损失),co=过储代价(囤一件的负担)。
    返回(再订货点, 安全库存)。"""
    z = NormalDist().inv_cdf(cu / (cu + co))     # 临界分位数
    rop = mu_d * lead_days                        # 周期内的期望消耗
    return rop + z * std_d * lead_days ** 0.5, z * std_d * lead_days ** 0.5

rop, ss = war_reserve(mu_d=100.0, std_d=40.0, lead_days=10, cu=8.0, co=1.0)
assert abs(ss - 155.1) < 1.5                     # 断供:过储=8:1 → ~1.55σ
print(f"再订货点 {rop:.0f} 日份(含安全库存 {ss:.0f})")
```

十行代码完成的事:代价不对称 → 分位数 → 缓冲深度。
**断供代价越高于过储代价,金字塔越厚**——海湾"铁山"就是
这个公式在 cu≫co 且不确定性被高估时的输出(00 章反直觉①的
解析面)。

## 5. C4 配送排队走廊(最小示例)

维修件申请是排队:到达率逼近服务率时,等待时间非线性爆炸
——"再加一个组"的收益也是非线性的:

```python
def wait_days(lam, groups, mu_per_group):
    """M/M/1 型等待(天):lam=到达率,groups 个服务组,
    每组修复率 mu_per_group。"""
    cap = groups * mu_per_group
    assert lam < cap, "到达率超服务率:排队发散(需加组或分流)"
    return 1.0 / (cap - lam)

w2 = wait_days(18.0, 2, 10.0)   # 两组:利用率 90%
w3 = wait_days(18.0, 3, 10.0)   # 三组:利用率 60%
assert w3 < w2 / 5
print(f"两组等待 {w2:.2f} 天,三组 {w3:.2f} 天——第五个十分点的利用率,买回六倍时效")
```

**走廊警告**:排队模型假设泊松到达;战时申请是爆发性的
(战损聚集)——按平稳假设排的产能,高峰日按优先级熔断。

## 6. C5 预测性后勤走廊(最小示例)

消耗时序的指数平滑 vs 全局均值——预测精度的价值最终兑换成
安全库存的削减(00 章假设三:信息替代库存):

```python
import random

rng = random.Random(7)
demands, level = [], 100.0
for _ in range(200):                    # 缓慢漂移+噪声的消耗水平
    level += rng.uniform(-1.0, 1.6)
    demands.append(max(0.0, level + rng.gauss(0, 8.0)))

def mae(pred_fn):
    errs = [abs(pred_fn(i) - demands[i]) for i in range(30, 200)]
    return sum(errs) / len(errs)

alpha, f = 0.3, demands[0]
def es(i):                              # 指数平滑:近象权重大
    global f
    f = alpha * demands[i - 1] + (1 - alpha) * f
    return f

es_mae, mean_mae = mae(es), mae(lambda i: sum(demands[:i]) / i)
assert es_mae < mean_mae * 0.8
print(f"平滑预测误差 {es_mae:.1f} vs 均值法 {mean_mae:.1f}——误差每降一档,安全库存少囤一档")
```

**走廊警告**:预测吃的是和平消耗数据;对抗环境下数据底座
本身会被攻击(01 章热线二)——预测性后勤的强度=其数据底座
的脆弱度。

## 7. 工程师落点(军事后勤学给你的工程赠礼)

- **供应链管理直接同构**:安全库存/S&OP/牛鞭治理就是 C2-C5
  的民用原名——军民两个语汇共享同一门流量科学
  ([讲透管理学](../../讲透管理学/README.md)互链的工程面)
- **多级缓存=库存金字塔**:CDN 边缘节点/区域中心/源站的
  三层结构,与携行-预置-储备同构——离用户越近量越小响应
  越快,越远越大越慢
- **容灾与混沌工程=对抗性环境注入**:故意打断链路看系统
  断供表现,就是给 p>0 的世界做演习——分篮/冗余/预置的
  民用训练场
- **降级预案=优先级裁定前置**:熔断规则把"舍谁保谁"写成
  预先声明的优先级表——把战时裁定变成平时架构(边界§1 的
  组织学解法:算法不定优先级,但可以执行人定的优先级)
- **游戏 RTS 经济系统=后勤玩具模型**:采矿-运输-建造的
  流量约束就是给养函数的娱乐版——玩家在快乐地解 03 章的
  周期模型

**走廊三警告**(承[军事史](../讲透军事史/04-军事史转代码.md)与
指挥学 04 章警告同源):

1. **参数=消耗标准**:消耗率谁定的,结论就归谁——引用储量
   与断供数字必附参数来源与强度假设
2. **仿真输出=机器化的反事实**:蒙特卡洛的断供天数是模型
   世界的数,冒充实兵检验是数字时代新病
3. **独立性假设必注**:批次遭袭独立、源间独立——对手的
   相关打击(学节奏、打咽喉、攻数据)会系统性摧毁分篮与
   融合逻辑;不注明独立性假设的对抗模型,默认按教科书处理,
   不按后勤学处理
