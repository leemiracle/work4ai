# 04 · 军制学转代码——编制·账本·权衡的最小走廊

> **本章回答五问之 Q5(问题→代码转换)**。
> **本质一句话**:军制学的问题一旦变成"关于编制表、力量账本与
> 采办组合数据的计算",就能进代码——编制表变树与校验器、
> 力量结构变账本与折扣换算、力量设计变齐射权衡推演;
> **唯一不可外包给代码的,是政治变量的取值与改革的裁定**
> (兵役制度选哪种、番号保不保,是合同签订,不是计算)。

---

## 0. 开篇:一个预算,三种买法,谁说了算

「同一笔预算,买 5 艘高端平台、50 艘低端艇,还是 3+20 混合?」
——这是力量设计时代(00 章 §1.4)最典型的军制学问题。
它表面上像购物决策,实际上是**组织结构问题**:分散的平台
需要网络与 C2 节点撑着才有战力,而节点本身又是高价目标。

`experiments/force_design_tradeoff.py` 把这个问题做成可算的
齐射交换推演(休斯 salvo 模型的heterogeneous 版),跑出的
结论有两条:基线场景下混合组合的费效比占优(分散红利×
网络依赖的乘积);但把廉价平台的自主性参数 κ 从 0.4 扫到
1.0,优势区间会移动直至反转——**混合优势是有条件边界的,
不是教条**。代码替你算权衡,替不了你判断参数(哪支部队的
廉价平台真有 κ=1 的自主战力,是情报与建制评估,不是数学)。

## 1. 可机械化边界(三件套之一)

**能进代码的**(军制数据化后的一切校验、换算与推演):

| 任务 | 机械化形式 |
|------|-----------|
| 编制表校验 | 树结构校验(无环/单亲)+员额加总+装备编配上限(03 章三硬校验) |
| 编制 diff | 版本序列→结构/行项/改名三类变更分类统计(实质变动率) |
| 折扣换算 | 纸面×满编×可用×在位的换算器与敏感性表 |
| 兵役流守恒 | 入口-存量-出口的流量平衡检查(动员数学) |
| 采办组合前沿 | 多目标(速度/成本/风险/产能)组合的可达前沿枚举 |
| 力量结构推演 | 齐射交换模型下的平台组合战损与费效比较(家族实验) |

**不能进代码的**(军制学的"不可判定域"):

1. **政治变量取值**——征兵制还是募兵制、基地留不留:这是
   合同签订(预算、选区、军种政治),模型只能把它们声明为
   外生参数扫描,不能"优化"出答案
2. **改革时机的裁定**——危机创新律(00 章⑥)是历史统计,
   不是预测器;窗口期的判断是政治判断
3. **番号与认同的价值**——一个历史番号的士气值没有度量函数;
   裁撤的账算得清,情算不清
4. **采办绩效的最终归因**——冲突性授权框架能列出目标冲突
   矩阵,但"哪条授权该改"是立法政治,评估止步于前沿刻画

> 边界的一句话:**代码是编制科的算盘,不是军事委员会的表决器**。

## 2. C1 力量结构权衡走廊(✅ 已实现,家族实验)

`experiments/force_design_tradeoff.py` 的机制与断言:

| 构件 | 设定 | 军制学含义 |
|------|------|-----------|
| 平台类型 | 高价平台(贵/火力强/带防御/带 C2 节点)、廉价平台(便宜/火力弱/无节点) | 装备学支的"高低端组合"问题的最小化身 |
| 组合 | 同预算三组合:5 高价 / 50 廉价 / 3 高价+20 廉价 | 力量结构账本的实例层(03 章) |
| 交战律 | 齐射交换(休斯模型):进攻齐射−防御拦截→命中→按持续力折损 | 分布式海上作战力量结构的通说模型族(方向锚) |
| C2 依赖 | 无 C2 节点存活时,廉价平台战力打 κ 折 | "分散红利×网络依赖"的乘积机制:网络是编制问题不是平台问题 |
| 断言一 | 基线(κ=0.55,随机分配):混合组合费效比(净价值+胜率)严格优于两个纯组合 | 混合优势的存在性 |
| 断言二 | κ 扫描 0.4→1.0 + 分配规则翻转:κ=1.0 或对手点名节点时,大量廉价组合反超(实测两处翻转) | **条件边界**:廉价平台足够自主/节点可被点名时,节点保险费不再值得付 |

读输出的正确姿势:断言一不是"混合永远好"的证明——它是
"在 κ=0.55 的建制假设下混合好"的机器化重述;断言二才是
本走廊的真教益:**费效比的排序随建制参数翻转**——把建制
假设(网络依赖度)当显式变量扫描,是力量设计推演区别于
购物清单比较的第一特征。

## 3. C2 编制表校验走廊(最小示例)

03 章三硬校验的可运行核心——树与加总:

```python
# 编制表片段:unit -> (parent, 员额)
TOE = {"师部": (None, 800), "1团": ("师部", 3000),
       "2团": ("师部", 3000), "炮团": ("师部", 2500)}

def check_toe(toe):
    roots = [u for u, (p, _) in toe.items() if p is None]
    assert len(roots) == 1, "隶属树必须单根(一个师一个师部)"
    for u, (p, _) in toe.items():          # 硬校验 1:无环+可达
        seen, cur = set(), u
        while cur is not None:
            assert cur not in seen, f"隶属成环:{u}"
            seen.add(cur); cur = toe[cur][0]
    assert sum(n for _, n in toe.values()) == 9300, "硬校验 2:员额加总"
    return True

assert check_toe(TOE)  # 结构不变式过了,才谈得上满编率
```

十行完成:一张编制表→结构合法性判定。扩展方向:行项级
(岗位×军衔×专业)校验、版本 diff 三分类(结构/行项/改名)——
00 章"版本眼"的自动化。

## 4. C3 折扣换算走廊(纸面→可部署)

```python
def deployable(paper, fill, readiness, presence):
    """三重折扣换算器(03 章骨架二);折扣口径见 02 章。"""
    assert all(0 < r <= 1 for r in (fill, readiness, presence))
    return paper * fill * readiness * presence

# 历史通说量级:三折扣连乘常落 0.5-0.7(00 章假设一)
assert 0.5 < deployable(6, 0.92, 0.85, 0.88) / 6 < 0.7
```

一行公式,两层纪律:入口断言(折扣必须(0,1])与出口口径
(输出是"可部署"口径,与"在编"口径禁止直接混比——02 章
满编歧义的代码化)。敏感性分析(任一折扣±5% 对输出的摆动)
是本走廊的自然扩展。

## 5. C4-C6 走廊指引(待产记账)

- **C4 兵役流守恒**:入口(征/募,政策变量声明值)-存量-出口的
  流量平衡;可做 30 年兵力年龄结构推演(入口政策扫描)
- **C5 采办组合前沿**:项目集×多目标(速度/成本/风险/产能)的
  帕累托前沿枚举;授权条款计数作约束维度(01 章热线三的数据面)
- **C6 编制 diff 统计**:版本序列→三类变更分类→实质变动率曲线
  (军制变迁的量化史)

## 6. 工程师落点(三件套之三)

- **数据工程**:编制表/力量年报/预算文档的结构化入库
  (03 章 schema);口径与授权条款是必带字段,不是元数据装饰
- **校验器/CLI**:TOE 校验器、满编口径换算器做成小工具
  ——军制数据的第一价值是"让非法数据进不了库"
- **推演服务**:齐射权衡模型参数化(κ、折扣、齐射系数)后
  挂上参数扫描——把"力量设计讨论"从形容词之争变成区间之争
- **可视化**:版本 diff 图(编制变迁)、组合前沿图(采办)、
  κ-费效曲面(力量设计边界)——军制学的三类标准图式
- **红线**:推演输出=机器化的反事实(T6 化,承军事史家族
  04 章边界);一切输出必须携带参数来源与建制假设声明;
  模型非任何真实军队的编制建议

## 📌 收束

四条已实现的走廊(权衡 C1/校验 C2/换算 C3)与三条待产
(C4-C6)共用一条边界:**政治变量声明不推导、口径不齐不入库、
推演结果带参数源**。跑到这里,回头再看 00 章那句钉住本质的话:
军队的胜负在开战前几十年就写进了三张表——代码能帮你算表,
签表的笔永远在人手里。

**🧠 认知升维**:

- **参数即建制眼**:推演结论先看 κ 和折扣率从哪来
  ——建制假设(网络依赖/满编口径)比模型形式更决定结论
- **扫描眼**:任何"X 优于 Y"的力量设计结论,先问扫了哪个
  建制参数区间——单点参数的结论是立场,带边界的结论才是知识
- **校验先于优化眼**:军制数据的第一工程是让非法数据进不了库
  (结构不变式),其次才是任何优化
