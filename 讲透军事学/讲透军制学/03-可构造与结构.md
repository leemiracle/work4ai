# 03 · 可构造与结构——编制表、账本与组合:军队作为数据对象

> **本章回答五问之 Q4(可构造性与结构)**。
> **本质一句话**:军制学里"可构造"的不是军队,而是**军队的三套
> 账**:编制表(组织账:谁在结构里)、力量结构账本(形态账:
> 有多少个什么)、采办组合(流量账:钱怎么变成装备)。而"结构"
> 是军制史自身的骨架:模块化-互换性的组织语法、纸面-实态的
> 折扣结构、编制-国土-预算的三重绑定。

---

## 0. 开篇:三张表撑起一支军队

任何一个国防部都在同时维护三张表:一张**编制表**(这个旅
应该有什么:员额、岗位、装备),一张**力量结构表**(国家实际
有几个这样的旅、几艘这样的船),一张**采办组合表**(未来十年
的钱怎么花,才能让前两张表成立)。00 章说编制表是合同——
本章把三张合同全部数据化:**编制表是模板,力量结构是实例数,
采办组合是使实例数随时间演化的转移规则**。这三层叠起来,
就是"军队"作为数据对象的完整形态。

## 1. 什么是"可构造"的:六类军制对象

| 对象 | 数学化身 | 可构造性 | 构造中的坑 |
|------|---------|---------|-----------|
| **编制表(TOE)** | 树+行项(员额/装备) | ✅ 高度可构造(法定模板,字段齐全) | 纸面≠实编:模板行项须带"等级/可用性"折扣字段 |
| **力量结构账本** | 组合计数 {单位类型→数量}×年 | ✅ 完全可构造(年报数据) | 口径歧义(02 章):满编/可部署/已部署三口径必须显式 |
| **采办组合** | 项目集{预算流/里程碑/授权条款} | ✅ 高度可构造(预算文档) | 里程碑延误与超支的口径;跨财年比较须通胀校正 |
| **兵役流** | 流水网络(入口→服役→出口) | ✅ 可构造(动员数学:流守恒) | 入口政策变量(征/募)是政治变量,建模须声明 |
| **编制-地理绑定** | 二部图(单位↔驻地/军区) | ✅ 可构造(部署数据) | 保密分层:公开数据粒度粗,须标注可得性边界 |
| **"最优编制"** | 优化目标函数 | ⚠ 半可构造:约束可写,目标函数是立场 | 费效比/韧性/威慑值不可公度——只能做多目标前沿,不做单一最优解 |

**不可构造的**:编制的政治过程(番号为何保留)、组织认同
(番号的士气价值)、"改革的正确时机"、转型学习的认知存量
(01 章热线二只能案例研究,不能参数化)。

### 1.5 三套账本的最小数据模式(动手者的 schema)

```yaml
# 编制表行项(TOE 的一行:一个岗位或一件装备)
toe_line: {unit: str,                 # 隶属单位番号
           item: 岗位|装备,           # 行项类型
           spec: str,                  # 岗位(军衔×专业)或装备型号
           quantity: int,              # 编配数(纸面应有)
           availability_tier: 一级|二级|战时补充,   # 满编等级折扣
           as_of: str,                 # 版本快照日期(00 章版本眼)
           source_tier: T1..T6}

# 力量结构账本(某年国家军队的形态)
force_ledger: {year: int,
               units: [{toe_ref: str,    # 指向哪个编制模板
                        count: int,      # 该模板的实例数
                        fill_rate: float,  # 平均满编率(实态折扣)
                        readiness: float}], # 可用率(可部署口径)
               source_tier: T1..T6}

# 采办组合(项目级)
acq_portfolio: {programs: [{name: str,
                            phases: [立项, 研制, 生产, 列装, 保障, 退役],
                            budget_by_year: {str: float},  # 财年流量
                            mandate_refs: [str],   # 授权条款(01 章热线三)
                            status: str}]}

# 兵役流(动员数学的节点守恒)
service_flow: {intake: 征兵|募兵|预备役动员,   # 入口(政策变量,须声明)
               stock: {军官: int, 士兵: int},   # 在役存量
               outflow: 退役|转预备役|减员,      # 出口
               year: int}
```

注意三个设计决定:①`availability_tier` 与 `fill_rate` 把
"纸面≠实态"写进数据结构(02 章满编歧义的 schema 化);
②`mandate_refs` 让采办项目携带法律出处(冲突性授权框架的
数据面);③兵役流的入口是**政策变量**——建模者只能声明它,
不能推导它(军制学的政治边界写进 schema)。

## 2. 骨架一:编制的模块语法(树+接口)

- **树**:隶属关系构成严格树(无环、单亲)——03 章 schema 的
  第一硬校验;军-师-旅-营的层级=树的深度,指挥跨度=节点的
  子数上限(通说 3-5,受通信与认知带宽约束的历史经验值)
- **接口**:模块可编组的条件是**接口标准化**——指挥接口
  (谁指挥谁,军语/频率/报文格式)、保障接口(谁的补给渠道)、
  数据接口(谁的传感器喂谁的射手)。罗马军团的"标准大队"
  (00 章①)之所以可互换,正是因为三接口全标准化;
  现代联盟互操作(STANAG)是同一语法的大规模实现
- **版本**:编制表是版本化文档(修订号+生效日期)——编制史
  可以做成**版本序列的 diff 分析**:哪次改革动了模块(结构)、
  哪次只动了行项(资源)、哪次只改了名(政治)——三类变更
  分开统计,军制变迁的"实质变动率"才有意义

## 3. 骨架二:纸面-实态的折扣结构

三重折扣是力量评估的常量语法(02 章口径眼的结构化):

```
可部署力量 = 纸面编制 × 满编率(fill)× 可用率(readiness)× 在位率(presence)
```

- 历史经验:三折扣连乘的结果常在 0.5-0.7 区间(两次大战与
  冷战评估的通说量级,T4)——**纸面师的一半到三分之二**
  才是可部署师
- 这条公式是 00 章假设一(纸面编制假设)的定量形式;账本 schema
  的 `fill_rate`/`readiness` 字段就是它的载体
- 与[国防经济学](../../讲透经济学/讲透国防经济学/)的接口:
  折扣率的倒数就是"维持一个可部署单位需要的纸面投资"
  ——资源账的军制侧写法

## 4. 骨架三:采办组合的流量结构

- 采办=**把预算流变成装备存量的转移规则**:组合的约束有预算上限
  (年度授权)、产能上限(01 章热线四:产能本身是军事资产)、
  风险分散(单项目失败不致断代)
- **冲突性授权的目标向量**(01 章热线三)在组合层的形态:
  速度目标(里程碑最短)×透明目标(竞争招标)×保密目标×
  工业基础目标(国内产能)——四目标在组合空间里互斥,
  组合前沿而非最优解是唯一诚实输出
- **平台组合的战损权衡**(家族实验的主题):给定预算,"少量
  高价 vs 大量廉价 vs 混合"的选择问题在齐射交换模型下可算
  ——`experiments/force_design_tradeoff.py` 的机制设计:
  混合组合的优势=分散红利(目标多,单点损失小)×网络依赖
  (廉价平台的战力挂在稀缺 C2 节点上)——**两个因子相乘,
  任一归零优势归零**(κ 扫描边界,04 章走廊一)

## 5. 从结构到评估:这套骨架买到了什么

- 模块语法 → 编制改革可以做 diff 统计(实质变动率)
- 折扣结构 → "有几个师"到"能出动几个师"的换算器
- 组合流量 → 采办评估的多目标前沿(替代单一"超支率"批评)
- 平台权衡 → 力量设计的最小可算实验室(费效比+边界条件)

## 6. 构造合法性清单(动手前三问)

把任何军制材料变成数据之前,先过三问——本家族的"类型检查":

1. **快照与版本齐了吗**:编制断言带 as_of 与修订号了吗?
   不带版本的编制表是"活着的合同",每天可能都在改
2. **口径声明了吗**:满编率/可用率的分母与口径(在编/可部署/
   已部署)写进字段了吗?口径不明的率值禁止入库
3. **政治变量标了吗**:兵役入口、授权条款、驻地调整这些
   外生政策变量,是声明值不是推导值——把政治变量当内生
   变量优化的模型,输出的是立场不是方案

三问全过,数据才获得进入 [04 章走廊](04-军制学转代码.md)的
资格。**军制学计算的第一特征不是算法,是合同与口径的入库纪律**
——这一条与[军事史家族](../讲透军事史/03-可构造与结构.md)
的"证据等级入库"同宗,军制版把证据级换成了口径与授权。

## 📌 收束

可构造的是**三套账**(模板/实例/流量),不可构造的是**政治与
认同**;结构不是装饰——折扣结构是评估的换算器,模块语法是
变迁统计的坐标,组合前沿是采办批评的解毒剂。下一章把三套账
接上代码:[04-军制学转代码](04-军制学转代码.md)。

**🧠 认知升维**:

- **三账眼**:任何军队问题先分账——组织账(模板)、形态账
  (实例)、流量账(钱);三账对齐了才算看清一支军队
- **折扣眼**:纸面数字自动乘三折扣(满编×可用×在位),
  乘完再谈对比
- **政策边界眼**:模型里每个外生政治变量都贴声明标签
  ——军制学模型的可信度,首先看它诚实标出了多少个"不归我算"
  的变量
