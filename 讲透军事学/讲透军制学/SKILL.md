# 军制学思维技能卡(GB/T 83045 · 讲透军制学家族的抽象层)

## 1. 何时用此分支(问题特征触发词)

- 「这个军/师/旅**怎么编的**、为什么这么编」——编制解剖需求
- 「军队**改革/转型为什么这么难**」——编制粘性与转型学习
- 「一款武器**从立项到列装**为什么十年起步还超支」——采办
- 「买 5 艘高端还是 50 艘低端还是混着买」——力量结构权衡
- 「征兵制/募兵制/动员体制**怎么运转**」——兵员制度
- 「纸面编制 vs 实际能出动的兵力」——折扣换算
- 「编制表/满编率/采办预算**怎么变成数据**」——schema 级需求
- 「力量设计/Force Design 是什么」——01 章连续设计话语

## 2. 核心思维模式

| 模式 | 操作 |
|------|------|
| **合同眼** | 编制表不是描述是合同:每行员额对应预算、岗位、渠道——读表先读预算 |
| **三件套眼** | 编制(骨架)/装备(手段)/管理(代谢)三张表一起看,单看一张必错(三张皮病) |
| **折扣眼** | 纸面×满编率×可用率×在位率,三重折扣连乘(经验 0.5-0.7)才是可部署力量 |
| **神经-骨架眼** | 指挥是神经,军制是骨架——机构设置问题归军制,命令流程问题归指挥学 |
| **危机创新眼** | 军制创新高发于失败与危机后(耶拿→总参;危局→全民征兵),不在强盛时 |
| **版本眼** | 编制是版本化文档:看改革先分清动了模块层、接口层还是合同层 |
| **目标向量眼** | 评价制度绩效先重构法定目标向量(速度/透明/保密/产能互斥)——单指标批评失焦 |
| **边界眼** | 力量设计结论必带建制参数区间(如 C2 依赖度 κ):单点参数的结论是立场不是知识 |

## 3. 工具箱(何时用什么)

- **学科史四节点**:罗马军团模块化(前3世纪)→全民征兵(1793)
  →普鲁士军区制(1814)→力量设计连续化(2019-)——
  一切编制问题先在此坐标上定位
- **三套账本 schema**(03 章):TOE 行项(带 availability_tier
  与 as_of)/力量结构账本(带 fill_rate)/采办组合(带
  mandate_refs 授权条款)
- **三重折扣换算器**:deployable = paper×fill×readiness×presence
  (04 章 C3 十行实现)
- **齐射权衡模型**(家族实验 `experiments/force_design_tradeoff.py`):
  同预算三组合的战损推演;混合优势=分散红利×网络依赖,
  κ 扫描出条件边界
- **编制三硬校验**:隶属无环/员额加总/装备编配上限(04 章 C2)
- **军语对译表**(02 章):编制 vs 编成 vs 部署;acquisition ≠
  procurement;force design ≠ force development
- **政治变量标签法**:兵役入口/授权条款/驻地调整=外生声明值,
  模型只扫描不优化

## 4. 常见误区与禁忌

- ❌ **纸面直读**:拿编制表员额当实际兵力——三重折扣先乘上
- ❌ **番号拜物**:番号≠兵力≠能力;"精锐番号"的修辞价值大于
  描述价值;跨国比较只比功能不比番号
- ❌ **单指标批评采办**:只骂慢或只骂贵——多目标法定授权下
  慢与贵可能是均衡;批评要落在目标冲突矩阵上
- ❌ **把推演当选型**:齐射/兰彻斯特输出是机器化反事实;
  κ 与折扣率是建制假设,取值是情报评估不是数学
- ❌ **政治变量内生化**:让模型"优化出"兵役制度或基地取舍
  ——那是合同签订,不是计算
- ❌ **敏感红线**:不评价任何国家现行政治制度、军队政策与
  人物;涉外军力量设计/采办改革按公开文献通说,
  只述学理与建制史实
