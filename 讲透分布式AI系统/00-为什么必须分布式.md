# 00 · 为什么大模型必须分布式

> 本章建立全系列地基：**算清一笔账——训练一个大模型要多少显存，为什么单卡装不下**。理解了这笔账，就理解了所有分布式算法（DP/ZeRO/TP/PP）都是在解决"显存怎么分摊 + 通信怎么平衡"。

## 一、训练显存账：四个大头

训练一个模型，显存被四部分吃掉：

### 1.1 权重（Parameters）

模型参数本身。FP16 每个 2 bytes：

$$
\text{权重显存} = N_\text{params} \times 2 \text{ bytes}
$$

### 1.2 梯度（Gradients）

反向传播算出的梯度，和权重一一对应，同大小：

$$
\text{梯度显存} = N_\text{params} \times 2 \text{ bytes}
$$

### 1.3 Optimizer State（最大头！）

Adam 维护 **momentum + variance** 两个状态，且通常用 **FP32** 存（数值稳定）：

$$
\text{Optimizer} = N_\text{params} \times 4 \text{ bytes} \times 2 = N_\text{params} \times 8 \text{ bytes}
$$

> ⚠️ **反直觉**：optimizer state 是权重的 **4 倍**（8 bytes vs 2 bytes）！这是显存最大头。

### 1.4 Activation（激活）

前向中间结果，用于反向。和 batch、序列长度、层数成正比。activation checkpointing 可以用计算换显存（重算），是省显存的关键技术。

### 1.5 实例：Llama-2-70B 训练显存

| 部分 | 计算 | 显存 |
|------|------|------|
| 权重（FP16）| $70\text{B} \times 2$ | 140 GB |
| 梯度（FP16）| $70\text{B} \times 2$ | 140 GB |
| Optimizer（Adam FP32）| $70\text{B} \times 8$ | **560 GB** |
| Activation | 取决于 batch/seq | 几十~几百 GB |
| **合计（不含 activation）** | | **840 GB** |

**单卡 H100 = 80 GB → 装不下 1/10**。这就是为什么必须分布式。

> 🎯 **一句话**：训练显存里，**optimizer state 是最大头**（权重 4 倍），不是权重本身。ZeRO 的核心洞察就是"optimizer state 有 N 卡份冗余，可以分摊"。

## 二、四范式总览

四种分布式范式，解决不同问题：

### 2.1 数据并行（Data Parallel, DP）

**思路**：每卡有**完整模型副本**，但训练**不同 batch 的数据**。每步结束同步梯度。

```
GPU 0: 模型副本 + batch 0    ┐
GPU 1: 模型副本 + batch 1    ├→ AllReduce 梯度 → 同步更新
GPU 2: 模型副本 + batch 2    │
GPU 3: 模型副本 + batch 3    ┘
```

- **优点**：简单，接近线性加速
- **问题**：每卡要装完整模型 → 大模型装不下（70B 单卡都装不下）

### 2.2 ZeRO（Zero Redundancy Optimizer）

**思路**：DP 的基础上，把"冗余的部分"（optimizer state / gradient / parameter）**分摊到各卡**，按需聚集。

- ZeRO-1：分 optimizer state
- ZeRO-2：+ 分 gradient
- ZeRO-3：+ 分 parameter（等价于 FSDP）

详见 [02 篇](./02-ZeRO.md)。

### 2.3 Tensor Parallel（TP，Megatron）

**思路**：把**每一层的矩阵乘法**切到多卡（层内并行）。

```
一层的前向 Y = X·W
切成 W = [W_1 | W_2]（按列）
GPU 0 算 Y_1 = X·W_1
GPU 1 算 Y_2 = X·W_2
AllReduce: Y = [Y_1 | Y_2]
```

- **优点**：每卡只装一部分权重，能训大模型
- **问题**：每层要 AllReduce，**通信频繁**——一般只在机内（NVLink 高带宽）用
- 详见 [03 篇](./03-TP与PP.md)。

### 2.4 Pipeline Parallel（PP）

**思路**：把**不同层**分到不同卡（层间并行），用 micro-batch 流水线。

```
GPU 0: Layer 1-20    ┐
GPU 1: Layer 21-40   ├→ 一个 micro-batch 顺序流过
GPU 2: Layer 41-60   │   多个 micro-batch 重叠填充流水线
GPU 3: Layer 61-80   ┘
```

- **优点**：通信少（只在边界传 activation），适合跨机
- **问题**：流水线 bubble（空泡）降低效率
- 详见 [03 篇](./03-TP与PP.md)。

### 2.5 四范式对比

| 范式 | 切什么 | 通信 | 适合 |
|------|--------|------|------|
| **DP** | 数据 | 梯度 AllReduce（每步）| 小模型 + 多卡 |
| **ZeRO** | optimizer/grad/param | 按需 gather（ZeRO-3）| 大模型，主流 |
| **TP** | 层内矩阵 | 每层 AllReduce | 机内（NVLink）|
| **PP** | 层间 | activation 传递 | 跨机 |

**实际大模型训练**：四者**组合用**——3D 并行（DP + TP + PP）。比如 GPT-3 训练：机内 TP，跨机 PP，全局 DP。

## 三、通信代价：分布式的"隐性税"

分布式不是免费午餐——每步要通信。通信带宽决定扩展效率。

### 3.1 集合通信原语

| 原语 | 做什么 | 复杂度 |
|------|--------|--------|
| **AllReduce** | 所有卡都拿到所有卡梯度的和 | $O(N)$ ring 算法 |
| **AllGather** | 所有卡都拿到所有卡的片段（拼成完整）| $O(N)$ |
| **ReduceScatter** | 每卡拿到聚合结果的一段 | $O(N)$ |
| **Broadcast** | 一卡的数据广播给所有卡 | $O(N)$ |

### 3.2 网络拓扑决定一切

| 层级 | 带宽 | 延迟 | 适合 |
|------|------|------|------|
| **NVLink**（机内 GPU 互连）| ~900 GB/s | 低 | TP（频繁通信）|
| **InfiniBand**（跨机）| ~100-400 GB/s | 中 | PP / ZeRO |
| **以太网** | ~10-100 GB/s | 高 | DP（少量同步）|

> 🎯 **铁律**：**TP 放机内（吃 NVLink），PP/DP 放跨机（吃 IB）**。这就是为什么 3D 并行要这样设计——把通信密集的操作放在带宽高的拓扑上。

### 3.3 通信 vs 计算重叠

高级技巧：**通信和计算重叠**（compute-comm overlap）。一边算当前层，一边通信前一层——隐藏通信延迟。Megatron / FlashAttention 都用这个。详见 [06 篇](.)。

## 四、扩展定律：为什么万卡是必需

GPT-4 估计训练用了 ~25000 H100，Llama-3-405B 用了 ~16384 H100。为什么这么多卡？

### 4.1 训练时间 = 总计算量 / 总算力

$$
T = \frac{6 \times N_\text{params} \times N_\text{tokens}}{N_\text{GPU} \times \text{FLOPS}_\text{per GPU} \times \text{MFU}}
$$

- $6 N D$：训练总 FLOPs（Chinchilla 公式，前向 2ND + 反向 4ND）
- MFU（Model FLOPs Utilization）：实际效率，通常 30-50%

**GPT-3（175B，300B tokens）**：
- 总 FLOPs = $6 \times 175\text{B} \times 300\text{B} \approx 3.15 \times 10^{23}$
- 单 H100 ≈ 1000 TFLOPS = $10^{15}$ FLOPS
- 单卡时间 = $3.15 \times 10^{23} / 10^{15} / 0.4 \approx 9$ 年
- 10000 卡 ≈ 8 小时... 实际要算上通信/IO，要几周

**结论**：要训大模型，**万卡是刚需**，不是奢侈。

## 六、一句话总结

> 🎯 **三句话**：
> 1. 训练显存四部分：权重 + 梯度 + **optimizer state（最大，权重 4 倍）**+ activation——Llama-70B 要 840GB，单卡 80GB 装不下 1/10。
> 2. 四范式：DP（分数据）、ZeRO（分冗余）、TP（层内切矩阵）、PP（层间切模型）——大模型训练组合用（3D 并行）。
> 3. 通信是分布式的隐性税：**TP 放机内（NVLink），PP/DP 放跨机（IB）**；万卡是训大模型的刚需。
