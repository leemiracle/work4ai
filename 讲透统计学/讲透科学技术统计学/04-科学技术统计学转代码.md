# 04 · 科学技术统计学转代码:把文献库变成计算对象

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角)。

---

## 开篇:本家族转代码的不是定理,是管道

数学家族转代码,翻译的是对象与断言;本家族转代码,搭建的是**数据管道**:

```
口径(规则) → 查询(API) → 抓取(分页) → 清洗(解析/消歧) → 指标(计算) → 看板(呈现)
```

本家族是全部统计学里**数据最容易拿到的家**:Crossref、OpenAlex、
Semantic Scholar 都有免费 API,亿级元数据随取随用(01 章主线 B 的开放图谱红利)。
所以本章的问题不是"数据在哪",而是"管道怎么搭得又快又诚实"。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 概念 | 代码化身 | 备注 |
|------|---------|------|
| 文献检索/元数据 | REST API+JSON(Crossref/OpenAlex/S2) | DOI 是天然主键;亿级记录免费 |
| 计数指标 | 论文数/被引/h 指数/影响因子 | h 的核心是"被引列表降序+一趟扫描" |
| 增长拟合 | 对数-线性回归+翻倍期换算 | 本家族实验 Part 1 的全部 |
| 幂律拟合 | 对数-对数回归+尾部斜率 | 实验Part 2 的全部 |
| 引文网络 | 邻接表+中心性(PageRank/入度) | DAG;可局部展开(k-hop) |
| 强度/占比面板 | 分组聚合+时序连接 | 研发仪表盘的骨架 |
| CD 指数 | 边型五元组计数 | 纯机械,难在解释不在算 |

**转不动/转不动的边界(红色区)**:

1. **作者消歧**:同名同姓、改名换机构、缺 ORCID——没有金标准,
   图谱端全是概率猜测。工程对策:接受"实体 resolution 是持续成本",
   版本化消歧结果,不假装一劳永逸。
2. **学科归一化**:分类体系(WoS 类目/Scopus 主题/OpenAlex 概念)互不兼容,
   换体系指标值漂移。工程对策:归一化结果**永远标注分类体系版本**。
3. **口径调查**:Frascati 问卷靠专家判定,无法 API 化。工程对策:
   调查数据进库走另一条采集线,别与文献计量混流。
4. **语义判读**(引用动机/同行评议预测/主题聚类边界):ML 能猜,效度无保证。
   工程对策:输出附不确定性,人审最后一公里。

**边界的一句话**:绿色区=**读帐**(算得出),红色区=**记帐与审计**
(判得定)——管道越往后越需要人,这是本家族与纯计算家族的分别。

## 二、代码走廊清单(三条走廊,每条=对象→数据结构→算法→真实系统)

### 走廊 1:文献数据库 API 走廊(从"搜论文"到"拉数据集")

```
检索需求 ──Crossref/OpenAlex/S2 API──▶ JSON 记录 ──解析──▶ 结构化数据集
   │                                        │
   └──DOI/ORCID 主键────────────▶ 实体链接(论文/作者/机构)
```

- **对象→结构**:论文=DOI(主键)+题录+参考文献列表;作者=ORCID(尽力)+机构;
  三家的记录模型各异(Crossref 是注册处、OpenAlex 是全图谱、S2 带 AI 特征),
  **用 DOI 对齐三家**是标准操作。
- **算法层**:cursor 分页(OpenAlex)/偏移分页(Crossref);
  速率限制下的礼貌并发+指数退避重试;增量抓取(按更新日期过滤);
  缓存(抓过的元数据永不再抓)。
- **真实系统**:文献计量服务(分析机构产出)、开放学术搜索引擎、
  引文管理器的元数据补全。
- **性能工程要点**:亿级库不慌——你要的永远是**子集**;先用过滤参数
  (机构/年份/领域)把集合做小再拉;注意 API 的礼貌政策(Rate-Limit 头),
  把退避写进骨架而不是注释里。

### 走廊 2:引文网络走廊(把参考文献变成图)

```
论文记录 ──references 字段──▶ 有向边(新→旧) ──构建──▶ 引文 DAG
                                        │
                          中心性(PageRank/入度)·共被引·耦合·CD 边型
```

- **对象→结构**:引文网=有向无环图(只引已发表者,00 章引擎 2);
  邻接表存储;局部展开(k-hop around a seed paper)是内存友好形态。
- **算法层**:入度=承认计数;PageRank=带衰减的承认(引用者的地位也计入);
  共被引/文献耦合=从"边"造"相似度"再聚类——科学地图的流水线;
  CD 指数=对每篇论文数后继引用的边型(颠覆/巩固)。
- **真实系统**:学术搜索排序(网络指标+文本相关性混合特征)、
  推荐系统(共被引近邻)、领域综述的自动初稿。
- **性能工程要点**:全图数十亿边不必装内存——**抽样与局部估计**:
  PageRank 可在 k-hop 子图上近似;共被引矩阵只对种子集计算;
  增量更新只触碰新论文的邻域(新边不改变旧边的入度)。
  图算法的地基在 [../../讲透数学/讲透图/](../../讲透数学/讲透图/)。

### 走廊 3:指标计算走廊(从原始量到可比量再到看板)

```
原始记录 ──聚合──▶ 面板(国家×年度×指标) ──变换──▶ 强度/归一化/指数 ──呈现──▶ 仪表盘
```

- **对象→结构**:面板表(行=国家/机构,列=年度);MSTI 就是这种形态的成品
  (148 项指标,01 章);调查侧(GERD 族)与文献侧(产出族)两源合流。
- **算法层**:比率化(÷GDP、÷人数);增长率与翻倍期(实验 Part 1 的拟合);
  学科归一化(领域-年份期望被引);复合指标(OECD/JRC 手册的敏感性检验流程)。
- **真实系统**:研发仪表盘(机构/区域/国家)、科技统计年鉴的生成管道、
  政策简报的图表底座。
- **性能工程要点**:这一走廊的瓶颈不是算力是**口径版本**——
  时间序列接错版本(口径修订断点)比慢一万倍更致命;
  指标管道要像代码一样有 version pin。

## 三、工程师落点(两个主战场+一张速查表)

### 战场 1:学术搜索引擎

- 排序=文本相关性+网络指标(被引/PageRank)+新鲜度;
- 引文网指标可**离线预计算**(承认分数随时间单调,适合物化);
- 实体链接(DOI/作者消歧)是搜索质量的地基——走廊 1 的功底全用上。

### 战场 2:研发仪表盘(R&D dashboard)

- 面板 ETL:调查数据(投入)+文献计量(产出)+财务(经费)三源管道;
- 诚实呈现是硬需求:幂律数据**报中位数与百分位**,不只报均值(00 章发现 3);
  排名附区间与权重敏感性(02 章莱顿原则的工程化)。

| 你遇到的问题 | 工具/方法 | 落点 |
|-------------|----------|------|
| 批量拉一个机构的全部论文 | Crossref/OpenAlex API+机构过滤+分页 | 走廊 1 |
| 给研究者/论文排"承认度" | 入度/PageRank+学科归一化 | 走廊 2 |
| 评估团队产出质量 | h/归一化被引+分布呈现(勿单值) | 走廊 3 |
| 识别领域前沿/睡美人 | 参考文献年龄分布+被引曲线 | 走廊 2 |
| 国家/区域研发对比 | 面板聚合+强度+口径版本管理 | 走廊 3 |
| 文献综述冷启动 | 共被引聚类+高 PageRank 种子 | 走廊 2 |
| PDF 参考文献解析 | GROBID 类解析器 | 走廊 1 前置 |

**性能工程的管道观**:本家族的"优化"大头不是循环,是**缓存、增量与诚实**——
不重抓(缓存)、不重算(增量)、不装精确(分布)。
三条都要在设计期写进管道,事后补的都是事故。

## 四、三问检验仪式(把本家族用成瑞士军刀)

遇到任何科技指标看板,做三问:
1. **口径问**:定义域是什么?哪个手册哪个版?数据源边界在哪?
2. **来源问**:哪个库、哪年抓的?口径修订过吗?序列接过断点吗?
3. **分布问**:这是均值还是中位数?数据是幂律的吗?前 1% 扛了多少?

三问过完,看板的骨架与伤疤一起显形——剩下的才是真正的难点(解释与治理)。
