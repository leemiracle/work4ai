# 04 · 生物与医学统计学转代码:三条走廊与两个落点

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角)。
> 家族的特殊性先立:本分支转代码的验收标准不是「算得快」,是「**经得起审计**」——
> 逐位重演(03 章)、全程留痕(02 章 GCP/CONSORT)、边界诚实(法规红线)。
> 换言之:这是一门**把统计纪律写成基础设施**的工程。

---

## 开篇:别的分支在「实现算法」,本分支在「浇筑流程」

数理统计转代码,重心是把估计量/检验写成正确高效的函数;
生医统计转代码,重心是把**从随机化到 p 值的整条链路**铸成可复现、
可审计、可监管的管线:随机化列表要封存、期中分析要预锁、
数据修正要留痕、分析代码要版本冻结(SAP 指定的版本,一行不许动)。
写代码的人在这里多了一个身份:**法庭书记员**。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 生医概念 | 代码化身 | 备注 |
|---------|---------|------|
| KM 估计/中位数/RMST | 事件表→风险集扫描→连乘(纯标准库可实现) | 本家族 `experiments/00_survival_sim.py` 全手写,逐位对齐教科书 |
| logrank(含分层/加权) | 事件时刻 2×2 表聚合→χ² | 大样本渐近;小样本换置换版 |
| Cox 回归 | 偏似然+牛顿迭代(梯度=残差,黑塞=信息矩阵) | ~50 行可实现单协变量;工业级看 lifelines/survival |
| 样本量/功效 | 解析公式(logrank 事件数 d=4(z_{α/2}+z_β)²/(ln HR)²)+仿真两条路 | 设计阶段的法定计算 |
| 随机化列表(区组/分层) | 分层内随机区组生成器+密封信封(软件化=IRT 系统) | 可复现种子+留痕是合规要件 |
| alpha 消耗/期中边界 | 边界序列计算+独立数据监查委员会(IDMC)触发逻辑 | 01 章战线 3 的 ICH E20 落地形态 |
| 标准化(直接/间接/SMR) | 率表×标准人口的矩阵乘 | 流行病支标准件 |
| 多重检验校正 | BH/qvalue/置换 FDR(数学本体见 [数理统计 FDR 实验](../../讲透数学/讲透数理统计/experiments/00_fdr.py)) | 组学支的法定出口 |
| CONSORT 流程图 | 数据库视图:随机化人群流向的自动记账 | 报告自动化=审计自动化 |

**转不动/转不动的边界(红色区)**:

1. **因果强度本身**:RWE 的未测混杂无法由数据证明不存在——代码只能做
   **敏感性分析**(E-value 类:扫描「多强的隐藏混杂才翻案」),不能「解决」混杂。
   目标试验仿真的管线(走廊 2 落点)管的是**纪律的机械化**,不是因果的机械化。
2. **伦理约束下的设计优化**:数学可以最小化样本量,但「对照组能不能用安慰剂」
   「何时必须早停」是伦理委员会的判断;优化器没有「临床均势」这个目标函数项。
3. **个体因果效应(HTE)**:个体级反事实不可识别——代码能拟合预测模型、
   能做亚组分析,**不能**输出「这个病人用新药多活 X 月」的因果断言。
4. **替代终点→临床结局的桥**:统计上可估相关性,桥的**有效性**要生物学证据;
   代码只能监控桥(相关性追踪),不能担保桥。
5. **监管裁量**:同一份管线,FDA/EMA/NMPA 可能不同裁决——流程可以自动化,
   **决定权的设计**永远在人间。

**边界的一句话**:绿色区=「纪律的可执行化」(几乎全量);红色区=「判断的不可替代化」
(因果强度/伦理/监管)——**代码是书记员,不是法官**。

## 二、代码走廊清单(三条走廊,每条=对象→数据结构→算法→真实系统)

### 走廊 1:生存分析走廊(KM/logrank/Cox 的全链路)

```
(T,δ) 观测表 ──排序/风险集──▶ 事件时刻快照序列 ──构造──▶ KM 曲线/logrank/Cox
      │                                          │
      └── CDISC/ADaM 标准数据集 ◀── 分析代码冻结(SAP 版本) ◀── TLF(表-图-清单)输出
```

- **对象→结构**:生存观测=(时间,事件比特,协变量);风险集=按事件时刻的倒排索引
  (03 章引擎 1);Cox 的偏似然=每事件时刻一次 softmax(死者得分/风险集总分的竞赛)。
- **算法层**:KM=连乘;logrank=期望/方差累计;Cox=牛顿迭代(单协变量版 30 行内);
  PH 检验=Schoenfeld 残差对时间回归——**上线前的体检必做**(02 章)。
- **真实系统**:临床试验统计编程(SAS proc lifetest/proc phcomp 的开源替代 lifelines、
  R survival);医院结局研究;CDISC 数据标准(数据结构由法规定——02 章规范化的工程化身)。
- **性能工程要点**:事件时刻扫描 O(n log n);大 n×多协变量 Cox 的瓶颈在
  风险集得分和(可增量维护;历史上 Breslow/Efron 并列处理是正确性与速度的谈判点)。
  **正确性压倒速度**:渐近公式与置换版双实现互检,是本走廊的审计配置。

### 走廊 2:RCT 功效计算走廊(从公式到期中仿真)

```
设计假设(HR/α/功效/入组率) ──Schoenfeld 公式──▶ 事件数/样本量 ──仿真验证──▶ 设计证书
        │                                                                │
        └── alpha 消耗边界 ──▶ 期中分析触发器 ──▶ IRT 随机化系统(分层区组+封存)
```

- **对象→结构**:设计=参数包(效应量/α/β/脱落率/入组曲线/期中次数);
  序贯边界=预计算的分位点序列。
- **算法层**:样本量公式(解析初值)→事件驱动仿真(入组泊松+事件指数+删失,
  即 `00_survival_sim.py` 的造数器)→边界穿越概率(验证 α 不膨胀、功效达标)。
  **三步法**:直觉(样本量≈事件数/事件率;HR 越接近 1 事件数平方级膨胀)→
  严格(Schoenfeld 公式+脱落/入组修正)→最小例子(HR 0.6→0.9,样本量×10 的实拍)。
- **真实系统**:试验设计器(临床运营的样本量计算器+边界表);IRT(交互式应答技术)
  随机化系统——分层区组、药物编号、应急破盲;IDMC 期中报表(独立统计师执行,
  申办方只见结论——防火墙也是架构)。
- **性能工程要点**:功效仿真是**蒙特卡洛服务化**的典型场景(设计参数扫描=参数网格,
  千次重复×参数组合,天然并行);但**种子管理必须可复现**——监管重演时,
  同种子同结果,随机数发生器版本都要写进设计文档。

### 走廊 3:组学 FDR 走廊(p≫n 的发现流水线)

```
表达矩阵(基因×样本) ──标准化/voom 类权重──▶ 每基因线性模型 ──▶ p 值向量(数万~百万)
        │                                                        │
        └── 经验贝叶斯 shrinkage(ebayes 思想)                   ▼
                                             BH/qvalue 阈值 ──▶ 发现集+火山图+通路富集
```

- **对象→结构**:矩阵行为基因(百万级)、列为样本(几十);检验=逐基因 t/线性模型,
  但方差借全库信息收缩(经验贝叶斯:小样本方差的救命稻草)。
- **算法层**:BH 阈值一行(见 [数理统计 FDR 实验](../../讲透数学/讲透数理统计/experiments/00_fdr.py)
  的手写实现与 FDR≤q 断言);qvalue 的 π₀ 估计(重估 null 占比,把「多数基因无差异」
  这条先验变成增益);富集=发现集上的超几何/排列检验。
- **真实系统**:差异表达管线(limma/DESeq2 思想谱系);单细胞流程(Seurat 类);
  A/B 平台监控的告警风暴治理(同一套 BH 迁移到工程告警,数学本体完全同源)。
- **性能工程要点**:逐基因模型是**完美向量化对象**(矩阵化后 numpy 一气呵成,
  百万检验秒级);瓶颈在 I/O 与多重校正的相依结构讨论——**FDR 的可复现性
  依赖管线容器化**(版本冻结=02 章审计链的组学形态)。

## 三、工程师落点(性能工程视角的速查表)

### 落点 1:临床试验设计器

一个内部工具的完整画像:**输入**设计假设(HR/α/功效/入组曲线/脱落/期中次数)
→ **输出**样本量、期望事件数、期中边界序列、操作特征曲线(α 花费/功效随 HR 变化)
→ **核心**=走廊 2 的公式+仿真双引擎(公式给初值,仿真给真值)
→ **工程要点**:参数扫描网格化+缓存;报告自动生成(设计证书直接出 PDF);
审计日志(谁在何时改了哪个假设——GCP 思想内化到工具)。

### 落点 2:真实世界证据管线

目标试验仿真的数据工程(01 章战线 2 的落地形态):
**协议优先**(先写目标试验七要素,再碰数据)→ 数据对齐(合格标准落地为
SQL/DSL 查询)→ 克隆-删失-加权(每人多份克隆、策略偏离即删失、IPCW 权数列)
→ 生存分析标准件收尾(走廊 1 复用)→ 敏感性分析出口(E-value 扫描、
阴性对照结局)。**工程要点**:策略偏离的检测规则库、权数稳定性诊断、
全链路版本冻结——这条管线的价值=「纪律可审计」,性能反而是次要指标。

### 速查表

| 你遇到的问题 | 工具 | 落点 |
|-------------|------|------|
| 「治疗有没有延长生存」 | KM+logrank(+Cox 调协变量) | 走廊 1;PH 检验必做 |
| 「要多少人/多少事件」 | Schoenfeld 公式+事件驱动仿真 | 走廊 2/落点 1 |
| 「期能不能提前看数据」 | alpha 消耗边界+IDMC 触发器 | 走廊 2 |
| 「几百万个检验怎么报」 | BH/qvalue(+经验贝叶斯) | 走廊 3;FDR 本体在数理统计 |
| 「观察数据库里比疗效」 | 目标试验仿真管线 | 落点 2;混杂敏感性分析 |
| 「分组怎么造才合规」 | 分层区组随机化生成器(IRT 思想) | 走廊 2;种子封存+留痕 |
| 「报告怎么不漏」 | CONSORT 自动记账视图 | 走廊 1 的数据面 |

## 四、可机械化的检验仪式(把本家族用成瑞士军刀)

遇到任何生医数据系统,做三问:
1. **时间问**:结局是「到事件的时间」吗?有删失吗(什么机制)?
   ——是,就上风险集语法;当普通均值比较就输在起跑线
2. **随机问**:分组怎么来的(随机/医生指定/自选)?——分组的来源决定
   能用置换引擎(03 章)还是必须走仿真纪律(01 章战线 2)
3. **多重问**:同时在检验多少个假设(多臂/多终点/多时点/多基因)?
   ——超过一个就记 alpha 账本;超过一百个就上 FDR

三问过完,系统该走哪条走廊、哪些结论**永远不能**由代码代答,一目了然。
