# 04 · 经济统计学转代码:把仪表盘搬进终端

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角)。

---

## 开篇:别的统计分支在"建模",本分支在"建厂"

数理统计转代码,核心是复现推断(bootstrap/MCMC);
本家族转代码,核心是**复现生产线**:拉数据、对日历、算指数、
做季节调整、换不变价——每一步都是国家统计局车间的公开工序。
工化程度高意味着两件事:①可机械化的比例极大;②**陷阱全在口径里**
(版本、基期、季节调整与否),不在算法里。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 经济统计概念 | 代码化身 | 备注 |
|-------------|---------|------|
| 指数(拉氏/帕氏/费雪/链式) | 十行加权平均+连乘 | `experiments/00_chain_index.py` 全流程可跑 |
| 名义→实际(不变价) | 除以平减指数 ×100 | 一行,但"哪年的价"必须显式参数化 |
| 同比/环比/年化 | 滚动窗口对数差 | `ln(x_t/x_{t-1})×100`;年化 `×4` 或 `^4`(环比) |
| 季节调整 | X-13 思路的移动平均复刻(走廊 3) | 简化版可自写;生产级用 `statsmodels.x13`/`seasonal` |
| 时序对齐(月度↔季度) | 重采样+日历对齐 | `pandas.resample`;留意各国财年/工作日数差异 |
| PPP 换算 | 乘/除购买力平价因子 | 因子表从世行 ICP 下载,注意轮次年份 |
| 仪表盘 | API→DataFrame→图表 | 走廊 1 的终点 |

**转不动/转不动的边界(红色区)**:

1. **口径裁决**:这笔回款算出口还是转口?自有住房该虚拟多少租金?
   ——SNA 手册数百页的制度谈判,无算法。工程对策:把口径做成
   **元数据字段**随数据走,绝不硬编码。
2. **质量调整的商品对应**:hedonic 需要特征数据与回归裁决
   ("屏幕大 1 英寸值多少");新品的特征组合史无前例。
   工程对策:hedonic 回归框架可自动化(走廊 2),特征定价仍需人工复核。
3. **数据修订的原因诊断**:同一个季度的数字变了——是新数据、方法、
   还是口径切换?统计机构自己都要写论文解释。工程对策:按
   **vintage(版本号)存档**所有拉取(03 章"数字有版本号")。
4. **免费品/福利估值**:选择实验的设计与执行是科学实验,
   不是管道(01 章 GDP-B 仍属研究前沿)。

**边界的一句话**:绿色区=一切"已定义清楚的计算",红色区=一切"定义本身
在谈判的东西"。本家族的工程纪律是:**计算可以自动,口径永远显式**。

## 二、代码走廊清单(三条走廊,每条=对象→数据结构→算法→真实系统)

### 走廊 1:数据管道走廊(FRED 与全球指标 API)

```
官方 API(FRED/世行/欧统局/统计局) ──▶ DataFrame 对齐 ──▶ 口径换算 ──▶ 仪表盘
     │ vintage 存档                      │ 月/季混合          │ 平减/PPP/年化
     └── 元数据(单位/季节调整/基期)随行 ──┴─ 工作日历对齐     ┴─ 异动告警
```

- **对象→结构**:序列(id, 频率, 单位, seasonal_adjusted, vintage)——
  **vintage 与口径字段是一等公民**,不是注释。
- **算法层**:API 拉取→合并外连接按日期对齐→对数变换→同比/环比年化。
- **真实系统**:FRED(圣路易斯联储,免费 API key)、世行 WDI、
  Eurostat SDMX、国家统计局;下游=Grafana/Streamlit 仪表盘、
  宏观因子库(量化基金的标准组件)。
- **性能工程要点**:官方 API 限速(串行礼貌抓取+本地缓存全量落盘);
  时间序列对齐用 `merge_asof` 处理各国发布日错位;
  **永不在管道里隐式做季节调整**——混合口径是宏观数据工程第一大坑。

### 走廊 2:指数计算走廊(从固定权重到 hedonic)

```
价格×数量表 ──▶ 拉氏/帕氏 ──▶ 费雪(几何调和) ──▶ 链式连乘
     │
     └── 特征表(规格/性能) ──▶ hedonic 回归 ──▶ 质量调整价格
```

- **对象→结构**:一期一张 (商品, 价格, 数量[, 特征]) 长表。
- **算法层**:
  - 拉氏 `Σpₜq₀/Σp₀q₀`、帕氏 `Σpₜqₜ/Σp₀qₜ`、费雪 `√(L·P)`;
    链式=逐段连乘(全部实拍于 `experiments/00_chain_index.py`);
  - 几何平均(Jevons/Superlative 类):类内先用几何平均——
    这一个改动约值 0.2-0.3 pp/年的替代偏差修正;
  - hedonic:`ln(price) ~ 特征` 回归,残差即质量调整后的价格变动——
    BEA 对 IT 产品做了四十年(00 章反直觉 2 的算法本体)。
- **真实系统**:各国 CPI 编制系统、Scanner 数据研究管线
  (亿行级超市扫码数据直接进 CPI 的实验项目,如 ONS/RBNZ)。
- **性能工程要点**:亿行 scanner 数据用列式引擎(DuckDB/Polars)
  按"商品组×期间"分组聚合;hedonic 回归按组滚动重估
  (系数漂移本身是信息:特征定价在变)。

### 走廊 3:季节调整走廊(X-13 思路的工程复原)

```
原始序列 y ──▶ 离群值预调整(疫情/罢工) ──▶ 趋势滤波(中心化移动平均)
   ──▶ 季节因子估计(按月/季聚合,逐年滑动) ──▶ 迭代至收敛 ──▶ 季调序列
```

- **对象→结构**:乘法模型 `y = T × S × I`(趋势×季节×残差),
  或加法 `y = T + S + I`;季节性检验(月度序列的 12 期自相关/谱峰)。
- **算法层**(简化 X-13 三步):
  1. 中心化移动平均提取趋势 T̂;
  2. `y/T̂` 按月聚合平均得季节因子 Ŝ(逐年滑动窗口更新);
  3. 季调序列 = `y/Ŝ`;迭代 2-3 轮收敛。
  生产级:X-13ARIMA-SEATS / TRAMO-SEATS(`statsmodels` 可调),
  关键在**离群值预调整**——不摘除 2020 级冲击,季节因子会被永久污染。
- **真实系统**:全球统计局月度数据发布标配;央行短观调查。
- **性能工程要点**:全历史重估——每来一个月新数据,
  X-13 重算的**历史季调值会小幅回漂**;工程上要么实时重算全序列,
  要么冻结并发布"修订政策"(又是 vintage 问题)。

## 三、工程师落点(性能工程视角的速查表)

| 你遇到的问题 | 经济统计工具 | 落点 |
|-------------|-------------|------|
| 要一排国家 × 一排指标的历史 | 官方 API 管道 | 走廊 1;vintage 落盘 |
| 名义增速怎么变实际增速 | 平减指数 | 除以同基期平减指数;检查基期年份 |
| CPI 数据做生活成本追踪 | 链式/几何平均指数 | 走廊 2;别拿固定权重算十年 |
| 月度序列有春节/圣诞周期 | 季节调整 | 走廊 3;中国春节用移动假日模型 |
| 跨国比较收入水平 | PPP | 世行 ICP 因子;标明轮次 |
| 给业务做宏观仪表盘 | FRED→Grafana/Streamlit | 同比+环比+z-score 异动告警 |
| 通胀挂钩合同/年金重算 | 官方 CPI 公式复刻 | 公式与基期以合同文本为准(可诉) |
| 回测宏观策略 | vintage 数据 | 只用"当时可见"的初值,防前视偏差 |

**性能工程的核算观**:经济数据工程最大的事故不是算错,
是**口径错配**——不同基期、不同季节调整、不同 vintage 的序列
被 join 进同一张表。设计数据层时,把"口径三元组"
(基期/季节调整/vintage)当成主键的一部分,是本家族给数据工程
最贵的一条礼物。

## 四、可机械化的检验仪式(把本家族用成瑞士军刀)

遇到任何经济数据,做三问:
1. **指数问**:它是指数还是水平?什么公式(固定/链式/几何)?基期哪年?
2. **口径问**:名义还是实际?季节调整没有?哪版 SNA/哪个统计机构?
3. **版本问**:这是初值还是第 N 次修订?历史会回漂吗?

三问过完,数字才真正进入你的系统——剩下的才是建模(交给
../../讲透经济学/ 数量经济侧与 ../../讲透数学/讲透数理统计/)。
