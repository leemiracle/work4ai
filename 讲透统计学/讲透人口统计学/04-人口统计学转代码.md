# 04 · 人口统计学转代码——普查、投影与死亡率因子三条走廊

> **本章回答五问之 Q5(问题→代码转换)**。
> **本质一句话**:人口统计学的计算内核惊人地小——一张年龄表、一个矩阵乘法、
> 一次低秩分解;**不能外包给代码的,是口径裁决(谁算常住人口)与参数信仰
> (生育率往哪走)**。本章三件套:可机械化边界 → 三条代码走廊 → 工程师落点。

---

## 0. 开篇:三行代码的官方预测

```python
def step(L, n):                    # n = 各年龄组人口(列向量)
    return [sum(L[i][j] * n[j] for j in range(3)) for i in range(3)]
```

**全世界所有官方人口预测,剥掉包装,核心就是这一行的豪华版**——队列要素法:
把 L 从 3×3 换成逐年龄×性别×逐年变化的版本,再加上迁移项。联合国的概率化预测(01 章)
是给它外面套了上万次抽样。一个学科的最高科技产品,内核三行——这是工程师进入本家族
最友好的门。

## 1. 可机械化边界(三件套之一)

**能进代码的**(结构计算,03 章的全部):

| 任务 | 机械化形式 | 走廊 |
|------|-----------|------|
| 生命表构造 | q_x→l_x→L_x→e_0 的纯算术流水线 | C1 |
| 年龄金字塔/抚养比 | 年龄×性别计数→份额→比值 | C1 |
| Leslie/队列要素投影 | 矩阵乘法+特征值(增长率/稳定结构) | C2 |
| Lee-Carter 拟合 | 中心化 log 死亡率矩阵的低秩分解+约束 | C3 |
| 普查再加权 | 抽样权数→总体估计;双系统估计公式 | C1 延伸 |
| 数据质量指数 | Whipple/Myers 指数(年龄堆积检测) | C1 延伸 |

**不能进代码的**(本家族的「不可判定域」):

1. **口径裁决**——谁算「这个城市的人」(常住/户籍/工作日人口):政治+统计判断,
   代码只负责执行口径,不负责裁决口径。城镇化率不可跨国直接比(02 章 §2)是本条的
   国际法版本。
2. **数据质量的信任决策**——Whipple 指数告诉你堆积严重,修不修、用什么平滑、
   回填多少婴儿死亡:是统计学家的责任判断,不是一个阈值。
3. **生育率参数的信仰**——超长期 TFR 走向没有任何方法能从数据内决定;贝叶斯先验
   =把判断穿上概率的外衣(01 章 §3)。写 `TFR_2050 = 1.4` 的那行代码,
   装载的是世界观,不是测量。
4. **情景的语义**——SSP/政策变体是 what-if 不是预报;「中变体被当成承诺」的传播事故
   无法用代码防御,只能用文档纪律(变体名必须随数同行)防御。

> 边界的一句话:**代码是人口结构的显微镜,不是人口学家**——倍数越高,
> 越要记得载玻片(口径与参数)是谁准备的。

## 2. 走廊 C1:普查数据(三件套之二)

**最小成品骨架**(纯标准库,输入=年龄×性别计数表):

```python
# pop = {("M", 0): 480, ("M", 5): 510, ("F", 0): 455, ...}  # 5 岁组
def pyramid(pop):
    total = sum(pop.values())
    share = {k: v / total for k, v in pop.items()}
    youth = sum(v for (s, a), v in pop.items() if a < 15)
    old   = sum(v for (s, a), v in pop.items() if a >= 65)
    work  = total - youth - old
    return share, old / work          # 份额 + 老年抚养比
```

**数据字典**(普查走廊的表):

| 字段 | 类型 | 约束/坑 |
|------|------|--------|
| sex | 枚举 M/F | 出生性别比(105±)是数据质量哨兵:偏高=选择性漏报或性别选择 |
| age | int(组起点) | **年龄堆积**:Whipple 指数>105 需平滑声明(03 章 §5) |
| count | int | 口径字段必随行:常住/户籍、普查日、是否含军警/集体户 |
| (建议加)coverage | PES 修正标记 | 未修正数与修正数不可直接拼接成时间序列 |

**示范问题**:同一国家两次普查的金字林叠放——底座收窄(生育下行)、顶部增宽
(存活改善)、中段凹陷(动量与迁移的痕迹)——三个结构性事实一次读出。

## 4. 走廊 C3:Lee-Carter 思路(骨架,非成品)

C3 给**思路走廊**而非成品(生产环境请用 `numpy.linalg.svd`):
两步估计+一步外推:

```python
# 1) 中心化:A[x][t] = log m(x,t);a_x = 行均值;C = A − a_x(每行减均值)
# 2) 低秩:C ≈ b_x · k_t(秩 1)——用幂迭代取 C·Cᵀ 的主特征向量得 b,再解 k
#    归一约束:Σb_x=1, Σk_t=0(可识别性,03 章 §4)
# 3) 外推:k_t 按随机游走带漂移外推 → m̂(x, t+Δ) = exp(a_x + b_x·k̂_{t+Δ})
def power_first_pair(C, iters=200):        # 纯标准库幂迭代(示意)
    n = len(C)                              # C: 年龄×年份(嵌套列表)
    v = [1.0 / n] * n
    for _ in range(iters):
        w = [sum(C[i][j] * v[i] for i in range(n)) for j in range(len(C[0]))]
        z = [sum(C[i][j] * w[j] for j in range(len(C[0]))) for i in range(n)]
        nv = sum(x * x for x in z) ** 0.5
        v = [x / nv for x in z]
    return v                                 # v = b_x(年龄敏感度指纹)
```

**数据字典**(因子走廊的死亡率表):

| 字段 | 类型 | 约束/坑 |
|------|------|--------|
| m(x,t) | float>0 | 死亡数/暴露人年;0 死亡格需平滑(婴儿/高龄) |
| x, t | int | Lexis 格位(03 章 §2):数据错位=第一类 bug |
| (输出)k_t | float 序列 | 外推前先诊断:漂移稳定吗?2020 残差进 k 还是进 ε(03 章练习 3) |

## 5. 工程师落点(三件套之三)

**落点 1:人口预测 API**。把队列要素法做成服务:输入(基年人口+三组率+区间规格)→
输出(逐年人口+区间)。接口设计三原则:**率版本化**(L 矩阵的每个版本可回溯——
预测数字必须能拆成「数据版本+参数版本+代码版本」);**区间必带**(点值只是摘要,
01 章 §3);**口径声明字段**(常住/户籍,返回值不带口径=埋雷)。应用侧:养老金精算
(法定要按人口假设出报告)、学校/医院床位规划、SaaS 市场规模测算(TAM 的年龄结构校正)。

**落点 2:老龄化仪表盘**。数据管道:WPP 公开 CSV(或本国普查表)→ C1 金字塔 →
指标层(老年抚养比/潜在支撑比/e_0 与 HALE 双轨)。设计要点:**金字塔时间轴回放**
(把 1950-2100 的结构变化做成动画——「倒置」是动态事实,静态截图讲不出);
**变体切换器**(中变体/区间带并列展示,防「中变体=承诺」的误读);
**动量标注**(在时间轴上标出「当前增长中已锁定的部分」——00 章 §七的工程化)。

**落点 3:你的用户的「常住人口」问题**。互联网口径之爰:DAU 是 de facto(当天在场)
还是 de jure(注册归属)?多设备用户=流动人口的双重居住;换机/共享账号=普查的重复
计数;双系统估计(捕获-再捕获)可以直接搬去估真实用户数。人口统计学三百年攒下的
口径智慧,是用户度量这场泥潭战里少数现成的武器(02 章 §4「可数性的代价」的用户版)。
