# 03 — 规划与搜索：CoT、ToT 与计划-执行分离

> 「讲透 Agent」第四篇。前两篇讲了 Agent 的"循环"和"手脚"，本篇讲"大脑"——**当任务有多步决策、走错了能回头、需要权衡多个候选时，Agent 怎么思考？** 从最朴素的 CoT（线性思维链）到 ToT（树搜索），再到 ReWOO（计划-执行分离），三种规划策略一次讲透。
>
> 配套实验：`experiments/03_planning.py`。

---

## 1. 灵魂：一句话钉死

> **CoT 是一条线（贪心走到底不回头），ToT 是一棵树（走错了回头再试），ReWOO 是一张图（先全局规划再机械执行）。三者的本质差异是「思考空间」的拓扑：一维 vs 树状 vs 一次性。**

$$
\underbrace{\text{CoT}}_{\text{一维 · 线性}}
\quad\xrightarrow{\text{加回溯}}\quad
\underbrace{\text{ToT}}_{\text{树状 · 搜索}}
\quad\xleftarrow{\text{减回溯加规划}}\quad
\underbrace{\text{ReWOO}}_{\text{一次性 · 先想后做}}
$$

**核心论断**：思考空间越宽，准确率越高但 token 越贵。CoT 省 token 但脆；ToT 抗难但贵；ReWOO 中庸且省。**没有银弹，要看任务难度选**。

---

## 2. 从「思维链」到「思维树」

### 2.1 CoT（Chain of Thought）：线性思考

最朴素的规划：LLM 一步一步想，每步基于上一步的结论。这就是 CoT（[Wei et al. 2022](https://arxiv.org/abs/2201.11903)）。

```
问题: 罗纳尔多是哪年获得金球奖的?
Thought 1: 我需要先确认是哪个罗纳尔多 —— 巴西大罗还是葡萄牙C罗
Thought 2: 假设是大罗, 他 1997 年首次获金球奖
Thought 3: 但还可能是C罗, 他 2008 年首次获金球奖
Thought 4: 题目没说, 我应该列出两个答案
Final Answer: 大罗 1997, C罗 2008
```

**特点**：
- **拓扑**：一维序列（$s_0 \to s_1 \to s_2 \to \cdots \to s_n$）
- **决策**：每步只选 1 个"最优"思路，不保留候选
- **回溯**：❌ 没有。走错了就错了。
- **适用**：流程顺、决策点少、走错了影响小的任务（如多跳问答）

### 2.2 ToT（Tree of Thoughts）：树搜索

[Yao et al. 2023](https://arxiv.org/abs/2305.10601) 提出：把"思维链"扩展成"思维树"。每个思考节点生成 $k$ 个候选，评估每个的价值，DFS/BFS 搜索，走错了回溯。

```
                        [初始问题]
                       /     |     \
                  候选1   候选2   候选3     ← 生成 k=3 个候选思路
                  /  \     |       |
              子1  子2   子3     子4     ← 每个候选再生成子候选
              ✓    ✗     ✓       ✗
              └─── 最佳路径 ────┘
```

**特点**：
- **拓扑**：$k$ 叉树
- **决策**：每步生成 $k$ 个候选，评估后选最优
- **回溯**：✅ 有。失败分支剪掉，回上一个分叉点。
- **适用**：高难度可回溯任务（24 点、数独、代码、创意写作）

### 2.3 ReWOO：计划-执行分离

[Xu et al. 2023](https://arxiv.org/abs/2305.18323) 提出 Reasoning WithOut Observation：**先一次性生成完整计划，再严格按计划执行，期间不再调 LLM**。

```
阶段1 Plan:    LLM 一次性输出 5 步:
              Step1: 查 X
              Step2: 查 Y
              Step3: 用 X,Y 算 Z
              Step4: 用 Z 查 W
              Step5: 综合 X,Y,Z,W 答

阶段2 Execute: 严格按 plan 执行 (不再问 LLM), 把结果填回占位符
阶段3 Solve:    最后再调 1 次 LLM 综合答案
```

**特点**：
- **拓扑**：DAG（有向无环图）
- **决策**：plan 阶段全局规划，execute 阶段机械执行
- **回溯**：❌ 没有。但 plan 一次定全局。
- **适用**：流程固定、可预先列出的任务（API 编排、ETL、批处理）

---

## 3. 数学视角：三种规划是三种搜索策略

把 Agent 看作在状态空间 $\mathcal{S}$ 里搜索路径 $\pi: s_0 \to s_g$：

| 范式 | 搜索算法 | 节点扩展复杂度 | 是否完整（一定能找到解）|
|------|---------|:-----------:|:-------------:|
| **CoT** | **贪心**（Greedy）| $O(d)$（$d$=深度）| ❌ 易陷局部最优 |
| **ToT** | **DFS + 剪枝** 或 **BFS**| $O(k^d)$（最坏）/ $O(k \cdot d)$（剪枝好时）| ✅ 完整（深度有界时）|
| **ReWOO** | **开环规划**（一次定全程）| $O(1)$（plan 1 次）| ❌ plan 错就全错 |

**关键洞见**：ToT 在最坏情况下是 $O(k^d)$（指数爆炸），但**配上剪枝后通常是 $O(k \cdot d)$**（线性）——这就是为什么实验里 ToT k=5 的 token 只是 k=1 的 3-5 倍，而不是 25 倍。

形式化：CoT 是 $\arg\max_a V(s, a)$，ToT 是 $\arg\max_\pi \sum_t V(s_t, a_t)$（带回溯），ReWOO 是 $\pi^* = \text{LLM.plan}(s_0, s_g)$（无环境反馈）。

## 4. 实验：网格寻路上三种规划对比

### 4.1 实验设计

**任务**：8×8 网格寻路，(0,0) → (7,7)，随机障碍。
- **简单网格**：障碍率 15%
- **迷宫网格**：障碍率 35%（贪心几乎必卡死）
- 4 个动作（上下左右），100 个随机任务/批次

**三种规划**：
- **CoT**：每步贪心选曼哈顿距离最小的动作，10% 概率"思考错"（模拟 LLM 噪声），不回头
- **ToT**：每步生成 $k$ 个候选动作（按曼哈顿距离排序），DFS + 剪枝 + 回溯
- **ReWOO**：先用 BFS 找最短路径作为"LLM planner"的代理输出，15% 概率 plan 错

### 4.2 实测结果（100 任务/范式）

**简单网格（障碍率 15%）**：

| 范式 | 成功率 | 平均 LLM 调用 |
|------|:-----:|:----------:|
| **CoT（贪心线性）** | 45.0% | 24.5 |
| ToT k=2 | 95.0% | 47.7 |
| **ToT k=3** | **98.0%** | **37.5** |
| ToT k=5 | 98.0% | 37.3 |
| **ReWOO（plan-exe）** | 85.0% | **4.8** |

**迷宫网格（障碍率 35%）**：

| 范式 | 成功率 | 平均 LLM 调用 |
|------|:-----:|:----------:|
| **CoT（贪心线性）** | **24.0%** | 27.1 |
| ToT k=2 | 95.0% | 42.4 |
| **ToT k=3** | **100.0%** | 34.1 |
| ToT k=5 | 100.0% | 34.6 |
| **ReWOO（plan-exe）** | 80.0% | **4.7** |

### 4.3 数字解读

1. **CoT 在迷宫上崩盘**（24%）：贪心走进死胡同无法回头 → 必败。
2. **ToT k=3 几乎完美**（100%）：3 个候选 + 回溯，足以跳出局部最优。
3. **ReWOO token 最省**（4.7 vs CoT 的 27.1，少 5.7x）：因为只在 plan 阶段调 1 次 LLM，执行是机械的。
4. **ToT k=3 比 k=2 token 还少**（34.1 vs 42.4）！—— 这是因为 $k$ 大时剪枝更激进（找到解的概率大，搜索深度更浅）。**反直觉但合理**。

### 4.4 分支因子 $k$ 的三边权衡

迷宫任务下扫描 $k$：

| $k$ | 成功率 | 平均 LLM 调用 | 相比 $k=1$ 的 token 膨胀 |
|:--:|:-----:|:-----------:|:---------------------:|
| 1 | 18.0% | 14.7 | 1.0x |
| 2 | 96.0% | 44.3 | 3.0x |
| **3** | **100%** | **34.1** | **2.3x** |
| 5 | 100% | 34.6 | 2.4x |
| 10 | 100% | 34.6 | 2.4x |

**关键洞见**：
- $k$ 从 1 → 3，成功率从 18% → 100%，但 token 只膨胀 2.3x。**性价比之王**。
- $k$ 从 3 → 10，成功率不变（都 100%），token 也几乎不变（剪枝好）。
- **工程经验**：$k=3-5$ 是 ToT 的甜蜜区，再大没有边际收益。

---

## 5. 反直觉点

### 5.1 "CoT 在简单任务上 token 比 ReWOO 还高"

CoT 每步都让 LLM 想（24.5 次 LLM 调用），而 ReWOO 只在 plan 阶段调 1 次 LLM（共 4.8 次含执行）。**长任务 + 流程固定 → ReWOO 反而更省**。这就是为什么 OpenAI Assistants、AWS Step Functions 这种"工作流引擎"本质都是 ReWOO 思路。

### 5.2 "ToT 的 token 不是 $k^d$"

最坏情况是 $O(k^d)$（指数爆炸），但配上剪枝（visited set + 启发式排序）后通常退化为 $O(k \cdot d)$。所以 $k=5$ 的 token 通常只是 $k=1$ 的 3-5x，不是 25x。**"树搜索很贵"是误区**，剪枝得好其实可控。

### 5.3 "ReWOO 的失败模式是 plan 漂移"

ReWOO 假设环境静态，但真实环境会变（API 改了、数据变了）。Plan 出来时正确，执行时可能已失效，但 Agent 还在傻跑。**真实工程要加 plan 校验 + 中途 re-plan 机制**（这叫 MPC，Model Predictive Control）。

---

## 6. 横评表：何时用哪个

| 维度 | CoT | ToT | ReWOO |
|------|:---:|:---:|:-----:|
| **思考拓扑** | 一维 | 树状 | DAG（一次定全局）|
| **是否回溯** | ❌ | ✅ | ❌ |
| **LLM 调用次数** | 多（每步 1 次）| 多（每节点 1 次）| **少**（1-2 次）|
| **抗环境变化** | 中（可中途调整）| 高（可回溯）| **低**（plan 漂移）|
| **任务难度上限** | 低 | **高** | 中 |
| **典型任务** | 多跳问答、简单计算 | 数学题、代码、24 点、数独 | API 编排、ETL、批处理 |
| **代表论文** | CoT (2022) | ToT (2023) | ReWOO (2023) |
| **迷宫实测** | 24% | **100%** | 80% |

**实战组合拳**：
```
默认 CoT  →  失败升级到 ToT  →  高频任务用 ReWOO 缓存 plan
```

例：客服 Agent → 默认 CoT 答简单问题；遇到投诉升级用 ToT 分析根因；常见投诉场景预先用 ReWOO 缓存响应流程。

## 7. 进阶：搜索算法的工程化

### 7.1 MCTS（蒙特卡洛树搜索）

AlphaGo 同款算法。ToT 的进阶版：

```
Selection: 用 UCB 公式选最有潜力的节点
Expansion: 在选中节点扩展新候选
Simulation: 从新节点随机走到底估价值
Backprop:  把价值回传到所有祖先
```

适用于：决策空间巨大、价值难直接评估的任务（如下棋、长程规划）。代表项目：**LATS**（Language Agent Tree Search, Zhou et al. 2023）。

### 7.2 Self-Consistency（自洽性）

CoT 的低成本升级：跑 $N$ 次 CoT（不同温度采样），取**多数票**作为答案。

```python
answers = [llm_cot(query, temperature=0.7) for _ in range(N=5)]
final = mode(answers)   # 投票
```

GSM8K（小学数学）上提升 ~17 个百分点。**比 ToT 便宜得多**（不需要回溯），是性价比之王。

### 7.3 Adaptive Search（自适应搜索）

根据任务难度动态调整：
- 简单任务 → CoT
- 中等任务 → Self-Consistency
- 困难任务 → ToT
- 超难任务 → MCTS

实测可省 50%+ token，因为大部分任务不需要重武器。

## 8. 一句话总结

> **CoT 是线性贪心（不回头，简单任务够用但易卡死，迷宫实测 24%）；ToT 是树搜索（带回溯，复杂任务接近完美，迷宫实测 100%，$k=3$ 是甜蜜区）；ReWOO 是一次性 plan-then-execute（token 最省 4.7 vs CoT 27，但 plan 漂移风险高）。三者本质是「思考空间拓扑」的差异：一维 vs 树 vs DAG。没有银弹——简单任务用 CoT，高难度用 ToT ($k=3-5$)，高频结构化任务用 ReWOO。实战常组合：默认 CoT + 失败升级 ToT + 高频缓存 ReWOO。**
