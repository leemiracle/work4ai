# 12 · openhands/storage/ + 配置族 + alembic 迁移链：持久层、装配管线与代际钉子

## 1. 角色定位

这一篇覆盖三块拼图：`openhands/storage/` 是**无状态 KV 持久层**——一个 `FileStore` 鸭子类型接口被 local/S3/GCS/内存四种实现落地，会话元数据、事件、状态（pickle）、settings、secrets 全部以"文件"形态躺在它上面；配置族（`openhands/core/config/utils.py` 912 行装配巨石 + `openhands/server/config/server_config.py` V0 服务端配置）决定"用哪个实现、怎么拼装"；`openhands/app_server/app_lifespan/alembic/` 是 V1 应用服务器的六个数据库迁移——V0 用文件存一切，V1 引入 PostgreSQL，这条 001→006 迁移链正是代际替换的数据库侧注脚。三者合观，就是"OpenHands 把状态放在哪、怎么迁"的完整答案。

## 2. 内部结构

**FileStore 接口**（`openhands/storage/files.py:4`）只有 write/read/list/delete 四个 `@abstractmethod`（`:5-19`）——但**没有继承 ABC**，`@abstractmethod` 在非 ABC 类上不做运行时强制，纯鸭子约定（批 14 阶段钉版）。实现家族：`LocalFileStore`（`openhands/storage/local.py:8`）构造即 makedirs（`:11-15`）、`get_full_path` 剥前导斜杠保证相对 root（`:17-20`）、write 按 str/bytes 双模式（`:22-27`）、delete 走文件/目录二分（`:40-53`）；`InMemoryFileStore`（`openhands/storage/memory.py:7`）；`S3FileStore`（`openhands/storage/s3.py:22`，配三个 boto3 TypedDict 别名 `:10-20`）；`GoogleCloudFileStore`（`openhands/storage/google_cloud.py:12`）。

**webhook 装饰器全家桶**：`WebHookFileStore`（`openhands/storage/web_hook.py:9`）在 write/delete 后即时 POST；`BatchedWebHookFileStore`（`openhands/storage/batched_web_hook.py:17`）是批版——双阈值常量 `WEBHOOK_BATCH_TIMEOUT_SECONDS=5.0` 与 `WEBHOOK_BATCH_SIZE_LIMIT_BYTES=1048576`（`:13-14`，5 秒/1MB），**时间自最后一次插入重算**（`:167-177`：新事件 cancel 旧 Timer 重起，锁内 `_batch_size` 记账含"同 path 旧内容减重"`:146-157`），到限即刷（`:162-164`），发送丢给 EXECUTOR 后台线程（`:186-197`），tenacity 3 次×1 秒重试（`:216-219`），bytes 非 UTF-8 时 base64 兜底（`:244-253`），`flush()` 供关机前同步清账（`:263-268`）。工厂 `get_file_store`（`openhands/storage/__init__.py:15`）按类型字符串分发四种实现（`:23-32`），webhook URL 存在时再包一层，`SESSION_API_KEY` 环境变量自动转 `X-Session-API-Key` 头（`:37-40`），batch 开关选批版或即版（`:47-55`）。

**三商店**（全走"文件当数据库"模式）：`FileConversationStore`（`openhands/storage/conversation/file_conversation_store.py:29`）——`search`（`:67-96`）先把目录下**全部**会话 ID 列出（`:75-79`），逐个 `get_metadata` 加载（`:86-92`，失败仅 warning），`sort` 后内存切片（`:93-94`），`next_page_id` 是 `base64(offset)` 游标（`:95`，`openhands/utils/search_utils.py:4-11` 的 offset_to_page_id/page_id_to_offset）——**O(N) 全量加载分页**，会话多时是性能地雷；`get_metadata` 顺手弹出历史遗留 `github_user_id` 字段（`:46-48`）。`FileSettingsStore`（`openhands/storage/settings/file_settings_store.py:15`）路径写死 `settings.json`（`:17`），`load` 里**硬编码 `settings.v1_enabled = True`**（`:25-27`，注释明说"Turn on V1 in OpenHands / can simplify-remove this as part of V0 removal"——读路径强制开 V1 的代际迁移钉子）。`FileSecretsStore`（`openhands/storage/secrets/file_secrets_store.py:15`）路径 `secrets.json`（`:17`），load 时过滤空 token（`:23-28`），store 用 `model_dump_json(context={'expose_secrets': True})`（`:34-36`）**绕过 pydantic 掩码序列化真实令牌明文落盘**——安全性完全托付给底层 FileStore 的访问边界。

**配置巨石** `openhands/core/config/utils.py`（912 行、13 个模块级函数）：`load_from_env`（`:46`）→`load_from_toml`（`:144`）两级灌入 `OpenHandsConfig`；`get_or_create_jwt_secret`（`:376`）把 JWT 密钥当文件存进 FileStore；`finalize_config`（`:386-474`）做装配后手术——`sandbox.volumes` 挂载解析与 `/workspace` 特判（`:389-428`）、弃用 workspace 参数兼容（`:430-440`）、llm 日志目录绝对化（`:443-444`）、jwt_secret 兜底（`:456-461`）、**CLIRuntime 自动关掉所有 agent 的 jupyter+browsing**（`:463-474`）；组配置取数 `get_agent_config_arg`（`:477`）/`get_llm_config_arg`（`:530`）/`get_condenser_config_arg`（`:635`）；多模型路由 `get_llms_for_routing_config`（`:597`）/`get_model_routing_config_arg`（`:747`）；入口三连 `parse_arguments`（`:791`）→`register_custom_agents`（`:804`）→`load_openhands_config`（`:827`，`:839` 调 finalize）→`setup_config_from_args`（`:847`）。V0 服务端配置 `openhands/server/config/server_config.py:13` 的 `ServerConfig`：**PostHog 遥测 key 硬编码** `phc_3ESMmY9SgqEAGBB6sMGK5ayYHkeUuknH2vP6FmWH9RA`（`:18`）、四个 store 类的字符串装配（`:21-33`）、`enable_v1` 默认开（`:34`，仅 `ENABLE_V1=0` 关）、`load_server_config` 用 `get_impl` 动态实例化（`:36-69`）。

**迁移链** `openhands/app_server/app_lifespan/alembic/`（alembic.ini 的 `script_location` 在 `openhands/app_server/app_lifespan/alembic.ini:8`，DB URL 在 `openhands/app_server/app_lifespan/alembic.ini:87-89` 注释掉——运行时由 env.py 的 DbSessionInjector 动态注入）：`versions/001.py` 建五张表（app_conversation_start_task `:30`、event_callback `:67`、event_callback_result `:87`、v1_remote_sandbox `:127`、conversation_metadata `:158-185`——注意后者列混合了 V0 计费字段与 V1 兼容字段）；`002.py` docstring 抄坏了（`:3-5` 仍写"Revision ID: 001 / Revises:"），真实代码 `revision='002'`/`down_revision='001'`（`:16-17`），给 event_callback 加 status/updated_at（`:31-45`）；`003.py` 加 `parent_conversation_id`（`:23-26`）；`005.py` 链上 `Revises: 004`；`006.py` 给 v1_remote_sandbox 加 `session_api_key_hash` 索引（`:23-31`）。

## 3. 外部连接

FileStore 是被引用最广的接口之一：`openhands/controller/state/state.py:32` import、`openhands/controller/agent_controller.py:98`（构造参数 file_store）、`core/config/utils.py` 的 jwt secret、resolver 无关但 V0 全部会话产物（事件流 `EventStream`、state pickle `openhands/controller/state/state.py:129-141`、conversation stats）都经 locations.py 的路径函数（`openhands/storage/locations.py:4-37`，注意 `:25` 的 `get_conversation_init_data_filename` 对应 ConversationInitData 会话初始化数据文件）落进 FileStore。三商店由 `ServerConfig` 的类名字符串（`openhands/server/config/server_config.py:21-33`）经 `get_impl` 动态加载（批 14 阶段：配置驱动、无静态边）。config/utils.py 的消费方横跨两代：`core/main.py`、`openhands/resolver/issue_resolver.py:26`（load_openhands_config）、app_server 侧也复用部分装配；其大量函数体内延迟 import（controller.agent、condenser_config 等）是本仓规避循环依赖的惯例（批 12 阶段钉版）。alembic 只服务 `openhands/app_server/`（V1），迁移里 import 的模型来自 `openhands/app_server/app_conversation/app_conversation_models.py`（`openhands/app_server/app_lifespan/alembic/versions/001.py:14-19`）。

## 4. 数据流

一次配置到落盘的全程：进程启动 → `setup_config_from_args`（`openhands/core/config/utils.py:847`）→ `load_openhands_config`（`:827`）三源合并（默认→toml→env）→ `finalize_config`（`:839`）修 mounts/密钥/CLIRuntime 联动 → 会话创建 → `ServerConfig` 类名字符串 `get_impl` 出三个商店 → `FileSettingsStore.load` 读 settings.json 且强制 `v1_enabled=True`（`openhands/storage/settings/file_settings_store.py:27`）→ 运行中每个事件经 `locations.py` 路径写 FileStore → 若配了 webhook batch，写操作进 5s/1MB 双阈值批队列（`openhands/storage/batched_web_hook.py:127-177`）异步 POST → 会话结束 state pickle+base64 落 `agent_state` 文件（`openhands/controller/state/state.py:135-141`）。V1 线：app_server 启动时 alembic 沿 001→006 升库，conversation_metadata 等表接管元数据，沙箱注册记 v1_remote_sandbox。

## 5. 设计决策

Legacy-V0→V1 语境下四个决策：其一，**文件即数据库**（三商店+locations 路径函数）：V0 用最糙的 KV 抽象换取"local 目录可调试、S3 可上云"的零成本切换，代价是 `FileConversationStore.search` 的 O(N) 分页（`openhands/storage/conversation/file_conversation_store.py:86-94`）——V1 直接上 PostgreSQL+alembic 修正（conversation_metadata 表 `openhands/app_server/app_lifespan/alembic/versions/001.py:158-185` 保留同名列做平滑迁移）。其二，**v1_enabled=True 硬编码钉子**（`openhands/storage/settings/file_settings_store.py:27`）：与其做灰度开关不如读路径强制开，注释预告"V0 移除时一并删"——代际切换用一行代码而不是一套开关系统。其三，**webhook 双阈值批处理**（`openhands/storage/batched_web_hook.py:13-14`）：事件流写放大严重（每事件多文件），批+后台 EXECUTOR 把同步路径上的 HTTP 摘干净，"时间自最后一次插入重算"防止低频流量下的过早发送。其四，**FileStore 不继承 ABC**（`openhands/storage/files.py:4`）：牺牲运行时强制换取"任何鸭子都能当存储"的扩展自由——enterprise 层正是靠字符串类名+get_impl 塞进自己的实现。

## 6. 新人提示

- **安全发现一**：`secrets.json` 明文落盘（`openhands/storage/secrets/file_secrets_store.py:34-36` 的 expose_secrets 上下文绕过掩码），本地模式即本地文件权限问题，S3 模式即桶权限问题——泄密半径取决于 FileStore 边界。
- **安全发现二**：PostHog 遥测 key 硬编码在 `openhands/server/config/server_config.py:18`，属客户端 key 性质但会进一切日志与分发物；同文件 `:34` 的 `enable_v1` 只认 `ENABLE_V1=0`，其他任何值（包括 typo）都当开。
- **迁移链时间倒退证据**：`openhands/app_server/app_lifespan/alembic/versions/001.py:5` Create Date=2025-10-05（真实 autogen 带微秒），`openhands/app_server/app_lifespan/alembic/versions/003.py:5`=2025-11-06、`openhands/app_server/app_lifespan/alembic/versions/005.py:5`=2025-11-11 递增正常，但 `004.py` Create Date=**2025-01-27**、`openhands/app_server/app_lifespan/alembic/versions/006.py:5`=**2025-02-24**——都在链尾却比链头早大半年，是手写迁移文件时填错/复制了旧日期；`openhands/app_server/app_lifespan/alembic/versions/002.py:3-5` 的 docstring 更是整段抄 001 忘改（真实 revision 在 `:16-17`）。alembic 只看 revision/down_revision 链，这些日期错误无害，但按文件名+日期推断迁移史会被误导。
- **勘误**：本仓没有 `openhands/server/alembic/`——迁移链真实位置是 `openhands/app_server/app_lifespan/alembic/versions/`（alembic.ini 也在 app_lifespan 下）；config 巨石在 `openhands/core/config/utils.py`，`openhands/server/config/` 里只有一个 69 行的 server_config.py。
- `FileConversationStore.search` 的 `next_page_id` 是 base64(offset)（`openhands/utils/search_utils.py:4-9`）——不是数据库游标，翻页期间新会话插入会造成偏移/重复；`iterate`（`openhands/utils/search_utils.py:14-29`）是该协议的通用遍历器。
- `openhands/storage/batched_web_hook.py:163` 大小阈值用 `>=` 且在**加锁路径内**同步判刷，`_enqueue_batch_from_lock` 拆批次后发 EXECUTOR——慢 webhook 不会阻塞写线程，但 tenacity 只 3 次（`:216-219`），超限批次**静默丢弃**（`_send_batch` 的 except 只 logger.exception，`:213-214`）。
- `LocalFileStore.get_full_path` 剥前导 `/`（`openhands/storage/local.py:18-20`）意味着传入绝对路径会被"相对化"——想写根目录文件是不可能的，这是防路径逃逸的隐性设计（但不防 `..` 上跳）。
- `openhands/controller/state/state.py:132-133` save 时摘 `conversation_stats`、`:154` 恢复引用——pickle 里永远没有运行态统计对象，恢复会话的 stats 从零计。
