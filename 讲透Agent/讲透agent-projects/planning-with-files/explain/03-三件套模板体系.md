# 03 · 三件套模板体系：task_plan / findings / progress（方法的数据结构）

> 对应图谱 L4-L6 三层（task_plan/findings/progress 各三层变体），tour t05-t07。核心文件：`templates/task_plan.md`（133 行）、`templates/findings.md`（96 行）、`templates/progress.md`（115 行）、初始化器 `scripts/init-session.sh`。任务书建议的 planning/sticky-notes/state 三分在仓内的实名是 task_plan（规划）/findings（知识便签）/progress（状态时间线）。

## ① 角色定位

如果说 SKILL.md 是方法引擎，三件套就是方法的**数据结构**——所有规则最终都落在"往这三个文件的哪个节写什么"。三文件各答一问（skills/planning-with-files/SKILL.md:173-183 的 5-Question 映射）：task_plan 答"去哪/到哪了"（工作记忆），findings 答"学到了什么"（外部知识库），progress 答"做了什么"（会话时间线）。`templates/` 根级副本供 `CLAUDE_PLUGIN_ROOT` 引用（README.md:288），`scripts/init-session.sh` 提供免对话的命令行初始化。

## ② 内部结构

**task_plan.md** 八节：Goal 单句北极星（templates/task_plan.md:8-14）；Current Phase 快指针（templates/task_plan.md:16-21）；Phases 五阶段默认骨架（templates/task_plan.md:23-84）——需求发现→规划→实现→测试→交付，每阶段 checklist+`**Status:**` 三态（pending/in_progress/complete，templates/task_plan.md:39-44 注释定义）；Key Questions（templates/task_plan.md:86-95）；Decisions Made 决策表（templates/task_plan.md:97-107）；Errors Encountered 错误表含 Attempt 列（templates/task_plan.md:109-120）；Notes 尾部复诵（templates/task_plan.md:122-132）。

**findings.md** 六节：Requirements（templates/task_plan.md:8-21）；Research Findings（templates/task_plan.md:23-34）；Technical Decisions（templates/task_plan.md:36-48）；Issues Encountered（templates/task_plan.md:50-61）；Resources 链接仓（templates/task_plan.md:63-73）；**Visual/Browser Findings**（templates/task_plan.md:75-86，多模态内容的强制文本化落点）。

**progress.md** 五节：Session 日期头（templates/task_plan.md:8-13）；每 Phase 日志块——Status/Started/Actions taken/Files created-modified 四槽（templates/task_plan.md:15-56）；Test Results 五列表（Test/Input/Expected/Actual/Status，templates/task_plan.md:58-69）；Error Log 带 Timestamp 与 Attempt（templates/task_plan.md:71-83）；5-Question Reboot Check 自检表（templates/task_plan.md:85-105）。

三模板最大共性：**每个空节上方都有 HTML 注释块**，按 WHAT/WHY/WHEN(/EXAMPLE) 三到四元组教学（如 templates/task_plan.md:2-6、templates/findings.md:75-79）。模板不是死表单而是自带说明书的训练数据。

**init-session.sh**：幂等三连建——`if [ ! -f ]` 守卫下 heredoc 写 task_plan（scripts/init-session.sh:13-62）、findings（scripts/init-session.sh:65-89）、progress（scripts/init-session.sh:91-116）。

## ③ 外部连接

模板被三方消费：① SKILL.md Quick Start 引用为参考（skills/planning-with-files/SKILL.md:70-72）；② 钩子系统 grep 模板的**结构标记**——PreToolUse 注入 task_plan 前 30 行（skills/planning-with-files/SKILL.md:15），check-complete.sh 数 `### Phase` 标题与 `**Status:** complete` 行（scripts/check-complete.sh:14-19）判定完成度，status 命令读 "## Current Phase"（commands/status.md:9）；③ sync-ide-folders.py 把三模板摊到 13 个 IDE 目录（scripts/sync-ide-folders.py:32-36）。findings 的 Visual/Browser Findings 节是 SKILL.md 2-Action Rule（skills/planning-with-files/SKILL.md:100-103）与 reference.md Principle 3（skills/planning-with-files/reference.md:27-40）的交汇点。

## ④ 数据流

**写路径**：阶段完成→task_plan 状态翻转 in_progress→complete+checkbox `[ ]`→`[x]`（docs/workflow.md:137-148）；发现新知→findings 对应节；动手/测试/出错→progress 按时间戳追加。**读路径**：每次工具调用前 PreToolUse 重注入 task_plan 头 30 行（覆盖 Goal+Current Phase+Phase 1——templates/task_plan.md:1-44 恰好被截在 Phase 2 前，头部信息密度是刻意排布）；/clear 后会话恢复先读三件套全文；/plan:status 只读 task_plan 渲染。错误是双写流：task_plan 错误表（聚合视图，Attempt 序号）与 progress Error Log（时间线视图，Timestamp）各一份（docs/workflow.md:151-157）。

## ⑤ 设计决策与陷阱

- **结构标记=协议**：`### Phase`、`**Status:**`、`## Current Phase`、`[ ]`/`[x]` 不只是排版——check-complete.sh 与 status 命令靠 grep 它们工作，且有双格式回退（`**Status:**` 优先、`[complete]` 内联兜底，scripts/check-complete.sh:21-26）。**改模板字段名=破坏钩子协议**，两处必须同步改。
- **init-session.sh 的内嵌模板是简化版**：heredoc 里的 task_plan 缺 Key Questions 节、错误表缺 Attempt 列（scripts/init-session.sh:14-58 对照 templates/task_plan.md:86-120）——脚本建的文件与模板版不同构。且两个 task_plan heredoc 用单引号 `'EOF'` 原样输出（templates/task_plan.md:14），progress 用裸 `EOF` 展开 `$DATE`（templates/task_plan.md:93）——一文件两式，复制粘贴时易错。
- **前 30 行截断的边界效应**：PreToolUse 只注入头 30 行，若用户把 Goal 写成长段落，Phase 状态就被截掉——保持头部紧凑是隐性契约。
- **三态状态机与 checkbox 双轨并行**：同一阶段既有 `- [ ]` 又有 `**Status:**`，两处更新不同步时 check-complete 只认后者（scripts/check-complete.sh:17）——人读 checkbox、机读 Status 行。
- 模板注释里埋着量化依据："After 50+ tool calls, your original goals can get forgotten"（templates/task_plan.md:4），出处是 skills/planning-with-files/reference.md:46。

## ⑥ 新人提示

把三模板当 schema 背下来：写任何规划文件前先问"这行属于哪张表"。实践顺序：用 init-session.sh 建文件（快）但对照 templates/ 补齐缺失节（全）；填 Goal 时限一句（北极星检验）；每个错误立刻双写 task_plan+progress——错误表是整个方法里防重复失败（skills/planning-with-files/SKILL.md:125-130）的唯一持久层。自造模板变体时，至少保住四个 grep 锚：`### Phase` 标题、`**Status:**` 值、`## Current Phase`、`## Errors Encountered`，否则整套钩子静默失效。
