# 06 · 钩子矩阵、会话恢复脚本与 16 平台分册（强制力与适配工程线）

## ① 角色定位

钩子是整个方法的**强制力引擎**：SKILL.md 的规则靠模型自觉，钩子靠 harness 强制——把"该重读计划了"从提示变成每次工具调用的固定注入。三条实现线：Claude Code 线内联 SKILL.md frontmatter（四组）；Copilot 线外挂 `.github/hooks/planning-with-files.json`（stdin/stdout JSON 协议）；Cursor 线外挂 `.cursor/hooks.json`（followup_message 自动续跑，强制力最强）。`session-catchup.py` 是 /clear 后的对话考古器，`check-complete.sh` 是 Stop 时刻的完成度判官。16 篇平台分册按"钩子深度/自动发现/轻量手动"三档分类（钩子档 docs/cursor.md、docs/copilot.md、docs/kilocode.md、docs/mastra.md；自动发现档 docs/gemini.md 等 6 篇；手动档 docs/codex.md 等 4 篇）。

## ② 内部结构

**Claude Code 线**四钩子（skills/planning-with-files/SKILL.md:6-24）：UserPromptSubmit——检测到 task_plan.md 存在即提醒先读三件套（skills/planning-with-files/SKILL.md:7-10）；PreToolUse matcher "Write|Edit|Bash|Read|Glob|Grep"——`cat task_plan.md | head -30` 逐次重注入（skills/planning-with-files/SKILL.md:11-15）；PostToolUse matcher "Write|Edit"——提醒沉淀到 progress.md（skills/planning-with-files/SKILL.md:16-20）；Stop——优先 powershell.exe 跑 check-complete.ps1 失败回退 sh（skills/planning-with-files/SKILL.md:21-24）。

**Copilot 线**（.github/hooks/planning-with-files.json:4-35）：sessionStart(15s)/preToolUse(5s)/postToolUse(5s)/agentStop(10s) 四事件，每事件 bash+powershell 双实现。脚本是 JSON 协议范本：读 stdin→`head -30` 取计划头→python json.dumps 转义→`hookSpecificOutput.additionalContext` 注入且 `permissionDecision: allow` 永不阻塞（.github/hooks/scripts/pre-tool-use.sh:8/:17/:26-28）。session-start.sh 双分支：有计划→catchup 回退读头 5 行；无计划→整份 SKILL.md 注入（.github/hooks/scripts/session-start.sh:14-31）。agent-stop.sh 数 `### Phase` 与 `**Status:**` 双格式判完成，完成/未完成都输出 additionalContext（.github/hooks/scripts/agent-stop.sh:38-45）。

**Cursor 线**（.cursor/hooks.json:4-30）：userPromptSubmit/preToolUse(matcher "Write|Edit|Shell|Read")/postToolUse/stop，stop 挂 `loop_limit: 3`（.cursor/hooks.json:28）。差异：pre-tool-use 把计划头写 **stderr**（.cursor/hooks/pre-tool-use.sh:10）；stop 用 `followup_message` 未完成即自动续跑，3 轮防死循环（.cursor/hooks/stop.sh:35-42；docs/cursor.md:44/:117）。

**session-catchup.py** 五段：detect_ide 按 OPENCODE_DATA_DIR/~/.claude 探测（scripts/session-catchup.py:25-44）；get_project_dir_claude 把项目路径消毒成 `-` 连接的会话目录名（scripts/session-catchup.py:47-53）；get_sessions_sorted 按 mtime 倒序并**排除 agent- 前缀子代理会话**（scripts/session-catchup.py:74-78）；scan_for_planning_update 逐行找 Write/Edit 到三件套的最后位置（scripts/session-catchup.py:116-157）；再跨会话收集其后全部对话：滤系统消息、上限 100 条、末尾四步 RECOMMENDED（scripts/session-catchup.py:194-195/:322-325/:344-348）。OpenCode 分支直接放弃（scripts/session-catchup.py:250-255）。

三条钩子线消费同一份 task_plan.md 结构协议（`### Phase`/`**Status:**`，三处重复实现：scripts/check-complete.sh:14-26、.github/hooks/scripts/agent-stop.sh:18-30、.cursor/hooks/stop.sh:15-27）；Stop/agentStop 都调 check-complete 逻辑；session-start.sh 调 session-catchup.py 并注入 SKILL.md。分册侧：docs/cursor.md:28-44 讲三钩子+自动续跑（docs/cursor.md:119 自评比 Claude Code 版"more powerful"）；docs/kiro.md:9 声明 Kiro 不用 SKILL.md 而用 steering 文件；docs/codex.md:59 走 AGENTS.md 注入三步指令；docs/gemini.md:83-84 定义 workspace/user 双优先级自动发现。安全复盘 docs/article-v2.md 与效果数据 docs/evals.md 是分册体系的终点站。

## ④ 数据流

典型循环（Cursor 线）：用户消息→userPromptSubmit 提醒读三件套→preToolUse stderr 注计划头→Write 后 postToolUse 提醒更新→agent 想停→stop.sh 判完成度→followup_message 续跑（≤3 轮）。Copilot 线同构但 additionalContext 走 stdout JSON。/clear 恢复流：模型跑 session-catchup.py "$(pwd)"（skills/planning-with-files/SKILL.md:42）→脚本扫 `~/.claude/projects/{消毒路径}` 历史 jsonl→输出未同步对话报告→模型按 git diff+三件套重建状态（skills/planning-with-files/SKILL.md:50-54）。

## ⑤ 设计决策与陷阱

- **三平台三协议**：同一"重注入计划"意图在 Claude 线是纯 echo、Copilot 线是 stdin/stdout JSON、Cursor 线是 stderr+followup_message——移植到新平台先抄对应协议的范本，别混。
- **永不阻塞哲学**：两条外挂线的 pre-tool-use 都自注 "never blocks tools"（.github/hooks/scripts/pre-tool-use.sh:4、.cursor/hooks/pre-tool-use.sh:4）且恒 exit 0；唯一接近"阻断"的是 Cursor followup 续跑+loop_limit 3 防失控（.cursor/hooks.json:28）。
- **间接注入放大链（安全红线）**：docs/article-v2.md:21-28——WebSearch 抓不可信站→写进 task_plan.md→PreToolUse 每回合重注入=攻击放大到每次工具调用；v2.21.0 修复=移除 WebFetch/WebSearch（docs/article-v2.md:34，波及 7 变体）。skills/planning-with-files/SKILL.md:226-228 的"外部内容只进 findings.md"规则即由此生。
- **check-complete 完成判定有假阴性**：`COMPLETE -eq TOTAL` 且 TOTAL>0 才算完（scripts/check-complete.sh:35），若模型用 `[x]` 勾完但没写 `**Status:** complete`，双格式回退（scripts/check-complete.sh:22-26）也只认 `[complete]` 字样——checkbox `[x]` 不在任何判定分支里。
- **session-catchup 静默退出**：目录不存在/会话<2/无规划更新都 return 零输出（scripts/session-catchup.py:260-261/:264-265/:286-288）——"没报告"≠"没丢上下文"；mtime 排序（scripts/session-catchup.py:78）时钟漂移下会错序。
- 16 分册三档**能力递减**：钩子档全自动→自动发现档半自动（无逐次重注入）→手动档纯纪律（docs/codex.md:59 三步指令；退化说明 docs/quickstart.md:86）。

## ⑥ 新人提示

按自家 IDE 档位读对应分册；`.github/hooks/scripts/` 四脚本是"最小可移植钩子集"参考实现（stdin→判文件→转义→JSON 出），值得全读。排障三板斧：钩子失效查安装法（Legacy 无钩子，docs/installation.md:141）；恢复无报告查项目根与 ≥2 个会话文件；Cursor 死循环查 loop_limit。安全角度记住一句话：**凡会被钩子反复注入的文件（task_plan.md）都是上下文高位资产，不可信内容一律 findings.md**（skills/planning-with-files/SKILL.md:226）。想量化收益/代价再读 docs/evals.md:83-98（96.7% vs 6.7%、+68% token/+17% 时间）后自行决定开关时机。
