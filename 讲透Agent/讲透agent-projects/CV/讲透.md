## 一、仓定位：教学笔记仓，不是简历

GitHub slug AccumulateMore/CV 里的 "CV" 指 Computer Vision，不是简历（curriculum vitae）——但内容早已溢出 CV 边界：157 册 ipynb + 1 个 README，从 PyTorch 工具链一路铺到 Transformer、BERT、RAG 与大模型 API，是中文社区高 star 的深度学习学习地图（commit c1dbbe57）。

它是"视频课转写工程"而非软件项目：无 requirements.txt、无 CI、无 src 目录，所有代码活在 notebook cell 里；README 前 25 行是全仓唯一的结构元数据——四条教程线各自锚定一位 UP 主的视频课（README.md:5/9/13/17/21），其余约六成是招聘内推营销内容（图谱甄别结论）。目录即课程表：编号前缀=教程线，编号顺序=视频课顺序。

四条线册数恰好合计 157：土堆线 23 册（100-122）+ 李沐线 69 册（200-268）+ 吴恩达线 55 册（300-354）+ Agent 线 10 册（400-409），与图谱 157 个 file 节点一一对应，零杂项零孤儿。

## 二、四条教程线地图

**土堆线（100-122）**：B 站 PyTorch 入门课随堂笔记，全线开篇 100 是 23 个 markdown 单元+1 个验环境代码单元的开箱自检模板。教学法=工具箱逐件拆解：环境（100-102）→数据装载（103-107）→网络层（108-113）→小实战 Sequential（114）→损失/优化器（115-116）→模型改写存取（117-118）→训练验证闭环（119-121）→看开源项目（122）。每册自包含可独立运行，适合零基础快速上手 PyTorch API。

**李沐线（200-268）**：《动手学深度学习》（d2l）课程完整跟随。教学法=手写从零实现与框架版双轨对照：225 批归一化先手写 batch_norm（区分全连接/卷积输入两种分支）再对照 nn.BatchNorm2d；261 的解码器内部用 d2l 库版 AdditiveAttention 而非 260 手写版——"手写懂原理、库版做工程"双轨并存。数学密度全线最高：204 矩阵计算零 code cell、9 张公式图承载全部推导。覆盖线性回归到 BERT 微调的完整谱系，适合已入门者建立体系。

**吴恩达线（300-354）**：深度学习专项课程的"理论+测验+作业"三件套。理论册多为 0 code cell 的讲义截图形态（329 卷积基础 31 张 PNG、332 风格迁移 41 张）；作业册是 numpy/TF1.x 时代手写方法论（322 仍用 tf.placeholder/tf.Session）；测验册（306-309 等）是纯 Markdown 选择题。适合补理论地基与手推直觉。

**Agent 线（400-409）**：大飞主讲，四线中最新（2025 年内容）。RAG 五册（401-405）从朴素关键词检索演进到 LangChain 管道；406 手写 Transformer 语言模型；407-409 讲 DeepSeek API（安装/参数/多轮对话）。适合 RAG 与 LLM API 入门。

README.md:21 还留着 500-5XX 线的占位符（"预计明年上线"）——仓仍在生长。

## 三、知识拓扑亮点：五条演进链

图谱 412 条边中 158 条 file→file related 边把 157 册连成教学复用网络，五条演进链是"一个知识点如何长大"的活标本——这正是 100+ related 边的教学价值：

**Tudui 六代链（土堆线）**：土堆用同一个网络名 Tudui 当全线主人公——12 册共 35 次 `class Tudui`。演进轨迹：108 以 nn.Module 教学首次定义 → 110-116 各组件课各自重写（110/115/116 各 3 次，111/112/113 各 2 次）→ 114 一册四版对照（114:79/134/191/248，手搭版与 Sequential 版逐一演进）→ 119 完整训练闭环基线（119:98，后续两册均以此为底本）→ 120 GPU 训练（120:190 `DataLoader(batch_size=64)`）→ 121 验证套路 → 118 保存与读取。一个虚构网络名串起整条工具链教学。

**CNN 七代谱系（李沐线）**：220 LeNet→221 AlexNet→222 VGG→223 NiN→224 GoogLeNet→225 批量归一化→226 ResNet，七册接力讲完 CNN 进化史。220:209 定义的 train_ch6（43 行，内含 Animator 动画与计时）是共享训练器，221/222/223/224/226 五册逐字拷贝复用——全李沐线最关键的复用资产。

**NMT 六函数复抄链（李沐线）**：255 机器翻译数据集定义 read_data_nmt（255:46）/preprocess_nmt（255:80）/tokenize_nmt（255:127）/truncate_pad（255:1088）等六函数管线，257 seq2seq（:454）、261 注意力 seq2seq（:135）、263 Transformer（:576）三册完整逐字复抄而非 import——notebook 教学"自包含优先"惯例的典型样本，也是 related 边最密集的簇。

**作业四代（吴恩达线）**：课程 1 作业逐周进阶——310 numpy 构建基本函数→311 Logistic 回归→312 单隐层分类→313 逐步构建深度网络（452 行，课程 1 最大作业；predict 在 cell 92/112 双定义，分别服务两层模型与 L 层模型）。

## 四、已知坑与勘误精选

1. **407 册硬编码 API key 泄漏（安全红线级）**：407:45 注释中残留真实 DeepSeek key（sk-9340...3c2，已截断）——虽已注释掉，但进了公开仓的 git 历史，等于永久泄漏。同册 407:41 的 `os.environ['DEEPSEEK_API_KEY']` 才是正解。另一处不一致：407:49 用 deepseek-reasoner，而 404/408/409 均用 deepseek-chat，线内模型选择不统一。
2. **406 册双 bug**：类名 SimleTransformerLM 系 Simple 拼写错误（406:149 定义、:343 实例化，两处一致沿用照跑不误）；SimpleDecoderLayer 注释自证"本例未使用"（406:113）——死代码，且其 forward 第二次残差连接误加 tgt 而非 ffn_output（406:143 `tgt = tgt + self.dropout(tgt)`），一旦学生当真照抄即错。该册 Decoder-only 用 nn.TransformerDecoder+memory=zeros_like 取巧实现（406:158/185），而非 nn.TransformerEncoder 因果掩码正路。
3. **349 册形参笔误**：`def sample(parameters, char_to_is, seed)`（349:370）形参名 char_to_is 系 char_to_ix 笔误，函数体实际引用全局 char_to_ix——传参名对不上靠全局变量兜底。同册还有三引号包裹的 pseudoCell（标注"示例，请勿执行"）。
4. **拼写错误跨册传染**：402:7 首标题 "# mebdding.py"（embedding 笔误）；403 的 collection 拼成 collecton（403:131/161/170/186 共 4 处），随 file_db.py 复抄传染到 404（:50/:163）——"自包含惯例"连错误一起复制的实证。
5. **408 册 system 文案笔误**："所有的回答不到得少于100个字"（408:100），同册前一 cell 为"不得少于"，两版并存。
6. **403 册路径不可移植**：模型路径 r'model_dir\BAAI\bge-large-zh-v1___5'（403:29 输出佐证）——Windows 反斜杠原始字符串+ModelScope 点号转下划线三连（___），Linux 直接跑不通。
7. **体积指标陷阱（读仓方法论）**：246 序列模型 JSON 11090 行为全仓最大，真实代码仅 110 行——膨胀全来自 9 个 markdown attachments 的 base64 PNG；207/210/213 的函数行号同样被输出污染拉长（图谱批阶段已逐册人工校正）。评估任何"行数/体量"都必须按真实代码行解读。
