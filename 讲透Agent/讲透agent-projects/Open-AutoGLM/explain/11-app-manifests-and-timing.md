# 11 · 应用清单与时序资产：config/apps×3 与 timing.py

## ① 角色定位

「打开微信」这句自然语言要落到设备真实包名，靠的是三份平台清单：`phone_agent/config/apps.py`（Android，`APP_PACKAGES` 168 条）、`apps_harmonyos.py`（鸿蒙，`APP_PACKAGES` 115 条 + `APP_ABILITIES` 39 条）、`apps_ios.py`（iOS，`APP_PACKAGES_IOS` 182 条 Bundle ID）。`timing.py` 则把全项目"动作后睡多久"的时序收进 `TIMING_CONFIG` 单例（:116），14 个延迟项全部可用环境变量覆盖。这四个文件是产品化落地时改动频率最高的"数据资产"——加一个 App 支持或调一拍时序，动的是它们而非逻辑代码。

## ② 内部结构

**apps.py**：单字典按用途分组注释（Social & Messaging/E-commerce…，:5 起），尾部三函数 `get_package_name`（:191）/`get_app_name`（:204）/`list_supported_apps`（:220）提供正反查。多别名是其特色：`com.android.settings` 挂 5 个键（`AndroidSystemSettings`/`Android System Settings`/含双空格与连字符变体/`Settings`），`com.booking` 也挂 5 键（大小写与域名变体）——同一包名的一键多值，专为对齐模型输出与系统 dumpsys 的不同写法。**apps_harmonyos.py**：双字典结构——`APP_ABILITIES`（:10-39）按 bundle→ability 映射，覆盖第三方（如 `com.taobao.taobao4hmos`→`Taobao_mainAbility`）与华为系应用（`com.huawei.hmos.settings`→全限定 ability），头部注释自曝生成方式 `Generated by: python test/find_abilities.py`（该脚本未随仓发布）；`APP_PACKAGES` 中文键为主（115 条）；尾部同款三函数（:230/:243/:259）。**apps_ios.py**：`APP_PACKAGES_IOS`（:7）按公司生态分组（腾讯系/阿里系/字节系/美团系…），键是中文名、值是 iOS Bundle ID（如 `微信`→`com.tencent.xin`）；除正反查外还有三个在线函数——`check_app_installed`（:243，**勘误：走 iTunes API 而非 WDA**，见 `apps_ios.py:267` 的 `itunes.apple.com/lookup?bundleId=`，签名里的 `wda_url` 形参是死参数；docstring :254-257 自认要查本地须改用 WDA）、`get_app_info_from_itunes`（:282）与 `get_app_info_by_id`（:312），调 `https://itunes.apple.com/lookup` 公共 API。**timing.py**：三个 dataclass——`ActionTimingConfig`（:11-34，键盘切换/清空/输入/恢复 4 项）、`DeviceTimingConfig`（:37-76，tap/double_tap/long_press/swipe/back/home/launch 8 项）、`ConnectionTimingConfig`（:79-96，adb_restart 2.0s/server_restart 1.0s）——各自 `__post_init__` 读 `PHONE_AGENT_*` 环境变量覆盖默认值；`TimingConfig` 聚合三者（:100-111），`update_timing_config`（:129-156）支持运行时整体替换。

## ③ 外部连接

消费方按平台各取一份：adb/device.py 与 phone_agent/hdc/device.py:8 分别导入自家清单做 `launch_app` 反查与前台应用名反查（phone_agent/hdc/device.py:70-75）；phone_agent/xctest/device.py:7 导入 `APP_PACKAGES_IOS as APP_PACKAGES`。timing.py 的消费面最广——hdc/device.py 的每个手势末尾 `TIMING_CONFIG.device.default_*_delay`（如 :93,:118,:148,:183）、phone_agent/hdc/connection.py:286/:346 的连接延迟、adb 栈与 handler 层同理。`main.py`/`ios.py` 的 `--list-apps` 是清单的展示出口（main.py:707-728）；`list_supported_apps` 三平台同名异实现（main.py:28-30 三行别名导入）。

## ④ 数据流

启动流：模型输出 `do(action="Launch", app="抖音")`→handler 查平台清单 `get_package_name("抖音")`→Android 得 `com.ss.android.ugc.aweme`（apps.py:35）直接 `am start`；鸿蒙得 `com.ss.hm.ugc.aweme`（apps_harmonyos.py:91）后还需二次查 `APP_ABILITIES`，缺省回落 `EntryAbility`（phone_agent/hdc/device.py:282）→`aa start -b -a`；iOS 得 Bundle ID `com.ss.iphone.ugc.Aweme`（apps_ios.py:50）→WDA `wda/apps/launch`。感知流反向：设备栈拿到前台包名后用 `get_app_name` 反查中文名喂给模型（"current_app"状态行）。时序流：设备操作函数末尾统一 `time.sleep(TIMING_CONFIG.device.default_tap_delay)` 之类——读屏稳定性全靠这些拍子，例如 ADB 键盘切回场景的 `keyboard_restore_delay`（timing.py:19,32-34）。

## ⑤ 设计决策与陷阱

1. **清单是硬能力边界**：不在清单里的应用 `Launch` 直接失败（phone_agent/hdc/device.py:272-275 会打印前 10 个可用名）；模型嘴上说能打开，设备层说不行——扩展新 App 是运营活。
2. **一键多值 vs 一值多键的语义差**：Android 清单"多别名指向同包"是为容错；但 `淘宝` 与 `淘宝闪购` 同包（apps.py 中 `com.taobao.taobao` 双键）、`京东`/`京东秒送` 同包——这些是**有意的产品别名**，反查 `get_app_name` 只返回首个命中键，顺序敏感。
3. **鸿蒙 ability 不能瞎默认**：`EntryAbility` 只覆盖未登记的应用；登记错误的 ability 会导致启动静默失败，`APP_ABILITIES` 的 39 条是实测积累。
4. **iOS 在线函数是隐藏外联**：`get_app_info_from_itunes`（apps_ios.py:282-310）会让离线环境抛超时（异常被吞返回 None）；`check_app_installed`（:243）查的是 iTunes API `lookup?bundleId=`（:267）——语义是"App Store 是否存在此 App"而非"设备本地是否安装"，签名里的 `wda_url` 形参根本未使用。
5. **时序字段名的 adb 残留**：`ConnectionTimingConfig.adb_restart_delay`（timing.py:84）被 hdc 栈共用（phone_agent/hdc/connection.py:286）——调鸿蒙时序别只看名字找变量。
6. **环境变量覆盖在实例化时一次性生效**：`TIMING_CONFIG` 是 import 时创建的模块级单例（:116），之后改 env 不生效，要么重启进程要么调 `update_timing_config`。
7. **pre-commit 的 exclude 陷阱**：`.pre-commit-config.yaml:4-5` 连写两个 `exclude:` 键——YAML 后键覆盖前键，注释意图排除的 `apps.py` 实际**没被排除**（真正生效的是 `README_en.md`），ruff-format 可能重排清单字典。

## ⑥ 新人提示

加 App 支持的完整三步：平台清单加一行→（鸿蒙）确认 ability 名→跑 `python main.py --list-apps` 验证。调时序先试环境变量（`PHONE_AGENT_TAP_DELAY=2 python main.py …`），14 个变量名在 timing.py 三个 `__post_init__` 里对号；真机慢（老设备/冷启动）就把 launch 类延迟调到 2-3s。读清单时注意中文键的大小写别名是刻意为之，不要"清理重复"。iOS 联网函数仅在需要核对 Bundle ID 真伪时用。
