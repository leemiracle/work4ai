# ⚠️ 第 4 幕 · 不足：缓存的失败模式

## 1. Stale Cache（过期）
世界变了，cache 还在返回旧答案。
**例**：知识库更新了，但 cache 命中返回旧知识。
**缓解**：TTL（Anthropic 5 分钟）、版本号、主动失效。

## 2. 前缀失效（Prefix Invalidation）
prompt caching 要求前缀严格相同。**改一个字，整块 cache 失效**。
**例**：system prompt 加了一行，所有历史 cache 作废。
**根因**：因果注意力——前缀变，后续 K/V 全变。
**缓解**：把易变部分放后面、固定部分放前面、分段缓存。

## 3. 语义相似 ≠ 语义相同
语义缓存的陷阱：「退款金额」和「退款流程」embedding 接近，但答案完全不同。
**根因**：cosine 只看方向，不区分关键语义差异。
**缓解**：高阈值（0.95+）、rerank 二次确认、关键实体匹配。

## 4. 隐私泄漏
语义缓存跨用户共享时，A 的查询命中 B 的缓存答案。
**缓解**：严格 tenant 隔离、缓存键含 user_id。

## 5. 显存碎片化
KV cache 碎片化导致显存利用率低。
**缓解**：PagedAttention（分页管理）。

## 6. 命中率波动
工作负载变化时命中率忽高忽低，成本不可预测。
**缓解**：监控命中率、容量规划。

## 7. 一致性 vs 性能
多副本部署时，cache 一致性难保证。
**缓解**：分布式 cache（Redis）、最终一致性 + TTL。

## 8. 「假命中」
cosine 阈值太低，返回不相关结果，用户被误导。
**比 miss 更危险**——miss 触发重新计算，假命中直接返回错的。
**缓解**：宁可 miss 不要假命中（阈值偏高）、日志记录命中供审计。

## 9. Anthropic 5 分钟 TTL 的现实
5 分钟对客服场景够（会话内），对长期知识不够。
**判据**：高频重复 prefix → 用 prompt cache；长期知识 → 用记忆层（`讲透记忆/`）。

---

## 🎬 收束

> 缓存 = 用空间换时间换正确性。**确定性 prefix（prompt caching）安全，语义相似（语义缓存）危险**。最危险的是假命中——比 miss 更隐蔽。**生产铁律：宁可 miss 不要假命中，阈值偏高，日志可审计**。记忆层（`讲透记忆/`）才是长期知识的归宿。
