## §0 全局视角：Agent = "LLM + 循环 + 工具 + 记忆"

```
Agent = LLM（决策核心）
      + 循环（多步推理）
      + 工具（行动能力）
      + 记忆（跨步保持状态）
```

> 🔑 **核心 DNA**：Agent 把 LLM 从"单次问答"升级为"持续决策"——本质是**给 LLM 加上时间维度**。

## §1 十条算法经验

### 算法经验 AG1：思考时机的三种范式（深化 G7）

> **ReAct**：边走边想（每步决策）
> **Plan-Execute**：想完再走（前置规划）
> **Reflexion**：走错了再想（失败反思）
>
> 这是 G7（规划-执行-反思）的三种具体实现——**思考位置不同 = 范式不同**。

可迁移（应用 DC4 对话策略、D1 transition = MDP）：
- **实时系统**：ReAct（无前瞻）
- **离线规划**：Plan-Execute（如物流调度）
- **学习型系统**：Reflexion（如 AlphaGo 的自我对弈）

### 算法经验 AG2：工具调用 = 函数调用 = action space

> Agent 调用工具本质是 **RL 的 action**：状态 → 选动作 → 观察结果 → 新状态。
>
> 这与 D1（transition-based parser = MDP）、Ch9 #9（RL 4 角色）完全同构。

可迁移：所有"决策 + 反馈"的系统都是 agent（机器人、自动驾驶、对话系统）。

### 算法经验 AG3：记忆的四个层级

> Agent 记忆体系：
> 1. **Working memory**（上下文窗口）—— 当前任务相关
> 2. **Episodic memory**（事件历史）—— 过去经验
> 3. **Semantic memory**（知识库 / RAG）—— 知识事实
> 4. **Procedural memory**（系统 prompt / 训练权重）—— 技能

这四种记忆对应不同存储位置（应用 R1 参数化 vs 非参数化）：
| 记忆类型 | 存哪 | 更新成本 |
|---------|------|---------|
| Working | 上下文 | 0（每步重置）|
| Episodic | 向量库 | 低 |
| Semantic | 文档库 / 知识图谱 | 中 |
| Procedural | 模型权重 | 极高（需重训）|

### 算法经验 AG4：规划 = 把搜索空间树化（深化 Ch9 §4.5 ToT）

> 规划本质是**显式展开状态空间树**：
> - ReAct：贪心（每步选最优）
> - Plan-Execute：一次规划（深度优先）
> - Tree of Thoughts：宽度优先 + 评估剪枝
> - MCTS：蒙特卡洛树搜索（AlphaGo 用）
>
> 算法本质：**搜索算法在 LLM 上的应用**（应用 C1 CKY 区间 DP、AS2 CTC 边缘化）。

### 算法经验 AG5：反思 = 自我评估 + 经验写入

> Reflexion 的核心：**失败 → 写反思笔记 → 下次避开**。
>
> 算法本质：**经验回放 + 离线学习**——RL 经验回放的 LLM 版本。

可迁移：所有"可重试"的系统都该加反思（对应 G5 自反思、G6 评估-纠错）。

### 算法经验 AG6：MCP（Model Context Protocol）= 工具标准化

> MCP 让工具调用像 USB 一样即插即用——这是 Agent 生态的"协议层"。
>
> 算法本质：**接口标准化降低集成成本**（与 HTTP、SQL、BPE 同构）。

### 算法经验 AG7：多 Agent 协作 = 分布式系统

> 多 Agent 系统的本质是**分布式系统**：
> - **Coordinator-Worker**（主从）：分工
> - **Debate**（辩论）：多视角
> - **Hierarchical**（层级）：抽象
> - **Competitive**（竞争）：博弈
>
> 算法本质：**Actor 模型 + 消息传递**（应用 G7、Q1 全局归一化）。

### 算法经验 AG8：Agent 的失败模式

> Agent 失败的 5 大模式：
> 1. **死循环**：卡在同一动作
> 2. **幻觉工具调用**：编造工具名/参数
> 3. **过早收敛**：第一个看似合理的方案就停止
> 4. **工具依赖**：能用 LLM 知识的非调工具
> 5. **token 爆炸**：历史太长
>
> 解法：**约束 + 评估 + 早停 + 压缩**（应用 G6 评估-纠错、R10 chunking）。

### 算法经验 AG9：Agent 评估 = 端到端 + 过程

> Agent 评估既要看**最终任务完成**（end-to-end），也要看**过程质量**（步数、token、是否最优）。
>
> 这是与单次 LLM 评估的根本差异——Agent 是**多步决策**，过程指标同等重要（应用 F5 任务难度档）。

### 算法经验 AG10：Agent 边界 = "何时不用 Agent"

> 不是所有任务都需要 Agent。判断：
> - **单步任务** → 普通 LLM 调用
> - **多步但模板化** → 流水线（非 agent）
> - **多步且需灵活** → ReAct
> - **复杂规划** → Plan-Execute
> - **学习型任务** → Reflexion
>
> **经验**（应用 M6 成本权衡、N7 好思想新形态回来）：**过度 agentic 是工程大坑——能用简单方法就别用 agent**。

## ✍️ 练习

**A**（AG1 三范式）：同一个任务（如"找某论文并总结"）用 ReAct / Plan-Execute / Reflexion 各跑一遍，比较步数/token/成功率。

**B**（AG3 记忆层级）：给一个 Agent 加 episodic memory（向量库存过去经验），观察它是否能在相似任务上少走弯路。

**C**（AG8 失败模式）：分析 Claude/GPT 的 agent 模式常见失败——找出 AG8 里哪几类。

**D**（Deep Thinking）：当 LLM 上下文涨到 1B token，Agent 还需要"记忆机制"吗？（提示：成本 + 检索效率 + 可更新性。）
