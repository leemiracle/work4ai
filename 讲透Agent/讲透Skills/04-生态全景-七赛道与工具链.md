## 3. 用户指定六仓精确定位（全部一手核实）

### 3.1 addyosmani/agent-skills（89,574★）——六阶段生命周期方法论的标杆

```
DEFINE   PLAN    BUILD   VERIFY  REVIEW  SHIP
Idea→    Spec→   Code→   Test→   QA→     Go→Live
/spec    /plan   /build  /test   /review /ship
```

24 个 skill + 8 个 slash command 的**双形态交付**：slash command 显式入口（用户敲 `/spec`），skills 自动激活（设计 API 自动触发 api-and-interface-design）。`/build auto` 一步生成计划+逐任务自主实现（每任务仍测试驱动+独立提交，失败即停）——"移除的是人在任务之间的机械干预，不是验证"。安装：`npx skills add addyosmani/agent-skills`（vercel CLI，70+ agent 通用）。

### 3.2 Fission-AI/OpenSpec（66,157★）——spec 驱动开发（SDD）的 skills 化

哲学五条：fluid not rigid / iterative not waterfall / easy not complex / **built for brownfield not just greenfield**（存量项目友好——与多数 SDD 工具只管绿地项目相反）。新工作流 `/opsx:propose` → 归档，artifact 引导。npm 包 `@fission-ai/openspec`，CI 集成。定位：**"spec 即 skills"路线**——规格说明不再是被动的文档，而是 agent 可执行加载的活指令。

### 3.3 obra/superpowers（277,259★）——完整软件开发方法论

安装矩阵覆盖 **16 个工具**（Claude Code/Codex/Cursor/OpenCode/Gemini CLI/Devin/Factory Droid/Kimi Code...）。核心循环：先逼出 spec（分块给人看）→ 签核后出"初级工程师也能执行"的计划（真红绿 TDD + YAGNI + DRY）→ `subagent-driven-development` 逐任务推进，可自主数小时不偏航。定位：**skills 的"操作系统"级用法**——不是一堆技巧，是自洽方法论 + 让 agent 一定会用它的初始指令。

### 3.4 muratcankoylan/agent-skills-for-context-engineering（17,817★）——教学型技能库

context engineering 课程的 skills 化：context-fundamentals / context-degradation（lost-in-middle/poisoning/distraction/clash）/ context-compression / multi-agent-patterns / long-horizon-prompting。**学术地位**：被北大 MCE 论文（arXiv:2601.21557）和 Agent Harness Engineering Survey（CMU 等 8 校）引用为 static skill architecture 代表作。定位：**用 skill 教 skill 的元循环样本**。

### 3.5 kepano/obsidian-skills（47,219★）——垂直领域标准范本

Obsidian CEO（kepano）官方出品：obsidian-markdown / obsidian-bases / json-canvas / obsidian-cli 四技能，严格遵循 agentskills.io 规范。README 明确给出三工具安装路径（marketplace / npx skills / 手动 clone），是"**一个标准 skill 走天下**"的最干净示范。定位：垂直软件厂商把自家产品文档 skills 化的模板。

### 3.6 anthropics/skills（171,450★）——生态源仓

19 个官方 skills（四大类：Creative & Design / Development & Technical / Enterprise & Communication / Document Skills）+ spec/ + template/。document skills（docx/pdf/pptx/xlsx）是 Claude.ai 文档能力的生产引擎（source-available）。`skill-creator` 是官方元技能（[07 章详解](07-自动优化-从skill-creator到MCE.md)）。API 侧 `/v1/skills`。

## 4. 分发工具链（安装路径矩阵）

| 工具 | 用法 | 覆盖 |
|---|---|---|
| **vercel-labs/skills CLI** | `npx skills add owner/repo [--list]` | **70+ agent**（事实标准的安装器） |
| Claude Code plugin marketplace | `/plugin marketplace add owner/repo` → `/plugin install name@market` | Claude 系 |
| opencode | clone 到 `~/.opencode/skills/`（自动发现所有 SKILL.md） | opencode |
| Codex | 复制到 `~/.codex/skills/` | Codex 系 |
| skills.sh | badge + 索引站 | 发现层 |
| 手动 | 任何 agent：找到其 skills 目录放进去 | 全部 |

跨工具注意：目录布局有微差（obsidian README 明确警告 opencode 要 clone **整个仓**而非只拷内层 skills/，因为 opencode 扫描 `~/.opencode/skills/**/SKILL.md`）。

## 5. 生态治理三个坑（装第三方 skill 前）

1. **scripts/ 就是代码**——`npx skills add` 装进来的 skill 可能含任意可执行脚本。规范无签名机制，marketplace 审核各异。装前读 scripts/，同 npm 包审 postinstall。
2. **AI 批量生成 slop**——生态全景实测 top500 中 79% 创建于 2025-10 后，低质仓库是统计大多数。看 star 活跃度 + 作者，别只看名字。
3. **语义漂移**——同一 SKILL.md 在 16+ 工具上行为不完全一致（superpowers 安装矩阵要按工具分支不是没原因的）。关键 skill 在目标工具实测。
