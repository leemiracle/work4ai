# 12 · 不足与批判收尾：窗口中心主义的黄昏

> 讲透Context 第 12 章（五幕第四幕：不足）| 汇总 E1-E8 的负面结果与领域级批判

## 1. 实验负面结果总账（诚实优先）

- **E2 零结果**：位置效应（U 型曲线）在本地双模型上**全格无信号**——NIAH 词面任务太容易。教训双层：①流行的位置效应证据比想象中脆（任务难度依赖）；②**零结果必须报**（否则领域只剩幸存者偏差）；
- **E3 rot 严格模型依赖**：glm 六格全对、Qwen 崩一半——"长上下文能力"的很多结论换个模型就翻转，**单模型 benchmark 的外部效度可疑**；
- **E5 压缩器三宗罪**：细节丢 37.5%；幻觉人名（张伟）；Qwen 假摘要（抄用户原话充数）——**compaction 不是无损的，连"有损但可控"都要挑模型**；
- **E6 LLM 摘要输给 1997 年的数据结构**：Bloom 97.9% vs glm 超预算 92%——set membership 这种"结构可判"的任务，**别用生成式压缩**（Thm 3 的 $\Theta(\log n)$ 税白交）；
- **E7 结构化模板的翻车**：模板即过滤器——丢字段诱发幻觉改值（5%→10%）——**"更结构化"不总是更保真**；
- **E8 蒸馏悬崖 + brevity bias 复发**：朴素 5× 蒸馏只剩 17% 事实；LLM 压缩器给了下限仍超压一半——**蒸馏率是安全关键参数，且指令管不住**。

## 2. 领域级批判四条

**批判一：度量危机**。context engineering 的核心主张（"最小高信号集"）至今没有公认度量——signal 怎么测？检索指标（recall@k）会撒谎（GEM 2026 的 retrieval-generation gap），端到端任务又太贵太噪。E2 的零结果就是这个危机的微观写照：我们连"位置效应存不存在"都要看任务脸色。**在度量危机解决前，这个领域的"最佳实践"本质上是风格指南**。

**批判二：理论工具的错配风险**。2608.01326 的通信复杂度框架优美，但它的源模型是"事实袋"（set membership）——真实会话历史是**强结构、强时序、强指涉**的（"他说的那个方案"依赖 3 轮前的先行词）。结构性信息的压缩下界还没有对应定理——**别急着把 log n 税外推到一切 compaction**。

**批判三：供应商叙事的污染**。"context engineering"一词的爆红路径（Karpathy 推文 → 框架博客 → 咨询报告）天然偏向**听起来可采购的答案**（买我的记忆层/压缩器/图数据库）。本单元的实验反复显示：最重要的收益来自**便宜得无聊的动作**（日期注入 30 tok、渐进披露、自由笔记）——**越性感的解决方案越该先跑消融**。

**批判四：窗口中心主义本身在过时**。六线综述（Ch10）的合流方向是：状态外移（环境/图/记忆层）+ 理论化。窗口正在缩编为"寄存器"。**一门以"管理窗口"命名的学科，其长期命运可能是把自己管没了**——这是它最好的结局（就像"内存管理"最终变成了操作系统的一部分）。

## 3. 什么留下来了（沉淀清单）

穿过批判还站得住的六条（全部有本单元实验背书）：

1. **记账先行**（E1）：不审计就谈不上工程；
2. **组件互补，缺谁塌哪**（E4）：schema/时间锚/示例不可互换；
3. **压缩有税，结构可免**（E6/E8）：Bloom 与抽取式告诉我们——**能结构化判定的就别生成式压缩**；
4. **外移优于硬塞**（E7/E8 + 本会话现场）：状态进文件/图/环境；
5. **弃权优于幻觉**（E7）：丢信息时让模型说"我不知道"；
6. **一切组件的价值是模型的函数**（E3/E4 跨模型翻转）：没有模型无关的最佳实践，只有消融方法论是可迁移的。

## 4. 姊妹篇终局坐标

```
讲透Prompt  ：一句话怎么问          （单次调用内）
讲透Context ：窗口里放什么          （单 agent 内）← 本单元
讲透Harness ：模型周围挂什么        （单 agent 外）
讲透Loop    ：跨调用怎么循环        （时间维）
讲透Graph   ：多 agent/知识怎么组织 （系统维）
```

五环各管一层，context 是中间层——**它往上被 Graph 接管（状态外移到图），往下被 Prompt 复用（组装的组件本质是 prompt 块）**。学完本单元，最值钱的不是任何单个技巧，是"**每个 token 都是决策，每个决策都可消融**"的工程观。
