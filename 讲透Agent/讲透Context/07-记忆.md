# 07 - 记忆：窗口之外的持久化

> 讲透Context 第 07 章 | 实验：E7（`experiments/e7_notes.py`，results/e7_notes.json/png）| 素材：Anthropic structured note-taking + harness 博客（✅一手）

## 一、直觉：交接班日记 vs 会议纪要

compaction（Ch05）像**会议纪要**：把对话流线性压扁，连续性好，但细节随缘。
structured note-taking（本章）像**交接班日记**：护士下班前按习惯写几行——3 床停用抗生素、7 床等空腹结果——下一个人看日记接手，没人去重听 8 小时的护理录音。

Anthropic 的定义：agent 定期把笔记写到**窗口之外**的持久存储，之后再拉回来。两个关键差别：

1. **写入时机自主**：不是"窗口满了才压"（被动），而是 agent 边干边写（主动、增量）；
2. **读取按需**：笔记是文件/API，不占常驻预算——这是"把信息搬出注意力市场"的完整含义。

生产案例（全部一手核实）：Claude Code 的 to-do list、自定义 agent 的 NOTES.md、Anthropic harness 博客的 `claude-progress.txt`（跨窗口交接的核心工件，与 git log 并列为状态恢复的两大来源）、以及我们自己的 `RESUME-*.md` 断点文件——**本仓库每天在跑本章的实验**。

## 二、数学：记忆 = 带查询接口的外部状态

形式化：agent 会话 $t$ 结束时，把状态 $S_t$ 写为外部记忆 $M_t = \mu(S_t)$；会话 $t+1$ 的上下文 = 系统提示 + $\rho(M_t, q)$（按当前问题 $q$ 检索回填）。与 compaction 的本质区别：

| | compaction | 外部记忆 |
|---|-----------|---------|
| 保留函数 | $\mu$ 一次性、有损、预算硬 | $\mu$ 增量、可无损（文件系统） |
| 访问函数 | 全量进窗口 | $\rho$ 按需检索（子集进窗口） |
| 失败模式 | F1/F2/F3（Ch05） | 检索失败（recall@k）+ 陈旧/冲突 |
| 信息论地位 | GEN 博弈（Thm 1 下界管着） | 把下界摊到多次查询上**分摊支付** |

最后一行是关键洞察：compaction 必须**一封信写完所有未来查询的答案**（下界最凶）；记忆系统允许**每个查询发自己的信**（每封信的通信复杂度都小）。Scroll（arXiv 2608.21690，✅一手）把这个思路推到极致：Event Log 无损保存 + Python kernel 按需物化，LOCA256K 超最佳系统 37.4pp。

## 三、代码：E7 双会话接力对决

**设计**：与 E5 同一份 20 事实转录、同一 12 题、同一答题器。会话 1 让 glm-4-flash 写交接笔记（两种引导：N1 自由"写下接手需要的备忘"；N2 给定字段模板"每个字段必须填"）。会话 2 全新上下文只读笔记答题。

```bash
cd 讲透Context/experiments
python3 e7_notes.py    # ~3 min（纯 API）
```

**实测结果**：

| 交接介质 | 成本 (tok) | 主旨 | 细节 | 总 acc |
|---------|-----------|------|------|--------|
| compaction 线性摘要（E5） | 166 | 100% | 62.5% | 75.0% |
| N1 自由笔记 | 349 | 100% | **87.5%** | **91.7%** |
| N2 结构化模板笔记 | 325 | 100% | 75.0% | 83.3% |

### 发现 1：笔记碾压摘要（+25pp），代价是 2 倍 token

"写给接手人看"的任务框架让模型自发保住了大部分数字细节（苏晴/8841/90天/3号节点全活）。信息论解读：摘要要在一封信里赌所有未来查询；笔记是"状态转储"心态，不赌。**多花 183 tok 买回 25 个百分点**——这是 context 经济学里最划算的一笔交易。

### 发现 2（反直觉）：结构化模板输给自由笔记

Factory.ai 的 36,611 消息实测说"结构化摘要 3.70 > 自由摘要 3.44"；我们的 N2（结构化）却输给 N1（自由）75% vs 87.5%。死因在 N2 全文里看得清清楚楚——**模板即过滤器**：

模板的"架构决策"栏只写了"库存服务暂缓"，灰度 5% 和超时 8s 没有自己的字段就死了。而 N1 没有栏位约束，模型自行判断"这俩数字接手的人得知道"。**字段化的记忆是白名单，白名单之外一律蒸发**——这与讲透Graph 的"类型边"教训同构：结构换来精度，也带来结构性盲区。

### 发现 3（最重要）：丢字段会诱发幻觉与陈旧值回归

N2 会话 2 的两道错题，答题器没有弃权，而是：

- 灰度题 → 答"**10%**"（幻觉改值，转录里从没有 10）
- 超时题 → 答"**3 秒**"（**检索回调整前的旧值**——转录里"从 3 秒调到 8 秒"）

对照 N1 的唯一错题：答题器老实说"备忘未给出具体数字"（诚实弃权）。

**推论**：交接介质的失败模式会传染给下游行为。自由笔记丢信息时模型倾向弃权；模板丢字段时留下的"应有此栏"心理暗示，把弃权改造成了编造。给 agent 设计记忆模板时，**每个"待填"字段都必须有"未知/无此项"的合法出口**，否则空栏就是幻觉发生器。（本仓库 AGENTS.md 的规范"孤儿文件=死亡内容"、frontmatter 必填字段，同理。）

## 四、工程启示：记忆系统设计清单

1. **compaction 保连续，memory 保状态，sub-agent 保隔离**（Anthropic 三分法）——别用错工具：审计级细节走 memory，不走摘要；
2. **模板设计即信息生死判决**：每个字段问三遍"漏了会怎样"；给"无此项"出口；定期对照真实查询审计字段覆盖率（本仓库 graph_lint 同思想）；
3. **写入要勤，读取要懒**：增量写（每个里程碑一行）+ 按需读（当前任务相关的 section），这是 Anthropic harness "initializer + coding agent" 模式的内核；
4. **记忆要带时间戳与版本**：E7 的"3 秒"教训——没有时间锚的旧值会和新值打架（讲透Graph 的 bi-temporal 边是同一家族的解）；
5. **会话恢复协议**：先读 progress 文件 + git log，再干活，结束必写——把 RESUME 模式制度化（本仓库 RESUME-*.md 是活样板）。

## 五、不足与批判

- 单轮交接（20 分钟任务）；真实长期记忆面临**遗忘治理**（什么该删）、**冲突消解**（两次记录打架）、**检索质量**（记忆多了以后 $\rho$ 成为新瓶颈）——本章只测了"写入保真"，没测"规模化之后的读取"，那是 2602.06052（TMLR 综述）的领地；
- N1/N2 各只跑一次（temp=0.1），模板效应的结论需要多种模板复现才稳（练习 2）；
- "笔记优于摘要"混入了 token 预算差异（349 vs 166）——公平版应把摘要预算也提到 349（练习 1）。
