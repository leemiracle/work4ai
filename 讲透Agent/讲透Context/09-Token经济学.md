# 09 · Token 经济学：一次 compaction $13 的算术

> 讲透Context 第 09 章 | 用 E1/E4/E6/E8 的实测数字换算

## 1. 直觉层：上下文是订阅制，窗口里的每个 token 每轮都收费

最常见的成本错觉："多塞点上下文不要紧，反正一次就付一次钱"。错。**多轮会话里，历史每轮都重发一遍**——上下文不是买断制，是订阅制。第 $t$ 轮的输入成本：

$$C_{\text{in}}(t) = \sum_{\tau=1}^{t-1} [c_{\text{sys}} + c_{\text{tools}} + \text{out}(\tau)] + c_{\text{query}}$$

历史随轮数线性堆，**累计输入成本随轮数平方堆**（$\sum_t t \sim t^2/2$）——讲透Graph E2 的 O(N²) 历史税在本章换成美元面额。

## 2. 算术三则

**算术一：长会话的隐性账单（$13 的由来）**
以 Claude Sonnet 档价格（$3/M 输入，缓存的未命中同价）估算一个重型 agent 会话：system+tools 1.5K，RAG 注入 3K，每轮输出 500 tok，跑 40 轮：
- 最后一轮输入 ≈ 1.5K + 3K + 39×500 ≈ 24K；
- 累计输入 ≈ $\sum_{t=1}^{40} (4.5K + 0.5K(t-1))$ ≈ 4.5K×40 + 0.5K×780 = 180K + 390K ≈ **570K 输入 token ≈ $1.7**。
放大到 200 轮重度会话 + 更肥的 RAG（每轮 8K）即破 $13——**单个会话两位数美元，纯粹的"历史重发税"**。两个解法：prompt caching（命中部分约 1/10 价）与 compaction（砍历史本体）。

**算术二：compaction 的盈亏平衡点**
compaction 一次的成本 = 全历史读入（$c_{\text{hist}}$）+ 摘要输出（$m$）。收益 = 之后每轮省 $(c_{\text{hist}} - m)$ 的重发。设之后还会跑 $T$ 轮、输出价是输入的 5 倍：

$$\text{净收益} = T \cdot (c_{\text{hist}} - m) \cdot p_{\text{in}} - (c_{\text{hist}} \cdot p_{\text{in}} + m \cdot p_{\text{out}}) > 0$$

代入 $c_{\text{hist}}=20K$、$m=2K$、$T=10$：收益 180K·$p_{\text{in}}$ − 成本 30K·$p_{\text{in}}$ ≈ **6 倍回报**——这就是 Factory.ai 实测"70% 利用率主动压缩优于 95% 被动"的数学结构（早压比晚压省，因为省的是之后每一轮）。

**算术三：蒸馏的量纲（E8 换算）**
E8 的 sub-agent 模式：探索 4.5K 字 → 回传 1/5。按 glm-4-flash 档（输入 ¥/M 极低）不值一提，但按旗舰档（$15/M 输出）放大到生产规模——每天 1 万次 sub-agent 派遣、每次探索 50K、回传 2K：探索若不隔离而全进主窗口，历史税会以 50K/次 的速度污染所有后续轮次；隔离后主窗口只增 2K/次。**sub-agent 的价值随"探索深度 × 后续轮数"放大，随蒸馏率缩小**——E8 的悬崖告诉我们回传不能低于 1/5，算术三告诉我们不必高于 1/2。

## 3. 本单元自己的账单（诚实披露）

本单元 8 个实验全部 LLM 调用走 glm-4-flash（免费档）+ 本地 Qwen（电费），API 现金成本 ≈ **¥0**。但 token 成本真实存在（E8 一次 ≈ 9 条件×12 题×~1K tok + 3 次压缩 ≈ 120K token）——**零现金成本不等于零工程成本**：如果换旗舰模型，本单元一天的实验账单会到数十美元。这也是"实验用 mini 档、结论跨档引用时要标价差"的纪律。

## 4. 价格敏感度：哪些结论会随价格翻转

- **prompt caching 普及后**：历史重发税打 1 折 → 算术一的紧迫性下降 → compaction 触发点后移（从 70% 利用率后移到 90%+）——**缓存是 compaction 的竞争技术**；
- **长上下文降价后**：E3 的 rot 提醒我们"窗口能装 ≠ 窗口能用"——**降价不治 rot，只治账单**；
- **输出/输入价比变化**：E6 的 Bloom 对照（Selection vs Generation 的 Θ(log n) 差距）会随输出降价而缩小——但 E5/E8 的幻觉与 brevity bias 是行为问题，不随价格消失。

## 5. 不足与坑

- **价格数字时效性**：本章单价是 2026-08 的量级快照，做决策前查当日价目表；结构性结论（平方律、盈亏平衡、量纲分析）比单价稳；
- **缓存命中的工程条件**（前缀稳定、不被动态内容打断）常被忽略——system 里塞时间戳会让全前缀缓存失效，**为了 30 tok 的日期锚杀死了 4K 的缓存**（E4 的日期注入要用，但要注入到 query 侧而非 system 侧）；
- **隐性成本未计**：延迟（用户等待）和失败重试（讲透Prompt 的 retries=1 教训）在 token 账单外，但常是主要痛点。
