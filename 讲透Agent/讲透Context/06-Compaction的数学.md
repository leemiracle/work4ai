# 06 - Compaction 的数学：通信复杂度下场

> 讲透Context 第 06 章（本单元的数学王牌）| 实验：E6（`experiments/e6_bloom_vs_summary.py`，results/e6_bloom_vs_summary.json/png）| 素材：arXiv 2608.01326《Context Compaction Theory》（2026-08，✅一手）

## 一、直觉：把摘要当成"给未来自己的一封信"

把 compaction 抽象到最简：Alice（现在的 agent）要把状态 $S$ 压进一条 $B$ token 的消息，交给 Bob（未来的 agent，上下文已清空）回答查询 $q$。**这是一通信问题**——而且是最难的那种：Alice 发完信就消失（单向），Bob 只能凭信作答。

通信复杂度理论对"一条 $B$ 比特的消息能保多准"研究了四十年。2026 年 8 月，Context Compaction Theory 把这张桥梁图纸搬进了 agent 世界：

- **Thm 1**：Context Generation Game（任意有界摘要）的最小预算 = 对应通信问题的**单向随机通信复杂度**——摘要的下界不再是经验值，是定理；
- **Thm 3**：存在查询族，Selection（只能挑原文子集保留）比 Generation（可以自由改写）多花 $\Theta(\log n)$ 倍预算——**"让模型自由发挥摘要"有可证明的优势空间**；
- **附录 A 案例研究**：给 Anthropic 生产级 compaction endpoint 喂 15,000 项集合，声明"只用于 membership 查询"，实测其错误率**接近随机猜**，而同尺寸 Bloom filter 近乎最优——通用摘要被专用数据结构碾轧。

E6 做的就是这个案例的玩具级公平复现。

## 二、数学：两个游戏与一个过滤器

### 2.1 两个游戏（2608.01326 的形式化）

**Selection Game**：选择器从 $n$ 项状态里挑子集 $T \subseteq S$，$|T|$ 受预算 $B$ 约束；随后对手出题 $q$，答题方只能看 $T$。
**Generation Game**：压缩器输出任意消息 $m$，$|m| \le B$；答题方只看 $m$。

关键不等式链：$\text{预算}_{GEN}^*(q, \epsilon) = \text{CC}^{1\text{-way}}(q, \epsilon) \le \text{预算}_{SEL}^*(q, \epsilon)$，且差距可达 $\Theta(\log n)$（Thm 3）。

### 2.2 Bloom filter：membership 查询的近最优 GEN 策略

$n$ 项集合压进 $m$ bit、$k$ 个哈希函数。假阳率有闭式：

$$FPR = \left(1 - e^{-kn/m}\right)^k$$

取最优 $k^* = \frac{m}{n}\ln 2$ 时 $FPR^* \approx 0.6185^{m/n}$——每项花 10 bit 即 FPR ≈ 0.8%。**假阴率恒等于 0**（在集合里的项绝不可能被报"不在"）——这是数据结构给的数学保证，LLM 摘要没有对应物。

### 2.3 为什么这对 agent 工程重要

生产 agent 的状态里有大量"集合型"子结构：已访问 URL、已改动文件、已验证定理、白名单/黑名单。对这类子状态，**不要用 LLM 摘要承载**——用可序列化的数据结构（Bloom/bitmap/倒排表），token 效率有数量级差距。LLM 摘要只该承载"语义综合型"子状态（决策、风格、目标）。这就是 Thm 1 的工程翻译：**先给状态分类学（查询族），再选压缩策略**。

## 三、代码：E6 对决

**设计**：120 个随机 6-hex ID 的集合；预算锚定 Selection 保留 40 项（261 tok）；三策略在同一预算量级下接受 48 次 membership 查询（24 正 24 反）。

```bash
cd 讲透Context/experiments
python3 e6_bloom_vs_summary.py    # Bloom 部分 <1s；LLM 部分几分钟
```

**实测结果**：

| 策略 | 预算 (tok) | Acc | FPR | FNR | 备注 |
|------|-----------|-----|-----|-----|------|
| **Bloom** (m=1024, k=3) | 256 | **97.9%** | 4.2% | **0** | 理论 FPR 2.6%，48 样本 1 个 FP，统计一致 |
| Selection (40/120) | 261 | 64.6% | 0 | 70.8% | FNR ≈ 2/3 = 未保留率的精确预测 |
| glm-4-flash 摘要 | **500（超预算 92%）** | 77.1% | 0 | 45.8% | 策略=排序列表抄写，500 tok 只抄到 ~60 项被截断 |
| Qwen-0.5B 摘要 | 6 | 50.0% | 0 | 100% | 摘要只剩 1 个 ID = brevity bias 极端标本 |

四层解读：

1. **Bloom 完胜**：FNR=0 是数学保证的兑现；FPR 与理论值在抽样误差内一致——**理论与实测闭环**；
2. **Selection 的损失可精确预测**（保留率 1/3 → 对未保留项 FNR=100% → 总 FNR ≈ 2/3 实测 70.8%）：它的失败是**确定性的、可算的**，这反而是工程优点（可预算）；
3. **glm 的策略曝光是全场最深的一课**：它的"最优解"就是**人肉当 Bloom**——把 ID 排序后尽量多抄。但 500 token（已超预算 92%）只抄到 60/120 项。LLM 在结构化任务上的理性策略收敛于"模拟数据结构"，而 token 效率天然吃亏（每 ID 6 个 hex 字符 ≈ 3-4 tok，Bloom 每项摊 ~2.1 tok 且假阴为零）。**这就是通信复杂度差距的肉眼版**；
4. **预算不守恒是 LLM 压缩器的通病**：指令说"不超过 ~261 tok"，glm 自然写到 500——E5 的"400 字"压到 166 tok 是反向失控。**LLM 压缩器的输出长度是概率性的，不是工程性的**——需要外层硬截断兜底。

## 四、理论到工程的映射表

| 2608.01326 概念 | 本实验对应 | 工程动作 |
|----------------|-----------|---------|
| Selection Game | 保留 40 项原文 | 截断/保留最近 N 条 = 最糙的 compaction |
| Generation Game | LLM 自由摘要 | Claude Code 式 compaction |
| 单向通信复杂度 | 预算下界定理 | "再聪明的摘要也绕不过信息论下界"——别对摘要保数字抱幻想 |
| Bloom 近最优 | 97.9%/FNR=0 | 集合型状态用数据结构序列化，不进摘要 |
| endpoint 接近随机猜 | glm 77.1%（我们的玩具场更宽容） | 生产摘要器在结构化查询上是重灾区 |

**与 Ch05 的接口**：F2（压缩中信息损失）的定量刻画就是本节的保留率上界；F3（访问失败）对应"信息在 $m$ 里但答题方没取到"——通信复杂度里这是协议成本，工程里这是 Ch05 发现 2 的幻觉温床。

## 五、不足与批判

- 玩具规模（N=120 vs 论文 15,000）：LLM 的劣势随 N 单调放大（每 ID ~4 tok 线性膨胀 vs Bloom 近线性 bit），我们的实验**低估**了生产场景的差距；
- 只测了 membership 一种查询族——Generation 的 $\Theta(\log n)$ 优势查询族（如"第 大元素"、频次统计）没构造，Thm 3 只有陈述没有本地验证（好练习，见下）；
- Bloom 的 256 tok 里 hex 序列化有 token 化效率损失（hex 字符 ≈2.5 字符/tok），二进制直存更省但 LLM 读不了——**"给 LLM 的压缩"与"给机器的压缩"是两个不同目标函数**，本实验混在了同一预算标尺上，论文原文其实也是。
