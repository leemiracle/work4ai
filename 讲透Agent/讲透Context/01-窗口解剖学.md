# 01 · 上下文窗口解剖学：token 都花在哪

> 讲透Context 第 01 章 | 实验 E1（`experiments/e1_anatomy.py` → `results/e1_anatomy.json`）

## 1. 直觉层：先看账单，再谈策略

Context engineering 的第一课不是"怎么放"，是"**钱花哪了**"。把一个典型 agent 会话的窗口摊开记账，你会发现一个刺眼的事实：**用户的查询本身只占 17 个 token——其余全是你塞进去的**。窗口不是用户的地盘，是工程师的地盘；每个 token 都是你决策的结果。

五个策略档位（E1 实测，Qwen2.5 tokenizer 计数）：

| 档位 | 构成 | 总量 |
|------|------|------|
| S1 最小 | query 17 | **17** |
| S2 标准 | system 82 + 4 轮历史 135 + query 17 | 234 |
| S3 带工具 | + 3 个工具 schema 238 | 472 |
| S4 厨房水槽 | + 10 工具全量 997 + RAG 6 段 438 | 1,669 |
| S5 渐进披露 | 10 工具只给 L1 清单 219 | 453 |

三个结构性观察：

1. **工具 schema 比对话历史贵**：3 个工具（238）> 4 轮历史（135）。agent 场景里"挂什么工具"是比"聊了几轮"更大的 token 开销——这就是讲透Harness 与本单元的交叉点；
2. **query 占比 <2%**：S4 里用户的问题占 17/1669 ≈ 1.0%。context engineering 的本质是**管理那 99%**；
3. **渐进披露省 78%**：10 个工具从全量 schema（997）换成一行式清单（219），功能可达性不变、详情按需加载——这是讲透Skills E2（省 93.1%）的同构机制，也是一切"分层上下文"设计的原型。

## 2. 数学层：窗口是预算约束，不是容器

把窗口看作容量为 $W$ 的预算，各类内容竞争配额：

$$\sum_i c_i \le W, \quad c = (c_{\text{sys}}, c_{\text{tools}}, c_{\text{hist}}, c_{\text{RAG}}, c_{\text{query}})$$

工程问题变成：在预算内**最大化边际信号**。第 $i$ 个 token 的价值不是独立的——存在三类交互：

- **互补**（schema+示例Together 才有效，见 E4 的 C3）；
- **替代**（历史可以用摘要替代，见 E5 compaction）；
- **对抗**（distractor 主动伤害，见 E3：干扰×长度双重打击）。

所以线性"塞满窗口"是错的目标函数。Chroma 的实证格言："whether relevant information is present is not all that matters—**how it is presented matters more**"。

**预算的时变结构**：多轮会话里 $c_{\text{hist}}$ 每轮增长，挤占 $c_{\text{RAG}}$ 的空间——这就是 compaction 触发时机的经济学（Ch09 把它换算成美元）。

## 3. 代码层：自己记账

E1 的核心就二十行：tokenizer 数一遍每块内容。任何项目都能在一天内装上这个仪表盘：

```python
from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained(model_path)
def audit(parts): return {k: len(tok.encode(v)) for k, v in parts.items()}
# 输出就是上面的表格——惊讶通常从"工具比历史贵"开始
```

**建议的监控三指标**：query 占比（健康 <5%，失控说明窗口被劫持）；tools/total 比（>50% 时该做渐进披露）；每轮增速（历史线性增长的斜率决定 compaction 何时被迫触发）。

## 4. 不足与坑

- **tokenizer 依赖**：同一个字符串在不同 tokenizer 下计数差 ±20%，跨模型比较要标注 tokenizer（E1 用 Qwen2.5）；
- **计数≠注意力**：E2 的零结果证明"放进去"和"被用到"是两回事——本章的账单只回答成本侧，收益侧要看位置效应（Ch02）和 rot（Ch03）；
- **隐形上下文**：system prompt 里继承的模板、工具返回值里的冗余字段，往往不在任何人账上——审计要含"谁塞的"标签（provenance），否则没法问责。

## 5. 与姊妹篇接口

- ← 讲透Prompt：prompt 是这里 $c_{\text{sys}}$ 里最贵的那一段；
- → 讲透Graph Ch01：图的查询结果序列化后就是新的 $c_{\text{RAG}}$ 条目——图管窗口外，本章管窗口内；
- → Ch09：本章的 token 数全部会在 Ch09 换算成美元账单。
