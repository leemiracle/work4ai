# 02 - 位置效应：放进去 ≠ 用得上

> 讲透Context 第 02 章 | 实验：E2（`experiments/e2_position.py`，results/e2_position.json/png）| 上游：[00-开场白.md](00-开场白.md)

## 一、直觉：图书馆的书架问题

想象你在图书馆查一个事实，但这本书可能被放在第一排、正中间、或者出口处的还书车上。直觉上：**出口处（最近）最容易拿到，第一排（最初）也行，正中间最惨**——你必须穿过整个图书馆。

LLM 的注意力 allegedly 就是这个结构：对上下文开头（primacy，训练数据里指令常在开头）和结尾（recency，因果注意力天然偏向近处）的信息利用更好，中段存在"盲区"。这就是著名的 **lost in the middle** 现象（Liu et al. 2023，arXiv 2307.03172，🔁转引待核，写作用到时再核）——20 个文档的 QA 准确率呈 U 型：第 1 位和第 20 位文档的答案利用率最高，中间文档塌陷。

**为什么这属于 context engineering 而非 prompt engineering**：你控制不了模型内部的位置偏置，但你完全控制**每条信息落在窗口的哪个位置**。RAG 命中的段落放前还是放后、system prompt 里的关键约束放第几条、工具结果要不要后置重排——都是策展决策。

## 二、数学：位置偏置从哪来

三个来源（定性 + 一个定量钩子）：

1. **因果注意力的结构性近因**：softmax 注意力对每个 query token 归一化，位置越近的 key 通常注意力质量越大（尤其是没有显式位置衰减补偿时）。记位置 $j$ 的 key 对当前 query 的注意力权重 $a_j = \frac{\exp(e_j)}{\sum_k \exp(e_k)}$——窗口越长分母越大，**每个远处的 $a_j$ 被稀释**，中段信息既要对抗距离又要对抗数量；
2. **训练分布偏置**：指令微调数据里，指令在开头、答案在结尾，模型学到了"头尾重要"的先验；
3. **位置编码的分辨率衰减**：RoPE 等相对位置编码在长距离上内积退化（讲透Transformer 有专章），外推区尤其严重。

定量钩子（Ch06 会兑现）：无论位置偏置多严重，它只是"利用率的非均匀分布"；而窗口总预算 $B$ 限制了你能放的 token 数——位置最优排布是预算约束下的分配问题。

## 三、代码：E2 实验——以及一个重要的零结果

**设计**：4 个 needle 事实句（密钥保管人/口令/截止日/限流值），插入 filler 段落 5% / 50% / 92% 处，问题固定在末尾。Qwen2.5-0.5B（本地 CPU）与 glm-4-flash（API）双模型。

```bash
cd 讲透Context/experiments
python3 e2_position.py --model qwen --lengths 600      # ~4 min
python3 e2_position.py --model qwen --lengths 3200     # ~13 min
python3 e2_position.py --model glm --lengths 600,1600,3200,6400
python3 e2_position.py --plot
```

**实测结果（24 个格子）**：

| 模型 | 长度 | 首(5%) | 中(50%) | 尾(92%) |
|------|------|--------|---------|---------|
| Qwen-0.5B | 600 | 4/4 | 4/4 | 4/4 |
| Qwen-0.5B | 3200 | 4/4 | 4/4 | 4/4 |
| glm-4-flash | 600 | 4/4 | 4/4 | 4/4 |
| glm-4-flash | 1600 | 4/4 | 4/4 | 4/4 |
| glm-4-flash | 3200 | 4/4 | 4/4 | 4/4 |
| glm-4-flash | 6400 | 4/4 | 4/4 | 4/4 |

**全满。零位置效应。**

## 四、零结果的正确读法：NIAH 幻觉的本地复证

这个"失败"恰恰复现了 Chroma《Context Rot》报告对行业现状的批评：

> NIAH（大海捞针）本质是**词面检索**任务——needle 里写着"KX-2077"，问题里也写着"KX-2077"，模型只需要做字符串匹配级别的关联。**在词面匹配任务上，0.5B 模型在 3.2K 窗口、API 模型在 6.4K 窗口都毫无压力。**

所以"NIAH 全绿 → 长上下文已解决"的推理是错的。真实 agent 轨迹里没有这么客气的问题：

- 问题与答案**没有词面重叠**（NoLiMa：问"谁去过赫尔辛基"，needle 说"住在 Kiasma 博物馆旁边"）；
- 上下文里有**同形干扰**（KX-2076 王倩 / KX-2077 林澈，要求精确绑定）；
- 任务是**综合**而非检索（对比两个相隔 5000 token 的工具输出）。

这正是 Ch03 要干的事：E3 换上同形干扰项，位置固定中段（50%），专测"绑定混淆 × 长度"。（剧透：Qwen 崩了，glm 没崩——rot 严格模型依赖。）

## 五、工程启示：位置策展清单

即便词面检索测不出 U 型，位置策展仍是低成本高收益的工程习惯（对齐 lost-in-the-middle 文献与各厂 prompting guide 的共识建议）：

1. **关键约束放头尾，别埋中段**：system prompt 首条的指令遵循率高于中段指令（讲透Prompt Ch08 模型适配有互证素材）；
2. **长文档 RAG：重排器（reranker）的本质是位置策展**——把最相关 chunk 从中段捞到尾部；
3. **"重申"是廉价的近因补贴**：超长上下文任务在结尾复述一遍关键目标（Anthropic multi-agent 系统的 CitationAgent 等子 agent prompt 都这么干）；
4. **别用 NIAH 当验收标准**：加一类"同形干扰绑定题"进你的 eval（抄 E3 的 DISTRACTORS 设计即可，20 行代码）。

## 六、不足与批判

- E2 的 needle 是词面型，测不出 ≠ 不存在位置效应，只说明"该任务测不出"——U 型要在语义 needle / 多跳 / 综合任务上复现（本单元 E3 部分覆盖，语义 needle 留作扩展练习）；
- filler 是重复同一段话（结构均质），Chroma 实测 **haystack 的结构本身影响结果**（反直觉：有序连贯的 haystack 反而比打乱的更伤性能）——我们的 filler 设计绕开了这个变量；
- n=4/格，统计功效低；结论方向（任务难度才是主变量）与文献一致，故采信。
