# 05 - Compaction：压缩的艺术与三种失败

> 讲透Context 第 05 章 | 实验：E5（`experiments/e5_compaction.py`，results/e5_compaction.json/png）| 素材：Anthropic 工程博客 + preprints 202605.2065 失败分类

## 一、直觉：搬家公司装箱

搬家时你请了个装箱师（压缩器）：把 20 个房间的家当装进 3 个箱子（400 字摘要装下 2000 字对话）。装完到新家（下一个推理窗口），你问装箱师："我的黑色转接头呢？"

三种可能的悲剧：

- **F1 他压根没觉得转接头重要**（该装箱没装——压缩前的决策错误）；
- **F2 他装了别的，转接头被扔了**（装箱过程中的信息损失）；
- **F3 转接头就在箱子里，你翻三遍没翻到**（信息还在，访问失败）。

这就是 preprints 202605.2065（Context Compression for LLM Agents: A Survey）给出的失败分类 F1/F2/F3——compaction 的工程学，一半是压缩率，另一半是**失败模式学**。

**Compaction 的定义**（Anthropic）：把接近窗口上限的对话摘要化，用摘要重启新窗口。Claude Code 的实现：保留架构决策、未解 bug、实施细节，丢弃冗余工具输出，外带最近 5 个文件。它是长时程 agent 的**第一杠杆**（first lever）。

## 二、数学：损失率的分解

设转录含事实集 $F = \{f_1, ..., f_N\}$，摘要器 $S$ 产出 $S(F)$。会话续跑时的问答正确率可分解为：

$$P(\text{答对}) = \underbrace{P(f \in S(F))}_{\text{保留率 (1-F2)}} \times \underbrace{P(\text{答对} \mid f \in S(F))}_{\text{访问率 (1-F3)}} + P(\text{答对} \mid f \notin S(F)) \times \underbrace{P(f \notin S(F))}_{\text{损失率}}$$

最后一项在无外部记忆时≈瞎猜或幻觉。注意 $P(f \in S(F))$ 由**摘要器的策展决策**决定（F1 是其系统性偏差：把"该保的类别"都丢了），F2 是其对"细节 vs 主旨"的隐性取舍。压缩率 $\rho = |S(F)|/|F|$ 不是自由参数——给定 $\rho$，保留率有信息论上界（Ch06 的通信复杂度下场）。

## 三、代码：E5 实验——20 项事实的压缩保真率

**设计**：20 项事实（代号/人数/决策/参数/bug/日期）嵌入迁移对话转录 → 两种压缩器（glm-4-flash / Qwen-0.5B，同一压缩提示词："保留架构决策、未解决 bug、关键实施细节，400 字以内"）→ 固定答题器（glm-4-flash, temp=0）分别在 {完整转录, 两种摘要} 上答 12 题（4 主旨 + 8 细节）→ 按答案串是否在摘要文本里分 F2/F3。

```bash
cd 讲透Context/experiments
python3 e5_compaction.py    # ~4 min（1 次本地压缩 + 36 次 API 问答）
```

**实测结果**：

| 介质 | 总 acc | 主旨 | 细节 | 失败分类 |
|------|-------|------|------|---------|
| 完整转录 | 91.7%* | 75%* | **100%** | 基线（*见评分假阴性注） |
| glm 摘要（166 tok） | 75.0% | **100%** | 62.5% | F1=0，F2=2，F3=1 |
| Qwen 摘要 | 16.7% | 25% | 12.5% | **F1=3，F2=7** |

*评分假阴性：全文基线那道"错"的主旨题，模型答"库存服务这次不迁移"（语义正确），关键词是"暂缓"——关键词评分的局限，人工复核后基线实为 100%。

三个层级的发现：

### 发现 1：选择性失忆是特性不是 bug
glm 摘要**主旨 100% / 细节 62.5%**——压缩器精准执行了"保决策弃细节"的指令。丢的两项：时区偏移"13 小时"被压成"时区偏移"（数字蒸发）。这与 Anthropic 的设计意图一致：**compaction 天生为连续性（continuity）服务，不为审计（audit）服务**。要审计精度，别用摘要，用外部存储（Ch07）。

### 发现 2：压缩不仅丢信息，还会造假信息
问"回滚脚本由谁维护"，glm 摘要里没有苏晴，答题器答了"**张伟**"——一个转录里从未存在的名字。F2 的阴影面是幻觉：模型对"应该有个负责人"的先验压过了"摘要里没有"的事实。**摘要窗口里的空字段是幻觉的温床**。

### 发现 3：小模型压缩器会输出"假摘要"
Qwen-0.5B 的"摘要"是**把用户原话抄一遍**——5 行用户提问，零事实零压缩。F1=3 说明连主旨都没保住。这与 E6 里它"摘要只剩 1 个 ID"是同族病：小模型对"压缩"指令的执行退化成抄写或清空。**压缩器本身需要门槛，0.5B 不及格**。

## 四、工程启示：compaction 工艺手册

综合 Anthropic 博客的调法与本实验：

1. **先 recall 后 precision**（Anthropic 原话）：压缩提示词先迭代到"什么都不漏"，再删冗余——顺序反了会把 F2 埋进习惯；
2. **结构化 > 自由文本**（Factory.ai：3.70 vs 3.44，36,611 消息实测）——但见 Ch07 的反例：模板本身是过滤器，字段漏了=信息必死；
3. **70% 触发线**：退化在 ~30K 后加速，主动压缩优于被动到线；
4. **审计级信息走旁路**：数字/编号/承诺这类"未来争议证据"，写外部笔记（Ch07）或结构化存储（E6 的 Bloom filter 是极致版），不要赌摘要；
5. **压缩后立刻做一次"定向复述"**：问摘要几个已知答案的哨兵问题（canary），F3（访问失败）当场暴露——比事后翻车便宜得多；
6. **压缩器选型**：至少中档模型；小模型压缩器的失败不是"压得糙"而是"根本没压"。

## 五、不足与批判

- 12 题 × 1 转录，样本小；F2/F3 边界依赖"答案串在不在摘要里"的字符串判定，弱关键词（如数字"3"会撞"9月3日"）会污染分类——E5 的 F3=1 实际混入了一例这种噪声（对账节点题），已在结果 json 里标注；
- 只测了单次压缩。生产 agent 是**级联压缩**（摘要的摘要的摘要），误差复利——2608.01326 称之为 compaction 的 carried-forward 结构，Ch06 讨论；
- "400 字以内"是软约束，glm 实际 166 tok（它自己压得更狠），Qwen 输出格式失控——预算控制本身是个未解工程问题（Ch06 的 E6 也有同款发现：**LLM 压缩器不守 token 预算**）。
