# 04 · 组装：检索、结构化与渐进披露

> 讲透Context 第 04 章 | 实验 E4（`experiments/e4_assembly.py` → `results/e4_glm.json` / `e4_qwen.json`）

## 1. 直觉层：窗口是装配车间，不是仓库

Ch01 记了账，本章管装配：**同一堆信息，拼法不同，产出生死不同**。原型案例是 dair-ai 指南里的 Search Planner：让模型把自然语言查询转成结构化检索请求（JSON），组装方式分四档（累积式，每次只加一块）：

- **C0 裸指令**："转成检索请求"——只说目标；
- **C1 +schema 字段表**：字段名/类型/必填性——**结构宪法**；
- **C2 +日期注入**：当前日期 + "相对日期必须解析为绝对日期"——**时间锚**；
- **C3 +JSON 示例**：一个 worked example——**格式示范**。

## 2. E4 实测：缺谁塌哪块（glm-4-flash，8 查询 × 4 配置）

| 配置 | JSON 合法率 | 相对日期正确率 |
|------|------------|---------------|
| C0 裸指令 | 8/8 | 无 date_range 字段（0 尝试） |
| C1 +schema | 8/8 | **0/4**（字段有了，日期全错） |
| C2 +日期注入 | 8/8 | **4/4** |
| C3 +示例 | 8/8 | 4/4（保持） |

三条工程结论：

1. **JSON 合法率在强模型上已不是问题**（glm-4-flash 全档 8/8）——2023 年的"结构化输出难题"被模型能力进步和 schema 约束双重解决了；
2. **schema 给结构，但给不了时间**：C1 的 date_range 字段存在但内容全错（模型不知道"上周"是哪周）——**时间锚（当前日期注入）是独立于 schema 的必需组件**。这一课的通用形式：上下文组件之间**不可互相替代**（Ch01 说的"互补性"）；
3. **示例是格式保险而非能力开关**：C3 与 C2 持平——few-shot 在这里买的是输出格式稳定性（JSON 形状），不买正确性。

Qwen-0.5B 侧（6 查询，实测见 `results/e4_qwen.json` 与 e4_assembly.png）：**schema 把必填字段率从 0/6 拉到 6/6（救命组件）；但相对日期解析四个配置全部 0/4——时间锚救得了强模型（glm 0/4→4/4），救不了弱模型**（"上周=哪七天"的日历算术是 0.5B 的硬能力门槛，不是上下文能补的）。原始输出里还有两个更细的失败形态：C2 的 date_range **只写 start 丢 end**（Q2 的 start=2026-04-01 居然对——知识在、结构半残）；C3 加示例后**退化成形状抄写**（date_range 空对象 `{}`，json 合法率也掉到 5/6——模仿了例子的壳，丢了内容）。一句话总账：**强模型的瓶颈是知识（"上周"是哪周），弱模型的瓶颈是结构完整性；给弱模型加示例可能引入新失败模式（形状抄写）**。这与 E3 的 rot 结论同构：上下文组件的价值严格依赖模型能力分布。

## 3. 数学层：组装是组合优化

把装配形式化：候选组件池 $\{c_1..c_m\}$（schema/日期锚/示例/RAG 段/工具清单...），预算 $W$，任务成功率 $P(\text{success} \mid \text{selected})$：

$$\max_{S \subseteq \{c_i\}} P(\text{success} \mid S) \quad \text{s.t.} \quad \sum_{i \in S} |c_i| \le W$$

E4 的四配置就是这条优化的一条坐标轴切片。注意 $P$ 关于组件**非单调**：distractor 组件（E3）使 $P$ 下降；重复组件（多份相似 RAG 段）近似冗余。实际工程没有人真解这个优化——都用 E4 这种**累积式消融**摸方向：先加最便宜的确定性组件（日期锚 30 tok），再加贵的（示例 200+ tok）。

**性价比排序**（E4 + E1 合并视图）：日期注入（~30 tok，日期题 0%→100%）> schema 表（~150 tok，字段合法+防幻觉字段）> few-shot 示例（~250 tok，格式稳定）> RAG 全段（最贵，只在该有的事实没有时才加）。

## 4. 渐进披露：组装的时间维度

E1 已给数字（工具 schema 997→219，省 78%）。本章把它放进组装框架：**L0 清单常驻，L1 摘要按需，L2 全量按需**——三层组装把"每 token 的边际信号"从静态分配变成动态分配。dair-ai 指南的原话值得抄：schema 字段表 + 日期注入 + JSON 示例，就是 Search Planner 从"能跑"到"可靠"的全部距离（E4 证实：这三件 ≈ 400 tok）。

## 5. 不足与坑

- **组件间交互未扫**：E4 是累积式（C0⊂C1⊂C2⊂C3），没做全组合消融（如"示例但无 schema"）——16 格全扫是 4 倍成本，留给读者当练习；
- **日期锚的隐患**：注入的"今天"如果错了（时区/夏令时/系统时间漂移），所有相对日期解析**系统性偏移**——确定性组件的 bug 是全局性的；
- **temperature=0 的假象**：E4 用 temp=0，生产中 temp>0 时 JSON 合法率会掉几个点，C3 示例的"格式保险"价值会变大。
