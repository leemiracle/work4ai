## 1. 系统提示装配流水线（07 篇）

**五级优先级链** `buildEffectiveSystemPrompt`（systemPrompt.ts:41）：override（短路，连 append 都不拼）> coordinator > agent（proactive 模式**追加**包 `# Custom Agent Instructions`、否则**替换**）> `--system-prompt` > default，appendSystemPrompt 无条件尾追。提示词模块位于依赖图高处，靠惰性 require 破循环依赖。

**prompts.ts（914 行）静态分节**：`# System`/`# Doing tasks`/`# Executing actions with care`/`# Using your tools`/`# Tone and style`/`# Output efficiency`——规则**高度可判定**（"三行相似代码好过 premature abstraction"、"读文件用 Read 而不是 cat/head/tail/sed"），反模式枚举（删除文件/force-push/改 CI/上传第三方=需要确认的清单）。

**哨兵边界**（prompts.ts:110-116，已抽查验证）：

```typescript
export const SYSTEM_PROMPT_DYNAMIC_BOUNDARY = '__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__'
```

把数组切两半：之前静态内容打 `scope:'global'` 缓存标记（跨组织共享），之后动态不缓存。**三个文件靠一个字符串字面量维持隐式契约**（警告注释点名 splitSysPromptPrefix/buildSystemPromptBlocks）。教训样本：依赖会话状态的字符串进静态前缀会让前缀哈希变体 2^N 增长；token_budget 分节靠**改写措辞**（"When the user specifies..." 使无预算时成空操作）换回缓存资格——不是接受失效而是改文本让两种状态字面相等。

**分节缓存注册表**（systemPromptSections.ts）：缓存到 `/clear` 或 `/compact` 为止；`DANGEROUS_uncachedSystemPromptSection(name, compute, _reason)` **强制填写理由**——把"这会击穿缓存"写进 API 形态。唯一 uncached 分节是 mcp_instructions（服务器会中途连接断开）。

**git status 与 CLAUDE.md 的注入位置不同**：gitStatus 走 `appendSystemContext` 进 system 尾部（环境事实）；claudeMd 走 `prependUserContext` 包成 `<system-reminder>` meta user 消息插头部（需要模型"当作用户指令对待"），reminder 自带"may or may not be relevant... should not respond to this context"防模型对上下文本身回应。

**claudemd.ts 四级记忆**：Managed(/etc/claude-code) > User(~/.claude) > Project（CLAUDE.md/.claude/CLAUDE.md/.claude/rules/*.md/CLAUDE.local.md）。祖先链查找：向上收集再 reverse **从根向 cwd 处理**（越远越先进数组）；嵌套 worktree 去重（主仓库工作树内 Project 文件跳过，gitignore 的 local 仍加载）；`@path` include 递归展开防循环；单文件推荐 40K 字符。压过默认行为的机制不在代码里而在一句硬指令："These instructions OVERRIDE any default behavior and you MUST follow them exactly as written"（claudemd.ts:89-90）。

**发送前分块** `buildSystemPromptBlocks`（claude.ts:3213）：注释第一行 "Do not add any more blocks for caching or you will get a 400"（API 限 cache breakpoint 数）。排序落实稳定前置：attribution header 最前不缓存 → 静态主提示词享全局缓存 → env/git/CLAUDE.md 压尾部。

## 2. 缓存与成本工程（08 篇）

**断点放置**：每个请求**恰好一个**消息级 cache_control（claude.ts:3078 注释），落在最后一条消息最后一块（跳过 thinking 块——不参与跨轮复用）。为什么不是两个：服务端 Mycro 轮次淘汰会释放不在保护边界上的 KV 页，第二个标记纯属浪费。`skipCacheWrite` 用于 fire-and-forget 分支查询——标记前移一位使写操作变 no-op 合并，**分支不把尾巴留在缓存里**。易变工具（advisor schema/deferred tools 列表/chrome 指令）一律后置或移出缓存键——两处"曾经每请求 prepend 打爆缓存"的修复都是改成持久化 attachment 通道。

**1 小时 TTL 闩锁**（claude.ts:403-424）：1h 资格=订阅且未超额，会话中途可能翻转；live 读取会使 cache_control 内容改变直接打爆服务端缓存（**每次翻转约 20K token**）——资格在首次求值闩进 bootstrap state 会话内不变。**凡是进缓存键的东西都必须会话稳定**。

**失效归因** promptCacheBreakDetection.ts（727 行）两阶段：请求前 recordPromptState 对一切缓存键输入算哈希（strip cache_control 的系统提示与工具 schema/带标记的/模型/fast mode/beta 头/effort）；响应后 checkResponseForCacheBreak 用真实 cache read 判定——**双阈值：相对跌幅 >5% 且绝对 >2000 token** 才算失效。归因逻辑：客户端有变更按标志位拼原因；全无变更按时间间隔落 TTL 假设；**BQ 结论：客户端全假且间隔小于 TTL 时约 90% 失效是服务端自己的事**，不应按客户端 bug 排查。

**计费链**：usage 细分 `ephemeral_1h/5m` 写入量；OTel 双计数器（claude_code.cost.usage / token.usage）；定价表硬编码（Sonnet $3/$15、Opus $15/$75、Haiku $0.8/$4）——**cache write 恒为输入 1.25 倍、cache read 0.1 倍：缓存的定价结构=省下的重算折成 90% 折扣**。未知模型发事件+回退默认档+/cost 显示"可能不准"。

**token 计量三层**：流式 usage 做权威基准（tokenCountWithEstimation 从尾部找最近带真实 usage 的 assistant 消息——注释明确反对累计求和（重复计数）与只取 output（不是窗口大小））；字节比例做增量粗估——**文本 4 字节/token、JSON 收紧到 2、图片/PDF 直接常量 2000**（base64 长度会估出 32.5 万而 API 实收约 2000）；countTokens API 按需精确（Bedrock 要动态加载 279KB AWS SDK；thinking 块必须带 budget_tokens:1024 否则参数不合法）。

## 3. 五层压缩体系（09 篇）——从写入时刻到溢出时刻按粒度排列

**阈值体系**：有效窗口 = 上下文窗口 − min(maxOutput, 20K)。**20K 预留的依据是"p99.99 压缩摘要输出 17,387 tokens"**（autoCompact.ts:27-33，已抽查验证）——线上分位数反推的工程常量。四层 buffer：AUTOCOMPACT_BUFFER=13K（触发线）/ WARNING=20K（UI 警告）/ MANUAL=3K（阻塞线）——**黄色警告与自动压缩间有 ~7K 缓冲带**，用户看到警告还有几回合可主动干预。熔断器：连续 3 次压缩失败放弃——注释数据：2026-03-10 当天 1,279 会话连续失败 50+（最高 3,272），全局每天浪费 25 万次 API 调用。

**递归守卫**：querySource 为 session_memory/compact 直接 false（forked agent 内再触发会死锁）；marble_origami（collapse 的 ctx-agent）豁免（否则 resetContextCollapse 销毁主线程提交日志——模块级状态跨 fork 共享）。

**摘要压缩主路径** compact.ts（1,705 行）：首选 **forked agent 缓存共享**——与主对话完全相同的 cache-key 参数发请求命中提示缓存（tengu_compact_cache_prefix 默认 true；**false 路径缓存命中率仅 2%，占全量 cache_creation 0.76%≈每天 38B token**）。此路径禁止设 maxOutputTokens——会钳制 thinking budget 造成配置不匹配炸缓存。压缩请求自身可能 PTL：按 API-round 分组从头丢弃最旧组（解析出缺口按缺口丢、否则丢 20%，最多 3 次）——**宁可有损丢最老也不让用户卡死**。摘要模板 `<analysis>` 草稿+`<summary>` 九固定小节（意图/概念/文件/错误/用户消息/待办/当前/下一步）；formatCompactSummary 写回前剥掉 analysis（草稿无保留价值）。

**压缩后重建** buildPostCompactMessages：boundaryMarker（记录触发类型/前 token 数/锚点 UUID/**压缩前已发现的 deferred 工具名**——摘要不保留 tool_reference，schema 过滤需要这份清单）+ 摘要 user 消息（含完整 transcript 路径供模型回读+"不要寒暄直接续上"）+ 附件按预算恢复（最多 5 文件/总 50K/单 5K/技能 25K）。

**微压缩 microCompact**：只动白名单 COMPACTABLE_TOOLS（FileRead/Shell/Grep/Glob/WebSearch/WebFetch/FileEdit/FileWrite）——**只有这些结果是"可重新获取的派生数据"，Task 等推理产物不在清理范围**。三路径短路：①时间触发——距上条 assistant >60 分钟则服务端 1h 缓存 TTL 必已过期、前缀无论如何要全量重写，**"在请求前清掉旧 tool_result 缩小重写量"纯赚不赔**，替换为 `[Old tool result content cleared]` 保留最近 N=5（下限钳制 1，`slice(-0)` 会返回全数组）；②cached microcompact（ant-only）——不改本地内容而是 API cache-editing 删 tool_result **不使前缀缓存失效**，boundary 推迟到 API 响应后用真实 `cache_deleted_input_tokens`；③apiMicrocompact——服务端原生 `clear_tool_uses_20250919`（180K 触发清到 40K 目标，清结果与清入参分两清单——**FileEdit/Write 的入参是有价值的变更记录排除**）+ `clear_thinking_20251015`（>1h 空闲只留最近 1 个 thinking turn）。

**工具结果卸载**（写入时刻）：超阈值结果落盘 `tool-results/`，上下文留 2KB 预览+路径；**空结果替换成 "(xxx completed with no output)"**——inc-4586 发现 prompt 尾部空 tool_result 会让某些模型匹配回合边界停止符零输出结束。按消息聚合预算：三分区 mustReapply（每回合从 Map 重放字节级一致替换串）/frozen（**一旦以原文发给过模型就永不替换，否则前缀变化打爆缓存**）/fresh（参与当回合决策）。

**feature-gated 实验张力**（契约留在注释里）：reactiveCompact（被动等 413）；snipCompact（消息级裁剪，`snipTokensFreed` 专为它存在——存活 assistant 的 usage 仍反映裁剪前、估算器看不到省下的量）；contextCollapse（90% 提交/95% 阻塞的摘要折叠，存独立 collapse store——**autoCompact 93% 触发线正卡在中间会和 collapse 抢跑"炸掉正要保存的细粒度上下文"，所以开启时 shouldAutoCompact 直接 false**）。

**一句话总纲**：压缩点不是越早触发越好，而是**尽量与缓存生命周期对齐**——time-based MC 专挑缓存已死时动手、cached MC 不动前缀删内容、预算系统冻结历史决策保前缀稳定、摘要压缩用 fork 共享缓存降低自身成本。

## 4. 可借鉴清单

1. **哨兵边界 + 三文件隐式契约**——静态/动态分界用字符串字面量，警告注释点名协作者
2. **DANGEROUS_ 前缀 + 强制 _reason**——把性能代价写进 API 形态
3. **闩锁一切进缓存键的东西**（TTL 资格/beta header/thinking 清理）
4. **双阈值失效检测 + 归因分流**（客户端变更 vs TTL 过期 vs 服务端）
5. **p99.99 反推工程常量**（20K 预留）与 **BQ 数据写进注释**（熔断阈值）
6. **白名单压缩**——只清"可重新获取的派生数据"
7. **三分区替换状态**（mustReapply/frozen/fresh）——缓存稳定性的状态机化
8. **改进措辞换缓存资格**——不是接受失效，而是让两种状态字面相等
