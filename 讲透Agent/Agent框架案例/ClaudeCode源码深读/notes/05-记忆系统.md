## 0. 反直觉总纲

**没有向量数据库，没有 KV 存储**。长期记忆是纯 Markdown 文件；`MEMORY.md` 索引常驻上下文换 O(1) 的"知道有什么"；相关性靠 Sonnet 读 frontmatter 清单做选择。六条链路：memdir 文件记忆 / findRelevantMemories 查询召回 / extractMemories 每轮提取 / autoDream 后台整理 / SessionMemory 会话笔记 / teamMemorySync 团队共享——共享目录约定，触发/权限/提示词各不同。

## 1. memdir：文件即记忆

物理位置 `~/.claude/projects/<sanitized-git-root>/memory/`；路径三级覆盖中**项目级 settings 被刻意排除**——防恶意仓库把记忆目录指向 `~/.ssh`（paths.ts:168-186）；validateMemoryPath 拒绝相对/根/UNC/含 null 路径（**记忆目录同时是文件写入工具的豁免白名单根**）。

入口文件 `MEMORY.md` 无条件注入系统提示，硬上限带分位数依据（memdir.ts:34-38）：

```typescript
export const ENTRYPOINT_NAME = 'MEMORY.md'
export const MAX_ENTRYPOINT_LINES = 200   // ~125 chars/line at p97
export const MAX_ENTRYPOINT_BYTES = 25_000 // p100 observed: 197KB under 200 lines
```

**四类型封闭分类法**（memoryTypes.ts:14-19）：`user/feedback/project/reference`——feedback/project 规定正文结构：规则先行 + `**Why:**` + `**How to apply:**`（"知道 why 才能在未来判断边界情况，而不是盲目遵守规则"）。WHAT_NOT_TO_SAVE 排除一切可推导内容（代码模式/架构/git 历史/CLAUDE.md 已有/临时状态）。

**召回防漂移**（TRUSTING_RECALL_SECTION）：记忆提到路径先确认存在、提到函数先 grep——"记忆说 X 存在"≠"X 现在存在"。**注释记录 eval 驱动过程：H1 假设从 0/2 到 3/3，以及"放在 When to access 小节下就掉到 0/3，位置很重要"的教训**。

## 2. findRelevantMemories：查询时召回

每轮用户输入时：扫目录 frontmatter（≤200 文件按 mtime 倒序）拼清单 → Sonnet side query 挑**最多 5 个"明确有用"**文件 → JSON schema 结构化输出 → validFilenames 过滤防幻觉文件名。两条反噪音规则：拿不准不选；工具使用文档不选但该工具的警告坑点要选（"正在使用时恰恰是这些最重要"）。

**时间维度**：mtime 转 "today / yesterday / N days ago"——**"模型不擅长日期算术，原始 ISO 时间戳不会像 '47 days ago' 那样触发陈旧度推理"**；超一天附加陈旧度警告（时间点观察非实时状态，断言前先验证）。召回不阻塞主流程：选择器 promise 预取与主模型流式输出并行，到收集点只读已 settle 结果。

## 3. extractMemories：每轮结束的兜底提取

主代理忙着干活忘了存 → stopHooks 以 fire-and-forget 触发 forked agent（**共享父对话 prompt cache**）。闭包状态：UUID 游标（上次处理到哪）+ inProgress 防重入 + pendingContext（下运行期间到达的请求，结束后跑尾随提取）。

**互斥**：主代理本轮自己写过记忆文件（assistant 有指向 auto-mem 路径的 Write/Edit）→ 后台提取整轮跳过并推游标。**权限收窄** `createAutoMemCanUseTool`：Read/Grep/Glob 不限；Bash 只放行 isReadOnly；Edit/Write 仅限 auto-mem 目录；其余全拒。提示词配合：有限轮次预算下"第一轮并行发所有 Read、第二轮并行发所有 Write/Edit"、"只用最近 N 条消息，不要花轮次 grep 源码验证"；`maxTurns:5` 硬上限；现有记忆清单预注入省掉 ls 一轮。游标推进考虑失败与压缩：失败不动下次重提；**游标指向的消息被压缩移除时回退为统计全部可见消息——否则提取会在会话剩余时间里被永久禁用**。

## 4. autoDream：睡眠时的四阶段整理

三道门从便宜到贵：时间门（≥24h，一次 stat）→ 会话门（≥5 个新会话）→ 锁。**锁的经济设计**：锁文件 mtime 即"上次整理时间"，内容是持有者 PID；获取=写 PID 使 mtime 变 now；回滚=utimes 拨回；崩溃=mtime 卡住但 PID 已死，检查 isProcessRunning 后回收，**超 1 小时即使 PID 活着也视为过期（防 PID 复用）**。

四阶段提示词（consolidationPrompt.ts:26-61）：**Orient**（ls/读索引/浏览现有 topic——目标是改进而非新建重复）→ **Gather**（按优先级：daily logs → 与代码现状矛盾的旧记忆 → 必要时窄关键词 grep 会话 JSONL"不要穷尽地读转录"）→ **Consolidate**（合并进已有文件、相对日期转绝对、删被证伪事实）→ **Prune**（MEMORY.md 修剪回 200 行/25KB，删过期指针）。做梦代理复用提取代理的权限收窄；每轮被 progress watcher 监视，完成后主转录内联汇报 "Improved N memories"。

## 5. SessionMemory 与 teamMemorySync

**SessionMemory**（会话内笔记，服务 compaction）：post-sampling hook 且只在 auto-compact 开启时注册；**触发不看消息条数看 token 增长**（首提 10K、此后每 +5K 且工具调用 ≥3，或自然停顿点）；token 阈值是硬条件（防过度提取）；权限比提取更紧——**只放行对那一个记忆文件本身的 Edit，其余一切拒绝**。

**teamMemorySync**（TEAMMEM，团队共享）：auto-mem 下 `team/` 子目录按 git remote 维度组织内共享。同步语义写在文件头：pull 服务端为准覆盖；push 只传 hash 不同的 key（增量）；**删除不传播**（本地删文件下次 pull 会恢复）。体积闸门：单文件 250KB/PUT 200KB（躲网关 413，超限拆顺序 PUT 靠 upsert-merge）；条目上限**不写死客户端而是从服务端 413 的 extra_details.max_entries 学习**。**教训样本**：无 OAuth 设备曾 2.5 天发 16.7 万次 push——永久失败置 pushSuppressedReason 彻底停试。安全双层：路径 key 拒 null/URL 编码穿越/NFKC 归一化穿越；**上传前 gitleaks 高置信规则扫描，命中不上传——密钥不出本机**。

## 6. 可借鉴清单（对讲透Agent/自有记忆系统）

1. **索引常驻+按需召回**：MEMORY.md 200 行索引换 O(1) 知道有什么，topic 文件小模型选择器召回——比向量库轻一个量级且可调试
2. **四类型 + Why/How 结构**：feedback/project 带 why 是未来边界判断的依据
3. **相对时间格式**："47 days ago" 触发陈旧度推理，ISO 不触发
4. **互斥提取**：主代理写过记忆则后台跳过——双写者协调的最简方案
5. **mtime 当锁**：文件系统原语足够，别上分布式锁
6. **eval 驱动的提示词迭代记录在注释**——记忆读写行为是被测产品功能，不是存起来再说
7. **删除不传播 + 服务端学习上限**——同步协议的保守取向
8. **与本项目互锚**：本卡记忆设计与 openclaw 的跨会话记忆、claw-code 的 CLAUDE.md→CLAW.md→AGENTS.md 祖先链构成三案对照；讲透模型宇宙 Part IV"建调改用"的记忆章可直接引用
