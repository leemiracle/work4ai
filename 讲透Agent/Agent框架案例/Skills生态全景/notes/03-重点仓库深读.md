## A. 官方厂牌

### A1. anthropics/skills —— 170,317★（生态源仓，不在 topic 榜）

- **定位**：Claude 官方技能系统 + 规范参考实现。created 2025-09-22，topics 只有 `agent-skills`（topic 盲区铁证）。
- **结构**（README）：`skills/`（官方技能样例：Creative & Design / Development & Technical / Enterprise & Communication / Document Skills）+ `spec/`（规范）+ `template/`（模板）。
- **要点**：样例技能已内置 Claude.ai 付费计划；API 侧走 `/v1/skills`；模板即 `template-skill`。官方 pdf/xlsx skill 用 Python 脚本处理文档——scripts/ 是"杀器"（agent 直接 spawn 进程，不靠 LLM 模拟）。
- **对照**：中文侧评论（iaieye 2026-05）称官方 frontend-design skill 安装量 277k+。

### A2. openai/skills —— 25,028★（不在 topic 榜）

- **定位**："Skills Catalog for Codex"——OpenAI 对 SKILL.md 标准的官方目录响应。48 小时跟进的实物证据。

### A3. google/skills —— 18,482★

- **定位**：Google 产品线技能全集（Cloud/GKE/Gemini/BigQuery/Agent Platform）。
- **组织方式**：按产品分类的 solution skills（如 RAG for enterprise search using GKE and AlloyDB）+ Agent Platform 全生命周期（endpoint/registry/tuning/eval flywheel/prompt management）。
- **分发**：`npx skills add google/skills` 向导式选装。开发中状态（README NOTE）。

### A4. microsoft/skills —— 2,919★

- **定位**：Azure SDK / AI Foundry 技能 + custom agents + AGENTS.md 模板 + MCP 配置，"Context-Driven Development"。
- **规模**：175 skills，**语言后缀制**（Core 11 / Foundry 11 / Python 39 `-py` / .NET 28 `-dotnet` / TS 25 `-ts` / Java 25 `-java` / Rust 7 `-rust`）。
- **工程亮点**：① evals 双 CI（test-harness + skill-evaluation）；② Skill Explorer 网站一键装；③ README 明确警告 **"Loading all skills causes context rot"**——官方也承认技能装载有 attention 稀释代价，"只装当前项目必需的"。
- **多工具共享**：`.github/skills/` 为主，symlink 到 `.opencode/skills`、`.claude/skills`。

### A5. cloudflare/skills —— 2,671★

- **定位**：Developer Platform 全家桶（Workers/KV/D1/R2/Agents SDK/Durable Objects/sandbox/wrangler/web-perf）。
- **双形态**：skills（对话触发自动加载）+ **commands**（`/cloudflare:build-agent`、`/cloudflare:build-mcp` 用户显式调用）——同仓演示了 skill 与 slash command 两种交付形态。
- **价值**：README 的跨工具安装路径表是本系列笔记 02 §3 的一手来源。

### A6. android/skills —— 6,823★

- **定位**：Google Android 官方。**生态里最清晰的"选题方法论"**：
  > "Our Android skill development focuses on use cases and workflows **where evaluations show LLMs underperform**. We aren't prioritizing well-established areas where LLMs are already proficient."（README）
- 即：技能只补 evals 证实的短板（如 R8 分析），不重复模型已熟练领域（基础 Compose 规范）。**这是"何时值得写 skill"的官方判据**，与 microsoft 的 context rot 警告一体两面。
- 分发：android CLI（`android skills add --all`），默认装给 Gemini/Antigravity；Apache 2.0；暂不接受社区 PR。

### A7. google-gemini/gemini-skills —— 3,912★

Gemini API/SDK/模型交互技能，Google 双仓布局（google/skills 面向云平台，此仓面向 Gemini 生态）。

## B. 方法论框架

### B1. obra/superpowers —— 273,749★（榜首，现象级）

- **定位**：完整软件开发方法论，Jesse Vincent（obra）作。"agentic skills framework & software development methodology that works."
- **工作流**（README）：不直接写码 → 榨出 spec → 分块给人签核 → 生成"热情但没判断力的初级工程师也能执行"的 plan（强调真红绿 TDD/YAGNI/DRY）→ **subagent-driven-development** 逐任务执行+审查，"自主跑数小时不偏航"。
- **安装矩阵**：Claude Code（官方 marketplace `superpowers@claude-plugins-official`）/ Antigravity / Codex App+CLI（**openai/plugins 官方市场**）/ Cursor / Devin / Factory Droid / Gemini CLI / Copilot CLI / Grok Build / Kimi Code / OpenCode / Pi / Hermes——**14+ harness 通吃**，本身就是 SKILL.md 可移植性的最强实证。
- **商业层**：企业支持 sales@primeradiant.com——方法论开源+服务收费模式。
- **对照**：与 [`../../deepseek-harness插件化框架/`](../../deepseek-harness插件化框架/) 的 dsh 插件体系同一关切（工程纪律注入 agent），但 superpowers 用纯 SKILL.md 而非插件框架实现。

### B2. addyosmani/agent-skills —— 88,413★

- **定位**：Addy Osmani（Google Chrome 团队）的"production-grade engineering skills"。
- **结构**：8 个 slash commands 映射生命周期：`/spec`(定义)→`/plan`(拆原子任务)→`/build`(一次一片)→`/test`(测试即证明)→`/review`→`/webperf`→`/code-simplify`→`/ship`；命令自动激活对应 skills。
- **亮点**：`/build auto` 一次批准后自主跑完所有任务——"移除的是人肉步进，不是验证"：每任务仍 test-driven 独立提交，失败/高危即暂停。

### B3. Leonxlnx/taste-skill —— 77,813★

- **定位**："The Anti-Slop Frontend Framework"——反 AI 垃圾审美，"gives your AI good taste, stops generic slop"。
- **商业形态**：完整 sponsor 矩阵（IMG.LY/animations.dev/React Bits/Vercel OSS Program）+ tasteskill.dev 站点——**单技能做成产品**的极致案例。

### B4. antfu/skills —— 5,771★（实验标杆）

- **定位**：Anthony Fu 的个人技能集 + **"从官方文档自动生成 skills 并保持同步"的 POC**（README 自称 proof-of-concept）。
- **三来源模式**：① Hand-maintained（opinionated：antfu/antfu-design）② **文档生成**（vue/nuxt/pinia/vite/vitepress/vitest/unocss/pnpm ← 官方 docs 仓库，unopinionated but tilted）③ Vendored（同步外部官方 skills 如 slidev）。
- **意义**：技能生产的自动化管道方向——文档源 → SKILL.md 生成 → 人工微调 → 同步。若成立，SDK 文档 skills 化（赛道 B）可规模化。

## F. 观察合成

1. **官方仓的三个共同动作**：挂 `npx skills add` 徽章 / 按产品线或语言后缀组织 / 配 evals CI（microsoft 双工作流）——registry 时代的"发行纪律"。
2. **方法论 > 单技能**（star 结构）：superpowers/addyosmani/taste-skill 三巨头全是"工作方式改造"而非"工具教学"。
3. **中文生态三形态**：创作者人设技能库（归藏/卡兹克）+ 搬运镜像商店（anbeime）+ 大厂治理基建（讯飞）。
4. **单技能也能产品化**（taste-skill 77k★ + sponsors）——skill 即 content，内容创业新单元。
