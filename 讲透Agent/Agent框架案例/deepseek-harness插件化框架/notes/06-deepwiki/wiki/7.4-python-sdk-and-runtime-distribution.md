The DeepSeek Harness (DSH) Python ecosystem provides a high-level interface for driving agentic workflows from Python. It consists of two primary components: the `deepseek-harness-sdk` (the client library) and the `deepseek-harness-runtime-bin` (the platform-specific execution environment). This architecture allows Python users to leverage the full Node.js-based agentic capabilities of DSH without requiring a local Node.js installation.

## Architecture & Data Flow

The SDK operates as a thin wrapper that spawns the DSH runtime as a subprocess and communicates via a JSON-RPC protocol over `stdio`. The runtime itself acts as a host for the Cordis plugin system, providing the agent loop, tool execution, and LLM adapters.

## The Runtime Distribution (`deepseek-harness-runtime-bin`)

The runtime is distributed as platform-specific wheels containing a single-file executable (SEA) created using `@yao-pkg/pkg`. This executable bundles the Node.js runtime, the Cordis framework, and a curated set of plugins.

### Runtime Carriers
1.  **EXE (Production):** A single-file Node executable named `dsh-jsonrpc-agent-pkg-<platform>-<arch>`. It includes a `/snapshot` virtual filesystem (VFS) to hold ESM modules without transpilation [python/sdk-runtime/README.zh.md:9-11](), [.agents/notes/implemented/architecture/2026-07-10-single-file-executable-sdk-runtime-distribution.md:17-20]().
2.  **Node (Dev-only):** A full deployment closure under `runtime/node/` used for local development. It is triggered by setting `DSH_RUNTIME_MODE=node` [python/sdk-runtime/README.zh.md:12-12]().

### Zero-Config Design
The runtime requires a configuration to boot. If the user provides no explicit `cordis.yml`, the SDK injects a default configuration located in the runtime package [python/sdk-runtime/README.zh.md:31-31](). This default config includes:
*   `@deepseek-ai/dsh-sdk-jsonrpc-server`: The stdio gateway [python/sdk-runtime/README.zh.md:31-31]().
*   `llm-deepseek`: The official DeepSeek adapter [python/sdk-runtime/README.zh.md:31-31]().
*   `tool-bash-persistent`: Persistent shell state across turns [.agents/notes/implemented/feature/2026-07-29-persistent-bash-str-replace-editor.md:7-12]().
*   `tool-str-replace-editor`: String replacement tools for efficient file editing [.agents/notes/implemented/feature/2026-07-29-persistent-bash-str-replace-editor.md:13-21]().

## Internal Python Protocol (`code-runtime-python`)

When the agent executes Python code (e.g., via `run_code`), it spawns a CPython subprocess. The host (Node.js) and the Python child communicate via a versionless JSON-lines protocol on file descriptor 3 (`PROTOCOL_FD = 3`) [packages/code-runtime/code-runtime-python/src/protocol.ts:10-18]().

### Wire Protocol Frames
The protocol defines several message types for synchronization and resource management:
*   `BootMessage`: Sent by the host to apply resource limits (`cpuSeconds`, `addressSpaceBytes`) and declare namespaces [packages/code-runtime/code-runtime-python/src/protocol.ts:46-61]().
*   `CallMessage`: Sent by Python to invoke host-side tools (e.g., `await tools.name(args)`) [packages/code-runtime/code-runtime-python/src/protocol.ts:74-85]().
*   `LogMessage`: Streamed output from the Python process, including truncation markers if `maxLogBytes` is exceeded [packages/code-runtime/code-runtime-python/src/protocol.ts:91-105]().
*   `DoneMessage`: Signals program settlement, carrying the final `value` or an `error` (traceback) [packages/code-runtime/code-runtime-python/src/protocol.ts:124-128]().

**Sources:** [packages/code-runtime/code-runtime-python/src/protocol.ts:1-155](), [packages/code-runtime/code-runtime-python/tests/protocol.spec.ts:11-110]()

### Build Implementation Details
*   **Legacy Deploy:** The builder uses `pnpm deploy --legacy` to create a hoisted, symlink-free closure for the SEA binary [scripts/build-exe-for-python-sdk.ts:1-7](), [.agents/notes/implemented/architecture/2026-07-10-single-file-executable-sdk-runtime-distribution.md:44-47]().
*   **Native Addons:** For Linux, `node-pty` is rebuilt against `manylinux_2_28` to ensure compatibility across distributions [.github/workflows/build-exe-for-python-sdk.yml:185-195]().
*   **Platform Matrix:** The system targets `linux-x64`, `linux-arm64`, and `macos-arm64` [scripts/build-exe-for-python-sdk.ts:53-56](), [.github/workflows/build-exe-for-python-sdk.yml:89-109]().
