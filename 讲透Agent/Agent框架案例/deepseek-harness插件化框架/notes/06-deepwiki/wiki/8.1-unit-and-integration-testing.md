The DeepSeek Harness (dsh) testing infrastructure is built on Vitest and designed to enforce a strict "100% per-file" coverage requirement while managing the complexities of a monorepo that spans multiple operating systems and process-global state [vitest.config.ts:10-13](). The system distinguishes between thread-safe logic and process-bound integration tests to ensure deterministic results in high-concurrency CI environments [vitest.config.ts:114-116]().

## Vitest Configuration & Project Split

The test runner is partitioned into two primary projects within `vitest.config.ts` to balance execution speed with isolation requirements [vitest.config.ts:137-160]().

### Thread-Safe vs. Process-Bound
Most packages run in the `thread-safe` project using forked workers for stability [vitest.config.ts:141-143](). However, suites that manipulate process-global state, timing-sensitive I/O, or specific Node.js process APIs are isolated in the `process-bound` project to avoid interference under aggregate gate contention [vitest.config.ts:114-116, 153-156]().

| Project | Pool | Criteria for Inclusion |
| :--- | :--- | :--- |
| `thread-safe` | `forks` | Pure logic, Cordis plugin composition, and stateless utilities [vitest.config.ts:141-143](). |
| `process-bound` | `forks` | `session-persistence-jsonl`, `subagent-acp`, `time-context`, `llm-pi-ai`, and `app-boot` [vitest.config.ts:117-126, 153-156](). |

### Platform-Specific Gating
The configuration dynamically excludes suites based on the host OS. Bash-requiring packages (e.g., `bash-local`, `tool-bash`) are excluded on Windows, while Windows-only sources (like `sandbox-windows-acl`) are excluded from Linux coverage denominators to maintain the 100% gate [vitest.config.ts:22-35, 57-65]().

## Quality Gates & Coverage Requirements

DSH enforces a strict quality gate where every source file must reach 100% coverage [vitest.config.ts:10-12]().

*   **Uncovered Locations:** A custom reporter (`scripts/coverage-uncovered-locations.cjs`) prints exact `path:line:col` records for any missing branches or statements [vitest.config.ts:14]().
*   **Coverage Exemptions:** Specific "heavy" suites or platform-unreachable code can be exempted via `scripts/coverage-exempt.ts` to prevent CI timeouts or false negatives on non-native hosts [vitest.config.ts:7, 100-106]().
*   **In-Job Partitioning:** To handle the large volume of tests, coverage is partitioned into shards (e.g., 8 shards on 16-core runners) to optimize wall-clock time without saturating host memory [.agents/notes/implemented/process/2026-08-18-in-job-partitioned-coverage.md:21-23]().
*   **Windows Coverage:** Native Windows CI (`windows-native` job) independently enforces coverage for Windows-specific sources like `sandbox-windows-acl` and `windows-inspector.ts` [.agents/notes/implemented/process/2026-08-08-native-windows-pull-request-ci.md:11-12,57]().

Sources: [vitest.config.ts:7-14, 57-64](), [.agents/notes/implemented/process/2026-08-08-native-windows-pull-request-ci.md:19-21]()

## Snapshot Testing & Session Logs

DSH utilizes snapshot testing to verify complex agent behaviors and protocol exchanges.

### Session Event Snapshots
Agents produce an append-only `SessionEvent` log. Tests verify these logs against `.jsonl` snapshots to ensure the stability of the agent loop, tool execution, and message derivation [examples/headless-agent/tests/snapshots/advanced-toolchain/session.jsonl:1-10](). These snapshots include `turn/start`, `step/start`, and `user/message` events with deterministic timestamps and IDs where possible [examples/headless-agent/tests/snapshots/advanced-toolchain/session.1.jsonl:1-8]().

### ACP Snapshot Harness
The `@deepseek-ai/dsh-acp-snapshot` package provides a suite factory for testing the Agent Client Protocol (ACP). It supports three modes:
1.  **Replay:** Runs the agent against existing snapshots using `llm-replay` [examples/acp-agent/tests/acp.snapshot.ts:27]().
2.  **Record:** Executes the agent against real LLM APIs to generate new transcripts [examples/acp-agent/tests/acp.snapshot.ts:25-26]().
3.  **Refresh:** Rewrites expected outputs without re-running model calls to update non-functional formatting [examples/acp-agent/tests/acp.snapshot.ts:27]().

## Test Support Packages

The monorepo includes specialized packages to facilitate hermetic testing:

*   **`llm-mock-server`:** Provides a local server that implements LLM provider APIs for unit tests.
*   **`llm-replay`:** Intercepts LLM requests and provides deterministic responses from saved snapshots [examples/acp-agent/tests/acp.snapshot.ts:46]().
*   **`acp-snapshot`:** A factory for scenario-based testing of ACP-compliant agents, handling temp directory management and fixture seeding [examples/acp-agent/tests/acp.snapshot.ts:10-16]().

### Workspace Fixtures
Tests often require specific filesystem states. Functions like `prepareFsSearchWorkspace` seed temporary directories with fixed `mtimes` so that tools like `ripgrep` (which might sort by modified time) produce deterministic results [examples/acp-agent/tests/acp.snapshot.ts:113-124]().

Sources: [examples/acp-agent/tests/acp.snapshot.ts:10-19, 113-124]()

## CI Infrastructure & Failover

Testing is orchestrated via GitHub Actions, utilizing a mix of hosted enterprise pools and self-hosted runners [.agents/notes/implemented/process/2026-07-26-ci-failover-runbook.md:9-13]().

*   **Platform-Specific Failover:** The `DSH_CI_FAILOVER_LINUX` and `DSH_CI_FAILOVER_WINDOWS` variables allow responders to retarget jobs to in-house pools (`vm-backup` for Linux, `dsh-win-ci` for Windows) without merging code if hosted pools degrade [.agents/notes/implemented/process/2026-07-26-ci-failover-runbook.md:13, 33]().
*   **Wine Blocking Gate:** A required `windows` job runs on `ubuntu-latest` using Wine to provide a fast win32 toolchain signal without consuming Windows runner capacity [.agents/notes/implemented/process/2026-08-08-native-windows-pull-request-ci.md:9, 15]().
*   **Native Windows Gate:** The `windows-native` job runs on `dsh-windows-2025-16core` to prove NTFS, DACL, and ConPTY behavior that Wine cannot simulate [.agents/notes/implemented/process/2026-08-08-native-windows-pull-request-ci.md:9, 17]().
