# 01 · 接缝模式与能力矩阵

> 对应 `packages/README.md`、`.agents/notes/implemented/architecture/2026-06-13-capability-seams.md`、各能力组
> 行号钉版 `47f943859b`

## 1. 三角色接缝（本仓库最重要的抽象）

一个 **capability seam（能力接缝）** = 三个角色合起来的完整能力，缺一不可：

| 角色 | 形态 | 约束 |
|---|---|---|
| Service Definition | Cordis `Service` 子类 + `ctx.<key>` 声明 + 词表类型 | **绝不能是裸 TS interface** |
| Service Provider | `super(ctx, '<key>')` 的实现插件 | 单槽接缝二次注册即 throw；注册表型暴露 `registerX()` 返回 disposer |
| Consumer | `export const inject = [...]`，只 import Definition | **永不 import provider 类型** |

规则出处：`AGENTS.md:109`（"A capability seam comprises Service Definition / Service Provider / Consumer roles. It is complete, never one role"）。

## 2. 标准样例：shell 接缝

```text
Definition  packages/shell/shell/src/index.ts:65   abstract ShellExecutor (ctx.shell)
Provider    packages/shell/bash-local              LocalBashExecutor, inject=['subprocess']
Provider    packages/shell/bash-sandbox            继承 local, 注入沙箱包装 —— 纯换实现
Consumer    packages/shell/tool-bash:242           bash 工具, inject=['tools','shell','systemPrompt','shellEnv']
```

bash-local 自己是 subprocess 接缝的 Consumer——**接缝消费接缝**，形成能力供给链。

## 3. 换 Provider = 换产品形态（E2B 样例）

挂载 `e2b`（`ctx.e2b`，独占一个远程沙箱）+ `fs-e2b`（注册 `ctx.fs`）+ `subprocess-e2b`（注册 `ctx.subprocess`）：

- `bash` 工具远程执行（它只 inject `subprocess`）
- PTY 终端远程（`spawnTerminal` 原语有 E2B 实现）
- LSP 远程（`lsp-stdio` inject `['fs','lsp','subprocess']`）
- glob/grep 远程（`tool-fs-search` 经 `ctx.subprocess` 跑打包的 ripgrep）

**所有工具 schema 零改动**——文件系统与进程共居一个远程 Linux 世界（"portable execution world"，`packages/fs/README.md:17`）。

## 6. 设计要点提炼

1. **接口即插件服务**——TS interface 无法热替换、无法声明合并、无法在 ctx 上被发现；Service 可以。
2. **Consumer 的无知是力量**——工具不知道自己在本地还是远程沙箱跑，才能两者都对。
3. **单槽 vs 注册表**两种接缝形态都有（shell 单槽、llm/subagent 注册表），按"能力天然几个实现"选。
4. **能力事件挂策略**（`fs/write-intent` 等）——策略与实现正交。
