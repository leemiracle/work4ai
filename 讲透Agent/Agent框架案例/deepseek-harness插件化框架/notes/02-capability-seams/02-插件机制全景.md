# 02 · 插件机制全景：从 Plugin 形态到自修改运行时

> 对应 `vendor/cordis/`、`vendor/loader/`、`vendor/include/`、`vendor/hmr/`、`packages/core/scope/`、`packages/extensions/`、`packages/preset/`、`docs/cordis-primer.md`、`docs/cordis-tutorial/`、`docs/cookbook/`
> 行号钉版 `47f943859b`。前一篇（01-接缝模式）讲"插件提供什么能力"；本篇讲"插件这个机制本身"。

## 1. 插件是什么：三种入口形态

权威定义在 vendored 框架（`vendor/cordis/src/registry.ts:91-133`）：

| 形态 | 签名 | 典型用法 |
|---|---|---|
| Function | `(ctx, config) => void` | 教程第一个插件：`export const name = 'hello'; export function apply(ctx) {}` |
| Constructor | `new (ctx, config)` | `Service` 子类，构造器里自动注册为 `ctx.<name>`（`vendor/cordis/src/service.ts:42-59`） |
| Object | `{ apply(ctx, config) }` | 判定标准就是"有 `apply` 函数的对象"（`registry.ts:8-10`） |

共享元数据（`registry.ts:100-111`）：`name`（显示名/fiber 诊断）、`Config`（**Standard Schema v1** 校验器，启动前跑）、`inject`（必需服务；不全则插件不加载）、`provide`、`intercept`。

仓库规则：**命名导出 `name/inject/apply`、禁止 default export**——这是从事后剖析（`docs/postmortem/0001-acp-default-export-drops-inject.md`）学来的：default export 会静默丢掉 `inject` 元数据。子路径条目用 `name: '@deepseek-ai/dsh-tool-subagent-control/list-agents'` 行挂载。

package.json 里**普通插件不需要 `dsh` 字段**——Cordis 只看模块导出形状。`dsh` 字段属于组合角色：`dsh.bundle`（可安装 bundle）、`dsh.profile`（profile 清单）、`dsh.client`（浏览器半边插件）。

## 2. Context 与 Fiber：生命周期

- `Context` 是**代理**：属性读走 service 解析器；`extend()/isolate()/intercept()` 造作用域子上下文而不改父（`vendor/cordis/src/context.ts:99-145`）。
- 每次 `ctx.plugin()` 铸一个 **Fiber** = 一次插件应用运行时（`vendor/cordis/src/fiber.ts:184-198`）。状态机：

```text
PENDING → LOADING → ACTIVE → UNLOADING → DISPOSED
                 ↘ FAILED
```

- **PENDING 等 inject**：`_refresh()` 从被注入实现的 fiber uid 算出"epoch"，全部可解析才激活（`fiber.ts:611-623`）——**加载顺序由服务可用性驱动，与文件顺序无关**。
- 激活 = `internal/config` 瀑布 → schema 校验（`ValidationError` 聚合 standard-schema 问题）→ 执行插件体；构造器插件额外跑 `[Service.init]` 钩子。
- `fiber.update(config)` 走 `internal/update` 瀑布（HMR 可否决）再重启；`fiber.restart()` 用当前配置重挂。
- 本地加固（vendored 修改，`vendor/README.md:38-39`）：owner 处于 `UNLOADING` 时拒绝新 effect；同步 setup 失败立即回滚；`Fiber.update()` 返回瀑布结果（可等待的重启带同步校验）。

## 3. cordis.yml：配置即数据

### 3.1 行与条目

配置文件 = **顶层 YAML 数组**（`vendor/include/src/index.ts:261-263` 强制）。每行 `EntryOptions`（`vendor/loader/src/config/entry.ts:9-22`）：`id`（树内稳定 id，缺省随机 8-hex）、`name`（模块说明符：相对路径/npm 包/子路径/绝对路径/`cordis:` 内建）、`config`、`group`、`disabled`、`inject`、`intercept`、`isolate`。

### 3.2 `!!js` 表达式（延迟求值是核心设计）

include 注册 YAML schema 扩展，`!!js` 标量构造成 `{__jsExpr}` 节点**原样往返**（parse/dump/write-back 都不丢）——这正是 `dsh --dump-config` 能打印"未求值的组合"的原因。求值是 `with(ctx){ return eval(expr) }`，但**作用域刻意收窄**（`docs/cordis-primer.md:38`）：

- 行的 `config` 在**该插件声明的注入激活之后、针对该插件上下文**求值 → `port: !!js ctx.myAppStartup.port ?? 8080` 可用；
- `disabled` 在**每次挂载决策时针对 loader 上下文**求值；
- Include/Group 载体的 config **永不求值**——嵌套行的 `!!js` 保持懒绑定到各自的 fiber。

真实样例：`cwd: !!js process.cwd()`、`compression: !!js "process.env.DSH_SNAPSHOT === undefined ? 'zstd' : 'none'"`、平台门控 `disabled: !!js process.platform === 'win32'`（`packages/bundle/base/cordis.patch.yml:180`）。

### 3.3 patch 算法：整键替换、无深合并

`applyEntryPatches`（`vendor/include/src/index.ts:58-128`，专门导出给配置工具，"组合、flag 推导、config dump 与真正启动的东西不会漂移"）：

- patch 按 `id` 命中行，`insert` 插入新行（插入的行立即入索引，同列表后续 patch 可再命中它）；
- 非 insert patch 校验 `name`（不匹配警告跳过）；**config 覆盖 = 整体替换该行 config，不做深合并**（`packages/bundle/base/README.md:21`）。

四层叠加顺序：bundle patch（按 `dsh.profile.bundles` 序）→ profile `cordis.patch.yml` → `$DSH_HOME/cordis.patch.yml` → `--patch` overlay（argv 序）。**后层胜出**。

### 3.4 schema 校验与 isolate/group

- 插件导出 `interface Config` + 同名 **schemastery** schema（实现 Standard Schema 接口，`fiber.ts:50-62` 里跑校验）；缺字段给默认、非法值 fail-loud。
- `isolate: Dict<true|string>` 给条目独立服务作用域：`true` = 条目私有 `LocalRealm`，字符串 = 共享 `GlobalRealm`（多条目同域）（`vendor/loader/src/config/isolate.ts:48-88`）； realm 在最后一个引用者消失时 GC。
- group 行 = 给"一个 provider + 它的 consumers"整体一个 isolate realm 的方式（`packages/boot/app-boot/src/index.ts:505-510`）。

## 4. Loader 与 HMR

- `Loader extends EntryTree`（`vendor/loader/src/index.ts:65`）：条目 store 按 id、`import(name)`（`cordis:` 内建 → 内部 ModuleLoader → URL/bare import）。发布 `loader/config-update`、`loader/entry-init`、`loader/partial-dispose`、`loader/patch-context` 事件。
- **自处置检测**：插件在 loader 控制之外处置自己的 fiber → loader 把该行翻成 `disabled: true` 并持久化（`index.ts:117-157`）——运行时自我修改会写回配置，不留幽灵状态。
- `Entry.update()` **事务性带回滚**：纯 config diff → patch + `fiber.update()`；name/inject/group 变化 → dispose + 重导入 + 重启，失败回滚到上一个插件（`entry.ts:142-246`）。
- Include = 文件承载子树：序列化 apply 队列、原子写回（tmp+rename，EACCES/EBUSY 重试）、内容变更即刷新。
- **HMR**（`vendor/hmr/src/index.ts`）：chokidar 去抖 100ms；分类三路——配置文件变更 → `include.refresh()` 串行；externals 变更 → 整树重启；模块缓存命中 → **partial reload**：分析依赖链、清除接受的 ESM/CJS 缓存、受影响的 `Plugin.Runtime` **逐 fiber 重挂**（保留旧 config 与条目绑定），重导入失败全量回滚（`:400-549`）。

### 启动接线（app-boot）

`mountRootInclude`（`app-boot/src/index.ts:486-529`）：注册 include（`HostResolvedRootInclude` 子类把 bare 说明符重定向到已安装宿主的 `bareModuleBaseUrl`，**让树外插件行可解析**）+ 固定 id 的 include 条目。`healProfilesModuleFallback` 维护扁平的 `$DSH_HOME/profiles/node_modules` 符号链接，bare 名走 Node 父级解析。

### 树外插件安装（官方唯一路径）

```sh
dsh plugin --profile <name> add <package>   # 转发给 profile 目录里的 pnpm
```

声明了 `dsh.bundle` 的包被追加进 `dsh.profile.bundles`；remove 同步移除。**git 安装的两道闸**：作者必须提供 `prepare` 脚本、用户侧 pnpm `allowBuilds` 白名单——文档原话："install 时执行该包代码的许可"（`docs/user/develop/basic/publish.md:153-178`）。**仓库内无 marketplace 机制**——发现完全靠 profile 清单 + npm。

## 5. Effect 与处置模型（"注册即 effect"的机制底座）

- `ctx.effect(execute)` 接受 disposer / disposer 的 promise / disposer 的可迭代（生成器 effect：每 yield 一个注册一个）（`vendor/cordis/src/fiber.ts:356-400`）。disposed/unloading fiber 上调用抛 `INACTIVE_EFFECT`。
- 语义：立即执行；产出的 disposer **按注册逆序**在卸载或手动调用时运行；异步 disposer 会被 await；调用两次幂等。
- `ctx.on()` 也是 effect：监听器经 `EventsService.register` 包一层 `ctx.fiber.effect`，标签 `ctx.on("<name>")`（`vendor/cordis/src/events.ts:288-302`）。
- 五种分发模式（`events.ts:32`）：`emit`（同步即发即忘）/ `parallel` / `serial`（顺序等待，可 bail）/ `bail`（同步首个非空）/ **`waterfall`**（around 中间件：最后参数 `next`，不调即否决/短路**包括内建行为**）。
- 实践规则（primer）：异步 disposer 并发执行——顺序敏感的清理要放进**同一个** disposer 里串行。

## 6. ScopedLayers：作用域注册（agent.ctx 的机制）

- `createScope(ctx, key)` 铸出带 `ScopeKey` 的子上下文，背后由一个 no-op fiber 拥有**经由它的一切注册**（`packages/core/scope/src/index.ts:104-147`）。
- 两条方向规则（`index.ts:34-39`）：**注册视图沿链向下继承**（子见祖先层、就近遮蔽）；**事件准入沿链向上扩展**（未打标监听器全局收、打标监听器匹配 key 或任何祖先）——事件上流、永不下流。
- agent loop 每个 agent 一个 scope：`this.ctx = this.scope.ctx.extend({ agent: this })`（`agent-loop/src/agent.ts:94-96`）；视图链 `agent → preset → global`。
- `ScopedLayers<L>`（`scope/src/store.ts:159-170`）是工具表/系统提示共用的注册表底座：`merge` = 全局层 + 祖先链遮蔽（同名最近胜出）；`effect(ctx, action)` 从调用上下文**同时推导可见性与 effect 归属**——在 `agent.ctx` 里注册 = 可见性落 agent 层 + 卸载权归该 agent 的 fiber。
- 部分注册**要求作用域**：`tools.presentAs()/restrict()` 在无作用域上下文调用直接 throw（`tools/src/index.ts:949,1074`）。

## 7. 自修改：agent 挂载自己的插件（packages/extensions）

四包：`tool-cordis`（模型工具）+ `cordis-host-runner`（`ctx.dynamicCordisRunner`：定义注册表 + `node:vm` 沙箱 + run 往返）+ `cordis-client-runner`（浏览器半边）+ `ui-cordis`（面板/卡片）。设计笔记 `.agents/notes/implemented/feature/2026-07-08-self-referential-cordis-toolset.md`。

- **动机**：agent 活在插件运行时里却看不见它。三个正确性问题：模型写的注册要在注册期校验、模型写的代码要会 service API（它没见过）、**一切可处置**。
- 工具词表（演化后）：`cordis_inspect`（只读巡检 services/plugins/tools/events）、`cordis_define`（语法检查后记录包，铸 `dyn-<n>`）、`cordis_run`（host 半在 vm 求值、browser 半投递页面）、`cordis_stop`（处置到静止，定义存活）、`cordis_undefine`。
- **沙箱语义**：async 函数体进全新 vm realm；全局面刻意极小（tagged write-through `console`、`harness.defineTool`、编码原语）；`process`/`Buffer` 为 undefined；挂载的插件得到**白名单上下文门面**——service 读取需声明 `inject`，保留 Cordis 激活/卸载语义。文档诚实声明："vm 隔离的是意外全局污染……这是与 bash 等价的信任、不是安全边界"。
- **生命周期**：所有临时插件是工具插件下一个 `cordis-dynamic` 组的子节点——普通 fiber 处置就覆盖工具集重载/卸载。**仅进程内存**：不落盘、不改 cordis.yml、重启不存活。
- **跨挂载组合**：挂载 A `provide` `foo`，挂载 B `inject: ['foo']` 才激活；卸 A 则 B 回 PENDING、注册全部回卷——动态插件间也保持依赖语义。
- **生成的目录**：`api-catalog.ts`/`client-catalog.ts` 与文档同一 AST 走查生成、新鲜度门禁（`verify-cordis-api`）——"模型读的数据与渲染的文档不能分叉"。
- **被否决的方案**：每能力一个结构化注册工具（`cordis_register_tool` 等）——"一个词表（cordis 插件）覆盖现在和将来的所有 effect"。

## 8. Preset 与 Persona：每会话组合

- **preset** = 一个目录 + 一份 `agent.cordis.yml`（普通 loader 行列表）。roster **每进程一次**在常设 scope 下挂载，每个会话把自己的 agent scope key **parent 到挂载点**（`packages/preset/agent-presets/README.md:5`）——子代视图 `agent → preset → global`。
- 挂载只在 agent 工厂 `setup(agentCtx)` 里、**发布之前**——被拒的组合回滚整个创建。每代盖 mtime+size 章：运行中会话活过编辑、后续会话拿新一代。
- bare 包名**从宿主组合解析**（用户 home 里的 preset 走不到 harness node_modules）；preset 子树 `write()` 覆写为 no-op——"preset 文件是输入、永不是持久化目标"。
- **信任分级**：`trust: 'system' | 'user'` 由发现根继承，`preset.yml` **不可写** id/trust（"否则本地自制的 preset 可以把自己命名为出厂集"）。关键立场（README:135）："**user preset——无论人写还是 agent 写——携带与 shell 访问等价的信任；trust 字段是为了让消费者呈现差异，不是为了强制**"。
- **persona** = 把 agent 人格做成可组合行：单 agent 遮蔽 `deployment:persona` 段；scope-only（全局挂载即冲突报错）；`complete: true` 可在组装后作为唯一系统提示段恢复。"没有这一行，preset 能改 agent 的工具却改不了它的身份"。

## 9. 插件作者路径（官方 cookbook）

新增工作区包清单（`docs/cookbook/adding-a-package.md`）：package.json（含 `@deepseek-ai/cordis` 同时进 peer+dev 依赖、schemastery 进依赖、精确 `files` 列表）→ tsconfig（挂 host 或 client 聚合，**永不两边**）→ `src/index.ts`（service 默认导出或 name/inject/apply/Config）→ README（服务 API/事件/扩展点 + **必含 `## Model Experience`（What the model sees / Token effect / KV Cache effect 三个 H4）+ `## Known Limitations and Deferred Work`**，两个 verifier 脚本强制）→ 验证命令 `doc-sync && constraints && typecheck && lint && build && hygiene`。

工具插件最小形状（`adding-a-tool.md`）：`inject: ['tools']` + `ctx.tools.register(defineTool({...}))`；"注册即 effect：处置插件 fiber 即注销工具"。

四种扩展形态对比（`extension-cookbook.md`）：**native hook 就是普通 Cordis 插件**（无外部协议）；UI 插件、外部协议驱动（ACP 为例）、可运行叶子。feature→mechanism 映射表让微内核主张可检验。

## 10. Skills 与 Hooks：插件的两条"轻量近亲"

| | 插件 | Skill | Hook |
|---|---|---|---|
| 本质 | 运行时里的代码 | **数据**（SKILL.md + frontmatter） | **外部进程** + 线协议 |
| 贡献 | 服务/事件/effect/工具 | 调用期注入的指令（`<skill_content>`） | 映射到既有扩展点的退出码/stdout 编码 |
| 注册 | cordis.yml 行 | `ctx.skills.registerProvider`（provider 注册表，同 ScopedLayers 形状） | 桥插件解析 `hooks.json` 一次 |

| 定位 | 一等公民 | "经注册接缝在调用时贡献指令，从不在运行时执行" | "原生插件能做这桥做的一切——桥只是兼容路径" |

## 11. Jobs / Workflow / Code-runtime：插件托管"离环代码"的三种模式

共同模式：**插件行拥有生命周期与 effect（主环上），工作本体跑在 worker/受跟踪 job 里，寿命绑定 owning fiber/scope**——插件行 HMR/卸载可靠地取消并静止离环工作。

- **jobs**（`ctx.jobs`）：后台作业注册表，`start(spec)` 校验 controller/spec/owner 后才提交；注册 **owner-relative over dsh-scope**（"无自己 controller 的组合不能在别人的控制器上启动后台工作"）；进程内契约。
- **workflow-worker-thread**：每次 run 一个 Node worker 线程——"同步脚本不能阻塞 harness 事件环、无视取消的脚本可以连同 worker 一起终止。**不是安全沙箱**"。空环境（环境凭据不穿越）、结构化克隆 + 纯 JSON 校验、`terminate()` 兜底；lossless-JSON 值边界拒绝奇异原型/函数/环/`__proto__`。
- **code-runtime**（`ctx.codeRuntime`）：定义"针对一组宿主异步 binding 跑一段模型写的程序并回报 `{value, logs, error?}`"而不定方式；每个程序结果**必 resolve**（error 是字段不是 reject）；程序是敌意对等体；**两次运行间无状态存活**；binding 全局名语言可移植。

## 12. 设计要点提炼

1. **一个词表、四条挂载路径**：静态 loader 行、preset 常设挂载、模型挂的临时插件（vm + `cordis-dynamic` 组）、浏览器半边插件（`loader.create`）——全部共享 Plugin/fiber 语义。
2. **配置是数据、求值要晚**：`!!js` 节点穿过 parse/dump/write-back，在**最窄的正确作用域**求值——组合的可检查性与求值的上下文正确性兼得。
3. **处置是设计不变量**：从逆序 disposer 到 ScopedLayers 生成器 effect 到 worker terminate+宽限期，每种扩展形态都有定义好的静止路径——HMR、preset 重组合、动态卸载全部因此安全。
4. **信任是组合性的、不在插件层强制**：preset trust 呈现差异、动态挂载 bash 等价、git 安装要 allowBuilds——插件机制保证**可处置可巡检**，约束在信任平面（见 03-trust 笔记）。
5. **加载顺序 = 服务可用性顺序**：没有手写的 bootstrap 依赖表，inject 声明即依赖图。
