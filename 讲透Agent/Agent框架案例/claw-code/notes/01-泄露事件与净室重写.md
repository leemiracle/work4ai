## 2. "净室"是怎么净的

- **法律姿势**：不复制任何专有源码，只重实现架构模式——README 明确声明不主张对原 Claude Code 源材料的所有权、与 Anthropic 无关联（README.md:296-299）。这是 Wine/ReactOS 走过的同一条路；Anthropic 对该仓未发出公开法律动作（WaveSpeed 2026-04-02 报道口径）。
- **工程姿势**：Python 侧不是"翻译"而是"镜像"——`src/reference_data/` 保存 29 份子系统 JSON 快照（commands/tools/services...），`parity_audit.py` 诚实报告"archive 不可用就不能比较"（parity_audit.py:87-88）。**先建坐标系，再补实现**——魔都水滴称之为"镜像优先的移植工作区"。
- **组织姿势**：Python 一夜版（4-01）→ Rust 正典（4-03 检查点）→ 语言迁移本身成为路线图：README 从"Python 优先、Rust 在路上"翻转为"Rust 正典、Python 降为伴生参考区"（README.md:104-111）。

## 3. 为什么最后变成"博物馆"

PHILOSOPHY.md 的自白（:3-7）：*“如果你只盯着生成文件看，你看错了层。Python 重写是副产品，Rust 重写也是副产品。真正值得研究的是**生产它们的系统**：clawhip 协调循环，人类给方向、自主爪子干活。”*

三层系统：
1. **OmX**（oh-my-codex）：工作流层——把一句话指令变成可重复的工作协议（planning 关键词/执行模式/持续验证循环/并行多 agent）；
2. **clawhip**：事件与通知路由层——盯 git/tmux/issue/PR/agent 生命周期，**把监控与送达移出编码 agent 的上下文窗口**；
3. **OmO**（oh-my-openagent）：多 agent 协调层——Architect/Executor/Reviewer 分歧时有结构地收敛而非崩塌。

**关键判断**（PHILOSOPHY.md:59-71）：瓶颈不再是打字速度，而是架构清晰度/任务分解/品味/判断。所以 8 月的收尾动作是"让 agent 给仓库写好档案然后封存"，人去做下一个值得存在的东西（LazyCodex/Gajae-Code）。

**这是 agent 时代仓库生命周期的首个完整标本**：出生（泄露应激）→ 爆发（2h50K）→ 制度化（PARITY/gates/ledger）→ 降级（后继者分流）→ 自我归档（AGENTS.md）→ 休眠。
