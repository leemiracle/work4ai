## 1. 缺点清单（照例先泼冷水）

1. **生产不可依赖（自己承认）**：README 置顶"not the serious production project"→ LazyCodex/Gajae-Code；crates.io 包名被抢注弃用；无版本稳定承诺（WaveSpeed 04-02 判断至今成立）。
2. **巨型平铺文件 by design**：main.rs 19,831 行 / tools lib.rs 10,892 行 / commands lib.rs ~7.2K——AGENTS.md 称"组织是位置性的"，但**新人/新 agent 的导航成本全部转嫁给了 AGENTS.md 这份外部地图**；地图一旦过期（rust-analyzer 引用计数已超时未完成，AGENTS.md:51 自述），位置性组织即失效。
3. **深度换速度的净室缺口**：AutoDream/KAIROS/microcompact/44 feature flags 未实现；Team/Cron 无真调度器；MCP 是 registry 桥非端到端；LSP 是 dispatch 级；bash 深校验长期 branch-only（PARITY Lane 1）——**重写永远追不上泄露分析里最有趣的部分**。
4. **rust/README.md 规模口径过期**（自称 ~20K 行，实测 115,957）——连"信源唯一"治理也没能防住 README 腐化。
5. **max_iterations 默认 usize::MAX**：靠压缩兜底而非硬上限，配 `--dangerously-skip-permissions` 时失控成本估计不足（对比泄露版记录的 16 次硬限——净室版反而放宽了，方向存疑）。
6. **休眠无交接测试**：7 月起 6 commits，最终 release-readiness（g012）之后再无验证轮——"博物馆化"意味着**门体系的最后一轮全绿无人复跑**。

## 2. 三极对比：openclaw / dsh / claw-code

| 维度 | openclaw（插件宿主） | dsh（官方插件化） | claw-code（净室重写） |
|---|---|---|---|
| 出生 | 需求驱动（个人助手） | 官方产品 | **事件驱动（泄露应激）** |
| 规模 | 386,825★/937 TS 文件/22 包 | 219 插件包 | 1690 commits/11 crates/116K 行 Rust |
| 主循环 | agent-core 零 I/O 纯循环 | turn/step 状态机 | ConversationRuntime（压缩内嵌） |
| 扩展 | 42 挂点插件 | 插件+能力接缝 | hooks+plugins+slash 120+ |
| 安全 | 四档+pairing+net-policy | 沙箱+审批+供应链 | 五档权限+enforcer 双层+门测试 |
| 治理 | 轨迹 schema+PRISM 外挂 | 五带金字塔 | **PARITY 对拍+g 门+.omx 回执（最强）** |
| 记忆 | steering+catalog 数据 | — | CLAUDE.md→CLAW.md→AGENTS.md 祖先链 |
| 教学价值 | 产品化运维样本 | 官方工程节奏样本 | **harness 组件教材+移植方法学** |

**三者殊途同归的信号**：机器可读输出合同（openclaw 轨迹 schema / claw NDJSON）、权限拒绝回注对话（openclaw steering 与 claw 同款）、外部化监控（openclaw gateway vs claw clawhip）——**收敛证据比任何单一设计更有引用价值**。

## 3. 按件拆借清单（不整屋搬）

**直接可搬（对 work4ai / deepseek harness 系）**：
1. **PARITY.md 做机器消费文档**：差多少=测试夹具；deepseek 五仓的"冒烟"层可升级为"PARITY 对拍层"（mock 确定性剧本 + 场景→条目映射 JSON）。
2. **9-lane 并行合并表**：每道 feature+merge 双哈希+行级证据——rae/exp 系列多 agent 并行时照此汇报。
3. **门三件套**：contract 文档 + verification map + 源码树内 conformance 测试（g004 模式）。
4. **agent 自证档案**：goals.json + ledger.jsonl + 门状态机文件（.omx 模式）——比"跑完就丢"的日志可审计一个量级。
5. **拒绝回注对话**：权限/钩子拒绝一律生成 `tool_result(is_error=true)`——讲透Agent 教学可直接引 conversation.rs:505-510。
6. **压缩即 prompt 工程**：摘要后处理（剥 analysis/抽 summary/合成续接消息，compact.rs:55-94）。
7. **反 slop 三律**：main 推送封禁 / 自动化禁关 PR-issue / 文档信源 CI——任何 agent 自管仓库的起手式。
8. **Session.workspace_root 防 phantom completions**：多 lane 共享会话仓的必抄防御（session.rs:107-115）。

**观察即可**：三产品线切分（等 deepseek 系有第三产品时再套）；博物馆化收尾（等我们自己的仓库退休时再抄）。

**不要搬**：位置性巨型文件；usize::MAX 迭代上限；俄语文档（贡献者顺产但受众窄）。

## 4. 法律与伦理注脚

- 净室重写的法律正当性（只重实现模式不复制代码）在本案未被法院检验——Anthropic 沉默本身不是先例；引用本案作法律论据时须降级为"社区惯例"。
- 泄露的原始 TS 分析（AutoDream/KAIROS/feature flags）**引用需标注出自未授权快照**；claw-code 未实现它们，别把分析当实现。
- 用户侧教训：`.map` 进 npm 包=源码裸奔——**构建产物审计**应进任何发布 CI（claw-code 的 dogfood GIT_SHA 自证是同族问题的正面样本）。

## 5. 收束：这个案例在讲透Agent 宇宙的位置

- 它是 **harness 六组件的"可引用实现集"**：openclaw 讲宿主、dsh 讲官方、claw-code 讲组件解剖+治理档案。
- 它是 **agent 自管仓库的完整生命周期标本**（出生→制度化→归档→休眠）——比任何"AI 自动写代码"的宣言都更具体：2h50K 是营销，g 门+.omx 回执才是干货。
- 一句话总评：**作为产品它死了，作为教材它恰好活着——而且它自己选的（PHILOSOPHY.md:103-108：The repository is the artifact. The coordination system is the product lesson.）**
