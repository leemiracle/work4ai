# 04 · 安全平面（单操作者模型的安全工程）

> 单操作者（single operator）不等于低安全——恰恰因为助手持有你的密钥、跑在你设备、出现在你的聊天频道，攻击面反而独特。

## 一、四层防线全景

### 1. 会话权限四档 + per-session 工具覆写
- 档位：read-only / guarded / workspace / full（`sessions-row.ts` 会话 schema 内嵌）
- per-session：MCP server 开关、`mcpToolsDeny`、skills、webSearch（:17-24）——**状态即权限，随会话持久化**
- 工具层三层准入兜底（beforeToolBatch → beforeToolCall → validateToolArguments）

### 2. 通道信任边界（你的聊天软件 = 攻击入口）
- 通道接入走 **pairing 审批流**：`channel_pairing_requested` 钩子 → operator-approval-store → `openclaw pairing approve` CLI 人工放行
- 发件人 allowlist 体系（channel-policy.ts:198+），含**危险名字匹配告警**（display-name 伪装检测）
- 通道层六挂点（inbound_claim → message_received → … → message_sent）给策略插件留位——**PRISM 的 10 hooks 正是这层的消费范例**

### 3. 网络层 fail-closed（net-policy 独立成包）
- `ip.ts:36-66`：封锁 IPv4/IPv6 special-use 全集 + **云元数据 IP 硬编码**（100.100.100.200/fd00:ec2::254）+ RFC2544 前缀 = SSRF 防火墙原语
- 设计哲学原文注释："**throw loudly instead of failing open**"（ip.ts:17-19）
- 独立成包原因：零下游依赖 → 日志脱敏/配置快照/plugin SSRF runtime/web-fetch 全场景复用——**安全原语必须无依赖才能到处用**

### 4. 进程与协议硬边界
- Worker 进程 admission 握手（WorkerAdmissionHandshakeSchema）+ 协议帧硬上限（payload bytes/frame id/method 长度）
- 三轨版本协商；catalog 原子发布（旧代完整则不serve部分新代）
- exec-approvals 独立运行时管命令执行授权

## 二、与 PRISM 的关系（手册 14 章带一的实地锚点）

PRISM（arXiv:2603.11853，Frank Li）= OpenClaw 的**零 Fork 运行时安全层插件**：进程内插件 + 4 sidecar，10 hooks×5 阶段，会话级风险累积（TTL 衰减）。实测拦截率 0.955/误报 13.9%（已在手册纠错框标注）。
**本案例价值**：读 OpenClaw 的 hook-types.ts（42 挂点）能看清 PRISM 的 10 hooks 落在哪些层——通道层（message_received/message_sending）+ 工具层（before/after_tool_call）+ 生命周期（subagent/session）——**安全插件是挂点系统的最大消费者**。

## 三、"own your data" 的安全含义

| 维度 | 云助手 | OpenClaw |
|---|---|---|
| 密钥 | 平台持有 | 你的 SecretStore（secret-ref 契约隔离） |
| 数据 | 平台留存 | 本地 session store（可 tombstone 删除） |
| 网络 | 平台路由 | net-policy 本地封锁（含云元数据 IP——防你自己的云被 SSRF 探测） |

代价：**安全责任也 own**——Gateway 暴露面（bonjour 发现/bridge 协议/cloudflare-access 等 docs/gateway/ 十余篇）全靠操作者自己配置正确。
