# 02 · 六组件实证（harness工程手册 03 章的对照样本）

> 全部锚点来自 packages/ 与 src/（HEAD f612675284）。本篇 = 手册六组件在一个 38.7 万星项目里的工业级实现。

## E · 执行循环（agent-core，零 I/O 纯库）

- `packages/agent-core/src/agent-loop.ts:298-355` — `runLoop` 双层循环：内层消化 toolCalls+steering，外层 `while(true)` 消化 follow-up 消息
- 终止三态：自然结束（无 follow-up 无 steering → `agent_end`，:518-520）/ error/aborted 立即终止（:398-405）/ 工具批量 `terminate===true` 全员到齐才终止（:1202-1207）——**对应手册 12 章"三终止条件"**
- 熔断：同一 run 内第二次 critical 循环故障直接熔断整个 run（:72-73,442-461）——防失控工具循环
- **steering 机制**（最有个性）：运行中用户插话经 `getSteeringMessages` 注入，未执行工具被跳过并标 `deniedReason:"steering"`（:926）；插话必须被消化后才允许 agent_end（:512-517 双重复查）——**人 > 任务完成度**
- 逐轮热切换：`prepareNextTurn` 钩子可中途换 model/thinkingLevel/reasoning（:469-486）
- 工具执行分 sequential/parallel 两路（:694-736）；消息流 `transformContext→convertToLlm→流式→finalize`（:530-628）

## T · 工具注册

- 延迟解析：工具不在注册表时走 `resolveDeferredTool`，成功后动态追加并**强制名字一致防错位**（:1237-1256）
- 准入三层：`beforeToolBatch` 批量（types.ts:347）→ `beforeToolCall` 单个可 block（:1302-1325）→ `validateToolArguments` 强校验（:1400 + validation.ts）
- 声明式插件工厂：`plugin-sdk/tool-plugin.ts:168` `defineToolPlugin`（工具+config schema 一起声明）
- 内置工具面：computer/cron/gateway/ask-user/goal + 整套 MCP server 生命周期管理（src/agents/tools/agent-bundle-mcp-*.ts）
- **tool-call-repair 独立成包**（2900+ 行）：修复模型以纯文本吐工具调用的三种语法（Harmony commentary/analysis/final 通道标记、`<tool_call>` XML-ish、named-bracket），payload.ts:13-18,49 解析后由 promote.ts 升格为结构化 toolcall——**把"模型不可靠"当一等工程问题**

## C · 上下文管理

- 压缩触发：`contextTokens > contextWindow - reserveTokens` 纯阈值（harness/compaction/compaction.ts:243-251）
- 每请求前 `transformContext` 可整段重写上下文——宿主挂 compaction/replay 的位置（agent-loop.ts:541-543）
- **分支摘要而非线性截断**（branch-summarization.ts）+ toolCall/toolResult 配对完整性保障（compaction-trailing-toolresult）——对应手册 04 章"压缩不破坏配对"
- 角色过滤：`defaultConvertToLlm` 只放行 user/assistant/toolResult 三角色（agent.ts:42-47）

## S · 状态存储

- 会话主存储 `SessionRowSchema`：key/kind(direct|group|global)/channel/owner/peer + null tombstone 信封（gateway-protocol/src/schema/sessions-row.ts:41-161）
- **per-session 工具覆写**：MCP server 开关、`mcpToolsDeny`、skills、webSearch 开关（:17-24）——状态即权限
- 密钥存储协议（SecretStore set/list/delete + secret-ref 契约）
- Gateway 常驻实体：operator-approval-store / board-store / progress-card-store / node-wake-state-store（src/gateway/）

## L · 生命周期钩子

- **42 个挂点全量**（src/plugins/hook-types.ts:96-138），六层分布：
  模型层（before_model_resolve/llm_input/llm_output/model_call_*）
  回合层（agent_turn_prepare/before_prompt_build/before_agent_finalize）
  工具层（before/after_tool_call/tool_result_persist）
  会话层（session_start/end/subagent_*）
  通道层（inbound_claim/message_received/message_sending/message_sent）
  gateway 层（gateway_start/stop/cron_reconciled/skill_*）
- 编译期断言 hook 名单无遗漏（:183-188）——**类型级完整性检查**，挂点增删过不了编译
- 对照：PRISM 的 10 hooks 就是这 42 个的子集（通道层+工具层为主）

## V · 验证接口

- 每个 RPC 方法配 `validate*Result` + validator-registry 统一注册（gateway-protocol/src/index.ts:5-9,35）
- 三轨版本协商：MIN_CLIENT/MIN_NODE/MIN_PROBE_PROTOCOL_VERSION（version.ts）
- 能力声明 + 协议硬上限（max payload bytes/frame id/method 长度，public-schema.ts:54-73）；Worker 进程须 admission 握手（:27-28）

## 小结：一张 Completeness Matrix 全 ✓ 的活样本

OpenClaw 是手册 03 章六组件的"全绿"实证——且每个组件都比教学版多一个**防御性细节**（熔断/名字防错位/tombstone/编译期断言/协议硬上限）。教学版学结构，这里学的是结构上的锈斑处理。
