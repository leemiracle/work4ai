# 03 · 协议中枢与插件面（运行机制篇）

> 核心问题：一个 38.7 万星项目怎么组织"agent 怎么跑"？答案：循环内核 + 协议中枢 + 插件宿主三层，且每层边界极硬。

## 一、三层架构（一次请求的完整旅程）

```
用户（Telegram/CLI/TUI/app）
   │ 消息进入通道层 hook（inbound_claim → message_received）
   ▼
Gateway daemon（常驻，src/gateway/）           ← S+V 层
   │ 会话路由（SessionRow: key/kind/channel/owner/peer）
   │ 密钥（SecretStore）/审批队列/节点唤醒
   │ WS+JSON-RPC（gateway-protocol 的 typebox schema 校验每一帧）
   ▼
agent-core runLoop（packages/agent-core，零 I/O 纯库） ← E+C 层
   │ agent_turn_prepare → before_prompt_build（L 挂点）
   │ transformContext → convertToLlm（只放行 user/assistant/toolResult）
   │ LLM 流式回包（9 provider 家族，llm-core 统一类型）
   │ tool-call-repair：纯文本工具调用 → 结构化（三种语法解析+promote）
   │ beforeToolBatch → beforeToolCall → validateToolArguments（三层准入）
   │ sequential/parallel 分路执行 → tool_result_persist
   │ 压缩检查（阈值触发 → 分支摘要，保配对）
   │ steering 检查（用户插话优先，未执行工具标 deniedReason:"steering"）
   ▼
agent_end（无 follow-up 无 steering 才允许）→ 通道层 message_sending/sent
```

## 二、模型差异 = 数据目录，不是适配器代码

`model-catalog-core/model-catalog-types.ts`：
- 10 个 API 家族（+ollama/github-copilot）+ 7 种 thinking wire 格式
- `CompatConfig` 约 40 个**逐模型兼容开关**（supportsTemperature/toolCallArgumentsEncoding…）
- 模型接口自带 cost/contextWindow/maxTokens——模型=数据
- 版本协商三轨（client/node/probe）+ catalog 原子发布（"失败代绝不与部分新代共存"）

**对照**：deepseek 家族 harness 的 engines/dialects.py 是同一思想的 Python 缩微版（8 引擎方言注册表）。**教训：多模型支持的正确形态是"目录+开关"，不是 if-else 适配器森林。**

## 三、插件系统（42 挂点 + 包契约）

- 挂点六层分布见 [02-六组件实证](02-六组件实证.md) L 节
- 外部插件最小契约（plugin-package-contract/src/index.ts:29-32）：package.json 必填 `openclaw.compat.pluginApi`（semver range）+ `openclaw.build.openclawVersion`，可选 `minGatewayVersion`
- 资源声明进 manifest（docs/agent-runtime-architecture.md）：`openclaw: {extensions/skills/prompts/themes}` 走 package.json 元数据，未声明则回退目录约定发现
- **编译期断言挂点名单无遗漏**（hook-types.ts:183-188）——挂点演进不靠文档靠类型系统

## 四、三个反直觉设计决策（源码证据）

1. **真底座是 normalization-core**：入度 16/23（实测），而名为中枢的 gateway-protocol 入度仅 2——协议包极简零耦合，任何端可独立实现（apps/android、ios 才能各自直连）。
2. **2900 行修"模型写错工具调用"**：tool-call-repair 单独成包处理 Harmony 通道标记/XML-ish/named-bracket 三种野语法，流式+非流式+promote 三路——工业界对"模型不可靠"最重的投资之一。
3. **steering > 任务**：插话跳过整批未执行工具 + 双重复查才准 agent_end——把"操作者随时可夺回控制权"做成循环级原语，不是 UI 层补丁。

## 五、runtime 选择：harness 也可插拔

- 内置 runtime id `openclaw`（legacy `pi` 归一化）；插件可注册更多（如 `codex`）
- 选择策略：model/provider 级配置，`auto` = 按有效 provider 路由选插件 harness，否则内置
- OpenAI 精确官方 HTTPS Responses 路由才隐式选 codex；明文官方 HTTP 端点直接拒——**安全边界进 runtime 选择**
