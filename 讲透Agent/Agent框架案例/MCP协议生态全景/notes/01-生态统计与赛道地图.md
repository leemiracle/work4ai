### 1.3 双口径对账的洞察

- **语言结构反转**：topic 全量里 Python 第一（33.8%），awesome 收录里 TS 第一（54%）——解释：Python 仓多但"目录级质量"收录率低（大量模板/玩具/个人脚本），TS 生态出产更高比例的"值得收录" server。**若做 MCP 开发选型，跟 TS 生态的质量中位数；若看生态热度，看 Python 的量。**
- **收录率**：3,371 / 64,438 ≈ **5.2%**——topic 里的仓 95% 不进主流目录，与用例库 279 快照「22% README 提及 MCP」互证：MCP 更多是**产品的配件**而非仓库的主题。

## 3. 六赛道归类（结构层）

- **A 平台型 host（13/41）**：把 MCP 当能力插槽的终端产品（n8n/dify/open-webui/siyuan/思源式笔记/AstrBot/JeecgBoot…）。**最大赛道**——MCP 的"需求方"
- **B 目录与治理（4/41）**：awesome 系 + Registry。生态的"黄页与海关"（找/评/分发 server）
- **C 大厂官方 server（2/41）**：chrome-devtools-mcp/playwright-mcp——用官方协议重新暴露自家王牌工具
- **D 基建 server/中间件（12/41）**：context7（文档）/mempalace（记忆）/headroom（压缩）/kong+OmniRoute（gateway）/codebase-memory+graphify（代码智能）/Scrapling+Agent-Reach（数据获取）——**MCP 的"供给方"主力**，与本项目 Agent上下文案例 六路线高度重叠
- **E harness/agent 工程（5/41）**：ECC/cc-switch/goose/nanobot/UI-TARS——agent 本体与管家（本项目 Agent框架案例 主战场）
- **F 学习资源（4/41）**：书+教程+面试指南——MCP 已进入教材层 = 扩散晚期信号

**赛道洞察**：头部 41 仓中"平台/工具搭车"（A/C/D/E/F）占绝对多数，**纯 MCP server 进不了 top**——头部由"用 MCP 的产品"占据，"MCP 产业本身"（SDK/参考实现）在官方 org 里（03 篇）。生态分层清晰：**官方管协议、目录管长尾、平台管需求、基建管供给**。

## 4. 趋势信号（2026-08 快照）

1. **x402 微支付商业化**：awesome 目录 233 处 x402 字样——pay-per-call（USDC on Base）成为 server 变现的主流实验路径（awesome Aggregators 类里密度最高：一个 MCP 聚合 N 个付费 API）。**基础设施已配套成型**：x402-mcp（Coinbase Bazaar 100+ 付费 API 自动发现）、x402search（索引 14,000+ x402 API）、payfetch/solinkify（硬性限额防超额）。⚠️ **批判**：x402station 的 preflight 反诈服务自称"**~70% x402 端点是死链或骗局**"——微支付生态繁荣的镜像面是质量泥沙俱下，agent 侧付费前探测是刚需（与 dsh 信任平面的 fail-loud 原则同源）
2. **skills 与 MCP 并轨**：awesome-claude-skills（72.8k）与 agentic-awesome-skills（45.1k）高悬 topic:mcp——Skills 路线（声明式、按需加载）与 MCP 路线（协议化、常驻）正在同一赛道竞争又互补（对照 [`前沿与媒体/103-AgentSkills开放标准深度解析.md`](../../../../前沿与媒体/103-AgentSkills开放标准深度解析.md)）
3. **gateway 中间件层崛起**：Kong（44k，API gateway 巨头）把 mcp-gateway 列为正式 topic——企业级 MCP 治理（SSO/RBAC/审计）成为基建新市场（FastMCP 的 Prefect Horizon 同方向）
4. **上下文经济学**：headroom（压缩进 LLM 前的 tool 输出）+ context-firewall 类"122 工具折叠成 4 元工具"——**工具面爆炸的反作用力**是 2026 生态主矛盾（正解参考 [03](03-官方仓与SDK格局.md) §5 toolsets 设计）。定量实证：awesome Frameworks 类的 graph-tool-call（BM25+图遍历检索工具）自称把 248 工具场景的调用准确率 12%→82%——**工具多了不是能力，检索得动才是能力**
