## 一、编排框架流派（LLM-in-the-loop 协调）

| 框架 | 创新点 ★ | 缺点 ✗ |
|---|---|---|
| **autogen-ms** | ★ Actor 消息模型运行时（Topic 订阅/发布 + gRPC 分布式）；五种 Team 编排模式（RoundRobin/Selector/**Swarm handoff**/GraphFlow/MagenticOne 双循环）；**双向 MCP**（可当 Host 反向 sampling/elicitation） | ✗ **官方维护模式**（README 明示转向 Microsoft Agent Framework）；0.2→0.4 大重构断裂生态，新旧教程互不兼容；三层包概念多学习曲线陡 |
| **ag2** | ★ register_reply 责任链（一切交互模式皆挂 hook）；**工具依赖注入**（按类型注解注入运行时对象，超越 plain function calling）；A2A/AG-UI 双协议 | ✗ 与 microsoft/autogen 分叉造成社区分裂、两头迁移风险；经典 GroupChat 全历史广播 token 消耗大 |
| **metagpt** | ★ **SOP 物化**：watch 订阅拓扑（cause_by 即路由键）+ ActionNode 结构化产物合同——"装配线而非聊天室"降幻觉；RoleZero 自我革命（SOP→动态规划器） | ✗ 固化 SOP 对非软件任务不适用；新旧两套心智模型并存；多角色全流程 token 成本高 |
| **agentscope** | ★ **model-driven 哲学**（不 imposing workflow，编排智能下放模型）；Toolkit 中间件链；Msg content blocks 跨模态统一；单机/分布式同一编程模型 | ✗ 国际生态弱于 LangChain（文档/社区）；群聊默认全历史广播；插件薄 |
| **semantic-kernel** | ★ **三源函数归一**（代码/prompt/OpenAPI→KernelFunction）+ 三类 filter 洋葱切面；.NET/Python 双语言平行实现 | ✗ 官方宣布汇入 Microsoft Agent Framework（又一个迁移周期）；双语言功能漂移（.NET 常领先）；企业味重原型慢 |
| **haystack** | ★ **类型化 socket 组件 DAG**（编译期连接检查）；**Snapshot 断点恢复**（长时 Agent 可持久化可审计）；Pipeline 即 Tool 递归组合 | ✗ 2.x→3.0 破坏性迁移伤社区；Agent 能力比 LangGraph 年轻；集成拆包后安装组合复杂 |
| **agency-swarm** | ★ communication_flows 显式通信拓扑（组织架构即代码）；SendMessage(阻塞)/Handoff(移交) 双语义；MasterContext 显式共享状态 | ✗ Assistants API→Agents SDK 转型期代码断裂；OpenAI 绑定深；文档滞后于重构 |
| **swarm** | ★ 极简双原语教育标本：Agent=提示词+工具包、**handoff=函数返回值**；100 行 run loop 讲尽多 Agent 本质（OpenAI Agents SDK 的概念原型） | ✗ **官方已废弃**（experimental）；无持久化/无观测/无生产特性——只配当教具 |
| **agentdock** | ★ configurable determinism（确定性刻度可配：哪些环节 LLM、哪些环节确定性工作流）；一切皆 Node 统一抽象 | ✗ 生态小；编排深度不如 LangGraph；TypeScript 单语言 |
| **agentgpt** | ★ **前端跑循环+后端无状态**（2023 爆款架构标本：workLog 队列自主循环 + 6 端点 LLM 编排） | ✗ **已停止维护**；无长期记忆（刷新即失）；4k 上下文时代的 token 工程已过时——纯教具 |

## 二、编码 Agent 流派（终端/IDE 自主软件工程）

| 框架 | 创新点 ★ | 缺点 ✗ |
|---|---|---|
| **aider** | ★ **SEARCH/REPLACE 容错级联**（四级降级匹配 + 故意禁用模糊匹配防误改 + 失败诊断回喂反思）；**RepoMap = PageRank 上下文工程**（graph-based RAG，非 embedding）；三层模型路由（main/weak/editor）；88% 代码自写 | ✗ 单 Agent 单线程（无并行 agent/后台任务）；无沙盒（直接改本地文件，全靠 git 兜底）；超大 monorepo 的 repo map token 预算紧张 |
| **cline** | ★ **Plan/Act 双模式分离**（同一循环两套 prompt+权限，规划只读/行动全量）；**Focus Chain** 跨 compaction 进度追踪（压缩不丢总目标）；Checkpoints 每步快照可回滚 | ✗ VSCode 扩展为原生宿主（CLI/SDK 后长出，成熟度差一档）；大仓库上下文仍吃紧；无原生沙盒 |
| **opencode** | ★ **client-server 分离**（一个 Hono 后端喂 TUI/Desktop/VSCode/Web 四端）；Effect 化 DI/Schema；**三级上下文防御**（buffer→prune→compaction→replay，含 DOOM_LOOP 检测） | ✗ V1→V2 演进期 API 不稳定；Effect 生态读码门槛高；迭代快导致文档漂移 |
| **openhands** | ★ **CodeAct**（一切动作=代码，工具即语言）；**沙盒即服务**（Docker/Remote/Process 三后端 + 沙盒内 ActionExecutionServer）；EventStream 事件总线 + **Condenser 三策略记忆压缩** | ✗ V0→V1 大迁移中（V0 已删、文档与代码脱节）；部署重（Docker+PG+镜像）；全事件流回灌 token 巨大 |
| **plandex** | ★ **版本控制优先**（plan 内建 git branch 沙盒，apply 前零污染）；structured edits→tree-sitter 验证→XML 自修→whole-file 降级的**多级兜底管线**；DB 行锁+心跳并发控制 | ✗ 自托管 Go 服务器运维成本；2M 直连上下文依赖昂贵模型；社区小于 aider/cline |
| **claw-code** | ★ Rust 双轨（生产轨+Python parity **对拍审计轨**）；Worker Boot 状态机 + Lane Events 机器可读事件流 + Recovery Recipes 六类失败自愈；Trident 三级压缩（Supersede/Collapse/Cluster+边界保护） | ✗ 双轨维护成本高（Python 轨易滞后）；Rust 贡献门槛；对拍基准是 mock 而非真实 provider 行为 |
| **codel** | ★ **NextTask 单步循环**（LLM 每步只决定"下一个任务"，失败降级为 ask 用户永不崩）；LLM 选 Docker 镜像（LLM 当运维）；GraphQL subscriptions 直播 Agent 操作 | ✗ **docker.sock 挂载是安全大洞**（容器逃逸风险）；无全局 plan 视图；项目活跃度下降 |
| **agentk** | ★ 微内核自进化（**AgentSmith 造 Agent**/ToolMaker 造 Tool + 强制 smoke test 质量门 + 防过度特化"代理化"自律条款） | ✗ 个人实验项目成熟度；自生成代码无强保证；run_shell_command 无沙盒 |

## 三、研究/科学发现流派

| 框架 | 创新点 ★ | 缺点 ✗ |
|---|---|---|
| **gpt-researcher** | ★ Plan-and-Solve 子查询分解 + **三层 LLM 成本分层**（FAST/SMART/STRATEGIC 各司其职）；embedding 相似度压缩管线（0.35 阈值滤无关）；LangGraph 编辑部 review-revision 状态机（审稿人点头才算过） | ✗ 深度绑定 Tavily（检索天花板=搜索 API）；报告仍偏拼接式综合；多智能体模式 token 贵 |
| **ai-scientist** | ★ idea→实验→论文→评审**全自主闭环**（$15/篇）；**few-shot 检索式 LLM 评审器**（ICLR 样本库相似度检索拼装 + reflection 二审）；模板化领域封装（领域知识全外置） | ✗ 实验范围锁死在 4 个模板；生成论文新颖性/质量争议大（自审分析显示评审偏差）；v1 已被 v2 tree-search 版取代 |
| **adas** | ★ **Meta Agent Search**（NeurIPS 2024 开山）：LLM 在代码空间搜索/发明 Agent 架构，热加载进评估循环——"Agent 设计自动化"起点 | ✗ **动态代码执行无沙盒**（直接 exec）；搜索空间受 prompt 模板约束；发现的架构泛化性存疑；基准窄（5 个） |
| **aideml** | ★ **Agentic Tree Search**（解树+三旋钮：num_drafts/debug_prob/max_debug_depth = 探索/修复/利用）；**MetricValue 把优化方向编码进类型**；双 LLM 分工（生成/评审 function calling 四字段） | ✗ 树搜索 token 成本线性于节点数；OpenAI 生态为主；限表格型 ML 竞赛任务 |
| **actionbook** | ★ **发现/执行分离**（"爬一次用千次"：ReAct 浏览器探索→带置信度多路 selector 手册资产化）；DB 状态机+SKIP LOCKED+心跳恢复的多 Agent 容错编排 | ✗ 手册构建本身要跑 AI 浏览器（成本前置）；网站改版仍需重录（腐化只被缓解）；生态早期 |

## 四、基础设施/记忆/可观测流派

| 框架 | 创新点 ★ | 缺点 ✗ |
|---|---|---|
| **phoenix** | ★ **OpenInference 语义约定**（十类 SpanKind 跨框架 trace 互通的数据契约）；SpanFilter DSL（Python AST→SQLAlchemy 子句）；PxI 自举（用 Phoenix 追踪 Phoenix 自己的 Agent） | ✗ Python 生态为主 JS 端薄；LLM-as-judge 评估有成本+偏差；UI 学习曲线对比 Langfuse 偏陡 |
| **screenpipe** | ★ **事件驱动捕获**（AppSwitch/Click/TypingPause 触发而非固定轮询）；pipe.md 声明式 Agent 插件（YAML+prompt=一个定时 Agent）；**SQL 行级权限过滤**（最小权限到数据行） | ✗ 隐私原罪（录屏录音，local-first 也难过企业合规）；~20GB/月存储增长；OCR/STT 质量依赖平台；桌面资源占用 |
| **aeon-agent** | ★ **GitHub Actions 当运行时+git 仓库当数据库**的零基础设施架构；Prefetch/Post-process 双脚本绕沙箱（Deferred Execution）；Exit Taxonomy 六类退出码支撑自愈 | ✗ 严重耦合 GitHub（Actions 配额/限速）；沙箱无网络→实时性差；调试困难（执行分散在 CI） |
| **agentic-context-engine** | ★ **Recursive Reflector**（LLM 写 Python 代码程序化分析 trace，而非单遍总结）；Skillbook 策略库+引用追踪（哪些 skill 真正生效）；Learning Tail 异步学习不阻塞主答 | ✗ REPL 沙箱非强隔离；学习环依赖高质量 eval signal；概念体系大（93 页）学习成本高 |
| **cortex-mem / bernstein** | ★ bernstein：**zero-LLM coordination**（纯 Python 状态机协调，LLM 只当乐手——杜绝递归幻觉循环）；HMAC 审计链+Lineage 溯源+确定性重放；WAL/DLQ/drain 三重可靠性 | ✗ 零智能协调的另一面=无自适应（Plan 失败需人工改 YAML）；单线程 orchestrator 吞吐上限；40+ adapter 维护负担；社区小 |
| **aden-hive** | ★ **Goal→Judge 验收驱动**（路由让位于成功判据，ACCEPT/RETRY/ESCALATE 三态）；**coding agent 读日志改图**的 self-improving loop；tool doom loop 检测 | ✗ 单生产节点类型（EventLoopNode）表达力受限；自改进依赖外部 coding agent（Claude Code/Codex）；文件持久化大规模性能存疑 |
| **babyagi-ui** | ★ BabyAGI 五段循环（create→prioritize→execute→enrich→context）的 TypeScript 最小实现；Skill descriptionForModel 自描述（手写 function calling 前史标本） | ✗ **已归档**（2023 历史使命完成）；Pinecone 依赖；无并行——教具价值>实用 |
| **dspy** | ★ **声明式 Signature+编译器范式**（prompt 优化变成 metric 驱动的搜索问题："PyTorch 之于 NN，DSPy 之于 LM 程序"）；MIPROv2/GEPA 优化器族（bootstrap→提案→贝叶斯搜索） | ✗ 抽象层学习成本高；编译需训练集+metric（冷启动门槛）；优化后 prompt 可解释性下降；长 horizon agent 弱于 LangGraph |
| **smolagents** | ★ **CodeAgent**（写 Python 代码代替 JSON 工具调用）+ **LocalPythonExecutor 五层 AST 沙箱**（函数/import 白名单+资源上限+FinalAnswerException 继承 BaseException 防吞）；HF Hub 工具/Agent 双向分享 | ✗ 核心极简=企业特性薄（无分布式/审计）；AST 沙箱防不住所有逃逸（对照容器沙箱弱一档）；Hub 序列化需 trust_remote_code（供应链风险） |
| **storm** | ★ **视角引导提问**（先发现 persona 再用视角驱动检索对话，广度来自显式变量）；Co-STORM Moderator 未用信息重排序公式专治对话僵化；多 LM 分级成本工程 | ✗ 线性流水线不可回溯；检索质量决定上限（FreshWiki 基准显示时效主题弱）；长文引文偶有错配 |
| **xagent** | ★ **计划是活树**（SPLIT/ADD/DELETE/EXIT 四算子运行时改树+树宽深有界防失控）；工具全跑 Docker ToolServer（部署层隔离）；XAgentGen 约束解码让开源模型做 function calling | ✗ 依赖重（MySQL/Redis/MongoDB 全家桶）；OpenAI 绑定较深；项目迭代放缓（2024 后更新少） |
| **taskweaver** | ★ 双历史有状态会话（chat+code execution，DataFrame 跨轮存活）；**embedding 自动选插件**（早期 RAG 选工具实践）；AST 白名单+Docker CES 双层安全 | ✗ 微软后转向其他框架（维护节奏放缓）；插件生态小；无多 Agent 协作 |
| **superagi** | ★ ReAct 拆成**可暂停/审批/调度的分布式状态机**（Celery 步进+9 状态）；HITL 权限落库+Action Console 审批 UI；三合一市场（模板/工具/模型） | ✗ 项目已停更（2023 遗产）；六容器部署重；工具市场质量参差 |
| **voyager** | ★ **skill library 开山**（代码即技能+Chroma 检索式程序性记忆，不微调终身累积）；自动课程（LLM 当课程规划器）；迭代提示三重反馈闭环 | ✗ 强绑定 Minecraft/Mineflayer（抽象到新域要重写环境层）；GPT-4 依赖贵；评估靠游戏内进度缺跨域基准 |
| **restgpt** | ★ **零封装接 REST API**（直接消化 OpenAPI 文档组织参数，换场景只换 spec 文件）；**代码生成解析 JSON 响应**（写代码代替逐 token 读，防上下文爆炸）+三级降级；RestBench 基准 | ✗ PythonREPL 弱沙盒（反面教材）；LangChain 旧版 Chain 结构；项目停更，基准被后继工作超越 |
| **lagent** | ★ PyTorch 哲学：**Agent 即 nn.Module**（forward+state_dict 整树序列化）；工具与 Agent 同构消息（ActionExecutor 统一路由）；docstring 元类自动 schema；session_id 并发隔离 | ✗ 生态主要在中文社区；学习型组件空白（对照自进化主题）；英文文档少 |
| **mastra** | ★ **循环即 workflow**（ReAct 循环=dowhile 工作流，免费获得 suspend/快照/time travel）；三执行引擎 hook 换芯（内存/Inngest/Evented+Temporal）；TS 全栈产品闭环（dev→Studio→deploy→SDK） | ✗ 迭代极快文档漂移；TS-only（Python 用户无缘）；119 页概念体系大学习曲线 |
| **strands-agents-sdk** | ★ **一个函数的事件循环**（"a model, some tools, and a loop"极简派）；一切皆 Hook（框架内置功能与用户扩展同一条路）；**Cedar 策略引擎+HITL 打断**（最完整权限模型，AWS 基因） | ✗ AWS 绑定深（Bedrock 一等公民，跨云要适配）；社区年轻文档薄；TS/Python 双轨功能漂移 |
| **swarms-framework** | ★ **SwarmRouter 统一 14 种拓扑**（编排模式做成一等可切换对象+auto embedding 自动选型）；ReasoningAgentRouter 六种推理策略工厂；Conversation 五后端记忆 | ✗ Agent 类 100+ 参数（配置地狱）；kyegomez 多线维护质量参差；auto 模式实现滞后于宣传 |

## 五、跨流派洞察（3 条）

1. **协调光谱**：同一个"多 Agent"问题，从 zero-LLM（bernstein 纯状态机）→ 声明式图（haystack/MetaGPT 订阅拓扑）→ LLM 路由（autogen Selector/Swarm handoff）→ 涌现式（agentk 自造 Agent）——**确定性 ↑ 可审计性 ↑，自适应性 ↓**。没有最优解，只有场景匹配（监管团队→bernstein；探索任务→agentk）。
2. **上下文工程是共同战场**：aider 用 PageRank、plandex 用 tree-sitter 地图+2M 直连、openhands/opencode/claw-code 用三级压缩、screenpipe 用 FTS5 时间窗——2026 年"上下文管理"已取代"编排"成为框架差异化的主轴。
3. **Agent 自我改进的三个层次**：运行时反思（aider 失败回喂）→ 经验固化（ACE Skillbook）→ 结构自改（aden-hive 改图 / agentk 造 Agent / bernstein evolve L0-L3）——层次越高，对质量门和审计的要求越硬（smoke test→HMAC 链），这是 2026 主线。
