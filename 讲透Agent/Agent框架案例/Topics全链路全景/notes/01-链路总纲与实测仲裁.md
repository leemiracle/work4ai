## 1. 为什么要做实测仲裁（三家对账结论）

Kimi 报告与用户框架提供了结构，但数字层面发现**三处重大口径问题**，全部经实测纠正：

| 争议点 | Kimi/素材说法 | 本机实测（2026-08-19） | 判定 |
|---|---|---|---|
| `fine-tuning` 规模 | Kimi：72 仓 | **4,863** | Kimi 错 67 倍（疑搜索被截断/带隐藏条件） |
| RAG 层规模 | Kimi：896 仓（只列 agentic-rag 等长尾） | **`rag` 主 topic = 41,086** | Kimi 漏了主 topic，低估 45 倍 |
| MCP 层规模 | Kimi：670（只测 `modelcontextprotocol`） | `mcp` = 64,438（8-19 快照）；`mcp-server` = 24,858；`modelcontextprotocol` = 663 | Kimi 只测了官方长名 topic |
| `prompt-engineering` | 素材2：8,200+；Kimi：16,334 | **16,098** | 素材2 过时一半；Kimi 基本准确 |
| `lora` | Kimi：2,234 | **4,997** | Kimi 疑用早期数据 |
| `context-engineering` | 素材2：2,200+ | **2,702** | 素材2 基本准确 |

**方法论教训**（与 MCP/Skills 两篇的 topic 盲区教训同构）：topic 检索有三重陷阱——①官方长名 topic 与社区短名 topic 规模可差百倍（`modelcontextprotocol` 663 vs `mcp` 64,438）；②聚合报告常漏主 topic 只算长尾（RAG 层）；③单一来源数字不可信，必须 API 逐个实测。

## 4. 结构洞察（数字怎么说）

1. **规模断层**：`llm`(116k) / `ai-agents`(74k) / `mcp`(64k) / `rag`(41k) 是四个"万仓级"超级 topic——它们已是**领域名**而非技术标签。检索时用处反而低（噪声大），适合看趋势不适合找具体项目。
2. **动词层最实用**：1k-25k 区间的 topic（mcp-server 24,858 / agent-skills 16,276 / prompt-engineering 16,098 / multi-agent 13,821）是"做某类东西的人"的聚集地——检索信噪比最高。
3. **概念热 ≠ topic 热**：`reasoning-model` 只有 9 仓、`rlvr` 119、`multimodal-rag` 123、`data-centric-ai` 111——这些 2025-2026 的热词在 topic 体系里还是空壳，相关项目散在 `llm-evaluation`、`rag` 等老 topic 里。**用新词搜 topic 会漏，用老 topic 搜会杂**。
4. **对齐三兄弟旗鼓相当**：rlhf 778 / grpo 522 / dpo 441——方法迭代（RLHF→DPO→GRPO）没有带来 topic 替换，三个标签并存，说明社区用 topic 表达"阵营"而非"版本"。
5. **产品名成为 topic**：`vllm`(2,104)、`unsloth`(477)、`engram`(76)——工具影响力大到用户自发打标签，这是"事实标准"的 GitHub 侧写。
6. **`agent-skills`(16,276) > `skills`(11,492)**：标准名反超通俗名，且官方源仓（anthropics/skills 170,317★）只挂前者——生态正从通俗词向标准词收敛（Skills 生态全景 §topic 盲区的镜像证据）。

## 5. MECE 校验与层间边界

十层划分来自用户两份框架的合并，做两处修正：
- **RAG 独立成层（L5）**：Kimi 把 RAG 并在链路里但漏了主 topic；用户框架2 有独立层。采纳独立层——41k 仓规模配得上。
- **Data/Eval（L8）独立**：素材1 把 evaluation 混在模型层、素材2 独立。采纳独立——评测是横跨训练与推理的第三方视角（benchmark 10,860 仓）。
- 已知重叠：`embeddings`/`vector-database` 横跨 L2/L5（本表归 L5）；`memory-management`(3,395) 横跨 L2/L4（agent-memory 2,849 在 L4）——记忆是"上下文的持久化"，两处都合理，卡片里互指。
