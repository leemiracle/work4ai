## 1. 全链路 5W2H 总分析

| 维度 | 分析 |
|---|---|
| **What（这是什么）** | 一套覆盖「用户输入 → 模型本体」完整技术栈的 GitHub topic 索引体系：68 个实测 topics 分十层，规模从 9 仓（reasoning-model）到 116,500 仓（llm），总计约 35 万仓次（含跨层重复计数）。它是 **AI 应用技术栈的 GitHub 侧写**——比任何架构图都诚实，因为打 topic 是开发者的自发行为。 |
| **Why（为什么存在/为什么分析它）** | ①选题需要：找参考实现/判断技术成熟度/评估赛道拥挤度，topic 规模与增速是**社区用脚投票的信号**；②学习需要：十层即 AI 应用开发的完整知识地图（与讲透模型宇宙 Part IV 能力地图互为镜像）；③避坑需要：topic 有三重陷阱（长名/短名百倍差、漏主 topic、新概念空壳——见 01 篇 §1），需要一份实测校准的索引。 |
| **Who（谁在用/谁该用）** | 打标签的人：应用开发者（L1/L5）、框架作者（L2/L4）、工具作者（L3）、算法工程师（L6-L8）、推理工程师（L9）、模型团队（L10）。**该用这份索引的人**：选型者（按层定位候选）、研究者（看生态分布与空白）、求职者（每层的热门栈就是岗位技能表）。 |
| **When（何时用哪层）** | 按问题演化顺序：先 prompt（L1，零成本）→ 上下文与检索（L2/L5，零训练）→ 工具与技能（L3/L4，零训练）→ 微调（L6，GPU 小时级）→ 对齐（L7，集群级）→ 自研/改造底座（L9/L10，团队级）。**训练是最后手段**，前五层全部零训练。 |
| **Where（在哪里发生/在哪检索）** | GitHub topics 页 + Search API（`topic:x`）；组合检索公式：`topic:llm-inference OR topic:quantization`（同层 OR 扩覆盖）、`topic:mcp-server topic:typescript`（跨域 AND 收窄）、按 star 排序看头部、按 recently updated 看活跃。生产检索注意 `skills` 这类双义词要加时间/关键词过滤。 |
| **How（怎么用这套体系）** | 三步：①定位你的问题在哪层（01 篇链路图）；②取该层 1k-25k 规模的"动词 topic"检索候选（信噪比最高）；③用代表仓验证（每层 3-5 个锚点仓已给）。**反向用法**：发现某概念 topic 空壳（如 reasoning-model 9 仓）→ 说明该领域没有形成项目聚集，蓝海或伪需求二选一。 |
| **How much（规模/成本/收益）** | 规模：四大超级 topic（llm 116k/ai-agents 74k/mcp 64k/rag 41k）+ 六十四个中长尾。成本：检索成本近零，误用成本高（漏主 topic 差 45 倍）。收益：一份实测索引把"找参考实现"从碰运气变成查表。 |

## 3. 补充方法一：第一性原理看链路

**唯一的第一性问题：固定权重的模型如何获得它没有的能力与知识？**

全链路就是对这一个问题的一组递进回答：
- 改**输入**（L1 指令 / L2 窗口 / L5 检索）——能力来自上下文，零训练；
- 改**连接**（L3 工具 / L4 技能）——能力来自外部执行与程序性知识，零训练；
- 改**权重**（L6 适配 / L7 对齐 / L8 数据）——能力内化，训练成本；
- 改**运行方式与本体**（L9 推理 / L10 模型）——能力的物质基础。

**推论**：越靠近"改输入"的层 topic 增长越快、参与者越多（大众化），越靠近"改权重/本体"的层越专业、规模越小但单仓价值密度越高——实测数据完全吻合（prompt 16k vs rlhf 778）。**2026 年的工程智慧：能用 L1-L5 解决的绝不进 L6-L8。**

## 4. 补充方法二：SWOT（这套 topics 体系本身）

- **S 优势**：自发标签=真实需求侧写；规模/增速可量化；免费且实时；
- **W 劣势**：三重陷阱（长短名/漏主 topic/新概念空壳）；无语义控制（skills 双义）；star 通胀；
- **O 机会**：空壳 topic（reasoning-model 9 仓）= 新概念尚未项目化的窗口；`agent-skills>skills` 的收敛趋势可预测标准词投资价值；
- **T 威胁**：GitHub 算法推荐弱化 topic 作用；厂商改名（MemGPT→Letta）造成标签断代；AI 批量打标签污染。

## 5. 补充方法三：技术选型成本阶梯（When 的量化版）

| 路径 | 成本 | 时延 | 上手 | 何时止步换下一条 |

| L1 改 prompt | ~0 | 分钟 | 人人 | 效果方差大、指令装不下领域知识 |

## 6. 收束：这张地图怎么长期用

1. **季度复测**：68 topics 的 counts.json 已留档（/tmp/opencode/topics-audit/），重跑脚本即可对比增速——`agent-skills`、`agentic-rag`、`grpo`、`speculative-decoding` 是最值得盯的四个增长指标；
2. **新概念落地检测**：出现热词先查它的 topic 是否空壳——空壳=尚未项目化（蓝海/伪需求），非空壳=看头部仓定格局；
3. **与本项目的缝合**：L3/L4 已有深潜篇（MCP/Skills 全景），L2/L4 记忆有 mem0 案例，L4 框架有 dsh 案例——**其余各层按需开深潜**，本目录作为总索引长期挂网。
