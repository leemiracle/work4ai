## 一、信号层：从运行轨迹中获得学习信号

Agent 每次运行产出轨迹（动作序列/工具结果/成败判定/中间推理）。持续进化的第一步是**从轨迹提取信号**——综述定版（2507.21046/2607.13104）按 what/when/how 三维展开，信号的形式决定下游一切：

| 信号形式 | 提取自 | 典型机制 | 我们的实例 |
|---------|--------|---------|-----------|
| 标量奖励 | 终局成败 | RLVR/评价函数 | 发现引擎五类 reward；Prover 的 lake build 0/1 |
| 文本反馈 | 判官/批判 | 反思/经验抽取 | Prover 蒸馏的 e1-e6 失败案例分析 |
| 执行轨迹本身 | 完整 rollout | 轨迹回放/对比 | T4 的 trace 统计→守卫补丁；121k 图验证日志 |
| 梯度 | 可微损失 | SFT/RL | θ 侧（我们暂缓） |

**关键洞察**（与后训练综合的状态分布观衔接）：信号不仅要有，还要**在正确的状态上提取**——失败轨迹的价值密度取决于失败模式是否可复现（埋雷验收的"拒收通路"就是在采这个信号）。

## 二、四种沉淀：经验变成什么

轨迹信号最终沉淀为四种产物（综述定版的"what to evolve"，加上 ∆-∇ 连续体——Microsoft 框架）：

| 产物 | 形态 | 固化模式 | 我们的资产 | 激活方式 |
|------|------|---------|-----------|---------|
| **知识** | 陈述性记忆（事实/规律/反例） | ∆ | 幸存不等式→知识卡；Obstruction 死路卡；卷积闭包表 | 检索 |
| **指令** | prompt/规则 | ∆ | Prover 十条规律→prompts.py；讲透Skills 的 SKILL.md | 触发匹配 |
| **程序** | 可执行代码/工具 | ∆ | **T4b 三层过滤漏斗脚本**；oprover-math skill；remote/ 脚本群 | 调用 |
| **参数** | 权重 | ∇ | 暂缓（Prover RL 化期权；MOPD 图纸已备） | 前向传播 |

**∆→∇ 的单向内化路径**是成熟系统的标志（结构搜索发现有效配置→参数化吸收）——我们目前全在 ∆ 侧，∇ 侧的图纸（MOPD）已在后训练综合备好。

## 三、更新对象的逐层扩大：五级深度定版

用户框架"单条规则→结构化上下文→工作流→Harness 代码→优化器代码"已被 2026 综述（可靠自进化 survey）定版为五级，**每级配一个特征失败模式**：

| 级 | 更新对象 | 特征失败 | 我们的实例 | 状态 |
|----|---------|---------|-----------|------|
| **L0 输出级** | 当前输出/任务内轨迹 | 自我确认（self-confirmation） | Self-Refine 式迭代；单次会话内改答案 | ✅ 日常 |
| **L1 模型级** | 权重 θ | 模式坍缩/奖励黑客 | TTRL/RLVR（文献）；我们暂缓 | ○ 期权 |
| **L2 脚手架级** | prompt/skill/记忆/工作流/harness | **脚手架过拟合**（scaffold overfitting） | 讲透Skills 的渐进披露优化；发现引擎 Obstruction 记忆；**记忆/知识卡全自动治理** | ✅ 主力 |
| **L3 改进器级** | 产生更新的程序本身 | **指标捕获**（metric capture） | **T4 的 R4 规则**（外环改外环的守卫参数）；E4 Phase A 诚实外环 | 🔶 雏形 |
| **L4 准则级** | 评估协议/奖励/约束/价值观 | **准则漂移**（criterion drift） | ③裁决（人定攻坚方向）；验证阶梯本身作为不变式 | ◐ 原则性实践 |

**可靠性判据**（该综述最值钱的一句话）：*"Reliable self-evolution depends not on self-evolution depth alone, but on whether evaluation and oversight remain independent of the update and cover the relevant tasks."*——翻译成我们的话：**L 越深，验证阶梯必须站得越外**；L3/L4 的最小安全架构是三角色分离："执行产生经验；改进者提议变更；**独立审计决定留存**"（=maker/improver/criterion 三权分立，讲透Loop maker-checker 的进化版）。RSI 边界：递归自改进从 L3 开始、L4 延伸——恰是 2607.07663"方向设定留在人类手里"的结构位置。

## 四、长期闭环：发现循环 + 两能力轴

**发现循环**（假设→实验→评估→反馈）的 Agent 版 = MATH_LOOP_ENGINE 七阶段循环的泛化；闭环要长期运转，需要两个**独立**的能力：

- **Harness-updating（更新能力）**：从轨迹产生**有价值的持久修改**——产出侧。判据：修改的期望收益 > 维护成本（否则是知识库膨胀）；
- **Harness-benefit（受益能力）**：任务 Agent 在后续运行中**找到、激活并正确使用**这些修改——消费侧。判据：修改的激活率与正确使用率。

**两轴独立是关键洞见**：updating 强 benefit 弱 = 知识库坟场（写了没人用——大部分 RAG 系统的宿命）；benefit 强 updating 弱 = 复用旧经验但无新沉淀。闭环健康度 = min(两轴)。Microsoft 框架补充第三轴：**选择压力来源**（H=0 自主 vs H≠0 人类介入）——人类输入还应细分为示范/评价/协作/隐式信号，且**人的认知容量本身会被进化过程重塑**（co-evolution 反身性：工具越强人越依赖，监督质量下降——这就是为什么要 L4 准则外置）。

## 六、可验证闭环的边界：当"完成"不等于"进步"

四条我们用血换来的定律在此汇成一句：**闭环的"完成"信号若与"进步"不同构，闭环会精确地完成不进步**——

1. 自评完成 ≠ 完成（87.3% 早停，讲透Loop E2）；
2. SFT 完成 ≠ RL 后好（PEAR 秩反转，后训练综合）；
3. 代理指标完成 ≠ 真值（Goodhart 剪刀差 +193% 假产出，T3/E4B）；
4. 验证完成 ≠ 数学进步（121k 图零违反 ≠ 定理——C1 还需 Lean 化/文献确认才是**不可逆推进**）。

**操作性定义**：进步 = 在验证阶梯上**至少上升一级的不可逆状态变化**（数值→符号→形式→文献确认）。 sleeps cycle 的整合也应以此为准：整合的产出若不能提升下一轮的验证层级或效率，就不是进步，是搬运。

## 七、持续进化的安全边界

- **深度-独立监督配对律**（§三）：每升一级更新深度，审计外移一级；
- **验证器即攻击面**：L2+ 的自进化系统里，被优化得最狠的往往是验证器本身（reward hacking 全家；污染 state file = 讲透Loop Ch06 冷水）——**准则（L4）最好放在系统外**（人/形式系统/git 历史）；
- **回滚是一等公民**：每次持久修改带快照与 diff（我们的 git 纪律；370 行批次 commit 规矩；E4 每代存配置）；**kill switch**（睡眠 worker 权限只限记忆/缓存，不得改代码/花钱/联系用户——sleep-time 工程模式铁律）；
- **一致性协议**（后台整合与前台运行的竞态）：单写者/乐观并发版本号/快照处理三选一（数学域实践将采用快照+版本）。

2026 三篇实证 + 一篇工程文把"离线巩固"从比喻变成技术：

| 系统 | 机制 | 数字 | 对我们的启示 |
|------|------|------|-------------|
| **Auto-Dreamer**（2605.20616） | 快写（会话内 append-only）+ 慢整（跨会话区域重写：region 只读→合成紧凑替换集）；**GRPO 用端到端任务性能训练 consolidator** | 记忆库 12× 小 + 7 分；跨域迁移（ScienceWorld 训→ALFWorld/WebArena 用） | 两时间尺度是正确架构；**整合本身可以学习** |
| **SCM**（2604.20943） | NREM（重放强化共现）/REM（**做梦=高价值概念的新奇组合**）/价值遗忘（重要性×时间衰减，自适应阈值控稳态大小） | 噪声 -90.9% 保关键召回 | **REM=发现引擎的隐喻实现**：梦=从知识图生成新组合——我们的猜想生成就是 agent 的 REM |
| **Compaction Cliff**（2608.22752） | 类型盲压缩：**安全规则 1 轮存 53%、5 轮存 10%**；Knowledge Triage 分型三通道（约束零失真/信念可压/情节占位） | TypeCompact 保安全规则 2-4× | **遗忘必须有类型通道**：验证规则/已知定理蕴含等"约束类"知识零失真；轨迹日志才可压 |
| **RecMem** | 复发触发（θcount 次相似交互才整合） | 构建 token -87% | 不是每条轨迹值得 LLM 整合——**复发=价值信号** |
| Sleep-time 工程 | 前台/后台分离；一致性三协议；provenance 边 | — | 后台 worker 权限最小化 |

**与我们理论的对接**：遗忘地板 e\*=f/(r+f) 是睡眠学习的**数学骨架**——SCM 的自适应阈值就是在调 f 使稳态大小落在目标区；Compaction Cliff 证明"均匀 f"在异质知识上是灾难（安全规则的 f 必须为 0）；RecMem 的复发触发=用信号价值调 r。**保鲜**（capability preservation）= 定期回归测试（我们的埋雷集就是回归测试集）+ replay（保留依赖子图重放——动态图综述的 continual learning 方案）。

### 9.4 与 C1 攻坚的关系（L4 实践标本）

C1 攻坚的每一步都是 L4 准则守护下的持续进化：文献深查（人审 open）→ 121k+293k 图验证（L4 数值）→ Lean 陈述通过（L5 形式）——**验证层级每升一级，结论的不可逆性升一级**。若未来 REM 做梦生成 C1 的变体猜想（如"有向图版/加权版"），整个管线无需改动——这就是"准则外置+五闭环"设计的复利。

## 十、批判与开放问题

1. **benefit 轴的量化方法学不成熟**：激活率/正确使用率的测量本身会改变行为（观测者效应）——文献也缺（自进化综述的 evaluation 章承认）；
2. **睡眠整合的学习**（Auto-Dreamer 式 GRPO 训 consolidator）在我们语境=用发现引擎的成败训练"整合策略"——**L1×L3 交叉**，需要 θ 侧启动，是 MOPD 的姐妹期权；
3. **co-evolution 反身性**（人被工具重塑）对个人学习系统的意义未被吸收：MATH_LOOP_ENGINE 的"人在环"位置需要定期重校准（每季 review 人的判断是否被引擎的输出绑架）；
4. **开放数学问题**：五级深度×验证阶梯的**配对定理**不存在（"L_k 级更新需要至少几级独立的验证"是经验律非定理）——可作为 AI_MATH_FOREST 的 L3 入口新条目。
