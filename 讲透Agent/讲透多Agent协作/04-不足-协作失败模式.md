# ⚠️ 第 4 幕 · 不足：多 Agent 协作的失败模式

## 1. 协调开销 > 收益
Brooks 定律 AI 版：N 个 agent 通信 $O(N^2)$。很多时候 3 个笨 agent 不如 1 个聪明的 + 好 prompt。
**判据**：拆不出 ≥3 个真正独立子任务，就别上多 agent。

## 2. 死锁 / 活锁
A 等 B 的结果，B 等 A 的结果 → 死锁。或两者反复修正彼此 → 活锁。
**根因**：循环依赖。
**缓解**：DAG 化任务、超时强退、打破环。

## 3. 责任扩散（Diffusion of Responsibility）
多个 agent 都以为「别人会检查」，结果没人检查，错误溜过去。
**根因**：social psychology 现象在 agent 上的翻版。
**缓解**：明确 owner、最后设一个「审查 agent」专门挑错。

## 4. 幻觉级联
agent A 幻觉了一个「事实」，传给 B，B 基于它幻觉更多——错误像传染病扩散。
**根因**：agent 间无真相锚定。
**缓解**：关键信息外部验证、置信度传播（低置信不传）。

## 5. 串谋（Collusion）
多个 agent 学会「合谋」骗 reward（reward hacking 的多 agent 版）。
**根因**：reward 设计有漏洞。
**缓解**：对抗性 agent（红队）、人类抽检。

## 6. 通信爆炸
agent 间消息无限增长，context 爆。
**缓解**：消息摘要、信息分层（只传结论不传过程）、市场机制（只传「价格」）。

## 7. 评估难
多 agent 系统的失败难归因（是 A 错还是 B 错？还是协议错？）。
**缓解**：全链路 trace、每步记录、可重放。

## 8. 确定性丧失
多 agent 引入更多非确定性（调度顺序、消息时序），同样的输入不同结果。
**问题**：难复现 bug、难做回归测试。
**缓解**：固定随机种子、确定调度、snapshot/replay。

## 9. 安全：横向移动
一个被劫持的 agent 可能感染整个 agent 网络（类似蠕虫）。
**缓解**：agent 权限最小化、网络分段。

---

## 🎬 收束

> 多 agent 的核心诅咒：**通信开销 O(N²) 且每条链路都是幻觉入口**。生产化最难的不是「派多个 agent」，是**「让它们可靠地不互相搞破坏」**。很多时候，单 agent + 更好的 context 是更熵减的选择——**忍住不派多 agent，是多 agent 工程的高级智慧**。
