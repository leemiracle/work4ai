# Agent 设计总纲：从器官到主体（2026-08-27）

> **本文是什么**：把本仓库全部实证教训（讲透Loop 循环设计学 / 记忆系统 44 仓 / 持续进化五闭环 / 后训练状态分布观 / 发现引擎实战 / A05b 七层架构）**收敛为一份 Agent 设计总纲**——回答"怎么设计好一个 Agent"，并诚实指出我们目前"引擎多而 Agent 缺"的结构性缺口。
> **定位**：后续一切 Agent 建设的宪法。新机制先过本文的设计审查，再动手。
> 实例化语境：数学研究 Agent（MathAgent）；设计本身宿主无关（A05b 方法论的直接应用：骨架换肉不换）。

## 〇、七条设计原则（全部来自我们自己的实验教训，无一条是抄来的原则）

| # | 原则 | 教训来源 |
|---|------|---------|
| **P1 验证层级决定一切** | Agent 的自治上限 = 其验证器的最高层级（L1 自评→L3 判官→L4 测试→L5 形式）；每个"完成"信号必须声明层级 | C1 攻坚全流程；87.3% 自评早停（Loop E2） |
| **P2 三权分立** | 执行者/提议者/审计者分离；**审计必须独立于更新边界之外**（改哪层，验证站哪层之外） | T4 R4 规则；L4 保护集 veto；2607.07663 |
| **P3 信号施加在正确的状态上** | 学习信号的价值 = f(信号质量, 施加分布)；在 Agent 自己会到达的状态上学 | OPD 状态分布观；T3 窄空间 UCB 反输 |
| **P4 两能力轴，健康度 = min** | updating（产出持久修改）× benefit（后续激活使用）；**benefit 未测量 = 闭环未闭合** | benefit 1.7%→18.6% 实测；坟场定律 |
| **P5 完成 ≠ 进步** | 进步 = 验证阶梯上至少一级的**不可逆**状态变化；循环可以精确地完成不进步 | Goodhart 剪刀差 +193%；PEAR 秩反转 |
| **P6 睡眠节奏** | 快写慢整（会话内 append + 睡眠时区域重写）；遗忘分型（约束零失真/事实可压）；复发才值得整合 | sleep_cycle 实跑；Compaction Cliff |
| **P7 深度-审计配对** | 每升一级更新深度（L0→L4），审计外移一级；L4 准则（评价标准本身）最好放在系统外 | L3 规则被 L4 保护集管住；F-001 升级被 L5 卡住=纪律生效 |

**一句话总纲**：Agent = 在验证阶梯约束下，沿四层堆栈组织起来的、按睡眠节律运转的持续进化系统——**它的一切能力边界由验证器决定，一切成长由两能力轴衡量，一切安全由深度-审计配对保证**。

## 一、Agent 身份：先回答"它是谁"，再谈"它有什么"

设计 Agent 的第一问不是架构，是**身份三要素**（多数 Agent 设计的缺失项）：

```
身份 = Goal（什么算完成——机器可查的终态定义）
     + Scope（做什么/不做什么——负空间显式化）
     + Memory Contract（跨 run 记住什么/忘什么/谁可改）
```

**MathAgent 的身份三要素（示范）**：
- **Goal**：产出"验证层级 ≥ L4 且文献定位明确"的数学陈述（发现/加强/形式化）。终态五件套之一：verified（过阶梯）/ known（文献已收）/ refuted（反例）/ stalled（熔断）/ exhausted（预算）——**不允许无声消失**；
- **Scope**：做——不等式发现/猜想验证/Lean 形式化/文献定位；不做——参数训练（∇ 侧暂缓，理由见 §六）、开放式研究方向自主设定（L4 留人类）；
- **Memory Contract**：math_kb（分型知识库，NREM 唯一写入者）；dreams（梦必须过阶梯才转正）；regression 锚（约束类，只能加不能删）。

**推论**：没有身份三要素的 Agent 是脚本集合，不是 Agent。我们此前的"发现引擎"缺的正是显式身份——它是靠任务惯性而非身份定义在运转。

## 二、四层堆栈：Agent 的骨架（宪法主轴）

```
┌─ L3 Loop 层：谁触发、怎么验证、何时停、状态在哪 ─────────────────┐
│   外循环：cron 触发（睡眠）/ 任务触发（唤醒）/ goal 驱动（攻坚）    │
│   三守卫全套（cap/熔断/独立验证）+ 五终态 + 断点卡（RESUME 协议）   │
├─ L2 Harness 层：单次 run 的器官编排 ────────────────────────────┤
│   器官注册表：生成器/验证器/KB/LP判型器/文献查证（现有零件全在这层）│
│   器官间协议：输入输出 json + 溯源字段（activated_count 回写）      │
├─ L1 Context 层：每轮窗口里放什么 ───────────────────────────────┤
│   注入经济学：稳定进 system（吃 cache）/易变 prepend/原始下沉工具   │
│   数学域实例：KB 规则表前置（18.6% 过滤）+ Obstruction 死区        │
├─ L0 Prompt 层：单次调用怎么问 ──────────────────────────────────┤
│   角色提示词三份分离：proposer / verifier / auditor（P2 的 prompt 侧）│
└──────────────────────────────────────────────────────────────────┘
```

**骨架判断律**（A05b 模式 15）：设计新 Agent 先画此四层再填肉；缺失层显式标"无"，不许默认不存在。**我们现有零件全部在 L2（器官层）**——这正是主体缺失的含义：L3 没有统一的调度主体，L1/L0 没有按角色分离的注入设计。

## 三、横切面：三个子系统贯穿四层

### 3.1 记忆（三层 × 分型）

| 层 | 内容 | 写者 | 保真 |
|----|------|------|------|
| 工作记忆 | 当前 run 的任务状态+断点 | 执行者 | 易失（RESUME 沉淀） |
| 知识库 | math_kb（约束/事实/轨迹） | **NREM 唯一** | 约束 exact / 事实可压 |
| 经验库 | Obstruction 死区 + kb_rules + L3 规则 | 各自闭环回测后 | 可演化（带 precision 记录） |

### 3.2 学习（五级深度 × 两轴）

- 当前定位：L2 主力 + L3 最小实现（precision 1.0 已回测）；L1（∇）明确暂缓；
- **每次学习动作必须回答两问**：改的是哪一级？benefit 怎么测？——答不出就不做。

### 3.3 治理（三权分立的实例化）

```
执行者（发现引擎各 run）──产出──▶ 提议缓冲（候选知识/规则/梦）
                                        │
                          独立审计（regression 锚 + L4 保护集 + 人）
                                        │ PASS
                                        ▼
                              KB 写入（NREM 统一执行）
```

## 四、生命周期：一次完整 run 的解剖（Agent 主循环规格）

```
唤醒（cron 07:30 睡眠 / 任务触发 / goal 续跑）
  → 读身份（Goal/Scope/Memory Contract）+ 断点卡
  → 回归自检（regression_suite：地基没漂移才继续——P7）
  → L1 注入（KB 规则表 + 死区 + 任务上下文，按注入经济学）
  → L2 器官编排（生成→级联验证→漏斗，全程 activated_count 回写——P4）
  → 终态判定（五终态之一，机器可查——P1/P5）
  → 提议缓冲（新知识候选 → 独立审计 → NREM 择机写入）
  → 睡眠（整合复发计数 / REM 做梦入缓冲 / 分型遗忘）
  → 断点卡更新（读帧写验，事实非 vibes）
```

**关键缺口**：这个主循环目前**不存在**——现有零件（regression/sleep/benefit/discovery）各自被手动/cron 独立触发，没有一个主体按此规格统一调度。这就是"设计好 Agent"之后要建的第一件东西（见 §七）。

## 五、与现有零件的映射（诚实对账）

| 设计件 | 状态 | 资产 |
|--------|------|------|
| 器官（L2） | ✅ 齐全 | 发现引擎 T1-T4b / sleep_cycle / regression_suite / benefit_run / l3_miner / KB 10 卡 |
| 守卫与终态 | ◐ 散落 | 各实验有 timeout/埋雷；无统一五终态判定 |
| 断点卡 | ✅ | RESUME 协议（讲透Loop Ch06）+ 各结果卡 |
| 独立审计 | ✅ 最小 | L4 保护集 + regression 锚 |
| **主循环主体** | ❌ **缺** | 无统一调度者（当前=人/cron 拼凑） |
| **角色分离的 L0/L1** | ❌ 缺 | proposer/verifier/auditor 三份提示词与注入策略未分离 |
| **身份文档** | ❌ 缺 | 本文档 §一 是规格，尚无 Agent 可读的身份实例 |

## 六、不做什么（负空间——与正设计同等重要）

1. **不做 ∇ 侧（参数训练）**：当前验证器全在 L4 以上，∇ 侧收益无法按 P5 度量；等 C1 类成果证明管线价值后再启动（MOPD 图纸已备）；
2. **不做 L4 自主**：研究方向设定/准则修改永远留人类（RSI 边界 + co-evolution 反身性）；
3. **不做无 benefit 测量的新机制**：每个新器官上线前先回答"activated_count 从哪来"（P4，防器官增殖）；
4. **不做无身份的自动化**：任何新 cron/循环必须挂到身份三要素之下，否则是脚本不是 Agent；
5. **不追器官数量**：当前零件已够支撑一个完整 Agent 的一生——**接下来一年做减法（组装/打磨），不做加法**。

## 七、实施路线：从器官到主体的三步

| 步 | 内容 | 规模 |
|----|------|------|
| **A. 身份实例化** | 写 `loops/agent_identity.yaml`（Goal/Scope/Memory Contract/器官注册表/终态定义）——主循环的配置真源 | 半天 |
| **B. 主循环主体** | `math_agent.py`：按 §四规格的调度器（读身份→回归→注入→编排→终态→提议→睡眠），把现有六器官挂进注册表 | 1-2 天 |
| **C. 角色分离注入** | proposer/verifier/auditor 三份 L0 提示词 + 三套 L1 注入策略（P2 落到 prompt 层） | 1 天 |

完成三步后，Agent 才真正存在——此前的所有建设是它的器官培养皿。

## ✍️ 练习（给设计者自己）

1. 用身份三要素给你手头任何一个"自动化脚本"打分——多数会卡在 Goal 没有机器可查的终态。这一问就是"脚本 vs Agent"的分界。
2. §五 的三个 ❌ 为什么都指向"主体"而非"零件"？（提示：器官培养皿 vs 生物体——差的是循环调度与身份连续性。）
3. 负空间设计（§六）里哪条最难守？（提示：P4——新机制的诱惑总是以"以后再测 benefit"进门。）
