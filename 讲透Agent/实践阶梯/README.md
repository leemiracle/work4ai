# 实践阶梯 · 端侧事实记忆 Agent

> **讲透Agent 的实操单元**：用 L1→L5 实践阶梯，把「读别人的仓库」变成「会造自己的 agent」。
> **真实载体**：端侧事实记忆 Agent——CPU-only 环境跑 Qwen2.5-0.5B，从用户话语中抽取事实（日程/账单/人际/档案/健康）存为 memory，再服务意图识别。
> **为什么这个场景**：模型越小，agent 工程杠杆越大。0.5B 的幻觉与能力短板是放大镜，让每一层工程矫正的价值都可测量——这正是「衡量 agent 各类技术」的最佳实验台。

## 第零号证据（2026-08-24 实测，一切设计的出发点）

裸模型（无示例、贪心、要求严格 JSON）在 5 条中文事实句上：

| 层 | 结果 | 细节 |
|---|---|---|
| JSON 语法层 | **5/5 通过** | 格式全对，0 解析失败 |
| 语义层 | **0/5 合格** | category 越界 4/5（输出"日期/地理/药物/财务"，枚举只允许 日程\|账单\|人际\|档案\|健康）；fact 字段塌缩成标签词（输出"日期"而非"明天早上八点去医院复查"） |
| 速度 | 7.0 tok/s @1 核 | 多线程无收益（4核6.8 / 8核6.7）——0.5B 太小，同步开销吃掉增益 |

**结论**：语法缺陷可靠约束解码修（outlines/grammar/校验重试），**语义塌缩只能靠 agent 工程修**（few-shot 示例 + 枚举校验器 + 证据接地：fact 必须是原句子串）。这是本单元「模型弱→工程矫正」主线第一证。原始日志：[experiments/smoke.log](./experiments/smoke.log)。

## 终局对照（L3 评估环，34 条任务集 × 5 版）

| 版 | 改动 | ★pass | 关键发现 |
|---|---|---|---|
| A | 裸指令 | 6/34 | cat_ok 仅 6，塌缩 32 处 |
| B | +few-shot | 8/34 | 塌缩 32→**0**，cat_ok 6→24：语义层第一杠杆 |
| C | +反馈修复重试 | 7/34 | 27 次重试**净负**——小模型防线前移优于事后修复 |
| D | +漏抽拆句重抽 | **10**/34 | 对症漏抽 +2 有效 |
| E | +词袋接地 | 8/34 | 与 B 持平：误杀是少数，漏抽才是主杀手 |

**评估环否决了本单元自己的三个设计断言**：金标准精确匹配（→多重集）、"闭集永远用 scoring"（→受限 generation 65% > PMI 41% > naive 27%）、反馈重试有用（→净负）。详见 [03-L3评估环](./03-L3评估环.md) §四。

## 执行环境（开发-运行分离）

- **开发侧**：本机写脚本（本仓库 `讲透Agent/实践阶梯/`）
- **运行侧**：内部服务器 docker 容器（96 核 CPU / 503G 内存 / torch 2.9 cpu / transformers 5.12），容器内模型路径 `/work/models/Qwen2.5-0.5B-Instruct`（954M，f32 safetensors）
- **工作流**：scp 推脚本 → 容器内后台跑 → scp 拉回日志/产物存档 experiments/（**模型与日志绝不进 git**）
- 容器内跑长任务用 `docker exec -d` 后台 + 日志轮询（防交互超时）
