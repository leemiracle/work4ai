# 05 · L4b 意图识别：一场被评估环救回来的设计事故

> 本章是整个单元的戏眼：**00 章的设计断言（"闭集任务永远用 scoring"）在这里被
> 自己的实验证伪，修正后才拿到正确架构。** 评估环不是形式主义，它连设计者本人
> 的直觉都审。

## 一、实验设计

三种意图判别方法对照（[04b_intent.py](./experiments/04b_intent.py)，意图闭集 7 类，测试 22 句=7意图×3+2 句真模糊）：

| 方法 | 原理 | 成本 |
|---|---|---|
| naive scoring | 逐意图 teacher-forcing 算平均 logprob，排序 | 每意图 1 次 forward，零采样 |
| PMI scoring | 同上再减"中性锚下的意图先验"（logP(it\|句)−logP(it\|锚)） | +7 次一次性 forward |
| generation | chat template+意图列表受限生成，字符串匹配回集合 | 每句 ~12 token 自回归 |

外加 **margin 弃权闸**：top1−top2 分差 < 阈值 → 回问用户而不是硬答。

## 二、实测终局（2026-08-24，容器 96核CPU，295s）

| 方法 | acc（不弃权） | 最佳弃权点 | acc\|answered |
|---|---|---|---|
| naive scoring | 6/22 = **27%** | m=0.5 弃 9 | 46% |
| PMI scoring | 9/22 = **41%** | m=0.5 弃 5 | **53%** |
| generation | **13/20 = 65%** | （未设弃权） | — |

先验表（中性锚下意图自身的 logprob）：闲聊 −6.74 / 查账单 −6.02（短高频，naive 天然偏爱）vs 查人际档案 −9.70（长标签，naive 天然压制）。

## 三、事故分析：naive scoring 为什么只有 27%

1. **语言先验主导**："闲聊"2 token 且是高频句首词，P(闲聊|任意前文) 都不低——这个分数度量的是"闲聊是不是常见词"，不是"用户是不是在闲聊"。13 句里 9 句被 naive 判成闲聊。
2. **PMI 校准修复一半**（27→41）：减掉先验后"闲聊"泛滥治住了（降压药/血压/报告句全部救回 ✓）。
3. **但 PMI 引入新偏差**："查日程"（−8.27，中等低先验）被校准反向加分，"老王电话多少"错判为查日程；"查人际档案"标签太书面，0.5B 对它的条件理解弱。**标签措辞本身成了变量**。
4. **generation 为什么赢**：chat template + "从这些意图里选一个"的指令给了一个强任务框架，模型在框架内做的是"选择题"（它被指令约束），而 scoring 是"填空题"（无框架，裸概率）。0.5B 需要框架。

## 四、修正后的架构结论

> ~~闭集任务永远用 scoring~~（00 章原断言，**已证伪**）
> → **端侧小模型的意图判别：受限 generation 为主；scoring 只在 generation 不可用的场景（如批量离线打标签）作备选，且必须 PMI 校准。**

generation 也有自己的代价（实测：模糊句无法弃权、硬答"设提醒/查健康"），所以完整方案是 **generation + 弃权闸**：对生成意图词的 token 概率做 margin（首 token 的 top1−top2），低于阈值回问用户。这是 D 版之后的方向，未在本轮实现（诚实标注）。

## 五、margin 弃权曲线的读法

PMI 版：m=0 弃 0 → 41%；m=0.5 弃 5（23%）→ 53%。**每弃权 4-5% 的覆盖换 2-3pp 准确率**——在"错误答案伤信任"的语音助手场景值得；在"漏答也可重问"的 GUI 场景可以更激进。弃权阈值是**产品决策**不是技术决策，没有免费午餐。

## 七、批判

- 22 句测试集太小，65% vs 41% 的差距在 n=20 时置信区间宽（±20pp 级），结论方向可信、数值需扩集
- 意图标签措辞是自由变量（"查人际档案"vs"查人"），未做标签消融
- generation 的 65% 里"体检约在几点→查健康"算对还是算错有标注口径问题（既是日程查询又是健康主题）——又是金标准粒度问题，与 L1 教训同源
