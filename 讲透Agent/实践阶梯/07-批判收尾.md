## 二、最大的四个不足（诚实清单）

1. **实验室≠真端侧**。96 核服务器容器模拟"CPU-only 约束"，但真手机的内存带宽/散热降频/3-4 核 A55 级单核性能与此天差地别。7 tok/s 是这台服务器的数字，手机上 0.5B f32 可能只有 1-2 tok/s 甚至跑不动。**所有速度结论在真机验证前都是量级参考不是性能承诺**。
2. **规模太小**。任务集 34 条、意图测试 22 句、单一标注者、无 κ 一致性、贪心单跑无方差——每个数字的置信区间都很宽。本单元的方法论价值（评估环否决了三个设计断言）大于数值价值。
3. **f32 是过渡形态**。954M f32 在端侧是错的部署形态：量化到 int4（~350MB）+ llama.cpp 才是正道，预期提速 3-10×（0.5B 规模的 GGUF Q4 在中端手机可达 10-20 tok/s 级）。未实测（容器无 llama.cpp，且 llama_cpp Python 包未装），是明确的下一步。
4. **单轮抽取，非流式会话**。真实产品是持续对话流：一句"对了我爸那也是这样"要继承上文。本单元每句独立，上下文消解完全未做。

## 三、方法论的边界（什么条件下本单元全错）

- **模型换到 3B+**（如未来端侧 3B 量化可用）：few-shot 的边际价值下降、重试可能转正（meta 反馈理解力增强）、generation 与 scoring 差距收窄——矫正分层的重心整体上移，部分结论反转
- **任务换成开放域**（不限五类）：枚举校验失效，类别体系本身需要动态化——本单元的校验器全家桶建立在"闭集"这个前提上
- **隐私前提放松**（允许云端）：整个端侧设计作废，应直接换大模型——0.5B+重矫正的方案只在"数据不出设备"下是理性的

## 五、给"讲透Agent"主线回填的三条通识

> **方法论升级包（2026-08-24）**：《AI-Agents-in Depth》第7章（见 [../AI-Agents-in-Depth全书深读卡.md](../AI-Agents-in-Depth全书深读卡.md)）与本单元 L3 是同一主题的理论/实践两面。阶梯 L3 可直接吸收的四个升级：① **Pass@k vs Pass^k** 分离（能力上限 vs 连续可靠性——阶梯的"pass"是 Pass@1，34条上做 Pass^k 会更有说服力）；② **轨迹前缀回归**（截首个错误前状态只验证决策边界，比端到端回归便宜——E版归因时已隐含用到）；③ **评判者校准**（人工金标集+kappa 门槛——阶梯"无第二标注者"批判的官方解法）；④ 统计显著性的配对分析（McNemar/bootstrap——阶梯"±1条=±3pp"的经验判断的形式化版本）。

1. **校验器会与教学材料打架**（03 章 §3.3：few-shot 示例自己通不过校验）——给任何 agent 设计校验时，先拿自己的示例过一遍
2. **小模型防线前移**：预防（few-shot/校验丢弃）> 治疗（反馈重试）——重试预算应该花在"拆句重抽"这类结构性重访上，不是 meta 反馈上
3. **评估环连设计者的直觉都审**：本单元 00 章的两个断言（scoring 优先/重试有用）全部被自己的实验否决——"衡量 agent 技术的标准"最终是消融对照里活下来的东西，不是任何权威的 best practice
