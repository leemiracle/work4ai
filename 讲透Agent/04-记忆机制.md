# 04 — 记忆机制：从上下文窗口到向量库

> 「讲透 Agent」第五篇。前三篇讲了循环、工具、规划，但都假设"Agent 记得所有历史"。本篇讲一个被严重低估的核心问题：**Agent 怎么记住 1000 轮对话之前的事？** 从上下文窗口（短期记忆）到向量库（长期记忆），到混合架构（现代 LLM 默认）。
>
> 配套实验：`experiments/04_memory.py`。

---

## 1. 灵魂：一句话钉死

> **记忆 = 记得准 + 塞得下 + 找得到。上下文窗口解决"记得准"但塞不下；摘要记忆牺牲"记得准"换容量；向量检索三者兼得但需要外部依赖。现代 Agent 必然是混合架构：短期用窗口、中期用滑动、长期用向量、元知识用摘要。**

$$
\underbrace{\text{Context Window}}_{\text{短期·工作记忆}}
\quad+\quad
\underbrace{\text{Sliding Window}}_{\text{中期·最近 N 轮}}
\quad+\quad
\underbrace{\text{Vector DB}}_{\text{长期·按需检索}}
\quad+\quad
\underbrace{\text{Summary}}_{\text{元知识·用户画像}}
$$

---

## 2. 为什么记忆是个被低估的难题

### 2.1 直觉：人和 LLM 的记忆差距

| 维度 | 人 | LLM（无外置记忆）|
|------|----|----|
| 容量 | 几乎无限（突触可塑）| 受限于 context window（4k~200k token）|
| 检索 | 联想式（语义+情境）| 顺序扫描（按位置读取）|
| 持久 | 跨年 | 单次会话 |
| 成本 | 几乎为零 | 每 token 都要付钱 |

**核心痛点**：LLM 的 context window 是"工作记忆"，但人对话 1000 轮的事实塞不进 200k token——必须把"长期记忆"外移。

### 2.2 实验证据：长对话下 5 种策略对比

50 轮长对话，每轮陈述一个事实（"张三的年龄是 25"）。第 51 轮随机问 30 个事实，看召回率：

| 策略 | 近端召回（最近 10 轮）| 远端召回（早期 20 轮）| 整体召回 | token/查询 |
|------|:------------:|:------------:|:------:|:---------:|
| **无记忆** | 0% | 0% | 0% | 0 |
| **全历史 N=10**（FIFO 截断）| **100%** | **0%** | 18.5% | 80 |
| **滑动窗口 K=5** | 51% | 0% | 11% | 40 |
| **摘要记忆**（30% 损失）| 70% | 72% | **72%** | 200 |
| **向量检索 top-3** | **100%** | **100%** | **100%** | **24** |

**结论**：
- 无记忆全丢；全历史近端完美但远端截断；滑动窗口只能记最近 K 轮。
- 摘要记忆的 72% 反而**比滑动窗口的 11% 高**——因为摘要保留了"事实存在"，丢了"具体值"；而滑动窗口直接把早期事实丢了。
- **向量检索三者兼得**：100% 召回，token 仅 24（是全历史 80 的 30%）。

## 3. 五种记忆策略逐一拆解

### 3.1 无记忆（Stateless）

每轮独立，历史完全丢弃。适合**单次问答**任务（如搜索引擎一次性返回结果）。

### 3.2 全历史（Full Buffer）+ FIFO 截断

把所有历史塞进 context window，超出窗口就 FIFO 截断（先进先出）。

```python
class FullBuffer:
    def __init__(self, window=10):
        self.buf = deque(maxlen=window)   # 自动 FIFO
    def add(self, msg): self.buf.append(msg)
```

**致命缺陷**：窗口满了早期就被挤出。50 轮对话问早期事实 → 召回率 0%。

### 3.3 滑动窗口（Sliding Window）

只保留最近 K 轮。比 FIFO 更激进——明确放弃早期。

```python
class SlidingWindow:
    def __init__(self, k=5): self.buf = deque(maxlen=k)
```

**适用**：客服场景"用户最近提到的实体"（如最近 5 次操作）。

### 3.4 摘要记忆（Summary Memory）

把旧历史压缩成摘要，**有损但保留事实存在**。

```python
class SummaryMemory:
    def add(self, fact):
        if random.random() > 0.30:    # 70% 保留细节
            self.summary.append(fact["text"])
        else:                          # 30% 压缩成"已遗忘"
            self.summary.append(f"{fact['subj']}的{fact['attr']}是[已遗忘]")
```

**反直觉优势**：摘要的 72% 召回 > 滑动窗口的 11%。因为摘要保留了"事实存在"（知道张三有年龄），丢了"具体值"（忘了 25）；而滑动窗口连"张三有年龄"都不知道。

### 3.5 向量检索（Vector Retrieval）

把所有事实存进向量库，query 时按语义相似度召回 top-k。

```python
class VectorRetrieval:
    def __init__(self, top_k=3): self.docs = []
    def add(self, fact): self.docs.append(fact["text"])
    def query(self, q):
        # 1. 把 q 和所有 docs 都 embed
        # 2. 算余弦相似度
        # 3. 取 top-k, 塞进 LLM 上下文
        scored = [(t, cosine(embed(q), embed(t))) for t in self.docs]
        scored.sort(key=lambda x: -x[1])
        return [t for t, _ in scored[:self.top_k]]
```

**为什么吊打其他**：向量库容量几乎无限（外存），LLM context 只装 top-k——把"容量"和"工作记忆"解耦。

---

## 4. top-k 的三边权衡

扫描 top-k（50 轮对话场景）：

| top-k | 整体召回率 | token/查询 | 相比全历史 |
|:-----:|:--------:|:--------:|:--------:|
| 1 | ~80% | 8 | 2% |
| 2 | ~92% | 16 | 4% |
| **3** | **~98%** | **24** | **6%** |
| 5 | ~99% | 40 | 10% |
| 10 | ~100% | 80 | 20% |

**甜区是 top-3 ~ top-5**：
- top-1 太激进，漏掉相关但语义略偏的事实。
- top-10 边际收益递减，token 翻倍但召回率只多 1-2%。
- **工程经验**：top-3 起步，看效果调到 5-7。RAG 系统通常 top-3-5。

## 5. 现代 Agent 的混合架构

ChatGPT Memory、Claude Projects、Cursor、Mem.ai 都用混合策略：

```
┌─────────────────────────────────────────────────┐
│ 用户对话                                         │
│    │                                            │
│    ▼                                            │
│ ┌────────────┐  当前轮    ┌─────────────────┐  │
│ │ 短期记忆   │ ─────────► │ Context Window  │  │
│ │ (本轮)     │            │ (4k-200k token) │  │
│ └────────────┘            └─────────────────┘  │
│    │                                            │
│    │ 滑出窗口                                    │
│    ▼                                            │
│ ┌────────────┐  最近 N 轮                       │
│ │ 中期记忆   │ ─────────► 滑动缓冲区             │
│ │ (近 N 轮)  │                                 │
│ └────────────┘                                 │
│    │                                            │
│    │ 超过 N 轮                                   │
│    ▼                                            │
│ ┌────────────┐  向量化                          │
│ │ 长期记忆   │ ─────────► Vector DB (Pinecone/  │
│ │ (历史事实) │            Chroma/Postgres+pg)   │
│ └────────────┘                                 │
│    │                                            │
│    │ 抽取关键事实                                │
│    ▼                                            │
│ ┌────────────┐                                 │
│ │ 元知识     │ ─────────► 用户画像 (持续更新)    │
│ │ (画像)     │                                 │
│ └────────────┘                                 │
└─────────────────────────────────────────────────┘
```

**查询时**：用户问 X → 同时检索短期 + 中期 + 长期 + 元知识 → 合并塞进 context。

**写入时**：每轮对话同时写入短期（context）+ 滑动（buffer）；N 轮后异步写入向量库 + 摘要。

## 6. 反直觉点

### 6.1 摘要比滑动窗口好

直觉上"摘要有损压缩应该比原文丢得多"。但实测摘要 72% > 滑动窗口 11%。因为滑动窗口**直接删除**早期事实（连"张三有年龄"都不知道），摘要**保留事实存在只丢值**（知道张三有年龄但忘了 25）。**"事实丢失" > "细节模糊"**。

### 6.2 向量检索不是万能

向量检索假设"语义相似 = 相关"，但有时相关事实语义距离远：
- 用户问"上次那个"——上次聊的是量子物理，但"上次那个"没有任何语义信号。
- 多轮指代消解：他/她/它需要会话结构，不是语义相似度。

**解法**：加**时间衰减**（近期事实加分）+ **会话结构索引**（同会话优先）+ **混合检索**（向量+关键词 BM25）。

### 6.3 长上下文（200k）不解决记忆问题

直觉上"GPT-4 128k、Gemini 1M token 应该够了"。但：
- **Lost in the Middle**（[Liu et al. 2023](https://arxiv.org/abs/2307.03172)）：上下文中间位置的信息召回率明显低于首尾。
- **成本**：200k 输入是 4k 的 50 倍费用。
- **延迟**：长上下文推理延迟线性增长。

**正确认知**：长上下文是"工作记忆扩容"，向量库是"长期记忆外存"——**互补不互斥**。

---

## 7. 一句话总结

> **记忆 = 记得准 + 塞得下 + 找得到。50 轮对话实测：无记忆 0%、全历史 N=10 远端 0%、滑动窗口 K=5 整体 11%、摘要 72%、向量检索 top-3 接近 100%——但 token 仅是全历史的 30%。反直觉点：摘要的 72% > 滑动窗口的 11%（"事实丢失" > "细节模糊"）。现代 Agent 必然混合：短期 context + 中期滑动 + 长期向量 + 元知识摘要——ChatGPT Memory、Claude Projects 都是这套。**
