# 讲透 Doriandarko/claude-engineer：Claude 3.5 世代的自主编程 agent 活标本

## 一、定位：从 AutoGPT 理想到原生 tool_use 的交点

Doriandarko/claude-engineer 是 2024 年中期（Claude 3.5 Sonnet 发布后）出现的**单人维护自主编程 agent**，29 文件同仓封存两代形态：

- **Claude-Eng-v2/main.py**（2235 行单文件巨石）：四模型角色分工的"瑞士军刀"——MAINMODEL 决策、TOOLCHECKERMODEL 消化工具结果（main.py:1886）、CODEEDITORMODEL 生成编辑块（main.py:590）、CODEEXECUTIONMODEL 分析执行输出（main.py:1202），四角色全部指向 `claude-3-5-sonnet-20241022`（main.py:309-312）。
- **根目录 v3**（ce3.py + tools/ 插件目录）：重构为 `Assistant` 类（ce3.py:29）+ `BaseTool` 抽象基类（tools/base.py:4）+ 13 个工具类插件的**插件化架构**，外加 Flask Web 界面（app.py:8）。

历史坐标上它属于 **AutoGPT（2023）与现代 coding agent（Claude Code/Devin 类）之间的过渡世代**：AutoGPT 靠 prompt 解析"伪工具调用"艰难驱动循环，而它已经用上 Anthropic 原生 tool_use API——`stop_reason == "tool_use"` 分支组装 tool_result 消息回填后 `return self._get_completion()` **递归自调用续跑**（ce3.py:394），这就是 ReAct 的 Act-Observe 环在原生 API 上的最简实现。README 宣称"No need for automode since Claude can intelligently decide when to run tools"（readme.md:13）——模型能力跃迁的自我意识。

## 二、agent loop 与工具集

**v3 主循环**（ce3.py:332-416）是教学级范本：`messages.create` 带拼接式 system prompt（DEFAULT+TOOL_USAGE，ce3.py:347）→ 遍历 content_block 执行工具 → 结构化结果（如截图 image block）原样保留进 tool_result（ce3.py:371-376）→ 递归直到最终文本。token 预算用 `max_tokens=min(MAX_TOKENS, 剩余预算)` 钳制（ce3.py:340），超 20 万即提示 reset——无官方 agent SDK 时代的手工上下文管理。

**工具发现是运行时的**：`_load_tools` 先清空 `sys.modules` 里 tools.* 缓存再 `pkgutil.iter_modules` 遍历目录逐个 importlib 加载（ce3.py:91-102），`inspect.getmembers` 找 BaseTool 子类抽取 name/description/input_schema 三元组直接作为 API 的 tools 参数（ce3.py:141-157）。最超前的是**依赖自愈**：某工具 ImportError 时解析缺失模块名，交互确认后伪造 `ToolUseMock` 假装模型调用 uvpackagemanager 真实执行安装并重试加载（ce3.py:55-73）——agent 系统自身也走工具协议的早期范例。

**toolcreator 自举**（tools/toolcreator.py:44-131）是点睛之笔：把自然语言描述填入内嵌 BaseTool 模板的 prompt，调 Claude 生成新工具代码、正则抽取工具名落盘到 tools/，用户输入 `refresh` 即热加载（ce3.py:159-177）——"用得越多能力越强"的自我扩展闭环，比现代 MCP 动态注册工具的理念早了半年。

v3 的 13 个工具覆盖文件系统（读/写/编辑/建目录）、网络（DDG 搜索 tools/duckduckgotool.py:33 免 key 爬 HTML 端点、正文抽取 webscrapertool 三级降级探测容器）、多模态（screenshottool 截屏转 base64 image block，tools/screenshottool.py:68）与质量环（lintingtool 包装 ruff）。

## 三、代码执行沙箱的三种形态

三种隔离策略同仓并存，一部微缩史：

1. **v2 本地 venv**：惰性创建 `code_execution_env` venv（main.py:246），代码写临时文件后 `activate && python3` 执行，`os.setsid` 建进程组（main.py:1012）、10 秒超时转后台常驻并登记 running_processes 供 `stop_process` 按 `os.killpg` 精确回收（main.py:1099）——**venv 只防依赖污染，完全不防恶意代码**。
2. **v3 云沙箱**：e2bcodetool 把代码送 e2b-code-interpreter 云端隔离执行，支持 base64 文件上传下载（tools/e2bcodetool.py:54-125）——唯一真正的安全边界，但要 API key。
3. **裸奔态**：v2 的 `run_shell_command` shell=True 直执行任意命令零校验（main.py:1105-1123），配合 automode 自主循环（main.py:2163-2215，`AUTOMODE_COMPLETE` 口令退出、25 轮上限、连续 3 次异常熔断）意味着**提示注入即可获得完整 shell**。现代 agent 的权限确认/沙箱分级（如 Claude Code 的 permission mode）在当时完全缺位。

## 四、与现代 agent 范式对照

| 维度 | claude-engineer（2024 中） | 现代范式（2025-26） |
|---|---|---|
| 上下文 | 文件全量注入 system prompt（main.py:524-527）+历史过滤（main.py:1727-1744） | 按需 Read+上下文压缩 |
| 编辑 | SEARCH/REPLACE 块 + difflib 模糊兜底（main.py:750-787） | 同源思想的字符串精确替换（Aider 谱系延续） |
| 工具 | BaseTool 插件目录 + 运行时发现 + LLM 自创工具 | MCP 协议标准化 |
| 降本 | prompt caching beta 早期采用（main.py:664-677）+四角色分账成本表（main.py:1966-2049） | 官方自动缓存 |
| 多 agent | 同模型四"角色"软分工 | 真多模型/子代理池 |

scan_folder（main.py:1142-1186）把整库压成 60 万字符 Markdown 喂模型，是"无 RAG 时代的暴力上下文"；decide_retry（main.py:1497）用第二个 LLM 调用裁决重试——这些手法在现代框架里都有直系后代。

## 五、使用建议与局限

**考古与学习价值高于实用价值**。读 ce3.py 的 400 行理解最小可行 agent loop，读 toolcreator 理解工具自举，读 v2 main.py 理解多角色编排与成本核算；**不建议直接跑**，硬伤清单：
- **ollama-eng.py 是移植半成品**：L33 `client = ollama.AsyncClient()` 却在 L322 按 Anthropic SDK 方式调 `client.messages.create`（Ollama 客户端无此方法，edit 工具一触发必炸），且 L266 引用的 `code_editor_tokens` 全文未定义——NameError 前置爆炸。
- **依赖声明三处漂移**：根 requirements.txt 缺 e2b-code-interpreter（pyproject.toml:39 有）→ 按 txt 装环境则沙箱工具必挂；v2 requirements.txt 的 anthropic 重复两次（L1/L5）且漏 pyaudio；pyproject 的 `project.scripts` 指向不存在的 `cev3.cev3:main`（pyproject.toml:115）。
- **提示词与工具箱脱节**：SystemPrompts.TOOL_USAGE 列的 Explorer/GitOperationsTool/ShellTool/SequentialThinkingTool（prompts/system_prompts.py:20-27）在 tools/ 目录均无对应文件——陈旧清单，模型会尝试调用不存在的工具。
- **安全三敞口**：run_shell_command 无防护；Web 前端 marked.parse 直接 innerHTML 无 sanitize（static/js/chat.js:38）；automode 下三者叠加。
- **工程卫生**：test.py 只测演示函数（test.py:57-99）不测 agent 逻辑——典型实验仓水位。

**一句话**：这是观察"原生 tool_use API 刚发布时，一个开发者如何手工拼出完整自主编程 agent"的最佳标本——递归续跑环、工具热发现、自创工具闭环至今仍是理解 agent 本质的最短路径；安全缺位与移植烂尾也正好标出那个时代个人 agent 项目的真实水位。
