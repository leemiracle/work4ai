# 02 · A/B 实验方法论卡（AgentKernelArena 模式）

> **问题**："衡量 agent 各类技术"的最大陷阱——你改了 3 个东西（模型+prompt+工具），结果变好 5%，**你不知道该感谢谁，也不知道该怕谁**。
> **答案**：控制变量法庭。AMD-AGI 的 [AgentKernelArena](https://github.com/AMD-AGI/AgentKernelArena) 把它做成了基础设施。
> 来源：2026-08-24 官方 README 一手检索（未克隆——HIP 环境依赖，方法论先落卡）。

## 一、核心设计：一次只换一个变量

AgentKernelArena 的自我定位：**A/B Testing and RL-Ready Environment for GPU Kernel Agents**。

```
同一批任务集 ──┬── 基线配置（baseline）──→ 同一评分管线 ──→ 结果 A
              └── 处理配置（treatment）─→ 同一评分管线 ──→ 结果 B
                     ↑ 只换一个变量，其余全部冻结
```

README 原文清单——可换的单变量：

> a different **model, prompt, MCP server, skill, tool, memory strategy, or policy**

冻结项：任务集、硬件、执行环境、评估规则（`while holding tasks, hardware, environment, and evaluation rules constant`）。

## 二、可复现性的三个硬承诺

1. **siloed-benchmarking**：每个 agent 跑在隔离环境里（防互相污染/防环境残留状态泄漏）
2. **客观可复现指标**：compilation / correctness / runtime / speedup / score——全部机器判定，无人工打分
3. **RL-ready**：同一套信号可以直接当 RL reward 用（`per-task compilation, correctness, runtime, speedup, and score signals that can be consumed as rewards`）——**评估基础设施与训练基础设施是同一套**，这是它和普通 leaderboard 的本质区别

## 三、多 agent 同台的真实用途

支持 Cursor Agent / Claude Code / Codex / SWE-agent / GEAK / mini-swe-agent / 自定义 agent 过同一接口——但同台不是为了排名，是为了**归因**：不同 substrate（宿主）跑同一任务，可以把"模型能力"与"harness 质量"两个混杂因素拆开——这正是 harness 精华线"测 harness 不测模型"基准观的落地。

## 四、最小内建版：我们的 A/B 清单（配合 03-perfloop 用）

任何 perfloop 改动，过这张 7 问清单才算数：

| # | 问题 | 不合格的典型反例 |
|---|---|---|
| 1 | 换的**唯一**变量是什么？ | "换了模型还顺手改了 prompt" |
| 2 | 任务集冻结了吗（同 seed 同输入）？ | 换了任务子集 |
| 3 | 硬件状态锁定了吗（频率/后台负载/缓存清理）？ | 一次跑在充电笔记本，一次在降温台 |
| 4 | 重复了几次（n≥3，报中位数±离散度）？ | 单次运行定胜负 |
| 5 | 基线结果存档了吗（可 diff）？ | "感觉比上次快" |
| 6 | 负结果记录了吗？ | 只报好听的（AKO4X 的 honest negatives 反例） |
| 7 | 结论的效应量超过噪声吗？ | 3% 提速 vs 5% run-to-run 方差（SOL-ExecBench 明示约 5% 方差） |
