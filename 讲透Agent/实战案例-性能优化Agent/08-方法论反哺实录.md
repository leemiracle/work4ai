## 二、双测实录（含三个当日现场课）

8 句子集 × A/B/C × 2 独立进程，`--verdict` 裁决：

```
===== 双测裁决（重叠 3 句 × A/B/C × 2 独立进程；run1 完成 3 run2 完成 5）=====
run1(重叠): A=0 B=0 C=0
run2(重叠): A=0 B=0 C=0
  B vs A: no-effect（两次均无差）
  C vs B: no-effect（两次均无差）
[非确定性探针] item 级翻转 0/9（greedy@threads=1 跨独立进程）——本轮稳定
```

现场课 1——**外部负载是活的混淆变量**：run1/run2 执行时机器 load average 5-7.6（外部任务抢核），单句耗时从预估 ~40s 漂到 ~190s。这正是 02 卡第 3 问"一次跑在充电笔记本，一次在降温台"的现场版：**不锁定硬件状态的跨 run 比较，测的是机器不是模型**。增量写盘（逐句 JSON）就是为此设计的断点保险。

现场课 2——**评估子集的选择本身决定结论可见性**：前 6 句恰是"双事实难句"（每句 2 gold facts，judge 要求类别+数量双匹配），所有版本 0 分——在容器全量 34 句上 B>A 的已知结论在这个子集上**不可见**。抽样偏差与双测协议互补：协议管"测得准"，子集管"测得着"。

现场课 3——**threads=4 跑不完就是数据**：首跑 threads=4 下 4 句耗尽 880s（~62s/生成），换 threads=1 提速 ~3×——perfagent 07 的"0.5B thread-adverse"从推理负载蔓延到交互式生成负载，端侧结论再+1：**0.5B 生成也钉单线程**。

## 三、verdict 语义（为什么 inconsistent 是一等公民）

单次 A/B 对照给出"B 好于 A"时，有三种真相：真改进 / 噪声 / 负载混淆。双测协议把它们分开：
- **confirmed**（两次同号）：跨负载稳健的真改进
- **rejected**（两次同负号）：稳健的退化（如容器版 C 重试净负）
- **inconsistent**（异号）：**单次结论作废**——不宣布、需第三次仲裁或加样本
- **no-effect**（两次均无差）：该子集分辨率不足（本次情形——难句全灭，版本差异不可见）

这四分支正是 perfagent `keep/revert/invalid` 语义在评估结论层的投影：**裁判的裁决也需要裁判**。

## 四、红队探针：majority-dummy 下界（意图识别指标 gaming 检查）

意图 TEST 集 n=20（另 2 条真模糊期望弃权），gold 均匀 7 类（各 3/2 条）：

| 策略 | 准确率 | 判读 |
|---|---|---|
| majority-dummy（永远猜"查日程"） | **15%** | gaming 下界：任何策略的"及格线" |
| naive scoring（已记录） | 27% | 仅 +12pp over dummy；n=20 二项 sd≈8% → **约 1.5σ，弱证据**——naive 可能不比无脑好多少 |
| PMI（已记录） | 41% | +26pp，约 3σ，可信 |
| generation（已记录） | 65% | **+50pp 真超额**——裸准确率有意义全靠 dummy 衬托 |

**方法论**：任何闭集分类指标发布时必须带 dummy 基线——`裸准确率 - dummy = 超额`才是真实能力（KernelBench"超 cuDNN 10% 再想想"的分类版：**先问比无脑好多少，再问绝对分数多高**）。当初 04b 的"naive 27%"若无 dummy 对照，会被读成"naive 有点用"；有了 dummy，27% 的成色立刻现形。
