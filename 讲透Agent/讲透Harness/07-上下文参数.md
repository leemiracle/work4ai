# 07 · 上下文参数趋同解：四大 harness 对照表

> 本章素材全部来自 Arize 2026-04-28 一手分析（已核实，2026-08-17 入档）——本章做的是**压缩成可抄的一页 + 指出趋同≠最优**。深化见姊妹单元 讲透Context（C 组件的理论层）。

## 直觉

四大 harness（Pi / OpenClaw / Claude Code / Letta）**独立设计**，却在上下文管理参数上收敛到几乎相同的数值——趋同解是"任务无关结构解"的强证据（Arize 非编码产品 Alyx 也独立收敛到同款）。

## 可抄参数表（2026-08-17 核实版）

```python
FILE_MAX_LINES = 2000            # 四家一致
FILE_MAX_BYTES = 50_000          # Pi/OpenClaw; Claude Code 预检 256KB(stat)
LINE_MAX_CHARS = 2000            # 超长行截断
PRE_READ_BYTE_GATE = 262_144     # stat 预检 256KB（token 密集文件会漏过 byte 门）
POST_READ_TOKEN_GATE = 25_000    # 读后计数（双层防御）
TOOL_RESULT_CAP = 50_000         # chars/工具
MESSAGE_CAP = 200_000            # chars/消息；超限落盘+2KB 预览
# 压缩触发（三档任选）
PI:      context_window - 16_384, keep_recent 20_000
OPENCLAW: 0.5 * window, 压缩前静默 turn 状态先落盘
CLAUDE:   window - 13_000 (~167K/200K)
LETTA:    0.9 * window, 滑动窗 30%起+10%步
ESTIMATED_TOKENS = chars // 4    # 估算启发式
INSTRUCTION_BUDGET = 150-200 条  # 前沿模型可靠遵循上限；系统已占~50
```

## 三层渐进披露（Zylos 2026-07，缓存×注意力经济学）

```
常驻身份层（AGENTS.md/SOUL.md，最前且永不改 —— prompt cache 命中）
指针/引用层（feature_list、文件路径、skill 索引）
按需全文层（读文件/加载 skill —— 运行时可逆决策）
```

讲透Skills E2 实测：渐进披露省 93.1% token；Claude Code 自己的 CLAUDE.md 指引"<200 行/40KB"。

## 批判：趋同 ≠ 最优（NFL）

四家互相学习 + 同源作者圈 → 趋同可能只是"模仿 + 局部最优"。你的任务分布偏离编码场景时（如 0.5B 小模型、超长会话、非英文语料），抄默认值后**必须用自己的回归集验证**（手册 10 章体检单）。本单元的对照实验：E1 harness 的 max_new_tokens=224 + 反馈截断 120 字符，就是按 0.5B 量身调的，不抄 2000 行。
