# 03 · ★ 验证即证据：幻觉式完成与三级金字塔

> 核心实验：**E2 验证器三级消融**（[experiments/e2_verifier_levels.py](../experiments/e2_verifier_levels.py)）

## 直觉

"agent 说做完了"是**观点**，"验证命令通过"才是**事实**。模型的最优解是"让回复看起来对"，世界的最优解是"让事情真的对"——V 组件用**世界本身的反馈**对抗语言的最优解伪造。

## 三级金字塔（手册 06 章骨架，本单元实测）

```
L3 语义验证   LLM-as-judge / maker-checker（贵、慢、覆盖语义）
L2 属性验证   断言：schema 合法、输出含/不含 X（快）
L1 确定性验证 编译/lint/类型/测试/规则集（最快、零误判）
```

## 本地复现（E2）

候选池：6 任务 × {1 个真实生成(t0.7), 合成逻辑坏(return None), 合成语法坏} = 18 个候选。三级验证器各跑一遍，V2 真执行当 ground truth：

```bash
cd 讲透Harness/experiments && timeout 1450 python3 e2_verifier_levels.py
```

**结果（results/e2_verifier_levels.json）**：

| 验证器 | 坏候选检出 | 好候选误杀 | 单次成本 |
|---|---|---|---|
| V0 自评（问模型"能过吗"） | 11/13（**漏报 2**） | 0 | **≈3862ms**（一次前向） |
| V1 结构（compile+签名） | 6/13（只抓语法层） | 0 | ≈0ms |
| V2 真执行（exec+断言） | 13/13 | 0 | ≈3ms |

![E2](../experiments/results/e2_verifier_levels.png)

## 三个读数

1. **V0 的两个漏报全在"看起来合理"的真实生成代码上**（逻辑错但语法对、长得像答案）——正是 Harness-Bench 命名的 execution-alignment failure（"plausible reasoning decoupled from verifiable output"，该基准失败症状 top1 contract/format 36.4% 同族）。合成坏候选反而全被抓：自评分辨得出"明显坏"，分辨不出"看起来对"。
2. **成本倒挂**：最不可靠的 V0 恰恰最贵（3862ms vs V2 的 3ms，1291×）。**先问 LLM 再不放心去跑测试 = 花大钱买不确定性**。
3. **V1 零误杀但只覆盖语法层**——分层原则实证：L1 能拦的绝不升 L3，L2 断言的绝不问 judge。

## 工程落地：任务三件套 + Goodhart 防御

```markdown
verify_cmd:    pytest tests/test_export.py -q      # L1 必须绿
verify_assert: output.rows == expected_rows        # L2 契约
verify_review: 导出顺序与用户时区一致（规格#42）      # L3 语义
done = L1 ∧ L2 ∧ (L3 ∨ 人工豁免记录在案)
```

Goodhart 反模式（指标被 gaming）：模型学会"让测试变绿"而非"让功能对"（改测试/特判输入）。防御：测试文件只读（Scope 隔离）+ 盲测集不进上下文。**maker-checker 分离**：生成与质检不同模型/不同 prompt——同模型自评是 Goodhart 温床（E2 的 V0 即"同模型自评"反面教材）。
