# 12 · 不足与展望：NFL、harness dependence 与收益饱和

> 收官章：harness 不是银弹——把它的**失效边界**画准，才知道什么时候该投资它、什么时候该换路。

## 一、NFL：harness 内部也没有免费午餐

AHE 消融（arXiv:2604.25850）是现成的实验证据：

| AHE 发现 | 数字 | 含义 |
|---|---|---|
| 增益定位 | tools/middleware/长期记忆承载全部增益；**system prompt-only 负收益** | "harness 有收益"本身都是分布依赖的（结构层 ✓ 文案层 ✗） |
| 跨模型迁移 | +2.3~+10.1pp，弱模型获益大 | **harness 收益随模型能力饱和而衰减**——它是能力补偿器，不是能力放大器 |
| 同家族非单调 | medium +2.3 / high +7.3 / xhigh +2.3 | harness 超参（step budget/timeout）对模型过拟合 |

本单元 E7（mini-Evo）在本地复现"harness 超参搜索的 train→held-out gap"——见 [09 章](./09-进化外环.md)。

## 二、harness dependence：弱模型的两面

Harness-Bench（2605.27922）：弱模型跨 harness 方差大——**同一个 0.5B，在好 harness 里和坏 harness 里是两个模型**。

两面性：
- **机会面**：预算有限时，投资 harness 比投资模型划算（23.8 分差距）
- **天花板面**：E3/E5 实锤——账本它读不准、SELECT 它选不对（0%），**harness 交付的状态与决策权，弱模型接不住**。对策是决策权代码化（E5），但那意味着这些能力**没有被模型获得**，只是被绕过了。模型升级时这些护栏要重新评估（AHE 同家族非单调的另一个读法）。

## 三、本单元自身的不足（诚实清单）

1. **任务规模**：E1-E7 全部 6-8 个迷你函数任务——证明机制存在，不证明幅度可外推（Harness-Bench 用 106 任务×5194 轨迹才敢报 23.8 分）
2. **模型单一**：本地全 Qwen2.5-0.5B + API glm 系——harness dependence 的"模型轴"只采了两个点（E6 的 glm-4-flash 太强，升级路径没触发）
3. **E6 升级侧未 exercise**：只演示了零遗憾侧（不亏损），救回侧（flash 失败→glm-5 救回）需要难分布
4. **E7 样本极小**：贪心搜索 6 个配置 × 4 任务，gap 噪声大（09 章如实标注）
5. **温度/采样**：E1/E2 部分条件用采样（seed 固定但单次），严格版需多 seed 重复

## 四、展望：三条已被证据指出的路

1. **配置级评估成为默认**（Harness-Bench 主张）：发布 agent 时报 model×harness 矩阵，而非单模型分数——你的 harness 上建私有回归集（任务失败史=私有 benchmark，手册 11 章）
2. **harness 进化外环工业化**（AHE→Meta/Self/Evo 谱系）：估→提取特征→优化→自动化，配冻结迁移验证防过拟合（E7/讲透Loop E4 是本地雏形）
3. **agent-native co-evolution**（Guo Phase 4）：模型开始感知 harness 状态（长上下文/工具学习/技能内化），harness 与模型边界重新划界——论述里"运行时操作系统"的最终图景

## 五、全单元一页总结

```
Agent = Model + Harness
可靠性 = V(验证即证据) × S(账本+代码化决策) × Scope(预算熔断) × L(生命周期) × C(参数趋同解) × T(工具+修复)
实证链：E1 FCR true→0 | E2 V0漏报2/13全在"看起来合理" | E3 无账本100%幻觉恢复,账本仍需代码化
       E4 零诚实放弃→cap熔断 | E5 SELECT 0%→100%(0调用) | E6 验证即级联零遗憾 | E7 harness超参过拟合
边界：收益随模型饱和衰减 × harness dependence × NFL（结构层✓文案层✗）
```
