# 00 · 开场白：从"怎么说"到"怎么跑"——工程四部曲收官

> 三层宪法：直觉 → 公式/结构 → 代码（bash 跑通）。本单元 = `讲透Prompt → 讲透Context → 讲透Loop → 讲透Harness` 的运行环境层收官。

## 一句话

**模型决定写什么，harness 决定何时/何地/怎么写。Agent = Model + Harness。**

## 四部曲各自回答什么

| 单元 | 对象 | 典型问题 | 典型失败 |
|---|---|---|---|
| 讲透Prompt | 单次调用的一句话 | CoT 怎么写、few-shot 放几个 | 措辞敏感、注入 |
| 讲透Context | 整个窗口的信息 | 放什么、怎么放、何时换 | Context Rot、压缩失真 |
| 讲透Loop | 循环的规格 | 停止条件、验证层级、轮次预算 | 自评早停 87%（讲透Loop E1） |
| **讲透Harness** | **这一切的组装与运行** | **可靠性从哪来** | **幻觉式完成、失忆、打转** |

walkinglabs 四层栈 prompt→context→loop→graph，harness 是装下全部四层的那辆车——**你在车外设计路，而不是坐在车里打方向盘**。

## 为什么现在（2026）

- 产业侧：Anthropic《Effective harnesses for long-running agents》、OpenAI《Harness engineering》、walkinglabs 11.4k★ 教程——"运行时层从幕后走到台前"
- 学术侧：2026 上半年四篇 harness 综述密集涌现（Meng/Li/Ning/Guo，引用见 [papers.md](../papers.md)）+ **Harness-Bench**（arXiv:2605.27922：同模型池换 harness 差 23.8 分）
- 用户侧：五仓家族（deepseek-{kernel,rust,rl,llm,agent}-harness）已把"换领域=换插件，宿主零改动"跑通——本单元 Ch11 活案例

## 批判性开场（Ch12 预告）

本单元同时给出 harness 的**失效证据**：AHE 消融里"仅改 system prompt 反而回退"；harness 收益随模型能力饱和而衰减（+2.3~+10.1pp 非单调）；Harness-Bench 的 harness dependence——**弱模型受 harness 影响最大**（本单元 E3/E5 的 0.5B 实测将两次撞上这堵墙）。harness 不是银弹，是把"模型能力缺口"补成"系统可靠性"的工程学。
