# 03 · 基准对比与领域定位：graphify vs codegraph 的正面对决

> 出处：上游 README "Benchmarks" + `BENCHMARKS.md`（链接级引用）+ 两仓库元数据（2026-08-14 核对）。
> 承接 [codegraph 案例 · 笔记 02](../../codegraph代码知识图谱/notes/02-基准方法论与诚实披露.md) 的"基准反欺骗"框架。

## 1. graphify 的基准：记忆赛道，不是代码智能赛道

graphify 报的是**长对话记忆/多跳问答**基准（LOCOMO n=300、LongMemEval-S n=50），对照系是 mem0 / supermemory——即它把自己放进"记忆层"赛道（YC S26 + app.graphify.com 的 always-on 记忆平台定位一致），而**不是** codegraph 的"agent 代码导航"赛道：

| 基准 | 指标 | graphify | 对照 |
|---|---|---|---|
| LOCOMO | recall@10 | **0.497** | mem0 0.048，supermemory 0.149 |
| LOCOMO | QA accuracy | 45.3% | **supermemory 49.7%**（赢家不是自己），mem0 27.3% |
| LongMemEval-S | QA accuracy | **76%** | 与 dense RAG 打平 |
| 图构建 | LLM credits | **0**（AST pass）| 多数系统按 token 计 |

方法学声明：同 harness、同模型、同预算；裁判盲评 + 第二裁判校验（**一致率 90.6%，Cohen's kappa 0.81**）；完整逐系统表 + 复现命令在 BENCHMARKS.md。

**诚实度判读**：
1. **主动报告自己输的指标**（LOCOMO QA 上 supermemory 更高）——与 codegraph 主动披露 residual context +80% 同一美德，通过 [`欺骗动力学`](../../../欺骗动力学-AI纪实验包.md) D4 透明检验。
2. recall@10 大胜 + QA accuracy 小输的组合本身就是信息：图检索召回强（0.497 vs 0.048/0.149），但答案生成端没有同等优势——**召回≠正确**，这个 gap 是诚实数字自己暴露的。
3. 裁判一致性 kappa 0.81 是"评测者可信度"的自证，可对标 codegraph 的"0/28 污染"声明——两家都用**方法学证据**而非仅结果说话。
4. 局限：两套基准（graphify 的 LOCOMO vs codegraph 的 7-repo tool-call）**不可直接互比**——没有任何 head-to-head 数字，任何"谁更强"的断言都是编造。

## 2. 正面对比表：两条 R3 路线的分岔

| 维度 | **codegraph** | **graphify** |
|---|---|---|
| 星数/许可 | 66.4k★ / MIT | **106k★** / Apache-2.0+MIT 双文件 |
| 语言/栈 | Rust 内核 + Node bundle，SQLite+FTS5 | **Python**（PyPI `graphifyy`），NetworkX + tree-sitter |
| 交付重心 | **MCP 常驻服务**（默认单工具 explore）+ CLI | **`/graphify` skill 按需构建** + 产物文件（CLI/MCP 可选）|
| 索引存储 | `.codegraph/codegraph.db`（本地派生，不共享）| `graphify-out/graph.json`（**git 提交共享**，union merge driver）|
| 新鲜度 | 三层 auto-sync（watcher 2s debounce + 横幅 + 连接对账）| `--update` 手动/post-commit hook 重建（AST 零成本）+ `watch`（debounce 3s）|
| 语料 | 代码（20+ 语言）+ 框架路由 + iOS/RN 桥接 | 代码（36 语法）+ **docs/PDF/Office/Google/图片/音视频/YouTube/arXiv** + MCP 配置 + SQL schema |
| 证据分级 | 桥接边标 `provenance:'heuristic'` | **每条边**三值 `EXTRACTED/INFERRED/AMBIGUOUS`，AMBIGUOUS 上报告待人审 |
| 图分析 | 调用路径 / blast radius / explore | **Leiden 社区 / god nodes / surprising connections / path / graph_diff / import cycles** |
| 为什么进图 | — | `# NOTE:/# WHY:` 注释、docstring、ADR/RFC 一等节点 |
| 记忆 | — | `save-result`/`reflect` → LESSONS.md 贴图 overlay |
| 协作 | 个人（platform beta 候补中）| `prs` 仪表盘 / `--conflicts` 合并序风险 / 团队共享图 |
| 后端 | 自带运行时 | 语义 pass 可选 gemini/kimi/claude/openai/deepseek/ollama/bedrock/azure |
| 遥测 | 匿名统计（可关）| **无遥测**（本地查询日志，默认开/关存在文档漂移，见笔记 02 §7）|
| 商业化 | getcodegraph.com 候补 | app.graphify.com 早期访问 + Enterprise（YC S26）|

**分岔的本质**（用本项目语言）：两者都做"预付熵减"，但付的位置不同——
- codegraph 把熵减付在**运行时新鲜度**（watcher/横幅/对账三层，索引永远追得上代码），赌"agent 每次问的都是当前代码"。
- graphify 把熵减付在**语料广度与团队共享**（一条图覆盖代码外的一切知识载体，且 commit 进 repo 人人同图），赌"项目知识 ≠ 源码"。

## 3. 定位结论与选型

- **日常代码导航/影响面**（"谁调用 foo""改这里会坏什么"）→ codegraph：常驻、秒级新鲜、调用边精确、驻留代价已知。
- **项目理解/架构考古/知识管理**（"auth 和 database 怎么连起来的""这个设计为什么这样""把 ADR/论文/会议视频也纳入"）→ graphify：path/god nodes/社区/why 注释是图谱独有查询，多模态语料无竞品。
- **团队**（图要人人一致、进 PR 流）→ graphify 的 commit-图 + merge driver + `prs --conflicts`；团队当前无协调成本预算则 codegraph 各自索引。
- **组合**：完全正交可叠加——codegraph 管热路径（编码时），graphify 管冷路径（理解/沉淀，周级重建）；一个读代码，一个读"代码+为什么"。

## 4. 对本项目的三点沉淀

1. **证据分级谱系成型**：dsh（单一日志账本）→ codegraph（heuristic 边标注）→ graphify（全边三值置信 + AMBIGUOUS 上报告）——"给 agent 供证据的基础设施"在 2026 年已把**证据溯源**当成 schema 必选字段，这是 [`欺骗动力学`](../../../欺骗动力学-AI纪实验包.md) 反欺骗机制工业化的又一实证。
2. **交付面光谱**：MCP 常驻（codegraph）↔ skill 按需（graphify）↔ prompt 注入（Aider）——工具的"存在方式"本身就是设计决策，graphify 的 20+ 平台矩阵证明 skill 路线的**分发优势**（106k★ > 66.4k★ 的主要解释变量之一：30 秒上手 vs 装两个组件）。
3. **文档漂移无处不在**：graphify README 的查询日志默认值自相矛盾、codegraph 撤回过未封锁的旧基准——**连最重视诚实的项目，README 也会骗人**；行号/版本钉版 + 源码复核（dsh 案例的方法）仍是黄金标准。
