# 05 · 任务图：分解、依赖与调度

> 讲透Graph 第 05 章 | 用到 E2（`experiments/E2_topology_cost.py`）

## 1. 直觉层：分解即图化

复杂目标第一步永远是拆——拆出来的子任务天然带依赖（先抓数据再分析）、并发（三个数据源同时抓）、验证（分析完得核对）。**任务分解的产物就是一张图**：节点=子任务/中间目标，边=先序/数据/逻辑依赖。

从 2023 到 2026，这条线从"人画图"进化到"机器找图"：

| 代际 | 代表 | 人/机分工 |
|------|------|----------|
| 人写死流程 | StateFlow（2403.11322） | 人画状态机，模型照着走 |
| 计划-执行分离 | ReWOO（2305.18323）：先出完整计划再执行，省 token；TDAG（2402.10178）：动态分解+按需生成 agent | 模型出计划（DAG），系统调度 |
| 编译器式并行 | **LLMCompiler**（2312.04511, ICML 2024）：把 function calling 编译成 DAG，无依赖调用并发执行 | 模型"编译"，运行时调度 |
| 图上规划 | Plan-over-Graph（2502.14563）：在依赖图上做并行调度 | 图是输入 |
| **自动图发现** | ADAS（2408.08435）/ **AFlow**（ICLR 2025）/ EvoFlow / MermaidFlow（安全约束演化） | 搜索空间就是"图的集合"，机器搜出最优工作流 |

AFlow 一代的深意：**workflow 本身成为可搜索工件**——agentic workflow 不再是人拍脑袋画出来的，而是 MCTS/进化搜出来的。MermaidFlow 再加一道保险：搜出来的图要过安全约束（不允许无限环、必须可达终点）。

## 2. 数学层：调度收益的天花板

任务图 $T=(V,E_d)$（$E_d$ 为依赖边），关键路径 $CP$ = 最长依赖链。$N$ 个任务、总工作量 $W$、关键路径工作量 $W_{CP}$：

$$\text{加速上限} \le \frac{W}{W_{CP}} \quad (\text{Amdahl 式})$$

**依赖不是敌人，是信息**：$E_d$ 告诉调度器哪些能并行（E2 的 fan-out）、哪些必须串行。LLMCompiler 的收益来源就一条：把 ReAct 循环里"串行等模型想下一步"的隐性依赖，替换成 DAG 里显式声明的最小依赖集——隐性依赖清得越干净，并行度越高。

**重规划（replanning）的数学**：静态计划在长任务上必然漂移（中间结果改变后继任务的输入）。TDAG 的答案是动态分解——每完成一步，重估剩余任务图。代价：每次重规划 = 1 次 LLM 调用 + 已完成部分的上下文。

## 3. 代码层

E2 已给出三种拓扑的成本（线性 13.2K vs 并行 6.7K token）。这里补 join 的视角：fan-out 出去的分支在 join 节点会合，**join 的等待时间 = 最慢分支**——所以 fan-out 前先问：各分支工作量方差大吗？方差大就等于被最慢的拖死（尾部延迟问题，straggler）。

```python
# LLMCompiler 式调度的玩具核心：拓扑排序 + 并发池
def schedule(tasks, deps):
    ready = [t for t in tasks if not deps.get(t)]
    done, running = set(), []
    while ready or running:
        launch(ready); ready = []          # 无依赖的全部并发
        finished = wait_any(running)       # 完成一个
        done |= finished
        ready = [t for t in tasks if t not in done
                 and deps[t] <= done]      # 依赖齐了才入队
```

## 4. 不足与坑

- **分解税**：过度分解——每拆一层多一次 LLM 调用 + join 综合，拆到叶子比不拆还贵。经验法则：只在"子任务可独立验证/可并行/需异构能力"时才拆；
- **plan drift**：静态 DAG 在动态环境里过期。两难：重规划太频繁（贵）vs 太稀疏（漂）。TDAG 的按需重估是当前最优实践；
- **自动图发现的搜索成本**：AFlow 类方法搜一次工作流 = 数百次 agent 运行——只在高频复用场景摊得平；
- **验证约束进不了图**：多数任务图只有先序边，没有"这个结果必须被谁验证"的边——ContextOS 的图契约观点：join/stop/verify 语义应该是一等边。
