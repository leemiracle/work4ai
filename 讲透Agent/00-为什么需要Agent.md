# 00 — 为什么需要 Agent？

> 这是「讲透 Agent」第一篇。横向打通把 Agent 列为"能力获取第四极"。这一篇讲透最根本的问题：**为什么单次 LLM 调用搞不定复杂任务，必须靠 Agent 的"推理+行动循环"？**
>
> 配套实验：`experiments/00_react.py`。

---

## 1. 单次 LLM 的局限：闭眼猜

单次 LLM 调用是：**输入 → 一次生成 → 输出**。这种模式有三个硬伤：

| 局限 | 表现 | 例子 |
|---|---|---|
| **无工具** | 只能用训练时记住的，算不准/查不到 | 问"北京上海温度差"，可能记错或编 |
| **无反馈** | 一次定生死，看不到中间结果 | 算错了没法回头改 |
| **无持久** | 每次独立，不记得上一步 | 多步任务的中间状态丢了 |

**本质**：单次 LLM 是"闭眼猜"——基于固定上下文一次性给答案，不能与环境交互、不能调用外部能力、不能根据反馈调整。

---

## 2. Agent 的定义：LLM + 工具 + 循环

Agent 把 LLM 变成一个**在环境里行动的智能体**：

$$\text{Agent} = \underbrace{\text{LLM}}_{\text{大脑}} + \underbrace{\text{Tools}}_{\text{手脚}} + \underbrace{\text{Loop}}_{\text{持续交互}}$$

- **LLM**：负责推理、决策（大脑）。
- **工具**：让 LLM 突破"只会说话"——查实时数据、算精确值、执行动作（手脚）。
- **循环**：反复"感知→思考→行动"，根据环境反馈调整（持续交互）。

---

## 3. ReAct：Agent 的核心循环

最经典的 Agent 范式是 **ReAct**（Reasoning + Acting，Yao et al. 2022）：

```
用户任务
   │
   ▼
┌─────────────────────────────────┐
│  Thought: 我该做什么? (推理)      │ ◄─────── 上一步的 Observation
│  Action : 调用某工具 (行动)       │
└─────────────────────────────────┘
   │
   ▼
Observation: 工具返回结果 (环境反馈)
   │
   ▼ (回到 Thought, 直到完成)
Final Answer
```

**每一步**：LLM 先想（Thought），再决定调用什么工具（Action），工具返回结果（Observation），结果喂回 LLM 作为下一步的上下文——**循环直到给出最终答案**。

### 实验：迷你 ReAct Agent（`00_react.py`）

任务"北京和上海的温度差"的完整 ReAct 轨迹：

```
[Thought 1] 需要北京的数据, 去查
  Action: lookup_weather(北京)  → Observation: 25℃
[Thought 2] 需要上海的数据, 去查
  Action: lookup_weather(上海)  → Observation: 30℃
[Thought 3] 两个都有了, 算差值
  Action: calculate(30-25)      → Observation: 5
[Thought 4] 算完了
  👉 Final Answer: 上海比北京高 5℃
```

**单次 LLM 一次性编不出准确温度差**（可能记错）；Agent 通过 4 步循环 + 3 次工具调用，**精确得出 5℃**。

---

## 4. Agent vs 单次 vs Pipeline：何时需要 Agent

| | 单次 LLM | Pipeline（固定流程） | **Agent** |
|---|---|---|---|
| 步数 | 1 步 | 固定 N 步 | 动态，按需 |
| 流程 | 无 | 预先写死 | LLM 自己规划 |
| 适合 | 简单问答 | 流程固定的任务 | 流程不定、要看中间结果的任务 |

**关键区分**：Pipeline 是"程序员写死流程"（如先检索再生成）；Agent 是"LLM 自己决定下一步做什么"。**当任务流程无法预先确定、需要根据中间结果动态决策时，才需要 Agent**。

> 反例：简单问答用 Agent 是杀鸡用牛刀（多轮调用又贵又慢）；固定流程用 Pipeline 更稳。Agent 适合"开放性、多步、要探索"的任务。

---

## 5. Agent 的本质：睁眼探索

把单次 LLM 和 Agent 类比为人：

- **单次 LLM** = 被蒙着眼问问题，只能凭记忆答。
- **Agent** = 睁着眼，可以查资料（工具）、做计算（工具）、看到结果调整策略（循环）。

**Agent 让 LLM 从"被动回答"变成"主动解决问题"**。三个关键：
1. **工具**突破训练数据的限制（查实时、算精确、执行动作）。
2. **循环**让 LLM 根据中间结果调整（像人遇错改策略）。
3. **Observation** 是环境反馈，让 Agent "睁眼"而非"闭眼猜"。

---

## 6. 一句话总结

> **单次 LLM 是"闭眼猜"——无工具、无反馈、一次定生死，复杂任务必然失败或幻觉。Agent = LLM + 工具 + 循环，核心是 ReAct 范式：Thought→Action(工具)→Observation→循环→Final。工具突破知识限制，循环允许据反馈调整，Observation 提供环境反馈——三者让 LLM 从"被动回答"变成"在环境里主动解决问题"。当任务流程不定、需动态决策时才用 Agent；简单任务用 Pipeline/单次更划算。**

## ✍️ 练习（`00_react.py`）

1. **加工具**：给 Agent 加一个 `search_web(query)` 工具和知识库，处理"谁获得了2024年诺贝尔物理学奖"这类实时问题。

## 费曼回炉记录（L2 自检 · 已迭代）

- **F2 卡壳点**：早期我混淆了"Agent"和"Pipeline"——以为只要串多步 LLM 调用就是 Agent。重读 ReAct 原论文后才发现**关键差别在"谁决定下一步"**：Pipeline 是程序员写死流程（即使每步用 LLM），Agent 是 LLM 自己根据上一步 Observation 决定下一步 Action。另外我误以为"工具=函数调用"，其实工具本质是**给 LLM 一个 action space**，函数调用只是它的载体；还有一个坑是把 ReAct 等同于 CoT，重读才意识 CoT 只是"想"，ReAct 是"想+做+看结果"的闭环。
- **F3 术语翻译**：
  - "Observation" → 工具给你回的话，相当于你做完事后看到的结果，下一步得根据它调整
  - "Action space" → 你这趟任务里手上能用的工具箱，能调多少工具就有多大动作空间
  - "Credit assignment" → 任务最后搞砸了，到底怪哪一步？给每一步算功劳或甩锅的过程
- **F4 回炉**：v1 写成"Agent = 多次调用 LLM"，把循环当装饰；v2 改成"Agent = LLM + 工具 + 循环"三件套缺一不可，并把 ReAct 的 Thought/Action/Observation 显式画出来——diff 是把"多步"从描述性陈述升级为"动态决策 + 环境反馈"的本质定义，并补上"何时不用 Agent"的反例边界。

### 三问

1. **讲透Agent 防的是什么欺骗？** → Agent 的中间推理步骤隐藏错误或被工具欺骗。
2. **被什么攻破？** → 工具返回伪造 / 规划死循环 / 记忆被污染。
3. **沉淀进哪条主链？** → AI 安全主链——Agent 信任栈 / 工具调用审计 / 可验证执行。

### 一句话

> Agent 越自主，越需要它的每一步都可审计——这是 Agent 时代的反欺骗基础设施。
