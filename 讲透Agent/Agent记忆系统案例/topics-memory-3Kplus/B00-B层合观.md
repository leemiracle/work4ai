# B-00 B 层合观：12 个"系统内存"仓库的跨域洞见

> 覆盖：B01 memray / B02 memlab / B03 fsrs4anki / B04 volatility3 / B05 psutil / B06 memreduct / B07 dawarich / B08 react-adaptive-hooks / B09 wgcloud / B10 WinMemoryCleaner / B11 volatility v2 / B12 sysstat
> 精读档 4 仓（代码钉行号）+ 结构档 8 仓（deepwiki+README+tree）。通读后横向提炼 5 条跨域洞见，每条给出对 Agent 记忆系统的落地含义。

## 洞见 1：分配溯源 ≈ 记忆写入溯源——"每字节有栈"应移植为"每条记忆有来源链"
- 证据：
  - memray 把每次分配钉在混合调用栈上（B01 §2.1-2.2），并按位置维护 `UsageHistory` 贡献度账本（`snapshot.h:289-359`）；
  - memlab 用 retainer path 回答"谁在持有"（B02 §2.3）， dawarich 用 import 打标防多源"编织"（B07 §2.1）。
- 现状：A 层记忆库普遍只存 payload+时间戳（至多 run_id），**记忆膨胀时无法归因**。
- 落地：写入时记录来源栈（任务链/prompt 版本/工具链），治理时按来源算贡献、给删除路径。mem0 的 `run_id/actor_id` 是雏形，缺"栈"与"贡献度账本"。

## 洞见 2：FSRS 三变量模型是 Agent 记忆 decay 的现成数学（本层最重要单项，B03 全篇）
- 要件齐备：
  - D/S/R 状态化（条目是带状态的实体，不是日志）；
  - 幂律遗忘曲线 `R=(1+at/S)^{-DECAY}`（非指数）；
  - 检索即再巩固，收益 ∝ `e^{(1-R)}`——**快遗忘时命中强化最大**（desirable difficulty）；
  - `requestRetention` 成本旋钮（愿意忘多少，反解巩固周期）；
  - 均值回归防元数据漂移 + 内容种子化 fuzz 防调度共振（`fsrs4anki_scheduler.js:195-236`）。
- Agent 记忆的 decay 普遍是"时间戳+硬过期"或干脆没有。迁移路线：条目存 `(D,S,last_t)` 三件套、R 现算、按条目独立调度巩固、命中按非线性加权更新——一个 375 行的调度器就是完整规格书。
- 反向馈赠：Agent 的"应命中未命中"（后续对话回补了该事实）可充当遗忘事件信号，反哺参数在线拟合——人类复习数据反而没有这种天然监督。

## 洞见 3：快照 diff 与高水位——记忆变化检测的两个原型协议
- memlab 三点法 `(target−baseline)∩final` 在任务边界定义"该凝缩什么/该丢什么"（B02 §2.1）；
- memray 高水位在峰值时刻做归因而非看均值（B01 §2.4）；
- dawarich 的五级管线（Point→Track→Visit→Place→Digest，B07 §2.1）是同一思想的地理版：**原始事件流不可变，各级凝缩可重放**。
- 落地：Agent 记忆缺**任务边界协议**（任务结束时的批量 diff+凝缩时机）与**峰值归因**（上下文爆满时刻哪些来源在贡献）；前者是 mem0 类"写入即抽取"流水线的必要补充，后者比日均 token 统计诊断力强得多。

## 洞见 4：分层列表模型 × 层栈重建——记忆的"运行时分层"与"读取时层栈"
- 运行时分层（Windows 内存列表，B06/B10）：
  - active working set / standby（可回收但内容还在）/ modified（待落盘）/ free 的状态机；
  - memreduct 九类、WinMemoryCleaner 六类可独立操作的清理菜单——**逐出 ≠ 删除**，分级驱逐优先牺牲低优先级 standby；
  - 对应记忆 GC 操作集：flush-pending（落盘）/ evict-standby（挤出冷缓存可召回）/ trim-workingset（缩热集不删内容）/ dedup-combined（**页合并 = 记忆去重的直译**）。
- 读取时层栈（volatility3，B04）：
  - LayerStacker 试错式叠加"物理→页表→虚拟→对象"，每级 is_valid 校验，试验在 context.clone 沙箱；
  - 符号表（ISF）是与数据解耦的版本化读取知识；无符号时退化为特征扫描（yarascan）仍可用；
  - 双路验证（链表遍历 vs 池扫描）审计结构化索引的可信度。
- v2→v3 的教训（B11）：**记忆解释知识不可编译进代码**——外置、版本化、运行时匹配。

## 洞见 5：时间线聚合与分级老化——episodic 重建的输出总线与保留窗口工程
- volatility3 Timeliner 定义 `(描述, CREATED/MODIFIED/ACCESSED/CHANGED, 时间)` 统一事件接口，任何插件可汇入同一条可排序时间线（B04 §2.5，"无需有序，排序后置"的接口契约）；
- sysstat 把老化做成显式配置：10 分钟采样 → 按天分片二进制 → `HISTORY=7` 热窗 → `COMPRESSAFTER` 压缩 → sadf 六格式回放（B12 §2.2）。
- 落地：Agent 的 episodic 重建（"我做过什么"）需要同款**事件总线契约**——对话、工具调用、任务完成、记忆写删全部发统一三元组，排序聚合一层完成；遥测类记忆按"分片+保留窗+延迟压缩"三段老化；原始档与展示格式解耦。
- 辅助件清单（运行卫生件）：
  - psutil：PID+create_time 双键、oneshot 预取上下文、NoSuchProcess/AccessDenied/Zombie 异常三态（B05）；
  - react-adaptive-hooks：deviceMemory 阶梯量化、unsupported+初始值降级契约（B08）；
  - wgcloud：采集/存储分离的心跳模式、多源统一信封（B09）。

---

**一句话总结**：系统内存工具比 Agent 记忆库早了十年回答同一组问题——什么该留（三点 diff/高水位）、何时忘（FSRS 幂律）、怎么忘而不丢（standby 分级逐出）、忘了怎么找回（层栈重建+时间线聚合）、谁该为膨胀负责（写入溯源+贡献度账本）。B 层是 A 层的"机制校准层"：A 层提供记忆系统的产品形态，B 层提供其内部物理学的现成公式。
