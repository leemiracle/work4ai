## ★ 迭代出的最优 system prompt（16/16 满分，直接可用）

```
你是严谨的算法工程师，精准第一。 先一步步推理，再给出最终答案。 严格遵循输出要求：不多不少，只输出要求的内容。
```

三组件全开（RCF）：**R**ole 角色 + **C**oT 推理指令 + **F**ormat 输出契约。

## 实验设计（六步闭环的 RL 化）

| 手册 11 章六步 | 本实验 |
|---|---|
| ① 造卷 | 4 类×4 题=16 题（math/json/code/know），规则可判（RLVR）|
| ② 摸底 | 朴素空 system 基线 |

## 组件贡献分析（bandit 3 样本/臂）

- **F（输出契约）单独贡献最大**：臂0(---) 0.33 → 臂1(--F) 1.00——"严格只输出要求内容"直接消灭格式性失分
- **R+C 提升知识题精度**：分歧题集中在 know 类——角色约束抑制"顺带解释"导致的关键词漂移
- **思考成本非单调**：math#2（9.8 vs 9.11）臂7 花 2678 思考 token vs 基线 97tk——契约压力触发更谨慎推理（GLM-5 thinking 是自主调节的，提示词影响其推理预算分配）

## 三条教训（比结果更值钱）

1. **判分器错了全链路歪**（RLVR 第一坑活体）：出题人笔误 409（真值 413）→ 模型答对被判错——**评估函数的可信度先于一切优化**（讲透Prompt/09 坑①的实锤）。修正判分后结论反而更强（16/16）。
2. **GLM-5 的 thinking 不可关闭但可引导**：reasoning_tokens 从 174~2678 波动，prompt 影响**推理预算分配**而非开关——"充分利用模型能力"= 让它在该想的地方多想（CoT+契约）。
3. **bandit 比全因子实验省 3 倍**：24 次调用锁定最优臂（全组合×全题=128 次）；配对决赛再防采样噪声——探索/验收分阶段。

## 与项目知识的互证

- 讲透RL/09§P1：UCB 探索实战样本效率 ✅
