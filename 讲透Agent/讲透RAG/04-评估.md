# 04 — RAG 评估：RAGAS 与 faithfulness / relevance

> RAG 系统好不好，不能只看"最终答案对不对"——检索差和生成差都会让答案错，但优化方向完全不同。这一篇讲透怎么**分别评估检索和生成**，定位瓶颈。
>
> 配套实验：`experiments/04_evaluation.py`。

---

## 1. 为什么要分开评检索与生成？

RAG = 检索 + 生成。答案错有两个完全不同的原因：
- **检索错了**：没召回到相关文档 → 答案自然错（召回率问题）。
- **生成错了**：检索到了，但 LLM 幻觉/跑题 → 答案错（忠实度/相关性问题）。

只看最终答案对错，**定位不了瓶颈**。所以 RAGAS（一个主流评估框架）把指标拆开。

---

## 2. RAGAS 四大指标

| 指标 | 评什么 | 衡量 |
|---|---|---|
| **context_precision** | 检索质量 | 检索回来的文档里，真相关的占多少 |
| **context_recall** | 检索质量 | 标准答案需要的信息，是否都被检索到 |
| **faithfulness** | 生成质量 | 答案的每个说法能否被检索文档支撑（防幻觉） |
| **answer_relevance** | 生成质量 | 答案是否切题回答了问题 |

前两个评**检索**，后两个评**生成**。

---

## 3. 实验：字符重叠近似 + 诚实局限（`04_evaluation.py`）

用字符重叠做忠实度/相关度的粗糙近似（无本地 LLM）：

```
案例                    忠实度   相关度   综合
✅好答案(忠于文档+切题)   0.94    0.62    0.59
❌幻觉(编175B/2023)      0.90    0.48    0.43
❌跑题(答MoE架构)        1.00    0.30    0.30
```

> ⚠️ 诚实说明：**字符重叠近似太粗**——幻觉答案"175B/2023"和文档"671B/2024"除数字外字符都重叠，忠实度被高估到 0.90（本该低）。**字符重叠无法捕捉事实/数字幻觉**。跑题（忠实1.0/相关0.3）能被相关度抓到。真实 RAGAS 用 **LLM 逐句核查**，能精确识别"这句的175B文档里没有"。

---

## 4. 真实评估：LLM-as-Judge

RAGAS 的实现：用 GPT-4 等强模型当裁判：
- **faithfulness**：把答案拆成原子陈述，逐个问 LLM"这条能否被文档支撑"。
- **answer_relevance**：让 LLM 从答案反推可能的问题，看和原问题多接近。

代价：每条样本多次 LLM 调用，**评估很贵**。但比字符重叠准得多。

---

## 5. 诊断与优化

| 症状 | 瓶颈 | 优化方向 |
|---|---|---|
| context_recall 低 | 检索召回不全 | 换更好的 embedding、加 BM25 混合、调 chunk |
| context_precision 低 | 检索噪声多 | 加 rerank、调 top-k |
| faithfulness 低 | LLM 幻觉 | prompt 强调"只基于文档"、降温度、Self-RAG |
| answer_relevance 低 | 答非所问 | prompt 优化、query 重写 |

**先评指标定位瓶颈，再针对性优化**——别盲目调参。

---

## 6. 一句话总结

> **RAG 评估必须分检索（context precision/recall）和生成（faithfulness/relevance）两块——检索差和生成差会让答案错，但优化方向完全不同。RAGAS 用 LLM-as-Judge 逐句核查忠实度和相关性（字符重叠近似太粗，抓不住数字幻觉）。先评指标定位瓶颈（召回率低→换embedding/混合检索；忠实度低→强约束prompt/Self-RAG），再针对性优化。**
