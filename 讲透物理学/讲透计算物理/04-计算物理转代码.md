# 04 · 计算物理转代码：一个"本身就是代码"的分支怎么谈转码

> **本章回答五问之五（本支：讲透计算物理）。**
> 特殊处境：别的物理分支谈"转代码"是翻译，计算物理**原文就是代码**。
> 所以本章的问题反过来：哪些环节仍然不可机械化（需要人类物理直觉），
> 以及——按本家族读者的工程口味——**生产级 MD 的性能内脏**长什么样。

---

## 一、可机械化边界（哪里仍需要人）

| 环节 | 机械化程度 | 为什么 |
|------|-----------|--------|
| 正问题求解（给定势/泛函 → 观察量） | ✅ 全自动 | LAMMPS/ESPRESSO 一条命令；管线成熟 |
| 轨迹后处理（RDF/MSD/谱） | ✅ 全自动 | MDAnalysis 标准件 |
| 势函数拟合（给定数据 → 经典势参数） | ✅ 基本自动 | force matching 流水线 |
| ML 势训练 | 🔄 半自动 | 框架自动；**训练集设计**（采哪些构型）是物理判断 |
| 交换关联泛函 | ❌ 人工 | 物理直觉+变分构造——DFT 的圣杯本质是"机器学不会先验" |
| 多尺度耦合方案 | ❌ 人工 | 哪些自由度积分掉、怎么传递通量——问题定义本身就是研究 |
| 模型选择与证伪 | ❌ 人工 | 误差三重奏的归因（02 章）永远需要领域眼 |

**判断**：越靠近"给定问题算答案"越自动；越靠近"问题本身怎么提"越人工——
与 AI 领域"模型自动/问题定义人工"的分界同构。

## 二、代码走廊（问题类 → 工具）

| 问题类 | 首选走廊 | 备注 |
|--------|---------|------|
| 全原子 MD（经典/ML 势） | LAMMPS · HOOMD-blue · OpenMM（生物） | OpenMM 的 GPU 内核可 Python 定制 |
| 第一性原理 DFT | Quantum ESPRESSO · ABINIT · VASP(商业) | 平面波系；all-electron 看 WIEN2k |

| 轨迹分析 | MDAnalysis · freud | in-situ 分析避免 I/O 墙 |
| 工作流/数据库 | ASE · pymatgen · AiiDA | 计算材料学的 DevOps 层 |

## 三、工程师落点：生产级 MD 的性能内脏（写深）

> 读者按性能工程背景设计本节：MD 是**访存受限的 N 体 stencil** 的活标本。
> 教学版 O(N²)（见 `experiments/lj_md.py`）到生产版差三个数量级，每一级都是系统功夫。

**① 邻居表：O(N²) → O(N) 的两次跳跃**

- **Verlet list**：邻居在 r+skin 内的对记账在册，皮肤厚度换刷新频率——
  每 10-20 步重建一次列表，其间力计算只扫在册对。
- **Cell list**：把盒子切成边长 ≥ rc 的格子，力计算只扫 27 邻格——
  重建 O(N) 且与皮肤无关。生产代码两者叠用（cell 造 Verlet）。
- **数量级**：N=10⁶ 时 O(N²)=10¹² 对 vs O(N)≈10⁷ 对——**两个数量级纯算法收益**，
  先于任何 SIMD/GPU 优化。

**② 空间域分解：并行=通信最小化**

- 按**空间**（不是按粒子编号）切分盒子：每个 rank/GPU SM 领一块空间，
  只与 26 邻居交换**边界壳层粒子**（两层：力壳+皮肤壳）。
- 为什么不用粒子编号均分：编号切分会让通信全对全（跨盒子对）——
  空间分解把通信面压到表面积 ∝ N^{2/3}。
- 负载均衡：密度不均（气液界面）时动态重划格子——与 GPU 常驻线程模型
  （每 SM 一格）天然契合（HOOMD 的设计哲学）。

**③ 混合精度分层**

- 力累加 FP64（百万对求和，舍入敏感），力的中间几何（r²/r⁻⁶ 查表）FP32/查表；
- ML 势的推理 FP16/BF16（网络本身对精度钝感）——**精度预算花在累加器上**，
  这条经验与深度学习训练的 loss scaling 同源
  （→ [`../../讲透GPU与系统级/`](../../讲透GPU与系统级/) 正主）。

**④ DFT 侧：平面波 = FFT 的马甲**

- 平面波基下动能/库仑算符在实空间与倒空间各自对角——每步自洽迭代
  若干次 3D FFT；ESPRESSO 的性能画像 ≈ FFT 通信 + 对角化 (O(N³))。
- 工程侧推论：调优 DFT 代码 ≈ 调优 FFT 栈 + 对角化库（ScaLAPACK/ELPA）
  ——与 [`../../讲透高性能计算/`](../../讲透高性能计算/) 的 workload 分类直接对接。

## 四、裂缝清单（不可转/难转的边界再确认）

1. **符号问题**：不是"更好的算法能解决"——是复杂度墙的显影（03 章）；
   通用量子 MC 加速器不存在（可视为计算物理的"永动机条款"）。
2. **泛函的发明**：交换关联泛函的每代进步（LDA→GGA→meta-GGA→rSCAN）
   都是物理直觉的产物——ML 泛函（DM21 一脉）是最新尝试，仍未取代人类设计。
3. **"模拟出了"≠"理解了"**：观察量的产出自动化了，**解释**（哪些项主导、
   机制是什么）仍是人的活——计算物理的最后一公里没有 corridor。

## 五、最小可跑示例（本家族实验）

`experiments/lj_md.py`（纯 numpy，O(N²) 教学版）实测（LJ 单位，N=64，dt=0.004）：
- Velocity-Verlet：2000 步系统性能量漂移 **0.105%**（震荡 0.341%）
- 显式 Euler：400 步漂移 **65.51%** 单调上升
- 三处数值坑的修复史（力方向/防护墙夹紧/漂移度量）本身就是 03 章
  "结构>精度"的活教材——详见脚本注释。

## 这一章的新眼睛（认知升维）

- **算法收益先于硬件收益**：邻居表的两个数量级是白送的，GPU 的十倍要算电费——
  优化顺序=算法→访存→并行→精度
- **通信=面积，计算=体积**：空间分解的 N^{2/3} 通信面是所有 N 体模拟的通用骨架
  （从 MD 到 N 体引力到 SPH）
- **精度是预算不是追求**：把它花在累加器和守恒律上，其余处省下的周期
  换更大的 N 或更长的轨迹——这才是物理想要的
