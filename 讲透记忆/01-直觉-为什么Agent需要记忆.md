# 🧠 第 1 幕 · 直觉：为什么 Agent 需要记忆

## 一个让你心疼的比喻：LLM 是一条金鱼

民间传说金鱼只有 7 秒记忆——绕鱼缸一圈，世界又是新的。这当然不科学（金鱼其实能记几个月），但**用来形容默认的 LLM，精确得残忍**：

> 你和 ChatGPT 聊了 2 小时，告诉它你的名字、你的偏好、你的项目背景。你关掉窗口。第二天打开——**它一个字都不记得你**。它对你来说是个老朋友，你对它来说是初次见面。

这不是 bug，是 **LLM 的设计本质**：模型权重是冻结的，所谓的「记忆」全在那个会消失的 context window 里。窗口一关，记忆清零。

**记忆工程，就是要把这条金鱼训练成大象。**

---

## 从人脑借地图：记忆不是一个东西，是四层

如果只有一个「记忆」，问题会简单——存下来就行。残酷的是，**人脑的记忆至少有四层，每层职责完全不同**（Atkinson & Shiffrin 1968；Tulving 1972）：

| 层 | 人脑位置 | 时间尺度 | 内容 | LLM 里的对应 |
|---|---|---|---|---|
| **工作记忆** Working | 前额叶皮层 | 秒-分钟 | 当前任务的活跃信息 | **context window** |
| **情景记忆** Episodic | 海马体 | 小时-年 | 「我经历过的事件」 | 对话日志 / 向量库（按时间） |
| **语义记忆** Semantic | 新皮层 | 永久 | 「事实/概念」 | 抽取的事实 / 知识图谱 |
| **程序记忆** Procedural | 基底神经节 | 永久 | 「怎么做」技能 | 骑车/打字——对应模型的**权重** |

**关键洞察**：当前所有 LLM 只强在有「工作记忆」（context），和一套凝固的「程序记忆」（权重）。**中间两层（情景 + 语义）几乎为零**——而这恰恰是「越用越懂你」的核心。

整部「讲透记忆」要补的就是中间这两层。

---

## 为什么「全塞进 context」是个陷阱

新手的第一反应：「既然 context 就是记忆，那把所有历史都塞进去不就行了？」

这条路有三个致命问题：

### 1. 物理上限：context 再大也是有限的
即便 Gemini 的 200 万 token、Claude 的 200K、Augment 的 60 万——**真实场景下用户几年的对话、几十个项目的代码、上千份文档，轻易超过**。而且越长越贵越慢。

### 2. 检索精度：塞进去 ≠ 找得到
**needle-in-haystack 实验**揭示了一个反直觉的事实：把一根针藏在一大段文本里，模型找出它的成功率**随长度上升而下降**。100% 命中只是营销数字，真实复杂任务上长 context 的有效利用率远低于宣传。

### 3. 干扰：太多信息会让模型分心
认知心理学叫「前摄/后摄干扰」——一堆旧信息和当前任务无关，反而稀释了注意力。LLM 也是：**context 里无关历史越多，当前推理质量越差**。

所以「全塞」不只是贵，是**质量上也会输**。

## 记忆工程的核心三问

把金鱼变大象，本质是回答三个问题（这贯穿后续所有章节）：

```
1. 写入什么？    哪些经验值得固化，哪些该丢弃？
2. 怎么检索？    给定当前任务，从海量记忆里召回最相关的？
3. 何时遗忘？    旧记忆怎么衰减/淘汰，避免污染？
```

这三个问题对应了三种不同的工程实现，**没有银弹**——这也是为什么 2024-2026 涌现了那么多家记忆创业公司，每家押注不同答案。

---

## 2024-2026 记忆层的军备竞赛（直觉地图）

把当前业界方案沿「写入/检索/遗忘」三轴摆开，会看到清晰的设计差异：

| 方案 | 写入策略 | 检索策略 | 遗忘策略 | 哲学 |
|---|---|---|---|---|
| **mem0 Oryza** (2025) | LLM 抽取事实→去重→合并 | 向量 + 图谱双路融合 | 显式 update/delete | 「记忆 = 可推理的事实集」|
| **Letta (MemGPT)** (2024) | LLM 自主决定 page in/out | 分级内存（core/recall/archival）| LLM 自主管理 | 「记忆 = 操作系统的虚拟内存」|
| **OpenAI Memory** (2024-2025) | 静默写用户事实 | 跨会话注入 prompt | 用户可见可删 | 「记忆 = 用户画像」|
| **Augment Context Engine** (2025) | 大规模代码语义索引 | 实时检索塞 context | —— | 「记忆 = 实时索引，不需要持久事实」|
| **Zep / Graphiti** (2024-2025) | 时序知识图谱 | 图谱遍历 + 时间衰减 | 时间衰减 | 「记忆 = 带时间戳的自传」|
| **Anthropic Context Engineering** (2025) | （主张：先优化 context） | prompt caching 90% off | 短 TTL | 「记忆是 context 工程的子集」|

**注意最后一家**：Anthropic 2025 年官方提「context engineering」主张——**在加记忆层之前，先把 context 用好**。这是反记忆层的，提醒我们：**记忆不是越多越好，有时是 context 没管理好的症状**。这个张力会在第 4 幕（不足）展开。

## 一个思想实验：什么算「记住了」

判断一个 Agent 有没有记忆，看它能不能回答这三类问题：

1. **关于你**：「我上次提的偏好，你还记得吗？」（情景 + 语义）
2. **关于它自己**：「我们之前是怎么解决类似问题的？」（情景 + 程序）
3. **关于演化**：「三个月前你给我的建议，现在还成立吗？」（时序 + 自我修正）

当前大多数「记忆方案」只能回答第 1 类。**能回答第 3 类的，才接近人脑的「自传体记忆」**——那是 Zep/Graphiti 这类时序图谱瞄准的圣杯。

## 与其他宇宙的连接

- **`讲透上下文缓存/`**：缓存是「无思考的复用」（前缀相同就复用），记忆是「有语义的复用」（理解相关性）。两者是认知复杂度的递进。
- **`讲透学习型Agent/`**：记忆的 L2（经验回写）= 学习型 Agent 的第二层。**记忆是「不改权重的学习」**。
- **`故事原语/02-熵论辩证`**：记忆的本质是「把高熵的瞬时经验，固化成低熵的可检索结构」——典型的负熵注入，且必须开放（否则 Model Collapse）。
