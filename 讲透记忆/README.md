# 🧠 讲透 Agent 记忆：从短时上下文到长期自传

> **User Story**：作为一个想造有长期记忆 Agent 的人，我想理解记忆的原语与权衡，以便选对架构而不被厂商绑架。

## 🎭 戏剧张力（故事的发动机）

Agent 想要「记住关于用户和世界的一切」，但遇到三重障碍：

1. **context window 有限**（即便 200 万 token 也会被长对话填满）
2. **检索精度有限**（全塞进去 ≠ 能找到；needle-in-haystack 失败率随长度上升）
3. **成本与延迟**（每多一个 token，推理费用和延迟都涨）

——这就是「**全塞会爆，不塞会失忆**」的核心冲突。整部「讲透记忆」就在解这个冲突。

## 🗺️ 2024-2026 前沿地图（记忆层军备竞赛）

| 方案 | 核心思路 | 关键数字 | 评价 |
|---|---|---|---|
| **mem0 Oryza** (2025) | LLM 抽取事实 → 向量 + 图谱双存储 → 检索时融合 | 比 LangChain Memory 快 11× | 工程化最成熟的开源记忆层 |
| **Letta (MemGPT)** (2024-) | OS 思路：分级内存 + LLM 自主管理 page in/out | 类 OS 抽象 | 把记忆当「虚拟内存」管理 |
| **OpenAI Memory** (2024-2025) | ChatGPT 静默写事实，跨会话复用 | 用户级事实库 | 闭源但产品化最彻底 |
| **Augment Context Engine** (2025) | 大规模代码库语义索引，实时检索塞 context | **60 万 token 真实可用** | coding agent 杀手锏 |
| **Anthropic Context Engineering** (2025) | 官方主张：先优化 context 再谈记忆 | prompt caching 90% off | 提醒：记忆是 context 工程的子集 |
| **Zep / Graphiti** (2024-2025) | 时序知识图谱，自动维护事实演化 | 图谱 + 时间衰减 | 长期记忆里最像「自传」的 |

## 🔗 与其他宇宙的关系

- 与 **`Agent记忆系统案例/mem0开源记忆层/`**（已有）：本宇宙讲**原理与权衡**，mem0 案例讲**工程实现**，互补不重叠。
- 与 **`讲透Agent/`**（已有）：记忆是 Agent 的「过去」维度；规划（`讲透世界模型/`）是「未来」维度。
- 与 **`讲透上下文缓存/`**（新）：缓存是「无思考的复用」，记忆是「有语义的复用」——后者更难。

## 💡 核心洞察（剧透）

> **记忆不是「存储」，是「以负熵为食的遗忘工程」。** 一个不遗忘的 Agent 会被噪声淹没；一个会精准遗忘的 Agent 才像活物。Ebbinghaus 早在 1885 年就告诉我们：遗忘不是 bug，是 feature。本宇宙的全部数学，就是在量化「该忘掉什么」。
