# 极简源码阅读方法论

> 读源码不是"从头到尾读完"，而是"建立一张地图，然后按需深入"。
> 这份方法论来自精读 micrograd（100 行）、nanoGPT（700 行）、rubber-docker（分关递进）三个真实项目的实践经验。
> 目标：让你面对任何陌生代码库，都能在 1-2 小时内建立可操作的认知。

---

## 一、读源码的程序员方法：五步法

### 第 0 步：先跑起来

**不跑通的代码读不进去。** 读源码前，先按 README 把项目跑起来，哪怕只是跑测试或 demo。

以 micrograd 为例，仓库根目录有 `demo.ipynb`，跑一遍能看到 MLP 拟合 moon 数据集的全过程。跑通后你建立了感性认知："这个库能做 X"，再读代码时脑子里有锚点。

跑不通怎么办：
- 读 `README.md` 的 Quick Start 段
- 读 `test/` 目录——测试是最准确的使用文档
- 看 `setup.py` / `pyproject.toml` 的依赖和 entry point

### 第 1 步：找入口

每个项目都有一个"主入口"，找到它就读对了 30%。

| 项目类型 | 入口在哪 | 怎么找 |
|---------|---------|--------|
| 库/API | 暴露的主类或函数 | 看 `__init__.py` 的 `__all__` |
| CLI 工具 | `main()` 或命令分发 | 看 `setup.py` 的 `entry_points` 或 `if __name__ == '__main__'` |
| Web 服务 | 路由注册 | grep `@app.route` / `@router` |
| 训练脚本 | 训练循环 | grep `for.*epoch` / `while True` |

micrograd 的入口是 `micrograd/engine.py` 的 `Value` 类——整个库围绕它。nanoGPT 的入口是 `train.py` 第 255 行的 `while True:` 训练循环。rubber-docker 每关的入口是 `rd.py` 的 `cli()` 命令组。

### 第 2 步：画调用图

读入口函数时，**边读边画调用关系**。不需要精美，纸笔或文本都行。

nanoGPT 的调用图（从 `train.py` 出发）：

```
train.py
├── get_batch()           # 数据加载
├── model(X, Y)           # → GPT.forward()
│   └── GPT.forward
│       ├── wte(idx)      # 词嵌入
│       ├── wpe(pos)      # 位置嵌入
│       └── for block in h:  # Block.forward()
│           ├── ln_1(x)
│           ├── attn(x)   # CausalSelfAttention.forward
│           ├── ln_2(x)
│           └── mlp(x)    # MLP.forward
├── loss.backward()       # autograd
└── optimizer.step()
```

画完这张图，你就知道"训练时数据怎么流过模型"，剩下只需挑不懂的节点深入。

### 第 3 步：挑核心函数深读

**不要平均用力。** 一个项目 80% 的价值集中在 20% 的核心函数。

| 项目 | 核心函数（值得逐行读的） | 可跳读的 |
|------|------------------------|---------|
| micrograd | `Value.__init__`、`__add__`、`__mul__`、`backward` | `__repr__`、`__neg__` 等语法糖 |
| nanoGPT | `CausalSelfAttention.forward`、`GPT.forward`、`get_lr` | `from_pretrained`、`crop_block_size` |
| rubber-docker | `run()`（fork/exec）、后续关的 `contain()` | 模板代码、错误处理 |

**怎么判断"核心"**：
- 被高频调用的（训练循环里的）
- 名字直击领域概念的（`attention`、`backward`、`fork`）
- 注释里写着公式或论文引用的

### 第 4 步：改一行看变化

读完不算懂，改了能预测行为才算懂。三个层次的修改：

1. **改参数**：nanoGPT 把 `n_head` 从 12 改成 4，观察显存和速度变化
2. **改逻辑**：micrograd 把 `relu` 的 `(out.data > 0)` 改成 `(self.data > 0)`，验证等价
3. **加功能**：micrograd 加一个 `tanh` 激活，跑通并和 PyTorch 对照梯度

rubber-docker 天然适合这种练法——它本身就是"分关递进"结构，每关在上一关基础上加一个系统调用，改一行就能观察到容器隔离行为的变化。

## 二、工具箱：读源码的瑞士军刀

### 2.1 代码导航：跳到定义

- **IDE 跳转**（VS Code/PyCharm 的 "Go to Definition"）：日常最常用，`F12` 或 `Ctrl+Click`
- **cscope**（C/C++ 项目）：构建符号索引，vim 里 `:cs find g symbol` 跳定义
- **ctags**：生成 `tags` 文件，vim/emacs 通用，`Ctrl+]` 跳转、`Ctrl+t` 回退
- **Python 的 `inspect` 模块**：`inspect.getsource(func)` 在 REPL 里直接看源码，调试时极有用

### 2.2 全局搜索：grep / ripgrep

读源码一半时间在搜索。记住几个高频模式：

```bash
# 找所有定义某类/函数的地方
rg "class Value" --type py
rg "def forward"

# 找某函数的所有调用点
rg "backward\(\)"

# 找配置项的默认值
rg "n_embd.*=.*768"

# 只看注释（理解作者意图）
rg "#.*TODO|#.*NOTE|#.*HACK"
```

`rg`（ripgrep）比 `grep` 快一个量级，默认忽略 `.gitignore`，是现代标配。

### 2.3 运行时分析：看真实调用

静态读容易"想当然"，运行时工具让你看到**真实**的调用链：

- **Python: `py-call-graph` / `py-spy`**：生成调用图或火焰图
- **Python: `pdb` / `ipdb`**：断点单步，`l` 看代码、`s` 步入、`n` 步过、`p var` 打印
- **Python: `logging`**：在关键函数插日志，比 print 更可控
- **`strace`**（C/系统编程）：看进程实际调用了哪些 syscall，rubber-docker 这种项目必备
- **`perf` / `py-spy`**：性能剖析，发现热点函数

### 2.4 可视化：understand / sourcetrail

对于大型项目（10 万行+），专门的代码可视化工具有用：
- **SciTools Understand**：构建代码数据库，可视化调用图、类继承图
- **Sourcetrail**：开源的代码浏览器，索引后可点击跳转 + 侧边栏显示关系
- **Sourcegraph**：在线代码搜索，支持跨仓库语义查询

小项目（< 1000 行）用不上这些，纸笔画调用图更快。

## 三、三个规模，三种策略

不同规模的项目，阅读策略完全不同。

### 3.1 微型项目（< 200 行）：逐行精读

**代表**：micrograd（engine.py 94 行 + nn.py 60 行）

**策略**：从头到尾逐行读，每个函数都不放过。这种规模的项目往往是"教学杰作"，每一行都有用意。

**要点**：
- 理解每个数据结构的字段含义（micrograd 的 Value 五个字段）
- 理解每个运算的局部导数（链式法则落地）
- 注意语法糖和惯用法（`sum(iterable, start)` 当偏置起点）

**验证手段**：写对照测试，micrograd 的 `test_engine.py` 就是用 PyTorch 当 ground truth 验证梯度正确性。

### 3.2 中型项目（200-1000 行）：骨架优先 + 选择性深入

**代表**：nanoGPT（model.py 330 行 + train.py 336 行）

**策略**：先画整体结构图，再挑 2-3 个核心模块逐行读，其余略读。

**要点**：
- 先读 `Config`/`dataclass` 了解全局参数
- 重点读前向传播（`forward`）——这是模型定义的精华
- 训练循环只看关键技巧（梯度累积、lr 调度、梯度裁剪），不用逐行
- 跳过工程兼容代码（`from_pretrained` 的权重映射、DDP 通信细节）

**判断"可跳读"的标准**：如果一个函数去掉，模型仍能训练，那它大概率是工程辅助（初始化、checkpoint、兼容性），不是核心逻辑。

### 3.3 渐进式项目（分关/分步）：跟着作者节奏走

**代表**：rubber-docker（levels/00 到 levels/10，每关一个 `rd.py`）

这种项目刻意设计成"每关加一个概念"，作者的 README 就是最好的导读。

**策略**：严格按关卡顺序读，每关对比上一关的 diff。

rubber-docker 的第 0 关 `rd.py` 只有 58 行，核心是 `os.fork()` + `os.execv()`——这是"启动新进程"的最本质写法。第 1 关加 `os.chroot()`（文件系统隔离），第 2 关加 `clone` 的 namespace 标志（挂载隔离）……每关的 diff 就是"容器化"的一个维度。

**要点**：
- 用 `diff levels/00_fork_exec/rd.py levels/01_chroot_image/rd.py` 看增量
- 每关的 README 解释"为什么需要这一步"
- 这种项目的精髓在"增量小、可验证"——读完你能从零写出迷你 Docker

### 三种策略对比表

| 维度 | 微型（micrograd） | 中型（nanoGPT） | 渐进式（rubber-docker） |
|------|------------------|----------------|----------------------|
| 总行数 | ~150 | ~700 | 每关 ~50-100 |
| 阅读方式 | 逐行 | 骨架+选择深入 | 按 diff 增量 |
| 用时 | 2-3 小时 | 4-6 小时 | 每关 30 分钟 |
| 核心收益 | 理解一个概念的本质 | 理解一个系统的架构 | 理解一个技术的演进 |
| 验证手段 | 对照测试 | 复现训练 | 每关跑通 |
| 最怕的陷阱 | 漏掉语法糖 | 陷入工程细节 | 跳关读 |

## 四、读源码的心态校准

最后三条心法，比工具更重要：

1. **不要追求"读完"**。源码不是小说，没有结局。目标是"建立可检索的认知"，不是打卡。读完核心函数、能解释给别人听，就够了。

2. **遇到看不懂的，先标注跳过**。用 `# TODO: 理解这里` 或书签标记，继续往下读。很多时候后文会揭示前文的意图，或读到别处自然就懂了。卡在一处不动是最差策略。

3. **带着问题读**。"我想知道 attention 的 mask 怎么实现"比"我要读懂 nanoGPT"更容易聚焦。具体问题让你只读相关代码，避免漫无目的。

micrograd 让你看到"反向传播的本质是链式法则 + 拓扑序"，nanoGPT 让你看到"Transformer 的本质是 QKV + softmax + 残差"，rubber-docker 让你看到"容器的本质是 namespace + cgroup + 文件系统隔离"。**好源码的作用，是把复杂概念拆成你能逐行指认的代码。** 这就是读源码的全部价值。
