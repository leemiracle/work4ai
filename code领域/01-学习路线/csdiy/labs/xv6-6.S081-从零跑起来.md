# MIT 6.S081 (xv6-labs-2020) 从零跑起来

本手册基于 `xv6-labs-2020`（RISC-V 版 xv6）。照着做，从装工具链到跑通第一个 lab（util）并过 `make grade`。

## 0. 一句话环境要求

Ubuntu 20.04 / 22.04（推荐 20.04，qemu 版本最省心）。需要：`riscv64` 交叉编译器 + `qemu-system-riscv64`。WSL 也能跑，但 gdb 调试建议用原生 Linux。

## 1. 安装 RISC-V 工具链与 QEMU

```bash
sudo apt-get update
sudo apt-get install -y git build-essential gdb-multiarch \
    qemu-system-misc \
    gcc-riscv64-linux-gnu binutils-riscv64-linux-gnu
```

验证（每条都应输出版本号，不报 command not found）：

```bash
qemu-system-riscv64 --version       # 期望 4.2 或 5.x
riscv64-linux-gnu-gcc --version     # 10.x 即可
```

> 说明：6.S081 2020 用的是 `riscv64-linux-gnu-gcc`（不是 `riscv64-unknown-elf-gcc`，那是旧版课程）。Makefile 会自动找到它。

## 2. 拉代码并启动 xv6

```bash
git clone git://g.csail.mit.edu/xv6-labs-2020
cd xv6-labs-2020
git checkout util           # 切到 util 分支（每个 lab 一个分支）
make qemu
```

成功标志：看到 xv6 shell 提示符 `$`，输入 `ls` 能列出文件。退出 QEMU：先 `Ctrl-a`，松开，再按 `x`。

> 若 `g.csail.mit.edu` 连不上，用 GitHub 镜像：`git clone https://github.com/mit-pdos/xv6-labs-2020.git`
> 本地参考解法见 `github-repos/PKUFlyingPig/MIT6.S081-2020fall`，`git checkout util` 可看 FlyingPig 的实现。

## 3. util lab 完整流程（sleep → find → xargs）

util 分支要求实现 5 个用户程序：`sleep`、`pingpong`、`primes`、`find`、`xargs`。

### 3.1 看懂现有代码骨架

```bash
cat user/echo.c          # 最简单的用户程序模板
cat user/ls.c            # find 要参考它遍历目录
cat user/grep.c          # 字符串匹配，xargs/​find 可复用
grep -n "exit\|fork\|pipe\|exec" user/user.h   # 可用系统调用声明
```

每个程序骨架：`#include "kernel/types.h"` + `"kernel/stat.h"` + `"user/user.h"`，`main` 里干活，**最后必须 `exit(0)`**。

### 3.2 写 sleep（最简单，先跑通）

新建 `user/sleep.c`：

```c
#include "kernel/types.h"
#include "kernel/stat.h"
#include "user/user.h"

int main(int argc, char *argv[]) {
    if (argc != 2) {
        fprintf(2, "Usage: sleep seconds\n");
        exit(1);
    }
    sleep(atoi(argv[1]));
    exit(0);
}
```

### 3.3 在 Makefile 里注册程序

打开根目录 `Makefile`，找到 `UPROGS` 列表（约 100 行附近），按字母顺序加入你的程序：

```makefile
UPROGS=\
    $U/_cat\
    $U/_echo\
    ...
    $U/_sleep\          # 新增
    $U/_find\           # 新增（实现后）
    $U/_xargs\          # 新增
```

### 3.4 编译、运行、自测

```bash
make qemu
# 在 xv6 shell 里：
$ sleep 10
$ find . b              # find 实现后
$ echo 1 2 3 | xargs echo
```

### 3.5 跑评分脚本

```bash
make grade
```

`make grade` 会用 `gradelib.py`（Python3）跑一组测试（`grade-lab-util`），最后打印类似 `Score: 100/100`。需要本机有 `python3`（`sudo apt install python3`）。若某项 Score 为 0，按提示看 `xv6.out.*` 日志。

## 4. GDB 调试（选学，后续 lab 必备）

两个终端：

```bash
# 终端1：启动带 gdb stub 的 qemu
make qemu-gdb

# 终端2：连上
riscv64-linux-gnu-gdb kernel/kernel    # 或 gdb-multiarch kernel/kernel
(gdb) target remote :26000             # 端口见终端1输出，通常是 26000
```

若连接被拒，检查 `.gdbinit` 是否被加载：`echo "add-auto-load-safe-path $(pwd)/.gdbinit" >> ~/.gdbinit`。

## 5. 常见报错 → 修复

| # | 报错文本 | 一行修复 |
|---|---------|---------|
| 1 | `riscv64-unknown-elf-gcc: command not found` / Makefile 里找不到工具链 | 用 `gcc-riscv64-linux-gnu` 包；或设 `export TOOLPREFIX=riscv64-linux-gnu-` |
| 2 | `qemu-system-riscv64: command not found` | `sudo apt install qemu-system-misc` |
| 3 | xv6 启动后卡死/重启死循环（Ubuntu 20.04 上 qemu 5.0 bug） | 降级：`sudo apt install qemu-system-misc=1:4.2-3ubuntu1` 锁定版本 |
| 4 | `make: *** No rule to make target 'qemu'` / 编译乱套 | 你在错误目录跑 cmake 残留：删掉根目录的 `CMakeCache.txt`、`CMakeFiles/`；确认在 `xv6-labs-2020/` 根 |
| 5 | `panic: freerange` / 文件系统只读报错 | 误把只读 fs 的写入当 bug；正常现象。若要持久化见 fs lab，util 阶段忽略 |
| 6 | `make grade` 报 `python3: command not found` 或 `No module named 'gradelib'` | `sudo apt install python3`；并确认在仓库根目录跑（gradelib.py 在当前目录） |
| 7 | `sleep: not found`（在 xv6 里输入自己写的命令找不到） | 没在 Makefile 的 `UPROGS` 加 `$U/_sleep\`，或漏写反斜杠续行，重新 `make qemu` |
| 8 | gdb 连不上：`localhost:26000: Connection refused` | 终端1 没用 `make qemu-gdb`（用了 `make qemu`）；或 `.gdbinit` 未被信任，加 safe-path |
| 9 | `git clone git://g.csail.mit.edu` 超时 | 换 https 镜像：`git clone https://github.com/mit-pdos/xv6-labs-2020.git` |
| 10 | 编译报 `user/sleep.c:1:10: fatal error: kernel/types.h: No such file` | 文件没放在 `user/` 目录，或头文件路径写错（应为 `"kernel/types.h"` 不是 `<types.h>`）|
