## 1. 这门课是什么

Stanford CS144「Introduction to Computer Networking」，主讲之一是网络界巨擘 Nick McKeown（SDN/OpenFlow 之父、Barefoot Networks 创始人）。每章末尾他都会去访谈一位业界/学界的高人，视野非常开。

和绝大多数「计算机网络」课不一样，CS144 **不是一门 socket 编程课**，也不是「读 Kurose 教材做选择题」。它的 6 个 lab 是**自顶向下**的：先让你写一个最简单的字节流，然后逐步往上搭——

```
Lab 0  Reliable Byte Stream        （内存里的可靠字节流，热身）
Lab 1  Stream Reassembler          （流重组器：乱序/重叠/有洞的字节拼回顺序）
Lab 2  TCP Receiver                （收端：32 位 wrap 序号、ISN、ACK、窗口）
Lab 3  TCP Sender                  （发端：重传、滑动窗口、persist）
Lab 4  TCP Connection              （把收发端拼成一条能握手/挥手的连接）
Lab 5  Network Interface (ARP)     （IP 数据报 <-> 以太网帧，ARP 缓存与过期）
Lab 6  IP Router                   （最长前缀匹配，转发数据报）
```

做完这 6 步，你手里就是一套**几乎符合标准、能和 Linux 内核 TCP 互通**的 TCP/IP 栈。Lab 7（整合 + 通过中继服务器真实通信）是把前面拼起来跑一遍，不在 `make check` 范围里。

一句话：这门课是「年轻人最好的现代 C++ 入门课」+「计算机世界里没有魔法」的最好注脚。

## 2. 为什么值得做

很多人学网络的方式是：背三次握手图、背 TCP 状态机、会用 `socket()` 就算完事。然后线上遇到 `CLOSE_WAIT` 堆积、粘包、零窗口、重传风暴，还是两眼一抹黑。

看课本 vs 做 CS144 的区别，就像「读了一遍《设计模式》」vs「亲手写了一个能跑的 TCP 栈」：

- **滑动窗口**不是图上几个箭头，而是你亲手维护的 `_next_seqno` / `rwindow` 两个变量，错了重传就乱套。
- **32 位序号 wrap** 不是一句「会回绕」——你得在 `2^32` 空间和绝对序号之间正确换算，还要选对最近的那个解。
- **零窗口探测（zero-window probe）**不是一句话定义——你不实现它，发端就会永远卡死，收端永远不知道窗口开了。
- **ARP**不是「地址解析协议」四个字——你要管缓存表项的过期，过期了就要丢帧并发新请求。
- **RST / 同时打开 / 同时关闭**这些边角，自己写一遍状态机才记得住。

本仓库的 [notes/network-程序员视角-从抓包到原理.md](../notes/network-程序员视角-从抓包到原理.md) 是「从 bug 反推原理」的速查篇（RST / epoll / 粘包 / CLOSE_WAIT / TLS），而 CS144 是它的「正向补全」：先把协议栈从零实现一遍，再回去看那些线上故障，会豁然开朗。建议**两篇对照读**。

## 4. Lab 1：流重组器（Stream Reassembler）

对应 `lab_handouts/lab1.pdf`，文件 `libsponge/stream_reassembler.{hh,cc}`。

### 4.1 考点

给你一串带 `index`（字节绝对下标，从 0 开始）和 `eof` 标志的子串，**乱序到达、可能重叠、可能落在已组装区域之前/之后**，你要把它们拼回一条连续的、有序的字节流，喂给 Lab 0 的 `ByteStream`。

- **滑动窗口**：`[first_unassembled, first_unassembled + capacity)`。窗口大小 = `capacity`，它**同时**约束「未组装区」和「ByteStream 里已组装未读区」。两边共享同一个 `capacity`，这是设计上的关键耦合点。
- **字节索引**：`push_substring(data, index, eof)` 的 `index` 是 `data[0]` 在整条流里的绝对下标。
- **超容丢弃**：超出窗口右侧的字节直接丢；这是允许的，因为收端迟早会重传。

### 4.2 接口（骨架已定，你填实现）

```cpp
class StreamReassembler {
  public:
    StreamReassembler(size_t capacity);
    void   push_substring(const std::string &data, size_t index, bool eof);
    const ByteStream &stream_out() const;  // 读出已组装的有序流
    ByteStream &stream_out();
    size_t unassembled_bytes() const;       // 已收到但还没拼上的字节数
    bool   empty() const;
};
```

`push_substring` 的典型实现（FlyingPig 思路）：用一个定长滑动窗口 + bitmap 记录每个字节是否已就位；子串进来先和窗口求交、标记 bitmap，再从窗口起点向后扫连续就位字节，搬到 `ByteStream`，最后推进窗口起点。

### 4.3 陷阱

1. **eof 判定**：`eof=true` 只代表「这条子串的最后一个字节是流的末尾」，**不代表所有字节都到齐了**。常见 bug：一收到 eof 就 `stream_out().end_input()`，结果后面还有洞没填，流提前结束。正确做法：记录「eof 那个绝对下标」，等 `first_unassembled` 推过它、且窗口里没洞时，才真正 `end_input()`。
2. **重叠处理**：子串可能和已组装区 / 窗口内已有字节重叠。要先按 index 裁剪掉已组装部分，再处理窗口内重复。
3. **capacity 双重含义**：`unassembled` 区 + `ByteStream` 已写入未读区，合计不能超 `capacity`。意思是：如果上层不读，收端缓冲满了就要拒绝新数据（返回窗口 0）。忘了这点会导致 byte_stream 容量测试挂。
4. **空串 + eof**：`push_substring("", index, true)` 是合法的，别因为 `data.empty()` 就直接 return 把 eof 丢了。

## 5. Lab 2：TCP 接收端（TCPReceiver）

对应 `lab_handouts/lab2.pdf`，文件 `libsponge/wrapping_integers.{hh,cc}` + `libsponge/tcp_receiver.{hh,cc}`。

### 5.1 考点

**两部分**，先做 `wrapping_integers` 再做 `tcp_receiver`：

1. **32 位序号换算**：TCP 报文里的 `seqno` 是 32 位的，会回绕（wrap）。你要在「32 位 `seqno`」和「64 位绝对序号 `abs_seqno`」之间正确换算：
   - `wrap(abs_seqno, isn) -> WrappingInt32`：绝对序号 + ISN（Initial Sequence Number）→ 32 位。
   - `unwrap(seqno, isn, checkpoint) -> uint64_t`：32 位 → 绝对序号。**关键陷阱**：32 位会回绕多次，`unwrap` 要返回离 `checkpoint` 最近的那一个解。
2. **TCPReceiver**：收 `TCPSegment`，把 payload 交给 Lab 1 的 `StreamReassembler`；维护 ISN、收到的最高连续序号（用于回 ACK）和接收窗口。

### 5.2 接口要点

- `segment_received(const TCPSegment &seg)`：处理一个收到的报文。第一个带 SYN 的报文确立 ISN；把 `seqno` `unwrap` 成 `abs_seqno`，减掉 SYN 占的那 1 字节，作为流重组器的 `index` 喂进去；FIN 标志转成重组器的 eof。
- `send()` / `ackno()` / `window_size()`：生成要回给对方的 ACK 报文。`ackno` 是「下一个期望收到的字节」的 `seqno`（用 `wrap` 包回 32 位，注意 SYN 占 1 字节、FIN 占 1 字节的偏移）；`window_size = stream_out().writer().available_capacity()`。

### 5.3 陷阱

1. **SYN/FIN 各占一个序号**：SYN 占 `abs_seqno` 1，FIN 也占 1。算 `index` 给重组器时要**减掉 SYN**；算 ackno 时如果流已收到 FIN，要把 FIN 那 1 字节加上。漏了 SYN 偏移是最常见的挂点。
2. **unwrap 的 checkpoint**：用「上一次成功组装的最高绝对序号」当 checkpoint，保证选对最近解。千万别用 0 当 checkpoint，会在 2^31 边界翻车。
3. **ISN 只设一次**：只有第一个 SYN 报文才设 ISN，后续 SYN（重传/重复）要忽略。
4. **窗口为 0**：`window_size` 算出来是 0 时，回给对方的要写 1（sponge 里是 `max(1, ...)` 约定），否则发端会以为你给了 0 窗口而永远静默。具体看 handout。

## 6. Lab 3：TCP 发送端（TCPSender）

对应 `lab_handouts/lab3.pdf`，文件 `libsponge/tcp_sender.{hh,cc}`。

### 6.1 考点

发端要做：从上层 `ByteStream` 读数据 → 切成 `TCPSegment` → 维护**滑动窗口** → **超时重传** → 收到 ACK 后滑动窗口并丢弃已确认段。

- **重传计时器**：维护一个 RTO（初始 1 秒，handout 给定），到期就把最早未确认的段重传，并把 RTO 翻倍（指数退避）。
- **窗口**：发端能发的范围是 `[next_seqno, next_seqno + window_size)`。`fill_window()` 负责把窗口填满。
- **零窗口 persist**：收端给窗口 0 时，发端要发一个 1 字节的探测段（zero-window probe），否则死锁。

### 6.2 接口要点

- `fill_window()`：从 `stream_in()` 读数据，切成不超 `TCPConfig::MAX_PAYLOAD_SIZE` 的段，发到 `segments_out()`。第一个段要带 SYN；流关闭且窗口还有空时，最后一个段带 FIN。
- `ack_received(ackno, window_size)`：处理收到的 ACK。`ackno` 用 `unwrap` 看是否推进了；滑动窗口右边界；丢弃全部已确认的未确认段；收到有效新 ACK 后**重置 RTO 回初始值、重启计时器**。
- `send_empty_message()`：发一个纯 ACK/探测段（窗口 0 时用它做 persist 探测）。
- `tick(ms)`：时间推进，到期触发重传。

### 6.3 陷阱（FlyingPig 强调，handout 读 5 遍的章节）

1. **窗口右边界 vs 窗口大小**：用两个变量——一个记收端通告的 `window_size`，一个记「已被确认的右边界 `rwindow`」。每次 `fill_window` 只在 `next_seqno < rwindow` 之间发。别只存窗口大小，会算错。
2. **零窗口当 1 处理**：当 `window_size == 0` 且 `next_seqno == rwindow` 时，`fill_window` 要**当成窗口=1** 发一个字节探测。这一条不写，`t_send_window` 的零窗口场景必挂，且后面和内核 TCP 互通会死锁。
3. **SYN 当特例**：第一个 SYN 段单独处理（它占 1 字节序号但没 payload），别和普通数据混在一个循环里。
4. **重传只重传最早未确认的那段**（sponge 的约定，非全重传）。看 handout 当前版本要求，有的版本要求重传整个窗口。
5. **连续重传计数**：`consecutive_retransmissions()` 要在每次重传 +1，收到有效新 ACK 清 0。

| 1 | `t_send_retx` 失败 | RTO 没翻倍 / 收到有效 ACK 没重置 RTO；或重传的不是最早未确认段 |
| 2 | `t_send_window` 卡死 | 零窗口没当 1 发探测；`fill_window` 里 `next_seqno == rwindow && window_size==0` 分支缺失 |
| 3 | `t_send_ack` 失败 | `ack_received` 没正确判断 ackno 是否推进（用 unwrap 比较），或没丢已确认段 |
| 4 | `t_send_extra` 失败 | payload 切超 `MAX_PAYLOAD_SIZE`，或 SYN/FIN 没占序号 |
| 5 | 发了空段把发端搞乱 | `send_empty_message` 不该消耗窗口、不该更新 `next_seqno` 的字节流部分 |
| 6 | 和 Lab 4 联调时一发就死锁 | 99% 是零窗口 persist 没实现 |

## 7. Lab 4：TCP 连接（TCPConnection）

对应 `lab_handouts/lab4.pdf`，文件 `libsponge/tcp_connection.{hh,cc}`。把 Lab 2 的 receiver 和 Lab 3 的 sender 拼成一条完整的连接，实现**握手 / 数据 / 挥手 / RST / linger**。

### 7.1 考点

- **拼装**：`TCPConnection` 内含一个 `TCPSender` 和一个 `TCPReceiver`。收包：先给 receiver 解析，再把对方 ACK/window 喂给 sender 的 `ack_received`；发包：调 sender 的 `fill_window`，把它产出的段加上 receiver 的 `ackno/window_size` 再发出。
- **状态机**：`active()`、握手（`connect()` 发 SYN）、被动监听、`segment_received`、`end_input`、`tick`。
- **挥手与 linger**：`linger_after_streams_finish` 这个布尔——如果**入流比出流先结束**，置 false，三个 prereq 满足就直接 `done`；否则要再等 `10 × cfg.rt_timeout` 才算完。
- **RST**：收端 RST → 给两个流 `set_error()` → 连接非 active；发不下去也发 RST。

### 7.2 陷阱

1. **`fill_window` 的段不会自动出连接**：sender 把段放到它自己的 `segments_out()`，**不是** TCPConnection 的。你要手动 pop 出来、补 ackno/window、再 push 进连接的 `segments_out()`。FlyingPig 在 README 里反复强调这点。
2. **linger 判定时机**：在 `segment_received` 里**第一次发现入流结束**时就要决定 `linger_after_streams_finish` 的值（看入流是否比出流先 EOF）。错过这个点后面永远判不对。
3. **挥手里收到的 ACK 要清重传计时器**：避免挥手段被当超时重传。
4. **同时关闭 / 同时打开**：FSM 测试（`fsm_active_close` / `fsm_passive_close`）会覆盖，状态别写死成「我主动」一种。

### 7.3 跑测试

Lab 4 的测试不再是 ctest 单测，而是用 TUN 设备跑真实交互：

```bash
# 首次会要 sudo 建 tun0/tun1
sudo make check_lab4        # 跑 tun.sh check 144 145
```

`tun.sh check 144 145` 会建两张 TUN 网卡，把你写的 TCP 通过 `apps/tcp_ipv4`（或 lab7 那套）和内核 TCP 对打。过的话打印一段抓包摘要、连接正常关闭。

> 如果只想先做单元级的 FSM 测试（不用 TUN），`ctest -R 'fsm_(active_close|passive_close|connect|listen|ack_rst|loopback|reorder|retx)'` 这些纯内存状态机测试先过一遍，再去碰 TUN。

### 7.4 Lab 4 常见报错

| # | 报错/现象 | 一行修复 |
|---|----------|---------|
| 1 | `tun.sh` 卡住不结束 | linger 没实现，挥完手一直 active；或 sender 段没补 receiver 的 ack |
| 2 | `fsm_active_close` / `passive_close` 失败 | 状态迁移不全；对照 handout 的状态图逐条查 |
| 3 | 抓包看到全是重传 | 收 ACK 没清 sender 的重传队列 / RTO 没重置 |
| 4 | `sudo make check_lab4` 报 `Operation not permitted` 建 tun | 容器没给 `--cap-add=NET_ADMIN`；或非 root 没 sudo |
| 5 | 一收到 RST 还在发包 | RST 后没 `set_error` + 置 inactive |

## 8. Lab 5：网络接口（ARP）

对应 `lab_handouts/lab5.pdf`，文件 `libsponge/network_interface.{hh,cc}`。从这儿起进入 TCP/IP 栈的下半部分：把 IP 数据报和以太网帧之间用 ARP 抹平。

### 8.1 考点

- **发帧**：上层（Router）给一个 IP 数据报要发到某个下一跳 IP。你要：查 ARP 表有没有这个 IP 的 MAC → 有就封装成以太网帧发出；没有就**缓存该数据报**，广播一个 ARP 请求（目标 MAC 全 0/broadcast），等回复。
- **收帧**：收到 ARP 请求 → 回复自己的 MAC；收到 ARP 回复 → 学到「IP→MAC」映射，把缓存的等待数据报全部发出去。
- **ARP 表过期**：每条映射存活约 30 秒（handout 给定 5000ms ~ 30s，按你的 handout 来），过期要重新请求。这是 ARP 防止「IP 漂移」后还能通信的关键。

### 8.2 陷阱

1. **不要每个数据报都广播 ARP**：同一 IP 在缓存有效期内只发一次 ARP 请求（对同一未解析 IP 的后续数据报先排队，别再广播）。FlyingPig 说这 lab 简单到「一次编译过」，但 ARP 表过期和重复请求抑制容易漏。
2. **过期时间**：用发送时间戳记录，`tick` 时清理。
3. **ARP 请求/回复格式**：用 `ARPMessage` 类（`tcp_helpers/` 下），`opcode` 区分请求(1)/回复(2)。

### 8.3 跑测试

```bash
sudo make check_lab5      # tap.sh check 10，用 TAP 设备测 ARP
ctest -R 'arp'            # net_interface 内存级 ARP 测试
```

`arp_network_interface` 这一项通过即 ARP 基本正确。

### 8.4 Lab 5 常见报错

| # | 报错/现象 | 一行修复 |
|---|----------|---------|
| 1 | `arp_network_interface` 超时 | 同一 IP 反复广播 ARP（没抑制），或回复没发出去 |
| 2 | 表项不过期 | 没存时间戳 / 没在 tick 里清理，导致 IP 漂移后永远发老 MAC |
| 3 | 缓存数据报丢失 | ARP 回复回来时忘了把排队的数据报 flush 出去 |

## 9. Lab 6：IP 路由（Router）

对应 `lab_handouts/lab6.pdf`，文件 `libsponge/router.{hh,cc}`。基于 Lab 5 的网卡，实现 IP 路由：收到数据报，查路由表，按**最长前缀匹配**转发到对应网卡。

### 9.1 考点

- **路由表**：`add_route(route_prefix, prefix_length, next_hop, interface_num)` 加一条。
- **转发**：`route_datagram(dgram)` 遍历所有路由表项，找前缀匹配且 `prefix_length` **最长**的那条，把数据报从对应 interface 的 `network_interface` 发到 `next_hop`（若 next_hop 为空，目的就在该网段直连）。
- **默认路由**：`0.0.0.0/0` 是 prefix_length=0 的兜底，测试里专门测它。

### 9.2 陷阱

1. **别上来就写 Trie**：FlyingPig 明说「暴力遍历就够过测试」。先正确性后性能。
2. **prefix_length=0 特判**：`0.0.0.0/0` 匹配一切，但要选更长前缀的优先，所以匹配逻辑里要按 length 排序/取 max。
3. **掩码计算**：`mask = prefix_length==0 ? 0 : (~0 << (32 - prefix_length))`，注意 32 位边界（length=32 时全 1）。
4. **next_hop 为空**：表示目的 IP 就在该接口直连网段，ARP 时直接查目的 IP 的 MAC。

### 9.3 跑测试

```bash
make check_lab6          # 跑 arp_network_interface + router_test(network_simulator)
ctest -R 'router'        # network_simulator，模拟多网卡多路由转发
```

期望 2 项全过。`router_test` 会建一个虚拟网络拓扑，验证你的路由能把数据报到对的地方。

### 9.4 Lab 6 常见报错

| # | 报错/现象 | 一行修复 |
|---|----------|---------|
| 1 | `router_test` 转发到错网卡 | 没取最长前缀，取了第一个匹配 |
| 2 | 默认路由不生效 | `0.0.0.0/0` 没当 length=0 处理，掩码算成全 1 |
| 3 | 目的在直连网段时 ARP 找错 IP | next_hop 为空时该用 dgram 的目的 IP 去查 ARP，而不是 next_hop |

## 11. 学完能干嘛

做完这 6 个 lab，你手里有了一套**可读、可调、可改**的 TCP/IP 栈。直接的好处：

1. **能读懂 nginx / Linux TCP 栈的关键路径**。零窗口探测、重传、快速重传、ARP 缓存——这些在 nginx 的 `ngx_event`、内核的 `tcp_input.c` 里都是同一套概念，你亲手实现过，再看就不晕。
2. **线上故障能定位到协议层**。`CLOSE_WAIT` 堆积 = 收端没 `close`（你写过 FIN 处理）；粘包 = TCP 本就是字节流、没消息边界（你的 ByteStream 就是证据）；零窗口死锁 = persist 没做（Lab 3 的坑）；ARP 表过期导致偶发不通 = Lab 5 的过期机制。
3. **面试/答辩能讲清「为什么」**。三次握手为什么不是两次（你写过 SYN/ISN，知道 SYN 要被 ack）；TIME_WAIT 为什么 2MSL（你写过挥手的 linger）；滑动窗口为什么不能只看大小（你维护过 `rwindow`）。
4. **现代 C++ 上了一个台阶**。sponge 框架用了 `std::optional`、移动语义、RAII、接口/实现分离，读它的框架代码本身就是一堂 C++ 课。
