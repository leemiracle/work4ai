# 经典逻辑 vs 直觉主义逻辑：排中律之争

> Curry-Howard 天然覆盖直觉主义逻辑。经典逻辑需要"额外结构"。这场争论持续了 100 年。

---

## 一、排中律（LEM）——分歧的核心

**经典逻辑**：A ∨ ¬A 总是成立（每个命题非真即假）
**直觉主义逻辑**：A ∨ ¬A 不一定成立（你可能既没有 A 的证明也没有 ¬A 的证明）

| 定理 | 经典 | 直觉主义 | Curry-Howard |
|------|------|---------|-------------|
| A → ¬¬A | ✓ | ✓ | ✓ 有对应程序 |
| ¬¬A → A（反证法）| ✓ | ✗ | ✗ 无对应程序 |
| A ∨ ¬A（LEM）| ✓ | ✗ | ✗ 无对应程序 |
| ¬¬(A ∨ ¬A) | ✓ | ✓ | ✓ |

## 二、为什么 LEM 没有对应的程序？

`A ∨ ¬A` 的类型 = 和类型 `A + (A → ⊥)`。

要构造这个和类型，你必须有：
- 左边的值 `a : A`（A 的证明），或
- 右边的值 `f : A → ⊥`（¬A 的证明）

但对于某些 A（如 Goldbach 猜想），你可能**两者都没有**——不知道 A 成立也不知道 ¬A 成立。LEM 断言"总有一个"，但不告诉你**怎么找到**它。

## 三、经典逻辑如何嵌入 Curry-Howard

### 方法1：双否定翻译（Gödel-Gentzen）
把经典命题 A 翻译为直觉主义命题 A*：
- (A ∨ B)* = ¬¬(A* ∨ B*)
- (A → B)* = A* → B*
- (¬A)* = A* → ⊥

结果：经典逻辑可证明 A ⟺ 直觉主义逻辑可证明 A*

### 方法2：Continuation（call/cc）
在编程语言中，`call/cc`（call with current continuation）对应经典逻辑的 LEM。

```scheme
;; call/cc 允许"穿越"返回——经典控制流
(call/cc (lambda (k) ...))
```

类型：`((A → ⊥) → ⊥) → A` = Peirce 律 = 等价于 LEM

### 方法3：Lean 的做法——加经典公理
Lean 在依赖类型论基础上**额外加了** `Classical.choice`：
```lean
-- 接受经典逻辑
open Classical
theorem em (A : Prop) : A ∨ ¬A := by ...
```

这样 Lean 可以同时做直觉主义和经典证明。

## 四、Brouwer 的直觉主义哲学

L.E.J. Brouwer（1907）主张：
- 数学是**心智构造**，不是"客观真理"
- 存在 = 构造（"存在"意味着"我找到了"）
- 反对非构造性证明（反证法证明存在 ≠ 找到具体例子）

**Heyting**（1930）形式化了直觉主义逻辑。
**Kolmogorov**（1932）给出了 BHK 解释（Brouwer-Heyting-Kolmogorov）：
- A ∧ B 的证明 = A 的证明 + B 的证明
- A ∨ B 的证明 = A 的证明 **或** B 的证明（必须知道是哪个）
- A → B 的证明 = 一个把 A 的证明转化为 B 的证明的**算法**
- ¬A 的证明 = 一个把 A 的证明转化为矛盾的算法
- ∃x P(x) 的证明 = 一个**具体的** x **加上** P(x) 的证明

→ 这就是 Curry-Howard 的哲学先驱！

## 五、构造性数学的现代复兴

### 为什么现在关心构造性？
1. **计算机验证**：构造性证明 = 可执行程序（Lean/Coq）
2. **算法提取**：构造性证明可以直接提取算法
3. **有限计算**：构造性数学只承认可计算的东西
4. **Homotopy Type Theory**：HoTT 部分基于直觉主义

### 构造性分析的例子
经典定理："存在 x 使得 f(x)=0"（用 IVT + 反证法）
构造性版本：**给出算法**找 x（如二分法），保证精度

→ 经典数学说"有"，构造性数学说"在哪"。
