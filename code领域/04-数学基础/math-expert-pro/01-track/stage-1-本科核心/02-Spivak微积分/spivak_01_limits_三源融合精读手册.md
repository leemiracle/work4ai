### 1.2 习题分级(必做 / 选做 / 挑战)

> 以你手头 Spivak 版本章节编号为准,以下按"题型"分级(各版次题号略有差异)

**🟢 必做(阶段 1 验收要求,做出才算通关)**
- 线性函数 ε-δ 证明:`lim(x→a)(mx+b) = ma+b`,找 δ(ε)
- 平方函数:`lim(x→a) x² = a²`,找 δ(ε)——提示 δ=min(1, ε/(...))

**🟡 选做(巩固)**

**🔴 挑战(阶段 1 灵魂,做出=post-rigorous 门槛)**
- `sin(1/x)` 在 x→0 无极限的严格证明

### 1.3 ε-δ 证明骨架(不给答案,给思路)

```
证 lim(x→a) f(x) = L:

【草稿·倒推】从 |f(x)-L| < ε 出发
   |f(x)-L| = ...(代数变形)... = K·|x-a|
   要 < ε  ⟺  |x-a| < ε/K
   → 候选 δ = ε/K

【正式·正向】任给 ε>0,取 δ = ε/K
   则 0<|x-a|<δ ⟹ |f(x)-L| = K·|x-a| < K·δ = ε  □

【陷阱自检】
   □ K 是正常数吗?(若 K 依赖 x,要更精细)
   □ δ 需要取 min(...) 防止 x 跑出定义域吗?
```

> 🔑 **成熟度关键**:草稿可以乱,正式证明必须逻辑正向闭合。Spivak 全书在训练这种"分析-综合"双轨思维。

## §3 飞腾 D3000M 实测锚点(实践层)⭐ 本手册核心特色

> 这是任何普通微积分学习指南给不了你的:把抽象的"极限/ε"落到**你能亲手测的硬件行为**上。
> 以下数据均为飞腾 D3000M(FTC862)真机 `[实测]`,来源见飞腾项目 `CODE_INDEX.md`。

### 3.1 锚点一:机器精度 ε ↔ ε-δ 定义

**数学**:ε-δ 说"任意小的 ε 都能应对"。
**硬件现实**:计算机的 ε **有下限**——机器精度 `eps`。

| 浮点类型 | 飞腾 D3000M `[实测]` 性能 | ε(机器精度) | 含义 |
|---------|--------------------------|-------------|------|
| FP64 | 1.79 GFLOPS(基准) | ≈2.2×10⁻¹⁶ | 能区分 1 和 1+eps 的最小 eps |
| FP32 | 中间档 | ≈1.2×10⁻⁷ | 精度降 10⁹ 倍 |
| **FP16** | **6.82 GFLOPS(3.81× 快)**`[实测 Lab01]` | ≈9.8×10⁻⁴ | 精度只够 3 位有效数字 |

> 🔍 **思考题(连接数学与硬件)**:
> 1. 为什么 FP16 "快 3.81 倍"但"精度只够 3 位"?(位宽 16 vs 64,寄存器/带宽/ALU 全省)
> 2. ε-δ 证明里,如果 ε < 9.8×10⁻⁴,FP16 还能"应对"吗?(不能——这就是浮点的"δ 失效")
> 3. 这说明**计算机的极限世界是 ε-δ 的有限截断**,而非数学的"任意 ε"。

**亲手实验**(飞腾本机可跑):参考飞腾 `Lab01_ISA与汇编/src/fp16_perf.c`
```bash
taskset -c 0 ./fp16_perf   # 看 FP16/FP32/FP64 各自精度与速度
```

### 3.2 锚点二:迭代法收敛 = 极限的算法化

**数学**:`lim(n→∞) aₙ = L`,即迭代序列收敛。
**工程**:牛顿法、梯度下降何时停?→ 这就是"极限"的工程化身。

飞腾 `[实测 Lab00 iron_law]`:用性能模型预测 CPU 时间 T_pred,实测 T_med,**误差 < 2%**。
- 这本质是验证"模型值 ⟶ 真实值"的近似——一个**工程版的 ε-δ**(误差带 = ε)。

> 🔍 **思考题**:
> - 牛顿法 `xₙ₊₁ = xₙ - f(xₙ)/f'(xₙ)` 收敛到根,停止条件 `|xₙ₊₁-xₙ| < tol` 里的 `tol` 扮演 ε-δ 中的哪个角色?(ε)
> - 飞腾 2% 误差是模型偏差,不是浮点误差——区分"数学极限"与"工程容差"。

### 3.3 锚点三:浮点误差累积 ↔ 极限的"陷阱"

**数学陷阱**:Spivak §4 的 `sin(1/x)` 震荡——直觉失效。
**硬件陷阱**:浮点运算不满足结合律!`(a+b)+c ≠ a+(b+c)`。

飞腾 `Expert_08_Numerics`(数值分析专家视角)专门讲:
- IEEE 754 浮点的** catastrophic cancellation**(灾难性抵消)
- Kahan 求和算法:用误差补偿挽回精度

> 🔍 **思考题(进阶)**:
> - 浮点 `1/3 + 1/3 + 1/3` 在 FP64 等于 1.0 吗?(几乎,但有误差)
> - 这与 Spivak 极限的"运算法则要求极限存在"如何对应?(浮点的"极限"在每一步都已破坏)

### 3.4 三源融合一句话总结

> **Spivak 教你"任意 ε 都能应对"的理想极限;飞腾 D3000M 告诉你真实计算机的 ε 有底(机器精度)、会累积(IEEE754)、还要在精度与速度间权衡(FP16 3.81×)。数学是极限的上界理论,工程是极限的有限实现。**
