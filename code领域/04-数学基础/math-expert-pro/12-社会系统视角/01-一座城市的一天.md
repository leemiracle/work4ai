# 一座城市的一天：交通、电网、地铁、供水、急救如何协同

> **一句话点睛**：早上 7:30 新加坡 500 万人同时开始一天，6500 辆公交车在 9500 车道公里路网运行，每天 750 万次公共交通出行——交通信号实时调整、电网平衡 12GW 负荷、急救车从最近消防站出发，这一切由数学模型在后台协同。SCOOT 系统在 350+ 城市减少 15% 延迟。

---

## 真实场景（具体到人/地/时）

早上 7:30，新加坡。

赤道边的太阳已经升起。500 万人同时开始一天。6500 辆公交车在 9500 车道公里的路网上运行。地铁按秒级时刻表穿梭。交通信号灯在实时调整——不是固定的"红灯 30 秒绿灯 30 秒"，而是根据此刻各方向的车流量，每几秒钟重新计算最优配时。电网在平衡 12GW（1200 万千瓦）的实时负荷——写字楼空调启动、工厂机器开动、每家的电热水壶同时烧开。供水管网维持全市水压，让每一层楼的龙头都有水。急救车从最近的消防站出发，一路绿灯奔赴心脏病发作的老人。

**同一秒钟里，这座城市在做千万个数学决策。** 而你只是端着咖啡走向地铁站，完全感觉不到它们的的存在。

这就是"智慧城市"的真相：不是多装了几个摄像头，而是后端有无数数学模型在实时协同。我们拆开这座城市的一天，看看数学藏在哪。

## 数学如何出现（🟢事实，含 LaTeX 公式）

### 五个子系统，五种数学

| 子系统 | 核心数学 | 协同接口 |
|--------|---------|---------|
| **交通信号协同** | SCOOT：实时优化 Split（绿信比）+ Cycle（周期）+ Offset（相位差） | 🟢 15% 延迟减少 |
| **电网调度** | 经济调度（线性规划）：$\min \sum c_i P_i$ s.t. $\sum P_i = D_{load}$ | 实时匹配供需 |
| **地铁班次** | 排队论 + 时刻表优化（整数规划） | 与公交接驳 |
| **供水管网** | Hardy Cross 法 / 牛顿迭代解管网方程 | 压力-流量耦合 |
| **急救车调度** | 设施选址（p-中值问题）+ 实时调度（最短路） | 与交通信号联动 |

### 1. 交通信号——SCOOT 系统

🟢 **SCOOT**（Split Cycle Offset Optimisation Technique）由英国交通研究实验室（TRL）1979 年开发：

- 路面感应线圈检测各方向车流量 → 预测下一周期到达车辆数 → 优化三个参数：
  - **Split（绿信比）**：每个方向分到多少绿灯时间
  - **Cycle（周期长度）**：一轮红绿灯循环多久
  - **Offset（相位差）**：相邻路口的绿灯如何错开，形成"绿波带"（一路绿灯）
- 关键数学：把路口分组为"区域"（region），在区域层面**同时优化**所有路口的参数——不是单个路口各自为政，而是全局协调。

### 2. 电网调度——经济调度

每一秒，电网的发电量必须等于用电量（加上损耗）：

$$\min \sum_i c_i P_i \quad \text{s.t.} \quad \sum_i P_i = D_{load}, \quad P_i^{min} \leq P_i \leq P_i^{max}$$

其中 $c_i$ 是第 $i$ 台发电机组的单位成本，$P_i$ 是其出力，$D_{load}$ 是当前总负荷。这是一个**线性规划**——在满足供需平衡和机组容量约束下，让总发电成本最低。

### 3. 供水管网——Hardy Cross 法

城市供水是一个复杂的管网（节点=管道交叉点，边=管道）。水从泵站流入，在管网里分流。每条管道的流量和压力降满足流体力学方程。**Hardy Cross 法**（1936 年提出）用迭代（牛顿迭代法）求解这个非线性方程组，确保每个节点的流量守恒、每条管道的压力降一致。

### 4. 急救车——p-中值选址

急救车的部署是一个**设施选址问题**：在 $p$ 个候选消防站中选 $p$ 个，让全城居民到最近消防站的平均距离最短。数学上是 **p-中值问题**：

$$\min \sum_i \sum_j w_i d_{ij} x_{ij}$$

其中 $w_i$ 是区域 $i$ 的人口权重，$d_{ij}$ 是区域 $i$ 到消防站 $j$ 的距离，$x_{ij}$ 是分配变量。出车时再用最短路算法（Dijkstra）找最快路线，并与交通信号系统联动——让急救车一路绿灯。

## 真实案例剖析（年份/数据/出处）

- 🟢 **新加坡智能交通系统（ITS）**：新加坡陆交局（LTA）运营 **iTransport** 统一平台，整合所有交通数据。核心组件包括 EMAS（高速公路监控与建议系统）、ERP 2.0（基于卫星的拥堵收费系统）。新加坡道路占国土面积 **12%**，每天 **750 万次**公共交通出行。来源：[LTA Intelligent Transport Systems](https://www.lta.gov.sg/content/ltagov/en/getting_around/driving_in_singapore/intelligent_transport_systems.html)；[Smart Nation 2.0 Report](https://file.go.gov.sg/smartnation2-report.pdf)
- 🟢 **SCOOT 全球部署**：伦敦、多伦多（1992 年首装）、西雅图（Mercer Street 2017 年首装，覆盖 32 个路口）等 **350+** 城镇。SCOOT 比固定配时方案减少约 **15%** 的延误。来源：[Wikipedia: SCOOT](https://en.wikipedia.org/wiki/Split_Cycle_Offset_Optimisation_Technique)；[Seattle DOT](https://www.seattle.gov/transportation/projects-and-programs/programs/technology-program/mercer-scoot)
- 🟢 **伦敦升级**：伦敦交通局（TfL）正在用 **FUSION** 系统（与 Yunex Traffic 合作开发）替代 SCOOT，目标 2025/26 财年部署 500 个路口，2030/31 财年完成全部 **4,350** 个路口。
- 🟢 **新加坡 Punggol Digital District**：首个智慧社区，**开放数字平台（ODP）**统一整合电力、水务、照明系统——例如在人少时自动调低空调和照明。来源：[GovTech Singapore](https://www.tech.gov.sg/about-us/what-we-do/our-capabilities/smart-city-technology/)

**翻译一下这些数字**：SCOOT 减 15% 延迟，听起来不多——但如果一座城市的通勤者每天省 15% 的时间，一年下来就是每个上班族多出几十小时。4350 个路口全部智能协调，背后是每秒数万次的最优化计算。

### Python 实操：模拟急救车选址

```python
# p-中值问题的极简版：用 NetworkX 给城市消防站选址
import networkx as nx
# 构建城市路网，节点=路口，边=道路
G = nx.grid_2d_graph(20, 20)  # 20x20 的网格城市
# 选 3 个消防站，让所有路口到最近消防站的距离之和最小
# （真实 p-中值是 NP-hard，这里用贪心近似）
from itertools import combinations
best, best_dist = None, float('inf')
for stations in combinations(G.nodes(), 3):
    total = sum(min(nx.manhattan_distance(n, s) for s in stations) for n in G.nodes())
    if total < best_dist:
        best, best_dist = stations, total
print(f"最优消防站位置：{best}")
```

## 常见误区（❌标注）

- ❌ **"智慧城市 = 多装摄像头"** → 真正的核心是后端的**数学优化模型**实时决策。摄像头只是传感器的眼睛，没有大脑（优化算法），眼睛再多也没用。
- ❌ **"绿波带只是把绿灯拉长"** → SCOOT 是在每个周期实时微调 Split/Cycle/Offset 三个参数，不是简单延长绿灯。它要在"给主干道更多绿灯"和"不让支路等太久"之间做权衡。
- ❌ **"电网可以无限存储电"** → 目前电网级储能仍然有限（锂电池大多 4 小时），必须实时供需平衡（$\sum P_{gen} = P_{load}$ 每秒必须成立）。电能"现发现用"的特性是电网一切复杂性的根源。

## 这个场景教会我们什么（系统协同素养）

一座城市的"丝滑运转"是一种错觉——真相是千万个数学模型在实时协同。

SCOOT 不是把绿灯拉长，而是每秒重新计算最优配时，在主干道和支路、机动车和行人之间做权衡。电网不是"发电就行"，而是 $\sum P_{gen} = P_{load}$ 每一秒都必须成立——一旦发电跟不上用电，频率就会偏移，偏移太多就是停电（见 [05-电网与能源转型](05-电网与能源转型.md) 德州的教训）。急救车不是"跑得快就行"，而是 p-中值选址决定了它从哪里出发，最短路算法决定了它走哪条路，信号联动决定了它能不能一路绿灯。

理解这一点，你才会明白为什么"智慧城市"的真正瓶颈不是硬件（多装几个传感器很容易），而是**算法**——如何在毫秒内求解一个包含数千变量、数万约束的优化问题，而且每秒都要重算。

> **核心素养：系统性思维——看见组件之间的连接关系，而非单个组件。** 城市不是一个个人、一辆辆车、一栋栋楼的集合，而是一个由数学模型协同的活的系统。看见"协同"，你才能理解为什么一个环节出问题（比如电网跳闸）会让交通信号、地铁、供水全部连锁失效。
