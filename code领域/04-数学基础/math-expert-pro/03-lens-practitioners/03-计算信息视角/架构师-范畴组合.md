# 资深软件架构师（把数学当"设计模式"看）

> 公理 ≈ 接口契约，范畴论 ≈ 数学的"设计模式语言"——都给"可组合结构"命名。

架构师的日常是"分层抽象 + 给可复用结构起名字"，这恰好和抽象代数 / 范畴论做的是同一件事。本视角偏 🟡 类比，但能帮你在学代数结构时迅速建立工程直觉。

## 核心数学工具箱
🟢【事实】
- **抽象代数结构**：monoid / 半群（semigroup）——函数式编程 `Monoid` / `Semigroup` 类型类的基础
- **范畴论**：functor、natural transformation、monad（严格定义）
- **类型论**：代数数据类型 = 积类型（product）/ 和类型（sum）

## 独特视角：把数学当"设计模式"看
- 🟡 公理 ≈ 接口契约：都规定"怎样合法操作"，不关心内部实现
- 🟡 范畴论 ≈ 数学的"设计模式语言"（Gabriel Gonzalez "The category design pattern"：范畴是对"可组合结构"的命名）
- 🟡 Monad ≈ 依赖反转：把"副作用/上下文"从核心逻辑解耦
- 🟢 Haskell `Monad` 定律（左单位 / 右单位 / 结合律）数学上等价于 Kleisli 范畴公理——"每个 Monad 免费给你一个范畴"

## 作为学习透镜怎么用
- 学 **monoid / 半群** 时照一遍：它就是"可并行 reduce"的最小契约——结合律 = 可任意分组，单位元 = 空操作默认值。这就是 MapReduce 能跑的数学原因。
- 学 **functor** 时：理解"为什么 `map` 在 list / Maybe / Future 上都叫 `map`"——它们都满足同一组范畴论定律（保持恒等与复合）。
- 学 **抽象代数结构** 时做三连问：(1) 它满足哪些定律？(2) 这组定律能不能当"接口"用？(3) 哪些类型是它的实例？

## 适合照哪些数学概念
（来自 14×12 矩阵第 1 列）
- **抽象**：分层抽象 = 架构师的核心手艺，和数学层层抽象代数结构（ℝ→度量空间→拓扑空间）同一种思维
- **线性**：组合性 = 可独立处理，"线性"在架构里 = 可分解、可并行
- **不变量**：契约 / 断言 = 运行时不变量，对应数学"运算下封闭"
- **优化**：架构 = 约束下最优（在性能/可维护/成本间权衡）【类】
- **对称**：接口互换性 = 可替换实现，对应"对称=操作下不变"【类】
- **信息**：接口 = 信息隐藏，封装的本质【类】
- **证明**：契约验证 ≈ 类型检查/断言证明【类】
