# 证明

> 证明是把"为什么相信"压缩成可检验的形式。

## 出现在哪些教材/阶段

| 视角 | 出处 | 阶段 |
|------|------|------|
| 经典证明 | Euclid《几何原本》/ Hardy《数学家的辩白》 | 数学传统 |
| 构造性证明 | Bishop《构造性分析》/ Brouwer 直觉主义 | 计算数学、数理逻辑 |
| Curry-Howard 同构 | Howard 1969 / 类型论 | PL、定理证明 |
| Lean 形式化 | Lean / Coq / Isabelle | 机证、AI 数学 |

## 多重表征并列对照

| 视角 | 数学表象 | 直觉 | 典型场景 |
|------|----------|------|----------|
| 经典证明 | 前提 → 推理 → 结论 | 逻辑不可破的论证 | 数学论文、教材 |
| 构造性证明 | ∃x.P(x) 须给具体 x | 证明即算法 | 计算数学、算法验证 |
| Curry-Howard | 命题=类型，证明=程序 | 每个证明可执行 | 类型论、PL 设计 |
| Lean 形式化 | tactic / term 机器验证 | 机器不会被骗 | 复杂定理验证 |

### 经典证明：数学的黄金标准

经典证明是前提 → 逻辑推理 → 结论的链条，常用四种范式：
- **直接证明**：从前提直接推出结论。
- **反证法**：假设 ¬Q 推出矛盾。
- **构造法**：构造满足条件的对象。
- **数学归纳法**：基底 + 归纳步。

经典证明接受排中律 P ∨ ¬P，因此"非非 P"等价于 P，允许"通过排除不可能来证明存在"。

何时用：数学论文、教材、口试。这是绝大多数教材默认的证明范式。

### 构造性证明：直觉主义立场

构造性证明要求：证明 ∃x P(x) 必须给出具体的 x，或给出找到 x 的算法。不接受排中律——你不能仅凭"假设不存在会矛盾"就断言存在。

代表：Bishop《构造性分析》把整个分析学重构为可计算版本；Brouwer 直觉主义坚持数学是心智构造。

调研 01（Wildberger 节 14）记录了 Wildberger 的构造主义倾向：他反感"存在但不可计算"的证明，主张算法可执行、可输出。

何时用：计算数学、算法正确性、从证明中"抽取"程序（proof mining）。

### Curry-Howard 同构：证明就是程序

命题即类型，证明即程序。逻辑连接词对应类型构造：
- 合取 ∧ ↔ 积类型 A × B（pair）
- 析取 ∨ ↔ 和类型 A + B（tagged union）
- 蕴含 → ↔ 函数类型 A → B
- 真 ⊤ ↔ 单位类型，假 ⊥ ↔ 空类型
- ∀ ↔ 依赖类型 Π，∃ ↔ 依赖类型 Σ

直觉：构造某种类型的程序 ⟺ 证明对应命题。函数应用就是"切断推理"（modus ponens），λ 抽象就是"假设引入"。

何时用：类型论、依赖类型语言（Idris、Agda）、定理证明器的 term 模式、函数式编程"类型即规约"思想。

### Lean 形式化：机器不会撒谎

Lean / Coq / Isabelle 等证明助手把证明编码为内核可验证的形式对象。证明要么通过 kernel 检查，要么不通过——没有"差不多对"。

调研 03（discrete-math-lean 弹药）显示 Lean 已能形式化离散数学的标准内容；同时调研发现"Lean 几乎未被引用"于本科教材，是一个机会缺口。

AlphaProof（DeepMind）用 Lean 做 IMO 题，把 AI 推理接入形式化管道——AI 草拟思路，Lean 兜底验证。这是 AI 数学的当前范式前沿。

何时用：复杂数学定理的机器验证（四色定理、Feit-Thompson）、AI 数学、教学中"打消争论"。

## 它们的统一与差异

统一：Curry-Howard 揭示"证明"和"计算"是同一事物的两面。构造性证明恰好是"可执行的证明"——它给出算法。Lean 是 Curry-Howard 的工业实现：tactic 层写人话，term 层是类型化程序，kernel 层验证。

差异：
- 经典证明允许非构造（用排中律），可证存在但给不出例子。
- 构造性证明剥离排中律，得到算法。
- Curry-Howard 是两者之间的精确对应字典。
- Lean 是这套字典的工具化落地，把"信任"下沉到极小的 kernel。

高观点（谱系）：Brouwer 直觉主义（1920s）→ Heyting 形式化直觉主义逻辑（1930s）→ Curry-Howard 同构（1934/1969）→ Martin-Löf 类型论（1970s）→ Lean / Coq（2010s+）。一条从哲学到工程的主线：把"可验证"不断下沉到机器。

## 跨学科这张面孔

- **编译器角色**：类型检查就是轻量级的证明检查——通过类型检查 ⟺ 证明了一个（弱）定理。这是 Curry-Howard 在工程里最普及的化身。
- **密码学角色**：零知识证明（zk-SNARK）让你能"证明你知道"而不泄露内容；完整性与可靠性是它的两根支柱。
- **AI 角色**：AlphaProof = AI 推理 + Lean 验证；神经-符号系统的范式，把 LLM 的"直觉"与形式化的"严格"拼起来。
