# 问题定义与选择能力指标 ⭐ 最核心

## 核心公式

AI时代个人价值 =

**问题定义质量 × 问题选择能力 × 解决执行能力**

AI在"解决执行"上极强
AI能生成"框架内问题"
但AI无法：
- 质疑框架
- 定义价值
- 选择意义

这是人类最后的护城河。

---

## 什么是问题定义能力？

问题定义能力 ≠ 会提问。

**真正定义是**：

> 在混乱信息中，抽取"真正值得解决的核心问题"，并清晰设定边界与目标。

## 问题定义的四个要素

1. **找到真正的问题**（而不是表象）
2. **定义目标函数**（解决到什么程度）
3. **设定约束条件**（资源、时间、风险）
4. **明确成功标准**（如何判断对错）

**如果这四点不清晰，后续努力大概率浪费。**

## 问题定义的底层结构（核心模型）

任何问题都可以拆成五个维度：

### 1. 现状（What is happening?）
当前发生什么？

### 2. 期望（What should happen?）
应该发生什么？

### 3. 差距（Gap）
现状和期望之间的差距

### 4. 约束（Constraints）
资源、时间、风险等限制

### 5. 衡量指标（Metric）
如何判断问题解决？

### 公式化表达

**问题 = 目标 - 现状 + 约束条件**

- 如果没有目标，就没有问题
- 如果没有约束，就无法决策

## 为什么这能力稀缺？

因为大脑天然会：

1. **关注表面症状**
   - 看到现象直接跳到解决方案
   - 不深究根本原因

2. **急于给解决方案**
   - 大脑喜欢快速获得确定感
   - 不愿花时间定义问题

3. **忽略隐含假设**
   - 接受问题框架而不质疑
   - 不问"为什么这是个问题"

4. **混淆目标和手段**
   - 把"怎么做"当成目标
   - 忽略"为什么要做"

### 举例：性能问题

**现象**: "性能慢"

大多数人直接跳到"优化代码"

**真正问题可能是**：
- 架构设计问题？
- IO瓶颈？
- 资源分配不合理？
- 目标本身设定错误？
- 根本不需要优化？

## 系统训练框架（四步循环）

### 第一步：表象 → 根因

**训练动作**：

对任何问题连续问：
- 这是真的吗？
- 这是因还是果？
- 如果它不是问题，真正的问题是什么？

**练 5 Why**：
1. 第一个Why：为什么会发生？
2. 第二个Why：为什么会有这个原因？
3. 第三个Why：再深层的原因？
4. 第四个Why：还有更根本的原因？
5. 第五个Why：找到根因

---

### 第二步：目标函数明确化

**问**：
- 成功长什么样？
- 是速度？成本？体验？长期价值？

**很多人失败，是目标模糊。**

**目标清晰度检查**:
- 能用一句话描述目标吗？
- 知道什么时候达成吗？
- 知道什么是"足够好"吗？

---

### 第三步：边界设定

**问**：
- 时间约束？
- 资源约束？
- 风险容忍度？
- 不可触碰底线？

**方向来自边界。**

**边界清单**:
- [ ] 时间边界
- [ ] 资源边界
- [ ] 技术边界
- [ ] 合规边界
- [ ] 风险边界

---

### 第四步：反向定义

**问**：
- 如果我定义错问题，会发生什么？
- 是否存在更高层问题？

**这是方向能力的关键。**

**反向检查**:
- 假设解决了这个问题，会带来什么副作用？
- 如果不解决这个问题，真正会损失什么？
- 这个问题的上一层问题是什么？

## 三个关键升级点

### 1️⃣ 学会区分三类问题

**执行问题（How）**
- "如何实现这个功能？"
- "如何优化这个指标？"
- 特征: 框架给定，目标明确
- AI能力: 极强
- 人类价值: 低

**结构问题（Why）**
- "为什么采用这个架构？"
- "如何平衡这些目标？"
- 特征: 涉及权衡，需要理解
- AI能力: 中强
- 人类价值: 中

**方向问题（Should）**
- "这是正确的问题吗？"
- "我们应该追求什么？"
- 特征: 质疑框架，定义价值
- AI能力: 弱
- 人类价值: 极高 ⭐

**真正稀缺的是第三类。**

---

### 2️⃣ 练习"问题上移"

每次问：这个问题的上层问题是什么？

**例如**:

"产品增长慢"
↓
上层可能是：
"产品定位错误"
↓
再上层：
"目标市场选错"

**问题上移练习**：
- 第一层：表面问题
- 第二层：结构问题
- 第三层：方向问题
- 第四层：元问题（"我们为什么要这样做？"）

---

### 3️⃣ 练习"问题压缩"

用一句话精确表达问题。

**如果说不清，说明没定义清楚。**

**问题压缩练习**：
1. 写下问题的完整描述（100字）
2. 压缩到50字
3. 压缩到20字
4. 压缩到1句话

**标准**: 一句话要包含：
- 现状
- 期望
- 差距
- 约束

## 如何评估自己是否在进步？

你会出现三个变化：

1. **更少急于给答案**
   - 不会看到问题就马上说"我知道怎么解决"

2. **更常追问边界和目标**
   - 会问"成功的标准是什么？"

3. **更容易发现别人定义问题错误**
   - 能看到别人接受的问题框架
   - 能质疑别人的假设

**如果没有这三点，说明还停留在表层。**

## 练习方法

### 方法1: 假设清单练习
面对任何问题，列出隐含假设：

**步骤**:
1. 写下问题描述
2. 列出所有显性假设
3. 挖掘隐性假设
4. 质疑每个假设
5. 如果假设错误会怎样？

**示例**:
问题: "如何提高团队代码质量？"

假设:
- 代码质量是重要的（质疑：什么更重要？）
- 当前质量低（质疑：证据是什么？）
- 可以提高（质疑：约束是什么？）
- 提高质量是好事（质疑：代价是什么？）

### 方法2: 问题重构练习
重新表述问题，改变框架：

**原问题**: "如何让用户更频繁使用APP？"
**重构1** (价值): "用户需要什么，APP还没提供？"
**重构2** (替代): "用户不使用APP的真正原因是什么？"
**重构3** (元问题): "我们真的需要用户频繁使用吗？"

### 方法3: 价值评估练习
对问题进行多维度价值评估：

**维度**:
1. 用户价值 (谁受益？)
2. 商业价值 (创造利润？)
3. 社会价值 (让世界更好？)
4. 长期价值 (可持续？)
5. 机会成本 (不解决会怎样？)

**打分**: 每个维度1-10分
**总分**: 评估问题优先级

### 方法4: 杠杆点识别练习
找出解决能带来系统性改变的问题：

**问题**: "公司内部沟通效率低"

**杠杆点识别**:
- Level 1: 优化工具 (IM软件升级) - 弱杠杆
- Level 2: 优化流程 (会议规范) - 中杠杆
- Level 3: 优化组织 (部门重组) - 强杠杆
- Level 4: 优化文化 (透明度机制) - 最强杠杆 ⭐

## AI问题选择框架

当AI生成大量问题时，如何选择？

### 框架1: 价值密度
- 这个问题解决了什么核心矛盾？
- 解决的边际收益高吗？
- 负面影响是什么？

### 框架2: 可解决性
- 我们有能力解决吗？
- 需要什么资源？
- 时间窗口多久？

### 框架3: 系统影响
- 解决这个问题会带来什么连锁反应？
- 会暴露新的问题吗？
- 能系统改善吗？

### 框架4: 元价值
- 这是正确的问题吗？
- 问题的前提对吗？
- 我们应该问别的问题吗？

## 核心洞察

1. **问题定义能力是方向能力**
   - 不是执行能力
   - 而是选择"应该做什么"的能力

2. **AI时代的价值转移**
   - 从"解决问题"到"选择问题"
   - 从"执行者"到"判断者"

3. **问题定义的四个要素必须清晰**
   - 真正问题
   - 目标函数
   - 约束条件
   - 成功标准

4. **大脑的四个天然倾向需要对抗**
   - 关注表面症状 → 深入根因
   - 急于给解决方案 → 先定义问题
   - 忽略隐含假设 → 质疑前提
   - 混淆目标和手段 → 明确目标

5. **三个关键升级点**
   - 区分三类问题（执行、结构、方向）
   - 练习问题上移
   - 练习问题压缩

3. **价值不在解决的数量，而在解决的质量**
4. **最危险的是接受问题框架而不质疑**
