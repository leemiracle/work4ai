# Neo-OS · 执行路线（ROADMAP）

> 版本 v2.0。从 Phase 0 到 Phase 4，含里程碑、生死指标、降级方案。

---

## 核心纪律（刻在墙上）

> **"深度上专精，方法上通用。框架是提取出来的，不是设计出来的。"**
>
> **永远从 N=2 提取，不从 N=1 泛化——这是反 Hurd 的铁律。**

---

## Phase 0 · 立项与命门验证（4-6 周）

### 目标
验证两个命门假设；若失败，启动降级。

### 任务
| 周 | 任务 | 产出 |
|----|------|------|
| W1 | 锁定 7 个地基决策（本体/形式化语言/基座/kernel/场景/开源/验证实验）| DECISIONS.md |
| W2 | 形式化语言选型（Lean4 vs Isabelle 深度对比）+ 形式化粒度种子 | 形式化 PoC |
| W3 | 基座模型选型 + 数据管线搭建 | 数据 pipeline |
| **W4** | **1000 commit 抽取率实验（命门 V25）** | **生死指标** |
| W5-6 | ≥1 条合格规则产出 + 用户访谈 + 性能微基准 | 可行性报告 |

### 生死指标（W4 必须全绿）
1. 1000 commit 人工抽检，可蒸馏规则率 ≥10%
2. LLM 三元组提取 precision ≥0.7
3. 产出 ≥1 条满足四条件的规则（非平凡 + 蒸馏 + 可形式化 + 有用）
4. ≥3 位真实工程师确认"这个解释对我有具体价值"
5. 原型解释开销 <15%

### 情景分支
- **全绿** → 乐观情景，全力推进 Phase 1
- **黄（1-2 项红）** → 现实情景，调整后推进
- **红（≥3 项红）** → **启动降级讨论**

### 降级方案
| 崩塌假设 | 降级为 | 仍有的价值 |
|---------|--------|-----------|
| 形式化不可行 | LLM 代码考古工具 | 放弃 soundness，仍新颖 |
| OS 集成不可行 | Linux 可观测插件 | 不替换只增强 |
| world model 不可行 | commit 智能产品 | 数据资产仍在 |
| 全失败 | "为什么不行"负面结果论文 | 学术价值真实 |

## Phase 1 · OS Prototype（2-3 月）

### 目标
在 Linux + eBPF 上做出 trace→英文解释的最小可用 prototype。**不写 kernel 代码**。

### 任务
1. **L1 Event Ontology**：eBPF 采集 + IR 规则引擎 → JSONL 事件流
2. **L2 World Model v0**：Qwen2.5-Coder-7B + QLoRA 微调（Tier 1 syzkaller 数据起步）
3. **L2.5 软规则层**：暂不做形式化，只用 LLM + 规则过滤
4. **L3 English Interface**：三层讲解 + 费曼门的最小实现
5. **主场景**：内核 panic 解释 + 教学场景（容许不完美 soundness）

### 里程碑
- M1.1：eBPF → 统一事件流跑通
- M1.2：world model 在 100 个 held-out bug 上解释准确率 ≥40%
- M1.3：教学试点（清华 OS 课）——学生用 Neo-OS 学 page fault

### 产出
- 开源 prototype（Apache 2.0）
- Paper #1 草稿：Linux commit 蒸馏方法 + 数据集

## Phase 2 · 第二靶子（浏览器）验证内核领域不变性（2-3 月）

### 目标
**用浏览器暴力验证内核是否真的领域无关**。这是项目存亡判据。

### 为什么是浏览器
- DevTools Protocol 极成熟（trace_source 现成）
- HTML/CSS/WASM spec 形式化强（formal_anchors 现成）
- 与 OS 抽象距离足够大（事件驱动 vs syscall 驱动）——能真正验证五原子是否领域不变
- 受众最广（每个 web 开发者都是用户）

### 任务
1. 写浏览器 adapter（CDP + trace_event + V8 inspector → Event 流）
2. 内核**零代码改动**跑通浏览器解释
3. 主场景："网页为何卡顿/为何白屏"（命中 INP/LCP）

### 决策点
- **内核零改动跑通** → 五原子抽象成立，"通用"开始挣来
- **需要改内核** → 抽象泄漏，回 Phase 1 修正五原子定义

### 备选第二靶子（若浏览器太大）
**数据库查询规划器**：scope 小 / EXPLAIN ANALYZE 干净 trace / 关系代数形式化强 / "为何选这个计划"完美适配题。

## Phase 3 · 领域扩展（严格串行，反 Hurd 纪律）（6-12 月/域）

> ⚠️ **核心纪律（council C4 修正）**：Phase 3 不再是"6 域排序并行推进"，
> 而是 **一次一域，深透且 adapter <20% 才开下一个**。"通用"是挣来的结论，
> 不是起点的口号。每个域必须独立通过下述 gate，才允许启动下一个域。

### 目标
**串行**扩展靶子。每域深透（专家级 + adapter 薄 + 形式化非平凡），从 N=2 提取通用框架。**N=1 不泛化**（反 Hurd 铁律）。

### Gate（每域启动下一个域前必须全绿）

| # | gate 条件 | 度量 | 不满足则 |
|---|----------|------|---------|
| G1 | adapter 厚度 | <20% 代码（vs 内核）| 回炉抽象，五原子重新定义 |
| G2 | 五原子零修改 | Event/State/Causality/Invariant/DecisionPoint 定义无领域概念泄露 | 修正五原子 |
| G3 | 形式化非平凡 | ≥1 条真实规则通过 Lean4 kernel（超过 omega，sorry 清零）| 补形式化 |
| G4 | 因果蒸馏验证 | commit 抽取率 ≥40% + precision ≥0.7 | 调整蒸馏 |
| G5 | 用户价值实证 | ≥3 位真实工程师确认具体价值 | 回价值命题 |

**任一 gate 不过 → 不启动下一域，当前域继续打磨。** 这是反 Hurd 的硬纪律，防止"理性排序仍全部同时推进"（council 历史学家交锋）。

### 候选域排序（仅供参考；gate 优先于顺序）

候选按"形式化成熟度 + 因果追踪基础 + 历史语料密度"四轴绿灯数排序。**但实际推进严格串行**：第一域（见 [FIRST_DOMAIN_DECISION.md](../01-decisions/FIRST_DOMAIN_DECISION.md)）完成且全 gate 绿，才启动第二域。

1. **分布式共识**（Raft，四轴全绿）：TLA+ + OTel + Jepsen 21 issue 黄金语料 + Lean4 空白可补
2. **数据库查询规划器**（PostgreSQL，形式化最强）：关系代数等价律 + EXPLAIN ANALYZE + pgsql-hackers 语料
3. **编译器**（LLVM，多层语义理想）：IR 天然存在 + Alive2/CompCert
4. **网络协议栈**：RFC 锚点 + eBPF + BBR 状态机
5. **游戏引擎**（Bevy 优先）：frame = 事件包 + ECS 契合
6. **GPU/图形学**（最难端）：Vulkan spec + Mesa + SPIR-V

> 🔒 候选 3-6（council 说的 D5-D11 子集）**锁进抽屉**，直到 2 域证明 adapter <20%、五原子零修改、形式化非平凡。在 2 域验证前，候选 3+ 不启动。

### 形式化补全（串行内嵌，不延后）
每域的形式化与领域 adapter 同步推进：
- 从 Phase 1 的软规则层，逐步引入 Lean4 形式化（属性级，Cedar 范式）
- 神经符号闭环：LLM 归纳规则 → Lean4 验证 → expert iteration 回灌
- 并发正确性深度需求时，引入 Iris/Rocq（参见 ROUND3 R3-5）

### 产出（每域独立交付）
- 该域 adapter（<20% 代码）
- ≥1 条非平凡 Lean4 规则（C2 spinlock+preempt 范式）
- commit 蒸馏数据集 + 抽取 pipeline
- Paper（按域推进）：#2 神经符号架构（NeurIPS/NeSy/POPL）/ #3 CTC 度量（CHI/CSCW）

### 死法防线（本 Phase 特别执行）
- **历史学家警告**：理性排序仍会全部同时推进 → 严格串行 + gate 是唯一防线
- **Hurd 病**：N=1 就声称通用 → N=2 才允许提取框架

## Phase 4 · 提取通用框架 + 决策自研 kernel（12+ 月）

### 目标
**从 2+ 实例提取"通用可解释性框架"**。决定是否自研 microkernel。

### 框架提取判据
- ≥2 个零共享表面的领域都用同一内核零改动跑通
- adapter 始终薄（<20%）
- 五原子定义稳定（无领域概念泄露）

### 自研 kernel 决策
- 若 Linux + eBPF 能撑住 → 不自研
- 若事件本体被 Linux 阻塞 → 考虑 seL4 或自研 microkernel

### 终极形态
一个**领域不变的解释内核** + 一套**可复用的接入方法论**。使命按域可测，方法跨域可迁。

## 死法防线（来自红队 E08）

| 死法 | 概率 | 防线 |
|------|------|------|
| #1 概念核心不可证伪（粒度不存在）| ~40% | Phase 0 W4 必测，红线即转 |
| #2 孤儿综合征（无生态用户）| ~30% | 教学场景先行获用户；开源 + 学术双轨 |
| #3 蒸馏噪声（stochastic parrot）| ~25% | Tier 1 数据起步 + 形式化过滤 + 强制 citation |
| #4 抽象优先（Hurd 病）| — | **永远 N=2 提取，N=1 不泛化** |
| #5 采集器重造 | — | adapter 只读现有工具，不自造 tracer |
| #6 单域深度不足 | — | 每域必须达到专家级才声明 |

## 时间线情景

### 🟢 乐观（形式化顺利，蒸馏质量高）
- 6 月：Paper #1 + prototype v0
- 12 月：神经符号验证 + Paper #2
- 24 月：浏览器验证内核不变性 + 教学试点 + Paper #3
- 36 月：多领域 + 行业影响

### 🟡 现实（形式化部分成功）
- 6 月：commit 蒸馏 prototype + 软规则层
- 12 月：英文解释 MVP（无形式化保证）
- 24 月：形式化覆盖 30% 关键规则 + Paper
- 36 月：开源社区 + 教学模块

### 🔴 悲观（形式化失败，蒸馏质量低）
- 6 月：发现 commit 蒸馏质量不足
- 12 月：转在线 LLM 解释（放弃蒸馏）
- 24 月：沦为"另一个 AIOps"，失去独特性
- **Phase 0 W4 提前识别，启动降级**
