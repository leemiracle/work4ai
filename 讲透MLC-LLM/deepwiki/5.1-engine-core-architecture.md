## Purpose and Scope

 This page describes the internal implementation of the C++ serving engine core: `EngineImpl`, `ModelImpl`, `FunctionTable`, and the `RequestState`/`RequestStateEntry`/`RequestModelState` hierarchy. It also covers how `EngineConfig` and `GenerationConfig` are parsed and used to configure the engine.

 For information on the action-based request processing steps (prefill, decode, verify), see [Engine Actions and Request Processing](https://deepwiki.com/mlc-ai/mlc-llm/5.2-engine-actions-and-request-processing). For the Python wrappers that sit above this C++ layer, see [Engine Classes](https://deepwiki.com/mlc-ai/mlc-llm/6.1-engine-classes). For multi-GPU tensor and pipeline parallelism, see [Multi-GPU and Distributed Execution](https://deepwiki.com/mlc-ai/mlc-llm/5.5-multi-gpu-and-distributed-execution). For the prefix cache and engine state data structures, see [Engine State and Prefix Cache](https://deepwiki.com/mlc-ai/mlc-llm/5.4-engine-state-and-prefix-cache).

## EngineImpl

 `EngineImpl` is defined in [cpp/serve/engine.cc343-765](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine.cc#L343-L765) and implements the abstract `Engine` interface. It is the central coordinator for all inference work: model loading, request intake, batched execution, and result streaming.

 
### Fields

 
| Field | Type | Purpose |
|---|---|---|

| estate_ | EngineState | All runtime queues, request states, prefix cache, metrics |
| actions_ | Array<EngineAction> | Ordered action list (prefill → decode → verify, etc.) |

### Request Management

 **`AddRequest`** [cpp/serve/engine.cc664-724](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine.cc#L664-L724):

 
 - Routes special requests (e.g., `kQueryEngineMetrics`) directly via `HandleSpecialRequests`.
 - Calls `Request::FromUntokenized(request, tokenizer_)` to convert any `TextData` inputs to `TokenData`.
 - Rejects requests where `prompt_tokens >= engine_config_->max_single_sequence_length` by streaming back a `"length"` finish reason via `StreamBackErrorImpl` [cpp/serve/engine.cc86-102](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine.cc#L86-L102)
 - Appends the request to `estate_->waiting_queue`.
 - Creates a `RequestState` with entries: 
 - `n == 1`: one entry, with `parent_idx == -1`.
 - `n > 1`: `entries[0]` is the root (shared prefix), `entries[1..n]` are children with `parent_idx == 0`.
 - Stores the `RequestState` in `estate_->request_states[request->id]`.
 
 **`AbortRequest`** [cpp/serve/engine.cc103-146](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine.cc#L103-L146) (`AbortRequestImpl`):

 
 - Finds the request in `running_queue` or `waiting_queue`.
 - If running: calls `PrefixCache::RecycleSequence` or `RemoveRequestFromModel` to free KV pages, then `id_manager.RecycleId`.
 - Streams back an abort message via `estate_->request_stream_callback_`.
 
 
### Step Loop

 **`EngineImpl::Step`** [cpp/serve/engine.cc745-765](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine.cc#L745-L765): The engine iterates through `actions_` in priority order. The first action that processes any request terminates the step. If an action returns non-empty `processed_requests`, the engine invokes `ActionStepPostProcess` [cpp/serve/engine.cc754-758](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine.cc#L754-L758)

 `ActionStepPostProcess` drives token detokenization and stop-condition evaluation by calling `GetDeltaRequestReturn` [cpp/serve/request_state.cc173-261](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/request_state.cc#L173-L261) for each processed request entry.

## Model and ModelImpl

 `ModelObj` (abstract base) is declared in [cpp/serve/model.h92-400](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/model.h#L92-L400) and `ModelImpl` implements it in [cpp/serve/model.cc58-674](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/model.cc#L58-L674) Each `Model` wraps a single compiled model library and its associated KV cache.

 The `ModelImpl` constructor [cpp/serve/model.cc60-81](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/model.cc#L60-L81) runs:

 
 - Parse model config JSON (`LoadModelConfigJSON`).
 - Initialize `FunctionTable` (`ft_.Init`), which loads the compiled library and binds all packed functions.
 - Reset internal state and set `kind` from `ModelMetadata.kv_state_kind` [cpp/serve/model.cc80](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/model.cc#L80-L80)

### `ModelWorkspace`

 `ModelWorkspace` [cpp/serve/model.h39-66](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/model.h#L39-L66) holds pre-allocated tensors shared across engine action calls:

 
 - `embeddings`: Concatenated input embeddings.
 - `hidden_states`: Hidden states for the current batch.
 - `draft_probs`: Draft token probabilities for speculative decoding.
 - `draft_hidden_states_storage`: Storage for hidden states of draft tokens (Eagle).

## Request State Hierarchy

 The engine tracks each in-flight request through a three-level data structure. This design supports parallel generations and multi-model speculative serving.

 **RequestState / RequestStateEntry / RequestModelState Class Hierarchy**

 
```

```

 
### `RequestModelState`

 Tracks a single request's state within a single model [cpp/serve/request_state.h36-135](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/request_state.h#L36-L135)

 
 - `internal_id`: Physical sequence ID in the KV cache.
 - `committed_tokens`: Finalized `SampleResult` entries [cpp/serve/request_state.h53](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/request_state.h#L53-L53)
 - `grammar_matcher`: Active `xgrammar::GrammarMatcher` for constrained generation [cpp/serve/request_state.h91](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/request_state.h#L91-L91)
 
 `CommitToken` [cpp/serve/request_state.cc56-68](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/request_state.cc#L56-L68) appends to `committed_tokens`, updates `appeared_token_ids`, and advances the grammar state.

 
### `RequestStateEntry`

 Each entry represents one generation branch [cpp/serve/request_state.h196-273](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/request_state.h#L196-L273) It manages the `StopStrHandler` and RNG for sampling. For `n > 1` parallel generations, entries are organized as a tree where `entries[0]` is the root shared prefix.

### `GenerationConfig`

 `GenerationConfigNode` [cpp/serve/config.h117-147](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/config.h#L117-L147) controls per-request sampling behavior. It includes `temperature`, `top_p`, `logit_bias`, and `max_tokens`. `GenerationConfig::FromJSON` [cpp/serve/config.cc269-362](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/config.cc#L269-L362) merges user overrides with model defaults.
