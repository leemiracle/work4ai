  This glossary provides definitions for codebase-specific terminology, jargon, and domain concepts used throughout the MLC LLM project. It covers the end-to-end lifecycle from model compilation to multi-platform deployment and serving.

 
## Core Concepts

 
### MLCEngine

 The unified high-performance LLM inference engine that serves as the backbone for all MLC LLM deployment targets (Python, C++, iOS, Android, Web) [README.md63-64](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/README.md?plain=1#L63-L64) It provides an OpenAI-compatible API and manages the request lifecycle, token sampling, and KV cache orchestration [cpp/serve/engine.cc63-64](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine.cc#L63-L64)

 
### TVM Unity

 The compilation backend for MLC LLM. It uses the **Relax** (Recursive Lambda Abstractions) IR for graph-level optimizations and **TensorIR** (TIR) for low-level kernel code generation [README.md91-95](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/README.md?plain=1#L91-L95)

 
### Disco

 The distributed runtime component in TVM/MLC LLM used for multi-GPU execution. It manages worker processes/threads and provides collective communication primitives (e.g., `allreduce`) for Tensor Parallelism [cpp/serve/function_table.cc73-82](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/function_table.cc#L73-L82)

## Runtime & Serving Domain

 
### Engine Actions

 The `Engine` processes requests through a set of discrete `EngineAction` objects. Each action represents a specific step in the LLM inference pipeline.

 
 - **Prefill**: Processes input tokens to populate the KV cache and generate the first token.
 - **Decode**: Processes a single token for a batch of running requests.
 - **Verify**: In speculative decoding, validates draft tokens against the base model.
 
 
### KV Cache Management

 MLC LLM uses a **Paged KV Cache** system to manage GPU memory efficiently.

 
 - **PagedKVCache**: The abstraction for storing Key-Value tensors in non-contiguous memory blocks.
 - **Prefix Cache**: A mechanism (often a Radix Tree) to reuse KV cache blocks for common prefixes (e.g., system prompts) [cpp/serve/radix_tree.cc1-20](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/radix_tree.cc#L1-L20)
 
 
### Sampling

 The process of selecting the next token from the output probability distribution.

 
 - **LogitProcessor**: Applies penalties (repetition, presence), biases, and softmax to raw logits [cpp/serve/logit_processor.h1-20](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/logit_processor.h#L1-L20)
 - **GPUSampler**: Performs top-p and top-k sampling directly on the GPU to minimize host-device synchronization [cpp/serve/sampler/sampler.h1-30](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/sampler/sampler.h#L1-L30)

## Deployment & Platform Jargon

 
| Term | Context | Definition | Code Pointer |
|---|---|---|---|
| FFI (Foreign Function Interface) | Runtime | The mechanism used to call C++ engine functions from Python, Swift, or Java. | cpp/serve/engine.cc27-30 |
| DRef | Distributed | A "Distributed Reference" in Disco, pointing to a tensor or object residing on remote GPU workers. | cpp/serve/function_table.cc53-65 |
| System Lib | Mobile/Web | A way to bundle the model library into the application binary rather than loading a dynamic .so file. | cpp/serve/function_table.cc106-114 |
| Microserving | Serving | A disaggregated serving mode where prefill and decode steps are split across different engine instances. | python/mlc_llm/router/router.py1-30 |
| JIT (Just-In-Time) | Python | Automatic compilation of the model library at runtime if a pre-compiled library is not provided. | docs/compilation/compile_models.rst20-21 |
