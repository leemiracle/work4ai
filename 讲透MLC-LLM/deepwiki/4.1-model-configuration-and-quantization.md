  This page explains how models are configured and quantized in MLC-LLM. The configuration system manages model architectures through the `MODELS` registry, quantization methods through the `QUANTIZATION` registry, conversation templates, and the `gen_config` process that generates `mlc-chat-config.json`. These components work together to prepare pre-trained models for optimized inference across different hardware targets.

 
## Overview of Configuration and Quantization

 MLC-LLM uses a centralized system to configure models and apply quantization. The `gen_config` function orchestrates this process, reading model configurations, applying `ModelConfigOverride` overrides, selecting quantization methods from the `QUANTIZATION` registry, and generating the final `mlc-chat-config.json`.

## Model Registry (MODELS)

 The `MODELS` dictionary in [python/mlc_llm/model/model.py133-720](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/model/model.py#L133-L720) is the central registry of supported model architectures. Each entry maps a string key to a `Model` dataclass instance.

 
### Model and ModelConfig types

 `ModelConfig` is defined as a type alias (`Any`) in [python/mlc_llm/model/model.py53-59](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/model/model.py#L53-L59) with a documentation contract: any concrete config class must provide a `from_file(path: Path) -> ModelConfig` classmethod. The same file defines two function type aliases:

 
 - `FuncGetExternMap = Callable[[ModelConfig, Quantization], ExternMapping]` — maps model parameters from an external format [python/mlc_llm/model/model.py61](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/model/model.py#L61-L61)
 - `FuncQuantization = Callable[[ModelConfig, Quantization], Tuple[nn.Module, QuantizeMapping]]` — returns a quantized model and weight mapping [python/mlc_llm/model/model.py62](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/model/model.py#L62-L62)

### Quantization Method Types

 
| Class | kind value | Description | Registry keys |
|---|---|---|---|
| NoQuantize | "no-quant" | Full-precision (fp16/bf16/fp32) python/mlc_llm/quantization/no_quantization.py | q0f16, q0bf16 |
| GroupQuantize | "group-quant" | Int3/Int4 with per-group scales python/mlc_llm/quantization/group_quantization.py32 | q4f16_1, q3f16_0 |
| PerTensorQuantize | "per-tensor-quant" | Float8 per-tensor quantization python/mlc_llm/quantization/per_tensor_quantization.py34 | e4m3_e4m3_f16 |
| BlockScaleQuantize | "block-scale-quant" | Float8 with block-wise scaling python/mlc_llm/quantization/block_scale_quantization.py27 | fp8_e4m3fn_bf16_block_scale |

 
### BlockScaleQuantize

 `BlockScaleQuantize` handles FP8 quantization with per-block scaling. It is defined in [python/mlc_llm/quantization/block_scale_quantization.py22-46](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/quantization/block_scale_quantization.py#L22-L46) with these key fields:

 
| Parameter | Description | Values |
|---|---|---|
| weight_dtype | FP8 storage format | "float8_e4m3fn" or "float8_e5m2" |
| model_dtype | Computation dtype | "bfloat16" or "float16" |
| use_activation_scale | Enable pre-computed static activation scales | False / True |

 The `quantize_model()` method walks the `nn.Module` tree via `_Mutator(nn.Mutator)`, replacing `nn.Linear` nodes with `BlockScaleQuantizeLinear` (dynamic activations) or `BlockScaleQuantizeLinearStaticActivation` (static activations) [python/mlc_llm/quantization/block_scale_quantization.py74-178](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/quantization/block_scale_quantization.py#L74-L178)
