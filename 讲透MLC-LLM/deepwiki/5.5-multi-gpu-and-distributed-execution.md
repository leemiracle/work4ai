  This page covers how MLC LLM distributes inference across multiple GPUs using TVM's Disco framework. It explains the session creation logic, the `FunctionTable` initialization paths, weight loading, and how model forward passes operate in a distributed setting. For details on the engine request lifecycle that calls into this layer, see [Engine Core Architecture](https://deepwiki.com/mlc-ai/mlc-llm/5.1-engine-core-architecture). For compilation flags that bake parallelism settings into model artifacts, see [Compiler Pass Pipeline](https://deepwiki.com/mlc-ai/mlc-llm/4.2-compiler-pass-pipeline).

## Overview

 MLC LLM supports two orthogonal parallelism strategies:

 
| Strategy | Config Field | Description |
|---|---|---|
| Tensor Parallelism | tensor_parallel_shards | Each layer's weight matrices are split across N GPUs. All N GPUs participate in every forward pass step. |
| Pipeline Parallelism | pipeline_parallel_stages | The model's transformer layers are partitioned into S groups. Each group runs on a separate set of GPUs. |

 Both values are determined **at compile time** and are embedded in the compiled model's metadata. At runtime, the engine reads these values and allocates `num_workers = tensor_parallel_shards × pipeline_parallel_stages`.

 When `num_workers > 1`, the engine creates a TVM **Disco session**, which manages inter-process communication between workers. When `num_workers == 1`, inference runs locally with no IPC overhead.

## Session Creation

 `EngineImpl::CreateDiscoSession` performs these steps:

 
 - **Read metadata** from each model library by loading the VM executable and calling `ModelMetadata::FromModule`. This yields `tensor_parallel_shards` and `pipeline_parallel_stages` per model.
 - **Validate consistency**: all models must share the same `tensor_parallel_shards` value. Pipeline stages may differ, and the maximum is used for session sizing.
 - **Compute `num_workers`**: `num_workers = num_shards × max_num_stages`.
 - **Select CCL backend**: 
 - `kDLCUDA` → `"nccl"`
 - `kDLROCM` → `"rccl"`
 - Other devices → fatal error.
 - **Assign device IDs**: Workers are assigned IDs `[device.device_id, device.device_id + num_workers - 1]`.
 - **Create the session**: 
 - If pipeline parallelism is enabled and `MLC_SOCKET_HOST` / `MLC_SOCKET_PORT` are set, a `SocketSession` is created for cross-node communication.
 - Otherwise, a `ProcessSession` is created via `runtime.disco.create_process_pool`.

## FunctionTable Initialization

 `FunctionTable::Init` in [cpp/serve/function_table.cc67-153](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/function_table.cc#L67-L153) branches based on `num_workers`:

 
### Disco Path (`num_workers > 1`)

 
 - Sets `use_disco = true`.
 - Loads the compiled model into all workers: `sess->CallPacked(sess->GetGlobalFunc("runtime.disco.load_vm_module"), reload_lib_path, ...)` → stored in `disco_mod`.
 - `mod_get_func`: wraps every model function lookup as a call through the Disco session using `SessionFuncAsPackedFunc`.
 - `get_global_func`: wraps TVM global function calls through the session.
 - **CPU binding**: If env var `MLC_DISCO_WORKER_CPU_BINDING` is set (comma-separated CPU IDs), calls `runtime.disco.bind_worker_to_cpu_core` via `GetDiscoWorkerCPUBinding` [cpp/serve/function_table.cc28-51](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/function_table.cc#L28-L51)
 - **Pipeline logit gathering**: When `num_stages > 1`, `last_group_send_to_worker_0_` is bound to `mlc.multi_gpu.SendFromLastGroupToWorker0`.
 
 
### Local Path (`num_workers == 1`)

 
 - Sets `use_disco = false`.
 - Loads the compiled model as a plain TVM module via `Module::LoadFromFile`.
 - `mod_get_func`: calls `local_vm->GetFunction(name, true)`.
 - `get_global_func`: calls `Function::GetGlobalRequired(name)`.
 
 **FunctionTable key fields:**

 
| Field | Type | Purpose |
|---|---|---|
| use_disco | bool | Selects Disco vs local execution path throughout model.cc |
| sess | Session | The active Disco session |
| disco_mod | Optional<DRef> | Handle to the loaded module on all workers |
| local_vm | Optional<Module> | Local VM module (single GPU) |
| last_group_send_to_worker_0_ | Function | Sends logits from final pipeline stage to worker 0 |

## Weight Loading

 `FunctionTable::LoadParams` in [cpp/serve/function_table.cc155-205](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/function_table.cc#L155-L205) uses different paths:

 
### Disco Weight Loading

 
 - Checks env var `MLC_INTERNAL_PRESHARD_NUM`: 
 - Not set → calls `mlc.multi_gpu.LoadMultiGPU`.
 - Set → calls `mlc.multi_gpu.LoadMultiGPUPresharded`.
 - Both functions are implemented in `cpp/multi_gpu/multi_gpu_loader.cc`.
 
 
### Local Weight Loading

 
 - Calls `vm.builtin.tensor_cache.load` to load all weights into the tensor cache.
 - Retrieves params by name using `vm.builtin.param_array_from_cache_by_name`.
 
 
### How `LoadMultiGPU` Works

 In [cpp/multi_gpu/multi_gpu_loader.cc108-150](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/multi_gpu/multi_gpu_loader.cc#L108-L150) `BroadcastOrShardAndScatter` is the core distribution primitive:

 
 - If a parameter has no `preprocs` (sharding preprocessing), it is **broadcast** from worker 0 to all workers via `BroadcastFromWorker0`.
 - If a parameter has `preprocs` defined, worker 0 loads it, applies the `PreprocessorPool` (which transforms the weight matrix into N shards), then **scatters** each shard to its corresponding worker via `ScatterFromWorker0`.

## Model Forward Passes with Disco

 Every model computation method in `ModelImpl` (in `cpp/serve/model.cc`) has a conditional branch on `ft_.use_disco`.

 **Input distribution:**

 
 - `FunctionTable::CopyToWorker0` in [cpp/serve/function_table.cc305-344](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/function_table.cc#L305-L344) handles copying CPU tensors (e.g., token IDs) to all workers. In Disco mode, it calls `sess->CopyToWorker0(host_array, buffer_view)`, which distributes the data to worker 0 and the framework replicates as needed.
 
 **Result collection:**

 
 - After a forward pass, `Downcast<DRef>(ret)->DebugGetFromRemote(0)` fetches the result from worker 0's memory to the host [cpp/serve/model.cc176](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/model.cc#L176-L176)
 - For pipeline parallelism, `ft_.last_group_send_to_worker_0_` (bound to `mlc.multi_gpu.SendFromLastGroupToWorker0`) is called to transfer the logit tensor from the last worker group to worker 0 before host retrieval [cpp/serve/model.cc283-286](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/model.cc#L283-L286)

## Pipeline Parallelism Groups

 `DispatchFunctionByGroup` in [cpp/multi_gpu/builtin.cc28-60](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/multi_gpu/builtin.cc#L28-L60) implements per-stage function dispatch.

 
 - Workers are divided into groups based on `world_size / group_size`.
 - Each group executes a different function (subset of layers).
 - `DispatchFunctionByGroup` identifies the calling worker's `group_id` and executes the corresponding function.
 
 `SendFromLastGroupToWorker0` transfers the output of the last pipeline stage (logits) back to worker 0 for sampling. It is bound in [cpp/serve/function_table.cc284-286](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/function_table.cc#L284-L286)
