  This page documents the Python serving engine classes in MLC LLM: `MLCEngineBase`, `AsyncMLCEngine`, `MLCEngine`, `JSONFFIEngine`, and `SyncMLCEngine`. These classes form the Python interface layer that wraps the C++ threaded engine and expose OpenAI-compatible API surfaces.

 
---

 
## Class Overview

 The Python serving layer has two parallel families of engine classes:

 
 - **`MLCEngineBase` family** — wraps a threaded C++ engine with a dual-thread background loop; exposes full OpenAI API with both streaming and non-streaming support.
 - **`JSONFFIEngine`** — a simpler engine that serializes all requests as JSON through a C FFI boundary; streaming-only; used on mobile and for lightweight use cases.

 `MLCEngineBase` loads packed functions from the C++ `mlc.serve.create_threaded_engine` module. These functions include `add_request`, `abort_request`, `run_background_loop`, `run_background_stream_back_loop`, `reload`, and `init_threaded_engine`.

### Background Threads

 Two `threading.Thread` objects are started at construction:

 
 - `_background_loop_thread` — runs `_ffi["run_background_loop"]`, the main C++ engine step loop.
 - `_background_stream_back_loop_thread` — runs `_ffi["run_background_stream_back_loop"]`, which dispatches generated token callbacks back to Python.
 
 Sources: [python/mlc_llm/serve/engine_base.py631-669](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/serve/engine_base.py#L631-L669)

## EngineState

 `EngineState` in [python/mlc_llm/serve/engine_base.py385-548](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/serve/engine_base.py#L385-L548) bridges the C++ callback thread to Python consumers.

 **For `AsyncMLCEngine`:** It uses `call_soon_threadsafe` to schedule stream pushes into the asyncio event loop via `_async_request_stream_callback` [python/mlc_llm/serve/engine_base.py469-482](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/serve/engine_base.py#L469-L482)
