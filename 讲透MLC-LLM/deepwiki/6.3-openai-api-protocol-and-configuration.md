  This page documents the data structures that make up MLC LLM's OpenAI-compatible API surface: the request and response protocol types, the function calling types, and the two configuration objects (`EngineConfig` and `GenerationConfig`) that control how requests are executed.

 This page focuses on the *schema* of these objects. For how the REST server exposes them as HTTP endpoints, see [REST API Server](https://deepwiki.com/mlc-ai/mlc-llm/6.2-rest-api-server). For the engine classes that consume them at runtime, see [Engine Classes](https://deepwiki.com/mlc-ai/mlc-llm/6.1-engine-classes). For C++ engine internals, see [Engine Core Architecture](https://deepwiki.com/mlc-ai/mlc-llm/5.1-engine-core-architecture).

## Protocol Layer Overview

 The protocol layer lives in multiple places that must stay in sync to support cross-platform deployment:

 
 - **Python:** [python/mlc_llm/protocol/openai_api_protocol.py](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/protocol/openai_api_protocol.py) — Pydantic `BaseModel` classes used by the FastAPI server and the Python engine wrappers.
 - **C++:** [cpp/json_ffi/openai_api_protocol.h](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/json_ffi/openai_api_protocol.h) and [cpp/json_ffi/openai_api_protocol.cc](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/json_ffi/openai_api_protocol.cc) — Plain C++ structs with `FromJSON`/`AsJSON` helpers used by the JSON FFI engine.
 - **Swift:** [ios/MLCSwift/Sources/Swift/OpenAIProtocol.swift](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/ios/MLCSwift/Sources/Swift/OpenAIProtocol.swift) — `Codable` structs used by the iOS SDK.
 
 All implementations follow the same wire format so that a JSON request accepted by the Python server can also be consumed by the C++ engine directly.

## Engine Configuration

 
### `EngineConfig`

 `EngineConfig` controls the runtime behavior of the LLM engine, including memory allocation and speculative decoding modes.

 
| Field | Source/File | Notes |
|---|---|---|
| max_num_sequence | python/mlc_llm/serve/config.py19 | Max concurrent requests |
| gpu_memory_utilization | python/mlc_llm/serve/config.py23 | Fraction of VRAM for KV cache |
| prefix_cache_mode | python/mlc_llm/serve/config.py26 | Enable/disable Radix tree caching |
| prefix_cache_max_num_recycling_seqs | python/mlc_llm/serve/config.py27 | Max sequences kept in cache |
| prefill_chunk_size | python/mlc_llm/serve/config.py21 | Max tokens per prefill step |

 `GenerationConfig` is derived per-request to control sampling.

| stop_strs | python/mlc_llm/serve/engine_utils.py52 | Sequences that trigger early stop |

## Embedding Protocol

 The `/v1/embeddings` endpoint supports both encoder-only (BERT) and decoder-only (Qwen) models via the `AsyncEmbeddingEngine`.

 
| Feature | Implementation | Notes |
|---|---|---|
| Pooling | pooling_strategy | "cls", "mean", or "last" python/mlc_llm/serve/embedding_engine.py49 |
| Normalization | self.normalize | Enforces unit length per contract python/mlc_llm/serve/embedding_engine.py68 |
| Encoding | encoding_format | Supports "float" or "base64" python/mlc_llm/protocol/openai_api_protocol.py81 |

 The `EmbeddingResponse` contains `EmbeddingObject` entries, each holding the vector for a specific input index [python/mlc_llm/protocol/openai_api_protocol.py98-118](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/protocol/openai_api_protocol.py#L98-L118)
