  This document describes the `_mlc_llm_pipeline` compilation pass sequence that transforms a high-level model representation into optimized machine code for various hardware targets. The pipeline is the core of MLC LLM's compilation system, orchestrating TVM Unity passes across six distinct phases.

 
## Overview and Purpose

 The compiler pass pipeline is implemented as a TVM module pass registered with the name `"mlc_llm"`. It accepts a TVM Relax IRModule containing the model's computational graph and applies a carefully sequenced series of transformation passes to produce optimized code. The pipeline is structured into several phases:

 
 - **Phase 0**: Metadata attachment and model-specific preparation (KV cache, sampling, bounds).
 - **Phase 1**: High-level graph optimizations on Relax operators (fusion, dispatch).
 - **Phase 2**: Lowering from Relax to TVM TIR (Tensor Intermediate Representation).
 - **Phase 3**: TIR-level kernel optimizations (quantization fusion).
 - **Phase 4**: Dlight auto-scheduling for hardware-specific optimization.
 - **Phase 5**: VM bytecode generation and finalization.
 
 **Sources:** [python/mlc_llm/compiler_pass/pipeline.py1-210](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/pipeline.py#L1-L210)

 
## Core Data Structures

 The compilation process is driven by two primary dataclasses that encapsulate the configuration and state of the pipeline.

 
### CompileArgs

 The `CompileArgs` dataclass contains the high-level arguments provided to the compiler, including the model definition, target device, and optimization flags. It is initialized in the `compile` entrypoint.

 
 - **`config`**: Path to the model configuration.
 - **`quantization`**: The `Quantization` strategy being applied.
 - **`target`**: The `tvm.target.Target` (e.g., CUDA, Metal).
 - **`opt`**: An `OptimizationFlags` instance.
 - **`debug_dump`**: Optional path to dump IR at each phase.
 
 **Sources:** [python/mlc_llm/interface/compile.py27-41](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/interface/compile.py#L27-L41)

 
### OptimizationFlags

 `OptimizationFlags` controls specific performance features like FlashInfer, cuBLAS, and FasterTransformer. These flags are updated based on the target and quantization kind during `CompileArgs.__post_init__`.

 
 - **`flashinfer`**: Enables FlashInfer attention kernels (requires CUDA SM80+).
 - **`cublas_gemm`**: Enables cuBLAS for GEMM operations.
 - **`faster_transformer`**: Enables FasterTransformer-based kernels.
 
 **Sources:** [python/mlc_llm/interface/compile.py42-43](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/interface/compile.py#L42-L43)

## Phase 0: Metadata and Support Attachment

 Phase 0 prepares the IRModule by attaching model-specific information and auxiliary functions. These passes annotate the graph with metadata required for memory planning and runtime execution.

 
### Key Attach Passes

 
| Pass Name | Description | Source |
|---|---|---|
| AttachVariableBounds | Attaches tir_var_upper_bound (e.g., total_seq_len, batch_size) to Relax functions to assist memory planning. | python/mlc_llm/compiler_pass/attach_support_info.py12-28 |
| AttachGPUSamplingFunc | Attaches specialized TIR functions for GPU sampling like multinomial_from_uniform and sample_with_top_p. | python/mlc_llm/compiler_pass/attach_sampler.py14-66 |
| AttachLogitProcessFunc | Attaches apply_logit_bias_inplace, apply_penalty_inplace, and apply_bitmask_inplace kernels. | python/mlc_llm/compiler_pass/attach_logit_processor.py13-38 |
| AttachSoftmaxWithTemperature | Rewrites one-shot softmax into a two-stage chunked LSE (Log-Sum-Exp) + Softmax kernel for numerical stability. | python/mlc_llm/compiler_pass/attach_softmax_with_temperature.py14-26 |
| AttachSpecDecodeAuxFuncs | Attaches auxiliary functions required for speculative decoding verification. | python/mlc_llm/compiler_pass/attach_spec_decode_aux_funcs.py |

 
### Variable Bounds Interaction

 Variable bounds are derived from the `model_config` (e.g., `sliding_window_size`, `prefill_chunk_size`, `max_batch_size`). These bounds allow the compiler to perform static memory planning even for dynamic-shape graphs.

## Phase 1 & 3: Fusion and Dispatch

 These phases perform the primary graph-level and TIR-level optimizations, including operator fusion for quantized models and kernel dispatch.

 
### Fusion Categories

 
 - **Fuse Category**: Focuses on reducing memory bandwidth by combining operations. 
 - `FuseDequantizeMatmulEwise`: Fuses weight dequantization with matrix multiplication and subsequent elementwise ops. [python/mlc_llm/compiler_pass/fuse_dequantize_matmul_ewise.py](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/fuse_dequantize_matmul_ewise.py)
 - `FuseTransposeMatmul`: Fuses transpose into the matmul kernel. [python/mlc_llm/compiler_pass/fuse_transpose_matmul.py](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/fuse_transpose_matmul.py)
 - `FuseAddRMSNorm`: Fuses residual addition with RMSNorm for GPU targets. [python/mlc_llm/compiler_pass/fuse_add_norm.py1-15](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/fuse_add_norm.py#L1-L15)
 - **Dispatch Category**: Selects the best implementation for specific hardware. 
 - `DispatchKVCacheCreation`: Chooses between `TIRPagedKVCache` or `FlashInferPagedKVCache`. [python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py)
 - `BLASDispatch`: Replaces matmuls with cuBLAS/hipBLAS calls for unquantized weights. [python/mlc_llm/compiler_pass/blas_dispatch.py](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/blas_dispatch.py)
 - `DispatchTritonKernel`: Replaces Relax ops with external Triton implementations. [python/mlc_llm/compiler_pass/dispatch_triton_kernel.py](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/dispatch_triton_kernel.py)

## Phase 4: Dlight Low-Level Optimizations

 Phase 4 applies `tvm.s_tir.dlight`, which provides hardware-specific scheduling for TIR PrimFuncs.

 
 - **`LowBatchGemvSpecialize`**: Specializes GEMV kernels for small batch sizes (typical in decoding). [python/mlc_llm/compiler_pass/low_batch_specialization.py](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/low_batch_specialization.py)
 - **`ApplyDefaultSchedule`**: Automatically applies tiling, vectorization, and thread binding for GPU architectures (Matmul, Reduction, GEMV). [python/mlc_llm/compiler_pass/pipeline.py157-167](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/pipeline.py#L157-L167)

## Phase 5: VM Lowering and Memory Planning

 The final phase prepares the module for the Relax Virtual Machine (VM).

 
 - **`StaticPlanBlockMemory`**: Assigns static memory offsets to tensors to minimize peak memory usage.
 - **`LiftTIRGlobalBufferAlloc`**: Lifts allocations out of TIR kernels into the VM level for better reuse. [python/mlc_llm/compiler_pass/lift_global_buffer_alloc.py](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/lift_global_buffer_alloc.py)
 - **`AttachMetadataWithMemoryUsage`**: Records estimated memory usage for model weights and activation buffers. [python/mlc_llm/compiler_pass/estimate_memory_usage.py](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/estimate_memory_usage.py)
 - **`RewriteCUDAGraph`**: Groups sequences of kernels into CUDA Graphs to reduce CPU-side launch overhead. [python/mlc_llm/compiler_pass/pipeline.py186](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/pipeline.py#L186-L186)

## Debugging and Instrumentation

 The pipeline supports deep inspection via the `debug_dump` parameter.

 
### Debug Dump Pass

 The `_DebugDump` pass is a dummy pass that writes the current state of the `IRModule` to a file after each phase. This is critical for identifying which pass introduced a regression or optimization failure.

 
 - `debug-phase0.py`: State after metadata attachment.
 - `debug-phase1.py`: State after graph-level fusion.
 - `debug-phase3.py`: State after TIR-level fusion.
 
 **Sources:** [python/mlc_llm/compiler_pass/pipeline.py61-79](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/pipeline.py#L61-L79) [python/mlc_llm/compiler_pass/pipeline.py120-150](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/pipeline.py#L120-L150)

 
### Progress Logging

 The `_LogProgress` pass provides console feedback during the compilation process, indicating the start of major phases like "Lowering to TVM TIR kernels" or "Running TVM Dlight low-level optimizations".
