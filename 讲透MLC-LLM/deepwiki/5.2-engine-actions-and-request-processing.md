## Purpose and Scope

 This document describes the **EngineAction** system, which implements the modular request processing pipeline in MLC LLM's C++ serving engine. EngineActions are the executable units that orchestrate model inference, token generation, and request state management. Each action handles a specific phase of request processing: prefilling new requests, decoding tokens, or managing speculative decoding workflows.

 For information about the threading and FFI layer that invokes these actions, see [Engine Core Architecture](https://deepwiki.com/mlc-ai/mlc-llm/5.1-engine-core-architecture). For details on request state management, see [Engine Core Architecture](https://deepwiki.com/mlc-ai/mlc-llm/5.1-engine-core-architecture). For information on the paged KV cache used by actions, see [KV Cache and Neural Network Operators](https://deepwiki.com/mlc-ai/mlc-llm/4.3-kv-cache-and-neural-network-operators).

### NewRequestPrefill: Standard Prefill Action

 **Purpose**: Processes requests from `waiting_queue`, performs initial token prefill, and moves them to `running_queue`.

 **Key Steps** ([cpp/serve/engine_actions/new_request_prefill.cc30-261](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_actions/new_request_prefill.cc#L30-L261)):

 - **Match Prefix Cache** (line 44) - Checks if input tokens match cached sequences via `MatchPrefixCache()`.
 - **Update Request Status** (line 55) - Changes status from `kPending` to `kAlive` via `UpdateRequestToAlive()`.
 - **Run Model Prefill** (line 62-148) - For each model: 
 - Computes embeddings via `TokenData::GetEmbedding()` or `Model::TokenEmbed()`.
 - Invokes `Model::BatchPrefill()` to process input tokens.
 - Returns logits for the last token position.

 - **Sample Tokens** (line 173-247) - Samples next token for each request entry using `Sampler::BatchSampleTokensWithProbAfterTopP()`.
 - **Commit to KV Cache** (line 171) - Calls `prefix_cache->CommitSequenceExtention()`.

### Request State Transitions

 Requests progress through three states managed by `RequestStateStatus`:

 
| State | Description | Location | Actions |
|---|---|---|---|
| kPending | Waiting to be prefilled | waiting_queue | NewRequestPrefill reads cpp/serve/engine_actions/new_request_prefill.cc35 |
| kAlive | Generating tokens | running_queue | BatchDecode/Draft/Verify process cpp/serve/engine_state.cc40 |
| kFinished | Completed or stopped | Removed | Cleaned up by postprocessing cpp/serve/engine_actions/action_commons.cc315 |

## Speculative Decoding Actions

 
### Small Draft Model Mode (BatchDraft + BatchVerify)

 Speculative decoding uses a small "draft" model to propose multiple tokens, which are then verified in parallel by the large "verify" model.

 **BatchDraft Action** ([cpp/serve/engine_actions/batch_draft.cc38-300](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_actions/batch_draft.cc#L38-L300)):

 
 - **Draft Rounds** (line 112-293) - Repeats for `estate->spec_draft_length` iterations: 
 - Collects last committed token (first round) or last draft token (subsequent rounds).
 - Computes embeddings and runs `Model::BatchDecode()` on draft model.
 - Samples tokens and stores them in `RequestModelState::draft_output_tokens`.
 - **Lag Handling** (line 127-142) - If draft model lags behind verify model, prefills missing tokens via `PrefillLaggedTokensByChunk()`.
 
 **BatchVerify Action** ([cpp/serve/engine_actions/batch_verify.cc44-274](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_actions/batch_verify.cc#L44-L274)):

 
 - **Collect Drafts** (line 50) - Gets draft tokens from each `RequestModelState` via `GetDraftsToVerify()`.
 - **Embed and Verify** (line 115-123) - Runs `Model::BatchVerify()` with all draft tokens and token tree structure via `token_tree_parent_ptr`.
 - **Sample and Compare** (line 148-155) - Uses `Sampler::BatchVerifyDraftTokensWithProbAfterTopP()` to compare draft and verify probabilities.
 - **Accept/Reject** (line 174-215) - Commits accepted tokens to models and rolls back rejected ones.
