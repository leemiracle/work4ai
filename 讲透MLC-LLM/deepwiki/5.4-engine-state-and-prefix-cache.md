  This page covers the two data-management subsystems used by the C++ serving engine during inference: **`EngineState`**, which tracks all live and pending requests, and **`PrefixCache`**, which enables KV-cache reuse across requests via a paged radix tree. Both subsystems live entirely on the C++ side and are accessed by the engine actions at every step.

 For how these are consumed by the actions themselves (prefill, decode, draft, verify), see page [5.2](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/5.2) For the token sampling pipeline that reads from engine state, see page [5.3](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/5.3) For the engine configuration fields that control prefix cache behavior (`prefix_cache_max_num_recycling_seqs`), see page [6.3](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/6.3)

## EngineState

 `EngineStateObj` [cpp/serve/engine_state.h60-112](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_state.h#L60-L112) is the single shared mutable object that all engine actions read and modify at every `Step()` call. It is declared as a TVM Object and wrapped by the `EngineState` handle class.

### EngineInternalIDManager

 `EngineInternalIDManager` [cpp/serve/engine_state.h25-48](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_state.h#L25-L48) manages integer IDs used to identify sequences in the KV cache. It is a simple pool recycler:

 
 - `GetNewId()` returns the next available ID from `available_ids`, reusing freed IDs when possible [cpp/serve/engine_state.h30-38](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_state.h#L30-L38)
 - `RecycleId(id)` returns an ID to the pool [cpp/serve/engine_state.h41](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_state.h#L41-L41)
 - `Reset()` clears all state, setting `id_cnt` back to 0 [cpp/serve/engine_state.h44-47](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_state.h#L44-L47)
 
 This prevents unbounded growth of sequence IDs across many short requests.

 
### ActionPostProcessWorkspace

 `ActionPostProcessWorkspace` [cpp/serve/engine_state.h51-54](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_state.h#L51-L54) is pre-allocated memory that engine actions reuse on every step to avoid per-step heap allocation:

 
 - `finished_rsentries` — scratch list of `RequestStateEntry` items that finished during a step.
 - `callback_delta_outputs` — batch of `RequestStreamOutput` objects to be delivered to `request_stream_callback_`.
 
 
### Key Methods

 **`Reset()`** [cpp/serve/engine_state.cc15-26](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_state.cc#L15-L26) clears both queues, all request states, the ID manager, metrics, the prefix cache, and resets the `postproc_workspace`.

 **`GetRequestState(request)`** [cpp/serve/engine_state.cc28-31](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_state.cc#L28-L31) returns the `RequestState` for a given `Request` by following a back-pointer stored directly on the `RequestNode`.

 **`GetRunningRequestStateEntries()`** [cpp/serve/engine_state.cc33-50](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_state.cc#L33-L50) returns the list of `RequestStateEntry` items that are both alive (`kAlive`) and fully past prefill (`mstates[0]->inputs.empty()`). The result is cached in `cached_running_rsentries_` and only recomputed when `running_rsentries_changed` is set.

## PrefixCache

 The prefix cache enables KV-cache reuse when multiple requests share a common prompt prefix. When a new request arrives, the cache looks up the longest matching prefix among previously completed sequences and instructs the KV cache to either fork or recycle that sequence instead of starting from scratch.

 
### PrefixCacheObj Interface

 `PrefixCacheObj` [cpp/serve/prefix_cache.h56-133](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.h#L56-L133) is the abstract base class. The `PrefixCache` handle [cpp/serve/prefix_cache.h135-150](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.h#L135-L150) exposes two factory methods:

 
| Factory | Resulting Mode |
|---|---|
| PrefixCache::CreateRadixPrefixCache(max_recycling_seqs, remove_callback) | PrefixCacheMode::kRadix cpp/serve/prefix_cache.h142-143 |
| PrefixCache::CreateNoPrefixCache() | PrefixCacheMode::kDisable cpp/serve/prefix_cache.h147 |

 
#### PrefixCacheMatchedResult

 `InsertSequence` returns a `PrefixCacheMatchedResult` [cpp/serve/prefix_cache.h36-54](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.h#L36-L54) describing how the new sequence should be set up:

 
| Field | Type | Meaning |
|---|---|---|
| prefilled_offset | size_t | Number of leading tokens already prefilled (can skip them) cpp/serve/prefix_cache.h41 |
| forked_seq_id | int64_t | ID of an existing sequence to fork from (-1 if none) cpp/serve/prefix_cache.h45 |
| reused_seq_id | int64_t | ID of a recycled sequence that is taken over (-1 if none) cpp/serve/prefix_cache.h49 |
| reused_seq_pop_last_tokens | size_t | Trailing tokens to roll back on the reused sequence cpp/serve/prefix_cache.h53 |

## PrefixCacheImpl: Radix Cache

 `PrefixCacheImpl` [cpp/serve/prefix_cache.cc21-339](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.cc#L21-L339) is the active implementation used when prefix caching is enabled. It wraps a `PagedRadixTree` and applies an LRU eviction policy over recycling sequences.

 
### Sequence States

 Each sequence tracked by `PrefixCacheImpl` has one of two internal states, managed in `seq_states_`:

 
```

```

 
 - **`kActive`**: Sequence is in use. Can be forked by new requests [cpp/serve/prefix_cache.cc282](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.cc#L282-L282)
 - **`kRecycling`**: Sequence belongs to a finished request. KV cache pages are retained. Can be forked or fully taken over by a new request. ### LRU Eviction

 `PrefixCacheImpl` maintains two synchronized maps:

 
 - `recycling_seq_lrus_`: maps `seq_id → lru_timestamp` [cpp/serve/prefix_cache.cc32-33](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.cc#L32-L33)
 - `reversed_recycling_seq_lrus_`: maps `lru_timestamp → seq_id` [cpp/serve/prefix_cache.cc32-33](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.cc#L32-L33)
 
 `lru_counter_` is incremented each time a sequence is recycled. `TryFreeMemory()` [cpp/serve/prefix_cache.cc224-242](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.cc#L224-L242) removes the entry with the smallest `lru_timestamp` (oldest), calls `radix_tree_->RemoveSequence(seq_id)`, and invokes `remove_callback_` (which returns the sequence ID back to the engine's ID manager and removes the sequence from the KV cache).

 `RecycleSequence()` [cpp/serve/prefix_cache.cc190-215](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.cc#L190-L215) enforces the `max_num_recycling_seqs_` cap: if already at capacity, it calls `TryFreeMemory()` before inserting the new recycling entry.

 Sources: [cpp/serve/prefix_cache.cc190-242](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.cc#L190-L242)

 
### Lazy Extension

 `ExtendSequence()` [cpp/serve/prefix_cache.cc149-151](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.cc#L149-L151) only appends to the `uncommitted_extended_token_ids_` buffer. The actual `radix_tree_->ExtendSequence()` call is deferred until `CommitSequenceExtention()` is invoked [cpp/serve/prefix_cache.cc153-168](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.cc#L153-L168) This is called automatically at the start of `InsertSequence`, `RecycleSequence`, and `RollBackSequence` to ensure consistency.

## NoPrefixCache

 `NoPrefixCache` [cpp/serve/prefix_cache.cc344-425](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.cc#L344-L425) is the stub implementation used when `prefix_cache_max_num_recycling_seqs` is set to 0 or prefix caching is disabled. All state-modifying methods are no-ops or fatal errors. `InsertSequence` always returns `{0, -1, -1, 0}` (no match) [cpp/serve/prefix_cache.cc351-354](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.cc#L351-L354) and `TryFreeMemory` always returns `false` [cpp/serve/prefix_cache.cc385](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/prefix_cache.cc#L385-L385)

 This design allows the engine to call the same `PrefixCache` interface regardless of whether caching is enabled.
