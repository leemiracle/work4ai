  Microserving in MLC LLM refers to a fine-grained orchestration architecture that allows sub-request-level control over the LLM inference lifecycle. This architecture enables **Disaggregated Serving**, where the Prefill (encoding) and Decode (generation) phases of a single request are executed on different physical nodes or GPU clusters to optimize throughput and resource utilization.

 
## MicroServing API and Entrypoints

 The Microserving stack extends the standard OpenAI-compatible server with specialized endpoints for remote KV cache management and execution control. These endpoints are defined in `python/mlc_llm/serve/entrypoints/microserving_entrypoints.py` and are integrated into the FastAPI application during server startup [python/mlc_llm/interface/serve.py120](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/interface/serve.py#L120-L120)

 
### Key Endpoints

 
 - **/microserving/prep_recv**: Prepares a target engine to receive KV cache for a specific request.
 - **/microserving/remote_send**: Instructs an engine to send its local KV cache for a request to a remote destination.
 - **/microserving/start_generate**: Triggers the generation (decode) phase on a node that has already received the necessary KV cache.
 
 
### Protocol Types

 The communication between the Router and Microserving nodes uses specialized Pydantic models defined in `python/mlc_llm/protocol/microserving_protocol.py`:

 
 - `PrepRecvRequest`: Contains the `request_id` and metadata needed to allocate KV cache slots on the receiver.
 - `RemoteSendRequest`: Specifies the `request_id` and the `target_endpoint` where the KV cache should be transmitted.

## Disaggregated Prefill-Decode Pattern

 In disaggregated serving, a request is split into two distinct execution steps handled by different engine instances:

 
 - **Prefill Node**: Computes the initial hidden states and KV cache for the prompt. It then invokes a `remote_send` action to transfer the KV cache.
 - **Decode Node**: Receives the KV cache via a `prep_recv` action and then performs iterative token generation (`start_generate`).
 
 
### KV Cache Transfer (NVSHMEM)

 For high-performance deployments, MLC LLM supports **NVSHMEM-based KV transfer**. This allows direct GPU-to-GPU memory copies across nodes, bypassing the CPU host memory and standard networking stack where hardware supports RDMA. This logic is implemented within the C++ runtime actions `DisaggRemoteSendAction` and `DisaggPrepRecvAction`.

## The Router Base Class

 The `Router` is the central orchestrator in a microserving cluster. It is responsible for receiving client requests and "translating" them into a sequence of microserving API calls.

 
### Core Components

 
 - **Modes**: The router supports different balancing strategies, including `round-robin` and `disagg`.
 - **pd_balance_factor**: A configuration parameter used in disaggregated mode to balance the ratio of prefill-heavy nodes to decode-heavy nodes.
 - **translate_request**: The primary method that determines the execution plan for an incoming `ChatCompletionRequest`.
 
 
### Custom Router Implementation

 Users can implement custom scheduling logic by inheriting from the `Router` base class and overriding the `translate_request` method. This allows for sophisticated logic such as:

 
 - Locality-aware scheduling (sending requests to nodes that already have a prefix in cache).
 - Dynamic load balancing based on engine metrics.
 - Priority-based queuing.

## Implementation Details: C++ Engine Actions

 The microserving operations are backed by specific `EngineAction` implementations in the C++ core [cpp/serve/engine_actions/disagg_remote_send.cc](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/cpp/serve/engine_actions/disagg_remote_send.cc) These actions are triggered when the engine receives a request through the microserving entrypoints.

 
### DisaggRemoteSendAction

 This action identifies the KV cache fragments associated with a `request_id` in the `PagedKVCache` and initiates a network or NVSHMEM transfer to the target URI provided in the `RemoteSendRequest`.

 
### DisaggPrepRecvAction

 This action communicates with the `BlockManager` to reserve physical blocks in the KV cache before the data arrives, ensuring that the `start_generate` call has immediate access to the required context.
