## Purpose and Scope

 This page describes the technical implementation of two related subsystems:

 
 - **`PagedKVCache` Abstraction** — The compile-time interface used in model definitions to declare attention memory layout and Rotary Position Embedding (RoPE) configurations.
 - **`DispatchKVCacheCreation` Compiler Pass** — The transformation logic that rewrites generic cache declarations into concrete, target-specific factory functions (TIR vs. FlashInfer).
 - **TIR Neural Network Operators** — High-performance GPU kernels implemented in TVM TensorIR (TIR) for operations like tree attention (`tree_attn`), speculative decoding verification (`batch_spec_verify`), and nucleus sampling (`top_p_pivot`, `top_p_renorm`).
 
 For the full compiler pass pipeline that invokes these transformations, see [4.2](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/4.2) For the C++ engine's runtime management of the cache, see [5.1](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/5.1)

## PagedKVCache Abstraction

 `PagedKVCache` ([python/mlc_llm/nn/kv_cache.py14-15](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/nn/kv_cache.py#L14-L15)) is a subclass of `TVMPagedKVCache`. It provides the `create_generic` static method, which acts as a symbolic placeholder in the Relax IR during the initial stages of model compilation.

 
### The `create_generic` Method

 Model architectures (e.g., Gemma3 [python/mlc_llm/model/gemma3/gemma3_model.py12](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/model/gemma3/gemma3_model.py#L12-L12)) call `create_generic` to specify the cache's physical and algorithmic properties. Instead of allocating memory, it emits a `relax.call_pure_packed` node with the symbol `"mlc.create_paged_kv_cache_generic"` ([python/mlc_llm/nn/kv_cache.py56-92](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/nn/kv_cache.py#L56-L92)).

 
| Parameter | Type | Description |
|---|---|---|
| attn_kind | Union[str, List[str]] | Attention algorithm: "mha", "mla", or "mha_sliding". |
| max_batch_size | tir.Var | Maximum concurrent sequences supported. |
| page_size | tir.Var | Number of token slots per KV page. |
| rope_mode | RopeMode | RoPE strategy: NORMAL (stored) or INLINE (computed). |
| rotary_dim | Optional[int] | Dimensions to apply RoPE; defaults to qk_head_dim. |
| layer_partition | Optional[List[int]] | Layer boundaries for Pipeline Parallelism. |
| enable_disaggregation | bool | Enables prefill/decode disaggregation support. |

 **Sources:** [python/mlc_llm/nn/kv_cache.py18-42](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/nn/kv_cache.py#L18-L42) [python/mlc_llm/nn/kv_cache.py46-94](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/nn/kv_cache.py#L46-L94)

 
### Attention Kind and RoPE Modes

 The `attn_kind` parameter allows for heterogeneous attention types across layers. For instance, **Gemma3** uses a `sliding_window_pattern` to alternate between standard and sliding window attention ([python/mlc_llm/model/gemma3/gemma3_model.py41-43](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/model/gemma3/gemma3_model.py#L41-L43)).

 `RopeMode` ([python/mlc_llm/nn/kv_cache.py11](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/nn/kv_cache.py#L11-L11)) defines the lifecycle of rotated keys:

 
 - **`RopeMode.NORMAL`**: Keys are rotated before being written to the cache.
 - **`RopeMode.INLINE`**: Keys are stored un-rotated; RoPE is applied on-the-fly during the attention kernel.

## DispatchKVCacheCreation Compiler Pass

 `DispatchKVCacheCreation` ([python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py78-80](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py#L78-L80)) is a TVM `module_pass` that inspects the IRModule for generic cache creation calls and replaces them with concrete implementations.

 
### Pass Logic and Selection

 The pass performs the following steps ([python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py104-133](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py#L104-L133)):

 
 - **Extraction**: It parses the 18 arguments from the `mlc.create_paged_kv_cache_generic` call using `extract_creation_args` ([python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py16-75](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py#L16-L75)).
 - **Metadata Update**: It populates the model's global metadata with KV cache parameters (heads, layers, dimensions) ([python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py135-142](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py#L135-L142)).
 - **TIR Backend**: It always generates a `TIRPagedKVCache` using `create_tir_paged_kv_cache` ([python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py144-180](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py#L144-L180)).
 - **FlashInfer Backend**: If the target is CUDA and the `flashinfer` flag is enabled, it attempts to create a `FlashInferPagedKVCache` ([python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py182-237](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/compiler_pass/dispatch_kv_cache_creation.py#L182-L237)).

## Key TIR Neural Network Operators

 MLC LLM utilizes specialized TensorIR operators to handle complex logic that standard deep learning frameworks often struggle to fuse or parallelize efficiently.

 
### Attention and Tree Attention

 The `attention` operator ([python/mlc_llm/op/attention.py18-25](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/op/attention.py#L18-L25)) provides a unified interface for causal attention. It prioritizes the **FlashInfer** implementation if available and compatible (e.g., `head_dim=128`, `dtype=float16`) ([python/mlc_llm/op/attention.py101-136](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/op/attention.py#L101-L136)), otherwise falling back to a sequence prefill implementation ([python/mlc_llm/op/attention.py65-98](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/op/attention.py#L65-L98)).

 **`tree_attn`**: Imported from `tvm.relax.frontend.nn.llm`, this operator is critical for speculative decoding. It computes attention over a tree structure of tokens rather than a linear sequence, using a flattened mask to define parent-child relationships ([tests/python/op/test_tree_attn.py116-135](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/tests/python/op/test_tree_attn.py#L116-L135)).

 
### Speculative Decoding: `batch_spec_verify`

 `batch_spec_verify` ([python/mlc_llm/op/batch_spec_verify.py10](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/op/batch_spec_verify.py#L10-L10)) implements the parallel verification of draft tokens.

 
 - **Input**: `draft_probs`, `draft_tokens`, `model_probs`, and a `token_tree` ([python/mlc_llm/op/batch_spec_verify.py28-44](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/op/batch_spec_verify.py#L28-L44)).
 - **Logic**: It performs a tree traversal. For each node, it compares the target model's probability against a uniform sample scaled by the draft probability to decide acceptance or rejection ([python/mlc_llm/op/batch_spec_verify.py130-155](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/op/batch_spec_verify.py#L130-L155)).
 
 
### Sampling: `top_p_pivot` and `top_p_renorm`

 These operators implement nucleus sampling on the GPU ([python/mlc_llm/op/__init__.py15](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/op/__init__.py#L15-L15)):

 
 - **`top_p_pivot`**: Finds the threshold probability (pivot) such that the sum of probabilities above it equals `p` ([tests/python/op/test_top_p_pivot.py1-10](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/tests/python/op/test_top_p_pivot.py#L1-L10)).
 - **`top_p_renorm`**: Sets all probabilities below the pivot to zero and renormalizes the remaining distribution ([tests/python/op/test_top_p_pivot.py1-10](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/tests/python/op/test_top_p_pivot.py#L1-L10)).

### Position Embeddings (RoPE/mRoPE)

 Position embeddings are handled via specialized operators:

 
 - **Standard RoPE**: Integrated directly into `PagedKVCache` and attention kernels using `rope_theta` and `rope_scale` ([python/mlc_llm/nn/kv_cache.py77-79](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/nn/kv_cache.py#L77-L79)).
 - **mRoPE (Multimodal RoPE)**: Used in models like Qwen2.5-VL to handle multi-dimensional positional information for images and videos ([python/mlc_llm/op/mrope.py8-13](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/op/mrope.py#L8-L13)).
