## Purpose and Scope

 This page provides a practical guide for deploying MLC LLM as a production-grade REST API server. It covers the FastAPI-based serving infrastructure, engine configuration modes, speculative decoding setup, prefix caching, multi-model hosting (including embedding models), and OpenAI-compatible client integration.

 
## Overview

 MLC LLM provides a universal LLM deployment engine that exposes an OpenAI-compatible REST API. The server architecture leverages a multi-layered stack to ensure high-performance asynchronous inference:

 
 - **FastAPI Layer**: Handles HTTP routing, request validation using Pydantic protocols, and Server-Sent Events (SSE) for streaming.
 - **Python Serving Layer**: `AsyncMLCEngine` manages the asyncio event loop and interacts with the C++ backend via FFI.
 - **C++ Runtime Engine**: `ThreadedEngine` runs a background loop for batching, scheduling, and executing model actions (Prefill/Decode).
 - **Distributed Execution**: Multi-GPU support via TVM Disco for tensor parallelism.

## Engine Modes and Overrides

 The `--mode` flag determines default values for concurrency and memory allocation. These can be fine-tuned using the `EngineConfigOverride` class via the `--overrides` string.

 
| Mode | max_num_sequence | prefill_chunk_size | Description |
|---|---|---|---|
| local | 4 | Context Window | Optimized for local desktop use. |
| interactive | 1 | Context Window | Optimized for single-user low latency. |
| server | Auto-inferred | Auto-inferred | Maximizes GPU throughput and memory. |

## Speculative Decoding Configuration

 MLC LLM supports several speculative decoding algorithms to accelerate generation by using a smaller "draft" model or specialized heads to predict multiple tokens per step.

 
### Modes

 
 - **`small_draft`**: Standard speculative decoding using a separate smaller model (e.g., Llama-7B speculating for Llama-70B).
 - **`eagle`**: EAGLE-style speculation using lightweight regression heads.
 - **`medusa`**: Medusa-style speculation using multiple decoding heads on the base model.

## Prefix Caching

 Prefix caching optimizes multi-turn conversations and common system prompts by reusing KV cache segments.

 
 - **Mode**: Controlled by `--prefix-cache-mode` (default: `radix`). [python/mlc_llm/cli/serve.py162-167](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/cli/serve.py#L162-L167)
 - **Mechanism**: The `PagedRadixTree` manages cached blocks. When a request's prefix matches a cached sequence, the engine skips the prefill for those tokens. [python/mlc_llm/serve/radix_tree.py9](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/serve/radix_tree.py#L9-L9)
 - **Recycling**: `prefix_cache_max_num_recycling_seqs` determines how many sequences are kept in memory after completion for potential reuse. [python/mlc_llm/cli/serve.py27](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/cli/serve.py#L27-L27)

## Advanced Deployment Features

 
### CORS Setup

 The server uses `CORSMiddleware` to handle cross-origin requests. Configuration is exposed via CLI:

 
 - `--allowed-origins`
 - `--allowed-methods`
 - `--allowed-headers`
 
 **Sources:** [python/mlc_llm/interface/serve.py110-116](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/interface/serve.py#L110-L116)

 
### API Key Verification

 Basic security is provided via an optional API key. If `api_key` is set in `ServerContext`, the `verify_api_key` dependency checks the `Authorization` header.

 **Sources:** [python/mlc_llm/serve/entrypoints/openai_entrypoints.py29-39](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/serve/entrypoints/openai_entrypoints.py#L29-L39)

 
### Subprocess Management (PopenServer)

 For testing and integration, `PopenServer` allows launching the REST server as a managed background process. It includes logic to wait for the `/v1/models` endpoint to become healthy before returning.

 **Sources:** [python/mlc_llm/serve/server/popen_server.py18-162](https://github.com/mlc-ai/mlc-llm/blob/fcce2cc3/python/mlc_llm/serve/server/popen_server.py#L18-L162)
