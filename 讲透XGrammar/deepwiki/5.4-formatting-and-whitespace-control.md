## Purpose and Scope

 This document explains how XGrammar's JSON Schema converter controls whitespace and formatting in generated EBNF grammars. The formatting system determines whether JSON output must follow strict indentation rules or can have flexible whitespace, and how separators (commas, colons, newlines) are handled during grammar generation.

 For the broader JSON Schema converter architecture, see [5.1](https://deepwiki.com/mlc-ai/xgrammar/5.1-converter-architecture). For details on how these formatting rules apply to objects and arrays specifically, see [5.3](https://deepwiki.com/mlc-ai/xgrammar/5.3-object-and-array-schema-processing).

 
## Overview

 The formatting system provides fine-grained control over whitespace in generated JSON, balancing three competing needs:

 
 - **Strict formatting**: Requiring exact indentation for human-readable output
 - **Flexible formatting**: Allowing any whitespace for robustness
 - **Bounded flexibility**: Limiting whitespace to prevent excessive generation
 
 The system is built around two main components: parameter configuration and the `IndentManager` class that translates parameters into EBNF patterns.

## Configuration Parameters

 The JSON Schema converter accepts four formatting-related parameters:

 
| Parameter | Type | Default | Purpose |
|---|---|---|---|
| any_whitespace | bool | true | Allow any amount/type of whitespace between elements |
| indent | std::optional<int> | std::nullopt | Number of spaces per indentation level; nullopt means single-line output |
| separators | std::optional<std::pair<std::string, std::string>> | std::nullopt | Comma and colon separators; defaults to (",", ": ") with indent or (", ", ": ") without |
| max_whitespace_cnt | std::optional<int> | std::nullopt | Maximum whitespace characters when any_whitespace is true; nullopt means unlimited |

### State Management

 The `IndentManager` maintains a stack-based indentation state:

 
 - **`total_indent_`**: Current total indentation level (in spaces)
 - **`is_first_`**: Stack tracking whether we're at the first element in each nesting level
 - **`indent_`**: Number of spaces to add per level
 
 When entering a nested structure (object or array), the converter calls `StartIndent()`, which:

 
 - Increases `total_indent_` by `indent_`
 - Pushes `true` onto `is_first_` stack
 
 When exiting, `EndIndent()` reverses these operations.

## Integration with Grammar Generation

 The formatting system integrates with grammar generation for arrays, objects, and nested structures.

 
### Example: Array with Indentation

 Consider this schema with `indent=2`, `any_whitespace=false`:

 
```

```

 Generated EBNF fragment:

 
```
root ::= ("[" "\n  " basic_integer (",\n  " basic_integer)* "\n" "]") | ("[" "" "]")
```

 Breakdown:

 
 - `"\n "` - StartSeparator for first element (2 spaces indent)
 - `",\n "` - MiddleSeparator between elements
 - `"\n"` - EndSeparator before closing bracket
 - `""` - EmptySeparator for empty array

### Example: Object with Flexible Whitespace

 Schema with `any_whitespace=true`:

 
```

```

 Generated EBNF fragment:

 
```
root ::= "{" [ \n\t]* "\"name\"" [ \n\t]* ":" [ \n\t]* basic_string 
         [ \n\t]* "," [ \n\t]* "\"age\"" [ \n\t]* ":" [ \n\t]* basic_integer 
         [ \n\t]* "}"
```

 This accepts various whitespace patterns:

 
 - `{"name":"John","age":30}` - no whitespace
 - `{ "name" : "John", "age" : 30 }` - spaces
 - `{\n "name": "John",\n "age": 30\n}` - indented with newlines
 - `{\t"name"\t:\t"John",\t"age":\t30\t}` - tabs
