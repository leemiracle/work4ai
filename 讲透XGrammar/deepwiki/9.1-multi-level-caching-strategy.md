## Purpose and Scope

 This document describes the two-tier caching architecture used in xgrammar to optimize grammar compilation and token mask generation. The caching system consists of a **grammar-level cache** that stores entire `CompiledGrammar` objects and a **rule-level cache** that enables sharing of `AdaptiveTokenMask` objects across different grammars with similar finite state machines (FSMs).

 For information about the grammar compilation process itself, see [Grammar Compilation](https://deepwiki.com/mlc-ai/xgrammar/2.2-grammar-compilation). For details on token mask generation, see [Token Bitmask Generation](https://deepwiki.com/mlc-ai/xgrammar/8.3-token-bitmask-generation).

 
## Overview

 Grammar compilation and token mask precomputation are computationally expensive operations. The multi-level caching strategy addresses this by caching results at two granularities:

 
 - **Grammar-level**: Caches complete `CompiledGrammar` objects to avoid recompiling the same grammar
 - **Rule-level**: Caches `AdaptiveTokenMask` objects for individual FSM states to enable sharing across different grammars with similar structure
 
 This architecture provides both fast cache hits for identical grammars and partial reuse for structurally similar grammars.

## Grammar-Level Cache

 The grammar-level cache stores complete `CompiledGrammar` objects, keyed by the grammar specification. This cache is managed by the `GrammarCompiler` class and uses an LRU (Least Recently Used) eviction policy.

 
### Cache Structure

 The grammar-level cache is implemented using a thread-safe LRU cache with configurable memory limits:

 
| Property | Description |
|---|---|
| Key | Grammar serialization hash (includes grammar structure, tokenizer info, compilation options) |
| Value | CompiledGrammar object (contains optimized grammar, FSMs, and precomputed token masks) |
| Eviction Policy | LRU (Least Recently Used) |
| Memory Limit | Configurable via cache_limit_bytes (default: unlimited) |
| Thread Safety | Thread-safe via ThreadSafeCache wrapper |

### Concurrency Support

 The grammar-level cache supports concurrent access from multiple threads:

 
 - **Thread-safe operations**: All cache operations are protected by internal synchronization
 - **Parallel compilation**: Multiple threads can compile different grammars simultaneously
 - **No lock contention on hits**: Cache hits are efficiently served without blocking other threads

 The rule-level cache enables efficient reuse across different grammars:

 **Example: Similar Grammars**

 
```

Grammar B:  root ::= "[" string "]"
            string ::= "\"" [^"]* "\""
```

 Even though these grammars have different root rules, they share the same `string` rule. The rule-level cache allows Grammar B to reuse the precomputed token masks for the `string` rule from Grammar A.

## Cache Entry Storage

 Both cache levels use efficient storage representations:

 
### AdaptiveTokenMask Storage

 The `AdaptiveTokenMask` class uses three storage modes to minimize memory usage:

 
| Storage Type | Description | When Used |
|---|---|---|
| kAccepted | Stores list of accepted token indices | When accepted tokens < threshold |
| kRejected | Stores list of rejected token indices | When rejected tokens < threshold |
| kAcceptedBitset | Stores DynamicBitset of accepted tokens | When both lists would be large |

 **Threshold**: `AdaptiveTokenMask::USE_BITSET_THRESHOLD` (typically small constant)

 This adaptive storage significantly reduces memory usage for sparse masks.

## Usage Patterns and Performance

 
### Compilation Time Optimization

 The two-tier cache dramatically reduces compilation time for repeated or similar grammars:

 **Scenario 1: Identical Grammar**

 
 - First compilation: Full optimization pipeline (100-500ms)
 - Subsequent compilations: Grammar cache hit (~1-10μs)
 
 **Scenario 2: Similar Grammars**

 
 - First grammar: Full compilation
 - Second grammar: Partial rule cache hits (50-200ms, depends on overlap)

 **Unlimited Cache (default):**

 
 - **Pros**: Maximum speed, no compilation overhead after first use
 - **Cons**: Unbounded memory growth in long-running applications
 
 **Limited Cache:**

 
 - **Pros**: Bounded memory usage, predictable resource consumption
 - **Cons**: Potential cache thrashing if limit is too small

## Summary

 The multi-level caching strategy in xgrammar provides:

 
 - **Grammar-Level Cache**: Fast retrieval of complete `CompiledGrammar` objects for identical grammar specifications
 - **Rule-Level Cache**: Cross-grammar sharing of `AdaptiveTokenMask` objects for structurally similar FSMs
 - **Configurable Limits**: Both memory-unlimited and memory-bounded operation modes
 - **Thread Safety**: Concurrent compilation and cache access without user locking
 - **Intelligent Storage**: Adaptive storage modes minimize memory overhead
 
 This architecture enables efficient grammar compilation in production systems while supporting both caching for speed and memory management for resource-constrained environments.
