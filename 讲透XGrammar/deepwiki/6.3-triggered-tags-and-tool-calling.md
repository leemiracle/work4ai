  `TriggeredTagsFormat` is the primary structural tag format for implementing LLM tool calling. It enables the LLM to generate free-form text (like reasoning or responses) until it encounters a trigger string that signals a tool call, then constrains generation to follow the tool's parameter schema.

 This page demonstrates how to use `TriggeredTagsFormat` to implement tool calling for major LLM formats including Llama, Qwen, MiniMax, and DeepSeek. For the complete format specification, see [Format Specification](https://deepwiki.com/mlc-ai/xgrammar/6.1-format-specification). For internal implementation details, see [Analysis and Conversion Pipeline](https://deepwiki.com/mlc-ai/xgrammar/6.2-analysis-and-conversion-pipeline).

 
## Overview

 `TriggeredTagsFormat` monitors LLM generation for specific trigger strings and dispatches to structured tag handlers when a trigger is detected. This allows models to mix free text with structured tool calls naturally.

 **Core Mechanism:**

 
 - Define triggers (e.g., `"<function="`, `"<tool_call>"`) that signal tool call start
 - Define tags with begin/content/end that match each tool
 - LLM generates arbitrary text until a trigger appears
 - Upon trigger match, generation switches to the corresponding tag's structured format
 - After tag completion, generation can continue with more free text or additional tool calls
 
 **Key Features:**

 
 - Supports both JSON and XML-style tool calling formats
 - Handles parallel tool calling (multiple calls in one response)
 - Enforces tool choice (required, optional, forced specific tool)
 - Allows mixing reasoning text with tool calls
 - Efficient pattern matching using Aho-Corasick automaton internally

## TagDispatch Grammar Mechanism

 `TagDispatch` is the internal grammar construct that implements trigger-based dispatching. It uses an Aho-Corasick automaton to efficiently match multiple trigger patterns simultaneously during generation.

 
### TagDispatch Structure

 
```

```

 **Fields:**

 
 - `tag_rule_pairs`: Maps trigger strings to grammar rule IDs to execute after matching
 - `stop_eos`: If true, accept EOS token when no trigger matches
 - `stop_str`: Stop strings that terminate generation (even without triggers)
 - `loop_after_dispatch`: If true, continue monitoring for triggers after executing a tag rule
 - `excludes`: Strings that are forbidden in the generated text
