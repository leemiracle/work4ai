  This page documents how the JSON Schema converter handles string format validation and numeric range constraints. These features enable precise validation of string patterns (email, UUID, etc.) and bounded numeric values in generated grammars.

 For overall JSON Schema conversion architecture, see [Converter Architecture](https://deepwiki.com/mlc-ai/xgrammar/5.1-converter-architecture). For object and array processing, see [Object and Array Schema Processing](https://deepwiki.com/mlc-ai/xgrammar/5.3-object-and-array-schema-processing).

 
## Overview

 The JSON Schema converter supports two key validation mechanisms:

 
 - **String Formats**: Converting JSON Schema `format` keywords into regex patterns for email addresses, URLs, UUIDs, date-time strings, and other standardized formats
 - **Numeric Ranges**: Transforming numeric constraints (`minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`) into efficient regex patterns that accept only values within the specified range
 
 Both mechanisms operate during the schema parsing phase, producing `SchemaSpec` intermediate representations that are later converted to EBNF grammar rules.

### Parsing Integer Constraints

 The `ParseInteger` method extracts and validates integer bounds:

 
```

```

 **Integer Bound Validation**:

 
 - Values can be JSON integers or doubles (must be whole numbers)
 - Doubles are checked for precision loss at 64-bit boundaries
 - Values must fit in signed 64-bit integer range (`-2^63` to `2^63-1`)
 - Exclusive bounds are converted to inclusive by adding/subtracting 1
 - Overflow checks prevent invalid exclusive bound conversions
 
 **Special Cases**:

 
 - Rejects doubles at problematic precision boundaries (±9223372036854776000.0)
 - Returns error if `exclusiveMinimum == INT64_MAX` (would overflow)
 - Returns error if `exclusiveMaximum == INT64_MIN` (would underflow)

## Range Regex Generation

 
### Integer Range Regex Algorithm

 The `GenerateRangeRegex` function produces regex patterns matching integers in a given range:

 
```

```

 **Range Splitting Strategy**:

 
 - Split range into negative, zero, and positive components
 - For negative range `[a, b]` where `a < 0`, generate pattern for `[-b, -a]` and prepend `-`
 - For positive range, directly generate pattern
 - Add `0` as alternative if range includes zero
 - Combine all parts with `|` alternation

## Integer EBNF Generation

 The `GenerateInteger` method produces EBNF rules for integer constraints:

 
```

```

 **Effective Bound Calculation**:

 
 - Start with `INT64_MIN` to `INT64_MAX` default range
 - Apply inclusive bounds: `max(effective_min, minimum)`, `min(effective_max, maximum)`
 - Apply exclusive bounds: `max(effective_min, exclusive_minimum + 1)`, `min(effective_max, exclusive_maximum - 1)`
 - Result: tightest range satisfying all constraints

## Performance Considerations

 
### Range Regex Optimization

 The range regex generation algorithm employs several optimization strategies:

 
 - **Digit Count Grouping**: Splits wide ranges by digit count to minimize pattern size
 - **Common Prefix Extraction**: Identifies shared prefixes to reduce redundancy
 - **Character Classes**: Uses compact `[a-b]` notation instead of alternatives
 - **Caching**: Identical range patterns reused across schema
 
 **Complexity**:

 
 - Time: O(log₁₀(range) × digits) for pattern generation
 - Space: O(log₁₀(range)) for pattern size
 
 
### Format Lookup Performance

 Format-to-regex mapping uses constant-time hash lookups:

 
 - O(1) format keyword lookup
 - Regex patterns precomputed and stored as string literals
 - No runtime regex compilation during schema parsing
