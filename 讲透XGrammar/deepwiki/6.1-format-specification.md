  This page documents all format types available in the XGrammar structural tag system. Structural tags provide a declarative way to specify complex grammar patterns by composing format objects. For information about how these formats are analyzed and converted to grammars, see [6.2](https://deepwiki.com/mlc-ai/xgrammar/6.2-analysis-and-conversion-pipeline). For details on the `triggered_tags` format and tag dispatching mechanism, see [6.3](https://deepwiki.com/mlc-ai/xgrammar/6.3-triggered-tags-and-tool-calling).

 
## Overview

 A structural tag specification consists of a format object that describes the structure of text to be matched. Format objects can be simple (like constant strings) or complex (like nested sequences and conditional dispatching). The structural tag parser [cpp/structural_tag.cc29-62](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L29-L62) validates and parses these format specifications from JSON into internal C++ representations, which are then analyzed [cpp/structural_tag.cc501-748](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L501-L748) and converted to EBNF grammars [cpp/structural_tag.cc752-1304](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L752-L1304)

 
## Format Object Structure

 All format objects share a common base structure:

 
| Field | Type | Required | Description |
|---|---|---|---|
| type | string | Optional | Specifies the format type. If omitted, the parser attempts to infer the type from other fields. |

 The `type` field can be one of: `const_string`, `json_schema`, `qwen_xml_parameter`, `any_text`, `grammar`, `regex`, `sequence`, `or`, `tag`, `triggered_tags`, or `tags_with_separator`.

 **Type Inference**: When the `type` field is omitted, the parser tries each format type in a specific order [cpp/structural_tag.cc137-171](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L137-L171) to determine which one matches the provided fields. The `tag` format is prioritized during inference.

### triggered_tags

 Matches arbitrary text with tags that are triggered by specific string patterns. This enables dynamic grammar switching based on trigger strings. For detailed information about how this format works, see [6.3](https://deepwiki.com/mlc-ai/xgrammar/6.3-triggered-tags-and-tool-calling).

 **Fields:**

 
| Field | Type | Required | Description |
|---|---|---|---|
| type | string | Optional | Must be "triggered_tags" if present |

| tags | array of TagFormat | Required | Tag formats to dispatch to (must be non-empty) |
| excludes | array of strings | Optional | Strings that cannot appear in arbitrary text |

 **Internal Fields:**

 
 - `detected_end_strs_`: end strings detected from parent tag context [cpp/structural_tag.cc735-736](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L735-L736)

 - A tag matches a trigger if the trigger is a prefix of the tag's `begin` string

### Unlimited Format Analysis

 The `StructuralTagAnalyzer` [cpp/structural_tag.cc501-748](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L501-L748) performs a visitor pass over the format tree to:

 
 - **Detect end strings**: For `any_text`, `triggered_tags`, and `tags_with_separator` formats, the analyzer detects end strings from parent `tag` contexts [cpp/structural_tag.cc551-561](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L551-L561)
 - **Validate unlimited formats**: Formats like `any_text`, `triggered_tags`, and `tags_with_separator` can match unlimited text. The analyzer ensures:

 
 - In a sequence, only the last element can be unlimited (unless it has excludes) [cpp/structural_tag.cc657-664](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L657-L664)
 - In an `or`, all elements must be unlimited or all must be limited [cpp/structural_tag.cc684-695](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L684-L695)
 - In a tag with unlimited content, at least one end string must be non-empty [cpp/structural_tag.cc705-725](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L705-L725)
 - **Set internal flags**: The analyzer sets `is_unlimited_` flags on `sequence` and `or` formats based on their elements
 
 **Unlimited Detection Rules:**

 
| Format Type | Is Unlimited | Notes |
|---|---|---|
| any_text | Always | Unless has detected_end_strs_ |
| triggered_tags | Always | Unless has detected_end_strs_ |
| tags_with_separator | Always | Unless has detected_end_strs_ |
| sequence | If last element is unlimited and not excluded | cpp/structural_tag.cc672 |
| or | If all elements are unlimited | cpp/structural_tag.cc696 |
| All others | Never | - |

 Sources: [cpp/structural_tag.cc563-601](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L563-L601) [cpp/structural_tag.cc650-748](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L650-L748)

 
### JSON Parsing and Validation

 The `StructuralTagParser` [cpp/structural_tag.cc29-62](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L29-L62) parses JSON strings using the picojson library:

 
 - **Parse JSON**: The input string is parsed into a `picojson::value` [cpp/structural_tag.cc64-73](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L64-L73)
 - **Validate top-level**: Must be an object with optional `"type": "structural_tag"` field [cpp/structural_tag.cc75-96](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L75-L96)
 - **Parse format**: The `"format"` field is recursively parsed [cpp/structural_tag.cc98-171](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L98-L171)
 - **Type dispatch**: Based on the `"type"` field (or inference), the appropriate parsing function is called
 
 **Error Handling**: All parsing functions return `Result<T, ISTError>` types, enabling structured error propagation without exceptions. The `Result` type is defined in [cpp/support/result.h](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/support/result.h)
