## ArraySpec Intermediate Representation

 The `ArraySpec` structure represents a parsed array schema, capturing all array validation constraints as an intermediate form before EBNF generation. This struct is defined in [cpp/json_schema_converter.h73-81](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/json_schema_converter.h#L73-L81) and populated by `SchemaParser::ParseArray`.

 **ArraySpec Structure:**

 
| Field | Type | Description |
|---|---|---|
| prefix_items | std::vector<SchemaSpecPtr> | Ordered schemas for specific array positions (tuple validation) |
| allow_additional_items | bool | Whether items beyond prefix_items are allowed |
| additional_items | SchemaSpecPtr | Schema for items beyond prefix_items (nullptr if not allowed) |
| min_items | int64_t | Minimum number of items required (default: 0) |
| max_items | int64_t | Maximum number of items allowed (-1 means unlimited) |

## ObjectSpec Intermediate Representation

 The `ObjectSpec` structure represents a parsed object schema, capturing property definitions, constraints, and validation rules.

 **ObjectSpec Structure:**

 
| Field | Type | Description |
|---|---|---|
| properties | vector<Property> | Named properties with their schemas (preserves order) |
| pattern_properties | vector<PatternProperty> | Properties matching regex patterns |
| required | unordered_set<string> | Set of required property names |
| allow_additional_properties | bool | Whether undefined properties are allowed |
| additional_properties_schema | SchemaSpecPtr | Schema for additional properties |
| allow_unevaluated_properties | bool | Whether unevaluated properties are allowed |
| unevaluated_properties_schema | SchemaSpecPtr | Schema for unevaluated properties |
| property_names | SchemaSpecPtr | Schema that all property names must match |
| min_properties | int | Minimum number of properties required |
| max_properties | int | Maximum number of properties allowed (-1 means unlimited) |

## Property Number Constraints

 When `minProperties` or `maxProperties` are specified, the generator must ensure the produced EBNF enforces these constraints while respecting required properties.

 
### Number Constraint Handling

 The `JSONSchemaConverter::GetPropertyWithNumberConstraints` method at [cpp/json_schema_converter.cc1546-1564](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/json_schema_converter.cc#L1546-L1564) generates EBNF repetition patterns that enforce property counts. This is used to ensure `minProperties` and `maxProperties` constraints are satisfied.

 **Implementation Logic:**

 
 - **Early return** (line 1549-1551): If `max_properties != -1 && max_properties == already_repeated_times`, return `""`
 - **Calculate effective range** (lines 1552-1553): 
 - `lower = max(0, min_properties - already_repeated_times)`
 - `upper = max_properties == -1 ? -1 : max(0, max_properties - already_repeated_times)`
 - **Generate quantifier** (lines 1554-1563): 
 - `(pattern)*` when `lower == 0 && upper == -1`
 - `(pattern)?` when `lower == 0 && upper == 1`
 - `pattern` when `lower == 1 && upper == 1`
 - `(pattern){lower,upper}` or `(pattern){lower,}` otherwise

## Pattern Properties and Property Names

 
### Pattern Properties

 Pattern properties allow schemas to validate keys matching regex patterns. The parsing occurs at [cpp/json_schema_converter.cc697-709](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/json_schema_converter.cc#L697-L709) and generation at [cpp/json_schema_converter.cc1895-2079](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/json_schema_converter.cc#L1895-L2079)

 **Pattern Property Processing Flow:**

 
 - Parse pattern property schema (line 705): `Parse(pattern_props.at(key), "pattern_prop")`
 - Store as `PatternProperty{pattern, schema}` in `ObjectSpec::pattern_properties`
 - During generation, convert pattern using `RegexToEBNF(pattern)`
 - Combine with value: `FormatOtherProperty(key_pattern, value_rule, rule_name, suffix)`
 - Multiple pattern properties create an OR choice for additional keys
