## Versioning Scheme

 XGrammar follows **semantic versioning** (SemVer) conventions:

 
| Component | Meaning | When to Increment |
|---|---|---|
| MAJOR (0) | Breaking changes | API changes that break backward compatibility |
| MINOR (1) | Feature additions | New features without breaking existing API |
| PATCH (31) | Bug fixes | Bug fixes and minor improvements |

 **Pre-1.0 Status**: The current `0.x.y` version range indicates the API is not yet stable. Breaking changes may occur between minor versions during this phase.

 **Sources**: [pyproject.toml3-10](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L3-L10)

## Wheel Building Process

 The `cibuildwheel` tool automates building wheels for all supported platforms. The configuration enables parallel builds, testing, and validation.

 
### Build Configuration

 
```

```

 **Configuration Details**:

 
 - `build-verbosity = 1`: Display build command output for debugging
 - `build-frontend = "build[uv]"`: Use `uv` as package installer (faster than pip)
 - `test-command`: Runs pytest excluding tests marked with `hf_token_required` (which require HuggingFace credentials)
 - `test-extras = ["test"]`: Installs dependencies from [pyproject.toml30-39](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L30-L39) (`[project.optional-dependencies.test]`)
 
 **Build Process**:

 
 - **Environment Setup**: Install build dependencies via `uv` package installer
 - **C++ Compilation**: CMake builds `libxgrammar.a` static library from [cpp/](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/) sources
 - **Binding Generation**: nanobind compiles [cpp/pybind/](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/pybind/) to create `_core.so`/`_core.pyd` extension module
 - **Wheel Creation**: Package [python/xgrammar/](https://github.com/mlc-ai/xgrammar/blob/c30554f7/python/xgrammar/) Python code and extension into `.whl` file
 - **Testing**: Execute `pytest {project}/tests -m "not hf_token_required"` with test dependencies
 - **Validation**: Import test to verify wheel loads correctly on target platform

## Distribution Channels

 XGrammar releases are distributed through two primary channels:

 
### PyPI Distribution

 **Installation**: `pip install xgrammar`

 **Package Metadata** ([pyproject.toml1-29](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L1-L29)):

 
 - Package name: `xgrammar`
 - License: Apache 2.0
 - Python requirement: `>=3.8, <4`
 - Core dependencies: `pydantic`, `torch>=1.10.0`, `transformers>=4.38.0`, `numpy`
 - Platform-specific: `triton` (Linux x86_64 only)
 
 **URLs**:

 
 - Homepage: [https://xgrammar.mlc.ai/](https://xgrammar.mlc.ai/)
 - GitHub: [https://github.com/mlc-ai/xgrammar](https://github.com/mlc-ai/xgrammar)
 
 
### Conda-Forge Distribution

 **Installation**: `conda install xgrammar -c conda-forge`

 Conda-Forge packages are typically updated after PyPI releases through a separate feedstock repository that mirrors the version from PyPI.

## Release Checklist

 When creating a new release, follow this checklist:

 
### Pre-Release

 
 - Ensure all tests pass on main branch
 - Run pre-commit hooks: `pre-commit run -a`
 - Update CHANGELOG/release notes (if maintained)
 - Verify version follows semantic versioning
 - Check that dependencies are current
 
 
### Version Update

 
 - Update version in [pyproject.toml3](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L3-L3)
 - Commit version change: `git commit -m "Bump version to X.Y.Z"`
 - Push to main: `git push origin main`
 
 
### Release Execution

 
 - Run release script: `./scripts/release_new_version.sh X.Y.Z`
 - Verify tag created: `git tag -l`
 - Verify tag pushed to GitHub: Check repository tags
 
 
### Post-Release

 
 - Monitor CI/CD build status
 - Verify wheels published to PyPI
 - Test installation: `pip install xgrammar==X.Y.Z`
 - Update Conda-Forge feedstock (if not automated)
 - Announce release (if applicable)

## Summary

 The XGrammar release process is streamlined through:

 
 - **Single Source of Truth**: Version maintained in [pyproject.toml3](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L3-L3)
 - **Automated Tagging**: Shell script handles Git operations
 - **Multi-Platform Builds**: `cibuildwheel` generates platform-specific wheels
 - **Quality Assurance**: Pre-commit hooks and test suites ensure quality
 - **Wide Distribution**: PyPI and Conda-Forge reach diverse user bases
 
 The combination of manual version updates with automated build and distribution ensures releases are both controlled and reproducible across all supported platforms.
