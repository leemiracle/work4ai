# EBNF Parser and Grammar Construction

  Relevant source files 
 - [cpp/grammar_parser.cc](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/grammar_parser.cc)

  This document describes the EBNF parser implementation that converts Extended Backus-Naur Form (EBNF) grammar strings into internal `Grammar` objects. The parser is implemented in C++ and consists of two main components: the lexer for tokenization and the parser for syntax analysis and grammar construction.

 For information about the internal `Grammar` representation created by this parser, see [Grammar Representation](https://deepwiki.com/mlc-ai/xgrammar/2.1-grammar-representation). For details about grammar optimization passes applied after parsing, see [Grammar Optimization Passes](https://deepwiki.com/mlc-ai/xgrammar/7.2-grammar-optimization-passes). For JSON Schema conversion which generates EBNF internally, see [JSON Schema Converter Deep Dive](https://deepwiki.com/mlc-ai/xgrammar/5-json-schema-converter-deep-dive).

 
## Architecture Overview

 The EBNF parser follows a classic two-phase compilation architecture: lexical analysis (tokenization) followed by syntax analysis (parsing). The parser uses recursive descent parsing to build an abstract syntax tree that is directly translated into the internal Grammar representation via `GrammarBuilder`.

### Tokenization Process

 The `Tokenize()` method is the main entry point that processes the entire input string:

 
 - Initialize cursor position to start of input
 - Repeatedly call `NextToken()` until `EndOfFile`
 - Post-process tokens to identify rule names (identifiers before `::=`)
 - Return vector of tokens
 
 **String Literal Tokenization**

 String literals support escape sequences including:

 
 - Standard escapes: `\n`, `\t`, `\r`, `\"`, `\\`
 - Unicode escapes: `\uXXXX`, `\UXXXXXXXX`
 - UTF-8 sequences are parsed using `ParseNextUTF8OrEscaped()`
 
 The lexer converts escape sequences to their actual codepoints and stores both the original lexeme and the decoded UTF-8 string value.

## Quantifier Handling

 The parser transforms quantifiers into equivalent recursive rules or optimized forms.

 **Quantifier Transformation Strategies**

 
```

```

 
### Star Quantifier (`*`)

 For character classes, the parser creates an optimized `CharacterClassStar` expression type. For other expressions, it creates a left-recursive rule:

 
```
expr*  →  rule ::= "" | expr rule
```

### Plus Quantifier (`+`)

 Creates a left-recursive rule that requires at least one match:

 
```
expr+  →  rule ::= expr rule | expr
```

### Question Quantifier (`?`)

 Creates a choice between the expression and empty string:

 
```

```

### Repetition Range (`{n,m}`)

 The `HandleRepetitionRange()` method implements an adaptive strategy based on the range size:

 **Repetition Range Strategy Decision Tree**

 
```

```

 **Small Ranges (Legacy Strategy)**

 For `{n}`: Unrolls to `expr expr ... expr` (n times)

 For `{n,}`: Creates `expr expr ... expr rest` where `rest ::= "" | expr rest`

 For `{n,m}` where m-n is small: Creates a chain of rules:

 
```
expr{2,4} → expr expr rest1
rest1 ::= "" | expr rest2
rest2 ::= "" | expr
```

 **Large Ranges (Optimized Strategy)**

 For large ranges, uses the `AddRepeat()` builder method with lookahead hints to enable optimization during compilation:

 
```
expr{200,1000} → repeat_rule{72,872} expr × 128
repeat_rule ::= expr (=(expr × 128))
```

## Example: Parsing Walkthrough

 Consider parsing the EBNF: `root ::= [a-z]+ "!"`

 **Tokenization Phase**

 
```
Token 1: RuleName "root"
Token 2: Assign "::="
Token 3: LBracket "["
Token 4: CharInCharClass "a"
Token 5: Dash "-"
Token 6: CharInCharClass "z"
Token 7: RBracket "]"
Token 8: Plus "+"
Token 9: StringLiteral "!"
Token 10: EndOfFile
```

 **Parsing Phase**

 
 - `InitRuleNames()`: Registers "root" rule with empty body
 - `ParseRule()`: Begins parsing root rule
 - `ParseChoices()`: No `|`, delegates to `ParseSequence()`
 - `ParseSequence()`: Parses elements until end of rule 
 - `ParseElementWithQuantifier()`: 
 - `ParseElement()` → `ParseCharClass()` → returns expr_id for `[a-z]`
 - Sees `Plus` token → `HandlePlusQuantifier()` 
 - Creates new rule: `root_1 ::= [a-z] root_1 | [a-z]`
 - Returns reference to `root_1`
 - `ParseElementWithQuantifier()`: 
 - `ParseElement()` → `ParseString()` → returns expr_id for `"!"`
 - No quantifier, returns string expr_id
 - `AddSequence({ref_to_root_1, string_expr})` → sequence_expr_id
 - `UpdateRuleBody("root", sequence_expr_id)`
 - `builder_.Get("root")` → final Grammar object
