## Purpose and Scope

 This document describes the `Grammar` class and its construction methods in the XGrammar Python API. The `Grammar` class represents a context-free grammar (CFG) in Extended Backus-Naur Form (EBNF) and provides multiple factory methods for creating grammars from different input formats.

 For information about compiling grammars for efficient token generation, see [Grammar Compilation](https://deepwiki.com/mlc-ai/xgrammar/2.2-grammar-compilation). For details about the EBNF parser and internal grammar representation, see [EBNF Parser and Grammar Representation](https://deepwiki.com/mlc-ai/xgrammar/5.1-converter-architecture). For JSON schema-specific features and constraints, see [JSON Schema to Grammar Conversion](https://deepwiki.com/mlc-ai/xgrammar/3-python-api-reference).

## Grammar Class Overview

 The `Grammar` class is the primary object representing a context-free grammar in XGrammar. It stores the abstract syntax tree (AST) of a grammar following the GBNF (GGML BNF) specification as defined in the llama.cpp project.

 
### Key Characteristics

 
 - **Representation**: Context-free grammar in EBNF format
 - **Specification**: Follows GBNF format from llama.cpp
 - **Storage**: Immutable grammar AST with rules and grammar expressions
 - **Display**: Converts to EBNF string representation when printed
 
 The class is implemented using the Pimpl (Pointer to Implementation) pattern, where the Python `Grammar` object wraps a C++ `Grammar::Impl` object exposed through nanobind bindings.

 **Sources:** [python/xgrammar/grammar.py132-142](https://github.com/mlc-ai/xgrammar/blob/c30554f7/python/xgrammar/grammar.py#L132-L142) [include/xgrammar/grammar.h79-78](https://github.com/mlc-ai/xgrammar/blob/c30554f7/include/xgrammar/grammar.h#L79-L78)

## Implementation Notes

 
### Memory Management

 
 - `Grammar` objects use shared ownership via `std::shared_ptr<Grammar::Impl>` in C++
 - Python `Grammar` objects maintain reference to C++ handle through nanobind
 - Copy operations create new Python objects but share underlying C++ implementation
 
 
### Normalization

 
 - EBNF-based construction methods apply `GrammarNormalizer` [cpp/grammar.cc39](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/grammar.cc#L39-L39)
 - Normalization simplifies grammar structure for efficient compilation
 - Structural tag grammars bypass normalization
 
 
### Error Handling

 
 - Construction methods raise `RuntimeError` in Python for parsing errors
 - C++ uses `std::variant<Grammar, Error>` for type-safe error handling
 - `FromStructuralTag()` returns `std::variant<Grammar, StructuralTagError>` [include/xgrammar/grammar.h135-137](https://github.com/mlc-ai/xgrammar/blob/c30554f7/include/xgrammar/grammar.h#L135-L137)
