  This document describes the memory-efficient data structures used throughout the xgrammar system to minimize memory footprint while maintaining high performance. These structures are fundamental to the system's ability to handle large grammars and vocabularies efficiently.

 For information about the caching strategies that leverage these structures, see [Multi-Level Caching Strategy](https://deepwiki.com/mlc-ai/xgrammar/9.1-multi-level-caching-strategy). For details on parallel processing using thread pools, see [Multi-threaded Compilation and Matching](https://deepwiki.com/mlc-ai/xgrammar/9.2-multi-threaded-compilation-and-matching).

 
## Purpose and Scope

 The xgrammar system processes large grammars with thousands of rules and vocabularies with tens of thousands of tokens. To maintain reasonable memory usage while achieving high performance, the system employs several specialized data structures:

 
 - **DynamicBitset**: A runtime-sized bitset for efficient boolean array storage
 - **Compact2DArray**: A contiguous 2D array structure for cache-friendly access
 - **CompactFSM**: An immutable, compact representation of finite state machines
 - **CSR-Style Grammar Storage**: Compressed storage for grammar expressions
 - **Adaptive Storage**: Dynamic selection of storage format based on data characteristics
 
 These structures enable the system to scale to production workloads while keeping memory consumption under control.

## CSR-Style Grammar Storage

 Grammar expressions are stored using a Compressed Sparse Row (CSR) matrix style, where all expression data is stored consecutively in a single vector with an index pointer vector.

 
### Storage Layout

 
```

```

 **Sources:** [cpp/grammar_impl.h56-68](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/grammar_impl.h#L56-L68) [cpp/grammar_impl.h156-168](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/grammar_impl.h#L156-L168)

 
### GrammarExpr Format

 Each `GrammarExpr` is encoded as:

 
 - **Type** (1 int32_t): `GrammarExprType` enum value
 - **Length** (1 int32_t): Number of data elements
 - **Data** (variable length): Type-specific int32_t array
 
 
| GrammarExprType | Data Format | Example |
|---|---|---|
| kByteString | [byte0, byte1, ...] | "hello" → [104, 101, 108, 108, 111] |
| kCharacterClass | [is_negative, lower0, upper0, ...] | [a-z] → [0, 97, 122] |
| kRuleRef | [rule_id] | Reference to rule 5 → [5] |
| kSequence | [expr_id0, expr_id1, ...] | Sequence of 3 exprs → [10, 11, 12] |
| kChoices | [expr_id0, expr_id1, ...] | Choice of 2 exprs → [20, 21] |

 **Sources:** [cpp/grammar_impl.h107-130](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/grammar_impl.h#L107-L130)

 
### Memory Benefits

 The CSR-style storage provides several advantages:

 **Spatial Locality:** Related grammar expressions are stored close together in memory, improving cache performance during traversal.

 **Single Allocation:** Instead of allocating memory for each expression individually, all expressions share a single contiguous buffer.

 **Reference by Index:** Grammar expressions reference each other by integer IDs rather than pointers, making the structure serializable and reducing memory overhead.

 **Variable Length Support:** Each expression can have arbitrary length without padding waste.

 **Sources:** [cpp/grammar_impl.h252-261](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/grammar_impl.h#L252-L261)

## Adaptive Storage in Token Masks

 The `AdaptiveTokenMask` class dynamically selects the most memory-efficient storage format based on the characteristics of the accepted/rejected token sets.

 
### Storage Types

 
```

```

 **Sources:** [cpp/compiled_grammar_impl.h84-137](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/compiled_grammar_impl.h#L84-L137)

 
### Storage Type Selection

 The system uses a threshold-based approach to determine the optimal storage format:

 **Threshold Constant:**

 
```
AdaptiveTokenMask::USE_BITSET_THRESHOLD
```

 **Selection Logic:**

 
 - If `|accepted_indices| < threshold`: Use `kAccepted` (vector of indices)
 - If `|rejected_indices| < threshold`: Use `kRejected` (vector of indices)
 - If both exceed threshold: Use `kAcceptedBitset` (bitset representation)
 
 **Sources:** [cpp/compiled_grammar_impl.h89](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/compiled_grammar_impl.h#L89-L89)

## Performance Implications

 The memory-efficient data structures provide several performance benefits beyond just reducing memory usage:

 
### Cache Performance

 **Contiguous Storage:** `CompactFSM` and CSR-style grammar storage improve CPU cache hit rates by storing related data consecutively.

 **Reduced Pointer Chasing:** Using integer indices instead of pointers reduces memory indirection and improves prefetching.

 
### Allocation Efficiency

 **Single Allocations:** CSR-style storage and `Compact2DArray` perform one large allocation instead of many small ones, reducing allocator overhead and fragmentation.

 **Move Semantics:** `DynamicBitset` and other structures support efficient move operations, avoiding unnecessary copies.

 
### Traversal Optimization

 **Sorted Edges:** `CompactFSM` sorts edges to enable early loop termination during traversal.

 **Block Operations:** `DynamicBitset` uses 32-bit block operations for `Set()`, `Reset()`, and other operations instead of bit-by-bit manipulation.

## Summary

 The xgrammar system employs several memory-efficient data structures to achieve production-scale performance:

 
 - **DynamicBitset**: Flexible bitset with internal/external buffer modes
 - **Compact2DArray & CompactFSM**: Contiguous FSM storage for cache efficiency
 - **CSR-Style Grammar Storage**: Compressed grammar expression storage
 - **Adaptive Token Masks**: Dynamic storage format selection based on data characteristics
 
 These structures work together to minimize memory footprint while maintaining high performance, enabling the system to handle large vocabularies and complex grammars efficiently.
