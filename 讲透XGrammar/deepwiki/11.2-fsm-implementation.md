  This document describes the C++ implementation of finite state machines (FSMs) in xgrammar. FSMs are the core data structure used to represent grammar rules during matching and token validation. For the higher-level compilation process that builds FSMs from grammars, see [Grammar Processing Pipeline](https://deepwiki.com/mlc-ai/xgrammar/7-grammar-processing-pipeline). For the runtime usage of FSMs in token matching, see [GrammarMatcher Internal Architecture](https://deepwiki.com/mlc-ai/xgrammar/11.3-grammarmatcher-internal-architecture).

## Overview

 The FSM implementation provides three main classes:

 
 - **`FSM`**: A mutable finite state machine for construction and manipulation
 - **`CompactFSM`**: An immutable, memory-efficient representation for runtime use
 - **`FSMWithStartEnd`/`CompactFSMWithStartEnd`**: Wrapper classes that add start and accepting states to FSMs
 
 FSMs can represent both deterministic finite automata (DFA) and non-deterministic finite automata (NFA) with epsilon transitions. The implementation supports various edge types including character ranges, rule references, and repetition constructs.

## FSMEdge Structure

 The `FSMEdge` structure represents a transition between states in the FSM. It uses a compact 8-byte representation with tagged unions for different edge types.

 
### Edge Data Layout

 
| Field | Type | Size | Description |
|---|---|---|---|
| min | int16_t | 2 bytes | Type tag or range minimum |
| max | int16_t | 2 bytes | Range maximum or auxiliary index |
| target | int32_t | 4 bytes | Target state ID |

 
### Edge Types

 
```

```

 **Character Range Edges**: When `min >= 0`, the edge accepts any character (byte value) in the range `[min, max]`. This is the most common edge type, used to match literal characters and character classes.

 **Epsilon Edges**: Enable NFA construction by allowing state transitions without consuming input. Used during FSM building and removed during DFA conversion via epsilon closure computation.

 **Rule Reference Edges**: Allow one FSM to reference another rule's FSM. The `max` field stores the referenced rule ID. These edges are resolved during grammar matching.

 **EOS Edges**: Match the end-of-string token, used to mark completion points in the grammar.

 **Repeat Reference Edges**: Represent repetition constructs like `{min, max}` in EBNF. The `max` field is an index into the `edge_aux_data_` vector, which stores `[rule_id, lower, upper]` as three consecutive `int32_t` values.

## FSM Traversal Operations

 FSMs support various traversal operations for both NFA and DFA usage patterns.

 
### Single-Step Traversal

 
```

```

 Returns the first target state reachable from `from` by consuming `value` (or `-1` if no transition exists). Used primarily for DFA traversal where each state has at most one outgoing edge per input symbol.

 **Implementation**: Linear search through edges of `from` state, returning the first matching edge's target ([cpp/fsm.cc257-289](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/fsm.cc#L257-L289)).

 
### Multi-State Traversal (NFA)

 
```

```

 Computes the set of reachable states from a set of source states. This method:

 
 - Computes epsilon closure of `from` if `from_is_closure` is false
 - Finds all states reachable via edges matching `value` and `edge_type`
 - Computes epsilon closure of the result
 - Stores final state set in `result`
 
 Used for NFA simulation during FSM construction and DFA conversion.

 Sources: [cpp/fsm.cc257-351](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/fsm.cc#L257-L351)

 
### Epsilon Closure

 
```

```

 Computes the transitive closure of epsilon transitions using breadth-first search. All states reachable from the input set via epsilon edges are added to `state_set`.

 **Algorithm**:

 
 - Initialize queue with states in `state_set`
 - For each state in queue, examine epsilon edges
 - Add unvisited targets to both `state_set` and queue
 - Continue until queue is empty

### Rebuilding with State Mapping

 
```

```

 Creates a new FSM with remapped state IDs. This is the core operation used in DFA minimization, where equivalent states are merged.

 **Process**:

 
 - Create new edge vectors of size `new_num_states`
 - For each edge `(from, target)`, add edge `(state_mapping[from], state_mapping[target])`
 - Skip self-loop epsilon edges
 - Remove duplicate edges per state
 - Preserve `edge_aux_data_` (indices remain valid)

## CompactFSM: Memory-Efficient Representation

 `CompactFSM` uses `Compact2DArray<FSMEdge>` to store edges in a contiguous memory block, reducing memory overhead and improving cache locality.

 
### Memory Layout Comparison

 
| Structure | Storage | Overhead per State | Random Access |
|---|---|---|---|
| FSM | vector<vector<FSMEdge>> | 24 bytes (vector header) | O(1) |
| CompactFSM | Compact2DArray<FSMEdge> | 4 bytes (offset) | O(1) |

 
### CompactFSM Operations

 
```

```

 **Read-Only Access**: `CompactFSM` provides the same traversal methods as `FSM` but cannot be modified after construction.

 **Conversion**: The `ToFSM()` method creates a mutable copy, enabling further transformations if needed.

## Usage in Grammar Compilation

 FSMs are constructed and used throughout the grammar compilation pipeline:

 
### Construction Phase

 
 - **`GrammarFSMBuilder::CharacterClass()`**: Builds FSM for character classes like `[a-z]`
 - **`GrammarFSMBuilder::ByteString()`**: Builds linear FSM for byte sequences
 - **`GrammarFSMBuilder::Sequence()`**: Concatenates FSMs
 - **`GrammarFSMBuilder::Choices()`**: Creates union of FSMs
 - **`GrammarFSMBuilder::RuleRef()`**: Adds rule reference edges
 
 
### Optimization Phase

 
 - **Subset Construction**: Converts NFA to DFA for deterministic matching
 - **Hopcroft's Algorithm**: Minimizes DFA by merging equivalent states
 - **Edge Sorting**: Prepares for binary search in `CompactFSM`
 - **Compaction**: Converts to `CompactFSM` for memory efficiency
 
 
### Storage in Grammar

 
```

```

 Each rule can optionally have its own FSM stored in `per_rule_fsms[rule_id]`. If present, the FSM is used directly during matching; otherwise, the rule's body expression is interpreted.

## Memory Footprint

 The FSM implementation is designed for memory efficiency:

 
| Component | Memory per State (avg) | Notes |
|---|---|---|
| FSM edges | 24 bytes + edges | Vector overhead |
| CompactFSM edges | 4 bytes + edges | Compact array offset |
| FSMEdge | 8 bytes | Packed structure |
| Auxiliary data | 12 bytes per repeat | Shared across states |

 **Example**: A grammar with 100 rules, each with an average of 50 states and 100 edges per state:

 
 - FSM: ~100 * 50 * (24 + 100*8) ≈ 4.1 MB
 - CompactFSM: ~100 * 50 * (4 + 100*8) ≈ 4.0 MB
 
 The memory savings become more significant with larger grammars or when caching multiple compiled grammars.
