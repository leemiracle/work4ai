## Purpose and Scope

 This document describes the multi-threading capabilities in xgrammar for parallel grammar compilation and batch matching operations. xgrammar uses thread pools to accelerate batch processing of multiple grammar matchers simultaneously, enabling efficient inference for multiple sequences.

 For information about caching strategies that complement threading, see [Multi-Level Caching Strategy](https://deepwiki.com/mlc-ai/xgrammar/9.1-multi-level-caching-strategy). For memory optimization techniques, see [Memory-Efficient Data Structures](https://deepwiki.com/mlc-ai/xgrammar/9.3-memory-efficient-data-structures).

 
---

 
## Overview

 xgrammar provides multi-threading support primarily for **batch matching operations**, where multiple `GrammarMatcher` instances process tokens in parallel. This is particularly useful when running inference on multiple sequences simultaneously, such as in batched LLM generation.

 The threading infrastructure is implemented through:

 
 - `BatchGrammarMatcher` class for coordinating parallel matching operations
 - Configurable thread pool with automatic hardware detection
 - Thread-safe batch operations for token acceptance and bitmask generation

## Performance Considerations

 
### Thread Count Selection

 The optimal thread count depends on workload characteristics:

 
| Scenario | Recommended Configuration | Rationale |
|---|---|---|
| High batch size (>= hardware threads) | "auto" or explicit count | Maximizes parallelism |
| Small batch size (< 4) | 1 or small value | Avoids thread overhead |
| CPU-bound workload | hardware_concurrency() | Full CPU utilization |
| Mixed CPU/IO workload | hardware_concurrency() / 2 | Avoids oversubscription |

### Thread Safety

 Each `GrammarMatcher` instance operates independently during batch operations, ensuring thread safety:

 
 - **No shared state**: Each matcher maintains its own parser state
 - **Separate memory regions**: Bitmask writes target different indices
 - **Static methods**: `BatchAcceptToken` and `BatchAcceptString` are static, ensuring no shared instance state
 
 The thread pool itself handles synchronization internally, allowing safe parallel execution.

## Summary

 Multi-threading in xgrammar is designed for batch inference scenarios:

 
| Component | Threading Model | Key Classes |
|---|---|---|
| Batch Matching | Parallel via ThreadPool | BatchGrammarMatcher::Impl |
| Individual Matching | Single-threaded | GrammarMatcher::Impl |
| Thread Configuration | Automatic or explicit | Constructor with max_threads parameter |

 The threading infrastructure enables efficient parallel processing of multiple grammar matchers, with automatic hardware detection and configurable thread counts to optimize performance across different deployment scenarios.
