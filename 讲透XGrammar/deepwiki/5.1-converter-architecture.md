For information about specific JSON schema features supported (types, constraints, formatting), see [Supported JSON Schema Features](https://deepwiki.com/mlc-ai/xgrammar/5.2-supported-json-schema-features). ## Purpose and Scope

 The converter architecture implements a two-stage pipeline transforming JSON schemas into EBNF grammar strings:

 **Stage 1 - Parsing**: `SchemaParser` converts `picojson::value` (JSON AST) into `SchemaSpec` intermediate representation **Stage 2 - Generation**: `JSONSchemaConverter` converts `SchemaSpec` into EBNF grammar strings via `EBNFScriptCreator`

 This separation enables:

 
 - **Extensibility**: New output formats (e.g., XML-style tool calling) can reuse `SchemaParser`
 - **Deduplication**: Multiple schemas with identical structure share one `SchemaSpec` instance
 - **Circular references**: Forward declarations through `RefSpec` and `ref_cache_` enable recursive schemas

### Parsing Process

 The parser implements recursive descent with multi-level caching:

 
#### 1. Cache Key Computation ([cpp/json_schema_converter.cc198-244](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/json_schema_converter.cc#L198-L244))

 `ComputeCacheKey()` generates canonical string keys by:

 
 - Serializing schema to JSON with sorted keys
 - Excluding non-semantic fields: `title`, `default`, `description`, `examples`, `deprecated`, `readOnly`, `writeOnly`, `$comment`, `$schema` (see `kSkippedKeys` at line 199)
 - Recursively computing keys for nested schemas (arrays, objects)
 
 **Example:**

 
```
Input:  {"type": "integer", "title": "Age", "minimum": 0, "description": "User age"}
Output: {"minimum":0,"type":"integer"}
```

 Avoids re-parsing structurally identical schemas even if they have different descriptions/titles.

 
#### 3. Type Dispatch ([cpp/json_schema_converter.cc294-372](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/json_schema_converter.cc#L294-L372))

 Dispatch order (checked sequentially):

 
 - `$ref` → `ParseRef()` + `ResolveRef()`
 - `const` → `ParseConst()`
 - `enum` → `ParseEnum()`
 - `anyOf` / `oneOf` → `ParseAnyOf()`
 - `allOf` → `ParseAllOf()`
 - `type` (string) → dispatch to type-specific parser
 - `type` (array) → `ParseTypeArray()`
 - `properties` / `additionalProperties` / `unevaluatedProperties` → `ParseObject()` (inferred type)
 - `items` / `prefixItems` / `unevaluatedItems` → `ParseArray()` (inferred type)
 - Default → `AnySpec`
 
 
#### 4. Recursive Parsing

 Complex types recursively call `Parse()`:

 
 - **ArraySpec**: Calls `Parse()` for each `prefix_items` element and `additional_items` ([cc569-588](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cc#L569-L588))
 - **ObjectSpec**: Calls `Parse()` for each property, pattern property, additional properties schema ([cc682-684](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cc#L682-L684) [cc705-707](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cc#L705-L707) [cc737-739](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cc#L737-L739))
 - **AnyOfSpec**: Calls `Parse()` for each option ([cc898-901](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cc#L898-L901))
 - **AllOfSpec**: Calls `Parse()` for each schema ([cc913-916](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cc#L913-L916))

 - Generates EBNF body via `GenerateFromSpec()`
 - **Recursive Rule Generation**:
