# Cross-Platform Wheel Building

  Relevant source files 
 - [CMakeLists.txt](https://github.com/mlc-ai/xgrammar/blob/c30554f7/CMakeLists.txt)
 - [pyproject.toml](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml)
 
  This document explains the cross-platform wheel building infrastructure for xgrammar, which produces binary wheels for multiple operating systems, CPU architectures, and Python versions. The system uses `cibuildwheel` to orchestrate builds across different platforms, integrated with `scikit-build-core` to compile the C++ core library and Python bindings.

 For information about the underlying build system configuration and CMake setup, see [Build System and Configuration](https://deepwiki.com/mlc-ai/xgrammar/12.1-build-system-and-configuration). For details on project dependencies, see [Project Dependencies](https://deepwiki.com/mlc-ai/xgrammar/12.2-project-dependencies).

 
## Overview

 The xgrammar project distributes pre-compiled binary wheels that include both Python code and compiled C++ extensions. This requires building wheels for each combination of:

 
 - Operating systems: Linux, macOS, Windows
 - Architectures: x86_64, aarch64 (Linux), arm64 (macOS), AMD64 (Windows)
 - Python versions: 3.9, 3.10, 3.11, 3.12, 3.13 (with platform-specific restrictions)
 
 The build process is managed by `cibuildwheel`, which runs in CI/CD environments and locally for wheel generation.

 **Sources**: [pyproject.toml136-161](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L136-L161)

## scikit-build-core Integration

 The `scikit-build-core` package serves as the build backend, translating Python package build requests into CMake invocations:

 
### Configuration Mapping

 The following table shows how `pyproject.toml` settings map to build behavior:

 
| pyproject.toml Setting | Purpose | CMake Impact |
|---|---|---|
| tool.scikit-build.build-dir = "build" | Build directory | CMAKE_BINARY_DIR |
| tool.scikit-build.build.verbose = true | Enable verbose output | Shows compilation commands |
| tool.scikit-build.cmake.build-type = "RelWithDebInfo" | Build configuration | Sets CMAKE_BUILD_TYPE |
| tool.scikit-build.wheel.packages = ["python/xgrammar"] | Python source location | Files to include in wheel |
| tool.scikit-build.wheel.install-dir = "xgrammar" | Install destination | Where Python code goes |

## Wheel Naming Convention

 Binary wheels follow the PEP 427 naming convention:

 
```
xgrammar-{version}-{python}-{abi}-{platform}.whl
```

 Examples:

 
 - `xgrammar-0.1.32-cp311-cp311-manylinux_2_17_x86_64.manylinux2014_x86_64.whl` (Linux x86_64, Python 3.11)
 - `xgrammar-0.1.32-cp312-cp312-macosx_11_0_arm64.whl` (macOS ARM64, Python 3.12)
 - `xgrammar-0.1.32-cp310-cp310-win_amd64.whl` (Windows AMD64, Python 3.10)
 
 The platform tags indicate:

 
 - **manylinux**: Linux compatibility level (manylinux2014 = compatible with glibc 2.17+)
 - **macosx_11_0**: Minimum macOS version (though MACOSX_DEPLOYMENT_TARGET may be lower)
 - **win_amd64**: Windows 64-bit
 
 **Sources**: [pyproject.toml1-3](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L1-L3)

## Platform-Specific Build Requirements

 Each platform has specific build requirements:

 
### Linux

 
 - **Compiler**: GCC or Clang (provided by manylinux container)
 - **C++ Standard**: C++17
 - **glibc version**: 2.17+ (manylinux2014)
 - **Architecture support**: x86_64, aarch64
 
 
### macOS

 
 - **Compiler**: Apple Clang (from Xcode Command Line Tools)
 - **Minimum OS**: macOS 10.14 (Mojave)
 - **Architecture support**: x86_64, arm64 (Apple Silicon)
 - **Universal binaries**: Not currently built; separate wheels for each architecture
 
 
### Windows

 
 - **Compiler**: MSVC (Visual Studio 2017 or later)
 - **Architecture support**: AMD64 (x86-64)
 - **Runtime**: Static linking with MSVC runtime
