## Purpose and Scope

 This page documents the Finite State Machine (FSM) generation system in xgrammar, which converts grammar expressions into efficient automata for pattern matching. The FSM generation is a critical component of the compilation pipeline that transforms high-level grammar rules into low-level state machines optimized for token validation.

 For information about the grammar optimization passes that precede FSM generation, see [Grammar Optimization Passes](https://deepwiki.com/mlc-ai/xgrammar/7.2-grammar-optimization-passes). For details on how these FSMs are used during runtime matching, see [Earley Parser Implementation](https://deepwiki.com/mlc-ai/xgrammar/8.1-earley-parser-implementation).

## FSM Data Structures

 
### FSMEdge: Edge Representation

 `FSMEdge` is the fundamental building block representing transitions between states. It uses a compact 8-byte structure:

 
```

```

 
| Edge Type | min Value | max Value | Meaning |
|---|---|---|---|
| Character Range | ≥ 0 | character code | Accepts characters in range [min, max] |
| Epsilon | -1 | (ignored) | Epsilon transition (no input consumed) |
| Rule Reference | -2 | rule_id | Reference to another rule |
| EOS | -3 | (ignored) | End-of-string marker |
| Repeat Reference | -4 | aux_index | Reference to auxiliary data for repeat bounds |

 Sources: [cpp/fsm.h30-156](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/fsm.h#L30-L156)

 
### FSM vs CompactFSM

 The system maintains two FSM representations for different use cases:

 
```

```

 **FSM** (`FSM::Impl` in [cpp/fsm.cc191-255](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/fsm.cc#L191-L255)):

 
 - Mutable: supports `AddState()`, `AddEdge()`, `AddEpsilonEdge()`, etc.
 - Uses `std::vector<std::vector<FSMEdge>>` for flexible construction
 - Used during NFA construction and DFA operations
 
 **CompactFSM** (`CompactFSM::Impl` in [cpp/fsm.cc257-339](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/fsm.cc#L257-L339)):

 
 - Immutable: cannot be modified after creation
 - Uses `Compact2DArray<FSMEdge>` for memory efficiency and cache locality
 - Edges are sorted by (min, max, target) for binary search
 - Used for final storage in `Grammar::Impl::per_rule_fsms`

### Key Construction Methods

 
#### ByteString Construction

 Converts a sequence of bytes into a linear FSM:

 
```
"abc" → (s0) --'a'--> (s1) --'b'--> (s2) --'c'--> (s3)
```

 Implementation: [cpp/grammar_functor.cc1088-1118](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/grammar_functor.cc#L1088-L1118)

 
#### CharacterClass Construction

 Handles character ranges with Unicode support through packed UTF-8:

 
```
[a-z] → (s0) --[97-122]--> (s1)
[^a-z] → (s0) --[0-96],[123-255]--> (s1)
```

 For Unicode characters, the system uses `CodepointToPackedUTF8()` [cpp/grammar_functor.cc965-992](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/grammar_functor.cc#L965-L992) to convert Unicode codepoints to packed byte sequences.

 Sources: [cpp/grammar_functor.cc1006-1086](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/grammar_functor.cc#L1006-L1086)

 
#### Sequence Construction (Concatenation)

 Concatenates multiple FSMs by connecting the end states of one to the start state of the next:

 
```
FSM1: (s0) --> (s1)    FSM2: (s2) --> (s3)
Concat: (s0) --> (s1) --epsilon--> (s2) --> (s3)
```

 Implementation: [cpp/grammar_functor.cc1120-1198](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/grammar_functor.cc#L1120-L1198)

 
#### Choices Construction (Union)

 Creates an NFA that accepts any of the choice expressions using epsilon transitions:

 
```
--epsilon--> FSM1 --epsilon-->
(start)                                  (end)
        --epsilon--> FSM2 --epsilon-->
```

 Implementation: [cpp/grammar_functor.cc1200-1275](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/grammar_functor.cc#L1200-L1275)

### Implementation Details

 The `ToDFA()` function [cpp/fsm.cc815-1141](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/fsm.cc#L815-L1141) implements subset construction with optimizations:

 
 - **Epsilon Closure Computation**: [cpp/fsm.cc134-154](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/fsm.cc#L134-L154)

 
 - BFS traversal of epsilon edges
 - Cached closures for performance
 - **State Set Management**:

 
 - Uses `std::unordered_set<int>` to represent DFA states
 - Maps NFA state sets to DFA state IDs using hash maps
 - **Transition Computation**:

 
 - For each input value (character, rule reference, etc.)
 - Advances all NFA states in the current set
 - Computes epsilon closure of target states
 - Creates new DFA state if state set is novel
 - **Edge Type Handling**:

 
 - Character ranges: merged and optimized
 - Rule references: preserved as-is
 - EOS transitions: handled separately
 - Repeat references: special processing

 The `MinimizeDFA()` function [cpp/fsm.cc1143-1391](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/fsm.cc#L1143-L1391) implements Hopcroft's algorithm:

 
 - **Initial Partitioning**: [cpp/fsm.cc1159-1185](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/fsm.cc#L1159-L1185)

 
 - Separate accepting from non-accepting states
 - Use `UnionFindSet` for efficient partition management
 - **Partition Refinement**: [cpp/fsm.cc1187-1332](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/fsm.cc#L1187-L1332)

 
 - For each partition in worklist
 - For each possible input symbol
 - Split partitions based on which states have transitions to the current partition
 - Add new partitions to worklist
 - **Final DFA Construction**: [cpp/fsm.cc1334-1391](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/fsm.cc#L1334-L1391)

 
 - Map old states to representative states in each partition
 - Build new FSM with merged states
 - Preserve start and end state information
 
 
### Complexity Optimization

 The implementation uses several optimizations:

 
 - **Inverse Edge Maps**: Precompute inverse transitions for O(1) predecessor lookup
 - **Smallest-First**: Always process the smaller partition to minimize work
 - **Edge Grouping**: Process edges by type (character, rule ref, etc.) separately

## Performance Characteristics

 
| Operation | Time Complexity | Space Complexity | Notes |
|---|---|---|---|
| NFA Construction | O(n) | O(n) | n = expression size |
| Subset Construction (NFA→DFA) | O(2^n) worst | O(2^n) worst | n = NFA states; typically much better |
| DFA Minimization (Hopcroft) | O(n log n) | O(n) | n = DFA states |
| FSM Traversal | O(1) per edge | - | Sorted edges enable binary search |
| Unicode Character Matching | O(k) | O(k) | k = UTF-8 byte length (1-4) |

 The use of `CompactFSM` with sorted edges and memory-contiguous storage significantly improves cache performance during runtime matching.
