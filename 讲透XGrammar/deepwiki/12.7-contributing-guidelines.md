## Development Environment Setup

 
### Prerequisites

 The xgrammar project requires Python 3.8+ and a C++17 compiler. Core dependencies are defined in [pyproject.toml17-24](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L17-L24):

 
| Dependency | Purpose | Platform Notes |
|---|---|---|
| pydantic | Schema validation | All platforms |
| torch>=1.10.0 | Tensor operations | All platforms |
| transformers>=4.38.0 | Tokenizer integration | Version capped on macOS |
| triton | GPU kernels | Linux x86_64 only |
| numpy | Array operations | All platforms |
| typing-extensions>=4.9.0 | Type hints | All platforms |

 Additional test dependencies are listed under `[project.optional-dependencies]` at [pyproject.toml31-40](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L31-L40)

 Sources: [pyproject.toml17-40](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L17-L40)

### Python Code Standards

 Python code formatting is handled by **black** with a 100-character line length limit [pyproject.toml124-127](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L124-L127) Import sorting is managed by **isort** configured to use the black profile [pyproject.toml129-134](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L129-L134)

 **Ruff** is the primary linter, configured to check:

 
 - `C`: Convention violations
 - `E`: Errors (except E501 for line length)
 - `F`: Fatal errors (except F402, F823)
 - `W`: Warnings
 
 The configuration ignores complexity checks (C901) and certain error types, as specified at [pyproject.toml112-115](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L112-L115)

 **MyPy** enforces strict type checking with the `strict = true` setting [pyproject.toml106-107](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L106-L107) All Python code should include type annotations.

 Sources: [pyproject.toml106-134](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L106-L134)

 
### C++ Code Standards

 C++ code follows strict formatting rules enforced by **clang-format** version 19.1.7 [.pre-commit-config.yaml52-58](https://github.com/mlc-ai/xgrammar/blob/c30554f7/.pre-commit-config.yaml#L52-L58) The build system enforces comprehensive compiler warnings:

 
 - `-Wall -Wextra -Werror`: Treat all warnings as errors
 - `-Wno-pedantic`: Allow non-standard extensions
 - `-Wno-unused-parameter`: Suppress unused parameter warnings
 - `-Woverloaded-virtual`: Warn about hidden virtual functions
 
 Platform-specific adjustments are made for RISC-V and PowerPC architectures at [CMakeLists.txt54-70](https://github.com/mlc-ai/xgrammar/blob/c30554f7/CMakeLists.txt#L54-L70)

 Sources: [CMakeLists.txt48-71](https://github.com/mlc-ai/xgrammar/blob/c30554f7/CMakeLists.txt#L48-L71) [.pre-commit-config.yaml52-58](https://github.com/mlc-ai/xgrammar/blob/c30554f7/.pre-commit-config.yaml#L52-L58)

## Pull Request Process

 
### Before Submitting a PR

 
```

```

 **Diagram: Pull Request Workflow**

 Before submitting a pull request:

 
 - **Ensure all pre-commit hooks pass**: Run `pre-commit run -a` to check formatting
 - **Run the test suite**: Execute `pytest tests` to verify functionality
 - **Check type annotations**: Run `mypy` on modified Python files
 - **Update documentation**: Add docstrings and update relevant wiki pages if needed
 - **Write clear commit messages**: Use descriptive commit messages explaining the change
 
 Sources: [.pre-commit-config.yaml1-76](https://github.com/mlc-ai/xgrammar/blob/c30554f7/.pre-commit-config.yaml#L1-L76) [pyproject.toml101-104](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L101-L104)

 
### PR Guidelines

 
 - **Scope**: Keep PRs focused on a single feature or bug fix
 - **Description**: Clearly describe what the PR changes and why
 - **Tests**: Include tests for new features or bug fixes
 - **Documentation**: Update docstrings and wiki pages as needed
 - **Breaking changes**: Clearly mark and document any breaking API changes
 
 
### CI Checks

 The CI pipeline validates:

 
 - Cross-platform wheel builds for Linux, macOS, and Windows
 - Test execution on multiple Python versions (3.9-3.13)
 - Code formatting compliance
 - Test coverage on supported architectures
 
 Wheel building is configured at [pyproject.toml136-160](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L136-L160) using **cibuildwheel**.

 Sources: [pyproject.toml136-160](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L136-L160)

## Release Process

 
### Version Management

 Version numbers are stored in [pyproject.toml3](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L3-L3) and should follow semantic versioning:

 
 - **Major version**: Incompatible API changes
 - **Minor version**: New functionality, backward compatible
 - **Patch version**: Bug fixes, backward compatible
 
 The current version is `0.1.31`, indicating the project is in beta development status as declared at [pyproject.toml10](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L10-L10)

### Wheel Building Configuration

 The project uses **cibuildwheel** to build wheels for multiple platforms and Python versions:

 
| Platform | Architectures | Python Versions |
|---|---|---|
| Linux | x86_64, aarch64 | 3.9-3.13 (excluding 3.13 on aarch64 temporarily) |
| macOS | x86_64, arm64 | 3.9-3.12 (3.13 excluded on x86_64) |
| Windows | AMD64 | 3.9-3.13 |

 The configuration explicitly skips:

 
 - Python 3.6-3.8 (end of life)
 - PyPy builds (nanobind compatibility issues)
 - musllinux builds
 - Python 3.13 on macOS x86_64 (PyTorch wheel unavailability)
 
 These exclusions are defined at [pyproject.toml141-147](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L141-L147)

 The macOS deployment target is set to 10.14 for compatibility [pyproject.toml157](https://github.com/mlc-ai/xgrammar/blob/c30554f7/pyproject.toml#L157-L157)

## Summary of Key Contribution Steps

 
 - **Setup**: Fork, clone, install dependencies with `pip install -e .[test]`
 - **Code**: Follow Python (black, isort, ruff, mypy) and C++ (clang-format) standards
 - **Test**: Run `pytest tests` and ensure all tests pass
 - **Pre-commit**: Install and run pre-commit hooks before committing
 - **PR**: Create a focused PR with clear description and documentation updates
 - **Review**: Address feedback and ensure CI checks pass
 - **Release**: Maintainers use `release_new_version.sh` to tag and publish
 
 For questions or discussions, refer to the project's GitHub repository at [https://github.com/mlc-ai/xgrammar](https://github.com/mlc-ai/xgrammar).
