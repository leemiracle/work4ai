## Pre-commit Framework Overview

 XGrammar uses the [pre-commit](https://pre-commit.com/) framework to automate code formatting and validation. Pre-commit hooks execute before git commits to ensure all code meets project standards without requiring manual intervention.

 The framework is configured via `.pre-commit-config.yaml:1-76`, which defines repositories, hooks, and their execution parameters. The configuration emphasizes **formatting over linting**: hooks automatically fix formatting issues, while linting is delegated to CI systems `.pre-commit-config.yaml:18-19`.

 
### Key Usage Commands

 
| Command | Purpose |
|---|---|
| pre-commit run | Run hooks on staged files only |
| pre-commit run -a | Run hooks on all files in repository |
| pre-commit install | Install hooks to run automatically on every commit |
| pre-commit autoupdate | Update hook versions to latest releases |

 **Sources:** `.pre-commit-config.yaml:1-16`

## Formatting vs. Linting

 XGrammar's pre-commit hooks are **strictly for formatting**, not linting `.pre-commit-config.yaml:18-19`.

 
### Formatting (Pre-commit)

 
 - **Purpose:** Automated code style normalization
 - **Execution:** Local, before commit
 - **Action:** Auto-fixes files in place
 - **Examples:** Line length, indentation, import order, whitespace
 
 
### Linting (CI Only)

 
 - **Purpose:** Static analysis, bug detection, style violations
 - **Execution:** Continuous Integration
 - **Action:** Reports issues, fails build
 - **Examples:** Unused variables, type errors, complexity checks
 
 This separation ensures:

 
 - Developers get immediate formatting feedback without blocking commits
 - CI performs comprehensive checks that may require manual fixes
 - Pre-commit remains fast and non-intrusive

## Best Practices

 
 - **Install hooks early:** Run `pre-commit install` immediately after cloning the repository
 - **Run on all files initially:** Use `pre-commit run -a` to establish baseline formatting
 - **Keep versions updated:** Periodically run `pre-commit autoupdate` and test changes
 - **Don't skip hooks:** Avoid `--no-verify` unless absolutely necessary
 - **Separate formatting commits:** When adding new formatters, create dedicated formatting commits
 - **Review auto-fixes:** Always review changes made by formatters before committing
 - **Coordinate updates:** When updating hook versions, coordinate with team to avoid merge conflicts
