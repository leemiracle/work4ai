  This document describes the three-phase pipeline that converts structural tag specifications from JSON format into executable Grammar objects. The pipeline consists of parsing, analysis, and conversion phases, each with distinct responsibilities for validation, property detection, and grammar construction.

 For information about the individual format types and their specifications, see [Format Specification](https://deepwiki.com/mlc-ai/xgrammar/6.1-format-specification). For details on the TriggeredTagsFormat mechanism used in tool calling, see [Triggered Tags and Tool Calling](https://deepwiki.com/mlc-ai/xgrammar/6.3-triggered-tags-and-tool-calling).

### Type Dispatch Mechanism

 The parser implements two dispatch strategies:

 
 - **Explicit Type Field**: When the JSON object contains a `"type"` field, the parser directly dispatches to the appropriate parser method.
 - **Implicit Type Inference**: When no `"type"` field is present, the parser attempts to parse the object as each format type sequentially, returning the first successful match. TagFormat is prioritized in this inference.
 
 Sources: [cpp/structural_tag.cc104-171](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L104-L171)

 **Unlimited Format Detection**

 The analyzer determines if a format can match unbounded input:

 
 - `AnyTextFormat`: Always unlimited
 - `TriggeredTagsFormat`: Always unlimited
 - `TagsWithSeparatorFormat`: Always unlimited
 - `SequenceFormat`: Unlimited if the last element is unlimited
 - `OrFormat`: Unlimited if all elements are unlimited
 
 Sources: [cpp/structural_tag.cc559-579](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/structural_tag.cc#L559-L579)

 **Excluded Format Detection**

 Checks if a format has explicit exclusion strings:

 
 - `AnyTextFormat`: Has excludes if `excludes` field is non-empty
 - `TriggeredTagsFormat`: Has excludes if `excludes` field is non-empty
