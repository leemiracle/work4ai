  This page documents the `xgrammar.testing` module, which provides utilities for testing, debugging, and developing grammar implementations. These APIs expose internal implementation details and transformation passes that are useful when:

 
 - Writing tests for grammar behavior
 - Debugging grammar compilation issues
 - Developing new grammar features
 - Testing individual optimization passes in isolation
 - Profiling grammar matching performance
 
 **Target Audience**: Developers working on XGrammar core implementation or users needing to debug complex grammar issues.

 **Stability Warning**: All functions in this module are marked as unstable and subject to change. The module header explicitly states: "The APIs in this module are used for testing and debugging and are prone to change. Don't use them in production." ([python/xgrammar/testing.py1-4](https://github.com/mlc-ai/xgrammar/blob/c30554f7/python/xgrammar/testing.py#L1-L4))

 For production-ready APIs, see:

 
 - [Grammar Matching and Validation](https://deepwiki.com/mlc-ai/xgrammar/3.3-grammar-matching-and-validation) - Runtime matching APIs

## Module Organization

 The `xgrammar.testing` module ([python/xgrammar/testing.py](https://github.com/mlc-ai/xgrammar/blob/c30554f7/python/xgrammar/testing.py)) provides Python wrappers around C++ testing utilities. The module is organized into functional categories:

 
| Category | Functions | Purpose |
|---|---|---|
| Format Conversion | _json_schema_to_ebnf, _regex_to_ebnf, _qwen_xml_tool_calling_to_ebnf | Test conversion logic in isolation |
| Grammar Creation | _ebnf_to_grammar_no_normalization, _get_matcher_from_grammar, _get_matcher_from_grammar_and_tokenizer_info | Create test grammars and matchers |
| Validation | _is_grammar_accept_string | Test string acceptance with timing |
| Bitmask Debug | _get_masked_tokens_from_bitmask, _is_single_token_bitmask, bool_mask_to_bitmask, bitmask_to_bool_mask | Inspect and convert bitmasks |
| Grammar Inspection | _print_grammar_fsms, _get_allow_empty_rule_ids | Examine internal grammar state |
| Regex Generation | _generate_range_regex, _generate_float_regex | Generate numeric range patterns |
| Optimization Passes | GrammarFunctor.* | Apply individual transformations |
| Speculative Decoding | _traverse_draft_tree | Test draft tree validation |

```

```

 **Algorithm** ([python/xgrammar/testing.py251-262](https://github.com/mlc-ai/xgrammar/blob/c30554f7/python/xgrammar/testing.py#L251-L262)):

## Speculative Decoding Utilities

 
### Draft Tree Traversal

 The `_traverse_draft_tree()` function performs depth-first traversal of a speculative decoding tree, filling token bitmasks at each node based on grammar constraints. This enables grammar-constrained speculative decoding where a draft model proposes multiple token candidates and a target model validates them against grammar rules.

 **Speculative Decoding Context**: In speculative decoding, a faster draft model generates multiple token candidates in parallel, forming a tree structure. The target model then validates this tree to determine which paths are grammatically valid. This function fills bitmasks for each node in the tree, allowing efficient parallel validation.

 
```

```

 **Function Signature**:

 
```

```

 **Parameters**:

 
 - `retrieve_next_token`: 1D int64 tensor where `[i]` gives the child node index of node `i`, or -1 if none
 - `retrieve_next_sibling`: 1D int64 tensor where `[i]` gives the sibling node index of node `i`, or -1 if none
 - `draft_tokens`: 1D int64 tensor of draft token IDs at each node
 - `matcher`: GrammarMatcher instance to use for validation
 - `allocate_token_bitmask`: 2D int32 tensor `[num_nodes, bitmask_size]` to store generated bitmasks
 
 **Algorithm** ([cpp/testing.cc62-119](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/testing.cc#L62-L119)):

 
 - Start DFS from root node (node 0, always accepted)
 - For each node: 
 - Check if token is accepted by testing parent's bitmask
 - If accepted: 
 - Call `matcher.AcceptToken(token_id)`
 - Fill bitmask for this node
 - Recursively visit child node
 - Rollback matcher state
 - Visit sibling node
 - Bitmasks are filled for all reachable nodes
 
 **Validation Checks** ([cpp/testing.cc130-143](https://github.com/mlc-ai/xgrammar/blob/c30554f7/cpp/testing.cc#L130-L143)):

 
 - All tensors must have matching first dimension (number of nodes)
 - `retrieve_next_token` and `retrieve_next_sibling` must be int64
 - `draft_tokens` must be int64
 - `bitmask` must be int32
