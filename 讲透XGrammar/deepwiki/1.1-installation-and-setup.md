 The package automatically installs these required dependencies:

 
 - `pydantic` - Schema validation and parsing
 - `torch>=1.10.0` - Tensor operations and DLTensor integration
 - `transformers>=4.38.0` - Tokenizer integration
 - `numpy` - Array operations
 - `typing-extensions>=4.9.0` - Type hint support
 - `triton` - GPU kernel backend (Linux x86_64 only)

## Building from Source

 Building from source is necessary for development, custom configurations, or unsupported platforms.

 
### Prerequisites

 
#### System Requirements

 
 - **C++ Compiler**: C++17 support required 
 - Linux/macOS: GCC ≥7.0, Clang ≥5.0
 - Windows: MSVC ≥2019
 - **CMake**: Version ≥3.18
 - **Python**: Version ≥3.8, <4.0
 - **Git**: For cloning the repository and submodules

### Build Process

 
#### 1. Clone the Repository

 
```

```

 The repository includes these critical submodules:

 
 - `3rdparty/dlpack` - DLTensor specification
 - `3rdparty/picojson` - JSON parsing
 - `3rdparty/googletest` - C++ testing (if building tests)
 - `3rdparty/cpptrace` - Stack traces (optional)
 
 
#### 2. Configure Build Options

 Create a `config.cmake` file in the project root (or `build/config.cmake` or `cmake/config.cmake`) to customize the build:

 
```

```

 The CMake configuration loader checks for config files in this priority order:

 
 - `${CMAKE_BINARY_DIR}/config.cmake`
 - `${PROJECT_SOURCE_DIR}/config.cmake`
 - `${PROJECT_SOURCE_DIR}/cmake/config.cmake`
 
 
#### 3. Build and Install

 
```

```

 The build system uses `scikit-build-core` which automatically:

 
 - Invokes CMake with configuration from `pyproject.toml`
 - Compiles the C++ static library (`libxgrammar.a`)
 - Builds the Python extension module (`xgrammar_bindings`)
 - Installs the Python package

## Build Configuration Reference

 
### CMake Options

 The following options can be set via `config.cmake` or CMake command line:

 
| Option | Type | Default | Description |
|---|---|---|---|
| XGRAMMAR_BUILD_PYTHON_BINDINGS | BOOL | ON | Build Python extension module |
| XGRAMMAR_BUILD_CXX_TESTS | BOOL | OFF | Build C++ test suite with GoogleTest |
| XGRAMMAR_ENABLE_CPPTRACE | BOOL | OFF | Enable C++ stack traces (Linux only, requires RelWithDebInfo or Debug) |
| XGRAMMAR_ENABLE_COVERAGE | BOOL | OFF | Enable code coverage with gcov |
| XGRAMMAR_ENABLE_INTERNAL_CHECK | BOOL | OFF | Enable internal assertion checks |
| XGRAMMAR_CUDA_ARCHITECTURES | STRING | native | CUDA compute architectures (e.g., "75;80;86") |

 
### Build Type

 The default build type is `RelWithDebInfo` (optimized with debug symbols):

 
```

```

 Available build types:

 
 - `Release` - Full optimization, no debug symbols
 - `RelWithDebInfo` - Optimization + debug symbols (default)
 - `Debug` - No optimization, full debug symbols
 - `MinSizeRel` - Size optimization

### Common Installation Issues

 
| Issue | Symptom | Resolution |
|---|---|---|
| Import Error | ModuleNotFoundError: No module named 'xgrammar' | Verify installation with pip list \| grep xgrammar |
| Version Mismatch | AttributeError on class methods | Check Python version ≥3.8, reinstall package |
| Build Failure | CMake Error during source build | Verify CMake ≥3.18, C++17 compiler available |
| Missing Dependencies | ImportError: torch | Install dependencies: pip install torch transformers |
| Triton Missing | Warning on Linux | Expected on non-x86_64 platforms |

## Summary

 xgrammar installation is straightforward via pip for standard use cases. Building from source provides flexibility for development and custom configurations. The build system leverages `scikit-build-core` and CMake to manage the C++/Python integration seamlessly.

 
| Installation Type | Command | Use Case |
|---|---|---|
| PyPI Release | pip install xgrammar | Production, standard usage |
| Development | pip install -e ".[test]" | Contributing, testing |
| Custom Build | Configure config.cmake, then pip install . | Platform-specific optimizations |
