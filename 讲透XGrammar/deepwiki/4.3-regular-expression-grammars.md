  This page documents the regular expression to grammar conversion capabilities in XGrammar. It covers how to create Grammar objects from regex patterns, the supported regex syntax, and the conversion process.

 For information about other input formats, see [EBNF Grammar Specification](https://deepwiki.com/mlc-ai/xgrammar/4.1-ebnf-grammar-specification), [JSON Schema Conversion](https://deepwiki.com/mlc-ai/xgrammar/4.2-json-schema-conversion), and [Structural Tags System](https://deepwiki.com/mlc-ai/xgrammar/4.4-structural-tags-system). For details on how grammars are compiled and optimized after conversion, see [Grammar Compilation](https://deepwiki.com/mlc-ai/xgrammar/2.2-grammar-compilation).

 
## Overview

 XGrammar provides the ability to convert regular expression patterns into Grammar objects that can be used for constrained generation. The regex syntax follows the JavaScript (ECMA 262) specification. The conversion is a two-stage process: the regex pattern is first converted to EBNF format, then parsed into the internal Grammar representation.

 This feature is useful when you have existing regex patterns and want to use them for grammar-guided LLM generation without manually converting them to EBNF format.

## Supported Regex Syntax

 XGrammar supports most common regex constructs from the JavaScript (ECMA 262) specification:

 
| Feature | Syntax Example | Description |
|---|---|---|
| Literal characters | abc | Match exact character sequence |
| Character classes | [a-z], [^0-9] | Match characters in/not in set |
| Predefined classes | \d, \w, \s | Digit, word character, whitespace |
| Quantifiers | *, +, ? | Zero or more, one or more, optional |
| Exact quantifier | {n} | Match exactly n times |
| Alternation | a\|b | Match a or b |
| Grouping | (abc) | Group expressions |
| Anchors | ^, $ | Start and end of string |
| Escape sequences | \n, \t, \\ | Newline, tab, literal backslash |

 The regex syntax follows the standard documented at [https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Regular_expressions](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Regular_expressions).

 Sources: [python/xgrammar/testing.py68-79](https://github.com/mlc-ai/xgrammar/blob/c30554f7/python/xgrammar/testing.py#L68-L79)

 
## Unsupported Features

 The following ECMA 262 regex features are **not currently supported**:

 
 - **Backreferences** (`\1`, `\2`, etc.) - References to captured groups
 - **Non-capturing groups and assertions** (`(?:...)`, `(?=...)`, `(?!...)`, etc.) - Special group syntax
 - **Unicode character class escapes** (`\p{...}`) - Unicode property escapes
 - **Word boundaries** (`\b`, `\B`) - Position assertions
 - **Range quantifiers** (`{x,y}`) - Match between x and y times
 
 **Workaround for range quantifiers**: Instead of `a{2,4}`, you can repeat the element: `aa(a)?(a)?` or use explicit alternatives.

### Error Handling

 When regex parsing fails, the system raises a `RuntimeError` with details about the parsing error. This typically occurs when:

 
 - Using unsupported regex features
 - Syntax errors in the regex pattern
 - Invalid escape sequences
