# 05 · 多渠道网关架构模式（开源，IM Bot 抽象）

> 多渠道 AI 助手网关形态——**工程最严谨**，独有创新数第二（8 个）。本文档已脱敏。

---

## 一、形态定位

- **形态**：网关 + 多端（个人 AI 助手 + 多 IM 渠道接入）
- **用户**：任意个人（通过 WhatsApp/Telegram/Slack/Discord/Signal/iMessage 等 IM 使用）
- **特点**：多渠道统一抽象（数十个 IM channel 统一接口）
- **架构取向**：架构驱动，重协议严谨性和多用户治理

---

## 二、架构特点

- **基础**：TypeScript + monorepo（多 package + 大量扩展）
- **形态**：Node CLI + 多平台 native apps + Web UI
- **核心抽象**：**Multi-channel AI Gateway**（多 IM channel 统一接口）
- **协议层**：Gateway Protocol + ACP（agent-UI 解耦）
- **进程模型**：单进程 + Gateway daemon
- **持久化**：SQLite + 向量库（LanceDB）

---

## 三、独有设计（该形态的 8 个创新）

### ★★★★★ 多渠道统一抽象（异构 IM 统一接口）

数十个 IM channel（WhatsApp/Telegram/Slack/Discord/Signal/iMessage 等）抽象成统一接口——schema 驱动。

**借鉴价值**：**异构系统统一接口**的经典范式。每个 channel 适配一次，上层 agent 逻辑无感。

### ★★★★★ Agent Loop 双层循环（outer follow-up + inner tool）

```
outer loop: 处理用户 follow-up（用户边说边改）
inner loop: 处理 tool / steering
```

**借鉴价值**：**处理"用户边说边改"**。单层循环的 agent 难以应对用户在工具执行中途插话——双层循环让 follow-up 和 tool 执行解耦。

### ★★★★★ Tool Loop Recovery（死循环检测终止）

检测 agent 陷入工具死循环（反复调同一工具）并终止。

**借鉴价值**：**防死循环**。LLM agent 容易陷入"调工具→失败→再调"的循环，需要检测+恢复机制。

### ★★★★ Turn Tainting

被中断的 turn 标记为 tainted，防止 LLM 误用中断状态。

**借鉴价值**：中断的 turn 不应被当成正常 turn 继续推理——标记污染状态。

### ★★★★ AsyncLocalStorage 工具上下文

工具内可反向追溯调用者（通过 AsyncLocalStorage 注入上下文）。

**借鉴价值**：工具内能知道"谁在什么 session 上下文里调用了我"——便于审计和权限。

### ★★★★ 多 memory engine 分离（按职责）

多个 memory engine 按职责分离：embeddings / baseline / qmd / storage。

**借鉴价值**：记忆不应是单一 blob——按职责（向量检索/基础知识/工作记忆/持久化）分离。

### ★★★★ Frame Guards + Secret Ref（协议层安全）

- Frame Guards：协议层防注入 / 防越权
- Secret Ref：secret 用 ref 引用，不直接传值

**借鉴价值**：**协议层安全**。不依赖 prompt 防注入，在协议层拦截。

### ★★★★ Thread Ownership + Policy（多用户/多渠道治理）

多用户多渠道的 thread 所有权和策略管理。

**借鉴价值**：多租户 agent 必须有 thread ownership——谁 owns 这个会话，策略是什么。

### ★★★ Idle reaper + eviction（长跑防泄漏）

长跑服务定期清理空闲 session（防资源泄漏）。

## 五、借鉴价值

做**多渠道 IM Bot / 个人 AI 网关**时，借鉴此形态的：
- **多渠道统一抽象**（异构 IM 接口）
- **Agent Loop 双层循环**（处理用户插话）
- **Tool Loop Recovery**（防死循环）
- **AsyncLocalStorage 工具上下文**（反向追溯）
- **多 memory engine**（记忆按职责分离）
- **Frame Guards + Secret Ref**（协议层安全）
- **Thread Ownership + Policy**（多租户治理）
- **Idle reaper**（长跑防泄漏）

> 该形态是"防御性 + 多租户"设计的典范——8 个独有创新里大部分是**防御/治理机制**（死循环恢复 / 中断标记 / 协议层安全 / 多租户 / 长跑清理）。做服务端 agent 必读。
