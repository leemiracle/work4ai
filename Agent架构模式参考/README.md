## 这是什么

这是一份**给做 Agent 的人**的架构参考。基于对五类形态的 AI Agent 产品（两类 VS Code Fork IDE + 一类桌面办公 Agent + 一类 CLI/TUI 框架 + 一类多渠道网关）的架构分析，提炼出**架构分层 + 场景工作流 + 独有创新 + 反模式 + 借鉴清单**。

不是教程，不是评测，是**架构参考蓝图**。

## 核心结论速览（3 条）

1. **五类形态根本不是一个赛道**：
   - IDE-A / IDE-B = VS Code Fork AI IDE（编码助手）
   - 桌面 Agent = 桌面办公自动化（对标通用办公 Agent 范式）
   - CLI/TUI 框架 = 开发者命令行工具
   - 多渠道网关 = 个人 AI 助手 + 多 IM 渠道

2. **独有创新数排行**：**IDE-B（13 个）> IDE-A（8 个）≈ 多渠道网关（8 个）> 桌面 Agent（6 个）> CLI/TUI 框架（5 个）**

3. **做 Agent 时按场景借鉴**：
   - **做编码 IDE** → 借鉴 IDE-B（工程极致）或 IDE-A（企业市场）
   - **做桌面办公** → 借鉴 桌面 Agent（最完整）
   - **做 CLI/TUI** → 借鉴 CLI/TUI 框架（函数式工程化）
   - **做 IM Bot** → 借鉴 多渠道网关（多渠道抽象）

## 分析方法说明

本文档基于对五类形态 AI Agent 产品的**架构级分析**，方法包括：

- **应用结构分析**：Electron 应用结构 / deb 包组织 / 开源仓库源码阅读
- **架构模式提炼**：进程模型 / 协议设计 / 循环结构 / 扩展机制 / 安全模型
- **公开工程文献交叉验证**：与已发表论文、技术博客、开源实现对照

> 所有具体产品名、厂商、版本号、内部代号、包结构细节均已脱敏。本文档保留的是**可迁移的通用 Agent 架构模式**——这些模式（3 进程分离、Protobuf schema、CRDT、Shadow Workspace、函数式 Service 组合、多渠道抽象等）都是**公开的工程概念**，其价值在于"哪些组合在哪些场景有效"，而非任何单一产品的实现细节。
