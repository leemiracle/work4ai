## 组内横断发现

1. **"代数计数/状态旁路"防陈旧工作成为通用原语**：speech-to-speech 的 CancelScope 用 32 位回绕 generation 让 LLM/TTS 线程就地丢弃被打断的回合（cancel_scope.py:L32,L52-54）；inbox-zero 因 p-queue 不可撤销而发明 queuedJobs Map 旁路标记 cancelled（archive-queue.ts:L36-39）——两家殊途同归："过时的工作，轮到它时就地蒸发"，而不是尝试真取消。
2. **"便宜的先问、LLM 兜底"分层决策经济学**：inbox-zero 五级树中 learned pattern 命中即跳过 AI、cold email 先查历史通信再调 LLM、内容按 500/3000 字符分级截断；chandra base 安装不带 torch、生产走无状态 vLLM；llm 用 aliases.json 静态映射免查注册表——确定性层过滤流量后才花模型的钱。
3. **"索引是缓存、真源可重建"的存储哲学对立于重数据库派**：EverOS 明言 Markdown 为 canonical、SQLite/LanceDB 丢了可全量重建（docs/overview:L33-34）；llm 把日志与 embeddings 物理分库、默认模型存纯文本文件；h2ogpt 向量库三选一皆可再生——与 EverOS README 对比表痛批的"Mongo/ES/Redis 重栈"记忆库形成本批最鲜明的设计路线对立。
4. **OpenAI 兼容协议是"万用插座"夺回后端自由**：speech-to-speech 的 LLM 槽指向 llama.cpp 即全本地语音栈（README:L48-61）；h2ogpt 整体伪装成 OpenAI server；chandra 的 vllm 后端就是 openai client；inbox-zero 靠 Vercel AI SDK 换 provider——四仓用"说 OpenAI 方言"把供应商锁定反转成供应商菜单。
5. **独家发明清单**：EverOS——OME Reflection 的 Select→Merge→Re-extract→Deprecate 离线记忆演化 + import-linter 强制 DDD 单向依赖；inbox-zero——对话状态元规则（TO_REPLY/AWAITING_REPLY 合成 meta-rule 保线程连续性）；speech-to-speech——GIL 原子性论证下的无锁单写多读 CancelScope；MidJourney-Reference——对闭源模型做控制变量法（Sphere/Crystal/Tree 标准对象×版本×参数）的逆向词典；chandra——"没有 benchmark 就自造 90 语言 benchmark"的评估先行。
