### microsoft/promptflow
- **DeepWiki**：30 章；深读 1-Overview + 2.2 Flow Execution Model（命中）
- **架构模式**：四包分层 monorepo：`promptflow-core`（加载/执行流）+ `promptflow-tracing`（OpenTelemetry 观测、token 计数）+ `promptflow-devkit`（CLI/本地调试/run 管理）+ `promptflow-azure`（云端执行）；三种一等流类型 DAG（flow.dag.yaml）/Flex（Python 函数，flow.flex.yaml）/Prompty（.prompty 模板），FlowType 枚举见本地 `_constants.py:L74-79`。注意仓库已进入"迁移期"：keyfiles 里存在 `migration-guide/PromptFlow-to-MAF/...maf_prs/__init__.py`（"wraps a MAF workflow as an Azure ML parallel component"）——官方正引导用户迁往 MAF。
- **核心数据结构**：本地 `_constants.py` 是全库契约字典：`FLOW_DAG_YAML/FLOW_FLEX_YAML/PROMPTY_EXTENSION`（L28-31）、连接脱敏三件套 `CONNECTION_NAME_PROPERTY="__connection_name"/CONNECTION_SECRET_KEYS/CONNECTION_SCRUBBED_VALUE="******"`（L7-10）、`PF_MAIN_MODULE_NAME="__pf_main__"`（L42，用户代码以魔法模块名隔离加载）、批执行 `LINE_NUMBER_WIDTH=9` 零填充保证文件名可排序（L52-53）、`LINE_TIMEOUT_SEC=600`（L54）。
- **核心算法/协议**：① 执行五件套 FlowExecutor→ToolResolver→ResolvedTool→LineResult→BatchEngine（DW 2.2）；② ToolResolver 把五类工具（package/script/prompt/LLM/custom LLM）统一解析为"node 引用+callable+定义+初始化参数"，并做连接类型校验与 `CustomStrongTypeConnection` 强类型转换（DW 2.2 Tool Resolution）；③ 批执行 `LineExecutionProcessPool` 按系统内存/进程内存/行数动态决定 worker 数，fork(Linux)/spawn(全平台) 双模式（DW 2.2 Batch）；④ 异常分类学（DW 2.2 Error Handling 五类 + 本地 `_errors.py:L60-112`）；⑤ LLM 流式工具自动识别与流参数启用（DW 2.2 Streaming）。
- **设计模式与工程决策**：① `ToolExecutionError.tool_traceback` 调 `extract_stack_trace_without_core_frame`（`_errors.py:L89-94`）——把框架自身栈帧从用户 traceback 中剥掉，只呈现用户代码栈，是"平台透明性"的教科书实现；② 错误消息由 `message_format`+`message_parameters` 模板化组装（`_errors.py:L76-81`），支持本地化与结构化上报；③ 密钥在连接层静态脱敏（`******`/`<no-change>` 哨兵值），而非在日志层事后过滤。
- **教学映射**：透视Agent系统工程（流编排+批执行资源治理）+ 评测（flow 级质量评估体系，DW 6.2）
- **一句话本质**：把 prompt 工程做成"可批量跑、可评测、可部署"的 DAG 数据集，连报错栈都替你裁剪干净。

### tambo-ai/tambo
- **DeepWiki**：49 章；深读 1-Overview + 7.5 Tool Execution Pipeline（命中）
- **架构模式**：生成式 UI 全栈 monorepo：公开侧 `@tambo-ai/react`（TamboProvider 嵌套五层 context：Client/Registry/Stream/Mcp/ThreadInput）+ `tambo` CLI + `@tambo-ai/ui-registry`；私有云侧 NestJS `apps/api`（port 8261，本地 `main.ts:L68`）+ Vercel AI SDK 5 后端 + Drizzle/PostgreSQL。核心机制：React 组件带 Zod `propsSchema` 注册 → `schemaToJsonSchema()` 转 JSON Schema → 自动生成 `show_component_*` 工具；`withTamboInteractable` 包装的组件额外获得 `update_component_props_*` 工具（DW Overview）。
- **核心数据结构**：本地 `memory-extraction-schema.ts:L8-23`——`memoryImportanceSchema = z.union([1..5 字面量]).default(3)` + `memoryCategorySchema` 枚举 + `content max(1000)`，即长期记忆抽取被压成一个可校验的 Zod 合同；`streamReducer`（eventaccumulator.ts）不可变累积 AG-UI 事件并在 API 响应前先发合成事件做乐观 UI（DW Overview）；MCP 工具名前缀 `{serverKey}__{toolName}`、资源 URI `{serverKey}:{mcpUri}`（DW 7.5）。
- **核心算法/协议**：① 决策循环 `runDecisionLoop()` 聚合四源工具面（项目系统工具+客户端注册工具+MCP 服务器工具+UI 组件工具）；② 工具流四拍 `tool-input-start→delta→end→tool-call`，由 `ComponentStreamTracker` 做**增量 JSON 解析**，检测到 `show_component_*` 即发 `COMPONENT_PROPS_START/DELTA/END`——props 逐个到达、组件渐进渲染（DW 7.5）；③ 每 thread 乐观锁 `acquireRunLock()/releaseRunLock()` 防并发 run；④ MCP 客户端会话持久化：sessionId 变更即写库，重连复用；⑤ OAuth `OAuthLocalProvider` 自动刷新过期 token（DW 7.5）。
- **设计模式与工程决策**：① 本地 `mcp-server/server.ts:L24-88`：tambo **同时是 MCP server 和 client**——把用户配置的下游 MCP 服务器再代理出去，且"只有 hasClients 才 advertise prompts/resources 能力"防 Method not found；`dispose()` 用 `Promise.allSettled` 吞错清理，注释明言"一个坏客户端不阻止其他清理"（L70-86）；② 服务器级故障隔离：`Promise.allSettled` 逐服务器收集工具，失败者剔除、成功者照常，"fail-fast, no fallbacks"只作用于单服务器内部（DW 7.5）；③ `main.ts:L1-2` Sentry 最先初始化、helmet CSP 显式保守默认 + HSTS 仅生产开关启用；④ 考古证据：根 `package.json:L4` description 字段仍是 **hydra-ai 旧 README 徽章串**——本仓库由 michaelmagan/hydraai 更名而来。
- **教学映射**：多模态（LLM 输出→UI 组件的模态转换）+ 工具调用（组件即工具范式）
- **一句话本质**：让 LLM 的函数调用协议直接驱动 React 渲染树——Zod schema 是 UI 的 DNA。

### bytebot-ai/bytebot
- **DeepWiki**：43 章；深读 1-Overview + 6.1 Agent Processor（命中；keyfiles 目录为空，源2 依赖 README）
- **架构模式**：三层服务：bytebot-ui（Next.js 15 :9992，代理 HTTP/WS/VNC）→ bytebot-agent（NestJS :9991，任务编排+LLM）→ bytebotd（NestJS 守护进程 :9990，跑在 Ubuntu 22.04 容器内：XFCE4@1920x1080 + nut-js 自动化 + uiohook-napi 全局输入捕获 + noVNC/websockify + `/mcp` SSE 端点）（DW Overview Three-Tier）。
- **核心数据结构**：Prisma 四模型 `Task/Message/Summary/File`；`Summary` 自引用成层级（DW Persistence）；Message 内容为 `Json` 存 `MessageContentBlock[]` 数组，**直接兼容 Anthropic Claude API 的 content block 格式**（text/tool_use/tool_result/image/thinking/document，DW Persistence）；AgentProcessor 内部三态 `{currentTaskId, isProcessing, abortController}` + `services: Record<'anthropic'|'openai'|'google'|'proxy', BytebotAgentService>`（DW 6.1 L44-68）。
- **核心算法/协议**：① 主循环 `runIteration()` 九步（DW 6.1 L134-403）：校验状态→组上下文→LLM→存 ASSISTANT 消息→**token≥75% 上下文窗口则分层摘要**→执行工具→存 tool 结果→按 `set_task_status` 更新状态→`setImmediate()` 非阻塞续跑；② 上下文 = 最新 Summary（压缩的旧史）+ 未摘要消息（近期全量），任务可无限长；③ 工具仅三件：`computer`（发 bytebotd `/computer-use` 执行鼠键）、`create_task`（Agent 自我复制生成带调度的子任务）、`set_task_status`（COMPLETED/FAILED/NEEDS_HELP）；④ takeover 协作：`task.takeover` 事件 → abort 在飞请求 + `InputCaptureService.start()` **录制人类接管期间的输入**，`task.resume` 校验所有权后换新 AbortController 续跑；⑤ AgentScheduler 每 5s cron `findFirst({status:PENDING})` 领任务（DW 5.4）。
- **设计模式与工程决策**：① 单线程处理器 + `isProcessing` 互斥——刻意不并发，用事件循环让位（processTask 立即返回）；② 每次迭代**新建** AbortController，防止单 signal 上 abort listener 累积泄漏（DW 6.1 L155）；③ 错误二分：`BytebotAgentInterrupt`（takeover 预期内，不动状态）vs 其他（置 FAILED）——中断不是失败；④ "拥有自己电脑"的产品哲学：全桌面而非浏览器 DOM，用 1Password 等密码管理器过 2FA（README:L36-70）。
- **教学映射**：世界模型（截图即世界状态的 computer-use 视觉循环）+ 记忆（层级摘要滚动压缩）+ 人机协同（takeover/resume 双模控制权）
- **一句话本质**：给 LLM 一台带录屏、可被夺回方向盘的 Ubuntu 虚拟机，用 75% 水位线的摘要泵喂它无限记忆。

- **核心数据结构**：`Graph{nodes, connections, exposed_messages, exposed_properties}`（ten_rust/src/graph/mod.rs:L171-184）；节点三型 Extension/Subgraph/Selector（Selector 用 regex/exact 过滤 name/app/addon + and/or 逻辑组合动态匹配多节点，property.schema.json:L366-380）；连接承载四类消息流 cmd/data/audio_frame/video_frame，支持 `msg_conversion` 属性改名（如 transcript→text）；`GraphInfo{name, auto_start, singleton, import_uri, flattened_graph 缓存}`（graph_info.rs:L53-224）；本地 playground `global.ts:L30-45` 前端状态 `graphList/graphMap/addonModules` + `chatItems` 按 userId+isFinal+time 三元组去重乱序 ASR 片段（L97-120）。
- **核心算法/协议**：图处理八级流水线（DW 3.2 Processing Steps + mod.rs:L520-554）：parse(serde)→validate→**names 数组展开**（多消息名展开为多条 flow，且 names 与 msg_conversion 互斥防歧义，mod.rs:L411-518）→**selector 展平**（过滤求值替换为实名）→**反向连接转正向**（source 写法归一化为 dest）→**子图递归展平**（import_uri 支持 file://与 http://，节点名加前缀 `sg1_ext_c`，父属性覆盖合并，深度优先）→**graph proxy 注入**（有 exposed_messages 即造 `ten:graph_proxy` 虚拟节点做跨图路由，mod.rs:L556-823）→static_check+schema check（对照各扩展 manifest 的 api.cmd_in/data_out 校验连接两端 schema 兼容）。
- **设计模式与工程决策**：① **App URI 声明状态机**（mod.rs:L94-285）：NoneDeclared/UniformDeclared/MixedDeclared 三态合法，"部分声明"非法，且显式字符串 `"localhost"` 被禁止——用类型系统逼出单机/多机拓扑的一致性；② 图即数据：可视化 Designer（:49483）与 JSON 文本同源可逆；③ Windows 链接期直接把栈扩到 32MB（本地 `build.rs:L19-24` `/STACK:33554432`）——深递归图展平的工程兜底写进构建脚本；④ 生态拆仓：VAD/Turn Detection/Portal 独立仓库，本仓只做运行时+包管理。
- **教学映射**：多模态（audio/video frame 一等消息类型）+ 透视Agent系统工程（多语言扩展总线的图编排）

## 组内横断发现

1. **声明式图 vs 命令式循环的范式分裂**：TEN（八级图展平+manifest schema 静态检查）与 promptflow（DAG 拓扑执行+flow.tools.json 契约）把 Agent 编排当**编译问题**；tambo（runDecisionLoop）、bytebot（runIteration 九拍）、hexstrike（WorkflowManager）把编排当**运行时循环问题**。前者可校验不可即兴，后者可即兴不可校验——五仓恰好对半分治。
2. **"组件/工具 schema 编译器"是全组公约数**：tambo Zod→JSON Schema→OpenAI tool、TEN manifest.json api.in/out→连接级 schema check、promptflow tool.schema.json+连接强类型、hexstrike @mcp.tool 类型签名——四家都在做同一件事：把本地类型系统编译成 LLM 可消费的工具合同，schema 已成 Agent 世界的 ABI。
3. **MCP 的三重身份**：tambo 同时是 MCP client（聚合用户服务器，`serverKey__` 前缀防撞名）与 MCP server（`/mcp` 反向代理，hasClients 才 advertise 能力，本地 server.ts:L44-56）；bytebotd 把桌面操作以 `/mcp` SSE 外供；hexstrike 则是 MCP→REST(Flask) 的协议适配器。MCP 正在成为"Agent 后端总线"而非单纯工具协议。
4. **控制权让渡与中断语义**：bytebot 的 takeover（abort+录制人类输入+resume 换新 AbortController）与 `BytebotAgentInterrupt`≠失败的错误二分、tambo 的 per-thread run lock、promptflow 的进程池行隔离——三家各自回答"人和 Agent 抢方向盘时系统该怎么停"；TEN/promptflow 的 DAG 世界则根本未设此题，暴露声明式范式的协作盲区。
5. **仓库考古层**：tambo 根 package.json description 仍残留 hydra-ai 旧徽章（更名迁移痕迹）；promptflow 仓库内建 migration-guide/PromptFlow-to-MAF 目录（自我 deprecated 化）。AI 框架代际更替速度之快，已快到"仓库名即地层"。
