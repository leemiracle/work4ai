### opensandbox-group/OpenSandbox
- **DeepWiki**：9 章大目录（2 Lifecycle Control Plane/3 K8s Controller & CRDs/4 Data Plane/5 SDKs/6 CLI…）；深读 2.5 Snapshot & Pause/Resume
- **架构模式**：AI 沙箱基础设施四面体：控制面 `opensandbox-server`（FastAPI 生命周期 API+多租户 OSEP-0014）→ Docker/K8s 双 runtime backend；K8s operator 管 **BatchSandbox/Pool（预热池降冷启动）/SandboxSnapshot** 三 CRD；数据面：execd（容器内 Go 守护：命令/PTY/文件/遥测）+ Egress Sidecar（nftables+DNS 出口墙）+ Ingress Gateway + Credential Proxy（OSEP-0012 凭证金库：秘密不明文进负载）；5 语言 SDK+osb CLI+MCP server；gVisor/Kata/Firecracker 强隔离（OSEP-0004）。
- **核心数据结构**：本地 nodeagent api/types.go:L44-50 `Record{Kind:"container-log", Timestamp, Body, Resource, Attributes}`，Resource 字段全 OTel 风格（`k8s.pod.name` 等，L33-42）；L70-89 `AckDisposition{delivered|intentional-drop}` × `DeliveryGuarantee{durable|best-effort}` 二维投递语义。
- **核心算法/协议**：**rootfs 快照即暂停**（DW 2.5）：K8s 路径 SandboxSnapshot CR → Reconciler 起 image-committer Job 五拍（main.go:L82-225）：`nerdctl ps` 找容器 → 容器内 best-effort fsync（VM 隔离场景关键）→ `nerdctl pause` 静默 → `nerdctl commit` 成镜像 → **无论成败 unpause** → push OCI registry；pause 成功后删 pod 释放算力，resume 从镜像重建、sandboxId 稳定复用；Docker 路径退化为一行 `container.commit()` 打 `opensandbox-snapshots:{id}` 标签；`PersistedSnapshotService` 先写 SQLite CREATING 记录再 ThreadPoolExecutor 异步执行+重启扫描恢复未决快照。nodeagent 主程序（main.go:L47-140）readiness 门模式：每步失败 `readiness.Replace("invalid-config"/"state-unavailable"/"sink-unavailable"…)` 后 waitForSignal 存活不 crash。
- **设计模式与工程决策**：① Source/Sink 稳定扩展合同（types.go:L122-128/L183-189：Capabilities/Start/Acknowledge/Consume/Finalize），file/oss sink 用空导入注册（main.go:L38-39）；② 错误分类保守主义：`RetryableError` 未分类错误一律视为可重试（L130-145）；③ OSEP 公开设计提案制（19 篇）驱动演化；④ v1 限制诚实写在文档：每沙箱仅留一份快照、Credential Vault 不跨 pause/resume、仅支持单副本；⑤ 三 registry 发布+Cosign keyless 签名+provenance（README:L35-47）。
- **教学映射**：透视Agent系统工程（沙箱即基础设施）+ 软件即熵治理（OSEP 提案制+readiness 门）
- **一句话本质**：给 AI 代码执行造的"可暂停/恢复操作系统"——暂停就是把 rootfs commit 成镜像。

## 组内横断发现

1. **"Agent 的计算机"三级持久化谱系**：qm 给每个 scope 配 durable sandbox（会话级存活）、omi agent_vm 用状态收据+三级回滚（VM 级存活）、OpenSandbox 把整个 rootfs commit 成 OCI 镜像（文件系统级存活）——三家互不知晓却都把"沙箱状态持久化"做成一等公民，粒度逐级加深，构成一条完整的演进谱系。
2. **结构化输出降级是普遍工程现实**：nanobrowser 按 deepseek-r1/Llama 黑名单关 structured output 走"剥 think 标签+手工 JSON 提取"、qm 附件解码 fatal TextDecoder 失败后 tolerant 回退、Fay unadopt 用正则剥 `<think>` 再比对——"模型输出不可信，解析层必须自带兜底"已是跨语言共识。
3. **MCP 正在变成万能外设总线**：unity-mcp 连游戏引擎（命令上主线程）、Fay 连知识库（Logseq 纯文件系统 server + 同进程 stdio-runner）、OpenSandbox 连基础设施（沙箱生命周期即工具）、Open-LLM-VTuber 连虚拟形象（ToolManager）——四个完全不同的域用同一协议接入，且 Fay 的"直接读写 Markdown 不依赖宿主运行态"代表了一条轻实现路线。
4. **入模前门禁取代事后过滤**：qm 的 SecurityScreener 在 turn 到达 LLM 之前筛查（Auto posture 分类器+每文件 screenText）、nanobrowser 双闸（wrapUntrustedContent 标注不可信内容 + guardrails 识别 TASK_OVERRIDE/DANGEROUS_ACTION）、OpenSandbox 干脆用 nftables sidecar 管住网络出口——注入防御正从 prompt 层下沉到数据入口层和网络层。
5. **流与原子性的矛盾催生"切分器/叫号机"组件**：Open-LLM-VTuber 的 SentenceDivider（pysbd→regex→首逗号三级切分+TagState 防标签内切断）与 TTSTaskManager 序号叫号（并行合成、有序播报），同 nanobrowser 把 20+ 动作聚合进单个 Zod object——凡流式 LLM 参与实时系统，都需一个把连续流切为可调度原子并保序的专职组件。
