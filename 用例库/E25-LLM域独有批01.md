### affaan-m/ECC（240.2K · JavaScript · 2026-02 · 星/月榜 #2）
- **定位**：agent harness 优化系统——「给你的 Agent 一套协调的工程体系」：`plan -> test -> implement -> review -> verify -> remember -> improve` [README]
- **架构模式**：skill-first 插件体（68 agents + 284 skills + 94 legacy commands + hooks/memory/rules），跨 7 个 harness（Claude Code 全功能、Codex 同步路径、Cursor/OpenCode/Gemini/Zed/Copilot/Qwen 能力受限适配）[README 能力表]
- **核心机制**：① Plan Canvas「指着改而不是重打」的计划评审面；② Unified Memory Vault（开发中）把记忆持久化到上下文窗口之外——「Optimize the context window. Persist everything else」[README]; ③ AgentShield 安全扫描：扫 prompts/hooks/MCP 配置/权限/密钥/agent 文件（npm 独立包 `ecc-agentshield`）
- **工程决策**：① 安装纪律工程学：「Pick one path only (per harness)」，明确列出 Avoid 组合（plugin+manual install / sync+marketplace）并配 Reset/Uninstall——**把安装冲突当一等公民问题**；② 单维护者周更 + MIT/Pro 双轨（GitHub App 私仓 $19/seat/mo）+ CodeRabbit/Greptile/Atlas/Moonshot 赞助——一人公司的开源商业范本；③ 版本演进是活教材：v1.2 统一 commands→skills → v1.8 harness 性能系统 → v2.0 Agent Harness OS（2026-06）→ 2.1 Plan Canvas
- **教学映射**：讲透Agent（harness 分层）+ skills工程手册（skill-first 演进）+ 讲透记忆（Memory Vault）
- **一句话本质**：把「资深工程师的工作流」打包成 Agent 的操作系统，按席位收费、按周迭代。

### ollama/ollama（178.5K · Go · 2023-07）
- **定位**：本地模型运行时事实标准——`ollama run` 一条命令把任意开源权重变成本地 OpenAI 兼容服务
- **架构模式**：单二进制 Go 分发（macOS/Windows/Linux/Docker）→ 本地模型库管理（pull/run/rm）→ REST API（默认 11434 端口）+ Python/JS 官方 SDK [README]; 生态位：下游接 Coding（Continue/Cline）、Chat 界面（Open WebUI）、Libraries & SDKs、Frameworks & Agents 四类社区集成清单 [README Community Integrations]
- **工程决策**：① 不做界面只做运行时——把 UI 层整个让给 open-webui(148.8K)/jan(44K) 等下游，「**运行时与界面分离**」是本地生态分工的定局性决策；② README 描述排中英模型名（Kimi-K2.6/GLM-5.2/DeepSeek/gpt-oss/Qwen/Gemma）——中立运行时成为全球模型分发渠道；③ 与 llama.cpp 的关系：封装量化推理后端，价值在「模型管理的 npm 体验」
- **教学映射**：讲透LLM 03-全栈（部署层入口）+ 端侧AI架构参考
- **一句话本质**：开源模型界的 Docker——镜像是 GGUF，run 是一切。

### huggingface/transformers（164.1K · Python · 2018-10 · 存活 8 年的基岩）
- **定位**：模型定义框架——SOTA 文本/视觉/音频/多模态模型的统一推理与训练接口
- **架构模式**：三层 API 阶梯 [README Quickstart]：① `pipeline()`（一行推理）→ ② AutoClass（AutoTokenizer/AutoModel 自动解析 checkpoint）→ ③ 原生 PyTorch/TF 写法——**按用户水平分层收口**，新手到研究者同一仓库
- **工程决策**：① 「When shouldn't I use Transformers?」一节主动劝退（服务化用 TGI/推理用 vLLM——把生态位让给自己的兄弟项目）；② 100 projects using Transformers 清单自证平台地位；③ 8 年兼容 100+ 模型架构：每新增一个模型家族就是一次 `modeling_*.py` 的模式复制——**框架即模式库**
- **教学映射**：讲透Transformer + 讲透PyTorch + Karpathy经典代码精读（GPT 系实现）
- **一句话本质**：模型界的 Linux 内核树——每个新架构都以被 merge 进来为「正式存在」的标志。

### browser-use/browser-use（109.3K · Python · 2024）
- **定位**：让网站对 AI Agent 可用——把 DOM 变成 LLM 可操作的工具面
- **架构模式**：Python 库（`pip install browser-use` + `.env` 放 GOOGLE/ANTHROPIC key 即用）[README Quickstart]; 能力面 = 填表/抽取/多标签自动化；Open Source 核心与 Cloud 服务双轨，集成面（hosting/自定义工具/MCP）放 docs 站 [README]
- **工程决策**：① 「最易上手的网页自动化」定位——Quickstart 三行代码，把 playwright 的工程复杂度折叠掉；② 云服务作为开源功能的接续（会话托管/验证码/代理），开源获客+云变现的标准现代路径；③ 与其说和 playwright 竞争，不如说是「Playwright 之上的 LLM 语义层」
- **教学映射**：讲透Agent（工具使用）+ Agent多模态案例（视觉+DOM 双通道）
- **一句话本质**：给 LLM 发一个浏览器和一份 DOM 说明书。

### Graphify-Labs/graphify（106.5K · Python · 2026 · 星/月榜 #3）
- **定位**：codebase → 可查询知识图谱的 Claude Code/Cursor/Codex/Gemini CLI 技能
- **架构模式**：**反向量库宣言**：「Not a vector index. No embeddings, no vector store: a real graph you traverse」[README]; tree-sitter AST 确定性解析约 40 种语言的 `calls/imports/inherits/mixes_in` 跨文件边；Leiden 社区切分（**标签不用 LLM 生成**）；产物是单一 `graph.json`（query/path/explain 三种查询）
- **核心数据**：LOCOMO(n=300) recall@10 **0.497**（对照 mem0 0.048 / supermemory 0.149）；LongMemEval-S QA 76% 与稠密 RAG 打平；**图构建 LLM 消耗 = 0 credits** [README Benchmarks]
- **设计决策**：① 「God nodes」（最高连接度概念）直接给出架构重心——图拓扑本身可解释；② `# NOTE:`/`# WHY:` 注释与 ADR/RFC 文档升为一等节点与代码连线——**把设计理由写进图谱**；③ 文档/PDF/图片/音视频映射进同一张图
- **教学映射**：讲透RAG（无向量范式）+ 讲透符号主义（AST 确定性 vs LLM 概率性的混血）
- **一句话本质**：用确定性解析把代码库变成一张「每条边都能解释」的图，零 token 构建、遍历式检索。

### TauricResearch/TradingAgents（98.2K · Python · 2024-05）
- **定位**：多 Agent LLM 金融交易框架——把交易公司的组织结构图搬进代码
- **架构模式**：四层组织 [README]：**Analyst Team**（基本面/情绪/技术/新闻分析师）→ **Researcher Team**（**多头 vs 空头辩论**）→ **Trader Agent**（执行决策）→ **Risk Management + Portfolio Manager**（风险评估与仓位）
- **核心机制**：① 辩论式研究：bull/bear researcher 对抗后由 manager 裁决——**用组织结构实现对立观点的制度化**；② 持久化与恢复：Decision log + Checkpoint resume（长程任务断点续跑）；③ 可复现性：注明「推理模型忽略 temperature」等温度控制边界 [README Reproducibility]
- **工程决策**：① 组织隐喻直译（分析师/研究员/交易员/风控），领域专家秒懂；② CLI + Docker + Python 包三发行；③ 明确 Required APIs（数据源/LLM key 分离）
- **教学映射**：讲透多Agent协作（角色对抗+裁决）+ Agent编排案例 + finance 领域垂直
- **一句话本质**：把「投研晨会上的多空对骂」写成 DAG。

### vllm-project/vllm（89.1K · Python · 2023-06）
- **定位**：高吞吐、省显存的 LLM 推理与服务引擎（学界工业界双事实标准）
- **架构模式**：核心三件套：**PagedAttention**（KV cache 分页管理，显存利用率对标 OS 虚拟内存）+ **continuous batching**（迭代级调度，请求随到随拼车）+ OpenAI 兼容 API server；与 transformers 的关系 = 「定义模型的框架」vs「跑模型的服务」
- **工程决策**：① 从论文（Efficient Memory Management for LLM Serving with PagedAttention, SOSP'23）到工业标准的教科书路径；② 生态卡位：SGLang/DeepSpeed/TensorRT-LLM 竞争中靠**社区开放性**（多后端/多硬件 AMD/TPU/Blackwell）保持头部；③ README 极简（6KB）——复杂度在 docs 与代码，主页只做漏斗
- **教学映射**：讲透LLM 03-全栈（serving 层）+ 讲透KV Cache（PagedAttention 是其工业答案）+ 讲透GPU与系统级
- **一句话本质**：给 KV cache 装上操作系统的页表，吞吐翻倍只靠内存管理学。

### OpenHands/OpenHands（84.1K · TypeScript · 2024 · 原 OpenDevin）
- **定位**：AI 驱动开发平台——「软件工程 Agent 的参考实现」
- **架构模式**：三种启动路径分级 [README Quickstart]：无沙箱（直接试）→ Docker 沙箱（标准）→ 源码（贡献者）；**事件流架构**（agent 的每个动作/观察都是事件，可回放可审计）+ 沙箱隔离执行
- **工程决策**：① 改名 OpenDevin→OpenHands 并把范围从「复现 Devin」扩为「所有软件工程 Agent」——**更名即再定位**；② 沙箱一等内容：Quickstart 第二选项就是 Docker——安全边界先于功能；③ 学术绑定（SWE-bench 系列评测的常用 harness）
- **教学映射**：讲透代码生成（Agent 开发范式）+ 讲透Agent（事件流/沙箱两大基建）
- **一句话本质**：把「AI 程序员」做成一个可回放的事件流加一间一次性沙箱。
