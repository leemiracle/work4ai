### khoj-ai/khoj
- **DeepWiki**：1-overview、4.1-content-indexing-pipeline
- **架构模式**：FastAPI 路由 + Django ORM 双框架后端，PostgreSQL/pgvector 存储，多客户端（Next.js/Electron/Obsidian/Emacs）的"第二大脑"系统
- **核心数据结构**：`Entry` Pydantic 模型 `{compiled:"# filename.md\n## Heading\n...", raw, heading, file, uri:"file:///path#line=15", corpus_id:UUID}`（DW rawconfig.py:L14-30）；pyproject.toml:L38-98 锁死 pgvector==0.2.4、django==5.1.15、mcp>=1.23.0
- **核心算法**：索引管线四步——① 格式专用 processor 抽取（markdown 按 heading 递归分割并保留 `#` 级祖先链）② `RecursiveCharacterTextSplitter` 分块 ③ 对 `compiled` 做 **MD5 变更检测**，hash 已存在则跳过嵌入（text_to_entries.py:L156-175）④ Django `bulk_create` 批量入库；嵌入每 1000 条一批（embeddings.py:L109-114）。GitHub 源用 Magika 识别非标准扩展文件并轮询 `X-RateLimit-Remaining` 限速等待
- **设计模式与工程决策**：① 双框架嫁接：FastAPI 管路由、Django 管迁移；② hash 增量更新避免全量重嵌入；③ 客户端拉式索引：Obsidian 插件持有 `indexingTimer` 定时推送 vault
- **教学映射**：RAG（个人语料全链路）；记忆（第二大脑）
- **一句话本质**：把"个人笔记→可对话知识库"做成自托管 SaaS，真正的工程含金量在 MD5 增量索引而不是聊天。

- **核心数据结构**：`AgentWork` 接口 `{run(), conclude(), next(), onError()}` 组成责任链（analyze-task-work.ts:L8-38）；`RequestBody {model_settings, goal, run_id}` 贯穿所有 POST（agent-api.ts:L72-79）；首次响应回填 `run_id` 实现伪会话
- **核心算法**：任务环三协议端点——`/api/agent/start` 产初始任务列表 → 每任务先 `/api/agent/analyze`（带 `tool_names` 让 LLM 选工具）→ `/api/agent/create` 回传 `{result, last_task, tasks:remaining, completed_tasks}` 换新任务；`onError` 恒返回 true 使循环吞错继续
- **设计模式与工程决策**：① 状态机完全在客户端（Zustand），服务端零会话、天然水平扩展；② `setIsAgentThinking` 在 finally 中复位保证 UI 不死锁；③ agent 页面直接复用消息表回放任务
- **教学映射**：多Agent协作（plan-execute 循环最小样例）；透视Agent系统工程（把 loop 放前端的教学性反例）
- **一句话本质**：AutoGPT 的浏览器化重写——用无状态 HTTP 把自主循环塞进 React，代价是刷新即失忆。

### VectifyAI/PageIndex
- **DeepWiki**：1-overview、3.4-tree-structure-generation
- **架构模式**：vectorless RAG：文档→目录树 JSON 索引（node 含 LLM summary）→LLM 按 `node_id` 推理导航检索
- **核心数据结构**：节点 schema `{node_id:"0042"(4位零填充), title, start_index/end_index, line_num, text, summary(叶), prefix_summary(父), nodes[]}`（DW 3.4）；`pageindex/__init__.py:L20-30` 列出 `page_index_classic/flash/tree_optimize/mcp_bridge` 全模块表
- **核心算法**：① PDF 平坦→树：解析 `structure:"1.1.2"` 字段，`get_parent_structure()` 去尾段找父（utils.py:L351-356）；② Markdown：**栈式建树**——`while stack and stack[-1][1] >= current_level: pop`（page_index_md.py:L210）O(n) 定父子；③ tree_thinning 自底向上合并小节（L152-185）；④ 超大节点递归重探内部结构（page_index.py:L992-1019）；⑤ flash 引擎：几何块聚类——`SortedKeyList` 邻接扩展、Trie 规则判合并（flash/blocks/__init__.py:L1-56）
- **设计模式与工程决策**：① 惰性导入：模块级 `__getattr__` + `_LAZY` 表按名加载；② 叶/父摘要分离（summary vs prefix_summary）适配导航粒度；③ 建树失败回退 flat list 保证可用
- **教学映射**：RAG（与向量 RAG 的对立范式：similarity≠relevance，FinanceBench 98.7%）
- **一句话本质**：把检索从嵌入空间距离换成目录树上的 LLM 推理——树本身就是世界模型的显式编码。

### blakeblackshear/frigate
- **DeepWiki**：1-overview、4.4-object-detection-system
- **架构模式**：多进程 NVR：FrigateApp 编排 capture/track/detect/record/review 进程族，共享内存零拷贝传帧，Dispatcher 统一 MQTT/WS/ZMQ 三总线
- **核心数据结构**：归一化检测 `[class_id, confidence, y_min, x_min, y_max, x_max]`，上限 20 条 → 输出 SHM **固定 480 字节**（20×6×4，object_detection/base.py:L62）；SQLite：Peewee `Event/Recordings/ReviewSegment` + `SqliteVecQueueDatabase` 向量；api/app.py:L45-82 导入 `get_config_schema(FrigateConfig)` 动态生成 schema.json
- **核心算法**：检测调度五步——相机进程写张量入 `{camera}` SHM → `detection_queue` 只投递 camera_name → ObjectDetectProcess 池循环取队 → 读 SHM 调插件 `detect_raw` → 写 `out-{camera}` 并清标志（base.py:L94-129）。区域计算：`get_cluster_candidates()` 把运动框与已跟踪物体框聚类成候选区，避免全帧推理（util/object.py:L53）；watchdog：`detection_start` 超 10s 判卡死整体重启（watchdog.py:L36-41）
- **设计模式与工程决策**：① 队列饱和即天然背压：检测跟不上时相机进程阻塞，硬件自限速；② `DetectionApi` 硬件插件族（edgetpu/openvino/onnx/rknn/hailo）统一后处理；③ GenAI probe 双层超时 10s/15s 快速失败防挂起 worker
- **教学映射**：CV（边缘实时检测系统工程）；透视Agent系统工程（进程隔离+零拷贝的推理调度）
- **一句话本质**：一套用共享内存和进程隔离把昂贵 CNN 推理摊薄到 N 路摄像头的实时操作系统。

- **核心算法**：格式探测——顺序调用各工厂 `match()`：ONNX 依次试 7 个 reader（Ort/Proto/Text/Json/Pickle/Data/Meta）各验签（onnx.js:L8-34）；TF 用 protobuf tag 分析区分 SavedModel/GraphDef/MetaGraphDef；`filter()` 消除多文件歧义（模型 .pb 优先于权重）；多文件模型经 `context.fetch()` 拉伴生权重（openvino .xml+.bin、paddle .pdmodel+.pdiparams）
- **设计模式与工程决策**：① 零依赖哲学：web 端自制 module loader `window.exports.require`（index.js:L3-39）；② 浏览器硬门槛：BigInt/DataView 特性检测+版本墙（L96-108）；③ Electron `requestSingleInstanceLock` + ipcMain 直返式配置服务
- **教学映射**：PyTorch/Transformer（模型结构考古：亲自拆 ONNX/TFLite 图理解算子图）
- **一句话本质**：20+ 序列化格式的罗塞塔石碑——match/filter/open 三方法把格式巴别塔关进工厂。

### zeroclaw-labs/zeroclaw
- **DeepWiki**：1-introduction、8.1-memory-architecture
- **架构模式**：Rust 单二进制 trait 驱动 agent runtime：`ModelProvider/Channel/Tool/Memory` 四 trait 可全量热换，daemon+gateway(Axum) 编排
- **核心数据结构**：`MemoryEntry{id,key,content,category:Core|Daily|Conversation|Custom("visual"),timestamp,score,importance,namespace,agent_id}`（memory_traits.rs:L18-62）；`AgentScopedMemory{inner:Arc<dyn Memory>, agent_id, allowed_agent_ids:HashSet}`（agent_scoped.rs:L9-22）
- **核心算法**：记忆双轨——① `Memory` trait 语义记忆：SqliteMemory 混合检索（向量 cosine + FTS5 关键词，`hybrid_merge` 加权融合，vector.rs:L4-147）；② `AcpSessionStore` 存线性消息与 `ToolEventKind::In/Out` 工具轨迹（acp_session_store.rs:L15-32）；③ 装饰器链：所有写经 `store_with_agent` 强制盖章，读限 allowlist（agent_scoped.rs:L78-96, L149-187），再包 `AuditedMemory` 全操作入 audit.db
- **设计模式与工程决策**：① 写隔离读共享：agent 只能写自己空间、按 `read_memory_from` 白名单读兄弟；② 安全加固下沉到文件系统：audit 目录 chmod 0700、sqlite sidecar 0600（audit.rs:L14-80）；③ `refresh_embedder` 透传装饰器保证换 provider 后嵌入不失效
- **教学映射**：记忆（分层+权限+审计的完整范本）；学习型Agent
- **一句话本质**：用 Rust trait 把 agent 运行时做成一切皆可替换的单文件操作系统，记忆子系统自带 ACL 与审计日志。

## 组内横断发现

1. **上下文工程三派对立**：gpt-pilot 用 **LLM 自选文件**（RelevantFilesMixin）+标记截断；PageIndex 用**树索引推理**彻底去向量；khoj 用**嵌入+MD5 增量**经典 RAG——同一问题"给 LLM 喂什么"的三种世界观，PageIndex 是唯一把"检索=推理"做穿的。
2. **插件接口跨语言收敛**：netron `ModelFactory{match/open/filter}`(JS)、frigate `DetectionApi`(Python)、zeroclaw 四 trait(Rust)、spaCy `registry`——全部是"接口+注册表/工厂"，启动时静态装配、运行期零反射。
3. **SQLite 作为 Agent/边缘系统的记忆默认解**：frigate sqlite-vec、zeroclaw WAL+FTS5 混合、gpt-pilot 项目状态——印证"本地优先"部署共识。
4. **防御性解析是 LLM 工程共识、但程度分层**：next-ai-draw-io 13 步 XML 修复管线与 `lastSeenXml` 未见编辑检测（独家）、gpt-pilot JSONParser 强 schema + 魔词兜底；反例 AgentGPT 无输出解析层——恰好构成"该做/没做"的教学对照。
5. **独家发明清单**：PageIndex 无向量树检索（FinanceBench 98.7%）；gpt-pilot 的 LLM-as-file-filter；frigate 运动框+跟踪框聚类选区；zeroclaw 记忆 ACL 装饰器；gold-miner 用 GitHub 原生对象实现零服务协作工厂。
