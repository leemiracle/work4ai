- **架构模式**：Next.js/Bun monorepo，DAG 化"block"工作流引擎 + Trigger.dev 后台作业 + Socket.io 协同编辑。
- **核心数据结构**：`ExecutionSnapshot`（可恢复执行的完整状态封装，execution-core.ts:L73）；`NormalizedBlockOutput` 含 `_pauseMetadata.resumeLinks`（executor/types.ts:L223-224）；本地 driver.ts:L112-141 `DriverScopeState` 持有 `toolInvocationEpoch/snapshotCaptureEpoch/toolExecutionEpoch` 三个单调纪元计数器防竞态。
- **核心算法/协议**：执行五段式：preprocessExecution 鉴权/限流/计费 → executeWorkflowCore → DAGExecutor 拓扑遍历 → BlockExecutor 五步（VariableResolver 解引用→findHandler→execute→输出规范化→BlockStateWriter 落盘）；条件分支由 EdgeManager 依据 `selectedOption/selectedRoute` 激活出边并"失活未选分支的全部后代"（workflow-execution-utils.ts:L61-88）；HITL 暂停=generatePauseContextId+runFromBlock 从快照续跑。
- **设计模式与工程决策**：① 桌面浏览器 agent 坚持 trusted CDP 输入——"合成 KeyboardEvent 永不触发默认编辑行为"，driver.ts:L5-17 注释即设计文档；② 单浏览器工具调用串行队列+watchdog 三档超时；③ 沙箱用 isolated-vm 跑用户代码防 SSRF；④ 子工作流 validateCallChain 防递归。
- **教学映射**：透视Agent系统工程 + 多Agent协作
- **一句话本质**：把 Agent 编排做成"可断点续跑的 DAG 数据库事务"。

### herdrdev/herdr
- **DeepWiki**：14 章；深读 4.1 Screen Heuristics
- **架构模式**：Rust client/server 终端多路复用器，server 管 PTY/检测/会话，TUI 只是特殊客户端，JSON-RPC socket API 让 Agent 反向操控工作区。
- **核心数据结构**：`AgentState` 四态枚举 Idle/Working/Blocked/Unknown（detect/mod.rs:L13-19）；TOML 检测清单 rule 字段：`region`（osc_title/osc_progress/bottom_non_empty_lines(n)）+`state`+`contains`/`regex`+`any/all/not` 逻辑门（codex.toml:L6-79）；`ServerCapabilities{live_handoff, detached_server_daemon}`（本地 server.rs:L16-21）。
- **核心算法/协议**：Agent 状态推断三步：① 平台 API 扫前台进程组（/proc、proc_pidinfo）→进程名映射 Agent 类型；② 用对应 manifest 规则对屏幕缓冲区/OSC 序列做区域匹配定子状态；③ 迟滞滤波：`PendingIdleConfirmation` 需 ~700ms 或多次确认才发布 Working→Idle 转移，blocker 信号每 800ms 刷新（pane/agent_detection.rs:L7-65）。
- **设计模式与工程决策**：① 三层 manifest 加载（二进制内置→herdr.dev 远程→~/.config 本地覆盖）+版本校验+热重载，把"Agent UI 变更"的适配成本外置为数据；② 依赖极简：portable-pty+ratatui 单二进制；③ 会话可 detach 存活、跨重启、SSH 接入。
- **教学映射**：透视Agent系统工程 + 软件即熵治理（规则外置+版本化对抗生态漂移）
- **一句话本质**：给不会说话的 CLI Agent 做脑电图——用屏幕考古学反推黑盒状态机。

### Zackriya-Solutions/meetily
- **DeepWiki**：10 章；Overview 含模块地图
- **架构模式**：Tauri 桌面应用（React 前端 + Rust `app_lib` 后端 + llama-helper GPU sidecar），全本地隐私管线：采集→转写→摘要。
- **核心数据结构**：`ParakeetModel{encoder,decoder_joint,preprocessor:ONNX Session, vocab, blank_idx}`（本地 model.rs:L46-53）；`DecoderState=(Array3<f32>,Array3<f32>)` 流式解码器双状态张量（L13）；常量 `SUBSAMPLING_FACTOR=8, MAX_TOKENS_PER_STEP=3, TDT_DURATIONS=[0,1,2,3,4]`（L15-18）——TDT（token-and-duration）转写头。
- **核心算法/协议**：流式转写四段：preprocess ONNX(nemo128 特征)→encode→逐 token decode_step：喂上一 token 或 blank、`input_states_1/2` 递归状态（L265-292）→每步最多产 3 token、按 TDT 持续值跳帧；词汇表把 ▁(U+2581) 还原为空格（L165）。
- **设计模式与工程决策**：① 三重隐私约束表驱动设计：音频不出机、转写不出机（Ollama/内置 LLM 可选）、无云存（SQLite）；② int8 量化模型优先加载、缺失则回退 fp32（model.rs:L95-113）；③ 保留 legacy FastAPI backend 为独立部署目标，新旧架构共存。
- **教学映射**：多模态（语音→文本→结构化摘要全管线）+ 透视Agent系统工程
- **一句话本质**：用 ONNX 把一场会议的声波圈进你自己的 CPU。

## 组内横断发现

1. **"反思先于行动"成为工业惯例**：page-agent 的 MacroToolInput{evaluation_previous_goal,memory,next_goal,action}（types.ts:L171-185）与 openai-agents 的 output_type 结构化收束是同一范式两极——前者把 CoT 塞进单个 union schema 强制每步输出，后者用 guardrails 在出口验证；RAG_Techniques 的 Self-RAG/CRAG notebook 是其学术原型。
2. **浏览器操作的三种世界模型对立**：page-agent=页面内 JS 直改 DOM（零基础设施）；sim 桌面版 driver.ts:L5-17 明确论证"合成 KeyboardEvent 永不触发默认编辑"，改走 trusted CDP 事件+串行队列+三纪元防竞态；herdr 则完全不操作、只做屏幕启发式只读观测。侵入性递减，可靠性逻辑各异。
3. **长任务=可序列化状态机**：chroma WAL3 Manifest（ETag 条件写断点续传）、sim ExecutionSnapshot+_pauseMetadata.resumeLinks、openai RunState、herdr live_handoff——四仓各自独立发明"暂停点=唯一 ID+完整快照"。
4. **规则外置为数据是共同治熵手段**：herdr 三层 TOML manifest 热重载（应对 Agent UI 漂移）、page-agent customTools 覆盖/删除、SK 的 ADR+FEATURE_MATRIX、chroma 客户端工厂仅翻 settings 标志——把变更频率高的部分从编译产物中剥离。
5. **独家发明清单**：chroma——S3 conditional-put 充当无协调者共识+压实感知背压；herdr——PendingIdleConfirmation 700ms 迟滞滤波消除状态抖动；meetily——Rust 侧 TDT 逐 token 流式解码；sim——EdgeManager 对未选分支的"后代失活"传播；openai——handoff/as_tool 二元公理系。
