## 组内横断发现

1. **"纯核+宿主"双注册表成范式**：CodexBar（CodexBarCore 描述符 vs CodexBar 实现，CLI/GUI 同管线）、suna（IAM engine vs iam-client 前端 SDK）、eliza（core 运行时 vs agent/app 壳）不约而同把"可测逻辑核"与"UI/宿主适配层"拆成两个注册表——60+ provider、数十插件的可维护性全靠这一刀。
2. **结构强制对抗 LLM 不可靠，光谱从粗到细**：eliza 逐回合动态 GBNF 文法（最强）→ WeKnora `<knowledge_bases>` XML+协议提示（中）→ vercel/chatbot `stripFences` 事后剥围栏（最朴素的"文法"）——同一问题三种工程价位，教学上可连成一条约束解码演进线。
3. **递归+衰减+预算的三件套护栏**：deep-research（breadth/2+depth-1）、eliza（maxTrajectoryPromptTokens+TrajectoryRecorder）、WeKnora（MAX_ITERATIONS=100+200k token 预算+Consolidator 摘要）——自治 agent 的探索控制收敛于同一套"指数衰减宽度 × 硬预算 × 中途摘要"配方。
4. **MCP/插件面坚持"最小暴露"**：WeKnora 手工精选 10 工具拒绝从 CLI 树自动导出（防 destructive verbs 上 agent 面）、eliza 可选插件懒加载+移动端 null-stub、suna 凭证服务端代理不进沙箱——扩展协议普及后，"给 agent 看什么"反而成为显式安全设计。
5. **版本控制思想外溢到 agent 产出与知识**：suna 会话=branch、产出=change request 人审合并；WeKnora chunk/wiki 页版本快照+行级 diff+回滚——"agent 生成物必须像代码一样可 review、可 rollback"正成为 2026 年 agent 平台的共识底座（与 E08 sim 的可恢复快照、chroma 的 manifest 版本化同源）。
