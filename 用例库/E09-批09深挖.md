### iOfficeAI/OfficeCLI
- **DeepWiki**：8 章；Overview 含 L1/L2/L3 三层架构表（SKILL.md:L26-32）
- **架构模式**：C# 单二进制 Office 工具集：`IDocumentHandler` 工厂分派 pptx/xlsx/docx；MCP server（`officecli mcp`）+ `ResidentServer` 常驻进程免重复磁盘 I/O；Node/Python SDK 是薄壳，只做命名管道转发。
- **核心数据结构**：resident 协议（本地 sdk/node/index.js:L27-37）：pipe 名 `officecli-<SHA256(fullpath)[:16]>`（win/mac 路径大写、linux 原样）、一行请求+一行响应 UTF-8 `\n` 结尾、请求 PascalCase `{Command,Args,Props,Json}` 响应 `{ExitCode,Stdout,Stderr}`、剥离 BOM 与尾 `\r`；常量 `BUSY_CONNECT_TIMEOUT_MS=30000 / BUSY_MAX_RETRIES=3 / OPEN_IDLE_SECONDS=720`（L56-61）。
- **核心算法/协议**：① 管道寻址 `canonicalPath`：Windows 上必须 `realpathSync.native` 展开 8.3 短路径（RUNNER~1）才能与 .NET `GetFullPath` 哈希出同名管道（L99-117 注释是跨运行时对齐教科书）；② `rpc` 只重试 CONNECT、绝不重发命令——重发只发生在命令执行前，mutation 永不 double-apply（L188-216）；空响应（resident 中途崩溃）拒绝重送改抛错（L218-229）；③ `-ping` 旁路管道在主管道忙时仍可探活且校验所服务路径（L260-276）。
- **设计模式与工程决策**：① 三层 abstraction：L1 view/get/query（语义视图）→L2 add/set 路径寻址 DOM（`/slide[1]`）→L3 raw XPath 逃生舱；② 内置 HTML 高保真渲染引擎=给 AI"眼睛"，闭合 render→look→fix 环（README:L9）；③ `curl SKILL.md` 一行让 Agent 自装（README:L65-73）；④ 350+ Excel 公式求值器（DW 2.7）。
- **教学映射**：透视Agent系统工程（工具分层与常驻协议）+ 世界模型（文档坍缩为 HTML 视图）
- **一句话本质**：把 Office 操作压进一根命名管道，让 Agent 用路径寻址对文档做 DOM 手术。

- **设计模式与工程决策**：① README 前 45 行全是伦理与免责（仅限虚构角色/学术用途/数据集授权自负，L25-44）——深度伪造时代的合规样板；② 完全离线、不附模型、框架即代码；③ AGPL3。
- **教学映射**：多模态（语音转换全管线）+ 世界模型（内容/音高/音色三轴解耦表示）
- **一句话本质**：砍掉 VITS 的文本塔，用"内容+F0+音色"三轴分解给歌声换嗓子。

- **核心算法/协议**：① 环检测：最近 10 步窗口内 `SHA-256(tool名+input JSON+output)` 签名重复>5 次即判定死循环（loop_detection.go:L11-71）；② 派发三态串行化：accepted→(cancel-on-entry | queued | active) 在 `dispatchMu` 下原子转移；③ `agentic_fetch` 工具：网页>阈值落临时 .md 文件，起 small-model 子 Agent 用 view/grep 分析而非塞上下文（agentic_fetch_tool.go:L117-138）；子 Agent 工具不重复过 hook 防用户钩子被跑 N 次（L176-179）；④ backend `SendMessage` fire-and-forget + must-deliver `RunComplete` broker 保证 `crush run` 等待者必得终态（backend/agent.go:L30-80）。
- **设计模式与工程决策**：① 自研 `csync` 泛型并发容器（Value/Slice/Map）承载全部热更新；② LSP/MCP/权限/Hook 系统齐备，双模型 large/small 分工（标题生成/摘要用 small）；③ README 中英双语，Charm 生态（fantasy provider+catwalk 模型注册表）复用。
- **教学映射**：透视Agent系统工程 + 多Agent协作（子 Agent 委派+成本上卷回父会话）
- **一句话本质**：用 Go 并发原语把 Coding Agent 的排队/取消/防环锻成一台显式状态机。

## 组内横断发现

1. **可重入安全是 Agent 工程的共同暗线**：OfficeCLI"只重连不重发命令"防 mutation double-apply（sdk index.js:L188-229）、crush cancelMark 接受序号高水位+派发三态、task-master `<loop-blocked>` 信号——三仓各自发明了"忙时排队、取消精确到次"的串行化协议，这是多步 Agent 的通用难题解。
2. **元数据→代码生成消灭跨语言样板**：opendataloader `convert-options.generated.js` 同步三语言 CLI 选项、mlflow `dev/pyproject.py` 一源生三包、task-master paths.ts 90+ 项目界标表——把"容易漂移的双份真相"压缩成单一声明源。
3. **Agent 工具粒度对立路线**：serena 主张符号级高层工具（ReplaceSymbolBody 原子替换 vs 8-12 步文本手术）vs repomix/crush 的"扁平文本+海量上下文"（打包/glob/grep）路线；而 crush 两手都抓（LSP+view/grep 并存），deepagents 靠 middleware 让粒度可插拔——粒度之争正走向"按任务混合"。
4. **安全边界一律下沉到传输/沙箱层**：deepagents 明文"trust the LLM"（沙箱即边界）、OfficeCLI SDK"绝不绕过管道直接碰文件"（防与 resident 竞态即安全属性）、task-master Docker sandbox 循环、mlflow K8s SA token 60s 轮转缓存——无人指望模型自律。
5. **"给 Agent 眼睛"的渲染前处理层**：OfficeCLI HTML 高保真渲染（render→look→fix 闭环）、opendataloader annotated PDF/bounding boxes、crush agentic_fetch 网页落盘再 grep——把非文本世界转成模型可读中间表示，是本批 Agent 工具的共同前置投资。
