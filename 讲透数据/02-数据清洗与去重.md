## 一、直觉层

### 1.1 一个具体时刻

> 2023 年初，Meta LLaMA 团队赶在论文截稿前一个月跑最终 ablation。一名工程师把 Common Crawl 的"近似去重阈值"从 0.9 降到 **0.8**——也就是把 Jaccard 相似度 ≥ 0.8 的文档对都视为重复。**一次重训**，7B 模型在 MMLU 上掉了 1.3 分；团队回滚，确认去重阈值是**比学习率还敏感的旋钮**。
>
> 同一时间，OpenAI 在 GPT-4 报告里轻描淡写一句："我们对 benchmark 进行了 substring 匹配去污"——但社区随后发现 MMLU 的若干题目依然漏进了预训练数据。**角色**：你（数据工程师）。**冲突**：去重太狠丢多样性，去重太松算力和评估都虚高。**时刻**：你盯着 datasketch 跑出来的"重复文档占比 31%"那个数字，意识到——**清洗不是预处理，是模型行为的第一性变量**。

这就是本章的问题：**怎么用工程手段把"重复"和"污染"两个抽象概念量化、检测、控制**。

### 1.2 三类必须清洗的对象

| 类别 | 定义 | 不清洗的后果 |
|---|---|---|
| **近重复**（near-duplicate）| 同一篇文章被镜像 / 改写 / 自动翻译 | 算力浪费、记忆偏向、eval 虚高 |
| **Contamination**（污染）| 训练集包含 eval/benchmark 的题面 | benchmark 失真、研究不可比 |
| **PII**（个人身份信息）| 姓名、邮箱、电话、身份证、信用卡 | 隐私泄漏、合规违法、模型"反刍" |

## 二、数学层

### 2.1 Jaccard 相似度与精确去重的代价

对两份文档 $d_1, d_2$，先做 k-shingle（连续 k 个 token 的片段集合）：

$$S_k(d) = \{ (w_i, w_{i+1}, \dots, w_{i+k-1}) : i = 1, \dots, |d|-k+1 \}$$

**Jaccard 相似度**：

$$J(d_1, d_2) = \frac{|S_k(d_1) \cap S_k(d_2)|}{|S_k(d_1) \cup S_k(d_2)|} \in [0, 1]$$

精确计算需要两两比对：$O(N^2 \cdot |S_k|)$——10 亿文档要做 $5 \times 10^{17}$ 次集合运算，**不可行**。这是 MinHash 存在的根因。

### 2.2 MinHash — 用哈希近似集合

**核心思想**：用一个随机置换 $\pi$ 把集合元素打乱，取最小哈希值作为集合的"指纹"：

$$h_\pi(S) = \min_{x \in S} \pi(x)$$

**关键定理**（Broder 1997）：

$$\Pr[h_\pi(S_1) = h_\pi(S_2)] = J(S_1, S_2)$$

即"两个集合 MinHash 相等的概率 = Jaccard"。用 $n$ 个独立置换做 $n$ 次独立估计，**期望就是 Jaccard，方差为 $J(1-J)/n$**。这就是 `num_perm=128` 的含义——128 次置换换一个无偏估计。

**适用边界**：MinHash 只对"近重复"敏感，对**语义改写**（换词不换义）无效。改写检测要用 SimHash 或 embedding 相似度——但二者在大语料上的 false positive 比 MinHash 高一个量级。

### 2.3 LSH — 把 MinHash 桶进候选对

**问题**：即使有 MinHash，$N$ 个文档两两比签名还是 $O(N^2)$。

**LSH（Locality-Sensitive Hashing）**：把 $n$ 个 MinHash 签名切成 $b$ 段（每段 $r$ 个，$b \cdot r = n$），**只要任一段完全相同就把两份文档拉成候选对**，再对候选对算精确 Jaccard。

**调参的"和恒等式"**（threshold ≈ $(1/r)^{1/b}$）：

| num_perm | r | b | 近似 threshold |
|---|---|---|---|
| 128 | 8 | 16 | 0.62 |
| 128 | 5 | 25 | 0.55 |
| 128 | 16 | 8 | 0.76 |

调 $r, b$ = 调"召回/精度权衡"——这就是 1.1 节 LLaMA 团队调 0.8 vs 0.9 的数学背景。

### 2.4 Contamination 检测 — 为什么 substring 匹配不够

benchmark 污染的检测信号：

$$\text{contam}(b, D) = \mathbb{1}\left[\exists d \in D : \text{ngram}(b, n) \subseteq \text{ngram}(d, n)\right]$$

- **n-gram 精确匹配**（OpenAI GPT-4 tech report 用法）：n=8 或 10，命中即视为污染。**漏检率高**——只要题面被改一个字就逃过。
- **MinHash 近匹配**：把每道 benchmark 题也做 MinHash，与训练数据 LSH 碰撞即标记。**召回高但精度低**——很多"看似相似"其实只是常规模板（如 "What is the capital of X?"）。
- **语义匹配**（embedding）：精度最高，但**你不知道 eval set 是否被压进 embedding 库**，本身又有污染风险。

**目前没有完美方法**——所有 benchmark 都得标注"潜在污染比例"才可比较。

### 2.5 PII 脱敏的形式化

把文档里的 PII 跨度 $s$ 替换成 $[REDACTED\text{-}T]$（T 是类型），目标：

$$\min_{\text{redact}} \mathbb{E}_{d}[\text{PII missed}(d)] \quad \text{s.t.} \quad \text{utility}(d_{\text{redacted}}) \geq (1-\epsilon) \cdot \text{utility}(d)$$

utility 指训练后下游性能。**根本矛盾**：脱敏越狠隐私越好、性能越差。Presidio / Microsoft 的工具栈默认偏保守（高召回低精度），导致**大量非 PII 被误删**——这是为什么很多团队干脆自己写规则。

## 三、代码层

真实可跑的 MinHash + LSH 去重（用 `datasketch`）：

```python
# pip install datasketch
from datasketch import MinHash, MinHashLSH

def shingles(text, k=5):
    tokens = text.split()
    return {" ".join(tokens[i:i+k]) for i in range(len(tokens) - k + 1)}

def make_minhash(text, num_perm=128):
    m = MinHash(num_perm=num_perm)
    for s in shingles(text):
        m.update(s.encode("utf-8"))
    return m

def dedup(documents, threshold=0.8, num_perm=128):
    # threshold = Jaccard 阈值；超过即视为重复
    lsh = MinHashLSH(threshold=threshold, num_perm=num_perm)
    kept = []
    for doc_id, text in enumerate(documents):
        m = make_minhash(text, num_perm)
        # query 返回所有 Jaccard >= threshold 的已存文档 id
        if lsh.query(m):
            continue                      # 命中已有文档 → 丢
        lsh.insert(str(doc_id), m)
        kept.append(text)
    return kept

# Contamination 检测：把 benchmark 题面也建索引
def detect_contamination(train_docs, eval_items, threshold=0.5):
    lsh = MinHashLSH(threshold=threshold, num_perm=128)
    for i, doc in enumerate(train_docs):
        lsh.insert(f"train_{i}", make_minhash(doc))
    flagged = []
    for j, q in enumerate(eval_items):
        hits = lsh.query(make_minhash(q))
        if hits:
            flagged.append((j, hits))     # 题号 + 命中的训练文档
    return flagged
```

**PII 脱敏**（用 spaCy + regex 的常见组合）：

```python
import re, spacy
nlp = spacy.load("en_core_web_sm")

PII_PATTERNS = {
    "EMAIL": re.compile(r"[\w.+-]+@[\w-]+\.[\w.-]+"),
    "PHONE": re.compile(r"\+?\d[\d\s\-()]{8,}\d"),
    "SSN":   re.compile(r"\b\d{3}-\d{2}-\d{4}\b"),
    "CARD":  re.compile(r"\b(?:\d[ -]*?){13,16}\b"),
}

def redact(text):
    for t, p in PII_PATTERNS.items():
        text = p.sub(f"[REDACTED-{t}]", text)
    doc = nlp(text)
    # NER 覆盖 PERSON / GPE / ORG（按需开关，ORG 常误杀）
    return "".join(
        f"[REDACTED-{ent.label_}]" if ent.label_ == "PERSON" else tok.text_with_ws
        for tok in doc
    )
```

**反直觉数字**：LLaMA 论文报告，**1T tokens 训练集去重后保留了约 67%**——也就是丢了 1/3。CCNet pipeline 在更激进的 threshold 下保留率会跌到 **40-50%**。清洗本身在烧算力。

## 四、不足层

诚实标注本章方法的边界：

- **已证明的**：MinHash 是 Jaccard 的无偏估计，LSH 的 recall/precision 由 $(r, b)$ 调节，理论清晰（Broder 1997）。
- **经验但未证**：去重 threshold（0.7 vs 0.8 vs 0.9）的最优值随下游任务变化——LLaMA 报告 0.8，Phi 系列没披露。**没有跨任务通用最优**。
- **未解**：
  1. **语义重复**：同一事实被改写、翻译、转述成 N 个版本，MinHash 抓不到——而它们对算力的浪费和对 eval 的虚高一样严重。
  2. **AI slop 检测**：2024 年后 CC 里混入大量低质 LLM 生成内容，**和人类文本的 n-gram 分布几乎一样**，传统去重 / PPL 过滤都失效。
  3. **污染判定标准**：n=8 还是 n=10？是否做语义匹配？**业界没有共识**，导致同一 benchmark 在不同模型上不可比（见 [`讲透科学的现代性/02`](../讲透科学的现代性/02-可重复性危机.md)）。
  4. **PII 召回率无上界保证**：所有开源工具栈在低资源语言上的召回率低于 60%——**这是合规盲区**。
  5. **机器 unlearning 仍开放**：PII 一旦被训练进权重，"忘掉"它没有高效方法（见 [06 章](./06-数据伦理与合规.md)）。

## 五、费曼回炉（L2 自检）

- **F2 卡壳点**：我最初以为"去重就是去完全一样的文档"。卡在 `datasketch` 文档里的 `threshold=0.8` 到底指什么——重读 Broder 论文才知道它指 **Jaccard 阈值**，且 MinHash 是它的无偏估计。再卡在 LSH 的 $(r, b)$ 参数——后来才明白 $r \cdot b = n$ 是个约束、调它们等于调 recall/precision 的权衡曲线。
- **F3 术语翻译**：
  - "shingle" → 把文档切成连续 k 词的小片段集合，用来比对"长得像不像"。
  - "MinHash 签名" → 一个文档的 128 维指纹，每个维度是个哈希值，两份文档指纹里相等的位数 ≈ Jaccard。
  - "LSH" → 把指纹分段，任意一段完全撞上就拉成候选对，省下两两比对的算力。
- **F4 回炉**：v1 把 threshold 默认设 0.9，结果召回不够、eval 虚高；v2 改 0.8 并加 5-gram + 10-gram 两套 shingle 互补，召回/精度曲线更稳。
