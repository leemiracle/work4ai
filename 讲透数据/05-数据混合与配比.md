# 05 · 数据混合与配比 — DoReMi、Chinchilla 之外的因素

> 承接 [00-数据是新的代码](./00-数据是新的代码.md)（Chinchilla 给出**算力-参数-数据总量**的最优配比）和 [02 清洗](./02-数据清洗与去重.md)/[04 合成](./04-合成数据.md)（数据从哪来、怎么洗）。但 Chinchilla 只回答了"训多少 token"——**没回答"这些 token 在不同 domain 之间怎么分"**。这一章钻进后一个问题：**给定训练预算，代码 / 网络 / 论文 / 多语言各占多少才是最优**？
>

## 一、直觉层

### 1.1 一个具体时刻

> 2023 年，Meta 在 LLaMA-2 上发现一个反直觉现象：把**代码数据从 4.5% 拉到 5%**（其他不变），不只是代码 benchmark 涨——**数学推理也跟着涨**。Code 数据**像维生素**：少量必需，过量不必然更好但缺了会贫血。
>
> 2024 年 DeepMind 的 DoReMi 论文（Xie et al.）把这个直觉变成算法：**让一个 280M 的小模型跑参考配比，用多臂老虎机调每个 domain 的权重，把最优权重复制到 8B 大模型上——下游性能涨 5%+，算力还省 25%**。
>
> **角色**：你（数据科学家）。**冲突**：算力预算固定，每个 domain 都想吃更多。**时刻**：你盯着 DoReMi 的曲线——意识到"配比"是 Chinchilla 之外**还没被理论上界定的第二个 scaling 维度**。

这就是本章：**Chinchilla 解决了"训多少"，但"训什么"目前仍是经验主义**。

### 1.2 配比的两条主流经验法则

| 经验法则 | 来源 | 内容 |
|---|---|---|
| **LLaMA / RedPajama 配比** | Meta 2023 | CC 67% / C4 15% / GitHub 4.5% / Books 4.5% / ArXiv 2.5% / Wiki 4.5% / 专利 2% |
| **Phi "少而精" 反例** | Microsoft 2023-2024 | 不按域配，按"textbook quality"过滤，各域分布**和 LLaMA 完全不同** |

**核心矛盾**：两条法则都"work"，但**没法用同一套理论解释**——这是 05 章的根本开放问题。

## 二、数学层

### 2.1 Chinchilla 之外 — 配比是第二个维度

[00 章](./00-数据是新的代码.md) 的 Chinchilla 给出**总数据量** D* 和**参数** N* 的最优：

$$N^* \approx C/20, \quad D^* \approx C/20$$

但 D* 是**总 token 数**——没说**各 domain 占比**。设 domain 集合 $\{1, ..., K\}$，配比向量 $\alpha = (\alpha_1, ..., \alpha_K)$，$\sum_k \alpha_k = 1$。**Chinchilla 没给 $\alpha^*$**——这是 05 章填补的空白。

### 2.2 DoReMi 的形式化

**问题陈述**：给定参考配比 $\alpha^{(0)}$（如 LLaMA 配比）、domain loss $\mathcal{L}_k$、总预算 D，求 $\alpha^*$：

$$\alpha^* = \arg\min_{\alpha} \sum_{k=1}^{K} \alpha_k^{(0)} \cdot \mathcal{L}_k(\alpha) \quad \text{s.t.} \quad \sum_k \alpha_k = 1, \alpha_k \geq 0$$

**关键设计**：

1. 在**小模型**（如 280M）上跑**多臂老虎机** —— 每个 domain 是一个 arm，loss 反向更新权重。
2. 收敛后把权重 $\alpha^*$ 复制到**大模型**（如 8B）。
3. **核心假设**：配比的最优性在小模型和大模型间**近似可迁移**——这是"包络定理"的工程近似，**不是严格定理**。

### 2.3 为什么"代码像维生素" — Code 数据的多任务正则

形式化：设代码数据集 $D_{\text{code}}$，下游数学推理 loss $\mathcal{L}_{\text{math}}$。经验观察：

$$\frac{\partial \mathcal{L}_{\text{math}}}{\partial \alpha_{\text{code}}} < 0 \quad \text{当} \quad \alpha_{\text{code}} \in (0, \alpha^*)$$

但拐点之后变平甚至变负——**代码数据有饱和点**。LLaMA-2 / Qwen / DeepSeek 都报告 5-8% 是甜蜜区，**没有理论解释**，**所有团队都是 grid search 调出来的**。

### 2.4 多语言的配比 — Chinchilla 假设的另一个漏洞

Chinchilla 假设数据"同质"——但**英语和小语种的 token 经济性差几个数量级**。Qwen / DeepSeek / Yi 都报告：

- 英语:中文:其他语言 的最优比 ≠ 数据存量比
- 中文数据**信息密度更高**（一个汉字 ≈ 1.5 个英语 token），按 token 计的配比会系统性偏估

**目前没有跨语言的 Chinchilla 推广**——这是多语 LLM 的开放问题。

### 2.5 配比是动态的 — 课程学习的视角

固定配比 $\alpha$ 不是最优——**早期应偏简单数据，后期偏复杂**（curriculum）：

$$\alpha_k(t) = \text{softmax}(\beta_k \cdot g_k(t))$$

$g_k(t)$ 是 domain $k$ 在 step $t$ 的"价值"。Phi-2 / Minicpm / DoReMi 都用了某种形式的动态配比。**最优 curriculum 没有理论**。

## 三、代码层

DoReMi 的极简版（多臂老虎机）：

```python
import numpy as np

class DoReMi:
    def __init__(self, domains, ref_weights, lr=0.01):
        self.domains = domains                  # ["cc", "code", "books", ...]
        self.alpha = np.array(ref_weights, dtype=float)
        self.alpha /= self.alpha.sum()
        self.lr = lr
        self.ref = self.alpha.copy()

    def update(self, losses):
        # losses: dict[domain -> scalar]，每个 domain 在当前 batch 的训练 loss
        weighted = sum(self.ref[k] * losses[k] for k in self.domains)
        for i, k in enumerate(self.domains):
            excess = losses[k] - weighted
            # loss 比参考高的 domain → 加权重
            self.alpha[i] *= np.exp(self.lr * excess)
        self.alpha /= self.alpha.sum()
        return dict(zip(self.domains, self.alpha))

# 用法
domains = ["cc", "code", "books", "wiki", "arxiv"]
ref     = [0.67, 0.045, 0.045, 0.045, 0.025]   # LLaMA 配比（粗略）
ref    += [1 - sum(ref)]                        # 补到 1
sampler = DoReMi(domains, ref)

for step in range(num_steps):
    batch_losses = {k: train_one_batch(k) for k in domains}
    weights      = sampler.update(batch_losses)
    sample_next_batch_with_weights(weights)
```

**反直觉数字**：DoReMi 在 GLaM 8B 上的实验报告——**CC 从 67% 降到 49%、代码从 4.5% 升到 11%**，下游平均涨 5.3%。配比的杠杆比想象大得多。

## 四、不足层

诚实标注数据配比的边界：

- **已证明的**：给定参考配比 $\alpha^{(0)}$，DoReMi 的多臂老虎机收敛性有理论保证（regret bound）。**但 $\alpha^{(0)}$ 是经验输入**，不证明它本身最优。
- **经验但未证**：
  1. 小模型配比 → 大模型配比的**迁移性**没有理论上界保证，DeepMind 报告在 8B 上 work，到 70B 上是否还 work 没公开数据。
  2. "代码 5-8% 是甜蜜区"——LLaMA / Qwen / DeepSeek 经验一致，但**没有第一性原理解释**。
- **未解**：
  1. **没有跨 domain 的 Chinchilla**：N*、D* 之外应该有 $\alpha^*$，但解析形式未知。
  2. **合成数据怎么进配比**：合成数据"信息密度"和真实数据不同，按 token 计会系统性偏估（[04 章](./04-合成数据.md)）。
  3. **多语言最优配比**：跨语 token 经济性差几个数量级，按 token 计的 Chinchilla 失效。
  4. **课程学习无理论**：动态配比显著优于静态，但最优 curriculum 没有形式化。
  5. **DoReMi 的"参考配比"本身是个漏洞**：它把经验配比当 ground truth，只是局部优化。

## 五、费曼回炉（L2 自检）

- **F2 卡壳点**：我最初以为"Chinchilla 已经回答了所有 scaling 问题"。读到 DoReMi 才意识到——Chinchilla 只回答了"训多少 token"，**没回答"这些 token 怎么分"**。配比是第二个未界定的 scaling 维度。再卡在"为什么代码量只占 5%"——经验一致但没人给出第一性解释，承认这是开放问题。
- **F3 术语翻译**：
  - "Domain weight" → 每个数据源（代码/网络/书籍）在训练采样时所占的概率。
  - "DoReMi" → 用一个小模型跑参考配比，自动调权重复制到大模型上的算法。
  - "Curriculum" → 不固定配比，按训练进度动态调（早期简单，后期复杂）。
- **F4 回炉**：v1 把配比和 Chinchilla 混在一起讲；v2 拆出"Chinchilla 解决了总量、配比是第二个未界定维度"，并用 KL/loss 视角解释 DoReMi 的多臂老虎机。
