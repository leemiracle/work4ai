# 00 · 数据是新的代码

> **第一性问题**：Scaling law 说"算力↑ → 性能↑"，但**真的只要堆算力就行吗**？
>
> 2022 年 Chinchilla 论文打脸了这个朴素信念——GPT-3 的 1750 亿参数其实**严重欠训**，因为算力和数据必须**同步**增长。从此 AI 工程界意识到：**算力只是引擎，数据才是燃料**。再大引擎没油也跑不动。
>
> 2024-2026 共识再升级：**互联网公开数据快被训完了**——下一波突破要么靠合成数据，要么靠"少而精"的高质量数据。本系列从这个第一性问题切入。
>

## 一、Chinchilla：算力-数据的最优配比

### 1.1 GPT-3 的错误：大模型欠训

2020 年 GPT-3（OpenAI）发布：**1750 亿参数**，震撼业界。但 2022 年 DeepMind 的 Chinchilla 论文（70B 参数）打脸：

| 模型 | 参数 | 训练数据 | 性能 |
|---|---|---|---|
| GPT-3 | **175B** | 300B tokens | 基线 |
| Chinchilla | **70B**（小 2.5 倍）| **1.4T tokens**（多 4.7 倍）| **超过 GPT-3** |

**结论**：GPT-3 的参数和数据严重**不匹配**——参数太大，数据太少，模型记不住该记的，泛化不好。

### 1.2 Chinchilla 最优配比

```
Chinchilla scaling law（Hoffmann et al., 2022）：

给定算力预算 C（FLOPs），最优：
    N*（参数）  ≈ C / 20
    D*（数据）  ≈ C / 20
即：参数和数据应按 1:1（以 token 计）同步增长
```

**直觉**：每个参数应该被训练 ~20 个 token，才能榨干它的容量。

### 1.3 启示：算力墙变成数据墙

如果继续按 Chinchilla 配比放大：
- GPT-4 级（10T tokens 训练）→ 用掉互联网公开文本的相当部分
- GPT-5 级（100T tokens）→ **互联网公开数据不够了**

> 🎯 **核心**：算力墙还没到，**数据墙先到**。2024 年开始，业界普遍认为**数据是真正的瓶颈**。

## 二、数据墙：互联网公开数据的极限

### 2.1 数据从哪来

```
大模型预训练数据金字塔（按质量从高到低）：
    代码（GitHub）       高质量、结构化、稀缺
    书籍（Books3/Gutenberg） 长文本、连贯
    论文（arXiv/PubMed）   专业、严谨
    维基百科              高质量百科
    新闻                  时效性、严谨
    网页（Common Crawl）   海量但噪声大、低质
    社交媒体              低质、毒性高
```

**Common Crawl 占预训练数据 60-80%**（按 token 量），但**质量最参差**。

### 2.2 数据墙的证据

- **Epoch AI 估算**：高质量文本数据存量约 **4.6e12 tokens**（2024），按当前消耗速度，**2026-2028 年将用尽**
- **重复数据无效**：把同一份数据训两遍，效果不如训一遍新数据（重复数据训练有 diminishing returns，甚至退化）
- **去重后更少**：Common Crawl 去重后只有原始的 30-50%

### 2.3 数据墙的对策

| 路线 | 思路 | 代表 |
|---|---|---|
| **合成数据** | AI 生成训练数据 | Phi 系列、R1 蒸馏（详见 [02](./02-合成数据工程待写.md)）|
| **多模态** | 把图像/视频/音频转为可学信号 | GPT-4V、Gemini |
| **私有数据** | 用企业/政府私有数据 | BloombergGPT、Med-PaLM |
| **强化学习** | 不依赖静态数据，从环境学 | R1-zero、AlphaProof |
| **持续学习** | 不断吸收新数据，不一次性训 | 数据飞轮 |

> 🎯 **业界 2026 现状**：合成数据 + 多模态是主流，但 Model Collapse 风险未解（详见 [03](./03-Model-Collapse.md)）。

## 三、Quantity → Quality 范式转移

### 3.1 旧范式：堆量

2020-2023 主流："**更多数据 = 更好模型**"——把 Common Crawl 全抓来训。

### 3.2 新范式：精炼

2024 转折：**Phi 系列**（Microsoft）证明——用**少量高质量数据**能训出**性能超 10 倍数据量模型**的小模型。

```
Phi-1（2023）：1.3B 参数，只用 "textbook quality" 代码数据
    → 在 HumanEval 上超过用 100 倍数据训的模型
Phi-2、Phi-3：把这个范式推到通用文本
```

**"Textbook quality"** 是关键——**数据质量比数据量重要一个数量级**。

### 3.3 但"质量"是什么——开放问题

**数据质量没有统一理论**，目前经验主义分四维：

| 维度 | 含义 | 衡量 |
|---|---|---|
| **多样性** | 覆盖不同主题/风格/难度 | n-gram 多样性、聚类 |
| **难度** | 信息密度高、需要推理 | 困惑度、信息熵 |
| **毒性** | 有害、偏见、违法内容 | 分类器、规则过滤 |
| **重复** | 信息冗余 | MinHash、精确去重 |

> 🎯 **核心矛盾**：质量比量重要——但**怎么自动衡量"质量"没有共识**。Phi 的"textbook quality"也是人挑的，不可大规模复制。

### 3.4 DataComp：用基准测数据集

**DataComp**（2023-2024）开创了**数据集的 ImageNet 时刻**——固定模型架构，让研究者**只比拼数据集**。

```
任务：固定 CLIP 架构
目标：参赛者只改数据管线（filter/augment），不改模型
评测：在标准 benchmark 上比性能
```

**意义**：第一次让数据成为**可量化、可比的研究对象**——而不是"工程师的玄学"。

## 四、合成数据：双刃剑

### 4.1 合成数据的方法谱系

```
① Self-Instruct（2022）：用 LLM 生成指令-回答对（Alpaca/Vicuna 路线）
② Evol-Instruct（2023）：让 LLM 把简单指令"进化"成复杂（WizardLM）
③ Phi 路线：用 LLM 生成"textbook quality"内容
④ R1 蒸馏（2025）：用强 reasoning 模型生成推理轨迹，蒸馏给小模型
⑤ Self-play：模型自我对弈（辩论/翻译/数学）
⑥ Tooling data：AI 用工具（搜索/计算）生成带 ground truth 的数据
```

### 4.2 收益

- **突破数据墙**：理论上无限供应
- **可控**：可以生成特定主题/难度/风格的数据
- **可对齐**：生成"安全/有用"的示范数据
- **降本**：合成数据比雇佣专家便宜几个数量级

### 4.3 风险——Model Collapse

**核心警告**：用 AI 生成的数据训练下一代 AI，**多代之后模型会退化**（详见 [03 Model Collapse](./03-Model-Collapse.md)）。

```
M0（在人类数据上训）
    ↓ 生成数据
M1（在 M0 数据上训）—— 略退化
    ↓ ...
Mn —— 退化到只会输出几种模式（mode collapse）
```

**这是 AI for AI 的根本性限制**（[`07-AI for AI`](../讲透AI应用全景/07-AI for AI.md) 第④节深讲）。

> ⚠️ **当前缓解**：保留一部分高质量人类数据 + 严格过滤 AI 内容——但**这是权宜之计，根本解未找到**。

## 五、数据工程：被严重低估的"工程"

### 5.1 数据工程的"隐形劳动"

```
真实 ML 项目时间分配（经验估计）：
    数据收集/清洗/验证：60-80%
    模型训练/调参：10-20%
    评估/部署：10-20%
```

但**论文和课程几乎不讲数据工程**——这是 ML 教育和工业的巨大鸿沟。

### 5.2 数据管线的核心步骤

```
原始数据（Common Crawl / 私有源）
    ↓ 1. 提取（HTML → text）
    ↓ 2. 语言识别（过滤非目标语言）
    ↓ 3. 质量过滤（分类器 / 启发式）
    ↓ 4. 去重（MinHash / 精确）
    ↓ 5. 毒性过滤
    ↓ 6. PII 脱敏（个人身份信息）
    ↓ 7. 长度/格式过滤
    ↓ 8. 采样（按主题/语言配比）
训练数据
```

**代表开源工具**：datatrove（HuggingFace）、CCNet（FAIR）、 Dolma（AI2）。

### 5.3 数据版本管理

```
代码：git
数据：DVC（Data Version Control）/ LakeFS / Pachyderm
    → 数据是"代码的依赖"，必须可追溯、可复现
```

## 六、数据的伦理与法律

### 6.1 版权大战

- **NYT vs OpenAI**（2023-）：NYT 起诉 OpenAI 未经授权使用其文章训练
- **作者集体诉讼**：George R.R. Martin 等起诉
- **结果是悬而未决的世纪案**——将决定 AI 训练数据的合法性边界

### 6.2 隐私

- **PII 泄漏**：训练数据中的个人信息可能被模型记住并生成
- **GDPR**：欧盟要求"被遗忘权"——但 LLM 训完怎么"忘记"特定数据？（机器 unlearning 是开放问题）

### 6.3 同意与公平

- 数据创造者（用户/创作者）应该有**知情同意**和**收益分享**吗？
- 当前架构基本是"**抓走不付钱**"——这是 2024-2026 最大的争议。

## 七、开放问题

1. **数据质量有统一理论吗**？能从第一性原理推出"什么是好数据"吗？
2. **Model Collapse 能彻底解决吗**？合成数据的天花板在哪？
3. **数据污染能完全检测吗**？benchmark contamination 怎么彻底防？
4. **小模型 vs 大模型的最优数据策略**？Phi 范式（少而精）和 GPT 范式（多而广）哪个对？
5. **多模态数据怎么训最有效**？图像/视频/文本的最优混合比？
6. **AI 训练数据的伦理/法律框架**？版权/隐私/同意怎么平衡？
7. **数据作为公共品**？高质量数据应该开源还是私有？

> ⚠️ **诚实标注**：数据是 ML 最被低估、也最没理论根基的领域。任何"数据就这么搞"的宣称都是经验主义。

## 八、一句话总结

> 🎯 **四句话**：
> 1. Chinchilla 揭示算力-数据必须**同步增长**——但数据墙先到（2026-2028 公开数据用尽）。
> 2. 范式转移：**Quantity → Quality**（Phi 用 1/10 数据训出超 10 倍数据的模型），但"质量"没有统一理论。
> 3. 合成数据是数据墙的解药，但 **Model Collapse 是根本性风险**（[03 章](./03-Model-Collapse.md)）。
> 4. 数据工程占真实 ML 时间的 60-80%，但**论文和课都不讲**——这是教育-工业的巨大鸿沟。

## 🎭 欺骗动力学视角：数据污染与投毒

> 承接 [`欺骗动力学-社会进步的隐秘引擎.md`](欺骗动力学-社会进步的隐秘引擎.md) §5。

### 三问

1. **讲透数据 防的是什么欺骗？** → 训练数据被注入恶意样本或低质内容。
2. **被什么攻破？** → 数据集污染 / 后门触发器 / Model Collapse。
3. **沉淀进哪条主链？** → 验证主链——数据完整性审计 / 数据卡 / 数据集复现。

### 一句话

> 数据是模型的上游，污染的数据就是在源头注入欺骗；数据工程的核心是反投毒。
