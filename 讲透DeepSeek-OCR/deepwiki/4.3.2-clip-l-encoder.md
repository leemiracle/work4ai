## Purpose and Scope

 The CLIP-L Encoder is one of two vision encoders in the DeepSeek-OCR dual-encoder architecture. It provides semantic understanding and high-level visual features through a standard Vision Transformer (ViT) architecture with global attention mechanisms. This encoder complements the SAM encoder (see [4.3.1](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/4.3.1)) by capturing semantic information that aids in understanding document structure and content.

 This page covers the CLIP-L encoder's architecture, components, and processing pipeline. For information about how CLIP features are combined with SAM features, see [4.3.3](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/4.3.3) For the overall vision encoding system, see [4.2](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/4.2)

 **Key Characteristics:**

 
 - **Global Attention:** Unlike SAM's window attention, CLIP uses full self-attention where each token attends to all other tokens.
 - **Multi-Head:** 16 attention heads with 64-dimensional head size (1024 / 16 = 64).
 - **Flexible Backend:** Supports `flash_attn_qkvpacked_func` [DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py246](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py#L246-L246) for efficiency or PyTorch `scaled_dot_product_attention` [DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py270](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py#L270-L270) for compatibility.
 - **No Causal Masking:** All tokens can attend to all positions (bidirectional).

## Configuration

 The CLIP-L encoder configuration is defined in `vit_model_cfg` [DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py427-445](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py#L427-L445):

 
| Parameter | Value | Description |
|---|---|---|
| num_layers | 24 | Number of transformer blocks |
| hidden_size | 1024 | Dimension of hidden representations (CLIP-L standard) |
| num_attention_heads | 16 | Number of attention heads per layer |
| ffn_hidden_size | 4096 | Feed-forward network intermediate dimension (4× hidden) |
| seq_length | 256 | Maximum sequence length |
| image_size | 224 | Input image size (can be interpolated) |
| patch_size | 14 | Size of each image patch (14×14 pixels) |
| use_flash_attn | False | Whether to use Flash Attention or SDPA |
| layernorm_epsilon | 1e-5 | Epsilon for LayerNorm stability |
| attention_dropout | 0.0 | Dropout rate in attention (disabled) |
| hidden_dropout | 0.0 | Dropout rate in hidden layers (disabled) |

 **Patch Grid Calculation:**

 
 - For a 224×224 image with 14×14 patches: `(224/14)² = 16² = 256` patches.
 - With CLS token: `256 + 1 = 257` total tokens.
 
 The `build_clip_l()` factory function [DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py447-452](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py#L447-L452) instantiates the encoder with these settings and no frozen parameters.

## Integration with Dual-Encoder System

 The CLIP-L encoder works in conjunction with the SAM encoder to provide complementary visual features. As demonstrated in the test code [DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py495-504](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py#L495-L504) the typical usage pattern involves:

 
 - SAM encoder processes the image first.
 - These embeddings can optionally be reused as input to CLIP's `patch_embedding` [DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py138-142](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py#L138-L142)
 - CLIP encoder processes with its global attention mechanism.
 - Features from both encoders are combined (typically element-wise addition after alignment).
 
 **Sources:** [DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py455-504](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py#L455-L504)

## Special Features

 
### FP32 Layer Normalization

 The encoder supports optional FP32 LayerNorm [DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py54-60](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py#L54-L60) through the `LayerNormfp32` class, which casts inputs to `float32` before normalization and then back to the original dtype. This can improve numerical stability during training while maintaining mixed-precision efficiency.

 
### Freezable Components

 The `VitModel` constructor accepts `freeze_embed` and `freeze_pre_norm` parameters [DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py363-398](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py#L363-L398) allowing selective freezing of:

 
 - Patch embeddings, class token, and positional embeddings.
 - Pre-transformer LayerNorm weights.
 
 
### Micro Data Parallelism Flag

 All parameters are marked with `p.micro_dp = True` [DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py400-401](https://github.com/deepseek-ai/DeepSeek-OCR/blob/09eaf526/DeepSeek-OCR-master/DeepSeek-OCR-vllm/deepencoder/clip_sdpa.py#L400-L401) indicating support for micro-batch data parallelism during distributed training.
