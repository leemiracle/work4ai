# Part Ⅰ — 情感分析（Sentiment Analysis）

## 1. 直觉：情感分析到底分析什么

情感分析不是一个任务，是**一族任务**。SLP3 把它拆成三个正交的维度：

**① 极性（polarity / valence）** —— 最常见。一句话是正向、负向还是中性？
- "这家餐厅太好吃了" → positive
- "服务态度极差" → negative
- "我在楼下" → neutral

**② 情绪类别（emotion / affect）** —— 更细。不是好/坏，而是具体是哪种情绪。
- Ekman 六大基本情绪：anger（愤怒）/ joy（喜悦）/ fear（恐惧）/ sadness（悲伤）/ disgust（厌恶）/ surprise（惊讶）
- Plutchik 八情绪轮：在 Ekman 基础上加 trust（信任）/ anticipation（期待）
- "这款手机让我太失望了" → disappointment（属于 sadness 家族）

**③ 强度（intensity / strength）** —— 连续值。不是二分，而是"多强烈"。
- "还行" vs "还行吧" vs "相当不错" vs "简直完美" —— 强度递增
- 强度常映射到 `[-1, +1]` 或 `[1, 5]`（五星评分）

> **关键洞察**：极性是"分类"、强度是"回归"、情绪是"多分类"。同一个情感分析，换个目标函数就是不同任务。这也是为什么情感分析在工业界无处不在——电商评论、舆情监控、金融情绪指数、客服质检，全是它的变体。

## 2. 词典方法：最古老的 baseline，至今没死

### 2.1 核心思想

> **直觉**：如果一句话里"好词"比"坏词"多，它就是正向的。

这是朴素贝叶斯之前、甚至统计学习之前的情感分析方法：**人工编一份"情感词典"**（lexicon），每个词标一个情感值（valence ∈ [-4, +4]），然后把句子里所有词的情感值加起来。

这听起来"太简单"，但它有一个监督学习永远比不上的优势：**零训练数据**。词典是人工标注好的，拿来就用。

### 2.2 四大经典情感词典

| 词典 | 来源 | 特点 | 规模 |
|------|------|------|------|
| **LIWC**（Linguistic Inquiry and Word Count）| Pennebaker 等，心理学 | 不只是情感，还有 80+ 心理类别（焦虑、社交、认知…），按"百分比"输出 | ~6,400 词 |
| **VADER**（Valence Aware Dictionary and sEntiment Reasoner）| Hutto & Gilbert, 2014 | **为社交媒体优化**，带规则（否定/强调/标点/大小写），至今是工业界最常用 | ~7,500 词 |
| **SentiWordNet** | WordNet 派生 | 每个 WordNet 同义词集（synset）给 pos/neg/obj 三个分数，可自动生成 | ~117,000 synset |
| **HowNet（知网）** | 董振东，中文 | **中文情感词典的鼻祖**，在"义原"（sense）层面标情感，粒度极细 | 数万中文词 |

> **中文特别说明**：HowNet（知网）是中文 NLP 不可绕过的资产。它不只是情感词典，而是一整套"概念—义原"知识库（每个词拆成义原的组合）。基于 HowNet 衍生的中文情感词典（如 NTUSD、大连理工情感词典）至今是中文情感分析的传统主力。中文还有 BosonNLP 词典、SnowNLP 内置词典等。

### 2.3 VADER 算法详解（三层讲透）

VADER 是这一节的明星，因为它的设计**把"符号规则"发挥到了极致**——纯规则、零训练，却在社交媒体和产品评论上长期吊打一票监督模型。我们的实验就复刻它。

**直觉层**：好词加分、坏词减分，但"not good"要把"good"的分翻过来、"very good"要加码、"GOOD!"要更猛。所有这些"但"都是规则。

**公式层**：

对句子里每个在词典中的词 $w$，先取基础情感值 $\text{val}(w)$，再用规则修正：

1. **全大写**：若 $w$ 在原文里全大写且 $\text{val}(w)>0$，则 $\text{val}(w) \mathrel{+}= 0.733$；负向词则 $\mathrel{-}= 0.733$。
2. **程度副词**：往前看 1–2 词。若是增强词（very/really/so…），$\text{val}(w) \mathrel{+}= 0.293$；若是削弱词（slightly/kind of…），$\mathrel{-}= 0.293$。
3. **否定**：往前 3 词窗口内若有否定词（not/never/n't…），$\text{val}(w) \mathrel{*}= -0.74$（既翻转又衰减）。
4. **标点强调**：若句末有 $n$ 个 `!`（上限 3）且 $\text{val}(w)>0$，$\text{val}(w) \mathrel{+}= 0.293 \cdot n$。

把所有词的修正后情感值求和得 $S$，再做**句级归一化**（这是 VADER 的精髓——把无界的和压回 $[-1,1]$）：

$$\text{compound} = \frac{S}{\sqrt{S^2 + 15}}$$

> 这个 $\alpha=15$ 是个"魔法常数"，本质是个 soft clamp：$S$ 很大时 compound → ±1，$S$ 接近 0 时 compound ≈ $S/\sqrt{15}$，保持线性灵敏度。最后按阈值分类：$\text{compound} \geq +0.05$ → pos，$\leq -0.05$ → neg，否则 neu。

**代码层**（`experiments/22_sentiment_coref.py` 的 `vader_sentiment`）：

```python
# 核心：词典查值 → 4 条规则修正 → 求和 → compound 归一化
for i, tok in enumerate(tokens):
    if tok.lower() not in LEXICON:        # 查词典
        continue
    valence = LEXICON[tok.lower()]
    if allcap:  valence += 0.733          # (1) 全大写
    for back in (1,2):                    # (2) 程度副词
        if tokens[i-back] in BOOSTERS:   valence += 0.293
    for back in (1,2,3):                  # (3) 否定
        if tokens[i-back] in NEGATIONS:  valence *= -0.74; break
    if valence > 0 and n_excl:            # (4) 标点
        valence += 0.293 * min(n_excl, 3)
    total += valence
compound = total / sqrt(total*total + 15) # 归一化
```

跑出来的几个直观例子（实验 PART A 的真实输出）：

| 句子 | compound | 标签 | 起作用的规则 |
|------|---------|------|------------|
| This laptop is great. | +0.625 | pos | 基础值 |
| This laptop is **not** great. | −0.510 | neg | 否定乘子 −0.74 |
| This laptop is **very** great**!** | +0.689 | pos | 副词 + 标点 |
| This laptop is **GREAT!** | +0.729 | pos | 全大写 + 标点 |
| This laptop is **kind of** great. | +0.587 | pos | 削弱副词 |
| The screen broke... Useless. | −0.743 | neg | 多负词累加 |

## 3. 反直觉实验：词典在产品评论上击败监督学习

> 这是本篇的"铁证"。跑 `python3 -u experiments/22_sentiment_coref.py` 的 PART B。

**实验设计**：36 条简短产品评论，前 18 条作训练池（pos/neg/neu 交错），后 18 条作测试集。两个选手：

- **词典法（VADER-style）**：零训练数据，直接用规则打分。
- **朴素贝叶斯（多项式 NB，BoW）**：监督学习家族的朴素代表（BERT 是这个家族的天花板，但需要 1000+ 标注 + GPU）。从训练池取前 N 条训练，扫 N 看准确率。

**结果**（真实跑出来的数字）：

- 词典法（零训练）= **88.9%（18 中对 16）**，仅在 2 条**反讽句**上失败（如 "Oh great, it broke again. Love it." —— 正向词占多数，词典被骗成 pos，但金标是 neg）。
- 朴素贝叶斯在**低数据区（N=3）落后词典十几个百分点**，要积累大量标注才能追平。

### 为什么会这样？——这才是要"讲透"的

```
┌─ 反直觉的根源 ─────────────────────────────────────────────┐
│  产品评论语言简单直白 → 情感词信号极强、噪声极低           │
│  词典法【零训练】就抓住了这个强信号                        │
│  监督法却要"见过足够多例子"才能学会同样的规律              │
│                                                            │
│  推论：监督学习家族(含 BERT 微调)需要 1000+ 标注 + GPU     │
│  才能稳赢词典。在"低数据 + 简单文本"的真实场景，词典反胜。  │
└────────────────────────────────────────────────────────────┘
```

**诚实声明**（这点必须说清）：朴素贝叶斯只是"需训练数据"家族的**朴素代表**。真正 fine-tuned 的 BERT 在 10k+ 标注下能把准确率推到 ~95%，超过词典——但成本是词典的上千倍（标注人力 + 算力）。本实验隔离出的不是"词典永远最好"，而是**"成本-收益"的核心矛盾**：

> 何时该用零成本的词典？何时才值得上昂贵的监督模型？

答案是：**文本简单、标注稀缺、要快速上线 → 词典；文本复杂（反讽/隐式/跨域）、有大量标注、要榨干最后几个百分点 → 监督/LLM**。这就是为什么金融舆情、电商评论、客服质检至今仍大量混用词典——它便宜、可解释、零冷启动。

## 4. 否定、反讽、上下文：词典的"三座大山"

词典方法的天花板，正好是它的三座大山：

**① 否定（negation）** —— VADER 用 "−0.74 乘子 + 3 词窗口" 部分解决，但只覆盖近距离否定。
- "I don't think this is the best choice." → "best" 离 "don't" 太远，窗口抓不到，词典仍判正向。
- 更难的双重否定、范围否定（"Not all of them are bad"），词典基本无能为力。

**② 反讽与讽刺（sarcasm / irony）** —— 词典的**结构性盲区**。
- "Oh great, another bug." → 词典看 "great" 判正向，实际是强烈负向。
- "Just what I needed, another crash." → 同理。
- 反讽的本质是**字面情感与意图情感相反**，而词典只能读字面。这是它永远跨不过的坎，也是神经方法（尤其 LLM）的真正优势区。

**③ 上下文依赖（context dependence）** —— 同一个词在不同语境情感不同。
- "This phone is **cheap**." → 负向（廉价劣质）
- "This phone is **cheap**!" → 正向（性价比高）
- "predictable"（可预测）在剧情片评论里是负向（俗套），在汽车评测里是正向（可靠）。
- 词典给一个词一个固定值，无法处理这种**领域敏感**和**语用反转**。

> 这三座大山解释了为什么情感分析从词典进化到神经网络：不是因为词典"算得不准"，而是因为它**无法理解语境**。BERT/LLM 的优势不在于"好词坏词数得更对"，而在于能编码上下文。

## 5. 神经方法的进化谱系

情感分析的监督方法，是一条标准的"模型越变越大、数据越喂越多"的演化线：

```
词典(符号)  →  朴素贝叶斯/逻辑回归(浅层统计)  →  CNN/LSTM  →  BERT 微调  →  LLM 零样本
 零训练          需几百-几千标注              需万级标注      需千-万级标注    零/少样本
 ~85%           ~88%                        ~91%           ~93-95%         ~93-95%
```

**BERT 微调**（SLP3 Ch 10）：把 `[CLS]` token 的表示接一个分类头，用标注数据微调。这是 2018–2022 年的工业标准，至今仍是"精度/成本"平衡点的默认选择。

**LLM 零样本**（zero-shot）—— 这是 2023 年后的新范式：
```
prompt: "这条评论的情感是正向、负向还是中性？评论：{text}"
```
一句 prompt，无需任何训练，GPT-4 级模型在标准数据集上就能达到 ~93–95%。**情感分析就此被 LLM "收编"**——对绝大多数应用，调 LLM API 比自己训 BERT 更省事、更准。

> 但注意：LLM 收编的是**通用情感分析**。在三个场景下传统方法仍然有用：(1) 极低延迟/极低成本的边缘场景（词典几微秒，LLM 几百毫秒）；(2) 需要**完全可解释**的合规场景（金融、医疗）；(3) **细粒度 aspect-based 情感**（见下节）。

## 6. Aspect-Based 情感分析（ABSA）：情感分析的"高阶形态"

普通情感分析只给整句一个标签。但真实评论常是**混合**的：

> "这家餐厅环境很好，但是上菜太慢了，服务员态度也差。"

整句情感？说不清——**环境正向、速度负向、服务负向**。这就是 **ABSA（Aspect-Based Sentiment Analysis）** 要解决的：把情感拆到每个**方面（aspect）**上。

ABSA 的输出是三元组 `(方面, 方面词, 情感)`：
- (环境, 好, pos)
- (上菜速度, 慢, neg)
- (服务, 态度差, neg)

ABSA 本质上是**两个子任务的组合**：方面抽取（sequence labeling，类似 NER）+ 方面级情感分类。传统用 pipeline（先抽 aspect 再分类情感），现代用端到端 BERT/LLM 一次输出。ABSA 是电商、酒店、餐饮评论分析的核心技术——因为它告诉你**具体哪里好、哪里差**，而不只是一个总分。

# Part Ⅱ — 共指消解（Coreference Resolution）

## 7. 直觉：代词到底指谁

看这句话：

> "玛丽把书递给杰克，**她**冲**他**笑了笑。"

人类毫不费力地知道：**她**=玛丽，**他**=杰克。但对机器来说，这是一个**推理问题**——它得在文本里追踪"玛丽"和"杰克"这两个实体，判断每个代词回指（refer back to）哪一个。

**共指消解（coreference resolution）**的任务就是：**找出文本里所有指代同一实体的表达（mention），把它们聚成簇（cluster）**。

```
"玛丽₁ 把书递给杰克₂。她₁ 冲他₂ 笑了。那个男人₂ 也笑了。"
         ↓ 共指消解
簇1 = {玛丽, 她}
簇2 = {杰克, 他, 那个男人}
```

这里每个**mention**（玛丽/她/他/那个男人）都是指向某个实体的语言表达。共指消解把指向同一实体的 mention 归到一起。

### 几个关键术语

- **Mention（指称）**：指向实体的任何名词性表达——专有名词（"玛丽"）、名词短语（"那个高个子男人"）、代词（"她/他/它"）。
- **Anaphor（照应词/回指词）**：靠回指前文获得意义的表达，典型是代词。"她"是 anaphor。
- **Antecedent（先行词）**：anaphor 所指的前文表达。"玛丽"是"她"的 antecedent。
- **Anaphora（回指）** vs **Cataphora（前指）**：绝大多数是 anaphora（代词在后、先行词在前）；cataphora 反过来——"**他**还没来的时候，**约翰**已经在路上了"（代词在前）。
- **Coreference（共指）** vs **Anaphora（回指）**：两者常重叠但不等同。共指是"指同一实体"（实体层面的关系），回指是"靠前文获得意义"（语言层面的关系）。"no anaconda is an anaconda"里第二个 anaconda 回指第一个，但不共指（没有具体实体）。

> **中文的特殊难点：零指代（zero anaphora / pro-drop）**。中文（和日文）常常**直接省略主语代词**："李雷来了。Ø 看见了一只猫。"第二句主语是"李雷"，但文本里**根本没有代词**——它是个"零代词"(Ø)。英文必须写 "He saw a cat"，中文写"他"反而别扭。这让中文共指比英文难得多：mention 检测器在文本里**根本看不见 Ø**，必须靠句法和语篇推理去"恢复"它。我们的实验 PART C 会演示这一点。

## 8. 共指消解的流水线：先检测，再配对

共指消解分两步：

**Step 1：Mention 检测（mention detection）** —— 找出文本里所有可能的 mention。
- 早期：用句法分析器找出所有名词短语（NP）和代词。
- 现代（end-to-end）：考虑所有可能的**文本 span**（连续 token 片段），用打分函数筛出"哪些 span 像是 mention"。

**Step 2：配对/聚类（resolution / clustering）** —— 决定哪些 mention 指同一实体，聚成簇。

Step 1 看似简单，实则是个独立的难题（尤其要避免把过多 span 都当 mention）。Step 2 是共指的核心，SLP3 讲了**四种架构**。

## 9. 四种架构：从配对到端到端

### 9.1 架构一：Mention-Pair（指称对）模型

**直觉**：把共指变成一个**二分类问题**——给定两个 mention $m_i, m_j$，它们共指吗？用所有 mention 对训练一个分类器。

**公式**：

$$P(\text{corefer}(m_i, m_j) = 1 \mid m_i, m_j) = \sigma\big(\mathbf{w} \cdot \phi(m_i, m_j)\big)$$

其中 $\phi(m_i, m_j)$ 是**特征向量**，$\sigma$ 是 sigmoid。SLP3 列出的经典特征（Soon et al. 2001, Ng & Cardie 2002）包括：

| 特征 | 例子 | 为什么有用 |
|------|------|-----------|
| 字符串完全匹配 | "Mary"..."Mary" | 同名极可能共指 |
| 距离（中间隔几个 mention/句） | 近的更可能共指 | 代词倾向就近回指 |
| 性别一致 | "Mary"(F)..."he"(M) → 冲突 | 性别冲突几乎排除共指 |
| 数一致 | "they"(pl)..."Mary"(sg) → 冲突 | 单复数冲突排除 |
| 语义类别一致 | "Microsoft"(ORG)..."he"(person) → 冲突 | 人和机构不共指 |
| 两者都是代词 | "he"..."he" | 倾向不配（除非很近） |
| 句法角色 | 都是主语？ | 中心理论(centering)的线索 |

**致命缺陷**：mention-pair 的决策是**局部、不一致**的——可能判定 A-B 共指、B-C 共指，但 A-C 不共指，导致传递性矛盾（A,B,C 应该同簇，但分类器说 A,C 不共指）。后两种架构就是为了修这个。

### 9.2 架构二：Mention-Ranking（指称排序）模型

**直觉**：不再问"这对共指吗"，而是问"**这个 mention 最好的先行词是谁**"——对每个 anaphor，给所有候选先行词打分排序，选最高分，配不上的就**新开一个簇**。

**公式**：对 anaphor $m_j$，候选集 = $\{m_1, ..., m_{j-1}, \text{NEW}\}$（含一个"新实体"哑选项），打分后 softmax：

$$P(\text{ant}(m_j) = m_i) = \frac{\exp\, s(m_j, m_i)}{\sum_{k<j} \exp\, s(m_j, m_k) + \exp\, s(m_j, \text{NEW})}$$

$$s(m_j, m_i) = \mathbf{w} \cdot \phi(m_i, m_j)$$

配对时取 $\arg\max$：若最高分是某个 $m_i$，就把 $m_j$ 并入 $m_i$ 所在簇；若是 NEW，就新开簇。

**为什么比 pair 好**：每个 anaphor 只选**一个**最好先行词，天然避免矛盾，保证一致性。这是 2016 年前的主流。

### 9.3 架构三：Entity-Centric / Clustering（实体中心/聚类）

**直觉**：直接建模"实体"这个抽象对象，把共指变成**聚类问题**——在嵌入空间里，把同实体的 mention 拉近、不同实体的推开。

代表方法用**聚类损失**（如 must-link / cannot-link 约束），或对每个实体维护一个表示并增量更新。这类方法理论上最优雅，但工程上不如 ranking 直接。

### 9.4 架构四：End-to-End 神经共指（现代标准）

**直觉**：不再分"检测 mention"和"配对"两步，**端到端**地——对文本里**每一个可能的 span**，既判断它是不是 mention、又判断它的先行词是谁。一步到位。

这是 Lee et al. 2017（*End-to-end Neural Coreference Resolution*）的开创性工作。核心打分：

$$\text{score}(g_i) = s_m(g_i) + \max_{g_j \in \mathcal{Y}(i)} s_a(g_i, g_j)$$

其中 $g_i, g_j$ 是 span，$s_m$ 是"是不是 mention"的分数，$s_a$ 是"$g_i$ 以 $g_j$ 为先行词"的分数，$\mathcal{Y}(i)$ 是 $g_i$ 之前的候选 span 集合。span 的表示用其起止 token 的 BiLSTM/BERT 表示 **拼接 + 注意力池化**得到。

**关键创新**：把 mention 检测和共指决策**统一进一个可微分的目标**，联合训练，不再依赖外部句法器。这开启了神经共指时代。

## 10. 神经共指三巨头

| 方法 | 论文 | 核心贡献 |
|------|------|---------|
| **e2e-coref** | Lee et al., EMNLP 2017 | 端到端，span 表示 + 联合打分，摆脱句法器依赖 |
| **SpanBERT** | Joshi et al., TACL 2019 | **预训练任务革新**：随机 mask **整个连续 span** 而非单个 token，强迫模型学 span 边界语义。共指/关系抽取大幅提升——这是"为下游 span 任务量身定制的预训练" |
| **CorefQA** | Wei et al., EMNLP 2020 | 把共指**表述成问答**：对每个 mention 问"哪些 span 与它共指？"，用 QA 框架统一建模，处理嵌套/长距离更好 |

> **SpanBERT 的启示**值得单独讲：它证明了一个深刻道理——**预训练任务的设计要与下游任务对齐**。BERT 的随机 token mask 对"理解单个词"很好，但对"理解一个短语/span"不够；SpanBERT 专门 mask 整个 span，于是对共指、关系抽取这类"以 span 为单位"的任务收益最大。这是"任务感知的预训练"思想的典范。

## 11. Entity Linking：从 mention 到知识库实体

共指消解解决的是"**文本内部**谁和谁共指"。**Entity Linking（实体链接，EL）**则更进一步：把 mention 链接到**外部知识库（KB）**里的具体实体。

> 例：文本里出现"苹果"，它是水果（Wikidata: Q89）还是公司（Wikidata: Q312）？Entity linking 负责消歧并指到 KB 的确切条目。

EL 的标准两阶段流水线：

**① 候选生成（candidate generation）** —— 给 mention 找 KB 里的候选实体。
- 用别名表（dictionary）：同名实体都列出来。"苹果" → [水果, 公司, 电影《苹果》, …]
- 这一步追求**高召回**（别漏掉正确实体），可以用 KB 的别名表、surface form 扩展等。

**② 候选消歧/重排（disambiguation / ranking）** —— 从候选里选出正确的一个。
- 用**上下文相似度**：mention 周围的词 vs 各候选实体的描述（KB description）。
- 用**实体先验流行度**："苹果"在不加限定时更可能指公司。
- 现代方法：用 BERT 编码 mention 上下文 + 实体描述，算相似度，或直接做 KB 内的 link prediction。

EL 和共指常**联动**：先用共指把 mention 聚簇，再对每个簇做一次 EL（簇内所有 mention 共享一个 KB 实体），比逐 mention 链接更稳。这也是知识图谱构建（从文本抽取实体→链接→建边）的关键一环。

## 12. 共指为什么这么难（实验 PART C）

> 跑 `python3 -u experiments/22_sentiment_coref.py` 的 PART C。

我们的实验用 mention-pair + 一致性特征（字符串/性别/数/生命度/距离），在精心构造的简单句上能 100% 配对正确。但**这恰恰是错觉**——case 是挑过的。真实文本里，共指的难点在于：

**① 跨句、长距离** —— "玛丽...（十句之后）...她"。距离一远，"就近回指"的启发式就失效。

**② 嵌套 mention** —— "[[玛丽的] 父亲]" 里 "玛丽" 和 "玛丽的父亲" 都是 mention，但指向不同实体。mention 检测和配对都要处理这种嵌套。

**③ 真正的歧义（Winograd Schema）** —— 这是共指的"图灵测试"：

> "The trophy doesn't fit in the suitcase because **it** is too big."
> → "it" = 奖杯（大的那个装不进）
>
> "The trophy doesn't fit in the suitcase because **it** is too small."
> → "it" = 手提箱（小的那个装不下）

两句只差一个词（big/small），但"it"指代完全不同。要解对，必须理解"大东西装不进小东西"这种**世界知识**和**因果推理**。这正是 Winograd Schema Challenge（Levesque et al. 2012）的设计意图——**用最小的词汇差异，逼迫模型做真正的推理，而非模式匹配**。

**④ 中文零指代** —— 如前述，Ø 在文本里不可见，必须靠语篇推理恢复。

**残酷现实**：即便 GPT-4，在标准共指标注集（OntoNotes）和 Winograd schema 上**仍会出错**。共指是 LLM 时代**少数未被"收编"的 NLP 任务之一**——因为它本质是**跨句的世界状态推理**，而非局部的模式识别。

# Part Ⅲ — 批判与展望

## 13. 两个任务的命运分野：一张图看清

```
                    LLM 时代的 NLP 任务命运光谱
   ←──────────────────────────────────────────────────────→
   "已被收编"                              "仍是开放难题"

   情感分析 ──────────►        共指消解 ──────────►
   (浅层语义,统计可解)         (深层语篇,需世界推理)

   词典/NB/BERT 都能打         e2e/SpanBERT/CorefQA 仍吃力
   LLM 一句 prompt ≈ SOTA      GPT-4 在 Winograd 上仍犯错
```

**情感分析为什么"被收编"了？** 因为它的信号是**局部的、统计的**——情感词的分布基本决定极性，连词典都能做到 85%+。LLM 在此基础上叠加语境理解，轻松到顶。这类"信号集中、推理链短"的任务，是 LLM 的舒适区。

**共指为什么"没被收编"？** 因为它要求**跨句的实体追踪 + 世界知识推理**。"it" 指什么，取决于你对物理世界（大小/容量/因果）的理解，而非文本里的词频统计。这类"信号分散、推理链长、依赖世界模型"的任务，正是 LLM（和所有现役模型）的硬伤。

> **这条分野极其重要**：判断一个新 NLP 任务"能不能甩给 LLM"，就问自己——**它的答案主要藏在局部的词里，还是藏在跨句的推理里？** 前者 LLM 已解决（且词典/NB 这种老方法也够用）；后者是真正的前沿。

## 14. 局限与争议

**情感分析的局限**：
- **反讽/讽刺仍是死穴**——连 LLM 也远未解决（sarcasm detection 至今是独立研究方向）。
- **隐式情感（implicit sentiment）**：如"这个软件又更新了"——没一个情感词，但老用户读出"又要折腾了"的负向。这类需要常识和语用推理。
- **跨文化/跨语言情感表达差异大**：中文的"还行"常常是委婉的负向，直译成英文 "not bad" 则偏正向。情感词典/模型的跨语言迁移仍非平凡。
- **被收编的副作用**：当人人调 LLM 做情感，研究社区对传统方法（词典特征工程）的关注下降，但工业界反而更依赖它们（成本低、可解释）。学术与工业出现"脱节"。

**共指消解的局限**：
- **标注成本极高**：共指标注需要专家级语言学训练，OntoNotes 这类语料极昂贵，限制了数据规模。
- **评估本身的争议**：MUC/B³/CEAF/e 等共指评测指标各有偏好，同一系统在不同指标上排名可能反转。
- **中文共指标注资源稀缺**：Ontonotes 中文部分规模有限，且中文零指代的标注一致性差。
- **LLM 的尴尬**：LLM 在共指上"时灵时不灵"——简单句近乎完美，复杂句突然翻车，这种**不可预测的失败**比稳定的中等水平更难用于生产。

## 15. 工程实践：今天该怎么选

| 场景 | 推荐方法 | 理由 |
|------|---------|------|
| 电商/产品评论情感 | VADER 词典 或 LLM | 文本简单，词典够用且零成本；要精度上 LLM |
| 金融舆情实时监控 | 词典 + 规则（兜底）+ LLM（复杂句） | 低延迟、可解释合规要求 |
| 细粒度 ABSA | BERT 微调 或 LLM few-shot | 需要 aspect 级粒度 |
| 反讽检测 | LLM（仍难，需专门 prompt/微调） | 词典/传统模型无解 |
| 通用共指 | SpanBERT/CorefQA 微调（生产）+ LLM（原型） | 神经共指仍是 SOTA；LLM 不稳定 |
| Entity Linking | 候选生成（字典）+ BERT 重排 | 两阶段流水线仍是工业标准 |
| 中文共指 | 专门模型 + 人工后处理 | 零指代使中文格外难，LLM 也不可靠 |
