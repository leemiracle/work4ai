# 05 — 选型决策：任务 × 规模 × 成本

> 「讲透模型」第六篇。00-04 讲"模型是什么/怎么衡量"。本篇讲实战——**我的场景该选哪个模型**？这是工程师每周都要做的决策，但 90% 的人都在拍脑袋。
>
> 配套实验：`experiments/05_selection.py`。

---

## 1. 灵魂：选型是三维权衡

$$
\boxed{\text{选型} = \text{任务类型} \times \text{部署规模} \times \text{成本预算}}
$$

不是"用最大的"，而是"**最匹配的**"。

---

## 2. 三维决策空间

### 2.1 维度 1：任务类型（难度）

| 任务 | 难度 | 最低规模 |
|------|:--:|:------:|
| 闲聊/客服 | 易 | 7B |
| 文档总结 | 易 | 7B |
| 翻译 | 中 | 13B |
| 代码补全 | 中 | 13B |
| 函数级代码生成 | 中难 | 30B+ |
| 数学推理 | 难 | 70B |
| Agent 工具调用 | 难 | 70B |
| 多步推理/科研 | 极难 | 405B+ |
| 多模态理解 | 难 | 70B+ |

### 2.2 维度 2：部署规模

| 场景 | 模型 | 硬件 |
|------|:--:|:--:|
| 边缘（手机/IoT）| 1B-3B（Qwen-2.5 1.5B）| 手机/Mac |
| 单卡 | 7B-13B（Llama-3 8B）| 1× A100 |
| 多卡 | 70B+（Llama-3 70B）| 8× A100 |
| 云端 API | 任意（GPT-4o）| 无 |

### 2.3 维度 3：成本预算

| 预算 | 方案 |
|------|------|
| 免费（本地）| 开源 7B 自部署 |
| 低（<$100/月）| 开源 + 自部署 |
| 中（$100-10k/月）| 商业 API（GPT-4o-mini）|
| 高（>$10k/月）| SOTA API（GPT-4o / Claude）|

---

## 3. 实测：任务难度 × 模型规模 → 准确率

| 任务 | 7B | 13B | 70B | 405B |
|------|:--:|:--:|:--:|:--:|
| **闲聊/总结** | **91.3%** | 93.2% | 98.0% | 98.0% |
| 翻译/代码 | 81.1% | **90.1%** | 95.1% | 98.0% |
| 数学/Agent | 52.0% | 81.2% | **93.3%** | 98.0% |
| 复杂推理 | 47.1% | 53.3% | 91.7% | **97.0%** |

### 3.1 关键洞察

- **闲聊/总结**：7B 已 91%，**用 405B 是 90% 成本浪费**（只多 7 个百分点）。
- **数学/Agent**：7B 只有 52%（接近瞎猜），**必须 70B+**。
- **复杂推理**：13B 才 53%，**必须 405B 才接近 97%**。

### 3.2 性价比法则

$$
\text{性价比} = \frac{\text{准确率提升}}{\text{成本倍数}}
$$

- 简单任务用大模型：性价比低（提升 5pp，成本翻 10×）
- 难任务用小模型：性价比 0（根本不达标）

**核心原则**：**匹配任务难度**。任务简单用小模型省 90% 成本，任务难必须用大模型。

---

## 4. 部署成本对比

| 方式 | 前期 | 月运营 | 延迟 | 隐私 |
|------|:--:|:--:|:--:|:--:|
| API (GPT-4o) | $0 | 按量 | ~1s | ❌ 数据出本地 |
| API (Llama-3.1 70B) | $0 | 按量 | ~1s | ❌ |
| 自部署 7B（1×A100）| $8k | $200 | ~0.1s | ✅ |
| 自部署 70B（8×A100）| $200k | $2k | ~0.5s | ✅ |
| 自部署 405B（8×H100）| $400k | $5k | ~1s | ✅ |
| 边缘 1B（手机）| $2k Mac | $0 | ~0.05s | ✅ 离线 |

### 4.1 决策矩阵

| 场景 | 推荐 |
|------|------|
| 数据敏感（医疗/法律/金融）| 自部署 |
| 量小试水（<1k/天）| API |
| 高频大量（>1M/天）| 自部署或混合 |
| 边缘离线（手机 App）| 1B-3B 小模型 |
| SOTA 任务（科研/复杂推理）| API（GPT-4o / Claude）|

---

## 5. 选型工程 10 步清单

1. **明确任务类型**：生成 vs 理解 vs 推理 vs 多模态
2. **定 SLA**：延迟 < 100ms？< 1s？< 10s？
3. **定数据敏感性**：可上云 vs 必须本地
4. **算月调用量**：1k？1M？1B？
5. **选开源 vs API**：数据/成本/可控性
6. **跑 5 个候选模型**：在你的**真实任务**（不要只看 benchmark）
7. **人工评分 100 样本**：看真实偏好
8. **估算总成本**：API 按量 vs 自部署固定
9. **选 backfill 模型**：主模型挂了的备选
10. **持续监控**：每月重测（新模型不断出）

---

## 6. 反模式：避免这些坑

### 6.1 "用最大的就不会错"

**错**。简单任务用 405B 浪费 90% 成本，且延迟高。

### 6.2 "Llama-3 70B 一定能跑我的业务"

**不一定**。**你的具体任务**可能与 benchmark 不同，必须实测。

### 6.3 "开源等于免费"

**不等于**。自部署 70B 需 8×A100（$200k 硬件 + 月运营）。

### 6.4 "API 比自部署贵"

**不一定**。低频 API 比自部署便宜；高频 API 可能比自部署贵 10×。

### 6.5 "选了就一劳永逸"

**错**。每 3-6 个月有新模型，需要重新评估。

---

## 7. 一句话总结

> **选型 = 任务 × 规模 × 成本三维权衡。实测：闲聊 7B 91%、数学 7B 52%、复杂推理 7B 47%——任务难度决定最低规模。核心原则：匹配任务难度，简单任务用小模型省 90% 成本，难任务必须大模型。部署决策：数据敏感→自部署；量小试水→API；高频大量→自部署/混合；边缘离线→1B-3B。10 步清单：任务类型→SLA→数据敏感→月调用量→开源/API→跑 5 候选→人工评分→算总成本→backfill→持续监控。避免坑：不盲目用最大、必跑真实任务、开源≠免费、API 不一定贵、要持续重评。**

## ✍️ 练习（`05_selection.py`）

1. **加多模态**：把任务表加"图像理解"，看推荐模型。
2. **加成本计算器**：输入月调用量，自动算 API vs 自部署哪个便宜。
3. **接真实 benchmark**：用你业务的 100 个样本，跑 5 个模型对比。
4. **加 SLA 约束**：固定延迟 < 200ms，看哪些模型可用。
5. **加 fallback 策略**：主模型挂了切哪个？设计一个混合策略。
