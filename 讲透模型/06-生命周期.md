# 06 — 生命周期：模型作为可运维资产

> 「讲透模型」第七篇。00-05 讲"模型是什么/怎么衡量/怎么选"，本篇讲**选完之后**——模型不是一次性交付物，是有出生、服役、退役的**资产**。
>
> 配套实验：`experiments/06_lifecycle.py`。
>
> **与 [`讲透LLM/01-完整生命周期`](../讲透LLM/01-完整生命周期.md) 的分工**：那边是**训练侧叙事**（pretrain→SFT→RL→deploy 每步指路到专题）；本篇是**运营侧决策**——每个阶段的决策门、常见死法、退役判据。一个讲"怎么造"，一个讲"怎么养"。

---

## 1. 灵魂：模型是资产，不是交付物

$$
\boxed{\text{模型价值} = \int_{\text{服役期}} \text{产出} - \text{(训练 + 部署 + 监控 + 维护)}\,dt}
$$

软件工程的经验在模型上全部加倍：**上线才是开始**。数据分布会漂、能力会退化、成本会涨、新模型会来——不管理生命周期的模型，六个月内变成负资产。

---

## 2. 六阶段总表（每阶段的决策门）

| 阶段 | 做什么 | 典型成本 | **决策门（过不过？）** | 深读 |
|---|---|---|---|---|
| ① 预训练 | 造基座 | 千万 $ 级 | **99% 的团队直接跳过**——外购开源基座 | [`基础模型/02`](../讲透基础模型/02-ScalingLaw.md)、[`Transformer/07`](../讲透Transformer/07-预训练与ScalingLaws.md) |
| ② 后训练 | SFT + 对齐（RLHF/DPO/GRPO） | 百 $ ~ 百万 $ | 任务是"改行为"还是"注知识"？改行为才值得调 | [`Transformer/08`](../讲透Transformer/08-对齐训练.md)、[`讲透RL/03`](../讲透RL/03-RLHF-DPO-GRPO.md)、[`讲透微调/`](../讲透微调/) |
| ③ 评估 | 自建评测集 + 防污染 | 人天级 | 公开 benchmark 分 ≠ 你的任务分——**不过自评不上线** | 本系列 [04](04-能力评估.md)、[`宇宙/03`](../讲透模型宇宙/03-丈量模型-排行榜的真相.md) |
| ④ 部署 | 量化 / KV cache / 服务化 | 硬件 + 工程 | 延迟/吞吐/成本三角达 SLA？ | [`讲透KV Cache/`](../讲透KV Cache/)、[`Transformer/09`](../讲透Transformer/09-推理优化.md) |
| ⑤ 监控 | 漂移检测 / 退化 / 成本追踪 | 持续 | 指标跌破阈值 → 触发 ⑥ | [`讲透LLM/03`](../讲透LLM/03-工程全栈.md) monitor 节 |
| ⑥ 退役 | 换代 / 蒸馏 / 归档 | 迁移成本 | 见 §4 三判据 | [`宇宙/19`](../讲透模型宇宙/19-调与改.md) 蒸馏 |

**关键洞察**：①② 只占生命周期成本的一小段；④⑤⑥ 才是长尾。选型（[05](05-选型决策.md)）只决定起点，生命周期管理决定**总回报**。

---

## 3. 三条常见死法（反模式）

### 3.1 上线即弃（无监控）

模型对输入分布敏感：用户提问方式变了、季节变了、上游产品改版了——静默退化。**症状**：投诉先于指标崩。**解法**：留出 golden set 定期回放 + 监控输入分布（embedding 均值漂移）。

### 3.2 永不退役（维护费 > 重写费）

老模型带着：专属推理栈、量化补丁、没人懂的 prompt 兼容层。**症状**：新实习生问"为什么不用新模型"，没人答得上来。**解法**：给每个模型定**服役期预算**（如 12 个月），到期强制重评。

### 3.3 跳过自评直接上线

公开榜高分 ≠ 你的任务好用（污染 + 分布差，见 [`宇宙/03`](../讲透模型宇宙/03-丈量模型-排行榜的真相.md)）。**解法**：上线前 100 条自建样本 + 人工评分，不过不上。

---

## 4. 退役三判据（什么时候换）

| 判据 | 触发条件 | 动作 |
|---|---|---|
| **性价比** | 新模型在自评集上 +10pp 且总成本（含迁移）< 12 个月收益 | 升级换代 |
| **风险** | 老模型爆出安全漏洞 / 许可证变更 / 供应方停服 | 强制迁移（API 模型常见）|
| **能力债** | 任务需求升级（如要上 Agent 工具调用），老模型能力天花板不够 | 升级或蒸馏 |

**退役≠删除**：归档权重 + 评测记录 + 决策日志——三年后审计"当时为什么这么做"靠它。

---

## 5. 开源 vs API：两种生命周期

| 维度 | 自部署（开源） | API |
|---|---|---|
| 生命周期主权 | **你全责**：⑥ 阶段全管 | 供应方管①②，你管③⑤⑥ |
| 升级节奏 | 你定（可拖） | **供应方定**（deprecated 通知 = 强制退役倒计时）|
| 回滚 | 模型注册表存旧版，秒回滚 | 旧版本下线 = 无法回滚（快照 API 例外且贵）|
| 死法 | 3.2 永不退役 | 供应方悄悄换版，输出风格漂移没人通知 |

**API 用户最易忽略的监控项**：同一 prompt 的输出分布随时间变化——供应方更新模型不会发 changelog 给你。

---

## 6. 一句话总结

> **模型是资产：上线才是生命周期的开始。六阶段（预训练→后训练→评估→部署→监控→退役）每阶段有决策门：外购基座、改行为才调、自评不上线不叫上线、SLA 达标才部署、指标漂移必报警、性价比/风险/能力债三判据触发退役。三条死法：上线即弃、永不退役、跳过自评。开源管全责，API 管不了退役倒计时。选型定起点，生命周期管理定总回报。**

## ✍️ 练习（`06_lifecycle.py`）

1. **加成本模型**：给六阶段各配月成本，算一个 7B 自部署模型 24 个月总拥有成本（TCO）。
2. **加漂移模拟**：输入分布每月偏移 1%，画质量曲线，找出"该退役"的月份。
3. **加 A/B 与金丝雀**：新模型 5% 流量灰度，模拟质量回归时自动回滚。
4. **加 API 弃用倒计时**：供应方 90 天弃用通知，模拟迁移窗口内的双跑成本。
