# 03 · 训练循环的正确写法

> 本章是把前面（autograd/module/data）串成"能跑"的关键。PyTorch 训练 = 固定的**黄金 5 步循环**，但每一步都有新手坑。本章讲正确写法 + 三个最常见 bug + 三个进阶技巧（调度器/梯度累积/裁剪）。

---

## 一、黄金 5 步（所有 PyTorch 训练的骨架）

```python
for epoch in range(EPOCHS):
    for x, y in dataloader:
        optimizer.zero_grad()      # 1. 清零梯度(梯度累积, 见01章)
        logits = model(x)          # 2. 前向(建计算图)
        loss = loss_fn(logits, y)  # 3. 算 loss
        loss.backward()            # 4. 反向求梯度(图随后释放)
        optimizer.step()           # 5. 用梯度更新参数
```

这 5 步对应 autograd 机制（01章）：zero_grad（清零）→ forward（建图）→ loss → backward（反向+释放图）→ step（更新）。

---

## 二、三个最常见 bug（实验03 实测）

### Bug 1：忘了 `optimizer.zero_grad()`
梯度累积导致方向越来越乱。实验03 实测：不清零在 SGD 下会崩，Adam 有自适应还能撑但精度下降。
**铁律**：每步必须 zero_grad。

### Bug 2：记录 loss 忘了 `.item()`
```python
history.append(loss)        # ❌ 存了带 grad_fn 的 tensor, 计算图不释放, 内存泄漏
history.append(loss.item()) # ✅ 返回纯 float, 断开图
```
长训练必然 OOM。

### Bug 3：推理/评估忘了 `torch.no_grad()`
推理建图既慢又费内存，还可能污染梯度。
**铁律**：测试/评估一律 `with torch.no_grad():`。

## 三、三个进阶技巧（实验09 实测）

### 3.1 学习率调度器（收敛质量关键）
```python
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=EPOCHS)
# 每个 epoch 或每步在 step() 后调用 scheduler.step()
```
常用：`CosineAnnealingLR`（平滑衰减）、`OneCycleLR`（先升后降，super-convergence）、`LinearWarmup+Cosine`（大模型标配）、`ReduceLROnPlateau`（loss 不降自动降 lr）。
**铁律**：`scheduler.step()` 在 `optimizer.step()` 之后。

### 3.2 梯度累积（小显存模拟大 batch）
显存只够 batch=32，但想要 effective batch=128：
```python
opt.zero_grad()
for i, (bx, by) in enumerate(loader):
    loss = loss_fn(model(bx), by) / ACCUM_STEPS   # 注意 loss 要除以累积步数!
    loss.backward()
    if (i+1) % ACCUM_STEPS == 0:
        opt.step(); opt.zero_grad()
```
**关键**：loss 除以 ACCUM_STEPS，否则梯度被放大。

### 3.3 梯度裁剪（防爆炸，RNN/Transformer 必备）
```python
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
opt.step()
```
实验09 实测：gnorm 0.15 → 0.05（按比例缩放到 max_norm）。

## 四、反传的故障：梯度消失与爆炸

> 反传是局部导数的**连乘**。这个连乘在深层网络里出两个毛病：连乘<1 → 梯度消失（浅层学不动）；连乘>1 → 梯度爆炸（训练崩溃）。**这不是 bug，是链式法则的必然**——多层 = 多次乘法。

**根因：连乘的诅咒**。把 $L$ 层网络的反传想象成"梯度走过 $L$ 道门"，每道门把梯度乘一个局部导数。到达浅层的梯度 $\propto \prod_{i=1}^{L} f_i'(z_i)$：
- sigmoid：$f'(x)\le0.25$ → 连乘必衰减，$0.25^{20}\approx 9\times10^{-13}$
- ReLU：正轴 $f'(x)=1$ → 连乘不衰减（这是 ReLU 革命性的原因，见「讲透激活函数02章」）
- 大权重：线性层雅可比 $\approx W$，$\|W\|$ 大 → 连乘爆炸

```bash
cd experiments && python3 17_vanishing_exploding.py
```
20 层网络每层权重梯度范数（层 0=最浅）：
```
[Sigmoid] 层0: 3.6e-15  层19: 1.4e+2   (浅层几乎归零 = 消失!)
[ReLU]    层0: 5.9e-7   层19: 4.9e+0   (浅层比 sigmoid 高 8 个数量级)
```

**解法**（按效力排序）：
1. **残差连接（ResNet）：梯度的"高速公路"**。$y=x+f(x)$ 给梯度一条绕过 $f$ 连乘的直通路：$\partial y/\partial x=1+f'(x)\ge1$。实测 sigmoid+残差浅层梯度从 $3.6\text{e-}15 \to 330$。**这是 ResNet 能训上百层、Transformer 用残差的根本原因**，比 BatchNorm 更直接。
2. **激活改 ReLU**：正轴导数=1，不衰减。
3. **合理初始化（Xavier/Kaiming）**：让初始权重尺度使每层输出方差稳定。
4. **BatchNorm/LayerNorm**：稳定每层输入分布，间接控制梯度尺度。
5. **梯度裁剪（防爆炸）**：见上文 3.3。**注意：裁剪治标不治本——能防爆炸，但不解决消失**（消失是乘小数，裁剪帮不上）。

> 批判："BatchNorm 解决梯度消失"是半对。BN 主要解决 internal covariate shift，对梯度是间接作用。**解决消失的头号功臣是残差连接**。消失/爆炸是同一硬币两面，都源于连乘，解法都是"让连乘接近 1"。

## 五、梯度的全景：你算的到底是哪种梯度

"梯度"在深度学习里被滥用。反传算出的只是其中一种——**小批量平均梯度**。

**按数据量**（你喂多少数据算一次）：

| 类型 | 梯度来源 | 特点 |
|------|---------|------|
| 全批量（BGD）| 整个训练集平均 | 稳定但极慢，大数据放不下 |
| 随机（SGD）| 单个样本 | 快但方差大，loss 抖动剧烈 |
| **小批量** | 一小批（32/64）平均 | **现代训练默认**，兼顾稳定与速度 |

**按计算法**（你怎么得到梯度值）：
- **数值梯度**（中心差分）：用于**梯度检查**验证反传（见 [01 章 4.4](01-Autograd与计算图.md)），不用于训练（$O(n)$ 太慢）
- 解析梯度（手推）：精确但复杂网络易错
- **自动微分（AD）= 反传的引擎**：PyTorch/TF 都用

**特殊场景的"梯度"**（突破标准可微损失）：
- **策略梯度**（RL）：$\nabla J\approx\nabla\log\pi(a|s)\cdot R$，靠采样估计，不是反传的链式梯度
- **梯度惩罚**（WGAN-GP）：对**输入**的梯度，用反传本身算（二阶）
- **梯度反转层**：反传时梯度 $\times(-\lambda)$（领域自适应）

> 一句话：反传 = AD 反向模式，输出小批量平均梯度。这个梯度经优化器加工（[11 章](11-损失函数与优化器.md)），最终变成参数更新量。**理解"各种梯度"，就打通了从 loss 到参数更新的整条链。**

## 七、完整训练循环模板（整合所有技巧）
```python
scaler = torch.cuda.amp.GradScaler()
for epoch in range(EPOCHS):
    model.train()
    opt.zero_grad()
    for i, (x, y) in enumerate(loader):
        with torch.autocast("cuda"): loss = loss_fn(model(x), y) / ACCUM
        scaler.scale(loss).backward()
        if (i+1) % ACCUM == 0:
            scaler.unscale_(opt)
            clip_grad_norm_(model.parameters(), 1.0)
            scaler.step(opt); scaler.update(); opt.zero_grad()
    scheduler.step()
    # 评估
    model.eval()
    with torch.no_grad():
        ...  # 验证集
```

## 八、批判性视角

- **`model.train()` / `model.eval()` 别忘**：它切换 Dropout/BatchNorm 的行为。评估忘 `eval()` 会让 BN 用 batch 统计、Dropout 还在丢，结果错。
- **数据要 shuffle**（训练=True，验证=False），避免顺序偏差。
- **没有银弹组合**：AMP/scheduler/累积/裁剪按需用，过度堆砌反而难调。
