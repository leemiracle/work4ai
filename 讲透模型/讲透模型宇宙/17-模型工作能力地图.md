# 17 · 模型工作能力地图 + 自评

> 这是 Part IV 的总纲，也是本系列的**实用入口**。前 14 章是"理解"的地基；从本章起，进入"驾驭"的目的。本章给你一张**模型工作能力的 8 维地图**，帮你精准定位自己的强项和缺口——然后告诉你本系列（和 work4ai 其他系列）的哪一章能补哪个缺口。

## 17.1 为什么先要一张能力地图？

多数人学 AI 的失败，不是不够努力，而是**不知道自己缺什么**。你可能刷了很多教程，却说不清"我现在到底能在工作里驾驭模型到什么程度"。结果是：要么高估自己（遇到真问题懵了），要么低估自己（明明能做却不敢接活）。

能力地图解决这个：把"驾驭模型做工作"拆成 **8 个独立可评的维度**，每个维度给 L0-L3 的明确标准。你诚实自评，就知道**强项在哪、缺口在哪、最该补哪个**。

## 17.2 模型工作能力的 8 维

| 维度 | 一句话 | 在工作里意味着 |
|------|--------|--------------|
| **建**（Build）| 为一个工作问题搭出模型方案 | 拿到一个需求，能定数据/架构/目标的决策链 |
| **调**（Tune）| 系统化调参 + 微调 | 不是炼丹，是有方法论地让模型表现更好 |
| **改**（Modify）| 改造已有模型 | steering/剪枝/蒸馏/adapter，让模型适配新需求 |
| **用**（Use）| 部署 + 调用 | 把模型跑起来、接入业务、API/pipeline |
| **优化**（Optimize）| 推理与性能优化 | 量化/KV cache/服务化，让模型快、省、稳 |
| **复现**（Reproduce）| 把握 + 复现论文 | 读论文能抓住核心，并能跑通/改 |
| **沟通**（Communicate）| 领域专业对话 | 听懂术语、说专业的话、和从业者有效交流 |
| **拓展**（Extend）| 用模型扩宽工作边界 | 把模型能力迁移到新场景，做原来做不到的事 |

**关键认识**：这 8 维**不是线性的、不可互相替代**。一个"调"很强但"复现"为 0 的人，遇到新论文就卡住；一个"用"很强但"建"为 0 的人，只能用别人造的轮子。**短板决定你的实际天花板**（木桶效应）。

## 17.3 四级标准（L0-L3）

每个维度用统一的四级：

- **L0 不会**：完全没概念，没做过。
- **L1 跟着做**：能照教程/文档跑通，但脱离教程就卡。
- **L2 独立做**：能在真实工作场景独立完成，能排错。
- **L3 创新教**：能优化/创新方法，能教别人、做技术决策。

> **诚实是关键**：自评时别美化。L2 的标准是"**独立在真实工作里完成**"——不是"我看懂了教程"。看懂 ≠ 会做。

## 17.4 每维的 L2 达标线（具体）

让你能判断自己够不够 L2：

- **建 L2**：给一个工作问题（如"自动给工单分类"），你能独立定出：用什么模型（API/微调/规则）、要什么数据、怎么评估——并搭出可跑的原型。
- **调 L2**：模型效果不达标时，你能系统化排查（数据?损失?超参?），而不是随机改 lr。
- **改 L2**：能用 LoRA/adapter 让开源模型适配你的领域，或用剪枝/蒸馏把它变小。
- **用 L2**：能把模型部署成可调用的服务（vLLM/Ollama/API 封装），接入业务 pipeline。
- **优化 L2**：知道何时量化、何时压缩 KV、何时上 GPU，能把推理成本/延迟降一个量级。
- **复现 L2**：给一篇论文，能抓住核心思想讲清楚，并跑通它的代码、改一个变量看影响。
- **沟通 L2**：在领域对话里能听懂 80% 术语、用准确的话表达技术判断，不外行。
- **拓展 L2**：能把一个模型能力（如"摘要"）迁移到一个新场景（如"会议纪要自动化"），并落地。

## 17.7 批判：能力地图的局限

- **8 维不是全部**：还有"数据工程""评估设计""产品思维""工程纪律"等维度，本系列聚焦"模型核心 8 维"，不覆盖一切。
- **等级是粗的**：L2 内部差异很大。地图帮你定位"在哪个区"，精细水平要靠真实项目检验。
- **别陷入"刷等级"**：能力的目的是解决工作问题，不是凑分。一个 L2 但能落地解决真问题的人，比 L3 但只会纸面的人有价值。
- **沟通/拓展容易被低估**：技术人常觉得"沟通不硬核"——但这两维恰恰决定你的能力**能否被看见、能否放大**（见 Ch22）。
