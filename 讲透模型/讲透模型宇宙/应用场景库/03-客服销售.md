# 03 · 客服 / 销售场景

> 客服是 2026 年 AI 部署最成熟、ROI 最快的领域——量大、模式重复、易量化。本类 5 个场景。

---

### 场景 12：智能客服（FAQ / 问答 / 直接解决）
- **痛点**：海量重复问题（订单状态、退换货、政策），人工处理慢且贵。
- **输入 → 输出**：用户问题 → 答案 / 直接操作（查单/退款）。
- **模型方案**：**RAG（知识库）+ Agent（接业务系统执行）**。`讲透RAG`+`讲透Agent`。
- **真实案例**：**Kogan.com**（Salesforce Agentforce）—— 处理 5000 cases/月，36850 actions/周，true resolution 6.2%→20%，CSAT 接近人工，销售 +20% 同时服务成本 -10%（Salesforce，2026）。**Siemens** —— 90% 呼入电话自主处理（Amazon Connect，2026）。
- **工具栈**：Agentforce / Amazon Connect / Intercom Fin / 自建（RAG + tool calling）。
- **陷阱**：幻觉答错 → 必须接地知识库 + 低置信转人工；语气生硬 → 加品牌话术 few-shot。
- **起步 MVP**：把你 top 20 高频问题 + 答案做成 RAG，测回答准确率。

### 场景 13：工单分类 / 路由 / 优先级
- **痛点**：工单量大、类型多，人工分发慢且错。
- **输入 → 输出**：工单文本 → 类别 / 责任团队 / 优先级。
- **模型方案**：**LLM 分类 + 情感评分**（路由）。量大 → 微调小模型。
- **真实案例**：**Wayfair** Wilma 工单分诊，每月自动化 41000 tickets，部分流程达 70%（OpenAI，2026）。**Siemens** 用 Lex 意图识别替代 DTMF 菜单（AWS，2026）。
- **工具栈**：LLM 分类 + CRM 集成；情感 → NLP 模型。
- **陷阱**：长尾类别多 → 分层（先大类再细分）；路由规则变 → 规则外置可改。
- **起步 MVP**：导出 200 历史工单，让 LLM 分类，对比人工标签算准确率。

### 场景 14：实时 agent assist（坐席辅助）
- **痛点**：新坐席不熟知识；通话后整理耗时。
- **输入 → 输出**：实时对话 → 建议回答 / 知识卡片 / 通话后摘要。
- **模型方案**：**RAG + 实时流式 LLM**（通话中建议）+ **LLM 摘要**（通话后）。
- **真实案例**：行业数据 agent assist 降 handle time 15-25%（AliceLabs，2026）；**Wayfair** 为替换零件团队部署 co-pilot 读历史、提下一步、起草稿（OpenAI，2026）。
- **工具栈**：实时 → 流式 ASR + RAG + LLM；摘要 → 通话后 LLM + 写回 CRM。
- **陷阱**：建议延迟高没用 → 端到端 <1s；建议错误导坐席 → 标注"建议"非指令。
- **起步 MVP**：把客服知识库做 RAG，坐席输入问题秒出相关条款。

### 场景 15：呼叫中心语音质检 / 外呼营销
- **痛点**：通话质检覆盖率低；外呼效率低、个性化难。
- **输入 → 输出**：通话录音 → 合规/质量评分；外呼 → 个性化话术 + 意向判断。
- **模型方案**：**ASR + LLM 评分**（质检）；**语音 Agent**（外呼对话）。
- **真实案例**：**DoorDash** 语音 agent（Bedrock + Claude）每日数十万司机支持电话，延迟 ~2.5s，减少数千次人工转接（AWS，2026）。**Siemens** 外呼营销 agent POC，CRM 拉历史+产品推荐+意向评估（AWS，2026）。
- **工具栈**：Amazon Connect outbound / 自建语音 agent；质检 → ASR + LLM rubric。
- **陷阱**：外呼合规（GDPR/通话时段/拒接）→ 必须合规优先设计；语音延迟 >3s 体验差。
- **起步 MVP**：抽 50 通录音，用 ASR+LLM 按 checklist 质检，对比人工质检结果。

### 场景 16：销售辅助（线索评分 / 邮件 / 话术）
- **痛点**：销售线索多，优先级难判；个性化跟进难规模化。
- **输入 → 输出**：线索信息 → 评分 / 个性化邮件 / 话术建议。
- **模型方案**：**LLM 个性化 + 规则评分**。邮件 → few-shot 风格 + CRM 数据。
- **真实案例**：**Rippling** action agent 自动规范化职位/层级，跨 HR/IT/财务读写（LangChain，2026）。
- **工具栈**：CRM（Salesforce/HubSpot）+ LLM；邮件 → API + 模板。
- **陷阱**：邮件像群发 → 注入收件人具体信息；过度自动化失真 → 关键节点人工。
- **起步 MVP**：选 20 个线索，用 LLM 写个性化开场邮件，对比通用模板回复率。

## 🔧 深度实操要点（本类场景）

> 本类场景的实操指引。通用骨架代码/评估清单/排错指南见 [00 深度实操手册总纲](00-深度实操手册总纲.md)。

- **决策速查**：FAQ/问答→RAG(B)；直接操作(查单/退款)→Agent(D)；质检→ASR+LLM
- **关键骨架**：骨架 B (RAG) + D (Agent接业务系统)
- **评估要点**：解决率(true resolution)；CSAT；单次成本；转人工率
- **头号陷阱**：幻觉答错→接地知识库+低置信转人工(Kogan:等>15min转人工+回拨)
- **进阶路径**：RAG→Agent执行→全渠道→外呼语音

---

**本类共性建议**：从"场景 12 直接解决"起步（量最大、ROI 最快）。Kogan/Siemens 的路径都是"**先一个高频用例验证，再扩**"——别一上来全自动化。始终保留 human escalation（Kogan：等>15 分钟转人工 + 回拨）。
