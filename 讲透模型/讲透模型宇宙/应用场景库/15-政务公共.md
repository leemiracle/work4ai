# 15 · 政务 / 公共部门

> 政务是"高透明度要求 + 大额公共资金 + 反腐败刚需"领域。AI 在政府采购（占全球 GDP 12-15%）的反欺诈/透明化上 ROI 极高，但**治理/问责/数字主权**是硬约束。本类 7 个场景。**铁律**：凡涉公共资金的 AI 决策必须 human-in-the-loop + 可审计 + 可解释（EU AI Act 对公部门要求最严）。

---

### 场景 84：政府采购透明化 / 反欺诈
- **痛点**：采购腐败、低效、不透明；金额巨大（全球 $11-13 万亿/年）。
- **输入 → 输出**：采购全周期数据 → 红旗/异常/腐败风险评分。
- **模型方案**：**AI 红旗系统 + 实时仪表盘 + 开放数据（OCDS 标准）**。
- **真实案例（2025-2026）**：
  - **Tanzania NeST**（AI e-procurement，2023 起）：采购时间 **234→79 天（-155 天）**，**$12.5M 节省**（2 年），62,000 采购实体，21 政府系统集成，CO2 -64,768 吨，预计 3 百万就业；"situation room"实时监控 + 红旗系统（2026 上线）。
  - **Ukraine ProZorro**（开源，2014 起）：3 万+用户/年，EUR 21B 交易（2023），EUR 250M 节省（2021 起），AI 风险评估。
  - **Brazil Alice**（CGU，审计 AI）：2023 年分析 **19.1 万采购**，触发 203 审计涉 **EUR 4.15B**；2019-22 警报致 EUR 1.5B 投标暂停；**审计时间 400 天→8 天**；40 类风险典型。
  - **Singapore**（A*STAR）：采购欺诈预测，关联 HR/财务/审批 + 员工家属-供应商关系。
- **工具栈**：OCDS 标准化 + LLM 分类/抽取 + ML 风险模型 + 开放数据门户。
- **陷阱**：红旗误报多伤合法供应商 → 人工复核；数据互通是前提（Brazil 263 个分散系统）。
- **起步 MVP**：用 OCDS 标准化一个部门的采购数据，LLM 做异常分类，人工审 top 20。

### 场景 85：AI 监督公共采购决策（半自主审批）
- **痛点**：标书/资格/限价制定易被腐败影响。
- **输入 → 输出**：采购文档 → 草案/资格/价格上限/文件校验建议。
- **模型方案**：**四阶段 AI 监督 + 人工每步批准**（human-in-the-loop 严格）。
- **真实案例（2025-2026）**：**Albania Diella**（世界首个 AI 内阁部长，2025-09）—— 监督采购四阶段（标书/资格/价格上限/文件验证）；"不睡觉、不拿薪、无个人利益"；**human-in-the-loop：专家必须批准 AI 建议**；97.2 万公民交互 + 3.6 万带数字印章文件。**争议**：宪法挑战（部长须自然人）、数字主权（依赖 Azure）、问责真空（AI 错了谁负责）。
- **工具栈**：LLM + 采购知识库 + 审批工作流 + 审计轨迹。
- **陷阱**：**问责真空**——AI 决策出错谁负责必须先界定；过度宣称"100% 无腐败"不可信；EU AI Act 合规（风险评估/偏见面检/网络安全）。
- **起步 MVP**：让 AI 对一个已完成采购做"事后审计"建议，对比实际决策找偏差。

### 场景 86：公民服务虚拟助手（一站式政务）
- **痛点**：公民不知找哪个部门；服务分散。
- **输入 → 输出**：公民问题 → 引导到正确服务 / 直接办证。
- **模型方案**：**RAG（服务知识库）+ 多语言 + 语音**。
- **真实案例**：**Albania Diella**（eAlbania 平台，~1000 服务）—— 文本→语音头像 2.0（传统服饰）；**Singapore** 公民服务聊天机器人；多国政务门户 AI 助手。这是 03 客服的政务版。
- **工具栈**：LLM + 政务知识库 RAG + 多语言/语音 + 身份认证。
- **陷阱**：敏感个人信息 → 严格数据保护；错误引导公民 → 低置信转人工；数字鸿沟（老人/无网人群）。
- **起步 MVP**：把 top 50 高频公民问题做 RAG，测回答准确率。

### 场景 87：药品 / 医疗采购价格透明
- **痛点**：分散采购致价格差异大；公共健康资金浪费。
- **输入 → 输出**：跨系统采购记录 → 标准化价格比较 + 参考价。
- **模型方案**：**LLM 数据清洗/标准化/分类**（解决跨系统数据互通）。
- **真实案例（2026）**：**Brazil Medicamentos Transparentes**（2025-04 上线）—— LLM 把分散采购（263 系统/5568 市）分类到统一目录，**匹配率 5%→80%**（人工 90 分钟/100 项 → AI 5 秒）；全国药品价格可比，作法定"价格库"参考；Transparência Brasil 数据质量审计发现 30% 描述不足。
- **工具栈**：LLM 分类/抽取 + OCDS + 价格仪表盘。
- **陷阱**：垃圾进垃圾出——数据质量是前提（30% 描述差）；分类错致价格比错。
- **起步 MVP**：用 LLM 把一个系统的药品采购分类到标准目录，对比人工准确率。

### 场景 88：腐败早期预警 / 风险预测
- **痛点**：腐败事后才发现；损失已成。
- **输入 → 输出**：经济/政治/历史腐败数据 → 区域/项目腐败风险预测。
- **模型方案**：**ML 风险模型 + 文本挖掘**（投标文本里的串通信号）。
- **真实案例**：**Hungary**（11.9 万投标，Random Forest 文本挖潜，77%→82%）；**西班牙**（省级腐败早期预警，经济+政治+历史数据）；**Singapore**（员工-供应商关系网络）。研究：AI 检测串通准确率 81-95%。
- **工具栈**：ML 分类器 + 网络分析 + 文本特征。
- **陷阱**：误报伤无辜；模型偏见（历史腐败模式可能偏特定群体）；必须人复核。
- **起步 MVP**：用历史标注腐败案例训分类器，回测能否提前预警。

### 场景 89：税务 / 合规 / 反洗钱
- **痛点**：逃税/洗钱监测难；申报审核覆盖率低。
- **输入 → 输出**：申报/交易 → 风险评分/异常/稽查建议。
- **模型方案**：**异常检测 + 网络分析 + LLM 文档审**。
- **真实案例**：多国税务机关用 AI 风险评分（如美国 IRS、英国 HMRC）；与 06 金融反欺诈同源。`kyc-rules`/`kyc-doc-parse` skill 政务版。
- **工具栈**：异常检测 + 图网络 + LLM 审报告。
- **陷阱**：纳税人权利——误报的申诉机制；算法公平性审计；隐私。
- **起步 MVP**：对一类申报，AI 风险评分，人工复核高风险。

### 场景 90：立法 / 议会辅助
- **痛点**：立法研究量大；议员难跟踪所有议题。
- **输入 → 输出**：议题/法案 → 简报/辩论摘要/反论建议。
- **模型方案**：**LLM 立法研究助手**（简报/摘要/反论）。
- **真实案例**：**Albania Diella** 计划为 83 名议员生成 AI 议会助手（简报/缺席摘要/辩论记录/反论建议）；多国议会试点。
- **工具栈**：LLM + 立法知识库 + 议事记录。
- **陷阱**：AI 偏见影响立法；民主问责——AI 建议不能替代议员判断；透明度（公民要知道 AI 参与了多少）。
- **起步 MVP**：让 AI 对一项法案生成"正反论点简报"，对比人工立法研究。

## 政务领域 AI 的五条铁律
1. **human-in-the-loop 是法律红线**——公共资金/权力决策必须人批准（Diella 每步专家批准）。
2. **问责必须先于部署**——AI 错了谁负责？无答案别上线（Albania 宪法挑战的教训）。
3. **数字主权**——依赖外国云的政务 AI 有主权/网络安全风险（EU AI Act 合规）。
4. **开放数据是地基**——OCDS 标准化 + 跨系统互通，AI 才有用（Tanzania/Brazil 都先建数据）。
5. **宣称"100% 消除腐败"不可信**——AI 是监督工具非万能；过度宣称反损公信力。

> **政务领域的心法**：AI 在政务的最大价值是**透明化 + 把事后审计变实时监督**（Brazil 审计 400→8 天、Tanzania -155 天）。但政务 AI 的合法性来自**可审计 + 可问责 + 可解释**，而非"AI 比人公正"。这是 Ch22"规模杠杆"在公共资金上的体现——但要时刻警惕"AI 洗白"（用 AI 给不公决策披合法外衣）。
