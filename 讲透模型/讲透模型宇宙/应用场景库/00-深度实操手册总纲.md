## 一、5 步决策流程（每个场景都走，呼应 Ch18）

```
① 问清楚 ──→ ② 盘数据 ──→ ③ 选方法 ──→ ④ 定评估 ──→ ⑤ 跑 MVP
  (问题)      (数据)      (骨架)      (指标)      (最小验证)
```

**① 问清楚**（80% 失败在这跳过）：输入/输出格式？成功标准（可量化）？错误代价？延迟/成本约束？
**② 盘数据**：标注量？（<100→API few-shot；>1万→微调）；质量？覆盖真实分布？
**③ 选方法**（决策树）：
```
需要外部知识(文档/库)?
├ 是 → 骨架 B (RAG)
└ 否 → 需要领域风格适配?
      ├ 是, >1万标注 → 骨架 C (微调)
      ├ 是, 标注少 → 骨架 A (API few-shot)
      └ 否 → 骨架 A (API)
需要多步推理/工具?
└ 是 → 叠加骨架 D (Agent)
端侧/低延迟?
└ 是 → 量化/蒸馏 (见 Ch20)
```
**④ 定评估**：离线指标 + 在线业务指标 + **必有 hold-out 测试集**。
**⑤ 跑 MVP**：永远从骨架 A（API+prompt，1 小时）开始，验证可行再升级。

> **铁律**：MVP-0（API）→ MVP-1（few-shot）→ MVP-2（RAG）→ MVP-3（微调）。多数需求在 MVP-1/2 就够。

## 二、四个技术骨架（可跑）

### 骨架 A：API + Prompt（最简，90% 场景起步）

```python
# 文件: skeleton_a_api.py — 最小可用，任何场景的 MVP-0
from openai import OpenAI  # 或 anthropic.Anthropic()
client = OpenAI()

def ask(prompt, system="你是专业助手，按要求输出。", model="gpt-4o-mini"):
    r = client.chat.completions.create(
        model=model,
        messages=[{"role":"system","content":system},
                  {"role":"user","content":prompt}],
        temperature=0.3,
    )
    return r.choices[0].message.content

# 结构化输出（强烈推荐：用 JSON schema 约束，防格式乱）
def ask_struct(prompt, schema, model="gpt-4o-mini"):
    r = client.beta.chat.completions.parse(
        model=model,
        messages=[{"role":"user","content":prompt}],
        response_format=schema,  # Pydantic 类
    )
    return r.choices[0].message.parsed
```
**何时升级**：要外部知识 → B；要领域风格 → C；要多步 → D。

### 骨架 B：RAG（检索增强，知识类场景核心）

```python
# 文件: skeleton_b_rag.py — 最小 RAG，纯标准库+numpy
import numpy as np, json, hashlib

# 1. 建索引（一次）：把文档切块 → 向量（用 embedding API）
def embed(text, client):
    r = client.embeddings.create(input=text, model="text-embedding-3-small")
    return r.data[0].embedding

def chunk(text, size=500):
    return [text[i:i+size] for i in range(0, len(text), size)]

def build_index(docs, client):
    idx = []
    for d in docs:
        for c in chunk(d):
            idx.append({"text": c, "vec": embed(c, client)})
    return idx

# 2. 检索（每次问）：query 向量 → 余弦相似 top-k
def retrieve(query, idx, client, k=3):
    qv = embed(query, client)
    scored = [(np.dot(qv, x["vec"]), x["text"]) for x in idx]
    scored.sort(reverse=True)
    return [t for _, t in scored[:k]]

# 3. 生成：把检索片段拼进 prompt
def rag_ask(query, idx, client):
    ctx = "\n---\n".join(retrieve(query, idx, client))
    return ask(f"根据以下资料回答。不知道就说不知道。\n资料:\n{ctx}\n问题:{query}")
```
**升级**：向量库（Chroma/FAISS/Pinecone）；混合检索（语义+关键词）；rerank。
**陷阱**：切块太大召回差、太小丢上下文；**检索到≠相关** → rerank。

### 骨架 D：Agent（多步自主，详见 `讲透Agent`）

```python
# 文件: skeleton_d_agent.py — 最小 ReAct agent（think→act→observe 循环）
def agent(task, tools, client, max_steps=8):
    """tools: dict[name] -> function; 每个 tool 有 docstring 说明用途"""
    msgs = [{"role":"system","content":f"你可用工具: {list(tools.keys())}。"
             "每步: 思考→选工具调用→看结果。完成就回复 FINAL: 答案"}]
    msgs.append({"role":"user","content":task})
    for _ in range(max_steps):
        r = client.chat.completions.create(model="gpt-4o", messages=msgs, temperature=0)
        out = r.choices[0].message.content
        msgs.append({"role":"assistant","content":out})
        if out.startswith("FINAL:"): return out[7:]
        # 解析工具调用（简化：用 function calling 更稳）
        for name, fn in tools.items():
            if name in out:
                args = parse_args(out)  # 你实现
                obs = fn(**args)
                msgs.append({"role":"user","content":f"工具 {name} 结果: {obs}"})
                break
    return "达到最大步数未完成"
```
**升级**：用 LangGraph/LlamaIndex（状态图、并行、human-in-the-loop）；function calling 替代手解析。
**陷阱**：无限循环 → max_steps + 超时；幻觉工具参数 → 用 function calling + schema 校验。

## 三、评估清单（每个场景都要有）

| 评估层 | 指标 | 怎么测 |
|--------|------|--------|
| **功能** | 准确率/F1/精确率 | hold-out 测试集（标注 100-500 条）|
| **业务** | 解决率/省时/转化/CSAT | 在线 A/B（对照人工/旧方案）|
| **可靠性** | 幻觉率/拒答率/延迟 P95 | 抽样人工审 + 监控 |
| **成本** | 每次调用成本/每用户成本 | token × 单价 × 量 |

**铁律**：① 必有 hold-out 测试集 ② 报多 seed/多样本均值 ③ 业务指标 > 功能指标（Ch14）。

## 四、排错指南（按症状查）

| 症状 | 可能原因 | 修复 |
|------|---------|------|
| 输出格式乱 | prompt 没约束 | 用 structured output / JSON schema / few-shot 示例 |
| 幻觉/编造 | 模型瞎猜 | RAG 接地 + "不知道就说不知道" + 引用要求 |
| 召回差（RAG）| 切块/嵌入/检索问题 | 调切块大小 + 混合检索 + rerank |
| 太慢 | 模型大/无缓存 | 换小模型 + 语义缓存 + 流式 |
| 太贵 | 用大模型做小事 | 分层路由（简单→小模型，难→大模型）|
| 微调不收敛 | lr/数据/loss | 降 lr + 查数据质量 + 看 loss 曲线（Ch19）|
| agent 卡死 | 无限循环/工具错 | max_steps + 超时 + function calling |
| 过拟合 | 模型太大/数据少 | 早停 + 正则 + 加数据（注意 double descent，Ch13）|

## 五、成熟度阶梯（MVP → 生产）

```
L0 PoC      : API + prompt，证明能解（1 小时）
L1 Demo     : few-shot + 简单后处理，内部演示（1 天）
L2 Pilot    : RAG/微调 + hold-out 评估，小规模真实（1-2 周）
L3 Prod     : 监控 + 成本优化 + 治理，上线（1-3 月）
L4 Scale    : 多 agent + 自动化 + 全流程，规模化（持续）
```
**每升一级，回头验证上一级的指标是否仍达标**——别只往前冲。

## 六、安全 / 治理清单（生产前必过）

- [ ] **数据**：敏感数据脱敏/私有部署；RBAC 权限；审计日志
- [ ] **隐私**：合规（GDPR/HIPAA/个人信息保护法）；零留存 provider（敏感场景）
- [ ] **公平**：偏见/歧视审计（ hiring/lending/司法 等）
- [ ] **内容**：输入输出双重审核（toxicity/PII/机密）
- [ ] **可控**：破坏性动作 human-in-the-loop（架构性，非开关）
- [ ] **可复现**：固定 seed + config + 数据版本
- [ ] **监控**：延迟/错误率/成本/漂移告警
- [ ] **披露**：AI 用途按规披露（出版商/监管要求）

## 七、通用 Prompt 模板（直接套）

**结构化抽取**："从以下文本抽取字段，输出 JSON：{字段名: 类型}。文本：{text}"
**摘要**："用{n}个要点总结，每点含1个关键数字。文本：{text}"
**分类**："把以下分到类别[{classes}]之一，只输出类别名。文本：{text}"
**RAG 答**："根据资料回答，不知道就说不知道，引用资料编号。资料：{ctx}\n问题：{q}"
**few-shot**："示例：{in→out}×3\n现在：{in}\n输出："
