## §1 推理（Reasoning）— 2025-2026 最大突破

### 1.1 什么是 LLM 的推理

LLM 的"推理"指**多步逻辑链**能力：
- 数学（GSM8K / MATH）
- 代码（HumanEval / LiveCodeBench）
- 形式证明（Lean，[`讲透RL/04`](../讲透RL/04-RL与形式证明.md)）
- 常识 + 因果

### 1.2 推理的三大技术路线

| 路线 | 核心 | 代表 |
|------|------|------|
| **Chain-of-Thought** | 让模型"想一想再答"（few-shot 示范推理过程）| Wei 2022 |
| **Test-Time Compute** | 推理时多采样 + 自我验证 + 搜索 | o1 / R1 / Brown CS224R |
| **RLVR** | 用可验证 reward 训练 reasoning | DeepSeek-R1（[`讲透RL/05`](../讲透RL/05-RLVR的极限.md)）|

> 📘 **激活手段总纲**：22 个推理时激活手段的 5W3H 全解见 [`讲透Prompt/激活LLM能力-5W3H分析.md`](../讲透Prompt/激活LLM能力-5W3H分析.md)（CoT/SC/ToT/ReAct/RAG…含效果/成本/陷阱表）；CoT 机制深讲见 [`讲透Prompt/02`](../讲透Prompt/02-CoT思维链.md)；涌现前提（能力存在性）见 [`讲透基础模型/03-涌现能力.md`](../讲透基础模型/03-涌现能力.md)；四层激活谱系总图见 [`激活大语言模型能力-总结.md`](../激活大语言模型能力-总结.md)。

### 1.3 Test-Time Compute：新的 scaling 维度（详见 [`讲透RL/07 §2 主题④`](../讲透RL/07-2026最新研究全景.md)）

**Brown 的洞察**：传统 scaling 是**训练时加算力**；test-time compute 是**推理时加算力**——同样的模型，给更多推理预算，能力可以提升。

```
训练 compute（传统）: 大模型 + 多数据 → 强能力
test-time compute（新）: 小模型 + 多推理（采样/搜索/反思）→ 强能力
```

**代表**：o1（OpenAI）/ R1（DeepSeek）/ PaCoRe（8B 超 GPT-5，待核 [`讲透RL/07`](../讲透RL/07-2026最新研究全景.md)）。

### 1.4 推理的边界（诚实）

- ✗ **纯 LLM 不可靠**：多位数运算、严格逻辑会错
- 🟡 **CoT + 工具改善**：配计算器/Python/Lean 可达接近完美
- 🟢 **RLVR 有天花板**：[`讲透RL/05`](../讲透RL/05-RLVR的极限.md) 证明 RLVR 是锐化器不是发现器——它放大已有能力，不创造全新能力

## §2 代码（Code）— 最成熟的"工具能力"

### 2.1 LLM 编程的能力来源

代码能力来自**预训练数据中的 GitHub 代码**（~30%）+ SFT/RL 强化。模型在预训练时已经"理解"了代码语法和模式。

### 2.2 评估

| Benchmark | 任务 |
|-----------|------|
| **HumanEval** | 函数级代码生成（经典，但已污染）|
| **MBPP** | 基础编程 |
| **LiveCodeBench** | 动态（防污染）|
| **SWE-bench** | 真实仓库级 bug 修复（最难）|

### 2.3 Code Agent（2026 最热应用）

代码不只是"生成函数"，而是**端到端软件工程**：
- **Cursor / Copilot / Cline**：IDE 集成
- **Devin / OpenHands**：自主完成 issue
- 详见 [`讲透Agent/`](../讲透Agent/)

## §3 Agent 与工具使用 — 2026 商业化最前线

### 3.1 LLM Agent 的本质（详见 [`讲透Agent/00`](../讲透Agent/00-为什么需要Agent.md)）

LLM 本身是**单轮文本生成**。Agent = **LLM + 工具 + 记忆 + 循环**，让它能"行动"。

```
感知（用户输入）
    ↓
LLM 推理（决策调哪个工具）
    ↓
工具调用（API / 代码执行 / 搜索）
    ↓
观察结果，回 LLM
    ↓
循环，直到完成任务
```

### 3.2 工具调用（Function Calling）

**核心**：让 LLM 输出结构化 JSON，指定要调的函数 + 参数。

```json
{
  "function": "search_web",
  "args": {"query": "DeepSeek R1 论文"}
}
```

**训练**：SFT + RL，让模型学会"何时调工具 vs 直接答"。

### 3.3 Agent 的关键技术（详见 [`讲透Agent/`](../讲透Agent/)）

| 技术 | 作用 |
|------|------|
| **ReAct** | 推理 + 行动交替（Thought-Action-Observation）|
| **CoT / ToT** | 思维链 / 思维树搜索（[`讲透Agent/03`](../讲透Agent/03-规划与搜索.md)）|
| **记忆机制** | 短期（context）+ 长期（向量库）（[`讲透Agent/04`](../讲透Agent/04-记忆机制.md)）|
| **多 Agent** | 协作 / 辩论 / 分工 |
| **MCP 协议** | 工具调用标准化（2024 Anthropic）|

### 3.4 Agent RL：让 Agent 越用越聪明

**2026 最热方向**：用 RL 训 Agent（不是训 LLM 本体）。reward = **任务完成度**（代码能跑 / bug 修了 / 用户满意）。

详见 [`讲透RL/07 §2 主题①`](../讲透RL/07-2026最新研究全景.md) + [`讲透Agent/`](../讲透Agent/)。

## §4 多模态 — 让 LLM 看见听见

### 4.1 多模态 LLM 的架构（详见 [`讲透Transformer/10`](../讲透Transformer/10-VisionTransformer与多模态.md)）

```
图像 → ViT → 视觉 token ─┐
                          ├─→ LLM trunk → 文本输出
文本 → tokenizer ─────────┘
```

**核心**：把视觉 token 当作"另一种语言"喂给 LLM。这就是 VLM（Vision-Language Model）。

### 4.2 三大多模态能力

| 能力 | 现状 | 代表 |
|------|------|------|
| **图像理解** | ✅ 成熟 | GPT-4V / Claude / Gemini |
| **视频理解** | 🟡 进行中 | Gemini / V-JEPA |
| **音频理解** | 🟡 进行中 | Whisper / GPT-4o audio |

### 4.3 多模态与机器人的交叉

**VLA**（Vision-Language-Action）= VLM + 机器人动作，详见 [`讲透AIfor各学科/机器人/06`](../讲透AIfor各学科/机器人/06-VLA模型谱系2026.md)。这是多模态 LLM 在机器人域的延伸。

## §5 长上下文 — 让 LLM 记住更多

### 5.1 长上下文的挑战

**标准 Transformer 的注意力是 $O(n^2)$**——上下文从 4K 涨到 1M，计算量涨 6 万倍。

### 5.2 解决方案

| 方案 | 怎么做 | 代表 |
|------|-------|------|
| **稀疏 Attention** | 不让每个 token 看所有 | Longformer / BigBird |
| **线性 Attention** | 核函数近似 | Performer / Linear Attention |
| **KV Cache 优化** | 压缩 / 分页 | PagedAttention（vLLM）|
| **状态空间模型** | 用 SSM 替代 attention | Mamba / RWKV |
| **混合** | 短程 attention + 长程 SSM | Jamba |

### 5.3 长上下文的能力与坑

- ✅ **RAG 替代**：长上下文可以"把整个知识库塞进去"
- ⚠️ **"Needle in Haystack"** 能力不均匀——中间内容容易被忽略
- ⚠️ **成本线性增长**——1M context 的推理成本极高
- 🟢 **混合方案**：长上下文 + RAG + cache 是 2026 最佳实践（详见 [`讲透KV Cache/`](../讲透KV Cache/)）

---

## §6 一句话总结

> 🎯 **5 句话**：
> 1. **推理（reasoning）是 2025-2026 最大突破**：CoT + test-time compute + RLVR，让 LLM 从"会聊天"到"会推理"。
> 2. **代码能力最成熟**：预训练 + RL 强化，Code Agent 是 2026 商业化最前线。
> 3. **Agent = LLM + 工具 + 记忆 + 循环**——2026 商业化最热，Agent RL 是核心增长点。
> 4. **多模态**：视觉成熟、视频/音频进行中，VLM 是机器人的基础（VLA）。
> 5. **长上下文**：稀疏 attention / SSM / cache，但成本与能力需权衡，混合方案是最佳实践。
