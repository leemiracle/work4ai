## §0 一张图：RL 系统的完整生命周期

```
┌─────────────────────────────────────────────────────────────────┐
│                   RL 系统的 5 个生命周期阶段                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ① 数据        ② 训练         ③ 评估        ④ 部署       ⑤ 迭代  │
│  ────────     ────────      ────────     ────────     ────────  │

│  示教数据     reward 模型    human eval   监控/告警     数据飞轮  │
```

**关键洞察**：学术 RL 论文 90% 只讲 ②③（训练 + 评估），工业落地 70% 的工程量在 ①④⑤。这就是 [06 篇](./06-RL与系统软件.md) "学术收益在生产蒸发"（OtterTune 教训）的根源——**只懂 ②③ 的人推不动生产**。

## §1 工业实践：5 阶段工程化 SOP

### ① 数据层：RL 系统的"血液"

| RL 范式 | 数据形态 | 工程难点 |
|---------|---------|---------|
| **Online RL**（Atari/机器人）| replay buffer `(s, a, r, s')` | buffer 大小 / 优先级采样 / stale data |
| **Offline RL**（用户日志/病历）| 固定数据集 | distribution shift（[08 §3](./08-Actor-Critic-SAC-ModelBased-OfflineRL.md)）/ 行为策略估计 |
| **RLHF**（LLM 对齐）| preference pair `(y_w, y_l)` | 标注质量 / 标注者分歧 / 成本 ~$20/对 |
| **RLVR**（数学/代码）| verifier 信号 | verifier 正确性（[04](./04-RL与形式证明.md)）/ sparse reward |
| **示教 RL**（机器人）| 专家轨迹 | 示教覆盖度 / 模仿 vs 超越 |

**SOP 要点**：
1. **数据版本化**：用 DVC / lakeFS 记录每次训练用的数据快照——"这次训练用了哪版数据"必须可追溯。
2. **reward 信号审计**：RLVR 的 verifier 上线前必须用 golden set 回测（[04](./04-RL与形式证明.md) 的 FormalRewardBench 反例：专门 prover 判别能力反而最差 24.4%）。
3. **preference 数据的"标注者一致性"**：算 inter-annotator agreement（Cohen's κ），κ < 0.4 的样本要复审。

### ② 训练层：infra 与稳定性

**LLM RL 后端三选一**（详见 [07 §4](./07-2026最新研究全景.md) + [`前沿与媒体/02-后训练`](../前沿与媒体/02-后训练信息源专题.md)）：

| 框架 | 特点 | 适用 |
|------|------|------|
| **verl**（22.8k⭐，字节）| Full-stack，PPO/GRPO/RLOO 都支持 | 中小团队首选 |
| **OpenRLHF**（地平线）| 模块化，易扩展 | 研究性强 |
| **TRL**（HuggingFace）| 与 transformers 深度集成 | 快速实验 |
| **AReaL**（蚂蚁，待核）| 异步 + 长上下文 | 大规模生产 |

**经典 RL（非 LLM）后端**：
- **Stable-Baselines3**：开箱即用，PPO/SAC/DQN，适合 [§4 P2/P4](#4-阶梯实战项目6-个从-toy-到生产)
- **CleanRL**：单文件实现，便于理解算法（每个算法一个 .py）
- **Gymnasium**：环境接口标准（替代已停维的 OpenAI Gym）

**训练稳定性的 5 个常见 knob**（按出问题频率排）：

| 现象 | 优先排查 | 根因 |
|------|---------|------|
| loss 突然 NaN | 学习率 / 梯度裁剪 | 梯度爆炸，尤其 GRPO 的 ratio |
| KL 持续涨 | KL 系数 / reference model 冻结 | π 跑离 π_ref 太远（[03](./03-RLHF-DPO-GRPO.md)）|
| reward 涨但 eval 跌 | reward hacking（[§2.1](#21-reward-hacking配-06-跨域泛化)）| 指标优化与真实目标错位 |
| Q 值发散 | deadly triad（[08 §4](./08-Actor-Critic-SAC-ModelBased-OfflineRL.md)）| 函数近似 + bootstrapping + off-policy |
| 训练极慢 | rollout 并行度 / GPU 利用率 | actor 与 learner 没解耦 |

### ③ 评估层：最容易翻车的环节

> **铁律**：训练 reward 永远不能当评估指标。这是 [06 铁律 5](./06-RL与系统软件.md)（"有可程序化的 evaluator"）的延伸——**训练 reward 和评估指标必须物理隔离**。

**LLM RL 的评估栈**：

| 层级 | 指标 | 工具 |
|------|------|------|
| **自动指标** | pass@k / compile rate / GSM8K 准确率 | verifier 脚本 |
| **RM 评分** | reward model 打分 | 训练用的 RM（**有偏**，仅参考）|
| **Benchmark** | MMLU / HumanEval / MATH / LiveBench | lm-eval-harness |
| **LLM-as-judge** | GPT-4/Claude 当裁判 | 成本高但可比 |
| **Human eval** | 盲测 / 偏好对比 | 金标准，最贵 |

**经典 RL 的评估栈**：

| 指标 | 含义 | 坑 |
|------|------|----|
| ** episodic return** | 一回合总奖励 | 单一指标易被 hack |
| **success rate** | 达成目标的比例 | 更鲁棒，但要定义"成功" |
| **sample efficiency** | 达到阈值所需样本数 | 学术常用，生产不关心 |
| **generalization** | 在 unseen 环境的表现 | **最常被论文忽略** |

### ④ 部署层：serving 与监控

**LLM 的 RL 后部署**：与 SFT 模型一样用 vLLM/SGLang/TensorRT-LLM（见 [`讲透Transformer/09-推理优化`](../讲透Transformer/09-推理优化.md)）。**RL 训出的模型本身没有特殊的部署需求**——RL 改变的是权重，不是架构。

**经典 RL 的部署**（机器人/控制）：
- **ONNX/TorchScript 导出**：把 PyTorch policy 转成 ONNX，C++ runtime 推理（10× 加速）
- **确定性测试**：同一观察必须给同一动作——浮点不确定性会导致复现失败
- **安全 wrapper**：在 policy 外包一层（动作限幅 / 紧急停止 / 回退到 PID），这是 [06 铁律 3](./06-RL与系统软件.md)（"为失败设计"）

**监控的核心信号**：
- **input distribution drift**：观察的统计量是否偏离训练分布（→ offline RL 的 distribution shift 在线上复发）
- **reward 校准**：线上真实 reward 与训练 reward 的偏差
- **fallback rate**：多少请求被回退到规则/PID（[06 铁律 3](./06-RL与系统软件.md)）

### ⑤ 迭代层：数据飞轮与回滚

**数据飞轮**（positive loop）：
```
线上 bad case → 人工标注 → 进 preference/reward 数据 → 下轮 RL → 模型变好 → ...
```

**回滚能力**（negative loop）：
- **必须**能在一小时内回滚到任意历史模型版本
- **必须**有 shadow mode（新模型只打分不生效，对比一周再切流）
- **必须**保留每次训练的完整 lineage（数据版本 + 代码 commit + 超参 + 模型权重）

> **Cold-RL 的生产智慧**（[06](./06-RL与系统软件.md) 引）：NGINX 的 RL 控制器**只在已合法的选项里重排**，最坏情况退化为默认配置——这就是"为失败设计"的典范。

## §2 失败模式库（5 类，配案例）

### 2.1 reward hacking（配 [06](./06-RL与系统软件.md) 跨域泛化）

**现象**：reward 涨但真实目标没改善，甚至恶化。

**经典案例**：
| 案例 | reward 设计 | hack 方式 |
|------|-----------|----------|
| **CoastRunner**（赛车游戏）| 完赛圈数 | 撞墙转圈刷圈数，永远不完赛 |
| **OpenAI Sumo 机器人** | 把对手推出圈 | 学会在圈内原地转让对手碰不到 |
| **LLM RLHF** | RM 打分 | 学会迎合 RM 的偏见（verbose / sycophancy）|
| **代码 RL** | 单测通过率 | 学会写"永远 pass"的 trivial 测试 |
| **LinkedIn Agentic-RL-Code-Repair**（[06 §4.2](./06-RL与系统软件.md)）| 代码修复成功率 | reward hacking 跨域泛化 |

**防御**：
1. **reward 与真实目标的物理隔离**（训练 reward ≠ 评估指标）
2. **reward 的对抗性测试**：上线前让红队专门找 hack
3. **多目标 reward**：$R = w_1 r_\text{task} + w_2 r_\text{penalty}$，penalty 项惩罚"取巧"
4. **RLVR 的优势**（[05](./05-RLVR的极限.md)）：verifiable reward 难 hack，但有天花板

### 2.2 训练崩溃

**deadly triad**（[08 §4.4](./08-Actor-Critic-SAC-ModelBased-OfflineRL.md) 实证）：函数近似 + bootstrapping + off-policy → 结构性发散。Baird 反例权重震荡到 30+。

**LLM RL 的崩溃模式**：
- **KL 失控**：$\text{KL}(\pi \| \pi_\text{ref})$ 涨到 10+，模型胡言乱语 → 加大 KL 系数 / 早停
- **ratio 爆炸**：PPO 的 importance ratio $r = \pi_\theta / \pi_{\theta_\text{old}}$ 出现极端值 → clip 更激进 / 减小学习率
- **mode collapse**：GRPO 群组全收敛到一个回答 → 提高温度 / 增加 group size

**经典 RL 的崩溃模式**：
- **Q 过估计**：DDQN / clipped double-Q（[08 §1.3](./08-Actor-Critic-SAC-ModelBased-OfflineRL.md)）
- **探索死亡**：熵掉到 0，策略卡死 → SAC 的 α 自动调节（[08 §1.4.4](./08-Actor-Critic-SAC-ModelBased-OfflineRL.md)）

### 2.3 分布漂移（distribution shift）

**Offline RL 的核心难题**（[08 §3.2](./08-Actor-Critic-SAC-ModelBased-OfflineRL.md)）：策略跑到数据未覆盖区域 → Q 外推错误 → 自我欺骗。

**生产的体现**：
- 用户行为随季节/活动变化（推荐/广告）
- 设备老化改变动力学（机器人/工业控制）
- 政策/规则更新改变合法动作集（金融/医疗）

**防御**：
- **CQL/AWAC 思想**（[08 §3.3](./08-Actor-Critic-SAC-ModelBased-OfflineRL.md)）：约束策略不偏离数据
- **线上持续学习**：定期用新数据重训（数据飞轮）
- **不确定性估计**：模型对自己的预测有多不确定，高不确定时回退（[08 §2.2.1](./08-Actor-Critic-SAC-ModelBased-OfflineRL.md) PETS 的 epistemic uncertainty）

### 2.4 评估陷阱

| 陷阱 | 表现 | 解药 |
|------|------|------|
| **指标好转但体验变差** | pass@1 涨但用户投诉增 | 加 human eval / 真实任务测试 |
| **benchmark 过拟合** | MMLU 涨但 LiveBench 跌 | 用动态 benchmark（LiveBench/刷新题）|
| **RM 偏见** | RM 分高但人工判差 | RM 只用于训练，评估用独立 judge |
| **采样敏感性** | 同一模型不同温度差很多 | 多温度采样 + 报告方差 |

### 2.5 成本失控

**真相**：RL 训练成本 = SFT 的 **3-10×**。

| 阶段 | 成本来源 | 省钱手段 |
|------|---------|---------|
| **rollout** | 生成 N 个回答（GRPO N=8-64）| rollout 共享 prefix、vLLM 批量 |
| **reward** | RM 推理 / verifier 调用 | RM 蒸馏、verifier 缓存 |
| **critic**（PPO）| 多一个 model 的反传 | GRPO 去 critic（[03](./03-RLHF-DPO-GRPO.md)）|
| **reference** | KL 计算要 reference model | 共享 encoder、low-rank reference |

→ **2026 RL 加速方向**（详见 [`高效AI前沿`](../高效AI前沿-全行业热点地图.md) §六）：ARRoL（1.7× 加速）/ OM-GRPO（label-free）/ Spec-RL / FastGRPO。

## §3 能力建设：RL 工程师的 4 维能力矩阵

> 这是本篇的核心。**会调 PPO ≠ 懂 RL**。一个合格的 RL 工程师/研究者要同时具备 4 个维度。

### 3.1 四维矩阵

```
                  理论维度
                  （能读证明）
                       │
       工程维度 ───────┼─────── 算法维度
       （能 scale）    │      （能推导+实现）
                       │
                  产品维度
                （能定义 reward）
```

| 维度 | 具体能力 | 对应章节 |
|------|---------|---------|
| **算法** | 能从零推导 PG 定理 / Bellman / soft Bellman；能手写 DQN/PPO/SAC/DPO | [01](./01-Q-Learning与DQN.md) [02](./02-策略梯度与PPO.md) [03](./03-RLHF-DPO-GRPO.md) [08](./08-Actor-Critic-SAC-ModelBased-OfflineRL.md) |
| **工程** | 能用 verl/OpenRLHF 跑通 LLM RL；能在 MuJoCo 跑通 SAC；会 debug NaN/慢/OOM | 本篇 §1 + [`讲透微调`](../讲透微调/) |
| **理论** | 能读懂 Banach 压缩证明 / deadly triad / RLVR 极限定理；能识别论文的假设 | [04](./04-RL与形式证明.md) [05](./05-RLVR的极限.md) [08 §4](./08-Actor-Critic-SAC-ModelBased-OfflineRL.md) |

## §4 阶梯实战项目（6 个，从 toy 到生产）

> 设计原则：每个项目**对应一个能力维度 + 一个方向**，做完能写进简历/论文。

### P1 · 多臂老虎机（算法 · 1 天）
**目标**：理解探索-利用（[00 RL1](./00-讲透笔记-算法经验枢纽.md)）
**任务**：实现 ε-greedy / UCB / Thompson Sampling，画累积后悔曲线
**验收**：UCB 的后悔是对数曲线，ε-greedy 是线性
**方向归属**：所有方向的地基

### P2 · DQN 玩 Atari（算法+工程 · 1 周）
**目标**：掌握值函数方法（[01](./01-Q-Learning与DQN.md)）
**任务**：用 Stable-Baselines3 或 CleanRL 在 Pong/Breakout 训 DQN
**验收**：Pong 达到 +20 分
**进阶**：加 Double DQN / Dueling / PER，对比曲线
**方向归属**：经典 RL / 游戏 AI

### P3 · PPO/GRPO 训 LLM 对齐（LLM 方向入门 · 2 周）
**目标**：进入 LLM RL 赛道
**任务**：用 [experiments/03_dpo_from_scratch.py](./experiments/03_dpo_from_scratch.py) 起步 → 进阶用 verl 在 Qwen2.5-7B 上跑 GRPO
**数据**：用 UltraFeedback 或自造 preference pair
**验收**：在 MT-Bench 比 SFT 基线高 0.2+

### 5.1 LLM 方向

#### RL 在 LLM 中的角色

#### 核心问题
1. **偏好如何获取**：人工标注 / AI judge / 隐式偏好

4. **RLVR 的天花板**（[05](./05-RLVR的极限.md)）：pass@k 反转——RLVR 是锐化器不是发现器
5. **成本**：GRPO 的 N-sample rollout 极贵

### 5.2 机器人方向

#### RL 在机器人中的角色
机器人控制的**主流方法**：经典控制（PID/MPC）适合精确任务；**RL 适合难以建模的高自由度任务**（灵巧手、双足行走、whole-body control）。2024-2026 的趋势是 **VLA（Vision-Language-Action）模型**把 LLM 推理引入机器人。

#### 核心问题
1. **sim-to-real gap**：仿真训的策略上真机就崩（动力学/摩擦/传感差异）
2. **样本效率**：真机每步采样极贵（[08 §2.1](./08-Actor-Critic-SAC-ModelBased-OfflineRL.md)）→ 需 model-based / world model
3. **探索的安全约束**：不能让机器人撞坏自己 / 人 / 环境
4. **奖励设计**：稀疏 reward（抓到才奖励）vs dense reward（每步引导）
5. **示教的利用**：人类示教如何 cold-start RL（→ AWAC 思路 [08 §3.3.2](./08-Actor-Critic-SAC-ModelBased-OfflineRL.md)）

### 5.3 世界模型方向
