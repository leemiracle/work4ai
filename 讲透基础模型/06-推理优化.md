# 06 — 推理优化：KV Cache、量化、蒸馏

> 承接 00–05：模型训好了、对齐了。但**推理又慢又贵**——GPT-4 级模型一次生成要算万亿次浮点、占几百 GB 显存。这一篇讲透：让大模型"又快又省地跑"的三大支柱。
>
> 配套实验：`experiments/06_inference.py`。

---

## 1. 为什么推理慢/贵？

两个根源：

1. **自回归生成**：一次只产一个 token，每个新 token 要"关注"所有历史 token。生成长度 $n$ 的文本，总计算量是 $O(n^2)$ 量级（attention）甚至 $O(n^3)$（不带 cache 的朴素实现）。
2. **模型巨大**：70B 参数 × 4 字节（FP32）= 280GB，光加载就要 4–8 张高端 GPU。

三大优化分别针对这两点：**KV Cache**（降计算）、**量化**（降显存）、**蒸馏**（降模型大小）。

---

## 2. KV Cache：自回归生成的命门

### 问题

朴素生成时，每生成第 $t$ 个 token，要对**整个长度 $t$ 的序列**重新算 3 个投影（$Q=W_qX, K=W_kX, V=W_vX$）+ attention。历史的 $K/V$ 被反复重算——这是巨大浪费。

### 解法

**历史的 $K/V$ 算过一次就存起来**，之后每个新 token 只算它自己的 $q,k,v$，把新 $k,v$ 追加进缓存，用新 $q$ 对全部缓存 $K$ 做 attention。

### 计算量对比（`06_inference.py` Part 1）

| | 生成第 $t$ 个 token | 总（生成 $N$ 个） |
|---|---|---|
| 无 cache | $3td^2 + 2t^2d$ | $O(d^2N^2) + O(dN^3)$ |
| 有 cache | $3d^2 + 2td$ | $O(d^2N) + O(dN^2)$ |

实验数字（$d=256$，生成 80 token）：

```
总 FLOPs:  无cache 9.0e8  vs  有cache 1.8e7   →  减少 51x
序列长 90 时单步: 无cache 是有cache的 90x
```

**KV Cache 把生成从 $O(n^2)$/步 降到 $O(n)$/步**。没有它，ChatGPT 的流式输出根本不可能。

> ⚠️ 实验里 CPU 墙钟计时体现不出这个优势（小矩阵下 kernel-launch overhead 主导）。真实加速需要 GPU + FlashAttention 等融合 kernel，可达数十倍。本实验用**理论 FLOPs**揭示本质。

### 代价

KV Cache 占显存 = $2 \times n_{\text{layer}} \times n \times d \times \text{batch}$。长上下文（10 万 token）下 KV Cache 能吃掉几十 GB——这是 **PagedAttention**（vLLM）、**KV 量化**、**滑动窗口注意力**等后续优化的战场。

## 3. 量化：用更少比特存权重

### 思想

权重多半集中在 0 附近、范围有限。FP32（32 bit）远超必要，可以映射到 INT8（8 bit）甚至 INT4（4 bit）。

### 实验（Part 2）

```
FP32 → INT8:  误差 6e-4,  显存省 4x  (误差/权重幅度 1.0%, 几乎无损)
FP32 → INT4:  误差 1e-2,  显存省 8x  (误差/权重幅度 17.5%, 经 AWQ/GPTQ 优化后可用)
```

**工程意义**：70B 模型 FP32 需 280GB，INT4 仅 35GB——**单张 A100/H100 即可跑**。这是开源大模型能在消费级硬件部署的关键。

### 进阶

- **AWQ / GPTQ**：不是均匀量化，而是识别"重要权重"（激活幅度大的通道）保高精度、其余压低，INT4 下几乎无损。
- **KV 量化**：不只量化权重，连 KV Cache 也量化，省显存换速度。
- **局限**：量化对 outlier（异常大权重）敏感，而 LLM 恰好有 outlier——这就是为什么需要 AWQ 这类专门算法。

## 4. 蒸馏：大模型教小模型

### 思想（Hinton 2015）

大模型（teacher）的输出概率分布含**暗知识**——比如判断"这是猫"时，它可能给"狗"也留了点概率，暗示猫狗相似。小模型（student）学这个**软分布**，比只学硬标签（就是猫）学得更好。

### 损失

$$\mathcal{L} = \alpha\,\underbrace{\text{CE}(s, \text{硬标签})}_{\text{学对错}} + (1-\alpha)\,\underbrace{\text{KL}\big(\text{softmax}(s/T) \,\|\, \text{softmax}(t/T)\big)}_{\text{学 teacher 的类间关系}}$$

$T$ 是温度：$T$ 越大分布越软，暗知识越明显。

### 应用

- **Alpaca / Vicuna**：用 GPT-4 生成问答数据，蒸馏到 LLaMA-7B——"穷人的 GPT-4"。
- **DeepSeek-R1 蒸馏**：把 R1 的推理能力蒸馏到 1.5B/7B 小模型，让小模型也会思维链。
- **"数据蒸馏" > "logits 蒸馏"**：现代更常用大模型**生成数据**再 SFT 小模型（因为 logits 对齐麻烦，数据更灵活）。

## 5. 其他重要优化（简要）

| 技术 | 一句话 | 谁在用 |
|---|---|---|
| **FlashAttention** | 融合 attention 的多个 kernel，少读写 HBM，IO 层加速 2–4x | 所有主流 LLM |
| **推测解码 (Speculative Decoding)** | 小模型先草拟多个 token，大模型并行验证，打破自回归串行 | vLLM、DeepSeek |
| **MoE（混合专家）** | 每次只激活部分参数，总参数大但单次计算小 | GPT-4、Mixtral、DeepSeek-V3 |
| **连续批处理** | 动态拼接多个请求的 batch，提升吞吐 | vLLM、TGI |
| **PagedAttention** | 类 OS 分页管理 KV Cache 显存，近乎零碎片 | vLLM |

---

## 6. 一句话总结

> **大模型推理慢/贵，三大优化对症下药：①KV Cache 复用历史 K/V，把生成从 O(n²)/步降到 O(n)/步（实验中计算量减 51x），是流式输出的命门；②量化把 FP32 权重压到 INT8/INT4，70B 模型从 280GB 降到 35GB 单卡可跑，代价是 1%–17% 的微小精度损失；③蒸馏用大模型的软标签/生成数据训小模型，是"穷人的 Scaling Law"。配合 FlashAttention、推测解码、MoE 等，才让大模型从"实验室玩具"变成"可部署产品"。**
