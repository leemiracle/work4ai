# 讲透微调 · 思想史

> **一句话定位**：微调的历史是一部"动多少参数"的振荡史——从 CV 时代的"冻住特征、只训分类器"，到 2018 年的"全都要动"，再到 LoRA 时代"只动 1%"——每一次范式转移都是"通用↔专用"这一核心矛盾在新的模型规模上的重新求解。
>
> **与 [`讲透AI历史`](../讲透AI历史/) 的关系**：本篇是 AI 通史的**微调专项纵深**——通史覆盖五次范式转移（符号→连接→概率→深度→大模型，[`讲透AI历史/advanced/01`](../讲透AI历史/advanced/01-范式转移的库恩分析.md)），本篇聚焦"预训练之后、部署之前"这一段，追问：**为什么微调从全参数走向了参数高效？为什么 LoRA 赢了 Adapter？为什么对齐微调（RLHF/DPO）和参数高效微调（LoRA）最终合流？**
>
> **与 [`讲透LLM/HISTORY.md`](../讲透LLM/HISTORY.md) 的关系**：LLM 思想史问"模型本身怎么来的"，本篇问"**拿到预训练模型之后，怎么把它变成你要的样子**"。两者在 2018 ULMFiT/BERT 处交汇——那是预训练范式的起点，也是微调范式的起点。
>
> **方法论前提**：严格遵循 [`讲透AI历史/00`](../讲透AI历史/00-为什么学AI历史.md) 五原则——思想史 > 年代史、路径依赖敏感、失败与成功同等重要、跨学科、批判性。**不写"年份+方法+指标"的综述。**

## 0. 方法论：用思想史看微调

在进入历史之前，先建立**怎么读**的能力。

**年代史陷阱**：如果只看"2013 feature-based → 2018 fine-tune 全栈 → 2019 Adapter → 2021 LoRA → 2023 QLoRA/PEFT → 2023 DPO → 2024 模型合并"，你会以为历史是"方法越来越省参数、越来越聪明"的线性进步——每个节点都比前一个好。

**思想史纠正**：每一个节点背后都有**为什么此时此地**的问题：
- 为什么 CV 时代的 feature-based transfer（冻住 CNN、只训顶层分类器）"够用"了十年，到了 NLP 却突然要"全参数微调"才 work？
- 为什么"全参数微调"赢了 2018-2020，却在 2021 年被 LoRA 逆转——**赢的那个范式自己制造了失败条件**？
- 为什么 Adapter（2019）比 LoRA（2021）早两年、效果相当，却被淘汰——是科学问题还是工程问题？
- 为什么 Aghajanyan 的"本征维度"（2020-12）发现"微调只需 200 个参数"，但直到 LoRA（2021-06）才被工程化？
- 为什么 RLHF 的"对齐微调"和 LoRA 的"参数高效微调"看似两条独立的技术线，却在 2023 年的实践中合流（QLoRA + DPO）？

**核心判断工具**：每次看到一个"突破"，问三问——① 这个思想的**前世**是什么？② **为什么此时此地**爆发（模型规模/显存/数据到位了吗）？③ 谁在**抵抗**它？为什么？

> 🎯 **博士级核心**：微调史不是"方法越来越好"的进步叙事，而是一部**"动多少参数"的振荡史**。核心矛盾始终是"**通用基座↔任务专用**"——每一次范式转移都是在这个矛盾的两极之间找到新的平衡点，而平衡点的位置由**模型规模**决定：模型越小，全参数微调越可行；模型越大，参数高效越必要。**当前的 LoRA 主导不是因为它"最好"，而是因为模型已经大到全参数微调不可承受。**

## 1. 前夜：CV 迁移学习的"冻住"哲学

### 1.1 迁移学习的两种姿势

微调史的真正起点不在 NLP，而在计算机视觉（CV）。2012 年 AlexNet 在 ImageNet 上证明深度学习可行后，CV 社区立刻面对一个问题：**ImageNet 上训好的 CNN，能不能迁移到其他视觉任务？**

答案分两种姿势，这构成了微调史最底层的分叉：

| 姿势 | 名称 | 改什么 | 冻什么 |
|---|---|---|---|
| **冻住** | feature-based transfer（特征迁移） | 只训顶层分类器 | 冻住整个 CNN backbone |
| **全动** | fine-tune（微调） | 更新所有参数 | 不冻 |

2013-2016 的 CV 实践几乎一致选择了 **feature-based**：把 ImageNet 预训练的 CNN（VGG/ResNet）当**特征提取器**冻住，只训一个浅层分类器（SVM、MLP）放上面。

### 1.2 DeCAF：冻住就够好（Donahue et al. 2014）

2014 年，UC Berkeley 的 Jeff Donahue 等人发表 *DeCAF: A Deep Convolutional Activation Feature for Generic Visual Recognition*——把 AlexNet 在 ImageNet 上训好的中间层特征（activation）直接拿出来，冻住，只训顶层分类器，就在 Caltech-101、Scene-15 等多个数据集上刷出 SOTA。

**核心发现**：ImageNet 预训练的 CNN 特征**天生通用**——底层学到了边缘/纹理，高层学到了物体部件/语义概念。这些特征直接迁移到完全不同的视觉任务上就够用，**不需要动 backbone**。

同年，Yosinski 等人发表 *How Transferable Are Features in Deep Neural Networks?*——系统分析了 CNN 各层的可迁移性：底层（通用特征）迁移效果好，高层（任务特异性强）迁移时需重训。这篇文章给出了一个关键洞见：**网络的不同层有不同的"任务特异性"——底层通用，高层专用。**

### 1.3 "冻住"哲学的深层逻辑

为什么 CV 选择了 feature-based？三个原因：

1. **计算成本**：2013-2016 的 GPU 跑不动反复 backprop 整个 ResNet（152 层），冻住 backbone 只训浅层分类器快几个数量级。
2. **过拟合**：小数据集上微调整个深网络会过拟合（破坏预训练学到的通用特征）。冻住反而是正则。
3. **效果够用**：DeCAF 证明冻住就能达到接近 SOTA——"够好"就不追求"最优"。

**但 feature-based 有天花板**：当目标任务和 ImageNet 差异大（如医学影像、细粒度分类），冻住的通用特征不够好，需要微调高层。实践中出现了**部分微调**（冻底层、解冻高层）的折中方案。

> 🎯 **思想史洞察**：CV 迁移学习的十年实践（2012-2022）确立了一个**根深蒂固的直觉**：预训练模型是"特征提取器"，迁移时应该**尽量少动它**。这个直觉在 2018 年的 NLP 被**短暂推翻**（全参数微调赢了），然后在 2021 年以 LoRA 的形式**重新确立**——"少动"哲学最终回归，只是换了一种更聪明的"少动"方式（低秩增量而非完全冻住）。**这是微调史最重要的辩证回路。**

## 2. 第一次范式转移：fine-tune 全栈（2018）

### 2.1 旧范式：NLP 的特征工程时代

在 2018 年之前，NLP 的"迁移学习"也是 feature-based 风格：用 word2vec/GloVe 把词变成向量（冻住的"预训练特征"），然后在上面训任务特异性模型。

这和 CV 的 DeCAF 哲学完全一致——**预训练的东西冻住，只训下游**。

但 NLP 的 feature-based 比.cv 的更脆弱：静态词向量（word2vec）无法处理一词多义（"bank"是河岸还是银行），迁移效果有限。这为 2018 年的范式转移埋下了伏笔。

### 2.2 ULMFiT：全参数微调的宣言（Howard & Ruder, 2018-01）

2018 年 1 月，Jeremy Howard 和 Sebastian Ruder 发表 *Universal Language Model Fine-tuning for Text Classification*（ULMFiT），做了一个看似大胆的决定：

**不要只训顶层分类器——微调整个语言模型。**

ULMFiT 的三阶段流程：
1. **通用领域预训练**：在 Wikitext-103 上训练 LM（学通用语言能力）
2. **目标领域微调**：在目标任务的语料上继续训练 LM（学领域语言）
3. **分类器微调**：加分类头，微调**整个模型**（包括 LM 部分）

ULMFiT 的贡献不是某个算法，而是一个**概念宣言**：在 NLP，**全参数微调**是有效的迁移方式——不是"冻住预训练特征 + 训顶层"，而是"解冻一切 + 在目标数据上重训全部"。

为了防止全参数微调的灾难性遗忘，ULMFiT 引入了三个关键技术：**discriminative fine-tuning**（不同层用不同学习率，底层小、高层大）、**slanted triangular learning rates**（先升后降的学习率调度）、**gradual unfreezing**（从顶到底逐层解冻）。这三个 trick 本质上都是在**控制全参数微调的"动太多"风险**——这与后来 LoRA 的"动少一点"哲学形成呼应。

### 2.3 为什么 NLP 选了"全动"而 CV 选了"冻住"？

这是微调史最有趣的对比：

| 维度 | CV（2012-2018） | NLP（2018+） |
|---|---|---|
| 默认迁移方式 | feature-based（冻住 backbone） | full fine-tuning（全动） |
| 预训练特征质量 | CNN 中间层特征高度通用 | LSTM 上下文特征不如 CNN 强 |
| 模型规模 | ResNet-152 = 60M 参数 | BERT-base = 110M，BERT-large = 340M |
| 全参数微调可行性 | 深网络 backprop 贵 | 110-340M 参数"刚好"能全动 |

**关键差异**：CV 时代（2012-2018）的模型最大也就 ResNet-152（60M），全参数微调技术上可行但实践中不必要（冻住就够好）。NLP 时代（2018-2020）的模型（BERT/GPT）也还在 100-350M 量级，全参数微调完全可行，而且**明显比 feature-based 好**——因为 Transformer 的上下文表征质量高于静态词向量，值得全参数适配。

**但这恰恰埋下了下一次范式转移的种子**：全参数微调的可行性依赖于"模型不够大"。一旦模型大到 175B（GPT-3），全参数微调就从"默认选项"变成了"奢侈品"。

### 2.4 BERT/GPT：全参数微调的黄金期（2018-2020）

ULMFiT 之后，ELMo（2018-02）、GPT-1（2018-06）、BERT（2018-10）相继确立"预训练 + 全参数微调"范式。这一时期的标准流程：

```
预训练（大规模无标注）→ 全参数微调（任务标注数据）→ 部署
```

每个任务微调出一份完整模型。BERT 刷爆 GLUE 11 项 SOTA，每一项都是一份全参数微调的 BERT。

**全参数微调的黄金期特征**：
- 模型 100-350M 参数，单 GPU 可训
- 每个任务存一份完整模型（340MB），存储可接受
- 效果明显优于 feature-based——全参数微调成为共识

**但黄金期的裂缝**：当 OpenAI 把模型推到 GPT-2（1.5B, 2019）甚至 GPT-3（175B, 2020），全参数微调的成本开始爆炸：
- GPT-3 175B 全参数微调需要 ~1TB 显存（Adam 优化器状态 = 2× 参数量）
- 每个任务存一份 175B 模型 = 700GB 存储
- 只有 OpenAI 自己训得起

**这正是库恩意义上的"异常累积"**：全参数微调范式在"模型变大"这个维度上碰到了结构性障碍。危机正在酝酿——解决方案会在 2019-2021 年到来。

> 🎯 **博士级训练**：ULMFiT（2018）教会我们——一个范式的"正确性"依赖于**隐含的规模假设**。全参数微调在 100-350M 是对的，但这个"对"预设了"模型不够大"。**当模型大到全参数微调不可承受时，旧范式的胜利条件就变成了失败条件。** 这就是为什么 fine-tune 全栈赢了一时又输给了 LoRA——不是 LoRA 更聪明，而是模型变大了。

## 3. Adapter：参数高效的第一次尝试（2019）

### 3.1 问题的提出：每任务一份模型太贵

2019 年初，Google Brain 的 Neil Houlsby 等人面对一个工程问题：BERT 在 GLUE 上有 26 个分类任务，**全参数微调需要 26 份完整 BERT 模型**。能不能只加"一点点参数"就适配新任务，同时共享底座？

2019 年 2 月，Houlsby 等人发表 *Parameter-Efficient Transfer Learning for NLP*（arXiv:1902.00751），提出 **Adapter**：

**在每个 Transformer 层内部插入一个小的瓶颈模块**（bottleneck）：$d \to r \to d$（$r \ll d$），冻住原始权重，只训 Adapter 参数。

$$h \leftarrow h + f(h \cdot W_{\text{down}}) \cdot W_{\text{up}}$$

其中 $W_{\text{down}} \in \mathbb{R}^{d \times r}$、$W_{\text{up}} \in \mathbb{R}^{r \times d}$，$f$ 是非线性激活。 Adapter 只增加 ~3.6% 的参数，在 GLUE 上达到全参数微调的 99.6% 性能。

### 3.2 Adapter 的概念贡献

Adapter 在概念上做了两件事：

1. **冻结基座 + 只训增量**：回到了 CV 时代的"冻住"哲学，但更精细——不是完全冻住（在每层注入可学习模块），而是"冻住主干、训练分支"。
2. **任务可组合**：每个任务只存一个小 Adapter（几 MB），底座共享（一份 BERT）。N 个任务 = 1 个底座 + N 个 Adapter，而非 N 个完整模型。

这与 ULMFiT 的 gradual unfreezing 思路相反——ULMFiT 解冻主干，Adapter 永久冻主干。

### 3.3 AdapterHub 与 AdapterFusion：组合性的尝试（2020）

2020 年，Pfeiffer 等人发布了 **AdapterHub**——一个 Adapter 的"应用商店"，收集了数百个任务的预训练 Adapter。配套的 **AdapterFusion** 技术可以把多个任务的 Adapter 组合成一个多任务模型。

**思想史意义**：AdapterHub 试图建立"**微调模块的生态**"——一个模型 + 一堆即插即用的 Adapter，像乐高积木一样组合。这个愿景在 2020 年看起来很有希望。

**但 Adapter 有一个致命缺陷**——下一节会看到，正是这个缺陷让它在两年后被 LoRA 淘汰。

### 3.4 Adapter 的"不可消除的推理税"

Adapter 的瓶颈模块（$d \to r \to d$）是**永久插入在网络中的额外层**。推理时每次前向传播都要多算一次：

$$\Delta\text{FLOPs/层} = 2 \times d \times r \quad (\text{不可消除})$$

这看起来不多（3.6% 参数 → ~5% 额外 FLOPs），但在**在线推理**场景下是硬伤：
- 每个 request 多算一层 → 延迟增加
- 无法把 Adapter 的效果"合并"回原始权重——它永远是额外开销
- 部署时必须修改推理代码（多了一个模块），工程复杂度上升

**对比 feature-based（CV）**：feature-based 也冻住主干，但它训的顶层分类器**在主干之外**——推理时主干照常跑，分类器在最后一步附加，不影响主干计算。Adapter 把增量插在主干**内部**，无法脱离主干独立计算。

> 🎯 **思想史模式**：Adapter 是一个"**概念正确但工程有缺陷**"的经典案例。它第一次系统证明了"参数高效微调"可行（只加 3.6% 参数 ≈ 全参数微调），但它在**推理延迟**上的不可消除代价，注定了它会被一个"效果相当但推理零开销"的替代者淘汰。**科学上 Adapter 和 LoRA 没有本质区别——决定胜负的是推理路径上的工程约束。** 这揭示了一个深刻教训：**在微调方法的竞争中，推理成本比训练成本更致命。**

## 4. 第二次范式转移：LoRA（2021）

### 4.1 本征维度：LoRA 的理论前夜（Aghajanyan 2020）

2020 年 12 月，Facebook AI 的 Armen Aghajanyan、Luke Zettlemoyer、Sonal Gupta 发表 *Intrinsic Dimensionality Explains the Effectiveness of Language Model Fine-Tuning*（arXiv:2012.13255），做了一个惊人的发现：

**预训练模型微调时，权重的有效更新只发生在极低维的子空间里。**

具体地：他们用随机投影把 RoBERTa 的全参数空间（125M 维）压到只有 **200 维**，在 MRPC 任务上微调这 200 个参数，就能达到全参数微调 **90%** 的性能。

更惊人的是：**预训练越好的模型，微调所需的本征维度越低**。模型越大，本征维度反而越低——预训练已经把权重调到了一个"好区域"，微调只需在低维流形上微调即可。

这是 LoRA 的**直接理论前夜**。Aghajanyan 证明了"微调的 ΔW 是低秩的"，但他用的方法（随机投影 + 低维子空间优化）在实践中不方便——每次微调要固定一个随机投影矩阵，灵活性差。

**缺的最后一块拼图**：一个**可学习的、可合并的、推理零开销**的低秩参数化方式。

### 4.2 LoRA：低秩增量的完美参数化（Hu et al. 2021-06）

2021 年 6 月，Microsoft 的 Edward Hu 等人发表 *LoRA: Low-Rank Adaptation of Large Language Models*（arXiv:2106.09685），给出了那块拼图：

$$W_{\text{新}} = W_0 + \Delta W = W_0 + B \cdot A, \quad B \in \mathbb{R}^{d \times r},\; A \in \mathbb{R}^{r \times d},\; r \ll d$$

**冻结 $W_0$，只训 $B$ 和 $A$**。可训练参数从 $d^2$ 降到 $2dr$。以 GPT-3 175B 为例，LoRA 把可训练参数减少 **10000 倍**，GPU 显存需求降低 **3 倍**。

**关键创新——初始化的妙处**：$B$ 用零初始化，$A$ 用高斯初始化。这意味着训练开始时 $\Delta W = B \cdot A = 0$——**模型严格等于基座**，然后从 0 慢慢长出增量。这个 trick 保证 LoRA "从基座出发"而非"从随机扰动出发"，训练极其稳定。

**为什么 LoRA 比 Aghajanyan 的随机投影好？** 因为 $\Delta W = BA$ 是**可合并**的——训练结束后，把 $BA$ 加到 $W_0$ 上（$W_0 + BA$），就得到一个普通权重矩阵，推理时和原始模型**完全一样，零额外开销**。这正是 Adapter 做不到的。

### 4.3 为什么说 LoRA 是范式转移（库恩意义上）

**旧范式**（全参数微调）：每个任务更新全部参数 → 存全部模型 → 推理时每个任务一个完整模型。

**新范式**（LoRA）：每个任务只训一对小矩阵 $BA$ → 存几 MB 的"任务补丁" → 推理时把 $BA$ 合并回基座，零额外开销。

**不可通约性**：旧范式问"如何为任务 X 微调整个模型"，新范式问"如何用最少的增量参数把通用模型适配到任务 X"。问题从"动多少"变成了"怎么用最少参数达到等效的动"。

**异常的消解**：LoRA 直接消解了全参数微调在超大模型上的三个异常（显存爆炸、灾难遗忘、多任务存储）——通过只动 1% 参数，三个问题同时缓解。

### 4.4 LoRA vs Adapter：一场纯工程决胜

| 维度 | Adapter（2019） | LoRA（2021） |
|---|---|---|
| 效果 | ≈ 全参数微调 99.6% | ≈ 全参数微调（持平或更好） |
| 参数量 | ~3.6% | ~0.1-1% |
| 推理开销 | **永久多一层**（不可消除） | **零**（可合并进 $W_0$） |
| 可热插拔 | 是（换 Adapter） | 是（换 $BA$） |
| 工程复杂度 | 需改推理代码 | 不需要（合并后是普通模型） |

**结论**：科学上两者没有本质差异——都是"冻住主干 + 训增量"。但 LoRA 赢在**推理零开销**。这是一个纯工程决胜的案例。

> 🎯 **博士级洞察**：LoRA 赢了 Adapter，不是因为 LoRA 的数学更优雅（两者都是低秩），也不是因为效果更好（两者相当），而是因为 LoRA 的增量可以**合并回权重**——这个性质让 LoRA 在部署时**完全透明**。**在工业界，一个"训练时存在但推理时消失"的方法，永远比"永久占用资源"的方法有优势。** 这揭示了微调方法竞争的一条潜规则：**推理成本是终局裁判。**

### 4.5 LoRA 的诚实边界

LoRA 不是万能的：

1. **低秩假设的适用范围**：当任务和预训练差异巨大（全新语言、全新模态），$\Delta W$ 不再低秩，LoRA 明显不如全参数微调。
2. **rank 选择的难题**：$r$ 太小欠拟合，$r$ 太大退化成全参数微调（失去意义且过拟合）。实践中 $r=8/16/32$ 是经验甜区，但缺乏理论指导。
3. **知识注入的局限**：LoRA 擅长改"行为/格式/风格"，不擅长注入新"知识"（事实性知识用 RAG 更有效）。

这些边界在 [`00-为什么LoRA能用1%参数逼近全参数微调`](./00-为什么LoRA能用1%参数逼近全参数微调.md) 和 [`05-微调失败模式`](./05-微调失败模式.md) 有实验验证，此处不展开。

## 5. 第三次范式转移：QLoRA + PEFT 生态（2023）

### 5.1 开源浪潮：微调民主化的前夜

2023 年初，LLaMA 权重泄漏（详见 [`讲透LLM/HISTORY.md §7`](../讲透LLM/HISTORY.md)），开源社区第一次拿到了 7B-65B 级别的优质基座模型。但拿到模型≠能微调——65B 模型全参数微调需要 ~1TB 显存（8×A100 80GB 都不够）。

**LoRA 已经把可训练参数降到 0.1%，但基座本身仍需以全精度（fp16）驻留显存**——65B × 2 bytes = 130GB，仍然超过单卡 48GB。

裂缝出现了：**LoRA 解决了"训多少"，但没解决"基座多大能驻留"。**

### 5.2 QLoRA：显存革命（Dettmers et al. 2023-05）

2023 年 5 月，University of Washington 的 Tim Dettmers 等人发表 *QLoRA: Efficient Finetuning of Quantized LLMs*（arXiv:2305.14314），给了致命一击：

**把基座量化到 4-bit（NF4），冻住，然后在上面做 LoRA。**

QLoRA 的三个创新：
1. **NF4（4-bit NormalFloat）**：一种信息论最优的 4-bit 数据类型，专门为正态分布的权重设计。量化误差比普通 INT4 更小。
2. **Double Quantization**：把量化常数本身也量化，进一步省显存（每参数省 ~0.4 bit）。
3. **Paged Optimizers**：用 NVIDIA 统一内存处理显存峰值，避免 OOM。

**结果**：65B 模型在**单张 48GB GPU** 上微调，24 小时完成，效果达到全精度 LoRA 水平。训练出的 Guanaco 模型在 Vicuna benchmark 上达到 ChatGPT 99.3% 的水平。

**QLoRA 的思想史意义**：
- **它把"训不起"变成了"单卡能训"**——这是开源微调的事实标准起点。
- **它把量化（inference 技术）和 LoRA（training 技术）合流**——以前量化是为了部署（推理省显存），QLoRA 证明量化基座上也能训练（梯度通过 4-bit 冻结层回传到 LoRA）。
- **它开启了"人人能微调"的时代**——任何人有一张消费级显卡就能微调 70B 模型。

### 5.3 PEFT 库：参数高效微调的"统一框架"（HuggingFace 2023）

QLoRA 出现的同时，HuggingFace 的 **PEFT（Parameter-Efficient Fine-Tuning）** 库在 2023 年初发布，成为 LoRA/Adapter/Prefix/Prompt Tuning 的统一接口。

PEFT 库的思想史意义不在某个算法，而在**标准化**：
- 一个 API 调用就能切换 PEFT 方法（`peft.LoraConfig` / `peft.AdapterConfig` / ...）
- 统一了模型保存格式（只存 Adapter 权重，几 MB）
- 与 Transformers/Accelerate/TRL 生态无缝集成

**标准化降低了迁移成本**——研究者不用再为每个 PEFT 方法手写训练循环，社区创新速度被加速。这和 2015 年 Keras 之于深度学习的角色类似：**不是新算法，而是让旧算法更容易用。**

### 5.4 Prefix/Prompt Tuning：另一条路的兴衰

在 LoRA 和 Adapter 之外，还有一条独立的 PEFT 路线——**不改权重，改输入**：

| 方法 | 论文 | 改什么 | 参数量 |
|---|---|---|---|
| **Prefix Tuning** | Li & Liang, 2021 | 每层输入前加可学习 prefix 向量 | ~0.1% |
| **Prompt Tuning** | Lester et al., 2021 | 只在最初输入加软 prompt | ~0.01% |

**核心赌注**：模型不动，只在输入端加几个可学习的"虚拟 token"，让模型以为看到了某种"指令"。

**为什么这条路最终没成主流？** 关键发现：**Prefix/Prompt Tuning 只在超大模型（>10B）才有效**。小模型上明显不如 LoRA——因为小模型的表示能力不足以靠几个 prompt 向量扭转行为。

**但 Prompt Tuning 揭示了一个深刻的概念**：对于足够大的模型，**"行为适配"不需要动权重——只需要在输入空间找到正确的方向**。这与 GPT-3 的 in-context learning（prompt 里给几个例子就能学新任务）是同一个直觉的不同实现。

> 🎯 **思想史洞察**：2023 年的 QLoRA + PEFT 构成了微调史的**第三次范式转移**。旧范式（LoRA alone）解决了"训多少参数"，但没解决"基座多大能驻留显存"。QLoRA 把基座压到 4-bit，让 65B 单卡可训——**这是"微调民主化"的真正起点**。PEFT 库的标准化则让"参数高效"从学术概念变成了工程默认。**两者合流，定义了 2023 年至今的开源微调事实标准。**

## 6. RLHF / DPO / GRPO：对齐微调的独立轴线

### 6.1 对齐微调 ≠ 参数高效微调——两条平行线

到目前为止，我们讲的是"**参数高效微调（PEFT）**"——LoRA/Adapter/QLoRA 这条线，核心问题是"怎么用最少参数适配任务"。

但微调史还有另一条完全独立的轴线——**对齐微调（alignment fine-tuning）**：核心问题不是"参数效率"，而是"**怎么让模型的行为符合人类偏好/价值观**"。

两条线在 2018-2022 年平行发展，几乎不交叉：
- PEFT 线：Houlsby(2019) → Aghajanyan(2020) → LoRA(2021) → QLoRA(2023)
- 对齐线：Christiano(2017) → Stiennon(2020) → InstructGPT(2022) → DPO(2023) → GRPO(2024)

**它们在 2023 年合流**——实践中 DPO + QLoRA 成了标准组合（用 QLoRA 做参数高效，用 DPO 做偏好对齐）。这是后话。

### 6.2 RLHF：从偏好到策略的漫长孕育

RLHF（Reinforcement Learning from Human Feedback）的思想源头在 2017 年——Paul Christiano 等人发表 *Deep Reinforcement Learning from Human Preferences*，提出了"**人类偏好 → 奖励模型 → 强化学习**"的三步范式。

但 RLHF 在语言模型上引爆，经历了 5 年：

| 时间 | 工作 | 贡献 |
|---|---|---|
| 2017 | Christiano et al. | RLHF 范式提出（用于 Atari/MuJoCo） |
| 2020 | Stiennon et al. | RLHF 用于文本摘要——证明在语言任务可行 |
| 2022-01 | **InstructGPT**（Ouyang et al.） | RLHF 用于指令遵循——**1.3B InstructGPT 在人类偏好上超过 175B GPT-3** |
| 2022-11 | **ChatGPT** | RLHF 的产品化引爆 |

**InstructGPT 的关键数据点**（与 [`讲透LLM/HISTORY.md §6`](../讲透LLM/HISTORY.md) 一致）：一个 1.3B 参数的模型，经过 RLHF 对齐后，在人类偏好评估中**超过** 175B 的 GPT-3。

> **对齐（alignment）比规模（scale）更重要。**

### 6.3 RLHF 的工程痛苦

RLHF（具体用 PPO 算法）是出了名的难训：
- 同时维护 **4 个模型**：policy（被训练的模型）、reference（冻结的基线）、reward model（奖励模型）、critic（价值估计）
- reward hacking：模型学会钻奖励模型的漏洞（reward 看起来在涨，但实际输出质量在降）
- 训练极不稳定：PPO 的超参数极其敏感，不同随机种子结果差异巨大

这种工程痛苦，为 2023 年的 DPO 创造了**需求**。

### 6.4 DPO：把 RL 变成分类（Rafailov et al. 2023-05）

2023 年 5 月（与 QLoRA 同月！），Stanford 的 Rafael Rafailov 等人发表 *Direct Preference Optimization: Your Language Model is Secretly a Reward Model*（arXiv:2305.18290），做了一个精妙的数学推导：

**RLHF 的最优策略可以从偏好数据中直接用闭式解（closed-form）表达——不需要单独训练奖励模型，也不需要 RL。**

DPO 把 RLHF 的"reward model + PPO"两步，压缩成一个**简单的分类损失**：

$$\mathcal{L}_{\text{DPO}} = -\log\sigma\left(\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta\log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)$$

其中 $y_w$ 是人类偏好的"好"回答，$y_l$ 是"差"回答，$\beta$ 控制偏离 reference 的程度。

**只需要 2 个模型**（policy + reference），训练像 SFT 一样稳定。这让中小团队也能做对齐——DPO 迅速成为开源社区的主流对齐方法。

### 6.5 DPO 的诚实边界

DPO 不是万能的：
- **探索性不足**：DPO 是监督学习（从已知偏好数据学），没有 RL 的探索能力。对于"有明确答案可验证"的任务（数学、代码），RL 的探索比 DPO 的模仿更有效。
- **离策略（off-policy）偏差**：DPO 用的是"过去收集的偏好数据"，但模型在训练过程中分布会漂移，数据变得"过时"。
- **β 的脆弱性**：$\beta$ 太大模型不动，太小漂太远。

### 6.6 GRPO：RL 的回归（DeepSeek 2024）

2024 年，DeepSeek 在 DeepSeekMath 和 R1 中提出了 **GRPO（Group Relative Policy Optimization）**——去掉了 PPO 的 critic 模型，用**群组内相对优势**替代绝对价值估计。

$$A_i = \frac{r_i - \text{mean}(r_{1:G})}{\text{std}(r_{1:G})}$$

对同一个 prompt 采样 $G$ 个回答，用它们的 reward 的**相对排名**作为优势函数。这既保留了 RL 的探索能力，又简化了训练（去掉 critic）。

**R1-Zero 的戏剧性"aha moment"**：纯用 GRPO + 可验证奖励（数学有答案、代码能跑）训练，**跳过 SFT**，模型在中途自发涌现了 "Wait, let me reconsider..." 的自我反思行为——这种 chain-of-thought 没有被显式训练过。

**GRPO 的思想史意义**：它证明了**当 reward 可验证时，RL 比模仿学习（DPO/SFT）更有效**。这是 RL 在 LLM 对齐中的回归——2023 年 DPO 一度让人觉得 RL 过时了，但 2024 年 GRPO/R1 证明 RL 仍有不可替代的价值。

> 🎯 **博士级反思**：对齐微调史揭示了一个钟摆——**RL（探索强但难训）↔ 监督学习/DPO（稳定但探索弱）↔ RL 回归（GRPO 简化但保留探索）**。DPO 不是"更好的 RLHF"，而是"不同 tradeoff 点上的选择"。GRPO 的回归提醒我们：**当任务有可验证的 reward（数学/代码），RL 的探索能力是不可替代的——这恰好是 reasoning 模型（o1/R1）的根基。** 详见 [`讲透RL/03`](../讲透RL/03-RLHF-DPO-GRPO.md)。

## 7. 模型合并：微调之后的组合新范式（2024-）

### 7.1 从"微调一个模型"到"合并多个模型"

2024 年，开源社区出现了一个全新的范式——**模型合并（model merging）**：把多个独立微调的模型权重**直接算术合并**成一个模型，无需再训练。

这听起来不可能——把两个用不同数据微调的模型权重相加，难道不会互相干扰？

但实验表明：在一定条件下（尤其是同基座、相近微调），合并后的模型**同时具备多个微调的能力**，且性能损失可控。

### 7.2 合并方法谱系

| 方法 | 论文 | 核心思想 |
|---|---|---|
| **Model Soups** | Wortsman et al., 2022 | 多个微调模型权重的简单平均（"汤"） |
| **SLERP** | 经典图形学 | 球面线性插值——权重空间中的平滑混合 |
| **Task Arithmetic** | Ilharco et al., 2023 | 任务向量 = 微调权重 − 基座权重；任务向量可加减 |
| **TIES** | Yadav et al., 2023 | 修剪小权重 + 解决符号冲突 + 合并 |
| **DARE** | Yu et al., 2023 | 随机丢弃增量 + 重缩放 |

**Task Arithmetic 的概念突破**：定义"任务向量"$\tau = W_{\text{finetuned}} - W_{\text{base}}$，发现 $\tau$ 可以像向量一样**加减**：
- $W_{\text{base}} + \tau_{\text{法语}} + \tau_{\text{数学}}$ → 同时会法语和数学
- $W_{\text{base}} + \tau_{\text{毒性}}$ → 变得更毒；$W_{\text{base}} - \tau_{\text{毒性}}$ → 去毒

这揭示了一个深刻的事实：**微调产生的权重增量在不同任务间是近似"正交"的**——它们各自占据权重空间的不同方向，因此可以线性组合。

### 7.3 模型合并与 LoRA 的精神血脉

模型合并并非凭空出现——它是 LoRA 的"**可组合性**"愿景的延伸：

- LoRA 的 $\Delta W = BA$ 本质上就是一个"任务向量"——每个任务的 $BA$ 占据低秩子空间的一个方向。
- LoRA 的可合并性（$W_0 + BA$）已经展示了"增量可以加回权重"。
- 模型合并把这件事推到极致：**多个不同来源的增量可以同时加回去**。

**OpenRouter / HuggingFace 的合并工具**（mergekit, 2023-2024）让模型合并变成了几行配置的事——开源社区出现了大量"合并模型"（如 many-way merged 的通用模型）。

### 7.4 模型合并的思想史意义

模型合并代表了一种**根本性的范式转变**：

**旧范式**：一个任务 → 微调一个模型 → 得到一个模型。
**新范式**：多个任务 → 各自微调 → **组合出无限个"能力混合体"**。

这意味着微调的产物不再是"最终模型"，而是**可组合的能力模块**——和 AdapterHub 的愿景呼应，但落地方式更优雅（不需要框架支持，纯权重算术）。

> 🎯 **博士级洞察**：模型合并是 LoRA 哲学的终极实现——**"微调的增量是低维的、可组合的"**。LoRA 证明了单个 $\Delta W$ 是低秩的；模型合并证明了多个 $\Delta W$ 是近似正交的。两者共同指向一个结论：**预训练模型的权重空间有大量"空闲方向"，不同任务各自占据不冲突的子空间。** 这不仅是工程便利，更是关于"微调到底改变了什么"的深刻科学发现。

## 8. 思想史反思：五个反常识

### 反常识 1：全参数微调本身曾经是"创新"

流行叙事：全参数微调是"天经地义"的默认做法，参数高效是后来的优化。

**真相**：在 CV 时代（2012-2018），feature-based（冻住 backbone）才是默认。全参数微调在 NLP 的胜利（ULMFiT/BERT, 2018）是一个**反直觉的选择**——它需要解冻整个网络，冒着过拟合和灾难遗忘的风险。**"全都要动"曾经是激进的，"冻住"才是保守的。**

**教训**：**"默认做法"会随规模翻转**——在 100M 模型上"全动"是默认，在 175B 模型上"全动"是不可承受。判断一个方法的"正确性"，要看它隐含的规模假设。

### 反常识 2：LoRA 的"低秩"洞察比 LoRA 本身早半年

流行叙事：LoRA（2021）发明了"微调的权重更新是低秩的"这个洞察。

**真相**：Aghajanyan（2020-12）的"本征维度"论文**已经证明**了微调只需极低维度（200 维）——比 LoRA 早半年。LoRA 的贡献不是"发现低秩"，而是**找到了低秩的正确参数化方式**（$\Delta W = BA$，可合并、推理零开销）。

**教训**：**"发现现象"和"找到可用的工程化"之间有鸿沟**。很多好想法被埋没，不是因为现象没被发现，而是因为没找到好用的参数化。科学发现 ≠ 工程落地。

### 反常识 3：Adapter 输给 LoRA 纯粹是工程原因

流行叙事：LoRA 比 Adapter 效果好，所以赢了。

**真相**：两者效果几乎一样（都在全参数微调 99%+ 的水平）。LoRA 赢在**推理零开销**（可合并），Adapter 输在**永久推理税**（不可合并的额外层）。**科学上平手，工程上 LoRA 完胜。**

**教训**：**在微调方法的竞争中，推理成本是终局裁判。** 一个"训练时存在但推理时消失"的方法，永远比"永久占用资源"的方法有优势。

### 反常识 4：对齐 > 规模（但 alignment 不是免费的）

流行叙事：模型越大越好用。

**真相**：InstructGPT（1.3B，RLHF 对齐）在人类偏好上**超过** GPT-3（175B，未对齐）。**一个 100× 小但经过对齐的模型，比一个 100× 大但未对齐的模型更"有用"。**

**但 alignment 不是免费的**——它有"alignment tax"（对齐后某些能力会下降，详见 [`05-微调失败模式`](./05-微调失败模式.md)）。alignment 和 scale 是**正交的两个能力维度**，不是简单的替代关系。

**教训**：**能力的"有用性"不等于"规模"**——alignment 是一个独立的、与 scale 正交的维度。微调史的一半是对齐史。

### 反常识 5：模型合并"不该 work"但 work 了

流行叙事：模型合并是经验发现，缺乏理论解释。

**真相**：把两个独立微调的模型权重相加"理论上不该 work"——不同任务的梯度方向应该冲突。但它 work 了，原因是**不同任务的微调增量近似正交**（各自占据权重空间的不同低秩子空间）。这和 LoRA 的低秩发现是同一个底层规律的宏观表现。

**教训**：**经验先于理论**——模型合并"先 work 了再找解释"。这提醒我们：**不要因为"理论上不该 work"就放弃尝试。** 深度学习史充满了"先 empirically work、后 theoretically explain"的案例（Dropout、BatchNorm 都是）。

## 10. 失败方向与被淘汰的路线

### 10.1 BitFit：只调 bias 参数（过于极端）

Ben-Zaken et al.（2021）提出 BitFit——只微调模型的 bias 参数（参数量 ~0.1%）。在小模型上效果尚可，但在大模型上明显不如 LoRA。**失败原因**：bias 参数的表达力不足以捕获任务适配所需的全部信息。**教训**：参数高效的底线是"足够表达任务增量"——低于这个底线，再省也没用。

### 10.2 DiffPruning：可微剪枝（复杂度高）

Guo et al.（2020）提出 DiffPruning——把 $\Delta W$ 当成可学习的稀疏掩码来剪枝。理论上优雅，但实现复杂、训练慢，不如 LoRA 的"两个小矩阵相乘"简洁。**教训**：**简单性是方法传播的关键**——LoRA 的 $\Delta W=BA$ 可以用三行代码实现，这是它被社区快速采纳的重要原因。

### 10.3 Adapter 的推理税（前述 §3.4）

Adapter 不是"失败的方法"——它在概念上完全正确（参数高效、任务可组合）。它被淘汰是因为**推理延迟不可消除**。**教训**：一个方法可以科学上正确但工程上被淘汰——**部署约束是终局裁判**。

### 10.4 Prompt Tuning 的规模限制

Prompt Tuning 只在 >10B 模型有效，小模型上明显不如 LoRA。**失败原因**：小模型的表示能力不足以靠几个 prompt 向量扭转行为。**教训**：**方法的有效性依赖于模型规模**——不存在"所有规模都最优"的微调方法。选型必须考虑你的模型多大。

### 10.5 全参数微调在超大模型上的经济性崩溃

这不是"方法失败"，而是"范式失败"——全参数微调在 175B 模型上需要 ~1TB 显存，**经济上不可持续**。这是驱动整个 PEFT 范式转移的根本力量。**教训**：**一个范式的失败条件可能是它自己创造的成功条件**——全参数微调在"模型变大"这件事上太成功了，成功到把自己变得不可承受。

> 🎯 **博士级反思**：失败方向不是"愚蠢的错误"——BitFit、DiffPruning 在当时都是合理的探索。它们的失败揭示了微调方法竞争的几条潜规则：**① 足够表达（BitFit 太弱）② 足够简单（DiffPruning 太复杂）③ 推理零开销（Adapter 有税）④ 规模普适（Prompt Tuning 只大模型有效）**。LoRA 是唯一同时满足这四条的方法——这就是它成为事实标准的原因。

## 11. 路径依赖与偶然性

### 11.1 最大的"如果"：如果 Aghajanyan 没发表本征维度

**反事实分析**：如果 Aghajanyan 2020-12 的"本征维度"论文没有出现，LoRA 还会被发明吗？

可能的结果：LoRA 仍然会出现——因为"模型变大→全参数微调不可承受"的压力是客观存在的。但可能会推迟 1-2 年，而且可能以不同的形式出现（比如更接近 Adapter 的不可合并版本）。**Aghajanyan 的工作加速了 LoRA 的到来，并影响了它的形式（低秩而非稀疏）。**

### 11.2 如果 Houlsby 把 Adapter 设计成可合并的

**反事实分析**：Adapter 的致命缺陷是"不可合并"。如果 Houlsby 在 2019 年设计了一种可合并的 Adapter（比如 $\Delta W = f(\text{adapter input})$ 的形式，使得增量可以预计算加回 $W_0$），LoRA 还有空间吗？

可能的结果：如果 Adapter 可合并，它和 LoRA 就没有本质区别了——LoRA 可能仍然会出现（因为它更简洁），但 Adapter 不会被淘汰，两者会长期共存。**一个设计选择（不可合并 vs 可合并）决定了一个方法的生死。**

### 11.3 如果 LLaMA 没有泄漏

**反事实分析**：QLoRA 的意义在于"让开源社区能微调 65B 模型"。但如果没有开源基座（LLaMA 泄漏），PEFT 方法再好也没有"基座"可微调。

可能的结果：PEFT 方法会继续在学术圈发展，但不会形成"人人微调"的生态。**LLaMA 泄漏 + QLoRA = 开源微调生态的两大偶然性事件**——一个给了基座，一个给了方法。两者缺一不可。

### 11.4 偶然性清单

| 事件 | 如果没有发生 | 可能的替代 |
|---|---|---|
| Aghajanyan 2020 本征维度 | LoRA 推迟 1-2 年或以不同形式出现 | 不可合并的 Adapter 主导更久 |
| Houlsby 2019 Adapter 不可合并 | Adapter 可能不输 LoRA | LoRA+Adapter 长期共存 |
| LLaMA 泄漏（2023-03） | 开源微调生态推迟 1-2 年 | 闭源 API 微调服务更长期垄断 |
| Dettmers 的 bitsandbytes 库 | QLoRA 推迟——量化基础设施不成熟 | 全精度 LoRA 在消费级硬件上不可用 |
| DPO 的闭式解推导（2023-05） | RLHF 的痛苦持续更久 | PPO 仍是唯一选择，中小团队做不了对齐 |
| ChatGPT 免费（2022-11） | 对齐的需求不会被如此戏剧化激发 | DPO 的市场动力不足 |

> 🎯 **博士级核心**：**微调的当前格局（LoRA 主导 + QLoRA 民主化 + DPO 对齐 + 模型合并组合）有大量偶然性**。每一步都不是"必然最优"，而是特定历史条件（Aghajanyan 的理论发现 + Houlsby 的设计缺陷 + LLaMA 泄漏 + Dettmers 的量化库 + DPO 的数学巧合）的叠加。**学历史让你看到这些偶然，避免把当前格局当宿命。**

## 14. 费曼回炉记录（L2 自检 · 已迭代）

- **F2 卡壳点**：
  - **卡点 A**：长期把"全参数微调"当成"天经地义的默认"，以为参数高效是后来的"优化"。重读 CV 迁移学习史（DeCAF 2014）才意识到——**在 CV 时代"冻住 backbone"才是默认，全参数微调在 NLP 的胜利（ULMFiT/BERT 2018）本身是一个反直觉的激进选择**。这是最大的认知翻转：我以为的"默认"其实只有 5 年历史。
  - **卡点 B**：一直以为 LoRA 赢 Adapter 是因为"效果更好"。重读两者论文数据才发现**效果几乎一样（都在全参数微调 99%+）**，LoRA 赢在**推理零开销（可合并）**——这是纯工程决胜，不是科学决胜。这个区分很重要：它说明微调方法竞争的终局裁判是推理成本，不是训练质量。
  - **卡点 C**：把 LoRA 的"低秩洞察"当成 Hu 2021 的原创。重读 Aghajanyan 2020-12 才发现——**本征维度论文比 LoRA 早半年**，已经证明了"微调只需 200 维"。LoRA 的贡献是"找到了低秩的正确参数化"（$\Delta W=BA$ 可合并），不是"发现低秩"。

- **F3 术语翻译**：
  - "feature-based transfer（特征迁移）" → 冻住预训练模型当特征提取器，只训顶层——像把一个训练好的厨师"冻住"，只在他旁边放一个新菜单
  - "本征维度（intrinsic dimension）" → 一套权重真正需要调几个独立旋钮——预训练越好的模型，微调需要的旋钮越少（RoBERTa 只要 ~200 个）
  - "可合并（mergeable）" → 训练时多出来的部分，部署时能悄悄消失——像脚手架，楼盖好了就拆掉，房子里看不到它
  - "对齐（alignment）" → 不是让模型"更聪明"，而是让模型"更听话"——一个聪明的野蛮人和一个听话的普通人，后者更"有用"

- **F4 回炉**：
  - **v1（错误直觉）**：把微调史写成"方法越来越省参数"的线性进步（feature-based 3.6% → LoRA 0.1% → QLoRA 0.1% + 4bit）。
  - **v2（修正后）**：改成**"动多少参数"的振荡史**——核心矛盾始终是"通用↔专用"。feature-based 是"几乎不动"（太保守，天花板低）→ 全参数微调是"全动"（太激进，规模一爆就崩）→ LoRA 是"动 1%"（恰到好处的中道）。这个 diff 从"进步叙事"升级为"辩证回路"——训练读者看到 oscillation 而非 progress。

## §一句话总结

> 🎯 **六句话**：
> 1. **微调史是一部"动多少参数"的振荡史**——从 CV 的"冻住"（feature-based）到 NLP 的"全动"（full FT）再到 LoRA 的"动 1%"——核心矛盾始终是"通用↔专用"。
> 2. **全参数微调（2018）本身曾经是创新**——在 CV "冻住"是默认的时代，ULMFiT/BERT 选择"全动"是激进的反直觉选择；它赢了 2018-2020，又因为模型变大而自我否定。
> 3. **LoRA 赢 Adapter 纯粹是工程决胜**——两者效果相当，LoRA 推理零开销（可合并），Adapter 永久推理税。**推理成本是终局裁判。**
> 4. **QLoRA（2023）是微调民主化的真正起点**——4-bit 量化基座 + LoRA，让 65B 模型单卡可训。**量化（推理技术）和 LoRA（训练技术）在此合流。**
> 5. **对齐微调（RLHF/DPO/GRPO）是与参数高效微调平行的独立轴线**——前者解决"听话"，后者解决"省参数"。两者在 2023 年的实践中合流（QLoRA + DPO）。InstructGPT 证明**对齐 > 规模**。
> 6. **博士级核心**：**微调的当前格局有大量偶然性**——Aghajanyan 的理论发现、Houlsby 的设计缺陷、LLaMA 泄漏、Dettmers 的量化库、DPO 的数学巧合——每一步都不是"必然最优"。学历史让你看到这些偶然，训练对"LoRA 主导是天经地义"的免疫力。
