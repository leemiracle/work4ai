# 02 — PEFT 全家桶：LoRA / Adapter / Prefix / Prompt Tuning

> 00/01 讲透了 LoRA。但参数高效微调（PEFT）不止 LoRA 一个。这一篇横向对比四大方法，讲清楚**它们各自改什么、为什么 LoRA 成了主流**。
>
> 配套实验：`experiments/02_peft.py`。

---

## 1. 全家桶：四种方法改的是什么？

```
输入 x ──→ [Prefix/Prompt Tuning 改这里: 加可学习 token]
         │
         ▼
      ┌──────────────────────────┐
      │  Transformer 层          │
      │  ┌──────────────┐        │ ← Adapter: 层后插瓶颈模块(不可合并)
      │  │  W₀ (冻结)   │        │
      │  │  + ΔW=BA     │        │ ← LoRA: 低秩增量(可合并进 W₀)
      │  └──────────────┘        │
      └──────────────────────────┘
```

| 方法 | 改什么 | 参数量 | 推理是否变 |
|---|---|---|---|
| **Full FT** | 全部权重 $W_0$ | 100% | 不变（但要存全模型） |
| **Adapter** | 每层后插瓶颈层 $d\!\to\!r\!\to\!d$ | ~1-5% | **变（多一层，不可合并）** |
| **Prefix Tuning** | 每层输入前加可学习 prefix 向量 | ~0.1% | 变（序列变长） |
| **Prompt Tuning** | 只在最初输入加软 prompt | ~0.01% | 微变 |
| **LoRA** | 低秩增量 $\Delta W=BA$ | ~0.1-1% | **不变（可合并进 $W_0$）** |

## 2. 实验对比（`02_peft.py`）

sin→cos 任务，r=4：

```
方法        可训练参数   taskB loss   推理额外开销
Full FT      4353        0.0001      0 (但存全模型)
LoRA         1032        0.0000      0 (ΔW 可合并)
Adapter      1160        0.0001      +1024 FLOPs/层 (永久)
```

**LoRA 和 Adapter 参数量、效果几乎一样，但 LoRA 推理无额外开销，Adapter 推理永久多算**——这是 LoRA 胜出的关键。

---

## 3. 为什么 LoRA 淘汰了 Adapter

Adapter（Houlsby 2019）比 LoRA（Hu 2021）早两年，曾是 PEFT 主流。它被 LoRA 取代的核心原因：

1. **推理延迟**：Adapter 是额外插入的层，推理时**永远多一次 forward**（$d\!\to\!r\!\to\!d$），无法消去。在线服务对延迟敏感，这是硬伤。LoRA 训练后把 $BA$ 加到 $W_0$ 上，**推理和原模型完全一样**。
2. **可合并**：LoRA 的 $\Delta W$ 能合并进权重，部署时就是普通模型，不增加任何工程复杂度。
3. **可热插拔**：一对 $BA$ 就是一个"任务补丁"，切换任务只换补丁，不用换模型。

---

## 4. Prefix / Prompt Tuning：另一条路

Prefix（Li & Liang 2021）和 Prompt Tuning（Lester 2021）走完全不同的路：**不改权重，改输入**——在每层（Prefix）或输入开头（Prompt）加几个可学习的虚拟 token。

- **优点**：参数极少（~0.01-0.1%），多个任务的前缀可并行缓存。
- **缺点**：**只在大模型（>10B）才有效**。小模型上明显不如 LoRA——因为小模型的表示能力不足以靠几个 prompt 向量扭转行为。
- **适用**：超大规模模型的多任务热切换（如一个 100B 模型服务上千个任务，每个任务只存几百个 prompt 向量）。

---

## 5. 选择指南

| 场景 | 推荐 |
|---|---|
| 通用微调、要部署、要效果好 | **LoRA**（事实标准） |
| 显存极紧（消费级显卡训 70B） | **QLoRA**（下一篇） |
| 一个超大模型服务海量任务、可接受轻微延迟 | Prefix / Prompt Tuning |
| 任务和预训练差异巨大、不差钱 | Full FT |
| 历史遗留 / 特定框架 | Adapter（现已少用） |

---

## 6. 一句话总结

> **PEFT 四大方法按"改什么"区分：Full FT 改全部权重（贵）、Adapter 插额外层（推理变慢）、Prefix/Prompt 改输入（只大模型有效）、LoRA 加低秩增量（可合并、推理不变）。LoRA 因"参数少 + 效果好 + 推理无延迟 + 可热插拔"四者兼顾，成为事实标准；Adapter 因推理延迟被淘汰，Prefix/Prompt 只在超大规模多任务场景才有优势。**

## ✍️ 练习（`02_peft.py`）

1. **推理延迟**：在 Adapter 模型上测 1000 次前向的时间，对比 LoRA 合并后——亲手感受"不可合并"的代价。
2. **Prompt Tuning 尝试**：给 MLP 输入前拼 4 个可学习向量（维度 1），只训它们，看能否拟合 cos——你会看到小模型上 Prompt Tuning 效果差，理解"它只适合大模型"。
3. **混合**：同时用 LoRA + Prefix，看是否效果更好——现代方法常组合多种 PEFT。
