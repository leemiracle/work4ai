  The Model Registry is the central source of truth for model compatibility in TransformerLens. It manages the discovery, verification status, and architectural mapping of thousands of models from the Hugging Face Hub, ensuring that users can confidently load models with verified numerical parity.

 
## Registry Architecture

 The registry consists of a static data repository and a set of tools for programmatic access and verification tracking.

 
### Core Data Structures

 The registry is primarily defined by two JSON files located in `transformer_lens/tools/model_registry/data/`:

 
 - **`supported_models.json`**: Contains the comprehensive list of scanned models, their architecture IDs, and verification scores across various testing phases [transformer_lens/tools/model_registry/data/supported_models.json1-12](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/data/supported_models.json#L1-L12)
 - **`verification_history.json`**: A detailed log of verification runs, including timestamps, TransformerLens versions, and specific failure notes [transformer_lens/tools/model_registry/data/verification_history.json1-10](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/data/verification_history.json#L1-L10)
 
 
### Status Codes

 Each model in the registry is assigned a status code [transformer_lens/tools/model_registry/registry_io.py22-26](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/registry_io.py#L22-L26):

 
 - **0 (UNVERIFIED)**: Scanned but not yet tested.
 - **1 (VERIFIED)**: Passed numerical parity benchmarks.
 - **2 (SKIPPED)**: Known to be incompatible or too large for current hardware (e.g., OOM).
 - **3 (FAILED)**: Tested but failed to meet parity thresholds.

## Architecture Support

 The registry distinguishes between Hugging Face architecture strings and internal TransformerLens adapters.

 
### Supported Architectures

 TransformerLens supports over 60 Hugging Face architectures through the `TransformerBridge`. The `HF_SUPPORTED_ARCHITECTURES` set in `transformer_lens/tools/model_registry/__init__.py` serves as the canonical list for the registry [transformer_lens/tools/model_registry/__init__.py47-114](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/__init__.py#L47-L114)

 Key supported families include:

 
 - **Causal LM**: GPT-2, Llama (1/2/3), Mistral, Mixtral, Qwen, Gemma (1/2/3/4), Phi [transformer_lens/factories/architecture_adapter_factory.py83-161](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/factories/architecture_adapter_factory.py#L83-L161)
 - **Seq2Seq**: T5, BART [transformer_lens/utilities/architectures.py10-20](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/utilities/architectures.py#L10-L20)
 - **Masked LM**: BERT, RoBERTa [transformer_lens/utilities/architectures.py23-29](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/utilities/architectures.py#L23-L29)
 - **Multimodal**: LLaVA, Qwen3.5-VL, Gemma3/4 [transformer_lens/utilities/architectures.py32-39](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/utilities/architectures.py#L32-L39)
 
 
### Canonical Authors

 The registry maintains a mapping of `CANONICAL_AUTHORS_BY_ARCH` to prioritize original model releases (e.g., `meta-llama` for Llama architectures) during scraping and reporting [transformer_lens/tools/model_registry/__init__.py118-185](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/__init__.py#L118-L185)

 
## Implementation Detail: Registry API

 The `api.py` module provides the primary interface for interacting with the registry.

 
| Function | Purpose |
|---|---|
| is_model_supported(model_id) | Checks if a model's architecture is in the supported list. |
| get_architecture_models(arch_id) | Returns all models in the registry for a specific architecture. |
| get_registry_stats() | Returns counts of scanned, verified, and failed models. |
| get_unsupported_architectures() | Identifies architectures found on HF Hub that lack TL adapters. |

## Quantization Support

 The registry tracks compatibility for various quantization formats.

 
### HF-Loadable Formats

 Models quantized with formats like **AWQ**, **GPTQ**, and **BitsAndBytes** are admitted to the registry if they can be ingested via standard Hugging Face loaders [transformer_lens/tools/model_registry/registry_io.py30-73](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/registry_io.py#L30-L73) The registry identifies the required library (e.g., `auto_gptq`, `bitsandbytes`) based on naming patterns [transformer_lens/tools/model_registry/registry_io.py104-111](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/registry_io.py#L104-L111)

 
### Incompatible Formats

 The registry explicitly marks formats that require non-HF loaders as incompatible (Status 2), including:

 
 - **GGUF** (llama.cpp)
 - **MLX** (Apple Silicon)
 - **FP8/NVFP4** (NVIDIA specific)
 
 Sources: [transformer_lens/tools/model_registry/registry_io.py76-100](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/registry_io.py#L76-L100) [transformer_lens/tools/model_registry/registry_io.py116-118](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/registry_io.py#L116-L118)

 
## Verification Status & Reporting

 The registry is used to generate a comprehensive markdown report of the ecosystem status via `generate_report.py` [transformer_lens/tools/model_registry/generate_report.py1-13](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/generate_report.py#L1-L13)

 
### Architecture Gaps

 The registry identifies "Architecture Gaps"—popular architectures on the Hugging Face Hub that do not yet have a corresponding `ArchitectureAdapter` in TransformerLens. This helps prioritize development efforts [transformer_lens/tools/model_registry/api.py23-24](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/api.py#L23-L24)

 
### Verification Phases

 Model verification is recorded across multiple phases in `supported_models.json`:

 
 - **Phase 1 (P1)**: Parity with Hugging Face logits [transformer_lens/tools/model_registry/data/supported_models.json20](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/data/supported_models.json#L20-L20)
 - **Phase 2/3 (P2/P3)**: Parity with legacy `HookedTransformer` (where applicable) [transformer_lens/tools/model_registry/data/supported_models.json21-22](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/data/supported_models.json#L21-L22)
 - **Phase 4 (P4)**: Generation/KV Cache parity [transformer_lens/tools/model_registry/data/supported_models.json23](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/data/supported_models.json#L23-L23)
