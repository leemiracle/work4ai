  This guide provides a technical walkthrough for developers creating a new `ArchitectureAdapter` to support additional model architectures in the `TransformerBridge` (v3.0) system. An adapter acts as the translation layer that maps a third-party model (typically from Hugging Face) into the canonical TransformerLens component structure.

 
## Overview of the Adapter Role

 An **Architecture Adapter** is a specialized class that defines three primary mappings for a model architecture:

 
 - **Config Attributes**: Translates architecture-specific settings (e.g., normalization type, GQA parameters) into `TransformerBridgeConfig` [docs/source/content/adapter_development/adapter-creation-guide.md9-11](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/content/adapter_development/adapter-creation-guide.md?plain=1#L9-L11)
 - **Component Mapping**: A dictionary (`self.component_mapping`) that maps TransformerLens canonical names (like `blocks.0.attn.q`) to `GeneralizedComponent` instances wrapping specific Hugging Face modules [docs/source/content/adapter_development/adapter-creation-guide.md12-13](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/content/adapter_development/adapter-creation-guide.md?plain=1#L12-L13)
 - **Weight Processing**: Reshape rules (`self.weight_processing_conversions`) that convert weights from the external format to the internal TransformerLens format [docs/source/content/adapter_development/adapter-creation-guide.md13-14](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/content/adapter_development/adapter-creation-guide.md?plain=1#L13-L14)

## Implementation Steps

 
### 1. Define the Adapter Class

 Create a new file in `transformer_lens/model_bridge/supported_architectures/<model_name>.py`. Your class must inherit from `ArchitectureAdapter` [transformer_lens/model_bridge/architecture_adapter.py29](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/architecture_adapter.py#L29-L29)

 
### 2. Configure Architectural Attributes

 In the `__init__` method, set the core architectural flags on `self.cfg`. These flags determine how `GeneralizedComponents` behave during the forward pass [docs/source/_static/adapter-template.py47-66](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/_static/adapter-template.py#L47-L66)

 
| Attribute | Purpose | Reference |
|---|---|---|
| normalization_type | Set to "RMS" or "LN". | docs/source/_static/adapter-template.py54 |
| positional_embedding_type | Set to "rotary" or "standard". | docs/source/_static/adapter-template.py59 |
| gated_mlp | Boolean for SwiGLU/Gated architectures. | docs/source/_static/adapter-template.py63 |
| n_key_value_heads | Required for Grouped Query Attention (GQA). | docs/source/_static/adapter-template.py69-70 |

 **Sources:** [docs/source/content/adapter_development/adapter-creation-guide.md95-113](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/content/adapter_development/adapter-creation-guide.md?plain=1#L95-L113) [docs/source/_static/adapter-template.py42-71](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/_static/adapter-template.py#L42-L71)

 
### 3. Define Weight Conversions

 TransformerLens expects attention weights in the format `[n_heads, d_model, d_head]`. If the source model uses a different layout (e.g., `[d_model, 3 * d_model]` for joint QKV), you must define a conversion [transformer_lens/model_bridge/architecture_adapter.py93-103](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/architecture_adapter.py#L93-L103)

 Use the `_qkvo_weight_conversions()` helper for standard separate Q/K/V/O projections [transformer_lens/model_bridge/architecture_adapter.py106-119](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/architecture_adapter.py#L106-L119) For joint weights (like GPT-2), implement a custom `BaseTensorConversion` [transformer_lens/model_bridge/supported_architectures/gpt2.py29-37](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/supported_architectures/gpt2.py#L29-L37)

 **Sources:** [transformer_lens/model_bridge/architecture_adapter.py93-119](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/architecture_adapter.py#L93-L119) [transformer_lens/model_bridge/supported_architectures/gpt2.py145-170](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/supported_architectures/gpt2.py#L145-L170)

 The `component_mapping` attribute maps canonical strings to `GeneralizedComponent` objects. These components wrap the actual PyTorch modules from the remote model [transformer_lens/model_bridge/architecture_adapter.py136-147](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/architecture_adapter.py#L136-L147)

## Component Details

 Adapters use specialized "Bridge" components to wrap Hugging Face modules. These components ensure that hooks are placed correctly around the original operations.

 
 - **EmbeddingBridge**: Wraps token and position embeddings [transformer_lens/model_bridge/generalized_components/embedding.py15](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/embedding.py#L15-L15)
 - **NormalizationBridge**: Handles `LayerNorm` or `RMSNorm`. It can implement the calculation from scratch for better hook granularity or use the native HF autograd [transformer_lens/model_bridge/generalized_components/normalization.py12-43](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/normalization.py#L12-L43)
 - **MLPBridge / GatedMLPBridge**: Wraps the feed-forward network. `GatedMLPBridge` is used for architectures with a gate projection (e.g., Llama, Qwen) [transformer_lens/model_bridge/generalized_components/mlp.py14](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/mlp.py#L14-L14)
 - **LinearBridge**: A generic wrapper for `nn.Linear` layers (e.g., attention projections) [transformer_lens/model_bridge/generalized_components/linear.py12](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/linear.py#L12-L12)

## Weight Processing and Folding

 The `ProcessWeights` class provides static methods to transform weights for interpretability (e.g., LayerNorm folding). When creating an adapter, you must ensure that keys are translated correctly between the internal canonical names and the HF names [transformer_lens/weight_processing.py21-35](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/weight_processing.py#L21-L35)

 The adapter provides `preprocess_weights` for architecture-specific logic (like scaling embeddings) before standard folding occurs [transformer_lens/model_bridge/architecture_adapter.py121-134](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/architecture_adapter.py#L121-L134)
