  This document describes the Continuous Integration (CI) and Continuous Deployment (CD) pipeline used in the TransformerLens project. The pipeline automates testing, code quality checks, and the release process to ensure reliable software delivery. For information about setting up a development environment, see [Development Environment](https://deepwiki.com/TransformerLensOrg/TransformerLens/10.3-development-environment).

 
## Overview

 The TransformerLens CI/CD pipeline consists of two main workflows implemented as GitHub Actions:

 
 - **Checks Workflow** (`checks.yml`): Ensures code quality and functionality through automated tests and checks.
 - **Release Workflow** (`release.yml`): Automates the process of releasing new versions to PyPI.
 
 The pipeline has been migrated to use `uv` for fast dependency management and environment isolation [.github/workflows/checks.yml72-77](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.github/workflows/checks.yml#L72-L77)

## Checks Workflow

 The Checks workflow is defined in `.github/workflows/checks.yml` and is the primary gatekeeper for code quality. It utilizes environment variables like `TL_FORCE_EXIT_AFTER_TESTS` to handle lingering threads from native dependencies during interpreter shutdown [.github/workflows/checks.yml57-58](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.github/workflows/checks.yml#L57-L58)

## Testing Tiers

 Testing is organized into tiers via the `makefile`:

 
| Tier | Command | Description |
|---|---|---|
| Unit | make unit-test | Fast tests for individual components (MLP, Attention, etc.) .github/workflows/checks.yml112 |
| Integration | make integration-test | Tests component interaction and HF parity .github/workflows/checks.yml171 |
| Acceptance | make acceptance-test | High-level validation of core user workflows .github/workflows/checks.yml116 |
| Notebook | make notebook-test | Validates demos/ using nbval and doc_sanitize.cfg makefile41-64 |
| Benchmark | make benchmark-test | Runs performance and numerical parity suites makefile32-33 |

 The `notebook-test` tier uses a sanitization configuration `demos/doc_sanitize.cfg` to ignore volatile outputs like timestamps and memory addresses during validation [demos/doc_sanitize.cfg1-36](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/demos/doc_sanitize.cfg#L1-L36)

## Release Workflow

 The Release workflow in `.github/workflows/release.yml` is triggered by publishing a GitHub release [.github/workflows/release.yml3-6](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.github/workflows/release.yml#L3-L6)

 
```

```

 The workflow performs the following:

 
 - **Validation**: Invokes the `checks.yml` workflow to ensure the release candidate passes all tests [.github/workflows/release.yml9-13](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.github/workflows/release.yml#L9-L13)
 - **Version Parsing**: Extracts the version from the git tag (e.g., `v3.0.0` -> `3.0.0`) [.github/workflows/release.yml15-38](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.github/workflows/release.yml#L15-L38)
 - **Versioning**: Updates `pyproject.toml` version dynamically using the `version-set` target in the makefile [.github/workflows/release.yml59](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.github/workflows/release.yml#L59-L59) [makefile104-105](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/makefile#L104-L105)
 - **Publishing**: Builds the distribution and uploads to PyPI using `twine` with the `PYPI_TOKEN_PYPI` secret [.github/workflows/release.yml63-69](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.github/workflows/release.yml#L63-L69)

## Pipeline Configuration

 The pipeline behavior is controlled by several key files:

 
 - **`pyproject.toml`**: Defines dependency groups (`dev`, `docs`, `jupyter`, `multimodal`, `quantization`) and tool configurations for `pytest`, `black`, and `mypy` [pyproject.toml45-111](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/pyproject.toml#L45-L111)
 - **`uv.lock`**: Ensures reproducible environments across local development and CI runners [uv.lock1-15](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/uv.lock#L1-L15)
 - **`.github/workflows/checks.yml`**: Defines the CI triggers and job matrices [.github/workflows/checks.yml1-40](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.github/workflows/checks.yml#L1-L40)
