  Activation patching is a causal intervention technique that identifies which activations in a transformer model are important for producing specific outputs. The technique involves running the model on clean and corrupted inputs, then replacing specific activations from one run into the other to measure their impact.

 The core implementation is in `transformer_lens/patching.py` with the main function `generic_activation_patch` and specialized wrapper functions for common patching scenarios.

 
## Conceptual Overview

 Activation patching performs causal interventions to identify which activations matter for specific model behaviors. The technique compares clean and corrupted model runs, then measures the effect of replacing specific activations.

 
### Activation Patching Process

 
```

```

 The process involves:

 
 - **Clean run**: Execute `model.run_with_cache(clean_tokens)` to get `clean_cache`. [transformer_lens/patching.py15-20](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/patching.py#L15-L20)
 - **Corrupted run**: Execute `model.run_with_cache(corrupted_tokens)` to get `corrupted_cache`. [transformer_lens/patching.py15-20](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/patching.py#L15-L20)
 - **Patch selection**: Use `index_df` to specify which activations to patch (e.g., specific layers, positions, or heads). [transformer_lens/patching.py141-146](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/patching.py#L141-L146)
 - **Activation replacement**: Apply a `patch_setter` to replace corrupted activations with clean ones during a forward pass. [transformer_lens/patching.py141-146](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/patching.py#L141-L146)
 - **Measurement**: Apply a `patching_metric` (e.g., logit difference) to quantify the intervention effect. [transformer_lens/patching.py129-130](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/patching.py#L129-L130)
 - **Iteration**: Repeat for all specified activation indices to generate a heatmap of importance. [transformer_lens/patching.py219-226](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/patching.py#L219-L226)

## Implementation in TransformerLens

 The activation patching system is built around `generic_activation_patch` in `transformer_lens/patching.py`, with specialized functions for common activation types.

 
### Core Architecture

 
```

```

 The system has three layers:

 
 - **Core function**: `generic_activation_patch` implements the patching logic and iteration loop. [transformer_lens/patching.py126-137](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/patching.py#L126-L137)
 - **Specialized functions**: Pre-configured `functools.partial` applications for common scenarios like residual stream patching. [transformer_lens/patching.py336-355](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/patching.py#L336-L355)
 - **Patch setters**: Functions that define how to slice and replace specific activation tensors (e.g., handling the head dimension). [transformer_lens/patching.py235-331](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/patching.py#L235-L331)

## Usage

 
### Basic Workflow

 
 - **Define inputs**: Create clean and corrupted token sequences.
 - **Cache activations**: Use `model.run_with_cache()` to store clean activations. [transformer_lens/ActivationCache.py53-62](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/ActivationCache.py#L53-L62)
 - **Define metric**: Create a function to measure patch effectiveness (e.g., logit difference between correct and incorrect answers).
 - **Apply patches**: Use specialized patching functions like `get_act_patch_resid_pre`. [transformer_lens/patching.py336-355](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/patching.py#L336-L355)

## Path Patching

 Path patching is a more advanced technique that isolates the effect of a specific path between two components (e.g., Head A -> Head B). While `generic_activation_patch` handles node patching, specialized tools like `get_act_patch_direct_path` [tests/unit/test_direct_path_patching.py18](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/tests/unit/test_direct_path_patching.py#L18-L18) allow for finer-grained circuit analysis.

 
### Direct Path Patching

 This technique measures the direct effect of a source component on a destination component's input (Q, K, or V). [tests/unit/test_direct_path_patching.py148-162](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/tests/unit/test_direct_path_patching.py#L148-L162)

 
| Function | Purpose | Shape |
|---|---|---|
| get_act_patch_direct_path | Effect of one source on all downstream heads | [n_layers, n_heads] |
| get_act_patch_direct_path_all_sources | Effect of all pairs of heads | [n_layers, n_heads, n_layers, n_heads] |
