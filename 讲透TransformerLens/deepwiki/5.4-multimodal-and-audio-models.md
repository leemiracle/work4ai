  TransformerLens v3.0 introduces native support for multimodal and audio models through the `TransformerBridge` architecture. This allows mechanistic interpretability tools (hooks, activation caching, patching) to be applied to vision encoders, multimodal projectors, and audio feature extractors alongside the primary language model components.

 
## Overview

 Multimodal support is primarily driven by the `is_multimodal` configuration flag within `TransformerBridgeConfig`. When enabled, the bridge architecture wires specialized components such as `SiglipVisionEncoderBridge` or `CLIPVisionEncoderBridge` to the Hugging Face model's vision tower. This enables a unified interface for passing `pixel_values` and other multimodal tensors through `forward()`, `generate()`, and `run_with_cache()`.

 
### Supported Architectures

 
 - **LLaVA**: Combines CLIP vision encoders with Llama-based language models [transformer_lens/model_bridge/supported_architectures/gemma3_multimodal.py42-44](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/supported_architectures/gemma3_multimodal.py#L42-L44)
 - **Gemma 3**: Features SigLIP vision encoders and multimodal projectors [transformer_lens/model_bridge/supported_architectures/gemma3_multimodal.py38-44](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/supported_architectures/gemma3_multimodal.py#L38-L44)
 - **Gemma 4**: Supports both standard and "Unified" (encoder-free) multimodal variants [transformer_lens/model_bridge/supported_architectures/gemma4.py45-63](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/supported_architectures/gemma4.py#L45-L63)
 - **HuBERT**: Audio-based feature extraction and encoding (supported via the `ArchitectureAdapter` system).

## Key Components

 
### Vision Encoders

 TransformerLens provides specialized bridge components for common vision towers. These bridges resolve submodules even across different `transformers` library versions (e.g., handling the flattening of `SiglipVisionModel` in version 5.6.0) [transformer_lens/model_bridge/generalized_components/siglip_vision_encoder.py175-187](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/siglip_vision_encoder.py#L175-L187)

 
| Component | Description | Hook Aliases |
|---|---|---|
| SiglipVisionEncoderBridge | Wraps SigLIP towers (Gemma 3, MedGemma). | hook_vision_embed, hook_vision_out |
| CLIPVisionEncoderBridge | Wraps CLIP towers (LLaVA). | hook_vision_embed, hook_vision_out |
| SiglipVisionEncoderLayerBridge | Individual transformer layer within SigLIP. | hook_resid_pre, hook_resid_post, hook_attn_out |

### Normalization Dispatch

 Multimodal models often mix different normalization types (e.g., SigLIP uses `LayerNorm` while the language model uses `RMSNorm`). The `NormalizationBridge` performs introspection to ensure correct math is applied regardless of the global `uses_rms_norm` config [tests/unit/model_bridge/generalized_components/test_normalization_bridge.py101-110](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/tests/unit/model_bridge/generalized_components/test_normalization_bridge.py#L101-L110)

## Implementation Details

 
### Forward Pass and Generation

 The `TransformerBridge` intercepts `pixel_values` in the `forward` method. If `is_multimodal` is false, passing `pixel_values` raises a `ValueError` [transformer_lens/model_bridge/bridge.py82-89](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/bridge.py#L82-L89)

 During generation, `pixel_values` are typically only passed during the first iteration to compute the initial KV cache for the vision tokens. Subsequent steps only process the new text tokens [tests/unit/test_multimodal_bridge.py132-167](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/tests/unit/test_multimodal_bridge.py#L132-L167)

 
### Multimodal Input Preparation

 The `prepare_multimodal_inputs()` method facilitates the conversion of raw images and text into tensors compatible with the model's specific `processor` [tests/unit/test_multimodal_bridge.py169-195](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/tests/unit/test_multimodal_bridge.py#L169-L195)

### Weight Processing

 Multimodal adapters often require complex weight conversions. For example, `Gemma3MultimodalArchitectureAdapter` applies `ArithmeticTensorConversion` (Operation: `ADDITION`, Value: `1.0`) to RMSNorm weights because Gemma models use a `(1.0 + weight)` offset [transformer_lens/model_bridge/supported_architectures/gemma3_multimodal.py98-120](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/supported_architectures/gemma3_multimodal.py#L98-L120)
