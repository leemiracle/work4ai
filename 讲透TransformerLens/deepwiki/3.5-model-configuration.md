  The TransformerLens Model Configuration system provides a flexible way to define and control the architecture, behavior, and capabilities of transformer models. This page covers the `HookedTransformerConfig` class, the `TransformerBridgeConfig` for v3 models, and the implementation of key-value caching.

 
## Configuration Overview

 TransformerLens uses specialized configuration classes to centralize all parameters needed to define a model. While `HookedTransformerConfig` remains the standard for legacy and custom-built models, the v3 architecture introduces `TransformerBridgeConfig` to manage the mapping between native Hugging Face models and TransformerLens components.

## HookedTransformerConfig Class

 The `HookedTransformerConfig` class is the primary configuration object for the legacy `HookedTransformer` and `HookedEncoder` classes. It performs validation and derivation of dependent parameters in its `__post_init__` method.

 
### Key Parameters

 
| Parameter | Description | Default |
|---|---|---|
| n_layers | Number of transformer blocks | Required |
| d_model | Dimensionality of residual stream | Required |
| n_ctx | Maximum sequence length | Required |
| d_head | Dimensionality of each attention head | Required |
| n_heads | Number of attention heads | d_model // d_head |
| act_fn | Activation function (relu, gelu, silu, etc.) | Required |
| d_mlp | Dimensionality of MLP network | 4 * d_model |
| normalization_type | Normalization (LN, RMS, LNPre) | "LN" |
| device | Target device for the model | Auto-detected |

 
### Implementation Details

 
 - **Validation**: The class ensures that `d_model` is divisible by `d_head` if `n_heads` is provided [transformer_lens/config/hooked_transformer_config.py269-270](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/config/hooked_transformer_config.py#L269-L270)
 - **Inference**: If `d_mlp` is not specified for a non-attention-only model, it defaults to `4 * d_model` [transformer_lens/config/hooked_transformer_config.py287-289](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/config/hooked_transformer_config.py#L287-L289)
 - **Unwrapping**: The `unwrap` method is used throughout the codebase to handle both dictionary inputs and configuration objects [transformer_lens/config/hooked_transformer_config.py347-352](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/config/hooked_transformer_config.py#L347-L352)

## Key-Value Caching Configuration

 For efficient text generation, TransformerLens implements a robust KV caching system. This is managed by the `TransformerLensKeyValueCache` and `TransformerLensKeyValueCacheEntry` classes.

 
### Cache Initialization and Data Flow

 The cache is initialized based on the model's configuration (`HookedTransformerConfig` or `TransformerLensConfig`). It allocates tensors for `past_keys` and `past_values` for every layer.

### Key Components

 
 - **Dtype Management**: The cache entry uses `cfg.dtype` during initialization to prevent type promotion issues during the `torch.cat` operation in the attention layer [transformer_lens/cache/key_value_cache_entry.py30-38](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/cache/key_value_cache_entry.py#L30-L38)
 - **Grouped Query Attention (GQA)**: The cache handles GQA by checking `cfg.n_key_value_heads`. If set, it uses this value instead of `n_heads` for the key/value tensor dimensions [transformer_lens/cache/key_value_cache_entry.py29](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/cache/key_value_cache_entry.py#L29-L29)
 - **Freezing**: The cache can be "frozen" using `cache.freeze()`. When frozen, the `append` method returns the concatenated tensors for computation but does not update the stored state in the cache entries [transformer_lens/cache/key_value_cache.py77-80](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/cache/key_value_cache.py#L77-L80) [transformer_lens/cache/key_value_cache_entry.py56-58](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/cache/key_value_cache_entry.py#L56-L58)

## Pretrained Model Configuration Mapping

 When loading models from Hugging Face via `HookedTransformer.from_pretrained`, the library uses `convert_hf_model_config` to map native HF parameters to `HookedTransformerConfig`.

 
### Configuration Conversion Process

 
 - **Model Identification**: The system resolves aliases (e.g., "gpt2" to "gpt2-small") [transformer_lens/loading_from_pretrained.py113-123](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/loading_from_pretrained.py#L113-L123)
 - **HF Config Loading**: It fetches the `AutoConfig` from Hugging Face [transformer_lens/loading_from_pretrained.py160-164](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/loading_from_pretrained.py#L160-L164)
 - **Architecture Mapping**: It identifies specific architectural traits (e.g., Llama, Gemma, Phi) to set flags like `gated_mlp`, `normalization_type="RMS"`, or `positional_embedding_type="rotary"` [transformer_lens/loading_from_pretrained.py141-203](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/loading_from_pretrained.py#L141-L203)
 - **RoPE Parameters**: It extracts `rope_theta` handling both legacy and modern `transformers` config formats [transformer_lens/loading_from_pretrained.py81-95](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/loading_from_pretrained.py#L81-L95)

## Multi-GPU Configuration

 For large models, the configuration allows distributing layers across multiple devices using the `n_devices` parameter.

 
 - **Layer Distribution**: The `get_device_for_block_index` utility calculates which GPU should host a specific transformer block [transformer_lens/cache/key_value_cache.py48-50](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/cache/key_value_cache.py#L48-L50)
 - **KV Cache Placement**: The `TransformerLensKeyValueCache` automatically places each layer's cache entry on the same device as the corresponding transformer block [transformer_lens/cache/key_value_cache.py59-65](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/cache/key_value_cache.py#L59-L65)
