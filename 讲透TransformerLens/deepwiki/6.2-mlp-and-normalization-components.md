  This document covers the MLP (Multi-Layer Perceptron) and normalization components used throughout TransformerLens model architectures. These components implement the feedforward and normalization layers that are fundamental building blocks of transformer models.

## Component Overview

 The MLP and normalization components in TransformerLens support multiple transformer architectures with different feedforward and normalization strategies. The system uses specialized bridge components for the `TransformerBridge` (v3) architecture while maintaining legacy `HookedTransformer` components.

## MLP Components

 
### Standard MLP

 The standard MLP component implements the basic feedforward layer used in models like GPT-2 and BERT. In the `HookedTransformer` architecture, these are typically instantiated as `MLP` classes.

 
### Gated MLP (SwiGLU)

 The `GatedMLP` class implements the gated feedforward mechanism used in models like LLaMA and Mistral. It supports specialized activation functions like SwiGLU.

 **Mathematical Implementation:** The equation for gated MLP in TransformerLens is: `mlp_out = (act_fn(x @ W_gate) * (x @ W_in) + b_in) @ W_out + b_out` [transformer_lens/components/mlps/gated_mlp.py24-31](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/components/mlps/gated_mlp.py#L24-L31)

## Normalization Components

 
### LayerNorm

 The `LayerNorm` component implements standard Layer Normalization. It includes `hook_scale` and `hook_normalized` to allow mechanistic analysis of the normalization process [transformer_lens/components/layer_norm.py16-38](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/components/layer_norm.py#L16-L38)

 
### RMSNorm

 The `RMSNorm` component implements Root Mean Square normalization, which omits the centering (mean subtraction) and bias terms of standard LayerNorm.

 
| Feature | Implementation Detail |
|---|---|
| Formula | x / sqrt(mean(x^2) + eps) * w transformer_lens/components/rms_norm.py47-55 |
| Precision | Forces float32 for the scaling calculation to ensure numerical stability transformer_lens/components/rms_norm.py45-46 |
| Hooks | hook_scale (the denominator) and hook_normalized (pre-weight scaling) transformer_lens/components/rms_norm.py41-42 |

## Embedding and Positional Components

 
### Token Embeddings

 The `Embed` class manages the primary token embedding matrix `W_E`.

 
 - **Shape:** `[d_vocab, d_model]` [transformer_lens/components/embed.py21-23](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/components/embed.py#L21-L23)
 - **Features:** Supports `post_embedding_ln` for models like Bloom that apply normalization immediately after embedding [transformer_lens/components/embed.py25-35](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/components/embed.py#L25-L35)
 
 
### Positional Embeddings

 The `PosEmbed` class handles absolute positional embeddings.

 
 - **Shape:** `[n_ctx, d_model]` [transformer_lens/components/pos_embed.py22-24](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/components/pos_embed.py#L22-L24)
 - **KV Caching:** Supports `past_kv_pos_offset` for efficient generation [transformer_lens/components/pos_embed.py29-49](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/components/pos_embed.py#L29-L49)
 - **Padding:** Can zero-out embeddings for padded tokens using an `attention_mask` [transformer_lens/components/pos_embed.py58-68](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/components/pos_embed.py#L58-L68)
 
 
### Token Type Embeddings

 Used primarily in BERT-style models to distinguish between different segments (e.g., Sentence A vs Sentence B).

 
 - **Class:** `TokenTypeEmbed` [transformer_lens/components/token_typed_embed.py15](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/components/token_typed_embed.py#L15-L15)
 - **Implementation:** A binary embedding matrix `W_token_type` of shape `[2, d_model]` [transformer_lens/components/token_typed_embed.py25](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/components/token_typed_embed.py#L25-L25)

## Activation Function Resolution

 The `resolve_activation_fn` utility in the bridge system maps configuration strings to PyTorch functionals. It searches for activation names in `activation_function`, `hidden_activation`, `hidden_act`, and `act_fn` configuration attributes [transformer_lens/model_bridge/generalized_components/gated_mlp.py15-26](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/gated_mlp.py#L15-L26)

 - `silu`, `swish` -> `torch.nn.functional.silu` [transformer_lens/model_bridge/generalized_components/gated_mlp.py28-29](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/gated_mlp.py#L28-L29)
