  The Activation Cache system provides storage and analysis capabilities for transformer model activations during forward passes. It is primarily designed for mechanistic interpretability research, allowing researchers to investigate which components of a model are responsible for specific behaviors through activation decomposition, attribution analysis, and residual stream investigation.

 For information about the Hook system that captures these activations, see [Hook System](https://deepwiki.com/TransformerLensOrg/TransformerLens/3.3-hook-system). For details on the `HookedTransformer` that generates these caches, see [HookedTransformer (Legacy)](https://deepwiki.com/TransformerLensOrg/TransformerLens/3.2-hookedtransformer-(legacy)).

 
## System Architecture

 The `ActivationCache` system operates as a post-processing layer that receives activation data from the Hook system and provides analysis methods for interpretability research.

### Activation Key System

 The cache uses a structured key system to identify different activation points. While keys are strings, the `ActivationCache.__getitem__` method supports tuples for shorthand access via `transformer_lens.utils.get_act_name`.

 
| Activation Type | Key Pattern | Shape | Example |
|---|---|---|---|
| Residual Stream | blocks.{layer}.hook_resid_{pre/mid/post} | [batch, pos, d_model] | blocks.0.hook_resid_pre |
| Attention Heads | blocks.{layer}.attn.hook_{q/k/v/z/result} | [batch, pos, head, d_head] | blocks.1.attn.hook_q |
| Attention Patterns | blocks.{layer}.attn.hook_{pattern/attn_scores} | [batch, head, query_pos, key_pos] | blocks.2.attn.hook_pattern |
| MLP Activations | blocks.{layer}.mlp.hook_{pre/post/mid} | [batch, pos, d_mlp] | blocks.0.mlp.hook_post |
| Embeddings | hook_{embed/pos_embed} | [batch, pos, d_model] | hook_embed |
| Layer Norms | blocks.{layer}.ln{1/2}.hook_{scale/normalized} | [batch, pos, 1] or [batch, pos, d_model] | blocks.0.ln1.hook_scale |

## Analysis Methods

 
### Residual Stream Decomposition

 The cache provides several methods for decomposing the residual stream to understand component contributions:

 
 - **`accumulated_resid(layer, incl_mid, pos_slice)`**: Returns the residual stream at a specific layer, or a stack of the residual stream across all layers (often called the "Logit Lens" when projected to logits). [transformer_lens/ActivationCache.py322-452](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/ActivationCache.py#L322-L452)
 - **`decompose_resid(mode, return_labels)`**: Decomposes the residual stream into a sum of the outputs of each previous component (Embed, PosEmbed, and each Attention/MLP layer). [transformer_lens/ActivationCache.py566-654](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/ActivationCache.py#L566-L654)
 - **`get_full_resid_decomposition()`**: The most granular decomposition, breaking the stream down into individual attention heads and MLP neurons. [transformer_lens/ActivationCache.py1019-1109](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/ActivationCache.py#L1019-L1109)
 
 
### Logit Attribution Analysis

 The `logit_attrs()` method computes the "Direct Logit Attribution" (DLA). It takes a stack of activations (e.g., from `decompose_resid`) and projects them onto the direction of a specific token in the unembedding space.

### Component Stacking Methods

 These methods aggregate activations across layers or components into a single tensor for vectorized analysis.

 
| Method | Purpose | Output Shape |
|---|---|---|
| stack_head_results() | Stacks the result of every attention head across specified layers. | [num_heads, batch, pos, d_model] |
| stack_neuron_results() | Stacks the result of every MLP neuron. Warning: very memory intensive. | [num_neurons, batch, pos, d_model] |
| stack_activation() | Generic utility to stack any activation type (e.g., "z" or "mlp_out") across layers. | [num_layers, ...] |

## Utility Methods

 
### Layer Normalization Application

 Because models often apply LayerNorm before components, the residual stream in the cache is often "un-normalized". The `apply_ln_to_stack()` method uses cached `hook_scale` values to normalize a stack of activations so they can be validly compared to model weights or projected to logits.

## Performance Considerations

 
 - **Memory Usage**: The `ActivationCache` stores tensors in memory. For large models or long sequences, caching every activation can lead to Out-Of-Memory (OOM) errors. Users should use the `names_filter` in `run_with_cache` to limit storage. [transformer_lens/ActivationCache.py100-105](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/ActivationCache.py#L100-L105)
 - **Garbage Collection**: The cache holds a reference to the `model` to access configuration and weights for its analysis methods. To allow the model to be garbage collected while keeping the activations, set `cache.model = None`. [transformer_lens/ActivationCache.py152-153](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/ActivationCache.py#L152-L153)
