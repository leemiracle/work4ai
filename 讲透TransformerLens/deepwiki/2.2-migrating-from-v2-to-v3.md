  TransformerLens 3.0 introduces the `TransformerBridge` architecture, a major shift in how models are instrumented. In v2, `HookedTransformer` was a unified reimplementation of every supported architecture. In v3, `TransformerBridge` preserves the native Hugging Face (HF) implementation and wraps it using **Architecture Adapters**, providing a consistent interface while maintaining numerical parity with the source models [docs/source/content/migrating_to_v3.md7-12](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/content/migrating_to_v3.md?plain=1#L7-L12)

 
## Comparison: v2 vs v3 Loading

 The primary entry point has changed from `HookedTransformer.from_pretrained` to `TransformerBridge.boot_transformers`.

 
| Feature | v2 (HookedTransformer) | v3 (TransformerBridge) |
|---|---|---|
| Loading Method | HookedTransformer.from_pretrained | TransformerBridge.boot_transformers |
| Implementation | Custom reimplementation in TL | Native Hugging Face model |
| Weight Processing | Applied by default (e.g., fold_ln) | Opt-in via enable_compatibility_mode() |
| Hook Names | Canonical (e.g., blocks.0.hook_resid_pre) | Canonical (e.g., blocks.0.hook_in) + Legacy Aliases |
| Architecture Support | Manual per-model porting | 50+ architectures via Adapters |

## Key API Changes

 
### Removed and Moved Parameters

 Several parameters from the legacy `from_pretrained` method have been relocated or removed:

 
 - **Relocated to `enable_compatibility_mode`**: `fold_ln`, `center_writing_weights`, `center_unembed`, `fold_value_biases`, and `refactor_factored_attn_matrices` [docs/source/content/migrating_to_v3.md33-35](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/content/migrating_to_v3.md?plain=1#L33-L35)
 - **Removed**: `n_devices`, `move_to_device`, and `first_n_layers`. Multi-GPU support is handled differently in the bridge architecture [docs/source/content/migrating_to_v3.md37-39](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/content/migrating_to_v3.md?plain=1#L37-L39)
 
 
### New Parameters in `boot_transformers`

 
 - `load_weights: bool`: If `False`, initializes the bridge with config only (useful for shape checking) [docs/source/content/migrating_to_v3.md43](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/content/migrating_to_v3.md?plain=1#L43-L43)
 - `n_ctx: int`: Overrides the model's context length across different HF config field names (e.g., `n_positions`, `max_position_embeddings`) [docs/source/content/migrating_to_v3.md46](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/content/migrating_to_v3.md?plain=1#L46-L46)
 - `hf_config_overrides: dict`: Allows direct modification of the HF config before model construction [docs/source/content/migrating_to_v3.md45](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/content/migrating_to_v3.md?plain=1#L45-L45)

## Hook Name Aliasing

 The bridge uses a standardized `hook_in` / `hook_out` naming convention for all components. To ensure backward compatibility, an alias layer maps legacy `HookedTransformer` names to these new canonical points [transformer_lens/model_bridge/bridge.py153-158](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/bridge.py#L153-L158)

 
### Common Hook Mappings

## Compatibility Mode and Weight Processing

 In v2, weights were processed (LayerNorm folding, etc.) during loading. In v3, the bridge preserves raw HF weights by default. If your analysis (like Direct Logit Attribution) requires processed weights, you must call `enable_compatibility_mode()` [docs/source/content/migrating_to_v3.md51-54](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/content/migrating_to_v3.md?plain=1#L51-L54)

 
### Implementation of Compatibility Mode

 The `enable_compatibility_mode` method triggers:

 
 - **Weight Processing**: Folding LayerNorms and centering weights via `ProcessWeights` utilities [docs/source/content/migrating_to_v3.md61](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/content/migrating_to_v3.md?plain=1#L61-L61)
 - **Alias Registration**: Populating the component's namespace with legacy hook names [transformer_lens/model_bridge/generalized_components/base.py81-93](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/base.py#L81-L93)

## Architecture Adapters and Generalized Components

 The bridge system decouples the model implementation from the instrumentation.

 
 - **ArchitectureAdapter**: A class (e.g., `LlamaArchitectureAdapter`) that defines how a specific HF model's modules map to TL concepts [transformer_lens/model_bridge/architecture_adapter.py1-50](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/architecture_adapter.py#L1-L50)
 - **GeneralizedComponent**: Standardized wrappers like `AttentionBridge`, `MLPBridge`, and `BlockBridge` that host the `HookPoint` objects [transformer_lens/model_bridge/generalized_components/base.py18-28](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/base.py#L18-L28)

## Semantic Differences in Hooks

 There are specific cases where hook behavior differs between the versions, particularly regarding LayerNorm placement:

 
 - **`hook_mlp_in`**: In v3 compatibility mode, this hook is wired to fire **pre-LN2** to match v2 behavior. This requires an internal capture mechanism [transformer_lens/model_bridge/generalized_components/block.py113-161](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/block.py#L113-L161)
 - **Split QKV Hooks**: For architectures with fused QKV matrices (like GPT-2), `JointQKVAttentionBridge` provides virtual hooks for `hook_q`, `hook_k`, and `hook_v` by slicing the fused activations [transformer_lens/model_bridge/generalized_components/joint_qkv_attention.py23-28](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/joint_qkv_attention.py#L23-L28)
