  TransformerLens includes a comprehensive benchmarking and verification suite designed to ensure that `TransformerBridge` (v3.0) and `HookedTransformer` (legacy) maintain numerical parity with reference HuggingFace implementations. The system uses a multi-phase approach to validate logits, activation hooks, gradients, and weight processing transformations across over 50 supported architectures.

 
## Benchmark Suite Phases (P1-P8)

 The `run_benchmark_suite` function executes an optimized multi-phase comparison [transformer_lens/benchmarks/main_benchmark.py172-230](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/benchmarks/main_benchmark.py#L172-L230) Each phase targets a specific level of compatibility or model feature.

 
| Phase | Name | Description |
|---|---|---|
| P1 | HF + Bridge (Unprocessed) | Direct comparison between a raw HuggingFace model and a TransformerBridge with all processing (folding/centering) disabled transformer_lens/benchmarks/main_benchmark.py5 |
| P2 | Bridge + HT (Unprocessed) | Compares TransformerBridge against HookedTransformer with default (unprocessed) weights transformer_lens/benchmarks/main_benchmark.py6 |
| P3 | Bridge + HT (Processed) | Full compatibility mode testing where both models undergo weight folding and centering transformer_lens/benchmarks/main_benchmark.py7 |
| P4 | Text Quality | Perplexity-based scoring using GPT-2 Medium to ensure model output remains legible after transformations transformer_lens/benchmarks/main_benchmark.py8 |
| P5 | Granular Weight Tests | Individual tests for specific flags like LayerNorm folding or MLP centering transformer_lens/benchmarks/main_benchmark.py9 |
| P6 | Combined Weight Tests | Tests for interactions between multiple weight processing flags transformer_lens/benchmarks/main_benchmark.py10 |
| P7 | Multimodal Tests | Validation for models supporting pixel_values (Vision-Language models) transformer_lens/benchmarks/main_benchmark.py11 |
| P8 | Audio Tests | Validation for audio-specific architectures like HuBERT transformer_lens/benchmarks/main_benchmark.py83-86 |

### Numerical Parity Testing

 Numerical parity is verified using `safe_allclose`, which handles device and dtype mismatches [transformer_lens/benchmarks/utils.py79-92](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/benchmarks/utils.py#L79-L92)

 
 - **Logits:** Verified in `benchmark_forward_pass` [transformer_lens/benchmarks/forward_pass.py40-61](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/benchmarks/forward_pass.py#L40-L61)
 - **Activations:** Verified in `benchmark_forward_hooks`. It captures activations via `make_capture_hook` and compares them across the `hook_dict` [transformer_lens/benchmarks/hook_registration.py108-126](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/benchmarks/hook_registration.py#L108-L126)
 - **Gradients:** Verified in `benchmark_backward_hooks` by performing a backward pass on a dummy loss and capturing gradients via `make_grad_capture_hook` [transformer_lens/benchmarks/backward_gradients.py18-36](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/benchmarks/backward_gradients.py#L18-L36)

## Memory Management During Verification

 To prevent Out-of-Memory (OOM) errors when verifying large models, the `verify_models` tool and `main_benchmark` runner employ several strategies:

 
 - **Parameter Estimation:** Uses `estimate_model_params` to check memory requirements via `AutoConfig` before downloading the model weights [transformer_lens/tools/model_registry/verify_models.py181-195](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/verify_models.py#L181-L195)
 - **Aggressive GC:** Explicit calls to `gc.collect()` and `torch.cuda.empty_cache()` are made between benchmark phases and model transitions [transformer_lens/benchmarks/main_benchmark.py14-17](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/benchmarks/main_benchmark.py#L14-L17)
 - **Sequential Loading:** Reference models (HuggingFace) are loaded, run for Phase 1, and then deleted from memory before loading the `HookedTransformer` for Phase 2/3.
 - **Checkpointing:** The `VerificationProgress` class tracks state, allowing the `verify_models` script to resume after an interruption via `--resume` [transformer_lens/tools/model_registry/verify_models.py152-179](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/verify_models.py#L152-L179)

## Model Registry Integration

 The benchmarking results are persisted in `supported_models.json`. Each model entry includes scores for phases 1, 2, 3, 4, 7, and 8 [transformer_lens/tools/model_registry/hf_scraper.py161-176](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/hf_scraper.py#L161-L176)

 
 - **Status Codes:** Models are marked as `STATUS_UNVERIFIED` (0), `STATUS_VERIFIED` (1), `STATUS_FAILED` (2), or `STATUS_SKIPPED` (3) [transformer_lens/tools/model_registry/verify_models.py48-51](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/verify_models.py#L48-L51)
 - **Architecture Gaps:** Models with unsupported architectures are identified by the `hf_scraper` and logged in `architecture_gaps.json` to prioritize future adapter development [transformer_lens/tools/model_registry/data/architecture_gaps.json1-11](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/data/architecture_gaps.json#L1-L11)
