  The `HookedTransformer` class is the primary interface for loading and running transformer models with full activation access in TransformerLens. It wraps transformer models with a comprehensive hook system that allows users to inspect, modify, and cache activations from every layer and component during forward passes.

 In the v3.0 architecture, `HookedTransformer` is considered a "Legacy" interface, though it remains fully supported. It now operates alongside the `TransformerBridge`, which provides a more modular way to wrap Hugging Face models.

 
## Core Architecture

 The `HookedTransformer` class extends `HookedRootModule` and implements a complete transformer architecture with hook points at every significant activation. It supports over 50 pretrained models and provides a unified interface for mechanistic interpretability research.

### Weight Processing

 During loading, the `ProcessWeights` utility (often called via `model.process_weights_()`) performs several transformations:

 
 - **Layer Norm Folding** (`fold_ln`): Absorbs layer norm parameters into adjacent linear layers.
 - **Weight Centering** (`center_writing_weights`, `center_unembed`): Centers weight matrices to remove constant offsets.
 - **Matrix Refactoring** (`refactor_factored_attn_matrices`): Refactors factored attention matrices for easier analysis.

## Specialized Variants

 
### HookedEncoder (BERT)

 For bidirectional models like BERT, TransformerLens provides the `HookedEncoder` class. It implements a BERT-style encoder with specialized heads like `BertMLMHead` and `BertNSPHead`.

 Sources: [transformer_lens/HookedEncoder.py40-94](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/HookedEncoder.py#L40-L94)

 
### HookedEncoderDecoder (T5)

 For encoder-decoder architectures like T5, the library uses `HookedEncoderDecoder`, which manages separate encoder and decoder blocks while maintaining the hook system across both.

 
## Usage with Training

 `HookedTransformer` models can be trained using the `train()` utility. This requires a `HookedTransformerTrainConfig` specifying hyperparameters like learning rate, batch size, and optimizer (Adam, AdamW, or SGD).

 The model supports distributed computation across multiple GPUs. The `move_to_and_update_config` utility is used to manage device transitions while keeping the `cfg.device` attribute synchronized.
