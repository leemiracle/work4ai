  This document covers the development environment setup for TransformerLens, including package management, development tooling, documentation generation, and testing infrastructure. TransformerLens v3.0 has transitioned to using `uv` for lightning-fast dependency management and environment isolation.

 
## Package Management with uv

 TransformerLens uses `uv` for dependency management, replacing legacy Poetry workflows. The project configuration is centralized in `pyproject.toml`, which defines project metadata, dependency groups, and tool configurations.

### Dependency Groups

 The project organizes optional and development dependencies into specific groups. By default, `uv sync` installs the core dependencies plus the `dev`, `docs`, `jupyter`, and `multimodal` groups.

 
| Group | Purpose | Key Dependencies |
|---|---|---|
| dev | Development and linting tools | black, isort, pycln, pytest, mypy |
| docs | Documentation generation | sphinx, furo, nbsphinx, myst-parser |
| jupyter | Notebook environments | ipython, jupyterlab, ipywidgets |
| multimodal | Vision/Audio support | timm, torchvision |
| quantization | Model compression | bitsandbytes, optimum-quanto |

 **Sources:** [pyproject.toml45-92](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/pyproject.toml#L45-L92)

 
## Development Tooling Configuration

 
### Code Quality Tools

 TransformerLens enforces strict code quality through a suite of tools orchestrated via a `makefile`.

 
```

```

 **Sources:** [makefile13-22](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/makefile#L13-L22) [pyproject.toml113-132](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/pyproject.toml#L113-L132)

 
### Tool Configuration Details

 
 - **Black**: Formats code with a 100-character line length. It explicitly excludes `.venv`, `snapshots`, and `docs/build/`. [pyproject.toml122-132](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/pyproject.toml#L122-L132)
 - **isort**: Configured with the `black` profile to ensure compatibility. [pyproject.toml113-116](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/pyproject.toml#L113-L116)
 - **pycln**: Used to automatically remove unused imports across the project, excluding `__init__.py` files to preserve exported APIs. [makefile14](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/makefile#L14-L14)
 - **MyPy**: Performs static type checking, excluding legacy folders like `easy_transformer` and `tests`. [pyproject.toml117-121](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/pyproject.toml#L117-L121)
 - **Pyright**: Provides high-performance type checking with strict rules enabled for core logic. [pyproject.toml154-206](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/pyproject.toml#L154-L206)
 
 
## Documentation Generation

 
### Sphinx Configuration

 The documentation system is built on Sphinx and uses the `furo` theme. It automatically extracts API details from docstrings during the build process.

 
```

```

 **Sources:** [docs/source/conf.py22-28](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/conf.py#L22-L28) [docs/source/conf.py115-155](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/conf.py#L115-L155)

 
### Documentation Build Process

 
 - **API Doc Generation**: `run_apidoc()` is triggered when the builder initializes. it uses `sphinx-apidoc` to generate `.rst` files for the codebase. [docs/source/conf.py115-155](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/conf.py#L115-L155)
 - **Exclusion Logic**: Specific high-level classes like `HookedTransformer`, `ActivationCache`, and `FactoredMatrix` are excluded from the automated `apidoc` run because they have dedicated, hand-written documentation pages. [docs/source/conf.py135-144](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/conf.py#L135-L144)
 - **Notebook Integration**: `nbsphinx` allows including Jupyter notebooks from the `demos/` directory directly into the documentation. Notebooks are configured *never* to execute during the build to avoid OOM or device errors. [docs/source/conf.py178](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/docs/source/conf.py#L178-L178)

## Testing Infrastructure

 
### Test Configuration

 TransformerLens uses `pytest` with several plugins to handle the variety of tests (unit, integration, and notebook).

 
| Setting | Value / Purpose |
|---|---|
| addopts | --doctest-modules, --nbval, --jaxtyping-packages |
| testpaths | tests, transformer_lens |
| markers | slow: marks tests to be deselected with -m "not slow" |

 **Sources:** [pyproject.toml94-112](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/pyproject.toml#L94-L112)

 
### CI/CD Integration

 The development environment is mirrored in GitHub Actions. The `checks.yml` workflow performs:

 
 - **Compatibility Checks**: Runs unit and acceptance tests across Python 3.10, 3.11, and 3.12. [.github/workflows/checks.yml60-70](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.github/workflows/checks.yml#L60-L70)
 - **MPS Checks**: Runs specialized tests on macOS runners to ensure Metal Performance Shaders (Apple Silicon) compatibility. [.github/workflows/checks.yml120-153](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.github/workflows/checks.yml#L120-L153)
 - **Linting**: Runs the `format-check` job to ensure `black`, `isort`, and `pycln` rules are followed. [.github/workflows/checks.yml190-200](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.github/workflows/checks.yml#L190-L200)
 
 
## VS Code and Devcontainer

 
### VS Code Settings

 The repository includes a `.vscode/settings.json` file to standardize the local editor experience:

 
 - **Auto-formatting**: `editor.formatOnSave` is enabled using the Black formatter. [.vscode/settings.json11](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.vscode/settings.json#L11-L11)
 - **Import Organization**: `source.organizeImports` is triggered on save. [.vscode/settings.json8-10](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.vscode/settings.json#L8-L10)
 - **Rulers**: A vertical ruler at 100 characters helps maintain line length standards. [.vscode/settings.json12](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/.vscode/settings.json#L12-L12)
