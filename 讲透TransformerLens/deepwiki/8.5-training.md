  TransformerLens provides built-in utilities for training and fine-tuning `HookedTransformer` models on autoregressive language modeling tasks. The primary entry point for training is the `train()` function, which orchestrates the optimization loop, device management, and optional logging via Weights & Biases.

 
## HookedTransformerTrainConfig

 The training process is governed by the `HookedTransformerTrainConfig` dataclass, which encapsulates hyperparameters and environment settings.

 
| Parameter | Type | Description |
|---|---|---|
| num_epochs | int | Total number of passes over the dataset. |
| batch_size | int | Number of samples per gradient update. |
| lr | float | Learning rate (default: 1e-3). |
| optimizer_name | str | Supports "Adam", "AdamW", and "SGD". |
| warmup_steps | int | Number of steps for linear learning rate warmup. |
| max_grad_norm | Optional[float] | Threshold for gradient clipping. |
| weight_decay | Optional[float] | L2 regularization coefficient. |
| wandb | bool | Enables logging to Weights & Biases. |

 Sources: [transformer_lens/train.py22-61](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/train.py#L22-L61)

 
## The Training Loop

 The `train()` function implements a standard PyTorch training loop specialized for `HookedTransformer`. It assumes the provided `Dataset` returns a dictionary containing a `"tokens"` key formatted for autoregressive modeling.

 
### Implementation Details

 
 - **Optimizer Selection**: If `weight_decay` is provided with `"Adam"`, the function automatically switches to `AdamW` to ensure correct weight decay implementation [transformer_lens/train.py95-107](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/train.py#L95-L107).
 - **Device Management**: The function uses `utils.get_device()` to automatically select the best available hardware (CUDA, MPS, or CPU) if no device is specified in the config [transformer_lens/train.py91-92](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/train.py#L91-L92).
 - **Forward Pass**: The model is called with `return_type="loss"`, which leverages the internal `HookedTransformer` loss calculation logic [transformer_lens/train.py133](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/train.py#L133-L133).
 - **Checkpoints**: If `save_dir` and `save_every` are defined, the model `state_dict` is serialized at the specified step intervals [transformer_lens/train.py151-156](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/train.py#L151-L156).

## Device Selection and Safety

 Training often requires specific hardware acceleration. TransformerLens includes safety checks for the Metal Performance Shaders (MPS) backend on Apple Silicon.

 
 - **Automatic Selection**: `get_device()` prioritizes CUDA, then checks for MPS. MPS is only selected if the environment variable `TRANSFORMERLENS_ALLOW_MPS=1` is set, due to known silent correctness issues in certain PyTorch versions [transformer_lens/utilities/devices.py56-80](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/utilities/devices.py#L56-L80).
 - **Configuration Sync**: When moving a model using `move_to_and_update_config()`, the utility ensures that `model.cfg.device` is updated to reflect the actual location of the weights, preventing mismatches during hook execution [transformer_lens/utilities/devices.py152-195](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/utilities/devices.py#L152-L195).

## Training Native Models

 While `HookedTransformer` is the legacy standard, the v3.0 `TransformerBridge` supports training "native" models (models built entirely within TransformerLens without a HuggingFace source).

 
 - **Bootstrapping**: Use `TransformerBridge.boot_native(cfg)` to initialize a model with random weights according to a `TransformerBridgeConfig` [tests/unit/model_bridge/test_boot_native.py42](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/tests/unit/model_bridge/test_boot_native.py#L42-L42).
 - **Parameter Access**: The bridge surfaces the underlying model parameters via `bridge.parameters()`, allowing standard PyTorch optimizers to target the weights while maintaining the hook system functionality [tests/unit/model_bridge/test_build_bridge_from_module.py83-93](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/tests/unit/model_bridge/test_build_bridge_from_module.py#L83-L93).
