  This document explains how TransformerLens supports distributing model components across multiple GPUs. This feature allows users to load and run larger models than would fit on a single GPU by distributing the model's layers across multiple devices.

 
## Overview

 TransformerLens enables multi-GPU model execution through a configurable parameter-based approach. The library determines the optimal device allocation based on available memory and distributes transformer layers across available GPUs to maximize resource utilization.

## TransformerBridge Multi-GPU Support

 For `TransformerBridge`, multi-GPU support leverages HuggingFace Accelerate's `device_map` system while providing TransformerLens-specific safety checks.

 
### Device Map Resolution

 The `resolve_device_map` function converts configuration parameters into HF-compatible arguments [transformer_lens/utilities/multi_gpu.py152-186](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/utilities/multi_gpu.py#L152-L186)

 
 - **Balanced Dispatch**: If `n_devices > 1`, it returns a `"balanced"` strategy with a `max_memory` dictionary capping visibility to exactly `n_devices` [transformer_lens/utilities/multi_gpu.py168-171](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/utilities/multi_gpu.py#L168-L171)
 - **Safety Restrictions**: Values like `"disk"` or `"meta"` in a `device_map` are currently rejected because Bridge component wrappers may bypass Accelerate's offload hooks during forward passes [transformer_lens/utilities/multi_gpu.py164-166](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/utilities/multi_gpu.py#L164-L166)

## MPS (Metal Performance Shaders) Support

 TransformerLens provides specific utilities for Apple Silicon (MPS) devices, including safety checks for known PyTorch bugs.

 
### MPS Safety Checks

 
 - **Auto-selection**: MPS is only auto-selected by `get_device()` if the environment variable `TRANSFORMERLENS_ALLOW_MPS=1` is set [transformer_lens/utilities/devices.py68-71](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/utilities/devices.py#L68-L71)
 - **Version Warnings**: The library warns about specific PyTorch versions (e.g., 2.8.0) where `torch.nn.functional.linear` produces incorrect results on non-contiguous tensors [transformer_lens/utilities/devices.py27-32](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/utilities/devices.py#L27-L32)
 - **Correctness**: Users are warned that the MPS backend may produce silently incorrect results on older PyTorch versions [transformer_lens/utilities/devices.py120-129](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/utilities/devices.py#L120-L129)

## Activation Caching Across Devices

 TransformerLens maintains device consistency in its activation cache system. When using `run_with_cache()`, activations are stored on the device where they were computed:

 
| Component | Cache Key | Device |
|---|---|---|
| Input Embedding | hook_embed | Device 0 |
| Block 0 MLP | blocks.0.mlp.hook_post | Device 0 |
| Block N MLP | blocks.N.mlp.hook_post | Device 1 (if distributed) |

 When a model is moved to a specific device using `model.to("cuda:1")`, the cache generated by `run_with_cache` will reside on that same device by default [tests/acceptance/test_multi_gpu.py106-120](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/tests/acceptance/test_multi_gpu.py#L106-L120)

## Performance and Training

 
### Device Movement and Dtypes

 The `move_to_and_update_config` utility ensures that when a model is moved to a new device or its dtype is changed, the internal `model.cfg` is updated to reflect the new state [transformer_lens/utilities/devices.py152-192](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/utilities/devices.py#L152-L192)

 
### Training Configuration

 The `HookedTransformerTrainConfig` includes a `device` field. If not provided, the training loop defaults to the best available device via `utils.get_device()` [transformer_lens/train.py53](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/train.py#L53-L53) [transformer_lens/train.py91-92](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/train.py#L91-L92) During the training loop, the model and input tokens are explicitly moved to the configured device [transformer_lens/train.py127](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/train.py#L127-L127) [transformer_lens/train.py132](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/train.py#L132-L132)
