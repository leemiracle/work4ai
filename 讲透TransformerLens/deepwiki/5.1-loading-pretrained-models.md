  This page covers the system for loading pretrained transformer models from external sources (primarily Hugging Face) into TransformerLens format. The loading process handles model name resolution, configuration conversion, weight downloading, and architecture-specific weight transformations.

 In TransformerLens v3.0, the loading system has been expanded to include the **TransformerBridge** architecture, which allows for a more modular and extensible way to wrap Hugging Face models while maintaining the legacy **HookedTransformer** loading paths.

## Model Name Resolution

 TransformerLens supports a vast array of pretrained models through an alias system that maps user-friendly names to official Hugging Face model identifiers.

 
### Official Model Names and Aliases

 The system uses a centralized registry to resolve model names. The `get_official_model_name` function is the primary entry point for this resolution.

 
| Component | Description | File Location |
|---|---|---|
| OFFICIAL_MODEL_NAMES | List of canonical model names | transformer_lens/supported_models.py1-50 |
| MODEL_ALIASES | Mapping from aliases to official names | transformer_lens/supported_models.py51-100 |
| get_official_model_name() | Resolves aliases to official names | transformer_lens/loading_from_pretrained.py113-124 |
| make_model_alias_map() | Generates a lookup dictionary for all known names | transformer_lens/loading_from_pretrained.py98-110 |

## Configuration Conversion

 The system converts Hugging Face model configurations to TransformerLens formats (`HookedTransformerConfig` or `TransformerBridgeConfig`) through architecture-specific logic.

 
### Standardized Mapping

 The `map_default_transformer_lens_config` function provides a standardized mapping from various Hugging Face config field names (like `n_embd`, `hidden_size`, or `model_dim`) to the consistent TransformerLens naming convention (`d_model`).

## The Model Registry

 TransformerLens maintains a detailed registry of supported models and their verification status. This is stored in `supported_models.json`.

 
### Registry Metadata

 The registry tracks:

 
 - **Architecture ID**: The Hugging Face class name (e.g., `LlamaForCausalLM`).
 - **Status**: Verification level (1: Verified, 2: OOM/Large, 3: Numerical Mismatch).
 - **Benchmarks**: Scores across various verification phases (P1-P8).

### Weight Processing (ProcessWeights)

 After conversion, the `ProcessWeights` utility handles optional transformations like LayerNorm folding and weight centering.

 
| Operation | Purpose |
|---|---|
| fold_ln | Folds LayerNorm weights into subsequent linear layers to simplify the residual stream. |
| center_writing_weights | Centers weights that "write" to the residual stream (MLP out, Attn out) to remove constant offsets. |
| center_unembed | Centers the unembedding weights to ensure zero-mean logits. |
