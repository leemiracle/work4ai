  TransformerLens supports over 50 distinct model architectures through a flexible adapter system. These adapters allow researchers to perform mechanistic interpretability on a vast range of models from Hugging Face, including large language models (LLMs), vision-language models, encoder-only models, and state-space models like Mamba.

 
## Architecture Registry and Discovery

 The `ArchitectureAdapterFactory` serves as the central hub for mapping Hugging Face architecture strings to specific TransformerLens adapter classes. When a model is loaded via `TransformerBridge.boot_transformers`, the factory identifies the correct adapter based on the `architectures` field in the model's configuration.

 The following table illustrates how common Hugging Face architectures are mapped to internal adapters:

## Implementation Logic

 Each architecture adapter inherits from `ArchitectureAdapter` and defines two critical structures:

 
 - **`component_mapping`**: Maps TransformerLens logical names (e.g., `blocks.0.attn.q`) to the specific module paths in the Hugging Face model (e.g., `model.layers.0.self_attn.q_proj`).
 - **`weight_processing_conversions`**: Defines how weights should be reshaped or transformed during loading (e.g., folding LayerNorms or rearranging head dimensions).

## Specialized Adapters

 
### Encoder and Encoder-Decoder Support

 While TransformerLens is primarily known for decoder-only models, it provides robust support for bidirectional and conditional models.

 
 - **BERT (`BertArchitectureAdapter`)**: Supports `BertForMaskedLM` and `BertForNextSentencePrediction`. It handles the unique "Post-LN" structure of BERT where normalization occurs after the residual addition.
 - **T5 (`T5ArchitectureAdapter`)**: Supports the encoder-decoder architecture. The adapter maps components for both the `encoder` and `decoder` stacks into a unified `TransformerBridge` structure.
 
 **Sources:** [transformer_lens/model_bridge/supported_architectures/bert.py25-138](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/supported_architectures/bert.py#L25-L138), [transformer_lens/model_bridge/supported_architectures/t5.py1-50](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/supported_architectures/t5.py#L1-L50)

 
### Multimodal Adapters

 Multimodal adapters bridge vision encoders (like CLIP or SigLIP) with language decoders.

 
 - **LLaVA**: Uses `LlavaArchitectureAdapter` to wrap the `vision_tower`, `multi_modal_projector`, and the underlying `language_model`.
 - **Gemma 3/4**: Supports tri-modal and unified encoder-free multimodal designs.
 
 **Sources:** [transformer_lens/model_bridge/supported_architectures/llava.py1-40](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/supported_architectures/llava.py#L1-L40), [transformer_lens/factories/architecture_adapter_factory.py99-105](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/factories/architecture_adapter_factory.py#L99-L105)

 
### Fused Weights Handling (Phi-3)

 Some architectures like Phi-3 use "fused" projections (e.g., a single `qkv_proj` matrix instead of three separate matrices). The `Phi3ArchitectureAdapter` uses `_SizedSplitConversion` to slice these tensors into the standard Q, K, and V components during the `TransformerBridge` setup.

## Model Registry and Verification

 The library maintains a comprehensive registry of verified models to ensure numerical parity with Hugging Face implementations.

 
 - **`supported_models.json`**: A machine-readable database of over 1,000 verified model IDs across 60+ architectures.
 - **Verification Status**: Models are assigned statuses (e.g., `1` for full verification, `3` for parity issues).
 - **Canonical Authors**: The registry tracks "Canonical" authors (e.g., `google` for Gemma, `meta-llama` for Llama) to prioritize support for foundation models.
 
 **Sources:** [transformer_lens/tools/model_registry/data/supported_models.json1-40](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/data/supported_models.json#L1-L40), [transformer_lens/tools/model_registry/__init__.py118-185](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/__init__.py#L118-L185)

 
## Key Functions for Architecture Mapping

 
 - **`map_default_transformer_lens_config(hf_config)`**: Normalizes heterogeneous HF config fields (like `n_embd`, `hidden_size`, `model_dim`) into the standard `d_model` used by TransformerLens.
 - **`ArchitectureAdapterFactory.get_adapter_class(architecture_name)`**: Retrieves the adapter class registered for a specific HF architecture string.
 - **`prepare_model(hf_model)`**: A lifecycle method in adapters (like BERT) that dynamically adjusts mappings based on the specific task head present in the loaded model.
