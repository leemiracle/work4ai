  Direct Logit Attribution (DLA) is a technique used in mechanistic interpretability to decompose a model's output logit into the additive contributions of upstream components. Because the unembedding operation is linear and the residual stream is a sum of component outputs, the final logit can be expressed as a sum of per-component dot products with the unembedding direction of a specific token [transformer_lens/tools/analysis/direct_logit_attribution.py3-13](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/analysis/direct_logit_attribution.py#L3-L13)

 TransformerLens provides both low-level primitives in `ActivationCache` and a high-level analysis module to perform this decomposition across layers, sublayers, or individual attention heads.

 
## Core Concepts

 DLA relies on the fact that in a Transformer, the logit for a token $w$ at position $t$ is calculated as: $$L_{w,t} = \text{Unembed}(\text{LayerNorm}(\text{Resid}_{t}))$$

 By linearizing the final LayerNorm (or folding it into the weights), the logit becomes a linear function of the residual stream. Since the residual stream is the sum of the embedding and all sublayer outputs: $$\text{Resid}*{t} = x*{embed} + \sum x_{attn, l} + \sum x_{mlp, l}$$ The logit $L_{w,t}$ can be decomposed into the sum of attributions from each of these terms [transformer_lens/tools/analysis/direct_logit_attribution.py3-13](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/analysis/direct_logit_attribution.py#L3-L13)

 
### Mathematical Invariants

 The sum of all component attributions plus the unembedding bias ($b_U$) reconstructs the full logit: `sum(component DLA) + b_U[token] == logit[token]` [tests/integration/model_bridge/test_direct_logit_attribution.py7-8](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/tests/integration/model_bridge/test_direct_logit_attribution.py#L7-L8)

 For logit differences (e.g., Correct vs. Incorrect): `sum(component DLA_diff) == logit_diff - (b_U[correct] - b_U[incorrect])` [tests/integration/model_bridge/test_direct_logit_attribution.py12-13](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/tests/integration/model_bridge/test_direct_logit_attribution.py#L12-L13)

 
## Implementation in ActivationCache

 The `ActivationCache` class contains the primary logic for calculating attributions. It provides methods to stack activations and project them onto the unembedding space.

 
### Key Methods

 
 - **`logit_attrs`**: The core mathematical engine. It takes a stack of residual stream vectors and projects them onto the difference between the "correct" and "incorrect" residual directions [transformer_lens/ActivationCache.py83-93](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/ActivationCache.py#L83-L93)
 - **`decompose_resid`**: Breaks the residual stream into contributions from `embed`, `pos_embed`, and each layer's `attn_out` and `mlp_out` [transformer_lens/ActivationCache.py77-80](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/ActivationCache.py#L77-L80)
 - **`accumulated_resid`**: Provides the "Logit Lens" view by returning the cumulative residual stream at each sublayer [transformer_lens/ActivationCache.py97-98](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/ActivationCache.py#L97-L98)
 - **`stack_head_results`**: Decomposes the residual stream by individual attention heads [transformer_lens/tools/analysis/direct_logit_attribution.py126-128](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/analysis/direct_logit_attribution.py#L126-L128)

## The Direct Logit Attribution Module

 The `transformer_lens.tools.analysis.direct_logit_attribution` module provides a high-level wrapper that simplifies the process into a single function call.

 
### Function: `direct_logit_attribution`

 This function handles tokenization, running the model (if a cache isn't provided), and performing the requested decomposition [transformer_lens/tools/analysis/direct_logit_attribution.py165-172](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/analysis/direct_logit_attribution.py#L165-L172)

 
| Parameter | Type | Description |
|---|---|---|
| model | HookedTransformer \| TransformerBridge | The model to analyze. |
| input | str \| Tensor | The input prompt. |
| answer_tokens | TokenInput | The target token(s) for attribution. |
| incorrect_tokens | TokenInput | Optional tokens to calculate logit difference. |
| unit | "component" \| "layer" \| "head" | The granularity of decomposition. |
| pos | int \| None | The token position to analyze (defaults to last token -1). |

 
### Result: `DirectLogitAttribution`

 The function returns a dataclass containing the attribution tensor and human-readable labels [transformer_lens/tools/analysis/direct_logit_attribution.py70-86](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/analysis/direct_logit_attribution.py#L70-L86) It includes a `.top(k)` method to quickly identify the most influential components [transformer_lens/tools/analysis/direct_logit_attribution.py92-103](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/analysis/direct_logit_attribution.py#L92-L103)

 
### Architecture Support and Compatibility

 
 - **HookedTransformer**: Fully supported. Uses folded weights by default.
 - **TransformerBridge**: Requires `compatibility_mode` to be enabled via `model.enable_compatibility_mode()`. This ensures LayerNorm weights are folded into the unembedding, which is necessary for the projection in `logit_attrs` to be mathematically valid [transformer_lens/tools/analysis/direct_logit_attribution.py148-153](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/analysis/direct_logit_attribution.py#L148-L153)
 - **Hybrid Models**: Currently, DLA is restricted to standard Attention + MLP architectures. Models containing Mamba, SSM, or Mixer blocks are rejected to prevent incorrect decompositions [transformer_lens/tools/analysis/direct_logit_attribution.py155-162](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/analysis/direct_logit_attribution.py#L155-L162)

## Integration with Other Tools

 DLA is often the first step in a mechanistic interpretability pipeline, followed by:

 
 - **Activation Patching**: To verify if the identified components are causally necessary for the behavior [transformer_lens/patching.py46-47](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/patching.py#L46-L47)
 - **SVD Interpreter**: To analyze the weight matrices (OV, $W_{in}$, $W_{out}$) of the top-contributing layers or heads [transformer_lens/SVDInterpreter.py31-37](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/SVDInterpreter.py#L31-L37)
 - **Head Detection**: To classify the top heads (e.g., as Induction Heads or Previous Token Heads) [transformer_lens/head_detector.py34-44](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/head_detector.py#L34-L44)
