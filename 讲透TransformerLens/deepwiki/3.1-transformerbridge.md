  The `TransformerBridge` class is the central architectural component of TransformerLens v3.0. It serves as a structural and functional bridge between external model implementations (primarily from Hugging Face `transformers`) and the TransformerLens ecosystem. It allows users to perform mechanistic interpretability research—including activation patching and hook-based introspection—on a wide variety of model architectures without requiring a full manual rewrite of the model's logic into TransformerLens-native code.

 
## Core Purpose and Initialization

 `TransformerBridge` wraps an existing `nn.Module` and uses an `ArchitectureAdapter` to map the external model's internal components to a standardized TransformerLens-compatible structure [transformer_lens/model_bridge/bridge.py99-104](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/bridge.py#L99-L104)

 
### Bootstrapping Methods

 There are two primary ways to instantiate a `TransformerBridge`:

 
 - **`boot_transformers`**: The standard entry point for loading models from the Hugging Face Hub. It handles configuration mapping, model downloading, and adapter selection [transformer_lens/model_bridge/sources/transformers.py27-30](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/sources/transformers.py#L27-L30)
 - **`boot_native`**: Used for loading models already in the TransformerLens-native format or for custom research models [transformer_lens/model_bridge/supported_architectures/native.py1-5](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/supported_architectures/native.py#L1-L5)
 
 
### Component Mapping and Data Flow

 The bridge operates by replacing or wrapping original model submodules with "Generalized Components" (e.g., `AttentionBridge`, `MLPBridge`). This process, managed by `set_original_components`, ensures that activations flowing through the original model are captured by `HookPoint` objects [transformer_lens/model_bridge/bridge.py40-45](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/bridge.py#L40-L45)

## Key Implementation Details

 
### Forward Pass and Tokenization

 The `forward` pass of `TransformerBridge` is designed to be a drop-in replacement for standard model calls. It supports both raw tokens and string inputs. When strings are provided, the bridge handles tokenization internally, including complex logic for Beginning-of-Sequence (BOS) and End-of-Sequence (EOS) tokens [transformer_lens/model_bridge/bridge.py109-124](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/bridge.py#L109-L124)

 
 - **BOS Handling**: Controlled via `cfg.default_prepend_bos`. The bridge automatically reconciles this with the tokenizer's internal settings to prevent "double BOS" issues, especially when using chat templates [transformer_lens/model_bridge/bridge.py132-147](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/bridge.py#L132-L147)
 - **EOS Stripping**: For specific models (like OLMo), the bridge strips trailing EOS tokens during `to_tokens` to ensure the model receives a continuation sequence [transformer_lens/model_bridge/bridge.py120-124](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/bridge.py#L120-L124)
 
 
### Weight Property Accessors

 One of the most powerful features of the bridge is the ability to access weights using standardized TransformerLens naming (e.g., `W_Q`, `W_K`, `W_V`) even if the underlying model uses different names (e.g., `c_attn.weight`). This is achieved through `property_aliases` defined in the bridge components [transformer_lens/model_bridge/generalized_components/attention.py43-52](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/attention.py#L43-L52)

 
### Compatibility Mode

 To maintain backward compatibility with scripts written for `HookedTransformer`, the bridge implements a "Compatibility Mode". When enabled:

 
 - **Hook Aliases**: Canonical TransformerLens hook names (like `blocks.0.hook_q`) are registered as attributes pointing to the actual underlying `HookPoint` [transformer_lens/model_bridge/generalized_components/base.py81-93](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/base.py#L81-L93)
 - **Attribute Resolution**: The bridge uses `__getattr__` and an internal registry to resolve legacy names to their new locations in the bridged hierarchy [transformer_lens/model_bridge/generalized_components/base.py146-153](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/model_bridge/generalized_components/base.py#L146-L153)

## Architecture Support

 The bridge supports over 60 architectures via the `ArchitectureAdapter` system [transformer_lens/tools/model_registry/data/supported_models.json9-11](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/data/supported_models.json#L9-L11)

|---|---|---|
| Fused Weights | JointQKVAttentionBridge splits fused QKV matrices into individual virtual linear layers. | transformer_lens/model_bridge/generalized_components/joint_qkv_attention.py23-28 |
| Normalization | NormalizationBridge wraps various norm types (LayerNorm, RMSNorm). | transformer_lens/model_bridge/generalized_components/normalization.py1-5 |
| Blocks | BlockBridge manages the residual stream and wiring between Attention and MLP bridges. | transformer_lens/model_bridge/generalized_components/block.py1-10 |

### The Verification Pipeline

 Compatibility is ensured through a multi-phase verification process (P1-P8). This process checks for numerical parity between the original Hugging Face model and the bridged TransformerLens version [transformer_lens/tools/model_registry/data/supported_models.json19-25](https://github.com/TransformerLensOrg/TransformerLens/blob/4ba2187b/transformer_lens/tools/model_registry/data/supported_models.json#L19-L25)
