## 三、FP8/FP4 KV 格式：token-interleaved 细节与收益

动机（`docs/20260930-ascend-prefill-deep-dive.md:220`）：旧布局每 token 需两次 MTE2（data/scale 各一次）；interleave 后相邻一次取回。

- 旧（`ba89a34:csrc/kernels/kv_cache_format.h:4-7`）：页块内两数组——全部 token 数据在前，全部 scales 在后。
- 新（`csrc/cuda_kernels/kv_cache_format.h:5-6`）：每 token `[raw data, scales]` 相邻；NVIDIA 侧用 `KVCachePart<F,NUM_CTAS,CTA>` 适配 2-CTA TMA 视图（kv_cache_format.h:22-35）。

格式常量（kv_cache_format.h:8-20 与 `tests/quant.py:10-27` 互证）：

- **V41 FP8 = 528 B/token**：512 B e4m3 覆盖全部 512 维（含 64 维 RoPE，无 bf16 段）+ 16 B ue8m0 scale（每 32 维一个）。scale=amax/448 取 2 的幂上取整（quant.py:21）。
- **V41_FP4 = 288 B/token**：256 B e2m1（每 byte 2 值、偶下 nibble）+ 32 B e4m3 scale（每 16 维一个）。scale=amax/6 clamp 进 [2⁻⁹,448]；NaN 毒化整 tile；量化语义复刻 PTX `cvt.rn.satfinite.e2m1x2.f32`（quant.py:27-47）。
- **配对规则**（kv_cache_format.h:47-49）：extra_kv 同格式，或 fp8 主 cache + fp4 extra——**FP4 只作 `extra_k_cache` 合法**（README:143），对应 V4.1 双层 KV。
- **收益**：fp4 288B = fp8 的 54.5%，较 V3.2 旧格式 656B 省 56%。注意 V41 fp8 新旧同为 528B——**变的纯粹是排布，不是体积**。

## 四、V4.1 kernel 结构 vs 前代

三代谱系（docs/ 三篇 deep-dive + csrc 树）：

1. **2025.04 Hopper bf16 稠密解码（退役）**：splitKV + O_L/O_R 双 warpgroup 交错，绕 WGMMA 输出寄存器墙，H800 660 TFlops。
2. **2025.09 Hopper FP8 稀疏解码（退役）**：dequant-bound 分析（反量化 50 cyc vs MMA 34 cyc）+ crossover 借 DSMEM 互写共享，H800 410 TFlops。
3. **2026.09 V4.1 SM100（现行）**：
   - decode 主线 head64：`cuda_kernels/sm100/decode/sparse/head64/kernel.cuh`，4 instantiation（v41/v41fp4 × split/no_split）；head128 由 `fwd_for_small_topk/head128` 兼任（`decode/sparse/head128/README.md:1`）。
   - prefill：`fwd/head64|head128` 的 phase1_*_k512（k576 随 V3.2 删）+ small_topk 特化线。
   - fused norm-rope-attn-rope-cast：core_attn 12 instantiation + permute_q_b_proj/permute_wv_proj。五合一（Q-norm 仅 V4 用、Q-RoPE、attn、O-RoPE 共轭、cast FP8），B200 1460/950 TFlops，代价是 Q_b/Wv 权重预 permute（README:215-322）。
   - 维度：d_qk 从 576 变为 **d_qk=d_v=512 全量化**；`sm_scale_div_log2` 预计算（params.h:57）。
   - API 重排为 `csrc/api/*.cpp` 六文件；性能口径换 B200+CUDA 13.3：prefill 1350 / decode 1024 / fused 1460/950 / MHA fwd 1460/bwd 1000（README:41-71）。

## 五、Ascend 950 路线：异构并列的意义

**形态**：`csrc/ascend_kernels/prefill/sparse/` = 1701 行 `kernel_body.h` 单体模板 + config.h + 6 个 `.asc` 实例化（v41/v41fp4 × prefill/decode × sink/nosink）；单模板经 `Config.FWD_MODE` 覆盖 prefill 与 decode（kernel.h:8-14）。关键设计：**CUDA 与 Ascend 共享 `params.h` 与 `kv_cache_format.h` 两个协议文件**——`FLASH_MLA_GM`(`__gm__`)/`aclrtStream` 双平台化（params.h:27-37）。"一套算子协议、两套后端实现"，异构是同仓同构而非 fork。

**性能**：prefill 410 TFlops（95% 峰值）/ decode 360（83%）（README:53,63）。自洽：4096 FMA/cyc × 32 核 × 1.65GHz ≈ 432 TFlops（docs/20260930:85-92）。fused kernel 暂不支持 Ascend（README:43）。

**技术亮点**（docs/20260930）：64 q head/AI Core（M=64 已饱和 CUBE）；1C2V（1C1V 三否决：MTE2 在飞上限 16 / 反量化跟不上 / FixPipe 128B/cyc 推出 B_TOPK>73.14）；O 累加器放 UB（L0C 不能原地乘标量；拉回 CUBE 需关 HF32 只剩 256 FMA/cyc）；skip-scale（RESCALE_THRESHOLD=6，config.h:42）——max 漂移 ≤6 跳过 O 重标定，信号经 SS buffer 跨核传；gather2（burst_count=2 一次拷两稀疏 token）；ND2NZ 必须过 UB+SIMD VF（BIU 聚合要求 src/dst 双连续）；icache 32K/16K/8K 约束；L1 双 bank 对半放置。

**战略意义**：DeepSeek 官方算子库首次双后端，与 DeepSeek-V4.1-Flash 发布联动（README:7）；此前六家移植全是第三方分叉，Ascend 第一次进上游主干。结合 fused kernel 依赖 TileKernels/DeepGEMM（README:39），DeepSeek 系算子正走"协议层共享+后端树并列"的多后端化路线，国产算力从"社区适配"升格"官方一等公民"。
