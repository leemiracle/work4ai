  This document provides detailed technical documentation of the SM90 (Hopper architecture) CUDA kernel implementations in FlashMLA. These kernels target NVIDIA H800 and H100 GPUs and include dense decoding, FP8-quantized sparse decoding, and sparse prefill operations.

 For SM100 (Blackwell) kernel implementations, see [SM100 Kernels (Blackwell)](https://deepwiki.com/deepseek-ai/FlashMLA/5.2-sm100-kernels-(blackwell)). For high-level architecture information, see [System Architecture Overview](https://deepwiki.com/deepseek-ai/FlashMLA/4.1-system-architecture-overview). For performance optimization techniques shared across architectures, see [Kernel Performance Optimizations](https://deepwiki.com/deepseek-ai/FlashMLA/4.4-kernel-performance-optimizations).

 **Scope**: This document covers the implementation details, kernel variants, memory access patterns, and optimization techniques specific to SM90 kernels. It does not cover the Python API layer (see [Python API](https://deepwiki.com/deepseek-ai/FlashMLA/3.1-python-api)) or build configuration (see [Building from Source](https://deepwiki.com/deepseek-ai/FlashMLA/2.1-building-from-source)).

 
## Overview of SM90 Kernel Variants

 The SM90 kernel suite consists of 14 source files organized into three primary categories: dense decode, sparse decode with FP8 KV cache, and sparse prefill. Each category addresses different operational requirements and memory access patterns characteristic of the Multi-head Latent Attention (MLA) architecture.

## Dense Decode Kernels

 Dense decode kernels implement standard Multi-Query Attention (MQA) for the token generation phase with full context attention. These kernels operate on paged KV cache stored in bfloat16 or float16 precision without quantization.

## Sparse Decode FP8 Kernels

 Sparse decode FP8 kernels are designed for DeepSeek Sparse Attention (DSA) with FP8-quantized KV cache. These kernels address the memory capacity challenge by using fine-grained tile-level quantization.

 
### FP8 KV Cache Format and Dequantization

 Each token in the FP8 KV cache occupies exactly **656 bytes** [csrc/sm90/decode/sparse_fp8/components/config.h18](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm90/decode/sparse_fp8/components/config.h#L18-L18)

 
| Component | Size | Type | Description |
|---|---|---|---|
| Quantized NoPE | 512 bytes | float8_e4m3 | First 512 elements, tile-level quantization |
| Scale Factors | 16 bytes | float32 (×4) | One scale per 128-element tile |
| RoPE Part | 128 bytes | bfloat16 (×64) | Last 64 elements, unquantized for precision |

 The `cvt_fp8x8_bf16x8` function handles the conversion from FP8 to BF16 using a `scale_bf162` multiplier [csrc/sm90/decode/sparse_fp8/components/dequant.h21-34](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm90/decode/sparse_fp8/components/dequant.h#L21-L34)
