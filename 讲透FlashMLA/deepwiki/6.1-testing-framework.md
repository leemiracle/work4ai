## Purpose and Scope

 The testing framework validates FlashMLA's correctness and performance across different attention operation types. The test suite comprises specialized test files that verify decoding, prefill, and SM100-specific operations against PyTorch reference implementations. The framework systematically tests parameter combinations covering production workloads including variable-length sequences, FP8 quantization, and sparse attention patterns.

 For performance comparison tools and benchmarking against other implementations, see [Performance Benchmarks](https://deepwiki.com/deepseek-ai/FlashMLA/6.2-performance-benchmarks). For details about the specific CUDA kernels being tested, see [SM90 Kernels (Hopper)](https://deepwiki.com/deepseek-ai/FlashMLA/5.1-sm90-kernels-(hopper)) and [SM100 Kernels (Blackwell)](https://deepwiki.com/deepseek-ai/FlashMLA/5.2-sm100-kernels-(blackwell)).

## Correctness Validation Methodology

 
### Statistical Error Measurement

 The framework uses the `check_is_allclose()` function from `kernelkit` (imported via `lib.py`) to validate numerical accuracy with multiple tolerance criteria:

 
| Metric | Purpose | Typical Thresholds |
|---|---|---|
| Absolute Tolerance | Maximum pointwise error | 1e-3 (output)1e-6 (lse) |
| Relative Tolerance | Error relative to magnitude | 8.01/128 (output)2.01/65536 (lse) |
| Cosine Difference | Overall correlation | 7e-6 (output) |

 **Validation Examples:**

 
 - Output tensor validation: `check_is_allclose("out", out_flash.float(), out_torch, abs_tol=1e-3, rel_tol=8.01 / 128, cos_diff_tol=7e-6)` [tests/test_fmha_sm100.py125](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/test_fmha_sm100.py#L125-L125)
 - LSE validation: `check_is_allclose("lse", lse_flash.float(), lse_torch, abs_tol=1e-6, rel_tol=2.01 / 65536)` [tests/test_fmha_sm100.py126](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/test_fmha_sm100.py#L126-L126)
 - Gradient validation: `check_is_allclose("dq", q1.grad, q2.grad, abs_tol=1e-3, rel_tol=8.01 / 128, cos_diff_tol=7e-6)` [tests/test_fmha_sm100.py130](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/test_fmha_sm100.py#L130-L130)

## FP8 Quantization Test Utilities

 The `quant.py` utility provides logic to simulate the DeepSeek FP8 KV cache layout used in sparse attention kernels.

 
### KV Cache Layouts

 The `FP8KVCacheLayout` enum defines metadata for different model configurations:

 
 - **V32_FP8Sparse**: Used for V32 models (d=576, nope=512, rope=64) [tests/quant.py13](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/quant.py#L13-L13)
 - **MODEL1_FP8Sparse**: Used for Model1 (d=512, nope=448, rope=64) [tests/quant.py14](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/quant.py#L14-L14)
 
 
### Quantization Logic

 The `quantize_k_cache` function transforms a standard BF16 tensor into the packed FP8 format expected by the kernels:

 
 - **Tile Partitioning**: Splits the NoPE (non-RoPE) part into tiles (e.g., size 128 for V32) [tests/quant.py13](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/quant.py#L13-L13)
 - **Scale Calculation**: Computes `max(abs(tile)) / 448.0` for each tile, then casts to `ue8m0` format using `_cast_scale_inv_to_ue8m0` [tests/quant.py44-45](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/quant.py#L44-L45)
 - **Quantization**: Divides the BF16 tile by the scale and casts to `torch.float8_e4m3fn` [tests/quant.py49](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/quant.py#L49-L49)
 - **RoPE Preservation**: Copies the RoPE portion without quantization [tests/quant.py41](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/quant.py#L41-L41)
 
 Sources: [tests/quant.py6-15](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/quant.py#L6-L15) [tests/quant.py20-53](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/quant.py#L20-L53)

 
### Dequantization for Reference

 To ensure a fair comparison, the reference implementation often uses `dequantize_k_cache`. This function reconstructs the BF16 values from the FP8 cache and scales, allowing the reference to account for quantization noise [tests/quant.py81-123](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/quant.py#L81-L123)

 
## Test Parameter Generation

 The framework uses `lib.py` to generate complex test cases, specifically for sparse attention scenarios.

 
### Sparse Index Resolution

 The `abs_indices2indices_in_kvcache` function is a critical validation utility. It converts logical "absolute" indices (0 to sequence_length-1) into the physical indices required by the kernel's paged memory system (block index + offset within block) [tests/lib.py126-133](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/lib.py#L126-L133)

 
### Randomized Sequence Lengths

 For variable-length (`is_varlen`) testing, sequence lengths are generated using a normal distribution:

 
 - `seqlens_q`: `max(random.normalvariate(mean_sq, mean_sq / 2), 1)` [tests/test_fmha_sm100.py60](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/test_fmha_sm100.py#L60-L60)
 - `seqlens_k`: `max(random.normalvariate(mean_sk, mean_sk / 2), seqlens_q[i].item())` [tests/test_fmha_sm100.py62](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/test_fmha_sm100.py#L62-L62)

## Performance Measurement

 Performance is measured using `triton.testing.do_bench`. The framework calculates TFLOP/s based on the theoretical attention compute:

 
 - **Forward**: `total_attn_compute * h * 2 * (d + dv)` [tests/test_fmha_sm100.py153](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/tests/test_fmha_sm100.py#L153-L153)
