## Purpose and Scope

 This page documents the CUDA kernel implementations for NVIDIA SM100 (Blackwell B200) architecture. SM100 kernels provide highly optimized attention operations that leverage Blackwell-specific features including Tensor Memory (TMEM), enhanced TMA operations, and improved warp specialization capabilities.

 The implementation covers dense prefill FMHA (forward and backward passes) using CUTLASS, sparse prefill for DeepSeek Sparse Attention (DSA), and sparse decode optimizations for FP8 MLA.

## SM100 Architecture Requirements

 SM100 kernels require:

 
 - **GPU Architecture:** NVIDIA Blackwell B200 (compute capability 10.0).
 - **CUDA Version:** 12.8 or later (standard requirement for Blackwell support in FlashMLA).
 - **Compilation Flag:** Kernels are conditionally compiled and dispatched based on architecture detection.
 
 The implementation checks architecture at runtime and dispatches to SM100 kernels only when running on compatible hardware.

## Sparse FP8 Decoding Kernel

 The sparse FP8 decoding kernel (`flash_fwd_splitkv_mla_fp8_sparse_kernel`) implements token-by-token generation with FP8 quantized KV cache and sparse attention patterns.

 
### Kernel Configuration

 
| Parameter | Value | Description |
|---|---|---|
| Block dimensions | (B_H, B_TOPK) | (64, 64) tile size |
| Threads per block | 384 | 3 warpgroups × 128 threads |
| Working threads | 288 | Threads actively computing |
| Head dimension (K) | 576 | Query/Key dimension |
| Head dimension (V) | 512 | Value dimension |
| Buffer count | 2 | Double buffering |

### FP8 Dequantization

 The producer warpgroup performs on-the-fly FP8 dequantization when loading K tokens. The utility `fp8x2_to_bf16x2_with_scale` handles the conversion using a provided scale factor.

 **Memory Layout per Token:**

 
 - First 512 bytes: FP8 values for V dimension.
 - Next 16 bytes (4×float): Scale factors for 4×128 value groups.
 - Remaining: bf16 RoPE features.

## Dense Prefill Kernels

 The dense prefill kernels provide forward and backward passes for standard and MLA attention using specialized CUTLASS collectives.

 
### Forward Pass Implementation

 The forward pass is managed by `FwdRunner` which dispatches between standard FMHA and MLA configurations.

 **Key Components:**

 
 - **Mainloop:** `Sm100FmhaFwdMainloopTmaWarpspecialized` or `Sm100MlaFwdMainloopTmaWarpspecialized`.
 - **Epilogue:** `Sm100FmhaFwdEpilogueTmaWarpspecialized`.
 - **Tile Scheduler:** Supports `PersistentTileScheduler` and `CausalPersistentTileScheduler`.
 
 **Tile Shapes:**

 
 - **MLA:** `Shape<_256, _128, HeadDim>` where `HeadDim` is `Shape<_128, _64>`.
 - **FMHA:** `Shape<_256, _128, _128>`.
 
 **Sources:** [csrc/sm100/prefill/dense/fmha_cutlass_fwd_sm100.cuh45-121](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm100/prefill/dense/fmha_cutlass_fwd_sm100.cuh#L45-L121) [csrc/sm100/prefill/dense/fmha_cutlass_fwd_sm100.cu31-83](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm100/prefill/dense/fmha_cutlass_fwd_sm100.cu#L31-L83)

 
### Backward Pass Implementation

 The backward pass uses `BwdRunner` to execute the gradient computation. It supports both standard MHA and MLA via the `kIsMla` template parameter.

 **Kernel Dispatch Logic:**

 
 - **Head Dim QK 192, VO 128:** Dispatched as MLA (`true_type`).
 - **Head Dim QK 128, VO 128:** Dispatched as standard FMHA (`false_type`).
 
 **Tile Shapes for Bwd:**

 
 - **MLA:** `Shape<_64, _128, _192, _128>` (Q, K, D_QK, D_VO).
 - **FMHA:** `Shape<_128, _128, _128, _128>`.
 
 **Sources:** [csrc/sm100/prefill/dense/fmha_cutlass_bwd_sm100.cuh62-81](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm100/prefill/dense/fmha_cutlass_bwd_sm100.cuh#L62-L81) [csrc/sm100/prefill/dense/fmha_cutlass_bwd_sm100.cu11-26](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm100/prefill/dense/fmha_cutlass_bwd_sm100.cu#L11-L26) [csrc/sm100/prefill/dense/fmha_cutlass_bwd_sm100.cu65-78](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm100/prefill/dense/fmha_cutlass_bwd_sm100.cu#L65-L78)

## Key SM100 Optimizations

 
### TMEM and Memory Hierarchy

 SM100 kernels utilize a multi-tier memory hierarchy: Global Memory → Shared Memory → TMEM → Registers. TMEM is used for high-bandwidth intermediate storage, such as attention score accumulators.

 **Sources:** [csrc/sm100/decode/sparse_fp8/splitkv_mla.cu40-43](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm100/decode/sparse_fp8/splitkv_mla.cu#L40-L43) [csrc/sm100/decode/sparse_fp8/splitkv_mla.cu152-154](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm100/decode/sparse_fp8/splitkv_mla.cu#L152-L154)

 
### TMA Pipelining

 The kernels use Tensor Memory Accelerator (TMA) for asynchronous data movement. In the dense prefill passes, TMA is integrated with the GEMM mainloop to overlap data loading with computation.

 **Sources:** [csrc/sm100/prefill/dense/fmha_cutlass_fwd_sm100.cuh4-6](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm100/prefill/dense/fmha_cutlass_fwd_sm100.cuh#L4-L6) [csrc/sm100/prefill/dense/fmha_cutlass_fwd_sm100.cuh101-106](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm100/prefill/dense/fmha_cutlass_fwd_sm100.cuh#L101-L106)

 
### Warp Specialization

 Kernels are organized into Producer and Consumer warpgroups. For example, in the decode kernel, one warpgroup handles FP8 dequantization and loading while others perform the UTCMMA operations and softmax scaling.

 **Sources:** [csrc/sm100/decode/sparse_fp8/splitkv_mla.cu180-259](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm100/decode/sparse_fp8/splitkv_mla.cu#L180-L259) [csrc/sm100/decode/sparse_fp8/splitkv_mla.cu468-535](https://github.com/deepseek-ai/FlashMLA/blob/15f13e50/csrc/sm100/decode/sparse_fp8/splitkv_mla.cu#L468-L535)
