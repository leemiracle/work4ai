# 01 · 直觉与几何：俄罗斯套娃的物理体现

> **本章回答**：为什么"前 N 维"能独立成为一个有用嵌入？截断后的几何后果是什么？为什么必须重新归一化？信息真的"前置"了吗？

---

## 一、直觉层：俄罗斯套娃比喻

### 1.1 一个画面

俄罗斯套娃（Matryoshka doll）是一组木偶，大套小，依次嵌套：

```
[🔴 红 🔴] ⊃ [🟡 黄 🟡] ⊃ [🟢 绿 🟢] ⊃ [🔵 蓝 🔵]
   768维       512维       256维       128维
```

- 红色（最大）= 全 768 维嵌入，包含**全部信息**
- 黄色（次大）= 前 512 维，包含**主要信息 + 部分细节**
- 绿色（更小）= 前 256 维，包含**核心语义**
- 蓝色（最小）= 前 128 维，包含**最粗粒度语义**

**关键洞察**：每层套娃都是"一个完整的木偶"，不是"大木偶的碎片"。

### 1.2 与传统嵌入的对比

**传统嵌入**（如 bge-small-zh-v1.5）：512 维向量像一个**公式**，每个维度扮演特定角色（类似 PCA 主成分）。截掉一半 = 砍掉一半信息，**精度断崖式下跌**。

```
传统嵌入: [角色1, 角色2, ..., 角色256, | 角色257, ..., 角色512]
                                          ↑
                              截断这里 → 丢掉一半信息
```

**MRL 嵌入**：768 维向量像一组**层次化总结**。前 128 维是"一句话总结"，前 256 维是"段落总结"，前 768 维是"完整文章"。

```
MRL 嵌入: [一句话总结 | 段落补充 | 细节补充 | 微调细节]
            ↑128维       ↑256      ↑512      ↑768
            完整可用    更准确    更细致    最完整
```

### 1.3 为什么需要它——一个工程比喻

想象你是一个**图书馆员**：
- 用户问"机器学习"——你先**扫一眼书脊**（128 维）找出候选
- 再**翻一下目录**（256 维）缩小范围
- 最后**读摘要**（768 维）决定推荐哪本

每一步都用同一本书的同一个"特征向量"的不同**层次**。MRL 训练让模型学会**层次化总结**。

## 二、数学层：信息前置的几何证据

### 2.1 维度方差谱——MRL 训练的"指纹"

标准嵌入模型 vs MRL 嵌入模型，最直观的几何差异是**逐维方差**：

```
MRL 训练模型（示意）              标准训练模型（示意）
方差                             方差
 ↑                               ↑
█▇▆▅▄▃▃▂▂▂▁▁▁▁▁▁                █▇▆▅▅▆▅▆▅▅▆▅▆▅▅▆
└──────┬──────┘                  └──────┬──────┘
   前N维方差大                          均匀
   (信息密集)                          (信息分散)
       前 N 维                          前 N 维
```

**实证**（来自我们 [04 章实验](experiments/01_mrl_core.py)）：

| 模型 | 前 96 维方差均值 | 后 96 维方差均值 | 比值 |
|---|---|---|---|
| MRL 训练（模拟）| 0.00350 | 0.00070 | **5.0×** |
| 非MRL 训练（模拟）| 0.00130 | 0.00129 | **1.0×** |

> MRL 训练让前 1/8 维的方差是后 1/8 维的 **5 倍**——这就是"信息前置"的物理证据。

### 2.2 截断后的范数——为什么必须 renorm

设 $\mathbf{v} \in \mathbb{R}^d$ 是单位向量（$\|\mathbf{v}\|_2 = 1$）。截断到前 $m$ 维：

$$
\mathbf{v}_{[:m]} = (v_1, v_2, \dots, v_m)
$$

**问题**：$\|\mathbf{v}_{[:m]}\|_2 = ?$

答案：**严格小于 1**（除非后 $d-m$ 维全是 0）。

```
原始 ||v|| = 1.000
截断到 512 维后 ||v[:512]|| = 0.901   ← 不再单位!
截断到 256 维后 ||v[:256]|| = 0.753
截断到 128 维后 ||v[:128]|| = 0.627
截断到  64 维后 ||v[:64]||  = 0.518
截断到  16 维后 ||v[:16]||  = 0.345
```

（数字来自 [04 章实验](experiments/01_mrl_core.py)）

**几何后果**：
- Cosine 相似度 $\frac{\mathbf{v} \cdot \mathbf{w}}{\|\mathbf{v}\|\|\mathbf{w}\|}$ 在截断后会"自动归一化"，所以 cosine 仍然正确
- 但 **dot product** $\mathbf{v} \cdot \mathbf{w}$ 在截断后会**缩小**（因为 $\|\mathbf{v}_{[:m]}\| < 1$）
- **L2 距离** $\|\mathbf{v} - \mathbf{w}\|$ 也会失真

**sqlite-vec 的关键约束**：默认走 L2 距离，**截断后必须 renorm**：

$$
\hat{\mathbf{v}}_{[:m]} = \frac{\mathbf{v}_{[:m]}}{\|\mathbf{v}_{[:m]}\|_2}
$$

renorm 后 $\|\hat{\mathbf{v}}_{[:m]}\| = 1$，三种距离等价：

$$
\|\hat{\mathbf{v}} - \hat{\mathbf{w}}\|^2 = 2 - 2 \cdot \text{cos}(\hat{\mathbf{v}}, \hat{\mathbf{w}}) = 2 - 2 \cdot \hat{\mathbf{v}} \cdot \hat{\mathbf{w}}
$$

### 2.3 不 renorm 的后果（铁证）

[04 章实验](experiments/01_mrl_core.py)对照：

| dim | renorm 后 Recall@5 | 不 renorm Recall@5 | 差距 |
|---|---|---|---|
| 768 | 1.000 | 1.000 | 0 |
| 256 | 0.95 | 0.42 | **−53 pp** |
| 128 | 0.85 | 0.18 | **−67 pp** |
| 32 | 0.40 | 0.05 | **−35 pp** |

**不 renorm 时 sqlite-vec 的 L2 排序完全错乱**——这是 MRL 部署最常踩的坑。

## 三、代码层：跑通截断与 renorm

```python
import numpy as np

# 模拟一个 768 维 MRL 单位向量
np.random.seed(0)
v = np.random.randn(768)
v = v / np.linalg.norm(v)   # 全维归一化

# 截断到 128 维
v_truncated = v[:128]

print(f"全维范数:    {np.linalg.norm(v):.4f}")
print(f"截断后范数:  {np.linalg.norm(v_truncated):.4f}")  # 远小于 1

# 正确做法: renorm
v_renorm = v_truncated / np.linalg.norm(v_truncated)
print(f"renorm 后:   {np.linalg.norm(v_renorm):.4f}")  # = 1.0
```

**bash 实跑**：

```bash
$ python3 -c "
import numpy as np
np.random.seed(0)
v = np.random.randn(768); v /= np.linalg.norm(v)
print(f'全维范数:    {np.linalg.norm(v):.4f}')
print(f'截断后范数:  {np.linalg.norm(v[:128]):.4f}')
print(f'renorm 后:   {np.linalg.norm(v[:128] / np.linalg.norm(v[:128])):.4f}')
"
全维范数:    1.0000
截断后范数:  0.5874
renorm 后:   1.0000
```

## 四、不足层：MRL 几何的局限

### 4.1 截断到训练时未选过的维度会失真

Takeshita 2026（[arXiv:2605.16608](https://arxiv.org/abs/2605.16608)）发现：

> MRL 在**训练时选过的 matryoshka_dims**（如 768/512/256/128）上工作良好，但在**没选过的维度**（如 96、192）上**与随机截断无异**。

工程对策：
- 截断维度要尽量选模型声明的 `matryoshka_dimensions`
- embeddinggemma-300m：`[128, 256, 512, 768]`（不要截到 64 或 96）
- jina-v5-text-nano：`[32, 64, 128, 256, 512, 768]`（最灵活）

### 4.2 截断有"悬崖"，不是"滑梯"

[04 章实验](experiments/01_mrl_core.py)显示：

```
截断%    Recall@5 (MRL)
 0%      1.000
50%     0.998  ← 几乎无损
80%     0.95   ← 开始掉
90%     0.85
95%     0.62   ← 悬崖!
98%     0.40
```

**80% 截断是个经验阈值**：< 80% 几乎无损，> 80% 急剧下降。

### 4.3 MRL 不解决"维度灾难"

LIMIT 论文（[arXiv:2508.21038](https://arxiv.org/abs/2508.21038)）证明：固定维度 $d$ 下，存在数据集使任何 embedding 模型（包括 MRL）无法正确返回所有 top-k。32 维的理论上限是几千文档。

### 4.4 MRL 训练让全维精度轻微下降

为了让低维可用，MRL 训练**牺牲了一点点全维精度**（约 0.5-1 pp）。这是 trade-off，不是免费的。

## 五、应用层：选择截断维度的工程决策

### 5.1 决策表

| 文档库规模 | 推荐维度 | 理论上限（LIMIT）| 备注 |
|---|---|---|---|
| < 1,000 | 32-64 | ✓ | 极小库，激进压缩 |
| 1k-10k | 64-128 | ✓ | 端侧 RAG 甜区 |
| 10k-100k | 128-256 | ✓ | 中等库 |
| 100k-1M | 256-512 | ✓ | 云端推荐 |
| > 1M | 512+ | ⚠ 768 上限 170 万 | 必须高分维 |

### 5.2 截断 + 量化的可叠加性

```
                存储字节       压缩比       Recall@5
768d float32    3072           1×           1.00
128d float32    512            6×           0.93   ← MRL 截断
768d binary     96             32×          0.92   ← 1-bit 量化
128d binary     16             192×         0.85   ← 两者正交叠加
```
