## Purpose and Scope

 This page explains how Xinference handles two advanced LLM capabilities: **reasoning content parsing** and **tool calling (function calling)**. Reasoning content refers to models that expose their internal "thinking" process as part of the output (e.g., DeepSeek-R1, QwQ-32B). Tool calling enables models to invoke external functions or APIs as part of their responses.

 For general information about LLM model execution and backends, see page [LLM Serving System](https://deepwiki.com/xorbitsai/inference/3-llm-serving-system). For chat template formatting, see page [Chat Templates and Prompt Formatting](https://deepwiki.com/xorbitsai/inference/8.3-chat-templates-and-prompt-formatting).

## Reasoning Content

 
### What is Reasoning Content

 Reasoning models like DeepSeek-R1, QwQ-32B, and marco-o1 generate their internal thinking process before producing the final answer. This thinking process is typically wrapped in special tags (typically ``) and is extracted and presented separately from the final answer.

 **Example Model Output:**

 
```
The answer is Z.
```

 This gets parsed into:

 
 - `reasoning_content`: "Let me analyze this problem step by step..."
 - `content`: "The answer is Z."
 
 
### Supported Reasoning Models

 Models with the `"reasoning"` ability in their model definition include:

 
| Model Family | Model Name | Reasoning Tags | Context Length |
|---|---|---|---|
| DeepSeek-R1 | deepseek-r1 | <think> | 163,840 |
| QwQ | QwQ-32B | <think> | 32,768 |
| DeepSeek Prover | deepseek-prover-v2 | <think> | 163,840 |
| Baichuan | Baichuan-M2 | Model-specific | 131,072 |

### Reasoning Content Extraction

 
#### Streaming Extraction

 Streaming extraction is complex because tags may be split across chunks. The `extract_reasoning_content_streaming` method tracks state across chunks by comparing `previous_text` and `delta_text`.

 **State Transitions:**

 
 - **Start Tag Detection**: If `reasoning_start_tag` is found in `delta_text` or split between `previous_text` and `delta_text` [xinference/model/llm/reasoning_parser.py83-107](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/reasoning_parser.py#L83-L107)
 - **In-Reasoning**: While inside the thinking tags, content is assigned to the `reasoning_content` field of `ChatCompletionChunkDelta` [xinference/model/llm/reasoning_parser.py78-82](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/reasoning_parser.py#L78-L82)
 - **End Tag Detection**: If `reasoning_end_tag` is found, the parser splits the chunk into `reasoning_content` (before tag) and `content` (after tag) [xinference/model/llm/reasoning_parser.py58-69](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/reasoning_parser.py#L58-L69)
 
 **Sources:** [xinference/model/llm/reasoning_parser.py38-146](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/reasoning_parser.py#L38-L146)

 
### Hybrid Models and enable_thinking

 Some models support both thinking mode and non-thinking mode. The `enable_thinking` flag in `ReasoningParser` controls whether extraction occurs. This can be set via `model_config` [xinference/model/llm/vllm/core.py109-110](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L109-L110)

## Tool Calling

 
### What is Tool Calling

 Tool calling enables LLMs to invoke external functions. The model generates structured content specifying which function to call. Xinference parses these tool calls and formats them according to the OpenAI API specification.

 
### Tool Call Model Families

 Xinference categorizes tool-calling models into specific families in `xinference/model/llm/utils.py`.

 
| Family | Global Set Variable | Supported Symbols |
|---|---|---|
| Qwen | QWEN_TOOL_CALL_FAMILY | <tool_call>, </tool_call> |
| GLM4 | GLM4_TOOL_CALL_FAMILY | JSON-based |
| DeepSeek | DEEPSEEK_TOOL_CALL_FAMILY | JSON-based |
| Llama3 | LLAMA3_TOOL_CALL_FAMILY | Python-style dict |

 **Sources:** [xinference/model/llm/utils.py135-143](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/utils.py#L135-L143)

 
### Normalizing Tool Call Arguments

 Different models expect tool call arguments in different formats (e.g., JSON strings vs. dictionaries). Xinference provides `_normalize_tool_call_arguments_to_dict` in `ChatModelMixin` to ensure compatibility with Jinja2 templates like those used for Qwen models [xinference/model/llm/utils.py192-210](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/utils.py#L192-L210)

 
### Chat Template Integration

 Tool calls are often integrated into the model's prompt via the `chat_template`. For example, `gorilla-openfunctions-v2` uses a specific template to formulate executable API calls [xinference/model/llm/llm_family.json140](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.json#L140-L140)

## Backend Support

 
### vLLM Backend

 vLLM supports reasoning content extraction by configuring `reasoning_content: bool` in `VLLMModelConfig` [xinference/model/llm/vllm/core.py109](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L109-L109) When a `VLLMChatModel` is initialized, it sets up the `reasoning_parser` and `tool_parser` based on the model family [xinference/model/llm/vllm/tests/test_core_chat_model.py41-51](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/tests/test_core_chat_model.py#L41-L51)

 
### SGLang Backend

 SGLang also supports `reasoning_content` in its `SGLANGModelConfig` [xinference/model/llm/sglang/core.py65](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/sglang/core.py#L65-L65) During the `load()` phase, it calls `prepare_parse_reasoning_content` and `prepare_parse_tool_calls` [xinference/model/llm/sglang/core.py198-201](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/sglang/core.py#L198-L201)

 
### Transformers Backend

 The PyTorch (Transformers) backend supports reasoning via `PytorchModelConfig` [xinference/model/llm/transformers/core.py135](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/transformers/core.py#L135-L135) Specific models like `ChatglmPytorchChatModel` implement specialized `_handle_tools` methods to convert OpenAI tool formats to model-specific formats (e.g., GLM-4's `observation` role) [xinference/model/llm/transformers/chatglm.py107-123](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/transformers/chatglm.py#L107-L123)
