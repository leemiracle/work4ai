  This document describes the command-line interface (CLI) tools for deploying, managing, and interacting with Xinference. The CLI provides four main commands for different deployment scenarios: local single-process mode, distributed supervisor-worker mode, and a unified command interface. For information about programmatic interaction with Xinference, see [Python Client Library](https://deepwiki.com/xorbitsai/inference/6.1-python-client-library). For web-based management, see [Web UI](https://deepwiki.com/xorbitsai/inference/6.3-web-ui).

 
## Overview

 Xinference provides four CLI entry points defined in [xinference/deploy/cmdline.py126-164](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/cmdline.py#L126-L164):

 
| Command | Purpose | Deployment Mode |
|---|---|---|
| xinference | Unified CLI interface for model management and operations | Client-side tool |
| xinference-local | Start Xinference in local single-process mode | Local deployment |
| xinference-supervisor | Start the supervisor node in distributed mode | Distributed orchestration |
| xinference-worker | Start a worker node that connects to supervisor | Distributed execution |

 These commands enable different deployment architectures described in [System Architecture](https://deepwiki.com/xorbitsai/inference/2-system-architecture).

 Sources: [xinference/deploy/cmdline.py126-164](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/cmdline.py#L126-L164)

## xinference-local

 The `xinference-local` command starts Xinference in local mode, where both the supervisor and worker components run in a single process. This is the recommended mode for development, testing, and single-machine deployments. The `local` function in [xinference/deploy/cmdline.py214-229](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/cmdline.py#L214-L229) is the entry point for this command.

 The `xinference-local` command accepts several options to configure the local cluster:

## xinference-supervisor

 The `xinference-supervisor` command starts only the supervisor component, which coordinates multiple worker nodes in distributed deployments. The supervisor handles model registry, worker management, and request routing but does not execute models itself. The `supervisor` function in [xinference/deploy/cmdline.py233-259](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/cmdline.py#L233-L259) is the entry point.

### Supervisor Responsibilities

 The supervisor node performs the following functions as described in [Supervisor and Worker System](https://deepwiki.com/xorbitsai/inference/2.1-supervisor-and-worker-system):

 
 - **Model Registry**: Maintains the catalog of available models. The `_model_uid_to_replica_info` dictionary in `SupervisorActor` stores information about launched models [xinference/core/supervisor.py143](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py#L143-L143)
 - **Worker Coordination**: Tracks connected workers in `_worker_address_to_worker` [xinference/core/supervisor.py130](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py#L130-L130)
 - **Load Balancing**: Selects optimal workers for model launching based on resources, implemented by `IdleFirstLaunchStrategy` [xinference/core/supervisor.py61](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py#L61-L61)
 - **Health Monitoring**: Tracks worker health via `_worker_status` [xinference/core/supervisor.py131](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py#L131-L131) and `StatusGuardActor` [xinference/core/worker.py93](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py#L93-L93)
 - **Event Collection**: Aggregates events from workers via `EventCollectorActor` [xinference/core/worker.py84](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py#L84-L84)

## xinference (Unified CLI)

 The `xinference` command provides a unified interface for model management operations. The `cli` function in [xinference/deploy/cmdline.py126-164](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/cmdline.py#L126-L164) is the main entry point. This command typically offers client-side functionality for interacting with running Xinference instances.

 
### Typical Operations

 The `xinference` command supports various subcommands for model management, which are implemented by interacting with the RESTful API via `RESTfulClient` [xinference/client/restful/restful_client.py28](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/client/restful/restful_client.py#L28-L28)

 
 - **Listing available models**: `xinference list`
 - **Launching model instances**: `xinference launch`
 - **Terminating models**: `xinference terminate`
 - **Querying model status**: `xinference describe`
 - **Managing custom model registrations**: `xinference register`
 
 These operations are handled by the `RESTfulClient` class, which makes HTTP requests to the Xinference endpoint. For example, `client.list_models()` [xinference/client/restful/restful_client.py300](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/client/restful/restful_client.py#L300-L300) corresponds to the `GET /v1/models` API endpoint.

## Configuration Priority

 CLI configuration is resolved in the following priority order (highest to lowest):

 
 - **Command-line arguments**: Explicitly passed flags like `-H`, `-p` take precedence over environment variables and defaults.
 - **Environment variables**: Variables like `XINFERENCE_HOME` [xinference/constants.py22](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/constants.py#L22-L22) override default values.
 - **Default values**: Built-in defaults in the codebase, such as `XINFERENCE_DEFAULT_LOCAL_HOST` [xinference/constants.py36](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/constants.py#L36-L36) are used if no other configuration is provided.
 
 This allows flexible configuration for different deployment scenarios while maintaining sensible defaults.

## Related Components

 The CLI commands integrate with other Xinference components:

 
 - **RESTful API**: CLI tools expose the API server described in [RESTful API](https://deepwiki.com/xorbitsai/inference/5-restful-api), implemented by `RESTfulAPI` [xinference/api/restful_api.py160](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/restful_api.py#L160-L160)
 - **Python Client**: The CLI can be supplemented with the [Python Client Library](https://deepwiki.com/xorbitsai/inference/6.1-python-client-library), which uses `RESTfulClient` [xinference/client/restful/restful_client.py28](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/client/restful/restful_client.py#L28-L28)
 - **Web UI**: After starting via CLI, access the [Web UI](https://deepwiki.com/xorbitsai/inference/6.3-web-ui) at the configured host/port. The Web UI is mounted via `mount_frontend` [xinference/api/restful_api.py78](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/restful_api.py#L78-L78)
 - **Model Registry**: CLI manages models from [Model Registry and Cache Management](https://deepwiki.com/xorbitsai/inference/2.4-model-registry-and-cache-management). Model information is stored and retrieved by the `SupervisorActor` [xinference/core/supervisor.py143](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py#L143-L143)
 
 The CLI serves as the entry point to the distributed actor-based architecture described in [System Architecture](https://deepwiki.com/xorbitsai/inference/2-system-architecture).
