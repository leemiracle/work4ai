## Purpose and Scope

 This document describes the RESTful API endpoints used to manage model instances in Xinference. These endpoints handle the complete lifecycle of models: launching, listing, inspecting, and terminating model instances. For information about inference operations (chat, completions, embeddings), see [Inference Endpoints](https://deepwiki.com/xorbitsai/inference/5.2-inference-endpoints). For custom model registration, see [Model Registration Endpoints](https://deepwiki.com/xorbitsai/inference/5.3-model-registration-endpoints).

 The model management endpoints interact with the supervisor-worker architecture to orchestrate model deployment across distributed resources. All endpoints are prefixed with `/v1/models` and follow OpenAI-compatible conventions where applicable.

 
## Endpoint Overview

 The following table summarizes all model management endpoints:

 
| Method | Endpoint | Purpose | Authentication Scope |
|---|---|---|---|
| POST | /v1/models | Launch a new model instance | models:start |
| POST | /v1/models/instance | Launch a model by version | models:start |
| GET | /v1/models | List all running models | models:list |
| GET | /v1/models/{model_uid} | Get model details | models:list |
| GET | /v1/models/instances | Get instance info with resources | models:list |
| GET | /v1/models/{model_uid}/events | Get model lifecycle events | models:read |
| DELETE | /v1/models/{model_uid} | Terminate a model | models:stop |
| GET | /v1/models/{model_uid}/progress | Get launch progress | models:read |
| POST | /v1/models/{model_uid}/cancel | Cancel model launch | models:stop |
| POST | /v1/models/{model_uid}/requests/{request_id}/abort | Abort a specific request | models:read |

## Launching Models

 
### POST /v1/models

 The primary endpoint for launching model instances. This endpoint supports launching any model type (LLM, embedding, image, audio, rerank, video, flexible) with extensive configuration options.

 
#### Request Parameters

 
| Parameter | Type | Required | Description |
|---|---|---|---|
| model_uid | string | No | Custom identifier for the model instance. If not provided, a UUID is generated |
| model_name | string | Yes | Name of the model to launch (e.g., "qwen2.5-instruct") |
| model_type | string | No | Type: "LLM", "embedding", "image", "audio", "rerank", "video", "flexible" |
| model_engine | string | No | Backend engine: "vllm", "sglang", "transformers", "llama.cpp", etc. |
| model_size_in_billions | int/string | No | Model size variant (e.g., 7, "0_5") |
| model_format | string | No | Format: "pytorch", "ggufv2", "gptq", "awq" |
| quantization | string | No | Quantization: "none", "q4_0", "int4" |
| replica | int | No | Number of replicas (default: 1). Validated by _validate_replica |
| n_gpu | int/string | No | Number of GPUs: integer, "auto", or null for CPU |
| request_limits | int | No | Maximum concurrent requests per model instance |
| peft_model_config | object | No | LoRA/adapter configuration for fine-tuned models |

## Listing Models

 
### GET /v1/models

 Returns a list of all currently running model instances across all workers.

 
#### Implementation Details

 The endpoint aggregates models from the supervisor's internal state. The supervisor queries workers for their status, using `XINFERENCE_LIST_MODELS_PER_WORKER_TIMEOUT` to handle unresponsive nodes.

## Launch Progress and Cancellation

 
### GET /v1/models/{model_uid}/progress

 Polls the current progress of a model launch operation. The supervisor fetches progress data from the worker where the launch is occurring.

 Sources: [xinference/api/restful_api.py1504-1525](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/restful_api.py#L1504-L1525) [xinference/core/supervisor.py1433-1451](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py#L1433-L1451)

 
### POST /v1/models/{model_uid}/cancel

 Cancels an in-progress model launch. This triggers a cancellation signal in the worker, which stops the `CancellableDownloader` and kills any associated subpools.

### GET /v1/models/{model_uid}/events

 Retrieves lifecycle events for a model. Events are collected by the `EventCollectorActor` and include status transitions (PENDING, READY, ERROR).

## Request Abortion

 
### POST /v1/models/{model_uid}/requests/{request_id}/abort

 Aborts a specific inference request. This uses the `CancelMixin` to interrupt long-running generation tasks without terminating the entire model.
