  This document describes the testing infrastructure, continuous integration/continuous deployment (CI/CD) pipelines, and code quality tooling for Xinference. It covers test organization, execution strategies, automated workflows, and platform-specific testing approaches.

 
## Pre-commit Hooks

 Xinference uses pre-commit hooks to enforce code quality standards locally before commits reach the CI pipeline. This provides faster feedback to developers and reduces CI failures.

 
### Pre-commit Configuration

 The `.pre-commit-config.yaml` defines hooks that run automatically on `git commit`. These include formatting with `black`, import sorting with `isort`, linting with `flake8`, and static type checking with `mypy`.

 
| Hook | Repository | Purpose | Configuration |
|---|---|---|---|
| black | psf/black | Code formatting | exclude: thirdparty |
| flake8 | PyCQA/flake8 | Linting | args: [--config, setup.cfg] |
| isort | pycqa/isort | Import sorting | args: [--sp, setup.cfg] |
| mypy | pre-commit/mirrors-mypy | Type checking | args: [--ignore-missing-imports] |

 **Sources:** [.pre-commit-config.yaml1-40](https://github.com/xorbitsai/inference/blob/d97e0970/.pre-commit-config.yaml#L1-L40)

## Test Organization and Configuration

 
### Test Directory Structure

 Tests are organized alongside the code they test, following pytest conventions:

 
 - **Core Logic:** `xinference/core/tests/` contains tests for the actor system, worker management, and scheduling [xinference/core/tests/test_worker.py1-30](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/tests/test_worker.py#L1-L30)
 - **Model Logic:** Each model type has a dedicated test directory, e.g., `xinference/model/llm/tests/` [xinference/model/llm/tests/test_llm_family.py1-35](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/tests/test_llm_family.py#L1-L35)
 - **Utility Tests:** Shared helpers are tested in `xinference/core/tests/test_utils.py` [xinference/core/tests/test_utils.py1-31](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/tests/test_utils.py#L1-L31)
 
 
### Coverage Configuration

 Coverage tracking is configured in `setup.cfg`. It measures branch coverage and uses plugins for Cython support.

 **Sources:** [setup.cfg243-262](https://github.com/xorbitsai/inference/blob/d97e0970/setup.cfg#L243-L262)

 
## CI/CD Pipeline Architecture

 The primary CI pipeline is defined in `.github/workflows/python.yaml`. It manages linting, frontend builds, and a complex matrix of backend tests.

 
### Workflow Triggers and Concurrency

 The workflow triggers on pushes to all branches and pull request events [python.yaml3-8](https://github.com/xorbitsai/inference/blob/d97e0970/python.yaml#L3-L8) To save resources, it cancels in-progress runs on the same branch when new commits are detected [python.yaml10-12](https://github.com/xorbitsai/inference/blob/d97e0970/python.yaml#L10-L12)

 
### Change Detection and GPU CI Optimization

 A specialized `changes` job detects which parts of the codebase were modified to selectively trigger expensive GPU tests [python.yaml61-166](https://github.com/xorbitsai/inference/blob/d97e0970/python.yaml#L61-L166)

 
 - **LLM Changes:** Triggered by files in `xinference/model/llm/*` or `xinference/core/tests/test_continuous_batching.py` [python.yaml108](https://github.com/xorbitsai/inference/blob/d97e0970/python.yaml#L108-L108)
 - **Audio/Image/Embedding:** Specific paths like `xinference/model/audio/*` trigger their respective test groups [python.yaml105-107](https://github.com/xorbitsai/inference/blob/d97e0970/python.yaml#L105-L107)
 - **Full Run:** Changes to core runtime components (`xinference/core/*`, `xinference/api/*`, `xinference/deploy/*`) trigger all test groups [python.yaml138](https://github.com/xorbitsai/inference/blob/d97e0970/python.yaml#L138-L138)
 
 **Sources:** [.github/workflows/python.yaml73-166](https://github.com/xorbitsai/inference/blob/d97e0970/.github/workflows/python.yaml#L73-L166)

 
### Frontend and Static Content CI

 The `lint` job verifies the React-based frontend by running `npm ci`, `eslint`, and performing a static build export [python.yaml41-46](https://github.com/xorbitsai/inference/blob/d97e0970/python.yaml#L41-L46) It also verifies that the FastAPI backend can correctly serve these static files using `pytest` on `xinference/api/tests/test_frontend_static.py` [python.yaml55-58](https://github.com/xorbitsai/inference/blob/d97e0970/python.yaml#L55-L58)

 **Sources:** [.github/workflows/python.yaml15-59](https://github.com/xorbitsai/inference/blob/d97e0970/.github/workflows/python.yaml#L15-L59)

## Specialized Test Implementation

 
### Worker and Actor Testing

 Tests for the `WorkerActor` often use a `MockWorkerActor` to simulate model launches without requiring actual heavy model weights. These tests verify:

 
 - **Resource Allocation:** Correct assignment of CUDA devices via `allocate_devices` [xinference/core/tests/test_worker.py194-200](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/tests/test_worker.py#L194-L200)
 - **Status Management:** Tracking model state and status guards [xinference/core/tests/test_worker.py124-150](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/tests/test_worker.py#L124-L150)
 - **Cleanup:** Proper termination of sub-pools and device release [xinference/core/tests/test_worker.py126-134](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/tests/test_worker.py#L126-L134)
 
 **Sources:** [xinference/core/tests/test_worker.py31-168](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/tests/test_worker.py#L31-L168)

 
### Model Family and Spec Validation

 Tests in `xinference/model/llm/tests/test_llm_family.py` ensure that model configurations (GGUF, PyTorch, MLX) are correctly deserialized and matched against engine capabilities.

 
 - **Deserialization:** Validating `LLMFamilyV2` schemas [xinference/model/llm/tests/test_llm_family.py38-114](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/tests/test_llm_family.py#L38-L114)
 - **Cache Management:** Testing `LLMCacheManager` interactions with HuggingFace [xinference/model/llm/tests/test_llm_family.py116-176](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/tests/test_llm_family.py#L116-L176)
 
 **Sources:** [xinference/model/llm/tests/test_llm_family.py25-176](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/tests/test_llm_family.py#L25-L176)

 
### Launch Strategy Testing

 The `IdleFirstLaunchStrategy` is tested by mocking supervisors and workers to ensure replicas are balanced across available GPUs and nodes [xinference/core/tests/test_launch_strategy.py110-206](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/tests/test_launch_strategy.py#L110-L206)

## Docker CD Pipeline

 The `docker-cd.yaml` workflow automates the building and pushing of images to DockerHub.

 
 - **Architectures:** Builds for `aarch64` (ARM64) and `x86_64` [docker-cd.yaml25-62](https://github.com/xorbitsai/inference/blob/d97e0970/docker-cd.yaml#L25-L62)
 - **Variants:** Produces GPU-enabled images (using `Dockerfile`) and CPU-only images (using `Dockerfile.cpu`) [docker-cd.yaml63-138](https://github.com/xorbitsai/inference/blob/d97e0970/docker-cd.yaml#L63-L138)
 - **Tagging:** Handles `nightly` tags for branch pushes and version tags for releases [docker-cd.yaml51-58](https://github.com/xorbitsai/inference/blob/d97e0970/docker-cd.yaml#L51-L58)
 
 **Sources:** [.github/workflows/docker-cd.yaml1-172](https://github.com/xorbitsai/inference/blob/d97e0970/.github/workflows/docker-cd.yaml#L1-L172)

 
## Documentation CI

 The `pr_auto_run_gen_docs.yaml` workflow automatically updates built-in model documentation when the underlying JSON specifications are modified.

 
 - **Trigger:** Modified `llm_family.json` or `model_spec.json` files [pr_auto_run_gen_docs.yaml6-12](https://github.com/xorbitsai/inference/blob/d97e0970/pr_auto_run_gen_docs.yaml#L6-L12)
 - **Validation:** Checks PR metadata and model names for safety [pr_auto_run_gen_docs.yaml23-36](https://github.com/xorbitsai/inference/blob/d97e0970/pr_auto_run_gen_docs.yaml#L23-L36)
 - **Generation:** Runs `doc/source/gen_docs.py` to regenerate RST files [pr_auto_run_gen_docs.yaml120-125](https://github.com/xorbitsai/inference/blob/d97e0970/pr_auto_run_gen_docs.yaml#L120-L125)
 - **Commit:** Automatically commits changes back to the PR branch [pr_auto_run_gen_docs.yaml176-180](https://github.com/xorbitsai/inference/blob/d97e0970/pr_auto_run_gen_docs.yaml#L176-L180)
 
 **Sources:** [.github/workflows/pr_auto_run_gen_docs.yaml1-183](https://github.com/xorbitsai/inference/blob/d97e0970/.github/workflows/pr_auto_run_gen_docs.yaml#L1-L183)
