## Purpose and Scope

 This document explains how Xinference implements continuous batching and request scheduling for LLM inference. Continuous batching allows the system to dynamically group multiple inference requests together to maximize GPU utilization and throughput. This page covers the prefill/decode phases, KV cache management, scheduling policies, and engine-specific implementations including vLLM, SGLang, and Transformers.

 For information about the overall LLM serving architecture, see [LLM Serving System](https://deepwiki.com/xorbitsai/inference/3-llm-serving-system). For details about specific backend engines, see [Backend Engines](https://deepwiki.com/xorbitsai/inference/3.2-backend-engines). For distributed inference across multiple GPUs, see [Distributed Inference and Multi-Worker](https://deepwiki.com/xorbitsai/inference/3.6-distributed-inference-and-multi-worker).

## Continuous Batching Overview

 Continuous batching is an inference optimization technique that allows multiple requests to be processed simultaneously, dynamically adding and removing requests from batches as they arrive and complete. This contrasts with static batching, where all requests in a batch must start and finish together.

 
### Key Benefits

 
| Benefit | Description |
|---|---|
| Higher Throughput | GPU resources are utilized continuously without waiting for all requests to complete. |
| Lower Latency | Requests don't wait for batch formation; processing starts immediately. |
| Dynamic Scaling | Batch size adjusts automatically based on current workload. |
| Memory Efficiency | KV cache is managed efficiently; vLLM uses PagedAttention and SGLang uses RadixAttention. |

## Prefill and Decode Phases

 LLM inference consists of two distinct phases. Continuous batching handles these phases differently to optimize performance.

 
### Phase Comparison

 
| Phase | Characteristics | Batch Strategy |
|---|---|---|
| Prefill | Processes the entire prompt to compute KV cache for all tokens. | Multiple prompts can be batched together (e.g., prefill_batch_size in MLX). |
| Decode | Generates one token at a time using the existing KV cache. | Batch decode steps across all active sequences. |

 
### Transformers Engine Logic

 In the Transformers engine, the system explicitly separates requests into these phases during each iteration of `_batch_inference_one_step_internal`.

## KV Cache Management

 The Key-Value (KV) cache stores attention keys and values from previous tokens. Efficient management is critical for high-concurrency serving.

 
### KV Cache Operations (Transformers)

 The `PytorchModel` in the Transformers backend manages cache via the following mechanisms:

 
 - **Merging**: When combining new prefill requests with existing decode requests, the system merges their KV caches.
 - **Conversion**: Uses `DynamicCache` to handle modern Transformers cache formats.
 - **Padding**: Uses `_pad_seqs_inplace` to align sequences to the same length within a batch.

## Engine-Specific Implementations

 
### vLLM Engine

 vLLM is the primary high-performance backend. It uses `AsyncLLMEngine` to handle requests asynchronously.

 
 - **Scheduling Policy**: Defaults to `fcfs` (First-Come-First-Served) in newer versions [xinference/model/llm/vllm/core.py752-754](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L752-L754)
 - **Memory Management**: Configured via `gpu_memory_utilization` (default 0.9) and `block_size` [xinference/model/llm/vllm/core.py91-103](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L91-L103)
 
 
### SGLang Engine

 SGLang uses a Prefix Tree (RadixAttention) to reuse KV caches for requests sharing the same system prompt or context.

 
 - **Memory Fraction**: `mem_fraction_static` controls how much memory is reserved for the cache [xinference/model/llm/sglang/core.py56](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/sglang/core.py#L56-L56)
 - **Supported Architectures**: Explicitly lists models like `LlamaForCausalLM` and `Qwen2ForCausalLM` [xinference/model/llm/sglang/core.py119-140](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/sglang/core.py#L119-L140)
 
 
### MLX Engine (Apple Silicon)

 The MLX engine implements batching through a `BatchGenerator`.

 
 - **Batch Configuration**: Uses `completion_batch_size` (default 4) and `prefill_batch_size` (default 1) [xinference/model/llm/mlx/core.py179-186](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/mlx/core.py#L179-L186)
 - **Thread Safety**: Implements `_ensure_mlx_vlm_thread_local_stream` to ensure generation is safe across worker threads [xinference/model/llm/mlx/core.py72-96](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/mlx/core.py#L72-L96)
