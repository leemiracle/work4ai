  This document describes the authentication and authorization mechanisms in Xinference, including the database-backed JWT system, scope-based access control, and IP-based restrictions. These features allow secure multi-user deployments and fine-grained control over model operations.

 
## Overview

 Xinference implements a robust authentication and authorization system based on OAuth2 and JWT. Since v3.0, a database-backed system is enabled by default [doc/source/user_guide/auth_system.rst15-16](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/user_guide/auth_system.rst#L15-L16) It stores users, permissions, API keys, and refresh tokens in a local SQLite database [doc/source/user_guide/auth_system.rst10-13](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/user_guide/auth_system.rst#L10-L13)

 The system supports:

 
 - **JWT-based authentication** with access and refresh tokens [xinference/api/oauth2/advanced/auth_service.py154-175](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/auth_service.py#L154-L175)
 - **Scope-based authorization** for fine-grained access control [doc/source/user_guide/auth_system.rst119-134](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/user_guide/auth_system.rst#L119-L134)
 - **Encrypted API Keys** stored at rest using AES [xinference/api/oauth2/advanced/auth_service.py127-132](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/auth_service.py#L127-L132)
 - **IP-based access control** via trusted proxy configuration [xinference/api/oauth2/advanced/auth_service.py47-67](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/auth_service.py#L47-L67)

### AdvancedAuthService Implementation

 The `AdvancedAuthService` class manages the lifecycle of credentials. It is initialized with paths to the SQLite database and keys for JWT signing and data encryption [xinference/api/oauth2/advanced/auth_service.py127-132](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/auth_service.py#L127-L132)

 Key logic includes:

 
 - **Token Generation**: Access tokens are valid for a configurable duration (default 30 minutes) [xinference/api/oauth2/advanced/auth_service.py93-104](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/auth_service.py#L93-L104)
 - **Token Versioning**: Tokens include a `token_version`. If a user's password is reset, the database version is bumped, immediately invalidating all outstanding JWTs [xinference/api/oauth2/advanced/auth_service.py187-199](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/auth_service.py#L187-L199)
 - **API Key Security**: API keys are hashed (SHA256) for lookup and encrypted (AES) for retrieval/reveal [xinference/api/oauth2/advanced/database.py48-49](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/database.py#L48-L49)

## Authorization: Scopes and Permissions

 Xinference uses scopes to restrict access to specific functionalities. Permissions are stored in the `user_permissions` table [xinference/api/oauth2/advanced/database.py38-43](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/database.py#L38-L43)

 
### Interface Permissions

 
| Scope | Description |
|---|---|
| admin | Superuser; bypasses all specific scope checks xinference/api/oauth2/advanced/auth_service.py76 |
| models:list | Permission to list models and get model info doc/source/user_guide/auth_system.rst123 |
| models:read | Permission to use models for inference doc/source/user_guide/auth_system.rst124 |
| models:write | Permission to launch and stop models doc/source/user_guide/auth_system.rst125 |
| models:register | Permission to register/unregister custom models doc/source/user_guide/auth_system.rst126 |
| users:manage | Create, update, delete users and permissions doc/source/user_guide/auth_system.rst129 |
| keys:manage | List, update, delete, and reveal any user's API keys doc/source/user_guide/auth_system.rst128 |

 
### Permission Escalation Prevention

 The system enforces a strict hierarchy: a caller may only grant permissions they themselves hold [xinference/api/oauth2/advanced/routes.py113-122](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/routes.py#L113-L122) This prevents a user with `users:manage` but without `admin` from elevating themselves or others to administrator status [xinference/api/oauth2/advanced/routes.py133-139](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/routes.py#L133-L139)

## Security Configuration

 
### Environment Variables

 The authentication system behavior is tuned via environment variables:

 
| Variable | Default | Description |
|---|---|---|
| XINFERENCE_AUTH_ADVANCED | true | Enables/disables the entire auth system doc/source/user_guide/auth_system.rst25-31 |
| XINFERENCE_AUTH_JWT_SECRET_KEY | Auto-generated | Secret for signing JWTs doc/source/user_guide/auth_system.rst103-104 |
| XINFERENCE_AUTH_DB_PATH | ~/.xinference/auth/auth.db | Path to the SQLite database doc/source/user_guide/auth_system.rst109-110 |
| XINFERENCE_PASSWORD_MIN_LENGTH | 8 | Minimum length for user passwords xinference/api/oauth2/advanced/auth_service.py114-123 |

## Initial Setup and Recovery

 
### First-Run Setup

 When the database is empty, the system enters a "needs setup" state [xinference/api/oauth2/advanced/auth_service.py148-150](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/auth_service.py#L148-L150) The first user created via `POST /v1/admin/setup` is automatically granted the `admin` scope and all other permissions [xinference/api/oauth2/advanced/auth_service.py75-90](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/auth_service.py#L75-L90) This endpoint becomes unavailable once any user exists [xinference/api/oauth2/advanced/database.py158-178](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/oauth2/advanced/database.py#L158-L178)

 
### Password Recovery

 Administrators can reset passwords using the CLI tool `xinference-reset-auth-password` [doc/source/user_guide/auth_system.rst70-86](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/user_guide/auth_system.rst#L70-L86) This tool:

 
 - Updates the `password_hash` in the database.
 - Increments `token_version` to invalidate existing JWTs.
 - Deletes active `refresh_tokens` for that user [doc/source/user_guide/auth_system.rst82-83](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/user_guide/auth_system.rst#L82-L83)
