## Purpose and Scope

 This document provides detailed technical documentation for the five inference engines supported by Xinference for LLM serving: vLLM, SGLang, Transformers, llama.cpp, and MLX. Each engine is optimized for different hardware configurations, model formats, and performance requirements.

 For information about the overall LLM serving architecture, see [LLM Serving System](https://deepwiki.com/xorbitsai/inference/3-llm-serving-system). For details on how models are selected and matched to engines, see [Engine Selection and Matching](https://deepwiki.com/xorbitsai/inference/3.3-engine-selection-and-matching).

 
## Engine Architecture

 Xinference implements a pluggable engine system where each engine is represented by a class implementing the `LLM` base interface. The system automatically selects the appropriate engine based on model format, quantization, platform, and hardware availability.

## vLLM Engine

 vLLM is a high-performance inference engine designed for production LLM serving with state-of-the-art throughput.

 
### Key Features

 
 - **PagedAttention**: Efficient management of attention KV cache memory through paging mechanism.
 - **Continuous Batching**: Incoming requests are continuously batched for maximum throughput.
 - **Speculative Decoding**: Accelerates generation through speculation. Supported via `speculative_config` [xinference/model/llm/vllm/core.py115](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L115-L115)
 - **Multi-GPU Support**: Tensor parallelism and pipeline parallelism via `tensor_parallel_size` and `pipeline_parallel_size` [xinference/model/llm/vllm/core.py94-95](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L94-L95)
 - **Vision Support**: Specialized handling for multimodal models like Qwen2-VL and Llama-3.2-Vision [doc/source/getting_started/installation.rst71](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L71-L71)
 
 
### Selection Criteria

 vLLM is automatically selected when ALL of the following conditions are met:

 
 - **Platform**: Linux with at least one CUDA device [doc/source/getting_started/installation.rst61](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L61-L61)
 - **Model Format**: `pytorch`, `gptq`, `awq`, `fp4`, `fp8` or `bnb` [doc/source/getting_started/installation.rst57](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L57-L57)
 - **Quantization**: 
 - `pytorch` format: quantization must be `none` [doc/source/getting_started/installation.rst58](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L58-L58)
 - `awq` format: quantization must be `Int4` [doc/source/getting_started/installation.rst59](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L59-L59)
 - `gptq` format: quantization must be `Int3`, `Int4` or `Int8` [doc/source/getting_started/installation.rst60](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L60-L60)
 - **Model Support**: Model must be within the list of models supported by vLLM [doc/source/getting_started/installation.rst62](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L62-L62)
 
 
### Configuration

 The `VLLMModelConfig` TypedDict defines configuration parameters [xinference/model/llm/vllm/core.py91-122](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L91-L122):

 
| Parameter | Type | Description |
|---|---|---|
| gpu_memory_utilization | float | GPU memory utilization ratio (default typically 0.90) |
| max_num_batched_tokens | int | Maximum number of tokens per iteration |
| swap_space | int | CPU swap space in GiB |
| max_model_len | int | Override model's max context length |
| distributed_executor_backend | str | Backend for distributed execution (e.g., "ray" or "mp") |

 **Sources:** [xinference/model/llm/vllm/core.py91-122](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L91-L122)

 
## SGLang Engine

 SGLang provides high-performance inference with RadixAttention, which significantly accelerates execution by automatic KV cache reuse across multiple calls [doc/source/getting_started/installation.rst138](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L138-L138)

 
### Key Features

 
 - **RadixAttention**: Automatic KV cache reuse across multiple calls.
 - **Continuous Batching**: Efficient request batching.
 - **Structured Output**: Support for `json_schema` and `response_format` [xinference/model/llm/sglang/core.py88-89](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/sglang/core.py#L88-L89)
 - **Vision Support**: Broad support for vision models including `MiniCPMV`, `Qwen2_5_VL`, and `Gemma3` [xinference/model/llm/sglang/core.py141-148](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/sglang/core.py#L141-L148)
 
 
### Supported Models

 SGLang supports specific architectures for both causal LM and vision tasks:

 
| Category | Supported Architectures |
|---|---|
| Chat Models | LlamaForCausalLM, Qwen2ForCausalLM, MistralForCausalLM, DeepseekV3ForCausalLM, Gemma3ForCausalLM |
| Vision Models | Qwen2_5_VLForConditionalGeneration, MiniCPMV, MllamaForConditionalGeneration |

 **Sources:** [xinference/model/llm/sglang/core.py126-148](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/sglang/core.py#L126-L148)

 
### Port Management

 SGLang typically finds a port between its starting port and 40000. Xinference ensures the generated port is within this range [xinference/model/llm/sglang/core.py211-213](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/sglang/core.py#L211-L213)

 
## Transformers Engine

 The Transformers engine is the default backend for models in PyTorch format and supports the inference of most state-of-the-art models [doc/source/getting_started/installation.rst42](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L42-L42)

 
### Key Features

 
 - **Universal Compatibility**: Supports `pytorch`, `gptq`, `awq`, `bnb`, and `fp4` formats [doc/source/getting_started/installation.rst48](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L48-L48)
 - **Batch Scheduler**: Implements `allow_batch = True` and uses a custom scheduling logic for concurrent requests [xinference/model/llm/transformers/core.py95](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/transformers/core.py#L95-L95)
 - **Tensorizer Support**: Supports `enable_tensorizer` for faster model loading [xinference/model/llm/transformers/core.py134](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/transformers/core.py#L134-L134)
 - **LoRA Support**: Can load PEFT models via the `peft_model` parameter [xinference/model/llm/transformers/core.py103](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/transformers/core.py#L103-L103)
 
 
### Implementation Details

 The `PytorchModel` class handles the lifecycle of Transformers-based models. It manages device placement (including `device_map="auto"` via accelerate) and quantization configurations [xinference/model/llm/transformers/core.py123-136](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/transformers/core.py#L123-L136)

## llama.cpp Engine

 Xinference supports models in `gguf` format via the `xllamacpp` backend [doc/source/getting_started/installation.rst118-119](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L118-L119)

 
### Key Features

 
 - **Auto NGL (GPU Layers)**: Automatically detects the number of GPU layers to offload if `n-gpu-layers` is not specified [doc/source/user_guide/backends.rst52-54](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/user_guide/backends.rst#L52-L54)
 - **GGUF Support**: Native support for the LLaMA series and variants via `ggml` [doc/source/user_guide/backends.rst17-18](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/user_guide/backends.rst#L17-L18)
 - **Grammar-Based Decoding**: Converts `json_schema` to llama.cpp grammars for structured output [xinference/model/llm/llama_cpp/core.py42-52](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llama_cpp/core.py#L42-L52)
 - **Speculative Decoding**: Supports MTP (Multi-Token Prediction) speculative decoding, including Gemma 4 style assistants [xinference/model/llm/llama_cpp/core.py177-182](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llama_cpp/core.py#L177-L182)
 
 
### Hardware Acceleration

 Xinference automatically selects the matching `xllamacpp` GPU wheel for supported CUDA versions when per-model virtual environments are enabled [doc/source/getting_started/installation.rst131-133](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L131-L133)

## MLX Engine

 MLX-lm is designed specifically for Apple Silicon users to run LLMs efficiently [doc/source/getting_started/installation.rst147](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/installation.rst#L147-L147)

 
### Key Features

 
 - **Continuous Batching**: Uses `MLXBatchModel` wrapper around `mlx_lm.generate.BatchGenerator` for high throughput [xinference/model/llm/mlx/core.py99-100](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/mlx/core.py#L99-L100)
 - **Unified Memory**: Optimized for the shared memory architecture of Apple M-series chips.
 - **Thread-Local Streams**: Ensures safe generation across worker threads using `ThreadLocalStream` [xinference/model/llm/mlx/core.py72-96](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/mlx/core.py#L72-L96)
 
 
### Batching Implementation

 The `MLXBatchModel` maintains multiple batch generators keyed by sampling parameters like `temperature` and `top_p` [xinference/model/llm/mlx/core.py102-106](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/mlx/core.py#L102-L106) It supports the new MLX-LM API (version >= 0.31.2) for improved performance [xinference/model/llm/mlx/core.py147-153](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/mlx/core.py#L147-L153)

 **Sources:** [xinference/model/llm/mlx/core.py99-196](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/mlx/core.py#L99-L196)
