  This document describes how Xinference is containerized using Docker, including the Dockerfile structure, image variants (CUDA, CPU), dependency management, and container deployment configurations.

 
## Overview

 Xinference provides official Docker images to ensure a consistent runtime environment. Starting from **Xinference v3.0.0**, the GPU image has transitioned to a **slim** architecture. Instead of pre-installing every inference engine (which creates multi-gigabyte images), the container now acts as a base environment that dynamically manages engine dependencies at runtime via per-model virtual environments [xinference/deploy/docker/Dockerfile3-9](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L3-L9)

 Key features of the containerization strategy include:

 
 - **Dynamic Engine Loading**: Engines like vLLM or SGLang are installed into virtual environments at model launch time [xinference/deploy/docker/Dockerfile5-9](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L5-L9)
 - **Shared CUDA Stack**: A common PyTorch/CUDA stack is baked into the parent image to allow virtual environments to reuse heavy dependencies without redownloading them [xinference/deploy/docker/Dockerfile14-19](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L14-L19)
 - **Multi-Architecture Support**: The same Dockerfile builds for both `linux/amd64` and `linux/arm64` [xinference/deploy/docker/Dockerfile31-36](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L31-L36)

## Dockerfile Structure and Build Stages

 The build process is divided into two primary stages to optimize for size and build speed.

 
### Stage 1: Web UI Builder

 The frontend is a React application that is built into static assets using Node.js [xinference/deploy/docker/Dockerfile41-50](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L41-L50) These assets are later served by the Xinference Python backend, removing the need for a Node.js runtime in the final production image [doc/source/getting_started/using_xinference.rst55-58](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/using_xinference.rst#L55-L58)

 
### Stage 2: Runtime Image

 The runtime image uses `nvidia/cuda:13.0.2-devel-ubuntu22.04` as its base [xinference/deploy/docker/Dockerfile55](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L55-L55)

## Image Variants

 Xinference maintains different image variants to support various hardware targets.

 
| Variant | Tag Suffix | Base Image | Architecture |
|---|---|---|---|
| GPU (CUDA) | latest / vX.Y.Z | nvidia/cuda:13.0.2-devel-ubuntu22.04 | amd64, arm64 |
| CPU | -cpu | continuumio/miniconda3:23.10.0-1 | amd64 |

 
### GPU Image (CUDA 13.0)

 The GPU image includes the `deadsnakes` PPA to provide Python 3.12 on Ubuntu 22.04 [xinference/deploy/docker/Dockerfile73-81](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L73-L81) It includes `uv` to power the per-model virtual environment installer, which handles parallel downloads and timeouts for engine packages [xinference/deploy/docker/Dockerfile111-114](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L111-L114)

 
### CPU Image

 The CPU image is based on Miniconda and installs a specific CPU-only torch stack [xinference/deploy/docker/Dockerfile.cpu11-21](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile.cpu#L11-L21) It includes pre-installed engines suitable for CPU inference, such as `xllamacpp` and `gptqmodel` [xinference/deploy/docker/Dockerfile.cpu23-26](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile.cpu#L23-L26)

## Docker Compose and Orchestration

 For complex deployments, especially in air-gapped or multi-service environments, Xinference provides Docker Compose configurations.

 
### Standard Deployment

 The `docker-compose.yml` typically defines a supervisor and one or more workers.

 
 - **Supervisor**: Acts as the cluster entry point and API server.
 - **Worker**: Connects to the supervisor and manages the actual GPU resources.
 
 
### Offline / Air-gapped Support

 For environments without internet access, Xinference supports a private PyPI mirror setup. The worker is configured to point to a local `pypiserver` container that hosts the necessary wheels for inference engines [xinference/deploy/docker/Dockerfile8-9](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L8-L9)

 The project includes scripts to generate these package lists and download the required wheels for offline use:

 
 - `generate_package_lists.py`: Iterates through model specifications to identify required engine packages [xinference/deploy/docker/pypiserver/generate_package_lists.py71-82](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/pypiserver/generate_package_lists.py#L71-L82)
 - `download_packages.py`: Downloads the wheels into a directory used by the offline PyPI server [xinference/deploy/docker/pypiserver/download_packages.py144-164](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/pypiserver/download_packages.py#L144-L164)

## CI/CD and Release Pipeline

 Official images are built and pushed to Docker Hub via GitHub Actions.

 
 - **Triggers**: Images are built on every tag push, daily (nightly builds), or via manual dispatch [.github/workflows/docker-cd.yaml3-9](https://github.com/xorbitsai/inference/blob/d97e0970/.github/workflows/docker-cd.yaml#L3-L9)
 - **Multi-Platform Build**: The pipeline uses `docker buildx` to build `linux/arm64` images on ARM runners and `linux/amd64` on x86 runners [.github/workflows/docker-cd.yaml25-62](https://github.com/xorbitsai/inference/blob/d97e0970/.github/workflows/docker-cd.yaml#L25-L62)
 - **Tagging Strategy**: 
 - `latest`: Points to the most recent stable release [.github/workflows/docker-cd.yaml161-163](https://github.com/xorbitsai/inference/blob/d97e0970/.github/workflows/docker-cd.yaml#L161-L163)
 - `nightly-main`: Built from the latest code in the `main` branch [.github/workflows/docker-cd.yaml57](https://github.com/xorbitsai/inference/blob/d97e0970/.github/workflows/docker-cd.yaml#L57-L57)
 - `vX.Y.Z`: Specific release versions [.github/workflows/docker-cd.yaml52](https://github.com/xorbitsai/inference/blob/d97e0970/.github/workflows/docker-cd.yaml#L52-L52)
