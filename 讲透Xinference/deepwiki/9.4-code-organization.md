## Purpose and Scope

 This document describes the directory structure and code organization of the Xinference codebase. It explains where different components live, how they're organized, and how to navigate the code for development or debugging purposes. For information about how these components interact at runtime, see [System Architecture](https://deepwiki.com/xorbitsai/inference/2-system-architecture). For deployment configuration, see [Deployment](https://deepwiki.com/xorbitsai/inference/7-deployment).

 
---

 
## Repository Structure Overview

 The Xinference repository follows a modular structure organized by functional concern:

 
```
xinference/
├── api/                    # RESTful API implementation
├── client/                 # Python client library
├── core/                   # Core actor system (supervisor, worker, model)
├── deploy/                 # Deployment utilities and CLI
├── model/                  # Model type implementations
│   ├── llm/               # Large language models
│   ├── embedding/         # Embedding models
│   ├── image/             # Image generation models
│   ├── audio/             # Audio models (ASR, TTS)
│   ├── video/             # Video generation models
│   ├── rerank/            # Reranking models
│   └── flexible/          # Flexible/custom models
├── ui/                     # Web UI (React)
├── types.py               # Shared type definitions
├── constants.py           # System constants and configuration
├── device_utils.py        # GPU/device utilities
└── isolation.py           # Threading/async isolation utilities
```

 **Sources:** [xinference/constants.py1-115](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/constants.py#L1-L115) [xinference/types.py1-520](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/types.py#L1-L520)

## Model Type Implementations

 
### Model Type Directory Structure

 Each model type has its own directory under `xinference/model/` with a consistent structure:

 
```
xinference/model/<type>/
├── __init__.py           # Exports and registration functions
├── core.py               # Base model implementation
├── <engine_name>/        # Engine-specific implementations
├── <model_family>.py     # Model family matching logic
├── cache_manager.py      # Model download and caching
├── custom.py             # Custom model registration
├── model_spec.json       # Built-in model definitions
└── tests/                # Unit tests
```

 
### Common Architectural Patterns

 **1. Installation Pattern (`_install()` function):**

 Each model type's `__init__.py` defines an `_install()` function that:

 
 - Loads built-in model specifications.
 - Loads user-defined custom models from `$XINFERENCE_MODEL_DIR/v2/<type>/`.
 - Registers engine configurations.

## Deployment and CLI

 
### Entry Points

 CLI commands are defined in `pyproject.toml` (or `setup.cfg`) and implemented in `xinference/deploy/cmdline.py`.

 
| Command | Function | Purpose |
|---|---|---|
| xinference | cli() | Model management and interactive chat |
| xinference-local | local() | Start single-node cluster |
| xinference-supervisor | supervisor() | Start supervisor node |
| xinference-worker | worker() | Start worker node |
