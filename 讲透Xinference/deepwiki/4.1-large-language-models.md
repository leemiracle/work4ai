  This document covers the Large Language Model (LLM) subsystem in Xinference, focusing on model families, chat templates, tool calling capabilities, reasoning content parsing, and LoRA adapter support. The LLM system provides a unified interface for launching and serving various language models with advanced features like function calling and chain-of-thought reasoning.

 For information about specific inference engines that execute LLM models, see [Model Family Definitions](https://deepwiki.com/xorbitsai/inference/3.1-model-family-definitions). For details about deploying and managing LLM instances, see [Model Actor Framework](https://deepwiki.com/xorbitsai/inference/2.2-model-actor-framework).

 
## Model Family Architecture

 The LLM system is built around model families defined in `LLMFamilyV2`, where each family represents a group of related models with different sizes, formats, and quantizations. Model families are defined in JSON format and loaded at initialization.

### Model Abilities

 Models declare their capabilities through the `model_ability` field:

 
| Ability | Description | Example Models |
|---|---|---|
| generate | Text generation without conversation | codestral-v0.1, gpt-2, llama-2 |
| chat | Conversational with chat templates | gorilla-openfunctions-v2, baichuan-2-chat |
| tools | Function/tool calling support | qwen2.5-instruct, glm4-chat, deepseek-v3 |
| vision | Multimodal image understanding | glm-4v, cogagent, llama-3.2-vision |
| reasoning | Extended reasoning capabilities | deepseek-r1, marco-o1, QwQ-32B |
| hybrid | Switchable thinking mode | Qwen3-Thinking, Baichuan-M2 |

## Backend Engines

 Xinference supports multiple backends for LLM serving:

 
| Backend | Features | Source |
|---|---|---|
| vLLM | PagedAttention, Continuous batching, High throughput | doc/source/user_guide/backends.rst121-130 |
| SGLang | RadixAttention, KV cache reuse, Tensor parallelism | doc/source/getting_started/installation.rst138 |
| llama.cpp | GGUF support, Apple Silicon/CPU optimization via xllamacpp | doc/source/user_guide/backends.rst12-19 |
| Transformers | Default PyTorch backend, supports AWQ/GPTQ/BNB | doc/source/getting_started/installation.rst40-48 |
| MLX | Efficient inference for Apple Silicon | doc/source/getting_started/installation.rst145-147 |

 
### vLLM Integration

 The `VLLMModel` configures the engine with parameters like `tensor_parallel_size`, `gpu_memory_utilization`, and `max_model_len` [xinference/model/llm/vllm/core.py91-115](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L91-L115) It supports advanced features like speculative decoding via `speculative_config` [xinference/model/llm/vllm/core.py115](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L115-L115)

 
### SGLang Integration

 The `SGLANGModel` manages a runtime service. It handles port allocation and sanitizes configuration for the SGLang engine [xinference/model/llm/sglang/core.py151-215](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/sglang/core.py#L151-L215) It specifically supports vision models like `Qwen2_5_VL` and `MiniCPMV` [xinference/model/llm/sglang/core.py141-148](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/sglang/core.py#L141-L148)

 
## LoRA Support

 LoRA adapters are supported in both `vLLM` and `Transformers` backends.

 
 - **Transformers**: Uses `peft` to load adapters via `PeftModel.from_pretrained` or `load_adapter` [xinference/model/llm/transformers/core.py94-111](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/transformers/core.py#L94-L111)
 - **vLLM**: Passes `LoRA` objects to the engine which manages them via its own internal adapter system [xinference/model/llm/vllm/core.py57](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L57-L57)
