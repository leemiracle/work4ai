  Xinference provides a comprehensive suite of benchmarking tools designed to measure the performance of various model types under different load conditions. These tools allow developers to evaluate metrics such as Time To First Token (TTFT), Inter-Token Latency (ITL), throughput (tokens/sec and requests/sec), and total serving capacity.

 
## Core Architecture

 The benchmarking system is built on an asynchronous execution model using `aiohttp` for high-concurrency request dispatch. It utilizes a base class hierarchy to share common logic for request generation, timing, and statistical reporting.

 
### Benchmark Runner Hierarchy

 The system uses `BenchmarkRunner` as the foundation for all measurement tools.

 
 - **`BenchmarkRunner`**: Handles the basic request lifecycle, including warm-up phases, sending POST requests to the Xinference API, and parsing OpenAI-compatible responses [benchmark/benchmark_runner.py50-70](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_runner.py#L50-L70)
 - **`ConcurrentBenchmarkRunner`**: (Inherited by serving tools) Manages multiple workers to simulate parallel users [benchmark/benchmark_serving.py72-84](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_serving.py#L72-L84)

## Benchmarking Tools

 
### 1. Latency Benchmarking (`benchmark_latency.py`)

 This tool measures the latency of processing a single batch of requests sequentially. It is primarily used to establish a baseline for model performance without the noise of concurrent request contention [benchmark/benchmark_latency.py29-40](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_latency.py#L29-L40)

 
 - **Use Case**: Establishing the raw speed of a model on specific hardware.
 - **Key Metrics**: Average latency per request, total processing time [benchmark/benchmark_latency.py66](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_latency.py#L66-L66)
 
 
### 2. Serving Throughput (`benchmark_serving.py`)

 This is the most advanced tool in the suite, simulating real-world production traffic. It supports both fixed concurrency and Poisson distribution-based request rates [benchmark/benchmark_serving.py115-132](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_serving.py#L115-L132)

 
 - **Dataset Modes**: 
 - `sharegpt`: Uses real-world conversation data [benchmark/benchmark_serving.py152-160](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_serving.py#L152-L160)
 - `random`: Generates synthetic prompts with specific input/output lengths [benchmark/benchmark_serving.py161-170](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_serving.py#L161-L170)
 - **Request Dispatch**: If `request_rate` is set, it samples intervals from an exponential distribution to simulate a Poisson process [benchmark/benchmark_serving.py126-131](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_serving.py#L126-L131)
 
 
### 3. Long Context Benchmarking (`benchmark_long.py`)

 Specifically designed to test the model's performance and KV cache management over extended context windows. It generates prompts that require the model to sort random numbers based on a specified context length [benchmark/README.md45-53](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/README.md?plain=1#L45-L53)

 
### 4. Rerank Benchmarking (`benchmark_rerank.py`)

 Tailored for reranking models, this tool measures the throughput of the `/v1/rerank` endpoint. It uses the `mteb/scidocs-reranking` dataset by default [benchmark/benchmark_rerank.py143-151](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_rerank.py#L143-L151)

## Implementation Details

 
### Metrics Collection

 The `RequestOutput` dataclass stores the granular data for every request [benchmark/benchmark_runner.py39-48](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_runner.py#L39-L48):

 
| Attribute | Description |
|---|---|
| ttft | Time from request start to the first token received (streaming only) benchmark/benchmark_runner.py162-164 |
| itl | A list of time differences between consecutive tokens benchmark/benchmark_runner.py168-170 |
| latency | Total time from request start to finish benchmark/benchmark_runner.py174 |
| completion_tokens | Total number of tokens generated, extracted from usage field benchmark/benchmark_runner.py176-181 |

 
### Tokenizer Handling

 Accurate benchmarking requires correct token counting. The `get_tokenizer` utility in `utils.py` handles the initialization of HuggingFace tokenizers, with a specific optimization for LLaMA-based models using `hf-internal-testing/llama-tokenizer` to avoid slow initialization times [benchmark/utils.py37-60](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/utils.py#L37-L60)

 
### Data Sampling

 The `sample_requests` function filters the ShareGPT dataset to ensure quality [benchmark/utils.py98-144](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/utils.py#L98-L144):

 
 - Filters conversations with at least 2 turns.
 - Tokenizes both prompts and completions.
 - Prunes sequences that are too short (< 4 tokens) or exceed the `prompt_len_limit`.

## Common Options

 All benchmarking tools share a set of common CLI arguments:

 
 - `--model-uid`: The unique identifier of the model launched in Xinference [benchmark/benchmark_latency.py90](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_latency.py#L90-L90)
 - `--stream`: Enables streaming mode to measure TTFT and ITL [benchmark/benchmark_runner.py91-101](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_runner.py#L91-L101)
 - `--ignore-eos`: Forces the model to continue generating until `max_tokens` is reached, useful for throughput testing [benchmark/benchmark_runner.py112-113](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_runner.py#L112-L113)
 - `--api-key`: Optional JWT or API key for authenticated endpoints [benchmark/benchmark_runner.py116-117](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_runner.py#L116-L117)
 - `--print-error`: Prints the full traceback and error response if a request fails [benchmark/benchmark_latency.py101-104](https://github.com/xorbitsai/inference/blob/d97e0970/benchmark/benchmark_latency.py#L101-L104)
