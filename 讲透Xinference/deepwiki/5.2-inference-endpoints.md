For authentication requirements, see [Authentication and Authorization](https://deepwiki.com/xorbitsai/inference/5.5-authentication-and-authorization).

 
## Overview

 Xinference provides a comprehensive set of inference endpoints that support model types including LLM, embedding, rerank, image, audio, video, and flexible models. All endpoints follow OpenAI-compatible API conventions where applicable and support both synchronous and streaming responses.

 The inference endpoints are implemented in the `RESTfulAPI` class and handle:

 
 - Request validation and authentication.
 - Model reference resolution via the Supervisor.
 - Inference execution via `ModelActor`.
 - Response streaming using Server-Sent Events (SSE).
 - Error handling and metrics collection.

## LLM Inference Endpoints

 
### Text Completion: `/v1/completions`

 Generates text completions based on a prompt. Compatible with OpenAI's `/v1/completions` endpoint. It utilizes `CreateCompletionRequest` for validation.

 **Request Body Highlights:**

 
 - `model`: Model UID.
 - `prompt`: Input string or array.
 - `stream`: Boolean to enable SSE.
 - `max_tokens`: Limit on generated tokens.
 
 Sources: [xinference/api/restful_api.py1196-1277](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/restful_api.py#L1196-L1277) [xinference/api/schemas/requests.py](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/schemas/requests.py) [xinference/types.py179-186](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/types.py#L179-L186)

 
### Chat Completion: `/v1/chat/completions`

 Generates chat completions from message history. Supports tool calling, vision, and reasoning content (e.g., DeepSeek-R1).

 **Implementation Details:** The endpoint validates messages and handles multimodal content via `CreateChatCompletion`. It leverages the `ModelActor.chat` method.

## Embedding Endpoints

 
### Create Embeddings: `/v1/embeddings`

 Generates vector embeddings from text input. Supports both dense and sparse embeddings.

 **Request Body:**

 
 - `model`: Model UID.
 - `input`: String or list of strings.

## Rerank Endpoints

 
### Rerank Documents: `/v1/rerank`

 Ranks documents by relevance to a query. Uses `RerankRequest` for input validation.

 **Response:** Returns a list of `DocumentObj` containing relevance scores and indices.

## Request Limiting and Concurrency

 The `@request_limit` decorator in `ModelActor` controls concurrent access to inference methods.

 **Behavior:**

 
 - Increments `self._serve_count` on entry.
 - Checks against `self._request_limits`.
 - Raises `RuntimeError` if the limit is exceeded.
 - Decrements count on completion or error.
 
 Sources: [xinference/core/model.py88-170](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/model.py#L88-L170)

 
## Error Handling

 Centralized error handling converts internal exceptions to HTTP status codes:

 
 - `ModelNotReadyError` -> 503 Service Unavailable.
 - `RuntimeError` (Rate limit) -> 429 Too Many Requests.
 - `OutOfMemoryError` -> Handled by `_handle_oom_error` in `ModelActor`.
