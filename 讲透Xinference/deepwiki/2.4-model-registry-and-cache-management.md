## Purpose and Scope

 The Model Registry and Cache Management system is responsible for defining, discovering, and caching model artifacts in Xinference. This document covers:

 
 - **Model Registry**: JSON-based model definitions, built-in and custom model registration, and engine matching logic.
 - **Cache Management**: Download strategies, cache directory structure, version tracking, and storage optimization.
 
 For information about how registered models are instantiated and loaded into memory, see [Request Flow and Lifecycle](https://deepwiki.com/xorbitsai/inference/2.3-request-flow-and-lifecycle). For details on model actor lifecycle management, see [Model Actor Framework](https://deepwiki.com/xorbitsai/inference/2.2-model-actor-framework). For GPU resource allocation during model loading, see [GPU Resource Management](https://deepwiki.com/xorbitsai/inference/2.5-gpu-resource-management).

## Cache Management System

 
### Cache Directory Structure

 Xinference creates symlinks to the underlying hub caches (HuggingFace/ModelScope) to maintain a standardized directory structure while avoiding data duplication.

 
```
XINFERENCE_CACHE_DIR/
├── v2/
│   ├── embedding/
│   │   └── bge-large-en-pytorch-none/    # Symlink to Hub cache
│   │       └── __valid_download         # Validation metadata
│   ├── rerank/
│   │   └── bge-reranker-large-pytorch-none/
│   └── builtin/
│       └── embedding/
│           └── embedding_models.json    # Updated definitions
└── hub/                                 # Raw hub storage
    └── models--BAAI--bge-large-en/
```

### Download Strategies and Hub Selection

 The system detects the user's locale to select the optimal download source. If `XINFERENCE_ENV_MODEL_SRC` is not set, it defaults to `modelscope` for users in China and `huggingface` elsewhere.

 **Hub Priority Mapping:**

 
 - **HuggingFace**: Default global source.
 - **ModelScope**: Preferred in China locale.
 - **Local URI**: Used for custom models via `model_uri` [xinference/model/embedding/tests/test_embedding_models.py173-199](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/embedding/tests/test_embedding_models.py#L173-L199)

### Automated Engine Discovery

 During registration, Xinference iterates through all supported engines and calls their `match()` or `match_json()` methods to determine compatibility.

 
 - **`match()`**: Checks both JSON metadata and whether the required libraries are installed locally.
 - **`match_json()`**: Used when `XINFERENCE_ENABLE_VIRTUAL_ENV` is active; it only verifies metadata compatibility, assuming libraries will be installed on-demand.
