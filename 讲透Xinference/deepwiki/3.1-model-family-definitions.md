## Purpose and Scope

 This page documents the structure and organization of LLM model family definitions in Xinference. Model families are the central metadata system that describes all available models, their capabilities, supported formats, quantization options, and download locations. This page covers the JSON schema in `llm_family.json`, the corresponding Python data classes, and how models are registered and matched to inference engines.

 For information about how these definitions are used during model loading and inference, see [Backend Engines](https://deepwiki.com/xorbitsai/inference/3.2-backend-engines) and [Engine Selection and Matching](https://deepwiki.com/xorbitsai/inference/3.3-engine-selection-and-matching). For custom model registration via the API, see [Custom Model Registration](https://deepwiki.com/xorbitsai/inference/8.1-custom-model-registration).

 
---

 
## Overview

 Model family definitions serve as the single source of truth for all LLM models supported by Xinference. Each model family is defined in JSON format and includes:

 
 - **Model metadata**: name, description, language support, context length
 - **Model abilities**: capabilities like chat, generate, tools, vision, audio, reasoning, and hybrid
 - **Model specifications**: different formats (pytorch, ggufv2, mlx), sizes, and quantizations
 - **Download sources**: HuggingFace, ModelScope, CSGHub, or local paths
 - **Prompt formatting**: chat templates, stop tokens, reasoning tags
 
 The system maintains two categories of model families:

 
 - **Built-in families**: Defined in [xinference/model/llm/llm_family.json](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.json) and loaded at startup.
 - **Custom families**: Registered by users via the API or stored in `XINFERENCE_MODEL_DIR`.

## JSON Structure and Schema

 Each model family is defined as a JSON object. The structure follows the `LLMFamilyV2` schema [xinference/model/llm/llm_family.py169-208](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.py#L169-L208)

 
### Core Fields

 
| Field | Type | Required | Description |
|---|---|---|---|
| version | int | Yes | Schema version, must be 2 xinference/model/llm/llm_family.py170 |
| model_name | string | Yes | Unique identifier for the model xinference/model/llm/llm_family.py172 |
| model_lang | List[string] | Yes | Supported languages (e.g., ["en"]) xinference/model/llm/llm_family.py173 |
| model_ability | List[string] | Yes | Capabilities: "generate", "chat", "tools", "vision", "audio", "omni", "reasoning", "hybrid" xinference/model/llm/llm_family.py174-186 |
| model_description | string | No | Human-readable description xinference/model/llm/llm_family.py187 |
| context_length | int | No | Max context window size (default: 2048) xinference/model/llm/llm_family.py171 |
| model_specs | List[object] | Yes | List of model specification variants xinference/model/llm/llm_family.py190 |

 
### Optional Configuration Fields

 
| Field | Type | Description |
|---|---|---|
| chat_template | string | Jinja2 template for formatting chat messages xinference/model/llm/llm_family.py191 |
| stop_token_ids | List[int] | Token IDs that signal generation stop xinference/model/llm/llm_family.py192 |
| stop | List[string] | String sequences that signal generation stop xinference/model/llm/llm_family.py193 |
| reasoning_start_tag | string | Marker for reasoning content start xinference/model/llm/llm_family.py195 |
| virtualenv | dict | Package dependencies for specific engines xinference/model/llm/llm_family.json82-90 |

## Chat Templates and Prompting

 Xinference manages chat formatting through Jinja2 templates.

 
### Template Application

 The `ChatModelMixin` provides `_compile_jinja_template` using `ImmutableSandboxedEnvironment` to safely render prompts [xinference/model/llm/utils.py159-179](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/utils.py#L159-L179)

 
### Strict System Ordering

 Some models (e.g., Qwen3 family) require the `system` message to be strictly at the beginning. The `STRICT_SYSTEM_FIRST_MARKERS` in `llm_family.py` identify these templates [xinference/model/llm/llm_family.py57-70](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.py#L57-L70) If violated, `check_system_role_order` raises a `MessageRoleOrderError` [xinference/model/llm/utils.py67-90](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/utils.py#L67-L90)

 
### Tool Call Normalization

 For models like Qwen3.5-Coder that require dictionary arguments in templates, `_normalize_tool_call_arguments_to_dict` converts JSON-encoded strings into Python dictionaries before rendering [xinference/model/llm/utils.py192-208](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/utils.py#L192-L208)

## Registry and Engine Selection

 The system maps model families to available backend engines during initialization.

 
### Engine Matching Logic

 The function `generate_engine_config_by_model_family` iterates through all specs and supported engines to populate `LLM_ENGINES` [xinference/model/llm/__init__.py73-127](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/__init__.py#L73-L127)

 
 - **Format Check**: `check_format_with_engine` ensures, for example, that `ggufv2` is only matched with `llama.cpp` or `vLLM` [xinference/model/llm/__init__.py64-71](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/__init__.py#L64-L71)
 - **Class Match**: It calls `cls.match(model_family, spec, quantization)` for each engine class (e.g., `VLLMModel`, `SGLANGModel`) [xinference/model/llm/__init__.py89](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/__init__.py#L89-L89)
 - **Config Storage**: Matches are stored in `LLM_ENGINES[model_name][engine]` including the `llm_class` and supported quantizations [xinference/model/llm/__init__.py112-125](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/__init__.py#L112-L125)
 
 
### Speculative Decoding Support

 Engines like `vLLM` and `SGLang` support engine-neutral speculative decoding options. These are translated from `draft_model_path` and `num_speculative_tokens` in the `VLLMModelConfig` or `SGLANGModelConfig` [xinference/model/llm/vllm/core.py120-122](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L120-L122) [xinference/model/llm/sglang/core.py66-69](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/sglang/core.py#L66-L69)

## Context Length Determination

 Xinference determines context length using a fallback hierarchy:

 
 - **Manual Override**: The `context_length` defined in `llm_family.json` [xinference/model/llm/llm_family.py171](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.py#L171-L171)
 - **Config Discovery**: `get_context_length_from_config` searches model config for keys like `max_position_embeddings`, `max_sequence_length`, or `sliding_window` [xinference/model/llm/utils.py93-132](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/utils.py#L93-L132)
 - **Default**: If no value is found, it defaults to `2048` [xinference/model/llm/llm_family.py45](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.py#L45-L45)
