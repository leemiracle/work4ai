  This glossary defines codebase-specific terms, abbreviations, and domain concepts used within Xinference. It is intended to help onboarding engineers navigate the intersection of distributed actor systems and machine learning inference.

 
## Actor Model Terms

 Xinference is built on **xoscar**, a Python actor framework. This architecture allows for distributed state management and asynchronous communication across nodes.

 
| Term | Definition | Code Pointers |
|---|---|---|
| SupervisorActor | The central orchestrator of a Xinference cluster. Manages worker registration, model placement, and cluster-wide metrics. | xinference/core/supervisor.py127-174 |
| WorkerActor | A node-level manager responsible for launching model instances (ModelActors), monitoring local resources (GPU/CPU), and managing virtual environments. | xinference/core/worker.py255-300 |
| ModelActor | A specialized actor that wraps a specific model instance (e.g., an LLM or Embedding model). It handles inference requests and enforces concurrency limits. | xinference/core/model.py204-250 |
| ActorRef | A proxy object used to communicate with an actor. Calls on a ref are transparently routed to the correct node in the cluster. | xinference/core/supervisor.py130-141 |
| Subpool | A separate process managed by xoscar where actors can be isolated. Xinference uses subpools to isolate model instances and their dependencies. | xinference/core/worker.py65-75 |

 **Sources:** [xinference/core/supervisor.py](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py), [xinference/core/worker.py](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py), [xinference/core/model.py](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/model.py)

## Inference Engine Terms

 Xinference supports multiple backends to execute models. The choice of engine affects performance, hardware compatibility, and supported features.

 
 - **vLLM**: A high-throughput engine for LLM serving using PagedAttention. It is the preferred engine for CUDA-based production serving. 
 - *Implementation:* [xinference/model/llm/vllm/core.py236-280](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/vllm/core.py#L236-L280)
 - **SGLang**: A structured generation engine optimized for complex prompting and fast decoding. 
 - *Implementation:* [xinference/model/llm/sglang/core.py1-50](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/sglang/core.py#L1-L50)
 - **llama.cpp**: A C++ implementation optimized for CPU and Apple Silicon (GGUF format). 
 - *Implementation:* [xinference/model/llm/llm_family.py73-95](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.py#L73-L95)
 - **Transformers**: The HuggingFace library used as a general-purpose fallback engine for PyTorch models. 
 - *Implementation:* [xinference/model/llm/transformers/core.py1-60](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/transformers/core.py#L1-L60)

## Model Format & Registry Terms

 These terms describe how models are defined and stored within the system.

 
| Term | Definition | Code Pointers |
|---|---|---|
| LLM Family | A grouping of model versions (e.g., "llama-3"). Defined in JSON with metadata like chat templates and stop tokens. | xinference/model/llm/llm_family.json1-91 |
| Model Spec | A specific configuration of a model family, including its format (pytorch, gguf, mlx), size, and quantization. | xinference/model/llm/llm_family.py108-133 |
| GGUF | A binary format used primarily by llama.cpp for efficient CPU/GPU inference. | xinference/model/llm/llm_family.py74-82 |
| Quantization | The process of reducing model weights precision (e.g., 4-bit, 8-bit) to save memory. | xinference/model/llm/llm_family.py77 |
| Chat Template | A Jinja2 template used to format raw message dictionaries into the specific string format required by a model. | xinference/model/llm/utils.py159-180 |

 **Sources:** [xinference/model/llm/llm_family.json](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.json), [xinference/model/llm/llm_family.py](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.py), [xinference/model/llm/utils.py](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/utils.py)

## Deployment & Resource Terms

 Terms related to cluster management and hardware utilization.

 
 - **XINFERENCE_ENABLE_VIRTUAL_ENV**: An environment variable that, when enabled, causes the worker to create a dedicated Python `venv` for each model to avoid dependency conflicts. 
 - *Reference:* [xinference/core/worker.py55-57](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py#L55-L57)
 - **Replica**: An instance of a model. Xinference supports running multiple replicas of the same model across different GPUs or workers for load balancing. 
 - *Logic:* [xinference/core/supervisor.py118-126](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py#L118-L126)
 - **ResourceStatus**: A data structure containing CPU, memory, and GPU usage for a specific node. 
 - *Reference:* [xinference/core/resource.py1-50](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/resource.py#L1-L50)
 - **Launch Strategy**: The logic used by the Supervisor to decide which worker should host a new model replica (e.g., `IdleFirstLaunchStrategy`). 
 - *Implementation:* [xinference/core/launch_strategy.py61-65](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/launch_strategy.py#L61-L65)

## API & Protocol Terms

 Terms related to how external clients interact with the Xinference server.

 
 - **RESTfulAPI**: The FastAPI-based entry point for the cluster. It translates HTTP requests into actor messages. 
 - *Implementation:* [xinference/api/restful_api.py160-210](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/restful_api.py#L160-L210)
 - **OpenAI Compatibility**: Xinference provides endpoints that mimic the OpenAI API (e.g., `/v1/chat/completions`) to allow drop-in replacement for existing tools. 
 - *Logic:* [xinference/api/restful_api.py72-93](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/restful_api.py#L72-L93)
 - **SSE (Server-Sent Events)**: The protocol used for streaming tokens during inference. 
 - *Implementation:* [xinference/api/restful_api.py45](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/api/restful_api.py#L45-L45)
 - **Model UID**: A unique identifier assigned to a running model instance, used by clients to route requests. 
 - *Validation:* [xinference/core/utils.py68](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/utils.py#L68-L68)
