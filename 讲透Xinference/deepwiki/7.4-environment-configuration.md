  This document provides a comprehensive technical reference for the environment configuration system in Xinference. It details all `XINFERENCE_ENV_*` variables, their derivations in `constants.py`, and the internal path configuration logic used to manage data, logs, and virtual environments.

 
## Overview

 Xinference employs a centralized configuration pattern where environment variables serve as the primary source of truth. The module [xinference/constants.py](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/constants.py) acts as the registry, transforming raw OS environment strings into typed Python constants used by actors, inference engines, and deployment scripts.

 This system governs:

 
 - **Path Resolution**: Hierarchical directory structure rooted at `XINFERENCE_HOME`.
 - **Resource Limits**: Concurrency control, batch sizes, and GPU sharing policies.
 - **Cluster Stability**: Health check intervals, failure thresholds, and RPC timeouts.
 - **Dependency Isolation**: Virtual environment management and package installation strategies.
 - **Security**: Authentication database paths and IP allowlists.

## Core Path Configuration

 Xinference uses a deterministic path hierarchy. The base path is determined by `XINFERENCE_HOME` (defaulting to `~/.xinference`).

 
### Home Directory Derivation

 The function `get_xinference_home()` not only resolves the path but also injects configuration into the environment for third-party libraries (Hugging Face, ModelScope) to ensure they respect the Xinference storage root.

 
| Constant | Derived Path | Purpose |
|---|---|---|
| XINFERENCE_HOME | $XINFERENCE_HOME | Root directory for all data. |
| XINFERENCE_CACHE_DIR | $HOME/cache | Downloaded model weights and metadata. |
| XINFERENCE_LOG_DIR | $HOME/logs | Component-specific log files. |
| XINFERENCE_AUTH_DIR | $HOME/auth | JWT secrets, encryption keys, and DBs. |
| XINFERENCE_VIRTUAL_ENV_DIR | $HOME/virtualenv | Isolated model environments. |

 Sources: [xinference/constants.py71-93](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/constants.py#L71-L93)

 
### Path Logic Implementation

 In [xinference/constants.py71-81](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/constants.py#L71-L81) the system forces specific cache variables:

 
 - `HUGGINGFACE_HUB_CACHE` is set to `os.path.join(home_path, "huggingface")`.
 - `MODELSCOPE_CACHE` is set to `os.path.join(home_path, "modelscope")`.
 - `XDG_CACHE_HOME` is set to `os.path.join(home_path, "openmind_hub")`.

## Authentication Configuration

 Xinference supports an advanced authentication mode powered by a database-backed service.

 
### Advanced Auth Logic

 The function `is_auth_advanced()` in [xinference/constants.py105-110](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/constants.py#L105-L110) determines if JWT and user management are enabled. If enabled, the system requires two persisted secrets:

 
 - `XINFERENCE_AUTH_JWT_SECRET_KEY`: Used for signing tokens.
 - `XINFERENCE_AUTH_ENCRYPTION_KEY`: Used for encrypting API keys in the DB.
 
 
### Secret Persistence Flow

 The `_get_or_create_persisted_secret` function ensures that secrets are stable across restarts by writing them to `XINFERENCE_AUTH_DIR`.

## Logging and Metrics

 
### Log Rotation

 Logging is configured via `get_config_dict` in [xinference/deploy/utils.py104-112](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/utils.py#L104-L112)

 
 - **Max Bytes**: `XINFERENCE_LOG_MAX_BYTES` (default 100MB).
 - **Backup Count**: `XINFERENCE_LOG_BACKUP_COUNT` (default 30).
 - **Retention**: `XINFERENCE_LOG_RETENTION_DAYS` (default 30).
 
 
### Metrics Export

 The `XINFERENCE_DISABLE_METRICS` variable (checked via `is_metrics_disabled()`) prevents the `launch_metrics_export_server` from starting in the `WorkerActor`.

## Docker Environment Configuration

 The `Dockerfile` provides a reference for a production-ready environment setup.

 
### Docker Runtime Environment

 The image sets up specific system requirements for model virtual environments:

 
 - **Python 3.12**: The runtime interpreter used for all venvs [xinference/deploy/docker/Dockerfile80-85](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L80-L85)
 - **CUDA 13.0**: Provided by the `nvidia/cuda:13.0.2-devel-ubuntu22.04` base image [xinference/deploy/docker/Dockerfile55](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L55-L55)
 - **Build Tools**: `ninja-build` and `build-essential` are included to allow venvs to compile CUDA extensions (JIT) at runtime [xinference/deploy/docker/Dockerfile82](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L82-L82)
 
 
### Pre-installed Packages

 To optimize venv creation, common heavy packages are baked into the system environment:

 
 - `torch`, `torchvision`, `torchaudio` [xinference/deploy/docker/Dockerfile98-99](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L98-L99)
 - `transformers`, `accelerate` [xinference/deploy/docker/Dockerfile128](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/docker/Dockerfile#L128-L128)
 
 This allows the worker to use `XINFERENCE_VIRTUAL_ENV_SKIP_INSTALLED` to drastically reduce model startup time.
