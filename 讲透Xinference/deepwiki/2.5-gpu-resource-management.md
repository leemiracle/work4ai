## Purpose and Scope

 This document explains how Xinference manages GPU resources across workers, models, and inference engines. It covers GPU allocation strategies, device tracking mechanisms, constraints imposed by different backend engines (especially vLLM), and the lifecycle of GPU resource assignment from model launch to termination.

 For information about model lifecycle and actor creation, see [Model Actor Framework](https://deepwiki.com/xorbitsai/inference/2.2-model-actor-framework). For worker coordination and health monitoring, see [Supervisor and Worker System](https://deepwiki.com/xorbitsai/inference/2.1-supervisor-and-worker-system).

 
---

 
## Architecture Overview

 GPU resource management in Xinference is primarily handled by the `WorkerActor` class, which maintains GPU device allocations and ensures that models receive appropriate GPU resources based on their type and backend engine requirements.

## Device Tracking Data Structures

 The `WorkerActor` maintains several data structures to track GPU assignments. A key configuration variable `XINFERENCE_ALLOW_MULTI_REPLICA_PER_GPU` [xinference/constants.py49](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/constants.py#L49-L49) controls whether multiple model replicas can reside on the same GPU.

 
| Data Structure | Type | Purpose |
|---|---|---|
| _total_gpu_devices | List[int] | All GPU device indices visible to this worker xinference/core/worker.py341 |
| _gpu_to_model_uids | Dict[int, List[str]] | Maps GPU index to list of model UIDs xinference/core/worker.py343 |
| _gpu_to_embedding_model_uids | Dict[int, Set[str]] | Maps GPU index to set of embedding/rerank model UIDs xinference/core/worker.py344 |
| _user_specified_gpu_to_model_uids | Dict[int, Set[Tuple[str, str]]] | Maps GPU index to set of (model_uid, model_type) for user-specified allocations xinference/core/worker.py345 |

## vLLM Backend Special Constraints

 vLLM models require exclusive GPU access due to their aggressive KV cache management. Xinference enforces this by checking the model backend type before allowing any sharing [xinference/core/worker.py529-533](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py#L529-L533)

 The function `is_model_vllm_backend(model_uid)` [xinference/core/worker.py529-533](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py#L529-L533) is used to:

 
 - Identify if a running model uses the vLLM engine.
 - Block embedding/rerank models from being co-located on the same GPU [xinference/core/worker.py546-561](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py#L546-L561)
 - Prevent user-specified allocations (`gpu_idx`) from overlapping with vLLM instances [xinference/core/worker.py633-638](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py#L633-L638)

## GPU Resource Lifecycle

 
### Allocation Phase

 The allocation occurs during `launch_builtin_model` or `launch_model`. The worker determines the required number of GPUs and calls the appropriate allocation method [xinference/core/worker.py1040-1080](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py#L1040-L1080)

 
### Release Phase

 When `terminate_model` is called, the worker invokes `release_devices(model_uid)` [xinference/core/worker.py653-676](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py#L653-L676) This method:

 
 - Removes the model UID from `_gpu_to_model_uids`.
 - Clears the UID from `_gpu_to_embedding_model_uids`.
 - Filters the UID out of `_user_specified_gpu_to_model_uids`.

## Performance and Out-of-Memory (OOM) Handling

 Xinference provides an `@oom_check` decorator for `ModelActor` methods [xinference/core/model.py173-202](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/model.py#L173-L202) When a `torch.cuda.OutOfMemoryError` is caught:

 
 - The actor triggers `_handle_oom_error(ex)`.
 - It calls `empty_cache()` [xinference/device_utils.py55](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/device_utils.py#L55-L55) to free fragmented memory.
 - It logs the error and notifies the worker/supervisor of the failure.
