## Purpose and Scope

 Local deployment is the simplest deployment mode for Xinference, running both the cluster coordinator (`SupervisorActor`) and worker components (`WorkerActor`) within a single machine using multiprocessing. This mode is ideal for development, testing, or single-machine inference workloads where distributed coordination across multiple physical nodes is not required.

 This document covers the architecture, startup process, and configuration of local deployment. For distributed deployment across multiple nodes, see [Distributed Deployment](https://github.com/xorbitsai/inference/blob/d97e0970/Distributed Deployment) For environment configuration details, see [Environment Configuration](https://github.com/xorbitsai/inference/blob/d97e0970/Environment Configuration) For CLI usage, see [Command Line Interface](https://github.com/xorbitsai/inference/blob/d97e0970/Command Line Interface)

## Process Architecture

 Local deployment uses a two-process architecture: a main process and a subprocess. This separation provides isolation for the actor pool while keeping the RESTful API server in the main process.

### Process Isolation and CUDA

 The actor pool runs in a subprocess for isolation. The multiprocessing start method is explicitly set to `"spawn"` to ensure clean process initialization, particularly because CUDA may be initialized in the parent process or `xoscar` virtual environment, which can cause errors if sub-pools are created without a fresh process state [xinference/deploy/local.py160-163](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/local.py#L160-L163)

## Component Initialization

 The local deployment initializes the core cluster actors within the subprocess.

 
| Actor | UID | Purpose | Details |
|---|---|---|---|
| SupervisorActor | "supervisor" | Cluster coordination | Routes requests, manages workers, health monitoring xinference/core/supervisor.py |
| WorkerActor | "worker" | Model execution | Manages GPU devices, launches models, creates sub-pools xinference/core/worker.py |

 
### Actor Pool Configuration

 The actor pool is created with `n_process=0` [xinference/deploy/local.py59-63](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/local.py#L59-L63) While the main worker pool doesn't create fixed sub-processes, the `WorkerActor` will dynamically create sub-pools for model isolation when models are launched [xinference/deploy/worker.py30-57](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/worker.py#L30-L57)

### Startup Phases

 
 - **Process Spawning**: The main process creates a `multiprocessing.Pipe()` and spawns the subprocess as a daemon [xinference/deploy/local.py123-150](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/local.py#L123-L150)
 - **Actor Pool Initialization**: The subprocess creates the `SupervisorActor` [xinference/deploy/local.py64-66](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/local.py#L64-L66) and then calls `start_worker_components` to initialize the `WorkerActor` [xinference/deploy/local.py67-74](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/local.py#L67-L74)
 - **Signaling**: Once the pool and actors are ready, the subprocess sends the string `"ok"` through the pipe [xinference/deploy/local.py75-81](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/local.py#L75-L81)
 - **Health Check**: The main process performs a health check by attempting to connect to the supervisor address [xinference/deploy/local.py170-175](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/local.py#L170-L175)
 - **API Server**: Finally, the `restful_api` is started in the main process [xinference/deploy/local.py177-183](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/local.py#L177-L183)

## Configuration and Environment

 Local deployment is typically triggered via the `xinference-local` command.

 
### Key Configuration Parameters

 The `main` function in `xinference/deploy/local.py` accepts:

 
 - `host`: The host address for the API and cluster (default `0.0.0.0` or `127.0.0.1`) [xinference/deploy/local.py154-159](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/local.py#L154-L159)
 - `port`: The port for the RESTful API [xinference/deploy/local.py155](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/local.py#L155-L155)
 - `metrics_exporter_host/port`: Optional Prometheus metrics configuration [xinference/deploy/local.py156-157](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/local.py#L156-L157)
 
 
### Logging

 Xinference uses a specialized logging system to handle multi-process environments.

 
 - `SafeRotatingFileHandler`: A `RotatingFileHandler` subclass that uses `fcntl` file locks to serialize log rotation across multiple processes [xinference/deploy/utils.py47-172](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/utils.py#L47-L172)
 - `XINFERENCE_HOME`: Environment variable to change the default storage directory (defaulting to `~/.xinference`) [doc/source/getting_started/using_xinference.rst38-48](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/using_xinference.rst#L38-L48)

## GPU Resource Management in Local Mode

 Even in a single-process local cluster, `WorkerActor` must manage hardware resources.

 
 - **Device Detection**: `start_worker_components` checks for available devices using `get_available_device_env_name()` (e.g., `CUDA_VISIBLE_DEVICES`) [xinference/deploy/worker.py38-45](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/worker.py#L38-L45)
 - **Allocation**: If environment variables are not set, it defaults to using all GPUs detected by `gpu_count()` [xinference/deploy/worker.py45](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/worker.py#L45-L45)
 - **Worker Assignment**: These indices are passed to the `WorkerActor` during creation [xinference/deploy/worker.py47-57](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/worker.py#L47-L57)

## Comparison with Distributed Deployment

 
| Feature | Local Deployment (xinference-local) | Distributed Deployment |
|---|---|---|
| Process Count | 2 primary processes (Main + Sub) | Multiple nodes (Supervisor + N Workers) |
| Actor Location | Supervisor and Worker in same pool | Supervisor and Workers on different nodes |
| API Server | Runs in the main local process | Runs on the Supervisor node |
| Worker Discovery | Hardcoded to same address | Automatic registration via Supervisor |
