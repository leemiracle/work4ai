  This document explains how to register custom AI models in Xinference, including Large Language Models (LLMs), embedding models, image generation models, and other AI model types. Custom model registration allows users to extend Xinference's built-in model catalog with their own model configurations.

 For information about deploying and managing registered models, see [Deployment](https://github.com/xorbitsai/inference/blob/d97e0970/Deployment) For details about the available inference engines and their capabilities, see [Inference Engine System](https://github.com/xorbitsai/inference/blob/d97e0970/Inference Engine System)

 
## Model Family Structure

 Xinference organizes models into families defined by data structures like `LLMFamilyV2`, `EmbeddingModelFamilyV2`, and `RerankModelFamilyV2`. Each family contains metadata about the model and one or more specifications that define different variants (sizes, quantizations, formats).

### Model Specifications

 Each model family contains specifications that define different variants. Specifications include information about the model hub (Hugging Face, ModelScope), the format (PyTorch, GGUF, MLX), and the URI for local files.

 
| Model Type | Spec Class | Supported Formats |
|---|---|---|
| LLM | LLMSpecV1 (Union) | pytorch, gptq, awq, ggufv2, mlx |
| Embedding | EmbeddingSpecV1 (Union) | pytorch, ggufv2 |
| Rerank | RerankSpecV1 (Union) | pytorch, ggufv2 |

## Registration Process

 Custom models are registered through type-specific registration APIs. The process involves validation, engine compatibility mapping, and optional persistence to the filesystem.

### Key Registration APIs

 
 - **`register_llm(llm_family, persist=True)`**: Registers a custom LLM. If `persist` is true, it saves the config to `XINFERENCE_MODEL_DIR/v2/llm`.
 - **`register_embedding(embedding_family, persist=True)`**: Registers a custom embedding model to `XINFERENCE_MODEL_DIR/v2/embedding`.
 - **`register_rerank(rerank_family, persist=True)`**: Registers a custom rerank model to `XINFERENCE_MODEL_DIR/v2/rerank`.
 - **`unregister_model(model_name)`**: Removes a registered custom model and deletes its persistent config file if it exists.

## Model URI and Local Loading

 Xinference allows launching models directly from a local path without full registration using the `model_path` parameter in the launch API. For formal registration of local models, the `model_uri` field in the specification should be used.

 
### Usage of `model_uri`

 The `model_uri` field supports the `file://` scheme to point to a local directory. When registered, Xinference creates a symbolic link in its cache directory to the location specified by the URI.

## Persistence and Startup Loading

 When Xinference starts, it automatically loads custom models that were previously registered with `persist=True`.

 
 - **Migration**: It first calls `migrate_from_v1_to_v2()` to ensure legacy configurations are updated to the current schema.
 - **Directory Scanning**: It scans `XINFERENCE_MODEL_DIR/v2/{model_type}`.
 - **Loading**: Each JSON file is parsed into its respective `Custom*FamilyV2` class and registered in-memory.

## Engine Compatibility and Virtual Environments

 The registration process triggers `generate_engine_config_by_model_name()`, which determines which inference engines (vLLM, llama.cpp, Transformers, etc.) can run the registered model.

 
### Virtual Environment Support

 Custom models can define a `virtualenv` section to specify Python package dependencies. This allows models requiring specific versions of libraries (like `transformers` or `torch`) to run in isolation.

 
```

```

 If `XINFERENCE_ENABLE_VIRTUAL_ENV` is enabled, Xinference will skip strict local library checks during registration and instead verify format compatibility, assuming dependencies will be installed in the virtual environment at launch time.
