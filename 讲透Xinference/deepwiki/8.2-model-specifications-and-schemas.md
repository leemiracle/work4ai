  This document describes the data structures and schemas that define models in Xinference. These specifications determine how models are registered, cached, launched, and executed across different backends. Understanding these schemas is essential for registering custom models and extending Xinference's model registry.

 For information about registering custom models using these schemas, see [Custom Model Registration](https://deepwiki.com/xorbitsai/inference/8.1-custom-model-registration). For details about chat templates and prompt formatting, see [Chat Templates and Prompt Formatting](https://deepwiki.com/xorbitsai/inference/8.3-chat-templates-and-prompt-formatting).

 
## Overview

 Model specifications in Xinference serve as declarative definitions that describe:

 
 - Model metadata (name, language, abilities)
 - Storage format and quantization options
 - Download sources and revision information
 - Backend engine compatibility
 - Runtime configuration requirements
 
 All model specifications follow a versioned schema system (currently V2) and are stored as JSON files in the codebase or user-defined directories. The specification system supports multiple model types: LLM, embedding, image, audio, video, and rerank.

## LLM Model Family Schema (LLMFamilyV2)

 The `LLMFamilyV2` class defines the top-level specification for large language models.

 
### Core Fields

 
| Field | Type | Description | Required |
|---|---|---|---|
| version | Literal[2] | Schema version identifier | Yes |
| model_name | str | Unique model identifier | Yes |
| model_lang | List[str] | Supported languages (e.g., "en", "zh") | Yes |
| model_ability | List[str] | Model capabilities (chat, generate, tools, vision, reasoning) | Yes |
| model_specs | List[LLMSpecV1] | Format-specific specifications | Yes |
| context_length | Optional[int] | Maximum context window (default: 2048) | No |
| chat_template | Optional[str] | Jinja2 chat template or reference | No |
| reasoning_start_tag | Optional[str] | Start marker for reasoning content | No |
| reasoning_end_tag | Optional[str] | End marker for reasoning content | No |
| virtualenv | Optional[VirtualEnvSettings] | Virtual environment settings | No |

 Sources: [xinference/model/llm/llm_family.py128-181](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.py#L128-L181)

## Rerank Model Family Schema (RerankModelFamilyV2)

 Rerank models use a specific schema that tracks the reranker type (normal, LLM-based, or LLM-based layerwise).

 
| Field | Type | Description |
|---|---|---|
| version | Literal[2] | Schema version |
| model_name | str | Unique name |
| type | Optional[str] | "normal", "LLM-based", or "LLM-based layerwise" |
| max_tokens | Optional[int] | Token limit |
| model_specs | List[RerankSpecV1] | Pytorch or GGUF specs |

 Sources: [xinference/model/rerank/core.py73-84](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/rerank/core.py#L73-L84) [xinference/model/rerank/model_spec.json1-10](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/rerank/model_spec.json#L1-L10)

 
## Image Model Schema (ImageModelFamilyV2)

 Image models (Diffusion and OCR) follow a slightly different pattern where the family often maps directly to a model ID rather than a list of specs.

 
| Field | Type | Description |
|---|---|---|
| model_family | str | e.g., "stable_diffusion" |
| model_name | str | e.g., "FLUX.1-schnell" |
| model_id | str | Hub identifier |
| model_ability | Optional[List[str]] | "text2image", "image2image", "inpainting" |
| gguf_model_id | Optional[str] | GGUF variant ID |
| lightning_model_id | Optional[str] | Lightning/LoRA variant ID |

## Common Schema Fields

 
### model_hub

 Specifies the model registry source:

 
 - `"huggingface"` - HuggingFace Hub (default)
 - `"modelscope"` - ModelScope (Alibaba Cloud)
 - `"openmind_hub"` - OpenMind Hub
 - `"csghub"` - CSGHub
 
 Sources: [xinference/model/utils.py70-90](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/utils.py#L70-L90)
