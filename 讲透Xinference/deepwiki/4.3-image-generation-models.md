  This document describes the image generation model system in Xinference, covering text-to-image, image-to-image, inpainting, and OCR capabilities. For general model type architecture, see [Model Types](https://deepwiki.com/xorbitsai/inference/4-model-types). For API endpoints, see [Inference Endpoints](https://deepwiki.com/xorbitsai/inference/5.2-inference-endpoints). For LLM multimodal image understanding, see [Large Language Models](https://deepwiki.com/xorbitsai/inference/4.1-large-language-models).

 
## Purpose and Scope

 The image generation system enables inference on diffusion-based models (Stable Diffusion, FLUX.1, Qwen-Image) and OCR models (GOT-OCR2, DeepSeek-OCR) through a unified interface. Key features include:

 
 - Support for 20+ built-in image models with text-to-image, image-to-image, and inpainting capabilities.
 - Memory optimization through quantization (GGUF, BitsAndBytes, TorchAO), CPU offloading, and VAE tiling.
 - ControlNet support for conditional image generation.
 - Lightning LoRA for accelerated inference (4-step/8-step generation).
 - Batch scheduling for throughput optimization.
 - OpenAI-compatible API endpoints (`/v1/images/generations`, `/v1/images/variations`).

## Model Specification Schema

 The `ImageModelFamilyV2` class defines the complete specification for image models:

 
| Field | Type | Description |
|---|---|---|
| model_name | str | Unique identifier (e.g., "FLUX.1-dev") |
| model_family | str | Family type ("stable_diffusion", "ocr") |
| model_ability | List[str] | Capabilities: "text2image", "image2image", "inpainting", "ocr" |
| model_id | str | HuggingFace/ModelScope model ID |
| model_revision | str | Git revision or "master" |
| controlnet | List[ImageModelFamilyV2] | Optional ControlNet models |
| default_model_config | dict | Launch-time configuration (quantization, dtype) |
| gguf_model_id | str | Repository for GGUF quantized variants |
| gguf_quantizations | List[str] | Supported quantization levels (Q2_K, Q4_0, etc.) |
| lightning_model_id | str | Lightning LoRA repository |
| lightning_versions | List[str] | Available Lightning versions (4steps-V1.0, etc.) |

## Quantization and Memory Optimization

 Xinference provides several strategies to run large models like FLUX.1 and SD3.5 on consumer hardware.

 
### Quantization Methods

 
 - **GGUF Quantization**: Transformer components can be replaced with GGUF variants (e.g., `flux1-schnell-Q4_0.gguf`) [xinference/model/image/model_spec.json20-34](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/image/model_spec.json#L20-L34)
 - **Text Encoder Quantization**: Leverages `bitsandbytes` to quantize T5-XXL or other text encoders to 8-bit or 4-bit [doc/source/models/model_abilities/image.rst228-230](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/models/model_abilities/image.rst#L228-L230)
 - **Transformer Quantization**: Uses `nf4` or `int8` for the core transformer blocks via `transformer_nf4` parameter [doc/source/models/model_abilities/image.rst234](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/models/model_abilities/image.rst#L234-L234)
 
 
### Memory Optimization Parameters

 
 - `cpu_offload`: Moves components to CPU when not actively executing [doc/source/models/model_abilities/image.rst224-227](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/models/model_abilities/image.rst#L224-L227)
 - `vae_tiling`: Processes large images in tiles to prevent VAE OOM.
 - `sequential_cpu_offload`: An aggressive offloading strategy for extremely low VRAM.

## OpenAI Compatibility (SDAPI)

 Xinference provides a compatibility layer to translate OpenAI-style requests to Diffusers-style parameters.

 
| OpenAI / SD API Arg | Diffusers Arg |
|---|---|
| steps | num_inference_steps |
| cfg_scale | guidance_scale |
| denoising_strength | strength |
| init_images | image |
| mask | mask_image |

 The `SDAPIToDiffusersConverter` [xinference/model/image/sdapi.py22-76](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/image/sdapi.py#L22-L76) handles this mapping, while `SDAPIDiffusionModelMixin` [xinference/model/image/sdapi.py78-167](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/image/sdapi.py#L78-L167) provides the `txt2img` and `img2img` methods that return base64-encoded results compatible with existing Stable Diffusion WebUI integrations.
