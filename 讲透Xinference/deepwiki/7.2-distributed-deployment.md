  Xinference supports distributed deployment across multiple nodes using a supervisor-worker architecture built on the `xoscar` actor framework. This enables horizontal scaling by distributing model execution across multiple GPU-equipped machines while maintaining centralized coordination. For single-machine deployments, see **7.1 Local Deployment**.

 
## Architecture Overview

 The distributed deployment consists of three key components:

 
 - **Supervisor Node**: Runs `SupervisorActor` for cluster coordination, `RESTfulAPI` for HTTP endpoints, and supporting actors (`StatusGuardActor`, `CacheTrackerActor`, `EventCollectorActor`) for monitoring and state management.
 - **Worker Nodes**: Each runs a `WorkerActor` that manages GPU resources, launches model instances via `ModelActor` actors, and executes inference workloads.
 - **Communication Layer**: Uses `xoscar` actor messaging for RPC communication between supervisor and workers, with direct actor references for low-latency model inference.

## GPU Allocation and Subpool Isolation

 Workers implement sophisticated GPU allocation logic to prevent resource conflicts.

 
### GPU Allocation Strategy

 
| Strategy | Function | Logic |
|---|---|---|
| Standard | allocate_devices | Allocates contiguous GPUs for LLM models. |
| Embedding | allocate_devices_for_embedding | Allows sharing GPUs unless a vLLM backend is present. |
| User-Specified | allocate_devices_with_gpu_idx | Honors specific gpu_idx requested by the user. |

 
### Process Isolation

 When a model is launched, the worker creates an isolated subprocess (subpool) to host the model actor. This ensures that `CUDA_VISIBLE_DEVICES` is set correctly for that specific model without affecting other models on the same node.

## Health Checking and Monitoring

 The distributed cluster includes health monitoring to detect and handle node failures.

 
### Startup Health Checks

 Before starting the RESTful API, the supervisor verifies cluster connectivity using `health_check()` from [xinference/deploy/utils.py152-187](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/utils.py#L152-L187) This function attempts to connect to the supervisor actor multiple times:

 
 - `max_attempts`: Defined by `XINFERENCE_HEALTH_CHECK_FAILURE_THRESHOLD` [xinference/deploy/supervisor.py88-89](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/supervisor.py#L88-L89)
 - `sleep_interval`: Defined by `XINFERENCE_HEALTH_CHECK_INTERVAL` [xinference/deploy/supervisor.py89](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/supervisor.py#L89-L89)
 
 
### Log Management

 Distributed nodes use `SafeRotatingFileHandler` to manage logs across multiple processes safely. This handler uses `fcntl` file locking to serialize log rotation, ensuring that multiple subpools writing to the same log directory do not corrupt the files [xinference/deploy/utils.py47-73](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/utils.py#L47-L73)

## Deployment Variants

 
### Docker Deployment

 Xinference provides official Docker images. Starting from **v3.0.0**, the GPU image is a "slim" image based on CUDA 13.0 [doc/source/getting_started/using_docker_image.rst13-22](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/using_docker_image.rst#L13-L22)

 
 - **Virtual Environments**: By default, engines like vLLM are installed into per-model virtual environments at launch time [doc/source/getting_started/using_docker_image.rst46-51](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/using_docker_image.rst#L46-L51)
 - **Shared Memory**: For multi-GPU setups in Docker, `--shm-size=128g` is recommended [doc/source/getting_started/using_docker_image.rst83-85](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/getting_started/using_docker_image.rst#L83-L85)
 
 
### Virtual Environment Management

 To prevent dependency conflicts between different model engines (e.g., different `transformers` versions), Xinference uses `uv` to create isolated environments [doc/source/models/virtualenv.rst135-137](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/models/virtualenv.rst#L135-L137)

 
 - **Toggle**: Enabled by `XINFERENCE_ENABLE_VIRTUAL_ENV=1` [doc/source/models/virtualenv.rst32](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/models/virtualenv.rst#L32-L32)
 - **Optimization**: `XINFERENCE_VIRTUAL_ENV_SKIP_INSTALLED=1` allows the virtualenv to reuse system site-packages like `torch` to save space and time [doc/source/models/virtualenv.rst139-144](https://github.com/xorbitsai/inference/blob/d97e0970/doc/source/models/virtualenv.rst#L139-L144)
