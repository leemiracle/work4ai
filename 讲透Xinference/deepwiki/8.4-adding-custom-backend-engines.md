  This document explains how to implement and register custom inference backend engines in Xinference. A backend engine is responsible for loading models and executing inference requests. Xinference supports multiple engines (vLLM, SGLang, Transformers, llama.cpp, MLX, LMDEPLOY) that can be selected based on model format, quantization, and hardware capabilities.

 For information about registering custom models (not engines), see [Custom Model Registration](https://deepwiki.com/xorbitsai/inference/8.1-custom-model-registration). For model specification schemas, see [Model Specifications and Schemas](https://deepwiki.com/xorbitsai/inference/8.2-model-specifications-and-schemas).

## Engine Architecture Overview

 Xinference uses a pluggable engine architecture where each backend engine is a subclass of a base model class (e.g., `LLM`, `EmbeddingModel`, or `RerankModel`). Engines declare their capabilities through a `match_json()` method, which the system uses to automatically select appropriate engines for each model configuration.

## Core Components

 
### Base Classes for Engines

 Xinference provides base classes for different model types. All engines must inherit from these to ensure API compatibility:

 
| Base Class | Location | Purpose |
|---|---|---|
| LLM | xinference/model/llm/core.py47 | Abstract base for LLM engines |
| EmbeddingModel | xinference/model/embedding/core.py154 | Abstract base for Embedding engines |
| RerankModel | xinference/model/rerank/core.py123 | Abstract base for Rerank engines |

 Each base class requires three critical methods:

 
 - `check_lib()`: Returns `True` if dependencies (like `vllm` or `transformers`) are installed. [xinference/model/llm/core.py72-76](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/core.py#L72-L76) [xinference/model/embedding/core.py177-179](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/embedding/core.py#L177-L179)
 - `match_json()`: Determines if the engine supports a specific JSON model specification. [xinference/model/llm/core.py200-204](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/core.py#L200-L204) [xinference/model/rerank/core.py154-161](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/rerank/core.py#L154-L161)

## Virtual Environment Support

 Xinference allows engines to specify their own dependencies via a `virtualenv` configuration in the `model_spec.json`. This ensures that if a custom engine requires a specific version of a library (e.g., `vLLM >= 0.14.0`), it can be isolated.

 The system uses `_extract_engine_markers_from_packages` to identify which packages belong to which engine.

 
| Engine Marker | Example Requirement | File Reference |
|---|---|---|
| #engine# == "vllm" | #vllm_dependencies# | xinference/model/embedding/model_spec.json39 |
| #engine# == "flag" | FlagEmbedding | xinference/model/embedding/model_spec.json38 |
| #engine# == "llama.cpp" | #llama_cpp_dependencies# | xinference/model/rerank/model_spec.json196 |

## Handling Specialized Model Types

 
### Rerank Engines

 Rerank engines must implement the `rerank()` method. Xinference supports different rerank types like "normal" (cross-encoders) and "LLM-based". The system can auto-detect these types using the tokenizer class name.

 
 - **LLM-based**: Uses `LlamaTokenizerFast` or `GemmaTokenizerFast`. [xinference/model/rerank/core.py193-196](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/rerank/core.py#L193-L196)
 - **Normal**: Uses `XLMRobertaTokenizerFast`. [xinference/model/rerank/core.py196](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/rerank/core.py#L196-L196)
 
 Sources: [xinference/model/rerank/core.py189-207](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/rerank/core.py#L189-L207) [xinference/model/rerank/vllm/core.py154-180](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/rerank/vllm/core.py#L154-L180)

 Embedding engines implement `create_embedding()`. For vLLM-based embedding, Xinference handles specific overrides for models like `Qwen3` (e.g., setting `is_matryoshka: True`).

## Registration and Validation

 To register a custom engine, it must be added to the internal engine mapping (e.g., `EMBEDDING_ENGINES`). The `match_embedding` utility is used to find valid engines for a given embedding model name.
