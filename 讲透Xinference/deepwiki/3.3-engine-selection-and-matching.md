## Purpose and Scope

 This page explains how Xinference automatically selects the optimal backend inference engine for a given model based on its format, quantization, hardware availability, and capabilities. The selection process is transparent to users—when launching a model, Xinference evaluates which engines are compatible and chooses the most appropriate one based on system constraints.

 For details about individual backend engines and their capabilities, see [Backend Engines](https://deepwiki.com/xorbitsai/inference/3.2-backend-engines). For information about model specifications and family definitions, see [Model Family Definitions](https://deepwiki.com/xorbitsai/inference/3.1-model-family-definitions).

 
## Engine Selection Architecture

 Xinference supports multiple backend inference engines (vLLM, SGLang, Transformers, llama.cpp, MLX, LMDeploy), each optimized for different scenarios. The selection process occurs during model launch and involves matching model specifications against engine capabilities.

## Format and Engine Compatibility

 The `check_format_with_engine()` function enforces fundamental compatibility rules between model formats and engines.

 
| Model Format | vLLM | SGLang | Transformers | llama.cpp | MLX |
|---|---|---|---|---|---|
| pytorch | ✓ | ✓ | ✓ | ✗ | ✗ |
| gptq | ✓ | ✓ | ✓ | ✗ | ✗ |
| awq | ✓ | ✓ | ✓ | ✗ | ✗ |
| ggufv2 | ✓ | ✗ | ✗ | ✓ | ✗ |
| mlx | ✗ | ✗ | ✗ | ✗ | ✓ |

 Key constraints:

 
 - **GGUF format** (`ggufv2`) is supported by `llama.cpp` and `vLLM`, but rejected by others. [xinference/model/llm/__init__.py65-70](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/__init__.py#L65-L70)
 - **MLX format** is exclusive to the `mlx` engine. [xinference/model/llm/llm_family.py137-140](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.py#L137-L140)

## Engine Selection During Launch

 When a model is launched, `check_engine_by_spec_parameters()` validates the requested configuration against the `LLM_ENGINES` registry.

 
### Selection Logic

 
 - **Model Lookup**: Verifies if the model exists in the registry. [xinference/model/llm/llm_family.py570-573](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.py#L570-L573)
 - **Engine Normalization**: Converts engine names to a standard format (e.g., "vllm"). [xinference/model/llm/llm_family.py575-577](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.py#L575-L577)
 - **Parameter Matching**: Iterates through the registered configurations for that engine to find a match for `model_format`, `model_size_in_billions`, and `quantization`. [xinference/model/llm/llm_family.py583-597](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/llm_family.py#L583-L597)

## Virtual Environment Support

 Xinference supports running engines in isolated virtual environments. The selection logic accounts for this via `virtual_env_allows_missing_engine()`.

 When `XINFERENCE_ENABLE_VIRTUAL_ENV` is active, engine discovery tolerates missing local library installs because the engine and its dependencies are intended to be installed on-demand within the virtual environment.

 **Sources:** [xinference/model/utils.py110-129](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/utils.py#L110-L129) [xinference/model/utils.py181-186](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/utils.py#L181-L186)

 
## Embedding and Rerank Matching

 Embedding and Rerank models follow a similar pattern but use different registries and specialized matching functions.

 
 - **Embedding**: Uses `EMBEDDING_MODEL_DESCRIPTIONS` and `match_embedding()`. [xinference/model/embedding/core.py32-38](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/embedding/core.py#L32-L38)
 - **Rerank**: Uses `RERANK_MODEL_DESCRIPTIONS` and `match_rerank()`. [xinference/model/rerank/core.py25-35](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/rerank/core.py#L25-L35)
 
 Both types implement `match_json()` in their respective engine classes (e.g., `TransformersEmbeddingModel`, `LlamaCppRerankModel`).

## Summary

 The engine selection system provides:

 
 - **Automatic Discovery**: Built-in models are automatically mapped to all compatible engines at startup.
 - **Strict Validation**: Launch requests are validated against known working configurations.
 - **Hardware Sensitivity**: Engines only match if the underlying hardware (CUDA, Apple Silicon) is detected.
 - **Extensibility**: Custom models registered via `register_llm` are immediately processed by the same engine discovery logic. [xinference/model/llm/__init__.py130-148](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/model/llm/__init__.py#L130-L148)
