## Overview

 The Supervisor and Worker System is the core distributed orchestration layer in Xinference. It implements a supervisor-worker pattern using the `xoscar` actor framework to coordinate model deployment, execution, and lifecycle management across single or multiple nodes. The supervisor acts as the central coordinator that manages workers, routes requests, and maintains cluster state, while workers execute model instances in isolated subprocesses.

 This page covers the distributed coordination infrastructure. For model execution details within workers, see [Model Actor Framework](https://deepwiki.com/xorbitsai/inference/2.2-model-actor-framework). For complete request lifecycle from API to model execution, see [Request Flow and Lifecycle](https://deepwiki.com/xorbitsai/inference/2.3-request-flow-and-lifecycle).

## Core Architecture

 The system consists of a `SupervisorActor` that coordinates multiple `WorkerActor` instances, supported by specialized actors for health monitoring, event tracking, cache management, and progress tracking. All components communicate via `xoscar`'s actor messaging system.

## SupervisorActor

 The `SupervisorActor` is the central coordinator responsible for managing workers, routing model launch requests, tracking cluster state, and maintaining model registries.

 
### Key Responsibilities

 
| Responsibility | Implementation | Key Methods |
|---|---|---|
| Worker Registry | Maintains _worker_address_to_worker dict mapping addresses to actor refs | add_worker(), remove_worker() |
| Model Registry | Tracks running models via _replica_model_uid_to_worker and _model_uid_to_replica_info | launch_model(), get_model() |
| Load Balancing | Selects workers based on configured strategy (default: IdleFirst) | _choose_worker() |
| Health Monitoring | Tracks worker heartbeats and detects failures | _check_dead_nodes() |
| Autostart | Restores model states after supervisor restart | _autostart_models_task() |

 **Sources:** [xinference/core/supervisor.py127-174](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py#L127-L174) [xinference/core/supervisor.py380-401](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py#L380-L401)

 
### Worker Management

 Workers register themselves with the supervisor on startup. The supervisor maintains their status and reverse-ping failure counts to ensure cluster stability.

 
| Field | Type | Purpose |
|---|---|---|
| _worker_address_to_worker | Dict[str, xo.ActorRefType["WorkerActor"]] | Maps worker addresses to actor references |
| _worker_status | Dict[str, WorkerStatus] | Tracks last update time and resource usage |
| _unexpected_down_replicas | Dict[Tuple[str, int], str] | Tracks replicas lost due to worker failure |

 **Sources:** [xinference/core/supervisor.py111-162](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py#L111-L162)

## WorkerActor

 The `WorkerActor` manages model lifecycle, resource allocation, and subprocess isolation on a single node. Each worker executes models in separate `xoscar` subpools.

 
### Key Responsibilities

 
| Responsibility | Implementation | Key Data Structures |
|---|---|---|
| Model Lifecycle | Launch, monitor, terminate models | _model_uid_to_model |
| GPU Allocation | Assign GPUs to models, prevent conflicts | _gpu_to_model_uids, _user_specified_gpu_to_model_uids |
| Subpool Management | Create isolated subprocesses for models | _create_subpool() |
| Health Reporting | Periodic status updates to supervisor | _periodical_report_status() |
| Virtual Environments | Manage isolated Python environments per engine | VirtualEnvManager |

 **Sources:** [xinference/core/worker.py31-136](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py#L31-L136)

### Virtual Environment Management

 Xinference uses `VirtualEnvManager` to ensure that different inference engines (vLLM, SGLang, Transformers) can coexist without dependency conflicts.

 
 - **Package Pinning**: Critical dependencies like `transformers` or `torch` can be pinned to system versions using `#system_torch#` syntax.
 - **Fingerprinting**: The system calculates a hash of packages, variables, and architectures to avoid redundant environment setups.
 - **Offline Support**: Supports installation from local wheel mirrors when `XINFERENCE_VIRTUAL_ENV_OFFLINE_INSTALL` is enabled.

## Model Lifecycle and Data Flow

 
### Launch Sequence

 
 - **API Request**: `RESTfulAPI` receives a launch request and calls `SupervisorActor.launch_model`.
 - **Worker Selection**: Supervisor picks a `WorkerActor` based on the `LaunchStrategy`.
 - **Device Allocation**: Worker calls `allocate_devices` to reserve GPU/CPU resources.
 - **Subpool Creation**: Worker calls `_create_subpool` to spawn a new process.
 - **Model Initialization**: The model is instantiated within the subpool via `create_model_instance`.
 
 **Sources:** [xinference/core/supervisor.py291-340](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py#L291-L340) [xinference/core/worker.py799-850](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py#L799-L850)

 
### Termination Sequence

 
 - **Request**: `SupervisorActor.terminate_model` is called.
 - **Worker Delegation**: Supervisor routes the call to the specific `WorkerActor`.
 - **Resource Release**: Worker calls `release_devices` and removes the subpool via `_main_pool.remove_sub_pool`.
 - **State Cleanup**: Supervisor removes the model from its registry.
 
 **Sources:** [xinference/core/supervisor.py342-378](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/supervisor.py#L342-L378) [xinference/core/worker.py1191-1250](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/core/worker.py#L1191-L1250)

 
## Deployment Modes

 
### Local Deployment

 In local mode, the supervisor and a single worker are started within the same process. This is the default for `xinference-local`.

 **Sources:** [xinference/deploy/cmdline.py95-123](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/cmdline.py#L95-L123) [xinference/deploy/local.py](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/local.py)

 
### Distributed Deployment

 In distributed mode, the `SupervisorActor` and `WorkerActor` are started on different nodes. Workers must be provided with the supervisor's endpoint to register themselves.

 **Sources:** [xinference/deploy/cmdline.py232-296](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/cmdline.py#L232-L296) [xinference/deploy/cmdline.py299-365](https://github.com/xorbitsai/inference/blob/d97e0970/xinference/deploy/cmdline.py#L299-L365)
