## Purpose and Scope

 This document describes how llamafile embeds GGUF model files within ZIP archives to create single-file executables that contain both the inference engine and the model weights. This system enables distribution of complete AI models as standalone executables while maintaining GPU-compatible memory alignment for efficient inference.

 For information about the executable format itself, see [Cosmopolitan Libc Integration](https://deepwiki.com/mozilla-ai/llamafile/7.1-cosmopolitan-libc-integration). For multi-architecture binary creation, see [Multi-Architecture Support](https://deepwiki.com/mozilla-ai/llamafile/7.3-multi-architecture-support).

 
## Overview

 Llamafile uses the PKZIP archive format to embed GGUF model files directly into executables. The key technical requirement is that model weights must be stored **uncompressed** and **aligned** to specific byte boundaries to enable zero-copy memory mapping for GPU operations. The system provides:

 
 - **zipalign utility**: Creates properly aligned ZIP archives.
 - **llamafile_open_gguf API**: Transparently accesses models from files or embedded ZIP archives [llamafile/llamafile.h49](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.h#L49-L49)
 - **Memory mapping**: Zero-copy access to embedded models via `mmap()` [llamafile/llamafile.c214-233](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.c#L214-L233)
 - **ZIP64 support**: Handles models larger than 4GB [llamafile/zip.c21-65](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/zip.c#L21-L65)

## Alignment Requirements

 
### Memory Alignment for GPUs

 
| Platform | Minimum Alignment | Recommended | Reason |
|---|---|---|---|
| Apple Metal | 16KB (16384 bytes) | 64KB | MTLBuffer alignment requirement |
| CUDA/ROCm | 512 bytes | 64KB | Optimal coalesced memory access |
| CPU | System page size | 64KB | Universal page size compatibility |

 The default alignment of **65536 bytes (64KB)** ensures compatibility with all GPU platforms and page-aligned access on all architectures (4KB, 16KB, 64KB pages).

### ZIP Archive Access and Memory Mapping

 The `llamafile_open_zip()` function locates and memory-maps GGUF files within ZIP archives using the following process:

 
 - **Locate EOCD**: Searches backwards for the end-of-central-directory record [llamafile/llamafile.c111-133](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.c#L111-L133)
 - **Read Central Directory**: Loads the ZIP file index into memory [llamafile/llamafile.c143-154](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.c#L143-L154)
 - **Find GGUF Entry**: Iterates through entries to find a match for the requested filename or the first `.gguf` file [llamafile/llamafile.c162-182](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.c#L162-L182)

## ZIP Format Details

 
### Central Directory and ZIP64

 Llamafile supports large models (>4GB) via ZIP64 extensions.

 
 - **ZIP64 EOCD Locator**: Found by searching for `kZipCdir64LocatorMagic` (0x07064b50) [llamafile/llamafile.c116](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.c#L116-L116)
 - **ZIP64 Extra Field**: Used to store 64-bit sizes and offsets when the 32-bit fields in the standard header are set to `0xFFFFFFFFu` [llamafile/zip.c21-65](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/zip.c#L21-L65)
 
 
### Local File Header

 Each entry is preceded by a `LocalFileHeader` [llamafile/zip.h99-110](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/zip.h#L99-L110) The `llamafile_open_zip` function reads this header to find the start of the actual file data [llamafile/llamafile.c195-204](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.c#L195-L204)

## Technical Constraints

 
### Compression Requirement

 Model files **must** be stored uncompressed (`kZipCompressionNone` [llamafile/zip.h66](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/zip.h#L66-L66)). Compressed data cannot be memory-mapped for zero-copy GPU access. The system explicitly checks the compression method and will fail if the model is deflated [llamafile/llamafile.c187-193](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.c#L187-L193)

 
### Alignment Constraints

 If the model content in a ZIP archive is not aligned to at least a 16KB boundary, `llamafile_open_zip` will issue a warning regarding potential GPU performance issues [llamafile/llamafile.c208-212](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.c#L208-L212) This is because certain GPU backends like Apple Metal require specific alignment for `MTLBuffer` creation.
