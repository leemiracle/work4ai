  llamafile provides a multi-layered security system designed to protect the host system from potentially malicious models or exploits in the inference engine. This system leverages Cosmopolitan Libc to provide consistent sandboxing primitives across different operating systems, primarily using `pledge()` and `unveil()` semantics.

 The sandboxing system is active by default in all execution modes (CLI, CHAT, and SERVER) unless a GPU backend is utilized or the user explicitly disables it [docs/security.md8-19](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L8-L19)

 
## The Sandboxing Mechanism

 The core of the llamafile sandbox is built on two OpenBSD-inspired primitives implemented for Linux and OpenBSD within Cosmopolitan Libc:

 
 - **`pledge()`**: Restricts the system calls a process can make to a predefined set of "promises" [llamafile/sandbox.c23-26](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sandbox.c#L23-L26) On Linux, this is implemented using SECCOMP BPF filters [llamafile/sandbox.c24-25](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sandbox.c#L24-L25)
 - **`unveil()`**: Restricts the filesystem paths that a process can see and access [llamafile/sandbox.c27-30](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sandbox.c#L27-L30) On Linux, this utilizes the Landlock LSM (available in kernel 5.13+) [llamafile/sandbox.c28-30](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sandbox.c#L28-L30)
 
 
### Promise Sets

 llamafile uses specific promise sets depending on the operational mode:

 
| Promise Set | Description | Usage in llamafile |
|---|---|---|
| stdio | Basic I/O on open FDs, memory mapping (without PROT_EXEC), futexes, and thread creation. | Required for GGML inference and basic operation llamafile/sandbox.c39-41 |
| rpath | Read-only access to files. | Used to open model weights and the executable's internal ZIP store llamafile/sandbox.c42 |
| wpath | Write access to existing files. | Used for saving chat logs or persistent state llamafile/sandbox.c43 |
| cpath | Create/rename/unlink files. | Used in --chat mode for temporary files llamafile/sandbox.c44 |
| inet | Full IPv4/IPv6 networking (connect and accept). | Standard networking promise llamafile/sandbox.c46 |
| anet | "Async" networking: allows accept() but forbids connect(). | Primary security layer for --server mode on Linux llamafile/sandbox.c47-49 |

## Sandboxing in Different Modes

 
### CLI and Chat Modes

 In these modes, llamafile typically pledges `stdio rpath tty` (CLI) or `stdio rpath wpath cpath tty` (CHAT) [docs/security.md41-43](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L41-L43) This allows the engine to read model weights and interact with the terminal but prevents any outbound network activity. Path confinement is usually not applied here as these modes legitimately read user-chosen files (e.g., via `/upload` or `--image`) [llamafile/sandbox.c140-141](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sandbox.c#L140-L141)

 
### Server Mode

 The server mode utilizes a more complex sandbox to allow network listening while preventing the server from "calling home" or being used as a proxy.

 
 - **Promises**: Typically `stdio anet rpath` on Linux [docs/security.md23-24](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L23-L24)
 - **`anet` Promise**: This Linux-specific extension ensures the process can accept incoming HTTP connections but cannot initiate any outbound connections [llamafile/sandbox.c47-49](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sandbox.c#L47-L49)
 - **Relaxation**: If outbound features like `--rpc` or MCP proxies are used, the promise is relaxed to `inet` to allow `connect()` [docs/security.md74-77](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L74-L77)
 
 
### Path Confinement (`--confine-reads`)

 By default, `unveil()` is not applied because the server might need to open files at request time (like static assets or multimodal media) [docs/security.md37-38](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L37-L38) When `--confine-reads` is passed, llamafile restricts visibility to:

 
 - The executable itself.
 - The directory containing the weights and its shards.
 - Specific directories for media (`--media-path`) or web roots (`--path`) [docs/security.md46-52](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L46-L52)

### The GPU Exception

 GPU backends (CUDA, ROCm, Metal) are loaded dynamically via `cosmo_dlopen()`. Drivers require access to `/dev` nodes and `ioctl` calls that are not covered by standard sandbox promises [llamafile/sandbox.c60-62](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sandbox.c#L60-L62) If a GPU is in use, `llamafile_has_gpu()` returns true, and `sandbox_skip_status()` returns `LLAMAFILE_SANDBOX_GPU`, causing the sandbox to be skipped [llamafile/sandbox.c110-111](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sandbox.c#L110-L111)

 
### Penalty Mode

 On Linux, llamafile configures the sandbox to return `EPERM` (Permission Denied) rather than killing the process on a violation by setting `__pledge_mode = PLEDGE_PENALTY_RETURN_EPERM` [llamafile/sandbox.c120-121](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sandbox.c#L120-L121) This allows blocked syscalls to surface as ordinary I/O errors [docs/security.md89-92](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L89-L92) On OpenBSD, the process is always terminated with `SIGABRT` on violation [llamafile/sandbox.c69-70](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sandbox.c#L69-L70)

## Verification

 The sandbox can be verified manually or via the test suite:

 
 - **Manual Check**: On Linux, checking `/proc/$PID/status` for `Seccomp: 2` indicates the filter is active [docs/security.md122-123](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L122-L123)
 - **Unit Tests**: `tests/sandbox_test.c` (accessible via `make o//tests/sandbox_test`) exercises every promise set and asserts that forbidden operations return `EPERM` [docs/security.md98-106](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L98-L106)
 - **Integration Tests**: `tests/integration/run_tests.sh -m sandbox` verifies end-to-end behavior, including path confinement and the `--unsecure` flag [docs/security.md108-117](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L108-L117)
