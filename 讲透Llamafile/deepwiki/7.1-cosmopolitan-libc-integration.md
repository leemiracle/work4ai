## Purpose and Scope

 This document explains how llamafile integrates Cosmopolitan Libc to create Actually Portable Executables (APE) that run across multiple operating systems and CPU architectures without modification. It covers the APE format, the platform-specific execution flows, and how the build system utilizes the `cosmocc` toolchain to produce polyglot binaries.

 For information about how GGUF models are embedded as ZIP archives within llamafiles, see [Embedded Model Format](https://deepwiki.com/mozilla-ai/llamafile/7.2-embedded-model-format). For details on how both x86_64 and aarch64 binaries coexist, see [Multi-Architecture Support](https://deepwiki.com/mozilla-ai/llamafile/7.3-multi-architecture-support).

 
## Overview of Cosmopolitan Libc

 Cosmopolitan Libc is a C standard library that enables the creation of binaries that run on Linux, macOS, Windows, FreeBSD, OpenBSD, and NetBSD from a single file [docs/index.md19-22](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/index.md?plain=1#L19-L22) llamafile leverages this to collapse the complexity of LLM distribution into a single executable [docs/index.md13-15](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/index.md?plain=1#L13-L15)

 The integration uses the `cosmocc` toolchain (currently version 4.0.2) to compile C/C++ code into the APE format [build/config.mk19-23](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L19-L23)

 llamafile uses the Actually Portable Executable (APE) format, which is a polyglot file interpreted differently by various operating systems.

 The file begins with a shell script shebang, followed immediately by the `MZ` bytes required for Windows PE compatibility. This allows the same file to be run as a script on UNIX or as a native `.exe` on Windows [docs/index.md60-63](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/index.md?plain=1#L60-L63) On UNIX systems, llamafile extracts a small loader program named `ape` to `$TMPDIR/.ape-1.10` which is used to map the model into memory [docs/support.md14-17](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/support.md?plain=1#L14-L17)

## Build System Integration

 The llamafile build system is centered around the `cosmocc` toolchain. It defines the compiler (`cosmocc`), archiver (`ar.ape`), and specialized tools like `zipobj` for embedding data [build/config.mk19-26](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L19-L26)

 
### Toolchain Mapping

 
| Code Entity | File Path | Role |
|---|---|---|
| TOOLCHAIN | $(COSMOCC)/bin/cosmo | Base path for Cosmopolitan tools build/config.mk20 |
| CC | $(TOOLCHAIN)cc | Cosmopolitan C Compiler build/config.mk22 |
| CXX | $(TOOLCHAIN)c++ | Cosmopolitan C++ Compiler build/config.mk23 |
| AR | $(COSMOCC)/bin/ar.ape | APE-compatible static library creator build/config.mk24 |
| ZIPOBJ | $(COSMOCC)/bin/zipobj | Compiles files into COFF/ELF objects for ZIP embedding build/config.mk25 |

 
### Compilation Logic

 The build system uses `TARGET_ARCH = -Xx86_64-mtune=znver4` to target modern x86_64 features while maintaining compatibility via Cosmopolitan's runtime dispatch [build/config.mk33](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L33-L33) For multi-architecture support, the `AR` tool is used to create fat archives containing both x86_64 and aarch64 objects by creating a hidden `.aarch64` directory for ARM components [build/rules.mk68-71](https://github.com/mozilla-ai/llamafile/blob/43551265/build/rules.mk#L68-L71)

 **Sources:** [build/config.mk19-33](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L19-L33) [build/rules.mk68-71](https://github.com/mozilla-ai/llamafile/blob/43551265/build/rules.mk#L68-L71)

 
## Execution and GPU Backend Loading

 Because Cosmopolitan binaries are statically linked for portability, they cannot be pre-linked against platform-specific GPU libraries like CUDA or ROCm. Instead, llamafile uses shell scripts to compile and load GPU support at runtime [Makefile66-80](https://github.com/mozilla-ai/llamafile/blob/43551265/Makefile#L66-L80)

## Sandboxing with Cosmopolitan

 Cosmopolitan Libc provides the `pledge()` and `unveil()` primitives used by llamafile for security [docs/security.md3-5](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L3-L5)

 
| Function | OS Support | Description |
|---|---|---|
| pledge() | Linux (SECCOMP), OpenBSD | Restricts system calls. On by default docs/security.md6-8 |
| unveil() | Linux (Landlock), OpenBSD | Restricts filesystem visibility. Opt-in via --confine-reads docs/security.md9-13 |

 
### Sandbox Promise Sets

 
 - **Server Mode:** Uses `stdio anet rpath` on Linux. `anet` allows `accept()` but prevents `connect()`, blocking outbound exfiltration [docs/security.md23-30](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L23-L30)
 - **CLI Mode:** Runs under `stdio rpath tty` [docs/security.md41](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L41-L41)
 - **Chat Mode:** Runs under `stdio rpath wpath cpath tty` [docs/security.md41-42](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L41-L42)
 
 **Sources:** [docs/security.md3-42](https://github.com/mozilla-ai/llamafile/blob/43551265/docs/security.md?plain=1#L3-L42)

## Build Pipeline and Modes

 The build system supports multiple "modes" (e.g., `make m=dbg`) which are exported to the environment to control output directories and compiler flags [build/config.mk47-60](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L47-L60)

 
| Variable | Definition | Role |
|---|---|---|
| CCFLAGS | -O2 -g -fexceptions ... | Standard C flags for Cosmopolitan build/config.mk31 |
| CPPFLAGS_ | -iquote. -mcosmo ... | Essential Cosmopolitan preprocessor flags build/config.mk32 |
| LINK.o | $(CXX) $(CCFLAGS) ... | The link command using the Cosmopolitan C++ driver build/rules.mk8 |
