## Purpose and Scope

 This document provides a high-level architectural overview of the llamafile system, describing how its major components integrate to enable single-file distribution of Large Language Models with GPU acceleration and HTTP server capabilities. It covers the core integration of llama.cpp, Cosmopolitan Libc, and the execution modes introduced in v0.10.0.

## Core Integration Points

 
### llamafile.h: Central Configuration API

 The `llamafile.h` header defines the system's configuration interface through global `FLAG_` variables. These flags control all aspects of runtime behavior:

 
| Category | Key FLAGS | Purpose |
|---|---|---|
| GPU Control | FLAG_gpu | GPU backend selection (Auto/NVIDIA/AMD/Apple) llamafile/llamafile.h39 |
| Performance | FLAG_precise | Forces precise math in tinyBLAS kernels llamafile/llamafile.h36 |
| UI/UX | FLAG_nologo, FLAG_ascii | Controls branding and startup output llamafile/llamafile.h33-34 |
| Content | FLAG_nothink | Filters reasoning/thinking tokens from output llamafile/llamafile.h35 |
| Security | FLAG_unsecure | Disables pledge/unveil sandboxing llamafile/llamafile.h32 |
| Debugging | FLAG_verbose, FLAG_log_disable | Logging and diagnostic control llamafile/llamafile.h31-40 |

## Compute Backend Architecture

 
### GPU Acceleration and Dynamic Loading

 GPU support is provided via dynamic loading of shared libraries (DSOs). This allows a single binary to support multiple GPU vendors without hard dependencies on proprietary drivers at build time.

 
 - **NVIDIA/AMD**: Handled via `cuda.c`. It attempts to load `ggml-cuda.so` (for NVIDIA) or `ggml-rocm.so` (for AMD) using `cosmo_dlopen`. It uses `gpu_backend_probe` to verify hardware availability before committing to a backend. [llamafile/cuda.c42-82](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/cuda.c#L42-L82)
 - **Apple Silicon**: Handled via `metal.c`. It extracts Metal source files from the embedded ZIP, compiles them into a self-contained dylib using the system compiler, and loads it at runtime. [llamafile/metal.c22-31](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/metal.c#L22-L31)
 - **CPU Optimization**: The `tinyBLAS` suite provides runtime CPU dispatch to architecture-specific SIMD implementations (AVX, AVX2, AVX512, NEON) for matrix multiplication. [llamafile/BUILD.mk175-188](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/BUILD.mk#L175-L188)

## Distribution Model: Actually Portable Executables

 llamafile uses Cosmopolitan Libc to create "Actually Portable Executables" (APE) - single binaries that run on multiple operating systems (Linux, macOS, Windows, FreeBSD) and architectures (x86_64, aarch64).

 
### ZIP weights embedding

 The weights (GGUF models) are embedded inside the executable as uncompressed ZIP entries. The `llamafile_open_zip` function parses the Central Directory of the ZIP file appended to the binary to locate these weights.

## Execution Modes (v0.10.0)

 Version 0.10.0 introduces a unified entry point that manages four primary execution modes via the `ProgramMode` enumeration.

 
| Mode | Flag | Description |
|---|---|---|
| AUTO | Default | Automatically starts the HTTP server and opens a browser UI. llamafile/llamafile.h103 |
| CHAT | --chat | Launches the interactive TUI/REPL mode for local conversation. llamafile/llamafile.h104 |
| SERVER | --server | Starts the OpenAI-compatible HTTP server without opening a browser. llamafile/llamafile.h105 |
| CLI | --cli | Executes a single prompt or batch operation. llamafile/llamafile.h106 |

 **Sources:** [README.md29-36](https://github.com/mozilla-ai/llamafile/blob/43551265/README.md?plain=1#L29-L36) [llamafile/llamafile.h101-107](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.h#L101-L107) [llamafile/chatbot_repl.cpp1-50](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/chatbot_repl.cpp#L1-L50)

## Build System Architecture

 The build system is based on GNU Make and supports multi-architecture builds.

 
 - **Multi-Platform Compilation**: The system uses `cosmocc` to compile C/C++ code into APE format. [llamafile/BUILD.mk63](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/BUILD.mk#L63-L63)
 - **TUI Integration**: When `LLAMAFILE_TUI` is defined, the llama.cpp server's `main()` is renamed to `server_main()` and called by llamafile's `main.cpp`. [llamafile/BUILD.mk55-62](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/BUILD.mk#L55-L62)
 - **Patch Management**: Changes to submodules (llama.cpp, whisper.cpp) are managed via patches to remain compatible and upstreamable. [CONTRIBUTING.md7-8](https://github.com/mozilla-ai/llamafile/blob/43551265/CONTRIBUTING.md?plain=1#L7-L8) [llama.cpp.patches/llamafile-files/BUILD.mk1-5](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/llamafile-files/BUILD.mk#L1-L5)
