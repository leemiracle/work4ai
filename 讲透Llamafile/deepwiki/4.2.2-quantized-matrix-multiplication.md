## Purpose and Scope

 This page documents the IQK (Iwan's Quant Kernels) quantized matrix multiplication implementation for CPU backends. These kernels perform matrix-matrix and matrix-vector multiplication on quantized weight matrices (Q4_0, Q8_0, Q8_K, and other formats) using SIMD-optimized unpacking and computation strategies. The implementation achieves 150-400% speedup over baseline approaches for prompt processing by reusing unpacked quantized values across multiple Q8 columns through sophisticated tiling.

 For floating-point matrix multiplication (F32, F16, BF16), see [CPU GEMM Optimization](https://deepwiki.com/mozilla-ai/llamafile/4.2.1-cpu-gemm-optimization). For GPU-based quantized kernels, see [GPU GEMM Kernels](https://deepwiki.com/mozilla-ai/llamafile/4.3.4-gpu-gemm-kernels).

 **Sources:** [llamafile/iqk_mul_mat.inc61-77](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/iqk_mul_mat.inc#L61-L77)

 
## Supported Quantization Formats

 The IQK kernels support the following quantization formats for the weight matrix (A):

 
| Format | Bits per Weight | Block Size | Architecture Support |
|---|---|---|---|
| Q4_0 | 4-bit | 32 elements | AVX2, AVX512, ARM DOTPROD |
| Q8_0 | 8-bit | 32 elements | AVX2, AVX512, ARM DOTPROD |
| Q8_K | 8-bit | 256 elements | AVX2, AVX512, ARM DOTPROD |
| Q4_K | 4-bit + scales | 256 elements | AVX2, AVX512 (Zen4) |
| Q5_K | 5-bit + scales | 256 elements | AVX2, AVX512 (Zen4) |
| Q6_K | 6-bit + scales | 256 elements | AVX2, AVX512 (Zen4) |
| Q2_K | 2-bit + scales | 256 elements | AVX2, AVX512 (Zen4) |
| Q3_K | 3-bit + scales | 256 elements | AVX2, AVX512 (Zen4) |
| IQ4_XS | 4-bit i-quant | 256 elements | AVX2, AVX512 (Zen4) |

 All formats operate on block-quantized data where each block contains packed integer values and associated scaling factors. The activation matrix (B) is typically quantized to `GGML_TYPE_Q8_0` or `GGML_TYPE_Q8_K` format at runtime for optimal dot product computation.

### Data Flow and Tiling

 The `mul_mat_NxM` function implements a tiling strategy with a default `k_x_step = 64`. This works by partitioning the work into tiles that fit efficiently in CPU caches.

 
 - **Tile Iteration**: The outer loops iterate over columns (`ix`) in steps of 64.
 - **Row Batching**: It batches rows (`iy`) based on the number of available specialized functions in `funcs`.
 - **Kernel Execution**: The specialized kernel (e.g., `funcs.back()`) is called to perform the dot products for the current tile.
 
 **Sources:** [llamafile/iqk_mul_mat.inc125-144](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/iqk_mul_mat.inc#L125-L144)

 
### Memory Mapping and Indirect Addressing

 The `DataInfo` struct provides `src1_row` and `dst_row` methods that support both direct contiguous access and indirect mapping via `mmid_row_mapping`. This indirection is crucial for Mixture of Experts (MoE) where tokens may be routed to non-contiguous expert weights.

 **Sources:** [llamafile/iqk_mul_mat.inc90-118](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/iqk_mul_mat.inc#L90-L118)

 
## SIMD Unpacking Strategies

 
### ARM NEON Optimization

 For ARM architectures, IQK utilizes packed block types to minimize load instructions and ensure correct alignment for NEON intrinsics:

 
 - `block_q8_1_x4`: Groups 4 `block_q8_1` structures.
 - `block_q8_0_x4`: Groups 4 `block_q8_0` structures.
 
 **Sources:** [llamafile/iqk_mul_mat.inc46-57](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/iqk_mul_mat.inc#L46-L57)

 
### Q4 Scale Processing

 The `make_q4_scales` function efficiently unpacks 4-bit scales into 32-bit auxiliary buffers using bitwise shifts and masks, preparing them for vectorized scaling of dot product results.

 **Sources:** [llamafile/iqk_mul_mat.inc150-159](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/iqk_mul_mat.inc#L150-L159)

 
### Bit Manipulation Helpers

 The implementation includes large lookup tables like `keven_signs` (128 entries) to accelerate sign extraction and bit-level manipulations during the unpacking of i-quant and k-quant formats.

 **Sources:** [llamafile/iqk_mul_mat.inc161-176](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/iqk_mul_mat.inc#L161-L176)

 
## Numerical Consistency and Validation

 To ensure that these optimized quantized kernels maintain mathematical parity with standard implementations, llamafile provides the `backend_ops_test` harness. This tool compares the output of the IQK-accelerated CPU path against reference implementations.

 
 - **Gate Mechanism**: The harness wires `test-backend-ops` into llamafile's runtime loading path through functions like `llamafile_has_metal` or `llamafile_has_cuda`.
 - **Toggle**: Users can set `LLAMAFILE_DISABLE_SGEMM=1` to bypass IQK/tinyBLAS and use vanilla GGML code for attribution of numerical discrepancies.
