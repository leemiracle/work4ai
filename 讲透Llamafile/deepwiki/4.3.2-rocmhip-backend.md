  The ROCm/HIP Backend provides GPU acceleration for AMD graphics cards through AMD's ROCm (Radeon Open Compute) platform and HIP (Heterogeneous-compute Interface for Portability) API. This backend enables llamafile to offload tensor operations to AMD GPUs for faster inference by dynamically compiling or loading GGML CUDA kernels translated for AMD hardware.

 **Scope**: This page covers AMD GPU support implementation, including runtime architecture detection, dynamic compilation using `hipcc`, and DSO (Dynamic Shared Object) loading via `cosmo_dlopen`.

 
---

 
## Overview

 The ROCm/HIP backend provides a portable abstraction layer that allows llamafile to run CUDA-based compute kernels on AMD GPUs. The system treats the `ggml-cuda` source as a dual-purpose codebase that is compiled with `hipcc` to target AMD's discrete and integrated GPUs.

## Compilation Process

 When a pre-built DSO is not available, llamafile can compile the ROCm backend at runtime if `hipcc` (Linux) or `clang++.exe` (Windows ROCm SDK) is detected.

 
### The rocm.sh / rocm.bat Build Pipeline

 The scripts automate the parallel compilation of the GGML ROCm backend, combining core GGML CUDA source with llamafile's `tinyblas` kernels.

 
 - **Environment Setup**: 
 - **Linux**: Detects `hipcc` at `/opt/rocm/bin/hipcc` or via `ROCM_PATH` [llamafile/rocm.sh48-56](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.sh#L48-L56)
 - **Windows**: Detects `clang++.exe` via `HIP_PATH` or by searching `C:\Program Files\AMD\ROCm\*` [llamafile/rocm.bat80-94](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.bat#L80-L94)
 - **TinyBLAS Integration**: Copies `tinyblas.h`, `tinyblas.cu`, and `tinyblas-compat.h` to the build directory [llamafile/rocm.sh82-85](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.sh#L82-L85) [llamafile/rocm.bat124-126](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.bat#L124-L126)
 - **Compiler Flags**: 
 - `-DGGML_USE_HIP=1`: Enables HIP-specific code paths in GGML [llamafile/rocm.sh123](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.sh#L123-L123) [llamafile/rocm.bat135](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.bat#L135-L135)
 - `-DGGML_USE_TINYBLAS=1`: Opts for llamafile's optimized GEMM kernels over standard hipBLAS [llamafile/rocm.sh125](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.sh#L125-L125) [llamafile/rocm.bat135](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.bat#L135-L135)
 - `-fPIC -shared`: Required for creating the dynamic library [llamafile/rocm.sh113](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.sh#L113-L113)
 - `--offload-compress`: Shrinks the resulting fat binary by compressing device code [llamafile/rocm.sh128](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.sh#L128-L128) [llamafile/rocm.bat138](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.bat#L138-L138)
 - **Parallel Compilation**: 
 - **Linux**: Uses `compile_gpu_sources_parallel` to build `.cu` files using multiple CPU cores [llamafile/rocm.sh138](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.sh#L138-L138)
 - **Windows**: Uses a small C job runner (`parallel.exe`) to manage concurrent compilation [llamafile/rocm_parallel.bat108-116](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm_parallel.bat#L108-L116)
 - **Linking**: Combines object files into the final `ggml-rocm.so` or `ggml-rocm.dll` [llamafile/rocm.sh148](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.sh#L148-L148) [llamafile/rocm.bat214](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/rocm.bat#L214-L214)

## Runtime Loading and Symbol Mapping

 The backend is loaded dynamically at runtime using Cosmopolitan's `cosmo_dlopen`. This allows the main llamafile executable to remain small while loading the heavy GPU-specific code only when needed.
