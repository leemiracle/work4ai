  llamafile provides a robust HTTP API surface that maintains high compatibility with industry-standard protocols while introducing optimizations for local execution and portability. The server is derived from `llama.cpp` but is heavily patched to support the Cosmopolitan Libc environment, specialized sandboxing, and unified execution modes.

 
## Unified Server Entry Point

 The llamafile server logic is encapsulated in `server_main`, a modified entry point that allows the server to run either as a standalone process or as a background backend for the interactive TUI.

 
### Implementation Details

 The server implementation in [llama.cpp.patches/patches/tools_server_server.cpp.patch38-44](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/patches/tools_server_server.cpp.patch#L38-L44) replaces the standard `llama_server` with `server_main`. This function accepts optional callbacks:

 
 - `on_ready`: Invoked when the HTTP server is fully initialized and the model is loaded [llama.cpp.patches/patches/tools_server_server.cpp.patch41](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/patches/tools_server_server.cpp.patch#L41-L41)
 - `on_shutdown_available`: Provides the caller with a handle to trigger a graceful termination [llama.cpp.patches/patches/tools_server_server.cpp.patch42](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/patches/tools_server_server.cpp.patch#L42-L42)

## API Endpoints

 llamafile supports three primary API surfaces, served by default at `http://localhost:8080`.

 
### 1. OpenAI-Compatible API

 The primary endpoint for integration is `/v1/chat/completions`. It supports:

 
 - **Streaming**: Server-sent events (SSE) for real-time token generation.
 - **Vision**: Multi-modal inputs via base64 encoded images in the `messages` array.
 - **Tool Calling**: Integration for function calling, supported by patches to the `llama.cpp` server logic.
 
 
### 2. Anthropic Messages API

 llamafile provides compatibility for applications designed for the Anthropic Messages API, mapping these requests internally to the underlying GGML inference engine.

 
### 3. Local Web UI

 A user-friendly chatbot interface is available at the root URL (`/`). The assets for this UI are fetched from Hugging Face during the build process and embedded into the binary.

 
| Endpoint | Method | Description |
|---|---|---|
| /v1/chat/completions | POST | OpenAI-compatible chat completion |
| /v1/models | GET | Lists available loaded models |
| /health | GET | Returns server status (ready/loading/error) |
| /tokenize | POST | Converts text to model-specific tokens |
| /detokenize | POST | Converts tokens back to text |

## Web UI Asset Management

 The web UI is a Svelte/PWA application. llamafile uses a specialized script `fetch-ui-assets.sh` to download prebuilt assets from the `ggml-org/llama-ui` Hugging Face bucket [llama.cpp.patches/fetch-ui-assets.sh4-9](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/fetch-ui-assets.sh#L4-L9)

 
 - **Compression**: To minimize binary size, every asset is gzip-compressed and stored in a `_gzip/` mirror directory [llama.cpp.patches/fetch-ui-assets.sh11-14](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/fetch-ui-assets.sh#L11-L14)
 - **Embedding**: The `tools/ui/embed.cpp` utility bakes these files into `ui.cpp` and `ui.h` for static serving by the embedded server [llama.cpp.patches/fetch-ui-assets.sh8-9](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/fetch-ui-assets.sh#L8-L9)
 - **Fallback**: If assets cannot be fetched, the build generates a "no-asset" `ui.cpp`, allowing the server to function without the UI [llama.cpp.patches/fetch-ui-assets.sh16-18](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/fetch-ui-assets.sh#L16-L18)

## llamafile-Specific Patches

 The `llama.cpp` server is modified via several patches to handle the unique requirements of the Actually Portable Executable (APE) format and the Cosmopolitan runtime.

 
### Threading and Signal Handling

 To prevent process termination during signal interrupts, worker threads in `httplib.cpp` and `server-models.cpp` block signals. This ensures that `pthread_cond_timedwait` (used by `condition_variable::wait`) is not interrupted by `EINTR`, which can cause `libcxx` to terminate the process [llama.cpp.patches/patches/vendor_cpp-httplib_httplib.cpp.patch8-22](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/patches/vendor_cpp-httplib_httplib.cpp.patch#L8-L22) [llama.cpp.patches/patches/tools_server_server-models.cpp.patch67-82](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/patches/tools_server_server-models.cpp.patch#L67-L82)

 
### Futex Timeout Workaround

 On macOS (XNU), untimed futex waits in Cosmopolitan Libc can expire after approximately 72 minutes. llamafile patches `server-models.cpp` and `httplib.cpp` to replace `cond.wait()` with `cond.wait_for()` using a 30-second interval to prevent `ETIMEDOUT` exceptions [llama.cpp.patches/patches/tools_server_server-models.cpp.patch16-30](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/patches/tools_server_server-models.cpp.patch#L16-L30) [llama.cpp.patches/patches/vendor_cpp-httplib_httplib.cpp.patch32-38](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/patches/vendor_cpp-httplib_httplib.cpp.patch#L32-L38)

 
### Multi-modal Memory Management

 The server logic is patched to account for the memory requirements of multi-modal projection models (`mmproj`). When `params.fit_params` is enabled, the server calculates the size of the projection model tensors and reserves extra GPU VRAM to prevent allocation failures during request time [llama.cpp.patches/patches/common_common.cpp.patch104-120](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/patches/common_common.cpp.patch#L104-L120)

### SSL and CA Root Support

 llamafile enables SSL support via `mbedtls`. A key patch in `httplib.cpp` uses `__static_yoink("ssl_root_support")` to ensure that the Mozilla CA roots, zipped into the APE, are included by the linker [llama.cpp.patches/patches/vendor_cpp-httplib_httplib.cpp.patch46-52](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/patches/vendor_cpp-httplib_httplib.cpp.patch#L46-L52) This provides a trust-store fallback on hosts without a system CA store, such as Windows [llama.cpp.patches/patches/vendor_cpp-httplib_httplib.cpp.patch49-50](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp.patches/patches/vendor_cpp-httplib_httplib.cpp.patch#L49-L50)
