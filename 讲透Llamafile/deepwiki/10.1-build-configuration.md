  The build configuration system defines the toolchain, compiler flags, environment variables, and build parameters used throughout the llamafile compilation process. This page documents `build/config.mk`, which establishes the foundation for all compilation activities, including the integration of the Cosmopolitan Libc toolchain and the extraction of versioning metadata from the underlying `llama.cpp` core.

 
## Overview

 The build configuration is centralized in `build/config.mk`, which is included by the main `Makefile` before any build rules or package-specific definitions are processed [Makefile12-14](https://github.com/mozilla-ai/llamafile/blob/43551265/Makefile#L12-L14) This file establishes:

 
 - **Version Metadata**: Extracts GGML and llama.cpp versioning for backend compatibility [build/config.mk8-12](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L8-L12)
 - **Toolchain Selection**: Points to the Cosmopolitan Libc compiler suite (version 4.0.2) [build/config.mk19-20](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L19-L20)
 - **Compiler Flags**: Defines optimization, C++ standard compliance, and architecture targeting [build/config.mk30-33](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L30-L33)
 - **Build Environment**: Ensures deterministic builds via environment variable exports [build/config.mk54-60](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L54-L60)
 
 **Sources:** [build/config.mk1-76](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L1-L76) [Makefile12-14](https://github.com/mozilla-ai/llamafile/blob/43551265/Makefile#L12-L14)

 
## Version Metadata Extraction

 The build system programmatically extracts version information from the `llama.cpp` submodule to ensure that GPU backends and compiled objects remain synchronized with the core inference engine.

 
| Variable | Extraction Source | Purpose |
|---|---|---|
| GGML_VERSION_MAJOR | llama.cpp/ggml/CMakeLists.txt | Major version of the GGML tensor library build/config.mk8 |
| GGML_VERSION | Combined Major.Minor.Patch | Full version string for runtime checks build/config.mk11 |
| GGML_COMMIT | git rev-parse --short HEAD | Specific git hash for build traceability build/config.mk12 |

 These variables are passed as environment variables to GPU build scripts (e.g., `cuda.sh`, `rocm.sh`, `vulkan.sh`) to ensure shared libraries match the host executable's expectations [Makefile65-80](https://github.com/mozilla-ai/llamafile/blob/43551265/Makefile#L65-L80)

 **Sources:** [build/config.mk8-12](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L8-L12) [Makefile65-80](https://github.com/mozilla-ai/llamafile/blob/43551265/Makefile#L65-L80)

 
## Toolchain Configuration

 
### Cosmopolitan Toolchain

 The build system uses Cosmopolitan Libc version 4.0.2 as the compiler toolchain [build/config.mk19](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L19-L19) This toolchain enables "Actually Portable Executable" (APE) binaries that run natively on multiple operating systems (Linux, macOS, Windows, FreeBSD) without modification.

### Toolchain Acquisition and Verification

 If the toolchain is missing, `make` triggers the `.cosmocc/4.0.2` target which executes `build/download-cosmocc.sh` [build/config.mk75-76](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L75-L76) The script performs several critical steps:

 
 - **Dependency Check**: Ensures `unzip` and either `wget` or `curl` are available [build/download-cosmocc.sh27-75](https://github.com/mozilla-ai/llamafile/blob/43551265/build/download-cosmocc.sh#L27-L75)
 - **Bootstrap Hash**: If `sha256sum` is missing, the script compiles a minimal implementation from `build/sha256sum.c` using the host's system compiler [build/download-cosmocc.sh40-64](https://github.com/mozilla-ai/llamafile/blob/43551265/build/download-cosmocc.sh#L40-L64)
 - **Verification**: Validates the downloaded ZIP against a hardcoded SHA256 sum (`85b8c37a406d...`) [build/download-cosmocc.sh9-11](https://github.com/mozilla-ai/llamafile/blob/43551265/build/download-cosmocc.sh#L9-L11) [build/download-cosmocc.sh94-95](https://github.com/mozilla-ai/llamafile/blob/43551265/build/download-cosmocc.sh#L94-L95)

## Compiler and Linker Flags

 
### Architecture Targeting

 The `TARGET_ARCH` variable [build/config.mk33](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L33-L33) controls architecture-specific optimizations. The `-Xx86_64-mtune=znver4` flag optimizes for AMD Zen 4 microarchitecture, enabling advanced features like AVX-512 and VNNI where available.

 Note that `llamafile` uses multi-architecture compilation rules. While `TARGET_ARCH` sets defaults, `build/rules.mk` defines logic to produce `.aarch64` variants for ARM systems by creating subdirectories and invoking the toolchain with appropriate flags [build/rules.mk68-71](https://github.com/mozilla-ai/llamafile/blob/43551265/build/rules.mk#L68-L71)

 **Sources:** [build/config.mk33](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L33-L33) [build/rules.mk68-71](https://github.com/mozilla-ai/llamafile/blob/43551265/build/rules.mk#L68-L71)

 
### Global Flags

 
| Category | Flag Variable | Values / Purpose |
|---|---|---|
| Optimization | CCFLAGS | -O2 -g -fexceptions -ffunction-sections -fdata-sections -mclang build/config.mk31 |
| C++ Standard | CXXFLAGS | -frtti -std=gnu++23 (Enables modern C++ features) build/config.mk30 |
| Preprocessor | CPPFLAGS_ | -iquote. -mcosmo -DGGML_MULTIPLATFORM -DLLAMAFILE_DEBUG build/config.mk32 |
| Archiver | ARFLAGS | rcsD (Deterministic archive creation) build/config.mk29 |

 The `-ffunction-sections` and `-fdata-sections` flags [build/config.mk31](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L31-L31) are critical for minimizing binary size, as they allow the linker to discard unused code paths during the final link stage.

 **Sources:** [build/config.mk29-33](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L29-L33)

 
## Environment and Build Determinism

 To ensure that builds are reproducible (the same source produces the same binary hash), the configuration exports specific environment variables:


 
 - **`LC_ALL`**: Standardizes locale to prevent variations in text processing/sorting [build/config.mk55](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L55-L55)
 - **`SOURCE_DATE_EPOCH`**: Pins the Unix timestamp to 0 (1970-01-01) for all generated files to ensure consistent metadata [build/config.mk56](https://github.com/mozilla-ai/llamafile/blob/43551265/build/config.mk#L56-L56)

## Component Integration

 `build/config.mk` serves as the foundation, but the actual build graph is constructed by including component-specific logic. If not performing a setup task, the main `Makefile` includes the following in order:

 
 - `build/config.mk`: Toolchain and flags [Makefile13](https://github.com/mozilla-ai/llamafile/blob/43551265/Makefile#L13-L13)
 - `build/rules.mk`: Pattern rules for `.c`, `.cpp`, `.o`, and `.a` files [Makefile14](https://github.com/mozilla-ai/llamafile/blob/43551265/Makefile#L14-L14)
 - `third_party/BUILD.mk`, `llama.cpp/BUILD.mk`, `llamafile/BUILD.mk`, etc.: Component-specific source lists and local targets [Makefile16-25](https://github.com/mozilla-ai/llamafile/blob/43551265/Makefile#L16-L25)
 - `build/deps.mk`: Generated header dependencies [Makefile158](https://github.com/mozilla-ai/llamafile/blob/43551265/Makefile#L158-L158)
