## Purpose and Scope

 This document describes llamafile's performance monitoring and resource management systems. These systems prevent performance degradation through intelligent CPU core allocation, thermal throttling prevention, and mandatory architecture verification. The primary components are:

 
 - **Core Management**: Thread-aware CPU core allocation to prevent oversubscription.
 - **Temperature Monitoring**: Thermal governance for benchmark stability.
 - **CPU Feature Verification**: Early-stage validation of hardware capabilities to prevent illegal instruction crashes via `llamafile_check_cpu()`.
 - **CPU Description**: Runtime identification of the host processor and its utilized SIMD capabilities.
 
 For general debugging and diagnostics beyond performance monitoring, see [11.1 Floating-Point Exception Debugging](https://github.com/mozilla-ai/llamafile/blob/43551265/11.1 Floating-Point Exception Debugging) For HTTP server performance and slot management, see [5.4 Slot Management](https://github.com/mozilla-ai/llamafile/blob/43551265/5.4 Slot Management)

## CPU Feature Verification

 Before execution begins, llamafile performs a mandatory check of the host CPU's capabilities. This prevents the application from crashing with a `SIGILL` (Illegal Instruction) if it was compiled for a higher microarchitecture than the host provides.

 
### Implementation and Data Flow

 The check is implemented as a high-priority constructor that runs before `main()` and before C++ global objects are initialized. The function `llamafile_check_cpu()` is provided as a linker hook to ensure the constructor in `check_cpu.c` is included in the final binary.

### Verified Instruction Sets

 The system checks for the following features if they were required at build time (detected via `X86_NEED` macros):

 
 - **SIMD Extensions**: SSE3, SSSE3, AVX, AVX2, AVX512F, AVX512VBMI. [llamafile/check_cpu.c51-74](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/check_cpu.c#L51-L74)
 - **Math Accelerators**: FMA (Fused Multiply-Add), F16C (Half-precision conversion), AVX512_VNNI (Vector Neural Network Instructions). [llamafile/check_cpu.c63-77](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/check_cpu.c#L63-L77)
 
 If a required feature is missing, `on_missing_feature` prints a diagnostic message suggesting compatible hardware (e.g., Intel post-2013 or AMD post-2017 for AVX2) and terminates the process immediately via `_Exit(1)`. [llamafile/check_cpu.c34-45](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/check_cpu.c#L34-L45)

## CPU Identification and Capability Reporting

 The `llamafile_describe_cpu()` function provides a human-readable string identifying the host processor and the specific math kernels currently in use. This is used in logs and benchmarking headers to ensure results are contextually accurate.

 
### Host Identification Logic

 The function uses architecture-specific methods to extract the CPU model name:

 
 - **x86_64**: Uses the `cpuid` instruction with leaves `0x80000002` through `0x80000004` to retrieve the processor brand string. [llamafile/compute.cpp48-59](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/compute.cpp#L48-L59)
 - **ARM/Linux**: Parses `/proc/cpuinfo` for the "model name" or "Model" fields. [llamafile/compute.cpp61-82](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/compute.cpp#L61-L82)
 
 
### Feature Annotation

 The model string is appended with the specific compute capabilities being utilized:

 
 - **SGEMM Kernel**: Appends the name of the active TinyBLAS kernel (e.g., `(AVX2)`, `(AVX512F)`) via `llamafile_sgemm_name()`. [llamafile/compute.cpp89-95](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/compute.cpp#L89-L95)
 - **Fallback Detection**: 
 - On x86, it uses `__cpu_march` to identify the microarchitecture subtype. [llamafile/compute.cpp98-105](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/compute.cpp#L98-L105)
 - On ARM, it uses `getauxval(AT_HWCAP)` to detect specific features like `+fp16` (ASIMDHP) or `+dotprod` (ASIMDDP). [llamafile/compute.cpp108-119](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/compute.cpp#L108-L119)

## Core Management System

 The `CoreManager` class coordinates CPU core allocation across multiple threads to prevent resource contention. It ensures that threads do not oversubscribe available CPU cores, which would degrade performance through excessive context switching.

### Core Allocation API

 The `CoreManager` provides a two-parameter acquisition interface:

 
| Function | Parameters | Purpose |
|---|---|---|
| acquire(need, greed) | need: minimum cores requiredgreed: maximum cores desired | Acquires CPU cores, blocking until need is satisfied, then opportunistically taking up to greed. |
| release(count) | count: number of cores to return | Returns cores to the pool and signals waiting threads. |

 The `acquire` method implements a two-phase strategy:

 
 - **Blocking Phase**: Acquires cores until `need` is satisfied, blocking on a condition variable if insufficient cores are available. [llamafile/core_manager.cpp45-56](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/core_manager.cpp#L45-L56)
 - **Opportunistic Phase**: Attempts to acquire additional cores up to `greed` using non-blocking `pthread_mutex_trylock`. [llamafile/core_manager.cpp58-69](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/core_manager.cpp#L58-L69)

## Temperature Monitoring and Thermal Governance

 The temperature monitoring system prevents thermal throttling during benchmarks by waiting for the CPU temperature to drop below a configured threshold before proceeding.

### Configuration and Reading

 The system is controlled via environment variables:

 
 - `LLAMAFILE_TEMPERATURE_FILE`: Path to a Linux sysfs temperature sensor (e.g., `/sys/class/hwmon/hwmon3/temp1_input`). [llamafile/govern.cpp43](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/govern.cpp#L43-L43)
 - `LLAMAFILE_TEMPERATURE_MAX`: Maximum threshold in millidegrees Celsius (e.g., `60000` for 60°C). [llamafile/govern.cpp33](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/govern.cpp#L33-L33)
 
 The `llamafile_read_temperature()` function performs a raw read of the sysfs file and converts the string to an integer. [llamafile/govern.cpp42-55](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/govern.cpp#L42-L55)

 
### Governance Loop and Backoff

 The `llamafile_govern()` function implements an exponential backoff to minimize polling overhead. The delay starts at 1 microsecond and doubles per iteration until it reaches a cap of 16,384 microseconds. [llamafile/govern.cpp71-85](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/govern.cpp#L71-L85)
