  The llamafile integration test suite is a Python-based framework leveraging `pytest` to validate the end-to-end behavior of the system. Unlike unit tests, which verify individual components, integration tests execute the full `llamafile` binary across its various operational modes, including CLI, TUI, and Server API modes.

 
## Test Infrastructure Overview

 The testing harness ensures that the `llamafile` executable—built using Cosmopolitan Libc for multi-platform support—behaves consistently across different execution paths and hardware configurations.

 
### The `run_tests.sh` Harness

 The primary entry point for running integration tests is `tests/integration/run_tests.sh` [tests/integration/README.md113-120](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/README.md?plain=1#L113-L120) This script manages the Python environment (often via `uv`), model weight availability, and `pytest` invocation. For comprehensive testing across multiple model families, `tests/run_integration_tests.sh` iterates through a list of pre-defined models and filters [tests/run_integration_tests.sh5-30](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/run_integration_tests.sh#L5-L30)

 
### Core Components

 
 - **Full Binary Execution**: Tests run the actual compiled binary, such as `o/llamafile/llamafile` [tests/run_integration_tests.sh34](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/run_integration_tests.sh#L34-L34)
 - **LlamafileRunner**: A utility class in `tests/integration/utils/llamafile.py` that abstracts subprocess management, server polling, and log capturing [tests/integration/utils/llamafile.py112-206](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/utils/llamafile.py#L112-L206)
 - **Execution Modes**: Tests cover the four primary modes: `AUTO`, `CHAT`, `SERVER`, and `CLI` [llamafile/main.cpp25-30](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/main.cpp#L25-L30)
 
 
## Test Categories and Implementation

 The integration suite is divided into functional categories using `pytest` markers [tests/integration/pyproject.toml18-35](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/pyproject.toml#L18-L35)

 
### 1. CLI and TUI Tests

 
 - **CLI Mode**: Validates that passing `--cli` and `-p` (prompt) returns expected text output directly to `stdout` [tests/integration/tests/test_cli.py12-17](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_cli.py#L12-L17) It also tests the `--nothink` flag which filters reasoning content [llamafile/args.cpp85-86](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/args.cpp#L85-L86) [tests/integration/tests/test_cli.py50-60](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_cli.py#L50-L60)
 - **TUI/Chat Mode**: Tests interactive REPL behavior by piping input files containing user prompts and commands like `/exit` [tests/integration/utils/llamafile.py94-98](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/utils/llamafile.py#L94-L98) It verifies multi-turn conversation memory and multimodal uploads [tests/integration/tests/test_multimodal.py84-95](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_multimodal.py#L84-L95)
 
 
### 2. Server API Tests

 These tests focus on the embedded HTTP server capabilities.

 
 - **OpenAI Compatibility**: Validates the `/v1/chat/completions` endpoint and verifies JSON response integrity via `LlamafileRunner.chat_completion` [tests/integration/utils/llamafile.py228-258](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/utils/llamafile.py#L228-L258)
 - **Combined Mode**: Verifies that the TUI and Server can operate simultaneously, ensuring the server remains responsive during active TUI generation [tests/integration/tests/test_combined.py37-82](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_combined.py#L37-L82)
 
 
### 3. Tool Calling and Multimodal Tests

 
 - **Tool Calling**: Uses the `tool_calling` marker to verify that models can correctly invoke function definitions via the API [tests/integration/pyproject.toml21](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/pyproject.toml#L21-L21)
 - **Multimodal (Vision)**: Validates image processing by feeding images via the `--image` flag in CLI mode [tests/integration/tests/test_multimodal.py24-33](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_multimodal.py#L24-L33) or the `/upload` command in TUI mode [tests/integration/tests/test_multimodal.py84-95](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_multimodal.py#L84-L95) It also tests the OpenAI-compatible image completion API [tests/integration/tests/test_multimodal.py124-148](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_multimodal.py#L124-L148)
 
 
### 4. GPU Acceleration Tests

 Gated by the `gpu` marker, these tests verify compute backends (CUDA, ROCm, Metal) [tests/integration/tests/test_gpu.py124-126](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_gpu.py#L124-L126)

 
 - **Offloading**: The `check_gpu_in_output` function scans `llamafile` log output for patterns like `offloaded X/Y layers to GPU` or `using device` to confirm hardware utilization [tests/integration/tests/test_gpu.py49-112](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_gpu.py#L49-L112)
 - **Device Detection**: `get_available_gpu()` detects available hardware (Apple Silicon, NVIDIA, or AMD) and ensures the `--gpu` flag correctly targets the backend [tests/integration/tests/test_gpu.py14-46](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_gpu.py#L14-L46)
 
 
### 5. SSL and Help Tests

 
 - **HTTPS Serving**: Tests serving over TLS using `--ssl-cert-file` and `--ssl-key-file` [tests/integration/tests/test_ssl.py115-147](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_ssl.py#L115-L147)
 - **HTTPS Model Download**: Verifies client-side TLS support by downloading models from Hugging Face via `--hf-repo` [tests/integration/tests/test_ssl.py171-206](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_ssl.py#L171-L206)
 - **Help Delegation**: Ensures that `--help` correctly displays both llamafile-specific flags and the full catalog of llama.cpp options by delegating to `common_params_parse` [llamafile/main.cpp107-128](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/main.cpp#L107-L128) The suite asserts that specific llama.cpp flags like `--top-k` and `--ctx-size` are present in the output [tests/integration/tests/test_help.py48-55](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_help.py#L48-L55)

## Execution Markers

 The test suite uses markers in `pyproject.toml` to categorize tests [tests/integration/pyproject.toml18-35](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/pyproject.toml#L18-L35):

 
| Marker | Description |
|---|---|
| gpu | Tests GPU acceleration (NVIDIA, AMD, Apple). |
| thinking | Targets models with reasoning traces (QwQ, DeepSeek-R1). |
| tool_calling | Requires a tool-capable model. |
| server | Tests HTTP API endpoints. |
| ssl | Tests HTTPS serving and model downloads. |
| bare_executable | Tests requiring a binary without an embedded model. |
| determinism | Requires reproducible output at temperature=0. |
| multimodal | Requires a vision-capable model. |

 
## Continuous Integration (CI)

 The CI environment executes these tests to ensure no regressions in core functionality. The `help` and `ssl` tests are specifically designed to run against "bare" executables (those without embedded models) to verify the APE loading and argument delegation logic [tests/integration/tests/test_help.py141-152](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_help.py#L141-L152)
