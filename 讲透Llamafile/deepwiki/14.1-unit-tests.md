  The llamafile unit test suite provides low-level validation for critical performance kernels, GPU backend robustness, and security primitives. These tests ensure numerical parity across different CPU architectures and GPU vendors, verify the integrity of the sandboxing system, and prevent regressions in optimized mathematical routines.

 The test infrastructure is managed via `tests/BUILD.mk` and `tests/sgemm/BUILD.mk`, integrating both standard C/C++ unit tests and specialized benchmarking utilities.

 
## CPU Numerical Parity (fa_helpers_test)

 The `fa_helpers_test` is designed to catch numerical regressions in alternative AVX-512F implementations used for flash-attention. It compares `llamafile_fa_vec_dot_f16` and `llamafile_fa_fp16_to_fp32_row` against the upstream `ggml` reference implementations using random and edge-case inputs [tests/BUILD.mk53-62](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/BUILD.mk#L53-L62)

 This test is critical because llamafile ships specialized AVX-512F kernels that bypass standard paths to optimize for specific hardware like AMD Zen4 [tests/BUILD.mk66-74](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/BUILD.mk#L66-L74) Specifically, the `llamafile_fa_simd_gemm_amd_avx512f` implementation wraps `simd_gemm` from `simd-gemm.h` to leverage 16-lane zmm registers and a 4x4 tile configuration, providing significantly higher throughput on Skylake-X+ CPUs [llamafile/fa_simd_gemm_amd_avx512f.cpp4-17](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/fa_simd_gemm_amd_avx512f.cpp#L4-L17)

 
### Implementation Details

 
 - **Data Flow**: Randomly generated F16 tensors are passed to both the `llamafile` optimized helpers and the reference `ggml` functions.
 - **Verification**: The test asserts bitwise or near-bitwise equivalence. On CPUs lacking AVX-512F support, the test calls `llamafile_fa_vec_dot_f16_unsupported` or `llamafile_fa_simd_gemm_unsupported`, which return `false` to signal fallback to upstream `ggml` [llamafile/fa_helpers_unsupported.cpp16-29](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/fa_helpers_unsupported.cpp#L16-L29)

## GPU Backend Robustness (gpu_backend_test)

 The `gpu_backend_test` exercises the shared probing logic defined in `gpu_backend.c`. This test was specifically introduced to validate the fix for issue #988, ensuring that a GPU DSO (Dynamic Shared Object) that loads but contains no usable devices does not block the system from falling back to CPU [tests/gpu_backend_test.cpp21-25](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/gpu_backend_test.cpp#L21-L25)

 
### Crash Guard and Probe Validation

 The test uses "test doubles" and injected stub entry points to simulate various GPU driver behaviors without requiring actual hardware [tests/gpu_backend_test.cpp26-32](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/gpu_backend_test.cpp#L26-L32) The core probing logic in `gpu_backend_probe` uses a signal guard (`gpu_run_guarded`) to catch `SIGSEGV` or `SIGABRT` during driver initialization, which is common when a DSO attempts to initialize a broken or unsupported driver [llamafile/gpu_backend.c144-157](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/gpu_backend.c#L144-L157)

 
| Test Case | Simulated Behavior | Expected Outcome |
|---|---|---|
| dc_two | Reports 2 devices tests/gpu_backend_test.cpp67 | Backend accepted and registered tests/gpu_backend_test.cpp143-150 |
| dc_zero | Reports 0 devices tests/gpu_backend_test.cpp68 | Backend rejected and unlinked tests/gpu_backend_test.cpp154-161 |
| dc_segv | Driver crashes during init tests/gpu_backend_test.cpp74-77 | Signal guard catches crash; backend rejected llamafile/gpu_backend.c176-184 |

## Sandbox Verification (sandbox_test)

 The `sandbox_test` verifies the enforcement of `pledge()` and `SECCOMP` filters. It forks child processes to install specific promise sets used by the llamafile server and CLI modes, asserting that unauthorized syscalls are blocked with `EPERM`.

 
### Verified Promise Sets

 
 - **stdio rpath**: Used by CLI/Chat modes. Allows reading model weights but blocks network and filesystem writes.
 - **stdio anet**: Used by Server mode. Allows `accept()` on existing sockets but blocks outbound `connect()` calls.
 - **unveil**: Verifies filesystem confinement using Landlock (Linux) or `unveil()` (OpenBSD). Ensures files outside the allowed path are hidden.

## Matrix Multiplication Kernels (sgemm/iqk)

 The tests in `tests/sgemm/` focus on the correctness of TinyBLAS kernels and Integer Quantized Kernels (IQK). These include multithreaded CPU matrix multiplication for contiguous use cases where $C = A^T \times B$ [llamafile/tinyblas_cpu_sgemm.inc32-35](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas_cpu_sgemm.inc#L32-L35)

 
### Legacy Quantization (iqk_legacy_test)

 This test targets legacy GGML types (`Q4_0`, `Q4_1`, `Q5_0`, `Q5_1`) processed through the IQK path. It specifically addresses layout mismatches and bit-masking bugs in dequantizers, reproducing issue #922 [tests/sgemm/iqk_legacy_test.cpp4-10](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/sgemm/iqk_legacy_test.cpp#L4-L10)

 
### Implementation of `test_type`

 The `test_type` function in the legacy test performs the following flow:

 
 - **Quantization**: Converts source float data into the target quantized format (e.g., `Q4_1`) [tests/sgemm/iqk_legacy_test.cpp122-125](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/sgemm/iqk_legacy_test.cpp#L122-L125)
 - **Execution**: Runs the `iqk_mul_mat` kernel (or `iqk_mul_mat_arm82` on ARM) [tests/sgemm/iqk_legacy_test.cpp51-66](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/sgemm/iqk_legacy_test.cpp#L51-L66)
 - **Reference**: Dequantizes the data and performs a high-precision double-precision matrix multiplication [tests/sgemm/iqk_legacy_test.cpp166-174](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/sgemm/iqk_legacy_test.cpp#L166-L174)
 - **Comparison**: Validates the result against an error threshold, checking for `NaN` or `Inf` values [tests/sgemm/iqk_legacy_test.cpp182-195](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/sgemm/iqk_legacy_test.cpp#L182-L195)

## Build and Execution

 The test suite is built using the `TESTS` package in the main Makefile. Manual benchmark tests for SGEMM are separated into `tests/sgemm/BUILD.mk` because they involve large matrices and require manual inspection of ULP comparisons [tests/sgemm/BUILD.mk7-11](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/sgemm/BUILD.mk#L7-L11)

 
| Target | Description | Dependencies |
|---|---|---|
| o/$(MODE)/tests/fa_helpers_test | AVX-512 numerical test | sgemm.o, fa_helpers_amd_avx512f.o tests/BUILD.mk63-89 |
| o/$(MODE)/tests/gpu_backend_test | Probe and Crash Guard test | gpu_backend.o tests/BUILD.mk110-111 |
| o/$(MODE)/tests/sandbox_test | pledge/SECCOMP validation | sandbox.o tests/BUILD.mk133-134 |
| o/$(MODE)/tests/sgemm | Benchmark and correctness suite | TINYBLAS_CPU_OBJS, GGML_OBJS, llamafile.o tests/sgemm/BUILD.mk20-23 |
