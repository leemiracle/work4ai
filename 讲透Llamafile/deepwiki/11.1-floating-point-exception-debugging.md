## Purpose and Scope

 The floating-point exception (FPE) debugging system provides robust error detection, reporting, and recovery mechanisms for numerical instabilities that occur during model inference. This system traps floating-point exceptions (divide-by-zero, overflow, invalid operations) at the hardware level, provides detailed diagnostic information including computation graph dumps and stack traces, and implements architecture-specific recovery strategies to allow execution to continue.

 This page covers FPE trap handling, exception recovery, and diagnostic tooling. It also details the **Flash-Attention (FA) helper debugging** and optimization layer introduced to resolve performance regressions on x86 CPUs lacking native FP16 hardware acceleration.

 
---

 
## System Architecture

 The FPE debugging system operates at the signal handler level, intercepting hardware floating-point exceptions before they terminate the process. When enabled via the `FLAG_trap` configuration flag, the system installs a SIGFPE handler that captures exception context, diagnoses the issue, and optionally recovers by disabling the specific trap that triggered.

 
### Core Components

 
| Component | Purpose | Thread Safety |
|---|---|---|
| FLAG_trap | Global flag to enable FPE trapping | Read-only after init |
| llamafile_debug_op_index | Thread-local operation index in graph | Thread-local |
| llamafile_debug_graph | Pointer to current GGML computation graph | Thread-local |
| g_underflowed | Atomic counter for underflow events | Atomic |
| on_sigfpe() | Signal handler for SIGFPE | Signal-safe |
| recover() | Architecture-specific FPU state recovery | Signal-safe |

## Flash-Attention Helper Debugging (Issue #975)

 A specialized debugging and optimization effort was implemented to handle performance issues in the CPU Flash-Attention (FA) path. On x86 hardware without `AVX512-FP16` (e.g., Skylake-X, Zen 4), the standard `ggml-cpu` FA path was found to be significantly slower than non-FA paths due to frequent `f16<->f32` round-trips.

 
### FA Optimization Dispatch

 The `llamafile/sgemm.cpp` dispatcher provides optimized AVX-512F helpers that bypass the baseline AVX2 implementations in `ggml-cpu/ops.cpp`. These helpers are implemented in architecture-specific files and return `true` if the operation was handled by the optimized kernel, allowing the caller to fall back to generic code otherwise.

 
| Function | Implementation File | Purpose |
|---|---|---|
| llamafile_fa_vec_dot_f16_amd_avx512f | llamafile/fa_helpers_amd_avx512f.cpp25-53 | AVX-512F unrolled dot product for F16 using _mm512_fmadd_ps |
| llamafile_fa_fp16_to_fp32_row_amd_avx512f | llamafile/fa_helpers_amd_avx512f.cpp55-67 | Vectorized F16 to F32 conversion using _mm512_cvtph_ps |
| llamafile_fa_simd_gemm_amd_avx512f | llamafile/fa_simd_gemm_amd_avx512f.cpp24-33 | 4x4 tiled GEMM using 16-lane ZMM registers via simd_gemm |
| llamafile_fa_simd_gemm_unsupported | llamafile/fa_helpers_unsupported.cpp26-29 | Fallback stub returning false for non-AVX512 hardware |

 
### Automatic Recovery Strategy

 In `llama.cpp/src/llama-context.cpp`, llamafile implements a patch to automatically disable Flash Attention on CPU-only systems to prevent performance degradation unless explicitly requested by the user.

## Exception Trapping and Detection

 The system traps three classes of floating-point exceptions defined by the `TRAPS` macro:

 
 - **FE_INVALID**: Invalid operations (NaN generation, sqrt of negative)
 - **FE_DIVBYZERO**: Division by zero
 - **FE_OVERFLOW**: Result exceeds representable range

## Architecture-Specific Recovery

 The `recover()` function manipulates FPU control registers to disable traps and clear exception flags, allowing execution to resume.

 
### x86_64 Recovery

 On x86_64, the system manipulates the MXCSR register through the `fpregs` field of the signal context:

 
 - `mxcsr |= (traps << 7)`: Set mask bits to disable traps.
 - `mxcsr &= ~traps`: Clear exception flags.
 
 
### ARM64 Recovery

 On ARM64, the system walks the `__reserved` area of the ucontext to locate the `fpsimd_context` (identified by `FPSIMD_MAGIC`), then:

 
 - `fpcr &= ~(traps << 8)`: Disable trap enable bits in Control Register.
 - `fpsr &= ~traps`: Clear exception flags in Status Register.

## GGML Graph Dumping

 When an FPE occurs and `llamafile_debug_graph` is non-NULL, the system dumps the entire GGML computation graph to `/tmp/cgraph.txt`.

 
### Graph Dump Format

 The `print_graph()` function outputs each node in the graph: `<index> <tensor_addr> <type>:<op>(<src0_type>:<src0_op>[<src0_addr>], ...)`

## Underflow Monitoring

 Underflow exceptions (`FPE_FLTUND`) are common during quantized inference and do not typically indicate bugs. Instead of dumping diagnostics, the system displays a visual "check engine light" on the terminal using ANSI escape sequences (`UNDERFLOW_ALARM`).

 
### Underflow Handling Logic

 The atomic `g_underflowed` variable tracks the last underflow timestamp across all threads, ensuring the alarm doesn't flicker excessively (minimum `UNDERFLOW_DELAY` of 2ms).

## Regression Testing

 Numerical-equivalence tests for the optimized Flash-Attention helpers are provided in `tests/fa_helpers_test.cpp`. These tests compare the optimized AVX-512 kernels against `ggml_vec_dot_f16` and `ggml_fp16_to_fp32_row` reference implementations.

 
| Test Case | Code Reference | Purpose |
|---|---|---|
| fp16_to_fp32_row_normal_inputs | tests/fa_helpers_test.cpp160-181 | Validates bit-identical conversion for normal f16 values. |
| fp16_to_fp32_row_edge_values | tests/fa_helpers_test.cpp183-203 | Validates handling of ±0, ±INF, denormals, and NaN. |
| vec_dot_f16 | tests/fa_helpers_test.cpp205-231 | Validates dot product within ULP tolerance using vec_dot_tol. |

 The test suite uses `ASSERT_BITEQ_F32` [tests/fa_helpers_test.cpp87-102](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/fa_helpers_test.cpp#L87-L102) for bitwise comparisons and `ASSERT_NEAR_F32` [tests/fa_helpers_test.cpp104-118](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/fa_helpers_test.cpp#L104-L118) for reductions where floating-point summation order might vary between SIMD widths.
