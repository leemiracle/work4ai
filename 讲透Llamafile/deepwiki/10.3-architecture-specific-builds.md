## Purpose and Scope

 This document explains how llamafile compiles the same source code multiple times with different compiler optimization flags to create architecture-specific variants optimized for different CPU microarchitectures. At runtime, the appropriate variant is selected based on CPU feature detection.

 For information about:

 
 - The overall build system and Makefile structure, see [Build System](https://github.com/mozilla-ai/llamafile/blob/43551265/Build System) [10.1]
 - Cross-platform fat binaries (AMD64 + ARM64), see [Multi-Architecture Support](https://github.com/mozilla-ai/llamafile/blob/43551265/Multi-Architecture Support) [7.3]
 - CPU backend implementation and execution, see [CPU Backend](https://github.com/mozilla-ai/llamafile/blob/43551265/CPU Backend) [4.2]
 - CPU GEMM optimization details, see [CPU GEMM Optimization](https://github.com/mozilla-ai/llamafile/blob/43551265/CPU GEMM Optimization) [4.2.1]
 
 
## Overview

 Performance-critical matrix multiplication kernels are compiled multiple times from the same source code with progressively more aggressive SIMD instruction flags. This creates a collection of specialized object files (e.g., `tinyblas_cpu_sgemm_amd_avx2.o`, `tinyblas_cpu_sgemm_amd_zen4.o`). At startup, CPU feature detection (CPUID on x86_64, `getauxval()` on ARM) determines which variant to use, selecting the most advanced implementation supported by the running CPU [llamafile/sgemm.cpp64-133](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sgemm.cpp#L64-L133)

 This approach enables a single binary to achieve near-optimal performance across CPUs spanning two decades of microarchitecture evolution, from 2003 AMD K8 processors through 2023 Zen4 and Intel Alder Lake systems [llamafile/sgemm.cpp78-119](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sgemm.cpp#L78-L119)

### Feature Detection Logic

 The selection cascade ensures the most advanced supported variant is chosen using `X86_HAVE` macros [llamafile/sgemm.cpp65-119](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sgemm.cpp#L65-L119)

 
```
IF X86_HAVE(AVX512F) + X86_HAVE(AVX512_VNNI) + X86_HAVE(AVX512_BF16):
    → zen4 (AMD Zen4 2023+)
ELSE IF X86_HAVE(AVX512F):
    → avx512f (Intel Xeon Skylake+ 2015+)
ELSE IF X86_HAVE(AVXVNNI):
    → avxvnni (Intel Alder Lake 2021+)
ELSE IF X86_HAVE(AVX2):
    → avx2 (Intel Haswell 2013+)
ELSE IF X86_HAVE(FMA):
    → fma (AMD Piledriver 2011+)
ELSE IF X86_HAVE(AVX):
    → avx (Intel Sandy Bridge 2010+)
ELSE:
    → unsupported (AMD K8/Intel Nehalem)
```

 **Sources:** [llamafile/sgemm.cpp65-119](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sgemm.cpp#L65-L119)

### Fallback Mechanism

 If no optimized kernel is available for the host CPU (e.g., an extremely old x86 processor), the system dispatches to `llamafile_sgemm_unsupported`, which returns `false` [llamafile/tinyblas_cpu_unsupported.cpp22-26](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas_cpu_unsupported.cpp#L22-L26) This signals the GGML graph evaluator to fall back to its generic, non-optimized reference implementations [llamafile/sgemm.cpp117-119](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sgemm.cpp#L117-L119)
