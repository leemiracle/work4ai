## Purpose and Scope

 This page documents the GPU kernel implementations for General Matrix Multiplication (GEMM) operations in the tinyBLAS library. These kernels execute on NVIDIA CUDA and AMD ROCm/HIP GPUs to perform high-performance matrix multiplication operations (`C = α*A*B + β*C`). The implementations use block tiling, warp tiling, and shared memory optimization to approach cuBLAS-level performance [llamafile/tinyblas.cu32-39](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L32-L39)

 For the overall GPU backend architecture and dynamic loading mechanisms, see [GPU Backends](https://deepwiki.com/mozilla-ai/llamafile/4.3-gpu-backends). For CPU-based matrix multiplication, see [CPU GEMM Optimization](https://deepwiki.com/mozilla-ai/llamafile/4.2.1-cpu-gemm-optimization).

 The tinyBLAS GPU implementation provides specialized kernels with increasing complexity based on problem size and batching requirements.

## Block Tiling Kernel (matmul_block2d)

 The `matmul_block2d` kernel implements a block-tiled matrix multiplication suitable for small to medium matrices and batched operations. Each thread block processes a `BM×BN` tile of the output matrix [llamafile/tinyblas.cu143-145](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L143-L145)

 **Kernel Configuration**

 The block kernel uses template parameters to control tile sizes:

 
 - **BM, BN**: Block dimensions (typically 16×16) [llamafile/tinyblas.cu143](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L143-L143)
 - **BK**: K-dimension block size (equals `THREAD_COUNT`) [llamafile/tinyblas.cu147](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L147-L147)
 - **TM, TN**: Per-thread tile dimensions (typically 4×4) [llamafile/tinyblas.cu143](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L143-L143)
 
 **Algorithm Steps**:

 
 - **Load A and B tiles into shared memory** - Each thread loads data into `As` and `Bs` arrays [llamafile/tinyblas.cu185-192](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L185-L192)
 - **Synchronize threads** - `__syncthreads()` ensures shared memory is ready [llamafile/tinyblas.cu194](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L194-L194)
 - **Compute outer product** - Each thread computes a `TM×TN` tile using values from shared memory [llamafile/tinyblas.cu196-204](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L196-L204)
 - **Accumulate in registers** - Results accumulate in `Ct[TM * TN]` array [llamafile/tinyblas.cu170](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L170-L170)
 - **Write results** - After all K iterations, write `Ct` to global memory with alpha/beta scaling [llamafile/tinyblas.cu209-225](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L209-L225)

## Matrix-Vector Specialization (matvec)

 When multiplying a matrix by a vector (`n=1`), a specialized kernel achieves better performance through warp-level reduction [llamafile/tinyblas.cu81-128](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L81-L128)

 **Conditions for Use** [llamafile/tinyblas.cu131-137](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L131-L137):

 
 - `n == 1` (vector output)
 - `k >= 4096` (long enough for efficiency)
 - `!(m % WARPSIZE)` (m divisible by 32)
 - `!(k % WARPSIZE)` (k divisible by 32)
 - `isone(alpha) && !beta` (no scaling)

## Compatibility Layer

 TinyBLAS provides a compatibility header `tinyblas-compat.h` that allows the `ggml` CUDA backend to use TinyBLAS as a drop-in replacement for cuBLAS by mapping `cublas*` types and functions to `tinyblas*` equivalents [llamafile/tinyblas-compat.h20-30](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas-compat.h#L20-L30)

 **Key Mappings**:

 
 - `cublasHandle_t` → `tinyblasHandle_t` [llamafile/tinyblas-compat.h42](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas-compat.h#L42-L42)
 - `cublasSgemm` → `tinyblasSgemm` [llamafile/tinyblas-compat.h60](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas-compat.h#L60-L60)
 - `cublasGemmEx` → `tinyblasGemmEx` [llamafile/tinyblas-compat.h62](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas-compat.h#L62-L62)
 - `cublasStrsmBatched` → `tinyblasStrsmBatched` [llamafile/tinyblas-compat.h154](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas-compat.h#L154-L154)
 
 **Precision Warning**: TinyBLAS does not support BF16 (bfloat16). The compatibility layer maps `CUDA_R_16BF` to `TINYBLAS_R_16F`, but this will produce incorrect results due to different bit layouts. The backend is expected to check `GGML_USE_TINYBLAS` and disable BF16 paths [llamafile/tinyblas-compat.h103-113](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas-compat.h#L103-L113)

## Data Type Support

 The kernels support multiple precision levels through template instantiation [llamafile/tinyblas.cu560-642](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L560-L642)

 **Supported Combinations** [llamafile/tinyblas.cu591-641](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/tinyblas.cu#L591-L641):

 
| Input (A, B) | Output (C) | Compute Type | Use Case |
|---|---|---|---|
| half | half | half (16F) | Maximum throughput |
| half | half | float (32F) | Better accuracy |
| half | float | float (32F) | Mixed precision |
| float | float | float (32F) | Full precision |
