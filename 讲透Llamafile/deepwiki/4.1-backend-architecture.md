## Purpose and Scope

 This document describes llamafile's compute backend abstraction layer, which enables runtime selection between CPU and GPU acceleration backends (CUDA, ROCm, Metal, and Vulkan). The architecture uses dynamic loading, function pointers, and runtime feature detection to support multiple compute devices without requiring compile-time backend selection.

 For details on specific backend implementations, see [CPU Backend](https://deepwiki.com/mozilla-ai/llamafile/4.2-cpu-backend) and [GPU Backends](https://deepwiki.com/mozilla-ai/llamafile/4.3-gpu-backends). For the overall compute system overview, see [Compute Backends](https://deepwiki.com/mozilla-ai/llamafile/4-compute-backends).

## Robust Backend Probing

 A critical challenge in dynamic loading is handling driver initialization that may crash or hang. Llamafile implements two distinct mechanisms to protect the main process during hardware probing.

 
### Crash Guard (In-Process)

 The `gpu_run_guarded()` function uses `sigsetjmp` and signal handlers (`SIGSEGV`, `SIGABRT`, etc.) to trap faults during the call to `get_device_count`. If the driver faults, the system recovers cleanly and marks the backend as unavailable. This mechanism is specifically tested to ensure that a 0-device backend is rejected and unlinked so that `AUTO` mode can fall back to the next available backend [tests/gpu_backend_test.cpp154-161](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/gpu_backend_test.cpp#L154-L161)

 **Sources:** [llamafile/gpu_backend.c159-215](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/gpu_backend.c#L159-L215) [tests/gpu_backend_test.cpp143-170](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/gpu_backend_test.cpp#L143-L170)

 
### Out-of-Process Probe (OOP)

 On Windows, in-process recovery from SEH/C++ exceptions thrown by drivers can leave the process in a corrupted state. Llamafile solves this by spawning a short-lived child process (a re-exec of the binary) specifically to call the driver's device count function.

 
 - **Parent** calls `gpu_backend_probe_oop()` [llamafile/gpu_backend.c284-331](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/gpu_backend.c#L284-L331)
 - **Parent** spawns a child with a special environment variable `LLAMAFILE_GPU_PROBE` [llamafile/gpu_backend.c303-311](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/gpu_backend.c#L303-L311)
 - **Child** attempts to load the DSO and call `get_device_count`.
 - **Child** exits with the device count as the return code (or crashes).
 - **Parent** reads the exit status via `waitpid` [llamafile/gpu_backend.c317-323](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/gpu_backend.c#L317-L323)
 
 **Sources:** [llamafile/gpu_backend.c284-331](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/gpu_backend.c#L284-L331) [llamafile/gpu_backend.h108-118](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/gpu_backend.h#L108-L118)

## Runtime Detection and Selection

 
### GPU Configuration Flags

 The `FLAG_gpu` variable controls the selection logic. It supports explicit overrides and an "AUTO" mode.

 
| Value | Constant | Implementation Logic |
|---|---|---|
| 0 | LLAMAFILE_GPU_AUTO | Try Metal (if Apple), then CUDA, then ROCm, then Vulkan llamafile/cuda.c107-118 |
| 1 | LLAMAFILE_GPU_AMD | Force ROCm llamafile/cuda.c114 |
| 2 | LLAMAFILE_GPU_APPLE | Force Metal llamafile/metal.c286 |
| 4 | LLAMAFILE_GPU_NVIDIA | Force CUDA llamafile/cuda.c109 |
| 8 | LLAMAFILE_GPU_VULKAN | Force Vulkan llamafile/vulkan.c63 |

### Metal Dynamic Compilation

 Unlike other backends, Metal is compiled at runtime on macOS. It extracts source files from the embedded ZIP [llamafile/metal.c93-133](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/metal.c#L93-L133) and invokes the system compiler to produce a self-contained dylib [llamafile/metal.c23-27](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/metal.c#L23-L27) This is necessary because the Metal backend must include a subset of GGML to resolve symbols correctly when loaded via `cosmo_dlopen` [llamafile/metal.c29-30](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/metal.c#L29-L30)
