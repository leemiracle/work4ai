## Purpose and Scope

 This page documents the configuration flags that control model loading, GPU acceleration, context management, and runtime behavior in llamafile. These flags are declared as external global variables in [llamafile/llamafile.h31-40](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.h#L31-L40) and are primarily parsed and initialized during the early startup phase of the executable. They configure the underlying llama.cpp inference engine, the TinyBLAS compute kernels, the sandbox environment, and the dynamic GPU loading system.

 
## Flag Architecture

 In llamafile, flags are managed as global state to ensure consistency across various subsystems, including the HTTP server, CLI, and dynamically loaded GPU backends. The parsing logic is centralized in `lf::parse_llamafile_args`, which filters out llamafile-specific flags before passing the remaining arguments to the llama.cpp core.

## Global Configuration Flags

 The following flags are declared in the core header and control fundamental aspects of the executable's behavior.

 
| Flag Variable | Type | CLI Equivalent | Purpose |
|---|---|---|---|
| FLAG_log_disable | bool | N/A | Disables all logging output in chatbot_comm.cpp. |
| FLAG_nocompile | bool | N/A | Prevents dynamic compilation of GPU kernels in metal.c. |
| FLAG_ascii | bool | --ascii | Forces ASCII-only art for logos in chatbot_logo.cpp. |
| FLAG_nologo | bool | --nologo | Suppresses the display of the llamafile logo at startup. |
| FLAG_nothink | bool | --nothink | Filters out reasoning tags (e.g., <think>) from model output. |
| FLAG_precise | bool | N/A | Forces precise mathematical operations in tinyblas_cpu.h. |
| FLAG_recompile | bool | N/A | Forces recompilation of GPU libraries even if cached. |
| FLAG_unsecure | bool | --unsecure | Disables pledge()/SECCOMP sandboxing. |
| FLAG_gpu | int | --gpu | Selects the GPU backend (AMD, Apple, NVIDIA, Vulkan, or Auto). |
| FLAG_verbose | int | --verbose | Enables verbose diagnostic output for GPU and runtime. |

## GPU Backend Selection

 The `FLAG_gpu` variable controls which compute backend is utilized for matrix multiplications. Llamafile uses a dynamic detection system to choose the best available hardware at runtime, often involving out-of-process probing on Windows to prevent driver crashes from corrupting the main process.

 
### GPU Mode Constants

 The following integer constants are used to set and check `FLAG_gpu`:

 
| Constant | Value | Description |
|---|---|---|
| LLAMAFILE_GPU_ERROR | -2 | Indicates a failure in GPU detection or initialization. |
| LLAMAFILE_GPU_DISABLE | -1 | Forces CPU-only execution. |
| LLAMAFILE_GPU_AUTO | 0 | Automatically detects the best available GPU (Default). |
| LLAMAFILE_GPU_AMD | 1 | Forces the use of the ROCm/HIP backend. |
| LLAMAFILE_GPU_APPLE | 2 | Forces the use of the Metal backend. |
| LLAMAFILE_GPU_NVIDIA | 4 | Forces the use of the CUDA backend. |
| LLAMAFILE_GPU_VULKAN | 8 | Forces the use of the Vulkan backend. |

 **Sources:** [llamafile/llamafile.h101-107](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.h#L101-L107)

## Sandboxing and Security Flags

 Llamafile implements security via `pledge()` (syscall filtering) and `unveil()` (filesystem path confinement). These are controlled by `FLAG_unsecure` and `FLAG_confine_reads`.

 
### Security Policy Gate

 The function `sandbox_skip_status()` in `sandbox.c` acts as a centralized gate for determining if a sandbox should be applied based on the current configuration and hardware.

 
| Condition | Status Code | Result |
|---|---|---|
| FLAG_unsecure == true | LLAMAFILE_SANDBOX_UNSECURE | Sandbox skipped by user request. |
| llamafile_has_gpu() == true | LLAMAFILE_SANDBOX_GPU | Sandbox skipped (GPU drivers require /dev access). |
| OS unsupported | LLAMAFILE_SANDBOX_UNSUPPORTED | Sandbox skipped (Non-Linux/OpenBSD). |
| Default | LLAMAFILE_SANDBOX_ACTIVE | Sandbox is applied. |

## Runtime Utility Functions

 Llamafile provides several utility functions to handle the environment and file system, which are influenced by runtime flags.

 
### File and Directory Utilities

 
 - **`llamafile_has(char **list, const char *arg)`**: A helper to check if a specific string exists within a list of arguments. [llamafile/llamafile.c79](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.c#L79-L79)
 - **`llamafile_get_app_dir(char *path, size_t size)`**: Retrieves the directory where the llamafile executable or its assets are stored. [llamafile/llamafile.c80](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.c#L80-L80)
 - **`llamafile_extract(const char *zip_path, const char *dest)`**: Extracts embedded assets (like GPU DSOs) from the APE/ZIP structure. [llamafile/llamafile.c82](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.c#L82-L82)
 - **`llamafile_is_file_newer_than(const char *a, const char *b)`**: Used to determine if GPU kernels need recompilation. [llamafile/llamafile.c83](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.c#L83-L83)
 
 
### GPU Logging Control

 Llamafile allows redirecting or silencing logs from the GPU backends via specific callback setters.

 
 - **`llamafile_cuda_log_set`**: Configures logging for the CUDA/ROCm dynamic library. [llamafile/cuda.c190](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/cuda.c#L190-L190)
 - **`llamafile_metal_log_set`**: Configures logging for the Metal dynamic library. [llamafile/metal.c143](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/metal.c#L143-L143)
