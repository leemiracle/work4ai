  The `LocalScore` tool is a specialized benchmarking utility within the llamafile ecosystem designed to measure and quantify Large Language Model (LLM) performance across different hardware configurations. It focuses on three primary dimensions of inference: prompt processing speed, token generation speed, and responsiveness (latency). The tool calculates a unified "LocalScore" to facilitate objective comparisons between different systems and model architectures.

 
### LocalScore Formula and Metrics

 The performance of an LLM is reduced to a single scalar value, the **LocalScore**, which represents the geometric mean of three key performance indicators (KPIs). Using a geometric mean ensures that a significant deficiency in any one metric heavily penalizes the overall score, preventing a system from appearing performant if it is, for example, extremely fast at generation but takes minutes to start (high TTFT).

 The score is calculated as follows: $$\text{LocalScore} = \sqrt[3]{\text{Prompt TPS} \times \text{Generation TPS} \times \frac{1000}{\text{TTFT}}}$$

 
| Metric | Definition | Implementation Detail |
|---|---|---|
| Prompt TPS | Tokens Per Second during the initial prompt ingestion phase. | Measures the speed of filling the KV cache localscore/localscore.cpp147-158 |
| Generation TPS | Tokens Per Second during the autoregressive decoding phase. | Measures how quickly the model predicts subsequent tokens localscore/localscore.cpp165-169 |
| TTFT | Time To First Token (in milliseconds). | The latency between the end of prompt processing and the arrival of the first generated token. |

### Benchmark Methodology

 The benchmarking process follows a strict lifecycle to ensure results are reproducible and not influenced by cold-start penalties or hardware thermal throttling.

 
#### 1. Initialization and Warmup

 Before recording metrics, the system performs a `warmup_run` [localscore/localscore.cpp134-174](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/localscore.cpp#L134-L174) This function initializes the `llama_context` and performs a full pass of prompt decoding and token generation using random tokens from the model's vocabulary. This ensures that memory is paged in, GPU kernels are compiled/loaded, and the hardware has reached a stable operating state.

 
#### 2. Execution Flow

 The benchmark execution is managed through `cmd_params`, which defines the workload (batch sizes, thread counts, and GPU offloading). The parameters are parsed via `parse_cmd_params` [localscore/cmd.cpp70-176](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/cmd.cpp#L70-L176)

### Repetition Modes

 To improve statistical significance, `LocalScore` supports multiple repetition modes. These modes control the `reps` variable in `cmd_params`, which determines how many times the inference test is cycled before averaging the results.

 
| Flag | Mode | Repetitions (reps) | Purpose |
|---|---|---|---|
| (Default) | Standard | 1 | Quick verification of system capability localscore/cmd.cpp27 |
| --extended | Extended | 4 | Balanced measurement for stable environments localscore/cmd.cpp136-137 |
| --long | Long | 16 | Stress testing and identifying thermal throttling issues localscore/cmd.cpp138-139 |

 The `utils::avg` and `utils::stdev` functions are used to calculate the mean and standard deviation across these repetitions to ensure data integrity [localscore/utils.h60-79](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/utils.h#L60-L79)

### Output Formats

 Benchmark results can be exported in several formats to facilitate either human reading or automated data processing. This is controlled by the `output_format` member of the `cmd_params` struct [localscore/cmd.h33](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/cmd.h#L33-L33)

 
 - **CONSOLE (Default):** Prints a formatted table to the terminal. If the terminal supports ANSI and `NO_COLOR` is not set [localscore/utils.h189-195](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/utils.h#L189-L195) it uses the `utils::color_str` helper for syntax highlighting [localscore/utils.h197-202](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/utils.h#L197-L202) and the `ascii_display::printLargeNumber` function for visual impact [localscore/ascii_digits.h18-52](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/ascii_digits.h#L18-L52)
 - **CSV:** Generates a comma-separated values list suitable for import into spreadsheet software [localscore/cmd.h7](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/cmd.h#L7-L7)
 - **JSON:** Produces a structured JSON object via the `jt::Json` library [localscore/localscore.cpp53](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/localscore.cpp#L53-L53) This format includes comprehensive metadata including `SystemInfo` (CPU, RAM, Kernel) and `RuntimeInfo` (llamafile version, commit hash).

### Implementation Details

 
#### Metric Calculation

 The system uses `utils::get_time_ns()` to capture high-resolution timestamps before and after inference calls to ensure microsecond precision [localscore/utils.h22-25](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/utils.h#L22-L25)

 
#### System Information Integration

 The `get_sys_info` function populates the benchmark report with hardware context [localscore/system.cpp178-206](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/system.cpp#L178-L206) On x86 systems, it uses the `cpuid` instruction to determine the specific CPU architecture and manufacturer (e.g., "AuthenticAMD" or "GenuineIntel") [localscore/system.cpp21-56](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/system.cpp#L21-L56) On macOS (XNU), it utilizes `sysctlbyname` to extract brand strings and core counts (Performance vs Efficiency cores) [localscore/system.cpp98-124](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/system.cpp#L98-L124)

 
#### Live Updates

 For interactive console output, the `update_t_gen_column` function runs in a separate thread to provide real-time updates of the generation speed as tokens are produced, using ANSI escape codes to overwrite the current line [localscore/localscore.cpp81-118](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/localscore.cpp#L81-L118)

 
#### Result Submission

 Users can optionally submit their scores to `https://localscore.ai`. The tool prompts for confirmation unless the `--send-results` or `--no-send-results` flags are provided [localscore/localscore.cpp176-213](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/localscore.cpp#L176-L213) Submissions are sent via a POST request containing a JSON payload with system and performance data [localscore/localscore.cpp204-206](https://github.com/mozilla-ai/llamafile/blob/43551265/localscore/localscore.cpp#L204-L206)
