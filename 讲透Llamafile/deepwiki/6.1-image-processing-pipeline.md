## Purpose and Scope

 This document describes the image processing pipeline in llamafile, covering both the client-side preparation in the Web UI/Chatbot and the server-side ingestion into the multimodal LLM inference engine. The pipeline handles image upload, base64 encoding, compression, data URI parsing, and integration with the CLIP vision encoder for embedding generation.

 The pipeline supports the local Chatbot REPL (via the `/upload` command), the CLI mode (via the `--image` flag), and the HTTP server API (via OpenAI-compatible multimodal messages).

 
---

 
## System Overview

 The image processing pipeline bridges the gap between raw user files and high-dimensional vector embeddings. It begins with the user providing an image, which is normalized and encoded, and ends in the inference engine where it is processed by a CLIP model.

## Client and Interface Handling

 
### Chatbot REPL (/upload)

 In the interactive CLI, users can upload images using the `/upload` command. The command reads the file from disk, encodes it as a data URI, and prepares it for the next user message.

 
 - **Accumulation**: Content from `/upload` is stored in the global `g_pending_file_content` buffer [llamafile/chatbot_main.cpp60](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/chatbot_main.cpp#L60-L60)
 - **Integration**: When the user sends their next text message, the pending image content is prepended to the message body [llamafile/chatbot_repl.cpp218-220](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/chatbot_repl.cpp#L218-L220)
 
 
### CLI Mode (--image)

 The `llamafile` executable supports a `--image` flag for multimodal inference in non-interactive modes.

 
 - **Multiple Images**: Multiple images can be passed as a comma-separated list to `--image` [tests/integration/tests/test_multimodal.py50-53](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_multimodal.py#L50-L53)
 - **Markers**: The prompt must contain `<__media__>` markers to indicate where images should be injected. A mismatch between marker count and image count triggers an error [tests/integration/tests/test_multimodal.py60-70](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/integration/tests/test_multimodal.py#L60-L70)
 
 
### API Backend (Multimodal JSON)

 The `ApiBackend` class handles the conversion of text containing data URIs into structured OpenAI-compatible JSON.

 
 - **Content Building**: The `build_content()` function scans user input for `data:image/` prefixes [llamafile/chatbot_api.cpp58-62](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/chatbot_api.cpp#L58-L62)

## Server-Side Ingestion

 The server-side pipeline is responsible for extracting raw binary data from the encoded strings provided by the interfaces.

 
### Data URI Parsing

 The `DataUri` class (defined in `datauri.cpp`) implements a state-machine parser based on RFC 2397 to extract raw binary data from the incoming string.

## Inference Integration

 The final stage involves passing the decoded image data to the vision encoder to generate embeddings that the LLM can process.

 
### Data Flow to CLIP

 When a message containing an image is processed:

 
 - **Extraction**: `extract_data_uris()` (defined in `extract_data_uris.cpp`) identifies all embedded images in the prompt string [llamafile/extract_data_uris.cpp24](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/extract_data_uris.cpp#L24-L24)
 - **Encoding**: The binary data is passed to the CLIP encoder (contained within the `mtmd_context`) which performs image preprocessing and feature extraction.
 - **Projection**: The vision encoder produces a sequence of embeddings (typically representing spatial patches of the image).
 - **Decoding**: These embeddings are passed to `llama_decode()` as if they were a sequence of tokens, allowing the LLM to attend to the visual information via cross-attention or concatenation.
