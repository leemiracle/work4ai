## Purpose and Scope

 This page documents the sampling and generation system in llamafile, which controls how tokens are selected during inference to produce model outputs. This includes the configuration of sampling parameters (temperature, top-p, top-k), the application of repetition penalties, and the orchestration of the generation loop. For information about model loading and context management, see [Model and Context Management](https://deepwiki.com/mozilla-ai/llamafile/3.1-model-and-context-management). For details on tokenization before generation, see [Tokenization and Chat Templates](https://deepwiki.com/mozilla-ai/llamafile/3.2-tokenization-and-chat-templates).

 
## Overview

 Token generation in llamafile is a two-phase process: the model computes logits (scores) for all vocabulary tokens, and the sampling system selects the next token based on configurable strategies. The generation loop repeats this process until a stop condition is met (EOS token, max length, or stop sequence match).

 The sampling system provides multiple strategies:

 
 - **Greedy sampling**: Always select the highest probability token (temperature=0).
 - **Temperature sampling**: Scale logits by temperature to control randomness.
 - **Top-p (nucleus) sampling**: Sample from tokens comprising top-p cumulative probability.
 - **Top-k sampling**: Restrict sampling to k highest probability tokens.
 - **Repetition penalties**: Reduce probability of recently generated tokens.
 - **Grammar constraints**: Force output to conform to a grammar (e.g., JSON schema).
 
 
## Sampling Parameters

 
### Core Sampling Parameters

 The `common_params_sampling` structure defines all configurable sampling behavior. These parameters are often mapped from global flags or API request bodies.

 
| Parameter | Type | Default | Description |
|---|---|---|---|
| temp | float | 0.8 | Temperature scaling factor (0.0 = greedy, >1.0 = more random) |
| top_k | int32_t | 40 | Restrict to top-k highest probability tokens |
| top_p | float | 0.95 | Nucleus sampling: cumulative probability threshold |
| min_p | float | 0.05 | Minimum probability threshold for candidates |
| penalty_last_n | int32_t | 64 | Window of recent tokens for repetition penalty |
| penalty_repeat | float | 1.0 | Repetition penalty multiplier (>1.0 = discourage) |
| penalty_freq | float | 0.0 | Frequency penalty (OpenAI-style) |
| penalty_present | float | 0.0 | Presence penalty (OpenAI-style) |
| seed | uint32_t | -1 | Random seed for sampling (-1 = time-based) |

## Sampling Context

 
### common_sampler Structure

 The `common_sampler` maintains the state needed for sampling operations across multiple steps of generation. It is initialized via `common_sampler_init()` and cleaned up with `common_sampler_free()`.

 
 - **Parameters**: The `common_params_sampling` configuration.
 - **Previous tokens**: A buffer storing recent tokens used to calculate repetition penalties.
 - **Grammar state**: Parser state for grammar-constrained generation (e.g., GBNF).
 - **Mirostat state**: Running entropy estimates if Mirostat sampling is enabled.

### Synchronization Requirements

 Unlike standard inference loops that sample immediately, the llamafile chatbot requires explicit synchronization. `llama_decode()` may defer computation to later stages (like `common_sampler_sample()`). When loading system prompts or images where no sampling occurs, `llama_synchronize(g_ctx)` is called to ensure stats are computed and control returns to the REPL correctly.

## Token Selection Process

 
### Sampling Pipeline Steps

 The `common_sampler_sample()` function applies a sequence of transformations to raw logits:

 
 - **Logit Bias**: Modifies specific token probabilities via a `logit_bias` map.
 - **Penalties**: Applies repetition, frequency, and presence penalties based on the token history.
 - **Temperature**: Scales logits (e.g., `logits /= temp`).
 - **Truncation**: Applies Top-K, Top-P (Nucleus), and Min-P filtering.
 - **Grammar**: Masks tokens that violate the active GBNF grammar or JSON schema.
 - **Selection**: Performs a weighted random selection (or greedy selection if temp=0).
 
 **Sources:** [llama.cpp/common/sampling.cpp](https://github.com/mozilla-ai/llamafile/blob/43551265/llama.cpp/common/sampling.cpp)

 
### M-RoPE and Multimodal Generation

 For multimodal models (like LLaVA), llamafile tracks `n_past` and `n_pos` explicitly. In models using Multi-dimensional Rotary Positional Embeddings (M-RoPE), the number of positions (`n_pos`) does not always equal the number of tokens. The sampling pipeline must account for this discrepancy to maintain context integrity.

## Stop Conditions

 Generation terminates when one of the following triggers:

 
 - **End-of-Generation (EOG)**: The model produces a token identified by `llama_token_is_eog()`.
 - **Max Tokens**: The number of generated tokens reaches the `max_tokens` or `n_predict` limit.
 - **Stop Sequences**: The generated text matches a user-defined "antiprompt" or stop string.
 - **Thinking Filter**: If reasoning tags (like `<think>`) are detected and `FLAG_nothink` is enabled, generation behavior is modified.
