## Purpose and Scope

 This document describes how llamafile achieves **multi-architecture support** through "fat binary" compilation, enabling a single executable to run optimally on both x86_64 and aarch64 systems without recompilation. The system leverages **Cosmopolitan Libc** to create Actually Portable Executables (APE) that contain native code for multiple CPU architectures and instruction set extensions, with runtime detection and dispatch to the optimal code path.

 For information about the Cosmopolitan Libc integration that enables this capability, see [Cosmopolitan Libc Integration](https://deepwiki.com/mozilla-ai/llamafile/7.1-cosmopolitan-libc-integration). For CPU-specific SIMD optimizations and runtime dispatch, see [CPU Backend](https://deepwiki.com/mozilla-ai/llamafile/4.2-cpu-backend).

## Fat Binary Architecture

 llamafile executables are **fat binaries** containing compiled code for multiple architectures in a single file. This is achieved through the Cosmopolitan Libc toolchain, which creates Actually Portable Executables (APE) that can run on Linux, macOS, Windows, and FreeBSD on both x86_64 and aarch64 platforms.

## Build System Integration

 
### Dual Compilation Pipeline

 The build system compiles every source file twice: once for x86_64 and once for aarch64. Object files and archives are organized in parallel directory structures [build/rules.mk68-71](https://github.com/mozilla-ai/llamafile/blob/43551265/build/rules.mk#L68-L71)

 
| Architecture | Object File Location | Static Library Location |
|---|---|---|
| x86_64 | o/$(MODE)/*.o | o/$(MODE)/*.a |
| aarch64 | o/$(MODE)/.aarch64/*.o | o/$(MODE)/.aarch64/*.a |

 **Sources:** [build/rules.mk68-71](https://github.com/mozilla-ai/llamafile/blob/43551265/build/rules.mk#L68-L71) [build/rules.mk104-107](https://github.com/mozilla-ai/llamafile/blob/43551265/build/rules.mk#L104-L107)

## Architecture-Specific Kernel Dispatch

 Performance-critical kernels for matrix multiplication (`sgemm`), Mixture-of-Experts (`mixmul`), and Flash Attention helpers are selected at runtime. The `GemmFuncs` struct in `llamafile/sgemm.cpp` acts as the central dispatcher [llamafile/sgemm.cpp47-53](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sgemm.cpp#L47-L53)

 
### CPU Feature Detection Logic

 The dispatcher uses architecture-specific macros and system calls to identify CPU capabilities:

 
 - **x86_64**: Uses `X86_HAVE()` macros (wrapping `cpuid.h`) to check for `AVX`, `FMA`, `AVX2`, `AVX512F`, `AVX512_VNNI`, and `AVX512_BF16` [llamafile/sgemm.cpp64-87](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sgemm.cpp#L64-L87)
 - **aarch64**: Uses `getauxval(AT_HWCAP)` to check for `HWCAP_FPHP` (FP16), `HWCAP_ASIMDHP` (Advanced SIMD FP16), and `HWCAP_ASIMDDP` (Dot Product) [llamafile/sgemm.cpp120-124](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sgemm.cpp#L120-L124)
 
 
### Kernel Selection Table

 
| Target | Required Features | Selected Kernel Function |
|---|---|---|
| AMD Zen4+ | AVX512F, VNNI, BF16 | llamafile_sgemm_amd_zen4 |
| Intel Skylake+ | AVX512F | llamafile_sgemm_amd_avx512f |
| Intel Alderlake | AVXVNNI | llamafile_sgemm_amd_avxvnni |
| Modern ARM | DotProd, FP16 (e.g. M1, Pi 5) | llamafile_sgemm_arm82 |
| Baseline ARM | ASIMD (NEON) | llamafile_sgemm_arm80 |

## IQK (Integer Quantized Kernels) Support

 In addition to standard SGEMM, llamafile provides specialized kernels for k-quant and i-quant formats (Q4_K, Q8_K, etc.) which offer significant speedups. These also follow the multi-architecture dispatch pattern via `iqk_mixmul` [llamafile/sgemm.cpp38-39](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/sgemm.cpp#L38-L39)

 
| Kernel Type | Target Architecture | Implementation Function |
|---|---|---|
| MoE Zen4 | x86_64 (Zen4) | iqk_mul_mat_moe_zen4 |
| MoE AVX2 | x86_64 (AVX2) | iqk_mul_mat_moe |
| MoE ARM8.2 | aarch64 (DotProd) | iqk_mul_mat_moe_arm82 |

## GPU Backend Multi-Architecture Strategy

 While CPU code is bundled into a single APE fat binary, GPU backends are built as shared libraries. The build system passes `GGML_VERSION` and `GGML_COMMIT` to scripts like `llamafile/cuda.sh` and `llamafile/rocm.sh` to ensure compatibility [Makefile65-81](https://github.com/mozilla-ai/llamafile/blob/43551265/Makefile#L65-L81)

 
### CUDA Multi-Arch Support

 The CUDA build targets multiple "Compute Capabilities" in a single library, allowing support for various NVIDIA GPU generations (Pascal through Hopper) [Makefile66-72](https://github.com/mozilla-ai/llamafile/blob/43551265/Makefile#L66-L72)

 
### ROCm Multi-Arch Support

 The ROCm build targets multiple `gfx` architectures simultaneously using `hipcc` [Makefile74-76](https://github.com/mozilla-ai/llamafile/blob/43551265/Makefile#L74-L76)
