## Overview

 The model loading system provides a unified interface for accessing GGUF model files regardless of their storage format. Models can be:

 
 - **Standalone files**: Regular `.gguf` files on the filesystem.
 - **ZIP-embedded**: Models stored within a ZIP archive (including the executable itself).
 - **Aligned ZIP-embedded**: Models stored with specific byte alignment (typically 64KB) for GPU direct access via memory mapping.
 
 The system uses memory mapping for efficient access and includes optional multi-threaded warmup via `llamafile_schlep` to preload model data into physical memory.

 The function allows flexible model specification:

 - **ZIP64 EOCD Locator** (`kZipCdir64LocatorMagic = 0x07064b50`) [llamafile/zip.h83](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/zip.h#L83-L83)

 Both ZIP32 and ZIP64 formats are supported via macros like `ZIP_CDIR64_RECORDS` and `ZIP_CDIR_RECORDS`, enabling models larger than 4GB.

## Memory Mapping and Alignment

 
### Memory Mapping Strategy

 ZIP-embedded models use `mmap()` for zero-copy access. Because `mmap` requires page-aligned offsets, the system calculates a "skew" to find the actual data within the mapped page.


## Memory Warmup System

 
### llamafile_schlep Function

 The `llamafile_schlep()` function is declared in `llamafile.h` and is responsible for preloading memory-mapped data into physical RAM. It touches each page of the model, forcing the OS to perform page faults and populate the file cache.

 **Sources:** [llamafile/llamafile.h73](https://github.com/mozilla-ai/llamafile/blob/43551265/llamafile/llamafile.h#L73-L73)
