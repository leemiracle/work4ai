  `transcribefile` is a high-performance, single-file speech-to-text CLI built on the `transcribe.cpp` engine. It extends the core transcription capabilities with the llamafile distribution framework, enabling multi-platform execution via Cosmopolitan Libc, GPU acceleration (starting with Apple Metal), and self-contained model bundling using ZIP-embedded GGUF files.

 The tool supports over 16 model families, including:

 
 - **Parakeet** (TDT/RNN-T)
 - **Whisper** (OpenAI)
 - **Canary** (NVIDIA)
 - **Voxtral**
 - **Moonshine**
 
 
## Architecture and Integration

 `transcribefile` is implemented as a wrapper around the `transcribe.cpp` submodule. It replaces the upstream standalone entry point with a custom main function that integrates llamafile-specific features like automatic argument loading and GPU runtime detection.

 
### Data Flow and Entry Point

 The execution flow starts in `transcribefile/main.cpp`, which initializes the Cosmopolitan environment and merges command-line arguments with those found in the executable's internal ZIP store.

 
| Component | Responsibility |
|---|---|
| main() | Entry point; handles crash reports, versioning, and argument merging transcribefile/main.cpp114-158 |
| cosmo_args() | Merges arguments from /zip/.args into the process argv transcribefile/main.cpp134 |
| load_gpu_backends() | Probes for Metal support and registers backends with GGML transcribefile/main.cpp89-112 |
| transcribe_cli_main() | The core logic from transcribe.cpp/examples/cli/main.cpp transcribefile/main.cpp27 |

## GPU Acceleration and Metal Support

 `transcribefile` utilizes the llamafile runtime loader to provide GPU acceleration. Currently, Metal support is prioritized for macOS on Apple Silicon.

 
### Metal Runtime Compilation

 Unlike traditional binaries that link against a static GPU library, `transcribefile` bundles Metal shader sources. On the first run on a compatible Mac, it compiles these sources into `ggml-metal.dylib` and caches them under `~/.transcribefile` [transcribefile/main.cpp68-70](https://github.com/mozilla-ai/llamafile/blob/43551265/transcribefile/main.cpp#L68-L70) The cache is deliberately separated from the standard `~/.llamafile` directory to prevent divergence issues between `llama.cpp` and `transcribe.cpp` GGML trees [transcribefile/main.cpp118-122](https://github.com/mozilla-ai/llamafile/blob/43551265/transcribefile/main.cpp#L118-L122)

 
### Logging and Verbosity

 To maintain a clean CLI experience, GPU loader diagnostics and backend initialization logs are suppressed by default. They can be enabled using the `--verbose` flag, which sets the `FLAG_verbose` global and configures the Metal log callback [transcribefile/main.cpp107-110](https://github.com/mozilla-ai/llamafile/blob/43551265/transcribefile/main.cpp#L107-L110)

## Implementation Details

 
### Cosmopolitan Compatibility

 Because `transcribefile` is built as an Actually Portable Executable (APE), it requires shims for certain C++ standard library functions that may not be present in the underlying libc or require specific ABI matching for LP64 (where `long` and `long long` are both 64-bit).

 **Table 1: Compatibility Shims in `cosmo_compat.c`**

 
| Symbol | Implementation | Purpose |
|---|---|---|
| llround | lround(x) | Maps 64-bit round to available lround transcribefile/cosmo_compat.c15 |
| llroundf | lroundf(x) | Maps float 64-bit round transcribefile/cosmo_compat.c16 |
| llroundl | lroundl(x) | Maps long double 64-bit round transcribefile/cosmo_compat.c17 |

 Sources: [transcribefile/cosmo_compat.c1-17](https://github.com/mozilla-ai/llamafile/blob/43551265/transcribefile/cosmo_compat.c#L1-L17)

 
### Build System and Patches

 The build process involves applying llamafile-specific patches to the `transcribe.cpp` submodule. This includes renaming the upstream `main` function to `transcribe_cli_main` so that the llamafile wrapper can take control of the entry point [transcribe.cpp.patches/patches/examples_cli_main.cpp.patch8-13](https://github.com/mozilla-ai/llamafile/blob/43551265/transcribe.cpp.patches/patches/examples_cli_main.cpp.patch#L8-L13)

 The `BUILD.mk` for `transcribe.cpp` uses a "generic CPU" recipe (`-DGGML_CPU_GENERIC`), ensuring that a single binary can run on both x86_64 and aarch64 without needing architecture-specific CPU dispatching for the base build [transcribe.cpp.patches/llamafile-files/BUILD.mk14-17](https://github.com/mozilla-ai/llamafile/blob/43551265/transcribe.cpp.patches/llamafile-files/BUILD.mk#L14-L17)

## Testing and Verification

 `transcribefile` includes a multi-layered smoke test suite to ensure CLI stability and transcription accuracy across different backends.

 
### Smoke Test Layers

 
 - **Model-free Probes**: Validates `--help` and WAV file header parsing without requiring a heavy GGUF model [tests/transcribefile_smoke.sh46-59](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/transcribefile_smoke.sh#L46-L59)
 - **Parakeet End-to-End**: Performs a real transcription of `jfk.wav` using a Parakeet model, verifying that the output contains expected keywords like "country" [tests/transcribefile_smoke.sh61-80](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/transcribefile_smoke.sh#L61-L80)
 - **Metal Backend Verification**: On macOS/ARM64, it ensures the Metal backend is selectable and that its output matches the CPU backend's text exactly [tests/transcribefile_smoke.sh82-120](https://github.com/mozilla-ai/llamafile/blob/43551265/tests/transcribefile_smoke.sh#L82-L120)
