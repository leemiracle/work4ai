# 06 · 生命周期：把决策权从模型手里拿走

> 核心实验：**E5 SELECT 代码化**（[experiments/e5_select_codify.py](../experiments/e5_select_codify.py)）

## 直觉

walkinglabs 的会话生命周期仪式：

```
START   读 AGENTS.md → init.sh → progress.md → feature_list.json → git log
SELECT  只挑一个未完成 feature
EXECUTE 实现 → 跑验证 → 失败修复重跑 → 通过记录证据
WRAP UP 更新 progress.md → 更新 feature_list.json → 记录未决项 → 干净提交
```

注意 SELECT 的措辞——它没说"问模型下一个做什么"。**生命周期里满是确定性决策，确定性决策属于代码**。

## 本地复现（E5）

E3 发现账本可读但弱模型读不准 → E5 验证工程对策。三条件选"下一个任务"（正确答案 slugify）：

```bash
cd 讲透Harness/experiments && timeout 850 python3 e5_select_codify.py
```

**结果（results/e5_select_codify.json，3 reps）**：

| 条件 | 正确率 | LLM 调用 | 备注 |
|---|---|---|---|
| ask_model（把账本给模型问） | **0%** | 3 | 3/3 全选 count_vowels（**已完成的**） |
| hybrid（模型答→校验→兜底） | **100%** | 3 | 兜底触发 3/3，校验零成本 |
| code_select（dict 扫第一个 pending） | **100%** | **0** | 解析解 |

![E5](../experiments/results/e5_select_codify.png)

## 读数：ask_model 为什么 0%？

E3 的截断偏差复现：模型注意力被账本里"已完成"段的函数名占据（progress.md 完成段在前、待办段在后 + 讲透Context Ch02 位置效应）。这不是运气差，是**弱模型 + 状态文本**的系统性失败。hybrid 的价值：模型判断零信任基础时，代码护栏 100% 兜住——这就是"L2 断言护住 L3 判断"的一般模式（E2 同构）。

## 决策权三分法（本章方法论输出）

| 决策类型 | 归属 | 例 |
|---|---|---|
| 确定性 | **代码** | 选下一个 pending、读账本、格式转换 |
| 半确定 | **模型+护栏** | 代码结构选择（编译校验）、参数抽取（schema 校验） |
| 真模糊 | 模型 | 方案设计、语义审查（deep_plan/thinker） |

**给模型的每一个决策点，先问：它真的需要智能吗？** E5 的 SELECT 不需要——0 调用 100% 就赢了 3 调用 0%。
