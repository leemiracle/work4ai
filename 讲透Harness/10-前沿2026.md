# 10 · ★ 前沿 2025-2026：Harness-Bench 与"配置级报告"革命

> 引用全部一手核实（[papers.md](../papers.md)）。本章主角：Harness-Bench（arXiv:2605.27922，Qihoo360，2026-05-27，websearch abs 全文核实 2026-08-26）。

## 一句话

**agent 能力应该按 model–harness 配置报告，而不是归因于基座模型**——Harness-Bench 用 5194 条轨迹把这句话从口号变成了数据。

## Harness-Bench 是什么

- **106 个沙箱离线任务**（真实工作流模式，专家手工审核：realism/solvability/oracle-checkability/integrity）
- **6 可配置 harness × 8 模型全因子矩阵** + Codex 参照 = **5194 轨迹**
- 方法学：固定外部条件（任务/沙箱/预算/超时/评估器），保留各 harness **原生执行行为**（prompt/工具接口/状态策略/恢复）——harness 第一次成为**实验的一等变量**

## 核心数字

| 发现 | 数字 | 含义 |
|---|---|---|
| 同模型池 harness 差距 | **NanoBot 76.2 vs OpenClaw 52.4（23.8 分）** | 换 harness ≈ 换一档模型 |
| Codex（模型绑定栈） | 80.4 分 / 86.5% 完成 / 86.1K tokens | 参照点：好 harness+好模型的上界 |
| 失败症状 top2 | contract/format **36.4%** + tool/recovery **24.6%** | 六成失败在"执行对齐"，不在"推理"——E2 的 V0 漏报、E4 的打转全是这两族 |
| **harness dependence** | 弱模型跨 harness 方差大，强模型小 | **harness 是弱模型的能力补偿器**（E3/E5 本地实锤） |
| 效率差异 | NanoBot 68.7K vs NullClaw 175.1K tokens | harness 差异不只是准度，还有 2.5× 成本差 |

## 失败症状学与本单元实验的对照

| Harness-Bench 症状 | 占比 | 本单元对应实验 |
|---|---|---|
| contract/format violations | 36.4% | E2：V0 自评漏报全在"格式对但逻辑错"处 |
| tool/recovery failures | 24.6% | E4：不可解任务零放弃、无预算打转 |
| evidence/grounding issues | 14.6% | E1：naive FCR（声称与证据脱钩） |
| artifact commitment failures | 11.1% | E3：崩溃后 artifact 状态丢失 |
| state/continuation failures | 9.3% | E3：幻觉恢复；E5：SELECT 0% |

## 更大的图景：四综述 + 基准之争

- **四综述**（Meng 六组件/Li 七层/Ning code-as-harness/Guo 四范式，见 [harness三综述合并解析](../讲透Agent/harness三综述合并解析.md)）回答"harness 是什么"
- **Harness-Bench** 回答"harness 好不好怎么测"——与 awesome-harness 的 40+ 基准筛选标准（"能不能测出 harness 质量而非模型质量"）合流
- 开放前沿（综述 + 基准共同指向）：跨 harness 可移植性、组合式验证、多智能体拜占庭容错、开放动态模型池（Ensemble D2）、价值感知评估（成本/延迟/安全/漂移）
