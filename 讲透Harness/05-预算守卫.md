# 05 · Scope 与预算：发散、打转与熔断

> 核心实验：**E4 预算守卫**（[experiments/e4_budget_guard.py](../experiments/e4_budget_guard.py)）

## 直觉

Scope 子系统 = 给 agent 的"信用卡额度 + 门禁卡"。没有额度的修复循环是不可解任务上的碎钞机：每次重试都在烧钱，且**永远不可能成功**。Harness-Bench 失败症状第二位 tool/recovery failures 24.6%——无预算修复循环是第二大失败族。

## 本地复现（E4）

任务（矛盾，不可解）：`magic(5)==10 ∧ magic(5)==12`——任何实现都不可能同时通过。给了模型诚实出口（可回答 IMPOSSIBLE）：

```bash
cd 讲透Harness/experiments && timeout 900 python3 e4_budget_guard.py
```

**结果（results/e4_budget_guard.json）**：

| 条件 | 烧掉调用 | 诚实放弃（IMPOSSIBLE） |
|---|---|---|
| uncapped（硬上限 6 兜底） | 6 | **0** |
| cap=3 | 3 | **0** |
| cap=2 | 2 | **0** |

![E4](../experiments/results/e4_budget_guard.png)

## 三个读数

1. **0.5B 对矛盾任务 3/3 条件零诚实放弃**——即使明确给了出口、即使每次重试都收到同样的失败反馈，它依然相信"再试一次就成"。**预算必须由 harness 熔断，不能指望模型自觉**。
2. **cap=2 与 uncapped 同为失败**，但省 4 次调用（3×）——在不可解任务上，预算不改变结果，只改变**止损速度**。
3. 与讲透Loop E1 互证：自评停止 87% 早停（太早放弃）vs E4 零放弃（太晚）——**停止判定的两个方向都错**，方向选择必须匹配验证器的可信度：验证可信（E4 的 exec 断言必挂）→ 早熔断；验证模糊 → 谨慎终止。

## Scope 三件套（手册 10 章骨架）

1. **重试预算**：每任务 max_retries + 全局 max_turns（E1 harness 的 40 轮兜底）
2. **权限白名单**：工具默认拒（fail-closed）——五仓 authorize.py：新工具不加白名单不放行；改 authorize 自身=提权，拦
3. **盲测集隔离**：测试文件不进 agent 可写路径（Goodhart 防御，Ch03）
