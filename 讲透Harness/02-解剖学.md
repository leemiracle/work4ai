# 02 · 解剖学：五子系统、六组件与四综述切法的统一

> 本章无新实验——它是把存量地图（手册 02/03 章 + 三综述解析）压成一页"组件×失败模式"对照表，并给每行指到本单元的实验编号。

## 直觉：给"模型周围的一切"画部件图

把一辆车拆开看：引擎（模型）只有一个，但决定这辆车能不能安全跑长途的是刹车（验证）、油表（状态）、方向盘行程（Scope）、保养周期（Lifecycle）。

## 三种切法，一个交集

| 切法 | 来源 | 组件 |
|---|---|---|
| 五子系统 | walkinglabs（产业教学） | Instructions / State / Verification / Scope / Session Lifecycle |
| 六组件 H=(E,T,C,S,L,V) | Meng et al.（综述，23 系统 Completeness Matrix） | 执行循环/工具/上下文/状态/生命周期钩子/评估 |
| 七层 ETCLOVG | Li et al.（生产控制面） | +Observability、Governance 独立成层 |

**统一最小共识集**（四综述交集，缺一不可生产）：E 执行循环、T 工具接口、C 上下文、S 状态、V 验证治理、O 可观测。

## 组件 × 失败模式 × 本单元实验（本章主表）

| 组件 | 管什么 | 去掉会怎样 | 实验证据 |
|---|---|---|---|
| V 验证 | 完成判定权 | **幻觉式完成**（声称≠事实） | E1：FCR true→结构性0；E2：V0 自评漏报 2/13 全在"看起来合理"处 |
| S 状态 | 跨轮/跨会话记忆 | **失忆+幻觉恢复**（崩溃后瞎报进度） | E3：无账本 100% 幻觉恢复；E5：纯问模型选 next 0% |
| Scope 预算 | 停止条件/权限 | **打转烧钱**（不可解任务无限重试） | E4：矛盾任务 0.5B 零诚实放弃，cap=2 省 3× 调用 |
| L 生命周期 | 仪式（START/SELECT/EXECUTE/WRAP UP） | 断点即报废 | E5：SELECT 代码化 100% 零调用 vs 问模型 0% |
| C 上下文 | 窗口预算 | Context Rot/压缩失真 | 见姊妹单元 讲透Context E1-E8；本仓 C 参数抄手册 04 章 |
| T 工具 | schema/校验/修复 | 工具误用、纯文本调用丢失 | 五仓活案例：tool-call repair 三语法升格 |
| E 循环 | 轮次/终止/恢复 | 无界循环 | 讲透Loop 全单元（自评早停 87%） |

## Guo 四范式：本章的历史坐标

prompt engineering（怎么说）→ workflow/context engineering（给什么信息）→ **harness engineering（怎么闭环）**→ agent-native co-evolution（模型与 harness 共同进化）。每次迁移都因前一范式撞墙：context engineering 是前馈的，**解决不了漂移检测与错误恢复——harness 闭环才解决**。这正是"隐式胶水→显式运行时→可优化对象"（Ch12 展开）。

## 代码层：六组件在 200 行里长什么样

手册 12 章（[12-最小harness实现](../../工程化手册库/harness工程手册/12-最小harness实现.md)）给了 200 行骨架；E1 的 harness_run()（~30 行）是它的最小缩印：for 循环（E）+ 测试 exec（V）+ feature_list/progress（S）+ 逐任务 SELECT（L）+ 反馈回灌（C）。**六组件不是架构图上的框，是 30 行代码里的四五个变量。**
