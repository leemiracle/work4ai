# 01 · Agent = Model + Harness：模型不是瓶颈的证据链

> 核心实验：**E1 naive vs 最小harness**（[experiments/e1_naive_vs_harness.py](../experiments/e1_naive_vs_harness.py)）

## 直觉

同一个员工（模型），一份口头指令直接干活（naive），对比 给他任务清单+测试环境+账本（harness）——产出可靠性天差地别。模型没变，**环境**变了。

## 外部证据链（已核实，见 papers.md）

| 证据 | 数字 | 性质 |
|---|---|---|
| Anthropic 对照（walkinglabs 转述） | 无 harness $9/20min 不可用 → 全套 $200/6h 可玩 | 二手 |
| Meng et al. 2026.04（preprints 202604.0428） | order-of-magnitude 可靠性提升（模型不变） | 摘要级 |
| AHE（arXiv:2604.25850） | Terminal-Bench 2 69.7→77.0（+7.3pp，超人工 71.9%） | 一手 |
| **Harness-Bench（2605.27922）** | **同模型池：NanoBot 76.2 vs OpenClaw 52.4（23.8 分）** | 一手 |

## 本地复现（E1）

设计：同一颗 Qwen2.5-0.5B（CPU, temp=0），6 个迷你函数任务：
- **Condition A（naive）**：一次性要它写完 6 个函数，完成后让它自评
- **Condition B（harness）**：SELECT→EXECUTE→VERIFY（真测试 exec）→WRAP UP 生命周期，失败带错误反馈重试 1 次

```bash
cd 讲透Harness/experiments && timeout 1500 python3 e1_naive_vs_harness.py
```

**结果（results/e1_naive_vs_harness.json）**：

| 指标 | naive | harness |
|---|---|---|
| 真实完成（测试 exec 判定） | **4/6** | **5/6** |
| 自称完成 | 6/6（口头 ALL_CORRECT） | =账本（测试不过不算完成） |
| **幻觉式完成 FCR** | **TRUE**（自称 6 实际 4） | **结构性 0** |
| LLM 调用 | 2 | 8（4× 成本） |

![E1](../experiments/results/e1_naive_vs_harness.png)

## 解读：FCR（false completion rate）为什么是核心指标

naive 组最危险的输出不是"做错了"，是**"声称做完了"而实际 4/6**——如果这进入下游流水线，错误会在你不知道的地方复利放大（讲透Loop E2：漏检率被轮数放大）。harness 组的 FCR **结构性为 0**：完成判定从"模型说了算"换成"测试说了算"——这不是模型变好了，是**判定权转移**。

## 不足（诚实）

1. 4→5/6 的提升只有 +1，样本 6 太小——E1 的重点不是提升幅度，是 FCR 的结构性差异
2. "$9→$200"的幅度依赖"模型已够聪明"前提（$200 实验用的是强模型）；0.5B 上 harness 救不动能力缺口（E3 将实锤这一点）
3. harness 成本 4×：可靠性是用调用数买的（E4 会给出什么时候该停）
