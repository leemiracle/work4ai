# 04 · ★ 状态与失忆：账本交付状态，读取仍是模型能力

> 核心实验：**E3 崩溃恢复三条件**（[experiments/e3_state_amnesia.py](../experiments/e3_state_amnesia.py)）

## 直觉

长任务的 agent 像 value 每天换人的工地：图纸（账本）不落盘，每个新会话都在猜"昨天干到哪了"。S 组件 = 工地办公室的图纸柜。

## walkinglabs 最小四文件

`AGENTS.md`（指令宪法）+ `init.sh`（环境自检）+ `feature_list.json`（任务账本）+ `progress.md`（进度+证据）——"四个文件，agent 会话立刻显著稳定"。

## 本地复现（E3）

场景：6 任务做完 t1-t3 后崩溃（上下文全丢），重启后三种恢复条件：
- **A 无账本**：直接问"已完成哪些？下一个？"
- **B 截断窗口**：只保留崩溃前最后一轮对话
- **C 账本恢复**：注入 progress.md 全文

```bash
cd 讲透Harness/experiments && timeout 1400 python3 e3_state_amnesia.py
```

**结果（results/e3_state_amnesia.json，3 reps）**：

| 条件 | done 集精确恢复 | next 正确 | 幻觉模式 |
|---|---|---|---|
| A 无账本 | 0% | 33% | **声称全部完成**（乐观高报 200%+） |
| B 截断窗口 | 0% | 33% | 只记得最后一轮（t3）+ 幻觉 t2 |
| C 账本 | 33% | 33% | 信息全给到，**仍把 pending 段误读为 done** |

![E3](../experiments/results/e3_state_amnesia.png)

## 两个发现（第二个比第一个深）

**发现 1（预期内）**：无状态 = 幻觉恢复。A 组 3/3 全部声称"6 个全做完了"——模型的默认恢复策略是**乐观补全**，这在生产里意味着重复劳动或遗漏。

**发现 2（预期外，本单元最有价值的诚实发现）**：**账本 ≠ 恢复**。C 组账本信息 100% 充分，0.5B 只有 1/3 次完全读对（rep0 完美："已完成 add、rev、count_vowels，下一步 slugify"；rep1/2 把"## 待办"段读成完成）。这不是账本的问题，是**读取能力**的问题——S 组件交付状态，解析状态仍依赖模型。这正是 Harness-Bench **harness dependence**（弱模型受 harness 影响更大，2605.27922）的本地实锤，与 AHE"收益随模型饱和衰减"（+2.3~+10.1pp）互证。

**工程对策**（E5 将验证）：SELECT 由 harness 代码执行，不问模型——账本是给**代码**读的，不是给模型读的。

## meta 教训：解析器也是 harness

E3 v1 的解析器把第 2 问（"下一个做什么"）里出现的函数名也算进"已完成"，一度把 C 组 rep0 的完美恢复误判为幻觉。**度量工具本身的 bug 会污染实验结论**——实验代码也是 harness 的一部分，也要过验证（E2 的 L1/L2 层级对解析器同样适用）。
