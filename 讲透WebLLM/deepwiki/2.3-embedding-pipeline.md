  The Embedding Pipeline in WebLLM provides functionality for generating vector representations (embeddings) of text inputs. These embeddings capture semantic meaning and can be used for semantic search, retrieval augmented generation (RAG), clustering, and other applications. This page documents the implementation and usage of the embedding functionality in WebLLM.

 For information about the general architecture of WebLLM, see [Architecture](https://deepwiki.com/mlc-ai/web-llm/1.1-architecture). For details about the Chat System, see [Chat System](https://deepwiki.com/mlc-ai/web-llm/2.2-chat-system).

 
## Overview

 The Embedding Pipeline converts text inputs into fixed-length vector representations that preserve semantic meaning. Unlike the Chat System which generates text, the Embedding Pipeline focuses on creating numerical representations that capture the meaning of the input text. These embeddings can be used to measure semantic similarity between texts, power RAG systems, and enable other language understanding tasks.

### Response Format

 The embedding API returns a response with the following structure:

 
| Field | Type | Description |
|---|---|---|
| object | string | Always "list" |
| data | Array | Array of embedding objects |
| model | string | The model ID used |
| usage | Object | Token usage statistics |

 Each embedding object in the `data` array contains:

 
 - `object`: Always "embedding"
 - `embedding`: Array of numbers representing the embedding vector
 - `index`: Position in the original input array

### Memory Management

 Key memory considerations:

 
 - **Max Batch Size**: Limited by available GPU memory (set during model compilation)
 - **Context Window Size**: Maximum number of tokens for a single input
 - **Padding**: Inputs in a batch are padded to the same length
 
 Sources: [src/embedding.ts67-92](https://github.com/mlc-ai/web-llm/blob/632d3472/src/embedding.ts#L67-L92)

 
### Performance Metrics

 The Embedding Pipeline provides methods to track performance:

 
 - `getCurRoundEmbedTotalTime()`: Total time spent in the last embedding operation
 - `getCurRoundEmbedTotalTokens()`: Number of tokens embedded in the last operation
 - `getCurRoundEmbedTokensPerSec()`: Embedding throughput in tokens per second

## Error Handling

 The Embedding Pipeline includes several error types to handle various failure scenarios:

 
| Error Type | Description |
|---|---|
| EmbeddingUnsupportedModelError | Thrown when trying to use a non-embedding model |
| EmbeddingSlidingWindowError | Embedding should not use sliding window |
| EmbeddingChunkingUnsupportedError | Embedding doesn't support chunking |
| EmbeddingExceedContextWindowSizeError | Input exceeds model's context window |
| EmbeddingInputEmptyError | Input cannot be empty |
