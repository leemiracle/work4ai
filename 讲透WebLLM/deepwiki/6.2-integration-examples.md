## Chrome Extension Integration

 The Chrome extension example demonstrates how to integrate WebLLM directly into a browser extension. This allows running LLMs that can interact with web page content.

 
```

```

 The Chrome extension integrates WebLLM by:

 
 - Creating an `MLCEngine` instance in the extension's popup
 - Loading a model with progress reporting
 - Extracting content from the active tab to use as context
 - Streaming generated responses back to the UI
 
 Key integration patterns include:

 
```
// Creating the MLCEngine instance
const engine: MLCEngineInterface = await CreateMLCEngine(selectedModel, {
  initProgressCallback: initProgressCallback,
});

// Using the chat completions API with streaming
const completion = await engine.chat.completions.create({
  stream: true,
  messages: chatHistory,
});
for await (const chunk of completion) {
  const curDelta = chunk.choices[0].delta.content;
  if (curDelta) {
    curMessage += curDelta;
  }
  updateAnswer(curMessage);
}
```

## Framework-Specific Integration Patterns

 Different frameworks require specific integration approaches to work effectively with WebLLM.

 
| Framework | Integration Pattern | Key Considerations |
|---|---|---|
| React | React Hooks | Use useEffect for model loading, state management for chat |
| Next.js | Client Components | Avoid server-side loading with 'use client' directive |
| Vue | Composition API | Use ref and reactive for reactive state |
| Angular | Services | Create injectable services for WebLLM management |
| Svelte | Stores | Use stores for reactive state management |

## Performance Considerations for Integrations

 When integrating WebLLM with other technologies, consider these performance optimization patterns:

 
 - **Worker Integration**: Use Web Workers for computation-heavy tasks to prevent UI freezing
 - **Progressive Loading**: Load models in stages, allowing UI interaction before model is fully loaded
 - **Streaming Responses**: Use streaming to display partial results as they're generated
 - **Caching**: Leverage browser cache for model weights and tokenizer files
 
 For more details on performance optimization, see [Caching and Performance](https://deepwiki.com/mlc-ai/web-llm/5.4-caching-and-performance).
