  This document describes the function calling feature in WebLLM, which allows language models to invoke JavaScript functions based on user input. Function calling enables models to interact with external systems, fetch data, and perform operations that extend beyond text generation capabilities.

 For related features like structured output in JSON format, see [JSON Mode and Schema](https://deepwiki.com/mlc-ai/web-llm/5.2-json-mode-and-schema).

 
## Overview

 Function calling in WebLLM allows you to define functions that the language model can "call" during generation. The model identifies when to invoke a function based on user input, generates the appropriate arguments, and can incorporate the function's response in its final answer.

## Tool Choice Options

 WebLLM supports different modes for tool/function selection:

 
| Option | Description | Example |
|---|---|---|
| "auto" | Let the model decide whether to use functions | tool_choice: "auto" |
| "none" | Don't use function calling | tool_choice: "none" |
| Specific function | Force the model to use a specific function | tool_choice: { type: "function", function: { name: "fn_name" } } |

 The `getFunctionCallUsage` utility determines how functions should be used based on these options.

## Error Handling

 WebLLM provides specialized error types for function calling:

 
 - `ToolCallOutputParseError`: When the output cannot be parsed as JSON
 - `ToolCallOutputInvalidTypeError`: When the parsed output is not an array
 - `ToolCallOutputMissingFieldsError`: When required fields (`name` or `arguments`) are missing
 
 These errors help identify issues with the model's function calling output format.

 Sources: [src/support.ts10-17](https://github.com/mlc-ai/web-llm/blob/632d3472/src/support.ts#L10-L17)

## Conclusion

 Function calling in WebLLM provides a powerful way to extend language models with external capabilities. By allowing models to invoke JavaScript functions, WebLLM enables applications to perform actions beyond text generation, such as retrieving data, interacting with external APIs, or manipulating the user interface.

 The implementation supports different model formats, provides both OpenAI-compatible and manual approaches, and includes robust error handling to ensure reliable function calling.
