  The Text Completion API provides a straightforward interface for generating text from a single prompt using WebLLM. Unlike the [Chat Completion API](https://deepwiki.com/mlc-ai/web-llm/4.1-chat-completion-api) which handles structured conversations with multiple messages and roles, the Text Completion API offers a simpler approach focused on completing a single text input. This API follows the OpenAI Completions API pattern, making it familiar for developers transitioning from other environments.

 
## API Overview

 The Text Completion API is implemented as part of WebLLM's OpenAI-compatible API layer and is accessed through the `completions.create()` method on an MLCEngine instance.

## Request Format

 The Text Completion API accepts a variety of parameters to control the generation process:

 
| Parameter | Type | Description |
|---|---|---|
| prompt | string | The text to complete |
| max_tokens | number | Maximum number of tokens to generate |
| temperature | number | Controls randomness (0-2) |
| top_p | number | Alternative to temperature for nucleus sampling |
| n | number | Number of completions to generate |
| stream | boolean | Whether to stream the response |
| stop | string[] | Sequences where generation should stop |
| frequency_penalty | number | Penalty for token frequency in text so far |
| presence_penalty | number | Penalty for token presence in text so far |
| logit_bias | object | Modify likelihood of specific tokens |
| logprobs | boolean | Return log probabilities of output tokens |
| seed | number | Seed for deterministic generation |
| echo | boolean | Echo the prompt in the response |
| model | string | ID of the model to use (if multiple loaded) |
| ignore_eos | boolean | Ignore EOS token and generate until max_tokens |

## Differences from OpenAI API

 While WebLLM's Text Completion API closely follows OpenAI's design, there are some key differences:

 
 - **Model Loading**: Models must be loaded explicitly with `CreateMLCEngine()` or `engine.reload()` before making API calls
 - **Unsupported Fields**: Some fields from OpenAI's API are not supported: 
 - `suffix`
 - `user`
 - `best_of`
 - **Execution Environment**: WebLLM runs on WebGPU in the browser, while OpenAI's API runs on server-side infrastructure
 - **Performance Metrics**: WebLLM includes additional performance metrics in the response

## Conclusion

 The Text Completion API provides a simple yet powerful interface for generating text from prompts in WebLLM. Its compatibility with the OpenAI Completions API makes it familiar for developers, while its integration with WebLLM's engine enables running language models directly in the browser using WebGPU.
