  This document describes WebLLM's Web Worker integration, which enables running large language model inference in background threads to prevent UI freezing during computation. Web Worker integration maintains the same interface as direct MLCEngine usage while delegating the actual computation to a separate thread.

 For information about Service Worker integration, which provides similar functionality but with persistence across page refreshes, see [Service Worker Integration](https://deepwiki.com/mlc-ai/web-llm/3.2-service-worker-integration).

## Key Components

 
### WebWorkerMLCEngine

 `WebWorkerMLCEngine` runs in the main thread and implements the `MLCEngineInterface`. It serves as a client that delegates work to a Web Worker.

 The `WebWorkerMLCEngine` communicates with the worker thread through `WorkerRequest` and `WorkerResponse` messages, each containing:

 
 - `kind`: Type of request/response
 - `uuid`: Unique identifier to match requests with responses
 - `content`: Request parameters or response data

## Implementation Details

 
### Message Types

 The `WebWorkerMLCEngineHandler` handles various message types including:

 
| Message Kind | Purpose |
|---|---|
| reload | Load model(s) |
| chatCompletionNonStreaming | Non-streaming chat completion |
| chatCompletionStreamInit | Initialize streaming chat completion |
| completionStreamNextChunk | Get next chunk in streaming response |
| embedding | Process embedding request |
| interruptGenerate | Interrupt ongoing generation |
| unload | Unload model and free resources |

## Performance Considerations

 
 - **Memory Usage**: Web Workers run in separate threads but share memory with the main thread. Large models will consume significant memory regardless of using workers.
 - **Initialization Time**: Initial model loading happens in the worker thread, so the UI remains responsive during loading.
 - **Message Overhead**: There is some overhead for message passing between threads, but this is negligible compared to the inference time.
 - **Multiple Workers**: Running multiple models can be done by creating multiple workers, but be mindful of memory constraints.
