  This document covers the JSON Mode and Schema capabilities in WebLLM, which allow developers to constrain model outputs to valid JSON format and optionally enforce specific JSON schemas. These features enable structured data extraction from language models, making them suitable for applications that require machine-readable outputs.

 For information about related structured output capabilities, see [Function Calling](https://deepwiki.com/mlc-ai/web-llm/5.1-function-calling).

 
## Introduction to JSON Mode and Schema

 JSON Mode and Schema provide two levels of control over structured outputs from WebLLM models:

 
 - **JSON Mode**: Ensures the model's response is a valid JSON object, without specifying the internal structure
 - **JSON Schema**: Extends JSON Mode by enforcing a specific schema (structure) that the JSON response must follow
 
 These capabilities are particularly useful for:

 
 - Building applications that parse model outputs programmatically
 - Creating consistent data structures for downstream processing
 - Reducing the need for error handling and fallbacks due to malformed responses
 - Implementing tool use and function calling patterns

## JSON Mode

 JSON Mode is the simpler of the two features. It instructs the WebLLM model to generate a response that is syntactically valid JSON, without imposing constraints on the schema or content of that JSON.

 
### Implementation

 JSON Mode is enabled by setting the `response_format` property in the `ChatCompletionRequest` to `{ type: "json_object" }`. This tells the model to generate valid JSON output.

## JSON Schema

 JSON Schema extends JSON Mode by enforcing a specific structure that the JSON output must follow. This provides greater control over the format and content of model responses.

 
### Schema Definition Methods

 WebLLM supports multiple ways to define JSON schemas:

 
 - **JSON String**: Directly providing a schema as a JSON string
 - **TypeBox**: Using third-party libraries like TypeBox to create strongly-typed schemas
 - **EBNF Grammar**: Using Extended Backus-Naur Form grammar for more flexible constraints

### Best Practices

 
 - **Prompting Strategy**: Even with JSON Mode or Schema enabled, it's still helpful to explicitly instruct the model to generate JSON in your prompt. This can be done in either the user message or system prompt.
 - **Choose the Right Approach**:

 
 - Use JSON Mode when you need valid JSON but don't care about its exact structure
 - Use JSON Schema when you need to enforce a specific structure
 - Use EBNF Grammar for more complex constraints beyond what JSON Schema can express
 - **Testing**: Test your schema with different prompts to ensure the model can successfully generate valid outputs. Some complex schemas might be difficult for smaller models to follow.
 - **Streaming Considerations**: Both JSON Mode and Schema work with streaming, but be aware that parsing partial JSON during streaming might require special handling.

## Summary

 JSON Mode and Schema provide powerful capabilities for controlling the structure of model outputs in WebLLM. By constraining responses to valid JSON with optional schema validation, applications can reliably extract structured data from language models for programmatic use. These features can be combined with various prompting strategies and model configurations to enable advanced use cases like tool calling, data extraction, and structured knowledge representation.
