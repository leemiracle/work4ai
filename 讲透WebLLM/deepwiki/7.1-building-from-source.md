## Bundle Post-Processing

 The build process includes a post-processing step that fixes compatibility issues in the generated JavaScript bundle:

 
### Key Post-Processing Operations

 
 - **Worker Compatibility**: Removes `createRequire` imports to ensure compatibility with Web Workers and Chrome Extensions
 - **NextJS Compatibility**: Replaces file path references with dummy values
 - **Browser Compatibility**: Handles Node.js specific imports like `perf_hooks` and `ws`
 
 These modifications are necessary because the bundle needs to run in various environments (browsers, workers, extensions) that have different restrictions.

 Sources: [cleanup-index-js.sh1-31](https://github.com/mlc-ai/web-llm/blob/632d3472/cleanup-index-js.sh#L1-L31)

## Troubleshooting Common Build Issues

 
| Issue | Solution |
|---|---|
| TVM dependency errors | Try using the pre-built package instead of building from source |
| Rollup errors | Check Node.js version (should be v14+) |
| Post-processing script fails | Ensure you have proper permissions and Unix-like environment |
| Compatibility issues with examples | Check browser WebGPU support and enable flags if needed |

 
## Conclusion

 Building WebLLM from source gives you flexibility to modify and extend the library for your needs. The process involves setting up dependencies (especially TVM.js), building the TypeScript source files, and applying post-processing fixes for various environments.

 For most users who simply want to use WebLLM, installing the pre-built package is recommended. See [Getting Started](https://deepwiki.com/mlc-ai/web-llm/1.2-getting-started) for more information on that approach.
