  This page describes the high-level architecture of WebLLM, a system that enables running large language models directly in web browsers using WebGPU for hardware acceleration. We'll cover the core components, their relationships, and different integration options. For specific implementation details of individual components, please refer to their respective pages in this wiki.

 
## Overview

 WebLLM is designed as a browser-native LLM inference engine with OpenAI API compatibility. Its architecture is built around several key components that work together to provide high-performance, in-browser AI capabilities without requiring server-side processing.

 
```

```

 The system follows a modular design that separates concerns between model execution, conversation management, and API interfaces. This enables flexibility in how and where models are executed.

## Core Components

 
### MLCEngine

 At the heart of WebLLM is the `MLCEngine` class, which serves as the primary interface for interacting with the system. It manages model loading, inference, and provides an OpenAI-compatible API interface.

 
```

```

 The `MLCEngine` is responsible for:

 
 - Loading and managing models
 - Processing API requests (chat completions, text completions, embeddings)
 - Coordinating between different pipelines (chat, embedding)
 - Managing locks to prevent concurrent access to models
 
 Sources: [src/engine.ts104-147](https://github.com/mlc-ai/web-llm/blob/632d3472/src/engine.ts#L104-L147) [src/engine.ts433-457](https://github.com/mlc-ai/web-llm/blob/632d3472/src/engine.ts#L433-L457)

 
### Chat System

 The chat system consists of several interrelated components:

 
 - **LLMChatPipeline**: Handles the core inference for chat models, including token generation logic
 - **Conversation**: Manages conversation history and formats prompts according to model requirements
 - **ChatConfig**: Contains configuration for the chat model, including tokenizer settings and sampling parameters
 
 
```

```

 The `LLMChatPipeline` is the workhorse of the chat system, implementing the core autoregressive text generation algorithm. It handles:

 
 - Prompt prefilling
 - Token-by-token decoding
 - KV-cache management
 - Integration with the TVM runtime for WebGPU computation
 
 Sources: [src/llm_chat.ts40-291](https://github.com/mlc-ai/web-llm/blob/632d3472/src/llm_chat.ts#L40-L291) [src/llm_chat.ts489-652](https://github.com/mlc-ai/web-llm/blob/632d3472/src/llm_chat.ts#L489-L652) [src/config.ts73-94](https://github.com/mlc-ai/web-llm/blob/632d3472/src/config.ts#L73-L94)

 
### Conversation Manager

 The `Conversation` class manages conversation state and formats prompts according to the model's requirements. It handles:

 
 - Message history storage
 - System prompt management
 - Message formatting according to the model's conversation template
 - Support for different roles (user, assistant, system, tool)
 
 
```

```

 The `Conversation` class bridges the gap between the high-level OpenAI-style message format and the specific prompt format required by various open-source models.

## Integration Options

 WebLLM provides three main integration options to suit different application needs:

 
### Main Thread Integration

 The simplest integration option that runs everything on the main browser thread.

 
```

```

 This approach is simplest to implement but may cause UI freezing during computation.

 Sources: [README.md118-137](https://github.com/mlc-ai/web-llm/blob/632d3472/README.md?plain=1#L118-L137)

 
### Web Worker Integration

 Offloads computation to a background thread to keep the UI responsive.

 
```

```

 This integration provides better user experience for complex applications by moving computation off the main thread.

 Sources: [README.md214-255](https://github.com/mlc-ai/web-llm/blob/632d3472/README.md?plain=1#L214-L255)

 
### Service Worker Integration

 Enables persistent model loading across page reloads.

 
```

```

 The service worker integration allows models to persist across page reloads and enables offline operation in some scenarios.

## Conclusion

 WebLLM's architecture is designed to enable high-performance LLM inference directly in web browsers. Its modular design, with clear separation between the API layer, engine, and execution pipelines, provides flexibility in how and where models are executed.

 The system's OpenAI API compatibility makes it easy to integrate with existing applications, while its worker integration options enable different performance and persistence characteristics to suit varied application needs.
