  The Chat System is a core component within WebLLM that manages conversational interactions with language models running in the browser. This system handles the entire chat process from formatting prompts to generating responses, including conversation history management, token generation, and various techniques to control output quality.

 This document covers the technical implementation of the Chat System components. For information about the embedding functionality, see [Embedding Pipeline](https://deepwiki.com/mlc-ai/web-llm/2.3-embedding-pipeline). For details about the higher-level API endpoints, see [Chat Completion API](https://deepwiki.com/mlc-ai/web-llm/4.1-chat-completion-api).

### Configuration Hierarchy

 WebLLM uses a hierarchical configuration system:

 
 - **Model-level configuration** (`ChatConfig`): Loaded from the model's `mlc-chat-config.json` and contains model-specific settings that apply to all chat interactions with that model.
 - **Generation-level configuration** (`GenerationConfig`): Can be specified per generation request to override the default model settings for a specific chat interaction.
 - **Conversation template configuration** (`ConvTemplateConfig`): Defines how messages are formatted for the model, including system prompts, role markers, and separators.
 
 This layered approach allows for flexibility in configuring both the model's default behavior and per-request customizations.

### Generation Process

 The LLMChatPipeline implements a two-phase token generation process:

 
 - **Prefill Phase** (`prefillStep`):

 
 - Processes the entire input prompt at once
 - Chunks long inputs into manageable pieces
 - Updates the KV cache with the prompt tokens
 - Generates the first output token
 - **Decoding Phase** (`decodeStep`):

 
 - Generates one token at a time
 - Updates the KV cache with each generated token
 - Applies various sampling strategies and penalties
 - Checks for stop conditions

### Image Input Handling

 For images, the pipeline follows these steps:

 
 - Detects image URLs in the input message
 - Loads the image data from each URL
 - Converts the image to an RGB array
 - Passes the RGB array to the model's image embedding function
 - Combines text and image embeddings into a single sequence
 - Forwards the combined embeddings through the model
 
 The system is designed to handle interleaved text and image content within a single message, maintaining the proper order of the inputs.

### JSON Mode and Grammar Implementation

 The grammar-based generation system:

 
 - **Initializes Grammar Matcher**: Based on a JSON schema or grammar string
 - **Creates Token Bitmasks**: During each generation step to constrain possible tokens
 - **Applies Constraints on GPU**: Using the `apply_bitmask_inplace` function
 - **Validates Generated Tokens**: Ensuring they follow the grammar rules
 
 This approach ensures that the generated text strictly adheres to the requested format, such as valid JSON objects that match a provided schema.

## Customization Points

 The Chat System provides several ways to customize the generation process:

 
| Customization Point | Description | Implementation Location |
|---|---|---|
| Temperature | Controls randomness of generation | sampleTokenFromLogits() |
| Top-P | Controls diversity via nucleus sampling | sampleTokenFromLogits() |
| Repetition Penalty | Reduces repetition of tokens | sampleTokenFromLogits() |
| Frequency/Presence Penalties | Controls word repetition patterns | sampleTokenFromLogits() |
| Stop Strings | Custom strings that stop generation | processNextToken() |
| Max Tokens | Maximum tokens to generate | processNextToken() |
| LogitProcessor | Custom logit manipulation | sampleTokenFromLogits() |
| Response Format | Controls output format (e.g., JSON) | prefillStep() |
| Logit Bias | Manual adjustment of token probabilities | sampleTokenFromLogits() |

## Performance Considerations

 The Chat System includes several optimizations for browser performance:

 
 - **Chunked Processing**: Long inputs are processed in chunks to avoid blocking the main thread
 - **KV Cache Management**: Efficient handling of the attention cache to maximize context length
 - **Sliding Window Attention**: Enables processing of long sequences with limited memory
 - **Performance Metrics**: Tracks and reports token/second rates for prefill and decode phases
