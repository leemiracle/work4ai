# 03 · 知识图谱与本体

> 承接 [02-PROLOG到AnswerSet到ASP](./02-PROLOG到AnswerSet到ASP.md)。02 讲了符号推理**语言**的演化；本章讲符号主义在**知识表示**（Knowledge Representation, KR）层面的工程化——**知识图谱（KG）**与**本体（Ontology）**。这一支是符号主义唯一从未"死过"的分支：从 1968 年 Quillian 的语义网，到 2012 年 Google Knowledge Graph 上线，再到 2024+ LLM + KG 的检索增强（RAG）。**LLM 是隐式模糊 KG；KG 是显式严格 LLM**。

---

## 直觉层

### 一个具体时刻

> 2012 年 5 月 16 日，Google 搜索上线 **Knowledge Graph**，Amit Singhal 在博客里写下 "Things, not strings"——搜索不再只匹配字符串，而要理解"实体"。一夜之间，搜索右侧开始出现实体卡片。**角色**：Singhal。**冲突**：网页索引里只有文本，没有"概念"。**时刻**：他把 Google 多年收购的 Freebase（2010 收购 MetaWeb）+ NLP 抽取的实体融合成 5 亿实体、35 亿关系的产品级 KG。这是符号主义最大规模的工业胜利——比 MYCIN 大 1000 倍。

### 为什么这是 LLM 时代必读

LLM 是**压缩的隐式 KG**——训练数据里的所有三元组被压进权重。但 LLM 的"知识"有三大病：幻觉、不可溯源、不可编辑。**KG 反过来**：可溯源（每条边可指向 URL）、可编辑（改一条边立刻生效）、零幻觉（查不到就说查不到）。**LLM + KG（RAG）** 是 2023+ 工业部署的标配——这是符号主义在 LLM 时代的复活方式。

## 数学层

### RDF：三元组

RDF（Resource Description Framework）= **(主语, 谓词, 宾语)** 三元组的集合。

$$\text{KG} \subseteq S \times P \times O$$

如 `(苏格拉底, type, 人)`、`(苏格拉底, 死于, 饮鸩)`。形式上是**带标签的有向图**——节点是实体，边是关系。

### OWL：本体 + 描述逻辑

OWL（Web Ontology Language）在 RDF 上加**类、层级、约束**。其数学基础是**描述逻辑（Description Logic, DL）**——FOL 的**可判定子集**。

| DL 构件 | 含义 | FOL 翻译 |
|---|---|---|
| $C \sqsubseteq D$ | 类 C 是类 D 的子类 | $\forall x. C(x) \to D(x)$ |
| $\exists R.C$ | 存在 R 关系指向 C | $\exists y. R(x,y) \land C(y)$ |
| $C \sqcap D$ | 类交 | $C(x) \land D(x)$ |

**关键定理**：OWL 2 DL 的可满足性是 **2-NEXPTIME** 完备的——比 FOL 的半可判定**严格弱**，但**可判定**。这是 KG 工业化的根本保障——保证推理会在有限步停机。

### 适用边界

- **开放世界假设（OWA）**：RDF/OWL 默认 OWA——"没说的不等于假"。这让 KG 与 FOL 兼容。
- **vs 闭世界（CWA）**：数据库是 CWA——"没记录的就是假的"。PROLOG 的 NAF 偏 CWA。
- **incompleteness 是常态**：Wikidata 永远不全；但 DL 推理在 OWA 下仍可推出新事实（subclass 传递等）。

## 代码层

用 `rdflib` 建一个微型 KG 并查询：

```python
from rdflib import Graph, URIRef, RDF, Namespace
from rdflib.namespace import RDFS

EX = Namespace("http://example.org/")
g = Graph()
# 三元组
g.add((EX.苏格拉底, RDF.type, EX.人))
g.add((EX.柏拉图, RDF.type, EX.人))
g.add((EX.苏格拉底, EX.教导, EX.柏拉图))
# 本体层级
g.add((EX.人, RDFS.subClassOf, EX.会死的))

# SPARQL 查询：所有会死的实体
q = """
PREFIX ex: <http://example.org/>
SELECT ?x WHERE { ?x a ?c . ?c rdfs:subClassOf+ ex:会死的 }
"""
print(list(g.query(q)))  # [苏格拉底, 柏拉图]
```

**LLM + KG 的 RAG 模式**（伪代码）：

```python
def kg_rag(question: str) -> str:
    # 1. LLM 从问题抽取实体 + 关系
    entities = llm_extract_entities(question)
    # 2. 在 KG 里查 k-hop 子图（严格的符号检索）
    subgraph = kg_query(entities, hop=2)
    # 3. 把子图作为 prompt 上下文喂回 LLM 生成答案（可溯源）
    answer = llm_generate(question, context=subgraph)
    return answer, subgraph.provenance  # 每句话可追溯到三元组
```

**反直觉数字**：Google 2018 内部报告，KG + LLM 的 RAG 在 factoid QA 上比纯 LLM 错误率降 **40-60%**。代价是 recall 下降——KG 里没有的就答不出。

## 不足层

- **已证明**：OWL 2 DL 的可判定性（DL 理论，2009）；SPARQL 查询的复杂度（NP-完全）。
- **经验但未证**：KG 构建成本是每三元组 \$0.5-5（人工标注）——这是工业瓶颈，无理论保证能降到 LLM 自动抽取的 \$0.001 量级。LLM 抽取（REBEL、GPT-4-IE）在 precision 上还达不到人工水平。
- **未解**：
  1. **常识 KG 不可能手工完成**：CYC 的教训（见 00 章）。LLM 学到了常识，但是隐式的。
  2. **多模态 KG**：图像、视频里如何抽 KG？这是神经符号的开放前线。
  3. **演化与版本**：KG 随时间变化，如何做"时态 KG"推理？学术热点，工程仍难。
  4. **神经-符号桥的形式化**：怎么把 LLM 的向量表示"对齐"到 KG 的离散节点？embedding（TransE、RotatE）是工程解，理论未闭（[`讲透神经符号`](../讲透神经符号/)）。

## 费曼回炉记录（L2 自检）

- **F2 卡壳点**：我最初把 RDF 和 OWL 当成同一回事。重读 W3C 标准后发现：RDF 是数据模型（三元组），OWL 是在本体语言（带类、约束、推理规则）。OWL **基于** RDF，但加了描述逻辑的层。混淆这两者会把可判定性搞错——纯 RDF 不可判定（可嵌入任意 FOL），OWL DL 才可判定。
- **F3 术语翻译**：
  - "本体（ontology）" → 一套定义"什么东西属于哪类，类之间什么关系"的清单——比如"哲学家是人""教导是关系"。
  - "开放世界假设" → "知识库没记录的不一定是假的，只是不知道"——和数据库相反。
  - "subclass 传递" → "哲学家是人，人是哺乳动物，那哲学家也是哺乳动物"——自动继承。
- **F4 回炉**：v1 只讲 RDF 不讲 OWL；v2 加入 OWL 与描述逻辑，因为可判定性是 KG 工业化的命根——没这一层，KG 就退化为图数据库，不能叫"本体"。同时 v2 把"LLM + KG = RAG"作为主线，否则这章看不出与 LLM 时代的关联。
