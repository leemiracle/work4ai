## Overview

vLLM's test suite runs on multiple hardware platforms, with dedicated infrastructure for platform-specific testing. Each platform utilizes:

  1. **Execution Script** : Shell scripts (e.g., `run-amd-test.sh`, `run-intel-test.sh`) that orchestrate Docker containers, GPU state management, and test invocation.
  2. **Test Definition YAML** : Declares test steps, hardware requirements (e.g., `mi300_1`, `h100`, `intel_gpu`), and dependencies.
  3. **Command Processors** : Logic within execution scripts to rewrite `pytest` commands, adding platform-specific flags or re-quoting markers.
  4. **Hardware Overrides** : CI-level `mirror` configurations that duplicate NVIDIA-based tests on alternative hardware.

## AMD/ROCm Testing Infrastructure

AMD/ROCm tests run inside Docker containers pulled from a per-commit image on bare-metal Buildkite agents. The primary entry point for AMD CI configuration is `.buildkite/test-amd.yaml`.

### Agent Pools and Hardware Tiers

AMD CI utilizes several generations of hardware, tracked in `.buildkite/test-amd.yaml`:

  * **MI250** : Standard AMD unit testing [.buildkite/test-amd.yaml43-45](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/test-amd.yaml#L43-L45)
  * **MI300** : High-performance MI300 testing [.buildkite/test-amd.yaml43-45](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/test-amd.yaml#L43-L45)
  * **MI355** : Next-generation AMD hardware [.buildkite/test-amd.yaml43-45](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/test-amd.yaml#L43-L45)

### Integration and Stability

  * **V1 Engine** : Split across multiple steps (e.g., `V1 Sample + Logits`, `V1 Core + KV + Metrics`) to avoid resource interference [.buildkite/test-amd.yaml55-62](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/test-amd.yaml#L55-L62)
  * **Stability Scheduling** : V1 e2e tests using 4 GPUs are scheduled on 8-GPU machines to ensure process stability [.buildkite/test-amd.yaml57-58](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/test-amd.yaml#L57-L58)
  * **Compilation Tests** : Uses `find` to launch multiple `pytest` instances for unit tests under `compile/` to mitigate known execution issues [.buildkite/test-amd.yaml63-66](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/test-amd.yaml#L63-L66)

### Docker and Build Environment

The ROCm build environment is managed via the `run-amd-test.sh` script, which handles artifact downloading and local image preparation.

  * **Base Images** : The environment is built upon `rocm/vllm-dev:base` and `rocm/vllm-dev:ci_base` [docker/Dockerfile.rocm6-7](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile.rocm#L6-L7)
  * **Artifact Image** : Uses `rocm/vllm-ci-artifact` created from Buildkite wheel artifacts [.buildkite/scripts/hardware_ci/run-amd-test.sh168-183](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/scripts/hardware_ci/run-amd-test.sh#L168-L183)
  * **Multi-Node Detection** : Detects multi-node jobs structurally via the `NUM_NODES` environment variable or bracket command syntax [.buildkite/scripts/hardware_ci/run-amd-test.sh6-9](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/scripts/hardware_ci/run-amd-test.sh#L6-L9)

## Intel XPU Testing

Intel XPU testing is managed via `.buildkite/intel_jobs/` and the orchestration script `.buildkite/scripts/hardware_ci/run-intel-test.sh`.

### Environment and Dependencies

XPU testing relies on a specialized Docker environment defined in the Buildkite build scripts [.buildkite/intel_jobs/test-intel.yaml8](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/intel_jobs/test-intel.yaml#L8-L8)

  * **Linear Backends** : Support for XPU-specific linear backends for FP8 and low-precision execution, selectable via `--linear-backend xpu` [.buildkite/intel_jobs/test-intel.yaml72-76](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/intel_jobs/test-intel.yaml#L72-L76)
  * **Expert Parallelism** : Intel-specific Expert Parallelism (EP) testing on models like `PowerMoE-3b` [.buildkite/intel_jobs/test-intel.yaml46-47](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/intel_jobs/test-intel.yaml#L46-L47)
  * **Fused MoE Reference** : XPU tests often set `VLLM_XPU_FUSED_MOE_USE_REF=1` to ensure correctness during development [.buildkite/intel_jobs/test-intel.yaml49](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/intel_jobs/test-intel.yaml#L49-L49) [.buildkite/intel_jobs/misc_intel.yaml98](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/intel_jobs/misc_intel.yaml#L98-L98)

### XPU Test Categories

Testing is sharded into several functional areas:

  * **Example Tests** : Validates `offline_inference/generate.py` across different configurations (eager mode, `cudagraph_mode=NONE`, TP=2, Triton backend) [.buildkite/intel_jobs/test-intel.yaml34-50](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/intel_jobs/test-intel.yaml#L34-L50)
  * **V1 Engine Tests** : Validates core engine components, workers, and speculators, ignoring known unsupported features on XPU [.buildkite/intel_jobs/test-intel.yaml96-103](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/intel_jobs/test-intel.yaml#L96-L103)
  * **Quantization** : Validates W8A8 FP8, GPTQ, and AWQ integration on Intel hardware [.buildkite/intel_jobs/test-intel.yaml43-45](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/intel_jobs/test-intel.yaml#L43-L45) [.buildkite/intel_jobs/test-intel.yaml72-74](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/intel_jobs/test-intel.yaml#L72-L74)
  * **Disaggregated Serving** : Tests accuracy for Prefiller/Decoder separation using `run_xpu_disagg_accuracy_test.sh` with varying TP sizes [.buildkite/intel_jobs/misc_intel.yaml149-155](https://github.com/vllm-project/vllm/blob/185cada3/.buildkite/intel_jobs/misc_intel.yaml#L149-L155)

## CPU Testing
