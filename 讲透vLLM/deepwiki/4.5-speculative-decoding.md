## Purpose and Scope

Speculative decoding is an inference optimization technique that generates multiple tokens per forward pass by proposing "draft" tokens that are verified against the target model's output distribution. This document explains vLLM's implementation of speculative decoding, covering various methods such as N-gram matching, draft models, EAGLE, DFlash, Medusa, and Multi-Token Prediction (MTP). It details the draft token management lifecycle, acceptance logic via rejection sampling, and the integration within the `GPUModelRunner`.

## Architecture Overview

Speculative decoding in vLLM involves a "Proposer" (which generates draft tokens) and a "Rejection Sampler" (which verifies them). The system is integrated into the model execution pipeline, specifically within the `GPUModelRunner` in the V1 engine. The `SpeculativeConfig` object, defined in `vllm/config/speculative.py`, governs the behavior of these components.

## Speculative Configuration

Speculative decoding is configured via the `SpeculativeConfig` class [vllm/config/speculative.py69-79](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/speculative.py#L69-L79) which defines the method, the number of tokens to speculate, and specific parameters for the proposer.

### Supported Speculative Methods

vLLM supports a wide array of methods, defined in `SpeculativeMethod` [vllm/config/speculative.py69-79](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/speculative.py#L69-L79):

  * **ngram** : Look up matching sequences in the prompt or history.
  * **draft_model** : Use a smaller, faster model to predict tokens.
  * **medusa** : Use multiple heads on top of the base model.
  * **eagle / eagle3** : Extrapolation-based drafting using hidden states [vllm/v1/spec_decode/eagle.py10-22](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/spec_decode/eagle.py#L10-L22)
  * **dflash** : Parallel drafting via the DFlash architecture [vllm/v1/spec_decode/llm_base_proposer.py34-37](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/spec_decode/llm_base_proposer.py#L34-L37)
  * **dspark** : Speculative method used for DeepSeek-V4 DSpark, specifically validated for Qwen3-Omni [vllm/config/speculative.py143-179](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/speculative.py#L143-L179)
  * **mtp** : Multi-token prediction architectures (e.g., DeepSeek MTP) [vllm/v1/spec_decode/llm_base_proposer.py32](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/spec_decode/llm_base_proposer.py#L32-L32)
  * **suffix** : Decoding based on shared suffixes.

## Proposer Implementations

Proposers are responsible for generating draft tokens. In the V1 architecture, they typically inherit from `SpecDecodeBaseProposer` [vllm/v1/spec_decode/llm_base_proposer.py71-78](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/spec_decode/llm_base_proposer.py#L71-L78)

### EAGLE Proposer

The `EagleProposer` implements the EAGLE algorithm. It often requires hidden states from the target model to be passed back to the speculator for the next drafting step.

  * **Implementation** : `EagleProposer` [vllm/v1/spec_decode/eagle.py10-22](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/spec_decode/eagle.py#L10-L22)
  * **Hidden States** : It sets `pass_hidden_states_to_model=True` to enable hidden state communication [vllm/v1/spec_decode/eagle.py20](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/spec_decode/eagle.py#L20-L20)
  * **Eagle3 Support** : Specialized utility `set_eagle3_aux_hidden_state_layers` manages auxiliary states for EAGLE3 [vllm/v1/worker/gpu/model_runner.py135-137](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/model_runner.py#L135-L137)

### DFlash and Parallel Drafting

  * **DFlash** : Parallel drafting architecture supported by `DFlashQwen3ForCausalLM` and `DFlashLagunaForCausalLM` [vllm/v1/spec_decode/llm_base_proposer.py34-36](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/spec_decode/llm_base_proposer.py#L34-L36)
  * **Parallel Drafting** : DFlash always uses parallel drafting (all tokens in one pass) [vllm/v1/spec_decode/llm_base_proposer.py112-115](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/spec_decode/llm_base_proposer.py#L112-L115) It includes an additional slot for the `next_token_id` that does not shift like EAGLE [vllm/v1/spec_decode/llm_base_proposer.py110-112](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/spec_decode/llm_base_proposer.py#L110-L112)

## Rejection Sampling and Verification

The `RejectionSampler` [vllm/v1/worker/gpu/spec_decode/rejection_sampler.py138-141](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/spec_decode/rejection_sampler.py#L138-L141) ensures the tokens produced by speculative decoding are statistically identical to tokens that would have been produced by the target model alone.

### Acceptance Logic

The sampler compares the probabilities of the draft tokens against the probabilities assigned by the target model.

  1. **Verification** : If the target model's probability for a draft token is higher than the proposer's, the token is accepted.
  2. **Adaptive Verification** : vLLM supports `AdaptiveVerificationManager` to dynamically adjust the number of tokens verified based on acceptance history [vllm/v1/worker/gpu/model_runner.py131-134](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/model_runner.py#L131-L134)
  3. **Bonus Tokens** : If all draft tokens are accepted, a bonus token is sampled from the target model's final distribution.
