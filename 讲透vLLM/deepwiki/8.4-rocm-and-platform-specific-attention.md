## Purpose and Scope

This page documents ROCm-specific attention backends, AITER (AMD Instinct Triton Enhanced Runtime) optimizations, and platform-specific selection logic for non-CUDA hardware. ROCm (AMD's GPU platform) utilizes distinct attention implementations compared to CUDA, including AITER backends optimized for MI300/MI325 (GFX942/GFX950) architectures, custom paged attention kernels, and specialized "Skinny GEMM" operations. The page also covers CPU-based attention backends and how vLLM detects hardware capabilities to select the optimal backend based on architecture, model parameters, and environment configuration.

## ROCm Platform Detection and GCN Architecture

ROCm platform detection identifies the GPU's GCN (Graphics Core Next) architecture string to determine available backends and optimizations. vLLM differentiates between GFX9 (CDNA family) and GFX1X (RDNA family).

**Key Architecture Identifiers** :

  * **GFX9** : Includes `gfx90a` (MI200), `gfx942` (MI300), and `gfx950` [csrc/rocm/skinny_gemms.cu24-27](https://github.com/vllm-project/vllm/blob/185cada3/csrc/rocm/skinny_gemms.cu#L24-L27)
  * **GFX950** : Specifically targeted for high-performance operations, often detected via `on_gfx950()` flags [vllm/model_executor/layers/utils.py149](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/utils.py#L149-L149)
  * **GFX1X** : Covers RDNA architectures like `gfx11` and `gfx12` [csrc/rocm/skinny_gemms.cu29-32](https://github.com/vllm-project/vllm/blob/185cada3/csrc/rocm/skinny_gemms.cu#L29-L32)
  * **Compute Units** : Kernel launch configurations are often scaled based on the number of compute units available on the device, retrieved via `num_compute_units()` [vllm/v1/attention/backends/rocm_aiter_fa.py44-45](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_aiter_fa.py#L44-L45)

**Environment Consistency** : vLLM ensures that `HIP_VISIBLE_DEVICES` and `CUDA_VISIBLE_DEVICES` are synchronized at import time to prevent misconfigurations [vllm/envs.py24-25](https://github.com/vllm-project/vllm/blob/185cada3/vllm/envs.py#L24-L25)

## AITER Backend and Operations

AITER provides optimized Triton and Assembly kernels for ROCm. It is primarily supported on MI3XX (GFX942/GFX950) architectures. vLLM integrates AITER through several backend implementations and environment-controlled feature flags.

### AITER Optimized Operations

AITER provides specialized kernels for several bottlenecks in LLM execution on AMD hardware:

---|---|---

## Platform-Specific Attention Selection

### ROCm Attention Selection

ROCm uses a prioritized selection logic. When no backend is specified, vLLM iterates through compatible backends based on priority.

  1. **ROCM_AITER_UNIFIED_ATTN** : Preferred for MI3XX, supporting sinks and multimodal prefixes [vllm/v1/attention/backends/rocm_aiter_unified_attn.py60-75](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_aiter_unified_attn.py#L60-L75)
  2. **ROCM_ATTN** : PagedAttention-based backend for ROCm with Triton prefix prefill support [vllm/v1/attention/backends/rocm_attn.py163-176](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_attn.py#L163-L176)
  3. **ROCM_AITER_FA** : Optimized FlashAttention implementation for ROCm using AITER primitives [vllm/v1/attention/backends/rocm_aiter_fa.py190-200](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_aiter_fa.py#L190-L200)

## ROCm Attention Implementation Detail

### ROCm Flash Attention (AITER)

The `AiterFlashAttentionBackend` includes a custom `cp_mha_gather_cache_kernel` written in Triton to handle non-contiguous KV cache layouts (e.g., "NHD" or "SHUFFLE") during prefill by mapping tokens to batches and blocks [vllm/v1/attention/backends/rocm_aiter_fa.py47-73](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_aiter_fa.py#L47-L73)

### ROCm Unified Attention

The `RocmAiterUnifiedAttentionImpl` integrates the `unified_attention` operator from the `aiter` package [vllm/v1/attention/backends/rocm_aiter_unified_attn.py152-154](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_aiter_unified_attn.py#L152-L154)

  * **KV Cache Shape** : Requires block sizes to be a multiple of 16 [vllm/v1/attention/backends/rocm_aiter_unified_attn.py53](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_aiter_unified_attn.py#L53-L53)
  * **Layout** : Supports `LBHNC` and `LHBNC` layouts where the layer is outermost [vllm/v1/attention/backends/rocm_aiter_unified_attn.py93-97](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_aiter_unified_attn.py#L93-L97)

### Skinny GEMM Optimization

For small batch sizes (skinny GEMMs) on ROCm, vLLM provides optimized C++ kernels like `wvSplitK` and `LLMM1` to bypass standard `hipblaslt` overhead when beneficial [vllm/model_executor/layers/utils.py185-195](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/utils.py#L185-L195) These are specifically enabled via `VLLM_ROCM_USE_SKINNY_GEMM` [vllm/envs.py153](https://github.com/vllm-project/vllm/blob/185cada3/vllm/envs.py#L153-L153)

## CPU Attention Implementation Detail

CPU attention is highly optimized for various ISAs (Instruction Set Architectures) using a dispatch mechanism.

### ISA Detection and Dispatch

The CPU backend relies on `CPUAttentionMetadataBuilder` [vllm/v1/attention/backends/cpu_attn.py131](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/cpu_attn.py#L131-L131) to calculate scheduler metadata for execution.

  * **ISA Detection** : Determines the best available ISA (e.g., AMX, VEC, NEON, RVV) [csrc/cpu/cpu_attn_impl.hpp15](https://github.com/vllm-project/vllm/blob/185cada3/csrc/cpu/cpu_attn_impl.hpp#L15-L15)
  * **Sliding Window** : The builder resolves sliding window configurations across layers via `_group_sliding_window` [vllm/v1/attention/backends/cpu_attn.py168-187](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/cpu_attn.py#L168-L187)
