## Purpose and Scope

This page documents the Multi-Latent Attention (MLA) backends, specialized attention implementations for hybrid models (Mamba/SSM), and sparse attention mechanisms in vLLM. MLA is a core architectural feature of the DeepSeek-V2, V3, and V4 models, designed to significantly reduce KV cache memory footprints through latent space compression. This page covers the architecture of MLA backends, the unique KV cache formats used, and the integration of specialized attention for hybrid architectures.

**Sources:** [vllm/model_executor/layers/attention/mla_attention.py4-24](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/attention/mla_attention.py#L4-L24) [vllm/v1/attention/backends/mla/rocm_aiter_mla.py1-32](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/mla/rocm_aiter_mla.py#L1-L32)

## Multi-head Latent Attention (MLA) Architecture

MLA compresses Key and Value vectors into a lower-dimensional latent representation. DeepSeek's MLA simulates multi-head attention (MHA) while the compute profile is similar to multi-query attention (MQA) during decode.

### Latent Space Projection and Computation

MLA uses two primary approaches depending on the ratio of query sequence length ($S_q$) to KV sequence length ($S_{kv}$):

  1. **Compute Friendly (Prefill)** : Used when $S_q / S_{kv}$ is near 1. It projects the latent KV vector into separate $k_{nope}$ and $v$ heads before performing MHA. [vllm/model_executor/layers/attention/mla_attention.py66-86](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/attention/mla_attention.py#L66-L86)
  2. **Data-Movement Friendly (Decode)** : Used when $S_q / S_{kv}$ is small (e.g., during decoding). It performs attention in the latent space (MQA-like) and projects the output back to the head dimension afterward, minimizing KV cache bandwidth. [vllm/model_executor/layers/attention/mla_attention.py94-119](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/attention/mla_attention.py#L94-L119)

### Backend Implementations

  * **FlashMLA (NVIDIA)** : Optimized for Hopper (SM90) and Blackwell (SM100). It prepares scheduler metadata and supports FP8 KV cache through specialized kernels. [vllm/v1/attention/backends/mla/flashmla.py161-195](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/mla/flashmla.py#L161-L195)
  * **FlashInfer MLA (NVIDIA)** : Leverages the FlashInfer library. It supports FP8 and NVFP4 KV cache quantization. It uses `trtllm_batch_decode_with_kv_cache_mla` for decoding and provides a `FlashInferMLAMetadataBuilder` for uniform batch scheduling. ## Specialized Attention Mechanisms

### DeepSeek V3/V4 Indexer

The `DeepseekV32IndexerBackend` and `DeepseekV4IndexerBackend` are specialized for large-scale DeepSeek models. They implement a sparse indexing mechanism that splits prefill requests into chunks based on workspace size and logits constraints via `split_indexer_prefill_chunks`. This is critical for models where the latent dimension $L_{kv}$ is large (e.g., 512), requiring careful memory management during prefill. [vllm/v1/attention/backends/mla/indexer.py103-149](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/mla/indexer.py#L103-L149) [vllm/v1/attention/backends/mla/indexer.py152-198](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/mla/indexer.py#L152-L198)

### Sparse Attention and Quantization

vLLM provides kernels for sparse MLA on ROCm, such as `indexer_k_quant_and_cache_triton`. This kernel performs per-token FP8 quantization of the latent K vector and stores it in the paged KV cache. It supports "SHUFFLE" layouts for block-based access and handles scale factor calculation for `e4m3fnuz` (AMD) and `e4m3fn` (NVIDIA) formats. [vllm/v1/attention/ops/rocm_aiter_mla_sparse.py152-215](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/ops/rocm_aiter_mla_sparse.py#L152-L215) [vllm/v1/attention/ops/rocm_aiter_mla_sparse.py217-233](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/ops/rocm_aiter_mla_sparse.py#L217-L233)

### FlexAttention and Paged Mapping

For specialized attention patterns, `FlexAttentionBackend` provides a mechanism to map physical block locations to logical indices. The `create_block_mask` utility from PyTorch is used to define causal or custom sparsity patterns within the flex attention framework. [tests/v1/attention/test_attention_backends.py9-10](https://github.com/vllm-project/vllm/blob/185cada3/tests/v1/attention/test_attention_backends.py#L9-L10)

### DeepGEMM and FP8 Optimization

vLLM integrates `DeepGEMM` for high-performance FP8 execution on Hopper and Blackwell GPUs. It uses specialized scale formats like `UE8M0` (packed scales in `int32` tensors) to optimize memory throughput. The `DeepGemmQuantScaleFMT` oracle determines the optimal scale format based on the device capability (SM90 vs SM100). [vllm/utils/deep_gemm.py49-90](https://github.com/vllm-project/vllm/blob/185cada3/vllm/utils/deep_gemm.py#L49-L90) [vllm/utils/deep_gemm.py103-124](https://github.com/vllm-project/vllm/blob/185cada3/vllm/utils/deep_gemm.py#L103-L124)
