## Purpose and Scope

This document describes vLLM's argument parsing system, centered around the `EngineArgs` dataclass and associated utilities that convert command-line arguments and Python API parameters into configuration objects. This system bridges user-facing interfaces (CLI, Python API) with the internal `VllmConfig` object that drives engine initialization.

For information about the configuration objects that `EngineArgs` produces, see [2.2 VllmConfig and Specialized Configuration Objects](https://github.com/vllm-project/vllm/blob/185cada3/2.2 VllmConfig and Specialized Configuration Objects) For environment variable configuration, see [2.3 Environment Variables System](https://github.com/vllm-project/vllm/blob/185cada3/2.3 Environment Variables System) For compilation-specific configuration, see [2.4 Compilation Configuration and Optimization Levels](https://github.com/vllm-project/vllm/blob/185cada3/2.4 Compilation Configuration and Optimization Levels)

## Type Inference and Argument Generation

The `get_kwargs()` and `_compute_kwargs()` functions implement type inference to automatically generate `argparse` argument specifications from config dataclass type annotations.

### Type Inference Pipeline

Title: Annotation to Argparse Logic

### Type Annotation to Argparse Mapping

Type Annotation| Argparse Configuration| Example  
---|---|---  
`bool`| `action=BooleanOptionalAction`| `--enable-lora / --no-enable-lora`  
`Literal["a", "b"]`| `type=str, choices=["a", "b"]`| `--policy fcfs/priority`  
`Literal["a", "b"] | str`| `type=str, metavar=["a", "b"]`| Accepts literal or custom  
`list[int]`| `type=int, nargs="+"`| `--cudagraph-capture-sizes 1 2 4`  
`tuple[int, int]`| `type=int, nargs=2`| Fixed-length tuple  
`int | None`| `type=optional_type(int)`| Accepts int or "None"

## AsyncEngineArgs and API Serving

For asynchronous serving, `AsyncEngineArgs` extends `EngineArgs` to include API-specific parameters such as process count and rank.

### Multiprocess Forkserver

When `VLLM_WORKER_MULTIPROC_METHOD` is set to `forkserver`, the API server pre-imports heavy modules like `vllm.v1.engine.async_llm` in the forkserver process to speed up worker spawning.
