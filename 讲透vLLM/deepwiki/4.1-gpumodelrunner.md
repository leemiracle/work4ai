## Purpose and Scope

`GPUModelRunner` is the central coordinator for model execution on GPU devices in vLLM. It orchestrates the model forward pass, manages request state on the GPU, coordinates KV cache allocation, and integrates with the sampling and speculative decoding subsystems. This component bridges the scheduling layer (which decides what to execute) with the low-level model execution, handling all device-specific operations including attention metadata preparation and batch assembly. [vllm/v1/worker/gpu/model_runner.py158-188](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/model_runner.py#L158-L188)

vLLM provides two primary implementations:

  1. **Stable`gpu_model_runner`**: The established implementation which contains logic for both text and multimodal models within a single class structure. [vllm/v1/worker/gpu_model_runner.py230-240](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu_model_runner.py#L230-L240)
  2. **Model Runner V2 (`vllm/v1/worker/gpu/`)**: A modular architecture designed for the vLLM V1 engine. It follows a strict coding style to keep the core runner minimal, delegating specific behaviors to subcomponents for sampling, speculative decoding, multimodal processing, and pooling. [vllm/v1/worker/gpu/model_runner.py3-18](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/model_runner.py#L3-L18)

### RequestState Implementation

The `RequestState` class is optimized for high-throughput serving. Key attributes include:

  * **`all_token_ids`** : A `StagedWriteTensor` that stores the full token history for every request. By using host-resident memory (UVA), vLLM keeps these large buffers accessible to the GPU while reducing VRAM usage. [vllm/v1/worker/gpu/states.py33-38](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/states.py#L33-L38)
  * **Staged Writes** : To minimize synchronization, updates to GPU state are "staged" on the CPU and then committed to the GPU/UVA buffers in a single operation via `apply_staged_writes()`. [vllm/v1/worker/gpu/states.py125-131](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/states.py#L125-L131)

## Model Execution Pipeline

The `execute_model` method is the entry point for a single inference iteration. It coordinates state updates, input preparation, the model forward pass, and output processing. [vllm/v1/worker/gpu/model_runner.py228-235](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/model_runner.py#L228-L235)

### Execution Flow

  1. **State Synchronization** : `_update_states(scheduler_output)` processes new, cached, and finished requests to update the `RequestState`. [vllm/v1/worker/gpu/model_runner.py343-424](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/model_runner.py#L343-L424)
  2. **Input Preparation** : 
     * `prepare_prefill_inputs` copies token IDs from UVA buffers to the GPU `input_ids` buffer for prefill requests. [vllm/v1/worker/gpu/input_batch.py108](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/input_batch.py#L108-L108)
     * `combine_sampled_and_draft_tokens` prepares inputs for decode steps, including speculative draft tokens. [vllm/v1/worker/gpu/input_batch.py103](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/input_batch.py#L103-L103)
  3. **Attention Metadata** : `_prepare_attn_metadata` builds the metadata required by the attention backends (e.g., slot mappings, block tables). [vllm/v1/worker/gpu/model_runner.py461-512](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/model_runner.py#L461-L512)
  4. **Forward Pass** : The model's `forward` method is called. If CUDA graphs are available and the batch shape matches, `ModelCudaGraphManager` executes the captured graph. [vllm/v1/worker/gpu/model_runner.py270-282](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/model_runner.py#L270-L282)
  5. **Sampling/Pooling** : 
     * For generative models, the `Sampler` processes logits to select next tokens. [vllm/v1/worker/gpu/sample/sampler.py129](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/sample/sampler.py#L129-L129)
     * For pooling models, the `PoolingRunner` generates embeddings from hidden states. [vllm/v1/worker/gpu/pool/pooling_runner.py125](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/pool/pooling_runner.py#L125-L125)

Sources: [vllm/v1/worker/gpu/model_runner.py228-341](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/model_runner.py#L228-L341) [vllm/v1/worker/gpu/input_batch.py103-108](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/input_batch.py#L103-L108) [vllm/v1/worker/gpu/sample/sampler.py129](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/sample/sampler.py#L129-L129) [vllm/v1/worker/gpu/pool/pooling_runner.py125](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/pool/pooling_runner.py#L125-L125)

  * **Proposers** : Classes like `DraftModelSpeculator` generate candidate tokens. [vllm/v1/worker/gpu/spec_decode/speculator.py143](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/spec_decode/speculator.py#L143-L143)

## CUDA Graph Management

To achieve maximum performance during the decode phase, `GPUModelRunner` utilizes CUDA graphs via `CudaGraphManager` (and its model-specific wrapper `ModelCudaGraphManager`). [vllm/v1/worker/gpu/cudagraph_utils.py102-132](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/cudagraph_utils.py#L102-L132)

  * **Capture** : During initialization, the runner "warms up" the model by capturing graphs for common batch sizes and sequence lengths defined in `compilation_config.cudagraph_capture_sizes`. [vllm/v1/worker/gpu/cudagraph_utils.py173-183](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/cudagraph_utils.py#L173-L183)
  * **Dispatch** : During `execute_model`, the logic determines if the current batch matches a captured signature. [vllm/v1/worker/gpu/model_runner.py270-282](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/model_runner.py#L270-L282)
  * **Breakable CUDA Graphs** : vLLM supports a "breakable" CUDA graph mode which allows for partial graph execution without requiring full `torch.compile` integration. [vllm/v1/worker/gpu/cudagraph_utils.py139-143](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu/cudagraph_utils.py#L139-L143)
