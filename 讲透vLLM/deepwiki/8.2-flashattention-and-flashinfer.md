## Purpose and Scope

This document describes the primary attention backend implementations for standard decoder attention in vLLM: **FlashAttention** and **FlashInfer**. These backends handle efficient attention computation with paged KV cache for transformer models on NVIDIA and compatible hardware.

For information about:

  * Multi-Latent Attention (MLA) backends for DeepSeek models, see [8.3](https://github.com/vllm-project/vllm/blob/185cada3/8.3)
  * Backend selection logic and registry, see [8.1](https://github.com/vllm-project/vllm/blob/185cada3/8.1)
  * ROCm-specific attention (AITER), see [8.4](https://github.com/vllm-project/vllm/blob/185cada3/8.4)
  * Triton-based backends, see [vllm/v1/attention/backends/triton_attn.py3-6](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/triton_attn.py#L3-L6)

Both backends support:

  * Paged KV cache with variable sequence lengths [vllm/v1/attention/backends/flash_attn.py212-220](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/flash_attn.py#L212-L220) [vllm/v1/attention/backends/flashinfer.py12-16](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/flashinfer.py#L12-L16)
  * Mixed decode/prefill batches [vllm/v1/attention/backends/utils.py76](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/utils.py#L76-L76)
  * FP8 quantized KV cache [vllm/v1/attention/backends/flash_attn.py155-157](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/flash_attn.py#L155-L157) [vllm/v1/attention/backends/flashinfer.py95-97](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/flashinfer.py#L95-L97)
  * Cascade attention for prefix sharing [vllm/v1/attention/backends/flash_attn.py68-73](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/flash_attn.py#L68-L73) [vllm/v1/attention/backends/flashinfer.py17-18](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/flashinfer.py#L17-L18)

## Architecture Overview

### Class Hierarchy

**Diagram: Backend Class Structure**

The architecture follows a three-component pattern defined in `AttentionBackend` [vllm/v1/attention/backend.py59-86](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backend.py#L59-L86):

  1. **Backend class** : Defines hardware capabilities and factory methods for implementations.
  2. **Metadata builder** : Constructs the `AttentionMetadata` specific to the kernel's requirements (e.g., block tables, sequence lengths).
  3. **Implementation** : Executes the actual attention computation via the `forward` method, typically wrapping C++/CUDA extensions.

Sources: [vllm/v1/attention/backend.py59-86](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backend.py#L59-L86) [vllm/v1/attention/backends/flashinfer.py279-307](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/flashinfer.py#L279-L307) [vllm/v1/attention/backends/flash_attn.py78-137](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/flash_attn.py#L78-L137)

## Metadata Building Process

### FlashInfer Metadata Construction

**Diagram: FlashInfer Metadata Construction Flow**

The `FlashInferMetadataBuilder.build()` method creates `FlashInferMetadata` which encapsulates wrappers for prefill and decode. It decides between native FlashInfer and TRTLLM pathways based on hardware (e.g., Blackwell) and quantization modes [vllm/v1/attention/backends/flashinfer.py844-876](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/flashinfer.py#L844-L876)

## KV Cache Management

### Cache Layout and Quantization

vLLM supports multiple KV cache layouts. The backend registry determines compatibility via `get_supported_kv_cache_layouts` [vllm/v1/attention/backends/utils.py188-190](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/utils.py#L188-L190)

Layout| Internal Name| Description  
---|---|---  
**LBNHC**| `NHD`| Head-major layout used by native FlashAttention [vllm/v1/attention/backends/utils.py155](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/utils.py#L155-L155)  
**LBHNC**| `HND`| Block-major layout preferred by FlashInfer [vllm/v1/attention/backends/utils.py156](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/utils.py#L156-L156)  
  
Scaling factors for quantized KV caches (FP8) are initialized in `_init_kv_cache_quant` and synchronized between device and host to support backends like FlashInfer that require host-side scales [vllm/model_executor/layers/attention/attention.py148-175](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/attention/attention.py#L148-L175)

## Runtime JIT Compilation

vLLM utilizes JIT compilation to optimize kernels for specific runtime parameters.

  1. **FlashInfer JIT** : Uses `nvcc` to compile kernels if pre-built cubins are not available [vllm/utils/flashinfer.py55-63](https://github.com/vllm-project/vllm/blob/185cada3/vllm/utils/flashinfer.py#L55-L63) It manages a workspace buffer for intermediate JIT-compiled artifacts [vllm/v1/attention/backends/flashinfer.py103-109](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/flashinfer.py#L103-L109)
  2. **FlashAttention Compile-from-Specs** : FA4 introduces `compile_flash_attn_varlen_func_from_specs` which generates optimized kernel variants for specific head sizes and dtypes at runtime [vllm/vllm_flash_attn/flash_attn_interface.py1-20](https://github.com/vllm-project/vllm/blob/185cada3/vllm/vllm_flash_attn/flash_attn_interface.py#L1-L20)
