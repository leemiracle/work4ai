## Purpose and Scope

This page documents the FastAPI-based HTTP server that exposes vLLM's inference capabilities through an OpenAI-compatible REST API. It covers the server's entry points, startup sequence, route registration, middleware stack, engine client lifecycle, and multi-process deployment modes.

The server is designed to be a high-performance gateway to the underlying `AsyncLLM` engine, supporting various protocols including OpenAI Chat/Completions, Anthropic Messages, and specialized vLLM extensions like the Responses API, Batch API, and Disaggregated Serving.

The vLLM CLI dispatches subcommands through the `CLISubcommand` base class. The `serve` subcommand is the primary entry point for the API server, supporting various deployment topologies.

The dispatch logic in `ServeSubcommand.cmd()` examines `args.api_server_count` and data parallel load balancing modes:

Condition| Mode| Function  
---|---|---

## Server Startup Sequence

The key startup steps performed by `run_server_worker()` [vllm/entrypoints/openai/api_server.py59](https://github.com/vllm-project/vllm/blob/185cada3/vllm/entrypoints/openai/api_server.py#L59-L59):

  1. **`setup_server(args)`** – validates arguments, binds the socket (TCP or Unix domain), sets `ulimit`, installs a `SIGTERM` handler [vllm/entrypoints/openai/api_server.py59](https://github.com/vllm-project/vllm/blob/185cada3/vllm/entrypoints/openai/api_server.py#L59-L59)
  2. **`build_async_engine_client(args)`** – async context manager that creates the `AsyncLLM` engine and yields an `EngineClient` [vllm/entrypoints/openai/api_server.py59](https://github.com/vllm-project/vllm/blob/185cada3/vllm/entrypoints/openai/api_server.py#L59-L59)
  3. **`engine_client.get_supported_tasks()`** – queries the engine to discover which task types the loaded model supports (e.g., `generate`, `pooling`) [vllm/entrypoints/openai/api_server.py59](https://github.com/vllm-project/vllm/blob/185cada3/vllm/entrypoints/openai/api_server.py#L59-L59)
  4. **`build_app(args, supported_tasks)`** – constructs the `FastAPI` application, registers all routers, and applies middleware [vllm/entrypoints/openai/api_server.py59](https://github.com/vllm-project/vllm/blob/185cada3/vllm/entrypoints/openai/api_server.py#L59-L59)
  5. **`init_app_state(engine_client, app.state, args, supported_tasks)`** – populates `app.state` with engine clients and task handlers [vllm/entrypoints/openai/api_server.py59](https://github.com/vllm-project/vllm/blob/185cada3/vllm/entrypoints/openai/api_server.py#L59-L59)
  6. **`serve_http(app, sock=sock, ...)`** – starts the uvicorn server loop [vllm/entrypoints/launcher.py28](https://github.com/vllm-project/vllm/blob/185cada3/vllm/entrypoints/launcher.py#L28-L28)

### Anthropic Compatibility (`AnthropicServingMessages`)

The `AnthropicServingMessages` class handles requests for the Anthropic Messages API, inheriting from `OpenAIServingChat` [vllm/entrypoints/anthropic/serving.py99](https://github.com/vllm-project/vllm/blob/185cada3/vllm/entrypoints/anthropic/serving.py#L99-L99)

  * **Request Conversion** : Translates Anthropic message formats to internal OpenAI-compatible structures.
  * **Image Handling** : Converts Anthropic image sources (base64 or URL) to proper data URIs for vLLM's multimodal processors via `_convert_image_source_to_url` [vllm/entrypoints/anthropic/serving.py173-192](https://github.com/vllm-project/vllm/blob/185cada3/vllm/entrypoints/anthropic/serving.py#L173-L192)
