## Purpose and Scope

The Transformers backend ([vllm/model_executor/models/transformers/base.py17-113](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L17-L113)) enables vLLM to run Hugging Face Transformers models natively without requiring a dedicated vLLM model architecture implementation. It wraps any compatible `PreTrainedModel` and integrates it with vLLM's paged KV cache, tensor parallelism, pipeline parallelism, quantization, and weight loading infrastructure.

This backend serves as a fallback for models not yet optimized with native vLLM implementations, allowing for immediate support of new architectures as they are released on the Hugging Face Hub. It is designed to perform within a small margin of dedicated vLLM implementations for most architectures.

Sources: [vllm/model_executor/models/transformers/base.py17-113](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L17-L113)

## Activation

The backend is chosen at startup via the `model_impl` argument (or `--model-impl` CLI flag). When the registry resolves the architecture name, the loader selects one of the concrete classes defined in `vllm/model_executor/models/transformers/__init__.py`.

`model_impl` value| Behavior  
---|---  
`"vllm"`| Use vLLM's native implementation; error if none exists.  
`"transformers"`| Always use the Transformers backend.  
`"auto"`| Use vLLM's native implementation if available; fall back to Transformers backend.  
  
Sources: [vllm/model_executor/models/transformers/base.py103-105](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L103-L105) [vllm/model_executor/models/transformers/__init__.py115-176](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/__init__.py#L115-L176)

## `Base` Class Implementation

The `Base` class ([vllm/model_executor/models/transformers/base.py96](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L96-L96)) manages the lifecycle of the underlying Hugging Face model. It inherits from `VllmModel` and several capability interfaces like `SupportsQuant`, `SupportsLoRA`, and `SupportsPP`.

### Initialization Flow

  1. **HF Model Creation** : Instantiates the model on the `meta` device using `AutoModel.from_config` ([vllm/model_executor/models/transformers/base.py161](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L161-L161)). This delays buffer allocation until vLLM is ready to load weights.
  2. **Pipeline Parallelism** : `pipeline_parallel()` replaces layers not on the current rank with `PPMissingLayer` ([vllm/model_executor/models/transformers/base.py166](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L166-L166) [vllm/model_executor/models/transformers/base.py278-305](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L278-L305)).
  3. **Recursive Replacement** : `recursive_replace()` swaps standard `nn` modules (Linear, RMSNorm, Conv) with vLLM-optimized, tensor-parallel versions ([vllm/model_executor/models/transformers/base.py168](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L168-L168) [vllm/model_executor/models/transformers/base.py307-347](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L307-L347)).
  4. **Attention Hooking** : `create_attention_instances()` creates `Attention` objects that bridge HF forward calls to vLLM's attention backends ([vllm/model_executor/models/transformers/base.py170](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L170-L170) [vllm/model_executor/models/transformers/base.py349-405](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L349-L405)).

## Module Replacement and Parallelism

### Linear and Norm Replacement

`Base.recursive_replace()` uses utility functions to swap standard modules for parallel ones:

  * **Linear** : `replace_linear_class` converts `nn.Linear` to `ColumnParallelLinear`, `RowParallelLinear`, or `ReplicatedLinear` based on the model's parallel plan ([vllm/model_executor/models/transformers/utils.py110-147](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/utils.py#L110-L147)).
  * **Norm** : `replace_rms_norm_class` detects if a layer is standard `RMSNorm` or `GemmaRMSNorm` by testing weight initialization on CPU ([vllm/model_executor/models/transformers/utils.py218-247](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/utils.py#L218-L247)).
  * **Conv** : `replace_conv_class` swaps `nn.Conv2d`/`nn.Conv3d` for vLLM's optimized implementations ([vllm/model_executor/models/transformers/utils.py154-186](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/utils.py#L154-L186)).

### Attention Integration

The backend patches the global Transformers attention registry: `ALL_ATTENTION_FUNCTIONS.register("vllm", vllm_attention_forward)` ([vllm/model_executor/models/transformers/__init__.py111](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/__init__.py#L111-L111)).

When a model's attention forward is called, `vllm_attention_forward` retrieves the `Attention` instance for the specific `layer_idx` and executes vLLM's attention logic ([vllm/model_executor/models/transformers/__init__.py46-78](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/__init__.py#L46-L78)).

## Mixture of Experts (MoE) Support

The `MoEMixin` ([vllm/model_executor/models/transformers/moe.py140-144](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/moe.py#L140-L144)) enables support for MoE architectures like Mixtral or OLMoE via the Transformers backend.

### Fused MoE Implementation

It registers a custom operation `transformers_moe_forward` which extends vLLM's `FusedMoE` logic.

  * **TransformersMoERunner** : A `PluggableLayer` that extends `MoERunner` to handle MoE execution within the Transformers backend ([vllm/model_executor/models/transformers/moe.py58-67](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/moe.py#L58-L67)).
  * **Custom Routing** : Storing the `topk_ids` in the layer during the HF forward pass via `_transformers_moe_forward` so they can be accessed without interfering with CUDA graphs ([vllm/model_executor/models/transformers/moe.py95-105](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/moe.py#L95-L105)).
  * **EP/TP Handling** : The mixin provides `update_physical_experts_metadata` to coordinate expert-parallel load balancing ([vllm/model_executor/models/transformers/moe.py146-160](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/moe.py#L146-L160)).
  * **Weight Mapping** : `TransformersRoutedExperts.get_expert_mapping` defines how expert weights (gate, up, down projections) are mapped from HF checkpoint names to vLLM's fused expert layout ([vllm/model_executor/models/transformers/moe.py126-138](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/moe.py#L126-L138)).

## Weight Loading Infrastructure

The Transformers backend utilizes `WeightsMapper` and `AutoWeightsLoader` to map Hugging Face checkpoint keys to the vLLM internal structure.

### `WeightsMapper` and `AutoWeightsLoader`

  * **WeightsMapper** : Defines regex, prefix, and substring rules to rename keys during loading ([vllm/model_executor/models/utils.py47-135](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/utils.py#L47-L135)).

It supports overriding logic via `load_weights` or `weight_loader` methods on specific modules ([vllm/model_executor/models/utils.py214-228](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/utils.py#L214-L228)).

## Data Flow: Model Forward Pass

The forward pass in `Base.forward` bridges the standard vLLM execution flow into the Hugging Face `PreTrainedModel` interface.

  1. **Input Preparation** : Handles `input_ids` or `inputs_embeds` depending on the pipeline rank ([vllm/model_executor/models/transformers/base.py440-465](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L440-L465)).
  2. **Position IDs** : Construct `position_ids` from vLLM's `positions` tensor. For legacy models like RoBERTa, `LegacyMixin` adjusts these for padding offsets ([vllm/model_executor/models/transformers/legacy.py67-71](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/legacy.py#L67-L71)).
  3. **HF Forward** : Calls `self.model(...)` passing `attention_instances` to ensure the patched attention function can find its state ([vllm/model_executor/models/transformers/base.py480-493](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/base.py#L480-L493)).

## Pooling and Sequence Classification

### `EmbeddingMixin`

Attaches a `DispatchPooler` for embedding tasks. It defaults to `"CLS"` pooling and is used in `TransformersEmbeddingModel` ([vllm/model_executor/models/transformers/pooling.py33-46](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/pooling.py#L33-L46)).

### `SequenceClassificationMixin`

Instantiates an `AutoModelForSequenceClassification` on the `meta` device to extract the classification head (`classifier` or `score`). It uses `ClassifierWithReshape` to bridge the pooler output to the classification head's expected input shape ([vllm/model_executor/models/transformers/pooling.py86-97](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/transformers/pooling.py#L86-L97)).

## Model Adapters and Specialized Backends

These models typically wrap a base architecture (like Llama) and add auxiliary layers (`fc`, `norm`) to process hidden states for token prediction.

  3. Providing a specialized weight loader `_load_pooling_model_weights` to handle prefixes like `model.` or `language_model.` ([vllm/model_executor/models/adapters.py179-200](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/adapters.py#L179-L200)).
