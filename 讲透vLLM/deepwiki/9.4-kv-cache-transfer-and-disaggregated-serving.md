## Disaggregated Serving Concept

Disaggregated serving separates the **prefill** and **decode** phases of LLM inference onto different vLLM instances. A **prefiller** (producer) runs the prompt through the model to compute KV cache blocks, then transfers those blocks over the network to a **decoder** (consumer) that proceeds directly to token generation.

A proxy server orchestrates requests: it first sends the prompt to a prefiller, then forwards the completed request (with KV transfer metadata attached) to a decoder.

**Architecture:**

Sources: [vllm/distributed/kv_transfer/kv_connector/v1/nixl/scheduler.py1-12](https://github.com/vllm-project/vllm/blob/185cada3/vllm/distributed/kv_transfer/kv_connector/v1/nixl/scheduler.py#L1-L12) [vllm/distributed/kv_transfer/kv_connector/v1/nixl/worker.py1-13](https://github.com/vllm-project/vllm/blob/185cada3/vllm/distributed/kv_transfer/kv_connector/v1/nixl/worker.py#L1-L13) [vllm/distributed/kv_transfer/kv_connector/v1/nixl/metadata.py37-42](https://github.com/vllm-project/vllm/blob/185cada3/vllm/distributed/kv_transfer/kv_connector/v1/nixl/metadata.py#L37-L42)

**Key benefits:**

  * TTFT and ITL can be tuned independently by assigning different parallelism configs to each instance type.
  * Decode instances avoid prefill-decode interference, reducing tail ITL.
  * KV blocks move directly between GPU VRAM regions via RDMA (NIXL/UCX), bypassing CPU when possible.

### NIXL Handshake Protocol

Before blocks can be transferred, the decoder worker must register the prefiller's NIXL agent. This handshake is initiated lazily on first transfer to a given engine.

Sources: [vllm/distributed/kv_transfer/kv_connector/v1/nixl/metadata.py36-42](https://github.com/vllm-project/vllm/blob/185cada3/vllm/distributed/kv_transfer/kv_connector/v1/nixl/metadata.py#L36-L42) [vllm/distributed/kv_transfer/kv_connector/v1/nixl/scheduler.py1-12](https://github.com/vllm-project/vllm/blob/185cada3/vllm/distributed/kv_transfer/kv_connector/v1/nixl/scheduler.py#L1-L12)

### NIXL Configuration

NixlConnector relies on the NIXL library for communication. Environment variables like `VLLM_NIXL_SIDE_CHANNEL_PORT` and `VLLM_NIXL_SIDE_CHANNEL_HOST` are crucial for the handshake process. The `NixlConnectorWorker` handles Mamba/SSM regions specifically by computing NIXL descriptor IDs with specialized strides [vllm/distributed/kv_transfer/kv_connector/v1/nixl/base_worker.py107-167](https://github.com/vllm-project/vllm/blob/185cada3/vllm/distributed/kv_transfer/kv_connector/v1/nixl/base_worker.py#L107-L167)

### Bidirectional KV Transfer

NixlConnector supports bidirectional KV transfer for multi-turn conversations. In this mode, the decoder can send its existing KV blocks back to the prefiller via RDMA, reducing TTFT for subsequent turns.
