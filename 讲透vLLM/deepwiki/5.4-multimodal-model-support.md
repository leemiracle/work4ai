## Purpose and Scope

This page documents vLLM's multimodal model support system, covering the architectural interfaces, supported modalities (image, video, audio), and the data flow from raw input to model embeddings. It details the registration mechanisms that map HuggingFace architectures to vLLM implementations and the specialized processing required for diverse multimodal data.

vLLM supports a wide range of multimodal architectures, including Vision-Language Models (VLMs) like Qwen2.5-VL and LLaVA, audio models like Whisper and Voxtral, and "Omni" models that handle interleaved audio and visual inputs.

## Model Architecture and Interfaces

vLLM defines a standard set of Python Protocols (interfaces) in `vllm/model_executor/models/interfaces.py` that multimodal models must implement to integrate with the engine's execution pipeline.

### The `SupportsMultiModal` Interface

Any model supporting multimodal inputs must implement the `SupportsMultiModal` protocol. This interface ensures the model can handle non-textual data and provide the necessary metadata for the engine's scheduler and memory manager.

Title: Multimodal Interface Hierarchy

  * **`embed_multimodal`** : This is the core functional requirement. It takes multimodal keyword arguments (e.g., `pixel_values`, `image_grid_thw`) and returns `MultiModalEmbeddings` (tensors) to be merged with text embeddings. [vllm/model_executor/models/interfaces.py211-221](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/interfaces.py#L211-L221)
  * **`get_language_model`** : Returns the underlying language model (typically a decoder-only backbone) responsible for processing merged embeddings. [vllm/model_executor/models/interfaces.py237-240](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/interfaces.py#L237-L240)
  * **`configure_mm_token_handling`** : Handles cases where multimodal placeholder tokens are Out-Of-Vocabulary (OOV), ensuring they are masked during text embedding lookups. [vllm/model_executor/models/interfaces.py223-235](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/interfaces.py#L223-L235)

### Specialized Multi-Modal Interfaces

Models may implement additional interfaces to signal support for specific features:

Interface| Purpose  
---|---  
`SupportsMRoPE`| Indicates support for Multimodal Rotary Positional Embeddings (MRoPE), used in models like Qwen2.5-VL. [vllm/model_executor/models/interfaces.py270-278](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/interfaces.py#L270-L278)  
`SupportsTranscription`| Used for audio models that perform Speech-to-Text, requiring specific output processing. [vllm/model_executor/models/interfaces.py281-289](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/interfaces.py#L281-L289)  
`SupportsMultiModalPruning`| Allows the model to prune or compress multimodal tokens before they enter the LLM backbone. [vllm/model_executor/models/interfaces.py260-267](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/interfaces.py#L260-L267)

## Encoder CUDA Graphs

vLLM supports capturing the encoder (e.g., Vision Transformer) forward pass as CUDA Graphs to eliminate host-side kernel launch overhead. This is managed by the `EncoderCudaGraphManager`.

  * **Budget-based Strategy** : Graphs are pre-captured at different token capacity levels (budgets).
  * **Replay Buffers** : Models implementing `SupportsEncoderCudaGraph` use `EncoderCudaGraphReplayBuffers` to manage the tensors during graph capture and replay. [vllm/model_executor/models/qwen2_5_vl.py88](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/qwen2_5_vl.py#L88-L88)
  * **Implementation** : The model's vision tower forward pass is often wrapped in logic that handles both eager execution and graph replay based on whether the current batch fits a captured graph. [vllm/model_executor/models/qwen2_5_vl.py95](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/qwen2_5_vl.py#L95-L95)

## Key Implementation Details

### Embedding Merging Logic

A critical step in multimodal inference is correctly placing the visual/audio embeddings into the text embedding sequence at the locations of placeholder tokens.

  * **Function** : `_merge_multimodal_embeddings` (found in `vllm/model_executor/models/utils.py`)
  * **Logic** : It uses a boolean mask `is_multimodal` to identify where multimodal tokens exist in the input sequence and scatters the features returned by `embed_multimodal` into those slots. [vllm/model_executor/models/qwen3_vl.py152](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/qwen3_vl.py#L152-L152)
  * **Interleaved Data** : For "Omni" models, `check_interleaved_audio_video` determines if audio and video tokens are interleaved within a single contiguous region, triggering specialized merging logic. [vllm/model_executor/models/qwen2_5_omni_thinker.py135-179](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/models/qwen2_5_omni_thinker.py#L135-L179)

MRoPE extends standard RoPE to multiple dimensions (Time, Height, Width) to better represent spatial and temporal relationships in images and videos.

  * **Implementation** : The `compute_mrope_for_media` utility calculates the specific rotary offsets for vision patches based on their grid coordinates.
