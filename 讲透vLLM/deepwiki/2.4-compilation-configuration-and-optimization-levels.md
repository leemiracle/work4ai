This page documents vLLM's compilation configuration system, which controls `torch.compile` integration, CUDA graph capture, custom optimization passes, and performance tuning levels. For general configuration architecture, see [vllm/config/vllm.py](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/vllm.py) For runtime execution behavior, see [vllm/v1/worker/gpu_model_runner.py](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/gpu_model_runner.py)

## Overview

vLLM uses PyTorch's compilation infrastructure to optimize model execution through multiple strategies:

  1. **torch.compile** integration with custom backends.
  2. **CUDA graph capture** to reduce launch overhead.
  3. **Custom Inductor passes** for fusion optimizations (FP8 quantization, sequence parallelism, etc.).
  4. **Optimization levels** (O0-O3) that bundle common configurations.
  5. **vLLM IR (Intermediate Representation)** op framework for platform-portable kernel dispatch.

The compilation system is controlled by `CompilationConfig`, which is part of the larger `VllmConfig` object [vllm/config/vllm.py32](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/vllm.py#L32-L32)

## CompilationMode

The `CompilationMode` enum defines the approaches to compilation:

### Compilation Mode Logic Space

  * **NONE (0)** : No compilation, fully eager PyTorch mode. [vllm/config/compilation.py41-43](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/compilation.py#L41-L43)
  * **STOCK_TORCH_COMPILE (1)** : Uses standard `torch.compile` pipeline. [vllm/config/compilation.py44-45](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/compilation.py#L44-L45)
  * **DYNAMO_TRACE_ONCE (2)** : Single Dynamo trace without recompilation guards. [vllm/config/compilation.py46-47](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/compilation.py#L46-L47)
  * **VLLM_COMPILE (3)** : Custom vLLM Inductor-based backend with caching, piecewise compilation, and custom passes. [vllm/config/compilation.py48-51](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/compilation.py#L48-L51)

## Optimization Levels

vLLM provides predefined optimization levels (O0-O3) that bundle common `CompilationConfig` settings. These levels are defined in `vllm/config/vllm.py` [vllm/config/vllm.py93](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/vllm.py#L93-L93)

  * **O0** : No optimization. No compilation, no CUDA graphs, no other optimizations. The model starts immediately [vllm/config/vllm.py96-98](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/vllm.py#L96-L98)
  * **O1** : Quick optimizations. Enables Dynamo+Inductor compilation and piecewise CUDA graphs [vllm/config/vllm.py99-101](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/vllm.py#L99-L101)
  * **O2** : Full optimizations. Includes O1 optimizations, as well as full and piecewise CUDA graphs. This is the default optimization level [vllm/config/vllm.py102-103](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/vllm.py#L102-L103)
  * **O3** : Currently the same as O2 [vllm/config/vllm.py104-105](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/vllm.py#L104-L105)

## vLLM IR Op Framework

vLLM utilizes an IR (Intermediate Representation) op framework to provide platform-portable kernel dispatch. This allows the same model logic to dispatch to different hardware-optimized kernels or to `torch.compile` friendly implementations.

### vLLM IR Dispatch Logic

The dispatch logic checks configuration flags to enable fusions. For example, `enable_norm_fusion` checks if custom ops like `rms_norm` or `quant_fp8` are active in the `CompilationConfig` or if the `IrOpPriorityConfig` for `rms_norm` is not "native" [vllm/config/vllm.py120-128](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/vllm.py#L120-L128)

The framework allows for platform-specific priority, such as `IrOpPriorityConfig`, which dictates whether to use native PyTorch, AITER, or custom CUDA kernels [vllm/config/kernel.py78](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/kernel.py#L78-L78)

Sources: [vllm/config/vllm.py120-210](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/vllm.py#L120-L210) [vllm/config/kernel.py78](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/kernel.py#L78-L78)

## torch.compile Integration and Compiler Manager

vLLM manages the compilation process via the `CompilerManager` and `CompilerInterface`.

### Compiler Selection

The `make_compiler` function selects the appropriate adaptor based on the configuration and environment. It can use `InductorStandaloneAdaptor` for cached AOT artifacts (controlled by `VLLM_USE_STANDALONE_COMPILE`) or `InductorAdaptor` for standard JIT [vllm/compilation/backends.py96-113](https://github.com/vllm-project/vllm/blob/185cada3/vllm/compilation/backends.py#L96-L113)

### Caching Mechanism

`CompilerManager` handles caching of compiled graphs. It computes a hash based on the `VllmConfig` and saves artifacts to a Python file (`vllm_compile_cache.py`) for readability and persistence [vllm/compilation/backends.py139-183](https://github.com/vllm-project/vllm/blob/185cada3/vllm/compilation/backends.py#L139-L183)
