## Purpose and Scope

This document describes the **EngineCore** and **EngineCoreClient** architecture, which forms the execution backbone of vLLM's V1 engine. EngineCore is the "inner loop" responsible for scheduling requests, orchestrating model execution, and producing outputs. EngineCoreClient provides an abstraction layer that allows EngineCore to run in-process or in a separate background process with different concurrency models.

For configuration that feeds into EngineCore, see [VllmConfig and Specialized Configuration Objects](/vllm-project/vllm/2.2-vllmconfig-and-specialized-configuration-objects). For scheduler internals, see [Scheduler and Resource Allocation](/vllm-project/vllm/3.3-scheduler-and-resource-allocation). For the model execution layer that EngineCore orchestrates, see [GPUModelRunner](/vllm-project/vllm/4.1-gpumodelrunner).

## Architecture Overview

The EngineCore and Client APIs separate execution concerns into two layers:

  1. **EngineCore Layer** : Core scheduling and execution logic.
  2. **Client Layer** : IPC abstraction and concurrency management.

### Step Functions

EngineCore provides primary execution modes for processing batches:

  1. **Synchronous`step()`**: Executes one iteration of scheduling and model forward pass. It retrieves requests from the scheduler, executes them via the model runner, and processes the results. [vllm/v1/engine/core.py438-486](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/core.py#L438-L486)
  2. **Pipelined`step_with_batch_queue()`**: Used to manage multiple concurrent batches, typically for pipeline parallelism. It maintains a `batch_queue` to keep the hardware utilized while processing results asynchronously. [vllm/v1/engine/core.py488-586](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/core.py#L488-L586)

## EngineCoreClient Abstraction

### Client Interface

`EngineCoreClient` is an abstract base class defined in [vllm/v1/engine/core_client.py78](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/core_client.py#L78-L78) that provides a uniform interface for interacting with `EngineCore` regardless of whether it is in-process or in a separate background process.

Clients are instantiated via `EngineCoreClient.make_client()` or `make_async_mp_client()` based on the engine configuration. [vllm/v1/engine/core_client.py90-139](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/core_client.py#L90-L139)

## IPC Mechanisms and Multiproc Management

### ZMQ Communication

For multiprocessing modes, vLLM uses **ZeroMQ (ZMQ)** for low-latency IPC between the client and the `EngineCoreProc`.

  * **Request/Input Path** : The client sends `EngineCoreRequest` objects serialized via `MsgpackEncoder` over a ZMQ socket. [vllm/v1/engine/core_client.py67](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/core_client.py#L67-L67) [vllm/v1/engine/core_client.py535-542](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/core_client.py#L535-L542)
  * **Output Path** : The `EngineCoreProc` streams `EngineCoreOutputs` back to the client using ZMQ. [vllm/v1/engine/core_client.py544-550](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/core_client.py#L544-L550)

### CoreEngineProcManager

The `CoreEngineProcManager` handles the lifecycle of background processes. It spawns `EngineCoreProc.run_engine_core` as separate processes using the `spawn` context. [vllm/v1/engine/utils.py144-196](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/utils.py#L144-L196)

## Data Parallel Coordination

When `data_parallel_size > 1`, the engine uses a `DPCoordinator` to aggregate statistics and a `DPLBAsyncMPClient` to perform load balancing. [vllm/v1/engine/core_client.py133-139](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/core_client.py#L133-L139)

  * **Stickiness** : For tasks like Late Interaction, the client uses `get_late_interaction_engine_index` to route related queries and documents to the same DP rank based on a query key. [vllm/v1/pool/late_interaction.py66-67](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/pool/late_interaction.py#L66-L67)
  * **Load Balancing** : The `DPLBAsyncMPClient` tracks the load of various engine ranks and distributes requests to the rank with the most available capacity. [vllm/v1/engine/core_client.py1516-1544](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/core_client.py#L1516-L1544)
  * **External LB** : In some setups, `data_parallel_external_lb` is used, where each DP rank has its own client and load balancing is handled by an external component. [vllm/v1/engine/core_client.py134-136](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/core_client.py#L134-L136)

## Key Data Structures

### EngineCoreRequest

The primary input structure passed from clients to the engine. It is optimized for serialization using `msgspec.Struct`. [vllm/v1/engine/__init__.py107-112](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/__init__.py#L107-L112)

  * `request_id`: Unique ID for the request.
  * `prompt_token_ids`: The tokenized input.
  * `sampling_params`: Parameters for generation (e.g., temperature).
  * `mm_features`: Multimodal data (images, video).
  * `external_req_id`: The original ID provided by the user, preserved for output correlation. [vllm/v1/engine/__init__.py147](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/__init__.py#L147-L147)

### EngineCoreOutput

The response structure streamed back from the engine. [vllm/v1/engine/__init__.py196-201](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/__init__.py#L196-L201)

  * `request_id`: The ID of the request this output belongs to.
  * `new_token_ids`: Newly generated token IDs.
  * `finish_reason`: Reason for the request finishing (e.g., `STOP`, `LENGTH`, `ABORT`). [vllm/v1/engine/__init__.py47-66](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/__init__.py#L47-L66)
  * `pooling_output`: Tensor containing pooling results for pooling tasks. [vllm/v1/engine/__init__.py208](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/engine/__init__.py#L208-L208)
