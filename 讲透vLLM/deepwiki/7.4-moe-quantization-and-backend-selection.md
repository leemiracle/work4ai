This page documents how quantization is applied to Mixture-of-Experts (MoE) layers in vLLM, and how the runtime selects appropriate compute kernels based on hardware and quantization type. Topics include: FP8, INT8, GPTQ-Marlin, AWQ-Marlin, compressed tensors, MXFP4/NVFP4, and ROCm AITER variants.

For the modular kernel architecture (`FusedMoEKernel`, `FusedMoEPrepareAndFinalize`, `MoEPermuteScratch`), see [7.3](https://github.com/vllm-project/vllm/blob/185cada3/7.3) For FP8 quantization on linear layers, see [7.2](https://github.com/vllm-project/vllm/blob/185cada3/7.2) For the general quantization method registry and lifecycle, see [7.1](https://github.com/vllm-project/vllm/blob/185cada3/7.1)

## MoE Quantization Method Selection

Every `FusedMoE` layer acquires a `FusedMoEMethodBase` instance during `__init__`. This happens via the `FusedMoEFactory` function at [vllm/model_executor/layers/fused_moe/layer.py99-147](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/layer.py#L99-L147) which utilizes the provided `quant_config`. The `quant_config.get_quant_method(layer, prefix)` call determines the specific quantization implementation for the MoE experts.

The `FusedMoEMethodBase` interface defines:

  * `create_weights` — allocates quantized weight parameters [vllm/model_executor/layers/fused_moe/fused_moe_method_base.py53-60](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/fused_moe_method_base.py#L53-L60)
  * `apply` — executes the quantized forward pass [vllm/model_executor/layers/fused_moe/fused_moe_method_base.py62-75](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/fused_moe_method_base.py#L62-L75)
  * `maybe_roundup_sizes` — ensures expert dimensions meet kernel alignment requirements [vllm/model_executor/layers/fused_moe/fused_moe_method_base.py77-88](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/fused_moe_method_base.py#L77-L88)

### FP8 Backend Selection and Experts

The FP8 backend selection depends on hardware and quantization keys. Blackwell-family GPUs (SM100) utilize the `TrtLlmFp8ExpertsModular` backend [vllm/model_executor/layers/fused_moe/experts/trtllm_fp8_moe.py174](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/experts/trtllm_fp8_moe.py#L174-L174) This backend supports Blackwell-specific features and requires `flashinfer-trtllm` [vllm/model_executor/layers/fused_moe/experts/trtllm_fp8_moe.py146](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/experts/trtllm_fp8_moe.py#L146-L146)

For DeepSeek-style blockwise FP8, the `prepare_deepseek_fp8_x_sf` function [vllm/model_executor/layers/fused_moe/experts/trtllm_fp8_moe.py39](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/experts/trtllm_fp8_moe.py#L39-L39) validates and converts activation scales to the TRTLLM layout.

## FlashInfer and DeepGemm Integration

### FlashInfer Backends

FlashInfer provides high-performance CUDA kernels for various MoE formats. The `vllm/utils/flashinfer.py` file provides lazy wrappers for these kernels:

  * `flashinfer_trtllm_bf16_moe`: For unquantized BF16 routed MoE [vllm/utils/flashinfer.py113](https://github.com/vllm-project/vllm/blob/185cada3/vllm/utils/flashinfer.py#L113-L113)
  * `flashinfer_trtllm_fp8_block_scale_moe`: For block-scaled FP8 [vllm/utils/flashinfer.py116](https://github.com/vllm-project/vllm/blob/185cada3/vllm/utils/flashinfer.py#L116-L116)
  * `flashinfer_trtllm_fp8_per_tensor_scale_moe`: For per-tensor FP8 [vllm/utils/flashinfer.py119](https://github.com/vllm-project/vllm/blob/185cada3/vllm/utils/flashinfer.py#L119-L119)
  * `flashinfer_cute_dsl_fused_moe_nvfp4`: For NVFP4 via CuteDSL [vllm/utils/flashinfer.py139](https://github.com/vllm-project/vllm/blob/185cada3/vllm/utils/flashinfer.py#L139-L139)

### DeepGemm

DeepGemm is a specialized backend for DeepSeek-style MoE models. It is selected when `is_deep_gemm_supported()` is true [vllm/utils/deep_gemm.py94-99](https://github.com/vllm-project/vllm/blob/185cada3/vllm/utils/deep_gemm.py#L94-L99)

vLLM can auto-disable DeepGemm on Blackwell for specific models (like Qwen 3.5) if accuracy degradation is detected with the E8M0 scale format [vllm/utils/deep_gemm.py33-46](https://github.com/vllm-project/vllm/blob/185cada3/vllm/utils/deep_gemm.py#L33-L46)
