## Purpose and Scope

This page documents vLLM's distributed communication infrastructure, including backend selection (NCCL, XCCL, Gloo), topology detection, device communicators, and custom collective operations. This infrastructure enables tensor parallelism, pipeline parallelism, expert parallelism, and other distributed execution strategies.

For information about high-level parallelism strategies, see [Parallelism Strategies](/vllm-project/vllm/9.1-parallelism-strategies). For multi-process engine management and coordination, see [Multi-Process Engine Management](/vllm-project/vllm/9.3-multi-process-engine-management). For KV cache transfer in disaggregated serving, see [KV Cache Transfer and Disaggregated Serving](/vllm-project/vllm/9.4-kv-cache-transfer-and-disaggregated-serving).

## Communication Backend Selection

Each platform defines a specific distributed communication backend. The backend is used by PyTorch's distributed package for inter-process communication. Backends are configured via `ParallelConfig`.

### Backend Mapping by Platform

Platform| Backend| Description  
---|---|---  
CUDA| `nccl`| NVIDIA Collective Communications Library for GPU communication.  
ROCm| `nccl`| RCCL (AMD fork of NCCL) for AMD GPU communication.  
XPU| `xccl`| Intel collective communications library for XPU devices.  
CPU| `gloo`| Gloo library for CPU-based distributed communication.

## Shared Memory Broadcast Infrastructure

vLLM implements a custom shared memory (SHM) broadcast mechanism to communicate data between processes on the same node without NCCL, often used for distributing engine commands or small metadata.

### SpinCondition and ZMQ Notification

To minimize latency while avoiding 100% CPU utilization, vLLM uses a `SpinCondition` [vllm/distributed/device_communicators/shm_broadcast.py112-127](https://github.com/vllm-project/vllm/blob/185cada3/vllm/distributed/device_communicators/shm_broadcast.py#L112-L127)

  * **Busy-looping** : Readers spin on the shared memory flag for a configurable `busy_loop_s` period [vllm/distributed/device_communicators/shm_broadcast.py142-143](https://github.com/vllm-project/vllm/blob/185cada3/vllm/distributed/device_communicators/shm_broadcast.py#L142-L143)
  * **ZMQ Wakeup** : If no data arrives, the reader enters "idle mode" and waits on a ZeroMQ socket for a notification from the writer [vllm/distributed/device_communicators/shm_broadcast.py121-123](https://github.com/vllm-project/vllm/blob/185cada3/vllm/distributed/device_communicators/shm_broadcast.py#L121-L123)

## Distributed Fusions (torch.compile)

vLLM applies compiler passes to fuse collective operations with computation kernels to reduce synchronization overhead and memory traffic.

### AllReduce + RMSNorm Fusion

Fuses `all_reduce` with subsequent `RMSNorm` and optional residual addition.

  * **Backends** : Utilizes `FlashInfer` fused kernels (`call_trtllm_fused_allreduce_norm`) or ROCm Aiter kernels [vllm/compilation/passes/fusion/allreduce_rms_fusion.py188-203](https://github.com/vllm-project/vllm/blob/185cada3/vllm/compilation/passes/fusion/allreduce_rms_fusion.py#L188-L203)
  * **Heuristics** : Selection between one-shot and two-shot all-reduce is based on tensor size and device capability [vllm/compilation/passes/fusion/allreduce_rms_fusion.py158-177](https://github.com/vllm-project/vllm/blob/185cada3/vllm/compilation/passes/fusion/allreduce_rms_fusion.py#L158-L177)
  * **Quantization Support** : Supports fusing all-reduce with quantization to FP8 or NVFP4 [vllm/compilation/passes/fusion/allreduce_rms_fusion.py213-214](https://github.com/vllm-project/vllm/blob/185cada3/vllm/compilation/passes/fusion/allreduce_rms_fusion.py#L213-L214)

## Distributed Utilities

### StatelessProcessGroup

A lightweight wrapper used to communicate metadata between processes without creating a full NCCL/Gloo process group. It uses a `Store` (typically `TCPStore`) to exchange pickled objects via `send_obj` and `recv_obj` [vllm/distributed/utils.py167-202](https://github.com/vllm-project/vllm/blob/185cada3/vllm/distributed/utils.py#L167-L202)

### ForwardContext and DPMetadata

The `ForwardContext` object carries distributed metadata through the model's forward pass [vllm/forward_context.py129-142](https://github.com/vllm-project/vllm/blob/185cada3/vllm/forward_context.py#L129-L142)

  * **`DPMetadata`** : Tracks token counts across Data Parallel (DP) ranks [vllm/forward_context.py73-74](https://github.com/vllm-project/vllm/blob/185cada3/vllm/forward_context.py#L73-L74)
  * **`BatchDescriptor`** : Used for CUDA Graph dispatching, uniquely describing the padded batch [vllm/forward_context.py30-35](https://github.com/vllm-project/vllm/blob/185cada3/vllm/forward_context.py#L30-L35)
