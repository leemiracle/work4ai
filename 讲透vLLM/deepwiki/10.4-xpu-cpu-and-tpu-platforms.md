This document describes the Intel XPU, CPU, and TPU platform implementations in vLLM. These platforms extend vLLM's hardware support beyond NVIDIA CUDA and AMD ROCm GPUs, enabling inference on alternative hardware through a unified platform abstraction layer.

For information about the platform abstraction interface and detection mechanism, see [Platform Abstraction Layer](/vllm-project/vllm/10.1-platform-abstraction-layer). For GPU platforms (CUDA and ROCm), see [CUDA Platform](/vllm-project/vllm/10.2-cuda-platform) and [ROCm Platform](/vllm-project/vllm/10.3-rocm-platform).

## Overview

vLLM supports three additional hardware platforms through dedicated platform implementations:

  * **XPU Platform** : Intel Data Center GPUs (e.g., Max Series) and Arc GPUs, using Intel's oneAPI stack and Intel Extension for PyTorch.
  * **CPU Platform** : General-purpose CPUs (x86, ARM, PowerPC, S390X, RISC-V) with NUMA topology awareness and architecture-specific optimizations.
  * **TPU Platform** : Google TPUs via an external `tpu_inference` package.

Each platform inherits from the `Platform` base class [vllm/platforms/interface.py134-135](https://github.com/vllm-project/vllm/blob/185cada3/vllm/platforms/interface.py#L134-L135) and overrides methods to provide hardware-specific behavior for device management, attention backend selection, memory management, and distributed communication.

## XPU Platform (Intel GPUs)

The `XPUPlatform` provides support for Intel Data Center GPUs and Arc GPUs. It utilizes the Intel oneAPI Base Toolkit and Level Zero drivers.

### XPU Architecture and Initialization

The XPU implementation relies on `vllm_xpu_kernels` [vllm/platforms/xpu.py11-13](https://github.com/vllm-project/vllm/blob/185cada3/vllm/platforms/xpu.py#L11-L13) and Intel's oneCCL (via `xccl`) for distributed communication [vllm/platforms/xpu.py111](https://github.com/vllm-project/vllm/blob/185cada3/vllm/platforms/xpu.py#L111-L111) In the V1 engine, `XPUWorker` manages the device initialization and distributed environment setup.

### XPU-Specific Features and Capabilities

  * **Kernel Infrastructure** : Imports `vllm_xpu_kernels` for core, MoE, and XPU-specific operations [vllm/platforms/xpu.py11-13](https://github.com/vllm-project/vllm/blob/185cada3/vllm/platforms/xpu.py#L11-L13)
  * **Distributed Backend** : Uses `xccl` for multi-GPU communication [vllm/platforms/xpu.py111](https://github.com/vllm-project/vllm/blob/185cada3/vllm/platforms/xpu.py#L111-L111)
  * **CUDA API Shimming** : The `_torch_cuda_wrapper` context manager in `XPUModelRunner` dynamically replaces `torch.cuda` attributes with `torch.xpu` equivalents [vllm/v1/worker/xpu_model_runner.py17-18](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/xpu_model_runner.py#L17-L18)
  * **Attention Backends** : Supports `FLASH_ATTN`, `TRITON_ATTN`, `XPU_MLA_SPARSE`, and `TURBOQUANT` [vllm/platforms/xpu.py142-205](https://github.com/vllm-project/vllm/blob/185cada3/vllm/platforms/xpu.py#L142-L205)
  * **Memory Management** : Implements `get_mem_info_wrapper` to provide memory stats compatible with `torch.accelerator.get_memory_info` by calling `torch.ops._C_cache_ops.getMemoryInfo` [vllm/platforms/xpu.py31-97](https://github.com/vllm-project/vllm/blob/185cada3/vllm/platforms/xpu.py#L31-L97)
  * **Quantization Support** : Extensive support for quantization formats including `awq`, `gptq`, `fp8`, `mxfp4`, and `compressed-tensors` [vllm/platforms/xpu.py113-129](https://github.com/vllm-project/vllm/blob/185cada3/vllm/platforms/xpu.py#L113-L129)

### Memory and Thread Management

  * **NUMA Awareness** : `CPUWorker` performs NUMA node binding during initialization. It queries visible memory nodes via `get_visible_memory_node` and initializes the CPU memory environment using `torch.ops._C.init_cpu_memory_env` [vllm/v1/worker/cpu_worker.py45-71](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/worker/cpu_worker.py#L45-L71)
  * **OpenMP Integration** : The build system locates PyTorch's `libgomp` and creates a shim directory to ensure the same OpenMP runtime is used [cmake/cpu_extension.cmake39-58](https://github.com/vllm-project/vllm/blob/185cada3/cmake/cpu_extension.cmake#L39-L58)
  * **Shared Memory** : Includes a `shm_manager` for CPU-based collectives like `shm_allreduce` and `shm_all_gather` [csrc/cpu/torch_bindings.cpp39-58](https://github.com/vllm-project/vllm/blob/185cada3/csrc/cpu/torch_bindings.cpp#L39-L58)
  * **Configuration Overrides** : The CPU platform forces `disable_cascade_attn = True` and sets the default `block_size` to 128 (or 16 for reference CPU MLA) [vllm/platforms/cpu.py143-182](https://github.com/vllm-project/vllm/blob/185cada3/vllm/platforms/cpu.py#L143-L182)

## TPU Platform

The TPU implementation provides support for Google Cloud TPUs.

### TPU Platform Characteristics

  * **Detection** : vLLM attempts to import `tpu_inference.platforms` to detect a TPU environment [vllm/platforms/tpu.py9-15](https://github.com/vllm-project/vllm/blob/185cada3/vllm/platforms/tpu.py#L9-L15)
  * **Implementation** : 
    * The `TpuPlatform` is an alias for `TpuInferencePlatform` when the external package is available [vllm/platforms/tpu.py14](https://github.com/vllm-project/vllm/blob/185cada3/vllm/platforms/tpu.py#L14-L14)
    * The platform interface specifies that TPUs use host-device handling, leaving `DeviceConfig.device` unset [vllm/platforms/interface.py204-206](https://github.com/vllm-project/vllm/blob/185cada3/vllm/platforms/interface.py#L204-L206)
