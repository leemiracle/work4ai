The Rust Frontend (`vllm-frontend-rs`) is an experimental, high-performance alternative to the Python-based FastAPI server. It provides an OpenAI-compatible HTTP interface while leveraging Rust's concurrency model and memory safety. It communicates with the vLLM Python engine (specifically the V1 engine) via a ZeroMQ (ZMQ) transport layer, allowing the frontend and the model execution core to run in separate processes.

## Architecture Overview

The Rust frontend is organized into a layered crate architecture, each responsible for a specific level of abstraction from low-level IPC to high-level OpenAI protocol handling.

### Crate Hierarchy

  * **`vllm-server`** : The top-level crate that implements the HTTP server (using `axum`), manages the lifecycle of the application, and provides gRPC and TLS support [rust/src/server/src/lib.rs4-16](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/server/src/lib.rs#L4-L16)
  * **`vllm-chat`** : Handles chat-specific logic, including chat templates (via `minijinja`), tool calling, and reasoning parser integration [rust/src/chat/src/lib.rs29-43](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/chat/src/lib.rs#L29-L43)
  * **`vllm-text`** : Manages text processing, tokenization, detokenization, and lowering high-level requests to model-specific sampling parameters [rust/src/text/src/lower.rs35-41](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/text/src/lower.rs#L35-L41)
  * **`vllm-llm`** : Provides a high-level abstraction for interacting with Large Language Models and managing request-id-based routing [rust/src/server/src/lib.rs135](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/server/src/lib.rs#L135-L135)
  * **`vllm-engine-core-client`** : The lowest layer crate that implements the ZMQ protocol to communicate with the Python `EngineCore` [rust/src/engine-core-client/src/client.rs33-77](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/engine-core-client/src/client.rs#L33-L77)

## Integration with Python Engine

The Rust frontend can be launched as a standalone server connecting to an external engine or as a managed process. It communicates with Python `EngineCore` instances that perform the actual model inference.

### Transport and Handshake

The frontend and backend synchronize using a handshake protocol over ZMQ. The `TransportMode` determines how addresses are allocated.

  * **`HandshakeOwner`** : The Rust process owns the startup handshake, binding to a handshake address and waiting for engines to dial in [rust/src/engine-core-client/src/client.rs40-54](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/engine-core-client/src/client.rs#L40-L54)
  * **`Bootstrapped`** : The Python supervisor chooses addresses, and Rust binds to them [rust/src/engine-core-client/src/client.rs59-76](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/engine-core-client/src/client.rs#L59-L76)
  * **ZeroMQ Socket types** : The client uses `DealerSocket` for sending requests and `PushSocket` for certain utility signals [rust/src/server/src/routes/tests.rs51-52](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/server/src/routes/tests.rs#L51-L52)

### ZeroMQ Transport Protocol

## Key Components and Functions

### Request Lowering and Validation

Before a request is sent to the engine, it must be "lowered" from the high-level API representation to the engine's internal protocol.

  * **`lower_text_request`** : Converts a high-level `TextRequest` into a lower-level `GenerateRequest` ready for the model execution layer [rust/src/text/src/lower.rs35-73](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/text/src/lower.rs#L35-L73)
  * **`lower_sampling_params`** : Enriches user-provided sampling parameters with model/tokenizer defaults (e.g., EOS token IDs, temperature) [rust/src/text/src/lower.rs77-196](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/text/src/lower.rs#L77-L196)
  * **`prepare_chat_request`** : Performs lowering for Chat requests, handling message rendering and tool call parsing [rust/src/server/src/routes/openai/chat_completions.rs49-55](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/server/src/routes/openai/chat_completions.rs#L49-L55)

### Request Lifecycle in Rust Frontend

  1. **Ingress** : An HTTP request hits the `axum` router, specifically the `chat_completions` handler [rust/src/server/src/routes/openai/chat_completions.rs59-63](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/server/src/routes/openai/chat_completions.rs#L59-L63)
  2. **State Management** : `AppState` tracks server configuration and provides access to the `ChatLlm` facade [rust/src/server/src/lib.rs142-150](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/server/src/lib.rs#L142-L150)
  3. **Preparation** : `prepare_chat_request` validates the body and resolves the model (including LoRA adapters) [rust/src/server/src/routes/openai/chat_completions.rs68-71](https://github.com/vllm-project/vllm/blob/185cada3/rust/src/server/src/routes/openai/chat_completions.rs#L68-L71)
