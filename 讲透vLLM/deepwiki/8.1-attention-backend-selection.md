## Purpose and Scope

This document explains vLLM's attention backend selection system, which determines the specific kernel implementation used to execute attention operations during model inference. The system dynamically chooses backends based on hardware platform, device compute capabilities, model configuration (such as head size and Multi-Latent Attention usage), and user-specified environment variables or CLI overrides.

For information about specific implementations, see [8.2 FlashAttention and FlashInfer](https://github.com/vllm-project/vllm/blob/185cada3/8.2 FlashAttention and FlashInfer) [8.3 MLA and Specialized Attention](https://github.com/vllm-project/vllm/blob/185cada3/8.3 MLA and Specialized Attention) and [8.4 ROCm and Platform-Specific Attention](https://github.com/vllm-project/vllm/blob/185cada3/8.4 ROCm and Platform-Specific Attention)

## Overview

The attention backend selection system is designed to be platform-agnostic at the engine level while allowing specialized optimizations for different hardware. The core logic evaluates a priority-ordered list of backends against the current configuration until a compatible one is found.

## Backend Selection Behavior

vLLM supports both manual and automatic backend selection via the `AttentionConfig` object.

### Manual Selection

Users can specify a backend using the `--attention-backend` CLI flag or via `AttentionConfig` in the Python API [docs/design/attention_backends.md14-40](https://github.com/vllm-project/vllm/blob/185cada3/docs/design/attention_backends.md?plain=1#L14-L40) When manually selected, vLLM validates the backend against the hardware and model using `AttentionBackend.validate_configuration()`. If the selected backend does not support the configuration (e.g., `FLASHMLA` on unsupported compute capability), a `ValueError` is raised [docs/design/attention_backends.md65-80](https://github.com/vllm-project/vllm/blob/185cada3/docs/design/attention_backends.md?plain=1#L65-L80)

### Automatic Selection

When no backend is specified, vLLM iterates through backends in priority order for the detected platform [docs/design/attention_backends.md82-91](https://github.com/vllm-project/vllm/blob/185cada3/docs/design/attention_backends.md?plain=1#L82-L91)

**CUDA Priorities (Standard Attention):**

  * **Blackwell (SM 10.x)** : `FLASHINFER` -> `FLASH_ATTN` -> `TRITON_ATTN` -> `FLEX_ATTENTION` -> `TURBOQUANT` [docs/design/attention_backends.md101-110](https://github.com/vllm-project/vllm/blob/185cada3/docs/design/attention_backends.md?plain=1#L101-L110)
  * **Ampere/Hopper (SM 8.x-9.x)** : `FLASH_ATTN` -> `FLASHINFER` -> `TRITON_ATTN` -> `FLEX_ATTENTION` -> `TURBOQUANT` [docs/design/attention_backends.md111-120](https://github.com/vllm-project/vllm/blob/185cada3/docs/design/attention_backends.md?plain=1#L111-L120)

**ROCm Priorities:** On ROCm platforms, the selector typically defaults to `ROCM_ATTN` for standard attention [tests/kernels/attention/test_attention_selector.py136-137](https://github.com/vllm-project/vllm/blob/185cada3/tests/kernels/attention/test_attention_selector.py#L136-L137) However, if AITER is enabled via `VLLM_ROCM_USE_AITER=1`, specialized backends like `ROCM_AITER_UNIFIED_ATTN` may be used [vllm/v1/attention/backends/rocm_aiter_unified_attn.py74-75](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_aiter_unified_attn.py#L74-L75)

**Backend Per Kind Overrides:** Users can override the backend for specific KV-cache group kinds (e.g., `mla_attention`, `sliding_window`) using `AttentionConfig.backend_per_kind` [vllm/config/attention.py30-39](https://github.com/vllm-project/vllm/blob/185cada3/vllm/config/attention.py#L30-L39)

## Multi-Latent Attention (MLA) Selection

MLA (used in DeepSeek models) requires specialized backends due to its compressed KV cache structure.

### MLA Prefill Selection

For prefill, vLLM uses a dedicated selector logic. It prioritizes backends based on hardware:

  * **Blackwell** : `FLASHINFER`, `TRTLLM_RAGGED`, `FLASH_ATTN` [docs/design/attention_backends.md154-157](https://github.com/vllm-project/vllm/blob/185cada3/docs/design/attention_backends.md?plain=1#L154-L157)
  * **Hopper** : `FLASH_ATTN`, `FLASHINFER`, `TRTLLM_RAGGED` [docs/design/attention_backends.md154-157](https://github.com/vllm-project/vllm/blob/185cada3/docs/design/attention_backends.md?plain=1#L154-L157)
  * **ROCm** : Uses `ROCM_AITER_MLA` if supported by the hardware (CDNA 3+) and library availability [vllm/_aiter_ops.py134-154](https://github.com/vllm-project/vllm/blob/185cada3/vllm/_aiter_ops.py#L134-L154) Otherwise, it falls back to `TRITON_MLA` [tests/kernels/attention/test_attention_selector.py118-120](https://github.com/vllm-project/vllm/blob/185cada3/tests/kernels/attention/test_attention_selector.py#L118-L120)

## Implementation Details and Layouts

Different backends require specific memory layouts for the KV cache. The layout is managed via `KVCacheLayout` [vllm/v1/kv_cache_interface.py35](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/kv_cache_interface.py#L35-L35)

  * **NHD Layout** : Blocks, Heads, Tokens, Dims. Commonly used by `FlashAttentionBackend` [vllm/v1/attention/backends/rocm_aiter_fa.py94-103](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_aiter_fa.py#L94-L103)
  * **Shuffle Layout** : Specialized layout for AITER kernels on ROCm [vllm/v1/attention/backends/rocm_aiter_fa.py124-140](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_aiter_fa.py#L124-L140)
  * **LBHNC / LHBNC** : Layouts where the layer dimension is outermost, supported by `RocmAiterUnifiedAttentionBackend` [vllm/v1/attention/backends/rocm_aiter_unified_attn.py93-97](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_aiter_unified_attn.py#L93-L97)

### Metadata Building

Each backend provides a `MetadataBuilder` class (e.g., `RocmAttentionMetadataBuilder`) which prepares hardware-specific tensors like `block_table` and `slot_mapping` for the kernel forward pass [vllm/v1/attention/backends/rocm_attn.py76-86](https://github.com/vllm-project/vllm/blob/185cada3/vllm/v1/attention/backends/rocm_attn.py#L76-L86)

### AITER Integration on ROCm

For AMD hardware, vLLM integrates with the AITER library. The selection logic checks `is_aiter_found_and_supported()` to verify the environment and hardware (CDNA 3 or RDNA 4) before attempting to use AITER-based attention backends [vllm/_aiter_ops.py134-170](https://github.com/vllm-project/vllm/blob/185cada3/vllm/_aiter_ops.py#L134-L170)
