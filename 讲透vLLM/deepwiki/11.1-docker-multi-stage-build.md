## Purpose and Scope

This document describes vLLM's multi-stage Docker build architecture as defined in [docker/Dockerfile1-823](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L1-L823) The build system uses Docker multi-stage builds to:

  1. Compile C++/CUDA kernels and extensions in parallel.
  2. Minimize final image size by separating build-time and runtime dependencies.
  3. Enable layer caching for frequently-unchanged dependencies (PyTorch, FlashInfer).
  4. Support precompiled wheel distribution for faster CI builds.

The build process produces multiple image targets:

  * **base** : Build environment with Python, CUDA toolkit, and PyTorch [docker/Dockerfile94-188](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L94-L188)
  * **rust-build** : Builds the `vllm-rs` Rust frontend binary and PyO3 extensions [docker/Dockerfile442-485](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L442-L485)
  * **csrc-build** : Compiles vLLM's core C++/CUDA kernels from the `csrc/` directory [docker/Dockerfile191-308](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L191-L308)
  * **extensions-build** : Compiles third-party extensions (DeepGEMM, EP kernels) in parallel [docker/Dockerfile313-354](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L313-L354)
  * **build** : Assembles the final Python wheel from compiled components [docker/Dockerfile357-439](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L357-L439)
  * **vllm-base** : Minimal runtime image with JIT compilation support [docker/Dockerfile488-695](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L488-L695)
  * **vllm-openai** : Production API server image [docker/Dockerfile820-822](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L820-L822)

For Python package metadata and wheel generation, see [setup.py1-210](https://github.com/vllm-project/vllm/blob/185cada3/setup.py#L1-L210)

Sources: [docker/Dockerfile1-823](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L1-L823) [setup.py1-210](https://github.com/vllm-project/vllm/blob/185cada3/setup.py#L1-L210)

## Build Stage Overview

The Dockerfile defines multiple build stages with specific roles. The following diagram shows the stage dependencies and data flow:

**Diagram: Docker Build Stage Dependencies**

**Stage Purposes:**

Stage| Base Image| Primary Output| Lines  
---|---|---|---  
`base`| pytorch/manylinux2_28-builder:cuda13.0| Build environment with PyTorch| [docker/Dockerfile94-188](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L94-L188)  
`rust-build`| base| Pre-built `vllm-rs` binary| [docker/Dockerfile442-485](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L442-L485)  
`csrc-build`| base| vLLM C++/CUDA wheel (dist/*.whl)| [docker/Dockerfile191-308](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L191-L308)  
`extensions-build`| base| DeepGEMM + EP kernel wheels| [docker/Dockerfile313-354](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L313-L354)  
`build`| base| Final vLLM wheel with all binaries| [docker/Dockerfile357-439](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L357-L439)  
`vllm-base`| nvidia/cuda:13.0.3-base-ubuntu24.04| Runtime image with vLLM installed| [docker/Dockerfile488-695](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L488-L695)  
`vllm-openai`| vllm-openai-base| Production API server| [docker/Dockerfile820-822](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L820-L822)  
  
**Key Design Decisions:**

  1. **Parallel Compilation** : `csrc-build`, `extensions-build`, and `rust-build` execute independently, significantly reducing total build time.
  2. **Build vs Runtime Base Images** : Build uses a manylinux builder image for glibc compatibility [docker/Dockerfile41](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L41-L41) while runtime uses a minimal `-base` image [docker/Dockerfile43](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L43-L43)
  3. **Wheel-Based Assembly** : The `build` stage extracts precompiled `.so` files from wheels generated in earlier stages rather than copying raw build directories [docker/Dockerfile416-421](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L416-L421)
  4. **JIT-Capable Runtime** : `vllm-base` includes `cuda-nvcc` and `cuda-nvrtc` to support runtime kernel generation for FlashInfer and DeepGEMM [docker/Dockerfile545-557](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L545-L557)

## rust-build Stage (Lines 442-485)

This stage builds the `vllm-rs` Rust frontend binary. It runs in parallel with other build stages to optimize overall build time.

**Diagram: rust-build Stage Pipeline**

**Key Steps:**

  * **Dependencies** : Installs `protoc` for gRPC code generation and `rustup` for Rust toolchain management [docker/Dockerfile448-459](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L448-L459)
  * **Rust Toolchain** : The specific Rust toolchain version is pinned by `rust-toolchain.toml`.
  * **Parallelism** : `CARGO_BUILD_JOBS=4` is set to limit concurrent compilation jobs, preventing resource exhaustion in CI environments [docker/Dockerfile478](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L478-L478)
  * **Caching** : Uses Docker cache mounts for Cargo registry and Git dependencies to speed up subsequent builds [docker/Dockerfile481-483](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L481-L483)
  * **Output** : The compiled `vllm-rs` binary is placed at `/workspace/vllm-rs` [docker/Dockerfile484](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L484-L484) which is then copied into the `build` stage.
  * **PyO3 Integration** : `setup.py` detects precompiled `_rust_*.so` files and skips local Rust builds if they are present [setup.py52-78](https://github.com/vllm-project/vllm/blob/185cada3/setup.py#L52-L78)

Sources: [docker/Dockerfile442-485](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L442-L485) [docker/Dockerfile.rocm155-188](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile.rocm#L155-L188) [setup.py52-78](https://github.com/vllm-project/vllm/blob/185cada3/setup.py#L52-L78)

## csrc-build Stage (Lines 191-308)

This stage compiles the core vLLM C++ and CUDA extensions. It supports both local `ccache` and distributed `sccache` for compilation speed.

**Diagram: csrc-build Compilation Pipeline**

**Compilation Caching:**

  1. **sccache** ([docker/Dockerfile265-291](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L265-L291)): Distributed S3-backed cache for CI/CD. Configuration includes `SCCACHE_BUCKET` and `SCCACHE_REGION`.
  2. **ccache** ([docker/Dockerfile296-306](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L296-L306)): Local disk cache using Docker cache mounts. Automatically used if `sccache` is not enabled.

The stage produces a binary-only wheel with a dummy version `0.0.0+csrc.build` [docker/Dockerfile255](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L255-L255) This wheel is later used to extract `.so` files into the final package. The build uses `ninja` as the backend for `setup.py`'s `cmake_build_ext` [setup.py116-210](https://github.com/vllm-project/vllm/blob/185cada3/setup.py#L116-L210)

## build Stage (Lines 357-439)

The `build` stage assembles the final vLLM wheel by merging the Python source with the precompiled binaries from `csrc-build` and the Rust frontend from `rust-build`.

**Diagram: build Stage Assembly Process**

The build process uses `VLLM_PRECOMPILED_WHEEL_LOCATION` [docker/Dockerfile418-420](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L418-L420) to signal `setup.py` to extract `.so` files from the binary wheel instead of triggering a full CMake build. ## vllm-base Stage (Lines 488-695)

The `vllm-base` stage creates the final runtime environment. It installs vLLM and its extensions into a clean image based on `nvidia/cuda:base`.

**Key Components:**

  1. **CUDA Dev Tools** : Includes `cuda-nvcc` and `cuda-nvrtc` to support JIT compilation for FlashInfer and DeepGEMM at runtime [docker/Dockerfile545-557](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L545-L557)
  2. **FlashInfer** : Installs `flashinfer-python` and `flashinfer-cubin` [docker/Dockerfile589-594](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L589-L594)

  4. **vLLM Wheel** : Installs the final wheel generated in the `build` stage [docker/Dockerfile648-661](https://github.com/vllm-project/vllm/blob/185cada3/docker/Dockerfile#L648-L661)
