This document describes the architecture of the `FusedMoE` layer, which implements Mixture-of-Experts (MoE) functionality in vLLM. It covers the core layer structure, modular kernel interfaces, expert execution, and the configuration system.

## Purpose and Scope

The `FusedMoE` layer is vLLM's implementation of sparse Mixture-of-Experts neural network layers. It combines multiple expert networks with routing logic, supporting various quantization schemes, parallelization strategies, and hardware backends. The layer handles:

  * Expert weight creation and management.
  * Token routing to experts via top-K selection.
  * Expert parallelism (EP) with multiple distribution strategies.
  * Modular kernel execution for different hardware backends (Triton, CUTLASS, DeepGemm, FlashInfer, AITER).
  * Integration with tensor parallel (TP) and data parallel (DP) execution.

## Core FusedMoE Class

The `FusedMoEFactory` function is the central entry point, orchestrating the creation of a complete MoE execution pipeline including a Router, `RoutedExperts` (holding weights), and a `MoERunner`. [vllm/model_executor/layers/fused_moe/layer.py88-138](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/layer.py#L88-L138) It handles both MergedColumnParallel weights (gate_up_proj/w13) and RowParallelLinear weights (down_proj/w2). [vllm/model_executor/layers/fused_moe/layer.py146-148](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/layer.py#L146-L148)

### Key Initialization Parameters

The `FusedMoEFactory` accepts parameters that control layer behavior, including global expert counts and specialized routing functions. [vllm/model_executor/layers/fused_moe/layer.py89-137](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/layer.py#L89-L137)

Parameter| Type| Purpose  
---|---|---  
`num_experts`| `int`| Global number of experts across all ranks  
`top_k`| `int`| Number of experts selected per token  
`hidden_size`| `int`| Input/output dimension  
`intermediate_size`| `int`| Expert MLP intermediate dimension  
`quant_config`| `QuantizationConfig`| Quantization scheme configuration  
`tp_size`, `dp_size`, `pcp_size`| `int`| Parallelism dimensions  
`renormalize`| `bool`| Whether to renormalize logits in the router  
`scoring_func`| `str`| Routing scoring function (e.g., "softmax", "sigmoid", "sqrtsoftplus")

## Modular Kernel Architecture

vLLM utilizes a modular kernel design to decouple communication (dispatch/combine) from computation (expert GEMMs). This allows utilizing different communication mechanisms with any fused MoE kernel without combinatoric implementations. [vllm/model_executor/layers/fused_moe/modular_kernel.py48-59](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/modular_kernel.py#L48-L59)

**Modular Components Diagram**

### Modular Kernel Interfaces

The architecture relies on several abstract base classes defined in `modular_kernel.py`:

  1. **`FusedMoEPrepareAndFinalize`** : Handles quantization of inputs and distribution of tokens to experts. Bundled together because collective communication mechanisms must be consistent between dispatch and combine. [vllm/model_executor/layers/fused_moe/modular_kernel.py182-190](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/modular_kernel.py#L182-L190)
     * `prepare()`: Dispatches tokens to local experts, returning quantized/dispatched tensors and metadata. [vllm/model_executor/layers/fused_moe/modular_kernel.py216-224](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/modular_kernel.py#L216-L224)
     * `finalize()`: Combines expert outputs back to the original token order, potentially performing reductions. [vllm/model_executor/layers/fused_moe/modular_kernel.py231-240](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/modular_kernel.py#L231-L240)
  2. **`FusedMoEExperts`** : Implements the core expert computation (MatMul + Activation). [vllm/model_executor/layers/fused_moe/modular_kernel.py67-74](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/modular_kernel.py#L67-L74)
  3. **`TopKWeightAndReduce`** : Applies routing weights to expert outputs and performs the final reduction. [vllm/model_executor/layers/fused_moe/modular_kernel.py119-138](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/modular_kernel.py#L119-L138)

## Expert Execution Backends

vLLM supports multiple specialized backends for expert execution, selected based on hardware capabilities and quantization configuration via an "Oracle" pattern.

### Triton Backend

The Triton-based expert implementations support various quantization formats including GPTQ, AWQ, and FP8. [vllm/model_executor/layers/fused_moe/fused_moe.py65-112](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/fused_moe.py#L65-L112)

  * **Kernel** : `fused_moe_kernel_gptq_awq` implements the fused computation for token and expert matrices. [vllm/model_executor/layers/fused_moe/fused_moe.py65-112](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/fused_moe.py#L65-L112)
  * **Logic** : Tokens are sorted by expert ID (`expert_ids_ptr`) to ensure divisibility by `BLOCK_SIZE_M`. [vllm/model_executor/layers/fused_moe/fused_moe.py127-138](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/fused_moe.py#L127-L138)

### DeepGemm Backend

DeepGemm provides highly optimized kernels specifically for NVIDIA architectures (SM90/SM100).

  * **Support** : Enabled via `is_deep_gemm_supported`. [vllm/model_executor/layers/quantization/fp8.py80-82](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/quantization/fp8.py#L80-L82)
  * **Integration** : `DeepGemmFP4Experts` supports MXFP4 formats on SM100+. [vllm/model_executor/layers/fused_moe/oracle/mxfp4.py163-167](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/oracle/mxfp4.py#L163-L167)

### CUTLASS Backend

vLLM supports both native CUTLASS and FlashInfer-wrapped CUTLASS backends.

  * **VLLM CUTLASS** : Leverages CUTLASS for grouped GEMM operations. [vllm/model_executor/layers/quantization/fp8.py53-54](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/quantization/fp8.py#L53-L54)
  * **FlashInfer CUTLASS** : Supported via `FlashInferExperts` for FP8 and MXFP4. [vllm/model_executor/layers/fused_moe/oracle/fp8.py147-152](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/oracle/fp8.py#L147-L152) [vllm/model_executor/layers/fused_moe/oracle/mxfp4.py181-189](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/oracle/mxfp4.py#L181-L189)

### FlashInfer Backend

FlashInfer provides highly optimized kernels for MoE, including support for various quantization schemes like FP8, MXFP4, and NVFP4.

  * **FP8** : Supports TRTLLM-style kernels via `TrtLlmFp8ExpertsModular`. [vllm/model_executor/layers/fused_moe/oracle/fp8.py139-145](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/oracle/fp8.py#L139-L145)
  * **MXFP4** : Support includes `TrtLlmMxfp4ExpertsMonolithic` and `TrtLlmMxfp4ExpertsModular`. [vllm/model_executor/layers/fused_moe/oracle/mxfp4.py173-179](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/oracle/mxfp4.py#L173-L179)
  * **NVFP4** : Supported through backends like `TrtLlmNvfp4ExpertsModular`. [vllm/model_executor/layers/fused_moe/oracle/nvfp4.py153-157](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/oracle/nvfp4.py#L153-L157)

### ROCm AITER Backend

On AMD hardware, vLLM uses the AITER backend for MoE.

  * **Ops** : Uses `rocm_aiter_ops` for fused operations. [vllm/model_executor/layers/fused_moe/layer.py9](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/layer.py#L9-L9)
  * **Expert Class** : `AiterExperts` handles FP8/MXFP8/MXFP4 on ROCm platforms. [vllm/model_executor/layers/fused_moe/oracle/fp8.py202-207](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/oracle/fp8.py#L202-L207) [vllm/model_executor/layers/fused_moe/oracle/mxfp4.py118-123](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/oracle/mxfp4.py#L118-L123)

## Expert Distribution and Parallelism

### Parallelism Configuration

The `FusedMoEParallelConfig` manages dimensions for Tensor Parallelism (TP), Data Parallelism (DP), and Expert Parallelism (EP). [vllm/model_executor/layers/fused_moe/config.py57-63](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/config.py#L57-L63)

  * **Sequence Parallel** : Supports sequence parallelism (SP) where `sp_size` is derived from `tp_size`. [vllm/model_executor/layers/fused_moe/layer.py50-55](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/layer.py#L50-L55)

### Communication (All-to-All)

Modular kernels use `FusedMoEPrepareAndFinalize` implementations to handle All-to-All communication for EP. [vllm/model_executor/layers/fused_moe/modular_kernel.py182-190](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/modular_kernel.py#L182-L190)

  * **NVLink Backends** : Backends like `FLASHINFER_TRTLLM` provide specialized communication for EP via NVLink. [vllm/model_executor/layers/fused_moe/oracle/fp8.py44-45](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/oracle/fp8.py#L44-L45)

## Oracle and Sub-modules

The "Oracle" logic selects the best kernel at runtime based on the quantization method and platform.

  * **`oracle/fp8.py`** : `select_fp8_moe_backend` chooses backends (DEEPGEMM, TRITON, etc.) based on platform and `QuantKey`. [vllm/model_executor/layers/fused_moe/oracle/fp8.py32-36](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/oracle/fp8.py#L32-L36)
  * **`oracle/mxfp4.py`** : Handles selection for MXFP4 backends, including `select_mxfp4_moe_backend`. [vllm/model_executor/layers/fused_moe/oracle/mxfp4.py30-31](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/oracle/mxfp4.py#L30-L31)
  * **`oracle/nvfp4.py`** : Handles selection for NVFP4 backends, including `select_nvfp4_moe_backend`. [vllm/model_executor/layers/fused_moe/oracle/nvfp4.py42-43](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/oracle/nvfp4.py#L42-L43)
  * **`runner/shared_experts.py`** : Manages `SharedExperts`, which are MoE experts shared across all tokens (e.g., DeepSeek-V3). [vllm/model_executor/layers/fused_moe/modular_kernel.py26-29](https://github.com/vllm-project/vllm/blob/185cada3/vllm/model_executor/layers/fused_moe/modular_kernel.py#L26-L29)

## Router Implementation

  * **Algorithms** : Includes `DeepSeekV3` (Sigmoid + RoutingBiasAdd), `Llama4` (Top1 + Sigmoid), and `DeepseekV4` (sqrtsoftplus + Bias + Normalize).
