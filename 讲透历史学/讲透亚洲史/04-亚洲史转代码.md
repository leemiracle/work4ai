## 二、逐条速写

**走廊 1（王朝政体统计）**：把"中国王朝三百年周期律""日本万世一系"
这类教科书断语变成数据断言——**为什么值得**：这类命题人人会用却很少
被检验，一旦落成数据立即显出它其实是中国史的特殊律而非亚洲通则
（奥斯曼 623 年、朝鲜王朝 505 年远超"天花板"）。断言内嵌、脚本自验，
是历史假设的"单元测试"。

单元测试与史学论证的关系：断言通过≠命题成立——它只证明"在这个
样本与口径下成立"。所以每个断言旁都要写**威胁清单**：样本范围
（只列大一统王朝，分裂时期被排除）、口径选择（两宋合并计，西晋
短暂统一也计入）、幸存偏差（短命王朝文献少、易被漏列）。测试通过
后再读威胁清单，才是完整的史学习题。

**走廊 2（历法换算引擎）**：希吉来历 h→公历 g ≈ g = 0.970224×h + 621.57
（线性近似，斋月首日等精确问题需天文算法）；干支= (year-4) mod 60 的
模运算；日本年号在位表是一张小维表。**工程启示**：历法换算是纯粹的
确定性算法，但**语义**不是——"宽永三年"和"1626 年"不是同一个文化
事实，换算结果永远要双轨显示（原历法+公历），这是史学对工程的反向
约束。最小可跑样例（干支环）：

```python
GAN = "甲乙丙丁戊己庚辛壬癸"; ZHI = "子丑寅卯辰巳午未申酉戌亥"
def ganzhi(year):                       # 公历年 → 干支（农历年首 caveat）
    i = (year - 4) % 60
    return GAN[i % 10] + ZHI[i % 12]    # 1911→辛亥，1898→戊戌
```

这段五行代码是走廊 2 的"Hello, World"——它同时演示了算法的确定性
（mod 运算）与史学的陷阱（公历 1 月常属上一个农历年，断代要跨年
处理）。

**走廊 3（贸易网络重建）**：以沉船（黑石号、泉州湾宋船）、窑系分布、
港口遗址为节点建图，网络密度随世纪的升降即"海洋亚洲"兴衰曲线；
方法同 [讲透图](../../讲透数学/讲透图/)。**注意**：节点存在概率≠贸易
量——考古发现率受打捞努力偏差影响（幸者偏差的考古版）。

## 三、可机械化边界（裂缝清单）

- 可全自动：历法换算、世系树构建、王朝区间查询、瓷窑分布制图
- 半自动：碑铭 OCR+断代（多文字模型可用，尊号识别需专家复核）、
  王朝边界判定（颗粒度声明必须人工）
- 不可机械化：多语史料的义训（同一尊号在不同语文中的政治含义）、
  口传谱系分层、殖民档案反读——**AI 翻译史料不产生考据，只产生候选**

**工程师落点**：多历法日历库、古籍 OCR 管线、世系 DAG 数据库是真实
且未被充分解决的基础设施需求；东亚纪年数据（年号-干支-公元三元组）
是小而精的优质数据工程项目。

## ✨ 美之时刻：一行数据拆穿一句格言

"王朝不过三百年"——`max(lifespans) == 319 < 320` 成立，但把奥斯曼
加进同一张表（623 年），格言立刻从"历史规律"降级为"中国史的规律"。
为什么美：**意外**——同一组数据先证实再否定同一句格言，范围（scope）
的概念无需说教就教完了。怎么亲历：给实验加拜占庭（330/395-1453），
看它落在线轴哪里——你对"帝国寿命"的直觉会再校准一次。
