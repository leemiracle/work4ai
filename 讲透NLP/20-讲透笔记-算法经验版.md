## §0 全局视角：IE/SRL = "非结构化文本 → 结构化知识"的桥梁

信息抽取（IE）把文本变成三元组 `(实体, 关系, 实体)`，语义角色标注（SRL）把句子变成 `(谓词, 论元角色)` 框架。**两者都是从自由文本生成结构化数据**——这是知识图谱、图谱问答、智能助手的基础。

> 🔑 **算法 DNA**：IE/SRL 的核心难题是**结构稀疏 + 噪声标注**——这导致它在小数据上反而不如规则方法。

## §1 五条算法经验

### 算法经验 E1：远程监督 = 自动标注 + 噪声

> 远程监督（distant supervision）：用已有知识库自动标注文本。如：知道 `(Steve Jobs, founder, Apple)`，那所有同时提到三者的句子都标为这个关系。
>
> **优点**：海量自动标注；**缺点**：标注噪声大（句子可能是否定/假设/嘲讽）。

可迁移（应用 Ch9 RLHF 的偏好数据噪声）：
- **数据增强**（DA）
- **弱监督**（weak supervision）
- **伪标签**（self-training）
- **LLM 自动标注**（RLAIF）

### 算法经验 E2：规则方法在小数据上的反直觉优势

> 实验 20 的反直觉结论：**在窄领域小数据上，几条手写规则能击败 LLM 式的统计抽取**。
>
> 算法本质：**强先验在数据稀少时是优势**（对应 Ch14 S4 手工 vs 学习）。

可迁移（应用 Ch14 S7 强假设死、Ch10 M6 成本权衡）：
- **法律/医疗 NER**：术语表 + 规则
- **金融抽取**：模板 + LLM
- **代码分析**：解析器 + ML

### 算法经验 E3：实体链接 = 实体消歧

> 实体链接（Entity Linking）：把文本里的 "Apple" 链接到知识库的"苹果公司"还是"苹果水果"？这是**词义消歧**（Ch10 BERT 4.2）的实例化。

可迁移（应用 Ch10 M3 各向异性、Ch11 RAG）：
- **搜索 query 实体链接**（Google Knowledge Graph）
- **推荐 item 链接**（推荐系统 item embedding）
- **跨文档共指**（Ch22）

### 算法经验 E4：SRL = 谓词中心的结构化

> SRL 把句子围绕**谓词**组织论元："谁对谁做了什么"。
>
> 这是一种**中心化的结构表示**——和依存句法（Ch19 围绕头部）同构。

可迁移（应用 D1、C1）：
- **事件抽取**（事件触发词 + 论元）
- **代码理解**（函数 + 参数）
- **数学证明**（定理 + 假设 + 结论）

### 算法经验 E5：LLM 时代的 IE = prompting + 工具

> 现代 IE 用 LLM prompting："从这句话抽取所有 (实体, 关系) 三元组"。
>
> 但 **批量推理成本 + 一致性控制**让传统流水线方法仍在生产环境占主导。

可迁移（应用 T10 LLM 收编、Ch11 RAG R1）：
- **代码生成**（LLM + 编译器）
- **数学证明**（LLM + lean）
- **数据库查询**（LLM + SQL）
