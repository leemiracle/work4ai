## 一、信息抽取要解决什么

**直觉**：互联网上 80% 的信息是自由文本（新闻、简历、病历、合同）。机器想"查"它们，得先把"比尔·盖茨 1975 年创立微软"变成数据库里能 SELECT 的一行：

```
(比尔·盖茨, founder_of, 微软)        ← 关系三元组
(微软, founded_in, 1975)            ← 含时间表达式
```

信息抽取（Information Extraction, IE）就是这条流水线：

```
自由文本 ──NER──► 命名实体 ──关系抽取──► 三元组 ──事件抽取──► 事件结构
                                                              │
                                            (触发词 + 论元 + 时间)
```

这条流水线的终点是**知识图谱**（Knowledge Graph）。Google 2012 年推出 Knowledge Graph，背后就是大规模 IE——把网页里的实体和关系抽出来，让你搜"比尔·盖茨"时右边直接出现卡片。

**关键区分**：

| 子任务 | 输入 | 输出 | 例子 |
|--------|------|------|------|
| NER（实体识别） | 句子 | 实体 + 类型 | `[比尔·盖茨]_人 创立 [微软]_公司` |
| 关系抽取（RE） | 含实体的句子 | 关系三元组 | `(比尔·盖茨, founder_of, 微软)` |
| 事件抽取（EE） | 句子 | 触发词 + 论元集合 | `创立(施事=盖茨, 受事=微软, 时间=1975)` |
| 时间表达式 | 句子 | 归一化时间 | `上周二 → 2026-08-04` |

> 💡 **你会发现 SRL（第六、七节）和事件抽取几乎是同一个任务**：SRL 的"谓词 + 论元"就是事件的"触发词 + 论元"。区别只是粒度——SRL 关心**任意动词**的论元结构，事件抽取只关心**预先定义的事件类型**（并购、袭击、人事变动）。这正是合并讲它们的理由。

## 二、命名实体识别：IE 的地基（回顾）

关系抽取和事件抽取都假设实体已经标好。NER 在 Ch 17（序列标注）详细讲过，这里只回顾要点：

- **序列标注**：每个 token 打一个标签，BIO 编码（`B-PER`/`I-PER`/`O`）。
- **方法演进**：规则（gazetteer 地名表）→ HMM → CRF → BiLSTM-CRF → **BERT-token-classifier**。
- **SLP3 的核心公式**（线性链 CRF）：

$$P(\mathbf{y} \mid \mathbf{x}) = \frac{1}{Z(\mathbf{x})} \exp\left(\sum_{t} \big( A_{y_{t-1},y_t} + P_{t,y_t} \big)\right)$$

其中 $P_{t,y_t}$ 是位置 $t$ 取标签 $y_t$ 的发射分（来自 BiLSTM/BERT），$A_{y_{t-1},y_t}$ 是标签转移分（CRF 层学到的，比如 `O→I-PER` 应被惩罚）。这个公式后面关系抽取、SRL 全都复用。

> 📌 **NER 是 IE 的"准入门票"**：实体都标不对，后面的关系三元组全是错的。现代系统直接用 spaCy 或 HuggingFace 的 token-classification pipeline 做 NER，再喂给下游。

## 三、关系抽取：三元组是怎么来的

给定一个已经标好实体的句子，判断**两个实体之间是什么关系**——这就是关系抽取（Relation Extraction, RE）。

### 3.1 任务定义

输入：含两个实体的句子，例如

> *比尔·盖茨于 1975 年创立了微软。*

候选实体对：`(比尔·盖茨, 微软)`。

输出：关系类型 `founder_of`（或 `founded`、`org:founders`，取决于你的本体）。

完整三元组：**(比尔·盖茨, founder_of, 微软)**。

### 3.2 方法谱系：从 Hearst 模式到 LLM

关系抽取有四条技术路线，**按对标注数据的依赖从弱到强**排：

| 路线 | 思想 | 数据需求 | 典型 |
|------|------|---------|------|
| **① 基于模板/模式** | 语言学专家写正则或依存模板 | 0 标注 | Hearst (1992) 模式、领域专家规则 |
| **② Bootstrapping** | 几个种子 → 自动扩模板 → 再扩实例 | 极少种子 | DIPRE、Snowball |
| **③ 监督分类** | 把"两实体间是何关系"当多分类 | 大量标注 | CNN/BERT 分类器 |
| **④ 远程监督** | 用已有 KB 自动造噪声标注 | 0 人工标注 | Mintz et al. (2009) |

#### 路线①：Hearst 模式（hyponymy）

最早的 IE 用**模式匹配**。Hearst (1992) 发现"上下义关系"（is-a）可以用固定模板抓：

```
NP0  such as  NP1, NP2, ...    →  (NP1, is_a, NP0) 等
NP0  including  NP1, NP2       →  (NP1, is_a, NP0)
NP1  and other  NP0            →  (NP1, is_a, NP0)
```

例：`vehicles such as cars, trucks` → `(cars, is_a, vehicles)`, `(trucks, is_a, vehicles)`。

这套模板到今天还在抓 Wikipedia 的分类树。**优点是零标注、精度极高；缺点是召回低**——不符合模板的关系全漏。

#### 路线②：Bootstrapping（DIPRE / Snowball）

模板太少怎么办？**让算法自己长模板**：

```
1. 给几个种子三元组，如 (微软, founder_of, 比尔·盖茨)
2. 在语料里搜含这对实体的句子，归纳出模板：「X founded Y」「Y was founded by X」
3. 用新模板去语料里找新三元组，如 (谷歌, founder_of, 佩奇)
4. 用新三元组再归纳模板 …… 循环
```

核心风险：**语义漂移**（semantic drift）。第 5 轮可能学到错误模板，把无关实体也吸进来，越滚越脏。Snowball 加了置信度打分来抑制漂移。

#### 路线③：监督分类（神经分类器）

把关系抽取建模成**多分类**：

- 输入：句子 + 实体对的位置（用特殊 token 或位置 embedding 标记实体边界）。
- 输出：在 $K$ 个预定义关系类 + 1 个 `no_relation` 类上的 softmax。

早期用人工特征（词序列、实体类型、依存路径、词间距）喂 CNN/SVM；2015 年后 PCNN（piecewise CNN over dependency tree）成为经典；现在直接 BERT：

```
[CLS] 比尔·盖茨 [SEP] 于1975年创立了微软 [SEP]
          ↑位置1                       ↑位置2
```

在 `[CLS]` 上接分类头。缺点：**每个关系类型都要标注几百到几千例**，标注成本极高。

#### 路线④：远程监督（distant supervision）

监督方法要标注，标注太贵。Mintz et al. (2009) 的洞察：

> 如果知识库里已有三元组 `(比尔·盖茨, founder_of, 微软)`，那么**语料里任何同时提到"盖茨"和"微软"的句子，都可能是 founder_of 的正例**。

这样自动造出海量训练数据，零人工标注。代价是**标签极噪声**（详见第九节）。远程监督 + 多实例学习 + 神经编码器，是工业级无标注关系抽取的主力。

## 四、事件抽取：比关系更复杂

关系只连两个实体。**事件**（event）是 $n$-元的：一个触发词 + 多个论元，每个论元扮演一个角色。

### 4.1 事件的结构

SLP3 用 ACE 2005 风格定义事件：

```
触发词 (trigger):   创立          ← 通常是动词/名词，标定事件类型
论元 (arguments):   盖茨 → Arg0 (施事/创立者)
                   微软 → Arg1 (受事/被创立物)
                   1975 → Time
事件类型:           Business:Start-Org
```

对比关系三元组 `(盖茨, founder_of, 微软)`——三元组丢了"1975"这个时间论元。事件结构保留了**全部 $n$ 个论元**。

### 4.2 两步流水线

标准事件抽取分两步：

1. **触发词检测**：序列标注，给每个 token 打 `B-Trigger:I-Event` / `O`，找出哪个词触发事件、什么类型。
2. **论元识别 + 角色分类**：对每个候选实体，判断它是不是该事件的论元、是哪个角色（Arg0/Time/Place/...）。

```
输入:  "盖茨 1975 年创立了微软"
Step1: 触发词 = "创立" (Business:Start-Org)
Step2: 论元 = {盖茨:Agent, 微软:Entity, 1975:Time}
```

事件抽取的难点：**论元可能跨句**（同一事件的不同论元分散在前后句），而且**一个句子可含多个事件**。

> 🔗 **和 SRL 的同构**：把"触发词检测"换成"谓词识别"，把"论元角色分类"换成"Arg0–Arg5 分类"，事件抽取 ≈ 受限本体的 SRL。第七节讲完 PropBank 你会更清楚这个同构。

## 五、时间表达式与 TIMEX3

时间表达式（temporal expression, TIMEX）是 IE 的一个古老子任务——从文本里找"上周二""2025 年""三个月前"并**归一化**成机器能算的标准时间。

### 5.1 TIMEX3 标注规范

TimeML 项目定义了 **TIMEX3** 标签，ACE 和 TempEval 都用它：

```xml
他 <TIMEX3 tid="t1" type="DATE" value="1975-04-04">1975年4月4日</TIMEX3> 创立了微软。
会议<TIMEX3 tid="t2" type="DATE" value="2026-08-04" temporalFunction="true" anchorTimeID="t0">上周二</TIMEX3>召开。
```

- `type`：`DATE`（日期）/ `TIME`（时刻）/ `DURATION`（时段）/ `SET`（重复集合）。
- `value`：归一化值，ISO 8601 格式。
- `temporalFunction="true"`：这个时间需要**相对参考时间**（document creation time, DCT）才能算出绝对值——"上周二"得知道"今天"是哪天。

### 5.2 怎么抽 + 怎么归一化

传统方法两步：

1. **识别**：CRF 序列标注，把"上周二"标成 `B-TIMEX I-TIMEX`。
2. **归一化**：规则/有限状态机。中文有 SUTime（spaCy 集成），英文有 HeidelTime。

归一化是最难的部分——"春天""下个季度""二战期间"都得映射到具体区间，常常有歧义。现代做法：把识别+归一化合并成一个 seq2seq 任务，让 BERT/T5 直接输出 TIMEX3 XML。

## 六、语义角色标注：谓词的"谁做了什么"

现在切换到 SRL。SRL（Semantic Role Labeling）回答一个比关系抽取更"语言学"的问题：

> 句子里的**谓词**（通常是动词），它的**论元**各自扮演什么**语义角色**？

### 6.1 论元结构（argument structure）

看这两句：

> (a) *盖茨* **创立** 了 *微软*。
> (b) *微软* 被 *盖茨* **创立** 了。

句法主语不同（盖茨 vs 微软），但**语义关系**一样：盖茨是"创立者"，微软是"被创立者"。SRL 要识别的就是这种**不随句法位置变化的深层语义角色**——这就是早期 Fillmore 的"格语法"（case grammar）和"题元角色"（thematic roles）思想。

### 6.2 题元角色：施事 / 受事 / 工具 / 处所 / 时间

经典题元角色（thematic roles）：

| 角色 | 含义 | 例子（**打开**） |
|------|------|-----------------|
| Agent（施事） | 有意发起动作者 | *小王* 打开了门 |
| Patient（受事） | 状态被改变者 | 小王打开了 *门* |
| Theme（客体） | 位置/状态变化、本身不变者 | 小王把 *钥匙* 递给我 |
| Instrument（工具） | 用以完成动作的工具 | 用 *钥匙* 打开门 |
| Location（处所） | 发生地点 | 在 *办公室* 打开门 |
| Time（时间） | 发生时间 | *早上八点* 打开门 |
| Source / Goal（来源 / 目标） | 起点 / 终点 | 从 *北京* 飞往 *上海* |

问题：题元角色**颗粒度难以统一**——"打开门"的门是 Patient 还是 Theme？不同语言学家吵了几十年。于是产生了**可计算的、有明确编号的** PropBank 方案。

## 七、PropBank frameset：ARG0–ARG5 + ARGM-*

### 7.1 为什么需要 PropBank

题元角色靠"语义直觉"，没法直接当标签训练。PropBank（Proposition Bank，Palmer et al. 2005）的解法：**放弃给角色起语义名，直接给每个谓词的每个论元槽编号 ARG0、ARG1、ARG2…**，编号的含义由该谓词的 frameset（框架集）定义。

这样 ARG0 在不同动词里**语义不同**，但**位置一致**，可训练：

- `found.01`（创立）：ARG0 = 创立者，ARG1 = 被创立的组织
- `buy.01`（购买）：ARG0 = 买方，ARG1 = 被买物，ARG2 = 卖方
- `give.01`（给）：ARG0 = 给者，ARG1 = 被给物，ARG2 = 接收者

> 💡 **经验法则**：ARG0 通常是"主动方/施事"，ARG1 通常是"受影响的核心对象/受事"——但**只是经验法则**，不是定义。定义永远是 frameset 说了算。

### 7.2 PropBank 标注长什么样

句子：*盖茨于 1975 年在阿尔伯克基创立了微软。*

```
[盖茨]_ARG0  于 [1975年]_ARGM-TMP  在 [阿尔伯克基]_ARGM-LOC
  创立_V  了 [微软]_ARG1。
```

输出：

| span | label | 含义 |
|------|-------|------|
| 盖茨 | ARG0 | 创立者 |
| 微软 | ARG1 | 被创立的组织 |
| 1975年 | ARGM-TMP | 修饰语：时间 |
| 阿尔伯克基 | ARGM-LOC | 修饰语：处所 |
| 创立 | V | 谓词（target） |

### 7.3 核心论元 vs 修饰语

- **核心论元 ARG0–ARG5**：谓词 frameset 必填或强相关的论元。`give.01` 最多到 ARG2（接收者）。一般不超过 ARG5。
- **修饰语 ARGM-***（adjuncts）：几乎所有动词通用的、可选的论元。前缀 `ARGM-`：

| 标签 | 含义 | 例 |
|------|------|----|
| ARGM-TMP | 时间 | *昨天* |
| ARGM-LOC | 处所 | *在北京* |
| ARGM-MNR | 方式 | *用力地* |
| ARGM-CAU | 原因 | *因为下雨* |
| ARGM-PNC | 目的 | *为了毕业* |
| ARGM-DIS | 语篇标记 | *然而* |
| ARGM-NEG | 否定 | *不 / 没* |
| ARGM-ADV | 一般副词 | *很* |
| ARGM-DIR | 方向 | *向上* |
| ARGM-EXT | 程度 | *完全* |

> ⚠️ **PropBank 是英文为主**。中文对应的是 Chinese PropBank（CPB），ARG0–ARG5 语义基本一致，但修饰语标签略有调整。FrameNet（Berkeley）是另一套更细的框架语义资源，颗粒度更细但覆盖率低。

### 7.4 SRL 的三个子任务

标准 SRL 分三步（pipeline）：

1. **谓词识别（target/predicate identification）**：找出句子里的谓词（中文可省，因为动词多；英文通常已知）。
2. **论元识别（argument identification）**：找出哪些 span 是该谓词的论元（二分类：是/不是论元）。
3. **论元分类（argument classification）**：给每个识别出的论元分 ARG0–ARG5 / ARGM-*。

```
谓词 = 创立
论元识别:  {盖茨, 微软, 1975年, 阿尔伯克基} ← 这些是论元
论元分类:  {盖茨:ARG0, 微软:ARG1, 1975年:ARGM-TMP, 阿尔伯克基:ARGM-LOC}
```

现代神经 SRL 把这三步合成一个**端到端序列标注**（下一节）。

## 八、IE/SRL 的共同数学引擎：序列标注与 CRF

无论 NER、时间抽取、论元标注，本质上都是**给 token 打序列标签**。统一的数学框架是**线性链 CRF**（linear-chain CRF）。

### 8.1 把抽取变成 BIO 标注

SRL 的论元 span 用 BIO 编码（和 NER 一样）：

```
tokens:  盖茨    于    1975年  在    阿尔伯克基  创立  了   微软
labels:  B-ARG0  O     B-ARGM-TMP  O  B-ARGM-LOC  B-V   O   B-ARG1
```

`B-V` 标谓词本身。这样 SRL 就退化成一个标准的 token classification。

### 8.2 线性链 CRF 的目标

给定输入 $\mathbf{x}=(x_1,\dots,x_n)$ 和候选标签序列 $\mathbf{y}$，CRF 建模：

$$P(\mathbf{y}\mid\mathbf{x}) = \frac{1}{Z(\mathbf{x})}\exp\left(\sum_{t=1}^{n}\Big[\,f(y_t, x_t)\;+\;g(y_{t-1}, y_t)\,\Big]\right)$$

- $f(y_t,x_t)$：**发射分**，token $x_t$ 取标签 $y_t$ 的得分——由 BiLSTM/BERT 给出。
- $g(y_{t-1},y_t)$：**转移分**，相邻标签的搭配得分——CRF 层学到（如 `O→B-ARG1` 合理、`I-ARG0→B-ARG1` 不合理应惩罚）。
- $Z(\mathbf{x}) = \sum_{\mathbf{y}'}\exp(\cdots)$：配分函数（partition function），对所有可能标签序列求和，**前向算法** $O(n\cdot K^2)$ 算出。

**训练**：最大化对数似然 $\sum_i \log P(\mathbf{y}^{(i)}\mid\mathbf{x}^{(i)})$。

**解码**：找 $\hat{\mathbf{y}}=\arg\max_{\mathbf{y}}P(\mathbf{y}\mid\mathbf{x})$，**Viterbi 算法** $O(n\cdot K^2)$。

> 💡 **为什么 CRF 比"逐 token softmax"强**：逐 token 独立分类会输出非法序列（如 `B-ARG0` 后直接跟 `B-ARG1` 而中间断了）。CRF 的转移分 $g$ 显式建模标签依赖，保证输出是合法 BIO 序列。在 NER/SRL 里，CRF 头比纯 softmax 头通常高 0.5–1 个 F1。

### 8.3 评估抽取：precision / recall / F1

抽取任务用**三元组级**（或 span 级）的 P/R/F1，不是 token 级：

$$\text{Precision} = \frac{\#\text{正确的抽取}}{\#\text{系统抽取的}},\quad \text{Recall} = \frac{\#\text{正确的抽取}}{\#\text{金标准里的}}$$

$$F_1 = \frac{2 \cdot P \cdot R}{P+R}$$

关系三元组要 `(arg1, relation, arg2)` 三者全对才算对；SRL 要 `(predicate, role, span)` 三者全对才算对。这种"严格匹配"让 F1 数字比 token 准确率低得多——这是初学者常踩的坑。

## 九、远程监督：用噪声标签换规模

回到关系抽取的"无标注"痛点。远程监督（distant supervision）是工业级 IE 的关键招式，值得单独讲清它的数学。

### 9.1 假设

已有知识库 KB（含一堆三元组）。远程监督的核心假设（Mintz 2009）：

> **如果 KB 里有 $(e_1, r, e_2)$，那么语料里任何同时提到 $e_1$ 和 $e_2$ 的句子，都表达关系 $r$。**

于是自动造训练集：

```
KB:   (盖茨, founder_of, 微软)
语料: "盖茨 1975 年创立微软"   → 标 (盖茨, 微软, founder_of)  ✓ 正例
语料: "盖茨和微软关系破裂"      → 标 (盖茨, 微软, founder_of)  ✗ 噪声！这句不是 founder_of
```

### 9.2 噪声从哪来：the wrong label problem

第二句被错标。这就是远程监督的**根本噪声**：一对实体可以同时出现在多种关系里，但都被强行标成 KB 里那条关系。形式化：

设句包（bag，含同一实体对的所有句子）为 $B=\{s_1,\dots,s_m\}$，真实关系为 $r^*$，远程监督给的标签为 $r_{KB}$。噪声率：

$$\text{noise rate} = P(r_{KB} \neq r^* \mid r_{KB}\text{ 来自远程监督})$$

文献报告这个噪声率在通用关系上可达 **30%–80%**。

### 9.3 多实例学习（MIL）抑制噪声

Riedel et al. (2010) 的解法：**在句包级打标签，不让噪声句污染训练**。句包 $B$ 的标签取"句包里至少有一句表达 $r$"这个 OR 关系：

$$P(r \mid B) = 1 - \prod_{s \in B}\big(1 - P(r \mid s)\big)$$

即"句包含关系 $r$"的概率 = 1 − "包里所有句都不表达 $r$"的概率。训练时只对句包级的 $P(r\mid B)$ 算损失，让模型自己学会**忽略包里的噪声句**（at least-one 假设）。

> 📌 **这是为什么"远程监督 + 神经编码器 + 句包级损失"成了无标注 IE 的标配**——它把"无标注"和"高质量"这对矛盾用噪声建模绕了过去。

## 十、神经 SRL：BERT + 序列标注

### 10.1 现代架构

2018 年后 SRL 主流架构极简：

```
输入 tokens
   │
BERT 编码器  ──►  每个位置一个上下文向量 h_t
   │
[谓词标记] 把谓词位置用一个特殊 marker（如 [V] 包围）注入，让模型知道"标哪个谓词的论元"
   │
Linear(h_t) + CRF / softmax  ──►  BIO label per token
```

关键设计：**单谓词一次标注**。句子有 $k$ 个谓词就跑 $k$ 次，每次只标"针对这个谓词"的论元。He et al. (2017) 的深度 SRL 和 Shi & Lin (2019) 的 BERT-SRL 都是这个范式。

### 10.2 性能基准（CoNLL-2005 / CoNLL-2012）

- 经典特征 + SVM：~77 F1
- BiLSTM（He et al. 2017）：~81 F1
- BERT-base（Shi & Lin 2019）：~84–85 F1
- RoBERTa-large + 跨任务联合训练：~86–88 F1

注意：**SRL 已经接近天花板**——因为 PropBank 标注本身有人工分歧（标注者一致率约 0.88），88 F1 离人类上限不远了。这也是为什么 SRL 近年研究热度下降——**问题被"解决"了**。

### 10.3 中文 SRL 的特殊点

- **谓词识别更难**：中文没有形态变化，"哪个词是谓词"本身要判断。
- **论元边界模糊**：中文是 pro-drop（省略主语）语言，论元常隐含，给标注和评估都带来困难。
- **CPB（Chinese PropBank）** 规模比英文小，预训练模型对它的迁移效果不如英文 PropBank 好。

## 十一、批判：LLM few-shot 抽取 vs 专门模型

### 11.1 LLM 正在"吃掉" IE/SRL

GPT-4/Claude 这类 LLM 出现后，一个趋势很明确：**用 prompt + few-shot 就能做关系抽取、事件抽取、SRL**，不用训练专门模型。

典型 prompt：

```
从下面句子抽取 founder_of 关系三元组，输出 JSON：
句子：比尔·盖茨 1975 年创立微软。
输出：{"subject": "比尔·盖茨", "relation": "founder_of", "object": "微软"}
```

对**长尾关系、新关系类型、小批量抽取**，LLM few-shot 几乎是默认选择——零训练成本，换个 prompt 就换任务。

### 11.2 但工业级准确率仍靠 fine-tuned 模型

LLM few-shot 的天花板在哪？经验上：

| 场景 | LLM few-shot | fine-tuned 专门模型 |
|------|-------------|-------------------|
| 通用关系（founder_of, born_in） | 强，接近专门模型 | 略高 |
| 领域专有关系（医学/法律/金融本体） | **明显弱**，长尾本体 LLM 没见过 | **强** |
| 高吞吐（每秒万句） | 太贵太慢 | 快且便宜 |
| 需要严格 schema 一致性 | 易"幻觉"出非法关系/角色 | schema 被训练锁死 |
| F1 要求 > 90% | 难达到 | 可达 |

**所以现实是混合**：LLM 做冷启动 + 长尾 + 数据增强，fine-tuned 小模型（BERT 级）做大规模生产推理。这正是 SLP3 这两章没赶上、但工程界已成共识的格局。

### 11.3 规则方法没死——反直觉的真相

最反直觉的是：**在窄领域 + 高精度要求下，几条专家手写规则仍能击败 LLM 和神经模型**。原因：

1. **领域知识结晶**：专家把"什么模板一定表示 founder_of"写成规则，等价于把先验注入系统，零样本就高精度。
2. **可解释、可审计**：金融/医疗/法律抽取出错要追责，规则可解释，黑盒模型不能。
3. **小数据上神经模型学不动**：标注只有 50 句，BERT 根本过拟合；规则直接用。

这就是配套实验要展示的——**在精心构造的小数据集上，规则 baseline 击败"模拟 LLM 式"的统计抽取**。这是领域专家知识的价值铁证。

### 11.4 这两章在 LLM 时代的位置

- **SRL**：基本"被解决"，研究热度下降，更多作为 downstream feature（问答、信息检索、文本摘要的可控性）存在。
- **关系抽取 / 知识图谱构建**：仍然活跃，因为长尾本体和领域知识永远在变，LLM + 远程监督 + 主动学习是主流组合。
- **事件抽取**：最没被"吃掉"——复杂事件、跨句论元、细粒度事件本体，LLM few-shot 还差一截。
