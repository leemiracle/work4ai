## §0 全局视角：BERT 的真正贡献不是"双向"

很多人对 BERT 的印象是"它双向，GPT 单向"。这只是表面。**BERT 真正的概念贡献是三个**：

| # | 贡献 | 深层意义 |
|---|------|---------|
| 1 | **从 token-level 到 type→instance 表示** | 一个词不再是一个向量（word2vec），而是每个语境一个向量（contextual embedding） |
| 2 | **预训练-微调范式** | 大模型预训练 + 小数据微调，2018–2022 NLP 标准范式 |
| 3 | **完形填空作为自监督** | 用 [MASK] 制造监督信号，无需人工标注 |

> "双向"只是上述 #1 的实现手段——因为要给每个 token 一个"看完整个句子"的表示，attention 必须**没有 causal mask**。如果只能看左边（GPT），每个 token 的表示就只是"前面发生的事"，对理解任务（NER、句子分类）不利。

### 算法经验 M1：representation 是 ML 的"中间货币"

> BERT 的本质是**生产通用 token 表示**的机器。下游任务（分类、检索、NER）都消费这些表示。这是"表示学习 (representation learning)"的范例——**好的表示能让下游任务用最简单的模型（线性分类器）就解决**。

可迁移场景：
- **CV**：ResNet/ViT 的 backbone + 下游检测分割
- **推荐**：user/item embedding + 下游召回排序
- **图**：node embedding + 下游节点分类
- **多模态**：CLIP 的图文共享表示

**经验**：当面对新领域时，先问"能不能定义一个好的表示学习目标 + 一个简单的下游 head"，往往比直接端到端训练高效得多。

## §1 三层讲透 MLM

### 1.1 直觉层

> **NTP 是"蒙住右眼往前走"（只能看左边）；MLM 是"把句子中间擦掉一个字，睁大双眼看全句填空"。**

正因为要填空，模型被迫用左右两边——这就是"双向"的来源。

**关键认知（避免初学者最常见误解）**：BERT **不是聊天机器人**，它甚至不能完整说一句话。它是一台"给每个词算上下文向量"的机器。

### 1.2 数学层

主损失——选 15% 位置 mask，只在这些位置算 loss：

$$\mathcal{L}_{\text{MLM}} = -\frac{1}{|M|}\sum_{i \in M} \log P(x_i \mid x_{\text{mask}})$$

预测：最后一层输出 $h_i^L$ 过 unembedding 层 + softmax：

$$u_i = h_i^L E^\top, \quad y_i = \text{softmax}(u_i)$$

**只有 15% 位置参与损失**——这是 MLM 效率问题的根源。

### 1.3 代码层（三个关键片段）

**(1) 双向 attention——只是不加上三角 mask**：

```python
att = (Q @ K.transpose(-1,-2)) / math.sqrt(d_head)
if self.causal:                       # ← GPT 走这里
    att = att.masked_fill(triu_mask, float('-inf'))
att = F.softmax(att, dim=-1)          # BERT: causal=False, 跳过 if
```

**(2) 80/10/10 mask**：

```python
masked[m & (r < 0.8)]  = MASK_ID                    # 80% 换 [MASK]
masked[m & (r >= 0.8) & (r < 0.9)] = randint(...)   # 10% 换随机
# 剩下 10% 不变
```

**(3) MLM loss——`ignore_index=-100` 让 85% 位置不参与**：

```python
loss = F.cross_entropy(logits.reshape(-1, V),
                       labels.reshape(-1), ignore_index=-100)
```

## §2 BERT 的三大反直觉发现

### 2.1 发现 1：BERT 对 [MASK] 上瘾（训练-推理不一致）

| 被预测位置输入 | 准确率（真实 BERT）| 准确率（toy essence）|
|---|---|---|
| `[MASK]`（哨兵）| ~80% | 4.0% |
| 真实词 | ~85% | 2.0% |
| 随机错词 | ~40% | 1.0% |

> ⚠️ **toy 模型的诚实**：toy 模型整体准确率低（没训充分），但**相对趋势对了**——[MASK] > 真实词 > 随机。这告诉我们这个现象**对模型容量要求不高，是 MLM 目标的内在属性**。

**反直觉点**：模型预训练时最擅长的"看到洞就填"，在真实任务里**永远不出现**（微调/推理输入里没有任何 [MASK]）。这就是 80/10/10 设计要缓解（但无法消除）的原罪。

### 2.2 发现 2：各向异性（未微调句向量做相似度差）

| 句向量来源 | AUC（真实 BERT）| 平均余弦 |
|---|---|---|
| 静态嵌入平均（w2v 式）| 0.95 | 0.5 |
| BERT 原始 mean-pool（未微调）| 0.65 | 0.90+ |
| BERT 微调后 mean-pool | 0.98 | 0.6 |

> ⚠️ **toy essence 数据**：未微调 MLM encoder AUC=0.478 < 静态 0.510，余弦 0.707（没到 0.99，因为 toy 模型没"训到崩"）。趋势一致。

**反直觉点**：更"先进"的上下文嵌入，在**不做任何微调**时，做语义相似度**反而不如**最朴素的静态词向量平均！原因：**原始 BERT 向量全挤在一个方向**（各向异性 anisotropy）。

### 2.3 发现 3：MLM 比 NTP 慢 ~5–7 倍

| 预训练方式 | 50 步后下游准确率 | 追平 NTP 需要多少步 |
|---|---|---|
| NTP（100% token 监督）| ~95% | 1× |
| MLM（15% token 监督）| ~75% | ~5–7× |

> ⚠️ **toy essence 的局限（重要教学）**：在 toy 模型上，mask 比例 30%/50%/80% 反而 loss 更低（因为更多监督信号）。但这**不等于更好**——toy 模型没引入下游评估，看不到"上下文被破坏"那一面。

**算法经验**：**单看预训练 loss 是危险的**。必须用 frozen-encoder + 线性探针评估表征质量，才能看到 mask 比例的真实效应。

## §3 BERT 设计选择的算法 DNA

每个看似随意的选择背后都有算法理由——这是 BERT 设计的"算法 DNA"：

| 设计选择 | 算法理由 | 可迁移场景 |
|---------|---------|-----------|
| **15% mask** | 平衡"信号密度"和"上下文完整性" | 任何"破坏-重建"自监督 |
| **80/10/10 三选一** | 缓解训练-推理分布不一致 | data augmentation、domain randomization |
| **`[CLS]` token** | 提供一个"聚合槽位"做句级任务 | 任何需要"序列→单向量"的设计 |
| **segment embedding** | 标记句对（A/B）的角色 | 任何多输入融合 |
| **mean-pool / CLS-pool 选择** | mean-pool 通常更稳；CLS 需微调 | 句向量提取 |
| **不加 NSP（RoBERTa）** | 严格对照实验证明 NSP 无用 | **Ablation 是设计验证的金标准** |

### 算法经验 M2：每个设计选择都要有算法理由

> 看到一个 ML 设计（超参、损失、架构），问"它解决什么问题？删掉会怎样？"——这是 ablation 思维。RoBERTa 的贡献就是**严格 ablation 了 BERT 的每个选择**，证明 NSP 是错的。

可迁移：你自己的项目里，每个超参、每个 loss term、每个模块，都应该问"我能 ablate 它吗？删掉会怎样？"

## §4 各向异性：representation learning 的常见病

各向异性是高维表示的**普遍疾病**，不只是 BERT 有：

### 4.1 现象

- **各向同性 (isotropic)**：向量在所有方向均匀分布，随机两个向量余弦期望为 0
- **各向异性 (anisotropic)**：向量挤在少数方向（"rogue dimensions"），任意两个余弦都接近 1

### 4.2 出现的模型

- BERT（最后几层）
- GPT-2（最后几层）
- 早期 CLIP 文本编码器
- 任何深度 transformer 的高层表示

### 4.3 解法谱系

| 方法 | 思路 | 代表 |
|------|------|------|
| **z-score 标准化** | 减均值除标准差，压流氓维度 | Timkey & van Schijndel 2021 |
| **微调（supervised）** | 在相似度任务上 fine-tune | Sentence-BERT |
| **对比学习（unsupervised）** | 拉近相似、推开不相似 | **SimCSE** |
| **白化 (whitening)** | 线性变换到各向同性 | BERT-flow, Su et al. 2021 |
| **流向量空间** | 学一个 normalizing flow | BERT-flow (Li et al. 2020) |

### 4.4 算法经验 M3：高维向量都倾向各向异性

> 这是深度学习的"重力"——任何 ReLU/tanh 网络训久了，激活分布都会塌缩到窄方向。这是为什么所有 representation learning 工作（SimCSE、BERT-flow、whitening）都直接或间接对抗各向异性。

可迁移：**任何用余弦相似度的场景，先检查平均余弦**——如果接近 1，说明向量没区分度，再"聪明"的检索算法也救不了。

## §5 三大架构对照

这是 NLP 神经架构最核心的一张表，**必须记住**：

| 维度 | **Encoder-only**（BERT）| **Decoder-only**（GPT/Claude/Llama）| **Encoder-Decoder**（T5/BART）|
|---|---|---|---|
| 注意力 | 双向 | 因果（下三角）| encoder 双向 + decoder 因果 |
| 预训练目标 | MLM | NTP | denoising（破坏→重建）|
| 能生成文本？ | ❌ 基本不能 | ✅ 最强 | ✅ 可以 |
| 擅长 | 分类、NER、句向量、检索 | 对话、写作、通用 | 翻译、摘要 |
| LLM 时代地位 | 被收编为"特征提取器" | **统治者** | 逐渐被 decoder-only 挤压 |

### 算法经验 M4：架构选择 = 任务类型选择

> **生成任务用 decoder-only，理解任务用 encoder-only，转换任务用 encoder-decoder**。这不是审美，是注意力机制决定的：
> - 生成要求"看到目前为止的内容预测下一个"→ causal mask 必需
> - 理解要求"看到完整上下文给每个 token 一个表示"→ 双向必需
> - 转换（翻译）要求"读完源 + 生成目标"→ 两段式

可迁移：**当你面对一个新任务，先问"我需要生成还是理解？"——这决定了架构**。

### 历史脉络

```
2017  Transformer (Vaswani) — encoder-decoder, 翻译
2018  BERT (encoder-only)   — 杀翻 GLUE, 理解任务标杆
2018  GPT-1 (decoder-only)  — 还没火
2019  GPT-2 (decoder-only)  — zero-shot 萌芽
2020  GPT-3 (decoder-only)  — 175B, prompting 通吃, decoder 封王
2022  ChatGPT (decoder-only) — 大规模商用
2024  o1/R1 (decoder-only + RL) — 长思考时代
```

## §6 微调范式

### 6.1 pretrain → finetune 的工程美学

```
预训练 (昂贵, 一次)   → 通用表示
   ↓
微调 (便宜, 多次)     → 任务专精
```

预训练 BERT 用 16 个 TPU 训 4 天；微调只用单 GPU、几万样本、几小时。

### 6.2 三类微调任务

| 任务 | 用的表示 | Head | 例子 |
|------|---------|------|------|
| **序列分类** | $h_{\text{CLS}}^L$ | linear(d→k) | 情感、主题 |
| **句对分类** | $h_{\text{CLS}}^L$（拼 A+SEP+B）| linear(d→k) | NLI、QA 匹配 |
| **序列标注** | $h_i^L$（每个 token）| linear(d→k) | NER、POS |

### 6.3 算法经验 M5：表示 + 简单 head 优于端到端

> BERT 微调只动最后一两层 + 新 head，少量数据就能让 110M 模型学会新任务。这是 **representation learning 的精髓**——好的表示让下游任务"线性可分"。

可迁移：
- **CV**：ImageNet 预训练 backbone + 下游线性分类器
- **推荐**：双塔召回（user 塔 + item 塔，输出点积）
- **检测**：预训练 backbone + 检测 head

**反例**：LLM 时代这条规律被打破——大模型不需要微调，直接 prompting。但**对小数据/特定任务**，pretrain-finetune 仍是性价比之王。

## §7 实战：什么时候用 BERT、什么时候用 LLM

| 场景 | 选 BERT | 选 LLM | 理由 |
|------|--------|--------|------|
| **句向量 / 语义检索**（百万级文档）| ✅ | ❌ | BERT 比 LLM 便宜几个数量级 |
| **文本分类**（情感、意图）| ✅ | △ | BERT 几十毫秒，LLM 几百毫秒 |
| **NER / 序列标注** | ✅ | △ | BERT 微调仍是工业标配 |
| **句法分析** | ✅ | ❌ | 双向信息关键 |
| **端侧 / 低延迟**（手机、嵌入式）| ✅ DistilBERT | ❌ | 几十 MB vs 几 GB |
| **批量特征提取**（百万文档 embedding）| ✅ | ❌ | 成本差 100× |
| **写作 / 对话 / 代码生成** | ❌ | ✅ | BERT 不能生成 |
| **多步推理 / 复杂指令** | ❌ | ✅ | BERT 没这种能力 |
| **zero-shot / few-shot** | ❌ | ✅ | BERT 需要微调 |

> **一句话**：**LLM 赢了"能力上限"，BERT 赢了"性价比下限"**。

### 算法经验 M6：成本-能力权衡是工程现实

> 学术界追能力上限（用 LLM），工业界追性价比（用 BERT）。**任何 ML 系统设计的第一步是问"延迟预算和成本预算多少"**——这决定了模型选型。

## §8 批判性：为什么 NTP 赢了，BERT 没死

### 8.1 为什么 NTP 最终赢了？

**根本原因：scaling 对 NTP 友好，对 MLM 不友好。**

| | NTP（GPT）| MLM（BERT）|
|---|---|---|
| 监督密度 | 100% | 15% |
| 扩大规模时 | 信号密集，能力持续上升 | 信号浪费被放大 |
| 目标性质 | 密度估计（density estimation）| 完形填空（auxiliary task）|
| 能否生成 | ✅（核心能力）| ❌ |

2020 GPT-3 证明：**decoder-only + NTP + 足够大 = 通吃一切理解任务**（分类、NER、NLI 全能用 prompting 做）。从此 NLP 主线从 "pretrain→finetune" 转向 "pretrain→prompt/instruction"。

### 8.2 为什么 BERT 至今没死？

**"研究退场" ≠ "工程退场"**。在以下场景，BERT 类模型**仍然是首选**：

1. **不需要生成**——只需要"理解+打标签"
2. **要快、要便宜、要可批量**——百万文档 embedding，BERT 比 LLM 便宜 100×
3. **端侧部署**——DistilBERT 几十 MB
4. **小数据**——LLM zero-shot 不够稳，BERT 微调更可靠

### 8.3 BERT 类的现代演化

| 模型 | 解决什么 | 2025 年地位 |
|------|---------|------------|
| **Sentence-BERT / E5 / BGE** | 句向量微调 | **检索/RAG 的核心** |
| **SimCSE** | 无监督对比学习 | 句向量基石 |
| **ELECTRA** | 解决 MLM 监督稀疏 | 被 LLM 覆盖 |
| **DeBERTa** | 解耦注意力 | 微软内部主力 |
| **ModernBERT** (2024) | 现代 BERT（RoPE、Flash Attn、长上下文）| **2024 encoder-only 复兴** |

### 算法经验 M7：好范式会"演化"而非"消失"

> BERT 没死，是**演化为 BGE/E5 这类专精句向量模型**——主干还是 encoder-only，但目标换成了对比学习。这是 ML 的常态：**好的架构会被新目标接管，而不是被替换**。

可迁移：CNN 没死（变成 ViT 内部模块）、RNN 没死（变成 Mamba/RWKV）、SVM 没死（变成线性分类器）。

| BERT 原始 mean-pool | 0.672 | 0.999（高度各向异性）|
| BERT 微调后 mean-pool | 1.000 | 0.006 |

**发现 3**：MLM 比 NTP 收敛慢 ~3×

### 10.2 算法本质版（`10_essence_mlm.py`，无 attention）

| 发现 | 真实 BERT 趋势 | toy 模型趋势 | 一致性 |
|------|--------------|-------------|---------|
| 1 [MASK] 上瘾 | [MASK] > 随机 | [MASK] > 随机 | ✅ 趋势一致 |
| 2 各向异性 | AUC 差 | AUC 差 | ✅ 趋势一致 |
| 3 mask 比例 | 15% 最优 | 80% loss 最低 | ❌ toy 缺下游评估 |

> **算法经验 M8 强化**：**toy 模型的失败也是经验**——它告诉我们"没有下游评估时，预训练 loss 反映不了真实质量"。这是为什么真实 BERT 论文一定要做 GLUE/SuperGLUE 评估。

**练习 A**（算法经验 M2 ablation）：在 essence 脚本上，删掉 80/10/10 里的 10% 随机 / 10% 不变（全用 80% [MASK]），观察 [MASK] 上瘾现象是否更严重。

**练习 C**（架构选择 M4）：用一句话回答——为什么机器翻译通常用 encoder-decoder 而不是 decoder-only？虽然 GPT 也能做翻译，为什么工程上不如 encoder-decoder？（提示：源端要"读完再生成"，decoder-only 的因果掩码让源端编码受限。）

**练习 D**（成本-能力 M6）：假设你的 RAG 系统要给 100 万文档建索引。比较：(a) 用 GPT-4 算 embedding，(b) 用 BGE-large 算 embedding。计算成本（按公开 API 价格）和延迟。哪个合理？

**练习 E**（Deep Thinking）：MLM 的 80/10/10 设计是为了缓解训练-推理不一致。但**为什么 BERT 不直接在推理时也用 [MASK]**？（提示：因为推理时不知道"应该 mask 哪个位置"——MLM 是为了表示学习，不是为了预测本身。）
