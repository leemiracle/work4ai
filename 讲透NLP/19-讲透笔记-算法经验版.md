## §0 全局视角：依存句法 = "扁平化"的句法

成分句法（Ch18）用嵌套树，依存句法用**词与词的直接关系**——更简洁、更适合工程。

| | 成分句法（CFG）| 依存句法 |
|---|---------------|---------|
| 表示 | 嵌套短语树 | 词→词的有向边 |
| 边数 | $O(n)$ 内部节点 | $O(n)$ 边 |
| 标注成本 | 高（树结构复杂）| 低（头部 + 关系标签）|
| 工程友好 | 弱 | 强（spaCy/Stanza 默认）|

> 🔑 **算法 DNA**：依存句法把句法从"层次结构"扁平化为"图结构"——这更适合现代图算法和神经建模。

## §1 五条算法经验

### 算法经验 D1：transition-based = 强化学习的雏形

> Transition-based parser 用"动作序列"解析句子：
> - **Shift**：把词从 buffer 移到 stack
> - **Left-Arc / Right-Arc**：建立依存关系
> - **Reduce**：从 stack 弹出
>
> 这本质上是**状态 → 动作 → 新状态**的 MDP——**强化学习的标准框架**。

可迁移（应用 Ch9 PPO、#9 RL 4 角色）：
- **AlphaGo**：棋盘状态 → 落子动作
- **机器人控制**：感知 → 动作
- **对话系统**：对话状态 → 系统动作
- **编译器优化**：IR 状态 → 优化动作

### 算法经验 D2：oracle = 监督信号的来源

> Transition-based parser 训练时需要 **oracle**——告诉模型每一步该做什么动作。Oracle 通常从黄金树推导。
>
> 算法本质：**模仿学习**——从专家演示学策略。

可迁移：
- **行为克隆**（imitation learning）
- **蒸馏**（teacher → student）
- **代码助手的"人类示范"**

### 算法经验 D3：贪心 vs 全局优化

> Transition-based parser 用**贪心**（每步选最优动作）——快但可能落入次优。
> Graph-based parser 用**全局优化**（找最大生成树）——准但慢。
>
> 算法本质：**局部贪心 vs 全局搜索**的权衡。

可迁移（应用 T6 端到端 vs 流水线、Q1 局部 vs 全局归一化）：
- **beam search vs greedy**
- **DP vs 贪心**
- **RL 的 policy gradient vs value iteration**

### 算法经验 D4：项目ive 算法 = 栈 + 队列

> arc-standard / arc-eager 是经典 projective 算法，核心是**栈 + 输入队列**的数据结构。
>
> 这是**有限状态自动机**（FSA）的实例——和编译器解析、Pushdown automaton 同源。

可迁移：
- **Shift-Reduce Parsing**
- **编译器的 LR 解析**
- **正则引擎**
- **栈式虚拟机**

### 算法经验 D5：依存句法的"硬限"——非投影性

> Projective（投影）依存树要求"边不交叉"——但自然语言有**非投影**结构（如荷兰语、土耳其语的自由语序）。
>
> Transition-based parser 处理非投影要扩展动作集（swap action），graph-based 直接支持。
>
> 算法本质：**表达力 vs 计算复杂度的权衡**（应用 N3 参数共享的不变性）。
