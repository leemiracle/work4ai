## §0 全局视角：机器翻译史 = 半部 NLP 史

| 时代 | 催生的算法 | 后来被谁继承 |
|------|-----------|-------------|
| **SMT** (1990s–2010s) | EM、词对齐、短语表、log-linear reranking | 词对齐 → attention、log-linear → ranking |
| **RNN seq2seq** (2014) | encoder-decoder、瓶颈向量 | 所有自回归生成（GPT、diffusion）|
| **+ Attention** (2014) | 软对齐、动态上下文 | Transformer、CLIP、推荐召回 |
| **Transformer** (2017) | self-attention、多头、位置编码 | 整个 LLM 时代 |
| **多语言 MT** (2020s) | NLLB、SeamlessM4T | 多模态、跨模态对齐 |
| **LLM zero-shot** | in-context translation | prompt engineering |

> 🔑 **核心洞察**：**MT 不是 NLP 的一个子领域，是 NLP 算法的"孵化器"**。读懂 MT 史，就读懂了 NLP 算法骨架的演化。

### 算法经验 T1：MT 是 ML 算法的"试炼场"

> 几乎所有现代 ML 核心算法都首先在 MT 上验证：
> - **EM**（IBM Model 1, 1993）→ 后来用于 GMM、HMM、topic model
> - **seq2seq encoder-decoder**（2014）→ 后来用于摘要、对话、代码生成
> - **attention**（2014）→ 后来用于所有 Transformer
> - **beam search / length normalization** → 后来用于所有自回归生成
> - **RLHF 的 GRPO 早期形式**（minimum risk training for MT, 2016）

可迁移：**研究新算法时，先问"它能不能在 MT 上验证"——MT 任务有清晰的评测（BLEU）、丰富的数据、可控的规模，是算法验证的理想试炼场**。

## §1 三层讲透 IBM Model 1

### 1.1 直觉层

> **IBM Model 1 = "看哪个英文词老和哪个中文词一起出现，就认为它们互相翻译"。**

完全无监督，不需要词典，不需要对齐标注——纯靠双语共现统计 + EM 迭代。

### 1.2 数学层

**生成假设**（极简）：先均匀随机选对齐 $a_j$，再根据翻译概率 $t(f|e)$ 选词：

$$P(\mathbf{f}, \mathbf{a} \mid \mathbf{e}) = \prod_{j=1}^{m} \frac{1}{\ell+1}\, t(f_j \mid e_{a_j})$$

**边缘似然**（对所有对齐求和，因式分解）：

$$P(\mathbf{f}\mid\mathbf{e}) = \prod_{j=1}^{m} \frac{1}{\ell+1}\sum_{i=0}^{\ell} t(f_j \mid e_i)$$

**E-step**（求对齐后验）：

$$\gamma_j(i) = \frac{t(f_j\mid e_i)}{\sum_{i'} t(f_j\mid e_{i'})}$$

**M-step**（用期望计数更新）：

$$t_{\text{new}}(f\mid e) = \frac{\text{count}(f\mid e)}{\text{total}(e)}$$

### 1.3 算法本质：词袋贝叶斯

IBM Model 1 的 E-step 公式 $\gamma_j(i)$ **只依赖词本身，不依赖位置**——这是一个**词袋模型**。它本质上在做：

> 对每个目标词 $f_j$，按 $t(f_j|e_i)$ 把它"软分配"给所有可能的源词 $e_i$，归一化。

这就是为什么实验跑出"打乱词序后 t 表完全不变"——词袋天然对词序置换不变。

### 算法经验 T2：模型的数学不变性 = 它的硬上限

> **IBM Model 1 的置换不变性不是缺陷，是它的数学定义。**它**永远**学不到词序，无论多少数据、多少迭代。
>
> 理解模型在数学上"看不到什么"，比看到"它能做什么"更重要。

可迁移场景：
- **CNN 的平移不变性**：CNN 看不到"绝对位置"（需要 positional encoding 补救）
- **Transformer 的排列不变性**：transformer 看不到"顺序"（需要 positional encoding）
- **BOW 的词序不变性**：word2vec 看不到句法
- **mean-pooling 的位置不变性**：丢失位置信息（用 attention pooling 补救）

**经验**：**调任何模型前，先想清楚它的"数学不变性"——这就是它的硬上限**。

## §2 EM 算法：ML 历史上最伟大的"无监督学习"工具

### 2.1 EM 的算法本质

EM（Expectation-Maximization）解决"有隐变量 + 无标注"的学习问题。它是一个**坐标上升**算法：

```
循环:
  E-step: 固定参数 θ, 推断隐变量的后验 P(z|x; θ)
  M-step: 固定后验, 最大化期望对数似然, 更新 θ
```

**保证**：每次迭代，对数似然**单调不减**（直到局部最优）。

### 2.2 EM 在 ML 历史上的地位

| 年代 | 应用 | 隐变量是什么 |
|------|------|-------------|
| 1977 | Dempster 总结 EM 框架 | 一般框架 |
| 1990s | **IBM Model 1-5**（MT 词对齐）| 词对齐 a |
| 1990s | **GMM**（高斯混合）| 类别归属 |
| 1990s | **HMM**（语音/POS tagging）| 隐状态 |
| 2000s | **LDA / pLSA**（主题模型）| 主题分布 |
| 2010s | **k-means**（EM 的硬分配特例）| 簇归属 |
| 2013 | **VAE**（变分自编码器）| 潜在编码 z（用变分 EM） |
| 2020 | **Diffusion** 的训练 | 噪声水平 t |

> 几乎所有"无监督学结构"的方法都是 EM 或其变体。

### 2.3 算法经验 T3：EM 是隐变量问题的通用工具

> 任何"有标注缺失 + 想从数据中学结构"的场景，先想 EM。
>
> **核心思想**：把"猜测隐变量"（E）和"优化参数"（M）解耦，交替进行。

可迁移：
- **数据缺失**：用户画像有缺失字段，用 EM 推断
- **聚类**：k-means 是硬分配 EM
- **主题模型**：LDA 用变分 EM 或吉布斯采样
- **领域适应**：源域有标签、目标域无标签，用 EM 跨域

## §3 离散 → 连续：贯穿整个 ML 史的分水岭

### 3.1 MT 史上最清晰的"离散→连续"案例

| | 离散（IBM Model 1）| 连续（attention）|
|---|------------------|-----------------|
| 对齐表示 | $\gamma_j(i) \in \{0,1\}$（硬）| $\alpha_{t,i} \in [0,1]$（软）|
| 选择方式 | argmax（不可微）| softmax（可微）|
| 训练 | EM（坐标上升）| 梯度下降（端到端反向传播）|
| 表达力 | 受限（必须选一个）| 无限（可加权混合）|

### 3.2 离散 → 连续是 ML 主旋律

| 领域 | 离散版 | 连续版 |
|------|-------|-------|
| 聚类 | k-means（硬分配）| GMM（软分配）|
| 决策 | 决策树（硬阈值）| soft tree / neural net |
| 注意力 | argmax 选 token | softmax over vocabulary |
| 检索 | top-1 硬选 | top-k 软加权 |
| 采样 | argmax decoding | temperature sampling |
| 强化学习 | 离散动作 | 连续策略梯度 |

### 3.3 算法经验 T4：连续松弛是 ML 的"统一货币"

> **当你卡在"硬决策不可微"时，几乎总能用连续松弛解决**：
> - argmax → softmax + temperature
> - 硬聚类 → 软聚类
> - 离散采样 → Gumbel-softmax / reparameterization
> - 硬注意力 → 软注意力

可迁移：
- **离散优化**（背包、TSP）→ 连续松弛 + 投影
- **结构化预测**（argmax decoding）→ 软解码 + SOFTmax
- **强化学习离散动作**→ policy gradient / Gumbel-softmax

**经验**：**ML 进展的很大一部分，来自把"离散硬决策"换成"连续软决策"**。看到不可微，先尝试连续松弛。

## §4 对齐：结构化预测的核心抽象

### 4.1 "对齐"无处不在

| 任务 | 对齐的是什么 |
|------|-------------|
| **MT** | 源句 token ↔ 目标句 token |
| **seq2seq attention** | decoder step ↔ encoder state |
| **Cross-encoder rerank**（Ch11）| query token ↔ doc token |
| **CLIP** | 图像 patch ↔ 文本 token |
| **对比学习** | anchor ↔ positive |
| **推荐** | user ↔ item |
| **知识图谱** | 实体 ↔ 实体 |
| **RAG** | query ↔ chunk |
| **多模态 CoT** | 视觉概念 ↔ 语言概念 |

> 🔑 **抽象**：**对齐 = 找两个集合之间的（软或硬）对应关系**。

### 4.2 算法经验 T5：对齐是结构化预测的核心

> 凡是"两个集合要建立对应"的任务，本质上都是对齐问题，可以套同一套算法框架：
> - **学习一个打分函数** $s(x, y)$（点积、双线性、cross-attention）
> - **softmax 归一化**得到软对齐（或 argmax 得到硬对齐）
> - **训练目标**：对齐正确（contrastive loss / NLL / 偏好 loss）

可迁移：**当你看到一个新任务是"匹配两个东西"，先想"它是不是对齐问题？"——如果是，所有 MT/CLIP/RAG 的算法都能用**。

## §5 端到端 vs 流水线：ML 系统设计的永恒权衡

### 5.1 SMT vs NMT 的权衡

| | SMT（流水线）| NMT（端到端）|
|---|-------------|-------------|
| 组件 | 对齐 → 短语 → 解码 → 重排 | 一个网络 |
| 调试 | 容易（每组件独立）| 难（黑盒）|
| 数据 | 可分阶段加数据 | 需要端到端数据 |
| 误差 | 层层累积 | 整体优化 |
| 上限 | 受组件限制 | 理论上更高 |
| 可解释 | 强 | 弱 |

### 5.2 算法经验 T6：端到端 vs 流水线的权衡是 ML 永恒主题

> 这个权衡反复出现：
> - **CV 检测+识别**（流水线）vs **end-to-end detection**（YOLO）
> - **推荐召回+排序**（流水线）vs **end-to-end recommendation**
> - **TTS** 的文本→声学→声码器（流水线）vs **end-to-end TTS**（Tacotron）
> - **RAG**（检索器+生成器流水线）vs **长上下文 LLM**（端到端）

**通用规律**：
- **数据多、算力足、追求上限** → 端到端
- **数据少、要可控、要可解释** → 流水线
- **现实生产** → 通常混合（端到端核心 + 流水线外围）

可迁移：**设计任何 ML 系统的第一步，是问"端到端还是流水线"——这决定了模块化策略**。

## §6 瓶颈向量 → 动态上下文（RNN → attention）

### 6.1 seq2seq 的瓶颈

RNN seq2seq 把整句话压进**一个固定长度向量** $c = h_T$，再解码。句子一长就崩——这是 attention 诞生的直接动机。

### 6.2 Attention 的算法本质

Attention 不是"魔法"，是**动态上下文**：decoder 每一步根据当前状态，**重新算一个**上下文 $c_t$：

$$c_t = \sum_i \alpha_{t,i}\, h_i, \quad \alpha_{t,i} = \text{softmax}_i(a(s_{t-1}, h_i))$$

对比：

| | RNN seq2seq | Attention seq2seq |
|---|-------------|-------------------|
| 上下文 | 固定向量 $c = h_T$ | 动态 $c_t$（每步不同）|
| 信息容量 | 受 $c$ 维度限制 | 受所有 $h_i$ 总和限制 |
| 长句表现 | 崩 | 稳 |

### 6.3 算法经验 T7：固定表示 → 动态表示是 ML 通用升级

> 凡是"固定表示不够用"的场景，都能用动态计算解决：
> - **静态嵌入（word2vec）→ 上下文嵌入（BERT）**（Ch10）
> - **固定上下文向量 → attention 动态上下文**
> - **固定 prompt → 动态 in-context learning**
> - **固定模板 → soft prompt tuning**
> - **CNN 固定权重 → dynamic convolution**
> - **固定路由 → Mixture of Experts 动态路由**

**通用模式**：**把"固定参数"换成"输入相关的动态参数"，几乎总能涨点**——代价是计算变贵。

可迁移：**当你的模型在某类输入上效果差，先想"是不是用了固定表示？能不能动态化？"**

## §7 BLEU 与评测指标的盲区

### 7.1 BLEU 的设计与盲区

**BLEU 公式**：

$$BLEU = BP \cdot \exp\left(\sum_{n=1}^{4} \frac{1}{4}\log p_n\right)$$

三个机制（每个都对应一个反作弊）：
1. **修正 n-gram 精度 $p_n$ + clip**：防止"重复刷同一个对的词"
2. **高阶 n-gram（n=2,3,4）**：抓词序/搭配
3. **简短惩罚 BP**：防止"偷懒少翻"

**盲区**：
- 只看表面 n-gram，**不敏感于语义**（同义改写被低估）
- 句子级 BLEU 极苛刻（错一个词，4-gram 全废）
- 不区分"关键词错"vs"功能词错"

### 7.2 实验铁证

| 候选 | $p_1$ | $p_2$ | $p_3$ | $p_4$ | BLEU-4 |
|------|------|------|------|------|--------|
| 完美翻译 | 1.00 | 1.00 | 1.00 | 1.00 | 1.000 |
| 一处冠词错 | 0.86 | 0.67 | 0.40 | 0.25 | 0.489 |
| **词沙拉（词序乱）** | **1.00** | **0.00** | 0.00 | 0.00 | **0.000** |

> **词沙拉 $p_1=1.0$ 但 BLEU=0**——所有词都对，但顺序全错。这是 BLEU 用高阶 n-gram 抓词序的最清晰演示。

### 7.3 算法经验 T8：每个评测指标都有盲区

> 没有完美的指标——**评测指标的设计本身就是一种 bias**：
> - **BLEU** 只看表面 n-gram
> - **accuracy** 不区分类别不平衡
> - **FID**（图像生成）不感知物体类别
> - **perplexity**（LM）不感知生成质量
> - **precision@k**（推荐）不感知多样性

**经验**：
- **任何指标都有盲区，永远不要只看一个指标**
- **多指标 + 人工评估**是工程标配
- **学习型指标**（COMET, BLEURT）部分缓解，但带来新盲区

可迁移：**设计任何 ML 系统时，先想"评测指标的盲区在哪？我要不要补一个反指标？"**

## §8 实战：MT 任务在 LLM 时代的决策树

```
1. 语对?
   ├── 高资源（英中/英欧）→ LLM zero-shot 通常够用
   └── 低资源（小语种）→ 专用 MT（NLLB / SeamlessM4T）

2. 延迟要求?
   ├── 实时（字幕/同传）→ 专用 MT（蒸馏后小模型）
   └── 离线 → LLM 或专用 MT 都可

3. 术语可控?
   ├── 严格（法律/医疗）→ 专用 MT + 术语表注入
   └── 宽松 → LLM

4. 多模态?
   ├── 仅文本 → 上述
   └── 语音 → SeamlessM4T / 专用 ASR+MT+TTS pipeline

5. 大规模批量?
   ├── 是 → 专用 MT（成本低 1-2 个数量级）
   └── 否 → LLM
```

### 算法经验 T9：自回归生成是所有生成任务的统一范式

> seq2seq decoder 的"每步根据前面 token + 表示预测下一个"是：
> - **GPT 生成**的核心
> - **diffusion 反向采样**的对应
> - **RL 序列决策**的对应
> - **TTS 音频生成**的核心
> - **代码生成 / 蛋白质序列生成 / 视频帧生成**的核心

**通用模式**：**任何序列生成 = 自回归 = "根据过去 + 上下文，预测下一步"**。

可迁移：看到一个生成任务，先问"它是自回归的吗？"——如果是，所有 seq2seq / GPT 的工程技巧（beam search、temperature、KV cache）都能用。

## §9 批判性：LLM 时代 MT 的真实市场

### 9.1 LLM 收编了 MT 的哪部分？

| 任务 | LLM 是否收编 |
|------|-------------|
| 高资源语对、文本翻译 | ✅ 已收编（GPT-4 翻译质量超专用 MT）|
| 上下文敏感翻译（如歧义消解）| ✅ 已收编 |
| 多语种翻译（10+ 主流语言）| ✅ 基本收编 |
| 术语可控翻译（法律/医疗）| △ 部分（LLM 自由度高反而是缺陷）|

### 9.2 专用 MT 退守哪些阵地？

| 阵地 | 为什么 LLM 暂时进不来 |
|------|---------------------|
| **低资源语言（200+ 小语种）** | LLM 训练数据里没有，NLLB 专门攻 |
| **实时低延迟**（字幕/同传）| LLM 推理贵且慢，专用 MT 蒸馏后毫秒级 |
| **语音翻译** | SeamlessM4T 把 ASR+MT+TTS 焊一起，LLM 文本范式不直接覆盖 |
| **术语一致性**（专利/法律）| 专用 MT 支持约束解码，术语表注入 |
| **大规模批量翻译**（百万文档）| 专用 MT 成本低 1-2 个数量级 |

### 9.3 算法经验 T10：LLM 收编专业模型的通用规律

> **LLM 收编 ML 子领域的剧本几乎一样**：
> 1. **早期**：专用模型（如 BERT for NER, YOLO for detection,专用 MT）
> 2. **中期**：LLM 在通用任务上反超专用模型
> 3. **后期**：专用模型退守"低资源 / 低延迟 / 高可控 / 大规模批量"阵地
> 4. **稳定期**：两者共存，分层市场

可迁移：CV（专用检测 vs GPT-4V）、ASR（专用 vs GPT-4o）、推荐（专用 vs LLM-based agent）—— **所有 ML 子领域都在经历这个收编剧本**。

**经验**：**判断"专业模型会不会死"，问四个问题——低资源？低延迟？高可控？大规模？只要有一个 yes，专业模型就还活着**。

## ✍️ 练习（算法经验导向）

**练习 A**（数学不变性 T2）：证明 IBM Model 1 不仅对**目标句**词序置换不变，对**源句**词序置换也严格不变。（提示：检查 E-step 的 $\gamma_j(i)$ 是否依赖 $e_i$ 的位置。）

**练习 B**（EM 推广 T3）：找一个有缺失字段的数据集（如 MovieLens 用户画像），用 EM 推断缺失值。EM 的 E-step 推断缺失字段的后验，M-step 更新字段间的关系参数。

**练习 C**（连续松弛 T4）：k-means 是硬分配 EM（每个点完全属于一个簇）。把它改成软分配（GMM 风格），观察聚类边界的差异。

**练习 D**（对齐抽象 T5）：CLIP 是图像-文本对齐。它的对齐矩阵是什么？和 attention 的对齐矩阵有何异同？

**练习 E**（端到端 vs 流水线 T6）：CV 中的"检测+识别"是经典流水线。对比 YOLO（端到端）vs Faster R-CNN+CRNN（流水线）。各自的优势场景是什么？

**练习 F**（评测盲区 T8）：找一个 BLEU 评分很低但人工判断质量很好的翻译（同义改写）。讨论：如果你只能用 BLEU 优化，会扼杀哪些"好翻译"？

**练习 G**（Deep Thinking）：Transformer 原论文是 MT 论文（WMT 英德/英法）。但 Transformer 后来统治了**所有** NLP 任务，甚至 CV（ViT）。一个为 MT 设计的架构为什么这么通用？（提示：self-attention 是"任意两个 token 的对齐"，这个抽象足够通用。）
