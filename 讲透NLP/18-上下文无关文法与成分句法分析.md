# 18 — 上下文无关文法与成分句法分析

> 对应 SLP3 Chapter 18。这一章是 NLP 里「结构主义」的集大成：一句话不是词的平铺，而是一棵**嵌套的树**。CFG（上下文无关文法）是这棵树的形式语言，CKY 是把句子变回树的算法，PCFG 给树打分，树库是树的「教材」。
>
> 虽然 LLM 已经不太显式建树，但「成分结构」仍然是理解句法、语义组合、甚至 Transformer 注意力的底层脚手架。
>
> 配套实验：`experiments/18_cfg_cky.py`

---

## 1. 直觉：句子是树，不是串

看这句话：

> 我看见那个戴帽子的人。

你脑子里绝不是一个词一个词地「流」过去。你是在**分组**：

```
我  ［ 看见  ［ 那个  ［ 戴帽子的 ］ 人 ］ ］
 └──NP────────────────VP──────────────────┘
                     └──NP──────────────┘
                          └──(修饰语)──┘
```

- 「那个戴帽子的人」整体是一个**名词短语（NP）**，做「看见」的宾语；
- 「戴帽子的」是套在「人」外面的**修饰语**，它只跟「人」发生关系，跟「看见」无关。

这就是**成分（constituency）**：某些词组会「抱团」成一个单元，整体充当一个语法角色。换成英文更清楚——经典的 Groucho Marx 笑话：

> **I shot an elephant in my pajamas.**（我穿着睡衣开枪打了一头大象。）

正常理解是「我穿着睡衣」打的大象（VP 附着）。但字面也可以理解成「那头大象穿着我的睡衣」（NP 附着）。笑点恰恰来自**同一串词有两棵不同的树**——也就是**歧义（ambiguity）**。

> **为什么必须用树？** 因为「in my pajamas」这个介词短语（PP）到底挂在动词（VP）下面、还是挂在名词（NP）下面，决定了它修饰谁。线性串表达不了「谁套在谁里面」，只有层次树能表达。**句法的本质是层次，不是顺序。**

## 2. 数学：上下文无关文法（CFG）

### 2.1 形式定义

一个**上下文无关文法（Context-Free Grammar, CFG）** 是一个四元组：

$$G = (N,\ \Sigma,\ R,\ S)$$

| 符号 | 含义 | 例子 |
|------|------|------|
| $N$ | 非终结符（nonterminal）集合 | $\{S, NP, VP, PP, N, V, Det, P\}$ |
| $\Sigma$ | 终结符（terminal）集合，即真正的词，与 $N$ 不相交 | $\{$ the, cat, saw, on, ... $\}$ |
| $R$ | 产生式（production）规则的集合 | $S \to NP\ VP$， $VP \to V\ NP$ |
| $S$ | 起始符（start symbol），$S \in N$ | $S$（句子） |

每条**产生式**形如：

$$A \to \gamma,\quad A \in N,\ \gamma \in (N \cup \Sigma)^{*}$$

读作「$A$ 可以重写成 $\gamma$」。叫「上下文无关」是因为：**不管 $A$ 左右是什么，$A$ 都能换成 $\gamma$**——重写规则只看 $A$ 自己，不依赖上下文。

一组微型 CFG：

```
S    → NP VP                    # 句子 = 名词短语 + 动词短语
NP   → Det N   |  Pronoun       # "the cat" / "I"
VP   → V        |  V NP  |  V NP PP   # "sat" / "saw the man" / "saw him with..."
PP   → P NP                     # "with the telescope"
Det  → the | a                  # 前终结符，直接指向词
N    → cat | man | telescope
V    → saw | sat
P    → with | on
```

### 2.2 推导与树

从 $S$ 出发，不断把非终结符替换成右部，直到全是终结符——这叫**推导（derivation）**：

$$S \Rightarrow NP\ VP \Rightarrow Det\ N\ VP \Rightarrow the\ N\ VP \Rightarrow the\ cat\ VP \Rightarrow \cdots \Rightarrow the\ cat\ sat\ on\ the\ mat$$

每一步把**最左**的非终结符展开叫**最左推导**，最右的叫**最右推导**。同一棵树对应唯一的最左推导和唯一的最右推导——它们只是顺序不同。

每棵**句法树（parse tree）**的叶子从左到右拼起来就是句子，每个内部节点对应一条用到的产生式。

### 2.3 歧义：CFG 的「特性」也是「麻烦」

CFG 的力量在于**一个句子可以有多棵合法的树**——这就是结构歧义。最经典的是**介词短语附着（PP attachment）**：

> **I saw the man with the telescope.**

两棵树：

```
读法 A（VP 附着）：我用望远镜看见了他         读法 B（NP 附着）：他是那个带望远镜的人

        S                                        S
       / \                                      / \
     NP   VP                                   NP  VP
     │   /│ \                                  │  / │ \
     I  V NP PP                                I V NP PP
        │  │  │                                  │ /│  │
      saw ... with                            saw ...with
        │   │                                  │  │   │
        └──┘the man                            └──┘  the telescope
        "with..." 挂在 VP 上                        "with..." 挂在 NP 上
```

精确地说（用配套实验跑出来的两棵树）：

```
读法 A（VP 附着）：                 读法 B（NP 附着）：
S                                   S
├─ Pro → "I"                        ├─ Pro → "I"
└─ VP                               └─ VP
   ├─ VP                               ├─ V → "saw"
   │  ├─ V → "saw"                     └─ NP
   │  └─ NP                               ├─ NP
   │     ├─ Det → "the"                   │  ├─ Det → "the"
   │     └─ N → "man"                     │  └─ N → "man"
   └─ PP                                  └─ PP
      ├─ P → "with"                          ├─ P → "with"
      └─ NP                                  └─ NP
         ├─ Det → "the"                         ├─ Det → "the"
         └─ N → "telescope"                     └─ N → "telescope"
```

歧义不只这一种，常见的还有：
- **并列歧义**：`old men and women` —— 是「(old men) and women」还是「old (men and women)」？
- **词性歧义**：`flies` 在 `time flies like an arrow` 里是动词（时间飞逝），在 `fruit flies` 里是名词（果蝇）。

> 反直觉的是：**歧义不是 CFG 的 bug，是它的本质。** 英语里几乎每个长句都有几十甚至上百种合法解析，人脑靠语义/常识瞬间选出「对的」那棵，但纯 CFG 看不出哪棵对——它只知道「哪些树合法」。

### 2.4 乔姆斯基范式（CNF）

为了让算法统一、好分析，常把任意 CFG 改写成 **Chomsky Normal Form（CNF）**——规则只有两种形式：

$$A \to B\ C \quad(A,B,C \in N)\qquad\text{或}\qquad A \to w \quad(w \in \Sigma)$$

即：要么展开成**恰好两个**非终结符，要么直接指向**一个**词。任何 CFG 都能等价转成 CNF（见附录 F）：把多元规则 $A \to B\ C\ D$ 拆成 $A \to B\ X$、$X \to C\ D$，把一元链 $A \to B \to C$ 压平，把终结符包进前终结符。

> **为什么要 CNF？** 因为它保证「每条规则恰好把一个跨度切成两半」。CKY 算法就靠这一点做动态规划——见第 5 节。

## 3. 树库：句法树的「教材」

手写文法既累又不准。现代 NLP 不写规则，而是**标注一棵棵真实的树**，让算法从树里学文法。这种大规模句法树语料叫**树库（treebank）**。

### Penn Treebank（PTB）

- 最有影响力的英语树库，来自 **Wall Street Journal**（华尔街日报）。
- 规模约 **100 万词、约 4 万句**，每句都人工标注了成分树。
- 约 **45 个词性标签**（如 `NN`=单数名词、`VBD`=过去式动词、`IN`=介词/从属连词）。
- 标准 split：**sec 02–21 训练、22 开发、23 测试**——句法分析的「MNIST」。
- 几十年里，PTB 上的 F1 就是衡量句法分析器的标尺。

### Universal Dependencies（UD）

- PTB 是英语专属、标签体系也很「英语化」。**UD** 是跨语言的依存树库（注意：依存≠成分，见第 19 章），用一套**通用**的词性与依赖关系标注 **200+ 种语言**。
- 成分分析（本章）和依存分析（下章）是两种不同视角：成分强调「短语嵌套」，依存强调「词与词的修饰关系」。两者可以互相转换。

## 4. PCFG：给规则加概率

光有 CFG 选不出「对的树」。**概率上下文无关文法（PCFG）** 的做法：给每条规则一个概率，整棵树的概率 = 各规则概率之乘积。

### 定义

PCFG 给每条产生式 $A \to \gamma$ 一个**条件概率**：

$$P(A \to \gamma \mid A)$$

约束（归一化）：同一个左部 $A$ 的所有规则概率之和为 1：

$$\sum_{\gamma} P(A \to \gamma \mid A) = 1,\quad \forall A \in N$$

一棵树 $t$ 的概率是它用到的所有规则概率之积：

$$P(t) = \prod_{A \to \gamma \in t} P(A \to \gamma \mid A)$$

一个句子 $s$ 的概率是**所有能生成它的树**的概率之和：

$$P(s) = \sum_{t\, :\, yield(t)=s} P(t)$$

### 三个问题（和 HMM 高度同构）

| 问题 | 问什么 | 算法 |
|------|--------|------|
| 概率 | 给定 PCFG，求 $P(s)$？ | **内向算法**（inside），动态规划 |
| 解码 | 给定 $s$，求概率最大的树 $t^*$？ | **CKY + 概率（维特比式）** |
| 学习 | 给定树库，估计规则概率？ | **数树里每条规则出现的次数**（树库监督下是闭式解） |

> 学习为什么这么简单？因为树库**已经标好了树**——直接数「$A \to \gamma$ 在树库里出现了几次 / $A$ 作为左部出现了几次」就是最大似然估计。这比 HMM 的 Baum-Welch（没有标签要 EM）简单得多。

## 5. CKY 算法：$O(n^3)$ 的句法解码

**CKY（Cocke–Kasami–Younger）** 是自底向上的动态规划，要求文法是 CNF。

### 核心数据结构：chart

定义 `chart[i][j]` 覆盖词 $w_i \dots w_{j-1}$（左闭右开，长度 $j-i$）的子串能归约出的**所有非终结符**。

- **宽度 1**（单个词）：填词法规则。如 `the` → `{Det}`。
- **宽度 ≥ 2**：枚举断点 $k$，把跨度 $[i,j]$ 切成 $[i,k]$ 和 $[k,j]$；若左半有 $B$、右半有 $C$，且文法里有 $A \to B\ C$，就把 $A$ 放进 `chart[i][j]`。

### 形式化

```
# 宽度 1
for i in 0..n-1:
    for (A -> wi) in 语法:  chart[i][i+1].add(A)

# 宽度 2..n
for 长度 l = 2..n:
  for 起点 i = 0..n-l:
    j = i + l
    for 断点 k = i+1..j-1:
        for 每条规则 A -> B C:
            if B in chart[i][k] and C in chart[k][j]:
                chart[i][j].add(A)
```

### 复杂度

- 三层循环（长度 × 起点 × 断点）= $O(n^3)$；
- 每次再查文法 $O(|R|)$，总共 **$O(n^3 \cdot |R|)$** 时间、**$O(n^2)$** 空间。

> $n^3$ 听起来吓人，但 $n=20$ 的句子只有 8000 个 cell，现代机器毫秒级。真正贵的是「合法树的数量指数爆炸」——见下一节。

### PCFG 下的 CKY：留最优 + 回溯

把 `chart[i][j]` 从「存非终结符集合」升级成「**存每个非终结符的最优子树及其概率**」，并对每个 $A$ 记一个**回溯指针**（最佳断点 + 两个孩子）：

$$\text{best}[i,j,A] = \max_{k,\, A\to B\,C}\ \text{best}[i,k,B] \cdot \text{best}[k,j,C] \cdot P(A \to B\,C \mid A)$$

最后从 `chart[0][n][S]` 顺着回溯指针重建出概率最大的整棵树。这就是「概率」给工程带来的收益：**不必枚举全部树，只留每个 cell 的最优子树**。

## 6. 词法化 CFG：Collins 句法分析器

朴素 PCFG 有个致命弱点——它**完全不看具体是哪个词**。规则 $VP \to VP\ PP$ 的概率对所有动词都一样，但现实中：

- `eat pizza with a fork`（用叉子吃披萨）→ 几乎一定是 **VP 附着**（with a fork 修饰吃）；
- `eat pizza with mushrooms`（带蘑菇的披萨）→ 几乎一定是 **NP 附着**（with mushrooms 修饰披萨）。

**结构完全相同，最佳附着方向却相反**，决定因素是 `fork` vs `mushrooms` 这两个词。纯 PCFG 看不出区别，所以在 PP 附着任务上准确率只有约 **70% 上下**。

**Collins（1999）词法化句法分析器** 的解法：给每个短语节点标一个**中心词（head）**——比如 $VP$ 的中心词是它的动词，$NP$ 的中心词是它的核心名词。于是规则带上词：

$$P(\text{VP}[head=saw] \to \text{VP}[head=saw]\ \text{PP}[head=with])$$

中心词怎么找？靠一套**中心词寻找规则（head-finding rules）**——例如「$VP$ 的中心词是它的第一个 $V$」，「$NP$ 的中心词是最后一个 $N$」。词法化后，模型能区分「saw ... with」和「eat ... with」，PP 附着准确率大幅提升。

> 同时期还有 **Klein & Manning 的 Berkeley parser**——走相反路线：**不词法化**，而是把非终结符切得更细（$NP \to NP\_SBJ$、$NP\_OBJ$），用更精细的类别来编码上下文。两种思路在 2000 年代是句法分析的顶流。今天都被神经方法取代了（见第 9 节）。

## 7. 中文句法分析的特殊性

中文没有英语那种显式**屈折变化**（时态、单复数、格），但层次结构依然存在，只是「标记」不同：

### 「的」是结构枢纽

中文里**「的」是名词短语的核心结构标记**。它把一个修饰语「焊」到一个名词上：

> 「戴帽子的」+「人」= `NP[ NP_mod 的 ] N_head`
>
> 我看见 [那个 [戴帽子的] 人]。

「的」前面的成分（无论多长多复杂）整体变成定语，挂到「的」后面的中心名词上。这让中文的 NP 嵌套很深、歧义也很常见：

> 「**研究**生命的起源」——是「研究 / 生命的起源」（动宾），还是「研究生命 / 的起源」（定中，"研究生命"是修饰语）？

### 没有显式形态 → 更依赖语序和虚词

英文靠介词、冠词、时态标记成分边界；中文靠**虚词**（的、地、得、把、被、了）和**语序**。所以中文成分分析里，虚词的地位远比英文突出——它们往往就是短语边界的「括号」。

> 实践中，**中文更适合用依存句法**（第 19 章）而非成分句法，因为依存直接刻画「哪个词修饰哪个词」，绕开了中文缺乏明确短语括号的麻烦。这也是 Universal Dependencies 中文树库（如 GSD、CTB）以依存为主的原因。

## 8. 代码跑通：一个能建树的 CKY

```bash
python3 experiments/18_cfg_cky.py
```

实验用纯 CNF 的微型 CFG（S/NP/VP/PP/N/V/Det/P/Pro），实现 CKY 枚举所有树 + PCFG 打分。三个确定性结论：

**① 无歧义句只有一棵树** —— `the cat sat on the mat`：CKY 返回恰好 **1** 棵树：
```
S
├─ NP
│  ├─ Det → "the"
│  └─ N → "cat"
└─ VP
   ├─ V → "sat"
   └─ PP
      ├─ P → "on"
      └─ NP
         ├─ Det → "the"
         └─ N → "mat"
```

**② 歧义句有两棵树** —— `I saw the man with the telescope`：CKY 返回 **2** 棵树（VP 附着 + NP 附着）。

**③ 【反直觉】PCFG 选了「错」的那棵，而且理由跟语义毫无关系**：
- 在我们的 PCFG 里，最优树是 **VP 附着**（我用望远镜看见了他），概率 `1.225e-3`；次优是 NP 附着，概率 `9.19e-4`。
- 两者概率比 = **`P(VP→VP PP) / P(NP→NP PP)` = 0.4/0.3 ≈ 1.333**——所有「词」的概率、PP 子树、`VP→V NP` 全部在比值里约掉了。
- 把这两条规则频率对调（VP 附着规则变弱、NP 附着规则变强），**同一句话、一个字不改**，最优解读立刻翻转为 NP 附着。

> 这就是纯 PCFG 的软肋：**附着决策只受规则统计频率驱动，完全不看词义**。真实的附着偏好是词法的（fork vs mushrooms 决定方向），这正是 Collins 词法化分析器要补的洞。

## 9. 局限与批判

1. **CFG 的覆盖永远不够。** 人工文法总有漏的句子（生成不足）和过度接受的烂句（过度生成）。树库统计文法缓解了，但长尾依然头疼。

2. **指数级歧义爆炸。** 一个 20 词的句子合法树可以有成千上万棵。PCFG + 维特比靠「只留最优子树」绕开了枚举，但前提是打分函数（概率）足够准——而纯 PCFG 不够准。

3. **符号方法的准确性天花板。** 最好的词汇化/精细类别 PCFG 在 PTB 上 F1 约 **90%**，卡了很多年。瓶颈是：规则无法编码真正的语义和世界知识。

4. **神经方法全面接管（2017 后）：**
   - **span-based neural parser**（Stern et al. 2017；Kitaev & Klein 2018）：用 Transformer/BERT 给每个「跨度 (span)」打分，再 CKY-style 解码。把 PTB F1 推到 **95%+**。
   - **Berkeley Neural Parser（benepar）**：spaCy 生态里的开箱即用成分分析器，多语言，底层就是上述 span parser + 预训练。
   - **LLM 隐式句法**：GPT/CLT 类模型不显式建树，但探针（probing）显示其内部表征已隐含层次结构。

5. **但 CFG 仍是 NLP 入门必学，原因有三：**
   - 它是**唯一能让你真正看清「语言有层次结构」**的框架；
   - CKY 是**动态规划 + 概率推理**的教科书级案例，思想迁移到语音（HMM/CTC）、对齐（IBM 模型）；
   - 神经 parser 的解码骨架**仍然是一个 CKY/跨度打分**——只是把规则概率换成了神经网络分数。

> 一句话：**显式成分分析在工程上接近退役，但「成分结构」这个概念永远不会退役。** 理解了它，你才能理解 Transformer 的注意力为什么会在某些层上学出类似句法头的模式。

## 10. 在 LLM 时代的地位

| 用途 | 现状 |
|------|------|
| 显式成分句法分析 | 工程上被 BERT-span parser（benepar）取代，研究上基本不做了 |
| 句法树作为下游特征 | RPA/IE/语义角色标注的早期管线已过时，端到端神经直接吃 token |
| CFG 作为形式语言理论 | 仍是编译原理、形式语言、计算理论的基石（乔姆斯基层级） |
| CKY 思想 | 仍活在所有「跨度打分 + 组合」的解码器里（包括 span parser） |
