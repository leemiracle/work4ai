## §0 全局视角：3 不变量 × 3 变量

整个后训练章节，可以压缩成下面这张表——这是"最高层视角的算法骨架"：

| | **不变量（贯穿所有阶段）** | **变量（每阶段在改什么）** |
|---|---|---|
| 1 | **Next-token prediction** 作为底层目标 | **信号源**：自监督→监督→偏好→自我生成（RL）|
| 2 | **softmax 概率分布** 作为输出 | **约束**：无→loss mask→KL 惩罚→长 CoT 内化 |
| 3 | **梯度下降 + cross-entropy** 作为优化器 | **计算时机**：训练时→推理时（test-time compute）|

### 算法经验 #1（最重要的元经验）

> **现代 LLM 的整个生命周期，底层优化器没换过（SGD/Adam），换的是"喂给它的信号"和"给它的约束"。**

这条经验可以推广到一切 ML 子领域：**你 90% 的设计空间在"信号"和"约束"上，而不是"优化器"上**。当你看到一个新 ML 方法，问自己两个问题：
1. 它在用**什么新信号**？（contrastive、preference、self-supervised、curriculum…）
2. 它加了**什么新约束**？（KL、L2、adversarial、causal mask…）

90% 的情况，答案就在这两点里。

### 后训练三阶段的本质

```
预训练 (Pretraining)  → 信号: 万亿 token, 无监督 (自监督 NLL)
                       约束: 无
                       能力: 语言流畅, 世界知识
                       
SFT (监督微调)        → 信号: 数万-数百万"指令-回答"对
                       约束: loss mask (只在回答上算 loss)
                       能力: 遵循指令, 对话格式
                       
偏好对齐 (DPO/PPO)    → 信号: 数万-数十万"好坏回答对"
                       约束: KL 散度惩罚 (防遗忘)
                       能力: 区分好坏, 符合人类偏好
                       
Test-Time Compute     → 信号: 不变 (模型已固定)
                       约束: 不变 (参数不变)
                       改变: 推理策略 (CoT/BoN/ToT/Long CoT)
                       能力: 用算力换质量
```

## §1 SFT：监督学习的根本约束

### 1.1 一句话直觉

> **SFT = 一个读过整个图书馆的人（预训练），现在被送进客服培训学校——虽然培训内容只是"看到这个问题应该这样回答"，但他突然就学会了"对话"。**

数学上就是标准的 next-token NLL，只在 response 部分计算：

$$\mathcal{L}_{\text{SFT}} = -\frac{1}{|y|}\sum_{t=1}^{|y|} \log p_\theta(y_t \mid x, y_{<t})$$

### 1.2 三条算法经验

#### 算法经验 #2：监督学习只能"模仿正例"，无对比信号

> **SFT 损失里根本没有 $y_l$（坏回答）——它数学上无法区分"好"和"坏"，只能让坏回答的概率附带变化。**

这是后续所有对齐方法（DPO/PPO/KTO）**必须**显式引入对比信号的根本原因。可迁移场景：推荐系统（pointwise loss vs pairwise loss）、imitation learning（专家数据只能教"做什么"，不教"什么更好"）。

#### 算法经验 #3：loss mask 是因果性边界，不是细节

> 只在 response token 上算 loss，意味着模型**不学习如何生成 prompt**——这避免了 prompt 分布漂移。

可迁移场景：seq2seq 翻译、instruct-tuning、任何"输入-输出"配对训练。看到 `ignore_index=-100` 或 `labels[mask] = -100`，要知道这不是工程便利，是**因果性约束**。

#### 算法经验 #4："反直觉先升后降"现象的条件

跑实验发现一个微妙现象——SFT 在 chosen 上 P 上升时，与 chosen 共享 token 的 rejected，其 P 也可能**先升后降**：

| 模型 | P(rejected) 行为 | 原因 |
|------|------------------|------|
| **unigram 模型**（我跑的 essence 版）| 一直下降（6.25%→5.94%）| 归一化压制 > 共享 token 抬升 |
| **真实 tiny GPT**（原实验）| 第一步先升 +62%，后下降 | 共享路径概率 > 归一化压制 |

> **算法经验**：**反直觉现象是否出现，取决于"共享路径概率提升" vs "归一化压制" 的相对强度**——这是个可定量诊断的现象，不是黑魔法。

可迁移场景：任何带 softmax 的多 token 序列模型。看到"SFT 后某个坏回答概率意外上升"，先查它和好回答共享多少 token。

## §2 偏好学习：算法美的三连击

DPO 是教科书级的"算法美"案例——它把三个经典数学物理套路合在一起。这是最值得"背下来"的部分。

### 2.1 套路一：Bradley-Terry（偏好→概率）

把"$y_w$ 比 $y_l$ 好"这个二元判断，变成一个可优化的概率：

$$P(y_w \succ y_l \mid x) = \sigma(r(x, y_w) - r(x, y_l))$$

**推导**：把分数差 $\delta = r_w - r_l$ 当 logit（log-odds），反解即得 sigmoid。

#### 算法经验 #5：Bradley-Terry 是"两两比较"问题的万能桥

> **任何"两两比较"问题都可以套 Bradley-Terry**——它和逻辑回归**同构**（把 reward 差当 logit）。

可迁移场景：
- **Elo 等级分**（国际象棋、电竞）
- **Chatbot Arena** LLM 排名
- **推荐系统 pairwise ranking**（BPR、RankNet）
- **A/B 测试**量化偏好强度
- **PageRank 变体**（边权来自比较）

记忆口诀：**看到"两两比较" → Bradley-Terry → sigmoid(reward 差) → 交叉熵损失**。

### 2.2 套路二：KL 约束极大化 → Gibbs 分布

RLHF 的目标是"最大化期望奖励，但不要偏离参考模型太远"：

$$\pi^* = \arg\max_{\pi_\theta} \mathbb{E}_{x, y \sim \pi_\theta}\left[r(x,y) - \beta \log \frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)}\right]$$

这个 KL 约束极大化问题有**闭式解**：

$$\pi^*(y|x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y|x) \exp\left(\frac{r(x,y)}{\beta}\right)$$

#### 算法经验 #6："KL 约束下的极大化" → 解永远是 Gibbs/玻尔兹曼分布

> 这是统计力学的灵魂，反复出现在：
> - **RLHF/PPO**：约束 policy 偏离 ref
> - **DPO 闭式解**：推导第一步
> - **最大熵 RL**（Soft Actor-Critic, Ziebart 2008）
> - **变分推断**（ELBO 推导）
> - **正则化感知机**

记忆口诀：**"加 KL 惩罚 → 解是 $e^{r/\beta}$ 加权归一化"**。

$\beta$ 是温度参数的拉格朗日对偶：β 大→分布接近 ref（保守），β 小→分布尖锐（激进）。

### 2.3 套路三：配分函数作差消去

把闭式解重排，用策略表示奖励：

$$r(x, y) = \beta \log \frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} + \beta \log Z(x)$$

代入 Bradley-Terry 时，$\beta \log Z(x)$ 在作差时**消去**：

$$r(x, y_w) - r(x, y_l) = \beta \log \frac{\pi^*(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi^*(y_l|x)}{\pi_{\text{ref}}(y_l|x)}$$

#### 算法经验 #7：任何含 $Z(x)$（配分函数）的式子，作差或求梯度时大概率能消去

> 这是 DPO 的"魔法时刻"，也是**变分推断、EM 算法、归一化流**反复用到的招式。

可迁移场景：看到 $Z = \sum_y \exp(\cdot)$（不可处理的求和/积分）别慌，**先尝试作差/求导**——大概率会消去。

## §3 DPO 完整推导：四步走，全部经典套路

DPO 论文优雅的根源：**全部用经典套路，没有任何新数学**。这是"识别 + 重组"，不是"发明"。

### Step 1：从 RL 目标到闭式解（套路二）

KL 约束极大化 → Gibbs 分布：

$$\pi^*(y|x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y|x) \exp\left(\frac{r(x,y)}{\beta}\right)$$

### Step 2：反解奖励函数（重排）

把闭式解重排，用策略表示奖励：

$$r(x, y) = \beta \log \frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} + \beta \log Z(x)$$

### Step 3：代入 Bradley-Terry，配分函数消去（套路三）

把 Step 2 的 reward 代入 $P(y_w \succ y_l) = \sigma(r_w - r_l)$：

$$P(y_w \succ y_l | x) = \sigma\left(\beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)$$

### Step 4：DPO 损失 = 负对数似然（套路一）

$$\boxed{\mathcal{L}_{\text{DPO}} = -\mathbb{E}_{(x, y_w, y_l)}\left[\log \sigma\left(\beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)\right]}$$

**没有奖励模型，没有 RL 采样，没有 PPO。** 只需要冻结的 $\pi_{\text{ref}}$ 和偏好数据 $(x, y_w, y_l)$。

### DPO 推导的"美感"复盘

| 步骤 | 用的套路 | 学到的方法论 |
|------|---------|-------------|
| 1 | KL 约束极大化 → Gibbs | 任何带 KL 约束的优化，先想闭式解 |
| 2 | 重排反解 | 把"被优化的变量"（reward）表达为"优化的产物"（policy）|
| 3 | BT 模型代入 + 配分函数消去 | 看到不可处理的 $Z$，先尝试作差 |
| 4 | NLL 损失 | 最后落到标准交叉熵，工具链全可用 |

## §4 DPO 的工程陷阱：β 不是单调的

原笔记表格说"β 大=保守，β 小=激进"。我用 essence 实验（剥离 transformer）跑出了**更细腻的非单调性**：

### 4.1 实验数据

| β | KL(final) | Entropy 残留% | P(chosen≻rej) |
|---|-----------|--------------|---------------|
| 0.05 | 0.03 | 98.3% | 0.51（基本没学）|
| 0.10 | 0.11 | 93.1% | 0.54 |
| 0.30 | 0.49 | 67.8% | 0.73 |
| 0.50 | 0.61 | 60.3% | 0.87（最优区）|
| 1.00 | 0.51 | 67.1% | 0.97（熵反弹）|

### 4.2 β 的三段式行为

#### 算法经验 #8：约束强度超参的三段式（欠/刚好/过）

> β 有三段式行为：
> - **β 太小**（<0.05）：梯度微弱，学不动，但 KL 几乎不变——**"过保守区"**
> - **β 中间**（0.3–0.5）：梯度强、KL 增长可控、熵开始塌——**"最优区"**
> - **β 太大**（>1.0）：约束过强反而抑制坍塌，但代价是更多步数——**"再保守区"**

这跟深度学习里**学习率的三段式**完全同构（欠/刚好/过）。

**经验迁移**：任何带"约束强度超参"的算法（KL、L2、dropout、temperature），都遵循类似三段式，工程上画"超参 vs 两个目标"曲线就能找最优。

### 4.3 β 不是单调的——更深的解读

为什么 β=1.0 的熵反而比 β=0.5 高？因为 β 大→梯度小→固定步数下没训到位→熵还没坍塌。这意味着**"β + 步数"是耦合的**：β 大需要更多步，β 小会更快坍塌。**调参不能只看 β，要看"β × lr × steps"组合**。

## §5 PPO 的 4 模型：算法角色的物理分解

原笔记点出 PPO 需要 4 个模型，但没解释**为什么必须 4 个**。补上算法角色分解：

| 模型 | 算法角色 | 删掉它会怎样 |
|------|---------|-------------|
| **Policy $\pi_\theta$** | 被优化的策略 | 没有训练对象 |
| **Reference $\pi_{\text{ref}}$** | KL 锚点（防遗忘） | reward hacking，模型输出退化 |
| **Reward $r_\phi$** | 偏好的代理 | 没有梯度信号 |
| **Value $V_\phi$** | 方差缩减（baseline） | RL 梯度方差爆炸，根本训不动 |

### 算法经验 #9：RL 的工程复杂性 = 4 角色物理分解

> **任何 on-policy RL 系统都至少要回答这 4 个角色由谁担任**——这是 RL 系统架构的 checklist：
> 1. 被优化对象是谁？（policy）
> 2. 怎么防止它崩坏？（anchor/reference）
> 3. 梯度信号从哪来？（reward）
> 4. 怎么降低梯度方差？（value/baseline）

可迁移场景：Actor-Critic（2 个模型）、Soft Actor-Critic（3 个）、PPO with RM（4 个）、GRPO（去掉 value，3 个）。

### DPO 怎么省到 2 个模型？

DPO 通过"重排闭式解"，把 reward 表达为 policy 的函数——**RM 被吸收进 policy**；同时 DPO 是 offline（从数据集采样而非 policy 采样），**不需要在线评估**——**value 函数也不需要**。省掉 2 个模型，代价是失去探索能力。

| | PPO | DPO |
|---|-----|-----|
| Policy | ✅ | ✅ |
| Reference | ✅ | ✅ |
| Reward Model | ✅ | ❌（被吸收进 policy）|
| Value Model | ✅ | ❌（offline 不需要）|
| 在线采样 | ✅（可探索）| ❌（无探索）|

## §6 Test-Time Compute：范式的范式转变

这一节是 Ch9 最深的概念跃迁。

### 6.1 范式对比

| | 传统 ML 范式 | 新范式（2024–）|
|---|-------------|---------------|
| 训练完→参数 | 固定 | 固定 |
| 推理 | 简单前向传播 | 可花更多算力换质量 |
| 能力上限 | 由训练决定 | 由训练 + 推理算力决定 |
| 代表 | GPT-3（2020）| o1（2024.09）、R1（2025.01）|

**这违反了"训练-推理二分法"**——是真正的范式转变。

### 6.2 三层 test-time compute（按"是否改参数"分）

| 层级 | 改参数？ | 方法 | 算法本质 |
|------|---------|------|---------|
| **L1 提示工程** | 否 | CoT、Few-shot | 改变输入分布 |
| **L2 推理时搜索** | 否 | Self-Consistency、Best-of-N、ToT | 采样 + 评估 + 选择 |
| **L3 RL 内化搜索** | **是（训练时）** | o1/R1 的 Long CoT | 把"搜索策略"压进参数 |

### 6.3 算法经验 #10：显式算法 → 参数蒸馏

> **L3 的本质是把搜索算法蒸馏进参数**。o1/R1 不是"推理时搜索"，而是"训练时让模型学会何时回溯、何时验证、何时换思路"——这些原本是搜索算法的逻辑，被 RL 奖励信号压进了权重。

**这是"算法 → 参数"蒸馏的一般范式**，可以推广到任何"显式算法 → 神经网络内化"的场景：
- 把符号推理压进 LLM
- 把 A* 搜索压进 GNN（learn to search）
- 把 dynamic programming 压进 neural simulator（如 AlphaFold）
- 把 RAG 检索压进参数（RAG → long-context → in-context learning）

### 6.4 Test-time compute 的 scaling law（Snell et al. 2024）

推理计算 vs 性能也遵循 power law，但最优点**依赖于任务难度**——简单任务少花算力够，难任务多花算力才够。这催生了**自适应 test-time compute**：模型自己决定思考多久。

## §7 用模型与分析模型的实战经验

### 7.1 诊断模型偏好（看 logprob）

如果你想分析一个模型"偏向什么"，看 logprob 比看输出更深刻：

```python
# 给模型同一个 prompt, 喂不同 response, 看 log P(response|prompt)
# 比较不同 response 的 logprob 排名 → 模型"暗中偏好"什么
```

> **算法经验**：模型的真实偏好不在生成里（采样随机性大），在 **logprob 排名**里。这就是 DPO 的核心操作（比较 log-ratio），也是 LLM-as-judge 的本质。

可迁移应用：
- 鉴别一个模型是否被某种价值观"过度对齐"——给敏感 prompt，看不同回答的 logprob 分布
- 比较 chat 模型 vs base 模型——chat 模型在"礼貌回答"上 logprob 系统性偏高
- 检测 reward hacking——chosen logprob 趋近 0，rejected logprob 趋近 $-\infty$

### 7.2 诊断对齐训练健康度（三件套）

训练 SFT/DPO 时**必监控**：

| 指标 | 健康范围 | 异常征兆 |
|------|---------|---------|
| **KL(π_θ \|\| π_ref)** | < 1.5 | > 2 → 严重漂移，通用能力丧失 |
| **Entropy** | 占初始熵 > 40% | < 30% → 多样性坍塌，输出重复 |
| **chosen-rejected logprob 差** | 平稳上升 | 趋近 ±∞ → 过拟合 |

### 7.3 CoT/BoN/ToT 决策树

```
任务需要多步推理?
├── 否 → 直接生成
└── 是 → 错误代价高?
        ├── 否 → CoT (1× 成本)
        └── 是 → 有奖励模型/评判器?
                ├── 是 → Best-of-N (N× 成本, log N 收益)
                └── 否 → Self-Consistency (N× 成本, 多数投票)
任务需要回溯/规划?
└── 是 → ToT (指数级成本) 或 直接用 o1/R1 类模型
```

### 7.4 识别 reward hacking 的征兆

| 征兆 | 检测方法 |
|------|---------|
| 输出长度单调增长 | 监控 train set 平均输出 token 数 |
| 输出过度礼貌、空洞 | 抽样人工评估 + 多样性指标 |
| chosen 概率趋近 1，rejected 趋近 0 | DPO loss 趋近 0 但泛化崩 |
| KL 在特定步数突然跳变 | 训练日志画 KL 曲线 |
| 测试集 reward 上升但人类评估下降 | reward over-optimization 的经典症状 |

## §8 批判性：DPO 的局限 + 2025–2026 前沿

### 8.1 DPO 之后的方法谱系

| 方法 | 与 DPO 的区别 | 解决什么问题 |
|------|--------------|-------------|
| **IPO** (Identity PO, Azar 2023) | 用平方损失替换 σ | 避免 DPO 对偏好差距过大的样本过拟合 |
| **KTO** (Kahn-Tversky Opt., Ethayarajh 2024) | 不需要成对数据，只要二元反馈（thumbs up/down）| 标注成本减半 |
| **SimPO** (Meng 2024) | 长度归一化 reward，去掉 ref 模型 | 省一个模型，更稳定 |
| **ORPO** (Hong 2024) | 把 SFT 和偏好融合成一步 | 省一个训练阶段 |
| **GRPO** (DeepSeek 2024) | PPO 变体，去掉 value 网络 | R1 的训练方法，省一个模型 |
| **NLPO / RLAIF / Constitutional AI** | 用 AI 反馈代替人类反馈 | 标注成本 → 推理成本 |

### 8.2 RLHF/PPO 仍有优势的场景

尽管 DPO 工程上更简单，但 RLHF/PPO 在以下场景仍不可替代：

1. **探索性**：PPO 在线从 $\pi_\theta$ 采样，可以发现模型从未生成过的高奖励回答。创造性任务（写作、代码生成）很重要。
2. **奖励信号及时性**：PPO 的 RM 可以随策略更新不断评估新回答，形成闭环。DPO 偏好数据是静态的。
3. **细粒度控制**：PPO 的 KL 惩罚可以在训练中动态调整，DPO 的 β 是固定的。

### 8.3 对齐的根本困难

**算法经验 #11（批判性元经验）**：

> **所有后训练方法的"成功"，本质是对人类偏好分布的拟合。但人类偏好：主观、文化相关、会漂移、可被操纵——所以对齐不是一次性的工程，是持续的运维。**

这是 OpenAI、Anthropic 投入大量人力做 RLHF 数据标注的根本原因。也是为什么：
- 同一个模型在不同文化下"对齐度"差异巨大
- 2015 年的"对齐"和 2025 年的不同
- 用户可以通过精心构造 prompt 操纵模型输出特定内容

可迁移：任何涉及"拟合人类判断"的 ML 系统（推荐、内容审核、自动评分），都有同样问题。

### 8.4 我对 2025–2026 的判断

- **Long CoT RL 是新主流**：DeepSeek R1、Qwen3、Kimi K2、GLM-Z1 都走 GRPO/PPO 路线训练推理能力
- **Test-time compute scaling law** 会成为新基准
- **DPO 系仍占工程主流**（简单稳定），但 GRPO 系在推理任务上反超
- **对齐数据质量 > 对齐算法选择**（数据决定上限，算法决定达到上限的速度）
- **AI feedback (RLAIF)** 在数据成本压力下逐渐替代部分人类标注
