# 04 · 文学理论转代码:把定义机器搬进机器

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:文学理论的谱系左端(03 章)几乎可以无损转码,
> 右端几乎不可转码;三条代码走廊——**叙事语法**(生成与检测)、
> **文体指纹**(归属与消融)、**诗性投影**(约束与等价)——把
> "不是所有排列都是故事""指纹在功能词""约束杀死随意性,等价类
> 保住意义"变成可跑、可断言、可做参数扫描的实验。

---

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",文学理论转代码要解决"**对象化**":
把一段理论语言("故事有固定的功能次序")先翻成模型(功能表+转移
矩阵),再翻成代码。翻译的损耗全部发生在第一步——所以本章先划清
哪些对象第一步就走得通(绿色区),哪些走不通(红色区),再给三条
走通了的走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 理论概念 | 代码化身 | 备注 |
|---------|---------|------|
| 功能序列/叙事语法 | 功能表+相邻转移矩阵;生成=走矩阵,检测=查表 O(L) | 走廊 1(实验幕一) |
| 作者归属(Delta 思想) | 高频词相对频率向量+余弦/距离判别 | 走廊 2(实验幕二) |
| 消融检验(指纹在哪) | 特征集删列后重跑判别,对比准确率 | 走廊 2 附带(幕二断言②) |
| 诗性约束(等价×组合) | 语义类×韵部约束系统+可行选项与偏差度量 | 走廊 3(实验幕三) |
| 文本量(type-token/密度/齐普夫) | 词表计数+统计量 | 02 章第二栏的直译 |
| 情感弧线 | 分段+情感值序列+原型聚类 | 01 章主线 B 的方法侧(方向锚) |
| 结构卡(三张) | 定长字段记录+完整性断言 | 03 章 §五 schema |

**转不动(红色区)**:

1. **文学性判定**:没有算法能判"是不是文学"——那是定义问题
   (01 章主线 A);能算的是**指纹与模式**,不是文学性的成色。
2. **细读的生产**:程序可以计数偏离,不能指出"这一处反讽为什么
   重于那一处"——细读的功夫在判断,判断不可外包(03 章右端)。
3. **审美价值排序**:"哪一版更好"不进实验台;价值论证归公共批评
   与哲学侧([美学](../../讲透哲学/讲透美学/README.md))。
4. **功能从真实文本的识别**:模拟可以指定转移矩阵,**从故事文本
   反标功能**是解释工作(谁受过训练、标注信度多少)——模拟不能
   冒充标注。

**边界的一句话**:绿色区=语法类+分布类+约束类,覆盖"结构直觉
的校准";红色区提醒:**转码是理论的使用说明书,不是理论的替身**
——词频能判谁写的,判不了写得配不配得上署名。

## 二、代码走廊清单(三条主走廊,每条=理论→模型→算法→真实系统)

### 走廊 1:叙事语法走廊(可讲性的全机械化)

```
普罗普功能命题 ──参数化──▶ 功能表+转移矩阵+锚定 ──▶ 生成/检测双通道
      │
      └──对照实验──▶ 合法故事数 vs 自由排列 ──▶ 约束压缩比断言
```

- **理论→模型**:功能表(≤10 条,固定次序);合法转移=次序递增;
  锚定约束=必在场功能集合。
- **算法层**:生成=按矩阵走子列;检测=逐对查表(等价于全局保序
  判定);枚举=子列空间 2^L(8 功能即 256,31 功能 2³¹——生成用
  走矩阵,别枚举)。
- **本家族实现**:[`experiments/narrative_stylistics.py`](experiments/narrative_stylistics.py)
  幕一——断言合法 64 ≪ 40320(压缩 630×),千个随机排列检出率 100%。
- **真实系统**:互动叙事/游戏任务链的**剧情合法性校验器**(任务
  前置图就是转移矩阵);剧本工坊的节拍表检查;教学侧的"故事语法"
  训练器。
- **性能工程要点**:**生成难、检验易**(枚举 2^L 指数,查表 O(L))
  ——这是约束满足问题的一般形状;校验器只需矩阵+锚集两个常量,
  天然适合做 CI 检查(剧情数据一改,断言即跑)。

### 走廊 2:文体指纹走廊(归属与消融)

```
Delta 思想 ──参数化──▶ 高频词剖面向量 ──判别──▶ 最近剖面归属
      │
      └──消融──▶ 删特征列重跑 ──▶ "指纹在哪"的断言
```

- **理论→模型**:作者=词频分布;归属=距离最近剖面;指纹的定位
  由**消融**(删列重跑)回答,不靠直觉。
- **算法层**:向量化+余弦;Delta 原版用 z 分数+曼哈顿,可平替;
  标准化要点是**等长文本**(TTR 的教训,02 章)。
- **本家族实现**:同实验幕二——断言全词表 100%≫随机 50%,删
  功能词跌至 64%(降 36 个百分点)。
- **真实系统**:代笔/剽窃鉴定(司法文书战线);AI 生成文本检测
  的原理与限度(同一指纹思路,但生成模型在模仿分布——军备竞赛);
  出版侧的佚名作品考据;多版本作品(《红楼梦》后四十回式)的
  定量比对。
- **性能工程要点**:特征集几百维即够,瓶颈在**语料工程**而非计算
  (对齐、等长、去题材污染);报告成绩必须带消融行(03 章指纹卡
  的机器执法)。

### 走廊 3:诗性投影走廊(约束与等价)

```
雅各布森投影公式 ──参数化──▶ 语义类×韵部约束系统 ──▶ 约束生成
      │
      └──三对照──▶ 自由诗/诗人/押韵机器 ──▶ 选项收窄×语义有界双断言
```

- **理论→模型**:词库带双索引(语义类,韵部);诗行=类约束(必)
  +韵约束(条件);可行选项数与语义偏差双指标。
- **算法层**:约束交搜索(类∩韵=拉丁方单点);偏差=对类中心的
  距离;熵=log₂(可行选项)。
- **本家族实现**:同实验幕三——断言选项 8.0→4.5(熵 3.0→1.5
  比特),诗人偏差 max 0.50≤半径 0.5,押韵机器偏差 10.4(≈36×)。
- **真实系统**:**生成式写作的约束解码**(押韵/字数/格律约束的
  词级或 token 级掩码——大模型的"约束解码"正是投影引擎的产业
  化);对联/歌词生成器;游戏文案的"语体合规"检查。
- **性能工程要点**:双指标缺一不可——只测"押上韵"(选项收窄)
  不测"仍在等价类"(语义偏差),得到的是打油机器;评测生成器
  时两行断言都要跑(幕三的教训)。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:文本取证面板——归属问题先消融

- 任何"这段文字是谁的"场景(代笔疑云/账号同一性/匿名举报溯源)
  先想走廊 2:建剖面→判别→**消融**(功能词删掉还剩多少判别力)。
  消融行是报告的信用锚:指纹若在内容词,多半是题材泄漏而非作者
  签名——结论立刻降级。

### 落点 2:生成式写作的约束工程——两行断言都要跑

- 给生成管线(模型或模板)加诗性约束时,照抄幕三的双指标:
  合规率(约束满足)+语义偏差(等价类保持)。只优化合规率的生成器
  会把"押韵的无关词"端上来;语义偏差的度量可用词向量做代理,
  但须声明代理性质(03 章暗礁)。

### 落点 3:叙事/任务系统的语法校验器——把剧情当代码 lint

- 游戏任务链、互动剧分支、课程学习路径,本质都是**带锚定约束的
  转移矩阵**;把"新手任务必须在 BOSS 战之前"写成锚定断言,进
  CI。走廊 1 的查表检测 O(L),万级节点毫无压力——剧情数据一改,
  断言即跑,再没有"玩家跳关直接拿终局道具"的事故。

### 落点 4:品牌语体管理——用指纹卡管住"编辑部声音"

- 品牌文案、客服话术、官方公告要"声音一致",这就是作者归属的
  反向使用:建立品牌剖面(高频词表),新文案算距离,偏离即预警;
  季度审一次剖面的漂移(声音悄悄变了没有)——指纹卡的季度体检。

### 落点 5:情感弧线面板——讲故事的数据侧监工

- 内容平台看"完播率/弃读点",可加一层弧线视图(01 章主线 B 的
  方向):长文的分段情绪轨迹是否有"钩子-沉底-回升"的形状;
  但记住判读要点 2:弧线是描述,不是意义的证明——面板提示**哪里
  可能有问题**,不裁决**作品好不好**。

   误导→转折→揭示),锚定=谜面先于揭示;断言压缩比,并给出最短

3. ✋ 把落点 3 写成 checklist:你的系统里哪些"顺序性规则"其实是
   转移矩阵(部署顺序/权限依赖/流程节点)?列出锚定约束各一条
4. ✋ 用落点 2 的双指标评测一个你用过的 AI 写作工具:给同一任务
   十次生成,手工判合规率与"打油率"(押上约束但语义跑偏的比例)

## 📌 收束 + 🧭 认知升维

本章给你的**新眼睛:双指标之眼**——看到任何"文学×计算"系统,
先问两件事:它测的约束(语法/指纹/韵律)是什么,它守的等价类
(意义/风格/语义)在哪;只测约束不守等价的系统是打油机器,只谈
等价拒绝测量的系统是印象批评。
