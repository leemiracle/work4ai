# 04 · 东欧文学转代码:把铁幕时滞、传抄网络与双市场搬进机器

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:东欧文学的谱系左端(03 章)几乎可以无损转码,
> 右端几乎不可转码;三条代码走廊——**铁幕时滞**、**传抄网络**、
> **双市场回归**——把"铁幕是玻璃做的""弱连接传播,强信任保命"
> "回家等的是离开前的自己"变成可跑、可断言、可做参数扫描的实验。

---

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",东欧文学转代码要解决"**流通代理
化**":把一段学科语言("流亡出版社更快""地下出版打不死")先翻成
模型(双通道分布/分簇图/两队列计数),再翻成代码。损耗全部发生在
第一步——所以本章先划清哪些对象第一步就走得通(绿色区),哪些走
不通(红色区),再给三条走通了的走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 学科概念 | 代码化身 | 备注 |
|---------|---------|------|
| 流亡通道的提速 | 双通道时滞分布,均值比断言 | 实验幕一全程纯标准库 |
| 审查的类型配额 | 源头/过审构成对比+总变差距离 | 幕一的选择偏差读数 |
| 地下出版的鲁棒性 | 簇结构图+节点移除+可达覆盖(BFS) | 幕二;穷举单点与随机压制 |
| 接触即风险的演化 | 生长模型+度数平方检出压力+对照网 | 幕二;小而密的结构读数 |
| 换语的双市场代价 | 两队列接受/回流计数,双向反差断言 | 幕三 |
| 回归错位 | 旧作重译热 vs 新作回流热+时点差 | 幕三;回归比断言 |
| 三张结构卡 | 定长字段记录+完整性断言(证据分账非空) | 03 章 schema 的机器执法 |

**转不动(红色区)**:

1. **"代言"的伦理重量**:代码能量通道时滞,量不了"作家该不该替
   民族说话"——这是规范问题,写进评分函数等于让一种文学政治冒充
   自然法则(00 章争 2 永远双录)。
2. **中欧认同的规范内涵**:命名政治不可数值化;"东欧 vs 中欧"的
   裁决权在论争,不在参数。
3. **审查与压制的史学判决**:审查机器的运行史本体归历史学宇宙
   (文字提及);机器只供通道与时滞的形状,不供判决书。
4. **通道份额/过审率/检出形式等骨架假设**:幕一幕二的全部关键参数
   都是通说观察的风格化——转码者必须把它们写在显式假设栏,重估
   会移动数值,锚形状不锚数值。

**边界的一句话**:绿色区=通道+网络+市场三引擎,覆盖"流通直觉的
校准";红色区提醒:**转码是文学社会学的试算器,不是东欧文学的
替身**。

## 二、代码走廊清单(三条主走廊,每条=理论→模型→算法→真实系统)

### 走廊 1:铁幕时滞走廊(译介时滞的双通道监测)

```
出版事件流 ──代理化──▶ {作品, 首版年, 首译年, 通道, 类型} 记录
      │                          │
      └──统计──▶ 通道均值比 + 类型构成总变差 ──▶ 玻璃海关读数
```

- **理论→模型**:02 章"samizdat/tamizdat 成对记"的参数化——通道
  标签(官方/流亡/地下)×方向(东→西/西→东)×类型配额。
- **算法层**:单条 O(1) 聚合;分布统计 O(N);实验幕一 1080 书种
  毫秒级。
- **本家族实现**:[`experiments/iron_curtain_pipeline.py`](experiments/iron_curtain_pipeline.py)
  幕一——断言流亡通道均值<官方 45%、敏感两类过审份额<源头一半、
  敏感类时滞>古典 1.8 倍、构成总变差>0.25。
- **真实系统**:小语种文学的**译介时滞监测**(当代版权贸易数据:
  一部作品获奖/成名后各语种跟进的年份差);出版选题的**通道行情**
  (流亡/侨社出版社 vs 主流社的选题-首译间隔);翻译史研究的**
  双通道对账表**(官方协定通道与民间通道分别立账)。
- **性能工程要点**:算力可忽略,**价值全在口径**——"首译"必须
  是首语种首版本(重译、再版、选本分列);口径一混,时滞均值就是
  伪影。与模型家族同一条铁律:底表不标准,输出只是自洽的伪精确。

### 走廊 2:传抄网络走廊(分簇网络的韧性与选择压力)

```
信任网络 ──代理化──▶ 簇结构图(环+弦簇×弱桥)+ 检出压力模型
      │                            │
      └──仿真──▶ SI 传抄步数 + 移除扫描(BFS 覆盖)+ 演化对照 ──▶ 韧性读数
```

- **理论→模型**:03 章引擎 2 的参数化——强信任簇(高聚集)+弱连接
  桥(传播);"接触即风险"=度数平方的检出压力(高压筛掉大枢纽)。
- **算法层**:BFS 覆盖 O(N+E);穷举单点移除 O(N×(N+E))——240 节点
  毫秒级;SI 仿真 O(步数×E);演化 30 轮 O(轮数×(N+E))。全程秒级
  (实验幕二)。
- **本家族实现**:同实验幕二——断言传抄步数≥6(慢)、穷举单点移除
  最低覆盖≥0.78(无单点故障;官方印厂归零)、随机压制 15% 平均
  ≥0.70、演化后最大度<对照 60% 且聚集系数>对照 2 倍(小而密)。
- **真实系统**:**抗审查网络设计**的分簇参照(P2P/DHT 的分区与
  samizdat 同构:牺牲速度换生存);组织保密设计的**单元化**
  (compartmentation:联络人制度=桥节点最小化,信任簇=单元);"被
  压制平台"的韧性评估(移除节点扫描=封禁演练)。
- **性能工程要点**:教学版的穷举单点移除是 O(N×(N+E)),**生产版
  换割点/桥检测算法(Tarjan 系)一次 O(N+E) 即得全部"端掉即断网"
  的节点**——幕二穷举是为了讲清机制,不是最优解;这是文学实验
  反哺工程直觉的直接一例。另外 SI 仿真对接触率参数敏感,断言须带
  结构带(≥6 步)而非点值。

### 走廊 3:双市场走廊(流亡作品组合的双市场对账)

```
作家×作品集 ──代理化──▶ {队列(换语/母语), 旧作×N, 新作×M, 禁期, 名声}
      │                                │
      └──计数──▶ 西方接受指数 + 回流率 + 回归比 + 时点差 ──▶ 回归错位读数
```

- **理论→模型**:03 章引擎 3 的参数化——换语=西方免译直达+母国
  回译变贵;旧作重译热=多通道基数+名声外溢+禁期加成。
- **算法层**:计数与均值 O(N);实验幕三 60 位作家毫秒级。
- **本家族实现**:同实验幕三——断言换语西方接受>母语队列 1.4 倍、
  换语回流率<母语队列 60%、旧作回归热>新作 2 倍且早 3 年以上。
- **真实系统**:国际出版的**重译窗口管理**(作家获加冕后,母语
  旧作的重译窗口先开、最大化窗口期);流散文学的**双市场组合**
  (侨民出版社与母国出版社的版权分账时序);文学代理的**回归
  预案**(政治变动后的"解禁书单"先于新作引进——幕三断言②的
  商业版)。
- **性能工程要点**:计算平凡,**口径在三处**:①"旧作"以离国前
  出版为准(流亡期秘密出版的母语作算哪边?预声明);②"回流"三
  口径(重译/重版/选本)分列不合并;③"热度"以版本数计,不接
  销量(销量数据各市场不可比)。口径三声明齐,对账才有意义。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:译介时滞监测——给小语种上"通道仪表盘"

- 任何多语内容系统(文档/开源/知识库)都可以记**首译时滞与通道
  标签**:官方流程 vs 社区志愿(=流亡通道的当代对应);幕一说志愿
  通道均值是官方的 28%——仪表盘上两类通道分开画,别平均,平均即
  失真(与德国家族"分版本不合并"同一条纪律)。

### 落点 2:韧性网络的分簇参照——速度换生存的算术

- 设计抗封锁/抗单点故障的分布式系统时,samizdat 是现成的**组织学
  参照**:高聚集簇+稀疏桥的网络牺牲覆盖速度(50 轮 vs 1 步)换
  无单点故障(最低覆盖 96.7% vs 印厂归零);"接触即风险"对应**
  曝露面最小化**——把 hub 的度数压下来,就是把每个节点的被端
  概率压下来(演化网最大度 11 vs 24)。

### 落点 3:回归窗口——解禁/获奖后的"旧我先回"预案

- 内容解禁、品牌回归、创始人复出的市场预案同理:受众市场先要**
  离开前的经典**(回归热 2.78 倍,早 3.6 年),新作是第二批货;
  把旧作的重制/重发排在新品前面,是幕三断言②的产品含义。

### 落点 4:骨架假设的显式化——参数即立场

- 三条走廊的全部关键参数(通道份额 0.42/过审率 0.85-0.03/检出
  压力 0.02)都写在代码头部常量区;**改参数=改历史观**,重估参数
  的敏感性扫描(✍️练习 1)是这类人文实验的"性能压测"。
