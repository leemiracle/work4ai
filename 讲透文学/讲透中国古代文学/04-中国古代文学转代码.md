# 04 · 中国古代文学转代码:把形式系统搬进机器

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:古典文学的谱系左端(03 章)是全部文学传统里
> **最接近形式语言**的部分,几乎可以无损转码;右端(意境/风骨)
> 几乎不可转码;三条代码走廊——**格律走廊**、**对仗走廊**、
> **文体兴替走廊**——把"四式谱可以推导""工对难得有组合学本体"
> ""一代之文学是错峰更替"变成可跑、可断言、可做参数扫描的实验。

---

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",古典文学转代码最大的优势是**形式
侧早已形式化**——平仄是二值标注,对仗是桶匹配,词牌是四元组查表:
诗人先于程序员一千年写好了 spec。翻译的损耗全部发生在**判定与
评价的分界**上——所以本章先划清哪些对象在判定层(绿色区),哪些
在评价层(红色区),再给三条走通了的走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 古典概念 | 代码化身 | 备注 |
|---------|---------|------|
| 四式标准谱 | 对+粘+韵句限定的确定性推导(状态机) | 家族实验律一,全程纯标准库 |
| 合律校验 | 输入平仄序列→逐句比对骨架+禁手检查 | 判定问题,可精确求解 |
| 变体额度计数 | 锁定位/自由位的组合计数+双枚举验证 | 律一断言 2:2^16 与 29952 |
| 对仗配对/瓶颈 | 词性分桶+乘积计数+敏感度分析 | 律二:161280 与颜色桶瓶颈 |
| 词牌查表 | 字数-句式-平仄-韵位四元组字典 | 龙榆生《唐宋词格律》的数据化 |
| 押韵判定 | 韵书(平水韵系)的韵部查表 | 注意古今音差异(02 §四) |
| 体裁生命周期 | 双 logistic 曲线+峰值/开关/重叠期扫描 | 律三:错峰/重叠/序列对齐 |
| 结构卡 | 定长字段记录+完整性断言 | 03 章 schema 的机器执法 |

**转不动(红色区)**:

1. **意境/风骨的判定**:无显式判据,法庭没有成文法——例诗参悟是
   共同体的集体操作。工程对策:退到可构造代理(意象密度/景语情语
   比例只做测量),不当分类器目标。
2. **"好诗"的最终裁断**:合律可判定,好诗不可判定(崔颢《黄鹤楼》
   违律而登唐人七律之冠的公案,通说)——用语法检查器当主编,是
   本领域最经典的越界事故。
3. **古音的今读判定**:平仄依中古音系;入声字(白/独/竹)今读平
   而实仄。工程对策:平水韵查表,不用拼音声调近似——这是格律
   校验器最容易翻车的单点(01 章主线 C 的 AI 格律讨论同病)。
4. **经典化的因果**:苏轼推尊陶渊明是接受史叙事,不可实验复现;
   数据只能给"重估前后的引用率曲线",给不了"为什么是他"。

**边界的一句话**:绿色区=谱类+桶类+曲线类,覆盖"形式侧的全部
判定";红色区提醒:**转码是古典文学的使用说明书,不是文学的
替身**——左端越硬,越要记得右端才是这些约束服务的目的。

## 二、代码走廊清单(三条主走廊,每条=直觉→模型→算法→真实系统)

### 走廊 1:格律走廊(四式谱推导与合律校验的全机械化)

```
「律诗平仄有谱」常识 ──形式化──▶ 句式状态+对粘映射 ──推导──▶ 四式谱(与通行谱对照)
      │
      └──层叠──▶ 自由位计数 ─×细律禁手─▶ 变体额度 ──枚举──▶ 计数=枚举断言
```

- **直觉→模型**:四句式为状态空间;"对"=偶位取反的映射,"粘"=
  偶位保持的映射;四式=四种初值轨道,无搜索无回溯。
- **算法层**:推导 O(8);合律校验 O(n)(n=字数);变体计数 O(1)
  乘法+O(2^5·8) 逐句枚举+O(2^10) 联级全枚举。
- **本家族实现**:[`experiments/meter_parallel_genres.py`](experiments/meter_parallel_genres.py)
  律一——断言四式与王力《诗词格律》通行谱相符、两两不同;每式
  2^16 变体;细律后 262144→29952。
- **真实系统**:诗词创作 App 的格律校验器(输入诗句→标注平仄→
  对谱+禁手诊断+拗救建议);语文教学的格律可视化(把"对/粘"画
  成传播链);古籍库的律诗自动标谱与统计(某诗人用式偏好)。
- **性能工程要点**:推导与校验是 O(n) 便宜货,瓶颈全在**平仄标注**
  ——多音字(如"看/望/听"平仄两读)需词表消歧,查表优先于模型;
  若用统计标注,把"合律"断言降级为"疑似"输出,**判定器不许
  悄悄变成概率器**。韵部查表注意平水韵与词韵(词林正韵)是两套表。

### 走廊 2:对仗走廊(配对组合与瓶颈分析)

```
「工对难得」感叹 ──形式化──▶ 词性分桶+逐位取词 ──计数──▶ 合格数=∏桶宽
      │
      └──归因──▶ 敏感度=总数/桶宽 ──排序──▶ 瓶颈位=最窄桶 ──验证──▶ 全枚举
```

- **直觉→模型**:对仗的平行约束=各位独立选择;合格数=乘积;窄桶
  是产能上限(实验律二:161280;避重字层 99099;颜色桶 8 词为瓶颈,
  +1 词增益 20160 全场最大)。
- **算法层**:乘积计数 O(k);全枚举 O(∏桶宽)(16 万级,纯 Python
  秒级);敏感度排序 O(k)。
- **本家族实现**:同实验律二。
- **真实系统**:对联生成器的组合爆炸治理(逐位桶+束搜索,瓶颈位
  先行剪枝);对课教学 App 的"库存体检"(给小类词表查缺,颜色/
  数量类最薄);AI 辅助写作的"对仗建议"按瓶颈位优先补词。
- **性能工程要点**:全枚举只做验证,生产系统用乘积计数+采样;
  **词性桶与平仄约束正交**(律一与律二可复合:先词性后平仄过滤,
  或联合剪枝),复合后合格率骤降,束宽度要按瓶颈桶重新标定;
  桶的粒度(宽对/工对)是产品决策,不是技术决策——先问用户要
  工对还是宽对,再选桶。

### 走廊 3:文体兴替走廊(生命周期建模与换代监控)

```
「一代有一代之文学」命题 ──形式化──▶ 双 logistic 生命周期 ──扫描──▶ 峰值/开关/重叠期
      │
      └──检验──▶ 序列对齐 + 开关∈两峰之间 + 重叠期含跨界者 ──▶ 错峰更替断言
```

- **直觉→模型**:体裁强度=上升 logistic×下降 logistic;主导体裁=
  逐年 argmax;换代=开关点;跨界文人=重叠期的定位点(律三:峰值
  761/1139/1336/1693,开关 982/1285/1455,苏轼 1080/白朴 1280 落
  重叠期)。
- **算法层**:逐年扫描 O(T·G)(T=1451,G=4,毫秒级);峰值与重叠
  窗数值求解,断言只锚结构性质(序列/包含/间隔),不锚幅度。
- **本家族实现**:同实验律三。
- **真实系统**:内容平台的**品类生命周期监控**(网文品类/短视频
  形态的兴起-鼎盛-衰落曲线,峰值错峰检测,新旧的"重叠期运营");
  出版选题的体裁周期参考;数字人文的文学史份额曲线(律三的实证
  还债版,01 章主线 B 的数据)。
- **性能工程要点**:双 logistic 是三参数玩具,生产侧直接换成分箱
  产量统计+滑动平滑;**断言结构性质而非绝对年份**的纪律要带进
  生产——监控的报警语义应是"峰值易位/重叠期闭合",不是具体
  年份;反事实分析(改参数看序列稳定性)比点估计更有用。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:格律校验器——判定器与概率器分层

给诗词工具做校验:平仄标注层(查表+多音字消歧,允许"疑似"输出)
与合律判定层(纯规则,确定输出)**必须分层**——把标注的不确定性
透传给判定层,是这类产品最大的可信度事故;禁手诊断(孤平/三平调/
失对/失粘)与拗救建议是规则层的自然延伸,全程可 assert。

### 落点 2:对联/对仗系统的瓶颈先行

生成对仗内容时,先扫描桶宽,把**最窄的词性桶**提到前置约束
(实验律二的直接工程化):瓶颈位先选词,宽桶后填——组合爆炸在
源头剪掉;同时给内容团队输出"库存报告"(哪个小类词表最薄),
补词表比调算法有效。

### 落点 3:品类生命周期的错峰监控

运营多品类内容平台时,用律三的框架看品类曲线:相邻品类的**峰值
间隔**(是不是同步开关?同步说明互相倾轧,错峰说明生态位分工)、
**重叠期长度**(重叠期是跨品类创作者的窗口,重度运营价值区)、
**换代开关位置**(落在两峰之间才健康,开关贴着峰值说明旧品类
非正常死亡)。把"一代之文学"从文学史命题变成增长仪表盘。

### 落点 4:古籍库的结构化质检

古籍数字化项目中,把 03 章三卡 schema 作为元数据规范:律诗标
"式+韵部",词标"词牌+四元组核对结果",叙事标"体例要件"——
完整性可程序校验(牌名与字数不符自动挂账),**结构化质检比全文
OCR 的后处理便宜一个量级**。

## ✍️ 练习

1. 🐍 给走廊 1 加"三仄尾"禁手(句脚三连仄,通说视为小拗不禁,
   这里做实验):预测四式合计从 29952 收缩多少,改代码验证——
   你会发现 C 式句被砍,平起两式收缩更重;解释为什么
2. 🐍 给走廊 2 的桶宽做扫描:把颜色桶从 6 逐词加到 12,画出总数
   曲线——验证增益=总数/桶宽的线性关系,并标出它何时不再是
   瓶颈(被哪个桶接棒)
3. ✋ 把你团队的产品品类写成律三框架:各品类的"峰值年"是哪年?
   现在处于重叠期还是换代后?写出"重叠期运营"的三条具体动作
4. ✋ 用落点 1 的分层原则体检一个你用的写作辅助工具:它的"判定"
   (说你不合律/不通顺)背后是规则还是模型?它声明了吗?

## 📌 收束 + 🧭 认知升维

合格"类断言,先问它在判定层还是评价层(规则可 assert,品味不可);
看到任何生成/匹配系统,先找最窄的那只桶(产能上限住在那里)。
转码让这两问从修辞变成可跑的断言。
