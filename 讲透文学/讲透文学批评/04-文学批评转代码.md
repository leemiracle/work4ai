# 04 · 文学批评转代码:把打分表搬进机器

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:文学批评的谱系左端(03 章)几乎可以无损转码,
> 右端几乎不可转码;三条代码走廊——**情感弧线走廊**、**检出力走廊**、
> **范式排名走廊**——把"叙事有六种心跳""尺度即方法""框架即打分表"
> 变成可跑、可断言、可做参数扫描的实验。

---

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",文学批评转代码要解决"**测量化**":
把一段批评直觉("故事的形状就那么几种")先翻成模型(漂移模板+
噪声+聚类),再翻成代码。翻译的损耗全部发生在第一步——所以本章
先划清哪些对象第一步就走得通(绿色区),哪些走不通(红色区),
再给三条走通了的走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 批评概念 | 代码化身 | 备注 |
|---------|---------|------|
| 情感弧线/六型 | 漂移模板+噪声生成;z 标准化+k-means+留出集识别 | 家族实验幕一,全程纯标准库 |
| 形状的次序依赖 | 段落打乱(多重集不变)→识别率对照 | 幕一断言 2 的最小化身 |
| 主题检出/远读功效 | 词袋+背景率+2σ 阈值;样本量扫描 | 幕二;功效曲线随 √T 爬坡 |
| 细读 vs 远读分工 | 同篇数深读/浅读对照,分信号强度 | 幕二(2) |
| 框架=打分表 | 特征×权重表+线性打分+噪声 | 幕三 |
| 排名反转 | Spearman ρ+反转集合+维度偏置归因 | 幕三 |
| 框架卡/论证链卡 | 定长字段记录+完整性断言 | 03 章 schema 的机器执法 |

**转不动(红色区)**:

1. **阐释的有效性**:赫什的"含义"以不在场的作者意图为法庭——
   重建程序的被告缺席。工程对策:退到论辩与细读(03 章右端),
   不当分类器目标。
2. **审美价值的最终裁断**:代码能列全部证据(半构造),不能合成
   权重做终审——"好在哪"的最后一公里永远回到判断者。
3. **情感测量本身的文化校准**:实验里弧线是**指定**的模板;现实里
   要用词典/模型测,测量偏差(讽刺反分/文化偏差)是测量侧的账单,
   模拟不能冒充测量。
4. **框架特征清单的发明**:代码能算"两框架的权重差",不能决定
   "该有哪些列"——列的开立是框架的政治(00 §五),人的地界。

**边界的一句话**:绿色区=弧线类+信号类+表格类,覆盖"批评直觉的
形式校准";红色区提醒:**转码是批评的使用说明书,不是批评的替身**。

## 二、代码走廊清单(三条主走廊,每条=直觉→模型→算法→真实系统)

### 走廊 1:情感弧线走廊(叙事形状的全机械化)

```
批评直觉「故事就那么几种」 ──参数化──▶ 漂移模板+噪声 ──z标准化+k-means──▶ 六型+留出集识别
      │
      └──对照──▶ 段落打乱(多重集不变)──▶ 识别率=随机 ──▶ 「形状住在次序里」断言
```

- **直觉→模型**:弧线=初始值+分段漂移+逐段噪声;六型=漂移组合的
  六个参数化;z 标准化抹去电平幅度,只留形状。
- **算法层**:k-means++ 初始化+十次重启取惯量最小(局部最优的工程
  对策);留出集最近质心识别;打乱=同多重集的随机重排。
- **本家族实现**:[`experiments/arcs_paradigms.py`](experiments/arcs_paradigms.py)
  幕一——断言六纯簇双射、留出集 24/24、打乱后 16.67%(恰=1/6)。
- **真实系统**:连载内容的节奏监控(网文/剧集的弃读点预警)、
  叙事生成的弧线约束、阅读推荐的"形状口味"特征。
- **性能工程要点**:k-means 每轮 O(n·k·d)(n=弧数,k=6,d=60);
  距离计算用平方距离免开方;z 标准化 O(n·d) 一次预付。弧线数上万时
  先降维(取分段均值或 PCA 到 10 维)再聚类,惯量断言只锚簇纯度与
  留出集,不锚浮点尾数。

### 走廊 2:检出力走廊(细读/远读之争的统计化身)

```
「远读有理」口号 ──参数化──▶ 词袋+背景率+2σ阈值 ──扫描──▶ 检出率(n) 功效曲线
      │
      └──对照──▶ 同篇数深读/浅读 × 信号强度 ──▶ 分工断言(强信号深读胜,弱信号唯规模)
```

- **直觉→模型**:主题=标记词率的小幅抬升(θ=p0+δ);检出=标记数
  ≥期望+2σ;细读=单篇全读(200 词),远读=多篇浅读(15 词/篇)。
- **算法层**:蒙特卡洛功效估计(每档 1000 次);扫描 n∈{5,20,80,320}。
- **本家族实现**:同实验幕二——断言弱信号检出率 0.158→0.952 严格
  单调升;强信号同 3 篇细读 1.000 vs 浅读 0.728;弱信号细读 0.343
  漏检、唯规模可救。
- **真实系统**:语料主题普查前的**样本量预计算**(要检出多弱的
  信号,至少要多少篇?功效曲线反着读);内容平台"新题材发现"的
  报警阈值设计。
- **性能工程要点**:功效估计天然可并行(每档独立;按档分流种子
  保证可复现);大 T 时逐词伯努利 O(T·trials) 可换成二项抽样或
  正态近似(注明近似);断言锚单调性与端点,不锚中间档的尾数。

### 走廊 3:范式排名走廊(框架之争的算术化身)

```
「范式即打分表」命题 ──参数化──▶ 特征×权重表+线性打分+噪声 ──▶ 两框架排名
      │
      └──归因──▶ Spearman ρ + 反转集合 + 维度偏置 ──▶ 反事实(抹平争议列)──▶ 趋同断言
```

- **直觉→模型**:作品=特征向量;框架=权重表;名次=加权投影;
  评估噪声=框架内部的小幅摇摆。
- **算法层**:Spearman(排名的 Pearson);反转集合=一边前十且另一边
  后半;偏置=反转组在各维度上的极端度差;反事实=争议维度权重对齐
  后重排(噪声复用,公平对照)。
- **本家族实现**:同实验幕三——断言 ρ=0.163 可低、反转 10 部、偏置
  0.842 集中于权重差最大维度、抹平后 ρ 升至 0.686。
- **真实系统**:多视角榜单系统(同一批内容按不同打分表各出一份
  排名,差异可解释为权重差——范式透明化);评论社区"框架标签"
  的排序消偏。
- **性能工程要点**:60 作品×4 维是玩具规模;十万内容×百维时,排名
  O(N log N) 为主,权重扫描可向量化;反事实重排**必须复用噪声**,
  否则趋同信号会被噪声差淹没(实验的公平性设计)。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:连载内容的节奏监控——盯弧线,别盯均值

给连载/剧集运营配两个指标层:**情感均值层**(每章平均情绪——
管理层爱看)加**弧线层**(次序敏感的形状分类:现在是哪种型?
切换点是否拖了 5 章太久?)。幕一的教训:**只看均值层的面板
看不见形状**——两条均值完全相同的连载,一条是"灰姑娘变体"
(先抑后扬再抑再扬),一条是打乱的噪声,读者留存天差地别。

### 落点 2:新题材发现的样本量预计算

"语料里有没有一个占比很小的主题"是功效问题(幕二):先估背景率
与目标检出强度,反查功效曲线定样本量,再开工爬数据。**没有功效
设计的"没发现"只是没测到**——把这句话写进数据需求的模板里。

### 落点 3:榜单的范式透明化

推荐/榜单系统隐式使用一张打分表(哪些特征开多少权重);把它显式
化并提供多张表(对应不同"批评框架"),用户可切换——幕三说明差异
不是噪声,是结构性的(ρ 可低至 0.16)。**榜单差异的可解释性=权重
的透明度**,这比调参更接近问题本体。

### 落点 4:评论文证的质量校验

内容平台若存评论/书评资产,按 03 章三卡 schema 结构化:论证链卡的
"文本证据"字段非空(评论必须引用原文行号),完整性可程序校验——
**没有证据链接判断,等于打分表没有列**;聚合可查(哪类框架是社区
默认框架?它给什么记零分?)。
