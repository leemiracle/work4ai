# 04 · 中国少数民族文学转代码:把多语传统搬进机器

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:少数民族文学的谱系左端(03 章)几乎可以无损转码,
> 右端几乎不可转码;三条代码走廊——**演述变异性**、**语言选择
> 动力学**、**版本合并**——把"活态史诗不是文本是事件""全漂与
> 全留都不是均衡""整理即选择"变成可跑、可断言、可做参数扫描的
> 实验;而音像档案时代(01 章主线 A)让走廊 1 第一次有了全量数据
> 的可能,多语言产品时代让走廊 2 有了工业对照系。

---

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",少数民族文学转代码要解决"**无定本
对象的形式化**":把一段学科语言("同一艺人两晚唱得不一样")先翻成
模型(功能单元×个人扩容×当晚状态),再翻成代码。翻译的损耗全部
发生在第一步的**裁定**里(单元怎么切、份额按什么口径、收益怎么
参数化)——所以本章先划清哪些对象的裁定已经结算清楚(绿色区),
哪些永远结算不清(红色区),再给三条结算清楚的走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 学科概念 | 代码化身 | 备注 |
|---------|---------|------|
| 演述记录(场次档案) | 场次×艺人×单元集×行数的清单;组内/组间分层 | 幕一全程纯标准库;音像档案时代可实证取数(01 章主线 A) |
| 变异分解 | 同艺人内部 vs 艺人之间的长度差/tau/Jaccard 对照 | 16.6% vs 28.8% 类断言 |
| 序列骨架 | 功能序列的 Kendall tau;核心单元出场率 | 骨架/血肉分层的两个量 |
| 语言选择 | p(L2)=σ(γ·log(u2/u1)+κ) 的逐年模拟;配对臂 | 幕二;漂移/均衡/混写全可断言 |
| 双语份额面板 | 作家×年份×语言的作品矩阵;份额轨迹统计 | 均衡模型的现实输入(代表作级) |
| 异文分布 | 单元集的三档出现率;两两 Jaccard 距离矩阵 | 幕三;"无真本"的判据化 |
| 版本合并 | 四候选(并集/交集/多数/medoid)的长度/覆盖/距离 | 长度-完整性两难的 Pareto 声明 |
| 三张结构卡(03 章) | 定长字段记录(dict)+完整性断言 | 元走廊的元数据工程 |

**转不动(红色区)**:

1. **"民族性"与民族审美**:意象词频量得出指纹,量不出"民族性"
   ——"量得出收录,量不出认同"。工程对策:退到细读与语境
   (03 章右端),不当目标函数。
2. **艺人记忆机制**:幕一给出统计边界(骨架固定+填充自由),
   不给心理学解释("神授"等现象按 02 章§三登记为待解释——
   模拟不能冒充认知科学)。
3. **整理立场的正当性**:幕三能算出每种立场的代价,但"该选哪种"
   是学术伦理与行政需要的裁定——**转码是裁定的使用说明书,
   不是裁定的替身**。
4. **跨境传统的归属叙述**:共享经典的"共有书写"是史学与外交的
   论证,不进实验台;实验只在给定归属口径下量结构。

**边界的一句话**:绿色区=档案类+份额类+分布类,覆盖"活态传统
的变异结构、多语格局的力学、整理的代价结构";红色区提醒:
**传统算得出结构,认同读得出意义**——两套设备各干各的活。

## 二、代码走廊清单(三条主走廊,每条=理论→模型→算法→真实系统)

### 走廊 1:演述变异性走廊(骨架-血肉的分层计量)

```
"活态史诗不是文本是事件" ──参数化──▶ 功能单元×个人参数×当晚状态
      │                                      │
      └──检验──▶ 组内/组间对照(长度差/tau/Jaccard) ──▶ 断言
```

- **理论→模型**:一部=核心单元(骨架,公共)+可选单元(艺人库);
  艺人带个人扩容量(乘性)/可选单元库/个人章节块顺序;每晚带状态
  因子与逐单元抖动。
- **算法层**:分层配对统计——同艺人两两(组内)vs 跨艺人两两
  (组间),各算长度差分布、单元集 Jaccard、序列 tau;断言组内
  长度差落 10-30% 量级且 tau≥0.95、组间三者全面更大差异。
- **本家族实现**:[`experiments/epic_bilingual.py`](experiments/epic_bilingual.py)
  幕一——实测同艺人 16.6%/tau 1.00/核心 100%,艺人之间 28.8%
  (1.73 倍)/tau 0.829/Jaccard 0.789。
- **真实系统**:音像档案的**演述对照流水线**(逐场转写对齐→
  单元切分→变异分解——数字人文的现成工程,01 章主线 A 的 04 化);
  更广:直播/演出内容的"场次结构分析"(同一 IP 多场次的骨架一致率,
  落点 1)。
- **性能工程要点**:配对统计是 O(P²)(P=场次数),档案级十万场
  时先按艺人分桶、组内精确算、组间抽样估;tau 计算用位次表
  (pos 数组)避免 list.index 的 O(n²);断言只锚量级与比值,
  不锚尾数。

### 走廊 2:语言选择动力学走廊(两种力的均衡模拟)

```
"全漂与全留都不是均衡" ──参数化──▶ p(L2)=σ(γ·log(u₂/u₁)+κ)
      │                                   │
      └──配对臂──▶ 全漂臂(q≡1)/全留臂(q≡0) ──▶ 均衡断言
```

- **理论→模型**:作家带题材结构 q(可迁移份额)、收益敏感 γ、母语
  依恋 κ;可迁移题材按收益=读者规模×表达保真选语言;母语不可译
  题材恒母语;读者比与双语保真随时间爬升后停表。
- **算法层**:逐年作品抽签;三臂共享作家池(配对设计);统计群体
  份额轨迹、个体漂移方向、末期混写率、停表后的平稳性。
- **本家族实现**:同实验幕二——实测漂移 +14.4 个百分点(个体为正
  67%),主臂终局 56.9% 严格介于全留 0% 与全漂 92.3% 之间,
  末期混写 98%,停表后 3 年变动 2.2%。
- **真实系统**:**多语言产品与内容市场的语种策略**(什么内容做
  多语、什么内容锚定源语言——读者规模×表达保真是同一个公式,
  落点 2);跨语言社区的创作者语言选择(维基/开源文档的语种分布)。
- **性能工程要点**:作家×年份双重循环天然可并行(作家间独立,
  按作家号分流 seed);配对臂必须共享作家参数(变异减半,同
  现代文学家族幕二的设计);log(u2/u1) 拆成 log 项之和可逐项
  解释(读者比/保真度各贡献多少,是参数扫描的输出而不是重新建模)。

### 走廊 3:版本合并走廊(分布的度量与候选比较)

```
"整理即选择" ──参数化──▶ 异文=单元集分布;候选=并/交/多数/medoid
      │                                    │
      └──检验──▶ 距离矩阵 + 长度/覆盖 Pareto ──▶ 两难断言
```

- **理论→模型**:异文按三档出现率独立采样(分布本体);四种规范本
  候选;度量=两两 Jaccard 距离、长度比、记录内容覆盖(按诸本见证
  加权)。
- **算法层**:距离矩阵 O(N²)(N=异文数,天然小);覆盖率的加权
  分母固定(全部见证行数);"无真本"判据=每份异文的最大距离下界
  +medoid 平均距离下界。
- **本家族实现**:同实验幕三——实测两两距离中位 0.36、最优异文
  0.319;并集 1.50 倍/覆盖 100%、交集 0.44 倍/覆盖 44.3%、多数本
  距离最小(0.259)但删削每份近两成(最少 12%)。
- **真实系统**:**多源记录合并为"权威版本"的一切工程**——多方言
  音频转写结果的合并、多来源需求文档的"定稿"、多次会议纪要的
  单一事实源、众包标注的多答案归一(落点 3);社区知识库(维基类)
  的编辑历史即"异文分布",条目页面即每日重算的"多数本"。
- **性能工程要点**:候选比较是纯集合运算,frozenset 交并 O(平均);
  "见证加权覆盖"的权重(出现次数)要随分布一起存,别只存集合
  ——丢权重的覆盖率会把稀有真实内容算成噪音(幕三读数的工程版)。

### 元走廊:结构卡校验器(03 章三卡的机器执法)

三张卡各成一类记录;完整性断言:史诗艺人卡的**演述记录栏**必须
区分"多次采录/单场采录"(单场=变异不可分解,幕一前置条件不满足,
卡片自动降级);多语作家卡的**语言标注**非空(族别≠语言,02 章
§三纪律 2 的机器化);翻译链卡的**每一环要么有中介语要么显式
"不可考"**(缺证据与没查过是两个字段)。价值不在计算量,在纪律
(留作 ✍️练习 1)。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:现场内容的事件性审计

直播、演出、播客的同一 IP 多场次内容,问幕一的两个数:**骨架
一致率**(流程/环节结构的 tau)与**血肉波动**(时长/密度的组内
变异)。骨架不一致=IP 失控(观众认知分裂);血肉零波动=演述僵化
(复读机效应)。健康的现场 IP 应该长成活态史诗:**骨架是团队的,
血肉是当晚的**。

### 落点 2:多语言产品的语种策略

给任何多语产品(文档/内容/社区)配一次幕二体检:目标用户的语种
规模比是多少?哪些"内容资产"是**不可迁移的**(只能源语言承载的
梗、术语、韵律)?前者决定默认语种的漂移压力,后者决定必须保留的
多语投入。结论先行:**全单语与全多语都不是均衡**——把不可迁移
资产清单做实,其余按市场规模走。

### 落点 3:多源记录的合并治理

一切"多来源→一份权威版"的工程(转写合并/需求定稿/标注归一/
会议纪要),先跑幕三的四候选:并集(全保,膨胀没人读过)、交集
(只留共识,一半真实内容蒸发)、多数(可读但删削每份来源一成上下)、
medoid(挑一份"最典型"原样用)。工程默认值多是多数本——**把
幕三的删削率(本家族实测近两成)写进合并报告的 known issues,
就是"整理即选择"的工程声明**。

### 落点 4:专家演示的活态档案

老师傅/资深工程师的多次演示(同一操作的多次录屏/带教)就是活态
演述:骨架(步骤序列)高度一致,血肉(节奏/取舍/分支处理)随场
波动。知识管理别犯"定本错误"——把某一次演示定成 SOP 全文,等于
把一次演述当传统;正确做法:登记**分布**(多次演示的骨架一致率
+变异点),SOP 只写骨架,变异点写进"老师傅的判断"附录(幕一
的 KB 版)。

## 📌 收束 + 🧭 认知升维

本章给你的**新眼睛:档案之眼**——看到任何"现场/多源/多语"的
内容系统,先问三件事:骨架一致率多少(事件的结构层)、两种力的
均衡在哪(语种/来源的策略层)、合并用了哪种候选且声明了删削率
(版本的治理层)。转码让这三问从修辞变成可跑的断言;而红色区的
边界同样有用:**结构算得出,认同读出来**——两套设备各干各的活。
