# 04 · 英国文学转代码:把一座正典搬进机器

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:英国文学谱系的左端(03 章)几乎可以无损转码,
> 右端几乎不可转码;三条代码走廊——**Heaps 词汇画像**(词汇增长律
> 的拟合与外推)、**正典席位**(优先连接+范式转移的席位动力学)、
> **语言混合**(混合率梯度与接受区间)——把"莎翁词表是幂律段位"
> "顶尖席位几乎不动,范式转移只换中游""混合英语有最优区间"变成
> 可跑、可断言、可做参数扫描的实验。

---

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",民间文学家族要解决"户口化",
英国文学家族要解决"**名单化**":把一套学科语言("莎士比亚词汇
惊人"/"正典很稳固")先翻成模型(Heaps 幂律;优先连接+范式
切换),再翻成代码。翻译的损耗全部发生在第一步——所以本章先划清
哪些对象第一步就走得通(绿色区),哪些走不通(红色区),再给三条
走通了的走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 学科概念 | 代码化身 | 备注 |
|---------|---------|------|
| 词汇量/词表 | 词形统计+Heaps 拟合(\|V\|=k·N^β) | 走廊 1(实验律一) |
| 新词增量递减 | 分期差分+单调断言 | 走廊 1 附带 |
| 词频谱 | 排序-频次回归(Zipf 斜率) | 走廊 1 附带(模拟 −0.860) |
| 正典席位 | 声望存量+世代快照排名 | 走廊 2(实验律二) |
| 马太/重估 | 优先连接+契合切换的蒙特卡洛 | 走廊 2 附带(基尼/位移/重叠) |
| 语言混合率 | 母语插入 token 级统计 | 走廊 3(实验律三) |
| 接受区间 | 收益-代价二次拟合+峰值断言 | 走廊 3 附带(m\*=0.34) |
| 作者归属 | 词频特征向量+Delta 距离 | 走廊 1 的邻居(01 章主线 A) |

**转不动(红色区)**:

1. **"莎士比亚性"**:伟大不可参数化——统计再精也算不出"为什么
   是这一句"。
2. **"英国性"**:定义式与谱系式两问法(01 章),没有对应单一可测
   属性。
3. **"伟大的传统"的伟大性**:Leavis 名单是批评立场,可追踪其
   世代链,不可测其"伟大"真值。
4. **审美判断**:课堂与论文里的价值裁决,存在于批评共同体,不
   存在于函数。

**边界的一句话**:绿色区=幂律类+份额类+梯度类,覆盖"正典形态学
的校准";红色区提醒:**转码是英国文学的使用说明书,不是英国文学
的替身**——算得出词表 31,534,算不出那一行诗为什么让人停住。

## 二、代码走廊清单(三条主走廊,每条=史识→模型→算法→真实系统)

### 走廊 1:Heaps 词汇画像走廊(词汇增长律的拟合与外推)

```
文本 ──分词/归并──▶ (N, |V|) 检查点 ──log-log 回归──▶ k, β, R²
  │                                                └──倍增外推(新词预测)
  └──频谱排序──▶ Zipf 斜率 ──▶ 作者画像卡(03 章卡 1)
```

- **史识→模型**:作者写作=新词率递减+按频复用(Simon 优先连接);
  词表是篇幅的幂律函数,不是记忆天赋。
- **算法层**:词频 Fenwick 树 O(log V) 维护按频抽样;回归 O(检查点);
  全程线性——瓶颈在**分词与归并口径**,不在计算。
- **本家族实现**:[`experiments/heaps_canon_shift.py`](experiments/heaps_canon_shift.py)
  幕一——断言拟合 R²=0.9997>0.99、β̂=0.527∈(0.45,0.55);八创作期
  新词 10,662→2,049 严格递减;倍增外推 13,877 vs Efron-Thisted
  约 1.14 万(通说)同量级;频谱斜率 −0.860。
- **真实系统**:作者画像与抄袭/代笔检测(词表与频谱是作者指纹的
  一维);生成式文本的"词汇多样性"控制(LLM 采样温度与词表增长
  的关系);语料库建设的规模-词表预算(存多少文本需要多少词典)。
- **性能工程要点**:断言盯**拟合优度与单调性**而非绝对词数(口径
  会漂);比较作者必须**控篇幅**(TTR 定长原则,02 章第二栏);
  归并口径写成显式配置,不埋在代码里。

### 走廊 2:正典席位走廊(优先连接+范式转移的席位动力学)

```
作品池(入场时间/质量/契合度) ──逐代注意力分配──▶ 声望存量
    │                                              │
    │                    ┌──马太断言:队列基尼↑、差距放大───┐
    └──第 T 代契合切换 ──┴──重估断言:中游位移≫顶尖、前10重叠──┘
```

- **史识→模型**:正典=存量声望的优先连接再生产;范式转移=契合
  函数切换;席位=存量排名。
- **算法层**:每代权重 (S+4)^1.05·e^{0.8·fit},600 token 多项分配
  (自写二分落点);蒙特卡洛 40 世界取均值——**断言打在均值上**,
  单世界的运气不立法。
- **本家族实现**:同实验律二——断言队列基尼 0.702→0.757 严格
  上升、差距 ×3.7;中游位移 16.5 位 vs 顶尖 0.66 位(25 倍),
  前 10 重叠 9.1/10、内部序 ρ=0.95。
- **真实系统**:推荐系统的头部效应审计(流量∝存量是同一动力学,
  马太断言即"赢家通吃预警");学术引用与基金分配的累积优势研究;
  内容平台的"范式转移"策略(改排序函数=改契合,能撼动腰部、
  撼不动头部——席位动力学的工程翻译)。
- **性能工程要点**:两断言必须**分列**(马太面/重估面),混报
  会把"稳固"与"僵化"当成一件事;入场稀释是混杂源——集中度
  指标要**固定队列**(本实验的教训:全池份额会被新入场作品拉低)。

### 走廊 3:语言混合走廊(混合率梯度与接受区间)

```
作者群(代际参数) ──文本生成──▶ 混合率/未译片段长 ──分代统计──▶ 梯度断言
      └──评论打分模型 ──二次拟合──▶ 峰值 m* 与两端边际 ──区间断言
```

- **史识→模型**:移民文本=英语底+母语迁移;代际是梯度;接受度=
  差异化收益−可读性代价,有中间峰。
- **算法层**:片段生成为泊松式插入 O(token);二次拟合解 3×3 正规
  方程(Cramer);Welch t 手写——全部标准库可过。
- **本家族实现**:同实验律三——断言混合率 0.29>0.18>0.07
  (t=8.6)、片段长 3.8>2.2>1.1;接受度凹(二次项 −3.79)、
  m\*=0.339、峰顶高出全同化端 0.32。
- **真实系统**:多语言产品文案的"母语残留"检测(代码注释、UI
  文案、客服话术的迁移特征);跨语言搜索与推荐的混合语料处理;
  生成式模型的"语域混合"控制(中英夹杂输出是同一现象的机器版)。
- **性能工程要点**:**测量单位先行声明**(词级/短语级/句法级,
  混层统计无效);接受度模型是单变量截面——下总评价结论前先补
  其他维度(石黑案例,03 章引擎 3)。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:词汇画像——给"多产"一个幂律口径

任何长产量对象(作者、代码仓库、产品文案库)的"词汇量"都服从
Heaps 型增长:评估"丰富度"先控篇幅、再比 k/β;项目里"我们的
词汇/标签/接口数惊人"类汇报,先问一句**分母 N 多大**——走廊 1
的口径纪律直接搬用。

### 落点 2:头部审计——你的系统里范式转移能动多深

改推荐权重、改排序函数、改激励政策,都相当于"契合切换":预期
管理用席位动力学——**腰部会大动、头部几乎不动**;若目标是撼动
头部,需要的不是权重微调,是存量清零(新池子),这在正典史与
推荐史上同构(走廊 2 的马太断言是头部护城河的测量仪)。

### 落点 3:混合度调参——中间峰是普遍结构

"差异化收益 vs 学习成本"的权衡无处不在:产品的新功能密度、
文档的中英术语比、教学材料的生词率——收益饱和型(m/(m+c))+
成本平方型(m²)的组合几乎总给**中间峰**;先估峰值区间再定参,
别在两端浪费迭代(走廊 3 的拟合-断言流程直接复用)。

### 落点 4:名单即基础设施——选本、榜单与白名单的工程学

正典的可构造面告诉我们:**名单是机器不是观点**——字段(谁、
何时、凭什么、谁复核)齐全的名单可审计、可 diff、可回滚;工程侧
的"白名单/资质名单/推荐池"同理,03 章三张卡的字段设计就是
名单 schema 的参考实现。
