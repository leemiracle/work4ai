# 03 · 可构造与结构——图、公差与模型作为数据对象

> **本章回答五问之 Q4(可构造性与结构)。**
> **本质一句话**:工程图学里「可构造」的不是绘图的手艺,
> 而是**它的三类产出**——图样是把「形与量」写成视图组+
> PMI 集的结构(标题栏即效力字段),特征控制框是把
> 「怎么验」写成谓词+公差带+基准序的最小判例,尺寸链是
> 把「叠加风险」写成带方向的网络(MBD 模型树则是三者
> 在三维载体上的合体);把这些结构显式化,图样工作就从
> 制图手艺变成工程:可校验、可对表、可交接(04 章走廊的
> 地基)。

---

## 0. 开篇:一张图的四件结构化家具

拆开任何一张可执行的图(2D 或 3D),都能拆出四件家具:
其一是**图样身份**(标题栏:图号/版本/投影角/比例——
它是谁、按哪套约定、第几版),其二是**形**(视图组或
模型特征树),其三是**量**(尺寸与公差条目,含特征
控制框),其四是**链**(尺寸之间的装配关系网络)。四件
家具在手,「画—标—验—流」主链(00 章)的每一环就变成
**可机检的数据流水线**;从蒙日的两块投影面到 MBD 的
模型树,在数据结构层面是同一套 schema——变的是载体,
不变的是结构。

## 1. 什么是"可构造"的:四类结构对象

| 对象 | 数化身 | 可构造性 | 构造中的坑 |
|------|--------|---------|-----------|
| **图样文件** | 图框+标题栏(图号/版本/投影角/比例/状态)+视图组+PMI 集 | ✅ 高度可构造 | 投影角与版本不钉死(跨体系误读的根源);视图无来源说明 |
| **尺寸/公差条目** | 基本尺寸+上下偏差;或特征控制框 | ✅ 高度可构造 | 方形带语义含混(02 章开篇);基准缺席 |
| **特征控制框** | 特征符号+公差带(形状/大小)+修正符+基准序 | ✅ 高度可构造 | 修正符缺失即默认 RFS——默认值被当「没要求」误读 |
| **尺寸链网络** | 节点(尺寸+公差)+方向(增/减环)+封闭环+叠加方法 | ✅ 高度可构造 | 封闭环混入标注;最坏法/RSS 混用不声明;独立性假设隐式 |
| **MBD 模型树** | 特征树+PMI 挂载点+配置与版本 | ✅ 高度可构造 | PMI 语义在跨软件链(CAD→CAM→CMM)损耗(01 章未决问题) |

**不可构造的**:绘图的美学裁量(视图怎么摆最易读——
规范的骨架之内是手艺)、基准选择的工程裁量(哪个面当
A 基准是功能与工艺的权衡,规范只验格式不验最优)、
工艺意图(怎么造出来,归工艺文件)、以及「这张图该不
该这么标」的设计判断(00 章权威定义假设的暗面)。

### 1.5 最小数据模式(动手者的 schema)

```yaml
# 图样结构卡(标题栏=效力字段;GB/T 4457/4458 的机读版)
drawing_doc:
  identity: {number: str, revision: str,
             projection: first_angle|third_angle,   # 投影角必钉(跨体系误读根源)
             scale: str, status: current|superseded}
  views:
    - {name: str, type: principal|section|detail, source: face|cut_plane}

# PMI 集:尺寸条目 + 特征控制框
pmi:
  - {kind: dimensional, feature: hole_1,
     basic: 10.0, up: 0.5, low: 0.0}               # 基本尺寸+上下偏差
  - {kind: geometric, feature: hole_1,
     characteristic: position,                      # 位置度/垂直度/平面度…
     zone: {shape: cylindrical, value: 0.2, modifier: MMC},  # 公差带三件:形状/大小/修正
     datums: [A, B, C]}                             # 基准优先序(形状类为空)

# 尺寸链(实验律1/2 的对象)
tolerance_chain:
  loops: [{dim: str, tol: 0.05, sense: +1|-1}]     # 增环+1/减环−1
  closure: {target: str, method: worst|rss,         # 叠加方法必声明
            independence: declared|assumed}         # RSS 的前提显式化

# MBD 模型树(图样结构卡在三维载体上的合体)
mbd_model:
  features: [feature_id, …]
  pmi_attachments: [{feature: hole_1, frame: pmi[i]}]  # PMI 挂在特征上
  config: {revision: str, release: str}                 # 版本与配置(单一权威源)
```

注意 `projection`、`datums`、`method` 三处必填:把 02 章
的可判定规则写进数据结构——**数据层自带校验点,是图样
区别于普通图形文件的第一特征**(与[工程物理学家族]
(../讲透工程物理学/03-可构造与结构.md)schema 同款精神:
条款不 naked,参照系不缺席)。

## 2. 骨架一:图样身份卡(标题栏是效力字段)

- **投影角必钉**:第一角/第三角决定视图的摆放约定,默认
  值随标准体系反转(ISO 第一角/ASME 第三角,通说)——
  不标投影角的图在跨体系协作里是**歧义文件**(02 章术语
  表第一陷阱)
- **版本与状态**:图号+修订号+现行/作废——图纸是时效
  文件,与标准文献同理(标准科学技术家族的「状态眼」:
  引用作废图=引用失效法条)
- **比例与单位**:图上 1 不等于物上 1 时的换算声明;
  「不按比例」的局部必须显式标注(通说惯例)

## 3. 骨架二:特征控制框(GD&T 的最小判例)

- **四件套缺一不可**:控制什么(特征符号)、允许多少
  (公差值+带形)、怎么修正(MMC/LMC/默认 RFS)、按谁
  测(基准序 A|B|C)——一个框就是一条完整的可判定条款
- **形状类无基准,方向/位置类必有基准**:平面度自检,
  垂直度必须挂基准——基准缺席的方向/位置公差是**没有
  主语的句子**(02 章基准显式规则的 schema 版)
- **修正符连着功能量规**:Ⓜ 的存在意味着判定式含 bonus
  (律3):有效公差随实体偏离 MMC 线性放大,恒等式
  D−e≥虚拟条件把条款焊到量规上——**schema 里 modifier
  字段留空(RFS)与填 Ⓜ 是两种验收命运**(实验:33% 对
  73% 的通过率差)
- **与标准学的对表**:特征控制框=标准条款的微缩版(对象+
  限值+验证方式+参照系四件),与[标准科学技术](../讲透标准科学技术/README.md)
  02 章「验证成对规则」同构——GD&T 是图学内部的条款语言

## 4. 骨架三:尺寸链网络(叠加风险的图)

- **封闭环唯一**:装配要求的间隙/过盈是封闭环,零件尺寸
  是组成环;**标注里出现封闭尺寸回路是逻辑错误**(把
  封闭环当组成环标出=给自己制造矛盾约束,练习 1③)
- **方向列必填**:每个环对封闭环是增是减(sense:+1/−1),
  最坏法叠加前先按方向处理正负——网络不是清单,是**带
  符号的有向图**
- **方法列必声明**:worst 还是 rss,以及 RSS 的独立性
  假设是 declared 还是 assumed(00 章方法论之争第一场的
  schema 化)——混用不声明是尺寸链计算的最高频事故
- **两法的账可自动对表**:实验律1/律2 就是这张网络的
  求解器:worst=|Σsense·t|,rss=√(Σt²),比值 √n 随环数
  打开(04 章走廊 C1)

## 5. 骨架四:MBD 模型树(身份卡的载体合体)

- **PMI 挂在特征上,不再挂在纸面上**:模型树+挂载点取代
  「视图+标注」的分离结构——**单一权威源**(single
  source of truth,01 章方向一)的数据面
- **视图降格为派生对象**:视图=模型在投影约定下的输出
  (projection 字段仍要钉——投影角没有随纸消失);剖视=
  切平面参数,不再是一张独立画的图
- **配置与版本是模型树的一等公民**:MBD 时代「改图」=
  改模型+PMI+配置的三元组,任一滞后就是版本事故——
  与标准体系表的状态维护(复审/代替)同一门功课

## 6. 从结构到校验:这套骨架买到了什么

- 身份卡带投影角与版本 → 跨体系误读与引用作废图可机检
- 控制框带基准序与修正符 → 「无主语句子」「默认 RFS 被
  误读」可机检(02 章规则的运行时版)
- 尺寸链带方向与方法列 → 封闭环混标、两法混用可机检
- 模型树带挂载点与配置 → PMI 断链(特征改了公差没跟)
  可机检;跨软件链的语义一致性有了对表的抓手(01 章
  方向二的难点)

## 7. 构造合法性清单(动手前三问)

把任何图样构想变成数据结构之前,先过三问——本家族的
「类型检查」:

1. **参照系写全了吗**:方向/位置类公差的基准序齐吗?
   投影角钉死了吗?测量基准与设计基准的转换声明了吗?
2. **带形与修正钉死了吗**:公差带的形状(方/圆/圆柱/
   两平行平面)、大小、修正符(MMC/LMC/RFS)三件都
   显式了吗?
3. **状态钉死了吗**:图号/版本/发布状态/配置入表了吗?
   尺寸链的方法与独立性声明了吗?

三问全过,数据才获得进入 [04 章走廊](04-工程图学转代码.md)
的资格。**图样工程的第一特征不是线条多,是账目清楚。**

## 📌 收束

可构造的是**四类数据对象**(图样身份/特征控制框/尺寸
链网络/MBD 模型树),不可构造的是**美学与基准选择的
裁量**;结构化不是为了替代制图与设计判断,是为了让
画—标—验—流的链条可校验、可交接、可复盘。下一章把
骨架接上代码:[04-工程图学转代码](04-工程图学转代码.md)。

**🧠 认知升维**:

- **判例眼**:特征控制框=一条微缩判例(对象+限值+验证+
  参照系)——见框先查四件套齐不齐
- **网络眼**:尺寸不是清单是有向图——先问方向与封闭环,
  再谈叠加
- **挂载眼**:MBD 时代公差挂在特征上不挂在纸上——改了
  模型忘了 PMI 就是断链事故
