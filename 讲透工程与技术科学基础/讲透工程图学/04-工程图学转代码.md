# 04 · 工程图学转代码——公差叠加·投影计算·PMI 机读的走廊

> **本章回答五问之 Q5(问题→代码转换)。**
> **本质一句话**:图学问题一旦变成「公差带的计算与判定、
> 投影不变量的数值验证、PMI 条款的谓词化」,就能进代码
> ——尺寸链可两种叠加对表、MMC bonus 可蒙特卡洛验装配、
> 蒙日的从属/平行/定比可数值断言、特征控制框可编译成
> 可执行判定;**唯一不可外包给代码的,是视图布局的
> 可读性裁量、基准选择的工程权衡、公差值本身的功能
> 判据**(那是力学与经验的辖区)。

## 0. 开篇:一条装配链,代码自己说

「8 环尺寸链到底该留多少公差?MMC 救回的零件敢不敢
放行?」——`experiments/tolerance_stackup.py` 让代码回答:
最坏法封闭环公差=环数×单环公差(4 环各 ±0.05 → ±0.20,
8 环 → ±0.40,环数翻倍公差翻倍,线性放大)(律1);
RSS=√(Σtᵢ²)(8 环 √8×0.05≈0.141),两法比值恰为 √n
(8 环 2.83 对 4 环 2.00)——环数越多,保守代价越大,
但 RSS 的独立性前提必须声明(律2);MMC bonus 随实际
尺寸偏离 MMC 线性补入(有效公差=尺寸+几何+bonus),
恒等式 e≤0.2+(D−10.0) ⟺ D−e≥9.8 把「公差条款」与
「功能量规」焊死——蒙特卡洛十万件:刚性 RFS 判 33%
合格,MMC 判 73%,救回的四万件全部过 ⌀9.8 销,代数
担保,不靠运气(律3)。一条脚本把 00 章方法论之争与
02 章可判定规则全部落成可复现的数。

## 1. 可机械化边界(三件套之一)

**能进代码的**(图样数据化后的一切计算):

| 任务 | 机械化形式 |
|------|-----------|
| 尺寸链叠加 | 最坏法(Σt)/RSS(√Σtᵢ²)双法计算+比值 √n 对表(律1/律2) |
| MMC/LMC 判定 | bonus=偏离量;虚拟边界恒等式(条款式⟺量规式)+蒙特卡洛装配率(律3) |
| 投影计算 | 点/线/面的投影变换矩阵;真长/真形/夹角的图解法数值化 |
| 投影不变量校验 | 从属性/平行性/定比性在变换后逐条断言(蒙日体系的数值版) |
| PMI schema 校验 | 03 章四类对象的机检:基准缺席/封闭环混标/修正符默认/PMI 断链 |
| 公差带判定 | 特征控制框→谓词编译,对实测数据批量求值(合规检查) |

**不能进代码的**(工程图学的「不可判定域」):

1. **视图布局的可读性**——怎么摆视图最易读,规范骨架
   之内是美学裁量;代码能验格式,不能验「清楚」
2. **基准选择的权衡**——哪个面当 A 基准,是功能要求、
   加工可达性与测量便利的三方权衡;规范只验「写没写」,
   不验「选没选对」
3. **公差值的确定**——「该标 0.05 还是 0.1」的功能判据
   在力学与工艺经验里(间隙够不够/成本花不花得起),
   计算器只负责算账不负责定值
4. **设计意图的解释**——「为什么这样标」的 rationale
   (00 章表达力边界)仍是人的传承;PMI 语义化只偿还了
   一部分

> 边界的一句话:**代码是公差的算账台与条款的判定器,
> 不是设计师。**

## 2. C1 公差叠加走廊(✅ 已实现)

| 字段 | 类型 | 约束/坑 |
|------|------|--------|
| 最坏法 | worst=Σt | 线性放大,环数翻倍公差翻倍(律1);安全但贵 |
| 统计法 | rss=√(Σtᵢ²) | 前提=偏差独立;系统性漂移(刀磨损/夹具偏置)下系统性乐观 |
| 两法比值 | worst/rss=√n | 环数的单调解;链越长统计折扣越大,判据随之移动 |
| MMC bonus | bonus=D−MMC(孔) | 斜率 1 线性补入;有效公差=尺寸+几何+bonus |
| 虚拟边界 | VC=MMC∓geo_tol | 条款判定⟺量规判定(恒等式);RFS 是无 bonus 的严格子集 |
| 装配率 | 蒙特卡洛(固定种子) | 通过率差=救回零件数;数值随公差带宽可敏感性扫描 |

成品=`experiments/tolerance_stackup.py`。**改严格度换一行
t,改修正符换一个 modifier,改批量换种子**——03 章 schema
分离的好处:环(公差列)、方法(叠加列)、修正(功能列)
分居三处,敏感性分析就是在列间扫描。

## 3. C2 投影计算走廊(把蒙日写成代码)

画法几何的图解方法,数值化后就是**变换+不变量断言**:

```python
# 教学版:投影不变量的数值断言(蒙日体系的运行时)
def project(p, axis="z"):          # 正投影:压掉一维
    return (p[0], p[1]) if axis == "z" else (p[1], p[2])

# 断言一(从属性保持):点 P 在线 AB 上(参数 t)→投影后仍在投影线上
#   cross(P-A, B-A) == 0  ⇒  cross(P'-A', B'-A') == 0
# 断言二(平行性保持):方向 u∥v(cross==0)→投影方向仍平行
# 断言三(定比性保持):P=A+t·B 的 t 在投影后不变
#   —— 分点公式对投影可交换:project(A+t·(B-A)) 的 t 可原样反解
# 求真长:直角三角形法数值化 len3d = sqrt(len2d^2 + dz^2)
#   ——「量在显真形处」的代码版:先变换到显真形,再取长度
```

要点:其一,不变量断言(从属/平行/定比)是投影库的
**单元测试**——任何投影实现(渲染管线/CAD 内核/自制
工具)先过这三条,蒙日两百年前的定理成了今天的 CI;
其二,「求真长=先变换再度量」的流程,就是所有「把
不保真的量换到保真位置」的算法原型(坐标变换、数据
归一化、度量学习,骨架同款);其三,02 章不变量表是
这条走廊的规格书——先列什么可信,再写代码。

## 4. C3 PMI 机读走廊(条款→谓词)

「机器消费 PMI」(01 章方向二)的两级台阶:结构化
(03 章 schema)→可执行(本节)。最小机械化是**把
特征控制框编译成判定谓词**:

```python
# 教学版:从 03 章 schema 的 FCF 到可执行断言
def compile_fcf(frame):
    if frame["characteristic"] == "position" and frame["zone"]["modifier"] == "MMC":
        vc = frame["vc"]                      # MMC−geo_tol(虚拟边界)
        return lambda part: (part.D - part.e) >= vc   # 条款式=量规式(律3)
    if frame["characteristic"] in ("perpendicularity", "position"):
        assert frame["datums"], "无主语句子:方向/位置类公差缺基准(02 章规则二)"
    return lambda part: part.e <= frame["zone"]["value"]  # RFS 默认路径
# 断言风格:每条编译出的谓词必须可对「实测实例」给出
# True/False(可判定性);datums 为空 → 编译失败——
# 02 章基准显式规则的运行时版;PMI 的判定覆盖率=编译成功率
```

要点:其一,**修正符决定代码路径**(MMC 走虚拟边界式,
RFS 走定值式——同一符号两种验收命运,实验律3 的
0.33 对 0.73);其二,**编译失败是信号不是噪声**:基准
缺席、带形缺失当场报「无主语句子」——PMI 机读化是对
标注质量的最狠审计(与标准科学技术家族 04 章 C3「条款
编译」完全同构);其三,数字线程(01 章)的软件链
(CAD→CAM→CMM)就是这条走廊的工业放大版——语义损耗
发生在「同一 FCF 两处编译」的每条缝隙里。

**走廊三警告**(共用):

1. 独立性不声明不 RSS:工艺漂移未排查的链,统计叠加是
   乐观偏见(00 章方法论之争第一场)
2. 基准缺席不判定:方向/位置公差没挂基准,代码拒绝编译
   ——不要硬造参照系(不可判定域第二条)
3. 修正符不默认不显式:RFS 是沉默的严格,写图与写代码
   都要把它说出声(03 章坑表第一条)

## 5. 工程师落点(把这门学科带回家)

- **合同眼→API 文档**:一份接口文档就是一张图——签名是
  视图(定形),版本与序列化约定是标题栏(投影角),
  参数容差(单位/范围/精度)是公差带;**写文档时你在做
  蒙日与 Parker 做过的事,认真程度对齐一下**
- **两法叠加→排期与预算**:项目缓冲=公差:给每个任务
  全上最坏缓冲(算术叠加)安全但贵,关键路径统计缓冲
  (PERT/RSS 思路)折中——先问各任务延误是否独立,再
  选公式;**「环数翻倍公差翻倍」对项目同样成立**
- **判定成对→需求工程**:每条「应」同一时间写判定程序
  (与标准科学技术家族 04 章同构);写不出测试的需求是
  方形带——看着有界,验收时四角漏水
- **PMI 思维→schema-first**:字段先定判定再定存储;注释
  挂在「特征」(函数/端点)上而不是散落文档——改模型
  忘了改注释就是 PMI 断链(03 章挂载眼)
