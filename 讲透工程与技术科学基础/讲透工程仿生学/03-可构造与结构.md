# 03 · 可构造与结构——译卡、材料库与对照记录作为数据对象

> **本章回答五问之 Q4(可构造性与结构)。**
> **本质一句话**:工程仿生学里"可构造"的不是生物本身,
> 而是**仿生问题的三类数据对象**——仿生设计译卡是把
> "这次借鉴"写成生物原型/功能抽象/工程指标/使能工艺
> 四栏的报告结构,仿生材料数据库是把"38 亿年策略库"
> 写成按功能句柄检索的条目 schema,失效-对照记录是把
> "仿生真的更优吗"写成对自然原型与对现役方案的双对照
> 结构;把这些结构显式化,仿生工作就从灵感变成为工程:
> 可校验、可对表、可交接(04 章走廊的地基)。

---

## 0. 开篇:一份"仿生开发任务单"的三件结构化家具

拆开任何一次严肃的仿生开发(自洁表面/吸能结构/干黏附
器件),都能拆出三件家具:其一是**仿生设计译卡**(这次
借鉴——原型是谁、原理句是什么、指标几个、工艺靠什么),
其二是**材料库条目**(策略库——这条生物策略的机制证据
与指标档案),其三是**对照记录**(验收——比自然原型
差多少、比现役方案强多少)。三件家具在手,00 章翻译链
的每一环就变成**可机检的数据流水线**;从 Velcro 到
AI 五接口时代,在数据结构层面是同一套 schema——变的
是证据密度,不变的是结构。

## 1. 什么是"可构造"的:三类结构对象

| 对象 | 数化身 | 可构造性 | 构造中的坑 |
|------|--------|---------|-----------|
| **仿生设计译卡** | 四栏:生物原型/功能抽象/工程指标/使能工艺 | ✅ 高度可构造 | 功能抽象栏保留物种名(去物种化失败);指标单写;工艺栏空缺(纸面自由) |
| **仿生材料数据库** | 条目:功能句柄/生物原型/机制证据级(B1-B5)/指标对/使能工艺/TRL | ✅ 高度可构造 | 按物种索引而非按功能索引(检索面收窄一个量级);证据级混档 |
| **失效-对照记录** | vs 自然原型(差距%)/vs 现役方案(增量%)/失效模式/耐久工况 | ✅ 可构造(新) | 只报"像生物"不报性能;"对照"缺现役方案基准 |
| **多尺度结构档案** | 层级表:尺度-构件-机制-指标挂靠 | ✅ 可构造 | 只登记宏观漏登记纳米层(单尺度错觉) |
| **AI 生成候选记录** | 生成源(接口①-⑤)/提示/候选参数/人审结论 | ✅ 可构造(新) | 机器候选无证据级标注直接入库(幻觉进库) |

**不可构造的**:涌现的完整解释(指标能验收,解释不了
为何涌现)、演化史的意图(归生物学本体,180 待建)、
"这个策略在我产品上值多少钱"(经济性在语言外)、以及
尚未被机制化的直觉灵光(灵感入库前只是 B1)。

### 1.5 最小数据模式(动手者的 schema)

```yaml
# 仿生设计译卡(一次借鉴的四栏结构)
bioinspiration_card:
  prototype:                      # 第一栏:生物原型
    species: str                  # 物种+器官
    habitat: str                  # 生态位(工况的出身地)
    evidence: B2-observed|B3-characterized|B4-mechanistic|B5-modeled
  abstraction:                    # 第二栏:功能抽象(去物种化原理句)
    principle: str                # 不含物种名的机制句
    hierarchy: [molecular, nano, micro, macro]   # 功能住在哪几层
  specs:                          # 第三栏:工程指标(双写+工况)
    - {metric: contact_angle_deg, threshold: 150, condition: "2 μL 水滴,25 ℃"}
    - {metric: rolling_angle_deg, threshold: 10, condition: 同上}
  process:                        # 第四栏:使能工艺
    tech: str                     # 光刻/蚀刻/多材料打印……
    scale: str                    # cm² 还是 m²
    trl: 1-9
  caveats: [not_emergence_proof, durability_untested]

# 仿生材料数据库条目(按功能句柄检索)
bio_material_entry:
  function_handle: str            # 检索键:"怎样让表面自洁"——功能不是物种
  prototypes: [{species: str, evidence: B1-B5}]
  principle: str
  spec_pairs: [{metrics: [str, str], values: [float, float]}]  # 指标成对
  enabling: [{tech: str, trl: int, max_scale: str}]
  references: [str]

# 失效-对照记录(仿生声明的验收结构)
benchmark_record:
  vs_nature: {metric: str, engineered: float, natural: float, gap_pct: float}
  vs_incumbent: {metric: str, engineered: float, incumbent: float, gain_pct: float}
  failure_modes: [str]            # 耐久/老化/浸润坍塌……
  conditions: [str]               # 验收工况清单
```

注意 `evidence`、`specs`(成对)与 `process` 三处必填:
把 02 章的证据纪律写进数据结构——**数据层自带校验点,
是仿生工程区别于灵感笔记的第一特征**(与
[工程物理学家族](../讲透工程物理学/03-可构造与结构.md)
schema 同款精神:指标不 naked,工艺不缺席)。

## 2. 骨架一:仿生设计译卡(四栏语法)

- **第一栏 生物原型**:物种+器官+生态位三者缺一——
  生态位是工况的出身地,漏写则指标无根(02 章规则三);
  原型可以多个(功能句柄检索出的候选族),但须逐个立卡
- **第二栏 功能抽象**:去物种化的原理句,验收法简单:
  **句子里不许出现动植物名**。"像荷叶那样"不合格,
  "微结构截留空气的复合浸润降低接触角滞后"合格;
  层级字段清点功能住在几层(00 章反直觉①的判别式落卡)
- **第三栏 工程指标**:双指标起步、阈值+工况成套
  (02 章规则二/三);指标对里故意放一对"张力指标"
  (如黏附强度 vs 可剥离性)——张力显式化,设计权衡
  才可讨论
- **第四栏 使能工艺**:工艺名+尺度+TRL;这一栏空着的
  译卡只配标 bio-inspired(措辞谱降档),不配标
  biomimetic——**没有使能工艺的功能抽象是纸面自由**
  (00 章假设三)

## 3. 骨架二:仿生材料数据库(功能句柄索引)

- **检索键是功能不是物种**:按"荷叶"检索只得一种,
  按"怎样让表面自洁"检索得一族(荷叶/猪笼草口缘/
  蝉翅/蝴蝶翅)——**功能句柄索引是数据库的第一设计
  决策**,物种索引只是它的二级视图(美之时刻③的制度面)
- **证据级随条目走**:同一功能的不同原型证据级不同
  (荷叶 B5、某传说植物 B1),分级入条目;AI 五接口
  (01 章方向三)自动抽取的候选必须带 `evidence` 字段
  **降档标注**(机器转述默认 B1,人工核验后升级)——
  没有这一条,幻觉批量入库
- **指标对成套存储**:库里的数值必须是"指标对+工况",
  裸数(如"接触角 160°")不带条件不可比,入库即废
- **TRL 与尺度是检索过滤器**:设计阶段按尺度筛候选
  (要 m² 幕墙,TRL 3 的纳米工艺直接出局)——数据库
  不是博物馆,是选型台

## 4. 骨架三:失效-对照记录(验收的成套语法)

- **双对照缺一不可**:vs 自然原型回答"译得像不像"
  (差距%),vs 现役方案回答"值不值得"(增量%)——
  只做第一对照会得出"接近自然=成功"的错觉,而自然
  原型本身未必及格(00 章反直觉③:演化解的是繁殖
  最优)
- **失效模式入册**:超疏水面的浸润坍塌(高压下 Cassie
  态转 Wenzel 态,接触角掉 26°——家族实验律2)、干黏附
  的粉尘失效(壁虎在沙地上黏附骤降,通说)、砖泥结构
  的疲劳退化为仿形结构的三大经典失效,逐条入册——
  **失效模式是生物原型没经历过的工况,恰恰是工程
  必须回答的工况**(生态位工况≠服役工况)
- **验收工况清单**:单次冲击/疲劳/温湿老化/紫外——
  生物原型多只回答单次工况(01 章方向二未决问题的
  schema 面)

## 5. 从结构到校验:这套骨架买到了什么

- 译卡四栏齐 → 一次借鉴可复盘(独立于写它的人)
- 数据库功能句柄索引 → 候选检索面从一个物种扩到一族
- 证据级随行 → AI 生成候选有准入闸门,幻觉进不了库
- 双对照记录 → "仿生更优"从口号变成可审计的表
- 失效模式入册 → 设计的边界条件随数据交接

## 6. 构造合法性清单(动手前三问)

把任何仿生构想变成数据结构之前,先过三问——本家族的
"类型检查":

1. **功能句柄写了吗**:原理句去物种化了吗?层级字段
   清点了吗?——还是只写了一句"像荷叶一样"?
2. **指标双写+工况附了吗**:几个指标?阈值与测试条件
   在哪一行?张力指标(如强度 vs 可剥离)显式化了吗?
3. **使能工艺与尺度写了吗**:什么工艺?cm² 还是 m²?
   TRL 几?——以及,双对照(vs 自然/vs 现役)和失效
   模式在哪一层?

三问全过,数据才获得进入 [04 章走廊](04-工程仿生学转代码.md)
的资格。**仿生工程的第一特征不是灵感好,是账目清楚。**

## 📌 收束

可构造的是**三类数据对象**(译卡/数据库/对照记录),
不可构造的是**涌现解释、演化意图与经济性**;结构化
不是为了替代灵感,是为了让灵感-抽象-指标-工艺的链条
可校验、可交接、可复盘。下一章把骨架接上代码:
[04-工程仿生学转代码](04-工程仿生学转代码.md)。

**🧠 认知升维**:

- **句柄眼**:检索键从"是什么物种"换成"要什么功能"
  ——候选从一个变一族;这是数据库时代的第一设计决策
- **四栏眼**:原型/抽象/指标/工艺,缺一栏的译卡按
  措辞谱降档;纸面自由不是设计自由
- **对照眼**:vs 自然管忠实,vs 现役管价值;单对照的
  "成功"是半场哨
