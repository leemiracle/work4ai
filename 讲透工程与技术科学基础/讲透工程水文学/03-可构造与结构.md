# 03 · 可构造与结构——计算书、流域卡与站网作为数据对象

> **本章回答五问之 Q4(可构造性与结构)。**
> **本质一句话**:工程水文学里"可构造"的不是河流本身,
> 而是**水文问题的三类数据对象**——设计洪水计算书是把
> "水多大"写成序列-方法-参数-设计值成套的报告结构,
> 流域特征卡是把"流域什么脾气"写成面积-河网-下垫面
> 的静态档案,雨量站网 schema 是把"证据从哪来"写成
> 密度-代表性-插值方法的证书结构;把这些结构显式化,
> 水文工作就从手艺变成工程:可校验、可对表、可交接
> (04 章走廊的地基)。

---

## 0. 开篇:一份"防洪设计任务单"的三件结构化家具

拆开任何一次严肃的防洪设计(堤防/水库/城市排水),都
能拆出三件家具:其一是**设计洪水计算书**(水多大——
序列、方法、参数、x_T 表、合理性检查,成套出现),其
二是**流域特征卡**(响应多快——面积、比降、河长、
下垫面,产汇流的静态输入),其三是**雨量站网证书**
(证据多硬——站数、密度、面雨量插值法、代表性评估)。
三件家具在手,00 章翻译链的每一环就变成**可机检的数据
流水线**;从 Gumbel 时代的手算表格到今天的 AI 混合预报,
在数据结构层面是同一套 schema——变的是证据密度,不变
的是结构。

## 1. 什么是"可构造"的:三类结构对象

| 对象 | 数化身 | 可构造性 | 构造中的坑 |
|------|--------|---------|-----------|
| **设计洪水计算书** | 序列(带身份)→线型+参数法→x_T 表(设计/校核)→过程线(单位线/模型)→合理性检查 | ✅ 高度可构造 | 序列身份缺项(缺测/插补/还原不写);设计值不带区间;方法换了结论不换却不声明 |
| **流域特征卡** | 面积/河长/比降/形状系数/下垫面分类/土地利用时点 | ✅ 高度可构造 | 下垫面不附时点(城市化序列断裂的元凶);面积来源(DEM/纸图)不写 |
| **雨量站网 schema** | 站点/年限/密度/面雨量法(泰森/等值线)/代表性评估 | ✅ 可构造 | 站网密度与暴雨尺度不匹配不告警;迁站与改仪器造成的不一致性不入册 |
| **单位线档案** | 时段/净雨深/过程线坐标/场次来源/多场分歧 | ✅ 可构造 | 反演的适定性问题不声明;大洪水外推幅度不标注(00 章假设二) |
| **预报事件库** | 预见期/预报值/区间/实测值/误差归因 | ✅ 可构造(新) | AI 预报的基准对照缺失(与什么比?);经济价值三栏不齐(01 章方向一) |

**不可构造的**:序列之外的尾巴(外推不是观测)、确切的
到访时刻(重现期不是周期)、变化后的未来参数(曲线
出厂日期之后的漂移)、以及"这条河此刻的完整状态"
(一切模型都是快照,预报-校正闭环就是为此存在的)。

### 1.5 最小数据模式(动手者的 schema)

```yaml
# 设计洪水计算书(每步带身份,02 章三规则的落盘)
design_flood_doc:
  series:                                # 序列身份字段必填
    station: str
    years: [start, end]                  # 起讫
    missing: {years: [int], treatment: str}   # 缺测与处理
    historic_floods: [{year: int, q: float,
                       precision: investigated|measured}]  # 历史调查(E2)降精度入册
    naturalized: {done: bool, method: str}    # 人类活动还原
  method:
    dist: gumbel|piii|gev                # 线型身份
    estimator: mom|fitting|mle           # 参数法身份
    test: {goodness: str, p: float}      # 检验身份
  design_values:                         # 概率身份:值+重现期+用途成套
    - {t: 100, x: float, use: design, ci: [float, float]}
    - {t: 1000, x: float, use: check, method_extra: pmf_note}
  hydrograph: {source: unit_hydrograph|model,
               extrapolation_ratio: float}     # 外推幅度显式
  checks:                                # 合理性检查三件套
    - cross_method                       # 多法互比
    - mod_ratio_vs_neighbors             # 模数与邻域对表
    - envelope_curve                     # 地区外包线

# 流域特征卡(产汇流的静态档案)
basin_card:
  area_km2: float                        # 附来源
  river_len_km: float
  slope: {mean_channel_drop: float, method: str}
  shape_factor: float                    # 形状系数
  landcover:                             # 下垫面带时点(反直觉③的防线)
    - {epoch: int, classes: {forest: float, urban: float, ...}}
  response: {time_of_concentration_h: float,
             evidence: E3}

# 雨量站网(证据的证书结构)
raingauge_network:
  stations: [{id: str, years: [int, int],
              relocated: bool, gauge_change: bool}]
  density_km2_per_station: float
  areal_method: thiessen|isohyetal
  representativeness: {storm_scale_note: str,
                       bias_check: E1_anchor}   # 站锚订正
```

注意 `series.missing/historic_floods`、`landcover.epoch` 与
`design_values[].ci` 三处必填:把 02 章的身份纪律写进数据
结构——**数据层自带校验点,是水文计算书区别于论文表格
的第一特征**(与
[工程地质学家族](../讲透工程地质学/03-可构造与结构.md)
schema 同款精神:序列不 naked,区间不缺席)。

## 2. 骨架一:设计洪水计算书(安全的成套语法)

- **序列-方法-参数-设计值-检查五件套缺一不可**:序列
  不带身份(年限/插补/还原),后面全白算;方法与参数法
  成套(线型+矩法/适线,换一个换另一个);设计值必须
  值-重现期-用途三联(x₁₀₀ 设计、x₀.₁% 校核,用途不同
  不可混读)
- **设计值带区间**:抽样区间不是装饰——n=15 与 n=60 的
  x₁₀₀ 抽样标准差约为两倍(实测约 1.9 倍,家族实验断言②),
  单点值报出
  而无区间,是半张合同;区间算法(自助法/近似公式)与
  点估计同表交付
- **合理性检查三件套**:多方法互比(矩法 vs 适线 vs
  极大似然)、洪峰模数与邻域流域对表(单位面积洪峰的
  地区规律)、地区外包线(本站历史最大落在哪条包线内)
  ——**设计值的合法性由检查背书,不由曲线美观背书**
- **非平稳标注**:序列带趋势检验结果(趋势显著与否、
  变点);显著时附非平稳设计值或至少警示语——曲线的
  出厂日期进文档(00 章假设一的 schema 版)

## 3. 骨架二:流域特征卡(产汇流的静态档案)

- **面积是第一参数**:一切面-点换算(面雨量、洪峰模数、
  单位线移置)都以它为底;面积来源(DEM 圈划/纸图量取)
  要写,两种来源差百分之几很常见
- **下垫面带时点**:城市化改写产流(00 章反直觉③),
  `landcover.epoch` 字段是防"序列断裂"的第一道闸——
  用 1980 年的下垫面配 2020 年的暴雨,是设计计算的
  经典错配
- **响应特征带证据级**:汇流时间从公式估(经验式)、
  从单位线反推(E3)、从示踪或实测(更高),三种来源
  精度不同,卡上分级写

## 4. 骨架三:雨量站网 schema(证据的证书结构)

- **密度-尺度匹配**:站网密度必须对暴雨尺度负责——
  局地强对流暴雨(几十 km²)配稀疏站网,面雨量的采样
  误差直接进设计暴雨;schema 里 `density_km2_per_station`
  与 `storm_scale_note` 必须同时出现
- **一致性入册**:迁站、仪器更换、观测时制变更都制造
  假跳变;`relocated/gauge_change` 字段是序列清洗的输入
- **站锚订正**:遥感降水产品(01 章方向四)进设计流程
  前必须以站网实测为锚订正——E5 级证据不能单独支撑
  设计值(02 章规则一)

## 5. 从结构到校验:这套骨架买到了什么

- 计算书带序列身份 → 频率结论可复算(独立于写它的人)
- 设计值带区间 → 抽样风险可见(实验断言②的制度化)
- 流域卡带时点 → 序列一致性可审计(反直觉③的防线)
- 站网带证书 → 输入证据可问责(02 章阶梯的落盘)
- 预报库带基准 → AI 精度声明可对表(01 章方向一的
  评价协议)

## 6. 构造合法性清单(动手前三问)

把任何水文构想变成数据结构之前,先过三问——本家族的
"类型检查":

1. **序列身份写全了吗**:年限/缺测/插补/历史调查/还原
   处理各在哪一行?下垫面与序列同期吗?趋势检验做了吗?
2. **方法与参数可复算吗**:线型+参数法+检验成套吗?
   设计值带区间吗?多法互比与模数对表在检查栏吗?
3. **证据级配得上结论吗**:每个输入数字标了 E1-E5 哪级?
   遥感与模型量(低级)支撑的是初步设计还是最终标准?
   预报结论与设计结论分册了吗?

三问全过,数据才获得进入 [04 章走廊](04-工程水文学转代码.md)
的资格。**水文工程的第一特征不是算得深,是账目清楚。**

## 📌 收束

可构造的是**三类数据对象**(计算书/流域卡/站网 schema),
不可构造的是**序列外的尾巴与到访时刻**;结构化不是为
了替代水文工程师,是为了让序列-频率-设计-预报的链条
可校验、可交接、可复盘。下一章把骨架接上代码:
[04-工程水文学转代码](04-工程水文学转代码.md)。

**🧠 认知升维**:

- **身份眼**:计算书里每个数字带三重身份——序列身份、
  方法身份、概率身份;三缺一即不可复算
- **时点眼**:流域特征卡与序列必须同期——城市化年代里,
  静态档案是序列断裂的元凶
- **区间眼**:设计值是估计量不是测量值;不带区间的
  设计值,是在把抽样误差冒充为安全余量
