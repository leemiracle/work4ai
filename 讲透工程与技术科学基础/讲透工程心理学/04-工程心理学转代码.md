# 04 · 工程心理学转代码——SDT、信任动力学与界面预测的走廊

> **本章回答五问之 Q5(问题→代码转换)。**
> **本质一句话**:人因问题一旦变成「关于命中/虚警的
> 判据计算、信任更新的时间演化、指点时间的对数
> 预测」的计算,就能进代码——d′ 可分解、判据可寻优、
> 信任轨迹可仿真、界面可预测;**唯一不可外包给代码
> 的,是边界阈值的裁定**(什么算超负荷是规范语境)、
> **测量效度的裁定**(量表测到的是不是那个构念)与
> **伦理边界的裁定**(测什么不许测什么)——三件
> 都在人与制度那边。

## 0. 开篇:一个告警面板,代码自己说

「报太漏还是报太吵,到底怎么定?」——
`experiments/trust_calibration_sdt.py` 让代码回答:
信号检测论把「定阈值」变成两个自由度——敏感度 d′
(分辨本领,由信噪比与显示质量定)与判据 c(阈值
策略,由代价结构定)。固定 d′=1.5,扫描判据:命中率
与虚警率沿同一条 ROC 此消彼长;漏检代价从 1 抬到
100,最优判据持续**左移**——命中升,虚警也升,
没有免费的命中(律 1)。再让操作者用指数平滑
T←T+α(R̂−T) 跟踪系统的表现:两个系统**漏检率
相同**,高虚警的那个稳态信任只有 0.70,低虚警的
0.93——虚警的账在信任上扣,狼来了之后再准的系统
也没人听(律 2)。最后把依赖倾向 D 扫一遍:期望
成本是 U 形,底随真实可靠性 R 右移——信任不足与
过度信任都是钱(律 3)。一条脚本把 00 章三条
反直觉全部落成可复现的数。

## 1. 可机械化边界(三件套之一)

**能进代码的**(人因数据化后的一切计算):

| 任务 | 机械化形式 |
|------|-----------|
| SDT 分析 | 四格→H/F→d′/c;ROC 曲线;给定代价寻最优判据 |
| 告警策略优化 | 代价结构驱动的判据寻优(漏检×虚警的期望成本最小化) |
| 信任动力学仿真 | 表现流→感知可靠性→指数平滑信任;稳态与跟踪误差 |
| 依赖策略优化 | 期望成本 U 形扫描;最优 D*(R) 曲线 |
| 界面指点预测 | 菲茨定律 MT=a+b·log₂(2D/W);布局比较 |
| 负荷信号处理 | 生理信号滤波/次任务绩效统计 |
| 差错模式统计 | 分类×潜伏条件交叉表;防线失效率 |

**不能进代码的**(工程心理学的「不可判定域」):

1. **边界阈值的裁定**——TLX 多少算超负荷、SA 问答
   多少分算合格:这是规范与行业语境的制度决策;
   代码能算指标,不能替标准说「多少才算数」
   (标准成文归 41050 标准科学技术的人类工效标准化
   条目,同批在建,纯文本提及)
2. **测量效度的裁定**——量表分数是不是真测到了
   「信任」「负荷」:构念效度是科学判断,代码只能
   做信度统计
3. **伦理边界的裁定**——能测人的什么(生理信号/
   行为日志)要什么边界:制度问题,代码不设线
   (本家族不站队,通说讨论)
4. **个体差异的裁定**——按 P5 还是 P1 设计、豁免
   谁的指标:是设计决策与社会决策的乘积

> 边界的一句话:**代码是判据的验算台与信任的
> 试验场,不是伦理委员会,也不是标准委员会。**

## 2. C1 信号检测论走廊(✅ 已实现)

| 字段 | 类型 | 约束/坑 |
|------|------|--------|
| 模型 | 噪声~N(0,1),信号+噪声~N(d′,1);判「有」当 X>c | 等方差高斯版;生产版扩为任意分布+参数拟合 |
| 命中/虚警 | H=1−Φ(c−d′),F=1−Φ(c) | H 与 F 坐同一条 ROC——改阈值是搬家不是免费午餐 |
| 最优判据 | 等先验 c*=d′/2+(1/d′)·ln[C_fa/C_miss] | 判据由代价定;漏检代价升→c* 左移→H、F 同升(律 1) |
| 分解律 | d′=Z(H)−Z(F),c=−[Z(H)+Z(F)]/2 | 四格在,d′ 与 c 可互相复算(03 章 SDT 卡) |
| 断言风格 | 解析式 vs 数值扫描 vs 蒙特卡洛三方互证 | MC 涨落容差显式;固定种子可复现 |

成品=`experiments/trust_calibration_sdt.py` 实验 [1]。
**改代价换一行参数,改敏感度换一个 d′**——03 章
schema 分离的好处:敏感度(人与系统)、判据(策略)、
代价(场景)分居三列,调优就是在列间扫描。

## 3. C2 信任更新动力学走廊(✅ 已实现)

Lee & See 2004 的最小可算版(00 章故事框三):

```python
# 教学版信任更新器:表现流→感知可靠性→信任轨迹
def trust_step(T, r, alpha):
    return T + alpha * (r - T)        # 指数平滑,稳态≈E[r]
# r_t:本步表现分(命中/正确拒斥=1,虚警=0,漏检=0);
# 断言风格:稳态信任≈感知可靠性均值;漏检率相同而
# 虚警率不同→稳态信任差显著(狼来了,律 2);
# alpha 升→收敛快、轨迹方差大(灵敏-噪声的权衡)
```

要点:其一,**信任是动力学量不是常数**(00 章假设三
的拆除)——同一个系统,信任随经历走;其二,**虚警
在感知可靠性里扣款**,漏检常常不可见——账本不对称
是狼来了的机关;其三,扩展方向(生产版):不对称
惩罚权重、个体 α 差异、信任→依赖的阈值映射——
教学版留三个旋钮。注意本体:指数平滑是滤波器,接
[工程控制论](../讲透工程控制论/README.md)的反馈
语法;正态与 ROC 的数学本体见
[概率论](../../讲透数学/讲透概率论/README.md)。

## 4. C3 菲茨定律走廊(界面预测)

1954 年那条 log₂(00 章美之时刻①)的最小机械化:

```python
# 教学版菲茨定律:指点时间预测与布局比较
import math
def movement_time(D, W, a=0.1, b=0.15):
    # D:到目标距离,W:目标宽度;单位统一即可
    return a + b * math.log2(2.0 * D / W)
# 断言风格:MT 对 D 单调增、对 W 单调减;距离减半
# ≈宽度加倍(难度指数都是 −1 bit);改布局=改 D/W,
# 全键盘/全菜单的总预测时长=逐项求和
# 注意:系数 a、b 因输入设备与人群而异(02 章规则一:
# 指标带任务人群标签);log2(D/W+1) 为通说修正式
```

要点:其一,**界面之争变算术**:两个布局哪个快,
逐项算难度指数求和,不打嘴仗;其二,**系数有主人**
——a、b 随设备(鼠标/触摸/眼动)与人群分档,跨档
比较无效;其三,深度与宽度可互换(−1 bit 的两种
买法),这是 Fitts & Jones 1947「形状编码」在信息论
层面的表亲:降低难度指数,不止加宽目标一条路。

**走廊三警告**(共用):

1. 四格不存不复算:SDT 分析只报「准确率」就丢掉了
   d′ 与 c 的分离权——先存四格,再谈一切(03 章)
2. 仿真的参数要有出处:α、代价权重、Fitts 系数都是
   带标签的测量值,不是自然常数;参数裸奔的仿真
   是剧情演示,不是证据(02 章规则一)
3. 最优≠可接受:代码给出 c* 与 D*,但「这个虚警率
   用户接不接受」「这个依赖水平组织担不担」是
   制度裁定(不可判定域第一条)

## 5. 工程师落点(把这门学科带回家)

- **告警阈值=判据工程**:你维护的每个告警面板、
  审核规则、风控拦截都是 SDT 系统——改阈值是沿
  ROC 搬家:漏报降则误报升,**先问代价结构再动手**
  (律 1 是一切告警调优的第一课)
- **灰度发布=信任校准**:新功能推给用户就是新队友
  入队——早期每次失败都按 α 加权扣信任;「狼来了」
  律(律 2)说:宁可先保守(低虚警)攒信任,也别
  用激进策略烧掉依赖
- **on-call 与告警治理=警觉工程**:告警风暴训练出
  「全是狼」的值班员;合并告警、分级、静默期治理
  的本质是在修感知可靠性 R̂(律 2 的运营版)
- **代码评审与事故复盘=差错解剖**:把「人为差错」
  翻译成四分类+潜伏条件(00 章分类学)——检查单
  防 lapse,自动化防 slip,决策支持防 mistake;
  「加强培训」只对 mistake 一格有效
- **一切「指标+阈值」系统对表 FS 的工况语法**:与
  [工程物理学](../讲透工程物理学/04-工程物理学转代码.md)
  的误差预算三段式对表——同宗的账本纪律:指标不
  naked,代价有出处,阈值有签名

## 📌 收束

走廊三条:C1 SDT 管「判据怎么定、虚警漏检怎么权衡」,
C2 信任动力学管「用户的信怎么攒、怎么崩」,C3 菲茨
定律管「界面怎么算」;三条共用一条边界——**边界
阈值、测量效度、伦理边界永远留在人与制度那边**。
跑到这里回头再看 00 章那句话:人是最灵活也最不可靠
的元件;代码算的是人的账本,不是人本身。

**🧠 认知升维**:

- **两自由度眼**:一切「准不准」先拆两栏——判得清
  (d′)与卡得严(c);改阈值是搬家,不是免费午餐
- **账本眼**:信任有账本,虚警扣款、命中进账、
  漏检常常不入账——不对称是机关
- **U 形眼**:依赖与信任的代价曲线是 U 形;校准
  不是「多信」也不是「少信」,是把 D 调到 R 对应
  的底部
