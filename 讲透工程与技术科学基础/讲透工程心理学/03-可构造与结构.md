# 03 · 可构造与结构——需求卡、差错报告与 SDT 记录作为数据对象

> **本章回答五问之 Q4(可构造性与结构)。**
> **本质一句话**:工程心理学里「可构造」的不是人本身,
> 而是**人因问题的三类数据对象**——人因需求规格卡把
> 「系统要迁就人的哪条边界」写成人群-任务-指标-验收
> 成套的条目,差错报告 schema 把「怎么错的」写成分类+
> 潜伏条件+防线的解剖结构,SDT 实验记录卡把「判得多
> 准」写成刺激-判据-命中率-虚警率-d′ 成套的测量结构;
> 把这些结构显式化,人因工作就从手艺变成工程:可校验、
> 可对表、可交接(04 章走廊的地基)。

---

## 0. 开篇:一次「人因评估」的三件家具

拆开任何一次严肃的人因评估(界面评审/事故复盘/告警
调优),都能拆出三件家具:其一是**人因需求规格卡**
(系统迁就人的哪条边界——人群、任务、指标、验收),
其二是**差错报告**(怎么错的——分类、潜伏条件、
防线),其三是**SDT 实验记录卡**(判得多准——d′ 与
判据成套)。三件家具在手,00 章翻译链的每一环就变成
**可机检的数据流水线**;从三哩岛复盘到人-AI 组队
时代,在数据结构层面是同一套 schema——变的是测量
密度,不变的是结构。

## 1. 什么是「可构造」的:三类结构对象

| 对象 | 数化身 | 可构造性 | 构造中的坑 |
|------|--------|---------|-----------|
| **人因需求规格卡** | 人群×任务×边界指标×验收阈值,成套条目 | ✅ 高度可构造 | 「界面友好」这类无验收条款的空话;指标不带人群任务标签(02 章规则一) |
| **差错报告 schema** | 差错四分类+触发序列+潜伏条件+防线审计 | ✅ 高度可构造 | 「人为差错」一句结案(00 章反直觉③);分类混用(拿防 slip 的对策治 mistake) |
| **SDT 实验记录卡** | 刺激参数+判据 c+H/F+d′+代价结构,成套 | ✅ 高度可构造 | 只报准确率不报 H/F(准确率把 d′ 与判据搅成一团);判据不注代价结构 |
| **负荷与信任记录** | TLX 六维+依赖率+信任轨迹+校准差 | ✅ 可构造 | 负荷单证(02 章规则二);信任不与真实可靠性并排(失校无从谈起) |
| **团队涌现状态记录** | 凝聚/安全感/共享心智分+团队构成 | ✅ 可构造(新) | 用个体量表拼团队分(涌现状态在个体层不存在,01 章方向二) |

**不可构造的**:个体下一秒的状态(一切指标是统计
量)、体验的总量(涌现不可穷尽)、「该不该信」的
立场(校准是量,立场不进 schema)、以及没测过的
任务-人群组合(标签外的外推都是赌)。

### 1.5 最小数据模式(动手者的 schema)

```yaml
# 人因需求规格卡(每条带人群任务标签与验收阈值)
hf_requirement:
  id: str
  population: {who: operators, expertise: novice|expert,
               shift: day|night}                  # 平均人假设的补丁字段
  task: {name: str, scenario: normal|abnormal}
  boundary: {kind: perceptual|cognitive|motor,
             metric: search_time_s|err_rate|tlx|d_prime,
             limit: float}                        # 人的边界是设计输入
  acceptance: {metric: str, threshold: float,
               evidence_min: E3-simulator|E4-field}   # 验收要的最低证据级

# 差错报告(解剖结构:分类+潜伏条件+防线)
error_report:
  event: {when: str, system: str, phase: normal|transition|abnormal}
  classification: slip|lapse|mistake|violation     # 四分类不可混(00 章)
  sequence: [step1, step2, {step3: error_here}]
  latent_conditions: [ambig_display, similar_controls,
                      alarm_flood, mode_ambiguity] # 设计预置的病原
  defenses: {intended: [checklist, confirmation],
             failed: [which_one, why]}
  fix: {design_change: str, not_training_only: bool}  # 「加强培训」不是唯一答案

# SDT 实验记录卡(测量-判据-代价成套)
sdt_record:
  task: {signal_def: str, base_rate: float, population: str}
  results: {hits: int, misses: int, false_alarms: int,
            correct_rejections: int}
  derived: {d_prime: float, criterion_c: float,
            roc_curve_ref: str}                    # d′ 与 c 分居两栏
  cost: {c_miss: float, c_fa: float}               # 判据的最优性由代价定(律1)
  fidelity: online|lab|simulator|field             # 复现链站位(01 章方向三)
```

注意 `population`、`cost` 与 `fidelity` 三处必填:把
02 章的证据纪律写进数据结构——**数据层自带校验点,
是人因工程区别于论文表格的第一特征**(与
[工程物理学家族](../讲透工程物理学/03-可构造与结构.md)
schema 同款精神:参数不 naked,证据不缺席)。

## 2. 骨架一:人因需求规格卡(边界的合同化)

- **人群-任务-指标-验收四件套缺一不可**:边界指标
  (如「告警响应 d′≥2.0」)离开人群任务就是空话;
  验收阈值离开最低证据级(E3 模拟器还是 E4 现场)
  就是软条款——供应商可以用 E2 实验室数据过关
- **边界写「人」不写「机」**:好条款写「新手操作员
  在异常工况下 3 秒内定位首因告警(TLX≤60)」,
  坏条款写「系统响应≤200 ms」——后者是性能规格,
  不是人因规格
- **异常工况必须占位**:三哩岛的教训在 schema 层的
  翻译是——只有常态条款的规格卡是半张合同;交接、
  告警洪峰、模式切换各占至少一条(00 章故事框二)

## 3. 骨架二:差错报告 schema(解剖的流水线)

- **分类先于归因**:slip/lapse/mistake/violation 四分
  类决定对策方向(00 章美之时刻③):分类错了,防线
  修错楼层
- **潜伏条件与防线并排**:差错之所以穿透,是因为
  设计预置了病原、防线恰好失效——schema 强制两栏
  并写,复盘才不会停在「人错了」
- **设计变更优先字段**:`not_training_only` 是本 schema
  的灵魂布尔值:Fitts & Jones 1947 的原始姿态——
  差错数据进设计,不是进检讨书

## 4. 骨架三:SDT 实验记录卡(判断的完整账目)

- **H/F 原始四格必存**:命中/漏检/虚警/正确拒斥是
  重建一切的地基;d′ 与 c 是派生量,丢了四格就丢了
  复算权
- **d′ 与 c 分居两栏**:敏感度(人与系统的辨别力)
  与判据(阈值策略)是**两个自由度**(家族实验律 1)
  ——只报「准确率 92%」把两者搅成一团:可能是
  d′ 高,也可能只是判据松(虚警都藏在被放弃的
  那些机会里)
- **代价结构入卡**:同一 d′ 下最优判据由漏检/虚警
  代价定(律 1 的解析式);换场景(核电站 vs 垃圾
  邮件)代价变了,判据该搬家——卡上不存代价,
  判据就没有「应然值」可比
- **fidelity 站位**:01 章方向三的落字段版——在线/
  实验室/模拟器/现场,跨站结论先看站位再谈迁移

## 5. 从结构到校验:这套骨架买到了什么

- 规格卡带验收与证据级 → 「友好」从形容词变成
  可拒收的条款
- 差错报告带分类与潜伏条件 → 复盘从归责变成解剖,
  设计变更有靶子
- SDT 卡带四格与代价 → 判据调优可复算,「报太多/
  报太漏」有应然值
- 负荷信任并排记录 → 校准差(跟踪误差)可算,
  U 形两翼的成本可估(律 3 的数据前提)

## 6. 构造合法性清单(动手前三问)

把任何人因构想变成数据结构之前,先过三问——本家族
的「类型检查」:

1. **人群任务写全了吗**:每条指标、每份记录,who×
   task×state 标签齐吗?新手/专家、白天/凌晨分档
   了吗?(02 章规则一)
2. **代价与代偿声明了吗**:SDT 卡存了代价结构吗?
   负荷结论主客观双证了吗?「能应付」的交换代价
   写了吗?(02 章规则二/三)
3. **分类与潜伏齐了吗**:差错报告是四分类哪一类?
   潜伏条件列了吗?对策里设计变更字段置真了吗?
   ——以及团队层结论,用团队层测量了吗?

三问全过,数据才获得进入 [04 章走廊](04-工程心理学转代码.md)
的资格。**人因工程的第一特征不是测得巧,是账目清楚。**

## 📌 收束

可构造的是**三类数据对象**(需求规格卡/差错报告/
SDT 记录卡),不可构造的是**个体下一秒的状态与体验
总量**;结构化不是为了替代人因分析师,是为了让
测量-规格-复盘-调优的链条可校验、可交接、可复盘。
下一章把骨架接上代码:[04-工程心理学转代码](04-工程心理学转代码.md)。

**🧠 认知升维**:

- **合同眼**:人因需求是合同不是愿景——没有验收
  阈值与最低证据级的条款,等于没写
- **解剖眼**:差错报告的完整形态=分类+序列+潜伏+
  防线;停在「人为差错」的复盘都是半份
- **双栏眼**:d′ 与 c 分居两栏——「准」有两个意思,
  判得清(d′)与卡得严(c),别搅在一起
