## 0. 开篇:一张验收单,代码自己说

「抽多少件、允许几个缺陷,AQL 到底保护谁?劣标准
为什么能赢?」——`experiments/oc_curve_and_lockin.py`
让代码回答:计数抽样方案 (n,Ac) 的接受概率
P_a(p)=Σ C(n,k)p^k(1−p)^(n−k)(k≤Ac),扫描批缺陷率
p,P_a 严格单调降,n 增大曲线变陡(判别力升)(律1);
两点定样本量:AQL=1%(α=5%)给样本量**上限**,
LTPD=5%(β=10%)给**下限**——**Ac=0 的零接受方案两
限相撞(5<45),单自由度钉不住两个风险点**(律2 第一
课),而 LTPD 单点设计给出 n=45(5%)→76(3%)→230
(1%,理论值 229.1)的样本量代价表:**两点越靠近,样本量超线性
激增**(律2 第二课);锁定动力学
ds/dt=k·s(1−s)·[a(s−1/2)+q]:质量差 q=−0.1 的劣标准,
先发份额过临界值 s*=1/2−q/a 仍锁死胜出,低于则被
翻盘(律3,QWERTY 叙事的机制化)。一条脚本把 00 章
反直觉①②与 02 章风险成对规则全部落成可复现的数。

## 1. 可机械化边界(三件套之一)

**能进代码的**(标准数据化后的一切计算):

| 任务 | 机械化形式 |
|------|-----------|
| 抽样方案设计 | 二项 OC 曲线计算+两点风险求解(n,Ac)网格搜索 |
| 术语表机读 | 术语条目 schema+同义词归一+循环定义检测(本体/概念树) |
| 分类编码机读 | 分类树(层级码)+编码唯一性与层级一致性校验 |
| 机器可读标准 | 条款结构化(requirement 对象)+效力档字段 |
| 合规检查 | 「应」条款→可执行断言(规则编译+输入实例判定) |
| 锁定仿真 | 份额动力学(RK4/欧拉积分)+临界值解析对表 |
| 体系表维护 | 图遍历:作废引用检测、依赖冲突检测、复审到期提醒 |

**不能进代码的**(标准科学技术的「不可判定域」):

1. **协商一致的收敛**——分歧怎么妥协成条款,是人的
   过程;代码能管理提案与意见(工作流),不能替代
   共识本身
2. **FRAND 费率裁定**——「公平合理」的个案裁量和
   管辖法域绑定,是法律判断,不是可判定规则
3. **立标时机的裁定**——太早锁死、太晚错过(00 章
   反直觉①);窗口判断是战略决策,预标准化路线图
   (01 章方向二)只是它的情报输入
4. **符合性边界的裁量**——测试未覆盖的等同性判定
   (「差 2% 算不算符合」)最终靠委员会解释,规则引擎
   只执行已裁定的解释

> 边界的一句话:**代码是条款的验算台与风险的模拟器,
> 不是委员会。**

## 2. C1 抽样 OC 曲线走廊(✅ 已实现)

| 字段 | 类型 | 约束/坑 |
|------|------|--------|
| 接受概率 | P_a(p)=Σ_{k≤Ac} C(n,k)p^k(1−p)^(n−k) | 精确二项(math.comb),不用正态近似(小 n 失真) |
| 单调性 | P_a 对 p 严格单调降 | 曲线是「验收严格度」的真容:任何方案都是连续过渡,没有悬崖 |
| 判别力 | n 增大→最大斜率增大、p50 左移 | 「n 越大越严」的精确含义是判别力,不是单点接受率 |
| 两点设计 | (p₁,α) 给 n 上限,(p₂,β) 给 n 下限 | Ac=0 单自由度常无解(律2 第一课);网格搜 (n,Ac) 才能钉两点 |
| 锁定 | ds/dt=k·s(1−s)·[a(s−1/2)+q],临界 s*=1/2−q/a | 劣标准(q<0)临界份额右移;参数化路径依赖 |

成品=`experiments/oc_curve_and_lockin.py`。**改严格度换
一行 (n,Ac),改风险换一组 (α,β),改生态换一对
(a,q)**——03 章 schema 分离的好处:方案(样本量档)、
风险(两点)、生态(网络与质量)分居三列,敏感性分析
就是在列间扫描。

## 3. C2 术语与分类编码机读走廊(把语义钉死)

标准基础学(4105020)的核心工程:术语标准化与信息
分类编码,本质都是**把语义写成可机检的树**:

```python
# 教学版术语条目:同义词归一 + 循环定义检测(02 章规则三)
terms = {
  "认证": {"synonyms": ["产品认证(口语)"], "def": "第三方对产品/体系/人员符合性的证明"},
  "认可": {"synonyms": [], "def": "对认证机构能力的承认——认证的认证"},
  # ...
}
def check_terms(terms):
    # 1) 同义词必须归一到首选术语(一物多名→机检报警)
    # 2) 定义不得以自身词根开头(循环定义检测)
    # 3) 概念关系(属/分)不成本环(本体树无环断言)
    ...
# 断言风格:同义词表两两不相交;概念树是无环图;
# 分类码前缀包含(层级一致性:子类码以父类码为前缀)
```

要点:其一,术语表是**受控词表**(controlled
vocabulary),机器查的不是「意思」是**归一**:同义
术语折叠到唯一首选词,检索与互操作才成立;其二,
分类编码(如学科代码 GB/T 13745)是**树**:码的层级
一致性可断言(41050 的前缀必须是 4105x 族),树无环
可断言——**编码标准的「对不对」大部分是图性质,图
性质全部可机检**;其三,03 章术语条目 schema 的
`synonyms` 字段是这条走廊的输入接口。

## 4. C3 机器可读标准走廊(条款→规则)

「机器可读标准」的两级台阶:结构化(条款可解析)→
可执行(条款可判定)。最小机械化是**把「应」编译成
断言**:

```python
# 教学版:从 requirement 对象到可执行断言(03 章文献卡的下游)
def compile_rule(req):
    # req = {clause: "7.2", verb: "shall", text: "接口超时不得超过 3 s",
    #        verification: "test_clause_9_1", params: {"timeout_max_s": 3.0}}
    if req["verb"] != "shall":
        return None                    # 宜/可不编译为强制断言(02 章效力档)
    return lambda measured: measured["timeout_s"] <= req["params"]["timeout_max_s"]
# 断言风格:每条编译出的规则必须可对「测试实例」给出
# True/False(可判定性);给不出测试方法的条款编译失败——
# 02 章规则一的运行时版;「应」条款的验证覆盖率=编译成功率
```

要点:其一,**「应」编译,「宜」不编译**——效力档
直接决定代码身份(要求=断言,推荐=告警,允许=不管);
其二,**编译失败是信号不是噪声**:条款写「应鲁棒」
而参数表给不出「鲁棒」的度量,编译器当场报「不可
判定条款」——机器可读化是对标准起草质量的最狠审计;
其三,合规检查=断言集合对实例集合的批量求值,生态
测试套件就是事实标准的民间合格评定(00 章练习 3 的
机制化)。AI 时代这条走廊是新前线:评测基准(01 章
方向二的「先有尺」)正是「应条款的参数化」产业。

**走廊三警告**(共用):

1. 两点风险不齐不收算:只写 AQL 的验收条款是半张
   合同(02 章规则二;律2 的 Ac=0 教训)
2. 术语不归一不互操作:同义词表与编码树先过 C2,再
   谈数据对表
3. 断言不可判定就退回人:编译失败的条款交委员会
   裁定,不要硬造参数(不可判定域第四条)

## 5. 工程师落点(把这门学科带回家)

- **接口眼→API 设计**:每个 API 端点都是一次立标——
  签名是界面,版本化是复审制度,弃用(deprecation)
  流程是转换成本管理;**写 API 文档时你在做 Whitworth
  做过的事,认真程度对齐一下**
- **OC 思维→一切抽检**:code review 抽查率、测试抽样、
  内容审核抽检,都是 (n,Ac) 方案——先问两个风险点:
  好提交被误拒谁付成本,坏提交溜过谁付代价;**没有
   OC 曲线的抽检制度是拍脑袋**
- **锁定眼→依赖治理**:引入一个依赖=给一个标准投票;
  装机量(社区规模)、转换成本(替换工作量)、质量差
  (律3 的 a 与 q)三参数过一遍再决定——**依赖选择是
  微型的标准战**
- **验证眼→需求工程**:「应」条款写进需求单时,同一
  时间写测试方法;写不出测试的需求不是需求,是愿望
  (02 章规则一的跨域移植)

## 📌 收束

走廊三条:C1 抽样 OC 曲线(已成)管「验收的严格度住
在哪个量里、两点风险怎么定方案」,C2 术语与编码机读
管「语义怎么钉成树」,C3 机器可读标准管「条款怎么变
成断言」;三条共用一条边界——**协商、裁定、时机永远
留在人与程序那边**。跑到这里回头再看 00 章那句话:
市场选出事实,委员会写成规则,认证让它长牙;代码算
的是规则的算术,不是规则本身。

**🧠 认知升维**:

- **判别力眼**:「抽多少才严」的答案不是样本量,是
  OC 曲线的斜率——严格度是曲线形状,不是单点
- **归一眼**:互操作的前提是一物一名——同义词表与
  编码树是所有数据工程的第 0 层
- **编译眼**:条款的最高礼遇是变成断言;编译不过的
  「应」,就是起草时欠下的债
