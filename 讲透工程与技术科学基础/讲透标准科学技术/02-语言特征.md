# 02 · 语言特征——助动词的工程学:标准语言与它的证据规则

> **本章回答五问之 Q3(语言特征:表达力/逻辑性质/规范化)。**
> **本质一句话**:标准科学技术说的是**一种把承诺分级
> 的语言**——三个助动词(应/宜/可,shall/should/may)
> 把条款切成强制、推荐、允许三档,「规范性/资料性」
> 把文本切成有牙齿与没牙齿的两半,AQL/LTPD 把风险
> 写进表格,de facto/de jure 与 FRAND 把权力写进术语;
> 判断一段标准写作的优劣,不看文采,看**每条「应」
> 背后站着哪种可执行的验证**。三栏分别回答:这套语言
> 能说什么(表达力)、条款凭什么可执行(逻辑性质)、
> 术语如何被钉死(规范化)。

---

## 0. 开篇:三个助动词的一场官司(教学例)

📖 **故事框(教学例)**。同一台设备,三种写法:甲标准
写「设备**应**能在 −40 °C 启动」,乙标准写「设备**宜**
能在 −40 °C 启动」,丙标准写「设备**可**配备低温启动
装置」。合同引用甲:−40 °C 启动是**要求**,做不到即
不符合,验收可以据此拒收;引用乙:只是**推荐**,做
不到不构成不符合,仅说明偏离了「良好实践」;引用丙:只是**允许**,装不装都对。三个助动词,三档法律
效力——标准文本的一个字母之差,在验收单上是一批货
的归属(教学例,非判例引用;工程合同通说如此理解)。
标准语言的全部要义浓缩于此:**词汇即效力,语气即
合同**。

## 1. 表达力:标准语言能说什么(三栏之一)

**能说的**:

| 能力 | 语件 | 例 |
|------|------|-----|
| 承诺分级 | **助动词语言** | 应(shall,要求)/宜(should,推荐)/可(may,允许)/不应(shall not,禁止)——GB/T 1.1 与 ISO/IEC 导则的动词表 |
| 文本分级 | **规范性/资料性语言** | 规范性附录=合同的一部分;资料性附录=仅供参考——同册文本两种效力 |
| 风险定量 | **抽样语言** | AQL(可接受质量限)/LTPD(批允许缺陷率)/OC 曲线/生产方与使用方风险(α,β)——把「多严才算严」写成数字 |
| 接口钉死 | **公差语言** | 基本尺寸/极限偏差/配合等级——把「一样」定义为「差多少以内」 |
| 状态显式 | **版本语言** | 现行/修订/废止/部分代替——标准文献的时效身份(GB/T 13016 体系表) |
| 权力显式 | **产权语言** | SEP(标准必要专利)/FRAND(公平合理无歧视)/免版税承诺——把专利嵌入写成条款 |

**不能说的**(表达力边界,与生俱来):

- **不可测的品质**:「优雅」「鲁棒」「以人为本」进不了
  规范性条款,只能退居资料性——语言系统性地低估难以
  量化的价值(00 章假设二的代价)
- **协商的分歧**:共识文本只登「最大公约数」,谁反对、
  为什么反对,不进正文(进会议纪要,那是另一文体)
- **未来的接口**:标准发布即过时开始——技术前进与
  条款冻结天然错位,补救靠版本化语法,不靠正文
- **分布的行为**:传统条款写「单件满足 X」,统计学习
  系统「90% 的样本满足 X」算不算符合——分布符合性
  的语法是当前真正的语言缺口(01 章方向四研究缺口)

## 2. 逻辑性质:条款的可验证性规则(三栏之二)

标准条款的可信度来自**每条要求可追溯到一种验证**,
不是措辞严厉:

### 2.5 验证强度阶梯(标准版 V1-V4)

| 阶梯 | 措辞 | 验证状态 | 注意 |
|------|------|---------|------|
| V1 型式试验级 | 「应满足 X(按第 N 条试验)」 | 条款+测试方法成对 | 「应」无测试方法=不可判定条款(见规则一) |
| V2 检验批抽样级 | 「按 GB/T 2828.1,AQL=1%」 | 统计验证 | α/β 双风险显式;OC 曲线是条款的真容 |
| V3 体系审核级 | 「组织应建立…过程」 | 过程证据 | 认证对象是管理体系不是产品性能(42001/9001 族) |
| V4 声明符合级 | 「供方声明符合」 | 自我声明 | 无第三方;效力最弱,靠市场与法律责任兜底 |

### 2.6 三个内部语法规则

- **验证成对规则**:每条「应」必须能指向一种判定程序
  (试验方法/检验规则/审核证据);写「应」而给不出
  验证=**写了一张无法兑付的支票**——审查标准草稿的
  第一动作就是把所有「应」抽出来对表
- **风险成对规则**:抽样条款必须双侧显式——保护生产方
  (好批 p₁=AQL 误拒概率≤α)与保护使用方(坏批
  p₂=LTPD 溜过概率≤β);只写 AQL 不写 β 的条款是
  半张合同(家族实验律2:Ac=0 钉不住两点的原因)
- **效力分层规则**:规范性与资料性必须逐件标注(条款/
  附录/图表各自标);混用=把参考冒充要求,或把要求
  稀释成参考——标准文本的「两种线型」(与
  [工程地质学](../讲透工程地质学/README.md)证据级
  分线型同宗:揭示画实线,推断画虚线)

## 3. 规范化:术语与对译(三栏之三)

- 国际语境:ISO/IEC 导则 Part 2(标准起草)、ISO/IEC
  Guide 2(术语总纲);中文语境 GB/T 1.1。中英写作必须
  声明口径——特别是 conformity 这类制度词
- 度量:抽样语言无量纲(概率);公差语言带单位与
  温度基准(20 °C 标准温度,通说);版本语言带日期
  与代替关系

**术语对译表(日常语→标准语;中英对照)**:

| 中文(标准语) | 英文 | 日常语陷阱 |
|------|------|---------|
| 应 | shall | ≠「必须」(must 多用于法规自身;标准里 shall=要求);不写「应尽量」 |
| 宜 | should | ≠「最好」:推荐=不满足不算不符合 |
| 可 | may | ≠「可以」随意:允许=效力中性 |
| 不应 | shall not | 禁止;≠「不建议」(should not) |
| 协商一致 | consensus | ≠全体同意:重大异议被考虑后大体同意(ISO/IEC Guide 2 义) |
| 一致性/符合性 | conformity | 产品/过程对条款的满足;中文两译并存,合规语境常用「符合性」 |
| 合格评定 | conformity assessment | 证明满足的全部活动:检测+认证+认可的总纲 |
| 认证 | certification | **第三方**对产品/体系/人员的符合性证明 |
| 认可 | accreditation | 对**认证机构能力**的承认——「认证的认证」(03 章区分卡) |
| 可接受质量限 | AQL (acceptance quality limit) | ≠「合格线」:抽样体系锚点,好批仍可能被拒(α) |
| 批允许缺陷率 | LTPD (lot tolerance percent defective) | 使用方风险点;p₂ 处接受概率≤β |
| 操作特性曲线 | OC (operating characteristic) curve | 抽样方案的「真容」:接受概率对 p 的整条曲线 |
| 事实标准 | de facto standard | 市场选出的;≠「事实上的」修辞性用法 |
| 法定标准 | de jure standard | 机构发布的;法定性≠强制性与传播力 |
| 标准必要专利 | SEP (standard-essential patent) | 实施标准绕不开的专利;「必要」由声明+审查认定 |
| 公平合理无歧视 | FRAND/FAIR-REASONABLE | SEP 许可承诺;各法域对「合理费率」判定不一 |
| 互换性 | interchangeability | 按规定条件装配/替换仍满足性能(Whitworth 起点) |
| 公差 | tolerance | 允许的偏差区间;「一样」的工程定义 |
| 体系表 | standards system table | 标准体系的结构化清单(GB/T 13016) |
| 机器可读标准 | machine-readable standard | 条款可被程序解析执行(04 章 C3) |

## 📌 收束

标准科学技术语言=**承诺分级的助动词系统(应/宜/可×
规范性/资料性)+验证成对的证据规则(V1-V4 阶梯)+
制度术语的钉死术(一致性/认证认可/AQL/LTPD/FRAND)**。
它写下的每个「应」都在等一行测试方法与一份风险账。

[03-可构造与结构](03-可构造与结构.md)。

**🧠 认知升维**:

- **效力眼**:见到任何条款先问效力档——应还是宜?规范
  性还是资料性?语气即合同
- **验证眼**:每条「应」背后站着什么验证?试验方法、
  抽样方案还是审核证据?没有验证的「应」是空头支票
- **风险眼**:抽样条款永远双侧——AQL 护生产方,LTPD
  护使用方;只写一侧的验收标准是半张合同
