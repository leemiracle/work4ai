# 03 · 可构造与结构——布局卡、路线卡与判据卡作为数据对象

> **本章回答五问之 Q4(可构造性与结构)。**
> **本质一句话**:工业工程学里「可构造」的不是干活的过程,
> 而是**它的三类结构对象**——设施布局卡把「系统怎么摆」
> 写成活动单位+物流量的从至账,工艺路线卡把「活怎么流」
> 写成任务优先图+工时的拓扑表,控制图判据卡把「品怎么稳」
> 写成中心线+控制限+判异规则的决策表;把这些结构显式化,
> 生产系统的设计就从车间手艺变成工程:可校验、可复算、
> 可交接(04 章走廊的地基)。三张卡恰好对应三个优化对象:
> 空间(布局)、时间(路线)、变异(质量)。

---

## 0. 开篇:一个新建产线任务的三件结构化家具

拆开任何一次严肃的产线设计任务(新线规划/产线改造/过程
管控),都能拆出三件家具:其一是**设施布局卡**(哪些活动
单位、各占多大地盘、之间物流量多大——决定搬运成本与
在制品的行走距离),其二是**工艺路线卡**(哪些工序、各
多久、先后怎么约束——决定节拍、站数与平衡的输入),
其三是**控制图判据卡**(过程的关键质量特性、控制限怎么
定、什么形态判异——决定稳定性怎么「被看见」)。三件家具
在手,02 章的语言就变成**可机检的数据流水线**:家族实验
的 10 工序优先图(律1 的 TASKS 表)就是一张极简工艺路线
卡;从福特的节拍表到数字孪生的产线模型(01 章方向四),
在数据结构层面是同一套 schema——变的是规模与刷新率,
不变的是结构。

## 1. 什么是"可构造"的:三类结构对象

| 对象 | 数化身 | 可构造性 | 构造中的坑 |
|------|--------|---------|-----------|
| **设施布局卡** | 活动单位+从至表(流量×距离)+相邻关系等级 | ✅ 高度可构造 | 物流量只算物料不算信息与人的行走;距离用中心距还是边界距不统一;关系等级(REL 图)与流量账两张皮 |
| **工艺路线卡** | 任务(工时/前序)+优先图+节拍 | ✅ 高度可构造 | 工时不报件数语境(02 章件数眼);优先图漏边(做不了的拓扑)或加边(假约束);节拍由产能倒推(应为市场需求正推) |
| **控制图判据卡** | 特性+中心线+控制限+判异规则集 | ✅ 高度可构造 | 控制限照抄公差限(两限混用,02 章第一违规);判异规则不写误报率;给失控过程算 Cpk |
| **优先图(RPW 权重)** | 任务→(工时,前序)+RPW 权重表 | ✅ 高度可构造 | 把 RPW 当最优解(它是启发式;K*=⌈Σt/C⌉只是下界,命中与否要断言) |
| **排队模型卡** | 到达率/服务率/规则(FCFS 等) | ✅ 高度可构造 | 把峰值到达率当平均(平稳性假设的账,00 章假设二);忽视优先级规则对等待分布的改写 |

**不可构造的**:「标准方法」本身(动作怎么取消合并重排,
是现场知识)、评比系数的取值(「这个工人是正常速度的
1.1 倍」是判断不是测量)、改善的优先级政治(先改哪条线
涉及资源与人的安排)、以及节拍的市场选择(需求预测是
商业决策)——结构与决策要分开,数据结构只承载前者。

### 1.5 最小数据模式(动手者的 schema)

```yaml
# 设施布局卡(空间优化对象)
facility_layout:
  units:                                       # 活动单位(不是设备台数)
    - {id: str, name: str, area: num, type: work|store|office}
  from_to:                                     # 从至表:物流的账本
    - {from: unit, to: unit, flow: num, unit_flow: "件/日"|"盘/日"}
  distance_metric: centroid|boundary           # 距离口径必须统一
  constraints:
    - {type: fixed, unit: str, reason: str}    # 定死不动的(承重/洁净等)
    - {type: adjacent|separate, units: [a, b], reason: str}  # 相邻/分离约束
  objective: {name: 总移动量, formula: "Σ flow_ij × dist_ij"}  # 布局的目标函数
  # 校验:无孤立单位;from_to 对称项已合并或口径写明;
  # 目标值可复算——换一版布局,总移动量能重新算出来比较

# 工艺路线卡(时间优化对象:线平衡的输入)
process_route:
  part: {name: str, version: str}
  takt: {value: num, unit: min, source: market}   # 节拍:市场正推,不是产能倒推
  tasks:                                         # 工序清单
    - {id: str, desc: str, time: num, unit: min,
       time_basis: standard|unit_1|unit_n,        # 工时语境必写(02 章件数眼)
       preds: [id]}                               # 前序(优先图的边)
  totals: {sum_t: num}                            # Σt(校验:求和一致)
  balance: {k_star: "⌈Σt/C⌉", heuristic: RPW,     # 站数下界+排站方法
            efficiency: "E=Σt/(K·C)"}             # 效率必报分母
  # 校验:优先图无环;每任务前序齐;C≥max task time;
  # 排站结果逐站负荷≤C、前序所在站≤本站(04 章 C1 的断言组)

# 控制图判据卡(变异优化对象)
control_chart:
  characteristic: {name: str, unit: str, type: variable|attribute}
  sampling: {scheme: "均值-极差( x̄-R )", subgroup_size: num,
             frequency: str}                      # 抽样方案(组内/组间变异的分家)
  limits:
    center_line: {value: num, basis: "历史受控数据均值"}
    control_limits: {sigma: 3, source: "组内变异(如 R̄/d₂)",
                     value: [LCL, UCL]}           # 控制限来自过程声音,不是公差
    spec_limits: {value: [LSL, USL], source: 产品要求}  # 公差限另记,与控制限分栏!
  rules:                                          # 判异规则集(每条必配误报率)
    - {id: R1, text: "1 点落在 A 区以外(出界)", false_alarm_rate: "0.0027"}
    - {id: R2, text: "连续 9 点落在中心线同一侧", false_alarm_rate: "~0.0038"}
  capability: {index: Cpk, precondition: 过程受控}   # 能力前提显式化
  reaction: {on_signal: "查可查原因,记录与处置", on_noise: "不干预"}
  # 校验:控制限≠公差限(数值不重合口径必查);判异规则数越多
  # 误报率越高(规则的组合账);Cpk 只在受控前提下有效
```

注意 `time_basis`、`spec_limits` 与控制限分栏、`false_alarm_rate`
三处必填:把 02 章的三栏纪律写进数据结构——**数据层自带
校验点,是 IE 文档区别于普通文档的第一特征**(与
[计量学家族](../讲透计量学/03-可构造与结构.md)预算表
schema 同款精神:数值不 naked,前提不缺席)。

## 2. 骨架一:设施布局卡(空间的账本)

- **从至表是布局的心脏**:行=来处,列=去处,格=流量;
  布局的目标函数(总移动量=Σ流量×距离)直接从这张表计算
  ——**换布局不改表,只改距离**,这是布局可比较的前提
  (系统布置设计 SLP 的工程骨架,通说)
- **两张皮要合账**:物流量账(from_to)与相邻关系等级
  (REL:安全/管理/沟通等非物流理由)必须同表决策——只按
  物流摆布局,把危险品与办公区摆到一起,是账目清楚、决策
  错误
- **距离口径统一**:中心距与边界距差一个单位尺度;两版
  布局用不同口径比较,是比较两个不同的目标函数

## 3. 骨架二:工艺路线卡(时间的拓扑)

- **优先图是工艺的骨架**:任务为点、前序为边;家族实验的
  TASKS(10 工序,Σt=41)就是最小范本——**图无环是合法性
  第一断言**,环意味着没人能开工
- **节拍与工时的口径分离**:节拍是市场需求(可用时间/需求
  量),工时是工艺现实(测量+评比+宽放);**由「我们只有
  4 个人」倒推节拍,是把约束当需求**——产线将永远「恰好」
  满产且永远欠市场
- **平衡结果的账要能复算**:K* 是下界不是承诺;启发式排站
  (RPW)命中与否要断言(04 章 C1),站负荷、前序约束、
  效率三个断言组是排站结果的验收单

## 4. 骨架三:控制图判据卡(变异的语法)

- **两限分栏是这张卡的宪法**:控制限来自过程自身的组内
  变异(回答「过程变了没」),公差限来自产品要求(回答
  「产品合格没」)——**数值上两限可以互不知情**,混用即
  错(00 章故事框四教学点②的 schema 版)
- **判异规则是决策表不是直觉**:每条规则(点出界/连续同侧/
  连续升降,Western Electric-Nelson 判异族,通说)都要配
  误报率——**加一条规则=加一份误报**,规则越灵敏,对噪声
  动手的概率越大;选规则集是在「漏报-误报」之间站位
  (与[计量学](../讲透计量学/02-语言特征.md)的区间语法
  同源:灵敏度永远有价)
- **反应方案两分支**:信号→查可查原因;噪声→不干预——
  把「忍住别动」写进卡的 `on_noise` 字段,是对「对噪声动手
  就是制造噪声」的制度化(00 章故事框四)

## 5. 从结构到校验:这套骨架买到了什么

- 布局卡带从至表 → 总移动量可复算,布局版本之间可比较
- 路线卡带优先图与节拍 → 站数下界、排站、效率可全链复算
  (实验律1 的 schema 版)
- 判据卡带两限分栏与误报率 → 「控制限抄公差」「规则乱加」
  可机检报警
- 三卡齐 → 数字孪生的最小静态骨架:空间+时间+变异三个
  优化对象都有了数据格式,01 章方向四的「先在数字世界
  试错」才有试的对象

## 6. 构造合法性清单(动手前三问)

把任何产线设计任务变成数据结构之前,先过三问——本家族的
「类型检查」:

1. **口径写全了吗**:工时报件数语境了吗?节拍是市场正推
   还是产能倒推?距离口径统一了吗?流量单位写了吗?
2. **前提显式了吗**:控制限的来源是过程声音还是公差?
   判异规则配误报率了吗?Cpk 的受控前提查了吗?排队模型
   的平稳性声明了吗?
3. **账能复算吗**:Σt 与各任务求和一致吗?优先图无环吗?
   总移动量换布局后能重算吗?排站结果过三断言组吗?

三问全过,数据才获得进入 [04 章走廊](04-工业工程学转代码.md)
的资格。**产线设计的第一特征不是方案多巧,是账目可复算。**

## 📌 收束

可构造的是**三类数据对象**(设施布局卡/工艺路线卡/控制图
判据卡),不可构造的是**标准方法的发明、评比的判断、改善
优先级的政治与节拍的市场选择**;结构化不是为了替代车间,
是为了让「怎么摆、怎么流、怎么稳」可校验、可交接、可复盘。
下一章把骨架接上代码:[04-工业工程学转代码](04-工业工程学转代码.md)。

**🧠 认知升维**:

- **从至表眼**:空间问题先画流量账——布局的优劣是算出来
  的(Σ流量×距离),不是看出来的
- **拓扑眼**:工艺是图不是清单——工序的先后约束定死站数
  的下界,图错了平衡全错
- **两限眼**:控制限是过程的声音,公差限是客户的要求——
  见到「控制图」先问两限是不是被抄成了一个
