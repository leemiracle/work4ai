# 04 · 工业工程学转代码——线平衡·排队·学习曲线的走廊

> **本章回答五问之 Q5(问题→代码转换)。**
> **本质一句话**:工业工程学问题一旦变成「优先图上的站数
> 分配、稳态流的两个公式、幂律工时的外推」,就能进代码
> ——站数下界可算、排站可断言、队列账可盯盘、学习率可
  复利、控制图判异可机检;**唯一不可外包给代码的,是标准
> 方法的发明(动作怎么取消合并)、评比系数的判断、改善
> 优先级的政治与节拍的市场选择**——代码算三笔账:站的账、
> 队的账、学的账;账外皆是人的。

## 0. 开篇:一条产线,代码自己算

「十道工序、总工时 41 分钟、市场要每 12 分钟出一件——
要几站?效率多少?」「利用率开到九成五,队伍会多长?」
「第一批要 20 件,总共得排多少工时?」——
`experiments/ie_line_queue_learning.py` 让代码回答:
线平衡 K*=⌈Σt/C⌉,RPW 启发式三节拍(C=14/12/10)全部命中
下界,K=3/4/5,线效率 E=Σt/(K·C)=**97.6%/85.4%/82.0%**
——C 越贴近理想节拍 Σt/K* 效率越高,站数随 C 减小跳档
(律1);M/M/1 排队 L=ρ/(1−ρ) 在 ρ=0.50/0.80/0.90/0.95 时
L=**1.00/4.00/9.00/19.00**,W=1/(μ−λ) 与 Little 律 L=λW
逐点互证(稳态几何分布 MC 再证),利用率 0.80→0.95 只提高
18.75%,队长放大 **4.75 倍**、逗留时间翻两番(律2);学习
曲线 u_n=u₁·n^b,80% 学习率(b=log₂0.8)下 u₂=8.00、u₄=6.40、
u₈=5.12、u₁₀≈4.765,累计平均单调下降,对照 90% 率 u₁₀≈7.047
——**学习率 10 个百分点之差,第 10 件差 +47.9%≈近一半**
(律3)。一条脚本把 00 章反直觉①②③与 02 章三栏纪律全部
落成可复现的数。

## 1. 可机械化边界(三件套之一)

**能进代码的**(生产系统数据化后的一切计算):

| 任务 | 机械化形式 |
|------|-----------|
| 流水线平衡 | K*=⌈Σt/C⌉ 下界+RPW/最长后续路径启发式排站;站负荷/前序/效率三断言组 |
| 节拍-站数-效率联动 | E=Σt/(K·C)、平衡延迟 d=1−E;节拍扫描看站数跳档与效率变化 |
| 排队账 | M/M/1 闭式(L/W/P0)、Little 律换算(L=λW,知二求一)、稳态分布抽样互证 |
| 容量规划 | 给定服务水平(目标等待),反解安全利用率上限(律2 的反问题) |
| 学习曲线 | b=log₂(学习率);单位工时、累计平均、批次总工时外推;多学习率对比 |
| 控制图判异 | 控制限计算(组内变异)+判异规则集(出界/游程)机检+误报率记账 |
| 过程能力 | Cp/Cpk 计算(受控前提检查在前) |
| 布局评价 | 从至表×距离矩阵→总移动量复算,布局版本比较 |

**不能进代码的**(IE 的「不可判定域」):

1. **标准方法的发明**——动作怎么取消、合并、重排、简化
   (ECRS,通说)是现场知识;代码能对比两方案的工时与
   平衡账,不能凭空造第三方案
2. **评比系数的取值**——「该工人是正常速度的 1.1 倍」是
   判断不是测量;代码只能提示评比的敏感区间
3. **改善优先级的政治**——先改瓶颈还是先改最容易的、
   涉及谁的岗位调整,是资源与组织决策;代码给瓶颈清单,
   排序给人
4. **节拍的市场选择**——需求预测与产品策略是商业决策;
   代码能在给定 C 下算账,不能替你选 C

> 边界的一句话:**代码是三笔账(站/队/学)的验算台与
> 产线的盯盘器,不是方法与目标的定义者。**

## 2. C1 流水线平衡走廊(✅ 已实现)

| 字段 | 类型 | 约束/坑 |
|------|------|--------|
| 输入 | 任务(工时,前序)+节拍 C | 工时报件数语境;节拍市场正推(03 章路线卡纪律) |
| 下界 | K*=⌈Σt/C⌉ | 只是下界:优先约束可能迫使更多站;另有隐性下界=关键路径长/C |
| 排站 | RPW:RPW(i)=t_i+最长后续路径 | 启发式——**命中 K* 要断言,不能默认**(NP-难问题,通说) |
| 验收断言组 | ①逐站负荷≤C ②Σ负荷=Σt ③前序所在站≤本站 | 三断言齐=合法排站;缺一即账实不符 |
| 效率 | E=Σt/(K·C),d=1−E | 效率必报分母;d 是「等上站」与「等料」的空闲产能 |

成品=`experiments/ie_line_queue_learning.py` 实验[1]。
**改优先图换一张 TASKS 表,改产能换一个 C**——03 章
schema 分离的好处:图、节拍两居两列,节拍扫描(站数跳档
与效率曲线)就是在列间扫描。

## 3. C2 排队与容量走廊(把「忙」翻译成「堵」)

「利用率再压五个点,队伍会怎样?」——两个公式一台戏:

```python
# 教学版:M/M/1 稳态量 + Little 律守恒(律2 的最小内核)
def mm1(rho, mu=10.0):          # rho=利用率, mu=服务率(件/h)
    lam = rho * mu              # 到达率
    L = rho / (1.0 - rho)       # 平均队长:分母 (1-rho) 是全部戏剧所在
    W = 1.0 / (mu - lam)        # 平均逗留时间
    assert abs(L - lam * W) < 1e-9   # Little 律 L=λW:一行守恒律
    return L, W
# 断言风格:rho=0.50/0.80/0.90/0.95 -> L=1/4/9/19;
# rho 从 0.80 到 0.95(利用率只 +18.75%),L 放大 4.75 倍。
# 容量规划的反问题:目标 W<=30min,则 rho<=1-1/(mu*0.5)=0.95
# ——「安全利用率」不是经验值,是服务水平解出来的。
```

要点:其一,**拥挤全在分母 (1−ρ)**——线性逼近满负荷,
队列按 1/(1−ρ) 爆炸;其二,**Little 律是守恒律不是模型
假设**(1961 证明,通说):L=λW 对任意稳态系统成立,见
队列先做这行换算,量纲自洽就能拦住自相矛盾的汇报(02 章
栏二);其三,**反问题是容量规划的正解**:先定服务水平
(可接受等待),再解安全利用率上限——「开到九成五」应该
是解出来的数,不是拍出来的勇气。多站/多类的网络无闭式,
用这条走廊标定直觉、再用仿真放大(01 章方向四的孪生路线)。

## 4. C3 学习曲线走廊(把「熟练」翻译成「账」)

「这活儿干到第 20 件,平均每件多久?」——幂律一行:

```python
# 教学版:Wright 学习曲线(律3 的最小内核)
import math
b = math.log2(0.8)                    # 80% 学习率的指数
u = lambda n, u1=10.0: u1 * n ** b    # 第 n 件单位工时
# 断言风格:u(2)=8.00, u(4)=6.40, u(8)=5.12(翻番×0.8);
# u(10)=10*10**b≈4.765;累计平均 T(N)/N 单调下降;
# 对照 90% 率(指数 log2(0.9)):u10≈7.047,高出 47.9%。
# 工程面:批次 N 的总工时=Σu(n) —— 报价单的输入;
# 学习率每 10 个百分点,第 10 件差近一半 —— 培训与工装
# 投入的回报,就在这个指数上结算。
```

要点:其一,**学习率是政策变量**:80% 与 90% 不是命运,
是培训、工装、标准作业与重复设计投入的函数(00 章假设三
的正面用法);其二,**累计口径与单位口径分开报**:u_n 是
第 n 件,T(N)/N 是前 N 件平均,批次总工时是 Σu(n)——
三个数三种用途(报价用总、考核用均、平衡用稳态标准工时);
其三,**组织遗忘要留退路**:换人、换型、停产打断曲线,
模型外推要设「遗忘税」(经验上中断越久税率越高,方向锚,
不虚构数字)。

**走廊三警告**(共用):

1. 前提不写不收算:工时无件数语境、队列无平稳声明、
   能力无受控前提——一律裸数退回(02 章三栏纪律)
2. 启发式不装最优:RPW 命中 K* 要断言;命中不了要如实
   报差距(「K=K*+1,因优先约束」),而不是换个 C 掩盖
3. 账外不外包:方法发明、评比、优先级、节拍选择——
   代码给证据,人给结论(不可判定域四条)

## 5. 工程师落点(把这门学科带回家)

- **瓶颈眼→任何流水线**:CI/CD、数据管道、GPU 推理服务、
  食堂窗口——量每站耗时,找最小者;**给最快站优化是给
  平衡延迟白付利息**(律1 的 d 项)
- **队列眼→容量规划**:服务器/GPU 池的利用率目标别拍
  「越高越好」——ρ=0.95 的队列是 0.80 的 4.75 倍(律2);
  先定服务水平(SLO 的等待时间),再解安全利用率
- **学习眼→报价与排期**:新功能开发、新工艺爬坡、模型
  训练调参的「第 n 次」都在曲线上——**把 80%/90% 的差
  (第 10 件近 50%)算进报价,再把培训投入算进学习率**
  (律3 的复利账)
- **WIP 眼→个人与团队**:在制品上限(kanban 的 WIP limit)
  的数学根据是 Little 律——L 与 W 同向,限住 L 就缩短 W;
  「同时开五个坑」的流经时间,是「开一个」的五倍(同 λ 下)
- **两限眼→一切监控**:业务指标的告警阈值,该用过程自身
  噪声定(控制限),不是拍一个目标线(公差);对噪声告警
  的Pager 响应,是给系统注入新噪声(00 章故事框四的 SRE 版)

## 📌 收束

走廊三条:C1 线平衡管「站怎么排、效率怎么读」,C2 排队
管「忙与堵怎么换算、容量怎么解」,C3 学习曲线管「熟练
怎么复利、报价怎么算」;三条共用一条边界——**方法、
评比、优先级、节拍永远留在人那边**。跑到这里回头再看
00 章那句话:技术在既定时,效率与质量仍有一整门学科的
空间——这门学科的可计算内核,就是三行公式(K*=⌈Σt/C⌉、
L=ρ/(1−ρ)、u_n=u₁·n^b)加三张结构卡(布局/路线/判据);
其余的,是把这些账用在哪的判断。

**🧠 认知升维**:

- **验收断言组眼**:任何「排好了/算好了」的产出先过断言
  组(负荷≤上限、账实相符、前序合法)——合法先于最优
- **服务水平眼**:容量问题的第一问不是「能开多满」,是
  「等多久可接受」——从服务水平反解利用率,顺序反了
  就是拿队列赌运气
- **复利眼**:重复的事在按指数变便宜——识别你工作里的
  「第 n 件」,给它们记曲线;不记曲线的重复,是把复利
  存进不生息的账户
