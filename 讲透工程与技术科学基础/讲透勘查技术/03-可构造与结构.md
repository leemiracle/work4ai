# 03 · 可构造与结构——柱状图、测试记录与反演剖面作为数据对象

> **本章回答五问之 Q4(可构造性与结构)。**
> **本质一句话**:勘查技术里「可构造」的不是地层本身,
> 而是它的四类数据产出——钻孔柱状图(把「眼见」编成层
> 表)、原位测试记录(把读数与工艺元数据、校正链绑定)、
> 物探剖面(把观测与反演参数、多解性声明绑定)、勘察
> 方案(把孔网与阶段编成可审计的计划);把这些结构显式
> 化,勘查就从野外手艺变成可校验、可交接、可入库的
> 数据工程(04 章走廊的地基)。

---

## 0. 开篇:一份勘察报告的四件结构化家具

拆开任何一份严肃的勘察成果,都能拆出四件家具:其一
**钻孔柱状图**(眼见的东西长什么样——层序、描述、采样
与测试位置),其二**原位测试记录**(仪器读数+它的工艺
链),其三**物探剖面**(观测数据+反演模型+申报的先验),
其四**勘察方案**(这一轮取证打算怎么花——孔位、孔深、
阶段与理由)。四件在手,「钻-测-探」三通道(00 章)的
每一环都变成可机检的数据流水线;从 Hvorslev 的取样器
设计表到 01 章的岩土数据平台,在数据结构层面是同一套
schema——变的是数据量与密度,不变的是结构。

## 1. 什么是「可构造」的:四类结构对象

| 对象 | 数化身 | 可构造性 | 构造中的坑 |
|------|--------|---------|-----------|
| **钻孔柱状图** | 层表(层号/层厚/层名/状态描述/采样测试位置/水位) | ✅ 高度可构造 | 层界线画成直线=外推越权(孔间未知);编录词表不统一(一孔一方言) |
| **原位测试记录** | 曲线数组+仪器元数据+校正链字段 | ✅ 高度可构造 | 只存 N 不存 ER(校正链断链,数据债务);率定日期缺席 |
| **取样记录** | 取样器几何(面积比/间隙比)+质量等级 | ✅ 高度可构造 | 「原状」不标等级;面积比不入表(扰动账无凭) |
| **物探剖面** | 观测数据卡+反演模型卡(先验/正则化/残差) | ✅ 高度可构造 | 只交反演结果不交观测(多解性不可复核);无钻孔锚定外键 |
| **勘察方案** | 孔网(孔位/孔深/测试类型)+阶段+rationale | ✅ 高度可构造 | 孔距只有规范条文没有理由字段(01 章方向二要改的就是它) |

**不可构造的**:编录的地质解译(描述性语言→地层故事,
是判断不是填充)、扰动等级的现场触感评定(经验部分)、
反演先验的选择(多解性的裁决权)、勘察阶段与孔深的风险
权衡(规范+责任,00 章 04 章的不可判定域)。

### 1.5 最小数据模式(动手者的 schema)

```yaml
# 钻孔柱状图(眼见编成层表)
borehole_log:
  identity: {hole_id: str, xy: [float], collar_elev: float,
             depth: float, method: rotary|percussion|auger,   # 工艺元数据
             flushing: mud|water|air, casing: str}
  water_table: {depth: float, date: date}
  layers:
    - {top: float, bottom: float, geology: str,              # 岩土名称
       state: str,                                            # 编录词表取值
       samples: [{depth: float, type: str, area_ratio: float, # 面积比必填(扰动账)
                  quality_class: I|II|III|IV}],               # 取样质量等级必填
       tests: [{depth: float, kind: SPT|CPT|DMT|PMT, ref: str}]}

# 原位测试记录(读数+链)
in_situ_record:
  kind: CPTu
  raw: {depths: [float], qc: [float], fs: [float], u2: [float]}   # 每 2 cm
  instrument: {cone_area: 10cm2, sleeve_area: float,
               calibration_date: date}                        # 率定必填
  correction_chain: [qc_to_qt, n60_energy(ER=float),          # 校正链显式
                     stress_normalisation]
  derived: {layers: [change_point_ref], sbt: [str]}           # 成果注明方法

# 物探剖面(观测+反演双卡)
geophysics_profile:
  method: refraction|MASW|ERT|GPR
  observation: {geometry: [float], shots: int, travel_times: [float]}  # 原始观测必存
  inversion: {model: [float], prior: str, regularization: float,
              misfit: float, resolution_note: str}            # 多解性申报必填
  anchors: [{hole_id: str, depth: float, agreed: bool}]       # 钻孔锚定外键

# 勘察方案(孔网+理由)
investigation_plan:
  stage: feasibility|preliminary|detailed                    # 通说三级
  holes: [{xy: [float], depth: float, tests: [str],
           rationale: regulation_clause | variance_reduction}]  # 理由必填
  budget: {currency: str}
```

注意 `instrument`、`correction_chain`、`prior`、`rationale`
四处必填:把 02 章三条规则写进数据结构——**数据层自带
校验点,是勘查数据区别于普通文档的第一特征**(与
[工程地质学家族](../讲透工程地质学/03-可构造与结构.md)
的地层模型 schema 相接:它消费本 schema 的产出)。

## 2. 骨架一:钻孔柱状图(层的表)

- **层表三列不可缺**:层序(几何)、岩土名称与状态
  (编录语言)、证据位置(采样与测试在哪个深度)——
  层是「描述+证据」的配对,不是纯几何分区
- **层界线的外推身份要显式**:两孔之间的连线是假设一
  (代表性)的图形化;重要界面应标「钻孔控制/物探控制/
  推断」三种状态线型(与[工程地质学](../讲透工程地质学/README.md)
  的证据级线型约定同宗)
- **编录词表受控**:稠度、密实度、包含物的描述词必须
  从受控词表取值(可机检的前提);自由发挥的「一孔一
  方言」是数据平台时代的头号清洗债务

## 3. 骨架二:原位测试记录(读数+链)

- **原始读数与校正参数分居两列**:N 与 ER、qc 与锥头
  几何/率定、DMT 与膜片标定——校正可重放(换基准能量
  比、换率定系数时旧数据可升级,而不是作废)
- **校正链显式有序**:N→N60(能量)→N1₆₀(上覆应力
  归一)是一条管道,跳步的中间量没有可比性;每步的
  参数值随行(02 章规则一)
- **曲线的采样密度入档**:每 2 cm 与每 20 cm 的 qc 曲线
  是两种证据(律1 的界面精度账)——密度是元数据不是
  默认值

## 4. 骨架三:物探剖面(观测+反演双卡)

- **观测卡必存**:走时/频散/电阻率原始数据是反演结果的
  复核依据;只交最终剖面的物探成果,多解性永远不可
  复核(02 章规则三)
- **反演卡三必填**:先验(初始模型/参考剖面)、正则化
  参数(分辨率-方差的旋钮位置)、残差(解与观测的偏差)
  ——三件齐了,「这个解是众多合法解中的一个」才可审计
- **钻孔锚定外键**:物探层位与钻孔柱状图的对应关系是
  表间外键——物探给连续性,钻孔给身份,锚定关系本身
  是一等数据

## 5. 骨架四:勘察方案(孔网+理由)

- **孔位三列**:坐标、深度、测试类型;**第四列理由**:
  规范条款引用(传统模式)或方差缩减预期(信息价值
  模式,01 章方向二)——理由字段让方案从「合规文件」
  变成「可辩论的设计」
- **阶段是信息投资分期**:可行性/初步/详细三级(通说)
  的本质是分期买信息——上一阶段的方差图就是下一阶段
  的布孔依据(律3 的序贯逻辑写进 schema)
- **孔深的规范锚+风险锚**:规范最小深度是下限,控制性
  孔打到「满足分析深度」是判断——两者都应留痕

## 6. 从结构到校验:这套骨架买到了什么

- 柱状图带受控词表 → 编录语言可机检,一孔一方言可报警
- 测试记录带校正链 → 跨钻机、跨年代数据可归一(律2 的
  数据面)
- 物探双卡+锚定外键 → 多解性可复核,物探-钻孔互检自动
  化
- 方案带 rationale → 布孔决策可审计(规范理由还是信息
  理由,一目了然)
- 取样记录带面积比与质量等级 → 扰动账随样本走,参数
  统计时可按质量分层

## 7. 构造合法性清单(动手前三问)

把任何勘查数据构想变成结构之前,先过三问——本家族的
「类型检查」:

1. **工艺元数据带了吗**:每个读数能追到锤型/取样器/
   采集参数吗?追不到的数据先标「不可比」,不要混库
2. **校正链走完了吗**:存的是原始读数+参数,还是跳步
   的中间量?换基准时能重放吗?
3. **多解性与理由标了吗**:物探成果带先验申报吗?孔位
   带 rationale 吗?外推界线带状态线型吗?

三问全过,数据才获得进入 [04 章走廊](04-勘查技术转代码.md)
的资格。**勘查数据工程的第一特征不是字段多,是链条全。**

## 📌 收束

可构造的是**四类数据对象**(柱状图/测试记录/物探双卡/
勘察方案),不可构造的是**编录解译、扰动评定、先验选择、
风险权衡**四个判断位;结构化不是要替代这些判断,是让
它们与数据分离、可追溯、可交接。下一章把骨架接上代码:
[04-勘查技术转代码](04-勘查技术转代码.md)。

**🧠 认知升维**:

- **链眼**:数据的价值在链上——读数、工艺、校正、用途
  四环相扣,断一环就贬值一半
- **双卡眼**:间接证据(物探)永远两卡同行——观测卡
  定身份,反演卡定纪律
- **理由眼**:孔位不是点,是「一个理由的坐标」——没有
  rationale 的孔网只是合规装饰
