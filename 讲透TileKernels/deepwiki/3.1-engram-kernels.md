  The Engram module provides a set of low-level kernels designed for the Engram gating mechanism. This mechanism involves computing a signed-sqrt sigmoid gate based on normalized hidden states and key embeddings, combined with a specialized hashing scheme for n-gram lookup. The kernels are implemented using TileLang and are optimized for persistent execution and memory efficiency through fusion.

## engram_gate_fwd and engram_gate_bwd

 These are the primary kernels for the Engram gating operation. The forward kernel computes the RMSNorm of hidden states and keys, followed by a dot product and a signed-square-root sigmoid activation.

 
### Implementation Details

 
 - **Persistent Scheduling**: Both kernels use a persistent-block scheduling strategy to maximize SM utilization and reduce kernel launch overhead [tile_kernels/engram/engram_gate_kernel.py41-49](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/engram/engram_gate_kernel.py#L41-L49)
 - **RMSNorm Fusion**: The kernels perform on-the-fly normalization of input `hidden_states` and `k` (keys) [tile_kernels/engram/engram_gate_kernel.py143-144](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/engram/engram_gate_kernel.py#L143-L144)
 - **Async Pipelining**: Uses `T.async_copy` and `T.ptx_wait_group` to overlap memory transfers with computation [tile_kernels/engram/engram_gate_kernel.py100-110](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/engram/engram_gate_kernel.py#L100-L110)
 - **Backward Strategy**: The backward kernel is an 8-warp persistent implementation that processes tokens in tiles and accumulates partial gradients for weights [tile_kernels/engram/engram_gate_kernel.py236-250](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/engram/engram_gate_kernel.py#L236-L250)

## engram_fused_weight

 This kernel performs an element-wise product of two bfloat16 weight tensors (`weight_hidden` and `weight_embed`) and outputs the result in float32. This fused representation is consumed by the forward and backward gating kernels.

 
### Data Flow

 The kernel uses vectorized loads (`vec_size = 8`) to fetch weights into local registers before performing the multiplication [tile_kernels/engram/engram_fused_weight_kernel.py16-35](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/engram/engram_fused_weight_kernel.py#L16-L35)

## grad_w_reduce

 The `grad_w_reduce` kernel is responsible for aggregating the partial weight gradients produced by the persistent backward kernel.

 
### Key Features

 
 - **Pipelined Reduction**: It uses a `T.Pipelined` loop with 2 stages to fetch `grad_w_partial` into shared memory while processing previous tiles [tile_kernels/engram/engram_grad_w_reduce_kernel.py50-51](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/engram/engram_grad_w_reduce_kernel.py#L50-L51)
 - **Fused Weight Update**: After reducing the partials into `grad_w_fragment`, it immediately multiplies by the original weights to compute `grad_weight_hidden` and `grad_weight_embed` [tile_kernels/engram/engram_grad_w_reduce_kernel.py57-59](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/engram/engram_grad_w_reduce_kernel.py#L57-L59)
 - **In-place Accumulation**: The results are copied back into the global gradient tensors [tile_kernels/engram/engram_grad_w_reduce_kernel.py61-62](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/engram/engram_grad_w_reduce_kernel.py#L61-L62)

## engram_hash

 The `engram_hash` kernel implements a multi-layer n-gram hashing scheme. It maps sequences of token IDs to indices in embedding tables.

 
### Implementation Logic

 
 - **XOR Hashing**: It iterates through the n-gram tokens, applying a bitwise XOR with layer-specific multipliers [tile_kernels/engram/engram_hash_kernel.py51-54](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/engram/engram_hash_kernel.py#L51-L54)
 - **Modular Indexing**: For each n-gram size greater than 0, it computes indices by taking the hash modulo the `vocab_size` of the target embedding table and adding a base `offset` [tile_kernels/engram/engram_hash_kernel.py55-58](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/engram/engram_hash_kernel.py#L55-L58)
 - **Unrolling**: The loops for `ngram_idx` and `num_embed_table_per_ngram` are unrolled to optimize performance for small n-gram sizes (typically 2-4) [tile_kernels/engram/engram_hash_kernel.py50-56](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/engram/engram_hash_kernel.py#L50-L56)
