  The `TileKernels` test suite provides a comprehensive validation framework for TileLang-based kernels. It ensures numerical correctness against PyTorch reference implementations and measures hardware performance (bandwidth and latency) across various tensor shapes and configurations.

 
## Test Suite Structure

 The test infrastructure is organized by kernel family under the `tests/` directory. Each sub-directory mirrors the structure of the `tile_kernels/` source tree.

 
| Directory | Scope | Key Kernels Tested |
|---|---|---|
| tests/engram/ | Engram Gating | engram_gate_fwd, engram_gate_bwd, fused_weight, engram_hash |
| tests/mhc/ | Manifold HyperConnection | sinkhorn_kernel, expand_kernel, norm_fn_kernel, multilayer_recompute |
| tests/moe/ | Mixture of Experts | topk_gate_kernel, expand_to_fused, reduce_fused, group_count |
| tests/quant/ | Quantization & Casts | per_token_cast, per_block_cast, swiglu_forward_and_per_token_cast |
| tests/transpose/ | Tensor Transposition | batched_transpose_kernel |

## Standard Test Pattern

 All kernel tests follow a consistent lifecycle to ensure parity between TileLang kernels and PyTorch references.

 
### 1. Parameter Generation

 Tests utilize `generate_test_params` to create a list of configurations (e.g., hidden sizes, token counts). This function often uses `generate_hidden_sizes` or `generate_num_tokens` from the testing utilities to produce varied power-of-two and non-power-of-two shapes [tests/engram/test_engram_gate_fwd.py30-37](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tests/engram/test_engram_gate_fwd.py#L30-L37)

 
### 2. Data Preparation

 The `generate_test_data` function initializes input tensors on the GPU using `torch.randn` or `torch.randint`. For backward tests, it also prepares gradient tensors [tests/engram/test_engram_gate_bwd.py15-28](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tests/engram/test_engram_gate_bwd.py#L15-L28)

 
### 3. Execution and Validation

 The test compares the TileLang kernel output against a reference implementation (typically from `tile_kernels.torch.*`).

 
 - **Correctness:** Uses `assert_equal` or `calc_diff` to verify results [tests/engram/test_engram_fused_weight.py31-37](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tests/engram/test_engram_fused_weight.py#L31-L37)
 - **Autograd:** For modeling ops, `torch.autograd.backward` is invoked on both the kernel-based op and the reference to verify gradient parity [tests/mhc/test_expand.py33-45](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tests/mhc/test_expand.py#L33-L45)

## Benchmark Fixtures

 Tests marked with `@pytest.mark.benchmark` serve as performance regressions. They utilize two primary fixtures:

 
 - `benchmark_timer`: Measures the execution time of a kernel call in microseconds ($\mu s$) using CUDA events for precision [tests/engram/test_engram_fused_weight.py46](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tests/engram/test_engram_fused_weight.py#L46-L46)
 - `benchmark_record`: Logs the kernel name, operation type, parameters, time, and calculated bandwidth ($GB/s$) to the test report [tests/engram/test_engram_fused_weight.py50-56](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tests/engram/test_engram_fused_weight.py#L50-L56)
 
 Bandwidth is typically calculated using `count_bytes` to determine the total I/O volume of the kernel [tests/engram/test_engram_fused_weight.py48-49](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tests/engram/test_engram_fused_weight.py#L48-L49)

## Specialized Test Suites

 
### Engram Backward Testing

 The `test_engram_gate_bwd` suite is unique because it validates the kernel's backward pass using intermediates (like `rstd` and `gate_score`) generated by the reference forward pass. This isolates the backward kernel logic from potential forward-pass errors [tests/engram/test_engram_gate_bwd.py41-60](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tests/engram/test_engram_gate_bwd.py#L41-L60)

 
### MHC Multilayer Recompute

 The `test_mhc_multilayer_recompute` suite validates a fused recompute kernel that spans multiple layers. It compares the fused result against a loop of individual `mhc_pre_apply_mix` and `mhc_post` calls, specifically calculating "Speedup" and "Efficiency" against the theoretical memory I/O reduction [tests/mhc/test_multilayer_recompute.py92-158](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tests/mhc/test_multilayer_recompute.py#L92-L158)

## Environment Variables

 The test suite behavior can be modified via environment variables:

 
 - `TK_FULL_TEST`: When set, the parameter generators (like `generate_num_tokens`) produce a much larger set of shapes to pressure test the kernels across edge cases and alignment boundaries.
 - `TILELANG_PRINT_ON_COMPILATION`: Usually set to `'0'` in test files to suppress TileLang's source code output during the JIT phase [tests/engram/test_engram_gate_fwd.py12](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tests/engram/test_engram_gate_fwd.py#L12-L12)
 - `TK_PRINT_KERNEL_SOURCE`: If enabled, allows developers to inspect the generated CUDA/PTX code for the kernel under test.
