# MoE Dispatch and Reduction Kernels

  Relevant source files 
 - [tile_kernels/moe/expand_to_fused_kernel.py](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/expand_to_fused_kernel.py)

  The Mixture of Experts (MoE) dispatch and reduction kernels facilitate the data movement between token-level representations and expert-level buffers. This process, often called "scattering" and "gathering," involves expanding tokens into a larger fused layout where they can be processed by expert GEMMs, and subsequently reducing the expert outputs back into a single token-level tensor using learned routing weights.

 
## Dispatch: expand_to_fused_kernel

 The `expand_to_fused_kernel` is responsible for scattering token activations into a layout organized by expert. It supports standard floating-point tensors and quantized tensors with associated scaling factors (SF).

 
### Implementation Details

 The kernel uses a persistent-block-like approach where `num_blocks` is defined as the maximum of `num_tokens` and `num_expanded_tokens` [tile_kernels/moe/expand_to_fused_kernel.py38-40](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/expand_to_fused_kernel.py#L38-L40) Each thread block handles one token or one expanded position.

 
 - **Zero Initialization**: If a thread block's ID (`pid_token`) corresponds to an expanded position that is unassigned (mapping to expert index < 0), the kernel clears the memory in `expanded_x` [tile_kernels/moe/expand_to_fused_kernel.py56-65](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/expand_to_fused_kernel.py#L56-L65)
 - **Fragment Loading**: For valid tokens, the kernel loads the token data into `x_fragment` and its scaling factors into `x_sf_fragment` [tile_kernels/moe/expand_to_fused_kernel.py71-77](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/expand_to_fused_kernel.py#L71-L77)
 - **Top-K Scatter**: The kernel iterates through the `num_topk` assignments for the current token. It retrieves the target expanded position from `token_topk_to_pos` and writes the fragments into the corresponding rows of `expanded_x` and `expanded_x_sf` [tile_kernels/moe/expand_to_fused_kernel.py79-89](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/expand_to_fused_kernel.py#L79-L89)
 
 
### Scaling Factor Layouts

 The kernel supports complex SF layouts, including TMA-aligned column-major formats and packed `ue8m0` (unsigned 8-bit E0M0) formats for highly compressed quantization schemes [tile_kernels/moe/expand_to_fused_kernel.py28-32](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/expand_to_fused_kernel.py#L28-L32)

 
| Feature | Code Entity | Description |
|---|---|---|
| Token Buffer | x | Original token activations (num_tokens, hidden) |
| Mapping | token_topk_to_pos | Maps (token, k) to a row in the expert buffer |
| Expert Buffer | expanded_x | Output buffer (num_expanded_tokens, hidden) |
| SF Support | QuantTensor | Tuple of (data, sf) for quantized dispatch |

## Reduction: reduce_fused_kernel

 The `reduce_fused_kernel` performs the reverse operation: it aggregates the outputs from different experts back into the original token-level layout. This aggregation is typically a weighted sum based on the routing scores.

 
### Data Flow and Aggregation

 The kernel launches one thread block per original token (`num_tokens`) [tile_kernels/moe/reduce_fused_kernel.py37](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/reduce_fused_kernel.py#L37-L37)

 
 - **Weight Loading**: It loads the `topk_weights` and the `token_topk_to_pos` indices for the specific token into local fragments [tile_kernels/moe/reduce_fused_kernel.py39-48](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/reduce_fused_kernel.py#L39-L48)
 - **Accumulation Loop**: It iterates through the `num_topk` experts assigned to that token. For each expert, it fetches the result from the expert buffer (`x`), applies the routing weight (`s`), and optionally applies a per-token scaling factor (`x_sf`) [tile_kernels/moe/reduce_fused_kernel.py50-62](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/reduce_fused_kernel.py#L50-L62)
 - **FP8 Casting**: The kernel supports casting the final reduced result to FP8 (specifically `e4m3fn`) while applying an optional global scaling factor `sf` [tile_kernels/moe/reduce_fused_kernel.py64-65](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/reduce_fused_kernel.py#L64-L65) [tile_kernels/moe/reduce_fused_kernel.py103-107](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/reduce_fused_kernel.py#L103-L107)

## Weight Normalization: normalize_weight_kernel

 Before reduction, routing weights must often be normalized to ensure the sum of weights for each token equals 1.0. The `normalize_weight_kernel` performs this efficiently using a single pass per token.

 
### Implementation

 The kernel uses 128 threads per block [tile_kernels/moe/normalize_weight_kernel.py13](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/normalize_weight_kernel.py#L13-L13) Each thread handles one token row:

 
 - **Summation**: It reads all `num_topk` weights for a token into local registers and computes their sum [tile_kernels/moe/normalize_weight_kernel.py31-36](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/normalize_weight_kernel.py#L31-L36) A small epsilon (`1e-20`) is used to avoid division by zero [tile_kernels/moe/normalize_weight_kernel.py31](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/normalize_weight_kernel.py#L31-L31)
 - **Normalization**: It divides each local weight by the computed sum and writes the result to `normalized_weights` [tile_kernels/moe/normalize_weight_kernel.py39-40](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/normalize_weight_kernel.py#L39-L40)
 
 **Sources:** [tile_kernels/moe/normalize_weight_kernel.py7-42](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/moe/normalize_weight_kernel.py#L7-L42)
