# EngramGateFn: Autograd Integration

  Relevant source files 
 - [tile_kernels/modeling/engram/__init__.py](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/engram/__init__.py)
 - [tile_kernels/modeling/engram/engram_gate.py](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/engram/engram_gate.py)
 
  The `EngramGateFn` serves as the bridge between high-level PyTorch modeling and the optimized TileLang kernels for the Engram gating mechanism. It implements a `torch.autograd.Function` that handles the forward pass (fused RMSNorm and gating) and the backward pass (gradient computation and accumulation).

 
### Overview

 The `EngramGateFn` implements a gated residual connection with normalized inputs. Mathematically, it computes:

 
 - **Normalization**: $x_{norm} = \text{RMSNorm}(x, w_h)$ and $k_{norm} = \text{RMSNorm}(k, w_e)$.
 - **Gating**: $gate = \sigma(\text{signed_sqrt}(\text{dot}(x_{norm}, k_{norm}) \cdot \text{scalar}))$.
 - **Output**: $output = \text{hidden_states} + gate \cdot v$.
 
 Where $\text{signed_sqrt}(z) = \text{sign}(z) \cdot \sqrt{|z|}$ and $\text{scalar} = 1 / \sqrt{\text{hidden_size}}$.

### Forward Pass Implementation

 The `forward` method prepares the input tensors by flattening the batch and sequence dimensions into a single sequence dimension while preserving the `hc_mult` and `hidden_size` structure.

 
| Step | Operation | Code Reference |
|---|---|---|
| 1 | Reshape inputs to [-1, hc_mult, hidden_size] | tile_kernels/modeling/engram/engram_gate.py40-42 |
| 2 | Fuse RMSNorm weights using fused_weight | tile_kernels/modeling/engram/engram_gate.py44 |
| 3 | Execute engram_gate_fwd kernel | tile_kernels/modeling/engram/engram_gate.py45-47 |
| 4 | Save activations and intermediate stats (dot, rstd) | tile_kernels/modeling/engram/engram_gate.py49-52 |

 The `fused_weight` kernel is a prerequisite for the forward pass as it combines the two RMSNorm weights into a single buffer for optimized access within the fused gating kernel.

#### The main_grad Pattern

 If the weight tensors (`weight_hidden` or `weight_embed`) possess a `.main_grad` attribute, the `grad_w_reduce` kernel accumulates the computed gradients directly into those buffers in FP32. In this case, the `backward` function returns `None` for those specific parameters to prevent PyTorch from performing a second, redundant accumulation.

 
 - **Attribute check**: `getattr(weight_hidden, 'main_grad', None)` [tile_kernels/modeling/engram/engram_gate.py74-75](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/engram/engram_gate.py#L74-L75)
 - **Buffer allocation**: If no `main_grad` exists, a zeroed FP32 tensor is allocated [tile_kernels/modeling/engram/engram_gate.py76-77](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/engram/engram_gate.py#L76-L77)
