  The **Manifold HyperConnection (mHC)** modeling API provides a high-level functional interface for managing multi-head residual connections. It abstracts the complexity of coordinating multiple TileLang kernels—including RMSNorm, GEMM, Sinkhorn normalization, and gated mixing—into a unified pipeline for both training and inference.

 
## Overview

 The mHC system replaces standard additive residuals with a structured multi-head approach. The modeling API is organized into three layers:

 
 - **Functional API**: High-level entry points (`mhc_pre`, `mhc_post`, `mhc_head`) that orchestrate the sub-operations [tile_kernels/modeling/mhc/functional.py1-12](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/functional.py#L1-L12)
 - **Autograd Operations**: `torch.autograd.Function` wrappers located in `ops/` that manage the lifecycle of forward/backward passes and kernel dispatch [tile_kernels/modeling/mhc/ops/__init__.py1-10](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/ops/__init__.py#L1-L10)
 - **Kernel Integration**: Direct calls to the low-level TileLang kernels defined in `tile_kernels/mhc/`.
 
 
### Inference vs. Training Paths

 The API optimizes for inference by using a "Big Fuse" strategy. When `torch.is_grad_enabled()` is false, `mhc_pre` dispatches to `mhc_pre_big_fuse`, which collapses multiple normalization and mixing steps into a single execution flow to minimize memory round-trips [tile_kernels/modeling/mhc/functional.py69-82](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/functional.py#L69-L82)

## Core Functional API

 
### expand_from_embedding

 Converts a standard embedding of shape `(..., H)` into the multi-head residual format `(..., mhc_mult, H)`. This is the entry point for data entering the mHC subsystem [tile_kernels/modeling/mhc/functional.py14-27](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/functional.py#L14-L27)

 
### mhc_pre

 The primary entry point for sublayers (Attention or FFN). It performs the following sequence in training mode:

 
 - **mhc_pre_norm_fn**: Computes RMSNorm and a GEMM to produce raw mixing coefficients [tile_kernels/modeling/mhc/functional.py84-90](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/functional.py#L84-L90)
 - **mhc_pre_split_mixes**: Splits raw coefficients into `pre_mix`, `post_mix`, and `comb_mix` [tile_kernels/modeling/mhc/functional.py92-99](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/functional.py#L92-L99)
 - **sinkhorn_normalize**: Applies iterative doubly-stochastic normalization to the `comb_mix` [tile_kernels/modeling/mhc/functional.py101](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/functional.py#L101-L101)
 - **mhc_pre_apply_mix**: Applies the `pre_mix` to the residual to produce the sublayer input [tile_kernels/modeling/mhc/functional.py103](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/functional.py#L103-L103)
 
 In inference mode, these are fused via `mhc_pre_big_fuse` [tile_kernels/modeling/mhc/functional.py70-81](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/functional.py#L70-L81)

 
### mhc_post

 Updates the multi-head residual after the sublayer computation. It takes the sublayer output `x`, the current `residual`, and the mixing context (`post_mix`, `comb_mix`) returned by `mhc_pre` [tile_kernels/modeling/mhc/ops/post.py28-35](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/ops/post.py#L28-L35)

### Gradient Accumulation and `fuse_grad_acc`

 A key feature of the mHC API is the `fuse_grad_acc` flag in `MHCPreNormFn`.

 
 - When enabled, the backward pass of `MHCPreApplyMix` stores the residual gradient in the `untyped_storage` of the input tensor under the attribute `grad_from_mhc_post` [tile_kernels/modeling/mhc/ops/pre_apply_mix.py30-38](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/ops/pre_apply_mix.py#L30-L38)
 - `MHCPreNormFn.backward` then retrieves this accumulated gradient to combine it with its own computed gradients, reducing memory overhead for intermediate gradient tensors [tile_kernels/modeling/mhc/ops/norm_fn.py149-169](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/ops/norm_fn.py#L149-L169)

## Inference Optimization: `mhc_pre_big_fuse`

 The `mhc_pre_big_fuse` function is a specialized inference-only path. It utilizes a two-step fusion:

 
 - **GEMM Phase**: Executes `_mhc_pre_norm_fn_fwd_mul` to calculate the projections of the residual [tile_kernels/modeling/mhc/ops/pre_big_fuse.py58-64](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/ops/pre_big_fuse.py#L58-L64)
 - **Big Fuse Phase**: Executes `_mhc_pre_big_fuse_kernel`, which internally performs RMSNorm, Sinkhorn iterations, and the final residual mixing in a single persistent kernel [tile_kernels/modeling/mhc/ops/pre_big_fuse.py67-85](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/modeling/mhc/ops/pre_big_fuse.py#L67-L85)
 
 This path avoids allocating intermediate tensors for `pre_mix`, `post_mix`, and `comb_mix` in the global memory, significantly reducing DRAM bandwidth usage during generation.
