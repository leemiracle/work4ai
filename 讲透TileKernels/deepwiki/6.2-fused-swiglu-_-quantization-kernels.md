# Fused SwiGLU + Quantization Kernels

  Relevant source files

  The Fused SwiGLU + Quantization module provides high-performance TileLang kernels that combine the SwiGLU activation function with low-precision quantization (FP8/FP4). By fusing these operations, the system avoids redundant memory round-trips to High Bandwidth Memory (HBM), keeping intermediate activation values in registers or shared memory before casting them to their quantized representation.

 
## Purpose and Memory Efficiency

 In a standard Transformer MLP block, the SwiGLU operation is typically followed by a quantization step to prepare activations for the subsequent linear layer (often an FP8 GEMM). A non-fused implementation would perform:

 
 - **Read** BF16 input from HBM.
 - **Compute** SwiGLU in registers.
 - **Write** BF16 result to HBM.
 - **Read** BF16 result from HBM.
 - **Quantize** (compute scaling factors and cast).
 - **Write** Quantized result to HBM.
 
 The fused kernels in `tile_kernels/quant/` reduce this to a single Read-Compute-Write cycle, significantly improving performance in memory-bandwidth-bound scenarios.

## Fused Forward Kernels

 
### 1. swiglu_forward_and_per_token_cast

 This kernel implements the forward SwiGLU activation fused with per-token quantization. It calculates the scaling factor (SF) for each token independently by finding the maximum absolute value within that token's hidden dimension.

 
 - **Implementation**: Uses `T.reduce_absmax` across the hidden dimension to compute scaling factors [tile_kernels/quant/swiglu_forward_and_per_token_cast_kernel.py65-68](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/quant/swiglu_forward_and_per_token_cast_kernel.py#L65-L68)
 - **Scaling Factors**: Computed using the `get_sf_and_inv` macro, which handles optional power-of-two rounding and clamping [tile_kernels/quant/common.py196-210](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/quant/common.py#L196-L210)
 
 
### 2. swiglu_forward_and_per_channel_cast_and_transpose

 Designed for optimized weight-gradient computation or specific inference layouts, this kernel fuses SwiGLU, quantization, and a matrix transpose.

 
 - **Tiling Strategy**: Uses a `TILE_X` by `TILE_Y` grid where it reads tokens and hidden dimensions, performs the activation, and writes the result in a transposed layout [tile_kernels/quant/swiglu_forward_and_per_channel_cast_and_transpose_kernel.py22-37](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/quant/swiglu_forward_and_per_channel_cast_and_transpose_kernel.py#L22-L37)
 - **Bank Conflict Avoidance**: Employs shared memory padding `(TILE_Y, TILE_X + TILE_K)` and swizzling to minimize bank conflicts during the transpose operation [tile_kernels/quant/swiglu_forward_and_per_channel_cast_and_transpose_kernel.py39-61](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/quant/swiglu_forward_and_per_channel_cast_and_transpose_kernel.py#L39-L61)

## Fused Backward Kernels

 
### swiglu_backward_and_per_token_cast

 This kernel is used during the backward pass of a Transformer MLP. It computes the gradient of the SwiGLU activation and immediately quantizes the resulting gradient tensor.

 
 - **Input**: Takes the gradient of the output and the original gate/up-projection activations.
 - **Logic**: Applies the chain rule for SwiGLU, then calculates per-token scaling factors for the resulting gradient before casting to the target low-precision format.

## Per-Channel Fused Cast

 
### per_channel_cast_fused

 While not strictly a SwiGLU kernel, `per_channel_cast_fused` provides a fused path for casting tensors with per-channel scaling factors. This is critical for weights in quantized linear layers where each output channel (column in the weight matrix) requires a different dynamic range.

 
 - **Functionality**: Aggregates `amax` values across the specified channel dimension and applies the quantization cast in a single pass [tile_kernels/quant/per_channel_cast_fused_kernel.py1-5](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/quant/per_channel_cast_fused_kernel.py#L1-L5)

## Configuration and Metadata

 The behavior of these fused kernels is governed by the `CastOutputConfig` and `BaseCastConfig` classes.

 
| Parameter | Description |
|---|---|
| sf_block | A tuple (num_per_tokens, num_per_channels) defining the granularity of quantization tile_kernels/quant/common.py23 |
| round_sf | Boolean indicating if scaling factors should be rounded to the nearest power of two tile_kernels/quant/common.py47 |
| custom_clamp_min_value | Minimum value for scaling factors to prevent division by zero or underflow tile_kernels/quant/common.py48-60 |
| use_packed_ue8m0 | Enables a specialized packing format for scaling factors tile_kernels/quant/common.py25 |
