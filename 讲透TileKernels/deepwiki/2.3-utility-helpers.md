# Utility Helpers

  Relevant source files 
 - [tile_kernels/config.py](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/config.py)
 - [tile_kernels/quant/common.py](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/quant/common.py)
 
  Utility helpers in `TileKernels` provide foundational mathematical and alignment operations used across the library to calculate grid dimensions, memory offsets, and hardware-specific configurations. These helpers ensure that kernel launches are correctly sized relative to input dimensions and hardware constraints.

 
## Core Utility Functions

 The primary utility functions are defined in `tile_kernels/utils.py`. These are used extensively in kernel configuration and dispatch logic to handle tiling and alignment.

 
### `ceil_div`

 Performs ceiling division, commonly used to determine the number of blocks needed to cover a specific dimension given a tile size.

 
 - **Implementation**: `(a + b - 1) // b`
 - **Usage**: Calculating `num_blocks` for GPU grids.
 
 
### `align`

 Aligns a value to the next multiple of a specified alignment factor.

 
 - **Implementation**: `(value + alignment - 1) // alignment * alignment`
 - **Usage**: Ensuring shared memory allocations or TMA (Tensor Memory Accelerator) descriptors meet hardware alignment requirements (e.g., 16-byte alignment for certain PTX instructions).
 
 
### `is_power_of_two`

 Checks if an integer is a power of two using bitwise logic.

 
 - **Implementation**: `n > 0 and (n & (n - 1)) == 0`
 - **Usage**: Validating tile sizes for kernels that rely on power-of-two reductions or specialized indexing.

|---|---|---|
| ceil_div(a, b) | tile_kernels/utils.py | Calculates $\lceil a/b \rceil$ |
| align(value, alignment) | tile_kernels/utils.py | Rounds up to nearest multiple |

## Hardware Configuration Helpers

 The `tile_kernels/config.py` module manages device-level metadata, such as the number of Streaming Multiprocessors (SMs) and shared memory limits. These values are critical for "persistent-block" scheduling, where the grid size is tied to the hardware's capacity rather than the problem size.

 
### SM Management

 
 - `get_device_num_sms()`: Queries `torch.cuda.get_device_properties` to find the physical SM count [tile_kernels/config.py7-10](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/config.py#L7-L10)
 - `set_num_sms(num_sms)`: Allows manual override of the SM count for testing or performance tuning, ensuring the value does not exceed physical limits [tile_kernels/config.py13-16](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/config.py#L13-L16)
 - `get_num_sms()`: Returns the current SM count (either the default or the overridden value) [tile_kernels/config.py19-23](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/config.py#L19-L23)
 
 
### Shared Memory

 
 - `get_max_smem_per_sm()`: Retrieves the maximum shared memory available per SM, used to validate kernel configurations during the JIT compilation phase [tile_kernels/config.py26-29](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/config.py#L26-L29)

## Quantization Layout Helpers

 In the quantization subsystem, utility functions translate logical tensor shapes into physical memory layouts, especially for scaling factors (SF) and packed data types like FP4 (represented as `int8`).

 
### Hidden Dimension Mapping

 When using packed types, the "physical" dimension in memory differs from the "logical" dimension used in calculations:

 
 - `get_logical_hidden`: If using `torch.int8` for FP4, it doubles the hidden size [tile_kernels/quant/common.py116-120](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/quant/common.py#L116-L120)
 - `get_physical_hidden`: If using `torch.int8` for FP4, it halves the hidden size to account for packing two 4-bit elements into one byte [tile_kernels/quant/common.py123-127](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/quant/common.py#L123-L127)
 
 
### Scaling Factor (SF) Shape Calculation

 The function `get_sf_shape` calculates the dimensions of the scaling factor tensor based on the input shape and the block size (`sf_block`). It accounts for specialized layouts like `use_packed_ue8m0` (where 4 factors are packed) and `use_tma_aligned_col_major_sf` [tile_kernels/quant/common.py130-138](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/quant/common.py#L130-L138)

 
### Vectorization Selection

 `get_best_vectorize_size` determines the optimal vector load size (16 or 32 bytes) based on the GPU architecture's compute capability (e.g., Blackwell vs. Hopper/Ampere) and the data type's byte width [tile_kernels/quant/common.py13-17](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/quant/common.py#L13-L17)
