## Purpose and Scope

 `TileKernels` is a collection of high-performance CUDA kernels authored using the **TileLang** framework. The library is designed to integrate seamlessly with PyTorch, providing optimized implementations for Engram gating, Manifold HyperConnection (mHC), Mixture of Experts (MoE), and advanced Quantization schemes. Proper installation ensures that the TileLang JIT compiler can target the local GPU architecture, while the configuration API allows developers to tune persistent-block scheduling by managing Streaming Multiprocessor (SM) utilization.

 
## Installation and Prerequisites

 The installation process relies on `setuptools-scm` for versioning and requires a modern CUDA-enabled environment.

 
### Core Dependencies

 `TileKernels` requires the following base environment:

 
 - **Python**: `>=3.10` [pyproject.toml27](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/pyproject.toml#L27-L27)
 - **PyTorch**: `>=2.10` [pyproject.toml24](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/pyproject.toml#L24-L24)
 - **TileLang**: `>=0.1.9` [pyproject.toml25](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/pyproject.toml#L25-L25)

## Global Configuration API (`config.py`)

 The `tile_kernels/config.py` module provides a centralized interface for querying and controlling hardware-specific parameters. This is critical for TileLang kernels that utilize **persistent-block scheduling**, where the grid size is often calculated based on the available number of Streaming Multiprocessors (SMs).

 
### Implementation Detail

 The configuration state is managed via a global variable `_num_sms` [tile_kernels/config.py4](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/config.py#L4-L4) By default, the library queries the hardware directly, but it allows for manual overrides to simulate smaller devices or limit resource consumption.

 
### Key Functions

 
| Function | Description | Implementation |
|---|---|---|
| get_device_num_sms() | Queries the physical hardware for the total SM count. | Uses torch.cuda.get_device_properties tile_kernels/config.py8-10 |
| set_num_sms(num_sms) | Manually sets the SM count used for kernel grid calculations. | Validates that num_sms is within hardware limits tile_kernels/config.py13-16 |
| get_num_sms() | Returns the active SM count (either manual override or hardware default). | Checks if _num_sms is initialized tile_kernels/config.py19-23 |
| get_max_smem_per_sm() | Returns the maximum shared memory available per SM. | Cached via lru_cache tile_kernels/config.py26-29 |

## Device Requirements and Runtime

 The library is optimized for NVIDIA GPUs. At runtime, `TileKernels` uses `tilelang` to JIT-compile kernels. The `get_max_smem_per_sm` function [tile_kernels/config.py27-29](https://github.com/deepseek-ai/TileKernels/blob/36d9e45d/tile_kernels/config.py#L27-L29) is particularly important for kernels that perform heavy tiling, as it prevents the JIT compiler from attempting to allocate more shared memory than the physical hardware supports, which would otherwise result in a launch failure.
