## 一、可机械化边界:什么能算、什么算不了

**能机械化的**(有原理保证或明确程序对应的「算」):

| 广电动作 | 机械化形态 | 保证来自 |
|----------|-----------|---------|
| 排播装配 | 时段×类型契约×竞争对策的约束求解;EPG(电子节目表)自动生成 | 排播的构造语法(03 章层 1) |
| 收视/份额计算 | 样本统计与外推;回流数据聚合;rating/share 双指标 | 测量构造的成文程序(03 章层 2) |
| 响度归一 | LUFS 测量(计权能量积分)+增益批处理 | ITU-R BS.1770/EBU R128(02 章 §三第一档:真公理系统) |
| 音频分析 | 采样/DFT 频谱/基频与泛音提取 | 傅里叶定理:一切信号=正弦叠加(底座支「声学信号处理」) |
| 频道流生成 | 循环节目单→云端 playout→切片;FAST 频道即「流生成器即服务」 | flow 的可程序化(03 章层 3) |
| 时移与回看 | 录制窗(DVR window)+断点续看+倍速 | 时移需求的形式化(02 章 §一「说不出的话」的工程补全) |
| 推荐补排播 | 可见性分配(个人节目表:为你排的「黄金时段」) | 门户经济的调度问题(01 章战线 1) |

**机械化不了的边界**(为什么——原理级回答):
1. **黄金时段的社会协调价值不可优化,只可模拟**:共同在场的好处
   (第二天有得聊、仪式感)是**社会价值**,不存在可写的目标函数——
   排播可以机械化(约束求解),排播**该不该**把公共时间对齐不可机械化;
   这正是本家族实验用「模拟+断言」而不用「优化器」的原理级原因
2. **节目好坏的判定不可机械化**:完播率/点击预测的是行为不是价值
   (03 章层 2 的反身性:指标成目标即变形)——推荐系统可以最大化
   任何给定的代理,但「总体平衡」(今晚这条流对国民值不值)没有裁判程序
3. **响度合规≠好听**:LUFS 管得住「不超标」,管不住「动人」——
   测量层与审美层没有推理通道(02 章 §二)
4. **陪伴感不可由系统产出**:广播的「有人在场感」是节目与生活节奏
   的长程耦合(00 章反直觉 1)——系统可供给内容,供给不了「在场」;
   「陪伴型 AI 语音」是这个边界上的诚实注脚

## 二、代码走廊清单(从零到一的三条走廊)

**走廊 1:音频处理基础**(对应 02 章声音语、03 章层 4,00 章美之时刻 2)

合成一段「元音」并看它的频谱——傅里叶之美的纯标准库最小版:
```python
import math

def synth_vowel(f0=120.0, harmonics=((1, 1.0), (2, 0.55), (3, 0.30),
                                     (4, 0.20), (5, 0.28), (6, 0.10)),
                dur=0.25, rate=8000):
    """按泛音列合成准周期声:音色=泛音比例(00 章美之时刻 2 的数)。"""
    n = int(dur * rate)
    return [sum(a * math.sin(2 * math.pi * f0 * k * t / rate)
                for k, a in harmonics)
            for t in range(n)]

def dft_peak(x, rate, f_lo, f_hi, steps=400):
    """教具级 DFT 扫频:在 [f_lo, f_hi] 找能量峰(频谱骨架,
    生产级用 FFT/Goertzel)。"""
    best = max(
        ((abs(sum(x[t] * math.cos(2 * math.pi * f * t / rate) for t in range(len(x))) )**2
          + abs(sum(x[t] * math.sin(2 * math.pi * f * t / rate) for t in range(len(x))) )**2,
          f)
         for i in range(steps)
         for f in (f_lo + (f_hi - f_lo) * i / steps,)),
        default=(0.0, f_lo))
    return best[1]
```
用法:合成 f0=120Hz 的元音,扫频 60-1000Hz 逐峰提取——打印出的
**等距泛音阶梯**就是「音色」的物理形状;改一组泛音比例,
阶梯变、扫出的峰变,听感随之变。要点:采样率必须高于两倍最高频率
(奈奎斯特——信息论邻居([../../讲透数学/讲透信息论/](../../讲透数学/讲透信息论/))
的第一课在音频链上的显形);响度可用能量均方根近似
(生产级换 BS.1770 的 K 计权)。

**走廊 2:黄金时段共同在场模拟**(对应 00 章反直觉 2,03 章层 1)

家族实验 [`experiments/00_primetime.py`](experiments/00_primetime.py):
观众可用性钟形曲线×多频道份额竞争——**不给任何「节目质量」先验**,
断言黄金时段在总收视曲线里自发涌现(A2)、社交协调把峰值磨尖(A4)、

**走廊 3:推荐与时移——排播的最小继承者**(对应 01 章战线 1,03 章钢梁④)

把「排播表」翻译成「个人的节目表」,纯标准库骨架:
```python
def personal_schedule(catalog, viewer, slots):
    """点播时代的'排播':给每个时刻挑全局最优(线性) vs 个人最优(时移)。"""
    # 线性模式:全体同一张表(编辑排播)——共同在场最大化
    linear = {t: max(catalog, key=lambda p: p.appeal) for t in slots}
    # 时移模式:每人一张表(个人可用性匹配)——个人便利最大化
    shifted = {t: max(catalog, key=lambda p: p.fit(viewer, t)) for t in slots}
    return linear, shifted
```
要点:两行代码就是两种经济(排播经济 vs 门户经济)的全部结构差异;
把家族实验的 A5 断言接到这里——时移后**总量守恒、峰值塌陷**,
即「共同在场假设买的是峰,不是量」。推荐的完整形态=
个人偏好×平台目标(完播率/多样性约束)——注意它是**可见性分配**,
本质是把 03 章层 1 的排播立法从编辑手里移到算法手里。

**走廊间自检断言清单**(exit-0 纪律的通用版):
```python
assert all(-60 <= lufs <= 0 for lufs in loudness_reports)     # 响度语法:LUFS 合法域
assert 0.0 <= share_a + share_b + share_c <= 1.0 + 1e-9       # 份额语法:市场守恒
assert peak_slot(tuned) in primetime_window                   # 涌涌现断言(走廊 2)
assert abs(total(shifted) - total(linear)) <= 0.05 * total(linear)  # 时移守恒(走廊 3)
```
断言失败的位置=理论假设被凿的位置——与社会统计家族「断言看守假设」同构。

## 三、工程师落点(性能工程视角)

| 落点 | 广电原理 | 工程现场 |
|------|---------|---------|
| **流媒体分发** | 广播=一点对全体的**组播经济学** | 单播 CDN:每人一条流,带宽成本随观众**线性**涨——「直播」在流媒体时代反而最贵;ABR 码率阶梯(同一内容切多档)、HLS/DASH 切片、CDN 边缘缓存、P2P 分发都是在对冲这个反转 |
| **低延迟直播** | 直播感=共同在场(02 章 §二) | LL-HLS/LL-DASH/WebRTC:把切片延迟压到秒级;**延迟预算就是体验预算**——弹幕/竞猜场景对齐到秒,否则剧透穿帮 |
| **FAST 频道** | flow 重生(03 章层 3) | 云 playout:循环节目单→自动导播→切片上 CDN——**线性流生成器即服务**;EPG 由节目单模板自动渲染 |
| **时移/回看** | 错过即失去的钢梁拆除(03 章 §二①) | 边缘 DVR:直播流滚动落盘 N 小时,拖进度条即回看;断点续看=每个账户一个播放指针 |
| **响度合规** | BS.1770/R128(02 章 §三第一档) | 上线前 LUFS 批处理归一;转码流水线里挂响度滤镜——「每条一样响」是数学不是玄学 |
| **EPG 与排播系统** | 排播=约束分配(03 章层 1) | 编播系统的约束求解器;竞品排播爬取→对位决策辅助;注意:**给建议不给裁决**——裁决的社会价值不可编码(§一 1) |
| **收视/流量分析** | 测量反身性(03 章层 2) | 全量回流替代抽样:消除样本偏差,引入**平台内偏差**;指标设计者手里握着内容进化的选择压 |

**性能工程特别提示**:直播的热点在**首帧时间**(秒开)与切片边缘命中率
(切片缓存天然 CDN 友好:同一秒的切片全民共享——广播的组播经济学
在缓存层悄悄还魂);转码热点在批量并行(纯函数,天然横向扩展);
**每路流的码率决策日志必须随行**(哪一档、为何切换)——
排播系统的审计教训同构:串联结构里,不可追溯的环节等于不可修复的环节。

## 四、一个完整案例:把一个线性频道搬上平台(FAST 化全链路)

**问题**:一个只有存量片库的地方频道,要变成平台上的 24 小时 FAST 频道。

1. **翻译成广电问题**:它要卖的不是目录(点播已有),是**流**——
   观众要的是「打开就在播、不用选」的换台体验(03 章层 3 的 flow 需求)
2. **排播层**:循环节目单生成器——片库按类型契约(电影频道/剧频道)
   与时段曲线(晚间强片、白天填充)自动装配;带动与吊床逻辑写进
   装配规则(03 章层 1 的代码化)
3. **播出层**:云端 playout 按节目单滚动切片→HLS 清单→CDN;
   响度归一在转码流水线批量过(§三)
4. **测量层**:播放器回流(开播/停留/切换)聚合为份额指标——
   注意口径:测的是「流上的停留」,不是「节目被看」(03 章层 2 的反身性)
5. **广告层**:广告位插在切片边界,按**时段+人群**定价——
   黄金时段的稀缺性定价在 FAST 上复活(02 章 §一的经济重述)
6. **边界**:系统能最大化停留,不能回答「这条流对本地观众值不值」——
   编辑岗(排播策略)保留人裁,算法只装配(§一 1/2)

一条链走完家族四层:排播构造(层 1)、流构造(层 3)、测量构造(层 2)、
工程落点(§三)——这就是「广电的语法,工程的句子」。

## 五、为什么不直接「全部交给推荐算法」

常见混淆:门户时代,排播死了,算法分发接管一切——三条原理级反驳:
①**推荐优化的是个人代理,排播生产的是公共品**:共同在场的好处
   分摊在全体头上(第二天有得聊、社会有共同时刻),不在任何个人的
   完播率里——全盘个性化等于**系统性拆除公共时间**,而它的代价
   (共同体时间表的消失)不进任何一家的目标函数(00 章中心战场);
②**指标反身性不可逃**:完播率成目标,内容就长成完播率的形状
   (03 章层 2)——换指标不除刚性,只换选择压方向;
③**正当性来源不同**:排播的正当性来自编辑与频道的公共问责
   (谁的黄金时段给了谁,可质询),推荐的正当性来自效果宣称
   (相关性分数)——前者可辩论,后者只能 A/B。
   算法的正确位置:装配器与可见性分配器,**公共时间的立法留给人**。
