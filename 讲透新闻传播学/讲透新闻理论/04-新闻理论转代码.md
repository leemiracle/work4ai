## 一、可机械化边界:什么能算、什么算不了

**能机械化的**(有原理保证或明确程序对应的"算"):

| 新闻理论动作 | 机械化形态 | 保证来自 |
|-------------|-----------|---------|
| 议程测量 | 报道流→议题桶→显著性排序;相关性计算 | 议程设置的确证传统(数千研究) |
| 框架分析 | 词频对比(卡方/对数似然比)挑区别性词证;框架词典匹配 | Entman 四功能位的操作化(03 章层 2) |
| 可信度信号 | 文体特征(感叹号密度/煽情动词率/限定语比)/溯源特征(独立源计数)/自愈特征(更正历史) | RECLAIM 2023 等(检索校准 2026-09-07) |
| 误讯/谎讯分级路由 | 按三分法+危害度分流(标注/降权/限流/删除) | Broda & Strömbäck 2024 三分法(检索校准 2026-09-07) |
| 议程动力学 | 有限注意力传播模型(媒体显著性→公众议程) | 本家族实验(assert 自验证) |
| 事实句/意见句粗标 | 规则+模型的句子级分类 | 报道语法层的规范结构(02 章) |

**机械化不了的边界**(为什么——原理级回答):
1. **真实性判定不可完全自动化**:语境、意图、讽刺、旧图新配的"真图假景"
   (恶讯)是语义难题;自动核查能压范围不能兜底——**最后一公里必须留给人审**,
   这是制度设计题不是模型升级题
2. **新闻价值判断不可机械化**:五要素可操作化(02 章)到判据层,但"总体平衡"
   (今天的世界值得这幅图吗)没有目标函数可写——把价值判断写死在管道里
   =把编辑部的立场藏进代码(与社会统计家族"口径不可自动化"同构)
3. **信任不可由系统直接产出**:系统供给的是可信度**信号**;信任是制度的
   涌现性质(03 章构造极限)——"我们做了信任分"这句话在语法上夸大其辞
4. **文体信号正在贬值**:LLM 天然文体满分(01 章战线 3)——把可信度押在
   文体特征上的系统,在生成式 AI 时代**必然失守**,信号重心必须迁移到溯源

## 二、代码走廊清单(从零到一的三条走廊)

**走廊 1:媒体框架分析文本工具**(对应 03 章层 2,02 章 §四句型)

两份同题报道语料(A 源/B 源),挑出各自"区别性词证"的最小骨架:
```python
def distinctive(freq_a, total_a, freq_b, total_b):
    """对数似然比挑区别词:词在两语料中的出现次数对比。
    LLR = 2 * (k1*log(k1/e1) + k2*log(k2/e2)),k=实际频次,e=同分布期望。"""
    ...
chi2 = (freq_a * total_b - freq_b * total_a) ** 2 / (
    (freq_a + freq_b) * (total_a + total_b))      # 卡方(教具版,2x2)
```
用法:挑出 A 源 top 区别词(如"受害者/补偿/家园")与 B 源 top 区别词
(如"工期/分流/效率"),对照 Entman 四功能位归类——**取景框当场显形**。
要点:区别性≠倾向性;词证必须回到例句核对(避免"词袋反讽"——引述词
被算成立场词)。这是"你没框架"这句假话的机器化反驳(03 章反直觉)。

**走廊 2:可信度信号提取器**(对应 03 章层 3,01 章战线 3 的工程对应物)

单篇文本的可信度信号面板,纯标准库最小版:
```python
def style_signals(text):
    return {
        "exclaim_density": text.count("!") / max(1, len(text.split("."))),
        "shout_ratio":     sum(w.isupper() and len(w) > 3
                               for w in text.split()) / max(1, len(text.split())),
        "hedge_ratio":     count_hedges(text) / len(text.split()),   # 限定语词典
        "sensate_verbs":   count_sensational(text) / len(text.split()),
    }
def source_signals(article):
    return {
        "has_attribution": ...,          # 有无"据…"结构
        "n_independent_sources": ...,    # 独立信源计数(排除转述串门)
        "correction_history": ...,       # 历史更正次数与响应时长
    }
```
纪律:信号**多源冗余**——单信号必被 Goodhart 化(03 章层 3);文体信号
只作低权重先验,溯源与自愈信号作主权重;输出必须是"信号面板"而非
"可信度分数"(后者是修辞升级,不是计算)。

**走廊 3:议程设置模拟**(对应 03 章层 1/美之时刻 3)

家族实验 [`experiments/00_agenda_sim.py`](experiments/00_agenda_sim.py):
两议题有限注意力竞争——媒体显著性 M_A 的报道流 + 人际交谈的共鸣放大,
输出公众议程 P_A;三条断言:媒体议程→公众议程的相关 r≥0.95、
共鸣放大(P 比 M 更极端)、中间区域赢者通吃。它是"媒体告诉人们**想什么事**"
的零智力自涌现证明——也是平台"热搜制造共识"的最小病理模型。

**走廊间自检断言清单**(exit-0 纪律的通用版):
```python
assert 0.0 <= p_public <= 1.0                        # 概率语法:议程是占比
assert pearson(m_agenda, p_agenda) >= 0.95           # 议程设置主效应(走廊 3)
assert all(s >= 0 for s in signals.values())          # 信号非负、无单点 >1 主导
assert len(top_words_a & top_words_b) == 0            # 区别词不重叠(走廊 1 自检)
```
断言失败的位置=理论假设被凿的位置——与社会统计家族"断言看守假设"同构。

**最小工具栈**:

| 层 | 首选 | 一句话理由 |
|----|------|-----------|
| 教具级 | 纯标准库(math/statistics/collections/random) | 家族做法:透明第一,能 assert 自验证 |
| 文本处理 | jieba(中文分词)+ scikit-learn(CountVectorizer/χ²) | 走廊 1 生产级;中文分词是前置 |
| 序列标注 | 规则+小模型(事实句/意见句、信源抽取) | 走廊 2 的抽取层;不可全信,置信度随行 |
| 图分析 | networkx(信源独立性图/协同账号网络) | "据多方消息"的串门检测;协同轰炸检测 |

## 三、工程师落点(性能工程视角)

| 落点 | 新闻理论原理 | 工程现场 |
|------|-------------|---------|
| **内容审核系统** | 把关理论(03 章钢筋 2) | 审核流=新把关漏斗:串联闸门连乘放大偏差——每一环的假阳性/假阴性要单独审计,不能只看端到端 |
| **真实性系统** | 三分法路由(01 章战线 1) | 误讯→标注与素养提示;谎讯→溯源与限流;恶讯→隐私与语境处置——**分级先于判断**,混装即错配 |
| 饱和轰炸检测 | 普遍怀疑效应(01 章战线 2) | 监测目标从"单条内容假"升级为"账号群的协同节律"(发帖时间熵骤降、内容模板化)——战术是制造怀疑,特征就要抓"工业化的怀疑生产" |
| 可信度特征工程 | 信号-代理之别(03 章层 3) | 文体特征降权(AI 贬值中),溯源/自愈特征升权;单一信号上 KPI=给它写死刑 |
| 热搜/推荐议程 | 议程设置+赢者通吃(走廊 3) | 推荐系统的显著性分配就是媒体议程——"只推不编"照样带议程;中间区域的赢者通吃要人为加平滑(探索位/多样性约束) |
| A/B 平台的"平衡" | 假平衡语法(02 章) | 两面呈现≠中立:给证据悬殊双方同权重是算法化的假平衡——权重要跟证据质量走 |

**性能工程特别提示**:审核管道的热点在级联判决的吞吐与文本特征的批量计算
——特征提取是纯函数,天然可并行;协同检测的网络分析注意稀疏表示;
**每环判决的审计日志必须随行**(谁拒的、依据哪条信号)——
把关理论的老教训:串联结构里,不可追溯的环节等于不可修复的环节。

## 四、一个完整案例:从问题到代码的全链路

**问题**:平台发现某争议话题下"怀疑一切"情绪激增,设计一套分级响应。

1. **翻译成新闻理论问题**:饱和轰炸式暴露→普遍怀疑抬升(01 章战线 2 的现场);
   载体大概率是协同账号群(工业化的怀疑生产)
2. **检测**(走廊 2+落点 3):账号群发帖时间熵骤降+内容模板化=协同信号;
   话题内信源独立性图分析:多账号引用同一源头=串门(02 章"据多方消息"的机器版)
3. **分级路由**(三分法):无恶意的误传→标注"未证实"并提示核查方法;
   蓄意谎讯→溯源处置+限流;真图假景(恶讯)→语境补丁与隐私处置
4. **反饱和**(议程层):对协同群的显著性增益做封顶,给非协同内容留探索位——
   不让赢者通吃把议程锁死(走廊 3 的均衡干预)
5. **度量**(勿越界):成功的度量是"普遍怀疑曲线回落"与"非协同内容触达恢复",
   **不是**"删除量"(删除量是产出不是效果,Goodhart 风险最高)
6. **制度**:每步处置留审计日志与申诉通道——把关的正当性来自可追溯,
   不来自判决正确率(新闻法支的正当程序原则,工程版)

一条链走完家族四层:三分法与信号(01/03 章)、把关与议程(00/03 章)、
正当程序(伦理与法支)——这就是"新闻理论的语法,工程的句子"。

## 五、为什么不直接"全部交给 LLM"

常见混淆:LLM 能读能写,审核与核查直接端到端——三条原理级反驳:
①LLM 是**文体完美主义者**:RECLAIM 2023 证明文体显著影响可信度判断,
   而文体恰是 LLM 免费满分的维度——用 LLM 做可信度裁判,等于让最会"写得像"的
   选手兼任验伪官(01 章战线 3 的裁判版);
②LLM 缺**溯源通道**:可信度的主信号在消息源与更正历史(外部的、可审计的),
   不在文本内部——真实性是供应链问题,不是阅读理解问题;
③LLM 不可**问责**:把关的正当性要求判决可追溯到规则与证据(§四案例第 6 步),
   端到端模型把判决理由压进权重——黑箱把关是黄色新闻以来最老问题的新马甲。
LLM 的正确位置:特征提取器与初筛漏斗(可并行、可降本),
**判决的最后一公里与问责链留给人与制度**。
