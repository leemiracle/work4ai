## 一、可机械化边界:什么能算、什么算不了

**能机械化的**(有原理保证或断言护栏的"算"):

| 新闻业务动作 | 机械化形态 | 保证/护栏来自 |
|-------------|-----------|--------------|
| 结构化新闻(财报/体育/天气/地震快讯) | 模板引擎+数据 API → 自动成稿 | 字段全覆盖断言(缺"同比"字段=拒发) |
| 自动摘要 | 倒金字塔=抽取式摘要天然对齐:按信息单元权重取前缀 | 摘要保真断言(核心单元覆盖率≥阈值) |
| 数据新闻管线 | 取数→清洗→聚合→视觉编码草案 | 每数带出处列(可溯源断言) |
| claim 检索匹配 | 新言论 ↔ 已核查库的相似度匹配(关键词/嵌入) | 匹配只输出"候选",判定必须人工签署 |
| 转写与翻译初稿 | ASR+说话人分离+译后编辑台 | 人工校对环节不可跳过(引语一字不改的纪律) |
| 文体 lint | 数字规范/无归因句侦测/标题字数 | 02 章栏一的语法表 → 规则集(与 linter 同构) |
| 调查线索生成 | 多 agent 交叉检索公开记录 → 线索表 | "线索机器生成,证实人到场"(01 章战线 5) |

**机械化不了的边界**(为什么——原理级回答):

1. **采访不可远程化**:信源在信任关系里才交付的信息、现场的身体感知——
   信息本身不在线上,远程构造不出它(03 章 §三极限 1)。
   电话采访是折中,视频是折中的折中;**在场性是信息,不是态度**
2. **责任不可外包**:AI 能写稿、能给判定建议,但"判它为真"的署名责任不能外包——
   机器不能担保,因为机器不能被问责。这不是能力问题,是**制度结构问题**:
   署名=责任锚点(02 章栏三),锚必须钉在一个可被追责的人上。
   04 章的全部门槛归结为一句:**机器填结构,人签判断**
3. **新闻价值的最后一级不可自动判定**:清单可辅助筛选,
   "这条稿为什么重要"的编辑直觉没有算法代理(03 章层 4 的外骨骼原理)
4. **价值判断与立场不可代笔**:评论的署名立场、社论的机构立场——
   让模型代写立场,等于机构把自己的责任资产抵押给一个不能被问责的作者

## 二、代码走廊清单(从零到一的三条走廊)

**走廊 1:数据新闻管线**(对应 00 章美之时刻 2、03 章层 2 数据监测源)

```python
# 纯标准库最小管线:CSV -> 清洗 -> 聚合 -> 排行 + 变化率
import csv

def load_and_clean(path, must_cols):
    rows = [r for r in csv.DictReader(open(path, encoding="utf-8"))
            if all(r.get(c) for c in must_cols)]          # 缺关键字段整行拒收
    return rows

def rank(rows, key, by):
    agg = {}
    for r in rows:
        agg[r[by]] = agg.get(r[by], 0) + float(r[key])
    return sorted(agg.items(), key=lambda kv: -kv[1])

assert rows_with_no_source_column == []                    # 断言 1:每数带出处列
assert abs(sum(agg.values()) - total_from_official) < eps  # 断言 2:聚合数对得上官方总数
```

要点:**每个数拖着"怎么来的"字段**(哪个文件哪一行)——
数据新闻的可信度不在图漂亮,在表格里每个数可双击溯源(03 章归因钢筋的数据版)。
AI 的位置(01 章战线 3):清洗建议、异常点标注、可视化草案——
但**坐标轴/图例/色板走断言不走生成**(可视化复刻的"像但不对"陷阱,01 章方向锚)。

**走廊 2:自动摘要——倒金字塔的实用化**(家族实验的工程版)

```python
# 抽取式摘要 = 按"信息单元权重"取前缀,天然继承倒金字塔的截断保真
def summarize(facts_by_para, core_ids, k=3):
    covered = set().union(*facts_by_para[:k])
    return covered

core_cov = len(summarize(p, CORE, 3) & CORE) / len(CORE)
assert core_cov >= 0.8        # 摘要保真断言:前三段必须覆盖 >=80% 核心单元
```

LLM 时代这条走廊的分裂:抽取式(选段,可断言保真)vs 生成式(改写,流畅但可引入
未溯源细节)。工程纪律:**可断言的场景用抽取式;生成式摘要必须过"细节溯源"人工闸**——
因为模型幻觉=机器自动生成的细节密度(00 章 §七发现 2 的放大)。

**走廊 3:事实核查工具雏形**(对应 03 章层 3 工序)

```python
# claim 匹配:新言论的关键词集合 vs 已核查库;输出候选,判定必须人工签署
def match_claims(new_claim_kw, checked_db, threshold=0.4):
    cands = []
    for entry in checked_db:                      # entry: {kw, verdict, evidence, signer}
        j = len(new_claim_kw & entry["kw"]) / len(new_claim_kw | entry["kw"])
        if j >= threshold:
            cands.append((j, entry))
    return sorted(cands, reverse=True)

for _, e in match_claims(kw, DB):
    assert e["signer"] != "auto"                  # 断言:已核查结论的判定人非"auto"
decision = {"verdict": human_verdict, "signer": editor_name}   # 判定永远人工签署
```

要点:匹配算法只负责"把已核查结论递到人眼前";ClaimReview 式元数据
(verdict/evidence/signer)是核查结论成为公共品的前提(01 章战线 6)。
**"signer != auto" 是这条走廊的第一断言**——责任盒刚性(03 章钢筋 3)的代码化。

**走廊间自检断言清单**(三条走廊通用的 exit-0 纪律):

```python
assert all(r["source"] for r in published_numbers)      # 每个数有出处
assert core_coverage(summary) >= 0.8                     # 摘要保真
assert decision["signer"] in HUMAN_EDITORS               # 判定有人签
assert template_fields_complete(rendered_draft)          # 模板稿字段全覆盖
assert correction_links_to_original(erratum)             # 更正可回链原稿
```

五条断言看守五个假设:可溯源(00 章 §五客观性假设)、截断保真(倒金字塔假设)、
责任在位(把关假设)、结构完整(模板护栏)、错误可返(更正制度)——
断言失败的位置=假设被凿的位置(与社会统计家族的"断言看守假设"同构)。

**最小工具栈**(走廊从零到一的装配顺序):

| 层 | 首选 | 一句话理由 |
|----|------|-----------|
| 教具级 | 纯标准库(csv/random/字符串集合) | 家族实验的做法:透明第一,能 assert 自验证 |
| 单机生产 | pandas/DuckDB | 管线与聚合的现役标配;出处列必须全程随行 |
| 内容层 | CMS 模板引擎+结构化数据 API | 机器人写稿的母港:模板与数据解耦 |
| 检索层 | 向量检索(claim 库/线索库) | claim 匹配与多 agent 线索生成的地基件 |
| 元数据层 | ClaimReview/C2PA 式 schema | 核查结论与影像溯源的公共品格式 |

装配纪律:任何一层引入 LLM,**输出必须落在断言护栏之内**——
生成的是"草案/候选",签署的才是"内容"(层与层的方向不可逆)。

## 三、工程师落点(性能工程视角:编辑部工具链)

| 落点 | 原理(本家族) | 工程现场 |
|------|-------------|---------|
| **转写流水线** | 采访录音→文字初稿(引语纪律=逐字保真) | ASR+说话人分离+校对台;批处理队列,GPU 排队与优先级(截稿刚性→SLA 分级) |
| **结构化写作系统** | 模板+数据 API(走廊 1 的姊妹) | 财报快讯分钟级出稿;字段断言先行,缺字段拒发 |
| **核查看板** | claim 库+ClaimReview(走廊 3) | 新言论入库→匹配→复核队列;向量检索的嵌入缓存与更新策略 |
| **标题 A/B 与版面实验** | 标题学(编辑支)+ 假平衡/点击率张力 | 实验分流;**指标反噬警报**:CTR 最大化会系统性偏向负面/耸动——新闻价值清单是护栏不是竞速表(Goodhart) |
| **多 agent 线索池** | 调查线索生成(01 章战线 5) | 公开记录爬取→交叉不一致侦测→线索表;人复核队列;检索预算与礼貌爬取 |
| **实时数据管道** | 截稿刚性的极端形态 | 选情/灾难之夜:实时写入、多级缓存、**降级预案**(管道挂了发"数据延迟"模板稿——完结优先于完美) |
| **内容版本控制** | 三审三校的 git 化 | draft→edit→signoff 不可变审计链;每稿每版可回溯(更正制度的技术底座) |

**性能工程特别提示**:事件夜的写放大(数百万次增量更新+读风暴)、
转写批处理与截稿 SLA 的冲突(排队论问题:优先级队列按截稿时间而非提交时间)、
嵌入检索的缓存失效(claim 库日更,热向量与新向量的双索引)——
编辑部的性能问题,全是**截稿刚性**在系统各处的投影。

## 四、一个完整案例:财报快讯从数据到发布

**问题**:上市公司财报 22:00 发布,快讯要求 10 分钟内上稿,准确率 100%。

1. **拆任务**(01 章战线 1 三步法):数据已结构化✓/字段可校验✓/人审签署✓ →
   机器起草+人签发
2. **取数**:数据 API 拉原始报表 → 字段断言(营收/净利/同比三件套缺一拒发)
3. **渲染**:模板引擎成稿(倒金字塔模板:导语=三件套,次段=业务分解,末段=背景)——
   模板即文体语法的代码化(02 章栏一)
4. **自动摘要**:推送通知的 60 字版本=导语再压缩(走廊 2,覆盖率断言)
5. **人审签署**:编辑 3 分钟复核数字与措辞 → 签发(署名=责任锚点)
6. **发布+存档**:CMS 发布,全链路审计存档;差错走更正流程(错误返回值)

对照错误路径:某财经站曾因数据源字段错位,把"同比下滑"发成"同比上升"——
缺的不是模型,是**第 2 步的字段断言**(数值与方向的交叉校验)。
结构化体裁的全部安全感来自断言,不来自生成质量。

## 五、为什么不直接"全部交给大模型"

常见混淆:生成式 AI 写得比初级记者流畅 → 编辑部可以裁人。
三个原理级反驳:

1. **幻觉=不可溯源细节**:模型生成的具体细节(一个精确数字、一句"现场人士"引语)
   恰恰是最像新闻的部分(00 章 §七发现 2)——机器以工业规模生产"细节可信度信号",
   而信号与事实的耦合在生成过程里没有任何保证
2. **责任结构不匹配**:署名的人要对每个字负责,而模型的输出不可向作者追责——
   "AI 写的稿"在署名制下**结构性无主**;披露条款(02 章栏三)处理的是
   "辅助"的边界,不是"代笔"的许可
3. **Cools 2024 的行业证据**(检索校准 2026-09-07):从业者对 GenAI 的真实使用
   集中在内部辅助(头脑风暴/摘要/标题候选/代码),公开发布文本最保守——
   行业用脚投票的结论与本章边界一致:**AI 当同事,不当替身**
