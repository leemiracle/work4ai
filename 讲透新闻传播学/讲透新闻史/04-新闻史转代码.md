# 04 · 新闻史转代码——报纸数字化档案与词频年代学的两条走廊

> **本章回答五问之 Q5(问题→代码转换)**。
> **本质一句话**:新闻史的问题一旦变成「关于史料的计算」,就能进代码——
> 编年变密度曲线、旧报纸变带元数据的全文对象、概念的兴衰变词频年代学;
> **唯一不可外包给代码的,是史学判断本身(选样、定性、分期裁决)**。
> 本章三件套:可机械化边界 → 两条代码走廊(报纸数字化档案/词频年代学)→
> 工程师落点(媒体档案系统)。

---

## 0. 开篇:113 条记录检验「媒介换代加速」

「印刷→电报→广播→电视→互联网,每次换代新闻事业大事密度跳一级」——这是
写在通史直觉里的话。它对吗?

`experiments/00_press_timeline.py` 用 113 条大事记录(713-2023)做了最朴素的
检验:按技术代际窗口切片、数事件、算密度。跑一遍你会看到:

```
技术代密度递增检验:
  印刷(1450-1836)   18 件/387 年 =  4.7 件/百年
  电信(1837-1919)   25 件/ 83 年 = 30.1 件/百年
  广播(1920-1935)    9 件/ 16 年 = 56.2 件/百年
  电视(1936-1988)   32 件/ 53 年 = 60.4 件/百年
  互联网(1989-2006) 13 件/ 18 年 = 72.2 件/百年
  —— 五代单调递增 ✓(移动/社交代进行中,右删失,不纳入断言)

中国近现代密度检验:1840-1949 窗口中国事件 25 件
  ≈ 22.7 件/百年,为古代窗口(713-1839,0.44 件/百年)的 51 倍;
  且占同期全库事件的过半——近现代中国报刊的高密度带是数据事实
```

直觉被确认。但脚本同时打印**选样声明**:密度度量「正史关注度」,不是
「新闻活动总量」。**代码替你算数,替不了你解释数**——而「替你算数」已经
足以把一段修辞变成一个可反驳的命题(03 章 §0 的第一课)。

## 1. 可机械化边界(三件套之一)

**能进代码的**(史料数据化后的一切结构计算):

| 任务 | 机械化形式 | 走廊 |
|------|-----------|------|
| 编年密度/技术代际检验 | 事件点列 → 世纪直方图、窗口密度比 | 家族脚本(已实现) |
| 旧报纸检索与统计 | 全文库 API → 词频/共现/版面分布 | C1 |
| 概念兴衰(词的三步法计量版) | 逐年词频 → 消长曲线(「黄色新闻」何时入中文) | C2 |
| 标题/版面的大规模提取 | CV 目标检测 → 标题框→字号/位置序列(01 章 §1.3) | C1 延伸 |
| 报业种数/发行量曲线 | 目录数据 → S 型三幕与交叉点(03 章 §5) | C1 延伸 |

**不能进代码的**(新闻史的「不可判定域」):

1. **选样正当性**——113 条编年的入库资格是史学判断;代码只能做敏感性分析
   (换窗口/换选样重跑,§5)。
2. **邸报定性之争**——「官报算不算报纸」取决于「公众性/批评权」的判据选择,
   **判据本身是史学立场**,不可被 assert(00 章 §4)。
3. **「第一份报纸」裁决**——1605 vs 1615 之争的实质是「印刷?周期?售卖?」
   的定义之争;代码可核对证据链,不可裁决定义(03 章 §5 同构)。
4. **死亡预言的判断**——报纸会死吗是开放未来;史学方法只能给结构位置
   (03 章 §2 第四个问号),把预测写进 assert 是对两边的冒犯。

> 边界的一句话:**代码是史料的显微镜,不是史学家**。放大倍数越高,
> 越要记得镜头(选样/OCR 质量/库的收录范围)是谁选的。

## 2. 走廊 C1:报纸数字化档案(三件套之二)

**史料基础设施的公共样本**:Chronicling America——美国国会图书馆(LC)与
NEH 的国家数字报纸计划(NDNP)建设的历史报纸全文库(2007 上线),数百万页
18-20 世纪报纸,开放的 JSON API 与标准元数据(方向锚,时效声明见 01 章 §1.6)。
欧洲对应物 Europeana Newspapers(2012 起)。

**最小可用操作**(纯标准库,联网;检索词任意替换):

```python
from urllib.request import urlopen
from urllib.parse import quote
import json

BASE = "https://chroniclingamerica.loc.gov/search/pages/results/"
q = quote("yellow journalism")          # 检索词:任何词都行
url = f"{BASE}?format=json&rows=20&q={q}"
data = json.load(urlopen(url, timeout=30))
print("总命中页数:", data["totalItems"])
for item in data["items"][:5]:
    print(item["date"], item["title"])   # 日期×报名=最小的编年证据
```

跑一次你就完成了新闻史最典型的一次查询:**一个词,百年报纸,总命中数+逐年分布**。
把 `q` 换成任一候选词,你就得到它的「档案足迹」曲线——C2 词频年代学的原料。

**C1 数据字典**(数字报纸档案的四层骨架,03 章 §4 的落地):

| 字段 | 类型 | 约束/坑 |
|------|------|--------|
| title | str | 报名含沿革;更名要当新节点处理(否则曲线断裂) |
| date | ISO 日期 | 历法换算坑:民国纪年/日本年号须换算;**缺日期页面单独标桶** |
| page/sequence | int | 版次;头版与否是重要性分层的粗判据 |
| ocr_text | str | OCR 错误率随年代字体漂移——跨年代比较先抽样人工校对(§3 坑) |
| (结构标准) | METS/ALTO | 版面坐标+文本层的 XML 标准;扫描图共享 IIIF——**有 ALTO 才有 CV 标题提取的地面真值** |

**C1 的扩展练习**:①统计某词命中的逐年分布并画 ASCII 直方图;②对比两个同义
词的命中曲线(如 evening edition 相关检索);③找一个中文历史报刊库,核对它有没有
公开 API——把「有没有 API」本身记为一条史料学观察。

## 3. 走廊 C2:词频年代学

概念的三步法(02 章 §3)有一个计量版:**词频的时间消长**。最小可用分析——
分桶计数(纯标准库,对任何已获取的文本语料):

```python
from collections import Counter
corpus = {  # 时段: 文本(示意:各取自该年代报刊文本的样例)
    "1872-1900": "邸报 京报 申报 电音 消息 京报 京报 ...",
    "1912-1930": "新闻 舆论 副刊 记者 舆论 消息 ...",
    "1980-2000": "新闻 舆论监督 报纸 发行 都市报 ...",
}
for period, text in sorted(corpus.items()):
    print(period, Counter(text.split()).most_common(5))
```

**示范问题:「喉舌」与「舆论监督」的消长**。同一份百年报业文本里,
「喉舌」类词(02 章 §3 第 2 行)与「舆论监督」类词(第 4 行后的中国 1980s 术语)
的相对词频,就是**两种新闻观在同一语言共同体中的力量对比曲线**——
词频曲线是新闻思想史的体温计。

**C2 数据字典**(词频年代学语料表):

| 字段 | 类型 | 说明 |
|------|------|------|
| period | (起年, 止年) | 分桶即分期假设(02 章 §2):桶改,曲线改 |
| source | 枚举 | 语料来源(报名/库);**跨库比较要按库分层** |
| term | str | 追踪词;同义词组要成组计数(词义漂移的对策) |
| freq | int | 命中数;按百万词归一化后才有可比性 |

**断言的史学版**:「『舆论监督』词频 1988 年后陡增」——先手工核对 20 条原文
语境(它说的是制度诉求还是工作总结?),再让代码全量验证。
**代码验证假设,不生成假设。** OCR 坑提示:早期铅字 OCR 会把关键词错认
(如「日」与「曰」),跨年代词频差可能混入**OCR 质量的年代差**——
分层校对是词频年代学的义务(03 章 §4)。

## 4. 工程师落点(三件套之三):媒体档案系统

工程师读新闻史,最划算的落点不是背年表,而是认领一个系统:**媒体档案系统**
——Ringel 2023(《纽约时报》数字报纸存档案例,检索校准 2026-09-07)证明这是
真实存在且有硬问题的工程领域。三个直接落点:

**落点 1:存档格式与元数据——「备份」不是「存档」**。数字原档的三件套
(01 章 §3 军规 3):开放格式(文本+版面坐标,METS/ALTO 一类)、完整元数据
(题名/日期/版面/责任者)、**迁移计划**(格式过期的触发条件)。互联网公司的
「快照备份」缺第二三件——二十年后就是一堆打不开的比特。你设计的 CMS 里,
每篇稿子有没有稳定的版本树与导出格式?这是「今天的新闻史能不能写」的基础设施。

**落点 2:OCR/CV 流水线——版面是数据**。历史报纸处理流水线(扫描→版面分析
(CV 切块)→OCR→结构化索引)与今天的「文档智能」是同一套技术栈;
ITAL 系列工作(深度学习提取历史报纸标题,检索校准 2026-09-07)证明旧报纸是
CV 的真实战场(噪点/多栏/字号混杂)。给档案系统做 OCR 时,**置信度分层数据库**
(低置信页人工复核队列)比「整体准确率」指标有用得多。

**落点 3:检索系统要懂史学选样**。档案检索产品有两个史学需求的默认缺口:
①**coverage 透明**——库收了什么没收什么要成为一等公民数据(01 章 §1.1
的「数据库也是史料」立场);②**查询词的历史别名**——跨年代检索需要同义词组
(「报纸/新闻纸/日报」),否则检索曲线混入词史假象。把这两个做成产品功能,
你的检索系统就比大多数学术数据库懂史学家。

> 一句话:**读史的工程师,是唯一能把「明天的史料」存好的人**——
> 存档不是 IT 后勤,是新闻史能否续写的前提(01 章 §1.4)。
