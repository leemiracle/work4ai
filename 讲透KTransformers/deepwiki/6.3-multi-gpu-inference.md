  This page describes how to distribute model layers across multiple GPUs in KTransformers for improved inference performance. Multi-GPU inference enables running large models (e.g., DeepSeek-V3 671B parameters) by partitioning computation and memory across available GPU devices.

 For general CPU-GPU heterogeneous architecture, see [CPU-GPU Heterogeneous Computing](https://deepwiki.com/kvcache-ai/ktransformers/3.2-cpu-gpu-heterogeneous-computing). For optimizing expert placement and performance, see [Performance Tuning](https://deepwiki.com/kvcache-ai/ktransformers/6.4-performance-tuning). For YAML-based configuration syntax, see [Optimization Rules (YAML)](https://deepwiki.com/kvcache-ai/ktransformers/10.1-optimization-rules-(yaml)).

## NUMA-Aware Multi-GPU Configuration

 When using multiple GPUs on NUMA systems (dual-socket servers), GPU-to-NUMA-node affinity affects performance. Each GPU should ideally be paired with the CPU socket it is physically connected to via PCIe to minimize cross-socket latency.

### Expert Memory Placement

 On dual-socket systems, KTransformers can leverage both NUMA nodes. When running inference, the `--cpu_infer` parameter specifies the number of CPU threads used for MoE computation. For optimal performance on NUMA systems, ensure that the CPU threads are pinned or allocated in a way that respects the physical connection to the GPUs.

## Advanced VRAM Utilization

### Performance Trade-offs

 
| Aspect | Impact | Recommendation |
|---|---|---|
| VRAM Usage | ~6GB per expert layer (DeepSeek-R1/V3) | Monitor with nvidia-smi |
| Loading Speed | Slower for each expert moved to GPU | Use for critical performance layers |
| CUDA Graph | Must be closed to move experts to GPU | Check --cuda_graph settings |
| Inference Speed | Significant speedup for offloaded experts | Prioritize based on VRAM budget |
