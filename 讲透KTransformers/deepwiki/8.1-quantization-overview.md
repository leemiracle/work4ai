## Purpose and Scope

 This page introduces the core concepts of weight quantization in KTransformers, explaining the supported quantization formats (INT4, INT8, FP8, BF16), methods (GPTQ, RTN, AWQ), and strategies for CPU-GPU heterogeneous execution. KTransformers leverages specialized CPU instruction sets like **Intel AMX** and **AVX512** to accelerate quantized inference, specifically targeting the Mixture-of-Experts (MoE) architecture where parameters are distributed across memory tiers.

 
## Core Quantization Strategies

 In KTransformers' heterogeneous architecture, quantization is applied differently based on where the weights reside during inference:

 
 - **CPU-resident Experts ("Cold Experts")**: Frequently quantized to **INT4** or **INT8** using AMX-optimized memory layouts. This allows large models (e.g., DeepSeek-V3 671B) to fit into system DRAM while maintaining high throughput via CPU acceleration [kt-kernel/README.md31](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L31-L31)
 - **GPU-resident Experts ("Hot Experts")**: Typically use **W4A16** or **W8A16** quantization to maximize VRAM efficiency for frequently accessed parameters.
 - **Universal CPU Deployment**: Supports **GGUF** formats (Q4_K, Q5_K, etc.) via the llamafile backend for broad compatibility across different CPU architectures [kt-kernel/README.md32-44](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L32-L44)
 - **Native Precision**: Supports `FP8`, `BF16`, and `RAWINT4` formats on AVX512-capable servers [kt-kernel/README.md30-42](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L30-L42)

## Supported Quantization Methods

 KTransformers implements several quantization schemes, each mapped to specific C++ backend operators and kernel implementations.

 
### INT4 Variants

 
 - **AWQ INT4**: Supports 4-bit quantization with per-group scales and zero-points. The conversion process handles the complex interleaving required by AWQ [kt-kernel/scripts/convert_cpu_weights.py178-188](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_cpu_weights.py#L178-L188)
 - **RAWINT4 (KGroup)**: A native INT4 format optimized for Kimi-K2, using group-wise scales. Supported on AVX512 CPUs with software fallback for older versions [kt-kernel/README_zh.md41-92](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README_zh.md?plain=1#L41-L92)
 - **AMX INT4**: High-performance 4-bit integer quantization for Intel Sapphire Rapids+ CPUs [kt-kernel/README.md43](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L43-L43)
 
 
### INT8 and FP8

 
 - **AMX INT8**: High-performance 8-bit integer quantization for Intel Sapphire Rapids+ CPUs [kt-kernel/README.md31-43](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L31-L43)
 - **FP8 (E4M3)**: Supports 8-bit floating point with block-wise scaling. The conversion script supports processing FP8 inputs by extracting `weight_block_size` from `config.json` [kt-kernel/scripts/convert_cpu_weights.py94-119](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_cpu_weights.py#L94-L119)
 
 
### BF16 and Native Precision

 
 - **Native BF16**: Direct inference on BFloat16 weights using AMX or AVX512 instructions [kt-kernel/README.md30-42](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L30-L42)

## Implementation Details

 
### CPU Weight Conversion (`convert_cpu_weights.py`)

 This tool handles the transformation of high-precision weights into formats optimized for CPU inference.

 
 - **Input Formats**: Supports BF16, FP16, FP8, and AWQ [kt-kernel/scripts/convert_cpu_weights.py58-180](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_cpu_weights.py#L58-L180)
 - **FP8 Handling**: Extracts `weight_block_size` (e.g., [128, 128]) from model configuration for block-wise scaling [kt-kernel/scripts/convert_cpu_weights.py102-115](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_cpu_weights.py#L102-L115)
 - **Packing**: 4-bit weights are packed into 32-bit integers (`STORAGE_BITS`) for efficient memory storage [kt-kernel/scripts/convert_cpu_weights.py24-141](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_cpu_weights.py#L24-L141)
 - **AWQ Reordering**: Reverses AWQ interleaving using `REVERSE_AWQ_PACK_ORDER = [0, 4, 1, 5, 2, 6, 3, 7]` to recover the original row-major order [kt-kernel/scripts/convert_cpu_weights.py29-175](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_cpu_weights.py#L29-L175)
 
 
### C++ Backend Infrastructure

 KTransformers uses a sophisticated C++ hierarchy to manage quantized weights:

 
 - **`MOE_KERNEL_TP`**: A template class that handles Tensor Parallelism (TP) parts and NUMA-aware weight loading [kt-kernel/operators/moe_kernel/moe.hpp22-122](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/operators/moe_kernel/moe.hpp#L22-L122)
 - **`WorkerPool`**: Manages the thread pool and NUMA-aware job dispatching for inference [kt-kernel/operators/common.hpp42-158](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/operators/common.hpp#L42-L158)
