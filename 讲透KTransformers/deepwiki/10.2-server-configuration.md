## Purpose and Scope

 This page documents server-level configuration parameters for running KTransformers inference servers. It covers runtime settings for the `ktransformers` and `balance_serve` backends, memory management across CPU and GPU, and KV cache configuration. Configuration is primarily controlled through command-line arguments and YAML rule files.

 For multi-concurrency backend details, see [balance_serve Multi-Concurrency](https://deepwiki.com/kvcache-ai/ktransformers/6.1-balance_serve-multi-concurrency). For operator-level configuration and layer placement, see [Optimization Rules (YAML)](https://deepwiki.com/kvcache-ai/ktransformers/10.1-optimization-rules-(yaml)).

 Server configuration in KTransformers operates through multiple layers that control different aspects of inference execution. ## Server Launch Parameters

 The server is typically launched via `ktransformers/server/main.py`. This script handles the initialization of the selected backend and the OpenAI-compatible API [doc/en/balance-serve.md114-125](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L114-L125)

 
### Key Launch Parameters

 
| Parameter | Type | Description | Default |
|---|---|---|---|
| --model_path | string | Path to model directory containing config.json. Since v0.2.4, this must be a local directory doc/en/balance-serve.md135-136 | Required |
| --gguf_path | string | Path to directory containing quantized .gguf weights doc/en/balance-serve.md117 | Required |
| --port | integer | Port for the OpenAI-compatible REST API doc/en/balance-serve.md115 | 10002 |
| --backend_type | string | ktransformers (single) or balance_serve (multi-concurrency) doc/en/balance-serve.md134 | ktransformers |
| --optimize_config_path | string | Path to the YAML optimization rules file doc/en/balance-serve.md118 | - |

## Backend Comparison: ktransformers vs balance_serve

 KTransformers evolved from a single-request engine to a complex multi-concurrency system. The `balance_serve` backend is the recommended choice for production-like workloads.

 
### Backend Capabilities

 
| Feature | ktransformers | balance_serve |
|---|---|---|
| Concurrency | Single Request | Multi-Concurrency doc/en/balance-serve.md15-16 |
| Scheduling | Sequential | Continuous Batching (FCFS) doc/en/balance-serve.md25 |
| Prefill Mode | Standard | Chunked Prefill doc/en/balance-serve.md24 |
| Implementation | Python-centric | C++ Scheduler + FlashInfer doc/en/balance-serve.md39-41 |
| Throughput | Baseline | ~130% improvement (4-way) doc/en/balance-serve.md18 |

## Memory and Cache Management

 KTransformers uses a tiered approach to memory, leveraging GPU VRAM for compute-intensive tasks (MLA, shared experts) and CPU DRAM for memory-intensive tasks (MoE experts) [doc/en/fp8_kernel.md6-9](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/fp8_kernel.md?plain=1#L6-L9)

 
### KV Cache Configuration

 The KV cache is managed globally based on the `--cache_lens` parameter.

 
 - **Shared Pool**: All concurrent requests in `balance_serve` share the space defined by `--cache_lens`. Space is released after requests complete [doc/en/balance-serve.md120](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L120-L120)
 - **3-Layer Cache**: Support exists for a 3-layer (GPU-CPU-Disk) prefix cache to reuse KV states for long contexts [README.md37](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/README.md?plain=1#L37-L37)
 - **VRAM Constraints**: For 24GB VRAM GPUs (like 4090), a `cache_lens` of 32,768 is recommended for DeepSeek-V3/R1 to avoid OOM [doc/en/balance-serve.md120](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L120-L120)
 
 
### Expert Offloading Configuration

 The distribution of experts is defined in the optimization YAML rules, but server arguments influence the available compute resources.

 
 - **CPU Threading**: The `--cpu_infer` argument should typically be set to the number of physical cores + 1 for optimal performance on MoE offloading [doc/en/fp8_kernel.md59](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/fp8_kernel.md?plain=1#L59-L59)
 - **NUMA Awareness**: On dual-socket systems, setting `USE_NUMA=1` during installation and launch is critical to prevent cross-node memory latency [doc/en/install.md113-114](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/install.md?plain=1#L113-L114)
