## Verifying CPU Variant Detection

 KTransformers automatically detects the optimal CPU instruction set at runtime. This detection occurs during module import and selects the highest-performance backend available.

 
### Detection Hierarchy

 KTransformers checks for hardware features in the following order:

 
 - **AMX**: Intel Sapphire Rapids+ (e.g., Xeon Gold 6454S) [doc/en/DeepseekR1_V3_tutorial.md75-79](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/DeepseekR1_V3_tutorial.md?plain=1#L75-L79)
 - **AVX512**: Modern Intel/AMD CPUs (e.g., Zen 4) [README.md65-66](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/README.md?plain=1#L65-L66)
 - **AVX2**: Older x86_64 CPUs [README.md21-22](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/README.md?plain=1#L21-L22)
 - **llamafile**: Fallback for universal compatibility [README.md49-50](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/README.md?plain=1#L49-L50)

## Common First-Run Issues

 
### 1. CUDA Out of Memory (OOM)

 If you encounter OOM on a 24GB VRAM GPU when running DeepSeek-R1, ensure you are using the optimized YAML rule: `DeepSeek-V3-Chat-serve.yaml`. This rule is specifically tuned for constrained VRAM environments [doc/en/balance-serve.md118-125](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L118-L125)

 
### 2. NUMA Configuration

 For dual-socket systems (e.g., 2x Xeon), you must set `USE_NUMA=1` during installation to avoid performance degradation caused by cross-socket memory traffic [doc/en/install.md108-115](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/install.md?plain=1#L108-L115)

 
### 3. R1 "No Thinking"

 If DeepSeek-R1 skips the reasoning process, use the `--force_think` flag to ensure the model generates the `<thought>` tags [doc/en/balance-serve.md137-138](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L137-L138)
