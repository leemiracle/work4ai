# Long Context Inference

  Relevant source files 
 - [doc/en/long_context_introduction.md](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/long_context_introduction.md?plain=1)
 - [doc/en/long_context_tutorial.md](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/long_context_tutorial.md?plain=1)
 
  KTransformers provides robust support for long context inference, enabling models like InternLM2.5-7B-Chat-1M and ChatGLM4 to handle sequences ranging from 128K to 1M tokens on consumer-grade hardware. This is achieved through a combination of heterogeneous CPU/GPU memory management, sparse attention mechanisms, and optimized KV cache offloading.

 
## Overview and Purpose

 As context windows grow, the primary bottleneck for local inference is the massive KV cache requirement. For instance, InternLM2.5-7B-Chat-1M requires approximately 145GB of memory for its 1M-token KV cache [doc/en/long_context_introduction.md13](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/long_context_introduction.md?plain=1#L13-L13) KTransformers addresses this by leveraging the mathematical principle of **Attention Sparsity**, where typically less than 5% of tokens contribute significantly to the attention score [doc/en/long_context_introduction.md18-20](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/long_context_introduction.md?plain=1#L18-L20)

 The framework implements a sparse attention operator that retrieves only the most relevant "semantic blocks" from CPU/DRAM or Disk to participate in the GPU-based attention calculation [doc/en/long_context_introduction.md30-32](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/long_context_introduction.md?plain=1#L30-L32)

 
## System Architecture for Long Context

 The long context system utilizes a 3-layer storage scheme (GPU, CPU, and Disk) to manage the KV cache. This architecture is designed to keep the "local" (most recent) window on the GPU while offloading the historical "global" context to the CPU or Disk.

## Implementation Details

 
### Sparse Attention Mechanism

 KTransformers implements a "Retrieval-based" approach inspired by InfLLM and Quest. Instead of pruning the KV cache, it organizes tokens into semantic blocks and selects representative tokens (anchors) to calculate similarity [doc/en/long_context_introduction.md32-42](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/long_context_introduction.md?plain=1#L32-L42)

 Key configuration parameters for this mechanism include:

 
 - `anchor_type`: Method for selecting representative tokens (e.g., `DYNAMIC`) [doc/en/long_context_tutorial.md18](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/long_context_tutorial.md?plain=1#L18-L18)
 - `block_size`: The granularity of KV cache management (default 128) [doc/en/long_context_tutorial.md14](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/long_context_tutorial.md?plain=1#L14-L14)
 - `second_select_num`: Number of blocks retrieved for the attention calculation [doc/en/long_context_tutorial.md16](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/long_context_tutorial.md?plain=1#L16-L16)
 - `anchor_num`: The number of representative tokens within a single KVCache block [doc/en/long_context_tutorial.md21](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/long_context_tutorial.md?plain=1#L21-L21)

### Configurable Parameters (`~/.ktransformers/config.yaml`)

 
| Parameter | Description | Default/Example |
|---|---|---|
| max_seq_len | Total KVCache length supported (limited by DRAM) | 100000 |
| local_windows_len | Length of KVCache stored directly on GPU | 4096 |
| threads_num | CPU threads for sparse retrieval | 64 |
| kv_type | Precision of the stored KV cache (e.g., FP16) | FP16 |
| chunk_size | Prefill chunk size | 4096 |
| preselect_block | Whether to preselect blocks | False |

## Performance Benchmarks

 In 128K context scenarios, KTransformers achieves a **7.1x speedup** compared to `llama.cpp` while maintaining 100% accuracy on "needle in a haystack" tests [doc/en/long_context_introduction.md7](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/long_context_introduction.md?plain=1#L7-L7) In 1M context scenarios, it can reach ~16 tokens/s on a single 24GB GPU [doc/en/long_context_introduction.md7](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/long_context_introduction.md?plain=1#L7-L7)

 
| Context Length | DRAM Required | GPU VRAM Required | Speed (Tokens/s) |
|---|---|---|---|
| 32K | 4.29 GB | < 24 GB | - |
| 128K | 17.1 GB | < 24 GB | ~16 |
| 1M | 145.49 GB | < 24 GB | ~16 |
