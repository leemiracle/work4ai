 KTransformers is designed as a research framework for efficient inference and fine-tuning of large language models through heterogeneous computing. The system separates concerns into two independent but complementary modules, each with distinct build systems, dependencies, and deployment targets.

 **kt-kernel: High-Performance Inference Kernels**

 The `kt-kernel` module provides CPU-optimized kernel operations for heterogeneous LLM inference. It is implemented as a standalone Python package with C++ extensions, optimized for Intel AMX, AVX512, and AVX2 instruction sets.

 
| Component | Path | Purpose |
|---|---|---|
| Python API | kt-kernel/kt_kernel/ | Exposes KTMoEWrapper, CPUInfer interfaces |
| C++ Kernels | kt-kernel/csrc/ | AMX/AVX implementations, llamafile backend |
| Build System | kt-kernel/setup.py | Multi-variant compilation (AMX, AVX512, AVX2) kt-kernel/setup.py105-110 |

 Key classes:

 
 - `KTMoEWrapper`: Base wrapper for MoE operators [kt-kernel/README.md35-37](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L35-L37)
 - `CPUInfer`: Thread pool for CPU inference with NUMA awareness [kt-kernel/README.md45-48](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L45-L48)
 - `AMXMoEWrapper`: Specialized wrapper for Intel AMX-accelerated experts [kt-kernel/setup.py7-9](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/setup.py#L7-L9)

 **SGLang Integration Architecture**

 KTransformers integrates with SGLang via the `sglang-kt` package [kt-kernel/README_zh.md125-133](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README_zh.md?plain=1#L125-L133) This integration allows offloading "cold" experts to the CPU while keeping "hot" experts and MLA operators on the GPU.

 Configuration parameters for SGLang integration [kt-kernel/README_zh.md171-189](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README_zh.md?plain=1#L171-L189):

 
 - `--kt-method`: Backend type (`AMXINT4`, `AMXINT8`, or `LLAMAFILE`).
 - `--kt-weight-path`: Path to converted CPU weights.
 - `--kt-cpuinfer`: Number of CPU inference threads (recommended: physical core count).
 - `--kt-threadpool-count`: Number of thread pools (recommended: NUMA node count).
 - `--kt-num-gpu-experts`: Number of experts retained on the GPU.

### YAML Rule Structure

 Each injection rule in YAML files under `ktransformers/optimize/optimize_rules/` defines how to replace standard layers with optimized KTransformers operators.

 **MLA Optimization**: KTransformers replaces standard attention with optimized operators to capitalize on Multi-head Latent Attention (MLA). This involves absorbing decompression matrices into projection layers to reduce KV cache size and increase arithmetic intensity [README.md43-45](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/README.md?plain=1#L43-L45)

## Hardware Abstraction Layer

 KTransformers provides a hardware abstraction layer that enables operator implementations to target different devices and backends.

 
### CPU Backend Runtime Selection

 The `kt-kernel` module features automatic CPU detection that selects the optimal kernel variant at runtime [kt-kernel/README.md112-122](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L112-L122):

 
 - **AMX**: Best performance for Intel Sapphire Rapids+ (2023+) using AMX instructions.
 - **AVX512+BF16**: Excellent performance for Ice Lake server and Zen 4+.
 - **AVX512+VBMI**: Required for high-performance FP8 MoE.
 - **AVX512+VNNI**: Optimized for INT8 quantization.
 - **AVX2**: Universal fallback for Intel Haswell+ and AMD Zen+.
 
 
### Expert Placement Strategy

 KTransformers supports heterogeneous expert placement to optimize for hardware constraints [README.md78-80](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/README.md?plain=1#L78-L80):

 
 - **GPU**: Stores MLA operators and "hot" experts for low latency.
 - **CPU**: Stores the bulk of MoE experts in system DRAM.
 - **Disk**: Used in the 3-layer prefix cache system (GPU-CPU-Disk) for KV cache reuse [README.md37](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/README.md?plain=1#L37-L37)

## Integration with External Frameworks

 
### LLaMA-Factory Integration

 KTransformers integrates with LLaMA-Factory to enable fine-tuning of ultra-large MoE models (e.g., DeepSeek-V3/R1) on consumer hardware by offloading experts to CPU [README.md91-102](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/README.md?plain=1#L91-L102)

 
 - **Heterogeneous Training**: Supports CPU/GPU hybrid fine-tuning with INT8/INT4 quantization.
 - **Performance**: Achieves 6-12x training speedup compared to standard ZeRO-Offload in MoE workloads.
 
 
### SGLang Integration

 KTransformers is integrated into the SGLang project via the `sglang-kt` package [kt-kernel/README.md12-15](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L12-L15) This integration enables:

 
 - **Triton MLA Kernel**: High-efficiency attention for long context [doc/en/DeepseekR1_V3_tutorial.md97-98](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/DeepseekR1_V3_tutorial.md?plain=1#L97-L98)
