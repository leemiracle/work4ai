## Purpose and Scope

 This page documents the core architecture of the `kt-kernel` module, focusing on its multi-variant build system, runtime CPU detection, and the Python-C++ interface that orchestrates high-performance inference.

 `kt-kernel` is the high-performance engine of KTransformers, designed to provide optimal CPU performance across diverse x86-64 and ARM hardware by distributing multiple optimized kernel variants in a single package and automatically selecting the best variant at runtime.

 
---

 
## Multi-Variant Build System

 `kt-kernel` uses a **single wheel, multiple binaries** approach. It includes several progressively optimized CPU variants that are selected automatically at runtime based on the host's instruction set support.

 **Variant Build Process** The build system produces specialized binaries for different instruction sets. For example, the AMX variant includes specific support for INT4 and INT8 operations using Intel Advanced Matrix Extensions [kt-kernel/python/utils/amx.py18-23](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/amx.py#L18-L23)

 
| Variant | Instruction Set Requirements | Key Supported Kernels |
|---|---|---|
| amx | AMX_TILE, AMX_INT8, AMX_BF16 | AMXInt4_MOE, AMXInt8_MOE, AMXFP8_MOE |
| avx512 | AVX512F, AVX512_VNNI, etc. | AVXVNNI256GPTQInt4_MOE, AVXVNNI256RawInt4_MOE |
| avx2 | AVX2, FMA | AVX2BF16_MOE, AVX2FP8_MOE, AVX2RawInt4_MOE |

## Runtime CPU Detection and Loading

 At import time, `kt-kernel` automatically detects CPU features and loads the optimal kernel variant. This process is managed by `_cpu_detect.py` and exposed through the package initialization.

 
### Detection Flow

 
```

```

 **Implementation Details**

 
 - **Flag Detection**: The system reads `/proc/cpuinfo` to identify flags like `avx_vnni` or `amx_tile` [kt-kernel/python/utils/amx.py47-59](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/amx.py#L47-L59)
 - **Dynamic Injection**: The selected C++ extension is injected into `sys.modules` as `kt_kernel_ext` [kt-kernel/python/__init__.py41-47](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/__init__.py#L41-L47) This allows other Python modules to use `import kt_kernel_ext` regardless of which physical binary was loaded.
 - **Environment Overrides**: Users can manually select a variant using `KT_KERNEL_CPU_VARIANT` [kt-kernel/python/__init__.py31-32](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/__init__.py#L31-L32) Specific backends can also be forced, such as `KT_GPTQ_INT4_BACKEND` or `KT_RAWINT4_BACKEND` [kt-kernel/python/utils/amx.py75-104](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/amx.py#L75-L104)

## Python-C++ Interface

 The interface between Python and the C++ kernels is built using `pybind11`. It centers around the `CPUInfer` class and a task-based execution model.

### Key Components

 
 - **CPUInfer**: The main C++ orchestrator. It manages a `WorkerPool` for parallel execution and a `TaskQueue` for serializing requests from Python [kt-kernel/cpu_backend/cpuinfer.h34-39](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/cpu_backend/cpuinfer.h#L34-L39)
 - **TaskQueue**: A thread-safe queue that uses a `std::thread` worker to execute tasks asynchronously [kt-kernel/cpu_backend/task_queue.cpp19-23](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/cpu_backend/task_queue.cpp#L19-L23) It provides a `sync()` method to wait for task completion [kt-kernel/cpu_backend/task_queue.cpp53-59](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/cpu_backend/task_queue.cpp#L53-L59)
 - **WorkerPool**: Manages a pool of threads, often NUMA-aware, to perform the actual heavy lifting of matrix multiplications and MoE routing [kt-kernel/cpu_backend/cpuinfer.h44-46](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/cpu_backend/cpuinfer.h#L44-L46)
 - **MOEBindings**: A C++ template class that exposes MoE operations to Python. It includes methods for `warm_up`, `load_weights`, and inference execution [kt-kernel/ext_bindings.cpp172-205](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/ext_bindings.cpp#L172-L205)

## Backend Selection Strategy

 `KTMoEWrapper` acts as a factory that selects the specific implementation based on the requested `method` and `mode` [kt-kernel/python/experts.py68-74](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts.py#L68-L74)

 
### Support Matrix

 
| Mode | Method | Backend Class | Features |
|---|---|---|---|
| Inference | AMXINT4 | AMXMoEWrapper | AMX-optimized INT4 quantization kt-kernel/python/utils/amx.py139-143 |
| Inference | LLAMAFILE | LlamafileMoEWrapper | GGUF format support via llamafile kt-kernel/python/experts.py29 |
| Inference | BF16 | NativeMoEWrapper | Native BF16 precision kt-kernel/python/utils/amx.py28 |
| SFT | AMXBF16_SFT | AMXSFTMoEWrapper | Fine-tuning with LoRA adapters kt-kernel/python/experts.py139 |

 **Dynamic Expert Placement** The system supports heterogeneous placement where some experts reside on GPU and others on CPU. This is controlled via the `gpu_experts_mask` [kt-kernel/python/experts.py155-158](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts.py#L155-L158) Strategies like `uniform` or `frequency` determine this mask at runtime to optimize throughput [doc/en/kt-kernel/experts-sched-Tutorial.md96-105](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/kt-kernel/experts-sched-Tutorial.md?plain=1#L96-L105)
