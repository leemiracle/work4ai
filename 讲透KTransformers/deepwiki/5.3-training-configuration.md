## Purpose and Scope

 This document describes the YAML configuration system for fine-tuning models using `kt-sft` with LLaMA-Factory integration. It covers the dual-level configuration structure, the `use_kt` parameter, `kt_optimize_rule` syntax, and resource allocation strategies for heterogeneous CPU-GPU training.

 KTransformers enables fine-tuning ultra-large MoE models (like DeepSeek-V3 671B) on consumer hardware (e.g., 2–4 RTX 4090s) by offloading expert computation to the CPU while keeping Attention and LoRA parameters on the GPU [doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md20-28](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md?plain=1#L20-L28)

 
## Configuration Structure

 Training configuration in `kt-sft` uses a two-level YAML system:

 
 - **Main Training Configuration**: A LLaMA-Factory-compatible YAML file that specifies model paths, datasets, training hyperparameters, and KTransformers-specific activation flags [doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md122-132](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md?plain=1#L122-L132)
 - **Optimization Rule Configuration**: A KTransformers-specific YAML file (`kt_optimize_rule`) that defines operator placement (CPU/GPU) and backend selection (AMX/llamafile) [doc/en/SFT/injection_tutorial.md18-31](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/injection_tutorial.md?plain=1#L18-L31)

## Optimization Rule Configuration (`kt_optimize_rule`)

 This YAML defines how KTransformers identifies modules in the PyTorch graph and replaces them with optimized heterogeneous operators.

 
### Rule Syntax

 Rules use a `match` and `replace` pattern:

 
 - **match**: Uses `name` (regex) or `class` to identify target modules [doc/en/SFT/injection_tutorial.md21-23](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/injection_tutorial.md?plain=1#L21-L23)
 - **replace**: Specifies the `class` of the replacement operator and its `kwargs` [doc/en/SFT/injection_tutorial.md24-29](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/injection_tutorial.md?plain=1#L24-L29)
 - **recursive**: Whether to inject submodules (default `True`). Set to `False` for MoE experts to prevent deep injection into individual expert linear layers [doc/en/SFT/injection_tutorial.md30-40](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/injection_tutorial.md?plain=1#L30-L40)
 
 
### Operator Placement and Backends

 
| Component | Target Name Regex | Replacement Class | Device/Backend |
|---|---|---|---|
| Attention | ^model\.layers\..*\.self_attn$ | KDeepseekV2Attention | cuda:0 (MLA implementation) doc/en/SFT/injection_tutorial.md94-99 |
| MoE Experts | ^model\.layers\..*\.mlp\.experts$ | KTransformersExperts | cpu (using AMXBF16 or llamafile) doc/en/SFT/injection_tutorial.md109-114 |
| Linear | ^model\.layers\..*\.mlp\.(gate\|up\|down)_proj$ | KTransformersLinear | cuda:0 (Marlin or Torch backend) doc/en/SFT/injection_tutorial.md121-125 |

## Resource Allocation and Placement

 
### Multi-GPU Training

 To lower per-GPU memory peaks, `kt-sft` uses **model parallelism + explicit placement** instead of standard `DataParallel` [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md83-84](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L83-L84)

 
 - **KTrainer**: A custom trainer that overrides `.to(device)` to honor the YAML placement rules, constructing layers directly on the target GPU [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md87-88](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L87-L88)
 - **Gradient Aggregation**: Gradients from layers on different GPUs are aggregated for the optimizer update [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md83-85](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L83-L85)
 
 
### CPU Memory and Backends

 
 - **MoE Offloading**: Sparse MoE parts are executed on the CPU, while Attention compute and KV cache reside on the GPU [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md49-50](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L49-L50)
 - **Backward Pass**: $W^\top$ (weight transposes) are precomputed and cached at load time to reduce runtime overhead. Intermediate activations are also cached for reuse in backward passes [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md76-79](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L76-L79)
 - **Backends**: Supported backends for training include `AMX (INT8/BF16)` and `llamafile` [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md77-78](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L77-L78)

## Summary of Configuration Flow

 
 - **Set Environment**: Export `USE_KT=1` to activate the KTransformers trainer [doc/en/SFT/SFT_Installation_Guide_KimiK2.5.md151](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/SFT_Installation_Guide_KimiK2.5.md?plain=1#L151-L151)
 - **Define Training Params**: Set `use_kt: true` and specify `kt_optimize_rule` in the main YAML [doc/en/SFT/SFT_Installation_Guide_KimiK2.5.md122-132](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/SFT_Installation_Guide_KimiK2.5.md?plain=1#L122-L132)
 - **Define Injection Rules**: Map model submodules to `KTransformers` operators and assign devices (e.g., `cpu` for MoE, `cuda:x` for Attention) in the optimization rule YAML [doc/en/SFT/injection_tutorial.md89-114](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/injection_tutorial.md?plain=1#L89-L114)
 - **Execute**: Run `llamafactory-cli train <config>.yaml` [doc/en/SFT/SFT_Installation_Guide_KimiK2.5.md151](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/SFT_Installation_Guide_KimiK2.5.md?plain=1#L151-L151)
