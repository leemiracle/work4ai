## Purpose and Scope

 This page covers the management of LoRA (Low-Rank Adaptation) adapters after training with the `kt-sft` module. It documents the conversion, storage, and serving workflows for LoRA adapters trained using LLaMA-Factory with KTransformers backend. The system supports heterogeneous execution where base model experts are offloaded to CPU while LoRA parameters and attention remain on the GPU for efficient inference of ultra-large MoE models [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md24-28](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L24-L28)

## Post-Training Adapter Structure

 After training with LlamaFactory, the LoRA adapter is saved to the directory specified by `output_dir` [doc/en/SFT_Installation_Guide_KimiK2.5.md120-134](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT_Installation_Guide_KimiK2.5.md?plain=1#L120-L134) During training, `KTransformersLinearLora` replaces original `KTransformersLinear` layers (Q/K/V/O), preserving KT optimizations while enabling LoRA trainability [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md53-57](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L53-L57)

 
### Directory Structure

 
```
output_dir/
├── adapter_config.json          # LoRA configuration (rank, alpha, target_modules)
├── adapter_model.safetensors    # LoRA weights (matrices A and B)
├── trainer_state.json           # Training loss and metrics
└── training_args.bin            # Binary training arguments
```

## Converting Base Model Weights (Optional)

 To reduce CPU memory consumption during serving, base model weights can be quantized to INT8 or INT4 using `convert_cpu_weights.py` [doc/en/SFT_Installation_Guide_KimiK2.5.md186-194](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT_Installation_Guide_KimiK2.5.md?plain=1#L186-L194) This is particularly critical for ultra-large models like Kimi-K2.5 or DeepSeek-V3.2 where experts are offloaded to CPU [doc/en/Kimi-K2.5.md3](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/Kimi-K2.5.md?plain=1#L3-L3) [doc/en/kt-kernel/deepseek-v3.2-sglang-tutorial.md3](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/kt-kernel/deepseek-v3.2-sglang-tutorial.md?plain=1#L3-L3)
