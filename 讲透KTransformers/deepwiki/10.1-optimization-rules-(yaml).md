  This page documents the YAML-based configuration system for injecting optimized operators into models at runtime. YAML rules define how KTransformers replaces standard PyTorch modules (like `torch.nn.Linear` or attention layers) with specialized implementations optimized for heterogeneous CPU-GPU inference and fine-tuning.

 
## Overview of YAML Rule System

 The YAML rule system enables declarative model transformation without modifying source code. When loading a model, KTransformers traverses all submodules, matches them against YAML rules, and replaces matched modules with optimized implementations. This system is core to the "Arithmetic Intensity Guided Offloading" strategy, where compute-intensive operators (like MLA) are placed on the GPU, and memory-intensive but sparse operators (like MoE experts) are placed on the CPU [doc/en/deepseek-v2-injection.md52-60](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/deepseek-v2-injection.md?plain=1#L52-L60)

### Match Section

 The `match` section specifies which modules to target:

 
| Field | Type | Description |
|---|---|---|
| name | String (regex) | Regular expression matching module name in model hierarchy (e.g., from .safetensors keys) doc/en/SFT/injection_tutorial.md51 |
| class | String | Fully qualified class name or imported class reference (e.g., from modeling_deepseek.py) doc/en/SFT/injection_tutorial.md52 |

 Both `name` and `class` can be used simultaneously. When both are specified, a module must match **both** criteria to be injected [doc/en/SFT/injection_tutorial.md32](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/injection_tutorial.md?plain=1#L32-L32)

### Device Configuration Keywords

 Operators like `KTransformersExperts` and `KTransformersLinear` use `kwargs` to define execution strategy:

 
 - **`generate_device`**: The device used during the decoding/generation phase (e.g., `"cpu"`, `"cuda:0"`) [doc/en/SFT/injection_tutorial.md36](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/injection_tutorial.md?plain=1#L36-L36)
 - **`generate_op`**: Specifies the backend implementation to use (e.g., `"KExpertsCPU"` for llamafile-based CPU inference) [doc/en/multi-gpu-tutorial.md52](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/multi-gpu-tutorial.md?plain=1#L52-L52)
 - **`out_device`**: The device where output tensors are placed, critical for multi-GPU layer chaining [doc/en/multi-gpu-tutorial.md53](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/multi-gpu-tutorial.md?plain=1#L53-L53)
 
 
## Recursive Injection Control

 The `recursive` field (default `True`) determines whether KTransformers should continue matching rules against submodules of the current replaced module [doc/en/SFT/injection_tutorial.md37](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/injection_tutorial.md?plain=1#L37-L37)

 **When to use `recursive: False`:**

 
 - **MoE Experts**: In DeepSeek models, experts are implemented as an `nn.ModuleList`. Setting `recursive: False` on the `.mlp.experts` match prevents KTransformers from traversing and individually injecting every single expert (e.g., all 160 experts), allowing the wrapper class (`KTransformersExperts`) to manage them as a single parallel block [doc/en/SFT/injection_tutorial.md105-111](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/injection_tutorial.md?plain=1#L105-L111)
 - **Self-Attention**: If replacing a full attention block, setting this to `False` prevents internal linear layers (Q/K/V/O) from being accidentally matched by general linear replacement rules [doc/en/SFT/injection_tutorial.md39](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/injection_tutorial.md?plain=1#L39-L39)

 During fine-tuning, the framework replaces original `KTransformersLinear` layers (Q/K/V/O) with `KTransformersLinearLora`, which inherits from both `KTransformersLinear` and `LoraLayer`. This allows the model to use KTransformers' high-performance prefill/generate paths while accepting LoRA parameters (`lora_A`/`lora_B`) [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md53-56](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L53-L56)

 The fine-tuning framework also uses YAML to select between different differentiable backends, such as `AMXBF16` or `llamafile`, for the MoE experts during backward passes. The backend can be switched via the `backend` keyword in the YAML [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md71](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L71-L71)
