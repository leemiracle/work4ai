## Purpose and Scope

 The llamafile backend provides a universal CPU inference backend for `kt-kernel` that supports any CPU with AVX2 or better instruction sets. It serves as the fallback and maximum-compatibility option when AMX or advanced AVX512 capabilities are unavailable. This backend uses GGUF-format weights directly without requiring weight conversion, making it the easiest path for deployment across diverse CPU architectures.

 For AMX-optimized inference, see [AMX Kernel Implementation (7.2)](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/AMX Kernel Implementation (7.2)) For general MoE operator system overview, see [MoE Operator System (4.2)](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/MoE Operator System (4.2)) For CPU-specific optimizations, see [AVX/AVX512 Support (7.3)](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/AVX/AVX512 Support (7.3))

## Overview

 The llamafile backend is built on top of the llamafile project's highly optimized BLAS kernels, adapted for KTransformers' MoE inference needs. It provides:

 
 - **Universal CPU Support**: Works on any x86-64 CPU with AVX2 (Intel Haswell 2013+, AMD Zen+) or ARM CPUs with NEON. [third_party/llamafile/sgemm.cpp93-156](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/third_party/llamafile/sgemm.cpp#L93-L156)
 - **GGUF Native Loading**: Loads pre-quantized GGUF weights directly from disk via memory mapping using a singleton `GGUFLoader`. [kt-kernel/python/utils/llamafile.py76-79](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/llamafile.py#L76-L79) [kt-kernel/python/utils/llamafile.py158-195](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/llamafile.py#L158-L195)
 - **Multiple Quantization Formats**: Supports Q4_K, Q8_0, and various i-quant (IQ) types through specialized dequantizers. [third_party/llamafile/iqk_mul_mat.inc72-74](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/third_party/llamafile/iqk_mul_mat.inc#L72-L74) [third_party/llamafile/iqk_mul_mat.inc181-356](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/third_party/llamafile/iqk_mul_mat.inc#L181-L356)
 - **Architecture-Specific Variants**: Automatically selects optimal kernel variants (AVX2, AVX512F, Zen4, ARM82) at runtime. [third_party/llamafile/sgemm.cpp32-162](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/third_party/llamafile/sgemm.cpp#L32-L162)
 
 The backend is selected using `--kt-method LLAMAFILE` in SGLang integration or `method="LLAMAFILE"` in the Python API. [kt-kernel/python/utils/llamafile.py43](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/llamafile.py#L43-L43)

## MoE-Specific Operations

 
### iqk_mul_mat_moe Implementation

 For MoE layers, `iqk_mul_mat_moe` provides specialized matrix-matrix multiplication that reuses unpacked quants and scales across several columns to speed up prompt processing. [third_party/llamafile/iqk_mul_mat.inc50-65](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/third_party/llamafile/iqk_mul_mat.inc#L50-L65)

 **Optimization Strategy:**

 
 - **Reusing Unpacked Quants**: Unpacking `QX` quants and scales is expensive; the implementation reuses them for multiple `Q8_K` columns. [third_party/llamafile/iqk_mul_mat.inc60-65](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/third_party/llamafile/iqk_mul_mat.inc#L60-L65)
 - **Tiling**: Uses a `k_x_step` (typically 64) within `MulMat::mul_mat_NxM` to achieve fewer memory loads. [third_party/llamafile/iqk_mul_mat.inc126-155](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/third_party/llamafile/iqk_mul_mat.inc#L126-L155)
 
 
### Dequantization Lookup Tables

 For I-quants, the backend utilizes large pre-computed grid tables to accelerate the mapping from quantized bits to float values. [third_party/llamafile/iqk_mul_mat.inc181-356](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/third_party/llamafile/iqk_mul_mat.inc#L181-L356)

## Performance Characteristics

 Based on the implementation notes in `iqk_mul_mat.inc`, this backend provides significant speedups over baseline `llama.cpp` for prompt processing (prefill):

 
| Quantization Type | Speedup vs Mainline llama.cpp |
|---|---|
| Legacy & K-Quants | 150-200% |
| I-Quants (IQ) | 250-400% |
