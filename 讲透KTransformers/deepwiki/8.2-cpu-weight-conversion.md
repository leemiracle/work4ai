## Purpose and Scope

 This page documents the CPU weight conversion system in KTransformers, which transforms model weights from various formats (AWQ, FP8, FP16, BF16) into optimized formats for CPU inference. The conversion process handles quantization, memory layout transformation, and NUMA-aware weight distribution across CPU sockets using `convert_cpu_weights.py`.

 The primary goal is to prepare "cold" experts (less frequently accessed MoE experts) for AMX-optimized execution on the CPU while keeping "hot" experts on the GPU.

## AWQ to Column-Major Conversion

 The `AWQToColumnMajorConverter` transforms AWQ-quantized weights from row-major interleaved format to column-major format suitable for CPU inference kernels.

 
### AWQ Interleaving and Packing

 AWQ weights use a specific interleaving pattern within each 32-bit packed integer. The converter must reverse this before re-packing for the CPU backend.

 
```

```

 **Interleaving Pattern:** The `REVERSE_AWQ_PACK_ORDER` constant `[0, 4, 1, 5, 2, 6, 3, 7]` [kt-kernel/scripts/convert_cpu_weights.py29](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_cpu_weights.py#L29-L29) is used to map the AWQ-specific bit layout back to a linear sequence before any further processing.

## Online Quantization Path

 The `OnlineQuantConverter` performs runtime quantization from higher-precision formats (FP8/FP16/BF16) to INT4/INT8 using CPU kernels.

 
### FP8 Dequantization

 For FP8 input (e.g., DeepSeek-V3), weights are dequantized using a Triton kernel `weight_dequant_kernel` [kt-kernel/scripts/convert_cpu_weights.py34-45](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_cpu_weights.py#L34-L45) which applies block-wise scaling.

 **Block Size Configuration:** FP8 quantization uses block-wise scaling (e.g., 128x128). These are extracted from the `quantization_config` in `config.json` via `load_model_config` [kt-kernel/scripts/convert_cpu_weights.py94-119](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_cpu_weights.py#L94-L119)

 
### KTMoEWrapper Integration

 The online quantization path leverages `KTMoEWrapper` [kt-kernel/scripts/convert_cpu_weights.py867-887](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_cpu_weights.py#L867-L887) to perform quantization with the same AMX-optimized kernels used during inference.

 
| Method | Backend Kernel | Precision | Use Case |
|---|---|---|---|
| int4 | AMXINT4 | 4-bit integers | Maximum compression, Sapphire Rapids+ |
| int8 | AMXINT8 | 8-bit integers | Better accuracy, 4th Gen Xeon+ |
| moe_int4 | MOE_INT4 | 4-bit integers | Alternative INT4 kernel |
| moe_int8 | MOE_INT8 | 8-bit integers | Alternative INT8 kernel |

## Weight File Organization

 
### NUMA-Aware Weight Distribution

 Weights are distributed across NUMA nodes to optimize memory bandwidth. Each expert's weights are split according to the `threadpool_count` (typically 2 for dual-socket systems).

 
```

```

 
### File Naming Convention

 The C++ backend `MOE_KERNEL_TP` expects weights in specific `.kt` files if not using SafeTensors. ## Memory Management during Conversion

 Converting large models (e.g., DeepSeek 671B) requires strict memory management.

 
 - **Low Memory Mode:** The `--no-merge-safetensor` flag [kt-kernel/scripts/README.md80-89](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/README.md?plain=1#L80-L89) prevents the script from attempting to merge all experts into a single massive SafeTensor file, keeping them as individual `.kt` files instead.
 - **Resume Layer:** The `--resume-layer` argument [kt-kernel/scripts/README.md112-124](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/README.md?plain=1#L112-L124) allows restarting the process from a specific layer if the system crashes or runs out of memory.
 - **Periodic Cleanup:** The converter performs `gc.collect()` and `torch.cuda.empty_cache()` every 5 layers [kt-kernel/scripts/convert_cpu_weights.py411-415](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_cpu_weights.py#L411-L415)
