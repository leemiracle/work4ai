  This page describes how `kt-kernel` integrates with SGLang for production inference serving. The integration enables CPU-GPU heterogeneous MoE inference: the GPU executes attention and "hot" experts, while the CPU executes "cold" experts using optimized AMX/AVX kernels.

 
## Overview

 SGLang is an inference serving framework that `kt-kernel` extends with heterogeneous MoE capabilities. The integration operates through SGLang's `--kt-*` command-line parameters that instantiate `KTMoEWrapper` instances for MoE layers. This allows deployment of extremely large models, such as DeepSeek-V3 (671B), Kimi-K2.5, or Qwen3-Next-80B, on hardware with limited VRAM by offloading experts to system RAM.

 **Key Integration Points:**

 
 - **Entry**: `sglang.launch_server` CLI with `--kt-method`, `--kt-weight-path`, and `--kt-cpuinfer` parameters [kt-kernel/README.md180-189](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L180-L189)
 - **Wrapper**: `KTMoEWrapper` class [kt-kernel/python/__init__.py53](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/__init__.py#L53-L53) instantiated per MoE layer to coordinate hybrid execution.
 - **Backends**: AMX (INT4/INT8), LLAMAFILE (GGUF), RAWINT4 (native INT4), and FP8/BF16 native backends [kt-kernel/README.md41-45](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L41-L45)
 - **Execution**: `CPUInfer` C++ class [kt-kernel/README.md132-133](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L132-L133) manages worker pools and NUMA-aware expert computation.

## Weight Preparation

 Serving with SGLang and `kt-kernel` typically requires specific weight formats for the CPU side, depending on the chosen backend.

 
### CPU Weights: AMX Backend (`AMXINT4`/`AMXINT8`)

 Requires converting Hugging Face weights (BF16/FP16/FP8) into AMX-optimized layouts using `convert_cpu_weights.py` [kt-kernel/README_zh.md146-151](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README_zh.md?plain=1#L146-L151)

### CPU Weights: Native Backends (`RAWINT4`, `FP8`, `BF16`)

 These backends often use the same weights for both CPU and GPU. For example, Kimi-K2.5 uses `RAWINT4` weights for both [doc/en/Kimi-K2.5.md61-63](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/Kimi-K2.5.md?plain=1#L61-L63)

 
### CPU Weights: LLAMAFILE Backend (`LLAMAFILE`)

 Uses standard **GGUF** format weights. No conversion script is needed if GGUF files are downloaded directly from repositories like Hugging Face or ModelScope [kt-kernel/README_zh.md160-165](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README_zh.md?plain=1#L160-L165)

## Server Configuration

 Launch the SGLang server using the `sglang.launch_server` module with `--kt-*` flags.

 
### Core KT-Kernel Parameters

 
| Parameter | Type | Description |
|---|---|---|
| --kt-method | String | Backend type: AMXINT4, AMXINT8, RAWINT4, FP8, BF16, LLAMAFILE kt-kernel/README_zh.md172 |
| --kt-weight-path | Path | Directory containing CPU-optimized weights or GGUF file kt-kernel/README_zh.md173 |
| --kt-cpuinfer | Int | Number of physical CPU cores to use for inference kt-kernel/README_zh.md174 |
| --kt-threadpool-count | Int | Number of thread pools (typically set to NUMA node count) kt-kernel/README_zh.md175 |
| --kt-num-gpu-experts | Int | Number of experts to keep on the GPU kt-kernel/README_zh.md176 |

## Tuning Guidelines

 
### Backend Selection

 
 - **`AMXINT8`/`AMXINT4`**: Best for Intel Sapphire Rapids+ using quantized weights [kt-kernel/README.md116](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L116-L116)
 - **`RAWINT4`**: Optimized for Kimi-K2 models using native INT4 weights [doc/en/Kimi-K2.5.md84](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/Kimi-K2.5.md?plain=1#L84-L84)
 - **`AVX512 Native Precision`**: Supported for `FP8`, `BF16` and `RAWINT4` formats on AVX512 CPUs [kt-kernel/README.md30](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L30-L30)
 - **`LLAMAFILE`**: Universal fallback for any CPU supporting AVX2 [kt-kernel/README.md121](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README.md?plain=1#L121-L121)
 
 
### Threading and NUMA

 
 - **`--kt-cpuinfer`**: Recommended to be set to the number of **physical cores** [kt-kernel/README_zh.md174](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README_zh.md?plain=1#L174-L174)
 - **`--kt-threadpool-count`**: Should match the number of **NUMA nodes** (sockets) on the system [kt-kernel/README_zh.md175](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/README_zh.md?plain=1#L175-L175)
 
 
### Expert Scheduling

 
 - **`frequency` Strategy**: Places the most frequently activated experts on GPU. Requires activation statistics (`--init-expert-location`) [doc/en/kt-kernel/experts-sched-Tutorial.md103](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/kt-kernel/experts-sched-Tutorial.md?plain=1#L103-L103)
 - **Dynamic Update**: Use `--kt-enable-dynamic-expert-update` to allow the system to redistribute experts during inference based on real-time activation patterns [doc/en/kt-kernel/experts-sched-Tutorial.md125](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/kt-kernel/experts-sched-Tutorial.md?plain=1#L125-L125)
