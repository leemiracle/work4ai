## Purpose and Scope

 This page documents the direct Python API for `kt-kernel`, covering programmatic usage of `KTMoEWrapper`, `CPUInfer`, and related classes for custom CPU-GPU heterogeneous MoE inference and fine-tuning (SFT) integration. This API allows developers to integrate KTransformers optimized kernels into custom inference pipelines or training loops.

 For SGLang-based production serving, see [SGLang Integration](https://deepwiki.com/kvcache-ai/ktransformers/4.3-sglang-integration). For fine-tuning with LLaMA-Factory, see [LLaMA-Factory Integration](https://deepwiki.com/kvcache-ai/ktransformers/5.2-llama-factory-integration).

 
---

 
## API Architecture Overview

 The Python API serves as a high-level factory and management layer around the C++ extension (`kt_kernel_ext`). It provides a unified interface (`KTMoEWrapper`) that abstracts different backend implementations (AMX, Llamafile, Native, SFT) and manages the lifecycle of CPU inference worker pools.

## Weight Loading Workflow

 
### Loading from Disk (SafeTensor/GGUF)

 Backends use specific loaders to read weights. `AMXMoEWrapper` and `GeneralMoEWrapper` use `SafeTensorLoader` [kt-kernel/python/utils/loader.py102](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L102-L102) while `LlamafileMoEWrapper` uses `GGUFLoader` [kt-kernel/python/utils/loader.py240](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L240-L240)

 **Loader Features:**

 
 - **NUMA Sharding**: `SafeTensorLoader` supports loading tensors with `.numa.{id}` suffixes to distribute weights across memory nodes [kt-kernel/python/utils/loader.py180-181](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L180-L181)
 - **Name Translation**: `GGUFLoader` translates PyTorch tensor names to GGUF format using `translate_name_to_gguf` [kt-kernel/python/utils/loader.py53-99](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L53-L99)

## Buffer Management

 
### KExpertsCPUBuffer

 This class manages pinned memory buffers to optimize data transfer between GPU and CPU [kt-kernel/python/experts_base.py75-80](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L75-L80)

 **Buffer Structure:** It maintains a circular buffer of depth 2 (defined by `buffer_depth`) to support pipelining [kt-kernel/python/experts_base.py86](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L86-L86)

 
| Buffer Component | Data Type | Purpose |
|---|---|---|
| input_tensor_cpu | bfloat16 | Hidden states copied from GPU kt-kernel/python/experts_base.py100-101 |
| immediate_experts_ids_cpu | int64 | Expert IDs for immediate CPU computation kt-kernel/python/experts_base.py104-105 |
| deferred_experts_ids_cpu | int64 | Expert IDs for deferred computation kt-kernel/python/experts_base.py108-109 |

## Advanced Features

 
### GPU Expert Placement

 The `generate_gpu_experts_masks()` utility generates boolean masks for expert placement based on activation frequency [kt-kernel/python/experts_base.py21-24](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L21-L24)

 **Mechanism:**

 
 - It takes an `activation_freq` table of shape `(num_layers, num_experts)` [kt-kernel/python/experts_base.py32](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L32-L32)
 - It identifies the global top-K most active experts [kt-kernel/python/experts_base.py63](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L63-L63)
 - It returns a mask where `True` indicates the expert should be placed on GPU for optimal performance [kt-kernel/python/experts_base.py66-72](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L66-L72)
 
 **Sources:** [kt-kernel/python/experts_base.py21-72](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L21-L72)

 
### Instruction Set Selection

 The `kt-kernel` package includes logic to automatically select the best CPU instruction set for a given quantization method [kt-kernel/python/utils/amx.py74](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/amx.py#L74-L74)

 **Selection Logic for GPTQ_INT4:**

 
 - Prefers `AVXVNNI256GPTQInt4_MOE` if `avx_vnni` is supported and group size is a multiple of 32 [kt-kernel/python/utils/amx.py96-97](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/amx.py#L96-L97)
 - Falls back to `AVX2GPTQInt4_MOE` [kt-kernel/python/utils/amx.py98-99](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/amx.py#L98-L99)
 - Supports environment variable overrides via `KT_GPTQ_INT4_BACKEND` [kt-kernel/python/utils/amx.py75](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/amx.py#L75-L75)
