## Purpose and Scope

 This document explains the `balance_serve` backend engine, the multi-concurrency inference system introduced in KTransformers v0.2.4. The `balance_serve` backend enables handling multiple concurrent inference requests through continuous batching, chunked prefill, and asynchronous C++ scheduling. It is specifically designed to optimize throughput for large models like DeepSeek-V3/R1 and LLaMA 4 by leveraging CPU-GPU heterogeneous resources.

## Key Features

 
### Continuous Batching

 The scheduler organizes queued requests into batches in a First-Come-First-Served (FCFS) manner. This allows the engine to process new requests (prefill) while simultaneously generating tokens for existing requests (decode).

 **Batching Constraints:**

 
 - **`--max_batch_size`**: Maximum number of requests (prefill + decode) processed in a single run. [doc/en/balance-serve.md131](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L131-L131)
 - **`--cache_lens`**: Total length of KV cache allocated by the scheduler. All requests share this space. [doc/en/balance-serve.md130](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L130-L130)
 - **Space Management**: KV cache space is released immediately after a request completes. [doc/en/balance-serve.md133](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L133-L133)
 
 Sources: [doc/en/balance-serve.md7-8](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L7-L8) [doc/en/balance-serve.md130-134](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L130-L134)

 
### Chunked Prefill

 To prevent long prefill operations from blocking the generation (decode) of other requests, `balance_serve` uses chunked prefill.

 
| Parameter | Description | Recommended Value |
|---|---|---|
| --chunk_size | Maximum number of tokens processed in a single engine run. | 256 doc/en/balance-serve.md121 |

 This mechanism ensures that the engine's execution time per step remains bounded, improving overall system responsiveness.

### Variable Batch Size CUDA Graph

 The backend utilizes `custom_flashinfer`, a specialized implementation based on the [FlashInfer](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/FlashInfer) library.

 
 - **Variable Batch Size**: Supports dynamic batch compositions without requiring fixed-size padding. [doc/en/balance-serve.md17](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L17-L17)
 - **Memory Efficiency**: Reduces memory overhead and padding waste. [doc/en/balance-serve.md17](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L17-L17)
 - **Performance**: Contributes to the ~130% throughput improvement observed in 4-way concurrency benchmarks. [doc/en/balance-serve.md18](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L18-L18)

## Configuration and Deployment

 
### Command-Line Arguments

 To use the multi-concurrency backend, the `--backend_type` must be set to `balance_serve`.

 
| Argument | Description | Usage Example |
|---|---|---|
| --backend_type | Specifies the engine. balance_serve for multi-concurrency. | balance_serve |
| --max_batch_size | Max requests in one run. | 4 |
| --cache_lens | Total KV cache capacity (tokens). | 32768 |
| --chunk_size | Max tokens per engine step. | 256 |
| --model_path | Local directory containing model config. | /path/to/config |
| --force_think | Forces reasoning tags for DeepSeek-R1. | Flag |

## Performance Benchmarks

 The `balance_serve` backend significantly improves throughput by utilizing hardware more efficiently during concurrent requests.

 
| Platform | Configuration | Throughput (1 req) | Throughput (Multi) | Improvement |
|---|---|---|---|---|
| Standard | 4-way concurrency | - | - | ~130% doc/en/balance-serve.md18 |
| Xeon6 + MRDIMM-8800 | Multi-concurrent | 17 tokens/s | 40 tokens/s | ~2.35x doc/en/balance-serve.md19 |

 **Bottleneck Analysis:** On high-performance CPU platforms (like Xeon6), the bottleneck has shifted from CPU expert computation to the GPU (e.g., 4090D), suggesting that more powerful GPUs could further unlock performance. [doc/en/balance-serve.md19](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/balance-serve.md?plain=1#L19-L19)
