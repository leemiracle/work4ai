  This document provides guidelines for contributing to KTransformers, including development setup, coding standards, pull request workflow, and review processes. KTransformers is an open-source framework focused on efficient CPU-GPU heterogeneous inference and fine-tuning for large language models.

 
## Purpose and Scope

 Contributions are welcome from the community in the following areas:

 
 - **Core Framework**: Improvements to `kt-kernel` (inference) and `kt-sft` (fine-tuning) modules.
 - **Hardware Acceleration**: New CPU/GPU kernels (AMX, AVX512, llamafile integration) and optimizations.
 - **Model Support**: Adding support for new LLM architectures via YAML rules or custom operators.
 - **Documentation**: Tutorials, guides, and API documentation.
 - **Bug Fixes**: Addressing issues and improving stability.
 
 
## Development Environment Setup

 
### Prerequisites

 
 - **Python**: 3.8 or higher.
 - **C++ Compiler**: GCC 9+ or Clang 10+ with C++17 support.
 - **Build Tools**: CMake 3.18+, Make.
 - **CUDA Toolkit**: 11.8+ or 12.1+ (for GPU support).
 - **Git**: With submodule support.

### Git Hooks and Formatting

 KTransformers uses automated hooks to ensure code quality. The script `kt-kernel/scripts/install-git-hooks.sh` sets up symlinks from `kt-kernel/.githooks` to the local `.git/hooks` directory [kt-kernel/scripts/install-git-hooks.sh1-58](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/install-git-hooks.sh#L1-L58)

## Contributing Workflow

 
### Fork and Branch Strategy

 
 - **Fork the repository** on GitHub.
 - **Clone your fork** locally and add the upstream remote: `git remote add upstream https://github.com/kvcache-ai/ktransformers.git`.
 - **Create a feature branch**: `git checkout -b feature/my-new-feature`.
 - **Make changes and commit**: Use descriptive commit messages.
 - **Rebase on upstream**: `git fetch upstream && git rebase upstream/main`.
 - **Push and Open PR**: Push to your fork and open a Pull Request against the `main` branch.
 
 
### PR Requirements

 Before submitting a PR, ensure you have completed the checklist in the PR template [.github/PULL_REQUEST_TEMPLATE.md1-8](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/.github/PULL_REQUEST_TEMPLATE.md?plain=1#L1-L8):

 
 - Read the contributor guidelines.
 - Wrote new necessary tests.
 - Linked the PR to a relevant issue (e.g., `Fixes # (issue)` [.github/PULL_REQUEST_TEMPLATE.md3](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/.github/PULL_REQUEST_TEMPLATE.md?plain=1#L3-L3)).
 
 
### Testing and Validation

 For kernel-level changes, contributors should use reproduction scripts to validate stability. For example, `kt-kernel/examples/repro_llamafile_re.py` is used to catch intermittent `RuntimeError` issues in the `LLAMAFILE` backend by running high-iteration stress tests [kt-kernel/examples/repro_llamafile_re.py1-31](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/examples/repro_llamafile_re.py#L1-L31)

 Key validation steps in the repro script:

 
 - Initialize `KTMoEWrapper` with specific hardware parameters (threads, threadpools, etc.) [kt-kernel/examples/repro_llamafile_re.py96-109](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/examples/repro_llamafile_re.py#L96-L109)
 - Run a warmup iteration [kt-kernel/examples/repro_llamafile_re.py128-132](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/examples/repro_llamafile_re.py#L128-L132)
 - Execute a main loop with `submit_forward` and `sync_forward` to test async stream integration [kt-kernel/examples/repro_llamafile_re.py135-160](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/examples/repro_llamafile_re.py#L135-L160)
 
 
## Coding Standards

 
### Python Standards

 
 - Follow PEP 8.
 - Use type hints for all public function signatures.
 - Document classes and methods using Google-style docstrings.
 - **Naming**: `PascalCase` for classes, `snake_case` for functions/variables.
 
 
### C++ Standards

 
 - Use 2 spaces for indentation (enforced by `clang-format`).
 - Use `snake_case` for functions, `PascalCase` for classes.
 - Use `SharedMemBuffer` and `MemoryRequest` for NUMA-aware memory allocation [kt-kernel/cpu_backend/shared_mem_buffer.cpp49-85](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/cpu_backend/shared_mem_buffer.cpp#L49-L85)
 - Ensure all new C++ functionality is bound via `pybind11` in `ext_bindings.cpp`.
 
 
## Issue Reporting

 When reporting bugs or requesting features, use the provided GitHub templates:

 
 - **Bug Reports**: Include system info (output of `lscpu`, `nvidia-smi`), reproduction steps, and stack traces [.github/ISSUE_TEMPLATE/-bug-.yaml23-43](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/.github/ISSUE_TEMPLATE/-bug-.yaml#L23-L43)
 - **Feature Requests**: Provide a clear description of the proposed feature and mention if a PR is already in progress [.github/ISSUE_TEMPLATE/-feature-.yaml23-41](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/.github/ISSUE_TEMPLATE/-feature-.yaml#L23-L41)
 
 
## Code of Conduct

 All contributors are expected to uphold the **Contributor Covenant Code of Conduct**, which pledges a harassment-free experience for everyone [.github/CODE_OF_CONDUCT.md2-8](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/.github/CODE_OF_CONDUCT.md?plain=1#L2-L8) Unacceptable behavior includes trolling, personal attacks, or sexualized language [.github/CODE_OF_CONDUCT.md20-27](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/.github/CODE_OF_CONDUCT.md?plain=1#L20-L27) Violations can result in warnings or bans [.github/CODE_OF_CONDUCT.md48-70](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/.github/CODE_OF_CONDUCT.md?plain=1#L48-L70)
