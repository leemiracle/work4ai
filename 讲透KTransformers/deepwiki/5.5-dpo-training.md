  Direct Preference Optimization (DPO) is a stable and efficient method for aligning large language models with human preferences. Within the KTransformers framework, DPO training is integrated via **LLaMA-Factory**, leveraging the **kt-sft** module to enable fine-tuning of ultra-large Mixture-of-Experts (MoE) models (e.g., DeepSeek-V3 671B) on consumer-grade hardware like 2–4 RTX 4090 GPUs [doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md20-24](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md?plain=1#L20-L24)

 
## Overview and Architecture

 The DPO workflow uses LLaMA-Factory as the orchestration layer for data processing, training scheduling, and LoRA injection, while KTransformers serves as a pluggable high-performance backend [doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md24-26](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md?plain=1#L24-L26)

 
### Data and Logic Flow

 In DPO training, the system processes preference pairs (chosen vs. rejected responses). The **kt-sft** backend optimizes this by offloading heavyweight MoE experts to the CPU while keeping the Attention mechanism and active LoRA adapters on the GPU [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md49-51](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L49-L51)

## Training Configuration

 DPO training is configured via a YAML file. Key parameters include the training stage, preference loss type, and KTransformers-specific optimization rules.

 
### Key YAML Parameters

 
| Parameter | Description | Example Value |
|---|---|---|
| stage | Training stage for DPO | dpo |
| finetuning_type | Use LoRA for parameter efficiency | lora |
| pref_loss | Preference loss function | sigmoid, orpo, or simpo |
| use_kt | Enable KTransformers backend | true |
| kt_optimize_rule | Path to the injection rule YAML | DeepSeek-V2-Lite-Chat-sft-amx.yaml |

### Operator Injection for DPO

 KTransformers uses a specialized class, `KTransformersLinearLora`, which inherits from both `KTransformersLinear` and `LoraLayer` [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md53-56](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L53-L56) This allows the model to use high-performance KT kernels while maintaining the ability to train LoRA weights during the DPO process.

### MoE Optimization

 For MoE layers, `KSFTExpertsCPU` (referenced as `KExpertsCPU` in injection rules) encapsulates expert computation as a differentiable black-box operator [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md68-71](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L68-L71) This is critical for DPO as it requires calculating gradients through the sparse MoE structure on the CPU. The backend uses precomputed weight transposes ($W^\top$) to accelerate the backward pass and caches intermediate activations to reduce recomputation [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md76-79](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L76-L79)

 
## Inference with DPO Adapters

 After training, the resulting LoRA adapters can be loaded for inference using the same `kt_optimize_rule` used during training. The `infer_backend` should be set to `ktransformers` in the inference YAML to leverage the optimized CPU/GPU heterogeneous serving [doc/en/SFT/DPO_tutorial.md135-147](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/DPO_tutorial.md?plain=1#L135-L147)
