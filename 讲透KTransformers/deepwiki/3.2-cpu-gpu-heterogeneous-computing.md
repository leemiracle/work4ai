## Purpose and Scope

 This document describes the heterogeneous computing architecture that enables KTransformers to run ultra-large Mixture-of-Experts (MoE) models on consumer-grade hardware by intelligently distributing computation between CPU and GPU resources. The system leverages CPU-optimized kernels for cold experts and GPU acceleration for attention and hot experts.

## Heterogeneous Inference Strategy

 
### Why Heterogeneous Computing?

 Traditional approaches to running large MoE models face a fundamental constraint: GPU memory capacity. For example, DeepSeek-V3 with 671B parameters requires 8×80GB GPUs for standard inference using the official implementation. This makes such models inaccessible to most researchers and developers.

 KTransformers addresses this by recognizing a key architectural insight: not all model components have the same computational characteristics or access patterns.

 **Computational Characteristics:**

 
| Component | Compute Intensity | Memory Access Pattern | Optimal Device |
|---|---|---|---|
| Multi-head Latent Attention (MLA) | Very High | Sequential (KV cache) | GPU |
| Hot Experts (frequently activated) | High | Random access | GPU |
| Cold Experts (rarely activated) | Medium | Sparse access | CPU |
| Shared Experts | High | Sequential | GPU |

 The Multi-head Latent Attention operations are highly computationally intensive and benefit greatly from GPU parallelism. However, in MoE architectures, experts exhibit a skewed activation pattern where a small subset accounts for the majority of activations.

## Expert Placement Strategy

 
### Hot vs Cold Experts

 The expert placement problem determines which experts reside in GPU memory versus CPU memory. This decision critically impacts both performance and memory usage.

 **Expert Activation Distribution:**

 In typical MoE inference, expert activations follow a power-law distribution. For DeepSeek-V3, only a small fraction of experts are activated per token (e.g., 6 or 8 out of 256).

### GPU Expert Selection

 The `num_gpu_experts` parameter controls how many experts are kept in GPU memory. The selection is often based on activation frequency.

 **Configuration Parameters:**

 
| Parameter | Description | Example Value | Code Reference |
|---|---|---|---|
| num_gpu_experts | Total experts in GPU memory | 32 (for 24GB GPU) | kt-kernel/python/experts_base.py23 |
| gpu_experts_mask | Boolean mask for GPU placement | torch.Tensor | kt-kernel/python/experts_base.py159 |
| activation_freq | Frequency table for selection | torch.Tensor | kt-kernel/python/experts_base.py22 |

 **Selection Logic:** The function `generate_gpu_experts_masks` selects the top `num_gpu_experts` experts with the highest activation frequency across all layers to be placed on the GPU [kt-kernel/python/experts_base.py21-72](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L21-L72)

 - Offloading high arithmetic intensity Multi-head Latent Attention (MLA) to GPU [doc/en/DeepseekR1_V3_tutorial.md65](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/DeepseekR1_V3_tutorial.md?plain=1#L65-L65)
