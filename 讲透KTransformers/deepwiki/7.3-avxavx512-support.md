## Purpose and Scope

 This page documents AVX and AVX512 instruction set support in KTransformers' CPU inference kernels. It covers:

 
 - Implementation of AVX2 and AVX512 variants for multiple precisions (BF16, FP8, GPTQ_INT4, RAWINT4).
 - How AVX512/AVX2 kernels complement AMX kernels as fallback and low-latency alternatives.
 - Runtime kernel selection and support for AVX-VNNI extensions.
 - Specialized implementations for Kimi-style RAWINT4 weights on non-AMX hardware.
 
 For AMX-specific implementation details, see [AMX Kernel Implementation](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/AMX Kernel Implementation)

 
## Architecture Overview

 KTransformers implements a multi-tier CPU acceleration strategy. AVX512 and AVX2 kernels serve three critical roles:

 
 - **Fallback kernels**: Providing high-performance execution on hardware lacking AMX (e.g., Intel Haswell/Skylake, AMD Zen series) [doc/en/kt-kernel/AVX2-Tutorial.md3-32](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/kt-kernel/AVX2-Tutorial.md?plain=1#L3-L32)
 - **Low-latency kernels**: Handling small batch sizes (decode phase) where AMX tile configuration overhead may be suboptimal.
 - **Broad Format Support**: Supporting diverse quantization schemes including GPTQ, FP8, and RAWINT4 (Kimi-native) [doc/en/kt-kernel/AVX2-Tutorial.md20-27](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/kt-kernel/AVX2-Tutorial.md?plain=1#L20-L27)

## AVX2 Implementation Details

 On hardware lacking AMX/AVX512, KTransformers provides specialized AVX2 operators. These use 256-bit registers (`__m256`) and specific utility functions for quantization.

 
### BF16 MoE (AVX2)

 The BF16 implementation performs on-the-fly conversion since AVX2 lacks native BF16 arithmetic.

 
 - **Conversion**: BF16 values are loaded into 32-bit registers by shifting left 16 bits [kt-kernel/operators/avx2/avx2_bf16_utils.hpp26-30](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/operators/avx2/avx2_bf16_utils.hpp#L26-L30)
 - **GEMM**: `gemm_bf16` implements the core loop using `_mm256_fmadd_ps` for FP32 accumulation [kt-kernel/operators/avx2/avx2_bf16_gemm.hpp165-195](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/operators/avx2/avx2_bf16_gemm.hpp#L165-L195)
 - **Layout**: Uses row-major storage for weights, avoiding the 16x16 tile transposition required for AMX [kt-kernel/operators/avx2/bf16-moe.hpp8-12](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/operators/avx2/bf16-moe.hpp#L8-L12)
 
 
### FP8 MoE (AVX2)

 Uses a Lookup Table (LUT) approach for E4M3 dequantization.

 
 - **LUT**: A 256-entry table initialized at startup maps FP8 to FP32 [kt-kernel/operators/avx2/fp8_dequant.hpp26-52](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/operators/avx2/fp8_dequant.hpp#L26-L52)
 - **Vectorized Lookup**: Employs `_mm256_i32gather_ps` to perform 8 parallel lookups from the LUT using zero-extended indices [kt-kernel/operators/avx2/fp8_dequant.hpp70-77](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/operators/avx2/fp8_dequant.hpp#L70-L77)
 
 
### RAWINT4 (Kimi Native) Support

 KTransformers provides two specialized backends for the Kimi RAWINT4 layout (signed int4 packed 2 per byte, BF16 scales):

 
 - **AVX2 Standard**: Uses bit-shifts to unpack nibbles and performs dequantization to FP32 before multiplication [kt-kernel/operators/avx2/rawint4-moe.hpp23-29](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/operators/avx2/rawint4-moe.hpp#L23-L29)
 - **AVX-VNNI-256**: For CPUs supporting AVX-VNNI (e.g., Intel 12th Gen+), it quantizes activations to int8 on-the-fly and uses `dpbusd` for group-wise inner products [kt-kernel/operators/avx2/rawint4_avxvnni-moe.hpp11-16](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/operators/avx2/rawint4_avxvnni-moe.hpp#L11-L16)

### Key Buffer Structures

 
 - **BufferA**: Input activations. In `avxvnni_rawint4`, this buffer also handles the on-the-fly quantization of BF16 inputs to int8 [kt-kernel/operators/avx2/rawint4_avxvnni-moe.hpp55-75](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/operators/avx2/rawint4_avxvnni-moe.hpp#L55-L75)
 - **BufferB**: Weights. For `RAWINT4`, this stores packed uint8 nibbles. The `from_raw_mat` function handles the unpacking and sign-correction (value = nibble - 8) [kt-kernel/operators/avx2/rawint4-moe.hpp23-29](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/operators/avx2/rawint4-moe.hpp#L23-L29)
 - **BufferC**: Output buffer. Usually FP32, converted back to BF16 via `store_fp32_to_bf16` [kt-kernel/operators/avx2/avx2_bf16_utils.hpp35-48](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/operators/avx2/avx2_bf16_utils.hpp#L35-L48)
