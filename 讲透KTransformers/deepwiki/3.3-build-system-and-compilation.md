  This document describes the build system for `kt-kernel`, covering CMake configuration, multi-variant compilation, CPU feature detection, and runtime variant selection.

 
## Purpose and Scope

 The `kt-kernel` build system is designed to provide high-performance kernels across a wide variety of x86-64 hardware. It supports:

 
 - **Single-variant builds**: Optimized for a specific CPU using `-march=native` (ideal for local development). [kt-kernel/setup.py:104-109]
 - **Multi-variant builds**: Compiles six progressive CPU variants (AMX, AVX512 variants, AVX2) into a single wheel to ensure the best performance on any target machine. [kt-kernel/setup.py:300-372], [kt-kernel/README.md:110-122]
 - **Automatic CPU detection**: Both at build time (via CMake) and runtime (via Python). [kt-kernel/cmake/DetectCPU.cmake:4-65], [kt-kernel/python/_cpu_detect.py:26-163]
 - **GPU backend support**: Integration for CUDA (with static runtime support), ROCm, MUSA, and Intel XPU. [kt-kernel/CMakeLists.txt:16-19]
 - **Environment-based configuration**: Extensive control over compilation via `CPUINFER_*` variables. [kt-kernel/setup.py:14-40]

## Build Modes

 
### Single-Variant Build (Default)

 Builds one optimized `.so` file for the host CPU. By default, it uses `NATIVE` mode which maps to `-DLLAMA_NATIVE=ON` (enabling `-march=native`). [kt-kernel/setup.py:109], [kt-kernel/CMakeLists.txt:5]

 
### Multi-Variant Build (Distribution)

 Triggered by `CPUINFER_BUILD_ALL_VARIANTS=1`. It compiles six distinct variants to ensure compatibility across different CPU generations. [kt-kernel/setup.py:300-372]

 
| Variant | Instruction Requirements | Performance |
|---|---|---|
| amx | AMX (Tile/Int8/BF16) + AVX512 | ⚡⚡⚡ Best |
| avx512_bf16 | AVX512 + BF16 | ⚡⚡⚡ Excellent |
| avx512_vbmi | AVX512 + VBMI | ⚡⚡ Great |
| avx512_vnni | AVX512 + VNNI | ⚡⚡ Great |
| avx512_base | AVX512 Foundation + BW | ⚡⚡ Good |
| avx2 | AVX2 (Fallback) | ⚡ Good |

 **Sources:** [kt-kernel/setup.py:300-372], [kt-kernel/README.md:110-122]

 
## CPU Feature Detection

 
### Build-Time Detection (CMake)

 The `detect_cpu_features` function in `DetectCPU.cmake` parses `/proc/cpuinfo` to set CMake cache variables. This is skipped if flags are already provided via environment variables (e.g., from `install.sh` or `setup.py`). [kt-kernel/cmake/DetectCPU.cmake:12-26], [kt-kernel/cmake/DetectCPU.cmake:75-87]

 
### Runtime Detection (Python)

 When `kt_kernel` is imported, it uses a progressive variant hierarchy to load the best binary available in the package.

## Environment Variables

 
### Compilation Knobs

 
 - `CPUINFER_CPU_INSTRUCT`: Target instruction set (NATIVE, FANCY, AVX512, AVX2). [kt-kernel/setup.py:18]
 - `CPUINFER_BUILD_TYPE`: Build optimization level (Debug, Release, etc.). [kt-kernel/setup.py:113]
 - `CPUINFER_PARALLEL`: Number of parallel build jobs. [kt-kernel/setup.py:116-124]
 - `USE_CONDA_TOOLCHAIN`: If `ON`, prioritizes compilers and libraries in the active conda environment. [kt-kernel/CMakeLists.txt:4-49]
 
 
### Feature Toggles

 
 - `CPUINFER_ENABLE_AMX`: Maps to `-DKTRANSFORMERS_CPU_USE_AMX`. [kt-kernel/setup.py:19]
 - `CPUINFER_ENABLE_AVX512_VBMI`: Required for FP8 MoE kernels. [kt-kernel/setup.py:26]
 - `CPUINFER_USE_CUDA`: Enables NVIDIA GPU acceleration. [kt-kernel/setup.py:38]
 - `CPUINFER_CUDA_STATIC_RUNTIME`: Statically links the CUDA runtime for portable wheels. [.github/workflows/release-pypi.yml:113]
 
 **Sources:** [kt-kernel/setup.py:14-33], [kt-kernel/CMakeLists.txt:4-28]
