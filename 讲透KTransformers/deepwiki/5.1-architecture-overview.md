## Purpose and Scope

 The **kt-sft** module is the fine-tuning component of the KTransformers framework. It is designed to enable efficient LoRA (Low-Rank Adaptation) fine-tuning of ultra-large Mixture-of-Experts (MoE) models—such as DeepSeek-V3 (671B) and Qwen3-MoE—on resource-constrained hardware (e.g., 2–4 RTX 4090 GPUs) [doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md20-22](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md?plain=1#L20-L22)

 By integrating with the **LLaMA-Factory** orchestration layer, kt-sft provides a pluggable high-performance backend that takes over core operators (Attention and MoE) to enable **GPU+CPU heterogeneous training** [doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md24-26](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md?plain=1#L24-L26)

 Key architectural features include:

 
 - **Heterogeneous Training**: Offloading heavyweight MoE experts to CPU while keeping Attention and KV cache on GPU [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md49-50](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L49-L50)
 - **LoRA Coexistence**: A dual-inheritance architecture that allows KTransformers' optimized kernels to work seamlessly with PEFT LoRA adapters [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md53-56](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L53-L56)
 - **Differentiable MoE Operators**: Encapsulating expert computation into custom Autograd functions with C++ backends (AMX, llamafile) [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md67-72](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L67-L72)

## Attention Layer: Dual Inheritance Architecture

 To support fine-tuning, KTransformers must handle both the optimized base weights (often quantized or offloaded) and the trainable LoRA parameters. This is achieved via the `KTransformersLinearLora` class [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md53-54](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L53-L54)

## MoE Operator Design

 MoE layers are the primary memory bottleneck. kt-sft encapsulates expert computation as a differentiable "black-box" operator [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md68-70](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L68-L70)

### Key MoE Optimizations

 
 - **Weight Transpose Caching**: To avoid expensive runtime transposes during the backward pass (where $W^\top$ is required), $W^\top$ is precomputed at load time [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md77-78](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L77-L78)
 - **Activation Caching**: Intermediate expert projections are cached during the forward pass to be reused in backward calculations, reducing recomputation [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md78-79](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L78-L79)
 - **Pluggable Backends**: Users can switch between `AMXBF16`, `AMXINT8`, or `llamafile` via YAML configuration [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md71-72](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L71-L72)
 - **Buffer Management**: The `KExpertsSFTBuffer` provides a grow-only shared CPU buffer for forward and backward passes, minimizing reallocation overhead [kt-kernel/python/sft/base.py21-27](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/sft/base.py#L21-L27)

## Multi-GPU Placement Strategy

 kt-sft eschews standard DataParallel (which replicates the entire model) in favor of **Model Parallelism + Explicit Placement** [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md81-83](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L81-L83)

 
### KTrainer and Device Mapping

 The `KTrainer` class takes over the `.to(device)` calls to prevent moving the entire model to a single GPU [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md87-88](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L87-L88)

 
| Component | Device Placement | Strategy |
|---|---|---|
| Attention / KV Cache | GPU (cuda:0, cuda:1, etc.) | Layer-wise distribution across GPUs |
| MoE Experts | CPU | Offloaded to system RAM, shared across GPUs |
| Gradients | cuda:0 | Aggregated on a primary device for optimization |

## Data Flow: Forward and Backward

 
 - **Forward Pass**: 
 - LLaMA-Factory prepares input batches [doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md24-25](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md?plain=1#L24-L25)
 - Attention layers execute on GPU using `KTransformersLinearLora` (Base + LoRA) [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md60-62](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L60-L62)
 - MoE layers route tokens to CPU, where `kt-kernel` executes expert FFNs using shared buffers [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md70-71](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L70-L71) [kt-kernel/python/sft/base.py51-60](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/sft/base.py#L51-L60)
 - **Backward Pass**: 
 - Gradients are computed for LoRA parameters on GPU [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md55-56](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L55-L56)
 - Custom C++ backward kernels compute gradients for MoE layers on CPU using cached activations and transposed weights [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md77-79](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L77-L79) [kt-kernel/python/sft/base.py61-65](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/sft/base.py#L61-L65)
 - All gradients are synchronized and the optimizer updates parameters [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md103-104](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md?plain=1#L103-L104)
