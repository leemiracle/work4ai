# Prefix Cache System

  Relevant source files 
 - [doc/en/prefix_cache.md](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/prefix_cache.md?plain=1)
 
  **Purpose and Scope**: This page documents KTransformers' 3-layer prefix cache system, which stores and reuses KV (Key-Value) cache across GPU, CPU, and disk storage tiers. This system enables efficient serving with prefix reuse, particularly for long-context models and high-concurrency environments.

 
## Overview

 The prefix cache system in KTransformers implements a hierarchical storage strategy for KV cache data. By distributing cache across three tiers, the system overcomes GPU VRAM limitations while maintaining high performance through intelligent migration.

 **Key Benefits:**

 
 - **Prefix Reuse**: Common prompt prefixes (e.g., system prompts, few-shot examples) are cached and reused across requests, saving prefill computation [doc/en/prefix_cache.md1-3](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/prefix_cache.md?plain=1#L1-L3)
 - **Tiered Storage**: Hot cache entries stay in GPU memory, while cold entries move to CPU RAM or persistent disk storage [doc/en/prefix_cache.md13-18](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/prefix_cache.md?plain=1#L13-L18)
 - **Scalability**: Supports massive context lengths by utilizing system RAM and NVMe storage [doc/en/prefix_cache.md16-18](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/prefix_cache.md?plain=1#L16-L18)
 
 The system is integrated into the `balance_serve` multi-concurrency backend and utilizes **PhotonLibOS** for high-performance disk I/O [doc/en/prefix_cache.md3-35](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/prefix_cache.md?plain=1#L3-L35)

## 3-Layer Cache Architecture

 
### Storage Tier Hierarchy

 The system automatically manages the lifecycle of KV cache pages across the following hierarchy:

 
| Tier | Storage Medium | Configuration Parameter | Characteristics |
|---|---|---|---|
| Tier 1 | GPU VRAM | utilization_percentage | Fastest access; used for active inference and hot prefixes. |
| Tier 2 | CPU DRAM | cpu_memory_size_GB | Large capacity; stores warm prefixes evicted from GPU. |
| Tier 3 | Disk (NVMe/SSD) | disk_path | Persistent; stores cold prefixes. Powered by PhotonLibOS. |

## Configuration

 The prefix cache is configured via `./ktransformers/configs/config.yaml`. To enable the 3-layer mode, `gpu_only` must be set to `false`.

 
### Parameters

 
| Section | Parameter | Default | Description |
|---|---|---|---|
| attn | page_size | 16 | Size of a page in KV Cache (tokens). doc/en/prefix_cache.md11 |
| attn | chunk_size | 256 | Processing chunk size for prefill operations. doc/en/prefix_cache.md12 |
| kvc2 | gpu_only | false | Set to false to enable Disk + CPU + GPU storage. doc/en/prefix_cache.md14 |
| kvc2 | utilization_percentage | 1.0 | Target GPU memory utilization before eviction. doc/en/prefix_cache.md15 |
| kvc2 | cpu_memory_size_GB | 500 | Amount of CPU memory (GB) allocated for KV Cache. doc/en/prefix_cache.md16 |
| kvc2 | disk_path | - | Path to store KV Cache on disk. doc/en/prefix_cache.md17 |

## PhotonLibOS Integration

 KTransformers integrates **PhotonLibOS** as a submodule to handle the persistent storage layer. This allows for high-throughput asynchronous disk operations, ensuring that spilling KV cache to disk does not block the main inference thread.

## Maintenance and Limitations

 
### Cache Management

 Currently, the system does not support an internal API for deleting specific KV cache entries. If the `disk_path` accumulates too much data, users must manually delete the `.kvc` files from the filesystem [doc/en/prefix_cache.md37-39](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/prefix_cache.md?plain=1#L37-L39)

 
### Hardware Recommendations

 
 - **Disk Tier**: NVMe SSDs are highly recommended for the `disk_path` to ensure the latency of loading prefixes from disk remains acceptable.
 - **CPU Tier**: Sufficient system RAM should be allocated via `cpu_memory_size_GB` to act as a buffer between GPU and Disk.
