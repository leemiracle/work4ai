## Purpose and Scope

 This document describes the automated Continuous Integration and Continuous Deployment (CI/CD) pipeline for KTransformers. The pipeline handles building, testing, and distributing both Python wheels (`kt-kernel` and `sglang-kt` packages) and Docker images across multiple CPU architectures and configurations.

 The system is designed to produce "fat wheels" that include multiple optimized CPU variants (AMX, AVX512, AVX2) and statically linked CUDA runtimes to ensure maximum compatibility across different Linux environments without requiring local compilation by the end user.

### CPU Variant Selection Logic

 The wheel includes 6 optimized variants that are **automatically selected at runtime** based on the host CPU capabilities detected by `kt_kernel`.

 
| Variant | Target CPUs | Performance | Selection Trigger |
|---|---|---|---|
| AMX | Intel Sapphire Rapids+ (2023+) | ⚡⚡⚡ Best | AMX instructions detected |
| AVX512+BF16 | Ice Lake server, Zen 4+ (2021+) | ⚡⚡⚡ Excellent | AVX512 + BF16 detected |
| AVX512+VBMI | Ice Lake client (2019+) | ⚡⚡ Great | AVX512 + VBMI detected |
| AVX512+VNNI | Cascade Lake+ (2019+) | ⚡⚡ Great | AVX512 + VNNI detected |
| AVX512 Base | Skylake-X+ (2017+) | ⚡⚡ Good | AVX512 base detected |
| AVX2 | Haswell+ (2013+), AMD Zen+ | ⚡ Good | Fallback for maximum compatibility |

## Docker Image Build Workflow

 The `docker-image.yml` workflow builds and publishes Docker images to DockerHub. It supports custom CUDA versions and mirror settings.

 
### Docker Build Configuration

 
| Parameter | Default Value | Description |
|---|---|---|
| cuda_version | 12.8.1 | Target CUDA version for the image [.github/workflows/docker-image.yml16] |
| ubuntu_mirror | 0 | Toggle for using Tsinghua Ubuntu mirror (0/1) [.github/workflows/docker-image.yml26] |
| DOCKERHUB_REPO | kvcache-ai/ktransformers | Target repository [.github/workflows/docker-image.yml33] |

 
### Build and Push Strategy

 The workflow executes a build script `push-to-dockerhub.sh` located in the `docker` directory [[.github/workflows/docker-image.yml136](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/[.github/workflows/docker-image.yml#L136-L136)].

 
 - **Testing**: Before building for push, it runs a test build using `docker/Dockerfile` [[.github/workflows/docker-image.yml45](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/[.github/workflows/docker-image.yml#L45-L45)].
 - **Multi-Variant Support**: The images are built to support the same multi-variant CPU features as the wheels.
 - **Simplified Tagging**: Optionally pushes a simplified tag like `v0.2.0-cu121` alongside the full timestamped tag [[.github/workflows/docker-image.yml116-118](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/[.github/workflows/docker-image.yml#L116-L118)].

## Verification and Quality Gates

 
### CI Verification Steps

 The project uses a set of automated checks in `release-pypi.yml` to ensure package integrity:

 
 - **Static Linking Check**: Verifies that the wheel does not depend on `libcudart.so` by using `ldd` on the extracted `.so` files [[.github/workflows/release-pypi.yml151-159](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/[.github/workflows/release-pypi.yml#L151-L159)].
 - **Variant Existence**: Checks the wheel contents using `python -m zipfile -l` for the presence of AMX, AVX512, and AVX2 `.so` variants [[.github/workflows/release-pypi.yml144-149](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/[.github/workflows/release-pypi.yml#L144-L149)].
 - **CUDA Functionality**: Installs the wheel and verifies that `submit_with_cuda_stream` is present in the `kt_kernel_ext.CPUInfer` class [[.github/workflows/release-pypi.yml135-142](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/[.github/workflows/release-pypi.yml#L135-L142)].
 - **Manylinux Repair**: Uses `auditwheel` to ensure compatibility with `manylinux_2_17_x86_64` and excludes `libcuda.so.1` from being bundled [[.github/workflows/release-pypi.yml161-170](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/[.github/workflows/release-pypi.yml#L161-L170)].
