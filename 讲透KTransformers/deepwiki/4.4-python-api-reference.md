  This page documents the Python API for kt-kernel's MoE CPU inference and fine-tuning (SFT) operations. The API is centered around the `KTMoEWrapper` factory class, which provides a unified interface for creating backend-specific MoE operators (AMX, LLAMAFILE, Native, etc.). This reference covers initialization parameters, weight loading methods, forward inference interfaces, and buffer management utilities.

 For integration with SGLang for production serving, see [SGLang Integration](https://deepwiki.com/kvcache-ai/ktransformers/4.3-sglang-integration). For details on the underlying C++ kernel implementations, see [MoE Operator System](https://deepwiki.com/kvcache-ai/ktransformers/4.2-moe-operator-system).

## KTMoEWrapper Factory Class

 The `KTMoEWrapper` class serves as the main entry point for kt-kernel's Python API. ### Backend Selection Logic

 The factory automatically routes to the appropriate backend based on the `method` parameter [kt-kernel/python/experts.py186-210](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts.py#L186-L210):

 
| Method Value | Backend Class | Use Case |
|---|---|---|
| AMXINT4, AMXINT8 | AMXMoEWrapper | Intel AMX-optimized INT4/INT8 quantization kt-kernel/python/utils/amx.py139 |
| RAWINT4, FP8, BF16, GPTQ_INT4 | NativeMoEWrapper | Native weight formats or standard quantization kt-kernel/python/utils/amx.py246 |
| LLAMAFILE | LlamafileMoEWrapper | GGUF-based universal CPU backend via llamafile kt-kernel/python/utils/llamafile.py21 |
| MOE_INT4, MOE_INT8 | GeneralMoEWrapper | General purpose quantized kernels kt-kernel/python/utils/moe_kernel.py29 |

## Initialization Parameters

 The `KTMoEWrapper` constructor accepts the following parameters to configure the MoE operator [kt-kernel/python/experts.py149-174](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts.py#L149-L174):

 
### Core Parameters

 
| Parameter | Type | Description |
|---|---|---|
| layer_idx | int | Layer index in the model. |
| num_experts | int | Total number of experts in this MoE layer. |
| num_experts_per_tok | int | Number of experts per token (top-k routing). |
| hidden_size | int | Hidden dimension size (model width). |
| moe_intermediate_size | int | Intermediate dimension in expert FFN. |

 
### Resource Allocation Parameters

 
| Parameter | Type | Description |
|---|---|---|
| gpu_experts_mask | Optional[torch.Tensor] | Boolean mask indicating which experts are on GPU. If None, all are on CPU kt-kernel/python/experts.py155-158 |
| cpuinfer_threads | int | Number of CPU inference threads. |
| threadpool_count | int | Number of NUMA subpools (typically matching NUMA node count). |
| numa_nodes | Optional[List[int]] | Explicit list of NUMA node IDs for subpool mapping kt-kernel/python/experts.py166 |
| chunked_prefill_size | int | Maximum prefill chunk size for batch processing. |

 
### Weight and Backend Parameters

 
| Parameter | Type | Description |
|---|---|---|
| weight_path | str | Path to CPU weights (directory for SafeTensors or path for GGUF). |
| method | str | Backend method: "AMXINT4", "BF16", "LLAMAFILE", etc. |
| mode | str | Operation mode: "inference" or "sft" kt-kernel/python/experts.py168 |
| cpu_save | bool | Whether to save weights to CPU memory (used for online quantization) kt-kernel/python/experts.py164 |
| max_deferred_experts_per_token | Optional[int] | Number of experts per token to defer for pipelined execution kt-kernel/python/experts.py165 |

## Forward Inference Methods

 The API supports synchronous and asynchronous execution.

 
### Synchronous Forward

 `wrapper.forward(...)` performs a full forward pass, blocking until completion [kt-kernel/python/experts_base.py270](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L270-L270)

 
### Asynchronous Forward (Pipelined)

 
 - **`submit_forward(...)`**: Submits the expert computation to the CPU thread pool and returns immediately [kt-kernel/python/experts_base.py241](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L241-L241)
 - **`sync_forward(...)`**: Waits for the submitted computation to complete and returns the result [kt-kernel/python/experts_base.py255](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L255-L255)

## Buffer Management

 The `KExpertsCPUBuffer` class manages pinned memory buffers to optimize GPU-to-CPU transfers and avoid allocation overhead [kt-kernel/python/experts_base.py75-80](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L75-L80)

 
### Key Methods

 
 - **`get_buffer(hidden_states, num_experts_per_tok)`**: Retrieves or allocates pinned memory buffers for a specific batch size [kt-kernel/python/experts_base.py89-142](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L89-L142)
 - **`buffer_depth`**: Number of buffers kept for pipelining (default is 2) [kt-kernel/python/experts_base.py86](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L86-L86)
