## Static Expert Placement Strategies

 Static strategies determine which experts reside on GPU at server startup. Configuration uses `--kt-expert-placement-strategy` parameter.

 
### Strategy Comparison

 
| Strategy | Description | Use Case | Requires Statistics |
|---|---|---|---|
| uniform | Evenly distributes GPU experts across all MoE layers | Default, no prior knowledge needed | No |
| frequency | Places most frequently activated experts on GPU | Best performance when statistics available | Yes (--init-expert-location) |
| front-loading | Fills GPU experts starting from layer 0 | Early-layer bottleneck scenarios | No |
| random | Random selection with fixed seed (42) | Baseline comparison, testing | No |

### Configuration Guidelines

 The `_MoEBase._get_cpu_infer` method manages the singleton `CPUInfer` instance, configuring it based on provided threads and NUMA nodes [kt-kernel/python/experts_base.py159-198](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L159-L198)

 **Physical Cores vs Hyperthreads:**

 
 - ✅ **Correct**: `cpuinfer_threads` = physical core count.
 - ❌ **Incorrect**: `cpuinfer_threads` = hyperthread count (often degrades performance).
 
 **NUMA Node Configuration:** NUMA-aware execution is handled by designing thread pools for multi-socket machines. The `threadpool_count` should typically match the number of NUMA nodes [kt-kernel/python/experts_base.py180-195](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/experts_base.py#L180-L195)

## Backend-Specific Considerations

 
### AMX Backend (AMXINT4/AMXINT8)

 
 - **Target**: Intel Sapphire Rapids+ (2023+).
 - **Optimization**: Uses AMX tile registers and quantized weights.
 - **Support**: `GeneralMoEWrapper` supports `MOE_INT4` and `MOE_INT8` methods [kt-kernel/python/utils/moe_kernel.py32-33](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/moe_kernel.py#L32-L33)
 
 
### Native Backends (RAWINT4/BF16/FP8)

 
 - **Target**: AVX512-capable CPUs (Skylake-X+, Zen 4+).
 - **Feature**: Automatically detects CPU variant (`amx`, `avx512`, `avx2`) at runtime [kt-kernel/python/__init__.py8-9](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/__init__.py#L8-L9)
 
 
### LLAMAFILE Backend

 
 - **Target**: Universal (AVX2+).
 - **Weight Format**: Directly uses GGUF weights. `LlamafileMoEWrapper` requires `moe_intermediate_size` to be divisible by `QK_K` (256) for alignment [kt-kernel/python/utils/llamafile.py82-89](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/llamafile.py#L82-L89)
 - **NUMA Support**: Implements tensor parallel (TP) splits across NUMA nodes by distributing blocks to different subpools [kt-kernel/python/utils/llamafile.py92-121](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/llamafile.py#L92-L121)
