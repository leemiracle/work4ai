  This page documents the deployment and optimization of the Kimi-K2 model family (including Kimi-K2-0905 and Kimi-K2-Thinking) using the KTransformers framework. These models are large-scale Mixture-of-Experts (MoE) architectures that leverage KTransformers' CPU-GPU heterogeneous inference capabilities to offload experts to system memory while maintaining high performance via Intel AMX and AVX-512 optimizations.

 
## 1. Deployment Overview

 KTransformers supports Kimi-K2 through two primary serving backends: `balance_serve` (integrated into the KTransformers server) and the `sglang-kt` fork for high-concurrency production environments.

 
### 1.1 Model Variants and Resource Requirements

 
| Model Variant | Quantization | Backend | VRAM | DRAM | Performance (approx.) |
|---|---|---|---|---|---|
| Kimi-K2 | Q4_K_M (GGUF) | balance_serve | 14 GB | 600 GB | 10-14 TPS |
| Kimi-K2-0905 | Q4_K_M (GGUF) | balance_serve | 14 GB | 600 GB | - |
| Kimi-K2-Thinking | AMX INT4 | sglang-kt | 48 GB+ | 650 GB | 46 total tok/s (decode) |
| Kimi-K2-Thinking | RAWINT4 | sglang-kt | 48 GB+ | 650 GB | 33-53 TPS (Prefill) |

## 3. Serving Kimi-K2-Thinking with SGLang

 For the "Thinking" variant, KTransformers integrates with `sglang-kt` (the kvcache-ai fork of SGLang) to provide advanced features like chunked prefill and mixed-batching.

 
### 3.1 Quantized vs. Native Deployment

 
 - **Quantized Deployment:** Uses AMX INT4 weights specifically quantized for CPU. 
 - **CPU Weights:** `KVCache-ai/Kimi-K2-Thinking-CPU-weight`
 - **Method:** `--kt-method AMXINT4`
 - **Native Deployment:** Uses the same RAWINT4 weights for both CPU and GPU. 
 - **Weights:** `moonshotai/Kimi-K2-Thinking`
 - **Method:** `--kt-method RAWINT4`

### 3.3 Prefill Strategy: Layerwise vs. Hybrid

 The parameter `--kt-gpu-prefill-token-threshold` determines the prefill behavior:

 
 - **$\leq$ Threshold (Hybrid):** Uses both CPU and GPU. No extra VRAM required, but performance degrades slowly as token count increases.
 - **> Threshold (Layerwise):** Uses GPU only by processing layers sequentially. Requires significant extra VRAM (~9GB for K2-Thinking) but scales near-exponentially.

### 4.1 Key Implementation Parameters

 
 - **`--kt-cpuinfer`**: Number of CPU inference threads. Recommended to be set to (number of physical CPU cores - number of GPUs).
 - **`--kt-threadpool-count`**: Number of thread pools, typically set to match the NUMA node count.
 - **`--kt-num-gpu-experts`**: Number of experts retained on GPUs to accelerate decoding.
 - **`--kt-max-deferred-experts-per-token`**: Used in native mode to control how many experts are deferred for processing.

## 5. Performance and Optimization

 
### 5.1 NUMA and Threading

 For dual-socket systems, enabling NUMA optimizations increases performance from roughly 10 TPS to 14 TPS for Kimi-K2.

 
### 5.2 Throughput Benchmarks (Kimi-K2-Thinking)

 Based on testing with 8x NVIDIA L20 and Intel Xeon Gold 6454S (Quantized AMXINT4):

 
| Phase | Metric | Value |
|---|---|---|
| Prefill | Input Token Throughput | 577.74 tok/s |
| Decode | Output Token Throughput | 45.91 tok/s |
| Decode | Median ITL | 797.89 ms |

|---|---|---|---|
| 1x RTX 4090 | 53 | 184 | 290 (qlen=30k) |
