  This document provides a complete reference of weight formats supported by `kt-kernel` for MoE expert inference. It covers input formats, quantized CPU-optimized formats, and native precision formats, along with their conversion processes and auto-detection mechanisms.

 
## Overview

 The KTransformers framework supports multiple weight formats to accommodate different hardware backends and performance/accuracy trade-offs. Each format is loaded by a specialized loader class that handles format detection, tensor loading, and scale handling.

 **Format Categories:**

 
 - **Input Formats**: Original model weights in standard formats (SafeTensors, GGUF).
 - **CPU-Optimized Formats**: Quantized formats requiring offline conversion (AMXINT4, AMXINT8) [kt-kernel/python/utils/amx.py92-116](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/amx.py#L92-L116)
 - **Native Formats**: Shared CPU-GPU formats with no conversion (RAWINT4, FP8, BF16) [kt-kernel/python/utils/loader.py240-675](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L240-L675)
 
 **Loader Classes:**

 
 - `SafeTensorLoader`: Base loader for AMX quantized weights [kt-kernel/python/utils/loader.py102-170](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L102-L170)
 - `CompressedSafeTensorLoader`: Loader for RAWINT4 compressed layout [kt-kernel/python/utils/loader.py623-675](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L623-L675)
 - `FP8SafeTensorLoader`: Loader for FP8 weights with auto-detection for DeepSeek/Mixtral/Mistral [kt-kernel/python/utils/loader.py240-456](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L240-L456)
 - `BF16SafeTensorLoader`: Loader for native BF16 weights, including packed Qwen3.5 formats [kt-kernel/python/utils/loader.py459-620](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L459-L620)
 - `GGUFLoader`: Loader for GGUF quantized weights via `gguf_reader` [kt-kernel/python/utils/loader.py678-963](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L678-L963)

## Detailed Format Specifications

 
### GGUF (Universal CPU Backend)

 GGUF is a universal quantized format loaded by the `GGUFLoader` class. It supports direct loading of pre-quantized weights without further conversion [kt-kernel/python/utils/loader.py678-707](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L678-L707)

 **Loader Implementation:**

 
 - Uses `gguf.gguf_reader.GGUFReader` for metadata and tensor access [kt-kernel/python/utils/loader.py16](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L16-L16)
 - Translates PyTorch tensor names to GGUF format via `translate_name_to_gguf()` [kt-kernel/python/utils/loader.py53-99](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L53-L99)
 - Supports sharded GGUF files (e.g., `model-00001-of-00002.gguf`) [kt-kernel/python/utils/loader.py690-705](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L690-L705)
 
 **Quantization Types:** The backend supports various GGML types, including `Q4_K`, `Q5_K`, `Q8_0`, and `IQ4_XS` [kt-kernel/python/utils/loader.py19-51](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L19-L51)

### Native Formats (Shared CPU-GPU)

 Native formats enable zero-copy weight sharing between CPU and GPU. These are loaded directly from SafeTensors with automatic detection of model families (DeepSeek, Mixtral, Qwen).

 
#### RAWINT4 (Native INT4)

 
 - **Loader**: `CompressedSafeTensorLoader` [kt-kernel/python/utils/loader.py623](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L623-L623)
 - **Characteristics**: Loads weights with `weight_packed` and `weight_scale` suffixes [kt-kernel/python/utils/loader.py657-658](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L657-L658)
 - **Backend**: `AMXInt4_KGroup_MOE` [kt-kernel/python/utils/amx.py20](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/amx.py#L20-L20) The `_select_rawint4_backend` function in `kt-kernel/python/utils/amx.py` handles the selection of the appropriate RAWINT4 backend based on available CPU features (AMX, AVX-VNNI, AVX2) and environment variables (`KT_RAWINT4_BACKEND`) [kt-kernel/python/utils/amx.py103-136](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/amx.py#L103-L136)
 
 
#### FP8 / FP8_PERCHANNEL

 
 - **Loader**: `FP8SafeTensorLoader` [kt-kernel/python/utils/loader.py240](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L240-L240)
 - **Auto-Detection**: Detects block-wise (`weight_scale_inv`) vs. per-channel (`weight_scale`) scaling by inspecting tensor shapes [kt-kernel/python/utils/loader.py314-353](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L314-L353)
 - **Backend**: `AMXFP8_MOE` or `AMXFP8PerChannel_MOE` [kt-kernel/python/utils/amx.py21-23](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/amx.py#L21-L23) The `AMXMoEWrapper` class supports these FP8 backends [kt-kernel/python/utils/amx.py139-162](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/amx.py#L139-L162)
 
 
#### BF16

## Auto-Detection Mechanisms

 
### MoE Format Detection

 The `FP8SafeTensorLoader` and `BF16SafeTensorLoader` scan SafeTensor keys to identify the MoE architecture [kt-kernel/python/utils/loader.py283-313](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L283-L313):

 
| Detected Format | Expert Path Template | Projection Names |
|---|---|---|
| DeepSeek | {base}.mlp.experts | gate_proj, up_proj, down_proj |
| Mixtral | {base}.block_sparse_moe.experts | w1, w3, w2 |
| Mistral | {base}.experts | w1, w3, w2 |

 
### Scale Format Detection

 For FP8 weights, the loader automatically determines the scaling strategy [kt-kernel/python/utils/loader.py333-353](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L333-L353):

 
 - **Block-wise**: Detected if `.weight_scale_inv` exists.
 - **Per-channel**: Detected if `.weight_scale` exists and has a shape of `[N]` or `[N, 1]`.
 
 Sources: [kt-kernel/python/utils/loader.py283-353](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L283-L353) [kt-kernel/python/utils/loader.py481-509](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/loader.py#L481-L509)

 
## Conversion Process

 
### Offline Quantization

 The `convert_cpu_weights.py` script is used to transform standard SafeTensors into CPU-optimized formats.

 
 - **INT4/INT8**: Converts weights to a column-major layout required by AMX kernels [kt-kernel/scripts/README.md10-11](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/README.md?plain=1#L10-L11)
 - **AWQ**: The `AWQToColumnMajorConverter` class handles the specific unpacking and repacking logic for AWQ-quantized weights [kt-kernel/scripts/convert_cpu_weights.py476-628](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_cpu_weights.py#L476-L628)
 - **GPU Weights**: The `convert_gpu_weights.py` script quantizes weights for GPU-resident experts using GPTQ or RTN methods (W4A16/W8A16) [kt-kernel/scripts/convert_gpu_weights.py1-26](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/convert_gpu_weights.py#L1-L26) This is distinct from the CPU-optimized formats and is used for heterogeneous expert placement [kt-kernel/scripts/README.md175-179](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/scripts/README.md?plain=1#L175-L179)
 
 
### Online Quantization

 Backends like `GeneralMoEWrapper` (supporting `MOE_INT4` and `MOE_INT8`) can perform online quantization during weight loading [kt-kernel/python/utils/moe_kernel.py125-181](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/moe_kernel.py#L125-L181)

 
 - It accepts BF16/FP16 tensors directly.
 - It triggers a `load_weights_task` which quantizes and saves weights to the specified `weight_path` [kt-kernel/python/utils/moe_kernel.py179](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/kt-kernel/python/utils/moe_kernel.py#L179-L179)
