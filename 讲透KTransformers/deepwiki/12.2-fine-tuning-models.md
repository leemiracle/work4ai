  This page provides complete technical documentation for fine-tuning workflows using the `kt-sft` module integrated with **LLaMA-Factory**. It covers the architecture of heterogeneous training, configuration of LoRA adapters, and deployment of fine-tuned ultra-large MoE models.

 
---

 
## Overview

 KTransformers fine-tuning enables LoRA-based training of ultra-large MoE models (e.g., DeepSeek-V3 671B, Kimi-K2.5) on consumer hardware (e.g., 2–4x RTX 4090s) by offloading the heavyweight MoE experts to the CPU while keeping Attention and KV cache on the GPU [doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md:18-24].

 The workflow follows this pipeline:

 
 - **Environment Setup**: Installing `kt-sft` and `LLaMA-Factory` in a dedicated environment [doc/en/SFT_Installation_Guide_KimiK2.5.md:42-50].
 - **Weight Preparation**: Converting models to BF16 (required for SFT) [doc/en/SFT_Installation_Guide_KimiK2.5.md:101-101].
 - **Configuration**: Defining YAML files with `use_kt: true` and specific `kt_optimize_rule` files [doc/en/SFT_Installation_Guide_KimiK2.5.md:120-131].
 - **Training Execution**: Running `llamafactory-cli train` with the KTransformers backend [doc/en/SFT_Installation_Guide_KimiK2.5.md:147-152].
 - **Adapter Management**: Converting LoRA adapters for optimized serving with SGLang [doc/en/SFT_Installation_Guide_KimiK2.5.md:177-184].
 
 Sources: [doc/en/SFT_Installation_Guide_KimiK2.5.md:1-9], [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md:18-28]

## Architecture of kt-sft

 The `kt-sft` framework replaces standard PyTorch operators with high-performance heterogeneous versions during the LLaMA-Factory training loop [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md:45-47].

### 1. Attention (LoRA + KT Coexistence)

 To support fine-tuning, `kt-sft` introduces `KTransformersLinearLora`, which inherits from both `KTransformersLinear` and `LoraLayer` [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md:53-54]. This allows the model to retain KTransformers' high-performance prefill/generate paths while training `lora_A` and `lora_B` parameters [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md:55-57].

 
### 2. MoE (Differentiable Operator)

 The MoE layer is encapsulated as a differentiable black-box operator [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md:66-68].

 
 - **Forward Pass**: Uses `pybind11` to call C++ extensions (AMX BF16/INT8 or llamafile) [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md:70-71].
 - **Backward Pass**: Implements custom Autograd functions. To optimize performance, $W^\top$ (transposed weights) are precomputed at load time [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md:76-77]. Intermediate activations (expert projections) are cached to reduce recomputation [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md:77-78].
 
 
### 3. Multi-GPU Placement

 Instead of standard DataParallel (which duplicates the model), `kt-sft` uses **model parallelism + explicit placement** [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md:81-84]. `KTrainer` takes over the `.to(device)` call to construct layers directly on target GPUs as defined in the `kt_optimize_rule` YAML [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md:87-88].

## Performance and Resource Benchmarks

 Fine-tuning ultra-large models with `kt-sft` significantly reduces GPU memory requirements compared to standard backends [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md:28-39].

 
| Model | Backend | Throughput | GPU Memory (Peak) |
|---|---|---|---|
| DeepSeek-V2-Lite (14B) | HuggingFace | 303.58 token/s | 32.12 GB |
|  | KTransformers | 530.38 token/s | 6.08 GB |
| DeepSeek-V3 (671B) | HuggingFace | Too Huge | ~1400 GB (Theoretical) |
|  | KTransformers | 40.35 token/s | 70 GB |

 Sources: [doc/en/SFT/KTransformers-Fine-Tuning_Developer-Technical-Notes.md:30-39], [doc/en/SFT/KTransformers-Fine-Tuning_User-Guide.md:30-39]

 
### Hardware Requirements for Kimi-K2.5 SFT

 
 - **GPU**: 4 * NVIDIA RTX 4090 (24GB) [doc/en/SFT_Installation_Guide_KimiK2.5.md:27].
 - **CPU**: x86 with AMX support [doc/en/SFT_Installation_Guide_KimiK2.5.md:28].
 - **RAM**: At least 2TB system memory (Swap can be used) [doc/en/SFT_Installation_Guide_KimiK2.5.md:29-30].
