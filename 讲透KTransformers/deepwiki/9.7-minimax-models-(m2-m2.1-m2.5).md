  This page provides technical documentation for deploying and optimizing MiniMax family models (M2, M2.1, and M2.5) using the KTransformers framework. These models leverage native FP8 precision and CPU-GPU heterogeneous inference to achieve high performance on consumer and enterprise hardware.

 
## Overview of MiniMax Support

 KTransformers supports the MiniMax model family by integrating `kt-kernel` with a specialized fork of SGLang (`sglang-kt`). This integration allows for:

 
 - **Native FP8 Inference**: Utilizing the unquantized FP8 weights provided by MiniMax for high accuracy and reduced VRAM footprint [doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md1-3](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md?plain=1#L1-L3)
 - **Heterogeneous MoE Offloading**: Offloading Mixture-of-Experts (MoE) layers to the CPU while keeping active components on the GPU [doc/en/MiniMax-M2.5.md1-3](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/MiniMax-M2.5.md?plain=1#L1-L3)
 - **Layerwise Prefill**: A strategy to handle large prompt lengths by processing layers sequentially to manage VRAM usage [doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md189-192](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md?plain=1#L189-L192)

### Key Parameters for M2.1

 When manually configuring via `sglang.launch_server`, the following parameters are critical:

|---|---|
| --kt-method FP8 | Enables native FP8 inference mode doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md119 |

## Performance Benchmarks

 
### Comparison with llama.cpp

 KTransformers achieves significant performance gains over `llama.cpp` by using native FP8 weights instead of GGUF-quantized weights (like Q8_0) and utilizing optimized heterogeneous kernels.

 
| Metric | Hardware | Result (vs llama.cpp) |
|---|---|---|
| Prefill Speed | 2x RTX 5090 + EPYC 9355 | >4.5x faster doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md183 |
| Decode Speed | 2x RTX 5090 + EPYC 9355 | 30% faster doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md183 |

### Troubleshooting Out-of-Memory (OOM)

 Layerwise prefill requires additional VRAM (approx. 3.6GB for M2.1 and incremental costs based on prompt length) [doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md189](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md?plain=1#L189-L189) To mitigate OOM:

 
 - **Reduce `--kt-num-gpu-experts`**: Decreases the number of experts stored in VRAM [doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md193](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md?plain=1#L193-L193)
 - **Decrease `--chunked-prefill-size`**: Lowers the memory allocated for prefill batches [doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md194](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md?plain=1#L194-L194)
 - **Adjust `--max-total-tokens`**: Limits the KV cache size [doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md124](https://github.com/kvcache-ai/ktransformers/blob/02be2bf5/doc/en/kt-kernel/MiniMax-M2.1-Tutorial.md?plain=1#L124-L124)
