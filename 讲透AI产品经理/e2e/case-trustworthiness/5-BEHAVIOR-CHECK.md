# E2E 演练 ⑤：Agent 行为一致性检验报告

> **方法**：三个独立 general subagent，各自**只读**对应 agent 文件（`.opencode/agent/*.md`）+ 宪法（AGENT-OS.md），处理同一案例输入，**不接触对照组**（原 1-SC/2-PRC/3-DEC）。对照评分：字段完整性 / 纪律遵守 / 质量对比。
> **结论先行**：**3/3 通过**——agent 文件作为行为规范可独立执行，且三份产物均出现"纪律条款的指纹"（证据分级/占位符声明/因果怀疑等 prompt 条款在产物中留下可辨认的痕迹）。两处产物质量超过原版，已标注为可回写增量的候选。

## 纪律指纹（prompt 条款 → 产物痕迹的因果链）

这是本次检验最有价值的发现——**agent 文件里的纪律条款不是装饰，在 subagent 产物中有可辨认的对应物**：

1. ceo.md「证据分级强制标注」→ 产物 thesis 字段里出现 `[HYPOTHESIS]`/`[JUDGMENT]` 前缀
2. ai-pm.md「不接受拍脑袋——除非明说占位符待校准」→ 产物出现"绝对阈值待基线（占位声明：非最终值）"
3. ai-pm.md「离群点自查」→ 产物主动质疑 -23pp 的因果性（"客诉者本身更活跃"混杂），原版演练漏了这点
4. domain-expert.md「不凭记忆编造/知识缺口显式化」→ 产物声明"span 对齐 SOTA 属声明的知识缺口"

## 检验局限（诚实声明）

- subagent 拿到的场景是压缩版（背景数据直接给定），真实使用中 PM/Domain 需要自己从仓库/日志找证据——信息获取能力未被检验；
- 单次运行（n=1），无法排除"恰好表现好"；严格结论需 n≥3（本仓 agentbook 实验的教训：n=1 无统计力）；
- general subagent 与项目 agent 的实际运行环境（用户直接 @ 调用）仍有差异。

**结论**：行为一致性检验通过，Agent OS 三件套具备独立可执行性。PM 的"拒绝率护栏"增量已回写（见 6-EVIDENCE 附注）。
