# 04 — 概率性产品设计：三角、降级、信任

> "模型 92% 的时候是对的。你的工作是让剩下 8% 不毁掉用户信任。"（institutepm.com, 2026）
> 这一章是 AI PM 的设计学：**在 cost-quality-latency 三角上选座位，为错误设计连续谱的体验，把每次失败变成信任修复的机会。**

---

## 04.1 cost-quality-latency 三角：每次调用的权衡

传统 PM 的三角是 scope-time-resource（项目级）；AI PM 的三角是 **cost-quality-latency（每次调用级）**。三者不可兼得：

- 更便宜的模型 → 更差的输出
- 更快的输出 → 更低质量或更贵
- 更好的质量 → 更慢或更贵

**真实案例**（institutepm.com, 2026）：**同一个产品内 Notion AI 的不同功能坐在三角的不同点上**——自动补全用小快模型（P95 <300ms，用户打字不等人的场景），长文生成用大模型（多秒延迟预算，用户愿意等好内容）。**PM 逐功能定座位，不是逐产品。**

### 座位决策三问

1. **用户在等吗？**（打字补全 vs 后台批处理——等待容忍决定延迟上限）
2. **错一次多贵？**（补全错 = 按 Esc；合同扫描错 = 职业责任——错误成本决定质量下限）
3. **调用频次多高？**（高频 × 单价 = 成本主导；低频高价值 = 质量主导）

### 分层路由：同一产品的多座位策略

```
用户请求 → 意图分类器（小模型，ms 级）
            ├─ 简单请求 → 小模型（80% 流量，成本地板）
            ├─ 复杂请求 → 大模型（15% 流量，质量主力）
            └─ 高风险请求 → 大模型 + 引用溯源 + 置信闸门（5%，安全优先）
```

2026 年的主流架构。PM 的决策：**路由规则（什么算简单/复杂/高危）和各档的质量门槛**。模型在变便宜，但**用好三层路由省下的钱往往超过等下一代模型**（institutepm.com, 2026：规模化后 30% 成本削减常常就是下一个功能的预算）。

## 04.2 失败的连续谱：从"对/错"到五态

传统软件只有 happy path 和 error state。AI 产品的输出是五态连续谱（institutepm.com, 2026 改编），**每态要不同的 UX 回应**：

| 状态 | 表现 | UX 回应 | 例 |
|---|---|---|---|
| **对且自信** | 正确输出 | 正常呈现 | — |
| **部分对** | 对但有缺口/多余 | 结构化呈现 + 可编辑（不掩盖） | 摘要漏了要点 → 高亮原文对照 |
| **自信地错** | 流畅但错误（最危险） | **溯源 + 校验**（用户无法直觉发现，设计必须替他发现） | Harvey 每条法律论断挂引用 |
| **不确定** | 模型低置信 | 主动降级声明 | Copilot 给低置信补全降透明度 |
| **拒绝** | 不回答 | 拒绝分类学（04.4） | "我不能访问该数据" ≠ "这是有害请求" |

**设计金句**：对"自信地错"的唯一防线是**把验证结构做进界面**（引用、对照、可diff），因为用户自己发现不了。

## 04.3 降级设计（graceful degradation）四层

系统级降级阶梯（成本从低到高触发）：

```
L1 提示降级：输出附置信标记（"以下为低置信结果，请核对"）
L2 范围降级：拒答高风险部分，答有把握的部分
L3 模式降级：切确定性兜底（规则/模板/检索原文）
L4 人工降级：转人工队列（agent 类产品的最后防线）
```

**PM 拥有降级触发表**：什么信号（置信分/eval 分/超时/预算）触发哪层。这张表就是 agent 产品的"紧急联系卡"。

## 04.4 拒绝分类学（refusal taxonomy）

模型拒绝有三种原因，**混为一谈的 copy 是体验杀手**（institutepm.com, 2026）：

| 拒绝原因 | 用户感受 | 正确 copy 与恢复路径 |
|---|---|---|
| **安全拒绝**（harmful） | "被说教了" | 简短说明边界 + 引导到可做的相邻任务 |
| **能力拒绝**（做不到） | "它不行的样子" | 诚实 + 换路径建议（"我无法解析扫描件，上传文字版可提取"） |
| **范围拒绝**（无权限/无数据） | "为什么不理我" | 明确缺什么 + 补数据的入口 |

**PM 写这张表**——拒绝话术是产品人格的一部分，不能散落在工程代码里。

## 04.5 HITL（human-in-the-loop）决策树

什么时候要人？四个判据（综合 agenticareers/paraform 2026）：

```
错误成本高吗？（财务/安全/法律责任）
  ├─ 否 → 自动执行 + 事后可撤销（chatbot 档）
  └─ 是 → 错误可被发现吗？
            ├─ 易发现（用户当场看到） → copilot 档：建议+人批准（Tab 键模式）
            └─ 难发现（深层修改/批量操作） → 事前审批档：diff 预览 + 确认门
                                              + 高危操作升级（双人/延迟执行/审计日志）
```

两个 2026 实例：
- **Cursor 的 accept/reject UX**：代码建议的教科书设计——错误可见、拒绝零成本、采纳一键（institutepm.com, 2026）
- **Agent 的权限分级**（01 章 Tier 3-4 产品标配）：读类操作自动、写类操作确认门、删类操作双人（tianpan.co, 2026-04：agent 的信任必须显式设计——scoped credentials/变更日志/回滚/升级路径）

## 04.6 信任的账户模型

信任像账户：**每次"自信地错"是巨额提款，每次"诚实的降级"是小额存款**。设计原则：

1. **预期管理先行**：新手引导里明说"AI 会犯错，重要信息请核对来源"——说出来不丢人，隐瞒会爆炸
2. **可见性 > 完美**：展示引用/置信/来源的产品，用户对错误的容忍度显著更高（Harvey 模式）
3. **恢复路径常驻**：错误发生后，edit-and-rerun / 换模型 / 转人工的入口**永远在场**
4. **信任修复公式**：发现错误 → 承认（标记哪句错了）→ 解释（为什么错）→ 补偿（正确的在哪）。沉默修复 = 用户自己发现 = 双倍提款

**自动化偏见（automation bias）的反向防御**：人对系统有过度信任倾向（行为经济学，见 06 章）——高采纳率产品要**主动制造摩擦**：定期抽检提示、"你确定要批准全部吗"的批量确认中断。

## 04.7 Agent 特有的设计件（01 章的深化）

| 设计件 | 内容 | 为什么关键 |
|---|---|---|
| **权限矩阵** | 操作类型 × 自治级别（自动/确认/禁止） | 01.5 八层表面的第 8 层（治理控制台）是 2026 年企业采购的信任前提 |
| **审计日志** | agent 每个动作可回放 | 出事后的责任追溯（合规刚需） |
| **预算闸** | 单任务 token/金额上限 + 超限熔断 | runaway cost 是 agent 第一事故源 |
| **里程碑确认** | 长任务中途展示 plan + 进度 | 用户对"黑箱数小时"的容忍极低 |
| **kill switch** | 一键停 + 状态保存 | 信任的最后防线 |

## 核心洞察

1. **三角是逐功能决策不是产品级决策**——Notion AI 一个产品里至少两个座位。
2. **"自信地错"是唯一的致命态**，唯一防线是界面里的验证结构（引用/对照/diff），因为用户自己发现不了。
3. **拒绝分类学是产品人格**：三种拒绝三种话术，PM 亲自写。
4. **信任设计的不对称律**：毁掉信任一次的代价 >> 建立信任一百次——所以降级与诚实声明永远优于硬撑。
5. **高自动化产品需要设计摩擦**（抽检/批量确认中断）对抗自动化偏见。
