# 07 — 商业化与单位经济学：token 时代的生意

> "规模化后 30% 的成本削减常常就是下一个功能的预算。"（institutepm.com, 2026）
> AI PM 与传统 PM 在商业上的最大区别：**边际成本不为零**。传统软件复制成本≈0；AI 产品每次调用都在烧钱。这一章讲透这笔账怎么算、价格怎么定、壁垒在哪。

---

## 07.1 单位经济学：先算清一笔账

**核心公式**：

```
单位毛利 = 用户愿付的每任务价格 P
         − 推理成本（tokens × 单价 × 路由档位）
         − 检索/工具调用成本（RAG/embedding/API）
         − 失败重试与人工兜底成本（错误率 × 重试次数 × 单价 + 转人工成本）
```

**四个传统软件没有的成本项**：

| 成本项 | 说明 | PM 杠杆 |
|---|---|---|
| **推理成本** | 每次调用的模型费用 | 分层路由（04.1）、缓存（prompt cache）、蒸馏小模型 |
| **重试成本** | 错误→重试→放大调用 | eval 门槛前的质量投资直接省这 |
| **人工兜底** | HITL/转人工队列 | 降级触发表（04.3）控制流向 |
| **数据成本** | 标注/清洗/语料授权 | 显性化管道复用（06.7） |

**关键比率**：**毛利率 = 1 − 变动成本/收入**。AI 产品的健康线：C 端订阅制 60%+（推理占比失控会跌到 30%）、API/按量制 70%+、企业定制 40-55%（含实施）。**毛利不是财务的事，是 04 章三角选择的直接结果**——每个功能的"座位"决定了它的毛利率。

**实例锚**：Customer.io 的 Builder Plan（CLI+MCP+webhooks，2026）：**$0.40/千条消息，跨渠道同价**——按量计价的 AI-native 样本（framework.ai-native-transformation.com, 2026-06）。

→ `experiments/03_cql_tradeoff.py` 三档配置 × 毛利模拟，可改参数复算。

## 07.2 定价：per-seat 崩塌与四种继任

**为什么 per-seat 崩塌**：agent 替代的是"座位上的劳动"——一个 agent 干三个人的活，席位从 3→1。**按人头收费 = 收入与创造的价值反相关**（2026 年 AI-native 定价讨论共识，framework.ai-native-transformation.com）。

| 模式 | 形态 | 适用 | 风险 |
|---|---|---|---|
| **按量（usage-based）** | per token/per call/per task | API、开发者产品 | 用量波动→收入波动；用户预算焦虑 |
| **按结果（outcome-based）** | per resolved ticket/per closed deal | 客服/销售 agent（Sierra/Decagon 模式） | 归因争议（算谁的功劳）；结果定义要铁 |
| **混合（base+overage）** | 订阅含量+超额按量 | C 端 Pro 档、企业套餐 | 定价复杂度 |
| **按价值分成** | 抽成节省的成本/增量收入 | 垂直 AI（Harvey 类） | 信任门槛高，需可审计的价值度量 |

**PM 的定价三问**：
1. 我们的**计价单位**与用户获得的**价值单位**同构吗？（客服按"解决的工单"收费 = 完美同构；按 token = 用户替你承担了模型低效的风险）
2. 谁承担波动？（按 token = 用户；按结果 = 你）
3. 有没有**反向激励**？（按结果计价 → agent 可能为了"解决"而过度让步——reward hacking 的商业版）

## 07.3 商业模式画布：AI 版增量

经典画布（Osterwalder）九格里，AI 改写了五格：

| 格 | AI 版改写 |
|---|---|
| 价值主张 | 从"功能"到"能力×可靠性"——可靠性本身是付费点（99.9% 版溢价） |
| 成本结构 | 边际成本>0（07.1），固定成本里算力研发占大头 |
| 收入流 | 07.2 四模式；**免费档的推理成本是真金白银**——免费额度=获客成本，要算 CAC |
| 关键资源 | 算力配额/专有数据/标注团队/eval 资产 |
| 壁垒 | 见 07.4——从网络效应转向三重壁垒 |

## 07.4 三重壁垒：AI 产品的护城河重构

传统 SaaS 的壁垒（网络效应/切换成本/规模经济）在 AI 时代部分失效——**模型是商品，UI 是易抄的，prompt 是会泄漏的**。2026 年的可防御资产：

1. **数据壁垒**——但不是"有数据"，是**数据飞轮**：用户使用→产生带反馈的数据（采纳/拒绝/修正）→模型或检索变好→体验提升→更多使用。**反馈闭环的数据**（特别是用户的修正行为）是模型公司拿不到的私有资产。深层形态见 06.7：隐性知识显性化的执行能力。
2. **工作流壁垒**——产品嵌入的深度（权限/集成/审计），尤其 agent 时代：**八层表面全铺的公司**（01.5）比只有 chat 界面的公司难替换一个数量级。
3. **信任壁垒**——合规认证（SOC2/EU AI Act 分级/行业资质）+ 审计能力 + 事故记录。B2B 里**安全审查通过本身是资产**（05.2 影响者角色的一票否决权）。

**诚实的反面**：这三重壁垒都需要时间，而模型能力每代跃迁都会**重置一部分先发优势**（你的微调优势可能被下一代基线抹平）。→ 战略含义：**把赌注放在"随模型变强而增值"的资产上**（工作流深度/反馈数据），而不是"与模型能力赛跑"的资产上（纯质量调优）。这是 02.10 能力窗口规划的商业侧镜像。

## 07.5 竞争分析：AI 市场的四层格局

```
L4 应用层（Harvey/Sierra/Notion AI…）     ← 溢价高、被基线跃迁威胁
L3 编排层（LangChain/MCP 宿主/agent 平台）← 标准之争（MCP 已成事实标准）
L2 模型层（OpenAI/Anthropic/DeepSeek…）   ← 商品化+价格战（2025-2026 硬事实）
L1 算力层（NVIDIA/云厂自研芯片）          ← 供给周期决定全行业成本曲线
```

**PM 的竞争三问**：
1. 我的护城河在 L4 的哪一格？基线跃迁（L2 每代发布）会重置它吗？（07.4 诚实反面）
2. 我的供应商（L2）会变成我的竞争者吗？（模型公司向上做应用是 2025-2026 常态——**平台风险**是 AI 应用 PM 的常设风险项）
3. 我在 L3 标准上的位置（MCP 服务器质量/注册表存在感）是资产还是负债？

## 07.6 投资人/董事会视角：AI PM 要会讲的账

三个 2026 年融资市场的标准问题（综合 thrumos/paraform）：

1. **"AI-native 还是 AI-washed？"**——七类形态（01.1）里你真在哪类？尽调会拆穿虚标。
2. **"毛利率随规模怎么走？"**——正确答案不是"更高"而是**有结构的**：规模→路由优化+缓存命中→推理单价降；但用户期望升级→档位上移→单价升。两条曲线的赛跑要能讲清。
3. **"净收入留存（NRR）的驱动是席位还是深度？"**——per-seat 逻辑的扩张=加人（AI 时代悖论），深度逻辑=单客户用量/价值增长（按量/按结果模式天然 NRR 友好）。

## 07.7 商业化检查清单

- [ ] 单位毛利公式每一项可算？最敏感的变量是哪个（敏感性分析见 experiments/03）？
- [ ] 计价单位与价值单位同构？
- [ ] 定价模式有无反向激励？
- [ ] 免费档的推理 CAC 算过吗？
- [ ] 三重壁垒各自的时间线和"基线跃迁重置风险"评估过？
- [ ] 平台风险（供应商变竞争者）有 Plan B（多模型路由/开源兜底）？

## 核心洞察

1. **边际成本>0 改写一切**：定价、免费策略、毛利结构、甚至功能取舍（贵的功能要配贵的价格或省的成本）。
2. **per-seat 与 AI 价值创造反相关**——计价单位与价值单位同构是定价的第一原则。
3. **按结果定价是 agent 时代的自然解**，但要防 reward hacking 商业版，且结果定义必须铁。
4. **护城河赌"随模型变强而增值"的资产**（工作流深度/反馈闭环数据），不赌"与模型赛跑"的资产。
5. **AI PM 必须懂成本侧到能做三角决策**（04.1）——不懂推理账本的 PM 在 2026 年等于不懂服务器成本的电商 PM。

## ✍️ 自测

1. 把你产品的单位毛利公式写出来，对最敏感变量做 ±30% 敏感性（可用 experiments/03 改参）。
2. 你的计价单位 vs 用户的价值单位，错位多大？最近的提价/降价是按成本还是按价值？
3. 如果明天基线模型免费达到你产品的质量，你还剩下什么？（护城河压力测试）
