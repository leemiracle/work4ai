# 05 — 用户与客户画像：谁在用 AI 产品，谁在买 AI 产品

> AI 产品的"用户"和"客户"经常不是同一人，且**两者的动机可能相反**（员工要省事，雇主要可控）。本章三部分：市场三分法（C 端/B 端/开发者）→ B2B 采购中心解剖 → AI 特有的采纳与信任画像。

---

## 05.1 市场三分法：三类用户，三套逻辑

| | **C 端** | **B 端（知识工作者/企业）** | **开发者** |
|---|---|---|---|
| 代表产品 | ChatGPT、豆包、Character.AI | Harvey、M365 Copilot、Sierra | API、vLLM、Cursor、Claude Code |
| 买者=用者？ | 是 | **否**（采购中心，05.2） | 常常是（或强力影响） |
| 核心动机 | 好奇/效率/情感陪伴/创作 | 省 moment、降本、合规、老板指令 | **能力/成本/可控性**——能力天花板优先 |
| 付费意愿 | 低（订阅疲劳），期待免费档 | 高（ROI 可计算时） | 中-高（按量） |
| 对错误的容忍 | 玩具期高、工具期骤降 | 分任务：草拟高/签核零 | 编译/测试可验证 → 容忍高 |
| 评价指标 | 留存/分享/D30 | 任务完成率/席位激活率/续约 | 集成摩擦/延迟/成本/能力上限 |
| 杀手问题 | "新鲜感退了为什么还用" | "雇员为什么绕过它" | "天花板不够时我为什么不用别家" |
| 2026 动态 | 入口战争（超级 app 化） | **L1→L2 漂移**（客户操作从手动 UI 向 agent 编排过渡，2026-06 AI-native 框架） | **CLI/MCP 优先**：开发者要先在 agent 宿主里试你的产品 |

**开发者画像细分**（对模型即产品/AI PaaS 形态最重要）：
- **评估型**（选型中）：看 benchmark 但更看自己的 eval——**给他 playground 和透明定价**
- **集成型**（已上车）：要 SDK 质量/限流透明/版本稳定性——**模型 deprecation 政策是留存变量**
- **调优型**（重度）：要 fine-tune/蒸馏/私有部署选项——**算力与合规是成交条件**

## 05.2 B2B 采购中心：六角色模型（Webster-Wind 经典 + 2026 修订）

企业买 AI 产品不是一个人决定，是**采购中心（buying center）**。经典六角色 + AI 时代修订：

| 角色 | 关心什么 | AI 时代的新事实 |
|---|---|---|
| **发起者**（一线遇到痛点的人） | 自己的痛 | **shadow AI 现象**：员工先用起来再汇报——你的产品可能已被员工私下用了一年（治理术语叫 shadow AI，2026 taxonomy Ring 2） |
| **使用者** | 好不好用 | 采纳率是最大风险（见 05.3 鸿沟） |
| **影响者**（技术评估） | 架构/安全 | **安全审查是 2026 年 AI 采购的一票否决**：PII 处理、部署架构（公有云/单租户/BYOC/本地）直接决定哪些单子可能成交（thrumos.com, 2026） |
| **决策者**（预算） | ROI/风险 | "错误成本>订阅成本"的算术（03 章阈值经济学的买方版） |
| **购买者**（采购/法务） | 条款 | EU AI Act 风险分级让"我们买的是哪一级系统"成为合同问题 |
| **守门人**（IT/安全） | 接入控制 | **MCP 正在变成新的 SSO**：agent 接入的注册表/权限/审计是 2026 采购新关卡（framework.ai-native-transformation.com, 2026-06） |

**PM 动作**：GTM 矩阵按角色准备证据——给使用者的是体验 demo，给影响者的是安全白皮书与部署选项表，给决策者的是 ROI 计算器，给守门人的是 MCP 治理面板（01.5 第 8 层表面）。

## 05.3 采纳曲线与鸿沟：AI 版

技术采纳生命周期（Rogers 创新扩散 → Moore 鸿沟理论）在 AI 产品上的 2026 修正：

```
创新者(2.5%) → 早期大众(13.5%) ══鸿沟══ → 后期大众(34%) → 落后者(16%)
```

**AI 产品的三条特殊鸿沟**：

1. **玩具-工具鸿沟**（C 端，创新者→早期大众之间）：尝鲜者容忍错误，大众用户把产品当基础设施要求可靠性。跨过的信号：**用户开始把重要工作托付给你**（不重开一个 ChatGPT 窗口核对答案）。
2. **试点-生产鸿沟**（B 端，早期大众→后期大众之间）：Tier 3 agent 试点停滞率 ~55%、Tier 4 ~70%（Presenc AI, 2026-05）——从 pilot 到 production 的死亡谷。跨过的证据不是"试点成功"而是**"续约且扩席位"**。
3. **人-组织鸿沟**（企业内部）：工具买回来了，工作流没改 = 席位空转。M365 Copilot 式产品的激活率问题——**购买≠采纳，采纳≠价值**（06 章组织变革视角展开）。

**采纳的代理指标**（比"满意度"诚实）：
- 周活跃深度（真用它做核心工作的频率）
- **绕过率**的反面：用户遇到难题时"回到老方法"还是"换个问法再试"
- agent 类：人工介入率的下降斜率（自治能力在赢得信任）

## 05.4 AI 特有的信任与心理画像

用户对 AI 的心理模型（mental model）决定一切。四个画像维度：

| 维度 | 两极 | 设计含义 |
|---|---|---|
| **自动化信任** | 盲信（自动化偏见）↔ 全不信 | 盲信者需要摩擦设计（04.6），不信者需要可见的成功案例 |
| **拟人化倾向** | 高（当人看）↔ 低（当工具看） | 高拟人用户对"拒绝/错误"的反应是社交性的（道歉话术有效） |
| **验证意愿** | 主动核对 ↔ 全盘接受 | 低验证意愿 × 高错误成本 = 危险象限，产品必须**替他验证**（04.2 结构化验证） |
| **任务可托付度**（05.2 JTBD×概率） | 高（草拟/brainstorm）↔ 低（签核/申报） | 决定功能的市场分层——同一个人对不同任务坐在不同格子里 |

**画像构建方法**（研究方法论速查）：

1. **访谈仍为王**，但加 AI 特有问法："上次 AI 答错你怎么办的？"（验证意愿）/"你把什么工作交给它了，什么还不敢？"（可托付度边界——**这条边界就是你的 roadmap**：边界右移 = 产品成长）
2. **日志挖掘 > 问卷**：真实使用分布里的重试模式/放弃点/绕过路径是画像金矿
3. **AI 加速研究但别信综合**：40 份访谈一下午聚簇完，但"模型会抹平那条本该杀死你假设的不便引语——**离群点亲自读**"（pmtoolkit.ai, 2026-06）
4. 合成画像（persona）仍要建，但 AI 产品加两栏：**该 persona 的可托付度地图 + 验证意愿等级**

## 05.5 画像→产品决策的三条落点

1. **North Star 按画像分层**：C 端看"每周成功任务数"，B 端看"席位激活率×任务完成率"，开发者看"深度集成数"（进入生产调用的 API 数）
2. **风险功能按画像排序**：先做"高验证意愿"人群的高错误成本功能（他们会核对，容错养功能成熟），再推向低验证意愿人群（此时质量已达标）
3. **GTM 按采购中心角色排弹药**（05.2 表）

## 核心洞察

1. **AI 产品的买者/用者/付款者三分离**比传统软件更极端——画像必须做三层：用户画像×采购中心角色×组织成熟度（L1/L2/L3）。
2. **三条特殊鸿沟**（玩具-工具/试点-生产/人-组织）比经典鸿沟更致命，各有各的跨越证据。
3. **任务可托付度边界就是 roadmap**：用户"敢交给 AI 什么"的边界随质量与信任右移——产品战略 = 主动管理这条边界的移动速度。
4. **低验证意愿 × 高错误成本是危险象限**，产品必须替用户验证（溯源/diff/二次校验）。
5. **shadow AI 是事实入口**：员工先用的产品在企业采购时领先半个身位——PLG 与 top-down 销售在 AI 时代合流。
