# 02 — 方法论武器库：经典六器 + AI 特有五器

> 传统 PM 方法论没有作废——**discovery、优先级、利益相关者、书面沟通全部迁移**。但有几个习惯会**主动伤害**转型中的 PM（institutepm.com, 2026）。本章把武器库分成两格：能带走的，和必须新造的。

---

## 02.1 经典六器（全部可迁移，个别要改用法）

### ① JTBD（Jobs to be Done）
**"用户雇用产品做什么工作"**（Christensen 牛奶昔故事 / Ulwick ODI）。AI 时代它变得**更重要**：模型能力月月在变，唯一稳定的是 job。问法升级：

> 传统：用户雇 Excel 做什么？→ 记账。
> AI：用户雇"记账"这个 job 里，哪一段是**痛苦到愿意托付给一个 92% 可靠的系统**的？（收据识别 ✅；税务申报 ❌ 直到可靠性>99%）

**JTBD × 概率性 = 任务可托付度分析**：把 job 拆成步骤，每步问两问——出错成本多高？错误可发现吗？（见 04 章 HITL 决策树）

### ② RICE 优先级
Reach × Impact × Confidence ÷ Effort。AI 产品两个改动：

1. **Reach 要按"数据就绪度"折价**：用户要 ≠ 数据能。institutepm/paraform 都强调 AI 用例排序要**按 data readiness 而非仅用户需求**——没有训练/检索数据的用例 Reach 实际为 0。
2. **Confidence 要按"可行性未证"降级**：传统功能可行性开工前就知；AI 功能可能要试完才知道 recall 够不够（opendatascience.com, 2026-08）。→ 见 `experiments/01_rice_priority.py`，内置 reach 诚实度敏感性分析。

### ③ Kano 模型
魅力/期望/必备/无差异/反向五分类。**AI 功能的 Kano 位置漂移极快**——2023 年"AI 摘要"是魅力属性，2026 年是必备属性（竞品都有 = 不加分，没有 = 减分）。Kano 线每年整体下移，**期望管理要按季度重测**。→ `experiments/02_kano_classify.py` 用标准 Kano 问卷对（正反两问）做分类模拟。

### ④ 双钻设计（Double Diamond）
发散-收敛 ×2（问题→方案）。AI 插了一颗新钻：**可行性与合意性之间多了"能力钻"**——方案空间被"当前模型做得到什么"剪枝。改造成三钻：

```
问题钻（用户痛点） → 能力钻（模型在 eval 上离要求多远？） → 方案钻（产品形态）
```

能力钻的核心动作：**用 1-2 周 spike 测核心任务的 eval 基线**，达不到阈值的功能不进方案钻——这就是"exploratory data analysis、标注、benchmarking 成为 discovery 的一部分"（Google 生产 ML 指南, via opendatascience.com 2026-08）。

### ⑤ North Star 指标
一个代表用户获得价值的指标。AI 产品的 North Star 常见陷阱：**把模型指标当产品指标**。正确姿势是双栏：

| 产品指标（North Star 候选） | 模型指标（护栏/诊断） |
|---|---|
| 任务完成率、每周成功任务数 | precision/recall/幻觉率 |
| "AI 帮我省了多少时间" | P95 延迟、成本/任务 |

**模型指标必须连接到业务指标**（转化/留存/解决时长/风险下降），否则更准的模型可能是更差的产品（更慢更贵，opendatascience.com, 2026-08）。

### ⑥ HEART 框架（Google）
Happiness/Engagement/Adoption/Retention/Task success。AI 版每个维度加"概率切片"：Engagement 要按"模型答好 vs 答坏"分段看留存——**答坏一次的用户的 7 日留存曲线**是 2026 年 AI 产品最关键的一条曲线（呼应 00 章"8% 不毁信任"）。

## 02.2 AI 特有五器（传统工具箱里没有的）

### ⑦ Eval 门控开发（本系列 03 章专讲）
**Roadmap 从"功能+日期"变成"能力赌注+质量门槛"**：

> 传统："Q3 上线文档对话。"
> Eval 驱动："Q3 文档对话 eval 套件达 90% helpfulness **后**上线。"——可能早于也可能晚于 Q3。

Anthropic、OpenAI、Harvey、Cursor 都跑在这个模式上，**PM 显式拥有 eval 套件和门槛**（institutepm.com, 2026）。

### ⑧ 幻觉预算（hallucination budget）
按功能分配"可容忍错误量"，像性能预算一样写进 PRD：

```
功能：会议纪要生成
幻觉预算：事实性错误 ≤2%（抽检 rubric），其中"行动项张冠李戴"=0 容忍（高成本错误）
防御：引用溯源（每条行动项链接到发言时间戳）+ 高风险字段二次校验
```

**预算不为零——为用户和团队诚实设定期望**；防御设计按错误成本分级（04 章）。

### ⑨ 数据需求文档（Data Requirements Doc）
AI PRD 的标配姊妹篇：要收集什么、怎么标注、何时"训练集够好能发版"、代表性检查（样本是否代表目标人群）、标注一致性、隐私/许可约束。**数据是第一等输入**：RAG 功能里语料质量常常比 prompt 更重要（aiarch.dev, 2026）。

### ⑩ 能力窗口规划（capability window planning）
传统 roadmap 只受工程产能约束；AI roadmap 还受**模型能力曲线**约束——今天做不到的功能，下一代模型发布日就可行。PM 要**追踪能力曲线、把 roadmap 摆在窗口打开时刚好接得住的位置**（agenticcareers.co, 2026-04）。配套纪律：功能分"现在可做"与"窗口打开即做"两栏，后者维护着评估好的 PRD 草稿。

### ⑪ 降级设计（graceful degradation）
传统软件只有 happy path 和 error state；AI 产品的失效是**连续谱**——部分正确、自信地错、拒绝、跑题，每种要不同的 UX 回应（institutepm.com, 2026）。04 章专讲。

## 02.3 会主动伤害你的旧习惯（institutepm.com, 2026 明确清单）

| 旧习惯 | 为什么有害 | 替代 |
|---|---|---|
| **像素级 spec**（规定每个状态） | 输出方差存在，逐状态 spec 拖慢团队且暴露不懂媒介 | 行为 spec + eval rubric |
| **单变量 A/B 测一切** | 输出方差淹没单变量信号 | 离线 eval + holdout 集 + 在线质量看板；A/B 留给 shell UX |
| **年度路线图** | 模型landscape比年度周期快 | 季度能力赌注 + 6 周滚动功能视野 |
| "feature done = QA 过" | QA 过 ≠ 分布可接受 | eval 门槛 + 上线后监控 |

## 02.4 工具栈的变化（2026）

传统 PM 住 Jira；AI PM 住**eval 平台（Braintrust/LangSmith/Patronus/Inspect AI）+ 模型 playground（OpenAI/Anthropic console）+ prompt 管理工具**，更多时间在代码旁侧环境和 notebook（institutepm.com / agenticcareers.co, 2026）。QA 团队淡出背景；新利益相关者进场：应用科学家、模型提供商、AI 安全审查、（受监管行业的）合规官。

## 02.5 方法论选型速查

```
我在哪个环节？
├─ 找方向 ──────→ JTBD（job 拆步）× 数据就绪度
├─ 定优先级 ────→ RICE（Reach 折价 + Confidence 降级）
├─ 探方案 ──────→ 三钻（中间加能力钻/eval spike）
├─ 写需求 ──────→ 行为 spec + eval 门槛 + 幻觉预算 + 数据需求文档
├─ 定指标 ──────→ North Star（产品）× 模型护栏（双栏）
├─ 排路线 ──────→ eval 门控 + 能力窗口两栏
└─ 出问题 ──────→ 降级连续谱 + 失败分类学（04 章）
```

## 核心洞察

1. **经典手艺是多数工作**（discovery/优先级/沟通/gtm 仍占大头，aiarch.dev 2026），AI 层是叠加不是替换。
2. **三处经典工具必须改装**：RICE（数据就绪折价）、双钻（加能力钻）、roadmap（eval 门控）。
3. **AI 特有五器的共同底色**：把"质量分布"当管理对象——预算它（幻觉）、测量它（eval）、等它（能力窗口）、兜住它（降级）。
4. **转型最危险的不是不会新的，是旧的用得太顺**：像素级 spec 和单变量 A/B 是 2026 年 AI PM 的两大隐形杀手。
