# EPLB Functions

  Relevant source files 
 - [lplb/eplb.py](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py)
 
  This page provides comprehensive reference documentation for the EPLB (Expert Parallelism Load Balancer) functions defined in `lplb/eplb.py`. These functions implement static load balancing by reordering, replicating, and packing experts across GPUs based on historical workload statistics.

 For information about how EPLB integrates into the overall LPLB system, see [Core Concepts](https://deepwiki.com/deepseek-ai/LPLB/3.2-eplb:-static-load-balancing). For the `Planner` class that invokes these functions, see [Planner Class](https://deepwiki.com/deepseek-ai/LPLB/4.1-planner-class). For dynamic per-batch load balancing, see [LPLB: Dynamic Load Balancing](https://deepwiki.com/deepseek-ai/LPLB/3.3-lplb:-dynamic-load-balancing).

## Overview

 The EPLB module provides four public functions that work together to achieve static load balancing:

 
| Function | Role | Lines |
|---|---|---|
| rebalance_experts | Main entry point; selects hierarchical or global policy | lplb/eplb.py151-190 |
| rebalance_experts_hierarchical | Core algorithm implementing three-stage hierarchical balancing | lplb/eplb.py80-148 |
| replicate_experts | Creates expert replicas using greedy max-load minimization | lplb/eplb.py49-77 |
| balanced_packing | Packs weighted items into bins using greedy balanced assignment | lplb/eplb.py6-46 |

 These functions transform logical expert indices into physical expert assignments that minimize load imbalance across GPUs. The core operation is a three-stage process:

 
 - **Group-to-Node Packing**: Pack expert groups onto nodes using `balanced_packing`
 - **Expert Replication**: Create redundant experts within nodes using `replicate_experts`
 - **Physical-to-GPU Packing**: Pack physical experts onto GPUs using `balanced_packing`
 
 **Sources:** [lplb/eplb.py1-191](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L1-L191)

 Main entry point for the EPLB static load balancing system. Selects between hierarchical and global balancing policies based on topology constraints.

 
### Signature


 
### Parameters

 
| Parameter | Type | Shape | Description |
|---|---|---|---|
| weight | torch.Tensor | [layers, num_logical_experts] | Historical workload statistics (token counts) for each logical expert across MoE layers |
| num_replicas | int | - | Total number of physical experts after replication; must be a multiple of num_gpus |
| num_groups | int | - | Number of expert groups; typically equals num_gpus for standard configurations |
| num_nodes | int | - | Number of server nodes; experts within a node use faster NVLink communication |
| num_gpus | int | - | Total number of GPUs; must be a multiple of num_nodes |

 
### Returns

 
| Tensor | Shape | Description |
|---|---|---|
| physical_to_logical_map | [layers, num_replicas] | Maps each physical expert index to its corresponding logical expert index |
| logical_to_physical_map | [layers, num_logical_experts, X] | Maps each logical expert to all its physical replicas; padded with -1 where X = max(logcnt) |
| expert_count | [layers, num_logical_experts] | Number of physical replicas for each logical expert |

 
### Behavior

 The function implements policy selection logic:

 
 - **Hierarchical Policy** [lplb/eplb.py171-175](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L171-L175): Used when `num_groups % num_nodes == 0`, indicating that expert groups align with node boundaries. This enables node-aware balancing that minimizes inter-node traffic.
 - **Global Policy** [lplb/eplb.py176-180](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L176-L180): Used otherwise, treating all GPUs as a single pool by calling `rebalance_experts_hierarchical` with `num_groups=1` and `num_nodes=1`.
 
 After computing the mappings, the function constructs `logical_to_physical_map` by scattering physical expert indices into a zero-padded tensor [lplb/eplb.py182-189](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L182-L189)

 Core algorithm implementing three-stage hierarchical load balancing. This function orchestrates group-to-node packing, expert replication, and physical-to-GPU packing to achieve balanced expert distribution.

|---|---|---|---|

| num_groups | int | - | Number of expert groups |

 The function enforces several divisibility constraints [lplb/eplb.py97-103](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L97-L103):

### Stage 1: Group-to-Node Packing [lplb/eplb.py114-121](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L114-L121)

 Groups experts and packs them onto nodes:

 
 - Compute `tokens_per_group` by summing weights within each group
 - Call `balanced_packing(tokens_per_group, num_nodes)` to assign groups to nodes
 - Construct `log2mlog` permutation that reorders experts by their node assignment
 
 The permutation ensures that experts assigned to the same node are contiguous in memory.

 
### Stage 2: Expert Replication [lplb/eplb.py123-128](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L123-L128)

 Creates redundant copies of experts within each node:

 
 - Reshape weight tensor to `[layers * nodes, log_experts / nodes]` treating each node independently
 - Call `replicate_experts()` to greedily create replicas that minimize maximum load per replica
 - Compute `tokens_per_phy` by dividing expert load by replica count
 
 This stage produces `phy2mlog` (physical-to-modified-logical mapping), `phyrank` (replica ranks), and `mlogcnt` (replica counts).

 
### Stage 3: Physical-to-GPU Packing [lplb/eplb.py130-148](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L130-L148)

 Packs physical experts onto individual GPUs:

 
 - Call `balanced_packing(tokens_per_phy, num_gpus / num_nodes)` within each node
 - Construct `phy2pphy` permutation that orders physical experts by GPU assignment
 - Compose all permutations to produce final mappings: 
 - `pphy2log`: physical expert → original logical expert
 - `pphyrank`: physical expert → replica rank
 - `logcnt`: logical expert → total replica count
 
 
### Permutation Composition

 The function uses an `inverse()` helper [lplb/eplb.py105-112](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L105-L112) to invert permutations via scatter operations:

## replicate_experts

 Greedily replicates logical experts to create physical replicas, minimizing the maximum load across all replicas.

 
### Signature

 
```

```

 
### Parameters

 
| Parameter | Type | Shape | Description |
|---|---|---|---|
| weight | torch.Tensor | [X, num_log] | Workload for each logical expert; X is typically batch dimension or layers×nodes |
| num_phy | int | - | Total number of physical experts after replication; must be ≥ num_log |

 
### Returns

 
| Tensor | Shape | Description |
|---|---|---|
| phy2log | [X, num_phy] | Logical expert ID for each physical expert |
| rank | [X, num_phy] | Replica rank (0-indexed) for each physical expert |
| logcnt | [X, num_log] | Number of replicas created for each logical expert |

 
### Algorithm

 The function uses a greedy approach [lplb/eplb.py64-77](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L64-L77):

 
 - **Initialize** [lplb/eplb.py68-71](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L68-L71): First `num_log` physical experts map 1-to-1 with logical experts (rank 0, count 1)
 - **Greedy Selection** [lplb/eplb.py72-76](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L72-L76): For each additional replica: 
 - Compute normalized load: `weight / logcnt` for each logical expert
 - Select the expert with maximum normalized load
 - Create a replica: increment `logcnt`, assign replica rank
 - **Result**: Each iteration reduces the maximum normalized load, achieving approximate balance

```

```

 
### Complexity

 The algorithm performs `num_phy - num_log` iterations, each requiring O(num_log) operations to find the maximum. Total complexity: **O((num_phy - num_log) × num_log)**.

## balanced_packing

 Packs weighted items into a fixed number of bins using a greedy balanced assignment strategy. Each bin receives exactly `n / m` items, and the algorithm minimizes total weight imbalance across bins.

 
### Signature

 
```

```

 
### Parameters

 
| Parameter | Type | Shape | Description |
|---|---|---|---|
| weight | torch.Tensor | [X, n] | Weight of each item; X is batch dimension (typically layers) |
| num_packs | int | - | Number of bins/packs; must divide n evenly |

 
### Constraint

 The function requires `n % num_packs == 0` [lplb/eplb.py20](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L20-L20) This ensures each pack contains exactly `groups_per_pack = n / num_packs` items.

 
### Returns

 
| Tensor | Shape | Description |
|---|---|---|
| pack_index | [X, n] | The pack/bin index (0 to num_packs-1) assigned to each item |
| rank_in_pack | [X, n] | The position (0 to groups_per_pack-1) of the item within its pack |

 
### Algorithm

 
```

```

 **Sources:** [lplb/eplb.py6-46](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L6-L46)

 
### Behavior

 
 - **Trivial Case** [lplb/eplb.py23-28](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L23-L28): If each pack contains exactly one item, return identity mapping
 - **Sort Items** [lplb/eplb.py30](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L30-L30): Sort items by weight in descending order (heaviest first)
 - **Greedy Assignment** [lplb/eplb.py33-45](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L33-L45): For each item in sorted order: 
 - Find the pack with minimum current weight that hasn't reached capacity
 - Assign the item to that pack
 - Update pack weight and item count
 
 The greedy strategy (heaviest items first) provides good empirical balance by preventing large items from accumulating in the same bin.

 The algorithm processes items in sorted order once: **O(n log n)** for sorting + **O(n × num_packs)** for greedy assignment.

## Tensor Shape Transformations

 The following table tracks tensor shape transformations through `rebalance_experts_hierarchical`:

 
| Stage | Tensor | Shape | Description |
|---|---|---|---|
| Input | weight | [L, E] | L=layers, E=num_logical_experts |
| Stage 1 | tokens_per_group | [L, G] | G=num_groups, sum over group_size |
|  | group_pack_index | [L, G] | Node assignment for each group |
|  | log2mlog | [L, E] | Permutation: logical → modified-logical |
| Stage 2 | tokens_per_mlog | [L×N, E/N] | N=num_nodes, reshaped per-node |
|  | phy2mlog | [L×N, P/N] | P=num_physical_experts |
|  | phyrank | [L×N, P/N] | Replica rank within node |
|  | mlogcnt | [L×N, E/N] | Replica count per mlog expert |
| Stage 3 | tokens_per_phy | [L×N, P/N] | Physical expert loads |
|  | pack_index | [L×N, P/N] | GPU assignment within node |
|  | phy2pphy | [L×N, P/N] | Permutation: node-physical → global-physical |
| Output | pphy2log | [L, P] | Final physical → logical mapping |
|  | pphyrank | [L, P] | Final replica ranks |
|  | logcnt | [L, E] | Final replica counts |
