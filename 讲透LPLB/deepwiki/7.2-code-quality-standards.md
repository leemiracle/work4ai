## Purpose and Scope

 This document describes the code quality standards enforced in the LPLB codebase and the automated tools that maintain them. These standards ensure consistent code style, type safety, and correctness across all Python, C++, and CUDA code.

 For information about setting up these tools in your development environment, see [Development Environment Setup](https://deepwiki.com/deepseek-ai/LPLB/7.1-development-environment-setup). For information about testing practices, see [Testing](https://deepwiki.com/deepseek-ai/LPLB/7.3-testing).

 
---

 
## Overview

 LPLB enforces strict code quality standards through automated tooling integrated via pre-commit hooks. The quality enforcement system consists of three primary layers:

 
 - **C++ Formatting**: `clang-format` with LLVM style for C++/CUDA code
 - **Python Type Checking**: `mypy` with strict type safety requirements
 - **Python Linting/Formatting**: `ruff` with comprehensive rule coverage
 
 All quality checks run automatically before commits via pre-commit hooks, preventing low-quality code from entering the repository.

## C++ and CUDA Code Formatting

 
### clang-format Configuration

 C++ and CUDA files are formatted using `clang-format` with the LLVM base style. The configuration is minimal, relying on LLVM's well-established conventions:

 
| Configuration File | Style Base |
|---|---|
| .clang-format | LLVM |

 The LLVM style enforces:

 
 - 2-space indentation
 - Column limit of 80 characters (default)
 - Consistent pointer/reference alignment
 - Predictable brace placement
 - Consistent spacing around operators
 
 **Applied to file types:** `.cpp`, `.c`, `.cu`, `.h`

 **Pre-commit hook:** `clang-format` v20.1.4 from `https://github.com/pre-commit/mirrors-clang-format`

 **Sources:** [.clang-format1-2](https://github.com/deepseek-ai/LPLB/blob/0490f794/.clang-format#L1-L2) [.pre-commit-config.yaml23-27](https://github.com/deepseek-ai/LPLB/blob/0490f794/.pre-commit-config.yaml#L23-L27)

 
### Format Enforcement

 The `clang-format` hook runs automatically on all C++ and CUDA files during:

 
 - Every git commit (pre-commit stage)
 - Manual execution via `pre-commit run clang-format`
 
 **Example:** The C++ plugin code in `lplb/csrc/plugin.cpp` is formatted according to LLVM style, ensuring consistency with NVIDIA's cuBLASDx and cuSolverDx examples.

 **Sources:** [.pre-commit-config.yaml23-27](https://github.com/deepseek-ai/LPLB/blob/0490f794/.pre-commit-config.yaml#L23-L27)

## Python Type Checking with mypy

 
### Type Checking Philosophy

 LPLB enforces **strict type safety** for all Python code except test files. Every function must have complete type annotations, and the type checker validates correctness at the deepest level.

 
### mypy Configuration

 The following table summarizes the strict type checking rules configured in `pyproject.toml`:

 
| Setting | Value | Purpose |
|---|---|---|
| python_version | "3.8" | Target minimum Python version |
| exclude | '^tests/.*\.py$' | Skip test files |
| check_untyped_defs | true | Check function bodies even without annotations |
| disallow_incomplete_defs | true | Require complete parameter/return annotations |
| disallow_untyped_defs | true | Require all functions to be typed |
| no_implicit_optional | true | Require explicit Optional for None defaults |
| strict_equality | true | Strict comparison type checking |
| strict_optional | true | Strict None checking |
| warn_no_return | true | Warn about missing return statements |
| warn_redundant_casts | true | Warn about unnecessary casts |
| warn_unreachable | true | Warn about unreachable code |
| warn_unused_configs | true | Warn about unused config options |
| warn_unused_ignores | true | Warn about unnecessary # type: ignore |
| ignore_missing_imports | true | Don't fail on missing stub files |
| show_error_codes | true | Display error codes for reference |

 **Sources:** [pyproject.toml42-63](https://github.com/deepseek-ai/LPLB/blob/0490f794/pyproject.toml#L42-L63)

### Import Sorting Configuration

 - **Standard library extensions:** `typing_extensions` treated as standard library

### Execution Stages

 Pre-commit hooks run at three stages:

 
| Stage | Trigger | Typical Use |
|---|---|---|
| pre-commit | git commit | Fast checks before commit |
| pre-push | git push | Additional validation before push |
| manual | pre-commit run | On-demand execution |

 Default stages: All hooks run on `pre-commit`, `pre-push`, and `manual` unless specified otherwise.

 **Sources:** [.pre-commit-config.yaml3](https://github.com/deepseek-ai/LPLB/blob/0490f794/.pre-commit-config.yaml#L3-L3)

 
### Critical Hooks with Fast Fail

 Two hooks are configured with `fail_fast: true`, immediately aborting the commit if they fail:

 
 - **`check-merge-conflict`**: Detects unresolved merge conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`)
 - **`check-ast`**: Validates Python syntax by parsing the AST
 
 These hooks prevent obviously broken code from being committed.

 **Sources:** [.pre-commit-config.yaml13-14](https://github.com/deepseek-ai/LPLB/blob/0490f794/.pre-commit-config.yaml#L13-L14) [.pre-commit-config.yaml20-22](https://github.com/deepseek-ai/LPLB/blob/0490f794/.pre-commit-config.yaml#L20-L22)

 
### Auto-fixing vs. Blocking Hooks

 
```

```

 **Ruff behavior:**

 
 - `ruff-check` with `--fix`: Auto-fixes safe issues, exits non-zero if fixes were applied
 - `ruff-check` with `--exit-non-zero-on-fix`: Forces review of auto-fixes
 - `ruff-format` with `--exit-non-zero-on-format`: Forces review of formatting changes

## Code Quality Standards Summary

 
### Standards Matrix

 
| Language | Tool | Configuration File | Key Standards |
|---|---|---|---|
| C++/CUDA | clang-format | .clang-format | LLVM style, 2-space indent |
| Python (Types) | mypy | pyproject.toml [tool.mypy] | Strict typing, complete annotations |
| Python (Style) | ruff | pyproject.toml [tool.ruff] | 100-char lines, single quotes, extensive rules |
| All | pre-commit | .pre-commit-config.yaml | Automated enforcement |

 
### Quality Gates

 The following quality gates must pass before code can be committed:

 
 - **Syntax Validity**: Python AST must parse, YAML/TOML must be valid
 - **Security**: No merge conflicts, private keys, or security vulnerabilities
 - **Formatting**: Code must match clang-format (C++) or ruff-format (Python) output
 - **Type Safety**: Python code must pass mypy strict type checking
 - **Linting**: Python code must pass all enabled ruff lint rules
 - **Basic Hygiene**: No trailing whitespace, proper line endings, no large files
 
 **Sources:** [.pre-commit-config.yaml1-60](https://github.com/deepseek-ai/LPLB/blob/0490f794/.pre-commit-config.yaml#L1-L60) [pyproject.toml40-152](https://github.com/deepseek-ai/LPLB/blob/0490f794/pyproject.toml#L40-L152)

## Best Practices

 
### For Python Development

 
 - **Write type annotations first**: Define function signatures with complete types before implementation
 - **Run mypy frequently**: `pre-commit run mypy --all-files` catches type errors early
 - **Use IDE integration**: Configure your editor to show ruff and mypy errors in real-time
 - **Review auto-fixes**: Don't blindly accept ruff's `--fix` changes; understand them
 - **Avoid `# type: ignore`**: Use proper typing instead of suppressing errors
 
 
### For C++ Development

 
 - **Format before committing**: Run `clang-format -i file.cpp` manually if editing outside git workflow
 - **Follow LLVM conventions**: Understand LLVM style guide for consistent idioms
 - **Check formatting**: `pre-commit run clang-format --files lplb/csrc/plugin.cpp`
 
 
### For Notebook Development

 
 - **Strip output before committing**: nbstripout automatically handles this, but verify
 - **Keep important outputs**: Use `--keep-output` flag (already configured)
 - **Test notebook execution**: nbstripout doesn't validate execution correctness

## Troubleshooting

 
### Common Issues

 
| Problem | Cause | Solution |
|---|---|---|
| mypy errors about missing stubs | Third-party library lacks type stubs | Already handled via ignore_missing_imports = true |
| clang-format not found | clang-format not in PATH | Pre-commit downloads its own version |
| ruff-check --fix fails | Unfixable linting error | Read error message, fix manually |
| Hook hangs indefinitely | Network timeout downloading repos | Run pre-commit clean and retry |
| Type errors in tests | Tests excluded from mypy | Normal; tests don't require type annotations |
