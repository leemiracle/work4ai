## .gitignore - Version Control Exclusions

 The `.gitignore` file defines patterns for files and directories that should not be tracked by Git. LPLB excludes build artifacts, compiled extensions, and downloaded dependencies.

 
### Excluded Patterns

 
| Pattern | Description | Reason for Exclusion |
|---|---|---|
| dist/ | Distribution packages created by build tools | Generated at build time |
| build/ | Temporary build directory used by setuptools | Generated at build time |
| *.egg-info/ | Python package metadata directory | Generated during installation |
| *.so | Compiled shared library (C++ extension) | Platform-specific binary |
| *.pyc | Compiled Python bytecode | Generated by Python interpreter |
| __pycache__/ | Python bytecode cache directory | Generated by Python interpreter |
| lplb/resources/mathdx/ | Downloaded NVIDIA Math libraries | Downloaded by download-mathdx.sh1-30 |
| nvidia-mathdx-*.tar.gz | cuSolverDx/cuBLASDx archive | Downloaded dependency |
| .vscode/ | VSCode IDE workspace settings | User-specific IDE configuration |

## .editorconfig - Cross-Editor Formatting

 The `.editorconfig` file ensures consistent formatting across different editors and IDEs. It is supported natively by most modern editors (VSCode, IntelliJ, Vim, Emacs, etc.) via plugins or built-in support.

 
### Global Settings

 All files share these base settings [.editorconfig5-11](https://github.com/deepseek-ai/LPLB/blob/0490f794/.editorconfig#L5-L11):

 
| Setting | Value | Purpose |
|---|---|---|
| charset | utf-8 | Universal character encoding |
| end_of_line | lf | Unix-style line endings (cross-platform) |
| indent_style | space | Use spaces instead of tabs |
| indent_size | 4 | Default 4-space indentation |
| trim_trailing_whitespace | true | Remove trailing spaces |
| insert_final_newline | true | Ensure files end with newline |

 
### Language-Specific Overrides

 The following table shows indent size overrides for different file types:

 
| File Pattern | Indent Size | Languages |
|---|---|---|
| *.py | 4 spaces | Python |
| *.{cpp,hpp,cxx,cc,c,h,cu,cuh} | 2 spaces | C/C++/CUDA |
| *.rs | 4 spaces | Rust |
| *.go | tabs | Go (uses tab indentation) |
| *.{yaml,yml,json} | 2 spaces | Configuration files |
| .clang-{format,tidy} | 2 spaces | Clang config files |
| Makefile | tabs | Makefiles (require tabs) |
| *.sh | 4 spaces | Shell scripts |
| *.bat | 4 spaces, CRLF | Windows batch files |
| *.md | 2 spaces, soft wrap | Markdown |
| *.rst | 4 spaces, soft wrap | reStructuredText |

 **EditorConfig Rule Application**

 The configuration uses pattern matching to apply language-specific rules. For example, C++/CUDA files [.editorconfig16-17](https://github.com/deepseek-ai/LPLB/blob/0490f794/.editorconfig#L16-L17) use 2-space indentation, while Python files [.editorconfig13-14](https://github.com/deepseek-ai/LPLB/blob/0490f794/.editorconfig#L13-L14) use 4-space indentation. This aligns with community standards for each language.

## .clang-format - C++ Code Style

 The `.clang-format` file defines formatting rules for C++ and CUDA code. It is used by the `clang-format` command-line tool and integrated into the pre-commit hooks (see [Code Quality Standards](https://deepwiki.com/deepseek-ai/LPLB/7.2-code-quality-standards)).

 While the file itself is not included in the provided sources, it is referenced by `.editorconfig` [.editorconfig28-29](https://github.com/deepseek-ai/LPLB/blob/0490f794/.editorconfig#L28-L29) and is part of the code quality enforcement pipeline. The formatting rules ensure consistent style for:

 
 - `plugin.cpp` - The C++ extension module
 - `minilp.cu` - The CUDA kernel template
 - Test files in C++
 
 The clang-format configuration is automatically applied when:

 
 - Running `pre-commit run --all-files`
 - Committing changes (via pre-commit hook)
 - Manually invoking `clang-format -i <file>`
 
 Sources: [.editorconfig28-29](https://github.com/deepseek-ai/LPLB/blob/0490f794/.editorconfig#L28-L29)

 - **Licensing**: MIT License permits unrestricted use with attribution requirements
 
 These configuration files work together with the build system (see [Build System](https://deepwiki.com/deepseek-ai/LPLB/6-build-system)) and code quality tools (see [Code Quality Standards](https://deepwiki.com/deepseek-ai/LPLB/7.2-code-quality-standards)) to maintain a professional, maintainable codebase.
