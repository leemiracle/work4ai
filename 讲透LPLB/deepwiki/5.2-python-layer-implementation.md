## Purpose and Scope

 This page documents the Python layer implementation of LPLB, which provides the user-facing API and orchestrates both static and dynamic load balancing operations. The Python layer consists of two primary components: the `Planner` class (the main API interface) and the `eplb` module (static load balancing logic).

 For the overall system architecture context, see [Architecture Overview](https://deepwiki.com/deepseek-ai/LPLB/5.1-architecture-overview). For details on the C++ extension layer that this Python code interfaces with, see [C++ Extension and Runtime Compilation](https://deepwiki.com/deepseek-ai/LPLB/5.3-c++-extension-and-runtime-compilation).

### Initialization and State Management

 The `Planner.__init__()` method establishes the core topology and configuration:

 
| Parameter | Type | Purpose |
|---|---|---|
| redundant_to_original | torch.Tensor [group_size, num_redundants] | Defines which redundant expert copies which original |
| n_routed_experts | int | Total physical experts including redundants |
| n_logical_routed_experts | int | Total logical experts (before replication) |
| ep_size | int \| None | Number of EP ranks (defaults to group.size()) |
| group | ProcessGroup \| None | Distributed communication group |

 **Key invariants enforced:**

 
 - Each rank has the same number of redundant experts
 - The i-th redundant expert on any rank is a copy of the i-th expert on another rank
 - Each redundant expert is shared between exactly two ranks

### Dynamic Balancing Interface Methods

 The `Planner` provides three core methods that interface with the C++ `CompiledSolver`:

 
#### count_workload()

 Delegates to `CompiledSolver.count_idx()` to count token distribution across experts using GPU-accelerated histograms.

 
```

```

 **Parameters:**

 
 - `idx`: Logical expert indices with shape `[batch_size * seq_len * top_k]`, values in `[-1, n_logical_routed_experts)`
 - `n_sms`: Number of streaming multiprocessors for parallel histogram computation
 
 **Returns:**

 
 - Global workload count: `[n_logical_routed_experts]`
 - Per-SM workload: `[n_sms, n_logical_routed_experts]` (used for deterministic mapping)
 
 **Sources:** [lplb/planner.py184-194](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/planner.py#L184-L194)

## EPLB Module

 The `eplb` module implements static load balancing through three key algorithms: balanced packing, expert replication, and hierarchical balancing.

 
### Balanced Packing Algorithm

 The `balanced_packing()` function implements a greedy bin-packing algorithm that minimizes load imbalance:

 
```

```

 **Algorithm properties:**

 
 - **Time complexity:** O(n log n) for sorting + O(n × m) for greedy assignment
 - **Space complexity:** O(n) for indices + O(m) for pack tracking
 - **Constraint enforcement:** Each pack contains exactly `n/m` items
 
 **Implementation:** [lplb/eplb.py6-46](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L6-L46)

 **Sources:** [lplb/eplb.py6-46](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L6-L46)

 
### Expert Replication Strategy

 The `replicate_experts()` function creates redundant expert copies to balance load:

 
```

```

 **Greedy heuristic:** Always replicate the expert with the highest load-per-replica ratio. This tends to balance the maximum load across replicas.

 **Sources:** [lplb/eplb.py49-77](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L49-L77)

 
### Hierarchical Load Balancing

 The `rebalance_experts_hierarchical()` function implements a three-stage hierarchical balancing strategy optimized for multi-node clusters:

 
```

```

 **Hierarchical strategy benefits:**

 
 - **Node-level balancing:** Keeps expert groups together on nodes to minimize inter-node communication
 - **Intra-node replication:** Creates redundant experts within each node for local load balancing
 - **GPU-level packing:** Distributes physical experts to GPUs to balance compute load
 
 **Configuration requirements:**

 
 - `num_logical_experts % num_groups == 0` (experts evenly divided into groups)
 - `num_groups % num_nodes == 0` (groups evenly distributed to nodes)
 - `num_gpus % num_nodes == 0` (GPUs evenly distributed to nodes)
 - `num_physical_experts % num_gpus == 0` (physical experts evenly distributed to GPUs)
 
 **Sources:** [lplb/eplb.py80-148](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/eplb.py#L80-L148)

 
### Entry Point: rebalance_experts()

 The `rebalance_experts()` function is the public API entry point:

 
```

```

 **Policy selection:**

 
 - **Hierarchical:** Used when `num_groups % num_nodes == 0`, respecting node boundaries
 - **Global:** Used otherwise, treating all GPUs as a single pool

## Coordination with C++ Extension

 The Python layer maintains minimal state and delegates all GPU-intensive operations to the C++ `CompiledSolver`:

 
| Python Method | C++ Method | Kernel Launched | Purpose |
|---|---|---|---|
| count_workload() | CompiledSolver.count_idx() | kernel_count_idx | Parallel histogram computation |
| solve_probs() | CompiledSolver.solve() | kernel_solve | Interior Point Method LP solver |
| weighted_select_target() | CompiledSolver.map_idx() | kernel_map_idx | Deterministic index remapping |

 **Cached solver factory:**

 The `_get_solver()` function uses `@functools.lru_cache(maxsize=None)` to ensure only one `CompiledSolver` instance exists per configuration:

 
```

```

 This caching is critical because `CompiledSolver.__init__()` triggers expensive runtime compilation via NVRTC. See [Runtime Compilation and Caching](https://deepwiki.com/deepseek-ai/LPLB/6.3-runtime-compilation-and-caching) for details.

 **Sources:** [lplb/planner.py17-36](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/planner.py#L17-L36) [lplb/planner.py95-102](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/planner.py#L95-L102)

 
## State Management Summary

 The Python layer maintains the following state across invocations:

 
| State Category | Components | Mutability | Purpose |
|---|---|---|---|
| Topology | r2o, o2r, group_size, num_redundants | Immutable after __init__() | Define redundancy structure |
| Expert Counts | n_routed_experts, n_logical_routed_experts, ep_size, n_group | Immutable after __init__() | Dimension tracking |
| Current Mapping | phy2log | Updated by update_redundancy_mapping() | Physical-to-logical assignment |
| Communication | ep_group, deep_ep_initialized, solver | solver immutable, flags mutable | Distributed coordination |

 **Thread safety:** The `Planner` class is **not thread-safe**. Each process rank should maintain its own instance. The cached `_get_solver()` is process-local and safe for single-threaded access.
