## Purpose and Scope

 This page documents LPLB's three-tier distributed communication architecture, which enables efficient load balancing across multi-GPU, multi-node deployments. The architecture is designed to minimize communication overhead by using the fastest available communication path for each data exchange pattern.

 This page focuses on the communication primitives and protocols. For the LP solver algorithm that uses these primitives, see [5.5](https://deepwiki.com/deepseek-ai/LPLB/5.5-linear-programming-solver). For the C++ extension that manages kernel compilation and launch, see [5.3](https://deepwiki.com/deepseek-ai/LPLB/5.3-c++-extension-and-runtime-compilation). For optional DeepEP Buffer integration details, see [8.1](https://deepwiki.com/deepseek-ai/LPLB/8.1-deepep-integration).

 LPLB employs a hierarchical communication strategy with three tiers, each optimized for different communication scopes:

 The hierarchy follows a principle of locality: data is exchanged at the narrowest scope possible. Thread blocks use shared memory, GPUs within a node use CUDA IPC, and GPUs across nodes use NVSHMEM RDMA.

## Performance Characteristics

 
### Communication Bandwidth Hierarchy

 The three tiers have vastly different bandwidth characteristics:

 
| Tier | Mechanism | Typical Bandwidth | Latency |
|---|---|---|---|
| Intra-SM | Shared memory | ~20 TB/s | 1-2 cycles |
| Intra-Node | CUDA IPC (NVLINK) | ~900 GB/s | ~1 μs |
| Inter-Node | NVSHMEM RDMA (InfiniBand) | ~200 GB/s | ~5 μs |

 **Sources:** System architecture general knowledge, not directly from code

 
### Workload Size Optimization

 The inter-node communication is optimized for the expected workload sizes:

 
 - Each expert's workload: 4 bytes (float32)
 - Total experts per node: `n_groups * GROUP_SIZE * n_experts_per_rank`
 - Allgather message size: `n_nodes * n_experts * sizeof(float)`
 
 **Sources:** [csrc/plugin.cpp391-392](https://github.com/deepseek-ai/LPLB/blob/0490f794/csrc/plugin.cpp#L391-L392) [lplb/resources/csrc-tmpl/minilp.cu116-127](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/resources/csrc-tmpl/minilp.cu#L116-L127)

 The symmetric heap allocation is 128-byte aligned for optimal RDMA performance:

 **Sources:** [csrc/plugin.cpp391-392](https://github.com/deepseek-ai/LPLB/blob/0490f794/csrc/plugin.cpp#L391-L392)

 
### Thread Specialization

 Communication tasks are strategically assigned to minimize thread divergence:

 
| Task | Thread Assignment | Rationale |
|---|---|---|
| NVSHMEM operations | Thread 0 only | Minimize message count |
| Memory copies | All threads (strided) | Maximize bandwidth |
| Warp reductions | Warp 0 (threads 0-31) | Native warp operations |
| IPC signaling | Thread 0 | Atomic operation sequencing |

 **Sources:** [lplb/resources/csrc-tmpl/minilp.cu114-155](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/resources/csrc-tmpl/minilp.cu#L114-L155) [minilp.cu165-174](https://github.com/deepseek-ai/LPLB/blob/0490f794/minilp.cu#L165-L174)

 This specialization balances parallelism with communication efficiency.
