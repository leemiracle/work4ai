## Unit Tests: Solver Validation

 The `test_solve.py` module contains parameterized tests that validate the LP solver's ability to achieve load balance across different topology configurations. The test function `test_planner_solve()` exercises the complete solve pipeline and verifies convergence.

 
### Test Configuration Matrix

 
```

```

 **Test Parameters** [tests/test_solve.py13-23](https://github.com/deepseek-ai/LPLB/blob/0490f794/tests/test_solve.py#L13-L23)

 
| Parameter | Values Tested | Purpose |
|---|---|---|
| r2o | CUBE_8P2E, RING_8P, HYPERCUBE_16P2E, torus_2d(8,4) | Different redundancy topologies |
| n_logical_experts | 256 | Number of logical experts to balance |
| ep_size | 16, 32, 64 | Number of GPUs in expert parallel group |
| n_redundants_per_rank | 1, 2, 4 | Replication factor per rank |
| with_reorder | True, False | Whether to apply EPLB reordering |
| tolerance | 1.01-1.1 | Maximum allowed balance coefficient |

 
### Test Execution Flow

 The test follows this sequence [tests/test_solve.py24-90](https://github.com/deepseek-ai/LPLB/blob/0490f794/tests/test_solve.py#L24-L90):

 
 - **Initialization**: Creates `Planner` instance with specified topology
 - **Optional Reordering**: Calls `update_redundancy_mapping()` with synthetic workload history
 - **Workload Generation**: Creates random workload distribution
 - **Solve**: Invokes `solve_probs()` to compute optimal load distribution
 - **Validation**: Computes actual workload distribution and verifies balance coefficient

### Weighted Target Selection Test

 The `test_weighted_select_target()` function validates deterministic routing of expert indices based on computed load distribution probabilities [tests/test_idx_processing.py55-139](https://github.com/deepseek-ai/LPLB/blob/0490f794/tests/test_idx_processing.py#L55-L139)

 **Test Flow** [tests/test_idx_processing.py60-138](https://github.com/deepseek-ai/LPLB/blob/0490f794/tests/test_idx_processing.py#L60-L138):

 
 - **Setup**: Initialize planner and generate random workload history
 - **Mapping Update**: Call `update_redundancy_mapping()` to establish `log2phy` mapping
 - **Weight Generation**: Create random weight tensor `o_weight` in range [0, 1]
 - **Counting**: Count current workload with `count_workload()`
 - **Mapping**: Execute `weighted_select_target()` to map logical to physical indices
 - **Validation**: Verify mapped indices satisfy constraints and approximate target distribution
 
 **Validation Assertions**:

 
| Assertion | Purpose |
|---|---|
| mapped_idx.shape == idx.shape | Shape preservation |
| mapped_idx.min() >= -1 | Valid index range |
| (mapped_idx == -1) == (idx == -1) | Padding consistency |
| either_equal check | Mapping to valid replicas |
| err < 5e-2 | Distribution error within 5% |

 The distribution error validation [tests/test_idx_processing.py132-138](https://github.com/deepseek-ai/LPLB/blob/0490f794/tests/test_idx_processing.py#L132-L138) computes the relative difference between expected and actual workload distributions:
