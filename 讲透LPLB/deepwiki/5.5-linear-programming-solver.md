## Purpose and Scope

 This page provides a detailed explanation of the Interior Point Method (IPM) implementation used by LPLB's `kernel_solve` to compute optimal token distribution ratios across redundant experts. The solver minimizes load imbalance within an expert-parallel group by formulating a linear program with load balance and assignment constraints, then solving it through iterative refinement using NVIDIA's cuSolverDx and cuBLASDx libraries.

 For information about the broader CUDA kernel architecture, see [CUDA Kernel Implementation](https://deepwiki.com/deepseek-ai/LPLB/5.4-cuda-kernel-implementation). For how the solver coordinates across multiple nodes, see [Distributed Communication Architecture](https://deepwiki.com/deepseek-ai/LPLB/5.6-distributed-communication-architecture).

 
## Problem Formulation

 The LP solver addresses the following optimization problem: given a set of experts with redundant replicas distributed across GPUs in a group, determine what fraction of each expert's workload should be handled by the original expert versus its replicas to minimize the maximum load on any GPU.

 **Inputs:**

 
 - `global_workload`: Aggregated token counts per logical expert (normalized so max = 1)
 - `r2o` (redundant-to-original): Topology matrix defining which redundant experts map to which original experts
 - `phy2log`: Physical-to-logical expert index mapping
 
 **Outputs:**

 
 - `result`: Load distribution ratios for each (rank, duplicate) pair, where `result[rank*DUP_PER_RANK + dup]` specifies the fraction of tokens for that redundant expert to be processed by its original expert (remainder goes to replica)
 
 **Objective:** Minimize the maximum load across all GPUs in the group while ensuring that for each expert, the sum of loads assigned to its original and replica equals the total workload.

## Constraint Matrix Construction

 The constraint matrix `a` has dimension `NC x NV` where `NC = GROUP_SIZE + GROUP_SIZE * DUP_PER_RANK` constraints:

 
### Load Balance Constraints (First `GROUP_SIZE` rows)

 Each row `ic < GROUP_SIZE` enforces that rank `ic`'s total load plus slack equals the maximum load:

 
```
a[ic][iv] * x[iv] + slack[ic] = max_load
```

 The coefficients are:

 
 - For original expert variables: `a[ic][var_rank*DPR+var_dup] = dup_workload[var_rank][var_dup]` if `var_rank == ic`, else 0
 - For replica variables: `a[ic][var_rank*DPR+var_dup] = dup_workload[var_rank][var_dup]` if `r2o[ic*DPR+var_dup] == var_rank`, else 0
 - For slack variable: `a[ic][GS*DPR*2+ic] = 1`
 - For max variable: `a[ic][GS*DPR*2+GS] = -1`
 
 The right-hand side `b[ic]` equals the negative sum of fixed (non-replicated) expert workloads on rank `ic`.

 
### Assignment Constraints (Remaining `GROUP_SIZE * DUP_PER_RANK` rows)

 Each row `ic >= GROUP_SIZE` enforces that the sum of original and replica loads for a redundant expert equals 1:

 
```
x[ic - GROUP_SIZE] + x[ic - GROUP_SIZE + GROUP_SIZE * DUP_PER_RANK] = 1
```

 Sources: [lplb/resources/csrc-tmpl/minilp.cu236-273](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/resources/csrc-tmpl/minilp.cu#L236-L273)

 
### Big M Column Construction

 The final column uses the Big M method to ensure initial feasibility. For each constraint row `ic`, the coefficient is computed as:

 
```
a[ic][NV-1] = b[ic] - sum(a[ic][0:NV-1])
```

 This ensures `A @ vec(1) = b`, allowing initialization with `x = vec(1)`.

 Sources: [lplb/resources/csrc-tmpl/minilp.cu276-282](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/resources/csrc-tmpl/minilp.cu#L276-L282)

 
### Objective Vector

 The objective vector `c` minimizes the maximum load and penalizes the artificial variable:

 
```
c[0:NV-2] = 0
c[NV-2] = 1        // Minimize max load
c[NV-1] = 1000     // Big M penalty for artificial variable
```

## Interior Point Method Algorithm

 The solver implements a primal Interior Point Method with 5 fixed iterations. Each iteration updates the solution using a Newton-like step with diagonal scaling.

 
```

```

 
### Algorithm Steps

 **Initialization** [minilp.cu331-333](https://github.com/deepseek-ai/LPLB/blob/0490f794/minilp.cu#L331-L333):

 
```
x[j] = 1 for all j in [0, NV)
```

 **Iteration Loop** [minilp.cu335-367](https://github.com/deepseek-ai/LPLB/blob/0490f794/minilp.cu#L335-L367): For `step = 0` to 4:

 
 - **Diagonal Scaling**: Compute `ax2[i][j] = a[i][j] * x[j]²` to incorporate the current iterate's quadratic scaling
 - **Gram Matrix**: Compute `ax2a = ax2 @ aᵀ` using `matmulNT<NC, NC, NV>`
 - **Scaled Objective**: Compute `ax2c = ax2 @ c` using `matmulNT<NC, 1, NV>`
 - **Solve Linear System**: Solve `ax2a * y = ax2c` using Cholesky decomposition via `gaussian_elimination_solve<NC>`
 - **Compute Dual**: Compute `r = y @ a` using `matmulNN<1, NV, NC>`
 - **Descent Direction**: Compute `d[j] = x[j] * (c[j] - r[j])` and `d_max = max(d)`
 - **Update Solution**: Compute step size `α = 0.999 / d_max` and update `x[j] *= (1 - α * d[j])`
 
 Sources: [lplb/resources/csrc-tmpl/minilp.cu335-367](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/resources/csrc-tmpl/minilp.cu#L335-L367)

 
### Mathematical Formulation

 The Interior Point Method maintains a barrier term through the `x²` scaling. At each iteration, the solver approximately minimizes:

 
```
minimize    cᵀx - μ·sum(log(x))
subject to  A·x = b
            x > 0
```

 The KKT conditions lead to the Newton system:

 
```
(A·X²·Aᵀ)·y = A·X²·c
```

 where `X = diag(x)`. The descent direction is then `d = X·(c - Aᵀy)`.

 Sources: [lplb/resources/csrc-tmpl/minilp.cu335-367](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/resources/csrc-tmpl/minilp.cu#L335-L367)

## Workload Preprocessing

 Before solving, the kernel aggregates and normalizes workload:

 
### Workload Aggregation

 For distributed setups with NVSHMEM [minilp.cu109-177](https://github.com/deepseek-ai/LPLB/blob/0490f794/minilp.cu#L109-L177) block 0 performs:

 
 - **Inter-node allgather**: Synchronize `workload` across nodes using `nvshmem_putmem_signal_nbi`
 - **Inter-node sum**: Sum workloads across nodes into `workload_buf_intra`
 - **Intra-node sync**: Use CUDA IPC atomics to synchronize within node
 - **Intra-node sum**: Sum workloads across devices in node to `global_workload`

## Performance Characteristics

 The solver is designed for single-SM execution per LP problem:

 
 - **Latency**: ~100 µs per solve for intra-node optimization (longer for inter-node)
 - **Iteration Count**: Fixed at 5 iterations (no adaptive convergence)
 - **Parallelism**: One block per expert-parallel subgroup (gridDim.x = number of groups)
 - **Memory**: All data fits in shared memory (~10 KB for typical configurations)
 
 The fixed iteration count trades potential accuracy for predictable performance. The 5-iteration choice balances convergence quality with latency constraints for real-time MoE inference.
