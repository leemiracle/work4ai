## Purpose and Scope

 This document explains how LPLB manages its external dependencies during build and runtime. LPLB requires several categories of dependencies: NVIDIA math libraries (cuSolverDx), CUDA runtime components (NVRTC, NVJitLink), Python packages (PyTorch), and optional distributed communication libraries (NVSHMEM). The dependency management system ensures these components are downloaded, extracted to the correct locations, and properly linked during the build process.

 For information about how these dependencies are used during the build, see [Build Configuration](https://deepwiki.com/deepseek-ai/LPLB/6.1-build-configuration). For details on runtime kernel compilation that uses these dependencies, see [Runtime Compilation and Caching](https://deepwiki.com/deepseek-ai/LPLB/6.3-runtime-compilation-and-caching).

 
## Dependency Overview

 LPLB's dependencies are organized into four categories:

 
| Category | Components | Management Method | Required |
|---|---|---|---|
| NVIDIA Math Libraries | cuSolverDx, cuBLASDx | download-mathdx.sh script | Yes |
| CUDA Runtime Libraries | nvrtc, nvJitLink, cuda | System CUDA installation | Yes |
| Python Packages | torch, setuptools, wheel | pip/pyproject.toml | Yes |
| Distributed Communication | NVSHMEM, deep_ep | Environment detection | No |

│   └── ...                            # Additional cuSolverDx headers
└── external/

### NVSHMEM Integration

 NVSHMEM support is conditionally enabled based on environment detection [setup.py9-12](https://github.com/deepseek-ai/LPLB/blob/0490f794/setup.py#L9-L12):

 **Detection Mechanism:**

 
```

```

 Sources: [setup.py9-12](https://github.com/deepseek-ai/LPLB/blob/0490f794/setup.py#L9-L12)

 When detected, the build system:

 
 - Sets the `USE_NVSHMEM` preprocessor macro [setup.py38](https://github.com/deepseek-ai/LPLB/blob/0490f794/setup.py#L38-L38)
 - Adds NVSHMEM include directory [setup.py32](https://github.com/deepseek-ai/LPLB/blob/0490f794/setup.py#L32-L32)
 - Defines `NVSHMEM_DIR` and `DEEP_EP_SO` macros [setup.py39-40](https://github.com/deepseek-ai/LPLB/blob/0490f794/setup.py#L39-L40)
 - Links the DeepEP shared library [setup.py26](https://github.com/deepseek-ai/LPLB/blob/0490f794/setup.py#L26-L26)
 
 The `NVSHMEM_DIR` environment variable must point to the NVSHMEM installation directory. This directory structure is expected:

 
```
$NVSHMEM_DIR/
└── include/
    └── nvshmem.h          # NVSHMEM C API headers
```

 **Compile-Time Macros:**

 
| Macro | Value Source | Purpose |
|---|---|---|
| USE_NVSHMEM | Always defined if NVSHMEM found | Enables NVSHMEM code paths in C++ |
| NVSHMEM_DIR | $NVSHMEM_DIR environment | Provides path for runtime resource loading |
| DEEP_EP_SO | deep_ep_cpp.__file__ | Specifies DeepEP library location |

 Sources: [setup.py32-44](https://github.com/deepseek-ai/LPLB/blob/0490f794/setup.py#L32-L44)

### Resource File Purposes

 
| Resource Path | Runtime Usage | Accessed By |
|---|---|---|
| resources/csrc-tmpl/* | CUDA kernel source templates | CompiledSolver::compile_and_load_module |
| resources/mathdx/lib/libcusolverdx.fatbin | Pre-compiled cuSolverDx device code | NVJitLink during kernel linking |
| resources/mathdx/include/**/* | cuSolverDx C++ API headers | NVRTC during kernel compilation |
| resources/mathdx/external/**/* | cuBLASDx C++ API headers | NVRTC during kernel compilation |

 The glob pattern `**/*` [pyproject.toml36-37](https://github.com/deepseek-ai/LPLB/blob/0490f794/pyproject.toml#L36-L37) ensures all nested files in the include directories are packaged, preserving the directory structure required by the `#include` directives in the CUDA kernel code.

### MathDx Version

 The MathDx library version is hardcoded [download-mathdx.sh3](https://github.com/deepseek-ai/LPLB/blob/0490f794/download-mathdx.sh#L3-L3):

 
```

```

 This version provides:

 
 - cuSolverDx API compatible with the Interior Point Method implementation
 - cuBLASDx headers for matrix operations in the solver kernel
 
 Updating to a different version requires modifying the version string in the download script and verifying API compatibility.

 
### PyTorch Version

 No explicit PyTorch version constraint is specified in `pyproject.toml` [pyproject.toml10](https://github.com/deepseek-ai/LPLB/blob/0490f794/pyproject.toml#L10-L10) The build system assumes compatibility with the installed PyTorch's C++ extension API. Users should install a PyTorch version that matches their CUDA toolkit version.
