  This page provides reference documentation for the project configuration files that control version control behavior, editor formatting consistency, and C++ code style. These files ensure consistent development practices across different development environments and are automatically enforced through pre-commit hooks (see [Code Quality Standards](https://deepwiki.com/deepseek-ai/LPLB/7.2-code-quality-standards)).

 For information about the build configuration (`setup.py`, `pyproject.toml`), see [Build Configuration](https://deepwiki.com/deepseek-ai/LPLB/6.1-build-configuration). For development environment setup, see [Development Environment Setup](https://deepwiki.com/deepseek-ai/LPLB/7.1-development-environment-setup).

## Overview

 LPLB includes three configuration files that standardize code formatting and version control:

 
| Configuration File | Purpose | Scope |
|---|---|---|
| .gitignore | Excludes generated files from version control | Git |
| .editorconfig | Enforces consistent formatting across editors | All file types |
| .clang-format | Defines C++ code style rules | C++ source files |

 These files work together to maintain code quality standards across the development lifecycle, from local editing to pre-commit validation.

## .gitignore

 The `.gitignore` file specifies which files and directories should be excluded from version control. This prevents build artifacts, compiled binaries, and downloaded dependencies from being committed to the repository.

 
### Exclusion Rules

 
| Pattern | Purpose | Generated By |
|---|---|---|
| dist/ | Distribution packages | python setup.py sdist |
| build/ | Build artifacts | python setup.py build |
| *.egg-info/ | Package metadata | setuptools |
| *.so | Compiled shared objects | C++ extension build |
| *.pyc | Python bytecode | Python interpreter |
| __pycache__/ | Python cache directories | Python interpreter |
| lplb/resources/mathdx/ | Downloaded cuSolverDx library | download-mathdx.sh |
| nvidia-mathdx-*.tar.gz | Compressed dependency archive | download-mathdx.sh |
| .vscode/ | VS Code workspace settings | VS Code editor |

### Key Design Decisions

 The `.gitignore` configuration ensures:

 
 - **Reproducible Builds**: Build artifacts are excluded so developers rebuild from source, ensuring build script correctness.
 - **Dependency Management**: The `mathdx/` directory is excluded because the `download-mathdx.sh` script [download-mathdx.sh](https://github.com/deepseek-ai/LPLB/blob/0490f794/download-mathdx.sh) fetches it automatically during installation.
 - **Cross-Platform Development**: IDE-specific directories (`.vscode/`) are excluded to avoid conflicts between developers using different editors.
 
 **Sources:** [.gitignore1-10](https://github.com/deepseek-ai/LPLB/blob/0490f794/.gitignore#L1-L10)

## .editorconfig

 The `.editorconfig` file enforces consistent code formatting across different text editors and IDEs. This file is automatically recognized by most modern editors (VS Code, Vim, IntelliJ, etc.) and applies settings when files are opened.

 
### Global Settings

 All files share these base settings:

 
```
[*]
charset = utf-8
end_of_line = lf
indent_style = space
indent_size = 4
trim_trailing_whitespace = true
insert_final_newline = true
```

 **Sources:** [.editorconfig5-11](https://github.com/deepseek-ai/LPLB/blob/0490f794/.editorconfig#L5-L11)

 
| Setting | Value | Rationale |
|---|---|---|
| charset | utf-8 | Universal character encoding |
| end_of_line | lf | Unix-style line endings (Git normalizes on checkout) |
| indent_style | space | Consistent rendering across editors |
| indent_size | 4 | Default for most file types |
| trim_trailing_whitespace | true | Prevents spurious diffs |
| insert_final_newline | true | POSIX compliance |

 
### Language-Specific Settings

 The configuration defines specialized rules for different file types:

 
| File Pattern | Indent Size | Notes |
|---|---|---|
| *.py | 4 spaces | Python PEP 8 standard |
| *.{cpp,hpp,cxx,cc,c,h,cu,cuh} | 2 spaces | C++ and CUDA files |
| *.rs | 4 spaces | Rust standard |
| *.go | tabs | Go standard |
| *.{yaml,yml,json} | 2 spaces | Configuration files |
| .clang-{format,tidy} | 2 spaces | LLVM config files |
| Makefile | tabs | Make syntax requirement |
| *.sh | 4 spaces | Shell scripts |
| *.bat | 4 spaces, CRLF | Windows batch files |
| *.md | 2 spaces | Markdown documents |
| *.rst | 4 spaces | reStructuredText |

 **Sources:** [.editorconfig13-48](https://github.com/deepseek-ai/LPLB/blob/0490f794/.editorconfig#L13-L48)

### Special Settings

 The configuration includes special directives for documentation files:

 
 - **Markdown files** (`*.md`): Set `x-soft-wrap-text = true` to enable soft wrapping in supported editors [.editorconfig41-43](https://github.com/deepseek-ai/LPLB/blob/0490f794/.editorconfig#L41-L43)
 - **reStructuredText files** (`*.rst`): Also enable soft wrapping [.editorconfig45-47](https://github.com/deepseek-ai/LPLB/blob/0490f794/.editorconfig#L45-L47)
 
 These settings improve readability for long-form documentation without affecting how the files are processed by documentation generators.

## .clang-format

 The `.clang-format` file defines C++ code formatting style for all C++ and CUDA source files. This configuration is applied automatically by the `clang-format` tool during pre-commit validation.

 
### Configuration

 The file contains a minimal configuration:

 
```
BasedOnStyle: LLVM
```

 **Sources:** [.clang-format1-2](https://github.com/deepseek-ai/LPLB/blob/0490f794/.clang-format#L1-L2)

 This directive bases all formatting rules on the LLVM coding standard, which includes:

 
| Style Element | LLVM Standard | Applied To |
|---|---|---|
| Indentation | 2 spaces | lplb/plugin.cpp, lplb/resources/minilp.cu |
| Brace style | Attach to control statements | All C++ control structures |
| Column limit | 80 characters | Line wrapping threshold |
| Pointer alignment | Right (int *ptr) | Pointer and reference declarations |
| Namespace indentation | None | Namespace blocks |

 
### Enforcement

 The `.clang-format` configuration is enforced through multiple mechanisms:

 
 - **Pre-commit hooks**: The `clang-format` tool runs automatically before commits [7.2](https://github.com/deepseek-ai/LPLB/blob/0490f794/7.2)
 - **Manual formatting**: Developers can run `clang-format -i` on modified files
 - **IDE integration**: Most IDEs (VS Code, CLion) automatically apply `.clang-format` rules

### LLVM Style Impact on LPLB Code

 The LLVM style particularly affects the following C++ and CUDA files:

 
 - **`lplb/plugin.cpp`**: The main C++ extension implementation
 - **`lplb/resources/minilp.cu`**: CUDA kernel template file
 
 The 2-space indentation matches the `.editorconfig` rule for C++ files [.editorconfig16-17](https://github.com/deepseek-ai/LPLB/blob/0490f794/.editorconfig#L16-L17) ensuring consistency between editor behavior and automated formatting.

## Configuration File Hierarchy

 The three configuration files form a layered system with different scopes:

 
```

```

 **Layer Responsibilities**

 
| Layer | Configuration | Timing | Enforced By |
|---|---|---|---|
| Version Control | .gitignore | On git add | Git |
| Editor Behavior | .editorconfig | On file open/save | Text editor |
| Language Style | .clang-format | On commit | Pre-commit hooks |
| Language Style | ruff (in pyproject.toml) | On commit | Pre-commit hooks |
| Type Checking | mypy (in pyproject.toml) | On commit | Pre-commit hooks |

 This hierarchy ensures that code is formatted correctly at edit time (via `.editorconfig`), validated before commit (via pre-commit hooks reading `.clang-format` and `pyproject.toml`), and only includes source files in version control (via `.gitignore`).

 **Sources:** [.gitignore1-10](https://github.com/deepseek-ai/LPLB/blob/0490f794/.gitignore#L1-L10) [.editorconfig1-48](https://github.com/deepseek-ai/LPLB/blob/0490f794/.editorconfig#L1-L48) [.clang-format1-2](https://github.com/deepseek-ai/LPLB/blob/0490f794/.clang-format#L1-L2)
