## Purpose and Scope

 This document provides a high-level overview of LPLB's three-layer architecture and explains how the major components interact to perform dynamic load balancing. The architecture consists of a Python API layer (user interface), a C++ compilation layer (kernel generation), and a CUDA execution layer (GPU computation).

 For detailed explanations of individual components, see:

 
 - Python layer implementation: [Python Layer Implementation](https://deepwiki.com/deepseek-ai/LPLB/5.2-python-layer-implementation)

### Layer 2: C++ Compilation

 
| Component | File | Responsibilities |
|---|---|---|
| compiled_solver class | csrc/plugin.cpp122-661 | C++ plugin exposed to Python via pybind11. Manages kernel compilation, caching, and launching. |
| compile_cubin() | csrc/plugin.cpp149-327 | Uses NVRTC to compile CUDA kernels at runtime, specialized for specific problem parameters. Links with cuSolverDx via NVJitLink. |
| prepare_module() | csrc/plugin.cpp329-352 | Loads compiled CUBIN into CUDA driver API, extracts kernel pointers, queries shared memory requirements. |
| solve() | csrc/plugin.cpp491-578 | Launches kernel_solve with appropriate grid/block configuration and arguments. |
| count_idx() | csrc/plugin.cpp580-600 | Launches kernel_count_idx to histogram expert indices. |
| map_idx() | csrc/plugin.cpp602-660 | Launches kernel_map_idx to map logical indices to physical indices based on LP solution. |

 **Key mechanism:** The `compiled_solver` uses a hash-based caching strategy [csrc/plugin.cpp203-244](https://github.com/deepseek-ai/LPLB/blob/0490f794/csrc/plugin.cpp#L203-L244) to avoid recompiling kernels with identical parameters. The cache key includes kernel source, compilation options, and problem dimensions.

## Runtime Compilation Flow

 LPLB uses a two-stage compilation strategy to balance build-time efficiency with runtime performance:

 
```

```

 **Key implementation details:**

 
 - **Build-time compilation** [setup.py](https://github.com/deepseek-ai/LPLB/blob/0490f794/setup.py): Compiles `plugin.cpp` into a Python extension module with optional NVSHMEM support.
 - **Hash-based caching** [csrc/plugin.cpp203-206](https://github.com/deepseek-ai/LPLB/blob/0490f794/csrc/plugin.cpp#L203-L206): Combines kernel source, compilation options, and problem parameters into a hash to create unique cache directory names.
 - **Cache collision detection** [csrc/plugin.cpp218-241](https://github.com/deepseek-ai/LPLB/blob/0490f794/csrc/plugin.cpp#L218-L241): Verifies both source code and compilation options match to prevent hash collisions from causing incorrect behavior.
 - **Template specialization** [lplb/resources/csrc-tmpl/minilp.cu21-26](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/resources/csrc-tmpl/minilp.cu#L21-L26): Kernels are compiled with specific `GROUP_SIZE`, `DUP_PER_RANK`, and `BLOCK_DIM` values, enabling aggressive compile-time optimizations.

## Summary

 The LPLB architecture achieves a clean separation of concerns through its three-layer design:

 
 - **Python layer** provides a user-friendly API and manages high-level coordination
 - **C++ layer** handles runtime compilation, caching, and efficient kernel launching
 - **CUDA layer** implements optimized GPU algorithms for counting, solving, and mapping
 
 This architecture enables LPLB to:

 
 - Generate specialized kernels for specific problem configurations
 - Cache compiled kernels to avoid recompilation overhead
 - Leverage NVIDIA's math libraries (cuSolverDx, cuBLASDx) through runtime linking
 - Support both single-node and multi-node distributed execution
 - Maintain clean interfaces between layers for testability and maintainability
