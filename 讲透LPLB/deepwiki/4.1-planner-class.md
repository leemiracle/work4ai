# Planner Class

  Relevant source files 
 - [lplb/__init__.py](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/__init__.py)
 - [lplb/planner.py](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/planner.py)
 
  The `Planner` class is the primary user-facing API for LPLB (Linear-Programming-Based Load Balancer). It orchestrates both static and dynamic load balancing operations for Mixture-of-Experts models by managing expert topology configurations, workload counting, linear programming optimization, and deterministic index mapping. This page documents the complete API reference for the `Planner` class, including its constructor, methods, and typical usage patterns.

 For conceptual explanations of static vs dynamic balancing, see [Core Concepts](https://deepwiki.com/deepseek-ai/LPLB/3-core-concepts). For implementation details of the underlying C++ extension and CUDA kernels, see [System Architecture](https://deepwiki.com/deepseek-ai/LPLB/5-system-architecture).

 
## Class Overview

 The `Planner` class serves as the main orchestrator that coordinates between three subsystems:

 
 - **EPLB (Expert Rebalancing)** - Handles static load balancing through expert reordering and replication
 - **CompiledSolver** - C++ extension that manages runtime-compiled CUDA kernels
 - **Distributed Communication** - Coordinates workload synchronization across ranks via PyTorch ProcessGroup or DeepEP

## Constructor

 
### `__init__`

 
```

```

 Initializes a new `Planner` instance with the specified expert topology configuration.

 
#### Parameters

 
| Parameter | Type | Description |
|---|---|---|
| redundant_to_original | torch.Tensor | Shape [group_size, num_redundants]. Mapping from redundant experts to their original indices. This matrix defines the expert redundancy topology. Each column represents a redundancy relationship, where experts across ranks share workload. See Topology Configurations for predefined topologies. |
| n_routed_experts | int | Total number of physical routed experts across all ranks, including redundant copies. Must equal ep_size * n_local_routed_experts. |
| n_logical_routed_experts | int | Total number of logical routed experts (without redundancy). Must equal ep_size * n_local_logical_routed_experts. |
| ep_size | int \| None | Total number of expert parallel ranks. If None, inferred from group.size(). Required if group is None. |
| group | ProcessGroup \| None | PyTorch distributed process group for expert parallelism. If None, no distributed workload reduction is performed (single-rank mode). |

 
#### Derived Attributes

 The constructor computes several derived attributes from the input parameters:

 
| Attribute | Type | Computation | Description |
|---|---|---|---|
| r2o | torch.Tensor | redundant_to_original.int().cuda() | Redundant-to-original mapping on GPU |
| o2r | torch.Tensor | r2o.argsort(dim=0).int().contiguous() | Original-to-redundant inverse mapping |
| group_size | int | r2o.shape[0] | Number of ranks in each redundancy group |
| num_redundants | int | r2o.shape[1] | Number of redundant expert pairs/groups |
| n_group | int | ep_size // group_size | Number of redundancy groups |
| n_local_routed_experts | int | n_routed_experts // ep_size | Physical experts per rank |
| n_local_logical_routed_experts | int | n_logical_routed_experts // ep_size | Logical experts per rank |
| combined_redundant_experts | int | (n_local_routed - n_local_logical) // num_redundants | Number of expert groups for LP solving |
| phy2log | torch.Tensor | Initialized by update_redundancy_mapping() | Physical-to-logical expert mapping |
| ep_group | ProcessGroup \| None | group | Stored reference to communication group |
| deep_ep_initialized | bool | False | Whether DeepEP integration is active |
| solver | CompiledSolver | Via _get_solver() | Cached C++ solver instance |

 
#### Redundancy Structure Requirements

 The `redundant_to_original` matrix must satisfy specific structural constraints for the LP solver:

 
 - **Uniform redundancy**: Each rank has the same number of redundant experts (`num_redundants`)
 - **Paired redundancy**: The i-th redundant expert on any rank must be a copy of the i-th expert on another rank within the same redundancy group
 - **Extensibility**: The actual number of redundant experts can be a multiple of `num_redundants`, allowing multiple redundant experts to be grouped together
 
 These constraints ensure that each redundant expert is shared between exactly two ranks, enabling the LP solver to compute optimal load distribution ratios.

## Methods

 
### `init_from_deep_ep`

 
```

```

 Initializes DeepEP integration for optimized distributed communication. This method should be called after a DeepEP `Buffer` has been created and before the first call to `solve_probs`.

 
#### Parameters

 
| Parameter | Type | Description |
|---|---|---|
| buffer | deep_ep.Buffer | DeepEP buffer instance providing optimized NVLINK and NVSHMEM communication primitives |

 
#### Behavior

 
 - Sets `deep_ep_initialized` to `True` to bypass standard PyTorch distributed operations
 - Calls `solver.init_comm()` with configuration derived from buffer settings: 
 - `use_ipc`: Determined by `not buffer.low_latency_mode`
 - `skip_nvshmem`: Determined by `buffer.num_rdma_bytes == 0`
 
 Once initialized, subsequent calls to `solve_probs` will use optimized DeepEP paths instead of `torch.distributed.all_reduce` for workload synchronization.

 **Sources:** [lplb/planner.py104-113](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/planner.py#L104-L113)

### `update_redundancy_mapping`

 
```

```

 Updates the physical-to-logical expert mapping based on historical workload statistics. This method integrates EPLB for static rebalancing and produces the mapping tensors required by the dynamic solver.

 
#### Parameters

 
| Parameter | Type | Description |
|---|---|---|
| workload | torch.Tensor \| None | Historical workload statistics with shape [n_logical_routed_experts]. If None, uses identity mapping without reordering. |

 
#### Returns

 Returns a tuple of three tensors:

 
| Index | Name | Shape | Dtype | Description |
|---|---|---|---|---|
| 0 | phy2log | [n_routed_experts] | int32 | Physical-to-logical expert mapping |
| 1 | log2phy | [n_logical_routed_experts, max_logcnt] | int32 | Logical-to-physical expert mapping (padded with -1) |
| 2 | logcnt | [n_logical_routed_experts] | int32 | Count of physical experts for each logical expert |

 
#### Algorithm

 The method performs the following steps:

 
 - **EPLB Rebalancing** (optional, if workload provided):

 
 - Calls `rebalance_experts()` to compute balanced expert-to-rank assignment
 - Reshapes result into `[n_group, group_size, n_local_logical_routed_experts]`
 - **Workload-Based Sorting** (optional, if workload provided):

 
 - On each device, sorts experts by workload in descending order
 - Ensures heavily-loaded experts are prioritized for redundancy
 - **Redundancy Selection**:

 
 - Selects top `combined_redundant_experts * num_redundants` experts per device
 - Creates redundant copies according to `r2o` matrix structure
 - Concatenates original and redundant experts to form `phy2log`
 - **Inverse Mapping Construction**:

 
 - Transposes `phy2log` and constructs `log2phy` mapping
 - Ensures original experts precede copies in the mapping
 - Pads with -1 for uniform tensor shape

### `count_workload`

 
```

```

 Counts the workload for each logical expert by histogramming the input indices. This method delegates to the compiled CUDA kernel `kernel_count_idx` via `CompiledSolver`.

 
#### Parameters

 
| Parameter | Type | Description |
|---|---|---|
| idx | torch.Tensor | Selected logical expert indices with values in [-1, n_logical_routed_experts). Value -1 is ignored. Shape is arbitrary (typically [batch_size, seq_len, top_k]). |
| n_sms | int | Number of CUDA streaming multiprocessors to use for parallel counting. Should match the GPU's SM count. |

 
#### Returns

 Returns a tuple of two tensors:

 
| Index | Name | Shape | Dtype | Description |
|---|---|---|---|---|
| 0 | local_workload | [n_logical_routed_experts] | Device-dependent | Global count of each logical expert |
| 1 | local_workload_by_sm | [n_sms, n_logical_routed_experts] | Device-dependent | Per-SM histogram (cumulative sum across SMs) |

 The per-SM histogram (`local_workload_by_sm`) is used by `weighted_select_target` to perform deterministic, SM-aware index mapping.

### `solve_probs`

 
```

```

 Solves the linear programming problem to compute optimal load distribution ratios between original and redundant experts. This is the core dynamic balancing operation.

 
#### Parameters

 
| Parameter | Type | Description |
|---|---|---|
| workload | torch.Tensor | Workload statistics with shape [n_logical_routed_experts]. Typically the output of count_workload. |
| avail_counter | torch.Tensor | Feasible solution counter with shape [1]. Used for validation and fallback logic. |

 
#### Returns

 Returns a tensor of shape `[num_redundants, combined_redundant_experts]` containing the load distribution ratio for each redundant expert pair/group. Values are in the range `[0, 1]`, where:

 
 - `ratio[i, j] = 0.0`: Send 100% of workload to redundant copy
 - `ratio[i, j] = 0.5`: Split workload 50/50 between original and redundant
 - `ratio[i, j] = 1.0`: Send 100% of workload to original expert
 
 
#### Distributed Coordination

 The method performs workload synchronization based on the configuration:

 
 - **If DeepEP initialized** (`deep_ep_initialized == True`):

 
 - Uses optimized NVLINK/NVSHMEM communication via DeepEP buffer
 - Synchronization handled internally by `solver.solve()`
 - **If standard PyTorch distributed** (`ep_group != None` and `deep_ep_initialized == False`):

 
 - Clones workload tensor
 - Performs `torch.distributed.all_reduce` on cloned tensor
 - Passes synchronized workload to `solver.solve()`
 - **If single-rank mode** (`ep_group == None`):

 
 - No synchronization performed
 - Uses local workload directly

### `weighted_select_target`

 
```

```

 Maps logical expert indices to physical expert indices using the load distribution ratios computed by `solve_probs`. This method performs deterministic, SM-aware routing to ensure balanced workload distribution.

 
#### Parameters

 
| Parameter | Type | Description |
|---|---|---|
| idx | torch.Tensor | Selected logical expert indices (same tensor passed to count_workload). Values in [-1, n_logical_routed_experts). |
| o_weight | torch.Tensor | Load distribution ratios with shape [num_redundants, combined_redundant_experts]. Output of solve_probs. |
| local_workload_by_sm | torch.Tensor | Per-SM workload histogram with shape [n_sms, n_logical_routed_experts]. Second output of count_workload. |
| n_sms | int | Number of streaming multiprocessors. Must match the value used in count_workload. |

 
#### Returns

 Returns a tensor with the same shape as `idx`, containing physical expert indices in the range `[-1, n_routed_experts)`. Value `-1` in the input is preserved as `-1` in the output.

 
#### Deterministic Routing

 The mapping is deterministic based on the per-SM cumulative workload. For each logical expert that has redundancy:

 
 - Computes the cumulative count of tokens routed to this expert up to the current SM
 - Compares this count against the threshold determined by `o_weight[i, j]`
 - Routes to original expert if count is below threshold, otherwise routes to redundant copy
 
 This ensures that the distribution matches the optimized ratios while maintaining determinism across the batch.

 **Sources:** [lplb/planner.py219-243](https://github.com/deepseek-ai/LPLB/blob/0490f794/lplb/planner.py#L219-L243)

## Solver Caching

 The `Planner` uses a module-level LRU cache to reuse `CompiledSolver` instances across multiple `Planner` instantiations with the same configuration parameters. This avoids redundant kernel compilation.

 
```

```

 The cache key consists of all parameters that affect kernel specialization. The `ProcessGroup` object is included in the cache key, so different process groups will not share solver instances.
