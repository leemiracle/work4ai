# 06 · 注意力后端谱系：主后端/FMHA 库/七家稀疏算法的三层分派

## 角色定位

`tensorrt_llm/_torch/attention/`（图谱 759 节点）是 PyTorch 后端的算力心脏，分三层：通用后端层（AttentionBackend 契约+TRTLLM/FlashInfer/Vanilla）、FMHA 库层（fmha/ 11 个相位化后端+管理器）、稀疏算法层（sparse/ 七家）。改本目录前先读 ATTENTION_DEVELOPER_GUIDE.md。

## 内部结构

**契约与主后端**：`backends/interface.py`（1142 行）是核心契约——`AttentionMetadata`（backends/interface.py:67，巨型 dataclass：批调度/KV cache/稀疏元数据）与 `AttentionBackend`（backends/interface.py:1013，泛型基类，support_mla/fp4_kv 等能力探测）。`get_attention_backend`（backends/utils.py:33）按名字与稀疏参数选后端（回退 TRTLLM）。主后端 `backends/trtllm.py`（2775 行）内含约 1450 行元数据巨类；模块层 `mla.py`（2163 行）是 DeepSeek 系 MLA 全链（低秩压缩/吸收态/FP8 BMM 按 SM 切 CuTe DSL 与 torch bmm）；`attention.py` 管 QKV 权重并分派后端，附 `_helix_*` 做 Helix 上下文并行特化。

**FMHA 库层（fmha/）**：`interface.py` 定义 Fmha ABC 与 FmhaPhase 枚举；`phased.py` 的 PhasedFmha 把 forward 拆 run_context/run_generation，是 8 个后端共同父类；`init_fmha_libs`（fmha/registry.py:30）延迟 import（注释明言环切断点）构建 10 项注册表，`_parse_fmha_libs_env`（fmha/registry.py:63）解析 TLLM_FMHA_LIBS；`FmhaManager`（fmha/manager.py:301）的 `_select_non_mla`（:444）/`_select_mla`（:504）两级分派。特色成员：cute_dsl_mla（Blackwell MLA decode）、fp4_mla（NVFP4）、prims_ts（vendored 适配器）。

**稀疏算法层（sparse/，七家）**：`sparse/registry.py:33-43` 按 algorithm 分发，sparse/registry.py:113 补 glm_kpool——rocket/dsa/deepseek_v4/skip_softmax/minimax_m3/qsa/glm_kpool。集成靠 `MLASparseHooks`（sparse/hooks.py:38）与 `AttentionSparseHooks`（sparse/hooks.py:103），`prepare_sparse_runtime_params`（sparse/hooks.py:225）一次预测 sparse_kv/sparse_attn/block_sparse 给投机解码。重点三家：

- **RocketKV**（rocket/）：`kernels.py` 1787 行（wc -l 实证）Triton 全集——QK 分裂/KT cache 更新/分页 KT BMM/双调 argsort/直方图 topk 20+ 组 kernel 对；backend.py 双实现：RocketTrtllmAttention 与 RocketVanillaAttention（CPU 参照）。
- **QSA**（qsa/）：`kernels.py` 2257 行（本批最大）——预索引器、Gemma norm+RoPE 融合、分页稀疏 GQA、MTP topk 复用；`QSAIndexer`（qsa/indexer.py，598 行）；qsa/module.py 748 行编排全链。
- **MiniMax-M3**（minimax_m3/）：**前三层层混合实证**——trtllm_gen_dense_decode.py:3 docstring "trtllm-gen decode attention for MiniMax-M3's dense layers (0-2)"，稠密前三层走 trtllm-gen 全因果路径（:314 注释 M3 dense layers are fully causal），其余层块稀疏。**MSA 双后端**：`MiniMaxM3MsaSparseAttention`（msa_backend.py:1219，继承 TrtllmAttention，1553 行）与 `MiniMaxM3SparseRuntimeBackend`（triton_backend.py:896，继承 AttentionBackend，1196 行，Triton 全链参照）。选块在 `MsaIndexer`（msa_indexer.py:208）；cache_manager.py 让 draft/target 共用 KV 池。

其余四家：DSA（dsa/indexer.py 2136 行 TopK；两段式 custom op：Op1 投影可捕获+Op2 注意力不捕获）、DeepSeek-V4（footer_scale_kv.py 每 token 584B=448 FP8+64 BF16 RoPE+7 UE8M0 scale+1 填充，与 C++ 逐位对齐）、skip_softmax（params.py 400 行 SkipSoftmaxFormula 阈值缩放，可从 checkpoint 配置解析）、glm_kpool（GLM-5.3 NoPE 池压缩，CUDA graph 安全）。

## 外部连接

- 上游：TorchLlmArgs.attn_backend（01 篇）与五家稀疏配置（llm_args.py:736/858/1093/1341）进 registry 分发；模型层经 MLASparseHooks 注入算法逻辑（02 篇 DSV4Hooks），避免 mla.py 堆 per-model 分支。
- 下游：预测钩子直连投机解码（04 篇）；KV 二进制契约（584B footer-scale、656B inline-scale）钉进 KVCacheManagerV2 与 C++ thop。

## 数据流

每步 forward：模型层 Attention → get_attention_backend 选系 →（非稀疏）FmhaManager 按层选 FMHA 库跑 context/generation 相位；→（稀疏）按 algorithm 选 cache manager+后端 → indexer 选块（RocketKV KT 分数排序/QSA 压缩/M3 maxscore topk/V4 压缩坐标）→ 块表/掩码写入 AttentionMetadata → 稀疏 kernel 执行 → 输出回模型层。KV 写入统一量化打包（584B/656B）。

## 设计决策

1. **三层分派各管一事**：名字级管 kernel 来源、FMHA 层管相位化选择、algorithm 级管稀疏语义——新算法只挂第三层。
2. **环切断是显性工程**：fmha/registry 与 sparse/registry 的延迟导入都有注释钉版。
3. **二进制契约跨语言钉死**：584B/656B 布局与 C++ cache_scale_type 逐位对齐，改动两侧同步。
4. **参照成对存在**：RocketVanilla、triton_backend 提供正确性对照。
