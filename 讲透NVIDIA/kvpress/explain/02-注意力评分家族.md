# 02 · 注意力评分家族：从观测权重到免前向近似

## 角色定位

注意力评分系是 kvpress 七文件家族（图谱 LL05），共同信念：**注意力质量可以当 KV 重要性代理**。谱系从"最贵最准"到"最省近似"排布：ObservedAttention 直接用观测注意力权重，ExpectedAttention 用几何量免前向近似，CriticalKV 加输出投影修正，DuoAttention 区分头类型，Finch/NonCausal 用问题信号与双向分块。它们全部回答同一个问题：不跑完整前向，怎么知道哪些 KV 会被将来的 query 用到。

## 内部结构

**ObservedAttentionPress**（`kvpress/presses/observed_attention_press.py:14`，ScorerPress 子类）最直接：score（`kvpress/presses/observed_attention_press.py:34`）返回 attentions 张量聚合，代价是必须 `output_attentions=True` 跑注意力矩阵（显存 O(L²)，长上下文不实用，定位是基准与教学）。**ExpectedAttentionPress**（`kvpress/presses/expected_attention_press.py:18`，score 在 `kvpress/presses/expected_attention_press.py:126`）：用 query/key 的 RoPE 前几何量（‖q‖‖k‖ 与相对位置衰减）估计注意力质量，完全免前向；统计版 ExpectedAttentionStatsPress（`kvpress/presses/expected_attention_with_stats.py:22`）配 ExpectedAttentionStats 模块（`:108`，PyTorchModelHubMixin 可发布到 HF Hub）采集真实分布校准近似，patch_rotary_embedding（`:142`）临时换 rotary 实现捕获 query（`:230` 消费）。**CriticalKVPress**（`kvpress/presses/criticalkv_press.py:18`）两阶段：先评分粗压，再用 Wo@values 的输出投影加权值通道（docstring `:20-23`）；同文件 CriticalAdaKVPress（`:101`）与逐头分配结合。**DuoAttentionPress**（`kvpress/presses/duo_attention_press.py:32`，BasePress 子类）混合头：retrieval 头全保、streaming 头只留 sink+recent（`:34-38`），on_the_fly_scoring 开关（`kvpress/presses/duo_attention_press.py:66` 默认 False，`:80` 消费）支持在线推理模式。**FinchPress**（`kvpress/presses/finch_press.py:18`，BasePress 子类）要求 `context + delimiter + question` 输入格式（`:23`），用问题 token 的注意力做重要性引导——评分发生在看到问题之后。**NonCausalAttnPress**（`kvpress/presses/non_causal_attention_press.py:18`）打破因果掩码，用全序列双向 chunk attention 做重要性信号。

## 外部连接

整族的 query 供给来自 `kvpress/utils.py` 的 get_query_states（`:57`）/get_prerope_query_states（`:13`）；关键的"无 query 前向也能拿权重"魔法在 `kvpress/attention_patch.py`：search_hyperplane（`:8`）给 key 张量找分离超平面 Y，使超平面侧的 query 注意力权重被偏置为约零，attention_patch（`:51`）包装 attention 函数消费该掩码，patch_attention_functions（`:98`）在 import kvpress 时全局生效——观测权重的"假通道"。评分家族与预算家族互通：PyramidKVPress 继承 SnapKVPress 只换逐层预算（`kvpress/presses/pyramidkv_press.py:17`），证明"评分"与"预算分配"是正交维度。

## 数据流

以 ExpectedAttention 为例：prefill 时 forward_hook 拿到该层 keys/values → score 用 q·k 几何量+位置衰减算每 token 分 → compress 模板 topk 保留 → 压缩后的 cache 进入解码。DuoAttention 路线不同：它不走 score/topk，而是给每个头贴"retrieval/streaming"标签，streaming 头的 cache 直接按 sink+窗口截断——head 级掩码靠 `kvpress/__init__.py` 导入时打的 attention 补丁生效。Finch 则把问题 token 拼进 context 尾部再评分，delimiter（`kvpress/presses/finch_press.py:23`）防止问题内容污染被压缩侧。

## 设计决策

三个决策：①精度-开销谱系完整保留而非只留最优——ObservedAttention 是上限参照，ExpectedAttention 是工程折中，对比本身有研究价值；②统计版把"近似误差"显式化成可校准分布（Hub 可发布的统计模块），比黑盒调参诚实；③DuoAttention 坚持头级粒度而非 token 级——retrieval/streaming 的区分在头维度最稳定，token 维度噪声大。
