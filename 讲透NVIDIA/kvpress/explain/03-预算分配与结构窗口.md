# 03 · 预算分配与结构窗口：token/头/层/通道四维的取舍

## 角色定位

图谱 LL07+LL08 两族回答两个正交问题。**预算分配系**（8 文件）：总预算定了，token 维（TOVA/SnapKV）、头维（AdaKV/LUKV）、层维（PyramidKV）怎么分才最优？**结构窗口系**（8 文件）：不细打分，直接按结构剪——sink+滑窗、均匀分块、通道丢弃、解码期合并。两者合看，KV 压缩的"分母"从 token 数扩展成 token×头×层×通道四维预算空间。

## 内部结构

预算分配系：**SnapKVPress**（`kvpress/presses/snapkv_press.py:18`，score `:69`）是教科书实现——用末窗（observation window）attention 模式给全部 KV 打分，假设"近期关注的模式代表全局"；**TOVAPress**（`kvpress/presses/tova_press.py:16`，score `:35`）在线逐 token 最优值注意力——不需要预知问题，解码时动态评分；**PyramidKVPress 继承 SnapKVPress**（`kvpress/presses/pyramidkv_press.py:17`）只覆写 get_layer_budget（`:47`）按层数分摊浅层多留深层少留（`:106` 消费）——继承即组合的最小样例；**AdaKVPress**（`kvpress/presses/adakv_press.py:15`，BasePress 子类，compression_ratio property `:47/:51`）逐头非均匀分配，头级掩码依赖 import 时的 attention 补丁；**LUKVPress**（`kvpress/presses/lukv_press.py:40`）逐头预算可学习，load_budget_curve 从远端装载预算曲线（`:33`，`:93` 逐模型加载）；LagKV（`kvpress/presses/lagkv_press.py:14`）滞后窗口相对注意力；Cap（`kvpress/presses/cap_press.py:16`）上下文感知先验；SimLayerKV（`kvpress/presses/simlayerkv_press.py:17`）层间相似性。结构窗口系：**StreamingLLMPress**（`kvpress/presses/streaming_llm_press.py:14`）是 ScorerPress 的优雅用法——score（`:38`）把 sink 段与滑窗外打 0（`:52`），纯窗口语义零评分成本，n_sink 默认 4（`:36`）；**ChunkPress**（`kvpress/presses/chunk_press.py:14`）均匀分块各留固定比例；**ChunkKVPress**（`kvpress/presses/chunkkv_press.py:14`）语义分块+块内聚类联合排序（`:20`），熵门控变体 EntropyGatedChunkKVPress 继承之（`kvpress/presses/entropy_gated_chunkkv_press.py:16`，高熵块少压）；**ThinKPress**（`kvpress/presses/think_press.py:15`）压 key 通道维（`:33-34` ratio 语义=删除通道比例）——与 token 维正交的另一半战场；**CAMPress**（`kvpress/presses/cam_press.py:25`）继承 DecodingPress 在解码期合并相似 KV 而非丢弃；CompressionRatioDecodingPress 解码期固定比例；RandomPress（`kvpress/presses/random_press.py:15`）随机对照基线。

## 外部连接

预算系大量复用评分基建：SnapKV 的 score 消费 get_query_states/get_prerope_query_states（`kvpress/utils.py:57/:13`）与 extract_keys_and_values（`:150`）；AdaKV/LUKV 的头级操作依赖 `kvpress/attention_patch.py:98` 打的全局补丁（head-wise key masking）。窗口系与组合器天然亲和：KeyRerotationPress（`kvpress/presses/key_rerotation_press.py:17`）给任何"剪 token"的 press 补 RoPE 重旋转；MergingPress（`kvpress/presses/merging_press.py:19`）把丢弃改合并；BlockPress（`kvpress/presses/block_press.py:15`）块级保留——三者可包本族任意策略。ThinK 与 token 维策略正交可叠加（通道+token 双压）。

## 数据流

两条代表性链路。SnapKV 链：context 尾部拼 observation window → prefill forward_hook 拿末窗 attentions → 对全序列评分 → topk 截断。AdaKV 链：每头独立评分 → 按头预算解分配（贪心保高分头）→ masked_key_indices 写入 attention 掩码 → 补丁化的 attention 函数在生成时跳过被掩 key。ThinK 链：score 评的是通道显著性 → 整通道 gather 而非整 token——剪完 key 形状变短，RoPE 不受影响（这是它免 rerotation 的原因）。

## 设计决策

三个亮点：①PyramidKV 用"继承+单方法覆写"表达"同评分、异预算"——最小差异编程的范例；②StreamingLLM 把窗口法编译成评分法——所有窗口策略免费获得 ScorerPress 的组合能力；③ThinK 证明压缩空间是四维的（token/头/层/通道），本库是少数把四维都做齐的开源实现。
