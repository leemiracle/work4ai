# 01 · 三层基类体系：BasePress / ScorerPress / DecodingPress

## 角色定位

`kvpress/presses/` 下 47 个 Press 类全部长在一棵三层继承树上：BasePress 是公共祖先（钩子挂接+压缩入口），ScorerPress 把"评分→排序→保留"抽成模板方法供 20+ 策略复用，DecodingPress 抽象解码期压缩（缓冲+周期触发）。这套设计的意义：新策略只需实现一个 score 函数或覆写一个 compress，钩子管理、ratio 语义、模型兼容检查全部由基类承包。入口管线 KVPressTextGenerationPipeline（`kvpress/pipeline.py:25`）把 press 当普通参数传。

## 内部结构

**BasePress**（`kvpress/presses/base_press.py:44`）：三件套——post_init_from_model（`:55`，从模型反推配置）、compress（`:61`，子类覆写）、forward_hook（`:101`，拿到 attention 层输出后压缩 KV）。生命周期由 `__call__` contextmanager 管理（`:165`）：进入时给每层 `layer.self_attn.register_forward_hook(self.forward_hook, with_kwargs=True)`（`:203`），退出时摘钩子。模块级 is_prefilling（`:37`）用 `cache_position[-1]+1 == q_len` 判定是否 prefill。模型兼容性是白名单告警制：SUPPORTED_MODELS 覆盖 Llama/Mistral/Phi3/Qwen2/Qwen3/Gemma3（`:27-33`），不在名单只打 warning 不拦截（`:188-189`）。**ScorerPress**（`kvpress/presses/scorer_press.py:18`）：score 抽象方法（`:36`）输入 module/hidden_states/keys/values/attentions/kwargs，输出每 token 分数；compress（`:77`）是模板方法——ratio==0 直通（`:87`）→ score → compute_n_kept → `scores.topk(n_kept)`（`:96`）→ gather 剪枝 keys/values。断言 0≤compression_ratio<1（`:34`）。**DecodingPress**（`kvpress/presses/decoding_press.py:23`）：面向 CAM/CaM 类解码压缩——`__post_init__`（`:50`）建 per-layer 隐状态缓冲（defaultdict，`kvpress/presses/decoding_press.py:53`，buffer 默认 256 条 `:48`），post_init_from_model（`:65`）从模型拿层数/head 配置，compress（`:68`）周期触发压缩并保持 KV 与位置一致性，reset（`:181`）在生成间复位；`__call__`（`:187`）不挂 prefill 钩子而是持续观察解码步，_find_target_compression_ratio（`:194`）把"目标 token 数"反解为 ratio。

## 外部连接

上游是 transformers：BasePress 直接操作 DynamicCache（extract_keys_and_values `kvpress/utils.py:150`），量化缓存走 dequantize_layer（`kvpress/utils.py:131`）。`import kvpress` 触发全局 monkey-patch——`kvpress/__init__.py` 调 patch_attention_functions()（`kvpress/attention_patch.py:98`）改写 transformers 的 ALL_ATTENTION_FUNCTIONS 支持 head 级 key 掩码（AdaKV 前置条件），patch 对无 masked_key_indices 的模型透明。评分信号多来自 query：get_prerope_query_states（`kvpress/utils.py:13`）取 RoPE 前 query（pre-RoPE 几何更稳），get_query_states（`:57`）取 RoPE 后。下游消费：pipeline 的 _forward（`kvpress/pipeline.py:173`）在 prefill 时把 press 挂进模型；组合器（ComposedPress `kvpress/presses/composed_press.py:12` 等）把基类实例再组合成新 press。

## 数据流

一次带压缩的生成：pipeline.preprocess（`kvpress/pipeline.py:105`）处理 chat 模板（无模板告警 `:140`、apply_chat_template `:146`）与 tokenization → `with press(model):` 进入 contextmanager 挂钩 → 模型 prefill，每层 attention 前向结束触发 forward_hook → hook 内 is_prefilling 为真则调 compress：ScorerPress 路径 score→topk→gather 改写 cache → 退出 with 摘钩 → 解码生成（DecodingPress 子类在此期间持续压缩）→ postprocess（`kvpress/pipeline.py:321`）组装答案。保留数的唯一口径在 compute_n_kept（`kvpress/utils.py:137`）：`max(1, int(k_len*(1-ratio)))`——ratio 是**删除比例**且永远至少留 1 个 token（防短上下文静默清空缓存）。

## 设计决策

四个取舍：①模板方法而非自由钩子——ScorerPress 把控制流焊死，策略只填评分函数，20+ 策略的行为因此可横向对比（leaderboard 的前提）；②ratio 语义统一为删除比例并钳位保底 1，跨策略可比；③钩子用 with_kwargs=True 的 forward_hook 拿新式 attention 签名（`base_press.py:203`），避免侵入模型源码；④兼容性告警不拦截（`:188`）——社区模型长尾太大，白名单只标"测试过"。
