# 03 · RPC 协议契约——CPU 侧 RM 与 GSP 固件 RM 的消息边界

> 仓库：NVIDIA open-gpu-kernel-modules 615.71.09 · 层：RM ctrl 与 SDK 公共头（图谱第 8 层）/GSP 固件与虚拟化（第 12 层）
> 本文行号锚全部源码核实（rpc.h / g_rpc-structures.h / rpc_global_enums.h / rpc_headers.h / g_rpc-message-header.h / kernel_gsp.c）

## ① 角色定位

GSP-RM 架构（Turing 及以后）把 RM 主体搬进 GSP 处理器固件，内核驱动里的 RM 只剩"物理 RM 代理"；两侧通过**共享内存队列上的版本化 RPC 消息**对话。本篇的"契约三巨头"就是这场对话的全部语法：

1. **src/nvidia/inc/kernel/vgpu/rpc.h**（595 行）——CPU 侧发起面：35 个 `NV_RM_RPC_*` 宏（ALLOC_MEMORY/MAP_MEMORY_DMA/CONTROL/FREE/UPDATE_BAR_PDE/INVALIDATE_TLB...），把每个 RM 关键动作包装成一次 RPC 往返；
2. **src/nvidia/generated/g_rpc-structures.h**（12367 行）——消息体全集：219 个 `rpc_*` 结构 typedef、66 个互异的 `_vXX_YY` 版本后缀，由内部模板 `inc/kernel/vgpu/gt_rpc-structures.h` + 定义 `inc/kernel/vgpu/rpc-structures.def` 生成（两文件均不在本仓，g_rpc-structures.h:23-27 注释明言 autogenerated）；
3. **src/nvidia/inc/kernel/vgpu/rpc_global_enums.h**（308 行）——命令号与事件号总表：X 宏展开的 `NV_VGPU_MSG_FUNCTION_*` 命令 233 条 + E 宏的 `NV_VGPU_MSG_EVENT_*` 事件（0x1001..0x102e）。

值得一提的是：rpc.h 路径在 vgpu/ 下，因为这套协议最初为 vGPU（宿主 RM↔客户 RM）设计，GSP-RM 沿用它作为"物理 RM↔固件 RM"通道——同一契约，三种部署形态（GSP、vGPU host、DCE client），rpc.h:124 的 `IS_DCE_CLIENT` 分支就是活证据。

## ② 内部结构

**发起宏的解剖**（NV_RM_RPC_ALLOC_MEMORY，rpc.h:113-152）：`GPU_GET_RPC(pGpu)` 取 OBJRPC → 条件门（SRIOV 虚拟化 + WAR200577889 + 非 MODS 时跳过，rpc.h:120-123）→ DCE client 走本地 `pRmApi->AllocWithHandle` 快路径（rpc.h:140-142）→ 否则 `rpcAllocMemory_HAL(pGpu, pRpc, ...)`（rpc.h:146-147）进 HAL 分发。宏统一以 `do{...}while(0)` 包裹、以 `status` 出参返回——所有调用点拿到 NV_STATUS。

**消息头**（g_rpc-message-header.h）：`rpc_message_header_v03_00` = header_version/signature/length/function/rpc_result/rpc_result_private/sequence 八个 NvU32 + 柔性数组 `rpc_generic_union rpc_message_data[]`。版本协议钉死：头版本 3.0（`NV_VGPU_MSG_HEADER_VERSION_MAJOR_TOT 0x03`，rpc_headers.h:62-64），签名必须等于 `NV_VGPU_MSG_SIGNATURE_VALID 0x43505256`（rpc_headers.h:66，ASCII "CPRV"）。错误协议同样钉死：坏签名/坏长度时，收端把签名与长度"修回合法值"并回 `NV_VGPU_RESULT_INVALID_MESSAGE_FORMAT`，而签名、长度、function 三字段收端永不改动，result 必置（rpc_headers.h:46-52）。

**命令号表**（rpc_global_enums.h）用 X 宏惯用法：`X(UNIT, RPC, VAL)` 一行一条（rpc_global_enums.h:6），UNIT 取 RM/GSP/UVM 三类——例如 `X(RM, ALLOC_MEMORY, 4)`（rpc_global_enums.h:14）、`X(GSP, GSP_RM_CONTROL, 76)`（rpc_global_enums.h:86）、`X(UVM, UVM_PAGING_CHANNEL_ALLOCATE, 160)`（rpc_global_enums.h:160 段）。表头注释是 ABI 铁律："Deprecated RPC's numbers cannot be reused in order to not break compatibility"（rpc_global_enums.h:4）——废弃号永久占坑（ALLOC_DEVICE=3、BIND_CTX_DMA=8 等已 deprecated）。事件方向（GSP→CPU 通知）独立编码于 0x1000 段（如 `E(GSP_LOCKDOWN_NOTICE, 0x101c)`、`E(TRIGGER_BUGCHECK, 0x1023)`），到 `E(NUM_EVENTS, 0x102e)` 封口。

**版本化消息体**（g_rpc-structures.h）：每个命令对应 `rpc_<name>_vXX_YY` 结构 + 无版本 typedef 别名（如 `rpc_set_guest_system_info_v03_00`→`rpc_set_guest_system_info_v`，g_rpc-structures.h:36-48）。同一命令保留多个历史版本并行（rpc_alloc_object 有 v25_08/v26_00/v27_00/v29_06/v2B_04/v2C_01 六代，g_rpc-structures.h:100-158），收端按头版本号选择解释——这是永不破坏老固件兼容的代价与手段。结构体字段直接复用 SDK 参数（NV0000_ALLOC_PARAMETERS 等）。

## ③ 外部连接

- **上游**：NV_RM_RPC 宏被第 9-11 层（mem_mgr/fifo/mmu 等）直接内联调用——grep `NV_RM_RPC_` 可见全 RM 的 GSP 拦截面；
- **下游（发送）**：OBJRPC（src/nvidia/src/kernel/gpu/rpc/objrpc.h）封装队列；GSP 模式下 `rpcSendMessage_FNPTR(pRpc) = _kgspRpcSendMessage`（src/nvidia/src/kernel/gpu/gsp/kernel_gsp.c:3553）在 kgsp 构造时挂接函数指针，RPC 消息经共享内存环形队列（GSP RPC queue）投递；
- **g_rpc 族其他生成物**：g_rpc_hal.h（HAL 原型）、g_rpc_iom.c/g_rpc_odb.h（内联对象方法）、g_rpcstructurecopy_*（结构深拷贝生成器）——消息体含指针时按字段复制，杜绝裸 memcpy；
- **vGPU 复用**：rpc_vgpu.h/vgpu_events.h 同一套表驱动宿主-客户通信；VGPU_RESERVED_HANDLE_BASE 0xCAF3F000（rpc_headers.h:42）保留 handle 段；
- **结果码映射**：`NV_VGPU_MSG_RESULT_*` 直接别名 NV_STATUS（rpc_headers.h:71-75，"codes below 0xFF000000 must match exactly the NV_STATUS codes"），两侧错误语义一比一对齐。

## ④ 数据流

**出站（CPU→GSP）**：RM 内核代码 `NV_RM_RPC_ALLOC_MEMORY(...)` → OBJRPC 分配消息槽 → 填 `rpc_message_header_v03_00`（版本 3.0、签名 "CPRV"、function=NV_VGPU_MSG_FUNCTION_ALLOC_MEMORY=4、sequence 递增）→ 追加 `rpc_alloc_memory_v13_01` 体（g_rpc-structures.h:71-83）→ rpcSendMessage → GSP 固件 RM 执行真实分配 → 结果沿头结构回写 → CPU 侧按 sequence 匹配、取 status。
**入站（GSP→CPU 事件）**：固件发 0x1000 段事件号（如 NVLINK_FAULT_UP=0x101b、MIG_CI_CONFIG_UPDATE=0x101d）→ CPU 侧事件队列线程转成 RM 内部事件分发。
**尺寸约束**：消息缓冲约 4KB 上限的直接证据是 `VGPU_MAX_REGOPS_PER_RPC 100`（rpc_headers.h:37-39 注释明言 "RPC message buffer size being limited to 4k"）——超大批操作必须分片。

## ⑤ 设计决策

1. **宏而非函数**：NV_RM_RPC_* 全是 do-while 宏而非内联函数，好处是能在调用点自然短路（status 已非 NV_OK 时跳过）、并让每个调用点按上下文展开不同分支（如 IS_VIRTUAL_WITH_SRIOV 的 GPU 专属 WAR 判定内联展开）；
2. **版本号写进类型名**：_v03_00 后缀让"哪代驱动跟哪代固件说什么话"在编译期类型层面可见，收端按头版本 dispatch——代价是 12367 行巨表与 66 个版本变体并存；
3. **命令号即 ABI**：233 条命令号永不复用（含 deprecated），事件号独立段——从 vGPU 时代延续至今的兼容承诺；
4. **防御式收端协议**：签名/长度坏时强制修复并回错误（而非丢弃），保证发送方永远能拿到确定的失败结果，避免悬挂等待；
5. **一套协议三种部署**：GSP-RM/vGPU host/DCE 共用契约，rpc.h 内按 IS_DCE_CLIENT/IS_VIRTUAL 分流，减少协议分叉维护成本。

## ⑥ 新人提示

- 调一条 GSP 路径的顺序：rpc.h 找宏 → rpc_global_enums.h 找命令号 → g_rpc-structures.h 找消息体（注意版本后缀）→ kernel_gsp.c 找队列收发；
- 追加 RPC 字段的正确方式是新增 `_vXX_YY` 版本结构并保留旧版，绝不能改旧结构——老 GSP 固件二进制仍按旧布局解读；
- 消息体里看到内嵌指针字段就要想到 g_rpcstructurecopy 生成器：跨处理器边界后指针要由收端翻译成自身地址空间；
- 查协议行为时先读 rpc_headers.h 的注释块（46-66 行），它就是协议的"宪法条款"；
- 任务书称 g_rpc-structures.h 12367 行，源码实测一致（12367 行）；rpc.h 实际路径为 src/nvidia/inc/kernel/vgpu/rpc.h（非任务书所写 inc/api/rpc.h，本仓无 src/nvidia/inc/api/ 目录，以源码为准）。
