# 01 · IR 三根继承树：Statement / Val / Expr

## 角色定位

nvFuser 的全部中间表示长在同一棵继承树上，树根是 `csrc/ir/base_nodes.h`（722 行）里的三个类：Statement@94、Val@219、Expr@518。本仓图谱共提取 184 条 inherits 边，其中 Statement 子树 82 个类（81 对父子关系），从 UnaryOp、ReductionOp 一直覆盖到 kir::ForLoop。这一层不定义任何具体算子，只回答四个问题：节点如何被创建（passkey 工厂）、如何判等（sameAs/sameDefinition）、如何运行时分发（dispatch）、如何求值（evaluate）。它是整个编译器"约 200 个节点类型的祖先"（图谱摘要语），读懂它就拿到了 IR 侧一切文件的公共词汇表。

## 内部结构

Statement 继承 NonCopyable 与 PolymorphicBase（base_nodes.h:94），只允许移动不允许拷贝；它提供静态 dispatch 模板（:103 起，实现于 dispatch.cpp）、isVal/isExpr 判断与 asVal/asExpr 收窄。Val@219 携带 vtype_/dtype_/value_ 三元组（value_ 是 PolymorphicValue），isSymbolic() 区分"符号值"与"已绑定常量"；def-use 链是 SSA 式的：一个 Val 只有一个定义 definition()（:354，setDefinition@410），但可有多个使用（addUse@440 / removeUse@444，私有成员 definition_@461、uses_@462）。Expr@518 持有 inputs/outputs/attributes；比较语义分三级——sameOp（不比输入）、sameDefinition（输入用 sameDefinition 比）、sameAs（:536 起声明）。evaluate 协议有两个重载（:553 与 :564）：前者单算子求值，后者允许 CatOp 这类算子跳过中间输入做多算子联合求值，是常量折叠的执行点。

## 外部连接

向上被 builder.h:31 的 IrBuilder 消费：create\<T\>@36 从 FusionGuard::getCurFusion() 取当前容器并登记，SimplifyingIrBuilder@169 覆盖 30 余个工厂函数、建节点的同时做代数化简。构造入口由 builder_passkey.h:16 的 IrBuilderPasskey 把守——只有 friend class IrBuilder（:17）能构造该 key，因此所有 IR 节点构造函数第一参都是 passkey，绕过登记的 new 在编译期就不可能。向下由 container.h:31 的 IrContainer 管理：vals/exprs 双 deque 保序（deterministic_vals@54 / deterministic_exprs@57），所有权在 unique_ptr 池（vals_up_@155）；Fusion 与 Kernel（kernel.h:222，Kernel final : public Fusion）都是它的派生容器。分发靠 dispatch.h:221 OptOutConstDispatch 与 :247 OptOutDispatch（宏表驱动），深克隆靠 cloner.h:32 的 IrCloner。Val 的五个直接子类是树的第一次分叉：TensorView（interface_nodes.h:380）、IterDomain 与 TensorDomain（internal_base_nodes.h:92/:535）、NamedScalar（internal_nodes.h:2083）、host_ir 的 Stream；Expr 则有 74 个直接子类，分布在 internal_nodes.h（43 个）、composite_nodes.h（14 个）、host_ir/ir.h（16 个）与 expr_simplifier.h:171 的 FlattenedAssocCommOp。

## 数据流

用户在 ops/arith.cpp 调用算子函数 → IrBuilder::create\<T\> 在 FusionGuard 当前 Fusion 中登记节点 → Expr 构造时把输出 Val 的 definition_ 指回自己、并把自己 addUse 进输入 → 遍历器（iter_visitor）沿 def-use 链拓扑行走 → segmenter/cloner 复制切分 → lower 后同一套 Statement 体系迁入 Kernel。接入新节点的"操作手册"直接写在头注释里：新增 Val 六步（base_nodes.h:210-218），新增 Expr 八步（:500-517）——dispatch 宏表、mutator、graphviz、type 枚举与字符串表逐项同步，漏一步就会在运行时 unhandled。

## 设计决策

三根而非两根：Statement 是运行时异构传递点（容器里混装 Val/Expr），Val/Expr 各自垂直分化，避免到处 dynamic_cast。passkey 工厂强制"创建即登记"，容器视图永远完整，这是后续 deterministic 遍历与克隆正确性的前提。判等三级分离是为调度分析服务的：sameAs 严格（算子+输入全等），sameDefinition 宽松（输入同构即可），IdModel 等价类分析大量依赖后者。另一个工程事实：三个根类声明都带 `class NVF_API` 宏前缀（定义在 visibility.h:15-20，Windows dllexport / ELF visibility），这正是 tree-sitter 的提取盲区——图谱中三根类是批次分析手工补齐的（NOTES-DIGEST batch-5 甄别），全仓约 50 处 NVF_API 前缀类声明同受影响。

## 新人提示

第一步只读 base_nodes.h 的类声明与两段"新增节点清单"注释，不必陷入实现。查具体算子时记住四处分流：标量/形状类算子在 internal_nodes.h，高层数学算子（MatmulOp/SdpaFwd 等）在 composite_nodes.h，设备侧节点在 kernel_ir.h，host 侧在 host_ir/ir.h。调试打印用 operator\<\<（base_nodes.h:719）与 toString(indent)。做等价判断前先想清楚该用 sameAs 还是 sameDefinition，两者混用是新手最常见 bug 源。图谱消费提示：凡 lineRange 为 [1,2] 的补建类节点（如 Selector）行号不可信，引用前回源码核对。
