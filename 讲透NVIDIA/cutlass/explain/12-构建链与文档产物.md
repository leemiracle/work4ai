# 12 · 构建链与文档产物：CMake 骨架、Python 载荷与 Sphinx 化石层

## 角色定位

本篇收拢三条支撑线：仓根 CMake 构建链（CMakeLists.txt 1223 行+cmake/+顶层工具 cmake）、Python 发布载荷（四个现役包的打包/版本/命名考古）、文档产物层（python/docs/ 的 Sphinx 快照与断链）。它们是新人最先撞到、也最易误读的部分——大量"看似错误"的引用实为构建期生成或历史遗存。

## 内部结构

**仓根 CMakeLists.txt**（1223 行）：`CMP0112 NEW`（CMakeLists.txt:30）、`cutlass_LOADED` 守卫防重复 fetch（CMakeLists.txt:32-36）、`CUTLASS_VERSIONS_GENERATED` 宏注入编译旗标（CMakeLists.txt:265-266）、configure_file 把 cmake/version_extended.h.in 生成到构建目录 include/cutlass/version_extended.h（CMakeLists.txt:759-760）、`CUTLASS_CTEST_TEMPLATE_FILE` 指向 ctest 模板（CMakeLists.txt:870），以及 file(READ) 内联 per-test 代码模板（CMakeLists.txt:959）。**勘误锚**：include/cutlass/version.h:46 条件包含 version_extended.h——该头仓内不存在，缺省回落 `CUTLASS_BUILD 0`（version.h:48）；版本真值 4.8.0 在 version.h:41-43。

**cmake/ 七件**：CTestTestfile.configure.cmake（按测试组生成 CTestTestfile.cmake）与 CTestTestfile.test.configure.cmake（被 L959 内联）；googletest.cmake 钉 v1.14.0 且 EXCLUDE_FROM_ALL 不进默认目标；**nop.cu 是全仓零引用的探测样本**（供手动/外部工具探 CUDA 工具链）；NvidiaCutlassConfig.cmake.in/NvidiaCutlassPackageConfig.cmake 供安装消费；version_extended.h.in 即上段生成源。

**顶层工具 cmake**：CUDA.cmake 的 unity 批文件名取内容 SHA256 前 12 位保证确定性，clang 设备编译要求 CMake≥3.30；cuBLAS.cmake/cuDNN.cmake 各自封装依赖发现；bin2hex.cmake 以定界符 abc1ae6e1e82e3de 防内容碰撞（消费方 test/unit/nvrtc）；customConfigs.cmake:48-52 调第 11 篇 generator。

**Python 载荷**：现役四包 CuTeDSL/cutlass_cppgen/cutlass_library/pycute（+仓根 operators 第五包）。**命名考古**：python/README.md 明言 cutlass_cppgen 前身名就是 cutlass——这解释了 python/docs/ 旧文档树 cutlass.emit/cutlass.op/cutlass.utils 与新包名的错位（是整体更名非删除，模块一一对应）；setup_cutlass.py 的三处死导入（copy L34/os L35/build_ext L38 未用）与"文件名 setup_cutlass/产物名 cutlass_cppgen"不一致均为迁移残迹。**版本三条线**：根 pyproject.toml:7 是 4.2.0.0（落后 C++ 4.8.0，轮子版本独立维护）；CuTeDSL 的 pyproject 用 dynamic version 指向 VERSION.EDITABLE（pyproject.toml:18/29）——该文件 git 检出中不存在，由发布管线生成，源码树直接 pip install 会失败，必须走 setup.sh 或轮子；setup.cfg 的 exclude_package_data 再剔载荷中的 .py——C++ 模板资产是轮子体积大头。

**文档化石层**：python/docs/ 整目录是 v3.x 世代 Pythonic 接口（import cutlass）的 Sphinx 构建快照——_modules/ 六页与现 cutlass_cppgen 源相似度 0.36-0.79（op/op.py 最陈旧）；python/docs_src/source/ 是其文档源，index.rst:6 以 include 指令渲染 ../../README.md（README 是站点首页唯一真源）；externals/*.nblink 指向的 notebook 已迁 examples/python/deprecated/——**断链由 conf.py 的 nbsphinx_allow_errors=True 构建期容忍**；_static/ 四个 CSS 未被任何页面引用（主题随带历史资产）。python/docs/externals/00_basic_gemm.ipynb 的 `import cutlass` 顶级包与 CuTeDSL 的 cutlass 包同名——包名解析歧义使快照误连到 CuTeDSL 线。

## 外部连接

构建链向上接 CUDA Toolkit/NVML/cuBLAS/cuDNN 四依赖（cuBLAS.cmake/cuDNN.cmake）；CTest 模板接 test/ 目录海量单测的注册（generated by generator.py 的清单，第 11 篇）；Python 载荷接 PyPI 发布管线与 cuda-python 对齐约束（源码安装要求 CUDA Toolkit 与 cuda-python 大小版本对齐，docs_src install.md 钉版）。许可证三色：根 LICENSE.txt 与 cutlass_compiler/LICENSE.txt 均 BSD-3-Clause（仅版权年份行不同，diff 验证；grep "Apache" 零命中——勘误"Apache 许可"讹传）；CuTeDSL 与根 EULA.txt 双份专有许可逐字节相同。

## 数据流

配置期：CMakeLists.txt → 检测 CUDA → customConfigs.cmake 调 generator.py 生成 kernel 清单 → 模板实例化编译 → CTestTestfile 模板按测试组展开 → ctest 驱动。发布期：C++ 侧走 NvidaCutlassConfig 安装；Python 侧 CuTeDSL 轮子由发布管线生成 VERSION.EDITABLE 并打包（剔除 .py 只留模板资产），cutlass_cppgen 走 setup_cutlass.py。文档期：docs_src + README.md + nbsphinx（容忍断链）→ python/docs/ 静态站——但当前快照已是化石，勿按其 API 写新代码。

## 设计决策

1. **版本头构建期生成**（version.h:46）：源码树可独立编译（缺省 BUILD=0），构建树携带完整版本——代价是"grep 不到 version_extended.h"的困惑，靠 CMakeLists.txt:759 configure_file 解释。
2. **SHA256 命名 unity 批**（CUDA.cmake）：同内容必同名，ccache 命中率最大化。
3. **旧文档快照保留而非删除**：v3.x 用户仍需离线文档；README 明示更名史避免误读。
4. **EULA 双份专有**（CuTeDSL）：DSL 商业组件与 BSD 核心分线发布，发布产物装配时各取各的。

## 新人提示

- 找不到 cutlass/version_extended.h 不是 bug：它是构建生成物（CMakeLists.txt:759-760）；查版本用 version.h:41-43。
- python/docs/ 的 cutlass.* API 全部已更名 cutlass_cppgen.*——写代码以 python/cutlass_cppgen/ 现源为准。
- 源码树装 CuTeDSL 用 setup.sh，别直接 pip install（VERSION.EDITABLE 不在 git）。
- cmake/nop.cu 零引用是故意的；同理 tools/util 大部被裁出分析范围，packed_stride.hpp 是该目录在图谱中唯一节点。
