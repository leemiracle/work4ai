# 06 · offline.py + client_utils.py + utils 工具线：离线评测入口与服务端配套

> 锚点基线：`moshi/moshi/offline.py`（431 行）、`client_utils.py`（213 行）、`utils/logging.py`（76 行）、`utils/connection.py`（228 行）、`moshi/pyproject.toml`。本篇覆盖服务端主线（01/05 篇）之外的全套工具层。

## ① 角色定位

`offline.py` 是 server.py 的"去网络镜像"：不架 WebSocket，从 WAV 读用户音频，跑同一套模型管线（Mimi×2 + LMGen），把 agent 音频与文本落盘。它承担三重角色：**离线评测/回归入口**（固定输入→固定输出对比，模型/依赖升级的验收基准）、**批量合成工具**、以及**服务端逻辑的可读参考实现**（module docstring 自述 "mirrors server.py behavior without a WebSocket server"，offline.py:28-40，还在开头列出六步高层流程）。配套三件：`client_utils.py` 本是 Kyutai 命令行客户端的终端渲染器；`logging.py` 给服务端会话染色的日志器（NVIDIA 增补）；`connection.py` 自举 TLS 证书（NVIDIA 增补）。`pyproject.toml` 的 `[project.scripts]` 注册 `moshi-server` 与 `moshi-offline` 两个控制台入口，后者即本篇主角。

## ② 内部结构

### offline.py

- 与 server.py 的四处**有意复刻**：`seed_all`（offline.py:66-80，同样 `cudnn.deterministic=False`）、`wrap_with_system_tags`（offline.py:83-90，与 server.py:79-86 逐字相同）、`warmup`（offline.py:93-110，注释明言 "Replicates the same warmup behavior as server.py"，offline.py:96）、`_get_voice_prompt_dir`（offline.py:125-150，server.py:312-338 的整段拷贝）——两边各自维护一份，改动需同步。
- `decode_tokens_to_pcm`（offline.py:113-122）：单步 token → `mimi.decode(tokens[:, 1:9])` → mono numpy，与 server.py:231-234 的 opus_loop 内层逐行对应。
- `run_inference`（offline.py:153-318）十二步流水（docstring 编号到 12 步，offline.py:181-320 注释逐段标号）：seed 判据 `seed != -1`（offline.py:182-183）→ 下载 config.json 刷计数（offline.py:187）→ 装双 Mimi + tokenizer + LM（offline.py:191-208，含 `cpu_offload` 透传）→ 构造 LMGen（offline.py:212-224，`use_sampling=not greedy/temp/temp_text/top_k/top_k_text` 五参全传 offline.py:219-223）→ `streaming_forever(1)` 三连（offline.py:226-228）→ warmup → 音色/文本提示词（offline.py:236-243，`.pt` 嵌入与 WAV 分流同 server）→ reset + **同步版** `step_system_prompts`（offline.py:250-255）→ `lm_load_audio` 读用户 WAV 重采样到模型采样率（offline.py:259）→ 逐帧循环（offline.py:267-295）：`lm_gen.step(step_in)` 位置参数即 `input_tokens` 用户通道（offline.py:279），文本 token 按 (0,3) 过滤、此处**真的用上** `text_token_map`（offline.py:286-295）→ 空帧守卫（offline.py:297-299）→ 输出裁剪/补零对齐输入时长（offline.py:301-309）→ `sphn.write_wav` 写 mono WAV + json.dump 写文本数组（offline.py:312-318）。
- `main`（offline.py:321-427）：`--input-wav/--output-wav/--output-text` 三必填（offline.py:326-334）；默认文本提示词 "You are a wise and friendly teacher..."（offline.py:335）；**采样参数齐全**：`--temp-audio`(0.8)/`--temp-text`(0.7)/`--topk-audio`(250)/`--topk-text`(25)/`--greedy`/`--seed`(-1)（offline.py:362-383）——server.py 注释冻结的那四个旋钮（server.py:143-146）在离线版全部开放；`--cpu-offload`（offline.py:380-382）与 `torch.no_grad()` 包裹（offline.py:407）。

### client_utils.py（Kyutai 原版遗产）

- `colorize`（client_utils.py:11-14）与 `make_log`（client_utils.py:17-26）：ANSI 染色与 [Info]/[Warn]/[Err] 前缀——server.py:48 与 offline.py:55 只进口这两个函数。
- 两代渲染器：`RawPrinter`（client_utils.py:29-49）裸写 token，`print_lag` 打红色 [LAG]（client_utils.py:44-46）；`Printer`（client_utils.py:122-208）是精致的终端排版引擎——`Line/LineEntry`（client_utils.py:52-119）维护带颜色分段的当前行，`erase`（client_utils.py:92-103）用 `\r` 重画回卷，`print_token`（client_utils.py:144-186）处理跨行折行（"词首空格则换行"与"回卷合并"两策略），`print_pending`（client_utils.py:200-208）渲染 |/−\\ 旋转等待符并随等待时长 32→33→31 变色（client_utils.py:204）。`AnyPrinter = Printer | RawPrinter`（client_utils.py:211）。

### utils/logging.py

- `random_id(4)`（logging.py:30-31）大写字母+数字短 ID；`setup_logger`（logging.py:34-51）控制台+可选文件双 handler；`print_log`（logging.py:54-59）按 level 选 make_log 或单染 info；`ColorizedLog`（logging.py:62-68）带色前缀轻打印器，`randomize()` 类方法（logging.py:70-75）从 7 色（91-97）随机挑一色 + 4 位 ID——server.py:138 每会话一个实例，多会话日志一眼可分。

### utils/connection.py

- `get_lan_ip`（connection.py:32-48）：UDP socket connect 8.8.8.8 后读 `getsockname` 的经典技巧——不真正发包，connect 只为让内核填本端路由地址。
- `ensure_mkcert`（connection.py:51-120）：mkcert 缺失时按 OS/arch 拼 URL **自动从 GitHub Releases 下载 v1.4.4 二进制**（URL 拼接 connection.py:84-94，`urlretrieve` connection.py:99-101）装进 `~/.local/bin` 并 chmod 755（connection.py:107-108），再以 `-help` 验证可执行（connection.py:113-118）。
- `create_cert_if_needed`（connection.py:144-199）：cert.pem/key.pem 已存在直接复用（connection.py:168-169）；否则 `ensure_mkcert_ca` 装 CA（`mkcert -install`，connection.py:132-141），为 `localhost/127.0.0.1/::1/LAN IP` 四个 SAN 出证（connection.py:184-192）；任何失败 warn 并降级 HTTP 返回 (None, None)（connection.py:173-175、194-196）。
- `create_ssl_context`（connection.py:202-228）：总入口，返回 `(ssl_context, "https"/"http")` 二元组，server.py:473 消费。

## ③ 外部连接

- 调用图：`moshi-offline` CLI → offline.main → run_inference → loaders（与 server 同路）+ `lm.py` 的 `load_audio/_iterate_audio/encode_from_sphn`（offline.py:57-59 显式 import 复用，正是 05 篇 LMGen 音色提示词用的同一批 helper）+ `client_utils.make_log`。server.py:48-51 消费 client_utils（make_log/colorize）、logging（setup_logger/ColorizedLog）、connection（create_ssl_context/get_lan_ip）。
- 产物消费方：输出 WAV/JSON 供人工试听与 ASR/延迟类离线评测；`voices/*.pt` 音色嵌入缓存（由 LMGen 写出，lm.py:1052-1061）被 server.py:164-169 与 offline.py:236-240 的 `.pt` 分支共同消费——离线先跑一遍即可为在线预热音色。
- `Printer/RawPrinter` 在本仓 **Python 侧零消费者**（grep 实证）：Kyutai 原版配套 CLI 客户端未随 NVIDIA 发行版带入（Web 前端取而代之），渲染器失配成死代码；client_utils 只剩 make_log/colorize 两个函数是活资产。

## ④ 数据流

离线一次完整运行：CLI 参数 → voices.tgz 兜底下载（offline.py:388-394）→ 用户 WAV 经 `sphn.read + resample` 到 24kHz（lm.py:121-129）→ `_iterate_audio` 按 1920 样本切片、尾片补零（lm.py:131-150）→ `encode_from_sphn` 用 mimi 逐片编码成 [1,8,T] token（`max_batch` 实际锁 1，lm.py:161-162）→ 循环 `lm_gen.step`：每步同一时间步产出 17 路 token（1 文本+16 音频）→ 音频 1..8 路进 Mimi 解码成 1920 样本 PCM、文本路进 JSON 列表（offline.py:279-295）→ 全帧拼接 → 对齐输入时长（截尾或补零）→ sphn 写 WAV + json.dump 写文本。与 01 篇服务端数据流的唯一差异：用户音频来自文件而非 Opus 流、输出落盘而非 `\x01` 二进制帧——模型侧逐位同构，这正是它够格当回归基准的原因。

## ⑤ 设计决策

- **复刻而非抽公共库**：warmup/seed/wrap_with_system_tags/_get_voice_prompt_dir 四段在 server/offline 各存一份。代价是双份维护（改 bug 要改两处），收益是评测工具与在线服务解耦演进——offline 不会因 server 加路由/锁/协程逻辑而被牵连，评测基线稳定。
- **同步/异步双系统提示词**：offline 走 `step_system_prompts`（offline.py:253），server 走 `step_system_prompts_async`（server.py:283）；实现靠 `_step_*_core` 系列生成器在 `yield` 点给 async 外壳插 `is_alive` 探活（lm.py:1025-1115）——一份算法两种外壳，评测路径不必处理协程取消。
- **输出时长对齐输入**（offline.py:301-309）：延迟/打断点对位类评测要求 agent 音频与用户音频等长可比，宁可截尾补零也保持时间轴对齐——评测友好优先于听感完整。
- **采样旋钮只在离线暴露**：服务端温度/topk 读取被注释冻结（server.py:143-146），离线全开（offline.py:362-376）——在线求稳定（默认 0.8/0.7/250/25）、离线求超参扫描，产品分工清晰。
- **mkcert 自动化降级链**：浏览器麦克风 API 要求安全上下文，connection.py 把"装 mkcert→建 CA→出含 LAN IP 的证书→失败降级 HTTP"全自动化（connection.py:51-228），`--ssl` 从运维负担变成一行参数。

## ⑥ 新人提示（坑与勘误）

1. **seed 判据两处不同源**：offline 是 `seed is not None and seed != -1`（offline.py:182），server 是 `"seed" in request.query` 且取值路径本身带 bug（01 篇勘误⑥-2）；迁移脚本时别假设两者语义一致。
2. **`max_batch` 假参数**：`encode_from_sphn` 的批量路径有未修 bug，函数体强制 `max_batch = 1`（lm.py:161-162，注释 "TO-DO: Fix the batching bug"）——传大于 1 无效且无警告。
3. **`text_token_map` 的两种命运**：offline.py:293 是活代码（打印 EPAD/BOS/EOS/PAD 名字进输出 JSON），server.py:242 却是死赋值——同名变量一处活一处死，review 别一刀切。
4. **离线输出被强行对齐输入时长**（offline.py:303-309）：agent"话没说完"会被截尾、"沉默"会被补零——评估响应长度/话轮切换类指标时要意识到这个人为约束，必要时注释掉这段再跑。
5. `ensure_mkcert` 会从 GitHub 下载二进制并 chmod 755（connection.py:99-108）——离线/受控环境预置 mkcert 或准备镜像，避免首次启动卡在下载；安全审计视角这也是一条供应链暴露面。
6. **复活 CLI 客户端的注意点**：`Line.erase` 依赖 `\r` 重画（client_utils.py:92-103），输出重定向到文件会满屏控制符；`Printer` 折行策略假定等宽终端（max_cols=80，client_utils.py:123）。
7. pyproject 锁 `torch >= 2.2.0, < 2.5`、`aiohttp >= 3.10.5, < 3.11`（pyproject dependencies）——CUDA graph 与流式卷积行为在这些版本调过，升级依赖后先跑 `moshi-offline` 回归再上线，这正是本篇存在的意义。
