# 08 系统服务：chrony 的 Galaxy 整编痕迹、CA 预生成与 move-home-dirs 临时用户技巧

## 一、角色定位

对应图谱 L08 集群系统服务层（62 节点）：时间同步（deepops_chrony）、用户与认证（deepops_users/kerberos_client/nis_client）、日志汇聚（rsyslog 双角色）、自定义 facts、registry 缓存信任根（nginx-docker-registry-cache+gen-ca.sh）、home 迁移（move-home-dirs）。多数是 Galaxy 外来角色整编——收编进 roles/ 并保留上游痕迹。

## 二、内部结构

**deepops_chrony 是 Galaxy 整编活标本**：meta 署名作者 `unxnn`、role_name chrony（roles/deepops_chrony/meta/main.yml:3-4），目录留有 Galaxy 安装写下的 `.galaxy_install_info`（2020-04-02、commit c95f844，:1）与上游 .travis.yml。任务结构是外来角色风格：include_vars 按 os_family 分流（tasks/main.yml:3-4），渲染 chrony.conf（:8-16），DeepOps 只在尾部追加时区步骤（:29-30）。RedHat 路径处理 ntpd 互斥——stat 探测再 stop+mask（roles/deepops_chrony/tasks/redhat.yml:5-11）。

**认证 CA 预生成**治"每次部署换 CA、全集群重配证书"：`scripts/nginx-docker-cache/gen-ca.sh` 生成 4096 位 RSA（:12，口令固定 foobar）与 1300 天自签证书（:15，O=DeepOps/CN=DeepOps）；nginx-docker-registry-cache 在 `nginx_docker_cache_ca` 已定义时直接 copy 预生成 key/crt（roles/nginx-docker-registry-cache/tasks/server.yml:18-34，defaults 默认注释该变量 :24），CA 落位 /opt/deepops/nginx-docker-cache/ca（:6）。

**move-home-dirs 的临时用户技巧**是本层最精巧设计。注释开门见山：当前登录用户的 home 无法被搬（roles/move-home-dirs/tasks/move_users.yml:1-2），于是自造"搬运工"：本地生成一次性 RSA 密钥（:16，delegate 127.0.0.1），建临时用户注入 authorized_key（:36），发 NOPASSWD sudo（:43），写 /etc/localusers 获 Slurm SSH 权限（:49）；再以该身份循环跑 move_user.yml——关键在 include_tasks 的 vars 覆盖 `ansible_user: "{{ tmp_user }}"`（:55-57），执行者与被搬者分离；收尾三步回收：撤 localusers（:65-67）、删 sudoers.d（:71-72）、删临时用户（:77）。

## 三、外部连接

- **deepops_users** 是用户面单一事实源：admin 组免密 sudo（roles/deepops_users/tasks/main.yml:3-10，visudo 校验）→建组（:11）→逐用户建号（:23+）。kerberos_client/nis_client 是企业认证外挂（krb5.conf.j2），rsyslog 双角色组成 99-forward→01-listen 汇聚对。
- **facts 角色**投放 gpus.fact/memory.fact/topology.fact，供 GPU 角色以 ansible_local 读硬件拓扑。
- move-home-dirs 与 autofs/nfs 联动：迁到 NFS 新根后由 autofs 接管挂载。

## 四、数据流

deepops_users 建号（home 默认 /home/<user>）→move-home-dirs 以临时用户整体搬迁（搬完回收权限）→autofs 挂新 home→chrony 统一时钟（mask ntpd）→rsyslog 汇日志。CA 线独立服务镜像：gen-ca.sh 跳板机跑一次→变量指向产物→全集群 docker 客户端信任→nginx 缓存代理可做 TLS 中间人缓存。

## 五、设计决策与甄别

1. **收编优于 fork**：chrony/users/kerberos 保留 Galaxy 原味，DeepOps 不改上游结构只在尾部追加——升级 diff 最小，代价是目录里有化石文件。
2. **临时用户方案幂等**：先删后建（move_users.yml:26 absent 在 create 前），角色可重复执行。
3. 甄别：cachefilesd 与 rsyslog_client 的 molecule prepare.yml 里 policy-rc.d 的 shebang 写作 `$!/bin/sh`（printf 单引号内 `$!` 不展开）——上游笔误，但容器场景只需文件存在且退出 0，"带病工作"（见 README 勘误）。
4. gen-ca.sh 的 foobar 口令与 1300 天有效期是演示级默认，生产必须替换。

## 六、新人提示

1. 读 L08 角色先看 meta/.galaxy_install_info 时间戳，快速分清外来角色与 DeepOps 亲写。
2. move-home-dirs 跑前确认无用户登录（它只能搬"别人"的 home），搬 /home 配维护窗口。
3. kerberos_client/nis_client 与 nfs 的 molecule 场景同源复制（变量残留互串），CI 跑到无关变量别意外。
4. rsyslog 客户端 99-forward-syslog.conf 与服务端 01-deepops-listen.conf 编号前缀即 rsyslog.d 加载序。
