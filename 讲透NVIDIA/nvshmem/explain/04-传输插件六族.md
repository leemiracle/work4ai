# 04 传输插件六族——ops 表挂接的网络数据面

## 角色定位

传输插件层（图谱 L05，45 节点）是 NVSHMEM 的网络数据面：一切跨节点 put/get/AMO 最终都落到某个传输插件的真实 verbs 调用上。设计核心是"一套 ABI、六族实现、按环境变量组装"——`src/host/transport/transport.cpp:31` 硬编码 `NVSHMEM_TRANSPORT_COUNT 6`，运行期解析 NVSHMEM_TRANSPORT 列表→dlopen→调用插件导出的 `nvshmemt_init`（transport.cpp:229）。插件 ABI 极窄：`nvshmem_transport.sym` 只导出 nvshmemt_init 一个符号。

## 内部结构

ABI 契约在 `src/include/internal/host_transport/transport.h`（258 行）：rma/amo/fence/quiet/put_signal 等函数指针 typedef 集中于 transport.h:153-167，`nvshmem_transport_host_ops` 结构在 transport.h:174（含 connect_endpoints/get_mem_handle/progress/finalize 全表），`nvshmem_transport` 结构在 transport.h:208（host_ops 成员挂 transport.h:236），内联分派器 nvshmemt_rma 在 transport.h:242。六族实现于 `src/modules/transport/`：**ibgda**（GPU 直接发起 IB；ibgda.cpp 5348 行全仓最大 .cpp）、**ibrc**（IB RC 连接型）、**ibdevx**（DEVX 直造 QP）、**ucx**、**libfabric**（Slingshot/CXI）、**gpunetio**（DOCA，配 externals vendored 库）。节点内不走插件：内置 `src/host/transport/p2p/p2p.cpp` 走 NVLink/PCIe cuMemcpy。公共底座在 common/：`transport_gdr_common.cpp` 的 gdrcopy_function_table 在 transport_gdr_common.cpp:19 定义，map_v2 可选符号在 transport_gdr_common.cpp:34 声明、transport_gdr_common.cpp:274 LOAD_SYM 装载、版本容忍逻辑在 transport_gdr_common.cpp:151-194——解决 GPU 显存到 CPU 可见映射；`transport_ib_common.cpp` 几乎所有入口都接收 ftable/mlx5dv_ftable 函数指针表——dlopen 解耦贯穿全层；`mlx5_ifc.h`（5542 行）是 ConnectX 固件命令的纯布局数据字典。

## 外部连接

上游：init.cu 装载（transport.cpp:229 传入 nvshmemi_cuda_syms 与接口版本，:206 做插件主版本检查）；proxy 与 putget 调 host_ops.rma/amo（transport.h:242 的 nvshmemt_rma 内联分派）。下游：驱动与网卡——ibgda/ibrc/ibdevx 依赖 libibverbs/mlx5dv，gdrcopy 依赖 libgdr，全部 dlopen。设备侧对接：ibgda 与设备头 `non_abi/device/pt-to-pt/ibgda_device.cuh`（3823 行）组成宿主/设备双面结构——宿主建资源，设备直接发 WQE。

## 数据流

以 ibgda 为例：nvshmemt_init（ibgda.cpp:4911）建 protection domain/设备可见 QP/CQ 并把 host_ops 逐项赋值（can_reach_peer 等在 ibgda.cpp:5302-5309），而 **host_ops.rma 与 host_ops.amo 显式置 NULL（ibgda.cpp:5310-5311）**——IBGDA 的数据路径全在设备：kernel 里 ibgda_store_wqe_segment（ibgda_device.cuh:309）把控制段+数据段写进 GPU 可见 WQE 环（ibgda_get_wqe_ptr 在 ibgda_device.cuh:459 按 wqe_idx 取模寻槽），写 doorbell 即完成一次 verbs 发送；完成侧从 CQE 的 wqe_counter 回收（ibgda_device.cuh:482-491 的原子读+BSWAP16）。宿主 ops 表的 NULL 是"此路不通、请走设备"的声明式路由。

## 设计决策

ops 表插件化让传输可裁剪（按网络硬件选 UCX/libfabric/ibgda）、可组合（NVSHMEM_TRANSPORT 接受列表）；宿主/设备双面结构是 IBGDA 的精髓——资源建立归宿主（复杂但低频），数据面归设备（简单但超高频）；gdrcopy 可选符号表体现"按版本容忍"的软依赖哲学；vendored gpunetio 与 common 底座复用同一 mlx5_ifc 数据字典，两份拷贝（externals 版 5699 行 vs src/modules 版 5542 行）已漂移——同源不同步是 vendored 的经典债。

## 新人提示

选型先读 skills/nvshmem-select-remote-transport 的决策表；排查看 nvshmem-info 的传输段输出。读 ibgda 从两端夹击：先 ibgda.cpp:4911 的 init 看资源建立，再 ibgda_device.cuh:309/:459 看 WQE 写入与环形管理。注意 transport.h:88 的 op_attrs 与 :102 的 pe_info——能力协商与端点信息是插件间差异最大的两块。改 ops 表结构必须同步 nvshmem_transport.sym 与全部六族的赋值点。
