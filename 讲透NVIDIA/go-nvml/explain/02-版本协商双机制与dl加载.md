# 02 · 版本协商双机制与 dl 加载（lib.go / pkg/dl / init.go / return.go / refcount.go）

## 角色定位

图谱 L04+L05 层，仓库的"心脏"。go-nvml 一个二进制要跑在从 Kepler 到 Blackwell 的任意驱动上，而 NVML 符号随驱动版本演化（nvmlDeviceGetPciInfo 有 v1/v2/v3）。解法是**双机制**：编译期宏控可见性 + 运行期符号探测热升级，全部实现在 lib.go（300 行，仓库最值得精读的文件）与自包含的 pkg/dl 包。

## 内部结构

**编译期半边**：nvml.go:23 `-DNVML_NO_UNVERSIONED_FUNC_DEFS=1`（nvml.yml:37 CFLAGS 与 :41 Defines 双处配置同源）令 nvml.h 的 `#ifdef` 只留版本化符号；nvml.go:21 `--unresolved-symbols=ignore-in-object-files` 放过链接期检查。**运行期半边**：lib.go:149-170 把全部版本化函数变量先默认 v1（`var nvmlInit = nvmlInit_v1` 一族），`updateVersionedSymbols()`（lib.go:205）对 22 个符号族逐个 `dl.Lookup("nvmlXxx_v2")` 探测（lib.go:206-297），命中即替换包级变量。注意 lib.go:236 `nvmlDeviceRemoveGpu_v2` 探测被注释（grep 23 处 Lookup 活跃仅 22）。

加载底盘 pkg/dl：`DynamicLibrary`（pkg/dl/dl.go:32）Name/Flags/handle/path 四字段，Open（dl.go:74）/Close（dl.go:96）/Lookup（dl.go:111）三方法。平台分流靠 build tag：dl_linux.go `_GNU_SOURCE`+dlinfo、dl_other.go `//go:build !linux`。生命周期：全局单例 lib.go:59 `var libnvml = newLibrary()`，默认 "libnvidia-ml.so.1"+RTLD_LAZY|RTLD_GLOBAL（lib.go:23-24）；api.go:52-56 `SetLibraryOptions`/`WithLibraryPath` 可改路径但仅限未加载时。

## 外部连接

上游：lib.go:98 委托 dynamicLibrary 接口（lib.go:40-44 定义，`go:generate moq -stub` 产 dynamicLibrary_mock.go——未设 Func 返零值不 panic 的 stub 变体）。下游：init.go 的 Init/InitWithFlags/Shutdown 是公开生命周期入口；return.go:33 的 ErrorString 依赖 errorStringFunc 变量。refcount.go:20-29 `IncOnNoError/DecOnNoError` 被 load/closeLocked 的 defer 消费。

## 数据流

`Init()`（init.go:18）→ `load()`（lib.go:102）：Lock→defer refcount 自增→已有引用直接返回→`dl.Open()` 失败返 `ERROR_LIBRARY_NOT_FOUND`→成功后 errorStringFunc 切到真 nvmlErrorString（lib.go:113）→updateVersionedSymbols 探测升级（lib.go:120）。`Shutdown()`（init.go:40）：refcount==0 返 `ERROR_UNINITIALIZED`（init.go:44，2026-10 PR#206 行为变更）→nvmlShutdown→closeLocked（lib.go:134）dl.Close 且 errorStringFunc 切回默认（lib.go:143）。dl.Lookup 内部：先 dlError() 清残留（dl.go:116-117，glibc dlerror 是线程不安全全局态）再 dlsym。

## 设计决策

①**变量替换而非 IFUNC**：用包级函数变量做运行期分派，Go 层零成本实现"同一二进制跨驱动版本"，比编译期绑定具体 .so 版本优雅得多。②**LockOSThread 包死全部 dl\***（dl.go:59-63 `withOSLock`）：dlopen/dlclose 在多线程下有 loadstore 竞态风险，直接序列化最稳。③**errorStringFunc 双态**（return.go:37）：库未加载也能给出错误文案，Debug 友好。④**refcount 绑定错误**（refcount.go）：副作用与错误返回值绑定，防错误路径污染计数导致库提前卸载。⑤探测列表手工维护：新版本化 API 要同时改 lib.go 探测清单+默认 v1 变量（README.md:595-605 "Add new versioned APIs" 是官方指引）。

## 新人提示

先通读 lib.go 全文（300 行）再读其他任何文件。验证版本协商是否生效：起进程后 `cat /proc/<pid>/maps | grep nvidia-ml` 确认 so 已载入，再用 dl 包的 Lookup 语义理解探测。排查 "symbol not found" 告警时先看驱动版本是否支持对应 _v2/_v3。Init 多次调用是安全的（refcount 幂等），但 Shutdown 未配对调用现在会拿 ERROR_UNINITIALIZED。锚 20 处。
