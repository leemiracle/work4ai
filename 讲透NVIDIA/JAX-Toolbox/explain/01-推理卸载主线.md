# 01 · 推理卸载主线：OffloadingSession 编排与双引擎协作

## 1. 角色定位

jax-inference-offloading 是 JAX-Toolbox 的核心子项目：RL 后训练里 rollout 生成往往吃掉大半算力，这套桥把训练留在 JAX、把自回归生成卸载给 vLLM。主线三块——`session.py` 的 OffloadingSession 是 JAX 侧总前台，管 gRPC 连接与握手；`engines/` 三件套：VLLMTransferEngine 搬权重、VLLMRolloutRequester 发请求、RolloutAccumulator 累积流式结果；`controller/` 是 vLLM 侧对接层与网关。barrel docstring 写死四进程分工（`jax_inference_offloading/__init__.py:22-26`）。

## 2. 内部结构（行号锚）

- **OffloadingSession**（session.py:38）：建 insecure channel 阻塞等就绪（session.py:91-92），装配 CouplingControllerStub + MessageBrokerStub 双 stub（:93-94），握手结果 mapping_specs 转 frozen dataclass（:103-105）。
- **握手**：`_do_handshake` 被 `@on_spmd_leader` 装饰（session.py:114-118），只在 0 号进程执行（spmd.py:45）结果广播到全部 rank（spmd.py:49-62）。先订阅随机回执 topic `handshake/results/{token_hex(16)}`（session.py:120），发 HandshakeRequest（:128-132）走 AsyncHandshake RPC（:139），在流上等响应并断言两侧 TP 为 2 的幂（:147-151）。
- **VLLMTransferEngine**（vllm_transfer_engine.py:38）：先建 NCCL 传输——leader 内 `configure()` 算拓扑、经 CreateTransport RPC 让 vLLM 建对侧（:116-127），再建本侧（:132）；再按 transfer_mode 在 fused/unfused/grouped 三选一（:76-104）。
- **update_weights**（vllm_transfer_engine.py:151-189）：入参兼容 dict / nnx.State / nnx.Module（:168-185），摊平后调 `self._model_transport(named_params)`（:189）阻塞到传完。
- **VLLMRolloutRequester**（vllm_rollout_requester.py:37）：零 JAX 依赖。未传 response_topic 时轮询网关 KV 自发现（key 常量 :34、轮询 :97-129）；`request()` 组 InferenceRequest 后 AsyncInference 即发即忘（:180-190），返回 batch_id 对账。
- **RolloutAccumulator**（vllm_rollout_accumulator.py:54）：按 `(batch_id, prompt_index)` 分组（:86），凑满 num_rollouts 整组入队（:89-92）；`result_consumer_thread` 独立线程读流（:155-181），主线程阻塞也不丢消息。

## 3. 外部连接（图谱边佐证）

图谱把 controller/gateway.py 标为神经中枢（hub fanIn=12/fanOut=9）；rollout_client.py 是全包出边最多的文件（fanIn=9/fanOut=17），订阅网关 topic 驱动 vLLM；session.py fanIn=6/fanOut=6，import 边指向 api 层双 pb2 与 controller.spmd/utils；api/controller.proto schema 节点 fanOut=44、被 11 个文件 import，是全仓被依赖最重的契约。

## 4. 数据流

decoupled_synchronous 示例是完整闭环（examples/decoupled_synchronous/jax_controller.py）：①读 mapping JSON 建 mesh（:90-97）载 checkpoint；②建 Session 握手（:122-127）；③结果 topic 写网关 KV 供 dispatcher 发现（:143-146）；④update_weights 推权重（:172）；⑤发 sync/weights_ready 信号（:181-184）；⑥dispatcher 收信号发 prompt（prompt_dispatcher.py:104-125）；⑦vLLM 的 RolloutClient 消费 inference_requests（rollout_client.py:334-349）并 publish 结果回 response_topic；⑧JAX controller 收 InferenceResponse（jax_controller.py:191-193）。

decoupled_asynchronous 把⑤-⑧换成：dispatcher 连发不等信号；JAX 侧起 consumer 线程 + RolloutAccumulator（decoupled_asynchronous/jax_controller.py:165-176），每凑 update_interval 个完成组推一次权重（:239-241），NCCL 阻塞期间 consumer 照常收流；vLLM 侧换 AsyncRolloutClient（rollout_client.py:394-407）做 max_staleness 有界陈旧度、更新后排空 pending 队列（:524-548）；每次更新后 rollout_client.py:151 `reset_prefix_cache()` 让旧 KV 失效。

## 5. 设计决策

- **握手走异步 RPC + broker 回执**：随机 response_topic 给每个会话私有回执通道，支持多会话共用网关。
- **on_spmd_leader 序列化器可插拔**（spmd.py:30-33）：握手响应用 protobuf 专用 ser/deser（session.py:115-116），其余默认 cloudpickle；广播经 jax.experimental.multihost_utils 通吃单机/多进程。
- **Requester 只发不收**：发送与接收拆成两类客户端、两个进程；跨进程用网关 KV 做服务发现。
- **累积器双队列**（pending_groups + completed_queue，vllm_rollout_accumulator.py:72-73）：凑组与消费解耦，"NCCL 阻塞零丢失"由此而来。
- **shutdown 幂等**（session.py:181-183）+ context manager（:207-214），默认连网关一起 Shutdown（:186-192）——网关是示例拓扑的根进程。

## 6. 新人提示（坑/勘误）

- 握手断言两侧 TP 必须是 2 的幂（session.py:147-151）：JAX TP=8 配 vLLM TP=3 直接 assert 失败，没有降级路径。
- 控制面 RPC 只由 leader 代发（CreateTransport vllm_transfer_engine.py:124-126、StartWeightUpdate :144-149 带 `broadcast_result=False`），NCCL 数据面却全员参与。
- streaming=True/False 是两套返回格式：前者逐条 RolloutResult、后者整批 InferenceResponse（controller.proto:101-110），不可混用。
- requester 的 seed 兜底 `config.seed or 42`（vllm_rollout_requester.py:175）：seed=None 不是随机，是被钉成 42。
- shutdown 里 Shutdown RPC 失败被静默吞掉（session.py:191-192），别指望这里报错。
