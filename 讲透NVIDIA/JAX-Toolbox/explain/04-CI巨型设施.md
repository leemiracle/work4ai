# 04 · CI 巨型设施：_ci.yaml 17-job 流水线与五镜像 Dockerfile 体系

## 1. 角色定位

`_ci.yaml` 是仓库心脏：单架构可复用 workflow（`name: ~CI, single-arch`，`.github/workflows/_ci.yaml:1`），顶层 ci.yaml 按架构各调一次，一条龙完成 **基础镜像→JAX 主镜像→四框架镜像→GPU 测试→标签汇总**（17 job）。三大设施：bazel-remote S3 sidecar（`.github/workflows/_ci.yaml:78-124`）、build-container 复合 action（mealkit→final 两段+推 GHCR）、五镜像串联——base（CUDA 地基）→ jax（源码编 jaxlib+TE）→ 四框架镜像以 jax-mealkit 为 `BASE_IMAGE`（:222 等）。`manifest.yaml` 是上游 18 包的"世界状态"。

## 2. 内部结构

**_ci.yaml（707 行）**：六输入（`.github/workflows/_ci.yaml:3-33`），`SOURCE_URLREFS` 以 JSON 强制指定 jax/xla/flax/TE 的 git ref（L172-176→`URLREF_*` build args）。拓扑：build-base（L50）→ build-jax（L67）扇出四框架构建与 test-nccl（L59）；九个测试 job 跑 EKS/GKE 真机；collect-docker-tags（L314）收口。

**sidecar**：OIDC 凭据→ `umask 077` 写临时 AK/SK 只读挂载进容器→ `docker run -d`（`--s3.prefix` 按架构隔离，L86）→ 轮询 `/status`、空串 SHA-256 探 CAS（L151）→ `if: always()` 收诊断删容器（L196-200）。

**action.yml**：两次 build-push——`target: mealkit`（L157，`<run_id>-<名>-<架构>-mealkit`）；`target: final` 用 `build-contexts: mealkit=docker-image://…@<digest>`（L190）把刚推的 mealkit 层当命名上下文。L119-131 下载 `version.py` 塞进 nsys_jax 包（容器无 .git，scm 造不出）。

**五 Dockerfile**：base 以 `cuda-dl-base:26.09-cuda13.4` 为地基（`.github/container/Dockerfile.base:2`），克隆 pip 23.3.1 打 `pip-vcs-equivalency.patch`，做 CUDA/cuDNN/NCCL/NVSHMEM 符号链接满足 XLA 预期。jax 三阶段：builder `--no-install` 产 jaxlib/TE wheel；mealkit 拷源码、写 `.in` 声明（`.github/container/Dockerfile.jax:121-157`）；final 仅一句 `pip-finalize.sh`（`:163-164`）；四框架镜像是同构菜谱。**manifest.yaml**：`git-clone` 10 包、`pip-vcs` 7 包、`pip-constraint` 1 包（pydantic，`.github/container/manifest.yaml:23-25`）；flax 独有 `mirror_url` 与补丁路由（`:13-17`）；余者带 `latest_verified_commit` 真值。

## 4. 数据流

ci.yaml 跑 bump → 产物在 `_build_base.yaml` 内替换 checkout 的 manifest → build-base 出 `DOCKER_TAG` 被 build-jax 当 `BASE_IMAGE`（L161）。build-jax 出双 tag：MEALKIT 喂四下游 BASE_IMAGE，FINAL 喂全部测试。镜像内：`git-clone.sh` 把实际 commit 写 `/opt/manifest.d/git-clone.yaml`（`.github/container/Dockerfile.jax:114`）→ mealkit 只写 `.in` → final 的 `pip-finalize.sh` 两遍 pip-compile 钉 VCS 后 `pip-sync --no-deps`。collect-docker-tags 组装 priority 化的 10 tag JSON（L329-343）。

## 5. 设计决策

- **mealkit/final 两段 + registry 摘要交接**：mealkit 是带源码与 wheel 的可复用中间层，四下游免重编 jaxlib，final 可换 runner。
- **sidecar 而非常驻缓存**：S3 凭据只活在单 job，按架构分 prefix 防互串。
- **heredoc RUN 块**（`# syntax=docker/dockerfile:1-labs`）：逻辑段独立缓存，改菜谱不失效 base。
- **声明式依赖积累**：构建期只追加 `.in`，钉版/安装推迟到 pip-finalize.sh。
- **URLREF 注入**：同一 Dockerfile 兼吃 manifest 默认值与外部强制 commit（triage 走此口）。

## 6. 新人提示（坑/勘误）

1. **顶层 `return 1` bug（`.github/container/build-te.sh:93`）**：`--sm all` 且 `CUDA_ARCH_LIST` 未设时报错用 `return 1`，但该处不在函数内——bash 只会报 "return 只能在函数/sourced 脚本内" 类费解错误。cuda-dl-base 恒定义该变量（L92）生产踩不到；L104 是正确的 `exit 1`。
2. **maxtext requirements 重复追加**：`.github/container/Dockerfile.maxtext:19-29` 与 `:31-44` 两个 RUN 块把 `-e file://…`/`-r base_requirements`/jetstream grep 各追加两遍，后者仅多 tensorflow 两个 pin——编辑事故，pip-compile 去重无实害。
3. **_test_nccl_gke.yaml year-0 陷阱（`.github/workflows/_test_nccl_gke.yaml:30`）**：`BUILD_DATE: 0000-00-00 # not important; this image is never published`。BUILD_DATE 进 OCI 标签 `org.opencontainers.image.created`（`.github/actions/build-container/action.yml:145`/`182`），非法日期——注释即契约：永不发布才无人校验；L9 默认 JAX_IMAGE 钉死旧 run_id。
4. **collect-docker-tags 漏 torchax**：needs 列表（`.github/workflows/_ci.yaml:317-322`）与 tag 表（L330-340）均无 build-torchax——构建了但 tag 不进 `DOCKER_TAGS`，别假设五 flavor 齐全。
5. L418 在 `[[ ]]` 里对 `${{ matrix.test }}` glob 比较，含空格值会炸；`cancel-in-progress`（L41）重推杀链。
