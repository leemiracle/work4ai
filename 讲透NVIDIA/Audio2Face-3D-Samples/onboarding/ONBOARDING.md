## 1. 项目定位：A2F-3D 官方示例集是什么

这是 NVIDIA Audio2Face-3D（A2F-3D）NIM 微服务的**官方样例仓**，不是引擎本体。A2F-3D 把语音转成 ARKit Blendshape 面部动画（52 个 blendshape），叠加 Audio2Emotion（A2E）自动情绪检测与用户指定情绪（README.md:5-10）。引擎容器从 NGC Catalog 拉取（README.md:18-22 已列出 2.0.0 版条目），本仓只提供四类资产：**gRPC 契约（proto/）**、**三套客户端示例（scripts/ + early_access/）**、**部署配置族（configs/ + quick-start/）**、**版本迁移工具（migration/）**。仓是 Apache-2.0，但模型按 NVIDIA Open Model License 另行授权（README.md:54-58）。一个重要的版本代差要先行钉版：根 README 的目录表已指向 NIM 2.0.0，而 proto/README.md:18 明言"NIM v1.3 continues to use v1.2.0 of the nvidia_ace gRPC python module"，quick-start 两个 compose 的镜像也是 `audio2face-3d:1.3`（docker-compose.yml:18）。样例代码整体锚定 1.3 代。

## 2. 仓库地图：10 层架构总览

87 个源文件按图谱分 10 层：L01 文档门面层（各目录 README）、L02 early_access 授权示例层、L03 API 客户端层、L04 微服务交互 app 层、L05 proto 契约层、L06 风格化配置层、L07 v1.0→v1.2 迁移工具层、L08 部署编排层、L09 配置抓取辅助层、L10 示例音频资产层（example_audio/ 16 个 wav：Claire 五情绪 + mandarin/outofbreath + Mark 五情绪 + 6 个压测专用 sadness 变体）。目录与层的对应关系：`proto/`（16 个 .proto + 生成脚本 + 预编译 wheel）→ L05；`scripts/audio2face_3d_api_client/` → L03；`scripts/audio2face_3d_microservices_interaction_app/` → L04；`early_access/a2f-3d-authoring-sample-app/` → L02；`configs/`（8 个 yaml）→ L06；`quick-start/` → L08；`migration/` → L07；`scripts/config_fetching_app/` → L09。代码体量极小（三套客户端 8 个主文件约 2280 行，加迁移/抓取共约 2930 行 Python），但每层各司其职、互不 import——三套客户端之间唯一的共享物是 proto 生成的 `nvidia_ace` 包与逐字节相同的 config yml 双拷贝。

## 3. proto 契约层：整个仓的宪法

16 个 .proto 定义了 ACE 动画微服务族的完整 gRPC 契约（`proto/protobuf_files/`）。主数据链是 `nvidia_ace.a2f.v1.proto`：AudioStream oneof 包装 AudioStreamHeader（audio.v1.proto:22 的 AudioHeader 四字段 + FaceParameters + EmotionPostProcessingParameters + BlendShapeParameters + EmotionParameters，a2f.v1.proto:42-62）与 AudioWithEmotion（:168-174，音频字节 + 带时间码情绪）。服务面入口 `nvidia_ace.services.a2f_controller.v1.proto:26-31` 的 A2FControllerService.ProcessAudioStream 是全仓唯一被三套客户端共同消费的双向流 RPC：入参 controller.v1.proto:28-40 的 AudioStream（无 ID 版 header + EndOfAudio 标记），回传 controller.v1.proto:104-118 的 AnimationDataStream（header / AnimationData / Event / Status 四分支）。回传实体 animation_data.v1.proto:76-83 的 AnimationData 携带 SkelAnimation（blendshape 权重曲线，:107-115）与 `map<string, Any> metadata`——emotion_aggregate.v1.proto:29-39 的 EmotionAggregate（input / a2e_output / a2f_smoothed_output 三路情绪）就藏在这个 Any 里。注意两对"同名异构"消息：a2f.v1 与 controller.v1 各有一个 AudioStreamHeader（带/不带 AnimationIds），controller.v1 与 animation_data.v1 各有一个 AnimationDataStreamHeader（animation_data.v1.proto:28-31 注释自证）。代码生成有两条互斥路线：装预编译 wheel `proto/sample_wheel/nvidia_ace-1.2.0-py3-none-any.whl`（50 条目，8 个模块族），或跑 `generate_code_from_protos.py files_to_compile.yaml`（generate_code_from_protos.py:147 产出 generated/，:152-164 把点号文件名重排成 nvidia_ace/ 目录树并补 __init__.py），再按 proto/README.md:78-84 用 setup.py 打自制 wheel（setup.py:22 版本同为 1.2.0）。

## 4. 三套客户端对比：同一服务的三种打开方式

**① scripts/audio2face_3d_api_client（NVCF 云端最小客户端）**：入口 nim_a2f_3d_client.py:31-45 只有 main——拼 metadata（function-id + Bearer apikey，:34）→ create_channel(uri="grpc.nvcf.nvidia.com:443")（:36）→ 双 asyncio 任务并发 write/read（:41-42）。auth.py:21-39 的 create_channel 全部走 grpc.aio（异步通道），metadata 经回调凭据注入每个请求；Auth 类 docstring 却留着 Riva 痕迹（auth.py:57 "a Riva URI"，默认值 localhost:50052 与 docstring 写的 50051 也不一致，:46 vs :57）。service.py 是流式推理主体：write_to_stream（:171-243）scipy 读 wav、按 1 秒分块、首包附情绪时间码表（:213-229）、收尾发 EndOfAudio（:242）；read_from_stream（:91-168）解析 header 存 blendshape 名单、逐帧攒 CSV、拆包 EmotionAggregate（parse_emotion_data:61-89 用 Any.Unpack）、落盘 out.wav。
**② early_access/a2f-3d-authoring-sample-app（Authoring 服务客户端）**：面向的是另一套 A2FAuthoringService API（services.a2f_authoring.v1.proto:10-16，UploadAudioClip + GetAvatarFacePose 两个一元 RPC，"逐帧取姿态"的 authoring 范式）。common.py:263-302 上传音频取 SHA-256 哈希，:305-338 按时间码构造 FacePoseRequest（DEFAULT_FACE_PARAMS 14 项，:52-67；EMOTION_KEYS 10 情绪全零，:69-80；30fps 常量 TIME_1_FRAME，:82）。LatencyTesterClient（:545-595）+ threading.Thread 线程池（:510-518）是性能测量核心，LatencyResult.plot_percentiles（:209-260）出 matplotlib 百分位直方图。auth.py:46-48 与 api_client 版近同源但返回**同步** grpc.Channel。client_local_deploy.py 与 client_nvcf_deploy.py 是同构双入口（health_check / data_capture / latency 三子命令），差异只在通道参数：本地明文（client_local_deploy.py:132）vs NVCF 复合凭据（client_nvcf_deploy.py:169-173 三元组 metadata 含 version-id）。
**③ scripts/audio2face_3d_microservices_interaction_app（本地部署交互 + 压测）**：a2f_3d.py 是 proto 绑定最全的一处（:31-41 九条 import 覆盖 8 个模块族，含 health），自带 health_check 子命令（:320-337 走 grpc.health.v1 HealthStub）与 run_inference 主链（:398-453 双任务并发 + 三级异常捕获）；write 侧比 api_client 多做音频校验（:236-240 拒非 16bit/非 mono）与 EmotionParameters 注入（:268-271）。nim_performance_test.py 见第 7 节。**辅助**：scripts/config_fetching_app/fetch_deployment_configs.py:30-50 调 A2XExportConfigService.GetConfigs 拉取运行中服务的三份 YAML（a2x_export_config.v1.proto:19-21，alpha API）。

## 5. 配置族：三角色 × 双模型 × 两套方言

`configs/` 是服务端静态配置：8 个 yaml = deployment_config.yaml（端口 52000 双向流端点 :50、stream_number:10 :21、遥测开关 :82-84、prometheus_endpoint :96）+ advanced_config.yaml（输入消毒：采样率 16k-144k :20-22、low_fps:29 :38、三级队列 :63-65、TRT 精度 a2e 必须 fp32 :94）+ 三角色（claire/james/mark）× 双族 stylization 配置。同角色两族 diff 仅两键：claire_stylization_config.yaml:43 `inference_type: regression` vs claire_diffusion_stylization_config.yaml:43 `diffusion`，加 diffusion:51 `constant_noise: true`——418 行文件只差这两行。角色间差异集中在 inference_model_id（claire_v2.3.1 :46 / james_v2.3.1 / mark_v2.3）与 face_params 微调（james 与 mark 差 5 个系数，input_strength 1.0 vs 1.3 等）。注意 diffusion 族用的是 `multi_v3.2` 共享底模 + identity 键（:49-50）。**另一套方言**是客户端 config yml（config_{claire,james,mark}.yml，257 行）：face_parameters 用 camelCase 键（直配 proto FaceParameters map），而 stylization yaml 用 snake_case（服务端 face_params）——两套名字体系不要混。这 3 个 yml 在 api_client 与 interaction app 两目录各存一份，md5 逐字节相同（6bc7e102/55adb663/84a14965 三对全等）。

## 6. 容器编排：两份 compose 与可观测性链

quick-start/docker-compose.yml 是基础版：a2f-3d-init 先跑 generate_trt_models.py 生成 TRT 引擎写入 a2f-3d-init-data 卷（:23-27），a2f-3d-service `service_completed_successfully` 依赖后以 host 网络 + GPU 启动 a2f_pipeline.run（:40-43）。init-data 卷是 bind 型 local driver 指向 ./a2f-3d-init-data（:61-67），TRT 引擎缓存在此、删 *.trt 即失效（quick-start/README.md Model cache 节）。`quick-start/configs` 是指向 `../configs` 的真符号链接（git mode 120000），两份 compose 都以 `--stylization-config /mnt/configs/${A2F_3D_MODEL_NAME}_stylization_config.yaml` 消费根 configs（:24,:43）——所以跑 diffusion 版要么 `A2F_3D_MODEL_NAME=claire_diffusion` 要么手动改名（compose 只引用 `{name}_stylization_config.yaml` 一种模板）。observability 版（docker-compose-with-observability.yml）差异三点：entrypoint 先用 sed 把挂载的 deployment_config.yaml 里 metrics_enabled/traces_enabled 改 true 再启动（:44-47）；追加 jaeger all-in-one（16686/4318/9411，:65-73）与 prometheus（:75-81）；prometheus.yml:16-23 以 1s 间隔抓 0.0.0.0:9464（与 deployment_config.yaml:96 的 prometheus_endpoint 精确对应）。

## 7. 压测与迁移：两条独立工具链

**压测** nim_performance_test.py：main() 硬编码 6 个 Claire_sadness 变体（16khz/44.1khz × 5/10/20s，:350-355），`--request-nb`/`--max-stream-nb`/`--url` 三参（:129-131）。每个音频用 multiprocessing.Pool(max_stream_nb) 起进程池（simulate_multiple_clients:320-343），每个"客户端"子进程跑 `python3 a2f_3d.py run_inference <file> config/config_mark.yml -u <url> --skip-print-to-files --print-fps`（run_single_client:140，config 也是硬编码），再用正则从 stdout 抓 "First packet sent/received" 时间戳算首包延迟（get_single_client_perf:152-182），StatsHolder 出 9 档统计（:185-239）。输出 performance_output_{N}/ 四件套（csv/png/fps.txt/latency.txt，:362-379）。**迁移** migration/deployment_configuration_files_from_v1.0_to_v1.2：convert_configuration_files.py 读 v1.0 旧 YAML（ucs 或 docker_config 两种来源，:120-128），经 a2f_data_classes/ 三棵 dataclass 树（a2f_config.py:67-73 五节点、a2f_controller_config.py:61-64、ucs_app_config.py:20-43）做字段名映射装载（load_yaml_to_dataclass:104-117 递归），再以根 configs 为模板逐键覆写产出 v1.2 三件套。核心转换：LIST_FACE_PARAM_ORDER 固定 52 个 ARKit 名单（:39-92），把旧版线性乘子列表 zip 成 v1.2 weight_multipliers 字典（:285-286）；旧版 10 情绪线性表按索引配对（:214-216）。坑：模板目录 default_configs_v1_2 在 git 里是**普通文本文件**（内容 `../../configs`），不是符号链接——直接跑会 FileNotFoundError，需先 `ln -sfn ../../configs default_configs_v1_2`。

## 8. 新人上手路线与坑清单

推荐顺序（半天跑通）：①装 proto：`pip3 install proto/sample_wheel/nvidia_ace-1.2.0-py3-none-any.whl`（或按 proto/README.md:30-35 自生成）；②起服务：quick-start 里 `A2F_3D_MODEL_NAME=claire docker compose up`（首跑数分钟生成 TRT）；③探活：`python3 a2f_3d.py health_check --url 127.0.0.1:52000`（interaction README 给的默认端口即 deployment_config.yaml:50 的双向流端点）；④推理：`python3 a2f_3d.py run_inference ../../example_audio/Claire_neutral.wav config/config_claire.yml -u 127.0.0.1:52000`，产物在 output_000001/ 三 CSV + out.wav；⑤压测/云端按需。八个高频坑：A. 压测必须 cd 到 interaction app 目录跑（'a2f_3d.py'、'config/config_mark.yml'、'../../example_audio/' 全是相对路径，nim_performance_test.py:140）；B. 迁移脚本先补符号链接（第 7 节）；C. config yml 双拷贝改一处忘另一处（第 5 节 md5 实证）；D. audio 只吃 PCM16 单声道，a2f_3d.py:236-240 会硬拒；E. emotion metadata API 是 alpha（interaction README Notes 明言），EmotionAggregate 拆包逻辑可能随版本变；F. read_from_stream 的 emotion_key_frames 只初始化 input/a2f_smoothed_output 两键（a2f_3d.py:135-138），parse_emotion_data 却会写 a2e_output 键（:100）——服务端真回 a2e_output 条目时会 KeyError，属两份拷贝共有的休眠 bug；G. 三处 compute_output_directory_name 同名复制（a2f_3d.py:116 / convert_configuration_files.py:95 / fetch_deployment_configs.py:56-60），改输出逻辑勿只改一处；H. 端口 52000 是 compose 默认（deployment_config.yaml:50），auth.py docstring 的 50051/50052 是 Riva 遗留，别照抄。
