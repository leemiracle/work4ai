# 12 部署后端：Triton backend 七族 + TensorRT plugin 五族

## 角色定位

`triton_backend/` 是 FT 的在线服务出口：把引擎包装成 Triton Inference Server 可加载的模型库（权重/多卡/张量转换）；`tensorrt_plugin/` 是图编译出口：把 encoder/decoder 包成算子编进 TensorRT engine。

关键勘误：本仓 triton_backend 只是库——全目录 grep 不到 TRITONBACKEND_ModelInstanceExecute、ModelRepositoryManager、ProcessRequests，std::thread+请求队列在外部仓 fastertransformer_backend。本仓线程模型在示例 examples/cpp/multi_gpu_gpt/multi_gpu_gpt_triton_example.cc:350：每卡起一个 std::thread 建实例/跑 forward，节点间 MPI 广播请求。

## 内部结构

框架层两抽象：AbstractTransformerModel（triton_backend/transformer_triton_backend.hpp:289）约定 createModelInstance/createSharedWeights 等；Instance 约定纯虚 forward 与流式回调。

七族 TritonModel/TritonModelInstance：bert（仅张量并行，吃 input_hidden_state，triton_backend/bert/BertTritonModelInstance.cc:61）、gptj、gptneox、multi_gpu_gpt、multi_gpu_gpt_fp8（cublasFP8MMWrapper）、t5、t5-encoder。TritonModel 读 ini 超参、按 device 建权重副本；Instance 做张量转换+forward。

tensorrt_plugin 五族：swin（fp16/INT8）、vit（含 INT8）、t5（Encoder+Decoding 双 plugin）、wenet、bert_fp8，全继承 IPluginV2DynamicExt（tensorrt_plugin/vit/ViTPlugin.h:58），supportsFormatCombination/configurePlugin/enqueue/serialize 齐备。

## 外部连接

向上：外部 shim 经 createGptModel 等 6 个静态工厂拿模型。向下：instance 持有 FT 模型本体（ParallelGpt/T5Encoder+T5Decoding 等）与 cublasMMWrapper。横向：createNcclParams（triton_backend/transformer_triton_backend.cpp:20）——node0 生成 uniqueId 后 MPI bcast，tp_rank=rank%tp、pp_rank=rank/tp（:49），pp 通信子取 uid[tp_size+tp_rank] 跨 tp 互联。

## 数据流

GPT Triton 链：HTTP → tritonserver 核心（dynamic batcher 拼批并 padding，max_batch 语义在此生效）→ 外部 backend shim → instance.forward：batch 取 input_ids.shape[0]（triton_backend/multi_gpu_gpt/ParallelGptTritonModelInstance.cc:68），convert_inputs 做 H2D；多卡各自线程进 gpt_->forward 做 context decoding，产出 output_ids 写 response。

三处勘误：变长 padding 不在 instance——Triton 核心拼批时已完成，input_lengths 携带真实长度；异常不出 C 边界，catch(...) 以 error_message 张量回传（:252）；t5 族并非双仓协作——triton_backend/t5/T5TritonModelInstance.cc:129 在单实例内先 encoder 后 decoding，output_hidden_state 以 GPU 张量直传 decoding，不经序列化；t5-encoder 族才是独立 encoder-only 服务（triton_backend/t5-encoder/T5EncoderTritonModelInstance.cc:99）。

TensorRT 链：engine 反序列化走 deserializePlugin 的 data+length 构造；enqueue 把 TRT 缓冲区零拷贝包成 ft::Tensor，同 engine 内 encoder 输出直接接线 decoding。

## 设计决策

权重两条哲学：ViT/Swin/wenet/bert_fp8 在 build 期经 PluginFieldCollection 拿权重、随 serialize() 写进 plan，运行期 deserialize 恢复（tensorrt_plugin/vit/ViTPlugin.cpp:76）；T5 只序列化 sizeof(m_) 元数据（tensorrt_plugin/t5/T5Plugin.cu:406），ckpt_path 存于元数据、运行时 loadModel 外部加载，代价是须带 ckpt 目录；getOutputDimensions 硬编码 d_model=512（:494）是坑。bert_fp8 单独成族因走 Hopper FP8 专路（fp8_e4m3 权重 build 期 transposeWeight 进 engine）；fp16/int8 BERT 已被 bert 族与 TRT 原生算子覆盖。max_batch/seq_len 传 0（triton_backend/multi_gpu_gpt/ParallelGptTritonModel.cc:360），缓冲随请求 reMalloc 免预规划；每卡一份 shared_weights_[device_id]（:411 按 rank 分解 tp/pp）。wenet encoder 吃语音特征（tensorrt_plugin/wenet/EncoderPlugin.cc:425），conv 下采样出 ctc_log_probs。

## 新人提示

1）请求主循环在 fastertransformer_backend 仓，本仓线程模型看 triton_example。2）TRITONSERVER API 低于 1.17 无 BF16。3）首跑读 gemm_config.in（plugin 族读 -SM-BS 后缀 .in），缺失拖慢首载。4）调 plugin 用 WHERE_AM_I 宏打点。5）config.pbtxt 的 auto-complete 同在外部 backend；T5 plugin 换 d_model 须同步改 ：494。
