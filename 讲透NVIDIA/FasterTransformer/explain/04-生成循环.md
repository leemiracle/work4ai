# 04 生成循环：惩罚、top-k/top-p 采样、束搜索与 DynamicDecode 调度

## 角色定位

生成循环是 decode step 的"后半程"：从 logits 到 output_ids/finished/should_stop 更新完毕的全部 GPU 工作。`layers/DynamicDecodeLayer.cc` 是唯一调度入口，按 beam_width 二分到束搜索或采样；kernel 层无状态，共享输出 buffer。

## 内部结构

**惩罚**：温度惩罚 `(logit+bias)/T`；repetition/presence 两阶段共享内存法，注释明言"penalized once"（kernels/sampling_penalty_kernels.cu:386），重复 token 只罚一次；min_length mask 掉 end_id；束搜索等价物 invokeAddBiasApplyPenalties；bad_words 回溯封禁短语。

**采样**：top-k 两段分治——stage1 以 8 个 block 切词表、循环 k 次"归约求最大后打桩"迭代抽取（kernels/sampling_topk_kernels.cu:199），stage2 对 8k 个候选归并、exp 重整、轮盘。top-p 三段——top-1 概率已 ≥p 则跳过排序（kernels/sampling_topp_kernels.cu:849）；否则 cub 降序排序；再前缀和采样；免排序核默认编译死。

**束搜索**：beam_width 硬编码 case 分发；stage2 内嵌 BeamHypotheses 簿记、最多 2k 轮——凑齐 k 条 finished 但分数可能差（kernels/beam_search_topk_kernels.cu:269）；online 版以 MD{m,d} 在线归约 softmax 并切 voc_parts 并行。

**终止**：stop_words 匹配与长度上限 `finished |= step>=limit`（kernels/stop_criteria_kernels.cu:118），总数经 pinned 自旋回读得 should_stop。

## 外部连接

forward 每 step 一次（ParallelGpt.cc:1501，"result sampling and stop check" 区间）；Torch 侧入口 th_op/common/DynamicDecodeOp.cc。勘误：ParallelGptDecoder.cc 不调用 DynamicDecodeLayer，生成循环在 ParallelGpt.cc。logits 源头是 gpt_kernels 的末 token 隐状态查找；T5/BART 另消费 tile/insertUnfinishedPath，旧 Decoding 走 decoding_kernels。

## 数据流

beam_width=1 单步链：① logits 进 BaseSamplingLayer::forward；② 混跑则先拷 logits 防互污；③ 惩罚顺序 temperature → repetition/presence（step>1 生效）→ min_length；④ invokeBatchTopKSampling：stage1 分治抽取、stage2 softmax+轮盘；⑤ 写 output_ids 与 finished=(id==end_id)；⑥ 追加 stop_words 与 length 判定得 should_stop；⑦ 判退出否则 step+1。束搜索等价链：惩罚→invokeTopkSoftMax→invokeUpdate 写 parent/output_ids。

## 设计决策

**top-k 采样与束搜索 topk 非同一套 kernel，但同源同构**：两文件的 stage1/2 与 opt3 逐行近似（同 TopK_2 归约+打桩），差异全在 stage2——采样做 softmax+轮盘，束搜索做 BeamHypotheses 簿记；独立的是 diversity 路径 per-thread TopK<T,MAX_K> 有序数组插排。勘误："位示图(bitmap) top-k"当前代码零命中。

**top-p 翻转累积论证**：朴素法需先找截断点再归一化采样。FT 把均匀随机数缩放进 [0,p)（kernels/sampling_topp_kernels.cu:912），对降序概率做 InclusiveSum，ballot 找首个 rand≤prefix 处；因 prefix 在 nucleus 边界已达 p，命中必在 nucleus 内，选中概率恰为 p_i/p——截断与采样翻转合成一遍扫描，平均只扫 nucleus 大小。

**tensor 驱动分支**（伪代码级）：forward 读 beam_width——>1 时若 hasDiffRuntimeArgs（扫 runtime 参数逐元素不等）则退化为 bs=1 逐句循环（DynamicDecodeLayer.cc:289），否则整批进 OnlineBeamSearch；==1 时整批先 topk 后 topp 互补跳过（官方注释：topk 处理 [4,x,4+0.5]，topp 处理 [x,0.5,x]）。每句 k/p 由 top_ks/top_ps tensor 逐 block 读取，归一规则：k=p=0→贪心 k=1；k>0,p=0→p=1；clip k≤1024；skip_decode=k==0。

**Online 与 v2**：v2 先全词表 softmax 物化 float log_probs，topk 硬编码 float 模板（BeamSearchLayer.cu:237），half 也升 float 再进 topk，即"浮点 softmax 降精度豁免"；Online 候选值按原精度 T 直通 topk（TOPK_FP16_STORAGE=0，online_softmax_beamsearch_kernels.cu:34），省整份物化。勘误：DynamicDecodeLayer.cc:375 的 `if (true || ...)` 令 v2 永不可达，是死代码但仍被构造。

**勘误与互斥**：presence=Additive、repetition=Multiplicative 且二者互斥（BaseSamplingLayer.cc:174），无独立 frequency penalty——只罚一次非按次数累加；sampling 与 beam search 按 beam_width 二选一，束搜索强制 cum_log_probs；finished 是采样/stop_words/length 三来源按位或。bonus：diverse beam search 即 diversity_rate>0，对第 i 候选加 rate*i。

## 新人提示

阅读顺序：BaseSamplingLayer 的 forward → sampling_topk → DynamicDecodeLayer.cc → 束搜索三件套。调试：top-p 必须先 softmax 而 top-k 不必；提前停排查先分清 finished 三来源谁置位；top-k 上限 1024、beam_width 只支持专列 case。设计活体在 TensorRT-LLM。
