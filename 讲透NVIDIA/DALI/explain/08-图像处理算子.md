# 08 · 图像处理算子族：注册层、融合核与实验后端

## 一、角色定位

L10（175 节点，158 文件）是 `dali/operators/image/` 图像算子族：convolution/remap/resize/crop/color/paste/clahe/mask/distortion/morphology/filter 十一个子域。定位是"算子注册层"——每个算子把 schema、参数解析、CPU/GPU 双实现组装成 DAG 节点；真正可复用的数学在 kernels/imgproc（L05），本层多数文件是壳+胶水。枢纽是 `dali/operators/image/crop/new_crop_mirror_normalize.cu`：27 条 include（甄别勘误：批阶段笔记记 22 条，实测 27）串起 core/kernels/算子三层。

## 二、内部结构

**注册三件套**：`.cc` 内 `DALI_SCHEMA` 声明参数 + `DALI_REGISTER_OPERATOR` 绑定 CPU/GPU 模板实例——`paste.cc:19` 声明 Paste 的 fill_ratio/fill_color，`paste.cc:104` 注册 CPU 版；`crop_mirror_normalize.cc:23`/`crop_mirror_normalize.cc:83` 同范式。同名双后缀是全目录通则：`crop.cc`/`crop.cu`、`brightness_contrast.cc`/`.cu`、`color_twist.cc`/`.cu` 成对出现，CPU 与 GPU 实现分文件。

**convolution**：`gaussian_blur_gpu/` 按数据类型一型一文件实例化（impl_{i8..f64}.cu 九件），把单编译单元时长压到可承受，每文件只做一层模板展开。

**resize**：`resize_base.cc:127`/`resize_base.cc:128` 用 extern template（头文件声明）+ 尾部 `template class ResizeBase<CPUBackend>;`/`<GPUBackend>;` 显式实例化控制编译膨胀——DALI C++ 常用模式。实验后端 `dali/operators/image/resize/experimental/resize_op_impl_cvcuda.h:32` 的 `ResizeOpImplCvCuda` 以 Impl 接口插入不动主框架；批缓存池设计：`resize_op_impl_cvcuda.h:249` `CachedBatches` 持 in/out 两个 `nvcv::TensorBatch`，`GetBatches`/`ReturnBatches`（`:267` 起）取还，`resize_op_impl_cvcuda.h:297-298` `std::unordered_map<int, BatchCache> batch_cache_` 按 batch_size 分桶缓存，避免反复分配。

**crop 融合核**：`new_crop_mirror_normalize.cu:109` `SliceHwc2HwcChwNormalizeGPU`、`new_crop_mirror_normalize.cu:174` `SliceFlipNormalizeGPU`、`new_crop_mirror_normalize.cu:267` float 特化——三条融合核路径按 output_layout/dtype 经 TYPE_SWITCH（`:101`/`:152`）动态选择，裁剪/镜像/布局/归一化/类型转换一条核完成。

**remap**：`displacement_filter`+`jitter`+`remap` 三算子共享位移场语义；`remap/cvcuda/warp_perspective.cc` 子目录是 CV-CUDA 备胎后端（与篇 7 的 `nvcvop` 桥同生态）。

**核层协作**（kernels/imgproc）：`color_space_conversion_impl.h:30-48` 用 constexpr 函数族（`get_max_value`/`scale_factor`/`bias_scale`）把色彩空间系数表做进编译期，免运行时查表；`connected_components.h:28` 引 `disjoint_set.h` 做标签合并，`:39` `TensorSlice<T,ndim>` 递归模板按 ndim 分派、`:56` `slice()` 逐维降阶；`warp_cpu.h:84` VALUE_SWITCH（`:22` 含 static_switch.h）把插值类型展开成模板分支，消运行时 if。

**paste 家族**：`paste.cc`/`multipaste.cc` 双算子；核在 kernels 层 `dali/kernels/imgproc/paste/paste_gpu.h:15`，文件头注释自述 "THIS WHOLE CODE IS A COPY-PASTE OF multiply-add kernel"——粘贴改造的诚实标记（勘误：paste GPU 核是 multiply-add 内核整块拷贝后改的，非独立设计）。

## 三、外部连接

上游是 L09 解码器输出的 HWC 张量与 reader 给的 ROI 元数据；下游接 normalize/pad 与 L14/L16 框架迭代器的喂批。向上依赖 L05 kernels/imgproc 核库与本层 L12 的几何/随机增广（crop 的随机窗来自 random 分布）；向右经 `nvcvop` 桥接入 CV-CUDA 生态（remap/cvcuda、resize/experimental 两处消费）。`crop_mirror_normalize` 的镜像/均值方差参数与训练侧框架约定（如 PyTorch Normalize）对齐，是互操作关键面。

## 四、数据流

以 `new_crop_mirror_normalize` 为例：crop 窗（含随机 crop 的 anchor 形状）→ mirror 位翻转 → HWC/CHW 布局转换 → mean/std 归一化 → output_dtype 类型转换，五步融合为一条核调用（`:109`/`:174`/`:267` 三路径覆盖 layout×dtype 组合），TYPE_SWITCH 先按 input/output dtype 双层展开再选核。resize 流：参数解析进 `ResizeBase` 共享状态 → 按 backend 分派 Impl（CPU 采样核/GPU 核/实验 CvCuda）→ CvCuda 路径先 `GetBatches` 领缓存批、PushFramesToBatch 装载、算完 `ReturnBatches` 归还池。paste 流：fill_ratio/fill_color 参数 + 输入张量 → multiply-add 语义把小图贴进大画布。

## 五、设计决策与取舍

两层架构（operators 注册壳 / kernels 可复用核）让同一核服务多算子（slice 核族同时喂 crop 与自定义切片类算子），代价是每个算子文件 70% 是模板胶水。编译膨胀三重控制：一型一文件（gaussian_blur）、extern template（resize_base）、TYPE_SWITCH 受限类型集——本质都是把编译时长从"指数模板积"压回线性。实验后端走 Impl 接口插件化而非 fork 主实现，CV-CUDA 升级不污染主线；paste_gpu 的整块拷贝是短期捷径的诚实样本——注释自述而非伪装独立实现，但维护上两处 multiply-add 修复需双写。融合核（五合一）以代码复杂度换 kernel launch 次数，是 GPU 预处理吞吐的关键取舍。

## 六、新人提示

加新算子从三件套起步：DALI_SCHEMA + 双后缀 .cc/.cu + DALI_REGISTER_OPERATOR；找实现先找同名 .cc(CPU)/.cu(GPU) 对，再下沉 kernels/imgproc。理解融合核范本首选 `new_crop_mirror_normalize.cu`（27 条 include 就是依赖地图）；编译卡在 convolution 别惊讶——一型一文件就是为此。改 resize 记得检查 experimental cvcuda 路径是否覆盖你的场景（批缓存池行为与默认路径不同）；调 paste 色彩问题记得它是 multiply-add 语义，fill 与输入同权相加。
