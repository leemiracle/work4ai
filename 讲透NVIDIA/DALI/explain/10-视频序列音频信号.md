# 10 · 视频 / 序列 / 音频 / 信号算子

## 一、角色定位

L13 四族"时间轴数据"算子：video（解码三代架构）、sequence（序列+光流）、audio（MFCC/mel/resample）、signal（FFT/分贝）。核心叙事是视频解码三代演进：legacy 一代→decoder 二代→frames_decoder+input/reader 三代。甄别勘误：resampling 内核在 kernel 层 `dali/kernels/signal/resampling_cpu.cc`，`resample.cc:25` 只是算子包装。

## 二、内部结构

**一代 legacy/**：`readers__Video` 继承 `DataReader<GPUBackend, SequenceWrapper>`（`video_reader_op.h:48`），demux/解码/后处理全锁在 reader 内。`VideoLoader` 用专属 worker 线程读文件（`video_loader.h:155`）；`CUVideoParser` 经 pUserData 把 handle_sequence/handle_decode/handle_display 三静态回调绑给 NvDecoder（`cuvideoparser.h:80`）；解码结果进 `SequenceWrapper`（`sequencewrapper.h:36`）——GPU tensor 加 CUDAEvent 记录异步完成。

**新基座 frames_decoder_***：`FramesDecoderBase` 定义拉取式虚接口 ReadNextFrame/SeekFrame，`FrameIndex`（`frames_decoder_base.h:40`）缓存逐帧 PTS/关键帧索引支持深 seek。`FramesDecoderGpu`（`frames_decoder_gpu.h:127`）走 NVDEC，配进程级 `NVDECCache`（`frames_decoder_gpu.cc:81`）：按 codec/分辨率/chroma/bitdepth 精确匹配租借解码器，不匹配才创建；`cuvidReconfigureDecoder` 复用路径被编译开关保护（`frames_decoder_gpu.cc:150`），注释自述 target 尺寸难预知、设过大会拖慢。

**二代 decoder/**：`decoders__Video`，`VideoDecoderBase` 模板（`video_decoder_base.h:39`）以 FramesDecoder 为实现细节——CPU 端配 FramesDecoderCpu（`video_decoder_cpu.cc:214`），Mixed 端配 FramesDecoderGpu（`dali/operators/video/decoder/video_decoder_mixed.cc:19`）；帧选取全面参数化 frames/start/end/stride/pad_mode。

**三代 input/ 与 reader/**：`experimental__inputs__Video`（`video_input_cpu.cc:20`）是 InputOperator 形态数据源，`DetermineBatchOutline`（`video_input.h:52`）预先算出整文件切批轮廓；文件源 `experimental__readers__Video`（`video_reader_decoder_op.cc:731`）。

**光流**：adapter 抽象层可插 stub（无 SDK 环境编译测试用）；真实现 vendored NVIDIA SDK 头（nvOpticalFlowCommon.h，BSD），头自述 Turing 及以上才有硬件光流引擎（`nvOpticalFlowCommon.h:32`），运行时 dlopen libnvidia-opticalflow.so 取 `NvOFAPICreateInstanceCuda`（`optical_flow_impl.cc:107`）。

**音频/信号**：`Spectrogram`（`spectrogram.cc:30`）；MFCC（`mfcc.h:74`）=mel_filter_bank+DCT；`ToDecibels` 用 min_ratio=10^(cutoff/multiplier) 截下限（`to_decibels_op.h:47`）。序列切分/重排见 element_extract、sequence_rearrange、per_frame 三算子。

## 三、外部连接

FFmpeg libavformat/libavcodec（demux 与软解，MemoryVideoFile 自定义 AVIO 内存读）；libnvcuvid.so（`dynlink_nvcuvid.cc:24`）与光流库全部运行时 dlopen——DALI 不静态链接视频栈，CPU-only 包可无 NVDEC 构建，符号存在性用 cuvidIsSymbolAvailable 探测（`dynlink_nvcuvid.cc:57`）。cuviddec.h 是 MIT 许可 SDK 头直接入库（`cuviddec.h:2`）锁 NVDEC 类型契约。音频内核全在 dali/kernels/signal/（dct/fft/resampling/window/moving_mean_square）。

## 四、数据流

NVDEC 硬解链：文件/内存→FFmpeg demux 出 AVPacket→包成 CUVIDSOURCEDATAPACKET→cuvidParseVideoData 驱动状态机→三回调（sequence 建解码器、decode 提交 cuvidDecodePicture（`frames_decoder_gpu.cc:453`）、display 经 cuvidMapVideoFrame 取 NV12）→`VideoColorSpaceConversionKernel`（`dali/operators/video/color_space.cu:26`）做 YUV→RGB 输出 FHWC。代际本质：一代回调推送+独立线程，二三代同步拉取式 ReadNextFrame，逐帧 seek 精确可控。音频主流水线：波形→preemphasis→spectrogram（FFT+窗）→mel_filter_bank→DCT→MFCC→to_decibels（可选）。

## 五、设计决策与取舍

三代动机：一代全封装进 reader，只能输出 GPU 序列、帧选取受限；二代把解码变成普通 mixed 算子（输入 encoded bytes），帧选取/padding 全参数化，代价是用户自管读文件；三代补回数据源形态与文件源 reader。FramesDecoder 被抽成可复用基座，供 decoder 算子与 input/reader 两类消费者共享。NVDECCache RAII 租约+精确匹配避免反复分配 decode surfaces——解码器创建是最贵操作。光流 adapter/stub 分层让算子逻辑在无 SDK 环境可测。Mixed 与 CPU 后端 API 不一致（Run vs RunImpl），模板共库需手动桥接，源码留 awkward 注释（`video_input_mixed.cc:22`）。codec 分层：VP8/VP9/MJPEG 双端，H.264/HEVC/AV1/MPEG4 仅 Mixed 硬解。

## 六、新人提示

名称迷宫先理清：`readers__Video`（一代，别名 VideoReader 已弃用，`video_reader_op.cc:206`）、`decoders__Video`（二代，留 experimental 弃用别名）、`experimental__readers__Video`/`experimental__inputs__Video`（三代）——搜代码先分清三代。NVDECCache 是进程级全局静态，单测间可能互相污染。光流 output_grid 语义易错：向量场是粗分辨率网格，对齐像素分辨率需除以 grid。改音频行为去 dali/kernels/signal/ 找内核；ARM 重采样走 NEON 向量化（`dali/kernels/signal/resampling_cpu.cc:57` 的 vsetq_f32 手写）。
