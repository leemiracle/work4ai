# 03 精讲：示例与工程链（examples/ + 构建体系）

> 勘误钉版：图谱 t04 tour 写"三示例"，实际 examples/ 下**只有 devices 一个示例**（find 实证：examples/devices/main.go 是唯一示例文件，graph L03 fileCount=2 计入了入口函数节点）。本文按实态讲这唯一的示例与全套构建链。

## 角色定位

examples/devices/main.go 是库的"可执行 README"——十行核心代码演示最简用法：枚举+打印。构建链则是 NVIDIA 云原生系 Go 仓的标准模板：Makefile 两级（Makefile+versions.mk）、vendor 提交、CI 四作业、go-licenses 许可合规，与 go-nvlib/go-nvml/k8s-device-plugin 同款骨架。

## 内部结构

**示例**（examples/devices/main.go:26-38）：`gpuallocator.NewDevices()`（:27）→逐台 `device.Details()` 打印（:34-37）。注意它**不建 Allocator**——只想看拓扑时无需进入分配域；Details() 输出 UUID/BusID/SocketAffinity/全部链路类型（device.go:176-191）。

**Makefile**：`include versions.mk`（Makefile:17）后 TARGETS 列表（:22）经 `patsubst` 批量生成 docker-% 目标（:23,100-110）；`build` 锁 `GOOS=linux`（:26,28-29）；`test` 先 build 再 `go test -v -coverprofile`（:58-59）；`coverage` 过滤 _mock.go 后统计（:61-63）；`vendor` 三连 tidy/vendor/verify（:65-68），`check-vendor` 用 `git diff --quiet` 锁零漂移（:70-71）；go-licenses 按版本装入 bin/（:73-76）。

**versions.mk**：全部 `?=` 可覆盖（GIT_TAG/GIT_COMMIT :15-16、MODULE :18、REGISTRY :20、GOLANG_VERSION 1.24.4 :24、GO_LICENSES_VERSION v2.0.1 :26、BUILDIMAGE :28-29）。

## 外部连接

CI（.github/workflows/golang.yml）四作业并行：**check**（golangci-lint-action@v9 + make check-vendor，:28-49）、**test**（:50-65）、**build**（:66-80）、**check-third-party-notices**（:81-96）。三处作业都先从 versions.mk `grep "GOLANG_VERSION ?=" ` 提取版本（:36,59,74,90）——versions.mk 是工具链单点真源。触发面：PR 与 push 到 main/release-*（:17-25）。stale.yaml 管 issue 分诊。许可链：hack/generate-third-party-notices.sh 由 make third-party-notices 调用（Makefile:78-79），CI `git diff --exit-code` 强制 THIRD_PARTY_NOTICES.md 与依赖同步（:81-86）。

## 数据流

贡献者视角：改代码→make fmt（:35-37）→make test（先 build 验证编译再测试）→make check-vendor（vendor 一致性）→make third-party-notices（许可文件再生成）→PR→CI 四作业全绿。版本流：CI grep versions.mk→setup-go 装对应 Go→各作业跑 make 目标；go-licenses 仅在 third-party-notices 目标按需安装（版本锁定 v2.0.1）。

## 设计决策

① **vendor 提交入库**：离线可构建+依赖审计确定性，代价是仓体积——微库也照做，NVIDIA 云原生家族统一姿势。② **版本单点真源**：Go 版本只写在 versions.mk，CI 反向 grep，杜绝双处漂移。③ **go.mod 声明 go 1.21（go.mod:3）但工具链 1.24.4（versions.mk:24）**：语言版本滞后声明，兼容性下限与实际构建分离。④ **许可合规自动化**：go-licenses 生成+CI 漂移检测闭环（Makefile:81-86），法务友好。⑤ examples/ 被 .golangci.yml exclusions 排除（paths: examples$）——示例代码 lint 豁免，降低贡献门槛。

## 新人提示

- **docker-% 与 build-image 目标是死路**：Makefile:19 引用不存在的 images/devel/Dockerfile，:92-95 引用 versions.mk 未定义的 CLIENT_GEN/CONTROLLER_GEN/MOQ 变量——模板继承残留，本地只跑 make build/test/check 即可。
- 本地跑示例需真机 NVML（libnvidia-ml.so）；无 GPU 环境下 NewDevices 直接报错退出（examples/devices/main.go:28-31）。
- make build 产物锁 linux 平台，交叉开发（macOS 上改码）用 go build ./... 自验即可。
- 跑示例遇 panic 先查 NUMA：Details() 解引用 CPUAffinity 无保护（device.go:181），sysfs 无 numa_node 的机器会炸。
