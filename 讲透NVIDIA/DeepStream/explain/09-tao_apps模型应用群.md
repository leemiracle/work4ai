# 09 tao_apps：TAO 模型应用群与三后端矩阵

## 一、角色定位

`src/apps/tao_apps/` 回答一个工程问题："TAO（Train-Adapt-Optimize）工具链训出来的模型，怎样零改动进 DeepStream？"。它是**模型侧的集成样例集**——与 sample_apps 的"管线模式教学"互补，这里的主角是模型：14 个 TAO 模型家族（PeopleNet/PeopleNet-Transformer/TrafficCamNet/CitySemSegFormer/Mask2Former/Reidentification/BodyPose3DNet/PoseClassification/LPD_ch·us/LPR_ch·us/Retail Object Detection·Recognition）每个都配齐 nvinfer、triton、triton-grpc **三套推理后端配置**（configs/ 下三个平行目录逐一对应），README:52 自述"run twelve TAO models"。三大通用 app（detection/segmentation/classifier，915/1085/920 行）吃同一套 YAML 驱动，五个专项 app（tao_others/）覆盖 LPR 车牌、姿态分类、MDX 感知、NV-ODCR 光学字符、自定义预处理等复合场景。download_models.sh + models/ 目录（11 个样例桩）+ build_triton_engine.sh 构成模型供给链。

## 二、内部结构

**三 app 同骨架**：deepstream_det_app.c / deepstream_seg_app.c / deepstream_clas_app.c 都是"YAML 配置驱动"风格——main 里 `nvds_parse_source_list`（deepstream_det_app.c:581）→逐组件 `nvds_parse_gie_type/nvds_parse_gie`（deepstream_det_app.c:585-589）→sink 三选一（egl/file/fake，deepstream_det_app.c:725-732 按配置 enable 优先级链），差异只在 PGIE 配置指向检测/分割/分类模型。**插件切换是配置项而非编译期**：每个 app YAML 里 `plugin-type: 0/1` 对应 nvinfer/nvinferserver（deepstream_det_app.c:709-711 运行时分派），lpr_app_ch_config.yml 的 config-file-path 下三行注释就是三后端切换现场（nvinfer 启用、triton/triton-grpc 注释备选）。**configs 矩阵**：nvinfer/triton/triton-grpc 三目录 × 14 家族子目录，每家族含 pgie/sgie 配置；triton 版多为 .yml（nvinferserver 的 proto 化配置格式），triton-grpc 是 Triton gRPC 端点变体。**post_processor/**（nvdsinfer_custombboxparser_tao.cpp，840 行）是自定义解析器集中营：导出 `NvDsInferParseCustomBatchedNMSTLT`（第 64 行）、`NvDsInferParseCustomBatchedYoloV5NMSTLT`（第 57 行）等 extern "C" 入口，被各模型配置的 custom-bbox-parser 字段 dlopen。**LPR 专项**（deepstream_lpr_app.cpp，632 行）：三推理实例链——`primary-infer-engine1`/`secondary-infer-engine1`/`secondary-infer-engine2`（第 451-458 行）+ tracker + nvdsanalytics + tiler + 10 个 queue；配套 nvinfer_custom_lpr_parser.cpp 导出 `NvDsInferParseCustomNVPlate`（第 33 行）解析 LPRNet 输出，dict_ch.txt/dict_us.txt 是中美车牌字符字典。**姿态分类专项**（deepstream_pose_classification_app.cpp，838 行）：比 LPR 多两级非推理组件——SGIE0 后接 secondary-postprocess0（加载 postprocesslib_impl/libpostprocess_impl.so 做 BodyPose3D 后处理），SGIE1 前接 secondary-preprocess1（nvdspreprocess 做分类前_roi 提取）。

## 三、外部连接

向上依赖 src/gst-plugins 的 nvinfer/nvinferserver/nvtracker/nvdsanalytics/nvdspreprocess/nvmultistreamtiler 插件族与 includes/nvds_yml_parser.h 的 `nvds_parse_*` C API（YAML→GObject 属性的批量赋值器，是三 app 骨架的粘合剂）。模型侧连接 TAO 生态：etlt 加密权重经 tlt-encoded 模型格式（nvdsinfer_tlt.h 定义密钥接口）加载，TensorRT engine 由 Makefile/deploy 时生成；Triton 路径连接外部 Triton Inference Server（triton_server.md/triton_server_grpc.md 两份文档分别讲容器内启动与 gRPC 远端部署，triton-grpc 允许推理服务器不在本机）。LPR 的车牌矩形经 nvll_obb 旋转摆正（与 07 篇 OBB 链路呼应）。pysm-apps/ 是 service-maker Python 镜像（tao_detection/tao_segmentation/tao_others 四 app），把同一批模型配置暴露给 Python DSL。misc/dev_blog/ 存放 LPDR（License Plate Detection and Recognition）博客配套的数据集工具（coco2kitti.py、lpd_prepare_data.py 等），是文档级资产而非构建目标。

## 四、数据流

以 LPR 为完整样本（lpr_app_ch_config.yml 三级级联）：视频解码进 streammux 成批 → **PGIE TrafficCamNet 车辆检测**（unique-id:1）→ tracker 给车贴 track_id → **SGIE0 LPD DetectNet2 车牌检测**（unique-id:2，`process-mode: 2` 即从父对象 ROI 裁剪输入——只在车内找牌）→ **SGIE1 LPRNet 车牌识别**（unique-id:3，同样 process-mode:2，输入是车牌小图）→ nvdsanalytics（ROI 过滤）→ OSD 画三级结果。元数据层面每级 nvinfer 把自己的 obj_meta 挂到同一对象的 obj_meta 链（parent 循环找 unique_id），probe 里按 component_id 分拣。姿态分类的数据流多两跳"非推理处理"：PeopleNet 检出人 → BodyPose3DNet 推理输出 3D 关键点张量（后处理按 24/10/17 关节分组解码，post_processor_bodypose.cpp:267/352/631） → **自定义 postprocess** 把张量转成 pose 元数据（libpostprocess_impl.so）→ nvdspreprocess 用 pose 结果生成分类网络输入 → 分类 SGIE 输出动作标签；app 侧还有个防御细节：PGIE batch-size 与源数不符时强制覆盖并告警（pose app 第 594-599 行）。三后端切换不改数据流，只改张量在哪里算（本地 TensorRT / 本机 Triton / 远端 Triton gRPC）。

## 五、设计决策

①**一模型三后端的矩阵化配置**：14 家族 × 3 后端的平行目录是最显式的"可移植性即资产"宣言——用户换推理后端只动一行注释，app 代码零改动；代价是配置数量三倍膨胀，靠注释行约定默认 nvinfer。②**通用 app 与专项 app 分层**：det/seg/clas 三兄弟覆盖 90% 单模型场景（骨架 900 行里 700 行是样板），复合场景才上专项 app——避免一个超级 app 配置爆炸。③**级联推理用 process-mode:2 声明式表达**："在父对象 ROI 内推理"不需要写裁剪代码，配置一行即得，这是 DeepStream 级联范式的核心。④**TAO 专有张量格式交给自定义解析器**：TAO 模型输出布局（DetectNet2 回归簇、YoloV5-NMS-TLT 变体）与标准 COCO 不同，post_processor 集中实现避免每个 app 重复；extern "C" + dlopen 让解析器与 app 解耦。⑤**README 口径与配置矩阵的错位**：README:52 说"twelve TAO models"并列出 OCDNet/OCRNet，但 configs/ 实为 14 个家族目录且** OCDNet/OCRNet 在本仓无任何配置**（find 全树无 ocdnet/ocrnet 命中）——12 是"README 重点讲解的模型数"，14 是配置矩阵的真实宽度，读者按 14 理解。⑥**模型交付走 git-lfs 子模块 + 下载脚本双轨**：README 要求 `git submodule update --init --recursive`（样例仓指针）+ download_models.sh（NGC 拉取），兼顾可复现与仓体积。

## 六、新人提示

先跑通 detection app 再碰专项：`cd apps/tao_detection && ../../../../..../deepstream-tao-det-app -c ../../configs/app/det_app_config.yml` 这条路径里相对路径环环相扣，**换目录跑必挂**（与 08 篇同一铁律，配置里 config-file-path 全是 `../nvinfer/...` 相对引用）。三后端切换实验建议顺序 nvinfer→triton→triton-grpc：第一步只需本地 engine；第二步要起 Triton 容器并 build_triton_engine.sh；第三步还要改 triton_server_grpc.md 里的 URL。两个坑：(1) `plugin-type` 与 config 版本必须同代——nvinferserver 只认 .yml 的 proto 风格配置，拿 .txt 喂它会静默解析失败；(2) LPR 中美双轨不能混——LPD_ch 检出的中文车牌喂 LPRNet-us 字典（dict_us.txt）会输出乱码，ch/us 从检测到识别是两条独立链。想加自己的 TAO 模型：拷一个 configs/nvinfer/<家族>/ 目录改四个字段（model-file/labels/parsed/custom 解析器名），在 post_processor 加 extern "C" 解析函数，比改 app 快一个量级。甄别说明：本篇 14 家族=三后端配置目录实测计数；README"twelve models/OCDNet/OCRNet"表述与仓内实际不符处已在设计决策⑤注明；任务书"pose 三级管线"经核实为 PeopleNet→BodyPose3DNet(+自定义后处理)→姿态分类(+nvdspreprocess) 的检测-姿态-动作三级，非三个同类推理。
