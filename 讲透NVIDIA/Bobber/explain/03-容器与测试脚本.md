# 03 · 容器底座与测试脚本：Dockerfile 双 stage 与 setup_fio 函数化

## 角色定位

这一层是 Bobber 的"被测世界"：`bobber/lib/docker/Dockerfile` 定义一个自带全部基准工具的镜像，`bobber/lib/docker/management.py` 管它的生命周期，`bobber/test_scripts/` 七个脚本在容器内真正执行测试。Python 层只决定"跑什么、什么参数"；怎么跑、在什么环境跑，全部下沉到镜像与脚本。

## 内部结构

**Dockerfile 双 stage**（128 行）：

- build stage（`Dockerfile:3-68`）：`cuda:11.2.0-devel-ubuntu20.04` 底座，装齐编译链（swig/bison/gfortran/cmake 等，`Dockerfile:9-47`），然后钉 commit 编译三件套：nccl-tests@`ec1b5e22`（`Dockerfile:50-53`，`make MPI=1`）、OSU micro-benchmarks 5.6.2 源码包（`Dockerfile:56-62`，`--enable-cuda`）、io-500-dev@`0232acfa`（`Dockerfile:65-68`，`utilities/prepare.sh` 会连带构建 IOR/mdtest）。
- runtime stage（`Dockerfile:71-128`）：`cuda:11.2.0-runtime`，三组 `COPY --from=build` 只搬产物（`Dockerfile:108/111/114`）；装 fio/openmpi/ssh/python3（`Dockerfile:75-87`）；写 `NCCL_DEBUG=INFO` 进 `/etc/nccl.conf`（`Dockerfile:90`）；**SSH 重建**：端口 sed 成 2222（`Dockerfile:97`）、`StrictHostKeyChecking no`+`UserKnownHostsFile /dev/null`（`Dockerfile:95-96`）、预生成 4096 位 RSA 免密密钥并自授权（`Dockerfile:100-101`）、`EXPOSE 2222`（`Dockerfile:128`）；DALI 仓库 clone 钉 `fd30786d`（`Dockerfile:116-118`）+ pip 装 imageinary/dali（`Dockerfile:120-124`）；`COPY test_scripts /tests/`（`Dockerfile:126`）。

**management.py 双客户端**（`management.py:28-36`）：`docker.from_env()` 高级客户端管容器，`docker.APCLI(timeout=600)` 低级接口专供 build 流式输出（`management.py:185-195` 逐行解码 stream）。`cast()` 以 detached+`sleep infinity` 长驻容器（`management.py:113`），`network_mode='host'`+`ipc_mode='host'`+`privileged=True`（`management.py:117-119`），存储 bind 到 `/mnt/fs_under_test`（`management.py:130-135`）；`execute()` 经 `exec_run(stream=True)` 注入命令并实时落日志（`management.py:247-259`），入口有两道闸：容器在跑（`management.py:236-239`）与版本一致（`management.py:241-246`）。

**test_scripts 分工**：`fio_multi.sh`（bw/125k/iops 三合一入口）+ `setup_fio.sh`（函数库）+ `fio_fill_single.sh`（磁盘预热，转调 `/storage-perf-test/run_disk_fill_test.sh`，`fio_fill_single.sh:4/14`）；`nccl_multi.sh`/`mdtest_multi.sh`/`dali_multi.sh`/`call_dali_multi.sh` 各管一域。所有多机脚本统一 `-mca plm_rsh_args "-p 2222"` 走容器 SSH（`nccl_multi.sh:41`、`dali_multi.sh:51`、`mdtest_multi.sh:34`）。

## 外部连接

Python 编排层通过 `docker/__init__.py` 门面调用（`__init__.py:5` 实例化、`__init__.py:9-13` 别名）；`run_tests.py:53/100/146/194/231/276` 的六处 `manager.execute('tests/xxx.sh', environment=...)` 是唯一入口，参数全走环境变量（如 `run_tests.py:91-99`）。脚本回传结果的通道只有日志文件——stdout 被 `update_log` 落盘（`management.py:258-259`）。

## 数据流

`setup_fio.sh` 无 shebang、被 `fio_multi.sh:39` `source`，结构为五函数（`drop_caches`/`stop_servers`/`start_servers`/`create_jobfile`/`launch_fio`，`setup_fio.sh:1/30/48/70/81`）+ 环境变量默认值区（`setup_fio.sh:108-133`，`FSTYPE` 由 `df -T` 探测 `setup_fio.sh:109`）。fio 流程（`fio_multi.sh:42-68`）：stop 旧 server → 起 fio server（多机 `--client` 分发 `setup_fio.sh:94-98`）→ `--create_only=1` 大块预写（`fio_multi.sh:53`）→ write → drop_caches → read → drop_caches → 清场。**GPFS 分流**是 `drop_caches()` 的核心（`setup_fio.sh:1-28`）：gpfs 明确跳过（服务端缓存客户端控不了，`setup_fio.sh:5-7`），其余类型并行 ssh 下发 `sysctl vm.drop_caches=3`（`setup_fio.sh:20-25`）。

## 设计决策

- **为什么 build/runtime 分离**：devel 镜像数 GB、编译链在跑分时无用；分离让 runtime 只带二进制。nccl-tests/io-500/DALI 三处钉 commit 保证跨时间结果可比——这是基准工具的公信力底线。
- **为什么 SSH 而非 docker exec 组网**：mpirun 需要 rsh 通道跨机拉进程；每台机器跑同款容器+同款免密钥（构建期注入），MPI 就把容器集群当成普通主机集群。代价是 2222 端口占用与密钥固定（镜像公开即密钥公开，只能算测试环境取舍）。
- **为什么参数走环境变量而非命令行**：`exec_run` 注入环境字典最简单（`management.py:248-251`），脚本侧用 `if [ "x$X" = "x" ]` 全量兜默认值（`fio_multi.sh:3-29`）；代价是脚本自身无 usage，参数真相在 `run_tests.py`。
- **create_only 先行**：官方注释明说先建文件能提升后续性能、小块创建太慢（`fio_multi.sh:51-53`）——写路径先铺满再测，读测的是稳态而非首次分配。

## 新人提示

改 fio 行为先读 `setup_fio.sh:108-175` 的变量区再读函数，变量即配置面。多机失败先查三件：SSH 2222 通不通、`btl_tcp_if_include` 网卡名对不对（`nccl_multi.sh:41`）、容器版本闸门（`management.py:241-246`）。mdtest 的 `THREADS=44` 硬编码有注释"线程多了会炸、原因不明"（`mdtest_multi.sh:4-5`）——别好心调大。`fio_fill_single.sh` 依赖镜像里并不存在的 `/storage-perf-test` 目录，属历史残留（`fio_fill_single.sh:4`），当前版本不可直接用。
