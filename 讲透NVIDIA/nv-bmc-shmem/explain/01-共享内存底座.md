# 讲透 nv-bmc-shmem 之一：共享内存底座（契约 · RAII · 驻留容器）

## 一、角色定位

L02 底座三层件是整个遥测库的地基：`lib/include/shm_common.h`（115 行）定义 producer 与 client **跨进程共享的数据契约**；`ManagedShmem`（`lib/impl/managed_shmem.hpp:47` + `lib/managed_shmem.cpp` 85 行）用 boost::interprocess 以 **RAII** 管理共享段的创建/挂接/加锁；`Map` 模板（`lib/impl/shmem_map.hpp:52`）把 STL 关联容器**直接构造进共享内存段**。bmcweb MRD SLA 优化（README.md:9-22 的动机）最终落地的每一字节都经过这三层——上层聚合器（`shm_sensor_aggregator.cpp:201` 的 insertShmemObject）与客户端（`telemetry_mrd_client.cpp:62` 的 getAllMRDValues）只是这三层的编排者。

## 二、内部结构

**契约层**：`SensorMapValue`（`shm_common.h:73-84`）是驻留值类型——boost interprocess 的 `char_string_t sensorValue/timestampStr/metricProperty` + `uint64_t timestamp`，构造器接收 `void_allocator_t`（段分配器，`:80-82`）；`SensorValue`（`:86-94`）是 std::string 版本的进程本地镜像。**两种类型的分野是底座最重要的类型纪律**：跨段生存必须用带分配器版本，进程内消费用标准版本。debug 通道 `SHMDEBUG` 直通 phosphor-lg2（`:27-29`），受 meson 的 debugTraces 选项控制。

**段管理层**：`ManagedShmem` 持两样东西——`managed_shared_memory` 段与**命名 `named_upgradable_mutex`**（名字 = 段名+"lock"）。两个构造器对应两种角色：创建者走 `create_only`（`managed_shmem.cpp:31`，锁创建后立即 `unlock()` 复位初态，`:55-57`）；挂接者走 `open_only`（`:62`）。读锁 API `TryReadLock`（`hpp:60` 声明）：返回类型 `shmem_read_lock_t`（`hpp:39`）= `sharable_lock<named_upgradable_mutex>`——多读者并行、写者需独占升级。三个异常类定义在 `hpp:70/77/82`：LockAcquisitionException / BadMapException / PermissionErrorException。

**容器层**：`template <class MapType, class ValueType> class Map : public ManagedShmem`（`shmem_map.hpp:51-52`）——**组合了"段的所有权"与"容器语义"**。显式实例化 `Map<SensorMap, SensorValue>` 的全部操作在 `lib/shmem_map.cpp`：双构造器（`:26` 创建 / `:46` 挂接）、`getAllKeyValuePair`（`:57`）、`getAllValues`（`:72`）、析构（`:87`）、`getValue`（`:113`）、`updateTimestamp`（`:129`）、`updateValue`（`:155`）。

## 三、外部连接

- **向上（库内）**：`SHMSensorAggregator` 的每个命名空间持有一个 Map（创建于 `createShmemNamespace`，`shm_sensor_aggregator.cpp:159`）；`ShmSensorMapIntf` 门面（`shm_sensormap_intf.hpp:39`）把 Map 操作包装成命名空间级 API（`updateTimestamp` 遍历在 `:142`）；client 的 `getAllMRDValues`/`getAllKeyValuePair`（`telemetry_mrd_client.cpp:62/:40`）逐命名空间打开只读 Map；
- **向左（进程外）**：producer 守护（gpumgrd/hwmontemp，`configurations/shm_mapping.json` 的 Producers 字段）与 bmcweb——它们通过 `/dev/shm` 里的同名段与命名锁会合；
- **向下（依赖）**：boost::interprocess（段/分配器/锁三件全来自它）与 phosphor-logging（`lib/meson.build:7` 的 dependency）；
- **测试替身**：`test/stubs/phosphor-logging/lg2.hpp`（57 行最小桩）——真 lg2 的模板设施在离线单测环境不可用，底座测试全部跑在桩上（`test/shmem_map_extra_test.cpp` 14 用例、`test/sensor_map_test.cpp` 20 用例）。

## 四、数据流

一次 producer 写入到 bmcweb 读出的完整路径：

1. **建段**：producer 调 `AggregationService::namespaceInit`（`telemetry_mrd_producer.cpp:28`）→ 聚合器 `createShmemNamespace`（`:159`）→ Map 创建构造器（`shmem_map.cpp:26`）以 create_only 建段+命名锁，段尺寸来自 ConfigReader.getSHMSize（`config_json_reader.cpp:163`，按命名空间查 shm_mapping.json）；
2. **写入**：`updateTelemetry`（`telemetry_mrd_producer.cpp:83`）→ `updateSHMObject`（`shm_sensor_aggregator.cpp:509`）→ 键生成 `getSensorMapKey`（`:273`）→ Map 的 `updateValue`（`shmem_map.cpp:155`，写侧持排他/升级锁）与 `updateTimestamp`（`:129`）；
3. **读出**：bmcweb 调 `getAllMRDValues(mrdNamespace)`（`telemetry_mrd_client.cpp:62`）→ 以 open_only 挂接 Map（`shmem_map.cpp:46` 构造器）→ `TryReadLock`（`managed_shmem.cpp:73`）取 1 秒超时的 sharable_lock → `getAllValues`（`:72`）把 `SensorMapValue` 逐条转为进程本地 `SensorValue`；
4. **失败路径**：锁超时抛 LockAcquisitionException（`managed_shmem.cpp:83`）；命名空间不存在抛 NameSpaceNotFound（`telemetry_mrd_client.cpp:58/:118`）；空段抛 NoElements（`:110`）——README `:199` 明示客户端按异常编程；
5. **诊断旁路**：`tools/nv_shmem_tool.cpp`（`main` 在 `:36`）以第三只眼只读挂接，trace 计时输出段状态（`:53-59`）。

## 五、设计决策

1. **interprocess 容器而非裸缓冲**：直接把 map 构造进共享段，键值语义、分配器、迭代器全部由 boost 托管——比手滚环形缓冲多了类型安全，代价是必须接受"所有驻留类型带分配器"的纪律（SensorMapValue vs SensorValue 双轨）；
2. **命名锁与段同生命周期**：锁名 = 段名+"lock"，跟随段一起 create/open（`managed_shmem.cpp:42/67`）——进程崩溃后锁随段回收，避免分布式死锁遗留；
3. **TryReadLock 的"1 秒超时 + 异常"而非阻塞或纯 try**：读侧永不无限等（bmcweb 的 HTTP 线程不能挂死），也不静默重试（把 SLA 问题显性化）——超时即异常，让上层决定降级路径；
4. **Map 继承 ManagedShmem**（而非持有）：每个命名空间一段一锁一容器三位一体，生命周期天然同步——多个 Map 不会共享段，坏域隔离按命名空间粒度成立；
5. **open_only/create_only 双构造器显式分角色**：producer 创建、client 只读挂接，权限模型在构造期就定死（配合 PermissionErrorException）。

## 六、新人提示

- 先把 `SensorMapValue`（`shm_common.h:73`）与 `SensorValue`（`:86`）的区别刻进脑子——90% 的段操作错误是把带分配器类型当普通结构体用；
- 读 `managed_shmem.cpp` 全部 85 行（半小时）就能看到段+锁的完整生命周期，这是全仓性价比最高的一次阅读；
- 写测试时参考 `test/shmem_map_extra_test.cpp`：Map 的段在夹具里建/拆，桩 lg2 由 `test/meson.build` 注入 include 路径；
- 部署排障第一工具是 `tools/nv_shmem_tool.cpp`（`nv_shmem_tool` 可执行）——段是否创建、剩余空间、逐传感器值与时间戳一目了然；
- 改契约结构（shm_common.h）等于改跨进程 ABI：producer 与 bmcweb 必须同步升级，版本常量就在 shm_common.h 里（留意段尺寸重算）。
