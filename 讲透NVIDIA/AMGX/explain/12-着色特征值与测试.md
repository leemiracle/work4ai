# 12 着色、特征值与测试（matrix_coloring / eigensolvers / testframework）

## 角色定位

本篇覆盖 AMGX 质量基建三兄弟：matrix_coloring 为并行松弛提供无冲突分组（多色 GS/ILU 的前提）；eigensolvers 为多项式平滑器自动估谱区间；testframework+determinism_checker 守住 GPU 浮点正确性底线。三者共享与 solver.h 同构的"基类+静态注册表工厂"模式，是理解 AMGX 插件式架构的最小样本。

## 内部结构

着色：`include/matrix_coloring/` 13 个头=11 个策略+基类工厂（matrix_coloring.h，165 行）+着色工具（coloring_utils.h）；`src/matrix_coloring/` 12 个 .cu 对应。注册在 core.cu:669-678 集中完成 10 个名字：MIN_MAX/MIN_MAX_2RING/PARALLEL_GREEDY/ROUND_ROBIN/MULTI_HASH/UNIFORM/GREEDY_MIN_MAX_2RING/SERIAL_GREEDY_BFS/GREEDY_RECOLOR/LOCALLY_DOWNWIND——11 头对 10 名，因 bfs.h（426 行）是 greedy 族的共享 BFS 遍历基础设施而非独立工厂。工厂实现 `matrix_coloring.cu:345` registerFactory、`matrix_coloring.cu:398` allocate 按 matrix_coloring_scheme 配置字符串分发；基类还读三个配置：coloring_level/boundary_coloring/halo_coloring（`matrix_coloring.cu:33-35`），着色状态字段在构造器初始化（`matrix_coloring.cu:31`）——分布式下边界与 halo 区可各自选 SYNC_COLORS 或 FIRST/LAST 策略。合法性自检工具直接内建：`matrix_coloring.cu:74-212` 的检查器遍历邻接报告违例百分比。

特征值：`include/eigensolvers/eigensolver.h` 184 行两段式——EigenSolver 基类（`eigensolver.h:25`，setup/solve 虚接口+谱区间参数）与 EigenSolverFactory（`eigensolver.h:151`）。实现骨架 `src/eigensolvers/eigensolver.cu` 509 行：setup（`eigensolver.cu:124`）、solve 主循环（`eigensolver.cu:195`）、registerFactory（`eigensolver.cu:414`）、allocate（`eigensolver.cu:466`）。注册清单 `src/eigensolvers/eigensolvers.cu:38-48` 共 9 个名字映射到 7 个类：SINGLE_ITERATION/PAGERANK/POWER_ITERATION/INVERSE_ITERATION 四名共享 SingleIteration 工厂（幂法/逆迭代/Pagerank 同骨架，`eigensolvers.cu:38-43`），再加 SUBSPACE_ITERATION/LANCZOS/ARNOLDI/LOBPCG/JACOBI_DAVIDSON 五类（`eigensolvers.cu:44-48`）。Arnoldi 是平滑器估谱默认路径，生命周期三段在 `arnoldi_eigensolver.cu:40/83/96`；PageRank 特化（dangling nodes+随机矩阵平移）在 `single_iteration_eigensolver.cu:246` solver_pagerank_setup；块算法正交化内核 HouseholderQR 在 `src/eigensolvers/qr.cu:441`（592 行实现）。

## 外部连接

测试基建四件套：`include/testframework.h`（109 行，UnitTestDriver 在 `testframework.h:33`，tests 按 名字×mode 双键注册、register_test/run_test 在 `testframework.h:44-49`）+`src/testframework.cu`（608 行驱动器）+`include/unit_test.h`+`src/unit_test.cu`——测试基类与框架分离，UnitTestDriverFramework 在 `testframework.h:64`，支持崩溃后续跑（`.secondtryflag` 标志文件机制）。`src/tests/` 60 个 .cu 覆盖：着色合法性双保险（`src/tests/matrix_coloring_test.cu:53-167` CheckColoring+`matrix_coloring_test.cu:20-41` neighbor_color_validity_checker，覆盖 8 种着色器；`src/tests/valid_coloring.cu:17-83` CheckColoringVC）、确定性双测（`src/tests/aggregates_determinism_test.cu` 与 `src/tests/low_deg_determinism.cu`）、C API 契约（`src/tests/capi_graceful_failure.cu` 与 `src/tests/capi_upload_tests.cu`）、工厂全量冒烟（`src/tests/factories.cu`）、注入式验证（`src/tests/preconditioner_usage.cu:24-115` UnittestSolver 派生 Solver 专测预条件子被正确调用）、边界压力（`src/tests/zero_in_diagonal_handling.cu` 672 行与 `src/tests/large_matrices_support.cu` 509 行 64 位索引全流程）。确定性核心 `include/determinism_checker.h`（28 行）：hash_path_determinism_checker（`determinism_checker.h:16-27`）以单例+checkpoint/checksum 接口，逐 kernel 把输出累进哈希链——绕开浮点归约顺序不定问题，跨运行比对哈希即可判定可复现性（实现 src/determinism_checker.cu）。

## 数据流

着色：求解器 isColoringNeeded → MatrixColoring allocate（matrix_coloring.cu:398）→ 策略产出 m_row_colors/m_sorted_rows_by_color（构造器初始化，matrix_coloring.cu:31）→ Matrix reorderColumnsByColor（matrix.cu:840）消费。估谱：AMG setup 调 eigensolver 工厂（默认 ARNOLDI）→ 谱区间喂 polynomial/Chebyshev 平滑器系数。测试流：UnitTestDriver 按 mode 逐个跑（mode 枚举即被测模板组合），日志回写；determinism_checker 在 kernel 后手动埋 checkpoint 哈希。

## 设计决策

其一，三族工厂同构（solver/coloring/eigensolver 的 registerFactory/allocate 双静态），学一套通全库。其二，PageRank 用"别名注册"复用 SingleIteration 骨架——工厂名与类解耦的范例。其三，着色合法性检查进生产代码而非仅测试（matrix_coloring.cu:74-212），因分布式 boundary/halo 策略组合易错。其四，哈希链确定性检验是对 GPU 归约不确定性的工程化妥协：不追求位级复现，只验证"同输入→同哈希路径"。

## 新人提示

加新着色策略三步：派生 MatrixColoring、core.cu 注册一行、matrix_coloring_test.cu 的覆盖清单加名。估谱失败先看 eigensolver 的谱区间参数是否为 0（多项式平滑器会静默退化）。读测试从 factories.cu（工厂冒烟）+preconditioner_usage.cu（注入式）两篇起步最快；debugging 不可复现问题挂 determinism_checker checkpoint，别逐 kernel 打印比对。测试注册键是 名字×mode，漏注册某 mode 会在 CI 静默跳过而非报错。
