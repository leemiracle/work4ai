# 10 分布式通信层（include/distributed/）

## 角色定位

`include/distributed/` 是 AMGX 多卡架构的通信账本与传输流水：DistributedManagerBase 管"谁的数据在哪"（索引映射与邻接账本），DistributedComms 族管"怎么搬"（MPI 传输），访问者把数据类型与通信动作解耦。三巨头体量：distributed_manager.h 2111 行、comms_visitors.h 1206 行、glue.h 同为 1206 行——全库头部最重的三块基础设施都在这条线上。

## 内部结构

账本核心 `distributed_manager.h:194` `template <typename TConfig> class DistributedManagerBase`（类本体延展至约 L1340）。头部 L9-17 是九个前置声明（DistributedArranger/DistributedComms/CommsMPIDirect/CommsMPIHostBuffer 系等），随后 L20-28 前置声明三家 AMG Level 基类。账本字段在构造器初始化列表一屏可见（约 `distributed_manager.h:260-262`）：neighbors（邻居 rank 表）、B2L_maps/L2H_maps/B2L_rings（边界↔halo 的行列映射环）、halo_ranges/part_offsets（halo 区间与划分偏移）、halo_rows/halo_btl（halo 行与其 back-to-local 映射），以及 m_is_glued/m_use_cuda_ipc_consolidation 等 glue 状态标志。类尾 L1337-1342 用 friend 把 energymin/classical/aggregation 三家 AMG_Level_Base 与 host/device 兄弟特化放进来——分布式内部状态对 AMG 层级半公开。通信抽象根 `distributed_comms.h:25` DistributedComms（394 行）定义 allreduce/bcast/exchange 通用接口，后端理论上可换 NCCL；MPI 基座 `comms_mpi.h:36` CommsMPI 派生它，CloneSubComm 纯虚（`comms_mpi.h:50`）支持粗层通信域裂分，Accept 入口在 `comms_mpi.h:52`。

## 外部连接

访问者模式是本层的组织原则：`comms_mpi.h:22` VisitorBase 三个纯虚重载 VisitComms/VisitCommsHostbuffer/VisitCommsMPIDirect（L24-26）构成双分派入口。`comms_visitors.h` 全 1206 行 24 个 struct：根 CommVisitor（`comms_visitors.h:18`，VisitComms 留空注释"purposely empty"）→ 方向三件 Receiver/Sender/Synchronizer（L144/180/212）→ 向量收发四件 Synch/AsynchSend/RecvVecVisitor（L355/385/415/445）→ halo 交换 functor 链 ExcHalo1/2/3（L634/763/791）与 Async 变体（L821/860）→ AddFromHalo 归并三件（L933/999/1039）→ SendRecvWait 等待（L1086/1126）。四份 ETI 清单头 `comms_visitors1_eti.h`~`4_eti.h` 为全部 TemplateConfig 组合（device/host×精度×位宽）生成链接期实例——纯实例化清单，无结构可提取属预期。传输双路径：host 缓冲流 `comms_mpi_hostbuffer_stream.h:17` CommsMPIHostBufferStream（打包 kernel→暂存→MPI→解包 kernel 流水）；GPUDirect `comms_mpi_gpudirect.h:14` CommsMPIDirect 继承 HostBufferStream——运行时探测 MPI 库 CUDA-aware 能力决定直发 device buffer，探测失败回退基类 hostbuffer 路径，继承即回退通道。

## 数据流

多卡 setup：DistributedRead 分片读入（`distributed_io.h:14`）→ DistributedArrangerBase（`distributed_arranger.h:28`）做 one-ring/half-ring 全局重排 → DistributedManagerBase 建立本 rank 窗口与 B2L/L2H 映射账本。solve 期每次 SpMV 前后：ExcHalo functor 按色交换 halo 向量段（着色序保证通信与计算重叠），AddFromHalo 把 halo 贡献归并回本体。glue.h 的 thrust functor（add_constant_op 在 `glue.h:141`）支撑置换与全局索引重编号的设备端执行。

## 设计决策

其一，账本与传输分离——Manager 只记账不收发，Comms 只收发不记账，粗层复用靠 CloneSubComm 裂域。其二，访问者解耦数据类型：新向量类型只需扩 visitor，不必碰 CommsMPI 三层继承链（NOTES 钉版）。其三，GPUDirect 以继承 HostBufferStream 落地，运行时探测+回退零配置切换。其四，`amgx_mpi.h` 装 MPI 错误处理器把 MPI 错误翻译成异常，与 error.h 的 FatalError 体系合流。

## 新人提示

读分布式从 comms_mpi.h 的 68 行开始（三层继承+VisitorBase 一页读完），再进 comms_visitors.h 按"L18→L144→L634"三站走。调试多卡结果错位先查 B2L_maps 语义（边界行→各邻居本地行的映射，方向极易读反）。ETI 清单头报链接错误时，去 comms_visitors*_eti.h 对应序号补组合，别在 visitors.h 里找定义。glue.h 与 comms_visitors.h 行数相同（1206）是巧合不是复制，别按"同文件"心智检索。
