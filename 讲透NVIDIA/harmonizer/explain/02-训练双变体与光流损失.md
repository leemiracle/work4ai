# 02 · 训练双变体与光流损失

## 角色定位

`src/` 的两个训练脚本与四个损失/工具模块构成训练面。它们落实论文的三失败模式训练（appearance harmonization / artifact correction / lighting realism，`README.md:19`），其中 **RAFT 后向光流时序损失**是"保时序一致性"卖点的代码载体。双变体让同一模型核心以"完整 tokenizer"与"faster+AOT"两形态分别服务训练与部署。

## 内部结构

双变体成对：**harmonizer 版** `train_pix2pix_turbo_harmonizer.py`（537 行）组装标准 `Pix2Pix_Turbo`（`pix2pix_turbo_harmonizer.py:177`，`fast_tokenizer=False`，`:29`），复刻 legacy 多数据集形态——docstring `:5` 自述前身 `train_..._cosmos_skip_tp_multidataset_optical.py`，支持逗号分隔多源、加权采样、GAN/CLIP/LPIPS/风格多损失与 RAFT 光流（`:8`）。**nocond 版** `train_..._nocond_cosmos_base_faster_tokenizer.py`（437 行）组装 faster_tokenizer 变体（`...faster_tokenizer.py:217`，`fast_tokenizer=True`，`:32`；DiT 权重指向 `model_fast_tokenizer.pt`，`:34`），数据走 `PairedDatasetV2`（`:164/168`）。两者都经 accelerate 多卡启动（`:31`）。`--pretrained_path` 给 `diffusion_harmonizer.pkl` 则续训，省略则从裸 Cosmos 0.6B 微调（`README.md:159`）。

光流损失 `opticalflow_loss.py`（114 行）：`TorchvisionRAFT`（`:46`）封装 torchvision raft_small/raft_large 双选（`:49-55`），参数冻结（`:70`）并经 `accelerator.prepare`（`:72`）；`warp_backward`（`:24`）以 base_grid+归一化流构造 `grid_sample` 采样网格并返回界内有效掩码；`get_temporal_loss`（`:78`）对 5D `(B,C,V,H,W)` 多视角张量逐时刻调 `raft.backward(x_tgt[:,t], x_tgt[:,0])`（`:91`），把首帧预测 warp 到后续帧做 Charbonnier 惩罚（`:102`）——首帧锚点即时序一致性的归纳偏置。

## 外部连接

配对数据由 `training_utils.py`（758 行）供给：策略矩阵直接编码在函数名——`get_gt_multiview_randomNone_noteven2_kx_ispdata_gap1`（`:526`）、`..._ds_gap1`（`:536`）、`..._randomwhite_..._kx_gap1`（`:546`）、`..._relight_gap1`（`:578`），四维=随机参考(None/white)×非均匀采样(noteven2)×数据源(kx/ds/ispdata/relight)×间隔(gap1)；数据集两形态 `PairedDataset` 目录式（`:596`）与 `PairedDatasetV2` JSON 式（`:660`）；超参入口 `parse_args_paired_training`（`:27`，含 `--lambda_opticalflow`，`:46`）。辅助损失：`style_loss.py`（Gatys 风格）、`dino_struct.py` 的 `VitExtractor` 白盒 DINO 特征（22 方法+`BLOCK_KEY/KEY_MAPPING` 常量表）。数据策展见 `doc/dataset_preparation_tutorial.md`，退化帧策略沿 Difix3D+ 四程序（`README.md:112`）。

## 数据流

一个训练 step：`PairedDataset(V2)` 吐"退化渲染帧 + 干净目标帧 + 参考视角帧"三元组 → 前者经 VAE encode（patch 后可回梯度）成 latent，以最大噪声单步构造 `xt` → DiT 单步前向出预测 → 解码回像素 → 损失聚合：像素/感知（LPIPS）对齐目标帧，`get_temporal_loss`（`opticalflow_loss.py:78`）用 RAFT 光流惩罚"首帧预测 warp 与后续帧预测"的不一致，可选 GAN 判别器与风格/DINO 损失加权进总损失 → accelerate 梯度同步。多源按权重采样混合域，Relight 系专喂 lighting realism。

## 设计决策

① **光流 warp 首帧而非全对全**：O(V) 次 RAFT 调用而非 O(V²)，且把"锚点=首帧"固化为时序基准；② **RAFT 冻结+prepare**（`:70/72`）：损失模型不训练但走分片，多卡数值一致；③ **策略矩阵进函数名**：新增组合=新函数，可检索但不易参数化；④ **双变体分开而非一模型双模式**：checkpoint 与管线依赖差异大到值得两套入口。

## 新人提示

先跑 nocond 版（`PairedDatasetV2` JSON 源最简）。`--lambda_opticalflow` 默认 0（`training_utils.py:46`），要时序损失须显式给值。查数据问题第一站是 `get_gt_multiview_*`（`:526-578`）与 `.json` 后缀分流逻辑。harmonizer 版加权采样语法"数据集名:权重"，逗号转义易踩坑。
