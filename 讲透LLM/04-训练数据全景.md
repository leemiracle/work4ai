# 04 · LLM 训练数据全景 — pretrain / SFT / RLHF / 合成数据

> **数据是 LLM 的"燃料"**——再好的架构，没有好数据也训不出好模型。本篇整合 LLM 各阶段的数据全景，指向 [`讲透数据/`](../讲透数据/) 的深挖。
>
> 与 [`讲透数据/`](../讲透数据/) 的区别：讲透数据是数据工程通用方法，本篇聚焦 **LLM 特有的数据问题**——配比/质量/合成/对齐数据。

---

## §0 LLM 数据的四个阶段

```
① 预训练数据     ② SFT 数据       ③ RLHF 偏好数据   ④ 合成数据（横跨）
万亿 token       万级 pair         万级 preference   贯穿所有阶段
广度知识         指令遵循          价值对齐          数据增强
质量过滤         质量>>>数量        标注者一致性      强模型蒸馏
```

---

## §1 ① 预训练数据：万亿 token 的工程

### 1.1 数据来源（详见 [01 §1.1](./01-完整生命周期.md)）

| 来源 | 占比 | 作用 |
|------|------|------|
| **Common Crawl**（网页）| ~50% | 广度 |
| **GitHub 代码** | ~30% | 推理 |
| **Books** | ~10% | 深度 |
| **arXiv** | ~5% | 学术 |
| **数学数据** | ~5% | 推理强化 |

### 1.2 数据质量 = LLM 上限

**铁律**：**数据质量决定模型上限，架构和算力只是逼近这个上限**。

**质量维度**：
- **准确性**：事实正确（去垃圾/广告/SEO 内容）
- **多样性**：覆盖广领域（避免某域过载）
- **新鲜度**：时效（知识截止）
- **安全性**：去有害/暴力/违法

**质量过滤 pipeline**（详见 [`讲透数据/`](../讲透数据/)）：
```
原始 Common Crawl
    ↓ 去重（MinHash）
    ↓ 语言识别（fasttext）
    ↓ 质量分类（启发式 + classifier）
    ↓ 去有害（safety model）
    ↓ 去重（exact + fuzzy）
高质量预训练数据
```

### 1.3 数据配比的实验性

配比影响能力分布：
- 代码多 → 推理强，但语言风格"机械"
- 中文多 → 中文好，但英文弱
- 学术多 → 专业强，但口语化差

**DeepSeek 的洞察**：提高代码/数学比例 → reasoning 显著提升。这是 DeepSeek 系列能在推理上领先的数据原因。

## §2 ② SFT 数据：质量 >>> 数量

### 2.1 LIMA 启示：1000 条 > 5 万条

LIMA（Meta 2023）证明：**1000 条高质量人工 SFT 数据 > 5 万条低质量数据**。

**核心洞察**：预训练已经给了语言能力，SFT 只是教"怎么对话/遵循指令"——少量高质量样本足够。

### 2.2 SFT 数据的三种来源

| 来源 | 质量 | 成本 |
|------|------|------|
| **人工编写** | 最高 | 最高（~$10/对）|
| **强模型蒸馏** | 高 | 低（API 调用）|
| **公开数据集** | 中 | 免费但需清洗 |

### 2.3 SFT 数据的坑

- **过度蒸馏**：全用 GPT-4 数据 → 学到 GPT-4 的偏见（verbose/sycophancy）
- **分布偏差**：任务类型不均 → 长尾能力差
- **格式污染**：数据带 markdown/特殊格式 → 模型硬套

## §3 ③ RLHF 偏好数据：最贵的数据

### 3.1 偏好数据的形式

```
prompt: "解释量子纠缠"
response A (chosen): 详细准确解释 ...
response B (rejected): 错误简化解释 ...
```

模型学的是"A 比 B 好"的相对偏好，不是绝对质量。

### 3.2 标注的三大挑战

| 挑战 | 表现 | 解法 |
|------|------|------|
| **标注者分歧** | 同一对比对，不同标注者判断不同 | 多人标注 + majority vote |
| **标注者偏见** | 偏好长回答/礼貌回答（sycophancy）| 标注规范 + 校准 |
| **成本** | ~$20/对人工 | AI judge（GPT-4 标，便宜 100×）|

### 3.3 AI Judge：2026 主流

用 GPT-4/Claude 当裁判给 response 打分，成本从 $20/对降到 $0.2/对。

**风险**：AI judge 有自己的偏见（偏好自己风格的回答），会传递给被训模型。
**缓解**：多个 judge 交叉 / 人工校准 judge。

## §4 ④ 合成数据：2026 的新范式

### 4.1 为什么需要合成数据

- **高质量真实数据枯竭**：互联网好数据快被用完了
- **特定任务无真实数据**：如长程推理 / 罕见场景
- **对齐数据难采**：人工偏好标注慢且贵

### 4.2 合成数据的方法

| 方法 | 思路 | 代表 |
|------|------|------|
| **强模型蒸馏** | 让 GPT-4 生成数据 | Alpaca/WizardLM |
| **自我改进** | 模型生成 → 自我筛选 → 再训 | SELF-INSTRUCT / R1 Zero |
| **种子扩展** | 少量种子 → 扩展 | Evo | 
| **反演生成** | 给答案 → 让模型生成问题 | 数学题生成 |

### 4.3 合成数据的风险

**模型崩溃（Model Collapse）**（Shumailov 2024）：用模型生成的数据再训模型，几代后**多样性坍缩**，能力退化。

```
原始数据 → 训 G1 → G1 生成数据 → 训 G2 → ... → Gn
                                            ↓
                                    多样性坍缩 + 能力退化
```

**防御**：
- 混合真实 + 合成（不要纯合成）
- 多样性筛选（embedding 去重）
- 用真实数据校准

### 4.4 DeepSeek-R1 的合成数据启示

R1 用 **RLVR** 让模型自我生成 reasoning trace，无需人工标注——这是"合成数据 + RL"的极致组合。但 [`讲透RL/05`](../讲透RL/05-RLVR的极限.md) 证明这有天花板（pass@k 反转）。

## §5 数据飞轮：闭环迭代

```
上线模型
    ↓ 收集用户 query
bad case 识别（人工 + AI judge）
    ↓
标注 / 改写 → 进 SFT/RLHF 数据
    ↓
重训模型
    ↓
shadow mode 对比
    ↓
全量切流
    ↓
（循环）
```

**关键工程**：
- **数据版本化**（DVC）：每次训练用哪版数据可追溯
- **数据血缘**：每个样本来源可追溯（避免污染）
- **反馈延迟**：用户反馈到模型更新的时间（越短越好）

---

## §6 一句话总结

> 🎯 **5 句话**：
> 1. **数据质量 = LLM 上限**——架构和算力只是逼近这个上限。
> 2. **预训练数据**：万亿 token，配比（代码/数学）直接影响推理能力，DeepSeek 的领先部分是数据配比胜利。
> 3. **SFT 数据**：质量 >>> 数量（LIMA：1000 条 > 5 万条）。
> 4. **RLHF 偏好数据最贵**（~$20/对人工），AI judge 是 2026 主流但有自己的偏见。
> 5. **合成数据是新范式**（强模型蒸馏 + 自我改进），但警惕模型崩溃（多样性坍缩）。
