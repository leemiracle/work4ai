# 问题转 code 路由 · 讲透政治学（GB/T 810）

> **定位**：把政治学的**真实问题/任务**逐条翻译成可接单的 code 任务。
> 分工：各家族 04 章管**边界与走廊**——什么能机械化、走哪条计算走廊、
> 自动化档位在哪；本表管**具体问题怎么接单**——一句话问题 → 形式化 →
> code 任务 → 算法锚点 → 落点家族。宇宙全景见 [README](README.md)。

## 使用方法

1. **找最近邻行**：把问题在路由表扫一遍，找最像的一行（不必精确匹配；
   找不到，说明问题可能尚未形式化，先过第 2 步再回来）
2. **过形式化关**：把问句改写成数学对象——算什么规则输出？估计什么
    坐标/概率？仿真什么均衡？写不出形式化，就还不是 code 任务
3. **按档位接单**：
   - **[A 可直接编码]**：形式化基本唯一（规则即算法）→ 直接写代码+断言
   - **[B 需先建模]**：形式化有多种选择（编码方案/校准/效用设定）→
     先写设定页再动手，测量效度先于模型精度
   - **[C 研究级开放]**：基率/识别/外推至少一环无共识 → 先读文献，
     把问题降级成可行的 A/B 子问题
4. **算法/库只是锚点不是背书**：换库自由，断言不自由（见尾部工作流）

## 三层占比与读法

| 档位 | 行数 | 占比 | 接单纪律 |
|---|---|---|---|
| A 可直接编码 | 15 | 52% | 断言先行，直接写 |
| B 需先建模 | 10 | 34% | 设定页先于代码；编码方案要人签字 |
| C 研究级开放 | 4 | 14% | 先降级成 A/B 子问题；报告基率与尝试次数 |

**读法**：A 层集中在"规则即算法"地带（席位翻译/权力指数/排队/审计）——
确定性纯算术，政治学里最接近数学定理的部分；B 层大头是测量与仿真（文本
编码/ABM 校准/预测聚合）——模型可行，校准靠人；C 层是预测与因果（冲突
预警/政权更替/态度因果）——基率低、数据偏、识别难。与经济学宇宙相比
本表 B/C 占比更高：对象是人与权力，**测量误差先于建模误差**。

## 通用工作流（问题→形式化→选走廊→写断言）

```text
1 问题     一句自然语言+判断标准（"公平/可信/收敛到什么"先说清）
2 形式化   四选一：规则输出 / 坐标估计 / 均衡求解 / 涌现仿真
3 选走廊   对照家族 04 章走廊总表，锁定工具链与自动化档位
4 写断言   三选一，先于实现：
           ① 解析/复现锚——已知常数写进 assert（如孔多塞循环概率
             →Guilbaud 常数 0.0877）
           ② 退化情形——维度/门槛推到边界退回已知结果（单峰偏好下
             循环率→0）
           ③ 不变量——规则该满足的公理性质（无孔多塞赢家时报错）
5 接单     A 直接写；B 设定页先于代码；C 先降级再接
```

**走一遍样例**（第 1 行）："这次改用排序复选好不好"→形式化为偏好
profile 在两套规则下的胜者与悖论率→政治学理论 04 章走廊 1（社会选择）
→断言三件：经典 3×3 循环 profile 复现、无偏文化下循环率逼近 0.0877、
孔多塞赢家被博尔达击败（规则敏感性）→照 condorcet_cycle 式脚本落地。

**断言先于实现**：数值对不上时，assert 给出"先怀疑理论还是先怀疑实现"
的仲裁顺序——这是本宇宙所有家族实验的公共纪律。
