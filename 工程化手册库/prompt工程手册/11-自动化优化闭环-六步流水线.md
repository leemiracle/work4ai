# 11 · 自动化优化闭环：六步流水线

> **核心论点**：本手册 01-10 章的要求（七要素 / 6 维评价 / 30 反模式 / 黄金集）**不是让你手动 checklist 的——它们是规格（spec），工具是实现**。六步闭环把"手动迭代 prompt"从天级缩到分钟级。
> **触发问题**：用户问"手动达到手册要求太难太花时间，有哪些工具 + 怎么操作自动优化？顺序是先评估 → 提取特征 → 优化 → 自动化吗？"
> **本文是什么**：2026-08-17 对上述问题的完整回答，含顺序修正、可跑骨架、环境实测状态。

---

## 🎯 先修正两个概念

### 修正 1 · 顺序：评估之前还差一步

你猜的顺序：`评估 → 提取特征 → 优化 → 自动化`
正确的顺序：

```
① 造卷 → ② 摸底 → ③ 归因 → ④ 调参 → ⑤ 验收 → ⑥ 上岗
黄金集   基线评估  失败分析  优化     验证防漂移  CI/CD闭环
```

**评估（②）永远在优化（④）之前**——优化器的每一步决策都吃"评估分数"作为指南针。没有基线，你无法证明任何优化有效。而评估之前必须先有卷子（①黄金集），否则评估无题可评。

### 修正 2 · "提取特征"在 prompt 世界不存在

这是 ML 思维的迁移误解：prompt 不是模型，没有特征可提。对应环节叫**失败归因**——每个失败 case 定位到 ROIF-CSE 哪个要素弱。手动做是"看失败矩阵"，自动做就是 GEPA 的 reflection LM 在干的事（见下文 §与 03-Reflexion 的桥）。

## 📐 六步闭环总览

```
┌─────────────────────────────────────────────────────────┐
│  ① 造卷      ② 摸底       ③ 归因                        │
│  黄金集  →   基线评估  →   失败分析                      │
│  (人工主导)  (全自动)      (半自动)                       │
│                                                          │
│  ④ 调参      ⑤ 验收       ⑥ 上岗                        │
│  优化     ←  验证防过拟合   CI/CD + 监控                 │
│  (自动为主)  (全自动)      (全自动)                       │
│      ↑                                      │            │
│      └────── 生产失败样本回流，新增 case ←──┘            │
└─────────────────────────────────────────────────────────┘
```

| 步骤 | 干什么 | 用什么 | 人工/自动 | 产出物 |
|---|---|---|---|---|
| **① 造卷** | 10-50 个 input→期望输出，覆盖正常 70% / 边界 20% / 对抗 10% | LLM 合成 + **人工校验**（[08](08-黄金集模板.md) 方法 2） | **人工必须** | `golden_set.jsonl` + `promptfooconfig.yaml` |
| **② 摸底** | 当前 prompt 跑全部 case | `npx promptfoo@latest eval` | 全自动 | 基线：通过率 / 格式合规率 / token 成本 / 延迟 |
| **③ 归因** | 失败 case 分类 → ROIF-CSE 弱项定位 | `npx promptfoo@latest view` 看矩阵 | 半自动 | "F 要素弱：3 例 JSON 解析失败"这类结论 |
| **④ 调参** | 手动：surgical 只改弱项要素；自动：GEPA 进化 prompt | 手动改 / `dspy.GEPA` | 自动为主 | 优化后 prompt 候选 |
| **⑤ 验收** | 在**没参与优化**的 val 集上重跑，对比基线 | promptfoo A/B + 统计检验（[08](08-黄金集模板.md) 的 `ttest_rel`） | 全自动 | 优化前后对照表（防过拟合） |
| **⑥ 上岗** | PR 门禁 + 模型版本变更自动重跑 + 生产监控 | promptfoo GitHub Action / LangSmith / Phoenix | 全自动 | 闭环流水线 |

## 🌉 与 [03-Reflexion](03-5种prompt模式.md) 的桥：GEPA = prompt 级的 Reflexion

[03](03-5种prompt模式.md) 第 5 种模式的定义是：

> **失败 → 反思 → 重试。**

GEPA 做的是**同一件事，只是作用对象从"输出"换成了"prompt"**：

| | Reflexion（03 章的推理模式） | GEPA（本闭环的④调参） |
|---|---|---|
| 失败 | 这道题答错了 | 这个 prompt 在黄金集上挂了 N 题 |
| 反思 | "上次错在 X，下次应该 Y" | reflection LM 读 metric feedback + 失败样本，假设"prompt 缺什么" |
| 重试 | 带着反思重新作答 | 重写 prompt 候选，再跑评估 |
| 循环终止 | 答对 / 步数上限 | Pareto 候选池收敛 / 预算用完 |

**记忆点**：手动时代你自己做 Reflexion（看失败 → 想为什么 → 改 prompt）；GEPA 把这个循环自动化了，reflection LM 替你写"上次错在 X"那句反思。

## 🔍 ③ 归因速查表（失败模式 → ROIF-CSE 要素 → 修法）

| 失败模式 | 归因要素 | 修法 |
|---|---|---|
| JSON 解析失败 | **F**（Format） | 明示 schema / 换 `json_object` 模式 |
| 漏抽事实 / 漏做步骤 | **I**（Instructions）规则不足 | 补规则条目 |
| 抽了不该抽的 / 做了多余事 | I 过宽 / **E** 缺反例 | 补"不该做"的例子 |
| 中文 / 多语言翻车 | **C**（Context）/ **S** 缺覆盖 | 补多语言 few-shot |
| 被注入攻破 | **E**（Edge）防护缺失 | 加分隔符 + redteam 测试 |
| 角色漂移 / 风格不稳 | **R**（Role）设定弱 | 强化角色 + system 层固定 |

手动归因看 promptfoo 的失败矩阵；自动归因就是 GEPA reflection LM 的工作。

## 🛠️ 最小可跑骨架（两个文件 + 三条命令）

### 文件 1 · `promptfooconfig.yaml`（②摸底 + ⑤验收）

```yaml
description: "mem0 fact extraction golden set"
prompts: [file://prompts/fact_extraction.txt]
providers:
  - openai:gpt-5-nano        # 换成任何你有 key 的模型；litellm 语法
tests:
  - description: "Basic name"
    vars: { conversation: "Hi, my name is Alice." }
    assert:
      - { type: llm-rubric, value: "extracts 'Name is Alice'" }
  - description: "Empty"
    vars: { conversation: "Hi." }
    assert:
      - { type: llm-rubric, value: "returns empty facts list" }
  # ...其余 8 条照搬 08 章 mem0 黄金集
```

### 文件 2 · `optimize.py`（④调参，DSPy GEPA）

```python
import dspy, json

class ExtractFacts(dspy.Signature):
    """Extract user facts from a conversation."""
    conversation: str = dspy.InputField()
    facts: list[str] = dspy.OutputField()

def fact_metric(gold, pred, trace=None):
    expected, got = set(gold.facts), set(pred.facts)
    score = len(expected & got) / max(len(expected), 1)
    fb = f"Score {score}."
    if expected - got: fb += f" Missing: {expected - got}."
    if got - expected: fb += f" Extra(hallucination?): {got - expected}."
    return dspy.Prediction(score=score, feedback=fb)

examples = [dspy.Example(**json.loads(l)).with_inputs("conversation")
            for l in open("golden_set.jsonl")]
train, val = examples[:8], examples[8:]          # ①造卷的产物在这里喂进去

gepa = dspy.GEPA(metric=fact_metric,
                 reflection_lm=dspy.LM("openai/gpt-5"),  # 强模型反思 = 自动归因
                 auto="medium")
compiled = gepa.compile(dspy.Predict(ExtractFacts), trainset=train, valset=val)
```

### 三条命令串起全流程

```bash
# ② 摸底（基线）
npx promptfoo@latest eval -c promptfooconfig.yaml
# ④ 调参（自动优化，机器时间为主）
python optimize.py
# ⑤ 验收（优化后的 prompt 塞回 promptfoo 重跑，对比基线）
npx promptfoo@latest eval -c promptfooconfig.yaml && npx promptfoo@latest view
```

## ⚠️ 诚实边界（自动化的三个陷阱）

1. **metric 是新的 prompt**。GEPA 找的是"在你 metric 定义下的最优"——metric 写歪了（比如只奖励召回不罚幻觉），它就朝歪的方向进化。
2. **黄金集太小（<30）时容易过拟合**：train 上 100%，val 上回落。⑤验收必须留 holdout，这也是为什么闭环拆成 ④/⑤ 两步。
3. **首版 prompt 仍值得手写好**（按 [02-ROIF-CSE](02-ROIF-CSE-7要素解析框架.md)）：起点越好，优化器收敛越快、越不易锁死局部最优。**工具消灭的是"反复手动迭代"，不是"第一次的认真思考"**。

## 🏆 方案对决：④调参的两种路线——纯 Prompt 优化闭环 vs RL 介入闭环

> **触发问题**：④调参这一步，GEPA 式 prompt 进化（方案 A）和强化学习介入（方案 B）怎么选？
> **证据**：2026-08-17 用本仓 [`讲透Agent/实战案例-RL领域Agent/`](../../讲透Agent/实战案例-RL领域Agent/README.md) 的双环 agent 做了**四象限对照实验**（同 seed 同任务，目标 = reward − 0.02×步数）。

### 一、两方案的正确定位（先消除伪对立）

在 [2502.11560 优化框架](../../讲透Prompt/Prompt综述精华-四篇地图.md)（离散/连续/混合三空间）里：

| | 方案 A：Prompt 优化闭环 | 方案 B：RL 介入闭环 |
|---|---|---|
| 优化对象 | 离散空间 $\mathcal{P}_d$ 的**指令/示例** | bandit/MDP 的**策略参数**（Q 表；深水区是模型权重 $\mathcal{P}_c$）|
| 在 11 章闭环的位置 | ④调参（GEPA/DSPy）| ④调参的另一实现 + ②摸底持续在线化 |
| 信号 | 评估分数（黄金集）| 环境奖励（可验证/塑形）|
| 对应 03 章 | Reflexion 作用在 prompt 上 | Reflexion 作用在策略/记忆上 |

**伪对立**：两者都是"评估信号驱动的搜索"，区别只在**参数化层**——这正是 [讲透Agent/05](../../讲透Agent/05-自进化延伸.md) What 轴的 Prompt 层 vs 模型层。

### 二、四象限实测（收益重叠实验）

```
A. 冷启动+默认prompt      0.964（步数1.8）
B. 冷启动+APO最优prompt   0.980（步数1.0）  ← APO 增益 +0.016
C. RL训练20任务+默认prompt 0.980（步数1.0） ← RL  增益 +0.016
D. RL+APO 双环           0.980（步数1.0）  ← 叠加增益 +0.000 ⚠
```

**三个结论**：
1. **B = C**：本 toy 中 prompt 先验与 Q 表在决策上是加性可互换项（`pick = argmax[Q + prior]`）——**谁到位都行，冷启动 APO 快一个量级**（1 次评估循环 vs 20 任务学习）。
2. **D ≠ B+C**：收益 100% 重叠（toy 中）。两个方案是同一策略的两个入口，**不是两种独立能力**——"全都要"不会双倍收益。
3. **过拟合对照**：APO 过拟合黄金集（⑤验收必须 held-out）；RL 过拟合环境分布（流量小时 Q 表噪声大）。防法都在闭环的⑤。

### 三、八维对比与选型

| 维度 | A：Prompt 闭环（GEPA/DSPy）| B：RL 介入（bandit/RLVR）| 胜者 |
|---|---|---|---|
| 冷启动速度 | 分钟级（一次评估循环）| 需 ~20+ 任务积累 | **A** |
| 每次改动成本 | LLM 调用重跑黄金集 | 线上流量自然喂（零额外成本）| **B** |
| 可解释/可审查 | prompt 人类可读可 diff | Q 表/权重是数字 | **A** |
| 可迁移/可复制 | prompt 文本跨机复制 | 经验表绑定环境 | **A** |
| 跟随分布漂移 | 需重跑闭环（人触发）| 在线持续跟随 | **B** |
| 上界（AlignPro）| 有：模型能力边界 | bandit 同顶；**动权重可破**（但成本+风险跳档）| 平（toy）/ B（深水区）|
| 需要可验证奖励 | 否（judge/人评即可）| **是**（RLVR/塑形——reward 设计错=学错）| A |
| 过拟合风险面 | 黄金集 | 环境 + 奖励函数 | 平 |

### 四、分层结论（不是二选一，是接力）

```
上线第 1 天（无流量）   → 方案 A：GEPA/APO 快速到位（手册 11 章六步全流程）
上线第 N 天（有流量）   → 方案 B：Q 表/bandit 在线接管，持续跟随分布
                       （A 的收益被 B 逐步"重叠吸收"——实测 D=C，不浪费但也不叠加）
能力到顶要突破          → 方案 B 深水区：RLVR 微调权重（P3 路径，讲透Prompt/09 §3.1；
                          成本/风险跳档，toy 验证不了，走讲透RL/05 的真实验）
```

**一句话**：**A 是冷启动引擎，B 是巡航引擎；收益重叠（实测 B=C=D）意味着先后接力而非并行堆叠。**

> **v3 后续（同日）**：该案例已扩为**三进化环**——Q 表（B 形态）+ APO（A 形态）+ **Ctx-APO**（context 栈配置的 A 形态进化，MemAgent arXiv:2507.02259 思想 toy 版：把检索深度/记忆预算/路由/bookend 变成被奖励信号优化的对象）+ kb_curate（实验结论固化回知识库）。见 [README v3](../../讲透Agent/实战案例-RL领域Agent/README.md)——恰好是本文"接力"结论的活体实现：同一 RLVR 信号驱动 A/B 两形态各改各的层。

### 五、诚实边界（toy → 真实的修正）

- toy 中 prompt 先验与 Q 表数学上完全同构（都是决策加项）→ 重叠 100%。**真实 LLM 场景 prompt 还改变检索关键词/输出格式/推理路径**，作用面更广，重叠度会低于 100%——A 的独立价值比 toy 显示的更大。
- 方案 B 的深水区（GRPO/PPO 动权重）在本实验完全未触及——那是 [讲透RL/03·05](../../讲透RL/) 的领域，且有模型坍缩/奖励 hacking 风险（审查报告 P0-1 的活体教训：奖励判定错 1 行，agent 就学坏）。
- 学术对照：GEPA（2025）声称反思式 prompt 进化**胜 RL**——与本实验"B=C 时 A 更快更便宜"一致；但它是离散空间结论，不覆盖权重层。
