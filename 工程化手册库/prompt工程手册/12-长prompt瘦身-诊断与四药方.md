# 12 · 长 prompt 瘦身：诊断与四药方

> **核心论点**："长"不是一种病，是四种病——指令冗余（I）/ 例子堆积（S）/ 上下文膨胀（C）/ 历史滚动。不诊断就删 = 乱开药。
> **触发问题**：用户问"prompt 太长一般是怎么解决的？"
> **本文是什么**：诊断脚本（可跑）+ 四药方 + "不删也能治"（缓存/位置）+ mem0 真实瘦身案例（476→143 行，实测 -70%）。

---

## 🎯 要点速览

1. **先计量再动手**：分段数 token，找肥肉在哪段（脚本见 §一）
2. **一半问题不用删**：稳定前缀吃 prompt caching，长 ≠ 贵（§三）
3. **删减必须走验收**：[11 章闭环](11-自动化优化闭环-六步流水线.md)的②摸底→删→⑤验收。**prompt 不是越短越好，是信息密度越高越好**
4. **删过头比留长更危险**：指令不足 → 模型开始猜，错误从"贵"变成"错"

---

## 一、诊断：肥肉在哪（10 分钟，可跑）

通用版诊断脚本（标准库零依赖，按 markdown 标题切段）：

```python
import re

def profile(prompt: str) -> None:
    total_tok = len(prompt) // 4          # 英文粗估；中文用 len/1.5
    print(f'总计 {len(prompt.splitlines())} 行  ~{total_tok} token')
    marks = [(m.start(), m.group(0).strip()) for m in re.finditer(r'^#{1,2} .+$', prompt, re.M)]
    marks.append((len(prompt), 'END'))
    for i in range(len(marks) - 1):
        seg = prompt[marks[i][0]:marks[i+1][0]]
        pct = 100 * (len(seg) // 4) // max(total_tok, 1)
        print(f'{marks[i][1][:38]:40} {len(seg.splitlines()):4} 行 {len(seg)//4:5} tok ({pct}%)')

profile(open('your_prompt.txt').read())
```

**判读标准**：

| 段 | 健康占比 | 超标信号 |
|---|---|---|
| 指令（I） | ≤30% | 规则重复/互相覆盖、"be helpful"类废话 |
| 例子（S） | ≤40% | 例子的**输入内容**比例子要教的**模式**还长 |
| 上下文（C） | 按需 | 塞了整篇文档但任务只用 3 段 |
| 历史消息 | 滚动摘要 | 原样带全部过往轮次 |

## 二、四药方

### 病 1 · 指令冗余（I 肥）

| 药方 | 做法 | 效果 |
|---|---|---|
| **删废话** | "You are a helpful assistant"、重复安全声明、礼貌用语 | -10~20% |
| **合并同族规则** | "不要 markdown""不要 YAML""只要 JSON" → "只输出 JSON"（正面表述，[10](10-常见反模式-30条铁律.md)） | 规则数减半 |
| **schema 代散文** | 20 行格式描述 → 一个 JSON Schema | 更短**且**更可靠 |
| **分层** | 稳定规则进 system，动态内容进 user，别重复 | 利于缓存 |

### 病 2 · 例子堆积（S 肥）

- **砍量**：保留最有区分度的（1 正例 + 1 空边界 + 1 最易错 + 1 机制演示）；旗舰思考模型 0-3 个——2026-08-17 [GLM-CtxAPO 实测](../../讲透Agent/实战案例-RL领域Agent/GLM-CtxAPO实验报告.md)：在最优 RCF prompt 上加 1 条 few-shot 即掉分（5/6→4/6）且思考 token ×2.4，**思考模型上 few-shot 是负资产**（与本章"信息密度"论断互证：例子的输入内容稀释注意力）
- **砍例本身**：教"空输入返回空"用 `"Hi." → {"facts": []}` 一行，不要 30 行对话
- **砍解说**：例子尾部的"lessons learned"解说段，压成一行括号注释
- **自动挑**：DSPy `BootstrapFewShot` 从训练集自动选最小充分例子集——[11 章闭环](11-自动化优化闭环-六步流水线.md)④调参的免费副产品

### 病 3 · 上下文膨胀（C 肥）

- **RAG top-K**（[10](10-常见反模式-30条铁律.md) #19 正解）：检索相关 chunk，不塞全文档
- **Map-Reduce 分段摘要**：智谱/Kimi 官方指南同款——逐级归纳，单次瘦身 10-100 倍
- **工具化**：静态参考资料变 tool，按需 fetch——"全部预付"变"按用计费"

### 病 4 · 历史滚动 / 架构性臃肿

- **多轮历史**：滚动摘要替代原样全带（Kimi 官方建议保留最新 ~20 条）
- **拆 pipeline**：一个巨型 prompt 干 N 件事 → N 个小 prompt 链
- **路由分类**（Kimi 官方技巧）：先分类查询，只注入该类需要的指令子集——40 条规则分流后单次只带 8 条

---

## 三、不删也能治：缓存与位置

**长 ≠ 贵**。两件事比删更先做：

1. **Prompt caching**：**永不变化的部分**（system + 规则 + few-shot）放最前，**变化的部分**（用户输入）放最后。GLM-5.3 隐式缓存自动命中；OpenAI/Anthropic/Kimi 有显式 caching。4000 token 中 3500 是稳定前缀 → 实际成本接近 500。
2. **位置重排**（lost in the middle 对策）：中段信息利用率最低，**关键规则开头结尾各出现一次**（bookend，[06](06-模型差异矩阵.md)）。零成本，先做。

## 五、真实案例：mem0 ADDITIVE_EXTRACTION_PROMPT 瘦身（2026-08-17 实测）

> 源文件：`~/ai/photo/ocr/mem0/mem0/configs/prompts.py:468-944`（[09 章](09-实战案例-mem0-检测报告.md)的诊断对象）
> 瘦身版：[`prompts/mem0_additive_slim.txt`](prompts/mem0_additive_slim.txt)（可直接进 promptfoo）

### 诊断（§一脚本实测）

| 段 | 原版 | 占比 | 判定 |
|---|---|---|---|
| # ROLE | 8 行 / 212 tok | 3% | ✅ 健康 |
| # INPUTS | 73 行 / 976 tok | 12% | ⚠️ 解说过长 |
| # GUIDELINES | 153 行 / 3371 tok | **40%** | 🔴 最肥 |
| # EXAMPLES | 203 行 / 3240 tok（11 例实占 237 行 / 3818 tok） | **45%** | 🔴 最肥 |
| # CHECKLIST + # OUTPUT | 37 行 / 611 tok | 7% | ✅ 健康 |

原版总量：**476 行 / 33,653 字符 / ~8,413 token**。（修正 [09](09-实战案例-mem0-检测报告.md) 的 ~4000 token 估算：实际翻倍。）

### 处方（对应 §二）

| 动作 | 依据 |
|---|---|
| 例子 11 → 4（保留：多主题正例 / 空返回 / 文档抽取反 meta-extraction / linking 机制） | 病 2 砍量——每类错误一个代表；砍掉的 7 个（dedup/时态/多说话人/结构化数据等）教的模式已由 GUIDELINES 规则覆盖 |
| 例子尾部解说段压成一行括号注释 | 病 2 砍解说 |
| GUIDELINES 153 → ~55 行：Bad/Good 对从 ~15 组砍到 6 组最典型（transition/proper noun/qualifier/meaning 三反例等） | 病 1 合并同族——剩余 6 组已覆盖全部错误类别 |
| INPUTS 73 → ~25 行：解说减半、Optional 4 条压 1 行 | 病 1 删废话 |
| **Integrity Rules 8 条全保、FINAL CHECKLIST 全保、OUTPUT schema 全保** | 诚实边界——防幻觉核心，删过头比留长更危险 |

### 结果（实测）

| 指标 | 原版 | 瘦身版 | 变化 |
|---|---|---|---|
| 行数 | 476 | 143 | **-70%** |
| 字符 | 33,653 | 10,207 | -70% |
| token 粗估 | ~8,413 | ~2,551 | **-70%** |
| 例子数 | 11 | 4 | -64% |
| Integrity Rules | 8 | 8 | 0（全保） |

### 验收方案（换上生产前必做，对应 [11 章闭环](11-自动化优化闭环-六步流水线.md)②→⑤）

1. 黄金集：用 [08 章](08-黄金集模板.md) mem0 十条起步，**针对砍掉的 7 个例子各补 1 条对应 case**（共 ~17 条：dedup、旧观察日期时态、多说话人、D&D 结构化数据……）——砍掉的每个例子都是一条潜在回归风险，黄金集必须替它站岗
2. 双 prompt 进 promptfoo（原版 vs 瘦身版同 config A/B），指标：抽取召回 / 幻觉率（Extra）/ JSON 合规率 / token 成本
3. 通过线：召回与幻觉均不劣于原版 -2pp 以内、成本 -60% 以上才算成功；否则把对应被砍例子加回
4. 注意：ADDITIVE 是 **system prompt**（稳定前缀），若模型侧有缓存，**钱的收益会小于 70%**（缓存命中部分本来就打折）——瘦身的真正收益是**注意力密度**（lost in the middle 缓解）与非缓存场景

## 五·二 · 案例实战 2：DEFAULT_UPDATE_MEMORY_PROMPT（病 2 极端形态，2026-08-17 实测）

> 源：`~/ai/photo/ocr/mem0/mem0/configs/prompts.py:176-324`　工件：[`prompts/mem0_update_slim.txt`](prompts/mem0_update_slim.txt)
> 选材：对文件剩余 6 个 prompt 全量跑 §一脚本后，它最肥（148 行/~1327 tok；其余：ANSWER 9 行健康、FACT 45 行已被 ADDITIVE 替代、PROCEDURAL 77 行中等）。

### 诊断（§一脚本实测）

| 段 | 原版 | 判定 |
|---|---|---|
| 头部规则 | 13 行 / 156 tok（12%） | ✅ 健康 |
| 4 个例子（Add 27 / **Update 48** / Delete 31 / NoChange 29 行） | ~1169 tok | 🔴 **占 88%**——比案例 1 的 45% 更极端 |

每个例子都重复完整的 Old Memory 列表 + New Memory 全量输出（纯 JSON 结构行 103 行）。

### 处方（这个 prompt 的结构优势）

**输出 JSON 天然每行带一个 event——一个合并例子就能同时演示 ADD/UPDATE/DELETE/NONE 四种操作 + schema**，4 例 → 1 例不丢信息。配合病 1 处方：例子里的判定语义（pizza 同义不更新 / cricket 信息更多则更新 / 矛盾触发 DELETE）**提炼成显式规则上移**，不能只留在被砍的例子里。ID 规则（ADD 新建 / UPDATE·DELETE 复用原 ID）全保。

### 结果（实测）

| 指标 | 原版 | 瘦身版 | 变化 |
|---|---|---|---|
| 行数 | 148 | 37 | **-75%** |
| token | ~1,327 | ~527 | **-61%** |
| 例子数 | 4（独立） | 1（四 event 合并） | 语义 10 关键词自检全 ✅ |

### 补岗验收（针对砍掉的 3 个独立例子）

黄金集必须加 3 条 guard case：① 空记忆 + 新事实 → 全 ADD；② 矛盾事实 → DELETE 且**复用原 ID 不新建**；③ 同义改写 → NONE 不触发 UPDATE。第 ②③ 条是最易回归点——判定语义从例子搬进了规则，规则没读进去就会翻车。

### 附加发现（病 1 的跨 prompt 形态）

`get_update_memory_messages`（prompts.py:406-460）尾部拼的 24 行/~302 tok 指令，与 system prompt 的 ADD/UPDATE/DELETE 语义**重复解释**（还带一段独立的 output schema 描述）。system 侧瘦身后的规则已覆盖——尾部可砍到只剩 JSON schema + "return only JSON"，合计还能再省 ~200 tok。未动其代码（mem0 仓库），记为建议。

## 六、批判边界

1. **删过头比留长更危险**：错误从"贵"变成"错"。效率维度（[04](04-6维度客观评价标准.md)）是 6 维中最不该单优化的。
2. **"500 字以内"别死记**（[10](10-常见反模式-30条铁律.md) #29 的数字是给弱指令遵循模型的）：旗舰模型 2000 token 结构良好的 system prompt 完全正常——**关键是密度，不是绝对长度**。
3. **判断标准始终是黄金集**：删完通过率不掉 = 安全；掉了 = 删多了，加回来。
