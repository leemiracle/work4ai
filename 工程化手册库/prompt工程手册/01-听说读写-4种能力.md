# 01 · 听说读写 prompt：4 种能力

> **核心论点**：90% 的人只会"写 prompt"——结果一辈子水平没进步。学语言要听说读写，**学 prompt 完全一样**。

---

## 🎧 听（读懂别人的 prompt）

**核心能力**：拿到任何 prompt（GitHub / 论文 / 泄露 system prompt），**30 秒内**用 ROIF-CSE 拆解。详见 [`02-ROIF-CSE`](02-ROIF-CSE-7要素解析框架.md)。

### 听的 3 个层次

**L1 · 字面听**：读懂 prompt 在说什么。
**L2 · 结构听**：识别 7 要素（ROIF-CSE）+ 5 模式（CoT/ReAct/...）。
**L3 · 意图听**：理解 prompt 作者为什么这么写——他怕什么失败？他优化什么指标？

### 练习材料
- **生产 prompt**：`github.com/TrustedSource/leaked-system-prompts`（所有主流 AI 产品的 system prompt 泄露）
- **论文 prompt**：CoT / ReAct / Reflexion 论文附录
- **Anthropic Prompt Library**：`docs.anthropic.com/en/prompt-library`（几十份生产级 prompt）
- **OpenAI Cookbook**：`cookbook.openai.com`

### 练习方法
拿一份 prompt，3 分钟回答：
1. **R**：作者给它什么角色？为什么这个角色？
2. **O**：核心目标 1 句话是什么？
3. **I**：有 N 条指令，哪条是"安全网"（防 failure mode）？
4. **F**：输出格式是什么？为什么选这个？
5. **C**：需要什么 context？作者怎么传 context？
6. **S**：few-shot 例子选了什么场景？为什么？
7. **E**：边界 case 怎么处理？

## ✍️ 写（输出 prompt）

### 写 prompt 的 5 种模式（详见 [`03-5种prompt模式`](03-5种prompt模式.md)）

| 模式 | 何时用 | 反模式 |
|---|---|---|
| **Zero-shot** | 简单任务 / 强模型 | 复杂推理 |
| **Few-shot** | 需要特定格式 / 风格 | 例子 ≠ 目标 |
| **CoT** | 多步推理 / 数学 | 强制 CoT 在简单任务（浪费）|
| **ReAct** | 需要工具 / 检索 | 不提供工具时 |
| **Reflexion** | 长任务 / 可验证 | 不可验证任务 |

### 写 prompt 的 7 个常见错误（详见 [`10-反模式`](10-常见反模式-30条铁律.md)）

1. **负面指令**：「不要用 markdown」→ 改成「用流畅散文」
2. **角色太抽象**：「你是专家」→ 改成「你是 15 年 React 经验的 staff engineer」
3. **没说格式**：让模型自己决定 → 一定不稳定
4. **例子格式不一致**：3 个 few-shot，3 种输出格式 → 模型蒙
5. **指令在前，数据在后**：长文档场景**反过来**
6. **没 edge case**：「找所有 bug」→ 找不到时模型编造
7. **一次要太多**：8 个约束同时给 → 模型丢 1-2 个

## 📐 学习路径建议

### 第 1 周（建立"听"和"读"）
- 每天读 3 份 Anthropic Prompt Library
- 用 ROIF-CSE 拆解 1 份泄露 system prompt

### 第 2 周（建立"说"）
- 加入 Discord / Reddit prompt 社群
- 用 L3 层次（黄金集 + 跨模型）分享 1 个你写的 prompt

### 第 3-4 周（建立"写"）
- 用 ROIF-CSE 模板写 5 个 prompt
- 用 Promptfoo 测试，找到你 prompt 的失败模式
- 用 DSPy GEPA 自动优化 1 个
