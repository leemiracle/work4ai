# 11 · 自动进化闭环：估 → 提取特征 → 优化 → 自动化

> **核心论点**：harness 本身可以成为优化对象——但前提是"可观测"。观测性是自动进化的第一瓶颈。
> **本文是什么**：AHE 三观测性支柱 + 进化闭环设计 + 防过拟合的验证协议。

---

## 🔄 闭环总览

```
        ┌──────────────────────────────────────────┐
        │                                          │
        ▼                                          │
   ① 估（跑基准/任务集，得质量信号）                   │
        ↓                                          │
   ② 提取特征（从海量轨迹蒸馏可行动的证据）              │
        ↓                                          │   模型不动
   ③ 优化（改 harness：tools/middleware/记忆/参数）    │   只改环境
        ↓                                          │
   ④ 自动化（每步编辑绑定可证伪预测，下轮验证回滚）──────┘
```

这就是 prompt工程手册 11 章六步流水线在 harness 层的同构——**对象从 prompt 换成了 harness 组件**。区别：prompt 是离散文本空间（GEPA 反思搜索），harness 是结构化组件空间（文件级表示 + 可回滚编辑）。

---

## 🔬 AHE 三观测性支柱（arXiv:2604.25850，当前最强实证）

| 支柱 | 机制 | 解决什么瓶颈 |
|---|---|---|
| **① 组件可观测** | 每个可编辑组件一个**文件级表示**（七类组件：tools/middleware/memory/...）| 编辑空间显式化且可回滚——" heterogeneous action space"问题 |
| **② 经验可观测** | 海量轨迹 token → 分层 drill-down **证据语料**（蒸馏成根因，不是原始日志）| 进化 agent 吃不下百万 token 轨迹 |
| **③ 决策可观测** | 每次编辑配**自 declared 预测**（"这个改动应该提升 X"），下轮用任务结果**证伪** | 编辑归因难——无效改动按文件粒度回滚 |

**核心洞察**：harness 进化瓶颈**不是 agent 能力而是可观测性**——给进化 agent 清晰的动作空间 + 结构化证据 + 可证伪契约，它就能可靠收敛。

**战果**：Terminal-Bench 2 69.7%→77.0%（10 轮，超人工 Codex 71.9%）；冻结迁移 SWE-bench-verified 最高聚合 + 省 12% token；跨模型家族 +5.1~+10.1pp。

**消融的警示**（01 章已引，这里从进化视角再看）：增益全部在 tools/middleware/长期记忆；**system prompt 单独进化是负收益**——进化方向选错层，闭环越勤快越糟。进化空间要排除 prompt-only。

**准入门槛**（没达到别开闭环）：
- 有一套可重复的评估（⑥上岗的回归集，prompt 手册 11 章六步之"造卷"）
- 组件已文件化（能被编辑/回滚；写死在代码里的不叫组件）
- 每轮进化的编辑数 ≤ 3（多编辑 = 归因失效）

## 🛡️ 防过拟合协议（AHE 的验证设计，直接抄）

1. **冻结迁移验证**：在 A 基准上进化 → 冻结 harness → 在 B 基准上验证增益保持。掉了 = 过拟合 A
2. **跨模型迁移验证**：换底座模型再跑——增益应保持（保持的是工程经验，不是模型怪癖）
3. **消融归因**：每类组件单独 A/B——增益必须能定位到组件（定位不了 = 增益可疑）
4. **进化日志留痕**：每轮 edits + predictions + 结果 = 审计线（这也是 06 章证据链在进化层的延伸）

**元层生态**（2026 下半年最活跃方向）：revfactory（生成团队 harness）、penguin-harness（RSI 自进化）、ruflo-metaharness（打分）、Harness Evolver（论文化）、Trellis update-spec（新规则晋升回规范）——**"造 harness 的 harness"**。你的进化闭环成熟后，它自己也可以是被 harness 管理的任务（递归一次就够，别无限套娃）。
