# 03 · 六组件解剖：H = (E, T, C, S, L, V)

> **核心论点**：harness 可以形式化为六元组——每件都可治理、可评估、可替换。
> **本文是什么**：Meng et al. 六组件逐件拆解 + Completeness Matrix 自检 + 与七层/六责任的对照。

---

## 🧩 六组件定义（preprints 202604.0428，2026-08 一手核实）

| 组件 | 符号 | 职责 | 最小实现 | 缺失后果（综述实证）|
|---|---|---|---|---|
| **Execution Loop** | E | observe-think-act 循环、终止条件、错误恢复 | while + max_turns + stop_reason 分支 | 无限循环 / 无刹车 |
| **Tool Registry** | T | 类型化工具目录、路由、schema 校验、监控 | Pydantic → JSON Schema → 校验 → 执行 | 工具幻觉、参数错乱 |
| **Context Manager** | C | 什么进上下文、压缩、检索 | 文件上限 + 分页 + 工具结果预算 | 上下文爆炸 / 关键信息丢失 |
| **State Store** | S | 跨轮/跨会话持久化、崩溃恢复 | JSONL 追加日志 + progress.md | 失忆、重复劳动 |
| **Lifecycle Hooks** | L | auth、日志、策略执行、埋点 | pre-call 权限钩子 + post-call 审计 | **无法执行安全策略** |
| **Evaluation Interface** | V | 轨迹、中间态、成功信号 | 测试命令 + 通过/失败即证据 | **无法调试失败** |

**Completeness Matrix 实证发现**（23 系统编码）：生产级系统**全部六组件齐备**；研究原型普遍只有 E+T。缺 S 无法崩溃恢复，缺 L 无法安全，缺 V 无法调试——三件"看不见"的组件恰是 demo 与生产的分界线。

## 🔍 四种切法对照（同一对象，不同刀）

| 切法 | 来源 | 组件 | 独有洞察 |
|---|---|---|---|
| **六组件** | Meng et al. 2026.04 | E/T/C/S/L/V | 枚举完备，23 系统实证 |
| **七层 ETCLOVG** | Li et al. 2026（OpenReview）| E/T/C/L + **O**观测 + V + **G**治理 | O 和 G 在生产各有独立工具栈、不同团队——必须独立成层 |
| **code 三层** | Ning et al. arXiv:2605.18747 | Interface / Mechanisms / Scaling | 代码是最佳 harness 媒介：**可执行**（验证）、**可检视**（trace）、**有状态**（程序=进度）|
| **六运行时责任** | Guo et al. arXiv:2606.20683 | observation/context/control/action/state/verification-governance | 运行时视角：memory 部署时由 context 选择+工件存储+检索索引+checkpoint 任一实现 |

**统一最小共识**（四刀交集）：E / T / C / S / 验证治理(V+G) / 可观测(O)。记忆（memory）在功能环里是 state，在部署中是 C+S 的组合实现——别把它当第七件，当 S 的一种持久化策略。

## 🛠️ E 组件：执行循环骨架（一切的核心）

```python
def agent_loop(model, tools, max_turns=40):
    messages = bootstrap()               # START 仪式（07 章）
    for turn in range(max_turns):        # 终止条件 1：轮数上限
        resp = call_model(messages, tools)
        if resp.stop_reason != "tool_use":
            return final(resp)           # 终止条件 2：模型收工
        for tc in resp.tool_calls:
            if not authorized(tc):       # L 组件挂点
                result = deny(tc)
            else:
                result = execute_with_budget(tc)  # C/T 预算
            messages.append(tool_result(tc, result))
    return timeout_summary(messages)     # 终止条件 3：超限也要可交接
```

三个终止条件一个不能少：**自然结束 / 轮数上限 / 超时**。第三种必须产出交接摘要（07 章），否则前功尽弃。

## 🛠️ T 组件：工具注册三道关

```
1. schema 校验（Pydantic/JSON Schema）—— 参数错在门前拦
2. 执行沙箱/白名单 —— Scope 子系统的执行端
3. 结果预算 + 截断（参数见 04 章）—— 防 60KB grep 结果灌爆窗口
```

工具描述本身是 prompt（"错误信息教模型下一步"）：Claude Code 的超限报错直接写"用 offset/limit 或 grep"——**报错即导航**。

## 🛠️ L 组件：钩子挂点地图

```
prepare_context      → 注入合规策略/审计上下文（C 前置）
authorize_tool_call  → 权限门（fail-closed：无规则=拒绝）
process_tool_result  → 脱敏/压缩/审计日志（C 后置）
on_event / on_error  → 监控、告警、恢复路径（O 层喂料）
```

（钩子名来自 Pi/AWS harness-sdk 实现层，非 Meng 论文原文——概念一致，命名各家不同。）
