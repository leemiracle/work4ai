# 05 · 状态与记忆：最小四文件 + 四层架构

> **核心论点**：agent 的失忆不是模型问题，是 S 组件缺失。四个文件起步，会话立刻显著稳定。
> **本文是什么**：最小落地 → 四层记忆 → git 化记忆（2026 新趋势）。

---

## 📦 最小四文件（walkinglabs 实证）

```
project/
├── AGENTS.md           # 指令宪法：你是谁、怎么干活、去哪查（Tier 1+2）
├── init.sh             # 环境自检：依赖/工具/版本，FAIL 即停
├── feature_list.json   # 任务账本：唯一事实源，做完勾销
└── progress.md         # 进度+证据：做到哪、怎么验证的、还剩什么
```

> "四个文件，agent 会话立刻显著稳定。"——不是修辞，是教程的实验结论。

**设计原则**：
- **事实源单一化**：任务状态只活在 feature_list.json 一处；progress.md 记叙事与证据
- **账本优先于记忆**：宁可让 agent 每次读文件，不要指望它"记得"
- **git 管理**：状态文件进版本控制——状态可回滚、可审计、可交接

**本仓库活例子**（work4ai 自身就是这套约定）：`.agent/MEMORY.md`（跨会话教训，一行=教训+证据+日期）+ `progress` 型文档 + `git 状态即审计`。**会话死了，账本活着**。

## 🧠 四层记忆架构（学术版，Meng/Ning 综述交叉）

| 层 | 管什么 | 时间尺度 | 代表 |
|---|---|---|---|
| **Working Memory** | 修复轨迹、运行时编辑状态 | 单任务内 | SWE-agent, CodeMem |
| **Semantic Memory** | 仓库结构、代码证据、检索片段 | 跨任务、按需检索 | AutoCodeRover, RepoCoder |
| **Experiential Memory** | 轨迹反思、经验教训 | 跨任务、回放 | ExpeL, MemGovern |
| **Long-term Memory** | intent-to-code 映射、验证过的修复 | 跨项目、沉淀 | MemCoder, TALM |

四层的工程含义：**不同时间尺度用不同存储**——working 活在窗口里，semantic 活在索引里，experiential 活在反思文件里，long-term 活在知识库（含记忆三家：agentmemory 27k★/memU 14.3k★/memsearch）里。

**记忆独立成品的产业信号**：qm（13.6k★）让员工自选 harness，但记忆必须沉淀——"harness 可换，记忆不能丢"。

## 🌿 git 化记忆（Letta Context Repositories，2026 新范式）

```
memory/ 是一个 git 仓库：
- agent 自己写/合并/回滚记忆（commit message 即记忆说明）
- 多子代理在隔离 worktree 并发学习 → git merge 合并认知
- system/ 目录 = Tier 1 常驻（agent 自己管理什么钉在上下文）
- 记忆碎片化 → "defragmentation" 子代理重整为 15-25 个聚焦文件
- sleep-time 后台反思进程定期把重要信息 commit 进去
```

**为什么 git 是对的媒介**（呼应 03 章 code-as-harness）：可执行（操作有确定结果）、可检视（diff 可读）、有状态（历史可回溯）、**可并发**（worktree+merge 解决"记忆形成是单线程"的老问题）。

与 work4ai 的 `.agent/MEMORY.md` 策展约定同构：**教训=commit，重复出现=合并升格，3 次不触发=归档衰减**。

## ⚠️ 记忆的三种死法（每种都有对策）

| 死法 | 症状 | 对策 |
|---|---|---|
| **漂移（drift）** | 记忆过期，与现状矛盾 | TTL + 写前验证 + provenance 标注 |
| **过度泛化** | 一次经验当永远真理 | 记忆条目带适用域（"在 X 仓库/Y 模型下"）|
| **污染（pollution）** | 错误经验毒害未来决策 | 验证过的才入长期层（MemGovern 式过滤）|

**铁律**：记忆是**泄漏面**（隐私）+**毒药面**（错误沉淀）——入长期层前过验证门（06 章），出库时带来源。
