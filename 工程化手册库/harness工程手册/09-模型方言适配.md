# 09 · 模型方言适配：thinking 参数与 Preserved Thinking

> **核心论点**：harness 的 provider 适配层里，最深的坑不是消息格式，是"思考"的表示与保留。
> **本文是什么**：五家 thinking 参数映射表 + Preserved Thinking 铁律（与 prompt 手册 06 章互补：那边讲 prompt 方言，这边讲运行时方言）。

---

## 🗺️ thinking 参数五家对照（2026-08 官方文档核实）

| 家 | 参数 | 取值 | 关得掉吗 | 思维链字段 |
|---|---|---|---|---|
| **GPT（OpenAI）** | `reasoning_effort` | low/medium/high | effort=low 近似关 | 不返回（黑盒）|
| **Claude** | extended thinking | on/off + budget_tokens | ✅ | thinking 块（可回传续接）|
| **GLM（智谱）** | `thinking.type` | enabled/disabled | 4.6/5/5.1/5.2 可关；**4.7 强制开**；**5.3 取消 disabled，改 reasoning_effort low/high/max** | `reasoning_content` |
| **Kimi（月之暗面）** | `thinking.type + keep` | k2.5/k2.6 可开关；**k2.7-code 永远开**；k3 改 reasoning_effort low/high/max | 见左 | `reasoning_content` |
| **Gemini** | `thinkingBudget` | 0~N（0=动态，-1=关）| ✅ | thought summaries（可选）|

**适配层设计**：统一抽象为三档（off / auto / force）+ 预算（token 数），per-model 映射：

```python
THINKING_MAP = {
    "gpt-5":      lambda mode, budget: {"reasoning_effort": {"off":"low","auto":"medium","force":"high"}[mode]},
    "glm-5.3":    lambda mode, budget: {"reasoning_effort": {"off":"low","auto":"high","force":"max"}[mode]},  # 不可真关
    "glm-4.6":    lambda mode, budget: {"thinking": {"type": {"off":"disabled","auto":"enabled","force":"enabled"}[mode]}},
    "kimi-k2.6":  lambda mode, budget: {"thinking": {"type": "enabled" if mode!="off" else "disabled", "keep": "all"}},
    "gemini-2.5": lambda mode, budget: {"thinkingBudget": budget or (8192 if mode=="force" else 0)},
}
# 注意：GLM-5.3 / kimi-k2.7 的 "off" 是假的——只能降档，不能真关。计费按输出 token，思维链照算钱。
```

## 🔒 Preserved Thinking：跨轮保留思维链的铁律

**问题**：多轮 agent 会话中，上一轮的 `reasoning_content` 默认被清除（省 token）。但长程任务需要模型"接着上次的思路想"。

| 家 | 开关 | 行为 |
|---|---|---|
| GLM | `clear_thinking: false` | 保留历史轮思维链 |
| Kimi | `thinking.keep: "all"` | 同上；**k2.7-code 强制 all，不可关** |
| Claude | 回传 thinking 块 | 原生支持续接 |

**⚠️ 两条铁律（两家文档原文级一致，说明是硬约束）**：

1. **原样透传**：开启保留后，历史 `reasoning_content` 必须在 `messages` 里**完整、未修改、按原顺序**回传——缺失/裁剪/改写/重排会导致效果下降或直接失效。实现上：把上一轮 API 返回的 assistant 消息**整条 append 回 messages**，不要手工重组。
2. **计费照算**：保留的思维链持续占上下文、持续计费。GLM Coding Plan 按 output 系数（5.3 是 24），Kimi 文档明说 "billed accordingly"。

**衍生工程约束**：
- 会话存储要保存**原始响应对象**（含 reasoning_content），不能只存 content
- 压缩逻辑（04 章）要感知思维链：Preserved Thinking 开启时，思维链块的保护优先级高于普通历史
- 双模型协作时 thinking 字段不互通——切换模型 = 思维链断，长程任务别中途换模型

## 🔌 端点方言（09 章独有：同一家不同端点行为不同）

- GLM coding 端点（`/api/coding/paas/v4`）：订阅过 Coding Plan 的账号**只能走 OpenAI Chat Completion 协议**（Anthropic 协议暂受限）
- Kimi：`api.moonshot.ai` 提供 OpenAI / Anthropic **双兼容**端点
- Claude Code / OpenClaw 可直接把 GLM Coding Plan 配成后端（`~/.claude/settings.json` 改 model name 即升级）

**工具调用 ID 方言坑（自部署 Kimi 时）**：K2 系工具调用 ID 必须是 `functions.{函数名}:{全局递增序号}`；ID 不对 → tool-call crash（content 吐 `<|tool_call_begin|>` 裸 token）。vLLM/SGLang 旧版生成随机 ID，要升级或客户端改写。
