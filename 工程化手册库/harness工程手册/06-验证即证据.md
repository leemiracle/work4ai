# 06 · 验证即证据：V 组件的工程化

> **核心论点**：没有跑通的测试不算完成。"agent 说做完了"是观点，"验证命令通过"才是事实。
> **本文是什么**：V 组件的三级设计 + 验证的反模式 + 确定性/LLM 分层。

---

## 🎯 为什么验证是 harness 的灵魂

agent 最危险的失败模式不是"做不出"，是**"幻觉式完成"——声称做完，实际没做或做错**。模型优化目标是"让回复看起来对"，不是"让世界真的对"。V 组件就是用**世界本身的反馈**（测试/lint/编译/运行）对抗语言的最优解伪造。

三源收敛：
- walkinglabs L09：验证是五子系统之一，"验证即证据"是教程反复敲的铁律
- Trellis Verify 阶段：check 子代理对着 spec 评审 diff + lint/类型/测试，能自修则自修
- 阿里 open-code-review：**确定性管线先过筛，LLM 只做规则覆盖不到的语义判断**（NPE/线程安全/XSS/SQL 注入规则集先行）

---

## 📊 验证金字塔（三级设计）

```
        ┌─────────────┐
        │  L3 语义验证  │  LLM judge / maker-checker（贵，慢，覆盖语义）
        ├─────────────┤
        │  L2 属性验证  │  断言：输出含/不含 X、schema 合法、维度正确（快）
        ├─────────────┤
        │  L1 确定性验证 │  编译/lint/类型/测试/规则集（最快，零误判）
        └─────────────┘
```

**分层原则**：L1 能拦的绝不升到 L2；L2 能断言的绝不问 L3。每上一级，成本×10、噪声×10。

| 级 | 工具 | 延迟 | 误报 | 用途 |
|---|---|---|---|---|
| L1 | pytest/eslint/mypy/clippy/规则集 | 秒级 | ~0 | 客观正确性 |
| L2 | assert schema / contains / 维度检查 | 秒级 | 低 | 输出契约 |
| L3 | LLM-as-judge / 双模型互查 | 分钟 | 中 | 语义质量、规格符合度 |

**maker-checker 模式**：生成和质检分离（甚至不同模型）——同一个模型既当运动员又当裁判是 Goodhart 的温床。Trellis 的 Implement/Verify 分子代理、ruflo 的 quality 插件组、revfactory 的 Producer-Reviewer 团队模式，全是这一条。

---

## 🛠️ 落地：每个任务三件套

```markdown
## feature: 用户导出 CSV
verify_cmd:     pytest tests/test_export.py -q        # L1：必须绿
verify_assert:  output.rows == expected_rows          # L2：契约
verify_review:  导出顺序与用户时区设置一致（规格 #42）   # L3：语义，人工或 judge
```

**完成的定义（DoD）**：
```
done = L1 通过 ∧ L2 通过 ∧ (L3 通过 ∨ 人工豁免记录在案)
```
任一失败 → 不是"差不多完成"，是**没完成**。WRAP UP 时未过验证的任务必须回到 feature_list 标记未完成+记录卡点（07 章）。

---

## ⚠️ 验证的四个反模式

1. **只验最终态**：任务中途的方向错误发现太晚——对策：分阶段检查点（每子任务一个 mini-L1）
2. **指标被 gaming（Goodhart）**：模型学会让测试变绿而不是让功能正确（改测试/特判输入）——对策：测试文件只读权限（Scope 隔离）+ 盲测集不进上下文
3. **验证结果不回写**：跑完测试结果不进上下文，模型看不到——对策：失败输出**原样回灌**（错误信息即反馈，截断规则走 04 章预算）
4. **只有 L3 没有 L1**：全靠 LLM 互查 = 又贵又飘——对策：能编译的绝不 judge

---

## 🔗 V 与其他组件的接口

- **V × C**：验证结果占预算——失败输出截断要保留关键行（错误栈最后 N 行优先）
- **V × S**：验证证据写进 progress.md（"pytest 42 passed, 3.2s, commit a1b2c3"）——证据可复查
- **V × L**：验证失败触发恢复路径：重试 → 降级 → 人工升级（fail 的去向必须显式）
- **V × 评估**：验证用例积累成回归集——**你的任务失败史就是你的私有 benchmark**（11 章自动进化的燃料）
