# 07 · 会话生命周期与交接：从 START 到 WRAP UP

> **核心论点**：长任务不是被"解决"的，是被"接力"的。生命周期仪式 = 每次交接不丢信息的形式保证。
> **本文是什么**：四阶段仪式 + 崩溃恢复 + 子代理交接 + Anthropic 长任务工件。

---

## 🔄 会话生命周期仪式（walkinglabs 原版，值得逐字照抄）

```
START   读 AGENTS.md → 跑 init.sh → 读 progress.md → 读 feature_list.json → 看 git log
SELECT  只挑一个未完成 feature（贪心单任务，不并行开新坑）
EXECUTE 实现 → 跑验证（06 章）→ 失败则修复重跑 → 通过则记录证据
WRAP UP 更新 progress.md → 更新 feature_list.json → 记录仍未解决/未验证项 → 干净状态提交
```

**每个阶段的唯一职责**：
- **START = 恢复现场**（五件事一件不省：指令→环境→进度→账本→历史）
- **SELECT = 防贪多**（一次一个 feature；并行是 graph 层的事，02 章判断式）
- **EXECUTE = 验证驱动**（实现和验证在同一段里，不验证不进下一阶段）
- **WRAP UP = 为下一个会话铺路**（你不是在收尾，你是在写下一棒的开场）

**触发时机**：不只在会话结束——上下文接近阈值（04 章触发参数）、任务里程碑、长任务定时检查点，都该走一遍 mini-WRAP UP。**Anthropic 长任务指南的 claude-progress.txt 就是这个仪式的工件化**：本会话结束时写，下个会话开工前先读。

## 💥 崩溃恢复：按"死了之后"设计

崩溃不是异常，是常态（OOM/超时/API 断/上下文爆）。设计问题只有一个：**死了之后，下一个会话能接上吗？**

```
恢复清单（新会话冷启动路径）：
1. 读 progress.md 最后一段 → 知道做到哪
2. 读 feature_list.json    → 知道还欠什么
3. git log / git status    → 知道工作树的真实状态
4. 跑验证套件             → 知道当前代码的真实健康度
5. ⚠️ 对账：账本说的 vs git 说的 vs 测试说的，矛盾时以"世界"为准
```

**hive 的生产四件套**（crash-safe 的工业实现）：park/resume（任意时刻挂起恢复）、成本强制（超预算即停）、带外 human-in-the-loop（Sentinel）、深度可观测。
**反面教训**（本仓库真实事故，2026-08）：会话中断未 commit → 产物丢失重建降级；并行会话全量重写日志 → 互相覆盖。两条衍生铁律：**里程碑落盘立即 commit**；**日志类文件只允许锚定尾部追加，禁止整文件重写**。

## 👥 子代理交接：隔离 vs fork

四大 harness 趋同解（Arize 核实）：

| 模式 | 机制 | 适用 | 代价 |
|---|---|---|---|
| **默认隔离** | 子代理只收到任务字符串，零父历史 | 独立可定义的子任务 | 子代理需自己重新探索 |
| **fork 复制**（Claude Code）| 复制父 transcript + 合成 assistant 消息 + placeholder tool 结果 | 需要完整语境的委派；顺便共享 prompt cache | token 贵 + 继承噪声 |
| **allowlist fork**（OpenClaw）| 只复制 AGENTS/TOOLS/SOUL.md | 中间态：要规范不要历史 | 手工维护 allowlist |

**交接契约（handoff contract）三元组**：显式的**输入**（给什么上下文）/ **输出**（交付什么形式）/ **约束**（不许碰什么）。任务字符串写足这三样，隔离模式就不丢信息。
（K2.5 Agent Swarm 的 100 并行子代理就是这套契约的规模化——orchestrator RL 训练的即是"怎么拆、怎么分、怎么收"。）

## 📦 Anthropic 长任务四工件（ initializer 模式）

| 工件 | 作用 | 等价物（本手册）|
|---|---|---|
| feature list | 任务分解账本 | feature_list.json（05 章）|
| init.sh | 环境自检脚本 | init.sh |
| claude-progress.txt | 会话间记忆桥 | progress.md 的 WRAP UP 段 |
| 交接产物（handoff artifacts）| 子任务委派的规范 | 交接契约三元组 |

`/init` 的意义：**新任务进来先花 5% 预算生成这四件，而不是直接开干**——磨刀不误砍柴工的 agent 版。
