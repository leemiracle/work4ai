# 02 · 五子系统：harness 的最小完备集

> **核心论点**：任何 harness 都可以拆成五个子系统——少一件就漏一种失败模式。
> **本文是什么**：五子系统定义、检查单、四层栈定位。

---

## 🧩 五子系统（walkinglabs 教程 L02，产业多方印证）

| 子系统 | 管什么 | 缺失时的失败模式 | 对应六组件（03 章）|
|---|---|---|---|
| **Instructions**（指令）| 常驻契约：AGENTS.md / 系统提示 / 规范 | agent 每次行为漂移，不知道自己是谁 | C 的一部分 |
| **State**（状态）| 进度、账本、事实源单一化 | 跨会话失忆、重复劳动、互相矛盾 | S |
| **Verification**（验证）| 测试/lint/类型检查 = 完成的唯一判据 | "幻觉式完成"——声称做完实际没做 | V |
| **Scope**（边界）| 权限、沙箱、允许碰的文件/命令 | 跑飞、删库、越权 | L + T |
| **Session Lifecycle**（会话生命周期）| START→EXECUTE→WRAP UP 的仪式 | 上下文耗尽、任务烂尾、无交接 | E + L |

**为什么是这五件**（不是四件不是六件）：这是"教程给定义、Trellis 给实现（spec/tasks/workspace）、dsh 给插件化、Chorus 给会话级"的多方收敛——每件都有独立的失败模式和独立的修复动作，合起来覆盖 agent 的全部典型事故。

---

## ✅ 五子系统一页检查单

```markdown
## Instructions
- [ ] 有常驻指令文件（AGENTS.md），<200 行（指令预算见 04 章）
- [ ] 告诉 agent "去哪查"而不是"全写进来"（渐进披露）

## State
- [ ] progress.md 记录做到哪 + 证据
- [ ] feature_list.json 是任务的唯一账本
- [ ] 事实源单一化（一处写、处处读）

## Verification
- [ ] 每个任务有可执行的验证命令（tests/lint/typecheck）
- [ ] 验证不过 = 没完成，无例外
- [ ] 失败输出能直接定位（错误信息即反馈）

## Scope
- [ ] 允许写的目录白名单
- [ ] 危险命令拦截（rm -rf / force-push）
- [ ] 密钥文件读取隔离

## Session Lifecycle
- [ ] START：读指令→跑 init→读进度→看 git log
- [ ] WRAP UP：更新账本→记录未解决项→干净提交
- [ ] 断点可续传（会话死了下一个会话能接上）
```

## 🗼 四层栈定位：prompt → context → loop → graph

（教程 L13/L14 收敛，决定你的问题在哪层修）

| 层 | 管什么 | 典型问题 | 典型修法 |
|---|---|---|---|
| **prompt** | 单次询问质量 | 问得不清楚 | 结构化提示（→ prompt工程手册）|
| **context** | 进窗口的信息生命周期 | 该看的东西没看到 | 检索/记忆/预算（→ 04 章）|
| **loop** | 反馈循环本体 | 干完不自查 | generator/evaluator 分离、maker-checker |
| **graph** | 多节点协作 | 局部看不见全局、并行互踩 | 特化/并行/共享状态/检查点上移 |

**判断式**（原句值得背诵）：
> "一个 loop 是只有一个节点的图。当任务需要**特化、并行、共享状态、验证、恢复**——它就不再是 loop，是 graph。"

in-loop 检查点治不了三种结构病：**Goodhart**（指标被 gaming）、**向上盲区**（局部节点看不见全局冲突）、**冲突**（并行分支互相踩）——这三种必须上移到 graph 层。

Loop 层六原语：automations / worktrees / skills / connectors / sub-agents / external state。三种 loop：goal loop（做到为止）、timer loop（定时跑）、maker-checker loop（生成+质检分离）。

**金句**：Harness engineering builds the vehicle. Loop engineering designs the road.（你在车外设计路，而不是坐在车里打方向盘。）
