# 04 · 德育原理转代码:把价值层的问题搬进机器

> **本章回答五问之五:这个分支的问题怎么变成 code 问题?**
> 三件套:**可机械化边界 / 代码走廊清单 / 工程师落点**(性能工程视角贯穿)。
>
> **本章一句话**:德育的可构造端(03 章谱系左半——两难与评分器)
> 几乎可以无损转码;**价值判断永远不可转码**——"什么算好品格、
> 选哪些价值"不可从数据推出,机器只能携带与呈现价值,不能产生价值;
> 五条代码走廊——**两难生成 / 理由-阶段判定 / 推理-行为差距仿真 /
> 品格指标审计 / SEL 落地矩阵**——把德育最硬的结构变成可跑、
> 可断言、可扫描的实验。德育的红线比教学论更硬:
> 教学论转不动的目的,这里连内容都是规范的。

---

## 开篇:不是"能不能转",是"转到哪一层"

数学家族转代码要解决"离散化",德育原理转代码要解决"**双负载的
剥离**":把一句双负载的德育语言(品格=稳定特质+价值理想)先翻成
单负载的模型(两难参数/理由编码/相关系数),再翻成代码。翻译损耗
全部发生在第一步——所以本章先划清哪些对象第一步走得通(绿色区),
哪些走不通(红色区),再给五条走通了的走廊。

## 一、可机械化边界(什么能转,什么转不动)

**能机械化(绿色区)**:

| 德育概念 | 代码化身 | 备注 |
|---------|---------|------|
| 道德两难 | 参数化生成器:(义务A, 义务B, 惩罚, 利益, 认可…)→冲突形状 | 03 章引擎 1 的直接编码;本家族实验全程纯标准库 |
| 阶段判定 | 规则编码器:理由文本→考量类别→阶段档位 | 规则版几十行(关键词表);LLM 版做预标注,编码一致性 kappa 是闸门 |
| 推理-行为差距 | 相关结构仿真:推理分数×耦合参数×情境权重→行为选择 | 道德认同与情境力量的参数化(00 章反直觉 1 的机制表达) |
| 品格指标体系 | 清单→指标→证据三层 schema+覆盖度/孤点报告 | 03 章引擎 2 的审计工具化 |
| SEL 落地 | 能力×场景矩阵+空缺格检测 | 03 章引擎 3;与素养 schema 同构,复用图工具 |
| 测量效度条件 | 冲突强度-辨识度扫描 | "弱两难没有诊断力"的数值化(实验断言 3) |

**转不动/转不动的边界(红色区)**:

1. **价值内容判断**:哪些美德进清单、哪种生活值得过,不可从数据
   推出(休谟铡刀的德育版)——任何把"选价值"外包给推荐算法的
   系统,实际是把**设计者的价值清单编译成了默认设置**。
   工程对策:清单显式化、可审计、修订留痕(谁改哪条,谁留名)。
2. **阶段的教育加速决策**:"是否应当促进学生过阶段"是规范命题;
   仿真只能回答"哪种干预与阶段上移相关",不能回答"该不该"。
   加速是否可欲,留给公开论证。
3. **道德行为的合格判据**:什么算"诚实的行为"在情境间不可通约
   (哈特肖恩-梅)——把行为打分外包给监控系统,得到的是
   监控可见的行为片段,不是品格。
4. **关怀的现场**:关怀伦理的核心(对具体他人的回应)是关系性
   判断——可编码其外显(回应延迟/求助网络),不可编码其意义。

**边界的一句话**:绿色区=03 章谱系左半段+三条引擎的可参数化部分;
红色区=价值内容+规范决策。**红线:凡涉及"应当教什么价值",
机器只能携带与呈现,不能产生。**

## 二、代码走廊清单(五条走廊,每条=理论→模型→算法→真实系统)

### 走廊 1:道德两难生成走廊(冲突的参数化)

```
科尔伯格式两难 ──参数化──▶ (义务A强度, 义务B强度, 惩罚概率, 利益, 认可度…)
      │
      └──冲突强度扫描──▶ 弱两难/锋利两难的判别力曲线 ──▶ 两难题库设计
```

- **理论→模型**:两难=两种义务的受控冲突;阶段权重(六阶段×
  六考量)与情境参数共同决定(结论, 理由)对。
- **本家族实现**:[`experiments/kohlberg_dilemmas.py`](experiments/kohlberg_dilemmas.py)
  ——断言①同一结论可出自不同阶段的理由(结论碰撞、理由互异);
  调惩罚参数可见"结论翻面、理由不动"。
- **真实系统**:伦理与合规培训的情景库;医学/工程职业伦理的
  案例生成(冲突强度可控=难度可控)。
- **性能工程要点**:参数扫描天然并行;输出(结论,理由)对的
  联合分布而非单点——分布才是测量对象。

### 走廊 2:理由-阶段判定走廊(编码器的两代实现)

```
访谈理由文本 ──规则版──▶ 考量关键词表 → 阶段档位(基线)
      │
      └──LLM版──▶ 预标注+人工抽检 ──→ 编码一致性 kappa 报告(质量闸门)
```

- **理论→模型**:阶段不含在结论里,含在理由结构里(00 章反直觉 2)
  ——判定器的输入必须是理由,不是选择。
- **算法层**:规则版几十行(惩罚/利害/认可/法律/契约/原则的
  关键词与句式);生产版 LLM 预标注+双人抽检,kappa<阈值即回炉
  (评分者信度是这门测量的生命线,02 章)。
- **真实系统**:两难讨论课的课堂即时反馈;大规模道德推理调查。
- **性能工程要点**:**审计胜过生成**——判定器的价值在于可复核的
  编码依据(哪句话触发了哪类考量),黑箱判定在这里不合规。

### 走廊 3:推理-行为差距走廊(相关结构的仿真)

```
道德认同/情境力量理论 ──参数化──▶ 行为 = a·推理 + b·特质 + c·情境(阈值化)
      │
      └──耦合参数扫描──▶ 相关系数曲线 ──▶ "德育买到什么"的效果预算
```

- **理论→模型**:行为选择对推理分数的耦合 a 是**世界参数**——
  理想世界(a≈1)里推理决定行为,经验世界(a 小、情境权重大)里
  相关弱;Blasi 的道德认同=提高 a 的候选机制,情境力量=压低 a
  的候选机制(00 章两条解释线的参数化)。
- **本家族实现**:实验断言②——主世界相关落在弱区间(与通说综述
  r≈0.2-0.3 对表),理想世界相关>0.7;情境权重上升,相关单调下降。
- **真实系统**:德育项目的效果预估(只训推理的方案,预期买到
  的就是推理);诚信系统的行为数据审计(宣称测"品格"的监控,
  实际测的是可见片段)。
- **性能工程要点**:断言写成区间与单调性(结构性质),不写具体
  点值;多 seed 平均防单次抽样的偶然。

### 走廊 4:品格指标审计走廊(三层塔的工程检查)

```
品格清单 ──schema化──▶ (美德, 指标, 证据通道) 三层表
      │
      └──孤点/单通道检测──▶ 宣言节点报告 ──→ 古德哈特风险清单
```

- **理论→模型**:03 章引擎 2 的审计工具化——无指标的美德=宣言,
  单证据通道的指标=注水风险,行为证据空缺=塔底未承重。
- **真实系统**:学校品格方案的年度审计;招聘"价值观测评"的
  供应商尽调(同一数学)。
- **性能工程要点**:红线同教育学原理 04 章素养走廊——**同一美德
  至少两条证据通道**;证据通道的元数据(采集频率/观察者)入库可查。

### 走廊 5:SEL 落地矩阵走廊(覆盖度的图工具)

```
五能力×四场景矩阵 ──schema化──▶ 能力节点×场景节点二部图
      │
      └──空缺格/孤点分析──▶ 覆盖度报告 ──→ 空谈格与重叠格清单
```

- **理论→模型**:03 章引擎 3——孤点=无场景供养的能力(宣言格);
  空谈格=只有课程没有测评的格;格间的优先级排序是价值决定,
  报告只呈现,不替排。
- **真实系统**:区县 SEL 实施方案的差距分析;校本课程图谱审计。
- **性能工程要点**:矩阵是呈现工具不是决策工具——**排序权
  留在公开审议**,这是走廊 5 与推荐系统的本质区别(红线 1 的
  应用现场)。

## 三、工程师落点(把本家族用到你的日常)

### 落点 1:AI 德育/价值观产品的默认设置审计

- 做"品格教育 APP""AI 陪练道德两难"先过两问:**价值清单是谁的**
  (内容端红色区——显式化、可审计)?**判定器凭什么编码**
  (走廊 2——可复核依据)?把"应当"藏进推荐权重的德育产品,
  是 00 章价值澄清批评(把立场藏进过程)的算法版。
- 大模型的"价值观对齐"工程与德育原理在此正面相遇:
  对齐(align)谁的价值、由谁审计——RLHF 的偏好数据就是一份
  隐形品格清单(走廊 4 的审计表可直接复用)。

### 落点 2:校园/平台行为管理系统的古德哈特红线

- "品格积分""诚信分"类系统把走廊 3 的警示制度化:**可奖励的
  行为片段≠品格**——积分一旦成为目标,行为片段会被优化而
  整体性流失(古德哈特德育版,与讲透管理理论 04 章多任务扭曲
  同构)。工程对策:积分只呈现不结算(不与重大利益挂钩)、
  多通道证据、定期重审指标。

### 落点 3:职业伦理培训的两难情景生成器

- 走廊 1 在企业/医院/工程伦理培训的直接落地:冲突强度可控的
  情景库=难度分级;理由记录(而非对错选择)作为培训数据——
  培训的 KPI 是理由结构的多样性,不是"答对率"。
- 性能工程视角:情景生成的瓶颈是**参数-叙事的自然度**
  (生态效度),不是算力——人工审读环节不可省(02 章
  神经神话风险的同族教训:翻译链条每节都要人守)。

## 📌 收束 + 🧭 认知升维

本章给你的**新眼睛:价值审计者之眼**——评估任何德育技术
(品格 APP/诚信分/AI 陪练),先问三件事:它的价值清单是谁写的、
显式吗?它的判定依据可复核吗?它奖励的是行为片段还是品格?
规范性不可机械化——这不是工程的自卑,是工程的红线:
**机器放大价值,从不产生价值;德育系统的第一行代码应是清单的署名栏。**
