### Purpose and Scope

This page documents the actor and critic network modules in TorchRL that form the core of policy and value function architectures in reinforcement learning algorithms. These modules provide standardized interfaces for:

  - Actors : Neural networks that map observations to actions (deterministic or stochastic)

  - Critics : Neural networks that estimate value functions (state values or state-action values)

  - Q-Value Networks : Specialized modules for discrete action spaces in Q-learning algorithms

All these components are built on TorchRL's `TensorDict`-based module system, enabling seamless integration with environments, collectors, and loss functions. For information about the underlying `TensorDictModule` system, see 6.1. For exploration strategies that wrap actors, see 6.5. For how these modules integrate with loss functions, see 7.

The hierarchy reflects three design principles:

  - Spec-based safety : SafeModule adds optional validation that outputs conform to action/value specifications

  - Key-based interface : All modules use in_keys and out_keys to read from and write to TensorDict objects

  - Composability : Modules can be chained using TensorDictSequential or wrapped with exploration/normalization transforms

### SafeModule: Spec-Based Validation

`SafeModule` extends `TensorDictModule` with optional output specification and projection. This is the foundation for most actor-critic modules in TorchRL.

#### Key Features

| Feature | Description |
| Spec validation | Checks outputs against TensorSpec if safe=True |
| Projection | Projects out-of-bounds values back into valid space using spec.project() |
| Composite specs | Supports multiple outputs with Composite spec |
| Lazy initialization | Compatible with nn.LazyLinear and similar lazy modules |

#### Spec Handling

When `spec` is provided:

  - If single output and non- Composite spec: automatically wrapped as Composite({out_keys[0]: spec})

  - If multiple outputs: must provide Composite spec with matching keys

  - Missing spec entries are set to None (no validation)

When `safe=True`:

  - A forward hook validates outputs against specs

  - Out-of-bounds values are projected using spec.project()

  - Useful for handling numerical issues or exploration noise

### Probabilistic Actors

#### ProbabilisticActor Class

`ProbabilisticActor` implements stochastic policies by wrapping a module that produces distribution parameters. It handles sampling, mode computation, and log-probability calculation.

```

```

Diagram: ProbabilisticActor Pipeline

#### Constructor Parameters

| Parameter | Type | Description |
| module | TensorDictModule | Produces distribution parameters |
| in_keys | list[str] or dict | Distribution parameter keys (e.g., ["loc", "scale"] ) |
| out_keys | list[str] | Sample output keys (default: ["action"] ) |
| distribution_class | Type[Distribution] | PyTorch distribution (default: Delta ) |
| distribution_kwargs | dict | Additional kwargs for distribution |
| default_interaction_type | InteractionType | How to extract value (default: DETERMINISTIC ) |
| return_log_prob | bool | Whether to compute log-probability (default: False ) |
| cache_dist | bool | Whether to cache distribution parameters (default: False ) |

#### Interaction Types

The `default_interaction_type` controls how values are extracted from the distribution:

| Type | Behavior | Use Case |
| InteractionType.DETERMINISTIC | Uses distribution mode | Evaluation |
| InteractionType.MODE | Uses dist.mode attribute | Deterministic policy |
| InteractionType.MEAN | Uses dist.mean attribute | Average behavior |
| InteractionType.MEDIAN | Uses dist.median attribute | Robust estimation |
| InteractionType.RANDOM | Samples via dist.rsample() | Training/exploration |

The global `set_exploration_type()` context manager overrides the default.

### Q-Value Networks for Discrete Actions

#### QValueModule Class

`QValueModule` handles the unique requirements of Q-learning in discrete action spaces:

  - Takes action-value estimates as input

  - Selects the greedy action via argmax

  - Extracts the chosen action's value

This pattern is fundamental to DQN and related algorithms.

```

```

Diagram: QValueModule Processing Pipeline

#### Action Space Support

| Action Space | Encoding | Example |
| categorical | Integer indices | action = 2 (out of 5 actions) |
| one_hot | One-hot vectors | action = [0, 0, 1, 0, 0] |
| mult_one_hot | Multiple one-hot groups | action = [0, 1, 0, 1, 0, 0] (2 groups) |
| binary | Binary vectors | Not yet implemented |

#### Constructor Parameters

| Parameter | Type | Description |
| action_space | str | One of: "categorical" , "one_hot" , "mult_one_hot" , "binary" |
| action_value_key | str | Input key for action values (default: "action_value" ) |
| action_mask_key | str | Optional mask for invalid actions |
| out_keys | list[str] | Output keys (default: ["action", "action_value", "chosen_action_value"] ) |
| var_nums | int | For mult_one_hot : number of actions per group |
| spec | TensorSpec | Action specification |
| safe | bool | Enable projection for out-of-spec actions |

### Distributional Q-Networks

#### DistributionalQValueModule Class

Extends `QValueModule` for distributional reinforcement learning (e.g., C51, QR-DQN). Instead of scalar Q-values, it works with distributions over values.

#### Key Differences from QValueModule

| Aspect | QValueModule | DistributionalQValueModule |
| Input | Raw Q-values | Log-probabilities of value distribution |
| Support | N/A | Discrete support points for value distribution |
| Action selection | argmax(Q(s,a)) | argmax(E[Z(s,a)]) where Z is distribution |

### Summary: Key Classes Reference

| Class | Base | Purpose | Default Keys |
| SafeModule | TensorDictModule | Adds spec validation and projection | User-defined |
| Actor | SafeModule | Deterministic policy | in=["observation"] , out=["action"] |
| ProbabilisticActor | SafeProbabilisticTensorDictSequential | Stochastic policy with distributions | out=["action"] |
| ValueOperator | TensorDictModule | Value function estimator | in=["observation"] , out=["state_value"] |
| QValueModule | TensorDictModuleBase | Q-value to action converter | in=["action_value"] , out=["action", "action_value", "chosen_action_value"] |
| DistributionalQValueModule | QValueModule | Distributional Q-learning | Same as QValueModule with support |

All classes are located in torchrl/modules/tensordict_module/actors.py and torchrl/modules/tensordict_module/probabilistic.py
