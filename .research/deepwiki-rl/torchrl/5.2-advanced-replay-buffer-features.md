This page documents advanced features of TorchRL's replay buffer system beyond the basic composable architecture. For the foundational replay buffer design with Storage, Sampler, and Writer components, see ReplayBuffer Architecture.

Advanced features covered here include:

  - Prioritized Experience Replay (PER) : Importance sampling based on TD-error

  - Trajectory Storage : Multi-dimensional buffers for episode/trajectory data

  - Checkpointing : Saving and loading buffer state with space-efficient formats

  - Delayed Initialization : Lazy buffer construction for distributed scenarios

  - Buffer Ensembles : Combining multiple buffers with different sampling strategies

  - Advanced Writers : Priority-based and max-value writers

  - Storage Compression : Efficient memory usage for large-scale applications

### Prioritized Experience Replay

Prioritized Experience Replay (PER) samples experiences based on their importance rather than uniformly. This is implemented through the `PrioritizedSampler` class, which uses segment trees for efficient priority-based sampling.

#### Parameter Guidelines

| Parameter | Typical Range | Effect |
| alpha=0.0 | Uniform sampling | No prioritization |
| alpha=0.4-0.7 | Balanced | Good trade-off |

| eps=1e-8 | Small constant | Prevents zero priority |

#### Implementation Details

The `PrioritizedSampler` maintains two segment trees for O(log n) operations:

  - SumSegmentTree : Stores cumulative priority sums for proportional sampling

  - MinSegmentTree : Tracks minimum priority for importance sampling weight normalization

When `max_priority_within_buffer=True`, the sampler tracks the maximum priority within the current buffer contents rather than globally. This affects `default_priority` for new samples.

### Summary

This page covered advanced replay buffer features in TorchRL:

  - Prioritized Experience Replay : PrioritizedSampler with segment trees for O(log n) priority updates and sampling with importance sampling correction

  - Trajectory Storage : Multi-dimensional storage with SliceSampler for sequences, and LazyStackStorage for variable-length trajectories

  - Checkpointing : Multiple backends ( TensorStorageCheckpointer , FlatStorageCheckpointer , H5StorageCheckpointer ) with space-efficient formats and save/load hooks

  - Delayed Initialization : Factory pattern with transform_factory for picklable buffers in distributed settings

  - Buffer Ensembles : ReplayBufferEnsemble for mixing multiple buffers with weighted sampling

  - Advanced Writers : TensorDictMaxValueWriter for maintaining top-k experiences by ranking criteria

  - Storage Compression : CompressedListStorage with configurable backends (lz4, zstd, gzip) for memory efficiency

For the basic replay buffer architecture with composable Storage, Sampler, and Writer components, see ReplayBuffer Architecture.
