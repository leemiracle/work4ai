### Purpose and Scope

Environment transforms modify or create data in TensorDicts during environment interactions. This page covers the `Transform` base class, the `TransformedEnv` wrapper, transform composition with `Compose`, and the complete library of built-in transforms for observation processing, action modification, reward shaping, and state management.

For information about the base environment interface that transforms operate on, see EnvBase and Environment Specifications. For specific environment backend integrations, see Backend Integrations.

Sources: torchrl/envs/transforms/transforms.py189-237 docs/source/reference/envs.rst1-63

### Core Architecture

#### Transform Base Class

The `Transform` class (torchrl/envs/transforms/transforms.py189-855) is an `nn.Module` that receives a `TensorDict` as input and returns a modified `TensorDict` as output. Transforms define which keys they read from (`in_keys`) and write to (`out_keys`), enabling precise control over data flow.

```

```

Key Attributes:

| Attribute | Type | Description |
| in_keys | Sequence[NestedKey] | Keys to read from input TensorDict |
| out_keys | Sequence[NestedKey] | Keys to write to output TensorDict |
| in_keys_inv | Sequence[NestedKey] | Keys for inverse transform input |
| out_keys_inv | Sequence[NestedKey] | Keys for inverse transform output |
| parent | TransformedEnv | None | Parent environment up to this transform |
| container | EnvBase | None | Top-level environment containing this transform |
| invertible | bool | Whether transform supports inverse operations |

Sources: torchrl/envs/transforms/transforms.py189-346

#### TransformedEnv Wrapper

`TransformedEnv` (torchrl/envs/transforms/transforms.py865-1370) wraps an `EnvBase` with a transform or `Compose` chain. It intercepts `step()` and `reset()` calls, applying transforms to observations and inverse transforms to actions.

```

```

Key Features:

  - Auto-unwrap : When wrapping a TransformedEnv in another TransformedEnv , transforms are automatically merged into a single chain (configurable via auto_unwrap parameter)

  - Spec caching : Transformed specs are cached by default ( cache_specs=True ) for performance

  - Transform composition : Multiple transforms can be chained using Compose

Sources: torchrl/envs/transforms/transforms.py865-1010

### Transform Execution Flow

Transforms have three distinct execution contexts with different method hooks:

```

```

Method Hierarchy:

| Context | Public Method | Internal Hook | Leaf Operation |
| Environment step | step() → transforms | _step(td, next_td) → _call(next_td) | _apply_transform(tensor) |
| Environment reset | reset() → transforms | _call(td) | _apply_transform(tensor) |
| Action preprocessing | Before step() | _inv_call(td) | _inv_apply_transform(tensor) |
| Standalone forward | forward(td) or __call__(td) | _apply_transform(tensor) | Direct application |
| Standalone inverse | inv(td) | _inv_apply_transform(tensor) | Direct application |

Sources: torchrl/envs/transforms/transforms.py405-576

### Composing Transforms

The `Compose` class chains multiple transforms into a sequential pipeline:

```

```

Usage Pattern:

```

```

Compose Features:

  - Sequential execution : Transforms applied in order during forward pass, reverse order for inverse

  - Spec propagation : Output spec computed by sequentially applying each transform's spec transformation

  - Parent/container management : Each transform in the chain maintains references to the Compose instance

  - Transform iteration : Compose is iterable and indexable like a list

Sources: torchrl/envs/transforms/transforms.py1372-1900

### Spec Transformation

Transforms must update environment specs to reflect changes in data structure. The spec transformation system ensures that the transformed environment's specs match its actual outputs.

```

```

Example: CatFrames Spec Transformation

When `CatFrames` stacks N frames along dimension `dim`, it updates the observation spec to reflect the new shape:

```

```

Example: Resize Spec Transformation

```

```

Key Methods:

| Method | Purpose | When to Override |
| transform_observation_spec() | Modify observation specs | Transform changes observation shape/dtype/bounds |
| transform_action_spec() | Modify action specs | Transform changes action constraints |
| transform_reward_spec() | Modify reward specs | Transform changes reward range/dtype |
| transform_done_spec() | Modify done specs | Transform adds/modifies termination signals |
| transform_state_spec() | Modify state specs | Transform changes environment state |
| transform_input_spec() | Modify input specs | Combination of action and state changes |
| transform_output_spec() | Modify output specs | Top-level orchestration (rarely overridden) |
