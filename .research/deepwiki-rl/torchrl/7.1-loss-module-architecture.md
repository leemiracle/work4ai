### Purpose and Scope

This document describes the architecture of the loss module system in TorchRL, which provides the computational backbone for implementing reinforcement learning algorithms. Loss modules compute training objectives (policy loss, value loss, entropy bonus, etc.) from batched trajectory data and coordinate the interaction between neural networks, value estimators, and target networks.

For information about individual RL algorithms (PPO, SAC, DQN, etc.), see On-Policy Algorithms, Off-Policy Algorithms, and Value-Based Algorithms. For value estimation methods (GAE, TD-Lambda, etc.), see Value Estimators.

### Base Class: LossModule

The `LossModule` class torchrl/objectives/common.py71-275 is the abstract parent class for all RL loss modules. It inherits from `TensorDictModuleBase` and implements a standardized interface for computing losses from trajectory data stored in TensorDicts.

#### Key Design Principles

  - TensorDict-Based I/O : All inputs and outputs are TensorDicts, enabling structured data flow

  - Functional Modules : Neural networks are converted to functional form, separating parameters from computation

  - Target Networks : Automatic management of target network parameters for stability

  - Value Estimators : Pluggable advantage/value target computation

  - Key Configurability : TensorDict keys are customizable via set_keys()

### Functional Module Conversion

Loss modules convert neural networks to functional form, separating the stateless computation graph from the learnable parameters. This design enables:

  - Meta-learning and parameter-space optimization

  - Efficient target network management

  - Gradient control for shared parameters

  - Batched/vmapped execution over parameter ensembles

#### Conversion Process

```

```

Sources: torchrl/objectives/common.py277-433

#### Method: convert_to_functional()

The `convert_to_functional()` method torchrl/objectives/common.py277-433 performs the following steps:

  - Extract Parameters : Creates a TensorDict from the module's parameters and buffers using TensorDict.from_module(module, as_module=True)

  - Store Parameters : Registers the parameter TensorDict as <module_name>_params (e.g., actor_network_params , qvalue_network_params )

  - Store Stateless Module : Stores the original module in __dict__ to avoid nn.Module parameter tracking

  - Create Target Parameters (optional): If create_target_params=True , creates a detached copy for target networks

  - Parameter Expansion (optional): If expand_dim > 0 , expands parameters for ensemble methods (e.g., REDQ with 10 Q-networks)

  - Shared Parameter Handling : If compare_against list is provided, detects shared parameters and avoids gradient propagation

#### Example Parameter Structure

For `SACLoss(actor, qvalue, value)` with functional conversion:

```
SACLoss
├── actor_network (stateless module in __dict__)
├── actor_network_params (TensorDictParams)
│   ├── module.0.weight
│   ├── module.0.bias
│   └── ...
├── qvalue_network (stateless module)
├── qvalue_network_params (TensorDictParams, shape=[2, ...])
│   ├── module.linear.weight [2, ...]
│   └── module.linear.bias [2, ...]
├── value_network (stateless module)
├── value_network_params (TensorDictParams)
└── target_value_network_params (TensorDictParams, detached)
```

### Target Network System

Target networks are a stabilization technique used in off-policy RL algorithms. They provide slowly-updated reference values for bootstrapping, preventing the moving target problem.

#### Target Parameter Creation

#### Target Network Updaters

The `TargetNetUpdater` abstract class torchrl/objectives/utils.py146-294 provides a common interface for updating target parameters. It automatically detects target parameters in a loss module and provides a `step()` method.

##### SoftUpdate

`SoftUpdate` torchrl/objectives/utils.py297-354 performs exponential moving average updates:

```
θ_target ← (1 - ε) · θ_target + ε · θ_source
```

  - ε (eps): update rate, typically 0.001-0.01

  - Equivalent to Polyak averaging with τ = 1 - ε

  - Updates every step

```

```

##### HardUpdate

`HardUpdate` torchrl/objectives/utils.py356-390 performs periodic full copies:

```
θ_target ← θ_source  (every N steps)
```

  - value_network_update_interval : steps between updates, typically 1000-10000

  - Original Double DQN approach

Value estimators compute advantage estimates and value targets from trajectory data. Loss modules integrate value estimators to support algorithms that require advantage-based policy updates (PPO, A2C, REINFORCE) or value bootstrapping (all algorithms).

#### Value Estimator Types

| Estimator | Enum Value | Formula | Use Case |
| TD0Estimator | ValueEstimators.TD0 | A(s,a) = r + γV(s') - V(s) | DQN, value-based methods |

### Key Management System

Loss modules use a configurable key system to read from and write to TensorDicts. This allows users to customize key names to match their data structure.

#### The _AcceptedKeys Pattern

Each loss module defines an `_AcceptedKeys` dataclass torchrl/objectives/ppo.py351-388 that:

  - Lists all configurable TensorDict keys

  - Provides default values

  - Supports post-initialization logic (e.g., composite distribution key selection)
