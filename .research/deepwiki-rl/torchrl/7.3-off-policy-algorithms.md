This document covers off-policy reinforcement learning algorithms in TorchRL: SAC (Soft Actor-Critic), DDPG (Deep Deterministic Policy Gradient), and TD3 (Twin Delayed DDPG). These algorithms learn from replay buffers containing past experience, enabling sample-efficient training through repeated learning from stored transitions.

Off-policy methods separate the behavior policy (used for data collection) from the target policy (being optimized). This separation requires careful management of Q-value networks, target networks, and actor-critic coordination patterns.

For on-policy algorithms, see On-Policy Algorithms. For the loss module architecture, see Loss Module Architecture. For value estimation methods, see Value Estimators.

### Actor-Critic Coordination

Off-policy algorithms use actor-critic architectures where the actor (policy network) and critic (Q-value network) are trained with different objectives. The actor maximizes expected return while the critic estimates the value of state-action pairs.

#### Parameter Sharing and Separation

Off-policy losses support a `separate_losses` flag that controls gradient flow to shared parameters:

  - separate_losses=False (default): Shared parameters receive gradients from both actor and critic losses

  - separate_losses=True : Shared parameters only train on actor loss, preventing critic updates from affecting shared layers

This is implemented via the `compare_against` parameter in `convert_to_functional`, which identifies shared parameters between networks.

Sources: torchrl/objectives/sac.py318-398 torchrl/objectives/ddpg.py224-240 torchrl/objectives/td3.py138-161

### Q-Value Networks

Q-value networks estimate the expected return of taking action `a` in state `s`. In off-policy algorithms, Q-networks are trained via temporal difference (TD) learning using the Bellman equation:

```
Q(s, a) = r + γ * max Q(s', a')  (or E[Q(s', a')] for stochastic policies)
```

```

```

#### Double Q-Learning

SAC and TD3 use two Q-networks to reduce overestimation bias. The minimum of the two Q-values is used for the policy update target:

```
Q_target = r + γ * min(Q1(s', a'), Q2(s', a'))
```

This is implemented via `num_qvalue_nets=2` and the `_vmap_func` utility for efficient parallel computation across Q-networks.

Sources: torchrl/objectives/sac.py318-398 torchrl/objectives/td3.py138-259 torchrl/objectives/utils.py1-43

### Target Network Updates

Target networks stabilize off-policy learning by providing slowly-changing targets for TD error computation. Without target networks, the Q-value estimates and targets would both shift during training, leading to instability.

#### Soft Updates (Polyak Averaging)

`SoftUpdate` performs exponential moving average updates at every optimization step:

```

This is the default for SAC and recommended for continuous control. The update formula is:

```

#### Delay Flags

Loss modules control target network creation via `delay_*` flags:

  - delay_actor=True : Creates target_actor_network_params separate from actor_network_params

  - delay_qvalue=True : Creates target_qvalue_network_params separate from qvalue_network_params

When `False`, target parameters are just detached references to the source parameters (no separate copy).

### SAC (Soft Actor-Critic)

SAC is an off-policy actor-critic algorithm that maximizes both expected return and policy entropy. This encourages exploration and improves robustness to hyperparameters.

SAC Architecture

```

```

#### SAC Loss Computation

The actor loss maximizes Q-value while encouraging entropy:

```
L_actor = E[α * log π(a|s) - Q(s,a)]
```

The critic loss minimizes TD error using the minimum of two Q-networks:

```
L_critic = E[(Q(s,a) - (r + γ * min(Q1(s',a'), Q2(s',a')) - α * log π(a'|s')))^2]
```

Sources: torchrl/objectives/sac.py62-256 torchrl/objectives/sac.py549-668

#### Entropy Temperature (Alpha)

SAC uses a temperature parameter `α` to control the entropy-return tradeoff:

  - fixed_alpha=True : α is a constant hyperparameter

  - fixed_alpha=False (default): α is learned to match a target_entropy target_entropy="auto" : Set to -dim(action_space) target_entropy=<float> : Custom target entropy value

The alpha loss is:

```
L_alpha = E[-α * (log π(a|s) + target_entropy)]
```

Alpha is constrained between `min_alpha` and `max_alpha` via log-space parameterization.

Sources: torchrl/objectives/sac.py318-449 torchrl/objectives/sac.py779-866

#### SAC Versions

SAC has two versions:

  - Version 2 (default, value_network=None ): Uses two Q-networks only

  - Version 1 ( value_network provided): Adds a separate V-network

Version 2 is simpler and more commonly used. Version 1 separates the value function estimation but requires an additional network.

Sources: torchrl/objectives/sac.py318-379

### Key Features and Utilities

#### Reduction and Output Management

Loss modules support configurable output reduction (`"none"`, `"mean"`, `"sum"`) and selective output key filtering through `select_out_keys()`. This enables flexible integration with different training frameworks and logging systems.

#### Compatibility Modes

Loss modules can operate in two modes:

  - TensorDict Mode : Full integration with TorchRL's tensordict ecosystem

  - Non-TensorDict Mode : Direct tensor input/output for compatibility with existing codebases

The non-tensordict mode automatically handles input key mapping and returns tuples of tensors in a predictable order.

#### Performance Optimizations

The system includes several performance optimizations:

  - vmap support for vectorized operations across ensemble members

  - Functional programming to enable meta-learning and parameter sharing

  - Efficient target network updates with minimal memory overhead

  - Lazy parameter initialization for memory efficiency
