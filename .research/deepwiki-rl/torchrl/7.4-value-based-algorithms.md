This document covers value-based reinforcement learning algorithms in TorchRL, which learn Q-value functions to determine optimal actions. Unlike policy gradient methods (see 7.2 and 7.3), value-based algorithms directly estimate action-values Q(s,a) and select actions by maximizing these values. The core algorithm is DQN (Deep Q-Network), with extensions including distributional RL, offline RL methods, and ensemble approaches.

For the base loss module architecture, see Loss Module Architecture. For value estimation methods used by these algorithms, see Value Estimators.

### Overview of Value-Based Methods

Value-based algorithms estimate the action-value function Q(s,a) representing the expected return from taking action a in state s. Unlike actor-critic methods that maintain separate policy and value networks, value-based methods derive the policy implicitly through action selection (typically ε-greedy or greedy).

Key Characteristics:

  - Off-policy : Learn from any experience, enabling replay buffers

  - Discrete/Continuous : Most value-based methods target discrete action spaces

  - Target Networks : Use delayed parameter updates for stability

  - Bootstrap : Use value estimates to compute TD targets

### DQN and Core Algorithms

#### DQN Loss

The `DQNLoss` class implements Deep Q-Network training, the foundational value-based algorithm. DQN approximates the optimal action-value function Q*(s,a) using a neural network and trains it via temporal difference learning.

DQN Architecture and Data Flow

```

```

Key Features:

  - Action Space : Supports "one_hot" , "categorical" , and "mult_one_hot" action specs

  - Target Networks : Optional delayed updates via delay_value=True

  - Double DQN : Decouples action selection from evaluation with double_dqn=True

  - Value Estimators : Configurable TD learning (TD0, TD1, TD-Lambda)

Key Parameters:

| Parameter | Type | Default | Description |
| value_network | QValueActor or nn.Module | Required | Q-value network |
| loss_function | str | "l2" | Loss function: "l1" , "l2" , "smooth_l1" |
| delay_value | bool | True | Use separate target network |
| double_dqn | bool | False | Enable Double DQN |
| action_space | str or TensorSpec | None | Action space specification |
| reduction | str | "mean" | Loss reduction method |

Sources: torchrl/objectives/dqn.py36-231 test/test_cost.py462-797

#### Double DQN

Double DQN addresses overestimation bias in standard DQN by using the online network to select actions and the target network to evaluate them:

```
Standard DQN:  Q_target = r + γ * max_{a'} Q_target(s', a')
Double DQN:    Q_target = r + γ * Q_target(s', argmax_{a'} Q_online(s', a'))
```

Enable with `double_dqn=True` in `DQNLoss` constructor.

Sources: torchrl/objectives/dqn.py36-231 test/test_cost.py658-697

#### Distributional DQN

`DistributionalDQNLoss` implements categorical distributional RL (C51), which models the full distribution of returns rather than just the expected value.

Distributional Q-Learning Architecture

```

```

Key Parameters:

| Parameter | Type | Default | Description |
| value_network | DistributionalQValueActor | Required | Distributional Q-network |
| gamma | float | None | Discount factor (from value estimator) |
| delay_value | bool | True | Use target network |
| action_space | str | None | Action specification |

The network outputs a probability distribution over a discrete support (atoms). The loss projects the Bellman update onto this support and minimizes the cross-entropy between predicted and projected distributions.

### Offline RL Methods

Offline RL algorithms learn from fixed datasets without environment interaction. Value-based offline methods address distribution shift and overestimation through conservative value estimation.

#### Conservative Q-Learning (CQL)

`CQLLoss` implements Conservative Q-Learning for both continuous and discrete action spaces. CQL adds a regularization term that penalizes Q-values at out-of-distribution actions while maximizing values at dataset actions.

CQL Loss Components

```

```

Key Features:

  - Conservative Bias : Underestimates Q-values for actions outside training distribution

  - Temperature : temperature parameter controls the penalty magnitude

  - Min Q-Weight : min_q_weight scales the CQL regularization term

  - Lagrange Multiplier : Optional automatic tuning with with_lagrange=True

CQL Parameters:

| Parameter | Type | Default | Description |
| actor_network | ProbabilisticActor | Required | Policy network |
| qvalue_network | TensorDictModule | Required | Q-value network(s) |
| temperature | float | 1.0 | CQL temperature |
| min_q_weight | float | 1.0 | CQL penalty weight |
| max_q_backup | bool | False | Use max Q-value backup |
| num_random | int | 10 | Number of random action samples |
| with_lagrange | bool | False | Use Lagrangian constraint |

Discrete Action Variant:

`DiscreteCQLLoss` applies CQL to discrete action spaces with simplified regularization that operates directly on Q-value logits.

Sources: torchrl/objectives/cql.py38-639 test/test_cost.py97-100

#### Implicit Q-Learning (IQL)

`IQLLoss` implements Implicit Q-Learning, which avoids explicit policy optimization and instead learns Q-values, V-values, and the policy separately using expectile regression.

IQL Architecture

```

```

Key Features:

  - Expectile Regression : V-network uses asymmetric loss with expectile τ

  - Decoupled Learning : Q, V, and policy updated independently

  - No Q-Value Maximization : Avoids overestimation through implicit policy

  - Temperature : Controls advantage weighting via temperature parameter

IQL Parameters:

| Parameter | Type | Default | Description |
| actor_network | ProbabilisticActor | Required | Policy network |
| qvalue_network | TensorDictModule | Required | Q-value network(s) |
| value_network | TensorDictModule | Required | State-value network |
| temperature | float | 3.0 | Advantage weighting (β) |
| expectile | float | 0.7 | Expectile for V-learning (τ) |
| num_qvalue_nets | int | 2 | Number of Q-networks |

The expectile τ controls how much weight is given to advantages above vs. below the V-value. Values τ > 0.5 emphasize upper tail, enabling "stitching" of trajectories for long-horizon tasks.

Discrete Variant:

`DiscreteIQLLoss` adapts IQL for discrete action spaces with `QValueActor` instead of continuous policy networks.

Sources: torchrl/objectives/iql.py32-687 test/test_cost.py110

### Ensemble and Multi-Network Methods

#### REDQ Loss

`REDQLoss` (Randomized Ensembled Double Q-Learning) extends SAC with an ensemble of Q-networks and random subsampling for improved sample efficiency.

REDQ Ensemble Architecture

```

```

Key Features:

  - Ensemble Size : Maintains num_qvalue_nets Q-networks (default 10)

  - Subsampling : Uses sub_sample_len networks (default 2) for target computation

  - SAC Integration : Combines ensemble with entropy regularization

  - High UTD : Enables high update-to-data (UTD) ratios

REDQ Parameters:

| Parameter | Type | Default | Description |
| actor_network | TensorDictModule | Required | Policy network |
| qvalue_network | TensorDictModule or list | Required | Q-network(s) to ensemble |
| num_qvalue_nets | int | 10 | Ensemble size |
| sub_sample_len | int | 2 | Number of Q-nets for target |
| target_entropy | float or "auto" | "auto" | Entropy target |
| fixed_alpha | bool | False | Fix entropy coefficient |

REDQ reduces variance through ensembling while maintaining low bias through subsampling, enabling more frequent network updates without instability.

Sources: torchrl/objectives/redq.py32-549 test/test_cost.py121

`QMixerLoss` implements QMIX for multi-agent value-based learning. QMIX learns individual Q-values Q_i(s,a_i) for each agent and combines them through a mixing network that enforces monotonicity.

#### Action Selection and Spec Compatibility

Value-based losses work with `QValueActor` or `DistributionalQValueActor` modules that handle action selection:

Action Space Support

| Action Space | Spec Class | DQN Support | Description |
| One-Hot | OneHot | ✓ | Single discrete action |
| Categorical | Categorical | ✓ | Discrete without one-hot |
| Multi One-Hot | MultiOneHot | ✓ (Distributional) | Multiple discrete choices |
| Continuous | Bounded / Unbounded | ✗ | Use actor-critic instead |

The `action_space` parameter in loss constructors accepts:

  - String: "one_hot" , "categorical" , "mult_one_hot"

  - TensorSpec: Direct spec object

Action selection modes (controlled via `exploration_type` context):

  - MEAN/MODE/DETERMINISTIC : Greedy action selection (argmax Q)

  - RANDOM : Uniform random actions

  - Module exploration : ε-greedy via exploration modules

### Key Features and Utilities

#### Reduction and Output Management

Loss modules support configurable output reduction (`"none"`, `"mean"`, `"sum"`) and selective output key filtering through `select_out_keys()`. This enables flexible integration with different training frameworks and logging systems.

#### Compatibility Modes

Loss modules can operate in two modes:

  - TensorDict Mode : Full integration with TorchRL's tensordict ecosystem

  - Non-TensorDict Mode : Direct tensor input/output for compatibility with existing codebases

The non-tensordict mode automatically handles input key mapping and returns tuples of tensors in a predictable order.

#### Performance Optimizations

The system includes several performance optimizations:

  - vmap support for vectorized operations across ensemble members

  - Functional programming to enable meta-learning and parameter sharing

  - Efficient target network updates with minimal memory overhead

  - Lazy parameter initialization for memory efficiency
