### Purpose and Scope

This document covers TensorDict and TensorSpec, the core data structures that form the foundation of TorchRL's data handling system. TensorDict serves as the universal data container for passing structured data between components, while TensorSpec provides type validation and action space processing capabilities. Together, they enable type-safe, efficient data flow throughout the reinforcement learning pipeline.

For information about how these data structures are used in replay buffers, see Replay Buffers. For their integration with environments, see Environments. For their use in neural network modules, see Modules and Models.

### TensorDict: Central Data Container

TensorDict is TorchRL's primary data structure for managing collections of tensors with associated metadata. It provides a dictionary-like interface for structured data that can be efficiently batched, indexed, and transformed throughout the RL pipeline.

#### Key Characteristics

TensorDict serves as the universal data exchange format between all major TorchRL components:

  - Environments : Output observations, rewards, and done flags as TensorDict instances

  - Actors : Receive TensorDict observations and produce TensorDict actions

  - Collectors : Accumulate experience data in TensorDict format

  - Replay Buffers : Store and sample TensorDict experiences

  - Loss Modules : Process TensorDict batches for gradient computation

### Serialization Support

#### CloudpickleWrapper

The `CloudpickleWrapper` provides serialization support for functions and objects in multiprocessed environments while maintaining compatibility with TensorSpec validation:

  - Prevents usage with EnvCreator class to avoid shared tensor transmission issues

  - Supports serialization of spec validation functions

  - Maintains function wrapper metadata through functools.update_wrapper
