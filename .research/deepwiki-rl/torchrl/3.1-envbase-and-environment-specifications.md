## EnvBase and Environment Specifications

This page documents `EnvBase`, the foundational abstract class for all environments in TorchRL, and the specification system that enables type-safe, validated environment interactions.

### Overview

`EnvBase` is an abstract base class (subclass of `torch.nn.Module`) that defines the standard interface all TorchRL environments must implement. It provides three key components:

  - Core Interface : Abstract methods _reset() , _step() , and _set_seed() that subclasses must implement

  - Specification System : Comprehensive TensorSpec objects that define the structure, dtype, shape, and constraints of all environment inputs/outputs

  - Validation Framework : Automatic validation of data against specs to catch errors early

All data exchange uses `TensorDict` as the standardized container, enabling consistent behavior across different environment types.

### EnvBase Class Definition

`EnvBase` is defined in torchrl/envs/common.py314 and inherits from `torch.nn.Module`. It uses the `_EnvPostInit` metaclass torchrl/envs/common.py258 to perform post-initialization tasks such as locking specs and validating key consistency.

#### Constructor Arguments

```

```

Key parameters:

  - device : Device where input/output tensors should reside (can be None for deviceless environments)

  - batch_size : Leading dimensions for batched environments (defaults to empty torch.Size([]) )

  - run_type_checks : If True , performs dtype/shape validation on every reset() and step()

  - spec_locked : If True , specs are locked and cached for performance (default)

  - auto_reset : If True , automatically wraps env in AutoResetTransform

#### Abstract Methods (Must Implement)

Subclasses must implement three abstract methods:

| Method | Signature | Purpose |
| _reset() | _reset(self, tensordict: TensorDictBase, **kwargs) -> TensorDictBase | Initialize/reinitialize environment, return observations |
| _step() | _step(self, tensordict: TensorDictBase) -> TensorDictBase | Execute one step given actions, return next observations/rewards/dones |
| _set_seed() | _set_seed(self, seed: int | None) -> None | Set environment's random seed for reproducibility |

Sources: torchrl/envs/common.py1579-1641

#### Public Interface Methods

Public methods that call the abstract methods with validation:

| Method | Purpose |
| reset(tensordict=None, **kwargs) | Public reset with validation and post-processing |
| step(tensordict) | Public step with validation and automatic key handling |
| rollout(max_steps, policy, ...) | Execute multi-step rollout with policy |
| set_seed(seed) | Set seed and return next seed for distributed seeding |
| rand_step(tensordict=None) | Execute step with random action from action_spec |
| step_and_maybe_reset(tensordict) | Step and automatically reset done environments |

### Environment Specifications

The specification system is the core mechanism for defining and validating the structure of environment inputs and outputs. All specs are `Composite` or `TensorSpec` objects that define shape, dtype, device, and constraints (bounds, discrete vs. continuous, etc.).

#### Spec Properties

`EnvBase` provides multiple property accessors for specs:

| Property | Type | Description |
| input_spec | Composite | Parent spec containing all input specs |
| output_spec | Composite | Parent spec containing all output specs |
| full_action_spec | Composite | All action tensor specs |
| full_state_spec | Composite | All state tensor specs (non-action inputs) |
| full_observation_spec | Composite | All observation tensor specs |
| full_reward_spec | Composite | All reward tensor specs |
| full_done_spec | Composite | All done signal specs ( done , terminated , truncated ) |

Additionally, there are convenience properties that return the leaf spec when only one exists:

| Convenience Property | Returns | Fallback |
| action_spec | Leaf action spec if single action | full_action_spec otherwise |
| observation_spec | Leaf observation spec if single obs | full_observation_spec otherwise |
| reward_spec | Leaf reward spec if single reward | full_reward_spec otherwise |
| done_spec | Always returns full_done_spec | N/A |
| state_spec | Always returns full_state_spec | N/A |

#### Automatic Spec Creation

If not explicitly set, some specs are created automatically:

  - full_done_spec : Automatically created with done , terminated , and optionally truncated entries torchrl/envs/common.py 1387-1444

  - full_reward_spec : Defaults to Unbounded if not specified

  - full_observation_spec : Must be set explicitly by the environment

The `_create_done_specs()` method torchrl/envs/common.py1387 ensures that done specs always contain at least `done` and `terminated` keys.

Sources: torchrl/envs/common.py1387-1444

#### Spec Locking and Caching

Specifications are locked by default (`spec_locked=True`) for performance. When locked:

  - Specs cannot be modified (raises RuntimeError )

  - Spec-derived properties are cached in self._cache dictionary

  - Modifications require unlocking via set_spec_lock_(False)

```

```

The caching mechanism is implemented via the `@_cache_value` decorator torchrl/envs/common.py88-102 and `@_clear_cache_when_set` decorator torchrl/envs/common.py105-119

#### Spec Keys

Environments track which keys belong to each spec category:

| Property | Returns | Purpose |
| action_keys | List of action key names | Identify action tensors in TensorDict |
| observation_keys | List of observation key names | Identify observation tensors |
| reward_keys | List of reward key names | Identify reward tensors |
| done_keys | List of done key names | Identify done/terminated/truncated signals |
| state_keys | List of state key names | Identify non-action input keys |

These are cached properties that extract keys from the corresponding specs.

#### Done Signal Conventions

TorchRL distinguishes between different types of episode termination:

| Key | Type | Meaning |
| done | bool | Episode is over (either terminated or truncated) |
| terminated | bool | True terminal state reached (e.g., goal reached, failure) |
| truncated | bool | Episode cut off by time limit or external factor |

The relationship: `done = terminated | truncated`

If only `done` or `terminated` is provided by `_step()`, the missing signals are filled automatically by the `_terminated_or_truncated()` helper torchrl/envs/utils.py927-1010

Sources: torchrl/envs/common.py1387-1444 torchrl/envs/utils.py927-1010

### Spec Validation

The spec system enables automatic validation of environment inputs and outputs. Validation can be enabled in multiple ways.

#### Runtime Validation with run_type_checks

Set `run_type_checks=True` in the constructor to enable validation on every `reset()` and `step()`:

```

```

When enabled, validation checks:

  - Tensor shapes match spec shapes

  - Dtypes match spec dtypes

  - Values satisfy bounds (for Bounded specs)

  - Required keys are present

Sources: torchrl/envs/common.py481-543 test/test_env.py262-283

#### Manual Validation with check_env_specs()

The `check_env_specs()` function performs a comprehensive validation by executing a rollout and checking all tensors:

```

```

This function:

  - Calls env.reset() and validates the output

  - Executes several env.step() calls

  - Validates all keys, shapes, dtypes, and bounds

  - Checks for dynamic specs (tensors with varying shapes)

Sources: torchrl/envs/utils.py653-909

#### Common Validation Errors

| Error Type | Cause | Solution |
| TypeError: expected done.dtype to... | Done signal has wrong dtype | Ensure done tensors are torch.bool |
| KeyError: key not found | Missing required key | Add missing key to output or adjust spec |
| ValueError: shape mismatch | Tensor shape doesn't match spec | Fix shape in _reset() or _step() |
| AssertionError: out of bounds | Value outside Bounded range | Check action or observation values |

Sources: test/test_env.py262-283

### Batch Size and Device Management

#### Batch Size

The `batch_size` property defines the leading dimensions of all environment tensors. For a single environment, `batch_size=torch.Size([])`. For batched environments, `batch_size=torch.Size([num_envs])` or higher-dimensional.

```

```

The `batch_locked` property determines whether the environment requires inputs with matching `batch_size`. Most base environments are batch-unlocked, while batched environments are batch-locked.

Sources: torchrl/envs/common.py801-846

#### Device Management

The `device` property specifies where tensors should reside. Can be `None` for deviceless environments (common for numpy-based backends):

```

```

Specs are automatically moved to match the environment device. When calling `step()`, inputs are expected to be on the correct device.

### Conclusion

The environment base classes in TorchRL provide a unified, flexible interface for interacting with environments. By leveraging TensorDict as a core data structure and utilizing a comprehensive specification system, these base classes enable consistent behavior across different environment types while supporting advanced features like batching, device management, and transformation.

Understanding these base classes is fundamental to working with environments in TorchRL, whether using existing environments or implementing custom ones.
