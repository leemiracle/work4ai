## TensorDict System

Relevant source files

  - torchrl/data/utils.py

### Purpose and Scope

This document explains TensorDict as TorchRL's universal data container and how it enables composable, type-safe RL components. TensorDict is a dictionary-like structure from the `tensordict` library that TorchRL uses as its central data abstraction for representing environment observations, actions, rewards, and all other tensorial data flowing through the RL pipeline.

This page covers:

  - TensorDict's role as the central data hub in TorchRL

  - Core concepts: batch dimensions, nested structure, and key-based access

  - Operations: indexing, slicing, stacking, concatenation

  - Integration patterns: in_keys / out_keys for composable modules

  - How TensorDict enables zero-copy data sharing across system boundaries

For information about the type system that validates TensorDict contents, see TensorSpec System.

### What is TensorDict

TensorDict is a dictionary-like container that stores PyTorch tensors with a shared leading batch dimension. Unlike a standard Python dictionary, TensorDict:

  - Enforces shape consistency : All contained tensors must share the same batch dimensions

  - Supports batch operations : Indexing, slicing, and stacking operate on all tensors simultaneously

  - Enables nested structure : Keys can be tuples for hierarchical organization (e.g., ("agents", "observations") )

  - Provides zero-copy views : Indexing and slicing return views, not copies

  - Integrates with TensorSpec : Each key can have an associated spec for validation

### Core Concepts

#### Batch Dimensions

Every TensorDict has a batch size (a tuple of integers) that defines its leading dimensions. All contained tensors must have these dimensions as their leading shape.

The batch dimensions represent:

  - First dimension (32): Number of parallel environments

  - Second dimension (10): Number of timesteps in rollout

  - Remaining dimensions: Feature dimensions specific to each tensor

TensorDict supports nested keys using tuples for organizing related data:

This hierarchical organization is extensively used in TorchRL for:

  - Temporal structure : ("next", key) for next-state data

  - Multi-agent : ("agents", agent_id, key) for per-agent data

  - Complex observations : ("observation", "pixels") vs ("observation", "state")

#### Key Types and Conventions

TorchRL follows these key naming conventions throughout the codebase:

| Key Pattern | Purpose | Example |
| "observation" | Current state observation | Environment state |
| "action" | Agent action | Policy output |
| ("next", key) | Next-timestep data | Bootstrapping targets |
| "reward" | Scalar reward | Environment feedback |
| "done" | Episode termination flag | Reset signal |
| "terminated" | True termination | Episode naturally ended |
| "truncated" | Time limit truncation | Max steps reached |
| ("agents", id, key) | Multi-agent data | Per-agent observations/actions |

### Summary

TensorDict serves as TorchRL's universal data container, enabling:

  - Standardized interfaces : All components communicate via TensorDict

  - Batch operations : Efficient vectorized processing

  - Composability : Modules connect via in_keys / out_keys

  - Type safety : Integration with TensorSpec for validation

  - Zero-copy efficiency : Views and shared memory reduce overhead

The TensorDict abstraction is fundamental to TorchRL's modular architecture, allowing arbitrary combinations of environments, transforms, policies, and algorithms to work together seamlessly.

For the type system that validates TensorDict contents, see TensorSpec System.
