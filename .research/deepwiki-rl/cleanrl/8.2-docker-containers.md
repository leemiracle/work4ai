### Purpose and Scope

This document covers CleanRL's Docker containerization strategy for reproducible training environments. It explains the main production Dockerfile configuration, the Gitpod-based development environment, and the dependency installation workflow using `uv`. For information about using these containers in cloud infrastructure, see AWS Batch Setup. For local development without containers, see Installation.

### Container Architecture Overview

CleanRL provides two Docker configurations: a production container for cloud deployment and a Gitpod container for browser-based development. Both share a common dependency installation strategy but differ in base images and use cases.

The production Dockerfile builds a CUDA-enabled container optimized for GPU training on cloud infrastructure. It uses a multi-stage approach to minimize image size while maintaining necessary runtime dependencies.

#### System Dependencies Installation

The container installs essential system packages in a single `apt-get` layer to minimize image layers:

### Dependency Installation with uv

CleanRL uses the `uv` package manager for fast, reproducible dependency installation. The installation process follows a specific sequence to leverage Docker layer caching.

```

```

The `cleanrl_utils` directory creation at Dockerfile10 occurs before `uv` installation to satisfy package discovery. The `pyproject.toml` and `uv.lock` files are copied separately from source code at Dockerfile12-13 to maximize cache hits when only code changes. The final installation is performed via `uv pip install .` Dockerfile14

### Gitpod Workspace Configuration

The `.gitpod.yml` file configures workspace behavior and prebuild settings.

#### Initialization Task

The `init` task at .gitpod.yml5 runs `uv pip install .` during workspace creation. This installs CleanRL and its dependencies before the user accesses the workspace, reducing startup time.

#### Prebuild Configuration

CleanRL enables aggressive prebuilding for the `master` branch and all other branches, including Pull Requests from forks .gitpod.yml12-20 This ensures that the environment is ready for review as soon as a PR is opened.

| Setting | Value | Effect |
| master | true | Prebuild main branch |
| branches | true | Prebuild all branches |
| pullRequests | true | Prebuild internal PRs |
| pullRequestsFromForks | true | Prebuild fork PRs |
| addLabel | prebuilt-in-gitpod | Label prebuilt PRs |

Sources: .gitpod.yml1-27
