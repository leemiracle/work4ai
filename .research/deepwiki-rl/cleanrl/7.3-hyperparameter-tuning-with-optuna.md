This document describes CleanRL's hyperparameter tuning system built on Optuna, which provides automated hyperparameter search for RL algorithms. The `Tuner` class orchestrates trials across multiple seeds and environments, integrates with Weights & Biases for tracking, and supports advanced Optuna features like pruning and custom samplers.

The primary philosophy of the `Tuner` is to find a single set of hyperparameters that work well across multiple tasks of a similar type (e.g., one set for all MuJoCo tasks) rather than over-tuning per individual task docs/advanced/hyperparameter-tuning.md3

### Overview

The hyperparameter tuning system is implemented in the `cleanrl_utils.tuner` module and provides:

  - Automated hyperparameter search using Optuna's optimization algorithms (TPE, CMA-ES, etc.) cleanrl_utils/tuner.py 135-136

  - Multi-seed evaluation to mitigate the impact of randomness on results docs/advanced/hyperparameter-tuning.md 73

  - Multi-environment support with score normalization across different reward scales docs/advanced/hyperparameter-tuning.md 54-57

  - Early stopping via Optuna's pruning mechanisms cleanrl_utils/tuner.py 119-122

  - Persistent storage using SQLite for resumable and parallelizable studies cleanrl_utils/tuner.py 36

  - W&B integration for tracking trial results cleanrl_utils/tuner.py 75-83

### Tuner Class

#### Initialization

The `Tuner` class is configured with the search space and the target metrics.

| Parameter | Type | Description |
| script | str | Path to the single-file algorithm (e.g., "cleanrl/ppo.py" ) cleanrl_utils/tuner.py 27 |
| metric | str | The TensorBoard tag to optimize (e.g., "charts/episodic_return" ) cleanrl_utils/tuner.py 28 |
| target_scores | Dict | Env IDs mapped to [min, max] scores for normalization cleanrl_utils/tuner.py 29 |
| params_fn | Callable | Lambda/function suggesting parameters via trial.suggest_* cleanrl_utils/tuner.py 30 |
| aggregation_type | str | Strategy for multi-env/multi-seed: average , median , max , min cleanrl_utils/tuner.py 32 |
| storage | str | SQLite connection string (default: sqlite:///cleanrl_hpopt.db ) cleanrl_utils/tuner.py 36 |

Sources: cleanrl_utils/tuner.py24-69

#### Score Normalization and Aggregation

Because different environments have different reward scales, the `Tuner` uses `target_scores` to normalize performance before aggregation docs/advanced/hyperparameter-tuning.md54-57

  - Normalization : For each environment, the raw metric $x$ is transformed to $z = (x - min) / (max - min)$ cleanrl_utils/tuner.py 104-107

  - Aggregation : Scores across environments are combined using aggregation_fn (e.g., np.average or np.median ) cleanrl_utils/tuner.py 52-61

  - Final Value : The objective returns the average of the aggregated normalized scores across all seeds cleanrl_utils/tuner.py 126-128
