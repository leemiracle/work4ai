This page documents how CleanRL works with classic control environments, which are the simplest benchmark problems in reinforcement learning. These environments have low-dimensional state spaces and simple dynamics, making them ideal for learning reinforcement learning concepts and testing algorithm implementations. For more complex environments such as Atari games, see Atari Games, and for continuous control tasks like MuJoCo, see MuJoCo and Continuous Control.

### What are Classic Control Environments?

Classic control environments in reinforcement learning refer to a set of simple control problems originally from the control theory literature that have become standard benchmarks. In CleanRL, these environments are implemented through the Gymnasium library (formerly OpenAI Gym).

The main classic control environments include:

| Environment | Description | Observation Space | Action Space | Default Episode Limit |
| CartPole-v1 | Balance a pole on a moving cart | 4D vector (cart position, cart velocity, pole angle, pole angular velocity) | Discrete(2) | 500 steps |
| MountainCar-v0 | Drive an underpowered car up a mountain | 2D vector (position, velocity) | Discrete(3) | 200 steps |
| Acrobot-v1 | Swing up a two-link robot | 6D vector (sin/cos of angles, angular velocities) | Discrete(3) | 500 steps |
| Pendulum-v1 | Swing a pendulum to an upright position | 3D vector (sin/cos of angle, angular velocity) | Continuous(1) | 200 steps |

Sources: cleanrl/ppo.py37-38 cleanrl/dqn.py44-45 cleanrl/ppo_continuous_action.py43-44

The environment setup in CleanRL follows these steps:

  - Define a make_env function that returns a "thunk" (function that creates an environment) cleanrl/ppo.py 81-91

  - The thunk creates an environment using gym.make(env_id) (where env_id is something like "CartPole-v1") cleanrl/dqn.py 78-81

  - Apply common wrappers like RecordEpisodeStatistics for tracking performance metrics like episodic_return cleanrl/dqn.py 82 cleanrl/ppo.py 88

  - Optionally apply RecordVideo for capturing agent behavior cleanrl/dqn.py 79

  - Create multiple instances using SyncVectorEnv for parallel training cleanrl/ppo.py 162-164

### Network Architectures for Classic Control

Due to the simple nature of classic control environments (low-dimensional state spaces), CleanRL uses simple multi-layer perceptron (MLP) architectures for these environments:

Key differences between network architectures in CleanRL:

  - PPO : Uses an Agent class containing both actor and critic networks with Tanh activations and 64-unit hidden layers cleanrl/ppo.py 100-116 It uses orthogonal initialization via layer_init cleanrl/ppo.py 94-97

  - DQN : Uses a QNetwork class with ReLU activations and 120/84 hidden units cleanrl/dqn.py 91-103

  - Continuous PPO : Uses an actor_mean network and a separate actor_logstd parameter for Gaussian action distributions cleanrl/ppo_continuous_action.py 122-129

### Testing and Validation

Classic control environments serve as the primary target for automated testing in CleanRL to ensure algorithm correctness with minimal compute resources. Tests typically run for a very small number of timesteps to verify the code path executes without error.

  - PPO Test : Executes ppo.py with 1 environment and 256 total timesteps tests/test_classic_control.py 4-9

  - DQN Test : Executes dqn.py with specific learning-starts and total-timesteps tests/test_classic_control_gymnasium.py 4-9

  - Evaluation : The cleanrl_utils.evals module provides scripts like c51_eval.py to load saved models and evaluate them on environments like CartPole-v1 cleanrl_utils/evals/c51_eval.py 54-64

Sources: tests/test_classic_control.py4-9 tests/test_classic_control_gymnasium.py4-9 cleanrl_utils/evals/c51_eval.py49-64
