This page provides technical instructions on how to run and utilize CleanRL's reinforcement learning algorithm implementations. It covers command-line execution, the `Args` dataclass pattern powered by `tyro`, and the standard training loop structure found across the codebase.

### Command Line Execution

CleanRL uses `uv` for dependency management and environment isolation. There are two primary workflows for executing scripts:

  - Direct Execution : Using uv run to execute a script within the project's environment.

  - Activated Environment : Activating the virtual environment with uv venv and running scripts directly with python .

### Configuration via Tyro and Dataclasses

CleanRL utilizes the `tyro` library to transform a Python `dataclass` into a command-line interface. This pattern ensures that hyperparameters are typed, documented, and easily accessible throughout the script.

#### The Args Dataclass Pattern

Each script defines an `Args` class. The fields in this class serve as the experiment's configuration schema.

### Core Training Loop Structure

CleanRL follows a "single-file implementation" philosophy where the entire logic—from environment setup to the training loop—resides in one file.

#### Implementation Workflow

The scripts generally follow this sequence:

  - Argument Parsing : Initialize Args via tyro cleanrl/ppo.py 130

  - Environment Setup : Initialize vectorized environments using make_env helpers cleanrl/ppo.py 162-164

  - Agent Initialization : Define and instantiate neural network modules (e.g., Agent or QNetwork ) cleanrl/ppo.py 167

  - Training Loop : Rollout Collection : Interact with the environment to collect transitions cleanrl/ppo.py 192-225 Optimization : Perform gradient updates on the networks cleanrl/ppo.py 261-295 Logging : Write statistics to SummaryWriter cleanrl/ppo.py 298-310

### Environment Wrappers and Vectorization

CleanRL scripts use `gym.vector.SyncVectorEnv` to manage multiple environments in parallel cleanrl/ppo.py162 This is paired with the `make_env` utility function which applies standard wrappers:

  - RecordEpisodeStatistics : Essential for tracking episodic return and length cleanrl/ppo.py 88

  - RecordVideo : Triggered when capture_video is True, specifically for the first environment index cleanrl/ppo.py 83-85

  - Normalization : Algorithms like ppo_continuous_action.py apply NormalizeObservation and NormalizeReward to stabilize training cleanrl/ppo_continuous_action.py 97-99

  - Atari Preprocessing : dqn_atari.py includes a suite of wrappers such as NoopResetEnv , MaxAndSkipEnv , and FrameStack to match the Nature DQN paper cleanrl/dqn_atari.py 91-99
