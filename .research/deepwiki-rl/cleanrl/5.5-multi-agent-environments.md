This page documents CleanRL's integration with PettingZoo for multi-agent reinforcement learning scenarios. It covers the implementation of competitive and cooperative multi-agent algorithms, focusing on the Atari multi-agent environment setup.

For single-agent Atari environments, see Atari Games. For GPU-accelerated parallel environments, see Isaac Gym Integration.

### Overview

CleanRL supports multi-agent environments through the PettingZoo library, specifically implementing PPO for competitive Atari games. The implementation handles multiple agents within the same environment, where agents may compete or cooperate. The key implementation is `ppo_pettingzoo_ma_atari.py`, which adapts single-agent PPO to handle multiple simultaneous players.

Key Features:

  - Support for PettingZoo's Atari environments (e.g., pong_v3 , tennis_v3 , boxing_v3 ) [cleanrl/ppo_pettingzoo_ma_atari.py 40-41 ]

  - Competitive two-player scenarios with shared policy networks [cleanrl/ppo_pettingzoo_ma_atari.py 87-117 ]

  - Agent-specific observation encoding through indicator channels [cleanrl/ppo_pettingzoo_ma_atari.py 157 ]

  - Parallel vectorized environment execution [cleanrl/ppo_pettingzoo_ma_atari.py 158-159 ]

  - Per-player episodic return tracking [cleanrl/ppo_pettingzoo_ma_atari.py 210-215 ]

Sources: cleanrl/ppo_pettingzoo_ma_atari.py1-314

### Network Architecture Modifications

```

```

Agent Network with Multi-channel Input

The network architecture in `ppo_pettingzoo_ma_atari.py` differs from single-agent implementations in two key ways:

  - Input channels : Processes 6 channels instead of 4 (4 stacked frames + 2 agent indicator channels) [cleanrl/ppo_pettingzoo_ma_atari.py 91 ]

  - Selective normalization : Only the first 4 channels (RGB frames) are normalized by 255; agent indicator channels remain unnormalized [cleanrl/ppo_pettingzoo_ma_atari.py 106 ]

The agent indicator channels encode which player is observing the state, allowing the shared policy network to condition its behavior on player identity.

Sources: cleanrl/ppo_pettingzoo_ma_atari.py87-117

### Multi-agent PPO Training Loop

```

```

Multi-agent Training State Machine

The training loop maintains the same structure as single-agent PPO but handles multiple players within each environment instance. The key difference is in the rollout phase, where actions are sampled from a shared policy network for all agents simultaneously [cleanrl/ppo_pettingzoo_ma_atari.py199-201].

Sources: cleanrl/ppo_pettingzoo_ma_atari.py186-311

### Observation and Action Handling

#### Observation Space

The observation space for multi-agent Atari environments has shape `(84, 84, 6)` [cleanrl/ppo_pettingzoo_ma_atari.py91]:

| Channels | Content | Preprocessing |
| 0-3 | Stacked grayscale frames | Normalized by 255 [cleanrl/ppo_pettingzoo_ma_atari.py 106 ] |
| 4-5 | Agent indicator | One-hot encoding of player ID [cleanrl/ppo_pettingzoo_ma_atari.py 157 ] |

The agent indicator allows the shared policy network to differentiate between players, enabling competitive strategies.

#### Vectorized Environment Structure

```

```

Each game instance contains two players. With `num_envs=16`, the system runs 8 parallel games, providing experience from 16 agent perspectives simultaneously [cleanrl/ppo_pettingzoo_ma_atari.py159].

Per-player Metric Tracking

### Algorithm Details

#### Shared Policy Architecture

The implementation uses a shared policy network [cleanrl/ppo_pettingzoo_ma_atari.py87] where both players are controlled by the same neural network parameters. The agent indicator channels allow the network to condition its outputs on player identity, enabling it to learn asymmetric strategies when appropriate.

#### GAE Computation

Generalized Advantage Estimation (GAE) is computed using the same discount factor (`gamma=0.99`) [cleanrl/ppo_pettingzoo_ma_atari.py52] and GAE lambda (`gae_lambda=0.95`) [cleanrl/ppo_pettingzoo_ma_atari.py54] as standard PPO. The advantages are calculated independently for each agent's experience in the vectorized buffer.

#### Loss Functions

The loss function combines three terms [cleanrl/ppo_pettingzoo_ma_atari.py264-285]:

  - Policy loss : Clipped surrogate objective [cleanrl/ppo_pettingzoo_ma_atari.py 267 ]

  - Value loss : MSE between predicted and actual returns [cleanrl/ppo_pettingzoo_ma_atari.py 281 ]

  - Entropy loss : Encourages exploration [cleanrl/ppo_pettingzoo_ma_atari.py 277 ]
