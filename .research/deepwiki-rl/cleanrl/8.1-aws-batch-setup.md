### Purpose and Scope

This document describes the infrastructure and tooling for deploying CleanRL experiments on AWS Batch. It covers the Terraform configuration for compute environments (on-demand and spot g4dn instances), IAM roles, and networking. Additionally, it details the `cleanrl_utils/submit_exp.py` utility used to programmatically build Docker containers and submit multi-seed experiments to AWS Batch.

### Infrastructure Architecture

The AWS Batch infrastructure is defined using Terraform modules in the `cloud/` directory. The setup creates parallel compute environments for both on-demand and spot instances across multiple instance types.

### Experiment Submission Utility

The `cleanrl_utils/submit_exp.py` script automates the process of containerization and AWS Batch job submission. It supports local Docker dry-runs and remote AWS execution.

#### Key Functions and Workflow

  - Docker Build/Push : If --build is toggled, it uses docker buildx to create images for specified architectures cleanrl_utils/submit_exp.py 51-57

  - W&B Integration : It automatically retrieves the W&B API key from .netrc if not provided, ensuring experiments are tracked cleanrl_utils/submit_exp.py 59-64

  - Command Generation : It expands a single base command into multiple seed-specific commands cleanrl_utils/submit_exp.py 67-69

  - AWS Batch Submission : For provider == "aws" , it uses boto3 to register job definitions and submit jobs to the specified queue cleanrl_utils/submit_exp.py 90-142

### Resource Naming Convention

Terraform systematically names resources to match the `job-queue` argument in `submit_exp.py`:

  - On-demand : replace(instance_type, ".", "-") (e.g., g4dn-xlarge ) cloud/modules/cleanrl/main.tf 7

  - Spot : replace("${instance_type}-spot", ".", "-") (e.g., g4dn-xlarge-spot ) cloud/modules/cleanrl/main.tf 43
