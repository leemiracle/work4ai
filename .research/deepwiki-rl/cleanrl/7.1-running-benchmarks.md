This page describes CleanRL's benchmarking infrastructure for evaluating RL algorithms across multiple environments, seeds, and hardware configurations. Benchmarking is essential for ensuring implementation quality by comparing results against reference implementations and for understanding algorithm performance characteristics.

For information about experiment tracking with W&B and TensorBoard during individual training runs, see 7.2 For hyperparameter optimization using Optuna, see 7.3

### Overview

CleanRL provides shell scripts in `benchmark/` for systematically evaluating algorithms across multiple environments and random seeds. These scripts use the `cleanrl_utils.benchmark` module to orchestrate parallel experiment execution, optionally leveraging SLURM clusters for large-scale benchmarking.

Key Features:

  - Multi-environment testing : Run the same algorithm across multiple environments in parallel.

  - Multi-seed evaluation : Execute multiple random seeds per environment for statistical reliability.

  - Local and cloud execution : Support for both local machines and SLURM-managed clusters.

  - Automated tracking : Integration with Weights & Biases for result aggregation.

  - Auto-tagging : Automatic tagging of runs with Git metadata and Pull Request numbers.

### Implementation Details

#### Auto-Tagging and Metadata

The `autotag()` function in `cleanrl_utils/benchmark.py` retrieves Git metadata to populate the `WANDB_TAGS` environment variable `cleanrl_utils/benchmark.py:54-87`:

  - It identifies the git tag via git describe --tags cleanrl_utils/benchmark.py:59 .

  - If no tag exists, it generates one using the commit count and short hash (e.g., no-tag-123-gabc123 ) cleanrl_utils/benchmark.py:67 .

  - It queries the GitHub API to find associated Pull Request numbers for the current commit hash cleanrl_utils/benchmark.py:76-83 .

#### Local Execution

When `args.workers > 0` and no SLURM template is provided, the module uses `concurrent.futures.ThreadPoolExecutor` to run experiments in parallel `cleanrl_utils/benchmark.py:110-116`. The `run_experiment` function uses `subprocess.Popen` to execute the generated commands `cleanrl_utils/benchmark.py:39-52`.

#### SLURM Integration

If `args.slurm_template_path` is provided, the script generates a `.slurm` file in the `slurm/` directory `cleanrl_utils/benchmark.py:121-149`. It performs string replacement on placeholders within the template:

  - {{array}} : Configures the SLURM job array (e.g., 0-8%9 ) cleanrl_utils/benchmark.py:129 .

  - {{env_ids}} and {{seeds}} : Injects the lists of environments and seeds cleanrl_utils/benchmark.py:130-134 .

  - {{cpus_per_gpu}} : Calculated as math.ceil(args.slurm_total_cpus / (args.slurm_gpus_per_task * args.slurm_ntasks)) cleanrl_utils/benchmark.py:138-140 .

### OpenRL Benchmark Integration

CleanRL integrates with the `openrlbenchmark` utility for performance analysis and "RLops". This is a requirement for performance-impacting changes in the contribution guide `.github/pull_request_template.md:22-32`.

Workflow for Contributors:

  - Obtain access to the openrlbenchmark W&B team .github/pull_request_template.md:24 .

  - Submit experiments using cleanrl_utils.benchmark with the --track flag .github/pull_request_template.md:25 .

  - Generate comparison tables and learning curves using python -m openrlbenchmark.rlops .github/pull_request_template.md:26-32 .
