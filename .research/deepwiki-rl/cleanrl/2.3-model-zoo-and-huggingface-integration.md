## Model Zoo and HuggingFace Integration

Relevant source files

  - cleanrl_utils/huggingface.py

  - docs/get-started/experiment-tracking.md

  - docs/get-started/zoo.md

### Purpose and Scope

This page documents CleanRL's integration with HuggingFace's Model Hub, which enables sharing and loading pre-trained reinforcement learning models. This integration is currently in experimental phase and supports a subset of CleanRL's algorithms docs/get-started/zoo.md6-7 The page covers how to download and evaluate models from the cleanrl organization on HuggingFace, use the `cleanrl_utils.enjoy` evaluation utility, and upload your own trained models with the `--save-model` and `--upload-model` flags docs/get-started/zoo.md50-57

For information about training algorithms from scratch, see Basic Usage. For benchmarking and performance tracking, see Experiment Tracking.

### Supported Algorithms

CleanRL's HuggingFace integration currently supports the following algorithm variants docs/get-started/zoo.md9-22:

| Algorithm | PyTorch Variants | JAX Variants |
| DQN | dqn.py , dqn_atari.py | dqn_jax.py , dqn_atari_jax.py |
| C51 | c51.py , c51_atari.py | c51_jax.py , c51_atari_jax.py |
| DDPG | ddpg_continuous_action.py | ddpg_continuous_action_jax.py |
| TD3 | td3_continuous_action.py | td3_continuous_action_jax.py |

Each algorithm supports both classic control environments (e.g., CartPole-v1) and, where applicable, Atari environments with CNN-based processing docs/get-started/zoo.md25-39

Sources: docs/get-started/zoo.md1-23 docs/get-started/zoo.md25-39

Diagram: CleanRL HuggingFace Integration Flow

The integration follows a three-phase workflow:

  - Training Phase : Algorithm scripts create network instances wrapped in agent classes that implement model serialization.

  - Local Storage : Models are saved to the runs/ directory with the .cleanrl_model extension docs/get-started/zoo.md 52

  - Upload Phase : The push_to_hub function in cleanrl_utils/huggingface.py handles the creation of the repository, generation of a model card, and uploading of weights, code, and metadata cleanrl_utils/huggingface.py 15-143

  - Evaluation Phase : The cleanrl_utils.enjoy module fetches models and runs them in environments docs/get-started/zoo.md 27-31

### Model Persistence Implementation

The `push_to_hub` function in `cleanrl_utils/huggingface.py` automates the repository setup and file management:

```

```

Diagram: push_to_hub Implementation Steps

Key implementation details in `push_to_hub`:

  - Model Card Generation : Automatically creates a README.md with performance metrics ( mean_reward ) and the command to reproduce the training cleanrl_utils/huggingface.py 48-110

  - Source Code Preservation : Uploads the exact training script ( sys.argv[0] ), pyproject.toml , and poetry.lock to the repository cleanrl_utils/huggingface.py 129-135

  - Video Previews : Automatically finds the latest recorded .mp4 and renames it to replay.mp4 for the HuggingFace video preview cleanrl_utils/huggingface.py 113-121

  - Automatic Cleanup : Deletes previous TensorBoard event files and videos in the repository before pushing new ones to avoid clutter cleanrl_utils/huggingface.py 40-46

### Limitations and Future Roadmap

The HuggingFace integration is currently in experimental status docs/get-started/zoo.md6:

| Limitation | Details |
| Algorithm Coverage | Only DQN, C51, DDPG, and TD3 variants supported docs/get-started/zoo.md 9-22 |
| Missing Algorithms | PPO, SAC, and advanced algorithms not yet integrated |
| Retry Logic | The upload process uses a retry mechanism (10 attempts, 3s wait) to handle network instability cleanrl_utils/huggingface.py 14-15 |

Sources: docs/get-started/zoo.md6-23 cleanrl_utils/huggingface.py14-15
