This document details the implementation and variants of the Proximal Policy Optimization (PPO) algorithm in CleanRL. PPO is a popular policy gradient method that improves training stability through a clipped surrogate objective function. All PPO implementations in CleanRL are augmented with the "13 core implementation details" identified in the study of `openai/baselines` docs/rl-algorithms/ppo.md81-100

### Overview of PPO

PPO is designed to balance sample efficiency, implementation simplicity, and performance. It addresses the challenge of determining appropriate step sizes when optimizing policies by using a "clipped" objective function that restricts policy updates to a reasonable range.

#### Agent Architecture

The `Agent` class implements both policy (actor) and value (critic) networks. CleanRL uses `layer_init` to perform orthogonal initialization, which is a critical detail for performance cleanrl/ppo.py94-97

For discrete action spaces (e.g., `ppo.py` for `CartPole-v1`):

  - Critic : Three linear layers with Tanh activation cleanrl/ppo.py 103-109

  - Actor : Three linear layers with Tanh activation, outputting logits for Categorical distribution cleanrl/ppo.py 110-116

For continuous action spaces (e.g., `ppo_continuous_action.py`):

  - Actor : Learns actor_mean via a network and maintains a separate actor_logstd parameter cleanrl/ppo_continuous_action.py 122-129

  - Distribution : Uses torch.distributions.normal.Normal cleanrl/ppo_continuous_action.py 138

Sources: cleanrl/ppo.py100-126 cleanrl/ppo_continuous_action.py112-141

#### Data Flow and Loss Functions

  - GAE Calculation : CleanRL calculates advantages using the lastgaelam variable to track the recursive GAE term cleanrl/ppo.py 217-232

  - Clipped Surrogate Objective : The policy loss is the minimum of the unclipped and clipped ratios cleanrl/ppo.py 266-271

  - Value Loss Clipping : CleanRL supports clipping the value function loss to prevent the value function from changing too much in a single update cleanrl/ppo.py 274-284

### PPO Variants in CleanRL

CleanRL provides several specialized PPO variants:

| Variant | File | Key Feature |
| Standard | ppo.py | MLP for low-dimensional discrete tasks cleanrl/ppo.py |
| Atari | ppo_atari.py | CNN with Nature DQN architecture and Atari wrappers cleanrl/ppo_atari.py |
| Continuous | ppo_continuous_action.py | Gaussian policy for MuJoCo/dm_control cleanrl/ppo_continuous_action.py |
| LSTM | ppo_atari_lstm.py | LSTM layer for POMDPs without frame stacking cleanrl/ppo_atari_lstm.py |
| Multi-GPU | ppo_atari_multigpu.py | DistributedDataParallel via torchrun cleanrl/ppo_atari_multigpu.py |
| EnvPool | ppo_atari_envpool.py | C++ vectorized environments for speed docs/rl-algorithms/ppo.md 30 |
| Robust (RPO) | rpo_continuous_action.py | Perturbed action mean for better exploration docs/rl-algorithms/rpo.md 5 |

#### Atari PPO

Uses a specific CNN architecture: three `Conv2d` layers followed by a `Linear` layer cleanrl/ppo_atari.py120-130 It incorporates `NoopResetEnv`, `MaxAndSkipEnv`, `EpisodicLifeEnv`, and `FrameStack` wrappers cleanrl/ppo_atari.py97-105

#### LSTM PPO

Integrates an `nn.LSTM` between the CNN extractor and the actor/critic heads cleanrl/ppo_atari_lstm.py131 It handles state resetting by multiplying the hidden state by `(1.0 - done)` cleanrl/ppo_atari_lstm.py152-153

#### Multi-GPU Training

Uses `torch.distributed` to synchronize gradients across ranks cleanrl/ppo_atari_multigpu.py175 The local batch size is multiplied by the world size to determine the global batch size cleanrl/ppo_atari_multigpu.py168-172

### Hyperparameters and Logging

CleanRL uses `tyro` for command-line arguments and `SummaryWriter` for logging. Key metrics include:

  - losses/policy_loss : The clipped surrogate objective cleanrl/ppo.py 307

  - losses/approx_kl : Measured by (logratio.exp() - 1) - logratio (k3 estimator) cleanrl/ppo.py 304

  - losses/explained_variance : How well the value function predicts returns cleanrl/ppo.py 311

  - charts/SPS : Steps Per Second cleanrl/ppo.py 302

#### Default Hyperparameters

  - learning_rate : 2.5e-4 (annealed by default) cleanrl/ppo.py 41-47

  - num_steps : 128 per environment cleanrl/ppo.py 45

  - update_epochs : 4 cleanrl/ppo.py 55

  - clip_coef : 0.2 cleanrl/ppo.py 59

Sources: cleanrl/ppo.py17-79 cleanrl/ppo.py301-312 docs/rl-algorithms/ppo.md64-79

### Implementation Optimization Features

CleanRL's PPO implementations include several optimizations:

  - Advantage Normalization : Stabilizes updates by standardizing advantages within a minibatch cleanrl/ppo.py 261-262

  - Learning Rate Annealing : Linearly decays the learning rate based on total iterations cleanrl/ppo.py 187-190

  - Gradient Clipping : Uses nn.utils.clip_grad_norm_ to prevent exploding gradients cleanrl/ppo.py 289

  - Orthogonal Initialization : Specific std values for actor (0.01) and critic (1.0) to improve convergence cleanrl/ppo.py 108-115
