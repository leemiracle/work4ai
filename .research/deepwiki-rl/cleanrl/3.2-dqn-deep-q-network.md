### Purpose and Scope

This document describes CleanRL's implementation of Deep Q-Network (DQN), a value-based reinforcement learning algorithm for discrete action spaces. DQN extends Q-learning with neural network function approximation, experience replay, and target networks to achieve stable training on high-dimensional state spaces.

This page covers the four DQN variants implemented in CleanRL:

  - Classic control environments ( cleanrl/dqn.py )

  - Atari games with CNN architecture ( cleanrl/dqn_atari.py )

  - JAX/Flax implementations for both ( cleanrl/dqn_jax.py cleanrl/dqn_atari_jax.py )

For other value-based algorithms, see Advanced Algorithms. For policy gradient methods, see PPO (Proximal Policy Optimization). For continuous action spaces, see DDPG and TD3 or SAC (Soft Actor-Critic).

Sources: docs/rl-algorithms/dqn.md1-25 cleanrl/dqn.py1-20

### Algorithm Overview

DQN learns a Q-function $Q(s, a)$ that estimates the expected cumulative reward from taking action $a$ in state $s$. The algorithm introduces two key innovations over tabular Q-learning:

  - Experience Replay : Stores transitions $(s, a, r, s')$ in a replay buffer and samples mini-batches for training, breaking correlation between consecutive samples.

  - Target Network : Maintains a separate, slowly-updated copy of the Q-network to compute stable TD targets.

The core update minimizes the temporal difference (TD) error:

$$L(\theta) = \mathbb{E}{(s,a,r,s') \sim \mathcal{D}} \left[ \left( r + \gamma \max{a'} Q(s', a'; \theta^{-}) - Q(s, a; \theta) \right)^2 \right]$$

where $\theta$ are the Q-network parameters, $\theta^{-}$ are the target network parameters, and $\mathcal{D}$ is the replay buffer.

### Core Components

#### QNetwork Architecture

The architecture varies significantly between classic control (vector inputs) and Atari (pixel inputs).

```

```

Classic Control Network (cleanrl/dqn.py91-103):

  - Input: Low-dimensional observation vector.

  - Architecture: Simple 3-layer MLP (120 → 84 → n_actions).

Atari Network (cleanrl/dqn_atari.py108-125):

  - Input: 4 stacked 84×84 grayscale frames.

  - Architecture: Nature DQN CNN (3 conv layers + 2 FC layers).

  - Pixel normalization: Divides by 255.0 at forward pass ( cleanrl/dqn_atari.py 125 ).

### Implementation Details

#### Atari Environment Wrappers

Atari environments use a specific preprocessing pipeline to convert raw RGB frames into stacked grayscale observations (cleanrl/dqn_atari.py82-104):

  - NoopResetEnv : Up to 30 random no-op actions at reset ( cleanrl_utils/atari_wrappers.py 12 ).

  - MaxAndSkipEnv : Repeat action for 4 frames, return max over last 2 ( cleanrl_utils/atari_wrappers.py 97 ).

  - EpisodicLifeEnv : End episode when a life is lost ( cleanrl_utils/atari_wrappers.py 61 ).

  - FireResetEnv : Execute FIRE action at reset for specific games ( cleanrl_utils/atari_wrappers.py 41 ).

  - ClipRewardEnv : Clip rewards to {-1, 0, 1} ( cleanrl_utils/atari_wrappers.py 125 ).

  - Resize/GrayScale/FrameStack : Standard Gymnasium wrappers to output 84x84x4 tensors.

Sources: cleanrl/dqn_atari.py82-104 cleanrl_utils/atari_wrappers.py1-130

### JAX Implementation Details

The JAX variants (cleanrl/dqn_jax.py cleanrl/dqn_atari_jax.py) use the `TrainState` pattern from Flax to manage model parameters and optimizer state (cleanrl/dqn_jax.py102-103).

Key Features:

  - JIT Compilation : The update function is decorated with @jax.jit to compile the gradient descent step into optimized XLA code ( cleanrl/dqn_jax.py 166 ).

  - Functional State : Instead of optimizer.step() , the update function returns a new q_state ( cleanrl/dqn_jax.py 179 ).

  - Memory Management : For Atari, XLA_PYTHON_CLIENT_MEM_FRACTION is set to 0.7 to prevent JAX from pre-allocating all GPU memory ( cleanrl/dqn_atari_jax.py 8 ).

Sources: cleanrl/dqn_jax.py147-179 cleanrl/dqn_atari_jax.py176-218

### Differences from Original Paper

CleanRL's implementation differs from the Nature DQN paper (Mnih et al., 2015) in several ways:

  - Optimizer : Uses Adam ( cleanrl/dqn_atari.py 170 ) instead of RMSprop.

  - Target Network Frequency : Uses 1,000 steps ( cleanrl/dqn_atari.py 66-67 ) instead of 10,000.

  - Loss Function : Uses standard MSE instead of clipped error (Huber-like) loss ( docs/rl-algorithms/dqn.md 102 ).

  - Soft Updates : Supports Polyak updates via --tau ( cleanrl/dqn_atari.py 64-65 ).
