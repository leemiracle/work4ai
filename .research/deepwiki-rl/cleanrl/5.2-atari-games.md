This wiki page provides technical documentation for working with Atari environments in CleanRL. It covers the specific environment wrappers, network architectures, and implementation details for running reinforcement learning algorithms on Atari games.

For general or Classic Control environments, see Classic Control. For continuous action environments, see MuJoCo and Continuous Control.

### Environment Setup

Atari environments in CleanRL utilize a standardized preprocessing pipeline to transform the raw Atari game observations into a format suitable for reinforcement learning algorithms. This preprocessing is crucial for stabilizing training and improving sample efficiency.

### Neural Network Architectures

Atari implementations use CNN-based architectures based on the "Nature DQN" design to process image observations.

#### Nature CNN Architecture

### Algorithm Implementations for Atari

CleanRL provides several algorithm implementations specifically optimized for Atari:

#### DQN (Deep Q-Network)

The `dqn_atari.py` script implements the standard DQN with a large replay buffer and epsilon-greedy exploration.

  - Replay Buffer : Uses optimize_memory_usage=True to store observations efficiently.

  - Exploration : Linear annealing from start_e (1.0) to end_e (0.01) over the exploration_fraction of total timesteps.

  - Training : Samples batches of size 32 every 4 environment steps.

Sources: cleanrl/dqn_atari.py68-79 cleanrl/dqn_atari.py174-181

#### PPO (Proximal Policy Optimization)

The `ppo_atari.py` script implements PPO with parallel environment sampling.

  - Vectorization : Uses SyncVectorEnv to run 8 parallel environments by default.

  - Normalization : Pixel values are divided by 255.0 inside the forward pass.

  - GAE : Uses Generalized Advantage Estimation with gae_lambda=0.95 .

Sources: cleanrl/ppo_atari.py51-60 cleanrl/ppo_atari.py134-143

### Advanced Implementations

#### PPO with LSTM

The `ppo_atari_lstm.py` implementation handles partial observability by replacing the frame stack with a recurrent LSTM layer.

  - FrameStack : Set to 1 in make_env .

  - LSTM Layer : A nn.LSTM(512, 128) layer processes the CNN features.

  - State Management : The LSTM hidden and cell states are tracked per environment and reset when an episode ends ( 1.0 - d ).

Sources: cleanrl/ppo_atari_lstm.py105 cleanrl/ppo_atari_lstm.py131-158

#### PPO with Multi-GPU Support

`ppo_atari_multigpu.py` uses PyTorch's distributed backend for high-throughput training.

  - Distributed Setup : Initializes process groups via dist.init_process_group .

  - Gradient Sync : Uses DistributedDataParallel (DDP) to wrap the agent.

  - Batching : Calculates local_batch_size based on the rank's local environments.

Sources: cleanrl/ppo_atari_multigpu.py175-183 cleanrl/ppo_atari_multigpu.py218

### ROM Licensing and Installation

Running Atari games requires the Arcade Learning Environment (ALE) and the game ROMs. CleanRL uses `AutoROM` to handle ROM installation.

  - Requirements : The requirements-atari.txt includes ale-py , autorom , and shimmy .

  - License : Users must accept the Atari ROM license. This is typically done via AutoROM --accept-rom-license or by installing autorom-accept-rom-license .

Sources: requirements/requirements-atari.txt6-12 requirements/requirements-atari.txt229-230

### Memory Efficiency and Performance

For Atari environments, memory optimization is particularly important due to large observation spaces (84x84 grayscale images).

  - Replay Buffer Optimization : In dqn_atari.py , the buffer is initialized with optimize_memory_usage=True . This avoids storing redundant frames in the FrameStack .

  - Pixel Normalization : To save memory, observations are stored as uint8 (0-255) and converted to float32 and normalized (divided by 255.0) only when passed to the GPU/Network.

Sources: cleanrl/dqn_atari.py179 cleanrl/dqn_atari.py125 cleanrl/ppo_atari.py138
