CleanRL provides high-performance JAX implementations for several core reinforcement learning algorithms. These implementations typically offer a 2-4x speedup over their PyTorch counterparts by leveraging XLA compilation and functional programming patterns.

### Architecture Overview

The JAX implementations follow a functional paradigm, separating state from logic. Unlike the PyTorch versions where models hold their own parameters, CleanRL's JAX scripts use a centralized `TrainState` to manage parameters, target parameters, and optimizer states.

#### Key Components

  - Flax nn.Module : Defines the neural network architecture using the @nn.compact pattern cleanrl/dqn_jax.py 89-99 .

  - Optax Optimizers : Used for gradient transformations and updates cleanrl/dqn_jax.py 151 .

  - TrainState Management : A container that holds the model parameters, optimizer state, and specifically for RL, target_params cleanrl/dqn_jax.py 102-103 .

  - Functional Updates : Core logic is encapsulated in jax.jit decorated functions that take the current state and a batch of data, returning a new state cleanrl/dqn_jax.py 166-179 .

### DQN and C51 Implementations

DQN and its distributional variant, C51, are implemented for both classic control (MLP-based) and Atari (CNN-based) environments.

#### DQN (Deep Q-Network)

The JAX implementation of DQN uses a `QNetwork` class cleanrl/dqn_jax.py89-99. The update step calculates the TD target using `q_state.target_params` and updates the online network via `jax.value_and_grad` cleanrl/dqn_jax.py167-178.

#### C51 (Categorical DQN)

C51 extends the DQN architecture to output a probability mass function (PMF) over a discrete set of "atoms" representing the return distribution cleanrl/c51_jax.py93-106.

  - Atoms : Initialized as a linear space between v_min and v_max cleanrl/c51_jax.py 160 .

  - Projection Step : The target distribution is projected back onto the support of the atoms using a specialized binning logic cleanrl/c51_jax.py 182-204 .

Sources: cleanrl/dqn_jax.py89-99, cleanrl/c51_jax.py93-106, cleanrl/c51_jax.py176-204.

### Continuous Control: DDPG and TD3

Continuous control algorithms in JAX follow a multi-state pattern where the Actor and Critic maintain separate `TrainState` objects.

#### DDPG (Deep Deterministic Policy Gradient)

DDPG maintains an `Actor` cleanrl/ddpg_continuous_action_jax.py92-106 and a `QNetwork` (Critic) cleanrl/ddpg_continuous_action_jax.py80-89.

  - Update Logic : The critic is updated to minimize MSE loss against the Bellman target cleanrl/ddpg_continuous_action_jax.py 179-199 , while the actor is updated to maximize the critic's output cleanrl/ddpg_continuous_action_jax.py 201-213 .

#### TD3 (Twin Delayed DDPG)

TD3 improves DDPG by adding clipped double Q-learning and target policy smoothing.

  - Clipped Double-Q : Uses two critic states ( qf1_state , qf2_state ) and takes the minimum of their target values to prevent overestimation cleanrl/td3_continuous_action_jax.py 217-220 .

  - Target Policy Smoothing : Adds noise to the actions sampled from the target actor network cleanrl/td3_continuous_action_jax.py 203-210 .

Sources: cleanrl/ddpg_continuous_action_jax.py80-106, cleanrl/td3_continuous_action_jax.py161-184, cleanrl/td3_continuous_action_jax.py189-231.

### Performance Considerations

#### XLA Memory Management

CleanRL JAX scripts often set the `XLA_PYTHON_CLIENT_MEM_FRACTION` environment variable (typically to `0.7`) to prevent JAX from pre-allocating all available GPU memory, which allows sidecar processes like `RecordVideo` or `SummaryWriter` to function without OOM errors cleanrl/dqn_atari_jax.py8.

#### JIT Compilation

The core update functions (e.g., `update`, `update_critic`, `update_actor`) are wrapped in `@jax.jit` cleanrl/dqn_jax.py166. This compiles the Python logic into highly optimized XLA kernels. Note that the first call to these functions will be slow due to compilation, but subsequent calls will be extremely fast.

Sources: cleanrl/dqn_atari_jax.py7-8, cleanrl/dqn_jax.py166, cleanrl/ddpg_continuous_action_jax.py178.
