## 一、六处修复（按严重度排序）

### F1【归属错误·最严重】六组件 H=(E,T,C,S,L,V) 张冠李戴
- 原文说法：六组件框架出自 "Agent Harness Engineering: A Survey"（arXiv 2026）
- **事实**：六组件 H=(E,T,C,S,L,V) 出自 **Meng, Qianyu et al. 2026.04**, "Agent Harness for Large Language Model Agents: A Survey", **preprints 202604.0428 (v3)**, DOI 10.20944/preprints202604.0428.v3, GitHub: Gloriaameng/Awesome-Agent-Harness（110+ 篇文献 × 23 系统的 Harness Completeness Matrix）
- 而 "Agent Harness Engineering: A Survey" 是 **Li, Junjie et al. 2026**（OpenReview），提出的是**七层 ETCLOVG**（Execution, Tooling, Context, Lifecycle, Observability, Verification, Governance）——Observability 和 Governance 在此独立成层
- 交叉验证：arXiv:2606.20683 (Guo et al.) 表 1 明确区分 "Meng et al. [55] six-component tuple / Li et al. [106] seven-layer ETCLOVG"；arXiv:2605.12239、arXiv:2606.21856 均按六组件引用 Meng et al.
- **六组件内容核实**（GitHub README，与拆解文本逐项对照）：E=execution loop（observe-think-act/终止/错误恢复）✅、T=tool registry（typed catalog/routing/schema 校验）✅、C=context manager（窗口管理/压缩/检索）✅、S=state store（跨会话持久化/崩溃恢复）✅、L=lifecycle hooks（auth/logging/policy enforcement）✅、V=evaluation interface（轨迹/中间态/成功信号）✅ ——**内容基本无误，只是归属错了论文**
- ⚠️ 拆解文本中 L 的具体钩子名（prepare_context/authorize_tool_call/process_tool_result/on_event）未在 Meng et al. README 中出现，可能混入了 harness-sdk/Pi 的实现细节，待查正文

### F2【数字错误】临床信息提取综述"129 篇"→ 实为 85 篇
- "Harnessing Large Language Models for Clinical Information Extraction: A Systematic Literature Review"（**ACM Transactions on Computing for Healthcare**, 2025-10-13, DOI 10.1145/3744660）系统检索 + 筛选后纳入 **85 篇**（Entity Extraction 独立任务 49 篇为最大子类）
- 拆解文本把交通综述的 129 写进了临床综述——两篇都被写成"129 篇"是复制污染的证据
- 混淆源候选：arXiv:2505.22280（NLP for EBM scoping review）恰好也是 129 篇，但主题是循证医学非临床信息提取

### F3【会议年份错误】Hybrid LLM "ICLR 2025" → **ICLR 2024**
- arXiv:2404.14618（Ding, Mallick, Wang, Sim, Mukherjee, Rühle, Lakshmanan, Awadallah）
- 三源确认 ICLR 2024（Vienna, 2024-05）：proceedings.iclr.cc、mlanthology.org/iclr/2024、Microsoft Research 官方页
- 内容核实 ✅：DeBERTa-v3-large 路由器 + BARTscore 质量度量，MixInstruct 数据集，40% 少调大模型无质量损失

### F4【引用体例错误】arXiv:2605.18747 不是"某综述的 Harness 章节"
- 该 ID 是独立 survey：**"Code as Agent Harness ♦ Toward Executable, Verifiable, and Stateful Agent Systems"**（Ning, Xuying et al. 42 作者, 2026-05-18, cs.CL）
- 主标题是 Code as Agent Harness，"Toward Executable..." 是副标题；GitHub: YennNing/Awesome-Code-as-Agent-Harness-Papers
- 三层结构：Harness Interface（code for reasoning/acting/environment modeling）→ Harness Mechanisms（planning/memory/tool use/control）→ Scaling the Harness（multi-agent 共享代码工件）

### F5【数字存疑】"TerminalBench +26% / 数学 +4.7pp"
- Meng et al. 摘要原文只说 "order-of-magnitude reliability gains through harness redesign alone"（对应 10× ✅）
- +26% / +4.7pp 两个具体数字在摘要级来源未出现，需查论文正文；注意 AHE 论文（arXiv:2604.25850）在 Terminal-Bench 2 上的结果是 69.7%→77.0%（**+7.3pp**），两者不可混用
- 处理：正文核实前，这两个数字按"未证实"标注

### F6【标题不完整】Edd Mann 博客
- 正确标题：**"Around the Loop: Building a Coding Agent Harness in Python"**（eddmann.com, 2026-04-27）
- 内容核实 ✅：七环结构（providers/tools/sessions/context/prompts/extensions/delivery）"loop 之外皆是 harness"；自举开发（用 agent 造 agent）
