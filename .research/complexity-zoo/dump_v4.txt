###MA | title: Merlin-Arthur | id: ma | url: https://complexityzoo.net/Complexity_Zoo:M#ma
The class of decision problems solvable by a <i>Merlin-Arthur protocol</i>, which goes as follows. Merlin, who has unbounded computational resources, sends Arthur a polynomial-size purported proof that the answer to the problem is "yes." Arthur must verify the proof in [[Complexity Zoo:B#bpp|BPP]] (i.e. probabilistic polynomial-time), so that <ol> <li>If the answer is "yes," then there exists a proof such that Arthur accepts with probability at least 2/3.</li> <li>If the answer is "no," then for all proofs Arthur accepts with probability at most 1/3.</li> </ol> Defined in [[zooref#bab85|[Bab85]]]. An alternative definition requires that if the answer is "yes," then there exists a proof such  ……[中略]……  that MA/1 cannot be solved on more than a <math>1/2 + 1/{n^k}</math> fraction of inputs having length <math>n</math> by any circuit of size <math>n^k</math>. Finally, it was shown that MA does not have ''arithmetic'' circuits of size <math>n^k</math>. ''See also'': [[#mae|MA<sub>E</sub>]], [[#maexp|MA<sub>EXP</sub>]], [[Complexity Zoo:O#oma|OMA]].

###MAC^0 | title: Majority of AC^0 | id: mac0 | url: https://complexityzoo.net/Complexity_Zoo:M#mac0
Same as [[Complexity Zoo:A#ac0|AC<sup>0</sup>]], except now we're allowed a single unbounded-fanin majority gate at the root. Defined in [[zooref#jks02|[JKS02]]]. MAC<sup>0</sup> is strictly contained in [[Complexity Zoo:T#tc0|TC<sup>0</sup>]] [[zooref#abf94|[ABF+94]]].

###MA^cc | title: Communication Complexity MA | id: macc | url: https://complexityzoo.net/Complexity_Zoo:M#macc
Here, Alice and Bob collectively constitute "Arthur", and the cost of an MA<sup>cc</sup> communication protocol is defined as the bit length of Merlin's message plus the communication cost of the ensuing randomized protocol between Alice and Bob. (Not charging for the length of Merlin's message would enable every function to be computed with constant cost in this model.) Does not contain [[Complexity Zoo:C#conpcc|coNP<sup>cc</sup>]] (first shown by [[zooref#kla03|[Kla03]]]). It is open to prove that there exists an explicit two-party function whose MA<sup>cc</sup>-type communication complexity is &omega;(n<sup>1/2</sup>).

###MA_E | title: Exponential-Time MA With Linear Exponent | id: mae | url: https://complexityzoo.net/Complexity_Zoo:M#mae
Same as [[#ma|MA]], except now Arthur is [[Complexity Zoo:E#e|E]] instead of polynomial-time. If MA<sub>E</sub> = [[Complexity Zoo:N#nee|NEE]] then [[#ma|MA]] = [[Complexity Zoo:N#nexp|NEXP]] &#8745; [[Complexity Zoo:C#conexp|coNEXP]] [[zooref#ikw01|[IKW01]]].

###MA_EXP | title: Exponential-Time MA | id: maexp | url: https://complexityzoo.net/Complexity_Zoo:M#maexp
Same as [[#ma|MA]], except now Arthur is [[Complexity Zoo:E#exp|EXP]] instead of polynomial-time, and the message from Merlin can be exponentially long. There is a problem in MA<sub>EXP</sub> that does not have polynomial-size circuits [[zooref#bft98|[BFT98]]]. On the other hand, there is an oracle relative to which every problem in MA<sub>EXP</sub> does have polynomial-size circuits. [[zooref#mvw99|[MVW99]]] considered the best circuit lower bound obtainable for a problem in MA<sub>EXP</sub>, using current techniques. They found that this bound is <i>half-exponential</i>: i.e. a function f such that f(f(n))=2<sup>n</sup>. Such functions exist, but are not expressible using standard asymptotic notation.

###mAL | title: Monotone AL | id: mal | url: https://complexityzoo.net/Complexity_Zoo:M#mal
Defined in [[zooref#gs90|[GS90]]]. Equals [[#mp|mP]] by definition.

###MA_POLYLOG | title: {{zcls|m|ma}} With Polylog Verifier | id: mapolylog | url: https://complexityzoo.net/Complexity_Zoo:M#mapolylog
Identical to {{zcls|m|ma}} except for that Arthur (the verifier) has random access to the proof string given by Merlin, and is limited to running times of order <math>O(\textrm{poly}(\log n))</math>. This class was used by {{zcite|SM03}} to show that if {{zcls|e|exp}} has circuits of polynomial size, then {{zcls|e|exp}} = [[#ma|MA]].

###MA' | title: Sparse MA | id: maprime | url: https://complexityzoo.net/Complexity_Zoo:M#maprime
The subclass of [[#ma|MA]] such that for each input size n, there is a sparse set S<sub>n</sub> that Merlin's proof string always belongs to (no matter what the input is). Defined in [[zooref#kst93|[KST93]]], where it is also observed that if [[Complexity_Garden#graph_isomorphism|graph isomorphism]] is in [[Complexity Zoo:P#ppoly|P/poly]], then the complement of [[Complexity_Garden#graph_isomorphism|graph isomorphism]] is in MA'.

###MaxNP | title: Maximization NP | id: maxnp | url: https://complexityzoo.net/Complexity_Zoo:M#maxnp
Has the same relation to [[Complexity Zoo:N#np|NP]] as [[#maxsnp|MaxSNP]] does to [[Complexity Zoo:S#snp|SNP]]. Contains [[#maxpb|MaxPB]]. The closure of MaxNP under [[Complexity Zoo:P#ptas|PTAS]] reduction is [[Complexity Zoo:A#apx|APX]] [[zooref#kms99|[KMS+99]]], [[zooref#ct94|[CT94]]].

###MaxPB | title: MaxNP Polynomially Bounded | id: maxpb | url: https://complexityzoo.net/Complexity_Zoo:M#maxpb
The subclass of [[#maxnp|MaxNP]] problems for which the cost function is guaranteed always to be bounded by a polynomial. [[#minpb|MinPB]] can be defined similarly. Defined in [[zooref#kt94|[KT94]]]. The closure of MaxPB under [[Complexity Zoo:P#ptas|PTAS]] reductions equals [[Complexity Zoo:N#npopb|NPOPB]] [[zooref#cks99|[CKS+99]]].

###MaxSNP | title: Maximization SNP | id: maxsnp | url: https://complexityzoo.net/Complexity_Zoo:M#maxsnp
The class of optimization problems reducible by an "L-reduction" to a problem in [[#maxsnp0|MaxSNP<sub>0</sub>]]. (<i>Note:</i> 'L' stands for linear -- this is <i>not</i> the same as an [[Complexity Zoo:L#l|L]] reduction! For more details see [[zooref#py88|[PY88]]].) Defined in [[zooref#py88|[PY88]]], where the following was also shown: <ul> <li>Max3SAT is MaxSNP-complete. (Max3SAT is the problem of finding an assignment that maximizes the number of satisfied clauses in a CNF formula with at most 3 literals per clause.)</li> <li>Any problem in MaxSNP can be approximated to within a fixed ratio.</li> </ul> The closure of MaxSNP under [[Complexity Zoo:P#ptas|PTAS]] reduction is [[Complexity Zoo:A#apx|APX]] [[zooref#kms99|[KMS+99]]], [[zooref#ct94|[CT94]]].

###MaxSNP_0 | title: Generating Class of MaxSNP | id: maxsnp0 | url: https://complexityzoo.net/Complexity_Zoo:M#maxsnp0
The class of function problems expressible as "find a relation such that the set of k-tuples for which a given [[Complexity Zoo:S#snp|SNP]] predicate holds has maximum cardinality." For example (see [[zooref#pap94|[Pap94]]]), the Max-Cut problem can be expressed as follows: <ul> Given a graph G, find a subset S of vertices that maximizes the number of pairs (u,v) of vertices such that u is in S, and v is not in S, and G has an edge from u to v. </ul> Defined in [[zooref#py88|[PY88]]].

###mcoNL | title: Complement of mNL | id: mconl | url: https://complexityzoo.net/Complexity_Zoo:M#mconl
Defined in [[zooref#gs90|[GS90]]], where it was also shown that mcoNL does not equal [[#mnl|mNL]]. See also: [[#ml|mL]].

###MinPB | title: MinNP Polynomially Bounded | id: minpb | url: https://complexityzoo.net/Complexity_Zoo:M#minpb
Same as [[#maxpb|MaxPB]] but for minimization instead of maximization problems.

###MIP | title: Multi-Prover Interactive Proof | id: mip | url: https://complexityzoo.net/Complexity_Zoo:M#mip
Same as [[Complexity Zoo:I#ip|IP]], except that now the verifier can exchange messages with many provers, not just one. The provers cannot communicate with each other during the execution of the protocol, so the verifier can "cross-check" their assertions (as with suspects in separate interrogation rooms). Defined in [[zooref#bgk88|[BGK+88]]]. Let MIP[k] be the class of decision problems for which a "yes" answer can be verified with k provers. Then for all k&gt;2, MIP[k] = MIP[2] = MIP [[zooref#bgk88|[BGK+88]]]. MIP equals [[Complexity Zoo:N#nexp|NEXP]] [[zooref#bfl91|[BFL91]]]; this is a famous non-relativizing result. In fact, there is an MIP for [[Complexity Zoo:N#ne|NE]] where the verifier is quasilinear time [[zooref#cm23|[CM23]]].

###MIP_EXP | title: Exponential-Time Multi-Prover Interactive Proof | id: mipexp | url: https://complexityzoo.net/Complexity_Zoo:M#mipexp
The exponential-time analogue of [[#mip|MIP]]. In the unrelativized world, equals [[Complexity Zoo:N#neexp|NEEXP]]. There exists an oracle relative to which MIP<sub>EXP</sub> equals the intersection of [[Complexity Zoo:P#ppoly|P/poly]], [[Complexity Zoo:P#pnp|P<sup>NP</sup>]], and [[Complexity Zoo:Symbols#parityp|&#8853;P]] [[zooref#bft98|[BFT98]]].

###MIP^ns | title: MIP with Non-Signaling Provers | id: mipns | url: https://complexityzoo.net/Complexity_Zoo:M#mipns
Same as [[#mip|MIP]], except that the provers can have non-signaling strategies. MIP<sup>ns</sup> with two provers is equal to [[Complexity Zoo:P#pspace|PSPACE]] [[zooref#ito10|[Ito10]]]. MIP<sup>ns</sup> with polylogarithmically many provers is equal to [[Complexity Zoo:E#exp|EXP]] [[zooref#krr13|[KRR13]]].

###MIP* | title: MIP With Quantum Provers | id: mipstar | url: https://complexityzoo.net/Complexity_Zoo:M#mipstar
Same as [[#mip|MIP]], except that the provers can share arbitrarily many entangled qubits. The verifier is classical, as are all messages between the provers and verifier. Defined in [[zooref#cht04|[CHT+04]]], where evidence was given suggesting that MIP* does not "obviously" equal [[Complexity Zoo:N#nexp|NEXP]]. MIP* contains [[Complexity Zoo:N#nexp|NEXP]] [[zooref#iv12|[IV12]]]. By contrast, [[Complexity Zoo:M#mip|MIP]], the corresponding class without entanglement, equals [[Complexity Zoo:N#nexp|NEXP]] (and even MIP[2,1] with two provers and one round equals NEXP). Even MIP*[4,poly] and MIP[5,1] contain NEXP [[zooref#iv12|[IV12]]]. MIP*[2,1] contains [[Complexity Zoo:X#xormipstar21|XOR-MIP*[2,1]]]. In 2012 it was shown that [[Complexity Zoo:Q#qmip|QMIP]] = MIP* [[zooref#ruv12|[RUV12]]] In 2020 it was shown that MIP* = [[Complexity Zoo:R#re|RE]] [[zooref#jnvwy20|[JNVWY20]]].

###(M_k)P | title: Acceptance Mechanism by Monoid M_k | id: mkp | url: https://complexityzoo.net/Complexity_Zoo:M#mkp
A <i>monoid</i> is a set with an associative operation and an identity element (so it's like a group, except that it need not have inverses). Then (M<sub>k</sub>)P is the class of decision problems solvable by an [[Complexity Zoo:N#np|NP]] machine with the following acceptance mechanism. The i<sup>th</sup> computation path (under some lexicographic ordering) outputs an element m<sub>i</sub> of M<sub>k</sub>. Then the machine accepts if and only if m<sub>1</sub>m<sub>2</sub>...m<sub>s</sub> is the identity (where s is the number of paths). Defined by Hertrampf [[zooref#her97|[Her97]]], who also showed the following (in the special case M is a group): <ul> <li>If G is any nonsolvable group (for example S<sub>5</sub>, the symmetric group on 5 elements), then (G)P = [[Complexity Zoo:P#pspace|PSPACE]].</li> <li>(Z<sub>k</sub>)P = [[#comodkp|coMod<sub>k</sub>P]], where Z<sub>k</sub> is the cyclic group on k elements.</li> <li>If |G|=k, then (G)P contains [[#comodkp|coMod<sub>k</sub>P]].</li> </ul>

###mL | title: Monotone L | id: ml | url: https://complexityzoo.net/Complexity_Zoo:M#ml
The class of decision problems solvable by a family of monotone log-width polynomial-size leveled circuits. (A <i>leveled</i> circuit is one where gates on each level can depend only on the level immediately below it.) Defined in [[zooref#gs90|[GS90]]], who raise as an open problem to define a uniform version of mL. Strictly contains [[#mnc1|mNC<sup>1</sup>]] [[zooref#gs91|[GS91]]]. Contained in (nonuniform versions of) [[#mnl|mNL]] and [[#mconl|mcoNL]].

###MM | title: Problems reducible to matrix multiplication | id: mm | url: https://complexityzoo.net/Complexity_Zoo:M#mm
The set of all problems reducible to matrix multiplication. That is, the set of problems <math>P</math> that can be reduced to the multiplication of two square matrices can be reduced to <math>P</math> in linear time. Currently, the best known algorithm for multiplying two <math>n\times n</math> matrices is the [http://en.wikipedia.org/wiki/Coppersmith%E2%80%93Winograd_algorithm Coppersmith–Winograd_algorithm], which has a time complexity of <math>O(n^{2.376})</math> {{zcite|CW90}}. Note that for the general problem, a lower bound of <math>\Omega(n^2)</math> is trivial from the number of elements being considered.

###MMSNP | title: Monadic Monotone SNP | id: mmsnp | url: https://complexityzoo.net/Complexity_Zoo:M#mmsnp
Defined in [[zooref#fv93|[FV93]]] as a subclass of [[Complexity Zoo:S#snp|SNP]]. There are three syntactic restrictions defining the subclass MMSNP, based on the form of the SNP formula defining the language: # The second order existentially quantified variables, known as the proof relations, are restricted to be monadic. (Monadic relations can be treated as sets.) # Any relations in the formula other than the proof relations must occur only negated (the formula is monotone). # No inequality relations can occur in the formula. Every constraint satisfaction problem with a fixed target structure is expressible in MMSNP, and there is a polynomial time Turing reduction from every MMSNP query to finitely many constraint satisfaction problems. MMSNP therefore seems to capture the class of constraint satisfaction problems with fixed templates, [[Complexity Zoo:C#csp|CSP]].

###mNC^1 | title: Monotone NC^1 | id: mnc1 | url: https://complexityzoo.net/Complexity_Zoo:M#mnc1
The class of decision problems solvable by a family of monotone [[Complexity Zoo:N#nc1|NC<sup>1</sup>]] circuits (i.e. AND and OR gates only). A uniformity condition could also be imposed. Defined in [[zooref#gs90|[GS90]]]. Strictly contained in [[#mnl|mNL]] [[zooref#kw88|[KW88]]], and indeed in [[#ml|mL]] [[zooref#gs91|[GS91]]]. Strictly contains [[#mtc0|mTC<sup>0</sup>]] [[zooref#yao89|[Yao89]]].

###mNL | title: Monotone NL | id: mnl | url: https://complexityzoo.net/Complexity_Zoo:M#mnl
See [[#mp|mP]] for the definition of a monotone nondeterministic Turing machine, due to [[zooref#gs90|[GS90]]]. mNL is the class of decision problems solvable by a monotone nondeterministic log-space Turing machine. mNL does not equal [[#mconl|mcoNL]] [[zooref#gs90|[GS90]]], in contrast to the case for [[Complexity Zoo:N#nl|NL]] and [[Complexity Zoo:C#conl|coNL]]. Also, mNL strictly contains [[#mnc1|mNC<sup>1</sup>]] [[zooref#kw88|[KW88]]]. See also: [[#ml|mL]].

###mNP | title: Monotone NP | id: mnp | url: https://complexityzoo.net/Complexity_Zoo:M#mnp
The class of decision problems for which a 'yes' answer can be verified in [[#mp|mP]] (that is, monotone polynomial-time). The monotonicity requirement applies only to the input bits, not to the bits that are guessed nondeterministically. So, in the corresponding circuit, one can have NOT gates so long as they depend only on the nondeterministic guess bits. Defined in [[zooref#gs90|[GS90]]], where it was also shown that mNP is 'trivial': that is, it contains exactly the monotone problems in [[Complexity Zoo:N#np|NP]]. Strictly contains [[#mp|mP]] [[zooref#raz85|[Raz85]]].

###Mod_kL | title: Mod-k L | id: modkl | url: https://complexityzoo.net/Complexity_Zoo:M#modkl
Has the same relation to [[Complexity Zoo:L#l|L]] as [[#modkp|Mod<sub>k</sub>P]] does to [[Complexity Zoo:P#p|P]]. For any prime k, Mod<sub>k</sub>L contains [[Complexity Zoo:S#sl|SL]] [[zooref#kw93|[KW93]]]. For any prime k, Mod<sub>k</sub>L<sup>ModkL</sup> = Mod<sub>k</sub>L [[zooref#hrv00|[HRV00]]]. For any k>1, contains [[Complexity Zoo:L#logfew|LogFew]] [[zooref#bdh92|[BDH+92]]].

###Mod_kP | title: Mod-k Polynomial-Time | id: modkp | url: https://complexityzoo.net/Complexity_Zoo:M#modkp
For any k&gt;1: The class of decision problems solvable by an [[Complexity Zoo:N#np|NP]] machine such that the number of accepting paths is divisible by k, if and only if the answer is "no." Mod<sub>2</sub>P is more commonly known as [[Complexity Zoo:Symbols#parityp|&#8853;P]] "parity-P." For every k, Mod<sub>k</sub>P contains [[Complexity_Garden#graph_isomorphism|graph isomorphism]] [[zooref#ak02|[AK02]]]. Defined in [[zooref#ch89|[CH89]]], [[zooref#her90|[Her90]]]. [[zooref#her90|[Her90]]] and [[zooref#bg92|[BG92]]] showed that Mod<sub>k</sub>P is the set of unions of languages in Mod<sub>p</sub>P for each prime p that divides k. In particular, if p is prime, then Mod<sub>p</sub>P = Mod<su ……[中略]…… ow for itself, for p prime. On the other hand, if k is not a prime power, then there exists an oracle relative to which Mod<sub>k</sub>P is not closed under intersection or complement [[zooref#bbr94|[BBR94]]]. For prime p, there exists an oracle relative to which Mod<sub>p</sub>P does not contain [[Complexity Zoo:E#eqp|EQP]] [[zooref#gv02|[GV02]]].

###ModL | title: Mod{{zcls|l|l}} | id: modl | url: https://complexityzoo.net/Complexity_Zoo:M#modl
A language <math>L\in\mathsf{ModL}</math> if there are functions <math>f\in\mathsf{GapL}</math> and <math>g\in\mathsf{FL}</math> such that for all strings <math>x</math>: * There exists a prime <math>p</math> and a natural number <math>\alpha</math> such that <math>g(x)=0^{p^{\alpha}}</math>. * <math>x\in L</math> if and only if <math>f(x)\equiv0(\left|g(x)\right|)</math>. Thus, for any prime <math>p</math> and natural number <math>\alpha</math>, <math>\mathsf{Mod}_{p^{\alpha}}\mathsf{L}\subseteq\mathsf{ModL}</math>. Moreover, {{zcls|f|fl}}<sup>ModL</sup> = {{zcls|f|fl}}<sup>{{zcls|g|gapl|GapL}}</sup> {{zcite|AV04}}. Defined in {{zcite|AV04}}.

###ModP | title: Mod_kP With Arbitrary k | id: modp | url: https://complexityzoo.net/Complexity_Zoo:M#modp
The class of decision problems solvable by a [[#modkp|Mod<sub>k</sub>P]] machine where k can vary depending on the input. The only requirement is that 0<sup>k</sup> be computable in polynomial time. Defined in [[zooref#kt96|[KT96]]], where it was also shown that ModP is contained in [[Complexity Zoo:A#ampmp|AmpMP]].

###ModPH | title: Modular Counting Hierarchy | id: modph | url: https://complexityzoo.net/Complexity_Zoo:M#modph
The closure of [[#p|P]] under the ∃, ∀, and Mod<sub>''k''</sub> operators. Equivalently, the smallest class ''C'' such that NP<sup>''C''</sup>, coNP<sup>''C''</sup>, and Mod<sub>''k''</sub>P<sup>''C''</sup> are included in ''C'' for each ''k''. Introduced in [[zooref#gkr95|[GKR+95]]]. Contains [[Complexity Zoo:P#ph|PH]] and [[#modkp|Mod<sub>''k''</sub>P]] for each ''k''. Contained in, and low for, [[Complexity Zoo:A#ampmp|AmpMP]] and [[#mp2|MP]]. For a fixed ''m'', the restriction of the class that only allows Mod<sub>''k''</sub> for ''k'' = ''m'' is denoted ModPH<sub>''m''</sub> [[zooref#buss17|[Buss17]]]. Toda’s theorem [[zooref#tod89|[Tod89]]] implies that for prime ''m'', ModPH<sub>''m''</sub> = BP·Mod<sub>''m''</sub>P.

###ModZ_kL | title: Restricted Mod_kL | id: modzkl | url: https://complexityzoo.net/Complexity_Zoo:M#modzkl
The class of decision problems solvable by a nondeterministic logspace Turing machine, such that <ol> <li>If the answer is "yes," then the number of accepting paths is not congruent to 0 mod k.</li> <li>If the answer is "no," then there are no accepting paths.</li> </ol> Defined in [[zooref#bdh92|[BDH+92]]], where it was also shown that ModZ<sub>k</sub>L contains [[Complexity Zoo:L#logfewnl|LogFewNL]] for all k>1. Contained in [[#modkl|Mod<sub>k</sub>L]] and in [[Complexity Zoo:N#nl|NL]].

###mP | title: Monotone P | id: mp | url: https://complexityzoo.net/Complexity_Zoo:M#mp
The definition of this class, due to [[zooref#gs90|[GS90]]], is not obvious. First, a <i>monotone nondeterministic Turing machine</i> is one such that, whenever it can make a transition with a 0 on its input tape, it can also make that same transition with a 1 on its input tape. (This restriction does not apply to the work tape.) A <i>monotone alternating Turing machine</i> is subject to the restriction that it can only reference an input bit x by, "there exists a z at most x," or "for all z at least x." Then applying the result of [[zooref#cks81|[CKS81]]] that [[Complexity Zoo:P#p|P]] = [[Complexity Zoo:A#al|AL]], mP is defined to be [[#mal|mAL]]: the class of decision problems solvable by  ……[中略]…… ng both a monotone problem and in [[Complexity Zoo:P#p|P]], requires monotone circuits of superpolynomial size [[zooref#raz85b|[Raz85b]]]. Letting MONO be the class of monotone problems, it follows that mP is strictly contained in MONO &#8745; [[Complexity Zoo:P#p|P]]. See also: [[#mnc1|mNC<sup>1</sup>]], [[#ml|mL]], [[#mnl|mNL]], [[#mconl|mcoNL]].

###MP | title: Middle-Bit P | id: mp2 | url: https://complexityzoo.net/Complexity_Zoo:M#mp2
The class of decision problems such that for some [[Complexity Zoo:Symbols#sharpp|#P]] function f, the answer on input x is 'yes' if and only if the middle bit of f(x) is 1. Defined in [[zooref#gkr95|[GKR+95]]]. Contains [[Complexity Zoo:A#ampmp|AmpMP]], and [[#modph|ModPH]], which is low for both AmpMP and MP. Contained in [[Complexity Zoo:P#psharpp1|P<sup>#P[1]</sup>]]. MP with [[#modp|ModP]] oracle equals MP with [[Complexity Zoo:Symbols#sharpp|#P]] oracle [[zooref#kt96|[KT96]]].

###MPC | title: Monotone Planar Circuits | id: mpc | url: https://complexityzoo.net/Complexity_Zoo:M#mpc
The class of decision problems solvable by a family of <i>monotone stratified planar circuits</i> (a uniformity condition may also be imposed). Such a circuit can contain only AND and OR gates of bounded fanin. It must be embeddable in the plane with no wires crossing. Furthermore, the input bits can only be accessed at the bottom level, where they are listed in order (x<sub>1</sub>,...,x<sub>n</sub>). Defined in [[zooref#dc89|[DC89]]]. [[zooref#blm99|[BLM+99]]] showed that we can assume without loss of generality that the circuit has width n and depth n<sup>3</sup>.

###mP/poly | title: Monotone P/poly | id: mppoly | url: https://complexityzoo.net/Complexity_Zoo:M#mppoly
The class of decision problems solvable by a nonuniform family of polynomial-size Boolean circuits with only AND and OR gates, no NOT gates. (Or rather, following the definitions of [[zooref#gs90|[GS90]]], the entire input can be negated as long as there are no other negations.) More straightforward to define than [[#mp|mP]].

###mTC^0 | title: Monotone TC^0 | id: mtc0 | url: https://complexityzoo.net/Complexity_Zoo:M#mtc0
The class of decision problems solvable by a family of monotone [[Complexity Zoo:T#tc0|TC<sup>0</sup>]] circuits (i.e. constant-depth, polynomial-size, AND, OR, and threshold gates, but no NOT gates). A uniformity condition could also be imposed. Defined in [[zooref#gs90|[GS90]]]. Strictly contained in [[#mnc1|mNC<sup>1</sup>]] [[zooref#yao89|[Yao89]]].

###NC^0 | title: Level 0 of NC | id: nc0 | url: https://complexityzoo.net/Complexity_Zoo:N#nc0
By definition, a decision problem in NC<sup>0</sup> can depend on only a constant number of bits of the input. Thus, NC<sup>0</sup> usually refers to <i>functions</i> computable by constant-depth, bounded-fanin circuits. There is a family of permutations computable by a uniform family of NC<sup>0</sup> circuits that is [[Complexity Zoo:P#p|P]]-hard to invert [[zooref#has88|[Has88]]]. Recently [[zooref#aik04|[AIK04]]] solved a longstanding open problem by showing that there exist pseudorandom generators and one-way functions in NC<sup>0</sup>, based on (for example) the hardness of [[Complexity_Garden#integer_factorization|factoring]]. Specifically, in these generators every bit of the output depends on only 4 input bits. Whether the dependence can be reduced to 3 bits under the same cryptographic assumptions is open, but [[zooref#aik04|[AIK04]]] have some partial results in this direction. It is known that the dependence cannot be reduced to 2 bits.

###NIPZK | title: Non-Interactive PZK | id: nipzk | url: https://complexityzoo.net/Complexity_Zoo:N#nipzk

###NIQSZK | title: Non-Interactive QSZK | id: niqszk | url: https://complexityzoo.net/Complexity_Zoo:N#niqszk

###NPC | title: NP-Complete | id: npc | url: https://complexityzoo.net/Complexity_Zoo:N#npc
The class of decision problems such that (1) they're in [[#np|NP]] and (2) every problem in [[#np|NP]] is reducible to them (under some notion of reduction). In other words, the hardest problems in [[#np|NP]]. Two notions of reduction from problem A to problem B are usually considered: <ol> <li><i>Karp</i> or <i>many-one</i> reductions. Here a polynomial-time algorithm is given as input an instance of problem A, and must produce as output an instance of problem B.</li> <li><i>Turing</i> reductions, in this context also called <i>Cook</i> reductions. Here the algorithm for problem B can make arbitrarily many calls to an oracle for problem A.</li> </ol> Some examples of NP-complete problems ar ……[中略]……  [[#np|NP]] [[zooref#bks95|[BKS95]]]. This means that, given k Boolean formulas F<sub>1</sub>,...,F<sub>k</sub>, if you can rule out even <i>one</i> of the 2<sup>k</sup> possibilities in polynomial time (e.g., "if F<sub>1</sub>,...,F<sub>k-1</sub> are all unsatisfiable then F<sub>k</sub> is satisfiable"), then [[Complexity Zoo:P#p|P]] = [[#np|NP]].

###NP_C | title: NP Over The Complex Numbers | id: npc2 | url: https://complexityzoo.net/Complexity_Zoo:N#npc2
An analog of [[#np|NP]] for Turing machines over a complex number field. Defined in [[zooref#bcs97|[BCS+97]]]. It is unknown whether [[Complexity Zoo:P#pc|P<sub>C</sub>]] = NP<sub>C</sub>, nor are implications known among this question, [[Complexity Zoo:P#pr2|P<sub>R</sub>]] versus [[#npr|NP<sub>R</sub>]], and [[Complexity Zoo:P#p|P]] versus [[#np|NP]]. However, [[zooref#ckk95|[CKK+95]]] show that if [[Complexity Zoo:P#ppoly|P/poly]] does not equal [[#nppoly|NP/poly]] then [[Complexity Zoo:P#pc|P<sub>C</sub>]] does not equal NP<sub>C</sub>. [[zooref#bcs97|[BCS+97]]] show the following striking result. For a positive integer n, let t(n) denote the minimum number of additions, subtractions, and multiplications needed to construct n, starting from 1. If for every sequence {n<sub>k</sub>} of positive integers, t(n<sub>k</sub> k!) grows faster than polylogarithmically in k, then [[Complexity Zoo:P#pc|P<sub>C</sub>]] does not equal NP<sub>C</sub>. See also [[Complexity Zoo:V#vnp|VNP<sub>k</sub>]].

###NP^cc | title: Communication Complexity NP | id: npcc | url: https://complexityzoo.net/Complexity_Zoo:N#npcc
The analogue of [[Complexity Zoo:P#pcc|P<sup>cc</sup>]] for nondeterministic communication complexity. Both communication bits and nondeterministic guess bits count toward the complexity. Does not equal [[Complexity Zoo:P#pcc|P<sup>cc</sup>]] or [[Complexity Zoo:C#conpcc|coNP<sup>cc</sup>]] because of the [[Complexity Garden#equality|EQUALITY]] problem. Also, does not contain [[Complexity Zoo:B#bppcc|BPP<sup>cc</sup>]] because of that problem. Is not contained in [[Complexity Zoo:B#bppcc|BPP<sup>cc</sup>]] (first shown by [[zooref#bfs86|[BFS86]]]). SET-INTERSECTION, in which Alice's and Bob's strings are identified with characteristic vectors of sets and yes-inputs are intersecting while no-inputs are disjoint, is the canonical [[Complexity Zoo:N#npcc|NP<sup>cc</sup>]]-complete problem. Sometimes SET-DISJOINTNESS also refers to this problem, but sometimes it refers to the complement of this problem. The complexity measure corresponding to NP<sup>cc</sup> is equivalent to the log of the number of rectangles needed to cover exactly the set of 1-entries of the communication matrix.

###NPI | title: NP-Intermediate | id: npi | url: https://complexityzoo.net/Complexity_Zoo:N#npi
Sometimes used to denote the set of decision problems in [[#np|NP]] that are neither NP-complete (that is, in [[#npc|NPC]]) nor in [[Complexity Zoo:P#p|P]]. Is thought to contain (for example) decision versions of factoring and [[Complexity_Garden#graph_isomorphism|graph isomorphism]]. Is nonempty if [[Complexity Zoo:P#p|P]] does not equal [[#np|NP]] [[zooref#lad75|[Lad75]]]. Indeed, under this assumption, it contains an infinite number of distinct polynomial-time equivalence classes.

###NP ∩ coNP | title: The intersection of NP and coNP | id: npiconp | url: https://complexityzoo.net/Complexity_Zoo:N#npiconp
The class of problems in both [[#np|NP]] and [[Complexity Zoo:C#conp|coNP]]. Contains [[Complexity_Garden#integer_factorization|factoring]] [[zooref#pra75|[Pra75]]]. Contains [[Complexity_Garden#graph_isomorphism|graph isomorphism]] under the assumption that some language in [[#ne|NE]] &#8745; [[Complexity Zoo:C#cone|coNE]] requires nondeterministic circuits of size 2<sup>&#937;(n)</sup> ([[zooref#mv99|[MV99]]], improving [[zooref#km99|[KM99]]]). In particular, if a problem in NP &#8745; coNP is NP-hard with Turing reduction, then NP = coNP. Is not believed to contain complete problems. A language in [[#nppoly|NP/poly &#8745; coNP/poly]] comes from two possibly different languages in [[#np|NP]] and [[Complexity Zoo:C#conp|coNP]] which become the same with good advice. There is an oracle relative to which [[#nppoly|NP/poly &#8745; coNP/poly]], indeed NP/1 &#8745; coNP/1, is not contained in (NP &#8745; coNP)/poly [[zooref#ffk93|[FFK+93]]]. Recently they improved this to NP/1 &#8745; coNP [[zooref#ff..|[FF..]]]. If [[#np|NP]] is contained in (NP &#8745; coNP)/poly, then [[Complexity Zoo:P#ph|PH]] collapses to [[Complexity Zoo:S#s2p|S<sub>2</sub>P]]<sup>[[#npiconp|NP &#8745; coNP]]</sup> [[zooref#cch01|[CCH+01]]].

###NP_^cc | title: NP^cc in NOF model, players | id: npkcc | url: https://complexityzoo.net/Complexity_Zoo:N#npkcc
Has the same relation to [[#npcc|NP<sup>cc</sup>]] and [[#np|NP]] as {{zcls|p|pkcc|P<sub><math>k</math></sub><sup>cc</sup>}} does to {{zcls|p|pcc|P<sup>cc</sup>}} and {{zcls|p|p}}. NP<sub><math>k</math></sub><sup>cc</sup> is not contained in {{zcls|b|bppkcc|BPP<sub><math>k</math></sub><sup>cc</sup>}} for <math>k\le(1-\delta)\cdot\log n</math> players, for any constant <math>\delta>0</math>. As a result, NP<sub><math>k</math></sub><sup>cc</sup> is not equal to {{zcls|r|rpkcc|RP<sub><math>k</math></sub><sup>cc</sup>}} under the same conditions {{zcite|DP08}}.

###NP/log | title: NP With Logarithmic Advice | id: nplog | url: https://complexityzoo.net/Complexity_Zoo:N#nplog
Same as [[#nppoly|NP/poly]], except that now the advice string is logarithmic-size. Shown in [[zooref#fk05|[FK05]]] that [[Complexity Zoo:E#exp|EXP]] &sube; NP/log if and only if [[Complexity Zoo:E#exp|EXP]] = [[Complexity Zoo:P#pparnp|P<sup>||NP</sup>]].

###NPMV | title: NP Multiple Value | id: npmv | url: https://complexityzoo.net/Complexity_Zoo:N#npmv
The class of all (possibly partial, possibly multivalued) functions computed by an [[#np|NP]] machine as follows: ignore the rejecting paths, and consider any output of an accepting path to be "one of the outputs." Contains [[#npsv|NPSV]] and [[#npmvt|NPMV<sub>t</sub>]]. Defined in [[zooref#bls84|[BLS84]]]. Contrast with [[Complexity Zoo:F#fnp|FNP]].

###NPMV-sel | title: NPMV Selective | id: npmvsel | url: https://complexityzoo.net/Complexity_Zoo:N#npmvsel
Has the same relation to [[#npmv|NPMV]] as [[Complexity Zoo:P#psel|P-Sel]] does to [[Complexity Zoo:P#p|P]]. Defined in [[zooref#hhn95|[HHN+95]]].

###NPMV_t | title: NPMV Total | id: npmvt | url: https://complexityzoo.net/Complexity_Zoo:N#npmvt
The class of all (possibly multivalued) [[#npmv|NPMV]] functions that are total (that is, defined for every input).

###NPMV_t-sel | title: NPMV_t Selective | id: npmvtsel | url: https://complexityzoo.net/Complexity_Zoo:N#npmvtsel
Has the same relation to [[#npmvt|NPMV<sub>t</sub>]] as [[Complexity Zoo:P#psel|P-Sel]] does to [[Complexity Zoo:P#p|P]]. Defined in [[zooref#hhn95|[HHN+95]]].

###NPO | title: NP Optimization | id: npo | url: https://complexityzoo.net/Complexity_Zoo:N#npo
The class of function problems of the form, "Find any n-bit string x that maximizes a cost function C(x), where C is computable in [[Complexity Zoo:F#fp|FP]] (i.e. polynomial-time)." Defined in [[zooref#acg99|[ACG+99]]]. Contains [[Complexity Zoo:A#apx|APX]] and [[#npopb|NPOPB]].

###NPOPB | title: NPO Polynomially Bounded | id: npopb | url: https://complexityzoo.net/Complexity_Zoo:N#npopb
The subclass of [[#npo|NPO]] problems for which the cost function is guaranteed always to be bounded by a polynomial in n (the input size). See [[zooref#acg99|[ACG+99]]]. NPOPB equals the closure of [[Complexity Zoo:M#maxpb|MaxPB]] under [[Complexity Zoo:P#ptas|PTAS]] reductions [[zooref#cks99|[CKS+99]]].

###NP/poly | title: Nonuniform NP | id: nppoly | url: https://complexityzoo.net/Complexity_Zoo:N#nppoly
Has the same relation to [[#np|NP]] as [[Complexity Zoo:P#ppoly|P/poly]] does to [[Complexity Zoo:P#p|P]]. Contains [[Complexity Zoo:A#am|AM]]. On the other hand, if NP/poly contains [[Complexity Zoo:C#conp|coNP]] then [[Complexity Zoo:P#ph|PH]] collapses to the third level. NP/poly-natural proofs cannot show that circuit families are outside [[Complexity Zoo:P#ppoly|P/poly]], under a pseudorandomness assumption [[zooref#rud97|[Rud97]]].

###(NP,P-samplable) | title: Average NP With Samplable Distributions | id: nppsamp | url: https://complexityzoo.net/Complexity_Zoo:N#nppsamp
See [[Complexity Zoo:A#avgp|AvgP]] for basic notions of average-case complexity. (NP,P-samplable) is the same as [[Complexity Zoo:D#distnp|DistNP]], except that the distribution &#956; only needs to be <i>samplable</i> in polynomial time. &#956;'s cumulative density function does not need to be computable in polynomial time. Any problem complete for [[Complexity Zoo:D#distnp|DistNP]] is also complete for (NP,P-samplable) [[zooref#il90|[IL90]]].

###NP_R | title: NP Over The Reals | id: npr | url: https://complexityzoo.net/Complexity_Zoo:N#npr
An analog of [[#np|NP]] for Turing machines over a real number field. Defined in [[zooref#bcs97|[BCS+97]]]. It is unknown whether [[Complexity Zoo:P#pr2|P<sub>R</sub>]] = NP<sub>R</sub>, nor are implications known among this question, [[Complexity Zoo:P#pc|P<sub>C</sub>]] versus [[#npc2|NP<sub>C</sub>]], and [[Complexity Zoo:P#p|P]] versus [[#np|NP]]. Also, in contrast to the case of [[#npc2|NP<sub>C</sub>]], it is an open problem to show that [[Complexity Zoo:P#ppoly|P/poly]] distinct from [[#nppoly|NP/poly]] implies [[Complexity Zoo:P#pr2|P<sub>R</sub>]] distinct from NP<sub>R</sub>. The difference is that in the real case, a comparison (or greater-than) operator is available, and it is not known how much power this yields in comparison to the complex case. See also [[Complexity Zoo:V#vnp|VNP<sub>k</sub>]].

###NPSPACE | title: Nondeterministic PSPACE | id: npspace | url: https://complexityzoo.net/Complexity_Zoo:N#npspace
Equals [[Complexity Zoo:P#pspace|PSPACE]] [[zooref#sav70|[Sav70]]]. On the other hand, this result does not relativize if we allow strings of unbounded length to be written to the oracle tape. In particular, there exists an oracle relative to which NPSPACE is not contained in [[Complexity Zoo:E#exp|EXP]] [[zooref#gtw91|[GTW+91]]].

###NPSV | title: NP Single Value | id: npsv | url: https://complexityzoo.net/Complexity_Zoo:N#npsv
The class of [[#npmv|NPMV]] functions that are single-valued (i.e., such that every accepting path outputs the same value). Defined in [[zooref#bls84|[BLS84]]]. Contains [[#npsvt|NPSV<sub>t</sub>]]. [[Complexity Zoo:P#p|P]] = [[#np|NP]] if and only if [[Complexity Zoo:F#fp|FP]] = NPSV.

###NPSV-sel | title: NPSV Selective | id: npsvsel | url: https://complexityzoo.net/Complexity_Zoo:N#npsvsel
Has the same relation to [[#npsv|NPSV]] as [[Complexity Zoo:P#psel|P-Sel]] does to [[Complexity Zoo:P#p|P]]. Defined in [[zooref#hhn95|[HHN+95]]].

###NPSV_t | title: NPSV Total | id: npsvt | url: https://complexityzoo.net/Complexity_Zoo:N#npsvt
The class of all [[#npsv|NPSV]] functions that are total (that is, defined on every input). Contained in [[#npmvt|NPMV<sub>t</sub>]].

###NPSV_t-sel | title: NPSV_t Selective | id: npsvtsel | url: https://complexityzoo.net/Complexity_Zoo:N#npsvtsel
Has the same relation to [[#npsvt|NPSV<sub>t</sub>]] as [[Complexity Zoo:P#psel|P-Sel]] does to [[Complexity Zoo:P#p|P]]. Also known as NP-sel. Defined in [[zooref#hhn95|[HHN+95]]].

###NQL | title: Nondet Quasi-Linear | id: nql | url: https://complexityzoo.net/Complexity_Zoo:N#nql
The class of problems that can be decided in quasi-linear time by a multitape nondeterministic Turing machine. Quasi-linear here means n(log n)<sup>k</sup> + k, for some k. Equals [[#nnlt|NNLT]]. SAT is NQL-complete under quasi-linear-time reductions (which can be computed in deterministic quasi-linear time) [[zooref#sch78|[Sch78]]]. Defined in [[zooref#sch78|[Sch78]]]. See also: [[#nlt|NLT]], [[Complexity Zoo:Q#q|Q]], [[Complexity Zoo:Q#ql|QL]]. Unrelated to [[#nql_2|the other NQL]] below.

###NQL | title: Nondeterministic Quantum Languages | id: nql_2 | url: https://complexityzoo.net/Complexity_Zoo:N#nql_2
An unfortunate name collision. The class of problems nondeterministically recognized by ''Kondacs-Watrous Quantum Finite Automata''. These are automata that undergo a unitary transformation for each symbol consumed, and are measured after '''each''' step to check for acceptance or rejection. The "nondeterminism" refers to the fact that the automaton will accept with positive probability if in the language, or with exactly zero probability otherwise. Has the same caveats as [[#nqp|NQP]] and [[Complexity Zoo:E#eqp|EQP]] because of the exact acceptance probabilities. Initially studied in <ref>A. Kondacs; J. Watrous. On the power of quantum finite state automata. https://ieeexplore.ieee.org/docu ……[中略]…… nite automata. https://arxiv.org/abs/0902.2081v2</ref> it was shown that this inclusion was strict. Also showed that NQL = [[Complexity Zoo:S#sneq|S<sup>≠</sup>]] Contrast with [[Complexity Zoo:Q#qrl|QRL]], which is a different model of quantum finite automaton, in which measurement only occurs at the end. Unrelated to [[#nql|the other NQL]] above.

###NQP | title: Nondeterministic Quantum Polynomial-Time | id: nqp | url: https://complexityzoo.net/Complexity_Zoo:N#nqp
The class of decision problems solvable by a QTM in polynomial time such that a particular '|Accept&gt;' state has nonzero amplitude at the end of the computation, if and only if the answer is 'yes.' Since it has an exact amplitude condition, NQP has the same technical caveats as [[Complexity Zoo:E#eqp|EQP]]. Or it would, except that it turns out to equal [[Complexity Zoo:C#cocequalsp|coC<sub>=</sub>P]] [[zooref#fgh98|[FGH+98]]]. Defined in [[zooref#adh97|[ADH97]]]. Contrast with [[Complexity Zoo:Q#qma|QMA]].

###NSPACE(f(n)) | title: Nondeterministic f(n)-Space | id: nspace | url: https://complexityzoo.net/Complexity_Zoo:N#nspace
Same as [[#npspace|NPSPACE]], but with f(n)-space (for some constructible function f) rather than polynomial-space machines. Contained in [[Complexity Zoo:D#dspace|DSPACE]](f(n)<sup>2</sup>) [[zooref#sav70|[Sav70]]], and indeed [[Complexity Zoo:R#revspace|RevSPACE]](f(n)<sup>2</sup>) [[zoorefComplexity Zoo:C#cp|95|[CP95]]]. NSPACE(n<sup>k</sup>) is strictly contained in NSPACE(n<sup>k+&#949;</sup>) for &#949;&gt;0 [[zooref#iba72|[Iba72]]] (actually the hierarchy theorem is stronger than this, but pretty technical to state).

###NT | title: Near-Testable | id: nt | url: https://complexityzoo.net/Complexity_Zoo:N#nt
The class of decision problems such that whether the answer on input x agrees with the answer on input x-1 (that is, the lexicographic predecessor of x) is solvable in polynomial time. The Turing machine has to decide agreement or disagreement without access to the answer for x-1. Is contained in [[Complexity Zoo:E#e|E]], [[#ntstar|NT*]], and [[Complexity Zoo:Symbols#parityp|&#8853;P]]. Defined in [[zooref#ghj91|[GHJ+91]]] to study [[Complexity Zoo:Symbols#parityp|&#8853;P]]-complete problems. They show that [[Complexity Zoo:P#p|P]], NT, [[#ntstar|NT*]], and [[Complexity Zoo:Symbols#parityp|&#8853;P]] are either all equal or strictly nested. In particular, they differ with probability 1 relative to a random oracle.

###NTIME(f(n)) | title: Nondeterministic f(n)-Time | id: ntime | url: https://complexityzoo.net/Complexity_Zoo:N#ntime
Same as [[#np|NP]], but with f(n)-time (for some constructible function f) rather than polynomial-time machines. The Nondeterministic Time Hierarchy Theorem: If f and g are time-constructible and f(n+1)=o(g), then NTIME(f(n)) does not equal NTIME(g(n)) [[zooref#sfm78|[SFM78]]] (this is actually stronger than the hierarchy theorem for [[Complexity Zoo:D#dtime|DTIME]]). NTIME(n) strictly contains [[Complexity Zoo:D#dtime|DTIME(n)]] [[zooref#pps83|[PPS+83]]] (this result does not work for arbitrary f(n)). For any constructible superpolynomial f, NTIME(f(n)) with [[#np|NP]] oracle is not in [[Complexity Zoo:P#ppoly|P/poly]] [[zooref#kan82|[Kan82]]].

###NT* | title: Near-Testable With Forest Ordering | id: ntstar | url: https://complexityzoo.net/Complexity_Zoo:N#ntstar
Defined like NT, but with a more general ordering on inputs. A problem L is in NT* if, first, there is a partially defined predecessor function pred(x) in [[Complexity Zoo:F#fp|FP]] that organizes the space of inputs into a forest. The size of the lineage of each x must also be bounded by 2<sup>poly(|x|)</sup>. Second, if L(x) is the Boolean answer to L on input x, then L(x)+L(pred(x)) is computable in polynomial time; or if pred(x) does not exist, L(x) is computable in polynomial time. Defined in [[zooref#ghj91|[GHJ+91]]]. Contains [[#nt|NT]] and is contained in [[Complexity Zoo:Symbols#parityp|&#8853;P]]. The inclusions are either both strict or both equalities (whence [[Complexity Zoo:Symbols#parityp|&#8853;P]] = [[Complexity Zoo:P#p|P]] as well).

###OCL | title: One-Counter Languages | id: o2p | url: https://complexityzoo.net/Complexity_Zoo:O#o2p
The class of languages accepted by nondeterministic one-counter automata: finite automata equipped with one nonnegative counter that can be incremented, decremented, and tested for zero. Equivalently, OCL is the class accepted by pushdown automata with a singleton stack alphabet, plus a bottom marker. REG ⊊ OCL ⊊ CFL. As decision problems over strings, OCL ⊆ NL. Examples include {a^n b^n : n ≥ 0} and the one-parenthesis Dyck language. The two-parenthesis Dyck language is CFL but not OCL. Contains [[Complexity Zoo:D#DOCL|DOCL]] and [[Complexity Zoo:P#PB-OCL|PB-OCL]]. Contained in [[Complexity Zoo:C#CFL|CFL]] and [[Complexity Zoo:N#NL|NL]].

###OIP | title: Oblivious IP | id: oip | url: https://complexityzoo.net/Complexity_Zoo:O#oip
[[Complexity Zoo:I#ip|IP]] where only the input size is known during the interaction with the prover, and after that interaction, the verifier gets the specific input. L is in OIP if there exists a randomized, polynomial time interrogator I which takes an input size and interacts with a prover to produce a witness, and polynomial time verifier V that takes an input and a witness so that <ol> <li>Given an input size n, there is prover so that I given n and interacting with the prover produces a witness w so that, for any input x of length n where x is in L, V accepts on x and w.</li> <li>For any x not in L of length n, for any prover interacting with I on input n gives a witness w' which V will reject with x and w' with probability at least 2/3.</li> </ol> OIP = [[Complexity Zoo:I#ip|IP]] &#8745; [[Complexity Zoo:P#ppoly|P/poly]] [[zooref#gm15|[GM15]]].

###OMA | title: Oblivious MA | id: oma | url: https://complexityzoo.net/Complexity_Zoo:O#oma
The class of functions computable in randomized polynomial time with a shared, untrusted witness for each input size. The input-oblivious version of [[Complexity Zoo:M#ma|MA]]. L is in OMA if there exists a randomized, polynomial time verifier V taking an input and a witness, so that: <ol> <li>There is a witness for each n of polynomial size, so that for any input of size n, if the input is is in L, then the verifier accepts on that input and the witness.</li> <li>If the input is not in L, then for any witness, the verifier rejects on that input with probability at least 1/2.</li> </ol> [[Complexity Zoo:N#np|NP]] is contained in OMA iff [[Complexity Zoo:N#np|NP]] is in [[Complexity Zoo:P#ppo ……[中略]…… EXP]] is contained in [[Complexity Zoo:P#ppoly|P/poly]] iff [[Complexity Zoo:E#exp|EXP]] = OMA [[zooref#fsw09|[FSW09]]]. [[Complexity Zoo:B#bpp|BPP]] is contained in OMA [[zooref#gm15|[GM15]]]. Implicit in {{zcite|San07}} that OMA/1 (that is, OMA with 1 bit of trusted advice) does not have circuits of size <math>n^k</math> for any <math>k>0</math>.

###ONP | title: Oblivious NP | id: onp | url: https://complexityzoo.net/Complexity_Zoo:O#onp
The class of functions computable in polynomial time with a shared, untrusted witness for each input size. The input-oblivious version of [[Complexity Zoo:N#np|NP]]. L is in ONP if there exists a polynomial time verifier V taking an input and a witness, so that: <ol> <li>There is a witness for each n of polynomial size, so that for any input of size n, if the input is in L, then the verifier accepts on that input and the witness.</li> <li>If the input is not in L, then for any witness, the verifier rejects on that input.</li> </ol> Defined in [[zooref#fsw09|[FSW09]]], where it was shown [[Complexity Zoo:N#np|NP]] has size n<sup>k</sup> circuits for some constant k if and only if ONP/1 has si ……[中略]…… N#np|NP]] iff [[Complexity Zoo:N#np|NP]] is in [[Complexity Zoo:P#ppoly|P/poly]] [[zooref#fsw09|[FSW09]]]. If [[Complexity Zoo:N#ne|NE]] is not [[Complexity Zoo:E#e|E]] then ONP is not [[Complexity Zoo:P#p|P]] [[zooref#gm15|[GM15]]]. See also [[Complexity Zoo:Y#yp|YP]] for an input oblivious analogue of [[Complexity Zoo:N#npiconp|NP &#8745; coNP]].

###OptP | title: Optimum Polynomial-Time | id: optp | url: https://complexityzoo.net/Complexity_Zoo:O#optp
The class of functions computable by taking the maximum (or minimum) of the output values over all accepting paths of an [[Complexity Zoo:N#np|NP]] machine. OptP[f(n)] restricts the size of the output to f(n) bits. Defined in [[zooref#kre88|[Kre88]]]. Contrast with [[Complexity Zoo:F#fnp|FNP]]. [[MaxSat]] that returns the number of satisfied clauses, [[Clicque]] that returns the size of the clique, [[Chromatic Number]] are OptP[log n]-complete.
