## Purpose and Scope

 This section documents the Tenant Skill Catalog and Installation mechanism in WeKnora. It details how skills—modular code packages that extend sandbox runtimes—are sourced, uploaded, installed, verified, managed, and cleaned up. The technical coverage spans skill resolution from external sources (`ClawHub`, `SkillHub`, Git, ZIP uploads), the asynchronous installation pipeline, bundle verification rules, environment variable declarations, resource cleanup, and the Vue.js frontend UI components.

 
---

 
## 1. Skill Sources: ClawHub, SkillHub, Git, and ZIP Uploads

 WeKnora accepts skills from multiple origins, normalizing them into a skill bundle archive (`SkillBundle`) that the backend installs into a tenant sandbox image.

 
### Supported Sources and Identification

 
 - **Registries (`ClawHub` / `SkillHub`):** Skills are referenced via registry slugs (e.g., `@owner/slug` or `slug@version`) resolved through anonymous HTTP queries.
 - **Federated `skills.sh`:** Prefixed as `skills-sh:owner/repo/slug`, resolved via registry APIs to pinned GitHub commits.
 - **Git Repositories (GitHub / GitLab):** Referenced directly via repository URLs or commit/path specifiers.
 - **Direct ZIP URLs:** Arbitrary HTTP downloadable ZIP bundles.
 
 The input string is processed by `parseSkillSource` to produce a `parsedSkillSource` struct ([internal/application/service/tenant_skill_source.go54-64](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_source.go#L54-L64)).

 
### Parsing and Fetching Flow

 The parsing function `parseSkillSource` maps raw inputs to a specific `skillSourceKind` without network probing ([internal/application/service/tenant_skill_source.go138-191](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_source.go#L138-L191)).

## 2. Installation Pipeline and Skill Bundle Verification

 
### Bundle Structure and Safety Limits

 A `SkillBundle` encapsulates metadata parsed from `SKILL.md` (Name, Version, Description, Instructions) alongside a file map (`Files`) containing archive-relative file contents. Parsing enforces strict safety boundaries:

 
 - Maximum file count (20,000)
 - Maximum ZIP entries (100,000)
 - Maximum single file size (32 MiB)
 - Maximum total bundle size (512 MiB)
 
 
### Installation Execution Flow

 The installation pipeline is coordinated by `TenantSkillService.installParsedSkill` ([internal/application/service/tenant_skill_install.go88-177](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_install.go#L88-L177)).

 
 - **Existence & Conflict Check:** Validates if an existing skill of the same name exists to perform an in-place upgrade (`[internal/application/service/tenant_skill_install.go:98-157]`).
 - **Catalog Storage:** Upserts the bundle into catalog storage ([internal/application/service/tenant_skill_install.go162-171](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_install.go#L162-L171)).
 - **Background Goroutine Execution:** Dispatches an asynchronous worker unbound from the HTTP request context ([internal/application/service/tenant_skill_install.go178-210](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_install.go#L178-L210)).
 - **Sandbox Command Sequence:** Executes atomic runner steps inside the sandbox container: 
 - `prepare-skill-dir`: Cleans workspace scratch directories.
 - `seed-files`: Transfers files via a single `tar` archive (`skillSeedArchivePath`) to optimize round-trips ([internal/application/service/tenant_skill_install.go44-48](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_install.go#L44-L48)).
 - `skillTreeVerifyCommand` / `installPythonVerifyCommand`: Verifies structural integrity and Python interpreter dependencies across verification rounds ([internal/application/service/tenant_skill_install.go49-59](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_install.go#L49-L59)).
 - **Snapshot & Pointer Switch:** Generates a new immutable sandbox snapshot (via `skillSnapshotBuildName`) and atomically updates the image pointer (`[internal/application/service/tenant_skill_install_test.go:43-76]`, [internal/application/service/tenant_skill_install_test.go98-107](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_install_test.go#L98-L107)).

## 3. Bundle Verification and Environment Declarations

 
### Bundle Verification

 Verification confirms that declared script imports match required python packages. Because `SKILL.md` prose may omit transitive dependencies (e.g., `defusedxml` or `lxml`), the verification engine operates in up to two reconciliation rounds ([internal/application/service/tenant_skill_install.go49-59](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_install.go#L49-L59)). Commands execute under unprivileged user contexts within the container runtime.

 
### Environment Variable Declarations

 Skills declare required environment variables in their metadata (`types.SkillEnvVars`). The API layer project these declarations through `skillEnvResponse` structs ([internal/handler/sandbox_skill.go120-131](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/sandbox_skill.go#L120-L131)):

 
 - `Name`: Identifier of the environment variable.
 - `Description`: Human-readable prompt.
 - `Required`: Boolean constraint flag.
 - `IsSet`: Indicates whether a workspace-level credential value has been stored (raw secrets are never returned in reads) ([internal/handler/sandbox_skill.go133-147](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/sandbox_skill.go#L133-L147)).

## 4. Reaper Cleanup and Resource Management

 The reaper and removal pipeline (`TenantSkillService.RemoveSkill`) ensure that uninstalled skills leave no dangling artifacts ([internal/application/service/tenant_skill_remove.go18-57](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_remove.go#L18-L57)).

 
 - **State Transition:** The skill entity status is updated to `types.SkillStatusRemoving` ([internal/application/service/tenant_skill_remove.go34-43](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_remove.go#L34-L43)).
 - **Lock Acquisition:** Acquires a per-config run lock (`withSkillRunLock`) to prevent race conditions with ongoing installations ([internal/application/service/tenant_skill_remove.go48-55](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_remove.go#L48-L55)).
 - **Directory Removal & Snapshot Generation:** Removes the target directory (`sandbox.SkillDirFor`), captures a new snapshot excluding the skill, and advances the generation pointer ([internal/application/service/tenant_skill_remove.go95-176](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_remove.go#L95-L176)).
 - **Rollback Safeguards:** If an error occurs after image modification, failure handlers log inconsistencies or restore the database row to a retryable state ([internal/application/service/tenant_skill_remove.go117-135](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tenant_skill_remove.go#L117-L135)).
