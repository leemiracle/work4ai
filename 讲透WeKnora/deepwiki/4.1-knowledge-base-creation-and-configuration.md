## Purpose and Scope

 This document details the creation and configuration of knowledge bases in WeKnora. Knowledge bases serve as logical containers for organizing, chunking, parsing, and retrieving knowledge entities (documents, FAQ items, and Wiki pages). This page explains the underlying data models, creation workflows, chunking strategies, parser rule engines, embedding model associations, and storage provider bindings.

 For information about document ingestion, see [Document Upload and Processing](https://github.com/Tencent/WeKnora/blob/10973ed3/Document Upload and Processing) For FAQ-specific workflows, see [FAQ Management](https://github.com/Tencent/WeKnora/blob/10973ed3/FAQ Management) For indexing and vector operations, see [Chunk Management and Vector Indexing](https://github.com/Tencent/WeKnora/blob/10973ed3/Chunk Management and Vector Indexing)

## Knowledge Base Types

 WeKnora supports three primary knowledge base types, defined in `internal/types/knowledgebase.go`:

 
| Type | Identifier | Use Case | Storage Model |
|---|---|---|---|
| Document | document | General document collections (.pdf, .docx, .txt, etc.) | File-based with hierarchical chunking, vector embeddings, and optional graph extraction |
| FAQ | faq | Question-answer pairs with priority matching | Direct structured chunk storage without file intermediaries |
| Wiki | wiki | Structured technical documentation and cross-linked content | Specialized wiki-generation pipeline and auto-link generation |

 **Document Knowledge Bases** (`KnowledgeBaseTypeDocument`) manage unstructured files that undergo parsing, chunking, and vectorization [internal/types/knowledgebase.go33](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/knowledgebase.go#L33-L33)
 **FAQ Knowledge Bases** (`KnowledgeBaseTypeFAQ`) manage structured Q&A entries [internal/types/knowledgebase.go34](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/knowledgebase.go#L34-L34)
 **Wiki Knowledge Bases** (`KnowledgeBaseTypeWiki`) coordinate auto-wiki generation and hierarchical page storage [internal/types/knowledgebase.go35](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/knowledgebase.go#L35-L35)

### Chunking and Parser Configuration

 Chunking parameters and parser engine rules are governed by `KBModelConfigRequest` [internal/handler/initialization.go96-121](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L96-L121) and mapped to `types.ChunkingConfig` [internal/types/knowledgebase.go79](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/knowledgebase.go#L79-L79) during updates.

 
| Parameter | Type | Description |
|---|---|---|
| chunkSize | int | Target character size for text chunks internal/handler/initialization.go105 |
| chunkOverlap | int | Character overlap between consecutive chunks internal/handler/initialization.go106 |
| separators | []string | Delimiters used for splitting text internal/handler/initialization.go107 |
| parserEngineRules | []types.ParserEngineRule | Custom file-type to parser engine routing rules internal/handler/initialization.go108 |
| strategy | *string | Adaptive splitting tier (auto, heading, heuristic, legacy) internal/handler/initialization.go117 |
| enableParentChild | bool | Enables hierarchical parent-child chunking internal/handler/initialization.go109 |

### Storage Providers and Vector Store Binding

 Storage providers and vector store backends determine where original files, artifacts, and embeddings are stored.

 
 - **Storage Backend Selection**: Configured via `storageProvider` (`local`, `minio`, `cos`, etc.) and `storageBackendId` [internal/handler/initialization.go128-131](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L128-L131)
 - **Vector Store Binding (`VectorStoreID`)**: Explicitly links a knowledge base to a registered vector store instance [internal/types/knowledgebase.go97-103](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/knowledgebase.go#L97-L103) Enforced as immutable via GORM tag (`<-:create`) [internal/types/knowledgebase.go103](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/knowledgebase.go#L103-L103)
 - **Metadata Enrichment**: Handlers enrich responses with store status using `buildKBResponse` and `buildKBListResponse` [internal/handler/knowledgebase.go109-176](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/knowledgebase.go#L109-L176)
