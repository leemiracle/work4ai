  This document describes WeKnora's dependency injection (DI) system and service layer architecture. It covers how components are registered, resolved, and managed throughout the application lifecycle using Uber's `dig` container framework [internal/container/container.go30-79](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L30-L79)

 
## Purpose and Scope

 The purpose of this page is to document the wiring, configuration, and structural patterns used in WeKnora's backend architecture. This includes the initialization sequence in the `container` package, service registration mechanisms, interface bindings, and the layered architecture enforcing clean boundaries between HTTP handlers, business services, and data repositories [internal/container/container.go1-108](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L1-L108)

## Overview

 WeKnora implements dependency injection using the [go.uber.org/dig](https://github.com/Tencent/WeKnora/blob/10973ed3/go.uber.org/dig) library to manage component lifecycle and dependencies [internal/container/container.go30-79](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L30-L79) The DI container is built at application startup in `BuildContainer()` [internal/container/container.go112](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L112-L112) and handles:

 
 - **Component Registration**: Services, repositories, handlers, and infrastructure clients are registered with the container [internal/container/container.go113-142](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L113-L142)
 - **Dependency Resolution**: Constructor functions declare their dependencies via parameters; `dig` automatically resolves and injects them [internal/container/container.go30](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L30-L30)
 - **Lifecycle Management**: Resources requiring cleanup (database connections, goroutine pools, tracers) are registered with a `ResourceCleaner` [internal/container/container.go113-117](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L113-L117)
 - **Layered Architecture**: Enforces separation between HTTP handlers, business logic services, and data access repositories.
 
 The container is fully constructed before the HTTP server starts, ensuring all dependencies are satisfied at startup rather than at runtime.

 Sources: [internal/container/container.go1-112](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L1-L112)

## Service Layer Architecture

 WeKnora follows a strict layered architecture. Each layer communicates only with the layer directly below it via interfaces.

 **Dependency Rules:**

 
 - **Handlers** depend only on **Services** and **Config**. Handlers consume interfaces to interact with business logic [internal/types/interfaces/](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/)
 - **Services** depend on **Repositories**, other **Services**, and **Infrastructure clients** [internal/application/repository/](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/)
 - **Repositories** depend on database drivers or specific infrastructure clients [internal/container/container.go42](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L42-L42)
 - All dependencies are injected as **interfaces** defined in the `internal/types/interfaces` package to facilitate testing and decoupling [internal/types/interfaces/](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/)

### 3. System Settings Service

 The `SystemSettingService` provides a runtime-tunable configuration layer. It uses a registry to define legal keys, types, and fallback environment variables.

 
 - **Registry authority**: Only keys in the registry can be updated.
 - **Persistence**: Settings are stored in the database and cached in memory. Changes are propagated across replicas using Redis Pub/Sub.

## Lifecycle and Cleanup

 WeKnora ensures that resources like database connections and thread pools are closed gracefully during server shutdown.

 
 - **ResourceCleaner**: A central registry for cleanup tasks [internal/container/container.go117](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L117-L117)
 - **Registration**: Infrastructure components register their cleanup functions via `container.Invoke`. 
 - `registerLangfuseCleanup`: Ensures observability data is flushed [internal/container/container.go128](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L128-L128)
 - `registerPoolCleanup`: Releases the `ants` goroutine pool [internal/container/container.go131](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L131-L131)
 - **Execution**: During server shutdown, the system executes all registered tasks in the `ResourceCleaner`.
