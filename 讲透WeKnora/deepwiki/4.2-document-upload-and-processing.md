## Purpose and Scope

 This document details the document ingestion, validation, parsing, asynchronous task orchestration, and status tracking pipeline in WeKnora. It covers how files, URLs, text passages, and manual Markdown enter the system through `KnowledgeHandler` [internal/handler/knowledge.go30-38](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/knowledge.go#L30-L38), get processed via `knowledgeService` [internal/application/service/knowledge.go48-85](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge.go#L48-L85), and are transformed into persistent chunks and vector indices using repository and chunking services.

## Document Ingestion Overview

 WeKnora supports four primary document ingestion paths, each mapped to specific API endpoints, handler methods, and service interfaces:

 
| Ingestion Method | API Route | Handler Method / Service Interface | Processing Mode | Use Case |
|---|---|---|---|---|
| File Upload | POST /api/v1/knowledge-bases/:id/knowledge/file | KnowledgeHandler.CreateKnowledgeFromFile (interfaces.KnowledgeService.CreateKnowledgeFromFile) | Asynchronous (Asynq) | Uploading binary documents (PDF, DOCX, TXT, MD) |
| URL Import | POST /api/v1/knowledge-bases/:id/knowledge/url | KnowledgeHandler.CreateKnowledgeFromURL (interfaces.KnowledgeService.CreateKnowledgeFromURL) | Asynchronous (Asynq) | Crawling web pages or downloading direct files from URLs |
| Text Passages | Internal API | interfaces.KnowledgeService.CreateKnowledgeFromPassage / processDocumentFromPassage | Asynchronous (Asynq) | Programmatic passage ingestion |
| Manual Markdown | POST /api/v1/knowledge-bases/:id/knowledge/manual | KnowledgeHandler / interfaces.KnowledgeService.CreateKnowledgeFromManual | Synchronous / Draft | User-authored markdown editing |

 All ingestion methods instantiate a `types.Knowledge` record in PostgreSQL via `knowledgeRepository.CreateKnowledge()` [internal/application/repository/knowledge.go56-60](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/knowledge.go#L56-L60) with a default `processing` status, then enqueue an asynchronous task for parsing and chunking.

## File Upload Pipeline

 
### API Endpoint and Handler Validation

 File uploads are initiated via a multipart form HTTP request.

 
 - **Endpoint:** `POST /api/v1/knowledge-bases/{id}/knowledge/file`
 - **Handler:** `KnowledgeHandler` delegates access verification to `validateKnowledgeBaseAccessWithKBID()` [internal/handler/knowledge.go95-105](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/knowledge.go#L95-L105) to ensure the caller holds appropriate tenant permissions or organization sharing grants.
 - **Payload Parameters:** Expects a multipart file header (`*multipart.FileHeader`), optional `process_overrides` (`types.KnowledgeProcessOverrides`), and an array of `tag_ids`.
 
 Sources: [internal/handler/knowledge.go30-105](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/knowledge.go#L30-L105), [internal/types/interfaces/knowledge.go13-26](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/knowledge.go#L13-L26)

 
### Configuration Merging, Type Verification, and Deduplication

 Once the handler validates the request, `knowledgeService` processes the upload file:

 
 - **Configuration Merging:** Combines knowledge-base-level parsing and chunking configurations with per-upload `process_overrides`.
 - **Validation:** Validates file formats and extensions. Unsupported file types trigger `ErrInvalidFileType` [internal/application/service/knowledge.go30](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge.go#L30-L30).
 - **Deduplication:** Computes file hashes to check for collisions within the same knowledge base, returning `ErrDuplicateFile` when a duplicate exists [internal/application/service/knowledge.go38](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge.go#L38-L38).
 
 Sources: [internal/application/service/knowledge.go28-44](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge.go#L28-L44), [internal/types/interfaces/knowledge.go13-26](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/knowledge.go#L13-L26)

 
### Document Parsing, Chunking, and Indexing

 Files undergo a multi-step extraction and chunking sequence:

 
 - **Document Reading:** `interfaces.DocumentReader.ReadDocument()` parses the binary stream.
 - **Chunking Engine:** Extracted text is fed into `chunker.Chunker.Chunk()`. When parent-child chunking is enabled, records are structured with parent and child links (`ProcessChunksOptions`) [internal/application/service/knowledge_process.go194-200](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge_process.go#L194-L200).
 - **Embedding Generation:** Vector representations are calculated using the designated embedding model.
 - **Repository Persistence:** Chunks are saved in batches via `interfaces.ChunkRepository.CreateChunks()` [internal/application/repository/chunk.go42-69](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/chunk.go#L42-L69).
 - **Vector Indexing:** Chunks are registered into vector engines via `interfaces.RetrieveEngineRegistry`.

## Async Orchestration and Status Tracking

 
### Asynq Worker Pool Architecture

 WeKnora executes long-running ingestion and processing tasks asynchronously using `Asynq` worker pools:

 
 - **Core Server (`QueueCore`):** [internal/router/task.go31](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/task.go#L31-L31) Handles heavy document parsing, text extraction, and manual knowledge updates (`ProcessDocument`, `ProcessManualUpdate`).
 - **Post-Process Server (`QueuePostProcess`):** [internal/router/task.go32](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/task.go#L32-L32) Manages lightweight fan-out tasks and finalization steps.
 - **Enrichment Server (`QueueSummary`, `QueueQuestion`):** [internal/router/task.go33](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/task.go#L33-L33) Runs LLM-bound operations like summary generation and auxiliary question synthesis.
 
 Sources: [internal/router/task.go24-51](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/task.go#L24-L51), [internal/application/service/knowledge.go107-122](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge.go#L107-L122)

 
### Span Tracking and Frontend Timeline Integration

 The `SpanTracker` interface [internal/application/service/knowledge.go83](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge.go#L83-L83) logs hierarchical execution spans per parse attempt, allowing the frontend component `knowledge-processing-timeline.vue` [frontend/src/components/knowledge-processing-timeline.vue1-40](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/components/knowledge-processing-timeline.vue#L1-L40) to render real-time pipeline stages.

 
 - **Attempt Scoping:** `withAttempt()` [internal/application/service/knowledge.go172-177](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge.go#L172-L177) tags request contexts with attempt identifiers.
 - **Cancellation:** `CancelKnowledgeParse()` halts active workers and updates task states.

## Status Management

 The lifecycle of a knowledge entry is governed by `ParseStatus` fields stored on `types.Knowledge`:

 
| Parse Status | Code Constant | Description |
|---|---|---|
| processing | types.ParseStatusProcessing | Document is currently parsing or awaiting async enrichment subtasks. |
| completed | types.ParseStatusCompleted | Parsing, chunking, embedding, and indexing completed successfully. |
| failed | types.ParseStatusFailed | Unrecoverable error encountered during execution. |
| finalizing | types.ParseStatusFinalizing | Primary ingestion finished; background enrichment tasks ongoing. |
| cancelled | types.ParseStatusCancelled | Parsing manually terminated by user action. |
| draft | types.ParseStatusDraft | Manual markdown content saved in draft state. |
