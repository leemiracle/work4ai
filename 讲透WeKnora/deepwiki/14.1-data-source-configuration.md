  The Data Source Configuration system in WeKnora enables automated ingestion of knowledge from external platforms like Feishu, Notion, Yuque, GitLab, RSS feeds, and more. It manages the lifecycle of external data connectors, including credential management, hierarchical resource selection, automated synchronization schedules, and detailed sync logging.

 This page explains how to configure data source connectors, manage sync schedules, inspect sync logs, and handle credential lifecycle with full technical details, data flows, implementation specifics, and associated code entities.

 
---

 
## System Architecture and Data Flow

 The data source subsystem is implemented primarily in `DataSourceService` [internal/application/service/datasource_service.go26-64](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/datasource_service.go#L26-L64) which coordinates between database repositories, asynchronous task queues, connector implementations, and a scheduling mechanism.

 
 - **Data Sources** represent configured external connectors targeting a knowledge base (`types.DataSource` [internal/types/datasource.go65-129](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/datasource.go#L65-L129)).
 - **Connectors** implement platform-specific API logic for resource listing and synchronization (`datasource.Connector` [internal/datasource/connector.go11-52](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/datasource/connector.go#L11-L52)).
 - **Sync Tasks** are queued via `asynq` to perform asynchronous data ingestion.
 - **Sync Logs** track every sync attempt with granular metrics and error reporting (`types.SyncLog` [internal/types/datasource.go145-193](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/datasource.go#L145-L193)).

## Connector Management

 Connectors abstract platform-specific details, allowing WeKnora to support external systems uniformly.

 
### Connector Interface

 All connectors implement the `datasource.Connector` interface [internal/datasource/connector.go11-52](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/datasource/connector.go#L11-L52) containing these core methods:

 
 - **`Type() string`**: Returns the unique connector type identifier (e.g., `"feishu"`, `"notion"`, `"gitlab"`).
 - **`Validate(ctx, config)`**: Verifies connectivity and credentials [internal/datasource/connector.go15-17](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/datasource/connector.go#L15-L17)
 - **`ListResources(ctx, config, parentID)`**: Lists selectable hierarchical resources with lazy loading support via `parentID` [internal/datasource/connector.go19-28](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/datasource/connector.go#L19-L28)
 - **`ResolveResourceAncestors(ctx, config, resourceIDs)`**: Resolves external IDs of ancestors for nested selections [internal/datasource/connector.go40-42](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/datasource/connector.go#L40-L42)
 - **`FetchAll(ctx, config, resourceIDs)`**: Performs a full sync [internal/datasource/connector.go46](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/datasource/connector.go#L46-L46)
 - **`FetchIncremental(ctx, config, cursor)`**: Performs incremental sync using a `types.SyncCursor` [internal/datasource/connector.go48-51](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/datasource/connector.go#L48-L51)
 
 
### Connector Registry

 The `ConnectorRegistry` [internal/datasource/connector.go121-124](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/datasource/connector.go#L121-L124) manages available connectors via registration [internal/datasource/connector.go133-143](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/datasource/connector.go#L133-L143) and lookup [internal/datasource/connector.go145-152](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/datasource/connector.go#L145-L152)

## Credential Management

 Credentials are treated as sensitive sub-resources separated from standard data source configurations.

 
### Storage and Access

 
 - Credentials are never returned in full in standard API responses; the frontend tracks configuration status via a boolean flag (`credentialsConfigured`) [frontend/src/views/knowledge/settings/DataSourceEditorDialog.vue36-41](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/settings/DataSourceEditorDialog.vue#L36-L41)
 - The `DataSourceService` enforces that credentials passed in standard `PUT /datasource/{id}` bodies are ignored, requiring updates through the dedicated credential subresource endpoints [internal/application/service/datasource_service.go173-187](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/datasource_service.go#L173-L187)
 - Credentials can be explicitly removed via `deleteDataSourceCredentials` [frontend/src/views/knowledge/settings/DataSourceEditorDialog.vue85-100](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/settings/DataSourceEditorDialog.vue#L85-L100)

## Sync Scheduling and Execution

 Data synchronization can be triggered manually or via scheduled cron expressions.

 
### Scheduling Configuration

 
 - Data sources define a `SyncSchedule` cron expression and a `SyncMode` (`incremental` or `full`) [internal/types/datasource.go85-90](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/datasource.go#L85-L90)
 - Conflict strategies (`overwrite` or `skip`) and `SyncDeletions` options control handling during sync execution [internal/types/datasource.go94-98](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/datasource.go#L94-L98)
 - Repositories manage sync status updates through `DataSourceRepository.UpdateSyncState` [internal/application/repository/datasource_repo.go103-124](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/datasource_repo.go#L103-L124)

## Monitoring and Sync Logs

 Each synchronization run produces a `SyncLog` entry tracking execution metrics [internal/types/datasource.go145-193](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/datasource.go#L145-L193)

 
### Stored Metrics

 
 - `status`: Execution state (`running`, `success`, `partial`, `failed`, `canceled`) [internal/types/datasource.go153-157](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/datasource.go#L153-L157)
 - Item counters: `items_total`, `items_created`, `items_updated`, `items_deleted`, `items_skipped`, `items_failed` [internal/types/datasource.go165-181](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/datasource.go#L165-L181)
