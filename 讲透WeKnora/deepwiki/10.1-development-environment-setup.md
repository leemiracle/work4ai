  This page provides a comprehensive guide to setting up a local development environment for WeKnora. It focuses on a "Fast Development" workflow that enables hot-reloading, IDE debugging, and rapid iteration by running application code on the host while keeping infrastructure services in Docker.

 
---

 
## Overview

 WeKnora is designed to be developer-friendly with a clear separation between the application layer (Go backend and Vue.js frontend) and the infrastructure layer (databases, parsers, vector stores). The development environment supports various deployment profiles, ranging from basic RAG capabilities to full-stack configurations including Knowledge Graphs and hybrid document parsers.

 
| Mode | Target | Tooling | Characteristics |
|---|---|---|---|
| Fast Dev | Active Coding | air (Go hot reload), npm run dev (Vue dev server) | Hot-reload enabled; debugger attachable; backend/frontend run on host. |
| Docker Mode | Integration Test | docker-compose | Production-parity; requires image rebuilds on code changes. |
| Lite Mode | Zero Infra Dev | Embedded SQLite, memory stream | Minimal dependencies, no Redis/Postgres needed. |

## Fast Development Mode Architecture

 In fast development mode, backend and frontend code run locally on the host, leveraging hot reload and debuggers on native code. Infrastructure services (databases, message brokers, parsing services) run inside Docker containers.

 This setup is realized by `docker-compose.dev.yml` and helper scripts (`scripts/dev.sh`) to selectively launch needed infrastructure profiles.

 Edit `.env` to match your local setup. Critical variables include:

 
| Variable | Description | Default / Dev Value |
|---|---|---|
| DB_DRIVER | Backend primary DB driver (postgres for dev) | postgres |
| DB_HOST | Postgres service hostname (Docker network) | postgres |
| DB_PORT | Postgres port | 5432 |
| DB_USER | Database user | postgres |
| DB_PASSWORD | Database password | postgres123!@# |
| STREAM_MANAGER_TYPE | Stream backend type (redis for dev) | redis |
| REDIS_ADDR | Redis hostname | redis:6379 |
| REDIS_PASSWORD | Redis password | redis123!@# |
| DOCREADER_ADDR | DocReader gRPC address | docreader:50051 |
| FRONTEND_PORT | Frontend server listen port | 80 |
| APP_PORT | Backend API listen port | 8080 |

 Ensure ports do not conflict with existing services.

## Specialized Development Features

 
### DocReader and OpenDataLoader (ODL) Hybrid Mode

 
 - The `docreader` is a gRPC service for document parsing, running in a container.
 - To enable hybrid parsing with OpenDataLoader, start dev services with `--odl-hybrid` (`scripts/dev.sh:150`).
 - The script awaits successful health check before allowing backend to connect (`scripts/dev.sh:155-177`).
 
 Sources: [scripts/dev.sh139-177](https://github.com/Tencent/WeKnora/blob/10973ed3/scripts/dev.sh#L139-L177)

 
---

 
### Dependency Injection (DI) Container and Service Layer

 The backend leverages Uber Dig for DI, centralizing initialization and wiring in `internal/container/container.go`:

 
 - Registers configuration loading, database connection pool (GORM), Redis client, Langfuse tracing, and core services (`internal/container/container.go:121-127`).
 - Initializes retrieval engines (`internal/container/container.go:135`) and external clients like DocReader (`internal/container/container.go:139`) and Ollama (`internal/container/container.go:141`).
 
 Sources: [internal/container/container.go108-144](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L108-L144)

 
---

 
### Debugging & IDE Integration

 
 - **Backend**: Set `GIN_MODE=debug` and run with `air` watcher (`.air.toml:1-12`) to enable hot reload and breakpoint debugging.
 - **Frontend**: Use Vue dev server (`npm run dev`) which supports source maps and HMR.
 - Ensure `.env` file is loaded or environment variables set inside your IDE run configurations for parity.
 - Backend dependencies requiring CGO or specific build flags (e.g. sqlite-vec bindings) must run with appropriate `go build` tags (`.air.toml:8`).

## Summary

 The fast development environment offers:

 
 - Separation of infrastructure (Docker) and application code (host) for agility.
 - Hot reload with `air` and Vue dev server for immediate feedback.
 - Scripted management of infrastructure with `scripts/dev.sh` and Docker Compose profiles for flexible service allocation.
 - Dependency injection architecture to manage service dependencies for backend code.
 - Easy debugging and configuration overrides through `.env` files.
