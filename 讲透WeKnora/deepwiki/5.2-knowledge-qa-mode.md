## Purpose and Scope

 Knowledge QA Mode is WeKnora's standard retrieval-augmented generation (RAG) mode for answering user queries using knowledge base content. It implements a linear, event-driven pipeline that retrieves relevant document chunks, reranks them, formats context, and streams LLM responses. This mode prioritizes accuracy through structured retrieval stages rather than iterative reasoning.

 For autonomous tool-using agents with ReACT loops, see [Agent Mode and Tool Integration](https://deepwiki.com/Tencent/WeKnora/5.3-agent-mode-and-tool-integration). For session lifecycle management, see [Session Management and Context](https://deepwiki.com/Tencent/WeKnora/5.4-session-management-and-context).

## Architecture Overview

 Knowledge QA Mode executes as a single-pass pipeline with discrete, sequential processing stages managed by `sessionService.KnowledgeQA`. Each stage is implemented as a plugin responding to specific event types.

## Retrieval Strategy

 The Knowledge QA mode utilizes a hybrid retrieval strategy combining vector similarity and keyword-based search (BM25).

 
### Search Targets and Scoping

 Retrieval is scoped using `types.SearchTarget`, which can represent an entire knowledge base or specific files (`SearchTargetTypeKnowledge`) [internal/types/search.go12-16](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/search.go#L12-L16) Tag-based filtering is supported via `types.TagScope`, which allows restricting search to documents carrying specific tags within a KB [internal/types/search.go19-22](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/search.go#L19-L22)

 
 - **Knowledge Base Resolution:** `sessionService.resolveKnowledgeBases` checks explicit `@mentions`, agent configurations (`RetrieveKBOnlyWhenMentioned`), and tenant API key scopes [internal/application/service/session_qa_helpers.go16-60](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session_qa_helpers.go#L16-L60)
 - **Tag Scoping:** Tag scopes are restricted to the allowed agent scope using `sessionService.restrictTagScopesToAgentScope` [internal/application/service/session_qa_helpers.go62-85](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session_qa_helpers.go#L62-L85)
 - **Hybrid Search:** Executed concurrently within `PluginSearch.OnEvent`, combining knowledge base search targets and optional web search [internal/application/service/chat_pipeline/search.go62-122](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/search.go#L62-L122)
 - **Query Expansion:** If recall is low, `PluginSearch` runs keyword-focused query expansion to capture additional candidate chunks [internal/application/service/chat_pipeline/search.go141-146](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/search.go#L141-L146)

### 1. Query Understanding (`chatpipeline.PluginQueryUnderstand`)

 This plugin optimizes the user query for retrieval.

 
 - **Rewriting:** Generates a standalone `RewriteQuery` using templates to perform coreference resolution and ellipsis completion [internal/application/service/chat_pipeline/query_understand.go64-67](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/query_understand.go#L64-L67)
 - **Intent Classification:** Categorizes the query into intents like `kb_search`, `web_search`, `greeting`, `chitchat`, or `summarize` [internal/application/service/chat_pipeline/query_understand.go28-32](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/query_understand.go#L28-L32)
 - **Multimodal Analysis:** If images are present, it uses a VLM/vision model to generate an `ImageDescription` [internal/application/service/chat_pipeline/query_understand.go57-60](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/query_understand.go#L57-L60) This description is persisted to user messages asynchronously [internal/application/service/chat_pipeline/query_understand.go142-144](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/query_understand.go#L142-L144)
 
 
### 2. Search and Expansion (`chatpipeline.PluginSearch`)

 
 - **Concurrent Retrieval:** Executes Knowledge Base searches and Web searches in parallel using goroutines and `sync.WaitGroup` [internal/application/service/chat_pipeline/search.go93-122](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/search.go#L93-L122)

### 3. Merging (`chatpipeline.PluginMerge`)

 The merge pipeline (`PluginMerge.OnEvent`) follows an 8-step process:

 
 - **Input Selection:** Picks rerank results or falls back to search results sorted by score [internal/application/service/chat_pipeline/merge.go101-113](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L101-L113)
 - **Initial Deduplication:** Removes exact duplicate chunk IDs [internal/application/service/chat_pipeline/merge.go115-126](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L115-L126)
 - **History Injection:** Appends relevant history references and deduplicates [internal/application/service/chat_pipeline/merge.go128-145](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L128-L145)
 - **Parent Chunk Resolution:** Resolves child chunks to parent chunks and scopes image metadata [internal/application/service/chat_pipeline/merge.go76-78](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L76-L78)
 - **Grouping & Merging:** Groups by Knowledge ID and Chunk Type, merging sequential bodies [internal/application/service/chat_pipeline/merge.go149-191](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L149-L191)

 - **Context Expansion & Re-merge:** Expands short contexts with neighboring chunks and re-merges [internal/application/service/chat_pipeline/merge.go85-89](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/merge.go#L85-L89)

## Context Formatting and Fallback

 
### Context Preparation

 The `PluginIntoChatMessage` plugin prepares the final prompt.

 
 - **Prompt Placeholders:** Renders placeholders such as `{{query}}`, `{{language}}`, and `{{contexts}}` [internal/application/service/chat_pipeline/common.go92-96](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/chat_pipeline/common.go#L92-L96)
 - **Image Enrichment:** `EnrichSearchResultsImageInfo` and `CollectImageInfoByChunkIDs` fetch and embed image OCR and captions into search results for multimodal QA [internal/searchutil/imageinfo.go55-160](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/searchutil/imageinfo.go#L55-L160)
 
 
### Fallback Mechanism

 If retrieval yields no results, the system employs a fallback strategy defined by `types.FallbackStrategy` [internal/application/service/session_knowledge_qa.go68-72](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session_knowledge_qa.go#L68-L72)

 
 - **Fixed Strategy:** Returns a static fallback message (`types.FallbackStrategyFixed`) [internal/application/service/session_knowledge_qa.go68-72](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session_knowledge_qa.go#L68-L72)
 - **Model Fallback:** Invokes the LLM with a `FallbackPrompt` including conversation history to answer based on general knowledge [internal/application/service/session_knowledge_qa.go121-123](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session_knowledge_qa.go#L121-L123)
