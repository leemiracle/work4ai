## Package Structure

 WeKnora organizes its source code inside the `internal/` directory, following an idiomatic Go project layout that encapsulates private application logic not intended for public reuse.

 
### Directory Layout

 
```
WeKnora/
├── internal/                      # Private application code
│   ├── application/               # Core business logic
│   │   ├── repository/            # Data persistence abstractions & implementations
│   │   │   └── retriever/         # Vector store driver implementations
│   │   └── service/               # Business logic service layer
│   │       ├── chat_pipeline/     # Chat pipeline plugins and processors
│   │       ├── file/              # File storage and management
│   │       └── retriever/         # Retrieval engine services
│   ├── agent/                     # Agent system & tooling (incl. approval logic)
│   │   └── approval/              # Agent tool execution approval module
│   ├── container/                 # Dependency injection container wiring
│   ├── handler/                   # HTTP handlers using the Gin framework
│   │   └── session/               # Session-specific HTTP handlers
│   ├── router/                    # Route declarations & RBAC enforcement
│   ├── types/                     # Domain types, constants, interfaces
│   │   └── interfaces/            # Interface abstraction contracts
│   ├── config/                    # Configuration loading and schema definitions
│   ├── database/                  # Database migrations and schema setup
│   ├── event/                     # Event bus for internal asynchronous events
│   ├── logger/                    # Logging utilities and context enrichment
│   ├── models/                    # Model integrations (LLM, Ollama, etc.)
│   ├── mcp/                       # Model Context Protocol implementation
│   ├── stream/                    # SSE and streaming response management
│   └── tracing/                   # OpenTelemetry and Langfuse tracing integrations
├── frontend/                      # Vue 3 + Pinia + Vite frontend SPA
└── scripts/                       # Shell scripts for development and build
```

 This modular separation helps maintain clear boundaries between layers and responsibilities, easing testing, maintenance, and extension.

### Package Organization Principles

 
| Layer | Package Path | Responsibilities |
|---|---|---|
| Types | internal/types | Core domain types, constants, context keys |
| Interfaces | internal/types/interfaces | Interface contracts to decouple layers |
| Repository | internal/application/repository | Data access and persistence including SQL and vector storage |
| Service | internal/application/service | Business logic orchestration and domain operations |
| Handler | internal/handler | HTTP request parsing, binding, and response formatting |
| Container | internal/container | Dependency injection wiring and lifecycle management |
| Router | internal/router | HTTP route registration and RBAC middleware attachment |

## Multi-Tenancy and Context Patterns

 WeKnora enforces multi-tenancy through explicit context propagation and middleware that manages tenant-scoping and role-based access control.

## Configuration Management

 WeKnora employs a hierarchical configuration system to support flexible and environment-specific settings.

 
### Configuration Layers

 
| Source | Functionality | Details/Location |
|---|---|---|

## Logging and Observability Patterns

 The system incorporates a centralized logging strategy enriched with request context and optional tracing.

 
 - A private logger instance ensures logging does not pollute the global environment and supports ANSI color stripping for file logs while maintaining colors on stdout.
 - Logs incorporate contextual fields such as `request_id` and `trace_id` (from Langfuse) to provide observability into user requests and event flows.
 - Tracing and metrics integration with external observability tools is provided optionally via Langfuse tracing in the DI container startup.

# Summary

 WeKnora's codebase is architected carefully with a classic layered design ensuring separation of concerns:

 
 - **Package layout** enforces module responsibility and encapsulation.
 - **Dependency Injection using uber-go/dig** builds a composable, testable service graph.
 - **Repository-Service-Handler** pattern cleanly divides data persistence, business logic, and HTTP layers.
 - **Multi-tenancy** is rigorously enforced using typed context keys and middleware.
 - **Retrieval engines** are pluggable components wired into the container according to config.
 - **Hierarchical configuration** allows flexible overrides through env variables and YAML.
 - **Logging and tracing** embed rich contextual info for observability.
