  This page documents the programmatic interfaces for WeKnora, including the Go client SDK for programmatic access (`client/`), the Python-based Model Context Protocol (MCP) server for tool integration (`mcp-server/`), the DeepSeek Harness package as part of the MCP setup, and the WeChat Mini Program client. These components enable external application integration, LLM tool-calling environments, and automated workflows with WeKnora.

 
---

 
## Go Client SDK

 The Go Client SDK is the primary programmatic interface to WeKnora’s REST API, providing comprehensive client-side support for managing tenants, knowledge bases, knowledge entries, sessions, agents, and models.

 
### Client Initialization and Authentication

 The `Client` struct manages HTTP communication and authentication configuration. It supports long-lived API keys via the `X-API-Key` header and short-lived Bearer tokens via the `Authorization` header. The client is configured using functional options:

 
 - `WithAPIKey(string)` to set the API key
 - `WithBearerToken(string)` to set a Bearer token
 - `WithTimeout(time.Duration)` to configure HTTP timeouts
 - `WithTenantID(uint64)` to set a default tenant ID for requests
 
 This design allows for flexibility in authenticating and managing request context.

 Sources: [client/client.go20-101](https://github.com/Tencent/WeKnora/blob/10973ed3/client/client.go#L20-L101)

 
### Knowledge Ingestion and Management

 The SDK exposes knowledge creation endpoints to ingest data into knowledge bases. Knowledge entries can be created from:

 
 - Local files (`CreateKnowledgeFromFile`): Uploads documents via multipart/form-data, supporting optional metadata and parse configuration overrides for chunking, multimodel enabling, and ASR or VLM options.
 - URLs (`CreateKnowledgeFromURL`): Creates knowledge entries from a remote web resource.
 - Raw text (through MCP tooling).
 
 The ingestion process sends data to endpoints such as `/api/v1/knowledge-bases/{id}/knowledge/file` or `/api/v1/knowledge-bases/{id}/knowledge/url`. Per-upload parse overrides can be sent to customize parser engines and chunking behavior for that specific knowledge item.

 Sources: [client/knowledge.go89-97](https://github.com/Tencent/WeKnora/blob/10973ed3/client/knowledge.go#L89-L97) [client/knowledge.go108-181](https://github.com/Tencent/WeKnora/blob/10973ed3/client/knowledge.go#L108-L181)

 
### Chat and Agent Execution

 The SDK supports both Knowledge QA and Agent modes using streaming server-sent events (SSE).

 
 - **Knowledge QA** is performed by the method `KnowledgeQAStream`, which sends queries for knowledge-based retrieval and streams back generated answers using the `StreamResponse` structure.
 - **Agent Mode** offers ReAct style reasoning and tool integration via `AgentQAStreamWithRequest`. It streams `AgentStreamResponse` events representing various phases: `thinking`, `tool_call`, `tool_result`, `answer`, `error`, and `complete`.
 - **Multimodal Support** enables agents to include images encoded as base64 attachments for VLM analysis, enhancing the query context.
 
 Sources: [client/session.go211-218](https://github.com/Tencent/WeKnora/blob/10973ed3/client/session.go#L211-L218) [client/agent.go44-122](https://github.com/Tencent/WeKnora/blob/10973ed3/client/agent.go#L44-L122) [client/session.go204-208](https://github.com/Tencent/WeKnora/blob/10973ed3/client/session.go#L204-L208)

 
### Session and Model Management

 The SDK exposes a rich set of APIs to create, update, delete, and query chat sessions and AI models.

 
 - Sessions serve as conversation containers and can be titled automatically using `GenerateTitle` based on dialogue context.
 - Models are created and managed with detailed parameters controlling QA style, retrieval, and embedding models.
 
 Sources: [client/session.go60-199](https://github.com/Tencent/WeKnora/blob/10973ed3/client/session.go#L60-L199) [client/model.go](https://github.com/Tencent/WeKnora/blob/10973ed3/client/model.go)

 
### Sandbox Skill Management

 Agent sandbox skills provide extensibility for adding user-defined capabilities executed in secure sandboxes.

 
 - Skills can be installed from remote sources or local zip files with APIs like `UploadSandboxSkill` and `InstallSandboxSkillFromSource`.
 - Skill files such as `SKILL.md` can be inspected via dedicated API calls.
 - The SDK offers methods to list available skills and manage skill lifecycle.
 
 Sources: [client/skill.go36-198](https://github.com/Tencent/WeKnora/blob/10973ed3/client/skill.go#L36-L198)

## Python MCP Server

 The WeKnora MCP Server is a standalone Python service implementing the Model Context Protocol (MCP 2.x), enabling LLMs like Claude Desktop or Cursor to use WeKnora as a backend knowledge management toolset via a defined set of tools.

 
### Implementation Overview

 The MCP server is implemented using the `mcp` Python package’s high-level `MCPServer` API. Key implementation points include:

 
 - It registers tool functions using `@mcp.tool()` decorators (`mcp-server/weknora_mcp_server.py`). Each tool method corresponds to a backend API call or functionality, e.g., `create_tenant`, `list_knowledge_bases`, `create_knowledge_from_url`, etc.
 - The `WeKnoraClient` class acts as an internal HTTP client to the WeKnora REST API, maintaining thread-local `requests.Session` instances for safe concurrent calls. It manages SSL verification (configurable via `WEKNORA_VERIFY_SSL`) and API key authentication.
 - Network transports are supported in three modes: `stdio`, `sse`, and `http`, selectable via CLI or environment (`mcp-server/main.py`).
 - Security middleware `MCPAuthMiddleware` enforces a shared secret authentication token on `sse` and `http` transports, configured via the `MCP_SERVER_AUTH_TOKEN` environment variable.

## DeepSeek Harness Package

 The DeepSeek Harness is integrated with the MCP server to rigorously test and execute workflows against the WeKnora API for automatic QA system benchmarking and skill validation.

 
 - It provides harness interfaces to invoke MCP tools and simulate agent behaviors.
 - The harness package elaborates on running complex read-access generation chains programmatically, reused in MCP tool implementations.
 - It leverages the MCP protocol for testing toolchains and ensuring consistent integration between LLM agents and backend APIs.
 
 Sources: [mcp-server/test_mcp_transports.py1-166](https://github.com/Tencent/WeKnora/blob/10973ed3/mcp-server/test_mcp_transports.py#L1-L166)

## WeChat Mini Program Client

 WeKnora supports a WeChat Mini Program client to enable lightweight mobile access for knowledge QA and agent queries.

 
 - The Mini Program integrates with WeKnora's backend APIs via standard REST calls.
 - It supports user authentication, knowledge base selection, chat sessions, and multimedia input.
 - Multimodal features like image attachments are passed from Mini Program UI to backend through the Go client SDK or MCP server protocols for VLM-enhanced chat responses.
