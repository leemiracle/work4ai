## Purpose and Scope

 This document provides a technical deep dive into WeKnora's hybrid retrieval algorithms, detailing how natural language queries translate into executable search targets, execute across heterogeneous backend stores, and merge via Reciprocal Rank Fusion (RRF), score normalization, reranking, and result enrichment.

 
---

 
## 1. Retrieval Engine Architecture & Target Resolution

 WeKnora structures retrieval around unified search targets (`types.SearchTarget`) and multi-tenant scoping. Before executing hybrid searches, callers define targets that specify whether an entire knowledge base or explicit knowledge files are queried [internal/types/search.go26-47](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/search.go#L26-L47)

 The core coordination happens in `knowledgeBaseService.HybridSearch`, which handles embedding dimension validation (`validateQueryEmbeddingDimension`), model identity resolution (`ResolveEmbeddingModelKeys`), and permission verification [internal/application/service/knowledgebase_search.go26-169](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledgebase_search.go#L26-L169)

## 2. Hybrid Search Flow and Score Fusion

 When a search request executes, WeKnora splits retrieval into vector-based similarity search and keyword-based BM25 search. ## 3. FAQ Post-Processing and Iterative Retrieval

 For FAQ-type knowledge bases, WeKnora applies specialized post-processing (`applyFAQPostProcessing`) [internal/application/service/knowledgebase_search_faq.go24-55](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledgebase_search_faq.go#L24-L55) If candidate unique chunks fall short of `MatchCount`, an iterative retrieval loop (`iterativeRetrieveWithDeduplication`) progressively expands top-K parameters across bound stores while filtering out negative questions [internal/application/service/knowledgebase_search_faq.go57-176](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledgebase_search_faq.go#L57-L176)

## 4. Score Normalization Across Heterogeneous Engines

 Because different vector store backends (Milvus, Qdrant, Postgres pgvector, Elasticsearch, etc.) return scores on different scales or raw metrics, `EngineAwareNormalizer` maps raw vector scores into a standard `[0, 1]` scale [internal/application/service/retriever/normalizer.go10-141](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/retriever/normalizer.go#L10-L141) Keyword scores (BM25) bypass normalization and are handled via rank-based RRF fusion [internal/application/service/retriever/normalizer.go15-18](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/retriever/normalizer.go#L15-L18)
