  This page provides a technical reference for the APIs that manage AI models, tenant-specific configurations (agents, conversations, parsers, storage), and system information in WeKnora. These APIs are critical for administrators and advanced users to configure and operate the underlying AI services that power the Retrieval-Augmented Generation (RAG) and Agentic features.

 
---

 
## System Information and Engine Discovery

 The system-level APIs surface metadata about the current deployment, including version info, runtime engine states, and backend service availability such as vector stores, parsers, and graph databases.

 
### Implementation and Data Flow

 The `SystemHandler` aggregates system state from multiple sources:

 
 - Static configuration (`config.Config`)
 - Database migration versioning info
 - Environment variables for features and driver selection
 
 It provides this as a unified JSON response to clients, enabling frontend components to adapt dynamically.

## Model Management API

 WeKnora supports managing diverse AI models in a multi-tenant context. Models are defined by type, source, configuration parameters, and operational status.

 
### Model Lifecycle and UI Association

 Models are categorized by type:

 
 - `chat` (LLM for conversation)
 - `embedding` (vector embedding models)
 - `rerank` (reranking models)
 - `vlm` (vision-language models)
 - `asr` (automatic speech recognition)
 
 The frontend UI uses these types to filter, list, and present model cards in settings panels.

### Key Implementation Details

 
 - **Request Validation and SSRF Protection:** Incoming model creation requests validate URLs (`BaseURL`) against SSRF attacks via `secutils.ValidateURLForSSRF` [internal/handler/model.go88-94](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/model.go#L88-L94)

## Engine Configuration APIs

 WeKnora provides APIs to manage several specialized engine configurations: vector databases, storage backends, document parsers, and MCP tool services.

 
### Vector and Storage Engines

 
 - Storage backends support multiple providers such as `local`, `minio`, `cos`, `tos`, `s3`, `oss`, `ks3`, and `obs`.
 - Knowledge bases specify storage backend through `storage_backend_id`, influencing document upload and content image hosting [internal/handler/initialization.go129-130](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L129-L130)
 
 
### Document Parsing Engines

 
 - Multiple parser engines are supported, including the built-in Go parser and remote engines like MinerU and PaddleOCR-VL.
 - APIs to list available parser engines, test parser credentials, and update tenant parser configs are exposed.
 
 
### MCP Tool Services

 
 - MCP (Model Context Protocol) services are managed via dedicated APIs.
 - Service URLs are SSRF-validated on creation [internal/handler/mcp_service.go70-76](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/mcp_service.go#L70-L76)
 - OAuth-blocked MCP calls expose a resolution endpoint to help end-users authorize and un-block tooling usage [docs/docs.go89-148](https://github.com/Tencent/WeKnora/blob/10973ed3/docs/docs.go#L89-L148)

## Tenant Configuration APIs

 Tenant-scoped settings are stored in generic key-value stores and specialized initialization endpoints.

 
### Knowledge Base Configuration

 
 - The `InitializationHandler` provides a dedicated endpoint to update KB model IDs, document splitting rules, multimodal flags, and graph extraction settings using the `KBModelConfigRequest` structure [internal/handler/initialization.go97-148](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L97-L148)
 - Multimodal configuration toggles multimodal processing per knowledge base [internal/handler/initialization.go124-128](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/initialization.go#L124-L128)
 
 
### Tenant Generic K/V Store

 
 - The `TenantHandler` exposes CRUD endpoints for generic tenant-level configuration keys.
 - Supported keys include `prompt-templates`, `web-search-config`, `parser-engine-config`, `storage-engine-config`, and `retrieval-config` [internal/handler/tenant.go400-440](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/tenant.go#L400-L440)
