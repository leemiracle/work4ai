## Purpose and Scope

 This document explains WeKnora's FAQ (Frequently Asked Questions) management system, which provides specialized handling for question-answer pairs within knowledge bases of type `faq`. FAQ Management enables creation, storage, retrieval, and maintenance of structured Q&A entries with hybrid indexing strategies optimized for precise question matching.

 **Key capabilities covered:**

 
 - FAQ data model and storage architecture (`FAQEntry`, `FAQChunkMetadata`) [internal/types/faq.go17-25](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/faq.go#L17-L25)
 - Single and batch FAQ entry CRUD operations via `FAQHandler` [internal/handler/faq.go24-38](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/faq.go#L24-L38)
 - Async batch import with progress tracking and validation [internal/handler/faq.go145-184](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/faq.go#L145-L184)

## FAQ Data Model and Storage Architecture

 
### FAQ as Specialized Chunks

 FAQ entries are stored as specialized `Chunk` entities with `chunk_type = "faq"`. Unlike document chunks which represent text segments, FAQ chunks encapsulate complete question-answer pairs with rich metadata stored in a JSON column.

### FAQChunkMetadata Structure

 The `FAQChunkMetadata` structure defines the schema for FAQ data stored in `Chunk.Metadata` [internal/types/faq.go17-25](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/faq.go#L17-L25):

 
| Field | Type | Description |
|---|---|---|
| standard_question | string | Primary canonical question text |
| similar_questions | []string | Question variations and paraphrases |
| negative_questions | []string | Anti-examples (what this FAQ is NOT about) |
| answers | []string | One or more answer texts |
| answer_strategy | AnswerStrategy | Strategy: all (return all) or random (return one) |

 **Content Hash Calculation:**

 WeKnora computes a deterministic SHA256 hash from normalized FAQ metadata via `CalculateFAQContentHash` to enable duplicate detection [internal/types/faq.go208-236](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/faq.go#L208-L236) The normalization process includes `NormalizeQuestion` (cleaning whitespace, traditional-to-simplified conversion) and sorting arrays to ensure identical content produces the same hash [internal/types/faq.go131-144](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/faq.go#L131-L144) [internal/types/faq.go184-206](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/faq.go#L184-L206)

## Batch Import and Export

 
### Async Batch Upsert

 Batch operations are processed asynchronously via the `UpsertEntries` handler method [internal/handler/faq.go145-184](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/faq.go#L145-L184)

 
 - **Append:** Adds new entries while skipping duplicates based on `content_hash`.
 - **Replace:** Clears existing FAQ entries before importing the new batch.
 
 **Implementation Detail:** The service handles imports in batches of 50 entries (`faqImportBatchSize`) [internal/application/service/knowledge.go87-91](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge.go#L87-L91) Progress tracking utilizes Redis or in-memory maps (`memFAQProgress`) in Lite mode [internal/application/service/knowledge.go73-78](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/knowledge.go#L73-L78) The `FAQBatchUpsertPayload` defines the request structure for batch operations, including a `DryRun` option for validation without actual import [client/faq.go54-61](https://github.com/Tencent/WeKnora/blob/10973ed3/client/faq.go#L54-L61)
