## Purpose and Scope

 This page details the configuration and architecture of WeKnora's document processing subsystem. It covers parser engine configuration, the Python-based `DocReader` gRPC service setup, `MinerU` integration for advanced PDF/document parsing, web page scraping via `StdWebParser`, image resolution and storage handling, and file type rule management across system, tenant, and knowledge base levels.

## Configuration Overview

 Document processing configuration spans three distinct hierarchical layers in WeKnora:

 
 - **System Level** — Global environment variables controlling service ports, concurrency limits, file size caps (`MAX_FILE_SIZE_MB`), and storage endpoints [frontend/src/utils/index.ts23-26](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/utils/index.ts#L23-L26)
 - **Tenant Level** — Tenant-specific overrides such as `mineru_endpoint` and parser engine preference maps [docreader/parser/registry.py116-145](https://github.com/Tencent/WeKnora/blob/10973ed3/docreader/parser/registry.py#L116-L145)
 - **Knowledge Base Level** — Knowledge base configurations (`ParserEngineRule`) dictating parser assignments and options (e.g., `xlsx_first_row_as_header`) per file extension group [frontend/src/views/knowledge/settings/KBParserSettings.vue85-118](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/settings/KBParserSettings.vue#L85-L118)
 
 
### Core Processing Components and Configuration

 
| Component | Purpose | Code Entity / Config Source |
|---|---|---|

## Parser Engine Configuration

 WeKnora supports a dynamic registry (`ParserEngineRegistry`) that maps file extensions to parser classes [docreader/parser/registry.py35-42](https://github.com/Tencent/WeKnora/blob/10973ed3/docreader/parser/registry.py#L35-L42) When a requested engine does not support a specific file type, the registry falls back to type-level defaults (e.g., routing `.ppt`, `.pptx`, and `.csv` to `markitdown`) and finally to `builtin` [docreader/parser/registry.py25-115](https://github.com/Tencent/WeKnora/blob/10973ed3/docreader/parser/registry.py#L25-L115)

 
### Engine Registration and Fallback Logic

 
 - **Registration (`register`)**: Registers engine identifiers, supported file extension mappings, descriptions, and availability checks [docreader/parser/registry.py49-66](https://github.com/Tencent/WeKnora/blob/10973ed3/docreader/parser/registry.py#L49-L66)
 - **Resolution (`get_parser_class`)**: Resolves the appropriate `BaseParser` implementation [docreader/parser/registry.py68-115](https://github.com/Tencent/WeKnora/blob/10973ed3/docreader/parser/registry.py#L68-L115) If an engine lacks support for an extension, it checks `_DEFAULT_ENGINE_BY_TYPE` before returning an actionable error [docreader/parser/registry.py89-114](https://github.com/Tencent/WeKnora/blob/10973ed3/docreader/parser/registry.py#L89-L114)

## MinerU Integration

 The `MinerUReader` client connects WeKnora to a self-hosted MinerU conversion service for high-precision document parsing (`pipeline`, `vlm-*`, `hybrid-*` backends) [internal/infrastructure/docparser/mineru_converter.go33-61](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/docparser/mineru_converter.go#L33-L61)

 
### MinerU Configuration Parameters

 
 - `mineru_endpoint`: Target URL for the MinerU API server [internal/infrastructure/docparser/mineru_converter.go52](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/docparser/mineru_converter.go#L52-L52)
 - `mineru_model`: Backend model selector (default `pipeline`) [internal/infrastructure/docparser/mineru_converter.go53](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/docparser/mineru_converter.go#L53-L53)
 - `mineru_enable_formula`: Boolean toggle for mathematical formula parsing [internal/infrastructure/docparser/mineru_converter.go55](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/docparser/mineru_converter.go#L55-L55)
 - `mineru_enable_table`: Boolean toggle for table structure recognition [internal/infrastructure/docparser/mineru_converter.go56](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/docparser/mineru_converter.go#L56-L56)

## Image Resolution and Storage Handling

 The `ImageResolver` component scans parsed markdown content for image references, data URIs, and base64 content, filters out icons, and persists them via `interfaces.FileService` [internal/infrastructure/docparser/image_resolver.go67-145](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/docparser/image_resolver.go#L67-L145)

 
### Image Resolution Pipeline

 
 - **Icon Filtering**: `isIconImage` inspects dimensions and byte size (skipping images below `minImageDimension` = 64px or `minImageBytes` = 512 bytes) [internal/infrastructure/docparser/image_resolver.go34-56](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/docparser/image_resolver.go#L34-L56)
 - **Deduplication**: Caches saved references by filename (`__filename__:` key) to prevent duplicate object storage writes [internal/infrastructure/docparser/image_resolver.go177-191](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/docparser/image_resolver.go#L177-L191)
 - **URL Replacement**: Replaces markdown image paths with stable serving URLs (`provider://...`) [internal/infrastructure/docparser/image_resolver.go78-144](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/docparser/image_resolver.go#L78-L144)
