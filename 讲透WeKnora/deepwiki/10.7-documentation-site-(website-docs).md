  The WeKnora documentation site, housed within the `website-docs/` directory, provides comprehensive technical documentation covering architecture, getting started guides, API references, client integration, and development workflows. It is engineered using [VitePress](https://vitepress.vuejs.org/), leveraging Vue 3 for reactive theme components and static site generation.

 
---

 
## 1. Documentation Site Structure and Configuration

 The documentation workspace follows a structured hierarchy where content is partitioned into domain-specific directories containing Markdown (`.md`) files. The build behavior, sidebar generation rules, and site metadata are governed by `.vitepress/config.mts`.

 
 - `website-docs/` — Root container for all documentation Markdown sources and VitePress configuration.
 - `website-docs/index.md` — VitePress landing page entry point.
 - `website-docs/01-getting-started/`, `website-docs/02-architecture/`, `website-docs/03-features/`, `website-docs/04-api/`, `website-docs/05-clients/`, `website-docs/06-development/` — Section directories containing numbered Markdown modules.
 - `website-docs/.vitepress/config.mts` — Core site configuration defining navigation bars, automatic sidebar traversal, markdown extensions, and theme properties.
 
 Sidebar navigation is dynamically assembled by scanning section directories and extracting first-level headers (`#`) to populate menu hierarchies without manual index maintenance.

## 2. Theme Components and Customizations

 WeKnora overrides default VitePress styling and layout behaviors to deliver a customized technical reading experience.

 
 - `.vitepress/theme/index.ts` — Entry point extending the default VitePress theme runtime.
 - `.vitepress/theme/style.css` — Global styling overrides, typography rules, and dark/light mode color bindings.
 - `.vitepress/theme/Landing.vue` — Single File Component rendering the custom homepage with data bindings for product statistics, ingestion pipelines, and architecture surfaces.
 
 The theme integrates `vitepress-plugin-mermaid` to parse fenced markdown code blocks into native client-side Mermaid diagrams. Local search capabilities utilize a customized tokenizer tailored for bilingual technical terminology.

## 3. Build and Deployment Pipeline

 The documentation site compiles static assets into an optimized distribution bundle (`.vitepress/dist`) via Node.js scripts. Containerized deployment is orchestrated through a dedicated multi-stage Dockerfile and NGINX configuration.

 
 - `website-docs/Dockerfile` — Multi-stage build container using a Node.js builder stage to execute static compilation, followed by an NGINX production runtime stage.
 - `website-docs/nginx.conf` — Server block configuration defining port bindings, gzip compression rules, asset caching headers, and route redirects.
 - `website-docs/docker-entrypoint.sh` — Initialization wrapper executing environment substitutions and launching the NGINX daemon in the foreground.

## 4. Content Authoring and Extension Workflow

 Adding or updating documentation pages follows a strict convention to preserve sidebar ordering and rendering fidelity:

 
 - **File Placement**: Create or modify Markdown files within the corresponding category folder under `website-docs/`, ensuring numerical filename prefixes (`01-introduction.md`, `02-installation.md`) dictate lexical ordering.
 - **Heading Conventions**: Define a primary `# Heading` at the top of each file, which is automatically extracted as the sidebar navigation label.
