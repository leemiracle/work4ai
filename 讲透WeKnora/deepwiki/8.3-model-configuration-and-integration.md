## Purpose and Scope

 This document specifies the technical architecture and implementation details for configuring and integrating various machine learning models within WeKnora. It covers chat/LLM, embedding, vision-language (VLM), rerank, and automatic speech recognition (ASR) models across multiple cloud providers and local runtimes (such as Ollama). Additionally, it details the provider registry pattern, built-in model YAML declarations, tenant-level credential security, and the asynchronous lifecycle management of local models.

 
---

 
## Model Types and Architecture

 WeKnora supports five primary model categories, each corresponding to an architectural abstraction within the backend model subsystem. These are typed via `ModelType` string constants [internal/types/model.go14-23](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/model.go#L14-L23).

 
| Model Type | Identifier | Primary Use Case | Core Interface / Implementation Package |
|---|---|---|---|
| Chat/LLM | KnowledgeQA | Text Generation & Reasoning | chat.Chat (internal/models/chat) |
| Embedding | Embedding | Vector Generation | embedding.Embedder (internal/models/embedding) |
| Rerank | Rerank | Result Reordering | rerank.Reranker (internal/models/rerank) |
| VLM | VLLM | Image Understanding | vlm.VLM (internal/models/vlm) |
| ASR | ASR | Speech-to-Text transcription | asr.ASR (internal/models/asr) |

 Models are further distinguished by their execution source (`types.ModelSource`), which dictates whether their lifecycle involves local downloading or remote API communication [internal/types/model.go91-114](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/model.go#L91-L114).

## Provider Integration Framework and Registry

 WeKnora implements a centralized provider registry in `internal/models/provider` to abstract multi-vendor API discrepancies [internal/models/provider/provider.go1-169](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/provider/provider.go#L1-L169).

 
### Provider Detection and Resolution

 When a user provides a `BaseURL` without explicitly selecting a provider, `provider.DetectProvider()` inspects the URL substring or domain to resolve the matching `ProviderName` [internal/models/provider/provider.go224-243](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/provider/provider.go#L224-L243).

## Model Implementations

 
### Chat and LLM Integration

 Chat models implement the `chat.Chat` interface [internal/models/chat/chat.go113-125](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/chat/chat.go#L113-L125). The `RemoteAPIChat` struct handles OpenAI-compatible endpoints, custom HTTP headers, proxy routing, and reasoning strategies [internal/models/chat/remote_api.go23-39](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/chat/remote_api.go#L23-L39).

 For local execution, `OllamaChat` converts messages into Ollama-native structures and communicates via `ollama.OllamaService` [internal/models/chat/ollama.go19-32](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/chat/ollama.go#L19-L32). Special reasoning models (e.g., DeepSeek thinking mode or Qwen3) have their reasoning tokens mapped to `ReasoningContent` fields [internal/types/chat.go87-91](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/chat.go#L87-L91).

 
### Embedding Model Integration

 Embedding models implement the `embedding.Embedder` interface [internal/models/embedding/embedder.go15-33](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/embedding/embedder.go#L15-L33).

 
 - `OpenAIEmbedder` provides batch vectorization with exponential backoff retries via `doRequestWithRetry()` and token truncation support [internal/models/embedding/openai.go16-161](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/embedding/openai.go#L16-L161).
 - Aliyun and Volcengine adapters differentiate between text-only and multimodal vision embedding endpoints [internal/models/embedding/embedder.go127-181](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/embedding/embedder.go#L127-L181).
 
 
### Rerank Model Integration

 Rerank models implement the `rerank.Reranker` interface [internal/models/rerank/reranker.go13-23](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/rerank/reranker.go#L13-L23). The `NewReranker` factory delegates to specialized providers like Aliyun, Zhipu, Jina, Nvidia, or OpenAI-compatible backends [internal/models/rerank/reranker.go133-169](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/rerank/reranker.go#L133-L169).

 
### Vision Language Model (VLM) and ASR Integration

 
 - `RemoteAPIVLM` encapsulates OpenAI-compatible VLM endpoints supporting image base64 encoding and Mime-type detection [internal/models/vlm/remote_api.go41-107](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/vlm/remote_api.go#L41-L107). It automatically shapes requests for reasoning-capable vision models by migrating `max_tokens` to `max_completion_tokens` [internal/models/vlm/remote_api.go190-202](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/vlm/remote_api.go#L190-L202).
 - ASR configurations manage audio-to-text transcription parameters across knowledge base document ingestion pipelines.

## Built-In Model Declarations and YAML Sync

 WeKnora supports provisioning preconfigured models via declarative YAML files (`builtin_models.yaml`).

 
 - The system synchronizes the database `models` table with YAML specifications upon startup.
 - Built-in models are assigned to a reserved system tenant ID (`10000`) with `managed_by: "yaml"` [internal/types/builtin_models_config.go95-108](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/builtin_models_config.go#L95-L108).
 - Environment variable interpolation (e.g., `${OPENAI_API_KEY}`) is supported for sensitive parameters within the YAML definitions [internal/types/builtin_models_config.go56-64](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/builtin_models_config.go#L56-L64).
 - If an admin modifies a built-in model via the user interface, its YAML-managed flag is cleared to prevent subsequent reloads from overwriting custom edits [internal/types/builtin_models_config.go138-150](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/builtin_models_config.go#L138-L150).

## Security, Credentials, and Configuration Schema

 
 - **AES Encryption:** Sensitive parameters such as `AppSecret` are encrypted using AES-GCM before database persistence and decrypted at runtime via `utils.DecryptAESGCM()` [internal/application/service/model.go54-64](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/model.go#L54-L64).
 - **Credential Fallback:** For WeKnoraCloud models, missing credentials automatically fall back to tenant workspace settings configured in the initialization wizard [internal/application/service/model.go66-93](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/model.go#L66-L93).
 - **Custom Headers:** The `CustomHeaders` map in `ModelParameters` allows injecting custom HTTP headers (such as enterprise gateway keys) into all outbound model requests [internal/types/model.go130-136](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/model.go#L130-L136).
