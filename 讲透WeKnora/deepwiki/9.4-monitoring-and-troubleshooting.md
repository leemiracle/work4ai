## Pipeline Span Tracking

 WeKnora implements an internal "Span Tracker" system that provides granular visibility into the document ingestion pipeline. This system allows operators to see exactly which stage of a multi-step ingestion process failed.

 
### Implementation and Data Flow

 
 - **Attempt Management**: Each re-parse of a document increments an `attempt` number to isolate historical failures, tracked persistently.
 - **Stage Lifecycle**: Uses well-defined stages like `StageDocReader`, `StageChunking`, `StageMultimodal`, and `StageEmbedding`, each wrapped within spans to indicate start/end of each pipeline stage.
 - **Sub-Span Tracking**: Parallel tasks such as multimodal image processing (`ImageMultimodalService`) spawn child spans for each image chunk, recording their results and errors [internal/application/service/image_multimodal.go62-134](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/image_multimodal.go#L62-L134)
 - **Tracing Metadata**: Sub-spans capture detailed data for VLM results including model IDs, byte counts, OCR preview snippets, enabling detailed trace inspection.
 
 The pipeline stage results are stored in a tree structure keyed by the Knowledge ID and attempt number. This approach helps isolate failures and provides a clear progress remote to operators.

## Agent and LLM Observability with Langfuse

 WeKnora integrates with **Langfuse** to provide deep visibility into agent reasoning loops, LLM generation, and tool call token costs. This enables developers and operators to understand internal agent behavior and optimize usage.

 
### Chat and Generation Tracing

 The `langfuseChat` wrapper wraps the standard `Chat` interface and automatically triggers Langfuse "generation" spans on each invocation. This starts when the client calls `Chat` or `ChatStream` and ends on completion or error.

 Key features include:

 
 - Recording input, output, and cached token usage with conversion to Langfuse's `TokenUsage` structures.
 - Handling special reasoning (think) tokens to provide richer trace content for intermediate steps.
 - Reporting errors or cancellations precisely as part of the generation lifecycle.
 
 
### Agent Tool Call Tracing

 During ReAct agent execution, each tool call creates a separate Langfuse span:

 
 - The function `buildToolSpanInput` shapes the payload which includes `model_arguments` (raw LLM output) and `resolved_arguments` (after dereferencing any handle-type inputs). This allows stack traces of calls and data transformations.
 - Tools flagged as sensitive (such as `database_query`) have raw arguments redacted but keys preserved to facilitate debugging without leaking secrets.
 - Tool outputs are truncated to a maximum preview size (4000 runes) to keep trace payloads manageable while preserving meaningful data.

## Logging and Log Analysis

 WeKnora uses a custom Logrus logger (`appLogger`) to produce colorized console logs and clean plain-text file logs [internal/logger/logger.go23-28](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/logger/logger.go#L23-L28) This logger supports flexible templating, context-aware fields, and trace ID propagation.

 
### Configuration Variables

 
 - `LOG_LEVEL`: Controls verbosity (`debug`, `info`, `warn`, `error`, `fatal`) [internal/logger/logger.go42-52](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/logger/logger.go#L42-L52)
 - `LOG_FORMAT`: Custom template string controlling log line format, supporting placeholders like `%d` (timestamp), `%level`, `%thread` (goroutine id), `%logger` (callsite), `%traceId`, and `%msg` [internal/logger/logger.go68-75](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/logger/logger.go#L68-L75)
 - `LOG_PATH`: If set, logs also persist to a file with automatic rotation using `lumberjack` [internal/logger/logger.go251-260](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/logger/logger.go#L251-L260)
 
 
### Custom Formatter Implementation

 The `CustomFormatter` implements safe and performant formatting strategies:

 
 - Utilizes `strings.NewReplacer` for single-pass placeholder substitution, preventing cascading replacements that corrupt output [internal/logger/logger.go136-144](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/logger/logger.go#L136-L144)
 - Efficiently extracts goroutine ID only if `%thread` is present in the template to reduce runtime overhead via `getGoroutineID()` [internal/logger/logger.go122-125](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/logger/logger.go#L122-L125) [internal/logger/logger.go211-228](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/logger/logger.go#L211-L228)
 - Colorizes the log level and parts of the output when enabled for terminal output [internal/logger/logger.go129-133](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/logger/logger.go#L129-L133)
 - Writes logs to stdout with ANSI colors, while stripping ANSI sequences from logs written to files using `ansiStripWriter` [internal/logger/logger.go33-40](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/logger/logger.go#L33-L40) [internal/logger/logger.go250-263](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/logger/logger.go#L250-L263)

## Runtime Queue Inspection and Troubleshooting

 WeKnora leverages the Asynq task queue system backed by Redis for asynchronous background processing of documents, images, and enrichment tasks.

 
### Task Inspection Interface

 
 - The `TaskInspector` interface exposes operations to cancel tasks by knowledge ID, check for queued tasks, and retrieve queue statistics [internal/handler/system.go52-56](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/system.go#L52-L56)
 - The `asynqTaskInspector` implementation scans relevant queues (`document`, `image_multimodal`, `post_process`, etc.) via `queuesScanned` to manage tasks related to knowledge processing [internal/router/task_inspector.go30-81](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/task_inspector.go#L30-L81)
 - Cancellation operations remove pending tasks referencing a knowledge ID and signal active workers to gracefully stop through `CancelTasksForKnowledge` [internal/router/task_inspector.go109-124](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/task_inspector.go#L109-L124)
 - Queue stats include counts of active, pending, retry, and archived tasks per task pool to inform monitoring dashboards.
 
 
### Frontend Runtime Queues View

 The Vue.js component `RuntimeQueues.vue` presents:

 
 - An overview with counts of active, pending, retrying, and failed tasks [frontend/src/views/system/RuntimeQueues.vue80-97](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/system/RuntimeQueues.vue#L80-L97)
 - Pools breakdown showing concurrency, active workers, instance count, utilization, and queue depth [frontend/src/views/system/RuntimeQueues.vue108-128](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/system/RuntimeQueues.vue#L108-L128)

## Troubleshooting Common Issues

 
### Agent and Pipeline Failures

 
 - Transient errors like HTTP 429/503 or timeouts trigger automatic retries to improve reliability [internal/logger/logger.go47-50](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/logger/logger.go#L47-L50)
 - The engine retries on empty LLM outputs to avoid premature termination of reasoning loops.
 - Detection of repeated identical LLM responses triggers forced loop termination to prevent infinite cycles without progress.
 
 
### Debugging Steps

 
 - **Enable Debug Logs**: Set `LOG_LEVEL=debug` to reveal raw prompts, API calls, and tool execution details [internal/logger/logger.go47](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/logger/logger.go#L47-L47)
 - **Inspect Langfuse Tracing**: Check tool spans for `error` fields and success indicators. `finishToolSpan` explicitly reports success or failure in Langfuse [internal/models/chat/langfuse_wrapper.go11-55](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/models/chat/langfuse_wrapper.go#L11-L55)
 - **Queue Inspection**: Verify background queue backlogs and worker pool availability using `RuntimeQueues.vue` [frontend/src/views/system/RuntimeQueues.vue80-128](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/system/RuntimeQueues.vue#L80-L128) and `asynqTaskInspector` [internal/router/task_inspector.go30-43](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/router/task_inspector.go#L30-L43)
