  This page details WeKnora's chunk management and vector indexing subsystem, which transforms raw document content into structurally sound, vectorized chunks stored and indexed across multiple retrieval engines (PostgreSQL/pgvector, Qdrant, Elasticsearch v7/v8, and others). It covers adaptive chunking strategies (parent-child, heading-based, heuristic, and recursive), chunk metadata invariants, vector generation with backoff handling, and indexing engine repositories.

 **Scope**: This page focuses on chunk splitting, adaptive strategies, data models, embedding pipelines, and storage engine repositories. For document upload and parser selection, see [4.2 Document Upload and Processing](https://github.com/Tencent/WeKnora/blob/10973ed3/4.2 Document Upload and Processing); for FAQ-specific processing, see [4.3 FAQ Management](https://github.com/Tencent/WeKnora/blob/10973ed3/4.3 FAQ Management)

## 2. Adaptive Chunking Strategies and Sizing

 WeKnora implements an adaptive chunking system managed by `SplitterConfig` and resolved through strategy tiers in `internal/infrastructure/chunker/strategy.go` [internal/infrastructure/chunker/splitter.go59-74](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/chunker/splitter.go#L59-L74) [internal/infrastructure/chunker/strategy.go34-58](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/chunker/strategy.go#L34-L58)

 
### Default Sizing Constants

 
 - `DefaultChunkSize = 512` characters (approx. 100-130 English tokens, ~300 Chinese tokens) [internal/infrastructure/chunker/splitter.go102-104](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/chunker/splitter.go#L102-L104)
 - `DefaultChunkOverlap = 80` characters (approx. 15% of chunk size) [internal/infrastructure/chunker/splitter.go104](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/chunker/splitter.go#L104-L104)
 
 
### Strategy Tiers

 
 - **`StrategyHeading` (`heading`)**: Splits Markdown documents at heading boundaries (`#`, `##`, etc.) and manages breadcrumbs via `internal/infrastructure/chunker/heading_splitter.go` [internal/infrastructure/chunker/strategy.go18-24](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/chunker/strategy.go#L18-L24)
 - **`StrategyHeuristic` (`heuristic`)**: Scans for structural markers (form feeds, chapter headers, bullet lists) while protecting atomic content blocks (LaTeX blocks, code fences, inline code, table rows) using `protectedSpansRune` [internal/infrastructure/chunker/splitter.go116-126](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/chunker/splitter.go#L116-L126) [internal/infrastructure/chunker/heuristic_splitter.go1-54](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/chunker/heuristic_splitter.go#L1-L54)
 - **`StrategyRecursive` / `StrategyLegacy` (`legacy`)**: Iteratively splits text using prioritized separators (`\n\n`, `\n`, `。`) [internal/infrastructure/chunker/splitter.go112-114](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/chunker/splitter.go#L112-L114)
 - **Parent-Child Chunking**: `SplitParentChild` splits documents into large parent chunks (broad context) and sub-divides them into smaller child chunks linked to the parent index [internal/infrastructure/chunker/strategy.go135-186](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/infrastructure/chunker/strategy.go#L135-L186) The frontend configuration allows tuning these parameters interactively (`frontend/src/views/knowledge/settings/KBChunkingSettings.vue`) [frontend/src/views/knowledge/settings/KBChunkingSettings.vue106-162](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/settings/KBChunkingSettings.vue#L106-L162)

## 3. Vector Generation and Hybrid Indexing

 Once chunks are split, text content undergoes sanitization and batch embedding before being stored in retrieval engine backends via `KeywordsVectorHybridRetrieveEngineService` [internal/application/service/retriever/keywords_vector_hybrid_indexer.go43-84](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/retriever/keywords_vector_hybrid_indexer.go#L43-L84)

 
### Sanitization and Batch Embedding with Backoff

 
 - **`sanitizeForEmbedding`**: Scrubs inline base64 image data payloads from text and enforces an absolute safety limit (`safetyMaxChars = 20000`) to prevent pathological inputs from overflowing embedding APIs [internal/application/service/retriever/keywords_vector_hybrid_indexer.go20-40](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/retriever/keywords_vector_hybrid_indexer.go#L20-L40) [internal/application/service/retriever/keywords_vector_hybrid_indexer.go160-176](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/retriever/keywords_vector_hybrid_indexer.go#L160-L176)
 - **`batchEmbedWithBackoff`**: Implements exponential backoff (`embedRetryAttempts = 5`, base delay 200ms) when calling `BatchEmbedWithPool` on external embedder models [internal/application/service/retriever/keywords_vector_hybrid_indexer.go27-32](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/retriever/keywords_vector_hybrid_indexer.go#L27-L32) [internal/application/service/retriever/keywords_vector_hybrid_indexer.go132-154](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/retriever/keywords_vector_hybrid_indexer.go#L132-L154)

## 4. Retrieval Engine Repositories

 WeKnora abstracts vector storage across multiple database and search engines through the `interfaces.RetrieveEngineRepository` interface [internal/application/repository/retriever/qdrant/repository.go34-49](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/qdrant/repository.go#L34-L49) [internal/application/repository/retriever/elasticsearch/v7/repository.go35-58](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/elasticsearch/v7/repository.go#L35-L58) [internal/application/repository/retriever/elasticsearch/v8/repository.go32-55](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/elasticsearch/v8/repository.go#L32-L55) [internal/application/repository/retriever/postgres/repository.go24-28](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/postgres/repository.go#L24-L28)

 
 - **Qdrant**: Manages dimension-specific collections (`weknora_embeddings_{dimension}`), payload indexes for filtering (`chunk_id`, `knowledge_id`, `knowledge_base_id`), and multilingual text indexes [internal/application/repository/retriever/qdrant/repository.go34-135](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/qdrant/repository.go#L34-L135)
 - **Elasticsearch (v7 & v8)**: Automatically detects field types (`keyword` vs `text` with `.keyword` suffixes) and indexes chunks for hybrid vector-keyword retrieval [internal/application/repository/retriever/elasticsearch/v7/repository.go69-127](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/elasticsearch/v7/repository.go#L69-L127) [internal/application/repository/retriever/elasticsearch/v8/repository.go68-104](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/retriever/elasticsearch/v8/repository.go#L68-L104)
