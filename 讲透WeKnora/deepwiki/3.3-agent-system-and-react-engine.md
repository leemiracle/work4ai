## Purpose and Scope

 This document explains WeKnora's Agent System and its implementation of the ReAct (Reasoning + Acting) pattern for intelligent question answering. The agent system enables multi-step reasoning, tool usage, and iterative refinement to provide comprehensive answers across knowledge bases, databases, and external APIs.

 For information about the normal RAG pipeline without agents, see [RAG Pipeline Architecture](https://deepwiki.com/Tencent/WeKnora/3.2-rag-pipeline-architecture). For tool-specific integrations including MCP (Model Context Protocol) servers, see [MCP Tool Integration](https://deepwiki.com/Tencent/WeKnora/5.5-mcp-tool-integration). For the chat interface that displays agent reasoning, see [Chat Interface and Agent Display](https://deepwiki.com/Tencent/WeKnora/7.3-chat-interface-and-agent-display).

## Overview

 
### ReAct Pattern

 WeKnora implements the ReAct (Reasoning + Acting) pattern, which alternates between:

 
 - **Reasoning**: The LLM thinks about what to do next, generating reasoning tokens or reasoning blocks (`AgentEngine.systemPromptOptions`, `streamLLMResult`) [internal/agent/engine.go128-154](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/engine.go#L128-L154), [internal/agent/think.go20-28](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/think.go#L20-L28).
 - **Acting**: The LLM selects and executes tools via the tool registry [internal/agent/tools/registry.go139-178](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/tools/registry.go#L139-L178).
 - **Observing**: The LLM processes tool results (observations) and determines the next step within a managed context window [internal/agent/observe.go39-67](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/observe.go#L39-L67).
 
 This iterative cycle continues until the agent produces a final answer or reaches `MAX_ITERATIONS` [internal/application/service/agent_service.go30](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/agent_service.go#L30-L30).

### Agent Execution Model

 The core execution logic resides in `AgentEngine` [internal/agent/engine.go35-64](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/engine.go#L35-L64). It manages conversation state, handles the iterative LLM loop, and coordinates tool execution. The engine is stateless across turns; conversation history is rebuilt from the database once per turn by the caller (`LoadAgentHistory`) and passed into execution context [internal/application/service/session_agent_qa.go142-157](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session_agent_qa.go#L142-L157).

#### `AgentEngine`

 The `AgentEngine` [internal/agent/engine.go35-64](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/engine.go#L35-L64) coordinates the execution loop. It relies on a `chat.Chat` model for inference, a `ToolRegistry` for action invocation, and a token estimator/compactor for window management [internal/agent/engine.go38-51](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/engine.go#L38-L51).

 The `ToolRegistry` [internal/agent/tools/registry.go16-22](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/tools/registry.go#L16-L22) registers tools, exposes schemas via `GetFunctionDefinitions`, and executes calls safely through argument parsing and validation.

 - `KnowledgeBases` / `KnowledgeIDs`: Retrieval scope boundaries [internal/types/agent.go111-112](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/agent.go#L111-L112).
 - `WebSearchEnabled`: Toggles web search capabilities [internal/types/agent.go119](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/agent.go#L119-L119).

## Context Management and Token Control

 To handle long contexts, `AgentEngine` manages token limits via `manageContextWindow` [internal/agent/observe.go39-44](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/observe.go#L39-L44):

 
 - **Threshold Check**: Evaluates token consumption against `MaxContextTokens` and reserved buffer limits [internal/agent/observe.go42-45](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/observe.go#L42-L45).
 - **Compaction**: Summarizes older turns using `runCompaction` [internal/agent/observe.go73-78](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/observe.go#L73-L78).
 - **Tool Result Trimming**: Drops or truncates oversized individual tool outputs if compaction leaves the session over budget [internal/agent/observe.go65-66](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/agent/observe.go#L65-L66).
