## Purpose and Scope

 This page documents the tag management system, folder hierarchies, document list and card views, batch operations, and tag-based filtering within WeKnora. It bridges the backend persistent storage layer (`internal/application/repository/tag.go` and `internal/application/service/tag.go`) with the frontend UI layout components (`KbFolderTree.vue`, `DocumentListView.vue`, and `DocumentCardView.vue`) [internal/application/repository/tag.go1-20](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/tag.go#L1-L20) [frontend/src/views/knowledge/components/DocumentListView.vue1-35](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/components/DocumentListView.vue#L1-L35) [frontend/src/views/knowledge/components/DocumentCardView.vue1-40](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/components/DocumentCardView.vue#L1-L40)

## 1. Tag Data Model and Persistence

 The tag subsystem revolves around the `KnowledgeTag` entity, which represents categories scoped to specific knowledge bases and tenants [internal/types/interfaces/tag.go10-15](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/tag.go#L10-L15) Each tag maintains a unique UUID `ID` for internal routing and an auto-incrementing integer `SeqID` for external APIs [internal/application/repository/tag.go33-66](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/tag.go#L33-L66)

 
### Extended Statistics (`KnowledgeTagWithStats`)

 To display usage indicators across documents and FAQ chunks without N+1 query penalties, tags are enriched with reference metrics via `BatchCountReferences()` [internal/application/service/tag.go107-128](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/tag.go#L107-L128)

## 3. Folder Trees and Document Organization

 Knowledge base folders are structured hierarchically using pure frontend helper utilities (`frontend/src/views/knowledge/folderTree.ts`) and rendered by `KbFolderTree.vue` [frontend/src/views/knowledge/components/DocumentListView.vue41-44](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/components/DocumentListView.vue#L41-L44)

 
### Core Folder Concepts

 
 - **Root Folder Path**: Represented by an empty string `ROOT_FOLDER_PATH = ''`, which points to the base level of the knowledge base [frontend/src/views/knowledge/components/DocumentListView.vue15-30](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/components/DocumentListView.vue#L15-L30)
 - **Tree Flattening**: The `buildFolderRows()` function transforms recursive folder nodes into a flat array based on an expanded set (`Set<string>`) to handle indentation and toggle states [frontend/src/views/knowledge/components/DocumentListView.vue32-58](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/views/knowledge/components/DocumentListView.vue#L32-L58)

## 5. Tag-Based Filtering and Retrieval Search

 The system distinguishes between **browsing** (viewing direct sub-folders and documents inside a specific folder) and **filtering/searching** (running a subtree search across all nested documents) using search parameters and repository filters [internal/application/repository/tag.go94-136](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/tag.go#L94-L136)

 When `tagIds` or keywords are supplied, repository queries extend constraints to fetch matching items recursively from the path subtree and join relation tables like `knowledge_tag_relations` [internal/application/repository/tag.go152-166](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/repository/tag.go#L152-L166)
