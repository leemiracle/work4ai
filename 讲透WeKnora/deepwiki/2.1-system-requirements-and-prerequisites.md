## Overview

 WeKnora is a modular LLM-powered knowledge framework primarily deployed through containerization. It offers flexible profiles from a minimal footprint for single users to a full enterprise-grade stack integrating distributed vector stores, graph databases, and observability tools.

 The architecture follows a microservices pattern separating:

 
 - Core backend services (`app`) [docker-compose.yml36-46](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L36-L46)
 - Frontend UI (`frontend`) [docker-compose.yml2-16](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L2-L16)
 - Document parsing engines (`docreader`) [.env.example94](https://github.com/Tencent/WeKnora/blob/10973ed3/.env.example#L94-L94)
 
 It supports complex multi-tenant RBAC, fine-grained storage quotas, and secure encryption mechanisms for sensitive credentials configured via environment variables and configuration files [internal/config/config.go19-42](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/config/config.go#L19-L42)

## Hardware Recommendations

 WeKnora's resource consumption depends on the number of users, scale of knowledge bases, and whether LLM inference runs locally.

 
### Resource Allocation Profiles

 
| Tier | RAM | CPU | Storage | Use Case Description | Reference |
|---|---|---|---|---|---|
| Minimal | 4 GB | 2 Cores | 20 GB | Single-user, basic RAG with cloud LLM | config/config.yaml1-5 |
| Standard | 8 GB | 4 Cores | 50 GB | Small teams, local parsing, hybrid retrieval | .env.example170-184 |
| Enterprise | 16+ GB | 8+ Cores | 100+ GB | Production, Wiki Mode at large scale | docker-compose.yml77-105 |
| Inference | 32+ GB | 12+ Cores | 200+ GB | Local LLM (Ollama) hosting with multimodal processing | internal/container/container.go137 |

 
### Hardware Notes

 
 - **Disk I/O**: Use fast SSDs for `postgres` and vector stores for optimal low-latency retrieval and task queue handling.
 - **Worker Pool Governance**: Asynq worker pools are configurable via environment variables (`WEKNORA_ASYNQ_CORE_CONCURRENCY`, `WEKNORA_ASYNQ_ENRICHMENT_CONCURRENCY`, etc.) to manage concurrency effectively [.env.example170-184](https://github.com/Tencent/WeKnora/blob/10973ed3/.env.example#L170-L184)
 - **Architecture**: Supports `amd64` and `arm64` with automatic architecture detection during builds via Docker multi-stage builds [docker-compose.yml8-13](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L8-L13)

## Advanced Feature Prerequisites

 
### Supported Vector and Graph Storage Backends

 WeKnora can bind knowledge bases to multiple vector databases for retrieval fan-out and also supports graph databases for Wiki mode. These are initialized via the `initRetrieveEngineRegistry` in the dependency injection container [internal/container/container.go130-132](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L130-L132)

 
| Component | Environment Variable / Setting | Usage | Reference |
|---|---|---|---|
| PostgreSQL (pgvector) | DB_DRIVER=postgres | Default vector and relational backend | .env.example127-138 |
| Apache Doris | RETRIEVE_DRIVER=doris | Stream-load and hybrid query backend | internal/types/retriever.go15 |
| Tencent VectorDB | RETRIEVE_DRIVER=tencent_vectordb | Enterprise vector search | internal/types/retriever.go17 |
| Neo4j | NEO4J_URI | Wiki Mode knowledge graph visualization | docker-compose.dev.yml206-213 |
| Qdrant | QDRANT_HOST | Vector database | docker-compose.dev.yml107-117 |
| Milvus | MILVUS_ADDRESS | Vector database | docker-compose.dev.yml177-187 |
| Weaviate | WEAVIATE_HOST | Vector database | go.mod71-72 |
| Elasticsearch | ELASTICSEARCH_ADDR | Vector database (v7/v8) | go.mod20-21 |
| SQLite (sqlite-vec) | DB_DRIVER=sqlite | Local vector storage | go.mod13 |

## Network and Port Requirements

 
 - **Default Ports**

 
 - Frontend UI: Port `80` (HTTP) or as configured via `FRONTEND_PORT` [docker-compose.yml15-16](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L15-L16)
 - Backend API Service (`app`): Port `8080` [docker-compose.yml45-46](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L45-L46)
 - DocReader gRPC Service: Port `50051` [.env.example94](https://github.com/Tencent/WeKnora/blob/10973ed3/.env.example#L94-L94)
 - MCP Server (optional): Port `8082` [.env.example118-119](https://github.com/Tencent/WeKnora/blob/10973ed3/.env.example#L118-L119)
 - **Container Networking**

 
 - All internal containers resolve each other by standardized service names within the Docker network [docker-compose.yml32-33](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L32-L33)
 - **Outbound Connectivity**

 
 - Access to LLM providers (OpenAI, Anthropic, DeepSeek, Zhipu, Ollama, etc.) over HTTPS [internal/container/container.go137](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L137-L137)
 - Web Search providers and object storage endpoints.
 - **Security Considerations**

 
 - **Redis TLS Support**: Encrypted connections to Redis are supported via `REDIS_USE_TLS` [.env.example163-167](https://github.com/Tencent/WeKnora/blob/10973ed3/.env.example#L163-L167)
 - **Credential Encryption**: Sensitive credentials at rest are protected via encryption configurations [docker-compose.yml120-143](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L120-L143)
