## Purpose and Scope

 This page provides comprehensive technical documentation for the REST and Server-Sent Events (SSE) HTTP endpoints responsible for managing conversation sessions, executing KnowledgeQA and AgentQA inference, searching direct knowledge, and handling media attachments in WeKnora. It details the underlying handler structures, request/response data models, streaming execution flows, and integration patterns.

 For pipeline architecture internals, see [5.2 Knowledge QA Mode](https://github.com/Tencent/WeKnora/blob/10973ed3/5.2 Knowledge QA Mode) and [5.3 Agent Mode and Tool Integration](https://github.com/Tencent/WeKnora/blob/10973ed3/5.3 Agent Mode and Tool Integration) For conversation history and state management, see [5.4 Session Management and Context](https://github.com/Tencent/WeKnora/blob/10973ed3/5.4 Session Management and Context) For authentication headers and token handling, see [6.1 Authentication and Authorization](https://github.com/Tencent/WeKnora/blob/10973ed3/6.1 Authentication and Authorization)

## Session Management Endpoints

 Sessions operate as decoupled containers for multi-turn conversations. Configuration parameters such as knowledge bases, model instances, and agent selection are resolved dynamically per query rather than bound permanently at session creation [internal/handler/session/types.go7-15](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/session/types.go#L7-L15)

 
### Visibility and Read Scoping

 Session queries execute through `loadSessionForRead`, which enforces per-user ownership rules while granting administrators access to tenant channel sessions (such as API keys, IM channels, and embedded chat widgets) [internal/application/service/session.go62-101](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/application/service/session.go#L62-L101) Mutation actions strictly invoke `GetOwnedSession` to protect system-managed sessions from administrative overwrite [internal/types/interfaces/session.go18-22](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/session.go#L18-L22)

## QA Endpoints and Streaming Execution

 Both `KnowledgeQA` (`POST /api/v1/knowledge-chat/{session_id}`) and `AgentQA` (`POST /api/v1/agent-chat/{session_id}`) stream responses via Server-Sent Events (SSE). The frontend UI utilizes `useStream` and `fetchEventSource` to process live payloads [frontend/src/api/chat/streame.ts1-61](https://github.com/Tencent/WeKnora/blob/10973ed3/frontend/src/api/chat/streame.ts#L1-L61)

 
### Request Parsing and Context Building

 When a QA request is received, `parseQARequest` initializes a `qaRequestContext` structure holding immutable pipeline states, attachment metadata, and tracking IDs [internal/handler/session/qa.go38-164](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/session/qa.go#L38-L164)

 
 - **Validation**: Validates path parameters and request bodies, rejecting empty queries [internal/handler/session/qa.go133-152](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/session/qa.go#L133-L152)
 - **Resource Rewriting**: Resolves stream rewriters for outbound storage asset URLs (`resource_urls=public`) [internal/handler/session/qa.go155-159](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/session/qa.go#L155-L159)
 - **Payload Construction**: Converts `qaRequestContext` into a `types.QARequest` via `buildQARequest()` for service execution [internal/handler/session/qa.go98-123](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/session/qa.go#L98-L123)

## SSE Event Stream Format and Agent Streaming

 Real-time streaming is managed by `AgentStreamHandler`, which subscribes to a request-scoped `event.EventBus` instance [internal/handler/session/agent_stream_handler.go32-69](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/session/agent_stream_handler.go#L32-L69)

 
### Answer Segments and Preamble Filtering

 To ensure that intermediate reasoning steps or search status preambles do not corrupt the persisted final assistant message when tools are invoked, `AgentStreamHandler` tracks text accumulation through `answerSegment` instances [internal/handler/session/agent_stream_handler.go76-103](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/session/agent_stream_handler.go#L76-L103)

## Direct Knowledge Search

## Generation Control and Metadata

 
### Session Title Generation

 Titles are generated via `GenerateTitleAsync`, which emits an `event.EventSessionTitle` event when text summary models finish evaluating the initial conversation turn [internal/types/interfaces/session.go55-58](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/interfaces/session.go#L55-L58)

 
### Multimodal and File Attachments

 `CreateKnowledgeQARequest` accepts multimodal image attachments (`ImageAttachment`) and structured document uploads (`AttachmentUploads`) [internal/handler/session/types.go59-61](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/session/types.go#L59-L61) Images are pre-processed by Vision-Language Models (VLM) via `extractImageURLsAndOCRText` prior to running the chat pipeline [internal/handler/session/helpers.go31-55](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/handler/session/helpers.go#L31-L55) File attachments are formatted into prompt contexts with security guardrails using `MessageAttachments.BuildPrompt()` [internal/types/message.go154-180](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/types/message.go#L154-L180)
