## Purpose and Scope

 This page provides a comprehensive technical reference for all environment variables consumed by the WeKnora backend (`app` service) and associated infrastructure components. These variables control database connectivity, file storage providers, retrieval engines, model service integrations, asynchronous worker pools, feature toggles, and observability systems.

 Environment variables act as the primary deployment-level configuration bridge between container orchestration platforms (e.g., Docker Compose) and the Go backend runtime, which is initialized via `internal/container/container.go` [internal/container/container.go112-142](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L112-L142) and mapped to configuration structs in `internal/config/config.go` [internal/config/config.go19-42](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/config/config.go#L19-L42)

 
---

 
## How Environment Variables Are Loaded and Used

 Environment variables are loaded into the application runtime through container configuration files such as `docker-compose.yml` (`env_file: .env`) [docker-compose.yml65-76](https://github.com/Tencent/WeKnora/blob/10973ed3/docker-compose.yml#L65-L76) At startup, the dependency injection container (`internal/container/container.go`) invokes setup functions like `config.LoadConfig`, `initDatabase()`, `initRedisClient()`, and `initFileService()` to bind these values into application services [internal/container/container.go121-125](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L121-L125)

## General Application and Runtime Variables

 These variables govern core application behavior, logging verbosity, internationalization, and administrative policies.

 
| Variable | Default | Description |
|---|---|---|
| GIN_MODE | release | Gin framework mode (release disables Swagger docs; debug enables detailed logs and Swagger) docker-compose.yml90 |
| LOG_LEVEL | debug | Logging verbosity (debug, info, warn, error, fatal) docker-compose.yml80 |
| LOG_PATH | (empty) | Target path for log files; if empty, logs are written exclusively to stdout docker-compose.yml82 |
| LLM_DEBUG_LOG | false | Enables detailed logging of LLM payloads into llm_debug.log docker-compose.yml86 |
| TZ | Asia/Shanghai | System timezone setting for log timestamps and runtime operations docker-compose.yml92 |
| WEKNORA_LANGUAGE | (empty) | Document processing fallback language, overriding Accept-Language headers docker-compose.yml95 |
| DISABLE_REGISTRATION | false | When set to true, disables user self-registration docker-compose.yml122 |
| AUTO_MIGRATE | true | Automatically performs database migrations upon application startup docker-compose.yml103 |

## Database Configuration Variables

 WeKnora connects to relational databases via GORM, supporting PostgreSQL, MySQL, and SQLite drivers.

 
| Variable | Default | Description |
|---|---|---|
| DB_DRIVER | postgres | Primary database driver (postgres, mysql, or sqlite) docker-compose.yml138 |
| DB_HOST | postgres | Database network host address docker-compose.yml139 |
| DB_PORT | 5432 | Database network port docker-compose.yml140 |
| DB_USER | (required) | Database authentication username docker-compose.yml141 |
| DB_PASSWORD | (required) | Database authentication password docker-compose.yml142 |
| DB_NAME | (required) | Target database schema/instance name docker-compose.yml143 |
| DB_PATH | (empty) | File system path used exclusively when DB_DRIVER=sqlite docker-compose.yml145 |

 Database initialization is orchestrated via `initDatabase()` inside the container wiring logic [internal/container/container.go123](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L123-L123)

## File Storage Configuration

 Storage backends for uploaded assets and system documents are controlled by the `STORAGE_TYPE` variable and associated provider parameters.

 
| Variable | Default | Description |
|---|---|---|
| STORAGE_TYPE | local | Storage provider (local, minio, cos, tos, s3, obs, oss) |
| MAX_FILE_SIZE_MB | 50 | Maximum allowed document upload size in megabytes docker-compose.yml18 |
| MINIO_ENDPOINT | (empty) | Endpoint URL for MinIO S3-compatible storage |
| COS_SECRET_ID | (empty) | Tencent Cloud COS Secret ID for object storage docker-compose.yml111 |
| COS_BUCKET_NAME | (empty) | Tencent Cloud COS bucket identifier docker-compose.yml114 |

 Storage initialization is executed through `initFileService()` [internal/container/container.go124](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L124-L124)

## Retrieval Engine Configuration

 Semantic search operations and vector index storage are bound to the selected retrieval driver.

 
| Variable | Default | Description |
|---|---|---|
| RETRIEVE_DRIVER | postgres | Vector store backend (postgres, qdrant, milvus, elasticsearch, opensearch, weaviate, doris, sqlite, tencent_vectordb) |
| QDRANT_HOST | (empty) | Qdrant vector database host address |
| MILVUS_ADDRESS | (empty) | Milvus vector database gRPC address |
| ELASTICSEARCH_ADDR | (empty) | Elasticsearch cluster endpoint |

 Retrieval engine registration is handled centrally within `initRetrieveEngineRegistry()` [internal/container/container.go135](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/container/container.go#L135-L135)

## Document Parser and External Services

| Variable | Default | Description |

| DOCREADER_TRANSPORT | grpc | Transport layer protocol (grpc or http) docker-compose.yml96 |
| OLLAMA_BASE_URL | http://ollama:11434 | Base URL for the Ollama local LLM service |
