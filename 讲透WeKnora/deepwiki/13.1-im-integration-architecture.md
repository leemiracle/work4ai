  The WeKnora Instant Messaging (IM) integration subsystem provides a unified gateway connecting Large Language Model (LLM) agents to external messaging platforms including Feishu, Lark, WeCom, DingTalk, Slack, Telegram, Mattermost, WeChat, QQBot, and Yunzhijia. Using an adapter pattern, it encapsulates platform-specific protocols (Webhook, WebSocket, Long-polling) into a standardized internal message pipeline, enabling consistent Retrieval-Augmented Generation (RAG) and ReAct agent interactions across disparate messaging channels.

 
---

 
## 1. Unified Message Processing Architecture

 The core orchestration resides in `im.Service`, which coordinates message intake, session resolution, request queuing, pipeline execution, and reply delivery across all adapters.

 Incoming events are received by platform-specific listeners, verified, and parsed into a normalized `im.IncomingMessage` struct ([internal/im/adapter.go48-85](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/adapter.go#L48-L85)). The message is dispatched to `im.Service` ([internal/im/service.go343-380](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/service.go#L343-L380)), which resolves the conversational context and serializes execution through an internal queue (`[internal/im/qaqueue.go:137-178]`).

## 2. The IM Adapter Pattern and Interfaces

 Platform implementations satisfy the core `im.Adapter` interface and optional capability interfaces, decoupling protocol details from the unified service layer ([internal/im/adapter.go125-174](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/adapter.go#L125-L174)).

 
| Interface / Type | Key Methods / Fields | Responsibility |
|---|---|---|
| im.Adapter | VerifyCallback, ParseCallback, SendReply, HandleURLVerification | Core lifecycle: signature validation, payload parsing, and direct reply dispatch (internal/im/adapter.go126-144). |
| im.StreamSender | StartStream, UpdateStreamContent, FinalizeStream, EndStream | Manages incremental card/message edits for streaming output (internal/im/adapter.go150-164). |
| im.FullOutputProgressSender | SupportsFullOutputProgress() | Indicates support for an initial placeholder message replaced once with final output (internal/im/adapter.go169-172). |
| im.FileDownloader | DownloadFile | Optional adapter extension to fetch attachment contents for OCR, VLM analysis, or embedding. |

## 3. Channel Management and Bot Identity Routing

 An `IMChannel` record binds a specific bot configuration on an IM platform to a WeKnora tenant agent ([internal/im/types.go18-34](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/types.go#L18-L34)).

 
 - **Bot Identity Derivation:** `computeBotIdentity()` hashes or compiles platform credentials into a unique identifier (`bot_identity`) to prevent cross-tenant collision and route incoming webhooks/sockets to the correct channel ([internal/im/types.go143-190](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/types.go#L143-L190)). Examples: 
 - Feishu/Lark: `feishu:<app_id>` ([internal/im/types.go177-180](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/types.go#L177-L180))
 - WeCom WebSocket: `wecom:ws:<bot_id>` ([internal/im/types.go164-167](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/types.go#L164-L167))
 - Telegram: `telegram:<bot_id>` ([internal/im/types.go181-188](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/types.go#L181-L188))
 - **Session Modes:** Configured via `SessionMode` ([internal/im/adapter.go28-36](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/adapter.go#L28-L36)): 
 - `SessionModeUser`: Resolves sessions by `(platform, user_id, chat_id, tenant_id)`.
 - `SessionModeThread`: Resolves sessions by `(platform, thread_id, chat_id, tenant_id)` (e.g., Slack or Feishu threads).

## 4. Concurrency and Queue Management (`im.qaQueue`)

 To prevent LLM provider rate limits and handle heavy inbound traffic spikes, `im.Service` uses an asynchronous queue worker pool (`[internal/im/qaqueue.go:71-99]`).

 
 - **Deduplication:** Incoming message IDs are tracked in a TTL map (`dedupTTL = 5 * time.Minute`) to drop duplicate webhook deliveries ([internal/im/service.go45-48](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/service.go#L45-L48)).
 - **Worker Concurrency:** Bounded worker loops process queued `qaRequest` payloads, ensuring serialized execution per user or channel when required.

## 5. Streaming and Full Output Execution Modes

 Channels specify an `OutputMode` (`stream` or `full`) governing how answers are rendered back to users (`[internal/im/types.go:26]`).

 
 - **Streaming Output Mode:** The adapter initializes a stream via `StartStream()`, pushes incremental updates using `UpdateStreamContent()`, and finalizes with `FinalizeStream()` (`[internal/im/adapter.go:150-164]`). Content flushes are throttled at `streamFlushInterval = 300 * time.Millisecond` to balance perceived latency and API rate limits ([internal/im/service.go63-65](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/service.go#L63-L65)).
 - **Full Output Mode:** The system displays a temporary placeholder message (e.g., a "thinking" card via `FullOutputProgressSender`), holds intermediate chunks, and replaces the placeholder with the complete response once generation concludes ([internal/im/full_output_test.go179-204](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/full_output_test.go#L179-L204)).

## 6. Content Transformation and Output Sanitization

 LLM outputs often contain internal XML tags, thinking blocks, or storage paths that are incompatible with IM clients. `im.Service` applies rigorous transformations before delivery:

 
 - **Citation Stripping:** `stripIMCitationTags()` removes agent pipeline inline `<kb .../>` and `<web .../>` tags ([internal/im/service.go74-79](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/service.go#L74-L79)).
 - **Image Tag Collapse:** `stripImageXMLTags()` converts internal `<image>...</image>` blocks back to clean Markdown image syntax `![alt](url)` using nested `<image_original>` tags ([internal/im/service.go81-99](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/service.go#L81-L99)).
 - **URL Rewriting:** `rewriteStorageURLs()` translates internal `storage://` schemes into signed, publicly accessible HTTP URLs ([internal/im/service.go104-109](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/service.go#L104-L109)).
 - **Stream Holdback:** `holdbackCutoff()` delays flushing if an XML tag or storage URL is split across chunk boundaries, preventing malformed rendering ([internal/im/service.go119-141](https://github.com/Tencent/WeKnora/blob/10973ed3/internal/im/service.go#L119-L141)).
