## 一、什么是 AI 系统逆向工程

**正向工程**：从需求 → 设计 → 代码 → 二进制。
**逆向工程**：从二进制 → 设计 → 需求。

**AI 系统逆向**特指针对**包含 AI 模型的系统**——除了传统的代码/二进制逆向，还要多两层：
1. **数据资产逆向**：词典、NLU 库、训练语料、配置表
2. **模型逆向**：网络结构、权重、量化参数、推理引擎调用约定

一个完整的端侧 AI 系统通常包含 5 层：

```
┌─────────────────────────────────────────────┐
│  应用层（Agent / 业务逻辑，Java/Kotlin）    │  ← 传统逆向
├─────────────────────────────────────────────┤
│  SDK 层（统一接口，IMemory/IVector 等）     │  ← 传统逆向
├─────────────────────────────────────────────┤
│  模型层（推理引擎 + 模型文件）              │  ← AI 逆向特有
├─────────────────────────────────────────────┤
│  数据层（向量库 / NLU 库 / 词典 / SQLite）  │  ← AI 逆向特有
├─────────────────────────────────────────────┤
│  持久化层（混淆类 + 自定义二进制文件）      │  ← 难点
└─────────────────────────────────────────────┘
```

**传统逆向只覆盖上下两层**，中间三层（模型 + 数据 + 持久化）是 AI 系统特有的、也是最有价值的部分。

## 二、为什么要学

### 1. 工业级 AI 系统的真相只在闭源里

学术界的 AI 系统是干净的（论文 + 开源代码 + 预训练 checkpoint），但工业级端侧 AI 系统往往是**混淆 + 加固 + 加密**的——因为厂商要保护：
- 训练数据（花了真金白银标的）
- 模型结构（核心技术壁垒）
- 推理引擎优化（端侧性能竞争）
- 业务逻辑（差异化卖点）

**想真正理解工业级 AI 系统长什么样，必须会逆向。**

### 2. AI 系统形式化、对标、审计的前提

近年兴起几个方向，都需要先逆向：
- **AI 系统形式化验证**（Lean4 / Coq）：要验证一个闭源引擎，先得还原它的语义
- **开源对标**（如 LLaMA 对标 GPT）：要知道对标什么，先逆向出目标
- **安全审计**（AI 系统的供应链安全）：不知道里面跑了什么模型，怎么审计
- **互操作性**（让你的系统能读厂商的格式）：必须先理解厂商格式

### 3. 端侧 AI 的特殊学习价值

端侧 AI 系统（手机、车机、IoT）有几条**云端 AI 看不到**的工程约束，让逆向特别有学习价值：
- **离线优先**：所有模型、词典、NLU 库必须打包进 APK，**完全可逆**
- **性能预算紧**：必须用量化、字典降级、三级 fallback 等技巧
- **多模态融合**：文本 + 图像 + 行为日志通常耦合在一个系统里
- **持久化**：进程死了重启要能 recall，这逼出有趣的存储设计（如 SQLite + 自定义向量文件双写）

## 三、攻黑盒哲学 ⭐

这是本教程最重要的部分。**逆向一个 AI 系统不是"暴力破解"，而是"科学方法"**。

### 3.1 黑盒不是"硬骨头"，是"分层防御"

商业 AI 系统的反逆向通常是**分层**的——厂商不会把所有资源都投入到一层防御，因为：
- 全用代码混淆 → APK 太大、运行慢
- 全用 native 加固 → Java 层逻辑复杂度爆炸
- 全用资产加密 → 模型加载延迟 unacceptable

所以典型分层是：
- **表面层**（Java DEX）：字段名明文（用 `@Keep` 防 ProGuard 混淆）
- **中间层**（混淆类）：业务逻辑混淆
- **深层**（native so）：核心算法 + 加密
- **资产层**（模型/词典）：可能加密，可能不加密

**攻黑盒的策略：找到防御最薄的那一层，横向穿透。**

> 📌 **铁律**：永远先问"哪一层最薄"，而不是"哪一层最有趣"。最有趣的层（往往是核心算法）通常防御最厚；最薄的层（往往是配置、字符串、SQL）能给你 80% 的信息。

### 3.2 五步法（详见 [10-攻黑盒五步法](10-攻黑盒五步法与案例索引.md)）

```
1. 观察（看）
   ↓ 读所有 .so / .dex / .db / assets 文件清单 + 大小
   ↓ 抓所有 DEX 字符串常量（const-string 是金矿）
2. 假设（猜）
   ↓ 基于文件名/类名/方法签名/字符串，给每个黑盒起假设
3. 反推（推）
   ↓ 用工具（androguard / Frida / d4l3k walker）验证假设
   ↓ 横向对照：开源等价模型 / 同 APK 不同版本 / 不同 APK 同模块
4. 实测（试）
   ↓ 写最小可跑脚本，用真实数据/二进制跑通
5. 验证（对）
   ↓ 输出 vs 原系统输出 diff
   ↓ 95% 一致 = 攻下；90% = 半攻；<90% = 还有黑盒
```

每一步都有具体的工具和技巧，散落在 01-09 章。

### 3.3 高 ROI 心态：先低成本方法

| 成本 | 方法 | 何时用 |
|------|------|--------|
| 🟢 **0 硬件，1 小时** | 静态字符串扫描、SQLite dump、FlatBuffer vtable walker | **永远先做这个** |
| 🟡 **0 硬件，半天** | androguard 完整解析、PyTorch 网络重建、LLM 语义反推 | 静态扫描不够时 |
| 🟠 **需要真机，半天-1 天** | Frida Java/Native hook、Waydroid + frida-gadget 重打包 | 黑盒还有不确定时 |
| 🔴 **重投入，数周** | SCA 侧信道、Fuzzing、LLM4Decompile 9B GPU 反编译 | 最后手段 |

> 📌 **铁律**：永远从低成本方法开始。业界公开的逆向工程案例研究证明，**只靠 🟢 成本的方法就能达到 95% 还原度**。需要 🟠 以上的方法只占 5%。

### 3.4 失败比成功重要

每次反推**失败**都是信息：
- "VNDL field[10] 不是 layer_offset_table" → 说明 PReLU 负斜率表的位置
- "Signature value 指向 `\nStack Trace:`" → 说明厂商做了分层反逆向
- "Hook 后没有 hit" → 说明方法被混淆，真实方法名在另一个 dex

**记录失败原因**比记录成功结论更重要——它告诉你下一层防御长什么样。

## 四、ROI 矩阵：什么值得花时间

逆向一个完整 AI 系统有几十个组件，不可能全攻。按 ROI 排序：

| ROI | 攻击对象 | 为什么 |
|-----|---------|--------|
| ⭐⭐⭐⭐⭐ | **数据资产**（SQLite、词典、NLU 库）| 1 小时拿 80% 信息，无防御 |
| ⭐⭐⭐⭐⭐ | **二进制格式**（FlatBuffer、marisa-trie）| 工具现成，1 小时破 schema |
| ⭐⭐⭐⭐ | **开源等价模型**（MobileNet、CLIP）| 不用反推，直接用 |
| ⭐⭐⭐⭐ | **官方 SDK 文档**（开发者平台公开 PDF）| 蓝海信息源，常被忽视 |
| ⭐⭐⭐ | **持久化格式**（自定义二进制）| 需要反汇编 + 实测 |
| ⭐⭐⭐ | **Java 业务逻辑**（混淆类）| JADX + LLM 可以补位 |
| ⭐⭐ | **native so 核心**（推理引擎）| 反编译 + LLM4Decompile |
| ⭐⭐ | **加密 assets**（厂商加密）| 要先拿到 key |
| ⭐ | **端侧训练 API**（极少用）| 优先级最低 |

> 📌 **决策规则**：先打 ⭐⭐⭐⭐⭐，全打完再考虑 ⭐⭐⭐。⭐⭐ 以下只在前面打完还有剩余时间时才碰。

## 五、合法边界 ⚖️

这是**必须读**的一节。逆向工程在很多司法管辖区有灰色地带，本教程的立场是：

### 5.1 明确允许的场景

- **学术研究**：发表论文、写学位论文（绝大多数情况下合法，但要避免发布商业系统的完整源码）
- **互操作性研究**：让你的开源系统能读厂商的格式（受 DMCA §1201 例外保护）
- **安全审计**：在**获得厂商书面授权**的前提下做漏洞研究
- **个人学习**：在自己拥有的设备上做个人学习（大多数司法管辖区允许）
- **公开发布的方法论**：发布"如何逆向 X 类系统"的方法论文档（**不发布** X 系统的具体内部细节）

### 5.2 明确禁止的场景

- **绕过 DRM / 加密 / 签名校验**（DMCA §1201 / 中国《著作权法》第 49 条）
- **窃取商业秘密**（中国《反不正当竞争法》第 9 条 / 美国 DTSA）
- **未授权访问他人设备**（中国《刑法》第 285 条 / 美国 CFAA）
- **发布商业系统的内部细节**（即使你逆向出来了）
- **用于制造盗版或绕过付费**

### 5.3 本教程的立场

- ✅ **只讲方法论**：所有命令、脚本、实验都基于公开 APK、自造靶子、开源学术工具
- ✅ **全量脱敏**：所有厂商名、产品代号、内部 URL、类名、文件名都已脱敏为"目标系统 X"、"X 助手"等抽象名
- ✅ **不复述商业系统内部细节**：本教程不写"X 系统有 N 个 NLU 表、M 个 NER 标签"这种具体数字
- ❌ **本教程不提供**：任何商业系统的 APK 下载链接、内部 URL、加密 key、签名校验绕过方法

### 5.4 你做逆向时的自检清单

在发布任何逆向产物前，问自己：
1. 我有授权吗？（学术 / 互操作 / 已获授权安全审计）
2. 我发布的是**方法论**还是**商业系统细节**？（前者 OK，后者不行）
3. 我引用的是**公开信息**（APK 文件名、开源工具）还是**未公开内部细节**（类名、API URL）？
4. 我的产物**损害厂商商业利益**吗？（开源对标 OK，破解付费 NO）
5. 我**遵守了厂商 ToS** 吗？（很多厂商 ToS 禁止逆向，需注意）

> 📌 **铁律**：当不确定能不能发布时，**默认不发布**。先咨询法务或伦理委员会。

## 六、本教程的诚实标注

本教程是**方法论抽取**，从一次完整的端侧 AI 系统逆向经验中提炼出**可迁移到任何系统的工具、思路、陷阱**。我们诚实地标注：

| 我们做的 | 我们没做的 |
|---------|----------|
| ✅ 把 7 大方法层系统化（静态/动态/格式/数据/模型/同构/LLM） | ❌ 复述 X 系统的内部架构 |
| ✅ 把工具原理讲透（Frida / androguard / d4l3k walker）| ❌ 提供 X 系统的 APK 下载 |
| ✅ 用公开/自造靶子演示每个方法 | ❌ 提供 X 系统的加密 key |
| ✅ 引用开源学术工作（LLM4Decompile / TCHES 2026） | ❌ 引用 X 系统的内部 URL |
| ✅ 讲厂商的反逆向手段（一般性） | ❌ 讲 X 系统具体用了什么加固方案 |

## 七、本教程不教你什么

为了不踩法律红线，本教程**故意不教**：
1. 如何 root 任何厂商的设备（root 教程厂商机型相关，且可能违反保修）
2. 如何绕过具体厂商的加固（腾讯乐固 / 360 加固 / 爱加密等）
3. 如何反编译任何商业 APK 的完整业务逻辑
4. 如何制作盗版应用或绕过应用付费

如果你需要这些知识，请寻找专门的安全研究社区（且自负法律责任）。

  - "互操作性研究" → 不是为了抄它，是为了让你的开源程序能读懂它的私有文件格式，法律上一般有豁免

## 🎭 欺骗动力学视角：系统黑箱

> 承接 [`欺骗动力学-社会进步的隐秘引擎.md`](欺骗动力学-社会进步的隐秘引擎.md) §5。

### 三问

1. **讲透AI系统逆向工程 防的是什么欺骗？** → 闭源系统的内部行为被刻意隐藏或模糊。
2. **被什么攻破？** → 混淆 / 加固 / 反逆向手段。
3. **沉淀进哪条主链？** → 验证主链——逆向工程 = 强制让黑箱暴露内部 = 识诈的工程化。

### 一句话

> 逆向工程是识诈的硬核形态：你不让我看，我偏要看清楚你到底在做什么。
