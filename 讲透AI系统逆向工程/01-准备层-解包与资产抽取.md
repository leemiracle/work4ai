# 01 · 准备层：APK 解包与资产抽取

> 任何逆向的第一步：把 APK 拆开，列出所有"可观察表面"。这一步**不需要任何反编译技能**，只要会 `unzip` + `strings`——但它是后面所有章节的基础。
>
> 本章工具全是公开、开源、跨平台的。不涉及任何商业 APK 加固脱壳技术（见 [09 章](09-反逆向手段与对策.md)）。

---

## 一、APK 是什么

APK（Android Package）本质上是个 **ZIP**：

```
target.apk
├── AndroidManifest.xml      ← 二进制 XML（需 aapt 解码）
├── classes.dex              ← 主 dex
├── classes2.dex             ← 多 dex
├── classes3.dex
├── ...
├── lib/
│   ├── arm64-v8a/           ← ARM64 原生库
│   │   ├── libnative.so
│   │   └── libaiengine.so
│   ├── armeabi-v7a/         ← 32 位 ARM
│   └── x86_64/              ← 模拟器用
├── assets/                  ← ★ AI 资产都在这
│   ├── models/
│   │   ├── clip_encoder.tflite
│   │   └── nlu_classifier.onnx
│   ├── dicts/
│   │   ├── main.marisa
│   │   └── stopwords.txt
│   └── config/
│       └── nlu_patterns.json
├── res/                     ← 资源（图片/布局/字符串）
├── META-INF/                ← 签名
└── resources.arsc           ← 编译后的资源
```

**AI 系统的金矿在 `lib/` 和 `assets/`**——dex 和 res 通常只是 UI 层。

## 二、解包工具链

### 2.1 基础：unzip

最朴素的 `unzip` 就能拆 APK：

```bash
mkdir apk_unpacked && cd apk_unpacked
unzip ../target.apk
```

但这种方式拿到的 `AndroidManifest.xml` 是二进制 XML，需要 `aapt` 或 `apktool` 解码。

### 2.2 aapt（Android Asset Packaging Tool）

`aapt` 是 Android SDK 自带的工具，能解码 manifest：

```bash
aapt dump badging target.apk
# 输出关键信息:
# package: name='com.xxx.target' versionCode=123 versionName='1.2.3'
# launchable-activity: name='com.xxx.target.MainActivity'
# uses-permission: android.permission.INTERNET
# uses-permission: android.permission.READ_EXTERNAL_STORAGE
# ...
```

### 2.3 apktool（更彻底）

`apktool` 能把整个 APK 拆成**人类可读**形式（包括 smali）：

```bash
apktool d target.apk -o target_unpacked
# 产出:
# target_unpacked/
#   AndroidManifest.xml     ← 文本 XML
#   apktool.yml
#   unknown/
#   original/
#   res/                    ← 解码的资源
#   smali/                  ← 反汇编的 dex（每 dex 一目录）
#   assets/                 ← 原样
#   lib/                    ← 原样
```

### 2.4 JADX（最强反编译）

JADX 把 dex 直接反编译成**可读 Java**：

```bash
jadx-gui target.apk
# 或 CLI:
jadx -d target_jadx target.apk
# 产出:
# target_jadx/sources/com/xxx/target/MainActivity.java
#                   /.../...
```

> 📌 **铁律**：**永远同时用 apktool + JADX**。JADX Java 更可读，apktool smali 更精确（JADX 偶尔反编译错，smali 永远对）。

## 三、AI 资产抽取清单

### 3.1 模型文件

```bash
# 找所有可能的模型文件
find apk_unpacked -type f \( \
    -name "*.tflite" -o -name "*.lite" \
    -o -name "*.onnx" -o -name "*.pb" \
    -o -name "*.pt" -o -name ".pth" \
    -o -name "*.model" -o -name "*.bin" \
    -o -name "*.vndl" -o -name "*.vndl" \) -exec ls -lah {} \;
```

对每个文件做 `xxd | head` 看头部：
- `TFL3` magic → TFLite
- `\x08\x05` 开头 → ONNX（Protobuf）
- 标准 FlatBuffer offset → FlatBuffer / 厂商自有
- 随机字节 → 加密了

### 3.2 词典 / NLU 资源

```bash
# 找文本/二进制词典
find apk_unpacked/assets -type f | xargs file | grep -iE 'text|data'
# file 命令识别格式
```

### 3.3 SQLite 数据库

```bash
find apk_unpacked -type f -name "*.db" -exec sqlite3 {} ".tables" \;
```

### 3.4 .so 文件清单

```bash
ls apk_unpacked/lib/arm64-v8a/
# 每个 .so 都是一个功能模块
```

命名约定（参考）：
- `libnative.so` / `libapp.so` — 通用 native 代码
- `libcrypto.so` — 加密
- `libaiengine.so` / `libinference.so` — AI 推理
- `libtokenizers.so` — 分词（参考 Rust tokenizers 库）
- `lib{xxx}_sdk.so` — 第三方 SDK

## 四、自动化：批量抽取

### 4.1 一行命令抽取所有字符串

```bash
# 所有 dex + so + assets 的字符串汇总
find apk_unpacked -type f \( -name "*.dex" -o -name "*.so" \) -exec strings {} \; \
    | sort -u > all_strings.txt

wc -l all_strings.txt  # 通常几十万行
```

### 4.2 找 URL / 文件路径 / API

```bash
grep -E '^https?://' all_strings.txt | sort -u > urls.txt
grep -E '\.(json|yaml|txt|db|model|so|dex)$' all_strings.txt | sort -u > file_refs.txt
```

### 4.3 找中文日志（暴露类名/方法名）

```bash
grep -E '[\x{4e00}-\x{9fff}]' all_strings.txt | head -100
# 中文日志常含类名: "FooBar.start() called"
```

## 五、JADX-GPT 配置

JADX-GPT 是 JADX 的 LLM 增强插件，能自动给混淆类重命名。

### 5.1 安装

```bash
# 需要 JADX 1.4+ 和 OpenAI API key
git clone https://github.com/ITayheeLau/jadx-gpt
cd jadx-gpt && ./gradlew distZip
# 把 zip 解压到 jadx plugins 目录
```

### 5.2 配置

```bash
export OPENAI_API_KEY=sk-xxx
# 启动 jadx-gui
jadx-gui target.apk
# 选中一个混淆类 → 右键 → "GPT Rename"
```

### 5.3 局限

- 需要 API key（成本）
- LLM 偶尔给错名字（重要场景要人工核对）
- 对超长方法体效果差

## 六、伦理 / 法律提示

### 6.1 你能做的

- ✅ 解包任何**你合法持有**的 APK（自己装的、F-Droid 下载的、自己开发的）
- ✅ 抽取**公开 APK** 的 assets（厂商默认会允许）
- ✅ 把抽取出来的"开源等价物"（如词典）用于自己的项目
- ✅ 发布**脱敏的方法论**

### 6.2 你不能做的

- ❌ 发布商业 APK 的**完整源码**（即使你反编译出来了）
- ❌ 分享**有版权的资产**（如模型权重、训练数据）
- ❌ 绕过 DRM / 签名校验
- ❌ 用于制造盗版应用
