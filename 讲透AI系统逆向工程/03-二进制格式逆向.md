# 03 · 二进制格式逆向 ⭐

> 端侧 AI 系统里几乎每一份非代码资产都是**自定义二进制格式**——模型文件、向量库、词典、NLU 状态机、配置 blob。这一章讲透三种最典型的格式：**FlatBuffer（模型）**、**marisa-trie（词典）**、**AC 自动机（NLU）**。掌握这三种就能拆 80% 的端侧 AI 资产。
>
> 核心方法：**vtable walker**（来自 d4l3k 的 Go gist），让我们对**未知 schema 的 FlatBuffer** 也能反推出字段语义。

---

## 一、为什么端侧 AI 偏爱这三种格式

| 格式 | 用途 | 为什么是它 |
|------|------|-----------|
| **FlatBuffer** | 模型文件、配置 | 零拷贝反序列化、内存映射友好、有 schema 但可不依赖 schema 解析 |
| **marisa-trie** | 大词典（中文分词、NER）| 内存占用比 hash table 小一个数量级，加载快 |
| **AC 自动机** | 多模式匹配（地名、机场）| 一次扫描匹配所有关键词，O(N) |

厂商自有的格式往往是这三种的**变种**——例如某厂商的模型格式就是在 FlatBuffer 外套一层 metadata + 加密头。

## 二、FlatBuffer 逆向 ★

### 2.1 FlatBuffer 基础

FlatBuffer 是 Google 的序列化库（同 Protobuf、Cap'n Proto）。**核心特征：零拷贝**——序列化后的 buffer 可以直接解读，不需要 parse 成对象。

```
┌────────────────────────────────────────────────┐
│  FlatBuffer 内存布局                            │
│  ─────────────────────                         │
│  [root offset u32]   ← 指向 root table         │
│  [vtable]            ← 描述字段偏移            │
│  [table data]        ← 实际字段值              │
│  [vectors / strings] ← 内联数据               │
└────────────────────────────────────────────────┘
```

**关键概念**：
- **vtable**：描述 table 里每个字段相对于 table 起点的偏移（voffset_t = u16）
- **root table**：FlatBuffer 的入口，第一个 u32 就是它相对 buffer 起点的偏移
- **inline data**：字符串、数组等紧跟在 table 后面

### 2.2 vtable walker：对**未知 schema** 的 FlatBuffer 反推 ★

**问题**：正常 FlatBuffer 解析需要 `.fbs` schema 文件编译出代码。但厂商不会给你 schema。

**解法**（d4l3k 思路）：**FlatBuffer 格式自带 vtable**，schema 就在 buffer 里——只要走 vtable 就能 dump 所有字段。

```python
import struct

def parse_flatbuffer_unknown_schema(data: bytes):
    """对未知 schema 的 FlatBuffer 反推字段结构"""
    # 1. 读 root offset（buffer 第一个 u32）
    root_offset = struct.unpack_from('<I', data, 0)[0]
    root_table_pos = root_offset  # root table 在 buffer 中的位置
    
    # 2. root table 的前 4 字节是 vtable offset（soffset_t = i32）
    #    注意：vtable offset 是 *负* 偏移（相对 root table 起点）
    vtable_soffset = struct.unpack_from('<i', data, root_table_pos)[0]
    vtable_pos = root_table_pos - vtable_soffset
    
    # 3. vtable 头：[vtable_size u16] [table_size u16]
    vtable_size = struct.unpack_from('<H', data, vtable_pos)[0]
    table_size = struct.unpack_from('<H', data, vtable_pos + 2)[0]
    
    # 4. vtable 字段偏移数组（u16 × N，N = (vtable_size - 4) / 2）
    n_fields = (vtable_size - 4) // 2
    fields = []
    for i in range(n_fields):
        offset_in_table = struct.unpack_from('<H', data, vtable_pos + 4 + i * 2)[0]
        if offset_in_table == 0:
            fields.append(None)  # 字段不存在
            continue
        # 字段值在 root_table_pos + offset_in_table
        field_pos = root_table_pos + offset_in_table
        # 候选类型探测：u8 / u16 / u32 / u64 / offset
        candidates = {
            'u8':  struct.unpack_from('<B', data, field_pos)[0] if field_pos + 1 <= len(data) else None,
            'u16': struct.unpack_from('<H', data, field_pos)[0] if field_pos + 2 <= len(data) else None,
            'u32': struct.unpack_from('<I', data, field_pos)[0] if field_pos + 4 <= len(data) else None,
            'u64': struct.unpack_from('<Q', data, field_pos)[0] if field_pos + 8 <= len(data) else None,
        }
        fields.append({'offset': offset_in_table, 'pos': field_pos, 'candidates': candidates})
    
    return {
        'root_offset': root_offset,
        'vtable_pos': vtable_pos,
        'vtable_size': vtable_size,
        'table_size': table_size,
        'n_fields': n_fields,
        'fields': fields,
    }
```

### 2.3 字段语义反推：4 个启发式

dump 出所有字段的候选数值后，**怎么判断每个字段的实际类型/含义**？这是 vtable walker 的艺术。4 个启发式：

#### 启发式 1：**字符串候选** — offset 落在 ASCII 高密度区

如果一个 u32 字段值 = buffer 中某偏移，且那个偏移处是 4 字节长度前缀 + ASCII 字符串，那 99% 是字符串。

```python
def maybe_string_at(data, pos):
    if pos + 4 > len(data):
        return None
    length = struct.unpack_from('<I', data, pos)[0]
    if length == 0 or length > 1000:  # 合理性检查
        return None
    if pos + 4 + length > len(data):
        return None
    raw = data[pos + 4 : pos + 4 + length]
    # ASCII printable check
    if all(0x20 <= b < 0x7F or b in (0x0a, 0x0d, 0x09) for b in raw):
        try:
            return raw.decode('utf-8')
        except UnicodeDecodeError:
            return raw.decode('latin-1')
    return None
```

**实例**：在反推某厂商模型格式时，field[1] 的 u32 值指向的位置 decode 出 `"tflite"`——这立刻告诉我们**源格式是 TFLite**。

#### 启发式 2：**向量候选** — offset 落在大量同质数据区

如果 u32 字段值 = 某偏移，且那个偏移前 4 字节是个合理 length，紧跟 length 个同质数据（全是 finite float32），那 99% 是向量。

```python
def maybe_f32_vector_at(data, pos, max_elements=1000):
    if pos + 4 > len(data):
        return None
    length = struct.unpack_from('<I', data, pos)[0]
    if length == 0 or length > 1_000_000:
        return None
    if pos + 4 + length * 4 > len(data):
        return None
    floats = struct.unpack_from(f'<{min(length, max_elements)}f', data, pos + 4)
    # 全部 finite 且分布合理
    import math
    if not all(math.isfinite(f) for f in floats):
        return None
    return {'length': length, 'samples': floats[:10]}
```

**实例**：模型文件中段 weights blob 通常是这种结构。

#### 启发式 3：**元数据字符串反查** — tail strings 是金矿

FlatBuffer 的 string 区域往往集中在文件末尾。dump 所有 strings 后逐个**反查**：
- `dense_20` / `Sigmoid` / `p_re_lu_*` → 暴露层名 + 激活函数
- `vendor_encoder_128d_v1.tflite` → 暴露源文件名（**金矿**，可直接搜索开源等价模型）
- `embedding_10` / `conv1d_138` → 暴露网络结构

**铁律**：永远先 dump 所有 strings 到一个文本文件，逐行读——这一步不需要任何工具，1 分钟搞定，但能给你 30% 的信息。

#### 启发式 4：**字段间相对关系** — 偏移递增 = 列表

如果 field[N]、field[N+1]、field[N+2] 的 offset 值递增（如 0xfc、0x299b5c、0x299c1c），那它们很可能是**一组指针**，指向连续的子结构（如 layer_offset_table）。

### 2.5 进阶：`flatcc --annotate` 验证

如果反推出的 schema 有把握，把它写成 `.fbs` 文件，用 [`flatcc`](https://github.com/dvidelabs/flatcc) 的 `--annotate` 模式跑一下原 buffer：

```bash
flatcc --annotate presumed_schema.fbs target.bin
# 输出 target.bin.txt，每行带字段名标注
```

如果 `flatcc` 解析无误且字段值合理，schema 就是对的。

## 三、marisa-trie 逆向

### 3.1 marisa-trie 是什么

[marisa-trie](https://github.com/s-yata/marisa-trie) 是一种**压缩前缀树**，广泛用于中文分词、NER 实体词典。优点：
- 内存占用比 hash table 小 5-10 倍
- 加载快（mmap 一次）
- 支持 prefix / predict 查询

jieba / cppjieba / 很多厂商的中文分词都用它做主词典。

### 3.2 文件格式

marisa-trie 的二进制格式由多个 patricia trie 层级联组成，**官方文档没明确文档化**——但好消息是 **Python 库 `marisa-trie` 可以直接加载并 dump 所有 keys**：

```python
import marisa_trie

trie = marisa_trie.Trie()
# ⚠️ 铁律: load() 接受 str 路径,不接受 pathlib.Path
trie.load(str('/path/to/dictionary.marisa'))

# dump 所有 keys
keys = trie.keys()
print(f'词典规模: {len(keys)}')
print(f'前 10 个: {keys[:10]}')

# 词长分布
from collections import Counter
length_dist = Counter(len(k) for k in keys)
print(f'词长分布: {sorted(length_dist.items())}')
```

### 3.3 实证：加载公开 jieba 词典

```bash

```

实验内容：
1. 下载 jieba 主词典（公开）
2. 用 `marisa_trie.Trie()` 构建 + save
3. load 回来 + dump keys + 统计

预期：约 35 万词，2 字词最多（约 15 万），3 字次之（约 11 万），符合中文分词词典一般规律。

### 3.4 进阶：识别"非标准" marisa-trie

厂商有时会用 marisa-trie 的变种（自定义 value 字段），`marisa_trie.RecordTrie` / `marisa_trie.BytesTrie` 支持 value：

```python
# RecordTrie: 每个 key 关联一个固定格式的 record
trie = marisa_trie.RecordTrie('<i')  # 每个 key 关联一个 int32
trie.load('label.marisa')

# BytesTrie: 每个 key 关联任意 bytes
trie = marisa_trie.BytesTrie()
trie.load('entity.marisa')
for key, value in trie.items():
    print(f'{key!r}: {value!r}')
```

如果厂商用了更深的变种（如自改 marisa 源码），可能要读 `marisa-trie` C++ 源码反推格式——但这种重投入一般 ROI 不高，不如直接 hook 内存拿 keys。

## 四、AC 自动机逆向

### 4.1 AC 自动机是什么

Aho-Corasick 自动机是**多模式字符串匹配**算法——一次扫描文本就能匹配所有关键词。端侧 AI 系统用它做：
- 省份/城市/机场识别（NLU 用）
- 实体名匹配（NER 用）
- 触发词检测（业务规则用）

### 4.2 文件格式

AC 自动机序列化通常是：
- **goto 表**（状态转移，二维数组）
- **fail 表**（失败指针，一维数组）
- **output 表**（每个状态的输出关键词）

**好消息**：很多厂商的 AC 自动机其实就是**纯文本格式**（虽然扩展名是 `.model`），因为它内部就是数字。

```python
def parse_ac_automaton(path):
    """解析 AC 自动机文本格式"""
    with open(path, encoding='utf-8') as f:
        lines = f.read().splitlines()
    
    # 典型格式: 每行一个状态转移
    # "from_state  char  to_state"
    transitions = []
    for line in lines:
        parts = line.split()
        if len(parts) >= 3 and parts[0].isdigit():
            transitions.append((int(parts[0]), parts[1], int(parts[2])))
    
    print(f'状态转移数: {len(transitions)}')
    print(f'状态总数: {max(t[0] for t in transitions) + 1}')
    return transitions
```

### 4.3 实证：自造 AC 自动机 + dump

```python
import ahocorasick  # pyahocorasick 库

# 自造关键词集
keywords = ['北京', '上海', '广州', '深圳', '北京首都机场', '上海浦东机场']
auto = ahocorasick.Automaton()
for kw in keywords:
    auto.add_word(kw, kw)
auto.make_automaton()

# 序列化 + 反序列化
auto.save('demo.ac')
auto2 = ahocorasick.Automaton()
auto2.load('demo.ac')

# 测试
text = '我从北京首都机场飞到上海浦东机场'
for end_idx, kw in auto2.iter(text):
    print(f'位置 {end_idx - len(kw) + 1}-{end_idx}: {kw}')
```

## 五、其他常见格式速查

| 格式 | 用途 | 反推方法 |
|------|------|---------|
| **TFLite** | TensorFlow Lite 模型 | 用 `flatc --json` + 标准 schema |
| **ONNX** | 开源神经网络交换格式 | `onnx.load()` 直接解析 |
| **Protobuf** | 配置、协议 | 用 `protoc --decode_raw` 反推 |
| **自定义加密** | 厂商自有 | 先找 key（往往在 native so 里），再 standard 解 |
| **SQLite** | 业务数据 | 直接 `sqlite3 file.db ".tables"` |
| **LevelDB / RocksDB** | KV 存储 | 用相应库直接 open |
| **Room** | Android ORM | 实际是 SQLite + 注解，参考 [02 章 DEX annotation](02-静态分析-DEX反编译.md) |

## 六、陷阱总结

| 陷阱 | 症状 | 解法 |
|------|------|------|
| **FlatBuffer 大端 / 小端搞错** | vtable_size 不合理（>1000）| 试试 `<` 和 `>` 互换 |
| **marisa-trie 加载报错** | `marisa_trie.Trie.load` 返回 False | 确认传 `str(path)` 不是 `Path`；确认版本兼容 |
| **AC 自动机看似二进制** | 用 hexdump 看是 ASCII | 直接当文本读 |
| **厂商改了 FlatBuffer 标准** | 标准 walker 解出垃圾 | 找开源等价模型对比（[07 章](07-同构对比与文档考古.md)）|
| **加密头骗过 walker** | walker 报错"非 FlatBuffer" | 先去 native so 找解密函数（[04 章 Frida](04-动态插桩-Frida.md)）|
