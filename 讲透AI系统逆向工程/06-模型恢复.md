# 06 · 模型恢复 ⭐

> 端侧 AI 系统的模型往往以**闭源格式**打包（FlatBuffer 变种 / 加密 / 自定义量化）。这一章讲透**如何从这些格式恢复出可推理的 PyTorch 模型**——四条技术路线，从最简单（直接装载）到最难（侧信道攻击）。
>
> 核心洞察：**厂商不会重新发明算法**，绝大多数端侧模型都能在开源世界里找到等价物。先想"开源有没有"，再想"自己拆"。

---

## 一、四条恢复路线总览

| 路线 | 难度 | 还原度 | 工作量 | 适用场景 |
|------|------|--------|--------|---------|
| **1. 同构装载** | 🟢 易 | 95%+ | 1-3 天 | 厂商格式 = 开源格式的变种（如 FlatBuffer 套壳 TFLite）|
| **2. 中段权重切分装载** | 🟡 中 | 85-95% | 半天 | 反推出 schema + 网络结构，但权重切分有歧义 |
| **3. KD 蒸馏** | 🟡 中 | 90-95% | 半天-1 天 | 有真机能跑原模型 collect (in,out) |
| **4. 侧信道攻击（SCA）** | 🔴 难 | 80-95% | 数周 | 模型完全闭源、无 API、需要硬件 |

> 📌 **决策规则**：永远从路线 1 开始。路线 1 不行才考虑 2。路线 3 需要 + 路线 4 不建议（除非学术研究）。

---

## 二、路线 1：同构装载（最优先）

### 2.1 核心思路

端侧模型有 90% 是基于以下开源生态的：
- **TFLite**（TensorFlow Lite）
- **ONNX**（Open Neural Network Exchange）
- **PyTorch Mobile**（torchscript）
- **NCNN / MNN / TNN**（中国厂商常用的端侧推理引擎）

**厂商自有格式往往是这些的"套壳"**——核心数据（网络结构 + 权重）原封不动，外面套一层 metadata + 可能加密。

### 2.2 实操步骤

#### Step 1：dump 所有 strings 找源格式线索

```bash
strings target.model | grep -iE '\.(tflite|onnx|pb|pt)$'
# 典型输出: mobilenet_v3_0905_sim.tflite
#          vendor_encoder_128d_v1.tflite
#          bp_2d_squeezenet.onnx
```

**只要找到一个文件名**，下一步就能做开源检索。

#### Step 2：开源检索

把文件名拆解成关键词，在以下平台检索：
- **GitHub**：`github.com/search?q=mobilenet_v3_0905&type=repositories`
- **HuggingFace**：`huggingface.co/models?search=mobilenet-v3`
- **TensorFlow Hub**：`tfhub.dev`
- **PapersWithCode**：`paperswithcode.com`

> 📌 **铁律**：源文件名里的数字（如 `128d_Nc`）往往是关键线索：
> - `128d` = 128 维 embedding
> - `Nc` = N 个类别（App 推荐场景就是 N 个 App）
> - `Nwi` = N 周的 install 数据

#### Step 3：找到开源等价模型后对照

假设找到了对应的 TFLite 模型，下载下来：

```python
import numpy as np

# 1. 用开源工具解析 TFLite
interpreter = tf.lite.Interpreter(model_path='open_source_model.tflite')
interpreter.allocate_tensors()

# 2. 拿到层图 + 权重
tensor_details = interpreter.get_tensor_details()
for t in tensor_details:
    print(f"{t['name']:40s} shape={t['shape_signature']} dtype={t['dtype']}")
```

把开源模型的层名 + shape 列表，与**你从 FlatBuffer 反推出的层名**对照——如果层名一致（如 `embedding_10`、`conv1d_138`、`dense_20`），那这两个模型就是同一个网络，可以直接用开源模型的 PyTorch 转换版。

### 2.3 实证：MobileNetV3 同构装载

```bash
cd 讲透AI系统逆向工程/experiments
python 07_weight_loader.py
```

实验内容：
1. 下载公开 MobileNetV3 TFLite 模型
2. 解析它的层图
3. 找到 PyTorch 等价实现（`torchvision.models.mobilenet_v3_small`）
4. 验证两者输出一致（对拍 1000 个随机输入）

预期：两个模型对同一张图片的 top-5 预测 99%+ 一致。

## 三、路线 2：中段权重切分装载

### 3.1 适用场景

如果路线 1 找不到开源等价物，但你**反推出了 schema 和层图**（通过 [03 章](03-二进制格式逆向.md)），就可以走路线 2。

### 3.2 核心思路

闭源模型文件的 weights 通常以**连续 blob**存储（一个大数组）。从层图知道每层的 shape，就能反推：
```
total_params = embedding.weight.numel() + conv1.weight.numel() + ...
weights_blob[:embedding_offset] → embedding.weight
weights_blob[embedding_offset:conv1_offset] → conv1.weight
...
```

### 3.3 实操：PyTorch 网络重建 + 装载

```python
import torch
import torch.nn as nn
import numpy as np
import struct

# Step 1: 重建网络（从反推出的层图）
class ResidualBlock(nn.Module):
    def __init__(self, in_ch, out_ch):
        super().__init__()
        self.prelu1 = nn.PReLU(in_ch)
        self.bn1 = nn.BatchNorm1d(in_ch)
        self.prelu2 = nn.PReLU(out_ch)
        self.bn2 = nn.BatchNorm1d(out_ch)
        # ... maxpool + add

    def forward(self, x):
        # ...

# 举例常量（真实逆向时从文件名/字段反推具体数字）
NUM_CLASSES = 3000      # App 类别数（embedding 输入维度）
NUM_OUTPUTS = 800       # multi-label 分类输出维度
NUM_WEEKS = 150         # install 数据时间窗（约 3 年）

class TargetModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.embedding = nn.Embedding(NUM_CLASSES, 128)
        self.conv1d = nn.Conv1d(128, 128, 1)
        self.blocks = nn.ModuleList([ResidualBlock(128, 128) for _ in range(7)])
        self.dense = nn.Linear(128, NUM_OUTPUTS)
        self.sigmoid = nn.Sigmoid()
    
    def forward(self, x):
        x = self.embedding(x).transpose(1, 2)
        x = self.conv1d(x)
        for b in self.blocks:
            x = b(x)
        x = x.max(dim=-1).values
        return self.sigmoid(self.dense(x))

model = TargetModel()

# Step 2: 从 weights_blob 切分装载
weights_blob = np.fromfile('target.model', dtype=np.float32, offset=0x100)  # 跳过 header
print(f'weights_blob 大小: {weights_blob.size} floats = {weights_blob.size * 4 / 1024:.1f} KB')

# Step 3: 按层顺序切分（需要从层图知道每层 shape）
param_names = list(model.state_dict().keys())
param_shapes = [model.state_dict()[n].shape for n in param_names]
param_sizes = [np.prod(s) for s in param_shapes]
total_expected = sum(param_sizes)
print(f'模型总参数: {total_expected}')

if weights_blob.size < total_expected:
    print(f'⚠️  weights_blob 比 expected 少 {total_expected - weights_blob.size}')
elif weights_blob.size > total_expected:
    print(f'⚠️  weights_blob 比 expected 多 {weights_blob.size - total_expected}（可能有未识别的层）')

# Step 4: 逐层装载
new_state_dict = {}
offset = 0
for name, shape, size in zip(param_names, param_shapes, param_sizes):
    tensor = torch.from_numpy(weights_blob[offset:offset+size].reshape(shape))
    new_state_dict[name] = tensor
    offset += size

model.load_state_dict(new_state_dict)

# Step 5: 推理验证
dummy_input = torch.randint(0, NUM_CLASSES, (1, NUM_WEEKS))
output = model(dummy_input)
print(f'输出 shape: {output.shape}')
print(f'输出统计: mean={output.mean():.3f}, max={output.max():.3f}, min={output.min():.3f}')
```

### 3.4 BN 4 参数顺序陷阱

BatchNorm 有 4 个参数：weight (gamma)、bias (beta)、running_mean、running_var。**不同框架顺序不同**：
- PyTorch: `[weight, bias, running_mean, running_var]`
- TensorFlow: `[gamma, beta, moving_mean, moving_variance]`
- TFLite: 可能是 `[mean, var, gamma, beta]` 或其他顺序

**症状**：如果 BN 顺序装错，模型 sigmoid 输出会**饱和到 0 或 1**（所有预测都是同一个类）。

**解法**：
1. 跑 4 种排列组合（4! = 24 种，但前两个通常固定，只试 4 种）
2. 用 KD 蒸馏（路线 3）自动修复
3. 反编译 native so 拿 BN struct 定义（最难，[08 章 LLM4Decompile](08-LLM辅助逆向.md)）

### 3.5 实证：自造 ResidualMLP 装载

```bash
cd 讲透AI系统逆向工程/experiments
python 07_weight_loader.py --mode residual_mlp
```

实验内容：
1. 自己 build 一个 ResidualMLP（embedding + 7 residual block + dense）
2. save 成"厂商格式"（一个 binary blob + tail strings）
3. 模拟"不知道 schema"，从 tail strings 反推层名
4. 用 vtable walker 拿 weights_offset
5. 切分装载回 PyTorch 模型
6. 与原模型对拍 1000 个输入，确认输出完全一致

## 四、路线 3：KD 蒸馏（动态对照）

### 4.1 适用场景

如果你**有真机能跑原模型**（哪怕是个 API），就可以用知识蒸馏：
- 把闭源原模型当 teacher
- 把你的 PyTorch 模型当 student
- 收集 (input, teacher_output) 对，监督学习

### 4.2 收集数据

```javascript
// Frida hook 推理 API
Interceptor.attach(target_native_forward, {
    onEnter: function(args) {
        // dump input tensor
        var input_data = read_tensor(args[1]);
        send({type: 'input', data: input_data});
    },
    onLeave: function(retval) {
        // dump output tensor
        var output_data = read_tensor(retval);
        send({type: 'output', data: output_data});
    }
});
```

跑 ~1000-10000 个真实输入，收集 (in, out) 对。

### 4.3 蒸馏训练

```python
import torch
import torch.nn.functional as F

# 加载装载好的 student（来自路线 2）
student = TargetModel()
student.load_state_dict(loaded_weights)

# 加载 (in, out) 对
pairs = load_pairs('frida_collected.jsonl')  # [{"input": [...], "output": [...]}, ...]

optimizer = torch.optim.Adam(student.parameters(), lr=1e-4)

for epoch in range(50):
    for pair in pairs:
        x = torch.tensor(pair['input'])
        y_teacher = torch.tensor(pair['output'])
        
        y_student = student(x)
        
        # KL 散度（softmax 输出）or MSE（sigmoid 输出）
        loss = F.mse_loss(y_student, y_teacher)
        
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
```

### 4.4 优势与局限

**优势**：
- 自动修复 BN 顺序错误（loss 会反推正确归属）
- 自动修复 PReLU 负斜率装错
- 不需要 schema 完全正确

**局限**：
- 需要真机（or Waydroid）
- 数据量要够（1000+ 对）
- teacher 模型输出可能受随机性影响（如 dropout——但端侧模型一般 determinism）

### 4.5 防御视角

Caliber 2026 等工作提出了**反蒸馏**防御——teacher 模型在输出里加 perturbation，让蒸馏出来的 student 性能下降。这反向提示我们：**如果 KD 训练死活学不到 95%+，可能厂商在输出里加了 perturbation**，需要走 SCA。

## 五、路线 4：侧信道攻击（SCA） ⚠️ 学术

### 5.1 适用场景

当所有上述方法都不行（模型完全闭源、无 API、加密太严），只能走硬件物理侧信道。**这条路是学术研究路线**，工程上 ROI 极低。

### 5.2 SOTA（2025-2026）

| 工作 | 目标 | 还原度 | 工作量 |
|------|------|--------|--------|
| **TCHES 2026** | MobileNetV1 | 88.4% | 数周（需要示波器/EM 探针）|
| **TCHES 2026** | 170 万参数 MLP | 93.2% | 数周 |
| **Kraken** | GPU Tensor Core | N/A | 远场 1 米 EM 探测 |
| **USENIX Security 2024 SoK** | DNN 综述 | — | 综述 |

### 5.3 物理设置

```
[目标设备] ─── 运行闭源模型
    │
    │  功耗 / 电磁辐射 / 时间
    ↓
[示波器 / EM 探针] ─── 采集侧信道信号
    │
    ↓
[分析算法] ─── 反推权重
```

### 5.4 为什么不推荐

- **硬件投入大**：示波器（~$5000+）、EM 探针、屏蔽室
- **时间成本高**：每个模型数周
- **法律灰区**：在他人设备上做 SCA 可能违法
- **可替代性**：99% 的端侧模型都能用路线 1-3 解决

只在以下情况考虑：
1. 学术研究（发论文）
2. 安全审计（厂商委托）
3. 极高价值目标（如关键基础设施）

## 六、模型量化恢复

### 6.1 INT8 量化

端侧模型常用 INT8 量化（模型大小减 4×，推理快 2-3×）。反推时遇到 INT8 模型：

```python
# 量化模型通常存储为:
# - quantized_weights: int8 数组
# - scales: float32 数组（per-channel 或 per-tensor）
# - zero_points: int8 数组

# 反量化回 float32:
def dequantize(q_weights, scales, zero_points, axis=-1):
    return (q_weights.astype(np.float32) - zero_points) * scales

# 装载到 PyTorch 时:
# 选项 1: 反量化成 float32 装载（最简单，准确度高）
# 选项 2: 用 torch.quantization 保持 INT8 推理（快但复杂）
```

### 6.2 per-channel vs per-tensor

- **per-tensor**：整个 tensor 一个 scale（最简单）
- **per-channel**：每个 output channel 一个 scale（更准，端侧主流）

反推时要先确定**用了哪种量化策略**——通常在 native so 的反汇编里能看到。

## 八、完整决策树

```
拿到一个闭源 .model / .vndl / .bin
    ↓
Step 1: strings 找源格式线索
    ├─ 找到 .tflite/.onnx → 路线 1（同构装载）
    └─ 找不到 → Step 2
    ↓
Step 2: vtable walker 反推 schema
    ├─ 反推成功 → Step 3
    └─ 反推失败 → 加密了，先去 [04 章 Frida] 找解密函数
    ↓
Step 3: 找开源等价模型
    ├─ 找到 → 路线 1（同构装载）
    └─ 找不到 → 路线 2（中段切分）
    ↓
Step 4: 装载 PyTorch + 推理
    ├─ 输出合理（mean/max/min 在合理范围）→ ✅ 完成
    └─ 输出饱和到 0/1 → BN 顺序错，走 Step 5
    ↓
Step 5: 修复 BN 顺序
    ├─ 试 4 种排列组合 → 任意一种 OK → ✅
    └─ 都不行 → 路线 3（KD 蒸馏）
    ↓
Step 6: 有真机能跑
    ├─ 有 → 路线 3（KD）
    └─ 没有 → 路线 4（SCA，学术）or [08 章 LLM4Decompile]
```
