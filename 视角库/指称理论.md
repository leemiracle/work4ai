# 🗣 指称理论视角

> 语言哲学核心一句话灵魂：**"专有名词是严格指示词（rigid designator）——它在所有可能世界中指称同一对象，不通过摹状词（涵义）中介；指称由一条从最初命名的因果历史链确定。"**（克里普克《命名与必然性》, 1980）。又：罗素**"当今法国国王是秃子"**（《论指称》, 1905）——有涵义但不指称的表达式如何可能？
>
> **为什么这个视角值得放进 AI 镜片库**：grounding 问题（符号接地）就是指称理论的当代 AI 版——**token 指称什么？** 一个 LLM 的"苹果"token 有 embedding（涵义），但**不自动指向**现实中的苹果或 Apple 公司（指称）。用指称理论看 AI，你会理解：**实体链接（entity linking）就是工程化的指称确定；幻觉实体=罗素"无指称摹状词"的 AI 复现；严格指示词解释了为什么模型对专有名词尤其容易产生幻觉——因为专有名词不通过摹状词约束。指称不是意义的附属品，是独立的、因果历史的、需要单独 grounding 的一层。**

---
## 是什么

| 命题 | 出处/原文 | 一句话 |
|------|----------|--------|
| **摹状词理论** | 罗素《论指称》(1905)："当今法国国王是秃子" | 限定摹状词不直接指称，需分析为存在量化句 |
| **严格指示词（rigid designator）** | 克里普克《命名与必然性》(1980) | 专有名词在所有可能世界中指同一对象，不靠摹状词 |
| **因果历史指称** | 克里普克/普特南：指称由命名仪式→因果传递链确定 | 名字指向谁，由历史因果链决定，非由内涵定义 |
| **涵义决定指称？** | 弗雷格：涵义→指称；克里普克：不一定 | 经典之争——指称是否由涵义"给出" |

**关键辨析**：罗素认为**限定摹状词**（"当今法国国王"）不直接指称对象，而要被分析为**存在量化句**（"存在一个且仅一个当今法国国王，且他是秃子"）——因此当法国没有国王时，句子**不为真也不为假**（预设失败）。克里普克进一步推翻了"涵义决定指称"的弗雷格—罗素传统（描述论/descriptivism）：**专有名词不是缩略的摹状词**（"亚里士多德"不等于"柏拉图的学生+亚历山大的老师"）——它是**严格指示词**，直接指称，指称由一条**因果历史链**（最初的"命名仪式"→代代传递的使用）确定，而非由任何描述性内涵确定。**这个区分对 AI 极关键**：如果指称不由涵义（embedding）决定，那 LLM 光靠 embedding **永远无法确定指称**——它需要额外的因果链（grounding/entity linking）。

---
## 怎么应用到 AI（6 个对应）

### 1. grounding 问题 = 指称理论的当代 AI 版
- Harnad (1990) 的符号接地问题（symbol grounding problem）：**纯符号系统（如 LLM）的 token 如何"指向"真实世界中的事物？** 这正是指称理论的核心问题——只是把"表达式如何指称对象"换成了"token 如何接地"。
- 一个 LLM 可以完美使用"猫"这个词（有意义/有 embedding），但它**不知道"猫"指称现实中哪种毛茸茸的动物**——除非通过多模态 grounding（CLIP 让"猫"的 embedding 对齐视觉中的猫图像）或实体链接（链接到知识库中"猫"的条目）。
- **核心洞察**：grounding 不是可选增强，而是**指称层的必要补全**。LLM 的纯文本训练只给了涵义层（Sinn），没有给指称层（Bedeutung）。

### 2. 实体链接（entity linking）= 工程化的指称确定
- 实体链接任务：给定文本中的"苹果"token，确定它指称知识库（Wikidata/Freebase）中的哪个实体——Apple Inc.（Q312）还是 apple（fruit, Q89）？**这就是确定指称（Bedeutung）**。
- 弗雷格问题在 AI 中的精确再现：同一个 token（"苹果"）在不同语境中**涵义可能相同（embedding 邻近）但指称不同**——需要 context disambiguation 来确定指称。实体消歧（entity disambiguation）= 指称确定的工程实现。
- 知识图谱（knowledge graph）的作用=**提供指称的锚定基础设施**：每个实体节点是一个稳定的指称目标，token 通过 entity linking 锚定到节点上，获得确定的指称。

### 3. 严格指示词 = 专有名词直接指称（无涵义中介）
- 克里普克：专有名词（"亚里士多德""爱因斯坦"）是**严格指示词**——它们在所有可能世界中指同一对象，**不通过摹状词（涵义）中介**。即使"亚里士多德"的所有已知摹状词（柏拉图的学生、亚历山大的老师……）都被推翻，这个名字**仍指称那个人**——因为指称由因果历史链确定，不由涵义确定。
- **AI 对应**：命名实体识别（NER）直接锚定实体类型，不需先理解其所有属性。但这也解释了**为什么 LLM 对专有名词尤其容易幻觉**——因为严格指示词不通过摹状词（属性约束）中介，模型没有"属性约束"来验证指称是否正确。模型可以自信地说"亚里士多德写了《理想国》"（混淆了柏拉图），因为**它没有一条因果链来锚定"亚里士多德"到底指谁**。

### 4. 摹状词理论 → slot filling / 属性填充 / 幻觉实体
- 罗素的摹状词分析："当今法国国王是秃子"="存在 x，x 是当今法国国王，且 x 是秃子"。当法国没有国王时，**存在量词失败**，句子无真值。
- **AI 对应**：当 LLM 生成关于**不存在的实体**的描述时（幻觉实体），相当于**摹状词无指称**——模型说"约翰·史密斯在 2018 年发表了突破性论文"（John Smith 从未存在过或从未发表过），这就是罗素"当今法国国王"的 AI 版：**有完整的描述内容（涵义），但不指称任何真实对象**。
- 检测幻觉实体的方法=**摹状词的指称验证**：提取模型生成的实体描述（摹状词），去知识库/搜索引擎中验证是否存在对应的真实指称。

### 5. 多义词 = 指称依赖 context
- 同一个 token 在不同 context 中指称不同对象：`"bank"` 在 `"I sat by the bank of the river"` 中指称河岸，在 `"I deposited money in the bank"` 中指称银行。词义消歧（word sense disambiguation, WSD）就是**确定当前语境下的指称**。
- 这呼应了描述论 vs 直接指称论之争：描述论说"bank 的不同涵义决定不同指称"；直接指称论说"指称不由涵义单独决定，需要因果链 + context"。**AI 工程实践**：WSD 既靠 embedding 相似度（涵义），也靠上下文窗口（context），还靠知识库验证（指称锚定）——三者缺一不可。

### 6. 因果历史指称 → 训练数据的因果链 / 数据溯源
- 克里普克的因果历史理论：一个名字的指称由一条**从最初"命名仪式"（baptism）到当前使用的因果传递链**确定。我之所以用"亚里士多德"指称那个人，是因为我从别人那里学到了这个名字，别人又从更早的人那里学到……追溯到最初的命名。
- **AI 对应**：一个概念在 LLM 中的"指称"可以追溯到**训练语料中的因果使用链**——"猫"这个 token 在模型中的"指称"来自训练数据中所有包含"猫"的文本，这些文本又来自真实世界中对猫的描述……**数据溯源（data provenance）= 指称溯源**。
- 这也是为什么**数据污染/数据投毒**会扭曲指称：如果训练语料中的"猫"被系统性替换为"狗"的图片描述，模型的"猫"token 就会**指称错对象**——因果链被篡改，指称偏移。

## 反直觉发现

1. **grounding 问题不是新难题，是 2500 年指称争论的 AI 版**。从弗雷格（涵义决定指称）到罗素（摹状词分析）到克里普克（因果历史指称），哲学家们争论了上百年的"表达式如何指称对象"，在 AI 中变成了"token 如何接地"。**符号接地问题（Harnad 1990）与克里普克的指称理论是同一个问题的两个面孔**——只是一个用哲学语言，一个用工程语言。

2. **专有名词"无涵义"（克里普克）= 为什么 LLM 对专有名词尤其容易幻觉**。严格指示词不通过摹状词（属性约束）中介——所以模型**没有属性约束来验证**"亚里士多德"到底指谁。模型可以自信地说出完全错误的归属（"亚里士多德写了《理想国》"），因为**它对专有名词的"指称"缺乏因果链锚定**。普通名词（"猫"）有丰富的属性分布来约束指称；专有名词没有——这就是幻觉的不对称分布的哲学根。

3. **幻觉实体 = 罗素"当今法国国王"的 AI 复现**。罗素说"当今法国国王是秃子"不指称任何对象（预设失败）；LLM 生成"约翰·史密斯发表了突破性论文"（约翰·史密斯不存在）也不指称任何对象。**两者都是"有涵义（描述内容）但无指称（不指向真实对象）"**。检测幻觉实体=摹状词的指称验证——去知识库查这个"摹状词"是否有真实对应物。

4. **多模态 grounding = 给 token 装上"指称"的因果链**。CLIP/BLIP 等多模态模型让"猫"这个词**指向**视觉中的猫图像——这是因果历史指称的工程重建：通过视觉-文本对齐，建立了 token 到感知对象的"命名链"。**纯文本 LLM 的 token 没有这条链，所以指称悬空；多模态模型补上了这条链，指称落地**。

5. **数据溯源 = 指称溯源**。克里普克说名字的指称由因果历史链确定；AI 中，一个 token 的"指称"由训练数据的因果链确定。**数据污染/投毒扭曲因果链 = 指称偏移**。这也是为什么"数据来源透明"不只是工程规范，而是**指称正确性的哲学前提**——没有可追溯的因果链，就没有可靠的指称。

6. **涵义≠指称意味着"语义对齐"≠"指称对齐"**。两个模型可以用相似的 embedding（近涵义）来表示"自由"，但如果训练语料的因果链不同（一个来自自由主义传统，一个来自集体主义传统），它们的"自由"**指称的现实政治实践不同**。跨文化/跨模型的对齐不仅要对齐 embedding（涵义），还要对齐指称（因果链）——**涵义对齐 ≠ 指称对齐**。
