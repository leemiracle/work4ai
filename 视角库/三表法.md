# 🪶 三表法视角

> 墨子《非命》一句话灵魂：**"言必立仪。言而毋仪，譬犹立朝夕于运钧之上也。"** 言论必须确立检验标准（"仪"），否则就像在转动的陶轮上测日影——毫无准信。墨子提出判断真伪的**三表法**：**本之**（考历史先例/已有知识）、**原之**（察百姓耳目之实/直接观测）、**用之**（实际施政检验效果）。
>
> **为什么这个视角值得放进 AI 镜片库**：三表法是世界上最早的**三重实证认识论**，比近代"假设-实验"更全面——它同时要求理论依据（本之）、经验数据（原之）、**部署效果（用之）**。今天大量 AI 论文只做了前两表（在 benchmark 上本之原之），却跳过第三表（真实部署是否"中百姓人民之利"）。三表法 = **数据驱动 + 可复现 + 部署闭环**的完整方法论。墨子 2500 年前就指出：脱离"用之"的漂亮 benchmark 是"立朝夕于运钧之上"——自欺。

---

## 是什么

《墨子·非命》中判断言论真伪的三条标准（三表/三法）：

| 命题 | 原文 | 一句话 |
|------|------|--------|
| **本之** | "上本之于古者圣王之事" | 考察历史先例与已有知识体系 |
| **原之** | "下原察百姓耳目之实" | 考察直接经验与观测事实 |
| **用之** | "废以为刑政，观其中国家百姓人民之利" | 实际应用，检验真实效果 |

**关键辨析**：三表法**三表缺一不可**——只有"本之"是教条主义（只引经据典不看现实），只有"原之"是经验主义（有数据无理论框架），只有"用之"是实用主义（短视于眼前效果）。墨子要求三者合一，本质是**反教条、反空想、强调闭环验证的实证主义**。最被忽视的是第三表"用之"——许多 SOTA 模型在前两表（benchmark）无敌，却在真实部署中失效。

---

## 怎么应用到 AI（6 个对应）

### 1. "本之" = 先验知识与基线
- 训练/设计前先考"古者圣王之事"= 已有文献、SOTA、benchmark、理论框架。pre-training 语料是"本之于前人积累"——迁移学习的知识源头。
- 但"本之"必须被后两表校验：直接照搬预训练知识而不验证 = 教条（"立朝夕于运钧之上"）。

### 2. "原之" = 经验数据与观测
- 用真实数据（"百姓耳目之实"）校验，而非空想。supervised data、empirical evidence、ablation study——都是"原之"的体现。
- 数据驱动（data-driven）的精髓就是"原之"：一切结论要回到观测数据上站住脚，不接受"我觉得"。

### 3. "用之" = 部署反馈闭环
- 模型上线后观测真实效果（"中国家百姓人民之利"）= online evaluation、A/B testing、RLHF feedback loop、用户满意度。
- **这是最被 AI 学术界忽视的一表**：大量论文止步于 benchmark，从不验证"用之"。墨子指出——脱离"用之"的 benchmark 是自欺。

### 4. 三表合一 = 实证主义 AI 的完整方法论
- 优秀的 AI 研究同时满足三表：**有理论依据（本之）+ 有实验数据（原之）+ 有真实部署效果（用之）**。缺任一表都是"立朝夕于运钧之上"。
- 这也定义了 production-ready 的标准：只在 benchmark（原之）过线不够，必须经"用之"的部署检验。

### 5. 可复现性 = 三表的公共性
- 三表法的精髓是"可被他人验证"——如果只有你能复现"原之""用之"，它就不是公共知识。reproducible research（开源代码/数据/checkpoint/seed）让他人也能"原之""用之"。
- reproducibility crisis 的根源正是"原之"无法被独立复现——三表法天然要求开放可复现。

### 6. Anti-benchmark-overfitting = 反"只有原之"
- benchmark overfitting（在公开榜单上过拟合）= 只有"原之"（在特定数据上刷分）而无"用之"（真实泛化）。三表法要求**held-out / OOD / 真实部署**作为第三表来戳破 benchmark 幻觉。
- contamination 检测、动态 benchmark（live benchmark）都是为"用之"补的课。

---

## 反直觉发现

1. **三表法比近代"假设-实验"更全面**。它要求**理论（本之）+ 数据（原之）+ 部署（用之）三重验证**——许多 AI 论文只有前两表（benchmark），缺第三表（真实世界效果）。墨子 2500 年前就指出了这个学术盲区。

2. **"用之"是最被忽视却最重要的一表**。SOTA 模型在 benchmark 无敌（本之原之都过），部署后用户却不买账（用之失败）。Goodhart 定律（"指标一旦成为目标就不再是好指标"）正是"用之"缺位的后果——benchmark 是手段，"国家百姓人民之利"才是目的。

3. **ablation study 不够格作为完整验证**。ablation 只验证"原之"（组件在数据上的贡献），却不验证"用之"（组件在真实部署中的价值）。一个 ablation 上重要的组件，可能在部署中是噪声——三表法逼你跨出 benchmark。

4. **"本之于古者圣王"对应 transfer learning 的两面性**。复用预训练知识（前人积累）是高效的"本之"，但它**必须被"原之""用之"校验**——否则就是教条搬运。盲目全量微调一个不适配的预训练 backbone = 只本之不原之不用之。

5. **三表法是 anti-hallucination 的元方法**。模型自身也需要三表来对抗幻觉：**本之**（训练知识先验）+ **原之**（RAG 检索 grounding，给模型"百姓耳目之实"）+ **用之**（tool use / 代码执行验证效果）。RAG 的本质就是给模型"原之"的能力，让它不只靠"本之"臆断。

## Prompt 模板

```
你是精通《墨子·非命》三表法的墨家认识论分析专家。
用"三表法"视角分析 AI 概念 [X]：

1. [X] 的"本之"（理论依据/先验知识/已有基线）是什么？它是否有坚实的理论或前人积累支撑？
2. [X] 的"原之"（经验数据/观测/实验）做得扎实吗？数据是否真实、可复现、无污染？
3. [X] 的"用之"（真实部署效果/用户价值）有人验证吗？还是只停在 benchmark 自嗨？——这是最关键的一问。
4. [X] 在哪一表上最薄弱？是教条（只有本之）、是数据虚浮（只有原之）、还是脱离实际（缺用之）？
5. 如果给 [X] 补齐缺失的表（比如补做部署 A/B 或 held-out OOD 验证），结论会不会反转？

约束：落到 [X] 具体技术细节；至少 1 个反直觉洞察；重点拷问第三表"用之"。
```
