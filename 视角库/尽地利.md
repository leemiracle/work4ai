# 🌾 尽地利视角

> 农家一句话灵魂：**"因地制宜，地尽其利。"** 同样的作物，在不同土壤、水肥、坡向条件下，耕法不同；一寸土一寸力，把每一分地利榨干。现代翻译：算力/硬件是稀缺的"地"，**算法要和硬件协同**，把每 FLOP、每字节带宽、每焦耳都用到位——绿色 AI、效率优先。
>
> **为什么这个视角值得放进 AI 镜片库**：算力是稀缺"土地"。忽视硬件特性写"教科书式最优"算法，就像在盐碱地按沃土耕作。Flash Attention、KV cache、量化、稀疏化、kernel fusion——全是"尽地利"：让算法**贴着硬件的物理极限**走。不会量地力（roofline），就耕不好这块地。

---

## 是什么

农家与农书关于"地利"的核心命题：

| 命题 | 原文/出处 | 一句话 |
|------|-----------|--------|
| **因地制宜** | 《齐民要术》"顺天时，量地利" | 土地不同则耕法不同 |
| **地尽其利** | 《管子》重地力；一寸不空 | 把每分地利榨到极致 |
| **改良土壤** | 持续培肥、轮作、水利 | 持续优化算力栈与基础设施 |
| **间作套种** | 立体利用光水土 | 资源复用、时空重叠利用 |

**关键辨析**："尽地利"不是"在烂地上硬耕"，而是**先量地力（profile / roofline），再让耕法贴地而行**。一块地是 compute-bound 还是 memory-bound，决定了"最优算法"长什么样。脱离硬件谈算法最优，是悬浮式的纸上谈兵。

---

## 怎么应用到 AI（6 个对应）

### 1. 硬件感知算法 = 因地制宜
- Flash Attention 贴 SRAM、kernel fusion 贴带宽、tensor core 友好的 layout——都是"让算法贴着这块地长"。
- "教科书最优"的 O(n²) attention 在真实 GPU 上被"近似但贴硬件"的 IO-aware 算法吊打。

### 2. 绿色 AI / 能效 = 尽地利
- 每 FLOP、每焦耳都要榨出价值。能效（FLOPs/W, tokens/J）是"亩产"。
- 绿色 AI 不是道德口号，是"地尽其力"的工程必然——省下的算力就是多出的"地"。

### 3. 量化 / 蒸馏 / 剪枝 = 培肥与精量
- 用更少"地"（更少 bit、更少参数）养同样的"苗"（能力）：INT8/INT4 量化、知识蒸馏、结构化剪枝。
- 这是"以更薄的地力维持产量"的精量农业。

### 4. 混合精度 / 张量并行 / 流水并行 = 间作套种
- 混合精度立体利用硬件数值单元；张量/流水/数据并行把多卡"间作"起来——**立体利用，时空重叠**。
- 通信与计算 overlap（compute-comm overlap）就是典型的"套种"：让总线不闲着。

### 5. Roofline 分析 = 量地力
- 先 profile：这块"地"是 compute-bound 还是 memory-bound？peak FLOPS 与 peak bandwidth 在哪？
- 不量地力就调算法，等于盲耕。性能瓶颈（bottleneck）决定了该优化什么。

### 6. 推理引擎 = 针对不同硬件的精耕农具
- vLLM / SGLang / llama.cpp / TensorRT-LLM——针对 GPU/CPU/NPU/边缘设备各自的"地性"定制。
- 同一模型换硬件（GPU→NPU→手机），最优配置（batch、KV layout、量化策略）完全不同 = 因地制宜。

---

## 反直觉发现

1. **"理论上最优"的算法，在真实硬件上常常跑不过"贴硬件的近似算法"**。Flash Attention 不是数学更优，是 IO-aware 更优——地利使然。

2. **算力效率的提升，往往比算法新颖性更值钱**。把吞吐翻倍，等于免费多了一倍"地"，且可复利叠加。

3. **同一模型换硬件，最优配置完全不同**。GPU 上的王者在 NPU/手机上可能又慢又废——不"因地制宜"就吃哑巴亏。

4. **绿色 AI 不是牺牲性能，而是性能的另一面**。能效高的部署，往往也是成本最低、延迟最低的部署——地利与利他统一。

5. **"量地力"本身是被低估的工程能力**。会 profile、会读 roofline、会定位 compute/memory bound 的工程师，比会背论文的更"会种地"。

## Prompt 模板

```
你是精通农家"尽地利"思想的系统效率分析专家。
用"尽地利"视角审视 AI 系统/部署 [X]：

1. [X] 这块"地"是什么硬件？compute-bound 还是 memory-bound？量一量地力（roofline）。
2. [X] 当前的算法/配置，是"贴着硬件长"还是"教科书悬浮式"？哪里可以 kernel fuse / IO-aware？
3. [X] 哪些"培肥精量"手段（量化/蒸馏/剪枝/稀疏）能以更少地力维持产量？
4. [X] 哪些资源在闲置（带宽/总线/显存/算力单元）？能否"间作套种"（overlap / 立体复用）？
5. [X] 的"亩产"（tokens/J、tokens/$、throughput/latency）还有多少榨取空间？

约束：落到 [X] 的具体硬件/算子/带宽/显存细节；至少 1 个反直觉洞察。
```
