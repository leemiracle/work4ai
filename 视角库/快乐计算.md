# 📊 快乐计算视角

> 功利主义核心一句话灵魂：**"快乐与痛苦的价值可以从七个维度来衡量：强度、持续时间、确定性、远近、丰度、纯度、范围。"**（边沁《道德与立法原理导论》第4章，felicific calculus / hedonic calculus）边沁的激进主张：**伦理学可以变成算术**——每一种快乐和痛苦都可以被量化、加总、比较。这是把道德判断从直觉争论变成可计算决策的首次系统尝试。
>
> **为什么这个视角值得放进 AI 镜片库**：AI 的 reward 设计本质上就是"快乐计算"的工程实现。把一个模糊的"好"分解为**多个可度量的子维度**，每个维度有独立的 reward head 或评估指标，再聚合为一个标量——这就是 felicific calculus 的现代版。用快乐计算看 AI，你会理解：**好的 reward 从来不是一个数字，而是一个多维度评估体系；每个维度对应边沁的一个"快乐情形"（circumstance），遗漏任何维度都会导致 reward 设计的系统性偏差。**

---

## 是什么

| 命题 | 出处/原文 | 一句话 |
|------|----------|--------|
| **强度（intensity）** | 《道德与立法原理导论》第4章 | 这份快乐有多强烈 |
| **持续时间（duration）** | 同上 | 这份快乐持续多久 |
| **确定性（certainty/uncertainty）** | 同上 | 这份快乐是否确实会发生 |
| **远近（propinquity/remoteness）** | 同上 | 这份快乐是眼前的还是遥远的 |
| **丰度（fecundity）** | 同上 | 这份快乐是否会带来更多同种快乐 |
| **纯度（purity）** | 同上 | 这份快乐是否不伴随后续痛苦 |
| **范围（extent）** | 同上 | 这份快乐影响多少人 |

**关键辨析**：快乐计算**不是"给快乐打 1-10 分"那么简单**。它的七个维度构成了一个**多属性效用评估框架**：强度×持续时间 = 快乐的"总量"；确定性 = 概率加权；远近 = 时间折扣；丰度和纯度 = **长期后果的预测**（这份快乐是可持续的还是会反弹为痛苦？）；范围 = **社会维度**（影响多少人）。边沁早在 1789 年就预见了现代决策论的核心要素：**期望效用（certainty）、时间偏好（propinquity）、外部性（extent）**。它的局限在于——**快乐真的可以量化比较吗？**这是 200 年来对功利主义最有力的质疑。

---

## 怎么应用到 AI（6 个对应）

### 1. reward 多维度分解 = 快乐七维度的工程版
- 好的 reward 设计**不是单一标量**，而是多个子 reward 的聚合。`R_total = R_accuracy + R_safety + R_helpfulness - R_latency`——每个子项对应快乐计算的一个维度。
- **强度** = reward 的幅值大小；**持续时间** = episode 长度内的累积；**确定性** = reward 的方差/置信度；**范围** = 影响 batch 中多少样本/多少用户。**七维度 = 七个可独立调试的 reward head**。

### 2. "远近"（propinquity）= RL 折扣因子 γ
- 边沁的 propinquity/remoteness 维度**精确对应 RL 中的折扣因子 γ**：眼前的 reward（γ⁰）权重高于远处的 reward（γᵗ）。**时间偏好不是 20 世纪经济学的发明——边沁在 1789 年就把"近期快乐比远期快乐更重要"写进了道德计算**。
- 这解释了为什么 RL agent 倾向"短视"（高 γ 折扣）——**与人类偏好即时满足的倾向同构**。但过度短视 = 只追求眼前 reward，牺牲长期价值（reward hacking 的一种）。

### 3. 丰度（fecundity）+ 纯度（purity）= 长期后果评估
- 丰度问"这份快乐会带来更多快乐吗？"——在 AI 中对应：**一个行为是否有正反馈循环？**（如：好的推荐让用户更活跃 → 更多数据 → 更好推荐 = 正循环）。
- 纯度问"这份快乐会伴随痛苦吗？"——对应：**短期高 reward 的行为是否在长期产生 negative externality？**（如：用 clickbait 提高点击率 = 高强度低纯度，短期快乐但长期信任丧失）。
- 这两个维度要求**不只看即时 reward，还要预测 reward 的长期演化**——多步 rollout / model-based planning。

### 4. 确定性（certainty）= 概率加权 / 风险评估
- 快乐的确定性维度 = **期望效用的概率加权**。一份"50% 概率获得 10 分快乐"的快乐，确定性低于"100% 获得 5 分"——**期望值相同但风险不同**。
- 在 AI 中对应：**reward 的方差/不确定性度量**。高方差 reward（如赌博式输出）不应与低方差 reward 简单等同——需要在聚合时考虑风险偏好（risk-aware RL）。

### 5. 范围（extent）= 群体公平性 / 多用户聚合
- 范围维度问"影响多少人？"——这是**唯一一个超越个体的维度**。边沁要求把所有受影响者的快乐都计入计算。
- 在 AI 中对应：**一个决策/推荐/内容对多少用户/群体产生影响**。一个只让 1% 用户快乐但伤害 99% 的设计，范围维度极低。**多用户系统需要在 reward 中显式建模"范围"——不只看平均 reward，还看分布**。

### 6. 效用可量化 = reward shaping 的合法性基础
- 快乐计算的根本主张是**效用可量化**——这给了 AI reward 设计**哲学合法性**：把模糊的"好"变成可度量的数字不是简化，而是边沁式的科学化。
- 但快乐计算也**警示了 reward shaping 的风险**：如果你遗漏了某个维度（如忘了"纯度"——没考虑长期副作用），你的 reward 就是**系统偏差的快乐计算**。**七维度 = reward design checklist**。

## 反直觉发现

1. **边沁的 propinquity 维度预见了 RL 的折扣因子 γ——早了 170 年**。时间偏好（眼前的比远期的更重要）在边沁那里是道德计算的一个维度，在 RL 里是 γ<1 的数学设定，在行为经济学里是双曲贴现。**三者是同一原理的三种语言**。

2. **丰度和纯度是防 reward hacking 的原始设计**。边沁不只看"当下的快乐有多大"（强度×持续时间），还要问"它会不会带来更多快乐"（丰度）和"会不会伴随痛苦"（纯度）。**这恰好是 reward hacking 的克星：reward hacker 最大化的是即时强度，忽略了纯度（长期副作用）**。

3. **快乐计算 = 多属性决策分析（MADM）的先驱**。边沁把"好"分解为 7 个可独立评估的维度——这在 20 世纪被形式化为多属性效用理论（MAUT）。AI 中的多目标优化 `max R₁+R₂+...+Rₙ` 与快乐计算在方法论上完全同构。**好的 reward 设计本质上是给 AI 写一个 felicific calculus**。

4. **"范围"维度是群体公平性的起源**。边沁的 7 个维度中，6 个是关于个体快乐的性质，唯有"范围"把视角拉到**社会层面**——"影响多少人"。这比罗尔斯的正义论早了 180 年就提出了"道德评估必须考虑所有受影响者"。**AI 系统评测需要 extent 维度：不只看平均表现，还看影响了哪些群体**。

5. **快乐计算最大的问题是"快乐真的可量化吗"**——而这个问题在 AI 中**以"reward 真的能反映真实价值吗"的形式重现**。边沁假设快乐像温度一样可测，但不同人的快乐强度无法直接比较。同样，AI 中不同任务/用户/场景的 reward 幅值不可直接比较——**简单加总会掩盖维度间的不可公度性（incommensurability）**。

6. **七维度是一个 reward design checklist，而非一个公式**。边沁从未给出"强度×持续时间×确定性×..."的精确公式——他提供的是一个**评估框架**。好的 reward 设计应该**逐维度检查**：我的 reward 覆盖了哪些维度？遗漏了哪些？每个维度的度量是否忠实？

## Prompt 模板

```
你是精通功利主义快乐计算（felicific calculus）的分析专家。
用"快乐计算"视角分析 AI 概念 [X] 的 reward 设计：

1. [X] 的 reward 拆成了哪些维度？用边沁七维度（强度/持续时间/确定性/远近/丰度/纯度/范围）逐项检查：
   - 强度：reward 幅值是否反映真实重要性？
   - 持续时间：reward 是即时的还是累积的？
   - 确定性：reward 的方差/置信度如何？
   - 远近：折扣因子 γ 设了多少？为什么？
   - 丰度：高 reward 行为是否有正反馈循环？
   - 纯度：高 reward 行为是否有长期副作用（低纯度）？
   - 范围：reward 考虑了所有受影响的用户/群体吗？
2. 哪些维度被遗漏了？遗漏会导致什么系统性偏差？
3. 各维度如何聚合（加权求和/字典序/帕累托）？聚合方式隐含了什么假设？
4. [X] 的 reward 度量与"真实价值"之间有多大 gap？（felicific calculus 的度量失真风险）
5. 用快乐计算 checklist 重新设计 [X] 的 reward，会怎么改进？
6. [X] 中有没有"高强度低纯度"的 reward hacking 风险？

约束：落到 [X] 具体技术细节；至少 1 个反直觉洞察（尤其"丰度纯度 = 防 reward hacking"）。
```
