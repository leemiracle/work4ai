# 19 · 调与改：系统化调参 + 改造模型

> 模型效果不达标时，新手随机改学习率（炼丹），老手**系统化排查**。本章给你两套东西：一是"模型不达标时按什么顺序查"的**排查流程**（反炼丹），二是"怎么改造模型适配新需求"的**三把刀**（微调/剪枝/蒸馏）。深实操指向 `讲透微调`/`讲透复用权重`/`讲透端侧AI压缩`，本章只讲**决策与方法论**。

## 19.1 反炼丹：模型不达标时的排查流程

模型效果差，**不要先动超参**。按这个顺序查（前面没问题的，才查后面）：

```
1. 数据 ──→ 2. 评估 ──→ 3. 损失/目标 ──→ 4. 训练动态 ──→ 5. 超参 ──→ 6. 架构
   (80%的问题在这)        (经常错)          (loss曲线)       (最后才动)     (几乎从不需要)
```

### ① 数据（80% 的问题在这）
- **标注对吗？** 抽 20 条人工核对——标注错误率常超 10%。
- **数据覆盖真实分布吗？** 训练集和线上样本长得像吗？（分布漂移是头号杀手）
- **类别平衡吗？** 长尾会让模型偏向多数类。
- **数据量够吗？** < 100 条别想微调，去 few-shot/API。

### ② 评估
- **测试集干净吗？** 训练集和测试集有没有泄漏？（见 Ch14）
- **指标选对了吗？** 不平衡数据用 accuracy 会骗人，用 F1/PR-AUC。
- **错误分析**：看具体错例，是哪一类系统性地错？

### ③ 损失/目标
- **目标函数对吗？** 分类用 CE，回归用 MSE，生成用 seq2seq loss——选错全完。
- **微调任务和预训练目标差太远吗？** 差太远需要更多数据/更多层解冻。

### ④ 训练动态（看 loss 曲线）
- **train loss 不降** → 学习率太小 / 数据有问题 / 代码 bug。
- **train 降 test 升** → 过拟合（加正则/减模型/加数据）。
- **loss 突然 NaN** → 学习率太大 / 数值溢出（见 Ch13 临界点）。
- **震荡** → batch 太小 / 学习率太大。

### ⑤ 超参（最后才动）
- 学习率、batch size、epoch、warmup、weight decay。
- **调参的正确方法**：网格/随机/贝叶斯搜索，**固定种子、报方差**（见 Ch14）。
- 别在一个 seed 上调到最优就信——换个 seed 可能全变。

### ⑥ 架构（几乎从不需要改）
- 90% 的情况下，**换数据/换方法比换架构有效**。架构是最后选项。

> **反炼丹的核心**：**先查数据和评估，最后才动超参**。新手浪费 80% 时间在第 ⑤ 步，而问题其实在 ①。

## 19.2 微调方法决策

确定要微调后，选哪种？决策表：

| 方法 | 何时用 | 成本 | 指向 |
|------|--------|------|------|
| **Prompt + Few-shot** | 标注 < 100，任务简单 | 极低 | `讲透Prompt` |
| **LoRA** | 有 1k-100k 标注，领域适配 | 低（省 10-100× 算力）| `讲透微调` |
| **QLoRA** | 显存极紧（消费级 GPU）| 极低 | `讲透微调` |
| **全量微调** | 有大量数据 + 任务和预训练差远 | 高 | `讲透微调` |
| **DPO/RLHF** | 对齐人类偏好（不只准，还要"好"）| 中 | `讲透RL`/`讲透基础模型` |

**经验法则**：
- **从 LoRA 开始**。90% 的领域适配，LoRA（rank 8-64）够用。不够再升全量。
- **QLoRA 是消费级 GPU 的救星**：4-bit 量化 + LoRA，让 7B 模型在单张 24G 卡上微调。
- **DPO 用于"风格/偏好"**：当你想让模型"更礼貌""更简洁"（偏好问题），而非"更准"（能力问题）。

## 19.3 改造模型的三把刀

模型已训好，但要适配新需求——三把刀：

### 刀一：微调适配（改权重）
用你的领域数据继续训练。**LoRA 是首选**——只训少量参数，省且稳。见 §19.2。

### 刀二：结构压缩（改大小）
模型太大/太慢，要变小：
- **剪枝（Pruning）**：去掉不重要的权重/神经元。结构化剪枝（去整层/head）有实际加速。
- **蒸馏（Distillation）**：大模型（教师）教小模型（学生），学生学到接近的能力但小得多。
- **量化（Quantization）**：FP16→INT8→INT4，显存/速度大降，精度小降（见 Ch20）。

> **何时用哪把**：要部署到端侧 → 量化优先（最省）；要架构变小 → 蒸馏；要去冗余 → 剪枝。常组合（如 QLoA = 量化+蒸馏）。深细节见 `讲透端侧AI压缩`/`讲透复用权重`。

### 刀三：推理时干预（不改权重，改行为）
**这是本系列 Part II 给你的独特武器**：
- **Activation Steering**：在推理时给激活加/减一个方向，**实时改变模型行为**（Ch06 的概念方向）。例：加"礼貌方向"让回答更礼貌，不用重训。
- **Refusal direction 调节**：找到"拒绝方向"，可控地调强/调弱（Arditi 2024）。
- **Constrained generation**：用语法/正则约束输出格式（如强制 JSON）。

> **刀三的价值**：不重训、即时生效、可逆。当你只想"改行为不改能力"时，比微调高效 100 倍。这是"理解模型（Part II）→ 驾驭模型（Part IV）"的直接转化。

## 19.4 调参经验法则（哪些值得调，哪些别动）

**值得花时间调的（影响大）：**
- 学习率（最重要，对数尺度搜：1e-5, 3e-5, 1e-4, 3e-4）
- 训练数据的质量和数量（永远第一优先）
- LoRA rank（8/16/32/64）

**基本别动的（影响小或已有默认）：**
- batch size（按显存填满即可）
- warmup steps（总步数的 3-10%）
- weight decay（0.01 默认）
- 优化器（AdamW 默认，除非有理由换）

**别陷入的陷阱：**
- 调 20 个超参找最优——**过拟合到验证集**（见 Ch14 Goodhart）。
- 只调不验证机制——**换 seed 全崩**（报方差！）。

## 19.5 批判

- **调参有天花板**：数据差，怎么调都差。**数据 > 调参**，永远。
- **微调不是万能**：基座模型本身没有的能力，微调学不出来（如 0.5B 模型微调不出 GPT-4 级推理）。
- **压缩有代价**：量化/剪枝会掉精度，**玩具模型看不出损失，真实大模型才明显**（项目铁律）。
- **steering 不稳定**：方向找不准会误伤其他能力，需要仔细验证。
