# 01 · 通用办公 / 知识工作场景

> 知识工作者 60% 的时间耗在"读、写、找、整理"信息。这是 AI 渗透最深、ROI 最快的区域。本类 5 个场景几乎人人适用。

---

### 场景 1：文档摘要 / 信息抽取 / 问答
- **痛点**：每天读大量报告/合同/论文/邮件，提取要点耗时。
- **输入 → 输出**：长文档 → 摘要 / 结构化字段 / 针对性问答。
- **模型方案**：**API + prompt** 起步；文档常变/私有 → **RAG**（`讲透RAG`）。多数场景不需要微调。
- **真实案例**：**Sanofi** Concierge（Bedrock）—— 1100 万次对话/季，90% 好评，90.5% 员工报告省时，有人把某项核验任务时间砍 92%（AWS case，2026）。
- **工具栈**：Claude/GPT API + LangChain/LlamaIndex；私有 → Bedrock Knowledge Bases / Vertex AI Search。
- **陷阱**：长文档超上下文窗口 → 分块 + RAG；摘要遗漏关键数字 → 加"必须包含数字"约束。
- **起步 MVP**：把一份你常读的报告喂给 API，要"3 个要点 + 关键数字表"。1 小时。

### 场景 2：写作辅助（邮件 / 报告 / 改写）
- **痛点**：写邮件、周报、对外文案耗时；语气/格式反复改。
- **输入 → 输出**：要点/草稿 → 润色后的成文。
- **模型方案**：**API + few-shot prompt**（`讲透Prompt`）。风格统一 → 存"风格示例"做 few-shot。
- **真实案例**：**Sanofi** Concierge 让员工秒生成原本要外包给代理的内容（AWS，2026）；**Rippling** action agent 自动规范化职位/层级（LangChain，2026）。
- **工具栈**：ChatGPT Enterprise / Claude；批量 → API + 模板。
- **陷阱**：模型写得"对但空" → 给具体的受众/目的约束；机密内容别上公网 API（用企业版/私有部署）。
- **起步 MVP**：写一个"邮件助手"prompt（含你的语气样本），试 5 封真实邮件。

### 场景 3：会议纪要（录音转写 + 待办提取）
- **痛点**：开会 1 小时，整理纪要 1 小时；待办遗漏。
- **输入 → 输出**：会议录音/字幕 → 结构化纪要 + 决策项 + 待办（责任人/截止）。
- **模型方案**：**语音转写（Whisper）+ LLM 抽取**。待办结构化 → 加 JSON schema 约束输出。
- **真实案例**：这是 2026 办公场景的标配；**Rivian** 用 agent 把会议/SOP 转成可执行工作流（AWS，2026）。
- **工具栈**：Whisper / AssemblyAI 转写 + GPT/Claude 抽取；会议工具（Otter/Fireflies/钉钉飞书 AI）。
- **陷阱**：多人会议发言人混淆 → 用 diarization；术语识别错 → 喂术语表。
- **起步 MVP**：录一次周会，用 Whisper 转写 + LLM 抽"3 决策 + 5 待办"。

### 场景 4：信息检索与综合（研究 / 竞品 / 综述）
- **痛点**：要做竞品分析/行业综述/文献调研，信息散落几十个来源。
- **输入 → 输出**：研究问题 → 多来源综合 + 对比表 + 引用。
- **模型方案**：**RAG + Agent**（检索→阅读→综合→引用）。需要联网 → 加搜索工具（`讲透Agent`）。
- **真实案例**：**Jefferies** 交易助手（Bedrock + Strands + MCP）让交易员用自然语言查"美国交易板块分布"，agent 自动生成 SQL + 可视化（AWS，2026）。
- **工具栈**：Perplexity/ChatGPT 搜索；自建 → LangGraph/LlamaIndex + 搜索 API + RAG。
- **陷阱**：模型编造引用 → 强制引用真实 URL；来源过时 → 加日期过滤。
- **起步 MVP**：用 Perplexity 做一个竞品对比，再检查每个引用是否真实可点。

### 场景 5：数据清洗 / 标注 / 结构化
- **痛点**：脏数据（格式不一、字段缺失、半结构化文本）占数据工作 80% 时间。
- **输入 → 输出**：脏数据 → 清洗/标注/结构化的干净表。
- **模型方案**：**API 批量处理**（结构化抽取）；量大/领域固定 → **微调小模型**（省成本）。
- **真实案例**：**Trustpilot** fine-tune Gemma-2-9b 处理百万级评论/日的 NER/情感/分类，性能接近 Gemini 教师模型，成本用固定基础设施替代 per-token 计费（Google Cloud，2026）。**Wayfair** 用单个 OpenAI 模型修正 250 万商品标签，覆盖 100 万商品，属性补全速度 ×70（OpenAI，2026）。
- **工具栈**：LLM 抽取 + Pydantic/JSON schema 校验；量大 → 蒸馏小模型 + vLLM 服务。
- **陷阱**：LLM 输出格式不稳定 → 用 structured output/function calling + schema 校验；量大用大模型烧钱 → 蒸馏。
- **起步 MVP**：用 LLM 把 100 条脏文本结构化成 JSON 表，算每条成本，再决定是否蒸馏。

## 🔧 深度实操要点（本类场景）

> 本类场景的实操指引。通用骨架代码/评估清单/排错指南见 [00 深度实操手册总纲](00-深度实操手册总纲.md)。

- **决策速查**：文档问答/摘要→RAG(B)；写作→few-shot API(A)；数据清洗量大→微调小模型(C)
- **关键骨架**：骨架 B (RAG) + A (API few-shot)
- **评估要点**：摘要准确率(人工抽检100条)；省时(对比人工)；幻觉率<5%
- **头号陷阱**：长文档超上下文→分块+RAG；机密内容别上公网API→企业版/私有
- **进阶路径**：API→RAG(私有文档)→蒸馏小模型(量大)

---

**本类共性建议**：从"场景 1（文档摘要）"起步——ROI 最快、风险最低。验证可行后再扩到 2/3/4/5。机密内容务必用企业版/私有部署（见 Ch20）。
