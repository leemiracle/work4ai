# 06 · 财务 / 金融场景

> 金融是 agentic AI 生产部署率最高的行业（74%），监管严 + 交易量大。本类 6 个场景，ROI 最清晰（McKinsey：财务流程成本 -20~30%）。

---

### 场景 26：发票处理 / 三方匹配 / 对账
- **痛点**：发票格式不一；与 PO/收据匹配耗时；对账周期长。
- **输入 → 输出**：发票（任意格式）→ 结构化 + 匹配结果 + 异常标记。
- **模型方案**：**OCR + LLM 抽取 + 规则匹配**。量大 → 微调小模型。
- **真实案例**：行业——发票处理时间降 **80%**（Deloitte，2024）；文档处理/对账中位年省 **$1.1M**（KXN，2026）。**Rivian** 自动化定制模具采购计提（曾跨 18+ 月开发票，GAAP 要按期分摊），SOP 存知识库，agent 检测异常→组装上下文→算分摊→生成待审凭证（AWS，2026）。
- **工具栈**：OCR（Document AI）+ LLM 抽取 + ERP（SAP）集成；Bedrock AgentCore + MCP。
- **陷阱**：OCR 错数字 → 关键字段双重校验；金额异常 → 人工复核闸口。
- **起步 MVP**：100 张发票，LLM 抽取关键字段，对比人工录入准确率。

### 场景 27：反欺诈 / 风控
- **痛点**：欺诈模式多变；毫秒级判断难。
- **输入 → 输出**：交易（地理/行为/设备信号）→ 欺诈概率/拦截。
- **模型方案**：**异常检测模型 + LLM 解释**（可解释性）。实时 → 规则+模型混合。
- **真实案例**：**JPMorgan** 450+ AI agent 用例生产，含欺诈检测（aihive，2026）。**Aviva** AI 理赔优化年价值 **$80M**（Microsoft，2026）。
- **工具栈**：实时 → 规则引擎 + ML 模型；解释 → LLM 生成申诉说明。
- **陷阱**：误拦截伤体验 → 置信度分层 + 人工复核高价值；模型漂移 → 持续重训。
- **起步 MVP**：用历史标注欺诈样本训一个分类器，看召回/精度。

### 场景 28：财报分析 / 投研助手
- **痛点**：研报/财报海量，对比/抽取耗时。
- **输入 → 输出**：财报/研报 → 结构化指标 / 对比 / 摘要。
- **模型方案**：**RAG + LLM**（财报问答）。多公司对比 → Agent。
- **真实案例**：**Jefferies** 交易助手——交易员自然语言问"美国交易板块分布"，agent 生成 SQL+可视化（AWS，2026）。这是 `equity-research`/`comps-analysis`/`tear-sheet` 等 skill 的 AI 化。
- **工具栈**：财报 RAG + LLM + 数据可视化；专业 skill（见仓库内金融 skills）。
- **陷阱**：数字抽取错 → 强制引用原文页码；估值幻觉 → 只用真实数据。
- **起步 MVP**：把 3 家公司年报喂 RAG，让 LLM 做"营收增长率对比表"。

### 场景 29：月末结账 / 计提自动化
- **痛点**：月末结账周期长；计提（accrual）跨期复杂。
- **输入 → 输出**：业务事件 → 计提计算 + 待审凭证 + 审计轨迹。
- **模型方案**：**Agent（事件驱动）+ SOP 知识库 + 人工审批**。这是 `accrual-schedule`/`variance-commentary`/`roll-forward` skill 的 AI 化。
- **真实案例**：**Rivian** —— 月末结账省 **15+ 天/周期**，SOP 存 Bedrock 知识库（业务改流程改文档不改代码），完整审计轨迹，外部审计师赞扬透明度（AWS，2026）。
- **工具栈**：Agent（Strands/Bedrock AgentCore）+ ERP（SAP OData）+ 知识库 + 人工审批。
- **陷阱**：凭证必须人工过账前审（Rivian 铁律）；审计轨迹要完整可追溯。
- **起步 MVP**：选一个最耗时的计提流程，把 SOP 文档化，让 agent 按文档算 5 笔，对比人工。

### 场景 30：监管报送自动化
- **痛点**：IFRS/Basel/Solvency 报送模板复杂、易错。
- **输入 → 输出**：源数据 → 按监管模板的结构化报送。
- **模型方案**：**LLM + 监管模板 + 规则校验**。
- **真实案例**：AliceLabs 列"监管报送"为财务 AI 标准用例（2026）。BFSI 合规监控中位年省 **$780K**（KXN，2026）。
- **工具栈**：LLM + 监管模板库 + 校验引擎。
- **陷阱**：监管模板变 → 模板库更新流程；数字必须可追溯到源。
- **起步 MVP**：一份报送，用 LLM 按模板填充，人工核对每格来源。

### 场景 31：信贷 / 理赔决策辅助
- **痛点**：信贷审批/理赔定责耗时；标准案可加速。
- **输入 → 输出**：申请/理赔材料 → 风险评分 / 责任判断 / 建议。
- **模型方案**：**模型评分 + LLM 解释 + 人工决策**（合规要求留痕）。
- **真实案例**：消费贷标准案从 3-5 天压到 **60 分钟内**；银行 agentic AI 客均收入高 3-15%、服务成本低 20-40%（McKinsey，2026）。一家险企 80 个 AI 模型跨理赔，复杂案定责快 **23 天**、路由准 +30%、投诉 -65%（Swiftwater，2026）。
- **工具栈**：评分模型 + LLM 解释 + 决策留痕；分 Tier 自主（标准自主/复杂人工）。
- **陷阱**：歧视/公平性 → 模型公平审计；监管要求可解释 → LLM 解释 + 留痕。
- **起步 MVP**：历史理赔，让模型+LLM 评分，对比人工决策一致率。

## 🔧 深度实操要点（本类场景）

> 本类场景的实操指引。通用骨架代码/评估清单/排错指南见 [00 深度实操手册总纲](00-深度实操手册总纲.md)。

- **决策速查**：发票/对账→OCR+LLM抽取(A)；月末结账/计提→Agent+人工审批(D)；反欺诈→ML
- **关键骨架**：骨架 A (OCR+抽取) + D (Agent, human-in-the-loop)
- **评估要点**：处理时间降幅(发票-80%)；成本/单；审计通过率
- **头号陷阱**：凭证必须人工过账前审(Rivian铁律)；治理>技术(ISO 42001)
- **进阶路径**：OCR抽取→Agent计提→监管报送→全财务自动化

---

**本类共性建议**：金融场景**治理 > 技术**——ISO 42001、human-in-the-loop、审计轨迹是生产前提（78% 企业要求 Tier2+ 人工）。**从发票/对账（场景 26）起步**，ROI 最快（中位 $1.1M）。Rivian 的"SOP 存知识库、agent 按文档执行、人工审批"是金融 agent 的黄金范式。
