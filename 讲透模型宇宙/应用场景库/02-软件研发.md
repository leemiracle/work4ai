# 02 · 软件研发 / 代码场景

> 软件研发是 AI 渗透最深、效果最可量化的领域。代码天然适合 LLM（结构化、有测试验证）。本类 6 个场景，ROI 通常以"开发效率提升 20-50%"计。

---

### 场景 6：代码生成（补全 / 函数 / 测试）
- **痛点**：写样板代码、单测、工具函数耗时。
- **输入 → 输出**：注释/函数签名 → 可运行代码 / 测试。
- **模型方案**：**IDE 集成 AI**（Copilot/Cursor/Cline）。企业私有代码 → 私有部署 + 代码 RAG。
- **真实案例**：**Sanofi** 用 Concierge 加速临床制造技术转移（AWS，2026）；**IBM** Kiro 是 agentic AI IDE/CLI（2026）。
- **工具栈**：GitHub Copilot / Cursor / Cline / Claude Code；私有 → Continue.dev + 自托管模型。
- **陷阱**：AI 生成"看起来对但有微妙 bug" → 必须跑测试 + code review（见场景 9）；抄开源代码的 license 风险。
- **起步 MVP**：用 Cursor/Cline 写一个你下周要做的小功能，对比省时。

### 场景 7：代码理解与重构
- **痛点**：接手老项目，读不懂；技术债重，不敢重构。
- **输入 → 输出**：代码库 → 架构说明 / 重构建议 / 逐步 diff。
- **模型方案**：**代码 RAG + LLM**（理解全局）+ Agent（执行重构，逐步改+跑测试）。
- **真实案例**：**ServiceNow** 自己的 IT 部署 80% 工单自主处理，含代码理解类任务（2026）。
- **工具栈**：Cursor（@codebase 全库理解）/ Claude Code / Aider；大库 → 代码 RAG（Sourcegraph Cody）。
- **陷阱**：AI 不理解项目特有约定 → 喂架构文档 + 约定；重构破坏行为 → TDD 式小步改（`讲透PyTorch` 的 tdd skill）。
- **起步 MVP**：用 Cursor @codebase 让它解释你一个老模块的职责，对比你的理解。

### 场景 8：Bug 定位与修复
- **痛点**：报错堆栈难懂；复现/定位耗时。
- **输入 → 输出**：报错/堆栈/复现步骤 → 根因 + 修复 patch。
- **模型方案**：**Agent**（读日志→复现→定位→改→跑测试循环）。简单 → 贴报错给 LLM。
- **真实案例**：**Rippling** 用 LangSmith 半自动 self-healing——抓失败 trace → agent 分析→提修复→重跑 eval→人 review 合并（LangChain，2026）。
- **工具栈**：Claude Code / Cline / Devin；调试 → 把堆栈+相关代码喂 LLM。
- **陷阱**：AI 修了表象没修根因 → 要求它"解释根因再改"；环境相关 bug 它复现不了 → 给完整复现。
- **起步 MVP**：下一个 bug，先让 AI 分析堆栈给假设，再自己验证。

### 场景 9：代码审查
- **痛点**：PR 多、review 走形式；安全/性能问题漏看。
- **输入 → 输出**：PR diff → 风险点 + 改进建议。
- **模型方案**：**LLM 审查 + 规则引擎**（确定性规则 + LLM 语义判断）。
- **真实案例**：**IBM** Enterprise Advantage 把"代码审查"列为 IT agent 标准用例（2026）；行业报告 IT agent 事件解决快 40%（IBM，2026）。
- **工具栈**：GitHub Copilot review / CodeRabbit / 自建（diff + LLM + 检查清单）。
- **陷阱**：AI 噪音多（乱报）→ 只报高置信 + 给规则约束；不能替代人审安全关键代码。
- **起步 MVP**：写一个 review checklist prompt，跑在你下一个 PR 上，看它能否抓到你已知的问题。

### 场景 10：文档 / 注释生成
- **痛点**：没人爱写文档；文档与代码脱节。
- **输入 → 输出**：代码 → API 文档 / 注释 / README / 变更日志。
- **模型方案**：**LLM 自动生成 + CI 钩子**（PR 时自动更新文档）。
- **真实案例**：**Sanofi** Concierge 把"秒级生成原本要数周+外包代理"的内容常态化（AWS，2026）。
- **工具栈**：Copilot / Mintlify / 自建（代码 + LLM + 模板）。
- **陷阱**：文档和代码不同步 → 挂 CI 在 PR 时重新生成；文档空泛 → 要求"含输入输出 + 示例 + 边界"。
- **起步 MVP**：给一个无文档的函数，让 LLM 生成 docstring + 1 个用法示例。

### 场景 11：DevOps / 日志分析 / 运维
- **痛点**：日志海量、告警疲劳、故障定位慢。
- **输入 → 输出**：日志/告警 → 异常归类 / 根因假设 / 修复动作。
- **模型方案**：**Agent**（监控→告警→分析→（自主修复/上报））。
- **真实案例**：**IBM** 报告 ITOps 用 agentic AI 事件解决快 40%（2026）；**IBM** Enterprise Advantage 集成 CloudWatch + AIOps（2026）。
- **工具栈**：Datadog Watchdog / 自建 agent（日志 + LLM + 工具调用）；Bedrock AgentCore + Strands。
- **陷阱**：AI 自主改生产系统风险高 → 分级（自主只读 / 建议人工 / 受限写）；误报多 → 加阈值 + 置信度。
- **起步 MVP**：把一周的告警喂 LLM 做聚类归类，看能否合并噪音。

## 🔧 深度实操要点（本类场景）

> 本类场景的实操指引。通用骨架代码/评估清单/排错指南见 [00 深度实操手册总纲](00-深度实操手册总纲.md)。

- **决策速查**：补全→IDE AI；多文件重构/bug→agent(D)；概览场景，深化见 13-coding
- **关键骨架**：骨架 D (agent) — 见 13 深化
- **评估要点**：PR 接受率；测试通过率；省时(周)
- **头号陷阱**：AI生成'看似对实则微妙bug'→必跑测试+review(见13铁律)

---

**本类共性建议**：从"场景 6（代码生成，IDE 集成）"起步——零成本、立竿见影。然后 8（bug）→ 9（review）→ 10（文档）。DevOps（11）风险高，放最后，且必须 human-in-the-loop。
