# 18 · 跨职能横切（SecOps / 数据分析 / 知识管理 / 低代码）

> 这些不是行业，而是**横切所有行业的通用能力**——安全运营、数据分析、企业知识、低代码开发。它们的共性是"**跨系统、高重复、人在告警/数据里游泳**"，正是 agent 的主战场。本类 7 个场景，覆盖 2026 agentic SecOps/分析/搜索/低代码的前沿。

---

### 场景 103：SecOps 告警分流 / 自主 SOC
- **痛点**：告警海量；分析师在 30 分钟手动调查里淹没；AI 攻击压缩入侵→窃取到小时。
- **输入 → 输出**：告警 → 真/假阳性判决 + 置信度 + 攻击时间线 + 建议。
- **模型方案**：**确定性查询关明显误报（零 token）→ 专科 agent 调查 → 综合 agent 出报告**；人只开带完整调查的告警。
- **真实案例（2026）**：**Elastic agentic SOC**（InfoSec 自建）—— 告警分流 **30 分钟→<3 分钟**；确定性 ES|QL 关假阳性零成本，Initial Triage agent 关下一层（~50k token），专科 agent 调查端点/云/SaaS，Final Review agent 写判决到 Kibana case；**专科 agent > 宽泛 agent**（方法论写进 system prompt，省 5× 成本）。**Torq**：Context Graph + Memory Layer（Recall 先例/Reflex 学习/Retrospect 历史导入），Socrates 编排 HyperAgents。
- **工具栈**：Elastic Workflows / Torq / Splunk SOAR / 自建（确定性查询 + 专科 agent + 综合 agent）。
- **陷阱**：宽泛 agent 成本高 → 专科 agent + 方法论 prompt；误判 → 人审高风险；推理数据留存 → 零留存 provider。
- **起步 MVP**：top 10 高频告警类型，确定性规则关明显假阳性，算省时。

### 场景 104：安全编排 / 自动响应（Agentic SOAR）
- **痛点**：响应动作多跨工具；SOAR 规则僵化。
- **输入 → 输出**：事件 → 多 agent 编排调查+遏制+修复（人工审批破坏性动作）。
- **模型方案**：**多 agent + human-in-the-loop 破坏性动作**；无代码建 agent。
- **真实案例（2026）**：**CrowdStrike Charlotte AI AgentWorks**（无代码建安全 agent，Agentic SOAR 多 agent 编排，多检查点分析师审批，RBAC + 审计日志 + 版本控制，AWS Bedrock 多模型）。**Splunk Agent Launchpad**（2026-07 GA，无代码，从告警/搜索触发，RBAC + 证据链，agent 完成 **80%** 分析师工作）。**Tuskira**：containment **架构性 human-in-the-loop**（非开关）——"自主调查到判决，破坏性动作永远需人批"。
- **工具栈**：CrowdStrike AgentWorks / Splunk Agent Launchpad / Tuskira / Torq；MCP 连接器。
- **陷阱**：agent 自主破坏性动作风险 → **架构性 HITL**（Tuskira）；权限蔓延 → 最小权限 + 审计。
- **起步 MVP**：一个 phishing 分诊 agent（富化+建议下一步），人审判决。

### 场景 105：攻击路径建模 / 暴露验证
- **痛点**：漏洞海量；不知哪个真可被利用达入侵。
- **输入 → 输出**：资产/身份/暴露/控制 → 攻击路径 + 可利用子集 + 补偿控制建议。
- **模型方案**：**context graph + 数字孪生**，建模身份/资产/控制如何链成跨域攻击路径；验证哪些控制真断链。
- **真实案例（2026）**：**Tuskira** —— 联邦搜索 **150+ 工具**（数据不动），单一 context graph；CVE 一出，回答"它在你环境是否可达"并推荐先关哪个控制；把百万 finding 缩到"可利用+可达+无防御"小子集。某全球金融服务：finding 缩减 + **30 分钟分流**。
- **工具栈**：context graph + 联邦搜索（MCP）+ 攻击路径推理 + 数字孪生。
- **陷阱**：图建模不全 → 持续补实体/关系；控制评估错 → 定期红队验证。
- **起步 MVP**：把身份+端点+云资产建图，找一个已知 CVE 看是否可达。

### 场景 106：数据分析 agent（自然语言查数）
- **痛点**：业务要数据但不会 SQL/Python；IT 排队。
- **输入 → 输出**：自然语言问题 → SQL/Python → 结果 + 可视化 + 钻取。
- **模型方案**：**Text-to-SQL/Python agent + schema 检索 + 可视化**。
- **真实案例**：**Jefferies** 交易助手（见 06）；**Roblox analytics agent**（见 12）；**Amplitude** experiment agent；通用模式（Cursor cloud agent + 数据 MCP）。这是 `to-prd`/数据 skill 的 agent 化。
- **工具栈**：LangGraph/LlamaIndex + Text-to-SQL + 数据库连接（MCP）+ BI 可视化。
- **陷阱**：SQL 错 → schema 检索 + 只读 + 语法校验；大数据慢 → 物化视图/采样。
- **起步 MVP**：一个库的 schema 做知识库，agent 答业务问题，对比人工 SQL。

### 场景 107：企业搜索 / 知识管理
- **痛点**：知识散落 wiki/SharePoint/Confluence/HR 门户；搜索召回差。
- **输入 → 输出**：员工问题 → 跨源检索 + 角色分级 + 答案 + 引用。
- **模型方案**：**多源 RAG + 角色访问控制（RBAC）+ 智能升级**。
- **真实案例**：**Sanofi Concierge**（见 01，跨研究/制造/企业知识）；**Rippling** read/RAG agent（见 11）；内部知识 agent 是企业 AI "最快最低风险 ROI"（Algolia）。
- **工具栈**：多源连接器（wiki/SharePoint/Confluence）+ 向量搜索 + LLM + RBAC + 升级路由。
- **陷阱**：权限错配 → 严格 RBAC；知识过时 → owner 定期更新；召回差 → 混合检索（语义+关键词）。
- **起步 MVP**：把一个 wiki 空间做 RAG，员工问"报销流程"秒答带链接。

### 场景 108：低代码 / 公民开发者（无代码建 agent/应用）
- **痛点**：最懂流程的人（分析师/运营）不会写代码；IT 排队。
- **输入 → 输出**：自然语言描述 → 部署的 agent/应用。
- **模型方案**：**无代码 agent 构建器**（自然语言定义任务/工具/权限）。
- **真实案例（2026）**：**Splunk Agent Launchpad**（分析师无代码建 agent，从告警触发）；**CrowdStrike AgentWorks**（无代码，自然语言定义任务→分钟部署）；**Roblox Build**（见 12，文本→游戏）；通用低代码（Microsoft Copilot Studio / Salesforce Agentforce）。"最懂自动化的人是做活的分析师，他们很少会写集成代码——agent 构建器去掉这个依赖"（Splunk）。
- **工具栈**：Splunk Agent Launchpad / CrowdStrike AgentWorks / Copilot Studio / Agentforce / Roblox Build。
- **陷阱**：无代码 agent 失控 → 治理（RBAC + 审批 + 审计）；质量参差 → 模板 + 最佳实践。
- **起步 MVP**：用一个无代码平台，让运营建一个"工单分诊"agent。

### 场景 109：运维 / SRE agent（事件响应）
- **痛点**：告警疲劳；故障定位慢；MTTR 高。
- **输入 → 输出**：告警/日志 → 根因假设 + 修复动作（自主只读/受限写/人工批破坏性）。
- **模型方案**：**分级自主 agent**（自主只读分析 → 建议人审 → 受限写 → 人工批破坏性）。
- **真实案例**：**IBM** ITOps agentic AI 事件解决快 **40%**（见 11）；**Amplitude** 推 agent 到 CI/CD/部署（见 13）；Splunk/Torq 跨 IT+安全。
- **工具栈**：Splunk ITSI / Datadog Watchdog / 自建 agent（日志 + LLM + 工具）。
- **陷阱**：自主改生产风险 → 分级 + human-in-the-loop；误报多 → 阈值 + 置信度。
- **起步 MVP**：一周告警喂 agent 做聚类归类，合并噪音。

## 跨职能横切 AI 的五条铁律
1. **专科 agent >> 宽泛 agent**（Elastic：方法论写进 prompt，省 5× 成本，更一致）。
2. **确定性 + 生成平衡**——明显情况用规则（零成本），模糊处用 LLM（Kogan/Elastic 同理）。
3. **破坏性动作架构性 human-in-the-loop**（Tuskira：非开关，是架构）。
4. **context graph + memory 是 agent 智能的地基**（Torq：Recall/Reflex/Retrospect 让 agent 越用越懂你的环境）。
5. **最懂流程的人不该被代码挡住**——无代码 agent 构建器让分析师/运营自建（Splunk/CrowdStrike）。

> **跨职能横切的心法**：这些场景的共同本质是"**把人从告警/数据/知识的洪流里解放，升维到判断与决策**"。SecOps 的"每个告警带完整调查到人"、数据分析的"自然语言查数"、知识的"跨源秒答"、低代码的"分析师自建 agent"——都是 Ch22"规模杠杆 + 能力降门槛"在通用职能上的极致。**agent 不替代人，是重组工作**：AI 执行调查/抽取/编排，人做判决/策略。
