# 02 · 模型动物园与工具链

> 研究模型，先要有"笼子"装住它们、有"显微镜"看它们、有"秤"称它们。这一章给你研究者的全套工具链——以及每个工具会怎么骗你。

## 2.1 模型宇宙的"双枢纽"

2026 年，所有 AI 模型分成两个世界，工具链完全不同：

| 世界 | 代表 | 特点 | 工具链 |
|------|------|------|--------|
| **闭源 API** | GPT/Claude/Gemini/Grok | 黑箱，只给 API；权重不可见 | 官方 SDK、OpenRouter、LiteLLM |
| **开源权重** | Llama/Qwen/DeepSeek/Mistral/Gemma | 权重可下载；可改可部署 | **HuggingFace 生态**（本系列主战场）|

**研究者须知**：可解释性（Part II）几乎只能做在**开源权重**模型上——你拿不到 GPT-4 的权重，就没法做 probing/SAE。所以本系列默认"模型 = 开源权重模型"。

## 2.2 HuggingFace Hub：模型动物园本身

[huggingface.co/models](https://huggingface.co/models) 是开源模型的中央仓库，2026 年托管超过 **100 万**个模型。研究模型，你会反复和它打交道。

**核心三件套：**

1. **模型卡（Model Card）**——模型的"身份证 + 体检报告"。必读字段：
   - `base_model`：从哪个模型微调的（追血缘）
   - `training_data`：训了什么（判断数据污染）
   - `license`：能不能商用（⚠️ 很多好模型是 CC-BY-NC 非商用）
   - `eval_results`：自报的 benchmark 分（**默认怀疑**，见 §2.5）
   - `intended_use / limitations`：作者承认的局限（往往被忽视，但最有信息量）

2. **transformers 库**——加载和运行权重的标准接口：
   ```python
   from transformers import AutoModelForCausalLM, AutoTokenizer
   tok = AutoTokenizer.from_pretrained("Qwen/Qwen3-0.6B")
   model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen3-0.6B")
   ```
   `Auto*` 会根据模型卡的 `config.json` 自动选正确的类。研究者还要会用 `output_hidden_states=True` 拿到中间层激活——这是 Part II probing/SAE 的入口。

3. **Hub 的 metadata**——每个模型有 `downloads`、`likes`、`last_modified`、`pipeline_tag`。研究者筛模型的标准组合：`pipeline_tag=text-generation` + `downloads>10k` + 按 `likes` 排序，能过滤掉 90% 的噪音（大量是个人实验）。

## 2.3 本地推理三件套：从最简到最快

| 工具 | 定位 | 何时用 |
|------|------|--------|
| **Ollama** | 一键最简 | 想立刻在笔记本跑起来聊天/做实验 |
| **llama.cpp** | 极致省内存 | 端侧、CPU、量化到 4-bit |
| **vLLM** | 极致吞吐 | 服务化、批量推理、要 PagedAttention/KV cache 优化 |

研究者的典型组合：**vLLM 起服务 + transformers 做可解释性**。前者快，后者能拿中间层。

> ⚠️ **铁律（项目级）**：模型权重文件绝不进 git。下载到 `MODELSCOPE_CACHE`/HF cache 指向的仓库外目录，`.gitignore` 必须排除。

## 2.4 称模型的"质量"：Epoch AI

权重是模型的"形状"，**算力**才是它的"质量"。[Epoch AI](https://epoch.ai) 是追踪前沿模型算力/数据的权威，它的数据库记录了每个重要模型的：
- **训练算力**（FLOPs）—— 和能力高度相关；
- **训练数据量**（tokens）—— Chinchilla 定律的关键变量；
- **参数量**、**发布日期**、**是否开源**。

研究者用它回答："这个模型是真的强，还是只是堆了更多算力？" Epoch AI 的 *Frontier Models* 图表是把 scaling law 具象化的最好工具。

**一个反直觉用法**：用 Epoch 的数据画"算力 vs benchmark"，如果某个模型的点**偏离**了趋势线（同等算力分数明显低），说明它**架构/数据效率差**——这往往是值得深究的研究线索。

## 2.5 模型卡会怎么骗你（批判）

研究者读模型卡，要带三层怀疑：

1. **自报分数不可信**。模型卡上的 eval_results 是作者自己跑的，prompt 模板、few-shot 数、temperature 都会影响分数 5-10%。永远以**独立排行榜**为准（见 Ch03）。
2. **license 陷阱**。`CC-BY-NC-4.0`（非商用）、`Gemma License`（有附加条款）、`LLaMA Community License`（>7亿月活需授权）——做产品前必须看清。研究用途通常 OK，但二次发布要小心。
3. **数据污染**。模型卡很少主动声明"训练数据包含了 benchmark"——而这恰恰是分数虚高的头号原因。判断方法：看训练数据描述里有没有 Common Crawl（很可能含被爬的 benchmark 题）。

## 2.6 研究者工具链全景图

```
发现模型    HuggingFace Hub (搜/筛)  ← 按 downloads+likes 过滤
   │
追踪算力    Epoch AI (质量秤)
   │
下载权重    huggingface-cli / hf_transfer (断点续传)
   │
本地运行    vLLM(服务) / transformers(拿中间层) / llama.cpp(省内存)
   │
打开内部    probing / SAE / activation steering  ← Part II 主线
   │
记录复现    固定 commit + config + seed (Ch14 可复现性)
```
