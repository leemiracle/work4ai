  The User I/O Interface (USRBIO) provides FFI (Foreign Function Interface) bindings for user-space I/O operations in 3FS. Implemented as the `hf3fs-usrbio-sys` Rust crate, it serves as the primary interface layer between client applications and 3FS core services, enabling C-compatible access to distributed storage operations through shared memory communication.

 This document covers the FFI binding architecture, shared memory IPC mechanisms, and UUID generation for resource identification. For information about client-side tooling that uses USRBIO, see the FIO USRBIO Plugin page. For details on the storage backend that USRBIO communicates with, see Chunk Engine.

## Overview

 
### Purpose and Scope

 The `hf3fs-usrbio-sys` crate provides low-level FFI bindings that enable C/C++ applications to perform I/O operations against 3FS storage. The crate uses `bindgen` to automatically generate Rust-to-C++ bindings from the `hf3fs_usrbio.h` header, implements shared memory for high-performance IPC, and provides UUID generation for resource identification.

 Key responsibilities:

 
 - Generate FFI bindings from C++ headers using `bindgen` [src/lib/rs/hf3fs-usrbio-sys/build.rs9-14](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/rs/hf3fs-usrbio-sys/build.rs#L9-L14)
 - Manage shared memory regions (`hf3fs_iov`) for zero-copy data transfer [src/lib/api/UsrbIo.cc109-137](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/api/UsrbIo.cc#L109-L137)
 - Register file descriptors for user-space I/O [src/lib/rs/hf3fs-usrbio-sys/src/lib.rs212-222](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/rs/hf3fs-usrbio-sys/src/lib.rs#L212-L222)
 - Expose a C-compatible API surface for client applications [src/lib/api/hf3fs_usrbio.h1-174](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/api/hf3fs_usrbio.h#L1-L174)

## Core Data Structures

 
### I/O Vector (hf3fs_iov)

 The `hf3fs_iov` structure represents a memory region used for data transfer. It is backed by a shared memory segment created in `/dev/shm` and registered with the 3FS client via a symlink in the `3fs-virt/iovs` directory.

 
| Field | Type | Description |
|---|---|---|
| base | uint8_t* | Virtual address of the buffer in the user process |
| iovh | void* | Internal handle to hf3fs::lib::ShmBuf |
| id | char[16] | 128-bit unique identifier for the buffer |
| mount_point | char[256] | Path to the 3FS mount point |

 **Sources:** [src/lib/api/hf3fs_usrbio.h18-27](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/api/hf3fs_usrbio.h#L18-L27) [src/lib/api/UsrbIo.cc164-172](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/api/UsrbIo.cc#L164-L172)

 
### I/O Ring (hf3fs_ior)

 The `hf3fs_ior` structure manages a ring of I/O operations, similar to `io_uring`. It facilitates asynchronous submission and completion of I/O requests.

 
| Field | Type | Description |
|---|---|---|
| iov | hf3fs_iov | The underlying buffer ring |
| for_read | bool | Direction of the ring (Read or Write) |
| io_depth | int | Batch size for the I/O worker |
| flags | uint64_t | Control flags (e.g., HF3FS_IOR_FORBID_READ_HOLES) |

 **Sources:** [src/lib/api/hf3fs_usrbio.h32-49](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/api/hf3fs_usrbio.h#L32-L49) [src/lib/rs/hf3fs-usrbio-sys/src/lib.rs70-72](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/rs/hf3fs-usrbio-sys/src/lib.rs#L70-L72)

## Shared Memory and Virtual Filesystem

 The USRBIO interface communicates with the 3FS FUSE client through a "virtual" directory interface. When an I/O vector is created, it establishes a link between the process's shared memory and the 3FS filesystem.

 
### Registration Flow

 
 - **UUID Generation**: A random UUID is generated for the buffer [src/lib/api/UsrbIo.cc129](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/api/UsrbIo.cc#L129-L129)
 - **SHM Creation**: A shared memory segment is created at `/dev/shm/hf3fs-iov-<UUID>` [src/lib/api/UsrbIo.cc129-133](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/api/UsrbIo.cc#L129-L133)
 - **Symlink Registration**: A symlink is created at `<mount_point>/3fs-virt/iovs/<UUID>.<params>` pointing to the SHM file [src/lib/api/UsrbIo.cc147-155](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/api/UsrbIo.cc#L147-L155)
 - **FUSE Detection**: The 3FS FUSE client detects the new entry in its virtual directory and maps the shared memory to its own address space.

## Error Handling and Safety

 The USRBIO interface uses standard POSIX error codes (returned as negative integers).

 
 - **Thread Safety**: `hf3fs_prep_io` is explicitly documented as **NOT** thread-safe. Callers must synchronize access to a single `hf3fs_ior` across threads [src/lib/api/hf3fs_usrbio.h148-151](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/api/hf3fs_usrbio.h#L148-L151)
 - **Memory Safety**: The Rust wrapper `Iov` and `Ior` implement `Send` and `Sync` (where appropriate) and handle cleanup via the `Drop` trait, which calls `hf3fs_iordestroy` and `hf3fs_dereg_fd` [src/lib/rs/hf3fs-usrbio-sys/src/lib.rs33-34](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/rs/hf3fs-usrbio-sys/src/lib.rs#L33-L34) [src/lib/rs/hf3fs-usrbio-sys/src/lib.rs191-197](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/rs/hf3fs-usrbio-sys/src/lib.rs#L191-L197) [src/lib/rs/hf3fs-usrbio-sys/src/lib.rs224-230](https://github.com/deepseek-ai/3FS/blob/22fca045/src/lib/rs/hf3fs-usrbio-sys/src/lib.rs#L224-L230)
