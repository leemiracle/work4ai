  The Management Service (`mgmtd`) is the central control plane of a 3FS cluster. It is responsible for maintaining the global cluster state, including node membership, routing information (chain tables), and configuration management. It uses a lease-based primary election mechanism to ensure high availability and consistency of the cluster metadata.

 
## Service Architecture

 The `mgmtd` service is built upon the `OnePhaseApplication` framework and consists of several key components:

 
 - **`MgmtdOperator`**: The primary RPC handler that implements the `MgmtdService` interface. It coordinates requests between the network layer and the internal state. [tests/mgmtd/TestMgmtdOperator.cc7](https://github.com/deepseek-ai/3FS/blob/22fca045/tests/mgmtd/TestMgmtdOperator.cc#L7-L7)
 - **`MgmtdState`**: An in-memory representation of the cluster state, including the routing info and active node heartbeats. [src/mgmtd/ops/SetChainTableOperation.cc35](https://github.com/deepseek-ai/3FS/blob/22fca045/src/mgmtd/ops/SetChainTableOperation.cc#L35-L35)
 - **`MgmtdStore`**: The persistence layer that interacts with the underlying KV engine (e.g., FoundationDB or MemKV for testing) to store persistent cluster metadata. [tests/mgmtd/TestMgmtdOperator.cc50](https://github.com/deepseek-ai/3FS/blob/22fca045/tests/mgmtd/TestMgmtdOperator.cc#L50-L50)
 - **Background Workers**: Periodically perform tasks such as lease extension, heartbeat cleanup, and routing info synchronization.

## Primary Election and Leases

 The `mgmtd` cluster operates with a primary-backup model. Only the primary node is allowed to perform write operations on the cluster state.

 
### Lease Mechanism

 
 - **Lease Acquisition**: A node attempts to become primary by writing its `PersistentNodeInfo` to a specific key in the KV store with a lease expiration time. [tests/mgmtd/TestMgmtdOperator.cc50-60](https://github.com/deepseek-ai/3FS/blob/22fca045/tests/mgmtd/TestMgmtdOperator.cc#L50-L60)
 - **Lease Extension**: The current primary must periodically extend its lease. The interval is configurable via `extend_lease_interval`. [tests/mgmtd/TestMgmtdOperator.cc25-27](https://github.com/deepseek-ai/3FS/blob/22fca045/tests/mgmtd/TestMgmtdOperator.cc#L25-L27)
 - **Primary Validation**: Every operation that modifies state (like `SetChainTable` or `RegisterNode`) calls `doAsPrimary`, which checks if the local node still holds the valid lease according to the `MgmtdStore`. [src/mgmtd/ops/SetChainTableOperation.cc86](https://github.com/deepseek-ai/3FS/blob/22fca045/src/mgmtd/ops/SetChainTableOperation.cc#L86-L86)

## Routing Info and Chain Management

 One of the most critical roles of `mgmtd` is managing the `RoutingInfo`. This structure maps `ChainId`s to specific storage targets and organizes them into `ChainTable`s.

 
### Chain Table Management

 A `ChainTable` is a collection of chains used for data placement. When a client or the Metadata Service (`meta`) needs to allocate space for a file, it requests a layout from `mgmtd`.

 
 - **`SetChainTable`**: Defines a new version of a chain table. It validates that all provided `ChainId`s exist and have consistent target counts. [src/mgmtd/ops/SetChainTableOperation.cc7-32](https://github.com/deepseek-ai/3FS/blob/22fca045/src/mgmtd/ops/SetChainTableOperation.cc#L7-L32)
 - **`SetChains`**: Registers new chains or updates existing ones. It ensures that target IDs are not duplicated and that existing chains are not modified in an incompatible way. [src/mgmtd/ops/SetChainsOperation.cc60-98](https://github.com/deepseek-ai/3FS/blob/22fca045/src/mgmtd/ops/SetChainsOperation.cc#L60-L98)
 
 
### Deterministic Shuffle

 To ensure balanced data distribution, 3FS uses a deterministic shuffle algorithm when selecting chains from a table. Because different versions of `libstdc++` (GCC 10 vs GCC 11) produce different results for `std::shuffle`, 3FS implements `hf3fs_shuffle` to guarantee consistency across the cluster regardless of the compiler version used to build individual nodes. [src/common/utils/Shuffle.h162-172](https://github.com/deepseek-ai/3FS/blob/22fca045/src/common/utils/Shuffle.h#L162-L172)

## Node Management and Heartbeats

 The `mgmtd` service tracks the liveness of all nodes in the cluster (Storage, Metadata, and Clients).

 
 - **Registration**: Nodes must call `registerNode` before they can participate in the cluster. [tests/mgmtd/TestMgmtdOperator.cc87-92](https://github.com/deepseek-ai/3FS/blob/22fca045/tests/mgmtd/TestMgmtdOperator.cc#L87-L92)
 - **Heartbeats**: Nodes periodically send `heartbeat` requests to `mgmtd`. If a node fails to send a heartbeat within the `heartbeat_timestamp_valid_window`, it may be marked as offline. [tests/mgmtd/TestMgmtdOperator.cc28-29](https://github.com/deepseek-ai/3FS/blob/22fca045/tests/mgmtd/TestMgmtdOperator.cc#L28-L29) [tests/mgmtd/TestMgmtdOperator.cc72-77](https://github.com/deepseek-ai/3FS/blob/22fca045/tests/mgmtd/TestMgmtdOperator.cc#L72-L77)
 - **Routing Updates**: The `RoutingInfo` version is incremented whenever node states or chain configurations change. Clients use the version to determine if they need to fetch an updated routing table. [src/mgmtd/ops/SetChainTableOperation.cc40-41](https://github.com/deepseek-ai/3FS/blob/22fca045/src/mgmtd/ops/SetChainTableOperation.cc#L40-L41)

### Configuration Parameters

 The `MgmtdConfig` struct controls the behavior of the management service:

 
 - `lease_length`: Duration for which a primary lease is valid. [tests/mgmtd/TestMgmtdOperator.cc25](https://github.com/deepseek-ai/3FS/blob/22fca045/tests/mgmtd/TestMgmtdOperator.cc#L25-L25)
 - `extend_lease_interval`: How often the primary attempts to renew its lease. [tests/mgmtd/TestMgmtdOperator.cc26](https://github.com/deepseek-ai/3FS/blob/22fca045/tests/mgmtd/TestMgmtdOperator.cc#L26-L26)
