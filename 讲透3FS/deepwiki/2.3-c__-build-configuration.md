## Compiler Configuration and Language Standards

 The build system enforces the C++20 standard with specific compiler optimizations and platform-specific settings [CMakeLists.txt74-79](https://github.com/deepseek-ai/3FS/blob/22fca045/CMakeLists.txt#L74-L79)

 
| Configuration | Value | Description |
|---|---|---|
| CMAKE_C_STANDARD | 11 | C11 standard CMakeLists.txt74 |
| CMAKE_CXX_STANDARD | 20 | C++20 standard required CMakeLists.txt77 |
| CMAKE_CXX_STANDARD_REQUIRED | ON | C++20 strictly enforced CMakeLists.txt78 |
| CMAKE_CXX_EXTENSIONS | OFF | Disable compiler extensions CMakeLists.txt79 |
| CMAKE_POSITION_INDEPENDENT_CODE | ON | Enable PIC for shared libraries CMakeLists.txt80 |

## Custom Build Options

 3FS introduces specific build options for shuffle consistency and memory management.

 
### Shuffle Method Selection

 To ensure consistency across different GCC versions when generating file layouts, 3FS requires a specific `SHUFFLE_METHOD` [CMakeLists.txt30-45](https://github.com/deepseek-ai/3FS/blob/22fca045/CMakeLists.txt#L30-L45) This is critical for the `ChainAllocator` when picking chains for file layouts [src/meta/components/ChainAllocator.h115-120](https://github.com/deepseek-ai/3FS/blob/22fca045/src/meta/components/ChainAllocator.h#L115-L120)

 
| Option | Implementation |
|---|---|
| stdshuffle | Uses std::shuffle with std::mt19937_64 src/common/utils/Shuffle.h156-159 |
| g++10 | Replicates GCC 10's std::shuffle behavior src/common/utils/Shuffle.h151-153 |
| g++11 | Replicates GCC 11's std::shuffle behavior src/common/utils/Shuffle.h146-148 |

 
### Memory Management Options

 
| Option | Default | Purpose |
|---|---|---|
| OVERRIDE_CXX_NEW_DELETE | OFF | Override C++ new/delete operators for custom allocation tracking CMakeLists.txt56 |
| SAVE_ALLOCATE_SIZE | OFF | Use more memory to save allocation sizes CMakeLists.txt57 |

## Third-Party Dependencies Integration

 3FS integrates a large number of dependencies. A common pattern used is `store_compile_flags()` and `restore_compile_flags()` to prevent project-wide flags (like `-Werror`) from breaking external code [CMakeLists.txt112-114](https://github.com/deepseek-ai/3FS/blob/22fca045/CMakeLists.txt#L112-L114)

 
### Core Libraries

 
 - **folly**: Integrated with `FOLLY_NO_EXCEPTION_TRACER` enabled [CMakeLists.txt126-127](https://github.com/deepseek-ai/3FS/blob/22fca045/CMakeLists.txt#L126-L127)
 - **rocksdb**: Built with LZ4 and ZSTD support [CMakeLists.txt135-143](https://github.com/deepseek-ai/3FS/blob/22fca045/CMakeLists.txt#L135-L143)
 - **clickhouse-cpp**: Static linking with specific include directory overrides for bundled `absl` [CMakeLists.txt160-170](https://github.com/deepseek-ai/3FS/blob/22fca045/CMakeLists.txt#L160-L170)
 
 
### Apache Arrow Integration

 Arrow is integrated as an `ExternalProject` because of its complex build requirements and dependencies [cmake/ApacheArrow.cmake21](https://github.com/deepseek-ai/3FS/blob/22fca045/cmake/ApacheArrow.cmake#L21-L21)
